今日重点：苏州睿芯「高光 D35」RISC-V 数据流物理 AI 芯片量产获园区官方确认

日期：2026-09-14（厂商量产发布 09 月上旬）　来源：苏州工业园区管委会官网《RISC-V 数据流物理 AI 芯片量产！》、极客公园《全球首款 RISC-V 数据流物理 AI 芯片「高光 D35」量产》、新浪财经《跨越架构周期：睿芯高光 D35 与数据流的边缘突围》

苏州工业园区管委会官网于 09-14 14:25 刊发即时动态，确认苏州睿芯集成电路科技有限公司自主研发的「高光 D35」数据流 AI 芯片正式实现量产，并称其为「全球领先的基于 RISC-V 指令集的数据流架构物理 AI 芯片」，标志着数据流计算这一提出已逾 60 年的架构路线从学术研究阶段进入规模化商用。厂商口径给出的三项「领先级」定位为：首款实现商业化量产的数据流架构 AI 芯片；将 RISC-V 开放指令集与数据流计算架构深度融合的双路线方案；明确锚定「物理 AI」而非云端大模型算力的产品定位。硬件侧披露的一项关键参数是配备 128 GB 大显存，用于支撑更大规模模型在边缘侧本地部署，强调数据不出端、响应更快。企业侧，睿芯成立于 2020 年 8 月，总部位于苏州工业园区（独墅湖科教创新区），核心团队来自中国科学院计算所、中国科学院自动化所、IBM、Intel 等机构，研发人员占比超 70%、硕博学历成员达 50%，已发表 100 余篇学术论文，相关成果获 ISCA 2026 国际计算机体系结构顶会最佳论文提名；另有报道称公司首席科学家为中国工程院院士孙凝晖。公司已完成五轮融资。

产品落地层面，官方与厂商稿共同给出的场景划分为四类：行业智能计算（AI PC 加速、视频压缩与分析、工业智能控制）、具身智能（机器人、无人车域控等感知加决策加控制一体化场景）、舱驾一体（智能座舱与驾驶域控融合）、通信（5G 小基站、毫米波、AI RAN）。生态侧，睿芯宣布即将启动「光荣社区」，定位为面向数据流架构的 RISC-V 开发者社区，提供文档中心、SDK 工具链、模型库、在线实训与技术论坛，并设立「睿芯光荣基金」支持生态创新。技术论证上，厂商把能效比作为核心卖点，称全数据流架构相比同类竞品能效比提升数倍，理由是省去指令调度开销、数据在计算单元间直接流动而非反复读写内存、无分支预测失败与缓存失效带来的延迟不确定性。

为何值得关注：这一条是本刊 9 月首次收录的数据流架构量产事件，且此前未被本系列日报覆盖（经全库检索确认）。其分量在于三点：其一，数据流（dataflow）路线长期停留在论文与小批量验证阶段，若有厂商宣称进入量产交付，意味着该路线在中国出现了商业化样板；其二，它是「RISC-V 加非冯诺依曼架构」的少见组合，与国内主流的「RISC-V 加向量/矩阵加速」路线形成对照，为端侧物理 AI 提供另一种算力范式；其三，具身智能被其列为四大落地场景之一，与本期第四章的机器人软件栈动态形成上下游呼应。需要注意的边界：本条的量产宣称、能效比倍数与「自研 RISC-V CPU 内核获 Intel 全球唯一采购认可」等表述均来自厂商与媒体稿，尚无第三方独立测试或客户量产案例佐证，本报告按厂商口径收录并标注，后续应跟踪其 SDK 开放程度、社区启动实况与真实出货规模。

一、开源社区与软件生态

1.1 香山昆明湖：分支预测与向量通路修复集中合入，IFU/FTQ 补自修改代码分支训练

日期：2026-09-14　来源：OpenXiangShan/XiangShan 提交记录

开源高性能 RISC-V 处理器香山（昆明湖 V3 分支）在窗口内共 8 次提交，延续「新特性收敛后转正确性打磨」的节奏，重心集中在分支预测与取指侧。分支预测方面，zhou tao 于 09-14 22:42 提交 #6484，为 IFU 与 FTQ 增加「误预测时的直接跳转分支训练」，专门处理自修改代码（self-modifying code）引起的误预测——这类场景在动态生成代码、JIT 与加载器自改写场景中常见，是仿真与真实运行差异的典型来源；Muzi 于 22:41 提交 #6569，修正 ITTAGE 预测器中 useful 计数器掩码从条目字段推导的逻辑，并同日更新性能检查点（#6568）；Zhihao Xu 于 22:50 提交 #6461，对 Bpu 做使能修正与调试相关修复并清理代码。取指与异常方面，lengard2019 于 14:42 提交 #6428，修正 IFU 在异常与不可缓存访问同时触发时的异常 PC 传递，属特权态边界正确性修复；Zhihao Xu 同日提交 #6553，清理已废弃的 0604 传统性能测试基线。向量通路方面，Xuan Hu 于 11:02 连续两次提交（#6565、#6564），将向量源操作数反转的时机移到读寄存器之后，并为 VMove 结果补上浮点 boxing，避免窄位宽浮点值在寄存器合并时丢失 NaN-box 语义。整体看，当日提交几乎全部是「正确性与边界条件」类修复，未见新特性级推进。

1.2 XSCache：ZhuJiang（L3）子模块批次合入，HN 性能计数器改为按模块路径命名

日期：2026-09-14　来源：OpenXiangShan/XSCache 提交记录

香山配套的开源 L2（RN）与 LLC（HN）缓存仓库 XSCache 在窗口内一次性落 18 次提交，但提交时间集中在 09-14 17:48（北京时间），而作者日期横跨 2026-06-10 至 09-10，属典型的批次合入收尾（作者与提交日期不同日，本报告按合入时间计）。内容主线有三：一是 ZhuJiang（香山 L3 缓存方向子模块）相关工作的集中落地，包括参数化 cfgAxiDataBits、为 ZhuJiang 适配 gsim 仿真环境、修复 resetgen 与复位同步、修复 FIRRTL 构建兼容性、启用 stash refill 跟踪、以及新增 TestTopZhuJiang 测试顶层（支持 CoupledL2 加 ZhuJiang 组合、配置最小化 DongJiang 以加速仿真、初始化 ChiselDB）；二是性能计数器能力，zhengzhongqiang 提交 feat(perf): name HN collectors by module path，把 HN（Home Node）性能计数器从匿名编号改为按模块路径命名，便于与香山顶层做联合计数采集，同批加入「与香山协同采集 ZhuJiang 计数器」的能力；三是若干测试与适配修正（关闭 ZhuJiang 测试顶层的 DataCheck 与 Poison、保留 DCT home node ID）。本条的价值在于揭示香山的内存系统正在向「CoupledL2 加独立 L3（ZhuJiang）」的配置演进，且配套仿真、复位、构建与性能采集链路已同步补齐——这是 L3 缓存进入可验证状态的信号。

1.3 香山仿真与验证链：NEMU 精简单步边界，GEM5 校准 SBUFFER，difftest 切 slim 容器

日期：2026-09-14　来源：OpenXiangShan/NEMU 提交记录、OpenXiangShan/GEM5 提交记录、OpenXiangShan/difftest 提交记录

香山验证工具链在窗口内出现一组以「性能与效率」为目标的改动。NEMU（香山参考模型，超高速 RISC-V ISA 仿真器）由 Kamimiao 于 10:42 连续两次提交：perf(difftest): lazily prepare CSR shadow for REF（为参考模型延迟准备 CSR 影子副本，减少每步开销）与 perf(share): trim single-step execution boundary（裁简单步执行的边界），两条都直接作用于差分测试（difftest）每步执行的固定成本，属仿真吞吐优化。GEM5 香山分支由 ZHEN HAO 于 19:23 提交 cpu-o3: Calibrated SBUFFER behaviour（校准乱序流水线中 Store Buffer 的行为以贴近真实硬件）。difftest 框架由 Kunlin You 于 16:49 提交 #965，将 CI 容器从完整镜像切换为 slim 镜像并移除 GSIM 安装步骤，降低持续集成环境的体积与准备时间。三者合并观察：香山的验证基础设施正在同时做「跑得更快（NEMU/GEM5）」与「起得更轻（CI 容器）」两件事，属于大规模回归测试前的常态优化。

1.4 LLVM/Clang RISC-V 后端：RV32 下 f16 转换拆解，新增 packed widening add accumulate 内建

日期：2026-09-14　来源：OpenXiangShan/llvm-project 提交记录

香山维护的 LLVM 分支在窗口内推进 17 次提交，其中两条为 RISC-V 目标相关：Kane Wang 于 15:42 提交 [RISCV] Lower f16 to i64 fp_to_[su]int via i32 on RV32 (#222829)，在 32 位 RISC-V 上把半精度浮点到 64 位整数的转换拆解为经 i32 的两步路径，属 RV32 目标下的代码生成合法化修正；陈子昂于 15:05 提交 [Clang][RISCV] Add packed widening add accumulate intrinsics (#221622)，为 RISC-V 向量扩展增加「打包加宽累加」内建函数——这类内建直接对应向量点积/矩阵乘累加场景，是 AI 推理与信号处理内核的常用原语。其余提交为上游通用改动（GlobalOpt 断言修复、分配器对齐、ORC 运行时、libc 数学函数、LoongArch/SPARC 测试等）。结合本期香山在向量通路上的多次修复，可以看出香山的软件侧（编译器与参考模型）与硬件侧（向量执行）在同一周内同步推进。

1.5 CORE-V 生态：Wally 修 PWM 自检与 IFU 三连缺陷，CVFPU 补除法开方 NaN boxing

日期：2026-09-14　来源：openhwgroup/cvw 提交记录、openhwgroup/cvfpu 提交记录、openhwgroup/uap 提交记录

OpenHW 集团的开源核生态在窗口内多点推进。CORE-V Wally（cvw，面向教学的配置化 RISC-V 处理器）由 David Harris 于 09-15 03:56 提交 #1830，修正 PWM（脉宽调制）外设的 pending 位、计数器复位与 pwms 寄存器写入问题，并新增一套完整的自检式 PWM 测试；同日 IFU（取指单元）缺陷被成批修复，Rose Thompson 合并 #1855（satp 相关）、#1862（JALR 最低位处理）、#1861（flushm）、#1860（总线故障），四项均为取指路径正确性问题；Syed-Moeed-Ali 于 13:01 提交 #1864，修正不支持 U-mode 时 mcounteren 被非法访问的问题。CVFPU（参数化浮点单元，支持标准 RISC-V 浮点格式）由 Ihsane Tahir 于 16:32 合并 #185，修复除法与开方路径的 NaN boxing。UAP（统一 RISC-V 接入平台）由 sergialcaide 于 18:31 提交 #168，新增 BSC IP 卡支持。整体看，CORE-V 家族本窗口的改动集中在外设自检与取指/特权态正确性，与香山同期「正确性打磨」的取向一致，反映开源核社区普遍进入功能验证深水区。

2.1 JetKVM Mini：ESP32-P4X 双核 RISC-V 的 39 美元 IP-KVM，内置 H.264 硬编，10 月 26 日开售

日期：2026-09-14　来源：CNX Software、JetKVM 官方博客《Introducing JetKVM Mini》、产品页

JetKVM 发布旗下 IP-KVM 的紧凑低价版本 JetKVM Mini，产品页明确其主控为 ESP32-P4X（双核 RISC-V，400 MHz），配 32 MB PSRAM 与 16 MB flash，内置硬件 H.264 编码器——视频在芯片内采集并编码后通过 WebRTC 推送到浏览器，最高支持 1080p30 或 720p60；主机侧（Windows/macOS/Linux）安装 JetKVM OS Services 后可支持最高 4K 采集、共享剪贴板、来宾终端与文件传输。产品分两款：有线版 JetKVM Mini（RJ45 百兆以太网）售价 39 美元，无线版 JetKVM Mini W 售价 42 美元（三只装降至每只 33 与 36 美元）；Mini W 额外搭载 ESP32-C5（同样为 RISC-V 内核，单核 32 位 RISC-V 最高 240 MHz）提供双频 Wi-Fi 6、蓝牙 LE 配网与 802.15.4（Zigbee/Thread）。形态为 42 × 42 × 23 mm、5 V 500 mA，带 240 × 240 IPS 状态屏，支持 TF 卡虚拟介质、JetKVM Cloud 远程访问、网络唤醒、MQTT 与 Home Assistant、OIDC 登录以及带自动回滚的 OTA。厂商表示针对 ESP32-P4X 重写了固件并自首日起开源，沿用同一套 Web 界面与云端协议。产品将于 2026 年 10 月 26 日通过授权渠道开售。

观察：这是 ESP32-P4 系列（RISC-V 应用级 MCU）在「远程带外管理」这一细分市场的又一次产品化落地，与本刊 09-14 期收录的「ESP32-P4 跑起《古墓丽影》」同源——同一颗双核 400 MHz RISC-V 芯片，一端展示图形渲染能力边界，一端以内置 H.264 硬编支撑 39 美元的商用 IP-KVM，说明 RISC-V 应用级 MCU 的「能力上限」与「成本下限」正在同时被推开。另需注意该产品同时使用 ESP32-P4X 与 ESP32-C5 两颗 RISC-V 芯片（C5 为 Wi-Fi 6 连接芯片），是国产 RISC-V 无线连接芯片进入海外开源硬件产品的又一实例。

4.2 数据流架构与物理 AI 的交汇：睿芯高光 D35 的具身智能落点

日期：2026-09-14　来源：见今日重点条目信源

把今日重点的睿芯高光 D35 放在具身智能视角下看，其给出的四条场景线中有两条直接落在机器人方向：具身智能（机器人、无人车域控等「感知加决策加控制」一体化场景）与舱驾一体（智能座舱与驾驶域控融合）。其技术论证的核心是端侧能效比而非峰值算力——理由是物理 AI 场景下供电、体积与成本构成硬约束，端侧不可能外接数据中心，因此「单位瓦特能完成多少推理」取代「模型参数有多大」成为胜负手；数据流架构因为省去指令调度开销、数据在计算单元间直接流动、缺乏分支预测与缓存失效带来的延迟不确定性，被其定位为更匹配这类确定性低延迟推理的路线。硬件上 128 GB 大显存的产品定义，指向「大模型在端侧本地部署、数据不出端」这一与具身智能隐私与实时性需求直接对应的能力主张。对照观察：本刊同期持续跟踪的进迭时空路线是「RISC-V 通用 CPU 加自研推理后端加模型库」（见 3.3 与 4.1），睿芯则代表「RISC-V 控制核加专用数据流加速阵列」的非通用路线；两者在 RISC-V 与具身智能的结合上给出了不同答案。前者生态门槛低、复用通用软件栈，后者能效上限高、但依赖自有 SDK 与算子库，生态建设难度显著更大——这也正是其「光荣社区」与 SDK 工具链能否落地成为关键变量的原因。本报告对其量产与性能宣称保持厂商口径标注（详见今日重点条目）。

五、总结与趋势观察

  • 数据流架构在中国出现量产样板，RISC-V 与「非冯诺依曼」路线的组合值得跟踪。苏州睿芯「高光 D35」经苏州工业园区官方渠道确认量产，定位端侧与边缘的物理 AI 加速，配 128 GB 显存，主打单位功耗推理吞吐，并规划面向数据流架构的开发者社区。这是本刊 9 月首次收录该类事件。其关键在于：若量产与能效比宣称获第三方验证，RISC-V 在 AI 加速领域将不止「通用核加向量/矩阵扩展」一条路径，而数据流路线长期停留学术阶段的历史也可能被改写。当前证据仅为厂商与官方园区口径，须跟踪 SDK 开放度、社区启动与真实出货。

  • 开源高性能核集体进入「正确性深水区」。香山当日 8 次提交几乎全是分支预测、自修改代码分支训练、异常与不可缓存同时触发的 PC 传递、向量寄存器 NaN boxing 等边界条件修复；CORE-V Wally 同窗口修复 PWM 自检与 IFU 四连缺陷、CVFPU 修除法开方 NaN boxing。两家开源核的推进重心都落在「正确性验证驱动」，新特性节奏让位于已有功能的可靠性收敛。

  • 香山内存系统向「CoupledL2 加独立 L3」演进。XSCache 一次性批次合入 18 次提交，核心是 ZhuJiang（L3 方向）子模块的参数化、复位与构建修复、仿真环境适配，以及配套的 TestTopZhuJiang 测试顶层与 HN 性能计数器按模块路径命名。这表明 L3 缓存正在从开发走向可验证状态，配套的仿真、复位与性能采集链路已同步补齐。

  • 国产 RISC-V 应用级 MCU 同时推开能力上限与成本下限。JetKVM Mini 以 ESP32-P4X 双核 400 MHz RISC-V 加内置硬件 H.264 编码器，做到 39 美元的有线 IP-KVM 与 42 美元的无线版本，且固件首日开源；无线版另用 ESP32-C5 提供 Wi-Fi 6 与 Zigbee/Thread。与本刊上期收录的「ESP32-P4 跑起古墓丽影」互为印证：同一颗芯片既能跑 3D 游戏引擎，也能支撑商用带外管理设备。
