1.1 HAC 高保证密码规范第四日密集修订：Zl→Zkl 改名提案、WARL 规则、Smacestatus 整合（30+ 笔）

日期：2026-08-18（12:05 ~ 22:26 北京时间）　来源：riscv/riscv-high-assurance-cryptography GitHub

高保证密码学（HAC，面向 FIPS 140-3 级实现的密码扩展规范）仓库窗口内合入 30+ 笔提交，延续前三日的评审收敛主线，且进入”命名与结构收尾”阶段：

  • 命名定稿：Changed Zl extension prefix to Zkl（Zl 前缀改名 Zkl）、Added proposal for ratified names（批准名提案）、Fixed Zlkn dependencies、Reformatted new names table——扩展命名从工作名向批准名过渡；
  • 语义定稿：Defined WARL rules for aceiobuflen, aceiobuftop and acestart（三条关键 CSR 的 WARL 规则）、Clarify invalid aceiobuftop exception behavior（非法 aceiobuftop 异常行为）、Integrate mcrstatus CSR into Smacestatus extension（mcrstatus 并入 Smacestatus 扩展）、Clarify vector I/O replacement rules、Default CSR values out of reset（复位默认值）；
  • 文档结构重组：pseudocode 示例移至 Book 4、有限域运算定义移位、ace-introduction 连续多笔修订。

连续四日合计 80+ 笔修订，说明 HAC 正从”功能定义”推进到”命名冻结 + 语义收尾”阶段，距正式评审/批准更近一步，与本周 RISC-V 官方安全/密码主线（Spectre 论文、SPMP、riscv-security-model）完全同向。

香山主分支 08-18 02:41 UTC（10:41 北京时间）批量合入 13 笔提交，其中大部分为作者日期 07-22 ~ 08-13 的存量合入，一笔为当日新提交：

  • 当日新提交：perf(btb): update btb replacer using training touch strategy instead of prediction touch strategy——BTB 替换器改用”训练触碰”策略替代”预测触碰”策略，是分支目标缓冲器的替换算法级优化；

XSAI（AI 加速器）同步合入 fix(rob): assert AMU request lane ordering（作者 08-12）。香山主分支连续两日批量合入，开发节奏保持活跃。

1.3 riscv-unified-db 两笔指令语义修复：vector CSR 位宽、压缩 FP 访存寄存器文件

日期：2026-08-18 16:25 ~ 16:44（北京时间）　来源：riscv/riscv-unified-db GitHub

RISC-V 官方统一指令数据库（unified-db）窗口内合入两笔语义级修复：

  • fix(csr): seven vector CSRs take XLEN, not MXLEN (#2489)——七个向量 CSR（vstart/vxsat/vxrm/vcsr/vlenb/vtype 等）取 XLEN 而非 MXLEN；

UDB 作为 arch-test、Sail 等工具链的机器可读指令语义单一来源，此类低级修复直接影响测试与仿真正确性，属”规范基础设施”级维护（连续第三日收录该类动态）。

二、产品与生态动态

2.1 头条：平头哥官宣 XuanTie C950 原生运行 Qwen-3.8 27B——RISC-V 大模型推理的”Day 0”时刻

日期：2026-08-18（Wccftech 报道于 08-19 00:10 北京时间）　来源：Wccftech

阿里平头哥（T-Head Xuantie RISC-V 团队）官宣其旗舰 RISC-V 芯片 XuanTie C950 对最新开源模型 Qwen-3.8 27B 提供 Day 0（发布即支持） 原生推理支持，具体指标：64 核 C950（带 RVV 向量扩展）解码速度 30 tokens/s，首 token 延迟（TTFT）仅 1.9 秒。要点：

  • 芯片背景：C950 于 2026 年 3 月发布，定位”边缘 AI 的服务器级 RISC-V 处理器”——单芯片 64 个计算核、频率最高 3.20 GHz，不依赖 GPU 执行 AI 负载；配标准 L1、灵活可配置 L2、可选共享 L3，带硬件级智能数据预取。TSMC 5nm 制造（据 Wccftech）。
  • 模型背景：Qwen-3.8 27B 为 270 亿参数开源权重模型，官方称编码能力对标 Opus 4.5，可在单台 MacBook（32GB 内存）上运行——属”中尺寸高性价比”推理模型。
  • 战略意义：这是阿里”类英伟达垂直整合”打法的又一落子——自研芯片对自研模型 Day 0 优化，形成”模型-芯片-云”闭环；C950 可与其数据中心 AI 加速器组合，分摊推理负载。

这是 2026 年 RISC-V 阵营在”端侧/边缘大模型推理”方向最具标志性的进展之一：此前的 RISC-V 大模型演示多停留在小模型或量化蒸馏，而 C950 在 64 核 RVV 上跑 27B 级模型达到可用吞吐，验证了 RISC-V 多核+向量扩展路线在推理场景的可行性（详见 3.1 平头哥深挖）。

2.2 Xen 项目成立安全委员会（AMD/EPAM/Renesas 创始成员），推进 RISC-V 完整发布

日期：2026-08-18 10:59（北京时间）　来源：The Register

开源 Hypervisor Xen 项目成立 Safety Committee（安全委员会），创始贡献成员为 AMD、EPAM、Renesas，目标推动 Xen 符合 IEC-61508 等功能安全正式标准——面向汽车、机器人等工作负载隔离场景（”分区机器人大脑”）。同时设立新的 Premier Plus 会员层级，服务寻求功能安全认证的组织。波音（Boeing）近期加入 Xen 项目，据 The Register 了解其兴趣点正在于安全工作。与 RISC-V 的关联：Xen 月初发布的更新”推进了面向 RISC-V 处理器完整功能发布的工作”——Xen on RISC-V 距完整可用再进一步。虚拟化层的功能安全（隔离、分区、认证）与 RISC-V 在汽车/机器人的落地直接相关，值得跟踪。

四、重点方向专章：具身智能与机器人

4.1 安全虚拟化入场：Xen 安全委员会瞄准”机器人工作负载隔离”

Xen 项目成立安全委员会（AMD/EPAM/Renesas 创始成员）并推动 IEC-61508 合规，明确将”机器人”列为工作负载隔离的目标场景——”分区机器人大脑”意味着实时控制、导航、感知等混合关键性负载在同一硬件上的隔离运行成为可认证路径。对 RISC-V 具身智能的意义：Xen 的 RISC-V 支持正在推进”完整功能发布”，汽车/机器人领域的安全认证虚拟化层若在 RISC-V 上落地，将补齐”实时核+应用核”双核异构（滴水湖论坛路线）之外的第三种隔离形态——虚拟机级分区。Renesas（车规 MCU 主力）+ AMD 的组合也暗示该委员会的多架构定位。

4.2 C950 跑 27B 模型：RISC-V 边缘大模型推理的具身智能潜力

C950（64 核 RVV、3.2 GHz、30 tok/s）验证了 RISC-V 多核+向量路线在 27B 级模型推理上的可用性。对具身智能而言，端侧/边缘大模型推理是”大脑上移”的关键环节——VLA（视觉-语言-动作）模型若能在 RISC-V 平台达到可用吞吐，将降低整机对 GPU 的依赖。虽然 C950 目前定位边缘服务器而非嵌入式（功耗/体积与机器人本体部署仍有距离），但它是”RISC-V 跑大模型”从演示到产品的标志性一步，为后续中尺寸芯片下放提供了基线数据（30 tok/s / 1.9s TTFT 可作为同类方案的参照系）。

4.3 进迭”感知-决策-运控”栈更新

model-zoo-vision 新增 DEIMv2 COCO 检测器（实时检测方向）、model_zoo_rl 的 Eigen 构建修复合入主分支——进迭时空的 K3 humanoid RL 运行时与视觉模型库本周持续双线推进，与其”感知（vision）-决策（RL）-运控（SPERT NPU）”三层布局一致。节奏为”维护+增量”档，无重大新发布。
