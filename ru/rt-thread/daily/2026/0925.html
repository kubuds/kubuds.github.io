1. Динамика ядра и версий

1.1 BSP платы разработки Qinheng CH32V203C8T6 включён в основную ветку (09-24)

Дата: 2026-09-24 16:21 (пекинское время, время включения; предложение создано вечером 09-22)　Источник: PR #11827, коммит включения 386b877b

В окне в основную ветку включён новый комплект поддержки уровня платы: BSP платы разработки Qinheng Micro (WCH) CH32V203C8T6-EVT-R0, размещённый в bsp/wch/risc-v/ch32v203c-evt-r0. Эта плата основана на ядре Qingke V4B (CH32V20x_D6), имеет 64KB Flash с нулевым временем ожидания и 20KB SRAM; поскольку официальный SDK предоставляет только стартовый файл для D8W, а для D6 напрямую вызывает Exit(), стандартная сборка пакета не может создать прошивку. Предложение дополняет её таблицей векторов прерываний D6 (символ программного прерывания SW_handler) и скриптом компоновки для 64KB/20KB и исправляет скрипт пакета SDK только при этом условии, не затрагивая процесс D8W. Образ по умолчанию включает GPIO и UART1 (USART1 с мультиплексированием PA9/PA10), PWM, ADC, RTC, независимый сторожевой таймер и USB-устройство оставлены в menuconfig (ёмкость 64KB не позволяет одновременно разместить USB и четыре вышеуказанных типа периферии). Предложение также включает два исправления общих драйверов: drv_usbd.c корректирует 16-битное смещение SRAM для USBFS DMA и временную последовательность записи SET_ADDRESS (буфер конечной точки должен находиться в SRAM, длина пакета на полной скорости 64 байта), drv_iwdt.c добавляет адаптацию для серии CH32V2. Предложение содержит всего 4 коммита, 26 файлов (+2216/-57).

1.2 Дефект семантики ширины rt_vsnprintf и предложение по исправлению ядра (09-24)

Дата: 2026-09-24 20:52 ~ 21:29 (пекинское время, время отчёта о дефекте и предложения по исправлению)　Источник: Issue #11833, PR #11834

Участник сообщества в окне отправил отчёт о дефекте ядра и сопутствующее исправление: текущая реализация rt_vsnprintf (особенно tiny-версия) неверно обрабатывает семантику %[width].[precision]s, минимальная ширина ошибочно трактуется как максимальная ширина и обрезает строку — например, %3s при форматировании “abcdef” выводит “abc” вместо полной строки, варианты с выравниванием по левому краю %-3s и %*s также затронуты. Предложение по исправлению отправлено синхронно, изменения охватывают rt_vsnprintf_std.c, rt_vsnprintf_tiny.c и соответствующий модульный тест TC_rt_sprintf.c (всего 3 файла, +37/-18), содержание — дополнение проверки границ, реализация комбинированной функциональности ширины и точности и оптимизация тестовых случаев. Отчёт о дефекте имеет 3 обсуждения, предложение по исправлению находится на стадии рецензирования.

1.3 В очередь рецензирования добавлены три предложения: исправление сетевого стека и очистка сборки (09-24)

Дата: 2026-09-24 14:15 ~ 17:52 (пекинское время, время создания)　Источники: PR #11831, PR #11835, PR #11832

В этом выпуске в очередь на рассмотрение добавлено всего пять предложений, из которых исправление vsnprintf в ядре см. в 1.2, поддержка платы ESP32-C6 см. в 3.1, а в данном разделе собраны остальные три. Первое исправляет дефект распределения портов в lwip-nat: исходная реализация выделяла порт преобразования по счётчику сканирования, а не по индексу свободного слота; при входе в путь выделения счётчик всегда равен размеру таблицы, из-за чего каждое новое отображение получало один и тот же порт, параллельные сессии UDP/TCP конфликтовали между собой, а обратный трафик мог соответствовать неверной записи таблицы; предложение также завершает адаптацию к lwIP 2.1 (переименование заголовочных файлов и интерфейсы тайм-аутов) и ужесточает условия применения NAT до совпадения правил как по исходной, так и по целевой сети, а при заполнении таблицы ICMP вытесняет самую старую запись по LRU (1 файл, +41/-11). Второе добавляет отсутствующий заголовочный файл string.h в lwip-dhcpd: dhcp_server_raw.c напрямую вызывает memcmp / memset / strlen / strncmp / strchr, не включая стандартный заголовок; неявное объявление на 64-битных целях усекает возвращаемый указатель strchr() (1 файл). Третье удаляет избыточное определение макроса __RT_IPC_SOURCE__ в components/drivers/ipc/SConscript (1 файл).

3. Экосистема и адаптация производителей

3.1 Предложение BSP для отладочной платы Espressif ESP32-C6 и параллельный коммит исходников пакета (09-25)

Дата: 2026-09-25 01:20 ~ 02:38 (пекинское время, время создания и обновления предложения и сопутствующего предложения по пакету)　Источники: Основной PR #11836, PR #17 пакета esp-idf

Участник сообщества в окне мониторинга отправил в основную ветку предложение BSP для отладочной платы Espressif ESP32-C6-DevKitC-1: модуль ESP32-C6-WROOM-1 (RISC-V, 8MB Flash), добавлен bsp/ESP/ESP32_C6, по умолчанию включены GPIO, UART0 (GPIO16/17) и ADC; предложение подчёркивает, что для C6 необходимо использовать специальный образ bootloader (нельзя переиспользовать образ от C3), Flash — DIO 8MB 80MHz, смещение приложения 0x10000. Поскольку пакет esp-idf из upstream не обновлялся с 2023-11-26 и не содержит исходников для C6, участник параллельно отправил в репозиторий пакета PR #17, добавляющий исходный код сборки scons для C6; оба предложения находятся на рассмотрении (на стороне основной ветки 2 коммита, 40 файлов, +9492/-50). Этот участник — то же лицо, что и автор BSP CH32V203 из 1.1, в один и тот же день охвативший две линейки чипов RISC-V: WCH и Espressif.

3.2 Сообщество выпустило проект портирования RT-Thread Nano без IDF: работает на ESP32-S31 (09-25)

Дата: 2026-09-25 10:04 (пекинское время, время отправки)　Источники: репозиторий esp32s31_rtt_nano

Один разработчик из сообщества опубликовал проект портирования RT-Thread Nano для Espressif ESP32-S31 (двухъядерный RISC-V, тактовая частота 320 МГц, встроенные 16 МБ Flash и 16 МБ PSRAM). Особенность проекта в том, что он полностью обходит систему сборки ESP-IDF: самостоятельно написанный ассемблерный код запуска и скрипт компоновки, прямая компиляция с помощью riscv32-esp-elf-gcc, независимая прошивка через esptool. Образ загружается bootROM чипа напрямую из Flash по адресу 0x2000 (без использования вторичного загрузчика IDF); консоль работает через встроенный USB-Serial/JTAG, для тика используется SYSTIMER, прерывания обрабатываются через CLIC, периферия PIN / SPI (включая QSPI) / I2C подключена к фреймворку устройств RT-Thread и может быть проверена непосредственно в msh. Проект прошёл верификацию воспроизводимой сборки (89 отслеживаемых файлов собираются в побайтово идентичный образ в чистом каталоге). Это личный проект, предоставленный сообществу для ознакомления.

5. Итоги и наблюдения за тенденциями

5.1 Тенденции за последние сутки (24.09 ~ 25.09)

  • Три события по платформенной поддержке за один день, и все на RISC-V чипах: Qinheng CH32V203C8T6 влит в основную ветку, предложение по отладочной плате Espressif ESP32-C6 поступило на рассмотрение, сообщество портировало RT-Thread Nano на ESP32-S31 — RISC-V чипы трёх разных производителей в один день появились в цепочке платформенной поддержки, доля RISC-V в платформенной экосистеме RT-Thread продолжает расти.
  • Очередь рассмотрения сосредоточена на дефектах ядра и сетевого стека: семантика ширины rt_vsnprintf, распределение портов lwip-nat, отсутствие заголовочного файла lwip-dhcpd — все три проблемы были активно представлены сообществом, исправления, ориентированные на качество, стали основной частью этого выпуска.
  • Темп основной ветки остаётся низким: в окне мониторинга в основную ветку влит только один BSP, что соответствует темпу последней недели — единичные вливания и обработка очереди рассмотрения.
  • Официальные каналы молчат тридцать шестой день: страница новостей официального сайта по-прежнему недоступна для проверки, информация о продуктах и мероприятиях продолжает появляться сначала на форуме и на GitHub.
