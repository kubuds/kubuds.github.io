1. Динамика ядра и версий

1.1 Основной репозиторий: нулевое слияние продолжается третий цикл; новый PR #11780 исправляет утечку памяти метаданных SDIO CIS

Дата: 2026-09-05 (PR создан 16:59 пекинское время)　Источник: RT-Thread/rt-thread PR #11780 (связанный issue #11724)

Основной репозиторий rt-thread в этом окне: нулевое слияние, ноль новых issue; последнее слияние по-прежнему #11776 от 09-03 (продолжение третьего цикла), релиз по-прежнему v5.2.2 (2025-10-31). Единственное пополнение в окне — PR #11780 «[components][sdio] Fix CIS tuple memory leak», представленный разработчиком сообщества Huoyanlifusu: исправляет проблему, указанную в #11724 — при обработке части CIS tuple, таких как CISTPL_FUNCE и CISTPL_VERS_1, в sdio_read_cis() выделяется память, но после завершения обработки не освобождается; повторная инициализация/деинициализация SDIO-устройства приводит к утечке памяти. Решение: после завершения обработки вышеупомянутых двух ветвей временный tuple освобождается; неизвестные tuple по-прежнему управляются связным списком func->tuples и единообразно освобождаются через sdio_free_cis(). Изменён 1 файл, чистое добавление 2 строк, автор проверил на BSP qemu-vexpress-a9. Этот PR — третий подряд компонентный фикс автора (#11756 исправление краха по нулевому указателю в netdev ping было слито 08-26; #11774 исправление выхода за границы в sal SIOCGIFCONF всё ещё на ревью), продолжающий основную линию контрибуции «компонентные исправления безопасности памяти». Остальные пункты очереди ревью без изменений по сравнению со вчерашним: #11779 рефакторинг фреймворка CAN после заявления мейнтейнера CYFS3 09-03 новых комментариев не имеет, #11775 (c908 rt-smart), #11772 (куча ASan), #11689 (stm32 SPI BDMA) и другие остаются open без движения.

Дата: 2026-09-06　Источник: официальный новостной API RT-Thread

Официальный новостной API (категория rt_org) по-прежнему содержит 5 старых записей, самая свежая — репортаж об инвестиционном форуме в Абу-Даби от 2026-06-17; семнадцатый день подряд без пополнений. Следующее внешнее окно — выставка elexcon 2026 в Шэньчжэне 9-11 сентября (участие Ruiside, анонс «полного набора AI-оборудования» уже включён 08-30); сегодня последние выходные перед открытием, обратный отсчёт 3 дня. На стороне китайских и английских медиа (Google News через прокси, окна 1d/2d/3d) новых сообщений RT-Thread в окне нет; самый свежий медийный контент — по-прежнему публикация работ сообщества в EE Times China от 09-04 (включена вчера). В период молчания официального канала темп производства контента сообществом и медиа не снизился.

3. Экосистема и адаптация производителей

3.1 canopennode-rtt: завершена сторона контроллера CiA402 и диагностика/EMCY, запущена ветка универсального I/O profile CiA401

Дата: 2026-09-05 ~ 09-06 (14:08 ~ 10:06 следующего дня по пекинскому времени, 6 коммитов)　Источник: wdfk-prog/canopennode-rtt (ветка CIA401)

После включения вчера в 11:08 режимов циклической синхронизации CSP/CSV/CST разработка в этом репозитории не остановилась: в ветке по умолчанию добавлены «CiA402 device diagnostics and EMCY bridge» (диагностика устройств CiA402 и мост аварийных сообщений EMCY, 09-05 14:08), «Добавлена поддержка контроллера CiA402 и соответствующие тесты» (16:13, покрытие CiA402 расширено со стороны устройств на сторону контроллера) и очистка и рефакторинг документации (16:36); затем открыта новая ветка CIA401, и начиная с 09-05 21:53 последовательно реализованы «generic I/O device profile core», «digital event and output fail-safe support» и «Поддержка событий и функций отказобезопасности аналогового ввода-вывода» от 09-06 10:06. Таким образом, данный порт CANopenNode за неделю с 09-03 завершил двухлинейное расширение: профиль управления движением (CiA402: многоосевое управление, PP/PV/Homing, CSP/CSV/CST, диагностика и EMCY, сторона контроллера) и профиль универсальных устройств ввода-вывода (CiA401: цифровые/аналоговые события и отказобезопасность). Магистральное направление развития экосистемы CAN/промышленных полевых шин остаётся наиболее активным во всём сообществе. С учётом того, что этот же автор параллельно продвигает рефакторинг фреймворка Generic CAN в основном репозитории (#11779), тенденция параллельного движения по двум линиям «уровень фреймворка + уровень приложений» сохраняется.

3.2 Справочно по экосистеме: фреймворк отладки gdr GDB завершает адаптацию FreeRTOS, RT-Thread сохраняет первостепенную поддержку

Дата: 2026-09-05 (завершающий коммит в 17:39 по пекинскому времени)　Источник: flespark/gdr

topic:rt-thread репозиторий flespark/gdr (вспомогательный фреймворк отладки RTOS в среде GDB Python, предоставляющий дерево команд RTOS, таких как rtt threads/rtt timers, pretty-printer для объектов ядра и вспомогательные функции) в рамках окна мониторинга получил коммит «refactor(freertos): wrapup of new rtos support, code and docs quality enhance», завершающий второй адаптер FreeRTOS. Согласно его README: RT-Thread (3.1.x / 4.0.x / 4.1.x, проверено на всей линейке Cortex-A9, RV64 начиная с 4.0.4) по-прежнему остаётся первостепенным объектом поддержки; завершённый в окне мониторинга канал FreeRTOS (V10.3.0 ~ V11.3.x) на QEMU дополнен проверкой 64-битного RISC-V lane и двухъядерного SMP MPS2-AN521. Это расширение универсального фреймворка, а не специализированный коммит для RT-Thread, однако для пользователей RT-Thread (включая цели RISC-V) это положительный ориентир по инструментарию отладки GDB, поэтому включено как справочно по экосистеме.

5. Итоги и наблюдения за тенденциями

  • Со стороны ядра: основной репозиторий — ноль включений, входит в третье окно (последнее включение #11776, 09-03), новый PR только один — #11780 — исправление утечки памяти SDIO CIS tuple (1 файл, +2 строки, проверка qemu-vexpress-a9), автор третий раз подряд выполняет компонентное исправление, в очереди ревью других изменений нет, релиз по-прежнему v5.2.2, период накопления продолжается.
  • Со стороны экосистемы: canopennode-rtt в течение недели продвинул порт CANopenNode от управления движением (CiA402, все режимы) к профилю универсального ввода/вывода (CiA401) и поддержке на стороне контроллера — это наиболее активная линия разработки в сообществе на данный момент; фреймворк вспомогательной отладки GDB gdr завершил второй адаптер FreeRTOS, поддержка RT-Thread (включая RV64) остаётся приоритетной возможностью.
  • Со стороны официальных источников/СМИ: официальный API новостей молчит 17-й день подряд; в 24-часовом окне СМИ — ноль новых публикаций (прокси и проверка источников работают нормально); до elexcon 2026 (09-09~11, Шэньчжэнь) осталось 3 дня, предконференционное затишье — ожидаемый ритм.
  • Тренд за последние три дня (09-04 ~ 09-06): CiA402 многоосевой и PP/PV/Homing, EET перепечатало работу сообщества по USB-монитору вторичного экрана, официальное молчание 15-й день (09-04) → env включает WebUI keep_alive (#294), CiA402 циклическая синхронизация CSP/CSV/CST внедрена, официальное молчание 16-й день (09-05) → PR #11780 исправления утечки sdio CIS, диагностика CiA402/EMCY/сторона контроллера и запуск ветки CiA401 I/O profile, официальное молчание 17-й день (09-06). Текущая основная линия продвижения — «итерация опыта WebUI официального инструментария + расширение экосистемы CANopenNode с двумя профилями», внешняя активность накапливается к elexcon 2026.
