1. Динамика ядра и версий

1.1 BSP отладочной платы NXP FRDM-MCXC162 вошёл в основной репозиторий, ревью заняло три дня (PR #11785)

Дата: 2026-09-08 (слияние в 16:15 пекинского времени, т.е. 08:15:21Z)　Источник: RT-Thread/rt-thread commits (PR #11785)

#11785 [bsp][nxp] Add FRDM-MCXC162 BSP support (отправлен yandld), включённый в очередь ревью во вчерашнем отчёте, сегодня днём официально слит в master. Этот PR был создан вечером 09-07 (на момент включения вчера он ещё проходил ревью, сегодня утром были обновления), и всего за три дня ревью было завершено слиянием — темп довольно быстрый. FRDM-MCXC162 — отладочная плата начального уровня серии NXP MCX C1xx, BSP покрывает стандартную адаптацию периферии экосистемы MCUXpresso. yandld — давний контрибьютор NXP BSP, за этот месяц он последовательно отправил BSP для нескольких плат NXP; данное слияние вместе с его утренней массовой очисткой старых PR NXP BSP 09-08 (включено вчера в 1.3) образует замкнутый цикл упорядочивания очереди «новые платы приходят, старые заявки закрываются». Релиз по-прежнему v5.2.2 (2025-10-31), новых релизов нет.

1.2 В основной репозиторий добавлены ещё два коммита: сохранение порядка путей include для Keil (#11741) и чтение регистров GPT PWM Renesas (#11753)

Дата: 2026-09-08 ~ 2026-09-09　Источник: RT-Thread/rt-thread commits (commit 66648255, commit d7ea2bce)

В окне в основной репозиторий были добавлены ещё 2 коммита:

  • [tools][keil] Сохранять порядок путей include（влито 09-08 17:03 по пекинскому времени, PR #11741）：исправлена проблема изменения порядка путей include при генерации проекта Keil, обеспечен ожидаемый приоритет путей. Данный PR создан 08-24, влит примерно через две недели ревью, относится к исправлениям надёжности инструментальной цепочки (генерация проекта Keil MDK); вместе со влитым вчера исправлением переполнения sal и исправлением выхода за границы имени хоста AT относится к недавнему ритму «регулярного разбора очереди ревью».
  • [bsp/renesas][drivers] Считывать настройки PWM из регистров GPT（влито 09-09 10:33 по пекинскому времени, PR #11753, commit d7ea2bce）：изменение в драйверном слое HAL Renesas drv_pwm.c (+94/-22) — переход на прямое чтение текущей конфигурации PWM (период, коэффициент заполнения и т. д.) из регистров таймера GPT, что обеспечивает соответствие состояния драйвера фактической конфигурации оборудования и предотвращает рассинхронизацию программного кеша и регистров. Это очередная итерация драйверов BSP серии Renesas RZ/RA в этом месяце — 08-27 уже было два влития: исправление конфигурации SPI во время выполнения Renesas и триггер проверки карты SDHI (оба включены в отчёты); непрерывная доработка драйверов BSP Renesas является одной из текущих основных линий адаптации производителей. Данное влитие находится на границе окна (сегодня утром в 10:33) и является самым последним реализованным действием.

3. Экосистема и адаптация производителей

3.1 В окне canopennode-rtt добавлены три функции CiA401: поддержка профиля устройств RT-Thread, логические устройства в многоустройственных узлах, управление тестированием через MSH

Дата: 2026-09-08 (пакетное слияние в 17:56 по пекинскому времени, то есть 09:56:22Z)　Источник: коммиты wdfk-prog/canopennode-rtt

Внешний экосистемный репозиторий canopennode-rtt (порт CANopen, сопровождает wdfk-prog) в окне мониторинга пакетно принял три коммита с новыми функциями (время автора — утро 09-07 ~ 09-08, единое слияние вечером 09-08):

  • feat[canopennode][cia401]: add RT-Thread device profile support: в CiA401 (профиль устройств ввода-вывода) добавлен слой поддержки профиля устройств, ориентированный на RT-Thread;
  • feat[CiA401][device]: support logical devices in multiple-device nodes: поддержка логических устройств в сценарии многоустройственных узлов (несколько логических устройств в одном узле);
  • feat[CIA401][RTT]: add MSH bench controls for device testing: добавлено управление бенчмарк-тестированием через командную строку MSH для удобства тестирования устройств.

Это вторая партия функций CiA401 после двух событий аналоговых величин CiA401 и отказобезопасности 09-06 (уже включённых), что знаменует продвижение переноса профиля устройств CANopen CiA401 на стороне RT-Thread от «уровня протокольных кадров» к уровню «профиль устройств + множественные логические устройства + цепочка инструментов тестирования», функциональная область продолжает расширяться. wdfk-prog одновременно продвигает рефакторинг жизненного цикла драйвера CAN в официальном репозитории (#11779); «перенос внешней экосистемы + официальный фреймворк» по двум линиям параллельно — это самый активный контрибьютор в текущем направлении CAN/CANopen в RT-Thread.

3.2 Индекс packages: два обновления — корректировка конфигурации Tencent IoT SDK, рефакторинг параметров конфигурации autogen_parameter_manager

Дата: 2026-09-08 (17:56 / 18:16 пекинское время)　Источник: RT-Thread/packages commits (5d983b53, 866a20b5)

Репозиторий индекса пакетов packages прервал молчание с 09-01 (после добавления индекса CANopenNode — неделя без коммитов), в окне мониторинга добавлено два:

  • Update Tencent IoT SDK package configuration (#2034): обновление конфигурации Kconfig и package.json пакета Tencent Cloud IoT SDK (iot/iot_cloud/tencent-iot-sdk) — регулярное сопровождение конфигурации пакета SDK облачной платформы;
  • refactor(autogen_parameter_manager): корректировка значений по умолчанию опций конфигурации Kconfig: пакет misc/autogen_parameter_manager удаляет принудительный выбор зависимостей RT_USING_HEAP и RT_USING_CAN, а также меняет значения по умолчанию AUTOGEN_PM_USING_NVM, AUTOGEN_PM_NVM_OBJECT с y на n — снижение порога внедрения пакета, позволяющее генератору параметров управления питанием устанавливаться опционально и в конфигурациях без кучи/без CAN. Направление рефакторинга согласуется с недавними корректировками ряда пакетов «убрать зависимости, повысить гибкость» (сравните с ритмом добавления новых индексов, таких как CANopenNode 09-01).

4. Отраслевое применение

Нет сообщений о новых кейсах внедрения. В окне нет новостей о новых отраслевых применениях/кейсах внедрения; наиболее существенное действие на отраслевой стороне — упомянутая в 2.2 сегодняшняя онлайн-трансляция в 17:00 разбора конкурсной задачи AI-промышленного контроля качества промышленного подразделения Ruiside — промышленная платформа Ruiqing (промышленное ядро + NCNN + YOLOv3), ориентированная на восполнение цепочки инструментов «последней мили AI-контроля качества», представляет собой системную организацию направления промышленного контроля качества Ruiside от продукта к экосистеме разработчиков; превосходные адаптационные решения, полученные по итогам финала (24-10, Шанхай), могут обогатить возможности платформы.
