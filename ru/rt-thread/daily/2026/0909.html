1.2 主仓库再合入两笔：Keil include 路径顺序保持（#11741）与瑞萨 GPT PWM 寄存器读取（#11753）

日期：2026-09-08 ~ 2026-09-09　来源：RT-Thread/rt-thread commits（commit 66648255、commit d7ea2bce）

窗口内主仓库另有 2 笔合入：

  • [tools][keil] Preserve include path order（09-08 17:03 北京时间合入，PR #11741）：修复 Keil 工程生成时 include 路径顺序被改变的问题，保证路径优先级符合预期。该 PR 08-24 创建，评审约两周后合入，属工具链（Keil MDK 工程生成）健壮性修复，与昨日合入的 sal 溢出修复、AT 主机名越界修复同属近期「评审队列常态化消化」节奏。
  • [bsp/renesas][drivers] Read PWM settings from GPT registers（09-09 10:33 北京时间合入，PR #11753，commit d7ea2bce）：瑞萨 HAL 驱动层 drv_pwm.c 修改（+94/-22），改为从 GPT 定时器寄存器直接读取当前 PWM 配置（周期、占空比等），使驱动状态与硬件实际配置保持一致，避免软件缓存与寄存器失步。这是瑞萨 RZ/RA 系列 BSP 驱动在本月的又一笔迭代——08-27 曾有瑞萨 SPI 运行时配置修复与 SDHI 卡检测触发两笔合入（均已收录），瑞萨 BSP 驱动的持续打磨是当前厂商适配主线之一。该笔合入位于窗口终点（今晨 10:33），为最新落地动作。

3.1 canopennode-rtt 窗口内合入三笔 CiA401 功能：RT-Thread 设备行规支持、多设备节点逻辑设备、MSH 测试控制

日期：2026-09-08（17:56 北京时间批量合入，即 09:56:22Z）　来源：wdfk-prog/canopennode-rtt commits

外部生态仓库 canopennode-rtt（CANopen 移植，wdfk-prog 维护）窗口内批量合入三笔新功能提交（author 时间 09-07 ~ 09-08 上午，09-08 傍晚统一合入）：

  • feat[canopennode][cia401]: add RT-Thread device profile support：CiA401（I/O 设备行规）增加面向 RT-Thread 的设备行规支持层；
  • feat[CiA401][device]: support logical devices in multiple-device nodes：多设备节点场景下逻辑设备支持（一个节点内挂多个逻辑设备）；
  • feat[CIA401][RTT]: add MSH bench controls for device testing：新增 MSH 命令行基准测试控制，便于设备测试。

这是继 09-06 两笔 CiA401 模拟量事件与故障安全落地（已收录）后的第二批 CiA401 功能，标志着 CANopen CiA401 设备行规在 RT-Thread 侧的移植从「协议帧级」推进到「设备行规 + 多逻辑设备 + 测试工具链」层面，功能面持续扩大。wdfk-prog 同时在官方仓库推进 CAN 驱动生命周期重构（#11779），「外部生态移植 + 官方框架」双线并行，是当前 RT-Thread CAN/CANopen 方向最活跃的贡献者。

3.2 packages 索引两笔更新：腾讯 IoT SDK 配置调整、autogen_parameter_manager 配置项重构

日期：2026-09-08（17:56 / 18:16 北京时间）　来源：RT-Thread/packages commits（5d983b53、866a20b5）
