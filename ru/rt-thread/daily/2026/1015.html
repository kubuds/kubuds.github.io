1. Динамика ядра и версий

В окне основного репозитория выполнено 9 слияний и 1 коммит рефакторинга RISC-V — самый плотный пакет слияний за последнюю неделю; на стороне ревью одновременно обновлены 8 рассматриваемых предложений и несколько баг-репортов.

1.1 Новый коммит предложения Next RISC-V: рефакторинг порта архитектуры RISC-V, унификация общего слоя RV32/RV64 (10-15)

Дата: 2026-10-15 11:51 (время коммита)　Источник: PR #10320, коммит рефакторинга 6bf3686

Крупное предложение по рефакторингу RISC-V (#10320) в окне отправило большой коммит рефакторинга «[libcpu][risc-v] Refactor the RISC-V architecture port»: введён опциональный унифицированный общий слой RISC-V (RV32/RV64), выбор архитектуры и XLEN выполняется через ARCH_RISCV и ARCH_CPU_64BIT, унифицированы обработка context, trap, MMU, cache, timer, SBI, SMP и ISA, добавлена поддержка PLIC, CLIC, ACLINT, APLIC и IMSIC, а также создана таблица сопоставления физических HART ID с логическими CPU ID; сохранена ветка переопределений производителя T-Head. qemu-virt64-riscv стал первым BSP, подключённым к новому общему слою (один и тот же каталог поддерживает RV32 и RV64 S-mode), существующие BSP, не использующие макрос RT_USING_RISCV_NEW_COMMON, продолжают использовать пути legacy_common / common64. После коммита автоматические процессы перезапущены (уведомление о форматировании, назначение ревьюеров, отчёт о памяти membrowse); тикет отслеживания изменений RISC-V #11246 синхронно обновлён (11:52). Предложение остаётся открытым.

1.2 Пакет исправлений сетевого стека принят: два случая — деление на ноль в статистике ping и задержка последнего пакета — последовательно закрыты (10-14 ~ 10-15)

Дата: 2026-10-14 09:33 ~ 2026-10-15 09:10 (время слияния)　Источник: PR #11853, PR #11866

В окне мониторинга компонента netdev объединены два исправления, связанных с ping: первое (#11853, объединено 14.10) устраняет проблему падения shell из-за деления на ноль в статистике ping при недостижимости цели; связанный дефект #11852 закрыт в тот же день; второе (#11866, объединено утром 15.10) исправляет логику задержки последнего пакета — исходная проверка в цикле всегда была ложной, из-за чего после последнего пакета всё равно добавлялась задержка, а при нулевой задержке всё равно вызывался rt_thread_delay(0), возвращавший недопустимый параметр; изменено на запись фактического затраченного времени с вызовом только для не последнего пакета и при задержке больше нуля; связанный дефект #11865 закрыт в тот же день. Более раннее предложение в том же направлении #11862 закрыто без объединения.

1.3 Пакет исправлений ядра и USB объединён: переполнение calloc и усиление проверки числа интерфейсов USB host (14.10)

Дата: 2026-10-14 09:28 ~ 10:17 (время объединения)　Источник: PR #11848, PR #11822

На стороне ядра исправлена проблема целочисленного переполнения calloc (#11848), представленная и объединённая участником сообщества. На стороне USB завершено усиление legacy USB host (#11822): для дефекта «host напрямую доверяет сообщаемому устройством числу интерфейсов, что может вызвать выход за границы» (#11288) добавлена проверка верхней границы числа интерфейсов и обработка границ в путях перечисления интерфейсов и очистки; два коммита (уточнение проверки числа интерфейсов, завершение перечисления и очистки) объединены синхронно, дефект закрыт в тот же день.

1.4 Пакет объединённых BSP и драйверов от нескольких производителей: ra6w1, ESP32-C3, STM32H723, восстановление RISC-V-векторов и др. (14.10)

Дата: 2026-10-14 09:13 ~ 09:44 (время объединения)　Источник: PR #11814, PR #11847, PR #11851, PR #11861, PR #11855

Сопровождающие централизованно объединили несколько обновлений BSP и драйверов производителей: Renesas ra6w1 оптимизирован по распределению системных ресурсов (стек главного потока скорректирован до 4096, коммит от RC, #11814); Espressif ESP32-C3 исправлено сопоставление шаблонов IRAM в путях Windows и ошибочное сопоставление скрипта компоновки Bluetooth (#11847); STM32H723-DM-MC02 добавлена поддержка SPI6 BDMA (#11851); блок RISC-V-векторов исправляет восстановление состояния vstart после конфигурации (#11861); в components/drivers framework reset исправлена ошибка сборки при одновременном включении с ulog (#11855).

1.5 Находящиеся на рассмотрении предложения получили ревью сопровождающих: управление макросами lwip, BSP ESP32-S3, исправление rt_kprintf, ops Ethernet STM32 (14.10 ~ 15.10)

Дата: 2026-10-14 10:13 ~ 2026-10-15 09:22 (время ревью)　Источник: PR #11815, PR #11844, PR #11864, PR #11819

Сопровождающие в окне мониторинга дали ревью четырём находящимся на рассмотрении предложениям: предложение об управлении макросами сегментов lwip (#11815) утром 15.10 получило запрос на изменения (ранее автор уже 14.10 повторно отправил изменения); предложение о поддержке платы ESP32-S3 (#11844) после ответа автора 14.10 на замечания проверки утром 15.10 получило повторное рассмотрение сопровождающим с построчными комментариями; предложение об исправлении неявного объявления rt_kprintf (#11864) получило запрос на изменения — этот случай призван исправить аномальный вывод логов %f в среде IAR при отсутствии объявления; предложение об адаптации слоя ops нового драйвера Ethernet STM32 (#11819) получило запрос на изменения. Все четыре случая остаются открытыми.

1.6 Динамика остальных находящихся на рассмотрении предложений: дополнительный коммит clang-format, повторное открытие предложения по таймерам N32, дополнительные тесты предложения ASan (14.10)

Дата: 2026-10-14 09:46 ~ 12:27 (время обновления)　Источники: PR #11859, PR #11812, PR #11772

Предложение по уточнению спецификации clang-format (#11859) добавило два коммита: тонкая настройка правил стиля (выравнивание, перенос скобок и отступы) с демонстрацией практического эффекта на примере thread.c; предложение по дополнению таймеров серии N32 (#11812) было повторно открыто мейнтейнером — данный PR дополняет общую ветку драйверов для N32H47x/48x и H49x и сопровождается записью ci-attach; автор предложения по ASan для кучи (#11772) добавил пояснения: новые проверки диапазонов для rt_memcpy, rt_memset и rt_memmove с опциональной обёрткой интерфейсов libc, дополнены граничные тесты на выход за границы, доступ после освобождения, нулевую длину и т. д., в отчёте указано, что последний CI полностью пройден.

1.7 Старый баг-репорт получил новое обсуждение: направление решения переполнения at_gethostbyname требует уточнения (10-14)

Дата: 2026-10-14 16:26 (время комментария)　Источники: Issue #5913

Баг-репорт о переполнении буфера в куче, созданный в 2022 году (#5913), получил новый комментарий в окне мониторинга: отмечено, что обсуждение риска переполнения, связанного с обработкой ip_str в at_gethostbyname, отложено более чем на два года и до сих пор не имеет решения; рекомендуется сообществу определить направление решения — ограничить длину копирования или отклонять слишком длинные имена хостов, а также назначить ответственного за исправление; если проблема уже решена в других коммитах, достаточно добавить номер коммита для закрытия тикета.

3.2 Исправляющий коммит в репозитории стандартных периферийных драйверов N32: корректировка использования констант ECC в FEMC (10-14)

Дата: 2026-10-14 09:45 (время коммита)　Источник: исправляющий коммит 9983259

Репозиторий RT-Thread-packages/n32h7xx_std_driver: в окне принят исправляющий коммит: интерфейс чтения состояния ECC драйвера FEMC переведён на стандартную группу констант (FEMC_ECC_LAST_*); это относится к постоянной поддержке библиотеки стандартных периферийных драйверов серии N32H7 и вместе с одновременным предложением по дополнению таймеров N32 в основной ветке (см. 1.6) отражает рост плотности поддержки отечественной платформы N32.

Остальные каналы экосистемы в окне остаются без активности: репозиторий инструмента env (последний коммит 10-10), индекс Studio SDK (последнее обновление 10-10), сторонний downstream-репозиторий производителя GD32 — gd32_rt-thread (последнее принятие в основную ветку 09-28) — не имеют推送 в окне.

5. Итоги и наблюдения за тенденциями

5.1 Тенденции за прошедшие сутки (10-14 ~ 10-15)

  • Ускорение рефакторинга RISC-V: #10320 завершил рефакторинг на уровне libcpu (унификация общего слоя, расширение контроллера прерываний, отображение HART), трекер изменений RISC-V同步 обновлён; вместе с принятым 10-14 исправлением vector vstart стек архитектуры RISC-V входит в фазу интенсивной реализации.
  • Массовое принятие мейнтейнерами — самое плотное за неделю: с утра 10-14 в течение одного дня 9 PR принято в основную ветку — два случая по network ping, kernel calloc, усиление USB host и пять обновлений BSP производителей, что обнулило почти 45-часовое окно без принятий из предыдущего периода.
  • Замыкание основной линии устойчивости сетевого стека: два случая — деление на ноль в ping и задержка последнего пакета — были закрыты в день от дефекта до принятия исправления, вместе с закрытием аналогичного раннего предложения稳定性 netdev закрыта.
  • Очередь ревью полностью активна: 8 предложений на рассмотрении имели действия в окне; макроконтроль lwip и ESP32-S3 BSP перешли на этап ручного ревью, по двум случаям — rt_kprintf и STM32 Ethernet ops — также запрошены изменения.
  • Двухканальная выдача экосистемы и Community: packages завершил принятие индекса hpm_sdk; обзорная статья по Workshop на промышленной выставке и пост о работе роботизированной руки для физиотерапии на конкурсе продолжают выходить, плотность контента по робототехнике и康复-направлению растёт.
