1. Динамика ядра и версий

1.1 Основной репозиторий: двойной PR пакета совместимости RT-Smart POSIX влит, всего 13 коммитов

Дата: 2026-08-30 (слияние 20:49-20:55 пекинское время)　Источник: PR #11732、PR #11733

Вчерашний ежедневный отчёт констатировал, что в основном репозитории «продолжается пауза в разработке функций», однако уже тем же вечером это было опровергнуто. Основатель BernardXiong последовательно влил два PR, связанных с RT-Smart (RT-Thread Smart, режим совместимости с POSIX/Linux), всего 13 коммитов:

  • PR #11732 «Extend Smart POSIX filesystem and syscall compatibility» (слит в 20:49, 10 коммитов): блокировки записей DFS POSIX (record locks) и покрытие utest, fchmod, setattr tmpfs и исправление метаданных, поля файлов процессов/системы procfs, совместимого с Linux, пробуждение ожидающих в libc epoll при OOM, исправление копирования системных вызовов LWP, исправление EFAULT и битов атрибутов tmpfs, переключение сетевой карты virtio на зависимость от LWIP, выравнивание по clang-format.
  • PR #11733 «Harden RT-Smart serial ioctl arguments» (слит в 20:55, 3 коммита): ужесточение проверки аргументов ioctl последовательного порта RT-Smart, форматирование объявлений termios и реализация замечаний рецензентов.

Это самое крупное слияние в основном репозитории после BSP rt-smart для XuanTie C908 от 08-28; направление очевидно: слой совместимости файловой системы POSIX и системных вызовов RT-Smart последовательно приводится к семантике Linux (блокировки записей, многопользовательский procfs, epoll), а ioctl последовательного порта вступает в фазу ужесточения на уровне аргументов.

1.2 ENV WebUI переведён на TypeScript, исправлен сбой синхронизации BSP

Дата: 2026-08-31 (слияние PR в 00:56; дополнительный исправляющий коммит в 11:00)　Источник: RT-Thread/env PR #291

PR #291 инструмента ENV «feature/webui typescript» слит, три изменения: фронтенд WebUI мигрирован с JavaScript на TypeScript; при запуске WebUI плагином выполняется автоматический переход на страницу WebUI соответствующего плагина; обновлён логотип RT-Thread Env. Затем 08-31 в 11:00 добавлен исправляющий коммит «Fix WebUI module import error causing BSP package synchronization failure», устраняющий сбой синхронизации пакетов BSP из-за ошибки импорта модуля WebUI.

Продолжая вчерашний PR #290 (управление SDK и настройка локальной цепочки инструментов), перевод ENV WebUI вступает в фазу инженерной реализации; основатель третий день подряд лично занимается итерациями — темп модернизации официальной цепочки инструментов разработки не снижается.

2. Официальные и общественные мероприятия

2.1 Официальный новостной API одиннадцатый день подряд без пополнений, отчёт о прошедшем Workshop Ruiqing по-прежнему отсутствует

Дата: 2026-08-31　Источник: официальный новостной API RT-Thread

Официальный новостной API (категория rt_org) по-прежнему содержит 5 старых записей, самая свежая — репортаж об инвестиционном форуме в Абу-Даби от 2026-06-17, одиннадцатый день подряд без новых поступлений. Отчёт о воркшопе промышленной платформы Ruiqing (состоялся 08-27 в Шанхае) в окне мониторинга по-прежнему отсутствует: запрос gnews «Ruiqing when:2d» дал 4 попадания, все — шум от разбиения автомобильных слов (багажник Ford Lingrui, стартовая цена Lingrui от 98,8 тыс., гибрид Geely Zhiqing и т. п.), полезных записей нет. На медийной стороне в окне ноль новых материалов; анонс участия в elexcon 2026 (опубликован EE Times China 08-30, учтён вчера) остаётся единственным внешним сигналом за последнее время.

3. Экосистема и адаптация производителей

3.1 packages: в пакет AI Agent добавлен аудиофреймворк

Дата: 2026-08-31 (слияние в 11:04)　Источник: RT-Thread/packages PR #2029

PR #2029, представленный разработчиком сообщества CXSforHPU, слит в основную ветку: в ai/Agent/Kconfig добавлено меню «Agent Driver» и переключатель PKG_AGENT_DRIVER_AUDIO, при включении которого автоматически выбираются wavplayer (с поддержкой записи) и аудио BSP — таким образом пакет AI Agent получает канал аудиодрайвера, предоставляя аппаратную точку подключения для приложений интеллектуальных агентов с голосовым взаимодействием. Этот пакет лишь 08-24 получил поддержку мультимодальности и обрезку истории чата (PR #2022); теперь добавлена аудиосоставляющая, и картина возможностей ИИ на устройстве продолжает складываться. Изменения относятся к уровню конфигурации Kconfig, фактическая логика драйвера находится на стороне wavplayer/BSP, работоспособность ждёт проверки на реальном оборудовании.

3.2 packages: в optparse восстановлена запись версии v1.0.0, исправлено разрушительное изменение интерфейса

Дата: 2026-08-31 (слияние в 11:02)　Источник: RT-Thread/packages PR #2028

Из-за разрушительного изменения интерфейса optparse (число параметров optparse_init увеличено с 2 до 3, добавлен argc) перестали компилироваться существующие пакеты, включая wavplayer v0.2.0 (ошибка “too few arguments to function ‘optparse_init’”), а в индексе пакетов ранее содержалась только версия latest, поэтому пользователи не могли откатиться и были вынуждены вручную править исходники сторонних пакетов. PR #2028, представленный Leeee-wx, восстанавливает для optparse запись версии v1.0.0 (package.json + Kconfig), возвращая возможность отката — пользователи RT-Thread Studio могут откатиться напрямую. Управление индексом пакетов движется в сторону «совместимости при откате версий».

3.3 Экосистемная справка: обновление документации по реверс-инжинирингу h120d-protocol

Дата: 2026-08-30 (12:43)　Источник: H4ck3rTR/h120d-protocol

Личный проект по реверс-инжинирингу (4 звезды) обновил README: документированы данные пакетов реверс-инжиниринга WiFi-протокола дрона Holy Stone H120D, внутренняя структура RT-Thread и инструменты управления. Обновлена только документация, изменений кода нет, включено для наблюдения за экосистемой.

4. Отраслевые применения

В окне мониторинга нет новых записей об отраслевых применениях. Тренд за последние три дня: 08-30 EE Times China опубликовал анонс участия в elexcon 2026 (Ruiside — «больше, чем операционная система», «полный набор» для ИИ-оборудования, 9–11 сентября, Шэньчжэнь, район Баоань); 08-27 после воркшопа промышленной платформы Ruiqing (Шанхай) публичных сообщений нет; ИИ на устройстве (гибридное развёртывание AIOS, возможности Agent) — текущая точка приложения экосистемы, и добавление в индекс аудиофреймворка AI Agent перекликается с этим.

5. Итоги и наблюдения за трендами

  1. Основной репозиторий прервал трёхдневную паузу, серия исправлений совместимости RT-Smart с POSIX — самая ценная инженерная динамика в окне: PR #11732 (блокировки записей DFS, fchmod, метаданные tmpfs, procfs, совместимый с Linux, OOM в epoll, исправления libc) + PR #11733 (ужесточение параметров ioctl последовательного порта), всего 13 коммитов, слитых лично основателем; слой совместимости RT-Smart с Linux продолжает шлифоваться.
  2. Переход ENV на WebUI идёт третий день подряд: миграция на TypeScript + автоматический переход к WebUI плагина (PR #291), в 11:00 вновь исправлен сбой синхронизации пакетов BSP; модернизация официальной цепочки инструментов разработки не останавливается.
  3. Два PR экосистемы пакетов слиты в один день: в AI Agent добавлен аудиофреймворк (канал драйвера на уровне Kconfig), в optparse восстановлена запись версии v1.0.0 с исправлением разрушительного изменения интерфейса — управление индексом и возможности ИИ на устройстве развиваются параллельно.
  4. Официальная новостная повестка спокойна одиннадцатый день подряд: в новостном API нет новых записей, отчёт о воркшопе Ruiqing по-прежнему отсутствует, на медийной стороне в окне ноль новых материалов (анонс elexcon учтён вчера).
  5. Оценка тренда: слой совместимости RT-Smart, ENV WebUI и AI Agent идут по трём линиям одновременно; официальный период внешнего молчания контрастирует с инженерной активностью; следующий узел наблюдения — elexcon 2026, 9–11 сентября.

Ограничения: контент официального канала WeChat не покрывается gnews; отчёт о мастер-классе Ruiqing Workshop может быть опубликован только там; нулевые результаты gnews по запросу на английском «RT-Thread when:3d» — обычное явление (Google News ненадёжно разбивает слово “RT-Thread”); PR #2029 — изменения в аудиофреймворке на уровне конфигурации Kconfig, фактический эффект требует проверки на реальном устройстве; h120d-protocol — личный репозиторий с 4 звёздами, включён только для наблюдения за экосистемой.
