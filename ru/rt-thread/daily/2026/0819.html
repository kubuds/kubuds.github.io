1. Динамика ядра и версий

1.1 Статус версии стабилен, новых слияний в основном репозитории за окно нет

Дата: 2026-08-19　Источник: rt-thread releases / rt-thread commits

Последней официальной версией остаётся v5.2.2 (выпущена 2025-10-31), за окно новых релизов и предрелизов нет. В основном репозитории за последние 48 часов по времени коммиттера новых коммитов нет: после реализации нативных сокетов AF_UNIX (слияние 08-17 17:15, PR #11681, около 5700 строк) и исправления тихого отказа команды wlan wifi (08-17 14:34, PR #11696), охваченных вчерашним окном, на стороне ядра наступил период осмысления; крупные функции ожидаются в следующем релизе.

2. Официальные и общественные мероприятия

2.1 Старт медийного продвижения Workshop промышленной платформы Ruiqing

Дата: 2026-08-18 (17:30 пекинское время)　Источник: EE Times China (включено в Google News)

EE Times China опубликовал рекламную статью «27 августа, Шанхай Workshop промышленной платформы Ruiqing: практика управления в реальном времени EtherCAT и промышленных решений», официально подогревая интерес к шанхайскому Workshop 27 августа. Оригинальный сайт EET-China недоступен (известно исторически), детали текста раскрыть невозможно, приводится только ссылка gnews. Информация о мероприятии совпадает с предыдущим официальным анонсом: тема сосредоточена на управлении в реальном времени EtherCAT и практическом применении промышленных решений, ориентирована на специалистов по разработке промышленного контроля. Это очередное публичное появление промышленной платформы Ruiqing после презентации официальной новости от 2 июня «Промышленная платформа Ruiqing расширяет возможности разработки промышленного контроля» на форуме промышленных технологий.

2.2 В официальном API новостей за окно новых записей нет

Дата: 2026-08-19　Источник: официальный API новостей RT-Thread

Официальный API новостей (категория rt_org) по-прежнему содержит 5 старых записей, последняя — репортаж об инвестиционном форуме в Абу-Даби от 2026-06-17, отставание около 2 месяцев без улучшений; интерфейс категорий news/activity возвращает пустой результат. Продвижение Workshop Ruiqing, рейтинг конкурса AIoT и другие недавние события не синхронизированы в официальном API, темп обновления официального информационного канала продолжает отставать от фактической динамики.

3. Экосистема и пакеты

3.1 Новый AI-пакет LiME-TM добавлен в индекс packages (крупнейшее техническое событие окна)

Дата: 2026-08-19 (слияние 09:17 пекинское время)　Источник: RT-Thread/packages commit #2015

Пакет LiME-TM, представленный разработчиком сообщества wuhanstudio, сегодня слит в репозиторий индекса packages (ai/LiME-TM, коммит 69de99dd, PR #2015), в экосистеме RT-Thread AI появилось уникальное направление машинного обучения:

  • Позиционирование: полное название — “Lightning fast and Memory Efficient Machine Learning for MCU (Tsetlin Machine)”, то есть встраиваемая библиотека машинного обучения на языке C на основе Tsetlin Machine (вышестоящий репозиторий wuhanstudio/lime-tm.c, лицензия MIT). Tsetlin Machine выполняет классификацию с помощью клауз пропозициональной логики (булевых шаблонов), а не весовой сети; вывод сводится к битовым операциям, ресурсоёмкость крайне низкая, а решения интерпретируемы;
  • Возможности пакета: поддерживает обучение модели на кристалле (примеры обучения и тестирования MNIST, можно включить TSETLIN_MODEL_TRAINABLE); модель может быть скомпилирована компилятором tsetlin в статический заголовок C и напрямую встроена в прошивку либо загружена как файл protobuf из файловой системы (зависит от RT_USING_POSIX_FS); Kconfig предоставляет выбор из двух наборов примеров, по умолчанию — пример статической модели;
  • Значение: в каталоге packages/ai сейчас 14 AI-пакетов (nnom, ncnn, TensorflowLiteMicro, AIfES, r-tinymaix и др.), ориентированных в основном на нейросетевой вывод; LiME-TM впервые добавляет направление “интерпретируемого символьного обучения”, предлагая новый вариант для сценариев, где требуется аудит решений, — промышленной диагностики неисправностей, классификации показаний датчиков и т. п.

3.2 Обновление вспомогательной среды отладки gdr GDB

Дата: 2026-08-18 (16:06–17:27 пекинское время, 5 коммитов)　Источник: flespark/gdr

В окне мониторинга 5 подряд коммитов во вспомогательной среде отладки GDB RTOS gdr (расширение GDB Python, разбирающее объекты ядра RT-Thread на стороне отладчика): в вывод объектов ядра rtthread добавлено больше полей, улучшена читаемость вывода печати и команд, добавлена команда-алиас freertos (frt), унифицировано переименование символов config, улучшена документация. Вместе с вошедшими 08-12 подкомандами и дополнением по tab для имён объектов в реальном времени последовательно улучшается опыт разработчика при отладке ядра и пользовательского режима rt-smart. Личный проект (мало звёзд), но активно развивается; приводится как справочный по экосистеме.

3.3 Справочное по экосистеме (не отдельные динамики)

  • wdfk-prog/canopennode-rtt: пакет CANopenNode (личный репозиторий) обновлён 08-18 13:29, слабый кандидат, конкретное содержимое не проверено;
  • zlgopen/awtk: новых коммитов в окне нет (общие улучшения GUI, освещено вчера);
  • GD32-MCU-IOT/gd32_rt-thread: 08-18 плановая синхронизация с вышестоящим, неофициально и незначительно.

4. Специальный раздел по отраслевым применениям (промышленность / робототехника / воплощённый интеллект)

  1. Разогрев перед практическим промышленным Workshop по EtherCAT, промышленная линия вновь подтверждена: 27 августа в Шанхае «Практический Workshop по промышленной платформе Ruiqing: управление EtherCAT в реальном времени и промышленные решения» входит в 9-дневный обратный отсчёт, сегодня опубликованы медиа-материалы. EtherCAT —мейнстрим промышленная шина реального времени для управления движением; тема этого практикума вновь уточняет позиционирование платформы Ruiqing для промышленной автоматизации; вместе с поддержкой плагинной установки в промышленных сценариях в онлайн-маркете плагинов ENV (вошёл 08-18) постепенно проясняется путь синергии платформы Ruiqing и промышленной экосистемы.
  2. Новый вариант интерпретируемого AI на устройствах: потенциал Tsetlin Machine: предлагаемый LiME-TM путь вывода на булевых клаузах дополняет нейросети — интерпретируемые решения и низкая ресурсоёмкость естественно подходят для сценариев, требующих аудита и детерминированного поведения, таких как промышленная диагностика неисправностей и классификация поведения роботов. Сейчас это первая партия включения в индекс пакетов; фактическая проверка на платах и принятие сообществом пока ожидаются.
  3. Основная линия робототехники и многопроцессности входит в фазу усвоения: после включения 08-17 поддержки кросс-компиляции ROS 2 и локального IPC AF_UNIX на этой неделе новых действий по инфраструктуре робототехники нет; ожидается, что далее основное внимание будет уделено сопутствующему procfs ядра и примерам на реальных устройствах.

5. Итоги и наблюдения за тенденциями

  1. Сегодняшнее окно — “день экосистемы и пакетов”: в ядро новых включений нет, по релизам спокойно (v5.2.2), основная динамика на стороне пакетов — LiME-TM позволяет AI-экосистеме RT-Thread дополнить направление интерпретируемого машинного обучения (Tsetlin Machine); это техническое событие с наибольшей долгосрочной ценностью в данном окне.
  2. Официальный информационный канал по-прежнему запаздывает: официальный API новостей остановился на июне, материалы о Workshop платформы Ruiqing удаётся поймать только через сторонние медиа (EE Times China); проверка по медиа остаётся основным информационным каналом.
  3. Промышленная линия последовательно продвигается: опубликованы медиа-материалы о Workshop промышленной платформы Ruiqing; шанхайское практическое мероприятие по EtherCAT 27 августа станет наиболее заслуживающей отслеживания точкой наблюдения ближайшего времени.
  4. Обзор тенденций за последние 3 дня: 08-17 кросс-компиляция ROS 2 + IPC AF_UNIX в ядре → 08-18 онлайн-маркет плагинов ENV → 08-19 AI-пакет LiME-TM; инфраструктура и основная линия AI/робототехники сохраняют плотный ритм; в инструментальной цепочке включения идут 6-й день подряд.
  5. Ограничения: все события данного окна взяты из GitHub и медиа-агрегаторов; оригинальный сайт EET-China и основной текст gnews недоступны, детали медиа-материалов Workshop раскрыть невозможно; запаздывание официального API ограничивает полноту информации о мероприятиях.
