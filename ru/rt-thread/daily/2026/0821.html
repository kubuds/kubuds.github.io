1. Динамика ядра и версий

1.1 Совершенствование системы интеграции сборки Rust: исправление конфигурации сборки межкомпонентных модулей и добавление покрытия CI для STM32

Дата: 2026-08-21 (включено в 11:17 пекинское время)　Источник: RT-Thread/rt-thread commit 30af7388

Наиболее заслуживающее внимания включение в окне: [rust][tools] Fix Rust build example configuration handling. Описание коммита показывает, что это систематическое исправление интеграции сборки Rust, охватывающее четыре уровня: core, applications, components и примеры module: исправление распространения ошибок сборки, обработка target и feature, передача флагов компоновки, семантика конфигурации примеров, а также добавление покрытия CI attach для STM32 (stm32f407-rt-spark). Затронуто несколько файлов в components/rust/, включая Cargo.toml, SConscript, исходный код core и README на китайском и английском языках. В сочетании с ритмом включений, связанных с rust, с середины августа, поддержка Rust остаётся активной точкой инвестиций в направлении инструментальной цепочки RT-Thread; данный коммит включил корректность сборки примеров Rust в защиту CI.

1.2 Исправление расчёта переполнения месяца в libc timegm

Дата: 2026-08-21 (включено в 09:44 пекинское время)　Источник: RT-Thread/rt-thread commit 339bffb7

[fix][libc] fix timegm month overflow calculation: исправление ошибки расчёта переполнения месяца в реализации libc timegm. timegm используется для прямого преобразования struct tm в time_t (без учёта местного часового пояса); при выходе значения месяца (tm_mon) за границы допустимого диапазона результат вычисления оказывается неверным — данное исправление корректирует логику преобразования при переполнении. Относится к исправлениям устойчивости обработки времени на стороне libc.

1.3 Исправление утечки буфера пути в dfs utimensat

Дата: 2026-08-20 (включено в 18:30 пекинское время)　Источник: RT-Thread/rt-thread commit 7d1e5515

[dfs] Fix path buffer leaks in utimensat: исправление утечки буфера пути в реализации utimensat (системный вызов установки временных меток файла). На уровне dfs на пути разрешения пути отсутствовал путь освобождения для уже выделенного буфера — данное исправление восполняет это. Продолжая основную линию “исправления дефектов” вчерашней защиты от двойного освобождения memheap, на стороне ядра за последние два дня преобладают небольшие исправления устойчивости в области управления ресурсами и обработки времени.

1.4 Третья фаза расширения BSP серии N32H от Nations Technology: включена поддержка драйверов H47X/H49X/H7XX

Дата: 2026-08-20 (17:32 пекинское время, влито, PR #11711)　Источник: RT-Thread/rt-thread commit 9fce24b6 / PR #11711

[bsp][n32] add H47X/H49X/H7XX driver support (представлено участником сообщества OnlyoutzZ), 60 изменённых файлов, все расположены в bsp/n32/n32hxxx/libraries/N32_Drivers/drivers/config/: добавлены конфигурации драйверов CAN/UART для h47x_48x и h49x, расширены конфигурации периферии h7xx для ADC, CAN, DAC, I2C, LPTIM, импульсного энкодера, PWM, SPI, TIM, UART и других. Это третье влитие BSP серии N32H: 22.07 — первая версия (доработка и исправление n32h760zil7-stb + добавление поддержки плат n32h497zgl7-evb, n32h487zgl7-evb), 12.08 — вторая очередь (драйверы Nsing LCDC и SDRAM), на этот раз третья очередь дополняет конфигурации драйверов периферии H47X/H49X/H7XX, что соответствует итерационной модели вендорских BSP «сначала каркас, затем драйверы»; адаптация серии H (высокопроизводительные модели Cortex-M) National Technology в экосистеме RT-Thread продолжает углубляться.

1.5 Состояние версии стабильно

Дата: 2026-08-21　Источник: rt-thread releases

Последняя официальная версия по-прежнему v5.2.2 (выпущена 2025-10-31), в окне мониторинга нет новых релизов и предварительных выпусков. AF_UNIX (17.08), усиление memheap (20.08) и ряд сегодняшних исправлений, как ожидается, будут выпущены единым пакетом в следующей версии.

2. Официальные и общественные мероприятия

2.1 Официальный API новостей по-прежнему без пополнений, интерфейс категорий возвращает «данные категории не существуют»

Дата: 2026-08-21　Источник: RT-Thread официальный API новостей

Официальный API новостей (категория rt_org) по-прежнему содержит 5 старых записей, самая свежая — репортаж об инвестиционном форуме в Абу-Даби от 2026-06-17, отставание около 2 месяцев без улучшений; интерфейсы категорий news и activity на этот раз вернули «данные категории не существуют, обратитесь к администратору» (вчера возвращали пустой ответ), состояние интерфейсов официального канала информации изменилось, темп обновления продолжает отставать от фактической динамики. Приближается Workshop по промышленной платформе Shanghai Ruiqing 27 августа (практикум по EtherCAT), в окне мониторинга новой официальной анонсирующей информации или публичных сведений о саммитах/хакатонах/университетских программах не появилось.

3. Экосистема и программные пакеты

3.1 CI индекса packages обновлён: валидация Kconfig на этапе PR; исправление конфигурации по умолчанию LiME-TM

Дата: 2026-08-21 (09:24 пекинское время, влито)　Источник: RT-Thread/packages commits

В окне мониторинга два влития в репозиторий индекса программных пакетов:

  • ci: validate Kconfig from current PR: в CI программных пакетов добавлен процесс «валидация Kconfig из текущего PR», в сочетании с поддержанной 14.08 валидацией репозиториев Gitee порог качества при включении в индекс программных пакетов дополнительно повышен (ранее валидация выполнялась только для уже влитого индекса);
  • ai: Fix LiME-TM example choice default: исправлена конфигурация по умолчанию примера пакета LiME-TM, добавленного в индекс 19.08. LiME-TM — новый участник направления AI-пакетов RT-Thread (добавлен в индекс 19 августа, о нём сообщалось вчера), в тот же день получил исправление конфигурации, что относится к быстрой доработке после включения нового пакета.

3.2 Наблюдение за экосистемой: canopennode-rtt без новых коммитов в окне мониторинга

Дата: 2026-08-21　Источник: wdfk-prog/canopennode-rtt

Упомянутый вчера сторонний пакет интеграции CANopenNode (wdfk-prog/canopennode-rtt) в окне мониторинга не получил новых коммитов (последний по-прежнему от 20.08 11:11 пекинского времени — проверка блочной передачи SDO, уже освещалась). Остальные активные репозитории topic:rt-thread за последнюю неделю — awtk (20.08 только улучшения документации), gd32_rt-thread (21.08 синхронизация нижестоящего зеркала), h120d-protocol (21.08 обновление документации) и другие, все без специального нового содержания, приводятся лишь для справки по экосистеме.

4. Специальная глава о отраслевых применениях (промышленность / робототехника / воплощённый интеллект)

4.1 В окне мониторинга новых записей нет, обзор тенденций за последние 3 дня

Дата: 2026-08-18 ~ 2026-08-20　Источники: см. каждый пункт

В окне со стороны отраслевых приложений новых публичных сообщений нет, медийная основная линия продолжает тренд последних 3 дней (подробно освещено вчера, здесь — обзор):

  • Промышленная платформа Ruicore DSMC+FPGA связь 90 МБ/с (08-19, EE Times China): промышленная плата Ruicore Pai RK3506J + плата расширения FPGA, 16-битная параллельная шина DSMC + событийно-управляемый DMA rt_event, измеренная пропускная способность повышена до 90 МБ/с, направление сбора данных в реальном времени для промышленной автоматизации продолжает выдавать результаты;
  • Участие в отчёте о производительности RTOS Beningo 2026 (08-19): RT-Thread как единственная отечественная открытая RTOS вошёл в список из 8 участников тестирования;
  • Разогрев Workshop промышленной платформы Ruicore в Шанхае 8/27 (08-18): практика управления в реальном времени EtherCAT и промышленных решений — новейшее прикладное мероприятие недавней основной линии промышленной автоматизации.

5. Итоги и наблюдения за трендами

  1. На стороне ядра продолжается “период усвоения”, наиболее активное направление — Rust: после AF_UNIX (08-17), усиления memheap (08-20) из 3 слияний в окне 2 — исправления дефектов libc/dfs; крупнейшее действие — систематизированное исправление интеграции сборки Rust с включением в покрытие STM32 CI, темп вложений в поддержку Rust ясен.
  2. BSP серии N32H — трёхэтапное расширение: экосистема GigaDevice продвигается участниками сообщества, конфигурация периферийных драйверов H47X/H49X/H7XX дополнена (60 файлов), модель “сначала каркас, затем драйверы” полностью пройдена в три этапа.
  3. Апгрейд инфраструктуры качества пакетов: в packages CI добавлена проверка Kconfig на этапе PR, порог качества при включении в репозиторий сдвинут вперёд; новый пакет LiME-TM быстро дорабатывается.
  4. Требует внимания изменение состояния официальных информационных каналов: интерфейсы категорий news/activity из “пусто” стали “данные категории не существуют”, rt_org по-прежнему отстаёт на 2 месяца, у Workshop 8/27 нет информации о разогреве по официальным каналам, способность официального публичного информирования продолжает оставаться слабой.
  5. Ритм версий: v5.2.2 удерживается уже более 9 месяцев, недавние множественные исправления (AF_UNIX, memheap, libc, dfs, сборка Rust) накопились, окно выпуска следующей версии заслуживает внимания.
