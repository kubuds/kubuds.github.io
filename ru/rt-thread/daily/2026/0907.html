1. Динамика ядра и версий

1.1 Три дня без слияний завершены: утренний понедельничный батч влил 4 PR, охватывающих совместимость mmcsd AC5, Kconfig MPU, инструментальную цепочку eclipse, C++ сборку hpmicro

Дата: 2026-09-07 (окно слияния 10:19 ~ 11:18 пекинское время, т.е. 02:19:23Z ~ 03:18:42Z)　Источник: RT-Thread/rt-thread commits (PR #11690, PR #11766, PR #11762, PR #11777)

Основной репозиторий rt-thread завершил серию из трёх окон (трёх дней) без слияний, длившуюся с 09-03 #11776, и в утренний понедельничный час последовательно влил 4 PR:

  • #11690 [device][mmcsd] Fix Arm Compiler 5 build compatibility (коммит от CYFS3, создан 08-10, в очереди дольше всего — около 4 недель): системное исправление проблем совместимости при компиляции кода MMC/SD и блочных устройств компилятором AC5 — конфликт общего имени команды SWITCH с макросами регистров некоторых чипов (переименовано в MMC_SWITCH с одновременным изменением точек вызова в Phytium SDIF); предоставлен именованный способ доступа к полям состояния SD для ARMCC5 (остальные компиляторы продолжают использовать интерфейс с анонимными полями); обход связного списка блочных устройств через явный rt_list_entry вместо зависимости от typeof; добавлено определение структуры разделов при отключённом DFS; очистка арифметики указателей void *.
  • #11766 [mprotect][kconfig] Add safe defaults for MPU region count options (коммит от RogerNext, создан 08-28): добавлены значения по умолчанию Kconfig для NUM_MEM_REGIONS / NUM_CONFIGURABLE_REGIONS / NUM_EXCLUSIVE_REGIONS. Ранее при включённом RT_USING_HW_STACK_GUARD без явной конфигурации rtconfig.h генерировал пустой макрос (#define NUM_CONFIGURABLE_REGIONS), который разворачивался в недопустимое выражение C ((2 + ), for (i = 0U; i < ; i++)), что приводило к ошибке компиляции кода MPU для cortex-m4/m7/m33.
  • #11762 [tools][eclipse] Sync assembler include paths (коммит от wdfk-prog, создан 08-28): синхронизированы пути include ассемблера в проекте плагина eclipse, исправление согласованности сборки официального инструментария (плагин eclipse).
  • #11777 [bsp][hpmicro] wire CXX/CXXFLAGS from rtconfig into scons Environment (коммит от kaidegit, создан 09-01): в BSP hpmicro (серия HPM от HPMicro) при включённом RT_USING_CPLUSPLUS scons Environment не подхватывал CXX/CXXFLAGS из rtconfig и откатывался к хостовому g++, параметры компиляции группы C++ передавались как один аргумент без кавычек, что приводило к ошибке сборки; после исправления CXX/CXXFLAGS внедряются в окружение scons.

Этот пакет совпал по времени с интенсивным ревью мейнтейнера Rbb666 утром того же дня (см. 1.2); основной репозиторий перешёл из «фазы накопления» в «двойную активность: слияние + ревью»; релиз по-прежнему v5.2.2 (2025-10-31), новых действий по выпуску версии пока нет.

1.2 Концентрированная активность в очереди ревью: #11774 после отклонения повторно отправлен в тот же день, #11775 передан на повторное ревью, #11770 получил замечания в строках; новый PR #11781 принят

Дата: 2026-09-07 (пекинское время 10:16 ~ 11:18)　Источник: RT-Thread/rt-thread pulls

В тот же временной интервал, что и пакет слияний, мейнтейнер Rbb666 интенсивно обрабатывал очередь ревью:

  • #11774 [components][sal] Fix SIOCGIFCONF buffer overflow (Huoyanlifusu): в 02:30:45Z получено ревью Rbb666 со статусом CHANGES_REQUESTED, автор в тот же день в 03:04:48Z отправил новый коммит ([components][sal] Fix SIOCGIFCONF buffer overflow) в ответ — быстрый цикл итераций.
  • #11775 [bsp][c908] Поддержка rt-smart и MMU Sv39/48 (QEMU xiaohui c908, включая OpenSBI SMP) (BadmintonMaster): Rbb666 в 02:18:28Z оставил комментарий «@rcitach помоги с ревью», передав на повторное ревью другому мейнтейнеру; этот PR — поддержка rt-smart и OpenSBI SMP для Damo Academy XuanTie C908 на платформе QEMU xiaohui, связан с RISC-V.
  • #11770 fix[usb]: stop aliasing rt_ringbuffer as rt_serial_rx_fifo in VCOM (Finder16): Rbb666 в 03:17:12Z оставил построчную рекомендацию в components/legacy/usb/usbdevice/class/cdc_vcom.c:358 — дополнить путь опроса при rx_bufsz == 0 (Serial V2 при открытии устройства настраивает config.rx_bufsz в 0 и при RT_SERIAL_RX_BLOCKING переходит в режим опроса, не выделяя serial_rx), и привёл пример патча.
  • #11772 [components][asan] Add runtime AddressSanitizer for heap (RogerNext): в 02:16:58Z получен комментарий ревью Rbb666 (COMMENTED).

По новым PR: #11781 [BSP][STM32] Adapt Ethernet driver to new HAL API (CYFS3, создан 09-06 15:17 пекинское время) вошёл в окно, драйвер Ethernet STM32 адаптирован к новому HAL API, и вместе с находящимся в очереди #11689 (stm32 SPI BDMA, moment-NEW) относится к основной линии модернизации драйверов STM32. Новых issue в окне нет.

2. Официальные и общественные мероприятия

2.1 Официальный API новостей — восемнадцатый день подряд без пополнений, до открытия elexcon 2026 осталось 2 дня

Дата: 2026-09-07　Источники: RT-Thread официальный API новостей

Официальный API новостей (категория rt_org) по-прежнему содержит 5 старых записей, самая свежая — всё ещё репортаж об инвестиционном форуме в Абу-Даби от 2026-06-17, восемнадцатый день подряд без пополнений. До открытия elexcon 2026 в Шэньчжэне 9–11 сентября (участие Ruiside, анонс «полного набора AI-железа» был включён в отчёт 08-30) осталось 2 дня, среда на этой неделе — следующее окно для внешних коммуникаций. На китаеязычной стороне медиа (Google News через прокси, проверка “RT-Thread” when:3d, Жуйсайдэ when:7d, Жуйцинпай OR Жуйцин when:7d) и на англоязычной стороне (“RT-Thread” when:2d) в окне нулевых новых публикаций, самая свежая медиа-активность — всё ещё публикация работ сообщества в EE Times China от 09-04 (включена вчера), предконференционное затишье продолжается.

3. Экосистема и адаптация производителей

3.1 canopennode-rtt в окне приостановлен, PR автора wdfk-prog по официальному инструментарию eclipse влит в тот же день — экосистема движется по двум линиям

Дата: 2026-09-07　Источники: wdfk-prog/canopennode-rtt, RT-Thread/rt-thread PR #11762

Внешний форк-репозиторий canopennode-rtt после 09-06 10:06 (поддержка аналоговых событий и fail-safe по CiA401, включена вчера) в окне не имеет новых коммитов, расширение двух профилей CiA402/CiA401 вошло в фазовую паузу. Примечательно, что вклад того же разработчика wdfk-prog в официальный репозиторий приземлился сегодня: его PR #11762 по инструментарию eclipse, отправленный 08-28, сегодня утром влит в основной репозиторий (см. 1.1), а его ведущий рефакторинг CAN-фреймворка #11779 всё ещё на ревью (последний комментарий CYFS3 09-03). Ситуация параллельного движения по двум линиям — «внешний порт экосистемы CANopenNode (canopennode-rtt) + вклады в официальный CAN-фреймворк/инструментарий (#11779/#11762)» — не изменилась, а утреннее окно влития в этот понедельник стало первым случаем, когда результаты обеих линий приземлились в один день.

3.2 topic:rt-thread в экосистеме — других изменений в окне нет

Дата: 2026-09-07　Источники: GitHub topic:rt-thread

Проверка экосистемы topic:rt-thread: с 09-06 нет новых push в репозитории (поиск topic:rt-thread pushed:>2026-09-06 — 0 совпадений); индексный репозиторий packages по-прежнему без обновлений (последняя индексация CANopenNode 09-01, уже включена); в высокочастотных репозиториях, таких как zlgopen/awtk, в окне мониторинга нет коммитов, напрямую связанных со специальными задачами RT-Thread. Фокус экосистемы по-прежнему на canopennode-rtt и вкладе его автора в основной репозиторий.

5. Итоги и наблюдения за тенденциями

  • Сторона ядра: трёхдневная серия нулевых слияний завершена — в понедельник утром с 10:19 до 11:18 в течение часа пакетно влиты 4 PR — исправление совместимости mmcsd с AC5 (включая синхронизацию точек вызова Phytium SDIF, самая долгая в очереди около 4 недель #11690), значение по умолчанию Kconfig для region count MPU (исправление ошибок сборки cortex-m4/m7/m33), синхронизация include ассемблера инструментальной цепочки eclipse, исправление сборки C++ для BSP hpmicro; в тот же период мейнтейнер Rbb666 интенсивно проводил ревью — #11774 после отклонения в тот же день повторно отправлен автором, #11775 передан rcitach на повторное рассмотрение, #11770 получил предложение по встроенному патчу, #11772 получил комментарии ревью; новый PR #11781 (адаптация Ethernet HAL для STM32) принят, в окне ноль новых issue, релиз по-прежнему v5.2.2. Состояние основного репозитория сместилось от накопления к «двойной активности слияния + ревью»; учитывая скорое открытие elexcon 2026, намерение разгрузить очередь ревью перед конференцией очевидно.
  • Сторона экосистемы: canopennode-rtt в окне приостановлен (предыдущий коммит утром 09-06 уже включён), однако официальный PR #11762 его автора wdfk-prog по инструментальной цепочке eclipse и внешний порт были приняты в один день — «внешняя экосистема + официальный вклад» продвигаются параллельно; остальная часть экосистемы topic без динамики.
  • Официальная сторона/сторона медиа: официальный API новостей молчит 18-й день подряд; на стороне медиа в 24-часовом окне ноль новых записей (прокси и проверка источников в норме); до elexcon 2026 (09-09~11, Шэньчжэнь) осталось 2 дня, предконференционная тишина — ожидаемый ритм.
  • Тенденции за последние три дня (09-05 ~ 09-07): официальное молчание 16-й день, влитие env WebUI keep_alive (#294), PR #11780 об утечке sdio CIS, диагностика CiA402/EMCY/сторона контроллера и запуск ветки CiA401 (09-05) → официальное молчание 17-й день, аналоговые события CiA401 и отказобезопасность приняты, завершение адаптации gdr FreeRTOS (09-06) → официальное молчание 18-й день, пакетное влитие 4 PR в основном репозитории и концентрированная активность очереди ревью, новый PR #11781 адаптация Ethernet для STM32 (09-07). Основная линия продвижения переключилась с «итерации официального WebUI инструментальной цепочки + расширения двух профилей CANopenNode» на «двойную активность слияния/ревью в основном репозитории (в основном исправления сборки инструментальной цепочки и BSP) + разгрузку очереди перед конференцией», внешняя активность накапливает силы к elexcon 2026.
