1. Динамика ядра и версий

1.1 В основной репозиторий слито [utest][rtc]: добавлены тестовые примеры времени и будильника RTC

Дата: 2026-09-01 (слияние в 13:36 пекинского времени)　Источник: PR #11755 (коммит слияния b1e8365, сопровождающий Rbb666 слил)

После вчерашней партии из 4 PR по устойчивости (права MPU / освобождение net sal / PWM utest / Renesas CAN FD) единственным слиянием в окне основного репозитория стало это дополнение тестового покрытия: добавлены два набора тестовых примеров — тест времени RTC (rtc_time_tc.c) и тест будильника (rtc_alarm_tc.c) в каталоге components/drivers/rtc/utest/, а также подключено их включение в Kconfig / SConscript драйвера RTC и общей конфигурации components/utilities/utest. Драйвер RTC ранее не имел специализированных тестовых примеров в системе utest; данный коммит обеспечивает автоматизированную регрессию для функций времени и будильника, продолжая недавнюю основную линию на стороне ядра «дополнение тестового покрытия»; крупных слияний новых функций в окне не наблюдается.

2. Официальные и общественные мероприятия

2.1 Официальный новостной API тринадцатый день подряд без пополнений, elexcon 2026 на обратном отсчёте

Дата: 2026-09-02　Источник: официальный новостной API RT-Thread

Официальный новостной API (категория rt_org) по-прежнему содержит 5 старых записей, самая свежая — всё ещё репортаж об инвестиционном форуме в Абу-Даби от 2026-06-17, тринадцатый день подряд без пополнений. Множественные дополнительные проверки gnews (RT-Thread when:3d на китайском и английском, RT-Thread 睿赛德 when:3d, 睿擎派 OR 睿擎 when:3d): англоязычные запросы по-прежнему дают шум от разбиения «RT» — рейтинги Rotten Tomatoes / SCALR AI и т. п.; китайскоязычные запросы совпали только с записью-руководством EET-China, добавленной сегодня; запросы по Ruiqing пусты. Следующее официальное внешнее окно — выставка elexcon 2026 в Шэньчжэне 9-11 сентября (Ruiqing от Ruiside участвует, демонстрируя «полный набор» AI-оборудования, анонс от 8-30 уже учтён), до открытия неделя, продолжение периода молчания ожидаемо.

3. Экосистема и адаптация производителей

3.1 packages: программный пакет FM33LG0xx FL Library от Fudan Microelectronics вошёл в индекс, сопутствующий BSP всё ещё ожидает слияния

Дата: 2026-09-01 (слияние в 11:40)　Источник: RT-Thread/packages PR #2030

Добавлен официальный пакет программного обеспечения библиотеки FL-драйверов fm33lg0xx_fl_library для серии MCU FM33LG0xx от Fudan Microelectronics, доступны версии индекса v2.3.5 / latest, размещён по пути peripherals/hal-sdk/fm33/, что соответствует существующей системе HAL-драйверов отечественных производителей (каталог hal-sdk). В описании PR указано, что пакет предназначен для использования с rt-thread/bsp/fm33lg026 — этот BSP планируется перевести на зависимость от данного пакета, однако соответствующий BSP PR (#11729, создан 08-21) в настоящее время всё ещё находится в статусе open, то есть «пакет сначала попадает в индекс, BSP ожидает слияния в основной репозиторий». Очередной пример включения HAL-драйверов отечественного производителя низкопотребляющих MCU (серия FM33 от Fudan Microelectronics — линейка низкопотребляющих продуктов на Cortex-M0+) в официальную систему пакетов программного обеспечения.

3.2 packages: порт CANopenNode официально включён в индекс официальных пакетов

Дата: 2026-09-01 (слияние в 16:45)　Источник: RT-Thread/packages PR #2033, github.com/wdfk-prog/canopennode-rtt

В отчёте за прошлый день отмечалось, что репозиторий сообщества canopennode-rtt «независим от официального индекса packages, следим за тем, войдёт ли он в официальную систему пакетов»; сегодня это свершилось: порт CANopenNode для RT-Thread, представленный wdfk-prog, официально добавлен в официальный индекс, пользователи могут напрямую настраивать, загружать и использовать его через Env/menuconfig (из описания PR). CANopenNode — известный международный открытый стек протокола CANopen, данный пакет ориентирован на сценарии промышленной/автомобильной связи CANopen. Исходный репозиторий продолжает оставаться активным в течение окна мониторинга: 09-02 11:02 co_rtt_mainline_deadline_min переведён в extern для взаимодействия с планированием основной линии, 09-01 15:14 удалено временное тестовое именование и обновлена документация (событийно-ориентированное планирование основной линии 08:54 уже было включено вчера). Превращение проекта сообщества в официальный индекс подтверждает работоспособность пути «сообщество → официальный пакет».

3.3 В процессе: PR обновления конфигурации пакета Tencent IoT SDK ожидает рецензирования

Дата: 2026-09-02 (создан в 10:17, open)　Источник: RT-Thread/packages PR #2034

В индексе packages открыт новый PR #2034: обновление конфигурации пакета программного обеспечения Tencent IoT SDK, в настоящее время open, ожидает слияния. Подключение к Tencent Cloud IoT — часто используемый пакет в сценариях интернета вещей, детали обновления конфигурации будут наблюдаться после слияния, включено как текущая динамика в процессе.

4. Отраслевые применения

4.1 Публикация EET-China: практические заметки по развёртыванию YOLO-Fastest на NPU Ethos-U55

Дата: 2026-09-01 (опубликовано в 17:30)　Источник: Агрегация Google News (оригинальный сайт eet-china.com/mp/a521750.html, оригинальный сайт в настоящее время недоступен, детали по заголовку и аннотации)

В колонке «Технический сбор» издания EE Times China опубликованы практические заметки о сквозном порте алгоритма AI-распознавания лиц из среды обучения (PyTorch / TensorFlow) на платформу Arm Ethos-U55 microNPU (ориентировано на MCU с Ethos-U55, такие как Renesas RA8P1, популярная тема конкурса AI Renesas), основная работа охватывает квантование модели, калибровку точности и цепочку развёртывания инференса. Статья имеет тег RT-Thread на EET-China и найдена по запросам, связанным с RT-Thread, относится к категории руководств по развёртыванию периферийного AI в экосистеме RT-Thread; единственная новая запись на стороне СМИ в окне мониторинга. Тематика развёртывания инференса на периферийных NPU продолжает недавнюю популярность (согласуется с направлением AI-аппаратного обеспечения RT-Thread), обучающий контент имеет непосредственную ценность для экосистемы разработчиков.

5. Итоги и наблюдения за тенденциями

  • Сторона ядра: в окне мониторинга одно вливание в основной репозиторий ([utest][rtc] дополнение тестов RTC времени/будильника, 09-01 13:36), продолжение основной линии тестового покрытия после вчерашней партии по надёжности, ритм вливаний в рабочие дни стабилен, крупных новых функций не обнаружено.
  • Сторона экосистемы: индекс пакетов третий день подряд активен — библиотека FM33LG0xx FL от Fudan Microelectronics вошла в индекс (расширение HAL-драйверов отечественных MCU), порт-пакет CANopenNode переведён из статуса общественного проекта в официальный индекс (вчерашний прогноз реализован), обновление конфигурации Tencent IoT SDK в процессе; «управление и расширение экосистемы пакетов» — наиболее чёткая текущая линия продвижения.
  • Официальная сторона: официальный API новостей 13 дней подряд без новых поступлений; следующее внешнее окно — 9–11 сентября, Shenzhen elexcon 2026, до которого остаётся неделя.
  • Сторона медиа: единственная новая запись в окне — руководство по развёртыванию Ethos-U55 + YOLO-Fastest от EET-China, тематика развёртывания периферийного AI сохраняется; Google News по-прежнему сильно зашумлён разбивкой слова «RT-Thread», медиаисточники следует сверять с официальным API и GitHub.
  • Тренд за последние три дня (08-31 ~ 09-02): партия совместимости RT-Smart POSIX и управление двумя версиями optparse (08-31) → 4 PR по надёжности ядра, событийно-управляемая диспетчеризация CANopenNode (09-01 утро) → RTC utest, два пакета в индексе, перевод CANopenNode в официальный статус (09-01 после обеда ~ 09-02). Основные линии — дополнение тестового покрытия ядра + расширение индекса пакетов + продвижение промышленной связи (CANopen) и экосистемы периферийного AI; в дни с низким новостным потоком преобладает динамика репозиториев GitHub.
