1. Динамика ядра и версий

1.1 Исправление переполнения буфера SIOCGIFCONF на уровне sal влито в основной репозиторий (#11774)

Дата: 2026-09-07 (влито в 14:53 по пекинскому времени, то есть 06:53:10Z)　Источник: RT-Thread/rt-thread commits (PR #11774)

Упомянутый во вчерашнем отчёте в очереди ревью #11774 [components][sal] Fix SIOCGIFCONF buffer overflow (отправлен Huoyanlifusu) 09-07 после обеда был официально влит в master. Утром 09-07 этот PR получил от Rbb666 замечание CHANGES_REQUESTED с возвратом, и автор в тот же день повторно отправил пересмотренную версию (зафиксировано вчера); данное вливание знаменует завершение цикла «возврат — повторная отправка — вливание». Исправление касается риска переполнения буфера в обработке ioctl SIOCGIFCONF (получение списка адресов интерфейсов) на уровне sal и относится к категории исправлений безопасности памяти сетевых компонентов; время вливания — после вчерашней утренней партии из 4 PR, это единственное новое вливание в окне мониторинга. Релиз по-прежнему v5.2.2 (2025-10-31), новых выпусков версий нет.

Дата: 2026-09-08 (11:04 по пекинскому времени, то есть 03:04:16Z, одновременно создан tag v2.1.0)　Источник: RT-Thread/env-windows (commit fc857c5, tag v2.1.0)

Репозиторий версии для Windows инструмента RT-Thread Env (инструмент Env в среде оболочки ConEmu) сегодня утром выпустил v2.1.0: единственный коммит “Update Env to version 2.1.0”, затрагивающий обновление индекса пакетов packages, а также изменения tools/bin/env-init.bat и tools/scripts. С момента предыдущей официальной версии v2.0.0 (2024-07-10) прошло более двух лет — это первый скачок версии в репозитории env-windows после 2024-07 (за это время лишь в 2025-06 был добавлен один функциональный коммит с инструментом DTC); объект release v2.1.0 на странице GitHub Releases ещё не создан, на данный момент зафиксирован только tag, официальные примечания к релизу, как ожидается, появятся через каналы анонсов/официального аккаунта в WeChat. В связке с итерацией поддержки плагина WebUI, влитой в основной репозиторий env 09-04 (#294, уже зафиксировано), темп итераций инструментальной цепочки Env (конфигурация через меню / управление пакетами / плагин WebUI) в последнее время ускорился, что, возможно, является частью действий по интеграции инструментальной цепочки в преддверии и вокруг elexcon 2026.

Дата: 2026-09-07 ~ 2026-09-08　Источник: RT-Thread/rt-thread pulls

В окне мониторинга открыто два новых PR, в очереди ревью продолжается активность:

  • #11785 [bsp][nxp] Add FRDM-MCXC162 BSP support (yandld, создан 09-07 17:52, сегодня утром в 10:53 ещё обновлялся): добавлена поддержка BSP для отладочной платы NXP FRDM-MCXC162. yandld — давний контрибьютор NXP BSP, ранее уже неоднократно отправлял BSP серии NXP; MCXC1xx — это начальная серия MCU от NXP (Cortex-M0+), данный PR продолжает регулярное расширение покрытия плат экосистемы NXP. Всё ещё на ревью.
  • #11782 [net][at] Reject overlong numeric hostnames (wyf-777, создан 09-07 12:08): _gethostbyname_by_device() ранее копировала числовое имя хоста через strncpy(ipstr, name, strlen(name)) в 16-байтовый буфер стека — 16-байтовый ввод съедал терминатор, ввод длиной 17 байт и более приводил к записи за границы; исправление отклоняет чрезмерно длинные числовые имена хостов. Патч категории безопасности памяти сетевого компонента, вместе с #11774 относится к недавнему направлению исправлений безопасности/устойчивости.

По очереди ревью: #11775 ([bsp][c908] поддержка xiaohui C908 rt-smart + MMU Sv39/48 + OpenSBI SMP, BadmintonMaster) в окне добавлены два новых коммита (09-07 19:45, 20:11 пекинское время, соответственно добавлена поддержка rt-smart/MMU для xiaohui C908 и поддержка OpenSBI SMP), итерационное продвижение в ответ на повторное ревью rcitach/Rbb666; #11779 (рефакторинг жизненного цикла драйвера CAN, wdfk-prog) и #11772 (heap AddressSanitizer, RogerNext) сегодня утром 11:08 ~ 11:10 пекинское время всё ещё обновлялись (действия ревью/коммитов), застоя в очереди не наблюдается.

Действия по очистке со стороны мейнтейнеров: 09-08 09:37 пекинское время массово закрыты три старых PR по NXP BSP — #6658 (обновление драйверов NXP SDK для LPC55Sxx BSP до 2_12_0, закрыт без слияния), #11243 (frdm-mcxa366, слит в 2026-03), #9342 (frdm-mcxn236, слит в 2024-08), последние два представляют собой очистку очереди от дублирующих/устаревших PR по уже слитому содержимому. В сочетании с подачей нового BSP в #11785, «смена старого новым» в очереди NXP BSP согласуется с ритмом очистки перед конференцией elexcon.

1.4 Предложение темы OSPP 2026: ленивое переключение контекста FP/RVV для RISC-V (#11786)

Дата: 2026-09-07 (создано 23:49 пекинское время, то есть 15:49:05Z)　Источник: RT-Thread/rt-thread issue #11786

Внешний контрибьютор PiyushPatle26 подал в основной репозиторий предложение темы OSPP 2026 (issue #11786): текущий порт RISC-V при каждом переключении контекста безусловно сохраняет/восстанавливает полное состояние FPU, даже если поток никогда не использует плавающую точку; при этом ядро совершенно не поддерживает векторное расширение (RVV) — векторные регистры не входят в контекст потока, и состояние любого потока, использующего V-инструкции, будет молча нарушено при переключении контекста. Предлагается использовать уже предоставляемые аппаратно биты dirty mstatus.FS / mstatus.VS, чтобы перевести сохранение/восстановление расширенного состояния в ленивый (lazy) режим вместо безусловного выполнения. Эта тема связана с более ранним issue #10722 (пробел в поддержке векторов RISC-V). Если предложение будет отобрано, оно станет структурным улучшением управления контекстом расширений с плавающей точкой/векторных в порте RISC-V ядра, и вместе с #11775 (C908 rt-smart/MMU) относится к продвижению основной линии RISC-V на стороне ядра. В окне также два issue по проблеме параметра IRQ в legacy-пути pin_api_attach_irq (#11783 закрыт, #11784 отслеживается, созданы 09-07 15:14/16:57), это follow-up-отчёты по одной и той же проблеме регистрации драйвера.
