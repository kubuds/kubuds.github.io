1. Динамика ядра и версий

1.1 Исправление дублирующей диспетчеризации прерываний Renesas RZ/N2L влито: двойная диспетчеризация уровня trap Cortex-R52 и таблицы векторов FSP приводит к ошибочному подключению прерываний UART после включения CANFD (PR #11765)

Дата: 2026-09-10 (влито в 10:09 пекинское время)　Источник: RT-Thread/rt-thread commits (PR #11765)

Единственное функциональное вливание в основной репозиторий за окно мониторинга и самое значимое исправление уровня ядра за сегодня. PR #11765 [libcpu][cortex-r52] Fix duplicate interrupt dispatch on Renesas RZ (коммит CYFS, влито Rbb666) официально вошёл в master утром 09-10, изменения сосредоточены в libcpu/arm/cortex-r52/trap.c (+25/-27, один файл).

Первопричина проблемы чётко описана автором коммита: платформа RZ/N2L использует FSP (Flexible Software Package) Renesas для управления векторами прерываний, тогда как текущая обработка trap Cortex-R52 после вызова bsp_common_interrupt_handler() использует GIC INTID как индекс таблицы векторов FSP и снова диспетчеризует через isr_table RT-Thread — образуется двойная диспетчеризация. После включения CANFD GIC INTID 321 для UART RX ошибочно попадает в CANFD TX ISR из g_vector_table[321], что проявляется в виде входа в ошибочное прерывание при нажатии Enter в консоли и срабатывания data abort. Направление исправления — убрать лишнюю диспетчеризацию, чтобы прерывание шло по единственному пути.

Данный PR был создан 08-28, после примерно двух недель ревью влит 09-10, представляет собой ещё одно исправление корректности платформенного уровня в направлении BSP Renesas. Сопутствующее наблюдение: долгосрочные PR #11228 (аппаратная ошибка, вызванная выравниванием доступа к байтам klibc) и #11313 (настройка делителя clock_timer Renesas), также относящиеся к Renesas и низкоуровневому направлению, обновлены утром 09-10 и по-прежнему находятся в очереди ревью; темп ревью линии Renesas/KLIBC ускоряется.

1.2 Скрипт сборки компонента Rust избавляется от зависимости toml на этапе clean (PR #11791)

Дата: 2026-09-09 (влито в 13:31 пекинское время)　Источник: RT-Thread/rt-thread commits (PR #11791)

В пределах окна основного репозитория — ещё одно слияние, изменения в components/rust/examples/modules/SConscript (+3/-2), заголовок [rust][build] Avoid toml dependency during clean. При выполнении цели clean больше не требуется разбор toml, что позволяет завершить процесс очистки и в окружении без установленных соответствующих зависимостей Python. PR создан 09-09 12:56, слит 13:31, весь цикл около 35 минут — самое быстрое по скорости прохождения изменение дня; автор коммита — CYFS, выполнил слияние — Rbb666.

Само изменение невелико, но в сочетании с двумя другими действиями, связанными с Rust, в пределах окна можно наблюдать, что компонент Rust в RT-Thread (примерный модуль компонента rust) находится в периоде непрерывной доработки: оптимизация надёжности сборочных скриптов относится к типичному «подметающему» типу сопровождения, которое обычно появляется на этапе, когда поддержка нового языка переходит от «работает» к «пригодно для повседневного использования».

1.3 Наблюдение за очередью ревью: новый PR исправления SCI SPI для Renesas, новый PR документации QEMU, закрытый без слияния PR усиления консоли FinSH от Copilot

Дата: 2026-09-09 ~ 2026-09-10　Источники: RT-Thread/rt-thread pulls

  • [bsp/renesas][drivers] Fix SCI SPI runtime configuration and transfer errors (PR #11792, CYFS3, создан 09-09 17:25, 2 коммита, +254/-193): при диагностике проблемы замыкания SCI SPI на RZ/N2L EtherKit обнаружено несколько дефектов в общем драйвере SCI SPI — интерфейс делителя частоты RZ передаёт false как указатель на результат деления и не использует фактический источник тактирования из конфигурации FSP; конфигурация времени выполнения не передаётся надёжно в FSP, а при повторной конфигурации старый экземпляр не закрывается корректно; в процессе конфигурации единица разрядности RT-Thread ошибочно изменена с bit на byte; после тайм-аута или ошибки при ожидании приёма-передачи по-прежнему возвращается длина передачи, что приводит вызывающую сторону к ошибочному выводу об успехе. Утром 09-10 этот PR всё ещё обновлялся и является следующим ключевым объектом ревью в линейке драйверов Renesas (вместе с 1.1 относится к платформе RZ/N2L EtherKit).
  • [docs] point QEMU Linux quick start at qemu-nographic.sh (PR #11793, shiptux, создан 09-09 23:53, +12/-0): указывается, что в документации быстрого старта упоминается только ./qemu.sh, а этот скрипт передаёт -serial stdio без -nographic, из-за чего QEMU пытается открыть окно GTK и в среде без дисплея или по SSH зависает на gtk initialization failed; сам BSP уже предоставляет qemu-nographic.sh и рекомендует его в README для серверных сценариев, поэтому документация дополнена пояснением. Продолжение той же ритмики правки документации тем же контрибьютором, что и два PR по документации от 09-08 (#11789/#11790).
  • Harden FinSH console switching against unsafe output devices (PR #11455, Copilot, закрыт 09-10 09:26, не слит): этот PR создан 06-09, суммарно 5 коммитов (+290/-18), цель — добавить в rt_console_set_device() проверку устройства, разрешая переключать в консоль только устройства, предоставляющие флаг безопасного открытия консоли или обладающие возможностью асинхронной передачи через прерывания/DMA, а также сохранять старую консоль до прохождения проверки новым устройством, чтобы устранить путь крэша при печати в блокирующее устройство в контексте ISR или обработки сбоев. После трёх месяцев открытого состояния закрыт без слияния; сделан вывод, что решение не было принято (другой коммит Copilot из той же партии #11454 по усилению указателей sys_getaddrinfo всё ещё на ревью). В пределах окна в основном репозитории также открыто 3 новых PR, слито 2, создано 0 новых Issue.

3. Экосистема и адаптация производителей

3.1 Экосистемный репозиторий GigaDevice: четыре BSP GD32 массово влиты: 103c / 107c / 205r / e503v переведены на новую архитектуру BSP (09-09)

Дата: 2026-09-09 (13:52 ~ 19:56 пекинское время)　Источник: GD32-MCU-IOT/gd32_rt-thread commits

В экосистемном репозитории с topic:rt-thread нижестоящий репозиторий серии GD32 (GD32-MCU-IOT/gd32_rt-thread) в течение окна мониторинга массово принял четыре PR веток BSP — крупнейшая группа действий на стороне экосистемы за день:

  • gd32103c-eval (PR #69, влит в 13:52, 26 файлов +4783/-2341): для GD32F103VCT6 (Cortex-M3) дополнена инициализация уровня платы BSP и шаблоны проектов IDE, что позволяет компилировать и прошивать в трёх тулчейнах Keil (AC6) / GCC / IAR и прогонять utest, добавлены конфигурационные заголовки драйверов F10x и инициализация уровня board.
  • gd32205r-start (PR #65, влит в 15:09, 18 файлов +6294/-6283): добавлен board_msd_init.c для инициализации GPIO UART, удалены связанные с UART RX DMA опции Kconfig и rtconfig.h, файлы проекта обновлены до chip family GD32F20xxE.
  • gd32107c-eval (PR #66, влит в 19:38, 15 файлов +4213/-2439): обновление до новой архитектуры GD32 BSP, добавлены конфигурационные заголовки dma/uart/spi/i2c для f10x и поддержка серии SOC_SERIES_GD32F10x, board_msd_init.c.
  • gd32e503v-eval (PR #67, влит в 19:56, 35 файлов +10876/-2525): адаптация системы e503v и распространённых периферийных устройств, охватывающая GPIO, I2C, SPI, USART, DMA.

Общая линия всех четырёх изменений — «миграция на новую архитектуру GD32 BSP»: унифицированное добавление инициализации уровня платы board_msd_init.c, унифицированная перекомпоновка конфигурационных опций Kconfig/.config, унифицированное обновление файлов проектов Keil/IAR. Контрибьюторы — junying2025 и yuanshuo0, это коммиты, инициированные на стороне экосистемы GigaDevice. Данный репозиторий является нижестоящим по отношению к RT-Thread, а не основным, содержимое — адаптация уровня платы для семейства устройств GD32 (в данном случае все — ядра ARM Cortex-M) на RT-Thread, включено как окно наблюдения за продвижением экосистемы производителя.

3.2 Индекс пакетов: добавлен индекс пакета STM32N6 HAL SDK (PR #2037)

Дата: 2026-09-09 (объединён в 15:26 по пекинскому времени)　Источник: RT-Thread/packages commits (PR #2037)

В окне мониторинга в репозитории индекса пакетов RT-Thread появилась одна запись: [hal_sdk] add stm32n6 индекс репозитория пакета (коммит yans6666, создан 09-09 в 14:10, объединён в 15:26, рецензент Rbb666). Это реализация индекса репозитория пакета для HAL SDK серии STM32N6, позволяющая разработчикам напрямую ссылаться на поддержку HAL STM32N6 в менеджере пакетов. STM32N6 — это серия высокопроизводительных MCU от STMicroelectronics с собственным NPU; реализация индекса означает, что интеграция этой платформы в RT-Thread вступает в фазу пакетизации, образуя единую линию производителя с рядом недавних адаптаций драйверов для направления STM32 (BDMA for SPI, адаптация драйвера Ethernet к новому HAL API).

  • 09-08: в основной репозиторий объединён BSP NXP FRDM-MCXC162 (PR #11785, рецензирование заняло три дня) и исправление порядка путей include в Keil (PR #11741); открыто 4 новых PR (исключение скрытых каталогов Eclipse, 2 по документации QEMU, адаптация фреймворка ch32 закрыта в тот же день); в индексе пакетов обновлены конфигурации Tencent IoT SDK и autogen_parameter_manager; создан объект релиза Windows-версии Env v2.1.0.
  • 09-09: в основной репозиторий объединены чтение регистров Renesas GPT PWM (#11753) и удаление зависимости от toml в сборочном скрипте Rust (#11791); в репозиторий экосистемы GD32 объединены четыре BSP; в индекс пакетов добавлен STM32N6 HAL SDK; открылась выставка elexcon в Шэньчжэне.
  • 09-10: в основной репозиторий объединено исправление доставки прерываний RZ/N2L (#11765); открыт и продолжает обновляться PR с исправлением Renesas SCI SPI (#11792); PR по укреплению консоли FinSH от Copilot (#11455) закрыт без объединения.

Оценка основной линии

  • BSP от Renesas — самая активная линия вендоров на этой неделе: с 09-07 по 09-10 четыре дня подряд действия в этом направлении (обнаружение карт SDHI, запись выбора чипа SCI SPI, чтение регистров GPT PWM, распределение прерываний RZ/N2L), и все они представляют собой исправления корректности на уровне драйверов и прерываний, а не добавление новых плат, что указывает на этап шлифовки зрелости серии RZ на RT-Thread.
  • «Новые платы NXP поступают, старые заявки закрываются» и «массовая миграция GD32 на новую архитектуру» образуют два параллельных пути экосистемы вендоров: первый — темп приёма в основном репозитории, второй — самоорганизующееся продвижение в нижестоящих репозиториях вендора.
  • Темп разбора очереди ревью заметно дифференцирован: небольшие изменения (сборка Rust около 35 минут, индекс пакетов около 76 минут) проходят быстро, тогда как изменения на уровне ядра и драйверов (прерывания Renesas 13 дней, KLIBC и clock_timer — долгосрочные PR длительностью более месяца) имеют значительно более длительный цикл.

Пояснение ограничений

  • В данном окне мониторинга запросы Google News на китайском и английском по «RT-Thread» не дали действительных результатов (на английской стороне постоянно попадает шум категории кинорецензий Rotten Tomatoes), на китайской стороне остаётся лишь анонс elexcon от 08-30, поэтому данный отчёт в основном опирается на GitHub и официальный API, охват медиаисточников ограничен.
  • Информация о новых продуктах на месте и подписаниях в период выставки elexcon обычно высвобождается централизованно после закрытия; на момент публикации данного отчёта (второй день выставки) публичных материалов ещё нет, соответствующие пункты классифицированы как «в процессе», а не как «добавлено».
