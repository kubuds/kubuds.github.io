1. Динамика ядра и версий

1.1 В основной репозиторий влит [lwp]: terminal/ вынесен из глобального CPPPATH

Дата: 2026-09-03 (слияние в 09:20 пекинское время)　Источник: PR #11776 (коммит слияния 54e5164, автор коммита TTLLDD)

Ранее components/lwp/SConscript добавлял каталог ./terminal/ в глобальный CPPPATH; данный коммит убирает это. Проверка по всему репозиторию показывает: все неквалифицированные include заголовочных файлов подсистемы terminal (terminal.h, tty_config.h, bsd_porting.h и т. д.) исходят из внутренних исходных файлов components/lwp/terminal/, и поиск компилятором в форме кавычек их полностью удовлетворяет — необходимости утекать внутренний каталог в глобальный путь включения нет. Это минимальная демонстрационная реализация договорённости из обсуждения #10980 от 2025-11 «нормализовать использование CPPPATH» — компонент больше не пропускает внутренние каталоги в глобальный путь include; небольшой шаг в направлении гигиены системы сборки/include. Единственное слияние в основном репозитории за окно; ритм слияний утром рабочего дня соответствует недавнему, крупных функций нет.

1.2 В работе: разработчик сообщества представил PR структурного рефакторинга фреймворка CAN

Дата: 2026-09-02 (создан в 13:21 пекинское время, open, CI clean, не draft)　Источник: PR #11779

wdfk-prog (автор пакета портирования CANopenNode, вчера переведённого в официальный индекс) представил PR refactor[CAN]: структурный рефакторинг Generic CAN Framework и бэкенда STM32 bxCAN (2 коммита, 8 файлов, +2902/-1308), заново определяющий границы ответственности фреймворка — Generic CAN отвечает за управление аппаратными ресурсами, синхронизацию, ownership и жизненный цикл, а буферизация отправки/повторы/планирование и политика QoS протокола передаются верхнему протокольному стеку или приложению. У предложения два источника: запрос функции от 8-26 #11759 (для переключения скорости передачи CANopen CiA 305 LSS Activate Bit Timing в реальном времени требуются возможности TX Full Flush и Hardware Abort; закрыт) и обсуждение рефакторинга фреймворка от 8-28 #11767 (унификация TX Engine, Mailbox Ownership и Lifecycle; после закрытия обсуждения через 3 минуты был создан данный PR). Оба обсуждения были закрыты в пределах окна и сведены в этот PR; метки включают BSP: STM32 и component: drivers/can. Данный PR превращает пробелы в низкоуровневых возможностях, выявленные при портировании CANopenNode, в предложение по рефакторингу уровня фреймворка; в настоящее время ожидает ревью мейнтейнеров; в случае слияния это будет крупнейшая за последние годы корректировка границ ответственности Generic CAN Framework.

2. Официальные и общественные мероприятия

2.1 Официальный новостной API: четырнадцатый день подряд без обновлений, до elexcon 2026 — 6 дней

Дата: 2026-09-03　Источник: официальный API новостей RT-Thread

Официальный API новостей (категория rt_org) по-прежнему содержит 5 старых записей, самая свежая из которых — репортаж об инвестиционном форуме в Абу-Даби от 2026-06-17; четырнадцатый день подряд без новых добавлений. Дополнительные проверки по нескольким запросам в gnews (RT-Thread when:3d на английском и китайском, RT-Thread 睿赛德 when:3d, 睿擎派 OR 睿擎 when:3d): на английском по-прежнему шум от разбитого на слова названия Rotten Tomatoes и нерелевантные технологические посты, китайские запросы все пусты. Следующее внешнее окно — 9–11 сентября, Shenzhen elexcon 2026 (участие Ruiside, анонс от 8-30 уже учтён), обратный отсчёт 6 дней; продолжение предконференционного затишья ожидаемо.

3. Экосистема и адаптация производителей

3.1 Ветки функций canopennode-rtt продолжают оставаться активными, в окне мониторинга нет новых коммитов в основную ветку

Дата: 2026-09-02 (push в репозиторий в 22:30 по пекинскому времени)　Источник: github.com/wdfk-prog/canopennode-rtt

Один из репозиториев с push в окне мониторинга по topic:rt-thread. Последний коммит ветки по умолчанию master по-прежнему — от 09-02 11:02 по пекинскому времени «co_rtt_mainline_deadline_min скорректировано extern в соответствии с расписанием основной ветки» (уже учтён вчера), push в окне мониторинга пришёлся на две ветки функций — A04 и ds402 — то есть на продолжающуюся эволюцию веток для разных профилей CANopen (DS402 — управление движением, A04 — приложение); в основной ветке нового содержимого нет. В тот же день автор этого репозитория предложил в основном репозитории RT-Thread PR по рефакторингу фреймворка CAN (см. 1.2); двустороннее продвижение «прикладной уровень (пакет CANopenNode) → уровень фреймворка (рефакторинг Generic CAN)» делает экосистему CAN наиболее активной линией продвижения в сообществе на данный момент.

4. Отраслевое применение

4.1 Экосистемный справочник: обновление документа по реверс-инжинирингу прошивки потребительского дрона H120D

Дата: 2026-09-02 (push в 13:34 по пекинскому времени)　Источник: H4ck3rTR/h120d-protocol

Экосистемный репозиторий topic:rt-thread h120d-protocol обновлён в окне мониторинга (правка README, систематизация материалов апрельской публикации на Hackaday). Этот проект документирует методом реверс-инжиниринга протокол WiFi-связи потребительского дрона Holy Stone H120D и внутреннюю реализацию RT-Thread в его прошивке, а также предоставляет инструменты управления; код преимущественно на C++. В окне мониторинга существенных обновлений кода нет — это сопровождение документации; само существование проекта косвенно подтверждает развёртывание RT-Thread в прошивках потребительских дронов (заявление самого проекта реверс-инжиниринга, официально не подтверждено), учтён как низкоактивный экосистемный справочник.

5. Итоги и наблюдения за тенденциями

  • Ядро: в окне мониторинга — одно слияние: [lwp] перенос terminal/ из глобального CPPPATH (09-03 09:20), продолжение реализации темпов внедрения гигиены сборки/include (issue #10980), крупных слияний функций нет.
  • В процессе: PR структурного рефакторинга фреймворка CAN (#11779, +2902/-1308) представлен разработчиком сообщества wdfk-prog, CI clean, не draft, ожидает ревью мейнтейнера; обсуждение CAN конца августа (#11767) и запрос функции (#11759) уже закрыты и сведены в этот PR, направление рефакторинга получило консенсус на стороне сообщества.
  • Официальная сторона: официальный API новостей 14 дней подряд без новых добавлений; следующее внешнее окно — 9–11 сентября, Shenzhen elexcon 2026, обратный отсчёт 6 дней.
  • Экосистема: двойное продвижение CAN (уровень приложения — расширение веток профилей, таких как DS402, после повышения статуса CANopenNode + предложение по рефакторингу уровня фреймворка) — наиболее чёткая на данный момент основная линия сообщества; в индексе пакетов в окне мониторинга нет новых слияний, PR конфигурации Tencent IoT SDK #2034 всё ещё open.
  • Тренд за последние три дня (09-01 ~ 09-03): партия из 4 PR по надёжности ядра, событийно-управляемое планирование CANopenNode, RTC utest и включение двух пакетов Fudan Microelectronics FM33/CANopenNode в индекс (09-01) → PR конфигурации Tencent IoT SDK, предложение PR рефакторинга фреймворка CAN, обновление документа h120d (09-02) → слияние гигиены lwp CPPPATH, PR рефакторинга CAN ожидает ревью, 14-й день официального затишья (09-03). Основная линия продвижения переключилась с «расширения индекса пакетов» на «глубокое продвижение экосистемы CAN + нормализация системы сборки».
