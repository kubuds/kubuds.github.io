Ежедневный отчёт RT-Thread (2026-08-18)

2026-08-18 Kubuds

Окно мониторинга: последние 24 часа (2026-08-17 11:18 ~ 2026-08-18 11:18 пекинское время) Источники: официальный новостной API RT-Thread, GitHub (org: RT-Thread / topic: rt-thread / коммиты основного репозитория), агрегатор Google News (zh-CN, через прокси), HN и др. (подробнее в приложении)

1. Динамика ядра и версий

1.1 В ядро добавлена нативная реализация локальных сокетов AF_UNIX (влито 17 августа, крупнейшее событие в ядре за это окно)

Дата: 2026-08-17 17:15 (пекинское время влития)　Источник: rt-thread PR #11681

PR #11681 «Add AF_UNIX sockets implementation», отправленный основателем проекта Сюн Пусяном (BernardXiong) и влитый в основной репозиторий мейнтейнером Rbb666, затрагивает 36 файлов с чистым приростом около 5700 строк — крупнейшее по масштабу влитие в ядро за это окно. Ключевое содержание:

  • В SAL добавлен реестр локальных семейств протоколов: ранее SAL требовал, чтобы поставщик протокола сокетов обязательно был привязан к сетевому устройству; эта модель неприменима к локальному IPC; теперь введён механизм локальных семейств протоколов, независимый от netdev, а поведение существующих сокетов сетевых устройств остаётся неизменным;
  • Поддержка узлов S_IFSOCK в DFSv2: tmpfs и devtmpfs могут содержать файловые узлы сокетов, что прокладывает путь для сокетов, привязанных к путям, таких как /dev/log;
  • Передача дескрипторов через SCM_RIGHTS: добавлен помощник подсчёта ссылок на файлы DFS, поддерживается передача файловых дескрипторов между процессами (вспомогательные данные sendmsg/recvmsg);
  • Расширение преобразования системных вызовов сокетов в LWP: добавлена поддержка преобразования sockaddr_un, musl msghdr, вспомогательных данных (ancillary data) и MSG_CTRUNC, что открывает путь для использования AF_UNIX пользовательскими процессами rt-smart;
  • Добавлен опциональный компонент components/net/af_unix: поддерживаются SOCK_DGRAM и SOCK_STREAM, bind/connect по имени пути, socketpair, блокирующий/неблокирующий ввод-вывод, тайм-ауты приёма-передачи, готовность poll/select, shutdown и обработка закрытия на противоположной стороне, передача дескрипторов SCM_RIGHTS;
  • Сопутствующее: опции Kconfig, интеграция со SCons, документация компонента (README), 7 групп тест-кейсов utest (common/ipc/namespace/node/poll/rights и др., около 1800 строк тестов).

Мотивация и значение: такие приложения, как BusyBox syslogd/logger, зависят от сокетов AF_UNIX, привязанных к именам путей (типичный пример — /dev/log). Ранее RT-Thread не мог предоставить их нативно и мог лишь эмулировать их через сетевой стек. После этого влития RT-Thread (включая rt-smart) получает канал локального межпроцессного взаимодействия, не зависящий от сетевой карты; это ещё один ключевой элемент инфраструктуры, добавленный в направлении «модель пользовательских процессов + стандартный POSIX IPC» — вслед за налаживанием кросс-компиляции ROS 2 для rt-smart 17 августа, и он имеет непосредственную ценность для многопроцессного взаимодействия и цепочки системного журналирования в сценариях робототехники и воплощённого интеллекта.

1.2 В wlan исправлен сбой команды wifi, происходивший молча (17 августа)

Дата: 2026-08-17 14:34 (пекинское время влития)　Источник: rt-thread PR #11696

Исправление, отправленное kaidegit: при выполнении команды wifi ap, когда режим устройства не привязан к AP, происходил прямой сбой без каких-либо сообщений об ошибке, что затрудняло диагностику пользователем; теперь добавлена проверка режима и при сбое выдаётся ясное сообщение в логе. Проверка выполнялась на плате hpm + esp hosted. Это небольшое исправление удобства использования; вместе с влитым днём ранее флагом режимов безопасности WLAN (WPA3/корпоративный/WAPI/OWE/DPP) уровень фреймворка WLAN в последнее время находится в фазе интенсивной доработки.

1.3 Статус версий без изменений

Дата: 2026-08-18　Источник: rt-thread releases

3. Экосистема и инструментальная цепочка

3.1 В инструментальной цепочке ENV появился опциональный онлайн-маркет плагинов (слияние в ночь на 18 августа)

Дата: 2026-08-18 00:17 (слияние по пекинскому времени)　Источник: RT-Thread/env PR #288

PR #288 «Add optional online plugin market» под руководством BernardXiong слит в инструментальную цепочку ENV (серверная часть командной строки RT-Thread Studio):

  • Возможности CLI: добавлены команды rt-env plugin market / market set / market clear, поддерживается переменная окружения ENV_PLUGIN_MARKET_URL для переопределения адреса маркета из файла конфигурации;
  • Интеграция с WebUI: после настройки маркета WebUI отображает онлайн-каталог плагинов; локальный Host API проксирует каталог, сведения и процесс prepare; после загрузки артефакта через одноразовый upload id он передаётся локальному установщику для завершения установки;
  • Безопасность и совместимость: при ненастроенном маркете поведение полностью совпадает с текущим — страница «онлайн-плагины» скрывается, соответствующие API возвращают 404; ENV не устанавливает напрямую по ID плагина или произвольному URL (после загрузки выполняется проверка, затем установка);
  • Качество: пройдено 29 модульных тестов (test_market / test_env_cli / test_webui_server).

Значение: впервые официальная инструментальная цепочка RT-Thread получила канал распространения плагинов. В сочетании с интерактивным скаффолдом epack (мастер epack init), слитым 14 августа, и документацией по жизненному циклу плагинов от 13 августа, ENV сформировала замкнутый цикл плагинов «разработка (epack) → публикация/получение (маркет плагинов) → установка (безопасная установка по одноразовому upload id)». Со стороны инструментальной цепочки слияния происходят пятый день подряд (14/8 мастер epack → 15/8 импорт пакета Buildroot → 16/8 параллелизм команд плагинов → 17/8 smart-build ROS 2 → 18/8 маркет плагинов) — темп экосистемной инфраструктуры остаётся плотным.

3.2 Поддержка ROS 2 в smart-build: в окне новых слияний нет

Дата: 2026-08-18　Источник: RT-Thread/smart-build

После вчерашнего слияния стека кросс-компиляции пакетов ROS 2 (PR #50, цель дымового тестирования транспортного слоя ament + CycloneDDS + QEMU aarch64) в окне мониторинга smart-build новых слияний нет — идёт период осмысления. В дальнейшем следует следить за сопутствующими изменениями procfs на стороне ядра и реальными кейсами устройств на ROS 2.

3.3 Экосистемный справочный контекст (не специальная динамика)

  • zlgopen/awtk: 17 августа — высокая частота коммитов (улучшения компонентов pointer cursor / edit), все являются общими улучшениями GUI, специальной связи с RT-Thread нет;
  • wdfk-prog/canopennode-rtt: пакет CANopenNode (личный репозиторий) обновлён 17 августа, слабый кандидат;
  • GD32-MCU-IOT/gd32_rt-thread: нижестоящий репозиторий GD32, плановая синхронизация 18 августа, неофициальный и незначительный.

4. Специальная глава о отраслевых применениях (робототехника / воплощённый интеллект / промышленность)

  1. Локальная IPC-инфраструктура дополнена, многопроцессная архитектура роботов выигрывает: AF_UNIX добавлен, что позволяет rt-smart user-space процессам взаимодействовать между собой без зависимости от сетевого стека; вместе с передачей дескрипторов через SCM_RIGHTS это может поддерживать классическую архитектуру декомпозиции в робототехнических системах «главный управляющий процесс + сервисные процессы датчиков/исполнительных устройств», а также перекликается с поддержкой кросс-компиляции ROS 2, добавленной днём ранее — разделение обязанностей, при котором DDS в ROS 2 использует сетевой домен, а локальный вспомогательный IPC использует AF_UNIX, становится возможным на RT-Thread.
  2. Конкурс AIoT завершён, AI-проекты — основная тема: опубликованы результаты конкурса 2026 RT-Thread AIoT, среди конкурсных работ преобладают AI-проекты, что отражает устойчивую тенденцию миграции разработчиков сообщества от «bare-metal/традиционных RTOS-приложений» к «end-side AI-приложениям»; полный список и подробности о призовых проектах ожидаются в официальном объявлении.
  3. Промышленная линия остаётся неизменной: до шанхайского «Ruìqíng Industrial Platform Workshop: EtherCAT — реальное управление в реальном времени и практические промышленные решения» 27 августа остаётся 9 дней, в окне мониторинга новых анонсов нет; заслуживает внимания синергия Ruìqíng Industrial Platform и рынка плагинов ENV (плагинная развёртка для сценариев промышленной автоматизации).

5. Итоги и наблюдения за тенденциями

  1. Сторона ядра: локальный IPC прошёл путь от «отсутствует» до «есть»: нативная реализация AF_UNIX (локальное семейство протоколов SAL + DFSv2 S_IFSOCK + SCM_RIGHTS) — крупнейшее техническое событие этого окна, знаменующее реальный шаг RT-Thread в сторону POSIX-совместимости и возможностей межпроцессного взаимодействия, напрямую стыкующийся с user-space направлением rt-smart.
  2. Сторона инструментальной цепочки: официальный канал распространения плагинов от 0 до 1: рынок онлайн-плагинов ENV добавлен, вместе с каркасом epack формируется замкнутый цикл разработка-распространение-установка; в будущем способ поставки экосистемы плагинов Studio может измениться.
  3. Задержка официального информационного канала сохраняется, верификация через СМИ вернулась к норме: официальный news API по-прежнему отстаёт примерно на 2 месяца, такие события, как результаты конкурса AIoT, можно найти только через сторонние СМИ; в этом окне Google News снова доступен через прокси (вчера — тайм-аут), полнота верификации через СМИ выше, чем вчера.
  4. Последовательные действия в направлении робототехники сохраняются: 8/17 кросс-компиляция ROS 2 → 8/18 локальный IPC AF_UNIX — за два дня два инфраструктурных добавления, напрямую связанных с робототехникой/многопроцессной архитектурой, главное направление официальной работы во втором полугодии становится всё яснее.
  5. Версионная картина стабильна: v5.2.2 без изменений, крупная функция ядра (AF_UNIX) сначала добавлена в master, ожидается выпуск со следующей версией.
