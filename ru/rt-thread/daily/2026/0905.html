1. Динамика ядра и версий

1.1 Официальный инструментарий Env включает механизм сохранения состояния (keep_alive) для WebUI-плагинов

Дата: 2026-09-05 (слияние 09-05 00:08 пекинское время)　Источник: RT-Thread/env PR #294 (коммит слияния)

Официальный вспомогательный инструмент разработки RT-Thread Env (репозиторий RT-Thread/env) принял PR #294 «Add opt-in state retention for plugin WebUI pages», представленный основателем BernardXiong (Сюн Пусян). Ключевое изменение: в manifest.webui плагинов добавлено необязательное поле keep_alive (по умолчанию false); при его включении iframe WebUI плагина остаётся смонтированным при переходе между страницей плагина, страницей настроек и центром плагинов, больше не перезагружаясь каждый раз (плагины без включённого поля сохраняют прежнее поведение перезагрузки); одновременно удалена верхняя панель WebUI, действие «Выйти из WebUI» перенесено в нижнюю часть боковой панели, статические ресурсы изолированы по плагинам, а для изолированных (sandboxed) страниц WebUI открыт необязательный серверный контекст HTTP/WebSocket. Данный PR продолжает серию переделок WebUI в ветке env с 09-02 (поддержание жизненного цикла iframe по плагинам, токены ресурсов плагинов и границы CSP, проверка поколений запросов doctor и т. д., ветка feature/ws); это слияние знаменует переход системы WebUI-плагинов Env от «перезагрузка при переключении» к «сохранение состояния страницы по требованию», что является итерацией опыта официального инструментария и единственным слиянием в рамках org за данное окно.

1.2 В основном репозитории за окно ноль слияний и ноль новых PR, период накопления продолжается; PR #11779 по рефакторингу CAN без нового прогресса

Дата: 2026-09-05　Источник: список репозиториев org:RT-Thread (интерфейсы commits / pulls)

Основной репозиторий rt-thread второй раз подряд за окно не имеет новых слитых коммитов (последнее слияние по-прежнему #11776 утром 09-03, включено вчера), в окне также не создано новых PR, release по-прежнему v5.2.2 (2025-10-31). Состояние очереди ревью совпадает со вчерашним: последний комментарий к PR #11779 по рефакторингу фреймворка CAN (wdfk-prog, 2 commits, +2902/-1308) — по-прежнему высказывание мейнтейнера CYFS3 от 09-03 17:47 (пекинское время) о том, что не рекомендуется отдельно поддерживать собственный фреймворк CAN_V2 и хотелось бы, чтобы разработчики совместно участвовали в продвижении слияния; в окне новых комментариев и коммитов нет; #11775 ([bsp][c908] rt-smart и поддержка MMU Sv39/48), #11772 (AddressSanitizer времени выполнения для heap), #11774 (исправление переполнения sal SIOCGIFCONF), #11689 (stm32 SPI BDMA) и другие остаются open без изменений. Со стороны ядра наступил обычный период накопления после слияний.

3. Экосистема и адаптация производителей

3.1 canopennode-rtt добавляет циклический синхронный режим CiA402 CSP/CSV/CST, набор режимов управления движением дополнен

Дата: 2026-09-05 (push в 11:08 по пекинскому времени)　Источник: wdfk-prog/canopennode-rtt

topic:rt-thread В окне ветки по умолчанию репозитория экосистемы canopennode-rtt появился новый коммит «feat: support CiA 402 CSP CSV and CST modes», добавляющий в CiA402 (профиль управления движением DS402) три циклических синхронных режима: циклическая синхронная позиция (CSP), циклическая синхронная скорость (CSV) и циклический синхронный момент (CST). В связке с включёнными 09-03/09-04 профилями многоосевых устройств и режимами позиционирования/скорости/возврата в ноль PP/PV/Homing поддержка DS402 расширяется от апериодических режимов к циклическим синхронным замкнутым режимам, функциональный набор управления движением дополнен. С учётом того, что этот же автор параллельно продвигает рефакторинг фреймворка Generic CAN в основном репозитории (#11779), сохраняется тенденция параллельного движения по двум линиям — «прикладной уровень (расширение CANopenNode) + уровень фреймворка (рефакторинг CAN)»; CAN/управление движением остаются наиболее активным направлением продвижения в сообществе.

3.2 Колонка EE Times China рассказывает о работе сообщества: дополнительный экран USB-мониторинга на FRDM-MCXN947

Дата: 2026-09-04 (17:30 по пекинскому времени)　Источник: EE Times China a522648 (оригинал на форуме RT-Thread)

Колонка «Обмен открытыми проектами» EE Times China 09-04 опубликовала материал о практическом проекте USB Monitor на базе отладочной платы NXP FRDM-MCXN947: с помощью операционной системы RT-Thread + графической библиотеки LVGL + стека протоколов CherryUSB реализован вывод состояния работы CPU, GPU и т. д. на стороне ПК в реальном времени на дополнительный экран. Эта работа происходит из проекта «Дополнительный экран мониторинга через единый USB-канал» конкурса «24 встраиваемых дизайна» на форуме RT-Thread и является типичным примером распространения работы сообщества через отраслевые медиа, а также демонстрирует готовность RT-Thread «из коробки» на новой платформе NXP (MCXN947, двухъядерный Cortex-M33) в связке с экосистемой LVGL/CherryUSB. Прямой доступ к основному тексту на сайте EET невозможен, ссылка сохранена для подтверждения.

3.3 Geehy «Geehy Xinde EP.87»: руководство по использованию периферийных драйверов APM32 в среде RTT-Studio

Дата: 2026-09-03 (11:30 по пекинскому времени; добавлено сегодня при повторной проверке окна в 3 дня, вчерашний zh-запрос не дал попадания)　Источник: EE Times China a522255

87-й выпуск серии «Geehy Xinde» сообщества разработчиков Geehy Semiconductor (опубликован EE Times China 09-03): руководство по использованию периферийных драйверов APM32 в среде RTT-Studio. В статье объясняется использование драйверов периферии adc, dac, hwtimer, uart и др. после создания проекта APM32 в RT-Thread Studio, а также отмечается, что периферийные драйверы RT-Thread для APM32 уже инкапсулируют внутри драйвера инициализацию выводов нижнего уровня и включение тактирования периферии, поэтому разработчики могут напрямую обращаться к ним через интерфейсы модели устройств. Это непрерывный выпуск обучающих материалов от производителя чипов для экосистемы RT-Thread (ранее в этой серии уже освещались темы переноса RT-Thread BSP для серии APM32, LwIP, LVGL, CherryUSB и др.), имеющий непосредственную справочную ценность для пользователей APM32 и тех, кто начинает работу со Studio.

3.4 Справочно по экосистеме: обновление проекта реверс-документации по внутренним механизмам RT-Thread для дрона H120D

Дата: 2026-09-05 (push в 07:31 по пекинскому времени)　Источник: H4ck3rTR/h120d-protocol

Проект сторонней документации по обратной разработке h120d-protocol (stars 4) получил обновление в окне мониторинга: систематизированы пакеты обратной разработки WiFi-протокола аэросъёмочного дрона Holy Stone H120D, описание внутренних механизмов RT-Thread и сопутствующие инструменты управления. Этот проект представляет собой работу независимого энтузиаста по документации обратной разработки (неофициальную), в которой внутренние механизмы RT-Thread (потоки/сообщения и т. д.) в прошивке потребительского дрона документированы вместе с проприетарным WiFi-протоколом; это имеет определённую справочную ценность для изучения реальных форм применения RT-Thread в потребительской электронике/дронах и включено как справочный материал по экосистеме.

4. Итоги и наблюдения за тенденциями

  • Сторона инструментальной цепочки: в официальный инструмент Env влит PR #294 — система плагинов WebUI вводит opt-in сохранение состояния (keep_alive), изоляцию ресурсов по плагинам и контекст песочницы; основатель BernardXiong влил изменения лично, итерации опыта официальных инструментов разработчика ускоряются.
  • Сторона ядра: основной репозиторий второй период подряд — ноль влитых изменений, ноль новых PR (последний #11776 от 09-03), рефакторинг фреймворка CAN #11779 не получил нового прогресса в ревью (после заявления CYFS3 09-03 ожидается ответ сообщества), период накопления продолжается; релиз по-прежнему v5.2.2.
  • Сторона экосистемы: canopennode-rtt за два дня продвинул CiA402 от многоосевого режима + PP/PV/Homing до полного покрытия циклической синхронизации CSP/CSV/CST, основная линия управления движением активна; на стороне китайскоязычного контента экосистемы EE Times China продолжает выпускать материалы, связанные с RT-Thread (мониторинг USB на вторичном экране FRDM-MCXN947) и учебные материалы от производителей чипов (JiHai EP.87).
  • Официальная сторона: официальный API новостей молчит 16-й день подряд, до elexcon 2026 (9/9-11, Шэньчжэнь) осталось 4 дня; предконференционное молчание соответствует ожидаемому ритму.
  • Тенденции за последние три дня (09-03 ~ 09-05): влит #11776 в основном репозитории, многоосевой CiA402 и PP/PV/Homing, в ревью рефакторинга CAN появились разногласия и получено заявление мейнтейнера «не создавать CAN_V2» (09-03) → продвижение переработки env WebUI, EET перепечатал работы сообщества, официальное молчание 15-й день (09-04) → влит env PR #294, реализован режим циклической синхронизации CiA402, официальное молчание 16-й день (09-05). Текущие основные линии продвижения — «итерации опыта WebUI официальной инструментальной цепочки + две линии экосистемы CAN/управления движением», официальная внешняя активность накапливает силы в молчании до elexcon.
