Еженедельный отчёт TileLang (2026-11-16 ~ 2026-11-20)

2026-11-20 Kubuds

Период отчёта: с 16 ноября 2026 года (понедельник) по 20 ноября (пятница), 5 рабочих дней, 5 выпусков ежедневного отчёта; дополнительно включает проверку 30 репозиториев организации tile-ai за 168 часов в день публикации (21 ноября)

Часть 1 · Краткий обзор

В этом разделе представлена выборка ключевых моментов недели, по умолчанию до 800 знаков (в этом выпуске 701 знак); полные пункты, постатейные перечни и источники см. в архиве второй части.

За пять выпусков ежедневного отчёта на этой неделе зафиксировано 141 слитый коммит и 467 новых issue. На TileOPs приходится 84 коммита, в основном репозитории всего 12, из которых четыре — исправления среды выполнения.

  • Инцидент безопасности: 15.11 в вышестоящем репозитории Ascend внешний PR внедрил скрипт в CI, токен контрибьютора был похищен; в четырёх репозиториях появились PR в том же стиле, все закрыты без слияния, раскрытие см. в issue #2016.
  • TileOPs становится основным фронтом: за пять выпусков слито 15, 18, 12, 23, 16 коммитов. После перевода manifest на декларативные параметры операторы pilot-модели реализуются день за днём, ошибочно слитый Embedding в тот же день откатили и на следующий день повторно слили.
  • Аудит превращается в конвейер: в выпуске 16.11 за 72 часа открыто 406 issue, два аккаунта дали 314; затем в четырёх выпусках — 19, 15, 20, 7, очередь на рассмотрение в какой-то момент выросла до 102 коммитов.
  • Ascend внедряется по семействам: DSA и KDA по три комплекта каждый слиты в один день, catlass обновлён до v2.2.0 и устранён тихий NaN в fp32 GEMM; 17.11 дополнительно проведён аудит dtype примерно по 300 комбинациям.
  • Производительность уходит в правила селектора: одно правило #3045 покрывает 302 формы, 286 ускоряются в 1,03–2,6 раза; два долга — TopKSelect и MLA cache — закрыты в тот же день.
  • Расширение платформы: TileFoundry в тот же день выпустил цель Metal и автоматическое дифференцирование, оба остановились на уровне IR; отдельно проведён рефакторинг терминологии и раскладки на 303 файла.
  • RISC-V продвигается попеременно: на маршруте TVM открыта ветка hikari с пятью коммитами, на маршруте MLIR слиты перевод buddy-opt в режим по умолчанию и два примера; с 18.11 наступило молчание на три выпуска.

Суждение недели: основной фронт уже второе окно подряд лежит в библиотеке операторов, узкое место сместилось с объёма разработки на пропускную способность ревью; вставка барьеров при автоматической warp specialization становится риском первого уровня, а v0.1.15 стоит уже 51 день, и все изменения остаются за пределами следующего тега.

Часть 2 · Архив

Ниже приведён полный текст недели, структура и методология совпадают с предыдущими еженедельными отчётами; для каждого суждения из краткого обзора здесь можно найти постатейное обоснование и источники.

Источники материалов: 5 выпусков ежедневной хроники сообщества TileLang (16.11, 17.11, 18.11, 19.11, 20.11). Выпуск 16.11 охватывает 72-часовое окно через выходные (с 13.11 07:00 до 16.11 07:00). Остальные четыре выпуска идут подряд по 24 часа. Таким образом, фактический интервал поведения пяти выпусков — с 13.11 07:00 до 20.11 07:00. Предыдущий еженедельный отчёт завершился на 13.11 07:00, начало текущего с ним стыкуется. В день публикации дополнительно проведена проверка организации tile-ai за 168 часов (30 репозиториев, в окне было 12 пушей). Эта проверка используется только для подтверждения пушей и состояния версий и не изменяет факты, уже зафиксированные в ежедневных отчётах.

Пояснение к составлению: материал организован по семи измерениям: главные новости недели, прогресс ключевых проектов, адаптация множественных бэкендов, экосистема и стороны внедрения, обучающие материалы и мероприятия сообщества, наблюдения за тенденциями, приложение. Число слитых, находящихся на рассмотрении и новых issue взято из истинных значений поиска GitHub в каждом выпуске ежедневного отчёта (is:merged, is:open, created) и перекрёстно сверено с коммитами в основную ветку по каждому репозиторию. За пять выпусков слито последовательно 30, 30, 20, 38, 23 коммита, всего 141. Новых issue последовательно 406, 19, 15, 20, 7, всего 467. Слияния в неосновные ветки отмечаются постатейно с указанием ветки и не смешиваются с основными. Затронутые неосновные ветки: hygon distributed, mlir-ascend mlir-dialect и harness. Отдельно — TileOPs stats и nightly snapshots.

1. Главные новости недели

  • CI восходящего репозитория Ascend подвергся злоупотреблению, учётные данные контрибьютора украдены (произошло 11-15, раскрыто 11-16): Контрибьютор liggest открыл issue #2016 в tilelang-ascend. С 7 утра 11-15 аккаунт miramar-labs отправил PR #2014. Этот PR добавил скрипт, собирающий информацию о сервере во время выполнения CI. CI этого репозитория работает на собственных серверах. После компрометации атакующий получил большое количество информации и учётных данных для входа. Среди них — GitHub token liggest. С 9:39 до 11:40 утра 11-15 атакующий использовал этот token, выдавая себя за liggest. Он опубликовал 18 комментариев подряд под #2014. Он также открыл два PR со скриптами майнинга в TileOPs (#2902, #2903). Кроме того, он открыл аналогичный PR #5086 в SemiAnalysisAI/InferenceX. Автор утверждает, что два скрипта майнинга не были выполнены из-за автоматических проверок GitHub. Поиск показывает, что miramar-labs открыл PR в том же стиле в четырёх репозиториях. Четыре случая — это tilelang #4148, tilelang-ascend #2014, tilelang-mlir-ascend #251, TileOPs #2900. Номинально все они были оформлены как «прогрев кэша» или «зондирование возможностей CI». Все четыре закрыты, ни один не был смёржен. После закрытия issue автор добавил комментарий. Он заявил, что предыдущее описание «тоже выглядит преувеличенным», и что аккаунт восстановлен. Масштаб ущерба по-прежнему основан на самоотчёте автора, третья сторона ещё не проверила. Автор предлагает, чтобы PR новых контрибьюторов требовали одобрения мейнтейнера перед запуском CI, использующего собственные серверы. Источники: https://github.com/tile-ai/tilelang-ascend/issues/2016、https://github.com/tile-ai/tilelang-ascend/pull/2014、https://github.com/tile-ai/TileOPs/pull/2902

  • TileOPs стал главным полем битвы недели: за пять периодов смёржено 84 коммита — шесть десятых от 141 за всю неделю: За пять периодов смёржено соответственно 15, 18, 12, 23 и 16 коммитов. 11-18 за один день — 23 коммита, с 10:17 до 21:50 по пекинскому времени. Это самый плотный день квартала. 11-16 за один день — 18 коммитов, направление — выравнивание интерфейсов pilot-моделей. Основную линию пяти периодов можно свести к трём. Первая — дополнение возможностей описания параметров manifest. Вторая — поэтапная реализация операторов, реально вызываемых pilot-моделями. Третья — закрытие по issue задолженностей по производительности квантизации и внимания. В основном репозитории за ту же неделю смёржено только 12 коммитов. Из них четыре — исправления ошибок времени выполнения, два — изменения версий и документации. Источники: https://github.com/tile-ai/TileOPs/pulls

  • Интерфейс прежде реализации: manifest обновлён до декларативных типов параметров, затем поэтапная реализация по операторам: #2958 от 11-16 переписал выразительные возможности manifest. Он расширился от «описания только фиксированных тензоров и скаляров» до трёх видов сигнатур: последовательность тензоров, скаляр или тензор на выбор, обязательный, но допускающий None. Входные данные во время вызова унифицированно изменены на объявления с type и default. В том же окне #2967 дополнил истинные значения интерфейсов pilot-моделей. Pilot-модели означают Qwen3.6, DeepSeek-V4-Flash и GLM-5.3-Flash. Он зарегистрировал семь операторов как spec-only и добавил фактические параметры пятнадцати уже реализованным операторам. Последующая реализация продвигалась по дням. 11-17 смёржены gated RMSNorm (#2984) и MaskedScatter (#2982). Ошибочный контракт Embedding в тот же день откатили (#2983). 11-18 повторно предложены и смёржены Embedding (#2992), Concat (#2987) и RoPE с задаваемыми вызывающей стороной cos/sin (#2988). 11-19 добавлены attention sink (#3038, #3048), групповая квантизация FP4 (#3027) и хеш-маршрутизация MoE (#3036). Каждое предложение сопровождается эталонной реализацией и строками бенчмарков. Большинство самооценок по-прежнему «ниже порога приёмки». Это показывает, что порог смёрживания и порог производительности — две разные вещи. Источники: https://github.com/tile-ai/TileOPs/pull/2958、https://github.com/tile-ai/TileOPs/pull/2967、https://github.com/tile-ai/TileOPs/pull/2992

  • Аудит issue превратился из «выявления проблем» в «конвейерное производство проблем»: в выпуске от 11-16 за 72 часа было открыто 406 новых issue. Один аккаунт cn-sys вечером 11-15 за 1 час 46 минут подряд открыл 172 issue. Номера идут непрерывно от #4208 до #4381, ни одна не содержит примесей из других источников. ilovexsir за три дня тремя партиями открыл 142 issue. Вместе у них 314 issue — семьдесят семь процентов от общего объёма. Партия ilovexsir напрямую соответствует пяти batch-исправлениям в PR. Пять PR — это #4201–#4205, открытые в одну и ту же минуту. После этого в четырёх последующих выпусках было открыто 19, 15, 20 и 7 новых issue соответственно. Масштаб снизился, но не прекратился. 11-17 снова появился систематический аудит покрытия dtype. Участник JeffDing в течение минуты подряд отправил 4 issue, а через полчаса добавил пятое (#4391–#4395). Вывод: унарные и бинарные операторы T.simd вообще не проверяют dtype перед передачей во внутренние вызовы компилятора. Из 225 комбинаций (оператор, dtype) 70 пропускаются без проверки. Семейство кросс-lane редукций также лишено белого списка — из 63 комбинаций 27 пропускаются. Источники: https://github.com/tile-ai/tilelang/issues/4381, https://github.com/tile-ai/tilelang/pull/4201, https://github.com/tile-ai/tilelang/issues/4391

  • Ascend переходит от «дополнения операторов» к «пакетной реализации по семействам моделей»: 11-13 за один день в tilelang-ascend было слито девять коммитов. Трио разреженного внимания DSA реализовано в тот же день. Прямопроходная конвейерная версия объединяет DQK в один GEMM 512+64=576. Обратный проход сократил 79395 микросекунд до 27388 микросекунд. Редукция вероятностной массы topk дополнена двумя потоками. Трио KDA реализовано в тот же день, рекуррентность состояния полностью остаётся в UB. catlass обновлён с v1.0.0-6 до v2.2.0. Это обновление попутно исправило дефект, который до этого был полностью безмолвным. В старой версии CopyL1ToL0A/L0B не было float-специализации, и fp32 GEMM выдавал NaN или отрицательную бесконечность без ошибки. Четыре в одном bitwise исправления устранили выход за границы хвостовых байтов в упаковке uint8 PTO. В контролируемом тесте сигнальное значение 0xA5 было затоптано до 0x03. Источники: https://github.com/tile-ai/tilelang-ascend/pull/1870, https://github.com/tile-ai/tilelang-ascend/pull/1989, https://github.com/tile-ai/tilelang-ascend/pull/2000

  • Оптимизация производительности переходит от «подстройки под каждую форму» к «правилам селектора», два задолженных вопроса закрыты в тот же день: 11-19 в #3045 в селектор GEMM было внесено одно правило. Для GEMM класса NT, если сетка из 128 строк при ширине coop2 укладывается в одну волну, выбирается самый узкий tile coop2. Это правило влияет на 302 формы моделей. На одной карте H200 ни один случай не оказался медленнее основной ветки. 286 форм ускорились в 1,03–2,6 раза. Маршрутизационный prefill GLM-5.3-Flash сократился с 82,24 микросекунд до 32,13 микросекунд. В том же окне #3023 переписал TopKSelect. Три строки decode из отставания от vLLM примерно в 2 раза превратились в опережение в 1,22–1,34 раза. #3022 заставил копировать кэш MLA построчно 16-байтовыми векторами. Это устранило непосредственную причину отставания decode DeepSeek-V4-Flash от vLLM. 11-16 есть ещё одна заслуживающая внимания причинно-следственная цепочка. #2896 заменил 128-строчный тайл W4A16 на написанный вручную warp-specialized основной цикл. Примерно через 46 часов #2901 исправлял вызванное этим зависание. Причина в том, что барьер был вставлен компилятором в условную ветку, до которой другая warpgroup никогда не доходит. Источники: https://github.com/tile-ai/TileOPs/pull/3045, https://github.com/tile-ai/TileOPs/pull/3023, https://github.com/tile-ai/TileOPs/pull/2901

  • TileFoundry в тот же день реализовал цель Metal и автоматическое дифференцирование, границы платформы расширились до обучения и Apple GPU: 18.11 внесены два изменения платформенного уровня. #354 добавляет metal.Target("apple.m2_pro.gpu"). Топология — от threadgroup к thread. Девять инструкционных операторов покрывают классы матричных операций, редукций и операций с переупорядочиванием. Сопоставление lane в MSL записано в спецификацию автором после измерений на M2 Pro. #355 добавляет differentiate(module, wrt, recompute). Он возвращает два модуля: <Name>Forward и <Name>Backward. Правила обратного распространения записаны по операторам в отдельных файлах и покрывают все классы операторов встроенной модели Qwen. Ни одно из двух изменений не создаёт исполняемых ядер. Metal доведён только до TIR, автоматическое дифференцирование только генерирует модули HIR. На той же неделе #349 изменил 303 файла за один раз. Этот коммит добавил 10312 строк и удалил 9243 строки, сведя терминологию и алгоритмы компоновки к единой спецификации. Источники: https://github.com/tile-ai/TileFoundry/pull/354, https://github.com/tile-ai/TileFoundry/pull/355, https://github.com/tile-ai/TileFoundry/pull/349

  • Четыре источника RISC-V на этой неделе: две ветки продвинулись по одному разу каждая, остальные три дня тишина: в ходе обхода 16.11 в kubuds/tilelang-riscv-kubuds (путь TVM) открыта новая ветка kubuds-riscv-hikari. В эту ветку внесено пять коммитов, включая отчёт о портировании и верификации K3, разблокировку сборки rv64gc, разбиение сетки на 4 тайла для декодирования и 8 тайлов для префилла, а также прослеживание публичных спецификаций XSMTVDotII/vmadot. В тот же день страница индекса сообщества получила первый PR с момента создания (#1). Этот PR вносит kubuds fork в таблицу «Проекты сообщества». 17.11 в RuyiAI-Stack/tilelang-riscv (путь переписывания на MLIR) влит PR #6. Этот коммит по умолчанию включает buddy-opt и добавляет два примера: FP16 GEMM на стороне host и BOSC INT8 GEMM. 18.11, 19.11 и 20.11 во всех четырёх источниках не было ни коммитов, ни новых PR. Источники: https://github.com/kubuds/tilelang-riscv-kubuds, https://github.com/TongmingLAIC/tilelang-riscv/pull/1, https://github.com/RuyiAI-Stack/tilelang-riscv/pull/6

2. Прогресс ключевых проектов (основной репозиторий tilelang)

Версии и релизы

  • Последний тег основного репозитория по-прежнему v0.1.15 (выпущен 30.09). Ни в пяти ежедневных отчётах, ни при проверке в день релиза новых тегов не обнаружено. К пятнице этой недели эта версия не обновлялась 51 день.
  • Другие репозитории организации на этой неделе также без новых версий. TileOPs — v0.1.0 (27.10). TileFoundry — v0.0.4rc1 (25.10). tilelang-mlir-ascend — v0.1.2.020 (11.06).
  • Единственный новый релиз пришёл от независимого дистрибутива. tilelang-sunrise 18.11 влил #11, версия поднята до 0.1.15+sunrise.1.2.1. Предыдущая версия — 0.1.15+sunrise.1.2.0.
  • На стороне MetaX готовится v0.1.12+musa.5. Ветка release/v0.1.12-musa.5-source существует. #13 предназначен для публикации исходного кода и документации MUSA, на этой неделе не влит.
  • На этой неделе была одна чистка схемы нумерации версий. #4409 удаляет суффиксы бэкендов и переключатель NO_TOOLCHAIN_VERSION. Один и тот же чекаут во всех конфигурациях единообразно сообщает 0.1.15+gitabcdef12. Причина в том, что начиная с #1826 один wheel одновременно обслуживает несколько версий инструментальной цепочки CUDA. Старые суффиксы создавали у читателя впечатление, что wheel поддерживает только одну версию.

Среда выполнения и пути исполнения

  • Восстановление состояния устройства (#3872, влито 11-16): stub хоста tvm_ffi только устанавливает текущее устройство, но не восстанавливает его. При вызове тензора cuda:1 на cuda:0 результат корректен, но текущее устройство остаётся cuda:1. Последующие выделения с device="cuda" будут молча дрейфовать. Исправление — обернуть вызов на уровне адаптера в torch.cuda.device(...) и восстановить состояние по завершении.
  • Однопараметрическое ядро NVRTC (#3880, влито 11-16): имена и типы параметров соединяются через ", ". При одном параметре результат не является кортежем, и cuLaunchKernelEx напрямую бросает TypeError. Достаточно заменить на литерал кортежа с завершающей запятой.
  • Динамическая разделяемая память в cython (#3882, влито 11-16): лимит динамической разделяемой памяти изначально задавался только в init() один раз. Этот атрибут задаётся поустройственно. Ядра, которым нужно более 48 KB, на остальных устройствах будут выдавать cudaErrorInvalidValue. Исправление — генерировать вспомогательную функцию _set_dynamic_smem() для каждого ядра и запоминать устройства, на которых лимит уже повышен.
  • Повторное использование runtime ROCm HIP (#3899, влито 11-16): ROCm wheel от PyTorch загружает libamdhip64 с RTLD_LOCAL, и stub не может его найти. Исправление — сначала проверить уже отображённый runtime через RTLD_NOLOAD. Это позволяет избежать загрузки второй копии через dlopen и последующего несовпадения дескриптора модуля между runtime, из-за которого первый запуск ядра завершается ошибкой.
  • Чтение беззнаковых буферов (#3875, влито 11-17): на цели CuTeDSL значения, прочитанные из буферов uint8, uint16, uint32, трактуются как знаковые. Корневая причина — MLIR не имеет бита беззнаковости для целых, а генерация кода для каждого обращения к глобальной и разделяемой памяти исходит из типа итератора. Автор провёл проверку на 256 значениях uint8 на RTX PRO 6000. Пять вариантов записи в основной ветке ошибаются каждое на 128 значениях. Исправление — заставить tl.make_tensor принимать dtype= и повторно привязывать тип к представлению.
  • Сохранение привязки переменных-заполнителей компоновки при сериализации (#4410, влито 11-20): tl.Layout, tl.Fragment, tl.PartialFragment выражают индексы и отображение потоков через внутрипроцессные синглтон-заполнители tirx::Var. Критерием служит тождество объекта, а не name_hint. После кругового преобразования компоновки через pickle или tvm.ir.save_json заполнители пересоздаются. В результате map_forward_index([7]) возвращает [_i], а OutputShape() вычисляет (32,) как (_i + 1,). При понижении аннотированного PrimFunc в воркере, запущенном через spawn, происходит ошибка «forward map must be injective». Исправление — включить ссылки на привязанные переменные-заполнители в тот же канал ObjectGraphSerializer.
  • Повторная подача RFC для бэкенда CUDA Tile IR (#4402, #4403, 11-19): цель — генерировать CUDA Tile IR из программ TileLang и передавать его в tileiras для компиляции и планирования. Компоновка, конвейеризация, специализация по warp и выбор инструкций определяются tileiras. Бэкенд преобразует только ту семантику, которую CUDA Tile IR способен корректно выразить. Всё, что преобразовать нельзя, приводит к ошибке компиляции и отказу от программы, без стремления к полной совместимости с существующим бэкендом CUDA. Эта версия — переработка более ранней #3247. В ходе ревью отмечалось, что старая реализация содержала слишком много try-catch и была написана примерно на 18,5 тыс. строк Python в виде pass.

В этом выпуске фиксируется как «сообщено, ожидает обработки».
  • На рассмотрении исправление: пропуск повышения TMA при несовместимой раскладке при warp-специализации (#4413, 11-19): на b1367a59 конвейерный GEMM для sm_90a не понижается. Условие срабатывания — его 8-битный B tile использует swizzled-раскладку с заполнением. Загрузка A делает этот цикл подходящим для warp-специализации. Затем проход повышает обычное копирование B до TMA, а LowerBulk отклоняет раскладку с заполнением. Исправление — проверка аннотаций целевой раскладки для каждого кандидата на загрузку TMA.
  • Цепочка исправлений зависания (#2896 → #2899 → #2901, 11-15): после вливания #2896 gpu-smoke на main завис. sliced_pair сохраняет out_shared при условии i // wg_rows == bz. После понижения раскладки только consumer warpgroup, сохраняющий эту половину тайла, выполняет цикл сохранения. TileLang иногда вставляет барьер, защищающий эту запись, внутрь этой ветки. Этот барьер охватывает все 256 потребительских потоков. Другой warpgroup никогда до него не доходит. Обе группы останавливаются на разных экземплярах одного барьера. Хуже того, положение барьера нестабильно между двумя компиляциями с одним и тем же cache key. Постоянный кэш ядер в CI воспроизводит плохую сборку бесконечно. Исправление — вынести сохранение из условия, оба consumer warpgroup пишут свою половину.

6. Наблюдения за трендами

Во-первых, основной фронт уже сместился с самого компилятора к библиотеке операторов и планировщику, и это смещение подтверждается два окна подряд. Из 141 влитого коммита на этой неделе TileOPs занимает 84, а основной репозиторий — только 12. Из этих 12 в основном репозитории четыре — исправления ошибок рантайма, два — версии и документация. На прошлой неделе картина была похожей. Работа в основном репозитории сосредоточена на исправлении регрессий, а новые возможности всё больше появляются в виде тайлов, селекторов и моделей стоимости в библиотеке операторов. Основание для вывода — не только число влитых коммитов, но и направление зависимостей. Выводы о производительности TileOPs должны ссылаться на roofline и планирование TileFoundry, а основной репозиторий на этой неделе не дал им ничего нового.

Во-вторых, аудит уже поставлен на конвейер, и узкое место сместилось с «обнаружения» на «ревью». В выпуске 11-16 за 72 часа открыто 406 issue, два аккаунта внесли 314. 172 записи от cn-sys написаны за 1 час 46 минут. 142 записи от ilovexsir напрямую соответствуют пяти batch-исправлениям PR. Этот режим действительно сжимает цикл «от обнаружения дефекта до исправления»: issue и PR существуют в один и тот же день. Но он переносит давление на сторону ревью. В выпуске 11-16 на рассмотрении 102 коммита, влито 30. Из них 22 изоморфных PR mlir-ascend могут пройти только у очень немногих людей. Узким местом следующего этапа будет пропускная способность ревью, а не скорость обнаружения.

В-третьих, граница безопасности стала единственным неизбежным негативным событием этой недели, и она обнажила структурную проблему. Собственный CI был пронзён внешним PR, персональный токен украден. В четырёх репозиториях одновременно появились PR в одном стиле. Это показывает, что настройка по умолчанию «PR нового контрибьютора напрямую запускает CI на собственных серверах» является общим риском на уровне организации. Действия автора: отзыв старых разрешений, сохранение вредоносного форка для криминалистики, проведение мер безопасности для собственного CI-сервера. Предлагаемое исправление: PR новых контрибьюторов должны запускать CI только после одобрения мейнтейнера. Это правило одинаково применимо ко всему сообществу RISC-V и AI-компиляции. Граница доверия для собственных runner’ов должна по умолчанию ужесточаться, а не оцениваться отдельно для каждого репозитория.

В-четвёртых, корректность автоматической warp specialization стала риском первого класса. Цепочка #2896 – #2901 демонстрирует одну вещь. Когда изменение производительности перекладывает ответственность за синхронизацию на автоматическую инструментацию компилятора, место инструментации становится частью корректности. И оно непрозрачно для верхнего уровня. При двух компиляциях с одним и тем же cache key барьер может оказаться внутри ветки или вне её. В сочетании с персистентным кэшем ядра в CI случайная плохая инструментация закрепляется как стабильный сбой. Структурного решения этой проблемы пока нет — только локальные обходы вроде «вынести операции записи из условных веток». Если в дальнейшем больше тайлов пойдёт по пути ping-pong, зависания того же типа, скорее всего, повторятся.

В-пятых, границы платформы расширяются наружу, но всё останавливается на уровне IR. В один день появились цель Metal и автоматическое дифференцирование — компилятор протянулся от инференс-ядер к обучению и Apple GPU. Оба не порождают исполняемых ядер. Порядок ясен: сначала интерфейс, затем бэкенд и рантайм. На той же неделе TileFoundry с помощью 303 файлов свёл терминологию и алгоритмы компоновки к единой спецификации. Это эквивалентно переходу промежуточного представления от «вырастания из реализации» к «сначала определение, потом реализация». Подобные изменения краткосрочно увеличивают стоимость ревью, но в долгосрочной перспективе определяют, смогут ли внешние бэкенды корректно реализовать IR.

В-шестых, долгое отсутствие релизов — общая проблема выхода для всех достижений этой недели. v0.1.15 застрял на 09-30, к этой пятнице прошёл 51 день. Исправления рантайма в основном репозитории, изменения исполнительного бэкенда для Ascend, доработка операторов в TileOPs — всё это не раньше следующего тега попадёт в нижележащие дистрибутивные пакеты. Для сравнения, независимые дистрибутивы уже движутся вперёд. Sunrise выпускает 0.1.15+sunrise.1.2.1, MetaX готовит v0.1.12+musa.5, Hygon следует с объединёнными исправлениями. Три компании выпускают версии каждая самостоятельно, и выравнивание версий и матрица совместимости станут новой статьёй затрат на поддержку.

В-седьмых, четыре источника RISC-V на этой неделе продвинулись по одной ветке каждый, и ритм по-прежнему прерывистый. Маршрут TVM открыл новую ветку hikari с проверкой портирования K3 и данными RVV-сетки. Маршрут MLIR вмёржил buddy-opt по умолчанию и два примера. Индексная страница сообщества впервые включила форк со стороны TVM. Но с 11-18 все три выпуска молчат. Разделение труда между двумя маршрутами уже определилось. Маршрут TVM занимается «чтобы запускалось, с реальными данными». Маршрут MLIR остановился на «есть дизайн, есть примеры». За этой линией стоит следить по окнам, но не стоит считать прогресс понедельно.

Пояснения к проверке

  1. Данный выпуск охватывает пять рабочих дней с 16 по 20 ноября 2026 года и пять выпусков ежедневного отчёта. Выпуск от 11-16 охватывает окно в 72 часа через выходные (с 11-13 07:00 по 11-16 07:00), остальные четыре — последовательные 24-часовые окна. Таким образом, фактический интервал поведения — с 11-13 07:00 по 11-20 07:00.
  2. Количество слитых, находящихся на рассмотрении и новых issue взяты из зафиксированных в каждом ежедневном отчёте фактических результатов поиска GitHub (is:merged, is:open, created) и перекрёстно сверены с коммитами в основную ветку по каждому репозиторию. За пять выпусков слито 30, 30, 20, 38 и 23 коммита, всего 141. Распределение по репозиториям: TileOPs 84, основной репозиторий 12, TileFoundry 11, MLIR Ascend 8, topa 8, репозиторий Ascend 9, Hygon 3, Sunrise 1. Остальное — коммиты сайта документации, ветки harness и ночных снимков.
  3. Слияния в неосновные ветки отмечены в тексте по каждому коммиту. Слияния в mlir-ascend попадают в ветку mlir-dialect, её main не менялся с 11-04. Ещё 1 коммит попадает в harness. В TileOPs stats и TileOPs-nightly snapshots есть по нескольку коммитов. В main этих репозиториев за соответствующие окна ноль или мало коммитов, их видно только при проверке по веткам.
  4. Показатели производительности взяты из таблиц и строк Result: в текстах соответствующих PR без повторного пересчёта. Случаи недостижения целевой планки (below bar) и самозаявленной «ниже линии приёмки» сохранены как в оригинале, без приукрашивания.
  5. Границы инцидента безопасности основаны главным образом на изложении автора. После закрытия issue автор дополнил, что описание «выглядит также и преувеличенным». Настоящий отчёт фиксирует как это дополнение, так и часть, проверяемую со стороны поиска. Проверяемая часть — все однотипные PR в четырёх репозиториях закрыты, ни один не слит. Сам изложенное содержание не принимается за вывод третьей стороны.
  6. По новостной части во всех пяти выпусках ноль попаданий, внешних публикаций для перекрёстной проверки прогресса проекта за эту неделю нет. Попадания в Hacker News и arXiv — это шум от одноимённых или общих слов, они исключены.
  7. Ограничения со стороны сбора: в нескольких окнах этой недели лимит анонимного API GitHub был исчерпан в конце окна. Информация о ветках и тегах была перепроверена через Atom-подписки и git ls-remote, выводы не затронуты. Количество файлов и строк в отдельных PR — это возвращённые интерфейсом значения, diff построчно не перепроверялся.
  8. Настоящий отчёт не содержит никаких локальных путей, адресов прокси или внутренней сетевой информации. Все ссылки — общедоступные адреса.
