1. Основные достижения проекта

1.1 Пакет исправлений основного репозитория: скалярная разрядность T.view, повторное использование входов Autotuner, зависание autodd, гейтирование тестов LDGSTG — четыре объединения (10-09)

Дата: 2026-10-09　Источник: скалярная разрядность T.view (#3382)／ повторное использование входов Autotuner (#3415)／ исправление зависания autodd (#3385)／ гейтирование тестов LDGSTG (#3463)

  • Скалярная разрядность T.view (#3382, объединён в 17:38): bits_product при пустой форме напрямую возвращает 1, пропуская разрядность dtype и число каналов, из-за чего скалярный T.view принимает представления с несовпадающей разрядностью и ошибочно отклоняет скалярные/тензорные представления с равной разрядностью (дефект #3378); после исправления добавлена регрессия на стороне CPU (несовпадение разрядности, векторные каналы, переинтерпретация одинаковой ширины, ранг скаляра/тензора).
  • Повторное использование входов Autotuner (#3415, объединён в 15:33): при cache_input_tensors=True прямое сравнение dtype TVM и dtype PyTorch неизбежно даёт несовпадение (дефект #3412), совместимые входы повторно генерируются при каждом вызове и маскируется отсутствующая проверка ранга; заменено на существующее преобразование torch_dtype(), сначала отклоняется несовпадение ранга, затем сравниваются размерности.
  • Зависание autodd (#3385, объединён в 15:34): python -m tilelang.autodd --jobs 0 никогда не возвращается, поскольку не порождает рабочие потоки; теперь неположительные значения напрямую отклоняются.
  • Гейтирование тестов LDGSTG (#3463, объединён в 13:15): добавленный в #3390 тест вложенных предикатов на ROCm CI вызывает зарегистрированный только для CUDA проход LowerLDGSTG и выдаёт ошибку; добавлен гейт requires_cuda — выявлено упавшей задачей ROCm, исправлено в тот же день.

1.2 Основной репозиторий: объединено ревью маршрутизации интентов CodeRabbit — управление ревью переходит в инструментальную цепочку (10-09)

Дата: 2026-10-09　Источник: маршрутизация ревью CodeRabbit (#3456)

  • Список распределения ревьюеров поддерживается непосредственно в .coderabbit.yaml (используется нативная директива «предлагаемые ревьюеры», больше не создаётся отдельный файл списка или рабочий процесс распространения): по одному правилу на каждого ревьюера, разделённому на четыре секции «основная зона ответственности / рекомендуемый триггер / не рекомендуемый триггер / подсказки по путям», сопоставление по интенту изменений, а не по именам файлов или ключевым словам, с явным исключением самого автора PR (8 файлов).
  • Для сравнения: открытых PR в основном репозитории 177 (в предыдущий период 174) — управление пропускной способностью ревью начинает переходить от «добавления людей» к «правилам маршрутизации».

1.3 Новый пакет основного репозитория: десять коммитов с #3460 по #3469 — исправление пути PTO, двойное копирование A5, пример FlashMLA в списке (10-09)

Дата: 2026-10-09　Источники: Возврат помощника полного приведения PTODSL (#3469) / Преобразование пути двойного копирования A5 (#3468) / Пример ручного планирования FlashMLA (#3464) / Подъём барьера TMA store (#3462)

  • Возврат помощника PTODSL (#3469): в upstream PTOAS удалён ptodsl/_allreduce.py с расчётом на то, что downstream выполнит vendor самостоятельно; однако tilelang/contrib/ptodsl/simt.py по-прежнему ссылается на удалённый модуль, из-за чего компиляция любого оператора цели PTO на базе последнего CANN Weekly (09-30) выдаёт ModuleNotFoundError. Данный коммит переносит реализацию в contrib/ptodsl/allreduce.py и добавляет тесты примитивов приведения PTO — новый пример того, как изменения upstream-зависимостей напрямую затрагивают путь PTO основного репозитория.
  • Двойное копирование A5 (#3467 закрыт, переоткрыт как #3468): FixPipe на A5 не может одновременно включить двойное назначение и quant_pre, при этом преобразование L0C fp32 в UB f16/bf16 в T.dual_copy ранее требовало дополнительного vcvt; данный коммит переходит к «преобразованию по пути», избавляясь от дополнительного Vector-преобразования.
  • Прочие новые: требование к документации CANN 9.2.0 (#3460), очистка временных файлов обёртки bisheng (#3461), порядок выполнения барьера прокси TMA store (#3462), пример ручного планирования Ascend FlashMLA (#3464), диагностика ранга атомарной области CUDA (#3465), исправление понижения скалярного rsqrt для Ascend (#3466) — связанные с Ascend составляют четыре из них.

5. Наблюдения за тенденциями

5.1 От «очистки накопленного» к «заморозке прироста»: инженерные ограждения вступают в фазу принудительного действия

  • TileOPs превращает «встроенные строки исходного кода CUDA» из миграционного проекта в правило заморозки (после обнуления накопленного новые добавления отклоняются); линейное внимание переименовано без сохранения псевдонимов; на стороне основного репозитория CodeRabbit маршрутизирует намерения и регламентирует распределение рецензентов; CI для Ascend закреплён на самостоятельно собранном образе CANN 9.3. Общая черта инженерных действий по качеству: все они переводят разовую очистку в долгосрочное ограничение — период рефакторинга завершён, начинается период поддержания.

5.2 Два конца очереди: 177 открытых PR и 1030/1945 с нулевыми сбоями

  • Открытые PR: 177 в основном репозитории (+3 к предыдущему периоду), 225 в репозитории адаптации для Ascend — пропускная способность рецензирования по-прежнему остаётся переменной, влияющей на темп; на другом конце ночной конвейер из 1030 проверок корректности плюс 1945 бенчмарков (52 набора) непрерывно работает с нулевыми сбоями, обеспечивая регрессионную базу для большого объёма ожидающей проверки очереди. Из 29 новых открытых за окно 10 были слиты в тот же день (в основном TileOPs); «быстрый вход и быстрый выход» и «длинный хвост очереди» сосуществуют.

5.3 Продолжение «синхронного удара по трём направлениям» Ascend и расширение поверхности поддержки PTO

  • Функциональность (пример Expert, двойное копирование A5, rsqrt), инфраструктура (проверка образа CANN 9.3), путь компиляции (отчёт MLIR и argmax) — в один день расцвели в нескольких точках; а #3469 указывает на новую переменную: изменения интерфейса вышестоящего PTOAS напрямую прерывают компиляцию цели PTO в основном репозитории — второй путь PTO вступает в фазу задачи «управление вышестоящими зависимостями». На момент сдачи материала (утро 10-10) связанные с Ascend коммиты всё ещё обновлялись (#3466, #3468, #3469, а также #3321, #1657 и другие).
