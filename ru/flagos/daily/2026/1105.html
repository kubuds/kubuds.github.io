3.2 Horizon Robotics: библиотека операторов BPU доведена до рабочего состояния, цепное выполнение сокращает четыре диспетчеризации до 0,673 мс (11-04)

Дата: 2026-11-04　Источники: Torch-FL PR #721 · Torch-FL PR #726

  • Три серьёзных отказа: #721 выясняет, что eager-путь BPU на самом деле выполняет каждый оператор на CPU — ступень корзин операторов никогда не превышает 512 lane, артефакт с двумя входами отправляется с дескриптором одного тензора, что приводит к молчаливому неверному значению, а hbdk4 под box64 не может импортировать numpy, из-за чего x86-инструментарий недоступен. После исправления Run экспортируется через C ABI, чтобы eager-путь обходил aten dispatcher, а фиксированная работа каждого вызова выводится из горячего пути.
  • Измеренные данные: на RDK S600 relu с 262144 lane сокращается с 0,176 мс до 0,073 мс, один conv block — с 23,2 мс до 11,1 мс.
  • Цепное выполнение: #726 добавляет DeviceChain, который последовательно запускает на устройстве несколько артефактов BPU; промежуточные активации не возвращаются на хост, а проходят через память только на входе первого и выходе последнего, передаваясь через небольшой кольцевой буфер устройства. На S600 сериализованный elementwise сокращается с 0,417 мс до 0,104 мс, четыре независимые диспетчеризации — с 1,667 мс до 0,673 мс.
  • Оценка: узким местом линии Horizon Robotics является не вычислительная мощность, а фиксированные накладные расходы. Драйвер тратит 0,09 мс на каждый вызов — для одного оператора это немного, но для модели с десятками операторов на слой это основная стоимость; сохранение промежуточных активаций на устройстве сжимает эти расходы с «одного раза на оператор» до «одного раза на сегмент».

3.3 Hygon: реализован прямой проход FP32 flash attention, открыто ещё девять задач по оптимизации FP32 (11-04)

Дата: 2026-11-04　Источники: FlagGems PR #7388 · FlagGems PR #8404 · FlagGems PR #8451 · FlagGems-vllm PR #1066 · build-infra PR #1628

  • FP32 прямой проход: #7388 добавляет в реализацию _flash_attention_forward для Hygon явно поддерживаемый путь FP32, сохраняя при этом пяти-выходную схему ATen и существующее поведение FP16/BF16. Область поддержки описана очень узко: фиксированная длина, непрерывный 4D BSHD, квадратная MHA с одинаковой формой Q/K/V, head dim 64 или 128, dropout 0, без window/alibi/seqused/varlen. Неподдерживаемые комбинации сразу возвращают ошибку, а не идут по непроверенному пути.
  • Ключевые моменты реализации: для QK и PV используются скалярные произведения IEEE FP32; максимум в онлайн softmax инициализируется значением -inf, чтобы не поглощались допустимые logit ниже -1e30; для длинных последовательностей используются exp2/log2, для коротких сохраняется натуральная экспонента; выбираются три набора статических tile по head dim и длине последовательности; низкоточный путь изолирован от него на этапе компиляции.
  • Оптимизация на той же стороне: девять открытых одиночных PR от luojung охватывают rsqrt, floor, nonzero, полномерное сокращение FP32, masked_fill, nan_to_num, neg, masked_select, aminmax, все ограничены «непрерывным FP32». Это типичный порядок, при котором сначала доводят до правильного состояния один путь, а затем говорят о производительности.
  • Версии и плагины: base и runtime DTK 26.10 сегодня отмечены как 2.3.0 (см. 1.2); FlagGems-vllm #1066 исправляет импорт Hygon при отсутствии встроенного CUDA PDL; FlagBLAS исправляет collection для Hygon; mixed_gemm в FlagTrain покрывает Hygon.
