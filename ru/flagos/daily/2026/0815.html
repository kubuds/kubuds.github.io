Ежедневный отчёт FlagOS (2026-08-15)

1. Прогресс открытых проектов (динамика GitHub)

Обзор окна: из 52 репозиториев в организации 15 имели push в окне, поиск по коммитам дал 76 коммитов в окне (по дате коммиттера), официальных GitHub Release нет, но конфигурация build-infra уже продвинула номер версии до 2.1.2 — это первый сигнал запуска версионного цикла примерно через 7 недель после FlagOS 2.1 (синхронный выпуск шести компонентов 2026-06-24). Три основных направления в этом окне: запуск цикла релиза FlagOS 2.1.2 (полностью отлажен конвейер megatron wheel в build-infra), тройной прорыв в распределённых коммуникациях Torch-FL (Enflame GCU / Moore Threads MUSA / Ascend FSDP2), одновременное расширение чиповых бэкендов трёх базовых библиотек FlagFFT / FlagBLAS / FlagDNN (Moore Threads / Hygon / Ascend).

1.1 build-infra: запуск цикла релиза FlagOS 2.1.2, полная отладка конвейера megatron wheel (главная новость окна)

Источник: build-infra configs.yaml, build-infra commits

  • Продвижение номера версии: в configs.yaml version: "2.1.2", flaggems: "5.3.4" (ранее цикл 2.1.1 / 5.3.x); в тот же день #390/#398/#400 — три коммита “refresh image descriptions for 2.1.2”, автоматически обновляющие документацию описаний образов base/runtime через flagos-ci (8/15 17:57 ~ 8/16 00:52). Цикл релиза 2.1.2 официально запущен, wheel каждого компонента и теги образов единообразно привязаны к новому номеру версии.
  • Рефакторинг сборки megatron wheel (#375): отказ от прежней схемы “образ инструментальной цепочки сборщика + repack”, переход к сборке megatron wheel непосредственно внутри vendor runtime-образа (build env == delivery env), установка одним шагом одновременно проверяется при сборке; каталог repack/ удалён.
  • Замкнутый цикл верификации megatron (#379/#383): добавлен verify-megatron-backend.sh — поэлементное сравнение матриц torch/triton/flag_gems/numpy до и после установки wheel (обязательное побайтовое совпадение), проверка импорта megatron.core + привязки helpers_cpp pybind; #383 подключил шаги верификации к workflow app-image, при неудаче верификации gate блокирует push образа. Успешно протестировано на узле hygon25 (torch 2.9.0+das.opt1.dtk2604 / flag_gems 5.3.4 / megatron-core 0.17.1).
  • Отслеживаемость версий (#393): версия wheel переведена на отслеживание уровня коммита 0.17.1+fl.<дата>.g<sha> (например, 0.17.1+fl.20260814.gba22f6b673f3), в семантике PEP 440 фиксация ==0.17.1 не затрагивается, а сортировка по дате позволяет сравнивать старые и новые версии.
  • Усиление образа Hygon (#399): в runtime-образ hygon добавлен flash-attn (отметим, что ранее в матрице верификации megatron для hygon triton был MISSING; добавление flash-attn — сигнал совершенствования стека инференса на стороне Hygon).
  • Инженерные исправления: массовое исправление отсутствующего unzip (#382, 11 базовых образов), исправление label раннера MetaX (#384), тайм-аут клонирования github.com + HTTP_PROXY только для шага clone (#378), обход NO_PROXY для эндпоинтов aliyun/flagos/baai во избежание сбоя туннеля (#395), откат передачи gendoc TSV на upload-artifact (#388).

1.2 Torch-FL: тройной прорыв в распределённых коммуникациях (Enflame GCU / Moore Threads MUSA / Ascend FSDP2)

Источники: Torch-FL PR #103, PR #105, PR #106

  • #103 Enflame GCU: распределённый запуск через FlagCX (14.08 23:34): Ранее в ProcessGroupFlagOS не было строки для Enflame, и происходил fall through к конфигурации nvidia по умолчанию (flagcx_dev=”cuda” / no NCCL), из-за чего init_process_group на GCU вообще не работал. В этот раз добавлен профиль enflame, закреплён upstream-адаптер FlagCX для enflame (devName=”gcu”), а также добавлен _gcu_device_guard (GCU stream/указатель имеют область действия устройства, и коллективные операнды на других устройствах молча становятся no-op); 19 маршрутизационных тестов пройдено, покрыты collectives/DDP/FSDP2. Внимание: среды с аппаратным обеспечением GCU нет, live-скрипты не запускались вживую, требуется проверка на двух картах (примечание автора коммита).
  • #105 Moore Threads MUSA: распределённая коллективная коммуникация (15.08 00:30): Добавлена C++-привязка _flagos_identity_view (возвращает tensor как есть), позволяющая MUSA-адаптеру FlagCX напрямую использовать privateuseone tensor (FlagCX musa_adaptor.cc берёт data_ptr() без проверки типа устройства, преобразование storage не требуется, что обходит устаревший в torch UnsafeStorageView); MCCL (torch_musa ProcessGroupMCCL) служит нативным запасным вариантом. В комплекте 5 тестовых файлов объёмом около 650 строк: 6 базовых collective, DDP (3-слойный MLP), FSDP2, Qwen3-0.6B end-to-end DDP (синхронизация градиентов в масштабе, соответствующем продакшену). Модульные тесты пройдены 17/17.
  • #106 Ascend FSDP2: нативная семантика ACL stream/event (15.08 00:30, наибольший объём работ в этом окне): Ранее уровень stream/event для Ascend был лишь совместим по именам (query всегда False, wait/record деградировали до host-синхронизации, GuardImpl для всех stream возвращал ID 0), тогда как fully_shard из FSDP2 требует независимых compute/comm stream + явного порядка событий. В этот раз реализовано: общий реестр ACL stream (C++ thread-local + кэшированный GetDevice для избежания syscall на горячем пути), обёртки Python AclStream/AclEvent (ctypes + кэш dlopen), добавлены три необходимых для FSDP2 оператора split_with_sizes_copy.out / _chunk_cat.out / _foreach_copy_ (в CANN нет aclnnForeachCopy, разложен на поэлементный copy_ через aclnnInplaceCopy для устранения переходов на CPU). Протестировано на двух картах 910 с CANN 9.0: stream smoke, FlagCX collectives, DDP (loss 0.061/0.119), FSDP2 (4 grads/rank, loss 0.044/0.064) — всё пройдено.

1.3 FlagFFT: подключён бэкенд Moore Threads MUSA/muFFT (#14)

Источники: FlagFFT PR #14

  • Бэкенд MUSA (разработка 14.08 в 20:29, слияние в 23:06): FlagFFT через MUSA driver API адаптирован для GPU Moore Threads, muFFT используется как эталонный FFT oracle; опция CMake BACKEND поддерживает CUDA/MUSA, libtriton_jit конфигурируется с тем же значением; в src/adaptor/backend/musa/ полностью реализованы Memory/Stream/EventTimer/CudaGraph/device-запросы, device_architecture возвращает MUSA capability (например, 31), triton_target формирует musa:{arch}:32.
  • Специализация TLE codegen: бэкенд MTGPU LLVM (FlagTree mthreads 3.6) терпит неудачу при распределении регистров для трёх режимов — vectorized 3D transpose v2, thread-local mixed four-step, TLE fused twiddle, — и откатывается к стандартному kernel.
  • Практические испытания MTT S5000 (arch 31): все тесты точности 1D/2D/3D пройдены против muFFT. Это первый чиповый бэкенд FlagFFT за пределами NVIDIA; библиотека Fourier закрывает пазл «Moore Threads».

1.4 FlagBLAS: массовое слияние операторов Level-2 BLAS, мультибэкенд Ascend/Hygon (#29)

Источники: FlagBLAS PR #29, commits

  • PR #29 (слияние 14.08 в 23:09): добавлены операторы Level-2 BLAS и их модульные/точностные тесты, с поддержкой мультибэкенда Ascend / Hygon; сопутствующие #34 (файлы тестов, 15.08 в 00:44), #40 (исправление benchmark logger + Level-2 benchmark shapes, 15.08 в 22:02), #41 (очистка L1 benchmark, рефакторинг swap benchmark, 15.08 в 23:20) — операторы Level-2 и инфраструктура бенчмарков внедрены синхронно, FlagBLAS расширяется с L1 к L2.

1.5 FlagDNN: слияние бэкенда Hygon

Источники: FlagDNN commit

  • add hygon backend (14.08 в 19:04): библиотека операторов глубокого обучения FlagDNN получила новый бэкенд Hygon DCU. Таким образом, в данном окне мониторинга три базовые библиотеки — FlagFFT (Moore Threads), FlagBLAS (Hygon + Ascend), FlagDNN (Hygon) — синхронно расширили бэкенды, что вместе со вчерашним развёртыванием 8 бэкендов FlagAttention образует череду действий по «всесторонней мультичиповости базовых библиотек».

1.6 FlagCX: поддержка устройств Ascend NPU + конвейер модульных тестов MetaX

Источники: FlagCX commits

  • #536 Поддержка устройств Ascend NPU на уровне UIL (15.08 в 20:41): в FlagCX Ascend communicator добавлена поддержка NPU device (уровень UIL), что вместе с поддержкой #525 sunrise-sw-1.2.0 (14.08 в 19:09) продвигает линию адаптации устройств;
  • #532 Конфигурируемый конвейер модульных тестов MetaX (14.08 в 22:07): в CI добавлен workflow модульных тестов MetaX (конфигурируемый реестр платформ, среда RDMA, тесты P2P/RMA), FlagCX на стороне MetaX переходит от «сборка проходит» к «покрытию модульными тестами».

4. Итоги

  1. Запуск цикла релиза FlagOS 2.1.2: configs.yaml version продвинут до 2.1.2, flaggems 5.3.4; build-infra завершил фабрикацию megatron wheel (сборка внутри runtime-образа + проверка двух образов + прослеживаемость версии на уровне коммита), hygon25 прошёл фактическое тестирование, инфраструктура релиза готова.
  2. Три прорыва в распределённой коммуникации Torch-FL: #103 Enflame GCU распределённо через FlagCX (исправлена прежняя невозможность формирования группы), #105 MUSA коллективная коммуникация (identity view + резерв MCCL + тест Qwen3-0.6B DDP), #106 Ascend FSDP2 нативные ACL stream/event (фактический тест на двух картах 910).
  3. Массовое расширение бэкендов базовых библиотек: FlagFFT Moore Threads MUSA (фактический тест на MTT S5000), FlagBLAS Level-2 + Ascend/Hygon, FlagDNN бэкенд Hygon — вместе со вчерашними 8 бэкендами FlagAttention образуют главную тему «мультичиповости базовых библиотек».
  4. Расширение на стороне операторов: FlagGems sparse_sampled_addmm развёрнут сразу на шести бэкендах, начат autotune AMD RDNA4, FlagGems-vllm per-token-quant fp8 охватывает Muxi/Hygon/Moore Threads.
  5. Новостная сторона спокойна: по ключевым словам компонентов ноль совпадений, только одна запись экосистемного фона — регистрация на открытый конкурс Zhiyuan GOAI; HN — сплошной шум. Все основные динамики пришли из GitHub.
  6. Релизная сторона: официального GitHub Release нет; 2.1.2 находится на стадии «продвижение конфигурации + обновление документации образов», до официального релиза компонентов ещё далеко (с момента FlagOS 2.1 прошло более 7 недель).

Пояснение ограничений: коммиты Torch-FL #103 (GCU) и #105 (MUSA) содержат пометку «без фактического тестирования на оборудовании, требуется проверка на двух картах», только #106 Ascend имеет запись фактического теста на физических 910; переходные ссылки gnews не позволяют получить основной текст, детали новостей опираются на заголовки и перекрёстное подтверждение из нескольких источников.
