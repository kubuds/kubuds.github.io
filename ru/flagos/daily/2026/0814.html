Ежедневный отчёт FlagOS (2026-08-14)

2026-08-14 Kubuds

Окно мониторинга: последние 24 часа (2026-08-13 10:19 ~ 2026-08-14 10:19 пекинское время) Источники: GitHub (org: flagos-ai), агрегация Google News (китайский и английский), HN, сообщество Zhiyuan и др. (подробности в приложении)

1. Прогресс открытых проектов (динамика GitHub)

Обзор окна: из 52 репозиториев в org 16 имели push в окне, поиск по коммитам дал 46 попаданий коммитов в окне, официальных релизов нет (прошло более 7 недель с FlagOS 2.1). Три основные линии этого окна: реализация многобэкендовой runtime-архитектуры FlagAttention (развёртывание сразу 8 чиповых бэкендов), завершение переименования и интеграции PyTorch-Plugin-FL на уровне org под именем Torch-FL, FlagGems продолжает высокую частоту (19 коммитов, параллельное продвижение операторов NVIDIA в KernelGen и операторов Ascend/Tianshu Zhixin в KMCompiler).

1.1 FlagAttention: реализация многобэкендового runtime, 8 чиповых бэкендов развёрнуты за один раз

Источник: FlagAttention PR #48, FlagAttention commits

  • “add multi backends” (#48, смёржен 13 августа 12:18): добавлена унифицированная абстракция бэкендов src/flag_attn/runtime/backend/, сразу созданы 8 пакетов бэкендов — _ascend (Ascend), _enflame (Enflame), _hygon (Hygon), _iluvatar (Iluvatar CoreX), _metax и _mthreads (две линейки MetaX), _nvidia. FlagAttention превращается из библиотеки Triton-операторов attention с единственным бэкендом NVIDIA в библиотеку attention-операторов FlagOS для всех чипов, выравниваясь с многобэкендовой моделью FlagGems. Это самое важное архитектурное событие данного окна, список бэкендов почти взаимно однозначно соответствует чипам организаций-участников FlagOS.
  • Сопутствующие коммиты: три коммита “add multi backends / add copy right / fix” от 08-13 02:55-04:07 (UTC) — это процессные коммиты разработки #48.

1.2 Torch-FL: переименование и интеграция на уровне org (PyTorch-Plugin-FL → Torch-FL)

Источник: .github commits, Torch-FL commits

  • Официальный README org (английский + китайский) полностью заменил PyTorch-Plugin-FL на Torch-FL (замена 13 августа 18:44/18:45, исправление ссылок 21:25): PyTorch-Plugin-FL официально вошёл в основную линию org под именем Torch-FL (CI badge в README репозитория Torch-FL всё ещё указывает на старое имя репозитория, что говорит о том, что миграция ещё продолжается). Torch-FL позиционируется как PyTorch-плагин устройств FlagOS, предоставляющий унифицированное устройство flagos, с маршрутизацией операторов к переиспользуемым нативным kernel, компиляторным kernel, нативным реализациям производителей и явному CPU fallback.
  • Исправление #99 (14:54): сохранение module parameters в режиме неглобального swap;
  • docs #101 (14:56): добавлен отчёт об измеренной поддержке операторов (measured operator support report).

1.3 FlagGems: 19 коммитов, две линии KernelGen NVIDIA + KMCompiler Ascend/Tianshu Zhixin

Источник: FlagGems commits

  • KernelGen NVIDIA операторы, новые добавления (13 августа 13:06-14:22): max_pool3d_with_indices_backward (#5264), ormqr (#5252), heaviside (#5120), leaky_relu_backward (#5145), _scaled_dot_product_attention_math (#5168), _native_batch_norm_legit_no_training (#5243); кроме того, три оператора hardswish (#5139), absolute_ (#5187), arctanh (#4818) официально переведены из зоны генерации “Move to ops” в реестр — завершающее действие по включению сгенерированных операторов KernelGen в официальный список сопровождения;
  • Операторы KMCompiler (14 августа 10:19-10:22): добавлены linalg_cross (#4850), linalg_solve_triangular (#5201); бэкенд pairwise_distance для Ascend + исправление ошибки ссылок Iluvatar CPU компании Tianshu Zhixin (#5394) — продвижение двух бэкендов Ascend и Tianshu Zhixin в одном коммите;
  • Официализация зависимости flagtree: #5444 Bump flagtree version for NVIDIA (15:26); #5433 обновление ascend backends.yaml flagtree ascend whl до 0.6.1 (17:13) — вчерашняя оценка “система распространения FlagTree wheel” подтвердилась: FlagTree wheel (включая ascend 0.6.1) стал официальным компонентом зависимости для конфигураций всех бэкендов FlagGems;
  • Исправления и инженерия: обработка пустых нулевых элементов (empty) (#5438), исправление точности nested_view_from_buffer_copy (#5324), разделение и регистрация xor/ixor (#5283), исправление пути и dtype cat cpp wrapper + точность rwkv_mm_sparsity (#5388); ядро fused_marlin_moe переименовано согласно схеме точности и разделены бенчмарки (#5437, 10:28).

1.4 FlagGems-vllm: бэкенд mthreads для MetaX MC550 входит в Fused MoE

Источники: FlagGems-vllm #100

  • [KMCompiler] Fused moe: add mthreads backend and tune metax MC550 (#100, 13 августа 16:35): в ядро Fused MoE добавлен бэкенд mthreads (MetaX) и выполнена настройка под MC550 — MetaX продолжает продвижение на стороне операторов в сценариях vLLM (образует трёхлинейную связку компиляция-операторы-распространение вместе со вчерашней унификацией специализации FlagTree METAX и упаковкой MACA wheel);
  • Стабильная линия v0.1.1-rc: #618 удаление отладочных логов (18:23), #679 skip некоторых тестов (19:32).

2. Новости и экосистема

2.1 Alibaba открыла исходный код Qwen3.8-2.4T-A95B, сообщество FlagOS синхронно завершило адаптацию под несколько чипов (главная новость окна мониторинга)

Дата: 2026-08-13 (пекинское время 17:29)　Источники: Sina Finance (gnews)

Sina Finance сообщает, что Alibaba открыла исходный код нового флагманского MoE-модели Qwen3.8-2.4T-A95B (общее число параметров 2.4T, активных 95B), сообщество Zhiyuan FlagOS синхронно завершило адаптацию под несколько чипов. В тот же день (13 августа 21:25) появилось ещё одно сообщение: Qwen3.8-2.4T запущена на платформе Национальной суперкомпьютерной интернет-сети (caiwennews). Проверка: по состоянию на момент отчёта в окне мониторинга коммитов в GitHub org явных коммитов адаптации qwen3.8 пока не видно (поиск по коммитам находит только исторические записи, связанные с qwen3), работа по адаптации, возможно, находится на стадии подготовки зеркал/релиза; данный пункт включён по медийной формулировке. Это событие соответствует ритму «открытие модели + быстрая мультичиповая адаптация FlagOS», как в предыдущем случае Day0-адаптации DeepSeek-V4 под восемь чипов.

2.2 Отчёт за первое полугодие 2026 года Hygon Information (участник-организация): выручка 9,099 млрд юаней, +66,52%, чистая прибыль, приходящаяся на акционеров материнской компании, 1,798 млрд юаней, +49,69%

Дата: 2026-08-13 (начиная с 18:45 по пекинскому времени, несколько источников)　Источники: East Money, Sina Finance

Hygon Information (688041) опубликовала полугодовой отчёт за 2026 год: выручка 9,099 млрд юаней, рост на 66,52% год к году; чистая прибыль, относимая к акционерам материнской компании, 1,798 млрд юаней, рост на 49,69%. Спрос на отечественные высокопроизводительные чипы продолжает расти под влиянием AI-вычислений; несколько брокерских компаний сохранили или впервые присвоили рейтинг «покупать» (Huaxing Securities подтвердила рейтинг «покупать» по стратегии «CPU + DCU с двойным драйвером», 13 августа, 15:39). СМИ также обратили внимание на спор вокруг отрицательного операционного денежного потока и «стратегических запасов» с остатками на конец периода свыше 12,3 млрд юаней (Sina Finance, 14 августа, 09:07). В тот же день сообщение о «крупном централизованном государственном заказе на шесть отечественных CPU» показало, что Hygon возглавил список с 2059 единицами (Sina Finance, 14 августа, 07:26). Как член FlagOS (Hygon DCU), Hygon демонстрирует одновременное улучшение операционных показателей и экосистемной адаптации (в FlagAttention добавлен бэкенд hygon, см. 1.1).

2.3 Iluvatar CoreX (член организации) прогнозирует выход из убытков в первом полугодии

Дата: 2026-08-13 (17:38 по пекинскому времени)　Источники: Guandian, East Money

Iluvatar CoreX (09903.HK) опубликовала прогноз результатов: ожидается выход из убытков в первом полугодии 2026 года, чистая прибыль составит примерно от 60 млн до 140 млн юаней (в том числе доход от справедливой стоимости до примерно 790 млн юаней). В тот же день в FlagGems был принят фикс ошибки ссылки на CPU Iluvatar (#5394, см. 1.3) — техническая адаптация и операционные показатели продвигаются синхронно.

2.4 Moore Threads: интенсивный поток аналитики после выхода на гонконгскую биржу

Дата: 2026-08-13 ~ 08-14　Источники: Sina Finance, CSDN

После старта IPO акций класса H 12 августа последовал плотный поток аналитических публикаций: Sina Finance опубликовала материал «Moore Threads: момент, когда отечественный GPU наиболее близок к тому, чтобы “перейти снежные горы”» (14 августа, 07:52), CSDN — «Мультипликатор цена/выручка 180x! Moore Threads выходит на гонконгскую биржу» (09:09), China Post Securities впервые присвоила рейтинг «покупать» (13 августа, 17:54). Рынок сосредоточен на уровне оценки и конкурентной структуре отечественных GPU. На технической стороне конвейер тренировочных образов Moore Threads S5000 вчера был реализован в FlagScale (см. вчерашний отчёт, 1.1).

2.5 Общая оценка новостной повестки

Google News не дал ни одного прямого попадания по ключевым словам компонентов FlagGems/FlagScale/FlagTree/FlagPerf/FlagCX/KernelGen; новости в этом окне в основном касаются экосистемы открытых моделей (мультичиповая адаптация Qwen3.8) и операционной динамики членов организации (полугодовой отчёт Hygon, выход Iluvatar из убытков, продолжение IPO Moore Threads); на HN нет записей, связанных с FlagOS (компилятор C3 и симулятор CPU CoreTrace не связаны с FlagOS, исключены). Попадания по китайскому запросу “Zhiyuan Academy открытый исходный код” по-прежнему состоят в основном из букмекерского/SEO-шума, вся партия исключена.

Оценка тренда: крупнейший сигнал этого окна — единовременное развёртывание FlagAttention сразу для 8 бэкендов (ascend/enflame/hygon/iluvatar/metax/mthreads/nvidia) — библиотека операторов attention стала третьим компонентом после библиотеки операторов FlagGems и коммуникационной библиотеки FlagCX с “полным покрытием чипов”, причём список бэкендов тесно соответствует карте чипов членов организации, что доказывает: мультичиповая адаптация FlagOS переходит от “почипового подключения” к архитектурной фазе “унифицированной абстракции runtime”. Другой сигнал — переименование и интеграция Torch-FL: бренд слоя плагинов PyTorch унифицирован в единую абстракцию “flagos device”, объединён с wheel FlagTree (FlagPrism выделен независимо), а рефакторинг packaging build-infra вместе образуют предрелизную уборку “компонентизация + унификация бренда”. В операционном плане Hygon и Iluvatar демонстрируют улучшение результатов, база членов организации стабильна.

4. Резюме

  1. Внедрение многобэкендного runtime FlagAttention: в #48 за один раз добавлены пакеты для 8 аппаратных бэкендов (Ascend/Enflame/Hygon/Iluvatar/MetaX×2/NVIDIA), библиотека операторов attention стала полностью кроссплатформенной по чипам — это ключевой шаг в многоплатформенной архитектуре FlagOS.
  2. Официальное переименование и интеграция Torch-FL: в README организации PyTorch-Plugin-FL полностью заменён на Torch-FL, единая абстракция устройства “flagos device” стала единой точкой входа на уровне плагина PyTorch.
  3. FlagGems: две линии в высоком темпе: KernelGen — добавлено 6 новых операторов для NVIDIA и 3 внесены в реестр; KMCompiler — 3 оператора подряд для Ascend/Iluvatar; flagtree wheel (bump для NVIDIA + Ascend 0.6.1) стал официальной зависимостью для всех бэкендов — вчерашний прогноз о “системе распространения wheel” подтвердился.
  4. MetaX MC550: углубление продолжается: FlagGems-vllm Fused MoE добавил бэкенд mthreads и провёл оптимизацию под MC550; компиляция (специализация FlagTree METAX), распространение (MACA wheel), операторы (сценарий vLLM) — все три линии идут параллельно.
  5. Главная новость: открытый исходный код Qwen3.8-2.4T-A95B + многоплатформенная адаптация сообщества FlagOS (по данным Sina Finance), что продолжает ритм экосистемы FlagOS — “открытие модели означает быструю многоплатформенную адаптацию”; среди членов-организаций выделяются промежуточный отчёт Hygon и выход Iluvatar на операционную прибыль.
  6. Сторона релизов: официальных Release нет; рефакторинг build-infra packaging + стабильная линия FlagGems-vllm v0.1.1-rc, компонентные релизы всё ещё в стадии подготовки (с момента FlagOS 2.1 прошло более 7 недель).
