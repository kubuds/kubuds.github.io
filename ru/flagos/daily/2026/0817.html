Ежедневный отчёт FlagOS (2026-08-17)

2026-08-17 Kubuds

Окно мониторинга: 2026-08-16 10:18 ~ 2026-08-17 10:25 пекинское время Источники: GitHub (org: flagos-ai), агрегатор Google News (китайский и английский), HN, сообщество Zhiyuan и др. (подробности в приложении)

1. Прогресс открытых проектов (динамика GitHub)

Обзор окна: из 52 репозиториев в org 8 имели пуши в окне; поиск по коммитам выявил 26 коммитов в ветке по умолчанию в пределах окна (FlagBLAS 18, build-infra 7, FlagPrism 1), кроме того, были влиты два PR — Megatron-LM-FL #100 и FlagTree #969, официальных GitHub Release нет. Три основные линии этого окна: масштабное расширение набора бенчмарков FlagBLAS (полное покрытие Level-1/2/3, Hygon hipBLAS как явная цель адаптации), инженерная работа над образом Hygon в build-infra и проверка четырёх сценариев hygon25, добавление поддержки CI Kunlunxin P800 в Megatron-LM-FL (сигнал новой линейки чипов).

1.1 FlagBLAS: масштабное расширение набора бенчмарков BLAS, развёртывание бэкенда Hygon hipBLAS (10 PR / 18 коммитов)

Источник: FlagBLAS pulls

  • Бенчмарки Level-1 (влиты 8/16 10:38-13:46): вращение Гивенса rot (#46), общее обновление ранга-1 ger (#56), обновление ранга-1 (#50), обновление ранга-2 (#51).
  • Бенчмарки Level-2 (влиты 8/16 10:40-21:28): решение с треугольной матрицей trsv, упакованная эрмитова матрица-вектор hpmv (#52), разреженная упакованная spmv, эрмитова ленточная hbmv, треугольная матрица (#45, включая версию с Hygon hipBLAS #49), ленточная матрица (#47, Hygon hipBLAS), симметричная/эрмитова (#48, Hygon hipBLAS).
  • Бенчмарки Level-3: trmm — умножение треугольной матрицы на матрицу (#57, влит 8/16 23:41).
  • Сопутствующий core_shapes.yaml синхронно регистрирует основные формы каждого бенчмарка (несколько коммитов 8/16 16:40-21:55).

Комментарий: покрытие бенчмарков FlagBLAS разворачивается от скалярных/векторных операций Level-1 до матричного умножения Level-3, при этом три семейства Level-2 — треугольные, ленточные и симметричные/эрмитовы — все явно добавляют бэкенд Hygon/hipBLAS — Hygon является наиболее концентрированной целевой платформой адаптации бенчмарков в этом окне, что образует замкнутый цикл с работой над линейкой Hygon в build-infra.

1.2 build-infra: инженерия образа Hygon + проверка линейки megatron (7 коммитов, PR #403-#409)

Источник: build-infra pulls

  • #403 Добавление LLVM DTK в base-образ Hygon (16.08 11:18): добавлен пакет DTK LLVM, от которого зависит vendor triton, исправлено отсутствие цепочки компиляторов в образе.
  • #404 Hygon triton 3.3.0 → 3.5.1 (16.08 11:24): обновление версии Triton на стороне Hygon.
  • #405/#406 Автоматическое обновление описаний образов 2.1.2 (16.08 11:48/12:55): данные о версиях 17 бэкендов уровня base полностью прошли проверку; на уровне runtime 1 бэкенд не прошёл проверку (штатное автоматическое обновление).
  • #407 Патч sysconfig времени сборки megatron wheel (16.08 18:25): compile_helpers() изначально зависел от python3-config (артефакт сборки CPython, отсутствует в uv venv), заменён на stdlib sysconfig.get_config_var("EXT_SUFFIX"); трёхсостояточный идемпотентный патч-скрипт служит временным fallback до мержа #112 в Megatron-LM-FL, итоговая форма кода у обоих совпадает.
  • #408 Запись проверки четырёх сценариев hygon25 на Hygon (16.08 18:27): на основе полного megatron-core wheel (MLF #107) зафиксированы результаты четырёх сценариев training / rl / post_training / inference — rl заблокирован из-за платформенного gap (в megatron/rl/inference/megatron.py:87 жёстко зашит ассерт динамического инференс-движка flash-attn ≥ 2.7.3), tensorboard является необъявленной runtime-зависимостью, информация о версии vendor flash_attn перепутана (__version__ зафиксирован на 2.6.1, фактически 2.8.3+); исправление маски компилятора: flagtree 3.6.0 признан доступным на новом образе (прежний вывод blocked получен из старого контейнера без пакета DTK LLVM).
  • #409 env-фреймворк уровня app + gate vllm flashinfer (16.08 20:03): vLLM 0.24.0 на CUDA безусловно импортирует flashinfer (переключатель семплера по умолчанию включён), через новое третье измерение configs.yaml env.app.<app> инжектится VLLM_USE_FLASHINFER_SAMPLER=0; одновременно исправлена ловушка подтягивания torch в vllm версии по умолчанию 0.20.2 — голая установка vllm==0.20.2 одним шагом разрешает из индекса образа к последнему torch (2.11.0+cu130), перекрывающему runtime-матрицу, версия по умолчанию изменена на 0.24.0 с принудительным pin +flagos, при фактической установке torch больше не скачивается.

1.3 Megatron-LM-FL: KunlunXin P800 входит в CI (PR #100)

Источник: Megatron-LM-FL PR #100

  • Поддержка платформы KunlunXin P800 (мерж 17.08 09:48, AlexMa616): добавлена конфигурация платформы KunlunXin и отдельный CI workflow, 8 устройств XPU прогоняют полную матрицу юнит-тестов (узел kl-8g-cicd-megatron); функциональный тест Qwen3 0.6B TP1/PP1 пройден с фиксацией golden values для P800; настроен FlagCX с приоритетом бэкенда TransformerEngine-FL vendor.kunlunxin.
  • Известные ограничения: бенчмарки TP2/PP2 не включены — бэкенд KunlunXin недостаточно поддерживает kernel для sequence-length-4096, откат неподдерживаемых операторов на медленную реализацию приводит к таймауту, конфигурация бенчмарков сохранена до завершения последующих проверок на стороне TE-FL.

Толкование: это первое вхождение KunlunXin (XPU от Baidu) в матрицу CI Megatron-LM-FL. В сочетании с уже присутствующим в документации образов release-info base-образом kunlunxin-xre5.37.1 аванпост адаптации новых чипов тренировочной линии уже на месте — что согласуется с наблюдением в skill «PyTorch-Plugin-FL — аванпост подключения новых чипов», KunlunXin входит в экосистему FlagOS по пути base-образ → матрица CI.

2. Новости и экосистема

2.1 Общая оценка по новостной стороне

Google News по ключевым словам компонентов FlagGems/FlagScale/FlagTree/FlagPerf/FlagCX/KernelGen/FlagOS-Robo/FlagQuantum в пределах окна не дал прямых совпадений; запросы в HN (FlagOS/FlagGems/FlagScale/FlagTree/BAAI) релевантных совпадений не дали (совпадения — обсуждения классического AI, тарифы Stripe и прочие нерелевантные посты). Все попавшие в окно записи gnews — это финансовый/биржевой шум: котировки ETF с крупными позициями (Cambricon/Hygon Information/VeriSilicon), результаты за полугодие, прогнозы ребалансировки Hong Kong Stock Connect (Tianshu Zhixin 09903), позиции пенсионных фондов (Moore Threads), результаты Q1 Cambricon и уведомление о собрании акционеров — всё это не открытые разработки FlagOS; запрос “Институт Zhiyuan открытый исходный код” по-прежнему в основном даёт беттинг/SEO-шум (спортивные/официальные сайты/заголовки входных страниц), весь массив исключён. Агрегированные статьи сообщества Zhiyuan (Anthropic/Claude/DeepSeek Harness/Qwen3.8 и др.) — это темы индустрии AI, прямой связи с FlagOS нет. По новостной стороне в этот день значимых событий нет, основное содержание опирается на коммиты GitHub.

4. Итоги

  1. Масштабное расширение набора эталонов FlagBLAS (главная тема окна): 10 PR / 18 коммитов, полное покрытие Level-1 (rot/ger/rank-1/rank-2 update), Level-2 (trsv/hpmv/spmv/hbmv/треугольные/ленточные/симметричные), Level-3 (trmm), три семейства — треугольные/ленточные/симметричные — явно адаптированы под Hygon hipBLAS — систематическое пополнение поверхности эталонов производительности, прокладывающее путь к данным многочиповых эталонов после релиза 2.1.2.
  2. KunlunXin P800 вошёл в CI Megatron-LM-FL (сигнал новой чиповой линии): все 8 XPU юнит-тестов пройдены + функциональный тест Qwen3 0.6B TP1/PP1 пройден; TP2/PP2 отложены из-за недостаточной поддержки ядер, оставлены до завершения бэкенда KunlunXin в TransformerEngine-FL — аванпост адаптации новых чипов для линии обучения занят.
  3. Замкнутый инженерный цикл линии Хайгуан в build-infra: LLVM DTK в образе + обновление triton 3.5.1; верификация hygon25 по четырём сценариям (gap платформы rl, необъявленная зависимость tensorboard, путаница с информацией о версии flash_attn — всё задокументировано); патч sysconfig на этапе сборки megatron wheel (fallback до слияния upstream #112); исправление vllm flashinfer gate для ловушки подтягивания torch со значением по умолчанию 0.20.2.
  4. Продвижение распределённой линии FlagTree TLE: shard_id поддерживает node axis (#969, 10 коммитов слито), ветка распределения раскладки GPU в активной разработке; инженерия FlagPrism продолжается (CodeOwner).
  5. Новостная сторона спокойна: по ключевым словам компонентов ноль попаданий, на HN результатов нет; попадания gnews в окне — финансовый/биржевой шум; официальных GitHub Release нет, цикл 2.1.2 всё ещё находится в стадии верификации и завершения адаптации.

Пояснение об ограничениях: build-infra #408 — изменение только в документации, выводы верификации по четырём сценариям взяты из описания коммита (блокировка rl, зависимости tensorboard и т. д. — фиксирующие находки, коммитов с исправлениями не обнаружено); результаты верификации KunlunXin P800 взяты из описания PR и записей о слиянии, независимых скриптов воспроизведения не обнаружено; по ссылкам-редиректам gnews не удаётся получить основной текст, суждения по новостной стороне опираются на заголовки и перекрёстное подтверждение из нескольких источников.
