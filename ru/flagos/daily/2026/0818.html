Ежедневный отчёт FlagOS (2026-08-18)

2026-08-18 Kubuds

Окно мониторинга: 2026-08-17 10:25 ~ 2026-08-18 10:19 пекинское время Источники: GitHub (org: flagos-ai), агрегация Google News (китайский и английский), HN, сообщество Zhiyuan/BAAI и др. (подробнее в приложении)

1. Прогресс открытых проектов (динамика GitHub)

Обзор окна: из 53 репозиториев в org 16 имели пуши в окне; поиск по коммитам выявил 81 коммит в ветке по умолчанию в пределах окна, что делает его одним из самых активных окон этого месяца, официальных GitHub Release нет. Три основные линии этого окна: волна массового слияния операторов FlagGems KernelGen (около 25 коммитов, всестороннее развёртывание мультичиповых бэкендов), дополнение мультичиповой функциональности Torch-FL (Hygon DCU AMP, интеграция Enflame без torch_gcu, причём с поддержкой разработки агентом Claude Code), расширение матрицы мультивендорной валидации build-infra (Moore Threads MUSA 5.2.0/4.3.6, Ascend CANN 9.0.0 последовательно зафиксированы) + Hygon BW1000 вошёл в Megatron-LM-FL CI.

1.1 FlagGems: волна массового слияния операторов KernelGen, всестороннее развёртывание мультичиповых бэкендов (около 25 коммитов)

Источник: FlagGems commits

  • Мультибэкендовые операторы: linalg_det одним оператором сразу охватывает семь бэкендов NVIDIA/Ascend/Hygon/Thead/MetaX/Iluvatar (8/17 14:51); conj_physical добавлена конфигурация hygon runtime и ascend tune (#5434).
  • Массовое добавление операторов KernelGen NVIDIA (8/17 10:45-10:52, плотное слияние 16 штук): avg_pool1d, weight_int8pack_mm, special_bessel_y0, grid_sampler_3d_backward, upsample_bilinear2d_aa_backward, _native_batch_norm_legit, _fused_moving_avg_obs_fq_helper, special_shifted_chebyshev_polynomial_t, cdist, addr (inplace), empty_permuted, batch_norm_impl_index, addbmm, _adaptive_avg_pool3d_backward, fake_quantize_per_channel_affine и др., а также native_dropout_backward переотображён на canonical wrapper (#5414).
  • Чип-специфичные пакеты: [KernelGen][Hygon] пакет операторов Hygon (#5557, 8/18 10:21); [KernelGen][Iluvatar] пакет операторов Iluvatar CoreX (#5558, 8/18 10:21).
  • Линия KMCompiler/Ascend: replication_pad2d_backward бэкенд Ascend (#5508); оптимизация планирования строк layer norm forward (#4903).
  • Оптимизация Moore Threads: [MTHREADS] специализированное ядро constant_pad_nd (#5395); matmul_bias_activation переведён на оптимизацию инструкциями SQMMA (#5551).
  • Общие исправления: резервная функция чистого triton y0 для не-CUDA бэкендов (#5553).

Толкование: конвейер автоматической генерации операторов KernelGen ускоряется — на стороне NVIDIA в основном “расширяется охват операторов”, а на Hygon/Iluvatar впервые появился режим слияния “выделенных пакетов операторов” (утром 8/18 выпущено сразу два), что говорит о том, что подключение производителей чипов к процессу генерации KernelGen вошло в массовую фазу, перекликаясь с механизмом экспериментальной площадки FlagGems-Experimental, наблюдавшимся в отчёте от 8/12.

1.2 Torch-FL: дополнение мультичиповой функциональности, привлечение агента Claude Code для поддержки разработки (10 коммитов)

Источник: Torch-FL pulls

  • Обучение AMP на Hygon DCU (#117, влито 17.08 в 19:42): включены AMP autocast + GradScaler; в процессе разработки на реальном оборудовании Hygon DCU измерялось поведение AMP/dtype, после изоляции трёх независимых расхождений в реализации они были исправлены, а также добавлены регрессия на реальном устройстве и покрытие CI.
  • Интеграция FlagCX для Enflame без torch_gcu (#115, влито 17.08 в 17:25): больше не используется приватная обёртка torch_gcu от Enflame, реализовано прямое подключение к коммуникационному стеку FlagCX; проверка выполнена на двух устройствах Enflame S60, параллельно зарегистрирован issue #544 в FlagCX.
  • Прочее: унификация нативного RNG GCU и RNG FlagGems (#113); CUDA boxing отклоняет несовместимый генератор flagos (#118); восстановлены device activities профилировщика PPU (Zhenwu) (#119); FSDP2 генерирует kernel cat.out (#107); исправление интеграции подстановки во время установки FlagTree (#116); сборка и тестирование одного job в CICD (#112); документация harness для интеграции четырёх команд (#114).

Разбор: в обоих PR #115 и #117 явно указано “AI Agent: Claude Code CLI / Claude Opus 5 / ручная проверка zhaoyinglia” — команда FlagOS начала применять новую схему вспомогательного кодирования интеллектуальным агентом с проверкой инженером в задачах адаптации под реальное оборудование, что согласуется с направлением проекта FlagScale-Agent внутри org и является заслуживающим внимания сигналом о модели разработки в этом окне мониторинга.

1.3 Megatron-LM-FL: Hygon BW1000 входит в CI модульных тестов (PR #93)

Источник: Megatron-LM-FL PR #93

  • Платформа Hygon BW1000 (влито 17.08 в 14:09, AlexMa616): в матрицу модульных тестов Megatron-LM-FL добавлена поддержка CI на оборудовании Hygon BW1000 — добавлены конфигурация платформы и workflow GitHub Actions с ручным запуском, переиспользован уже проверенный образ CI BW1000 DTK (включающий существующие PyTorch и runtime ускорителя), а также добавлены шаги настройки окружения и проверки зависимостей, специфичных для Hygon.

Разбор: после отчёта от 17.08 о включении Kunlunxin P800 в CI, Hygon BW1000 становится ещё одной чиповой линией, вошедшей в матрицу модульных тестов тренировочной линии. В сочетании с добавлением пакета apex в runtime-образ Hygon в build-infra и повторной проверкой четырёх сценариев hygon25 (см. 1.4), цепочка “образ → модульные тесты → проверка сценариев” Hygon на тренировочной линии в этом окне мониторинга имеет действия на всех этапах, что делает Hygon наиболее полно адаптированной из текущих организаций-участников.

Комментарий: эталонный набор FlagBLAS всего за два дня перешёл от «массового расширения» к «стабилизационному завершению»; вместе с упорядочиванием реестра operators.yaml темпы инженеризации эталонной базы очень высоки, что прокладывает путь к публикации эталонных данных после 2.1.2.

Google News по ключевым словам компонентов FlagGems/FlagScale/FlagTree/FlagPerf/FlagCX/KernelGen — нулевых прямых попаданий в окне; запросы в HN (FlagOS/FlagGems/BAAI) — релевантных попаданий нет (найденное — всё инструменты feature flags, научпоп о мозге и прочие нерелевантные посты). Попадания gnews в окне в основном — пересказ старых новостей вне окна: Qwen3.8-2.4T «адаптация под девять чипов» (пересказ Sina Finance от 8/17; уже включено 8/13–14 в отчёт от 8/14, повторно не включается); Triton-TLE/FlagTree стократное ускорение (QQ News от 8/7, вне окна); автономный исследовательский агент AREX (включено 8/11). Записи в окне, которые можно использовать как экосистемный ориентир: 2026 CCF China Open Source Conference открылась в Чунцине (China Daily от 8/17, общая open-source конференция, явной связи с FlagOS не обнаружено); статья сообщества Zhiyuan «Разбор финансового отчёта Cambricon: выручка заблокирована поставками» (8/17, операционная сторона организации-участника). На новостной стороне в этот день значимых новых событий нет, основное содержание опирается на GitHub commits.

Оценка тренда: характерная черта чиповой карты этого окна — «все существующие участники полностью активизировались + заметное расширение линии Zhenwu PPU». После первого массового выхода Alibaba Cloud T-Head Zhenwu PPU в покрытие операторов FlagGems 12.08, в этом окне она одновременно появляется в четырёх компонентах — FlagFFT (бэкенд), FlagCX (интеграция ACCL), FlagTree (AABS), Torch-FL (profiler): Zhenwu быстро подключается по полностековому пути «библиотека операторов → библиотека коммуникаций → компилятор → плагин обучения». Hygon же переходит в стадию «детализированная верификация + вывод нового железа (BW1000) в CI»; обе линии образуют две главные оси динамики участников в этом окне.

4. Итоги

  1. Конвейер операторов FlagGems KernelGen осуществляет массовую поставку (главная новость окна мониторинга): около 25 коммитов, 16 новых операторов на стороне NVIDIA + единовременное покрытие linalg_det на семи бэкендах + впервые появившиеся «специализированные партии операторов» для Hygon/Iluvatar (серия коммитов утром 8/18) — процесс автоматической генерации операторов KernelGen вышел на стадию многоплатформенной массовой работы, стоимость интеграции на стороне производителей чипов заметно снизилась.
  2. Дополнение многоплатформенной функциональности Torch-FL + режим разработки с помощью агентов: Hygon DCU AMP (исправление трёх gap по результатам измерений на реальном железе), Enflame FlagCX без torch_gcu (проверка на двух S60); два ключевых PR разработаны агентом Claude Code и вручную проверены инженерами — сигнал о процессе разработки заслуживает отслеживания.
  3. Hygon BW1000 включён в CI модульных тестов Megatron-LM-FL: вслед за Kunlunxin P800 продолжается подключение новых чипов к линейке обучения; build-infra одновременно добавляет apex в runtime-образ Hygon и завершает повторную проверку triton 3.5.1 на hygon25 в четырёх сценариях, Hygon проявляет активность по всей цепочке «образ → модульные тесты → проверка сценариев».
  4. Расширение матрицы верификации build-infra на множество производителей + обновление механизма: Moore Threads MUSA 5.2.0/4.3.6 и Ascend CANN 9.0.0 E2E последовательно зафиксированы; в образе приложения megatron добавлен механизм условных зависимостей deps_app по производителю (#424), что представляет собой механизменное исправление зафиксированного в #408 пробела платформы.
  5. Обновление архитектуры коммуникационного абстрактного слоя FlagCX + полное подключение стека Zhenwu PPU: объединён уровень устройств Unified One-Sided IR (flagcxDev*); четыре компонента FlagFFT/FlagCX/FlagTree/Torch-FL одновременно проявляют связанные с PPU слияния, Zhenwu PPU быстро расширяется по всему пути стека.
  6. Новостная сторона спокойна: нулевые попадания по ключевым словам компонентов, отсутствие результатов на HN, повторы старых новостей не включаются повторно; официальных GitHub Release нет, цикл 2.1.2 всё ещё находится на стадии верификации и накопления функциональности, признаки веток 0.2.x/rc у нескольких компонентов указывают на то, что новый раунд релизов, возможно, уже близок.

Описание ограничений: количество и время слияния операторов KernelGen взяты из commit search (поисковый индекс может немного отклоняться от фактических данных, для отдельных коммитов время определяется по repos API pushed_at); выводы о проверке на реальном железе Torch-FL #115/#117 взяты из описания PR (сводка сессии Claude Code + ручная проверка), независимые скрипты воспроизведения не обнаружены; по ссылкам-редиректам gnews невозможно получить основной текст, суждения новостной стороны опираются на заголовки и перекрёстное подтверждение из нескольких источников; полное подключение стека Zhenwu PPU является обобщённым выводом на основе слияний в нескольких компонентах, явных деклараций зависимостей между точками слияния нет.
