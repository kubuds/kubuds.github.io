Оба коммита вместе превращают «сколько времени занимает одна синтезация и сколько памяти она занимает» в воспроизводимые цифры, а не в единичное наблюдение.

Для квантового стека это важнее, чем отдельные цифры производительности: это позволяет любому последующему изменению распределения регистров или синтеза гейтов немедленно измерять цену по существующим записям.

3.1 T-Head: специализированные операторы, модель стоимости MM и chunk_kda — три направления одновременно (2 ноября)

Дата: 2026-11-02　Источники: FlagGems PR #8240 · FlagTree PR #1236 · FlagGems-vllm PR #1038

  • Уровень операторов: 13 специализированных операторов T-Head влиты в FlagGems за 43 минуты, охватывают специальные функции, трёхмерную свёртку, квантованный LSTM, матричные нормы и обратное распространение пулинга. Общее для этих записей — низкая отдача универсальных реализаций на Triton на T-Head; после специализации они могут напрямую войти в диспетчеризацию по умолчанию библиотеки операторов.
  • Уровень компиляции: #1236 повышает пакет моделей стоимости MM/MV для T-Head ZW810E до версии 1.1.0, включает его в каталог моделей FlagTune и позволяет контракту автоматической настройки принимать явный список configs — с поштучной проверкой по имени параметра и допустимым значениям, отклоняя запись, сосуществующую с config_space. Пакет содержит 8 вариантов BF16 mm и 2 модели mul — это первая полная модель стоимости для автоматической настройки на T-Head.
  • Уровень инференса: #1038 добавляет для chunk_kda оптимизации двух бэкендов — Iluvatar CoreX и T-Head, относящиеся к пути длинных последовательностей FlagGems-vllm.
  • Оценка: действия T-Head в этот день распределены по трём уровням — операторы, компиляция, инференс — и все указывают на «специализацию», а не на «универсальную совместимость». Это согласуется с позиционированием T-Head как высокопроизводительного ядра RISC-V: сначала дополнить специализированные реализации длиннохвостых операторов, затем позволить модели стоимости управлять автоматической настройкой и, наконец, реализовать это в фреймворке инференса.

3.2 Kunlunxin: исправление контракта foreach XPU3 и четырнадцать закрытий по производительности (2 ноября)

Дата: 2026-11-02　Источники: FlagGems PR #8038 · FlagGems PR #8034 · FlagGems PR #8123 · FlagGems PR #8245

  • Тихая ошибка: #8038 указывает, что быстрый путь foreach сравнивает только число элементов, но не форму; список тензоров с разными формами, но одинаковым числом элементов унаследует форму первого тензора, и вывод не выдаст ошибку и не выйдет за границы. Исправление определяет допуск по полной форме, а также меняет шестнадцать скалярных выходов на адресацию от единой базы и объединяет списочные выходы в плоский буфер.
  • Сетка и слоты: #8034 вычисляет сетку автоматической настройки перед отправкой JIT; #7976 берёт индекс слота foreach из program_id(0); #7956 исправляет распаковку тройного возвращаемого значения при разборе скаляров.

Для мультибэкендовой библиотеки операторов такие дефекты опаснее десятикратного замедления — их не обнаружат бенчмарки, на них наткнутся нижележащие модели в виде «аномалии точности».

3.3 Ascend и Hygon: две реализации W8A8 INT8 — GEMM и BMM (11-02)

Дата: 2026-11-02　Источники: FlagGems PR #6060 · FlagGems PR #7741 · FlagGems PR #7774 · FlagGems PR #7760

  • Ascend GEMM: #6060 добавляет бэкенд Ascend для mm_w8a8_int8 и mm_w8a8_int8_out с диспетчеризацией через публичную точку входа. Оператор принимает предварительно квантованные INT8 A и B, FP32 скалярный или построчный/постолбцовый scale, опциональный bias; после целочисленного умножения-сложения применяются scale с обеих сторон и bias, вывод в BF16, FP16 или FP32; при малом M и узком N используется векторное ядро умножения-сложения, при этом каждый блок FP32-редукции содержит не более 1024 произведений INT8 для гарантии точности целочисленной части. Асимметричный zero point не поддерживается.
  • Hygon BMM: #7741 добавляет для Hygon канальный bmm_w8a8, повторно используя существующее scaled-MM ядро и выбор tile, объединяя INT8-матричное умножение, FP32-поканальное масштабирование и преобразование вывода в одном ядре.

  • Вывод: обе компании в одном окне добавили по одному пути W8A8 — Ascend выбрал полную семантику GEMM (включая построчный/постолбцовый scale и три типа выходного dtype), Hygon — канальное масштабирование с повторным использованием для BMM. Различие в широте охвата семантики и в компромиссе по повторному использованию реализации, что также отражает разные потребности нижестоящих моделей каждой из них в формах квантования.

3.4 Moore Threads: истинно одномерный GEMM в Conv1D вывел все 26 бенчмарк-примеров за черту 0.8x (11-02)

Дата: 2026-11-02　Источники: FlagGems PR #6754 · FlagGems PR #7428 · FlagGems PR #6903 · FlagBLAS PR #157 · FlagTree PR #1314

  • Результат Conv1D: #6754 добавляет покрытие бэкенда conv1d для MTT S5000, поднимая официальный бенчмарк conv1d_padding с 18/26 прошедших примеров до 26/26 примеров не ниже 0.80x torch; ранее все примеры FP32 K3/K5 padding давали лишь 0.41–0.53x.
  • Три уровня изменений: во-первых, conv1d изначально не имел покрытия MTHREADS и полностью шёл через общий conv2d, из-за чего формы с малыми группами материализовали padding, а формы с W=1 попадали лишь в единственный эффективный канал OW; после изменения маршрутизации устранены избыточные padding и выделение bias, а также исправлена диспетчеризация вырожденной ширины. Во-вторых, добавлено специализированное ядро Triton-MUSA Conv1D, выполняющее трёхмерное разбиение сетки по M, равному N умножить на Lout, при этом выходные каналы больше не вычисляются делением с остатком. В-третьих, веса предварительно упаковываются в порядке: ширина ядра, входные каналы, выходные каналы, в сочетании с SQMMA с компенсацией точности.
  • Сопутствующее: #7428 оптимизирует проверку и вывод one_hot на S5000; #6903 трактует пустой индекс как no-op для index_add; #157 добавляет L1 BLAS для MUSA; #1314 пропускает membar между двумя асинхронными копиями TME.
  • Вывод: это редкий в данном окне полный случай «вывода всех бенчмарков за черту» — маршрутизация, специализированное ядро, раскладка весов и компенсация точности на уровне инструкций изменены одновременно, с приведением сравнения до и после. Для других бэкендов это воспроизводимый шаблон.
