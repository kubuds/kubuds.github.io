1. Динамика сообщества открытого исходного кода и программной экосистемы

1.1 Официальная спецификация HAC для RISC-V — третий день подряд интенсивные правки (15+ коммитов, продолжается спринт по сходимости ревью)

Дата: 2026-08-17 18:00 ~ 2026-08-18 07:45 (пекинское время)　Источник: riscv/riscv-high-assurance-cryptography GitHub

В окне в репозиторий спецификации высоконадёжной криптографии (HAC) было влито ещё 15+ коммитов, что продолжает начатую в предыдущие два дня основную линию спринта по постквантовым ML-KEM/ML-DSA: Resolved ace.size returning a PI's size in a suitable status (уточнение, при каком состоянии CR ace.size возвращает размер PI), Clarify padding and key derivation behavior (разъяснение поведения заполнения и вывода ключа), Marked issue of ace.load/ace.store in wrong extension as a non-issue (проблема использования ace.load/store в другом расширении квалифицирована как не-проблема), три последовательных обновления ace-ISA-algorithms.adoc, правки ace-introduction/acronyms, обновление зависимости docs-resources (#146) и др. Интенсивные правки три дня подряд (в предыдущие два дня — около 12 коммитов в день) показывают, что спецификация этого расширения, ориентированная на реализации высоконадёжной криптографии уровня FIPS 140-3, всё ещё находится в фазе сходимости ревью, совпадая с основной линией безопасности/криптографии этой недели (статья о Spectre, поддержка SPMP): официальный RISC-V системно закрывает пробелы в инфраструктуре безопасности и криптографии.

1.2 XiangShan — 8 влитых коммитов в основную ветку за день: исправление MissQueue, случайное распределение Tage, рефакторинг banked regfile

Дата: 2026-08-17 10:38 ~ 14:59 (пекинское время)　Источник: OpenXiangShan/XiangShan GitHub

В окне в основную ветку XiangShan было влито 8 коммитов (ранее основная ветка остановилась на исправлении обновления satp #6014 от 08-14; во вчерашнем отчёте делался вывод об «отсутствии вливаний новых функций уровня основной ветки», сегодня это было опровергнуто):

  • Исправление MissQueue (#6308): secondary_ready should gate req_valid — сигнал готовности второго уровня должен стробировать валидность запроса; это исправление корректности в очереди обращения к памяти;
  • Исправление IFU (#6354): correct checkerRedirect taken — исправление пути перенаправления при выборке инструкций во фронтенде;
  • Новая функция Tage (#6349): random allocate — в предсказатель ветвлений Tage введена стратегия случайного распределения; это новая функция на уровне поведения предсказателя;
  • Рефакторинг регистрового файла (#6357): banked regfile теперь использует младшие биты индекса как bankIndex — оптимизация раскладки многобанкового физического регистрового файла;
  • Очистка Ftq (#6358): удалена логика счётчика dropTarinCounter;
  • Исправление transforms (#6361): разбор имени модуля перед сериализацией CHIRRTL;
  • configs (#6359): обновление mbtb/sc во фронтенде MinimalConfig; обновление CI labeler (#6333).

8 коммитов за день, смесь исправлений, новых функций и рефакторинга — темп разработки основной ветки XiangShan вернулся к активному уровню.

1.3 riscv-unified-db — влито три исправления семантики инструкций: знаковое расширение zalrsc, фиксированная длина sstateen, индекс c.sdsp

Дата: 2026-08-18 05:22 ~ 05:36 (пекинское время)　Источник: riscv/riscv-unified-db GitHub

Официальная унифицированная база данных инструкций RISC-V (unified-db, проект UDB) в рамках окна мониторинга включает три исправления на уровне семантики инструкций:

  • fix(zalrsc): sign-extend the lr.w result on RV64 (#2460) — результат lr.w расширения Zalrsc на RV64 требует знакового расширения;
  • fix(csr): sstateen0-3 take the stateen family's fixed length of 64 (#2395) — CSR sstateen0-3 имеют фиксированную 64-битную длину;
  • fix(isa): c.sdsp must use its full 5-bit register index (#2419) — компрессированная инструкция c.sdsp должна использовать полный 5-битный индекс регистра.

UDB — это единый машиночитаемый источник семантики инструкций для официального spec/программного инструментария RISC-V (riscv-arch-test, Sail и другие потребляют этот репозиторий). Подобные низкоуровневые исправления семантики напрямую влияют на корректность тестовых и симуляционных инструментов и относятся к обслуживанию уровня «инфраструктуры спецификаций».

2.1 Mouser начала продажи комплекта разработки для машинного зрения Espressif ESP32-P4X-EYE (единственная новинка на стороне новостей за сегодня)

Дата: 2026-08-17 (пекинское время 18:49 / сообщения в 04:18 следующего дня)　Источники: Electronic Design (ссылка gnews) / Electropages (ссылка gnews)

Mouser начинает поставки комплекта разработки для машинного зрения Espressif ESP32-P4X-EYE, ориентированного на AI, граничные вычисления, HMI и камерные приложения. По данным официальной страницы espressif.com: ESP32-P4 использует двухъядерный CPU RISC-V (до 400 МГц), поддерживает FPU одинарной точности и расширения инструкций AI, оснащён передовой подсистемой памяти и высокоскоростными периферийными интерфейсами — это первая серия высокопроизводительных универсальных SoC Espressif, полностью отходящая от Xtensa. Значение: аппаратная доступность Espressif в области устройства-стороннего AI на RISC-V (направление восприятия/зрения) получает дальнейшее развитие, а продуктовые линейки “высокопроизводительный RISC-V + расширения AI” за пределами серии ESP32-C начинают расширять каналы сбыта.

4. Специальная глава по ключевым направлениям: воплощённый интеллект и робототехника

В данном окне в направлении воплощённого интеллекта не было крупных новых релизов, наиболее заметным по-прежнему остаётся стек обучения с подкреплением для гуманоидных роботов K3 компании Jindie Space: в окне model_zoo_rl был выполнен push ветки fix/eigen-cmake-target (исправление интеграции сборки), в ветку по умолчанию 07-23 уже слиты декларативный ввод/вывод моделей и поддержка типизированных тензоров — стек вывода RL (включая ранее освещённый вывод полного графа SPERT NPU, CI robot-test, конфигурации per-policy kp/kd) продолжает развиваться, но темп соответствует «режиму поддержки», а не «режиму новых функций».

4.2 Доступность периферийного vision-оборудования: ESP32-P4X-EYE поступил в продажу

С точки зрения «уровня восприятия» воплощённого интеллекта, vision-комплект разработчика ESP32-P4X-EYE от Espressif (двухъядерный RISC-V 400MHz + расширения AI-инструкций + интерфейсы камеры/дисплея) поступил в продажу, предоставив новый низкозатратный вариант оборудования RISC-V для периферийного визуального восприятия (предобработка SLAM, фронтенд обнаружения объектов, взаимодействие HMI). Вместе с Jindie SPERT (периферийный вывод NPU) и библиотекой визуальных примеров Sophon (серия YOLO) это составляет постоянное усиление уровня восприятия в трёхуровневом пути локализации «восприятие—решение—управление движением» на отечественных RISC-V.

4.3 Обзор трендов за последние три дня

Возвращаясь к 08-15 ~ 08-17: форум Dishui Lake закрепил маршрут двухъядерного гетерогенного управления движением «реальное ядро + прикладное ядро» (Fengf FU75XX, Xianji HPM53M1, позиционирование управления движением Jindie K3); большая архитектурная дискуссия (лонгрид Grinberg против ответа инженеров глобального Юга) продемонстрировала редкое единодушие в том, что «дешёвые встраиваемые RISC-V неизбежны»; на этой неделе направление воплощённого интеллекта в целом находится в паузе между релизами, основная линия по-прежнему — локализация управления движением с приоритетом «чувствительность к стоимости + приоритет реального времени» и шлифовка периферийного стека восприятия.

5. Итоги и наблюдения за трендами

  1. День спокойных новостей и активного GitHub: в окне на новостной стороне лишь 1 новый продукт (ESP32-P4X-EYE поступил в продажу), HN за 24ч — ноль попаданий, запросы по производителям/на китайском — все пустые; но официальные организации RISC-V и отечественные команды сохраняют высокую активность на GitHub — характеристика «код как новость» выражена явно.
  2. Третий день подряд интенсивных правок спецификации HAC (15+ коммитов): семантика ace.size, padding/вывод ключей, определение кросс-расширенных ace.load/store — постквантовое криптографическое расширение, ориентированное на FIPS 140-3, вступило в финальную стадию ревью, безопасность/криптография — текущая приоритетная основная линия официального RISC-V.
  3. Основная ветка XiangShan вновь активна: 8 слияний за один день (исправления MissQueue, случайное распределение Tage, рефакторинг banked regfile, исправления IFU/Ftq), что нарушило тишину основной ветки с 08-14, темп разработки XiangShan вернулся к активному режиму.
  4. Отечественные команды продвигаются по трём линиям: Espressif (итерации фреймворка AI agent esp-claw 2014★ + синхронизация инструментальной цепочки RISC-V), Jindie (поддержка среды выполнения humanoid RL + выход основного ядра K1 7.2 в Yocto), Sophon (агентная трансформация инструментальной цепочки и отказоустойчивость); Pingtouge/Xinlai/ESWIN — тишина.
  5. Инфраструктурная поддержка экосистемы заслуживает отслеживания: три исправления семантики инструкций в riscv-unified-db (zalrsc/sstateen/c.sdsp) напрямую влияют на корректность инструментальных цепочек arch-test/Sail и т.п.; подобная динамика «инфраструктуры спецификаций» — опережающий индикатор здоровья экосистемы.

Пояснение об ограничениях: полный текст репортажа об ESP32-P4X-EYE через переход gnews дал лишь пустую страницу-оболочку; детали продукта (состав комплекта, цена) следует уточнять по заголовку и официальной странице espressif.com; данные GitHub основаны на неаутентифицированном API (выполнено в пределах лимита 60 req/h, часть push в репозиториях — динамика уровня веток, коммиты в ветку по умолчанию верифицируются через интерфейс commits); содержание слияний sophon-tools — итерации внутренней инструментальной цепочки, оценка влияния на бизнес не проводилась.
