1. Открытое сообщество и программная экосистема

1.1 Официальная поддержка RISC-V в CPython: стал официальной платформой tier 3 (08-25)

Дата: 2026-08-25 (одновременно с публикацией в блоге; в HN добавлено 08-24 20:12 UTC = 08-25 04:12 пекинское время)　Источник: blog.python.org, HN

CPython официально объявил RISC-V официально поддерживаемой платформой, отнесённой согласно PEP 11 к tier 3. Путь поддержки: RISE Project предоставляет несколько реальных RISC-V-устройств в качестве среды для тестирования buildbot и отладки архитектурных проблем (участники сообщества Ludovic Henry, Furkan Onder, Emma Smith и другие), стипендия Sovereign Tech Agency финансировала этот раунд работ по поддержке архитектуры. Следующие шаги: с помощью RISE RISC-V Runners подключить RISC-V напрямую к официальному CI CPython (более быстрая обратная связь, чем buildbot), в долгосрочной перспективе продвигать повышение до tier 2 и выполнять оптимизацию производительности под конкретную архитектуру. Значение: Python — стержневой язык программного стека AI/робототехники, официальная поддержка tier 3 закрывает ключевое звено в программной доступности RISC-V для периферийных и серверных сценариев (в сочетании с серверным прогрессом в 2.1).

1.2 В Linux 7.3 добавлена поддержка ряда расширений RISC-V (08-24)

Дата: 2026-08-24 (Phoronix 10:12 UTC = 18:12 пекинское время)　Источник: Phoronix

В разрабатываемый Linux 7.3 включена поддержка обнаружения и перечисления ряда относительно новых расширений RISC-V ISA: косвенный доступ к CSR (Smcsrind/Sscsrind), привилегированная фильтрация счётчиков (Smcntrpmf), конфигурация счётчиков в S-режиме (Ssccfg), делегирование счётчиков (Smcdeleg, охватывает все уровни привилегий), классы атомарности/когерентности памяти (Zicclsm — невыровненный доступ к памяти, Ziccamoa — атомарные операции, Ziccif — атомарность выборки инструкций, Ziccrse — прямое продвижение LR/SC, Za64rs — зарезервированные наборы), идентификация QoS (Ssqosid, мониторинг пропускной способности памяти/кэша). Также имеются улучшения обработки CFI Shadow Stack, переключение контекста меток QoS, сервисы UEFI Runtime для перезагрузки/выключения и т. д. Этот набор расширений ориентирован преимущественно на серверы и мониторинг производительности и напрямую перекликается по возможностям с продвижением серверной платформы RVA23 (см. 2.1).

1.3 Hot Chips 2026: NVIDIA подробно описывает технические требования для портирования CUDA на RISC-V (24.08)

Дата: 2026-08-24 (опубликовано Chips and Cheese; HN 68 баллов, 9 комментариев)　Источники: Chips and Cheese, HN

На Hot Chips 2026 NVIDIA представила доклад о расширении поддержки CUDA на RISC-V: требуется профиль RVA23 и спецификации RISC-V server SoC / server platform (включая базовые возможности RAS, выделенный процессор безопасности и т. д.); дополнительно требуются согласованность PCIe (иначе между DMA и кэшем CPU потребуется явная программная инвалидация, что трудно реализуемо в стеке CUDA), P2P PCIe между устройствами, поддержка предикатов векторных расширений и т. д., чтобы избежать ситуации “наименьшего общего знаменателя”, при которой невозможно использовать инструкции повышения производительности; проблемы с ACPI ранее тормозили портирование, но были решены благодаря поддержке ACPI для RISC-V со стороны форума UEFI в 2025 году и спецификации BRS (Boot and Runtime Services), утверждённой в прошлом году. Южнокорейское издание «Ежедневная экономика» (Республика Корея) в тот же период сообщило, что NVIDIA планирует расширить поддержку CPU для AI-серверов с Arm/x86 до RISC-V. В сочетании с подтверждением SiFive, что CUDA уже фактически работает на её платформе BigSky (см. 2.1), “CUDA на RISC-V” переходит от заявлений 2025 года к этапу реализации технических требований.

1.4 Руководство по системе команд RISC-V выходит на стадию проекта международного стандарта ISO/IEC DIS 26791-1 (24.08)

Дата: 2026-08-24 (HN 12:54 UTC = 20:54 пекинское время)　Источники: HN, iso.org/standard/94578

Руководство по системе команд RISC-V под номером ISO/IEC DIS 26791-1 вышло на стадию проекта международного стандарта (DIS) — в процессе стандартизации ISO/IEC JTC 1 стадия DIS предполагает голосование стран-членов и является ключевым этапом официальной международной стандартизации. Это знаковое действие по превращению открытой ISA в стандарт ISO, согласующееся с продвижением стандартизации RISC-V International в JTC 1. Примечание: страница на официальном сайте ISO защищена от парсинга, и получить основной текст напрямую невозможно; технический охват определяется официальным сайтом и текстом DIS.

2. Продукты и динамика экосистемы

2.1 SiFive BigSky SF-2U870: представлен первый в мире стоечный 2U RISC-V корпоративный сервер (24.08)

Дата: 2026-08-24 (пресс-релиз SiFive; HotHardware 12:23 EDT = 25.08 00:23 пекинское время)　Источники: пресс-релиз SiFive, HotHardware, HPCwire

SiFive одновременно с Hot Chips 2026 представила платформу разработки для центров обработки данных BigSky SF-2U870, заявленную как первый в мире корпоративный стоечный 2U RISC-V сервер: 32 ядра P870-D @2GHz, 256GB DDR5-5600, 3.84TB U.2 NVMe, сеть 10/25Gbps OCP 3.0, 64 линии расширения PCIe Gen5 (вмещают двухслотовые GPU и специализированные ускорители), соответствие RVA23; из коробки поддерживаются Ubuntu 26.04 LTS и RHEL 10; ориентирован на гипермасштабируемых облачных провайдеров, производителей чипов и разработчиков ПО для портирования корпоративного ПО, оптимизации нагрузок и предварительной проверки перед tape-out собственных чипов. Уже продаётся ограниченными партиями со склада (официально заявлено, что “спрос превышает предложение”, CEO Патрик Литтл: “Выход RISC-V в центры обработки данных больше не далёкая мечта”). Ключевая деталь: SiFive сотрудничает с NVIDIA над портированием CUDA и планирует интегрировать NVLink Fusion в будущие платформы, CUDA уже фактически работает на BigSky в качестве головного узла для современных рабочих нагрузок LLM на GPU NVIDIA — впервые аппаратное обеспечение RISC-V обладает такой возможностью.

2.2 IAR и Neusoft Reach заключили стратегическое партнёрство: восполнение цепочки инструментов для автомобильных RISC-V (сообщения 08-24/25)

Дата: сообщения от 2026-08-24/25 (EET-China 08-25 00:17 пекинское время; стороны подписали соглашение 08-20 в Шанхае)　Источники: BigGo Finance, EET-China (EE Times China)

Производитель встраиваемых инструментальных цепочек IAR и Neusoft Reach подписали стратегическое соглашение: акцент на глубокой интеграции NeuSAR OS с инструментами разработки IAR, предоставление комплексного решения из программного обеспечения и инструментальной цепочки для отечественных сценариев разработки, продвижение интеграции экосистемы ПО AUTOSAR с автомобильными RISC-V чипами; стороны совместно создадут полную инструментальную цепочку, охватывающую «чип — базовое ПО — разработка приложений», закрывая пробел в инструментальной цепочке для автомобильной разработки на RISC-V и ускоряя её масштабное развёртывание в автомобильной отрасли. Примечание: подписание 08-20, сообщения 08-24/25 попадают в данное окно, включено впервые; Neusoft Reach — основной производитель отечественного автомобильного базового ПО NeuSAR, IAR ранее уже поддерживал автомобильные ядра SiFive E7A/S7A.

2.3 Andes D23-SE получил сертификацию функциональной безопасности ISO 26262 ASIL-B/ASIL-D (сообщение 08-24)

Дата: сообщение от 2026-08-24 (New Electronics 18:42 пекинское время; анонс производителя 08-18)　Источники: New Electronics, andestech.com

Процессор AndesCore D23-SE получил сертификацию функциональной безопасности ISO 26262 по двум уровням ASIL-B и ASIL-D (процесс разработки соответствует частям 2/4/5/7/8). D23-SE представляет собой ориентированное на энергоэффективность безопасное ядро с трёхступенчатым конвейером и частичным двойным выпуском, охватывающее сценарии ECU/DCU, такие как антиблокировочная тормозная система, контроль давления в шинах, подушки безопасности, управление приводом двигателя; сертификация позволяет ему вместе с N25F-SE/D25F-SE/D45-SE составить полный набор автомобильных безопасных ядер Andes. Примечание: анонс производителя 08-18 (вне окна), в данном окне учтено сообщение New Electronics, включено впервые.

2.4 LilyGo T-Display K230 Kit: Tech Times сообщает, что текущая Ubuntu не запускается (08-24/25)

Дата: 2026-08-24/25 (Tech Times 08-25 03:48 пекинское время)　Источники: Tech Times (gnews)

Tech Times сообщает, что «RISC-V AI карманный компьютер не поддерживается текущей Ubuntu» — LilyGo T-Display K230 Kit (CoreSet около 150 долларов, двухъядерный RISC-V Kendryte K230 + сопроцессор ESP32-S3-R8, клавиатура и LoRa опционально). Это вторичное распространение события от 08-21, новые детали: текущие дистрибутивы Ubuntu не могут работать на нём (требуется специализированный образ Linux/RTOS), что подтверждает, что поддержка дистрибутивов для оконечных RISC-V терминалов остаётся слабым местом, и является предметом дальнейшего наблюдения за этой продуктовой линейкой (в контрасте с серверной стороной в разделе 2.1 «Ubuntu/RHEL из коробки»).

3.1 XiangShan: исправления COVE/MPT продолжают сходиться, многолинейное продвижение по производительности и подсистеме памяти (08-24~25)

Дата: 2026-08-24 10:19 ~ 08-25 07:12 пекинское время (время committer), 19 коммитов в окне　Источники: OpenXiangShan/XiangShan, поиск коммитов GitHub

В окне 19 коммитов в основном репозитории XiangShan и сопутствующих репозиториях, сгруппированы по направлениям:

  • Сходимость конфиденциальных вычислений COVE: fix(MMU, COVE): fix mpt walker bug, pre-flush transaction not properly cleaned (#6314) — исправлена проблема неправильной очистки pre-flush транзакции MPT walker; fix(mpt): correct mfence operand decoding (#6400) — исправлено декодирование операнда mfence. Продолжение линии CoVE/MPT (таблица защиты памяти) из отчёта 08-24, реализация вступила в фазу детальной сходимости;
  • Верификация матричного расширения AME: feat(ame): add mcfg state comparison to DiffTest (#944) — добавлено сравнение состояния конфигурации матрицы AME для дифференциального тестирования, система верификации матричного расширения усилена;
  • Память и производительность: feat(extLLC): support external LLC to v3 (#6384), feat(openLLC): enlarge openLLC to 32MB (#6401) (открытый LLC расширен с 16MB до 32MB), feat(prefetch): add L3 prefetch path for stash prefetch (#6274), feat(MMU): improve performance counters (#6383);
  • Верификация/инженерия: перенос difftest v2→v3 (#6387), совместимость синтаксиса globalmem с C++11, запись времени сборки GSIM и т.д.

Значение: XiangShan переходит от «функциональной отладки» к этапу двойного продвижения «завершение производительности + сходимость конфиденциальных вычислений»; расширение LLC и L3 prefetch, счётчики производительности MMU и другие работы показывают, что оптимизация производительности является текущим основным ритмом, одновременно продвигается верификация матричного расширения AME.

3.2 SpacemiT: новый API видеодекодирования и обновление документации инструментов разработки (08-24)

Дата: 2026-08-24　Источники: spacemit-com/mpp, spacemit-com/docs-chip, spacemit-com/docs-tool

6 коммитов в окне: в репозитории mpp (платформа обработки медиа) добавлен API извлечения последнего кадра видеодекодера (vdec извлекает последний кадр, что полезно для сценариев видео с низкой задержкой/машинного зрения); в docs-chip обновлён диапазон рабочих температур модуля P3 (#205); в docs-tool обновлены двуязычное руководство и скриншоты инструмента разработки Spacemit Studio (#44/#45). В целом — рутинная доводка драйверов и документации, без крупных действий в основной линии ядра; наблюдение за экосистемой K1/K3 ведётся по официальной основной линии и экосистеме операторов.

3.3 ESWIN Computing: в раскрытии гонконгского IPO накопленный убыток превысил 5,2 млрд юаней (08-25)

Дата: 2026-08-25 (Sohu Finance 08:20 пекинское время, конец окна)　Источники: Sohu Finance (gnews)

Согласно данным, раскрытым в проспекте эмиссии со ссылкой на Sohu Finance: у ESWIN Computing совокупный убыток превысил 5,2 млрд юаней, доля выручки от пяти крупнейших клиентов превышает 80% (в 2022/2023/2024 годах — 88,7%/90,7%/88,5% соответственно), цена ключевого продукта снижается; компания продвигает IPO на гонконгской бирже. ESWIN Computing — ведущая китайская компания по проектированию RISC-V чипов (на базе архитектуры RISC-V, бизнес охватывает два направления: интеллектуальные терминалы и interconnect computing, последнее ориентировано на автомобили, роботов и промышленные сценарии); её темпы коммерциализации и концентрация клиентов являются важным образцом для наблюдения за моделью прибыльности ведущих китайских RISC-V компаний. Примечание: данные взяты из сообщений СМИ и резюме проспекта эмиссии, приоритет имеют официальные раскрытые документы; время публикации сообщения находится в конце данного окна мониторинга, событие включено в рамках окна.

  • Полуфинал конкурса HICOOL 2026 RISC-V+AI на синергию инноваций успешно прошёл в Пекинском Ичжуане (официальный репортаж ncsti.gov.cn от 08-24; старт 08-21, победители выйдут в финал) — продолжение плотного ритма китайских соревнований и промышленной организации вокруг RISC-V+AI за последние две недели (форум Dishui Lake, Нанкинский альянс RISC-V на синергию инноваций, серия HICOOL).

4.1 Нет новых специализированных новостей: наблюдение за периферийными вычислениями и робототехническими сценариями продолжается (08-24)

5. Итоги и обзор тенденций

  1. Переход RISC-V в серверный сегмент вступает в фазу «поставок реального оборудования»: лимитированный запас стоечных серверов BigSky 2U + фактический запуск CUDA (в качестве головного узла для нагрузки LLM на NVIDIA GPU) + дорожная карта NVLink Fusion, в сочетании с расширением серверных возможностей Linux 7.3 (маркировка QoS/делегирование счётчиков/CFI) и продвижением стандартизации ISO — программный стек «последней мили» для центров обработки данных интенсивно достраивается;
  2. Поддержка NVIDIA CUDA — от заявления 2025 года до уточнения технических требований на Hot Chips 2026 (RVA23, согласованность PCIe, P2P): «серверный CPU + платформа» — жёсткий порог, что напрямую благоприятствует экосистеме высокопроизводительных ядер класса P870-D и серверным спецификациям RVA23;
  3. Внутренняя дифференциация сохраняется: XiangShan продвигается по двум направлениям (сходимость COVE + доработка производительности/памяти, 19 коммитов, наиболее активный в окне мониторинга); Jindie Shikong — рутинные работы с драйверами/документацией; ES Win Computing — раскрытие в рамках IPO на гонконгской бирже накопленного убытка свыше 5,2 млрд юаней и высокой концентрации клиентов — давление коммерциализации на ведущих китайских разработчиков RISC-V становится явным и требует постоянного отслеживания;
  4. Усиление автомобильной экосистемы: сотрудничество IAR×Neusoft Reach по инструментальной цепочке, сертификация Andes D23-SE ASIL-B/D, плюс ES Win EAI8800 (двойная сертификация в июле) — цепочка «IP — инструментальная цепочка — базовое ПО — чип» для автомобильного RISC-V постепенно замыкается, миграция экосистемы AUTOSAR на RISC-V ускоряется;
  5. Рост активности на стороне открытого исходного кода: CPython tier 3, включение множества расширений в Linux 7.3, рост обсуждений CUDA-on-RISC-V на HN (68 баллов) — контраст с относительным затишьем последних двух дней; официальная поддержка Python восполняет ключевое звено программного стека AI.

Ограничения: данные о производительности BigSky и детали запуска CUDA основаны на пресс-релизах производителя, независимых оценок пока нет; финансовые данные ES Win Computing взяты из сообщений СМИ и выдержек из проспекта эмиссии, приоритет имеют официальные документы раскрытия; страница ISO/IEC DIS 26791-1 защищена от парсинга и не может быть получена напрямую, конкретный технический охват определяется официальным сайтом ISO; содержание коммитов XiangShan определяется по commit message, без деталей микроархитектурной верификации; подписание IAR×Neusoft Reach — событие 08-20, попавшее в окно мониторинга через сообщения, само событие произошло вне окна.
