Главное за сегодня: полный стек Agent на стороне устройства от SpacemiT массово опубликован: выпуск 1.0Beta1 для BiBit GUI и голосового сервиса, компоненты Bianbu AgentOS открыты

Дата: 2026-10-14　Источник: bibit Release 1.0Beta1 (10-14), bibit-voice Release 1.0Beta1 (10-14), первичный импорт bianbu-agent-runtime (10-14), первичный публичный снимок bianbu-agent-memory (10-14)

Продолжая массовое создание репозиториев 10-13 (о чём сообщалось в прошлом ежедневном отчёте), SpacemiT в течение окна вывела системный программный стек Agent на стороне устройства (Bianbu AgentOS) в целом в публичное пространство: настольный BiBit GUI и офлайн-голосовой сервис Bibit Voice выпущены как 1.0Beta1, а runtime Agent, сервис памяти, компоненты безопасности и другие массово открыты. Ключевые моменты:

  • BiBit GUI (1.0Beta1): десктопный фронтенд для ассистента системы Agent, использующий в качестве основы кода открытый проект Jan (React 19 + Tauri 2 + Rust, цепочка сборки Yarn 4.5.3); в настоящее время сохраняет и развивает диалоговое взаимодействие, расширенные сообщения, вложения, историю сессий и интерфейс настроек; для Bianbu 4.x riscv64 предоставляется нативный пакет Debian (версия Yarn фиксируется в исходном коде для адаптации к ограничениям памяти сборочных машин RISC-V); Agent Runtime пока использует реализацию, совместимую с Jan, в дальнейшем через Adapter будет подключён к официальному рантайму.
  • bianbu-agent-runtime (первоначальный открытый исходный код): сервис Agent с конфигурацией на основе YAML, описывающий себя как ядро рантайма Bianbu AgentOS — сессия как поток событий (единая проекция для нескольких устройств), плагины могут предоставлять страницы Tool/Skill/Hook/MCP/Console, границы безопасности, такие как подписанный манифест securityd и одобрение Tool (в production-режиме fail-closed); в настоящее время поддерживается только K3 (riscv64, Bianbu 4.0).
  • bianbu-agent-memory: сервис памяти на стороне устройства с приоритетом локальности (демон на Rust + Python SDK + протокол Unix socket) — три уровня: события сессий L1 / рабочие сводки L2 / долговременная память L3, локальный полнотекстовый поиск, шифрование SQLCipher, обнаружение конфликтов версий и изоляция пространств имён; предоставляет CLI, сервис MCP и Runtime Bridge, а также содержит адаптеры Hermes и DeepSeek Harness.
  • Bibit Voice (1.0Beta1): стек офлайн-голосовых сервисов для K3/Bianbu Desktop — обнаружение ключевого слова (KWS), обнаружение голосовой активности (VAD) и распознавание речи (ASR, SenseVoice/Qwen3-ASR), на основе захвата PipeWire и sherpa-onnx SpacemiT runtime; предоставляет внешние два уровня Unix socket и MCP (8 инструментов); звук ответа на пробуждение «я здесь» распространяется вместе с пакетом.
  • Компоненты, открытые в той же партии: bibit-intent (маршрутизация намерений с приоритетом периферии и выполнение инструментов), bibit-filesearch (сервис локального поиска файлов), bibit-runtime-plugin, bianbu-agent-security первоначально опубликованы; кроме того, библиотека обработки медиа mpp переведена на лицензию MIT с унификацией заявления об авторских правах, в ai-sdk добавлен подмодуль KWS и архитектурные схемы на китайском и английском, в docs-product добавлен каркас страниц продуктов серии V100 (C2201/S5236/G5201).

Указанные компоненты вместе с аппаратным обеспечением K3 и дистрибутивом Bianbu образуют вертикальную комбинацию «чип—система—рантайм Agent»; маршрут Bianbu AgentOS, при котором сначала проводится проверка на единой платформе (K3), а затем расширение на другие платформы, уже достаточно ясен.

1. Открытое сообщество и программная экосистема

1.1 Патч ядра Linux делает «соответствие данной машины RVA23» доступным для проверки одним действием

Дата: 2026-10-14　Источники: Phoronix: Linux Finally Making It Easier To Answer The Question: “Is This RISC-V System RVA23?” (10-14), материалы доклада LPC 2026 «RVA23 in practice» (10-02)

Phoronix сообщает: пользователи Linux вскоре смогут «одним действием» ответить на вопрос «соответствует ли моя система RISC-V требованиям RVA23» — патч ядра, ожидающий включения, предоставляет возможность однократного запроса (в текущем состоянии требуется объединять /proc/cpuinfo, hwprobe и требования профиля и сравнивать их по пунктам; инструменты на стороне Ubuntu ранее могли выдать лишь «probably RVA23»). Иллюстрация в материале — это скриншот отчёта RVA23 для SpacemiT K3. Контекст (связь с предыдущими материалами этой серии): эта возможность и есть **однобитная схема riscv_hwprobe, раскрытая на LPC26 (KEY_BASE_BEHAVIOR: IMA RVA23U64, однократный расчёт при загрузке из полной битовой карты ISA)** — серия патчей была инициирована как RFC Andrew Jones, теперь продвигается Гоудон Сюем (Guodong Xu), 10-09 достигла v8 (из 11 патчей первые 8 включены в riscv/for-next), в v9 будут добавлены классификационные биты RVA22/RVA20. Профиль RVA23 имеет большое значение для унифицированного распространения современных бинарных файлов RISC-V (современные версии Ubuntu уже сделали его базовым, соответствующего требованиям оборудования пока мало).

1.2 Проект RISE выпустил результаты векторизованной оптимизации RVV для SpeexDSP: ускорение ресемплинга до 4,88 раза

Дата: 2026-10-13~10-14　Источники: RISE Project: Accelerating Audio Processing with SpeexDSP Optimizations for RISC-V (10-13), обсуждение на Hacker News (10-14)

Проект RISE (экосистема программного обеспечения RISC-V) опубликовал итоговые результаты RP020: для базовой библиотеки аудиообработки в реальном времени SpeexDSP (ресемплинг аудио, эхоподавление, джиттер-буфер и предварительная обработка; широко используется в VLC, Firefox, Wireshark, PulseAudio, Mumble и др.) внедрён написанный вручную ассемблер RVV, а также модернизирована инфраструктура сборки и верификации. Ключевые моменты:

  • Производительность: ядро векторного ресемплинга, написанное вручную, в сравнении с «автоматически векторизованным компилятором C» — ядро с плавающей точкой ускорено в 3,71 раза (Clang 18) / 3,59 раза (GCC 13); ядро с фиксированной точкой — в 2,69 раза (Clang 18) / 4,88 раза (GCC 13) (в последнем случае GCC не смог выполнить автоматическую векторизацию).
  • Кросс-аппаратная верификация: благодаря свойству RVV, не зависящему от длины, один и тот же ассемблерный код эффективен на двух типах физических платформ — SpacemiT K1 (VLEN=256) и Canaan K230 (VLEN=128).
  • Побочная выгода от инфраструктуры верификации: проверка Meson + Checkasm попутно выявила и исправила дефект зависимости данных в ядре SSE2, существовавший 8 лет (ядро скалярного произведения ранее было медленнее даже скалярного C в 0,58~0,75 раза).
  • Форма организации: продвигается инженерами Google в сотрудничестве с RISE (технический руководитель Nathan Egge, подрядчик FFlabs / Tristan Matthews), RISE финансировал проект на 40 тыс. долларов США.

1.3 openRuyi: выпуск прошивки «Ruyi Firmware 20261014», выбор режима двухкластерного CPU на K3 реализован

Дата: 2026-10-14　Источники: Ruyi Firmware 20261014 Release (10-14), edk2-ruyi: K3 persistent CPU selection modes (10-14), история коммитов openRuyi (10-14)

Линейка прошивок openRuyi выпустила «Ruyi Firmware 20261014», ключевая особенность которой — выбор режима кластера CPU на платформе K3: в UEFI Setup добавлен переключатель режима, настройка сохраняется в выделенном секторе SPI и считывается coreboot до запуска OpenSBI (вступает в силу при следующей загрузке, при обновлении прошивки восстанавливается значение по умолчанию); предусмотрены три режима — X100 only (по умолчанию, 8 ядер, RVV VLEN 256, сохраняется расширение H), X100 + A100 (16 ядер), A100 only (8 ядер, VLEN 1024) — и отображается в таких утилитах, как fastfetch, в виде k3 / k3-x100-a100 / k3-a100. Детали реализации: загрузка в режиме A100-only через SBI HSM передаёт SEC от hart 0 к hart 8 (ожидание остановки исходного hart с последующим переиспользованием стека), в дереве передачи UEFI узел X100 отключается, но физическая нумерация слотов IMSIC сохраняется; совместимая строка корня дерева устройств синхронно отражает режим для именования в пользовательском пространстве (без необходимости изменения исходного кода Linux). В основном репозитории синхронно включены обновление Mesa 26.2.4 и обратный перенос оптимизаций PowerVR (pvr), обновления SPECS, включая рекомендацию mesa-vulkan-drivers для mesa-gallium; на странице новостей официального сайта openRuyi новых версий пока нет (последняя по-прежнему 2026.09).

3.2 ESWIN Computing: открытый репозиторий тестовых векторов BF16 GEMM для расширения матриц RISC-V (AME)

Дата: 2026-10-13~10-14　Источники: eswincomputing/riscv-matrix-gemm-vectors (обновление 10-14), коммит обновления (10-14)

ESWIN Computing открыла репозиторий riscv-matrix-gemm-vectors (создан 10-13, 10-14 дополнен копирайтом и README): набор тестовых векторов матричного умножения-сложения BF16×BF16→FP32, ориентированный на предложение спецификации расширения матриц RISC-V (AME) v0.6.0 — каждый сценарий использования представляет собой bare-metal программу (выполняет операцию, самопроверяется и записывает вердикт), в комплекте — независимые от реализации эталонные значения и проверяющий результаты check.py. Вердикт выносится с использованием стандартной границы ошибки округления ( Ĉ−C* ≤ γ(G)·Σ a·b , по умолчанию G=K), а не побитового сравнения, чтобы учесть различия реализаций, допускаемые спецификацией при «неупорядоченном суммировании» (при взаимной компенсации положительных и отрицательных произведений корректный результат может отличаться от точной суммы на тысячи ULP); кроме того, предоставлены два сценария использования, в которых «все соответствующие требованиям реализации дают одинаковые биты результата», для выявления ошибочного округления. Эталонные значения и критерии не зависят от конкретного набора инструкций и могут быть переиспользованы в других реализациях расширения матриц, что представляет собой вклад китайского производителя в тестовую инфраструктуру для экосистемы AME.

4. Специальная глава о воплощённом интеллекте и робототехнике

4.1 Инфраструктура Agent на устройстве движется к «системному уровню упаковки»: наблюдение за комбинированной поставкой Bianbu AgentOS и K3

Дата: 2026-10-14　Источники: bianbu-agent-runtime (10-14), bibit-voice (10-14), репозитории организации spacemit-robotics

В этом окне основные наблюдения со стороны воплощённого интеллекта и робототехники сосредоточены на «системной упаковке инфраструктуры агентов на периферийных устройствах»: Jindie Space под именем Bianbu AgentOS открывает полную цепочку — настольный фронтенд (BiBit), среда исполнения, локальная память, офлайн-голос (KWS/VAD/ASR) и компоненты безопасности (см. сегодняшний фокус), при этом явно указывая K3 (riscv64) как первую и на данный момент единственную поддерживаемую платформу. Для роботов и периферийных устройств это означает, что «голосовое пробуждение — понимание намерения — выполнение инструментов — долговременная память — аудит безопасности» в виде самостоятельно развёртываемого открытого стека впервые получило на RISC-V полноценный комплектный образец, а не разрозненные SDK. В дополнение к этому, на аппаратной стороне выбор режима CPU-кластера K3 (X100/A100, см. 1.3) предоставляет опции на уровне прошивки для гетерогенного разделения труда «производительные ядра выполняют инференс, энергоэффективные ядра выполняют управление». Напротив, в окне специализированной робототехнической организации spacemit-robotics новых отправок нет (последние отправки периферийных библиотек IMU/моторов/восприятия — 10-12); комбинированная поставка «чип + программный стек агента + сценарная упаковка» продолжает углубляться, а программный стек движется от «работоспособности» к «сопровождаемости и аудируемости».

5. Итоги и наблюдения за трендами

  • Периферийные агенты становятся новой точкой фокуса программного стека RISC-V: Jindie Space централизованно публикует полный стек Bianbu AgentOS (GUI/среда исполнения/память/голос/безопасность), с K3 в качестве первой верификации — это контрастирует с «серверными» нарративами вроде Lanxin Computing, и на направлении инфраструктуры периферийных AI Agent у RISC-V появляется комплектный открытый стек.
  • Оба конца инфраструктуры усиливаются одновременно: запрос одного бита rva23u64 в ядре Linux близок к реализации (репортаж Phoronix; часть v8 уже вошла в riscv/for-next, v9 в пути), RISE добавляет в SpeexDSP написанное вручную векторное ядро RVV (ресемплинг до 4,88 раза) — две магистрали «квалификация (RVA23) + мультимедийная производительность (RVV)» продвигаются синхронно.
  • Неделя саммита приближается: предсаммитовые материалы RVSC2026 (10-18~20 Шэньчжэнь) — пресс-релизы, программа, план выставочного зала, параллельные мероприятия — полностью готовы, в дополнение к конференции разработчиков Jindie Space 10-17, GBA/HK Day 10-21, пекинскому семинару XuanTie 10-22; Ubuntu 26.10 с первыми официальными настольными образами RISC-V запланирован к выпуску 10-15 и станет ключевым объектом наблюдения в следующем выпуске.
  • Высокая плотность результатов на инженерной стороне в Китае: XuanTie от DAMO Academy добавляет векторные тесты BF16, Isilicon открывает исходные векторные тесты AME, XiangShan оптимизирует задержку доступа к L2 и исправляет ICache, SOPHGO рефакторит цепочку загрузки и серверную прошивку, Sipeed выпускает подряд две версии SLogic.
  • Пояснение об ограничениях: основной текст Phoronix ограничен защитой сайта, пункт 1.1 составлен на основе его RSS-аннотации и публичных материалов LPC26 путём перекрёстной сверки; часть информации по пункту RVSC2026 взята с официального сайта саммита и из аккаунтов WeChat, приоритет — за официальными публикациями; детали определения соответствия репозитория тестовых векторов Isilicon — согласно его README.
