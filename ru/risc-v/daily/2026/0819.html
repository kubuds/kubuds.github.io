Ежедневный отчёт RISC-V (2026-08-19)

2026-08-19 Kubuds

Окно мониторинга: последние 24 часа (2026-08-18 08:20 ~ 2026-08-19 08:20 пекинское время) Источники: HN (Algolia API), агрегация Google News RSS (английский + китайский, через прокси), CNX/LinuxGizmos/Phoronix/riscv.org RSS, GitHub API (официальная организация riscv/Сяншань/PingTouGe/Jindie Shikong/Suaneng/Espressif/Nuclei/ESWIN), прямая выборка с оригинальных сайтов Wccftech/The Register (подробности в приложении)

1. Динамика сообщества открытого исходного кода, ядра и версий

1.1 HAC: четвёртый день интенсивных правок спецификации высоконадёжной криптографии — предложение о переименовании Zl→Zkl, правила WARL, интеграция Smacestatus (30+ коммитов)

Дата: 2026-08-18 (12:05 ~ 22:26 пекинское время)　Источник: riscv/riscv-high-assurance-cryptography GitHub

В репозиторий высоконадёжной криптографии (HAC, спецификация криптографических расширений для реализаций уровня FIPS 140-3) в течение окна мониторинга было слито 30+ коммитов, что продолжает основную линию сходимости ревью предыдущих трёх дней и переходит в фазу «завершение именования и структуры»:

  • Финализация именования: Changed Zl extension prefix to Zkl (переименование префикса Zl в Zkl), Added proposal for ratified names (предложение об утверждённых именах), Fixed Zlkn dependencies, Reformatted new names table — именование расширений переходит от рабочих имён к утверждённым;
  • Финализация семантики: Defined WARL rules for aceiobuflen, aceiobuftop and acestart (правила WARL для трёх ключевых CSR), Clarify invalid aceiobuftop exception behavior (поведение исключения при недопустимом aceiobuftop), Integrate mcrstatus CSR into Smacestatus extension (объединение mcrstatus в расширение Smacestatus), Clarify vector I/O replacement rules, Default CSR values out of reset (значения по умолчанию после сброса);
  • Реорганизация структуры документа: примеры псевдокода перенесены в Book 4, определение операций над конечными полями перемещено, несколько последовательных правок ace-introduction.

За четыре дня в сумме 80+ правок, что указывает на то, что HAC продвигается от «определения функций» к фазе «замораживания именования + завершения семантики», приближаясь к официальному ревью/утверждению, полностью совпадая с основной линией безопасности/криптографии RISC-V на этой неделе (статья о Spectre, SPMP, riscv-security-model).

  • Новый коммит за день: perf(btb): update btb replacer using training touch strategy instead of prediction touch strategy — заменитель BTB переведён на стратегию «тренировочного касания» вместо стратегии «предсказательного касания», что является оптимизацией алгоритма замены на уровне буфера целевых адресов переходов;
  • Основная линия рефакторинга: refactor(pc): add Pc class to replace PrunedAddr(VAddrBits) + docs(Pc): add scaladoc + feat(PrunedAddr): add a strict mode — пакет рефакторинга представления PC фронтенда с миграцией от PrunedAddr к новому классу Pc;

1.3 riscv-unified-db: два исправления семантики инструкций: разрядность векторных CSR, регистровый файл для сжатых FP-обращений к памяти

Дата: 2026-08-18 16:25 ~ 16:44 (пекинское время)　Источник: riscv/riscv-unified-db GitHub

В официальную единую базу инструкций RISC-V (unified-db) в окне мониторинга вошли два исправления на уровне семантики:

  • fix(csr): seven vector CSRs take XLEN, not MXLEN (#2489) — семь векторных CSR (vstart/vxsat/vxrm/vcsr/vlenb/vtype и др.) принимают XLEN, а не MXLEN;
  • fix(isa): compressed FP load/stores must use the float register file (#2491) — сжатые инструкции загрузки/сохранения с плавающей точкой должны использовать регистровый файл чисел с плавающей точкой.

UDB, будучи единым машиночитаемым источником семантики инструкций для arch-test, Sail и других инструментальных цепочек, — подобные низкоуровневые исправления напрямую влияют на корректность тестирования и симуляции и относятся к обслуживанию уровня «инфраструктуры спецификаций» (третий день подряд фиксируется подобная динамика).

Дата: 2026-08-18 21:18 (пекинское время)　Источник: riscv/riscv-isa-manual GitHub

В официальное руководство ISA вошёл коммит Clarify that MXR doesn't affect M-mode pointer masking (#3318): бит MXR (разрешение выполнения чтения) не действует на преобразование адресов при маскировании указателей в M-режиме (Smmpm); это уточнение семантики взаимодействия расширения маскирования указателей с привилегированными режимами; также присутствует рутинное обслуживание Update marchid contact for Coreblocks (#3190). 2. Продукты и экосистема

2.1 Главное: T-Head официально объявила, что XuanTie C950 нативно запускает Qwen-3.8 27B — момент «Day 0» для инференса больших моделей на RISC-V

Дата: 2026-08-18 (Wccftech сообщил 08-19 00:10 пекинское время)　Источник: Wccftech

T-Head Xuantie RISC-V команда Alibaba официально объявила, что её флагманский RISC-V чип XuanTie C950 обеспечивает Day 0 (поддержка с момента выпуска) нативный инференс для новейшей открытой модели Qwen-3.8 27B; конкретные показатели: 64-ядерный C950 (с векторным расширением RVV) — скорость декодирования 30 tokens/s, задержка первого токена (TTFT) всего 1,9 секунды. Ключевые моменты:

  • Предыстория чипа: C950 выпущен в марте 2026 года, позиционируется как «серверный RISC-V процессор для периферийного AI» — 64 вычислительных ядра на одном чипе, частота до 3,20 ГГц, выполняет AI-нагрузки без опоры на GPU; оснащён стандартным L1, гибко конфигурируемым L2, опциональным разделяемым L3, с аппаратным интеллектуальным предварительным выбором данных. Производство TSMC 5 нм (по данным Wccftech).
  • Предыстория модели: Qwen-3.8 27B — открытая весовая модель с 27 млрд параметров; по официальным заявлениям, способности к кодированию сопоставимы с Opus 4.5, может работать на одном MacBook (32 ГБ памяти) — относится к «среднеразмерным высокоэффективным по цене» моделям инференса.
  • Стратегическое значение: это очередной шаг Alibaba в стратегии «вертикальной интеграции в стиле Nvidia» — собственная оптимизация Day 0 для собственного чипа и собственной модели, образующая замкнутый цикл «модель — чип — облако»; C950 может комбинироваться с её датацентровыми AI-ускорителями для распределения нагрузки инференса.

Это один из наиболее знаковых прорывов лагеря RISC-V в направлении «инференс больших моделей на устройствах/периферии» в 2026 году: ранее демонстрации больших моделей на RISC-V в основном ограничивались малыми моделями или квантизацией с дистилляцией, тогда как C950 на 64-ядерном RVV достигает пригодной для использования пропускной способности при запуске модели уровня 27B, что подтверждает осуществимость маршрута «многоядерность RISC-V + векторные расширения» в сценариях инференса (подробнее см. углублённый анализ T-Head в разделе 3.1).

2.2 Проект Xen учреждает комитет по безопасности (учредители AMD/EPAM/Renesas), продвигая полноценный релиз RISC-V

Дата: 2026-08-18 10:59 (пекинское время)　Источник: The Register

Проект открытого гипервизора Xen учредил Safety Committee (комитет по безопасности), среди членов-учредителей — AMD, EPAM, Renesas; цель — привести Xen в соответствие с формальными стандартами функциональной безопасности, такими как IEC-61508, для сценариев изоляции рабочих нагрузок в автомобилях, робототехнике и т. п. («разделение мозга робота»). Одновременно введён новый уровень членства Premier Plus, ориентированный на организации, стремящиеся к сертификации функциональной безопасности. Boeing недавно присоединилась к проекту Xen, и, по сведениям The Register, её интерес как раз связан с работами по безопасности. Связь с RISC-V: обновление Xen, выпущенное в начале месяца, «продвинуло работу над полнофункциональным релизом для процессоров RISC-V» — Xen on RISC-V ещё на шаг ближе к полной готовности. Функциональная безопасность слоя виртуализации (изоляция, разделение, сертификация) напрямую связана с внедрением RISC-V в автомобилях и робототехнике и заслуживает отслеживания.

4. Специальный раздел по ключевым направлениям: воплощённый интеллект и робототехника

4.1 Безопасная виртуализация выходит на сцену: комитет по безопасности Xen нацелен на «изоляцию рабочих нагрузок роботов»

Проект Xen учредил комитет по безопасности (члены-основатели AMD/EPAM/Renesas) и продвигает соответствие IEC-61508, явно указав «роботов» как целевой сценарий изоляции рабочих нагрузок — «разделённый мозг робота» означает, что изолированное выполнение смешанных критически важных нагрузок, таких как управление в реальном времени, навигация и восприятие, на одном и том же оборудовании становится сертифицируемым путём. Значение для воплощённого интеллекта на RISC-V: поддержка RISC-V в Xen продвигается к «полнофункциональному релизу»; если уровень виртуализации с сертификацией безопасности для автомобильной/робототехнической области будет реализован на RISC-V, это дополнит третий тип изоляции помимо двухъядерной гетерогенности «ядро реального времени + прикладное ядро» (маршрут форума Dishui Lake) — разделение на уровне виртуальных машин. Комбинация Renesas (ведущий поставщик автомобильных MCU) + AMD также намекает на мультиархитектурное позиционирование этого комитета.

4.2 C950 запускает модель 27B: потенциал воплощённого интеллекта для инференса больших моделей на периферии RISC-V

C950 (64 ядра RVV, 3.2 ГГц, 30 tok/s) подтвердил применимость маршрута RISC-V «многоядерность + векторы» для инференса моделей уровня 27B. Для воплощённого интеллекта инференс больших моделей на устройстве/периферии — ключевое звено «подъёма мозга наверх»: если модель VLA (зрение-язык-действие) сможет достичь приемлемой пропускной способности на платформе RISC-V, это снизит зависимость всего устройства от GPU. Хотя C950 в настоящее время позиционируется как периферийный сервер, а не встраиваемое решение (по энергопотреблению/размеру всё ещё далеко от развёртывания непосредственно в корпусе робота), это знаковый шаг «RISC-V запускает большие модели» от демонстрации к продукту, предоставляющий базовые данные (30 tok/s / 1.9 с TTFT можно использовать как систему отсчёта для аналогичных решений) для последующего спуска чипов среднего размера.

4.3 Обновление стека «восприятие-решение-управление движением» у Jindie

model-zoo-vision добавил детектор DEIMv2 COCO (направление обнаружения в реальном времени), исправление сборки Eigen в model_zoo_rl вошло в основную ветку — среда выполнения K3 humanoid RL и библиотека визуальных моделей Jindie Space продолжают продвигаться по двум линиям на этой неделе, что согласуется с их трёхуровневой компоновкой «восприятие (vision) - решение (RL) - управление движением (SPERT NPU)». Темп — уровень «поддержка + инкремент», крупных новых релизов нет.

5. Итоги и наблюдения за трендами

  1. Единственная крупная новость на новостной стороне: Pingtouge C950 нативно запускает Qwen-3.8 27B (64 ядра RVV, 30 tok/s, TTFT 1.9 с, поддержка Day 0) — один из наиболее практичных прогрессов RISC-V в направлении инференса больших моделей, нарратив вертикальной интеграции «чип-модель» реализован; в тот же день zero_stage_boot включает поддержку C920V5 — фокус Pingtouge на этой неделе ясен.
  2. Плотные правки спецификации HAC на четвёртый день (30+ коммитов) входят в фазу заморозки именования: предложение о переименовании Zl→Zkl, правила WARL, интеграция Smacestatus — ещё на шаг ближе к официальному ревью, официальная линия безопасности/криптографии RISC-V продолжает усиливаться.
  3. Пересечение безопасности и виртуализации набирает обороты: создание комитета по безопасности Xen (AMD/EPAM/Renesas, IEC-61508, разделение для роботов) + разъяснение указателей-масок в riscv-isa-manual + обновление riscv-security-model — «сертификация функциональной безопасности» становится следующим фокусом конкуренции в экосистеме RISC-V (автомобили/роботы/виртуализация).
  4. Основная ветка Xiangshan второй день подряд массово принимает изменения (13 коммитов: рефакторинг классов Pc, исправления TLB, замена политики тренировочных касаний BTB), темп разработки остаётся активным; семантические исправления unified-db появляются третий день подряд, интенсивность поддержки «инфраструктуры спецификаций» не снижается.
  5. Заметная дифференциация отечественных команд: Pingtouge (официальное объявление экосистемы C950 + стартовый код), Jindie (включение исправлений DEIMv2/RL), Sophon (итерация агентного инструментария) — продвижение по трём линиям; Espressif — рутинно, Nuclei/Eswin — тишина.

Оговорка об ограничениях: детали официального объявления C950 (характеристики чипа, техпроцесс, показатели) приведены по пересказу Wccftech, оригинал — цитата твита на платформе X, напрямую не подтверждено официальной страницей Alibaba (оригинал wccftech доступен); параметры самой модели Qwen-3.8 («сопоставима с Opus 4.5», «запускается на одном MacBook») — медийная формулировка; график «полного релиза» RISC-V в Xen не объявлен; содержимое включения sophon-tools — итерация внутреннего инструментария, оценка влияния на бизнес не проводилась.
