Главное за день: в tilelang-riscv смёржен #6, бэкенд RISC-V по умолчанию переведён на buddy-opt (11-16)

Дата: 2026-11-16　Источник: PR #6, merge-коммит 2204c7e

11-16 в 14:56 в tilelang-riscv смёржен #6 «Бэкенд RISC-V по умолчанию переведён на buddy-opt, добавлены два примера — BOSC и GEMM». 22 файла, +835 −284, два коммита: от 11-04 — «выбрать buddy-opt по умолчанию и разделить два корня инструментария», от 11-13 — «добавить примеры, поправить документацию». Это первое изменение репозитория после смёрженного 11-03 #5; в репозитории по-прежнему только одна ветка — main.

Скелет изменений находится в toolchain.py (+62 −4): у Buddy и LLVM есть собственные корневые каталоги инструментов, TILELANG_RISCV_OPT позволяет явно переопределить оптимизатор; выбор оптимизатора записывается в ключ кеша компиляции RISC-V (kernel_cache.py +4). Это практичнее, чем кажущееся «замена значения по умолчанию» — раньше после смены оптимизатора сохранялся риск попадания в старые артефакты кеша, теперь ключ кеша содержит оптимизатор, что превращает «какой набор инструментов используется» в индексируемое измерение сборки.

Добавлены примеры двух типов: examples/riscv/gemm — это FP16 GEMM на хост-машине (gemm.py +47), examples/riscv/bosc — набор самостоятельно собираемой прошивки BOSC INT8 GEMM (build.py +190, launch.c +122, env.sh и README). Наибольшие изменения в документации — в docs/get_started/BuildOnSG2044.md (+55 −178): пошаговые ручные операции заменены на переносимые пути и упрощённое использование. Тесты также дополнены тремя наборами: тесты набора инструментов +126 строк, тесты кеша компиляции +29 строк, тесты конвейера адаптации +45 строк — все в каталоге testing/python/riscv.

Главное за сегодня: triton и buddy в один день затронули набор инструментов, LLVM развязан и возвращён dump() (11-16)

Дата: 2026-11-16　Источники: triton-riscv PR #123, buddy-mlir PR #1062, triton-riscv PR #115

11-16 18:14 triton-riscv открыл #123 «развязать набор инструментов бэкенда от LLVM Triton». Проблема изложена в описании: бэкенд CPU не добавляет никакого C++ в libtriton.so, все pass идут через внешний процесс triton-shared-opt, но add_triton_plugin по-прежнему линкует библиотеки MLIR и их цепочку LLVM в libtriton.so, поэтому набор инструментов бэкенда может использовать только тот LLVM, с которым скомпилирован сам Triton. Решение — отключить TRITON_SHARED_BUILD_CPU_BACKEND, добавить llvm-hash.txt для отдельного закрепления пакета LLVM: libtriton.so использует LLVM, соответствующий исходникам Triton, triton-shared-opt собирается вместе с Triton, а buddy-opt／buddy-translate／buddy-llc／opt／llvm-objdump идут из релиза buddy, обмениваясь только текстовым IR. RISC-V +v и +xsmtime нужны только llc, поэтому LLVM, от которого зависит Triton, больше не обязан нести патчи RISC-V. Три файла, +16 −2; llvm-hash.txt пока закреплён на nightly/v0.1.4.dev20261103, кроме отсутствия одного плагина в libtriton.so, артефакты сборки не меняются.

Позже в тот же день (11-17 01:23) buddy-mlir открыл #1062 «Build LLVM with dump() support». Пакет LLVM собирается с -DLLVM_ENABLE_ASSERTIONS=OFF, а dump() в MLIR／LLVM определяется только при включённых утверждениях или LLVM_ENABLE_DUMP, поэтому у потребителей при вызове происходит ошибка линковки. В PR приведено подтверждение: mlir::Operation::dump() присутствует в пакете nightly/v0.1.4.dev20261103 и исчез в пакете nightly/v0.1.4.dev20261113. Triton — как раз такой потребитель: при включённом NDEBUG в заголовке нет даже объявления, а без него не линкуется. Патч добавляет только одну строку LLVM_ENABLE_DUMP=ON, сохраняя Release-сборку.

Обе вещи указывают на одно: пакет LLVM от buddy уже является по умолчанию вышестоящим для triton-riscv, и одна ночная замена пакета может заблокировать компиляцию у потребителей. Renovate #115 как раз закрепил зависимость на nightly/v0.1.4.dev20261113 (11-16 21:40 всё ещё обновляется); если #1062 не войдёт, этот гвоздь будет торчать постоянно.

2.1 openRuyi добавляет в Go 1.27 поддержку Zvk AES (11-16)

Дата: 2026-11-16　Источники: коммит 6592b995

16.11 14:21 в упаковочном репозитории появился коммит SPECS: go: Backport SHA-2 AES optimization, добавлен патч 1005-release-branch.go1.27-crypto-internal-fips140-aes-bl.patch (468 строк), в go.spec синхронно добавлены две строки. Пояснение написано прямо: перенести поддержку AES на основе Zvk из Go master в ветку релиза 1.27; автор коммита — Julian Zhu.

Zvk — это семейство векторных криптографических расширений RISC-V. Патч дополняет блочные процедуры crypto/internal/fips140/aes, позволяя AES на riscv64 использовать векторные инструкции вместо чисто скалярной реализации; включение зависит от обнаружения Zvk во время выполнения, ядра без этого расширения по-прежнему идут по исходному пути. На прошлой неделе упаковочный репозиторий только что поднял Go до 1.27.4 и дополнил более тридцати пакетов Go; этот коммит добавляет производительность после фиксации версии и относится ко второму слою — «сначала адаптация, затем оптимизация».

Дата: 2026-11-16　Источник: python-maturin 9d1e409e, mupdf 3d32c749, rpm-config e2baa296

rpm-config-openruyi (11:15, 16 строк) исправляет область действия макросов инструментальных цепочек: макрос суффикса версии изначально не был связан с семейством инструментальной цепочки, и установка номера версии для одной цепочки переименовывала команды другой — например, при указании основной версии 23 для clang набор команд GCC разворачивался в gcc-23. Подобные ошибки макросов не проявляются сразу, а становятся заметными, когда какой-либо пакет использует обе инструментальные цепочки одновременно.

3.1 +zvfbfmin стал обязательным элементом строки признаков по умолчанию (11-16)

Дата: 2026-11-16　Источник: PR #117

В описании #117 есть три граничных случая, которые стоит зафиксировать. Во-первых, без Zvfbfmin LLVM не понижает даже load и convert для масштабируемых bf16-векторов, и llc напрямую выдаёт Scalarization of scalable vectors is not supported. Во-вторых, lower-vir-to-vector из buddy-mlir сохраняет масштабируемые bf16-векторы и по умолчанию предполагает наличие Zvfbfmin у целевой платформы, поэтому при отсутствии этого расширения нижестоящий этап массово падает на стадии llc. В-третьих, после добавления преобразования идут через vfwcvtbf16.f.f.v и vfncvtbf16.f.f.w, то есть расширение и сужение между bf16 и fp32 передаются векторному блоку.

Поддерживаемые проектом цели RVV (SpacemiT K3, SOPHGO SG2044) несут это расширение; для ядер без него можно переопределить строку признаков по умолчанию через TRITON_RISCV_LLC_FEATURES. DEFAULT_MARCH не тронут, поскольку он управляет только шагом линковки GCC, а GNU as 2.42 не знает zvfbfmin — объекты, скомпилированные с +zvfbfmin, всё равно линкуются.

6. Наблюдения за трендами

6.1 Границы инструментальной цепочки перечерчены заново: один LLVM больше не покрывает всё

triton-riscv #123 и buddy-mlir #1062 — две стороны одного дня. Первый выносит инструментальную цепочку бэкенда из libtriton.so и отдельно фиксирует LLVM с помощью llvm-hash.txt; второй возвращает dump(), отключённый через LLVM_ENABLE_ASSERTIONS=OFF. Вместе эти два события показывают, что линия RuyiAI больше не предполагает «один LLVM на всё»: собственный экземпляр Triton, экземпляр в дистрибутиве buddy, экземпляр в бэкенде llc — каждый отвечает за свой участок, а интерфейсы сходятся к текстовому IR.

6.2 Выбор компилятора становится измерением сборки

tilelang-riscv #6 делает buddy-opt выбором по умолчанию и одновременно вписывает оптимизатор в ключ кэша. Это важнее, чем «сменить значение по умолчанию»: как только оптимизатор попадает в ключ кэша, артефакты одного и того же kernel под разными инструментальными цепочками не будут взаимно загрязняться, а переключение инструментальной цепочки превращается из «перебора переменных окружения методом проб и ошибок» в «явный параметр сборки». Добавленные в примеры BOSC и GEMM дают этой траектории две воспроизводимые точки приёмки.

6.3 Дистрибутив начинает осваивать RISC-V-специфичные расширения

Действия openRuyi на этой неделе сосредоточены на расширениях: Go получает обратную заливку Zvk AES, wheel-пакеты triton по умолчанию поставляются с +zvfbfmin, patchset и config ядра обновляются дважды за день. Всё это не относится к тому, что универсальный upstream может покрыть автоматически, — дистрибутив и мейнтейнеры инструментальной цепочки должны дополнять это по пунктам. После RVA23 точки дифференциации смещаются от «запустится ли вообще» к «можно ли использовать векторные и криптографические расширения».

6.4 Ежедневный информационный поток продолжает простаивать

Официальная главная страница не меняется, ruyiai-daily отсутствует девятый день, внешние новости не дают ни одного результата; все материалы этого выпуска взяты из коммитов и PR четырёх организаций GitHub и двух сообщений на форуме. В таком состоянии ценность суждений в отчёте определяется главным образом пониманием содержания коммитов, а не количеством новостей — особенно это касается официального релиза triton с пустыми примечаниями к выпуску, где остаётся только читать коммиты, на которые указывает tag.
