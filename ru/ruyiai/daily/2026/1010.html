Главное за сегодня: две линии синхронизации инструментальной цепочки — патч Triton-RISCV адаптирован к новому LLVM API (слит #86), ветка LLVM riscv завершила ещё один ночной прогон

Дата: 2026-10-09 ~ 2026-10-10　Источник: triton-riscv PR #86, коммит слияния e00fdd60, список коммитов ветки riscv в llvm-project, головной коммит 8f38c047, PR #25, PR #28

triton-riscv завершил первое с 09-14 (#81) слияние PR: контрибьютор trdthg 10-09 в полдень открыл и слил PR #86 «[patches] Support newer LLVM symbol and inline-asm APIs» (1 файл, +111 строк; от открытия до слияния около 20 минут). В основе — PR #84 обновления зависимости Buddy MLIR, поддерживаемый renovate: повышение buddy-compiler/buddy-mlir с nightly/v0.0.9 до nightly/v0.0.11, а v0.0.11 несёт более новую версию LLVM, чей MLIR API (например, интерфейсы символов и inline-asm) перестал быть совместим с Triton с зафиксированным фронтендом; CI для x64 и riscv64, а также для всех версий Python полностью падал на этапе сборки; #86 в форме патча добавляет поддержку новых LLVM-символов и API inline-asm, после слияния разблокировав ситуацию (#84 затем обновлён во второй половине того же дня и остаётся открытым в ожидании включения).

На стороне LLVM ветка riscv проекта llvm-project поздней ночью 10-09 завершила очередной полный повтор всего стека патчей: 26 локальных патчей были заново применены с новым временем коммиттера (пуш около пекинского времени 23:00), голова сохраняет #31 «A100 HP/SP и снижение pack/unpack со калибровкой планирования» (8f38c047); состав стека совпадает с предыдущим раундом (включая BOSC AME, Buckyball, снижение IME до A100 dot, расширения производителей вроде xtame и запись интеграции SyncBots). После завершения повтора время обновления двух PR бэкенда FPGA (#25 «BOSCAME FPGA backend», #28 «xboscame FPGA») обновилось в 10-10 00:53, ожидая продвижения ревью на новой базовой линии.

Ключевые выводы: в данном окне две линии сопровождения инструментальных цепочек заняли свои позиции — на стороне LLVM выполнен ночной повтор, на стороне Triton завершена патч-адаптация к новому LLVM API; вместе они образуют инженерию стабильности стека компиляции RISC-V AI под быстро эволюционирующим апстримом LLVM — «повтор — адаптация — канал сборки». Это слияние в тот же день было включено в выпуск ruyiai-daily от 10-10 с комментарием, что оно «непосредственно затрагивает цепочку сборки Triton→Buddy/MLIR в RuyiAI, устраняя несовместимость интерфейсов после обновления LLVM».

5. Наблюдения за тенденциями

5.1 Замкнутый цикл синхронизации инструментальной цепочки: от развития апстрима до патчей и каналов

Ключевое наблюдение данного окна мониторинга сосредоточено на замкнутом цикле «развитие апстрима — локальные патчи — каналы сборки»: на фоне быстрой итерации апстрима LLVM ветка riscv поддерживает синхронизацию базовой линии через ночной реплей; на стороне Triton патч #86 усваивает изменения API нового LLVM, расчищая путь для обновления зависимостей Buddy MLIR v0.0.11. Дальнейшие точки наблюдения: когда #84 (Buddy v0.0.11) будет влит в основную ветку и попадёт в ночной канал; прогресс ревью #85 (оптимизация softmax / matmul сообщества); результаты ревью двух PR бэкенда FPGA (#25 / #28) на новой базовой линии.

5.2 Ритм последующих партий расширения упаковки и точки наблюдения месячного выпуска

Вслед за одной партией из 31 коммита по экосистеме Go за один день 10-08, openRuyi 10-09 добавил ещё 13 SPECS модулей Go (включая franz-go, OpenTelemetry profiling, Jaeger IDL, OpenAPI Alibaba Cloud и др.); цепочка зависимостей облачно-нативных и наблюдаемых компонентов продолжает пополняться, продолжая расширение упаковки после выпуска 2026.09. Точки наблюдения: войдут ли эти две партии зависимостей в базовую линию сборки с началом цикла месячного выпуска 2026.10.

5.3 Двухвыпускная рассылка аналитики и период восстановления сообщества

ruyiai-daily в ежедневном ритме выпустил подряд два выпуска — 10-09 / 10-10, причём triton-riscv #86 был влит в тот же день и в тот же день включён в отчёт; связка между аналитикой и разработкой остаётся эффективной; напротив, на стороне сообщества (форум, двухнедельный отчёт) после праздников по случаю Дня образования КНР ещё не вернулись к предпраздничному ритму — в окне форума ноль новых постов, двухнедельный отчёт остановился на выпуске 077; его прогресс восстановления (выпуск 078 и серия информационных постов) — точка наблюдения на следующую неделю.
