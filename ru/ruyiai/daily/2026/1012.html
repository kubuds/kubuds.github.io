Главное за сегодня: расширение матрицы и синхронизация стека наступают по трём направлениям — Ztt одним пакетом 51 коммит, полная пересборка стека riscv в PyTorch (23 коммита), обновление зависимостей triton-riscv #84 влито

Дата: 2026-10-10 ~ 2026-10-11　Источник: список коммитов riscv-gcc ztt-dev, головной коммит a326bc3, список коммитов ветки riscv в pytorch, головной коммит 0fc3546d, triton-riscv PR #84

Развитие линии бэкенда GCC для матричных расширений на этой неделе продвинулось ещё дальше: контрибьютор pz9115 11 октября днём (13:50) одним пакетом отправил 51 коммит Ztt в ветку ztt-dev репозитория riscv-gcc — это крупнейший пакет для этой ветки с момента её создания 30 сентября (больше пакета из 36 коммитов от 8 октября). Ztt — это черновой набор инструкций для матричных расширений RISC-V, представляющий собой развитие инструментальной цепочки GCC от RuyiAI в дополнение к линии BOSC AME / A100 на стороне LLVM. Этот пакет посвящён систематической тонкой доработке инфраструктуры бэкенда Ztt: всестороннее переиспользование и кэширование системы дескрипторов (TC / ACC / zip / строка-столбец / конструкторы и consumer, состояние унарных операндов), индексированный поиск и регистрация (декодер builtin, объявления store, кандидаты перегрузок, поиск profile и типов, имена datatype и ключи регистрации), упрощения нулевых значений и узких носителей (нулевой регистр для скалярных / управляющих входов, узкие скалярные носители Ztt, свёртка сдвига с плавающим нулевым смещением), распространение дескрипторов по рёбрам ветвлений и fallthrough, очистка дескрипторов после DCE, факторизация вычисления динамического рабочего пространства, а также обновление проверок LTO dump и проверок оптимизированных инструкций. Все 51 коммит являются новыми разработческими коммитами (время автора и коммиттера совпадает с точкой отправки пакета), голова ветки продвинулась до a326bc3 «Update Ztt descriptor and LTO dump checks».

Полная пересборка стека в двух форках также завершилась в этом окне мониторинга. Ветка riscv форка LLVM 11 октября поздней ночью (около 23:00) завершила очередной ночной повтор: 26 локальных патчей были целиком перезафиксированы с новым временем коммиттера, голова по-прежнему #31 «A100 HP/SP и понижение pack/unpack, а также калибровка планирования», состав стека совпадает с предыдущим раундом, точка привязки повтора синхронизирована со снимком апстрима за 11 октября. После завершения пересборки / повтора на обеих сторонах записи базовых линий соответствующих открытых PR (8 в PyTorch, два FPGA PR #25 / #28 в LLVM) последовательно обновились в ожидании нового раунда продвижения ревью.

На стороне Triton PR #84 по обновлению зависимости Buddy MLIR, расчищенный в предыдущем окне, был влит 10 октября днём (13:31) (автоматическое слияние ботом): этот PR был открыт 20 сентября и обновляет buddy-mlir до nightly-версии v0.0.11.dev20260925; ранее сборка падала из-за несовместимости нового LLVM, который несёт v0.0.11, с фиксированным API фронтенда, а после расчистки патчем адаптации (#86) от 9 октября появились условия для слияния. 5. Наблюдения за тенденциями

5.1 Ритм пересборки работает по двум линиям: два форка за одну неделю завершили по одному циклу полной пересборки стека

В этом окне ветки riscv двух форков — PyTorch и LLVM — завершили по одному циклу полной пересборки стека: PyTorch — 23 повторно применённых коммита (в ночь на 10-11), LLVM — 26 воспроизведённых (поздно вечером 10-11); после пересборки базовые значения открытых PR в каждом из них обновились — «продвижение в upstream → полное воспроизведение стека → обновление базовой линии PR» стало штатной формой эксплуатации для обоих форков (в этом раунде — очередной цикл для PyTorch после 10-08 и для LLVM после 10-09). Точки наблюдения: пересборка гарантирует лишь совпадение базовой линии с upstream, реальное содержательное продвижение по-прежнему зависит от эффективности ревью PR (два коммита по FPGA в LLVM, серия RVV в PyTorch).

5.2 Линия Ztt ускоряется двумя партиями подряд: размер одной партии 36 → 51 коммит

Линия бэкенда GCC для расширения матрицы черновиков Ztt с момента основания 09-30 набрала темп: после 36 коммитов за один день 10-08 в этом окне добавился ещё 51 коммит (самая крупная отдельная партия), тематика сместилась с развёртывания функциональности к оптимизационной тонкой настройке системы дескрипторов (переиспользование, кэширование, индексирование и факторизация рабочей области) — обычно это означает, что функциональная поверхность стабилизируется и работа переходит в фазу оптимизации и завершения. Точки наблюдения: продвижение ztt-dev на стороне riscv-binutils (сейчас всё ещё на уровне 09-30) и путь в upstream.

5.3 Цепочка обновления зависимостей замкнулась: адаптация #86 → слияние #84

В предыдущем окне патч #86 расчистил путь для нового API LLVM, в этом окне #84 сразу был слит, и обновление зависимости Buddy MLIR v0.0.11 заняло своё место — адаптационная цепочка фронтенда Triton-RISCV между «быстрой эволюцией upstream LLVM — фиксацией фронтенда — обновлением зависимости» вновь замкнулась в цикл. Дальнейшие наблюдения: выпустит ли ночной канал новую сборку с v0.0.11 (сейчас последней остаётся сборка от 10-04); ревью社区 PR #85 по оптимизации (пути softmax и matmul); эволюция патчей A100 / BOSC AME в стеке LLVM в следующем раунде воспроизведения.
