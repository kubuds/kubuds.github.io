Главное за сегодня: открыты три PR с RVV-операторами для Caffe, 15 PR серии MXNet на рассмотрении — линия адаптации классических фреймворков переходит к практике

Дата: 2026-09-23 ~ 2026-09-28　Источник: caffe PR #1, caffe PR #2, caffe PR #3, список PR MXNet

С 14:56 по 14:59 по пекинскому времени 09-28 (в течение трёх минут) контрибьютор Xlawy в репозитории caffe (одном из двух репозиториев классических фреймворков, включённых 09-23) последовательно открыл три PR с RVV-операторами — это первые содержательные действия с кодом для обоих репозиториев с момента их включения:

  • #1 im2col (+113 / -9, 2 файла): сбор строк вывода im2col разделён на скалярные помощники и перегрузки RVV float; каждая строка разбита на две части — дополнение нулями и попадание в границы; в зависимости от stride_w выбирается загрузка с единичным шагом или с шагом вектора; применена блочная обработка переменной длины e32,m4; попутно однопараметрический API Protobuf SetTotalBytesLimit адаптирован к версии 3.6.0 и выше.
  • #2 float CPU max pooling (+167 / -24, 2 файла): внутренние столбцы max pooling обрабатываются блоками e32,m4; с помощью загрузок с шагом и строгого сравнения «больше» обновляются максимум и смещение выигрышной позиции; сохранена семантика первого выигрыша при равенстве и часовой -1; выполнено разворачивание окна из трёх столбцов; границы по-прежнему обрабатываются скалярно.
  • #3 float vPowx (+166 / -1, 2 файла): для не-MKL vPowx<float> добавлена специализация RVV — при условии, что все входные данные являются нормальными числами, а показатель степени находится в диапазоне [-1, 1], включается векторная аппроксимация log/exp (с промежуточными значениями двойной точности); показатели степени 0 и 1 обрабатываются прямыми векторными операциями; поддерживается блочный вызов на месте; при непрохождении проверки области определения весь вызов откатывается к скалярному пути.

Все три коммита добавляют новые специализации под защитой макросов RVV и сохраняют скалярный откат для сборок без RVV; в настоящее время все они открыты и не имеют записей о ревью. Более ранние действия того же направления сосредоточены в репозитории MXNet: за два дня с 09-23 по 09-24 трое контрибьюторов суммарно открыли 15 PR (ww8191201-coder — 11, Xlawy — 2, 6eanut — 2), из которых 11 PR посвящены векторизации операторов RVV — обратный GELU(erf), обратный ReLU, softmax, log-softmax, softmin, CTC log-softmax, im2col, col2im, batched cumsum, ближайшая соседняя повышающая дискретизация, приведение минимума float32; ещё 4 PR относятся к производительности и базе сборки (снижение силы индексных обращений в broadcast_reduce и reduce_with_axis, удаление volatile у сумматора-редьюсера, запрос -fno-math-errno для сборок без MSVC). Описания нескольких PR напрямую ссылаются на контекст тестирования SG2044 (RVV 1.0, GCC 15.1). Эта серия ранее в окне мониторинга не раскрывалась; в текущем выпуске она объединена с новыми действиями по Caffe.

К концу окна суммарно 18 PR в обоих репозиториях остаются открытыми, ни один не влит. С учётом записи выпуска от 09-24 о двух репозиториях как о «наблюдаемых кандидатах на архивацию, адаптационную базовую линию или новую отправную точку работы», текущая партия действий даёт промежуточный ответ: оба репозитория используются как практическая площадка для адаптации RVV в классических фреймворках; серия MXNet охватывает поверхность основных операторов вывода, а серия Caffe сосредоточена на инфраструктуре свёрток и активаций. В ту же ночь действия по RVV на стороне компилятора продолжил tilelang-riscv PR #4 (см. 1.1); RVV стал наиболее концентрированной технической темой дня внутри организации.

5. Наблюдения за трендами

5.1 Классические фреймворки: RVV оформляется по двум линиям — от «попадания в репозиторий» к «накоплению PR»

Когда 09-23 два репозитория вошли в состав, их назначение было отмечено как требующее наблюдения; в течение недели MXNet с 15 PR (три контрибьютора) охватил 11 операторов RVV и 4 направления производительности и базовой сборки, Caffe 09-28 подключился с тремя операторами RVV — маршрут «адаптации» официально сделан ход в измерении классических фреймворков. Примечательная деталь: несколько PR напрямую ссылаются на тестовый контекст SG2044 (RVV 1.0, GCC 15.1), что свидетельствует о том, что эта работа ориентирована на работающую реальную базовую платформу; это контрастирует с патчами RVV на стороне форка PyTorch (#46, #48), которые всё ещё ждут в очереди — текущее продвижение адаптации RVV частично обходит основную линию PyTorch.

5.2 Ритм до и после праздника середины осени: 09-28 — сосредоточенная выдача после праздника

09-25 (15-й день 8-го лунного месяца, праздник середины осени) и последующие выходные коммиты трёх организаций почти остановились; 09-28, в первый рабочий день после праздника, наблюдается сосредоточенная выдача: 5 коммитов в основном репозитории openRuyi, 3 коммита в kiwi-image, 2 коммита в плагине VS Code и релиз 0.1.7, ruyiai-daily и информационный пост форума возобновлены в тот же день — «спад и отскок», вызванные праздниками, полностью видны в двух окнах мониторинга.

5.3 Ритм релизов на стороне инструментов стабилен

В пределах окна три линейки инструментов продвигаются в своём ритме: плагин VS Code 0.1.7 стал正式ным (через 8 дней после beta), канал ночных сборок Ruyi Imager обновляется, еженедельные ночные сборки triton-riscv выходят по расписанию; соответственно, линейка версии 1.9 ruyi-tuner保持状态 «релиз не вышел, но изменения в пути» уже два окна мониторинга.

5.4 Пробелы и точки внимания данного окна

Пробелы: ветка riscv PyTorch и открытые PR непрерывно молчат (с 09-21); рецензирование PR #168 в llvm-project (исправление XTHeadVector) остановилось на 09-24; очередь на рассмотрении в support-matrix накопилась (с 09-21 по 09-24 без обновлений); анонс сентябрьской версии openRuyi 2026.09 не вышел; внешние новости и arXiv — нулевые попадания. Точки внимания: во-первых, рецензирование и ритм первых включений восемнадцати PR MXNet / Caffe; во-вторых, возобновит ли ruyiai-daily ежедневную рассылку; в-третьих, продвижение сборки ruyici для macOS и патча расширения p в riscv-gcc; в-четвёртых, войдёт ли метка ядра 6.18.54-1 в официальную сборку openRuyi.
