Главное за сегодня: FlagGems — пять партий, 245 операторов, за один день влиты в triton-riscv (11-25)

Источник: PR #136. Остальные четыре партии — #137–#140, ссылки в приложении [2]–[5].

С 11-25 10:13 по 19:53 в triton-riscv влиты пять партий примеров операторов FlagGems, всего 245 операторов.

Пять партий: 55 из B12, 51 из B13, 41 из B14, 50 по случайным числам, RNN и attention, 48 по разреженным и вложенным тензорам.

Каждая партия сопровождается тестом корректности на CPU для каждого оператора и единым экспортом из __init__.py пакета examples.

В сумме пять партий добавили 54 550 строк и удалили 315 строк. Запись проверки B13: все 146 тестов на riscv64 CPU пройдены, окружение — Python 3.12, PyTorch 2.10.0, CPU Triton 3.9.0.

B14 попутно исправила упаковщик int4. Ранее при превышении шириной выходного столбца 128 входных значений остаточные байты не записывались, а несмежные тензоры читались как непрерывная память.

Записи предыдущего отчёта о трёх партиях B12, B13 и B14 всё ещё находились на рассмотрении, в этом выпуске все они уже приняты. Вместе с 59 операторами линейной алгебры, влитыми 11-24, совокупный объём переноса в этом раунде составил 304 оператора.

Главное за сегодня: triton-riscv влил настройку бэкенда RISC-V, зависит от приближённой математики Buddy (11-26)

Источник: PR #129. Зависимость Buddy см. в приложении [24].

11-26 00:24 PR #129 влит в основную ветку triton-riscv, изменено 2 файла, добавлено 136 строк, удалено 15 строк.

Все изменения находятся в _ttsharedir_to_llir и действуют только при цели RISC-V.

Пять изменений: математические функции переведены на полиномиальную аппроксимацию; использованы масштабируемые векторы и хвостовой цикл AVL; ширина вектора matmul взята как 2·VLEN/32; buffer поднимается в стек до деаллокации; копирование strided memref переведено в linalg для векторизации.

Указанная в PR точность — от 1 до 7 ULP для f32, не более 1 ULP для f16 и bf16, за исключением субнормальных результатов exp и erfc.

Изменение зависит от pass polynomial-approximate-math и опции use-avl-loop, предоставляемых buddy-mlir#1068. При слишком старой версии buddy-opt RISC-V lowering завершится из-за неизвестного pass или опции.

Базовая линия настройки — плата разработчика RISC-V с VLEN-256, контрольная группа — triton-cpu.

1.2 PR настройки бэкенда #129: приближённая математика, масштабируемые векторы и векторизация matmul (11-26)

Источник: PR #129.

Полиномиальная аппроксимация охватывает 15 функций: exp, expm1, log, log2, log1p, tanh, erf, erfc, sin, cos, atan, atan2, asin, acos, cbrt.

Ранее в RVV не было векторной математической библиотеки, эти функции по lane деградировали до вызовов libm и не могли использовать векторные регистры.

Ширина вектора matmul изменена с фиксированной 4 на 2·VLEN/32, что соответствует 8 строкам аккумулятора, по два векторных регистра на строку, LMUL равен 2. В PR указано, что LMUL 4 приводит к переполнению.

В --lower-vir-to-vector добавлены use-scalable=true и use-avl-loop=true. Остаточный сегмент завершается одной итерацией по активной длине, больше не разбивается на половинные сегменты со скалярным циклом.

Копирование strided memref.copy переведено на convert-strided-memref-copy-to-linalg, копирование динамических форм понижается до SCF, копирование FP8 сохраняет исходный путь.

Источник: PR #135.

Источник: PR #1080. #1085 см. в приложении [19].

В окне мониторинга в buddy-mlir два коммита, оба ранним утром 26 ноября.

В 00:07 влит #1080 «Optimize masked tiles, reductions, and matmul», изменения в 23 файлах, добавлено 3163 строки, удалено 30 строк.

Этот PR добавляет устранение копирования masked tile, продвижение памяти tile и векторизованное сохранение масок, оптимизацию редукций и matmul, а также переиспользование стековых слотов малых блоков с неперекрывающимся временем жизни.

В 01:20 влит #1085 «Keep the reassoc of a linalg.reduce combiner», изменения в 2 файлах, добавлено 131 строка, удалено 4 строки.

Ранее -lower-linalg-to-vir при генерации vir.reduce терял reassoc, из-за чего редукции, допускающие переупорядочивание, понижались до упорядоченного vfredosum. Этот PR добавляет reassocOf(), который единообразно используется в четырёх путях понижения редукций.
