Еженедельный отчёт RuyiAI (2026-09-30 ~ 2026-10-07)

2026-10-07 Kubuds

Период отчёта: с 30 сентября 2026 года (среда) по 7 октября 2026 года (среда), всего 8 дней; специальный сводный период в честь праздника образования КНР (с 1 по 7 октября — праздничные дни, ежедневный отчёт приостановлен) Источники материалов: ежедневный отчёт RuyiAI данного издания (один выпуск от 2026-09-30, окно 09-29 04:30 ~ 09-30 04:30; с 10-01 по 10-07 в праздничные дни материалы ежедневного отчёта отсутствуют); дополнительно — проверка 216-часового окна репозиториев организации, двойная сверка по источникам сообщества и полное сканирование репозитория технической разведки за весь период (охват до утра 10-08) Пояснение к составлению: данный период охватывает праздник образования КНР — слияние кода перешло в режим низкой активности в праздничные дни, при этом очередь ревью, репозиторий разведки и каналы сообщества продолжали работу; все технические факты получены путём фактической проверки в репозиториях кода, релизах и форумах сообщества

1. Главные новости недели

  • Официальный релиз openRuyi 2026.09: доработка RVA23, расширение облачного и хранительного программного стека, включение проверки GPG в репозитории (09-30): анонс релиза опубликован в первый день данного периода (в окне ежедневного отчёта 09-30 ещё не виден, относится к новым обнаруженным в ходе проверки данного выпуска пунктам). Ключевые моменты: GCC 16 бэкпортирует исправление генерации кода BCLR — устранены зависание DPDK rte_softrss() и ошибки компиляции планировщика Mesa ACO; DPDK 25.07 включает путь поиска RVV на RVA23 (lpm / fib / acl / node); OpenJDK включает 15 патчей RISC-V (генерация инструкций Zbs / Zfa, оптимизация RVV vset, intrinsic CRC32C); на стороне контейнеров после разрешения riscv_hwprobe на Jiandie Shikong V100 фактически протестировано включение OpenSSL расширений векторной криптографии Zvkned / Zvknhb, zlib-ng включает ускорение crc32 через Zbc; ядро 7.2.6 / 6.18.54; добавлены мультиоблачная платформа Cloudpods 4.0.3, SPDK 25.09 (io_uring / RBD bdev / SMA) и снимок Ceph 21.3.0; цепочка установки по умолчанию включает проверку подписи GPG; массово внедрены обновления безопасности (expat / jq / vim / pcre2 / runc и др.); предоставлены четыре версии Server / Container / Desktop / Zero и экспериментальная версия RVA20. Источник: релиз openRuyi 2026.09

  • Опубликована статья «Практика PyTorch RISC-V CI»: сообщество Ruyi совместно с XuanTie и RISE раскрывает систему CI на реальном оборудовании (опубликована ранним утром 10-08): статья раскрывает полную картину непрерывной интеграции PyTorch RISC-V — совместное создание RuyiAI (Институт программного обеспечения Академии наук Китая), команды XuanTie и рабочей группы RISE AI/ML: используется базовая линия Debian Trixie / Python 3.13 / GCC 14 / OpenBLAS 0.3.33, принцип «одна сборка, тестирование на многих машинах»; параллельное шардирование Jenkins (основные тесты около 3 часов, полный набор около 5 часов); динамическое шардирование по историческому времени выполнения; единый blocklist, управляемый вручную с классификацией; централизованное архивирование журналов сбоев (community-ci.openruyi.cn); SyncBots непрерывно синхронизирует upstream main в рабочую ветку RISC-V и автоматически запускает основные тесты — в настоящее время основной набор тестов RISC-V стабильно проходит. Работа началась с RFC команды XuanTie (pytorch#171659) и tracking issue (#180975); Институт программного обеспечения является членом RISE, а член RuyiAI занимает должность сопредседателя RISE AI/ML WG. Источники: статья (на китайском и английском языках), RFC #171659, tracking #180975

  • PyTorch fork прекращает молчание: ветка riscv возобновляет ежедневную синхронизацию и завершает полную пересборку ранним утром 10-08 (09-30 ~ 10-08): ветка riscv ранее молчала с 09-21, утром 09-30 возобновлена отправка мейнтейнером — далее практически ежедневно по одному разу (с 09-30 по 10-07 всего 7 раз); ранним утром 10-08 (пекинское время) выполнена полная пересборка — локальный стек патчей воспроизведён по порядку (начиная с #1 RISC-V Blocklist, всего 23 коммита, включая исправление #44 bytes_to_scalar, #50 inductor blocklist, #42 допуск ULP и др.), интеграционный коммит SyncBots продвинул точку синхронизации с upstream до e188cec; базовые линии 8 открытых PR (#23 / #35 / #36 / #38 / #43 / #46 / #48 / #51) единообразно обновлены — в списке два PR по RVV (#46 поддержка ATen RVV, #48 RVV CPU capability) и CI локальный образ (#51). Источники: коммиты ветки riscv, список PR

  • Ветка riscv проекта llvm-project: три коммита серии A100 от SpacemiT включены (10-03); ритм ночных пересборок сохраняется в течение праздников (10-01 ~ 10-07): #30 понижает IME intrinsics до инструкций точечного произведения A100, #32 добавляет понижение и планирование A100 pack/unpack intrinsic, #31 дополняет понижение A100 HP/SP и pack/unpack и калибрует модель планирования — три коммита последовательно включены 10-03; ветка сохраняет ночную пересборку (ранним утром по пекинскому времени), голова последней пересборки в окне — 03e4e494. Предодобренный upstream PR #22 бэкенда стандарта AME (открыт в июле, 7 обсуждений) закрыт 10-02 (не включён); два PR по FPGA (#25 / #28) всё ещё на рассмотрении и получили обновление базовой линии. Источники: PR #30, PR #31, PR #32, PR #22

  • В riscv-gcc включены два PR по расширению P (10-02); открыта рабочая линия инструментальной цепочки черновика Ztt (с 09-30): #20 (серия abs / pabs переведена на понижение операторов в заголовочных файлах и исправлены тесты) и #21 (удалён ошибочный режим combine PAS/PSA одного канала) включены 10-02 (автор TelGome); в тот же период в riscv-gcc и riscv-binutils открыта новая ветка ztt-dev, добавляющая поддержку регистровых операндов, кодирования инструкций и CSR для расширения черновика Ztt, коммиты продолжаются в течение праздников (включая оптимизацию генерации кода, последние — до утра 10-08); в riscv-gnu-toolchain добавлена ветка ame-experimental. Источники: PR #20, PR #21, ветка ztt-dev

  • Линия работ по расширению матричных операций развёрнута: репозиторий AME-operator открыт, официальный репозиторий спецификации AME отфоркан (30.09): организация ruyisdk создала репозиторий AME-operator — ядра GEMM и GEMV для RISC-V AME/Ztt, независимый численный эталон и набор верификации DejaGNU/Spike (покрытие INT8 / UINT8 / INT32 / FP32 / BF16, T=4~128; дымовое тестирование из 16 ELF прошло все 32 запуска); в тот же день был отфоркан официальный репозиторий RISC-V attached-matrix-extension (управляющий репозиторий рабочей группы AME). Таким образом, матричное направление оформилось в трёхлинейную компоновку: «LLVM (BOSC AME / A100) — GCC/Binutils (Ztt) — операторы и верификация (AME-operator)». Источники: репозиторий AME-operator, форк attached-matrix-extension

  • В праздничные дни Национального дня «разведка и ревью работают без остановки»: ruyiai-daily выпустил 9 номеров подряд, очередь ревью openRuyi активна, в сообществе новые курсы (30.09 ~ 08.10): репозиторий технической разведки ruyiai-daily в праздничные дни непрерывно выпустил 9 номеров (с 30.09 по 08.10, публикация каждое утро), сохраняя структуру из пяти глав: экосистема PyTorch / LLVM-MLIR / Triton и TileLang / RISC-V / индустрия AI; на стороне открытых PR очередь openRuyi сосредоточена на интенсивном ревью включения поддержки RISC-V в audit (#1399), исправления тестов RISC-V go-github-chewxy-math32 (#1398), moby 29.8.1 (#1395) и других; на форуме сообщества опубликованы лекция и лабораторные работы главы 01 «Окружение и инструментальная цепочка» курса «Практика RISC-V Linux» (04.10, 06.10), а также ресурсный пост с примерами репозиториев для отладочных плат (30.09). Источники: ruyiai-daily, форум #2885

  • triton-riscv: выпущена сборка Nightly 2026-10-04; открыты PR по оптимизации softmax и matmul (05.10, 08.10): ночные сборки сохраняют недельный ритм — Nightly 2026-10-04-12c2f6a выпущен 05.10 (wheel для x86_64 и riscv64 с покрытием CPython 3.12–3.14); утром 08.10 открыт новый PR #85 «оптимизация softmax и matmul» (участник сообщества). Источники: Nightly 2026-10-04, PR #85

2. Прогресс стека RuyiAI (адаптация PyTorch / Triton / TileLang под RISC-V)

Обзор окна: действия организации RuyiAI-Stack (18 репозиториев) в этом периоде сосредоточены на llvm-project (серия A100 влита, ночные пересборки), pytorch (ежедневная синхронизация, полная пересборка и обновление PR), triton-riscv (еженедельные сборки, новые PR), ruyiai-daily (9 номеров) и блог сайта; в tilelang-riscv, mxnet, caffe, FBGEMM, cpuinfo, VecIntrinBench, IntrinTrans, torq-tile, dsh-osc, pytorch-ci и других коммитов нет; в harness коммитов нет, но на стороне PR есть активность по ревью.

Форк PyTorch: от «тихого завершения» к «ежедневной синхронизации + полной пересборке»

  • Синхронизация в период праздников (30.09 – 07.10): ветка riscv возобновила отправку утром 30.09 (до этого с 21.09 была тишина), после чего практически ежедневно выполнялась поддерживающая отправка (30.09, 01.10, 02.10, 04.10, 05.10, 06.10, 07.10 — всего 7 раз), выполняемая сопровождающим ветки — это реконструктивная синхронизация (перебазирование стека патчей на более новую upstream-базу); плановая upstream-синхронизация ветки main продолжается (общие коммиты MPS, ROCm, inductor и др. в соответствии с правилами фильтрации не включаются).
  • Полная реконструкция (раннее утро 08.10): ветка завершила последнюю в окне полную реконструкцию — стек из 23 патчей перебазирован по порядку (самые ранние восходят к апрельским RISC-V Blocklist #1 и построению CI #6–#12), интеграционный коммит SyncBots (e188cec) помещён на вершину; базовые состояния 8 открытых PR синхронно обновлены, время обновления унифицировано до 08.10.
  • Очередь ожидающих проверки RVV: два векторных патча (#46 поддержка ATen RVV, #48 RVV CPU capability) продолжают находиться в очереди — обновление в этом выпуске вызвано реконструкцией; PR #51 с локальным зеркалом CI (требуется нативное оборудование riscv64) находится в той же колонке.
  • Фоновая связь: данная реконструкция перекликается со статьёй в блоге «Практика PyTorch RISC-V CI» — SyncBots непрерывно синхронизирует upstream main и автоматически запускает ключевые тесты, что является работающим воплощением замкнутого цикла «от отслеживания upstream до регрессии на реальном железе» (подробности в главных новостях недели).

Линия компилятора (llvm-project): влита серия A100, ночные пересборки, конвергенция направления AME

  • Серия A100 (влита 03.10): #30 «Lower IME intrinsics to SpacemiT A100 dot instructions» — понижение IME intrinsics до инструкций скалярного произведения SpacemiT A100; #32 «Add A100 pack/unpack intrinsic lowering and scheduling»; #31 «Add A100 HP/SP and pack/unpack lowering with calibrated scheduling» — три патча последовательно влиты в течение одного дня, образуя основу понижения инструкций и планирования для платформы A100 на стороне LLVM.
  • Ночные пересборки (каждую ночь с 01.10 по 07.10): ветка riscv в период праздников поддерживала ритм ночных (по пекинскому времени, раннее утро) пересборок; начиная с ночи 03.10 включены изменения серии A100; последняя в окне пересборка продвинула точку синхронизации до последнего в окне upstream-коммита (голова 03e4e494), состояния трёх рассматриваемых PR обновлены соответствующим образом.
  • Изменения направления AME: бэкенд-PR #22 стандартного AME (RVI, стадия предварительного одобрения) закрыт 02.10 (не влит, с момента открытия 7 обсуждений); линии развёртки BOSC AME (#29 и предыдущая серия) и два патча FPGA (#25 / #28) являются текущими активными путями в репозитории.

triton-riscv: сохранение ритма еженедельных сборок, открыт новый оптимизационный PR

  • Nightly 2026-10-04-12c2f6a (выпущен 05.10): сохранён ритм сборок раз в неделю (предыдущий выпуск 27.09); wheel охватывает CPython от 3.12 до 3.14, двойная архитектура x86_64 и riscv64.
  • PR #85 «оптимизация softmax и matmul»: открыт утром 08.10 участником сообщества (на рассмотрении); ранее открытый dependency-PR #84 от renovate остаётся открытым.
  • Последний коммит главной ветки по-прежнему датирован 14.09 (в период праздников функциональных коммитов не было).

TileLang и другие целевые репозитории: тишина на протяжении всего периода

  • tilelang-riscv (последний коммит 16.07), FBGEMM (13.07), cpuinfo (20.05), torq-tile (09.04), dsh-osc (15.09), pytorch-ci (нет записей о коммитах) в период праздников активности не проявляли; в двух репозиториях mxnet и caffe коммитов нет (ранее открытая очередь PR без обновлений в окне).
  • harness: коммитов нет; PR #2 «Integrate Triton-RISCV agent backend and workbench with Harness» получил обновление по ревью 01.10 (в связке с направлением агентской рабочей среды triton-riscv).

Техническая разведка и сайт (ruyiai-daily / блог / сайт)

  • ruyiai-daily — 9 выпусков подряд: с 30.09 по 08.10 ежедневные непрерывные выпуски (публикация каждый день около 06:15), сохранена структура из пяти глав; в период праздников освещены динамика upstream PyTorch (оптимизация обратного прохода RMSNorm, кэш с подстановочными знаками AliasDb, серия исправлений MPS / ROCm и др.), достижения LLVM/MLIR (ClangIR, SLP и др.) и записи вверх и вниз по потоку RISC-V (избранное см. в разделе 4).
  • Сайт и блог: на официальном сайте добавлена версия статьи «Практика PyTorch RISC-V CI» на китайском и английском языках (коммит 07.10, публикация ранним утром 08.10, #79); файл данных о контрибьюторах в период праздников обновлялся ежедневно в плановом порядке (10 автоматических коммитов).
  • Примечание о методике: массовые коммиты upstream-форков (PyTorch main, LLVM main) включаются после фильтрации по ключевым словам RISC-V; не включённые общие коммиты не учитываются в прогрессе данного стека.

3. Инструментальная цепочка и дистрибутивы RuyiSDK (менеджер пакетов ruyi, packages-index, openRuyi)

Дистрибутив openRuyi: релиз 2026.09 состоялся, основные слияния в репозитории приостановлены на праздники, очередь интенсивных ревью

  • Релиз 2026.09 (09-30): ключевые моменты см. в «Главных новостях недели»; анонс версии — наиболее значимое событие со стороны дистрибутива за текущий период.
  • Темп основного репозитория: в праздничные дни новые слияния в основной репозиторий отсутствовали (последние слияния — #1388 / #1389 накануне окна мониторинга), со стороны коммитов наблюдается праздничная пауза; очередь PR остаётся активной — #1392 docker-cli (WIP), #1393 тесты python-numba, #1394 spdk bdevperf, #1395 moby 29.8.1, #1398 go-github-chewxy-math32 исправление тестов для RISC-V, #1399 audit 4.2.1 включение поддержки RISC-V, #1401 исправление метаданных, #1402 AGENTS.md (описание для агентов AI-кодирования) и другие постепенно открываются или получают ревью; #1379 OpenCL также находится в очереди.
  • Смежные компоненты: rpm-spec / rpm-spec-tool (ветка openruyi) и k1firmware продвинулись в праздничные дни; homepage #77 слит (09-30); сервис отслеживания пакетов «lookout» высокочастотно итерируется (около 30 коммитов), 10-07 обновлён до 0.2.0 — обеспечивает для openRuyi доступное только для чтения отслеживание версий источников RPM, апстрим-релизов, сборок OBS и свидетельств сопровождения; TakoPack (инструмент упаковки Rust/Python в RPM spec) открыл новый PR #1 по реализации Rust-конвейера (10-07).
  • openRuyi-zero: коммитов нет (последнее — исправление сборочного скрипта 09-29).

Менеджер пакетов ruyi и сопутствующая инструментальная цепочка

6. Наблюдения за трендами

  • Дифференциация в праздничном режиме: «низкая пропускная способность слияний, но очереди и разведданные не останавливаются»: у трёх организаций за 8 дней число слияний в основных репозиториях можно пересчитать по пальцам (два коммита в riscv-gcc, три в llvm-project, ноль в openRuyi), однако ревью PR, обновление веток, репозитории разведданных и каналы сообщества работали на протяжении всего времени; в первые часы послепраздничного дня (10-08) появились полная пересборка PyTorch и новый PR в triton — скорость восстановления заслуживает фиксации.
  • Системная организация расширения матрицы: на стороне LLVM — серия слияний A100, на стороне GCC/Binutils — черновая ветка Ztt, на стороне операторов — открытие исходного кода AME-operator, на стороне спецификаций — fork официального репозитория AME — направление матрицы перешло от разрозненных патчей к параллельному продвижению по схеме «компиляция — операторы — спецификации — верификация», что является наиболее технически значимым структурным изменением этого выпуска.
  • PyTorch RISC-V: от «способности компилироваться» к «непрерывной верификации»: блог о CI, пересборка fork и автоматическая синхронизация SyncBots совместно образуют замкнутый цикл «отслеживание upstream, регрессия на реальном оборудовании, обратная связь по проблемам»; следующий шаг — наблюдение за ревью двух PR по RVV (#46 / #48) и подключением дополнительных аппаратных бэкендов.
  • Нарратив «корпоративного программного стека» openRuyi: версия 2026.09 включает облачную платформу Cloudpods, хранилища Ceph / SPDK и подпись цепочки поставок GPG в основную линию, дополняя это исправлениями RVA23 и путём оптимизации производительности контейнеров — целевые сценарии дистрибутива смещаются от «запускается» к «готов к продакшену».
  • Непрерывное исправление корректности на уровне инструкций на стороне компилятора: исправление кодогенерации BCLR (бэкпорт в openRuyi GCC 16), lowering расширения P, A100 и Ztt — инструментальная цепочка одновременно получает результаты как по корректности существующих расширений, так и по поддержке новых.
  • Пробелы и точки внимания: выпуск двухнедельного отчёта 078; судьба стандартного маршрута AME после закрытия llvm-project #25 / #28 (FPGA) и #22; восстановление слияний в основном репозитории openRuyi и ритм версии 2026.10; непрерывность ruyiai-daily после праздников; ревью triton-riscv #85; ритм слияний support-matrix #409 и board-docs #50.
