I. Kernel and Version Dynamics

1.1 Build Toolchain Missing Check Merged: Build Fails Explicitly When Toolchain Directory Is Missing (10-12)

Date: 2026-10-12 09:56 (merge time)　Source: PR #11863

Build tool fix merged (#11863, author Rbb666, single file tools/building.py): the build entry point’s handling of a missing toolchain directory was changed from setting a local exit flag (need_exit = True) to directly calling sys.exit(1), causing the build to fail immediately and explicitly with a non-zero exit code instead of continuing subsequent steps with a missing toolchain. The proposal was opened on the morning of 10-12 and merged roughly 36 minutes later, the first item to land within the window.

1.2 Eclipse Project Generation Fix Merged: #11787 Lands, SCM Metadata Directories No Longer Recursively Scanned (10-12)

Date: 2026-10-12 11:06 (merge time)　Source: PR #11787

Eclipse target generation script fix merged (#11787, author wdfk-prog, single file tools/targets/eclipse.py): an SCM metadata directory list (.git / .svn / .hg) was introduced into the source file collection and exclusion logic, so such directories are no longer recursively expanded and scanned, avoiding traversal of massive numbers of object files in project trees containing version control metadata; hidden directories are likewise aligned with the exclusion rules for ordinary directories. The case was opened on 09-08 and merged this period after CI troubleshooting on 10-11 (the failure was due to a missing scons command in the pipeline, unrelated to the exclusion logic), the second item to land within the window.

1.3 New Proposal: rtdbg.h Include Relationship Fix, Resolving Implicit Declaration of rt_kprintf Under IAR (10-12)

Date: 2026-10-12 13:50 (creation time)　Source: PR #11864

New proposal (#11864, author meng-plus, single file include/rtdbg.h): change the header’s #include to #include , so that components that only redirect logs via rtdbg.h also obtain the formal function declaration of rt_kprintf. The author reports: under IAR 8.40, redirecting logs via rtdbg.h produces an implicit declaration of rt_kprintf, causing abnormal %f formatted output; the proposal includes two minimal comparison samples, with_proto / no_proto. The proposal is under open review.

1.4 RISC-V Vector: vstart Proposal Adjusts Test Organization per Maintainer Feedback (10-12)

Date: 2026-10-12 09:17 (review time)　Source: PR #11861, Issue #11786

The RISC-V vector context fix proposal (#11861) received a new round of maintainer review feedback within the window: it was suggested to move the tests and their assembly probes into a dedicated utest directory, enable conditional build integration, and add CI configurations for vector support, heap, and UTest under both VLEN=128 and VLEN=256 configurations. The proposal author had already pushed a revised commit on 10-11 per the previous round of feedback (allocating an independent stack frame for each call and releasing it uniformly on both success and failure paths); the case remains open, awaiting test organization adjustments. The OSPP 2026 topic “RISC-V Lazy FP/RVV Context Switching” (#11786) pushed by the same author also saw one update within the window and remains open.

1.5 ping Divide-by-Zero Second Case: Author Adopts Bypass Suggestions and Pushes Further Fix (10-12)

Date: 2026-10-12 20:18 ~ 20:47 (comments and push)　Source: PR #11862, PR #11853

The second netdev ping divide-by-zero fix case (#11862) iterated again within the window: contributor CXSforHPU raised two improvements regarding the delay logic inside the ping loop (the last packet should not add extra delay, and rt_thread_delay should not be called with a 0 argument), and asked whether to modify them together in this case; the original author ymj0440 adopted them that evening and pushed the fix — the delay condition was changed from the always-false index == times to index != times - 1, and the delay function is only called when delay_tick > 0, avoiding triggering -RT_EINVAL. This case runs in parallel with the first case #11853, still awaiting the maintainer to merge one of them.

1.6 Tools and Standards Review Queue Update: Keil/IAR Target Selection Receives Review Feedback (10-12)

Date: 2026-10-12 (update time)　Source: PR #11743, PR #11859, PR #11850, PR #11815, PR #11814

Multiple items in the tools and standards direction advanced in review: first, the author of the Keil/IAR target auto-selection proposal (#11743) requested a recheck of automation errors in the morning, and the maintainer gave two specific review comments that evening (the targets initialization loop and missing variables, and the way IlinkConfigDefines extracts invalid symbol entries); second, the clang-format rule convergence discussion (#11859) remained active — wdfk-prog gave LGTM, while Rbb666 considered the formatting appearance using thread.c as a sample unsatisfactory, and the author had earlier called for converging the rules as soon as possible to reduce the burden of appending formatting commits to each proposal; third, the STM32F103C6 “Blue Pill” support proposal (#11850) was updated late at night with a named review request (linked to defect ticket #11854); fourth, the lwip section macro control proposal (#11815) triggered an automated recheck after a force-push and received improvement suggestions; fifth, the RA6W1 resource allocation optimization proposal (#11814) refreshed its commits within the window.

II. Official and Community Activities

2.1 [2026 Embedded Competition] Portable Debugger Project Post Published (10-12)

Date: 2026-10-12 11:14 (publish time)　Source: Forum post 60a5931af4191d52

The 2026 Embedded Competition project post “Portable Debugger” was published: a handheld debugging platform built around the GD32H759IM (Cortex-M7 @600 MHz, Flash 3840 KB, AXI SRAM 832 KB) running RT-Thread — a 7-inch 800×480 RGB565 touchscreen (GT911 capacitive touch) with a fully Chinese graphical interface and a built-in dot-matrix font library of about 5,000 common Chinese characters; features cover serial debugging (USART1, eight-level baud rate hot switching and automatic baud rate detection), CAN bus debugging, a dual-channel oscilloscope (0~3.3 V), dual-channel switch detection, and a DDS signal generator, where the oscilloscope and switch detection share the same sampling chain to simplify hardware; an onboard GD-Link debug/download unit.

2.2 [2026 Embedded Competition] “Eyes Speak the Heart” Smart Assistive Device for Alzheimer’s Elderly Project Post Published (10-12)

Date: 2026-10-12 08:26 (publish time)　Source: Forum post 4656e92595977d25

The 2026 Embedded Competition project post “Eyes Speak the Heart - Smart Assistive Device for Alzheimer’s Elderly” was published: targeting home care scenarios for elderly with dementia, where the elderly can express needs simply by gazing at images on a screen. The lower-level controller was changed from an Arduino Mega 2560 to a GigaDevice GD32H759I-EVAL (Cortex-M7 @600 MHz), with development shifted to the official GD32 firmware library (Keil MDK / IAR), and the software framework reserving FreeRTOS / RT-Thread task scheduling options; it integrates a Hiwonder K230 vision module (face, fall, human figure, and eye gaze direction recognition), stepper gimbal face tracking, MPU6050 attitude detection, GPS positioning, a smart pillbox, a night light, a TJC serial screen, and voice announcements, forming a “watch, remember, protect, accompany” care loop.

IV. Industry Applications

4.1 End-Edge Collaborative Dexterous Robotic Arm System Open-Sourced: Titan Board RA8P1 Fully Autonomous Control and 17-Class Gesture NPU Recognition (10-12)

Date: 2026-10-12 (media publish time)　Source: EET-China original article, Project code repository

The RT-Thread AIoT Competition Excellence Award project “End-Edge Collaborative Dexterous Robotic Arm System” published a complete technical write-up and open-sourced its code (repository initial commit completed on 10-12): a desktop-level assistive robotic arm for people with unilateral upper limb impairment, decoupling robotic arm and dexterous hand control from a PC — using Titan Board (Renesas RA8P1, Cortex-M85 + Ethos-U55 NPU) as the sole control core, with a LeRobot SO101 robotic arm and Amazing Hand dexterous hand at the execution end, and a Joy-Con controller connected via ESP32 / Bluepad32 for teleoperation; a 17-class gesture recognition model is deployed on-board (YOLO-Fastest trained via PyTorch, INT8 TFLite quantized, compiled via RUHMI / Vela into a single fully-NPU subgraph, with all 107 operators landing on the Ethos-U55), with a single inference taking about 77~78 ms, camera capture at 640×480, local LCD display, and WebSocket video uplink to the cloud (160×120 JPEG, about 3~6 KB/frame) running in parallel, with MediaPipe hand keypoints overlaid on the web page. Engineering highlights include a phased startup strategy for D-cache and OSPI clocks (resolving WHD firmware download readback verification failures), WiFi and NPU project integration, and TinyJPEG low-bandwidth streaming, among others; the author also discloses two types of pitfall-handling experience: handling RT-Thread Studio software package index errors and a model conversion command-line workflow that does not depend on e2 Studio.
