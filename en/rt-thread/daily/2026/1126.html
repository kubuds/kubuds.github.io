1.1 ulog Can Print Calling Function, File, and Line Number; 2023 Issue Closed (11-25)

Date: 2026-11-25 18:17 (merged).
Source: #11987.
#7724.

The proposal was opened on November 5 and merged on November 25. Author ymj0440, 4 files changed, 398 lines added, 13 lines deleted.

The three switches are independent.
ULOG_USING_OUTPUT_FILE prints the file name.
ULOG_USING_OUTPUT_FUNC prints the function name.
ULOG_USING_OUTPUT_LINE prints the line number.
When all three are off, output is identical to before.

With all enabled, a log line looks like [main.c:42] app_entry(): this is a debug log!. The legacy interfaces ulog_output and ulog_e/i/w/d are unchanged. The new function ulog_output_ctx is called only by the LOG_X macros.

Issue #7724 was opened on June 26, 2023 and sat for about three years and five months; it is closed with this merge.

Assessment: This fills in debugging information rather than changing the logging skeleton. The basis is that it is off by default and the legacy interfaces are unchanged, so upgrading will not alter existing log formats.

1.2 ISO9660 Directory Name Length Unvalidated, Out-of-Bounds Write Fix Merged (11-25)

Date: 2026-11-25 17:52 (merged).
Source: #12062.
#12061.

When ISO9660 parses a directory record, namelen is taken directly from the medium with no range validation. Non-directory records unconditionally strip the ;1 version suffix. When namelen is 0 or 1, the length underflows, and the subsequent rt_strncpy writes out of bounds, crashing the kernel.

Two fixes. Clamp namelen to what the local name buffer can hold. Strip the version suffix only when namelen is at least 2. 1 file changed, 77 lines added, 23 lines deleted, submitted by maintainer Bernard Xiong.

The proposal’s self-reported verification only covers compile and link on qemu-virt64-riscv. Runtime reproduction with a block device was not done. Other record-traversal boundary issues in the same parser are out of scope for this commit.

Assessment: This is a security boundary fix, but with limited coverage. The basis is that only the name length was validated, and the author documented the uncovered items in the proposal.

III. Review Queue and Issues

3.1 CAN Filter Masks Narrowed to Frame-Type Bit Width (11-25)

Date: 2026-11-25 22:27.
Source: #12089.
#11576.

There are twelve initialization macros, all with masks set to 0xFFFFFFFF. Standard frame identifiers are only 11 bits, and extended frames are 29 bits. In Mask mode, a mask bit of 1 means that bit must match, so bits beyond the bit width should not remain in the mask.

The proposal adds two constants.
RT_CAN_STD_ID_MASK for standard frames.
RT_CAN_EXT_ID_MASK for extended frames.
All twelve macros are switched to use them, with the frame-type mapping unchanged. The change touches 1 file, with 25 insertions and 12 deletions.

The author is ymj0440, the same person behind the ulog proposal merged that day. The corresponding issue #11576 was opened on July 6.

IV. Industry Applications: The Motor Control Platform That Won First Prize in the Competition

4.1 Power-Distribution SVM Puts Dual-Port Energy Scheduling into the Modulation Layer (11-25)

Date: 2026-11-25 17:29 (published).
Source: EE Times China.
Original community post.

The RT-Thread WeChat account published a competition entry showcase that day, and EE Times China reposted it the same day. The entry, NS800-PD-FOC, won first prize in the 2026 RT-Thread Embedded Competition. The author is Zhu Yushi, community ID NinoC137_. The hardware uses the NSSinePad NS800RT7P65D, and the software is RT-Thread 5.3.0.

The core is a power-distribution SVM. Conventional SVM only resolves how the three-phase voltages are synthesized; this version simultaneously resolves how much power each of the two DC ports, high-voltage and low-voltage, bears. The distribution coefficient xi ranges from 0 to 1, SVM is computed once for each of the upper and lower voltage vector groups, and six sets of bridge-arm duty cycles are finally produced.

The bus voltage is no longer hard-coded. The two port voltages take the ADC readings measured in the current cycle, and fall back to configuration constants only when the readings do not meet the conditions.

4.2 Three-Layer Fault Shutdown, the Fastest Layer Bypasses the CPU (11-25)

Date: 2026-11-25 17:29 (published).
Source: EE Times China.

The first layer is hardware. The ADC post-processing block PPB1 monitors the phase current and triggers ADCAEVT1 when the limit is exceeded. The event is sent via ePWM X-BAR to the trip zones of EPWM8 through EPWM13, and the six PWM channels are driven low directly, entirely bypassing the CPU, with a response of less than 1 microsecond.

The second layer compares against the 22 A threshold in the 20 kHz control interrupt and forces a trip when exceeded, with a response of no more than 50 microseconds. The third layer is a guard thread that polls every 10 milliseconds and is responsible for latching, shutdown, and recording the state at the time of the fault.

The control fast path only performs the observer, dual-port SVM, and PWM updates. Display, serial port, and buttons fall into tasks at 100 milliseconds, event-driven, and 5 milliseconds respectively.

4.3 ADC Driver Merged into Mainline First, Then Fed Back by the Entry (11-25)

Date: 2026-11-25 17:29 (published).
Source: #11437.
Entry repository.

The NS800 ADC driver used by the entry was submitted separately as #11437, merged into mainline on June 8, with 6 files and 1124 lines added. The author and the entry author are the same person.

The driver integrates the ADC into the rt_adc_device framework. It also supports interrupts, PPB oversampling, and threshold events.

The project code is in the NinoC137/ns800_pdfoc repository on GitHub, created on June 26, with the most recent push on November 9, and currently 0 stars.

Assessment: This is a path where the driver goes upstream first and the entry is publicized later. The basis is that the ADC driver entered mainline in June, while the entry’s post was only published in November.
