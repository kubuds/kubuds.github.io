I. Kernel and Version Updates

1.1 Post-holiday development resumes: four new proposals filed in quick succession on a single afternoon in the main repo (10-08)

Date: 2026-10-08 12:51 ~ 17:23 (Beijing time, creation time)　Source: PR #11855, PR #11856, PR #11857, PR #11858

On the afternoon of the first development day after the holiday, the community filed four fix proposals in the main repo, all with test descriptions and under review: The first (#11855, 12:51, single file +3/-0) fixes a build error when the reset component and the logging component are enabled simultaneously — the logging compatibility macro unconditionally defines assert as ASSERT, causing the identically named member in the reset controller struct to be macro-expanded and fail compilation; the fix is to undefine the macro at the point of use. The second (#11856, 15:36, single file +40/-4) fixes missing C++ global constructors — newer GCC moves C++ global constructors into .init_array, while system initialization only traverses the old constructor range; the fix is to additionally run the .init_array range with overlap deduplication, and build verification has been completed on the simulator platform (related issue #11778). The third (#11857, 16:32, two commits, single file +64/-41) adjusts the reset order for colored logging to prevent color control codes from spilling onto the next line and corrupting the shell prompt colors (related issue #11296). The fourth (#11858, 17:23, single file +63/-33) adds buffer boundary checks to DHCP server option parsing, fixing an out-of-bounds read risk from malformed packets (related issue #11323). Three of the four came from the same contributor who was active before the holiday (with recent merged BSP records for ESP32-C6, CH32V003, etc.), and all triggered formatting and memory comparison pipelines that day.

1.2 Review queue observation: re-review of an old proposal confirms the mainline already contains a similar fix (10-08)

Date: 2026-10-08 14:22 (Beijing time, re-review comment)　Source: PR #11499

No new merges occurred in the main repo during the window (the last mainline merge remains the network protocol stack at 10-03 12:59). Two developments among existing proposals: The author of the kernel synchronization linked-list logging guard proposal filed in June (#11499) noted in re-review that the conflict stems from an upstream commit (timeout wakeup ownership fix) that already added a null pointer check at the same location, meaning the mainline already includes that fix, and further disposition of the proposal awaits maintainer assessment. The DHCP packet header supplement proposal (#11835) triggered an automated memory comparison re-check with no substantive progress. In addition, the RISC-V major refactor proposal (#10320) saw no new comments during the window, with its most recent action still the rebase refresh on the morning of 10-08 (already covered in the holiday weekly report).

II. Official and Community Activities

2.1 〖2026 Embedded Competition〗Smoke and Fire Alarm Monitoring System project published (10-08)

Date: 2026-10-08 17:21 (publish time)　Source: Forum article 0e815ddfc029ea9c

Another complete project has been added within the 2026 Embedded Competition window: a smoke and fire alarm monitoring system based on the NXP FRDM-MCXA346 and kernel 5.2.2. The system uses MQ-2 to collect smoke concentration (ADC) and DHT22 to collect temperature and humidity (single-wire bus), implementing three-page OLED display switching, buzzer and relay linkage, long-press mute, hysteresis threshold debouncing with automatic recovery, and provides multiple MSH debug commands and a PC-side dashboard (real-time curves, CSV logging, remote test control). The solution adopts a three-layer structure of hardware abstraction, business logic, and display, along with an alarm state machine design, with Keil MDK-ARM as the development environment. This post continues the pace of密集 competition project releases since the end of the holiday — other projects in the same period include an intelligent laboratory management terminal, GD32H759 motor control, and an Edgi-Talk display configuration guide (already covered in the holiday weekly report).

III. Ecosystem and Vendor Adaptation

3.1 env Tool Merged #300: Offline SDK Software Packages Skip Git Updates (10-08)

Date: 2026-10-08 20:10 (merge time)　Source: env PR #300

A packaging management fix was merged into the env tool repository during the window (#300, single file +7/-0): manually managed offline software packages within the SDK lack an independent .git directory, causing Git commands to be mistakenly executed in the parent repository during package updates; the fix checks for .git in the software package directory before repository validation and skips offline source code, while remaining compatible with worktrees and submodules that exist as .git files. This entry was submitted by a community contributor and merged by the founder that evening, marking the toolchain repository’s first merge after the holiday (the previous being #299 merged on 10-04, enhancing WebUI and plugin workflows).

3.2 RT-Thread Studio: Five Commits for Gino Pi SDK, Adding LVGL 8/9 Dual-Version Support (10-08)

Date: 2026-10-08 16:30 ~ 17:31 (commit time)　Source: Gino Pi Board Support Package Repository

The Gino Pi board support package for RT-Thread Studio (GigaDevice GD32H77D, Cortex-M7 up to 600MHz, 32MiB SDRAM, 720×720 MIPI DSI display, based on kernel 5.3.0, with 17 built-in peripheral and application projects) received five concentrated commits during the window: the display framework was extended to LVGL 8/9 dual versions (selecting packages by version macro), a standalone LVGL 8.3.11 example was added, the version macro parsing order was corrected, the bundled GD32 SDK library was marked as unmanaged (to prevent erroneous updates by the package manager), and English documentation was synchronized with MDK project generation steps added. This board is a joint product that went on sale in the store on 10-01, with display and documentation capabilities rapidly completed on the SDK side after the sales window.

3.3 Packages: esp-idf Adaptation Repository Resumes Merging, Completing ESP32-C6 scons Build Source (10-08)

Date: 2026-10-08 17:28 (merge time)　Source: esp-idf PR #17

The chip adaptation package repository esp-idf completed a substantive merge during the window (#17, 4 commits, 332 files, +48463/-5146): the scons build source required for ESP32-C6 was completed, with the contributor verifying entry into msh after compiling and flashing on an actual ESP32-C6-DevKitC-1; this merge went into the rtt-dev development branch, marking the repository’s first resumed merge since late 2023. After merging, the maintainer proposed in comments to follow up with an ESP-IDF version update, and the contributor responded with plans to upgrade to 6.1. The Espressif C6 support chain (BSP merge, SPI on-demand compilation proposal under review, scons build source, package index version proposal #2043 under review) has been advancing continuously before and after the holiday, with multiple layers progressing simultaneously.

3.4 Vendor Downstream: GD32 Repository Opens New GD32G553 DMA Support Proposal #72 (10-08)

Date: 2026-10-08 10:44 (creation time)　Source: GD32 Downstream Repository PR #72

A new proposal was opened in the GigaDevice GD32 board support repository during the window (#72, single commit, 16 files, +2571/-50): complete DMA support for SPI, I2C, and UART was added for GD32G553, including DMAMUX configuration for I2C2, full UART0 ~ 5 channels, SPI G5x3 compatibility, and Keil compiler compatibility fixes; the author compiled with zero warnings under GCC and Keil, and I2C-AT24C02 EEPROM DMA was verified on actual hardware, with the test board being GD32G553Q-EVAL. On the day of submission, the compilation bot reported a BSP (gd32_arm) build failure, pending fix and review; the repository’s previous merge was on 09-28 (PR #71).

IV. Industry Applications

4.1 “Zhi Shou Tong Xing” Sign Language Teaching Robot Open-Sourced: MaixCAM2 + Titan Mini + AmazingHand (10-09)

Date: 2026-10-09 00:10 (Beijing time, project material release commit)　Source: Open-source repository asungod/amazinghand

topic:rt-thread ecosystem welcomes a new open-source sign language introductory teaching robot project “Zhi Shou Tong Xing,” with teaching applications and project materials released during the window. The system consists of three parts: the MaixCAM2 vision node handles hand keypoint acquisition and hand shape/course step determination; the Titan Mini control board (Renesas RA8P1 platform, running RT-Thread firmware) handles communication and mechanical action execution, with firmware including bus servo drivers, motion safety gating, and voice keyword recognition modules; the AmazingHand robotic hand performs physical demonstrations. The course comprises 13 items (3 beginner, 4 intermediate, 6 advanced), accompanied by a browser-based practice interface, step-by-step feedback, practice records, and text communication cards, along with technical reports, verification materials, and competition presentation materials; the project’s internal documentation also discloses current development boundaries (the vision node serial link has been verified on real hardware, the control board firmware has been compiled, and dual-board integration and servo closed-loop control are still in progress). A similar community project in this board direction was previously covered for on-device acoustic event detection (included in the 09-30 daily report).
