I. Kernel and Version Dynamics

1.1 Network Stack Security Fix: DHCP Server Option Bounds Check Merged, #11323 Closed (10-10)

Date: 2026-10-10 17:20 (merge time)　Source: PR #11858, Issue #11323

The buffer bounds check proposal for DHCP server option parsing (#11858, single file +63/-33, two commits — bounds check and clang-format cleanup) was merged into mainline by a maintainer, and defect ticket #11323 (out-of-bounds read of the packet buffer during option parsing, reported by a security researcher) was closed accordingly. The fix adds bounds validation before option parsing, eliminating the out-of-bounds read path; the case was opened on 10-08 and entered the merge slot after being digested through the post-holiday queue, marking the first security-class fix on the network side within the window.

1.2 Stack 8-Byte Alignment Fix for All STM32 BSPs Merged (10-10)

Date: 2026-10-10 17:20 (merge time)　Source: PR #11841, Issue #7527

The stack alignment fix for all STM32 BSPs was merged (#11841, author avm1234567, 110 files +220/-220): the .stack section in each BSP linker script and template was uniformly changed from ALIGN(4) to ALIGN(8), satisfying the ARM AAPCS requirement for stack pointer alignment at public function boundaries. The fix cites defect ticket #7527 opened in May 2023 (linker script issue across all STM32 BSPs; the ticket remains open and was not automatically closed with this merge).

1.3 C++ Global Construction Compatibility Fix Merged: cplusplus_system_init Now Walks .init_array (10-11)

Date: 2026-10-11 16:11 (merge time)　Source: PR #11856, Issue #11778

The C++ runtime compatibility fix was merged (#11856, author cms19859230182-lang, 4 files +60/-6): newer GCC places C++ global constructors in the .init_array section, while the existing initialization flow only scanned the ctors_start/ctors_end range, causing constructors to be skipped on some BSPs that do not merge that section; the fix additionally walks __init_array_start/__init_array_end (declared as weak symbols) and skips duplicate entries already falling within the ctors range. Related defect ticket #11778 (abnormal C++ automatic construction support on multiple BSPs) was closed.

1.4 USB CDC VCOM Ring Buffer Aliasing Defect Fix Merged, #11739 Closed (10-11)

Date: 2026-10-11 17:37 (merge time)　Source: PR #11770, Issue #11739

The USB CDC virtual serial port fix was merged (#11770, author Finder16, single file +47/-6, two commits): the old implementation attached the embedded ring buffer directly to serial_rx, and Serial V2 interpreted that pointer according to the serial FIFO structure — it appeared to work because the ring buffer happened to be the first member, but fields such as rx_cpt and rx_timeout were actually misaligned; the fix switches to a proper attachment and adds VCOM polled receive support. The case was opened on 08-29 and merged into mainline after multiple review rounds, with defect ticket #11739 closed.

1.5 utest Performance Test Clock Dependency Fix Merged (10-11)

Date: 2026-10-11 15:59 (merge time)　Source: PR #11813

The test framework fix was merged (#11813, author CYFS3, 2 files +8/-1): it fixes utest performance tests’ dependency on fixed clock timing and hardens the test build guard, reducing false positives across different board-level and simulation environments.

1.6 RISC-V Vector: vstart Restore Order Fix Proposal Enters Review (10-10 ~ 10-11)

Date: 2026-10-10 13:37 ~ 10-11 17:15 (creation and updates)　Source: PR #11861, Issue #11786

The RISC-V vector context fix proposal entered review (#11861, author PiyushPatle26, 4 files +187/-5): RESTORE_VECTOR previously restored vstart before vsetvl, but the vector configuration instruction clears it, causing the restart index to be lost; the fix moves the restore action after the configuration instruction and adds regression cases on qemu-virt64-riscv covering zero/non-zero vstart along with vl, vtype, and vcsr (assembly probes + C cases). A maintainer confirmed in the 10-11 review that the approach is correct, suggesting the test concurrency issue be resolved first and verification evidence added; the author pushed a revised commit the same day. The OSPP 2026 topic “RISC-V lazy FP/RVV context switching” (#11786) driven by the same author also updated its implementation plan within the window.

1.7 netdev ping Statistics Division-by-Zero Defect Claimed, Fix Proposal Newly Opened (10-11)

Date: 2026-10-11 22:10 ~ 23:05 (claim and proposal times)　Source: Issue #11852, PR #11862, PR #11853

The fix trajectory for the netdev ping defect advanced noticeably within the window: defect ticket #11852 (reported 10-05; when the target is unreachable, received is 0, and the average division triggers x86 SIGFPE / Cortex-M divide-by-zero, killing the shell thread) was claimed by contributor ymj0440 in a comment on the evening of 10-11, who promptly opened proposal #11862 (single file +1/-1); an earlier similar proposal #11853 (author r3wretrhy, opened 10-06) had already passed review (LGTM) on 10-07 but has not yet been merged. The two cases run in parallel, awaiting the maintainer’s choice.

1.8 Next RISC-V Major Refactor Proposal Refreshed Again Within the Window (10-10)

Date: 2026-10-10 19:18 (latest commit time)　Source: PR #10320

The major refactor proposal “Next RISC-V” (#10320, author GuEe-GUI, 166 files +15175/-2614) was refreshed again within the window: the head commit was updated to “[libcpu][risc-v] Refactor the RISC-V architecture port,” another push following the 10-08 rebase. The proposal has accumulated over one hundred comments, with integration scope covering S-mode RT-Thread / RT-Smart, Sv32~Sv64 MMU, AIA / CLIC / PLIC interrupt controllers, and T-Head platform consolidation, and remains under open review.

1.9 Two Follow-ups in the Review Queue: #11787 CI Investigation, #11815 Commit Refresh (10-10 ~ 10-11)

Date: 2026-10-10 ~ 10-11 (update times)　Source: PR #11787, PR #11815

Two follow-ups in the review queue: first, after a maintainer flagged a CI error on 10-11 for the Eclipse target generation script hidden-directory exclusion proposal (#11787), the author completed the investigation that evening — the failure was due to the pipeline environment lacking the scons command, unrelated to the exclusion logic itself; second, the author of the lwip section macro switch proposal (#11815) refreshed three commits on 10-10, incorporating configurable PBUF_RAM headroom along with lease removal and startup error handling fixes.

IV. Industry Applications

4.1 Community Research Project: K230 + RT-Thread Smart Kitchen Fire Detection Prototype Updates Handover Document (10-11)

Date: 2026-10-11 18:57 (push time)　Source: 1nuoiscute/SRTP-K230-Fire-Guardian

The community research project “SRTP K230 Fire Guardian” updated its handover document: the project is a university student research prototype for kitchen scenarios — K230 serves as the vision node (flame object detection), while RT-Thread Smart handles on-board control, multi-sensor fusion, and adaptive actuation. This commit points the default branch entry to the full development record branch and summarizes the board-level baseline and acceptance status: board-level identity for the vision node and KEY2 controller has acceptance records, KEY1 panel coverage and long-duration stability remain unresolved, and the board-side region-of-interest (ROI) feature has not yet been implemented; the project continues to publish intermediate records at a research pace.
