II. Kernel and security

2.1 Power management registration initializes before linking, allocation moved out of critical section (11-23)

Date: 2026-11-23 14:56 (merged). Source: #12075.

The original rt_pm_device_register() first linked the node into _pm.device_list, then filled in the device and ops fields. During that interval, the node in the list carried uninitialized pointers.

The second round of changes put both insertion and removal of _pm.device_list inside interrupt-disabled sections, while leaving RT_KERNEL_MALLOC and RT_KERNEL_FREE outside the critical section.

This trade-off is precisely the crux of issue #10075. The reporter had enabled RT_USING_SMP on RISC-V hardware and hung inside RT_KERNEL_REALLOC when calling the registration interface, because the allocation was wrapped inside the critical section.

The change touches the single file pm.c, with 39 lines added and 3 lines deleted. Issue #10075 was closed the same day as the merge.

Assessment: This is drawing the lock boundary correctly, not adding a coarser lock. The basis is that the fix does two things at once: initialization before linking is completed, and the allocation is instead moved out of the critical section.

2.2 DFS open failure now reports positive errno, v2 no longer returns false success (11-23)

Date: 2026-11-23 10:53 (merged). Source: #12067.

The two versions of the file system report different values on open failure. When the descriptor table is full, DFS v1 sets errno to -ENOMEM; DFS v2 directly returns 0, and the caller treats 0 as a valid descriptor.

The proposal reports failure causes separately: reaching the descriptor limit reports EMFILE, and table expansion or file object allocation failure reports ENOMEM. The shared allocator publishes the error value after unlocking.

POSIX open() uniformly returns -1 on allocation failure and writes the corresponding positive value into errno. A successful open can still return descriptor 0.

The change spans 6 files, with 108 lines added and 71 lines deleted. Of these, 60 lines are new test cases covering both file-not-found and table-full scenarios. The A9 DFS configuration file was also changed so that the native suite and POSIX suite can actually run.

The verification environment is qemu-vexpress-a9 with QEMU 7.2.22. The proposal notes the development machine is Intel macOS, with builds done in a Linux container.

Assessment: This fixes return-value semantics, not a single call site. The basis is that the change touches both versions of dfs.c and dfs_posix.c and adds regression test cases.

III. Drivers and frameworks

3.1 Pin interrupt compatibility path requires locking on both read and write ends (11-23)

Date: 2026-11-23 10:51 (merged). Source: #12040.

When the GPIO controller has no pin_attach_irq operation, pin_api_attach_irq() takes the compatibility path, writing hdr and args into legacy_isr in two separate steps. If an interrupt lands exactly between the two writes, the handler will pair the new handle with the old arguments.

The proposal puts both the write and the clear on the compatibility path under pin_irq_lock protection.

The maintainer gave a P2 comment on November 13, pointing out that locking only the write end is insufficient. Under SMP, disabling interrupts calls rt_cpus_lock(), which only locks the local core; a GPIO interrupt on another core does not hold this lock and may still read a half-set of arguments.

The change touches dev_pin_dm.c, with 26 lines added and 12 lines deleted. Ten days passed from the comment to the merge.

Assessment: This comment pushes the problem from “add a lock” to “who reads”. The basis is that the maintainer named the read end pin_pic_handle_isr(), not the write end.

3.2 Serial V1 reopen with changed transfer mode rejected (11-23)

Date: 2026-11-23 09:54 (merged). Source: #12073.

rt_serial_open() allocates the transmit and receive buffers only on the first open. On reopen it only updates open_flag and does not touch the already-allocated structures.

So if you first open with INT_TX and then reopen with DMA_TX, the buffer is still the 4-byte rt_serial_tx_fifo. But the DMA transmit path accesses it as struct rt_serial_tx_dma, reading out of bounds into data_queue.

The fix is to reject such a reopen with a changed mode. The change touches dev_serial.c, with 18 lines added and 12 lines deleted. Issue #12072 was closed the same day.

Assessment: This blocks an invalid call combination at the door, not completing buffer reallocation. The basis is that the proposal title itself says reject, and the body does no secondary allocation.

IV. Toolchain and documentation

4.1 klibc test case out-of-bounds copy corrupts stack on RH850 (11-23)

Date: 2026-11-23 09:51 (merged). Source: #12065.

TC_rt_memmove_too_long originally copied 11 bytes from a 6-byte source into a 10-byte buffer. The test case itself was out of bounds, and compiling with -O2 on RH850 corrupted the stack.

The fix makes both buffers 11 bytes and adds a check after the NUL so that a copy that stops early can also be detected.

The change touches src/klibc/utest/TC_rt_memmove.c, with 8 lines added and 5 lines deleted. The submitter is Parthiban Nallathambi, from Linumiz.

Assessment: This is a defect in the test case, not in the function under test. The basis is that the change only touches the test case file under the utest directory and does not modify the memmove implementation.

4.2 Raspberry Pi Pico documentation adds toolchain path (11-23)

Date: 2026-11-23 09:55 (merged). Source: #12069.

The README for bsp/raspberry-pico/RP2040 adds 12 lines explaining how to configure the GNU Arm toolchain installation path.

The change is documentation only, no code. The submitter is Daiyuanranfeng, with an email domain of openatom.club.

Assessment: This belongs to the same category as the macOS QEMU documentation fix in the previous period. The basis is that both only modify the README and both fill in path issues that block quick-start.

VI. Ecosystem and Vendor Adaptation

6.1 Allwinner V861 review lands on build reproducibility: clean checkout missing DTB (11-23)

Date: 2026-11-23 09:46 and 14:08 (review and reply). Source: #12077 review.

Maintainer Rbb666 left an inline comment on builtin_fdt.S. The first point is that a clean checkout has no board/board.dtb, and SCons does not invoke the generation script. The second point is that running scons directly per the README fails here with a file-not-found error.

The comment asks that DTB generation and dependencies be wired into the build, and that the full build be run once more from a clean directory.

The author replied “ok no problem” at 14:08. The five V861 proposals remain unmerged as of now.

Assessment: The review’s focus has shifted from functionality to build reproducibility. The basis is that this round of comments says nothing about driver logic, only about whether a clean checkout can compile.

6.2 ivshmem validation proposal closed by author, noted as covered by #11993 (11-23)

Date: 2026-11-23 16:31 (closed). Source: #12056.

The proposal was opened on November 14 to add non-zero, non-overflow, and architecture-adaptation validation for the shared memory address and length read from PCI configuration space.

The author closed it himself at 16:31. The reason is that master has already merged #11993 (43791bbf). That change routes BAR through trusted-window validation, and the JailHouse path in ivshmem_shmem_from_config first checks for configuration read failure, then performs range validation.

The exact wording was “the validation intent of this PR is already covered; closing to avoid duplication,” and the branch stopped at 990ebe7f.

Assessment: This is a duplicate proposal self-clearing, not a rejection. The basis is that the close was initiated by the author and points to the merged change that covers it.

6.3 rt-carplay adds Classic CarPlay metadata and keyframe recovery (11-23)

Date: 2026-11-23 09:31 to 14:18 (pushes). Source: rt-carplay.

This repo was covered in the previous issue and continues to advance today. Three commits respectively handle Now Playing artwork assembly over wired and tunneled iAP2, Classic Screen keyframe recovery on the event channel, and SDK integration docs plus interface convention cleanup.

The repo is a CarPlay receiver SDK written in C, GPL-3.0, structuring the protocol core and portable runtime as parts that do not depend on RT-Thread headers, then providing two host ports for RT-Thread and embedded Linux.

Assessment: This is a community project treating RT-Thread as a target runtime, not an official action. The basis is that the repo is not under the RT-Thread organization, and the README only describes host ports.

VIII. Summary and Trend Observations

8.1 Six merges cleared in one batch, not sporadic approvals

The six merges landed within two hours, all handled by the same maintainer. This pattern looks more like batching up enough items and then processing them together, rather than merging each one as it arrives.

8.2 Three commits came with closures of existing issues

#12075 closes #10075, which had been pending for two months; #12040 closes #11784; #12073 closes #12072. None of the three are new discoveries; they add fixes to already-registered defects.

8.3 The queue shows its first net decrease of this issue

The previous issue’s queue rose from 142 to 151; this issue it falls from 151 back to 144. Zero new creations is the other half of the reason for this decline.

8.4 The review gate has shifted from functionality to build reproducibility

The functionality of the five V861 proposals is already laid out; this round the maintainer asks only one thing: whether a clean checkout can compile. This kind of comment is harder to get around than a functionality comment, because it requires the submitter to reproduce it in a directory with no leftovers.
