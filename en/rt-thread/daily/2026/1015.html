I. Kernel and Version Updates

The main repository completed 9 merges and 1 RISC-V refactoring commit within the window, marking the densest merge batch in the past week; on the review side, 8 pending proposals and multiple bug tickets were updated in parallel.

1.1 New Submission to Next RISC-V Proposal: RISC-V Architecture Port Refactoring, Unified RV32/RV64 Common Layer (10-15)

Date: 2026-10-15 11:51 (commit time)　Source: PR #10320, refactoring commit 6bf3686

The RISC-V major refactoring proposal (#10320) pushed a large refactoring commit within the window, “[libcpu][risc-v] Refactor the RISC-V architecture port”: it introduces an optional RISC-V unified common layer (RV32/RV64), uses ARCH_RISCV and ARCH_CPU_64BIT for architecture and XLEN selection, unifies context, trap, MMU, cache, timer, SBI, SMP, and ISA handling, adds support for PLIC, CLIC, ACLINT, APLIC, and IMSIC, and establishes a mapping table from physical HART ID to logical CPU ID; the T-Head vendor override branch is retained. qemu-virt64-riscv becomes the first BSP to adopt the new common layer (the same directory supports both RV32 and RV64 S-mode), while existing BSPs that do not select the RT_USING_RISCV_NEW_COMMON macro continue to use the legacy_common / common64 paths. After the commit, automated workflows re-ran (format notification, review assignment, membrowse memory report); the RISC-V adjustment tracking ticket #11246 was refreshed in sync (11:52). The proposal remains open.

1.2 Network Stack Fix Batch Merged: ping Statistics Division-by-Zero and Last-Packet Delay Both Landed (10-14 ~ 10-15)

Date: 2026-10-14 09:33 ~ 2026-10-15 09:10 (merge time)　Source: PR #11853, PR #11866

The netdev component merged two ping-related fixes within the window: the first (#11853, merged 10-14) fixes a shell crash caused by division-by-zero in ping statistics when the target is unreachable, with the associated bug ticket #11852 closed the same day; the second (#11866, merged on the morning of 10-15) corrects the last-packet delay logic—the original loop condition was always false, causing an extra delay after the last packet, and when the delay was zero it still called rt_thread_delay(0), returning an invalid argument; the fix records actual elapsed time and only calls the delay for non-last packets when the delay is greater than zero, with the associated bug ticket #11865 closed the same day. An earlier proposal in the same direction, #11862, was closed without merging.

1.3 Kernel and USB Fix Batch Merged: calloc Overflow and USB host Interface Count Validation Hardened (10-14)

Date: 2026-10-14 09:28 ~ 10:17 (merge time)　Source: PR #11848, PR #11822

On the kernel side, a calloc integer overflow issue was fixed (#11848), submitted and merged by a community contributor. On the USB side, legacy USB host hardening was completed (#11822): addressing the bug ticket (#11288) where “the host directly trusts the interface count reported by the device, which can trigger out-of-bounds access,” an upper-bound check on the interface count and boundary handling in the interface enumeration and cleanup paths were added; both commits (interface count validation clarification, enumeration and cleanup finalization) were merged in sync, and the bug ticket was closed the same day.

1.4 Multi-Vendor BSP and Driver Batch Merged: ra6w1, ESP32-C3, STM32H723, RISC-V Vector Restore, etc. (10-14)

Date: 2026-10-14 09:13 ~ 09:44 (merge time)　Source: PR #11814, PR #11847, PR #11851, PR #11861, PR #11855

Maintainers merged multiple vendor BSP and driver updates in a batch: Renesas ra6w1 optimized system resource allocation (main thread stack adjusted to 4096, RC commit, #11814); Espressif ESP32-C3 fixed IRAM wildcard matching and Bluetooth linker script mismatching under Windows paths (#11847); STM32H723-DM-MC02 added SPI6 BDMA support (#11851); RISC-V vector unit fixed vstart state restoration after configuration (#11861); the components/drivers reset framework fixed a build error when enabled together with ulog (#11855).

1.5 Pending Proposals Receive Concentrated Maintainer Review: lwip Macro Control, ESP32-S3 BSP, rt_kprintf Fix, STM32 Ethernet ops (10-14 ~ 10-15)

Date: 2026-10-14 10:13 ~ 2026-10-15 09:22 (review time)　Source: PR #11815, PR #11844, PR #11864, PR #11819

Maintainers provided reviews on four pending proposals within the window: the lwip section macro control proposal (#11815) received a change request on the morning of 10-15 (the author had already pushed further changes on 10-14); the ESP32-S3 board support proposal (#11844), after the author responded to review feedback on 10-14, received a maintainer re-review with line-level comments on the morning of 10-15; the rt_kprintf implicit declaration fix proposal (#11864) received a change request—this case aims to fix abnormal %f log output in the IAR environment when the declaration is not included; the STM32 new Ethernet driver ops layer adaptation proposal (#11819) received a change request. All four cases remain open.

1.6 Other Pending Proposal Activity: clang-format Additional Commits, N32 Timer Proposal Reopened, ASan Proposal Supplementary Tests (10-14)

Date: 2026-10-14 09:46 ~ 12:27 (update time)　Source: PR #11859, PR #11812, PR #11772

The clang-format specification refinement proposal (#11859) added two commits: style rule fine-tuning (alignment, brace line breaks, and spacing) with thread.c demonstrating the actual effect; the N32 series timer completion proposal (#11812) was reopened by a maintainer—this case completes the shared driver branch for N32H47x/48x and H49x with accompanying ci-attach entries; the heap memory ASan proposal (#11772) author added clarification: new range checks for rt_memcpy, rt_memset, and rt_memmove with optional libc interface wrappers, completing boundary tests for out-of-bounds, use-after-free, and zero-length cases, with the latest CI reportedly all passing.

1.7 Old Bug Ticket Receives New Discussion: Direction for at_gethostbyname Overflow Handling Awaits Clarification (10-14)

Date: 2026-10-14 16:26 (comment time)　Source: Issue #5913

A heap buffer overflow report ticket created in 2022 (#5913) received a new comment within the window: noting that the discussion on overflow risk related to ip_str handling in at_gethostbyname has been shelved for over two years without conclusion, and suggesting the community clarify the handling direction—either limit the copy length or reject overly long hostnames—and designate a fix owner; if already resolved in another commit, adding the commit number would suffice to close the ticket.

II. Official and Community Events

2.1 Industrial Expo AI Car Workshop Recap Published: A New Sample of Edge AI Deployment (10-15)

Date: 2026-10-15 11:50 (article publication)　Source: EET China

EET China published a recap of the RT-Thread Industrial Expo AI edge intelligent car Workshop: the on-site hands-on session on 10-13 was conducted with participants in pairs using dozens of intelligent car teaching kits, walking through the full workflow of hardware detection, system boot, peripheral debugging, real-time control, SLAM mapping, autonomous navigation, camera calibration, multimodal visual following, and AR comprehensive exercises, with on-site debugging of LiDAR, IMU, and depth cameras; the article also elaborates on its AIOS hybrid deployment concept—AI inference runs on the Linux side while high-reliability real-time control is handled by the RT-Thread kernel, with the two domains not interfering with each other; the event also showcased robots, drones, industrial control equipment, and other products built on the same foundation, with contact channels for solutions provided at the end. The article cites cumulative installations exceeding 2.5 billion units.

2.2 [2026 Embedded Competition] “Shuheng Zhiyang” AI Visual Acupoint Therapy Robotic Arm Project Post Published (10-15)

Date: 2026-10-15 08:32 (publication time)　Source: forum post a2a82aa707bc2966

The 2026 Embedded Competition project post “Shuheng Zhiyang · Adaptive Multimodal Therapy Robotic Arm” was published: the lower-level controller uses a GigaDevice GD32H759I-EVAL (Cortex-M7, 600MHz) as the main controller, running RT-Thread to handle concurrent multi-peripheral communication and real-time motion control; the K230 vision side extracts 17 sets of human skeletal keypoints in real time and computes 3D coordinates of acupoints such as Neiguan, Tiantu, Zhongwan, and Quchi; the main controller performs inverse kinematics solving and then drives a four-DOF bus servo robotic arm to execute biomimetic massage acupressure, supporting adaptive following of subtle body movements; dual-path control is provided via a local Taojingchi touchscreen and cloud-based Web, Qt PC, and Android multi-terminal interfaces, with the cloud configured with SpringBoot services and integrated with DeepSeek intelligent consultation; safety mechanisms include angle limits, parameter validation, state machine management, and emergency stop.
