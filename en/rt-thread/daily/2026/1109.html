I. Kernel and Version Dynamics

1.1 K230D merged: 128MB DDR variant gains ext4 and ptyfs (11-06)

Date: 2026-11-06 09:37 (merge time)　Source: PR #11897, PR #11892

15 files, 398 insertions, 198 deletions, submitted by maintainer BernardXiong, opened on October 18 and merged this issue. The content is a complete BSP fill-in: adds a choice between SOC_K230 and SOC_K230D, rearranges the default memory layout for 128MB DDR; registers GPIO as an RT-Thread pin device, adding 140 lines to the driver in one go, plus GPIO tests; enables the ext4 root filesystem, mounting ptyfs and procfs; removes a batch of unused board-level peripheral definitions. The toolchain remains the K230 SDK’s riscv64-unknown-linux-musl, and the ABI is still lp64d.

The weight of this one lies in its dependencies: it requires the RISC-V MMU and XuanTie architecture fixes from #11892 first (the item in section 1.2 of the previous report), and also needs the lwext4 package; the ptyfs and procfs mount points are precisely the prerequisites for the RT-Smart terminal and device tree export. In other words, K230D is not an isolated board addition, but rather strings together the batch of Smart fixes from 11-05 on a real RISC-V board with 128MB of memory. CI has not yet given a build conclusion; the author only compiled locally with the K230 SDK toolchain.

1.2 STM32F1/H7 input capture lands: 746 lines complete four timer channels (11-06)

Date: 2026-11-06 09:20 (merge time)　Source: PR #11975, Issue #11967

9 files, 746 insertions, zero deletions. The issue was raised on November 2; previously the forum had only a personal implementation, and four days later the driver entered mainline. The implementation uses STM32 HAL’s TIM1 through TIM4 as input capture devices, with configurable channels, filters, and initial capture polarity; it handles three platform differences: APB timer clock multiplication, TIMPRE, and 32-bit counters; pending capture and over-capture flags are cleared before restarting a capture channel.

CI covers two boards: the STM32F103 battleship board runs the inputcapture snippet, and the STM32H743 Nucleo runs the full configuration. For users, filling in this kind of peripheral framework expands applicability more than fixing kernel defects—input capture is a common path for motor control, encoders, and pulse measurement.

1.3 Correction of CPU time accounting for non-SMART builds (11-07)

Date: 2026-11-07 21:39 (merge time)　Source: PR #12001

Only two lines changed in src/clock.c: the user-mode time accounting branch is wrapped in RT_USING_SMART. Previously non-SMART builds also went through this logic, so thread time was counted as user-mode time, and system time and idle time statistics were correspondingly understated. A two-line change that affects the CPU usage readings of all non-Smart projects.

1.4 Format specifier fixes in GIC print functions (11-08)

Date: 2026-11-08 16:20 (merge time)　Source: PR #11914

3 files, 71 insertions, 48 deletions, modifying gic.c, gicv3.c, and gicv3.h. Four categories of issues: printing 32-bit physical addresses with %p, where passing a non-pointer to %p is undefined behavior; printing unsigned quantities with %d; a missing type cast for the GIC version number; and a signed left shift in the GIC RWP macro. The PR was opened on October 21 and merged on November 8; the author is Wei-beep, with maintainer Rbb666 as co-author. Compiling Cortex-A BSPs with -Wall -Wformat no longer spews warnings. This kind of cleanup does not affect functionality, but it directly affects the compilation cleanliness of vendor BSPs.

II. Security and libc Fixes

2.1 Two timerfd Checks Merged the Same Day (11-08)

Date: 2026-11-08 14:12 / 14:11 (merge time)　Source: PR #11996, Issue #11984, PR #11997, Issue #11980

Two commits landed one minute apart, each touching a single file.

The first is fd type validation in timerfd_settime and gettime: the original implementation dereferenced the private data of any file descriptor as a timer struct, so passing in an ordinary file or pipe caused the kernel to read the struct as the wrong type. The fix compares the file operations table first and only fetches the private data once confirmed to be a timerfd — DFS v2 checks df->fops, v1 checks vnode->fops; 25 lines added.

The second is an array out-of-bounds in POSIX timers: timer_gettime and timer_settime indexed _g_timerid directly with the user-supplied timer_t, while timer_delete already had a bounds check. The fix adds a check that id must be less than TIMER_ID_MAX; 19 lines added.

Both defects appeared in the security lists of the previous two reports; this issue they move from reported to fixed. timerfd and POSIX timer are both user-controllable handles, and the failure pattern is identical: dereference first, then check type or range.

2.2 picolibc Prototype Alignment: Array Parameters in asctime_r and ctime_r (11-08)

Date: 2026-11-08 14:01 (merge time)　Source: PR #11999

ctime.c: 13 lines added, 3 deleted. picolibc declares the buffer as a restricted array of length 26, while RT-Thread declared it as a pointer, producing both array-parameter and null-pointer-comparison warnings; other C libraries still use the pointer form, so the fix switches the declaration per library via conditional compilation. Author: Parthiban Nallathambi of Linumiz.

This is listed separately because it unblocks another thread: the Renesas RH850 port proposal explicitly states that utest CI must wait for this ctime.c fix — see 4.3.

2.3 RISC-V FPU Context Switch Defect: Fix Proposal Four Hours After Report (11-07)

Date: 2026-11-07 23:10 (report) / 2026-11-08 03:14 (proposal)　Source: Issue #12005, PR #12006

The one to watch this issue. Reporter boa-z, while porting ArtInChip D213 (C906, M-mode), found fs1 incorrect after a thread switch. To rule out BSP factors, they reproduced it on the official qemu-virt64-riscv: QEMU 10.0.13, OpenSBI 1.6, RV64D, single hart, master c63d7bc9. They wrote a test case that checks floating-point registers across switch types, confirming two problems.

The first is voluntary switching, i.e. rt_thread_yield: SAVE_CONTEXT and RESTORE_CONTEXT save only integer callee-saved registers, so two threads using floating point overwrite each other’s fs0 through fs11. The report gives measured values: expected 0x3ff0000100000000, got 0x3ff0000000000000. The second is timer preemption: SAVE_ALL saves f0 through f31 but not fcsr, so the floating-point rounding mode and exception flags are silently altered. This class of bug does not crash — it just makes results drift slowly.

Maintainer BernardXiong proposed #12006 four hours later: append fs0 through fs11 and fcsr to the switch frame, add fcsr save/restore to the trap frame, round the switch frame size up to guarantee 16-byte alignment, and initialize fcsr for frames constructed for interrupt switches; offset and layout macros are added to context_ext.h and stack.h accordingly. The proposal is still under review with no on-hardware verification recorded. Given RISC-V’s weight in RT-Thread, this one should be merged with priority.

  • Touch framework tests (#12002), Bouffalo ADC channel validation (#12003), dlmodule regression (#11989), utest multi-round runs (#11983), and ulog output call sites (#11987) are all under review; the first four belong to the test infrastructure thread — see 4.1.

3.2 Wuzhen Summit: Heterogeneous Converged Edge Intelligence AIOS Base selected for “Xinguang” list (11-02)

Date: 2026-11-02 (event) / 2026-11-06 09:52 (publish)　Source: Official news

On November 2, the 2026 World Internet Conference Wuzhen Summit opened under the theme of openness, openness, and shared building; the concurrent Light of the Internet Expo gathered more than 670 companies from 54 countries and regions. RT-Thread Ecosystem Director Li Yan presented “Virtualized Hybrid Deployment Embodied Intelligence Solution · AI Kit” at the expo, and the company’s self-developed RT-Thread Heterogeneous Converged Edge Intelligence AIOS Base was selected for this year’s “Xinguang” product recommendation list.

The technical description of the base still follows hybrid deployment: AI inference runs on the Linux side, real-time control on the RT-Thread side, with the two sides running independently so that anomalies on the AI side do not affect the control side, and control precision reaching the microsecond level; it is paired with the vmRT-Thread virtualization platform and the AI Kit toolchain. Embodied intelligence is explicitly named as the deployment scenario—multiple systems hybrid-deployed on the same hardware, respectively handling the brain’s compute elasticity and the cerebellum’s temporal determinism.

3.3 RISC-V China Summit: edge AI full stack, automotive-grade software already tested on vehicles (10-18)

Date: 2026-10-18 to 10-20 (event) / 2026-11-06 09:59 (publish)　Source: Official news

The 6th RISC-V China Summit was held at the Futian venue of the Shenzhen Convention and Exhibition Center, featuring 1 main forum, 7 parallel sub-forums, and a Member Day. RT-Thread technical expert Zhang Bingru spoke at two sub-forums—Embedded IoT Intelligent Hardware and Automotive Electronics/Industrial Robots—with the titles “From Models on Chips to Agents Entering the Scene: RT-Thread’s RISC-V Edge AI Full-Stack Practice” and “RT-Thread and RISC-V in Real-Time Control for Automotive and Robotics” respectively.

The core judgment of the first talk is a shift in focus: edge AI has moved from whether models can run to whether agents can reside stably under constrained compute and real-time constraints. The approach is to shield kernel differences downward with a unified BSP and driver framework, carry offline wake-up, voice interaction, and multimodal inference upward with a lightweight runtime, and place AI tasks and real-time tasks within a single scheduling system to prevent AI from preempting real-time performance.

The second talk delivered two hard advances: automotive-grade base software has been applied to RISC-V chips and completed on-vehicle testing, and is now moving toward mass production; the Chengxuan vehicle control system can provide RISC-V with complete AUTOSAR CP base software, covering system services, storage, communication, diagnostics, calibration, and information security, along with configuration and code generation tools. On the robotics side, RT-Thread Smart has completed adaptation of dozens of ROS2 C/C++ software packages on SoC-level chips. The adaptation scope is stated as having started in 2018, covering more than 100 chips and BSPs licensed by IP vendors such as Nuclei, XuanTie, and Andes, with the kernel natively supporting SMP and AMP.

IV. Ecosystem and Vendor Adaptation

4.1 QEMU Virtual Device Checklist Advances: SPI Loopback, CAN, SDIO, DAC/I2C Enter CI (11-06)

Date: 2026-11-06 to 11-08 (merge time)　Source: Issue #11972, PR #11979, PR #11990, PR #11752, PR #11758

This is the most systematic thread of the period. Issue #11972 is a checklist of QEMU virtual devices and coverage, and its background is stated plainly: per the release plan in #11955, Z releases rely mainly on QEMU plus CI to automatically test the kernel, components, and drivers within the scope of emulation support, aggregating coverage, pass rates, and known issues so maintainers can decide whether to release. The checklist lists utest and QEMU checkboxes item by item per framework, covering more than twenty items including adc, dac, i2c, spi, can, pwm, rtc, watchdog, timer, touch, audio, usb, sdio, flash, ethernet, wlan, pin, serial, and ipc.

Four PRs landed within the window:

  • SPI virtual loopback bus (#11979, 6 files, 154 lines): registers a pure-software SPI bus, default name spi2, using memory copies for loopback transfers, so qemu-vexpress-a9 can run SPI loopback cases even without a PL022 model; adds a matching utest configuration and CI matrix entry.
  • QEMU jobs for DAC and I2C (#11990): adds one utest configuration each, split into two independent jobs in the workflow.
  • CAN transmit/receive test (#11752, 1792 lines): a 1572-line test case file with 22 host stub scenarios, covering timeout renewal, tick wraparound, empty reads, error propagation, and normal reception; the author reproduced the original duplicate-frame and mismatched-frame hangs using a 50-tick timeout plus a 1000-tick watchdog.
  • SDIO block device read/write test (#11758, 438 lines): 372 lines of test cases, with validation limited to formatting and whitespace changes, without a full BSP build.

Two more PRs still under review belong to the same thread: the touch framework test (#12002) makes interrupt enable and disable return error codes and runs two consecutive rounds in QEMU using simulated operations; the dlmodule regression (#11989) generates real ARM ELF modules at build time, with 10 test cases covering relocatable objects, shared objects, symbol import/export, and repeated load/unload. Test infrastructure is shifting from scattered case additions to a checklist organized around the release process—a prerequisite for the Z release cadence.

4.2 Two WCH Threads: Nuclei Fast Interrupt Configuration and CH32V208 Low Power (11-07)

Date: 2026-11-07 to 11-08 (PR time)　Source: PR #12004, PR #12007

WCH’s RISC-V Nuclei cores are inconsistent on fast interrupts: support varies by model, and models with only two hardware interrupt levels should not use fast interrupts. PR #12004 configures the corresponding core capabilities per chip series, adds a fast interrupt switch, and unifies the interrupt attribute macros, so supported chips use fast interrupts while the rest fall back to normal interrupts; it also updates the SDK and adjusts the CH32V203 startup file. Validation boards are CH32V208W-R0 and CH32V307V-R1.

#12007 adds PM component support for CH32V208 and depends on the previous PR being merged. Both remain open. WCH is one of China’s largest RISC-V MCU vendors by shipment volume, and a BSP’s power management and interrupt configuration directly determine usability in low-power scenarios.

4.3 Renesas RH850 G4KH Port Proposal: A Third Architecture Beyond ARM and RISC-V (11-06)

Date: 2026-11-06 20:41 (PR time)　Source: PR #11998

libcpu/rh850 uses TRAP0 for thread switching, including nested interrupts, FPU context, and fault dumps; bsp/renesas/rh850 provides startup, interrupt controller, OSTM and RLIN3 serial drivers, plus the qemu-rh850-u2c board; CI covers both hard-float and soft-float builds plus kernel utest. The validation record is concrete: GCC 14.3 with picolibc toolchain v1.1.0, qemu-rh850 v1.0.0, msh starts, kernel_basic 22/22, and memory and ipc cases pass.

The PR is still marked draft because the utest CI needed ctime.c fixed under picolibc first; #11999 merged this period, removing that prerequisite. RH850 is a common architecture in automotive-grade MCUs, and RT-Thread has previously focused on ARM and RISC-V—if this PR merges, it amounts to validating the utest and libcpu abstractions on a third architecture.

4.4 Env Adds “Format Changed Files Only” Command (11-06)

The env repository had only one commit in the window: adding the cmd_format_changed command, with README, command registration, pyproject, and entry point updated together. Its purpose is to format only the files changed in this round, working with the repository’s clang-format flow to avoid whole-repo formatting introducing unrelated diffs. A small tool, but a direct help for commit cleanliness.

However, two programmatic documents for Z-version CI have appeared—the version management process in issue #11956 and the QEMU virtual device list in #11972—both ending in manual approval for release. The next observation point is whether these two lists can actually run end-to-end on QEMU.

  • Catching up on external communications: after a hiatus of more than four months, the official news feed published seven articles at once, stringing together September’s elexcon, mid-September’s automotive salon, October’s CIIF and RISC-V Summit, and early November’s Wuzhen Summit into a single line.
