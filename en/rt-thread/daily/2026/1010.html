I. Kernel and Version Updates

1.1 First Post-Holiday Merge to Main Repo: ulog Colored Log Fix Lands, #11296 Closed (10-09)

Date: 2026-10-09 08:58 (merge time)　Source: PR #11857, Issue #11296

The first post-holiday merge has landed in the main repository: the colored log reset ordering fix proposal (#11857, single file +64/-41, two commits) was merged into mainline by maintainer Rbb666, marking the repository’s first merge since 10-03. The change adjusts the ulog tail formatting order—writing the color reset code first, then the newline—resolving the issue where color control codes spilled onto the next line and corrupted shell prompt coloring, and includes a clang-format cleanup commit. The related defect ticket #11296, opened in March, was closed with the merge. The proposal was submitted by pre-holiday active contributor cms19859230182-lang, who also has three other cases under review (#11855 / #11856 / #11858).

1.2 New Proposal: clang-format Rule Refinement, with thread.c Formatting Example (10-09)

Date: 2026-10-09 10:31 (creation time)　Source: PR #11859

Contributor CYFS3 opened a formatting rule consolidation proposal (#11859, two commits, two files +106/-99): the first commit adjusts alignment, brace line-breaking, and spacing rules; the second fully formats src/thread.c as an example file under the new rules for intuitive comparison. The author explained the motivation in comments—recent proposals have all required follow-up formatting commits, dragging down review efficiency and commit logs—hoping the rules can be consolidated soon so the entire repository can be formatted in one pass; maintainer wdfk-prog approved (LGTM) on 10-10 08:41. This case connects with the late-September adjustment “formatting commits no longer skip CI,” marking the repository’s formatting standards entering a consolidation phase.

1.3 New Proposal: aarch64 GIC Acknowledge Path Removes Redundant Pending Clear (10-09)

Date: 2026-10-09 11:20 (creation time)　Source: PR #11860

Contributor Xenithya opened a kernel architecture fix proposal (#11860, single file -3 lines): removes the redundant pending bit clear (GIC_DIST_PENDING_CLEAR) write and corresponding mask calculation from the aarch64 GIC acknowledge function (arm_gic_ack), retaining only the EOI write. The proposal was submitted with mature-version self-checks and entered the review queue after creation at 11:20 that day, with no further comments within the window.

1.4 Under-Review Proposal Iterations: #11856 / #11858 Rewritten Commits, #11844 Refreshed (10-09)

Date: 2026-10-09 11:18 ~ 23:02 (commit times)　Source: PR #11858, PR #11856, PR #11844

Post-holiday cleanup continued within the under-review queue window: first, #11858 (DHCP server option bounds check) added a clang-format cleanup commit and unified both commit messages to English (11:18); second, #11856 (C++ global constructors adding .init_array) was rewritten with English commit messages late at night (23:02); third, the ESP32-S3-DevKitM-1 support proposal #11844 (opened 09-28, refreshed multiple times during the holiday) was updated again in the evening as a single commit (23:00). Meanwhile #11855 (reset and ulog coexistence build fix) saw no substantive progress within the window and remains in the review queue; all the above cases remain open.

1.5 Proposal Cleanup: #11816 Closed, Superseded by #11847 (10-09)

Date: 2026-10-09 14:50 (close time)　Source: PR #11816, PR #11847

The ESP32-C3 Windows path matching proposal (#11816, opened 09-21) was closed by the author on 10-09 14:50 (not merged): the author had previously explained that this case and #11847 address the same change, with #11847—redone against the then-current master—taking precedence, and added on-device (ESP32-C3 DevKitM-1) flashing verification notes. Both cases target the issue where GNU ld backslash paths under Windows cause linker script glob mismatches and abnormal IRAM section placement; #11847 remains open and is listed as under review.

RT-Thread Edge AI Car Workshop at the Industry Expo—Final Seats Await,” a near-term reminder of the 10-05 recruitment piece (already covered in the National Day weekly): the event remains scheduled for October 13 (Tuesday) 13:00–17:00 at the 26th Industry Expo at the National Exhibition and Convention Center (Shanghai), with teams of 2, 25 smart car teaching kits, and 50 slots; the hands-on flow covers hardware detection, system boot, SLAM mapping, autonomous navigation, camera calibration, and multimodal visual following. 2.2 Forum Technical Share: MCU HardFault On-Site Diagnosis Series Opens (10-10)

Date: 2026-10-10 09:43 (feed timestamp)　Source: Forum post 9834ccd63b766dfd

A new long-form technical post on the forum, “Fishing the Scene Out of HardFault: Cortex-M Crash Diagnosis (Part 1)” (author: 大目熊): centered on the key registers automatically pushed onto the stack when Cortex-M enters an exception and the SCB status registers, it explains how to read and print the fault scene at the HardFault entry, so that MCU crashes can report the error location like PC programs; the article provides a path for determining three types of trigger causes from HFSR (such as vector table fetch bus errors), and previews that Part 2 will cover recovering the full call chain from the stack. A companion video by the author (Bilibili) is linked at the end.

IV. Industry Applications

4.1 Community Open Source: GD32H7 Multi-Function Environmental Monitoring Data Logger Complete Project Released (10-09)

Date: 2026-10-09 22:43 (repository creation time)　Source: jxgfc/rt-thread-gd32h7-environment-monitor-keil

A community developer released a complete open-source project based on GD32H759I-EVAL — a multi-function environmental monitoring and local data logger: the tech stack is RT-Thread 5.3.0 and LVGL 8.3.11, with a Keil MDK project that compiles out of the box; features cover SHT40 temperature/humidity, BH1750 ambient light, SGP30 equivalent CO2 and TVOC acquisition, a 480×272 RGB touchscreen with Chinese UI (home / curves / settings / history), threshold-based audible and visual alarms, RTC time setting, and FAT32 SD card CSV logging; the project notes indicate Ethernet and TCP upload are not yet enabled. This adds another practical application-oriented reference project to the GD32H7 platform.
