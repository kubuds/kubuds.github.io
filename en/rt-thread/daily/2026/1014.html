I. Kernel and Version Dynamics

No new commits or merges in the main repository during the window: the latest master commit remains the Eclipse project generation fix from the morning of 10-12 (#11787), with roughly 45 hours of no merge activity since. Review and collaboration activity remains active: five open proposals and two older defect tickets all saw updates during the window, with community validation efforts concentrated on RISC-V refactoring and memory safety.

1.1 Next RISC-V Major Refactor Proposal Advances Through Community Testing: QEMU Configuration Guidance Clarified, ESP32-C3 Hardware Patch Verified (10-13)

Date: 2026-10-13 10:54 ~ 23:52 (comment and test times)　Source: PR #10320

The RISC-V major refactor proposal (#10320) saw four rounds of community interaction during the window: first, a contributor submitted a test report on five QEMU configurations, in which the “S-Mode with device model disabled” combination failed to link due to missing common boot and SMP scheduling symbols; second, maintainers clarified the platform adaptation approach — device model and no-device-model are mutually exclusive (qemu-virt64-riscv belongs to the former, while d1/d1s and smartl/e907 belong to the latter), and the tester adjusted test case allocation accordingly; third, that evening the contributor verified two companion patches on ESP32-C3 hardware (bsp/ESP switched to the new common RISC-V code path), reporting that both C3 and C6 compile successfully with zero warnings. The proposal remains open.

1.2 Heap Memory ASan Proposal Gains Additional Commits: libc Access Checks and Boundary Cases (10-13)

Date: 2026-10-13 15:25 (commit time)　Source: PR #11772

The heap memory runtime AddressSanitizer proposal (#11772, opened in late August) received additional commits during the window: building on the existing heap instrumentation runtime and QEMU CI coverage, it extends checks to libc memory accesses and adds boundary cases. The proposal uses GCC kernel-address instrumentation for memory accesses, with a runtime capable of detecting heap buffer overflows and use-after-free, and provides FinSH interactive commands for viewing diagnostic information. The proposal remains open and pending review.

1.3 lwip/WLAN Control Proposal Expands with Commits: Four Sets of Updates Covering DNS, DHCP, Buffers, and WLAN Lifecycle (10-13)

Date: 2026-10-13 14:27 ~ 16:08 (commit times)　Source: PR #11815

The lwip segment macro control proposal (#11815) expanded during the window from a macro-control topic into four sets of commits with two force pushes: first, cleaning up DNS configuration when disconnecting in STA mode; second, optimizing DHCP startup logic; third, configuring lwip buffer options and reserving PBUF tailroom; fourth, synchronizing WLAN AP lifecycle and direct-receive path handling. The proposal’s scope has expanded from compile-macro cleanup to network stack behavior fixes, and remains open.

1.4 ESP32-S3 BSP Proposal Completes Automated Review Fixes, Requests Manual Re-review (10-13)

Date: 2026-10-13 12:02 ~ 12:42 (comment times)　Source: PR #11844

The ESP32-S3 board support proposal (#11844) completed automated review fixes during the window: the author addressed Copilot review comments by correcting mutex macro expansion and UART0 interrupt allocation levels, and added notes on floating-point and AI instruction limitations; the remaining build check failure was determined to be a pre-existing upstream issue unrelated to this case, and the author explicitly requested manual re-review, with a maintainer responding that they would take a look later that day. The case has been open since 09-28 and refreshed multiple times, with this being substantive progress within the window.

1.5 Keil/IAR Target Selection Proposal: Author Responds to Two Re-review Comments, Remains Open (10-13)

Date: 2026-10-13 16:34 ~ 17:38 (comment times)　Source: PR #11743

The Keil/IAR target auto-selection proposal (#11743) responded to two re-review comments during the window: regarding the question about a “missing targets initialization loop,” the author noted that the relevant path and macro concatenation code had already been added and the issue does not exist; regarding the issue of an invalid –config_def symbol mixed into the IAR link configuration field, the author raised a discussion that each entry in that field is automatically prefixed by the IDE, so LINKFLAGS should not carry configuration definitions again, seeking maintainer confirmation. The proposal remains open.

1.6 Two Older Defect Tickets Picked Up by Community: Serial POSIX Control Parameters and DAC Documentation Example (10-13)

Date: 2026-10-13 22:13 ~ 22:17 (comment times)　Source: Issue #5073, Issue #6568

Two older defect tickets were picked up by community members during the window: serial POSIX interface ioctl unable to set underlying parameters (#5073) — after checking, a contributor noted that the previously associated proposal only covered some scenarios and the issue still exists in dfs_v1, and expressed intent to take over the ticket; DAC device driver documentation example issue (#6568) — the fix has been merged and the documentation center parameter description updated, with the contributor proposing further corrections to the documentation presentation format.

II. Official and Community Activities

2.1 Virtualization Hybrid Deployment Teaching Platform Article Published: RK3588 Single-Chip Dual-Domain Running Linux and RT-Thread (10-13)

Date: 2026-10-13 (media publication date)　Source: EE Times China original article

EE Times China published a feature on the RT-Thread virtualization hybrid deployment teaching platform: Rockchip HyperCar runs Linux/ROS 2 and RT-Thread dual-domain simultaneously on a single RK3588 chip, with HyperBoot handling boot, isolation, and resource allocation. The two domains collaborate via virtual networking and micro-ROS — the Linux side handles perception, decision-making, and application orchestration, while the RT-Thread side handles hard real-time chassis execution. The platform includes 16 case studies across four module categories — basic control, mapping and navigation, vision services, and robotic arm — along with a three-stage training path, and offers comprehensive case studies on local large model deployment and six-axis robotic arm grasping.

2.2 [2026 Embedded Competition] GD32H759IM USB Secondary Display + OV2640 Camera 2-in-1 Project Post Published (10-13)

Date: 2026-10-13 17:43 (publication time)　Source: Forum post 76ffa34214c0eda4

2026 Embedded Competition project post “GD32H759IM USB Secondary Display + OV2640 Camera 2-in-1” published: built around GD32H759IMK6, running RT-Thread 4.1.1 and LVGL 9.5, it turns a 4.3-inch 480×272 RGB screen into a computer’s second display via USB high-speed port; the firmware integrates TLI display, EXMC SDRAM, DCI camera, and USBHS0, providing three modes — PC monitoring dashboard, screen mirroring, and camera streaming — with a Python tool on the host side; under -O0 build, Flash is approximately 354 KB and RAM approximately 84 KB.

2.3 [2026 Embedded Competition] GD32H7-Based Multifunctional Environmental Monitoring and Local Data Logger Project Post Published (10-13)

Date: 2026-10-13 08:37 (publication time)　Source: Forum post 248f9e54e367993d

2026 Embedded Competition project post “GD32H7-Based Multifunctional Environmental Monitoring and Local Data Logger System” published: using GD32H759I-EVAL as the platform, RT-Thread 5.3.0 and LVGL 8.3.11, it collects temperature, humidity, light, equivalent CO2, and TVOC via SHT40, BH1750, and SGP30; the Chinese touch interface supports value viewing, threshold adjustment, trend browsing, and history review, with data periodically written to SD card as CSV, accompanied by a PC-side offline parsing tool; targeting local monitoring scenarios such as greenhouses, server rooms, and laboratories, the current version does not include networked upload.

III. Ecosystem and Vendor Adaptation

3.1 New packages Index Proposal: hpm_sdk v1.13.0 Package Index Opened, Upstream Tag Released Same Day (10-13)

Date: 2026-10-13 17:07 (creation time)　Source: PR #2045 (RT-Thread/packages), rtt-pkg-hpm-sdk v1.13.0

New proposal opened in the package index repository (RT-Thread/packages): adding a v1.13.0 index for HPMicro hpm_sdk — introducing the PKG_USING_HPM_SDK_V113 configuration and corresponding download entry, with the default version remaining v1.10.0 and requiring explicit selection; v1.13.0 adds support for the HPM5100 series (HPM5151 / HPM5100EVK) and synchronizes peripheral driver updates across series. The corresponding package repository rtt-pkg-hpm-sdk released the v1.13.0 tag on the same day (16:05). The proposal remains open.

3.2 Third-Party GDB Debugging Framework GDR Releases 2026.04: Adds Adapter Auto-Detection and Auto-Initialization (10-13)

Date: 2026-10-13 15:58 (publication time)　Source: GDR 2026.04 release page, project repository

Third-party GDB debugging assistance framework GDR released 2026.04: adds adapter auto-detection — gdr probe provides exact / range / undetected confidence levels based on matching symbols, version source, and layout fingerprint, while gdr init auto only auto-selects when there is a single definitive answer; simultaneously mounts the VSIX artifact of VS Code extension 2026.4.0. The framework interprets RT-Thread kernel objects within the debugger, supports 3.1.x / 4.0.x / 4.1.x, with RV64 verified since 4.0.4 and Cortex-A9 verified on real hardware; it is a third-party ecosystem reference.

Other ecosystem channels remained silent within the window: the env tool repository (last merged 10-09), packages index (last merged 09-24), and Studio SDK index (last updated 10-10) all had no pushes within the window; GD32 vendor downstream gd32_rt-thread had no new activity (last 10-10), and pushes within the window from repositories under the same organization in the Zephyr direction are outside the scope of this issue.
