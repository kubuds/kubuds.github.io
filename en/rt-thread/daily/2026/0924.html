I. Kernel and Version Updates

1.1 clang-format auto-commits no longer skip CI: formatting pipeline merged into routine validation (09-23)

Date: 2026-09-23 16:30 ~ 16:34 (Beijing Time, creation and merge time)　Source: PR #11830, merge commit

The mainline merged a continuous integration workflow adjustment within the window: the “skip CI” marker was removed from the commit message of clang-format auto-formatting commits, so that formatting commits now trigger the CI pipeline just like regular commits. This marker was originally used to avoid the loop of “auto-format commit triggering another CI round,” at the cost of formatting results entering the repository without build validation; after the adjustment, formatting actions are incorporated into the routine validation chain. The corresponding workflow file is the sole changed file in this proposal, which was submitted by a community contributor and merged approximately four minutes after creation.

1.2 Two new proposals added to review queue within window: netdev build fix and GD32H77D peripheral series (09-23)

Date: 2026-09-23 11:05 / 15:41 (Beijing Time, proposal time)　Source: PR #11828, PR #11829

Two new proposals were opened in the review queue within the window. The first is a small-scope fix for the network component (#11828, netdev AF_NETLINK build error): it adds a forward declaration for a struct and changes the node index reference in the route notification callback from a temporary variable to directly accessing the list node, fixing compilation errors when the relevant configuration combination is enabled, involving two files. The second is a large-scale vendor board-level proposal (#11829) — the GD32H77D GinoPi board peripheral series, with 19 commits and 142 files, detailed in Chapter III, Section 3.1.

II. Official and Community Activities

2.1 RSOC26 summer camp tutorial series systematized: “Chapter 1: Development Environment, BSP Configuration, and Device Model” updated within window (09-23)

Date: 2026-09-23 15:22 (Beijing Time, update time)　Source: forum article 5a5a1f34db847d92

The community forum updated an RSOC26 tutorial within the window, “Chapter 1: Development Environment, BSP Configuration, and RT-Thread Device Model,” providing a complete mainline from scratch to device model: installing RT-Thread Studio and deploying kernel source and chip support packages via the SDK manager; creating a project using the “chip-based” approach (Spark-1 platform STM32F407ZG, kernel 4.1.1, USART1 console, ST-LINK and SWD debugging); analyzing the BSP project directory structure and the responsibilities of board.c / board.h (clock tree 168 MHz, system tick, heap boundaries); explaining the three-layer architecture of the I/O device model and the GET_PIN pin numbering mechanism; and completing compilation, flashing, and FinSH (MSH) command-line verification with a GPIO heartbeat LED and serial printing. This piece, together with previously scattered Spark-1 practice articles, forms a chapter-based arrangement, serving as the systematized opening of the summer camp tutorial series.

III. Ecosystem and Vendor Adaptation

3.1 Gino Pi mainline BSP proposal enters review: 19 commits, 142 files for the GD32H77D peripheral series (09-23)

Date: 2026-09-23 15:41 (Beijing time, proposal time)　Source: PR #11829

The board support for GigaDevice’s GD32H77D board Gino Pi has been submitted for mainline review as a series proposal: 19 commits on a single branch, 142 files, with a net addition of roughly 26,000 lines. The content spans three layers: the board-level skeleton (project, linker script, rtconfig); a full peripheral suite—Ethernet, USB host and device, SDRAM, hardware I2C, SPI3, PWM, SDIO and filesystem, RTC and alarm, watchdog, CAN and CAN FD, OSPI Flash, MIPI LCD, GT911 touch, OV7670 camera, and LVGL; and the GinoPi peripheral demo project plus a full-BSP compilation check hook. It also includes Wi-Fi and MQTT support for the onboard GD32VW553 wireless module; the commit notes state that the module’s UART4 AT communication and MAC query have been verified, Wi-Fi association is still pending, and the module and examples are disabled by default. This board had previously completed Studio SDK indexing, release, and debugging-chain completion (see 3.2); this installment is a substantive step “from vendor SDK toward mainline,” and it is currently under review.

3.2 GD32 device support packages and Wi-Fi component synchronized across three repos: H77x_78x device/peripheral libraries and GD32VW553 networking support (09-23)

Date: 2026-09-23 16:01 ~ 16:10 (Beijing time, push time)　Source: gd32-arm-cmsis commit, gd32-arm-series commit, at_device commit

On the same afternoon as the mainline proposal, three repositories under the RT-Thread device support package organization completed preparatory updates in succession: the CMSIS device support package (gd32-arm-cmsis) and the GD32 peripheral library support package (gd32-arm-series) each added GD32H77x_78x support, providing a CMSIS device layer and new peripheral library for H77-series chips; the AT component repository (at_device) added GD32VW553 Wi-Fi device and TCP socket support, enabling this wireless module to connect to the network component via the AT channel. The three commits were pushed within the same time window as the mainline BSP proposal, constituting a synchronized landing of the Gino Pi software stack.

3.3 Triple merge in the package index: CanopenNode v1.2.0 configuration refactor, new virtual sensor package, AI Agent gains MQTT tool (09-24)

Date: 2026-09-24 09:23 ~ 09:25 (Beijing time, merge time)　Source: CanopenNode v1.2.0 merge, virtual sensor package merge, AI Agent configuration merge

The package index repository merged three proposals in a concentrated fashion within the window (all submitted between September 11 and 14, with review completed within the window): the first is CanopenNode v1.2.0, refactoring 9 Kconfig files and consolidating the previous CiA 401 device worker switches into a general device profile system—adding a pure-C, heap-allocation-free logical device registry decoupled from the real-time system, along with a profile controller transport contract and an RT-Thread master transport option, advancing the configuration structure of the industrial bus component toward modularity. The second is a new “virtual sensor” package: it provides simulated sensor data generation, optionally reported via MQTT (depending on the paho MQTT and cJSON components), targeting joint debugging and teaching scenarios without hardware, with the package source pointing to a standalone repository maintained by the author. The third is a configuration update for the AI Agent package: it adds an MQTT tool and configuration items such as the broker address, and introduces an automatic detection mechanism for rt_vsnprintf capability—using “whether the kernel has already defined this symbol” as the criterion (rather than applying a version number), automatically deciding whether to enable the full-featured formatting package, avoiding link failures caused by duplicate definitions on 4.1.x kernels while ensuring full capabilities such as floating-point formatting remain available.

3.4 Renesas RA8P1 Titan Mini OpenMV adds RGB LCD display and vision examples (09-24)

Date: 2026-09-24 09:42 (Beijing time, commit time)　Source: commit 98076cf8, Titan Mini OpenMV repository

Under the Studio BSP organization, the Renesas RA8P1 Titan Mini repository pushed a feature commit within the window (17 files, roughly 1,200 lines added): it connects the onboard RGB interface 800×480 screen (RGB565) for the OpenMV project, completes the LCD driver and the MicroPython lcd module, and synchronously adjusts display adaptation, NPU, and runtime-related files as well as machine modules such as machine_pin / machine_pwm; on the example side, it adds two vision examples—basic LCD display (color bars, text, graphics, 2x scaling, and backlight adjustment) and camera preview with red color-block tracking—with the backlight managed uniformly by the LCD (occupying GPT7). This project had previously completed the OpenMV release pipeline and performance optimization (already covered on 09-18 and 09-22); this installment shifts from performance wrap-up to display and example expansion, further completing the on-device vision demo pipeline.
