RT-Thread Weekly Report (2026-09-30 ~ 2026-10-07)

2026-10-07 Kubuds

Reporting period: September 30, 2026 (Wednesday) to October 7, 2026 (Wednesday), 8 days total; special National Day holiday summary period (October 1–7 is the holiday, daily reports paused) Sources: This publication’s daily RT-Thread updates (one issue on 2026-09-30, window 09-29 11:00 ~ 09-30 11:00; no daily report material during the 10-01 ~ 10-07 holiday); also includes holiday-window organizational checks (main repository commits / PRs / Issues / Releases, env, package index, Studio and device package organization, vendor downstream, topic searches), official news feeds and community forum scans, and media and aggregator channel reviews (coverage through the morning of 10-08) Editorial note: This period spans the National Day holiday—code merges entered a low-output mode during the holiday, while review and validation, package preparation, and community operations continued to run; all technical facts come from actual verification of code repositories, release records, and community channels

I. Weekly Highlights

  • Next RISC-V major refactor continues multi-platform real-world testing over the holiday, founder follows up to push it forward (09-30 ~ 10-08): The long-pending RISC-V architecture refactor proposal for the main repository (#10320), created in late May, entered a “test-driven” phase over the holiday — community testers validated it round by round across four platform categories: XuanTie virt64/c906, qemu-virt64-riscv (RV64 quad-core), XuanTie smartl/e907, and Allwinner D1/D1s. First, the qemu-virt64 default AIA configuration got stuck at PCI with NVMe timeouts (reported 10-02, fixed that same evening); on 10-03, retesting the default configuration entered msh three consecutive times with NVMe working normally. Next, the fallback issue when the RV64 standard build lacked an ABI environment variable was fixed (automatically selecting lp64d based on FPU, 10-03). Patches for e907 and D1/D1s adaptation were provided in turn, with patching and build verification completed (D1/D1s had no development board and were not flashed on real hardware; the author requested board assistance on 10-07). Founder Bernard Xiong commented and liked on 10-03 and asked for a status checklist to be compiled going forward; the proposal was rebased on the morning of 10-08 onto the latest mainline including the lwIP merge (head e7b6e13f0). 42 new comments were added within the window (including bot checks), and the proposal remains under open review. It now spans 164 files, +15164/-2611.

  • lwIP 2.2.1 merged into mainline (10-03) — the only merge during the holiday: Main repository PR #11797 was merged by the founder: lwIP 2.2.1 was added as an optional version (coexisting with 1.4.1 / 2.0.3 / 2.1.2, without forcing existing projects to switch), with 4 commits, 402 files, +162255/-45; the original source tree was imported, documentation files were cleaned up, and the sio_write signature conflict was fixed; the verification platform was the NXP i.MXRT1180 evaluation board (m7 core); the corresponding requirement #11588 (filed 2026-07-08) was closed the same day. The “network stack upgrade” that had sat in the review queue for multiple weeks landed in this period.

  • RT-Thread Env merges WebUI and plugin development workflow enhancements (10-03 ~ 10-04): The Env tool completed a feature merge focused on developer experience (PR #299, submitted by the founder, merged on the evening of 10-04) — adding a WebUI project homepage, build, documentation, and network settings interfaces; introducing the epack testing and marketplace publishing workflow, plugin image icons and workspace startup requirements, and a shared network policy; accompanied by command failure exit code propagation, venv dependency installation instructions, and a VS Code remote browser bridge. Env is evolving from a command-line tool toward “visualization + pluginization.”

  • Holiday development continues uninterrupted: 4 new proposals opened, multiple reviews refreshed (10-01 ~ 10-07): A C-only Picolibc build option for qemu-virt64-riscv (#11849, 10-01), STM32F103C6 support for blue-pill (#11850, 10-02), SPI6 BDMA support for the STM32H723 board (#11851, 10-03), and a divide-by-zero fix for netdev ping statistics (#11853, 10-06) were opened in succession; multiple pending proposals in the ESP32 and STM32 families (#11816 / #11847 / #11844 / #11819 / #11841) were refreshed on 10-06 ~ 10-07.

  • Two package index proposals: ESP32-C6 package versions and the “ms-probe” diagnostic tool prepared for inclusion (10-06 ~ 10-07): Two proposals were added to the index repository — Espressif ESP32-C6-related package versions (#2043, early morning 10-07) and the official diagnostic tool “ms-probe” (#2044, 10-07; Microscope embedded fault-scene diagnostic Probe, dual-licensed under GPL-2.0 and commercial, exporting context on the device side and parsing the scene and whitelisted memory on the host side). Both await review; the index mainline saw no new merges during the holiday.

  • Community operations converge on “competitions and recruitment”: Industry Expo Workshop recruitment, Edgi-X Challenge, embedded competition entries (10-05 ~ 10-08): The Industry Expo RT-Thread Workshop (October 13 Shanghai session) opened recruitment on 10-05 with a preview of physical displays of multiple categories of intelligent terminals; RT-Thread, together with Infineon and FMT, announced the “Edgi-X All-Domain Vehicle Adaptation Challenge” (announced 10-08, based on Infineon PSoC-E83 heterogeneous dual-core autonomous driving controller platform, with no restriction on vehicle type); 2026 embedded competition entry posts appeared densely toward the end of the period (intelligent laboratory management terminal, GD32H759 BLDC motor control, Edgi-Talk LVGL guide, etc.).

  • Official channels remain silent through Day 49 (09-30 ~ 10-08): The official news API saw zero additions throughout the period (the latest archived post remains 2026-06-17, with the continuous hiatus extending from Day 32 to Day 49); the official website news list page still cannot be directly verified. External information is primarily conveyed through forum, media, and store channels.

II. Kernel and Version Dynamics

Versions and Mainline

  • No new releases: The latest official version remains v5.3.0, released on 09-10; no new Releases or tags across the entire window, currently in a post-release digestion period.
  • Merge cadence: Only one merge during the holiday, on 10-03 (4 commits, all belonging to lwIP 2.2.1); the mainline was completely silent from 09-30 to 10-02 and from 10-04 to 10-07, the calmest pace in recent months.
  • Toolchain and supporting components (Env): On 10-03 to 10-04, WebUI and plugin development workflow enhancements were merged (PR #299, 11 commits, merged 10-04 21:25) — four WebUI interface types (project homepage, build, documentation, network settings), epack testing and marketplace release flow, plugin icons and network policies, command exit code propagation and venv dependency documentation, VS Code bridge; development tooling enters a visualization and plugin-based iteration phase.
  • Toolchain and supporting components (Studio): No pushes to the RT-Thread-Studio component organization across the entire window (most recent was the Titan Mini repo on 09-24); for a review of historical entries related to the 09-30 daily report, see Chapter III “Verification Notes.”

This Week’s Merge: lwIP 2.2.1 (the only one)

  • Merge info: PR #11797 “[Components][lwip]Add lwip-2.2.1 support,” authored by Tim-Wang38, created 2026-09-11, merged by the founder on 10-03 12:59; 4 commits, 402 files, +162255/-45.
  • Commit composition: Imported the lwIP 2.2.1 original source tree; integrated as an “optional item coexisting with 1.4.1 / 2.0.3 / 2.1.2” (existing projects are not forced to switch); cleaned up lwip documentation files; fixed the sio_write signature conflict.
  • Verification info: NXP i.MXRT1180 evaluation board (m7 core), configured with BSP_USING_ETH / RT_USING_SAL / RT_USING_NETDEV / RT_USING_LWIP.
  • Related: Requirement #11588 “Request to update the lwip components to version 2.2.1” (raised 07-08) was closed with the merge; the network component completed a major version expansion.

Security and Defects

  • netdev ping statistics divide-by-zero defect and fix (10-05 to 10-06): netdev_cmd_ping still performs integer division avg_time/received when the target is unreachable and all timeouts occur (received is 0), triggering a divide-by-zero that crashes the shell; the defect report (#11852, 10-05) and fix proposal (#11853, 10-06, 1 file, +1/-1, changed to check the receive count first) were filed in succession and are under review.
  • calloc overflow fix (#11848): Passed review on 09-30 with no further action during the holiday, awaiting merge.
  • ofw phandle hash out-of-bounds fix (#11845): No new activity within the window (most recent update 09-29).
  • blue-pill documentation defect (#11818): Updated interaction on 10-03 (README quick start missing steps to regenerate the MDK project), still not closed.

Review Queue Observations

  • Most active item remains #10320: 42 new comments within the window (including bots), cross-platform testing on four platform types, two fixes, and multiple rebases; rebase and CI refresh completed on the morning of 10-08 (head e7b6e13f0, base c3e94f7b5).
  • 4 new items opened during the holiday (details in Highlights): F103C6 (#11850, 7 files, +122/-13) and SPI6 BDMA (#11851, 20 files, +876/-2566) are board-level support, while C-only Picolibc (#11849, 2 files, +6/-0) and the ping divide-by-zero (#11853, 1 file) are build and stability fixes.
  • Refreshed and awaiting review: Two ESP32-C3 Windows path matching items (#11816 / #11847, 10-07), ESP32-S3-DevKitM-1 BSP (#11844, 10-06), STM32 Ethernet ops adaptation and log levels (#11819, 10-07), ARM AAPCS 8-byte stack alignment (#11841, 10-07).
  • Overall picture: 1 merge versus 10 active proposals under review across the entire window, a clear “low merge, high review” pattern during the holiday period.

III. Ecosystem and Vendor Adaptation

Vendor BSPs

  • ST-series small-capacity and board-level peripherals advance: The STM32F103C6 (32KB Flash / 10KB RAM) support proposal for blue-pill (#11850) and its companion requirements (#11854, 10-07) were opened; the SPI6 BDMA support proposal for STM32H723-DM-MC02 (#11851, 10-03) includes allocation of the WS2812 BDMA buffer in SRAM4 and synchronization of GCC / IAR / MDK5 linker scripts.
  • Espressif series continues to be refined: ESP32-C3 and ESP32-S3-DevKitM-1 proposals were refreshed over the holiday (#11816 / #11847 / #11844); on the package side, a C6 package version proposal was also filed (see below).
  • RISC-V board-level and architecture adaptation: Adaptation verification for XuanTie C906 / C907 / E907 and Allwinner D1 / D1s ran throughout the holiday (associated with #10320); the C-only Picolibc build option proposal for qemu-virt64-riscv (#11849) was opened — the RISC-V platform is advancing simultaneously at both the “board support” and “build system” levels.
  • Vendor downstream and device packages: The latest merge in the GD32 downstream repository (gd32_rt-thread) remains 09-28 (PR #71); no pushes occurred in the device support package organization during the window (most recent being gd32-arm-series on 09-23).

Packages and Middleware

  • ms-probe onboarding preparation (official tool): The tool repository (Real-Thread/ms-probe) completed “standalone packaging” preparation on 10-07 — importing Microscope embedded diagnostics, adding standalone RT-Thread package metadata and checks, completing index integration preparation and VExpress A9 testing, and merging the standalone packaging PR #1; on the index side, this is being advanced via the feature/ms-probe-package branch plus PR #2044. Positioned as a fault-site diagnostic Probe: device-side context export, host-side scene parsing and whitelisted memory; dual-licensed under GPL-2.0 and commercial.
  • ESP32-C6 package version proposal (#2043, early morning 10-07): A new proposal for ESP-IDF C6-related support was filed in the form of a “package version addition,” currently under review.
  • No merges to the index mainline: The package index main branch was quiet over the holiday (most recent merge 09-24); several other proposals remain pending review in the queue (litetype, CmBacktrace versions and configuration, DS1307 RTC, ADS1146, HSM state machine, am2320, etc.).
  • Middleware: lwIP 2.2.1 (see Chapter II); no other component merges.

IV. Official and Community Activities

  • Edgi-X All-Domain Vehicle Adaptation Challenge officially launched (10-08): Initiated by RT-Thread in partnership with Infineon and FMT — Edgi-X is a professional-grade autopilot hardware jointly developed by the three parties (Infineon PSoC-E83, Cortex-M55 + M33 heterogeneous dual-core), open to any vehicle type (multirotor, fixed-wing, unmanned boat, wheeled rover, wheel-legged robot, etc.), inviting developers to complete adaptation and real functional validation using their own vehicles; prize money is available, and hardware is gifted upon completion; aimed at engineers, robotics developers, university labs, and maker teams.
  • RT-Thread Workshop at the Industry Expo opens recruitment (10-05): Recruitment has opened for the RT-Thread Workshop at the 26th China International Industry Fair (October 12–16, National Exhibition and Convention Center (Shanghai)) (October 13 special session); the recruitment notice previews on-site displays of a wide range of intelligent terminal hardware including robots, drones, industrial control equipment, and boards.
  • A surge of 2026 RT-Thread Embedded Competition project posts (10-06 ~ 10-08): Smart lab management terminal (ArtInChip D12x + RT-Thread 4.1.1 + LVGL v9, including PC relay and Bluetooth door lock control); BLDC motor control on GD32H759I-EVAL + RT-Thread Nano (Hall six-step commutation, six-channel complementary PWM, host-side waveform monitoring); Edgi-Talk LVGL landscape display configuration guide.
  • Forum and community content: The technical post “MCU Linker Script ‘Upgrade’” was updated in the early hours of 10-08; FH8626V300L development board trial report (dual always-on power mode and servo PWM testing, 10-05); the Gino Pi launch post remained updated over the holiday (10-01).
  • Media channels: EE Times China published “From Cloud to Edge, Build an AI Car with Your Own Hands! RT-Thread Workshop at the Industry Expo Opens Recruitment” (10-05); it also carried the community technical share “Multi-channel ADC Acquisition Device Based on Ruiqing RC3506” (09-30, covering acquisition expansion board, display, and networking porting highlights).
  • Official channels: For the official news interface and website verification status, see item seven of the highlights; no other valid reports were seen on public aggregation channels during the holiday.

V. Industry Applications and Business Trends

  • K230 and RT-Thread Smart firefighting prototype continues to iterate (09-30 ~ 10-01): The kitchen flame detection, multi-sensor fusion, and adaptive linkage research prototype (SRTP-K230-Fire-Guardian) saw six consecutive commits over the holiday, advancing KEY1 / KEY2 panel sequence debugging and on-board acceptance records.
  • RV1103 single-chip drone prototype hardware design iterates intensively (10-01 ~ 10-06): The Linux and RISC-V MCU flight control loop prototype (Luckfox Pico Mini B) added an LTE + GNSS stacking board (LFX_LTE_R1), a 50×50 single-board flight controller (LFX_FC_R2), a frame adapter board (LFX_MOUNT_R1), and a 1503 motor frame (LFX_FRAME_R1), supplementing the GPS port (ATGM336H-class module) and the remote control / ground station sections.
  • Industrial robot communication gateway engineering core made public (10-02 ~ 10-03): The community published a gateway development record covering RT-Thread integration highlights such as Modbus RTU/TCP interfaces, CANopen message handling, fixed-length memory pools, queues, and priority inheritance (including CI release verification).
  • Commercial deployment: No new mass-production, commercial, or partnership deployments were reported during this period (the holiday); the nearest industry-side milestones are the October 13 Industry Expo Workshop and the Edgi-X Challenge after the holiday.

VI. Trend Observations

  • The holiday took a “low merges, high verification” shape: Only 1 merge occurred across the entire window, but multi-platform real-device testing of #10320, two fixes, and CI refreshes ran throughout the period, with the code side operating around a main axis of “verification and review.”
  • RISC-V architecture refactoring enters a testing-driven phase: The verification matrix expanded from XuanTie C906/C907 and QEMU virt64 to E907 and Allwinner D1/D1s, with “code review” advancing toward “multi-platform bring-up”; physical boards are becoming the next bottleneck (board assistance for verification has been requested for D1/D1s).
  • Network components and development tools land on two tracks: lwIP 2.2.1 was merged in a “coexisting optional” manner, while Env strengthens the development experience with WebUI and plugin workflows — pointing respectively to the two evolution lines of “component modernization” and “tool visualization,” both premised on not breaking existing projects.
  • The package ecosystem focuses its preparation on “official tool entry” and “wireless chip support”: ms-probe completed the last-mile preparation before onboarding, and the ESP32-C6 package version proposal reappeared — the holiday was a preparation window on the index side.
  • Community operations converge on mid-October milestones: The Industry Expo Workshop (10-13), the Edgi-X Challenge, and a dense wave of embedded competition project releases make the two weeks after the holiday a peak for operations and showcases.
  • Official channels fall deeper into silence: The news interface has now gone 49 days without an update (zero updates for the entire period), with external information increasingly relying on forum, media, and store channels — a contrast with the continuous operation on the code side.
