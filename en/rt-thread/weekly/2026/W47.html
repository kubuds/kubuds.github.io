I. Weekly Highlights

  • RT-Smart user-space boundary issues closed out in four places in one week (11-16 ~ 11-17): The four are concentrated in ptyfs, ivshmem, block device partitions, and FinSH completion. They are, respectively: deregistration not releasing file objects, the shared window being determined by the device, ioctl directly writing user pointers, and unbounded copying in path completion. All four were merged this week. The ptyfs one provided quantitative verification: comparing before and after 20,000 open/close cycles, the pre-fix version lost 7232 KB, roughly 369 bytes per cycle. After the fix, only 40 KB of fluctuation remained. The ivshmem one added a default-off JailHouse compatibility switch. The block device one switched to a user-space copy-back interface, writing no bytes when the pointer is invalid. The FinSH one took 53 days from report to fix, and only 3 days from proposal to merge.

  • Complete PoC for mailbox handle privilege escalation (11-19): Issue #11960 points out that sys_mb_send and sys_mb_recv bypass the LWP object ownership table. The RT_ASSERT in the mailbox implementation only reads the type field in the struct, which cannot stop forged objects. The reporter, on qemu-virt64-aarch64, changed the target qword from 0x74003e2f2068736d to 0x1122334455667788 and was able to read it back with the same call. Fix proposal #12015 modifies ten files, +1440/-126, replacing handle resolution with “look up the object table and take a reference.” As of publication, it has still not been merged.

  • Device control commands fully re-encoded (11-18): #11881 moves nine generic commands from 0x01 through 0x09 to 0x2001 through 0x2009, closing issue #5073 raised in September 2021. The conflict is that fcntl’s F_GETFL and CONFIG are both 3, and F_SETFL and CLOSE are both 4. The new encoding uses the class number in the high byte and the in-class index in the low byte. The commit only synchronizes 14 files in the repository, leaves no compatibility macros, and the verified BSP field is empty.

  • Three old issues assigned CVE numbers (11-16): The GPT partition entry underflow received CVE-2026-38160. The FinSH prompt format string received CVE-2026-50961. The AT socket parser stack overflow received CVE-2026-106729. The three issues were closed on 11-04, 04-09, and 09-21 respectively. The numbers were filled in on the same morning, part of wrapping up the disclosure process rather than new fixes that day. On the same day, the CherryUSB maintainer drew a boundary: no checks below 1.7.0.

  • ArtInChip D213 board package merged in three days (proposed 11-14, merged 11-17): 30 files, +1783 lines, centered on the T-Head C906, RV64GC, 128 MiB DDR3. The submitter is the same person who reported the RISC-V floating-point defect last week. He first hit incorrect fs1 after a thread switch on his own board, reproduced it on the official QEMU, fixed it, and then came back to submit the board package.

  • Seven package index entries in one week, Agent package reconfigured twice (11-16, 11-18): The six entries on 11-16 include Agent configuration item rearrangement (+416/-37), Wi-Fi and Bluetooth host drivers (+672, proprietary license), and the ms-probe diagnostic package. The other three are WS2812 LED strips, a multi-strip SPI driver, and multi-instance support for the infrared framework. The third entry on 11-18 adds an A2A channel and hierarchical memory to the Agent (+378/-212). Both times only Kconfig was changed, not the package itself.

  • Windows toolchain aligned with CI (11-16): The Env repository switched its bundled clang-format to 22.1.8 and upgraded the Arm GNU toolchain to 13.3.Rel1. 22.1.8 is exactly the formatting version used by the main repository’s CI. Previously, local formatting on Windows and the CI criteria could differ by a major version, so format check failures gave no visible reason. The last substantive change to this repository was Env 2.1.0 on 09-08.

  • Official channels silent for two full weeks, December events scheduled (11-19): The official news feed has had zero additions for ten consecutive issues; the latest is still the batch of five articles from 11-06 15:54. Dual-city salons were announced for Beijing on December 12 and Shenzhen on December 19, where RT-Thread AI Kit will be released on site. Security and Defect Closure

Date and source: Issues and proposals from 2026-11-16 to 2026-11-20, taken from the main repository’s issue list.

  • ptyfs unregister leak (#12029, merged 11-16): The unregister function only removed the pts from the root linked list and reclaimed the number; struct ptyfs_file was never freed. An unprivileged process could repeatedly open and close /dev/pts/ptmx to exhaust kernel memory. The fix completes four lifecycle points: freeing the object, initializing pts_unit to -1, correcting the release order on the creation-failure path, and skipping devices that were never registered. 3 files, +60/-6. Affects v5.1.0 through master; introduced by 83e95bdf (2024-03-28).
  • ivshmem shared window (#11993, merged 11-16): The JailHouse compatibility fallback when BAR2 is missing directly copied device configuration words 0x40 through 0x4f. The PCI core does not validate this, so the kernel could map in an arbitrary physical window. The fix adds an RT_IVSHMEM_JAILHOUSE option, off by default, three range checks before mapping, 64-bit local variables, and return-value checks. 2 files, +122/-7, 10 days in review.
  • Block device partition privilege-escalation write (#11981, merged 11-17): RT_DEVICE_CTRL_BLK_PARTITION treated a user raw pointer as the destination of rt_memcpy. It also failed to set err to success. When the caller received “failure,” the target memory had already been overwritten. The fix first copies into the kernel stack under LWP, then copies back with lwp_put_to_user. 5 files, +294/-59. Reported 10-29, proposed 11-03, merged 14 days later.
  • FinSH path completion (#12057, merged 11-17): msh_auto_complete_path did not guard the fixed-length buffer when concatenating the current directory with user input; an overlong path could write out of bounds with a single Tab press. The fix is only +5/-0, truncating directly on overlong input. Defect #11839 was reported 09-25, 50 days from report to proposal.
  • iso9660 directory name underflow (#12061 and #12062, early morning 11-17): When the directory record namelen is 0 or 1, the subtraction stripping the “;1” suffix underflows on unsigned numbers. The subsequent rt_strncpy then becomes an out-of-bounds write. Reported 01:46, proposed 02:03, 17 minutes apart. The fix limits namelen to the local buffer capacity and only strips the suffix when it is at least 2. 11 lines added. Affects v5.2.0 through v5.3.0 and master; introduced by 42a41c69.
  • serial_v2 DMA alignment (#12063, reported 11-17, unfixed): The rx fifo struct, ring buffer, and DMA ping buffer are obtained from a single allocation. On 32-bit M7 the struct is 44 bytes, so the ping buffer always lands at 12 mod 32. The driver invalidates D-cache in 32-byte lines, dropping dirty data below and over-invalidating adjacent heap blocks above. On STM32H7 this manifests as tx fifo’s buffer_ptr becoming NULL, asserting on the next write. The report provides a framework-level fix and a self-assessed CVSS of 4.6 to 5.3; it was claimed 4.5 hours later.
  • Mailbox handle privilege escalation (#11960 and #12015): See the second item in Top Stories for the defect mechanism and PoC. The fix proposal was pushed to commits on 11-19 11:36, 10 files, +1440/-126, not merged.
  • Serial V1 reopen mode out-of-bounds (#12072 and #12073, added on release day): Reported 11-20 13:27. When a device opened with INT_TX is reopened with DMA_TX, the 4-byte tx_fifo is treated as a 48-byte rt_serial_tx_dma, causing a heap out-of-bounds and an illegal function pointer call. 12 minutes later the same author submitted #12073, 1 file, +18/-12, rejecting cross-mode reopen with -RT_EBUSY. Both fall after the Friday daily’s window.

Architecture and Device Layer

Date and source: Three proposals from 2026-11-16 to 2026-11-20, numbered #11881, #12052, and #12068.

  • Command encoding (#11881): The base-address macro is computed as class number plus one, then multiplied by 0x100. The old mask only looked at the low 5 bits and is incompatible with the new encoding; the author grepped the whole repository, confirmed there were no callers, and removed it. Of the 14 files following the change, eight are efm32 board-level drivers. On the header side, dev_pin.h and dev_serial_v2.h were changed to enums, and rt-link’s rtdef.h added 34 lines. Out-of-tree BSPs or software packages that hard-code the old values will hit the wrong branch after upgrading.
  • STM32 input capture (#12052): Granularity drops from physical timer to channel. CH1 through CH4 of TIM1 through TIM4 can each be registered as independent devices, sharing the counter and HAL handle. Two exclusive modes are added: PWM Input and dual-edge. +1540/-285, proposed 11-12, merged 5 days later.
  • Device lifecycle lock (#12068, under review): Adds RT_USING_DEVICE_LIFECYCLE_LOCK, off by default. When enabled, each device uses its own priority-inheritance mutex to serialize initialization, open-mode decisions, reference-count updates, and driver callbacks. This responds to the ref_count corruption in #11234; test case is 229 lines.
  • dfs errno (#12067, under review): When the descriptor table is full, DFS v1 reports -ENOMEM in errno, while DFS v2 returns 0. Callers would treat 0 as a valid descriptor. The fix reports EMFILE or ENOMEM on allocation failure, and POSIX open returns -1 with a positive errno on failure. Test case +60 lines.
  • Build tooling (#12070, #12069, under review): A group library’s local compile flags are applied twice, registering two SCons actions for the same object. The fix compiles as a normal group first, then archives. This corresponds to issue #4417 from March 2021. Pico’s README adds the RTT_EXEC_PATH override syntax.
  • Positioning of Serial V1: A maintainer comment on 10-22 argued for freezing V1 as historical compatibility only and shifting serial focus toward V2. A reply on 11-20 06:54 confirmed that V1 must still accept fixes. This week #11909’s actual fix is 5 lines (34d2a002), with an additional 622-line clang-format (87b851b4) inflating the diff. The test case uart_rx_timeout.c is 226 lines and does not depend on hardware.

Community Projects and Competitions

Dates and sources: Repository creation and columns from 2026-11-15 to 2026-11-17, drawn from the grand prize project breakdown and boa-z/rt-carplay.

  • Grand prize breakdown (11-17 17:30): The entry is “A Multi-Sensor Device Information Fusion Monitoring System Based on an Edge Agent Kernel.” Hardware is Edgi-Talk (PSoC E84, Cortex-M55 with Helium, M33, Ethos-U55 NPU, 6 MB SRAM); software runs RT-Thread 5.0.2.
  • Six-layer architecture: Application layer with seven LVGL pages, Agent kernel, tools and channels, network protocol stack, kernel and BSP, external services. The Agent kernel is imported read-only from the upstream Agent-latest package.
  • Runtime parameters: A single AgentLoop thread handles sessions serially, with a 10 KB stack and priority 10, and input and output mailbox depths of 10 each. A single conversation sends at most 6 requests to the large model, executes the same tool at most 3 times, and trims context to 16 entries per round.
  • Tools and networking: 10 tools registered, three examples plus seven MQTT business tools. The subscription table has 13 slots and 4 threshold rules, with the latest 6 history entries kept per topic. The network stack is a Wi-Fi 6 host driver, SAL and netdev, lwIP 2.1.2, paho-mqtt, webclient 2.2.0, mbed TLS 2.28.1.
  • Stated gaps: The broker currently uses plaintext TCP with username/password authentication; TLS or account isolation must be added before multi-node scale-out. TTS, NPU inference, service-layer management and visualization remain reserved items. The code is on Gitee and can be imported with RT-Thread Studio.

  • How to split edge agents: Intent understanding, fusion assessment and alert copy go to the remote large model, while the edge handles only message routing, tool scheduling and result feedback. For a real-time kernel, this is currently the most compute-efficient and least error-prone split.

VI. Trend Observations

  • The security line has entered “single-commit full closure,” and verification remains the weak spot: ptyfs provided a memory curve over 20,000 cycles, ivshmem only reached compile conclusions for two configurations, and the block device commit has no runtime test cases. The high-quality serial_v2 report has yet to be fixed. This week there was not a single security fix with automated test cases.
  • The bottleneck is the “report to proposal” segment: FinSH took 50 days from report to proposal and 3 days from proposal to merge. The block device took 5 days from report to proposal and 14 days from proposal to merge. iso9660 took 17 minutes. Review is not slow; what is slow is finding someone willing to do the work.
  • The breaking change is this week’s item most in need of downstream attention: nine generic commands shifted wholesale, with no compatibility macros, an empty verified-BSP field, and only 14 files synced in-repo. Any out-of-repo BSP or software package that hardcodes the old command values will hit the wrong branch after upgrading.
  • Silent loss of test configuration is more insidious than a defect: mem.cfg did not select MEMHEAP, so the entire test group was not compiled in, yet both build and test showed passing. Such gaps can only be found by comparing configurations, not by running tests.
  • Ecosystem-layer throughput exceeds the kernel’s: 9 commits in the main repository, 7 in the package index, 2 in Env. The package index layer simultaneously handles vendor onboarding, AI component configuration and debugging tool standardization. For an OS with installations in the hundreds of millions, ecosystem-layer throughput reflects activity better than kernel commit counts.
  • Dual-track serial maintenance is not zero-cost: The maintainer designated V1 as low-maintenance rather than frozen, and V1 still took new defects this week, with a fix proposal within 12 minutes. V2, meanwhile, lacks the RX_TIMEOUT macro and requires the read-side control interface. The semantic differences between the two lines will persist long-term.
