Today’s Highlights: Matrix Extension and Stack Sync Advance on Three Fronts — Ztt Single Batch of 51 Commits, PyTorch riscv Full-Stack Rebuild (23 Commits), triton-riscv #84 Dependency Upgrade Merged

Date: 2026-10-10 ~ 2026-10-11　Sources: riscv-gcc ztt-dev commit list, head commit a326bc3, pytorch riscv branch commit list, head commit 0fc3546d, triton-riscv PR #84

The GCC backend line for the matrix extension direction took another step forward this week: contributor pz9115 pushed a single batch of 51 Ztt commits to the ztt-dev branch of riscv-gcc on the afternoon of 10-11 (13:50), the largest batch since the branch was established on 09-30 (surpassing the 36-commit batch of 10-08). Ztt is a draft instruction set for the RISC-V matrix extension direction, representing RuyiAI’s GCC toolchain effort alongside the BOSC AME / A100 line on the LLVM side. This batch performs systematic refinement of Ztt backend infrastructure: comprehensive reuse and caching of the descriptor system (TC / ACC / zip / row-column / constructors and consumer, unary operand state), indexed lookup and registration (builtin decoders, store declarations, overload candidates, profile and type lookups, datatype names and registration keys), zero-value and narrow-carrier simplification (zero registers for scalar / control inputs, narrow Ztt scalar carriers, floating-point zero-offset shift folding), descriptor propagation along branch edges and fallthrough, descriptor cleanup after DCE, factorization of dynamic workspace computation, and updates to LTO dump checks and optimized instruction checks. All 51 are newly developed commits (author and committer timestamps at the same push point), with the branch head advancing to a326bc3 “Update Ztt descriptor and LTO dump checks”.

Full-stack rebuilds of the two forks landed in sync during this window. The riscv branch of the PyTorch fork completed a full-stack rebuild in the early hours of 10-11 (around 03:00): 23 local commits were re-landed with new committer timestamps (author dates spanning from April through 10-04, including the merged #1 blocklist, the CI and fix series for #4 / #11 / #12 / #18 / #20 / #21 / #40 ~ #44, the #50 blocklist expansion, and three SyncBots integration records), with the head remaining “[SyncBots] Integrate PyTorch at e188cec” and the base advancing with upstream (including upstream commits from 10-10). The riscv branch of the LLVM fork completed another nightly replay late on 10-11 (around 23:00): 26 local patches were re-landed wholesale with new committer timestamps, with the head still #31 “A100 HP/SP and pack/unpack lowering and scheduling calibration”, the stack composition unchanged from the previous round, and the replay anchor synced to the 10-11 upstream snapshot. After the rebuilds / replays on both sides completed, the baseline records for their respective open PRs (8 for PyTorch, the two FPGA PRs #25 / #28 for LLVM) were refreshed in turn, awaiting the next round of review.

On the Triton side, the Buddy MLIR dependency upgrade PR #84, unblocked in the previous window, was merged on the afternoon of 10-10 (13:31) (auto-merged by bot): the PR had been open since 09-20, upgrading buddy-mlir to the nightly version v0.0.11.dev20260925; it had previously failed to build because the new LLVM shipped with v0.0.11 was incompatible with the pinned frontend API, and became mergeable after the patch adaptation (#86) on 10-09 cleared the way. The chain “patch adaptation (#86) → dependency upgrade (#84)” is now closed; the next things to watch are whether the nightly channel produces a new build containing v0.0.11, and the review progress of the community software optimization PR #85.
