Today’s Focus: BUDDY MLIR 0.1.1 Released — RISC-V Server-Side Cross-Compilation and Model Publishing Pipeline Land

Date: 2026-10-18　Sources: BUDDY MLIR 0.1.1 release page, 0.1.0 to 0.1.1 diff, PR #989 RISC-V server-side cross-compilation, PR #925 model publishing workflow

The main Buddy Compiler repo buddy-mlir released BUDDY MLIR 0.1.1 on 10-18 at 06:26 (Beijing time), roughly two days after 0.1.0 (10-16 00:53), making it the project’s second stable release in two days. Compared with 0.1.0, 0.1.1 contains only two changes across 24 files, about +896/-54 lines, both aimed at “deliverability.”

The first is #989 “add RISC-V server-side cross-compilation to buddy-server”: it adds a cross-compilation path targeting riscv64 for buddy-server, along with a handle implementation for the runtime dependency manifest (RaxDependenciesHandle, including unit tests and a test plugin), a stub implementation of plugin discovery and transcription tests, resolving runtime dependencies by manifest; it also streamlines buddy-cli (a net reduction of 40 lines) and updates the RVV environment documentation. The second is #925 “add publish-models workflow”: it adds a GitHub Actions publishing pipeline and a Hugging Face model publishing script (about 313 lines), enabling model artifacts to be pushed and published directly from CI. Together, 0.1.1 addresses both ends: “the server can run on RISC-V machines, and model artifacts can come out of CI.”

Downstream responded the same day: triton-riscv merged #87 on 10-17 22:41 to pin Buddy MLIR v0.1.0, then on 10-18 08:57 was upgraded to the v0.1.1 nightly by the automated version-tracking #88; tilelang-riscv added a Buddy MLIR release CI on 10-16 and builds the Python extension within that CI (see 1.3, 1.4, 4.1).

2.3 Kernel Line: linux-xuantie-kernel Adds Profile Extension Probing, Extension IDs Aligned with Upstream (10-16)

Date: 2026-10-16　Sources: linux-xuantie-kernel commit list, cpufeature profile extension commit 8fd30253, Zicclsm commit acc74e96, private ID segment commit 1b89fe6b

ruyisdk’s linux-xuantie-kernel (linux-6.6.36 branch) saw 4 commits during the window, all authored at 10-16 11:14 and landed as one batch: adding Ziccamoa, Ziccif, Ziccrse, Za64rs, and Zicclsm to cpufeature and hwprobe—the first four correspond to misaligned atomic access granularity, instruction-fetch atomicity, reserved-set, and 64-byte reserved-set guarantees respectively, while Zicclsm corresponds to support for misaligned accesses within a cache line, all capabilities required by the RVA20/RVA23 profiles; the other two commits carve out an ID segment for private extensions in hwcap and align the numbering with upstream. Combined with the previous issue’s unification of vendor extension keys into the XUANTIE_ form, XuanTie private extension naming and hwprobe exposure are gradually aligning with upstream rules.

3.2 Operator Coverage Evidence: triton-riscv Self-Test Results Under LLVM 24 / Buddy MLIR 0.1.0 (10-18)

Date: 2026-10-18　Sources: ruyiai-daily 10-18 issue, triton-riscv PR #87

The 10-18 issue of the technical intelligence repository recorded triton-riscv’s self-test data after completing adaptation to LLVM 24 and Buddy MLIR 0.1.0: 618 check-buddy items passed, 290 triton-shared items passed, and 9 expected failures; of the 3829 items covered locally by FlagGems, 10 native crashes remain, and some examples require a native RVV environment. The original text also notes that these are all the author’s local results and cannot be used to infer that full-model compatibility or all runtime validation on the RISC-V side has passed. For the operator stack, this data set defines the current usable boundary: the basic check chain is working, but operator coverage still has native crashes to clear.

IV. Buddy Compiler Updates (buddy-mlir Commits and Releases)

4.1 BUDDY MLIR 0.1.1: Two Changes — RISC-V Server-Side Cross-Compilation and Model Release Workflow (10-18)

Date: 2026-10-18　Source: Release page, Diff comparison, PR #989, PR #925 release workflow, Commit 60f354a7

The diff between 0.1.1 and 0.1.0 consists of just two commits, 24 files, and roughly +896/-54 lines: RISC-V server-side cross-compilation (#989) and the model release workflow (#925). The former adds a riscv64 cross-compilation path for buddy-server, introduces a runtime dependency handle (RaxDependenciesHandle) along with dependency manifest tests and a plugin-discovery stub, and also streamlines buddy-cli and updates the RVV environment documentation; the latter adds .github/workflows/publish-models.yml and a Hugging Face release script, bringing the release of model artifacts into CI. Together, the two changes complete both ends — server deployment and artifact delivery — and explain why 0.1.1 could ship just two days after 0.1.0 (the bulk of the content had already been frozen in 0.1.0).

VI. Trend Observations

6.1 Compiler stack version coupling tightens: Buddy MLIR ships two releases in two days, downstream follows same day

Buddy MLIR went from 0.1.0 to 0.1.1 in roughly two days, and both changes in 0.1.1 target deliverability — server-side cross-compilation lets buddy-server run on RISC-V machines, and the model release workflow lets model artifacts ship out of CI. Downstream response is also measured in days: triton-riscv merged #87 on 10-17 to pin 0.1.0, then was bumped to the 0.1.1 nightly by automated version tracking on the morning of 10-18; tilelang-riscv folded the Buddy MLIR release CI into its own pipeline on 10-16. Version coupling around the same LLVM backend is tightening across the three repos; the thing to watch is whether a unified release window and regression baseline emerge.

6.2 The two fork maintenance lines keep diverging: PyTorch merges and replays in parallel, LLVM silent for six days

The PyTorch riscv branch merged 143 commits in the window (mostly upstream syncs) and maintained its local patch stack via bulk replay, while also seeing its first PR merge in nearly five weeks (#51, riscv64 local image); the LLVM riscv branch, by contrast, has had no commits for six days since 10-12, with two FPGA backend PRs stalled at 10-12. Both are “upstream fork + local patch stack,” but one is a daily-moving pipeline and the other a static branch awaiting review — the gap in maintenance investment is more pronounced than in the previous window. Watch: whether the LLVM replay restarts on a new upstream baseline, and whether the FPGA backend PRs enter review.

6.3 RuyiSDK advances on three fronts: kernel probing filled in, distro coverage expanded, toolchain awaiting version window

On the kernel side, RVA23-related atomicity and instruction-fetch atomicity profile extensions were merged into cpufeature and hwprobe, with private extension IDs aligned to upstream; on the distro side, six Rust embedded packages were added, bringing the base dependencies for Rust bare-metal development into the software source; on the toolchain side, 0.54.0 is slated for late October, with ABI compatibility checks and K1/K3 adaptation continuing; the firmware line paused after three consecutive releases. The overall rhythm is “kernel probing filled in, distro coverage expanded, toolchain awaiting version window”; next, watch whether 0.54.0 ships on schedule and how the post-summit plans land.
