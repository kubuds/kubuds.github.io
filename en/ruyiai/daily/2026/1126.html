Today’s Focus: FlagGems’ five batches of 245 operators merged into triton-riscv in a single day (11-25)

Source: PR #136. The other four batches are #137 through #140; links in Appendix [2] to [5].

From 10:13 to 19:53 on 11-25, triton-riscv merged five batches of FlagGems operator examples, totaling 245 operators.

The five batches are B12 with 55, B13 with 51, B14 with 41, random/RNN/attention with 50, and sparse/nested tensor with 48.

Each batch includes a CPU correctness test per operator and is uniformly exported from the examples package’s __init__.py.

The five batches add 54,550 lines and delete 315 lines in total. B13’s verification record shows all 146 tests passing on riscv64 CPU, with the environment being Python 3.12, PyTorch 2.10.0, and CPU Triton 3.9.0.

B14 also fixed the int4 packer. Previously, when the output column width exceeded 128 input values, the remaining bytes were not written, and non-contiguous tensors were read as contiguous memory.

The previous report noted that batches B12, B13, and B14 were still under review; this issue confirms all have landed. Combined with the 59 linear algebra operators merged on 11-24, this round of porting totals 304 operators.

Today’s Focus: triton-riscv merges RISC-V backend tuning, depends on Buddy approximate math (11-26)

Source: PR #129. Buddy dependency in Appendix [24].

At 00:24 on 11-26, PR #129 merged into the triton-riscv mainline, changing 2 files, adding 136 lines and deleting 15 lines.

All changes are in _ttsharedir_to_llir and take effect only when the target is RISC-V.

Five adjustments: math functions switched to polynomial approximation; scalable vectors and AVL tail loops adopted; matmul vector width set to 2·VLEN/32; buffers promoted to the stack before deallocation; strided memref copies converted to linalg for vectorization.

The PR reports precision of 1 to 7 ULP for f32 and no more than 1 ULP for f16 and bf16, excluding subnormal results for exp and erfc.

The change depends on the polynomial-approximate-math pass and use-avl-loop option provided by buddy-mlir#1068. With an outdated buddy-opt version, RISC-V lowering will terminate due to unknown passes or options.

The tuning baseline is a VLEN-256 RISC-V development board, with triton-cpu as the control group.

1.2 Backend Tuning PR #129: Approximate Math, Scalable Vectors, and matmul Vectorization (11-26)

Source: PR #129.

Polynomial approximation covers 15 functions: exp, expm1, log, log2, log1p, tanh, erf, erfc, sin, cos, atan, atan2, asin, acos, and cbrt.

Previously RVV had no vector math library, so these functions degraded to per-lane libm calls and could not use vector registers.

The matmul vector width changes from a fixed 4 to 2·VLEN/32, corresponding to an 8-row accumulator with two vector registers per row and an LMUL of 2. The PR notes that LMUL 4 would overflow.

--lower-vir-to-vector gains use-scalable=true and use-avl-loop=true. The remainder segment is finished with a single active-length iteration instead of being split into halved segments plus a scalar loop.

Strided memref.copy now goes through convert-strided-memref-copy-to-linalg, dynamic-shape copies are lowered to SCF, and FP8 copies retain the original path.

IV. Buddy Compiler Updates

4.1 buddy-mlir merges two VIR optimization commits, major changes to masked tiles and matmul (11-25 to 11-26)

Source: PR #1080. For #1085, see Appendix [19].

Two commits landed in the buddy-mlir window, both in the early hours of 11-26.

At 00:07, #1080 “Optimize masked tiles, reductions, and matmul” was merged, touching 23 files, adding 3,163 lines and deleting 30.

The PR adds masked tile copy elimination, tile memory forwarding and masked vector stores, reduction and matmul optimizations, and reuses small stack slots with non-overlapping lifetimes.

At 01:20, #1085 “Keep the reassoc of a linalg.reduce combiner” was merged, touching 2 files, adding 131 lines and deleting 4.

Previously, -lower-linalg-to-vir dropped reassoc when generating vir.reduce, allowing reorderable reductions to be lowered to the ordered vfredosum. The PR adds reassocOf(), now used uniformly across four reduction lowering paths.

4.3 PR #1059 closed without merging, memref copy vector approach shelved (11-25)

Source: PR #1059.

PR #1059 “Copy memrefs with vectors instead of memrefCopy” was closed at 01:31 on 11-26 without being merged.

It touched 4 files, adding 216 lines and deleting 17.

The PR reports that on SpacemiT K3, memrefCopy generated by masked load/store accounted for 44% to 99% of kernel time for add, exp, softmax, and matmul.

The reason for closing is not stated on the page. During the same period, #1080 had already merged masked tile and tile memory optimizations.

4.4 EmbeddingGemma 300M tuning PR for K3 under review (status as of 11-25)

Source: PR #1070.

PR #1070 is still under review, focused on performance optimization of EmbeddingGemma 300M on SpacemiT K3.

It touches 17 files, adding 2,196 lines and deleting 8, with the latest update at 22:05 on 11-25.

The PR presents first-round data for nine workloads: 23.24x to 38.24x speedup over the F32 RAX baseline, and 7.11x to 19.03x over native Hugging Face F32.

Peak process RSS dropped 71.6% to 93.5% relative to the RAX baseline, and all 81 measurements passed the embedding accuracy threshold.

The PR continues #835, fixing model import, RAX packaging, and tokenizer compatibility, and uses K3’s IME and RVV.

VI. Trend Observations

6.1 Operator porting shifts to batch landing, 279 still in review queue

245 operators merged in one day, pushing the porting pace from “opening PRs” to “batch landing.”

Together with the 59 linear algebra operators from 11-24, the cumulative total this round is 304.

The review queue remains long: #132’s 61, #131’s 72, #130’s 40, #127’s 43, and #126’s 63 are all unmerged, totaling 279.

Landing speed has increased, but the backlog has not dropped noticeably.

6.2 Backend optimization increasingly coupled to Buddy versions

PR #129 depends on buddy-mlir#1068, and PR #135 depends on #1080.

triton-riscv backend optimization is starting to follow Buddy’s release cadence.

The distribution still pins buddy-mlir 0.1.4, while upstream is already at 0.1.9.dev20261125.

This version gap will constrain both triton builds and runtime tuning.

6.3 Distribution packaging dominated by dependency updates and kernel follow-ups

openRuyi had 38 commits in this window, mainly filling in Rust and Go dependencies, plus two kernel upgrades.

linux to 7.3.6 and linux-lts to 6.18.65, indicating relatively fast upstream kernel follow-up on the packaging side.

The AI stack saw no new changes in this window; triton and buddy packages remain at the previous issue’s state.
