Today’s Highlight: openRuyi PR #1350 Merged — the RuyiAI Trio Enters Distro Packaging Seven Weeks Later (11-03)

Date: 2026-11-03　Sources: PR #1350 Add Ruyiai packages, three packaging commits, follow-up fix PR #1575

At 15:59 Beijing time on 11-03, PR #1350 was merged into the main openRuyi repository. The PR was opened at 17:55 on 09-21 and spent 43 days in review; it ultimately carried only three commits, ten files, and 838 added lines, yet it formally brought the hardest-to-distribute segment of the RuyiAI stack — the compiler backend and MLIR toolchain — into the distro’s SPECS directory.

The division of labor among the three packages is clear. buddy-mlir is the MLIR compilation framework, providing the dialects and passes needed for RISC-V vector (RVV) lowering; its spec declares 0.1.2, pins source to buddy-compiler commit 60f354a7, bundles an LLVM snapshot from RuyiAI-Stack/llvm-project (commit 3845a205), bootstraps with clang/lld 22, disables tests and Python packages, and installs the toolchain to /usr/lib64/buddy-mlir/llvm. python-triton-ruyiai (package name python-triton-riscv in the spec) combines upstream Triton commit 5889527 with the triton-riscv tag nightly/20260913-da5291b, and depends at runtime on buddy-mlir, buddy-mlir-llvm, and clang. python-tilelang-ruyiai (package name python-tilelang-riscv in the spec) pins tilelang-riscv commit 0b7d66eb and separately packages five submodules — TVM, dmlc-core, rang, tvm-ffi, and DLPack — at the versions fixed upstream; building it also requires python3dist(torch).

The patch contents reveal where distro adaptation ran into trouble: tilelang’s five patches respectively relax the apache-tvm-ffi upper bound to 0.1.11, drop the torch-c-dlpack-ext and patchelf build dependencies, make the toolchain look under /usr/lib64/buddy-mlir/llvm, skip z3 soname rewriting, and handle the libbacktrace switch for TVM FFI; triton’s two patches replace cmake/ninja/nanobind with system packages and add PATH plus /usr/lib64/buddy-mlir/llvm/bin lookup fallbacks for buddy-translate, buddy-llc, llc, and mlir-translate. In other words, the paths assembled from environment variables in the source tree must each be turned into reproducible lookup rules in the distro — that was the main workload of the 43-day review.

At 20:16 the same day, PR #1575 added one more fix: changing the #/ separator to / in Source0 and Source1 of buddy-mlir.spec, correcting the RPM source URL format. Another packaging bug was fixed the same day, confirming that the complexity of these three specs lies not in functionality but in packaging conventions and path details; the previous daily’s note that “the nineteen review comments centered on spec style” is now resolved here.

The significance of this merge is not in version numbers but in the distribution path. Previously, using the RuyiAI stack meant pulling triton-riscv, tilelang-riscv, and buddy-mlir yourself and setting variables like BUDDY_MLIR_BINARY_DIR per the docs; now that these three components exist in openRuyi’s packaging repo, once builds pass, users can install the same LLVM/MLIR chain the distro way, with versions, dependencies, and install layout fixed by the specs. The PR description also flags assisted tools (GLM-5.3, DeepSeek V4.1 Flash) per openRuyi’s AI contribution policy.

One caveat remains: the code pinned by all three specs predates current upstream. Packaging completion does not mean capability parity; see 2.2 for the specific gap.

  • python-tilelang-ruyiai 0+git20261028.0b7d66e: the main source anchors tilelang-riscv commit 0b7d66eb (commit message “[RISC-V] Add TileKernels runtime tests and refresh docs (#3)”), and packages five submodules separately: TileLang/tvm 882a7748, dmlc-core 3031e4a6, rang cabe04d6, tvm-ffi ae346ec9, DLPack 93c8f2a3; the five patches handle the tvm-ffi version ceiling, torch-c-dlpack-ext and patchelf, buddy-mlir toolchain discovery, the z3 soname, and the libbacktrace switch; BuildRequires: python3dist(torch), runtime dependencies buddy-mlir-llvm and clang.

VI. Trend Observations

6.1 From source builds to distro packages: the RuyiAI stack’s distribution path closes the last mile

After the specs for the three-piece set entered openRuyi, the RuyiAI stack’s distribution path was written into distro configuration for the first time: previously it was “pull source + set environment variables + build LLVM yourself”; now the packaging repo contains an RPM dependency chain, with buddy-mlir providing the LLVM/MLIR prefix and triton and tilelang depending on buddy-mlir-llvm. Once the build artifacts enter the repository, the installation barrier for users drops from “can build a compiler” to “can install a package”; for the project, versions and dependencies are written into auditable specs for the first time.

This is also where the value of the seven-week review lies: what is being contested is not features but distro rules—path discovery, dependency ceilings, build isolation, package names, and Provides. PR #1575 fixed the source address that same day, showing that this chain is still fragile, but it can already run through the merge process.

6.2 Packaging anchors lag upstream: the date in the version string is not the code date

Among the three specs, triton’s code stops at 09-13, tilelang at 10-28, and buddy at 0.1.2; yet all three repositories still had new activity on 11-03. The most striking is tilelang: PR #5, merged on 11-03, was the first feature after eighteen days of silence, but it is not in the RPM merged that day—the package is anchored to 0b7d66eb from 10-28.

The version string 3.8.0+git20261103 reinforces misreading, treating the packaging date as the code date. For distro users, this means “you installed some snapshot,” not “you installed the latest.” Going forward, either establish a regular bump process or state the snapshot date clearly in the package description; otherwise, with every merged feature, the gap between the package and the repository widens a little more.

6.3 Two development lines resume the same day; ruyi mainline and openRuyi releases remain static

On 11-03, tilelang-riscv ended eighteen days of silence, buddy-mlir resumed nightly builds, and openRuyi merged seven PRs in one day; development-side activity concentrated on compiler backends and packaging. On the other side, the ruyi main repository had zero commits and zero new tags, and openRuyi’s 2026.10 monthly release is still missing.

The two lines are not in sync: code moves, releases do not. The previous issue summarized this state as “the bottleneck is in releases, not development,” which still holds this issue. The next observation points are whether the openRuyi November release includes the three-piece set, and whether triton-riscv’s #92 rebase is merged—the former determines whether the distro can ship, the latter determines where the next bump of the triton package lands.
