Today’s Highlights: Matrix Extensions Advance on Two Fronts — 36 Ztt Draft GCC Backend Commits in a Single Day, LLVM riscv Stack Completes Nightly Rebuild

Date: 2026-10-08 ~ 2026-10-09　Sources: riscv-gcc ztt-dev commit list, llvm-project riscv commit list, head commit 44b1cf2, PR #25, PR #28

The largest single-point output in this window came from the ztt-dev branch of riscv-gcc: contributor pz9115 pushed 36 consecutive Ztt backend commits on the morning of 10-08 (08:40 ~ 11:27). Ztt is a draft instruction set for the RISC-V matrix extension direction, representing RuyiAI’s GCC toolchain effort alongside the BOSC AME / A100 line on the LLVM side. The batch covers the stack from bottom to top: construction simplification for zero extraction and zero broadcast (x0 reuse and data type clearing), structural folding (project / rebuild / inverse operations / concatenation extraction / zip and unzip) and witness handling, Md (matrix descriptor state) tracking threaded through scalar, matrix, row-column, and grouped operation classes, descriptor register reuse, new floating-point row-column intrinsics, large ACC default rounding alias fix, builtin function input attribute caching, unused workspace cleanup, and tests and documentation for M-value semantics; this is the densest batch since the branch was opened on 09-30.

On the LLVM side, the riscv branch of llvm-project (the default branch) completed another nightly rebuild: the local patch stack of 26 commits was replayed in full with new committer timestamps (late night 10-08), with the push completing at 10-09 00:51 — the head is 44b1cf2 “[RISCV] Add A100 HP/SP and pack/unpack lowering with calibrated scheduling” (#31; identical to the head patch of the previous rebuild, a routine replay); the in-stack integration commit remains “[SyncBots] Integrate LLVM at b3b5e33”, with the replay anchor advanced to the upstream snapshot of 10-08 (the upstream baseline includes that day’s [RISCV] vector ISD fix #228215 and other commits). After the rebuild completed, the update timestamps of the two FPGA backend PRs (#25 “BOSCAME FPGA backend”, #28 “xboscame FPGA”) were immediately refreshed to 10-09 00:51, awaiting review progress under the new baseline. Also: a new buckyball branch was created in the fork at 10-08 18:38 (pointing to the old head from before the rebuild), sharing its name with the in-stack Buckyball vendor extension (#20 / #23).

Key takeaways: matrix extensions are advancing in parallel on two toolchains in the same window — LLVM (BOSC AME / A100) and GCC (Ztt); rebuild-style synchronization, FPGA-side PRs pending review, and new branch layout form the observation surface for the next phase.
