Today’s Highlight: openRuyi Opens the K3 Firmware Platform Line — edk2-ruyi / ruyifirmware Dual Repos Created with Full Initial Batch, First Firmware Release; Biweekly Report 078 Finalized with Summit Preview

Date: 2026-10-13　Source: edk2-ruyi commit list, ruyifirmware Releases, Biweekly Report 078 file, Forum topic #2891

openRuyi-Project on 10-13 finalized the K3 firmware platform line in one stroke: the new repository edk2-ruyi (created at 11:07 Beijing time that day) landed a full initial batch of 35 commits for the SpacemiT K3 Pico ITX EDK2 platform code (author RevySR, push window 11:55–16:21), covering the complete chain from platform package definitions to peripheral drivers. On the platform foundation side, it includes the standalone SpacemitPlatformPkg platform package with shared resource/clock handling, power domain control, DMA high-address non-coherent support, and board-level EEPROM and Ethernet MAC allocation. On the boot and security chain side, it includes SEC-phase memory discovery and device tree publication, boot selection and hotkey policy, boot logo with countdown/recovery status display, NOR-backed UEFI runtime variables, DDR training record persistence, and a full Fastboot implementation (EFI image loading, NOR/NVMe/UFS firmware updates, version query, verified updates with NV preservation, and USB device-side transfer). On the peripheral side, it includes storage (UFS high-speed link negotiation, QSPI NOR access), networking (EQoS native Ethernet, RTL8127 SFP link, SNP polling service and adapter information), display (DPU clock/scanout management, Inno DP AUX and link training, EDID modes and GOP operations), USB host controller, and PCIe controller/shared PHY. The final two commits address graphics console connection timing and 64-bit BAR reservation for devices with Option ROMs.

The companion ruyifirmware was created at 12:01 the same day and landed with 5 commits (12:17–18:31, also by RevySR): positioned as “firmware based on coreboot, OpenSBI, and EDK2,” it establishes a packaging chain make package for the K3 Pico ITX, with artifacts in two variants toggled by x64 emulation (the emulator is used to run x64 UEFI Option ROMs and supports discrete GPU GOP; the README notes that RX550 on K3 has a pointer truncation issue and recommends the no-x64emu variant), and includes PCI Option ROM/GOP updates and a CI build-and-release pipeline. At 18:46 the same day, the first firmware release “Ruyi Firmware 20261013” was published. The same organization’s kiwi-image also landed a GitHub Action and local build script for riscv64 images that day (3 commits, authors Z572 and Fancyhe1). With firmware, packaging, and images all moving in parallel on the same day, the open delivery chain for the K3 hardware foundation has taken shape.

On the community side, a dissemination milestone was also finalized the same day: RuyiSDK Biweekly Report 078 completed its editorial pipeline (#371–#378, 8 commits total, closing at 17:46 with “add summary, remove sections with no progress”) and went live — themed “RuyiSDK to Appear at the RISC-V China Summit” (10.18–20, Shenzhen Convention & Exhibition Center, Futian; keynote, poster presentation, and D15 booth demo); content summarizes the package manager 0.54.0 end-of-month release plan, one round of IDE polishing, and progress across the base C library/GCC/LLVM/V8/OpenJDK/Go lines (see 4.1 and 2.4 for details).
