Today’s Highlights: First Ztt Toolchain Push on the LLVM Side and Nightly Build Loop Closed — 26 Commits Land on ztt-dev Branch, New triton-riscv Build, Two VS Code Extension Features Merged

Date: 2026-10-12　Sources: ztt-dev commit list, head commit aeb52e1a, matrix register commit 836a7ebc, Nightly 2026-10-11-fe554ff, VS Code extension PR #264, PR #265

The Ztt matrix extension toolchain effort took a key step this window: ruyisdk/llvm-project created the ztt-dev branch on the morning of 10-12 and completed its first full-stack push — 26 LLVM / Clang patches (author LukeZhuang) landed with uniform committer timestamps (10:05–10:43), while author dates span from late September through 10-10, marking the first public push of an existing local development stack. The head is aeb52e1a “[RISCV] Match Ztt tests to AME diagnostics”. Coverage spans backend to frontend: base Ztt extension support and function-level profiles (-mzzt-profile, subtarget isolation by profile, cross-profile inlining suppression), CSR and matrix register groups, instruction assembly and disassembly, IR types and intrinsic definitions, Clang-side matrix register types and data scalar types, TableGen and builtin registration, builtin semantic checks, pseudo-instruction tables and register layout tracking, post-register-allocation pseudo expansion, M register and ACC spilling and stack frame handling, with the final commit aligning tests with the existing AME diagnostics framework. Following the GCC-side riscv-gcc ztt-dev branch (created 09-30, 51 commits in a single batch on 10-11), the Ztt line has now filled in the LLVM side, forming a GCC + LLVM dual-backend toolchain layout; within the same window, the documentation-side attached-matrix-extension Ztt intrinsic doc V0.6 PR is also being refreshed (see 3.1), keeping the “spec—docs—dual toolchain” chain active in parallel.

The Triton-side observation point materialized the same day: the nightly channel produced a new build, “Nightly 2026-10-11-fe554ff” (live on the morning of 10-12), built against the head of the riscv branch after the Buddy MLIR dependency upgrade (PR #84) merged on 10-10 — the first closed-loop artifact of the “patch adaptation (#86) → dependency upgrade (#84) → nightly artifact” chain. This release provides 6 wheels across CPython 3.12 / 3.13 / 3.14 and x86_64 / riscv64 (triton 3.8.0-prefixed packages); the previous release was still “Nightly 2026-10-04-12c2f6a”. With this, validation of the dependency upgrade moves from “build passes” to “artifacts usable”, with the next observation point being real-device feedback on the riscv64 wheels.

The two routine stack-sync lines continue: the LLVM fork’s riscv branch completed another nightly replay (26 local patches re-landed wholesale with new committer timestamps, head 0fb2da86 still #31); the PyTorch fork’s riscv branch completed another full-stack rebuild (23 commits re-landed, head updated to 6ff4eefe, keeping to the roughly one-push-every-morning cadence of the past week). On the tooling side, two UX features landed: VS Code extension #264 “move package installation errors into inner details” and #265 “add error reporting for package index refresh” merged on the afternoon of 10-12 — the former moves lengthy installation errors out of the dialog and into the “View Details” document view, while the latter adds error visibility for package index refreshes that may fail, gradually productizing the extension’s error diagnostics path.
