RuyiAI Weekly Report (2026-09-21 ~ 2026-09-25)

2026-09-25 Kubuds

Reporting period: Monday, September 21, 2026 to Friday, September 25, 2026 — 5 working days Sources: This publication’s daily RuyiAI updates (five issues: 09-21, 09-22, 09-23, 09-24, 09-25); plus a 168-hour window audit of organizational repositories and dual-source community verification (coverage through the morning of 09-26) Editorial note: This period covers five dimensions — RuyiSDK releases (ruyi 0.53.0), toolchains and kernels, the board support matrix, the openRuyi distribution, and community and events; all technical facts are based on hands-on verification of code repositories, release artifacts, and community forums

1. This Week’s Highlights

  • ruyi 0.53.0 officially released, cross-repository installation state issue closed in three days (09-21 ~ 09-25): On the evening of 09-21, a community user reported issue #501 — after switching software sources, installed packages showed as “not installed,” reinstalls were skipped, and uninstalls errored out, creating a deadlock where “files are on disk but state is forever ‘not installed’”; on the morning of 09-23, maintainer xen0n’s fix was merged into main via PR #502 (162 lines changed, 117 of which are regression tests), changing installation state to match across sources by installation identity; on the morning of 09-24, the fix was backported to the v0.53.x release branch (10:34) and immediately tagged (10:35), with 0.53.0 final released at 14:57 (GitHub Release, non-prerelease, with PyPI synced the same day at 14:56); on the evening of 09-25, release-day wrap-up PR #503 (test install timeout calculated by package count) was merged. The final release contains only two more commits than 0.53.0-beta.20260917; binary package ABI compatibility detection, default software source priority fix, and download-failure mirror fallback, all merged during the test period, graduated with the beta. Next version is announced for late October 2026. Source: Release 0.53.0, PR #502, PR #503

  • RuyiSDK appears at the Ruyi Community booth at the 2026 Yunqi Conference (09-22 ~ 09-24): The 2026 Yunqi Conference opened on 09-22, with RuyiSDK appearing at the conference’s Ruyi Community booth, presenting to industry partners and RISC-V developers a one-stop RISC-V software development kit, toolchain, package manager, IDE development plugins, and multi-hardware-platform adaptation results, with live hands-on demos and technical exchanges; the booth ran through the conference’s final day, 09-24. Source: Community post 2849

  • Biweekly Report Issue 077 released: “ruyi 0.53 Release” special edition goes live (09-24): Issue 077 of the “RuyiSDK Biweekly Progress Report” was officially published in the developer community at 16:01 on 09-24. Highlights include: package manager 0.53 update list (ABI compatibility detection and reporting infrastructure, default software source priority fix, multi-source same-name same-version installation state synchronization fix, etc.); 16 new IDE features; support matrix multi-board entries (P550 Fedora 44, CoM260 Kit, CH32V307, Milk-V Duo S’s Zephyr 4.1.99, etc.); foundational components (glibc porting pow into libmvec, newlib porting rsqrt and expm1, GCC completing backport of SpacemiT vendor extensions to the 16.2 branch, LLVM’s multiple merges in the P extension and RVA23.1/RVB23.1 directions, V8 reducing AOT builtin static code size by 2.7% via Word32 comparison optimization, OpenJDK’s 11 mainline PRs, Go chacha20 RVV retest); community updates include the Yunqi Conference appearance. The article notes the next version is planned for release in late October 2026, and this issue was published early due to Mid-Autumn Festival and National Day holiday arrangements. Source: Release post 2852, Issue 077 article

  • riscv-gcc 16.2 branch merges SpacemiT X100/A100 core support (09-21): Two patches (author Mark Zhuang of SpacemiT) formally add the two cores to the compiler’s -mcpu/-mtune: X100 scheduling maps to the generic out-of-order model generic_ooo; A100 is in-order dual-issue with a microarchitecture close to X60, temporarily reusing the X60 cost model, and is closest to X100 in ISA, with the main differences being that it does not implement the H extension, has VLEN=1024 (zvl1024b), and carries the xsmtvdotii extension (the extension definition is also written into riscv-ext-spacemit.def and the extension documentation). For development boards targeting the K3 platform (such as the CoM260 Kit’s combination of 8 X100 plus 8 A100), the toolchain can directly select the core via -mcpu and obtain the corresponding extension definitions and scheduling settings. Source: X100 commit, A100 commit

  • Twelve board support matrix reports in one week: “single board, multiple systems” model systematically rolled out (09-20 ~ 09-23): CoM260 Kit (SpacemiT K3) expanded from a single Buildroot to four system families: Bianbu, openEuler, and OpenHarmony; Milk-V Duo S added five reports for Arch Linux, Ubuntu, Debian, RT-Thread, and xv6; SiFive HiFive Premier P550 added Fedora 44 Server; CH32V307 updated to RT-Thread BSP 5.3.1; K510 updated its BuildRoot report. At the end of the window, three items were still under review: Duo S’s Zephyr and RT-Thread Smart, and ESP32C3’s RT-Thread 5.3.1. Accompanying board-docs were also updated with board documentation for P550 and CoM260, HelloWorld/CoreMark examples, and a ROS 2 course entry point. Source: Support matrix PR #400, PR #407

  • openRuyi distribution rolling updates advance at high frequency: dual-track kernel upgrades, containers allow riscv_hwprobe (09-20 ~ 09-24): Across the five daily report windows, the package directory saw a total of about 79 commits. The linux kernel was upgraded to 7.2.6, linux-lts to 6.18.52, with four ruyi/* branches pushed alongside; a new openruyi-linux-build package unifies build dependencies, and spec files were fully switched to RPM macros; containers-common allows riscv_hwprobe in the default seccomp whitelist (avoiding OpenSSL and zlib-ng silently falling back to scalar implementations due to ENOSYS, which would drag down in-container encryption and compression performance); security updates landed in batches (pcre2 10.48, imagemagick 7.1.2.31, expat 2.8.5, etc.). The testing line advanced BRS compliance coverage on the same days: fwts added ten riscv-brs AML checks, and kvm-unit-tests added BRS SBI and ACPI boot tests under EFI. Source: openRuyi commit history

  • llvm-project opens new matrix extension pre-research branches, XTHeadVector mixed-width memory access fix opened (09-23 ~ 09-24): ruyisdk/llvm-project added two new branches during the window, AME and riscv-ime-preview (together with ame0p6 on 09-23, forming a pre-research line for the matrix extension direction); on the afternoon of 09-24, PR #168 was opened based on rebase-17.0.6, fixing mixed-width index support for the XuanTie vector indexed memory access instructions th.vlxe/th.vxse (949 lines changed, covering 6 files), corresponding to issue #136, which was raised in February 2025 and has long remained open. Source: Branch list, PR #168

  • Framework side broad but shallow: PyTorch fork goes quiet after rebase, organization adds mxnet and caffe repos (09-20 ~ 09-23): After the PyTorch fork’s riscv branch completed a 96-commit rebase on 09-20 and underwent another force push on 09-21 (refreshing the baseline of 8 open PRs), there were no functional commits for the rest of the week; two RVV patches (#46 ATen RVV support, #48 RVV CPU capability) remained queued across the week without being merged; on the CI side, PR #51 was added (riscv64 local image build script, requiring native riscv64 hardware). On 09-23, the organization created two new repos, mxnet and caffe (carrying full upstream history), broadening coverage of classic deep learning frameworks. Source: riscv branch, PR #51

III. RuyiSDK Toolchain and Distribution (ruyi package manager, packages-index, openRuyi)

ruyi Package Manager: Full Record of the 0.53.0 Release Week

  • Fix closed loop (09-21 ~ 09-23): Issue #501 (reported by community user qingwan12138, 09-21 20:48) found that install records were keyed by source repository ID, but deduplication was based only on “name plus version,” causing a deadlock after switching repositories: “installed but shown as not installed, reinstall skipped, uninstall errors”; PR #502 (maintainer xen0n) changed status queries to match across repositories by install identity (category, name, version, host), preferring the exact source ID record for the same identity, and made uninstall cover all records of the same identity, totaling 162 changed lines, of which 117 were regression tests (merged into main 09-23 09:01).
  • Release actions (09-24): The v0.53.x branch received the backport at 10:34 (fd39afa3) and the version number commit at 10:35 (ceb2f961), followed by tagging, packaging, and announcement; GitHub Release 0.53.0 at 14:57 (marked latest, not pre-release), with the PyPI channel upload at 14:56 the same day.
  • Version comparison: 0.53.0 has only the above two commits relative to 0.53.0-beta.20260917; the binary package ABI compatibility detection infrastructure, default repository priority fix, and download failure mirror fallback fix merged during the test cycle were promoted to stable along with the beta.
  • Release-day wrap-up (09-25): PR #503 (community member weilinfox, calculating test install timeouts by package count instead of a fixed timeout) was merged on the evening of 09-25, adding a small test-line step to the 0.53.0 release cycle.
  • To watch: Artifact synchronization progress on public mirrors (the releases directory had not yet shown 0.53.0 by the end of the 09-25 daily report window); the next version is previewed for late October 2026; the last packages-index commit remains at 09-16 (issue 077 recorded its removal of Armbian software versions no longer provided upstream).

Compiler and Kernel Toolchain

  • riscv-gcc: The 16.2 branch merged X100/A100 core support (see “This Week’s Highlights”); the p-rebase branch continues the P extension lowering series, with PR #19 (author TelGome) wiring packed min/max and the psh1add instruction in via header-file operator forms; the other two commits on the 16.2 branch are routine (upstream libstdc++ gamma_distribution fix backport, daily build number).
  • linux-xuantie-kernel (XuanTie kernel tree): On 09-20, an upstream backport patch was merged extending the T-Head PMA memory type erratum to PUD (1GB) and P4D (512GB) huge pages (commit 167b3d7c, with Cc stable and Fixes tags), eliminating the risk of inconsistent memory attributes across different mapping sizes within the same process; on 09-23, two small fixes were merged—normalization of the RISC-V architecture name match in perf annotate (94494ca6) and correction of the COMPAT_UTS_MACHINE definition in the compat layer (5eed2594); no new commits followed through the end of the window.

The tool is not bound to a specific LLVM version or target architecture, and uses empirical measurement to mine optimization synergy pairs and find the optimization sequence that minimizes whole-package code size.

openRuyi Distribution

  • Commit volume: About 79 commits across five daily report windows (18 / 56 / 0 / 2 / 3 per issue), the most active package directory among the three organizations.
  • Kernel and build: linux upgraded to 7.2.6, linux-lts upgraded to 6.18.52, patch sets and kernel configurations refreshed in sync, with four branches pushed in support: ruyi/7.2.y, ruyi/7.1.y, ruyi/7.0.y, ruyi/6.18.y; the new openruyi-linux-build package provides unified dependencies for each flavored kernel variant; the linux, linux-lts, and linux-lts-kmhv2 spec files were reorganized using RPM macros.
  • RISC-V behavior fix: containers-common added a seccomp patch (41 lines) allowing riscv_hwprobe in the default whitelist—this call only reads CPU feature information, and OpenSSL and zlib-ng rely on it to probe ISA extensions; if it returns ENOSYS, they silently fall back to scalar implementations; the patch is signed by a maintainer from the Institute of Software, Chinese Academy of Sciences, and the corresponding upstream issue is in progress.
  • Security and feature updates: pcre2 10.48, imagemagick 7.1.2.31, python-ujson 6.0.0, python-datasets 5.0.1, python-pytorch-lightning 2.6.6, btrbk 0.32.7, expat 2.8.5 (all marked security-fixes); glibc updated to a new build baseline; added cloudpods 4.0.3 and cloudpods-operator, kes 0.24.0, go 1.27.1, jemalloc 5.4.0, iptables 1.8.13, flashrom 1.8.0, vkmark 2025.01, assimp 6.0.5, glm 1.0.3, fd, pngquant, and a batch of Go/Rust dependency packages; vkmark backported a fix for a lavapipe software rendering crash; python-zmq renamed to python-pyzmq; added a check-spdx-header pre-commit check.
  • Test line (BRS compliance): The fwts PATCH-6 branch added ten riscv-brs AML checks (AML_010 to AML_100, committed consecutively on 09-24); the kvm-unit-tests brs-i branch added BRS SBI requirement tests and ACPI boot under EFI (09-24 morning), part of the same work sequence as the spcr/mcfg checks merged on 09-21.
  • News page: No new announcements; the 2026.09 monthly release announcement is still not online (latest is 2026.08).

VI. Trend Observations

  • Release closed loop and operational rhythm: From issue report (#501, 09-21) to fix merge (09-23), backport and release (09-24), and wrap-up (09-25) took just over three days, and “fix, release notes, biweekly report” closed the loop within the same release cycle; the stable and beta versions differ by only two commits, and release branch discipline is clear. The community-facing rhythm (biweekly report 077 delivering on the “09-24 release” preview) is synchronized with the internal technical cadence.
  • The K3/Andes platform support chain continues to densify: On the toolchain side, the three layers of “core recognition (GCC -mcpu/-mtune) to operator optimization (RVV measured) to whole-package tuning (RuyiTuner)” all advanced this cycle; X100 temporarily using a generic out-of-order model and A100 reusing the X60 cost model are both transitional approaches, and scheduling refinement and test coverage are worth tracking.
  • The board support matrix has entered a systematic phase of “single board, multiple systems, plus supporting assets”: Twelve reports in one week span application-class (P550, K3) to MCU-class (CH32V307, K510), and the completeness of each board’s report, documentation, examples, and course materials is improving; the length of the review queue reflects community contribution activity better than the number merged in a single day.
  • Framework-side deep progress lags behind the toolchain and system sides: The PyTorch fork’s riscv branch is silent, and two RVV patches have been queued across weeks; the organization’s newly ingested mxnet and caffe are “broadening” actions, and the “broad but shallow” interim state awaits validation from the first commits in both repositories; next to watch are the #46/#48 reviews and the use cases for mxnet/caffe.
  • System software is shifting from “it runs” to “it runs correctly and compliantly”: Container seccomp allowing riscv_hwprobe, kernel PMA erratum extension, and concentrated BRS compliance test completion—the most technically substantive commits this cycle are mostly such fixes that generate no news, yet directly determine measured performance and platform quality claims.
  • Gaps and points of attention: ruyiai-daily has paused for two issues since 09-24; news-side searches in Chinese and English for RuyiAI, RuyiSDK, Ruyi Community, and openRuyi continue to return zero hits; the openRuyi 2026.09 monthly release announcement has not been published; mirror synchronization and community installation feedback for 0.53.0; the merge pace of the three support matrix items under review; follow-up content on llvm-project’s two pre-research branches.
