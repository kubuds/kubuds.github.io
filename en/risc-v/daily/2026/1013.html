Today’s Highlight: SpacemiT’s llama.cpp Fork Introduces a Standalone ggml-spacemit Backend, Releases v0.2.1

Date: 2026-10-12　Source: spacemit-com/llama.cpp PR #43: Add standalone ggml-spacemit backend (10-12), llama.cpp fork Release v0.2.1 (10-12)

SpacemiT’s llama.cpp fork repository merged PR #43, introducing a standalone ggml-spacemit backend that coexists with the existing CPU path as a dual-backend setup:

  • The standalone backend is explicitly enabled: when not enabled, the device registry reports zero devices and default behavior remains unchanged (still using the traditional CPU path); enabling it requires setting the environment variable
    GGML_SPACEMIT_BACKEND to 1, and users select the backend via --device SPACEMIT0.
  • Build fix: adjusted the build approach for the two libraries libggml-cpu and libggml-spacemit, fixing the symbol interposition conflict between them.
  • v0.2.1 released the same day (the previous version v0.2.0 was released on 09-24) — the fork’s version numbering maintains an iteration cadence of roughly 2–3 weeks.

Combined with other SpacemiT updates in this window (xslim static quantization support for ignored operators, model zoo additions of RT-DETR and the MNN backend, see 3.6) and the approaching official Ubuntu 26.10 support for K3 (see 1.1), the K3/K1 on-device AI inference and desktop upper-layer ecosystem chain are being refined both inside and outside the company in parallel.

Date: 2026-10-12　Source: NeoTeo: Ubuntu 26.10 RISC-V desktop images: what to test (10-12), Sina Finance: Ubuntu plans official 26.10 desktop images for the RISC-V instruction set (10-12), Canonical Discourse: Announcing Ubuntu Desktop Images for RISC-V (10-09, background)

Ubuntu 26.10 (Stonking Stingray) is scheduled for release on October 15, with the riscv64 desktop images entering their final week of focused pre-release testing. Testing-side follow-ups in this window: NeoTeo published a “what to test” guide (10-12), and Chinese-language outlets such as Sina Finance followed up with coverage (10-12). Previously reported highlights: Ubuntu Desktop ships official RISC-V images for the first time, alongside an experimental Xubuntu Minimal image (recommended for trial in a VM); official testing is recommended on SpacemiT K3 (Pico-ITX), which gains official support starting with 26.10; the full desktop experience targets RVA23-class hardware (Milk-V Jupiter 2, DeepComputing DC-ROMA, SiFive HiFive Unmatched); booting on real hardware requires supplying your own first-stage bootloader (U-Boot) and device tree; bug reports go through Launchpad.

1.2 RevyOS: Batch Kernel Config Expansion — Adds ESWIN EIC7700, linuxboot, and Type-C Stack Support

Date: 2026-10-12　Source: revyos/linux commit log (10-12)

The RevyOS kernel repository saw 20 commits in this window, a second round of batch configuration expansion (the 10-11 round was a baseline sync): adds ESWIN EIC7700 platform support (ARCH_ESWIN, DWMAC_EIC7700 Ethernet, PINCTRL_EIC7700, with DRM_AST display enabled) and DP1000 platform configuration; enables the display controller and UFS for K3; enables USB2 for K1 (Banana F3); enables the Type-C protocol stack (TYPEC/TCPM/UCSI/FUSB301/DP_ALTMODE/PHY_SPACEMIT) plus RTC_DRV_EFI, PWM fan sensors, and more; adds linuxboot configuration; and adds cross and native builds to CI. Distribution-level platform support for domestic SoCs (K1/K3/EIC7700) and TH1520 continues to deepen.

1.4 Tech Community: RVBNA (Bulk Normalization Algorithm) Explainer Published

Date: 2026-10-11 (spread via Hacker News on 10-12)　Source: FProx: RISC-V Bulk Normalization Algorithm (RVBNA) (10-11), Hacker News discussion (10-12)

Community author FProx published an explainer on RVBNA (RISC-V Bulk Normalization Algorithm) — a scalable approximate dot product scheme: built around a fixed-point accumulator, it applies round-to-odd rounding in both the multiply and accumulate stages, trading a small amount of precision for scalable implementation cost and latency (the accumulator’s guard bits scale with the number of accumulated terms). RVBNA has been written into the RISC-V ISA manual draft (merged in May) and is currently integrated into two extension projects: the Zvt family of the Vector Matrix Extension (VME) (riscv-isa-manual PR #2997) and the bulk dot product extensions Zvdota/Zvbdota (PR #2618). The article systematically compares the precision-cost trade-offs of FP MUL+ADD, FMA, Kulisch exact accumulation, and other approaches, and open-sources an error evaluator (rvbna-explorer).

II. Product and Ecosystem Updates

2.1 Meta: Open-Sources Muse Gadgets SDK; Official Home Link Hardware Based on ESP32-C5

Date: 2026-10-12　Source: CNX Software: Facebook releases Muse Gadgets SDK for ESP32 and Raspberry Pi/Linux-based devices (10-12), facebookincubator/muse-gadget-sdk (GitHub)

Meta released the open-source Muse Gadgets SDK (Apache-2.0), enabling DIY hardware to connect to its personal AI assistant Muse: it includes an ESP32 device SDK (image display, audio input/output, sensor/actuator interfaces, supporting multiple ESP32 development boards, covering RISC-V chip models such as ESP32-C5/C6) and a Linux device SDK (Raspberry Pi, etc., providing commands such as system.run and file.read/write); it also includes a third-party device skill catalog (smart home, printers, 3D printers, etc.). Meta’s self-made five thousand Muse Home Link units are being distributed free of charge to U.S. subscribers, with hardware based on the ESP32-C5 (dual-band Wi-Fi 6, BLE, 802.15.4). This is the latest case of a RISC-V wireless MCU entering mass-market consumer hardware from a major vendor, and also shows that the ESP32 ecosystem is being used as the hardware foundation for personal AI agents.

2.2 Industry Analysis: AI Workloads Accelerate RISC-V Adoption; SHD Forecasts 35.9 Billion SoC Shipments by 2031

Date: 2026-10-12　Source: Bisinfotech: Why AI workloads are accelerating RISC-V adoption (10-12)

Industry outlet Bisinfotech published an article analyzing how AI and edge computing are reshaping SoC design priorities: the performance bottleneck is shifting from clock frequency to data movement, memory hierarchy, and interconnect efficiency; in heterogeneous SoCs, RISC-V is well suited to take on control and system management roles, while leaving room for custom extensions such as matrix/tensor operations. The article cites SHD Group’s “2026 RISC-V Market Report”: RISC-V SoC shipments are expected to reach 35.9 billion units by 2031, with a CAGR of about 31.7%, and emphasizes the importance of hardware-software co-design (compiler/runtime support for custom instructions) and pre-silicon verification (FPGA prototyping) for bringing custom RISC-V SoCs to production.

III. Deep Dive into Domestic Teams

3.1 XiangShan: Fully Associative vBTB for MBTB Merged into Main Branch; NEMU Releases v2026.10.r3

Date: 2026-10-12　Source: XiangShan PR #6587: implement a fully associative vbtb (10-12), NEMU commit log (10-12), NEMU Release v2026.10.r3 (10-12)

The XiangShan main branch (kunminghu-v3) merged PR #6587: implementing a fully associative vBTB (virtual branch target buffer) for the MBTB (main branch target buffer) during this window. Simulation infrastructure advanced in parallel: NEMU refactored the AME matrix extension to decouple instruction dispatch from physical memory (PMEM) access (#1249), and released version v2026.10.r3. difftest/GEM5/XSCache pushes during the window were concentrated on feature branches (no in-window commits on the main branch). This follows the previous window’s compressed ROB (crob) merge, marking continued investment on two fronts: out-of-order frontend structures and matrix extension simulation.

3.2 DAMO XuanTie: Compliance Test Framework Introduces T-SBI, Test Suite Migrated to S-Mode Execution

Date: 2026-10-12　Source: damo-rv-priv-ats PR #37 (10-12), damo-rv-priv-ats repository

The damo-rv-priv-ats compliance test framework under the DAMO XuanTie (XUANTIE-RV) organization (covering 90+ extensions of the RISC-V privileged specification, running bare-metal programs directly on QEMU/Sail/Spike/FPGA) merged PR #37: introducing the T-SBI (Test Supervisor Binary Interface) protocol layer and migrating the entire test suite to an S-mode regular execution model—after completing M-mode-only initialization during the boot phase, execution drops to S(HS) mode before main(). The motivation: running test bodies in M-mode could not model register behavior from an S/HS perspective (for example, Smstateen-gated CSRs should trap when read in HS mode); after migration, the test execution location matches the specification’s judgment scenario. Of the 73 repositories in this organization, only this one saw pushes during the window.
