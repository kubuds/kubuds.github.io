Today’s Highlight: DAMO XuanTie C950 runs a 27B LLM without a discrete accelerator; results featured on the RISC-V International website

Date: 2026-10-15　Source: riscv.org: V Questions with… DAMO Academy’s Dr. Jianyi Meng (10-15)

The RISC-V International website’s “V Questions” column published an interview with Jianyi Meng, Chief Scientist of DAMO XuanTie and Vice Chair of the 6th RISC-V China Summit 2026, systematically introducing XuanTie’s recent landmark work and building momentum for the 10-18 Shenzhen summit. Key points:

  • Milestone data: The XuanTie team natively ran Qwen3.8-27B (27 billion parameters) on a 64-core C950 target configuration with no discrete GPU/NPU, achieving a decode speed of over 30 tokens/s (roughly 20–22 words/s, reaching natural real-time conversation level); this workload requires about 400 GB/s of memory data movement capability, and the interview emphasizes that “quantization, matrix instructions, on-chip memory, bandwidth, and operator optimization must be co-designed as a single system.”
  • C950 and AME: The C950 is a server-class 64-bit superscalar processor using the RVA23 profile (including RVV 1.0) as its general-purpose computing baseline; after XuanTie’s in-house matrix extension was silicon-validated, it co-initiated the AME (Attached Matrix Extension) task group with members including Qualcomm, IBM, VRULL, ISCAS, and BOSC, and is pushing the spec toward formal ratification and deployment.
  • Design trade-offs: AME uses separate tile registers rather than reusing vector registers—avoiding matrix workloads crowding out the RVV register file, reducing spills and cache disturbance, and natively supporting mixed-precision accumulation (INT4/INT8→INT32, FP4/FP8/FP16/BF16→FP32); matrix state is enabled on demand, saved/restored only when necessary.
  • Ecosystem call to action: Meng outlined three areas of expectation—continued filling-in of the high-performance data center software stack (Java runtime adaptation results have already been contributed back to the community), a complete AI software chain (optimized operator libraries, updated compilers, and a full stack for RISC-V as an xPU), and leveraging the openness of the ISA to explore new extensions and computing paradigms.

Date: 2026-10-15　Source: Ruyi Firmware 20261015 Release (10-15), ruyifirmware commit history (10-15), edk2-ruyi commit history (10-15), openRuyi main repo commit history (10-15)

The openRuyi firmware line released a new version, “Ruyi Firmware 20261015,” for the third consecutive day, with the K3 platform remaining the focus of iteration. On the firmware side, 8 commits landed within the window: raw SPI flashing installation documentation, an A100-only mode interrupt routing fix, a System Information page and DRAM inventory, graphics console initialization, an IMG GPU clock device tree correction, and packaging for “selectable UEFI driver emulation”; accompanied by 6 commits in edk2-ruyi—the K3 system information page, SMBIOS reporting of DRAM configuration, connecting the graphics console after GOP initialization, platform setup grouping, and a SPI-backed emulation option. On the main repo side, 8 SPECS updates focused primarily on security maintenance (backports and upgrades for cups, python-nltk (CVE-2026-81726), capstone 5.0.9, llama-cpp 0.4.1, multipath-tools 0.15.1, and spdk installing bdevperf, among others). 1.2 RevyOS: 7.3 Kernel Branch Enables Platform Configurations for K3 / ESWIN EIC7700 and Others in Bulk

Date: 2026-10-15　Source: revyos/linux revyos/7.3.y commit history (10-15)

RevyOS merged 20 bulk configuration commits into the 7.3 kernel branch (revyos/7.3.y) within the window: on the boot chain side, it added a linuxboot configuration and cross/native build CI; on the platform side, it enabled in one pass—SpacemiT K3 (UFS/DC) and K1 (Banana F3 USB2), ESWIN EIC7700 (ARCH_ESWIN/DWMAC/PINCTRL), the TH1520 USB module (including RESET_GPIO), USB Type-C and display links (TCPM/UCSI/DP_ALTMODE/PHY_SPACEMIT), DRM_AST, ERRATA_PICOHEART, and dozens of other items, while raising the number of active 8250 serial ports to 6. This batch indicates that RevyOS is consolidating multi-vendor platform support for its 7.3 kernel line.

1.3 openKylin Appears at OSS EU 2026: RVV Optimizations Speed Up ONNX Runtime FP32 Inference by 2–5x

Date: 2026-10-15 (conference 10-07~09)　Source: MarkTechPost: openKylin Outlines Its Vision for Reimagining Linux in the AI Era at OSS EU 2026 (10-15), openKylin official site

MarkTechPost published a recap of openKylin’s participation in Open Source Summit Europe 2026 (Prague): Executive Director Min Liu, in a main stage keynote, introduced the unified AI runtime KART and a system-level Agent execution environment (a three-layer architecture moving from “resource management” to “intent management”: the KART runtime layer / Agent execution layer / capability layer); Technical Committee member Jianfeng Li gave a lightning talk titled “Building an AI-Ready Linux Desktop on RISC-V.” Key RISC-V points: RVV kernel optimizations speed up ONNX Runtime FP32 inference by 2–5x, and the related kernel optimization and inference framework adaptation work is planned to be contributed upstream; the AI stack supports CPU inference with vLLM on SpacemiT K3, with delivery forms including .deb, Python wheel, Conda, and Docker. At the summit venue, SpacemiT exhibited a K3 laptop preinstalled with openKylin 3.0.

II. Product and Ecosystem Updates

2.1 HPMicro HPM5100 Series RISC-V Mixed-Signal MCU Enters Mass Production: Focused on Analog and Motor Control

Date: 2026-10-15　Source: CNX Software: HPMicro HPM5100 RISC-V MCU integrates four 16-bit ADCs, four op-amps (10-15)

Shanghai HPMicro’s HPM5100 series 32-bit RISC-V mixed-signal MCU has been covered by overseas media: the first HPM5151 part features a 400 MHz RISC-V core, 416 KB SRAM + 1 MB Flash, and integrates four 16-bit ADCs, four op-amps, and four analog comparators, targeting analog sensing and motor control scenarios; interfaces include USB 2.0 OTG (with built-in PHY), CAN FD, multiple UART/SPI/I2C, and 32 PWM channels, with hardware floating-point and DSP instruction support. The series is now in mass production: QFN48/QFN68/LQFP100 packages are priced at 15.60/16.90/19.50 RMB, with the EVK development board at 258 RMB; SDK 1.13.0 (September) has added support, along with SEGGER Embedded Studio for RISC-V.

2.2 Orange Pi O1 Launches: Powered by Sophgo BM1688 (with RISC-V Coprocessor), Targeting 16 TOPS Edge AI

Date: 2026-10-15　Source: CNX Software: Orange Pi O1 SBC features 16 TOPS SOPHGO BM1688 AI SoC (10-15), OrangePi O1 product page

Orange Pi has released the OrangePi O1 single-board computer, based on the Sophgo BM1688 SoC: 8-core Arm Cortex-A53 @1.65 GHz + RISC-V C906 coprocessor @1.2 GHz, with a built-in 16 TOPS@INT8 neural network acceleration engine supporting 16-channel 1080p video decoding / 10-channel encoding; it offers 8/16 GB LPDDR4X, M.2 NVMe, dual Gigabit Ethernet, Wi-Fi 6E/BT 5.3, 2×USB 3.0, and 4G/5G module expansion. Pricing is $195 (8 GB) / $325 (16 GB) (plus a $7.9 heatsink); Ubuntu images and Linux source code will follow. The Sophgo BM1688 ecosystem (previously mostly in module and server form factors) is beginning to extend down into general-purpose SBC channels.

2.3 Espressif ESP32-S31 Linux BSP Adds “Configurable Flash Layout”; Community Port Releases v0.3.1

Date: 2026-10-15　Source: espressif/esp-linux-bsp (updated 10-15), esp32-s31-linux: v0.3.1 Release (10-15)

Two new developments around “Linux on ESP32-S31”: first, the Espressif ESP32-S31 Linux BSP (esp-linux-bsp) merged a “esp32s31: configurable flash layout” commit during the window — the repository hosts the Buildroot image layout and packaging tools (a post-image hook wraps U-Boot SPL into Espressif image format and merges the SPL, U-Boot FIT, Linux device tree, XIP kernel, and cramfs root filesystem into s31_full_flash.bin), and is currently maintained on a developer preview branch. Second, the community project esp32-s31-linux released v0.3.1 (Linux 7.2 + OpenSBI 1.9 running on ESP32-S31-Korvo-1, using 16 MiB PSRAM as memory), adding Bluetooth and 802.15.4 RCP support and refining the release notes. The ESP32-S31 (dual RV32 cores @320 MHz) has gone from an MCU “not built for Linux” to an experimental platform with two open-source system paths, official and community.

2.5 The Next Platform Publishes zeroRISC Interview: A Decade of Open Silicon

Date: 2026-10-15　Source: The Next Platform: A Decade In, zeroRISC Sees A Bright Future For Open Silicon (10-15)

The Next Platform published a long-form interview with zeroRISC founder Dominic Rizzo (an early OpenTitan lead), reviewing a decade of open silicon and its commercial path. One of the core arguments is that RISC-V’s openness grants permission for “open implementations” — “if there’s an open ISA, why not an open implementation”; zeroRISC now builds on the OpenTitan security root (RISC-V-based) to offer a complete silicon + software + cloud management solution for data centers, ICS/OT, and IoT, and discusses the place of open silicon in supply chain trust. The piece offers a perspective on the evolution of the open hardware and security root market.

3.4 SpacemiT: Agent Capability Distribution Infrastructure Lands — APM, Agent Hub, and Bianbu Skills Mirror All See Substantive Content on the Same Day

Date: 2026-10-15　Source: spacemit-com/agent-power-manager, spacemit-com/bibit-agenthub-plugin, spacemit-com/bianbu-skill, model-zoo-vision commit log (10-15)

The “Agent system software” repo cluster created en masse on 10-13 landed its first batch of substantive content during this window, pointing to capability distribution infrastructure for edge Agents:

  • APM (agent-power-manager): A Go-based CLI tool that consolidates retrieval, installation, upgrade, uninstallation, and submission of four “Power” categories — Skill/Plugin/MCP/Expert — into a single command set; syncs metadata from Agent Power Cloud (APC), installs by version, is transactionally recoverable, supports target Agents such as bibit, and is open-sourced under Apache-2.0.
  • Bibit Agent Hub (bibit-agenthub-plugin): Bibit’s built-in “capability center” — a frontend plugin (TypeScript/React) plus a pure standard-library Go CLI Provider; offers installed manifests, full APC marketplace browsing, one-click upgrades, and custom resource uploads, with riscv64 build support.
  • Bianbu Skills (bianbu-skill): A read-only mirror repo of Skills publicly released on APC, with an initial collection of 11 Skills (K3 media pipeline, VPU/CoreMark benchmarks, RISC-V porting assistant, document-to-Markdown, offline HTML app generation, etc.), archived as-is per APC directory snapshots.
  • Supporting updates: model-zoo-vision had two fixes (OC-SORT Kalman tracking and memory safety #100, vision interface contract and numerical safety #101); ai-sdk updated the vision submodule for the second time; llama.cpp (mtmd-backend) synced with upstream (PR #46) and fixed the SMT path; lxqt-schedule introduced LXQt schedule management and desktop reminders.

Following the concentrated open-sourcing of Bianbu AgentOS components described in the previous daily report, SpacemiT has now filled in precisely the missing piece: “capability distribution and version governance.”

V. Summary and Trend Observations

  • XuanTie’s high-performance narrative reaches international channels: The achievement of running a 27B large model on a single C950 machine was disseminated via an official RISC-V International Foundation website interview (compounded by the 10-22 Beijing seminar and the 10-20 summit AME workshop), building hype for summit week; AME has upgraded from “in-house matrix extension” to “a standards proposal jointly advanced with Qualcomm/IBM and others,” making it the most worthwhile thread to track.
  • Open-source distributions and firmware “competing on platform coverage”: openRuyi firmware saw consecutive daily updates (8 commits on the K3 line + 6 on UEFI), and RevyOS 7.3 kernel batch-consolidated platform configurations including K3/EIC7700 — the competitive focus of RISC-V distributions is shifting from “can it boot” to “platform breadth + UEFI experience + security maintenance.”
  • Edge Agent infrastructure moves from components to distribution: SpacemiT’s APM/Agent Hub/Skills mirror forms a closed loop of “publish — retrieve — install — version governance,” and the RISC-V edge Agent ecosystem is beginning to see supporting engineering toolchains.
  • Three niche product lines launch in the same window: HPMicro HPM5100 (mixed-signal MCU in mass production), Orange Pi O1 (edge AI SBC), and Espressif ESP32-S31 Linux BSP iteration + community v0.3.1 — MCUs, AI boxes, and Linux-on-MCU each have new supply in three directions.
  • Summit week opening imminent: RVSC2026 opens on Sunday (10-18) in Shenzhen; the next issue will focus on the opening ceremony, main forum, and first-day content of the various thematic sub-forums.
  • Limitations note: The openKylin item is based on a 10-15 report (the conference was 10-07~09), and details are subject to official follow-up materials; the community ESP32-S31 Linux project is a hobbyist project, and its maturity is subject to its release notes; some repos had only branch-level pushes during the window, as noted in the source verification table.
