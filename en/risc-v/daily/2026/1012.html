Today’s Highlight: LPC26 Returns — RVA23u64 Kernel Profile Bits Advance, 8 Patches Merged into riscv/for-next

Date: 2026-10-11　Source: WeChat Official Account “Docular嘚吧嘚”: LPC26 Trip Report (10-11), LPC26 Presentation Slides, Author’s Homepage: Docular

Xu Guodong (Docular, currently at Qualcomm), the primary driver of the RVA23 kernel effort, published his trip report from Linux Plumbers Conference 2026 (LPC26, Prague): his Linux kernel rva23u64 profile bits series is advancing to v9 (in flight), and on October 9, the first 8 of the 11 patches in v8 were merged into riscv/for-next by RISC-V kernel maintainer Paul Walmsley (awaiting the next merge window for mainline), with the remaining 3 core patches to be submitted with v9 after incorporating feedback from LPC.

  • Problem being solved: RVA23 profile 1.0 (ratified 2024-10, 39 mandatory + 15 optional extensions) requires the kernel and userspace to answer “is this hardware RVA23?” at low cost — currently only bit-by-bit queries are possible, glibc and GCC each compute their own answer, and Ubuntu-side detection tools can only report “probably RVA23.” The proposed solution: the kernel computes an “RVA23 compliant” bit at boot and places it in the vDSO, so userspace can read it in one shot via the hwprobe UAPI.
  • Conclusions on the four Asks at LPC26: ① The v8 bit format was accepted by maintainers; v9 will add RVA22 / RVA20 tiered bits (to facilitate glibc’s stepwise fallback) and document the legacy behavior of not inheriting IMA bits; ② glibc will switch to profile-based builds + glibc-hwcaps automatic library selection (hwcaps sourced from kernel bits; ifunc reserved for microarchitecture-level selection), with GCC maintainer Jeff Law advancing in the same direction at the GNU Tools Cauldron RISC-V BoF; ③ The userspace interface for dynamically disabling the V extension will be deprecated — the very next day at LPC, Samuel Holland (SiFive) sent out a 3-patch series (cover letter: RISE and LPC26 have reached consensus, create more trouble than benefits); ④ Future extensions with register state (e.g., matrix) will not introduce similar switches.
  • Spillover effects: This series directly or indirectly drove no fewer than 5 mainline series — two old patch sets shelved for two years (extension name case unification, Zicclsm) were absorbed, ByteDance’s Qingwei Hu contributed Zic64b support, and additionally a “do not report disabled extensions” (6-patch series), cpufeature BUNDLE-to-SUPERSET streamlining, and the V-off deprecation series were sent out around the same time.
  • Note: This year’s LPC RISC-V MC featured 10 talks total, with Qualcomm contributing 3; the slides for this talk are now public (see reference links).

I. Open-Source Community and Software Ecosystem

1.1 Phoronix/LPC26: Kernel auto-vectorization yields positive results, LZ4 up to ~15% improvement

Date: 2026-10-11　Source: Phoronix: Auto Vectorizing The RISC-V Linux Kernel Shows Promising Results (10-11), LPC26 talk page: Optimizing the kernel with vector, Hacker News discussion

RISC-V kernel builds do not yet enable the V (vector) extension. Andy Chiu presented “Optimizing the kernel with vector” at LPC26 (October 5-7, Prague), describing an approach to optimize the kernel via compiler auto-vectorization: experiments targeting kernel scenarios such as crypto, RAID, XOR, and user copy show — LZ4 up to ~15% improvement, Btrfs ~8.4%, XFS ~5%, Nginx scenario ~2%; the cost is increased time and memory overhead from vector context management, and existing constraints on using vector units in kernel mode remain. Phoronix called the direction “promising results,” and the talk materials have been made public with the conference.

1.2 RevyOS: Kernel synced to 6.17.11 config, enabling Rust/PowerVR/NTSYNC and other features

Date: 2026-10-11　Source: revyos/linux commit log (10-11)

RevyOS (a multi-platform RISC-V Debian distribution) kernel repository saw 50 commits during the window: kernel configs were batch-synced to the 6.17.11 baseline, adding configs for platforms including K1/K3, DP1000, SG2042/SG2044, and TH1520, and enabling Rust, PowerVR DRM, NTSYNC, the K3 display controller and UFS, SPACEMIT PM domains, and the FUSB301 Type-C controller; device trees enable GPU and USB3 ports for the K3 Pico ITX and USB for the Milk-V Meles; CI adds cross/native builds. Display, USB, storage, and GPU support for platforms such as K3 is being densely filled in on the distribution kernel side.

II. Product and Ecosystem Updates

2.1 M5Stack ToughC5: Waterproof ESP32-C5 Industrial IoT Controller Launched

Date: 2026-10-10　Source: CNX Software: M5Stack ToughC5 weatherproof ESP32-C5 IoT controller (10-10)

M5Stack has launched the waterproof industrial IoT controller ToughC5 (an upgraded version of the 2021 M5Stack TOUGH): based on the ESP32-C5 (single-core RISC-V @240MHz + low-power RISC-V core), dual-band Wi-Fi 6, BLE 5, 802.15.4 (Zigbee 3.0/Thread 1.3), 8MB Octal PSRAM, 16MB flash, 2.0-inch 320×240 touchscreen (up to 853 nits), RS485 and 4x HY2.0-4P expansion, RX8130CE RTC (independent coin cell), 6-24V power supply; the waterproof enclosure has a built-in USB-C and 4-pin expansion port, with M12 cable routing. Targeting industrial field control, outdoor edge acquisition, and smart buildings, priced at $49.9.

2.2 Wireless-Tag WT32P4C5-43S: ESP32-P4 + C5 Dual-Chip 4.3-Inch Touchscreen Dev Board

Date: 2026-10-11　Source: CNX Software: Wireless-Tag WT32P4C5-43S (10-11)

Wireless-Tag WT32P4C5-43S touchscreen dev board: ESP32-P4 (dual-core RISC-V @400MHz + low-power core, 16/32MB PSRAM) paired with an ESP32-C5 wireless module, integrating a 4.3-inch 800×480 capacitive touchscreen (18-bit RGB interface), 15-pin MIPI CSI camera interface, microSD, dual USB-C (including debug/JTAG), 14-pin GPIO expansion. Targeting industrial automation, smart control panels, and edge AI vision terminals, starting at $32; the official offering includes two firmware repositories for the ESP32-P4 main firmware and the C5 coprocessor, plus schematics and STEP models, supporting ESP-IDF/Arduino/LVGL.

2.3 Industry Watch: Qualcomm v. Arm Trial Sees Sparring Over RISC-V Data Center Maturity

Date: 2026-10-11　Source: Wccftech: Even Court Judges Are Now Declaring That RISC-V Is Basically Worthless (10-11)

In the Qualcomm v. Arm licensing dispute trial (U.S. federal court in Delaware), RISC-V unexpectedly became a courtroom topic: Arm expert witness Timothy Simcoe described RISC-V and x86 as constituting “long-term competitive pressure”; presiding judge Noreika pressed on RISC-V’s current availability, and the witness acknowledged that its enterprise data center deployments remain at an early stage, with related designs mainly coming from Chinese companies (such as Alibaba’s XuanTie), after which the judge did not probe further. The report circulated with a sensationalist headline, sparking community discussion; the focus of the discussion was the enterprise data center scenario, which does not directly contradict RISC-V’s existing progress in embedded and edge deployments.

2.4 Industry Analysis: x86/Arm/RISC-V “Meet Head-On” at the Industrial Edge

Date: 2026-10-10　Source: 36Kr: “x86, Arm, RISC-V Meet Head-On at the Industrial Edge” (10-10)

The edge AI explosion has brought the three architectures into head-on competition in industrial scenarios: Semiconductor Industry Panorama (published with authorization from 36Kr) lays out — x86 relies on ecosystem (Intel Open Edge Platform, AMD Ryzen AI Embedded X100 up to 80 TOPS, already deployed in inspection robots); Arm relies on energy efficiency and heterogeneity (Rockchip RK3572 integrates a RISC-V core, RK182X coprocessor embeds multiple RISC-V cores, already adopted in hundreds of customer projects); RISC-V relies on openness and customizability (XuanTie C950, Nuclei NA900 pass ASIL-D, ESWIN R500A passes ASIL-B certification). The article judges that by 2030, RISC-V’s share of industrial edge chip shipments may rise from under 7% to over 24%, with the key to competition lying in toolchains, RTOS, and certification systems; it also previews a forum at the Shanghai Industrial Fair Guoxin Exhibition starting 10-12 titled “Can RISC-V Crack the Hard Nut of the Industrial Edge.”

Date: 2026-10-11　Source: peripherals-imu feat/bmi270-iio branch (10-11), peripherals-motor feat/m8010a-native-uart branch (10-11)

Two feature branches in the spacemit-robotics peripheral libraries advanced during the window: peripherals-imu added BMI270 IMU kernel IIO reading support (previously had BMI270 SPI event-driven and IWT603 UART drivers); peripherals-motor tightened native UART transaction boundaries for the M8010-A motor (previously added M8010-A RS485 shared library driver). V. Summary and Trend Observations

  • Two kernel low-level tracks advance in parallel: After LPC26, 8 RVA23u64 profile bits have entered riscv/for-next (glibc will build and distribute by profile, and the userspace interface for dynamically disabling the V extension will be deprecated); kernel auto-vectorization experiments show roughly 15% gains on LZ4, and the long-standing taboo of “using vectors in kernel space” is being re-evaluated.
  • Distribution configuration upgrades: RevyOS kernel synced to 6.17.11 and enabled Rust, PowerVR, NTSYNC, and other features for K3/TH1520/SG2042 and other platforms; openRuyi updated Go/OpenSSL and split docker-cli, with enhanced lookout inspection capabilities.
  • Edge competition narrative takes shape: A 36Kr long-form article and Qualcomm v. Arm courtroom discussion point to the same judgment—RISC-V already has “qualifying status” in embedded/edge, while data centers still need time; the 26th China International Industry Fair Guoxin Exhibition begins today (10-12) in Shanghai.
  • Edge-side and domestic team deployments: Espressif (esp-vision tracking and IPA statistics), Sophgo (zsbl v3.2.1, LLM-TPU model adaptation), Sipeed (SLogic v2.1.0), and SpacemiT (robotics peripheral libraries, documentation terminology unification) all had substantive commits.
  • To watch: Real-world feedback on the Ubuntu 26.10 (released 10-15) RISC-V desktop image; the direction of the RVA23 series v9 submissions and kernel vectorization discussions; follow-up performance validation of XiangShan’s compressed ROB.
