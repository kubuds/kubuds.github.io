I. Open-Source Community and Software Ecosystem

1.1 XiangShan: Structural Refactor of Vector Execution Path (Removal of VFAlu/VFMA Wrapper Layers), Dashboard Releases 1.0.0 and Adds Zicfilp Template (09-09)

Date: 2026-09-09 (Beijing time batch from 09:26 that day to 06:45 the next day)　Source: GitHub openxiangshan/XiangShan commits, XiangShan-Dashboard, difftest, XiangShanLab

The vector subsystem of the XiangShan open-source high-performance core (Kunminghu) has shifted from “feature rollout” to “structural refactor”: at 22:06 on 09-09, two adjacent commits respectively removed the VFAlu and VFMA wrapper layers for vector floating-point operations (refactor(vector): remove VFAlu wrapper and set fuGen to null in VfaluCfg, remove VFMA wrapper and set fuGen to null in VfmaCfg), switching to direct generation via functional unit configuration. This is a path cleanup following the consecutive merges from 09-06 to 09-08 (whole-register move, vfma/vfmac and widen instructions, VIDiv vector integer division), and typically indicates that this group of instructions has entered stabilization and a preliminary stage for subsequent matrix/reduction operation extensions. Other commits in the same window cover frontend and execution details: 09-09 23:36 fix(decode,rename): handle JAL/JALR link and jump uops (author date 05-08, a wrap-up merge of a long-running branch batch), 09-09 09:26 fix(I2F): pipeline move op's fflags result signal (#6519), 09-09 15:17 ci(emu): determine emu-mc threads with verilator version (#6517). On the supporting side: XiangShan-Dashboard released release: 1.0.0 at 03:10 on 09-10 and added version and build-time badges; difftest merged fix(fpga): recover specified name of XMR probe (#959); XiangShanLab added a Zicfilp (landing pad jump target validation extension) template; GEM5 added a repository code owner. Within the window, 16 repositories in the openxiangshan organization (XiangShan, difftest, GEM5, CoupledL2, XSCache, gsim, rocket-chip, ZhuJiang, etc.) had pushes, remaining the most active open-source core team at present, with verification and toolchain support evolving in sync.

II. Product and Ecosystem Updates

2.1 Waveshare Launches ESP32-C5 Pico Board: Dual-Band Wi-Fi 6 RISC-V Micro Board in Raspberry Pi Pico Form Factor (09-09)

Date: 2026-09-09　Source: CNX Software, Open Source For You, Waveshare Documentation Site, GitHub waveshareteam/ESP32-C5-Pico

Waveshare has released the ESP32-C5 Pico board, bringing Espressif’s ESP32-C5 dual-band Wi-Fi 6 SoC into the Raspberry Pi Pico form factor (approximately 51 to 56.85 x 21 mm). Key specifications: ESP32-C5-MINI-1/1U module (ESP32-C5HF4, single-core 32-bit RISC-V up to 240 MHz plus a 48 MHz low-power RISC-V core, 384 KB SRAM, 320 KB ROM, 4 MB SPI flash); wireless support for dual-band 2.4/5 GHz 802.11ax Wi-Fi 6 with Wi-Fi 4 backward compatibility, Bluetooth 5.0 LE (including Mesh), and 802.15.4 (Zigbee 3.0 / Thread 1.3 / Matter). On-board USB-C (power, flashing, charging), 2x20 pin Pico-compatible headers (up to 26 GPIOs, 20 PWM channels, plus 6 more via TCA9554PWR expander), reset and BOOT buttons, RGB LED, and lithium battery charge/discharge circuitry; available in four versions (on-board PCB antenna or IPEX external antenna, headers pre-soldered or unsoldered), with software support for Arduino IDE and ESP-IDF, and example code migrated from the official website to GitHub (board info, RGB, I/O expansion, dual-band Wi-Fi, UART, 1.83-inch touchscreen, MCP2515 SPI CAN, etc.). Significance: Since the ESP32-C5 entered mass production in April 2025, its “dual-band Wi-Fi 6 + RISC-V” capabilities are spreading downmarket along the Pico-compatible form factor, with the third-party board ecosystem (Waveshare being a Shenzhen manufacturer) serving as a direct amplifier for Espressif’s RISC-V wireless MCU deployment.

2.2 GigaDevice Podcast Discusses RISC-V, Robotics, and Edge AI: GD32 Dual-Architecture Strategy and EtherCAT Distributed Control (09-09)

Date: 2026-09-09　Source: Electropages, GigaDevice Humanoid Robot Solution Page, GigaDevice GD32V Launch Announcement

In an Electropages podcast (Robin Mitchell in conversation with GigaDevice Business Development Manager Kevin Jones), the company’s MCU strategy was discussed systematically: on RISC-V, GigaDevice was an early mainstream adopter, launching the GD32VF103 back in 2019 (with the core provided by Nuclei, a publicly acknowledged collaboration), and its current wireless product line also uses RISC-V; the company emphasizes that architectural flexibility allows chip vendors to customize processors around specific applications and workloads. On robotics, the multi-motor and complex motion requirements of industrial robots are raising determinism demands for inter-controller communication; the GD32H7 series supports EtherCAT, enabling distributed MCUs to each control individual motors and local subsystems, reducing reliance on sending all decisions back to a central processor. On edge AI, local inference tasks such as motor anomaly detection and human presence detection need not depend on high-end AI processors; Cortex-M7/M33 can handle them after model pruning, helping reduce dependence on the cloud in cost-sensitive scenarios. Combined with GigaDevice’s humanoid robot solution page (a “perception—decision—control—actuation” architecture, with MCU, memory, and analog chip combinations covering dexterous hands, joint modules, IMUs, power management, etc.), this illustrates its domestic MCU positioning of “Arm + RISC-V dual architecture + robotics/edge AI.” This item is interview-based content with no new product launch, included as a strategic observation.

III. Domestic Team Updates and Deep Dives

3.1 SpacemiT: Next-Generation Coherent Interconnect Bus N200 Completed, Forming Three Major Segments of General Computing + Intelligent Computing + Interconnect (released 09-07, backfilled in this issue)

Date: 2026-09-07 (company release; missed in the previous two windows, backfilled in this issue)　Source: SpacemiT official website news, GitHub spacemit-com/model_zoo_rl, spacemit-com/ai-sdk

SpacemiT disclosed on its official website that its next-generation self-developed high-performance coherent interconnect bus N200 has officially completed development. Following its layout of general-purpose computing CPU cores (X60/X100/X200) and intelligent computing AI cores (A60/A100/A200), the completion of N200 marks the finalization of its three core technology segments: “general computing, intelligent computing, and computing interconnect”; N200 will be used together with the general computing core X200 and the intelligent computing core A200 in its next-generation computing chip, with mass production expected in 2027. This is an architectural deepening move following K3 (the world’s first mass-produced RISC-V AI CPU compliant with the RVA23 specification, 60 TOPS, supporting on-device inference for 30 billion to 80 billion parameters): a self-developed interconnect bus means its next-generation chip will shift from “adopting off-the-shelf NoC” to full-stack self-development, directly supporting multi-core coherence and AI core collaboration bandwidth. On the GitHub side within the window, SpacemiT (spacemit-com)’s on-device AI toolchain continued to iterate: ai-sdk updated the rl/vision submodules multiple times on 09-09 at 14:01 and 17:45, and at 00:22 the next day (Beijing time); model_zoo_rl merged feat(rl): support inference cancellation and YAML provider selection (#11) on 09-09 at 20:19; model-zoo-vision, docs-ai, and linux also had pushes. The RL model zoo and features such as inference cancellation and YAML provider selection correspond to the practical needs of robotics and embodied scenarios for interruptible inference and multi-backend switching. (Note: the company’s news page also lists items in the same batch such as K3 running DeepSeek Harness and exhibiting at GIS 2026; the corresponding events all fall in earlier windows and are not re-included.)

3.2 Nuclei: UK Media Reviews Quintauris RISC-V Ecosystem Collaborations, Nuclei Automotive-Grade IP Aligns with RT-Europa (English media review 09-08~09, collaboration itself from H1 2026)

Date: 2026-09-08 (Electronics World review article; New Electronics reported on the same topic on 09-09)　Source: Electronics World, Automotive World, Quintauris newsroom, Nuclei announcement (2026-06-16)

UK media outlet Electronics World published a review article on 09-08, with New Electronics following on the same topic on 09-09: Quintauris is expanding its RISC-V ecosystem through sustained collaborations, adding four partnerships in H1 2026—Elektrobit (04-21, automotive software, serving software-defined vehicles), Nuclei (06-16, automotive-grade RISC-V processor IP aligned with the Quintauris RT-Europa real-time platform specification), Ashling (debug and development tools), and the EM-Altair Profile specification, covering software, hardware, and toolchain. The core of the Nuclei portion is: RT-Europa is the first platform specification for automotive real-time RISC-V processors (defining deterministic memory access, interrupt handling, privilege modes, physical memory protection, debug interfaces, and SoC integration requirements), with which Nuclei aligns its production-validated NA series; the Nuclei NA series is the world’s first RISC-V processor IP to pass ISO 26262 ASIL-D certification, covering ASIL-A through ASIL-D, with more than 300 customers, applied in LiDAR, millimeter-wave radar, domain controllers, automotive-grade MCUs, automotive Ethernet, and SoC safety islands. It must be made clear: this item is an English-media review-style re-report of existing collaborations, and the collaborations themselves all occurred in H1 2026 (not new events in this window); its value for inclusion lies in once again amplifying the industry signal that “Chinese RISC-V IP has entered an international automotive-grade reference platform”; within the window, the 42 repositories in the Nuclei-Software GitHub organization had no pushes, and there was no independent development activity.
