Today’s Highlight: DAMO XuanTie Submits Zvfc Complex Vector Extension Proposal with 18 Instructions (11-23)

On November 23, DAMO XuanTie submitted an extension proposal in the XUANTIE-RV/zvfx-proposal repository. The proposal is named Zvfc, short for Vector Floating-Point Complex Arithmetic. The repository is a mirror branch of riscv-unified-db, and the proposal is written into the standard extension slot under spec/std/isa following UDB’s YAML structure. The submission comprises 21 files, including 1 extension definition, 18 instruction definitions, and 2 golden sample updates.

Zvfc defines 18 instructions. vfcjadd.vv and vfcjsub.vv are add/subtract with j rotation, available only in vector-vector form. vfcmul, vfcmacc, vfcnmul, and vfcnmsac each have real (r) and imaginary (i) forms, and each group has both .vv and .vs forms. Complex numbers are stored as adjacent element pairs, with even indices holding the real part and odd indices holding the imaginary part.

The extension depends on Zve32f, version number 0.1.0, status marked as development. Multiply-accumulate is treated as a fused operation, with component products not rounded first. The register group must be able to hold one complete complex pair, otherwise the instruction is reserved. Odd vl is allowed; odd vstart is reserved. Implementations may read one extra source element when vl is odd, and only active output elements generate floating-point exception flags. The file header copyright is attributed to Alibaba Damo Academy.

RISC-V 100 Leaderboard Update

LineShine Entry Retitled TOP500 #1, Scoring Basis Clarified (11-21)

The riscv100.top inspection today reported a notable change, which upon review turned out to be the site retitling the November 21 announcement. The original title was LineShine LX2: SPEC CPU2017 Rate on One Node (256 copies). The current title is TOP500 #1 LineShine: Single-Node SPECrate 422/452. The announcement slug is unchanged, still 2026-11-21-lineshine-lx2-spec17-rate.

The leaderboard record itself is consistent with the previous issue. Date November 19, compiler LLVM 23.1.0, platform LineShine-LX2, integer 272.258, floating-point 291.613, status completed. The 422 and 452 in the new title are raw scores not normalized by clock frequency. 422 divided by 1.55GHz gives 272.258, and 452 divided by 1.55GHz gives 291.613.

LineShine is a CPU-only supercomputer at the Shenzhen National Supercomputing Center, with LX2 being an Armv9 platform. This record enters the cross-architecture comparison leaderboard, serving to provide a same-board baseline for RISC-V platforms. It does not constitute a RISC-V result. The six RISC-V channel leaderboards saw no new additions this issue, and there were no additions or removals of committee members.

Date: 2026-11-21　Source: https://riscv100.top/cross-arch/spec17/ .

I. Open-Source Community and Software Ecosystem

openRuyi 35 commits: nodejs bumped to 26.13.1, RISC-V return address offset fixed (11-23)

On November 23, the openRuyi main repo landed 35 SPECS commits within the window. nodejs was bumped to 26.13.1, with one commit specifically fixing Wasm frame code lookup and the RISC-V return address offset. The same batch switched nodejs to LLD, system Abseil, and shared Temporal, and adjusted test expectations for OpenSSL 4.

The remaining changes were spread across the graphics and language stacks. mesa was bumped to 26.3.1, opencv to 5.1.0, and linux and linux-lts refreshed their patch sets and configs. On the Rust side, 20-plus ICU4X-related packages were added in one go, including icu-calendar, icu-locale, diplomat, tzif, ixdtf, and temporal-rs. There was also an RPC schema fix for spdk-mcp, and python-mcp restored the pyjwt crypto extra.

Date: 2026-11-23　Source: https://github.com/openRuyi-Project/openRuyi.

ruyifirmware: EDK II bumped to edk2-stable202611, SG2042 switches to SBI for runtime variables (11-23)

On the same day, the companion firmware repo ruyifirmware landed 7 commits. The EDK II baseline was updated to edk2-stable202611, and the firmware version number now derives from the EDK II checkout. Persistent runtime variables on the SG2042 platform now go through SBI calls instead of relying on a platform-specific storage path.

CI was also re-based. One commit builds firmware in Debian 13, another switches to Ubuntu 26.04’s GCC and removes libgcc from coreboot. A separate commit adapts the K3 PCIe driver for GCC 16.

The edk2-ruyi repo synced 4 commits. The changes require RISC-V EFI memory maps to use identity mapping, decouple SG2042 runtime variables from high-address MMIO, and write the firmware identifier into the DSC. The Spacemit platform package moves PCIe sub-device initialization ahead of port validation.

Date: 2026-11-23　Source: https://github.com/openRuyi-Project/ruyifirmware.

XiangShan GEM5 adds RVWMO litmus tests to weekly regression (11-23)

The XiangShan GEM5 repo saw 5 commits that day. The latest hooks RVWMO litmus tests into the weekly regression. Another fixes write side effects of pure CSR reads and SATP squash under RISC-V, and another relaxes ordering constraints on read-only CSR instructions. The batch also includes a fetch-block trace database for cpu-o3 and a panic fix for bad addresses in the o3 commit stage.

Date: 2026-11-23　Source: https://github.com/OpenXiangShan/GEM5.

CVA6 and CVW: vector-mode base addresses aligned to 256 bytes, floating-point vectors run on Verilator (11-23)

On the openhwfoundation side, CVA6 merged a base-alignment commit that aligns the BASE of stvec and vstvec to 256 bytes in vector mode. CVW moved the TestFloat and cover-float vectors onto Verilator, comparing vector by vector.

On the same day, core-v-mcu fixed uDMA’s QSPI quad-line LSB-first reception and camera VSYNC polarity, and cvfpu-uvm added a test plan and functional coverage model.

Date: 2026-11-23　Source: https://github.com/openhwfoundation/cva6.

libRPMI seven commits: clock tree resource release and clock group test coverage (11-23)

riscv-software-src’s libRPMI saw 7 commits that day. The two core changes release all resources on clock tree destruction and fix rate counting for clock group linear ranges. On the test side, cases were added for clock group linear ranges and set rate round down and auto modes, and the README and logo were updated.

Date: 2026-11-23　Source: https://github.com/riscv-software-src/librpmi.

II. Product and Ecosystem Updates

Espressif esp-riscv-trace adds instruction semantic decoder and fault window (11-23)

Espressif’s esp-riscv-trace repo saw 6 commits that day, with two feature lines merged into master. On the decode side, an instruction semantic decoder was added and RV32 shared encoding rules were extracted into encoding.py. On the analysis side, a fault window for register origin backtracking was added, and callee names were filled in for calls entering untracked code.

The repo targets RISC-V instruction trace analysis, processing the trace stream emitted by the chip. In the same window, Espressif had routine commits to arduino-esp32 and IDF-related repos, with no RISC-V-specific changes.

Date: 2026-11-23　Source: https://github.com/espressif/esp-riscv-trace.

SpacemiT G1 integrates SONIC planner: gait, steering, and teleoperation merged (11-23)

SpacemiT spacemit-robotics saw 7 commits that day, centered on merging the feat/sonic-planner-teleop branch. The humanoid_unitree_g1 repo configured gait and steering control for the SONIC planner, and another commit corrected the documented turning speed value; PR #26 has been merged.

humanoid_common concurrently added support for real-time motion presets and heading control, with PR #41 merged. The changes in the two repos appear in pairs, indicating the planner interface landed at both the common layer and the model layer.

Date: 2026-11-23　Source: https://github.com/spacemit-robotics.

Go2 adds learned self-righting and dance policies (11-23)

The unitree-go2 repo merged PR #7, themed on learned self-righting and dance policies. Self-righting means the robot gets up on its own via a policy network after falling, rather than following a fixed action sequence. docs-ros added go2 self-righting and dance documentation the same day, and another commit reorganized the K3 depth-vision grasping chapter.

Date: 2026-11-23　Source: https://github.com/spacemit-robotics/unitree-go2.

V. Summary and Trend Observations

  • Standards layer: XuanTie’s Zvfc turns complex arithmetic into an RVV extension proposal, written directly into UDB’s data structures. Domestic vendors submitting ISA extensions in standard format has been uncommon until now.
  • Firmware layer: ruyifirmware and edk2-ruyi advanced on the same day. The EDK II baseline, SBI runtime variables, K3 PCIe, and SG2042 decoupling were all done together.
  • Robotics layer: Two SpacemiT repos integrated the SONIC planner in sync. The common layer provides the interface, the model layer provides the parameters.

Taken together, there were no launch events or new benchmarks that day. The verifiable progress all landed in structure: ISA definition files, firmware call paths, planner interfaces. This kind of work doesn’t make headlines, but it determines whether later platforms can be reused. The closest media items that day were follow-up reposts by RISC-V Club and T-Head’s capital narrative. The former was already covered in the November 23 issue; the latter centers on PPU and the Yitian line and is not RISC-V.
