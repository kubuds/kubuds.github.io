Today’s Highlights: MiniMax-M3.1-Flash Nine-Chip W8A8 Delivered Same Day; Runtime 2.3.0 Enters Rebuild Authorization; FlagQuantum Logs 505 Commits in Three Days (10-23 ~ 10-26)

Date: 2026-10-23 ~ 2026-10-26　Sources: FlagOS Multi-Chip Support Notes (MiniMax-M3.1-Flash) · FlagRelease model organization · build-infra PR #1484 · FlagQuantum commits (full list in appendix)

  • Delivery: MiniMax open-sourced M3.1 Flash on 10-23, and the FlagOS community listed W8A8 versions for nine chips on ModelScope and Hugging Face the same day: DAMO XuanTie (Zhenwu), NVIDIA, MetaX, Hygon, Huawei Ascend, Moore Threads, Iluvatar CoreX, Kunlunxin, and Tsingmicro. The nine repos were created in a burst between 14:06 and 14:39 on 10-23, with two additional video-model repos and dual versions of Hygon MiniCPM-V 4.7 following the same day.
  • Technical: FlagOS converted the model’s original QAT NVFP4 weights into a cross-chip unified W8A8 format. NVIDIA, Ascend, Kunlunxin, and DAMO XuanTie offer Express editions (model names carry -FlagOS-Express), while the other five are standard editions; the source path is given using the DAMO XuanTie example, combining vLLM 0.24.0 with vllm-plugin-FL 0.3.0 and FlagGems 5.4.0, with 8-card tensor parallelism.

  • Assessment: This is the second “nine chips ship on model open-source day” within a week, following GLM-5.3-Flash. The difference lies in the form of the deliverable: the previous round ran BF16 and multiple precisions in parallel, while this round converges on a single W8A8 path and packages four commonly used platforms as Express editions — indicating that Day-0 delivery has moved from “can it run” to “batch replication in a unified format.”

1.2 FlagRelease: MiniMax-M3.1-Flash W8A8 Lands on Nine Chips Same Day, Four Use Express Edition (10-23)

Date: 2026-10-23　Source: FlagOS multi-chip support notes · FlagRelease organization models · vllm-plugin-FL PR #631

  • Adaptation scope: Nine platforms—DAMO XuanTie (Zhenwu), NVIDIA, MetaX, Hygon, Huawei Ascend, Moore Threads, Iluvatar CoreX, Kunlunxin, and Tsingmicro—all offer W8A8 versions. Model repos sit under the FlagRelease organization, published via both ModelScope and Hugging Face.
  • Quantization path: FlagOS converts MiniMax’s native QAT NVFP4 weights into a cross-chip general-purpose W8A8 deployment version, with no secondary training on-device. NVIDIA, Ascend, Kunlunxin, and DAMO XuanTie are Express editions, named MiniMax-M3.1-Flash-W8A8-<platform>-FlagOS-Express; the other five are standard editions.
  • Model specs: M3.1 Flash has 428B total parameters and 23B activated, supports 1M context and image/video input, and adds an adjustable thinking-depth parameter. Official figures cite nearly 3x faster online inference than the previous generation and a 70% drop in composite token cost for agent scenarios.
  • Deployment path: The docs offer two routes—the recommended one is to use FlagRelease images directly (pick the repo by chip, pull drivers and containers by model card), or install from source: the DAMO XuanTie example uses vLLM 0.24.0, vllm-plugin-FL 0.3.0, and FlagGems 5.4.0, adding FlagTree and FlagCX as needed, and serves with tensor_parallel_size=8.
  • Code-side support: vllm-plugin-FL merged “add MiniMax-M3.1 support and inference example” (#631) at 10-24 08:25, bringing model integration and inference examples into main together; FlagGems-vllm merged the PPU-side flash_mla_sparse_fwd (#975) at 10-23 17:19, matching M3.1’s sparse MLA path.
  • Assessment: All nine repos were created within half an hour, showing the release pipeline is now templated. The real differentiator is the runtime matrix in each model card (framework version, plugin branch, FlagGems commit, whether FlagCX is needed)—which is also the verifiable basis for judging whether adaptation is genuine.

IV. Summary and Trend Observations

  • Day-0 delivery enters a phase of batch production: Within one week, GLM-5.3-Flash nine-chip and MiniMax-M3.1-Flash nine-chip were released simultaneously on the same day in two consecutive rounds, and this round is unified to a single W8A8 path with four Express versions. The replicability of delivery has been established; the next observation points are “whether the same format is stable across different models” and whether the model card version matrix is updated in sync with upstream upgrades.
  • 2.3.0 is in a suspended period of “authorized but unreleased”: All four items in build-infra—gating, changelog, rebuild authorization, and version parameterization—are in place, but the tag has not yet been cut. Unlike before the 2.2 release, this round makes “selecting component versions at container startup” a formal capability, meaning the runtime is decoupled from the operator library and compiler versions; in the long run this will change the granularity of adaptation and validation.
  • Organizational activity is highly concentrated in the quantum stack: FlagQuantum alone accounts for 82.5% of commits and 54% of merges. This concentration brings rapid structural reorganization (QEC package split, Quafu SDK switch) but also causes a marked decline in the organization’s “non-quantum side” throughput—daily average merges fell from 163 to 91, with the main gap coming from the decline in FlagGems and FlagGems-sglang.
  • The competition track becomes the main channel for operator supply: The vast majority of FlagGems-sglang’s 34 merges come from external contributors’ Competition-Track1, with 30 merges possible within two hours. Supply is fast and review is concentrated; filling in test contracts relies on subsequent batches, and the long-term quality of this channel needs observation of defect regression rates.
  • Vendor-side fixes enter a long-tail period: The actions of Kunlunxin, Ascend, MetaX, and Moore Threads this period are mainly “fixing existing operators until they work,” plus one rollback of a mistakenly ported CPU operator. This is an inevitable stage after backend onboarding, and it also shows that 2.2’s list of 1,454 operators still has coverage and precision gaps on real chips.
  • The information landscape is relatively quiet: Of 44 news candidates, only 3 are valid; there are no new version releases and no new repository creations (the new repos were all created between 10-13 and 10-14). The main body of this period’s content comes from GitHub, a typical “code active, launches silent” window.
  • Limitations: This period’s commit retrieval uses GitHub search’s total_count basis (612 commits), deduplicated by commit URL and assigned to repos one by one; individual repos may have a ±1 error due to cross-page duplication; FlagQuantum’s 505 includes merge commits and branch sync commits and cannot be equated with 505 functional changes; FlagRelease timestamps are Hugging Face’s UTC records, converted to Beijing time; expressions such as “Day-0” and “first” in vendor press releases are company statements and have not been verified by third parties; InfoQ’s cost figures are estimates converted from rental fees, not measured comparisons.
