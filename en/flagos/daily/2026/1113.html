  • Version transition: 16 build-infra PRs make corex5.0.1 the default for both the base and runtime lines, retiring the corex4.4.0 build layer; they add the driver user-space components, libopenmpi3t64, and a pinned flagcx 0.14.1, and backfill changelog dates entry by entry. This is not an incremental patch but a wholesale move of the SDK baseline forward by one version.
  • Three CI fronts: FlagScale #1322 wires BI training into the shared CI framework, Megatron-LM-FL #213 adds the BI-V150 pipeline and dev image, and FlagCX #711 fixes duplicate host-device helper definitions in the Iluvatar build.
  • Compilation and routing: FlagTree #1633 optimizes sort with tle_raw, FlagTree #1488 bumps the SDNN object to v0.3.6.9.1; Torch-FL #808 routes add.Tensor to FlagGems while preserving the complex-number escape path.
  • Under review: If FlagCX #714’s GDR and PXN capability hooks merge, Iluvatar will gain memory registration and topology discovery on the multi-node communication side — a step from “runs on a single node” toward “scales across nodes.”
  • Assessment: This round for Iluvatar is a version transition rather than operator volume; 16 PRs concentrated on a single SDK version indicate that 2.3.0 will take corex5.0.1 as its release baseline, with subsequent operators and CI hanging off that line.

3.5 T-Head: PPU Adaptation for vLLM 0.32 Lands, Marlin MoE and Log-Linear Attention Advance in the Same Week (11-12)

Date: 2026-11-12　Sources: vllm-plugin-FL #706 (PPU on 0.32) · FlagGems-vllm #752 (Marlin MoE) · FlagAttention #134 (Log-Linear Attention, under review) · build-infra #1751 (thead wheel guard)

  • Inference framework: #706 brings vLLM 0.32 (0.5.0-dev) to PPU-ZW810E using a “0.32-empty” adaptation: removed symbols and their call sites are deleted, with no 0.28 compatibility stubs retained. This is the key PR moving the T-Head line directly from 0.28 to 0.32.
  • Operators: #752 adds a unified fused_marlin_moe backend covering W4A16 INT4/MXFP4 and W8A16 INT8/FP8; the W8 path uses 64-element K tiles and packed BF16 instructions to reduce decode overhead, with MXFP4 scale conversion moved into CUDA Graph capture.
  • Attention: #134 is under review, adding Log-Linear Attention to the T-Head backend; 4 correctness cases pass on a single PPU-ZW810E and forward comparison is done against t-head/flash-linear-attention-for-sail. Such linear attention operators are candidate paths for long-context inference, but only one backend is currently pushing them.
  • Packaging pipeline: build-infra #1750 adds ppu and corex5.0.1 lines to flagcx and retires corex4.4.0, #1751 opens up thead in the wheel release guard, and #1768 records the ppu and corex5.0.1 lines; the flagcx wheel pipeline for PPU is now through.
  • Terminology: PPU in this section refers to T-Head’s AI accelerator card product line and is unrelated to DAMO XuanTie’s RISC-V processor line; thead is the upstream branch name T-Head continues to use and must not be written as “DAMO XuanTie.”

  • Moore Threads: #8539 optimizes FP8 TopK selection with an exact codebook histogram; on the KernelGen side, 5 MThreads-specific operators (grid_sampler_3d, upsample_nearest3d_backward and grad_input, conv_tbc, convolution_double_backward, greater) are under review, aimed at filling operator coverage rather than performance optimization.
  • Enflame: #8785 and #8968 fix compilation issues for the foreach family and asin_, erfc_ on GCU300; FlagCX #712’s ECCL device API is under review, and if merged Enflame will gain a device-API-level communication backend.

  • Intellifusion: FlagTree #1598 merges the Intellifusion backend (Triton 3.8, ifwa:100 target), including lowering, software pipelining, async copy, and a standalone wheel workflow; it is not yet registered in the README mainline matrix and counts as a newly added backend. This is also the first new vendor to join in the 2.3 cycle.

IV. Summary and Trend Observations

  • 2.3.0 moves from “scheduling proposals” to “filling in image docs”: Of the 28 build-infra PRs this period, 16 are the Iluvatar corex5.0.1 version transition and 12 are changelog backfills; the smallest unit of closure is now down to “one doc per backend.” This means release preparation is no longer about holding a meeting to set a date, but about aligning version data, drivers, and packaging lines backend by backend.
  • Version releases are gated in batches by backend: FlagTree 0.7.1 stable was granted only to ascend3.5 and xpu3.6, with the rest still at a1/a2/dev. This is not delay but the inevitable result of each backend passing CI on its own, and it also explains the pressure around the December 7 branch-cut node — backends not released before the cut can only ship pre-release versions.
  • The vLLM 0.32 migration becomes this week’s main thread: NVIDIA and T-Head have merged, and eight others are under review; yesterday’s py3.10 failure at Kunlunxin shows the real risk lies in platform differences, not API renames. The key question next period is “which vendor gives up on 0.32 first” or “whose patch lands upstream.”
  • Hygon’s “catch-up” investment is worth noting: 27 PRs in a single day, 20 foreach operators plus the bmm trio, directly reducing fallbacks on optimizer and matrix-multiplication paths. This kind of work makes no headlines, but it determines whether training scripts can run end-to-end on domestic cards, and changes usability more than single-point performance optimization.
  • The FlagQuantum surge needs to be viewed separately: 70 commits and 29 merges in one day advance both Hubbard/t-V model classes, parity symmetry, and native implementations of 216 programs at once. Quantum simulation is shifting from “demo” to “trainable model coverage,” but it remains far from productization and should not be read at release-level significance.
  • The news side and the code side continue to diverge: gnews component-name queries returned zero hits for consecutive periods, and nearly all facts this period come from GitHub. The daily brief’s judgments increasingly rely on first-hand data from commits, PRs, and the packaging matrix, with industry articles serving more as background than as evidence.
