3.1 T-Head: SDK Distributed Only via PAI-DSW Images, FlagTune Cost Model Enabled (11-06)

Date: 2026-11-06　Sources: Vendor doc thead · FlagGems #6497 · FlagAttention #127

  • Naming clarification: T-Head (Alibaba’s chip company) makes PPU (AI accelerator cards) and Yitian (Arm CPUs); thead is T-Head’s brand name and upstream branch name, and FlagOS’s backend keys thead-ppu*, the vendor doc docs/vendors/thead.md, and PPU_SDK in PAI-DSW all refer to this company. XuanTie was spun off from T-Head in 2024 and moved under DAMO Academy; it only makes RISC-V processors (C950, C908, etc.) and is unrelated to the PPU backend in this case—do not conflate the two.
  • Distribution constraint: T-Head provides no PPU SDK installer and keeps no source in the filestore; the SDK exists only inside its PAI-DSW training image, so the base layer can only reference that image directly (~25 GB), and changing versions means changing a FROM line.
  • Build location: The self-hosted runner for this backend is registered at the org level—it is the Alibaba Cloud PAI-DSW node itself, the only machine that can pull the domestically reachable vendor image; the node has no GitHub egress, and images are built directly on that node. Persistent storage is CPFS 685 GB, plus a writable OSS mount.
  • Compiler side: #6497 enables the FlagTune cost model for MM and MV; FlagAttention #127’s PPU-ZW810E Wall Attention was merged in the previous window, and this period marks its first corresponding base and runtime in the 2.3.0 delivery.
  • Assessment: From backend key versioning on 11-05 to the image and runtime on 11-07, T-Head’s FlagOS integration completed the three steps of “key—image—delivery” in two days; the app layer (vLLM and SGLang) is still under review.

IV. Summary and Trend Observations

  • The platform surface has moved from “having keys” to “being deliverable”: T-Head’s ZW810E PPU aligned backend key, base image, runtime changelog, and status matrix in four places within two days, and 2.3.0 is the first runtime delivery for this backend. The device is obtainable only inside the Alibaba Cloud PAI-DSW image and the runner has no GitHub egress—these two constraints determine a delivery shape different from other backends, and the app layer remains empty in the near term.
  • Operator production has entered a batch rhythm: 123 FlagGems merges in a single day, of which 87 Ascend operators were landed by one person within an hour, with another 20 Hygon dedicated operators queued for review. KernelGen has turned “writing operators” into “reviewing generated results,” shifting the bottleneck from implementation to review and acceptance—which explains why the number of PRs under review (269) stays persistently above the number merged.
  • The distribution layer is converging: TransformerEngine-FL supplies all non-NVIDIA vendors with a single pure-Python wheel, while FlagTree’s deb moves to one package per backend and the rpm builds directly from published wheels; both moves point at the same goal—reducing per-chip duplicate builds and keeping differences in configuration.
  • Framework adaptation comes in waves: Adaptation to vLLM 0.32.0 and SGLang 0.5.18 clustered within the window, covering five vendors—T-Head, Tianshu, MUSA, Kunlunxin, and Ascend—but the vast majority remain under review. Whether they can merge before the 11-30 rc0 is the key variable for whether 2.3 can be delivered per the matrix.
  • 2.3 enters the closing countdown: The community 2.3 schedule sets the FEP merge deadline at 11-13, feature freeze and rc0 at 11-30, rc1 at 12-07, rc2 at 12-14, code lock at 12-25, and GA at 12-30. No new FEPs were submitted this period; the six from 11-06 (0164 to 0168, 0170) remain Provisional Draft and self-describe as not having run GPU acceptance, so closing pressure concentrates in the coming week.
  • Risks and watch points: T-Head’s app layer not yet connected, all 20 Hygon operators under review, three of Tianshu’s four CI lines under review, and competition submissions only ingested without results—all four fall under “action taken, acceptance pending”; next week the focus should be on merge rate rather than new volume.

Corrections in This Edition

The PPU backend covered in this issue (thead-ppu2.1.0, ZW810E, PAI-DSW images, PPU_SDK) belongs to T-Head, not XuanTie. Previous editions labeled this backend line as “DAMO XuanTie,” conflating T-Head with XuanTie (the RISC-V processor unit spun off from T-Head in 2024 and transferred to DAMO); thead is simply the open brand name T-Head has continued to use and does not refer to XuanTie.
