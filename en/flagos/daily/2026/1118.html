1.9 Frameworks and Communication: Torch-FL Ascend Native Host Pilot Passes All 27, FlagCX Adds MUSA Platform (11-17)

Date: 2026-11-17　Source: Torch-FL #846 · FlagCX #712 · FlagCX #722 · sglang-plugin-FL #155

  • Torch-FL Ascend host: #846 adds experimental Ascend adaptation (+2232/-98, 35 files), using the shared native host ABI with the released FlagTree NPU loader and stock FlagGems kernels. The difficulty is in the ABI—Ascend uses packed structs rather than CUDA’s pointer arrays: booleans occupy 32 bits, FP16/BF16 scalars use float wire format, logical grids and workspace and locks and FFTS all depend on compiler metadata, plus ACL current-stream ownership issues. In testing, all 27 consistency cases passed with the wheel installed on 910C (29.90 seconds, zero skips, zero errors); the CI job on 85b1fd8e failed due to exhausted retries downloading FlagTree and needs a rerun; full-model logits and performance no lower than 0.8× the vendor PyTorch remain tracked in #833.

3.2 Ascend: Two Single-Core Fused Mega-Operators Deliver 1.34x and 1.18x (11-17)

Date: 2026-11-17　Sources: FlagGems-vllm #1286 · FlagGems-vllm #1287 · FlagGems-vllm #1239 · FlagTree #1637

  • MegaGate: #1286 adds a FlagTree TLE single core for 910B, fusing BF16 MoE routing projection with expert selection—the Cube core computes FP32-accumulated routing logits, the Vector core does scoring, optional bias correction, and group selection, returning top-k expert IDs and normalized routing weights; prepare_mega_gate binds the launcher and workspace to input shapes, routing config, and NPU stream, then reuses them on each call. Across 5 models and 353 shapes, average speedup is 1.336x over ACL Graph and 1.408x over Eager, with DeepSeek V4 Flash’s 106 shapes at 1.553x.
  • MegaMHC: #1287 fuses mHC post, mHC pre, and RMSNorm into a single core, supporting four residual streams and both normal and shifted execution; the shifted path uses the carried pre_mix to launch RMSNorm while the Cube computes the next projection. Across 63 shapes, average speedup is 1.175x over ACL Graph and 1.182x over Eager with pre-bound context, with DeepSeek V4 Pro at 1.773x for a single shape; Eager without pre-binding is only 0.648x, showing the gain comes from launch and workspace reuse rather than pure kernel arithmetic.
  • Supporting: #1239 switches mhc_pre to a mix-major layout and cleans up tests; #1637’s Triton 3.6.x backend port provides the compiler foundation for this class of TLE single cores.
  • Observation: Both changes focus on “single-core fusion + context pre-binding” and both include ACL Graph and Eager numbers. For Ascend, the gap between graph mode and eager mode is itself a product-line signal—the same kernel differs by over 20% between the two modes, so the deployment side’s choice of execution mode directly affects the payoff.

3.3 T-Head: INT8 MegaMoE Runs the Entire Expert-Parallel Pipeline in One Persistent Kernel (11-17)

Date: 2026-11-17　Sources: FlagGems-vllm #1274 · FlagGems #8526 · FlagGems-vllm #1280 · FlagTree 0.7.1+ppu3.6

  • Single-core scope: #1274 adds INT8 expert-parallel MegaMoE for the PPU backend (+4691/-8, 10 files), completing token dispatch, two expert GEMMs, SwiGLU, INT8 requantization, cross-card writeback, and merging within one resident FlagTree/Triton kernel; inputs are INT8 activations and expert weights plus FP32 scales and routing weights, output is on-card BF16. The caller provides a reusable context, symmetric peer buffers, and stream barriers.
  • Scheduling strategy: Eight-card workloads use whole-block dispatch; large-scale two-card and four-card workloads use partial return when every card satisfies the fast path. The EP group agrees on the return layout during context initialization, before CUDA Graph capture; when workspace alignment is inconsistent, the whole group falls back to per-route return, preventing cards from interpreting the same peer slot differently.
  • Same-day supporting changes: #8526 refreshes T-Head’s GEMM test shapes and layout coverage; #1280 optimizes cooperative_topk for PPU-ZW810E; the early-morning 0.7.1+ppu3.6 tag promotes the backend from the development line to the release line.
  • Observation: Packing dispatch, two GEMM stages, activation, quantization, writeback, and merging into one kernel saves a large amount of intermediate materialization and launch overhead, at the cost of requiring the caller to guarantee consistency of context state and peer buffers—which is why this change repeatedly emphasizes “layout aligned before capture.”
