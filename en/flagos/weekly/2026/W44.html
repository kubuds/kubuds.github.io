2026-10-30 Kubuds

Reporting period: Monday, October 26, 2026 to Friday, October 30, 2026, 5 working days in total.

Sources: 5 issues of this publication’s daily FlagOS update reports (10-26 / 10-27 / 10-28 / 10-29 / 10-30, with no missing issues during the period). The 10-26 issue is the Monday morning report, whose research window starts from the previous issue’s cutoff at 10-23 06:00, spanning 72 hours and covering the weekend of 10-24 and 10-25; the four issues from 10-27 to 10-30 use 24-hour windows that are contiguous, with the final window running from 10-29 06:00 to 10-30 06:00. The number of repositories with pushes in each issue was 16, 18, 20, 23, and 21 respectively, out of 61 organization repositories in total. Versions and tags were independently re-verified against the tags and Release atom sources of each component repository; the 10-31 verification result: the latest tag of build-infra remains v2.2.0, and the release/2.3 directory in the community repo still contains only the Chinese and English schedule tables, with no release manifest found.

I. Weekly Highlights

  • 2.3.0 completes the entire pipeline from runtime to application layer, but tags and release manifest still not in place (10-25 ~ 10-30): On 10-25, the 2.3.0 runtime was authorized for rebuild by version; on 10-26, twenty vllm0.24.0 application images were authorized for rebuild on the new runtime, and tags were consolidated from “backend-specific suffixes” into a unified 2.3.0-0.3.0; from 06:54 to 13:25 on 10-27, twenty consecutive bot commits recorded the application image tags for the twenty backend keys one by one; from 10-28 to 10-29, the changelog went live on the site page and Harbor. As of the morning of 10-30, the latest build-infra tag is still v2.2.0 from August 3, and community/release/2.3 still has no release manifest. Per schedule, 11-13 is the FEP merge deadline, 11-30 is feature freeze with rc0 pulled, 12-07 rc1, 12-14 rc2, 12-25 final seal, 12-30 release.

  • MiniMax-M3.1-Flash nine-chip W8A8 delivered same day, Day-0 enters the “unified-format batch replication” phase (10-23): On the day of MiniMax’s open-source release, FlagOS published W8A8 versions for nine chips on ModelScope and Hugging Face, with all nine repos created within half an hour between 14:06 and 14:39 on 10-23. The nine are DAMO XuanTie (Zhenwu), NVIDIA, MetaX, Hygon, Huawei Ascend, Moore Threads, T-Head, Kunlunxin, and Tsingmicro, with NVIDIA, Ascend, Kunlunxin, and DAMO XuanTie offering Express versions. The technical approach was to convert the model’s original QAT NVFP4 weights into a cross-chip unified W8A8 format; the source deployment example uses DAMO XuanTie as the baseline (vLLM 0.24.0, vllm-plugin-FL 0.3.0, FlagGems 5.4.0, tensor parallelism with 8 cards). This is the second “nine chips simultaneously on model open-source day” within a week, following GLM-5.3-Flash nine-chip; the difference is that the previous round ran BF16 and multiple precisions in parallel, while this round converges to a single W8A8 path.

  • Horizon BPU becomes a per-operator-executable PrivateUse1 backend for the first time, new platform goes from “unusable by design” to usable (10-28): Torch-FL #674 landed the per-operator execution layer (31 files, +5698 / -145). Previously, BPU registered no compute operators on PrivateUse1; hbDNNInferV2 only accepted a fully compiled graph, every aten call fell through to cpu_fallback, and backends_bpu.conf was empty. This PR fills in the missing intermediate layer: on the x86 side, hbdk4 compiles a per-operator .hbm artifact library, generates C++ kernels that commit these artifacts, and adds a drobotics conf route, covering 40 elementwise operators (32 unary, 8 binary) and 11 shape buckets, with all 440 artifacts on RDK S600 compared one by one against NumPy with zero differences. Three follow-up commits fixed the distribution log name, the CUDA copy kernel guard, and the vendor-name-to-platform-id mapping. The limitation is equally clear: backbone operators such as convolution still rely on the torch.compile full-graph path.

  • FEP-0140 changed to single release on 0.32, 0.28 skipped, AMD added, rules surface eliminates version-chasing cost in one pass (10-27 ~ 10-28): Two rewrites in the community repo (#157, #158) set the vLLM plugin’s multi-version compatibility strategy to “0.32 becomes the sole release version and covers all chips,” expanding the original scope of “five vendors selected by Day-0 demand” to the full matrix (the ten vendors of the 2.2 cycle plus NVIDIA and AMD); 0.28 is no longer a release version, with the matrix column and related PR sections deleted entirely, and already-merged 0.28 adaptations retained only as an upgrade baseline. On 10-28, profiling scope and validation plan were added (#159), and the status was changed to Implementable with Owner set to @ceci3 (#160); FEP-0141 was narrowed to SGLang 0.5.18 and basic functionality for MetaX and Tsingmicro (#161). The cost is stated explicitly: adaptations merged on 0.28 need to go through acceptance again on 0.32, and this workload is not yet reflected in any PR.

  • DAMO XuanTie fills two foundational gaps within a week: BLAS1 fifteen operator groups landed and PPU sparse attention (10-26 / 10-28): On 10-26, FlagBLAS #154 added fifteen Level-1 basic linear algebra operator groups in one pass — AMAX, AMIN, ASUM, AXPY, COPY, DOT, DOTC, DOTU, NRM2, ROT, ROTG, ROTM, ROTMG, SCAL, SWAP — touching 17 files with 16,168 new lines; previously this backend’s presence in FlagOS was concentrated in the inference path, with the numerical library a blank. On 10-28, FlagAttention #111 added MiniMax sparse attention inference operators for Zhenwu PPU (6 files, +4644 lines), supporting paged KV cache, causal masking, and forced block selection, with prefill passing 21/21 at a geometric mean of 2.299x and decode passing 18/18 at a geometric mean of 1.354x, for a total of 39/39 at a geometric mean of 1.800x. Measured against the three stages of “can run inference, can run training, numerical library self-consistent,” this week crossed the first step of the third stage.

  • MetaX moves acceptance evidence for 135 specialized operators into reviewable state, opening 135 PRs within an hour (10-27): FlagGems-Experimental opened #744 through #878 between 17:43 and 17:59, all titled “Add MetaX support for ," each a single file with roughly 200 lines changed. The PR description states this round is a retest of MetaX specialized operators (1027 batch): 150 operators participated, 135 passed three rounds of retesting and were submitted one by one, and the 15 that failed were left out of the batch; acceptance criteria were all 29 precision cases passing and a performance geometric mean of 1.008x (threshold 0.8), on an environment of torch 2.8.0 plus metax3.7.2.0, flagtree 0.6.1, and eight C550 cards. That day the organization's open PRs rose from 225 to 401, of which 135 came from this single batch submission.

  • Test infrastructure ref-as-candidate lands in two repos, “what to test” shifts from whether an operator exists to whether reference and implementation agree (10-29): FlagGems #7630 (9 files) lets correctness tests and benchmarks run an explicitly declared reference implementation as the candidate, no longer relying on external candidate files; missing references, non-callable references, and test bodies that do not actually invoke the candidate all fail explicitly. On the same day, FlagGems-sglang converted all correctness suites to get_candidate across eleven PRs #239 to #249, and added a daily automatic sync PR from master to kernelgen-dev (#242, two already generated that day); another 57 test fixes by the same author merged that day, covering skip conditions and reference ABIs for Ascend, MetaX, Enflame, Kunlunxin, and NVIDIA. This line produces no operator counts, but determines whether all subsequent backend alignment is trustworthy.

  • MiniCPM-OCR dual models achieve Day0 coverage on 12 platforms, first comparable normalized metrics (10-29): MiniCPM-OCR 1.0 (1.3B) and MiniCPM-OCR Jev (2B), open-sourced by ModelBest and OpenBMB, completed cross-chip adaptation, covering 12 platforms: DAMO XuanTie, NVIDIA, Huawei Ascend, Hygon, Kunlunxin, MetaX, Moore Threads, Tsingmicro, T-Head, Xiwang, Mac (ARM), and This Chip Technology. Performance metrics are stated separately: Jev averages 63.56 ms on DAMO XuanTie, with actual compute throughput reaching 98.7% of native NVIDIA H100; OCR 1.0, normalized by peak compute, achieves single-document P50 throughput at 169.3% of native and 137.1% in batch scenarios, with the explicit caveat that the 169.3% premise is higher utilization on low-peak-compute platforms rather than a faster single card; on the edge-side M5 CPU, Jev averages 1.2 seconds per page-block discrimination with a median of 895 ms.

FlagGems (224 Merges): Automated Supply and Correctness Fixes in Parallel

  • Operator supply is now handled by KernelGen: On 10-26, 16 KernelGen operators with the NVIDIA prefix were merged (one category each for sparse and structured, quantization, special functions, and tensor metadata). On 10-29 alone, 22 auto-generated operators landed (unsafe construction and reset of sparse tensors, nnpack spatial convolution, thnn convolution, fractional max pooling backward, cholesky, frobenius norm, chain_matmul, and a batch of edge-case operators), with five more opened the same day—the queue continues. Human effort goes not into writing operators but into launch parameters and test executability.
  • The correctness mainline is the week’s most valuable class of commits: The address arithmetic shared by index_put and _index_put_impl_ was changed to a wide type (#6892, two files, +112/−4 lines). Previously, on DAMO XuanTie PPU-ZW810E, int32 indices with large-stride tensors silently wrote to the wrong address—the target row was unchanged but guard prefixes within the same allocation were overwritten. The root cause: index-times-stride was evaluated in int32 and wrapped first, so converting only the final offset afterward came too late. On the Ascend side, flagtree was bumped from 0.7.0 to 0.7.1a1 with a new runtime validation script (#7837, five files, +291 lines), because the runtime image bakes flagtree into /opt/flagtree outside the virtual environment, so the pip-installed pin cannot override it. The Kunlunxin backend’s failure to import directly on current master was also fixed (#7803, 90 lines).
  • Backend tuning is densest on Kunlunxin: Eight out-of-place scalar-chain operators were converted to fused kernels (#7617, 275 lines)—single launch for small shapes, all pointers passed as kernel arguments, output allocated once and obtained via unbind; relative time improved from 0.083–0.126 to 0.813–0.934, roughly 7–10×. Batch-norm inference and QKV transform were converted to contiguous-segment kernels (#7600), with aggregate metrics improving from 0.228 to 1.357 and from 0.260 to 5.062, respectively. The integer-view fast path of masked_fill was rewritten in f32 form, improving from 0.577 to 0.829 on P800 (#7850, 594 test cases passing).
  • Other backends: Enflame’s conv_transpose2d was switched to seven hardware-tuned tiers indexed by data type, kernel size, stride, and output channels (#7036, +1886 lines), switching between direct-sweep and phase-specialized variants based on whether the output fits in L2. conv3d removed per-call channel zero-padding (#7061), with bit-identical output. MetaX added INT8 and FP8 grouped_mm_w8a8 (#6950, 7 files, +1220 lines); the benchmark shapes come from real call replays captured from GLM-5.2 on PPU SGLang TP=8—28 scenarios, 26 unique geometries, 3.24 million calls, 257 experts.
  • In-review structure: The 53 newly opened on 10-28 were mostly Enflame reference-implementation fixes (#7890 through #7908, consecutive numbers, covering Kaiser and inplace ldexp, aminmax, special_round, LU, vander and slogdet, median and stacking, Adagrad, batch-norm ABI), plus a one-line AMD fix—the vendor descriptor set the device name to cuda without providing triton_extra_name, causing pow, tanh, exp, rsqrt, erf, gelu, and others to all route through __nv_* and be rejected by the AMD backend. In the 10-29 window, FlagGems had 181 items in review, 60% of the organization, indicating that the bottleneck for multi-backend acceptance lies in reference implementations and test criteria, not operator supply.

FlagQuantum (226 Merges): From Structural Reorganization to Scenario Rollout

  • The week began with directory surgery: From 10-23 to 10-26, three days saw 505 commits and 148 merges, with this single repo accounting for 82.5% of organizational commits and 54% of merges. The QEC package reorganization ran through nine consecutive commits (#735 to #749): first auditing package boundaries and compatibility baselines, then sequentially isolating code matrices and noise sweeps, splitting code families and ownership, separating storage declarations from execution assembly, extracting the detector error model, separating decoding algorithms from optional adapters, finalizing package layout and installation guidance, and finally merging into main as a whole—directory surgery aimed at “installability.”
  • External dependencies take shape: The Quafu SDK lifecycle switch was completed in six commits (#852 to #866), with the discovery flow, logical tasks, physical program submission, topology resolution, and twin lifecycle each migrating to the SDK in turn, finally retiring the old execution lifecycle. The old path was deleted rather than kept as an alias—a hard switch. In the same period, Rydberg presence went from establishing the contract (#854) to rejecting observations in unconditional assembly (#865), encoding single-shot presence observations (#869), validating bounded coherent branch references (#873), and finally proposing finite dynamic coherent references (#876).
  • Mid-period shift to physical scenarios: The ten merges on 10-27 included expectation-value contraction of Module Hamiltonians under tensor networks (#939), fixed-shots error-correction memory experiments (#932), and completion of fixed two-qubit gate coverage (#935). Among the six on 10-28, “whether sharded MPS is equivalent to unsharded” was turned into two-arm executable evidence (#945: max_bond 64 with exact gradients changes only layout; max_bond 2 with approximate gradients changes both layout and truncation; the difference between the two arms separates the two contributions).
  • The week closed on the synthesis pipeline: 10-29 saw 60 commits and 15 merges, all concentrated on quantum circuit synthesis (the CS series). Ten specification and delivery documents are archived in the repo as FQ-SYNTH-CS01..CS07-20261029: CS-01 defines semantic boundaries and validation for coherent integer construction, CS-02 lowers coherent addition with pure arithmetic kernels, CS-03 handles multiplication and coherent polynomials, CS-04 opens up restricted Python workflows, CS-05 adds lifecycle and workspace scheduling, CS-06 lands in three stages, and CS-07 moves into register semantics and program admission. The same day added portable .fqx experiment file save/load (#960) and checked program execution for fq.run (#964).
  • Assessment: The quantum stack’s working method is four-stage evidence—design draft, contract draft, runnable example, acceptance record. It is costly but highly verifiable, which explains why it has long accounted for over 30% of organizational commits but only about a 30% merge rate. It is unrelated to multi-chip adaptation and is the only software-stack mainline in the 2.x cycle decoupled from hardware.

  • The bottleneck for 2.3 is no longer code, but whether the release can self-verify: The densest batch of work this cycle was not new operators, but gates, audit trails, retractions, and consistency checks—the changelog went from “human memory” to a push gate, published to the site page and Harbor; the application-page consistency check was wired into pre-commit; and two never-pushed images were retracted so that “the changelog file set equals the published set.” These actions produce no capability, but they directly determine whether the release manifest before 12-30 can be externally verified. The current state is that the build side is already accounting against 2.3.0 while the release manifest remains empty; the 11-13 FEP deadline and the 11-30 rc0 will compress the entire rc period.
  • The backend matrix continues to expand rather than converge in the 2.3 cycle: AMD ROCm 7.2.4 grew from a base image into a full backend, and the Horizon BPU went from “cannot be eager by design” to per-operator execution. What these two share is that the follow-up work required “only after integration” is extremely heavy—AMD needs builders and wheel rows added, the BPU needs distribution logs, copy-kernel guards, and vendor-name mapping, and the first hurdle for a new backend is always “it runs” rather than “it’s faster.”
  • Day-0 delivery has moved from “can it run” to “batch replication in a unified format,” and the next deciding factor is the measurement basis: Two nine-chip simultaneous releases within a week, with this round converging on a single W8A8 path and making four vendors Express editions, shows the release pipeline has been templated. The MiniCPM-OCR note goes further, stating the actual throughput ratio, the peak-normalized throughput ratio, and the on-device latency separately with explicit preconditions—this is more informative than a single multiplier and easier for peers to compare on the same basis in the next round.
  • With operator supply automated, all human effort shifts to correctness and contracts: KernelGen generating 22 operators in a single day and multiple batches per week has become the norm; by contrast, the most valuable commits this week were issues that “don’t error in tests but blow up in production”—int32 offset overflow in index_put, the Tianshu bf16 GEMM falling back to host, the Hygon DCU runtime linked from stubs, the missing shape-table load point in Enflame, and the Kunlunxin backend failing to import. The landing of ref-as-candidate in both repos plus 57 test fixes is the watershed that changes “what to test” from whether an operator exists to whether the reference and implementation agree.
  • The cost of rule convergence is deferred and comes due on 0.32: Skipping 0.28 appears to have eliminated the cost of chasing minor versions, but the adaptations already merged on 0.28 (Enflame S60, Tianshu, MetaX, Tsingmicro, Kunlunxin) need to go through acceptance again on 0.32, and no PR currently carries this rework. The first landing evidence for 0.32 in the same period is the native CUDA vLLM 0.32 adaptation (pinning vLLM 0.32.0 with cu129, PyTorch 2.13.0, Python 3.12.3); domestic backends have not yet begun.
  • The quantum stack has fully decoupled from multi-chip adaptation and become an independent mainline: FlagQuantum merged 226 commits in a week, accounting for 30% of the organization, and moved from structural reorganization (QEC package split, hard switch of the Quafu SDK) to scenario expansion (error-correcting codes, neutral atoms, thermal baths), then converged on the CS-01 to CS-07 circuit synthesis pipeline; FlagQAI built a local workbench in parallel. Its way of working is four-stage evidence retention—high cost, good verifiability—and it is the only software-stack mainline that does not depend on any chip vendor’s progress.
  • Three risk items need confirmation in the next issue: First, tags lacking release notes has become customary—FlagCX v0.14.1 and both FlagTree 3.6 special releases have only tags, forcing downstream to infer the backend and Triton version from the name; if 2.3 is delivered this way, verification costs will rise. Second, Cambricon has had no dedicated push within the organization for two consecutive weeks, leaving only a retraction record in build-infra; if this continues next issue, it should be listed separately. Third, the recovery of the training stack remains uncertain—Megatron-LM-FL has ten commits under review but zero merges this cycle, and FlagScale’s DeepSeek-V4 upstream sync has only reached [2/N]; training-side progress lags behind inference.
  • Next observation points: When the 2.3.0 tag is cut and when release-2.3.yaml is created; under the single-release 0.32 rule, when the first domestic backend (Ascend or Hygon) completes acceptance on 0.32; whether the BPU path expands from elementwise operators to backbone operators such as convolution; when FlagCV provides its first set of benchmarks and non-GPU backend data; and whether Megatron-MUSA-Titan code actually starts being pushed and forms reuse with Megatron-LM-FL.
