Compiler, Language Layer, and Execution Paths

  • PTO execution backend replaced (#3516, merged 11-11, 20 files +1549/−182): With target="pto" and execution_backend="auto", resolution now goes to tvm_ffi; shared host codegen handles MakePackedAPI and the C host, and the Ascend runtime launches the aibin produced by PTODSL via aclrtLaunchKernelWithHostArgs, matching the path used by AscendC kernels. On the device-build side, a new module-level toolchain callback compiles the entire PTODSL module in one pass (ptodsl → ptoas → bisheng fatobj-link → extract .aicore_binary), with the cache key incorporating ptoas arguments, ptoas version, and CANN identity. The old path is retained as execution_backend="pto", and the two sets of outputs are bit-identical; validation covers four new test groups: dynamic shapes, multi-device kernels, mixed cube/vector GEMM, and cache hits plus corrupted-entry error raising.
  • AutoSchedule tightens the cycle lower bound (#3776, 1 file +20/−1): Instead of bisecting from a fixed lower bound, it now takes the maximum of three necessary conditions — the single-task bound uses the maximum of each task’s initiation interval; the resource-clique bound sorts pairwise-conflicting tasks by residual value and derives, from adjacent differences and the head/tail differences, that the cycle is no less than the sum of initiation intervals within the clique; the self-dependence bound solves S_u - S_u >= wait - d*P for ceil(wait/d), with version-related distances scaled by num_stages. Empirically, on Ascend 950PR with the CANN 9.3.0 weekly build: all Ascend examples compile and scheduling results are unchanged, while cumulative Z3 solving time drops 10.04%. No additional lower-bound probing was introduced, and the scheduling model was not changed.
  • Cross-core synchronization forces batch scheduling to prevent deadlock (#3614, 5 files +102/−1, of which 78 lines are regression): mode=0 means “launch as soon as cores are available,” while mode=1 means “wait until all core resources the operator needs are in place, then launch as a whole.” An operator doing all-core synchronization, if launched in normal mode, may get only some cores and run ahead to an all-core barrier and wait there — while the cores it awaits are held by another stream, forming a resource cycle and hanging the device. The fix detects “cross-core synchronization with a constant 0” on the codegen side and automatically sets __schedmode__(1), resetting the flag per function to prevent leakage. It also narrows the integer mode_id of cross-core set/wait to 0/1/2/4 and documents that the three targets do not share the same mode set (910B/910C support 0/1/2, and only 950 adds 4).
  • VMI descriptor and logical-coverage validation closed out together (#3894, 6 files +925/−550): Fixes incorrect base address and stride when constructing descriptors for typed-view gather/scatter and single-element load forms; it also removes the frontend’s redundant logical-coverage rejection — removing the check is not a relaxation, but rather because the shared-memory detector fix (#3805) has landed, and a second frontend block would falsely reject cross-row, transposed, and dynamic views.
  • Two sets of instruction-level primitives added on the CUDA side (merged 11-10): #3490 (6 files +185/−1) adds L1 prefetch, uniform L1 prefetch, and L2 prefetch, and makes eviction priority a first-class parameter EvictPriority (six levels: default, normal eviction, evict-first, evict-last, no-change, no-allocate), with non-default priorities requiring compute capability 8.0 or above; #3605 (7 files +203/−1) adds T.clamp_symmetric(x, limit), which on SM86 and above clamps FP16/BF16/FP32 uniformly to [-limit, limit], preserving signed zero and subnormals, returning canonical NaN when any operand is NaN, lowering directly to a single min.NaN.xorsign.abs, and using the appearance of three scalar and packed forms in SASS as acceptance evidence.
  • Two preemptive hardening changes on the TIRx side (under review 11-11): tile-ai/tvm’s #94 ([Fix][TIRx] Make ceildiv exact for signed divisors) and #93 ([Arith] Guard negative scales in canonical split div/mod) fix two ends of the same class of problem — once signs enter integer division and modulo, the rewrite preconditions for canonicalization no longer hold. The main repo opened #3937 the same day (nested floor division produces wrong integers under negative multipliers) pointing at the same spot, except that #3937 is a user-side reproduction while #93/#94 are compiler-side preemption.

Correctness and Bug Fixes

  • Silently wrong code remains the heaviest category in the main repo: The new issue cluster in the 11-09 period centers on “computes wrong but raises no error” — #3842 (with warp specialization enabled, variable updates between pipeline rounds take effect only in the consumer branch), #3870 (in a copied parallel loop, fragment atomic operations and read-modify-write are each performed once per copy), #3871 (tvm_ffi calls do not restore the caller’s device on completion), #3877 (single-parameter kernels cannot launch on the NVRTC path), #3881 (on the cython path, dynamic shared memory over 48 KB fails on the second device); CuTeDSL’s unsigned semantics generated three issues in a row (#3874/#3875/#3876), the same type as #3808 and #3800 from the previous window.
  • CuTeDSL’s feature coverage and correctness boundary diverge in opposite directions: #3685 adds 63 files at once (+7075/−394), including warp vote, block predicate barriers, explicit-width load/store with cache hints, TMA and cluster copies, SM120 block-scaled MMA and NVFP4 GEMM examples, and incidentally fixes the long-standing problem of T.fill placed before a pipeline under warp specialization re-running every round; meanwhile the defects of the same period are all at the boundaries — grid barrier under multi-stream concurrency (#3868, switched to a barrier word in the grid workspace of each cooperative launch), signed integer division (#3551, now emitting tl.truncdiv per arith.divsi semantics), and unsigned atomics and unsigned buffers.
  • Metal shifts from adding operators to fixing correctness boundaries: #3907 reports a silent out-of-bounds — when copying an 8x8 metal.simdgroup matrix to an 8x1 output, the compiler emits a full simdgroup_store with row stride 1, overwriting the seven elements after the output (Apple M4, tvm_ffi, compilation cache disabled, detected with spare storage as a sentinel). The fix #3912 adds no runtime check; instead, before emitting each SIMD-group store it requires the arithmetic analyzer to prove that the full 8x8 footprint falls within both the destination buffer and the requested region, and raises a readable ValueError at lowering time if it cannot.
  • Structural limitations of Ascend PTO: #3901 reports duplicate physical segment errors when multiple explicit Cube/Vector regions are declared in the same kernel, with no fix PR yet; #3909 extends the host-mapped buffer contract established by #3802 on the CUDA side to Ascend (14 files +529), whereas previously Ascend kernels uniformly rejected CPU tensor arguments.
  • Three new CUDA-side issues, each representative (11-12): #3988 reports that fp16 T.gemm with M=1 and odd K still issues an illegal 2-byte transfer through pipelined cp.async, reproducible on both 0.1.15 and main, while the regression form originally fixed by #2365 passes; #3987 reports that tl.LayoutInference and tl.LowerTileOp grow exponentially with reused subexpressions in T.Parallel (the corresponding fix #3997 is already queued; the same regression went from 34.89 seconds, over the 10-second compile limit, to passing); #3996 reports that T.Pipelined with explicit order/stage and copies routed through fragments raises “Fragment buffer access with non-zero index [1]”, though that index does not appear in the user program.
  • TileFoundry’s pricing bias repeatedly pushed back by the operator side (11-10): #318 uses elementwise clamp for placement pricing on H200, pointing out that once the CTA grid exceeds one wave, the footprint of the split input is multiplied by the number of waves, and noting that the same behavior was reported in four closed issues, all marked not planned, and still reproduces in the current build; #319 lays out a 4096×7168×16384 persistent SM90 NT GEMM and gives five findings at once, the hardest being that check --help says bf16 has 8 explicit mantissa bits with a rounding bound of 2^-9, whereas bf16 actually has 7 explicit mantissa bits and unit roundoff 2^-8, so the rtol derived from it is only half of what it should be. The analyzer’s 26% pricing bias (962.1 vs. 1213.6 GFLOP) will not slow down an individual operator, but it will cause automatic schedule selection to systematically choose wrong on boundary grids.

VI. Trend Observations

First, the cleanup period after a major overhaul lasts longer than the overhaul itself, and the cost lands on “programs that were previously legal are no longer legal.” After #3512 replaced PTO’s vectorization and type system together, four consecutive windows were spent patching its regression surface: execution backend default switch (11-11), integer atomics (11-11, 11-12), explicit SIMD parallel loops and scalar cast facts (11-12), and VMI descriptors (11-12). What these four categories share is not “new features computing wrong results” but “old code no longer compiles or produces different results.” For compiler projects, the debugging cost of such regressions far exceeds that of new-feature bugs—the error location often lands on a scalar or address unrelated to the fault, and the stack trace gives no hint of who installed the wrong assumption first.

Second, Ascend’s bottleneck has shifted from “can it compile” to “do declarations match implementations,” and review bandwidth is the hard ceiling on this front. After the 14 static defects in October, two waves of audits this week extended the gap from the parameter layer down to the T.simd instruction layer, with almost all findings taking the form of “declared as supported but the implementation takes another path” or “should have been rejected but silently passes”; meanwhile, more than ten corresponding fix PRs are under review simultaneously. The tilelang-ascend default branch had zero merges across four windows while the review queue kept thickening, and all 3060 daily tests pass—tests cover legal paths, while the ability to reject illegal paths depends on audits. The real acceptance criterion should shift from “pass rate” to “generative alignment between declarations and implementations”: generate from HCU_MCPU_SET the list of architectures the backend must cover, and generate from the intrinsic registry the dtype/bit-width support matrix.

Third, the backend matrix has shifted from “one player advancing alone” to four fronts starting simultaneously, with investment depth falling into four categories. This period’s eight main-repo commits are all Ascend, but in the same window ROCm opened seven commits as a series, Hygon produced ten commits on one branch in a day, Sunrise is running its release pipeline (ci/sunrise-0.1.15-1.2.1-r6 created and deleted in 80 seconds), and Hexagon pushed TileLang onto mobile DSP in the form of a personal fork. The four forms (upstream built-in backend, vendor adaptation repo, standalone distribution, third-party fork) correspond to four depths of investment, and this differentiation itself is a usable indicator of each vendor’s degree of dependence: vendor repos track versions, distributions track mainline, forks track their own hardware.

Fourth, TileFoundry’s pricing gap keeps being pushed back by the operator side, which is more dangerous than any single operator slowing down. #318 states outright that the same behavior was reported in four closed issues, all marked not planned, and still reproduces in the current build; #319 reports five at once with a 962.1 vs. 1213.6 GFLOP deviation (26%); the bf16 mantissa convention differs by a full bit between check --help and the hardware facts. The analyzer is the prerequisite for TileLang’s “price first, then choose schedule” approach, and a 26% pricing error will cause automatic selection to systematically choose wrong on boundary grids. Such gaps won’t slow down any single operator, but they will make automation quietly make wrong decisions.

Fifth, “engineering for agents” is beginning to appear at scale. The mlir-ascend harness branch gained +7632 lines in a day, consisting of a skill library, simulation trace workflows, and a Roofline calculator, serving “people or agents who write operators” rather than the compiler itself; in the same week, the Hexagon fork’s README states outright that the backend and models were rewritten by AI agents under maintainer guidance, with 75 PRs in four days accounting for over 80% of the current code. The two point in the same direction: the abstraction layer of DSLs like TileLang happens to land at the granularity where “agents can write it correctly,” so the ecosystem is starting to build toolchains for agents rather than just documentation for humans. This one is worth tracking weekly.

Sixth, the four RISC-V sources have been silent for six consecutive windows, forming a stark contrast with overall activity, but the way this week quantified the gap changed. The TVM route, MLIR route, community index page, and Sophgo TPU—all four upstreams remain at their original references; beyond the four sources, the CPU line, after switching conventions on 11-11, concluded that 553/553 fall within 1.03x of Triton, yet the same batch of test cases the day before was “41 cases faster than reference, SG2044 median 0.0580x.” Neither set of numbers is fabricated; the difference lies in whether the measured object is “author-written programs” or “shared compiler artifacts.” The real observation point is: whether this “same compiler, two frontends” approach can feed back into upstream, and whether the RVV/IME path will be made to work first by projects outside the four sources. The stagnation is not because no one is working on it, but because the official four sources have yet to form a loop of “automatically discover gaps, automatically verify, automatically queue.”
