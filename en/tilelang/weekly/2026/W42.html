TileLang Weekly Report (2026-10-12 ~ 2026-10-16)

2026-10-16 Kubuds

Reporting period: October 12, 2026 (Monday) to October 16, 2026 (Friday), 5 working days in total, 5 daily-report source sets Source material: 5 issues of this publication’s daily TileLang updates (10-12, 10-13, 10-14, 10-15, 10-16); additionally supplemented by a 168-hour window check across 29 repositories in the tile-ai organization, item-by-item recomputation of test results from six nightly-pipeline snapshots, and review of each repository’s release metadata (see appendix)

I. Weekly Highlights

  • Main repo ROCm line closes out four consecutive days, DeepSeek new-architecture kernels become the third closing line (10-13 ~ 10-14): On 10-13, merged the 64-lane single-wave implementation of DeepSeek NSA forward/single-token decoding (#3152, +111/-2) and the LDS/VGPR budget-adaptive tiling for flash-decoding (#3149, +82/-5); in the early hours of 10-14, merged the mHC (manifold-constrained hyper-connections) pre/post-processing kernels (#3156, 2 files +83/-6, with the HIP side reworked to divide work across a full 64-lane wavefront and converting FP32 mixed weights to BF16 for MFMA) and the safe-gated KDA decoding example (#3249, +360, including a GLM-5.3-Flash TP8 specialized configuration); 10-14 also saw a 64-lane segment-width fix for cumsum/cummax (#2326). All four point to “adapting to device reality”: gfx942 wavefront size, MFMA input types, and LDS/VGPR budgets settled item by item, with ROCm support moving from “working” to “in sync with new-architecture releases.”

  • Ascend PTO elevated from “standalone target” to “first-class execution path,” NSA dual migration and rollback discipline in the same week (10-12 ~ 10-15): On 10-15, merged execution routing #3316—the combination of target="ascend" and execution_backend="pto", after execution-aware target normalization, connects directly to CodeGenTileLangPTO, while the auto path retains AscendC + TVM-FFI; the preceding example target selection #3474 (merged 10-14, removing the hardcoded target="ascend", with CI running once each for the ascend / pto dual targets) and the seven PRs under review in this window—the tvm_ffi backend, VMI vectorization, SS buffer, and partial L0 copy pitch—form the family.   • TileOPs 52 merges in one week: Op base-class refactor finalized, MoE dual operators settled, SM89 becomes the second platform (10-12 ~ 10-16): The Op base-class refactor merged on 10-11 (#2520, 363 files, +3362/-5227, self-described as “pre-release” closure) unifies operators with and without compilation boundaries through _run_call, merges select_kernel_key/select_implementation into key_for, and derives compilation boundaries from the manifest, with the docs site following up the next day with the “Op Base Class Guide”; on 10-13 the MoE dual operators were settled the same day—masked FP8 grouped GEMM (#2521, 20 files +1788/-37, aligned with deep_gemm masked semantics) and DeepSeek grouped top-k (#2535, 15 files +1193/-69, aligned with vLLM grouped_topk and fixing the 32/132 SM scheduling issue at T=512); SM89 has been closing out in batches since 10-12 (GQA prefill/decode, GDN / DeltaNet prefill, GLA / DeltaNet backward, KDA prefill, full Norm spectrum), putting RTX 40-series and L40 / 6000 Ada-class workstations on par with Hopper on the operator-library side.

Compiler, Execution Paths, and Language Layer

  • PTO execution routing (#3316, merged 10-15): adds an execution-aware target normalization hook (attached at BackendContext creation); the Ascend-specific normalizer specializes native Ascend targets into PTO target variants before parsing while preserving attributes such as arch; device codegen switches to PTO_CODEGEN and target.build.tilelang_pto_without_compile; the docs give the equivalent configuration of TILELANG_DEFAULT_TARGET=ascend plus TILELANG_EXECUTION_BACKEND=pto. Tests cover context resolution, target attribute preservation, cache dispatch, and environment-variable selection.
  • PTO DeepGEMM codegen (#3330, merged 10-14): tracks tl.ascend_set_mmad_direction across control flow and encodes the effective direction into MAD instructions, rejecting MADs reachable under conflicting directions; supports incremental loads after SIMD, UB address to PTODSL pointer conversion for mixed AIC/AIV kernels, dynamic L0C→UB dimensions and strides, and int16 signed packed MX scale. Self-reported 14 of 15 DeepGEMM PTO cases pass; test_bf16_m_grouped_padding remains blocked by the PTOAS VPTO backend’s inability to legalize FP32→BF16 conversion.
  • Independent AIV execution (#3485, merged 10-14): extends Ascend AutoSchedule so AIV0 and AIV1 can perform different work under sid dependencies (alternating epilogues, dequant/epilogue split, disjoint input partitions, in-loop role switching); AssignCore is moved ahead of latency estimation and scheduling, and independent identities are established for AIV-local UB buffers and scalar state.
  • Shared C-family codegen base class (#3289, merged 10-14): CodeGenTileLangCBase unifies CUDA, HIP, CPU C, Ascend C++, Metal, and C host code generation; fixes T.import_source, T.Kernel(prelude=...), and pragma_import_c swallowing the next generated line when the source text lacks a trailing newline or ends with a backslash. Validation: 83 focused regressions pass, 405 codegen and launch suite tests pass.
  • CPU grid parallelism (#3109, merged 10-14): adds MaterializeCPUParallelGrid to turn annotated CPU grid loops into OpenMP parallel loops, with loop collapse, thread-count configuration, a minimum trip-count threshold, and allocation sinking, plus compile flags for Linux / macOS / Windows — the CPU backend gains grid-level parallelism for the first time.
  • Host IR line under review all week: #3473 unifying the CUDA and CuTeDSL execution paths and #3481 for direct Host IR JIT with native caching have seen no merge since opening on 10-10, and remain the main repo’s largest in-review direction.
  • Seven PTO-family PRs (under review since 10-15): tvm_ffi execution backend (#3516), T.Parallel to PTO VMI vectorization (#3512), SS buffer (#3514), explicit pitch for partial L0 copies (#3511), NZ buffer UB→L1 partial copy (#3530), PTO Ramp value vector emission by type (#3535), and a fix for vector local access inside SIMT VF (#3523). Of these, SS buffer merged on the morning of 10-16 (#3514, confirmed via supplementary verification after the daily-report cutoff).

  • Rollback and redo: On 10-14, three documentation fact-check PRs (round semantics #1612, bitwise_rshift #1676, bitwise_xor #1681) were rolled back as a batch (#1888 through #1890). The reason is explained by the redo version #1893: when the daily full suite runs low-priority cases, the exception regex for expected-failure cases does not match—the actual throw is an InternalError from AscendVectorInstructionSelection rather than the asserted Compilation Failed, and since these cases are marked low_priority, CI does not execute them at the PR stage, so they are caught by the daily full run as a backstop. The redo removes all expected-failure assertions (unsupported dtypes are now covered by the documentation dtype support table), retaining the docstring rewrite and on-device tests.
  • Under review and queue: dav-3510 gemm_v0 silent numerical error (#1900, opened 10-15) is the most worth tracking this week—no exceptions, no NaN/Inf, no zero values, all multiset checks pass, and it only manifests as a precision failure on the remote; two separable commits (--npu-arch taken from the platform, gemm_v0 staging restriction) await verification of dependency order. IV. Ecosystem and Adopters

  • Governance: The Op base class refactor #2520 (merged 10-11, 363 files, +3362/-5227) was completed in ten commits following a “behavior first, mechanical rename later” approach: operators with and without compilation boundaries uniformly go through _run_call; on failure, rollback is decided by whether the target was selected by this call; if a sub-operator does not belong to any delegate_for stage, the composite call fails as a whole; _validate_dtypes is removed; key_for merges the two selection entry points; and the compilation boundary is now derived from the manifest. The documentation site merged the “Op Base Class Guide” (#69) the next day, keeping code and docs in lockstep.

  • SM89 becomes the second platform: Three merges on 10-12 (D256 dense GQA decode #2529, dense GQA prefill #2528, GDN / DeltaNet prefill #2527, with 21 “failure not dispatchable” cases turned passing), four on 10-13 (GLA backward #2546: shared memory 114688→81920 bytes; DeltaNet backward #2547: 147968→98816; KDA fused prefill #2548: 256 threads allocating 182528→101120; compact row-wise grouped GEMM #2549), plus GQA split log-sum-exp switched to FP32 accumulation (#2550, where split mixing under bf16 large scores deviates by at most 0.23, and autotune now times by the actually launched program) and D=256 decode extended to SM80/SM90 (#2563).

  • Sparse decode threaded through TIR (#223, merged 10-12, 84 files, +4424/-1543): Taking over the DSA decode legacy issues from #218 — fixing lost loop work, excessive lookup billing, and staged update errors, landing indexed async gather and Bitcast and Where sinking; allocation constraints changed to a single accessor (returning Storage), captured updates written directly into tiles (16B shared memory), and carried values for parameter initialization given independent storage with a preceding copy; 16 FixtureCase guards each include CLI invocation and output checks.

VI. Trend Observations

  • “Static preparation” during the release quiet period is now in place across four directions simultaneously: TileOPs’ Op base class refactor claims to be closed out ahead of release; the nightly foundation’s six snapshots show zero-failure growth; TileFoundry’s examples extend from decode to prefill with full-length outperformance; and multi-backend alignment at v0.1.15 is complete — the main repo has gone 16 days without a tag since 09-30, but the static preparation for the next version is largely in place this week. Whether to release depends on the review gate, not on content.
  • Multi-backend is moving from “version alignment” to “semantic convergence”: Hygon completed the full v0.1.15 upgrade and separately established a v0.1.12 maintenance line; MetaX caught up with the mirror and shifted to dev merge; Ascend is focusing on documentation fact-checking, cache semantics, and real-hardware validation (#1900); Moore Threads is the only gap. The gap among the four has shifted from “whether a backend exists” to “whether semantics are consistent.”
  • ROCm has become a second line synchronized with new model releases: for four consecutive days, DeepSeek NSA, mHC, KDA, and GLM-5.3-related kernels landed, with technical debt paid down item by item against device budgets (64-lane wavefront, MFMA input types, LDS/VGPR limits); after merging with the multi-generation co-fix for SM121 / SM89, the backend topology has shifted from “NVIDIA-first” to “multi-device concurrent maintenance.”
  • TileOPs’ performance engineering has shifted from “targeted work on key operators” to “daily leaderboard runs across all operators”: 8 to 11 entries per day, each with external comparisons (torch-compile / cuBLASLt / quack / FlashInfer / FLA), and residual shortfalls are written openly into PRs (lm-head’s two lines at 0.909x; GLA backward explicitly makes no speedup claim) — quantifying and documenting “shortfalls” demonstrates engineering discipline better than isolated speedups.
  • Ascend’s governance stance is shifting from “all passing” to “precise assertions”: three documentation checks were rolled back wholesale and then trimmed and redone because of an exception-regex mismatch in low-priority cases, exposing the two-tier CI structure in which low_priority is not run at the PR stage and a full daily run serves as the fallback; such rollbacks are not regressions but a signal of treating “expected failures” as technical debt to be cleared.
  • TileFoundry is shifting from a compiler tool to a deliverable product form: the standalone scaffold project, instance slots and lowering contracts, and the cross-ridge prefill example argumentation — in the same window the refactor landed, third-party vendors listed it alongside a defect ledger — the typical trajectory of productization is “after foundation refactoring, interface contracts converge and defects become public.” The next issue needs to track whether these emitter / runtime defects are absorbed.
  • Watch items for the next issue: whether main repo v0.1.16 is released (16 days of silence); whether the dual-track SM120 block-scaled MMA (#3495 / #3099) can be merged; the cumsum warp specialization fix (#3536) and the seven-entry PTO family’s progress; Ascend #1900’s two commits and A5 real-hardware validation scheduling; whether Hygon’s distributed IPC produces its first merged multi-card PR; TileOPs has seen release-pipeline cleanup-type commits (weekend) — whether these lead to the first official version; whether TileFoundry’s external defect list is absorbed.
