Today’s Focus

The heaviest action in this window is subtraction. The mainline rolls back in full the precise thread counting merged three weeks ago (#3291) (#3733), with a plainly stated rationale: that change moved expensive counting queries ahead of full-block barrier checks, so even when all threads will reach the barrier the proof still has to run; the current TVM solving budget gets exhausted and returns partial counts, causing otherwise legal remap and sequence helper kernels to fail compilation outright with “Cannot prove a thread rectangle.” The rollback proceeds on both ThreadSync implementations, deletes the tests introduced by #3291, and adds a reduction case where the loop is empty for most threads yet all 256 threads still reach the barrier; correctness improvements such as the quotient guard, precise participating-thread bounds, and non-rectangular thread sets are also withdrawn, with newly opened #3732 kept as a tracking issue for re-optimization after the migration. This is an explicitly labeled migration concession: TileLang is preparing the TIRX migration to shed its current TVM fork dependency, and the accompanying TVM fork optimization proposal has been closed.

The second thread is Ascend shoring up its foundations. #1948 fixes a host-side fixed cost independent of operator size: the Cython wrapper unconditionally constructs a TVM Analyzer on every call, measured at about 0.28 ms per call on 910B3, yet it is only needed when shapes are symbolic expressions; after switching to lazy construction, vec add single-block drops from 442–467 µs to 105.1 µs, 32-block drops from 441–493 µs to 108.0 µs, and kpool compression drops from 447–450 µs to 111.3 µs, while the bare ctypes call serving as a lower bound stays unchanged at about 12 µs. Meanwhile, the RFC in #1971 lays out a replacement path for the sync implementation: port the mainline sync core plus a standalone Z3 proof service, wire it into the existing compilation pipeline via a legacy TIR adaptation layer, preserve TVM, scheduling, memory planning, AscendC/PTO codegen, and the runtime ABI, then switch the default implementation and delete the old algorithm once acceptance passes—two landing points of the same effort as #1975’s migration of the entire Ascend repo to the mainline multi-backend architecture.

The third thread is in the operator libraries. TileOPs merged 13 PRs on 11-01 alone, almost all performance patches, each with an H200 measured table and a manifest regression gate. Among them, #2808 reduces GQA dense forward program selection to a single rule, cutting selection regret relative to the fastest candidate program from 1.818 to 1.017 (2 to 128 query positions, 586 calls), and fixes a real mainline bug: the score scale vanishes in FP32 after multiplying by log2(e), turning outputs into NaN or wrong values.

I. Core Project Progress

1.1 Mainline: Precise thread counting rollback in ThreadSync to make way for the TIRX migration (#3733)

Merged on 11-01 14:50. The reverted #3291 moved precise thread counting ahead of the full-block barrier check and added rectangle certification, at the cost of running CountSatisfyingValues even when all threads reach the barrier; once the TVM-side solving budget is exhausted it returns a partial count, and the remap and sequence helper kernels then fail with “[ThreadSync] Cannot prove a thread rectangle”. The regression reproduces on mainline cc903dcb9 with the unchanged TVM pin 4211874e9e, and the new test case reduces it to “loop empty for most threads, yet all 256 threads still reach the barrier”. The rollback covers both the shared and Ascend implementations, restoring the full-block fast path and the old partial-count behavior; the description explicitly states this is a temporary mitigation during the TIRX migration, the optimization proposal tile-ai/tvm#89 on the TVM fork side has been closed, and follow-up optimization moves to #3732.

Source: https://github.com/tile-ai/tilelang/pull/3733

1.2 Mainline: CUDA cross-warp full reduction merged into a single shared memory exchange, cutting 256 threads from 6 barriers to 2 (#3715)

Merged on 10-30 20:26. The old implementation in the CUDA reduction header reduce.h recursed from threads/2 down to scale, performing a full shared memory write-read exchange plus two barriers at every step with offset not less than 32: a 256-thread block’s three steps (128, 64, 32) totaled 3 shared memory round trips and 6 barriers, and a 512-thread block had 4 and 8. The change compresses all cross-warp steps into a single exchange (one st.shared per element, 2 barriers total): first do the scale < 32 segment within the warp, then have up to cross_radix lanes in each intra-warp group cooperate to fold, with bounded register pressure. Both the scalar and batched paths were changed.

Source: https://github.com/tile-ai/tilelang/pull/3715

1.3 Mainline: First milestone of T.Parallel vectorization on the PTO backend lands, elementwise operators run VMI instructions (#3512)

Merged on 10-30 01:29. The goal is to let users write scalar-parallel elementwise T.Parallel inside T.SimdVF(lanes=L), have the compiler vectorize it into PTO VMI instructions, and execute on Ascend 950 via PTOAS. The division of labor is clearly specified: the TileLang side handles logical lane layout inference, the vectorization pass pipeline, VMI instruction generation, and Fragment logical mapping; the PTOAS side handles physical register partitioning, mask materialization, Fragment buffer and vector register allocation, and mem_bar insertion. The roadmap has five milestones; this PR is the M1 core framework (elementwise computation, covering both cases of whether extent is divisible by lanes), with M2 control flow, M3 reduce, M4 UB capacity planning and register allocation, and M5 non-contiguous access and wider PACK data types following in order.

Source: https://github.com/tile-ai/tilelang/pull/3512

1.4 Mainline: Ascend DeepGEMM scale buffer switches to write-count multi-buffering, allowing data loads to be hoisted before conditional loads (#3629)

Merged on 10-30 05:48. DeepGEMM reuses scale factors across multiple K blocks; this PR adds an explicit write-count multi-buffering mode so the scale buffer version advances on actual writes: within each owner loop iteration it advances only once at the first write task actually executed, subsequent writes share that version, iterations with no write retain the old value, and multiple disjoint owners and shared clocks are supported. This allows data loads to be scheduled before the conditional scale load; it also flattens DeepGEMM’s K loop, fetching data before scale on both L1 and L0, and adds test cases for guard updates, nested updates, retained reads, flag and buffer reuse, and FP4’s K-major and MN-major with tail blocks and ring wraparound. This mode requires an explicit version count and assumes at most one update per owner iteration.

Source: https://github.com/tile-ai/tilelang/pull/3629

II. Multi-Backend Adaptation (Ascend / Hygon / Moore Threads / MetaX)

2.1 Ascend: Cython wrapper lazily constructs TVM Analyzer, 910B3 single call drops from ~450 µs to ~106 µs (#1948)

Merged on 10-30 07:44. CythonKernelWrapper.forward() previously constructed a TVM Analyzer() unconditionally on every call, a fixed host overhead of ~0.28 ms on 910B3, even though the object is only needed when the result or workspace shape is a symbolic expression; static-shape kernels never use it yet paid the same cost. The fix defers construction into the tir.PrimExpr branch and reuses it on demand. Measured: vec add single-block 442–467 µs down to 105.1 µs, 32-block 441–493 µs down to 108.0 µs, kpool compression 447–450 µs down to 111.3 µs, raw ctypes call ~12.5 µs down to ~12 µs. 2.2 Ascend: RFC proposes replacing the sync implementation with the mainline core plus a standalone Z3 proof service (#1971)

This RFC does not presuppose a speedup conclusion; it only fixes the comparison baseline: the Ascend repo sits on TileLang 43b0b69 and TVM c2921fd with the old tvm.tir as its IR foundation; mainline sits on TileLang 1c0f402 and TVM 4211874e9e with tvm.tirx and tvm.s_tir as its IR foundation, and its object and registration systems have also moved to the new FFI and reflection facilities. Migration therefore cannot be reduced to copying a single InsertSync file. The proposed route is to port the mainline sync core and the standalone Z3 proof service, wire them into the existing compilation pipeline through an old-TIR adaptation layer, and preserve the existing TVM, scheduling, memory planning, AscendC/PTO codegen and runtime ABI; only after acceptance on supported scope, correctness, performance and installation should the default implementation be switched and the old sync algorithm deleted. Companion PR is #1965.

Source: https://github.com/tile-ai/tilelang-ascend/issues/1971

2.4 Ascend under review: GLM-5.3 kpool fp8_mqa_logits example, dual-kernel with AIV/Cube division of labor (#1966)

An Ascend version modeled on the GLM-5.3 fp8_mqa_logits example under the main repo’s kpool directory. The operator semantics are the pooled history scoring of the GLM-5.3-Flash sparse attention indexer: for each query row, within the valid pool range, read E4M3 keys from 64-pool pages via the page table (uint8-carried bytes plus fp32 scale), dequantize, compute MQA scores for 32 indexer heads, multiply by per-pool scale, and reduce via a ReLU gate and per-head weighting to one FP32 logit per pool, outputting negative infinity for out-of-range or invalid pages. The implementation uses two kernels: a mask kernel generates per-lane 0 or negative-infinity masks per 64-pool tile to replace host pre-fill, and the main kernel assigns one block per row per page, with two AIVs each handling a 32-pool half-page while Cube reads the full page for a single 64×32×128 GEMM. Head count 32, dimension 128, page size 64.

3.6 TileOPs bug in progress: four Norm operators lose precision on rows far from zero, overflow to NaN around 1e36 (#2812)

Opened 11-01. LayerNorm, AdaLayerNorm (including -Zero), GroupNorm, and BatchNorm currently sum the raw row directly in fp32 to compute mean and variance (BatchNorm uses E[x²] minus the squared mean), the same class of defect fixed for FusedAddLayerNorm in #2773 and being fixed for the InstanceNorm training kernel in #2811. Symptoms: an fp32 row of constant 10000.1 normalizes to roughly ±weight instead of bias, and a row of 10000 plus random values fails to match the float64 reference within fp32 tolerance; rows near 1e36 overflow the sum, producing all-NaN output in both fp32 and bf16. Affected paths span fragment, shared-memory walk, one-row-per-warp, tiled, and streaming implementations.

Source: https://github.com/tile-ai/TileOPs/issues/2812

IV. Community, Tutorials, and Events

4.1 RISC-V research chain takes shape: three repos convert Numba CUDA Python to TileLang, then lower restricted PrimFuncs to single-hart RVV C (10-31)

Community researcher zishu0131-png assembled three repos on the same day, 10-31: tilelang-riscv serves as the main entry point, describing the research goals, the two-stage compilation chain, and the version combinations; numba2tilelang handles static parsing of Numba CUDA Python and converts it to TileLang source; tilelang2rvv converts supported real tvm.tirx.PrimFunc into RVV intrinsic C, which is then compiled by Clang into an RV64GCV ELF and run on QEMU virt with a single hart. The author states the boundaries clearly: this is not an officially registered TileLang backend, nor a general GPU model simulator; threadIdx-dependent addressing, cross-hart synchronization, and unsupported IR are all rejected, blocks execute sequentially, and shared and fragment are mapped to single-hart local arrays. The research environment is TileLang 0.1.15, Clang 23.1.3, and QEMU 11.1.0, with no guarantee of compatibility with other versions, and it is explicitly noted that upstream thread-level artifacts cannot automatically be treated as acceptable input for this backend.

Source: https://github.com/zishu0131-png/tilelang-riscv

V. Trend Observations

The most noteworthy judgment in this window comes from upstream itself: it would rather roll back correctness improvements than keep ThreadSync’s complexity off the critical path. The rollback note spells out the cost—three classes of improvements (quotient guards, precise participating-thread bounds, and non-rectangular thread sets) are withdrawn together, keeping only the old conservative path, with #3732 deferred until after the TIRX migration is complete. A compiler project willing to publicly state “our prover budget is insufficient, so we are reverting to the conservative implementation” says more about the real constraints of the current stage than any number of added features: the TIRX migration is the top priority on the mainline, and all other optimizations must give way to it.

Echoing this are two Ascend-side documents on “converging toward the mainline”: the RFC in #1971 would replace the synchronization algorithm with the mainline core plus a standalone Z3 proof service—research first, replacement later, with an old TIR adaptation layer kept in between; #1975 directly migrates the entire Ascend repo to the mainline multi-backend architecture. Both paths incur migration costs, so near-term visible work skews toward foundational items: #1948 cuts the fixed host overhead per call from about 450 microseconds to about 106 microseconds, four documentation fact-checks, and CI cleanup of internal cache references are all this kind of work.

TileOPs, meanwhile, has shifted its rhythm from “releasing” to “tuning.” Of 15 merges in 72 hours, 13 landed on the same day, nearly every one accompanied by an H200 measured-results table and a “no manifest regression” statement, and it has begun using metrics such as selection regret to describe the quality of scheduling rules (#2808 from 1.818 to 1.017). This means the competitive focus for operator libraries has shifted from “does this operator exist” to “is the right program selected for every shape”—which is precisely where the long-term value of DSLs like TileLang relative to hand-written kernels lies.

Two new forks have appeared on the ecosystem side. One is hardware dialects: Hygon treats gfx948 as gfx946-compatible, while Ascend continues to fill in PTO documentation and symbolic shapes. The other is a language outlet: the RISC-V research chain lowers restricted PrimFuncs to single-hart RVV C—low star count, and the author explicitly states it is not an official backend, but it uses TileLang’s IR as a portable asset, the same kind of signal as the repo-level branch adaptations for Ascend and Hygon. With multiple forks existing simultaneously, whether the upstream TIRX migration can deliver a stable IR boundary will determine whether these downstream investments accumulate or get reworked.
