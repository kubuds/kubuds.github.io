Today’s Focus: FlashQLA v0.1.4 Released, Dual-GPU CP Extended to Consumer Blackwell

QwenLM/FlashQLA released v0.1.4 on 11-25 23:16; the repo now has 770 stars. This is the most complete version delivery from an adopter in this window.

The release notes list three main threads. The first is a precision path for cross-partition correction, supporting FP32 and three-pass TF32x3, selected at runtime by a wave-aware heuristic. Inter-GPU h0 and dht folding now reads the already-aggregated (h, M) buffer directly via slot mapping, no longer materializing unpacking and re-indexing.

The second is dual-GPU CP on SM120 and SM121, covering both inter-GPU and intra-GPU combinations in forward and backward. The implementation adds aggregate_card_state and aggregate_m.

The third is the ZigZag inter-GPU CP layout. Rank r handles block r and block 2·cp−1−r of each document, aligned with the attention layer’s split positions, and requires no changes to the TileLang kernel.

The remaining changes are engineering-oriented. The KKT solve is changed to 8×8 diagonal-block substitution, merging FP16 MMA with FP32 recurrence, independently rewritten following FlashInfer’s block inversion. flash_qla.warmup() can precompile all static parameter combinations into the JIT cache. The CP interface build_cp_context enables inter-GPU and intra-GPU by default and accepts zigzag=.

One fix connects to the SM120 thread from the previous daily. block_DV=64 and a __threadfence_block prevent nvcc from hoisting g_exp_shared past the barrier. The backward barrier now commits dV writes before letting K reuse dqkv_shared.

Benchmarks cover three hardware tiers. Single-GPU: H200, GB200, and RTX 5090. Dual-GPU CP: H200×8, GB200×4, and RTX 5090×2. The release also includes technical reports on Auto-CP and Dual-CP.

Source: https://github.com/QwenLM/FlashQLA/releases/tag/v0.1.4.

Today’s Focus: Nightly Wheels Re-Tagged 0.1.16, Version-String Rework Brings Two Regressions

tilelang-nightly produced two wheels in the window. The 11-25 13:18 build carries the 0.1.16 stamp with commit 3684ae6a, and the 22:30 build has commit fa93ba14. The previous day was still v0.1.15+d20261124.

This indicates the version number merged on 11-24 has entered the packaging chain. The latest GitHub tag is still v0.1.15, the latest Releases entry is still v0.1.15 from 9-30, and tilelang on PyPI is also 0.1.15. So the accurate statement is that the build side has reached 0.1.16, but the release is not yet complete.

The version-string format was changed as well. The old format was 0.1.15+cuda.d20260125.githash; the new format is 0.1.16+githash, with the dYYYYMMDD date segment no longer present.

The rework brought two regressions, both reported around 11-25 17:26, on source build a3a4f9ce.

#4513 reports that build_date() silently returns None for dev versions. The function’s regex is [+.]d(\d{8}), which depends on the date segment. Parsing of both the old and new formats is itself correct; the problem is that actual artifacts no longer carry the date segment.

#4514 reports that do_bench always crashes on Ascend NPU with aclrtDeviceL2CacheFlush failed: 207000. After the profiler’s NPU path changed the cache buffer to an empty placeholder with cache_numel=0, _flush_cache unconditionally calls aclrtDeviceL2CacheFlush(None). The call fails on dav-3510 with CANN 9.2.1. Both issues already have 4 comments each.

Source: https://github.com/tile-ai/tilelang/issues/4513.

Today’s Focus: All Three Main-Repo Commits in the Caching Subsystem; Cache Key Now Includes Toolchain Version

The main repo had only three commits in the window, two of them directly touching caching. This contrasts sharply with the previous days’ batch of ROCm fixes and Ascend defect reports.

#4511 incorporates the current CUDA and Ascend toolchain versions into the kernel cache key, touching 20 files. It adds tilelang/contrib/bisheng.py, and pto_toolchain.py is slimmed down accordingly. BackendModule gains a toolchain_stamp callback that can be called with zero arguments. CUDA compiler selection is folded into _cuda_compiler_module.

The motivation is the cache invalidation boundary. Previously, after switching compilers or CANN versions, old binaries could still hit the cache. Tests add three cases: Ascend binary cache, PTO cache, and JIT diagnostics.

#3756 handles shared-cache permissions. Cache entries are staged first and then published by renaming the whole directory, so they inherit the creating process’s umask. On a shared cache root with SGID and group write, a process with umask 077 emits 0700 and 0600 entries that other users cannot read.

The fix legalizes staged entries before publishing. When the cache root has SGID, directories become 0o2755 and files become 0o644 with the executable bit preserved. Roots without SGID, and filesystems that do not support the bit, are left as-is. The commit adds 148 lines of permission regression tests and fixes shared-cache directory initialization and multi-root lookup.

There is also a companion open PR. #4512, titled keying the executable cache by toolchain identity, shares the same theme as #4511.

Source: https://github.com/tile-ai/tilelang/pull/4511.

I. Core Project Progress

1.1 Cache keys now include CUDA and Ascend toolchain versions, cutting off cross-toolchain reuse

#4511 was merged by LeiWang1999 at 23:09 and is the only functional change in this issue. The proposal lays out four steps: first key CUDA and Ascend JIT kernels by active toolchain, then restrict toolchain awareness to CUDA, then bring the Ascend toolchain in as well, and finally unify the toolchain stamp across backends.

Structurally, a new BackendModule.toolchain_stamp hook is added. On the CUDA side, tilelang/cuda/backend.py supplies the version string; on the Ascend side, tilelang/ascend/backend.py does. Both now go through the adapter layer under contrib.

Six test files were changed. Besides three cache test cases, the host-mapped output validation test was also adjusted; that test explicitly disables the kernel cache.

Source: https://github.com/tile-ai/tilelang/pull/4511.

1.2 Shared cache publishes group-readable entries by SGID, umask 077 no longer produces private directories

#3756 was merged by KellyFrog at 16:18, changing kernel_cache.py and one new test file. The proposal attributes the problem to the publishing method: staging followed by renaming the whole directory, with permissions coming from umask, inconsistent with the SGID intent of the shared root.

The decision condition only checks whether the cache root carries SGID. If it does, directories are 0o2755 and files 0o644, with the executable bit preserved. If not, nothing changes, covering filesystems such as Windows that do not support this bit.

Tests cover both the shared-root and private-root cases. Non-POSIX systems and filesystems that do not support POSIX permissions are skipped.

Source: https://github.com/tile-ai/tilelang/pull/3756.

1.3 CUDA attention sample tests parallelized, CI per-job time compressed

#4485 changes the block causal attention sample cases to run in parallel and adds a budget for Z3. Three files changed, including one line in ci.yml.

The proposal at one point withdrew a Z3 budget override for DeepSeek TopK, then restored the z3 limit. The previous day’s #4463 and #4489 also revolved around solver time for the same set of TopK cases; this change is the wrap-up of test duration for this issue.

Source: https://github.com/tile-ai/tilelang/pull/4485.

1.4 Nightly wheels relabeled 0.1.16, build_date() returns None for dev versions

Both nightly wheels are based on 0.1.16. The 22:30 one corresponds to commit fa93ba14, the merge point of #4485 in this issue. The 13:18 one corresponds to 3684ae6a, the first change after the window start.

This is a silent regression in a public API. It does not affect building or running, but it will break diagnostic and reproduction scripts that depend on the build date.

Source: https://github.com/tile-ai/tilelang/issues/4513.

II. Multi-Backend Adaptation (Ascend / Hygon / Moore Threads / MetaX)

2.1 Ascend sub-repo adds dtype pre-validation to bitwise_xor, crash becomes ValueError

#1986 merged into the ascendc_pto branch at 15:24, changing 6 files. The proposal links to #1722, with the goal of rejecting unsupported inputs before they reach the compiler.

The frontend checks the three operands dst, src0, src1. It allows int8, uint8, int16, uint16, int32, uint32, and rejects floating-point and 64-bit integers. The check is done on the scalar element type, compatible with vectorized dtypes.

The lowering stage performs a second check, covering paths that construct the intrinsic directly, bypassing the public API. int32 and uint32 are only allowed on PTO A5 with tl.ascend_memory_planning disabled.

The device-side compute implementation and workspace allocation are unchanged. On the test side, the XOR tmp contract now uses a legal int16 buffer, preserving the original workspace slot and layout assertions.

Source: https://github.com/tile-ai/tilelang-ascend/pull/1986.

2.2 gemm_v0 adds fp32 test matrix, backfilling the catlass precision gap

#2032 merged at 11:16, changing 8 files. The proposal states this fills the gap exposed by #1396 and #1921: the gemm_v0 test matrix was previously hardcoded to fp16, so the old catlass fp32 copy-wrong-value bug was never caught.

The new cases pin the fixed behavior for each historically meaningful branch shape. It follows the same pattern as 2.1: first turn the gap into a reproducible matrix, then talk about performance.

Source: https://github.com/tile-ai/tilelang-ascend/pull/2032.

III. Ecosystem and Adopters (TileOPs Operator Library / FlashQLA / TileFoundry)

3.1 Nine TileOPs Merges, Two Model-Level Performance Wins for DeepSeek-V4-Flash

TileOPs had 9 merges in the window, two of which directly change how the model side makes calls.

#3171 changes the DeepSeek-V4-Flash indexer ReLU to non-in-place. ReLUFwdOp(inplace=True) writes the result into a new buffer and then copies it back to the input, whereas this model only reads the returned scores. This copy-back involves one extra read and write of 537 MB of scores on the ratio-4 layers at 4096-token prefill.

#3170 makes the four types of index tensors computed only once per Step, handled by the first layer that reads them. The four types are the closed-entry count and zero-first-item read by top-k, the full key index for all-closed layers, and the ring slot for decode steps. The window type is int32, and index layers no longer recompute layer by layer.

Source: https://github.com/tile-ai/TileOPs/pull/3171.

3.2 Decode Steps Switched to CUDA Graph Replay, Yesterday’s Work Item Landed Same Day

#3168 merged at 15:00, changing 10 files. CausalLM.forward now serves both models: the model provides the index metadata and forwarding body for this call.

cuda_graph is enabled by default. Decode steps replay the _run graph on the CUDA device, with the token buffer and Step.moved_to rewritten in place. The first step of each phase runs eagerly first, then is captured on the model’s own stream.

This is precisely the implementation of the new work item #3155 opened in the previous issue. The companion #3175, under review, requires every decode operator of both models to pass a CUDA Graph capture eligibility test.

Source: https://github.com/tile-ai/TileOPs/pull/3168.

3.3 Five foundry Merges: INT8 Tile Extended to Width 192, One Idle Fix Each for Quantization and Sampling

The five merges are prefixed with foundry and are all operator-level tuning.

#3162 adds three tiers—80, 112, and 192—to the tile table for INT8 64-row GEMM. Width 192 uses T.wgmma_gemm rather than the dense WGMMA helper. 48, 144, 176, 208, 224, and 240 remain excluded, as each was measured to be slower every time it was selected.

#3163 makes the last block of FP8 in-place grouped quantization load only the rows that actually exist. When launched as a single block—for example, the KV of one row with seven groups in DeepSeek-V4-Flash—redundant loads cost the kernel an extra 64 to 96 nanoseconds.

#3164 widens 16-bit concat inputs to float32 via shared memory, using 16-byte reads and full-row writes. #3166 folds the split top-p row binning into each thread within the block. #3167 makes 16-bit isinf process two lanes at once, with a block size of 1024 threads.

#3169 separately fixes the head-count computation for zero tokens in the RoPE reference implementation.

Source: https://github.com/tile-ai/TileOPs/pull/3162.

3.4 TileFoundry Merges Example Exporting a Qwen3 Training Step to ASTRA-sim

#366 merged at 12:07, changing 42 files. The example exports one Qwen3 training step to ASTRA-sim in five configurations.

New content includes a calibration script and three JSON files: assumed.json, compute.json, and simulator.json. There is also to_chakra.py for conversion and sim/run.sh for running the simulation. On the documentation side, two specs—HIR and pass—were updated.

This merge was still under review in the previous issue and landed this issue. It extends TileFoundry’s validation surface from single operators to the training-step level.

Source: https://github.com/tile-ai/TileFoundry/pull/366.

V. Trend Observations

  • Caching is turning from an implementation detail into a first-class citizen. Three merges in one day revolve around it: cache keys recognizing the toolchain, shared caches recognizing permissions, and the one under review keying the executable cache by toolchain identity. Multi-user builds and coexisting toolchains are the driving factors.

  • The 0.1.16 release path has been paved on the build side. The nightly wheel was first relabeled 0.1.16, while the tag and PyPI remain at 0.1.15. After the version string dropped the backend label, two pieces of code depending on the old format reported regressions the same day, showing the compatibility surface of the format change is wider than expected.

  • The composition of Ascend defects is changing. The previous day it was ten cases of “inputs that should not be accepted being accepted”; this issue it is T.fmod missing lowering, SimtVF scoping misjudgment, and PTODSL multi-kernel symbol conflicts. The problems have sunk from interface contracts to the compilation and linking layer, and the cost per fix is rising.

  • TileOPs optimizations are beginning to land on how the model makes calls, not just inside kernels. Switching ReLU to non-in-place, computing index tensors once per step, and routing decode steps entirely through CUDA graph all reduce scheduling and copies rather than raising per-core compute.

  • The pace of adopters is accelerating. FlashQLA completed v0.1.4’s code, benchmarks, documentation, and technical report within a day, and TileFoundry pushed its validation surface to the training-step level. TileLang’s downstream users no longer just write kernels; they are starting to write system-level examples.

  • The RISC-V side has seen zero change for three consecutive windows. Both the TVM route and the MLIR route remain where they were, and the index page has no new PRs.
