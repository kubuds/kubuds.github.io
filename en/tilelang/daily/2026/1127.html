Today’s Focus: Moore Threads MP31 submits 14 PRs at once, filling in low-precision and collective communication together

tile-ai/tilelang-musa created 14 PRs between 02:18 and 04:16 in the early hours of 11-27, numbered #14 through #27. All of these submissions are based on the v0.1.15+musa.1 base branch and declare a stacking order; #25 requires merging after #19.

Low precision is the main thread. #19 legalizes MP31’s fragment-A SQMMA GEMM and adds a 188 KiB shared-memory guardrail. #25 adds MP31-native W4A16 SQMMA, covering both fp16/bf16 × int4 → fp32 and the reverse combination. #25 also rewrites sqmma.h to work around the issue in MUSA 5.2.0 headers where s4 is mistakenly written as fp4. #20 enables FP8 TME descriptors for warp-specialized GEMM.

Memory access and synchronization each take a batch. #27 enables packed UINT8 TME loads for 4-bit weights. #18 adds tme_flush() on exit for TME kernels. #16 changes MP31’s swizzle indexing to element units to preserve vectorization. #24 fixes warp-specialized TMA barriers; cross-squad partial synchronization is reduced to per-squad 128-thread barriers. #26 reduces consumer-side multi-warp AllReduce to MP31 partial barriers.

The language surface is also expanding. #23 adds block-parallel T.sort, T.argsort, and T.topk, implemented with a bitonic sort template, supporting six dtypes other than int4 and arbitrary non-power-of-2 lengths. #15 supports T.rng_init and T.rng_rand via murand. #21 adds T.reduce_prod, a two-barrier multi-warp one-dimensional scan, and a mem-bound TIR pass. #22 wires tl.enable_fast_math to mcc -ffast-math.

Validation is on MTT S5000 (mp_31). The 25 sorting test cases in #23 all pass, covering MoE top-2/8, NSA top-64/512, and non-power-of-2 lengths. #25 has additional low-precision and accumulation test cases.

Source: https://github.com/tile-ai/tilelang-musa/pull/25.

Today’s Focus: All three main-repo commits are Ascend; host-mapped buffer parameters enter mainline

tile-ai/tilelang main branch has only 3 commits in this window, all Ascend-tagged. This differs from the previous cadence of cache subsystem and ROCm fixes; Ascend has become a stable input source for the mainline.

#3909 merged at 09:44, adding explicit host-mapped buffer parameters for Ascend. Previously, ASCEND kernels would reject even already-mapped CPU tensors, forcing callers to disable tensor validation. The new path follows the contract from #3802, using the same T.annotate_host_mapped_buffers(...) interface. Both Cython and TVM-FFI sides verify the mapping with aclrtHostGetDevicePointer, then pass the device-visible address. Checks for dtype, shape, strides, and execution device are all retained.

#4486 merged at 11:32, fixing #4429. The trigger scenario is FlashMLA prefill with nk=topk=960: each query processes 15 KV tiles, two query slots alternate, and the first slot is reused after 30 iterations. The old implementation built one edge per iteration distance for each pair of same-pipeline sites; a single pair of sites could contribute 31 distances from 0 to 30. The new implementation stores disjoint closed intervals keyed by “source, destination, strictness”; composing two intervals still yields an interval, so newly covered distances can be propagated in batches.

#4390 merged at 12:25, switching PTOAS in Ascend CI to install from PyPI. The CANN 9.2 image is unchanged; the image’s built-in script first uninstalls its PTOAS component, then installs the latest compatible wheel with --upgrade --no-deps --only-binary=:all:. After installation it verifies Python 3.12, x86_64, package and CLI version consistency, and confirms that PTOAS, PTODSL, MLIR Python modules, and native extensions can all load from the virtual environment. If installation or verification fails, PTO backend examples and unit tests are skipped, and the step result is written to the job summary.

Source: https://github.com/tile-ai/tilelang/pull/3909.

Today’s Focus: TileFoundry opens Apple ANE target, TIR emits HWX container directly

tile-ai/TileFoundry adds under-review PR #369, whose title states the Apple ANE codegen pipeline. The path has three stages: TIR → task descriptor → HWX container. This builds on the ANE target already introduced in #361 and is the first on-device neural engine target in the TileLang ecosystem.

The implementation has two layers. The ISA layer provides register bitfield maps covering six block classes: Common, L2, PE, NE, TileDMA, and Kernel. Task descriptors use RUN/MASK packet encoding, with six primitive classes: load, store, compute-PE, compute-NE, conv, and activation. There is also a declarative formula and cross-field validation library that validates descriptors at build time in a fail-closed manner.

The codegen layer handles emitter dispatch, per-pass serialization, and HWX container output. The container is in Mach-O format, described as reverse-engineered and implemented from scratch, with word elimination applied to the default image. Out-of-range tile_height and tile_width are rejected directly at compile time.

On correctness, the proposal claims bit-level consistency with Apple’s own compiler output within the covered operator range.

The same repo merged #368 the same day, fixing issues left over from the #162 rename. Codegen projected tilefoundry::local for barriers still typed as ShardLayout, but that function had been renamed to local_tensor, causing compilation to break at the nvcc stage. The fix only fetches words for “whole-grid broadcast” barriers and rejects sharded barriers outright. The rationale is that sharded barriers assign different words to each warp, while CopyAsyncBulk arrives only once per CTA from the first warp’s thread, so the remaining warps would wait on a word for a phase that never completes.

Source: https://github.com/tile-ai/TileFoundry/pull/369.

I. Core Project Progress

1.1 Host-mapped buffer parameters land in mainline; Ascend no longer requires disabling tensor validation

#3909 modifies both the Cython and TVM-FFI binding paths. Both use aclrtHostGetDevicePointer to obtain the device-side address and carry the original dtype, shape, and strides into the kernel. The C++ binding signature is unchanged; instead, runtime queries are selected based on the existing device type. Cython retains the default CUDA resolver, with only Ascend providing an optional resolver. The CUDA side still goes through use_torch_stream(), and the shared device-selection logic is untouched.

Only Ascend signatures with “all-host parameters” explicitly install the original NPU stream. Tests cover three scenarios: all-host parameters, automatically allocated NPU outputs, and NPU Graph capture.

1.2 InsertSync propagates dependency distances by interval; 31 iteration distances no longer build edges one by one

#4486 changes only the InsertSync pass. Previously, for each same-pipeline site pair, the implementation inserted one edge per iteration distance and repeatedly composed them when building the dependency closure. The new implementation stores reachable distances as closed intervals, and composing two intervals yields another interval, so only distances not yet covered are propagated. Gaps and strictness are both explicitly preserved, and distances 0 and 1 are still handled according to the existing epoch-domain projection rules.

The FIFO work queue now uses std::set, keyed by source, destination, the two distance bounds, and strictness, to skip duplicate pending intervals.

1.3 Ascend CI installs PTOAS from PyPI; CANN 9.2 image stays unchanged

The motivation for #4390 is that PTOAS and CANN release on different cadences. Previously PTOAS was pinned with the image, so upgrades required workflow changes. Now any new version in the index is picked up automatically, with no need to modify the workflow or update existing dependencies.

The same change also adjusts the initialization of ordinary SIMD masks to accommodate the new PTOAS version.

1.4 16 PRs under review: PTO vectorization and positive-shape assumptions advance; T.reshape silent NaN awaits fix

There are 16 updates under review in the main repo. On the PTO side, #4523 vectorizes T.Parallel to PTO, covering conditional branches and lane-uniform serial loops. #4524 switches to vdiv in ptoas, and #4522 deduplicates helper symbols in multi-kernel PTO compilation.

On the performance side, #4526 removes redundant guards under the assumption that buffer shapes are positive. There are three fixes. #4519 adds the missing default_target_is_cutedsl to examples/conftest.py. #4520 fixes @T.prim_func decoration failing under from __future__ import annotations. #4521 routes bfloat16 scalar min/max through the float overload.

The most significant issue opened that day is #4525. T.reshape applied to T.StridedTensor drops strides and reads inter-row padding, causing the output to silently become NaN without an error. There is no fix PR for this yet.

Source: https://github.com/tile-ai/tilelang/issues/4525.

II. Multi-Backend Adaptation (Ascend / Hygon / Moore Threads / MetaX)

2.1 Moore Threads lands 14 PRs in a batch; MP31 adds W4A16 SQMMA and a 188 KiB shared-memory guardrail

The 14 PRs span five categories of work: low-precision MMA legalization, TME memory access and barriers, language-surface operators, fast-math switches, and verification cases. #19 is the foundation; several other PRs declare a dependency on it or share its stack.

The key point of #19 is legalization of the fragment-A layout SQMMA GEMM, while capping shared memory at 188 KiB and rejecting anything over the limit. #25 builds on it to add native W4A16 and provides int8/uint8 → fp32 accumulation legalization: the hardware side accumulates with int32 SQMMA, then losslessly converts to fp32. #25 also generalizes Hilbert2D thread-index reordering to non-square tiles, via the interface T.use_swizzle(..., order="hilbert").

#21 adds WarpFirstAllReduce, T.reduce_prod, and a two-barrier multi-warp one-dimensional scan, plus a TIR pass modeled on shared-memory bandwidth. #24 fixes the warp-dedicated TMA barrier and lowers cross-squad partial synchronization to a 128-thread barrier per squad. #26 likewise lowers the consumer-side multi-warp AllReduce to an MP31 partial barrier.

#14 adds packed integer vector construction for int8/uint8/int16/int32 broadcasts. #17 restores __launch_bounds__, annotate_min_blocks_per_sm, and -O3. #18 adds tme_flush() on exit for TME kernels, and #20 enables FP8 TME descriptors and constrains automatic TME to 16-byte in-frame alignment.

On the language surface, the sort family in #23 is the most complete item in this batch. The implementation imposes a strict total order with “smaller original index wins,” matching torch.sort(..., stable=True) and torch.topk. It supports float32, float64, float16, bfloat16, int32, and int64, one- and two-dimensional, ascending and descending, at arbitrary lengths. Buffers cover three classes: shared, fragment, and global. When sorting a shared buffer in place at power-of-two lengths, it uses no extra shared memory.

III. Ecosystem and Adopters (TileOPs Operator Library / TileFoundry / FlashQLA)

3.1 TileOPs: Ten Commits, Three 0.1.15 Performance Recoveries Land on the Same Day

The tile-ai/TileOPs main branch saw 10 commits in the window, all performance or test changes, no new operators. All three lines are recovering performance losses introduced by TileLang 0.1.15.

The first is dropout. #3181 reported that dropout on 16-bit rows has been 13% to 16% slower since 0.1.15. The cause is that after T.rng_rand_float() was vectorized by T.Parallel, one vector shares a single sample. 0.1.15 also narrowed 16-bit vectors from 8 elements to 4. #3187 changes this so each element independently draws a 32-bit Philox4x32-10 value from the counter: the high 16 bits use the thread’s first sample, and the low 16 bits are only drawn additionally when the high bits equal the threshold. This change also eliminates mask correlation within the vector, and the values go from correlated to independent.

The second is W4A8 prefill. #3172 adds T.sync_warp() for the consumer warp at the start of each tile iteration. Previously ptxas could not prove the warp had converged at the K loop, so it kept the ring buffer’s stage index and the WGMMA descriptor in vector registers and copied them to uniform registers before each WGMMA. As a result, R2UR rose from 20 to 52, and four shapes were 10% to 13% slower.

The third is RoPE. #3173 changes staged RoPE to launch on a (tokens, sides) grid, writing back an entire row with one 1D bulk write per block. Previously an 8 KiB row was split into 16 tensor-map writes, and each table lookup carried bounds protection. Measured gptj-6b prefill dropped from 15.440 microseconds to 15.264 microseconds.

3.2 DeepSeek-V4-Flash Prefill Drops RoPE Row Copies and Window Ring Copies

#3186 changes two places. The compression layer’s RoPE table now pre-stores the cosine and sine for each position according to the compression ratio, so the compressor prefill no longer passes RoPECosSinFwdOp a strided slice that is copied on every call. When prefill writes the last window_size rows of KV, it previously went through four steps—arange, modulo, gather, scatter—and now uses two slice copies.

On the test side, a case with a 256-token prompt and two full windows is added, whose ring write starts at slot 0.

3.3 Qwen3.8-27B’s 6-Head Query Groups Move onto the Warp-Specialized GQA Kernel

#3174 addresses the group-width limitation. GQAPagedFwdWSKernel previously packed an entire query group of one KV head into a 128-row tile, with each head occupying 128 // group rows. This only supported 1, 2, 4, 8, 16 heads or more than 16 heads; other combinations fell back to gqa_paged_varlen_kernel. Qwen3.8-27B’s 6-head groups fall exactly into the fallback branch: it has 24 query heads against 4 KV heads, with head_dim 256.

The new implementation puts only one head group per tile. _tile_heads takes the largest power of two that divides the query group and lets each head fill 8 rows of swizzle atoms—2 for Qwen. A KV head’s group is split into multiple head groups by slices, each becoming a work item, and the producer loads the K, V, and rotated key columns of the KV head at group_id // slices.

On the review side, a systematic series of six commits appeared the same day: #3189 to #3194, all on the theme of “in-place reads under strided views.” They cover six places: BMM’s a and out, CausalConv1d’s x, RMSNormGated’s x and z, and PagedKVCacheWrite’s k and v. Separately, #3195 builds Qwen3.8-27B’s positions only once per step instead of rebuilding them for each attention layer.

3.4 MXFP4 Grouped GEMM Locates Experts by Per-CTA Tile Prefix

#3177 addresses task-location overhead. The shared task_walk advances expert by expert, with one dependent global read per step and two on contiguous segments. Each CTA therefore pays for all experts in the layout, including empty ones.

The new table_task_walk has each CTA sum the row-tile counts of all experts into shared memory once. It then uses warp shuffle to scan the sums of a range of experts, and when the expert count exceeds the block’s thread count, has one warp scan the segment totals again. Finally each warp advances by at most one warp width of experts using a single ballot.

3.5 Sampling, Embedding, KDA, and CUDA Graph Eligibility Tests Merge the Same Day

#3184 handles the case where a top-p row’s probability is 1, switching to passing the whole row through and taking the keep key only once. #3188 lets wide embedding calls complete in a single wave with two-warp CTAs when the pass rate allows, instead of the conservative one-warp-per-CTA split.

#3179 fixes value-major KDA decoding diverging when the state approaches the FP32 limit, keeping it finite. #3175 adds item-by-item CUDA Graph capture eligibility tests for each model’s decode-step operators. #3176 fixes labels getting out of sync after title edits, switching to reading GITHUB_EVENT_PATH.

3.6 TileFoundry Fixes Codegen for Barrier Broadcasts, Sharded Barriers Now Rejected Outright

#368, besides fixing leftovers from the local_tensor rename, also handles two coordinate branches. They likewise emit functions that no longer exist, but are currently unreachable: since #186, type inference rejects coordinates on pointer views, and all passes build TensorView only from pointers.

V. Trend Observations

First, the nature of this batch of 14 Moore Threads PRs is not patches but a one-shot push of the MP31 backend to “low-precision usable, collective communication usable, language surface complete.” There are three pieces of evidence. Both W4A16 and int8 accumulation are legalized at the hardware instruction level. AllReduce already has three implementations, including warp-first, partial-barrier, and cross-squad splitting. The sort family directly aligns with PyTorch’s stability semantics. This combination typically appears just before a backend is ready to take on an inference operator library.

Second, Ascend has turned the main repo into a routine input channel. All 3 main-repo PRs in the window carry the Ascend label, and they are of different natures. One is an API capability (host-mapped buffers), one is compile-time complexity (InsertSync distance intervalization), and one is CI supply chain (PTOAS switched to installing from PyPI). Meanwhile, the 11 new Ascend defects are concentrated in RNG and DeepGEMM, indicating that coverage has reached the numerical-detail level.

Third, TileOPs is absorbing the performance-regression recovery for 0.1.15. All three lines (dropout, W4A8 GEMM, RoPE) stem from code-generation changes in 0.1.15, and each lands with concrete percentages or microsecond figures. This suggests that compiler-side changes need operator-level regression baselines to catch them, otherwise the loss is only discovered a version later.

Fourth, targets are expanding to edge devices. If the Apple ANE codegen PR is merged, TileLang’s target surface will expand from GPUs and domestic NPUs to the neural engines of phones and tablets. The implementation path is to lower TIR to task descriptors and then package them into vendor containers. This differs from the “generate vendor C++ and recompile” route taken by Ascend and Moore Threads, and is another way of landing.

Fifth, the four RISC-V sources show zero change for a second consecutive window. Both the TVM route and the MLIR route remain at the previous period’s citations, and the SOPHGO TPU branch count is unchanged. This direction remains at a low level and does not yet constitute a trend.
