Today’s Highlight: TileOPs Lands Fifty Merges in Three Days, Two Full Models Assembled from Operators

Over the three days from 11-20 to 11-22, TileOPs merged 50 PRs, the heaviest volume in the organization for that period. Two of them assembled entire models from public operators.

DeepSeek-V4-Flash was merged via #3072, authored by bigSheep123, entering main on 11-22 20:29. models/deepseek_v4/ lays out 43 layers onto the designated GPU, running batch-1 prefill and greedy decoding, with the MTP layer not built. On the config side, every setting the model does not compute is rejected; the loader rejects checkpoints it cannot fully read.

Acceptance is checked against the torch kernels in DeepSeek’s official inference/model.py. The test takes a three-layer model, using Flash width and one layer per attention type. It runs once with a long prompt and once with a three-token prompt.

Per-layer outputs and the logits across prefill and decoding must fall within the reference’s own bf16 rounding noise. The indexer’s selection must match the official indexer, and the two-card split must match a single card.

The text decoder for Qwen3.8-27B was merged via #3112, entering main on 11-22 13:20. models/qwen3_8/ provides from_pretrained, chunked prefill and decoding, reset, and greedy generate. Batch size is 1. The model’s model_type on Hugging Face is qwen3_5. Qwen3.5-27B and Qwen3.6-27B share the same config values and tensor names, so all three checkpoints load.

Gated DeltaNet layers go through CausalConv1dFwdOp, CausalConv1dUpdateFwdOp, and GDNFwdOp. Normalization goes through RMSNormGatedFwdOp. Full-attention layers go through FusedQKNormRoPEFwdOp (interleaved MRoPE, 1 + w), PagedKVCacheWriteFwdOp, and GQAPagedFwdOp. A sigmoid output gate is then added.

The loader reads safetensors shards layer by layer, skipping model.visual.* and mtp.*, and directly rejects any other tensor it cannot read.

The shells of the two models were merged. #3119 gives DeepSeek-V4 and Qwen3.8 a shared CausalLM and a shared read_checkpoint, and asserts that loaded tensors are bit-identical. The same PR folds the two sampling kernels into a single index-folding macro, producing byte-identical generated CUDA. Both loaders now raise ValueError instead of a bare KeyError for layers with missing tensors.

This path was decompose first, assemble later. On the morning of 11-20, TileOPs opened 14 DeepSeek-V4 work items at once (#3057 through #3068). They covered FP8 indexer scoring and top-k, packed KV gathering and sparse indexing, and dual packed-cache decoding.

There were also compressor state and packed-cache writes, and a fused QKV RMSNorm. Two trackers separately managed validating TileOPs inside vLLM on H200, and confirming the gap between the SM90 MXFP4 backend and TileOPs. Two days later the full model was merged.

Sources: https://github.com/tile-ai/TileOPs/pull/3072 https://github.com/tile-ai/TileOPs/pull/3112 https://github.com/tile-ai/TileOPs/pull/3119

Today’s Highlight: TileFoundry Adds Apple ANE Target, Fourth Hardware Class with Measured Performance Docs

#361 was merged on 11-22 21:33, authored by zhen8838, opened on 11-20. It adds an Apple Neural Engine target in tilefoundry-apple, modeled on the Metal target (#354): instructions declared in TIR, paired with an HIR, then lowered to TIR. Code generation and runtime are out of scope for this PR.

On the hardware side, two documents are provided: the apple.h14 architecture and the apple.m2_pro.ane device. The topology is one engine, one unit, shared gmem, with engine-owned smem (L2, capacity undisclosed). Performance lists one measured value: fp16 16.71 TFLOP/s, measured with a 3×3 convolution, 256 channels, 384×384.

There are six instructions, all f16. They are T.ane.conv, T.ane.bypass, T.ane.pool, T.ane.unary, T.ane.binary, and T.ane.reduce. Each carries a capability, an execution mesh, hir_matches, and access relations. There are also verify rules, and a torch evaluator that rounds step by step to fp16, ties away from zero. conv handles both Conv2D and MatMul with channels outside, while bypass handles C/H/W transposes, ReLU, and matrix reordering.

One hard constraint is written into the docs: when the feature map’s W is greater than 1, the W stride must be 1, because the engine has no element stride. ConvertHIRToTIR emits each T.ane.* only once per engine region for ANE.

The target interface itself was also changed along the way. The Target base class now declares capabilities(), documents(), and the class attribute hardware, and the core no longer reads concrete target attributes by name. The ane, metal, and amx targets are now frozen dataclasses with a single field, holding the device document’s ID or path. The cuda target implements the two methods, with its constructor unchanged.

With this, TileFoundry’s hardware family expands from three classes to four: CUDA, Metal, AMX, plus ANE. ANE is the first mobile inference engine in this class to arrive with a complete “docs + instructions + verify rules” form.

Sources: https://github.com/tile-ai/TileFoundry/pull/361

Three commits landed in the tilelang main repo window, of which #4422 bumps 3rdparty/tvm to tilelang_main@5fb5cb27. This brings in two upstream fixes.

The first is TVM #95: InitFuncState clears Let binding state in CodegenC. Previously the state persisted across functions, affecting binding resolution in subsequent functions.

The second is the behavior of the ROCm stub. TVM #79 changes the existence check for ROCMDeviceAPI from hsa_init() to hipGetDeviceCount(). The same commit also downgrades hipGetErrorName and hipGetErrorString, and removes the now-unused HSA stubs and the bundled hsa.h. 7 files changed.

II. Multi-Backend Adaptation (Ascend / Hygon / Moore Threads / MetaX)

2.1 MLIR Ascend merges eight dialect operators in one day, unary operators extracted into a shared template

On 11-20 alone, the mlir-dialect branch of tilelang-mlir-ascend merged eight operator PRs. The first four were #232 sort, #233 reshape, #234 arange, and #235 concat. The next four were #236 flip, #237 not, #238 abs, and #239 sqrt.

The first five were submitted by HadiaSaqib. reshape, as a pure view operator, lowers to memref.reinterpret_cast. concat is a variadic destination-style op that concatenates along a static axis. arange and flip each come with lowering and tests on both the TLIR and HIVM sides.

The last three were submitted by Areeshh, who extracted a shared unary infrastructure. The components are the TL_UnaryOp base class, the verifyElementwiseUnary verifier, the ConvertUnary<> conversion template, and the EmitUnary<> emission template. not lowers to hivm.hir.vnot, abs to vabs, and sqrt to vsqrt.

The author states the working method in the commit description: each operator gets its own branch cut from the current tip of mlir-dialect, the shared infrastructure is first copied within each PR, and whichever merges first wins while the rest need a small rebase. This is why this batch of operators could land in a single day, and it also means merge order will cause rework.

The same day, the repo’s main merged a separate RoPE kernel (#263). The silence on main since 11-04 ends here. On the release side, #265 publishes nightly wheels to OBS, and #266 wires Ascend NPU wheel testing into the Dist pipeline.

III. Ecosystem and Adopters (TileOPs operator library / TileFoundry / topa / adopters)

3.1 Thirty-one performance PRs: GQA decode merge 1.21x faster, MXFP4 decode down to nine instructions per eight codes

Of the 50 merged PRs in TileOPs, 31 carry the [Perf] tag, accounting for 60%. They cluster around eight areas: RoPE, indexing, GEMM, MoE, elementwise, pooling, normalization, and attention.

The GQA split-decode merge was changed by #3119: each shard is weighed once, in parallel, then divided by the sum once. Single-request decode is up to 1.21x faster. The same PR changes 16-bit on-chip softmax to take the warp max first and then sum; the fp32 kernel is untouched.

MXFP4 shared decode was changed by #3111: all eight e2m1 codes in a 32-bit word are converted in one pass, one mask feeds two magnitude permutations, and one shift plus two byte permutations places the signs. Per 8 codes, instructions drop from 11 to 9, and the decoded bytes are unchanged.

The same PR quantifies the gap: the difference between prefill rows and FP8 grouped GEMM lies in e2m1 decode. ncu on 32k-up counts 2264 warp instructions per tile step versus 909, of which about 1125 are in the decode warp.

GEMM was changed by #3106. For a wave of float32 NT grids, width 128, with at least two tiles on each axis, the selector switches to coop2 tiles and takes the deepest ring that fits in SMEM. The 128×128 base tile is retired. The root cause: coop2’s two consumer warpgroups overtake the base tile once ring depth matches its five stages, while the main branch caps coop2 at four; and when two tiles tie, the selector previously favored the base tile.

The self-assessment wording is worth noting: several PRs say “below bar” while noting every row is faster than the main branch. The acceptance bar evidently tracks a target multiple, not speedup relative to the main branch.

The remaining areas have one to five PRs each. RoPE, five: wide calls split tokens by SM, each row into shared memory, 64-bit indexing, integer work hoisted, and a dead single-head bounds check removed. Indexing, four: concat rows and vectors, embedding row tiles, int32 ids keeping their dtype. Elementwise, three: GELU, erf, and 16-bit tanh squeezed into a full-occupancy register budget. Attention, three: branchless key-scale sign for the FP8 indexer, DSAPaged’s two-way bf16 key split merged into a CTA pair, and paged GQA’s RoPE preparation via 16-byte vectors. There are also two pooling PRs, two normalization PRs, one KDA PR, and three MoE PRs.

The three in-review PRs all point at the same batch of models. #3099 closes the gap with SGLang for GatedPoolCompress on DeepSeek-V4-Flash decode. #3097 closes the gap with TileKernels for HyperConnection on decode and prefill. #3101 runs DSADense rows on resident CTAs.

Source: https://github.com/tile-ai/TileOPs/pull/3119

3.2 Partial backends no longer fail the whole suite; unserved operators are recorded as unverified

#3121 adds OpNotServedError, inheriting from OpNotAvailableError, with a target attribute. It is raised when the selected target has no kernel builder registered for the operator.

The test report records it as unverified (skipped and listed) in exactly one case: the target named in the exception equals the one pinned by --tileops-target at startup. Defaults set later by the test itself do not count. The same error naming another target still fails, e.g. the fake target in dispatch tests.

Previously, a backend serving only some operators would fail every test for an unregistered operator when the suite ran with --tileops-target, because the operator layer raised only a generic OpNotAvailableError. Backends built up operator by operator therefore could not use the full suite.

3.4 TileFoundry autodiff recomputes per ModuleList element; dot pairs operands by register order

Five more PRs merged in the TileFoundry window.

#362 changes autodiff’s recompute selection. Previously recompute was selected only by definition, and Layer:h applied to every ModuleList element. Peak-memory tuning needs per-layer selection (TorchTitan’s block_overrides), so element_copies is added. Elements with their own selectors are distinguished from copies of their subtrees, and ModuleList loops whose elements are not all identical are split into loops of identical elements. The same PR fixes --saved accounting. Previously a saved view was counted as its own byte size, so dropping one slice of a fused qkv looked like a saving. Now Saved.buffer counts buffers actually kept alive, each counted once.

#364 changes operand pairing for T.dot. It pairs by register index, numbering each unit upward from the smallest physical stride. The CUDA runtime previously paired by CuTe index; the two orders agree only when each local view has at most one mode with length greater than 1, or when modes are ordered by smallest stride. The repro: a row-major (2, 4) block paired with a (2, 4) parameter reads a[l, 1, 0] against b[0, 1]. Now both operands are read through views ordered by stride from smallest upward, swizzle is preserved, load width comes from the reordered view, and either side failing alignment falls back to elementwise reads.

#363 makes the analyzer reject plain global memory that two CTAs can reach without ordering. #365 fixes codegen to write each tensor value in the layout’s physical projection. #360 reads unannotated layouts as Broadcast and moves mesh declarations into the module class.

Source: https://github.com/tile-ai/TileFoundry/pull/362

Fifteen issues named after change descriptions were also filed (in the #48–#65 range), all single-item fixes to the cost model, scheduler, and evaluator. They include pricing register copy streams by resident CTA, counting multi-wave grids once, pricing gather per thread. They also include pricing staged epilogues, finalizing the column slice of the WGMMA accumulator, and pairing two CTAs’ global writes only when their element ranges overlap.

These issues share author and title style with the PRs, continuing the existing pattern of “agent rounds open topics automatically, human review closes them out.” The 11-18 report already documented this working method; this period is just higher volume.

The relation to 3.1 is worth pointing out: TileOPs’ 31 performance merges and topa’s pricing items share a source. Performance proposals come out of agent rounds, and their gains are then discounted by topa’s cost model; the two steps together form the criterion for whether an agent-produced PR can enter main.

IV. Community, Tutorials, and Events

4.1 Formal verification research lists TileLang kernels as a comparison target

Automated collection surfaced 6 candidates within the window. Five are metadata entries from the repositories themselves—the crawler treating repository pages as news. The sixth is a MarkTechPost 11-21 report on TensorLean, which has no direct relationship to TileLang, but its comparison table includes TileLang.

TensorLean is a formal verification framework from CertiK and Columbia University that works directly on compiled PTX, with specifications written in Lean and proofs discharged by the Lean kernel plus Z3 and cvc5. Its scale is 149 compiled GPU kernel instances, 83 of which were proven to satisfy their specifications. The remaining 66 exposed 38 correctness defects across six libraries, including 2 in DeepGEMM and 23 in FlashAttention.

The connection to TileLang is in its comparison table. Volta from MSR India and Stanford lists TileLang kernels as one of the verified targets, with scope covering tutorial-level reductions, SGEMM, FA-style, and TileLang. In other words, kernel verification research is beginning to treat code generated by TileLang as part of its target set.

V. Trend Observations

  • The unit of acceptance has risen from operators to models. Both model-assembly efforts use official reference implementations as the baseline: the DeepSeek side uses the torch kernels in inference/model.py, and the Qwen side uses the torch path in HF transformers. The criterion is layer-by-layer consistency within bf16 rounding noise, which is closer to evidence that “the production stack can be replaced” than operator-level alignment.
  • The center of gravity of defects has shifted from “fails to compile” to “compiles but computes wrong”: at least six of the 11 new CUDA defects are silent errors, while on the Ascend side it is compile success followed by device crashes at runtime or entire tiles being dropped. Such defects can be caught by test suites but not by compile-time assertions.
  • Backend expansion follows a “docs first” approach: the ANE target first provides hardware architecture documentation, measured compute throughput, and verify rules for six instructions, with code generation and runtime explicitly stated as out of scope. Establish the verifiable boundary first, then discuss implementation.
  • The half-finished backend now has a test channel: #3121 records unserved operators as unverified rather than failed. For the operator-by-operator Ascend and Hygon routes, this changes the test suite from “only take it on if everything is green” to “score by coverage.”
  • The agent pipeline has entered the pricing stage: all fifteen topa items are filling in the corners of the cost model (persistent CTA, multi-wave grids, gather rows, partial waves). Performance proposals produced by rounds still have to go through a discounting pass, and this step determines whether agent-produced PRs can enter the mainline.
  • The center of gravity of the two Ascend lines has swapped: last week it was MLIR laying down dialects and the main repo doing release engineering; this period MLIR did eight operators in a day, while the main repo had eleven new defects plus seven fixes, landing on correctness. The two lines have different rhythms, but both must pass the same test suite.
