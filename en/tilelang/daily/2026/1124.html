Today’s Highlight: Main repo JIT adds process-level parallel compilation, bypassing GIL limits on the thread pool

#3903 landed on main at 11-23 11:57, touching 6 files, +552 / -100 lines.

tilelang.par_compile() and kernel.par_compile() gain an optional parameter executor="process". The stated motivation: thread-based parallelism is constrained by the GIL on Python-heavy compilation workloads.

In process mode, the parent process first normalizes the target, execution backend, pass configuration, and cache root. Configurations already hit in memory or disk cache no longer spawn workers. Misses are deduplicated by key before dispatch.

Each worker uses KernelCache.compile_to_disk() to write results into the disk cache and returns the published cache_path. Worker exception types and tracebacks are preserved across IPC.

The parent process loads directly via KernelCache.load_published_entry(), with no fallback to serial compilation. On error, queued futures are cancelled immediately.

Backends that do not support disk caching are rejected before spawning workers, e.g. TorchKernelCache (supports_disk_cache = False). This avoids mutating global cache state.

Thread mode remains the default. Process mode requires caching to be enabled and requires the script to guard its entry point with if __name__ == "__main__":.

The proposal records validation on Ascend with 64 processes, covering 128 SwiGLU and MoE configurations. Regression tests live in testing/python/jit/test_tilelang_jit_parcompile.py. Cases include process compilation and deduplication under a custom TILELANG_CACHE_DIR.

Source: https://github.com/tile-ai/tilelang/pull/3903

I. Core Project Progress

1.1 Nightly wheels now published via Dist job, dual-channel through GitHub Releases and Huawei Cloud OBS

#4411 landed on main at 11-23 21:30, touching 2 files, adding 414 lines and removing 11. The proposal explains the background: the old tile-ai/tilelang-nightly pipeline has been retired, and OBS previously had no mainland China download path connected.

The approach is to reuse wheels already built by the Dist job across platforms. Once test-wheels-gpu passes, each platform’s wheels go directly into publishing. Builds triggered by schedule and workflow_dispatch get a date and commit suffix, controlled by TILELANG_BUILD_WHEEL_WITH_DATE=ON. The PyPI release version format is unchanged.

The two publishing channels are independent of each other. publish-github-nightly publishes wheels to GitHub Releases of tile-ai/tilelang-nightly. It also updates the index with SHA-256 at https://tile-ai.github.io/whl/nightly. When NIGHTLY_GITHUB_TOKEN is not configured, this channel is skipped with a warning.

publish-obs uploads wheels and a percent-encoded TileLang/index.html to obs://ascend-triton-open/TileLang/. It then verifies readability over anonymous HTTPS, falling back to -acl=public-read on failure. The index is written to https://tile-ai.github.io/whl/nightly-cn.

Source: https://github.com/tile-ai/tilelang/pull/4411

1.2 Layout and fragment objects own their placeholder vars; input dimension cap of 16 removed

#4416 landed on main at 11-23 21:07, touching 23 files, adding 607 lines and removing 583.

Previously, three layout types relied on process-level static tirx::Var singletons. The three types are tl.Layout, tl.Fragment, and tl.PartialFragment. The singletons are InputPlaceholder(0..15) and ReplicationPlaceholder().

This gave rise to three problems. FFI serialization required hand-written reflection accessors. Input dimensions were hard-capped at 16. Callers outside src/layout/ were implicitly coupled through the shared global Vars.

The fix aligns with TVM’s tirx::IndexMap. LayoutNode holds forward_vars_, and FragmentNode holds replicate_var_. Both are registered with SEqHashDef() before forward_index and forward_thread.

As a result, the two JSON graph interfaces can serialize directly. StructuralEqual and StructuralHash gain alpha equivalence. Constructors uniformly use MakeLayoutVars(ndim) and MakeReplicateVar() to generate canonical vars.

Source: https://github.com/tile-ai/tilelang/pull/4416

1.4 TVM submodule fixes two Z3 false proofs; main repo bump under review

Two PRs merged into the TVM submodule tilelang_main branch within the window, both from the same author.

#97 fixes two reliability defects. First, VisitShiftOp performs solver->add on a shared solver without push(), so any shift expression permanently constrains the shift amount b. The consequence is that in an outer scope where b < 0 or b >= 64, subsequent predicates may all be judged provable. Second, DivNode and ModNode use truncation toward zero, whereas Z3’s native / and % on Int have Euclidean semantics. Thus CanProve(truncmod(a, 4) >= 0) falsely succeeds even when a can be negative. The fix encodes symmetrically with floordiv and floormod, branching on a >= 0.

#96 separately fixes constant signed right shift, switching to integer arithmetic. The follow-up on the main repo side, #4482, is still under review.

Source: https://github.com/tile-ai/tvm/pull/97

II. Multi-Backend Adaptation (Ascend / Hygon / Moore Threads / MetaX)

2.1 PTO Generator Adds Loop-Carried Scalars, Five DeepGEMM Cases Restored to Compilation

#4418 landed on main on 11-23 at 10:17, touching 1 file, adding 23 lines and deleting 11.

The problem lay in the PTODSL (PTOAS 0.65) bundled with CANN 9.2.0. Five DeepGEMM scale-tail and group-padding cases failed to compile, all reaching the same loop in the grouped scale transform. MLIR rejected the generated scf.while, reporting operand #0 does not dominate this use.

The kernel initializes group_start to 0, then updates it inside if lo > 0. The first iteration needs the value selected by the branch. PTODSL’s liveness analysis missed this dependency and used the value inside the branch directly as the loop input. When lo == 0, that value is undefined.

The fix has the PTO code generator collect loop-carried locals before emitting the while header. For ordinary scalars already in scope and assigned within the loop body, it emits one bare-name read each. The generated PTODSL therefore gains three extra reads at the loop entry: group_start, lo, and num_ranges.

Source: https://github.com/tile-ai/tilelang/pull/4418

3.3 FlashQLA Fixes Shared Memory Being Read Early by the Compiler on sm120

QwenLM/FlashQLA #55 merged on 11-23 18:37, changing 1 file with 5 lines added.

Root cause verified via PTX. TileLang 0.1.12’s tl::mbarrier_wait lives in tl_templates/cuda/barrier.h. The inline assembly there has no "memory" clobber.

In blackwell_sm120/fused_fwd.py, the S warpgroup (tx < 128) never writes static shared memory. It only reads g_exp_shared[block_S - 1], a compile-time constant offset. When specialized to use_initial_state=False, nvcc or cicc hoists the ld.shared.f32 out of the for i_s loop. What it reads is uninitialized shared memory.

The consequence is growing state error after block 0. If the uninitialized shared memory contains a NaN bit pattern, it produces NaN directly.

The fix leaves torch.empty(...) and T.clear(h_fragment) untouched. It then inserts an intra-block fence call after the barrier wait. The insertion point is after T.barrier_wait(bar_1, i_s % 2). The call is T.call_extern("void", "__threadfence_block"), added in both warpgroups. In PTX this appears as membar.cta.

Validation environment: RTX 5090, CUDA 12.8, PyTorch 2.8.0+cu128, TileLang 0.1.12.

Source: https://github.com/QwenLM/FlashQLA/pull/55

V. Trend Observations

  • The cost of version upgrades is being quantified down to the line. After 0.1.15 shipped, TileOPs opened a “recover 25 lines” item, and within two days at least four merges returned to 0.1.12 timings. The rest are being worked down line by line via the nightly dashboard. Performance regressions are no longer described by feel but queued by line number.

  • Ascend engineering effort is shifting from operators to the release chain. MLIR Ascend merged seven dialect operators in one day while wiring nightly wheels into archiving and indexing. The main repo connects Dist wheels to GitHub Releases and Huawei Cloud OBS, and plans to add Ascend NPU wheel tests.

  • The type distribution of newly reported defects is stable. Of today’s 9 main-repo issues, 6 are documentation-implementation mismatches and 3 are compilation failures. The documentation ones cluster around Ascend target names and PTO parameter names, indicating these two renames were not synced to the docs and export manifests.

  • Parallel compilation is moving from threads to processes, reflecting that single-machine multicore is already GIL-bound in autotune scenarios. Process mode requires disk caching and entry-point protection, essentially managing build artifacts as cache objects rather than treating the compiler as a function call.

  • On the RISC-V side, today’s activity is only at the community index layer. The index page lists kubuds’s TVM-route fork, but neither of the two RISC-V backend lines has code commits. The TVM and MLIR implementations continue to advance separately.
