I. Core Project Progress

1.1 Main Repo: Two ROCm PRs — DeepSeek mHC Pre/Post Kernels and safe-gated KDA Decode Example (10-13 ~ 10-14)

Date: 2026-10-13, 2026-10-14　Source: DeepSeek mHC (#3156) / KDA Decode Example (#3249)

  • DeepSeek mHC Pre/Post Kernels (#3156, 2 files, +83/-6, merged early 10-14): mHC preprocessing on CUDA partitions work along 32-thread boundaries within a 96-thread block and uses TF32 GEMM inputs; on CDNA this splits the native 64-lane wavefront, and TF32 is not an MFMA input type. The HIP path now runs the split roles on full target-size wavefronts and converts FP32 mixed weights to BF16 in shared memory for MFMA computation; the CUDA side keeps the original 96-thread / TF32 layout unchanged, with added gfx942 pre/post kernel correctness coverage (32-token preprocessing, 8-token postprocessing, and other cases).
  • safe-gated KDA Decode (#3249, +360/-0): Adds a packed decode kernel — consumes post-convolution packed QKV and raw gating inputs (a, b, A_log, dt_bias), an FP32 state pool, and per-request state indices; performs Q/K L2 normalization and delta-rule recurrent updates, rewrites the specified state slot in place, and outputs [batch, 1, value_heads, value_dim]; a negative state index outputs zeros without modifying the state pool. The implementation is parameterized by dimension, with no model-name/architecture dispatch, and the documentation provides a specialized configuration for GLM-5.3-Flash TP8.

1.2 Main Repo: Two Ascend Compilation-Side PRs — SimdVF Multi-Buffer T.fill (#3455) and bisheng Temp File Cleanup (#3461) (10-13)

Date: 2026-10-13　Source: SimdVF T.fill (#3455) / bisheng Cleanup (#3461)

  • #3455 (+247/-31): Ascend SimdVF’s LowerFill previously supported only whole-buffer fills (each dimension must start at 0 and span the full buffer shape); in multi-buffer pipelines, MaterializeMultiBuffer adds a version dimension to buffers (e.g., a [64] logical buffer becomes a [2, 64] physical buffer), and a T.fill inside the loop only needs to fill the current version slot [v:v+1, 0:64], which the whole-buffer check rejected. This PR changes the target to the actual fill region, computes the write index for each VReg data block based on the region start and extent, checks constant extent, contiguity, and VReg alignment, and supports compact layouts and explicit strides; it adds 3 NPU tests (1D / 2D / two-stage pipelined multi-buffer).
  • #3461 (+2/-1): The bisheng wrapper did not pass keep_for_debug when creating temp directories, causing compiled AscendC sources to always be deleted — whereas nvcc, hipcc, and PTO wrappers all pass keep_for_debug=not env.should_cleanup_temp_files(). This PR aligns the behavior so that TILELANG_CLEANUP_TEMP_FILES=0 also takes effect on the Ascend backend.

3.1 TileOPs: Two MoE operators land — masked FP8 grouped GEMM and DeepSeek grouped top-k (10-13)

Date: 2026-10-13　Source: masked FP8 grouped GEMM (#2521) / DeepSeek grouped top-k (#2535) / MoE MMA refactor (#2551)

  • masked FP8 grouped GEMM (#2521, 20 files, +1788/-37, closes #2388): MoEGroupedGemmFP8FwdOp lands from spec — FP8 e4m3 grouped GEMM, 1x128 / 128x128 block scales, bf16 output, semantics aligned with deep_gemm’s masked variant; the manifest narrows to the masked layout and is marked implemented, with a 14-row workload: E=8 two rows plus EP=8 decode twelve rows (DeepSeek-V3, Qwen3-235B-A22B, Kimi-K2, batch 64 / 256). A new moe.masked_routed_metadata generator simulates expert imbalance (DeepSeek-V3 b64 empty 4/32, Kimi-K2 b64 empty 13/48); the sm90 kernel is a persistent grid of a TMA producer warp plus two WGMMA consumer warpgroups, tile walking reads row counts on device, empty tiles occupy no CTA, and each weight tile is read from HBM only once.
  • DeepSeek grouped top-k (#2535, 15 files, +1193/-69, closes #2268): FusedTopKFwdOp fills in
    num_expert_group, topk_group, and routed_scaling_factor (vLLM grouped_topk semantics), with FusedMoEFwdOp / shared-expert paths synced; fixes the scheduling issue where the default TOKENS_PER_BLOCK at T=512 lands 32 blocks on 32/132 SMs; documentation makes the fast-math boundary explicit.
  • MoE cleanup refactor (#2551, +20/-30): the compact row-wise layout is now served directly by MoEGroupedGemmMMAKernel (whose program already binary-searches for the group tail by sorted row id), removing the dedicated TightRow kernel and dispatch key — layout coverage extends to SM80 / SM86.

3.2 TileOPs: Four SM89 closures — GLA / DeltaNet backward and KDA prefill, plus a GQA fix (10-13)

Date: 2026-10-13　Source: GLA backward (#2546) / DeltaNet backward (#2547) / KDA prefill (#2548) / compact row-wise GEMM (#2549) / GQA fix (#2550)

  • GLA backward (#2546, +36/-27): hoists the inter-block key gradient computation ahead of the query gradient so the slimmed program finishes using dh before loading h — default shared memory for chunk 32, K=V=128 drops from 114688 to 81920 bytes, falling within SM89’s 101376 limit; adds FP16/BF16 cases.
  • DeltaNet backward (#2547, +166/-113): the three-stage program for chunk 64, K=V=128 fits within 90112 / 98304 / 98816 bytes; an explicit state buffer view cuts the 147968-byte w/u allocation reported by reviewers to 98816; shortens operand lifetimes, reusing state storage for keys and the inverse matrix after their last consumer.
  • KDA fused prefill (#2548, +186/-63): enables KDA fused prefill on SM89 — the compact shared-memory schedule for 128-dim inputs cuts the 256-thread allocation from 182528 to 101120 bytes; the fused path is selected only when the sequence/head block count reaches the SM count; adds four public FP16/BF16 numerical cases and replaces the outdated 2048-sequence rejection assertion with a numerical check.
  • Compact row-wise grouped GEMM (#2549, +45/-11): SM89 supports compact grouped GEMM that recovers segment tails by sorted expert id, reusing the existing MMA program (including empty experts and partial tiles).
  • GQA fix (#2550, 18 files, +341/-173): dense GQA decode’s split log-sum-exp switches to FP32 accumulation — bf16 steps by 0.5 over the 64 to 128 range, and split mixing deviates by up to 0.23 at large scores; autotune now times the program actually launched by forward (including the fused RoPE path), correcting the candidate selection criterion.
