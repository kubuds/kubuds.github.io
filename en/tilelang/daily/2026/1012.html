I. Core Project Progress

1.1 Main Repo: SM121 (DGX Spark) Lights Up Block-Scaled MMA; CuTeDSL Fence Election and Parameter Identity Fixes (10-10 ~ 10-11)

Dates: 2026-10-10, 2026-10-11　Sources: SM121 block-scaled MMA (#3430) / CuTeDSL fence election (#3400) / NVRTC / CuTeDSL parameter identity (#3414)

  • SM121 lights up (#3430, merged 10-11 00:32): SM121 (GB10, DGX Spark) actually supports SM120-class warp block-scaled MMA, but the SM120 helper only checked the CUTLASS SM120A macro guard (defined only when the device arch is 12.0), so on sm_121a every block-scaled MMA compiled to BPT.TRAP instead of OMMA.SF; this PR accepts both SM120 / SM121 targets by arch and family, gates NVF4 tests by the SM12x family, and allows sm_121 / sm_121a in the CuTeDSL TMA architecture table. The author verified it on a DGX Spark (driver 580.178.04, CUDA 13.0).
  • Fence election (#3400, merged 10-10 10:47): sync_grid() previously elected all threads with tid.x == 0, so under 2D / 3D thread blocks multiple threads repeatedly published the same block arrival and the fence could release early; it now elects only the physical thread (0, 0, 0), with the counter / generation protocol and cooperative launch unchanged. Regression covers 1D / 2D / 3D grids and repeated reuse (RTX 5090, CuTeDSL 4.7.0).
  • Parameter identity (#3414, merged 10-10 13:58): NVRTC and CuTeDSL host wrappers previously generated signatures from raw Var names and matched parameters by printed name, so duplicate names (stream, device_id, etc.) and device-side renames caused crosstalk; they now assign wrapper parameter names by Var identity while preserving positional ABI, and CuTeDSL allows the same kernel to be invoked repeatedly with different scalar bindings, so identically named shape / stride symbols can be distinguished.

1.2 Main Repo: GEMM dtype Whitelist Finalized — Unsupported Combinations Rejected Before CUDA Codegen (10-12)

Date: 2026-10-12　Source: GEMM dtype whitelist (#3245)

  • Some T.gemm operand dtype combinations (e.g. bf16 x bf16 to fp16) were previously accepted at the frontend and only failed inside nvcc with an opaque static_assert (issue #3004); this PR adds an explicit dtype whitelist for the Ampere / Ada mma.sync path, enforced on both the frontend (tileop/gemm) and C++ instruction selection, so unsupported combinations are rejected before CUDA codegen with a clear message.
  • Includes 1 negative and 3 positive regression cases; supported combinations and non-Ampere target behavior are unchanged. Merged 10-12 01:21, the latest merge before this window’s cutoff.

1.3 Main Repo: Five PRs Landed — For Step, JIT Output Index, popcount, Bit Reduction, and Test Infrastructure (10-10 ~ 10-11)

Dates: 2026-10-10, 2026-10-11　Sources: For loop step (#3427) / JIT output index (#3318) / popcount (#3300) / bit reduction (#3332) / test infrastructure (#3313)

  • For step (#3427, merged 10-10 12:54): Loop-carried conflict analysis previously treated the step as always 1 (contradicting the comment “defaults to 1, when unspecified”), distorting valid iteration-pair determination under non-unit / signed steps; it now shrinks the iteration-pair range by the explicit step, with both CUDA and HIP codegen preserving the step and delegating emission to CodeGenC, while respecting lexical allocation scopes for unrolled loops.
  • JIT output index (#3318, 10-10 12:02): out_idx=[-1] was polluted by normalization when reused across kernels with different parameter counts (a two-parameter kernel normalized [-1] to [1], and a four-parameter kernel then mistakenly occupied an input slot); it now copies the caller’s list before normalization, rejects scalar indices equal to the parameter count, and reports the valid range.
  • popcount (#3300, 10-10 12:02): Completes CUDA lowering for signed and 8 / 16-bit narrow integers — convert to unsigned at the original width before widening (int8(-1) counts 8 bits rather than 32), with 64-bit going through __popcll; covers 8 dtype regressions; fixes #2984, with all 16 tests passing on H100 (CUDA 13.0).
  • Bit reduction (#3332, 10-11 14:13): reduce_bitand / bitor / bitxor previously checked only the destination buffer and allowed floating-point sources ([1.0, 2.0, 4.5, 8.9] was silently truncated to 1 2 4 8 = 15 with no warning); source and destination are now uniformly rejected under integer / boolean rules (refs #3301).
  • Test infrastructure (#3313, 10-11 18:25): Adds shared IR inspection helpers (node collection, exact operator call counts, external call collection by symbol), migrating issue and transform tests from ad-hoc traversal code to the helpers; lower_ldgstg tests gain structural assertions, and selected transform tests pin the sm_90 target with availability-based skips.

3.2 TileOPs: MLA / KDA / NSA Performance Batch — SM89 Decode Speedup Up to ~4.6x (10-10 ~ 10-11)

Date: 2026-10-10, 2026-10-11　Source: MLA Decode SM89 (#2511) / MLA Tuning Split Expansion (#2524) / MLA Candidate Pruning (#2525) / WGMMA Descriptor (#2523)

  • MLA Decode (#2511, merged 10-10 22:31): On SM89, selects 2/4/8/16 KV splits by batch and head-block count (targeting 128 CTAs, cap 16), reusing the existing scan and FP32 split-merge kernels — single-request bf16 4k default latency drops from 0.158 to 0.034 ms (~4.6x), 32k from 1.170 to 0.162 ms (~7.2x).
  • MLA Tuning Surface (#2524 / #2525): Tuning candidate splits expanded to 1/2/4/8/16 (candidates from 24 to 40, with a measured 2.00x row against FlashInfer); candidate query tiles whose staged KV exceeds the shared memory budget are pruned (40 down to 20 at D=512), cold tuning plus first tune drops from 348.6 s to 151.6 s, with failed candidates eliminated.
  • WGMMA Descriptor (#2523 / #2504): Descriptors for MLA decode and the DSA seesaw kernel are now constructed via lane 0 broadcast (HGMMA’s R2UR wait eliminated, no overflow) — 26 MLA benchmark rows 0.7% to 4.1% faster; incidentally fixes a hang on SM90 in bs1 partial RoPE decode when the final split block is undersized.
  • KDA Prefill (#2510): SM89 single-sequence 4096 to 64k tokens, up to 8 value heads, split by 16-column value tiles — 4k / 32k / 64k latency reduced by 22.9% / 19.8% / 18.5% respectively.
  • NSA top-k (#2514): Each compressed block assigned to one CTA (query heads fill a 64-row WGMMA tile), in-register bitonic sorting network sorts entire rows (replacing the odd-even transposition sorter), importance ties broken by lower block number.
  • Paged GQA (#2512): SM90 warp-specialized TMA kernel (one TMA producer warp + two consumer warpgroups overlapping QK and PV), one persistent CTA per SM; stale V rows from tile-switching at the cache tail are zeroed before reading; packed layout preferentially dispatched when averaging at least one 128-row tile per request, with the four adopted rows on H200 dropping to 0.44 to 0.88x of original time.
