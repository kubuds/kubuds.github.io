I. Core Project Progress

1.1 Main Repo: ROCm Double Feature — DeepSeek NSA Forward/Decode and flash-decoding Feasible Tiles (10-13)

Date: 2026-10-13 (merged in the early hours of Beijing time)　Source: ROCm NSA (#3152) / ROCm flash-decoding tiles (#3149)

  • DeepSeek NSA on ROCm (#3152, +111/-2): gfx942 has a wavefront size of 64, and TileLang rejects HIP blocks smaller than the wavefront, while the two NSA examples hardcoded 32 threads; this PR selects a single 64-lane wave for the forward and single-token decode kernels, preserves CUDA’s existing 32-thread launch configuration, and adds correctness coverage for causal forward and single-token decode on gfx942 (against the PyTorch NSA reference, FP16, 16 Q heads / 1 KV head, sequence 64).
  • flash-decoding tile adaptation (#3149, +82/-5): on gfx942, the 128x64 tile generation kernel requires 66048 bytes of dynamic LDS (exceeding the 65536 device limit) and hits the 256 VGPR ceiling, causing an “invalid argument” launch failure; this PR checks the generated HIP LDS and VGPR usage before launch and falls back to the existing 64x64 tile only when over budget (not hardcoded by device name), leaves the CUDA path unchanged, and adds a gfx942 runtime regression.

Date: 2026-10-13　Source: Exact thread bounds (#3291)

II. Multi-Backend Adaptation (Ascend / MetaX / Hygon / Moore Threads)

2.1 Ascend: Two Major Migrations Merged — NSA Decode / NSA Bwd — with 48 Layered Tests (10-12)

Date: 2026-10-12　Source: NSA Decode (#1701) / NSA Bwd (#1730)

  • #1701 (+755): example_tilelang_nsa_decode.py implements NSA Decode single-core decoding (seq_q=1) via Developer mode hybrid (four pass_configs: combineCV + auto_cv_sync + auto_sync + memory_planning), with explicit L1/L0C/UB allocation and 5-segment GM workspace auto-assigned through workspace_idx=[6..10]; the compiler automatically splits Cube/Vector scopes and inserts cross-core flag synchronization (no manual barrier/Scope/set_flag needed). 28 layered tests: L0 thresholds, L1 functionality (including DeepSeek-V3 typical config D=128, S=16, BS=64), L2 exceptions and boundary special values; measured on 910B3, fp16 (B=2, SEQ_LEN=64).
  • #1730 (+1593): example_tilelang_nsa_bwd.py provides two JIT kernels — nsa_fwd (online softmax + sparse K block selection, for end-to-end) and nsa_bwd_single (single-core backward: 5 GEMM + softmax + Delta + dS on-chip fusion); the backward pass follows the flashattn_bwd paradigm using on-chip direct T.copy (L0C→UB, UB→L1) to eliminate 9 GM workspaces, retaining two-level compensation GEMM (ds_delta / ds_delta2); 20 layered tests. The migration batches for both spanned the National Day holiday period, and this window saw them land on the adaptation repo’s default branch.

III. Ecosystem and Adopters

3.1 TileOPs: SM89 platform expansion batch — GQA prefill/decode, GDN / DeltaNet, and Norm (10-12)

Date: 2026-10-12　Source: D256 GQA decode (#2529) / dense GQA prefill (#2528) / GDN / DeltaNet prefill (#2527) / InstanceNorm fix (#2526) / Norm config refactor (#2544)

  • D256 dense GQA decode (#2529): Opens 256-dim dense GQA decode on SM89 — reuses the 64×64, single-stage, 128-thread partition program; 16 candidate partitions occupy 98304 bytes (below the SM89 limit of 101376); excludes single-split candidates and keeps the two-split candidate for short KV; tests expanded to 61 nodes (+6), covering KV lengths 1 / 63 / 2048. Measured on RTX 6000 Ada.
  • dense GQA prefill (#2528, +260/-43): Adds FP16/BF16 and native FP8 prefill on SM89 (reusing the packed attention program, head dim 128); 14 cases fail on main and pass here (10 FP16/BF16 + 4 FP8); preserves rectangular masks, grouped heads, custom scale, softcap, RoPE, and FP8 dequantization; shares default config and memory accounting to avoid duplicate implementations.
  • GDN / DeltaNet prefill (#2527, 11 files): Reuses KDA’s chunk prepare and scan programs to implement SM89 prefill; 21 general prefill cases go from “failing, non-dispatchable” to passing; preserves raw-beta rounding, packed sequence boundaries, grouped heads, FP32 initial/final states, and GDN’s value-major state layout; the stable triangular solve is reused, and correlation-key cases do not relax tolerances.
  • Two Norm PRs: #2526 fixes InstanceNorm training compilation for 192×192 spatial inputs (six batch / precision combinations go from failing to passing, reusing GroupNorm’s width boundary and two-pass reduction); #2544 relocates the shared shift-reduction width constant (32768) into the norm config module (all 87 cases pass, no performance claims).

3.2 TileOPs: foundry performance batch — NSA persistent CTA, W4A16 GEMM, and 16-bit division (10-12)

Date: 2026-10-12　Source: NSA persistent CTA (#2531) / W4A16 GEMM (#2534) / 16-bit division (#2543)

  • NSA compressed persistent CTA (#2531, +391/-2): On SM90, NSACompressedVarlenFwdOp switches to the new kernel NSACompressedFwdVarlenTMAKernel — the old kernel used one 32-thread CTA per (token, KV head), reloading compressed K/V per token; the new kernel uses 512 persistent CTAs, each walking 64-row tiles (4 tokens × 16 heads), with queries fed through a double-stage TMA ring, requested K/V blocks resident in shared memory, QK via n=16 SS WGMMA and PV via n=64 RS WGMMA, and O written out via TMA together with log-sum-exp after QK reads complete; four 48KB CTAs reside per SM.
  • W4A16 GEMM (#2534, +24/-0): _legal_configs constrains the K tile to not exceed K and the ring depth to not exceed the number of K tiles, so K<512 no longer pads with zeros; single-tile (K=128) and multi-tile (K=256) rows switch to 8x64 tiles with 128/256-wide K tiles (two stages), leading torch dequantized matmul; the other 13 rows keep their configs unchanged, and 3 rows still lag (limitations self-listed by the author).
  • 16-bit division (#2543, 9 files): Reciprocal and bf16 sigmoid switch from IEEE float32 division to __fdividef fast division (range-scaled version for bf16); at 16M rows, fp16/bf16 latency is 17.86 / 17.79 microseconds, 1.02x the previous version and 0.991x / 0.995x of torch-compile.

3.3 TileOPs: linear attention fixes — TMA hang avoidance and GLA prefill state skip (10-12)

Date: 2026-10-12　Source: single-tile decode state load (#2538) / GLA prefill state skip (#2540)

  • #2538 (+66/-6): On SM90, the GLA / DeltaNet recurrent decode program with k_tile == dim_k hangs on first launch — TileLang 0.1.12 downgrades the single-step state copy to a 1D bulk copy, whose producer never reaches the barrier under warp specialization; after the four builders switch to non-TMA loads, any k_tile that evenly divides dim_k can run, and k_tile < dim_k behavior is unchanged; a FIXME is left in the code to reclaim the workaround once TileOPs pins TileLang 0.1.13+.
  • #2540 (+77/-67): The four GLAFwdOp prefill implementations are specialized on has_initial_state — when there is no initial state, the local recurrent tile is cleared and an unread scalar placeholder is used, eliminating allocation, zeroing, and reading of the entire FP32 initial-state tensor; the device source built with state is byte-for-byte identical to main, and the public interface and dispatch domain are unchanged (closes #2380).

V. Trend Observations

5.1 ROCm Catch-Up: Two Fixes Driven by Device-Budget Awareness

  • The two ROCm changes in this window point to the same theme — “adapting to device reality”: the 64-lane wavefront on gfx942 (#3152) and the LDS/VGPR budget (#3149). Both are fixed on the use-case side (examples) without touching in-kernel generation strategy, indicating that ROCm support is still in the “get it running and add regressions” stage; combined with the main repo’s recent multi-generation concurrent fixes for SM121 and SM89, TileLang’s backend topology is shifting from “NVIDIA-first” to “maintaining multiple devices simultaneously.”

5.2 SM89 Becomes a Second Platform: 6 Merges Plus 4 Under Review in a Single Day

  • TileOPs saw 6 SM89 merges in one day (attention prefill/decode, linear attention, full Norm coverage) plus 4 SM89 PRs under review; RTX 40-series and L40 / 6000 Ada-class workstations have become routine targets alongside Hopper on the operator library side.
