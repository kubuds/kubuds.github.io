Today’s Highlights

The output focus of this window is the “analyzer,” not the “generator.” TileFoundry merged five PRs in three days, three of which turned invariants that previously existed only in the author’s head into checkable objects: #291 brings shared operands of TMA copies into async-proxy semantics, pairing each TMA load with an mbarrier word, and rejects programs in cross-CTA scenarios where “one CTA performs async-proxy writes while another CTA reads the same global element without ordering”; #293 defines placement value semantics, writing the four states Split / Broadcast / Varying / Partial, the merge rule B ⊔ V = V, and the target validation for Reshard into a contract, while removing the no-longer-supported Dynamic attribute (64 files, +1165 to -536); #301 handles “regions that still need to read old data must be ordered before the schedule overwrites it,” recording the order in LivenessMetadata.orders and throwing AnalysisError when no order can be found. The other two (#290, #288) fix approximations in the analyzer itself.

The second item is pipelining. Of the 71 merges in 72 hours, TileOPs accounts for 33 and topa for 15, totaling 68%; 40 were submitted by the same author. Along with three CI changes in the same period (#2849 writes the nightly benchmark performance-gap queue into the wiki, #2852 syncs it to the Perf Tracker project, #2856 automatically moves caught-up operators to Done), performance work has formed a closed loop of “nightly benchmark → gap queue → single-operator round → review → merge”; the topa repo’s 15 PRs in two days (topa hunt, topa round start, topa round status, topa review prepare) are precisely the command-line shell of this loop. The efficiency gain is real, and so is the risk: a single-point author stacked with single-point review will degrade the pipeline into a one-person pipeline. Of the 96 PRs under review in 72 hours, 59 are still stuck in the main tilelang repo—review bandwidth is the next bottleneck.

The third item is on Ascend. On a single day, 11-07, one account opened 14 issues, with 13 fix PRs under review the same day: gemm_blockscaled’s positional parameters diverge from the public signature, causing policy to be moved into clear_accum (#3857); vcvt’s bf16-to-f16 swaps the round and sat parameters (#3829); vdupv silently maps an unknown pos to HIGHEST (#3832); fp4’s T.fill crashes with a divide-by-zero in SimdVF (#3852); the kernel cache key omits ASCEND_NPU_ARCH and the PTO toolchain, potentially reusing artifacts from one architecture on another (#3853). The common shape of these defects is “declared support, divergent implementation”: for architectures present in HCU_MCPU_SET, the C++ backend does not necessarily have a branch—the new Hygon gfx928 issue (#35) is the same shape. Meanwhile, all 3060 daily tests pass, showing that pass rates do not cover these combinations; test count cannot substitute for differential validation of shape combinations.

1. Core Project Progress

1.1 Mainline: CuTeDSL grid sync moved to per-launch workspace, multi-stream concurrency no longer cross-talks (#3868)

Merged 11-08 18:00. CuTeDSL’s sync_grid() previously kept the barrier counter and generation in module-level globals (__grid_sync_ctr, __grid_sync_gen), so the same kernel launched concurrently on two streams shared one barrier: arrivals from both grids were merged, a launch could be released before all its own blocks had arrived, and leftover counts could hang subsequent launches. On H200 NVL a single launch took 17.4 ms and a pair 17.8 ms, confirming cooperative launch was indeed running concurrently. The fix replicates cooperative_groups::details::sync_grids with inline PTX: the barrier word is taken from the barrier field of the grid workspace the driver provides for each cooperative launch, with the address coming from %envreg1 (high half) and %envreg2 (low half); thread 0 of each block does one atom.add.release.gpu, block 0 adding 0x80000000 - (nblocks - 1) and the rest adding 1, then spins on ld.acquire.gpu waiting for bit 31 to flip. State is isolated per launch, so concurrent launches no longer affect each other. The regression test hangs on main (killed at 300 seconds) and passes after the fix; the author also kept the CUDA backend as a control, which was correct all along.

Source: https://github.com/tile-ai/tilelang/pull/3868

1.2 Mainline: CuTeDSL signed integer truncation fixed to arith.divsi semantics (#3551)

Merged 11-08 07:48. CuTeDSL emitted Python floor division for signed TIR DivNode, so at runtime T.truncdiv(A[i], 3) returned -3 instead of -2 for -7, and the subsequent floor/ceil corrections computed on top of that quotient, spreading the error. The fix emits tl.truncdiv (backed by MLIR arith.divsi) for signed scalars and vectors, uses exact integer arithmetic for pure Python inputs, and leaves the vector store path and unsigned lowering untouched. 25 regression cases cover int8/int16/int32/int64, scalars and vectors, negative divisors, integer extremes, and “quotient times divisor plus remainder equals dividend.” The reporter had independently verified this with a CPU reference and MLIR in the issue #2973 discussion and pointed out the boundary of pure Python %; that feedback went directly into the implementation.

Source: https://github.com/tile-ai/tilelang/pull/3551

1.3 Mainline: CuTeDSL fills example gaps across 63 files in one pass, including SM120 block-scaled MMA (#3685)

Merged 11-07 18:59, +7075 to -394, 63 files — the largest change this period. New coverage includes: warp vote, match and bit search, block-predicate barriers, explicit-width loads and stores with cache hints, NaN-propagating min/max, TMA and cluster copies (multicast, store_cluster, gather4, scatter4), SM120 block-scaled MMA (mxf4nvf4) and a matching NVFP4 GEMM example. The same change also fixes an old warp specialization problem: a T.fill placed before the pipeline was moved into the producer/consumer branches and then re-ran after every iteration even across loops or conditionals, overwriting that iteration’s T.clear result.

Source: https://github.com/tile-ai/tilelang/pull/3685

1.4 Mainline: CUDA single kernel launches can be named, stages distinguishable in the profiler (#3816)

Merged 11-06 17:45. Multiple T.Kernel in one PrimFunc previously shared an auto-generated name prefix, making stages indistinguishable in the profiler. A new optional name= parameter is supported by both T.Kernel(grid, threads=128, name="compute_stats") and T.ClusterKernel; the generated device symbol is compute_stats, with no _kernel suffix appended. The name travels through LowerOpaqueBlock via the tl.kernel_name annotation and is consumed by SplitHostDevice when generating the device function; explicit names are validated as non-empty ASCII identifiers, duplicate names and host-function conflicts go through the existing global symbol supply, and unnamed launches keep the old naming. Docs now cover naming, host call targets, invalid input, eager JIT, shared memory and cluster launches.

Source: https://github.com/tile-ai/tilelang/pull/3816

1.5 Mainline: Multi-source cache directories, read from any, write to the first (#3807)

Merged 11-06 13:31, +593 to -288, 18 files. TILELANG_CACHE_DIR now accepts multiple colon-separated directories, e.g. /cache/read/and/write:/cache/readonly/A:/cache/readonly/B; compiled artifacts can be hit from any directory but are only written to the first. This matches the common cluster pattern of “shared read-only cache + local writable layer,” letting a batch of builds share one operator cache. The author notes a boundary: the CuTeDSL backend may have problems on read-only directories.

Source: https://github.com/tile-ai/tilelang/pull/3807

1.6 Ascend: Z3 scheduling global lock removed, slowest cold-compile case drops from 37.3 s to 25.6 s (#3812)

Merged 11-06 18:17. Ascend’s Python scheduling callback serialized all Z3 solves behind one global lock, even though each call already held a private Z3 context. After removal, independent compile threads can schedule in parallel: in a cold-compile batch with 8 threads and 8 configs per kernel, SwiGLU backward dropped from 33.1 s to 30.0 s and MoE gate forward from 37.3 s to 25.6 s. Validation covered 884 existing Ascend auto-schedule CPU tests, 64 concurrent requests matching serial results, and 16 sampled SwiGLU backward and MoE gate configs producing identical schedules, source and device ELF before and after the change.

Source: https://github.com/tile-ai/tilelang/pull/3812

1.7 Ascend: access_ptr region fix, cross-row and transposed views no longer lose DMA dependencies (#3805)

Merged 11-06 12:08. When contiguous SIMD loads crossed rows or used a transposed view, the region rebuilt by access_ptr lost input DMA dependencies, so AutoSchedule could schedule the load before the copy and InsertSync would no longer insert the MTE2-to-V sync. The fix reuses conservative pointer region reconstruction: carry the start offset when crossing rows, fall back to the whole buffer for layouts that cannot be reconstructed, and keep the simple 1-D positive-stride fast path. Regression covers two cross-row cases and one transposed view, verifying the “DMA → set/wait → load” order and event ID alignment with and without AutoSchedule; 171 related host-side IR tests pass, and device execution was not tested (the author states this boundary explicitly).

Source: https://github.com/tile-ai/tilelang/pull/3805

1.8 Examples: sm_12x picks tiles by available dynamic shared memory, all pass on RTX PRO 6000 (#3845)

Merged 11-08 06:25. The dim=128 block-causal varlen case previously fixed a 128x128 tile, requiring 128 KiB for forward and about 192 KiB for dK/dV, while sm_86/89/120 cap dynamic shared memory at about 99 KiB, so launch failed outright with Failed to set the allowed dynamic shared memory size. The fix derives block_size from get_max_dynamic_shared_memory(): data-center cards keep 128x128, small-shared-memory devices use 64x128 (about 96 KiB), and block_size stays divisible by dllm_block=64. On RTX PRO 6000 (sm_120), CUDA and CuTeDSL each report 209 passed, 26 skipped, 0 failed; on H200 NVL (sm_90) the two 128x128 cases pass. The author calls this the last failing example left by #3701.

Source: https://github.com/tile-ai/tilelang/pull/3845

1.9 New issue cluster: wrong results remain the heaviest category, covering WS loop-carried state, copied-loop atomics, unsigned semantics

29 new issues were opened in the main repo during the window, the heaviest being the “computes wrong but reports no error” group. #3842: with warp specialization enabled, updates to a variable between two pipeline rounds take effect only in the consumer branch and are invisible to the producer, producing wrong results. #3870: inside a copied parallel loop, atomic operations and read-modify-writes on a fragment are performed once per copy. #3871: the tvm_ffi backend does not restore the caller’s current device after a call, so the caller subsequently launches on the wrong device. #3877 and #3881: under the NVRTC path a kernel with only one parameter cannot launch; under the cython path dynamic shared memory above 48 KB fails on the second device. #3866: Metal’s packed FP16 vector arithmetic operates on integer bit patterns; #3884 is under review (switching to half2). CuTeDSL unsigned semantics also produced three issues in a row: #3874 atomic max/min compare as signed, #3876 unsigned atomic comparison, #3875 values read from unsigned buffers should stay unsigned. The first two of these are the same type as #3808 and #3800 from the previous window: the compiler reports no error, and the generated code gives wrong results under specific combinations.

V. Trend Observations

First, the automation loop has taken shape, but its center of gravity has shifted from “writing code” to “defining contracts.” None of topa’s 15 commits contains a single line of kernel code—they are all round rules, review checklists, PR body formats, and worktree cleanup; most of TileOPs’ 33 commits are “change one parameter per the target bar, provide a set of A/B”; and TileFoundry’s 5 commits define what counts as “placement equality,” “TMA completion,” and “read before overwrite.” Stacked together, the three form a complete pipeline: nightly benchmarks surface gaps, the queue assigns operators, agents modify within TileFoundry’s scheduling space, review checks the numbers against the checklist, and the item is automatically closed after merge. The pipeline’s output efficiency is already visible in the numbers (71 commits in 72 hours), but it is extremely sensitive to “whether the contract is written clearly enough”—today #2867 was still merged despite being labeled “below the target bar,” and #301 chose to error out rather than guess when it could not determine an order; both are examples of the contract at work.

Second, Ascend’s bottleneck has shifted from “whether it can compile” to “whether declaration and implementation agree.” None of the 14 issues is “a feature is unsupported”—all are “declared supported but the implementation takes another path”: HCU_MCPU_SET has gfx928 while the C++ side has no branch (same for Hygon), T.simd.vcvt documents int32/int64 to f16 while the implementation rejects it, the annotate_unlimit_memory error message tells users to pass "shared.ss" while the function itself rejects it, and gemm_blockscaled’s positional parameters diverge from the public signature. The common fix for this class of defect is not adding features but putting “declaration” and “implementation” in the same table for generative checking—for example, generating from HCU_MCPU_SET the list of architectures the backend must cover, and generating from the intrinsic registry a dtype/bit-width support matrix. Until that is done, a test report with all 3060 items passing only shows that “the combinations tested are fine.”

Third, CuTeDSL is at the stage of “feature coverage approaching CUDA, correctness boundaries not yet converged.” #3685 adds 63 files in one go, filling in capabilities CUDA has long had—cluster TMA, SM120 block-scaled MMA, Philox, warp vote—showing that feature-surface alignment is nearly complete; but the defects in the same window are all at the boundaries: grid barrier under multi-stream concurrency (#3868), signed integer division (#3551), unsigned atomics and unsigned buffers (#3874/#3875/#3876). These are not “not implemented” but “implemented with semantics inconsistent with CUDA.” The practical advice for users: the CuTeDSL path is suitable for running examples and development; before switching a production kernel’s backend, run a round of element-wise diffing against the CUDA backend, especially in scenarios involving negative division, unsigned comparison, and multi-stream concurrency.

Fourth, the way performance optimization is recorded is changing. The hallmark of this batch of TileOPs PRs is that each one clearly states “which op, which benchmark, whether the result meets the bar, and what the root cause is”: #2868 gives the concrete numbers of 900444 sectors versus 501760 writes, #2869 gives the distribution of 12 memory placements with 12 lagging, and #2855 gives the median over 12 warm-up rounds with 10 calls each and proactively declares “execution-order effects not controlled.” This style lets “below the bar” still be merged (#2867), because readers can judge whether it is worthwhile. By contrast, a PR that only says “improves X%” cannot be distinguished at review between the kernel getting faster and the measurement changing.

Finally, the RISC-V line. The four-source inspection shows no change in 72 hours: the two kubuds- branches of kubuds/tilelang-riscv-kubuds, the MLIR route of RuyiAI-Stack/tilelang-riscv, the index page of TongmingLAIC/tilelang-riscv, and the SOPHGO branch of TongmingLAIC/tilelang-tpu all remain at their original references. This contrasts with the mainline’s rhythm: the agent-driven pipeline on the GPU side has compressed iteration to “days,” while the RISC-V side is still manual progress at “weeks.” The gap between the two lines is not in engineering effort but in whether there is a loop that can automatically discover gaps, automatically verify, and automatically queue.
