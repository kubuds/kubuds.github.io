I. Core Project Progress

1.1 Main Repo: Ascend PTO Execution Routing — ascend × pto Direct PTO Codegen (#3316) (10-15)

Date: 2026-10-15　Source: PTO Execution Routing (#3316) / Main Repo PR List

  • Execution Routing (#3316): Makes the combination of target="ascend" and execution_backend="pto" actually take effect — an explicit PTO execution backend specializes the native Ascend target into a PTO target variant (preserving target attributes such as arch) before backend resolution, and compilation accordingly selects the PTO backend and PTO device code generator (CodeGenTileLangPTO, i.e. codegen_pto.cc). The implementation adds an execution-aware target normalization hook attached at BackendContext creation; the Ascend-specific normalizer handles the mapping, and device code generation switches to PTO_CODEGEN and target.build.tilelang_pto_without_compile.
  • Path Semantics (PR behavior table): ascend × auto maintains the AscendC + TVM-FFI path; ascend × tvm_ffi / cython goes through AscendC; ascend × pto and the existing target="pto" shorthand both go through the PTO backend. The documentation provides the equivalent environment configuration: TILELANG_DEFAULT_TARGET=ascend plus TILELANG_EXECUTION_BACKEND=pto. Tests cover direct context resolution, target attribute preservation, cache dispatch, and environment variable selection.
  • Connections: Continues from the example target selection merged on 10-14 (#3474, CI runs all Ascend examples once for each of the ascend and pto targets) and the in-review PTO family (tvm_ffi execution backend #3516, VMI vectorization #3512, SS buffer #3514, partial L0 copy pitch #3511) — the Ascend side’s “dual-path coexistence” is moving toward “one target, two execution backends.”

1.2 Main Repo: JIT Rejects Unhashable Compile-Time Arguments (#3417); Test Compile Time Elimination (#3517) (10-15)

Date: 2026-10-15　Source: JIT Hash Validation (#3417) / Test Compile Time (#3517)

  • JIT Rejects Unhashable Compile-Time Arguments (#3417): JIT specialization now requires compile-time arguments and default values to be hashable — unhashable default values raise TypeError at JIT wrapper creation, and explicitly passed unhashable arguments are rejected before kernel lookup or factory execution; this prevents mutable default values from silently reusing stale kernels and unifies the lazy and eager argument contracts. Validation uses hash() (including tuples containing unhashable values); the call-form cache checks hashability first before taking the “last call equality” shortcut; container content normalization is removed, and runtime tensor arguments still do not enter the specialization key. Verification: native source rebuild passes, argument binding and related suites total 91 passed, no skips.
  • Test Compile Time Elimination (#3517): Four packed-type CUDA source helper functions in
    test_tilelang_issue_2994.py now use target.build.tilelang_cuda_without_compile (only fetch generated source, no full build); these helpers only ever checked generated source and no longer bear the regular build overhead.

Date: 2026-10-15　Source: varlen GQA sink (#2537) / full-featured paged GQA (#2516) / PagedKVCacheWriteFwdOp (#2539) / MoEGroupedGemmFP8 docs (#71)

  • varlen GQA sink and pipelined sliding window (#2537): Adds optional FP32 per-head sinks for FP16 / BF16 / FP8 varlen GQA — a sink is an unscaled, untruncated logit that enters the softmax denominator; covers the varlen portion of the “attention sink” issue (#2269), while also folding in the pipelined sliding window.
  • Full-featured paged GQA (#2516): GQAPagedFwdOp gains read-only RoPE, two-sided sliding window, and optional per-head sinks, completing the paged path portion of the attention sink issue.
  • PagedKVCacheWriteFwdOp (#2539): New paged KV write operator — scatters K / V in place to caller-specified physical slots, skips -1 slots, and quantizes the FP8 cache with independent K / V scales; a single kernel handles both writes, with dynamic token count; preserves NaN, finite overflow, and infinity with native FP8 conversion saturation; the workload validates both written rows and untouched cache contents; accepted against FlashInfer and vLLM; exports PagedKVCacheWriteKernel from the attention package.
  • All three belong to the attention family; the previous window was already under review, and this window merged them together. Also: the docs site merged #71, adding API entries for PagedKVCacheWriteFwdOp and MoEGroupedGemmFP8FwdOp.

3.2 TileOPs: Three foundry performance PRs — W4A16 load reordering, sigmoid without IEEE division, SM89 scan widening (10-15)

Date: 2026-10-15　Source: W4A16 weight-first load (#2586) / sigmoid without IEEE division (#2588) / SM89 scan widening (#2574) / TileOPs PR list

  • W4A16 weight-first (#2586): GemmW4A16Kernel previously copied each K tile’s activations before the packed weights, and the warp-specialized producer issued in that order and waited stage by stage, so weights actually loaded from DRAM one K tile late; now weights go first (their stage is released immediately after the decode read). The 8-row decode tile replaces three operations with one shift (w4a16_dequant_word_one_shift masks the odd/even nibbles in place and centers with a single FMA, multiplying weights by 1/16). decode-long-k reaches 1.047x marlin-fp16 (previously 0.996x), the 8-row tile speeds up each row by 2.5% to 7.6%, and prefill-mlp-up is 5.7% faster (0.992x versus torch dequantized matmul, on par); no row is slower.
  • sigmoid without IEEE division (#2588): make_unary_regcopy supports evict_last loads — threads handling a full 16-byte vector use tileops::load16_evict_last, with the tail block guarded per vector; only SigmoidFwdKernel enables this path (the other 37 unary kernels generate identical CUDA, with 357 kernels compared per dtype). float16 sigmoid switches to refined_reciprocal (__fdividef reciprocal plus one Newton step, branchless), replacing the per-element range check and slow-path call; float16 / bfloat16 results are bit-identical to torch.sigmoid, and float32 keeps IEEE division. The forward input uses vector_aligned, fixing a misaligned address error when the starting element crosses a 16-byte boundary. 16M rows lead torch-compile by 1.020x to 1.042x; test nodes +2.
  • SM89 scan widening (#2574): The existing 16-column prefill scan is extended from 8 value heads to 16 value heads over the 4096 to 16384 token range (calls with ≤8 value heads keep the original strategy); it shares the same scan program and build identity, benefiting GDN and DeltaNet while leaving KDA unchanged. After a full A/B of the manifest, 19 affected workloads ultimately speed up by 2.5% to 19.7%.
  • TileOPs has 16 open PRs (17 last period); five newly opened: raster persistent tiles (#2589), GemmW4A8FwdOp (#2590, INT4 weights times FP8 activations), read-only paged GQA FP8 (#2591), SM89 long-prefill 32-column scan (#2592), and others.

3.3 TileFoundry: Three merges — instance slot refactor (#232), lowering contract (#233), and Qwen3.8-27B prefill example (#236) (10-15)

Date: 2026-10-15　Source: instance slot refactor (#232) / lowering contract (#233) / Qwen3.8-27B prefill example (#236) / analysis context (#238)

  • Instance slot refactor (#232, merged 03:02): Module child nodes become explicit shared instance slots — duplicate layers share a definition while retaining independent resources and instance identity (ownership copies would duplicate the definition, and inlining would lose instance identity, so both are abandoned). Retained calls are analyzed stepping through the callee, IR records are stored once per definition with call records equal to the callee summary; placement addresses are shared per SSA leaf, live ranges are cached per definition and translated at call sites, and reachable index weights are counted via ISL set union; check_program clones only once. The old inlining mechanism and Program are removed. Validation: full source suite 1674 passed, 11 skipped; installed version 161 passed.
  • Lowering and printer contract (#233, merged 05:12): Preserves author regions, storage definitions, update windows, tiled carry, staged ownership, and linear iteration indices; instruction admission is shared across ScheduleOp inference, candidate generation, lowering, and TIR validation; unifies logical layout and sharded window inference, and fixes MMA fragment declarations and physical register packing; SymbolRef.nested is defined as a child slot path relative to the caller’s Module, with validation and code generation sharing the same resolver.
  • Qwen3.8-27B prefill example (#236, merged 07:45): Adds prefill examples from 128 to 1024 tokens, deliberately crossing the roofline ridge — 128 tokens falls on the memory-bound side (51.4 GB of weights at 4.8 TB/s is about 10.71 ms), and from 256 tokens onward it is compute-bound, with the ridge at about 206 FLOP / byte; the SGLang baseline is measured empirically (fixed serving-path overhead exceeds the forward pass itself at short lengths); it is meant to answer whether multiple prompt lengths can share a single implementation.
  • 2 open PRs (3 last period); #238 (analysis evaluating definition facts per access context) is newly opened.

V. Trend Observations

5.1 PTO moves from “standalone target” to “first-class execution path”

  • #3316 lets the ascend target directly select the PTO execution backend, and together with #3474 from before the window (environment-variable target selection, CI dual-target parallelism) and the in-review #3512 / #3514 / #3516 / #3511, it turns PTO from a “standalone target with a separate pipeline” into a “composable execution path on the Ascend target.” In contrast, ascend repo #1900 reveals that silent numerical error class issues on dav-3510 (A5) are beginning to be systematically captured — with interface convergence on one end and verification entering deep water on the other, engineering on the Ascend side is advancing on both fronts simultaneously.

5.2 Attention family consolidation: long-context inference operator surface filled out

  • One window merged sinks (varlen and paged), bilateral sliding window, read-only RoPE, and paged KV writes, plus in-review read-only paged FP8 and 32-column scan — TileOPs’ paged / long-context attention matrix is being filled out, with FlashInfer, vLLM, and FLA external comparisons as acceptance criteria. The next observation point is the migration of same-family capabilities to Ascend (in-review Sparse MLA, KDA chunk series).

5.3 Hygon dual-line maintenance and distributed direction

  • Hygon simultaneously maintains v0.1.12-release (absorbing block-scaling patches) and the v0.1.15 mainline (upgrades merged and a release branch established), while advancing IPC collective communication on the distributed branch — the three-line structure of “old line for delivery, new line chasing upstream, new branch for distributed” is clear. If multi-card communication lands, Hygon will move from single-card adaptation into the multi-card system stage.

5.4 TileFoundry enters its external audit period

  • In the same window that the core refactor (instance slots #232, lowering contract #233) just landed, a third-party skills repo vendored TileFoundry into its workflow, listed emitter and runtime bugs, and delineated supported paths — the toolchain is beginning to undergo external auditing under the pressure of real use. A typical productization trajectory: after the chassis refactor comes interface contract convergence and public defect ledgers.
