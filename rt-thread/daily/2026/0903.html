一、内核与版本动态

1.1 主仓库合入 [lwp]：将 terminal/ 移出全局 CPPPATH

日期：2026-09-03（09:20 北京时间合并）　来源：PR #11776（合并提交 54e5164，TTLLDD 提交）

components/lwp/SConscript 此前把 ./terminal/ 目录加入全局 CPPPATH，本笔将其移除。全仓库核查显示：terminal 子系统头文件（terminal.h、tty_config.h、bsd_porting.h 等）的所有非限定 include 均来自 components/lwp/terminal/ 内部源文件，编译器引号形式查找即可满足，无需将内部目录泄漏到全局包含路径。这是 2025-11 议题 #10980「规范 CPPPATH 的使用」约定的最小化示范落地——组件不再把内部目录泄漏进全局 include 路径，属构建系统/include 卫生方向的小步推进。窗口内主仓库唯一合入，工作日早间合入节奏与近期一致，无大特性。

1.2 进行中：社区开发者提交 CAN 框架结构性重构 PR

日期：2026-09-02（13:21 北京时间创建，open、CI clean、非 draft）　来源：PR #11779

wdfk-prog（即昨日转正官方索引的 CANopenNode 移植包作者）提交 refactor[CAN] PR：对 Generic CAN Framework 及 STM32 bxCAN 后端做结构性重构（2 commits、8 文件、+2902/-1308），重新明确框架职责边界——Generic CAN 负责硬件资源管理、同步、ownership 与生命周期，发送缓存/重试/调度与协议 QoS 策略交由上层协议栈或应用自行决定。方案来源两条线索：8-26 特性请求 #11759（CANopen CiA 305 LSS Activate Bit Timing 运行时切换波特率需要 TX Full Flush 与 Hardware Abort 能力，已关闭）与 8-28 框架重构讨论 #11767（统一 TX Engine、Mailbox Ownership 与 Lifecycle，讨论关闭后 3 分钟即转本 PR）。两议题均已在窗口内关闭并汇集为本 PR，标签含 BSP: STM32 与 component: drivers/can。该 PR 将 CANopenNode 移植中暴露的底层能力缺口上升为框架层重构提案，目前待维护者评审，若合入将是 Generic CAN Framework 近年最大一次职责边界调整。
