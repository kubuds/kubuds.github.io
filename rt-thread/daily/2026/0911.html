一、内核与版本动态

1.1 RT-Thread v5.3.0 正式发布：自 v5.2.2 以来首个版本，覆盖内核 / 组件 / 设备模型 / 架构 / 工具 / BSP 全板块

日期：2026-09-10（18:05 北京时间发布）　来源：RT-Thread v5.3.0 Release（ChangeLog.md）

本窗口最重要的事件：RT-Thread 主仓库发布 v5.3.0 正式版本，这是继 2025-10-31 发布 v5.2.2 之后的第一个正式版本，间隔约十个半月，也是近一年多来规模最大的一次集成放量。版本由项目维护者 Rbb666 发布，变更日志（ChangeLog.md）新增 263 行，按 Kernel、Components、DM、Libcpu、Tools、Action、BSP 七大板块组织。

内核侧（Kernel）以正确性与健壮性修复为主：修复 IPC 与 LWP 等待路径上的超时唤醒归属竞态、线程被反复挂起时的延迟唤醒、禁止空闲线程被挂起、线程被他人删除时释放其持有的互斥量；线程 CPU 占用率改为按采样窗口增量统计；新增 8 位与 16 位原子操作支持；对象名长度断言改为安全截断；memheap 非法释放与 rt_smem_setname 空名处理加固；并新增控制台输出使能开关、导出中断钩子指针。

组件侧（Components）出现两处结构性新增：一是全新的时钟框架 clock_time，把时钟源与时钟事件分离，引入高分辨率定时器、启动时间辅助接口与外设定时器适配层，并替换原有的 ktime / cputime / hwtimer 实现，同时迁移架构、BSP 与 POSIX 时间集成；二是 ADC V2，具备会话管理、序列读取、电压换算与 FinSH 命令，并支持 DMA 流、最新帧与 FIFO 缓冲、定时器与比较器触发，与旧 ADC 驱动互斥。此外，串口 V2 新增 RX DMA 事件模式控制；DFS 新增 9PFS（用于与 QEMU 等虚拟机共享文件）并把 Elm FatFs 升级到 R0.16；网络侧新增可选 AF_UNIX 流式与数据报套接字（含 socketpair、SCM_RIGHTS 描述符传递）；WLAN 新增 WPA3、企业级认证、WAPI、OWE、DPP 安全模式定义；USB 更新 CherryUSB 到 v1.6.1；Rust 组件新增 ARM / AArch64 / RISC-V 目标检测与 SCons / Cargo 集成，并为线程、互斥量、信号量、消息队列、内存、时间与文件提供 Rust 封装。

设备模型（DM）是本次版本最大的结构性新增板块：扩展设备树与 OFW 支持（并在 Cortex-M 目标启用）、重构时钟框架并扩展 regulator / 电源域 / reset / 电源管理，新增动态电压频率调节（DVFS）、ARM SCMI 固件集成、硬件自旋锁与硬件缓存控制器、远程处理器消息（RPMSG）与可信执行环境（TEE）支持；VirtIO 升级到 1.2 并支持 packed queue、MMIO / PCI 传输，新增 9P、crypto、RNG、SCMI、SCSI 驱动；存储侧新增 UFS、DesignWare AHCI、通用 MTD 驱动与 NVMEM；网络侧新增以太网设备模型（MACB / DWMAC）与 IEEE 1588 PTP 时钟。

架构侧（Libcpu）与 RISC-V 直接相关的是：为 QEMU virt64 以及达摩院玄铁 C 系列 / R 系列处理器新增 SMP 支持，新增达摩院玄铁 C908X 平台支持，补齐 C908 的 Svpbmt 支持并修正 C906 / C908 的缓存属性与页表属性，修复 PLIC 中断处理顺序；Cortex-R52 侧则收进了本报告昨日记录的瑞萨 RZ/N2L 中断重复分发修复。

1.4 瑞萨 SCI SPI 运行时配置与传输错误修复合入（PR #11792）

日期：2026-09-10（16:23 北京时间合入）　来源：RT-Thread/rt-thread commits（PR #11792）

昨日报告中列为「新开并持续更新」的瑞萨 SCI SPI 修复，本窗口内正式合入：改动集中在 bsp/renesas/libraries/HAL_Drivers/drivers/drv_sci.c 单文件，两个提交合计 +254/-193（功能提交 +90/-41，随后一笔 clang-format 格式化 +164/-152），PR 09-09 17:25 创建、09-10 16:23 合入，历时约 23 小时，流转速度明显快于同属瑞萨方向、评审跨月的 klibc 与 clock_timer 两只长期 PR。

修复内容针对 RZ/N2L EtherKit 的 SCI SPI 回环排查发现的一组缺陷：RZ 分频接口把 false 当作分频结果指针传入且未使用 FSP 配置中的实际时钟源；运行时配置未可靠传递给 FSP、重复配置未正确关闭旧实例；配置过程把 RT-Thread 的位宽单位从 bit 误改为 byte；收发等待超时或出错后仍返回传输长度，导致调用方误判成功。方案为每条 SCI 总线保存持久的可写 FSP 配置副本、修正各分支分频调用、在重新配置前显式关闭已打开实例、保持位宽单位为 bit，并在超时或错误时关闭传输、清理事件与总线归属以便重试。该修复已随 v5.3.0 变更日志收录（Renesas 板块）。

3.1 软件包索引三笔更新：新增 Lely CANopen 包、CanopenNode 模块化 Kconfig 重构、参数存储自定义 backend（PR #2038）

日期：2026-09-11（11:09 北京时间合入）　来源：RT-Thread/packages commits（PR #2038）

窗口末尾（本报告采集前约 9 分钟）软件包索引仓库合入一笔 19 个文件 +2621/-1580 的集中更新（wdfk-prog 提交），同步三类 CANopen 与参数存储相关包的配置：

  • 新增 canopen-lely 包索引：把 Lely CANopen 的 RT-Thread 移植版加入 package index，提供 single-owner EV/IO2 运行时、RT-Thread CAN 集成、经典 CAN 与可选 CAN FD、自动运行时初始化、owner 线程配置、日志、启停配置以及可选的 CANopen 主站（Master）服务。其运行时以 LELY_NO_THREADS=1 方式工作，Lely 的 EV / IO2 / CANopen 对象由专用 RT-Thread owner 线程串行访问，异步 CAN、定时器与状态事件转交该 owner 处理。
  • CanopenNode Kconfig 模块化重构：把原先集中在 misc/CanopenNode/Kconfig 的配置按当前移植结构拆分，覆盖 core 协议配置、RT-Thread 运行时配置、存储配置、对象字典与 demo/test 配置、CiA 401 设备子协议、CiA 402 设备/控制器子协议以及各 profile 专属配置，并新增按 Kconfig 选择存储实现的 SCons 源文件选择。
  • autogen_parameter_manager 增加应用自定义存储 backend：新增 AUTOGEN_PM_BACKEND_APP_DEFINED 选项，选中时不启用包自带的 scalar backend，由应用提供强符号 par_store_backend_get_api()（必要时还可覆盖 par_store_backend_bind()）。原有默认 backend 保持不变，不影响既有工程。

加上 09-01 合入的 CANopenNode 索引，CANopen 协议栈在 RT-Thread 软件包层面已形成「Lely（面向主站与 EV/IO2 运行时）+ CanopenNode（面向从站）」的双栈选择，是工业现场总线与车载方向软件包化的重要补强。

3.2 厂商 BSP 全景（v5.3.0 版本级）：瑞萨、兆易创新、NXP、意法半导体、瑞芯微、树莓派、达摩院玄铁、芯来等

日期：2026-09-10（随 v5.3.0 发布）　来源：RT-Thread v5.3.0 Release 变更日志 BSP 板块

v5.3.0 的 BSP 板块覆盖面较广，可作为各厂商在 RT-Thread 上适配成熟度的版本级快照：

  • 瑞萨（Renesas）：新增 EK-RA6W1 与 RA8P1 Titan BSP，补齐 RA8P1 Titan 的 Cortex-M85 / M33 工程与 GPIO / 外部中断设备模型驱动，扩展 RA6W1 外设并改进 MDK 工程，修复 RA8D1 Vision Board 的 Keil 下载配置；驱动侧收录 SCI SPI 位速率与配置生命周期修复（PR #11792）、R7FA8M85 的 SDHI 卡检测、可配置 CAN FD 仲裁与数据速率、以及从 GPT 寄存器读取 PWM 周期与脉宽。瑞萨仍是本周期最活跃的厂商线。
  • 兆易创新（GigaDevice）：新增 GD32405RG 与 GD32VW553H-EVAL BSP，补齐 GD32VW553 的 UART、Wi-Fi、硬件 I2C、SPI、ADC、PWM、定时器与看门狗驱动，扩展 GD32F5 / H7 串口与 GPIO 支持。
  • NXP：新增 FRDM-MCXA366、FRDM-i.MX91 与 i.MX RT1180 EVK（Cortex-M33/M7）BSP，RT1180 支持多核启动、RPMsg-Lite、HyperRAM/HyperFlash、QSPI 文件系统、CherryUSB、NETC 与 EtherCAT 集成及 I2C DMA、CAN、SPI DMA、RTC、SDIO 驱动。
  • 意法半导体（ST）：新增 STM32F407 MICU、STM32H723 LXB Disco、STM32H723 DM-MC02 BSP，加入 ADC V2、共享 DMA 辅助层、硬件 I2C 轮询/中断/DMA 路径与 SPI 中断传输，改进 CAN 过滤与 FIFO 处理及 H7 CAN-FD 数据速率，新增 GPIO/EXTI 设备模型驱动。
  • 瑞芯微（Rockchip）：BSP 迁移到设备模型，新增 RK3528 支持，扩展 RK3300 / RK3500 平台配置并补齐 DVFS 与音频、显示、以太网、PCIe、PHY、存储、加密、多媒体支持。
  • 树莓派（Raspberry Pi）：新增树莓派 5（BCM2712 / RP1 设备模型）支持，并拆分 RP2040 / RP2350 BSP 布局。
  • 其他新增板卡：HC32F4A2 / HC32F467、N32H760 / N32H497 / N32H487、纳芯微 NS800RT7P65 NSSinePad（GPIO、串口、ADC、SPI、QSPI、I2C、CAN、RTC、定时器、EPWM、看门狗全驱动）、FT32F407XE、RDK S100；嘉楠 K230 新增 SPI、I2C DMA 与 GNNE 支持；QEMU / ZynqMP 侧扩展 AArch64 设备模型、启用 RISC-V SMP 并加入 ZynqMP A53 的 MACB 集成。
  • 达摩院玄铁（XuanTie）：新增 XuanTie XiaoHui C908X 平台支持，并为玄铁 C 系列 / R 系列处理器新增 SMP 支持，RISC-V 侧同时补齐 C908 Svpbmt 与 C906 / C908 缓存属性、页表属性修正。

4.1 睿赛德申报 2026 第八届金辑奖最佳技术实践应用奖，申报技术为程翧整车基础软件操作系统（09-11）

日期：2026-09-11（09:41 北京时间）　来源：盖世汽车（Google News 聚合条目）（2026 第八届金辑奖说明）

上海睿赛德以「程翧整车基础软件操作系统」申报 2026 年第八届金辑奖「最佳技术实践应用奖」，申报领域为汽车软件与人工智能，条目由盖世汽车发布。金辑奖由盖世汽车发起，聚焦「中国汽车新供应链百强」，2026 年第八届以「中国方案」向全球为年度主题，覆盖 ADAS/AD、智能座舱、智能底盘、车规级芯片、汽车软件与人工智能、动力总成电气化及充换电与热管理、车身及内外饰、新材料与先进制造、具身智能与跨界技术等赛道，评选维度包括企业申报、产业数据、专家评审与市场验证。睿赛德此前已于 2025 年获得第七届金辑奖「最佳技术实践应用奖」，本次为同一奖项的再次申报。

深挖：程翧是睿赛德面向汽车电子的整车基础软件产品线，2022 年以「程翧车载融合软件平台」发布并标志其进军车载操作系统市场，产品构成包括安全型实时系统 RT-Thread Secure Auto、微内核操作系统 RT-Thread Smart Auto、虚拟化系统 vmRT-Thread Hypervisor 与 vmBUS 统一消息总线，覆盖车身、底盘、动力、智驾与座舱等系统控制场景；其中多核 MCU 虚拟化为较新的技术点。睿赛德在功能安全上已通过 ISO 26262 ASIL D、IEC 61508 SIL 3、EN 50128 SIL 4 等认证，合作芯片企业包括英飞凌、NXP、德州仪器、意法半导体、黑芝麻智能、芯旺微等。本条属于品牌与产业评选类动态，未涉及窗口内的新产品发布或量产定点信息。

主线判断

  • 版本节奏：主线在 v5.2.2 之后约十个半月没有正式发版，本次一次性释放 v5.3.0，且发布当日即推进 v5.3.1 并回移 beta 修复，说明「发布正式版 → 主线续版本号 → 修复回移」的闭环已经成型，后续小版本节奏可能加快。
  • 设备模型（DM）是 v5.3.0 最具结构性的新增板块：设备树与 OFW、时钟与电源框架重构、DVFS、ARM SCMI、RPMSG 与 TEE、VirtIO 1.2、UFS/AHCI、IEEE 1588 PTP 集中落地，指向 RT-Thread 在 Cortex-A 与 RISC-V 高性能平台方向的定位强化，而非仅服务 MCU 场景。
  • RISC-V 侧：达摩院玄铁 C908X 平台与 C 系列 / R 系列 SMP 支持进入正式版本，与窗口内仍在评审的 c908 rt-smart / QEMU MMU 相关 PR（#11775）构成同一条演进线。
  • CANopen 生态成形：Lely（主站与 EV/IO2 运行时）与 CanopenNode（从站）双栈在软件包层落地，叠加主仓库 CAN 驱动生命周期重构在评审中，工业与车载现场总线是近期的持续性投入方向。
  • 评审消化节奏依旧分化：发布相关与文档类改动数小时内完成（#11795 约 36 分钟、#11792 约 23 小时），而内核、驱动与内存管理类长期 PR（#11228、#11313、#11689、#11772）仍跨周乃至跨月停留。
