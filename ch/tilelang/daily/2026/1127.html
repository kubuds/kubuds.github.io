今日重点：摩尔线程 MP31 一次抛出 14 笔 PR，低精度与集合通信同时补齐

tile-ai/tilelang-musa 在 11-27 凌晨 02:18 至 04:16 之间新建 14 笔 PR，编号从 #14 到 #27。这批提交全部以 v0.1.15+musa.1 为基础分支，并声明了堆叠顺序，#25 要求排在 #19 之后合入。

低精度是主线。#19 让 MP31 的 fragment-A SQMMA GEMM 合法化，并加上 188 KiB 共享内存护栏。#25 补上 MP31 原生 W4A16 SQMMA，覆盖 fp16/bf16 × int4 → fp32 与反向两种组合。#25 还改写了 sqmma.h，绕开 MUSA 5.2.0 头文件里 s4 被误写成 fp4 的问题。#20 打开 warp 专用 GEMM 的 FP8 TME 描述符。

访存与同步各占一批。#27 让 4 位权重的打包 UINT8 TME 载入可用。#18 给 TME 内核补退出时的 tme_flush()。#16 把 MP31 的 swizzle 索引改成元素单位，以保住向量化。#24 修 warp 专用 TMA 屏障，跨 squad 的部分同步被降到每 squad 的 128 线程屏障。#26 把消费者侧的多 warp AllReduce 降到 MP31 部分屏障。

语言面也在扩。#23 增加块内并行的 T.sort、T.argsort 与 T.topk，用双调排序模板实现，支持 int4 之外的六种 dtype 与任意非 2 的幂长度。#15 通过 murand 支持 T.rng_init 与 T.rng_rand。#21 增加 T.reduce_prod、两屏障多 warp 一维扫描与 mem-bound 的 TIR pass。#22 把 tl.enable_fast_math 接到 mcc -ffast-math。

验证侧落在 MTT S5000（mp_31）。#23 的排序用例 25 项全过，覆盖 MoE top-2/8、NSA top-64/512 与非 2 的幂长度。#25 另有低精度与累加用例。

来源： https://github.com/tile-ai/tilelang-musa/pull/25。

今日重点：主仓三笔全在昇腾，host-mapped 缓冲参数进入主线

tile-ai/tilelang 主分支窗口内只有 3 笔提交，全部带昇腾标签。这与此前缓存子系统、ROCm 修复的节奏不同，昇腾已成为主线的稳定输入源。

#3909 于 09:44 合入，给昇腾加上显式的 host-mapped 缓冲参数。此前 ASCEND 内核即使拿到已映射的 CPU 张量也会拒绝，调用方只能关闭张量校验。新路径沿用 #3802 的契约，走同一个 T.annotate_host_mapped_buffers(...) 接口。Cython 与 TVM-FFI 两侧都用 aclrtHostGetDevicePointer 验证映射，再传设备可见地址。dtype、形状、步长与执行设备的检查全部保留。

#4486 于 11:32 合入，修 #4429。触发场景是 nk=topk=960 的 FlashMLA 预填：每个 query 处理 15 个 KV tile，两个 query 槽交替，首个槽在 30 次循环后复用。旧实现给每对同管线站点按每个迭代距离各建一条边，单对站点可贡献 0 到 30 共 31 个距离。新实现按「源、目的、严格性」存不相交闭区间，两个区间复合仍是区间，于是能按批传播新覆盖的距离。

#4390 于 12:25 合入，把昇腾 CI 里的 PTOAS 改为从 PyPI 安装。CANN 9.2 镜像不动，先用镜像自带脚本卸载其中的 PTOAS 组件，再用 --upgrade --no-deps --only-binary=:all: 装最新兼容轮子。安装后校验 Python 3.12、x86_64、包与 CLI 版本一致，并确认 PTOAS、PTODSL、MLIR Python 模块与原生扩展都能从虚拟环境加载。安装或校验失败时跳过 PTO 后端示例与单测，并把步骤结果写进作业摘要。

来源： https://github.com/tile-ai/tilelang/pull/3909。

今日重点：TileFoundry 开 Apple ANE 目标，TIR 直出 HWX 容器

tile-ai/TileFoundry 新增在审 PR #369，标题写明 Apple ANE 的 codegen 链路。路径分三段：TIR → 任务描述符 → HWX 容器。该笔建立在 #361 已引入的 ANE 目标之上，是 TileLang 生态里第一个端侧神经引擎目标。

实现分两层。ISA 层给出寄存器位域图，覆盖 Common、L2、PE、NE、TileDMA 与 Kernel 六类块。任务描述符采用 RUN/MASK 包编码，并配套 load、store、compute-PE、compute-NE、conv、activation 六类原语。另有一套声明式公式与跨字段校验库，在构建期即以失败关闭的方式验证描述符。

代码生成层做发射器分派、逐 pass 序列化与 HWX 容器输出。容器是 Mach-O 格式，按其描述为逆向后从头实现，并对默认镜像做字消除。超出范围的 tile_height 与 tile_width 在编译期直接拒绝。

正确性上，提案称在已覆盖的算子范围内与苹果自家编译器的输出位级一致。

同仓同日合入 #368，修 #162 改名后遗留的问题。代码生成对仍为 ShardLayout 的屏障投射 tilefoundry::local，而该函数已改名为 local_tensor，编译到 nvcc 阶段即中断。修法是只为「整网格广播」的屏障取字，遇到分片屏障直接拒绝。理由是分片屏障给每个 warp 分配不同的字，而 CopyAsyncBulk 只从第一个 warp 的线程按 CTA 到达一次，其余 warp 会等一个永不完成相位的字。

来源： https://github.com/tile-ai/TileFoundry/pull/369。

一、核心项目进展

1.1 host-mapped 缓冲参数进主线，昇腾不再要求关掉张量校验

#3909 改在 Cython 与 TVM-FFI 两条绑定路径。两者都用 aclrtHostGetDevicePointer 取设备端地址，并把原始 dtype、形状与步长带到内核。C++ 绑定签名不变，改为按已有设备类型选择运行时查询。Cython 保留默认的 CUDA 解析器，只有昇腾提供可选解析器。CUDA 侧仍走 use_torch_stream()，共享设备选择逻辑未动。

只有「全 host 参数」的昇腾签名会显式安装原始 NPU 流。测试覆盖全 host 参数、自动分配的 NPU 输出与 NPU Graph 捕获三种场景。

1.2 InsertSync 改按区间传播依赖距离，31 个迭代距离不再逐条建边

#4486 只改 InsertSync 这一个 pass。此前对每个同管线站点对，实现按每个迭代距离各插一条边，并在构建依赖闭包时反复复合。新实现把可达距离存成闭区间，复合两个区间得到另一个区间，从而只传播尚未覆盖的距离。空隙与严格性都显式保留，距离 0 与 1 仍按原有的 epoch 域投射规则处理。

FIFO 工作队列改用 std::set，键为源、目的、两个距离边界与严格性，用于跳过重复的待处理区间。

1.3 昇腾 CI 改从 PyPI 装 PTOAS，CANN 9.2 镜像保持不动

#4390 的动机是 PTOAS 与 CANN 的发版节奏不同步。此前 PTOAS 随镜像固定，升级要改工作流。改后只要索引里有新版本就会被拾取，无需改 workflow 或更新既有依赖。

同一笔还调整了普通 SIMD 掩码的初始化，以适配新版 PTOAS。

1.4 在审 16 笔：PTO 向量化与正形状假设推进，T.reshape 静默 NaN 待修

主仓在审更新共 16 笔。PTO 方向有 #4523，把 T.Parallel 向量化到 PTO，覆盖条件分支与 lane 内均匀的串行循环。#4524 在 ptoas 里改用 vdiv，#4522 去重多内核 PTO 编译的辅助符号。

性能方向有 #4526，按缓冲区形状为正的前提删掉冗余保护。修复方向有三笔。#4519 补 examples/conftest.py 缺失的 default_target_is_cutedsl。#4520 修 from __future__ import annotations 下 @T.prim_func 装饰失败。#4521 让 bfloat16 标量 min/max 走 float 重载。

当日新开 issue 里最重的一条是 #4525。T.reshape 作用在 T.StridedTensor 上会丢步长并读到行间填充，输出静默变成 NaN，不报错。该条尚无修复 PR。

来源： https://github.com/tile-ai/tilelang/issues/4525。

二、多后端适配（昇腾 / 海光 / 摩尔线程 / 沐曦）

2.1 摩尔线程 14 笔成批提交，MP31 补 W4A16 SQMMA 与 188 KiB 共享内存护栏

14 笔 PR 覆盖五类工作：低精度 MMA 合法化、TME 访存与屏障、语言面算子、快速数学开关、以及验证用例。#19 是底座，其余多笔声明依赖它或与它同栈。

#19 的要点是 fragment-A 布局的 SQMMA GEMM 合法化，同时把共享内存上限定为 188 KiB，超限即拒绝。#25 在其上补原生 W4A16，并给出 int8/uint8 → fp32 的累加合法化：硬件侧用 int32 SQMMA 累加，再无损转 fp32。#25 还把 Hilbert2D 线程序号重排推广到非方形 tile，接口为 T.use_swizzle(..., order="hilbert")。

#21 新增 WarpFirstAllReduce、T.reduce_prod 与两屏障多 warp 一维扫描，另加一个按共享内存带宽建模的 TIR pass。#24 修 warp 专用 TMA 屏障，并把跨 squad 的部分同步降到每个 squad 的 128 线程屏障。#26 把消费者侧的多 warp AllReduce 也降到 MP31 部分屏障。

#14 补 int8/uint8/int16/int32 广播用的打包整型向量构造。#17 恢复 __launch_bounds__、annotate_min_blocks_per_sm 与 -O3。#18 给 TME 内核补退出时的 tme_flush()，#20 打开 FP8 TME 描述符并约束自动 TME 的 16 字节内框对齐。

语言面 #23 的排序族是本批最完整的一笔。实现按「原索引更小者优先」做严格全序，与 torch.sort(..., stable=True) 和 torch.topk 对齐。支持 float32、float64、float16、bfloat16、int32 与 int64，一维与二维，升降序，任意长度。缓冲覆盖 shared、fragment 与 global 三类。在 2 的幂长度上原地排序共享缓冲时不额外占共享内存。

2.2 昇腾子仓修缓存的适配器库路径，HF32 与 UB 列存储仍在审

tile-ai/tilelang-ascend 默认分支 ascendc_pto 窗口内 1 笔提交。#2002 于 14:51 合入，修 #1999 评审提出的问题：从磁盘缓存加载内核后，adapter.libpath 没有恢复，仍为 None。后果是依赖该路径在子进程重载动态库的测试，会在 ctypes.CDLL("None") 处抛 OSError。

修法是在 Cython 与 Ctypes 两个适配器的 from_database 里各补一行路径恢复，并新增回归测试。计算、同步逻辑与缓存命中策略都未改动。

在审两笔与计算相关。#2037 在 gemm_v0 里暴露 HF32 模式并扩充测试，#2025 修昇腾 UB 的列存储与 DMA 尺寸计算。

2.3 MLIR 昇腾把 CANN 版本差异移植到 master，L0 地址空间落在 mlir-dialect

#274 于 17:13 合入 master，与主仓 #4399 是同一份补丁，18 个文件完全一致。问题描述给出两个实证。其一，CANN 9.1 的跨步 GM↔UB 拷贝 API 会把 32 位块计数截成 16 位。其二，powf(-2.0f, 2.0f) 在 CANN 9.1.0 上返回 NaN。修法是生成代码继续用 SDK 函数名，把受影响的调用统一路由到兼容层，覆盖 DMA 块计数、矩阵拷贝参数、HF32 舍入模式、INT32 原子操作与标量 GM 读。

#252 于同日合入，但基础分支是 mlir-dialect 而非 master，因此不计入 master 的提交历史。该笔给 tl.alloc 增加 TL_L0A、TL_L0B、TL_L0C、TL_L1 四个地址空间。

在审侧，#261 增加 tl.vrelu 并给出 TL 到 HIVM 的下降与测试。#253 增加 reduce_sum、reduce_max、reduce_min 三个归约及其 HIVM 下降。

三、生态与采用方（TileOPs 算子库 / TileFoundry / FlashQLA）

3.1 TileOPs 十笔，三处 0.1.15 性能回收同日落地

tile-ai/TileOPs 主分支窗口内 10 笔提交，全部为性能或测试，无新算子。三条线都在回收 TileLang 0.1.15 带来的性能损失。

第一条是 dropout。#3181 报 16 位行的 dropout 自 0.1.15 起慢 13% 到 16%。原因是 T.rng_rand_float() 被 T.Parallel 向量化后，一个向量共用一次抽样。0.1.15 又把 16 位向量从 8 元素收窄到 4 元素。#3187 改为每个元素独立从计数器取 32 位 Philox4x32-10 值，高 16 位用线程首批抽样，低 16 位仅在高位与阈值相等时才补抽。该改动同时消除了向量内的掩码相关性，数值也从相关转为独立。

第二条是 W4A8 预填。#3172 在每个 tile 迭代开头给消费者 warp 补 T.sync_warp()。此前 ptxas 无法证明 warp 在 K 循环处已收敛，把环形缓冲的 stage 索引与 WGMMA 描述符留在向量寄存器里，每次 WGMMA 前复制到统一寄存器。结果 R2UR 从 20 涨到 52，四个形状慢 10% 到 13%。

第三条是 RoPE。#3173 把分阶段 RoPE 改成按 (tokens, sides) 网格发射，每块用一次一维批量写回整行。此前 8 KiB 的行被拆成 16 次 tensor-map 写，且每次查表都带越界保护。实测 gptj-6b 预填从 15.440 微秒降到 15.264 微秒。

3.2 DeepSeek-V4-Flash 预填去掉 RoPE 行拷贝与窗口环拷贝

#3186 改两处。压缩层的 RoPE 表按压缩比预存每个位置的余弦与正弦，压缩器预填不再给 RoPECosSinFwdOp 传一个每次调用都复制的跨步切片。预填写最后 window_size 行 KV 时，原先走 arange、取余、gather、scatter 四步，现改为两次切片拷贝。

测试侧新增 256 token 提示、两个完整窗口的用例，其环形写入从槽 0 开始。

3.3 Qwen3.8-27B 的 6 头查询组走上 warp 专用 GQA 内核

#3174 解决的是分组宽度受限。GQAPagedFwdWSKernel 此前把一个 KV 头的整个查询组塞进 128 行 tile，每头占 128 // group 行。这样只支持 1、2、4、8、16 头或超过 16 头，其余组合回落 gqa_paged_varlen_kernel。Qwen3.8-27B 的 6 头组正落在回落分支，它有 24 个查询头对 4 个 KV 头，head_dim 256。

新实现让一个 tile 只放一个头组，_tile_heads 取能整除查询组、且让每头占满 8 行 swizzle 原子的最大 2 的幂，对 Qwen 即 2。一个 KV 头的组按 slices 拆成多个头组，各自成为工作项，生产者加载 group_id // slices 这个 KV 头的 K、V 与旋转后的 key 列。

在审侧同日出现一个成体系的系列，共六笔：#3189 到 #3194，主题都是「跨步视图下原地读」。涉及 BMM 的 a 与 out、CausalConv1d 的 x、RMSNormGated 的 x 与 z、PagedKVCacheWrite 的 k 与 v 等六处。另有 #3195 把 Qwen3.8-27B 的 positions 每步只构建一次，不再逐注意力层重建。

3.4 MXFP4 分组 GEMM 改按每 CTA 的 tile 前缀找专家

#3177 处理任务定位的开销。共享的 task_walk 逐个专家前进，每步一次依赖的全局读，连续段上两次。每个 CTA 因此要为布局里所有专家付费，空专家也照付。

新增的 table_task_walk 让每个 CTA 把各专家的行 tile 数一次求和进共享内存。之后用 warp shuffle 扫描一段专家的和，专家数超过块内线程数时再让一个 warp 扫一遍各段总和。最后每个 warp 用一次 ballot 前进最多一个 warp 宽度的专家。

3.5 采样、嵌入、KDA 与 CUDA Graph 资格测试同日合入

#3184 处理 top-p 行概率为 1 的情形，改为整行直通并只取一次保留键。#3188 让宽嵌入调用在通过率允许时以两个 warp 的 CTA 单波完成，不再按每 CTA 一个 warp 的保守划分执行。

#3179 修值主序的 KDA 解码在状态接近 FP32 上限时发散，改为保持有限。#3175 给两个模型各自的解码步算子逐项做 CUDA Graph 捕获资格测试。#3176 修标题编辑后标签不同步，改为读 GITHUB_EVENT_PATH。

3.6 TileFoundry 修屏障广播的代码生成，分片屏障改为直接拒绝

#368 除修 local_tensor 改名遗留，还处理了两个坐标分支。它们同样会发射已不存在的函数，但当前无路径可达：#186 起类型推断拒绝在指针视图上带坐标，而所有 pass 都只从指针构建 TensorView。

五、趋势观察

第一，摩尔线程这一批 14 笔的性质不是补丁，而是把 MP31 后端一次性推到「低精度可用、集合通信可用、语言面齐全」。依据有三条。W4A16 与 int8 累加都在硬件指令层合法化。AllReduce 已有三套实现，含 warp 首、部分屏障与跨 squad 拆分。排序族直接对齐 PyTorch 稳定性语义。这套组合通常出现在后端准备承接推理算子库之前。

第二，昇腾已经把主仓变成常态化输入。窗口内主仓 3 笔全部带昇腾标签，且性质各异。一笔是 API 能力（host-mapped 缓冲），一笔是编译期复杂度（InsertSync 距离区间化），一笔是 CI 供应链（PTOAS 改从 PyPI 装）。同时 11 条昇腾新缺陷集中在 RNG 与 DeepGEMM，说明覆盖面已进入数值细节层。

第三，TileOPs 正在承担 0.1.15 的性能回归回收。三条线（dropout、W4A8 GEMM、RoPE）都由 0.1.15 的代码生成变化引起，且都以具体百分比或微秒数落地。这提示编译器侧的改动需要有算子级回归基线来兜住，否则损失会滞后一个版本才被发现。

第四，目标扩展到端侧。Apple ANE 的 codegen PR 若合入，TileLang 的目标面将从 GPU 与国产 NPU 扩到手机与平板的神经引擎。实现路径是把 TIR 降到任务描述符再打包成厂商容器。这与昇腾、摩尔线程走的「生成厂商 C++ 再编译」路线不同，是另一条落地方式。

第五，RISC-V 四源连续第二个窗口零变化。TVM 路线与 MLIR 路线都停在上一期引用，SOPHGO TPU 分支数也无增减。该方向仍处低位，暂不构成趋势。
