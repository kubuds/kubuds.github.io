  • PagedKVCacheWriteFwdOp（#2539）：新增分页 KV 写入算子——按调用方指定的物理槽位原地散射 K / V、跳过 -1 槽、以独立 K / V scale 量化 FP8 缓存；单个内核同时承担两种写入，token 数动态；保留 NaN、有限溢出与无穷按原生 FP8 转换饱和处理；工作负载同时校验已写入行与未触碰的缓存内容；与 FlashInfer 及 vLLM 对照验收；从 attention 包导出 PagedKVCacheWriteKernel。

3.2 TileOPs：foundry 性能三笔——W4A16 加载重排、sigmoid 免 IEEE 除法、SM89 扫描加宽（10-15）

日期：2026-10-15　来源：W4A16 先行加载（#2586）／ sigmoid 免 IEEE 除法（#2588）／ SM89 扫描加宽（#2574）／ TileOPs PR 列表

  • W4A16 权重先行（#2586）：GemmW4A16Kernel 原先在 packed 权重之前拷贝每个 K 瓦片的激活，warp 特化生产者按此顺序发射并逐级等待，权重从 DRAM 的加载实际晚出一个 K 瓦片；现在权重先行（其 stage 在解码读取后即释放）。8 行解码瓦片以一个移位替代三个（w4a16_dequant_word_one_shift 原位掩码奇偶半字节并以一次 FMA 居中，权重乘 1/16）。decode-long-k 达 marlin-fp16 的 1.047 倍（原 0.996 倍），8 行瓦片各行提速 2.5% 至 7.6%，prefill-mlp-up 快 5.7%（对 torch 反量化矩阵乘 0.992 倍，持平）；无行变慢。
  • sigmoid 免 IEEE 除法（#2588）：make_unary_regcopy 支持 evict_last 载入——整 16 字节向量的线程走 tileops::load16_evict_last，末块逐向量加守卫；仅 SigmoidFwdKernel 启用该路径（其余 37 个一元内核生成相同 CUDA，357 个内核逐 dtype 对照）。float16 sigmoid 改走 refined_reciprocal（__fdividef 倒数加一步牛顿、无分支），替代逐元素的范围检查与慢路径调用；float16 / bfloat16 结果与 torch.sigmoid 位一致，float32 保持 IEEE 除法。forward 输入走 vector_aligned，修复起始元素越过 16 字节边界时的错位地址错误。16M 行领先 torch-compile 1.020 倍至 1.042 倍；测试节点 +2。
  • SM89 扫描加宽（#2574）：既有 16 列预填扫描在 4096 至 16384 token 区间由 8 个值头扩展至 16 个值头（≤8 值头调用保持原策略）；共享同一扫描程序与构建身份，GDN 与 DeltaNet 受益、KDA 不变。完整清单 A/B 后 19 行受影响负载最终提速 2.5% 至 19.7%。
  • TileOPs 开放 PR 计 16 笔（上一期 17）；新开五笔：光栅持久瓦片（#2589）、GemmW4A8FwdOp（#2590，INT4 权重乘 FP8 激活）、只读分页 GQA FP8（#2591）、SM89 长预填 32 列扫描（#2592）等。

五、趋势观察

5.1 PTO 从「独立目标」走向「一等执行路径」

  • #3316 让 ascend 目标可以直接选择 PTO 执行后端，与窗口前的 #3474（环境变量目标选择、CI 双目标并行）及在审的 #3512 / #3514 / #3516 / #3511 一起，把 PTO 从「独立目标、单独链路」变为「Ascend 目标上的可组合执行路径」。与此相对，ascend 仓 #1900 揭示 dav-3510（A5）上的静默数值错误类问题开始被系统性捕捉——一端是接口收敛，一端是验证进入深水区，昇腾侧的工程化在两端同时推进。

5.2 注意力家族收口：长篇推理算子面补齐

  • 一窗合入 sinks（varlen 与分页）、双边滑窗、只读 RoPE、分页 KV 写入，加在审的只读分页 FP8 与 32 列扫描——TileOPs 的分页 / 长上下文注意力矩阵正在补齐，且以 FlashInfer、vLLM、FLA 外部对照为验收标准。下一个观察点是同族能力向昇腾的迁移（在审的 Sparse MLA、KDA chunk 系列）。

5.3 海光双线维护与分布式方向

  • 海光同时维护 v0.1.12-release（收块缩放补丁）与 v0.1.15 主线（升级已合入并立发布分支），并以 distributed 分支推进 IPC 集合通信——「老线保交付、新线追上游、新分支做分布式」的三线结构清晰。多卡通信若落地，海光将从单卡适配进入多卡系统阶段。

5.4 TileFoundry 进入外部审计期

  • 核心重构（实例槽 #232、lowering 契约 #233）刚落地的同一窗口，第三方技能仓就把 TileFoundry vendor 进工作流、列出 emitter 与运行时 bug 清单并划出受支持路径——工具链在被真实使用的压力下开始外部审计化。产品化的典型轨迹：底盘重构之后，是接口契约收敛与缺陷台账公开化。
