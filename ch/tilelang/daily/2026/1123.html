今日重点：TileOPs 三天五十笔合入，两个整模型由算子拼装完成

11-20 到 11-22 三天里，TileOPs 合入 50 笔，是同期组织内最重的一笔量。其中两笔把整个模型用公开算子拼了出来。

DeepSeek-V4-Flash 由 #3072 合入，作者 bigSheep123，11-22 20:29 进主干。models/deepseek_v4/ 把 43 层铺到指定 GPU 上，跑 batch-1 的 prefill 与贪心解码，MTP 层没有构建。配置侧拒绝模型不计算的每个设置，加载器拒绝读不全的 checkpoint。

验收对照的是 DeepSeek 官方 inference/model.py 的 torch 内核。测试取一个三层模型，按 Flash 宽度、每种注意力各取一层。用长提示与三 token 提示各跑一遍。

每层输出与 prefill、解码全程的 logits 要求落在参考自身 bf16 舍入噪声内。indexer 的选择要与官方 indexer 一致，两卡拆分要与单卡一致。

Qwen3.8-27B 的文本解码器由 #3112 合入，11-22 13:20 进主干。models/qwen3_8/ 提供 from_pretrained、分块 prefill 与解码、reset 与贪心 generate。batch 为 1。该模型在 Hugging Face 上的 model_type 是 qwen3_5。Qwen3.5-27B 与 Qwen3.6-27B 的配置值和张量名相同，因此三个 checkpoint 都能加载。

Gated DeltaNet 层走 CausalConv1dFwdOp、CausalConv1dUpdateFwdOp 与 GDNFwdOp。归一化走 RMSNormGatedFwdOp。全注意力层走 FusedQKNormRoPEFwdOp（交错 MRoPE，1 + w）、PagedKVCacheWriteFwdOp 与 GQAPagedFwdOp。之后再加一个 sigmoid 输出门。

加载器按层读 safetensors 分片，跳过 model.visual.* 与 mtp.*，其余读不了的张量直接拒绝。

两个模型的壳被合并了。#3119 让 DeepSeek-V4 与 Qwen3.8 共用一个 CausalLM 与一个 read_checkpoint，并声明加载后的张量逐位相同。同一笔还把两个采样内核收进一个索引折叠宏，生成的 CUDA 逐字节相同。两个加载器对缺张量的层改成抛 ValueError，不再是裸的 KeyError。

这条路径是先拆题后组装。11-20 上午，TileOPs 一次开了 14 条 DeepSeek-V4 工作项（#3057 至 #3068）。内容包括 FP8 indexer 打分与 top-k、packed KV 收集与稀疏索引、双 packed 缓存解码。

另有压缩器状态与 packed 缓存写入、融合的 QKV RMSNorm。两条 tracker 分别管在 H200 的 vLLM 里验 TileOPs、以及确认 SM90 MXFP4 后端与 TileOPs 的差距。两天后整模型合入。

来源： https://github.com/tile-ai/TileOPs/pull/3072 https://github.com/tile-ai/TileOPs/pull/3112 https://github.com/tile-ai/TileOPs/pull/3119

今日重点：TileFoundry 加入 Apple ANE 目标，第四类硬件带实测性能文档

#361 于 11-22 21:33 合入，作者 zhen8838，11-20 开出。它在 tilefoundry-apple 里加了 Apple Neural Engine 目标，形态照 Metal 目标（#354）：指令声明在 TIR，配一份 HIR，再降到 TIR。代码生成与运行时不在这笔的范围内。

硬件侧给了两份文档：apple.h14 架构与 apple.m2_pro.ane 设备。拓扑是一个 engine、一个单元，共享 gmem，engine 自有 smem（L2，容量未公开）。性能写的是一个实测值：fp16 16.71 TFLOP/s，测法为 3×3 卷积、256 通道、384×384。

指令共六条，都是 f16。分别是 T.ane.conv、T.ane.bypass、T.ane.pool、T.ane.unary、T.ane.binary 与 T.ane.reduce。每条带 capability、执行 mesh、hir_matches 与访问关系。另有 verify 规则，以及一个逐步舍入到 fp16、ties away from zero 的 torch 求值器。conv 同时承担 Conv2D 与通道在外侧的 MatMul，bypass 承担 C/H/W 转置、ReLU 与矩阵重排。

一条硬约束写进了文档：特征图的 W 大于 1 时，W 步长必须为 1，因为引擎没有元素步长。ConvertHIRToTIR 对 ANE 在 engine 区域内每条 T.ane.* 只发一次。

顺带改的是目标接口本身。Target 基类现在声明 capabilities()、documents() 与类属性 hardware，核心不再按名字读具体目标的属性。ane、metal、amx 三个目标都成了只有一个字段的冻结 dataclass，字段是设备文档的 ID 或路径。cuda 目标实现这两个方法，构造函数不变。

至此 TileFoundry 的硬件家族从三类扩到四类：CUDA、Metal、AMX，加 ANE。ANE 是这一类里第一个以「文档 + 指令 + verify 规则」齐全的形态进来的移动端推理引擎。

来源： https://github.com/tile-ai/TileFoundry/pull/361

一、核心项目进展

1.1 TVM 子模块跟进两笔：CodegenC 的 Let 绑定与缺驱动时的 ROCm 桩

tilelang 主仓窗口内合入三笔，其中 #4422 把 3rdparty/tvm 推到 tilelang_main@5fb5cb27。这笔带入上游的两处修正。

第一处是 TVM #95：InitFuncState 在 CodegenC 里清掉 Let 绑定状态。此前状态会跨函数残留，影响后续函数的绑定解析。

第二处是 ROCm 桩的行为。TVM #79 把 ROCMDeviceAPI 的存在性检查从 hsa_init() 改成 hipGetDeviceCount()。它期望没有 ROCm 运行时时返回非 hipSuccess。在 USE_ROCM=ON 加 hip_stub 的 Linux 构建上，hipGetDeviceCount 原先委托给 HIPDriverAPI::get()。libamdhip64.so 缺席时它抛 std::runtime_error，@requires_rocm 的收集因此在非 ROCm 机器上直接失败。本笔改为在库缺席时返回 hipErrorNoDevice。

同一笔把 hipGetErrorName、hipGetErrorString 一并降级处理，删掉不再使用的 HSA 桩与内置 hsa.h。改动 7 个文件。

来源： https://github.com/tile-ai/tilelang/pull/4422

1.3 新报缺陷集中在「编译过但算错」：流水化拷贝、向量化开关、fragment 对齐

主仓三天新开 11 条 CUDA 与 codegen 类 issue，过半属编译通过、结果错误。

#4423 是 NVRTC JIT 适配器在非连续 PyTorch 张量上给出静默错误输出，原因是缺 is_contiguous 检查。#4435 是 CUDA codegen 用 float4、int 强转读 fragment 数组却不做对齐，导致误读。

#4434 是 T.Pipelined(num_stages=2) 配 T.alloc_var 索引时结果错误，因为 codegen 把索引提到循环外。#4460 是 T.Pipelined 循环里读已拷贝瓦片的 continue、break 被发射到循环之后。

#4461 是 tirx.disable_vectorize 打断流水化的 fp16、bf16、int8 T.copy。它发出的是 1 或 2 字节的 cp.async。#4439 是打包的 FP16、BF16 T.fmul 会被收缩成 FMA，破坏舍入边界。

前两条已有在审修复：#4442 保留打包 T.fmul 的舍入边界，#4447 把本地数组对齐到 16 字节。

来源： https://github.com/tile-ai/tilelang/issues/4423

二、多后端适配（昇腾 / 海光 / 摩尔线程 / 沐曦）

2.1 MLIR 昇腾一天合入八个方言算子，一元算子抽出共用模板

11-20 一天，tilelang-mlir-ascend 的 mlir-dialect 分支合入八笔算子。前四笔是 #232 sort、#233 reshape、#234 arange、#235 concat。后四笔是 #236 flip、#237 not、#238 abs、#239 sqrt。

前五笔由 HadiaSaqib 提交。reshape 作为纯视图算子，降到 memref.reinterpret_cast。concat 是可变参数的 destination-style，沿静态轴拼接。arange、flip 各带 TLIR 与 HIVM 两侧的下降与测试。

后三笔由 Areeshh 提交，抽出了一套共用的一元基础设施。组件是 TL_UnaryOp 基类、verifyElementwiseUnary 校验、ConvertUnary<> 转换模板与 EmitUnary<> 生成模板。not 降 hivm.hir.vnot，abs 降 vabs，sqrt 降 vsqrt。

作者在提交说明里写明工作方式：每个算子各切一条从 mlir-dialect 当前末端拉出的分支，共用基础设施先在本 PR 内复制，先合的先赢，其余要小改 rebase。这是这批算子能在一天里连过的原因，也意味着合入顺序会带来返工。

同日该仓 main 另合一笔 RoPE 内核（#263）。main 自 11-04 起的静默到此结束。发版侧还有 #265 把夜间轮子发到 OBS，#266 把昇腾 NPU 的轮子测试接入 Dist 流水线。

来源： https://github.com/tile-ai/tilelang-mlir-ascend/pull/233

主仓三天新开 11 条带 [Ascend] 的缺陷。

950PR 上三条最具体：#4430 是 Split-K GEMM 在 28 核 950PR 上死锁，NUM_BLOCKS 32 超过常驻块数。#4432 是 do_bench 与自动调优在 950PR 上失败，aclrtDeviceL2CacheFlush 返回 207000。#4452 是大的 shared→shared reduce_sum 编译出空的内核二进制。

自动调度两条：#4436 是自动调度的 T.Kernel 把 UB→GM 存储在两个 AIV 上各写一遍且不插同步。#4441 是 AscendMGroupedTileScheduler 对落在组内的分组整块丢掉输出瓦片。

另两条是编译期：#4444 是参数或缓冲以 C++ 类型名（如 half）命名时生成代码破。#4429 是 InsertSync 在 flash-MLA prefill 的 nk、topk 取 832、896 等值时永不终止。#4453 是 flash attention 示例对不支持的形状抛无消息的 AssertionError。

社区索引页（TongmingLAIC/tilelang-riscv）的 main 停在 4499c2ae，窗口内无新 PR，表内无新增或移除项目。按既定口径，TVM 路线与 MLIR 路线分别表述，不合并成一条。

三、生态与采用方（TileOPs 算子库 / TileFoundry / topa / 采用方）

3.1 性能线三十一笔：GQA 解码合并提速一点二一倍，MXFP4 解码降到每八码九条指令

TileOPs 的 50 笔合入里有 31 笔带 [Perf] 标签，占六成。方向集中在 RoPE、索引、GEMM、MoE、逐元素、池化、归一化与注意力八处。

GQA 分拆解码的合并由 #3119 改：每个分片只称重一次、并行做，最后除以总和一次。单请求解码最多快 1.21 倍。同一笔把 16 位片上 softmax 改成先取 warp 最大值再求和，fp32 内核不动。

MXFP4 共享解码由 #3111 改：一次转完 32 位字里的八个 e2m1 码，一个掩码喂两个幅值置换，一次移位加两个字节置换放符号。每 8 个码从 11 条指令降到 9 条，解码出的字节不变。

该笔把差距量化了：prefill 行与 FP8 分组 GEMM 的差距就在 e2m1 解码。ncu 在 32k-up 上数出每瓦片步 2264 条 warp 指令对 909 条，其中约 1125 条在解码 warp 里。

GEMM 由 #3106 改。一波 float32 NT 网格、宽 128、两轴各两个以上瓦片时，选择器改用 coop2 瓦片并取 SMEM 能放下的最深环。128×128 基础瓦片退位。根因是 coop2 的两个消费 warpgroup 在环深追平基础瓦片的五级后会超车，而主分支把 coop2 封在四级；两瓦片同分时选择器原先偏向基础瓦片。

自评口径值得记下：多笔写「below bar」（验收线之下），同时注明每一行比主分支快。可见验收线看的是目标倍数，不是相对主分支的提速。

其余方向各有一到五笔。RoPE 五笔：宽调用按 SM 分 token、每行入共享内存、64 位索引、整数工作前移、去掉单头死边界检查。索引四笔：concat 行与向量、embedding 行瓦片、int32 id 保持 dtype。逐元素三笔：GELU、erf、16 位 tanh 压到满占用寄存器预算。注意力三笔：FP8 indexer 的 key-scale 符号无分支、DSAPaged 两路 bf16 key 拆分合进 CTA 对、paged GQA 的 RoPE 准备走 16 字节向量。另有池化两笔、归一化两笔、KDA 一笔、MoE 三笔。

在审三笔都指向同一批模型。#3099 收 GatedPoolCompress 在 DeepSeek-V4-Flash 解码上与 SGLang 的差距。#3097 收 HyperConnection 在解码与预填上与 TileKernels 的差距。#3101 让 DSADense 的行跑在常驻 CTA 上。

来源： https://github.com/tile-ai/TileOPs/pull/3119

3.2 部分后端不再让整套测试失败，未服务的算子记为未验证

#3121 新增 OpNotServedError，继承 OpNotAvailableError，带 target 属性。当所选目标没有为该算子注册内核构建器时抛这个错。

测试报告只在一种情况下把它记为未验证（跳过并列出）：异常点名的 target 等于启动时 --tileops-target 钉住的那个。测试自己后来设的默认值不算。同一错误点名其他 target 时仍判失败，例如派发测试里的假 target。

此前一个只提供部分算子的后端，用 --tileops-target 跑套件时会在每个未注册算子的测试上失败。原因是算子层只抛一个普通的 OpNotAvailableError。逐算子推进的后端因此用不了整套测试。

3.4 TileFoundry 的 autodiff 改为按 ModuleList 元素重算，dot 按寄存器序配对

TileFoundry 窗口内另合五笔。

#362 改 autodiff 的重算选择。原先 recompute 只按定义选，Layer:h 对每个 ModuleList 元素都算。峰值内存调优需要按层选（TorchTitan 的 block_overrides），因此新增 element_copies。带自己选择器的元素与其子树的副本区分开，元素不完全相同的 ModuleList 循环被切成若干同元素的循环。同笔还修了 --saved 的计数。原先把被保存的视图当自己的字节数，丢掉融合 qkv 的一个切片看起来像节省。现在 Saved.buffer 计实际保持活的缓冲，每个缓冲只计一次。

#364 改 T.dot 的操作数配对。它按寄存器索引配对，每个单元从最小物理步长往上编号。CUDA 运行时原先按 CuTe 索引配，两种序只在每个本地视图最多一个长度大于 1 的模式、或模式按最小步长排列时才一致。复现是一个按行存的 (2, 4) 块配 (2, 4) 参数时读到 a[l, 1, 0] 对 b[0, 1]。现改为两个操作数都按步长从最小往上的视图读，swizzle 保留，载入宽度取自重排后的视图；任一端不满足对齐时退到逐元素读。

#363 让分析器拒绝两个 CTA 无序可达的普通全局内存。#365 修 codegen，在布局的物理投影里写每个张量值。#360 把未标布局读成 Broadcast，并把 mesh 声明挪到模块类里。

来源： https://github.com/tile-ai/TileFoundry/pull/362

五、趋势观察

  • 验收单位从算子升到模型。两笔模型组装都拿官方参考实现当对照：DeepSeek 一侧用 inference/model.py 的 torch 内核，Qwen 一侧用 HF transformers 的 torch 路径。判据是 bf16 舍入噪声内的逐层一致，比算子级对齐更接近「可以替换生产栈」的证据。
  • 缺陷重心从「编译不过」转到「编译过但算错」：11 条 CUDA 新缺陷里至少六条属静默错误，昇腾侧则是编译成功、运行崩设备或整块丢瓦片。这类缺陷测试套能抓，编译期断言抓不到。
  • 后端扩张走「文档先行」：ANE 目标先给硬件架构文档、实测算力与六条指令的 verify 规则，代码生成与运行时明确写在不做范围。先把可验证的边界立住，再谈落地。
  • 半成品后端有了测试通道：#3121 把未服务的算子记为未验证而非失败。对逐算子推进的昇腾、海光路线，这是把测试套从「全绿才敢接」改成「按覆盖度计分」。
  • 代理流水线进入定价阶段：topa 十五个条目全在补代价模型的边角（常驻 CTA、多波网格、收集行、部分波）。性能提案由轮次产出后还要过一遍折价，这一步决定代理产出的 PR 能否进主干。
  • 昇腾两条线的重心互换：上周是 MLIR 铺方言、主仓做发版工程化；本期 MLIR 一天八个算子，主仓十一条新缺陷加七笔修复，落在正确性上。两条线节奏不同，但都要过同一个测试套。
