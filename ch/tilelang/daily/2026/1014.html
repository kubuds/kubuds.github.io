一、核心项目进展

1.1 主仓：ROCm 双笔——DeepSeek mHC 前/后内核与 safe-gated KDA 解码示例（10-13 ~ 10-14）

日期：2026-10-13、2026-10-14　来源：DeepSeek mHC（#3156）／ KDA 解码示例（#3249）

  • DeepSeek mHC 前/后内核（#3156，2 文件、+83/-6，合入于 10-14 凌晨）：mHC 前处理在 CUDA 上按 96 线程块内的 32 线程边界分工并采用 TF32 GEMM 输入；在 CDNA 上这会切开原生 64 lane 波前，且 TF32 不是 MFMA 的输入类型。HIP 路径改为在完整的目标尺寸波前上运行分割角色，并把 FP32 混合权重在共享内存中转 BF16 供 MFMA 计算；CUDA 侧保持原 96 线程 / TF32 布局不变，另补 gfx942 的前/后内核正确性覆盖（32 token 前处理、8 token 后处理等用例）。
  • safe-gated KDA 解码（#3249，+360/-0）：新增打包解码内核——消费卷积后打包 QKV 与原始门控输入（a、b、A_log、dt_bias）、FP32 状态池与按请求状态索引；执行 Q/K L2 归一化与 delta-rule 递归更新，原位改写指定状态槽并输出 [batch, 1, value_heads, value_dim]；负状态索引输出零且不改状态池。实现按维度参数化、不含模型名/架构分发，文档给出 GLM-5.3-Flash TP8 的专用化配置。

1.2 主仓：昇腾编译面两笔——SimdVF 多缓冲 T.fill（#3455）与 bisheng 临时文件清理（#3461）（10-13）

日期：2026-10-13　来源：SimdVF T.fill（#3455）／ bisheng 清理（#3461）

  • #3455（+247/-31）：昇腾 SimdVF 的 LowerFill 原先只支持整缓冲填充（各维须从 0 开始且范围等于缓冲形状）；多缓冲流水线中 MaterializeMultiBuffer 给缓冲加了版本维（如 [64] 逻辑缓冲变 [2, 64] 物理缓冲），循环内 T.fill 只需填当前版本槽位 [v:v+1, 0:64]，而被完整缓冲检查拒绝。本笔把处理对象改为实际填充区域，按区域起点与范围计算每个 VReg 数据块的写入索引，检查常量范围、连续性与 VReg 对齐，支持紧凑布局与显式 stride；补 3 例 NPU 测试（1D / 2D / 两阶段流水线多缓冲）。
  • #3461（+2/-1）：bisheng wrapper 建临时目录时未传 keep_for_debug，导致编译的 AscendC 源总是被删——而 nvcc、hipcc、PTO wrapper 均传 keep_for_debug=not env.should_cleanup_temp_files()。本笔对齐，使 TILELANG_CLEANUP_TEMP_FILES=0 在昇腾后端同样生效。

日期：2026-10-13　来源：masked FP8 分组 GEMM（#2521）／ DeepSeek 分组 top-k（#2535）／ MoE MMA 化重构（#2551）

3.2 TileOPs：SM89 四笔收口——GLA / DeltaNet 反向与 KDA 预填，加 GQA 修复笔（10-13）

日期：2026-10-13　来源：GLA 反向（#2546）／ DeltaNet 反向（#2547）／ KDA 预填（#2548）／ 紧凑逐行 GEMM（#2549）／ GQA 修复（#2550）

  • GLA 反向（#2546，+36/-27）：把块间 key 梯度计算提到 query 梯度之前，使精简程序在载入 h 前用完 dh——chunk 32、K=V=128 的默认共享内存从 114688 降到 81920 字节，落入 SM89 的 101376 上限内；补 FP16/BF16 用例。
  • DeltaNet 反向（#2547，+166/-113）：chunk 64、K=V=128 的三段程序落在 90112 / 98304 / 98816 字节内；显式状态缓冲视图把评审人报告的 147968 字节 w/u 分配降到 98816；缩短操作数寿命、键与逆矩阵在最后消费者后复用状态存储。
  • KDA 融合预填（#2548，+186/-63）：SM89 上启用 KDA 融合预填——128 维输入的紧凑共享内存调度把 256 线程分配从 182528 降到 101120 字节；仅在序列/头块数达到 SM 数时选用融合路径；新增四个公开 FP16/BF16 数值用例，并把过时的 2048 序列拒绝断言替换为数值检查。
  • 紧凑逐行分组 GEMM（#2549，+45/-11）：SM89 支持按排序专家 id 恢复段尾的紧凑分组 GEMM，复用现有 MMA 程序（含空专家与部分瓦片）。
  • GQA 修复（#2550，18 文件、+341/-173）：dense GQA 解码的 split log-sum-exp 改为 FP32 累加——bf16 在 64 至 128 区间步进 0.5，大分数下 split 混合最多偏差 0.23；autotune 改为对 forward 实际启动的程序计时（含 fused RoPE 路径），修正候选选择口径。

五、趋势观察

5.1 MoE：从成对拆分到成对落定

  • 窗口内 MoE 面连收两笔：masked FP8 分组 GEMM（对齐 deep_gemm masked 语义）与 DeepSeek 分组 top-k（对齐 vLLM grouped_topk）同日合入，加上紧凑逐行布局统一进 MMA 内核——TileOPs 的 MoE 覆盖从「算子逐个补」转入「按模型配方收口」，DeepSeek-V3 / Qwen3-235B / Kimi-K2 负载成批入册。在审侧同主题（gpt-oss swigluoai 专家、permute-align、专家搜索跳过）持续加厚，MoE 是当前 TileOPs 权重最高的方向。

5.2 foundry 性能批进入日更节奏

  • 一天 8 笔 foundry 性能合入加 8 笔新开：GEMM（瓦片重排、联合选择、单条 WGMMA）之后，池化、归一化、归约、RoPE 全面铺开，且每笔都带对照基准（torch-compile / cuBLASLt / quack）。单人作者的日更节奏说明：TileOps 的性能工程已从「重点算子攻坚」转为「全算子逐日刷榜」，残余落后面（MoE 四行、部分 16 位除法行）被逐笔记录在案。

5.3 ROCm：DeepSeek 新架构内核的第三条收笔线

  • 继 NSA 前向/解码与 flash-decoding 瓦片（10-12 ~ 10-13）之后，本窗口再收 mHC 前/后内核与 KDA 解码示例——ROCm 线连续第三日有合入，且主题高度集中于 DeepSeek 系新架构（NSA、mHC）与 GLM-5.3 推理。技术债务（CDNA 波前尺寸、MFMA 输入类型、LDS/VGPR 预算）逐笔清偿的方式表明：ROCm 支持正从「跑通」转向「与新架构发布同步」。

5.4 在审队列继续变厚，发布静默期的底盘增长
