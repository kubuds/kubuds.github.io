今日重点：TileFoundry 同日落地 Metal 目标与自动微分

11-18 一天里 TileFoundry 合入两笔平台级改动。#354 新增 Apple Metal 目标，#355 新增自动微分。前者把编译流程延伸到 Apple GPU，后者让框架自己生成反向传播。两笔都不产出可运行的内核：Metal 只做到 TIR，自动微分只生成 HIR 模块。

Metal 侧新增 metal.Target("apple.m2_pro.gpu")。拓扑为 threadgroup 到 thread。硬件参数写在 TOML 里，并附公开来源。能力表直接采用 27 个 MSL 原生函数名。

T.metal 下共九个指令算子。矩阵类为 ldmatrix、stmatrix、matmul 与 mma。归约与乱序类为 reduce、prefix、shuffle、shuffle_fill 与 ballot。一次调用覆盖 G 个 SIMD group，quad group 用同一组算子在宽度 4 的 mesh 上表达。

每个算子一个文件。typeinfer、access 与 evaluator 规则写在同一文件内，布局用命名常量。MSL 不规定矩阵的 lane 映射，作者在 M2 Pro 上实测后写入规格。HIR 经 hir_matches 匹配。fragment 操作数上的 MatMul 落到 matmul，Reshard 在内存与 fragment 之间落到 ldmatrix 与 stmatrix。该笔取代早先的 #294，后者因目标接口重组无法 rebase。

自动微分侧新增 differentiate(module, wrt, recompute)。它返回 <Name>Forward 与 <Name>Backward 两个模块。前向返回结果和一个 saved 元组。反向接收结果梯度与 saved，按 wrt 逐个返回梯度。

反向规则按算子写在各自文件里，经新增的 interfaces/autodiff 注册。覆盖范围是内置 Qwen 模型的全部算子类，另加 ReLU 与 Log。支持兄弟与子槽调用、元组参数、MeshRegion，以及迭代次数静态可数的循环。

循环只堆叠每次迭代变化的值。只被归纳变量、捕获与常量用到的量在反向重算，因此层循环不复制权重。梯度布局沿用 DTensor。

来源：https://github.com/tile-ai/TileFoundry/pull/354。

今日重点：TileOPs 一天 23 笔合入，FP8 量化链补齐、两条性能欠账当日关闭

11-18 的 TileOPs 主分支落下 23 笔合入，从北京时间 10:17 持续到 21:50。主线是 FP8：逐 token 分组量化、短行 GEMM 流式、paged decode 重写、WGMMA 原语化四笔同一天进主干。

FP8QuantPerTokenGroupFwdOp 起 UE8M0 尺度（#3026）。输出与 DeepSeek-V4-Flash 的 act_quant(x, 128, "ue8m0") 逐位一致，尺度用 float8_e8m0fnu 存储。新增 inplace 伪量化，模型里带步长的 kv[..., :448] 不必先复制。

UE8M0 路径用 bfloat16x2 做归约与缩放，并去掉饱和 e4m3 转换前的 clamp。对照实现是 vLLM 的 per_token_group_fp8_quant，DeepSeek 与 TileKernels 的数值在注释里给出。

FP8 paged GQA decode 内核被整体重写（#2997）。每个 CTA 拿一个请求的打包行、一个 KV 头与一段 key。每个 FP8 key/value tile 只解宽一次，TMA warp 负责拷页。上限来自共享内存：H200 上 8 行 tile 可服务 44,287 个请求，64 行 tile 为 33,023 个。

短行 FP8 改走 64 行块流式（#3010）。一个生产 warpgroup 通过深 TMA 环搬 b，一个消费 warpgroup 把每个 128 宽 K 步的 FP8 WGMMA 部分和加到 float32。

主分支原来把 8 或 16 行补成 64 或 128 行 tile。这样 160 个 tile 落在 132 个 CTA 上，或走 split-K。实测只有 DRAM 峰值的 31% 到 52%。

同一批还有两笔收尾。#3030 把 FP8 流每步的四个 k32 WGMMA 改用 TileLang 原语发出。dense_wgmma_helper.h 随之删除，只有该内核使用的 TrailingFence 模板参数一并去掉。#3029 修共享内存记账：尺度缓冲原先按原始字节相加，未计 1024 字节对齐。m=16、n=163840、k=3584 的形状因此在启动时失败。

两条性能欠账同日关闭。#3023 重写 TopKSelect：行数少于 SM 数两倍的调用走寄存器内核。它一次全局读一行，4096 桶直方图定阈值；长行走 radix，一次 16 字节装四个 key。三条 decode 行从落后 vLLM 约 2 倍变成领先 1.22 到 1.34 倍，关闭 #3016。

#3022 让 MLA cache 每行按 16 字节向量拷，最多 1024 线程。主分支把拷贝交给布局推断，448 宽 latent 每线程变成 7 次 2 字节标量访问。这是 DeepSeek-V4-Flash decode 落后 vLLM 的直接原因。

来源：https://github.com/tile-ai/TileOPs/pull/3026。

一、核心项目进展

1.1 主仓 CPU 后端补两个逻辑归约的串行降载：any_of 与 all_of

#4389 给 CPU 后端补上 tl.any_of 与 tl.all_of 的专用降载。此前这两个算子无法走 CPU 常规管线。实现新增 LowerCPUAnyAll pass，插在 LowerTileOp 之前。降载为按行主序的串行扫描，并带短路：any_of 命中真值即停，all_of 命中假值即停。

空归约取标准单位元：any_of 为 false，all_of 为 true。数值元素按非零转真值，浮点与 bfloat16 的 NaN 视为真。while 条件里的归约在每次条件判断时重新初始化并重扫，语义与原先一致。该 pass 同时暴露给 CPU 的 Python 变换接口。

来源：https://github.com/tile-ai/tilelang/pull/4389。

1.2 topk 回归测试给 Z3 设资源上限，压掉 CUDA CI 上的超时

#4407 处理 test_topk_candidate_overflow 在 CUDA CI 上的超时。原因是化简阶段发起了代价高昂的 Z3 查询。修法是在该测试加载内核时设置 arith.z3_rlimit 为 100，保留原有其它 JIT 选项。改动只作用于这条回归测试。

作者在本地对 topk 的四个特化生成 TIR，确认设限后 Simplify 能完成。作者同时注明：本机没有 CUDA 代码生成，也无可用的远程 GPU。完整编译耗时与 GPU 正确性均未验证。

来源：https://github.com/tile-ai/tilelang/pull/4407。

1.3 昇腾自调优测试移除跨 NPU 探测，避免污染后续用例

#4401 删掉 set_autotune_inputs 测试里的 other_npu 分支。该分支为判断运行时是否支持设备间输入对齐，会执行一次跨 NPU 拷贝。在部分 Torch-NPU 与 CANN 组合上，这次拷贝会中止 NPU 上下文。

捕获 RuntimeError 后跳过用例并不能恢复上下文。同一 pytest 进程里后续无关用例会跟着失败，故障表现因此依赖执行顺序。删掉后仍保留三类覆盖：当前 NPU 上捕获的输入留在当前 NPU、CPU 上捕获的输入搬到基准设备、传入张量须与基准设备一致。

来源：https://github.com/tile-ai/tilelang/pull/4401。

1.4 CUDA Tile IR 后端 RFC 重新提交：只转换 Tile IR 能表达的部分

#4402 与 #4403 提交了 CUDA Tile IR 后端的 RFC，中英文各一份，放在 docs/compiler_internals/tileir/。目标是从 TileLang 程序生成 CUDA Tile IR，交给 tileiras 编译与调度。布局、流水、warp 特化与指令选择都由 tileiras 决定，并按硬件代际优化。

后端只转换 Tile IR 能正确表达的语义。转换不了的语义直接报编译错误并拒绝该程序，不追求与现有 CUDA 后端完全兼容。作者给出的收益是：不改内核、不手写架构相关调度，仅靠自动调优就能拿到不错性能。

这版是对早先 #3247 的重做。评审指出旧实现 try-catch 过多、按见过的形式逐个降载、另建一套 IR，并用约 1.85 万行 Python 写 pass。新 RFC 针对这四点重新设计，PR 目前为草稿，讨论放在 #4403。

来源：https://github.com/tile-ai/tilelang/issues/4403。

二、多后端适配（昇腾 / 海光 / 摩尔线程 / 沐曦 / Sunrise）

2.1 MLIR 昇腾 mlir-dialect 分支一天合入 tl.shl、tl.shr、tl.cast

MLIR 昇腾仓的合入落在 mlir-dialect 分支，不在 main。该分支头在 11-18 从 06:23 推进到 08:47（UTC），一天合入三个 TLIR 算子。

#211 加 tl.shl，降载到 hivm.hir.vshl，复用已有的 NpuirShl 助手。#212 加 tl.shr，只支持 i16、i32、i64，round 为布尔属性且默认 true。该笔如实写明一处已知不匹配：rhs 按张量操作数建模，而 HIVM 的 vshr 有 ScalarOnlyHWTrait<1> 约束。根因在 NpuirShr 与 npuir_shr 的构造器不接受标量，留作后续。

#214 加 tl.cast，round_mode 限定在 round、rint、floor、ceil、trunc、odd 六种。该笔还改了一处方言级设置：TL_Dialect 增加 usePropertiesForAttributes = 0。原因是 tl.cast 是该方言第一个带非操作数属性的算子，走 ODS 默认的 Properties 生成会产出损坏的 CastOp。三笔都带 FileCheck 测试，测试取自真实捕获的输出。

来源：https://github.com/tile-ai/tilelang-mlir-ascend/pull/214。

2.2 MLIR 昇腾在审：tl.vrelu、tl.abs、tl.or、tl.xor 与 RoPE 内核

在审的 TLIR 算子还有四条。tl.vrelu 见 #261，tl.abs 见 #238，后者降载到 hivm.hir.vabs。tl.or 见 #225，tl.xor 见 #228。四笔都按「方言算子 + TIR 降载 + HIVM 转换」的同一套流程推进。

#263 走另一条路，直接加旋转位置编码内核，不再补单个算子。另有 #260 把 harness 里的 ascend-mfu 技能换成 ascend-roofline。新技能用一套 Cube/Vector 模型给出峰值、计数、roofline、MFU、BWU 与硬件参考。其 FMA 探针在该设备与该构建下标定到 26.3 TFLOPS，为标称 30 TFLOPS 的 88%。

来源：https://github.com/tile-ai/tilelang-mlir-ascend/pull/263。

2.3 海光单笔汇总十二项修正，覆盖 intrinsic、精度与整数向量

海光仓窗口内只有一笔合入（#27），内容却覆盖十二个方向。intrinsic 侧修 hexp 调用歧义、cos 与 sin 的分派。精度侧修 fp64 截断失败与 __builtin_bit_cast 尺寸不等。向量代码生成侧修 shuffle 降载，并打开整波 shuffle 归约。

新增能力包括：用 hipRAND 支撑 rng 操作、缓冲区载入重基、cache_warmup intrinsic。另有若干处收尾：8 位整数向量广播、运行期迭代次数的流水 epilogue 展开、shuffle 掩码防护、FP4 代码生成的顺序修正。CI 侧钉住 NumPy ABI。提交署名同时出现两位海光工程师。

来源：https://github.com/tile-ai/tilelang-hygon/pull/27。

沐曦仓窗口内 main 无提交。动静集中在开放的 #13 与发布分支：release/v0.1.12-musa.5-source 分支存在，#13 用于发布 v0.1.12+musa.5 源码与 MUSA 文档。摩尔线程侧主仓同样无新提交。

来源：https://github.com/tile-ai/tilelang-sunrise/pull/11。

三、生态与采用方（TileOPs 目标清单 / TileKernels / topa / 文档站）

3.1 mHC 两算子退场列为公开 API 破坏，HyperConnection 三算子接棒在审

#3021 删除 MHCPreFwdOp 与 MHCPostFwdOp，连同内核、manifest 条目、workload、基准与测试一起移除，按 #2796 的计划执行。DeepSeek-V4-Flash 与 GLM-5.3-Flash 改用 HyperConnection 的 pre、post、head 三个算子。mhc.expansion 这个 manifest 原语一并删除，只有被删算子用到它。

该笔在 scripts/ci/api_compat_allow.txt 里登记为经评审的公开 API 破坏。该文件用于登记经评审的接口删除，删除决定需在审查中确认。

接棒的三个新提案已在审：#3032 加 pre、#3035 加 post、#3039 加 head。另有 #3036 为 FusedTopKFwdOp 加 DeepSeek-V4-Flash 的 sqrt-softplus 与哈希路由。#3038 为 DSADenseFwdOp 加 attention sink 与仅索引选择。这一组改动指向同一件事：按 DeepSeek-V4 的实际结构重排序列建模与注意力接口。

来源：https://github.com/tile-ai/TileOPs/pull/3021。

3.2 七条性能目标 issue 把「距最快库」写成可验收清单

窗口内新开七条性能目标 issue，每条都带硬件、形状与目标。#3018 盯 GQA 变长在头维 72 的视觉行上落后 FlashAttention 3 的差距。#3019 盯 MLA cache 写入落后 vLLM 的差距。这两条的对应修复分别是 #3023 与 #3022，其中 #3022 当日关闭了 #3019。

#3037 给出 DSADense 的完整对照表：H200 跑 1500 MHz，bf16 稠密峰值约 811 TFLOPS。CSA 各行达到峰值约 58%，原因是每对的 softmax 与下一对的 key 收集夹在两次矩阵乘之间。HCA 的 4k 行付了 64 key 块的代价，160 个 key 按 192 个算。

#3031 盯 HyperConnection pre 在 decode 与中等序列上落后 TileKernels 的差距。#3034 盯 GatedPoolCompress 的 decode 行，目标是在该形状上达到 SOTA。

来源：https://github.com/tile-ai/TileOPs/issues/3037。

3.3 TileKernels 对照计时提案：跑测镜像仍钉在 tilelang 0.1.12

#3028 提出把 DeepSeek 的 TileKernels 加进基准对照，让 DeepSeek-V4 的行直接用 DeepSeek 自家内核计时。障碍在版本：TileKernels 要求 tilelang 不低于 0.1.15，而跑测镜像钉在 0.1.12。当前没有任何基准能导入它。

提案给出三条对应关系。FP4QuantPerGroupFwdOp 与 FP8QuantPerTokenGroupFwdOp 对 per_token_cast。SiLUAndMulFwdOp 对 quant.swiglu_forward。验收条件是这些基准在 CI 里真正计时到 TileKernels，并由夜间记录为对照。这解释了为何同日两笔量化提案的说明里，TileKernels 的数值只能在注释中给出。

来源：https://github.com/tile-ai/TileOPs/issues/3028。

3.4 topa 一条命令跑完一轮评审，GPU 只在计时期间独占

topa 合入 #41 与 #43，把评审做成可循环的轮次。#41 让每次 PR 变更触发一轮新尝试：新的 head 走完整评审，其余只做复查。只有 PR 未变且仍开放时才发布结果。GPU 侧新增按卡加锁的 topa-bench，只在计时期间独占一张卡，其余时间让给其它轮次。

#43 把三步流程压成一条 topa review <PR>。评审意见固定为三条单句要点：问题、复现、修法。同一 PR 的评审目录保留 worktree 与 posted.json，第二次评审只在本地落后于 GitHub 时才取回。评审轮次的无变化等待从 60 分钟放宽到 10 小时。

两笔之外，topa 在窗口内新开 10 条 issue（#35 至 #46）。它们都是带 fix(...) 标题的可执行工作项，方向集中在 roofline 定价。包括按 CTA 的波次算 makespan、按写入行数为 scatter 定价、把常驻 CTA 计入网格。这些是流水线给自己排的下一批任务。
