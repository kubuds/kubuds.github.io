一、核心项目进展

1.1 主仓：ROCm 双笔——DeepSeek NSA 前向/解码与 flash-decoding 可行瓦片（10-13）

日期：2026-10-13（合入于北京时间凌晨）　来源：ROCm NSA（#3152）／ ROCm flash-decoding 瓦片（#3149）

  • DeepSeek NSA on ROCm（#3152，+111/-2）：gfx942 波前尺寸为 64，TileLang 拒绝小于波前的 HIP block，而两枚 NSA 示例硬编码了 32 线程；本笔为前向与单 token 解码内核选择单个 64 lane 波，保留 CUDA 现有 32 线程启动配置，并补 gfx942 上因果前向与单 token 解码的正确性覆盖（对照 PyTorch NSA 参考，FP16、16 Q 头 1 KV 头、序列 64）。
  • flash-decoding 瓦片自适应（#3149，+82/-5）：gfx942 上 128x64 瓦片的生成核需 66048 字节动态 LDS（超 65536 设备上限）并触及 256 VGPR 天花板，导致启动报「invalid argument」；本笔在启动前检查生成的 HIP LDS 与 VGPR 占用，仅超预算时回退既有 64x64 瓦片（不按设备名硬编码），CUDA 路径不变，并加入 gfx942 运行时回归。

1.2 主仓：thread_storage_sync 精确线程边界（#3291）并修复 #2954（10-13）

日期：2026-10-13　来源：精确线程边界（#3291）

  • 为 thread_storage_sync 计算精确线程边界（4 文件、+292/-96），作者核实 #2954 由本笔修复；新增用例验证「等价的部分线程 guard 归约到同一 barrier」，并附 SM89（4060 Ti）上的前后编译产物对比。

1.3 主仓：Autotune 结构化试验报告、CodeRabbit 自动指派与测试规范文档（10-12 ~ 10-13）

日期：2026-10-12、2026-10-13　来源：试验报告（#3393）／ CodeRabbit 自动指派（#3487）／ 测试规范（#3489）

  • Autotune 试验报告（#3393，+98/-7）：新增实验性 AutoTuner.run(on_trial=...) 观察者接口（对应 RFC #3375），逐试验输出配置索引、JSON 配置、结果、时延、验证标签与限量错误文本；回调在聚合线程、共享缓存锁之外执行；报告/序列化出错只关闭该次报告、不影响调优，且不改动候选生成、超时与缓存身份。作者注明「回调 vs 固定 JSONL 工件」仍是开放 API 决策。
  • 评审护栏（#3487，+1/-1）：CodeRabbit 的 reviews.auto_assign_reviewers 置为 true，使其真正发出 review 请求（此前仅在走查中列出建议），11 条 reviewer 规则与顺序保持不变。
  • 测试规范（#3489，8 文件）：新增 Testing Style Guide——何时依赖现有覆盖、何时最小扩展、何时新增聚焦覆盖；tilelang-cpp-style 更名 tilelang-dev-guide，C++ 规则转为按需参考，CONTRIBUTING 精简并挂链。

3.2 TileOPs：foundry 性能批——NSA 持久 CTA、W4A16 GEMM 与 16 位除法（10-12）

日期：2026-10-12　来源：NSA 持久 CTA（#2531）／ W4A16 GEMM（#2534）／ 16 位除法（#2543）

  • NSA 压缩持久 CTA（#2531，+391/-2）：SM90 上 NSACompressedVarlenFwdOp 换用新核 NSACompressedFwdVarlenTMAKernel——旧核按（token, KV 头）一枚 32 线程 CTA、逐 token 重载压缩 K/V；新核 512 持久 CTA，每 CTA 步行 64 行瓦片（4 token × 16 头），查询经双 stage TMA 环、请求 K/V 块常驻共享内存，QK 以 n=16 SS WGMMA、PV 以 n=64 RS WGMMA，O 在 QK 读完后经 TMA 连同 log-sum-exp 出；每 SM 驻四个 48KB CTA。
  • W4A16 GEMM（#2534，+24/-0）：_legal_configs 限制 K 瓦片不超过 K、环深不超过 K 的瓦片数，K<512 不再填充零；single-tile（K=128）与 multi-tile（K=256）行改用 8x64 瓦片配 128/256 宽 K 瓦片（两 stage），领先 torch 反量化 matmul；其余 13 行配置不变，3 行仍落后（作者自列局限）。
  • 16 位除法（#2543，9 文件）：Reciprocal 与 bf16 sigmoid 从 IEEE float32 除法换到 __fdividef 快速除法（bf16 用范围缩放版），16M 行 fp16/bf16 时延 17.86 / 17.79 微秒，为旧版 1.02x、torch-compile 的 0.991x / 0.995x。

日期：2026-10-12　来源：单瓦片解码态加载（#2538）／ GLA 预填状态跳过（#2540）

五、趋势观察

5.1 ROCm 补课：设备预算感知的两笔修正

  • 本窗口两笔 ROCm 修改指向同一主题——「按设备现实自适应」：gfx942 的 64 lane 波前（#3152）与 LDS/VGPR 预算（#3149）。两者都在用例侧（examples）修正，未触及核内生成策略，说明 ROCm 支持仍处「跑通并加回归」阶段；与主仓近期 SM121、SM89 的多代并修合流后，TileLang 的后端拓扑正从「英伟达优先」转向「多设备同时维护」。

5.2 SM89 成为第二平台：单日 6 笔合入加 4 笔在审

  • TileOPs 一天内 6 笔 SM89 合入（注意力预填/解码、线性注意力、Norm 全覆盖）加 4 笔 SM89 在审；RTX 40 系与 L40 / 6000 Ada 级工作站在算子库侧成为与 Hopper 并列的常态目标。评测侧同步（夜间底盘 +10 项），SM89 的正确性覆盖正从「能编译」走向「有回归」。

5.3 昇腾迁移线转入正确性收尾

  • NSA 前向/反向两笔大迁移合入（合计 48 例分层测试）、缓存三分与 cross-warp allreduce 分组修复接续——昇腾线的重心从「示例与算子移植」转到「正确性、缓存语义与编译可用性」的收尾审计；#3469 修复后立即出现社区回馈的正确性修复（#3494），协作回路运转正常。

5.4 发布静默期的底盘增长

  • 主仓自 09-30 v0.1.15 后无新发布；组织开放 PR 计 507 笔（上一期 498 笔）、单窗口新开 41 笔，合入 20 笔——「合入闸门收紧、在审队列变厚」的结构延续。TileOPs 的 SM89 扩张与夜间底盘 +10 表明：正式版本虽静默，合入与评测两条线的「静态准备」仍在积累，发布窗口临近的判断不变。
