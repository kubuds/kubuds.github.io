一、核心项目进展

1.1 主仓：NaN 传播修复双线合入，两个缺陷单关闭（09-24）

日期：2026-09-24　来源：#3273／#3270／#3205／#3024

  • #3273（北京时间 17:03 合入）：为不支持的归约 NaN 传播 dtype 增加编译期报错——诊断信息给出操作名、支持的输出类型与实参 dtype；校验挂在原生 ReduceOp 构造器内，跨本地归约、碎片归约与写回累加统一持有累加器 dtype 契约。对应缺陷单 #3270（reduce_max/min/absmax 的 nan_propagate=True 在 float32/float64 上被静默忽略）随合入关闭——从 09-23 报告到修复合入，全程约一天半。
  • #3205（北京时间 13:44 合入）：T.clamp 的 NaN 传播语义修复——把 NaN 传播的 clamp 正确降低到设备模板。对应缺陷单 #3024 关闭，该单来自模糊测试发现「clamp 静默丢弃 NaN 并返回下界」的错误代码类问题。
  • 两条线在同一天落地，意味着上一期浮出水面的「NaN 传播」语义缺口已闭环：一侧把不支持的配置前移为编译期失败，一侧把静默错误行为修正为符合预期的传播语义。

1.2 主仓：SIMT im2col 与异步暂存——性能缺陷单与两级重构 PR 同日成形（09-24）

日期：2026-09-24　来源：#3274／#3275／#3279／#3278

  • 北京时间 12:48，性能缺陷单 #3274 开出：SIMT im2col 的降低时机过晚，错过了调度与向量化机会；三分钟后 #3275（CUDA/Transform，将 SIMT im2col 的加载提前到调度之前暴露）随即开出——「当天报告、当天出方案」的节奏再现。
  • 当日 23:22，#3278（Transform/CUDA：修复分区布局下的异步拷贝降低）完成合入——异步拷贝在分区布局（partitioned layouts）下的错误修复合入主线。
  • 09-25 凌晨 00:30，#3279 开出：「统一异步数据暂存与传输感知降低」——作者自述为 #3275 的激进重构，且对卷积、mHC 前置、Bounded GEMM 等场景有「实质性性能收益」，目前仍标注为实验性。要点（按 PR 摘要）：把逻辑层面的 tile 算子展开与物理降低分离，CUDA/CPU/Metal/ROCm/WebGPU 各管线在调度与布局推断之前先暴露逻辑访问；引入共享的传输分析（描述访存效应、值转换、执行守卫与 TMA 使用），供流水线规划识别预取阶段与异步候选、供 warp 特化分析识别 SIMT 生产者、供 CUDA 与 ROCm 异步拷贝注入器识别可转化传输；流水线等待规划开始支持依赖多个异步生产者阶段的消费者；向量化开始为向量化的 cp.async 拓宽访问区间；线程同步分析跟踪索引与指针访存的物理字节足迹；当生产者前缀写共享内存时，在 TMA 发布前补共享内存同步边。另附开发者文档，并把 im2col 回退测试更新为可配置流水线阶段数。
  • #3276（CUDA：保持 FP8 向量拷贝打包状态）同日开出、处于评审。

判读：从「缺陷单 → 提前暴露访问 → 统一暂存与传输感知」三级递进在同一天成形，且直接瞄准卷积与 GEMM 类负载的性能骨架。把「逻辑访问」与「物理降低」分离，与此前「随机数、布局证明、NaN 语义」等线索一脉相承——编译器正在系统性地把隐式行为显式化，以换取可组合性与可诊断性。

3.2 社区项目：ETH 苏黎世 TileLang SoftHier 扩展更新，面向 RISC-V 众核加速器（09-24）

日期：2026-09-24　来源：tilelang-softhier 仓库

  • 个人社区仓库 tilelang-softhier 北京时间 17:15~17:19 更新 README 并调整仓库文件。按仓库自述：这是把 TileLang 扩展到瓦片式多 PE（many-PE）加速器的工作——内核除计算外还需决定瓦片归属、瓦片在 NoC（片上网络）上的移动与同步位置；目标平台 SoftHier 是一个用 GVSoC 建模、可配置的多簇 RISC-V 加速器（苏黎世联邦理工学院集成系统实验室，Luca Benini 教授指导的学期项目，仓库为 TileLang 的 fork）。
  • 核心设计原则：内核作者只声明「计算什么、数据在哪」，编译器推导簇放置、集合通信路由与同步。结果表：4×4 簇配置、BM=BN=BK=128 的 2D SUMMA GEMM，N=7168、K=2048（对应 DeepSeek-V3 路由专家降维投影尺寸），M=512 时编译器生成代码 1.01 ms vs 手写 C 0.96 ms（差距 5.14%）。
  • 旁证：社区另有 TVM/TileLang Cookbook（30 星）等中文学习材料，窗口内推送为星标图表自动化（chart 分支），主分支无新内容；另有数个零星的个人实验仓库，无实质内容。

五、趋势观察

5.1 发布节奏：补丁线与小版本线并行的 TileRT

TileRT 在 09-24 一天内合入 v0.1.5.post3 与 v0.1.6 两笔发布 PR：前者是 v0.1.5 线的第三个补丁，后者把 GLM-5.2/5.3 的 ROCm（AMD Instinct MI350X/MI355X）支持与 PD 分离更新并入。相对 8 月仅一笔发布的节奏，这是发布管线加密的信号；但发布页与标签滞后于发布 PR，公开渠道的信息差需要下一期继续跟进。

5.2 显式化运动第二波：从语义校验转向调度与暂存

上一窗口的「NaN 传播」以编译期校验 + 语义修复双线合入、两个缺陷单关闭收尾；同一原则随即转向编译器调度层：SIMT im2col 的加载提前暴露（#3275）、逻辑访问与物理降低分离的异步暂存统一（#3279）、分区布局下异步拷贝的修复（#3278）。「先声明、后推导、隐式转显式」正在从语言语义延伸到性能关键路径，直接服务卷积、GEMM 与 mHC 等场景。

5.3 LinearAttention 家族进入整编期

从 DeltaNet 推理算子（09-23）到 GLA 推理 + SM90 DeltaNet 解码（09-24），再到同日的四笔「移除遗留路径 / 改名」草案，线性注意力家族的迭代模式完整呈现：扩张（训练侧→推理侧）→ 平台化（SM90/H200）→ 整编（删旧收敛）。分页 GQA 向统一算子迁移（#2202）属同一主线的注意力侧配套。

5.4 空白与风险点

其一，大件评审带宽：主仓的 TileIR 后端执行 PR 与魔法除法等大变更窗口内无新合入，加上发版停滞 23 天，「小单快合、大单慢审」的格局持续；其二，昇腾文档核验队列虽成批推进，但主体自 8 月中旬挂起至今仍为开放态，验收与合入路径未见说明；其三，TileRT 发布页滞后于发布 PR，对本主题的版本跟踪构成短期盲区；其四，摩尔线程连续第二周静默，国产适配四家热度不均。
