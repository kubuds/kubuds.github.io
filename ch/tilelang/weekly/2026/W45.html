TileLang周报（2026-11-02 ~ 2026-11-06）

2026-11-06 苦芽科技

报告周期：2026 年 11 月 2 日（周一）至 11 月 6 日（周五），共 5 个工作日 素材来源：本刊每日 TileLang 社区动态日报 5 期（11-02、11-03、11-04、11-05、11-06），五期采集窗口首尾相接，合计覆盖 10-30 07:00 至 11-06 07:00 共 168 小时（周一那期为 72 小时窗口，覆盖上周末；周二至周五为 24 小时），与上一期周报（10-26 至 10-30）无重叠；另经 tile-ai 组织各仓库 168 小时窗口补充核查、各仓发布页与标签、TileLang×RISC-V 四源巡检复核（详见附录）

一、本周要闻

  • 昇腾 950 的持久化 FlashMLA 内核直接写进主线，用编译器可调度的写法而非另仓移植（11-02 合入，#3678）：一笔新增 1997 行、删除 17 行、20 个文件、42 次提交，覆盖 BF16 prefill 与紧凑 FP8 decode 两条路径，并支持可选的 FP8 与 FP4 额外 KV 缓存、attention sink、非法索引与逐 query 独立长度。注意力循环、在线 softmax、反量化与调度全部用 TileLang 表达，靠 T.Stage 让编译器管理缓冲版本与同步；QK 与 PV 共用一块 L0B 存储环的两个不同 layout 视图，L1 落位由 T.annotate_buffer_addresses 直接指定；prefill 在一个累加器分配里分出四个不相交的输出切片，归一化算完一片就排空一片。为了让这套写法成立，编译器侧同期补了三处能力：L0C 到 UB 的拷贝保留 NZ 输出、每个 AIV 流在自身流水线之前选定、显式调度的阶段在物理发射相位相同时保持源码顺序。目标形状写得很窄：头数 64、Dqk 与 Dv 都是 512、topk 为 64 的倍数。来源：https://github.com/tile-ai/tilelang/pull/3678

  • ThreadSync 一周三改，先为迁移让路、再把性能与证明补回来（11-01、11-04、11-05）：11-01 的 #3733 把三周前合入的精确线程计数（#3291）整笔回退，理由写得很直白——那套改动把昂贵的计数查询搬到满块栅栏检查之前，即使所有线程都会到达栅栏也要跑证明，TVM 的求解预算被耗尽后返回部分计数，合法的 remap 与 sequence 辅助 kernel 直接以「Cannot prove a thread rectangle」编译失败；商守卫、精确参与线程界、非矩形线程集三类正确性改进一并撤回，#3732 留作迁移后重新优化的跟踪单。11-04 的 #3761 则处理回退派生的副作用：为了修 #3643 的命名屏障重号，同一组线程跨作用域也不能复用 ID，TileKernels 的 mhc_pre_big_fuse 内核每块 96 线程因此在两段式 cp.async 流水线上多拿一个 ID，编译产物声明的屏障资源从 4 变 5，B300 上隐藏维 1280 的屏障占用上限从 16 块/SM 掉到 12 块/SM；修法是让 ThreadSync 接受有序作用域列表，跨作用域共用一个 ID 之前先用新分析器证明参与谓词恒成立，验收标准是资源声明回到 4、占用回到 16 块/SM，#3643 的修复没有被回退。11-05 在审的 #3787 继续补证明器盲区：192 线程下 tx < 160 and tx // 32 % 2 == 0 这种「边界项与 warp 索引取模项用 and 拼起来」的形态会误报，根因是 FloorDiv 与 FloorMod 的编码在「上界加取模」组合下建立不起两个除法的关系，修法是把 threadIdx.x 改写成 warp_index * warp_size + lane。来源：https://github.com/tile-ai/tilelang/pull/3733、https://github.com/tile-ai/tilelang/pull/3761、https://github.com/tile-ai/tilelang/pull/3787

  • TIRx 迁移从「口头理由」变成一周三处硬证据，底座换代进入公开准备（11-03 至 11-06）：11-03 的 #3736 把 tilelang/language/ast/、tilelang/language/parser/ 与 tilelang/language/tir/entry.py 一并删掉——早期本地 TVMScript 解析器分叉的残留，新增 1 行、删除 3384 行、10 个文件，语言层改走上游 tvm.tirx.script.parser，AST 与语句覆写注册在 tilelang.language.overrides。11-06 合入的 #3752 与其前置的 tile-ai/tvm#91 把 Z3 的 rlimit 从写死的 100,000 变成可按 kernel 配置，作者的原话是「这间接修掉了很多与 Z3 证明器相关的问题」。11-06 的 #3803 提交完整迁移草案（draft）：把 vendored 的 TVM 换成独立的 Apache TIRx，前端、IR 变换、代码生成、JIT 适配与打包全部迁到原生对象模型，并 pin 了 apache/tvm-tirx 的 7e49a148 与 apache/tvm-ffi 的 3e906bc6，依赖树保持干净上游、不注入补丁。三条线指向同一件事：主线这一阶段的第一优先级是换底座，其余优化都要给它让路。来源：https://github.com/tile-ai/tilelang/pull/3736、https://github.com/tile-ai/tilelang/pull/3752、https://github.com/tile-ai/tilelang/pull/3803

  • 「静默生成错代码」成为本周最主要的缺陷类型，且跨四个发布版本（11-03 至 11-05）：最重的一条是 #3808——条件相关的标量化之后，共享内存 epilogue 少了一道 __syncthreads()，0.1.12、0.1.13、0.1.14、0.1.15 四个版本都会静默生成错误 CUDA，编译不报任何错，报告者给了完整可运行的复现脚本。同族还有 #3800（关掉 warp specialization 后，T.Pipelined 在 tcgen05 的 barrier 等待之前就重载下一 stage，MMA 读到被改写的 operand）、#3721（sm_100a 上对 TMEM 做 T.gemm，threads/32 不能整除 N 时 PTX 里一条 tcgen05.mma 都没有，乘积被静默丢弃）、#3775（生产环境 TP2 sglang 加 nvrtc 后端，CUDA graph 捕获被损坏，三次字节一致的配置复现出三个不同的首个失败点）、#1991 与 #1992（昇腾 910_9362 上 threads=2 时 AscendVidReduction 把注入的 tmp workspace 也无条件减半，sin/cos 作用在间接寻址 tile 上 3978/4096 个元素算错，即 97.1%）。这一族都不报错、都能通过常规测试，只能靠针对性复现抓到。来源：https://github.com/tile-ai/tilelang/issues/3808、https://github.com/tile-ai/tilelang/issues/3800、https://github.com/tile-ai/tilelang-ascend/issues/1991

  • TileFoundry 把同步从「分析能证明」推进到「发射必须与证明一致」（11-02 至 11-06）：#283 把「共享内存访问应当如何排序」做成可证明的分析层——按 lowering 的发射顺序走每个函数，在冲突访问之前规划 commit、wait 与作用域内栅栏，83 个调度夹具里计划 52 个、拒绝 31 个（24 个用 TMA 拷贝、6 个用 wgmma，两者的完成语义尚未声明）；因为默认没有调用方请求，75 个会 finalize 的夹具字节与 main 完全相同。11-04 合入的 #285 是它的执行端：CUDA lowering 按同步计划发射并逐条反向校验，不一致抛 LoweringError；单张 sm_89 上 7 个能构建的程序里 6 个与参考完全一致、synccheck 与 memcheck 全干净，而同样这 7 个按 main 的方式 lower 有 4 个结果错误，直接症状是 sm_89 的 E4M3 GEMM 最大偏 659。11-06 合入的 #286 补 WGMMA 的异步完成语义，11-05 合入的 #284 把 FSDP 与 HSDP 的训练语义做进 HIR 求值器并在四卡 sm90 上与真实的 2×2 PyTorch HSDP 对齐。作者对 #286 保留了明确的限定：矩阵指令发射器仍未接上，这笔不证明执行正确性、也不给性能。来源：https://github.com/tile-ai/TileFoundry/pull/283、https://github.com/tile-ai/TileFoundry/pull/285、https://github.com/tile-ai/TileFoundry/pull/286

  • TileOPs 五个窗口合入 15、7、1、7、9 笔，竞争点从「算子数量」彻底转到「选择器与准备成本」（全周）：首窗 15 笔里 13 笔压在 11-01 一天，几乎每笔都带 H200 实测表与「manifest 无已测行回退」声明；随后的 11-04 与 11-05 两个窗口各有 7 笔与 9 笔，把节奏推回节后最密。三条硬数字可以概括这一周的方向：GQA 稠密前向用一条实测规则选 decode 或 prefill 程序，相对最快候选的选择遗憾从 1.818 降到 1.017（#2808）；warp 专用 decode 把 softmax 与 QK、PV 重叠，受影响的 478 次扫描调用几何均值延迟为 main 的 0.952 倍（#2817）；广播操作数就地读让 lerp、where、clamp、masked_fill 五类算子的广播行耗时降到主线的 0.13 到 0.44 倍（#2832）。同期还有 roofline 计价重写（三条物理不可能的带宽行从 7.48、7.50、5.30 TB/s 修正为 0.62、0.62、2.65 TB/s，#2830）与三阶段瓦片因子单独拟合（选择遗憾从 0.89% 降到 0.06%，#2836）。来源：https://github.com/tile-ai/TileOPs/pull/2808、https://github.com/tile-ai/TileOPs/pull/2832、https://github.com/tile-ai/TileOPs/pull/2830

  • 国产后端从「自研分支」走向「公共评审」，海光第一次开出正式 PR（11-05）：海光仓主分支停在 11-02 的 #32（把 gfx948 按 gfx946 兼容处理），本周的动静先在 feat/hcu-scaled-cast 分支上攒了四笔（E8M0 缩放的 FP8/BF8/FP4 转换、64 bank 的 LDS 读相位、混合 LDS wrap 的至多两路证明、按物理读宽度做混合检查），11-05 又落三笔 LDS 相位修，并于 09:08 与 19:52 分别开出 #33（scaled cast）与 #34（reduction 的 XOR shuffle 用 DPP 与 lane swap）两个 PR——这是国产后端里第一个走完「自研分支到公共评审」这条路径的。mlir-ascend 同期把 BishengIR 工具链适配器搬进 contrib（#209），并用 #203、#211、#212 三个小 PR 把 tl.sub/mul/div/max/min、tl.shl、tl.shr 一个个搬进 TLIR 方言。摩尔线程在 11-05 落了一笔 README 文档提交，结束自 09-30 以来的完全静默。来源：https://github.com/tile-ai/tilelang-hygon/pull/33、https://github.com/tile-ai/tilelang-hygon/pull/34、https://github.com/tile-ai/tilelang-mlir-ascend/pull/209

  • 硬件支持向两头同时扩：Blackwell 新 SKU 与国产加速器（全周）：一头是新卡。B300 上报的 sm_103a 在两条路径上各卡一次——tcgen05.mma.kind::i8 只存在于 sm_100a 与 sm_110a，内核通过 lowering 后在 ptxas 报 Feature '.kind::i8' not supported（#3770）；CuTeDSL 的 TMA 辅助函数维护一张架构白名单，B300 在进 DSL 之前就被拒（#3772，加上 sm_103a 与 gr100 的 sm_107a 后 B300 上 8 通过 1 跳过、gr100 上 13 通过 1 跳过）。SM120 上 FP8 加 fp32 累加的 GEMM 一直用 SM89 的 mma.sync 原子，换成带 ue8m0 单位缩放的 block-scaled MMA 后，RTX 5090 上 8192 立方从 463 升到 727 TFLOPS（在审 #3790）。另一头是国产卡：海光在 64 bank 的 LDS 相位上做微架构级调优，昇腾把 Cube 与 Vector 的核心比从固定 1:2 改成可配置（#3783）、把 AutoSchedule 的周期下界收紧使 Z3 求解时间降 10.04%（#3776）。来源：https://github.com/tile-ai/tilelang/pull/3772、https://github.com/tile-ai/tilelang/pull/3790、https://github.com/tile-ai/tilelang/pull/3783

编译器、语言层与执行路径

  • 昇腾 950 FlashMLA 内核与配套的编译器能力（#3678，11-02 合入，20 文件 +1997/-17）：见要闻第一条。值得注意的是这笔把「显式调度」所需的三项底层能力同时补进主线，而不是在昇腾分支里打补丁——L0C 到 UB 的拷贝保留 NZ 输出、每个 AIV 流在流水线之前选定、物理发射相位相同时保持源码顺序。
  • cast 解耦的向量宽度回归连修两笔（#3734 11-02 合入，#3759 11-05 合入）：#3734 修 SM100 上 ViT 前向的 Cannot convert type float32x16 to CUDA type——向量化规划器为 256 位 BF16 存储选 16 个 lane 并推迟 cast 约束，而 #3579 让解耦跳过了读内存的守卫之后，最终合法化仍沿用推迟策略，残留的 FP32 表达式被撑成 512 位向量；修法是把 defer_cast_constraints 做成规划器的 C++ 参数而非 IR 属性，守卫的 FP32 转 BF16 降到 8 个 lane，成功解耦的 BF16 拷贝仍保留 16 个。#3759 收它的尾巴：条件里的 int64 cast 此前会把数据向量宽度从 16 lane 压到 4 lane，即使该条件在 16 个 lane 上完全一致；修法是把条件一致性分析复用到 cast 宽度豁免上，if 语句、tirx.if_then_else 与标量谓词的 Select 条件单独访问，子句里的 cast 仍受限。
  • ThreadSync 的三段式演进（#3733、#3761、#3787）：见要闻第二条。#3733 是明确的临时措施，原文写明「为 TIRX 迁移让路」，配套的 TVM fork 优化提案 tile-ai/tvm#89 已关闭。#3761 的 401 行改动里最值得记的是归因实验：作者单独改编译产物里声明的屏障资源数、不动任何可执行指令，就复现了同样的变慢，把「性能回退」从观感变成了可指认的单一变量。
  • 语言层与前端做减法：#3736 删掉 3384 行遗留 TVMScript 解析器分叉（见要闻第三条），保留它的风险写得很具体——一旦有人直接 import tilelang.language.parser.operation，它会在 tirx.PrimExpr 与 tirx.IterVar 上注册互相冲突的算子；#3760 给嵌套 T.macro 引入有界的进程内转换缓存，只存与上下文无关的转换结果，宏实例再绑定当前的 globals 与闭包值，解决「kernel 已命中缓存但宏仍重复解析编译」的问题；#3802 新增 T.annotate_host_mapped_buffers，把被注解参数的索引写进 PrimFunc 的 tl.host_mapped_params 属性，运行时用 cuMemHostGetFlags 校验注册状态、用 cuMemHostGetDevicePointer 解析设备可见地址，普通可分页内存仍被拒。
  • 调试与可观测性：#3703 把 #line 指令从「每条 TIR 语句只锚定首行」改成分级发射（0 关闭、1 语句级、2 以上逐行重锚定），实现落在 CUDA、HIP、CPU C、C host、Metal、Ascend 共用的 C 系输出流里，新增 TILELANG_EMIT_LINE_DIRECTIVES 作为 Python 侧默认值；作者注明 CUDA 与 HIP 用例在本机被跳过、cuda-gdb 的实际行为未直接验证。同日 LSP 仓跟进一笔，把 CUDA 调试对齐到新的行映射；11-04 VS Code 扩展仓再跟进一笔，更新文档并把产物改名 vsix。
  • 自动调优的口径：#3546 把 set_autotune_inputs 的供给闭包从「调用点从不传入的参数」改为 get_current_device()，此前在没有 CUDA 的机器上兜底分支把每个捕获张量搬到 CPU、每一轮调优都因启动器设备不匹配失败；双卡 Ascend950 上三笔昇腾自动调优回归修前全败、修后全过。同族的 #3784 在 AscendC CI 上给跨设备拷贝探针前后各加一次设备同步，让异步错误落回 try ... except RuntimeError 的作用域内——此前它会晚一步浮出，看起来像是无关的 torch.arange() 报了 4 字节 memcpy 尺寸不符。
  • Z3 求解资源从写死变成可调（#3752，11-06 合入，依赖 tile-ai/tvm#91）：rlimit 默认仍为 100,000，不配置时行为不变。这与同期昇腾侧收紧 AutoSchedule 周期下界（#3776，Z3 求解时间降 10.04%）是同一方向的两端：一个改搜索预算，一个改搜索起点。

正确性与缺陷修复

  • ThreadSync 与屏障：#3733 的整笔回退（见要闻）与 #3761 的跨域复用（见要闻）之外，在审的 #3765 把「单个线程索引边界守卫的部分屏障」在线程维是整 warp 数时显式接受，#3767 把多索引 fragment 访问的 StructuralEqual 内部断言换成带两个索引表达式的 ValueError，#3786 把 T.copy 目的区域越界改成编译期报错，#3788 修 ProveFragmentContains 的快速路径——它在大 fragment 完全复制时直接返回真，跳过了线程归属检查，于是「小 fragment 拥有线程 0 到 127、大 fragment 只拥有 0 到 95」被误判为包含成立。

六、趋势观察

第一，TIRx 迁移已经是主线事实上的第一优先级，而且它开始以「减法」的形式出现。 一周之内三处证据：11-01 为迁移回退整套 ThreadSync 正确性改进（#3733，同时关掉 TVM fork 侧的优化提案 #89），11-03 删掉 3384 行遗留解析器分叉（#3736），11-06 提交完整迁移草案（#3803，pin 两个上游提交、明确不注入补丁）。中间还夹着 Z3 资源从写死到可配置（#3752 与 tvm #91）。这套动作的共同点是把复杂度从关键路径上撤下来：宁可暂时退回保守实现，也不让 vendored 依赖的内部结构继续长在语言层里。代价是主干在迁移窗口里会有一批「已知不最优」的路径，收益是底座换代完成后所有下游后端能对着一个稳定的 IR 边界做适配。

第二，正确性风险已经换了形态：从「编译不过」变成「编译通过、运行不报错、结果错」，而且跨版本潜伏。 本周至少有七条属于这一族：#3808 跨 0.1.12 到 0.1.15 四个版本少一道 __syncthreads()，#3800 在 Blackwell 的 tensor memory 路径上让 MMA 读到被覆盖的 operand，#3721 在 sm_100a 上静默丢弃整个 GEMM 乘积，#3775 在生产环境损坏 CUDA graph 捕获，#3749 让依赖分析看不见物理加载范围，#1991/#1992 在昇腾 threads=2 下让 sin/cos 算错 97.1% 的元素，#3774 与 #3773 在消费级卡上给出错结果。这一族对用户的伤害最大，因为它把「编译器对不对」这个前提变成了需要验证的假设。本周的应对方向是把正确性做成可拒绝的证明——TileFoundry 的 #283/#285 是先证明再发射、发射后反向校验，#3786 与 #3787 是把默默生成错代码改成编译期报错或明确拒绝——而不是继续加单元测试数量。

第三，昇腾的角色从「适配目标」变成「首发目标」，工程化在两条腿上同时推进。 一条是架构：FlashMLA 这种 DeepSeek 自家解码路径上的核心内核直接以昇腾 950 为目标写在主线里，用的还是 T.Stage、annotate_buffer_addresses 这类为显式调度准备的底层能力；配合编译器侧三处配套改动，昇腾路径正在从「能跑」转向「能按调度意图跑」。另一条是骨架：#1975 用 2887 个文件、60 万行新增把整个 TileLang-Ascend 搬进主线多后端框架，靠 arch="dav-2201" 做后端分流；mlir-ascend 的 #208 把 Codex 的初始化、接入、恢复三套工作流和任务交接写进 .workspace/。把「迁移仓」与「用智能体迁移仓」放在同一周看，能看出昇腾侧的瓶颈已经从「缺算子」转向「缺一致的工程骨架与可复用的迁移流程」。

第四，算子库的竞争点彻底转到选择器质量与准备成本，性能差距的剩余空间不在「怎么算」。 11-05 的九笔 TileOPs 合入里，真正改 GPU kernel 的只有广播就地读与原生宽度瓦片两笔；reduction 布局缓存省的是调用准备（4.33% 到 6.17%，生成源码不变），三阶段瓦片因子改的是一个常数（regret 从 0.89% 降到 0.06%）。再加上 roofline 计价重写与 L2 刷写改只读，可以看到一条清晰的路线：先把每个形状的合法配置枚举出来，再用统一的代价模型排序，标定过程写成可复现的契约（#2826 已经把「扫描、拟合、检查」三步写进文档串）。这条路做对了，性能就不再依赖个别内核的手工调优；做不对，就会退化成「某些形状特别快、其他形状靠运气」。

第五，国产后端从「一次性合入一个大后端」转向「把可评审的最小单元推到公共仓库」。 海光从自研分支走到 #33 与 #34 两个正式 PR，摩尔线程以一笔 README 结束两个月静默，mlir-ascend 用三个小 PR 把 tl.sub/mul、tl.shl、tl.shr 一个个搬进 TLIR 方言，昇腾则把核心比、异常转储、性能技能这类工程细节逐项补齐。三条线的共同点是不再等一个大合入：这对上游是好事，评审者能早就布局与 lowering 的设计提意见，而不是在三万行一次性合入时才看；对下游也有代价——主干在这类窗口里会处于「已知有几处不工作」的状态，需要更强的发布前回归纪律。

最后一条风险面：底座切换会把所有胶水层的成本一次性暴露出来。 如果 #3803 推进，3rdparty/tvm 的 vendored 结构会被替换成两个 pin 的上游提交，届时所有依赖 TVM 内部 API 的后端（昇腾、海光、mlir-ascend 的胶水层）都要跟着改。草案里明确写了「不注入依赖补丁」，这既是承诺也是约束——本周 mlir-ascend 把 BishengIR 适配器搬进 contrib、昇腾把性能技能按芯片代际分叉，都可以看作是为这类底座切换预留的可替换面。判断这条线是否健康，看的是迁移草案合入后两周内，这几个后端能不能在不动核心 lowering 的前提下完成适配。
