TileLang周报（2026-10-12 ~ 2026-10-16）

2026-10-16 苦芽科技

报告周期：2026 年 10 月 12 日（周一）至 10 月 16 日（周五），共 5 个工作日、5 期日报素材 素材来源：本刊每日 TileLang 动态日报 5 期（10-12、10-13、10-14、10-15、10-16）；另经 tile-ai 组织 29 个仓库的 168 小时窗口补充核查、夜间流水线六份快照的测试结果逐份复算与各仓库发布元数据复核（详见附录）

一、本周要闻

  • 主仓 ROCm 线连续四日收笔，DeepSeek 新架构内核成为第三收笔线（10-13 ~ 10-14）：10-13 合入 DeepSeek NSA 前向/单 token 解码的 64 lane 单波实现（#3152，+111/-2）与 flash-decoding 的 LDS/VGPR 预算自适应瓦片（#3149，+82/-5）；10-14 凌晨再合入 mHC（流形约束超连接）前/后处理内核（#3156，2 文件 +83/-6，HIP 侧改在完整 64 lane 波前上分工并把 FP32 混合权重转 BF16 供 MFMA）与 safe-gated KDA 解码示例（#3249，+360，含 GLM-5.3-Flash TP8 专用化配置）；10-14 另有 cumsum/cummax 的 64 lane 段宽修复（#2326）。四笔共同指向「按设备现实自适应」：gfx942 波前尺寸、MFMA 输入类型、LDS/VGPR 预算逐项清偿，ROCm 支持从「跑通」转入「与新架构发布同步」。

  • 昇腾 PTO 由「独立目标」升为「一等执行路径」，NSA 双迁移与回滚纪律同周发生（10-12 ~ 10-15）：10-15 合入执行路由 #3316——target="ascend" 与 execution_backend="pto" 组合经执行感知的目标规范化后直连 CodeGenTileLangPTO，auto 路径维持 AscendC + TVM-FFI；前置的示例目标选择 #3474（10-14 合入，移除硬编码 target="ascend"，CI 对 ascend / pto 双目标各跑一遍）与本窗口在审的 tvm_ffi 后端、VMI 向量化、SS buffer、部分 L0 拷贝 pitch 等七笔构成家族。同周 10-12，昇腾 NSA Decode（#1701，+755，28 例分层测试）与 NSA Bwd（#1730，+1593，20 例）合入；10-14 三笔「文档事实核查」PR（#1612、#1676、#1681）因低优先级预期失败用例的异常正则不匹配被整批回滚（#1888 至 #1890），bitwise_rshift 以 重做版 #1893 删减预期失败断言后重新提交；10-15 开出 dav-3510 上 gemm_v0 的静默数值错误修复（#1900），暴露 --npu-arch 无条件取 dav-2201 导致 A5 内核瞄错架构。

  • TileOPs 一周 52 笔合入：Op 基类重构定稿、MoE 双算子落定、SM89 成为第二平台（10-12 ~ 10-16）：10-11 合入的 Op 基类重构（#2520，363 文件、+3362/-5227，自称「发布前」收口）把带与不带编译边界的算子统一经 _run_call 执行、select_kernel_key/select_implementation 合并为 key_for、编译边界改从 manifest 推导，文档站次日跟进《Op 基类指南》；10-13 MoE 双算子同日落定——masked FP8 分组 GEMM（#2521，20 文件 +1788/-37，对齐 deep_gemm masked 语义）与 DeepSeek 分组 top-k（#2535，15 文件 +1193/-69，对齐 vLLM grouped_topk 并修 T=512 时 32/132 SM 的调度问题）；SM89 从 10-12 起成批收口（GQA 预填/解码、GDN / DeltaNet 预填、GLA / DeltaNet 反向、KDA 预填、Norm 全谱），RTX 40 系与 L40 / 6000 Ada 级工作站在算子库侧与 Hopper 并列。

  • 夜间底盘六份快照：正确性 1032 → 1134（+102）、基准 1947 → 1989（+42），全程零失败（10-12 ~ 10-16）：本周六份快照的正确性用例由 1032 项升至 1134 项、基准由 1947 项（52 套件）升至 1989 项（55 套件），六份均为零失败零错误、各 1 项跳过。单日最大增幅出现在 10-15（+41，与 TileOPs 16 笔合入同拍）；10-16 出现两次快照（凌晨与夜间各一），为本周首次单日双快照。评测环境为 H200、CUDA 13.2、torch 2.13.0+cu132、tilelang 0.1.12（详见第四章表格）。

  • 多后端同版本收口：海光 v0.1.15 升级落地并开出分布式 IPC 线，沐曦追平上游，摩尔线程全周静默（10-13 ~ 10-16）：海光 10-14 合入 v0.1.15 全量升级（#20，保留 HCU 后端并新增块缩放 GEMM 的 scale 缓冲布局规划）并建立 v0.1.15-release 分支，同日以 #19（+2577/-28，44 文件）开出 Distributed 线（统一进程启动器、IPC allreduce 测试、IPC GEMM allreduce 示例等）；10-15 以 #21 把块缩放异步拷贝布局当日开、当日合进 v0.1.12-release 维护线；10-16 再合入 #22（K-major 打包 scale 拷贝与原生 FP32 MLS GEMM）。沐曦 10-13 将 main 推至上游 v0.1.15 节点（镜像 #3309），10-16 dev 线合入上游 main 并修一处 xfail 用例。摩尔线程自 09-30 后全周无活动，是四家中唯一未对齐 v0.1.15 的后端。

  • TileFoundry 一周十笔合入：稀疏解码贯通 TIR、Qwen3.8-27B 预填首次全长度超越 SGLang、核心重构与外部审计同期（10-12 ~ 10-16）：10-12 合入稀疏解码贯通 TIR 的 #223（84 文件、+4424/-1543，修丢失循环工作量、查找计费过高与分阶段更新错误）；10-13 合入 Qwen3.8-27B 预填示例 #229（89 文件、+38069），为该仓首个在 1024 / 4096 / 8192 三个长度上全部快于 SGLang 的示例（8192 时打分只占 FLOP 的 3.1%，负载超出 H200 拐点 36 倍）；10-15 同窗落地实例槽重构（#232，源码全套 1674 通过）与 lowering / printer 契约（#233）；10-16 补上 analysis 访问上下文（#238）与 issue 237 的分配/lowering 修正（#241）。重构落地的同一窗口，第三方技能仓即把 TileFoundry vendor 进工作流并列出 4 个 emitter bug 与 2 个运行时 bug——进入外部审计期。

  • 采用方首次出现版本迭代：TileKernels v2.1.0 昇腾侧重写、FlashQLA 修复 Blackwell sm120（10-14）：DeepSeek TileKernels v2.1.0（16 文件、+352/-382）是该仓 09-30 加入昇腾支持后的第一次版本迭代，改动集中在昇腾侧（norm_forward_asc 大幅重写、SwiGLU 前后向、Engram 门控），README 要求升至 TileLang 0.1.15、PyTorch 2.13、Ascend 950 NPU 与 CANN 9.2.0；Qwen FlashQLA #48（5 文件、+82/-5）修复自 0.1.13 起 Blackwell sm120 前向/反向不可用（block_DV 被误改为 128、缺 aggregate_card_state），RTX 5090 + tilelang 0.1.15 + CUDA 13.0 全部测试通过。

  • 硬件矩阵同周扩张：SM121 点亮、SM120 块缩放双线在审、D=256 解码扩至 SM80/SM90、CPU OpenMP 网格并行落地（10-12 ~ 10-15）：SM121（GB10 / DGX Spark）块缩放 MMA 于 10-11 点亮（#3430，DGX Spark 驱动 580.178.04 / CUDA 13.0 实测），此前 sm_121a 下所有块缩放 MMA 会编译成 BPT.TRAP；SM120 侧的 MXFP8/MXFP4（#3495）与 mxf8f6f4 全操作数家族（#3099）全周在审。消费级与工作站侧，D=256 FP16/BF16 稠密解码由 SM89 扩至 SM80/SM90（#2563，附 Gemma-2B 8K cache 负载，同时修复稠密 RoPE split 忽略 softcap）；主仓 10-14 合入 CPU 后端的网格级 OpenMP 并行（#3109）与 Windows NVCC 改走 cl.exe（#3510）。

二、核心项目进展（主仓 tilelang）

版本与发布

  • 主仓最新标签与发布仍为 v0.1.15（09-30 发布），全周无新标签、无新发布页条目，至本周五已 16 天。发布页最近三条依次为 v0.1.15（09-30）、v0.1.14（09-02）、v0.1.13（08-03），此前的月度节奏在本周被打破。
  • 适配线标签全周未动：昇腾 v0.1.2.000、MLIR 昇腾 v0.1.2.020.sglang.poc、沐曦 v0.1.14（10-13 仅 main 镜像到 v0.1.15 节点、未打新标签）、摩尔线程 v0.1.14+musa.1；海光以 v0.1.15 主线加 v0.1.12-release 维护线双线并行。
  • 发布静默的对照面是下游约束上移：TileKernels v2.1.0 明确要求 TileLang 0.1.15 起，FlashQLA 的 sm120 修复亦在 0.1.15 上验证——本周起「0.1.15 基线」成为采用方事实上的最低要求。

编译器、执行路径与语言层

  • PTO 执行路由（#3316，10-15 合入）：新增执行感知的目标规范化钩子（挂在 BackendContext 创建处），昇腾专属规范化器在解析前把原生 Ascend 目标专门化为 PTO 目标变体并保留 arch 等属性，设备代码生成改走 PTO_CODEGEN 与 target.build.tilelang_pto_without_compile；文档给出 TILELANG_DEFAULT_TARGET=ascend 加 TILELANG_EXECUTION_BACKEND=pto 的等价配置。测试覆盖上下文解析、目标属性保留、缓存分发与环境变量选择。
  • PTO DeepGEMM codegen（#3330，10-14 合入）：跨控制流跟踪 tl.ascend_set_mmad_direction 并把生效方向编码进 MAD 指令、拒绝冲突方向下可达的 MAD；支持 SIMD 后增量加载、混合 AIC/AIV 内核的 UB 地址到 PTODSL 指针转换、动态 L0C→UB 维度与步长、int16 有符号打包 MX scale。自报 15 个 DeepGEMM PTO 用例 14 个通过，test_bf16_m_grouped_padding 仍受 PTOAS VPTO 后端无法合法化 FP32→BF16 转换阻塞。
  • 独立 AIV 执行（#3485，10-14 合入）：扩展 Ascend AutoSchedule，使 AIV0 与 AIV1 可在 sid 依赖下执行不同工作（交替收尾、反量化与收尾分工、不相交输入分区、循环内角色切换）；AssignCore 提前到延迟估计与调度之前，并为 AIV 局部 UB 缓冲与标量状态建立独立身份。
  • C 系 codegen 共享基类（#3289，10-14 合入）：CodeGenTileLangCBase 统一 CUDA、HIP、CPU C、Ascend C++、Metal 与 C 主机代码生成；修复 T.import_source、T.Kernel(prelude=...) 与 pragma_import_c 在源文本缺少末尾换行或以反斜杠结尾时吞掉下一生成行的问题。验证：聚焦回归 83 通过、codegen 与 launch 套件 405 通过。
  • CPU 网格并行（#3109，10-14 合入）：新增 MaterializeCPUParallelGrid 把带注解的 CPU grid 循环转为 OpenMP 并行循环，配套循环 collapse、线程数配置、最小 trip 数门限与分配下沉，补齐 Linux / macOS / Windows 的编译标志——CPU 后端首次具备网格级并行。
  • Host IR 线全周在审：统一 CUDA 与 CuTeDSL 执行路径的 #3473 与直连 Host IR JIT 加原生缓存的 #3481 自 10-10 开出后未见合入，仍是主仓最大的在审方向。
  • PTO 家族七笔（10-15 起在审）：tvm_ffi 执行后端（#3516）、T.Parallel 到 PTO VMI 向量化（#3512）、SS buffer（#3514）、部分 L0 拷贝显式 pitch（#3511）、NZ 缓冲 UB→L1 部分拷贝（#3530）、PTO Ramp 值按类型向量发射（#3535）、SIMT VF 内向量局部访问修复（#3523）。其中 SS buffer 于 10-16 上午合入（#3514，日报截点之后经补充核查确认）。

性能与硬件矩阵

  • SM121（GB10 / DGX Spark）：#3430 让 tl::sm120_mma_sync_blockscaled 按 arch 与家族同时接受 SM120 / SM121，NVF4 测试按 SM12x 家族门控，CuTeDSL TMA 架构表放行 sm_121 / sm_121a。
  • SM120 块缩放：MXFP8（kind::mxf8f6f4、1X、UE8M0）与 MXFP4（mxf4nvf4、2X、UE8M0）扩展（#3495，+884/-51，FP32 累加、每 32 个 K 元素一标度）与全 f8f6f4 操作数家族（#3099）持续在审。
  • ROCm：除要闻四笔外，10-15 的 scan 波前修复（#2326）让 cumsum / cummax 按目标波前宽度选择段宽，32 线程块在编译期排除 64 lane 模板；B300 上 CUDA scan 套件 17 通过。

  • Windows / Metal：Windows NVCC 改走 MSVC（#3510，CUDA 13.3 下复现用例修复）；Metal 批十笔（#3194 至 #3210）在审，覆盖段归一累加器、simdgroup GEMM 片段、BF16 向量类型、短常量循环展开等。

三、多后端适配（昇腾 / 沐曦 / 海光 / 摩尔线程等）

昇腾（Ascend）：迁移合入、执行路径收敛与回滚纪律

  • 迁移合入：NSA Decode（#1701，10-12，+755）以 Developer mode hybrid 实现单核解码（seq_q=1），显式 L1/L0C/UB 分配、5 段 GM workspace 经 workspace_idx=[6..10] 自动分配，编译器自动切 Cube/Vector 作用域并插跨核 flag 同步；分层测试 28 例（L0 阈值、L1 功能含 DeepSeek-V3 典型配置 D=128/S=16/BS=64、L2 异常与边界特值），910B3 fp16 实测。NSA Bwd（#1730，+1593）提供 nsa_fwd 与 nsa_bwd_single 两枚 JIT 核，反向按 flashattn_bwd 范式以片上直连 T.copy（L0C→UB、UB→L1）省去 9 枚 GM workspace，分层测试 20 例。

媒体与学术：报道潮之后的持续静默

  • 10-10 至 10-11 的中文深度解读（知危，风闻与知乎两版）以 TileLang 为叙事核心，讲 Tile 抽象、三档编程接口与自动调优缓存机制，并给出昇腾适配对标 Ascend C「性能几乎无差别（A2 / A3）」的对比；10-11 境外聚合稿（tech-insider）属转引性质，非独立信源。
  • 10-12 起连续四个窗口 Google News 中英文多组查询零新增，Hacker News 无相关条目，arXiv 无新预印本（最近一篇仍为 07-24 的 TileSight 性能模型论文）。媒体侧在 09-29 至 10-11 的报道潮之后进入平静期，本周主体内容全部来自 GitHub 组织动态。

六、趋势观察

  • 发布静默期的「静态准备」在四个方向同时到位：TileOPs 的 Op 基类重构自称发布前收口、夜间底盘六份快照零失败增长、TileFoundry 的示例从解码跨到预填全长度超越、多后端 v0.1.15 对齐——主仓自 09-30 已 16 天无标签，但下一版本的静态准备在本周基本就位。是否发布，取决于评审闸门而非内容。
  • 多后端从「版本对齐」走向「同语义收口」：海光完成 v0.1.15 全量升级并另立 v0.1.12 维护线，沐曦镜像追平后转入 dev 合流，昇腾把重心放在文档事实核查、缓存语义与真机验证（#1900），摩尔线程是唯一缺口。四家的差距已从「有没有后端」变为「语义是否一致」。
  • ROCm 成为第二条与新模型发布同步的线：连续四日 DeepSeek NSA、mHC、KDA 与 GLM-5.3 相关内核落地，技术债按设备预算（波前 64 lane、MFMA 输入类型、LDS/VGPR 上限）逐笔清偿；与 SM121 / SM89 的多代并修合流后，后端拓扑已从「英伟达优先」转为「多设备同时维护」。
  • TileOPs 的性能工程从「重点算子攻坚」转为「全算子逐日刷榜」：单日 8 至 11 笔、每笔带外部对照（torch-compile / cuBLASLt / quack / FlashInfer / FLA），残余落后被公开写进 PR（lm-head 两行 0.909x、GLA 反向明确不主张加速）——把「落后」量化并留档，比单点提速更能说明工程纪律。
  • 昇腾的治理口径从「全部通过」转向「断言精确」：三笔文档核查因低优先级用例的异常正则不匹配被整批回滚再删减重做，暴露 PR 阶段不跑 low_priority、每日全量兜底的两级 CI 结构；这类回滚不是退步，而是把「预期失败」当成技术债清算的信号。
  • TileFoundry 从编译器工具转向可交付产品形态：scaffold 独立工程、实例槽与 lowering 契约、跨脊线的预填示例论证，重构落地的同一窗口即被第三方 vendor 并列出缺陷台账——产品化的典型轨迹是「底盘重构之后，接口契约收敛与缺陷公开化」。下一期需跟踪这些 emitter / 运行时缺陷是否被吸收。
  • 下一期关注点：主仓 v0.1.16 是否发布（已静默 16 天）；SM120 块缩放 MMA 双线（#3495 / #3099）能否合入；cumsum warp 特化修复（#3536）与 PTO 家族七笔的推进；昇腾 #1900 的两笔提交与 A5 真机验证排期；海光分布式 IPC 是否出现首个合入的多卡 PR；TileOPs 已出现发布流水线整理类提交（周末），其是否引出首个正式版本；TileFoundry 的外部缺陷清单是否被吸收。
