TileLang周报（2026-09-30 ~ 2026-10-07）

2026-10-07 苦芽科技

报告周期：2026 年 9 月 30 日（周三）至 10 月 7 日（周三），共 8 天——国庆假期特别汇总期（10 月 1 日至 7 日每日日报停刊，本刊为假期合并版） 素材来源：本刊每日 TileLang 动态日报之节前最后一期（2026-09-30，窗口截至当日 07:00）；假期动态以 tile-ai 组织（29 仓库）216 小时窗口的实测核查为准（提交、PR、标签与发布、夜间流水线，核查延伸至 10-08 午后），新闻侧为假期窗口（约 9 天）多组关键词公开检索（详见附录）

一、本周要闻

  • TileLang v0.1.15 节前发布：Ascend 950 原生后端随版本落地（09-30）：北京时间 07:31，标注「Public Release 9/30」的 Ascend 950 后端大 PR（#3308，134 提交、379 文件、+79956/-733）与版本提升 PR（#3309）相继合入；08:29，v0.1.15 正式发布（发布页）。版本四大亮点：Ascend 950 原生支持（端到端 NPU 后端：原生代码生成、Cube/Vector 自动调度与同步、SIMD/SIMT 混合编程）、CUDA 自动 warp 特化（按角色把 TMA 装载、MMA 计算与存储分派给专门 warp 组）、统一块缩放 GEMM（T.gemm_blockscaled 语义统一，SM100 指令选择与 SM120 片段扩充）、表达能力更强的 Python 前端（编译期迭代与推导式）。节前日报截稿时两笔 PR 尚处开放，本刊核验补全：当日晨间合入、发布页同步落账；Ascend A2/A3 支持保留在社区维护的适配仓。

  • DeepSeek 开源面向昇腾的基础设施组件，TileLang 昇腾版在列（09-30）：9 月 30 日，DeepSeek 宣布开源面向华为昇腾算力平台的基础设施组件，覆盖 TileLang 高级语言编译工具、计算库与分布式通信库（报道口径：与英伟达平台组件一一对应）。组织侧佐证：deepseek-ai 当日 DeepGEMM-Ascend、DeepEP-Ascend、TileKernels、FlashMLA、DeepSelect 等多个仓库有推送记录。报道引述「DeepSeek 训练中用到的每一个 TileLang 算子，在昇腾上都有对应的高性能实现」。中外媒体自当日起密集跟进（十组关键词约 210 条窗口内命中，详见第五章）。

  • PTO 后端合入主仓：Ascend 950 同日获得第二条代码路径（09-30）：#3310（+11406/-31、36 文件）于 12:08 合入——注册 pto 目标与执行后端、生成 PTO 设备代码、以内核包装加 Cython 运行时接口运行，并用 ptoas 与毕昇编译 PTODSL 内核；配套帮助函数覆盖 GEMM、SIMT/SIMD、同步、混合内核、缓存旁路访问与 Philox 随机数。跟随队列已开出逾十笔（PTO 执行路由、导入隔离、DeepGEMM 代码生成等），仍在评审。

  • TileOPs 假期 8 天合入 137 笔：量化、采样、线性注意力三线成建制（09-30 ~ 10-07）：137 笔合入、143 笔新开（另 10-08 复工日再添 2 笔）；09-30 单日 32 笔为峰值。采样线六枚内核从掩码到拒绝采样全链落账；线性注意力线 GLA、Gated DeltaNet、DeltaNet 与 Kimi Delta Attention（含张量核 WY 逆 #2365）密集推进；量化与 GEMM 线覆盖 INT4/INT8/FP8 多形态；内核接口重构、PyPI 发布流水线与 README 改版同步落地（详见第四章）。

  • 摩尔线程 MUSA 整备公共 0.1.15 并发布 v0.1.15+musa.1（09-30）：单日 53 笔提交（51 笔 MUSA 侧特性加 2 笔上游同步）——mp31 架构批（tme 系列、sqmma、wmma、warp 特化、缓存提示、peer memory 等）、运行时批（基础目标与后端入口、设备代码生成、JIT 包装、ipc/vmm、dlpack 兼容、显式流等）；傍晚「Prepare public TileLang MUSA 0.1.15」落账后，17:59 打出发布 v0.1.15+musa.1（上一版 v0.1.14+musa.1 为 09-11）。

  • 海光 Hygon 三连合入（09-30）：矩阵存储（gfx946，#14）、multi-XCD Cython 启动支持（#15）、LDS 策略冲突修复（#16）——继节前异步拷贝改进（#13）后的连续推进；海光是本期除昇腾外唯一有代码推进的国产后端。

  • 夜间流水线 12 份快照不间断：基准套件扩至 1939 项（09-30 ~ 10-08）：12 份快照逐日产出，正确性用例 1009 至 1044 项（测试组织重构期有起伏），最新快照 1027 项零失败；基准测量自 1355 项（39 套件）扩至 1939 项（52 套件）；全期唯一 1 例失败——10-07 一份快照的 FFT 用例因 CUDA 显存不足（环境性），次份快照即恢复全绿。

  • 采用方同日跟进：TileKernels v2.0.0 携昇腾支持发布、FlashQLA 更新 v0.1.3（09-30）：DeepSeek TileKernels 发布 v2.0.0（09:58），README 新增「Huawei Ascend support」：双后端由运行时自动选择，同一份 Python API 同时运行于英伟达 GPU 与华为 NPU（要求 TileLang 0.1.15+、CANN 9.2.0+）；Qwen FlashQLA 更新 v0.1.3（21:02），随附 sm90/sm100 autocp 系数与基准更新。采用方与上游发布同日落账，联动得到验证。

二、核心项目进展（主仓 tilelang）

版本与发布：v0.1.15 正式发布（09-30）

  • 时间线：09-30 07:31，标注「Public Release 9/30」的 #3308 与版本号提升 #3309 合入；08:29，v0.1.15 发布——距上一版 v0.1.14（09-02）28 天，与既有的月级发布间隔一致。
  • Ascend 950 段（版本说明节选）：新增 tilelang.ascend.language 与 target="ascend"（对应 dav-3510）；同一内核内组合 Cube GEMM 与 Vector 计算（T.SimdVF / T.SimtVF 区域）；显式 UB/L1/L0 存储、瓦片拷贝、跨核传输与 MXFP8/MXFP4 块缩放 GEMM；自动调度、流水线、多缓冲、布局推导与同步插入；集成毕昇编译、tvm_ffi 与 Cython 执行、PyTorch NPU 张量与流、NPU profiling；示例含 GEMM、DeepGEMM 风格内核、FlashAttention 前反向、RMSNorm 与 FP8 量化。A2/A3 支持保留在社区维护的 TileLang-Ascend 项目。
  • CUDA 段：角色式自动 warp 特化（可经环境变量启用）；SM120 块缩放 GEMM 扩展（片段常驻 A 操作数、行主序缩放片段、奇数 per-warp 原子网格）；T.fma/T.fmul 就近舍入；FP8 稀疏 MLA 前向示例（DeepSeek V3.2，Hopper，#3224）；WGMMA/UMMA K 面板步长修复与稀疏 MMA 异步栅栏。
  • 语言、编译器与运行时段：内核启动编码目标中立化；Python 编译期迭代与推导式；coalesced_width 提示化；AllReduce 线程步长与归约 NaN 传播 dtype 校验；缓存参数改 JSON、CUDA 二进制原子发布、墙上时钟基准、wheel 在 GPU runner 上校验、性能回归使 CI 失败。
  • ROCm、CPU 与 Metal 段：ROCm 支持 DeepSeek V3.2 Top-K 选择器、wave64 Hadamard 与 GLM-5.3 k 池示例；CPU 标量 GEMM 按累加 dtype 计算；Metal 32 位原子加。
  • 兼容性注记：T.Pipelined 移除未用的 sync/group 参数、T.gemm_sp 移除 k_pack；T.symbolic 转为弃用别名（新代码用 T.dynamic）；TILELANG_CACHE_VERIFY_HASH 移除、缓存哈希校验改为强制。

假期修复线与工程小步（10-02 ~ 10-08）

  • 正确性修复：#3361 支持 bfloat16 标量参数（10-02）；#3334 解码 NVFP4 保留的 UE4M3 NaN 缩放码字（10-03）；#3429 索引提升时保留显式转换（10-06）；#3441 LDSM 拷贝保留共享区域偏移（10-07）；#3439 SM89 上 fp8 T.gemm 改为门控报错而非启动即崩（10-07）。
  • JIT 与测试：#3435 惰性内核构建保留可变参数（10-07）；#3443 移除不支持的 BF16 标量回归测试（10-07）。
  • 工程杂项：#3418 合并两个完全相同的分支（10-03）；#3431 pre-commit 自动更新（10-07）。
  • 复工首笔（10-08）：#3299 修复 ROCm 上 T.round 的就近偶数舍入——发布日午间合入，节后节奏如期恢复。
  • 小结：全窗口 12 笔合入（09-30 三笔为发布批次，10-02 起九笔为假期小步修复），与节前单周 14 笔相比略降，实质增量集中在评审队列（下节）。

  • Ascend 950 的「Day-1 版本化」，多后端叙事完成转折：950 后端以「大 PR 加版本发布加第二代码路径（PTO）加使用指引」全套随 v0.1.15 交付，A2/A3 留驻社区仓，代际与维护分工清晰——「多后端」正式成为主干能力叙事。观察点：950 真机性能数据与更长周期的维护成本。

  • 工程化收口动作密集：PyPI 发布流水线、bench.Runner、缓存原子发布、测试统一与命名规范——瓶颈正从「写算子」转向「发布与验证流水线」，是库走向工程成熟期的典型序列。
