TileLang周报（2026-10-19 ~ 2026-10-23）

2026-10-23 苦芽科技

报告周期：2026 年 10 月 19 日（周一）至 10 月 23 日（周五），共 5 个工作日 素材来源：本刊每日 TileLang 社区动态日报 5 期（10-19、10-20、10-21、10-22、10-23），五期采集窗口合计 10-16 07:00 至 10-23 07:00；另经 tile-ai 组织 29 个仓库的 168 小时窗口补充核查与各仓库发布页、标签、VERSION 文件复核（详见附录）

一、本周要闻

  • TileFoundry 0.0.3 正式发布，把指令级调度交给 agent，H200 上 Qwen3.8-27B 预填三档全面快于 SGLang（10-21）：10-21 10:26 打出 v0.0.3，PyPI 为 tilefoundry==0.0.3，代号「Agent-driven scheduling」。核心变化是调度权归属——编译器列出每个 HIR 操作可由哪些指令实现、各自需要什么，agent 在候选中选定，编译器再把选定的调度下降为 TIR；配套 CLI 增加 schedule candidates 与 schedule facts，指令以 AtomSched 操作声明并带显式 TIR 操作数契约，从 CUDA MMA atom、SM90 WGMMA 与异步拷贝起步。性能面给出三组真实数字：Qwen3.8-27B 预填在单张 H200 上 1024 / 4096 / 8192 token 分别为 80.29 / 309.61 / 631.19 ms，SGLang 为 89.06 / 317.11 / 638.25 ms；短序列 128 / 256 / 512 / 1024 token 分别是 SGLang 的 1.88 / 1.41 / 1.10 / 1.03 倍。已知问题两项：wheel 尚未打包 CUDA 运行时头文件（从安装包出发编不出 CUDA kernel，需源码 checkout，下个版本修），以及性能时间线对 insert_slice、tf.zeros 跨 mesh 位置的定价有误（#239）。

  • SemiAnalysis 设 TileLang Ascend 专章：六个获昇腾支持的仓库中，文章写作时只有 TileLang 可用（10-21 ~ 10-22）：10-21 发布的《The Huawei-DeepSeek Symbiosis》副题直接列出华为 Ascend 950PR 微基准、DSv4.1 Flash 分析、DeepSeek 的昇腾支持、AICPU 与 TileLang Ascend。与 TileLang 直接相关的三点：其一，获得昇腾支持的六个仓库（TileLang、DeepGEMM、DeepEP、TileKernels、FlashMLA、DeepSelect）中，写作时只有 TileLang 可用，因为 CANN 9.2.0 尚未发布，而 DeepSeek 要求 CANN 9.2.0 与 C++20 编译器，9.2.0-beta.2 不提供后者；其二，昇腾 950 后端已并入 TileLang 主仓、而非只存在于单独适配仓，提供原生编译、调度、同步与运行时集成，AutoSchedule 依据数据依赖与预估执行时间决定重叠与片上缓冲槽数，在 950PR 上对小尺寸单算子最多缩短 40%；其三，与 CANN、Triton-ascend 对比时「某些尺寸可以打平或超过 CANN」，最优实现随尺寸切换（作者注明为热缓存下的朴素基准）。文章同时点出生态缺口：多数优化面向超节点，x86 主机上 vLLM-Ascend 0.26.0rc1 仍有多处问题。10-22 南华早报《Jensen’s nightmare》转述同一份报告，属二次传播，不构成新的技术进展，但说明该判断正在进入主流媒体口径。

  • 主仓一周完成三轮正确性硬化，缺陷类型从「算错数」扩到「选错目标」与「编译期状态失真」（10-19 ~ 10-23）：第一轮清 warp 特化与流水线几何——#3503 让纯 TMA 生产者每个线程都到达正向屏障（修 #3470 的 parity 挂死）、#2342 让兄弟流水线共享缓冲只展开一次（修 #2309 的四维 LayoutInference 崩溃）、#3536 给共享缓冲上的 T.cumsum 补线程偏移、#2822 保留传递性拷贝依赖。第二轮清静默数值错误——#2818 要求不支持的 MMA tile 显式 K 填充（原先会悄悄缩小 K 原子）、#2815 修 (64,1) 保留维归约崩溃、#3550 让 TIR 谓词随整数位宽提升同步改写、#3070 修批式 finalize_reducer 只归约首个输出块、#3350 对 cast 的源/目标/舍入三组合前置校验、#2860 让无 arch 的 CUDA target 报错而非静默填 sm_50。第三轮清编译期状态——#3579 把非零循环下界纳入向量化分析（10 文件 +818/-198，关掉 #2669 与 #2616）、#3612 在向量化重写前克隆 analyzer、#3226 修并行循环切分后旧 analyzer 绑定失效。三批的共同点是不报错、只在特定尺寸或循环形态下给出不可信结果。

  • 昇腾线重心移到训练反向与底层数据通路，单周合入 11 笔适配仓 PR 并开出 sparse_mla 双向（10-20 ~ 10-23）：训练侧算子集中落地——#1887 的 indexer_bwd（+1294，服务 DSA 稀疏微调，同时支持 AscendC 与 PTO 双后端，分快速、通用、cast 三档 kernel）、#1877 的 SiTU-GLU 反向（+854，语义对齐 CANN 的 aclnnSituGluGrad，用于 Kimi K3 Stable LatentMoE 门控激活反向，910B3 上与官方 aclnn 交叉校验最大相对误差约 3e-3）、#1892 的 LSTM（+2304，12 个 jit kernel，支持多层堆叠、双向、LSTMP 投影）与 #1902 的 GRU（+2267，8 个 kernel，手动关掉 AUTO_SYNC 以避开每时间步约 58 个 PipeBarrier）。在审队列接着补 sparse_mla 前向与反传（#1929 / #1928）、GLM-5.3 的 kpool 压缩（#1910）与 WY fast 系列（#1827 等）。数据通路一侧，#3530 以 18 文件 +993/-256 让压缩 NZ 缓冲支持部分 UB→L1 拷贝并显式给出 C0 组行距；#1795 定位到亚 32B 紧凑行距源无法表达，实测第二个 burst 读到 element 8 而非 element 1，修掉 keepdim reduce 的输出错乱；#1903 把 JIT 缓存改为原子发布并在缓存被删除时恢复。

  • TileOPs 一周合入 68 笔，SM89 与 SM90 并列成主线，规格与基准覆盖同时报 205/205（10-19 ~ 10-23）：组织统计分支在 10-18 单日 20 笔、窗口 44 笔合入后刷新为「已实现 205/205、已基准 205/205」，两项同时满格。SM90 方向一周新增六个 warp 特化 kernel——分页 GQA 前向（#2668）、FP8 lightning indexer 双 consumer warpgroup（#2666）、MLA 解码错位跷跷板（#2665）、dense prefill 持久化遍历（#2706）、dense GQA decode（#2694）、因果滑窗 band（#2696）。SM89 方向则为消费级与单卡场景集中补位：块缩放 FP8 分组 GEMM（#2659）与 INT8 W8A8（#2655）同日落地、FP8 BMM 默认瓦片改 64×64（#2681，1×16×64×128 从 5.161 降到 3.799 us）、W4A16 的 M 上界扩到 64（#2672，M=17 / 32 / 64 分别下降 43.35 / 47.20 / 40.00 个百分点）、分页 DSA 用 MMA 实现（#2669，0.269 ms 对 PyTorch FP32 参考 0.727 ms）、NSA top-k 扩到 2048 个压缩块（#2675）。同期两笔 NaN 修复都出现在 warp 特化路径上：共享内存活跃期判断错误（#2708）与 fast math 下 FMA 融合溢出（#2699）。

  • PTO 从「独立执行路径」走向「自动向量化 + 默认执行后端」（在审，10-18 起）：主仓 PTO 向量化框架 #3512 让用户在 T.SimdVF(lanes=L) 内书写标量并行的 T.Parallel（逐元素、控制流、归约），由编译器向量化为 PTO VMI 指令、经 PTOAS 编译后在 Ascend 950 上运行，规模从 10-18 的 44 文件、18988 行增至 10-21 的 50 文件、21022 行；#3516 拟让 target="pto" 配 execution_backend="auto" 解析到 tvm_ffi 并设为默认。已合入的配套为一串存储、谓词与归约语义修复：#3514 的 T.alloc_ss、#3437 的 SimdVF dim=1 归约、#3582 的 PTO 整数符号性、#3581 的谓词指数增长、#3523 的 SIMT 向量局部变量分配。主仓同时用 #3511 补 AscendC 侧的 L0 局部拷贝显式 pitch（24 文件 +1458/-187，让一个 GEMM tile 可由多次拷贝拼成）——两条路径是并行推进而非替换关系。

  • 下游分发形态出现第二例：Sunrise 打出 0.1.15+sunrise.1.2.0 发布 PR（10-22）：#9 于 10-22 16:48 建 candidate/sunrise-0.1.15-1.2.0-20261019 分支并开 PR，把 Sunrise 分发版更新到 0.1.15+sunrise.1.2.0，纳入 TileLang 0.1.15 及配套评审过的 TileOPs、TileKernels、TVM、tvm-ffi 变更；源导入与合并、分发适配分开提交，最终适配 TANG 后端的 wheel 并修掉切片 GEMM 回归。自报验证为本机契约测试 55 通过、TANG 流水线 codegen 测试 54 通过、两个 lint job 与信任边界检查通过；但 S2 wheel 构建出包后，装后 import 冒烟检查在 tangGetDeviceCount 处失败。该 PR 尚未合入。

二、核心项目进展（主仓 tilelang）

  • TileFoundry 0.0.3 是本周唯一的新版本（10-21 10:26），也是组织内 09-30 以来第一个新标签。适配线标签全周未动：沐曦 v0.1.14（09-17）、摩尔线程 v0.1.15+musa.1（09-30）、MLIR 昇腾 v0.1.2.020.sglang.poc（09-09）、昇腾 v0.1.2.000。

编译器、语言层与执行路径

  • Windows ARM64 进发布流水线（#2962，10-19 合入，12 文件 +356/-45）：新增 PowerShell 安装脚本从 NVIDIA 预发布通道拉取 CUDA 13.4 的 windows_arm64 本地安装包并落到固定路径，新增 FindPipCUDAToolkit 模块与 windows_arm64_clang_compat.h 兼容头，解决 MSVC 工具链在 ARM64 上的头文件与内建差异，同步调整 pyproject、两份 requirements 与布局、MSVC 辅助模块。这是继 ROCm 与昇腾之后补上的第三个非 x86 交付面。
  • lower trace 拆分宿主与设备源码（#3496，10-19 合入，6 文件 +121/-63）：设备侧输出 codegen_device.cpp 与 .original 基线、.latest 最新版，宿主侧另出 codegen_host.cpp 与同结构基线，report.html 以软链接指向最近一次运行。与之呼应，在审的 #3583（13 文件 +106/-4390）把 lower trace 实现、专属环境配置与相关测试从主仓整体抽走，只保留共享的编译器插桩接口，让追踪工具独立演进。
  • CUDA 16 位数学降级补齐（#3172，3 文件 +463/-8）：asin、acos、asinh、acosh、atanh、log1p、atan2、hypot、copysign、ldexp、nextafter 缺 CUDA 专用下降规则，float16 与 bfloat16 调用在 codegen 阶段无人接管。修复把它们注册进 CUDAMath 并补 half_t、bfloat16_t 重载：十个算子按 float32 求值再转回，nextafter 改为按 16 位编码做整数比较步进，以便在 fast math 下保住 bfloat16 次正规数。
  • eager 前端保留 Python 源码位置（#3558，4 文件）：把生成的循环调用映射回 for 语句、上下文包装映射回 with 语句，并补上可迭代参数解包的位置，修 traceback 与覆盖率错位。
  • BF16→FP32 向量化转换改走内联 PTX（#3595，4 文件 +19/-7）：新增成对 lane 一次转 f32x2 的实现，替掉逐 lane 标量提升，2、4、8 三种 lane 宽度均保持支持，语义不变、只动指令序列。
  • 展开 pass 与 ROCm Select（#2887）：循环展开不再消掉 trip count 为 0 的 stepped 循环，ROCm 侧向量化 Select 改为逐 lane 下降，避免整组下降在不支持的目标上失败。
  • softmax 跨 16-CTA 集群分裂（#2632，10-18 合入）：针对 lm-head 这类少行长行（4×102400）新增核，旧实现每行 58 段经全局内存交换 (max, sum) 并跨 grid 屏障，新实现把一行摊到 16-CTA 集群的寄存器上，每个元素只取一次指数，跨 warp、跨 CTA、跨集群用 shuffle 树按 max-first 折叠。
  • 在审方向：除 PTO 两笔外，[Transform] Locate VerifyBufferInit reads outside tile ops（#3620）、[Codegen] Add unsigned mulhi intrinsic（#3617）、[Transform] Keep assumption checks with local dependencies in scope（#3611）、[Transform] Preserve tl.assume predicates that simplify to true（#3610）、[CPU] Support clz in C and C host code generation（#3609）在窗口内有更新；#3597 的混合符号移位修复与 tile-ai/tvm fork 的 #87 成对提交，另 #86 把上游循环作用域修复回移。fork 在审 25 笔、主仓在审 163 笔，TIRx 侧先行、主仓跟进这条协作路径本周第二次出现。

  • 10-19：共享缓冲上的 T.cumsum 在 warp 特化下补线程偏移（#3536，4 文件 +101/-38，CUDA 与 HIP 两套 scan 模板引入 thread_offset）；call_extern 的裸 data 变量保守标记为写入（#2618，新增 69 行用例覆盖「call_extern 写输出缓冲」，方向是宁可少做优化也不做错优化）。
  • 10-20：向量化分析纳入非零循环下界（#3579，10 文件 +818/-198，原实现隐含假设循环从 0 起，下界非零时 unit-step 向量化会把不同 lane 的地址算成同一组）；共享内存跨线程 WAW 检测改用两个线程实例（#2821，3 文件 +153/-19，原 WAW 检查对两次访问复用同一线程变量故漏判、漏插屏障）；不支持 MMA tile 要求显式 K 填充（#2818，FP16 K=8 会算出错误结果，K=20 / 28 等不规则尺寸在布局推断阶段直接失败）；fragment reduce 支持保留维度目标（#2815，8 文件 +343/-63）；TIR 谓词随整数位宽提升同步改写（#3550，4 文件 +950/-27，新增 IndexPredicateRewriter）；CuTeDSL scan 补参与线程偏移（#3576，2 文件 +30/-6，tl.CumSum1D(32, False, 0) 此前直接报构造参数错误）。
  • 10-21：批式 finalize_reducer 此前只归约首个输出块（#3070，2 文件 +29/-5，输出维度大于 batch 时后续各段拿到未初始化值，修后按 ceil(OutputDim / batch) 逐块发射，L40S 上 23 项用例通过、外部复现矩阵 16 例零失配）；cast 的源/目标/舍入三组合前置校验（#3350，f32→E8M0 的 helper 向正无穷舍入、根本不接受舍入参数，而向量化分支从未读过 round）；无 arch 的 CUDA target 拒绝而非静默填 sm_50（#2860，1 文件，修 #1049，错误里给出两种显式 arch 写法）；软件流水保留传递性拷贝依赖并让线程域参与区域冲突判定（#2822）。
  • 10-22：向量化重写前克隆 analyzer（#3612，1 文件 +2/-1）；并行循环切分后旧 analyzer 绑定失效（#3226，6 文件 +55/-19，涉及 loop_partition、loop_vectorize、lower_tile_op 三处 pass）；deepseek_v32 top-k 选择器候选缓冲越界（#3280，2 文件 +91/-10，tl_topk_impl 把 radix 候选装进固定 [2, 4096] 共享缓冲且不约束第一轮阈值桶大小，低位尾数相同的 FP32 分数或全等输入会越界写并崩在 CUDA_ERROR_ILLEGAL_ADDRESS，改法是在 tl_topk 包装层申请 (batch, 2, seq_len) 全局 workspace）；sm8x 稀疏元数据非双射形状改为拒绝（#3125，单文件 +6/-0）。

六、趋势观察

  • 正确性硬化的层次在递进，而不是在同层重复：上周主仓清的是「形状与几何校验」，本周三段各不相同——先是 warp 特化与流水线的几何与屏障（#3503、#2342、#3536、#2822），再是静默数值错误（#2818、#2815、#3550、#3070、#3350、#2860、#3125），最后落到编译期状态一致性（#3579、#3612、#3226）。第三段最值得留意：这类缺陷生成的 kernel 可能仍然正确，但编译器对用户说的和它实际做的不一致；TileLang 正在接入 agent 自动写 kernel，编译期状态能否自洽会直接决定 agent 迭代闭环能不能收敛。
  • 昇腾侧的瓶颈已从算子数量移到内存模型、运行时边界与训练反向：本周 11 笔适配仓合入里，反向与递归算子占五笔（indexer_bwd、SiTU-GLU 反向、LSTM、GRU、CrossEntropy 文档），主仓侧最大的一笔是 NZ 布局的 UB→L1 行距表达（#3530，18 文件），技术密度最高的是亚 32B 紧凑行距不可表达只能显式中止（#1795）。加上 JIT 缓存原子发布（#1903）与 PTO 谓词指数增长（#3581），这条线的主题是「让已有算子在边界条件下不出错」。配合 CANN 社区另起 ops-tilelang 算子仓，可以读出分工：算子资产由社区仓承载，主仓专注后端语义与 codegen。
  • SM89 与 SM90 成为并列的两条硬件主线，且排优先级的标准从峰值性能转向可获得性：SM90 方向本周产出六个 warp 特化 kernel，SM89 方向则把块缩放 FP8、INT8 W8A8、FP8 BMM、W4A16、分页 DSA、NSA top-k 六条路径同时推进，且 PR 普遍附带单卡实测并写明「不主张 SM90 运行结果」「大用例基本打平，不构成普遍优势」。Ada 级显卡（L40S、4090 一类）是国内开发者手里的主力硬件，这一取向与 SemiAnalysis 指出的「优化多面向超节点、通用性落后于性能」正好互补。
  • 生态层的组织动作多于代码层：主仓本周无发布、无 breaking change，但组织外出现了中文系统教程仓、CANN 社区算子仓、agent SKILL 工作流、Hexagon 后端实验、VS Code 扩展与 SAIL 包装仓；组织内则有 TileFoundry 0.0.3 的 agent 调度、Sunrise 的第二个分发形态、TileOPs 的规格满格。把「人写规则、agent 调优、仓里沉淀基线」三者合看，昇腾侧与 TileLang 整体的工程分工正在重排，而代码节奏本身是平静的。
  • 分析机构开始把 TileLang 当作昇腾可用性的判据：SemiAnalysis 用「六个仓库中只有 TileLang 当时可用」来定义 DeepSeek 昇腾支持的完成度，这比任何单篇技术博客都更能说明 TileLang 在国产算力叙事里的位置——从实验性 DSL 变成默认承载层。同一篇报告也给出反向信号：优化集中在超节点、x86 主机支持仍不完整，性能与通用性之间存在明显取舍。SCMP 的转述说明该判断正在进入主流媒体口径。
