FlagOS周报（2026-10-12 ~ 2026-10-16）

2026-10-16 苦芽科技

报告周期：2026 年 10 月 12 日（周一）至 10 月 16 日（周五），共 5 个工作日

素材来源：本刊每日 FlagOS 动态报告 5 期（10-12 / 10-13 / 10-14 / 10-15 / 10-16，无缺期）。其中 10-12 期为周一晨报，调研窗口自 10-10 09:40 起（衔接 10-10 调休补报），故周末时段的部分内容（FlagQuantum 三个候选版、壁仞配售、沐曦高校开源行）经该期纳入本报告，并按原始日期标注。

编制说明：覆盖版本与发布、组件与代码共建、成员单位与厂商适配、生态与社区、趋势观察五个维度。周合计口径以 GitHub 检索补强核验（org flagos-ai，合并日期 10-12 00:00 至 10-16 23:59，北京时间）：合入 PR 385 笔、新开 PR 525 笔、窗口内有更新的在审 PR 338 笔；仓库总数由 55 增至 61。五期日报按其各自窗口累加则为提交 453 笔、合入 364 笔（各期窗口首尾相接，含 10-12 期覆盖的周末 44 小时）。

一、本周要闻

  • FlagQuantum 0.3 线完成收口：0.3.0 与 0.3.1 同日发布（10-16）：0.3.0 于北京时间 13:34 发布（PR #629），0.3.1 于 19:20 发布（PR #634），两者均晚于当日日报 06:00 截点，属本报告补强核查补录。0.3.0 为 0.3 线稳定包——Python 3.10 至 3.12 的 Stable ABI wheel、Linux x86_64 / macOS arm64 / Windows amd64 三平台制品、九鼎与 Quafu 可恢复作业（含可选回执与有序多电路结果）、六课工作坊中英双语版本；0.3.1 追加 flagquantum.services 本地研究能力服务（类型化请求校验与估算、本地 CPU 操作、两比特 Pauli-sum 基态 VQE 路径及版本化证据包），并保持 0.3.0 公共 API 不变。自 10-10 rc1、10-10 rc2、10-11 rc3 三个候选版到正式版收口，全程 6 天。
  • FlagOS 2.3 周期开线并进入实质提交（10-13 ~ 10-15）：community #126 于 10-13 合入 2.3 日程——FEP 合入截止 2026-11-13（硬门禁）、特性冻结与 rc0 11-30、rc1 12-07、rc2 12-14、封板 12-25、GA 12-30；冻结规则明确 “GA manifest 只接受 existing-tag 发布源”，并宣布 2.2 的”主干截止时间”兜底口径为一次性特例、不再沿用。10-14 22:35 至 10-15 01:49 一晚开出 11 份 FEP（#139 至 #149），覆盖离线安装器、vLLM 0.28 十平台兼容、SGLang 0.5.18、Megatron 三模型与 ViT 训练、TransformerEngine 上游插件迁移、Compressor 校准量化、LightX2V 生成插件与 Torch-FL 覆盖能力；10-15 对应的离线一键安装器在 build-infra #1348 合入（+1085 行，安装期 pip install --no-index 零网络依赖）。
  • 昆仑芯路线三级跳：去 CUDA-boxing、转原生 XPU、进入 XPU3 批量（10-12 ~ 10-14）：Torch-FL #502 以 47 文件 +5347/-2443，把 10-11 刚落地的 CUDA-boxing 方案整体替换为原生 XPU 路线（原生 kKunlunxin 后端槽、纯 C 的 libxpurt 设备层、基于 xdnn 的算子层），#503 同日挂上 P800 CI 车道，#504 在 24 小时内把车道转绿，#507 / #508 完成后端键修正与构建测试合并。10-13 起 FlagGems 单日开出 14 笔 XPU3 批（能力门控基础设施 #7098 与算子实现 #7103 至 #7117），FlagTree 同日发布 0.7.1a1+xpu3.6 构建线——接入、批量实现、CI 托管三段在一周内齐备。
  • Torch-FL 成为厂商接入统一入口：一周落地五条新路线（10-12 ~ 10-15）：清微「FlagGems-only」算子路线（#492 / #493）、昆仑芯原生 XPU（#502）、天数智芯 Iluvatar「FlagGems-primary」后端（#514，+3805/-40）与其原生 vendor 后端（#527，ixdnn / ixblas C ABI，+3022/-174）、清微集合通信经 FlagCX 打通（#536）、Apple Silicon Metal / MPS（#516 / #528，成为第 11 个加速器）。同时 CI 层收敛为配置驱动矩阵与变更感知路由（#519 / #521 / #534），并开启硬件无关的运行时一致性契约套件（#497，35 文件 +1947/-91）。

二、版本与发布动态

FlagQuantum 0.3 线：三连候选版到两个正式版

  • rc1（10-10 14:42）：0.3 系列首个候选版，打包电路组合与输出 API 扩展、梯度与向量导数 API、OpenQASM 导入、编译器优化级别、分布式工作流与九鼎 / Quafu 提供方指南更新。
  • rc2（10-10 20:38）：引入 cp310-abi3 wheel（覆盖 Python 3.10 至 3.12），原生 CPU 扩展对齐 PyTorch 2.10 Stable ABI 基线（运行时在 2.13 / 2.14 验证通过），自带 flagquantum-compiler-qsteed 0.2.0。
  • rc3（10-11 08:52）：每平台单一 cp310-abi3 wheel，完成 MSVC 可移植性修复（Stable ABI 标志注入、OpenMP SIMD、bit lookup），Linux / macOS / Windows 三平台流水线验证通过。
  • 0.3.0 正式版（10-16 13:34）：0.3 线稳定包，含三平台 Stable ABI wheel、PyTorch 优先的量子模拟 / 训练 / 远程执行、九鼎与 Quafu 可恢复作业（可选回执与有序多电路结果）、六课工作坊中英双语版。
  • 0.3.1（10-16 19:20）：追加 0.3.0 制品构建之后获批的本地研究能力服务——flagquantum.services 发现与描述、类型化请求校验与估算、本地 CPU 操作执行、结构化证据校验，附两比特 Pauli-sum 基态 VQE 路径与版本化证据包；发布说明明确本次不含由化学规格构造分子哈密顿量、不含量子硬件执行、不含 MCP server 与 agent runtime（MCP 适配器为独立包另行发布）。
  • 工程支撑：周内 FlagQuantum 合入 13 笔，包括 QCIS 静态导入器（#622，110 项测试通过）、Quafu 多电路单作业提交（#627）、量子比特序与加速器支持文档（#628）以及两个发布 PR（#629 / #634）。

六、趋势观察

  • 发布节奏从”版本发布”转向”发布火车加每日交付”：2.3 日程把 FEP 截止、冻结、三级候选版与 GA 写成硬性时间表并废除 2.2 的一次性兜底口径；build-infra 把打包 ref 钉到 release-2.2 正式标签、把 wheel 记账接成流水线钩子；FlagTree 改用”仅日期”版本号的每日轮子并支持当日手动重跑；FEP-0139 离线一键安装器让断网主机一条命令部署。四类动作合起来，意味着对外交付的单位正从”版本”变成”可持续可离线的制品流”。
  • Torch-FL 固化为厂商接入的标准入口：一周内清微、昆仑芯、天数、清微集合通信与 Apple Silicon 五条路线进入同一仓库，模式清晰可复用——一个新后端槽位、一条 CI 车道、一套打包与回退保护（失败算子路由 cpu_fallback）、一份硬件无关的一致性契约。厂商接入从”逐项目定制”变成”按规范落地”，这将直接压缩 2.3 周期接入新芯片的前置成本。
  • 昆仑芯案例显示后端路线的话语权已经上移：CUDA-boxing 方案落地不足一天即被判定不合规并整体替换为原生 XPU，随后 24 小时内补 CI 车道、跑绿、修首跑问题。这不是单纯的工程速度，而是治理规则（后端须直连厂商运行时）对短期可行方案的否决权——同类判断在 2.3 的 FEP 评审中预计会更常见。
  • 编译侧成为最大变量，方向从”多后端”走向”统一 IR 与可移植内核”：FlagTree 的 FlagMega 从 BI-V150 单点优化扩展到 RDNA 与 Ada，同一份 cooperative megakernel 在真实 Qwen3-1.7B 上跑通 decode 与 prefill；TileIR 升级 CUDA Tile IR 13.4；Trident 以 MLIR / LLVM 加 TVM FFI 做前端编译桥；进迭时空提交 smt_rvisa eDSL。四条线指向同一个问题——能否用一套中间表示同时喂饱多种芯片，这将是 2.3 周期技术叙事的主线。
  • Day-0 适配已沉淀为成员单位的对外资产与运营抓手：MiniCPM-V 4.7 十二平台当日覆盖、沐曦与清微当晚发稿、天数次日官宣，Step 5 Preview 四家同日；随后挑战赛把”跨芯优化”转化为面向全球开发者的赛事。适配能力不再只是内部指标，而是可对外发布、可招募开发者、可换取算力投入的品牌资产。
  • 组织边界仍在扩张，且开始补齐质量与治理底座：一周新建 6 个仓库（编译桥、测试设施、视觉、语音音频），版图从大模型算子向多领域工具链延伸；与此同时 optest 落地、ops-test 工作流跨仓铺开、周测修复与四平台一致性 CI 并行，community 把贡献者隶属与治理角色写成 people.yaml / projects.yaml 单一事实源。扩张与治理同步，是本周区别于此前放量期的结构特征。
  • 下一观察点：大会（10-17 / 18）现场发布物与大会后首期日报；FlagOS 2.2 公开版本与量智云平台的实际交付形态；2.3 首批 FEP（#139 至 #149）的审阅与合入进度（截止 11-13）；FlagMega AMD / Ada 五连与 PPU 修复的合入节奏；FlagTree 每日轮子的实际落地形态（版本号与发布站）；vLLM 0.28 剩余三线（MUSA / 玄铁 / S60）的合入顺序；MiniCPM 挑战赛的参赛规模。
