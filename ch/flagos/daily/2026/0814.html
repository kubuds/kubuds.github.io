FlagOS 每日动态报告（2026-08-14）

2026-08-14 苦芽科技

调研窗口：过去 24 小时（2026-08-13 10:19 ~ 2026-08-14 10:19 北京时间） 信源：GitHub（org: flagos-ai）、Google News 聚合（中英文）、HN、智源社区等（详见附录）

一、开源项目进展（GitHub 动态）

窗口总览：org 内 52 个仓库中 16 个在窗口内有推送，commit search 命中 46 条窗口内提交，无正式 Release（距 FlagOS 2.1 已 7 周余）。本窗口三大主线：FlagAttention 多后端 runtime 架构落地（一次性铺开 8 个芯片后端）、PyTorch-Plugin-FL 以 Torch-FL 名义完成 org 级更名整合、FlagGems 持续高频（19 条提交，KernelGen NVIDIA 算子与 KMCompiler 昇腾/天数智芯算子双线推进）。

1.1 FlagAttention：多后端 runtime 落地，8 个芯片后端一次铺开

来源：FlagAttention PR #48、FlagAttention commits

  • “add multi backends”（#48，8 月 13 日 12:18 合入）：新增 src/flag_attn/runtime/backend/ 统一后端抽象，一次性建立 8 个后端包——_ascend（昇腾）、_enflame（燧原）、_hygon（海光）、_iluvatar（天数智芯）、_metax 与 _mthreads（沐曦两系）、_nvidia。FlagAttention 从 NVIDIA 单后端 Triton attention 算子库走向 FlagOS 全芯片 attention 算子库，与 FlagGems 的多后端模式对齐。这是本窗口最重要的架构事件，后端清单与 FlagOS 成员单位芯片几乎一一对应。
  • 配套提交：08-13 02:55-04:07（UTC）的 “add multi backends / add copy right / fix” 三条为 #48 的开发过程提交。

1.2 Torch-FL：org 级更名整合（PyTorch-Plugin-FL → Torch-FL）

来源：.github commits、Torch-FL commits

  • org 官方 README（英文 + 中文）将 PyTorch-Plugin-FL 全部替换为 Torch-FL（8 月 13 日 18:44/18:45 替换、21:25 修正链接）：PyTorch-Plugin-FL 正式以 Torch-FL 名义进入 org 主线（Torch-FL 仓库 README 的 CI badge 仍指向旧仓库名，说明迁移尚在进行中）。Torch-FL 定位为 FlagOS 的 PyTorch 设备插件，暴露统一 flagos device，按算子路由到可复用原生 kernel、编译器 kernel、厂商原生实现与显式 CPU fallback。
  • 修复 #99（14:54）：非全局 swap 模式下保留 module parameters；
  • docs #101（14:56）：新增实测算子支持报告（measured operator support report）。

1.3 FlagGems：19 条提交，KernelGen NVIDIA + KMCompiler 昇腾/天数智芯双线

来源：FlagGems commits

  • KernelGen NVIDIA 算子新增（8 月 13 日 13:06-14:22）：max_pool3d_with_indices_backward（#5264）、ormqr（#5252）、heaviside（#5120）、leaky_relu_backward（#5145）、_scaled_dot_product_attention_math（#5168）、_native_batch_norm_legit_no_training（#5243）；另有 hardswish（#5139）、absolute_（#5187）、arctanh（#4818）三个算子从生成区 “Move to ops” 正式入册——KernelGen 生成算子进入正式维护列表的收尾动作；
  • KMCompiler 算子（8 月 14 日 10:19-10:22）：linalg_cross（#4850）、linalg_solve_triangular（#5201）新增；昇腾 pairwise_distance 后端 + 天数智芯 Iluvatar CPU 引用错误修复（#5394）——昇腾与天数智芯双后端同条提交推进；
  • flagtree 依赖正式化：#5444 Bump flagtree version for NVIDIA（15:26）；#5433 昇腾 backends.yaml 更新 flagtree ascend whl 至 0.6.1（17:13）——昨日”FlagTree wheel 分发体系”判断兑现：FlagTree wheel（含昇腾 0.6.1）已成为 FlagGems 各后端配置的正式依赖组件；
  • 修复与工程：empty 零元素处理（#5438）、nested_view_from_buffer_copy 精度修复（#5324）、xor/ixor 拆分并注册（#5283）、cat cpp wrapper 路径与 dtype 修复 + rwkv_mm_sparsity 精度（#5388）；fused_marlin_moe 内核按精度方案改名并拆分基准（#5437，10:28）。

1.4 FlagGems-vllm：沐曦 MC550 的 mthreads 后端进 Fused MoE

趋势判断：本窗口最大信号是 FlagAttention 一次性铺开 8 个后端（ascend/enflame/hygon/iluvatar/metax/mthreads/nvidia）——attention 算子库成为继 FlagGems 算子库、FlagCX 通信库之后第三个”全芯片覆盖”的组件，且后端清单与成员单位芯片映射高度一致，证明 FlagOS 的多芯片适配正从”逐芯片外挂”走向”统一 runtime 抽象”的架构化阶段。另一信号是 Torch-FL 更名整合：PyTorch 插件层品牌统一为”flagos device”单一抽象，与 FlagTree wheel 合并（FlagPrism 独立）、build-infra packaging 重构共同构成”组件化 + 品牌统一”的发布前整理。经营面上海光、天数智芯业绩向好，成员单位基本盘稳固。

四、总结

  1. FlagAttention 多后端 runtime 落地：#48 一次合入 8 个芯片后端包（昇腾/燧原/海光/天数智芯/沐曦×2/NVIDIA），attention 算子库全芯片化，是 FlagOS 多芯片架构的关键一步。
  2. Torch-FL 官方更名整合：org README 全面替换 PyTorch-Plugin-FL 为 Torch-FL，”flagos device”单一设备抽象成为 PyTorch 插件层的统一入口。
  3. FlagGems 双线高频：KernelGen NVIDIA 算子 6 新增 + 3 入册、KMCompiler 昇腾/天数智芯算子 3 连发；flagtree wheel（NVIDIA bump + 昇腾 0.6.1）成为各后端正式依赖，昨日”wheel 分发体系”判断兑现。
  4. 沐曦 MC550 持续深入：FlagGems-vllm Fused MoE 新增 mthreads 后端并调优 MC550，编译（FlagTree METAX 特化）、分发（MACA wheel）、算子（vLLM 场景）三线齐头。
  5. 新闻头条：Qwen3.8-2.4T-A95B 开源 + FlagOS 社区多芯片适配（新浪财经口径），延续”模型开源即快速多芯片适配”的 FlagOS 生态节奏；成员单位海光中报、天数智芯扭亏为经营面亮点。
  6. 发布侧：无正式 Release；build-infra packaging 重构 + FlagGems-vllm v0.1.1-rc 稳定线，组件化版本发布仍在酝酿（距 FlagOS 2.1 已 7 周余）。

局限性说明：Qwen3.8 多芯片适配条目以新闻口径为准，GitHub org 窗口内暂未见显式适配提交；gnews 跳转链接无法抓取正文，新闻细节依赖标题与多源交叉印证。
