今日重点：Torch-FL v2.10.0 发布落库——FlagOS 2.2 清单最后一项补齐（09-29）

日期：2026-09-29　来源：Torch-FL v2.10.0 Release、community #124、community #125

09-28 日报中 2.2 清单（24 项）的「唯一留白」Torch-FL 在本窗口落库——12:34 / 17:01 两个候选标签（v2.10.0rc1 / rc2）先行演练发布流水线，18:17 建立 Release、18:20 正式发布：

  • 发布内容：torch-fl 是 FlagOS 的 PyTorch 设备插件——将逐算子路由（原生厂商内核 / FlagGems 可移植内核 / CUDA 兼容 boxing / CPU 兜底）统一到单一 flagos 设备之下，同一 PyTorch 程序不改代码跨九类加速平台运行：NVIDIA（A100 / H800）、昇腾（910C）、海光（BW1000）、沐曦（C550）、达摩院玄铁（ZW810E）、摩尔线程（S5000）、燧原（S60）、昆仑芯（P800）与地平线系 BPU（s600）。
  • 版本与打包：自本版本起版本号跟随所绑定 PyTorch 小版本线（本次 >=2.10,<2.11）；wheel 命名为 torch_fl-2.10.0+<sdk>（如 +cuda13.3 / +dtk2604 / +cann9.0.0），「一个标签、每平台一个制品」；wheel 自描述（compatibility.json 记录平台、内核集、构建 ABI 与 FlagTree / FlagGems / FlagCX 钉版），并随附 torch-fl-preflight 校验 CLI（免导入 torch_fl 即可检查环境）。
  • 验证口径：DDP 与 FSDP2 在主流卡全部通过；torch.compile 将 flagos 注册为一等 inductor GPU 设备（FlagTree 后端覆盖六家、燧原走厂商 Triton、BPU 走板载编译器）；profiler 对齐 CUPTI（含各家专用 tracer）；跨平台基准（Qwen-Image-2.1，单卡 1024²、40 步）中 H100 原生 6.52 秒/图对照 FlagOS H100 10.67、摩尔线程 S5000 14.87、海光 BW1000 23.59、昇腾 910C 24.94、沐曦 C550 31.61、达摩院玄铁 ZW810E 37.44、燧原 S60 58.04（图像质量与 H100 对齐，CLIP-Score 偏差在 ±1.6% 内）；纯 CPU Arm 路径（Mac M5 Pro）取得对标 PyTorch CPU 1.74 倍的加速。
  • 三项新能力：新芯片后端接入 skill（本周期 T-Head ZW810E 与昆仑芯 P800 即按此路径引入）、boxing 路径的 FP8 / FP4 软件模拟（无 FP8 硬件可用）、算子级自动选路调优。
  • 边界说明（发布物自带）：torch.compile 各后端仍为实验特性；昆仑芯 P800 的 profiler / RNG 与 compile 尚在路线图；flex_attention 本版未支持；BPU s600 仅作 torch.compile 图设备（eager 落在 CPU）。
  • 体量：自 v0.1.0 起累计 269 笔提交（62 特性 / 101 修复 / 11 性能 / 25 CI / 18 文档 / 16 测试 / 10 重构 / 4 构建），HuggingFace 100+ 模型在矩阵各板验证。

判断：至此 2.2 官方清单全部 24 项均有对应发布物落库（清单中 Torch-FL 条目的审查快照仍为 pending，属预期，待下一修正批次刷新）；「标签 → Release → wheel → 镜像」四类制品链在本窗口闭合。

四、总结与趋势观察

  1. 2.2 收口完成：清单 24 项全部落库——Torch-FL v2.10.0 于窗口内发布，最后一项补齐；「修正 → 重建 → 复发布」纪律三连（#123 六库源修正 → #124 两库截点对齐 → #125 FlagScale 修复纳入）在 12 小时内完成闭环。
  2. 发布工程成为显性能力——Torch-FL 一天内走完 rc1 → rc2 → 正式发布，配套发布线多笔迭代（标签驱动构建、厂商自有 runner、并发上传重试、发布顺序修正）；wheel 自描述 + preflight 校验——发布物从「能装」走向「可验证、可追溯」。
  3. 开发线全面转入下一周期——FlagGems-Experimental alpha 升至 5.5、FlagGems-vllm 0.3.0-dev1（前窗口）、vllm-plugin-FL 面向新模型（Qwen3.8-Flash / GLM5.3-Flash / MiniCPM-V 4.7）与新硬件（CoreX BI-V150、P800 升级）的开放 PR 密集评审——发布冻结结束后，适配线重新加速。
  4. 三条主线在窗口内同频——KernelGen 算子覆盖（16 笔入主库）、厂商平台化优化（昇腾 / 海光 / 沐曦 / 燧原各有专门批次，FlagFFT 双优化分支）、量子系统栈（FlagQuantum 25 笔）——与 10-17 大会的 AI 系统 / 量智融合专场主题同向。
  5. 新闻侧第 23 个平静窗口与产业侧落子并存——代码侧驱动、会议节点叙事的格局延续；摩尔线程无锡案例（六智能体 + 满载标杆）是「国产算力商业化」叙事的新样本，与 Torch-FL 发布物中的 S5000 数据互为印证。
  6. 下一观察点：community 清单对 Torch-FL 条目的快照刷新、2.3 开发线合流（FlagGems 5.5、FlagGems-vllm 0.3.0、vLLM 0.28 适配）与 10-17 大会的对外发布物。
