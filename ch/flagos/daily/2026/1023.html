1.3 FlagQuantum：53 笔提交、20 笔合入，原生 Rydberg 从契约变代码（10-22）

日期：2026-10-22　来源：FlagQuantum 提交 · PR #700 · PR #707 · PR #714

  • 总量：53 笔提交、20 笔合入，提交占全组织 40%，合入居第二。与上一期（84 笔提交、34 笔合入）相比规模减半，但性质变了：上一期是动态电路的 Program IR 与出图补链，本期是中性原子物理从文档落到执行。
  • Core 前端（#700，22 文件，+2198/−16）：原生 Rydberg 控制不再借用线路适配，而是由 Core 直接在 ProgramRecord 上提供前端。记录增加类型化的 context 与 control 字段，既有验证器只接受一个物理 profile 并复用 CFG/SSA 检查；连续路径安全用编码坐标上的精确算术判定，与数值演化解耦；源编码复用既有标量编解码器，原生专用的严格字段与规范检查在任何张量解码之前就拒绝非法输入。未引入新的 IR 层级、绑定器、求解器、注册表或根导出。
  • 用户 API：RydbergProgram 以原子、位点、长度与时间单位、C6、损耗率、最小间距、传输通道与驱动通道构造，提供 move、pulse、to_ir 三个动作，示例输出原子标识 ('a','b')、维度 (3,3)、受控位置 (3.0,0.0) 与存活算子形状 (9,9)。PR 明确写明「受控位置不代表物理存在」。
  • Simulation（#707，19 文件，+1488/−188）：原生 Rydberg 程序可以走既有的 Lindblad 计划、运行与初始密度伴随入口，用户声明原子、线性传输、脉冲与吸收损耗，Simulation 自行装配区间矩阵；plan 1.7 密封为恰好七个外层字段，运行时不重新编译源。实验性数值路径为 CPU-only、一至两个 g/r/lost 角色，更大规模在指数级内存分配前拒绝；几何是施加线性路径的区间中点近似，网格收敛证据与求解器精度分开记录。
  • Examples（#714，3 文件，+217）：训练两个脉冲幅度绑定并让原子对移动，40 步、128 区间的实测输出为：无条件 RR 由 0.0431 升至 0.1228，存活条件 RR 0.1500，no-flag 选择 RR 0.1439，精确数值回放成立。本地默认全量 14,584 通过、167 跳过，约 518 秒；首轮 64 区间曾在 2.28e-10 上失败一个梯度，细化到 128 区间后通过且未改求解器与断言。
  • 判断：一天之内，量子栈把「能声明原子与脉冲」到「能算动力学」再到「能训练控制参数」三段接上，且每一段都写明能力边界（不宣称采样事件、反馈、加热、量子运动、GPU 或分布式，也不宣称 M3 完成）。这是本季最有信息量的单仓推进方式：先把契约写成可拒绝的实现，再逐块放开。

四、总结与趋势观察

  • 产能结构：FlagGems 一家吃掉 56% 合入，量子栈吃掉 40% 提交，构建与运行时各一成。合入量创近一周新高而提交量下降，说明当日的主旋律是消化积压而非扩张，这与 10-20、10-21 连续两日大额合入之后的状态一致。
  • 2.3 周期的第一格：FEP-0140 与 FEP-0141 在 10-21 合入，10-22 海光就把 vLLM 0.28.0 与 SGLang 0.5.18 两个版本同时落地。这条链路从「把矩阵写进文档」到「第一条实测通过」只用了一天，是本季最快的需求到证据闭环。剩下的九家与两条版本线是此后六周的主工作量。
  • 构建层收敛：昆仑芯成为 FlagTree 第七后端、flagcx 0.14.0 钉到二十个后端、optest 变成可安装包。三者合起来的效果是「换后端时不再改安装脚本」，这比任何单点性能提升都更能决定 2.3 的交付速度。
  • 可观测性成为新短板：清微第一次有设备时间线，昆仑芯跨卡拷贝此前一直静默失败。这两件事提示，多后端在「能跑」之后的第一道坎是可观测与可复现，而不是更快；过去两周的测试移植与用例契约改造（lukatao 一人 61 笔）正是同一判断的另一种表达。
  • 风险点一：FlagQuantum 的 20 笔合入全部由单一账号完成，且新增的原生 Rydberg 路径只覆盖 CPU、一至两个角色。物理语义的验证依赖同一批人写测试与实现，外部无法独立复核；提案 083（终端采样）尚未批准，若快速推进，会同时改动 Runtime、测量结果与随机源三处。
  • 风险点二：燧原 #7077 这类「整批更新」缺少可核对明细，26 文件与 +3520 行无法对应到具体算子与具体收益；昆仑芯融合 MoE 的三项性能又以替代基线测出。两者都会让后续的跨厂商对比失真。
  • 观察点：vLLM 0.28 的下一个厂商（清微或沐曦）是否复用海光的 empty 后端模板；FlagTree 0.7.1 开发构建（10-20 的 0.7.1.dev1）是否在 2.3 前转正式版；TransformerEngine-FL 的三笔 NPU PR 能否在周末前合入；地平线与寒武纪的静默是否延续到下周周报。
