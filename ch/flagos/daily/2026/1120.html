今日重点：寒武纪 Neuware 4.7.6 一天打通三层，2.3.0 底座新增最新一条 SDK 线（11-19）

日期：2026-11-19　来源：#1906 · #1907 · #1909 · cambricon-neuware4.7.6 变更记录

  • 三层同日：#1906 加 base 层（ubuntu:24.04），#1907 加 FlagCX 构建行，#1909 加 runtime 层与变更记录。三笔在北京时间 06:02 至 06:47 之间先后合入。
  • 版本口径：工具链是 cntoolkit 4.7.6、cnnl 2.2.18、cnnlextra 2.5.0 与 mluops 1.13.0。通信与视频侧为 cncl 1.30.10、cncv 2.12.1、cnclep 1.5.0，监控是 cnmon 6.5.52。变更记录写明这条线是该厂商最新一条 SDK 线，4.7.2 继续在役。
  • 运行时栈：Python 3.12，torch 2.13.0+cpu、torch-mlu 1.34.1、torch-mlu-ops 1.13.0，配 torchvision 0.28.0 与 torchaudio 2.11.0。编译器用 vendor Triton 3.4.0+mlu2.1.3。这条线不装 FlagTree，Triton 是唯一编译器。
  • 为什么拆三笔：4.7.6 的三个 pip 依赖还没齐，涉及 torch-mlu 1.34.1、torch-mlu-ops 1.13.0 与 flagcx 0.14.0+neuware4.7.6。它们要等 flagos-pypi-cambricon 补齐。base 先落，FlagCX 构建行与 runtime 各走一笔。
  • 一个容易漏的修正：新行复用 cambricon 标签。没有这条覆盖，矩阵会回落到默认的 h20 runner，而寒武纪节点不带这个标签，任务会一直排队。
  • FlagCX 为何单独 recipe：4.7.6 的 deb 文件名与 4.7.2 不同，cncl 是 1.30.10、cnnl 是 2.2.18，都不从行键推导。recipe 沿用 4.7.2 的 ubuntu:22.04 自包含形态，wheel 最多链接 glibc 2.35；default_for_vendor 先留 false，等节点验证过再切换。
  • 观察：与 11-18 沐曦换线是同一手法，base 先落、runtime 跟上、索引补齐再补轮子。沐曦那天用了六笔，寒武纪这次三笔。距 rc0 的 11-30 还有十天，底座层仍在逐条把清单对齐。

今日重点：BIS 新规生效引发国产算力股集体重挫，燧原跌停后公告「在手订单充沛」（11-19）

  • 三处收紧：海外数据中心向 D:5 国家组企业提供累计超过 1200 万 TPP 的算力须申请许可；印尼、马来西亚、新加坡、泰国、巴西五国纳入许可范围；16/14 纳米及以下 FinFET 逻辑芯片，代工厂不能再靠晶体管计数自行核验来推翻 3A090.a 的受控推定。
  • 第三条是关键：设计企业必须进入 BIS 的「Approved IC Designer」名单，代工厂才能接单。这条在生效前的最后两个交易日里没有被充分定价。
  • 盘面：11 月 19 日燧原科技 20% 跌停封死，收 364.33 元，跌 91.08 元，成交 19.62 亿元，换手率 28.35%。沐曦、摩尔线程、海光信息、盛科通信与港股天数智芯同日下挫，盘中跌幅多在 10% 以上。
  • 反向一侧：同日中芯国际 A 股涨 4.38%，华虹宏力涨 7.47%。资金没有离开国产算力，只是从设计端挪到制造端。
  • 传闻与证伪：11 月 18 日晚起有传闻称三星穿透严查代工，19 日一份点名各家代工依赖的截图流传，称天数智芯、翱捷科技、燧原科技对台积电依赖最大。上海证券报向多方求证后报道，三星并无严查代工的正式文件，传闻不准确；14/16 纳米订单过审确定性较高，5 纳米及以下逐案审批。翱捷科技同日回应，取得 ECCN 分类编码、确认不属限制范围的芯片可正常流片。
  • 与 FlagOS 的关系：被点名的公司里有五家是 FlagOS 成员单位，包括燧原、沐曦、摩尔线程、海光与天数智芯。这次波动不涉及任何组件代码，但成员单位的资本市场环境在同一天内一起变化。
  • 观察：市场把「许可制」交易成了「一刀切」。真正被改变的是境外先进制程通道的商业确定性，而不是当日的产能。国产算力「设计已国产化、制造还没有」这条结构性事实，第一次被一次传闻摆到台面上。

1.4 燧原厂商文档一次纠了三处口径，ECCL 的 64 位限制与算子限制分开记（11-19）

日期：2026-11-19　来源：#1916 · #1915

  • 过期口径：厂商页还写着 enflame-tops1.9.10 与 tops1.10.6，而矩阵早就换成 tops1.9.29 与 tops4.1.6。这次一并改掉，并补上 4.1.6 对应的 L600 芯片。
  • ECCL 版本无关：两条线的 ECCL 版本是 3.6.3.13 与 4.1.4，互不相关。文档此前暗示两者同源。
  • #1915 的证据：fp64 与 int64 的 all_reduce 在 MIN 与 SUM 上都失败。这是 ECCL 的 dtype 边界，不是某个 SDK 版本的回归。
  • 两堵不同的墙：TORCH_GCU_ENABLE_INT64_AND_UINT64 与 ENABLE_I64_CHECK 只管 kernel 代码生成。打开它们不会让集合通信接受 64 位类型，文档现在把这条写明。
  • 证据分级：1.9.10 与 1.10.6 在本仓库实测，1.9.29 来自 issue 且未在此复现，4.1.6 尚未验证。三级分开标注，不再混在一起。
  • 观察：这是一次口径治理。同一份文档里既有版本号过期，也有把两堵墙当成一堵的推论错误，改法是把证据来源也标出来。

1.7 FlagGems：昇腾 A5 架构探测与 950DT/950PR 脚手架合入（11-19）

日期：2026-11-19　来源：#9543

  • 问题：昇腾世代没法用通用查表区分。NPU 上 props.major 是 None，而 910B 与 950 的 SoC 名都以 9 开头。
  • 第一处改动：后端框架开放 get_arch_key 钩子，厂商可以自己接管架构判定。返回的键去索引 ARCH_MAP，返回 None 则继续走通用 kernel。
  • 第二处改动：昇腾厂商层声明 ARCH_MAP = {"a5": "a5"}，910B 系列仍是基线，不需要条目。ARCH 环境变量优先，别名包含 a5、ascend_a5、950、ascend_950；否则按驱动上报的 SoC 名做子串匹配，950 一个标记覆盖所有 SKU。
  • 降级：CPU-only 构建或驱动不可用时返回 None，通用路径不受影响。
  • 脚手架：新建空的 a5/ 与 a5/ops/ 包，作为后续 A5 算子特化的落点，并预留按架构的 tune_configs 与 enable_configs。
  • 观察：这一笔没有加任何 kernel，只把检测和位置准备好。同一天 FlagGems-vllm 在 ascend-a5-ops 分支合入了第一个 A5 算子，两条线在做同一个准备。
  • 附注：A5 对应 Ascend950DT 与 Ascend950PR，NpuArch 为 DAV_3510。

1.8 FlagGems-vllm：v0.2.1.dev1 打版，A5 首个算子提速约 4.5 倍（11-19）

日期：2026-11-19　来源：v0.2.1.dev1 · #1338 · #1321

  • 打版：v0.2.1.dev1 于北京时间 10:27 发布，发布说明只有一句「Release version 0.2.1.dev1」。同日 FlagTree 的 CI 把 HCU 的 gems-vllm 基线升到该版本。
  • A5 首算子：#1338 给 950DT 加 topk_softplus_sqrt 的持久化分块实现，落点在 ascend/a5/ops/。256 专家、bf16、topk=6 下，4096 token 从约 250 微秒压到 55 微秒。
  • 为什么快：每个 program 负责 BLOCK_M 个 token，用一次宽 tl.load 取整块分数；grid 按 AIV 核数封顶（950DT 回退 96），启动开销不再随 token 数增长。
  • 两种写回：宽块按 rank 直接写 HBM，窄块先拼 [BLOCK_M, BLOCK_K] 再连续写一次。索引取最大值的专家里最小的 id，保留原有并列语义。
  • 910 侧同日对齐：#1321 把 A5 的 KDA kernel 移植回 910，并把基准改为对厂商 AscendC 算子取值。移植时改了两个常数：_ASCEND_BT 从 64 降到 32（910B 的 AIV 核 UB 只有 192 KB，64 需要 224 KB），Neumann 展开从 0 改到 3。
  • 被否掉的方案：A5 的 causal_conv1d_fn 分块移植后在 (10, 4096, 4096) 上 63.9 毫秒，而 910 现版 1.20 毫秒。原因是 channel-first 分块把 BLOCK_N 卡在 32，切出 1664 个小程序。这一条被实测否掉并写进 PR。
  • 观察：这是 A5 从脚手架走向实测的第一天。同一批改动还修了基准口径。此前对 torch 循环或 vllm-ascend 的 Triton 回退取值，把加速比算高了。

四、总结

  • 底座层进入收尾：寒武纪 4.7.6 三层落地，海光补 amdsmi，昇腾 910C 改走 dispatch。17 笔合入里 11 笔是换线与修正，没有新功能。距 rc0 的 11-30 还有十天。
  • 算子层在做两件事：KernelGen 一天生成 43 个算子，同时 40 笔提交在修各家后端的精度与超时。补得快，但对齐慢，验收侧成了瓶颈。
  • A5 从脚手架走到实测：FlagGems 加了架构探测与空目录，FlagGems-vllm 在同一分支合入首个 950DT 算子并给出 4.5 倍。两条线在做同一个准备。
  • 生成式宿主成流水线：沐曦、海光、燧原三家原生宿主同日合入，三份 PR 都把未达标的数字原样留下。这个做法比漂亮的加速比更能支撑后续决策。
  • vLLM 0.32 把六家绑成同步动作：261 笔在审里最集中的就是这一波，沐曦、昆仑芯、海光、摩尔线程、清微与日出同做一件事。合入数 167 低于提交数 196，原因在这里。
  • 新闻面只有一条硬消息：BIS 新规生效当天，五家成员单位的股价一起重挫，燧原跌停后公告订单充沛。组件侧没有任何变化，但成员单位的资本市场环境在同一天一起改变。
  • 待观察：寒武纪 4.7.6 是否能赶进 2.3.0 默认矩阵；A5 算子能否在 910 上回填；vLLM 0.32 六笔能否在本周合齐；云天励飞 IFWA 的调优数据何时到位。
