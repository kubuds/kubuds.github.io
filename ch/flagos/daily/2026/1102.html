1.3 FlagQuantum：昇腾 910C 原生支持合入，167 项硬件验收通过（10-31）

日期：2026-10-31　来源：FlagQuantum PR #958 · FlagQuantum PR #970 · FlagQuantum 提交 c417d80

  • 验收数据：PR 正文记录的组合硬件运行结果为 167 passed, 293 warnings in 115.41s；其中两个集成文件分别覆盖 142 个电路、噪声、TEBD 与 QEC 用例，以及 25 个动力学用例，并含两次冷进程计划重放。另附 CPU 侧改动路径回归 1332 passed, 3 skipped in 21.04s，能力与证据字段契约测试 23 项通过。
  • 覆盖范围：complex64/complex128 态矢量、MPS、张量网络与密度矩阵；autograd 与显式梯度方法；混合训练、噪声与 TEBD；原生 Ising/Lindblad/Rydberg 动力学与仪器；QEC 预解码器训练；owner-sharded 态矢量、MPS 与张量网络训练。PR 明确说明 CPU 默认值、公开签名与 schema 版本保持不变，新增的是设备能力提案中已获批的加法式原生动力学能力。
  • 依赖边界：Torch-FL 取自 feat/ascend-complex-lowering 分支的 3aebd0c，FlagCX 取官方 v0.14.1 的 6fe3631 并附纯昇腾/FlagOS 补丁；PR 明言「已发布的 wheel 若不含这些修复不足以复现」，等于把可复现性绑定在源码提交而非二进制包上。
  • CI 侧：#970 在预置 ARM64 runner 上建 fail-closed 原生回归 lane，配套提交把原生回归所用 action 归档钉到已验证提交、在隔离 runner 镜像里保留原生 wheel provenance、用已认证 provider 覆盖继承的 wheel 版本，并让原生测试进度流式写入 watchdog。
  • 意义：此前 910C 只有实验性 split-FP32 路径的证据，这条线把量子栈的昇腾适配推到原生 provider 层，并把「硬件验收记录」写进仓库文档与 CI，而不是留在个人环境里。

1.4 FlagQuantum：单窗口 35 笔合入，合成线资源账目进入契约化阶段（10-31 ~ 11-02）

日期：2026-10-31 ~ 2026-11-02　来源：FlagQuantum PR #1000 · FlagQuantum PR #995 · FlagQuantum PR #993 · FlagQuantum PR #984

  • 总量与结构：FlagQuantum 72 小时内合入 35 笔，其中合成线 28 笔、昇腾原生支持 1 笔、CI 与工具 5 笔、仿真文档与修复 2 笔。合成线是绝对主体，且全部围绕「可提交输入、可验证语义、可核算资源」三件事。

  • 输入面：#969 提出公共 Qmod 输入与共享 Program 语义，#971 准入有界 Qmod 文件与文本输入，#985 准入原生一比特相位语句，#993 与 #994 支持有界 within/apply 作用域及其嵌套。Qmod 从内部格式变成对外可提交的输入形态。
  • 语义面：#972、#981、#982、#990 依次补上无符号相等/小于谓词、从 Python 条件一致地选值、无符号关系与链式区间谓词、原生无符号比较表达式；#974、#984、#995、#997 把谓词相位与已初始化寄存器借用组合起来，并做到不依赖临时标志位。
  • 资源面：#988 与 #989 在寄存器调用中验证 Const 借用与 fresh-output；#991 验证计算结果清理与存储复用，#992 验证本地所有权与零槽复用；#999 对已证明无进位的常量加法削减工作区，#1000 对精确 2 的幂乘法削减临时位。以 x * 256 为例，基线为 28 个分配量子位、18 个工作区位、14 个操作、深度 6、4 GiB 态缓冲；合入后为 19 个分配量子位、9 个工作区位、12 个操作、深度 4、8 MiB 态缓冲。x * 4 探针则由 14/12 分配与使用位、8 工作区位、24 操作、深度 18、256 KiB 降到 10/10、4、10、深度 4、16 KiB。
  • 边界与口径：PR 明示这些是「精确资源核算」，不是运行时加速、最优性或进程峰值内存的保证；零、一、非 2 的幂常量、两个量子操作数、以及带零下界的派生值仍走通用乘法；改动只落在 Compiler 的 lowering 一处生产文件。
  • 含义：量子合成编译器过去一个季度的主线是「能合成多少构造」，这个窗口转成「每个构造的资源账目能否被复算与回归」。这类工作的价值不在单点性能，而在于让资源预算成为可回归的契约——与主线算子库的性能补丁是两种不同性质的工程。

1.6 Torch-FL：地平线 BPU 走通卷积与池化，天数、沐曦、海光路径分头收敛（10-30 ~ 11-01）

日期：2026-10-30 ~ 2026-11-02　来源：flagos-ai 组织 · FlagQuantum PR #958 · build-infra PR #1584 · 新浪科技：AI 零帧起手写算子

  • 节奏：72 小时内 17 仓推送、256 笔提交、115 笔合入、275 笔在审。按日均折算，提交约 85 笔、合入约 38 笔，均低于上一期 24 小时窗口的 189 笔与 183 笔，周末效应显著。与此同时在审总量上升 8.7%、新开 146 笔，形成「产出降、积压升」的组合。
  • 结构：FlagQuantum 148 笔提交与 FlagQAI 42 笔合计 190 笔，占全部提交的 74%；主线算子与编译（FlagGems 16、Torch-FL 13、FlagTree 2）合计 31 笔，占 12%。周末的产出结构由量子与智能体两条新线支撑，主线依赖工作日厂商投入。
  • 发布：2.3.0 的两条镜像层（海光 DTK 26.10、AMD ROCm 7.2.4）已完成 changelog、依赖钉固与描述刷新，但 release/2.3 清单目录仍未建立、release-info 站点未列 2.3.0。按 2.2 的路径，2.3 还差清单冻结与站点上线两步，下一个工作周是关键窗口。
  • 技术方向：量子栈这一窗口的重心从「支持哪些构造」转到「资源账目能否复算」——x * 256 从 28 个分配量子位、4 GiB 降到 19 个、8 MiB 是可被回归验证的硬数字。配合 910C 的 167 项硬件验收与 fail-closed 回归 lane，量子线正在形成「语义、资源、硬件」三份可核对的证据，这比单点性能更接近工程可用。
  • 风险：FlagGems 在审 158 笔、新开 82 笔，绝大部分来自 KernelGen 批量提交，合入 18 笔与之严重不匹配。若 2.3 冻结前评审吞吐不提升，要么发布被积压拖住，要么大批算子绕开评审进主线，两者都会削弱「合入即验证」的口径。
  • 外部参照（非 FlagOS 项目）：面壁智能 10-30 开源算子生成系统 ForgeKernel，公开直播中在 B200 上经 22.5 小时、42 轮迭代把 FlashMLA prefill 从 1834 微秒压到 472 微秒，较 DeepSeek 的 518 微秒快 9.8%，并称在 CANNBench 的 A3、950DT、950PR 三榜登顶。它与 FlagOS 的 KernelGen 属同一赛道，说明「AI 写算子」已从论文指标进入公开打榜与真实框架接入阶段；对 FlagOS 的启示不在模型能力，而在评审与验证流程能否承接生成速度——这正是本期 FlagGems 积压暴露的问题。
