1.3 新公开仓库 Trident：实验性 MLIR/LLVM 编译桥（10-12）

日期：2026-10-12　来源：flagos-ai/Trident · README · 提交记录

  • 定位：Trident 是一个实验性编译桥——把包含 Triton/Torch 风格计算的 Python 函数编译为 MLIR/LLVM，再经 tvm_ffi 执行；核心为 C++/MLIR（CMake 构建、LLVM/MLIR 作为外部工程引入），Python 侧提供 trident.jit 与 trident.compile 入口，示例覆盖 add / attn / mm / softmax 等 ATen 算子下落，依赖 apache-tvm-ffi 与 torch>=2.10。
  • 时间线：仓库于 10-12 16:47（北京时间）在组织内建立并公开，master 分支提交历史可溯至 5 月中旬、累计 274 笔；窗口内 2 笔——「refactor: unify FX and Triton imports around TVM FFI」（10-12 23:10）与「test: reorganize coverage and check e2e CUDA memory leaks」（10-13 00:50）。
  • 观察：项目在 7 月完成从 torch-mlir 导入向 FX 直连 TVM FFI 的迁移，形态上属于面向多芯统一接入的”前端编译桥”探索，与 FlagTree 的统一编译器路线形成呼应；后续走向（是否与 TLE / FlagMega 线合流）值得跟踪。

四、总结与趋势观察

1. “大会前工程周”特征鲜明：68 笔合入、18 仓推送、13 仓合入，强度与节后放量期持平；但内容结构从”功能开发”转向”上线前收口”——去 boxing、CI 车道、版本标签、构建矩阵、发布文书的五类动作在 24 小时内同时出现（Torch-FL / build-infra / FlagTree / FlagGems / docs 各占一条），距 10 月 17-18 日大会还有 4 天，对外发布节奏（FlagOS 2.2、量智云平台预告）与对内工程收口同步展开。

2. 昆仑芯”去 CUDA-boxing”是本窗口最具技术含量的单笔变化：#502 以 47 文件规模把两天前刚落地的 CUDA-boxing 方案整体替换为原生 XPU 路线（libxpurt 设备层 + xdnn 算子层），随后 2.5 小时内补上 CI 车道、又于凌晨提交首跑修复——”快速试错 → 替换 → 托管”的完整闭环在 24 小时内走完，说明该组织对厂商后端的治理从”能接入”进入”按规范路线托管”阶段。

3. vLLM 0.28 适配批进入落点期：天数 / 昇腾首批合入，摩尔线程（#575 跨日高频更新）、玄铁（#574）、燧原 S60（#582）在审——上期”五线仍在审”的观察点在一天内兑现两线，剩余线仍处移动状态；这批适配完成后，各厂商推理栈将统一到 0.28 基线，为大会期间的端到端演示提供版本底座。

4. 开发线”开新面”信号密集：FlagGems 开出 5.5 开发线（v5.5.0.dev0）、FlagTree 天数构建线升至 0.7.1a1、组织新增 Trident 编译桥仓库——三者在 24 小时内同窗出现，叠加 FlagMega 在 BI-V150 上的 token 级量化优化与 TileIR 13.4 升级（#1352）在审，编译与算子栈正处于”上一交付周期收尾 + 下一周期布局”的叠加态。

5. 下一观察点：大会（10-17 / 18）现场发布（FlagOS 2.2、量智云平台与大会后的对外物料）；FlagQuantum 0.3.0 正式版（rc 三连后的收口节奏）；Torch-FL #504 合入与昆仑芯 CI 首绿；vLLM 0.28 剩余三线（MUSA / 玄铁 / S60）的合入顺序；FlagMega 分支是否转 PR 并入主线；2.3 周期 FEP 与里程碑推进。
