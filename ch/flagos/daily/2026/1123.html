今日重点：沐曦 Hy4 旗舰 Day0，并放出 FlagOS W8A8 权重（11-20）

日期：2026-11-20　来源：同花顺转沐曦官微。　另见：Pandaily。

  • 事件：11 月 20 日腾讯混元开源旗舰 Hy4。
  • 适配：沐曦曦云 C 系列当日完成 Day0 适配，并在平台上跑通。
  • 与 FlagOS 的关系：沐曦联合众智 FlagOS 社区，给出面向沐曦算力的 W8A8 版本。
  • 落地位置：量化权重上架魔搭与 Hugging Face，开发者可直接取用。
  • 沐曦口径：MXMACA 栈覆盖 40 余种框架、1000 多款模型与 6000 多个开源项目。
  • 算子面：官方称全量支持 PyTorch 2.8 的 2410 个 GPU 算子。
  • 累计数：沐曦称自 2025 年 12 月起完成 52 个模型的 Day0 适配。
  • 口径差：11 月 18 日 Hy4 flash 那篇官网稿写的是 51 个，两次差一个。
  • 测试规模：Pandaily 记的是 4 台服务器、每台 8 张 64GB C550，共 32 卡。
  • 负载：64 并发，输入约 4K、输出约 1K token。
  • 吞吐：开 decode-graph 时聚合输出 80.98 tokens/s，不开是 52.31，提升约 55%。
  • 时延：计排队后首 token 时延为 227.2 秒与 220.5 秒，开了反而更慢。
  • 上下文边界：部署配置的最大上下文是 65,536 token，远低于 Hy4 宣称的 100 万。
  • 未完成项：模型卡上两项多模态评测标的是「进行中」。
  • 许可：FlagRelease 侧标 Apache-2.0，腾讯 Hy License 1.0 把量化权重视为衍生作品。
  • 许可续：大规模 MaaS 需按原许可单独申请，不能只看分发包的标签。
  • 观察：这是 FlagOS 第一个带第三方媒体核算的商用推理案例。
  • 观察续：吞吐与时延不同向，32 卡也不等于生产验证，引用时要同时看这两个数。

今日重点：Runtime 2.3.0 三条镜像线记完账，CUDA 13.0.3 开线（11-22）

日期：2026-11-22　来源：#1951。　另见：community #176。

  • 2.3.0 记账：base 与 runtime 两侧的变更记录按厂商线分别落库。
  • 涉及三条线：ascend-cann8.5.0、ascend-cann8.5.0-910c 与 metax-maca3.8.1.3。
  • 方式：镜像内烘焙的系统包版本随标签一起记，一笔 PR 对应一个标签。
  • 校验：两个后端的版本数据校验都通过，0 失败、0 跳过。
  • 新后端：#1951 增加 nvidia-cuda13.0.3，含 base 与 runtime 两层。
  • 定位：它是第二条 CUDA 13 线，工具链小版本是 13.0。
  • 为什么加：vLLM 拉入的部分依赖按特定 CUDA 小版本预编译，社区改不了。
  • 兼容方向：CUDA 小版本只向前兼容，13.3 的 toolchain 落在 cu130 依赖的错误一侧。
  • 不变项：torch 闭包仍是 2.13.0+cu130，只有工具链移动。
  • NCCL 差异：13.3 的 NGC 运行镜像不带 NCCL，需手装并 hold 住 libnccl2。
  • 另一侧：13.0.3 镜像自带 2.28.3-1+cuda13.0。
  • FlagCX：仍停在 0.14.1+cuda13.3，是唯一链 libcudart.so.13 的轮子。
  • 验证：两条镜像在 h20 上构建并推送，容器内 torch 报 CUDA 13.0 可用。
  • 验证续：flagcx 注册为 privateuseone，import flag_gems 通过。
  • 未做：这条线还没有 app 层、状态矩阵单元格与 extras:。
  • 路线图：community #176 的 FlagOS 2.3 目标发布日期仍是 12 月 30 日。
  • 路线图续：SIG Compiler 第一项是把 Qwen3.8 与 GLM5.3 Flash 编进 MegaKernel。
  • 观察：底座层从换线转到记账，说明特性在冻结。
  • 观察续：CUDA 13 开第二条线是被上游依赖倒逼，不是主动扩矩阵。
