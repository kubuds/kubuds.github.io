今日重点：距 2.2 GA（09-28）3 天——交付范围审计启动：18 项 FEP 保留、6 项推迟至 2.3

日期：2026-09-24　来源：community #115、community #114

rc2 稳定期按官方排期于 09-24 截止，GA 定于 09-28。窗口内发布工程的主体动作从「发布物冻结」转入「范围与声明冻结」——09-24 14:29（北京时间），community 仓库开出 PR #115「docs: define delivered FlagOS 2.2 FEP scope and defer remaining work to 2.3」（分支 docs/fep-2.2-rc2-audit-20260924，当日两次推送至 16:12）：

  • 范围二分：2.2 索引含 18 项 Implemented FEP（保留）；FEP 0019、0069、0081、0084、0093、0100 六项目标版本改为 2.3、状态标记 Deferred。
  • 保留项收紧：每个保留 FEP 仅限「已实现的接口 + 已验证的配置」，其余目标移入显式 2.3 小节与关联的 deferred-work 索引。
  • 对照 RC2 更新来源：逐项更新 source revisions、API、打包细节、测试命令与关联 PR，并保留验证溯源、平台失败与已知限制。
  • 口径澄清：明确区分 Tree primitive QA 与 NVSHMEM 融合 / FlagCX-backed 融合，以及 Compressor 产物测试与全模型推理验收——避免把「组件级验证」讲成「端到端验收」。
  • 文风约束：要求简洁英文，删除模板文字与「未经支持的完成 / 性能声明」。

同期，L1 算子库十组件正式标签清单（community #114：flaggems v5.4.0、flagfft v0.2.0、flagsparse v0.3.0、flagdnn v0.3.0、flagblas v0.3.0、flagtensor v0.3.0、flagaudio v0.3.0、flagattention v0.4.0、flaggems-vllm v0.2.0、flaggems-sglang v0.1.0）仍在审（waiting merge）。

判断：昨天观察到的是「清单、标签、范围三者互为校验」，今天 #115 把校验推进到第三层——对外声明本身。GA 前 3 天不追新功能，而是把「已实现 / 已验证 / 推迟」分开陈述、逐条挂接证据。这是发布纪律动作：2.2 的公开介绍将以此版 FEP 文档为事实底稿，后续 2.3 的开发叙事（含 3D 算力、量子等新方向）也与 2.2 交付边界正式切开。

三、成员单位深挖

3.1 摩尔线程：Protenix-v2 全链路推理支持——AI4S 三场景闭环（09-24）

日期：2026-09-24　来源：IT之家（凤凰网转载）、第一财经

摩尔线程宣布，基于自主 MUSA 软件栈在训推一体智算卡 MTT S5000 上完成开源生物分子结构预测模型 Protenix-v2 的全链路推理支持。Protenix-v2 由字节跳动 Seed 团队研发（2026-04 发布），是全球少数可对蛋白质、DNA、RNA 及小分子配体复合物进行高精度端到端预测的全开源基座。实测：S5000 端到端推理性能较国际主流 GPU 平均提速约 26%，三维构象预测精度高度对齐。此次适配后，摩尔线程完成大分子结构预测、全基因组序列建模与临床医学影像三大 AI4S 核心场景的端到端工程验证。与昨日报告的 RLinf × S5000 训练侧动态相接——训练侧（具身 RL）与推理侧（AI4S）在同一周各落一子，「国产算力承接科研工作流」的场景叙事继续扩面。

3.2 昇腾：910C NPU 可见性修复与 RL 训练链就绪（09-24）

日期：2026-09-24 ~ 2026-09-25　来源：build-infra #1105、#1107、#1103、FlagGems #6654

两份 910C 配置（CANN 9.0.0 / CANN 8.5.0）在同一窗口内完成 megatron_rl 0.17.1 的 GRPO 端到端验证（详见 1.2），并以特权容器方式解决 NPU 不可见问题（Ascend-Docker-Runtime hook 未映射 davinci die 的工程故障，属「环境问题 ≠ 代码问题」的典型排查）。配套：cann9.0.0 与 cann8.5.0 两套 megatron 应用镜像 tag 2.2.0-0.2.3 记录、sglang ascend-cann8.5.0 应用页落库；算子侧 grouped_matmul 入 FlagGems 清单、FlagGems-vllm XCS 补录。

3.3 昆仑芯：XPU 大修复批与 P800 测试机迁移（09-24）

日期：2026-09-24　来源：FlagGems #6617 等（详见 1.5）、build-infra #1093

单窗口近 20 笔提交，覆盖 flash attention、GEMM（scaled_mm）、卷积系、逐元素与特殊函数、dropout 反向等方向的修复与性能快路径——是 2.2 发布前针对该平台最密集的一轮整备；测试基础设施同步迁移至 klx-p800 机型（#6617），sglang kunlunxin-xre5.37.1 应用页落库（#1093）。密集修复批与机型迁移同日出现，通常对应发布前的平台验收冲刺。

3.4 壁仞 / 曦望：SUPA 与 Sunrise 双线接入（09-24）

  • 壁仞（Biren）：SUPA 后端以「FlagGems 算子库 + vllm-plugin-FL 推理插件」双层同日进线（#6367 / #530）——与此前各家芯片的接入路径同构，属新芯片伙伴首次出现在 FlagOS 代码侧。
  • 曦望（Sunrise）：vllm-plugin-FL 将 0.2.1 的 Sunrise/PTPU patch 集移植至 vLLM 0.24 主线（#555，次日凌晨合并），修复 Qwen3.6 27B / 35B-A3B 在 PTPU 硬件上的 enforce-eager 运行，并以 14 个逐 patch 守卫避免 vLLM 0.24 API 失配导致的导入崩溃——为既有合作伙伴做「版本线跟进」。

  • 沐曦（MetaX）：FlagTree 0.7.0+metax3.6 标签落地 + SPEC cpp 后端纳入（FlagTree #1107）；FlagGems 同步更新 flagtree metax 参数（#6637）；MetaX vLLM 基准加入 CI（#1280）；sglang mthreads / hygon 应用页同日落库。

四、总结与趋势观察

  1. 发布工程进入「范围与声明冻结」：从发布物冻结（标签 / 清单）升级到范围审计（community #115）——18 项 FEP 保留、6 项推迟 2.3、声明净化为「有证据的完成度」。GA 前 3 天的动作以收口与诚实陈述为主，2.3 的开发叙事与 2.2 交付边界正式切开。
  2. 开发主线集体升位：十组件正式标签落库次日，FlagSparse 与 FlagAudio 主线即升 0.4.0、FlagAttention 版本更新——2.3 开发周期事实上已启动，与 2.2 GA 并行。
  3. 新芯片接入与版本跟进双线持续：壁仞以双层同日进线（FlagGems + vllm-plugin-FL），曦望完成 vLLM 0.24 线移植；「算子库 + 推理插件 + 编译器」三层同构接入模式重复出现，成为外部芯片接入 FlagOS 的标准路径。
  4. 平台矩阵细密度在发布前快速提升：build-infra 单夜七连发 sglang 应用页（七平台各一），FlagTree 0.7.0 变体扩至十余枚——2.2 的「平台覆盖表」仍在增密，覆盖面的可验证性是这轮发布的核心资产。
  5. 昇腾 910C 链路就绪：RL E2E 双配置通过 + 特权容器修复，为 2.2 在训练 / RL 场景的昇腾声明提供了可复现证据链（正对应 #115 强调的「保留验证溯源」要求）。
