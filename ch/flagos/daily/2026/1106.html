3.1 寒武纪：CNNL 融合注意力前向与反向，190 次回退清零（11-05）

日期：2026-11-05　来源：Torch-FL #748 · Torch-FL #749 · Torch-FL #757 · Torch-FL #754

  • 根因：SDPA 在寒武纪后端被分解成三个叶子算子，原因是 cambricon 被排除在复合覆盖之外，于是每次注意力都要把 B×H×S×S 评分矩阵写进 HBM 再读回。#748 把 CNNL 的融合前向接回覆盖，8 个文件、增 315 行减 27 行。
  • 前向之后补反向：#749 用 CNNL 的融合反向补上梯度路径，并与前向一起包成 C++ autograd Function，使一次训练调用前后两遍都走融合核。3 个文件、增 342 行减 112 行。
  • 普查式收尾：#757 不看单算子，而是先对一个完整 Qwen3 因果语言模型训练步做回退普查，找到仅剩的两个回退点——aten::mul.out 188 次与 aten::embedding_dense_backward 2 次，合计 190 次；两者改为在 MLU 上经 CNNL 执行后，同一步骤报告零算子 CPU 回退。
  • 工程细节：寒武纪代码生成器补进这两个算子，gen_vendor_confs.py 重新推导路由，使出厂配置与注册文件无法互相矛盾；#754 让 mul 的操作数留在设备上并共用运行时队列，避免中间结果往返主机。
  • 作者与工具：这三笔的 PR 正文都带 AI agent 信息段，工具为 dsh（DeepSeek Harness）与另一款编码代理，模型标注 deepseek-v4.1-flash 与 gpt-6.1-sol，人工评审统一为同一维护者。
  • 判断：从”能跑”到”零回退”是训练可用性的分界。190 次回退里 188 次来自同一个算子，说明这类收尾靠的是普查而不是猜。

3.2 燧原：GCU300 一夜清账 25 笔，NVIDIA 外部符号逐条换成本地实现（11-05）

日期：2026-11-05　来源：FlagGems #8443 · FlagGems #8442 · FlagGems #8441 · FlagGems #8429 · FlagGems #8426 · FlagGems #8417 · FlagTree #1576

  • 规模：25 笔合入，全部带 KernelGen 与 Enflame 前缀，落款同一作者；上一期新开的 41 笔 GCU300 覆盖单由此开始批量落地。

  • 改法二：换算法路径。special_chebyshev_polynomial_t 改用专用核；linalg_householder_product 用单遍反射扫；linalg_inv_ex 用单核 Gauss-Jordan；compute_linear_combination 把外积换成 tl.dot；mixed_dtypes_linear 重写打包与分块。

  • 判断：这条线的方法是把”上游写法”翻译成”本后端支持的写法”，逐条清账。代价是 PR 数量大、单笔改动小；收益是覆盖面可以在两周内从几十个算子推到上千。

四、总结与趋势观察

日期：2026-11-05 ~ 2026-11-06　来源：flagos-ai 组织 · 本期各条目的 PR 链接（见附录）

  • 一句话：这一天的主轴是”收口”——燧原把 25 笔 GCU300 改写单一次清完，寒武纪把融合注意力的前后向补齐并把训练步回退清零，社区则把 7 份 FEP 送进评审，为 2.3 的 11-13 截止备料。
  • 观察一：节奏回落，方向反而更清楚。提交 238→123、合入 167→94，但落到具体仓库都是”补完最后一段”：Torch-FL 补反向、FlagGems 清账、FlagTree 打开厂商手写核的口子。铺量阶段结束后的收口日，产出看起来少，但对可用性的推进更直接。
  • 观察二：FEP 批次是 2.3 范围的真实边界。七份新 FEP 指向同一件事——把”多后端能力”写成可验收条目：FlagMega v0.1 的 MegaKernel 编译、TLE Raw 的五后端、FlagPrism v0.2 的多后端调试、FLIR 在昇腾与 GPGPU 上的优化。全为 Provisional Draft 且都注明未跑 GPU 验收，说明这是范围声明而非完成声明；真正的硬边界是 11-13 的合入截止。
  • 观察三：版本工程开始”可审计地退役”。cuda12.8 因为 torch 2.13 不再发 cu128 wheel 而被冻结，做法是加 enabled 字段并置 false，保留规格与文档、让唯一解析器把它挡在所有矩阵之外。冻结不是删除，也不是放任——这套写法值得复用到其他后端退役上。
  • 观察四：CI 容量成了 FlagQuantum 的主要工作。27 笔提交里没有一笔是量子算法，全部是把托管 runner 的容量、镜像资格、覆盖分区与取消语义理顺。容错编译分支已有 276 个文件、3.1 万行的整合单，测试基础设施跟不上就是空转。
  • 观察五：AI agent 是主力提交者，瓶颈在评审。94 笔合入里 25 笔出自同一 agent 会话，PR 正文自带工具、模型与人工评审字段。评审侧的在审池仍有 255 笔、87 笔新开，FlagGems 与 FlagTree 两仓占六成——写已经不是瓶颈。
  • 待观：七份 FEP 能否在 11-13 前收进；FlagGems 的在审池会不会随燧原清账一起下降；FlagQuantum 的容错编译整合单何时从草稿转为正式评审；cuda13.3 这条线在 2.3.0 rc0（11-30）前是否还会再动 torch 版本。

本版订正说明

本期所载的 PPU 后端（thead-ppu* 后端键、ZW810E、PAI-DSW 镜像、PPU_SDK）属平头哥（T-Head），而非玄铁。此前版本把这条后端线写作「玄铁」，是把 2024 年从平头哥分拆、转属达摩院、只做 RISC-V 处理器的玄铁（XuanTie）与平头哥混为一谈；thead 只是平头哥沿用至今的开放品牌名。本版已逐处改为平头哥。
