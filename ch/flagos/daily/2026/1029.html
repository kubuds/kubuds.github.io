1.3 FlagGems：昆仑芯标量链融合提速十倍，燧原参考实现批量修复在审（10-28）

日期：2026-10-28　来源：FlagGems PR #7617 · FlagGems PR #7600 · FlagGems PR #7850 · FlagGems PR #7803 · FlagGems PR #7036 · FlagGems PR #7061 · FlagGems PR #7223

  • 融合内核：昆仑芯 XPU3 侧为八个出位标量链算子加后端特化（#7617，275 行）。同构 float 列表走一个融合内核：小形状单次发射、把所有指针作为内核参数带进去，大形状走流式分块；输出从一次分配加 unbind 得到，而非每张量一次分配器调用。八个算子的相对耗时从 0.083~0.126 提到 0.813~0.934，即约七到十倍。
  • 连续段内核：batch-norm 推理与 QKV 变换两个算子由「每 (n,c) 切片一个 program」改为「每 program 处理一段连续 BLOCK 元素、由平坦索引反推通道或打包行」（#7600）。聚合指标分别从 0.228 提到 1.357、从 0.260 提到 5.062；fp32 单精度那格仍低于 0.8，作者按聚合口径判定，并在正文里写明。
  • 向量化修复：masked_fill 的整数视图快路径因 arith.extsi 无向量形式整核停留在标量（fp16 0.34、fp32 0.50），改写为 x*(1-m)+V*m 的 f32 形式后 P800 上从 0.577 提到 0.829，masked_fill_、masked_fill_scalar 同步受益，594 个用例通过（#7850）。
  • 导入与执行器：昆仑芯后端在 master 最新提交上直接导入失败——_result_dtype 助手已随 #7561 从共享执行器移除，而后端仍在引用（#7803，90 行）；修掉导入后，共享执行器又报 operand #0 does not dominate this use，本笔一并修。
  • 算子覆盖：KernelGen 补 _indices_copy（#7223，250 行，H20 验证），但性能只有 torch 的 0.21 倍——属补齐覆盖率的产物，短期不能当加速项看。lighting_indexer 的参考实现改为逐头累加，峰值内存从约 8.6 GiB 降下来，修掉 40 GiB 卡上的 OOM（#5852）。
  • 在审侧：本窗口新开 53 笔，多数是 lukatao 的燧原参考实现修复（#7890 至 #7908 连号），涉及 Kaiser/inplace ldexp、aminmax、special_round、LU、vander/slogdet、median/stacking/Lanczos、Adagrad、batch-norm ABI 等；另有 AMD 侧一行修复（#7908）——AMD 的厂商描述符把设备名设成 cuda 且未给 triton_extra_name，导致 pow、tanh、exp、rsqrt、erf、gelu 等全部走 __nv_* 被 AMD 后端拒绝。

  • 训练栈：Megatron-MUSA-Titan 面向万卡集群的万亿参数 MoE，覆盖预训练与强化学习；支持 blockwise FP8、DeepEP 与 ACE 异步通信、专家并行与计算重叠，可与 slime、miles 协同（Megatron 训练 + SGLang 采样）。这是成员单位自研的 Megatron 系训练栈，与本栈的 Megatron-LM-FL 同源不同支，尚无代码回流迹象（仓库最后推送 10-16）。
  • 财务背景：同日发布三季度报告，营收 15.5 亿元、同比增长 1773.9%，实现单季度扣非盈利，前三季度营收 32.89 亿元、归母净利润 3769.73 万元，并推进港股二次上市。财报不改变本栈的技术判断，但解释了其开源节奏的投入能力。

  • 判断：摩尔线程近两周的动作集中在「训练 + 推理双栈自研开源」，与本栈的交集仍是算子与插件层（FlagGems、sglang-plugin-FL），而非训练框架层。

四、总结与趋势观察

  • 一条新路径打通：地平线 BPU 从「设计上不能 eager」变成可逐算子执行的 PrivateUse1 后端（40 个逐元素算子、440 个产物零差异），配套修了分发日志命名与 CUDA 拷贝内核守卫。这是本周期内最有结构意义的接入，但它只覆盖逐元素算子，主干仍靠整图编译。
  • 通信层进入标签与发行包阶段：FlagCX 打出 v0.14.1（按适配器生成设备位码），rpm 线从三个后端扩到六个，wheel 发布也被 build-infra 记账。需要注意该标签没有 Release 正文，与 v0.14.0 的做法不一致。
  • 发布工程在补课：changelog 上站与 Harbor、撤回两笔从未推送的寒武纪 megatron 镜像、应用页一致性检查进 pre-commit 与 CI、AMD 7.2.4 补 22.04 构建器。这些不产出新能力，但直接决定 2.3 的发布清单能否自证。
  • 在审结构变化：在审从 401 降到 288、新开从 269 降到 101，上一期 FlagGems-Experimental 的 135 笔批量提交既未合入也无新增。当前在审主体是 FlagGems 181 笔，其中 53 笔新开多为燧原参考实现修复——说明多后端验收的瓶颈在参考实现与测试口径，而不是算子供应。
  • 多分支需要区分口径：FlagGems 同时在 master 与 kernelgen-dev 上合入（#7905、#7934），FlagTree 的合入分散在 triton_v3.5.x 与 feature/flagmega 分支，FlagGems-Experimental 的默认分支是 infra-ci。按默认分支统计会低估实际工作量，按提交检索又会漏掉原子补核的仓。
  • 待观察三点：其一，v0.14.1 之后是否补 Release 说明并进入 2.3 清单；其二，BPU 路径是否从逐元素算子扩到卷积等主干算子；其三，Megatron-MUSA-Titan 的代码是否在窗口后真正开始推送，以及是否与 Megatron-LM-FL 形成复用。
