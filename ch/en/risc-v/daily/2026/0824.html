I. Open-Source Community and Software Ecosystem

1.1 Sedna: Pure-Java RISC-V emulator resumes development, evolving toward a multi-architecture framework (08-23)

Date: 2026-08-23 (README updated 23:11 Beijing; active development since 08-21)　Source: github.com/fnuecke/sedna

The pure-Java RISC-V emulator Sedna, born in 2020 (rv64imacfd + Zifencei, supports S-mode, can boot Linux, passes all riscv-tests cases, supports machine-state serialization, published on Maven Central), resumed active development in this window: the author migrated the old Z80 emulator into the Sedna framework (generalized instruction decoder generator, disk device migration, Z80 board-level integration), with the README updated at 08-23 23:11 (Beijing Time). The project’s positioning is evolving from a “single-architecture RISC-V emulator” toward a “multi-architecture emulation framework” — the decoder generator now also serves Z80 as a proof of concept, giving the JVM ecosystem an actively maintained RISC-V emulator option (beyond QEMU).

1.2 Arduino ESP32 core adds optional SHA-256 verification for OTA firmware (08-24)

Date: 2026-08-24 (03:38 Beijing, committer time)　Source: espressif/arduino-esp32 PR #12824

Espressif’s arduino-esp32 core merged feat(update): add optional SHA-256 checksum for incoming firmware (#12824): adding optional firmware SHA-256 verification to the OTA update flow, strengthening firmware integrity validation (against download corruption/tampering). Both the ESP32-C series (C3/C5/C6/C61 and other RISC-V cores) and the Xtensa series benefit; this is routine hardening of Espressif’s software ecosystem, with no breaking changes.

III. Domestic Team Updates and Deep Dives

3.1 XiangShan: Two Fixes to the COVE Confidential Computing MMU Path Merged (08-24)

Date: 2026-08-24 (00:02 Beijing, committer time)　Source: OpenXiangShan/XiangShan PR #6299, PR #6300

Two commits landed in the main XiangShan repository during the window, both targeting the MMU implementation of COVE (Confidential VM Extension):

  • #6299 fix(MMU, COVE): reject out-of-range Smmpt addresses: Previously, Smmpt43 requests exceeding the 43-bit address range were not rejected by MPTCache and were instead treated as cache misses and sent to the miss queue/table walker, rather than returning an access fault. The fix defines the PA width for Smmpt43 / Smmpt52 and the maximum legal PPN for each mode (43-bit: 0x007fffffff; 52-bit: 0xffffffffff), validates the request PPN at the stageCheck pipeline stage, returns accessFault via respHit for out-of-range requests, suppresses respMiss to prevent table walks, and clears permission / NAPOT / contiguous permission / MPT-level metadata on range faults, as well as clearing the range-fault register on cache flush;
  • #6300 fix(MMU, COVE): fix bug for mpt miss queue: The current MPT miss queue implementation violates the Decoupled protocol (twReq.valid is not gated by ready). Although no functional request loss has been observed, it was fixed for protocol compliance.

Significance: XiangShan is one of the few RISC-V open-source high-performance processor projects advancing the CoVE/MPT (Memory Protection Table) confidential computing path. Both fixes are of a “protocol compliance polish” nature, indicating that its COVE implementation has moved past functional bring-up and entered a detail-convergence phase—consistent with the overall recent cadence of a “performance wrap-up period” (a phase of fine-grained work following the convergence of major items such as branch prediction/AIA).
