I. Kernel and Version Updates

1.1 Major Feature Update for NXP i.MX RT1180 EVK BSP: I2C DMA/CAN/SPI/DWT/SDIO and EtherCAT Support

Date: 2026-08-21 (merged 17:45 Beijing time, PR #11715)　Source: RT-Thread/rt-thread commit 6ea68279 / PR #11715

The largest merge in this window, led by an NXP engineer (nxp-ran), spanning 46 files, +3579/-769. [BSP][NXP] Add new features of I2C DMA, CAN, SPI, DWT and SDIO for RT1180: updates templates, configuration files, and build scripts to support HyperRAM, multicore kickoff, rpmsg-lite, NetC Ethernet, CherryUSB, and EtherCAT; updates linker scripts for GCC/IAR/KEIL toolchains to support multicore kick-off and different loading methods; updates Keil debug ini files; and adds peripheral feature support for I2C DMA, CAN, SPI, DWT, SDIO, and more. The i.MX RT1180 is an NXP crossover MCU (Cortex-M33 platform with integrated NetC Ethernet), and this is a vendor-led feature-level enhancement of the evaluation board BSP. Notably, EtherCAT support has been added to the NXP BSP manifest, echoing the EtherCAT mainline of the RealChip industrial platform—industrial real-time bus capabilities are advancing on two fronts within the RT-Thread ecosystem.

1.2 Kernel IPC Timeout Wakeup Ownership Race Fix with Regression Tests

Date: 2026-08-21 (merged 16:52 Beijing time)　Source: RT-Thread/rt-thread commit ba79f694

[kernel][ipc] Fix timeout wakeup ownership race (submitted by ari.liu, 8 files, +721/-14): fixes the thread timer ownership issue when timer stop races with an in-flight timeout callback—thread timer ownership is retained until the timeout callback confirms it is no longer in progress, and IPC resources are only consumed after the waiter successfully resumes; also completes ownership cleanup for both generic and RT-Smart channel timeout callbacks. Accompanying deterministic scheduler and LWP regression tests cover six scenarios: Event, Semaphore, Mailbox, Message Queue, sender, and receiver. Resource ownership races in IPC timeout paths are a classic challenge in embedded RTOS, and this fix covers both the rt-thread kernel and rt-smart LWP channels while solidifying regression tests—a substantive enhancement to kernel robustness.

1.3 C906 Core Retains Only XuanTie MMU Properties

Date: 2026-08-21 (merged 16:51 Beijing time)　Source: RT-Thread/rt-thread commit 5ae08713

Ensure that c906 uses only the Xuantie MMU properties (submitted by rcitach, 1 file, -56 lines): cleans up libcpu/risc-v/t-head/c906/riscv_mmu.h to ensure the T-Head XuanTie C906 (RISC-V) core uses only XuanTie MMU properties, removing ambiguity caused by mixing with generic RISC-V MMU properties. This is ongoing maintenance of rt-smart RISC-V kernel-side adaptation.

1.4 Renesas RA6W1 BSP Device Driver Bug Fixes

Date: 2026-08-21 (merged 13:10 Beijing time)　Source: RT-Thread/rt-thread commit 46d74447

fix ra6w1 device bug (submitted by rcitach, 6 files, +124/-23): fixes device issues in RA6W1 EK board support, involving the ADC driver (drv_adc.c), PWM driver (drv_pwm_w.c), board-level Kconfig, and clock configuration (bsp_clock_cfg.h, hal_data.c). This continues the iteration cadence of the Renesas RA6W1 BSP: first version on 08-05, second phase on 08-11 with 45 files adding ADC/SPI/I2C and other drivers, and this third phase of bug fixes—consistent with the vendor BSP evolution pattern of “merge the skeleton first, then add drivers, then fix bugs.”

1.5 Nuvoton Four-Series CAN Driver Clamps Receive DLC

Date: 2026-08-21 (merged 11:22 Beijing time)　Source: RT-Thread/rt-thread commit 642040c4

[bsp][nuvoton] Clamp CAN receive DLC (submitted by hanzhijian, 4 files, +16): uniformly clamps the CAN receive DLC (data length code) in drv_can.c across the m2354, m480, n9h30, and nuc980 series to prevent out-of-range values from being passed in—a robustness patch for the CAN driver.
