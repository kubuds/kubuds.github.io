今日重点：FlagGems 算子集再添 63 个，triton-riscv 的示例仓扩到 239 个文件（11-18）

日期：2026-11-18　来源：PR #126。PR #120。

11-18 22:32，triton-riscv 新开 #126「Add FlagGems operators (63 ops)」。它把 63 个 aten 算子以 Triton 示例形式搬进 python/examples/flaggems/，每个算子配一份对 aten CPU 参考实现的测试。

这条分支接在仍开着的 #120 头上。按 PR 说明，相对 main 的 24 个提交、239 个文件中，111 个文件属 #120，128 个是本次新增。等 #120 合入后，本 PR 会收束为自己的提交。

算子按用途分六组。前四组是标量逐点、比较与位移 12 个；逐点中段、视图与工厂 14 个；数值、逻辑与 ldexp 11 个；unsafe 索引、amp 与量化辅助 9 个。后两组是掩码 softmax、pdist 与线性打包 9 个；foreach 与融合优化器 8 个。最后两组里含 81 个包装的 _foreach_binary 与 60 个条目的 _foreach_unary。

本工具链对部分 libdevice 内建无法 lower，buddy-opt 会直接拒绝调用。作者改用闭式等价式，并以 fp64 与 torch 为基准实测误差。tan 走 sin/cos，相对误差不超过 1.2e-7。log2 换成 log 乘 1/ln2，不超过 3.2e-7。lgamma 用 Lanczos g=7 加反射式，不超过 6.4e-4。sinh、cosh、tanh 走指数式，误差在 2.4e-5 至 6.3e-5 之间。

erfc 的处理最细。fp32 下直接算 1-erf，在 x 大于等于 3.5 时恒为零，于是 2.85 以下用 1-erf，之上改 12 项渐近级数；缝合处最差 6.4e-4，上方不超过 1.3e-4。四个边界值加无穷与 NaN 的取值与 torch 完全一致。

语义上以 torch 为准，上游 FlagGems 有出入的地方逐条用测试钉住。_fused_adam 的权重衰减按 L2 式（g 加 wd 乘 p），amsgrad 取未校正 v 的最大值。_fused_adamw_ 先做解耦衰减再走步。_fused_adagrad_ 与 _fused_sgd_ 只在 found_inf 恰为 1 时跳过更新。

验证记录是全套 FlagGems 用例 6416 项通过，跑在本地 x86_64 上，排除三个既有的原生崩溃文件。容差按实测最差误差留了 1.6 至 10 倍余量。

今日重点：XSAI 的矩阵与同步接口进 fork，Buddy 侧同步把 AME 实现换成 ZTT v0.6（11-18）

日期：2026-11-18　来源：llvm-project PR #33。buddy-mlir PR #1066。buddy-mlir PR #1064。

11-19 02:05（北京时间），llvm-project fork 的 riscv 分支出现一笔合并提交 163d6a7。它对应 PR #33「Add XSAI ZAMES and ZMASYNC vendor extensions」，补丁 5150 行，内容包括矩阵与同步内建、目标扩展类型、寄存器类、指令编码与汇编反汇编。

实现走 RV64 SelectionDAG，含寄存器分配前的配置物化与分配后的展开；跟踪矩阵内存操作数，校验内建立即数范围，并在 RV32 代码生成时给出明确诊断。矩阵 tile 类型放在 riscv.xsai.zames.tile.* 命名空间，同步值放在 riscv.xsai.zmasync.sync。

作者列出的范围缺口有三处：矩阵的拷贝、溢出与重载，以及跨函数 ABI。向量 exp2、MXFP 与 XX8 转换扩展明确不在本次改动内。验证口径是 28 个专项测试通过，另有 11 个冒烟场景。

同日 23:14，buddy-mlir 合入 #1064「Bump LLVM to 542365c9cd38」，只改 llvm 子模块指针。被跟进的这次 LLVM 更新正是 fork 里的 XAME/ZTT v0.6 后端，也就是上一期日报记录的那次合入。

随后 23:36，#1066「Replace legacy AME with ZTT v0.6 operations」开出：30 个文件、+8349 −1277。它把已退役的 AME 方言换掉，在原有 ame 命名空间下定义 138 个带类型的指令操作，并把两种接口统一 lower 到 llvm.riscv.ztt.*。

#1066 自带两套算例与两份 freestanding 的 gem5 校验负载。作者声明不承诺与旧 ISA 契约的数值兼容。4×4 有符号整数 workload 在 AME_gem5 上按精确比对通过：矩阵 A 取 1 至 16、B 全一、C 初值零，16 个结果与独立标量参考一致，打印行和为 10、26、42、58，两个 guest 进程退出码均为 0。

三条线拼起来是同一个方向：LLVM 提供后端能力，编译器中间端接上方言与降级路径，Triton 侧再用算子示例做验证。

1.3 夜间轮子去掉 668 MB 冗余，strip 与打包路径对齐（11-18）

日期：2026-11-18　来源：PR #125。夜间版 20261118。

11-18 18:43，#125「Strip the copies the wheel actually packages」合入，三个文件、+37 −31。此前 release.sh 的 strip 步骤作用在源码树产物上，而 wheel 打包的是构建目录里的另一份拷贝，于是有三个大件漏掉。

按 PR 给的数：triton-shared-opt 在 wheel 里 398 MB，剥离后约 118 MB。libtriton.so 441.5 MB，剥离后约 144 MB。libtriton_amd_codegen.so 在 amd/lib 与 amd/codegen/build 各有一份，各 84 MB。合起来是 502 MB 的 wheel 里 668 MB 可避免的成员。

修法分四步：剥离真正被打包的那几份，删掉重复的 cmake 构建树，strip 不生效时直接失败而不是静默跳过，发布前检查成品尺寸。PR 里还让 Release Wheels 工作流在每个 PR 上打印最终体积，但不发布。

此前那一期记录过 strip-all 把 wheel 减重四成的旧尝试，这次是把遗漏的拷贝补齐。合入前最近的夜间版是 nightly/20261118-e9c34b7（11-18 09:59 北京时间发布），体积尚未按新流程重建，下一版夜间构建才是第一份口径。

三、向量扩展与算子优化

3.1 FlagGems 套件用闭式替换补 libdevice 缺口，6416 项通过（11-18）

日期：2026-11-18　来源：PR #126。

#126 的价值不止在算子数量。它把这条工具链当前 lower 不了的 libdevice 内建逐条列了出来，并给出可实测的替代式，等于一份后端能力缺口的清单。

清单里提到的拒绝点集中在 buddy-opt。pow 只能走 libdevice 版本，AST 里的 ** 不被支持。round 改成显式 half-to-even。erfc 因 fp32 精度不足而分段处理。每条替代式都附了相对误差与边界行为，便于后续替换回原生内建时对比。

测试侧的口径也值得记：全部容差按实测最差误差留了 1.6 至 10 倍余量，种子与进程无关。这套做法让新增算子的回归结果可复现，不依赖运气。

3.2 VecIntrinBench、IntrinTrans 与 FBGEMM 仍静默（11-18 状态）

日期：2026-11-18　来源：VecIntrinBench。IntrinTrans。FBGEMM。

4.2 transpose 分块 pass 把转置桶从 199.6G 周期降到 31.5G（11-18）

日期：2026-11-18　来源：PR #1065。

#1065 新增 linalg-transpose-tile pass：把 memref 上的 linalg.transpose 改写成按 tile-size × tile-size 分块的 scf.parallel 循环，只改循环顺序，结果逐位相同。

默认的降级方式在换轴维度上按整行跨度逐元素搬运，大矩阵会反复冲刷缓存。作者在 x86 上以 240 个物化权重转置的图实测，转置桶从 199.6G 周期降到 31.5G，降幅 84%。

PR 的检查清单还没勾完：既有测试与文档两项为空，代码风格一项也未勾。合并前这几项需要补齐。
