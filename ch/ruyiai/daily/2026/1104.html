今日重点：openRuyi PR #1350 合入，RuyiAI 三件套七周后进入发行版打包（11-03）

日期：2026-11-03　来源：PR #1350 Add Ruyiai packages、三笔打包提交、后续修正 PR #1575

11-03 15:59（北京时间），openRuyi 主仓的 PR #1350 合入。这笔 PR 开于 09-21 17:55，复核走了 43 天，最终只带三笔提交、十个文件、838 行新增，却把 RuyiAI 栈里最难分发的一段——编译器后端与 MLIR 工具链——正式收进了发行版的 SPECS 目录。

三件套的分工是清楚的。buddy-mlir 是 MLIR 编译框架，提供 RISC-V 向量（RVV）降级所需的方言与 pass，spec 里写 0.1.2，源码锚定 buddy-compiler 的提交 60f354a7，同时自带一份 RuyiAI-Stack/llvm-project 的 LLVM 快照（提交 3845a205），用 clang/lld 22 引导构建，测试与 Python 包均关闭，工具链最终装到 /usr/lib64/buddy-mlir/llvm。python-triton-ruyiai（spec 内包名 python-triton-riscv）把上游 Triton 提交 5889527 与 triton-riscv 的 nightly/20260913-da5291b 标签拼在一起，运行期依赖 buddy-mlir、buddy-mlir-llvm 与 clang。python-tilelang-ruyiai（spec 内包名 python-tilelang-riscv）锚定 tilelang-riscv 提交 0b7d66eb，另外把 TVM、dmlc-core、rang、tvm-ffi、DLPack 五个子模块按上游固定的版本单独打包，构建期还需要 python3dist(torch)。

从补丁内容可以看出发行版适配卡在哪里：tilelang 的五个补丁分别放宽 apache-tvm-ffi 上限到 0.1.11、去掉 torch-c-dlpack-ext 与 patchelf 的构建依赖、让工具链在 /usr/lib64/buddy-mlir/llvm 下查找、跳过 z3 的 soname 改写、另有一笔处理 TVM FFI 的 libbacktrace 开关；triton 的两个补丁把 cmake/ninja/nanobind 换成系统包，并给 buddy-translate、buddy-llc、llc、mlir-translate 补上 PATH 与 /usr/lib64/buddy-mlir/llvm/bin 的查找回退。换句话说，源码树里那些靠环境变量拼起来的路径，在发行版里必须逐条落成可重现的查找规则，这才是 43 天复核的主要工作量。

同一天 20:16，PR #1575 又补了一刀：把 buddy-mlir.spec 里 Source0、Source1 的 #/ 分隔改成 /，修正 RPM 源地址写法。同日又修了一处打包 bug，说明这三份 spec 的复杂度不在功能，而在打包约定与路径细节；上一期日报记录的「复核十九条意见集中在 spec 写法」，在这里有了收尾。

这笔合入的意义不在版本号，而在分发路径。此前要用 RuyiAI 栈，得自己拉 triton-riscv、tilelang-riscv 与 buddy-mlir，按文档设 BUDDY_MLIR_BINARY_DIR 一类变量；现在 openRuyi 的打包仓里有了这三个组件，构建通过后用户可以按发行版方式安装同一套 LLVM/MLIR 链，版本、依赖与安装布局由 spec 固定。PR 自述里也按 openRuyi 的 AI 贡献政策标注了辅助工具（GLM-5.3、DeepSeek V4.1 Flash）。

需要留一个尾巴：三份 spec 锚定的代码都早于本期上游。打包完成不等于能力同步，具体差距见 2.2。

三、向量扩展与算子优化（VecIntrinBench / IntrinTrans / FBGEMM）

3.1 三个向量仓继续静默，最新提交仍停在 02-13、06-25、07-13（11-04 状态）

日期：2026-11-04（状态）　来源：VecIntrinBench、IntrinTrans、FBGEMM

三个以「向量」为主题的仓库本期均无窗口内提交，最新提交时间分别是 VecIntrinBench 02-13、IntrinTrans 06-25、FBGEMM 07-13。三者原本构成「测什么、怎么翻、算子怎么实现」的三角，现在分别停了近九个月、四个月、三个月。

停顿时间点不同，说明不是一次统一的项目终止，而是各自自然冷却。VecIntrinBench 停得最久，这对覆盖率判断影响最直接：基准不更新，它测到的内建函数集合与编译器实际支持的集合会越差越远，而 LLVM 侧的 A100/AME 降级链仍在扩展（见 1.3）。

六、趋势观察

6.1 从源码构建到发行版包：RuyiAI 栈的分发路径补上最后一公里

三件套的 spec 进入 openRuyi 之后，RuyiAI 栈的分发路径第一次被写成发行版配置：以前是「拉源码 + 设环境变量 + 自己编 LLVM」，现在打包仓里是一条 RPM 依赖链，buddy-mlir 提供 LLVM/MLIR 前缀，triton 与 tilelang 依赖 buddy-mlir-llvm。构建产物进入仓库后，用户的安装门槛会从「会编编译器」降到「会装包」；对项目而言，版本与依赖第一次被写进可审计的 spec。

七周复核的价值也在这里：争的不是功能，而是路径发现、依赖上限、构建隔离、包名与 Provides 这些发行版规矩。PR #1575 当天修源地址，说明这条链仍然脆，但它已经能跑通合并流程。

6.2 打包锚点滞后于上游：版本号里的日期不等于代码日期

三份 spec 里，triton 的代码停在 09-13，tilelang 停在 10-28，buddy 停在 0.1.2；而三个仓库在 11-03 都还有新动作。最刺眼的是 tilelang：11-03 刚合入的 PR #5 是十八天静默后的第一笔功能，但它不在当天合入的 RPM 里——包锚定的是 10-28 的 0b7d66eb。

版本串 3.8.0+git20261103 会强化误读，把打包日期当成代码日期。对发行版用户，这意味着「装到的是某个快照」，不是「装到的是最新」。后续要么建立定期的 bump 流程，要么在包描述里写清快照日期；否则每合入一笔功能，包与仓库的差距就再拉大一点。

6.3 两条开发线同日恢复，ruyi 主线与 openRuyi 发版仍静止

11-03 这一天，tilelang-riscv 结束十八天静默，buddy-mlir 重新出夜间版，openRuyi 一天合入七笔 PR；开发侧的动作集中在编译器后端与打包。另一边，ruyi 主仓零提交、零新标签，openRuyi 的 2026.10 月度版仍缺位。

两条线的节奏并不同步：代码在走，发版不走。上一期把这种状态概括为「卡点在发布不在开发」，本期仍然成立。下一个观察点是 openRuyi 十一月版是否把三件套收进去，以及 triton-riscv 的 #92 重基是否合并——前者决定发行版能否交付，后者决定 triton 包下一次 bump 的落点。
