日期：2026-10-09 ~ 2026-10-10　来源：triton-riscv PR #86、合并提交 e00fdd60、llvm-project riscv 提交列表、头部提交 8f38c047、PR #25、PR #28

triton-riscv 完成自 09-14（#81）以来的首次 PR 合入：贡献者 trdthg 于 10-09 中午开出并合入 PR #86「[patches] Support newer LLVM symbol and inline-asm APIs」（1 个文件、+111 行；开出到合入约 20 分钟）。背景是 renovate 维护的 Buddy MLIR 依赖升级 PR #84——将 buddy-compiler/buddy-mlir 从 nightly/v0.0.9 提升到 nightly/v0.0.11，而 v0.0.11 携带更新的 LLVM 版本，其 MLIR API（如符号与内联汇编接口）与固定前端的 Triton 不再兼容，x64 与 riscv64、各 Python 版本的 CI 在构建阶段全面失败；#86 以补丁形式补充对新 LLVM 符号与内联汇编 API 的支持，合入后解除该阻塞（#84 随后于当日下午刷新，保持开放待并入）。

要点归纳：本窗口两条工具链维护线前后落位——LLVM 侧完成夜间重放，Triton 侧完成对新 LLVM API 的补丁适配；两者共同构成 RISC-V AI 编译栈在快速演进的 LLVM 上游之下「重放—适配—构建渠道」的稳定性工程。该合入当日即被 ruyiai-daily 10-10 期收录，评注其「直接涉及 RuyiAI 的 Triton→Buddy/MLIR 构建链，解除升级 LLVM 后的接口不兼容」。
