今日重点：玄铁内核补丁把 T-Head PMA 勘误扩展到 PUD/P4D 大页

日期：2026-09-20　来源：linux-xuantie-kernel 提交 167b3d7c

北京时间 09-20 16:33，RuyiSDK 的玄铁内核树（linux-6.6.36 分支）合入一笔上游回移补丁，题为 riscv: mm: Apply T-Head PMA memory-type errata to PUD and P4D entries。补丁说明指出：达摩院玄铁的 PMA 内存类型勘误在构建页表项时通过 ALT_THEAD_PMA() 注入 PMA 类型位，此前只覆盖 pfn_pte()、pfn_pmd()、pfn_pgd() 与 pte_modify()，未覆盖 pfn_pud() 与 pfn_p4d()；因此 PUD 级（1GB）以及 sv57 下的 P4D 级（512GB）大页映射不会携带玄铁要求的内存类型编码，在这类核心上会退回隐式/默认 PMA，内存属性可能与其它尺寸的映射不一致。这些叶子项可由线性映射（create_pud_mapping() 以 PUD_SIZE 建立）与大页 vmap 触达。

修法是在 pfn_pud() 与 pfn_p4d() 中镜像 pfn_pmd() 的做法，对保护值运行 ALT_THEAD_PMA()。提交带 Cc stable 与 Fixes 标签（指向引入勘误处理的 a35707c3d850），上游讨论见内核邮件列表帖子；回移由阿里云侧维护者署名完成，并按本树风格把 ALT_THEAD_PMA() 作用于 u64 保护值。对使用玄铁核心并依赖 GB 级大页的负载（数据库缓冲、虚拟机内存、大模型权重映射）而言，这消除了同一进程内不同映射尺寸内存属性不一致的隐患。

北京时间 09-20 23:19，社区发布「荔枝派 4A RISC-V Linux 实践课」第三讲，主题为 GPIO 与执行器。课程以荔枝派 4A 加 RuyiSDK 与 C 语言为基线，本章用 gpiod 经继电器控制 5V 风扇，要求自写 line_request、fan_set、fan_decide 三个函数，跑通模拟温度滞回控制；帖子给出接线表与命令序列，并提示工程细节：信号脚为 1.8V 电平、风扇走继电器而非直驱 GPIO、一条 line 同时只能有一个占用者（残留 gpioset 进程会占线）。系列目录显示第 04 讲为命令对话与温控，讲义与实验含实机图与板上录像。

五、趋势观察

5.1 内核与容器两侧同日补 RISC-V 专属行为：从能跑转向跑得对

本窗口两笔最有技术含量的提交都不增加新功能，而是修正 RISC-V 特有语义：玄铁内核树把 PMA 勘误补到 PUD/P4D 级大页，避免 GB 级映射内存属性与其它尺寸不一致；openRuyi 把 riscv_hwprobe 加入容器 seccomp 白名单，避免 OpenSSL 与 zlib-ng 因 ENOSYS 静默退回标量。两者共同的判断标准已不是「能否运行」，而是「是否按硬件实际能力与架构约束运行」。这一层次的补丁通常不产生新闻，却直接决定实测性能与稳定性，值得在日报中持续跟踪。

5.2 工具链产品线转入小步发布：插件走 beta 通道，文档补齐图形化工具

VS Code 插件以 0.1.7-beta.1 进入下一版本预发布，文档站同日补入 Ruyi Imager 图形化烧写说明，支持矩阵补录进迭时空 K3 板卡的 Buildroot 报告——三件事分别覆盖编辑器插件、镜像烧写与系统适配三条使用链路，且都面向「降低上手门槛」。ruyi 本体保持静默、0.53 正式版仍未打号，产品节奏呈现「周边先行、主体消化」的形态。

5.3 PyTorch fork 的 riscv 分支借上游基线重排，CI 镜像本地化补位

riscv 分支本次以 96 个提交重排的方式把本地补丁移到较新上游基线，短期内会带来一次可观的同步工作量与随之而来的回归面；同日新开的 PR #51 要求原生 riscv64 硬件构建 CI 镜像，说明 RISC-V 侧流水线仍在补齐基础设施，而非推进特性。RVV 相关的两个开放合并请求（#46、#48）随重排被刷新，尚无新的评审进展，仍是本栈最值得等待的变更。

5.4 本窗口的空白与关注点

需要如实记录的空白：新闻侧对 RuyiAI、RuyiSDK、如意社区、openRuyi 的中英文多组查询继续零命中；arXiv 窗口内无新收录；ruyi 与 packages-index 静默；向量与算子三个专项目标仓库全部静默。关注点：一是 0.53 正式版的打号时点与 077 期双周进展；二是 openRuyi 2026.09 月度版本公告（上版为 2026.08）；三是 PyTorch fork 重排后是否会跟进新的 RISC-V 适配提交，以及 PR #51 的验证进度。
