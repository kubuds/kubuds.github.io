今日重点：K3 固件第二版发布——UEFI 设置引入 CPU 模式选择（X100/A100）并可持久化；OpenSBI K3 v4 系列与 coreboot / EDK2 同日协同就位

日期：2026-10-14　来源：Ruyi Firmware 20261014 发布、OpenSBI K3 v4 系列接入提交、edk2-ruyi 提交 ba4ff0ad、coreboot k3/port 提交列表、opensbi k3/port 提交列表

openRuyi 固件打包仓库 ruyifirmware 于 10-14 下午（14:42）发布第二期固件版本「Ruyi Firmware 20261014」，核心特性是给 K3 的 CPU 配置带来选择性：UEFI 设置界面新增 CPU 模式选择，设置持久化保存并在下次启动生效，fastfetch 等工具可将模式识别为 k3 / k3-x100-a100 / k3-a100。三档模式为：X100 仅用（默认，8 颗 X100，RVV VLEN 256，保留 H 扩展）；X100 + A100 混用（16 核，RVV 与 H 扩展均关闭）；A100 仅用（8 颗 A100，VLEN 1024，H 扩展关闭）。

本轮发布由 K3 固件栈四仓在同日下午协同完成：OpenSBI 的 k3/port 分支先行落地 K3 v4 系列（13 笔，FROMLIST 前缀 6 笔 09:50、RUYI 前缀 7 笔 13:05）；coreboot 的 k3-pico-itx 由 SPI 配置选择 CPU 档位（14:11），并把设备树 fixup 前移至 payload 交接前执行；EDK2 侧 edk2-ruyi 新增「持久化 CPU 选择模式」（14:11）；ruyifirmware 随后依次接入 OpenSBI K3 v4 系列（13:05）与 K3 CPU 选择模式（14:24），完成打包并发布。

从首期固件（20261013）到本期仅隔一天，K3 交付重心从链路打通（前一日 35 笔 EDK2 平台代码整批首推）转向硬件配置面——CPU 簇组合与扩展开关交由固件层选择。观察点：各模式（特别是关闭 RVV / H 的混用与大核模式）在实际负载下的性能与兼容性取舍、设置持久化在固件升级路径上的表现，以及它与 openRuyi 发行版镜像（kiwi-image）和开发中工具链（K1/K3 适配）的协同。

五、趋势观察

5.1 K3 固件进入「可配置」阶段：CPU 模式选择的取舍与协同观察点

从首个固件版本（10-13）到第二版（10-14）仅隔一天，K3 固件线的重心已从链路打通转向硬件配置面：CPU 簇组合（X100 / A100）与扩展开关（RVV、H）交由固件选择并持久化。观察点：其一，三档模式在实际负载下的性能与兼容性取舍——混用与大核模式关闭 RVV / H 的适用场景需要实测界定；其二，设置持久化在固件升级路径与恢复场景中的表现；其三，与 openRuyi 发行版镜像（kiwi-image）及开发中工具链（K1/K3 适配）的协同节奏——峰会周（10.18 起）临近，K3 相关成果是否集中亮相。

5.2 例行维护双线：PyTorch 晨间重建节奏延续，LLVM riscv 重放仍未回归

两条 fork 维护线本窗口延续差异：PyTorch riscv 分支照常完成晨间重建（23 笔，头部 b870a71a），8 笔开放 PR 于 10-14 上午批量刷新基线；LLVM riscv 分支连续第二个窗口未见新一轮夜间重放（头部维持 10-12 版本）——重放是否回归、以及 ruyisdk/llvm-project 的 rebase 线（XTHeadVector 修复已合入）与 fork 重放线的关系，继续列入观察。

5.3 openRuyi 深度维护面扩张：图形栈、存储 CI 与跨架构调优并进

发行版维护不止于批量依赖更新：本窗口 mesa（26.2.4 升级 + PVR 优化回移）、ceph-ci（fork-patches 持续修补）与 ruyi-tuner（编译对比结果落盘、v1.x 并入主线）分别在图形栈、存储栈与工具链三个方向小步推进，加上固件线的每日发版节奏，openRuyi 的「深度维护面」在峰会前持续扩张。观察点：这些专线工作与 0.54.0 版本、2026.10 镜像发布节奏的耦合方式。
