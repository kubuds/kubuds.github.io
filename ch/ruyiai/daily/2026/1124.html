今日重点：buddy-mlir 合入 Qwen3-0.6B FP16 优化，Prefill 86.01 token/s（11-23）

来源：PR #1001。

#1001 在 11-23 14:51 合入，标题为「Optimize Qwen3-0.6B FP16 Prefill and Decode on K3 A100」。改动 23 个文件，加 560 行、删 50 行。

实测在同一台 K3 的 A100 核心 8 至 15 上完成，八个物理核，输入端一致。Prefill 评估 128 个位置，Decode 从第 96 个位置起测 32 步，加载时间不计。

实现 Prefill（token/s） Decode（token/s）
Buddy 主干，未优化 FP16 4.24 0.84
llama.cpp 71.64 14.38
Buddy，本 PR 86.01 13.45

Prefill 比 llama.cpp 高 20.1%，是主干基线的 20.3 倍。Decode 为 13.45 token/s，比 llama.cpp 低 6.5%，仍是主干的 16.0 倍。

两项指标方向相反。Prefill 走的是分块 GEMM 与原生 VLEN=1024，Decode 受限于单 token 的 GEMV 带宽。PR 说明写明比较使用 all-position logits，双方口径在这点上对齐。

内核侧复用了 #997 的成果，包括 IME FP16 GEMM 与 GEMV、Decode 权重打包、RVV 与 SiLU 优化。Attention 用向量宽度 64，Decode 只切一路 KV。

配置集中到
models/qwen3/specs/f16_k3_a100.json，默认流水线不受影响。文件里 VLEN 为 1024，Prefill 向量宽度 64，Decode 打包宽度 32，线程数 8。输出词表权重单独存放，以便按投影选择布局。

正确性侧，96 个 Decode token 与三组重复贪心生成用例都与 PyTorch 参考一致。PR 说明也指出，完整的 check-buddy 被禁用的 Python 包目标挡住，未能全量跑。

4.2 #1077 提 strip 与 zstd 统一，目标是单资产上限（11-23）

来源：PR #1077。

#1077 在 11-23 11:05 开出，只改一个文件，尚未合入。标题为「Pack the LLVM and buddy tarballs with zstd」。

PR 说明给出起因。riscv64 的 LLVM 安装包 gzip 后略超 GitHub 单资产 2 GiB 上限。nightly/v0.1.5.dev20261120 因此发布失败，接口返回 422 与「size must be less than 2147483648」。

方案有三点：strip 二进制与共享库、去掉 MLIR Python 绑定、改用 zstd -19 –long=27 打包。作者给出的预估是 LLVM 从 2047 MB 降到约 840 MB，buddy 从 264 MB 降到约 180 MB。

说明里另提两处配套。triton-riscv 的 setup.sh 已能读 .tar.zst；此改动落地后的首个发行需跑一次 llvm_cache_mode=clean，因为缓存键不含这次过滤。

六、趋势观察

6.1 模型优化转入批量复用

#1001 明确写着复用 #997 的内核、权重打包与 RVV/SiLU 优化。队列里的 Whisper Base、PaddleOCR-VL-0.9B、EmbeddingGemma 也引用同一条路径。

这说明 K3 A100 上的模型加速已经从单点攻关转为模板化。新增一个模型的主要工作是写配置与跑正确性，而非重写内核。

判断依据有两条。一是配置集中到每个模型的 specs 目录，二是 PR 说明反复出现「shared kernels」与「reuse」的表述。

6.2 发布编号推进快于内容

ruyi 从 0.55.0-beta 推到 0.56.0-alpha，代码差异只有版本号三行。triton-riscv 补发的正式标签也指向 11-18 的旧提交。

两个仓在同一天出现了「有新版本、无新代码」的情况。这说明发布节奏由版本规划驱动，而不是由变更量驱动。

对下游的影响是版本号不再指示内容多少。判断是否值得升级，需要看发行说明的条目集合，而不是编号大小。

6.3 设备侧代码开始离开主仓

网站仓这一轮删掉 775 行，把设备运行时交给独立仓与子模块。同期 ruyisdk-test 组织下出现 ruyi-imager-webview 与 ruyi-imager-electron。

方向是把刷写工具拆成可独立发版、可独立测试的组件。主仓因此变小，构建权限也能单独隔离。

需要留意的是新仓落在一个测试组织下，尚未迁到 ruyisdk 主组织。这一步是否会发生，可作为后续观察点。
