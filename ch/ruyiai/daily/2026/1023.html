今日重点：双周报 079 补全六节，QEMU 补齐 P 扩展 v0.6 全指令并合入达摩院 AME v0.6

日期：2026-10-22　来源：双周报第 079 期、QEMU p-dev 分支、QEMU ame-0.6 分支、QEMU 仓库

昨日报告记录的 079 期草稿只写入了 OpenJDK、基础 C 库与开发板三节，本窗口内其余六节全部补齐：GCC、LLVM、V8、OpenJDK、Go、QEMU 以及包管理器与 IDE 小节，十个补丁提交在 10-22 09:26 ~ 14:20 之间陆续落到仓库（#383 至 #391）。

其中信息量最大的是 QEMU 一节。RuyiSDK 的 QEMU 仓库发布了 P 扩展 v0.6 的实现，称已完成当前 P 扩展全部指令的模拟支持，分支 p-dev 基于上游 v11.1.0。分支最后一批提交在 10-21 16:35，内容是打包 SIMD 系列（Q 格式乘加、纯乘法与乘累加、二路与四路乘加/减、加载复制、RV32 专用指令），并移除 P 对 Zbkb 的依赖以对齐规范、补了 TCG 测试。

同一期还记录了达摩院 AME 扩展 v0.6 合入 ame-0.6 分支：完成主要功能开发与架构重构，支持 32/64 位用户模式与系统模式，覆盖矩阵计算、整数与浮点混合运算、数据搬运和类型转换，并支持多核共享后端、状态迁移与调试，同样基于上游 v11.1.0。该分支可见提交截至 10-16，本窗口是把成果汇编入刊，不是新提交。

这两条与 RuyiAI 编译器侧形成对应关系：LLVM 分支上的 AME 补丁 #29（指令更新）、#30（IME 内建下降到 SpacemiT A100 dot）、#31/#32（A100 HP/SP 与 pack/unpack 调度）负责把矩阵扩展编译成指令，QEMU 侧负责在无硬件时模拟同一套语义。三处同源的扩展支持在本周同时到达 v0.6，意味着该扩展具备「编译器可生成、模拟器可执行」的最小闭环，剩下的缺口是硬件实测数据。

2.4 QEMU：P 扩展 v0.6 全指令覆盖，达摩院 AME v0.6 合入（10-22）

日期：2026-10-22　来源：双周报 QEMU 节、p-dev 分支、ame-0.6 分支、qemu 提交列表

P 扩展侧，p-dev 分支的收尾批次全部集中在打包 SIMD：Q 格式乘法与 Q 格式乘加、纯乘法、乘累加、二路与四路的乘加/减、加载复制，以及 RV32 专用指令集，另加移除 P 对 Zbkb 的依赖以对齐新版规范，并补了 tests/tcg/riscv 下的 P 扩展测试。分支基于上游 v11.1.0。

AME 侧，达摩院贡献的 v0.6 实现合入 ame-0.6 分支，官方描述为完成主要功能开发与架构重构，支持 32/64 位用户模式与系统模式，覆盖矩阵计算、整数与浮点混合运算、数据搬运与类型转换，支持多核共享后端、状态迁移与调试。该分支可见提交截至 10-16，内容是 Ztt 指令族落地：decodetree 译码、指令族 helper、GDB 状态暴露、实验性 CPU 配置暴露、disas 支持，以及 Ztt 数值/张量运算、控制与共享后端、内存与调试器集成、配置与迁移四组测试，另补了文档。

两条线的落点一致：把尚未量产的扩展做成可跑通的软件基线。对没有 P 扩展或 AME 硬件的开发者，QEMU 是唯一能验证工具链输出的途径；P 扩展全指令覆盖之后，GCC 的 P 0.6 更新与 LLVM 的 P 扩展 intrinsics 才有可对照的执行语义。

3.3 论文：长向量处理器上重排 FlashAttention，实测加速 1.84 至 2.08 倍（10-21）

日期：2026-10-21（略早于本期窗口起点，因 arXiv 索引在本窗口内首次可见而收录）　来源：arXiv 2610.29489v1

《Reorienting the Vector Axis: Restructuring FlashAttention for Long-Vector Processors》（Emmanuel Irabor、Marc Casas）把 PyTorch 的 CPU FlashAttention 内核移植到带 2KB 向量寄存器的 RISC-V CPU 上，先给出一个不客气的基线：只达峰值浮点吞吐的 16.2%。

原因分析得很具体。原内核按查询行逐行推进：与 V 的乘沿 64 元素头维向量化，softmax 的逐行最大值与求和是「把整个寄存器塌缩成标量」的归约，软件指数函数的多项式系数还要与 tile 数据抢向量寄存器，导致溢出到栈。三项叠加，向量寄存器的利用率上不去。

两条改法都不改算法与数值。第一条把分数 tile 与运行输出一起转置，让查询落在线性连续轴上——于是「一个 tile 里装多少查询」这一个参数就统一决定了内核各段的向量长度，可按机器配置，同时两个归约自然消失。第二条把多项式系数搬进标量寄存器，消除溢出，softmax 的向量访存指令减少 78.7%。

实测：头维 64 时，两项合起来把整核周期降到 1.84 至 2.08 倍加速，浮点利用率从 16.2% 升到 29.7%；同设计的 FPGA 对两项改动的排序一致且收益更高，达 2.71 倍。

对本栈的意义在方法而非数字：向量长度自适应与寄存器压力正是 triton-riscv 与 tilelang-riscv 在 RVV 降级上的结构性问题，而不是「有没有 intrinsics」；文中「按机器匹配 tile 内查询数」与 IREE 把 Tile N 取 vlen/8 属同一类决策，可直接做同口径比较。

六、趋势观察

6.1 重放从「择期」变「每日」：llvm 首次连续两日换基

前两期的判断是 pytorch 日更、llvm 择期：pytorch 连续三次在 03:00 重写，llvm 则在静默八日后才换一次基。本窗口推翻了后半句——llvm 在 10-22 23:00 再次整枝重写，间隔正好一天。

两次换基的跨度差异说明了机制：昨日那次 ahead 1769、300 文件，是八天上游积压的集中消化；今日这次 ahead 275、仍是 300 文件，是单日增量的常规追赶。分支已进入「每日把基线前移一小步」的状态，与 pytorch 收敛为同一种运维。

代价没有变：提交者时间被统一改写，SHA 每日失效，任何按 SHA 引用的下游都会当天过期，读这两个分支应看补丁标题集合而非 SHA。收益也没有变：补丁本身没有新增，pytorch 七笔、llvm 两笔开放 PR 都只刷新了时间戳，实际进度仍由评审队列决定。

6.2 openRuyi 进入规范补全期：清扫 54 笔压过升级 22 笔

本窗口 81 笔提交里 54 笔是同一种规范化改动（补源校验和、改用 %autochangelog），覆盖 m 到 x 一段包名；真正的版本升级 22 笔，比例二点五比一。

这与上一阶段「补依赖闭包」不同：那时 Go 去 vendor、Rust 补 crate，目标是让包能编出来；现在清扫的是可审计性与自动记账——源校验和决定构建输入可验证，%autochangelog 决定变更记录由提交历史生成而非手写。对用户的可感知收益落在安全更新链路上：统一路径通了，CVE 修复才会沿一条道传导。ISAC 源同步问题（见 2.6）提醒另一面——规范再好，发布通道堵塞时用户仍看不到更新。

6.3 发行版开始铺桌面与虚拟化验证栈

开放 PR 队列里出现一组同向提案：qemu 打开 GUI 测试特性（#1421）、新增 virglrenderer（#1415）、ovmf 支持 fwupd（#1436）、新增 ydotool（#1457）、修 xorriso 的 man 页冲突（#1489）。

五项分属虚拟化、图形虚拟化、固件更新、输入自动化与光盘镜像工具链，合起来指向同一件事：在 RISC-V 上跑完整桌面并对其做自动化验证。这与峰会展示的「AI 驱动 IDE 图形化测试」是同一需求的两端——测试框架要驱动真实界面，就必须先有可脚本化的输入与可虚拟化的图形栈。桌面支持此前是 RISC-V 发行版的弱项，这批提案把它拆成了可逐项合入的任务。

6.4 扩展落地路径成形：编译、模拟、算子三层先后到位

以 AME 为例，本周可见一条扩展从提案到可用的完整路径：先有后端设计与指令集定义（LLVM #16、#24、#27、#29），再有降低与调度的实现（#30、#31、#32），同时模拟器给出可执行语义（QEMU ame-0.6），最后算子库提供可测的 kernel 与验证套件（AME-operator）。

P 扩展走同一条路但已到后半程：QEMU 覆盖全部指令，GCC 支持更新到 0.6，LLVM 侧 mulq、乘高位累加、sati/usati、Packed Pair 等 intrinsics 分批合入上游。对照来看，P 扩展缺应用侧 benchmark，AME 缺真机。

这个顺序本身值得作为方法记录：没有模拟器无法验证编译器，没有算子库无法验证模拟器。三者齐备之前谈性能没有意义，齐备之后瓶颈才转移到硬件与实测。本周的进展是「齐备」而不是「更快」。
