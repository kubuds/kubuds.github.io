今日重点：buddy-mlir 合入 ZTT v0.6 与 LLVM 矩阵扩展，triton-riscv 后端调优跟进（11-19）

来源：buddy-mlir PR #1066。PR #1067。triton-riscv PR #129。

11-19 19:20 至 19:21，buddy-mlir 连续合入两个 PR。#1067 把 LLVM 子模块从 542365c9cd38 推到 163d6a753b58。

新指针指向 llvm-project fork 的 #33 合并点。该合并加入 XSAI 的 ZAMES 矩阵指令与 ZMASYNC 同步指令。覆盖面含矩阵与同步 intrinsic、无尺寸目标扩展类型、汇编与反汇编，以及 RV64 SelectionDAG 降级。

支持范围有边界。矩阵的拷贝、溢出与重载，以及跨函数 ABI 仍未覆盖。PR 说明只改子模块指针，行数为 +1 −1。

#1066 把已退役的 AME 方言整体换成 ZTT v0.6，仍沿用 ame 命名空间。它定义 138 个带类型的指令 op，配自定义汇编语法与 intrinsic 桥。

降级路径统一走 lower-ame，落到 llvm.riscv.ztt.* 调用。PR 附带 8×8 与 4×4 两组示例，以及两个 freestanding 负载在 gem5 上的校验。改动 30 个文件，+8349 −1277。

下游当天就跟上了。triton-riscv 18:20 开出 #129，调 RISC-V 目标的 buddy-opt 降级参数。改动只在目标为 RISC-V 时生效，共 2 个文件，+137 −12。

调优有三块。数学函数改用多项式近似，覆盖 exp、log、tanh、erf、sin、cos、atan 等 13 个算子。向量改用目标最小 VLEN 的可伸缩向量，并用 avl 循环收尾。矩阵乘的向量宽度改为 2·VLEN/32。

VLEN 从目标的 +zvlNb 读取。只给 +v 时按 128 计。作者在 VLEN-256 的 RISC-V 板卡上对比 triton-cpu 调的参数。

这条 PR 依赖尚未合入的 buddy-mlir #1068。PR 说明写明，用旧版 buddy-opt 会在未知 pass 或选项处直接失败。

1.2 FlagGems 示例三连：63 + 43 + 40 个算子分三支待合（11-19）

来源：PR #126。PR #127。PR #130。

FlagGems 示例在一天内叠成三支。#126 覆盖 63 个 aten 算子，#127 再加 43 个 torch.special 算子，#130 再加 40 个激活、dropout 与损失算子。

三支是串行堆叠的。#127 接在 #126 头上，#126 接在 #120 头上，#130 又接在 #127 头上。PR 说明都注明，前序未合时 diff 会把前序提交一并计入。

按各自说明，相对 main 的规模分别是 239、325、405 个文件。#130 自己的部分是 4 个提交、81 个文件，其余属前序 PR。

测试数逐层上涨。#126 记 6416 项通过，#127 记 6782 项，#130 记 7091 项。新增用例分别是 309 与 366 项。

#127 的内容是特殊函数。贝塞尔家族、四类 Chebyshev 加移位版、两种 Hermite、Laguerre 与 Legendre 都在内，另有 log_softmax 与 logsumexp。

工具链无法降级的 intrinsic 改用闭式。erfcx 用三段混合，fp32 段、fp64 段与渐近级数各管一段。log_ndtr 的尾部改算 −t² + log(erfcx(t)/2)，避开 ndtr 下溢。

#130 的内容偏神经网络算子。GELU、GLU 的反向公式，融合的 conv/addmm/prelu，dropout 与 randomized-ReLU 变体，以及含 CTC 前向与反向的损失组。

CTC 的格子动态规划用 fp64 的 Triton 核。反向把 beta 扫描留在主机侧，同时清洗传入的 alpha。作者注明，aten 的 CPU 实现会留下不可达格点未初始化。

卷积的 cudnn 尾声改走 aten。Triton 只保留 bias、Z 相加与 ReLU。triplet margin 按 pairwise_distance 的语义处理，eps 广播到差值向量上。

三支都把范围限制在 python/examples/flaggems。PR 说明写明不改后端、CI 与其他 PR 的文件。

1.3 RISC-V 后端调优 PR #129 开出，依赖 Buddy 尚未合入的 pass（11-19）

来源：PR #129。PR #128。buddy-mlir PR #1068。

#129 在 18:20 开出，标题与 #128 相同。#128 在 10:19 开出、10:20 关闭，随后以 #129 重开，内容一致。

改动集中在 Triton 到 LLIR 的一处函数。只有目标为 RISC-V 时才追加参数，其他目标不受影响。作者说明没有绑定特定 VLEN。

参数分三类。数学函数开多项式近似，涉及 exp、expm1、log、log2、log1p、tanh、erf、erfc、sin、cos、atan、atan2、asin、acos、cbrt。

向量化改用可伸缩向量，按目标最小 VLEN 取宽度，并开 avl 循环。矩阵乘的向量宽度改为 2·VLEN/32，而原来是常数 4。

精度依据在 Buddy 侧。#1068 的说明给出 f32 下 1 至 7 ULP，f16 与 bf16 至多 1 ULP。例外是 exp 与 erfc 的次正规结果。

依赖关系是硬约束。#1068 尚未合入，buddy 也还没有带这两个特性的 release。PR 说明写明，旧版 buddy-opt 会在未知 pass 或选项处停下。

三、P 扩展、向量与运行时优化

3.1 GCC 交付 3 个 P 扩展示例，13 个提交进主线（11-19）

来源：双周报第 081 期。GCC 主线提交 fb66e0c。

三个 P 扩展示例可在 RV32 与 RV64 直接运行。场景是图像匹配、Q15 定点点积与 Q15 数字滤波，仓库附预编译工具链与两份交互式教程。

图像示例里，RV32 每条打包指令比较 4 个像素，RV64 比较 8 个。程序遍历 289 个候选位置，找回了向右 5 像素、向上 3 像素的位移。

动态指令降幅按 QEMU 在 -O3、允许非对齐访存下统计。图像匹配 RV32 降 75.7%，RV64 降 80.0%。Q15 点积分别降 70.7% 与 74.9%，Q15 滤波降 69.5% 与 73.2%。

GCC 侧 13 个提交进主线。8 个改进位操作与旋转，4 个支持向量点积，1 个修通用循环优化。

K1 实机上的收益集中在标量位操作。32 位掩码的置位、清位与翻转，执行周期都减少约 27%。RV64 的单比特置位函数从 3 条指令缩到 2 条。

其他微基准有正有平。移位加法接左旋或右旋省约 19.8% 周期，接除法或取余时动态指令减 8.30%、周期持平。gem5 上拼接两个 32 位字省 32.77% 周期，SQLite 变长整数解码反增 0.63%。

向量点积的 Zvdota 与 Zvbdota 已进主线。C/C++ 可调用整数、BF16、FP8 点积与批量 FP32 点积。

Binutils 侧投了 Shlcofideleg v2。RISE 的 pre-commit CI 首次跑通手动试运行，三种配置能把补丁测试结果与生产基线自动比对。

3.2 LLVM 14 个 P 扩展 PR，13 个已合入（11-19）

来源：双周报第 081 期。LLVM PR #243813。

本期提交 14 个 P 扩展 PR，其中 13 个已合入上游。剩余一个仍在 review。

已合入的覆盖面较宽。扩宽移位的合法化被限制到左移，修掉右移被误选成左移指令的问题。

新增的 intrinsic 包括标量饱和移位加法、标量比较、饱和与舍入移位、高低半字乘法累加、标量 zip/unzip、窄化裁剪。

另有一批修复。zext_invec 补上 v8i8 到 v2i32 的匹配模式，打包移位遇零直接返回原操作数，RV32 的 i64 移位量合法化不再断言失败。

WADDA 与 WSUBA 在零累加值时的崩溃也修了。原因是零累加被选成 X0_Pair，改用 buildGPRPair 构造寄存器对。

GlobalISel 侧保留 KCFI 类型信息。间接调用因此能生成检查，行为与 SelectionDAG 一致。

仍在 review 的是 #243813。它按 P 扩展的有符号移位语义，折叠超出元素位宽的常量移位，生成零值或等价的填充与最高位提取。

3.3 V8 在 K3 上 JetStream 3 总分 +3.5%（11-19）

来源：双周报第 081 期。CL 8698757。

本期 V8 的收益来自一批性能补丁。双周报写明这些补丁由 riscvlint 等工具找点、AI 辅助起草与基准验证，再由 ISCAS 维护者人工评审后合入。

最大单项是蹦床池之后的短跳转。原来用 8 至 12 字节的 auipc 加 jr，现在改发 4 字节 jal，并新增 far-jump pool 保证目标可达。

K3 真机上 JetStream 3 总分提高 3.5%。75 项里 46 项超过噪声，gaussian-blur 单项提高 27%，wasm 类提高 17% 至 22%。生成代码减少 1.7 MB，约 2.2%。

Zfa 的 fli 也进了 TurboFan 与 Liftoff。每个浮点常量从 3 条指令变成 1 条 fli.d，JetStream 3 里消掉 248 处。

另有两笔清理。空寄存器列表的 PushAll 与 PopAll 提前返回，Maglev 去掉约 9 万条无用指令。Int32 比较直接比寄存器，指令数再降 0.47%。

内置模拟器侧同样有收益。IsShortInstruction 改为头文件内联后，richards 从 28.9 秒降到 19.0 秒，降幅 34%；ML 从 40.2 秒降到 27.3 秒，降幅 32%。

调试检查的缓存再省一成。未开调试时跳过六项检查，richards 降 27%，ML 降 28%。解码路径优化后，richards 再降 20%，ML 再降 22%。

本期合入与审阅的补丁各 13 与 15 笔。内容包括堆数值去重、Liftoff 栈参数符号扩展、fence 与 AMO 内存序建模、CAS 地址计算顺序等。

四、Buddy Compiler 动态

4.1 AME 方言换成 ZTT v0.6，138 个指令 op 合入（11-19）

来源：buddy-mlir PR #1066。

#1066 在 19:21 合入，改动 30 个文件，+8349 −1277。它把已退役的 AME 方言整体替换为 ZTT v0.6，命名空间仍是 ame。

新方言定义 138 个带类型的指令 op。每个 op 配自定义汇编语法、intrinsic 桥与矩阵/累加器目标扩展类型。

降级统一走 lower-ame，落到 llvm.riscv.ztt.* 调用。intrinsic 桥保留直接翻译到 LLVM IR 的路径。

验证分两层。一组覆盖降级、诊断、全 intrinsic、混合方言、副作用与后端选择。另一组是两个 freestanding 负载，在 AME_gem5 上以原子系统调用仿真模式跑。

4×4 的有符号 i32 负载与独立标量参考逐位比对通过。PR 说明写明替换了旧 ISA 契约，不承诺与旧实现的数值行为兼容。

文档不在本 PR 内。README 与独立文档留到后续 PR，BOSCAME 与 XTAME 的实现也未改。

4.2 LLVM 跟到 163d6a7，XSAI 的 ZAMES 与 ZMASYNC 进后端（11-19）

来源：buddy-mlir PR #1067。llvm-project PR #33。

#1067 在 19:20 合入，只改 LLVM 子模块指针，+1 −1。旧指针是 542365c9cd38，新指针是 163d6a753b58。

新指针对应 llvm-project fork 的 #33 合并点。该合并给 RISC-V 后端加入 XSAI 的 ZAMES 矩阵指令与 ZMASYNC 同步指令。

覆盖面包括矩阵与同步 intrinsic、无尺寸的目标扩展类型、汇编与反汇编，以及 RV64 的 SelectionDAG 降级。

边界同样明确。矩阵的拷贝、溢出与重载，以及跨函数 ABI 支持，都不在已支持范围内。

这次更新是 Buddy 原生 ZAMES 支持的前置条件。PR 说明写明，LLVM 后端就位后才能在 Buddy 侧接原生命令。

4.3 EmbeddingGemma-300M 在 K3 上提速 23 至 38 倍（11-20）

来源：buddy-mlir PR #1070。

#1070 在 11-20 凌晨 01:56 开出，改动 19 个文件，+3072。它接着 #835 的工作，修模型导入、RAX 打包与分词器兼容。

优化手段是 IME 与 RVV。单次前向在 K3 上相对 F32 RAX 基线提速 23.24 至 38.24 倍，相对原生 Hugging Face F32 提速 7.11 至 19.03 倍。

内存占用同步下降。峰值进程 RSS 相对 RAX 基线降 71.6% 至 93.5%。九个负载、81 次正式运行都通过嵌入精度门槛。

导入侧的修法换成了整图。双向加性掩码在模型包装层构造，一次导入到池化、两层 dense 与 L2 归一化，旧版对生成 MLIR 做文本改写。

批形状与滑动注意力也修了。导入用 eager attention，全量掩码与滑动掩码分开传，不再假定 B1。

4.4 GPT-2 解码修复开出，多项式近似数学 pass 待审（11-19）

来源：buddy-mlir PR #1069。PR #1068。PR #1065。

#1069 在 23:57 开出，修 GPT-2 解码的数值错误。问题出在转置 B 的批量矩阵乘被解码向量化按非转置布局处理。

linalg 层没有单独的转置 B 算子。两者共用 linalg.batch_matmul，只靠 indexing_maps 区分。解码流水线里两个 pass 前后相邻，前一个把所有 batch_matmul 都按默认布局向量化。

修法是加守卫。只有默认 indexing_maps 才进入向量化，转置 B 留给后面的专用 pass，并把这类算子标为动态合法。改动 2 个文件，+127。

#1068 是数学近似的本体，仍在审。新 pass 把 exp、tanh、log 等向量数学换成多项式，让计算留在向量寄存器里，不再逐 lane 调 libm。

上游 MLIR 的近似在六个算子上有边界问题。log 与 log2 把次正规输入钳到 FLT_MIN，sin 与 cos 的单常数归约在大参数上失真，atan2 的象限判断也有偏差。这个 pass 为它们另写了模式。

sin 与 cos 用三段 Cody-Waite 归约，超过 1e5 的参数走 192 位 Payne-Hanek。只在向量里出现这类 lane 时才进分支。

循环尾部也改了。avl 循环让余数只跑一次活跃长度迭代，不再切半加标量循环。

#1065 同日 11:10 关闭，未合入。它做的是 linalg.transpose 的缓存友好分块，创建于 11-18。
