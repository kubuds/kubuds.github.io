今日重点：RuyiTuner v1.8 发布，周末完成实际编译对比阶段、三阶段流水线成形

日期：2026-09-25 ~ 2026-09-27　来源：v1.8 Release、CHANGELOG、real_compile 拆分提交

RuyiTuner 是如意社区面向 LLVM 的编译器调优工具，基于「优化协同效应分析」自动搜索能够最大化缩减代码体积的 pass 序列。北京时间 09-25 上午（09:06），该工具发布 v1.8（tag 指向提交 a032c28c「Add ruyi-cc to use pass seq into project」）。v1.8 相对 v1.7（09-17）收拢的更新包括：为整个项目搜索公共 pass 序列的 --search_scope project 模式（聚合适应度 GA）、--max-path-length 参数、以及 scripts/ruyi-cc.sh 编译器包装脚本——把最优序列接入项目正常编译流程（make CC=scripts/ruyi-cc.sh），序列按评分口径做嵌套处理，-fPIC / -mcmodel 等代码生成选项转发 llc，已在 bzip2-1.0.2 上完成全量编译、链接与压缩解压功能验证。其中项目级搜索与 --max-path-length 两部分此前窗口已分别跟踪（09-22 / 09-24）。

发布后开发并未停步：09-25（7 笔，09:06 ~ 19:31）与 09-27（6 笔，16:11 ~ 18:22）两天，v1.x 分支连续 13 笔提交（并两次合并入 main），把 1.9 版本线推进到「实际编译对比」成型——先让项目级搜索的序列落盘（09-25 17:04），再把「用最优序列真实编译源码并报告体积缩减率」的阶段加进主入口（18:27），随后把能力从临时包装脚本收编，删除 scripts/ruyi-cc.sh（19:31）；09-27 将该阶段拆分为独立脚本 real_compile.py（18:10），与 train.py、run.py 构成三阶段流水线（阶段标题 1/3 至 3/3），并完成：输出按阶段重新编号（枚举文件改为 Step1 前缀、序列与结果改为 Step2 前缀）、协同对查找中间文件不再落盘（改为内存传递）、--dataset 支持单个 .c / .i 源文件、GA 的 obj-size 评分切换 pic 重定位模型（对齐 clang 在 x86_64 上的默认口径）、实编译阶段复用 C→IR 缓存的 .ll 文件、按项目抽取 x86 / RISC-V 代码体积数据、原理示意图更新至 V2.0。

截至窗口末，1.9 尚未发版（最新 Release 仍为 v1.8），其变更已完整写入 CHANGELOG「1.9 版本变更」段；工具的版本与架构通用性保持不变（不绑定 LLVM 版本与目标架构，目标由输入 IR 的目标三元组决定）。此轮重构把此前「两阶段搜索 + 外部编译包装脚本」的形态收敛为一条内置的三阶段流水线。

五、趋势观察

5.1 周末特例：单人维护者的高频迭代窗口

RuyiTuner 是本窗口唯一的高频开发面——09-25 与 09-27 两天由同一维护者连续推送 13 笔提交并两次合并入 main，把一项跨窗口进行中的重构（临时编译包装脚本到内置实编译阶段）收口为三阶段流水线。回看版本节奏：v1.6（08-31）到 v1.7（09-17）间隔约两周半，v1.7 到 v1.8（09-25）为 8 天，1.9 变更已在途——工具线以「每周可用增量」的速度迭代，与新窗口里主栈的安静形成对照。

ruyi 0.53.0 发布（09-24）后的第一个完整窗口内，主仓库仅一笔测试子模块跟进（#503）；0.53 版本周期相关的三条问题（#495、#498、#501）当前均已关闭，仅剩长期跟踪项 #401（PyPI 在 RISC-V 上的安装就绪跟踪）仍在开放列表。结合 077 期「下一版本 10 月底」的预告，当前处于版本间的维护安静段——发布质量关注点转向社区安装反馈。

5.3 支持矩阵的 RT-Thread 线继续扩展

窗口内支持矩阵唯一合入是 ESP32-C3 的 RT-Thread 5.3.1 报告；近两周该矩阵的 RISC-V 板卡覆盖多来自 RT-Thread 与 Zephyr 两款实时操作系统（CH32V307、ESP32-C3 连续更新），同时 Milk-V Duo S 平台三笔（RT-Thread / RT-Thread Smart / Zephyr）仍在队列。RISC-V 开发板的操作系统级测试目录在持续加密。
