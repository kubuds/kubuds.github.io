2.1 编译器调优工具 RuyiTuner 实现项目级搜索：聚合适应度遗传算法落进 v1.x 分支（09-22）

日期：2026-09-22　来源：v1.x 提交 d2367ec0、CHANGELOG

北京时间 09-22 15:59，ruyisdk 组织下的编译器自动调优工具 RuyiTuner 在 v1.x 开发分支合入一笔中等规模提交（+274/-154 行，覆盖 CHANGELOG、Readme、RunCSiBE 文档与 scripts/utils/GA.py 等 6 个文件）：Implement project-scope search with aggregated-fitness GA and update docs，正式实现项目级搜索模式。

按 CHANGELOG 记法，这构成 1.8 版本变更。要点有三：其一，utils/GA.py 抽出通用遗传算法搜索核心 _ga_search，并新增项目版函数 LeverageSyner_GA_codesize_project——适应度由「单文件指令数缩减比例」改为「按文件大小加权的整体缩减率（Σ基线−Σ优化后）/Σ基线」，为整个项目搜索一条公共的最优 pass 序列；其二，单文件版函数相应更名为 LeverageSyner_GA_codesize_file，与项目版对应，run.py 调用同步更新（--search_scope 参数此前先以「尚未实现」占位，本期补齐）；其三，工程细节上，序列在个别文件上 opt 失败时回退原始 IR 计数，并新增「（文件，序列）→大小」缓存以减少重复的 opt 运行。CLI 随之间接打通：ruyituner.py 移除占位提示，project 模式可走完训练加优化全流程。

RuyiTuner 的定位是「基于优化协同效应分析的 LLVM 调优工具」：不绑定特定 LLVM 版本与目标架构（由输入 IR 的目标三元组决定，天然覆盖 x86 与 RISC-V），通过实测挖掘「组合效果优于单 pass 之和」的协同对，再以遗传算法在协同对构成的搜索空间内寻找代码体积最优的优化序列。配套的 RunCSiBE.md 记录了 CSiBE v2.1.1 十九个基准项目在 LLVM 22.1.0-rc2 的 x86 与 RISC-V 工具链上的实测平均优化率，例如 compiler 项目 RISC-V 侧 53.94% 等；该文档本次同步补充了 --search_scope 的用法示例。仓库由社区开发者持续维护（8 月下旬建立，Apache-2.0），本次更新是其在 ruyisdk 组织内的首次日报收录。

RuyiTuner 本期补齐的项目级搜索（2.1）值得与前两期报告连起来看：09-21 是 GCC 侧为进迭时空 X100/A100 补齐 -mcpu/-mtune（工具链「认识核心」），09-17 是 ONNX Runtime 的 RVV 内核实测数字（算子「跑得更快」），本期则是把「优化序列怎么选」交给遗传算法做项目级自动调优（收益「落在整包体积」）。三者拼出 RuyiSDK 在编译器侧的一条完整链路：核心识别→算子优化→序列调优。项目级模式把评价指标从单文件升格为整包加权，直接对应软件发行中「整包体积」的真实诉求；下一步值得跟踪的是它是否被纳入 RuyiSDK 官方工具链分发，以及 RISC-V 数据集侧（datasets/ll_files/riscv）的扩充与新版 LLVM 的适配节奏。

5.2 发布与活动进入密集周：云栖大会（至 09-24）叠加双周报 077（09-24）

本窗口同时开启两条对外时间线：09-22 云栖大会启幕、如意社区展台开放至 09-24；同日晚间第 077 期双周报完成集成、计划 09-24 发布。叠加此前一周 K3/CoM260 平台的内容闭环（报告、示例、课程）与 P550 板卡的新增报告，RuyiSDK 的「对外可见度」在 09-22 至 09-24 三天内达到近期高点：线下有大会展台，线上有双周报与支持矩阵更新。关注点自然落在 09-24 双周报正式版是否公布 ruyi 新版本号（预发布线 0.54.0-alpha 之后的状态）与云栖大会的后续洽谈成果。

5.3 板卡验证的上下两端：应用级 P550 与 MCU 级 CH32V307 同期推进

本期支持矩阵的两笔报告分别覆盖两个端点：SiFive Premier P550（应用级、可跑 Fedora 44 Server）与 CH32V307（MCU 级、RT-Thread BSP 5.3.1）。结合 K3/CoM260 的多系统报告与 P550 文档、示例的同步补齐，RuyiSDK 的板卡支持矩阵在「应用处理器—MCU」整个跨度上都在滚动更新，且每块新增板卡的配套资产（系统报告、板卡文档、示例代码、课程入口）的完整度在提高。对以开发板为交付载体的团队，这意味着工具链之外的可复现材料在增厚。

5.4 本窗口的空白与关注点

需要如实记录的空白：PyTorch fork 无任何功能侧推进（riscv 分支与 8 个开放 PR 双静默，RVV 两笔补丁继续等待）；triton-riscv、tilelang-riscv 与向量算子专项目标仓库全部静默；ruyi 与 packages-index 无提交与发布；openRuyi 组织进入平静窗口；新闻侧对 RuyiAI、RuyiSDK、如意社区、openRuyi 的 Google News 中英文多组查询连续零命中，arXiv 窗口内无新收录。关注点：一是云栖大会展台在 09-23 至 09-24 的后续动态；二是双周进展第 077 期 09-24 正式发布及其是否带来 ruyi 版本节点；三是 RuyiTuner 项目级搜索的实际基准数字更新与纳入官方工具链的可能；四是 openRuyi 2026.09 月度版本公告。
