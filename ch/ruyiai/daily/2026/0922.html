今日重点：进迭时空 X100/A100 核心支持合入 RuyiSDK GCC 16.2 分支

日期：2026-09-21　来源：spacemit-x100 提交、Spacemit-A100 提交

北京时间 09-21 15:04 与 15:10，RuyiSDK 的 GCC 多版本维护仓库 riscv-gcc 的 16.2 分支先后合入两笔进迭时空核心支持补丁：RISC-V: Add basic spacemit-x100 core support 与 RISC-V: Add basic Spacemit-A100 core support，把两颗核心正式加入编译器的 -mcpu/-mtune 选项。

X100 一笔将调度映射到现有的 generic_ooo 模型，改动覆盖 riscv-cores.def 的核心与调优条目、riscv.cc 中新增的 spacemit_x100_tune_info、mcpu/mtune 文档再生成，并附新增用例测试 mcpu-spacemit-x100.c。A100 一笔的说明更详细：该核心为顺序双发射、微架构接近 X60，因此暂复用 Spacemit X60 的成本模型；ISA 上最接近 X100，主要差异是不实现 H（虚拟化）扩展、向量长度 VLEN=1024（zvl1024b），并带有 xsmtvdotii 扩展——该扩展定义一并写入 riscv-ext-spacemit.def 与扩展文档，测试与核心条目同步补齐。

两笔补丁的作者均为进迭时空的 Mark Zhuang（补丁署名日期为 6 月底），09-21 由仓库方完成合入。对采用 K3 平台的开发板（如 CoM260 Kit 的 8 颗 X100 加 8 颗 A100 核组合）而言，这意味着 RuyiSDK 工具链可以直接以 -mcpu 选择这两颗核心并获得对应的扩展定义与调度设置，而非仅使用通用配置。考虑到两笔均为 basic support（X100 用通用乱序模型、A100 复用 X60 成本），后续的调度细化与测试覆盖值得在日报中继续跟踪。

本窗口最具体的技术进展是 riscv-gcc 16.2 分支为进迭时空两颗核心补齐 -mcpu/-mtune 与扩展定义（含 VLEN=1024 与 xsmtvdotii）。结合 09-17 的 ONNX Runtime MLAS RVV 内核优化（K3/X100 实测提速 3.01 倍），针对 K3 平台的两条支撑线同时推进：性能侧有可复现的算子级数字，工具链侧有核心级识别与调度入口。下一步值得跟踪的是调度模型细化——X100 暂用通用乱序模型、A100 复用 X60 成本模型均属过渡方案——以及这些核心支持后续的维护路径。

5.2 openRuyi 的滚动更新进入内核双线与构建规范化阶段

单日 56 次提交中，内核 7.2.6 与 LTS 6.18.52 双线升级、openruyi-linux-build 新包与 RPM 宏重构是本轮最重的两块，其余为安全更新与云原生、桌面包补齐。结合新闻页尚无 09 月版本公告的现状，月度版本的内容仍在快速累积；下一个观察点是 2026.09 月度版本公告及其随版的内核与安全基线。

5.3 K3/CoM260 平台一周内完成验证、示例与课程的内容闭环

从 09-18 的 K3 Pico-ITX ROS2 课程入口，到 09-20 的 CoM260 Buildroot 报告、09-21 的 CoM260 Kit 三系统批量报告与 board-docs 示例补齐，再到同期 GCC 侧的核心识别支持，K3 平台在一周内完成了「多系统验证—示例代码—课程材料—工具链」的连续覆盖。对以 K3 为目标的开发者和产品团队，工具链、系统镜像与学习材料的就绪度明显提升。
