今日重点：buddy-mlir 一夜七笔补齐 RVV 可伸缩向量，双周报 079 期落版（10-26）

日期：2026-10-26　来源：buddy-mlir 主分支提交列表、#1002 按 vscale 步进、#1008 索引向量自动尺寸、双周进展 079 期

本期最集中的推进来自 Buddy Compiler。北京时间 10-26 22:48 到 10-27 03:22，四个半小时内七笔提交全部落在 VIR（向量化中间表示）上，围绕同一个开关 use-scalable：先是让 strip-mining 循环按 vscale 步进（#1002），再让向量尺寸选择在 RVV 上按 vscale = VLEN/64 与 LMUL 计算（#1003），随后把带结果的 vir.set_vl 降到可伸缩向量（#1004、#1005），补上动态向量的行置换 vir.shuffle（#1006），统一 vir.load 与 vir.store 的索引约定（#1007），最后修掉索引向量在没有显式宽度时的断言崩溃（#1008）。七笔串起来是「让 VIR 真正能用可伸缩向量表达」的一条完整链条，而不是零散修补。

同一窗口内，RuyiSDK 双周进展第 079 期于 18:02 发到社区论坛。报告期截至 10-22，本次落版给出两个明确时间点：包管理器 0.54.0 因发版周期调整改到 10 月底，openRuyi 月度版本仍未发布。开发中项也写得很具体——包与系统的 ABI 兼容性检测、更多官方包的 macOS 打包、SpacemiT K1/K3 的工具链适配。

上游侧的另一件事值得并读：llvm-project 的 riscv 分支在 10-26 23:00 完成六天内第四次换基，基线再前移 221 笔，26 个本地补丁一字未改；而换进来的上游内容里，有 17 个 RISC-V 后端 pass 在一小时内被同一作者迁入 NewPM。上游在换编译器管线，本地在换向量表达，两端同时动，但中间层（triton-riscv 的依赖锚点、pytorch 的 riscv 分支）本期都没接上。

日期：2026-10-26　来源：InsertVSETVLI 迁移、PreAllocZilsdOpt 迁移、DeadRegisterDefinitions 迁移

换基带进来的 221 笔上游提交里，RISC-V 相关 21 笔，其中 17 笔是 NewPM 移植，作者均为 Aiden Grossman，时间集中在 10-26 12:59 至 13:55（北京时间）不到一小时。清单覆盖后端主要 pass：指令选择后的 VSETVLI 插入、读写 CSR 与 VXRM 写入、VMV0 消除、压缩指令生成、压栈出栈优化、基址合并、LoadStore 优化、Zilsd 预分配、分支优化与 QCRelax 标记，另有寄存器死定义消除、冗余拷贝消除、间接跳转跟踪、落地垫设置与常量提升。

2.3 openRuyi：Go 回移 SHA-2 的 Zvk 向量密码学优化（10-26）

日期：2026-10-26　来源：openRuyi PR #1512、openRuyi 合并 PR 列表

18:33 合入的 PR #1512 是本窗口唯一一条与 RISC-V 指令集直接相关的发行版改动：把 Go 主线对 Zvk 的 SHA-2 支持回移到 openRuyi 的 Go 打包里。Zvk 是 RISC-V 向量密码学扩展族，SHA-2 是其中最常用的算法套件，回移意味着发行版里的 Go 工具链在支持该扩展的核上可以直接走向量指令，而不必等下一个 Go 大版本。

这条与 079 期里 GCC 侧的 Zvdota/Zvbdota rebase 形成呼应：工具链（GCC）与运行时（Go）两侧同时在接向量密码学，方向一致但通道不同——前者靠下游 fork 自己维护，后者靠发行版打补丁回移。

4.1 VIR 一夜七笔：从循环步进到索引约定一次补齐（10-26）

日期：2026-10-26 至 2026-10-27　来源：#1002 按 vscale 步进、#1003 RVV 可伸缩尺寸、#1006 动态向量行置换、#1007 统一索引约定

七笔提交由同一作者在 22:48 至次日 03:22 连做，编号 #1002 至 #1008，全部是 [midend][VIR] 前缀。看内容能拆成三层。

第一层是循环与尺寸：#1002 修掉 strip-mining 循环的步长——此前 vir.set_vl 不带结果时降成以常量 vector-width 为步长的主循环，每轮却按 N 倍 vscale 条 lane 访存，vscale 大于 1 时迭代会重叠；#1003 让尺寸选择在 RVV 上按 vscale = VLEN/64 计算，使 N 与 SEW 决定 LMUL 而不再退回定长向量；#1008 修掉索引向量在未显式给宽度时因为按元素位宽取尺寸而触发的断言。

第二层是带结果的 vir.set_vl：#1004 允许它降到可伸缩向量，此前它的分片（vl 与宽度向量、vl 对宽度取余的标量）依赖编译期已知的 lane 数；#1005 进一步支持多维动态向量，因为 decode attention 的 query 是从 region 外的 vir.from_vector 带进来的。

第三层是访存与置换：#1006 加上动态向量按行置换的 vir.shuffle；#1007 统一 vir.load 与 vir.store 的索引约定，让带结果与不带结果两种 set_vl 在多维动态向量上把行映射到 memref 末维之前的维度，与 vector.load 保持一致。

4.2 动机链：decode attention 与 RoPE 的表达缺口（10-26）

日期：2026-10-26　来源：#1005 多维动态向量、#1006 行置换、buddy-mlir 主分支提交列表

从提交说明看，这七笔不是泛化的向量化改造，而是被具体算子逼出来的。触发点是 VIR 的 decode attention：RoPE 的 rotate_half 要把一个 128 元素的头按前后两半互换再取负，即 [-x[1], x[0]]，本质是按行置换；而 VIR 此前无法表达动态向量的行置换，只能在外层用定长向量算好再把 query 带进 region。

于是 #1006 补置换、#1005 补多维动态向量、#1007 补索引入口，三笔合成一条「让 decode attention 整套留在 VIR 里」的路径。这条路径的意义在可移植性：一旦算子能完整表达，后端换 RVV 定长或可伸缩只影响降级，不影响中间表示。

六、趋势观察

6.1 上游换管线、本地换表达：同一天各走一步

10-26 这一天，两条与 RVV 相关的线同时动了：上游把 17 个 RISC-V 后端 pass 迁进 NewPM，本地把 VIR 的可伸缩向量支持补齐到索引约定。前者改的是编译器内部管线的组织方式，后者改的是中间表示对 RVV 的表达能力，两者指向同一个结果——RVV 的可伸缩向量不再只是「能生成」，而是「能被完整表达并稳定经过新管线」。

但中间层没跟上。triton-riscv 的 buddy-mlir 锚点仍停在 10-17 夜间版，pytorch 的 riscv 分支连续五日零提交。这意味着上游与本地两端的进展，本期都还没有落到 RuyiAI 栈的算子生成与框架适配这两级。判断这条栈是否真的在推进，下期应看两件事：triton-riscv 是否更新锚点并重建，pytorch 分支是否恢复重放。

6.2 发版窗口被双周报钉到月底，发行版进入补安全、攒包的收尾节奏

079 期把两个日期说得比以往清楚：ruyi 0.54.0 因发版周期调整改到 10 月底，当前正式版停在 0.53.0；openRuyi 2026.10 仍未发布。与之对应，openRuyi 本期 80 笔提交里 31 笔是安全修复、18 笔是 Rust crate 补齐、14 笔是版本更新，涉及 48 个包——这是典型的发版前清扫：先把依赖链补全、把 CVE 清掉，再切版本。

值得注意的是 ISCAS 软件源同步问题导致 packages-index 近两周无包更新，这会让 ruyi 用户在 ruyi update 时看到的内容落后于仓库实际状态。若 0.54.0 按期发布而软件源未恢复，包清单与发行版版本之间会出现一段错位，这是下期需要核实的风险点。
