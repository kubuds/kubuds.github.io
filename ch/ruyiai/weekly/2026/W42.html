RuyiAI周报（2026-10-12 ~ 2026-10-16）

2026-10-16 苦芽科技

报告周期：2026 年 10 月 12 日（周一）至 10 月 16 日（周五），共 5 个工作日

素材来源：本刊每日 RuyiAI 动态报告 5 期（2026-10-12 至 2026-10-16，每期窗口为前一日 04:30 至当日 04:30）；另含 RuyiAI-Stack、ruyisdk、buddy-compiler 三个组织的 168 小时仓库核查、openRuyi-Project 重点仓库补充核查，以及 RuyiSDK 开发者社区与 openRuyi 新闻页双源复核（覆盖至 10-17 晨）

编制说明：本周技术主线是 openRuyi 的 K3 固件平台线（10-13 至 10-15 三日连发三版）与 Ztt 矩阵扩展工具链的 GCC + LLVM 双后端落地。周报在日报素材之外补入两项核查新发现：其一，10-15 上午 riscv-gcc 的 ztt-dev 分支单批 20 笔 Ztt 提交（当日日报未收录）；其二，10-16 的 tilelang-riscv 复苏与 Buddy MLIR 0.1.0 发布（发生在日报窗口之后）。

一、本周要闻

  • openRuyi 开辟 K3 固件平台线，10-13 至 10-15 三日连发三版固件：10-13 新建 edk2-ruyi（35 笔整批首推 SpacemiT K3 Pico ITX 的 EDK2 平台代码）与 ruyifirmware（5 笔建立打包发布链），当日 18:46 发布首个版本「Ruyi Firmware 20261013」；10-14 第二版引入 UEFI 内的 CPU 模式选择（X100 仅用 / X100+A100 混用 / A100 仅用，含 RVV 与 H 扩展开关）并持久化保存；10-15 第三版加入只读 System Information 页、x64 与 ARM64 UEFI 驱动模拟（默认关闭、经 Platform Settings 启用）与实验性 AMD ARM64 GOP 1.68 试点。来源：edk2-ruyi、Ruyi Firmware 20261013、20261014、20261015

  • Ztt 矩阵扩展工具链补齐 LLVM 侧，形成 GCC + LLVM 双后端（10-12）：ruyisdk/llvm-project 于 10-12 上午新建 ztt-dev 分支并完成 26 笔 LLVM / Clang 补丁整栈首推（作者 LukeZhuang，覆盖 Ztt 扩展基础支持、函数级 profile、CSR 与矩阵寄存器组、指令汇编与反汇编、IR 类型与 intrinsic、Clang 矩阵寄存器类型、寄存器分配后伪指令展开、M 寄存器与 ACC 溢出处理，末笔把测试对齐 AME 诊断体系）；GCC 侧 riscv-gcc 的 ztt-dev 分支 09-30 建立后已连落 10-08 的 36 笔、10-11 的 51 笔与 10-15 的 20 笔（末批由本周核查发现）。叠加 attached-matrix-extension 的 Ztt intrinsic 文档 V0.6 PR，「规范—文档—双工具链」链路同步活跃。来源：llvm-project ztt-dev、头部 aeb52e1a、riscv-gcc ztt-dev

  • Buddy MLIR 0.1.0 正式发布，RISC-V 交叉编译与 CI 全面铺开（10-16）：buddy-compiler/buddy-mlir 本周 13 笔提交、3 个发布（核查窗口含边界日共 16 笔、4 个发布），其中 0.1.0 于北京时间 10-16 凌晨发布（tag release/v0.1.0），随后夜间线转入 0.1.1.dev 系列（dev20261016、dev20261017）。RISC-V 线动作密集：为 buddy-cli 增加 RISC-V 板卡交叉编译（#987）、修复 Makefile 的 RISC-V 目标（#986）、简化交叉编译流程（#975）、为 buddy-server 增加 RISC-V 服务端交叉编译（#989），并在 manylinux riscv64 构建中以 Ruyi 包索引安装 riscv64 版 torch、补齐 libsndfile（#990、#937、#988）。来源：buddy-mlir、BUDDY MLIR 0.1.0、PR #989

  • RuyiAI 的 tilelang-riscv 结束近一月静默：5 笔 RISC-V 提交接入 Buddy 发布链（10-16）：该仓库上次提交为 09-20，本周五连落 5 笔——代码格式化、支持上游算子运行时语义（lane-local 状态、ragged copy、动态控制流、FP8/FP4 转换修正）、升级 TileOps 运行时适配（子模块升至 67250e81，跑通 paged-cache gather 与 varlen GQA sinks 内核）、新增 Buddy MLIR release CI 与在 Buddy CI 中构建 Python 扩展。这意味着 TileLang 的 RISC-V 后端开始以 Buddy MLIR 的版本产物为基准做持续集成。来源：tilelang-riscv 提交列表、5 笔首批 32fce5ed

  • openRuyi 发行版单周大维护：Go 模块约 90 笔、KDE Plasma 6.7.5 共 39 包、LLVM 24、mesa 26.2.4 与 PowerVR 回移（10-12 ~ 10-14）：10-12 主仓库 40 笔，其中 39 笔把 KDE Plasma 桌面栈整体升至 6.7.5（plasma-workspace / kwin / systemsettings / powerdevil / breeze 等）；10-13 单日 103 笔——约 90 笔为 Go 生态模块批量更新（k8s 0.37.1 系列、gRPC 1.84、OpenTelemetry Collector 1.67、云厂商 SDK 等），另含 llvm-snapshot 升至 LLVM 24、audit 4.2.1 启用 RISC-V 支持、GnuPG 栈整批更新；10-14 三笔转向图形栈：mesa 26.2.4 与首轮 PowerVR 优化回移。10-16 又新增 rust-riscv-0.16 等 6 个 Rust RISC-V 相关 crate 的 SPEC。来源：openRuyi 提交列表、PR #1410、PR #1347、PR #1399

  • ruyisdk/llvm-project 合入 XTHeadVector 索引访存混合宽度修复（10-13，PR #168）：修复 th.vlxe / th.vxse 在数据与索引元素位宽不一致场景下的处理（保留有符号偏移、内存元素大小、掩码 passthrough 与零长度语义），把 intrinsic 降低扩展到整数与浮点向量的混合宽度，并为 RV32 / RV64 补充掩码、零长度、负偏移与大索引用例的 codegen 覆盖。该 rebase-17.0.6 分支上一次实质提交是 6 月，此次为玄铁向量工具链线由长期维护转入针对性修复的标志。来源：PR #168、issue #136

  • 内核双线推进：openRuyi linux 新开 ruyi/7.3.y 首批 31 笔；linux-xuantie-kernel 厂商键统一为 XUANTIE 并补 hwprobe 扩展（10-15 ~ 10-16）：ruyi/7.3.y 于 10-13 建立、10-15 落首批 31 笔（K3 GPU 节点与显示电源域、Type-C Port A / USB3 PHY / FUSB301、以太网 MAC 绑定 EEPROM、spacemit DP 修复系列、amdgpu 在 K3 禁用动态 PCIe 速率切换、UFS FASTAUTO、SG2044 SRD3-12 板级支持等）；linux-xuantie-kernel 10-15 把 T-Head 厂商扩展键整体更名为 XUANTIE 形态（XTHEADVDOT → XUANTIE_VDOT 等），10-16 再补 4 笔——把 Ziccamoa / Ziccif / Ziccrse / Za64rs / Zicclsm 纳入 cpufeature 与 hwprobe、在 ISA 扩展 id 空间划出私有带、并让扩展 id 与上游对齐。来源：ruyi/7.3.y、linux-xuantie-kernel

  • 双周报 078 上线，主题为「RuyiSDK 将亮相 RISC-V 中国峰会」；峰会 10-18 至 10-20 在深圳举行（10-13）：078 期经 8 笔编撰流水线（#371 ~ #378）定稿并同步论坛，要点包括包管理器 0.54.0 预计月底发布（ABI 兼容性检测、macOS 官方软件包、SpacemiT K1/K3 工具链适配在开发中）、IDE 一轮打磨、glibc 与 newlib 各 6 个向量数学函数移植、GCC 的 ZTT 后端完善与 GEMM/GEMV 验证方案（编译时间降低约 5.05% ~ 6.97%）、LLVM 的 RISC-V P 扩展 intrinsics、V8 首次在真实硬件上开展 RVV Wasm SIMD 测试并合入 hwprobe 回退补丁、OpenJDK 的 JEP 483 / 515 AOT 移植、Go 的 riscv64 原子操作修正。峰会议程含主题演讲、海报展示与 D15 展位演示。来源：078 期文件、论坛 #2891

外部动态：RISE 的 SpeexDSP RVV 优化与玄铁 C950 的矩阵扩展叙事

  • RISE SpeexDSP RVV 优化（10-14）：为 SpeexDSP 引入 Meson 构建、Checkasm 测试与手写 RVV 内核，并在 K1（VLEN 256）与 K230（VLEN 128）上验证——K1 浮点重采样相对 Clang 18 / GCC 13 基线分别约 3.71 倍 / 3.59 倍。该工作把 RVV 优化推进到 VoIP、音频重采样等基础多媒体库，与 SpacemiT 平台直接相关。来源：RISE 博文
  • 达摩院玄铁 C950 专访（10-15）：RISC-V 国际官网刊出对玄铁首席科学家孟建熠的专访——团队在 C950 的 64 核目标配置上本地运行 Qwen3.8-27B，吞吐超过 30 tokens/s，不依赖独立 GPU 或 NPU，达成该吞吐需约 400 GB/s 级内存搬运，依赖高带宽内存与硅上验证的自研矩阵扩展；团队随后联合高通、IBM、VRULL、ISCAS、BOSC 等发起 AME（Attached Matrix Extension）任务组推动标准化。要点：prefill 以稠密矩阵计算为主、decode 转向带宽瓶颈；采用独立矩阵寄存器（INT4 / INT8 至 INT32、FP4 / FP8 / FP16 / BF16 至 FP32 混合精度累加）以避免与 RVV 寄存器竞争；规范尚需覆盖数据布局、累加器、舍入与饱和、上下文保存恢复、异常与虚拟化、编译器与 ABI 映射。来源：RISC-V International 专访
  • 文档侧：attached-matrix-extension 的 Ztt intrinsic 文档 V0.6（PR #1）保持开放，与 GCC / LLVM 两条 ztt-dev 线的代码推进互为呼应。

  • K3 成为本周唯一的系统性主线：固件（三日三版）、内核（ruyi/7.3.y 首批 31 笔）、镜像（kiwi-image 自动化）三层在同一周内齐动，且固件已从「链路打通」走到「CPU 模式可选 + 驱动可模拟」。观察点在于这些能力能否在 10-18 峰会周形成可演示的整机形态，以及三档 CPU 模式的实测数据。
