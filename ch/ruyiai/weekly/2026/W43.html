RuyiAI周报（2026-10-19 ~ 2026-10-23）

2026-10-23 苦芽科技

报告周期：2026 年 10 月 19 日（周一）至 10 月 23 日（周五），共 5 个工作日。

素材来源：本刊每日 RuyiAI 动态报告 5 期（2026-10-19 至 2026-10-23，每期窗口为前一日 04:30 至当日 04:30，其中周一为过去 3 天、覆盖周末）；另含 RuyiAI-Stack、ruyisdk、buddy-compiler 三个组织的 168 小时仓库核查，openRuyi-Project 重点仓库补充核查，RuyiSDK 开发者社区与 openRuyi 发行版新闻页双源复核，以及 RuyiAI 官方主页三页快照（核查覆盖至 10-24 上午）。

编制说明：本周三条主线并行。其一，openRuyi 主仓以 637 笔提交完成「按依赖打包」的整体转向，从补 Rust crate 闭包、补 Python 云存储后端、Go 去 vendor，一路推进到补源校验和与 %autochangelog 的规范补全。其二，PyTorch 与 LLVM 两条 riscv 分支的整枝重放从「择期」收敛为「每日」，补丁标题集合不变、提交哈希每日失效。其三，RISC-V 矩阵扩展（AME 与 Ztt）的编译器、模拟器、算子三层在本周同时到位，形成「能编译、能执行、结果正确」的最小闭环。周报在日报素材之外补入七项核查新发现，均落在 10-23 白天（日报窗口之后）或周期边界，列于附录。

论文：长向量处理器上重排 FlashAttention，实测加速 1.84 至 2.08 倍

arXiv 2610.29489v1《Reorienting the Vector Axis: Restructuring FlashAttention for Long-Vector Processors》（Emmanuel Irabor、Marc Casas）把 PyTorch 的 CPU FlashAttention 内核移植到带 2KB 向量寄存器的 RISC-V CPU 上，先给出一个不客气的基线：只达峰值浮点吞吐的 16.2%。

原因分析具体：原内核按查询行逐行推进，与 V 的乘沿 64 元素头维向量化，softmax 的逐行最大值与求和是「把整个寄存器塌缩成标量」的归约，软件指数函数的多项式系数还要与 tile 数据抢向量寄存器，导致溢出到栈，三项叠加使向量寄存器利用率上不去。两条改法都不改算法与数值：其一，把分数 tile 与运行输出一起转置，让查询落在线性连续轴上，于是「一个 tile 里装多少查询」这一个参数就统一决定内核各段的向量长度，两个归约自然消失；其二，把多项式系数搬进标量寄存器，消除溢出，softmax 的向量访存指令减少 78.7%。

实测：头维 64 时两项合起来把整核周期降到 1.84 至 2.08 倍加速，浮点利用率从 16.2% 升到 29.7%；同设计的 FPGA 对两项改动的排序一致且收益更高，达 2.71 倍。对本栈的意义在方法而非数字：向量长度自适应与寄存器压力正是 triton-riscv 与 tilelang-riscv 在 RVV 降级上的结构性问题，而非「有没有 intrinsics」；文中「按机器匹配 tile 内查询数」与 IREE 把 Tile N 取 vlen/8 属同一类决策，可直接做同口径比较。来源：arXiv 2610.29489

技术情报侧本周有四项值得记录。其一，linux-riscv 上的 PAGE_KERNEL_RO 定义提案指出 RISC-V 缺该定义时会退回可写的 PAGE_KERNEL，导致 HugeTLB vmemmap 等本应只读的映射保留写权限，提案给出 QEMU virt 上的复现与修复前后页表对照。其二，系统调用重启路径需检查完整返回值，修正返回值截断问题。其三，SyterKit 在 C907 镜像中把 mstatus 向量状态置为 initial，使启动状态与编译进镜像的 RVV 代码一致；E907 则在开启缓存前先设置系统映射。其四，SpacemiT K3 PCIe 补丁 v7 收到新审阅意见，质疑用 PHY bulk API 一次控制多端口全部 PHY 的做法，指出每端口有独立 PHY 与 PERST#，资源建模需重新论证。来源：ruyiai-daily 10-19 期、PAGE_KERNEL_RO 提案、K3 PCIe 补丁 v7

七、趋势观察

打包单位从「源码树」变「依赖包」，本周完成从补闭包到规范补全的重心转移

本周 637 笔提交的主线只有一条：把「随源码 vendor」改成「按依赖打包」。Rust 侧补 crate 闭包（含 uv 构建后端的 23 个 rust-uv-* 包）、Python 侧补齐 fsspec 的全部主流云后端、Go 侧去 vendor 并把被删目录后必需的导入路径逐条补出。顺序本身说明去 vendor 的完成条件不是删掉 vendor 目录，而是让每个被依赖模块在发行版里能按原导入路径解析——缺了导入路径的补齐，删 vendor 只会直接编译失败。

这提示评价发行版进度不能只看提交数。补包、补校验和、补依赖路径都是为最终交付做准备，但任何一环卡在发布通道上，用户的实际体验就是停滞。下一个观察位是 0.54.0 是否如期在月底出 alpha，以及 ISCAS 同步问题是否随 2026.10 版本一并解决。

重放从「择期」变「每日」：两个 riscv 分支收敛为同一种运维，评审仍是实际节拍器

PyTorch 在 10-18 至 10-22 连续五个早晨整枝重写，LLVM 在八日静默后于 10-21、10-22、10-23 连续三次换基。共同特征是提交者时间被统一改写、补丁标题集合不变、提交哈希每日失效；差异只在跨度——LLVM 首日领先 1769 笔（八天积压），其后两日约 275 笔（单日常规追赶）。

工程意义是把「跟上游」与「维护本地补丁」解耦，代价是历史不可追溯：任何按哈希引用的下游（镜像构建、CI 缓存、issue 复现）都会当天或每次换基后失效，读这两个分支应以补丁标题集合而非哈希作版本判据。更值得注意的是本周补丁本身没有新增——PyTorch 七笔开放 PR、LLVM 两笔 FPGA PR 都只刷新时间戳，无新评审意见、无合入。重放机制已经稳固，实际节拍器变成了评审队列的消化速度。10-23 PyTorch 首次暂停重放，是否为节奏回调需下一周期确认。

扩展落地路径成形：编译、模拟、算子三层齐备才算可用，齐备之后瓶颈转到硬件实测

以 AME 为例，本周可见一条扩展从提案到可用的完整路径：先有后端设计与指令集定义（LLVM #16、#24、#27、#29），再有降低与调度实现（#30、#31、#32），同时模拟器给出可执行语义（QEMU ame-0.6），最后算子库提供可测的 kernel 与验证套件（AME-operator）。Ztt 也在本周补齐一侧——ruyisdk/llvm-project 的 AME 分支落下 spec v0.6 初版支持，与 GCC 侧 Ztt Md 支持、QEMU 的 Ztt 指令族实现对应。

P 扩展走同一条路但已到后半程：QEMU 覆盖全部指令（12 笔收尾批），GCC 更新到 0.6，LLVM 侧 mulq、乘高位累加、sati/usati、Packed Pair 等 intrinsics 分批合入上游。对照来看，P 扩展缺应用侧 benchmark，AME 缺真机。这个顺序值得作为方法记录：没有模拟器无法验证编译器，没有算子库无法验证模拟器；三者齐备之前谈性能没有意义，齐备之后瓶颈才转移到硬件与实测。本周的进展是「齐备」而不是「更快」。

RVV 后端焦点从「有没有指令」转向「分块与线程化」

IREE 用两天走完 f32 到 f16 的精度台阶，两次都复用同一个 lowerRiscvVFmaccLike 与同一套累加器合法化，次序是先保证有正确路径（f32），再按扩展可用性挑最快的一条（f16 原生、f16 加宽、+zvfhmin 回退），代价模型对三条路径分别定价。X60 上的实测把瓶颈位置说清楚了：单线程 inner_tiled 已快于 mmt4d ukernel，4 线程与 8 线程仍慢。

arXiv 那篇长向量 FlashAttention 重构给出的结论同源：把分数 tile 与运行输出转置、让查询落在线性连续轴之后，两个归约自然消失、寄存器溢出消除，整核周期降到 1.84 至 2.08 倍，浮点利用率从 16.2% 升到 29.7%。两者都在说同一件事——单核指令选择到位之后，剩下的是分块参数与线程化。对 tilelang-riscv 与 triton-riscv 来说，这是可逐条对照的路线图：Tile N = vlen/8 的取法、代价模型的分档方式、tile 内查询数与向量长度的绑定关系，都值得在自家 lowering 里做同口径比较，而不是只看「是否支持 f16」。

发行版开始铺桌面与虚拟化验证栈，平台形态出现服务器与嵌入式两条路径

openRuyi 的开放 PR 队列里出现一组同向提案：qemu 打开 GUI 测试特性（#1421）、新增 virglrenderer（#1415）、ovmf 支持 fwupd（#1436）、新增 ydotool（#1457）、修 xorriso 的 man 页冲突（#1489）。五项分属虚拟化、图形虚拟化、固件更新、输入自动化与光盘镜像工具链，合起来指向「在 RISC-V 上跑完整桌面并对其做自动化验证」——这与峰会展示的「AI 驱动 IDE 图形化测试」是同一需求的两端。
