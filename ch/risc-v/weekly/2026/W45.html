  • 进迭时空开源 RVISA 虚拟 ISA 规范工作草案，首轮补入 IME／VME／AME 三套映射与 blocked MMA（11-04 建仓、11-05 提交）：新仓库 spacemit-com/rvisa 提出 RISC-V Virtual ISA，为标量、向量与矩阵计算定义一层虚拟指令记法，当前规范版本号 0.2.0。定位写得很清楚：它刻意站在 NVIDIA PTX 之上、cuTile 之下——不绑定任何一门前端语言（源语言前端实现明确排除在本版范围外），也不直接规定某颗芯片的指令编码，而是把「目标映射」做成版本化 profile，逐条声明映射到哪一组寄存器类、寄存器组与指令序列，并附上游修订号与验证证据。记法参照 RVV Intrinsics 表达类型化操作、操作数角色与寄存器组约束，tile 支持一维到 N 维，reshape 与轴置换必须保持元素位置，布局由线性布局推导。最能说明它想解决什么问题的是「可表达性要求」：任何对 RVISA tile 计算的优化，都必须能被程序员在记法层面写出来——针对的正是矩阵扩展落地时编译器偷偷向量化、换一颗芯片就得重写的失败方式。成熟度需要说清：规范状态文件自己写明这是 working draft，不是 RISC-V International 已批准规范；目标映射档案只登记为草案、尚未建立实现一致性证据，MLIR dialect 与可执行一致性工具均标为 TBD，参考负载只有 .rvisa 记法源形、不能编译执行。仓库另有 RFC 0001 至 0003 三份草案，覆盖指令与寄存器映射契约、核心类型与操作契约、程序员可表达的 tile 布局。与 MCU 侧的 EM-Altair 是同一逻辑的两种表现：碎片化最终要由某一层稳定的「软件目标」收敛，差别在治理结构——一个是六家大厂合资公司主导，一个是单家厂商的工作草案。来源：spacemit-com/rvisa 仓库、规范状态页

  • Linux 7.4 把「快非对齐访问」改为运行期探测，发行版内核可吃到最多 11% 带宽收益（10-30）：这条改动的来路分两步。7.3 由 Tenstorrent 提交的改动让「为支持快速非对齐内存复制的 RISC-V 硬件编译的内核」跳过软件对齐，自测带宽提升最高 11%，但要求在编译时打开，而一个发行版内核要服务一批硬件、其中总有慢速非对齐访问的芯片，收益只能留在定制内核里。7.4 把判定改挂到 HAVE_EFFICIENT_UNALIGNED_ACCESS 上做运行期探测：只有探测到硬件确实支持，用户态拷贝才跳过软件对齐，通用构建与发行版内核都能默认带上。同批并入 7.4 的 RISC-V 改动还有 crash 热插拔、部分页表函数走优化路径、上下文切换优化、B 扩展进入 hwcap 与 hwprobe 上报、以及 Zic64b 上报支持。这几条合起来是「内核把平台能力摸清并交给自己调度」的一步，hwprobe 侧的上报正是运行期探测这类优化的前提。社区讨论里有一条判断值得记录：除 SiFive 外几乎各家都支持快速非对齐访问，SiFive 只在新一代性能核上支持——发行版打开这条优化后，实际受益面取决于芯片是否在 hwprobe 里如实上报。来源：Phoronix、Hacker News 讨论

二、指令集与架构生态

香山：一周 18 笔主仓提交，最重的一笔是 CBO 译码错误

香山主仓（kunminghu-v3）本周合入 18 笔，另有 GEM5 6 笔、NEMU 4 笔、difftest 11 笔（含 10-30 至 11-01 的九笔）。方向高度一致：找错与补可观测性，而非加功能。

  • CBO 操作码被或运算误合成 cbo.zero（11-03，#6754）：cache block 操作的指令里，操作类型本应整体选出完整操作码，代码却把「完整 CBO 操作码」与「基础操作码」做了按位或。当 CBIE 请求把 inval 转成 flush 时，or 运算把 cbo.inval 与 cbo.flush 合成了 cbo.zero——语义从「作废这一块」变成「把这一块清零」。inval 只是丢弃，zero 会写数据，带数据的清零落到正在被其他 hart 使用或即将回写的行上就是静默的数据破坏，且只在特定操作序列下触发，跑分与常规回归都发现不了。
  • 访存四笔集中排障（11-03）：#6762 让 flush 前先等 CBO zero 完成入队，#6718 修跨 16 字节非对齐访问的前递掩码，#6714 修 waitSqidx 已退休时 MdpHit 的判定，#6678 修同一 RobIdx 下 LoadUnit 回滚信息被后一条指令覆盖。四笔共同点是只在特定交错下出错：非对齐叠加前递、退休与命中判定同拍、同一 RobIdx 连续两条 load 触发重放。
  • TAGE 把 alt 信息存进 meta（11-03，#6800）：原先训练读与预测读抢同一份存储，改动把 alt 信息额外存进 meta，训练侧只在 TAGE 预测错误或实际分支结果与预测不符时才发起训练读——把一条高频读通路从关键路径上摘下来，是分支预测器里最典型的取舍。
  • 前端与预取：前端引入 FtqPrefetchQueue（10-30），是 iprefetch 重构第一步；同期把 prefetch.i／r／w 解码为 LSU 预取操作、修 MBTB 对隐藏 VBTB 分支的分配抑制。11-05 又修 MissQueue 在预取 miss 处于推测状态时仍合并 store 的问题（#6842）——store 与一次尚未确定的预取合并，一旦预取被取消，写回的数据归属就会出错。
  • 可观测性与工程流程：补 BPU 里与 s2_override 相关的性能计数器（#6777）、在 CROB 增 former／latter 剩余写回计数的解码信号（#6749）；刷新 README 并在仓库根目录加入面向 AI 编码代理的 AGENTS.md（#6849），约定构建方式、代码风格与提交规范——一个 RTL 项目主动维护这类文件，说明日常开发流程里已经默认有代理参与。

安全微架构：SecDMP 在 RISC-V 核上做出首个开源 DMP 实现
