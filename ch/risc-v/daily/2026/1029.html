今日重点：Qwenputer 把 RV32IM CPU 编译进 Qwen3.5 权重，以 GDN 状态充当 RAM（10-28）

开发者 Divyansh Agrawal 发布 Qwenputer：一个未经过训练的 Qwen3.5-4B，把一颗 32 位 RISC-V CPU 直接编译进模型权重，并用模型自身的 Gated DeltaNet 层状态作为内存。它在窗口内被 Adafruit、Startup Fortune 等多家媒体转述，并在 Hacker News 上引发讨论。

技术路径有三步。第一步把 GDN 精确化为可寻址 RAM：把门控置 1、写强度 beta 置 1、键用 one-hot 编码，每次写入只覆盖一行、每次查询只读取一个精确值，于是 GDN 头变成逐行寻址的存储，且状态大小不随上下文增长。第二步把 CPU 编译成层：无需训练，编译器把「读寄存器／相加／条件跳转」等步骤逐一映射成注意力头（查表）、前馈层（算术）与 DeltaNet 头（RAM），CPU 占据 Qwen 32 层之前的 11 层。第三步把执行在解码中跑出来：每条指令对应几个生成 token（ADDR 指定写入行、VAL 携带数值、STEP 结束指令），这些 token 本身就是执行轨迹。

这颗粒心是 RV32IM 加 Zba 扩展，另带一个小型大数单元，官方称通过 riscv-tests、程序结果与 qemu 一致，并自由运行（free-running，即完全依赖自身输出推进、中途无参考机纠正）1800 万条指令无一处错误；对约 23 万个输出位置与参考机回放比对，零不一致。它能跑 C 与 MicroPython，但需要一个小驱动 RvChat 载入固件并把轨迹 token 挡在 Qwen 层之外，因此暂时不能直接以普通的 generate 调用运行。性能上每条指令耗费数个解码 token，基准批处理执行器在 L4 上约 3200 CPU token／秒。

效果上，在 DeepMind 算术集上 div_big 得分 97.5%（给 Qwen 加 Python 工具为 95%、基础模型 72.5%）、mul_big 97.5%（工具 100%、基础 55%）、mul_div_multiple_longer 100%（工具 97.5%、基础 90%）、add_or_sub_big 97.5%（工具 97.5%、基础 87.5%）；在 NUPA 长整数算术上从 48.6% 提升到 100%。附带还做了一个实验性文件系统（1024 槽目录、最多 512 个文件、约 5.3 万 token 文本），写入 GDN 状态后可跨会话保留。代价是检查点 18.8 GB（约为基础模型两倍，大部分为零填充）。

  • 观察：这不是产业新闻，不宜按产品消息读。它值得收录的原因在于演示了两件与 RISC-V 相关的事：一是任何确定性 ISA 都能被编译成权重，ISA 的门槛从来不在指令编码，而在软件栈与生态；二是模型内部的可寻址状态可以充当确定性执行环境，这对「把监控能力编译进权重、模型自己无法篡改」这类安全研究是现成的试验台。反面同样要看清：18.8 GB 权重、每指令数个 token、需要专用驱动，注定它是研究装置而不是芯片替代品——真正做 RISC-V 芯片的团队不必因此调整路线。

一、开源社区与软件生态

1.1 香山 difftest 支持远程 XDMA 板卡中继，FPGA 验证可跨机调度

日期：2026-10-28　来源：GitHub：OpenXiangShan/difftest 提交记录

difftest 窗口内 3 笔提交，核心是 feat(fpga): support a remote XDMA board relay（#1011）：把 FPGA 上的待测核与参考模型之间的链路改造成可经远程 XDMA 板卡中继，验证机与板卡不再要求同机同席。配套两笔，一是 fix(fpga): let fork REF finish after the final endpoint（#1010），修正 fork 场景下参考模型在最后一个端点之后才收尾的时序；二是 fix(mma): accept zero-sized reference operations（#1012），让矩阵扩展路径容忍零长度的参考操作，避免空操作被当作错误拒绝。

  • 观察：这三笔合起来说明 difftest 正在从「单机比对器」变成「可远程调度的验证服务」。远程中继解决的是资源利用率——一套 FPGA 验证环境往往排队等人，链路能跨机后就能被多人多任务分时使用。对做 RISC-V 核的团队，验证机时通常比设计人力更稀缺，这类改动比多一个性能优化点更实用。

1.2 香山 GEM5 增加 TEA 剖析选项，XiangShan CI 更新 profile 与模糊测试

日期：2026-10-28　来源：GitHub：OpenXiangShan/GEM5 提交记录、GitHub：OpenXiangShan/XiangShan 提交记录（kunminghu-v3 分支）

GEM5 侧新增 cpu-o3: Add optional TEA profiling for XiangShan（#1255），为香山模型挂上可选的 TEA 剖析通路；此前窗口内该仓库刚合入 sv48 功能级 TLB 初始化修正、CDP 中 L2 预取源识别修正、Sstc 定时器支持等一批架构级修复。香山主仓同日 ci: update profile & improve fuzz（#6758），更新 CI 剖析配置并强化模糊测试流程。

  • 观察：剖析能力与模糊测试同时推进，是核进入「性能归因 + 长跑稳定性」阶段的标志。GEM5 这条线尤其值得关注——它不是简单的性能模型，而是带 TEA 剖析的体系结构探索平台，香山的很多微结构决策在 RTL 之前先在这里试。

1.3 openRuyi 单日 20 笔：rust-vmm 组件族成组入库，krb5 服务体系重构

日期：2026-10-28　来源：GitHub：openRuyi-Project/openRuyi 提交记录

openRuyi 主仓窗口内 20 笔提交（提交流前 20 条全部落在窗口内），分四块。第一块是 rust-vmm 组件族成组入库：新增 rust-linux-loader 0.14、rust-vm-memory 0.18、rust-kvm-ioctls 0.25，rust-acpi-tables 升到 0.2.1。第二块是 krb5 服务体系重构，三笔一并处理：KDC 路径与 systemd 服务统一对齐、realm 配置改为中性并可沿用上游凭据约定、构建选项改用系统库并跑上游测试。第三块是语言与构建基础设施：go 回移索引优化、go-google-api 与 go-git 相关包跟进 gcfg v2 依赖、cmake 提供 Python 分发包元数据、python-scikit-build-core 升 1.1.1、python-httptools 放宽 setuptools 版本钉、attr 升 2.6.0。第四块是收尾修补：ceph 跟进 main 分支新快照、procps 修 rpm 名并恢复 uptime、新增 sql-migrate、python-graphql-core 降到 3.2.13、删除 python-backports-zstd。

  • 观察：rust-vmm 四件套一次性入库是本期最实质的信号。这套组件是 Cloud Hypervisor 等 Rust 虚拟化栈的地基，成组进入发行版意味着在 RISC-V 上跑 Rust 写的 VMM 的依赖已经打通。相比把某个应用移植过来，把虚拟化底座的语言栈换掉，影响面要深一层。

1.4 CORE-V CVW 修正 CBO 缓存管理：非缓存 cbo.zero 末拍停顿与 PBMT 别名下发

日期：2026-10-28　来源：GitHub：openhwfoundation/cvw 提交记录

CORE-V 的 CVW 仓库合入两处缓存块操作（CBO）修正：Stall an uncached cbo.zero through its final beat 让非缓存区间的 cbo.zero 一直停顿到最后一拍，避免在写响应完成前就释放流水；Send cbo.clean/flush/inval to the D$ through PBMT=NC/IO aliases 让这三类操作在页表项被标记为非缓存或 IO 别名时仍正确送达数据缓存。两笔经 PR #2010、#2008 合并。

  • 观察：CBO 是 RVA23 里最容易被忽视的一组指令——它不像向量扩展那样出现在性能榜上，但非缓存区间的末拍时序与 PBMT 别名处理都是「平时不触发、一触发就是数据破损」的位置。CORE-V 这类把规范边界逐条对着测的项目，价值正在于此。

2.2 Microchip PIC64-HPSC 公布早期辐照结果：TID 200 krad(Si)、SEL 78.2 MeV·cm²/mg

日期：2026-10-28（发布 10-27）　来源：Microchip：PIC64-HPSC 项目里程碑新闻稿、Hacker News 讨论：PIC64GX 64 位 RISC-V 四核微处理器

Microchip 公布 PIC64-HPSC 高性能航天计算系列的早期项目里程碑。抗辐照型号 PIC64-HPSC1000-RH 的早期辐照表征显示总电离剂量（TID）达到 200 krad(Si)，单粒子锁定（SEL）在指定工作条件下测试至 78.2 MeV·cm²/mg；单粒子效应表征中系统控制器未出现不可纠正错误，也无需外部复位。同期早期访问计划已向客户提供硅片与开发套件，板卡伙伴正在开发基于该平台的 VPX 与 VNX+ 计算模块。该系列源自 NASA 与 JPL 对未来航天计算需求的评估，2022 年将 HPSC 合同授予 Microchip；NASA FY26 民用空间短缺优先级清单把「航天操作先进在轨计算」列为第三位的技术短板。

  • 观察：航天是 RISC-V 少有的「需求真实、指标硬、且不接受替代」的市场。200 krad(Si) 这一档意味着任务范围可从低轨覆盖到月球以远，而 SEL 与 SEE 数据是宇航级选型的入场券——没有实测辐照数据，架构再开放也进不了型号目录。这条线索的另一个看点是路径：政府先定需求（NASA／JPL 评估），商业公司交付平台，再由板卡伙伴做 VPX 形态适配，这是一条比消费电子长得多但确定性更高的产业链。

2.4 SiFive 把 RISC-V 定位为 AI 加速器控制层，X100／X200／X300 做 ACU

日期：2026-10-28（SiFive 博客 10-16，Jon Peddie 分析 10-26，10-28 在社区引发讨论）　来源：SiFive：The Next Leap in Datacenter AI — Orchestrating Custom Accelerators with Intelligent Control Units、Jon Peddie Research：SiFive makes the case for RISC-V as the control layer for custom AI accelerators

SiFive 提出用 Intelligence 系列处理器充当「加速器控制单元」（ACU），在主机处理器与定制加速器之间插一层可编程控制面，负责低延迟命令派发、数据搬运、前后处理与算法调整。其论证针对传统方案的三个缺陷：硬连线状态机在算法或数据格式变化时需要昂贵的硬件重做（respin）、共享总线上的频繁数据搬移带来不可接受的延迟并阻塞访存流水、把底层调度压给主机 CPU 会同时吃掉主机算力并放大时延。系列分工是 X100 面向控制密集且对面积与时延敏感的场景，X200 与 X300 提供更大向量带宽与算力。Jon Peddie Research 的分析补充了两条落地信息：Google 数据中心已把 Intelligence X200 用作 AI 计算主机，另有一家未具名的美国一级半导体公司获得 X100 授权用于工业边缘 AI。

  • 观察：这条判断值得记进趋势栏——RISC-V 的商业价值正在从「ISA 替代品」转向「异构系统里的固定角色」。SiFive 自己的表述是「价值正在移出 ISA」，剩下的差异化在实现与系统集成。对国内厂商的含义同样直接：与其正面替换 Arm 主控，不如在 AI 加速器旁做控制层与调度层，这条路径对软件生态的要求低得多，也更容易先拿到订单。

三、国内团队深挖

3.1 奕斯伟计算 CTO 何宁：车规与具身智能成第二、第三增长曲线，RISC-V 消费级 AI NAS 四季度量产

日期：2026-10-28　来源：21 世纪经济报道：21 对话｜奕斯伟计算 CTO 何宁，RISC-V 高价值拐点将到来

奕斯伟计算高级副总裁、首席技术官何宁在峰会后的专访中给出几条具体判断。其一，RISC-V 与 AI 的融合分三条路径：RISC-V 作主控 CPU 外接 NPU（松散结合，产品已多）、RISC-V 进入 AI 单元内部承担调度（英伟达 GPU 内部即嵌入大量小型 RISC-V 核）、以及通过向量与矩阵扩展让 RISC-V 自身具备 AI 算力。他给出时间表：矩阵扩展占大模型计算八成以上，规范成型并进入产品还需一到两年，再过两到三年才会有成规模的标准化产品；「RISC-V 与 AI 深度融合的爆发，大概还需要三年以上」。其二，软件生态仍是最大障碍，但出现三个机会窗口：AI 正在把软硬件一起重构、大模型重构了算法与算子工具链、算力重心从训练转向推理（推理生态复杂度显著低于训练）。

落地层面有三条硬进展。车规侧，EAM2011 是国内首颗支持轻量级 AI 应用的车规级 MCU，搭载自研 32 位 RISC-V 内核，已批量应用于显示屏总成、车载无线充电与电池管理系统；自研 RISC-V CPU IP R520A 已通过德国莱茵 TÜV 的 ASIL-D 功能安全认证，成为全球首个通过 ASIL-D 的多核多架构 RISC-V 内核（此前 R500A 为全球首个获 ASIL-B 认证的 RISC-V 内核）。边缘与智算侧，公司与极空间合作推出全球首款基于 RISC-V 架构的消费级 AI NAS，计划 2026 年第四季度正式量产发售。生态侧，公司已量产超过 150 款产品、服务全球 220 家客户，并依托 RISAA 生态技术平台与牵头成立的 RDI 聚力联盟推进生态。

  • 观察：访谈里最扎实的一句是车规的壁垒不在芯片而在体系——从供应链、Tier1 到车厂导入，链条极长，芯片做出来只是第一步。ASIL-D 之所以关键，是因为它把「能不能进智驾域」从商务问题变成了一张证书问题；拿到证书之后，RISC-V 的灵活性才有资格去匹配「智能汽车功能融合」这种需求频繁变化的部分。至于 AI NAS，四季度量产是个可验证的时间点，值得在下季度回看。

3.2 进迭时空 spine-triton 跟进 spine-mlir 0.8.1，VMT4D 示例重调分块

日期：2026-10-28　来源：GitHub：spacemit-com/spine-triton 提交记录

进迭时空的 Triton 后端仓库窗口内 5 笔提交（含 2 笔合并），实质两件：一是把预编译 spine-mlir 的下载链接升到 0.8.1，并同步更新版本号；二是把矩阵-向量转置 4D（VMT4D）示例重调到「基准最优」的 128×32 分块并做预处理转置。前一日该仓库还修了 smt_rvisa: fix constexpr capture shadowing kernel params——RISC-V ISA 侧常量捕获遮蔽 kernel 参数的问题，以及 CI 在设定 BUILD_COMMIT 时跳过非 wheel 任务的守卫。

  • 观察：spine-mlir 是编译器侧的上游，spine-triton 跟进 0.8.1 说明两仓在同步节奏上已经形成配合。更值得注意的是「示例即基准」的做法：把 VMT4D 示例的分块参数钉在实测最优值上，下游集成方拿到的就不是一个能跑通的样例，而是一个可复现的性能基线。

3.3 算能 LLM-TPU 新增 Qwen3.6-35B-A3B bmodel 链接

日期：2026-10-28　来源：GitHub：sophgo/LLM-TPU 提交记录

算能 LLM-TPU 仓库新增 feat: add qwen3.6-35b-a3b bmodel link，为 Qwen3.6-35B-A3B 提供已编译 bmodel 的下载链接。该仓库此前的适配节奏包括 MiniCPM5-2B 与 MiniCPMV4.7 的 Python 示例（面向 BM1684X 与 CV84X6），以及 bge-reranker-v2-m3 与 MinerU2.5-Pro 的兼容性支持。

  • 观察：35B-A3B 是 MoE 稀疏模型，激活参数只有 3B 量级，能在 TPU 上以 bmodel 形式提供下载，说明算能的模型适配已从稠密小模型转向稀疏大模型——这类模型对内存带宽与调度更敏感，对算力峰值反而不苛刻，恰好是国产 TPU 的舒适区。只给链接不给代码，是国内厂商常见的分发方式，权重与编译产物由模型方托管。

四、具身智能与机器人专章

4.1 进迭时空 humanoid_common 接入运动适配器与算子客户端，whole-body 控制支持表格化耦合

日期：2026-10-28　来源：GitHub：spacemit-robotics/humanoid_common、GitHub：spacemit-robotics/control_whole_body

spacemit-robotics 的 humanoid_common 合入 integrate motion adapters and operator clients，把运动适配器与算子客户端接入统一运行时；此前一笔（10-26）已接入算子语音客户端与静态参数。control_whole_body 同日合入 support tabulated couplings and feedback recovery（#8），为全身控制增加表驱动的关节耦合与反馈恢复路径。

  • 观察：昨天这一栏还是「批量同步、无实质提交」，今天同组织在 04:07 与 04:08（UTC）连出两笔功能提交，判断需要随之修正——进迭的机器人中间件层在持续推进。所谓「算子客户端」，是把动作、语音等能力以远程服务方式接入本体运行时的做法，这与其九月底以来的一串提交（算子服务、固定基座轨迹控制、上肢接管、SONIC 运动选择）是同一条线：humanoid_common 正在变成机器人本体的中间件层，而不是某个型号的驱动集合。

4.2 unitree-go2 切换为仅地形 V2 行走策略，IMU 快照零拷贝读取

日期：2026-10-28　来源：GitHub：spacemit-robotics/unitree-go2

unitree-go2 仓库窗口内 6 笔提交，重点是行走策略与感知读取：改用「仅地形」的 V2 行走策略并把模型下载固定到指定版本，同时保留既有模型归档下载架构；性能侧 read IMU snapshots without copying motor state（PR #4）让 IMU 快照读取不再连带拷贝电机状态；此外修复 CI 回归下 SBUS 依赖加载与可选 SBUS 恢复的硬件配置说明。

  • 观察：「仅地形」意味着策略不再按台阶、斜坡等工况分支，而是用一套地形策略覆盖——这是把 sim2real 的域随机化范围收窄、换取实机稳定性与可复现性的常见取舍。零拷贝读取 IMU 快照则直接对应 1kHz 级控制环里的抖动来源：把电机状态从数据路径上摘掉，读延迟就从「与状态量成正比」变成常数。

4.3 peripherals-imu 支持 HI91 串口反馈，BMI270 IIO 通道复用

日期：2026-10-28　来源：GitHub：spacemit-robotics/peripherals-imu

peripherals-imu 窗口内两笔：feat(imu): support HI91 serial feedback（#21）新增 HI91 的串口反馈解析；perf(imu): reuse BMI270 IIO channels and pace sensor reads（#22）改为复用 BMI270 的内核 IIO 通道并对传感器读取做节流。该仓库此前已覆盖 BMI270 的 SPI 事件驱动、IWT603 与 Forsense 的 UART 驱动，以及 ICM42670P 的中断输出。

  • 观察：IMU 驱动这条线正在从「每型号一套协议」走向「内核 IIO 统一入口 + 少量私有协议兜底」。对整机厂这是个好信号——传感器更换不再需要改应用层，只要内核里有 IIO 通道；对进迭自己，支持到第三家串口协议（IWT603、Forsense、HI91）意味着它的机器人参考设计正在适配更多国产 IMU 供应商。

五、总结与趋势观察

一、验证基础设施的下一步是资源池化。 香山 difftest 今天这笔远程 XDMA 板卡中继，把「验证机与板卡必须同机」这个约束去掉。结合近三日的 fast-ref 与 fork 检查、reftrace 记录回放、MMA 同步验证开关，difftest 的技术路线已经从提高单次比对速度，转到调度多套验证资源。国内做 RISC-V 核的团队普遍缺机时，这条路比再堆一个性能优化点更有现实价值。

二、RISC-V 在 AI 里的角色正在从「替代主控」变成「固定配角」。 同一天出现两处独立表述：SiFive 把 Intelligence 系列定位成 AI 加速器的控制单元（Google 数据中心已把 X200 用作 AI 计算主机），奕斯伟何宁把 RISC-V 与 AI 的融合拆成主控外挂、单元内调度、指令集扩展三条路径并给出三年的时间表。两者指向同一个判断——先进制程上的正面替代不是当下主战场，控制面、调度面与推理侧才是能拿到订单的位置。

三、车规是这一轮的分水岭，而不是消费电子。 奕斯伟 R520A 拿到 TÜV 莱茵 ASIL-D（全球首个多核多架构 RISC-V 内核）、EAM2011 车规 MCU 已批量上车、与极空间合作的消费级 AI NAS 排到四季度量产。三条线里，ASIL-D 是唯一一条无法靠价格战绕过的门槛：它把「能不能进智驾域」变成证书问题。国内其余 RISC-V 厂商若要做高价值场景，这张证书的时间表值得单独跟踪。

四、机器人栈从「同步」转为「开发」。 昨天判定为批量镜像同步的 spacemit-robotics，今天在四个仓库出了十笔实质提交：中间件层接入运动适配器与算子客户端、全身控制支持表格化耦合与反馈恢复、Go2 切换到仅地形 V2 策略、IMU 驱动扩到第三家串口协议并复用内核 IIO。这一栏的判读方法仍应坚持看主分支提交内容，但结论要跟着证据走。

五、本期信息量与判定依据。 中文与英文 Google News 窗口内去重命中后，实质新增集中在 Qwenputer、奕斯伟 CTO 专访、LILYGO K230、Microchip PIC64-HPSC、GUITION VisionGo 与 SiFive 控制层讨论六条；其余为峰会后续解读与股市行情稿，按去重规则剔除。开源侧则是本期主体：香山验证链、openRuyi 的 rust-vmm、CORE-V 的 CBO 修正与进迭的编译器／机器人栈，都有可核对的提交记录。
