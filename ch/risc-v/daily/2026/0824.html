1.1 Sedna：纯 Java RISC-V 模拟器重启开发，向多架构框架演进（08-23）

日期：2026-08-23（README 更新 23:11 北京；开发活跃自 08-21 起）　来源：github.com/fnuecke/sedna

2020 年诞生的纯 Java RISC-V 模拟器 Sedna（rv64imacfd + Zifencei，支持 S 态、可引导 Linux、通过 riscv-tests 全部用例、支持机器状态序列化，发布在 Maven Central）于本窗口重启活跃开发：作者将旧 Z80 模拟器迁移进 Sedna 框架（指令解码器生成器泛化、磁盘设备迁移、Z80 板级接入），README 于 08-23 23:11（北京时间）更新。项目定位正从”单架构 RISC-V 模拟器”向”多架构模拟框架”演进——解码器生成器已同时服务于 Z80 作概念验证，JVM 生态的 RISC-V 模拟器选项（QEMU 之外）由此获得一个活跃维护的补充。

三、国内团队动态与深挖

3.1 香山：COVE 机密计算 MMU 路径两笔修复合入（08-24）

日期：2026-08-24（00:02 北京，committer 时间）　来源：OpenXiangShan/XiangShan PR #6299、PR #6300

窗口内香山主仓库 2 笔提交，均指向 COVE（机密虚拟机扩展，Confidential VM Extension）的 MMU 实现：

  • #6299 fix(MMU, COVE): reject out-of-range Smmpt addresses：此前超出 43 位地址范围的 Smmpt43 请求未被 MPTCache 拒绝，会被当作 cache miss 送入 miss queue/table walker，而非返回 access fault。修复定义 Smmpt43 / Smmpt52 的 PA 宽度与各模式最大合法 PPN（43 位：0x007fffffff；52 位：0xffffffffff），在 stageCheck 流水级校验请求 PPN，越界请求经 respHit 返回 accessFault、抑制 respMiss 防止表遍历，并在 range fault 时清除 permission / NAPOT / 连续权限 / MPT 级元数据、cache flush 时清除 range-fault 寄存器；
  • #6300 fix(MMU, COVE): fix bug for mpt miss queue：MPT miss queue 当前实现违反 Decoupled 协议（twReq.valid 未按 ready 门控），虽未观察到功能丢请求，仍按协议修复。

意义：香山是 RISC-V 开源高性能处理器中少数推进 CoVE/MPT（内存保护表）机密计算路线的项目。两笔修复均为”协议合规性打磨”性质，说明其 COVE 实现已越过功能打通、进入细节收敛阶段——与近期”性能收尾期”的整体节奏一致（分支预测/AIA 等大项收敛后的细活阶段）。
