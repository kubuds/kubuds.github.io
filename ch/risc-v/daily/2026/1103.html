今日重点：Andes 放慢高端 RISC-V CPU Cuzco，AI 业务已占其营收一半（11-02）

EE Times 11 月 2 日台北报道，Andes 首席技术官 Charlie Su 确认公司已放慢高端 RISC-V CPU IP「Cuzco」的开发节奏，把工程资源挪向增长更快的 AI 业务。Cuzco 原先是 Andes 为数据中心级高端核专门分拆出去的 Condor 公司项目，2025 年 Hot Chips 上公开，今年早些时候被收回内部。Su 的说法是生态必须先走到那一步、硬件才有机会，而 AI 这条线增长太快，只能先把资源压到能立刻产生收入的地方。

数字方面，Andes 的 AI 业务目前占营收一半，去年增长 30%，今年预计增长 50%。其自研深度学习加速器规模不大，约 4 TOPS（1 GHz）并自带编译器；AI 收入的主体来自 AI 芯片公司拿 Andes 的 CPU 核做控制、编排与数据搬运，客户里点了 Meta、d-Matrix、Fractile 与 Axelera。这类授权多为定制核，交付周期极紧，这也是内部资源被抽走的原因。

Cuzco 没有取消。Su 表示它仍会做成产品、可能换个名字，只是时间表拉长，公司会「慢慢做，同时等值得加速的信号」。他把 IP 生意的逻辑讲得比较直白：今天贡献最多营收的核是十多年前设计的，客户可能在同一套核上迭代十年以上，所以「做对、可复用」比抢首发重要。近期优先项是存储市场的主控核（已有 10 家客户用小控制器核量产）、汽车与机器人。另一个背景是 Arm 推出自研高端 CPU 硅后改变了商业模式，Su 认为这反而伤害了客户信任，对 Andes 这类 IP 供应商有利。

值得记一笔的判断是：这条消息与「RISC-V 正在冲数据中心高端」的叙事方向相反，但并不矛盾——高端核的研发没有停，只是商业节奏改由市场动量而不是路线图决定；真正在付钱的是 AI 边缘与控制面。对国内做 RISC-V 高端核的团队来说，这是一个关于「谁先买单」的现实参照。

一、开源社区与软件生态

香山把乱序 CSRR 执行补回后端解码（11-02）

第 6779 号把 CSRR 一类指令的乱序执行补了回来。背景是香山后端新加入解码单元之后，此前那套 CSRR 乱序执行的实现被丢掉了，于是原本可以并行发射的 CSR 读写又退回串行，拖慢所有依赖 CSR 的路径。这次改动的直接目的就是把它重新接回新解码链路。

作者顺带指出一处遗漏：伪解码通道里，CSRRVL 与 CSRRVLENB 两条指令只在它们是 CSRR 形式时才做特殊处理，而 CSRRSI／CSRRC／CSRRCI 这几种同样会读写向量长度寄存器的形式没有覆盖。这类「只照顾了一种编码形式」的缺口在向量代码里容易出现，因为编译器常把 vsetvl 序列化成一串 CSRRSI 而不是 CSRR。

日期：2026-11-02　来源：XiangShan #6779

香山 TAGE 的 bankIdx 改用历史位，四 bank 的 2048 个位置变为可用（11-02）

第 6771 号改了 TAGE 分支预测器的索引方式。原先 bank 只由 PC 决定，等于同一段历史只能固定落在某一个 bank 的 512 个表项里，其余三个 bank 的容量对这段历史完全浪费。改动后历史同时参与 bank 与 set 的选择，理论上四 bank 合计 2048 个位置都能用上。

实测结论写得比较克制：astar、xalancbmk 与 gobmk 三项有明确收益，libquantum 出现回退，原因是新结构更容易撞 bank 冲突，作者留了后续再处理。这条改动的价值在于指出一个常被忽略的容量账——预测器表再大，如果索引只用一个维度，实际可用容量会被结构切碎。

日期：2026-11-02　来源：XiangShan #6771

香山预计算 BPU 的 s2／s3 override 条件，压缩次 PC 路径末级逻辑（11-02）

第 6753 号是纯时序优化。做法是把每个分支候选的 s2／s3 override 条件提前算好，再用「第一个 taken 分支」的独热掩码选中结果；同时把 s2 的 taken 结果按 TAGE 两种可能结果各预计算一份，让迟到的那份 TAGE 预测只负责最后一级选择。

效果是在 next-PC 这条最紧的路径上，把迟到信号之后的逻辑深度压下去，而预测行为保持不变。这类改动不出现在性能数字里，但决定了主频上限，是香山近一阶段「先把高频的时序堵塞铲掉」这条线的延续。

日期：2026-11-02　来源：XiangShan #6753

香山把 XSCache 子模块指到修「late hints」的版本（11-02）

第 6803 号只动了一行子模块指针，把 XSCache 从 e9488ae 提到 a041f07，提交说明是「换掉仲裁器以修复 late hints 的问题」。这类只改指针的提交容易在日报里被漏掉，但它往往意味着一次跨仓修复已经合入——缓存侧的 late hints 会直接影响预取效果，与本期香山前端预取队列的重构是同一条线上的工作。

difftest 在 squash replay 中保留异步 AME 校验器状态（11-02）

第 987 号修的是矩阵扩展校验在重放时丢状态的问题。改动在 squash 引发的 replay 前后快照并恢复三样东西：矩阵软件 ROB、待处理的 msync 事件、以及参考侧的 AME 状态；同时把 AME 提交序号贯穿到异步 MMA 校验里，用来区分「本包内的错误」与「更早留下的失败」，并在重放边界把待检项排空。

还有一个工程细节值得记：重放时重置排队的检查与保留的错误，但不替换后端，CUDA 服务与结果池保持存活，好让父进程里已经起来的 LightSSS 子进程能重新连上。这是把矩阵校验从「一次性批处理」做成「可中断可续跑」的必要条件。

NEMU 让矩阵访问走共享 TLB 优化路径，CI 改为复用性能评论（11-02）

第 1275 号把 PERF_OPT_SHARE 的共享缓存资格判定与 PBMT 检查扩展到矩阵访问上，同时保留原有的 SLOW 与两阶段翻译回退路径；矩阵命中改走公共的物理访问处理函数，以保住权限检查、AMU 事件与延迟数据搬运。换言之，矩阵访存不再是一条旁路，而是接入了和普通访存同一套 TLB 记账。

第 1276 号是 CI 改进：性能结果评论改为更新同一条（用隐藏标记定位），并按 PR 分支串行化，避免并发完成的 CI 重复刷评论。对每天要读性能回归的开发者来说，这比多一条新功能更实用。

CORE-V CVW 三笔：sfence.vma 后重载 DTLB、清理 CLINT 未完成代码、Verilator 与 VCS 收功能覆盖率（11-02 至 11-03）

KU Leuven 在 RISC-V 核上首次开源实现 DMP，提出 SecDMP 防御（11-03）

KU Leuven DistriNet 与 EURECOM 的论文（NDSS 2027 接收，扩展版 32 页）处理的是数据内存相关预取器（DMP）的侧信道。DMP 已进入主流桌面与服务器 CPU，它按内存内容里像指针的值去预取，性能有收益，但会把秘密编码进微架构状态，即使是对 Spectre 做过加固的常数时间代码也挡不住。

论文先给出 DMP 泄漏的分类与新攻击，再在 RISC-V 处理器上实现了首个开源 DMP，用实测证明现有唯一「想保住 DMP 性能」的防御挡不住整类泄漏；随后提出 SecDMP：要求在内存中标记秘密，确保 DMP 永不把这些秘密编码进微架构，并形式化证明其泄漏不超过「没有 DMP 的基线」，同时不牺牲公开数据的性能。硬件代价是 RISC-V 研究核上不超过 0.5% 面积。对开源核社区的价值在于，DMP 这类优化正从大厂专有走向可配置核，安全设计必须提前进入 RTL，而不是等流片后再补。

日期：2026-11-03　来源：arXiv:2610.37454 SecDMP（扩展版）、论文 HTML 版

二、产品与生态动态

欧洲发起 ERICI 工业计算倡议，要把 RVA23 做成「工业计算机」（11-02）

一个名为 ERICI（European RISC-V Industrial Computing Initiative）的倡议在 Hacker News 上出现，发起人是德国的 Yuri Zaporozhets，定位是非商业性的行业协作。它的问题陈述很直接：RVA23 硅已经到了，但「工业计算机」没有——板厂等软件、软件等板子、客户等两者，这个循环要靠一套跑在真实硬件上的开放参考栈来打破。

参考栈按层切分：固件做初始化与 POST，然后交 UEFI 引导器；gRouvr 像内核一样被加载，用 CPIO 打包各分区的内核与 initramfs，再把 CPU、内存、设备与各自的设备树分给实时分区和 Linux 分区，两者在同一 SoC 上并行隔离运行。许可证写得很清楚：HFI BIOS 走 GPL-2.0（基于 U-Boot），mr-bml 走 GPL-3.0，gRouvr 与 QSOE 走 Apache 2.0。分区栈已在进迭时空 K3 的 PicoITX 板上演示，QSOE 作为 gRouvr 客户机跑通登录。

它也诚实地列出差距：现成的 RVA23 机器（Firefly AIBOX-K3、Milk-V Jupiter2）在宽压输入、−40~85℃、现场总线与实时 I/O、导轨安装、工业 EMC 与安全认证、10~15 年长期供货这些项上大多「未标注」，分区软件栈也还没有落到产品上。这套「先定义层间接口、再逐层验证一起启动」的做法，与国内做 RISC-V 工业与车规的思路可以对照看。

日期：2026-11-02　来源：ERICI 官网、Hacker News 讨论

芯来新建 T0 Chiplet 双 SDK 仓，工具指南跟进 2026.10 发布（11-02）

芯来在 11 月 2 日下午新建了两个仓库：nuclei-t0-sdk（描述为 Nuclei Ecosystem T0 Chiplet Baremetal/RTOS SDK）与 nuclei-t0-linuxsdk（T0 Chiplet Linux SDK），两者目前都是空仓、零提交。空仓本身信息量有限，但「裸机／RTOS」与「Linux」两套 SDK 同时开张，且都以 T0 Chiplet 命名，说明其下一阶段的产品线会把 chiplet 形态的 T0 作为独立平台来铺软件栈，而不是挂在既有核的 SDK 里。

算能把 SG2044 平台 EDK2 的 PcieInitPei 模块改成默认不生成也不校验 ECRC，改动 20 行。ECRC 是 PCIe 事务层的端到端 CRC，理论上该开，但在实际板卡与转接卡组合上，端点不实现或实现不一致时会导致枚举失败与链路异常，因此不少平台默认关掉。这条改动属于「先把兼容性放前面」的工程取舍，也侧面说明 SG2044 的整机生态还在适配期。

humanoid_common 支持在线策略切换与异步 SONIC 规划（11-02）

humanoid_common 的第 26 号是上面那组改动的公共层：38 个文件、+2269／−71。核心是把行为状态机（HOME 与 RL 两个状态）、策略适配器（history-actor、关节轨迹、stance motion、SONIC 规划器）与传输执行器的状态上报打通，让「在线换策略」成为状态机的一个正常转移，而不是重启进程。

两处设计取舍值得一提：一是把「模式选择」与「动作回放」拆开，避免选模式时顺带触发动作；二是定时动作的观测从第 0 帧开始，不再丢掉起始帧。另有手柄配置、Web 客户端与掉电处理的若干修正，包括允许在状态过期时手动断电——这类边界条件正是从实验室走向现场时最常出问题的地方。

control_whole_body 用三角表做耦合映射，补启动反馈恢复（11-02）

五、总结与趋势观察

今天的信息量集中在三处，且指向不同层面。

第一，商业节奏压过路线图。Andes 把高端核 Cuzco 放慢、把资源压向已占营收一半的 AI 业务，是这一轮 RISC-V 产业里少见的「主动降速」样本。它提醒做高端核的团队：生态与客户预算不到位时，性能指标再好看也换不来订单，IP 生意的复利来自可复用而非首发。

第二，开源核的进步仍以「小而密」的方式出现。香山一天四笔（CSRR 乱序执行、TAGE 索引维度、BPU 时序、XSCache 指针），CVW 一天三笔（DTLB 重载测试、CLINT 减债、双仿真器功能覆盖率），NEMU 与 difftest 各修一处矩阵扩展相关的状态一致性问题。单笔都不大，但方向一致：把乱序与矩阵扩展这两条新路径的状态管理做扎实。

第三，机器人栈在补「部署」那一段。进迭时空三仓同日合并，重点不在新算法，而在硬件部署、在线策略切换、标定表映射与启动恢复——这些是把实验室策略变成可交付产品的必要件。与 ERICI 在欧洲试图把 RVA23 做成工业计算机的努力放在一起看，RISC-V 的下一段增长更像是从「能不能跑」转向「能不能长期稳定地跑在现场」。

榜单侧本期只有补录与站点功能更新，不宜读作性能跃升；会员企业官网巡检 391 家中有 93 家首页内容变动，均为营销与新闻位常规更新，无实质产品、融资或架构动态。
