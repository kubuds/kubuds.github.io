今日重点：云栖大会：达摩院玄铁（平头哥）发布真武 V900，首次公布倚天 720／730／750 CPU 路线图

日期：2026-09-22（2026 杭州云栖大会 9 月 22 日至 24 日）　来源：IT之家《阿里平头哥首次公布 CPU 规划：将推倚天 720、730、750 三代芯片》、新浪科技《阿里平头哥公布 CPU 规划》、快科技《阿里平头哥双芯重大进展：国产最强 AI 芯片真武 V900 亮相 倚天两代 CPU 定档 2027 年》、TrendForce《Alibaba Unveils AI Chip Zhenwu V900 for 1Q27 Mass Production, Maps Out New Server CPUs for 3Q27》

9 月 22 日，2026 杭州云栖大会开幕。阿里巴巴集团 CEO 吴泳铭在主论坛将 AI 模型、AI 芯片、AI 云并列为「机器智能」时代三大基石。达摩院玄铁（平头哥）当日发布新一代训推一体 AI 芯片真武 V900：采用自研并行计算架构，搭载 216GB 大容量显存，片间互联带宽 1200GB/s，单芯片性能为上一代真武 M890 的 3 倍，原生支持 FP8、FP4 低精度计算，面向万亿级参数大模型的训练与推理全场景；吴泳铭称其为「目前中国算力性能最强的 AI 芯片」。据披露，V900 将于 2027 年第一季度量产售卖并在阿里云数据中心规模化部署；配套新一代磐久超节点服务器 2027 年 Q1 上市，其自研 ICN Switch 单集群可连接最多 50 万颗 V900。

同场，平头哥首次公布倚天服务器 CPU 路线图：2027 年 Q3 推出倚天 720 与倚天 730——720 面向吞吐并发型负载（192 核、96 条 PCIe 通道，主打每核成本，服务 Agentic Rack 的大规模并发执行）；730 首次基于全自研 CPU 微架构设计（此前倚天 710 使用 Arm Neoverse IP 内核），支持两路同步多线程（SMT）与 128 条 PCIe，单核 SPECint2017／GHz 最高提升至倚天 710 的 1.4 倍，面向 AI Head Node 等延迟敏感场景；后续倚天 750 将采用第二代自研核，并首次原生支持自研 ICN 互联协议，实现倚天 CPU 与真武 AI 芯片的直接互联。平头哥称，随真武 AI 芯片、倚天 CPU、ICN Switch、磐脉智能网卡、镇岳存储主控五条产品线就位，其数据中心核心芯片已实现「算力、网力、存力」全栈自研。

边界与背景说明：真武与倚天系列均非 RISC-V 产品（倚天沿用 Arm 指令集），本条目按「国内团队深挖」口径收录——达摩院玄铁是 RISC-V 生态核心团队（玄铁 C 系列处理器 IP、「无剑联盟」、与北京开源芯片研究院／中科院软件所联合研发下一代开源香山），其数据中心自研路线与本报告长期跟踪的 RISC-V 高性能核（玄铁 C950 等）在同一团队内并行推进。另据官方口径（截至 2026 年 4 月），真武系列累计出货 56 万片、服务 20 多个行业 400 多家客户，底层软件栈 T-Head SAIL 已于 2026 年 7 月 WAIC 期间开源。

一、开源社区与软件生态

1.1 香山：master 合入向量浮点指令支持，NEMU／GEM5／difftest 多项修复

日期：2026-09-22　来源：XiangShan 提交：feat(vector): support vector-float instructions、XiangShan 提交：decode 补入 Zicbop 指令（#6586）、NEMU #1222

香山主仓库窗口内 3 项提交：最重的一项为「支持向量浮点指令」（feat(vector): support vector-float instructions），为昆明湖向量单元增加浮点向量运算路径，并配套整理 vecRegion 连接；decode 侧把缺失的 Zicbop 指令补进 uopTable（#6586）。周边仿真与验证仓库同步修复：NEMU 两项——NutShell 未实现的部分 CSR 改为省略（#1222）、无 Zicntr 时保持 CY／TM／IR 可写（#1223）；GEM5 三项——mem-cache 修复 probeHit 边界后启用 hit-under-block（#1164）、cpu-o3 禁用 IBuffer bypass 以修复 pflush vset（#1135）、SMT 增加按 IQ 的安全水位策略（#1175）；difftest 两项——iotrace 保留 EOF 处最后一个 zstd 分块（#972）、OpenIOMMU 文件清单改为条件化追加（#974）。XSCache 窗口内无新提交。

1.2 meta-riscv：BeagleV-Fire 主板支持入库，BeagleV-Ahead 加入 SD 卡启动

日期：2026-09-22　来源：meta-riscv：beaglev-fire 新 MACHINE、meta-riscv：hss-payload-generator-native 配方、meta-riscv：beaglev-ahead SD 卡启动支持

Yocto 的 RISC-V 层 meta-riscv 窗口内 5 项提交：新增 BeagleV-Fire（Microchip PolarFire SoC）主板 BSP 与配套的 hss-payload-generator-native 配方（PolarFire SoC 的 HSS 引导载荷生成工具）；BeagleV-Ahead 增加 SD 卡启动支持；gptfdisk 升级到 1.0.10；milkv-duo-fsbl 在小核 FSBL 中禁用 RTOS 核。BeagleV-Fire 与其引导工具链进入 Yocto 主线层，为这颗「FPGA 逻辑 + 4 核 RISC-V」的开源硬件平台补齐了发行版构建路径。

1.3 Tiny-Vedas 发布 arxiv-v0 快照：RISC-V AI 加速器开源基础设施进入论文版

日期：2026-09-22　来源：Tiny-Vedas 发布：arxiv-v0、快照提交：arXiv v0 论文源文件

面向 RISC-V AI 加速器的开源基础设施项目 Tiny-Vedas（56 星）窗口内发布 arxiv-v0 快照：将 STREAM YOLO 示例、U280 FPGA 桩与论文源文件一并冻结，对应其 arXiv v0 预印本（论文版尚未在 arXiv 检索到公开条目）。项目提供从可综合 RV32IM 核（4 级流水）、8x8 int8 GEMM 加速器（经 AXI4 共享 DCCM）、Python ISS／RTL 协同验证，到 PyTorch JIT（torch.compile 到 C 再到 RV32 ELF）的完整链路，路线图覆盖 VLIW、超标量、乱序与向量单元等多微架构扩展，物理设计基于 sv2v 与 OpenROAD。该项目 2025 年 4 月建仓，此次快照标志其方法论进入可引用阶段。（注：个人主导的开源项目，尚无流片记录。）

1.4 开源生态短波：RVVM 浮点单元修复、Zeitlos FPGA 项目进展、SLogic 工具链修正

日期：2026-09-22　来源：RVVM 合并 fcvt 动态舍入修复（#260）、Zeitlos 提交：jumploader 与 TTS 改进、slogic16u3-tools：烧录校验逻辑修正

四条轻量动态：其一，RISC-V 虚拟机 RVVM（约 1.3k 星）窗口内合入 5 项浮点修复——fcvt 动态舍入模式、fcsr 保留位与 frm 澄清、NaN 与 sqrt 结果规范化（#259、#260、#280），继续打磨浮点行为的规范一致性；其二，machdyne 的 RISC-V FPGA SOC／OS 项目 Zeitlos（PicoRV32／Zeitlos32 核，48MHz）密集提交 9 项——gateware 支持从任意 flash 位置加载、配置 flash 可写、语音合成改进等；其三，矽速 SLogic16U3 逻辑分析仪工具链修正空白烧录校验（改用 openFPGALoader 的读回校验而非退出码）；其四，Tenstorrent 的 RISC-V 核验证组件 rv_tester 新增 valgrind 支持（#70）。

二、产品与生态动态

2.1 AI Infra Summit 回顾报道：Epic Semi 全 RISC-V 服务器亮相，RISC-V 控制核「无处不在」

日期：2026-09-22 报道（展会 2026-09-15 至 09-17）　来源：More Than Moore《AI Infra Summit Day 2: Threads + Highlights》

More Than Moore 09-22 刊出 AI Infra Summit（9 月 15 日至 17 日，圣克拉拉）第二日回顾（作者 Dustin Sklavos，前 AnandTech 高级编辑、Tenstorrent 产品经理）：展场一角设 SiFive 与 Akeana 展台，Epic Semi 以正式展位展示「从上到下全 RISC-V」的服务器方案——主控 CPU 与 AI 处理器均基于 RISC-V 核。文章特别指出，RISC-V 在展会上的存在感远高于其展位占比：Tenstorrent 的 AI 架构与 CPU 产品线均采用 RISC-V 核，Axelera 用 RISC-V 核承担 AI 卡的数据流控制，Xcena 的 MX1 CXL 内存与闪存扩展模块使用超过一千颗 RISC-V 核做数据搬运与缓存。结合本刊 09-16、09-17 期已收录的 SiFive 与 AMD ROCm 移植演示，RISC-V 在 AI 基础设施中的「控制面／编排层」角色进一步得到印证。

达摩院玄铁 GitHub 组织窗口内 1 个仓库推送：特权态架构测试仓库 damo-rv-priv-ats 提交测试套件重构（让测试套件通过 PLATFORM 或 SUITE 配置运行），延续其「测试对齐规范」的主线（上一期收录的 PR #32 为测试计划与规范条款建立链接）。该组织其余 70 余个公开仓库窗口内无推送——结合云栖大会发布（见今日重点），其工程节奏正处于数据中心芯片路线披露期；RISC-V 侧以测试与规范工作维持推进。

3.2 进迭时空：edk2-spacemit 三连发 0.0.7 至 0.0.9，K3 UEFI 固件转向 Debian 包

日期：2026-09-22　来源：edk2-spacemit：release 0.0.9、edk2 与 edk2-platforms 转为仓库内联源码、postinst：Spacemit K3 检测修复

进迭时空 UEFI 固件仓库 edk2-spacemit 窗口内批量推送 20 项提交：连续发布 0.0.7、0.0.8、0.0.9 三个版本，把 edk2 与 edk2-platforms 由子模块改为仓库内联源码并同步至最新上游提交，配套完善 Debian 打包——control 依赖、gitignore 策略说明、postinst 中按需加载 mtdblock 内核模块、修复 Spacemit K3 平台检测、以 deb 版本号作为 edk2 平台版本。EDK2 是 K3 等平台 UEFI 启动链的核心组件；转向 Debian 化打包，通常意味着固件将随 Ubuntu／Debian 镜像体系向开发者与客户分发更新。

3.3 进迭时空软件栈：检测后处理优化、mpp 流包引用传递与嵌入模型预设

进迭时空软件栈窗口内多点推进：视觉模型库 model-zoo-vision 两项——收紧检测模型 NMS 与后处理（#90）、示例输入改用相机默认配置（#91）；mpp（多媒体处理平台）新增「流包按 VB（视频缓冲）引用传递」，减少链路数据拷贝；ai-gateway 新增 Qwen3-Embedding-0.6B-Q8_0 嵌入模型预设（#42）；ai-sdk 两次同步 vision、gateway 子模块；spacemit-com 的 FlagTree 分支补充新 builtins 文档（#1120）；docs-ros 为 K3 与 Reachy 语音指令补充英文文档。延续其「AI 与机器人软件栈同步加厚」的节奏。

3.4 算能：Qwen3.5 35B-A3B（MoE）适配 CV84X6，YOLOv8-seg 支持 CV186X 双核

五、总结与趋势观察

  • 国产数据中心芯片的「全栈自研」在云栖大会达到新密度：平头哥五条产品线（真武 AI 芯片、倚天 CPU、ICN Switch、磐脉智能网卡、镇岳存储主控）就位，倚天 730 转向全自研微架构。与此并行，同一团队的 RISC-V 线（玄铁 C 系列、无剑联盟）继续作为开放指令集生态的核心资产——「自研微架构冲刺数据中心性能」与「开放指令集拓展生态」两条路径在同一家公司内同时推进的格局，值得持续跟踪。
  • RISC-V 在 AI 基础设施中的「控制面」角色再获印证：AI Infra Summit 回顾显示，从 Tenstorrent 的大核矩阵、Axelera 的数据流控制，到 Xcena MX1 用千颗级 RISC-V 核做数据搬运，RISC-V 正作为 AI 芯片的编排层「无处不在」；Epic Semi 的全 RISC-V 服务器方案则提供了整机形态样本。
  • 开源硬件的「正确性补课」：本期香山向量浮点指令支持、RVVM 五项浮点修复、BeagleV-Fire 平台补全，指向 RISC-V 从旗舰核到仿真器、发行版层的浮点与向量正确性细化——恰是「从能用走向好用」阶段最密集的工作类型。
  • 平静侧观察：openRuyi 双源（官网新闻页与 GitHub 仓库）窗口内均无更新，2026.09 版本仍未发布；乐鑫 34 个仓库推送经抽查为 USB／蓝牙／WiFi／CI 例行迭代，无 ESP32-C 系列专项；芯来、奕斯伟计算、revyos、Radxa Linkr 窗口内无推送。
  • 局限性说明：本期数据来自公开网页与 GitHub 公开提交，未使用非公开渠道。云栖大会信息来自 IT之家、新浪科技、快科技、新快报、紫牛新闻、TrendForce 等多方报道并已交叉核对，部分更远期路线图的时间口径在媒体间存在差异，未逐一采用；会员官网巡检有 70 家抓取失败（以国内站点与反爬站点为主）。
