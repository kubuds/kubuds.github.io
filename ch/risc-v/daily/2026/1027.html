今日重点：Onsemi 以 1450 万美元接手 Codasip 低端 RISC-V 业务

日期：2026-10-26　来源：Jon Peddie Research：Onsemi picks up Codasip’s low-end RISC-V business for $14.5 million（10-26）、Codasip：战略调整与业务剥离公告（04-08）

安森美（Onsemi）已完成对 Codasip 低端 RISC-V 处理器业务的收购，交易金额据捷克商业媒体 e15 报道为 1450 万美元，其中约 90% 已支付。

  • 交易范围：只涉及 Codasip 约 260 名员工中的 27 人，另附 Studio 处理器设计工具的授权。Codasip 保留 Studio 的所有权与大部分受公共资金支持的项目。
  • 前因：Codasip 于 2026-04-08 宣布战略调整，剥离低端 RISC-V 处理器设计业务、转向基于 CHERI 的「网络韧性」安全架构；当时公告只说买方是一家美国上市半导体公司，未点名。
  • 捷克国内的质疑：Codasip 曾获欧盟与捷克国家级研究资助，今年 7 月还公开过逾 1.19 亿欧元的补助与股权支持（大部分尚未到账），1450 万美元的成交价因此引发讨论；公司口径是「合理重组」而非贱卖。
  • 竞争格局：CHERI 方向已出现直接对手 SCI Semiconductor，其在 2026 年 9 月完成 500 万英镑（约 667 万美元）融资，并称另有 770 万英镑政府合同；Codasip CEO Ron Black 对 CHERI 联盟表示，国防与关键基础设施客户的安全需求强于通用核授权。
  • 买方逻辑：Onsemi 拿到的低端 RISC-V 技术与团队，可直接服务其汽车与工业半导体业务——与它此前通过收购、授权拼装技术栈的做法一致。

Jon Peddie Research 的判断值得记录：基础处理器核正在变得难以差异化与变现，客户面前摆着越来越多的商用与开源替代；RISC-V 的下一阶段会更多由成熟半导体公司塑造，价值从指令集本身移向差异化产品与系统集成。

一、开源社区与软件生态

1.1 香山：35 笔修复一次性回收，TLB need_gpa 与向量异常成主线

日期：2026-10-26　来源：XiangShan 提交记录（10-26，kunminghu-v3）

香山主仓昆明湖 V3 分支在窗口内合入 35 笔提交，全部提交时间戳为 10-26 16:32，而原始作者日期跨 2026-02-04 至 2026-09-17——典型的长期分支批量回收，不是当日新开发。

  • TLB／MMU 成组：need_gpa 相关四笔——为 need_gpa 的 robidx 加掩码避免 X 态（#6233）、修复非末端口 need_gpa 清除丢失（#6251）、按翻译阶段匹配 need_gpa 响应（#6285）、以及新增超时清除机制。另有 TLB 因 needGpa 冻结的历史修复（#5610）一并回收。
  • 向量与访存：vlsu 把向量异常的 guest physical address 扩展到 XLEN（#6432）；Rob 侧向量 load/store 的 flushpipe 需要延迟（#6244）。
  • 虚拟化与特权：HLVHLVXHSV 的 PMP 检查改用 SPVP 模式（#6250）、RVH 下隐式 G 阶段读忽略 MXR（#6099）、HFENCE.GVMA 时刷新 VS 阶段 PageCache（#6082）、HLVX 的最终物理执行权限校验（#6017）。
  • 复位与 X 态治理：mtvec 复位值（#5862、#5889）、MemBlock／L2Top 缺复位值引起的 X 态（#5838）、LoadQueueRAR 用 RegEnable 规避 X（#5986）、CPU 时钟门控改用预扫描复位——这一组占了批次的三分之一。
  • 新特性与小项：NewCSR 打开 PMM 与 CBIE 的 CSR 写（#6269）；Debug 为 CBO 类指令补 LT／GE 触发器匹配（#6447）；hartIDDmodeWidth 参数化（#5627）。

把 35 笔按主题摊开，能看出这是一次以「收敛」为目标的合流：X 态、复位值、need_gpa 超时这类问题不影响功能演示，只在长跑、多核、虚拟化压力下暴露，属于流片前必须清账的项。作者日期最早回到 2 月，说明部分修复在分支里躺了七个月才进主线。

1.2 NEMU：AME 矩阵扩展的事件编码与主机 FMA 异常标志修正

日期：2026-10-26　来源：NEMU 提交记录（10-26）、NEMU 发布记录

参考模型 NEMU 窗口内 3 笔提交，两笔落在 AME（矩阵扩展）上，一笔是配置层重构。

  • AME 语义修正：fix(ame): encode MMA event types from mcfg semantics（#1269）——MMA 事件的类型此前按固定枚举编码，改为按 mcfg 寄存器的语义解码，矩阵配置变化时事件分类才正确。
  • 浮点异常保真：fix(ame): preserve host FMA exception flags（#1268）——AME 路径用主机 FMA 指令模拟，需把主机的浮点异常标志如实回传给客机，否则差异比对会漏掉异常侧的不一致。
  • 配置层重构：refactor(config): reduce duplication with shared config layers（#1259），把重复的配置项抽成共享层。
  • 背景：10-23、10-24 刚连发 v2026.10.r8、v2026.10.r9 两个标签，本批修正属标签后的继续打磨；NEMU 近一周的改动重心已从「加功能」转向「让差异比对更可信」。

参考模型的价值全在「错得比 DUT 少」。把主机浮点异常标志这种细节补齐，说明香山的验证已经推进到需要区分「数值相同但异常标志不同」的阶段。

1.3 difftest 落地 BOOM 支持，GEM5 加入译码融合压缩

日期：2026-10-26　来源：difftest 提交记录（10-26）、GEM5 提交记录（10-26）

差分验证框架与 GEM5 分支各有一笔方向性明确的提交。

  • difftest 接入 BOOM：feat(difftest): add BOOM DiffTest support（#998）——把加州大学伯克利分校的 BOOM 乱序核接进同一套比对框架。值得注意的是，10-23 的日报刚记录过 #995 只是「把 BOOM 的 DiffTest 接入写进文档」，四天后代码落地。
  • 构建兼容：同批的 #1003 保留 C++11 构建兼容，避免新代码抬高工具链门槛。
  • GEM5 译码融合：cpu-o3: Add optional decode fusion compaction（#1184）——在乱序模型里加入可选的译码融合压缩，让前端把可融合的指令对压成一条微操作，贴近真实前端行为。

difftest 从「只验证香山」走向「验证别人的核」，意义超出项目本身：一套能同时比 NEMU、BOOM 的框架，才有可能被外部团队当成公共验证基础设施来用。GEM5 侧加译码融合，则是让性能模型的乐观程度与硬件前端的实际做法对齐——仿真与硅片的口径差，往往就藏在这种可选项里。

1.5 开源 EDA 把自研 RV32I 核推向 GF180 流片：LibreLane 78 步全流程

日期：2026-10-26（会员官网巡检检出，活动 11-11）　来源：RISC-V 协会（日本）：RISC-V Day Tokyo 2026 Autumn 逻辑设计轨道议程、RISC-V 协会（日本）首页

RISC-V 协会（日本）在 10 月挂出 RISC-V Day Tokyo 2026 Autumn（11-11，东京大学本乡校区）的议程细节，其中一场 30 分钟的演讲公开了一条用纯开源工具链完成流片的完整路径。

  • 对象与路径：讲者黑川能毅（JASA 硬件委员会 RISC-V WG）用 LibreLane 3.1.0.dev2 把自研 RV32I 兼容核 SWC1 推到 GF180 工艺，流程覆盖 Verilator lint、Yosys 综合、OpenROAD 布局／CTS／布线、9 个 signoff STA 角、Magic 与 KLayout 双重 DRC、netgen LVS，共 78 道工序。
  • DFT 是本次新增：在综合后插入扫描 FF 替换与扫描链创建两道工序（GF180 上只有 5V 库带扫描单元），用开源 ATPG Atalanta 约 2 分钟生成 14,148 条测试图形，故障覆盖率 97%；插入扫描链后频率从 50MHz 降到 19MHz，扫描链本体可跑 200MHz 以上。
  • 踩坑记录：公开的 5V SRAM 模板按 README 能过，换自己的核就反复失败，最后发现是拿 5V 单元搭了 3.3V 核，切到 3.3V 单元后布局完成、STA 给出 50MHz 预期。
  • 环境：Windows 11 的 WSL2（Ubuntu 24.04）加 Nix，流程调试与 STA 报告检查用 Claude Code（Pro 计划）。SWC1 已于 2026-03 通过 Tiny Tapeout（IHP 130nm）流片，芯片在途期间在 FPGA 上跑 μT-Kernel 与 lwIP。
  • 同场下一讲：12:40–13:10 为圓山宗智的「AI-Designed RISC-V: From Claude Code to Linux Boot」。

这条的技术含量不在「用开源工具流片」这个结论——Tiny Tapeout 早已证明可行——而在把 DFT 补进开源流程：扫描链与 ATPG 长期是商用 EDA 的地盘，个人爱好者在 WSL2 上做出 97% 故障覆盖，说明开源流程的短板正从「能不能流片」转向「能不能可测」。对国内做教学芯片与 MPW 的团队，这是一份可直接对照的工序清单。

二、产品与生态动态

2.1 SiFive 把 RISC-V 定位为 AI 加速器的控制层

日期：2026-10-26　来源：Jon Peddie Research：SiFive makes the case for RISC-V as the control layer for custom AI accelerators（10-26）、SiFive 博文：Orchestrating Custom Accelerators with Intelligent Control Units（10-16）

SiFive 提出用 Intelligence 系列 RISC-V 处理器充当「加速器控制单元」（ACU），在主机与自研加速器之间做可编程的控制层。Jon Peddie Research 在 10-26 对这一思路做了整篇分析。

  • 问题陈述：硬连线状态机在算法变化时难改；共享总线容易成瓶颈；把底层编排交给主机 CPU 会吃掉算力并增加延迟。
  • 方案：用带标量与向量能力的 RISC-V 核承担数据准备与搬运、加速器操作派发、以及激活函数与数据格式化这类附属计算，通过 SSCI、VCIX 一类协处理器接口直连加速器；控制逻辑的改动落在软件／固件里，不动固定功能硬件。
  • 型号分工：X100 面向控制密集、低延迟与小面积；X200／X300 提供更大向量带宽与算力。
  • 已有落地：Google 数据中心已用 X200 作 AI 计算主机；另有 X100 授权给一家未具名的美国一级半导体公司，用于工业边缘 AI。
  • 评论口径：JPR 认为这印证了「价值正从 ISA 移向系统集成」——RISC-V 不必取代 Arm 或 x86 当主处理器，进入控制面同样能拿到有分量的位置。

这条与今日重点里的收购案是同一枚硬币的两面：通用核授权在贬值，而「把核嵌进别人的系统架构里」在升值。ACU 这个提法之所以成立，是因为 AI 加速器的形态越来越碎片化，没有哪家愿意为每种形态去改硬件状态机。

2.2 MIPS 的 RISC-V 全栈转型：Acies／Actus／Aegis 三平台与 S8200 内核

日期：2026-10-26　来源：电子工程专辑：从处理器 IP 到物理 AI 平台——MIPS 的 RISC-V 全栈转型（10-26）、NeoTeo：MIPS’s RISC-V platforms: what Acies, Actus and Aegis do（10-26）

放下自有指令集的 MIPS，在格罗方德（GlobalFoundries）收购、并整合新思科技 ARC 处理器 IP 之后，已把自己重新定义为「基于 RISC-V、面向汽车电子／边缘 AI／高性能网络的 IP 与全栈方案提供商」。2026 年 9 月发布的三个平台在本周被中英文媒体集中拆解。

  • Acies-1（推理原生）：基于 Atlas S8200，支持 RVA23、RVV 向量扩展与 VME，可运行 llama.cpp、Qwen 等大模型以及视觉 Transformer 与 VLA 模型；软件侧走 Atlas SDK 与基于 IREE 的 MLIR，兼容 TensorFlow／PyTorch／ONNX；硬件形态是易集成的 M.2 PCIe，面向机器人、自动化设备与边缘智能体。
  • Actus-1（事件原生）：基于 Atlas M8500，实时多线程架构并支持 FoC 加速，整合 VPX 矢量协处理器，以单板计算机形态交付，面向运动控制、传感器融合与预测性维护，符合 ISO 26262 与 ISO 21434。
  • Aegis-1（安全原生）：面向任务关键型物理 AI 系统，支持 RISC-V Android 与 Linux 开发，可在数据中心之外运行智能体负载，同样按 ISO 26262／21434 设计，目标是压缩高安全等级系统的认证周期。
  • S8200 内核：集成标量、向量与矩阵引擎，官方称能效较当前产品高 4 倍 TOPS/W，已向关键客户送样，首批硅参考平台预计 2027 年推出；与已量产的 NPX5／NPX6 专用 NPU 并行存在。
  • 客户基础：MIPS 称客户覆盖全球前十二大汽车制造商中的 九家，Mobileye、英飞凌均为其重要客户。

MIPS 的路径说明一件事：在 RISC-V 时代，「有历史包袱的 IP 公司」并非没有机会——把旧 ISA 丢掉、把工具链与客户关系留下，再用「工作负载原生」重做平台分层。Acies 直接点名 VLA 与机器人，是本周第二家把 RISC-V 的落点放在物理 AI 上的国际 IP 厂商。

2.3 Adafruit Metro ESP32-P4 Hydra：UNO 形态的双 RISC-V 核开发板

日期：2026-10-26　来源：CNX Software：Adafruit Metro ESP32-P4 Hydra（10-26）

Adafruit 推出 Metro ESP32-P4 Hydra，把乐鑫 ESP32-P4 做成 Arduino UNO 外形，并额外挂一颗 ESP32-C6 补无线。

  • 主控：ESP32-P4（v1），双核 32 位 RISC-V 高性能核最高 360MHz（带 AI 指令扩展与单精度 FPU），加一颗最高 40MHz 的低功耗 RISC-V 核；16MB PSRAM、16MB QSPI NOR；2D 像素处理加速器与 H.264／JPEG 编解码。
  • 无线：ESP32-C6 模块经 SDIO 连接，提供 Wi-Fi 6、蓝牙 LE 5.3 与 802.15.4（Thread／Zigbee，部分固件需自行集成）。
  • 接口：树莓派兼容的 2-lane MIPI DSI 与 CSI（22-pin、0.5mm 间距）、USB 2.0 高速 OTG 主机口（480Mbps）、microSD、UNO 排针与独立 SPI 排针、STEMMA QT、LiPo 充电。
  • 定位：HMI、相机与 IoT 原型；TinyUF2 支持拖放式固件更新。

ESP32-P4 的生态正在从模组走向「标准外形 + 完整接口」的成品开发板。对做端侧 HMI 与视觉原型的团队，UNO 外形意味着现成的扩展板库存可以直接复用——这类工程便利，往往比多几十兆赫兹更能推动选型。

三、国内团队深挖

3.1 算能：SG2044 固件补上签名密钥、打包工具与全平台 CI

日期：2026-10-26　来源：sophgo/sophgo-edk2 提交记录（10-26，devel-sg2044）

算能的 EDK2 固件仓在 SG2044 分支（devel-sg2044）上窗口内录得 6 笔提交，全部为 10-26 当日创作，内容集中在「让固件可被交付」，而不是改功能。

  • 签名链路：新增 SOPHGO 默认 RSA 签名密钥（keys:），配套 tools: 下的固件二进制签名脚本，把「能签」变成仓内可复现的步骤。
  • 打包：新增 firmware.bin 的打包工具，把分散的镜像拼成单一固件文件；同时提供 envsetup.sh，支持脱离完整 EDK2 树的独立固件构建。
  • CI：增加 firmware.bin 与 firmware.img 的构建，并把 全部 SG2044 平台纳入 CI 编译，防止某个板型在合入后静默坏掉。
  • 衔接：10-08 刚发布 BIOS v2.1.1；10-23 引导程序仓 zsbl 完成到 eboot 框架的重构（前一期已收录）。本期这批提交，正好补上重构后的交付侧空白。

国产高性能 RISC-V 服务器的短板长期不在核，而在「固件能不能被客户安全地刷进去」。签名密钥、打包工具、独立构建环境、全平台 CI 这四件凑齐，才算把固件从「研发能编」推进到「产线能发」。这一步没有发布会，但它决定下一批整机能不能出货。

四、具身智能与机器人专章

4.1 进迭时空机器人栈补位：宇树 Go2 跑上 K3，人形侧接入语音交互与图传

日期：2026-10-26　来源：GitHub：spacemit-robotics/unitree-go2、 humanoid_linglong、 humanoid_common、 omni-agent、 realtime-link

进迭时空的机器人组织 spacemit-robotics 窗口内 5 个仓库有推送、共 9 笔提交，四条线拼起来是一次栈级的补位。

  • 第三方机型适配（新仓）：unitree-go2 仓库名为「Go2 on SpacemiT K3」，README 直接给出在 K3 板端以 root 运行的启动脚本（SDK 位于 /root/spacemit_robot，使用 new_bigcore 配置），并规定启动前必须摆好蹲姿 Pose A、开机自启需在上电前摆好；配套网页控制台在同网段访问 go2-sdk.local:8082。窗口内 5 笔提交包含 ROS 2 应用 + ONNX 策略 + 网页控制，以及 SDK 交付简化、硬件生命周期与相机帧同步、CI 模型下载加固。
  • 人形侧（灵龙）：humanoid_linglong 对应灵龙 L1 V1.4，28 自由度（左腿 6 + 右腿 6 + 头 2 + 左臂 7 + 右臂 7），支持 MuJoCo 仿真与 whole_body 实机后端切换、PC 单机仿真、sim2sim 跨机推理（PC 仿真 + K3 板端 RL 推理）、K3 实机 28 轴电机与并联脚踝／Forsense IMU 控制，另有 Android App 与扫码网页经 HMI 服务接入。本期新增「静态交互与语音服务」配置。
  • 通用层：humanoid_common 新增操作员语音客户端与静态 profile；omni-agent 新增对讲（push-to-talk）与交互式语音工具（#20）。
  • 图传：realtime-link 新增视频传输（#2），提供单头文件 C ABI（libvideo_transmission.so）、参考 UDP 后端，并有基于 MPP 编解码器与 SDL2 显示的板端取图示例。

四条线合起来，是从「自家机型能跑」（灵龙）扩到「别人的机型也能跑」（宇树 Go2），再把语音交互与视频回传补上。对做端侧机器人平台的厂商，可复制的机型适配比单机演示更值钱：Go2 这类存量四足机器人数量大、SDK 相对开放，拿它做 K3 的对外样板，比再调一版人形更能说明平台化能力。需要克制的是，这些提交都是仓库内的代码与文档，未见第三方实测或量产落地数据。

五、总结与趋势观察

  • IP 层的估值分化已经落地到成交价：Codasip 低端 RISC-V 业务以 1450 万美元、27 人的规模转手，同期 SiFive 在卖「加速器控制单元」、MIPS 在做「工作负载原生」平台。三家在同一周给出同一结论的不同答案——通用核不再是价值中心，能不能嵌进客户的系统架构才是。
  • 国内团队补的是工程化的最后一公里：算能的固件签名与打包、进迭的 TEE 文档体系、芯来的扩展与追踪文档，三件事都不进发布会，却都是「能不能量产交付」的前置条件。这一层做扎实，比再发一版参数表更有意义。
  • 开源核进入收敛期：香山 35 笔修复批量回收，作者日期跨 2 月至 9 月，主题集中在 X 态、复位值与 TLB need_gpa；配合 NEMU 补浮点异常标志、GEM5 加译码融合，验证侧的动作比功能侧密集。参考模型「错得比 DUT 少」正在成为显式目标。
  • 发行版的工作量被安全债占满：openRuyi 46 笔里，带 [security-fixes] 的云原生组件更新与整套 Sequoia PGP 迁移是主体。RISC-V 服务器要承接真实业务，先要把签名、密钥与中间件 CVE 这些「非架构问题」清完。
  • 机器人栈从演示转向可复制：进迭时空把宇树 Go2 拉上 K3，并补齐语音与图传，路线从「自家人形能跑」转向「第三方机型可适配」。这类工作对平台的检验，比参数更有说服力。
  • 局限说明：Onsemi 收购 Codasip 的价格、人数与支付比例来自捷克媒体 e15 的报道与 Jon Peddie Research 转述，两家公司均未公布交易条款；Codasip 的公共资助数据引自其自身口径；SiFive 的 Google 部署与 X100 授权客户信息来自 SiFive 博文与 JPR 转述，未获客户确认；MIPS 的 S8200 能效倍数、2027 年硅参考平台时间与「前十二大车企中的九家」均为公司口径；香山 35 笔、openRuyi 46 笔为 GitHub 提交页逐页核对所得，作者日期与提交日期分离属批量回收特征，具体动机未见项目公告；算能、进迭时空、芯来的提交内容依据提交标题与 README 判断，未逐条核对补丁；LibreLane 一节的工序数、ATPG 图形数与覆盖率来自演讲摘要，活动尚未举行，数据待现场核实；会员官网巡检检出的变化多为高校与机构首页例行更新，仅 RISC-V 协会（日本）的会议议程构成实质信息。另：中科通量在 CNCC 2026（10-21 至 24，成都）的展台报道为同一批产品（SmarCo AI 工作站 12 核 RISC-V／250 TOPS INT8／128GB 统一内存）的复展，规格已于 10-20 日报收录，本期不重复；睿芯高光 D35 的「12nm 超越英伟达 7nm」报道系 9-23 内容的再次流转，同样不重复。
