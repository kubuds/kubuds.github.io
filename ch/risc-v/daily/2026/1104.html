一、开源社区与软件生态

香山 TAGE 把 alt 信息存进 meta，训练读只在预测或结果出错时发生（11-03）

第 6800 号改的是 TAGE 预测器里训练读与预测读抢同一份存储的冲突。原先前者要拿到 alt 分支的信息才能决定怎么训练，而这份信息在预测阶段也被读一次，两条通路撞在同一批表项上。改动把 alt 信息额外存进 meta，训练侧不再每次预测都去读一遍，只在 TAGE 预测错误、或实际分支结果与预测不符时才发起训练读。

这类改动的收益不体现在 IPC 上，而是把一条高频读通路从关键路径上摘下来：预测器每周期都要出结果，训练则是错一次才发生一次，把工作挪到低频事件上是分支预测器里最典型的取舍。对正在冲高频的香山来说，省下的端口争用比省下的表项更值钱。

香山修 CBO 操作码拼接错误：CBIE 的 inval-to-flush 被误合成为 cbo.zero（11-03）

第 6754 号是一个后果相当严重的译码 bug。cache block 操作（CBO）的指令里，操作类型本应整体选出完整操作码，代码却把「完整 CBO 操作码」与「基础操作码」做了按位或。当 CBIE 请求把 inval 转成 flush 时，or 运算把 cbo.inval 与 cbo.flush 合成了 cbo.zero——语义从「作废这一块」变成了「把这一块清零」。

两者的差别不只是缓存状态：inval 只是丢弃，zero 会写数据。带数据的清零落到正在被其他 hart 使用或即将回写的行上，就是静默的数据破坏，而且只在特定操作序列下触发，跑分与常规回归都发现不了。作者在提交说明里把成因写得很直接，这类「本该选择却写成或运算」的位域错误，在 RISC-V 新增的 CBO 扩展上尤其容易犯，因为操作码本身就是分层的。

日期：2026-11-03　来源：XiangShan #6754

香山 StoreQueue 与 LoadUnit 四笔修复：CBO zero 入队、跨 16B 前递掩码、MdpHit 判定、回滚信息丢失（11-03）

同日合入四笔访存相关修复，凑起来是一次对 load-store 通路的集中排障。第 6762 号让 flush 前先等 CBO zero 完成入队，避免清零操作在队列被冲刷时丢失；第 6718 号修跨 16 字节非对齐访问的前递掩码，这类访问会同时命中两个表项，掩码算错就前递出错误字节；第 6714 号修 waitSqidx 已退休时 MdpHit 的判定条件，属于时序边界上的状态判断；第 6678 号修同一 RobIdx 下 LoadUnit 回滚信息被后一条指令覆盖的问题。

四笔共同点是都只在特定交错下出错：非对齐访问叠加前递、退休与命中判定同拍、同一 RobIdx 连续两条 load 触发重放。香山近期在这块投入明显加密，与 Matrix 扩展引入的宽访存路径也有关系——通路越宽，边界条件越多。

difftest 拆分矩阵校验的写回与完成事件（11-03）

第 1025 号把矩阵单元的 AMU 事件拆成「写回」与「完成」两类。原先一个事件同时承担两个语义，参考模型与待测设计在乱序交错时容易把「数据已写回」误当成「指令已完成」，或反之，导致校验器在中间态放行。拆开后两类事件各自带序号，校验可以按语义对齐。

这是矩阵扩展校验走向可用的必经一步：MMA 这类长延迟指令的完成顺序与写回顺序本就不一致，用一个事件表达两件事，在多核或重放场景下必然误判。同日该仓库仅此一笔。

德国鲁尔大学等四机构在 RISC-V 多核 SoC 上实测四种随机化缓存（11-04）

鲁尔大学波鸿分校、马克斯·普朗克安全与隐私研究所与佐治亚理工的联合团队发布预印本《Randomized Caches in Hardware: Challenges and Trade-offs》（arXiv，2026 年 10 月，CC BY 4.0），作者为 Xinrui Wang、Pascal Kosak、Christof Paar、Daniel Genkin、Yuval Yarom 与 Anirban Chakraborty。随机化缓存通过打乱地址到缓存位置的映射来抵御侧信道攻击，此前的方案多停留在架构层描述，硬件实现的坑没人系统讲过。

团队把 CEASER-S、ScatterCache、SassCache 与 MIRAGE 四种设计全部实现为同一颗多核乱序 RISC-V SoC 的末级缓存，做成完整 FPGA 原型，并跑完 SPEC CPU 2017 rate 与 GAPBS 全部负载。据其表述，这是首次在同一套全系统硬件平台上对这四种设计做横向评估。论文侧重实现难点与折中，未在公开摘要里给出性能开销量化对比——这一点值得留意，安全机制的代价数据往往藏在正文表格里。

OpenBSD 8.0 的 RISC-V 改进被媒体重新解读（10-20 发布、11-03 报道）

OpenBSD 8.0 于 10 月 20 日发布，11 月 3 日有媒体重新梳理其中的 RISC-V 部分，值得单独记一笔，因为这一版 riscv64 平台的增量集中在架构特性而非驱动：内核开始探测 CPU 扩展并通过 elf_aux_info 的 AT_HWCAP 与 AT_HWCAP2 向用户态上报，用户态程序从此可以按硬件能力分派代码路径；内核加入 V 向量扩展支持；实现 bounce buffers；支持 RISC-V 高级中断架构并新增 imsic 与 aplic 两个驱动；加入 Sstc 定时器扩展支持。同一版本还退役了 Loongson 端口。

对 RISC-V 发行版来说，hwcap 上报是比任何单点优化都基础的设施——没有它，用户态只能按编译期猜测定分支。AIA 与 Sstc 的落地则意味着这块板子的中断与定时器路径开始摆脱旧的中断控制器假设。

二、产品与生态动态

安森美完成收购 Codasip 低端 RISC-V 处理器业务，Codasip 转向 CHERI（11-03 报道）

11 月 3 日有媒体报道安森美（onsemi）已完成对 Codasip 低端 RISC-V 处理器业务的收购，交易金额约 1450 万美元，约九成价款已支付，涉及 Codasip 约 260 名员工中的 27 人，同时获得 Codasip Studio 处理器设计工具的广泛授权。这笔交易本身在 4 月宣布、5 月完成交割，本次报道的价值在于补上了价格与人员规模的细节。

交易之后 Codasip 的方向已经很清楚：放弃通用 CPU IP 授权，转向基于 CHERI 能力硬件的内存安全处理器，面向国防与关键基础设施卖芯片而非卖设计。这条路的参照系是另一家 RISC-V 公司 SCI Semiconductor，其 CHERI 处理器在 9 月拿到 500 万英镑融资。对 RISC-V IP 市场，这是一次典型的出清——通用核的授权生意在供给过剩与价格战里越来越难做，能留下的要么是像安森美这样把核用进自家芯片的买家，要么是找到差异化安全叙事的卖家。

日期：2026-11-03　来源：Jon Peddie Research 报道、Codasip 4 月分拆公告

三、国内团队深挖

同榜获奖名单里的「Powered by XuanTie」：从 3D 近存计算到车规与 Wi-Fi 路由（11-02）

把玄铁 C950 的奖项与同榜客户芯片放在一起看，能读出这条 IP 产品线的实际分布。最高一档是东方算芯 DF1000，用 C908 加 C906 做高能效软件定义近存计算的 3D 芯片，与 C950 同获「年度重大创新突破产品」，说明高端 RISC-V 已经能进 3D 堆叠这类对能效与互联要求极高的形态。第二档是四颗「优秀技术创新产品」：全志 T536 高性能智慧工业 SoC 用 E907，江原 D1 云端推理芯片用 C908 加 E907，物奇 WQ9301 Wi-Fi 路由芯片用 E907，宏思 HSRU3 可重构算法芯片用 E906——分别对应工业控制、云端推理、无线连接与密码算法四个互不相干的赛道。

再往下是量产规模档：清微智能 TX81 可重构 AI 芯片用 C908、泰芯 TXW82X 三模音视频芯片用 E 系列，拿到「优秀市场表现产品」；匠芯创 D12X 智慧屏显 MCU 用 C906、九宸 TD1601 系列 MCU 用 E906、迈特芯 MEGA188 端侧 AI 芯片用 E902，拿到「芯火新锐产品」。从 C908 到 E902 四个内核档次覆盖十款芯片，且都不在同一个市场里打价格战，这是 60 亿颗出货与 400 家客户这两个数字的具体注脚。

humanoid_common 声明 whole_body 构建依赖（11-03）

第 27 号给 humanoid_common 补上 whole_body 的构建依赖声明。此前在并行构建下，全身控制模块可能在依赖尚未就绪时被编译，表现为随机失败的链接错误而非稳定的编译报错，排查成本很高。这类修复对使用方几乎无感，但对 CI 稳定性是必须的一笔。

日期：2026-11-03　来源：humanoid_common #27

ros2_simulation 用带纹理地面改善 G1 的 RGBD 重定位（11-03）

ros2_simulation 当日修了 G1 人形在 MuJoCo 里做 RGBD 重定位时的一个现实问题：纯色地面缺乏视觉特征，SLAM 在长廊式的仿真场景里容易丢失重定位。改动把同一份地面纹理共享给 MuJoCo 渲染与 RGBD 光线投射两条路径，保证仿真画面与深度图看到的是同一套纹理，默认地图库换成带纹理的版本，并同步更新了建图与定位示例。

这类改动看着琐碎，实际是把仿真里「算法不 work」与「场景没特征」两件事分开的关键：机器人视觉算法在仿真中的失败，很大一部分来自渲染与传感器模型之间的不一致，而不是算法本身。

日期：2026-11-03　来源：ros2_simulation 提交记录

五、总结与趋势观察

一、玄铁这一期的信息量在「名单」而不在「奖」。 C950 拿奖是预料之中的事，真正的增量是同一张榜单上十款客户芯片覆盖了从 C908 到 E902 四个内核档次、横跨近存计算、工业 SoC、云端推理、Wi-Fi 路由、可重构 AI 与显示驱动六个市场。这说明玄铁的营收结构已经从「卖核给少数大客户」转成「按档位铺开的长尾」，60 亿颗与 400 家客户是这一结构的自然结果。同日 repos 侧玄铁零推送，与新闻侧的密集形成反差——产品线成熟后，公开仓库不再是主要观察窗口。

二、香山这一天的工作重心是「找错」而不是「加功能」。 九笔提交里六笔是 fix，其中 CBO 操作码被或运算误合成为 cbo.zero 属于会静默破坏数据的严重译码缺陷，StoreQueue 与非对齐前递的四笔则集中在只有特定交错才触发的边界条件。这类问题的共同特征是跑分与常规回归都发现不了，只能靠形式化或定向激励。对使用香山做原型芯片的团队，这提醒了一件事：验证投入必须跟上特性扩张的速度，尤其是 CBO、矩阵这类新扩展。

三、openRuyi 把 RuyiAI 组件收进发行版，是这条栈从「项目」变「产品」的分界线。 TileLang、Triton 的 RuyiAI 包与 buddy-mlir 以 SPEC 形式进仓，意味着用户可以靠包管理器装到，而不是跟着文档编源码；同日内核 debuginfo 支持的补齐，则让线上性能问题的栈回溯第一次可用。这两件事放在同一天发生，指向同一个方向：这家发行版在补「可运维性」，而不只是「能跑起来」。

四、revyos 一次性合入二十笔配置，K3 的平台支持面明显变宽。 UFS、显示控制器、USB3 与 Type-C 整组、奕斯伟 EIC7700 的网口与 pinctrl，加上 linuxboot 配置与 CI 的交叉编译流水线，说明这条发行版正在从「板子能启动」走向「整机外设齐备、改动可验证」。linuxboot 这条尤其值得关注，它对应的是一类以固件方式装载内核的部署场景。

五、安全方向的论文与收购在同一天出现，不是巧合。 一边是四个机构把四种随机化缓存实现进同一颗 RISC-V 多核 SoC 做横向评估，一边是 Codasip 卖掉通用核业务转向 CHERI。两条线说的其实是同一件事：RISC-V 的通用核已经进入价格竞争，能讲出溢价的是安全与专用化。对国内做 RISC-V 的团队，这条判断比任何一个跑分都更值得记住。
