今日重点：科华数据与进迭时空签约，RISC-V 服务器芯片接入算力基础设施

日期：2026-10-22　来源：观点网：科华数据与进迭时空签署战略合作协议 共建国产算力生态（10-22）、搜狐：共赴「芯」征程——科华数据与进迭时空达成战略合作（10-22）

科华数据股份有限公司与进迭时空（北京）智能科技有限公司签署战略合作协议，围绕技术、产品、市场、生态四个维度开展合作，目标是打通 AI 芯片层与算力基础设施层 的适配链路，共建国产算力生态。

  • 科华侧能力：深耕电力电子行业近 40 年、有十余年数据中心建设运营经验，业务覆盖高端电源、精密温控与数据中心全生命周期运营管理；牵头主编《国产芯片与算力硬件基础设施协同技术规范（CCHS）》团体标准，并已与多家国内外头部 AI 芯片厂商合作。
  • 进迭侧产品：K3 为全球首颗符合 RVA23 规范并实现量产的 RISC-V AI CPU；V100 于 10-18 至 20 的峰会期间发布，官方口径为全球首款满足服务器全规格、符合 RISC-V Server SoC 规范的高性能服务器级 CPU，同步给出 C2201 计算服务器、G5201 智算服务器与 S5236 存储服务器三类整机。
  • 合作落点：推动自主可控算力方案从芯片定义、系统适配到规模化部署的全流程贯通；技术上推进 RISC-V AI 芯片与算力基础设施的协同优化，产品上联合打造面向不同算力场景的解决方案。

服务器芯片的发布只是把硬件做出来，能不能进机房取决于供电、制冷、整机设计与运维体系是否愿意为它改。这次签约的实际意义，是把「适配」从芯片公司单方面推动变成基础设施厂商的联合工作；而同期境外媒体的分析恰好指出，适配成本正是客户是否迁移的决定性变量。两条线索指向同一个结论：RISC-V 云端的下一程不在发布会，而在机房。

1.2 社区项目在 ESP32-S31 上跑通 Linux 7.3 与 OpenSBI 1.9

日期：2026-10-22　来源：GitHub：annoyedmilk/esp32-s31-linux（10-22）

社区项目 esp32-s31-linux 在乐鑫 ESP32-S31 上跑通了上游 Linux 7.3 内核与 OpenSBI 1.9，并把 16 MB 八线 PSRAM 当作主存使用。

  • 启动链：ESP ROM 到 ESP-IDF 二阶段，再到 loader、OpenSBI、Linux，最后挂 Buildroot 根文件系统（SD 卡、U 盘或 flash）。
  • 可用用户态：LCD 上的 shell、wpa_supplicant 联网、BlueZ 蓝牙、SSH、USB 键鼠与 U 盘、vim、gdb、strace、MicroPython 以及文本浏览器 links。
  • 技术看点：该 SoC 没有 PLIC、没有 Zicbom、也没有一致 DMA，项目用几百行代码给出了替代实现，并写了面向内核开发者的内部实现文档。
  • 硬件覆盖：ESP32-S31-Korvo-1、ESP32-S31-Function-CoreBoard-1 与 ESP32-S31-WROOM-3-N16R16V 模组三种构建。

一颗按 MCU 定位设计的双核 RV32（320 MHz、512 KB SRAM、16 MB PSRAM）能跑完整 Linux 用户态，说明软件栈对硬件的要求已经压得很薄。这类项目不构成产品路径，但它是检验工具链、内核移植与驱动成熟度的极端用例，对教学与移植参考都有直接价值。

1.3 香山昆明湖 V3 与 CORE-V cvw：补 mnret/dret 译码、jalr 勘误

日期：2026-10-22　来源：XiangShan 提交记录（10-22）、cvw 提交记录（10-22）

香山昆明湖 V3 分支窗口内 3 笔提交，全部落在细节而非功能：decode 补上 mnret 与 dret 两条特权返回指令的译码（#6692）、修正 ROB 重定向起始索引（#6729）、README 增加 Dashboard 与 star 历史链接（#6696）。

  • CORE-V 侧：cvw 仓库 2 笔，为 jalr 指令在 Table I.1 补上勘误条目（PR #1996）并合并。
  • 解读：mnret 与 dret 分别是 M 模式与调试模式的返回路径指令，补译码意味着香山在完善特权态与调试支持；jalr 勘误属文档级修正，对验证团队的价值大于外部用户。

开源核的进展常常就以这种”看不出功能”的提交为主。判断一个开源核是否在推进，看的是特权态、异常与调试这些容易被忽略的角落，而不是又跑通了哪个 benchmark。

二、产品与生态动态

2.1 毫米波雷达的 RISC-V 路线：国产芯片先落地，CPU 槽位仍是第二选项

日期：2026-10-22　来源：RFID 世界网：毫米波雷达 RISC-V 国产抢跑（10-22）

一篇梳理毫米波雷达芯片指令集选择的报道给出了相当务实的判断：在雷达芯片里，RISC-V 与 Arm 目前是并存选项，不是代际替代。

  • 国产先落地：正和微芯 RS6240（2024 年发布，双核 RISC-V）已用于智能家居、康养监护与安防预警；开酷 K60213 内置 RISC-V MCU 与 AI 加速器，进入电视、空调、风扇等室内交互设备。
  • 车规渗透：芯来 NA900 已获 ISO 26262 ASIL-D 认证，加特兰 Kunlun-Pro 内置该内核，双发射双核总算力 3668 DMIPS，约为上一代 Alps-Pro 的 5 倍，正往 L2 ADAS 前向感知推进。
  • 分工边界：外界关注的 10 倍信号处理算力来自加特兰自研的 RSP 2.0，不是 RISC-V 核；RISC-V 承担的是点云后处理与目标跟踪这类算法更新快、必须留在可编程 CPU 上的环节。厂商借开放扩展接口把排序、插值、三角函数做成硬件指令，实测聚类耗时约减半、跟踪耗时下降超过 50%。
  • 国际大厂：TI 的 AWR2188、NXP 的 TEF8388 与 SAF8444 仍用 Cortex-A53 与 M7，短期没有切换动力；奕斯伟在港股上市的招股书也坦言 RISC-V 仍处市场验证初期，用户认知与信任度尚未充分建立。

这条的价值在于给出了 RISC-V 在具体品类里的真实坐标：不是”替代谁”，而是”在哪个槽位上更划算”。驱动力是供应链可控、成本与定制自由，而非性能代差；功能安全也不是短板，NA900 早已具备 ASIL-D 能力，真正漫长的是整芯片三到五年的认证周期。

2.2 国际媒体视角：服务器 CPU 集中亮相后，适配成本成为真正门槛

日期：2026-10-22　来源：Global Times：Chinese chipmakers roll out new RISC-V server CPUs for AI demand（10-22）

峰会后境外媒体给出的一篇综述，把进迭时空 V100 与蓝芯算力 LX500 放进同一条叙事：中国厂商正把 RISC-V 从嵌入式推向 AI 服务器。

  • 事实部分：V100 为 46 核、最高 2.4 GHz、支持 DDR5 与 PCIe 5.0，并同时给出计算、AI 与存储三类整机；LX500 为 48 核并集成专用 AI 引擎，正在适配 Qwen、DeepSeek、Kimi 等模型，目标场景包括企业知识库检索、办公助手、金融合规推理与工业巡检。
  • 观点部分：受访分析人士认为服务器 CPU 的竞争不止于单芯片性能，替换处理器不是换个零件；操作系统、应用与开发工具能否顺畅运行，适配与维护成本能否被接受，才是客户是否迁移的关键。适配成本过高时，即便新芯片有技术优势，客户也会犹豫。

把”发布”与”落地”分开看，这篇提供了一个外部视角的标尺：展会上的整机证明硬件形态已经齐备，而生态侧的成本核算才决定订单。这与本期的今日重点互为注脚。

2.3 乐鑫 ESP32-S31 外溢到成品：GUITION 旋钮屏换代新 SoC

日期：2026-10-22　来源：CNX Software：Rotary encoder with 1.8-inch touch display gets upgrade to ESP32-S31 SoC（10-22）

GUITION JC3636F118C-I-YR1 是把原 ESP32-S3 版本升级到 ESP32-S31NRV16 的旋钮屏产品：1.8 英寸 360×360 圆形 TFT（ST77916 驱动加 CST816 触摸）、16 MB flash 与 16 MB PSRAM、扬声器与 MEMS 麦克风、DRV2605 触觉驱动与 USB-C 供电。

  • 无线规格：Wi-Fi 6、蓝牙 5.4（含 LE Audio、方向查找、Mesh 1.1）与 802.15.4 三模，CPU 为 320 MHz 的 RV32IMAFCP 高性能核加一颗低功耗 MCU 核。
  • 产品意义：距 ESP32-S31 首次出现在第三方开发板（10-14）不到十天，成品已开始换代。MCU 级 RISC-V 的整机跟进速度，比前几代架构明显更快。

三、国内团队深挖

3.1 达摩院玄铁 CubeSandbox：RISC-V CI 连推 12 笔，微虚拟机控制面跑通 MySQL

日期：2026-10-22　来源：XUANTIE-RV/CubeSandbox：feat/riscv64-ci 分支提交（10-22）

玄铁维护的 CubeSandbox 在窗口内把工作重心从”开出 RISC-V 分支”转到 CI 攻坚：feat/riscv64-ci 分支录得 12 笔提交，全部围绕在 RISC-V 上把微虚拟机（microVM）控制面稳定跑起来。

  • 内核配置：为 7.2 版本的 L1 内核打开 CONFIG_NUMA、把 XFS 与 dummy 驱动编进内核、补齐 tc-bpf、bridge 与 tap 网络栈。
  • 可观测性：失败时抓取 L1 的 dmesg 与 L2 guest 控制台输出；新增环境变量开关让 guest console 可观测；把 dirty log 默认关闭，另给 CUBE_DISABLE_VM_DIRTY_LOG 作逃生口。
  • 流程：拉长 shim 的虚拟机启动等待并在退出时关掉 L1；C1 控制面演示改用 apt 安装的 mysql systemd 单元，先修 mysqld 可观测性、再验证服务能正常停止。
  • 上游背景：上游是腾讯云开源的 AI Agent 沙箱（Apache 2.0，硬件级隔离、毫秒级启动、兼容 E2B 接口），RISC-V 侧的快照与恢复仍待 vAIA 状态迁移实现，属开发者预览阶段。

这十几笔提交没有一条是”功能发布”，全是把不稳定因素逐个钉死：内核配置、串口可观测性、脏页日志、MySQL 启停验证。微虚拟机在 RISC-V 上从能启动到能承载真实负载，成本几乎全花在这类工作上，这也是判断这条栈成熟度最可靠的观察点。

3.2 进迭时空软件栈三线迭代：视觉模型接口统一、llama.cpp 预填充优化

日期：2026-10-22　来源：model-zoo-vision 提交（10-22）、llama.cpp：mtmd-backend 分支提交（10-22）、ai-sdk 提交（10-22）

V100 发布之后，进迭时空的软件栈在三条线上同时小步迭代，方向都是”让外部开发者能直接用”。

  • 视觉模型库：model-zoo-vision 三笔提交，重构核心把各任务的 Run 接口统一、去掉 task 层接口（#109），统一各模型示例的 README（#110），为 track 与 match 两类模型补上 Python 示例（#111）。
  • 推理栈：llama.cpp 的 mtmd-backend 分支两笔，ggml 侧 SpacemiT 预填充优化（#49）与清理过时的重复 -lm 与 –load-mode 选项（#50）。
  • SDK：ai-sdk 两笔子模块更新，指向 vision 模块。
  • 配套文档：docs-ros 同日两笔把感知与视觉文档对齐新的节点行为与 SDK 接口（#217、#218）。

接口统一与示例补齐，是模型库开始面外部开发者的信号；预填充优化则直接影响长上下文的处理效率与首 token 延迟，是服务器场景最敏感的指标之一。芯片发布后软件跟进的速度，往往比规格更重要。

3.3 算能 sophon-demo 新增 PaddleOCR-VL 的 Python 样例

日期：2026-10-22　来源：sophgo/sophon-demo 提交记录（10-22）

算能的示例仓库 sophon-demo 在 release 分支新增 PaddleOCR-VL 的 Python 样例（paddleocr_vl.py），补上这条文档智能模型在自家平台上的可直接运行版本。

  • 前情：10-19 同仓刚做过一次整理，去掉随仓打包的 tpu-mlir wheel 下载；这次把 Python 版本补齐，形成文档加样例的完整组合。
  • 同期节奏：10-19 至 10-21 该仓连续补入 SAM3、SAM2、BLIP、MP_SENet、YOLO_world 的 C++ 样例，以及 CV84X6 平台的 MiniCPM4、InternVL3、MiniCPMV 适配。
  • 解读：示例库在两个月里从”Python 参考实现”扩展到”C++ 工程化样例 + 热点模型首日适配”。端侧芯片的竞争力越来越取决于模型到了能不能跑、照着文档能不能复现，这一层比参数宣传更实际。

四、具身智能与机器人专章

4.1 21 世纪经济报道专访孙彦邦：K3 支撑人形机器人完赛，机器人将走向单芯片

日期：2026-10-22　来源：21 世纪经济报道（新浪财经转载）：人形机器人马拉松背后的 RISC-V 力量（10-22）

峰会后的一篇深度专访，受访者为进迭时空联合创始人孙彦邦，给出了几条可核验的进展与判断。

  • 已发生的进展：2026 年 4 月北京亦庄人形机器人半程马拉松中，灵龙 2.0 完赛所用的是进迭时空 K3 芯片；K1 累计出货 15 万颗，K3 为全球首颗符合 RVA23 规范的量产 RISC-V 芯片并已规模量产交付。这两代端侧芯片的积累，被描述为向云端延伸的起点。
  • 市场预测：引用 Omdia 数据，RISC-V 处理器年出货量增长率为 50%，2030 年全球市占率将接近 25%，约每四颗处理器有一颗是 RISC-V。
  • 判断一：机器人产业进入规模化落地周期后必然走向单芯片集成路线，下一代机器人会更依赖 RISC-V，原因是对安全性的极致要求与强 CPU 加 AI 能力的融合。
  • 判断二：机器人的实时性需求”永远没有天花板”，AI Agent 逃逸现象频发，虚拟化与物理隔离都难以彻底保证系统始终在可控范围内，开源开放的机制反而可能是破局点；Physical AI 是最大的机遇。
  • 判断三：研发路线要与资金实力匹配；PPA 之外硬件必须超配，软件生态才有发挥空间；国产产业链迭代速度值得期待，但最终衡量标准仍是订单转化。
  • 外部观点：另引图灵奖得主 David Patterson 的判断，AI 推高存储带宽与容量压力，主流标准存储性能提升停滞，领域专用存储（DSA）在算力稀缺背景下变得可行。

这篇把”RISC-V 做机器人”从概念落到两个具体坐标：一颗已规模量产的端侧芯片，以及一条”安全加实时”的架构理由。相比算力数字，后者更能解释机器人厂商为什么愿意换架构；而”硬件必须超配”这句，也正好解释了当前机器人芯片普遍提前预留算力的做法。

4.2 spacemit-robotics：动作识别配置对齐 13 点骨架

日期：2026-10-22　来源：ros2_action_recognition 提交（10-22）、spacemit-com/docs-ros 提交（10-22）

进迭时空的机器人软件线在窗口内完成一次接口对齐：动作识别仓库合入修复，把 STGCN 配置与 13 点骨架定义对齐到视觉 API（#8）；同期 docs-ros 两笔把感知与视觉文档同步到新的节点行为与 SDK 接口，ai-sdk 两次子模块更新指向 vision。

  • 仓库定位：spacemit-robotics 覆盖手势识别、动作识别、实时链路与外设控制，属 K3 平台机器人的配套软件；同窗口内还有 realtime-link、manifest、peripherals_led 的推送。
  • 解读：骨架关键点从常见的 17 点或 21 点收敛到 13 点，是上游模型与自家推理管线对齐时典型的一步；文档与 SDK 同步更新，说明这条线在准备对外交付而不是内部试验。

五、总结与趋势观察

  • 服务器叙事的重心从”芯片发布”转向”基础设施适配”：峰会上 V100、LX500、C950A 集中亮相，峰会后的第一批新动作是科华数据与进迭时空的签约，以及境外媒体对适配成本的讨论。硬件形态已经具备，接下来拼的是机房侧的接受度与软件栈的迁移成本。
  • RISC-V 在细分品类的位置更清楚了：毫米波雷达的报道说明，在 DSP 与硬件加速器承担主要算力的芯片里，CPU 指令集是”方案选择”而非”代际替代”；国产厂商先用上的原因是供应链可控与定制自由，不是性能代差。
  • 发行版补齐的节奏稳定且层次上移：openRuyi 连续三天分别补 Go 云原生组件、uv 的 Rust 依赖与 Python、Node、Java 运行时版本，安全修复开始带标记走流程。RISC-V 发行版正在从”能装”走向”敢用于生产”。
  • 微虚拟机栈在 RISC-V 上进入调试期：CubeSandbox 的 12 笔提交全部是内核配置、可观测性与流程验证，没有一条功能发布。这是从能启动到能承载负载的必经阶段，也是观察 RISC-V 虚拟化成熟度的最佳窗口。
  • 端侧出现外溢效应：ESP32-S31 从预览器件到第三方成品只用了约十天，社区项目甚至在它上面跑通完整 Linux 与图形化外的全套用户态。这类”向下压榨”的玩法会持续放大 RISC-V MCU 的开发者曝光。
  • 机器人侧的证据仍来自端侧与实时控制：K3 支撑人形机器人完赛、关节控制芯片已量产，而大算力的”大脑”芯片多处在流片阶段。RISC-V 在机器人上的第一波真实出货，很可能仍来自运动控制而非通用 AI 算力。
  • 局限说明：科华数据与进迭时空的合作细节来自两家公司的对外口径与财经媒体转述，未披露合同金额、时间表与具体项目；毫米波雷达报道中的性能数字（3668 DMIPS、聚类与跟踪耗时）来自厂商测试，未见第三方复现；Global Times 的受访者为行业分析人士，观点不代表产业共识；ESP32-S31-Linux 属社区项目，作者自述为”非为 Linux 设计”的器件上的移植实验，不构成产品化路径；openRuyi 的提交内容依据提交标题判断，未逐条核对 changelog；CubeSandbox 的 RISC-V 支持仍为开发者预览，官方未提供发布镜像；会员官网巡检检出的 95 处变化均为高校、机构与厂商首页的例行更新，未发现实质产品、融资或架构发布。
