今日重点：车规 RISC-V 轮到工具链接棒，HighTec 与 TASKING 同日宣布支持 AURIX RC1（11-10）

英飞凌 AURIX RC1 在 11 月 4 日发布、11 月 9 日被确认 RISC-V 核来自 MIPS IP 之后，11 月 10 日进入第三个环节：工具链。两家欧洲车规软件工具厂商同日发布支持声明，恰好卡在慕尼黑 electronica 2026 开幕首日（11 月 10 至 13 日）。

HighTec EDV-Systeme 的公告说得很具体：其面向 RISC-V 的 Embedded AI、Rust 与 C/C++ 开发平台已支持 RC1，做法是把 RC1 的器件相关编译选项收敛进同一套多架构编译器，并与英飞凌合作加入针对流水线与代码尺寸的优化。这条路线的独特处在于语言覆盖面——同时提供经安全与信息安全认证的 C/C++ 与 Rust 工具链，并计划为 RC1 推出嵌入式 AI 开发平台；支持范围也顺势从 AURIX 扩到 TRAVEO 与 PSOC，即英飞凌把原先两条产品线合并后形成的整个 MCU 家族。HighTec 同时是 DRIVECORE RISC-V 虚拟原型捆绑包的参与方，该捆绑包含 Synopsys VDK、Lauterbach TRACE32、HighTec 的 RISC-V C/C++ 平台与外设驱动，并带 FreeRTOS 实现与协同仿真示例——芯片未到、软件先跑，这是车规项目的常规节奏。

TASKING 的口径是把整条生命周期收进一套工具：编译用 VX-toolset，调试用 winIDEA 与 BlueBox，验证接 LDRA，并在工具链里内置 Agentic AI。时间表给得明确：支持 RC1 的 VX-toolset for RISC-V 于 2026 年 12 月可用，工具链认证计划在 2027 年。AI 部分落在两处：12 月版本将把 TASKING 的工具链知识（构建、诊断、map 文件与 LSL 分析、启动代码）通过 MCP 接进 VS Code 环境，而已认证的工具本身不变；调试侧 winIDEA AI Kit 在三个用例中已显示出至少 50% 的工作量下降。对迁移中的团队，卖点是「换架构不换工具链」——从 TriCore 迁来的保留既有 CI/CD 与经验，从 Arm 迁来的用同一套工具覆盖两种架构。

把三天的消息串起来看，车规 RISC-V 的推进顺序是 IP、硅、工具链、认证，四步各自有明确的外部信号：11-09 是 IP 来源（MIPS，格芯代工），11-04 是产品定义（最高 12 核、40MB 存储、ASIL D、2027 上半年送样），11-10 是工具链可用性（12 月出编译器、2027 认证）。两家工具厂商给出的认证时点与英飞凌的送样时点对齐，说明这套时间表不是各说各话。对国内做车规 RISC-V 的团队，这一轮值得注意的不是又多了两家编译器供应商，而是「认证时间表」正在变成客户提问的标准格式。

日期：2026-11-10　来源：HighTec 新闻稿、TASKING 新闻稿（Business Wire）

一、开源社区与软件生态

RevyOS 内核一次落六笔：K3、K1、DP1000、EIC7700 四平台配置入树（11-10）

RevyOS 的 linux 仓库（revyos/7.3.y 分支）在窗口末尾一次性落地六笔配置提交：开启 SpacemiT K3 支持、开启 SpacemiT K1 支持、开启 UltraRISC DP1000 支持、开启 ESWIN EIC7700 支持，另加一份 linuxboot 配置与 CI 的交叉／原生构建任务。六笔提交同一作者、同一时间戳，属于一次平台矩阵的批量收口而非渐进开发。

配置入树的意义在于把「能启动」变成「默认能编译出来」。这四个平台分属三家厂商：进迭时空的 K1 与新一代 K3、超睿（UltraRISC）的 DP1000、奕斯伟的 EIC7700——恰好覆盖了当前国内 RISC-V 开发板与工控板最常用的几颗 SoC。linuxboot 配置与 CI 双构建一起进，说明这个发行版在往「可复现构建」上补，而不是只维护一台能跑的机器。

日期：2026-11-10　来源：revyos/linux

openRuyi 主仓转进安全修复批次：policycoreutils 升 3.11，cups／lxc／libmtp 回补上游补丁（11-10）

openRuyi 主仓在窗口内的工作重心从版本升级转向安全：policycoreutils 升到 3.11 并回补 fixfiles 的修复，lxc、libmtp、cups 三个包分别回补上游安全补丁（提交均带 security-fixes 标记），libssh 升到 0.12.2，llvm-snapshot 跟到 20261109 快照。

这与前一日该仓 20 笔「常规滚动升级」形成对照：一天做功能版本、一天做安全回补，是滚动发行版典型的节奏切换。cups 与 lxc 属于桌面与容器两条常用路径，libmtp 影响移动设备挂载，这三个包的回补对实际使用者的意义大于版本号变化——安全修复不进主线，发行版就没有「可用于生产」的说服力。

日期：2026-11-10　来源：openRuyi-Project/openRuyi

NEMU 修 riscv64 的 SIP 写入锁存定时器中断，AME 改用 CRC32C 算矩阵完成哈希（11-10）

香山的 NEMU 模拟器在窗口内合并两笔方向相反的提交。一笔是正确性修复：riscv64 侧阻止对 SIP（监管级中断挂起寄存器）的写入把定时器中断锁存下来（#1242），属于中断虚拟化路径上的细节错误——写 SIP 不该被当成软件触发中断的来源。另一笔是性能优化：AME（矩阵扩展）改用 CRC32C 计算矩阵完成的哈希（#1280），并配合此前 #1275 的 hosttlb 矩阵访问共享优化。

模拟器的这两类提交同时出现，说明矩阵扩展的软件栈正在被认真打磨：一边修特权态语义，一边给验证与缓存路径降开销。对做 RISC-V 矩阵／向量扩展评估的团队，NEMU 的 AME 实现是目前少数能跑完整软件栈的开源参考之一，这类提交比跑分更能说明成熟度。

二、产品与生态动态

riscv100.top 榜单页改版：完整表格换成「架构卡片 + 总览排名」（11-10）

riscv100.top 的榜单页在窗口内完成改版：原先按行罗列全部成绩的表格不再出现在页面源码里，改为「每个架构一张头名卡片 + Overall Ranking 总览列表」的结构，卡片给出平台、编译器、Ratio/GHz、Run rank、Tests 与 Run date，总览列表只保留各平台的最佳一行。以跨架构 SPEC CPU2006 为例，卡片分别对应 AWS EC2 Graviton5（GCC 15.1.0，24.91）、香山 KMHv3 RTL（XSCC 2.0，22.80，带 NEW 标记，记录日期 2026-10-17）与 AMD Ryzen 9 9950X（GCC 15.1.0，17.72）；RISC-V 侧在总览中另列进迭 K3 X100（XSCC 1.1，8.54）与倚天 710（XSCC 1.1，17.69）。首页 What’s New 现有六条，含 SpaceMiT K3 X100 XSCC 1.1 SPEC CPU2006、SpaceMiT K3 X100 Version Progress Now Available、Run Comparison Now Available 等。

改版带来的直接影响是「历史全量成绩」不再从页面直接可取，日报侧的原表格解析随之失效。本期不据此判定任何新增或下榜——站点在同一次改版中同时刷新了页面结构与快照基线，这类变化无法区分「成绩变动」与「展示收缩」。对读者的实用建议是：需要具体分数时按卡片与总览读，需要历史趋势时改用站点的 Version Progress 与 Run Comparison 两个区块。

詹姆斯敦基金会评中国 RISC-V 路线：策略先行于能力（11-10）

美国智库詹姆斯敦基金会 11 月 10 日刊文评估中国 RISC-V 推进情况，作者 Sunny Cheung。文章给出几条可核对的事实线索：进迭时空与香山团队在 10 月 19 日第六届 RISC-V 中国峰会上发布 46 核服务器芯片 V100，宣称是首款完全符合 RISC-V 服务器标准的通用芯片；9 月发布的《电子信息制造业「十五五」规划》提出推进 RISC-V 研发与产业化、发展面向人工智能的 RISC-V 芯片，此前国家级政策文件较少直接点名该指令集。

文章的核心判断是「策略优先于能力」：扩张使用与对国际组织的影响力是明确的，但性能仍弱于专有芯片，文中引述中国分析人士对「玻璃天花板」的担忧，并称国家信息技术替代计划中 RISC-V 芯片的替代占比「可忽略」。这类外部评估值得作为对照阅读——它把国内常讲的「生态已成」放到另一套指标体系下检验，而这两套指标之间的差距，恰好是下一阶段国产 RISC-V 需要回答的问题。

日期：2026-11-10　来源：Jamestown Foundation

三、国内团队深挖

香山昆明湖 V3 五笔：VBTB 改 taken-first 选择，NewCSR 断点门控重取（11-10）

香山主仓（kunminghu-v3 分支）在窗口内合并五笔实质提交：把 MBTB 中 VBTB 的预测选择逻辑改为 taken-first（#此前行为是另一套优先级）、修复 NewCSR 在 CSR 写入改变断点门控时未重新取值的问题（#6862）、在重定向清理时保留 ROB 待定槽位复位、把 CBO invalidate 事件对齐到 cache line 粒度（#6864），以及一笔 codeowners 维护。同一窗口内 NEMU、difftest、XSCache 也各有提交，difftest 侧集中在 Verilator 编译选项、gsim 断言注册与 FPGA 侧 XDMA 组排空。

五笔里最能说明问题的是 VBTB 的 taken-first 与 CBO invalidate 的对齐。前者是分支预测器内部的优先级取舍，直接影响取指带宽的利用率；后者属于缓存一致性协议与验证模型的对齐，错了不会立刻挂，但会让长跑回归出现难以复现的偏差。香山近期的提交风格一直是「微架构调优」与「验证基础设施」交替推进，这一窗口两件事同时出现。

日期：2026-11-10　来源：OpenXiangShan/XiangShan、OpenXiangShan/difftest

进迭时空 llama.cpp：恢复 IME1 稠密 Q4 路径，SSM 卷积融合保活输入（11-10）

spacemit-com 的 llama.cpp fork（mtmd-backend 分支）在窗口内合并三笔与 K3 后端直接相关的提交：恢复 IME1 的稠密 Q4 路径（#60）、在 ssm_conv 融合时保证 concat 输入不被提前释放（#58）、把门控 delta 网络按 head size 做 strip-mining（#59，前一日已收录同名方向，本期为合并落地）。另有 #61 把上游同步（sync/upstream-20261110）并入，服务端改用上游的视频能力探测逻辑。

三条线各指向一个具体问题：IME1 稠密 Q4 是 K3 上量化推理的主路径，恢复意味着此前的回退被撤回；ssm_conv 的输入保活属于融合算子的生命周期管理，这类 bug 只在特定图结构下暴露；按 head size 展开则是把 RVV 的向量宽度用满。上游同步与 K3 专有优化并行推进，是这个 fork 一直维持的模式——既不脱离上游，也不放弃本地后端。

日期：2026-11-10　来源：spacemit-com/llama.cpp

平头哥 IPO 进展：香港《信报》称已向港交所秘密提交申请（11-10）

作为 11 月 9 日「平头哥拟 2027 年赴港 IPO、募资 20 亿至 30 亿美元」消息的后续，香港《信报》11 月 10 日进一步报道称平头哥已向港交所秘密提交上市申请；阿里巴巴与平头哥方面截至发稿未作回应。此前披露的信息包括：估值区间 250 亿至 620 亿美元；真武系列 AI 芯片（PPU）累计出货超 47 万片、年化营收超百亿元，截至 2026 年 6 月服务超 650 家企业客户、外部客户占比超 60%；真武 V900 计划 2027 年一季度量产。

与 RISC-V 的关系需要说清楚：本次拟上市主体是平头哥，产品为真武 PPU（AI 加速卡）与倚天（Arm 服务器 CPU），玄铁 RISC-V 处理器 IP 已于 2024 年从平头哥分拆、转属达摩院。媒体在回顾平头哥产品线时常把「玄铁系列累计出货突破 60 亿颗」一并计入，那是历史沿革口径，不宜理解为本次 IPO 资产包含 RISC-V IP 业务。这条对判断「国产 RISC-V 的资本化路径」有参考价值，但不构成 RISC-V 产业本身的融资事件。

日期：2026-11-10　来源：同花顺财经转载财闻报道

矽速双线：TangMega-138K 修正 PCIe 例程并给出 Gen3 结论，MaixPy 修打包（11-10）

矽速（Sipeed）在窗口内两条产品线同时收尾。TangMega-138K-example 连出五笔文档与例程修正：删掉 PCIe 例程里重复的 rstn 与一处对 0x808760 的无效写入、把同样的修正套用到 Gen3（8G）工程、更正树莓派侧 PCIe 说明并记录 REFCLK 的修法、补充 NextTang Gen3 的测试结果，并明确写下「Gen3 长稳测试不可靠，建议仍用 Gen2」与「DRP 重放未内置」两句结论性说明。MaixPy 侧修掉镜像打包问题并把发布用 CMake 版本钉住。

两件事性质不同但都属「把话说清楚」：PCIe 的 Gen3 结论是主动降低预期，避免用户按宣传口径采购；MaixPy 的打包与版本钉住则是让发布产物可复现。对以开发板为主要形态的 RISC-V 生态，这类收尾工作的价值往往高于再发一块新板。

日期：2026-11-10　来源：sipeed/TangMega-138K-example、sipeed/MaixPy

四、具身智能与机器人专章

进迭机器人栈：Unitree G1 与 humanoid_common 对齐 SONIC 跟踪与调度（11-10）

spacemit-robotics 在窗口内对双足人形栈做了一轮一致性修正：humanoid_unitree_g1 修 G1 的 SONIC 跟踪、动作预设与启动就绪判定，humanoid_common 同步对齐 SONIC 调度并保持跟踪响应，control_whole_body 把反馈位置限幅与指令边界拆开处理。三笔提交的作者相同、时间相近，属于跨仓的一次协同修正。

技术要点在「跟踪」与「调度」被分开表述。此前的实现把规划器的 CPU 调度与跟踪回路耦合在一起（11-04 的 #14 已开始拆分），这一轮进一步把启动就绪、动作预设与跟踪误差的判定解耦。对在 K3 上跑人形控制的团队，这类改动的意义是让实时回路的抖动来源可定位——出问题时能判断是规划器排队还是跟踪本身超差。

日期：2026-11-10　来源：humanoid_unitree_g1、 control_whole_body

新仓 ros2_spacemit_vslam 初始提交，进迭补齐 SLAM 环节（11-10）

spacemit-robotics 新建仓库 ros2_spacemit_vslam 并完成初始提交，从命名看是把视觉 SLAM 封装为 ROS 2 节点、面向进迭平台交付。该组织此前已有 perception（把推理运行时打包进 las2）、unitree-go2、humanoid 系列与四足移植，SLAM 是其机器人软件栈里此前缺失的一环。

补齐 SLAM 之后，进迭的机器人栈在软件层面已经覆盖感知（perception）、定位建图（vslam）、全身控制（control_whole_body）与整机适配（unitree_g1／go2）四层。这个组合更像是「把一套可复现的整机参考实现做全」，而不是逐点发布单个算法——对想把 K3 放进机器人本体的团队，参考实现的完整度比单项指标更有用。

五、总结与趋势观察

一、车规的竞争点已经移到工具链与认证时点。 AURIX RC1 三天里的三步——11-04 产品定义、11-09 IP 来源、11-10 工具链支持——把车规 RISC-V 的推进顺序摆得很清楚：芯片厂定义平台，IP 厂供核，工具厂给编译与调试，最后是认证。HighTec 与 TASKING 给出的「12 月工具可用、2027 认证」与英飞凌「2027 上半年送样」严丝合缝，说明这套时间表是协同排过的。国内车规团队接下来被问到的，大概率不是「你们有没有 RISC-V 核」，而是「工具链什么时候过认证」。

二、发行版侧这一天做的是「可交付」而非「新功能」。 RevyOS 一次把 K3、K1、DP1000、EIC7700 四个平台配置入树并补 linuxboot 与双构建 CI，openRuyi 转进安全回补批次，两件事都在回答同一个问题：这套系统能不能作为交付物交付给别人。配置入树决定「别人能不能编译出来」，安全回补决定「敢不敢放到生产」。相比之下，新功能发布在这一天是缺席的。

三、国内团队的工作集中在把链路补齐，而不是把指标拉高。 香山改分支预测与验证对齐，进迭在 llama.cpp 上恢复量化主路径并修融合算子生命周期，机器人侧把 SONIC 调度与跟踪解耦、并补上 SLAM 仓。这些改动的共同点是「让现有能力稳定可复现」，与原先前一日的芯来 NI1000 发布（新 IP、新指标）形成两种节奏的交替。

四、榜单类信源的可比性需要重新确认。 riscv100.top 改版把全量成绩从页面移除，只留各架构头名与总览列表。对日常跟踪来说，这意味着「分数变化」这一维度暂时不可连续观测；本期的处理是不判定新增与下榜，等站点结构稳定后再重建基线。任何依赖单一榜单做结论的表述，在改版期间都应加一句口径说明。

五、离岸视角开始用「能力」而非「规模」来评估中国 RISC-V。 詹姆斯敦基金会的文章承认政策与生态推进的力度，但同时指出性能差距与替代占比「可忽略」。这类评估不必照单全收，但它提示一件事：当国内叙事以出货量、峰会规模、标准符合性为主时，外部观察者看的是单核性能、软件成熟度与实际替代率——两套指标之间的差距，正是下一阶段要补的功课。
