今日重点：进迭时空端侧 Agent 全栈集中公开：BiBit GUI 与语音服务发布 1.0Beta1，Bianbu AgentOS 组件开源

日期：2026-10-14　来源：bibit Release 1.0Beta1（10-14）、bibit-voice Release 1.0Beta1（10-14）、bianbu-agent-runtime 初始导入（10-14）、bianbu-agent-memory 初始公开快照（10-14）

接续 10-13 的集中建仓（上期日报已报道），进迭时空在窗口内把端侧 Agent 系统软件栈（Bianbu AgentOS）整体推向公开：桌面端 BiBit GUI 与离线语音服务 Bibit Voice 发布 1.0Beta1，Agent 运行时、记忆服务、安全组件等集中开源。要点：

  • BiBit GUI（1.0Beta1）：面向 Agent 系统助手的桌面前端，以开源项目 Jan 为代码骨架（React 19＋Tauri 2＋Rust，Yarn 4.5.3 构建链），当前保留并演进对话交互、富消息、附件、会话历史与设置界面；面向 Bianbu 4.x riscv64 提供 Debian 原生包（源码内固定 Yarn 版本以适配 RISC-V 构建机内存约束）；Agent Runtime 暂沿用 Jan 兼容实现、后续经 Adapter 接入正式运行时。
  • bianbu-agent-runtime（初始开源）：YAML 配置驱动的 Agent 服务，自述为 Bianbu AgentOS 的运行时核心——会话即事件流（多端同一投影）、插件可贡献 Tool／Skill／Hook／MCP／Console 页面、securityd 签名清单与 Tool 审批等安全边界（生产模式 fail-closed）；当前仅支持 K3（riscv64，Bianbu 4.0）。
  • bianbu-agent-memory：设备侧、本地优先的记忆服务（Rust 守护进程＋Python SDK＋Unix socket 协议）——L1 会话事件／L2 工作摘要／L3 长期记忆三层，本地全文检索、SQLCipher 加密、版本冲突检测与命名空间隔离；提供 CLI、MCP 服务与 Runtime Bridge，并含 Hermes 与 DeepSeek Harness 适配器。
  • Bibit Voice（1.0Beta1）：面向 K3／Bianbu Desktop 的离线语音服务栈——唤醒词检测（KWS）、语音活动检测（VAD）与语音识别（ASR，SenseVoice／Qwen3-ASR），基于 PipeWire 采集与 sherpa-onnx SpacemiT runtime；对外提供两层 Unix socket 与 MCP（8 个工具），唤醒应答音「我在」随包分发。
  • 同批开源组件：bibit-intent（边缘优先意图路由与工具执行）、bibit-filesearch（本地文件搜索服务）、bibit-runtime-plugin、bianbu-agent-security 初始公开；另 mpp 媒体处理库改用 MIT 许可并统一版权声明，ai-sdk 增设 KWS 子模块与中英架构图，docs-product 新增 V100 系列（C2201／S5236／G5201）产品页骨架。

上述组件与 K3 硬件、Bianbu 发行版形成「芯片—系统—Agent 运行时」的纵向组合；Bianbu AgentOS 以单一平台（K3）先行验证、再向其他平台扩展的路线已较清晰。

一、开源社区与软件生态

1.1 Linux 内核补丁让「本机是否 RVA23 合规」一键可查

日期：2026-10-14　来源：Phoronix：Linux Finally Making It Easier To Answer The Question: “Is This RISC-V System RVA23?”（10-14）、LPC 2026 演讲《RVA23 in practice》材料（10-02）

Phoronix 报道：Linux 用户即将能「一次性」回答「我的 RISC-V 系统是否 RVA23 合规」——待合入的内核补丁提供了单次查询能力（现状需拼合 /proc/cpuinfo、hwprobe 与档案要求逐项比对，Ubuntu 侧工具此前只能给出「probably RVA23」）。报道配图即为一台 SpacemiT K3 的 RVA23 报告截图。背景（与本系列此前报道衔接）：该能力即 LPC26 上披露的 **riscv_hwprobe 单比特方案（KEY_BASE_BEHAVIOR：IMA RVA23U64，开机从完整 ISA 位图一次性计算）**——系列补丁由 Andrew Jones 发起 RFC、现由徐国栋（Guodong Xu）推进，已于 10-09 达到 v8（11 枚 patch 中前 8 枚被收入 riscv/for-next），v9 将补充 RVA22／RVA20 分级位。RVA23 档案对统一现代 RISC-V 二进制分发意义重大（Ubuntu 现代版本已将其列为基线，合规硬件仍有限）。

1.2 RISE 项目发布 SpeexDSP 的 RVV 向量优化成果：重采样最高加速 4.88 倍

日期：2026-10-13~10-14　来源：RISE Project：Accelerating Audio Processing with SpeexDSP Optimizations for RISC-V（10-13）、Hacker News 讨论（10-14）

RISE（RISC-V 软件生态）项目刊出 RP020 结项成果：为实时音频基础库 SpeexDSP（音频重采样、回声消除、抖动缓冲与预处理，被 VLC、Firefox、Wireshark、PulseAudio、Mumble 等广泛使用）引入手写 RVV 汇编，并现代化其构建与验证设施。要点：

  • 性能：手写向量重采样内核对比「编译器自动向量化 C」——浮点内核加速 3.71 倍（Clang 18）／3.59 倍（GCC 13）；定点内核 2.69 倍（Clang 18）／4.88 倍（GCC 13）（后者 GCC 未能自动向量化）。
  • 跨硬件验证：得益于 RVV 的长度无关特性，同一份汇编在 SpacemiT K1（VLEN=256）与 Canaan K230（VLEN=128） 两类物理平台均有效。
  • 验证基建外溢收益：Meson＋Checkasm 校验顺带发现并修复了 SSE2 内核一个历时 8 年的数据依赖缺陷（内积内核此前比标量 C 还慢 0.58~0.75 倍）。
  • 组织形式：由 Google 工程师与 RISE 合作推进（技术负责人 Nathan Egge，承包商 FFlabs／Tristan Matthews），RISE 资助 4 万美元。

1.3 openRuyi：固件线发布「Ruyi Firmware 20261014」，K3 双簇 CPU 模式选择落地

日期：2026-10-14　来源：Ruyi Firmware 20261014 Release（10-14）、edk2-ruyi：K3 persistent CPU selection modes（10-14）、openRuyi 提交记录（10-14）

openRuyi 固件线发布 「Ruyi Firmware 20261014」，核心特性为 K3 平台的 CPU 簇模式选择：UEFI Setup 新增模式开关，设置持久化到 SPI 专用扇区并由 coreboot 在 OpenSBI 启动前读取（下次启动生效，固件升级则恢复默认）；提供三种模式——X100 only（默认，8 核、RVV VLEN 256、保留 H 扩展）、X100＋A100（16 核）、A100 only（8 核、VLEN 1024），并在 fastfetch 等工具中按 k3／k3-x100-a100／k3-a100 显示。实现细节：A100-only 引导通过 SBI HSM 将 SEC 从 hart 0 移交 hart 8（等待原 hart 停止后复用栈），UEFI 交接树中禁用 X100 节点但保留物理 IMSIC 槽位编号，设备树根兼容串同步反映模式供用户态命名（无需改 Linux 源码）。主仓侧同步合入 Mesa 26.2.4 升级与 PowerVR（pvr）优化回移、mesa-gallium 推荐 mesa-vulkan-drivers 等 SPECS 更新；openRuyi 官网新闻页暂无新版本（最新仍为 2026.09）。

3.2 奕斯伟计算：开源 RISC-V 矩阵扩展（AME）BF16 GEMM 测试向量库

日期：2026-10-13~10-14　来源：eswincomputing/riscv-matrix-gemm-vectors（10-14 更新）、更新提交（10-14）

奕斯伟计算（ESWIN Computing）开源 riscv-matrix-gemm-vectors 仓库（10-13 建立、10-14 补充版权与 README）：面向 RISC-V 矩阵扩展（AME）规范提案 v0.6.0 的 BF16×BF16→FP32 矩阵乘累加测试向量集——每个用例为裸机程序（执行运算、自校验并写回判决），随附与实现无关的参考值及结果检查器 check.py。判定采用标准舍入误差界（ Ĉ−C* ≤ γ(G)·Σ a·b ，默认 G=K）而非逐位比对，以适配规范允许的「无序求和」实现差异（正负乘积抵消时正确结果可距精确和数千 ULP）；同时提供两个「所有合规实现结果位相同」的用例以检出错误舍入。参考值与判据不依赖具体指令集，可复用于其他矩阵扩展实现，属国内厂商面向 AME 生态的测试基建贡献。

3.3 香山：昆明湖主线优化 L2 访存延迟；验证链（difftest／NEMU／GEM5）持续迭代

日期：2026-10-14　来源：XiangShan #6713：reduce L2 load-to-use latency（10-14）、XiangShan ICache 修复（10-14）、difftest：GBD1 DMA drain（10-14）、NEMU #1251（10-14）、GEM5 #1228（10-14）

香山（kunminghu-v3）窗口内合入 dcache 性能优化——降低 L2 load-to-use 延迟（#6713），并修复 ICache 异常传递（#6414）与取指块末偏移在数据 ECC 场景下的 bank 选择、支持 Zimop（MOP）指令解码（解码为 add rd, x0, x0）。验证与仿真基础设施：difftest 为 GBus DiffTest 增加 GBD1 frozen-bank DMA drain（面向 FPGA 场景）；NEMU 修复 AME 矩阵存储回滚记录（#1251）与 vcompute REM 分支判断（#1253）；GEM5 恢复 macOS 构建并新增手工冒烟 CI（#1228）、对齐 xsstream 活跃区判定（#1223）。XSCache 窗口内无主分支新提交。

3.4 算能：zsbl 启动链重构为两级平台模型；HD12 服务器固件更新

日期：2026-10-14　来源：zsbl：平台子系统与应用拆分（10-14）、mcu：HD12 固件更新（10-14）

算能（SOPHGO）双线更新：zsbl（零级启动加载器） 将平台组织重构为「子系统×应用」两级模型——一个平台可承载多个 CPU 子系统、每个子系统可运行多个引导应用（如 PLAT_SG2044／SG2044_MP／SG2044_MP_ZSBL），各子系统源码移入 plat///，平台级仅保留共用头文件与内存映射，并引入平台级 Kconfig；同时将 PLAT_BM1690TP 更名 PLAT_BM1690（BM1690 为 SoC、TP 为子系统）。**服务器 MCU／BMC 固件（mcu）** 为 HD12 主板合入 **RHS12 板卡兼容、C2C 互连链路（启动／清理与状态检查）、64GB DDR 支持，以及 MCU／BMC 引导日志经 I2C 暴露**（固件版本升至 14）。

3.5 矽速：逻辑分析仪软件 SLogic 发布 v2.3.0，引入共享采集引擎

日期：2026-10-14　来源：SLogic Release release-2.3.0（10-14）、SLogic 提交记录（10-14）

矽速（Sipeed）逻辑分析仪软件 SLogic 次日再发新版：v2.3.0 引入共享采集引擎（要求固件 202610140927 及以上），支持 0% 触发位置（主机侧预触发缓冲）、按链路能力限制采样率并增加链路标签、冷启动计时改为自 RUN 指令起算、修复 Windows 下 ngscopeclient 构建问题；发布说明提供中英双语。配套 ALL-LOGIC 库窗口内 7 笔提交（触发位置、链路限速、调试级别实时速率等）。矽速组织窗口内共 6 个仓库推送（另含 libsigrok、scopehal、pulseview），逻辑分析仪软硬件迭代保持高节奏。

四、具身智能与机器人专章

4.1 端侧 Agent 基建走向「系统级封装」：Bianbu AgentOS 与 K3 的组合交付观察

日期：2026-10-14　来源：bianbu-agent-runtime（10-14）、bibit-voice（10-14）、spacemit-robotics 组织仓库

本窗口具身智能与机器人侧的主要观察点是「端侧 Agent 基建的系统级封装」：进迭时空以 Bianbu AgentOS 名义开封完整链路——桌面前端（BiBit）、运行时、本地记忆、离线语音（KWS／VAD／ASR）与安全组件（见今日重点），且明确以 K3（riscv64）为首发且当前唯一支持平台。对机器人／边缘设备而言，这意味着「语音唤醒—意图理解—工具执行—长期记忆—审计安全」的可自部署开源栈首次在 RISC-V 上有成套样板，而非零散 SDK。配套地，硬件侧 K3 的 CPU 簇模式选择（X100／A100，见 1.3）为「性能核跑推理、能效核跑控制」的异构分工提供了固件级选项。相对地，机器人专项组织 spacemit-robotics 窗口内无新推送（外设 IMU／电机／感知库最近推送为 10-12）；「芯片＋Agent 软件栈＋场景封装」的组合交付仍在深化，软件栈正从「能用」走向「可维护、可审计」。

五、总结与趋势观察

  • 端侧 Agent 成为 RISC-V 软件栈新焦点：进迭时空集中公开 Bianbu AgentOS 全栈（GUI／运行时／记忆／语音／安全），以 K3 先行验证——与蓝芯算力等「服务器化」叙事形成对照，RISC-V 在端侧 AI Agent 基础设施方向出现成套开源栈。
  • 基建两端同时补强：Linux 内核 rva23u64 单比特查询接近落地（Phoronix 报道；v8 部分已进 riscv/for-next、v9 在途），RISE 为 SpeexDSP 补上手写 RVV 向量内核（重采样最高 4.88 倍）——「资格认证（RVA23）＋多媒体性能（RVV）」两条主线同期推进。

  • 国内工程侧高密度输出：达摩院玄铁补 BF16 向量测试、奕斯伟开源 AME 测试向量、香山优化 L2 访存延迟并修 ICache、算能重构启动链与服务器固件、矽速连发 SLogic 两版。
