今日重点：北京印发具身智能机器人三年行动方案，20 万台年产能与 5 万 PFlops 集群把需求侧量化（11-11）

北京市经济和信息化局 11 月 11 日印发《北京市具身智能机器人产业高质量发展行动方案（2026—2028 年）》，自印发之日起实施，有效期至 2028 年 12 月 31 日。文件把此前多轮政策里的方向性表述换成了可考核的数字：到 2028 年培育不少于 5 家国际一流、10 家国内领先的人形机器人整机企业；京津冀区域整机产能占全国 25%，关键零部件配套率超过 60%；在京形成 20 万台／年的整机生产能力；新增建设总规模超过 50000 PFlops 的具身智能专用算力集群，并推动重点企业与算力节点建设单位以「结对子」方式形成算力供需协同。

技术路线写得比以往具体。方案明确支持视觉语言动作模型（VLA）、世界模型（WM）、强化学习等多路线布局与融合，并把攻关拆成「大脑」与「小脑」两侧：大脑侧是多源信息融合、物理空间理解与人类情感识别，目标是让机器人理解物理规律约束、主动识别人的动作与表情等非语言指令；小脑侧是实时推理、跨本体迁移与自学习进化，指向多任务泛化、高可靠执行与超精密操作。制造端给的是一条条硬指标：打造 3 至 5 种国际一流整机平台，整机额定负载达到自重 40% 以上，平均无故障工作时间超过 2000 小时，核心运动部件与末端执行器年故障率低于 10%，设计使用寿命超过 5 年，连续作业工况电池续航 4 小时以上，高自由度灵巧手单只成本降至万元以内。

治理与资本安排同步给足。方案提出构建「一机一码」全过程管理体系，覆盖研发、生产、报废、回收全周期；建立整机企业上市「一对一」服务机制；在整机、关键零部件、具身智能模型与数据采集等领域培育不少于 200 家创新型企业，推动在京高校与科研院所建立 100 个机器人研究团队，并明确反对「内卷式」竞争。这些指标不是凭空定的：工信部 10 月 19 日披露，2026 年上半年国内人形机器人整机产品突破 400 款、产量超 4 万台，预计全年突破 10 万台；中国信通院 10 月报告则给出另一面——上半年公开披露的中标项目中教育科研机构占约 55.5%、政府及公共平台约 20.6%、工业及技术型企业约 21.1%，相当比例设备月均开机天数不足 10 天，整机价格可能只占总拥有成本的 40% 到 60%。

对 RISC-V 这条线，这份方案的价值在于把「需求侧」从愿景变成了采购参数。20 万台／年的整机产能、60% 的关键零部件本地配套率、万元以内的灵巧手，这三条合起来指向的是关节控制与本体算力两级芯片的成本与可靠性：关节侧要的是硬实时、低功耗与确定性网络，本体侧要的是能跑 VLA 推理的算力与内存带宽，且都要在 2000 小时无故障的约束下量产。国内 RISC-V 供给目前能对上这两级的，是进迭时空的 K3 系列（本体算力）、算能的 SG 与 BM 系列（服务器与边缘）、芯来的 N1000／NI1000（实时核与向量矩阵核）以及 MIPS 的 Atlas M8500（关节级实时核，11-09 已报道其 Actus 平台）。5 万 PFlops 的专用集群则落在训练与数据侧，与 PPU、DCU 这类加速卡直接相关。需要说明的是，方案本身没有点名任何指令集或供应商，上述对应关系是供给侧现状的对照，不是政策指定。

RevyOS 内核单窗口 101 笔：K3 显示与 USB3 落地、EIC7700 风扇与热区、SG2044 SRD3 双板入树（11-11）

revyos/linux 仓库的 revyos/7.3.y 分支在本窗口内落地 101 笔提交，按时间分成三个批次。最大的一批在 11-11 13:06（北京时间）前后，主体是平台特性与 FROMLIST 回补：SpacemiT 侧加入 K3 的 GPU 节点与显示电源域、K3 Pico ITX 的 Type-C Port A、USB3 PHY 与 FUSB301 自主控制器、PCIe 在 PHY 初始化后再拉 PERST#、UFS 的 WriteBooster 支持，并关掉 K3 上 amdgpu 的动态 PCIe 速率切换；ESWIN 侧为 EIC7700 补上 hwmon 风扇控制器、PWM、热区节点与 CPU／设备调频，最高频定在 1.4GHz；SiFive HiFive Premier P550 补齐 USB、SATA、PCIe、eMMC 与 SD；T-Head 侧让 Lichee Pi 4A 在交接时保持 USB 供电、为 Milk-V Meles 打开 USB。

芯片平台之外还有一层通用改动。一批 RISC-V 页表访问器相关的 FROMLIST 补丁被整体回补：让页表访问一律走访问器函数、允许访问器非幂等、修正写页表时的内存类型、把 N 与 MT 位在 ptdump 里按使能状态显示、为汇编暴露全部页表位、给 alternative 增加三参数宏与可替换链接寄存器，另外修了 DMA_DIRECT_REMAP 的选择逻辑。KVM 侧把全部计数器暴露给 VS-mode 以兼容 bootloader，并用 XLINUXENVCFG 这个 cpufeature 守护 SENVCFG 访问。

第三批是 14:52 的 defconfig 收口：在昨日报告的六笔基础上扩写为完整矩阵——K1、K3、DP1000、EIC7700、TH1520、SG2042／SG2044 逐个开启，另加 Picoheart errata、common options 与 debian_defconfig，并补上 linuxboot 配置、交叉与原生两套 CI 构建，以及「用大版本号作包名」等打包侧 HACK。三批加起来，这一天的重点不是某个新功能，而是把此前散落在各分支的板级支持收成一套能编译、能出包的组合。

值得单独看一眼的是 SG2044 的板卡线：SRD3-10-LB 与 SRD3-12 两块板的设备树同时入树，SRD3-12 还带一个 large-BAR 变体，并新增第二条 C2C1 x4 PCIe 口、eFUSE 控制器，PCIe 窗口按 EDK2 的实现对齐。对做 RISC-V 服务器整机的团队，板级描述与固件口径一致比多一个驱动更重要——不一致的窗口划分会在多卡场景下直接表现为设备枚举不全。

乐鑫 esp-riscv-trace 0.2.0：RISC-V 指令级 trace 补上 decode／profile／stats／history 四条命令（11-11）

乐鑫把 esp-riscv-trace 推到 0.2.0。这个工具做的事是解码乐鑫 RISC-V 芯片上抓到的硬件指令 trace：读 OpenOCD 产生的 .esptrace 抓包，或读 esp-coredump 生成的、带 trace 备注的 core ELF，重建程序执行流，把每个 PC 解析到函数与源码行，然后输出文本转储、热点表、崩溃前的调用历史，或可直接喂给火焰图的调用栈；连续性丢失的位置标为 gap 而不是猜测填补。0.2.0 新增的四条命令把这套能力从「能抓」推到「能分析」：decode 列出执行过的指令，profile 写出火焰图栈，stats 按源码行统计指令数，history 连同 open_capture 接口一起开放多份抓包的合并与回看。

支持的芯片列表覆盖 ESP32-C5、C6、C61、H2、H21、H4、P4 与 S31，包格式分 Processor Trace 1.0 与 Efficient Trace 2.0 两代。使用方式是在 ESP-IDF 里打开 trace 配置，用 OpenOCD 的 esp riscv_trace start／stop 抓包，panic 后固件会在调试器停机前先停 trace，避免最后一段丢失。

这件事的分量在「RISC-V 端侧的调试可见性」。过去在几十美分的 RISC-V MCU 上做性能分析，基本靠打点和计数；指令级 trace 长期是高档调试器的功能。乐鑫把它做成 pip 可装的 Python 工具，并对外开放读取抓包的接口，等于把「这段代码到底执行了多少条指令、热点在哪一行」变成常规手段。对在 RISC-V 上做推理算子与实时控制的团队，这类工具的边际价值往往高于再提一次主频。

ch32rv-clang：CH32 Arduino 核改用 RISC-V-only clang 与 lld，只编 RISCV 后端（11-11）

社区组织 CH32 RISC-V User Group 发布了 ch32rv-clang：从上游 LLVM 发行版构建、只保留 RISCV 后端的 clang 与 lld，按宿主系统各打一个压缩包，供 ArduinoCore-CH32RV 通过 Arduino 开发板管理器安装。这一版刻意做减法——压缩包里没有 C 库、没有编译器运行时，暂时仍链 xPack GNU RISC-V Embedded GCC 提供的 newlib-nano 与 libgcc；换来的是体积与安装路径的简化：一个根目录、bin 下 12 个工具（Linux 与 macOS 上是单一 multicall 二进制加软链，Windows 上是各自的可执行文件），解压即用。

指令集侧支持 WCH 青稞的 XW 压缩指令，对应 LLVM 19 及以后的 Xwchc 扩展（-march 里带 _xwchc）。哪些核具备 XW 由核心的设备表管理——这一点写得相当明确：QingKe V3A、V4A 这类没有 XW 的核上，一旦执行到第一条此类指令程序就停住，所以不能凭芯片型号猜。预编译覆盖五个宿主：x86_64 与 aarch64 的 Linux、x86_64 与 aarch64 的 macOS、以及 Windows MSVC。版本号按「LLVM 版本-构建号」标注，如 v23.1.5-1，一个标签触发全部宿主的构建并发布带 .sha256 的产物；构建脚本 MIT，归档内的 LLVM 为 Apache 2.0 with LLVM Exceptions。

对这条产品线，换编译器不是目的，降低上手门槛才是。CH32V003 这类十美分级别的 RISC-V MCU 过去在 Arduino 生态里依赖 GCC 工具链，版本与安装步骤都比较脆；把 LLVM 的 tar 包接进开发板管理器后，「装不上工具链」这个最常见的劝退点被消掉了一半。

NEMU 四笔：SMBLOCKCTL 加 PF 刷新位、RVV 零长访存置脏 VS、AME 矩阵快路径（11-11）

NEMU 在本窗口落地四笔。功能侧，SMBLOCKCTL 增加了 PF 刷新使能位（#1285），把这一控制位从保留位变成可配置行为；RVV 侧修了零长度 gather、slide 与 mask 类操作未置脏 VS 的问题（#1286）——向量状态脏位漏标在虚拟化场景下会让宿主误判上下文是否需要保存，属于典型的「只在特定指令组合下才暴露」的缺陷。MMU 侧修了第二页非规范地址时应当报告下一页基址的问题。

性能侧一笔更值得注意：共享 ref 中启用矩阵 load／store 的快路径（#1284）。AME 是香山系的矩阵扩展，这一年里 NEMU 对它的支持从指令语义补齐走到访存路径优化，说明矩阵单元在模拟器里已经跑得够多、性能成了瓶颈。同日 difftest 侧也有两笔配合动作：nightly 工作流去掉 Firtool 发行版的 latest 标签（#1040），以及把 MMA 的 CPU 校验向量化并复用已解码操作数（#1038）。

把这几笔连起来看，验证基础设施的重心正在从「功能对不对」转向「跑得够不够快」。矩阵扩展带来的状态量与时序复杂度，让纯软件参考模型的吞吐成为回归时长的决定因素；性能快路径与校验向量化是同一个方向上的两个动作。

日期：2026-11-11　来源：OpenXiangShan/NEMU、OpenXiangShan/difftest

openRuyi-Project 新建 ruyi-deck：面向仓库与发布的运维台（11-11）

与 RISC-V 的关系需要再说一次，因为这个口径已经被媒体重复了三轮：本次上市主体是平头哥，产品重心是 PPU（AI 加速卡）与倚天（Arm 服务器 CPU）；玄铁 RISC-V 处理器 IP 已于 2024 年从平头哥分拆、转属达摩院，只做 RISC-V 处理器。媒体在盘点平头哥产品矩阵时常把「玄铁 RISC-V IP 累计出货突破 60 亿颗」一并计入，那是集团层面的历史沿革口径，不等于上市资产包含 RISC-V IP 业务。本刊 11-10 与 11-11 两期已作同样区分，本期只记公告与定价区间这两项新增事实。

真正决定估值的不是叙事而是招股书里的两个切分：百亿级年化营收中，来自阿里云供货与集团外直接采购各占多少；部署在阿里云万卡集群里的芯片，按市场公允价结算还是内部调配。前者决定市场按「独立芯片公司」还是「阿里云成本中心」定价，后者决定剥离母体后的毛利率成色。小比例发行、分拆后仍保持控股的做法，本质是先要一个公开市场的定价锚，把后续资本运作的空间留住。

香山昆明湖 V3：TLB 一次重构 18 笔，权限检查与 PTW 旁路收敛到单一出口（11-11）

香山 XiangShan 的 kunminghu-v3 分支在本窗口落地 21 笔，其中 18 笔是同一天、同一时间戳的 refactor(TLB) 系列。这 18 笔没有一笔改行为，全部是结构治理：给 TLB 读结果与 PTW 旁路结果字段命名、共享动态 VPN 索引选择、把 S0 地址准备与前置检查抽成独立步骤、复用 TLB 存储查询与响应接口、把权限与 PBMT 检查抽到 TLB 源内、在 pre-fault 覆盖之前先赋权限结果、按端口聚合访问检查信息、复用权限 bundle 并去掉未用的 G-stage 有效位。

减法同样彻底：删除未使用的 blocking TLB 支持、TLB 存储脚手架、saveLevel 配置、partialStaticPMP 参数与 L1 侧辅助函数；把 TLB refill 的连接收敛成一次，把翻译阶段的选择集中到一处，并简化 TLBFA 的命中响应选择。另有三笔非 TLB 提交：修 MissQueue 里 CMOUnit 的通道选择（#6907）、重组 ROB 的 bundle 组织并厘清 IO 分组（#6881）、给 CI 的 EMU Basics 加上 ISA 冒烟测试（#6805）。

进迭 ai-sdk 与 model-zoo-vision：推理线程改按 TCM 核预算分配（11-11）

进迭的 ai-sdk 与 model-zoo-vision 两仓同日更新。ai-sdk 合并了新增 file2md 组件的改动（#12），并同步 avatar 与 vision 两个子模块；model-zoo-vision 的关键一笔是把推理执行提供者的线程数改为按 TCM 核预算分配（#117）——此前线程数大概按 CPU 核数或固定值给，现在由紧耦合存储的预算反推可用线程，避免推理线程与实时任务抢同一块片上内存。

这个改动看起来是参数调整，实际是端侧部署的常见坑：TCM 是有限的、按核划分的资源，推理线程开多了会挤占实时控制或显示通路的片上空间，症状是偶发卡顿而非报错。把线程数绑定到 TCM 预算，等于把这个隐性约束写进配置层。

file2md 组件的加入则透露 SDK 的方向：把文档转 Markdown 这类「AI 应用前置处理」也收进统一组件，而不是让每个应用自己接一遍解析器。对做端侧文档问答与多模态应用的团队，这类组件的价值在于减少重复集成。

五、总结与趋势观察

一、政策把具身智能的需求侧量化，RISC-V 的机会在关节与本体两级。 北京这份方案给出的 20 万台／年整机产能、60% 关键零部件本地配套率与万元以内灵巧手，本质是把「用什么芯片、什么成本、什么可靠性」写成了采购参数。关节侧要硬实时与确定性网络，本体侧要能跑 VLA 的算力与带宽，两级都不是靠单颗大芯片解决。国内 RISC-V 供给在这两级都已经有可对照的产品，接下来的竞争点不是峰值算力，而是能不能在 2000 小时无故障的约束下把成本压到整机厂愿意换料。

二、发行版这一天的关键词仍是「可交付」，但做法从补丁转向矩阵。 RevyOS 一日 101 笔，重心是把 K3、EIC7700、SG2044、TH1520 与 P550 的板级支持收成 defconfig 矩阵并接上交叉／原生两套 CI；openRuyi 一日 36 笔，把可观测性与认证两条供应链同时收口，并把内核升到 7.3.4／6.18.63。两家做的都不是新功能，而是「别人能不能编译出来、敢不敢放到生产」。

三、验证与可观测性成为工具链竞争的新前线。 NEMU 给 AME 矩阵访存加快路径、difftest 把 MMA 校验向量化、香山给 CI 加 ISA 冒烟测试、乐鑫把指令级 trace 做成 pip 可装的四条命令——四个动作指向同一个判断：核与扩展复杂到一定程度后，瓶颈从「设计对不对」转向「能不能快速看清它在做什么」。这条线上投入不足的团队，会在集成阶段付出成倍的时间。

四、香山的 18 笔纯重构说明高性能核进入结构治理期。 能对一个模块做「只动结构不动行为」的批量重构，前提是回归面足够密、行为已稳定。TLB 与 PTW 是访存路径上最难调试的一段，把权限检查与旁路结果收敛到单一出口，是在为后续扩展留接口。这类工作不出现在任何性能数字里，但决定下一代核加特性时的改动成本。

五、资本侧的定价锚摆上台面，但资产边界仍待披露。 阿里公告拟分拆平头哥赴港、港交所确认可拆分，估值区间从 200 亿至 300 亿美元到 250 亿至 620 亿美元不等。对做 RISC-V 的公司，这件事的参考价值不在估值数字，而在招股书将如何切分外部收入与关联交易——同一套标准很快会被用来衡量所有国产算力芯片公司，包括还在亏损期的 RISC-V 服务器与 IP 厂商。
