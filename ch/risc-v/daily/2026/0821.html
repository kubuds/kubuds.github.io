一、开源社区与内核/版本动态

1.1 Linux 7.2 发布盘点：RISC-V 侧 NR_CPUS 提升至 256、奕斯伟进入 defconfig（08-21）

日期：2026-08-16（内核发布，LKML）／2026-08-21（CNX 架构级盘点报道，06:00 北京）　来源：CNX Software、Linux Journal

Linus Torvalds 于 08-16 发布 Linux 7.2（LKML），CNX 于 08-21 出架构级盘点，RISC-V 侧更新密集。通用亮点：cache-aware 任务调度（同进程线程按 LLC 域共置）、受 CFS 启发的 Fair GPU 调度器、USB4STREAM 直连流式传输、swap table 第四阶段。RISC-V 专项：

  • NR_CPUS 64 位默认值提升至 256——官方理由直指国产多核机器：进迭时空（SpacemiT）已产 80 核 RVA23 服务器，双路 SG2042 的算能 Pisces 达 128 核，默认 64 已不够；
  • 奕斯伟（Eswin）SoC 加入 RISC-V defconfig——国产厂商进入主线默认配置，合入门槛高于普通驱动；
  • 平头哥 TH1520：PWM 修复，BeagleV Ahead、Lichee Pi 4a 两块板开启 WiFi；
  • 进迭时空：K1 增加 SPI/thermal 驱动与 I2C 使能、K3 增加 USB2 PHY 与 ASoC 驱动、P1 芯片补 reboot cell；K1 板级外设大量使能（Milk-V Jupiter eMMC、Muse Pi Pro EEPROM/PCIe/QSPI/USB、OrangePi R2S PMIC/USB3、OrangePi RV2 全外设）；新增 CoM260-IFX 与 DeepComputing FML13V05 两块 K1 板；
  • 算能：Milk-V Duo S 增加 bindings；SG2042/SG2044 设备树修正（CPU 地址改十六进制、MSI 实际仅 16 中断、PCIe RC 标记缓存一致性）；
  • 赛昉：JH8100 中断控制器因该芯片未量产即停产，改名重做为 JHB100 版；JH7110 加入 SiFive ccache 非标准 cache 操作名单（GPU DMA 非一致）；JHB100 新增 clint 绑定与 SGMII GMAC 支持；
  • 核心修复：kexec_file 大内存早期启动、无条件 sfence.vma、kfence 误报修复、CFI vDSO 补丁、ftrace_graph_ret_addr、BUILDTIME_MCOUNT_SORT 降低启动开销等。

7.3 merge window 已随发布开启（Linus 称已有 40 个待合入 PR）；Phoronix 报道 7.3 将大规模淘汰旧 32 位 ARM 平台（ARM 侧重构，对 RISC-V 影响待观察）。本次盘点印证：Linux 主线正为”80-128 核国产 RISC-V 服务器”批量铺路。

1.2 NetBSD 11 落地 64 位 RISC-V 支持（08-20）

日期：2026-08-20（The Register 报道 21:45 北京；HN 同步）　来源：The Register、HN 讨论

NetBSD 第 19 个主版本 11.0（07 月底发布）获 The Register 长篇评测：新增 64 位 RISC-V 支持（Tier II 平台，面向 QEMU 虚拟化环境），使 NetBSD 成为继 Linux、FreeBSD 之后又一对 RISC-V 提供主线支持的 BSD 系操作系统。11.0 同时带来：MICROVM 专用内核（x86 客户机约 10 毫秒冷启动，2020 年代处理器实测）、POSIX.1-2024 与 C23 合规提升、Linux 系统调用兼容增强、Xen/QEMU 运行优化、52 个 Tier II 平台与 9 个 Tier I 平台。评测同时指出 NetBSD 保持”老派”风格：sysinst 文本安装器、需手改 /etc/rc.conf、商业驱动稀少。对 RISC-V 生态的意义：BSD 阵营的 RISC-V 支持补齐，虚拟化场景（QEMU）先行落地。

二、产品与生态动态

2.1 Andes 关闭 Condor 设计中心，Cuzco 数据中心级核心 IP 回归母公司（08-17/08-20）

日期：2026-08-17（Jon Peddie Research 首曝）／2026-08-20（EE Times 跟进报道，06:00 北京）　来源：Jon Peddie Research、design-reuse 转载、EE Times

晶心科技（Andes Technology）正式关闭其美国德克萨斯州奥斯汀的高端设计中心 Condor Computing（2023-03 成立，近 100 人、85% 以上为研发）。Condor 承载 Andes 冲击数据中心级 RISC-V 的旗舰项目 Cuzco 核心——RVA23 合规、可授权，采用新型专利微架构（深度乱序执行 + 非常规时间调度设计，Hot Chips 2025 公开）。现状：Cuzco IP 回归 Andes 母公司，无后续 test silicon 开发；团队从 50 人砍至 15 人、再缩至个位数真正理解该 IP 的工程师；原 CEO Ty Garibay 已转任 Ambiq 的 SoC Design VP。关闭属 2026-04 公布的成本削减计划一部分：董事长兼 CEO Frankwell Lin 承认过去三四年扩张过快、营收未匹配，计划削减运营开支 10-20%、全球员工从 480 降至约 450（EE Times 估计当前已约 400）。

产业意义：Jon Peddie Research 分析师 David Harold 直言，这是”对 Andes 高端野心的挫折，也是 RISC-V 在数据中心建立 Arm/x86 可信替代努力的一次退却”。与 1.1 中 Linux 主线为多核服务器铺路形成对照——软件侧在加速，IP 供应商阵营却在洗牌收缩。

三、国内团队动态与深挖

3.1 香山：24 小时 20 笔提交，WritebackQueue 与 TAGE 性能优化（08-20）

日期：2026-08-20（10:59 ~ 次日 01:32 北京，committer 时间）　来源：OpenXiangShan/XiangShan、XiangShanLab、env-scripts

香山组织窗口内共 20 笔提交，主仓库（XiangShan）落 4 笔实质提交，性能向迭代明显：

  • timing(WritebackQueue): use lowestIndexFirst policy (#6379)（08-20 10:59 北京）——写回队列改 lowest-index-first 调度策略，访存后端时序优化；
  • build: generate CHIRRTL only for gsim (#6374)（11:36）——构建系统精简（CHIRRTL 仅 gsim 生成）；
  • perf(Tage): optimize UseAltOnNa (#6328)（17:24）——TAGE 分支预测器 UseAltOnNa 策略优化；
  • fix(uart16550): expose DesignWare status register (#6385)（08-21 01:32）——UART 状态寄存器透出，调试与板级可用性改进。

配套仓库：XiangShanLab 新增 xs bug replay 脚本（按 commit hash 回放 bug）、env-scripts 的 perf_trigger 两笔修复（#154/#155，运行时分析日志增强）。连续多日高强度合入，本轮重心从访存正确性转向写回队列调度与分支预测的性能微调，属于架构性能收尾期特征。

3.2 进迭时空：K1 软件栈 v2.2.11 版本更新（08-20）

日期：2026-08-20（09:07 ~ 17:25 北京）　来源：spacemit-com/buildroot-ext、uboot-2022.10、mpp、v2d-test

进迭时空组织窗口内 22 笔提交，核心是 K1 软件栈 v2.2.11 版本整包更新：buildroot-ext、uboot-2022.10、v2d-test 同步至 v2.2.11，其中 K1 buildroot 将 GENERIC_HOSTNAME 改为 “K1-Buildroot” 并将根文件系统扩至 1GB（适配更大软件集）；mpp 媒体管线两笔工程化重构（stream manager 移出 mpi 接口层、AL module 构建目标拆分），v2d-test 修复 K1 buildroot 构建错误。延续 08-18 已报道的”K1 主线内核 7.2 经 meta-riscv 落地 Yocto”节奏，本轮为 BSP 整包版本化交付，媒体管线在向可独立维护的模块结构演进。

五、总结与趋势观察

  1. Linux 7.2 是国产多核 RISC-V 服务器的主线里程碑：NR_CPUS 默认提至 256（点名 SpacemiT 80 核、Sophgo Pisces 128 核）、奕斯伟进入 defconfig、进迭 K1/K3 外设大规模使能——主线与国产高端 SoC 的耦合明显加深；
  2. 数据中心级 IP 阵营洗牌：Andes 关闭 Condor、Cuzco 回归母公司，是继 SiFive 收缩后的又一信号；高端 RISC-V 核心竞赛的”中国双雄”（平头哥/赛昉）权重进一步上升，软件侧铺路与 IP 侧收缩并存；
  3. BSD 生态补齐：NetBSD 11 提供 64 位 RISC-V 主线支持，主流开源 OS 对 RISC-V 的覆盖再下一城；
  4. 国内团队节奏分化：香山（性能微调期）、进迭时空（v2.2.11 整包交付）高活跃；平头哥/芯来/赛昉/奕斯伟仓库静默，但奕斯伟的合入动作在主线 defconfig；
  5. 平静日说明：gnews 中文查询窗口内为空、厂商英文查询多为已报道事件，国内动态主要靠 GitHub 组织检索捕捉（见附录核查表）。

局限性说明：Linux 7.2 RISC-V 变更以 CNX 转述为准、未逐条核对内核 changelog；Andes 关闭细节（团队规模、headcount）以 EE Times/JPR 报道口径为准，未经 Andes 官方确认（官方未发正式公告）；NetBSD 11 为 The Register 评测视角，RISC-V 端口属 Tier II（QEMU）而非 Tier I 实机；香山/进迭提交按 committer 时间归类，个别提交的 author 日期可能早于窗口。
