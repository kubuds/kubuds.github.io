今日重点：UPC 研究：用玄铁 C910 与片上性能计数器让 RISC-V 芯片「自检」微架构攻击，检出精度 99%

日期：2026-09-24　来源：Scienmag《Machine Learning Turns RISC-V Chips Into Their Own Hardware Attack Detectors》、论文：Pou, Otero, Robledo, Pajuelo & Canal, RISC-V hardware attack detection using on-chip hardware performance counters, Cybersecurity 9(1) Article 222、HARPY-V 数据集（CORA 研究数据仓库）

9 月 24 日，Scienmag 刊发西班牙加泰罗尼亚理工大学（UPC）团队的研究报道：研究者把机器学习检测器「装进」RISC-V 芯片自身的硬件性能计数器（HPC），实现在芯片内部对微架构攻击的实时检测，论文发表于期刊 Cybersecurity（9(1) 第 222 篇）。实验在真实商用硅片上完成——达摩院玄铁 C910（64 位乱序核，RV64GCV）搭载于矽速 LicheePi 4A 开发板、运行 Debian 13；团队构建并公开了数据集 HARPY-V：约 6.4 万条标注样本，含 16 种微架构攻击（Flush+Reload、Flush+Flush、Evict+Reload、Spectre V1/V2/RSB、计时漂移、TLB 与页表遍历类攻击，以及 GhostWrite 等）与 16 个良性程序，良性集刻意选用与攻击共享硬件结构的负载，使分类问题接近真实难度。

结果与工程细节：二元检测（攻击／良性）精度达 99%，多分类（区分具体攻击类型）约 95%；在「留一攻击」零日模拟中，随机森林配合 mRMR 特征选择、决策树配合 RFECV 的组合仍保持高检出率，而「选对计数器」比「堆更多计数器」更关键。团队还公开了两条珍贵的实测经验：在 C910 上，perf 同时监控多个计数器会相互干扰（部分读数被放大 3 倍以上），必须逐计数器单独采集；且 C910 的 perf 事件描述大多不准确，须以官方手册的计数器映射为准。

意义与边界：这是首批以商用 RISC-V 硅片（而非 FPGA 软核或模拟器）为平台、并公开可复现数据集的微架构攻击检测研究之一，「用芯片自带计数器加轻量模型做主动检测」是一条不需要改硅、不需要内核补丁的低成本加固路线，与 RISC-V 开放生态的安全叙事相呼应；同时需注意边界——实验仅覆盖单一核心型号，计数器模式与微架构强相关、跨芯片需重训练；监督学习依赖已标注攻击数据，对全新攻击类型的泛化仍待验证。

2.1 乐鑫 ESP32-S31 的 Linux 移植升温：从单片机迈向 SBC 形态

日期：2026-09-24　来源：XDA《The newest ESP32 can actually run Linux, and it’s getting uncomfortably close to a Raspberry Pi》、CNX Software：ESP32-S31 Linux BSP 开发者预览（08-22）

XDA 刊发专题讨论乐鑫 ESP32-S31：双核 32 位 RISC-V 主核（最高 320 MHz，另带 40 MHz 低功耗核）加上首个内置 Sv32 MMU 的 ESP32，硬件上还具备千兆以太网 MAC（RGMII）、USB 2.0 High-Speed OTG 主机、双槽 SDIO、DVP 摄像头输入与并行 LCD 控制器——外设组合已接近现代单板计算机。官方已于 8 月发布 Linux BSP 开发者预览（Buildroot 2025.02 + U-Boot + Linux 6.18 分支，整机镜像约 13.7MB）；社区移植同步推进：GrieferPig 的 Linux 6.12 supervisor 模式移植（约 15MB 可用内存、CoreMark 约 1059），以及基于 Linux 7.1 + OpenSBI 1.9、可驱动 800x480 LCD 控制台的另一移植。XDA 的判断：S31 的外设、带宽与 CPU 特权模型都已「靠近 SBC」，但 Linux 支持仍属实验性质，短期内不建议用于生产。

2.2 算能 BM1688 新单板 OrangePi O1 公布：16 TOPS TPU 加 RISC-V C906 协处理器

日期：2026-09-24　来源：LinuxGizmos《16-TOPS AI SBC with SATA 3.0 runs on octa-core Sophgo BM1688》

LinuxGizmos 刊发 OrangePi O1 单板（90×70mm）详情：基于算能（SOPHGO）BM1688 视觉计算处理器——8 核 Arm Cortex-A53（最高 1.65GHz）加 RISC-V C906 协处理器（最高 1.2GHz），内置 TPU 提供 INT8 16 TOPS／INT4 32 TOPS／FP16-BF16 约 4 TFLOPS，支持 Caffe、PyTorch、TensorFlow、ONNX、MXNet，定位边缘侧大模型与视觉模型推理。板上配置：8/16GB LPDDR4X、eMMC（16-128GB 可选）、M.2 NVMe（PCIe 3.0）、SATA 3.0、双千兆网口、Wi-Fi 6E／蓝牙 5.3、可选 4G/5G 模块、HDMI 2.0 4K60、双 MIPI-CSI 与 6 路视频输入；支持 16 路 1080p30 解码。BM1688 内嵌 RISC-V C906 协处理器，是这款以 Arm 为主核的边缘 AI 芯片的「RISC-V 内芯」，也是国产 RISC-V 厂商在多核异构 AI 芯片路线上的一类典型形态。

4.2 加州大学伯克利分校发布 IISWC 2026 教程：异构 RISC-V SoC 上的 ML 与机器人负载

日期：2026-09-24　来源：ucb-bar/IISWC-tutorial-2026-RISCV-ML-Robotics

加州大学伯克利分校（ucb-bar）发布 IISWC 2026 教程的微站仓库：《Building, Tracing, and Optimizing End-to-End ML and Robotic Workloads on Heterogeneous RISC-V SoCs with a Lightweight Zephyr Runtime》——围绕在异构 RISC-V SoC 上以轻量 Zephyr 运行时构建、追踪与优化端到端机器学习与机器人负载。教程把「机器人负载方法学」（构建、追踪、优化）作为独立议题组织，显示学术侧对 RISC-V 机器人与 ML 工作负载的研究正在体系化。

五、总结与趋势观察

  • 安全研究进入「可复现」阶段：UPC 以玄铁 C910 商用核与公开数据集完成微架构攻击检测研究，RISC-V 安全叙事从「单点漏洞披露（GhostWrite 等）」推进到「量化检测加数据集共享」；对国产核而言，被选为实验平台既是关注度提升的体现，也提示商用硅片需要主动检测方案。
  • 端侧 AI 软硬件同步补强：ESP32-S31 的 Linux 化尝试、BM1688 新单板、进迭时空 llama.cpp v0.2.0 与乐鑫 esp-vision，共同指向端侧推理从「能跑」到「好跑」的工程化阶段；RISC-V 在 MCU 到边缘盒子的形态边界继续扩张。
  • 开源社区双线节奏：香山在多分支上并行推进向量、预测与缓存微架构调优，开发密度维持高位；openRuyi 本周以安全更新与打包规范为主，等待 2026.09 发布窗口。
  • 具身智能分层推进：灵龙合入 SONIC 运动跟踪策略后，机器人软件栈按「运行时接口、策略资产、仿真闭环」三层持续沉淀；配合 IISWC 教程等学术活动，RISC-V 机器人负载的方法学建设在产业与学术两侧同步展开。
  • 观察点：openRuyi 2026.09 是否发布；ESP32-S31 官方 Linux BSP 由开发者预览转正的节奏；进迭时空 ggml-spacemit 后端的上游化动向。
