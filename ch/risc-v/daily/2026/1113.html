今日重点：达摩院玄铁发布 XL-300 吞吐型互联 IP，8 核异步连接配 32MB 可配 L3（11-12）

IT之家 11 月 12 日上午报道，阿里巴巴达摩院旗下 RISC-V 品牌玄铁（XuanTie）发布高吞吐缓存一致性互联 IP 设计 XL-300。报道给出的规格是：最多支持 8 个核心的异步连接，数据位宽 256bit，L3 Cache 最大可配置到 32MB，8 核并发线性度达到 90% 以上，带宽上限相比前代 XL-200 提升约一倍。新增的 Direct Memory Transfer 支持被单独点出，作用是绕过传统路径，突破大容量 L3 与高总线延迟带来的吞吐瓶颈。驱动之家、凤凰网科技、新浪科技与搜狐在同日转载了同一条消息，内容一致，均为 IT之家口径。

这条消息的分量不在单点参数，而在「互联 IP」这个位置。RISC-V 这几年在单核性能、向量与矩阵扩展上的进展是可验证的，但要把多颗核拼成一颗可用的 SoC，拼的是缓存一致性协议、跨核带宽与延迟、L3 的容量与分区策略——这部分过去是 Arm 与 x86 生态靠多年迭代堆出来的护城河，也是国内 RISC-V 服务器芯片最容易在硅后暴露问题的地方。玄铁把 XL-300 的三个指标摆在最前面（8 核异步连接、32MB L3、90% 线性度），指向的正是「多核能不能真的跑出多核性能」这个最朴素的问题。8 核并发线性度 90% 意味着第 8 颗核带来的边际收益仍有第一颗核的九成，这个数字比峰值带宽更能说明一致性协议与总线仲裁的实际水平。

需要把时间线摆清楚，避免把旧产品读成新品。XL-300 并非首次露面：今年 3 月一篇 C930 深度解析文章里，玄铁技术负责人已经把它列为与旗舰服务器核 C930 搭配的最强互联 IP，当时给出的口径是单 Cluster 最多 8 核、L3 最大 23MB、相比 XL-200 频率提升 20% 且带宽翻倍、面积仅增加 5%。再往前，2025 年 2 月的玄铁生态大会上，XL200 还只是「将提供更大规模、更高性能的多簇一致性互联」的研发计划。也就是说，XL-300 的定位是 C930 这一代服务器级 IP 的配套互联，本期报道带来的是更完整的对外规格披露。

两处口径差异值得记下来。其一，L3 容量：3 月的说法是最大 23MB，本期报道是 32MB。二者可能是不同配置档位（单 Cluster 与多 Cluster、或不同工艺库下的 SRAM 容量），也可能是规格随迭代上调，官方尚未发布可核对的规格书，本刊按两条独立口径并列记录，不取其中一条覆盖另一条。其二，本期报道用「发布」而非「量产」或「授权落地」，与 3 月「已与 C930 配套」的表述并不矛盾——IP 的对外发布、客户授权与硅上验证是三个不同阶段，报道本身没有披露授权客户数量。

对产业观察者，更有价值的问题是这条线接下来往哪走。玄铁的 XT-Link 系列从 2024 年 7 月的 XL100（首款缓存一致性多 Cluster 互联，8 至 32 核扩展、支持大小核）走到 XL200、再到 XL300，节奏大致是一年一代，每一代的着力点从「能不能连」转向「连得多快」再到「大 L3 下的吞吐效率」。这条路径与 C930 的 SPECint2006 15/GHz 级别单核性能是配套关系：单核越强，对互联的带宽与一致性要求越高，否则多核只是把瓶颈从执行单元挪到总线上。国内做服务器与高性能 SoC 的团队若采用玄铁核，互联 IP 的可选范围与授权条件，实际决定了他们能不能做出 32 核以上的机型。

一、开源社区与软件生态

香山昆明湖 V3 三笔：ROB 拆分功能与调试缓冲、FP 发射队列接入 topdown 计数器、BJU 补 isRVC 元数据（11-12）

香山昆明湖 V3 分支在窗口内落地三笔，分属三个方向。第一笔是重排序缓冲（ROB）的结构治理：此前 ROB 为每个槽位无条件保存一份完整的入队 uop，放在 debug_microOp 字段里；名字虽为调试，异常处理与 VLS 处理也在读它，导致正常 RTL 依赖了一个只该用于调试的结构。改动引入 RobSlotInfo，只保留正常 RTL 真正需要的三个字段（commitType、fuType、fuOpType）存入 slotUopBuf，把调试用的整份拷贝剥离出去。这类改动的收益不在周期数，而在面积、时序与后续扩展成本：一份多余的宽位向量在 ROB 里躺了若干代，每加一个字段都要跟着放大。

第二笔是把浮点发射队列与 ROB 的 topdown 计数器接通：把浮点发射活动与队列状态报给 topdown 采集器，包含发射取消的来源；整数与浮点发射队列的状态一并喂进 ROB 头部分类，浮点已发射 uop 计入发射计数；取消来源历史按所有编码来源分配长度，并只在 ROB 头被归类为发射取消时更新取消时间。第三笔是修复：JumpUnit 在预测错误或后端故障时创建后端重定向，但把重定向 bundle 清零，没有把 io.in.bits.ctrl.isRVC 赋给 redirect.isRVC，结果压缩跳转指令（如 c.jr）的后端重定向里 isRVC 被清成 false，影响后续对指令长度的判断。

三笔连起来看是一次典型的「结构治理 + 可观测性补齐」组合。topdown 计数器的意义在于把「流水线为什么空转」从经验判断变成可归因的数据：前端取指不足、后端发射阻塞、还是 ROB 满导致的停顿，各自有独立计数。对香山这类要跑 SPEC 与真实负载的开源核，能不能快速定位瓶颈决定了迭代速度；而 ROB 拆分与 isRVC 修复这类工作不产生任何性能数字，却直接决定加新特性时的改动半径。

openRuyi 五笔：LLVM 23 升 23.1.5，双内核补丁与配置刷新，gcab 与 OVMF 的 fwupd 支持入树（11-12）

openRuyi 主仓在窗口内落地五笔，全部集中在 SPECS 目录，时间跨度从上午 9 点 13 分到 11 点 27 分。第一笔把 llvm23 升到 23.1.5，这是本月内 LLVM 23 分支的又一次补丁级跟进。随后两笔由同一位提交者完成，分别刷新 linux 与 linux-lts 的补丁集与配置——注意是「refreshing patchset」与「refresh config」两件事一起做，意味着下游维护的那批 RISC-V 补丁要跟着新基线重排，同时内核配置项也要重新对齐；这种成对刷新往往发生在内核稳定版小版本更新之后，是发行版保持可编译的必要动作。

第四笔新增 gcab 软件包。gcab 是 GNOME 阵营的 Cabinet 文件（.cab）读写工具，本身很小，但它出现在依赖链上通常意味着某个上层组件需要处理固件或驱动包。第五笔正好印证：ovmf 增加对 fwupd 的支持。fwupd 是 Linux 上的固件更新守护进程，走到 OVMF（UEFI 固件）这一层，说明 openRuyi 在把「固件可更新」做成发行版能力，而不是让用户手工刷写。对 RISC-V 平台这是一条容易被忽略但很实际的需求：板卡厂商的固件发布节奏与发行版不同步，有 fwupd 通道才能在不重装系统的前提下推 BIOS 与固件修复。

把五笔放在一起看，openRuyi 这个窗口没有发布新版本，也没有大功能，做的是「把上游基线跟住、把固件更新链路补齐」。这与它 10 月两篇公告（Ruyi Firmware 提供开放 UEFI 固件方案、生态基础设施定位）是一条线上的延续：固件方案讲的是「怎么开放地启动」，fwupd 支持讲的是「启动之后怎么持续修」。

difftest 两笔：镜像解码与 RAM 加载分离、gsim 构建去掉 tee 管道（11-12）

difftest 仓库窗口内两笔改动都在工程层。第一笔把镜像的解码与 RAM 加载两个步骤分开：此前加载一个镜像时，解析格式与写入内存耦合在同一段逻辑里，改动引入独立的解码阶段，让「读得懂镜像」与「装得进内存」各自可测、可替换。对差分测试框架，这类解耦的价值在于新增镜像格式时不必碰内存布局代码，反之调整内存模型也不影响格式解析。

第二笔修复的是一个很容易被忽略的构建陷阱：gsim 的生成规则里写了 gsim-gen-cpp ... | tee gsim-gen-cpp.log，而 Make 默认没有设置 -o pipefail，管道的退出码取的是 tee 的状态，永远是 0。结果是 gsim-gen-cpp 因 bug 或 OOM 被杀掉时，make 仍然继续调用 gsim-gen-emu，最后以一个令人费解的 SimTop.h not found 报错收场。改动直接删掉内部 tee，理由写得很清楚：verilator.mk 没有这么做，用户想留日志可以自己在命令行外层加管道。这是那种「修一次省掉后来每个人半小时」的提交。

乐鑫 22 仓批量推送：模组库、视频与语音组件、芯片 errata 同批更新（11-12）

乐鑫（espressif）在窗口内有 22 个仓库出现推送，是整个窗口内组织级推送最密集的一家。清单可以分成几类：主机侧与云侧有 esp-hosted-linux、esp-cloud-common；芯片配套有 esp-chip-errata、esp-phy-lib、esp-coex-lib、esp-hal-3rdparty、usb-pids；无线与蓝牙模组库有 esp32s31-bt-lib、esp32h4-bt-lib；多媒体有 esp-video-components、esp-vision、esp-gmf；框架与工具有 esp-matter、esptool-js、idf-eclipse-plugin、esp-board-manager、esp-idf-security-dashboard、homebrew-eim；另有 esp-claw（2379 星）、esp-ptp、developer-portal、musl。

这类同日多仓推送在乐鑫身上是常态，属发布列车与上游同步，本刊不逐条拆分。值得留意的是媒体与蓝牙两条支线仍在扩：esp-video-components、esp-vision 与 esp-gmf 三个仓同时动，说明端侧视觉与音频链路还在补组件；esp32s31-bt-lib 与 esp32h4-bt-lib 出现在同一批，则是新芯片配套库在跟进。对用 ESP32-C 系列（C2/C3/C5/C6/C61，RISC-V 内核）做产品的团队，这些库的更新节奏基本决定了新模组能不能第一时间拿到可用固件。

二、产品与生态动态

Start9 推出 RISC-V 路由器：进迭时空 K1 八核、StartWRT 发行版、300 美元（11-12）

开源软硬件厂商 Start9 在 11 月 12 日正式发布其 RISC-V 路由器，与深度数智（DeepComputing）联合打造，主控是进迭时空 K1（八核 64 位 RISC-V），运行基于 OpenWrt 的 StartWRT 发行版，定价 300 美元（约合人民币 2006 元），随附一台 TP-Link 四口交换机。硬件配置为 4GB LPDDR4 内存、16GB eMMC 存储，无线走一块可更换的 miniPCIe 模块（AsiaRF AW7916-NPD，Wi-Fi 6E，2.4GHz 与 5GHz 并发，外置天线），外部接口为 1 个千兆 WAN、1 个千兆 LAN、2 个 USB 3.0 Type-A、1 个 USB-C 与 microSD 读卡器。

Start9 官方页面把「开放到什么程度」写得很细，这一点比参数更有参考价值。公开的部分包括：RISC-V 指令集本身、这块板所衍生的 K1 参考原理图（已随文档发布）、启动栈 OpenSBI 与 U-Boot、Linux 内核与 mt76 无线驱动、以及 MIT 许可的 StartWRT；不开放的部分也点名了——无线射频固件（厂商不提供开源固件，模块可拆、拆了照样能跑），以及上电时执行一次的两段早期二进制（DRAM 初始化与一阶段引导），后者正在替换中。这种「把不能开源的部位逐个列出来」的做法，在开源硬件产品里比笼统宣称「完全开源」更有可信度。

产品定位也值得说明：这台路由器的卖点不是吞吐，而是「每个设备走哪条隧道由你决定」——按配置文件分流、可串联两家 VPN 使单一供应商无法同时掌握身份与去向、每套配置独立指定 DoH 解析、网络层做设备隔离。这类需求过去由 x86 小主机加 OpenWrt 承担，功耗与体积都不理想；换成八核 RISC-V 之后，把家用网关、私有云入口与网络隔离做进一台低功耗盒子成为可行选项。对进迭时空，这是 K1 在消费级网络设备上的一个整机级落地案例，也说明 K1 的软件栈（OpenSBI/U-Boot/内核/发行版）已经能支撑第三方做完整产品，而不只是开发板。

SingNova 在新加坡安防展展出全栈 RISC-V AI 产品线，桌面机型标称 256 TOPS（11-12）

新加坡南洋理工大学孵化的 SingNova（南洋星科技）在 11 月 10 日至 12 日于滨海湾金沙举办的 Safety & Security Asia 2026 上展出一条以 RISC-V 为底座的产品线，共四款：智能视频存储服务器、AI Power Studio 桌面 AI 计算系统、AI 数字员工与存储工作站。官方新闻稿把主题定为「开放思维、开放系统、开放未来」，落脚点是安防与智慧城市场景里视频数据增长与带宽、存储、分析成本之间的矛盾。

参数上最具体的是 AI Power Studio：12 核 RISC-V CPU 加数据流（dataflow）架构，标称最高 256 TOPS（INT8），最多 128GB LPDDR5 ECC 统一内存，支持最多 128 路 1080p@30fps 视频解码，提供 PCIe 4.0 x16 扩展与高速网络接口，面向实时视频分析、本地大模型推理、生成式视频创作、机器人与 AI 智能体。视频存储服务器则主打编码侧：基于 RISC-V 架构与芯片级智能视频编码，把存储需求压到原来的三分之一（3:1 压缩比），同时保留高清画质与下游分析所需的视觉元数据，支持板级冗余、集群故障切换与自动恢复，兼容 RTSP/ONVIF 与 H.265/H.264。

玄铁 XT-Link 三代线：XL100 到 XL200 再到 XL300 的口径演进与规格核对（11-12）

把历年公开信息排成一条线，能看到玄铁互联 IP 的迭代节奏。2024 年 7 月，XL100 作为「首款支持缓存一致性的多 Cluster 互联 IP」发布，定位是给客户提供 8 至 32 核的处理器扩展方案，支持大小核配置，卖点是降低多 Cluster 系统互联的带宽需求、软件编程难度与额外 Cache 访问，并优化系统功耗。2025 年 2 月的玄铁生态大会上，XL200 出现在研发计划里，表述是「提供更大规模、更高性能的多簇一致性互联」，当时还没有具体参数。2026 年 3 月的 C930 深度解析中，XL-300 已经是与 C930 配套的最强互联 IP，口径为单 Cluster 最多 8 核、L3 最大 23MB、相比 XL-200 频率提升 20% 且带宽翻倍、面积仅增 5%，并提到弹性可配置架构、容量与带宽分配、以及对同 ID 上独立显卡的额外加速设计。本期报道给出的新口径是 8 核异步连接、256bit 位宽、32MB L3、8 核线性度 90% 以上、带宽较 XL-200 约翻倍、新增 Direct Memory Transfer。

三处值得核对的细节。第一，L3 容量从 23MB 到 32MB，跨度接近四成，不像笔误；可能是单 Cluster 与多 Cluster 配置的差别，也可能是同一产品在不同 SRAM 库或工艺节点下的上限不同。第二，「频率提升 20%」在 3 月的口径里有、本期没有，而本期新增了「8 核并发线性度 90% 以上」——前者是工艺与物理实现的指标，后者是架构与协议效率的指标，两家媒体各取一面，说明官方材料本身在不同场合强调了不同维度。第三，「8 核异步连接」这个说法需要一点解释：异步意味着各核可以跑在不同时钟域，这在大核小核混布、或核与 IO 分属不同电源域时是必须的，但也会让一致性协议的实现复杂度上升。

从产品逻辑看，XT-Link 这条线的对手不是别家的 RISC-V 互联 IP，而是「客户干脆自己攒一个」的诱惑。做服务器 SoC 的团队如果拿四颗 C930 加自研 NoC，理论上能省一笔授权费，但要自己啃一致性协议、死锁规避与硅后调试，风险极高。玄铁把 XL100、XL200、XL300 做成 8 核到 32 核的梯度，本质是把「多核怎么拼」这道题变成买与不买的选择题。接下来真正决定这条线成败的，不是再刷一次带宽数字，而是有没有第三方芯片公司公开宣布基于 XL-300 做出量产的多核 SoC——IP 的价值最终要在别人的硅片上兑现。

五、总结与趋势观察

一、互联 IP 从配角变成 RISC-V 服务器化的主线。 玄铁 XL-300 这一期披露的规格里，最能说明问题的不是 32MB L3，而是「8 核并发线性度 90% 以上」——这是一条只有真正跑过多核负载才敢给的指标。单核性能靠微架构，多核性能靠一致性与总线；国内 RISC-V 在单核上已经能用 SPECint2006 15/GHz 这个量级对话，接下来两三年的胜负手会落在多核扩展效率与硅后稳定性上。XL100 到 XL300 一年一代的节奏，说明这条线被当作产品在做，而不是一次性交付。

二、整机落地正在从开发板转向消费品。 Start9 的 RISC-V 路由器 300 美元、八核 K1、把「哪些开源哪些不开源」逐项写明，这是一个成熟硬件产品的写法；SingNova 把 12 核 RISC-V 加数据流做成能接 128 路摄像头的桌面盒子，同样是整机思路。两者共同点是软件栈自己维护（StartWRT、自研数据流运行时），不再依赖某块 x86 主机。RISC-V 要证明的不是「能跑 Linux」，而是「能撑起一台要卖给普通用户或集成商的设备」。

三、开源硬件这条支线在往「可审计」走。 Baochip-1x 用 22nm、RV32IMAC、公开 RTL 与 RRAM 换「每颗晶体管都能交代清楚」，市场很小但需求真实。它与高性能服务器路线不冲突，反而补上了 RISC-V 叙事里最容易缺的一块：在安全审查与供应链追溯日益严格的场景，能读到 RTL 比跑分高更值钱。

四、工具链与工程卫生成为这一天的暗线。 difftest 去掉一个 | tee 让构建失败不再伪装成 SimTop.h not found，香山把调试用的 uop 拷贝从正常 RTL 里剥离，进迭给漏发的版本补上手动通道，openRuyi 把固件更新接进 fwupd——四件事都不产生性能数字，但都在减少「下次改动要付的代价」。一个生态成熟与否，往往看这些不写进发布说明的提交有多密。
