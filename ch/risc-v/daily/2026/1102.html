今日重点：Linux 7.4 把「快非对齐访问」改为运行期探测，发行版内核可吃到最多 11% 带宽收益（10-30）

Linux 7.4 的 RISC-V 架构改动已并入主线，其中一条优化值得单独记：跳过软件对齐的判定从编译期挪到了运行期。

这条优化的来路分两步。Linux 7.3 由 Tenstorrent 提交的改动，让「为支持快速非对齐内存复制的 RISC-V 硬件编译的内核」跳过软件对齐，Tenstorrent 自测带宽提升最高 11%。但 7.3 要求该能力在编译时打开，而一个发行版内核要服务一批硬件，其中总有慢速非对齐访问的芯片，于是这条收益只能留在定制内核里，通用构建吃不到。7.4 把判定改挂到 HAVE_EFFICIENT_UNALIGNED_ACCESS 上做运行期探测：只有探测到硬件确实支持快速非对齐访问，用户态拷贝才跳过软件对齐。这样一来，发行版 RISC-V 内核与其它通用构建都能默认带上这条优化，而不必为老硬件保留一份特制镜像。

同批并入 7.4 的 RISC-V 改动还有：crash 热插拔支持、部分页表函数走优化路径、上下文切换的一处优化、「B」扩展进入 hwcap 与 hwprobe 上报，以及 Zic64b 扩展的上报支持。这几条单看都不大，但合起来是「内核把 RISC-V 平台能力摸清并交给自己调度」的一步——尤其是 hwprobe 侧的上报，正是运行期探测这类优化的前提。

社区讨论里有一个值得记录的判断：Hacker News 上有读者问快速非对齐访问是否只属服务器 CPU，回复指出除 SiFive 外几乎各家都支持，SiFive 只在新一代性能核上支持。这提示发行版打开这条优化后，实际受益面取决于芯片是否在 hwprobe 里如实上报，而不是取决于产品定位。

一、开源社区与软件生态

香山前端引入 FtqPrefetchQueue，iprefetch 重构第一步（10-30）

第 6691 号是香山前端本轮最重的一笔，16 个文件、+471/−198。改动核心是新增 FtqPrefetchQueue，把取指预取从 ICache-top 上收到 FTQ 侧统一调度。

原设计的三个问题写得很直白。其一，FTQ 只负责 FDIP，来自 memblock 的 Zicbop 软件预取 prefetch.i 由 ICache-top 处理，每周期只能收 1 个请求，且总是把软件预取排在高优先级——同一周期多条 prefetch.i 只有 1 条生效，其余被静默丢弃，性能收益低于预期。其二，密集 prefetch.i 会阻塞 FDIP 请求，反过来拉低性能。其三，prefetchPipe 要么处理 1 条 prefetch.i、要么处理 1 至 2 条 FDIP，即使两者在 SRAM 上并不冲突也不能并行，流水线利用率偏低。

新队列的做法是：先缓存软件预取请求，缓解丢失；再按队列空位与当前 FDIP 距离选择出队来源，解决阻塞；并允许 FDIP 与预取在同一周期并行发射，解决利用率。作者还留了扩展口——后续可以把 PDIP 一类算法的结果直接塞进同一队列。这是把预取从「一条通路」变成「一级可调度资源」的改法，比单纯调优先级更接近长期方案。

日期：2026-10-30　来源：XiangShan #6691

香山修 MBTB 对隐藏 VBTB 分支的分配抑制（10-30）

第 6750 号修的是预测器元数据互相压制的问题。VBTB 在预测时只暴露最早命中的那一条分支，但训练阶段仍可能命中一条「隐藏分支」——这条分支在预测时没被看到，却因为训练命中而抑制了 MBTB 的分配，结果是同一条分支反复预测失败。

改法分三处：只有在「预测时确实暴露过、且训练时仍驻留」这两个条件同时成立时，才因 VBTB 驻留而抑制 MBTB 写入；把全部 NumWay+1 条元数据条目传给 AlignBank，以便区分「VBTB 预测命中」与「SRAM 命中」；条件分支载荷只在真正 taken 时写入，因为 not-taken 的解决路径携带的是顺序下一条 PC 而非分支目标。最后一条同时施加于 MBTB 与 VBTB，并保留计数器训练与 IFU 失效请求（attribute=None）。改动只有 2 个文件、+33/−19，但属于「预测器越复杂、元数据口径越要对齐」的典型修复。

香山把 prefetch.i/r/w 解码为 LSU 预取操作（10-30）

CORE-V CVW 按 Svvptc 不再缓存无效 PTE（10-30）

第 1974 号修的是一个只在 RVA23 选项下才暴露的死锁：此前 HPTW 会把「遍历落在 V=0 的叶或非叶 PTE 上」的结果写进 ITLB/DTLB，之后命中该缓存项时一直从缓存条目触发 page fault，直到执行 SFENCE.VMA 才恢复。问题在于 Svvptc（RVA23 的可选项）允许处理程序把 V 置 1 后直接重试、不发 SFENCE.VMA——在这种合法用法下，缓存了无效 PTE 的实现会永久 fault。改法是让遍历器自己走既有 FAULT 路径从 LEAF 报错，不往 TLB 写任何东西，下一次访问重新遍历即可看到更新后的 PTE；相应地 tlbcontrol 不再检查 PTE.V，ITLB 的 ENVCFG_ADUE_1 覆盖排除也从第 18 行移到第 16 行。这是「规范给了你一个可选项，实现必须为它的合法用法留出通路」的典型案例。

日期：2026-10-30　来源：CVW #1974

CORE-V CVW 修 trace 的 VM 字段与 quad 溢出检测，rv64gc 覆盖率达 100%（10-30）

Qwenputer 把 RV32IM 编译进 Qwen3.5-4B 权重，用注意力状态当 RAM（10-30）

开发者 Divyansh Agrawal 于 10-22 发布的实验模型 Qwenputer，10-30 经中文媒体转述后进入大众视野。做法是把 RV32IM 指令集及扩展「编译」进 Qwen3.5-4B 的权重，用模型自带的 Gated DeltaNet 状态充当可精确定址的 RAM，从而在前向传播里跑真正的程序——不需要训练，编译器直接写出每个权重：注意力头做查表、前馈单元以查找表实现算术、DeltaNet 头持有内存。

可核对的收益集中在精确算术：大整数乘法从原版 55.0% 升到 97.5%，大整数除法 72.5% 到 97.5%，加减 87.5% 到 97.5%，多次乘除的更长链路 90.0% 到 100%，合成整数算术 75.0% 到 97.5%；长整数基准 NUPA 从 48.6% 到 100%。项目自述该 CPU 通过官方 RISC-V 测试，连续执行约 1,800 万条指令无错；还实验性地做了「模型内文件系统」，在 GDN 状态里存最多 512 个文件、约 5.3 万词元。

代价同样明确：模型体积涨到约 18.8GB（接近原版两倍），每条 CPU 指令要生成多个词元，原本毫秒级的计算可能拖到数秒，运行还需专用驱动，不能像普通模型那样直接加载；项目已在 Hugging Face 与 GitHub 开源，可在单张 24GB 显存显卡上跑。这条对 RISC-V 圈的意义不在性能，而在于「RISC-V 作为确定性执行层被另一种系统借用」——它验证了 RV32IM 这套极简 ISA 适合被形式化地嵌入异构载体。

日期：2026-10-30　来源：IT之家报道（搜狐转载）、技术解析

五、总结与趋势观察

一、内核侧的关键词从「支持」转向「按硬件能力调度」。 Linux 7.4 把快非对齐访问的判定从编译期挪到运行期，一条 7.3 时代只能留在定制内核里的优化，现在发行版内核默认就能带上，Tenstorrent 自测的带宽收益上限是 11%。同批并入的 hwcap／hwprobe 的「B」扩展与 Zic64b 上报，正是这类运行期决策的数据来源。对国内几家 RISC-V 发行版，这是零成本收益，但前提是芯片在 hwprobe 里如实上报——硬件厂把能力报全，比多做一次微架构优化更能让用户立刻受益。

二、香山前端进入「预取队列化」阶段。 第 6691 号把 iprefetch 从 ICache-top 的「每周期 1 条」逻辑上收到 FTQ，先解决丢失与阻塞，再谈 PDIP 一类算法；配套的 MBTB／VBTB 修正说明瓶颈已从「取指带宽」转向「元数据精度」。两条线合起来看，前端优化正在从加缓冲转向「把预取当成一级可调度资源」，这类改动的收益要靠长期负载才能验出来，短期跑分未必好看。

三、差分验证开始为加速器算子付性能成本。 difftest 三天 9 笔全部围绕 MMA：FP8 乘积打包、GPU 侧比对、CUDA 流水化、XDMA 中继打包、LightSSS 支持 CUDA 后端。RISC-V AI 核要走量产，验证吞吐必须跟上算子复杂度，否则「算得对」会变成「算不完」。这组改动的方向比单笔收益更值得记录。

四、工具链两侧同时定基线。 openRuyi 引入 llvm23，并把 riscv64-openruyi-linux 三元组的默认 ISA 定到 RVA23U64；芯来把 IDE 从 Eclipse 迁到 VS Code，并把 xlmodel、工具链与大端调试文档同步到 2026.10。前者定「默认生成什么代码」，后者定「开发者从哪里进来」，两者都属于长周期决定，短期看不到效果，但会影响此后一两年的默认选择。

五、国内侧本周期产出集中在算能与芯来，路线从板卡上移到系统栈。 算能的实质工作是模型支持与一个解码退化 bug 的修复（logits 拷进 4 字节 token 缓冲，导致每步解码破坏查表），这类缺陷只有真机逐 token 比对才能定位；芯来把工具链入口换到 VS Code 并顺手补齐 AI 助手接入。玄铁与奕斯伟在窗口内空档，进迭时空则同时推进 Bianbu AgentOS 伞仓与机械臂控制框架——一家公司把「端侧 agent 运行时」和「机械臂标定／诊断／运动学」并列推进，说明其 RISC-V 软件栈的重心正从驱动与文档转向可交付的系统层。本期新闻侧偏薄：中英文查询去重后实质新增只有 Linux 7.4、Qwenputer、Nuclei Studio 三条，其余为股市稿、消费电子与旧文重发；开源侧仍是主体。
