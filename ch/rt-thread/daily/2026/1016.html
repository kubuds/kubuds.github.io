一、内核与版本动态

1.1 内核与驱动修复合入批次：ofw 哈希表越界修复与 N32 定时器补全落定（10-15）

日期：2026-10-15 13:32 ~ 13:50（合入时间）　来源：PR #11845、PR #11812

维护者窗口内合入两笔社区修复。其一为设备树 ofw 修复（#11845，1 文件 +4/-2，维护者 Rbb666 合入）：修正 phandle 哈希表两处越界隐患——分配数量由 max-min 改为 max-min+1（查找下标为 phandle-min，phandle 取范围上限时原本会访问分配区之外），扩容清零改按旧表项数从旧表末尾起算（原实现未减去起始值，起始 phandle 非 1 时清零位置不正确）；作者以 6 组用例在 GCC 下经 ASan/UBSan 做函数级验证。其二为 N32 定时器补全（#11812，39 文件 +3956/-105）：为 N32H47x_48x 与 N32H49x 补上此前缺失的时钟源与 ATIM/GTIM/BTIM 实例表分支（两系列共用 drv_tim.c 但此前仅实现 H7xx 分支），LPTIM tick 改为按真实 LSI 推导、PWM 与脉冲编码器同步扩展，三块板配套真正编译到驱动功能声明的 ci-attach 条目，承接 #11800。

1.2 lwip 段内容宏控制提案合入：网络栈三笔提交收口（10-15）

日期：2026-10-15 13:04 ~ 13:28（提交 / 合入时间）　来源：PR #11815

lwip 段内容宏控制提案（#11815）在上一期报告截点前后完成落定：作者 rcitach 于 13:04 推送三笔最终提交（wlan AP 生命周期与直收路径同步、lwip 缓冲选项配置与 PBUF tailroom 保留、DHCP 启动逻辑优化），13:28 获合入，合计 6 文件 +188/-28。该案上一期以「在审、获请求修改」状态收尾，本期按合入终态补录。

1.3 9PFS 连曝两枚缺陷：ARMv7-A 未对齐访问致内核中止、getdents 越界读获复现确认（10-15）

日期：2026-10-15 20:33 ~ 21:18（评论 / 创建时间）　来源：Issue #11868、Issue #11289

贡献者 XueDugu 窗口内推进 9PFS 文件系统缺陷两案。其一为新开缺陷单 #11868：接收路径的 64 位取值宏以普通指针解引用缓冲（get_rx_value64_of），ARMv7-A 下 GCC 生成 LDRD 需 8 字节对齐，而结构体尺寸 292 与协议常量 42 使 rx_buffer+42 恒为 6 mod 8——任何 Tstat 应答（含完全正常的应答）都会在 dfs_9pfs_open / dfs_9pfs_stat 触发对齐异常、内核 data abort；报告定位到 2025-12 引入 9PFS 的提交，给出 CVSS 3.1 7.5（远程拒绝服务）评级与 QEMU vexpress-a9 完整复现链，并附反汇编与 addr2line 验证。其二为 3 月开出的 #11289（getdents 路径信任服务端下发的 stat/name 长度导致越界读），10-15 晚间获社区在 master（bsp/simulator + ASan）复现确认，根因是接收字节数被丢弃、记录边界未校验。两案均维持开放。

1.4 新提案：DFS 层 F_GETFL/F_SETFL 与设备控制命令撞码消歧（10-16）

日期：2026-10-16 00:51（创建时间）　来源：PR #11869

贡献者 CXSforHPU 开出 DFS 层消歧提案（2 文件 +56/-15）：POSIX 的 F_GETFL(=3)/F_SETFL(=4) 与 RT-Thread 的 RT_DEVICE_CTRL_CONFIG(=3)/RT_DEVICE_CTRL_CLOSE(=4) 数值撞码，两套命令共享同一整型参数，fcntl 路径下驱动可能误解释——dfs_v2 的 ioctl 为纯透传，串口等驱动在 LWP 关闭时甚至会把 F_GETFL 当作 CONFIG 重新配置硬件。提案不改命令编码，改以参数形态作消歧：命令 3 带参转发驱动、无参按 POSIX 返回文件状态标志；命令 4 无参转发驱动、带参走上层设置，同步改造 dfs_v1 与 dfs_v2 两代实现并保留 socket 通知路径。

1.5 在审提案评审：ESP32-C6 SPI 获三条行级意见并获作者逐条回应（10-15）

日期：2026-10-15 13:38 ~ 16:30（评审 / 回应时间）　来源：PR #11846

ESP32-C6 SPI 支持提案（#11846）获维护者 Rbb666 三条行级评审意见：其一，关闭 DMA 后 IDF 单次传输上限为 64 字节，而驱动仍整包提交，65 字节消息会触发中止，应分段传输或至少返回错误码；其二，C3/C6 共用 ESP-IDF-latest 时构建 C6 会把 gdma.c 永久改写为四参数调用，随后构建 C3 将报参数过多，应改用目标宏或独立副本；其三，位宽校验发生在总线初始化成功之后，16 位请求失败后以 8 位重试会因总线已初始化中止，应先校验再申请资源。作者回应将逐项整改（驱动内分段发送、按目标宏保留两套调用并双向编译验证、位宽校验前移），并同意移除构建脚本中的改写逻辑。

1.6 在审讨论：aarch64 GIC 应答路径去留之争深入（10-15）

日期：2026-10-15 13:57 ~ 19:39（评论时间）　来源：PR #11860

aarch64 GIC 修复提案（#11860）窗口内出现深入技术讨论：作者 Xenithya 说明所删为 EOI 之前多余的 GICD_ICPENDR 清 pending 写入——中断处理期间同一边沿源再现新事件（如其 NPU 场景：先报 AXI 错误再报完成）时该写会抹掉重新锁存的 pending、致新中断永久丢失，并给出实测数据：保留该写约 19~33 次推理必现一次完成中断丢失，删除后纯中断路径 48 万次推理零失败。维护者 GuEe-GUI 两次回应：该函数语义需按 GIC 非 EOI 模式理解，问题也可能出在 traps.c 对中断应答接口的调用方式，建议同步验证 trap 路径改法。提案维持开放。

1.7 新手任务激活：efm32 menuconfig 支持提案开出（10-15）

日期：2026-10-15 18:30 ~ 18:31（评论 / 创建时间）　来源：Issue #7530、PR #11867

长期挂起的「menuconfig 新手任务」缺陷单（#7530）窗口内重新激活：贡献者 ymj0440 认领 efm32 子任务——为 bsp/efm32 补缺失的 Kconfig 与 .config（.config 由 rtconfig.h 反推生成、RT_USING_LWIP 保持未启用），使该 BSP 支持 menuconfig 配置，援引 sam7x、lm3s8962 先例；18:30 认领评论发出后 1 分钟即开出提案（#11867，2 文件 +408）。该单此前标记待补的另一 BSP rm48x50 已随主线具备配置文件。

社区开发者发布移植项目 sf8086：将 8086tiny 模拟器移植到基于 RT-Thread 的思澈科技 SiFli SF32LB525（黄山派，Cortex-M33）开发板，板端直接运行 FreeDOS——BIOS、启动软盘与 Turbo C 2.01 编译工具链全部驻留固件，不依赖外部存储；A: 盘为每次启动自 flash 重建的 RAM 盘（约 144 KB 可用），可运行 EDIT、DEBUG、ZIP 等 DOS 工具；RT-Thread shell 与 DOS 控制台共用 UART1（含串口仲裁、终端按键映射等适配提交）。项目窗口内推送 13 笔提交，含 MS-DOS 6.22 启动盘构建脚本与板端运行截图，仓库标注 rt-thread、sifli、sf32lb525、freedos 等主题。
