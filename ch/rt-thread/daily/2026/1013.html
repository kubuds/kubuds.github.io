一、内核与版本动态

1.1 构建工具链缺失检查合入：工具链目录缺失时构建显式失败（10-12）

日期：2026-10-12 09:56（合入时间）　来源：PR #11863

构建工具修复合入（#11863，作者 Rbb666，单文件 tools/building.py）：构建入口在工具链目录缺失时的处理由置位局部退出标志（need_exit = True）改为直接 sys.exit(1)，使构建以非零退出码立即显式失败，不再带着缺失的工具链继续执行后续流程。该提案 10-12 上午开出、约 36 分钟后即获合入，为窗口内首笔落地。

1.2 Eclipse 工程生成修复合入：#11787 落地，SCM 元数据目录不再递归扫描（10-12）

日期：2026-10-12 11:06（合入时间）　来源：PR #11787

Eclipse 目标生成脚本修复合入（#11787，作者 wdfk-prog，单文件 tools/targets/eclipse.py）：为源文件收集与排除逻辑引入 SCM 元数据目录清单（.git / .svn / .hg），此类目录不再被递归展开扫描，避免在含版本库元数据的工程树上遍历海量对象文件；隐藏目录同步改为与普通目录一致的排除规则。该案 09-08 开出，经 10-11 CI 排查（失败原因为流水线缺 scons 命令、与排除逻辑无关）后本期合入，为窗口内第二笔落地。

1.3 新提案：rtdbg.h 包含关系修正，修复 IAR 下 rt_kprintf 隐式声明（10-12）

日期：2026-10-12 13:50（创建时间）　来源：PR #11864

新提案（#11864，作者 meng-plus，单文件 include/rtdbg.h）：将头文件内的 #include 改为 #include ，使仅经 rtdbg.h 做日志重定向的组件也能获得 rt_kprintf 的正式函数声明。作者报告：IAR 8.40 环境下经 rtdbg.h 重定向日志时出现 rt_kprintf 隐式声明，导致 %f 格式化输出异常；提案附 with_proto / no_proto 两组最小对照样例。提案处于开放评审。

1.4 RISC-V 向量：vstart 提案按维护者意见调整测试组织（10-12）

日期：2026-10-12 09:17（评审时间）　来源：PR #11861、Issue #11786

RISC-V 向量上下文修正提案（#11861）窗口内收到维护者新一轮评审意见：建议将测试及其汇编探针迁入专用 utest 目录、启用条件化构建集成，并补充 VLEN=128 与 VLEN=256 两种配置下向量支持、堆与 UTest 的 CI 配置。提案作者 10-11 已按前轮意见推送修正提交（为每次调用独立分配栈帧并在成败路径统一释放）；本案维持开放，等待测试组织调整。同作者推动的 OSPP 2026 议题「RISC-V 惰性 FP/RVV 上下文切换」（#11786）窗口内亦有一次更新，维持开放。

1.5 ping 除零第二案：作者吸纳旁路建议再推修复（10-12）

日期：2026-10-12 20:18 ~ 20:47（评论与推送）　来源：PR #11862、PR #11853

netdev ping 除零修复第二案（#11862）窗口内再迭代：贡献者 CXSforHPU 就 ping 循环内的延时逻辑提出两点改进（最后一条报文不应再补时延、避免以 0 参调用 rt_thread_delay），并询问是否在本案一并修改；原作者 ymj0440 当晚采纳并推送修复——延时判断由恒假的 index == times 改为 index != times - 1，且仅当 delay_tick > 0 时才调用延时函数，避免触发 -RT_EINVAL。本案与首案 #11853 并行，仍待维护者择一合入。

1.6 工具与规范在审队列更新：Keil/IAR 目标选择获复审意见（10-12）

日期：2026-10-12（更新时间）　来源：PR #11743、PR #11859、PR #11850、PR #11815、PR #11814

工具与规范方向多处在审推进：其一，Keil/IAR 目标自动选择提案（#11743）作者上午请求复核自动化报错，维护者当晚给出两处具体复审意见（targets 初始化循环与变量缺失、IlinkConfigDefines 对无效符号项的提取方式）；其二，clang-format 规则收敛讨论（#11859）维持活跃——wdfk-prog 给出 LGTM，Rbb666 则认为以 thread.c 为样例的格式观感不佳，作者此前呼吁尽快收敛规则、减少各提案追加格式化提交的负担；其三，STM32F103C6「蓝丸」支持提案（#11850）深夜更新并点名请求评审（关联缺陷单 #11854）；其四，lwip 段宏控制提案（#11815）force-push 后触发自动化复核并获改进意见；其五，RA6W1 资源分配优化提案（#11814）窗口内刷新提交。

2026 嵌入式大赛作品帖「便携式调试器」发布：以 GD32H759IM（Cortex-M7 @600 MHz，Flash 3840 KB、AXI SRAM 832 KB）为核心、运行 RT-Thread 的手持调试平台——7 英寸 800×480 RGB565 触摸屏（GT911 电容触摸）与全中文图形界面，内置约 5000 常用汉字点阵字库；功能覆盖串口调试（USART1，八档波特率热切换与自动波特率检测）、CAN 总线调试、双通道示波器（0~3.3 V）、双路开关检测与 DDS 信号发生器，其中示波器与开关检测复用同一采样链路以简化硬件；板载 GD-Link 调试下载单元。

2.2 【2026嵌入式大赛】目语心声-阿尔兹海默症老人智能辅具作品帖发布（10-12）

日期：2026-10-12 08:26（发布时间）　来源：论坛帖 4656e92595977d25

2026 嵌入式大赛作品帖「目语心声-阿尔兹海默症老人智能辅具」发布：面向失智老人居家照护场景，老人注视屏幕图片即可表达需求。下位机主控由 Arduino Mega 2560 更换为兆易创新 GD32H759I-EVAL（Cortex-M7 @600 MHz），开发方式转为 GD32 官方固件库（Keil MDK / IAR），软件框架预留 FreeRTOS / RT-Thread 任务调度选项；集成幻尔 K230 视觉模块（人脸、摔倒、人形、人眼朝向识别）、步进云台人脸跟踪、MPU6050 姿态检测、GPS 定位、智能药盒、起夜灯、淘晶驰串口屏与语音播报，形成「看、记、护、陪」照护闭环。

四、行业应用

4.1 端边协同灵巧机械臂系统开源分享：Titan Board RA8P1 全自主控制与 17 类手势 NPU 识别（10-12）

日期：2026-10-12（媒体发布时间）　来源：电子工程专辑原文、项目代码仓库

RT-Thread AIoT 大赛优秀奖作品「端边协同灵巧机械臂系统」刊出完整技术分享并开源代码（仓库 10-12 完成初始提交）：面向单侧上肢障碍人群的桌面级辅助机械臂，将机械臂与灵巧手控制从 PC 剥离——以 Titan Board（瑞萨 RA8P1，Cortex-M85 + Ethos-U55 NPU）为唯一控制核心，执行端为 LeRobot SO101 机械臂与 Amazing Hand 灵巧手，Joy-Con 手柄经 ESP32 / Bluepad32 接入实现遥操作；板端部署 17 类手势识别模型（YOLO-Fastest 经 PyTorch 训练、INT8 TFLite 量化、RUHMI / Vela 编译为全 NPU 单子图，107 个算子全落 Ethos-U55），单次推理约 77~78 ms，摄像头 640×480 采集、本地 LCD 显示与 WebSocket 视频上云（160×120 JPEG，约 3~6 KB/帧）并行，网页端叠加 MediaPipe 手部关键点显示。工程要点包括 D-cache 与 OSPI 时钟分阶段启动策略（解决 WHD 固件下载回读校验失败）、WiFi 与 NPU 工程融合、TinyJPEG 低带宽推流等，作者并公开两类踩坑处置经验：RT-Thread Studio 软件包索引报错处理与不依赖 e2 Studio 的模型转换命令线流程。
