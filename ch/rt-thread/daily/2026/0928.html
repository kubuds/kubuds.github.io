一、内核与版本动态

1.1 主线合入两笔维护性修复：GD32VW553H-EVAL 构建清理与 ipc 文件整理（09-26 ~ 09-27）

日期：2026-09-26 19:58 / 09-27 12:18（北京时间，合入时间）　来源：PR #11837、PR #11832、合入提交 b40aeb146、合入提交 05badce95

主线在窗口内合入两笔小型修复。其一（#11837）修复 GD32VW553H-EVAL BSP 的 CI 清理阶段失败：riscv-none 任务在构建、打包成功后的 scons -c 清理环节退出——根因是 SConstruct 注册的软件包预检查（bsp_pkg_check）在清理模式下也无条件执行，而清理时软件包可能已被移除或未拉取；修复为该检查在 clean 模式直接短路（1 个文件，+3/-0），正常构建的检查逻辑保持不变。该提案由 GitHub Copilot 编码代理（copilot-swe-agent）提交，代理会话由维护者触发、开题后约 3 分钟完成修改，09-26 19:58 由 Rbb666 合入。其二（#11832）移除 components/drivers/ipc/SConscript 中冗余的 __RT_IPC_SOURCE__ 宏定义（1 个文件，+1/-1），属 09-24 评审队列的消化，09-27 12:18 合入。

1.2 评审队列新增两笔健壮性修复：STM32 链接脚本栈对齐与 devtmpfs 路径越界（09-27）

日期：2026-09-27 20:57 ~ 21:11（北京时间，创建时间）　来源：PR #11841、PR #11842

评审队列在窗口内新增两笔健壮性修复。其一（#11841）修正 STM32 系全部链接脚本的栈对齐：将 .stack 段的 ALIGN(4) 改为 ALIGN(8)，以符合 ARM AAPCS 对栈指针在公共函数边界 8 字节对齐的要求，对应 2023-05 报告的旧缺陷 #7527（栈 4 字节对齐导致可变参数中 double 传参错误）；改动覆盖 12 个模板与 98 块板卡共 110 个链接脚本（+220/-220），未触碰各板卡的存储布局。其二（#11842）修复 devfs 的栈缓冲区溢出：devtmpfs.c 的 _path_separate() 与 _get_subdir() 未接收缓冲区长度参数，单个路径分量超过 255 字节即发生越界（最长越界约 3.8KB，写入内容与长度由调用者控制、可覆盖返回地址）；修复让 devfs 与 tmpfs 的既有校验对齐（越界返回 -ENAMETOOLONG，1 个文件 +48/-8），提交署名前缀 [HUST CSE]。两笔目前均处于评审状态。

1.3 FinSH 路径补全堆溢出缺陷报告：提交者已认领拟修复（09-26）

日期：2026-09-26 03:55（北京时间，创建时间）　来源：Issue #11839

社区在窗口内提交 FinSH 组件的高危缺陷报告：在 msh 中触发路径自动补全（Tab 键）时，msh_auto_complete_path 相关逻辑在拼接当前工作目录与用户输入时未做严格边界检查，超长或深层嵌套路径可造成堆缓冲区越界写（CWE-122），影响 v5.3.0 及当前主线、STM32F407-ATK 等板卡。议题附带缺陷描述与标签（bug、in progress 等），提交者 Acen28 当日认领该议题，拟自行提交修复。属继 devtmpfs 越界（见 1.2）之后又一条由社区审计推进的内存安全问题线索。

2.2 论坛教程《MCU 链接脚本“升级”》：孤儿 Section 与对齐处理（09-28）

日期：2026-09-28 08:17（发布时间，11:03 更新）　来源：论坛文章 54cb40d33610387a、B 站配套视频

社区作者「大目熊」的 MCU 底层系列更新（前篇《MCU GNU链接脚本》09-22 已收录）：本篇进阶处理孤儿 Section 与对齐问题。要点：用 -Wl,--warn-orphan 让链接器列出未显式安排的 section；按 SHF_ALLOC 标志把 section 分为运行时需要（.text/.rodata/.data/.bss，需分配内存区域）与不需要（.debug_*、.comment、.ARM.attributes、符号表等，显式列出但不分配）两类逐个安置；.ARM.exidx/.ARM.extab 属 ALLOC 类需安排并导出起止符号；最后以 4 字节对齐收束，验证链接警告全部消除、map 文件与脚本描述一致。附 B 站配套视频，属社区教程类内容。

三、生态与厂商适配

3.1 沁恒 CH32V003F4P6-EVT 板级支持提案进入评审（09-25）

日期：2026-09-25 21:11（北京时间，创建时间；09-27 有更新）　来源：PR #11838

贡献者 cms19859230182-lang（此前 CH32V203 BSP 与 ESP32-C6 提案作者）为沁恒 CH32V003F4P6-EVT 开发板提交 BSP 提案。CH32V003F4P6 为 RISC-V 内核、主频 48MHz、16KB Flash、2KB SRAM、TSSOP20 封装；默认镜像仅启用 UART1（TX PD5 / RX PD6，115200 进 msh），调试经单线 SWDIO（PD1）外接 WCH-LinkE。提交者已实测：以 WCH RISC-V GCC 8.2.0（-march=rv32ec -mabi=ilp32e）构建，镜像 15680 字节（装入 16KB Flash），烧录后串口输出 RT-Thread banner 与 msh 提示符。提案共 5 笔提交、47 个文件（+9258/-0），目前处于评审状态。

3.2 CANopen 生态双仓上线 MkDocs 文档站（09-28）

日期：2026-09-28 08:45 ~ 09:09（推送时间）　来源：canopennode-rtt、lely-canopen-rtt

社区贡献者 wdfk-prog（RT-Thread 软件包索引中 canopennode 包 09-24 合入 v1.2.0 的提交者）在窗口内为两个 CANopen 集成仓库发布文档站：canopennode-rtt（CANopenNode 集成，支持多设备节点的逻辑设备模式）与 lely-canopen-rtt（Lely CANopen 集成，单一所有者 EV/IO2 运行时与静态对象字典、可选主站服务）均推送 MkDocs 手册与 Doxygen API 文档；lely 仓另增加 PR 文档校验 CI。两包此前均在 RT-Thread 论坛有介绍帖（lely 主站用法长文 09-11 已收录）。工业通信方向软件包建设持续投入。

3.3 AWTK 开源许可证切换至 Apache 2.0（09-26）

日期：2026-09-26 08:50（提交时间）　来源：zlgopen/awtk 许可证变更提交

通用嵌入式 GUI 工具链 AWTK（zlgopen/awtk，3.3k stars）在窗口内把许可证从 LGPL-2.1 整体切换至 Apache License 2.0（LICENSE 文件 +201/-504），由项目主要作者 lixianjing 提交。AWTK 及其 RT-Thread 软件包（awtk 等）长期服务于 RT-Thread 上的 GUI 应用开发，许可证放宽有利于商用集成。属生态参考类消息（非 RT-Thread 专向）。

四、行业应用

4.1 Luckfox RV1103 单芯片无人机原型：RISC-V 核运行 RT-Thread 飞控（09-27）

日期：2026-09-27 17:25 ~ 20:04（创建与推送时间）　来源：luckfox-rv1103-drone

开发者 nguyencanhanh 公开一套单芯片四旋翼无人机原型：以 Rockchip RV1103（Luckfox Pico Mini B）为核心，Cortex-A7 运行 Linux 承担相机、NPU 识别、Wi-Fi、GPS 与遥控接收，片内 RISC-V MCU 核（HPMCU）运行 RT-Thread 执行 1kHz 飞控环路；项目目标是以实测数据回答“单芯片架构能否直接飞行”，备选方案为外挂独立飞控。截至 09-27：尚未实飞，但 Linux 与 MCU 已并行运行、1kHz 环路已实测，飞控软件可在模拟器中完整运行并支持 3D 操控视图；自研 LFX_FC_R1 飞控板（46×46mm）已完成布线。项目以 MIT + CERN-OHL-P 许可开源，属社区个人原型。
