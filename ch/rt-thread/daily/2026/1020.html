一、内核与版本动态

1.1 进迭时空 K1 BSP 首版合入主线：173 文件、5.4 万行，S 模式加 4 核 SMP（10-19）

日期：2026-10-19 18:49（合入时间）　来源：PR #11132、K1 BSP 说明

进迭时空 K1 平台的首版 BSP 合入，4 笔提交、173 文件 +53862/-12，作者 GuEe-GUI，提案自 2026-01-11 挂出，评审约九个月后落地，属 Next RISC-V 系列（#10320）的后续。BSP 面向 64 位 RISC-V、集成 8 个 X60 核的 K1，带向量扩展，由 U-Boot/OpenSBI 引导、在 S 模式运行，默认开启 MMU 与 4 核 SMP，验证平台为香蕉派 BPI-F3，控制台走 UART0（115200 8N1）。已支持 PCIe/NVMe、eMMC HS400、以太网与 PTP、HDMI 帧缓冲（含冷启动显示）、JPU 与 V2D 加速、ES8326 音频、CPUfreq 与热管理、AES/RNG/eFuse；SPI 与 QSPI 标注为已移植、验证中。驱动层单独抽到 bsp/spacemit/dm（147 文件、49 个 C 文件、约 30 个模块，含时钟、音频、图形、加解密、PCI、SDIO、串口、热管理等），供后续同系 SoC 复用。CI 侧新增 spacemit-k1 编译腿，并把原先只装 K230 工具链的步骤改为对全部 riscv64 musl BSP 生效。

1.2 RISC-V 原子 CAS 重试缺陷随同批修复：期望值不再被状态寄存器覆盖（10-19）

日期：2026-10-19 18:49（合入时间）　来源：合入提交 1c801efa、atomic_riscv.c

同一批提交修掉了 RISC-V 原子比较交换实现里的一个真实缺陷。原代码在
rt_hw_atomic_compare_exchange_strong 中用同一个变量 tmp 既存期望值，又接收 sc 指令的成败状态：sc 失败时会把 tmp 写成非零值，重试分支的 lr 结果再与它比较，等于拿被覆盖的值当期望值，循环可能永远退不出去或做出错误判断。修复把期望值转存为只读操作数、另立 status 寄存器接收 sc 结果，并把结果输出改为只写约束。该实现被所有 RISC-V 板卡的原子操作走，属架构公共代码，影响面大于单个 BSP。

1.3 rt_null 控制台设备提前到 BOARD 初始化：上电即支持将日志口设为 null（10-19）

日期：2026-10-19 16:53（合入时间）　来源：PR #11884、Issue #11472

社区提交的一行改动把 null 设备的注册时机从 INIT_DEVICE_EXPORT 提到 INIT_BOARD_EXPORT，使 RT_CONSOLE_DEVICE_NAME 配成 null 时上电即可生效，解决日志口与通信口复用同一路串口时无法在早期静默输出的问题。作者在 qemu-vexpress-a9 上验证：uart0 正常输出，改配 null 后 QEMU 无启动横幅，恢复 uart0 后 msh 提示符回归，rt_null.o 落入 .rti_fn.1 段。改动 1 文件 +4/-1，作者注明由 AI 辅助完成。早期与常规控制台拆分这一更彻底的方向未在本次实现。

1.4 设备模型框架两处修正：电源域 proxy 命名与 DVFS OPP 重复告警（10-19）

日期：2026-10-19 18:49（合入时间）　来源：power_domain.c、dvfs.c

K1 BSP 的合入同时带来两处框架层修正，属「BSP 先行、框架补齐」的典型。其一，电源域代理对象在注册时把名字写成了真实电源域的名字，导致按名字查找时把代理误认成域本身，现改用代理专用名，使设备树里的电源域引用能正确落到代理的解析回调。其二，DVFS 解析 OPP 表时直接新增而不查重，设备树重复表项会触发重复告警且新增失败，现先按频率查找、命中则复用。两处都在 components/drivers 下，受益方不只 K1。

1.5 netdev ping 时延统计修正：count 为 1 时最小时延不再漏记（10-19）

日期：2026-10-19 16:42（创建时间）　来源：PR #11900

社区提交 netdev 层 ping 统计修正（1 文件 +5/-1）。原逻辑在 ping 次数为 1 且成功时只统计最大时延，最小时延被跳过，表现为一次成功探测后最小值显示异常；修法是在首次成功收到响应时同时初始化最大值与最小值。改动小但属常用诊断命令的可见结果，提案仍在审。

二、安全与稳定性跟进

2.1 lwp 信号编号校验提案：sys_sigaction 入口限定 1 至 64（10-19）

日期：2026-10-19 08:49（创建时间）　来源：PR #11899、Issue #11882

维护者 BernardXiong 就上期缺陷单 #11882 开出修复提案（2 文件 +11-0）：sys_sigaction 把用户态传入的信号号直接交给 lwp_signal_action，而后者用信号号减一索引定长数组（_LWP_NSIG 为 64），越界或负值会造成内核堆越界读写，普通程序一次系统调用即可触发。提案在 sys_sigaction 入口只接受 1 至 64，否则置 EINVAL 返回，并在 lwp_signal_action 内加同样校验以保护后续新增调用者；仓库内已有 valid_signo_check，本次复用该思路。提案已分派 components 评审，处于在审状态。

2.2 OFW 设备树展开前加深度预检：超过 63 层直接拒绝（10-20）

日期：2026-10-20 01:12（创建时间）　来源：PR #11901、Issue #11879

社区成员 liangzhan5 就 #11879 提交修复（1 文件 +60-0）。fdt_unflatten_single 用固定 64 项栈暂存遍历路径，嵌套超过 64 层时压栈前无检查，会在启动阶段写越界并崩溃。提案在真正展开前先用自建栈遍历一遍设备树算最大深度，超过 63 层则打印错误并终止后续展开，避开残留树与二次断言问题；作者称已在 qemu 上复现该缺陷，验证配置为 qemu-virt64-aarch64，CLA 已签，提案在审。

2.3 新的 tmpfs 缺陷单：ftruncate(fd, 0) 释放缓冲区却返回成功（10-20）

日期：2026-10-20 01:53（创建时间）　来源：Issue #11902

贡献者 XueDugu 新开一枚 dfs_v2 缺陷单。tmpfs 的截断函数在 rt_realloc(data, 0) 返回空指针时置 ENOMEM 却返回 0，而两种堆后端对长度为 0 的 realloc 语义都是「释放并返回空」，于是合法的 ftruncate(fd, 0) 会先释放文件缓冲、再向应用报成功，留下悬空指针与过期长度，随后的读写落在已释放的内核堆上，可造成信息泄露与双重释放。缺陷由 2023-09-20 的提交引入（PR #8063），自 v5.0.2 起所有版本与 master 均受影响，已在 QEMU aarch64 的 RT-Smart 与 RP2350 上复现。单子保持开放。

2.4 维护者回应 libdl 动态模块缺陷：可做局部修复，彻底隔离需用户态（10-19）

日期：2026-10-19 08:16（评论时间）　来源：Issue #11898

上期收录的 libdl 重定位越界写缺陷单在本窗口获得维护者回应。BernardXiong 确认描述属实，认为边界校验可以做一定修复，同时指出动态模块本质是把一段代码插进内核、权限全开，这也是官方在该机制上未做更多尝试的原因；若要做到内存隔离，需要走用户态模式。该表态为后续修复范围划了边界：本轮预计只补元数据校验，不改动模块加载的整体权限模型。

日期：2026-10-19 09:35（发布时间）　来源：社区文章

2026 嵌入式大赛作品，面向小型与家庭大棚的本地化环境监测终端。硬件用 ArtInChip D12X-DEMO68 开发板，主控为达摩院玄铁 E907（RV32，396 MHz，带单精度 FPU），配 8 MB PSRAM、16 MB SPI NOR 与 480×272 电容触摸屏（GT911），传感器只有 DHT11 与 BH1750 两支，不接 Wi-Fi、不依赖云平台。软件基于 RT-Thread 4.1.1 与 LVGL 8.3.1：6 个线程按 12 至 26 级分层，两条消息队列分别喂报警与界面，互斥锁保护状态快照与传感器总线，阈值经信号量异步写入 LittleFS；界面四页缓存式切换，曲线保留最近 60 点环形缓冲且三通道不共用纵轴；报警带连续 3 次确认与 2 摄氏度、2% RH 回差，蜂鸣器走 PWM。另提供 12 条 MSH 诊断命令，可现场查采样有效位、触摸坐标与 UI 耗时。

六、总结与趋势观察

6.1 本期趋势

  • 高端 RISC-V 平台进入主线：K1 BSP 以 S 模式、MMU 与 4 核 SMP 的形态合入，配合 PCIe/NVMe、HDMI 与多媒体加速，标志 RT-Thread 在应用处理器级 RISC-V 平台上的支持从「能启动」走向「外设齐备」。
  • 驱动层按 SoC 家族沉淀：bsp/spacemit/dm 把约 30 个设备模型驱动独立成层，K1 只是第一个使用者，后续同系芯片可复用，BSP 目录结构开始出现「厂商层加板级层」的分工。
  • 框架随 BSP 一起修：同批提交里带出电源域代理命名、DVFS OPP 查重与 RISC-V 原子 CAS 三处框架与架构修正，说明新平台接入正在反向暴露通用代码的缺陷。
  • 安全债务清理进入修复期：上期四枚缺陷单中已有两枚开出修复提案（lwp 信号校验、OFW 深度预检），并新增一枚 tmpfs 截断缺陷；维护者对动态模块给出「局部修复可行、隔离需用户态」的边界判断。
  • 官方渠道继续静默：新闻接口停更逾四个月，v5.4.0 只有版本号先行，对外信息主要靠 GitHub 与社区作品。
  • 二进制固件合规需留意：K1 BSP 内嵌了取自厂商 Linux 镜像的 RCPU 固件（供 HDMI 音频服务），仓库说明中已给出校验值并提示合入前确认再分发条款，这类随 BSP 进入主线的厂商二进制值得后续跟踪。
