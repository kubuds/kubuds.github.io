一、内核与版本动态

1.1 K230D 合入：128MB DDR 变体接上 ext4 与 ptyfs（11-06）

日期：2026-11-06 09:37（合入时间）　来源：提案 #11897、提案 #11892

15 个文件、398 行新增、198 行删除，维护者 BernardXiong 提的，10 月 18 日建、本期合入。内容是一次 BSP 的完整补齐：新增 SOC_K230 与 SOC_K230D 二选一，按 128MB DDR 重排默认内存布局；把 GPIO 注册成 RT-Thread 的 pin 设备，驱动一次加 140 行，并补了 GPIO 测试；打开 ext4 根文件系统，挂载 ptyfs 与 procfs；删掉一批没有用到的板级外设定义。工具链保持 K230 SDK 的 riscv64-unknown-linux-musl，ABI 仍是 lp64d。

这条的分量在依赖关系：它要求先有 #11892 的 RISC-V MMU 与玄铁架构修正（上一期报告 1.2 那笔），还需要 lwext4 软件包；ptyfs 与 procfs 的挂载点正是 RT-Smart 终端与设备树导出的前提。也就是说，K230D 不是孤立加一块板，而是把 11-05 那批 Smart 修正在一块 128MB 内存的真实 RISC-V 板子上串起来。CI 尚未给出构建结论，作者只在本地用 K230 SDK 工具链编过。

1.2 STM32F1/H7 输入捕获落地：746 行补齐四路定时器（11-06）

日期：2026-11-06 09:20（合入时间）　来源：提案 #11975、议题 #11967

9 个文件、746 行新增、零删除。议题 11 月 2 日提出，此前论坛只有一份个人实现，四天后驱动进主线。实现用 STM32 HAL 的 TIM1 至 TIM4 做输入捕获设备，通道、滤波器与初始捕获极性都可配置；处理了 APB 定时器时钟倍频、TIMPRE 与 32 位计数器三处平台差异；重启捕获通道前先清挂起的捕获与过捕获标志。

CI 挂了两块板：STM32F103 战舰版挂 inputcapture 片段，STM32H743 Nucleo 挂完整配置。对使用者来说，这类外设框架补齐比内核修缺陷更能扩大适用面——输入捕获是电机控制、编码器与脉冲测量的常用路径。

1.3 非 SMART 的 CPU 时间记账纠偏（11-07）

日期：2026-11-07 21:39（合入时间）　来源：提案 #12001

只改 src/clock.c 两行：把用户态时间记账的分支用 RT_USING_SMART 包起来。此前非 SMART 构建也会走这段逻辑，线程时间被算进用户态，系统时间与空闲时间统计随之偏小。两行的改动，影响所有非 Smart 项目的 CPU 占用率读数。

1.4 GIC 打印函数的格式符纠正（11-08）

日期：2026-11-08 16:20（合入时间）　来源：提案 #11914

3 个文件、71 行新增、48 行删除，改 gic.c、gicv3.c 与 gicv3.h。四类问题：把 32 位物理地址用 %p 打印，向 %p 传非指针属未定义行为；把无符号量用 %d 打印；GIC 版本号的类型转换缺失；GIC RWP 宏里的一处有符号左移。提案 10 月 21 日建、11 月 8 日合入，作者 Wei-beep，共同作者是维护者 Rbb666。用 -Wall -Wformat 编 Cortex-A BSP 时不再刷警告。这类清理不影响功能，但直接影响厂商 BSP 的编译洁净度。

二、安全与 libc 修复

2.1 timerfd 两处校验同日合入（11-08）

日期：2026-11-08 14:12 / 14:11（合入时间）　来源：提案 #11996、缺陷 #11984、提案 #11997、缺陷 #11980

两笔相隔一分钟落地，各改一个文件。

第一笔是 timerfd_settime 与 gettime 的 fd 类型校验：原实现把任意文件描述符的私有数据当作定时器结构体解引用，传进来一个普通文件或管道，内核就会按错误类型读结构体。修法是先比对文件操作表，确认是 timerfd 才取私有数据，DFS v2 看 df->fops、v1 看 vnode->fops，25 行新增。

第二笔是 POSIX 定时器的数组越界：timer_gettime 与 timer_settime 直接拿用户给的 timer_t 当下标索引 _g_timerid，而 timer_delete 早就有边界检查。补上 id 不得大于等于 TIMER_ID_MAX 的判断，19 行新增。

这两处缺陷在前两期报告的安全清单里出现过，本期从已报告变成已修复。timerfd 与 POSIX timer 都属于用户可控句柄，问题模式一致：先解引用，再判断类型或范围。

2.2 picolibc 原型对齐：asctime_r 与 ctime_r 的数组参数（11-08）

日期：2026-11-08 14:01（合入时间）　来源：提案 #11999

ctime.c 13 行新增、3 行删除。picolibc 把缓冲区声明成长度 26 的受限数组，RT-Thread 用指针形式声明，于是数组参数与空指针比较两类警告一起出现；其它 C 库仍是指针形式，修法是用条件编译按库切换声明。作者 Parthiban Nallathambi，来自 Linumiz。

这笔单独列出的原因是它解开了另一条线的死结：瑞萨 RH850 移植提案明确写着 utest CI 要先等这个 ctime.c 修复，见 4.3。

2.3 RISC-V FPU 上下文切换缺陷：报告四小时后出修复提案（11-07）

日期：2026-11-07 23:10（报告）/ 2026-11-08 03:14（提案）　来源：缺陷 #12005、提案 #12006

本期最值得盯的一笔。报告者 boa-z 在移植 ArtInChip D213（C906，M 模式）时发现线程切换后 fs1 不对，为排除 BSP 因素，回到官方 qemu-virt64-riscv 复现，环境是 QEMU 10.0.13、OpenSBI 1.6、RV64D、单 hart、master c63d7bc9。他写了一个跨切换类型检查浮点寄存器的用例，坐实两个问题。

其一是自愿切换，也就是 rt_thread_yield：SAVE_CONTEXT 与 RESTORE_CONTEXT 只保存整数 callee-saved 寄存器，两个用浮点的线程互相覆盖 fs0 至 fs11，报告里给了实测值，期望 0x3ff0000100000000、实得 0x3ff0000000000000。其二是定时抢占：SAVE_ALL 存了 f0 至 f31 却没有存 fcsr，浮点舍入模式与异常标志会被静默改掉。这类问题不会崩，只会让计算结果慢慢漂移。

维护者 BernardXiong 四小时后提出 #12006：把 fs0 至 fs11 与 fcsr 追加进切换帧，trap 帧补 fcsr 的存取，切换帧大小向上取整保证 16 字节对齐，并为中断切换构造的帧初始化 fcsr；配套在 context_ext.h 与 stack.h 加偏移与布局宏。提案仍在审，尚无实机验证记录。考虑到 RISC-V 在 RT-Thread 里的权重，这条建议优先合入。

四、生态与厂商适配

4.1 QEMU 虚拟设备清单推进：SPI 回环、CAN、SDIO、DAC/I2C 进 CI（11-06）

日期：2026-11-06 至 11-08（合入时间）　来源：议题 #11972、提案 #11979、提案 #11990、提案 #11752、提案 #11758

本期最成体系的一条线。议题 #11972 是一份 QEMU 虚拟设备与覆盖率清单，背景写得很直接：按 #11955 的版本发布规划，Z 版本主要依靠 QEMU 加 CI 自动测试内核、组件与仿真支持范围内的驱动，汇总覆盖率、通过率与已知问题，供维护者决定是否发布。清单按框架逐项列 utest 与 QEMU 两个勾，覆盖 adc、dac、i2c、spi、can、pwm、rtc、watchdog、timer、touch、audio、usb、sdio、flash、ethernet、wlan、pin、serial 与 ipc 等二十余项。

窗口内落地的四笔：

  • SPI 虚拟回环总线（#11979，6 个文件、154 行）：注册一条纯软件 SPI 总线，默认名 spi2，用内存拷贝做回环传输，让 qemu-vexpress-a9 在没有 PL022 模型时也能跑 SPI 回环用例；配套加 utest 配置与 CI 矩阵项。
  • DAC 与 I2C 的 QEMU 任务（#11990）：各加一份 utest 配置，工作流里拆成两个独立作业。
  • CAN 收发测试（#11752，1792 行）：1572 行的用例文件，22 个主机桩场景，覆盖超时续期、tick 回绕、空读、错误传播与正常接收；作者用 50 tick 超时加 1000 tick 看门狗复现了原来的重复帧与不匹配帧挂死。
  • SDIO 块设备读写测试（#11758，438 行）：372 行用例，验证限定在格式与空白改动，未做整 BSP 构建。

仍在审的两笔同样属于这条线：触摸框架测试（#12002）让中断使能与禁用返回错误码，并用模拟操作在 QEMU 连跑两轮；dlmodule 回归（#11989）在构建时生成真实 ARM ELF 模块，10 个用例覆盖可重定位目标、共享目标、符号导入导出与重复加载卸载。测试基建正在从零散补用例变成按发布流程列清单，这是 Z 版本节奏的前置条件。

4.2 WCH 两条线：青稞快速中断配置与 CH32V208 低功耗（11-07）

日期：2026-11-07 至 11-08（提案时间）　来源：提案 #12004、提案 #12007

WCH 的 RISC-V 青稞内核在快速中断上并不齐整：不同型号支持程度不同，只有两级硬件中断的型号不该用快速中断。提案 #12004 按芯片系列配置对应的内核能力，新增快速中断开关，统一中断属性宏，让支持的芯片走快速中断、其余退回普通中断；顺带更新 SDK 并调整 CH32V203 启动文件。验证板是 CH32V208W-R0 与 CH32V307V-R1。

#12007 给 CH32V208 加 PM 组件支持，依赖前一笔记合入。两笔都还开着。WCH 是国内 RISC-V MCU 出货量最大的厂商之一，BSP 的电源管理与中断配置直接决定低功耗场景的可用性。

4.3 瑞萨 RH850 G4KH 移植提案：ARM 与 RISC-V 之外的第三个架构（11-06）

日期：2026-11-06 20:41（提案时间）　来源：提案 #11998

libcpu/rh850 用 TRAP0 做线程切换，含嵌套中断、FPU 上下文与故障转储；bsp/renesas/rh850 提供启动、中断控制器、OSTM 与 RLIN3 串口驱动，以及 qemu-rh850-u2c 板级；CI 覆盖硬浮点与软浮点两种构建加内核 utest。验证记录写得很实：GCC 14.3 加 picolibc 工具链 v1.1.0、qemu-rh850 v1.0.0，msh 能启动，kernel_basic 22/22，内存与 ipc 用例通过。

提案仍标草稿，原因就是 utest CI 需要先修 picolibc 下的 ctime.c，本期 #11999 已合入，这个前置条件解除。RH850 是车规 MCU 里常见的架构，RT-Thread 此前主力在 ARM 与 RISC-V，这一笔如果合入，等于把 utest 与 libcpu 抽象拿到第三个架构上验证。

5.1 睿擎进 PLC：Vinaro 沙龙上的「1+X+N」与微秒级指标（11-06）

日期：2026-11-06 13:03（发布）　来源：官方新闻

由上海开放处理器产业创新中心主办、上海市经信委指导的 Vinaro 技术沙龙工业控制与 PLC 专题在浦东创芯天地举行。睿赛德联合创始人兼工业事业部负责人邱祎讲《RT-Thread 睿擎工业开发平台加速工业设备演进》，给出「1+X+N」架构：一是统一基础软件平台，含硬件抽象、实时调度与工具链；X 是可复用工业组件，包括协议栈、边缘计算框架与安全模块；N 是电力、工控、轨交等细分行业方案。

指标写得具体：基于硬实时内核做到任务响应不超过 1 微秒、中断抖动不超过 5 微秒；已适配 EtherCAT、Profinet、Modbus、CANopen 与 OPC-UA；在三电控制、工业网关与 PLC 控制器上量产。RISC-V 侧的家底是 2018 年启动适配，30 余款 BSP、千余款芯片，覆盖芯来、兆易创新与玄铁等厂商。

六、总结与趋势观察

  • 三天十一笔，测试基建成为主线：11-06 五笔（K230D、STM32 输入捕获、CAN 与 SDIO 用例、DAC 与 I2C 的 CI）、11-07 一笔（CPU 时间记账）、11-08 五笔（GIC、timerfd 两笔、picolibc、SPI 回环）。与 11-05 单日 31 笔的清账高峰相比，本期是收尾加基建：真正的新功能只有 K230D 与输入捕获，其余一半以上在补测试与修编译告警。

  • 安全议题换了边界：前几期集中在系统调用层的用户指针，本期合入的是其中两笔 timerfd 修复；新报告转向两类，设备提供的输入（ivshmem、Bouffalo ADC 通道）与架构状态（RISC-V 的 fcsr 与 fs0 至 fs11）。后者更隐蔽，不会崩，只会让浮点结果漂移。

  • 版本节奏仍停在 v5.3.0：窗口内无新 tag 与 release，v5.4.0 还在开发线，缺陷报告引用的是 master 的 c63d7bc9。但 Z 版本 CI 的两份纲领性文档已经出现——议题 #11956 的版本管理流程与 #11972 的 QEMU 虚拟设备清单，都以人工批准发布为终点。下一阶段的观察点是这两份清单能否在 QEMU 上真正跑通。

  • 对外传播补课：官方新闻接口停了四个多月后一次补发七篇，把 9 月的 elexcon、9 月中旬的汽车沙龙、10 月的工博会与 RISC-V 峰会、11 月初的乌镇峰会串成一条线。叙事统一为 AIOS 混合部署加端侧 AI，落点是工业、汽车与机器人。事件不新，但口径齐了。
