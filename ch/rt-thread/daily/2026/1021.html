一、内核与版本动态

1.1 RISC-V 票号自旋锁改用原子加：多核争用下的活锁路径被移除（10-20）

日期：2026-10-20 16:04（创建时间）　来源：PR #11904、cpuport.c

维护者 GuEe-GUI 提交 RISC-V 公共层的票号自旋锁改造（6 文件 +33/-37，两笔提交）。原实现取号与释放都在同一个 32 位字上走「加载保留加条件存储」的循环：高 16 位是待发票号、低 16 位是当前持有号；一旦解锁方在同一字上重试条件存储，取号方的保留会被反复冲掉，多核高争用下可陷入活锁。新实现把取号换成一条原子加指令，向高半字加一即完成取号，不可能与解锁争用同一保留；解锁改为只由持有者写低半字，一次半字存储完成、不再读改写整字，因此在取号并发进行时也不会覆盖新票。拿到锁后另补一次内存屏障，保证临界区访问排在观察到释放之后。提案标为成熟版本，分派给 RISC-V 内核评审。

1.2 同优先级线程就绪顺序修复提案：IPC 唤醒与新启动改为追加队尾（10-21）

日期：2026-10-21 00:06（创建时间）　来源：PR #11907、Issue #8459

社区成员 Yunlk 就就绪队列插入顺序问题开出修复（4 文件 +255/-22，含新增 utest）。原逻辑对任何没有「已让出」标志的线程都插到队首，而线程被切走时该标志会被清掉，于是从信号量等 IPC 挂起队列恢复的线程、以及新启动的线程全都插队首，同优先级线程的实际执行顺序与就绪顺序相反。提案先保存原始状态再覆盖，只有「仍在运行、且时间片未用尽被抢占」这一种情况保留队首插入，其余一律追加队尾；单核与多核两处插入分支做一致修改，并新增一个覆盖信号量唤醒与启动两条路径的用例。作者在 qemu-vexpress-a9 实测：修复前信号量唤醒顺序为乙甲、启动顺序为丁丙，修复后分别为甲乙与丙丁。提案仍在审，两个工作流待维护者批准。

1.3 串口 V1 补上接收超时事件：超时并入 RX_IND 回调（10-21）

日期：2026-10-21 00:15（创建时间）　来源：PR #11909、Issue #8143

接收超时事件（编码 0x05）在头文件里早有定义，但 V1 框架的中断处理只覆盖前四个事件且没有兜底分支，驱动发出该事件时框架什么都不做，通知被静默丢弃。仓库里恰有两个驱动依赖它切分数据帧：沁恒 CH579M 与华芯微特 SWM341 都用芯片的接收超时中断判定「一帧收完」，两者都在 V1 框架上，结果是帧边界实际丢失，只能退化成按硬件水位上报。提案把该事件并入接收指示回调：先排空硬件 FIFO，再按软件 FIFO 已缓存长度回调上层。改动仅一行分支（含注释共 5 行），未动 V2，因为 V2 头文件根本没有这个宏。作者只做到编译级验证，缺少带空闲超时中断的硬件，另提出可在伪串口设备上补用例进 CI。

二、安全与稳定性跟进

2.1 cromfs 目录名长度未约束：ls/getdents 越界并劫持内核 PC（10-20）

日期：2026-10-20 19:29（创建时间）　来源：Issue #11905

贡献者 XueDugu 新开 cromfs 缺陷单。读取目录项时对目录名长度不做任何上界检查，超长名字会把内容拷进固定大小的目录项缓冲、越过其尾部，溢出量足够改写相邻数据，ls 或读取目录即可触发，作者称可将内核程序计数器导向可控位置。缺陷由 2022-12-14 的一笔 cromfs 同步提交引入，v4.1.1 尚无此问题，自 v5.0.0 起至 v5.3.0 与当前主线全部受影响；DFS 的两份实现同源，v1 与 v2 各有一份未加约束的拷贝。作者在 QEMU vexpress-a9 上复现，单子目前未被认领。

2.2 OFW 深度预检改为调试门控：维护者建议后作者加编译开关（10-20）

日期：2026-10-20 09:11 ~ 16:03（评论时间）　来源：PR #11901、Issue #11879

上期收录的设备树深度预检提案在本窗口走完一轮评审。评审先质疑预遍历的开销，建议改用运行期检查、超限即退出并释放内存；作者回应称不完整树的释放要沿指针递归遍历，分配点零散、易漏或重复释放，而检查函数只读、不分配、不解析属性，相对展开本身开销很小。随后维护者给出方向：OFW 在设计上偏信任固件，64 层远超多数 SoC 的实际需求，建议只在调试模式下启用这段检查。作者接受，把深度检查包进调试开关，并在 qemu-virt64-aarch64 上开启调试模式、用一棵 65 层设备树复测。改动已推送，提案仍在审。

2.3 tmpfs 截断缺陷在 RT-Smart 的 aarch64 上复现并被认领（10-20）

日期：2026-10-20 22:53（复现评论）　来源：Issue #11902

上期收录的 tmpfs 截断缺陷在本窗口补上设备侧证据。社区成员在 RT-Smart 的 qemu-virt64-aarch64 板级上复现：把文件截断到 0 字节时，缓冲区被释放、函数却返回成功，应用随后读写落在已释放的内核堆上，可造成信息泄露与双重释放。复现环境为 QEMU 11.0.0 的 virt 机型加 GICv3、交叉工具链 15.2.1、DFS_V2 配置。该单已于 10-20 由另一位社区成员认领，修复补丁尚未提交。

2.4 其余在审进展：中断应答修复待复测、IAR 隐式声明讨论继续（10-20）

日期：2026-10-20（评论时间）　来源：PR #11860、PR #11864、Issue #9941、PR #10096

4.2 中文 Windows 下 scons –attach 崩溃：表情符号换 ASCII 的修复提案（10-20）

日期：2026-10-20 23:42（缺陷单创建）　来源：Issue #11906、PR #11908

中文 Windows（代码页 936）下执行 scons --attach 会直接抛编码异常、整条命令中止：提示语里用了两个表情符号，GBK 无法编码。该命令的三种用法都走同一个函数，等于在中文环境完全不可用；设环境变量强制 UTF-8 可绕过，但普通用户不会知道。缺陷单当天提交，同日给出修复提案，把 4 处符号换成 ASCII 标记并保留原有 ANSI 颜色，作者称与仓库其他脚本的彩色输出惯例一致。另有一条评论说明该提案的内存报告检查失败源于上游第三方 action 自身损坏，与本改动无关。

4.3 全志 D1s 增加 QEMU 运行脚本，维护者建议改为 target-qemu 目录（10-20）

日期：2026-10-20 13:45（创建时间）　来源：PR #11903

全志 D1s 的板级支持此前只能上实板。提案新增启动脚本，调用一个独立仓库里的 D1s 模拟机型（单核、64 MB 内存、两路串口、中断与定时器、两路存储控制器），复用本目录的引导固件与设备树，串口作控制台，按默认配置可完成存储初始化并进入命令行。评审未直接接受脚本形态，而是建议在板级或芯片厂商目录下建统一的目标机子目录，放启动脚本与一份面向 AI 的构建说明，使其成为可复现的验证环境；作者尚未回复。

六、总结与趋势观察

6.1 本期趋势

  • 内核两条底层路径同时被修：调度器把同优先级就绪顺序拉回先来先服务，RISC-V 票号锁把取号改为单指令原子加、释放改为半字存储。前者影响执行顺序的可预期性，后者影响多核争用下的活性，两处都属长期被默认行为掩盖的问题。
  • 外设事件语义开始补齐：串口 V1 终于把「接收超时等于一帧结束」接进框架，受影响的恰是两个靠空闲中断切帧的国产板级支持，说明框架层的历史缺口仍在被逐个发现。
  • 缺陷发现继续由外部研究者驱动：本期 cromfs 越界单把影响面回溯到 v5.0.0，并指出 DFS 两份实现同源，这类带版本区间的报告比单点补丁更有价值，也提示 v1 与 v2 并行维护带来的重复风险。
  • 厂商平台从能启动走向可交付：K1 默认开到 8 核、SPI 与 QSPI 状态转正并进入支持矩阵；D1s 补上模拟器运行路径，评审把「可复现环境」提升为目录规范与面向 AI 的说明文档，属平台化思路。
  • 工具链的本地化细节进入视野：中文 Windows 下表情符号导致构建命令中止，问题小但影响面大，反映跨平台可用性测试仍是短板。
  • 官方渠道继续静默：新闻接口停更逾四个月，版本发布仍停在九月，对外信息主要靠 GitHub 与社区作品，这一格局已连续两周未变。

6.2 局限性与去重说明

  • 本期为 24 小时窗口（10-20 08:00 ~ 10-21 08:00），非周一，不做多日合并。
  • 主仓库窗口内无合入，全部条目来自提案、缺陷单与社区侧，故「内核与版本动态」中的三节均为在审提案而非已落地改动，各条已注明状态。
  • 与上期去重：设备树深度预检（#11901）与 tmpfs 截断单（#11902）本身在上期已收录，本期只写窗口内新增的评审结论与设备侧复现；中断应答（#11860）、IAR 隐式声明（#11864）、按需编译（#10096）与 attach 配置（#9941）均为更早条目，本期只记进展。
  • 两件大赛作品的主控均非 RISC-V：纳芯微 NS800RT7P65 是 Cortex-M7，联网侧的乐鑫 ESP32-C3 才是 RISC-V；Edgi-Talk 为 Cortex-M55 加 M33。收录原因是 RT-Thread 应用案例与工具链实践，不作 RISC-V 适配解读。
  • 组织级全量推送未能通过接口核查（匿名限额耗尽），改用仓库提交流与组织页交叉验证；Studio 的 SDK 索引经提交流确认停在 10-10。
  • 论坛文章接口只取前 20 条，超出部分未核；官方新闻列表页为前端渲染，抓取只得空壳，新闻以接口为准。
  • 谷歌新闻英文窗口零命中，中文三天的 2 条中 1 条为已收录稿、1 条为 10-18 旧稿；睿擎查询仍被同名汽车稿件淹没，均未产生额外条目。
