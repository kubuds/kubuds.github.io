一、内核与版本动态

1.1 沁恒 CH32V203C8T6 开发板 BSP 合入主线（09-24）

日期：2026-09-24 16:21（北京时间，合入时间；提案创建于 09-22 晚间）　来源：PR #11827、合入提交 386b877b

主线在窗口内合入一笔新板级支持：沁恒微（WCH）CH32V203C8T6-EVT-R0 开发板 BSP，落位 bsp/wch/risc-v/ch32v203c-evt-r0。该板为青稞 V4B 内核（CH32V20x_D6），64KB 零等待 Flash 与 20KB SRAM；因官方 SDK 只提供 D8W 启动文件、对 D6 直接调用 Exit()，常规软件包构建无法产出固件，提案以 D6 中断向量表（软件中断符号 SW_handler）与 64KB/20KB 链接脚本补齐，并仅在该条件下修补 SDK 包脚本，不影响 D8W 流程。默认镜像启用 GPIO 与 UART1（USART1 复用 PA9/PA10），PWM、ADC、RTC、独立看门狗与 USB 设备保留在 menuconfig 中（64KB 容量无法同时容纳 USB 与前述四类外设）。提案另附带两处共享驱动修复：drv_usbd.c 调整 USBFS DMA 的 16 位 SRAM 偏移与 SET_ADDRESS 写入时序（端点缓冲须驻留 SRAM、全速包长 64 字节），drv_iwdt.c 为 CH32V2 系列补充适配。提案共 4 笔提交、26 个文件（+2216/-57）。

1.2 rt_vsnprintf 宽度语义缺陷与内核修复提案（09-24）

日期：2026-09-24 20:52 ~ 21:29（北京时间，缺陷报告与修复提案的时间）　来源：Issue #11833、PR #11834

社区贡献者在窗口内提交内核缺陷报告与配套修复：当前 rt_vsnprintf 实现（尤其 tiny 版本）对 %[width].[precision]s 的语义处理有误，最小宽度被误作最大宽度截断——例如 %3s 格式化 “abcdef” 输出 “abc” 而非完整字符串，左对齐 %-3s 与 %*s 等变体同样受影响。修复提案同步提交，改动覆盖 rt_vsnprintf_std.c、rt_vsnprintf_tiny.c 与对应单元测试 TC_rt_sprintf.c（共 3 个文件，+37/-18），内容为补充边界检测、实现宽度与精度的组合功能并优化测试用例。缺陷报告已有 3 条讨论，修复提案处评审状态。

1.3 评审队列新增三条提案：网络栈修复与构建清理（09-24）

日期：2026-09-24 14:15 ~ 17:52（北京时间，创建时间）　来源：PR #11831、PR #11835、PR #11832

本期评审队列合计新增五条提案，其中内核 vsnprintf 修复见 1.2、ESP32-C6 板级支持见 3.1，本条收录其余三条。其一修复 lwip-nat 的端口分配缺陷：原实现按扫描计数器而非空闲槽位索引分配转换端口，进入分配路径时计数器恒等于表大小，导致每个新映射都拿到同一端口，并发 UDP/TCP 会话相互冲突、回程流量可能匹配到错误表项；提案同时完成 lwIP 2.1 适配（头文件更名与超时接口），并把 NAT 应用条件收紧为源与目的网络均匹配规则、ICMP 表满时按 LRU 淘汰最旧条目（1 个文件，+41/-11）。其二为 lwip-dhcpd 补上缺失的 string.h 头文件：dhcp_server_raw.c 直接调用 memcmp / memset / strlen / strncmp / strchr 而未包含标准头，隐式声明在 64 位目标上会截断 strchr() 返回指针（1 个文件）。其三移除 components/drivers/ipc/SConscript 中冗余的 __RT_IPC_SOURCE__ 宏定义（1 个文件）。

三、生态与厂商适配

3.1 乐鑫 ESP32-C6 开发板 BSP 提案与软件包源码同步提交（09-25）

日期：2026-09-25 01:20 ~ 02:38（北京时间，提案与配套软件包提案的创建与更新时间）　来源：主线 PR #11836、esp-idf 软件包 PR #17

社区贡献者在窗口内为乐鑫 ESP32-C6-DevKitC-1 开发板提交主线 BSP 提案：模组为 ESP32-C6-WROOM-1（RISC-V，8MB Flash），新增 bsp/ESP/ESP32_C6，默认启用 GPIO、UART0（GPIO16/17）与 ADC；提案强调 C6 须使用专用 bootloader 镜像（不可复用 C3 的镜像）、Flash 为 DIO 8MB 80MHz、应用偏移 0x10000。由于上游 esp-idf 软件包自 2023-11-26 起未更新、缺少 C6 源码，贡献者同步在软件包仓库提交 PR #17 补上 C6 的 scons 构建源码，两处提案均处评审状态（主线侧 2 笔提交、40 个文件，+9492/-50）。该贡献者与 1.1 中 CH32V203 BSP 的提交者为同一人，同日横跨沁恒与乐鑫两条 RISC-V 芯片线。

3.2 社区发布 RT-Thread Nano 免 IDF 移植工程：运行于 ESP32-S31（09-25）

日期：2026-09-25 10:04（北京时间，推送时间）　来源：esp32s31_rtt_nano 仓库

社区开发者公开一份面向乐鑫 ESP32-S31（双核 RISC-V，主频 320MHz，板载 16MB Flash 与 16MB PSRAM）的 RT-Thread Nano 移植工程，特点是完全绕开 ESP-IDF 构建系统：自写启动汇编与链接脚本、直接用 riscv32-esp-elf-gcc 编译、独立 esptool 烧录，镜像由芯片 bootROM 从 Flash 0x2000 直接加载（不使用 IDF 二级 bootloader）；控制台走芯片内置 USB-Serial/JTAG，tick 采用 SYSTIMER、中断走 CLIC，PIN / SPI（含 QSPI）/ I2C 外设接入 RT-Thread 设备框架，可在 msh 中直接验证。工程已做可复现构建验证（89 个跟踪文件在干净目录构建出逐字节一致的镜像）。属个人项目，供社区参考。
