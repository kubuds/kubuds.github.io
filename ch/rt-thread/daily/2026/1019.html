一、内核与版本动态

1.1 内核版本号切换至 v5.4.0：版本宏与 Kconfig 先行，发布物尚未落地（10-17）

日期：2026-10-17 09:43（合入时间）　来源：PR #11875、include/rtdef.h

维护者 Rbb666 合入版本切换提案（2 文件 +4/-3）：include/rtdef.h 的版本宏由 5.3.1 改为 5.4.0，并补一条 2026-10-17 的变更记录；src/Kconfig 中 RT_VER_NUM 的默认值由 0x50301 改为 0x50400。作者以 qemu-vexpress-a9 默认配置执行 scons –pyconfig-silent，确认生成的 rtconfig.h 中 RT_VER_NUM 为 0x50400。截至 10-19，仓库最新的 tag 与 release 仍为 v5.3.0（09-10 发布），ChangeLog.md 标题仍是 v5.3.0，说明本次只是版本周期的起点，5.4.0 的发布说明与发布物尚未出；窗口内的社区缺陷单已把 master 标注为 v5.4.0-dev。

1.2 Next RISC-V 大重构合入：165 文件统一 RV32/RV64，Sv32~Sv57 与 AIA 一并落地（10-17）

日期：2026-10-17 09:44（合入时间）　来源：PR #10320、Issue #10722

历时近五个月的 RISC-V 架构重构（#10320）合入，4 笔提交、165 文件 +15134/-2617。内容含 ISA 管理接口、32E/32I/64I 合并、按 CBOM ISA 处理缓存、Sv32/Sv39/Sv48/Sv57/Sv64 MMU 与 SVPBMT、M 态与 S 态 CSR 操作合并、SMP、APLIC/IMSIC（AIA）、CLIC、ACLINT/CLINT、INTC 与 PLIC、可选 DM（仅经 OFW）、T-HEAD 厂商代码合并，并在 qemu-virt64-riscv64 移植 DM、支持非 0 号核启动。计划表中 S-mode RT-Thread、S-mode RT-Smart（含 APP、DM、无 MMU、无 DM）与 M-mode（DM、无 DM）均已勾选，BSP 适配仍待推进。同日 #10722、#9571、#9567、#9566、#9521、#11226 六枚 RISC-V 任务单集中关闭。

1.3 RT-Thread Smart 十三笔提案批量开出：syscall 拆分、信号与 MMU 修复、K230D 适配（10-18 ~ 10-19）

日期：2026-10-18 19:35 ~ 10-19 02:49（创建 / 更新）　来源：PR #11896、PR #11897、PR #11892

维护者 BernardXiong 于 10-18 19:35 至 19:36 两分钟内连开 13 笔提案（#11885 ~ #11897），截至本期截点全部在审。主线是把 Smart 在 QEMU 与真实板卡上跑通：qemu-virt64-riscv64/aarch64 启用 RT_USING_SMART、riscv64 关闭 SMP、在 virtio-blk 上挂 ext4/elm 并挂载 ptyfs 与 procfs；libcpu/riscv 修正早期页表物理偏移换算、按核页表继承用户映射、用户态异常处理，并新增玄铁架构选择与 SVPBMT；lwp 拆分 syscall 实现、修正信号投递顺序与 ELF 段保护、补齐 TIOCLINUX 与 TIOCGWINSZ；K230D 增加 128MB DDR 配置与 ext4 根文件系统。另有 SAL RAW socket 协议校验、lwip 回环网卡、8250 earlycon 寄存器宽度、SDIO 块大小、poll 走 DFS 文件操作与 UTIME_OMIT 修复。

1.4 ESP32-C6 SPI 提案整改后合入：分段传输、BSP 自有 gdma、位宽校验前移（10-16）

日期：2026-10-16 11:31（合入时间）　来源：PR #11846、PR #11870

上期处于评审的 ESP32-C6 SPI 提案经评审整改后合入（7 文件 +1253/-26）：关闭 DMA 时按 IDF 单次 64 字节上限分段发送，gdma.c 改为 BSP 自有副本以免 C3/C6 共用构建互相改写，位宽校验前移到总线初始化之前。行为上，只有选择 BSP_USING_SPI 才链接 IDF SPI master，默认镜像仍关闭 SPI；共享 ESP 驱动不再穿透 SPI 模式、返回实际传输字节数，片选取自 SPI2_IOMUX_PIN_NUM_CS，配置为空时返回 -RT_EINVAL。同期把 C3/C6 适配到 ESP-IDF v6.1、RISC-V 工具链升到 GCC 15.2 的提案（#11870）仍在审。

1.5 HPMicro BSP 升至 hpm_sdk v1.13.0，新增 HPM5100EVK 板级支持（10-17）

日期：2026-10-17 16:28（合入时间）　来源：PR #11871、packages 索引提交

bsp/hpmicro 由 hpm_sdk v1.10.0 升至 v1.13.0（434 文件 +23873/-16669）：新增 hpm5100evk（HPM5151）的 board、startup、applications、Kconfig、文档与图片，并登记进 ALL_BSP_COMPILE.json 与 BSP 清单；11 块既有板卡按新 SDK 重新同步，保留 RT-Thread 侧改动（基于 clock_time 的 drv_timer、scons 接入 CXX、产物输出到 build/、具名 Kconfig choice、board_delay_* 走 rt_hw_us_delay、板级 codec 文件等），驱动层同步到 v1.13.0。软件包索引已于 10-14 先行加入 hpm_sdk v1.13.0。

1.6 安全审计四连发：libdl 任意写、lwp 信号越界、OFW 栈溢出、lwip-dhcpd 远程拒绝服务（10-17 ~ 10-19）

日期：2026-10-17 14:25 ~ 10-19 00:37（创建 / 更新）　来源：Issue #11898、Issue #11882、Issue #11879、Issue #11878

贡献者 XueDugu 在窗口内连开四枚缺陷单，均给出引入提交、受影响版本区间与 QEMU 复现环境。#11898：libdl/dlmodule 对 ELF 重定位元数据不做边界校验，畸形 .mo 可在加载阶段以受控值写内核态内存，最早可追到 2018 年 v3.1.0 的提交，ARM/RISC-V/x86 三套重定位实现同构。#11882：lwp 的 sys_sigaction 未校验信号编号，可越界读写内核堆（Smart，自 v5.0.0）。#11879：OFW 设备树展开无嵌套深度限制，会溢出 64 项 np_stack（自 v5.0.2）。#11878：lwip-dhcpd 租约池耗尽后 dhcp_client_alloc 死循环，可被未认证远端打满整个 lwIP 栈（自 v4.0.0）。四单均保持开放。

1.7 DFS 撞码提案关闭后改写重开：设备控制命令改按设备类编码（10-17）

日期：2026-10-17 16:55 ~ 17:06（关闭 / 重开时间）　来源：PR #11869、PR #11881

上期记录的 DFS 层 F_GETFL/F_SETFL 与 RT_DEVICE_CTRL_* 撞码提案（#11869）于 10-17 16:55 关闭，未合入；11 分钟后作者 CXSforHPU 另开 #11881（3 文件 +37/-20），改从编码层面解决：引入 RT_DEVICE_CTRL_BASE(Type) =（设备类 + 1）× 0x100，高字节表示设备类、低字节表示类内序号，并把 pin 配置命令、串口硬件控制命令迁到各自类基址之后，使通用控制命令不再与 POSIX 的 3 与 4 撞码。新提案在审。

2.2 社区教程：从 HardFault 提取 Cortex-M 崩溃现场（10-17）

日期：2026-10-17 17:04（发布时间）　来源：社区文章

社区作者「大目熊」发布 Cortex-M 崩溃定位系列上篇，讲清 HardFault 的处理思路：异常入口已把 8 个关键寄存器压栈，错误原因写入 SCB 状态寄存器，开发者只需在 HardFault 中读出并打印，就能定位到出错位置；文章按 HFSR 的说明梳理触发路径，并指出本系列上篇只解决「打印现场」，调用链回溯留待下篇。对缺少 core dump 机制的 MCU 固件调试有直接参考价值，也补足了社区在系统级排障方法上的内容。

五、总结与趋势观察

5.1 三日趋势（10-16 ~ 10-19）

  • 版本周期切换：v5.4.0 的版本宏与 Kconfig 先行落地，tag、release 与 ChangeLog 仍停在 v5.3.0，说明 5.4.0 进入开发周期而非已发布。
  • RISC-V 重构落地：165 文件、+1.5 万行的 Next RISC-V 合入，把 RV32/RV64、Sv32~Sv57、AIA/CLIC 与 M/S 态统一到一套 ISA 管理接口，六枚长期任务单同日关闭。
  • Smart 成为主线：13 笔批量提案覆盖 syscall、信号、MMU、rootfs、QEMU 与 K230D，方向从「能启动」转向「可测试、可交付」。
  • 安全债务集中暴露：四枚缺陷单跨 libdl、lwp、ofw 与 lwip-dhcpd，最早可追到 2018 年引入的代码，三枚影响 v5.0 之前版本，一日四单的密度在近期窗口中少见。
