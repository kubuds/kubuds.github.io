一、内核与版本动态

1.1 静默两天后主线恢复合入，4 笔在六分钟内落地（10-27）

日期：2026-10-27 19:20 ~ 19:26（合入时间）　来源：主仓库提交记录、提案 #11885

主线在 10-25 晚间之后停了约两天，10-27 19:20 至 19:26 六分钟内连续合入 4 笔，全部由同一位维护者操作，改动落在 dfs、net/sal、libc/posix 与 drivers/serial 四处，合计新增 46 行、删除 6 行。四笔里有三笔的 author 时间是 10-18，属于积压提案的集中落地，不是当天新写的代码。这也是本期唯一一次主线变动。

1.2 dfs 的 UTIME_OMIT 判断写反，要求不改的时间戳反被覆盖（10-27）

日期：2026-10-27 19:20（合入时间）　来源：提案 #11885

dfs_v2 的 utimensat 实现里，UTIME_OMIT 的分支条件写反了。按 POSIX 语义，置了 UTIME_OMIT 的那一项时间戳必须原样保留；原代码在取反后的条件下继续写 mtime，等于把调用方明确要求不动的时间戳覆盖掉，同时丢掉一个有效的时间戳。修法只改一个比较符，文件 dfs_posix.c 净变化一行。这类语义偏差在只测「设时间成功」的用例里看不出来，属于隐蔽型缺陷。

1.3 RAW socket 协议校验改用白名单，ICMP 这类协议不再被挡（10-27）

日期：2026-10-27 19:21（合入时间）　来源：提案 #11888

SAL 层创建 RAW socket 时，原来用 protocol 是否等于 IPPROTO_RAW 这一个等值判断把关，结果除 IPPROTO_RAW 之外的协议一律被拒，ICMP 这类需要原生套接字的场景走不通。本次改为 VALID_PROTOCOL 白名单校验，domain 与 type 的既有校验保持不变。同一提案还跟了一笔纯格式化的宏对齐修改，无功能变化。改动落在 sal_socket.c，净变化一行。

1.4 poll 改从 dfs_file 取 fops，DFSv1 与 DFSv2 同时兼容（10-27）

日期：2026-10-27 19:21（合入时间）　来源：提案 #11887

poll 之前直接从 vnode 取 fops，在 DFSv2 下拿到的结构与实际文件操作表不是同一套，等于把 poll 挂到错误的分发入口上。本次改为通过 dfs_file 解析 fops，同时保留 DFSv1 的兼容路径，并在解引用前加空指针校验。改动集中在 poll.c，新增 14 行、删除 2 行。这是 DFSv2 切换后遗留的一类适配问题，修复方式偏向保守而不是重写。

1.5 8250 earlycon 开始读 reg-io-width，宽寄存器平台不再按字节访问（10-27）

日期：2026-10-27 19:26（合入时间）　来源：提案 #11889

早期串口控制台此前不管设备树怎么写，都按字节宽度访问寄存器。本次从设备树读 reg-shift 与 reg-io-width，按 reg-io-width 选择 MMIO 访问宽度，并在早期初始化阶段直接拒绝不支持的宽度，其它 compatible 仍走通用 8250 路径。改动落在 early.c，新增 30 行、删除 2 行。对寄存器步长或位宽非默认的平台，早期日志错位与乱码有了统一解法，不必再逐板改代码。

1.6 发布侧仍停在 v5.3.0，主线 10-17 已 bump 到 v5.4.0 但未打 tag（10-27）

日期：2026-10-27（核查时间）　来源：版本发布记录、标签列表

releases 与 tags 两侧 24 小时内都没有新条目，最新发布版仍是 9-10 的 v5.3.0。主线在 10-17 有一笔版本号上调到 v5.4.0 的提交，说明开发分支版本号已经走到 5.4.0，但仓库还没有对应的 tag 与 release 记录。按往年节奏，正式发版一般在打 tag 之后才对外公告，本期尚不构成发版信号。

2.1 signalfd 关闭路径补上槽位越界与监听器解绑（10-27）

日期：2026-10-27 08:34（创建时间）　来源：提案 #11935

针对昨日日报记录的 signalfd 全局计数越界，社区当天提交了修复提案。做法是把全局索引计数器换成按上下文定位、带上限的槽位查找；signalfd_close 时遍历已注册的 lwp，把对应的通知节点从链表摘下并释放监听器结构，最后重置文件上下文指针并把表项清零，避免残留指针再被解引用。提案净增 41 行，单文件改动，当前可合并。原 Issue 与提案相隔不到一天，响应速度少见。

3.3 电子工程专辑三大 RTOS 横评，RT-Thread 在低功耗与消费级场景被列为优选（10-27）

日期：2026-10-27 22:27（发布时间）　来源：电子工程专辑：三大 RTOS 深度横评

电子工程专辑旗下专栏发布三大 RTOS 横评，按实时性、内存占用、生态、社区、AI 支持与迁移成本六个维度对比 FreeRTOS、RT-Thread 与 Zephyr。文中给 RT-Thread 的定位是 Apache 2.0 的轻量全家桶，内核 3KB Flash 加 1.2KB RAM，内置 POSIX、GUI、文件系统与 AI 包；低功耗组件在 Stop 模式下比另两者省电 15% 至 20%。选型决策表把 64KB RAM 以下的极致低成本项目、以及消费电子与可穿戴划给 RT-Thread。文章同时承认 Zephyr 在多协议多板卡与长期维护场景更强，结论是三分而不是一边倒，数据引自各项目官方文档与第三方基准，未见厂商投放痕迹。

安谋科技在上海西岸国际科技消费嘉年华（WTCC 2026）期间办小型具身智能方案研讨会，瑞芯微、瑞莎计算机与 RT-Thread 以开源 AIOS 联盟伙伴身份参加。RT-Thread AI 资深工程师郑炜按机器狗、HyperCar 与 Codex 编排三类 Agent 方案，讲智能体如何从对话走向执行，并明确 RT-Thread 后续以具身智能项目为重点，与安谋科技一起把 Agent 能力对到真实应用上。瑞芯微提出大模型推理正从计算密集转向内存密集、带宽成为端侧瓶颈，用主控 SoC 加 AI 协处理器解耦算力与控制。安谋科技同场发布 JishuFriends 与 JishuBuddy 两项落地成果。

4.2 K230 上的厨房火焰检测原型公开源码与复现记录，底座为 RT-Thread Smart（10-27）

日期：2026-10-27 19:19（推送时间）　来源：SRTP-K230-Fire-Guardian

一个以 K230 与 RT-Thread Smart 为底座的厨房火焰检测原型公开源码，内容包括多传感器融合、自适应联动策略、复现记录与模型评测，仓库同时放了参考资料，便于第三方按记录复跑。项目自述定位是研究原型而非产品。这是本期生态侧少见的、把 RT-Thread Smart 用在真实感知闭环里的公开项目，对评估 Smart 在视觉类场景的可用性有参考价值，也能看出 Smart 在板卡厂商之外的社区侧开始有人动手。

4.3 CH32H417 双核 RISC-V 上用 RT-Thread 加 LVGL 与 TFLM 做手写符号识别（10-27）

日期：2026-10-27 08:41（推送时间）　来源：ch32h417-tinyml-symbol-recognition

沁恒 CH32H417 双核 RISC-V 平台上的手写符号识别项目，技术栈是 RT-Thread 加 LVGL 加 TFLM，链路包含 OV5640 采集、定点图像预处理、INT8 量化模型推理与界面显示，训练侧另附工具链。项目刚建立、尚无关注度，价值在于把 RISC-V 上一条完整的轻量视觉链路摊开写清楚，从数据采集到量化部署都可对照，对准备在国产 RISC-V MCU 上做端侧推理的团队是可复用的样例。

五、行业应用与具身智能

5.1 AIoT 大赛作品转向工业侧：Titan Board 上做 BLDC 电机缺陷 AI 监测（10-27）

日期：2026-10-27 11:50（媒体转发）　来源：电子工程专辑：BLDC 电机缺陷 AI 监测系统

电子工程专辑转发 2026 RT-Thread AIoT 大赛的一项参赛方案：在瑞萨 Titan Board 上做 BLDC 电机运行状态缺陷的 AI 监测。硬件是 RA8P1，1GHz Cortex-M85 加 250MHz Cortex-M33 双核，带 Ethos-U55 NPU、单芯片 256 GOPS。系统采集三相电流、母线电压与逆变器温度，在 M85 核预处理后送进部署在 NPU 上的轻量 CNN，做实时缺陷识别；软件侧用 RT-Thread 起三个核心线程，分别负责界面显示、数据通信与 AI 推理，界面基于 LVGL，模型经 RUHMI 从 TFLite 转成 C 代码集成。方案强调不额外加传感器，只从驱动电流电压分析状态，走的是低成本预测性维护路线。

5.2 本期线索：芯片厂、板卡厂与操作系统侧在联盟框架下同台，落点一致指向具身智能（10-27）

日期：2026-10-27（本期）　来源：快科技报道、SRTP-K230-Fire-Guardian

把本期三条线索并排看，指向比较一致。上游 IP 与芯片侧，安谋科技用开源 AIOS 联盟把瑞芯微、瑞莎与 RT-Thread 拉到同一张桌子上，谈的是算力解耦与端侧带宽瓶颈；操作系统侧，RT-Thread 把具身智能项目提为重点，讲的是 Agent 从对话走向执行；社区与板卡侧，K230 与 CH32H417 两个项目分别把 Smart 和轻量推理落到火焰检测与符号识别这类具体任务上。三方都在往「小设备上跑完整感知与决策闭环」这个方向收，而不是各自扩功能清单。

六、总结与趋势观察

6.1 本期趋势：合入重启，修复集中在边界校验而不是新功能

日期：2026-10-28（本期）　来源：主仓库提交记录

本期最值得记的是合入节奏的恢复与其构成。四笔合入里三笔的 author 时间在 10-18，说明那批提案在评审里压了九天，现在开始逐个落地；同一批里还有四笔 Smart 相关提案挂在队列，可以预期后续几天主线仍以这批为主。四笔的技术取向一致：文件系统的时间戳语义、套接字的协议白名单、poll 的分发表来源、串口的寄存器宽度，都是边界校验与语义对齐，没有一个新功能。这四类位置平时不报错，一出问题就很难定位，集中在同一批里修掉，对长期稳定性是正向的。
