一、内核与版本动态

1.1 Next RISC-V 架构重构提案获创始人合并推动，提交者连夜变基刷新（09-29 ~ 09-30）

日期：2026-09-29 21:09（创始人评论）~ 09-30 00:01（最新提交）　来源：PR #10320

搁置数月的主仓库 RISC-V 架构重构提案「Next RISC-V」（#10320，171 个文件、+15018/-3490）在窗口内迎来明确推进信号：创始人 Bernard Xiong 于 09-29 21:09 评论「这份PR，近期能合并掉吧，同时在一些riscv的soc上，也尝试把设备树打开试试」，并点名维护者与提交者跟进。随后提交者 GuEe-GUI 让提案在当晚至次日凌晨连续触发三轮刷新记录（21:22、23:54、00:01，格式化与内存对比流水线随之重跑），最新 head 提交「Refactor the RISC-V architecture port」已于 09-30 00:01 重新变基至当前主线最新提交 dc8aaa73f 之上。方案要点：ISA 管理接口、RV32E/32I/64I 融合、按 CBOM 的缓存处理、Sv32~Sv64 MMU 与 SVPBMT、M/S 模式 CSR 操作合并、SMP、AIA（APLIC/IMSIC）、CLIC、ACLINT/CLINT、PLIC、设备树（DM）支持、T-HEAD 厂商代码合并、qemu-virt64-riscv64 设备树移植与从非 0 号核启动等；计划清单显示 S 模式 RT-Thread、RT-Smart 与设备树路径已完成验证，其余组合（含 M 模式、无 MMU 等）仍在推进。该提案自 2026-05 提交以来累计评审评论 74 条。

1.2 内核 calloc 溢出修复提案获评审通过（09-29 ~ 09-30）

日期：2026-09-29 22:34（提交）~ 09-30 08:30（获 LGTM）　来源：PR #11848

贡献者 luchenxu73 提交内核修复 #11848（单笔提交、3 个文件、+57/-3）：rt_calloc 分配时未检查 count×size 是否溢出，超限时结果回绕、存在分配与清零不一致的越界风险；修复方案为预计算分配尺寸并在超限时拒绝分配，改动覆盖 include/rtdef.h、src/kservice.c 与内存单元测试 src/utest/mem_tc.c（新增用例），验证平台为 qemu-vexpress-a9。该提案在 09-30 上午 08:30 获得社区评审「LGTM」通过，为窗口内推进最快的新提案。

1.3 三条驱动与 BSP 修复提案集中提交：ofw 哈希越界、ESP32-C6 SPI、ESP32-C3 链接脚本（09-29）

日期：2026-09-29 20:11 ~ 21:53　来源：PR #11845、PR #11846、PR #11847

09-29 晚间约一个半小时内，社区集中提交三条修复提案，均附测试证据、尚待评审。其一（#11845）设备树（ofw）phandle 哈希表越界修复：分配表项数用范围之差、查找下标却按 phandle 与起始值之差计算，导致范围上限被访问时越界，扩容时清零位置亦未减起始值；修复为表项数加一并在扩容时从旧表末尾起清零新增区域，作者以 GCC 加 AddressSanitizer/UBSan 完成 6 个用例的函数级验证（起始 phandle 取 1、5、128，另测上限 128 扩展至 256）。其二（#11846）乐鑫 ESP32-C6 按需编译 SPI：选中 BSP_USING_SPI 后接入 IDF SPI master，修正共享 ESP 驱动未返回传输字节数、片选引脚取值等问题，并在配置为空时返回 -RT_EINVAL（6 个文件、+466/-19）。其三（#11847）ESP32-C3 链接脚本在 Windows 路径下的通配符修正：sections.ld 中以「/」书写的通配符未能匹配 Windows 目标路径中的 riscv 目录对象文件、导致向量跳转重定位越限，改用「?」同时兼容两种分隔符；与 #11816 为同一处修改、本次基于最新主线重做，Windows 加 GCC 11.2.0 下 scons 构建通过。

四、行业应用

4.1 马来西亚理科大学毕设项目更新：RA8P1 + RT-Thread 端侧声学事件检测固件验证（09-30）

日期：2026-09-30 05:49 ~ 05:50（提交时间）　来源：KhaiFaw/ai-acoustic-event-detection

topic:rt-thread 生态下的第三方项目「Acoustic event detection at the edge」（马来西亚理科大学机电工程毕业设计）在窗口内连续提交两笔更新：核对声学固件构建与模型契约、修正嵌入式模型与固件之间的输入缩放不一致，并补充软件验证记录（16 项主机测试与一次全 BSP 本地构建通过；修正版固件尚未实机烧录评估）。项目基于瑞萨 RA8P1 Titan 板：RT-Thread 提供操作系统框架，瑞萨 FSP 提供设备支持，CMSIS-DSP 实现 FFT，TensorFlow Lite Micro 运行 INT8 CNN；以 MAX9814 麦克风采集 16000 点音频，经 MFCC 特征提取后在端侧识别婴儿啼哭、玻璃破碎、警报/警笛、敲门、门铃与背景六类声音。
