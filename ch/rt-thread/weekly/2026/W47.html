一、本周要闻

  • RT-Smart 用户态边界一周收口四处（11-16 ~ 11-17）：四处集中在 ptyfs、ivshmem、块设备分区与 FinSH 补全。它们分别是注销不释放文件对象、共享窗口由设备决定、ioctl 直接写用户指针、路径补全无界拷贝。四笔都在这一周合入。ptyfs 那笔给了量化验证：两万次开关前后对比，修复前少 7232 KB，折合每次约 369 字节。修复后只剩 40 KB 波动。ivshmem 那笔新增默认关闭的 JailHouse 兼容开关。块设备那笔改用用户态回拷接口，指针非法时不写入任何字节。FinSH 那笔从报告到修复用了 53 天，提案到合入只 3 天。

  • 邮箱句柄越权读写有了完整 PoC（11-19）：议题 #11960 指出 sys_mb_send 与 sys_mb_recv 绕过 LWP 对象归属表。邮箱实现里的 RT_ASSERT 只读结构体里的 type 字段，挡不住伪造对象。报告者在 qemu-virt64-aarch64 上把目标 qword 从 0x74003e2f2068736d 改成 0x1122334455667788，并能用同一个调用读回。修复提案 #12015 改十个文件、+1440/-126，把句柄解析换成「对上对象表并取引用」。截至发布日仍未合入。

  • 设备控制命令整体重编码（11-18）：#11881 把九个通用命令从 0x01 至 0x09 移到 0x2001 至 0x2009，关掉 2021 年 9 月提出的议题 #5073。冲突点是 fcntl 的 F_GETFL 与 CONFIG 同为 3、F_SETFL 与 CLOSE 同为 4。新编码用类编号占高字节、类内索引占低字节。提交只同步仓内 14 个文件，没有留兼容宏，验证 BSP 一栏为空。

  • 三条旧账挂上 CVE 编号（11-16）：GPT 分区项下溢拿到 CVE-2026-38160。FinSH 提示符格式化字符串拿到 CVE-2026-50961。AT socket 解析器栈溢出拿到 CVE-2026-106729。三个议题分别关闭于 11-04、04-09、09-21。编号在同一天上午补齐，属披露流程的收尾，不是当天的新修复。同日 CherryUSB 维护者划出边界：1.7.0 以下不做检查。

  • ArtInChip D213 板级包三天合入（11-14 提案、11-17 合入）：30 个文件、+1783 行，核心是平头哥 C906、RV64GC、128 MiB DDR3。提交者就是上周 RISC-V 浮点缺陷的报告人。他先在自家板子上撞到线程切换后 fs1 不对，回官方 QEMU 复现，修完之后再回来交板级包。

  • 软件包索引一周 7 笔，Agent 包两次改配置（11-16、11-18）：11-16 的六笔包括 Agent 配置项重排（+416/-37）、Wi-Fi 与蓝牙主机驱动（+672，专有许可）、ms-probe 诊断包。另三笔是 WS2812 灯带、多灯带 SPI 驱动、红外框架多实例。11-18 的第三笔给 Agent 加 A2A 通道与分层记忆（+378/-212）。两次都只改 Kconfig，不动包本体。

  • Windows 工具链对齐 CI（11-16）：Env 仓把捆绑的 clang-format 换到 22.1.8、Arm GNU 工具链升到 13.3.Rel1。22.1.8 正是主仓库 CI 使用的格式化版本。此前 Windows 用户本地格式化与 CI 判据可能差一个大版本，格式检查失败却看不出原因。这个仓上一次实质改动是 09-08 的 Env 2.1.0。

  • 官方渠道静默满两周，12 月活动定档（11-19）：官方新闻接口连续十期零新增，最新仍是 11-06 15:54 那批五篇。12 月 12 日北京、12 月 19 日深圳双城沙龙公布，RT-Thread AI Kit 将在现场发布。原文没有给版本号、芯片列表与接口形态。

安全与缺陷收口

日期与来源：2026-11-16 ~ 2026-11-20 的议题与提案，取自主仓库议题列表。

  • ptyfs 注销泄漏（#12029，11-16 合入）：注销函数只把 pts 从根链表摘掉、回收编号，struct ptyfs_file 从不释放。未特权进程反复开关 /dev/pts/ptmx 就能耗尽内核内存。修复补齐生命周期四个点：释放对象、把 pts_unit 初始化为 -1、修正创建失败路径的释放顺序、跳过从未注册的设备。3 文件 +60/-6。影响 v5.1.0 至 master，引入点 83e95bdf（2024-03-28）。
  • ivshmem 共享窗口（#11993，11-16 合入）：BAR2 缺失时的 JailHouse 兼容回退直接拷贝设备配置字 0x40 至 0x4f。PCI 核心不校验，内核于是可能把任意物理窗口映射进来。修复加默认关闭的 RT_IVSHMEM_JAILHOUSE 选项、映射前三道范围校验、64 位局部变量与返回值检查。2 文件 +122/-7，评审 10 天。
  • 块设备分区越权写（#11981，11-17 合入）：RT_DEVICE_CTRL_BLK_PARTITION 把用户裸指针当 rt_memcpy 的目的地址。它也不把 err 置为成功。调用方拿到「失败」时，目标内存已被改写。修复在 LWP 下先拷进内核栈，再用 lwp_put_to_user 回拷。5 文件 +294/-59。10-29 报告、11-03 提案，14 天后合入。
  • FinSH 路径补全（#12057，11-17 合入）：msh_auto_complete_path 拼接当前目录与用户输入时未守定长缓冲，超长路径按 Tab 即可写出边界。修复只有 +5/-0，碰到超长输入直接截断。缺陷 #11839 报于 09-25，报告到提案 50 天。
  • iso9660 目录名下溢（#12061 与 #12062，11-17 凌晨）：目录记录 namelen 为 0 或 1 时，剥离 “;1” 后缀的减法会在无符号数上下溢。随后那次 rt_strncpy 变成越界写。报告 01:46、提案 02:03，相隔 17 分钟。修法是把 namelen 限制在本地缓冲容量内，且只在大于等于 2 时剥后缀。11 行新增。影响 v5.2.0 至 v5.3.0 及 master，引入点 42a41c69。
  • serial_v2 的 DMA 对齐（#12063，11-17 报告，未修）：rx fifo 结构体、环形缓冲与 DMA ping 缓冲由一次分配得到。32 位 M7 上结构体是 44 字节，ping 缓冲因此恒落在 12 mod 32。驱动按 32 字节整行失效 D-cache，向下丢脏数据，向上多失效相邻堆块。STM32H7 上表现为 tx fifo 的 buffer_ptr 变 NULL，下一次写断言。报告给出框架级修法与 CVSS 自评 4.6 至 5.3，4 个半小时后被认领。
  • 邮箱句柄越权（#11960 与 #12015）：缺陷机理与 PoC 见要闻第二条。修复提案在 11-19 11:36 推入提交，10 文件 +1440/-126，未合入。
  • 串口 V1 重开模式越界（#12072 与 #12073，发布日补录）：11-20 13:27 报告。用 INT_TX 打开过的设备改用 DMA_TX 重开时，4 字节 tx_fifo 被当成 48 字节 rt_serial_tx_dma，造成堆越界与非法函数指针调用。12 分钟后同一作者提交 #12073，1 文件 +18/-12，用 -RT_EBUSY 拒收跨模式重开。两笔都在周五日报窗口之后。

架构与设备层

日期与来源：2026-11-16 ~ 2026-11-20 的三笔提案，编号 #11881、#12052 与 #12068。

  • 命令编码（#11881）：基址宏按类编号加一、再乘 0x100 计算。旧掩码只看低 5 位，与新编码不兼容，作者 grep 全仓确认无调用者后删除。跟随改动的 14 个文件里八个是 efm32 板级驱动。头文件侧 dev_pin.h 与 dev_serial_v2.h 改成枚举，rt-link 的 rtdef.h 新增 34 行。仓外 BSP 或软件包若把旧值写死，升级后会走到错误分支。
  • STM32 输入捕获（#12052）：粒度从物理定时器降到通道。TIM1 至 TIM4 的 CH1 至 CH4 可各自注册为独立设备，共享计数器与 HAL 句柄。另加 PWM Input 与双边沿两种独占模式。+1540/-285，11-12 提案、5 天后合入。
  • 设备生命周期锁（#12068，在审）：新增 RT_USING_DEVICE_LIFECYCLE_LOCK，默认关闭。打开后每台设备用自己的优先级继承互斥量，串行化初始化、open 模式决策、引用计数更新与驱动回调。这笔回应 #11234 的 ref_count 错乱，用例 229 行。
  • dfs errno（#12067，在审）：描述符表满时 DFS v1 在 errno 里报 -ENOMEM，DFS v2 返回 0。调用方会把 0 当有效描述符。修法是分配失败报 EMFILE 或 ENOMEM，POSIX open 失败返回 -1 并给正值 errno。用例 +60 行。
  • 构建工具（#12070、#12069，在审）：组库的局部编译标志被应用两次，同一对象注册两个 SCons action。修法是先按普通组编译再归档。这笔对应 2021 年 3 月的议题 #4417。Pico 的 README 补上 RTT_EXEC_PATH 覆盖写法。
  • 串口 V1 的定位：维护者 10-22 留言主张冻结 V1、只作历史兼容，串口重心往 V2 靠。11-20 06:54 的回复确认 V1 仍要接受修复。本周 #11909 的实际修复是 5 行（34d2a002），另有一笔 622 行 clang-format（87b851b4）把 diff 撑大。用例 uart_rx_timeout.c 226 行，不依赖硬件。

三、生态与厂商适配

厂商 BSP 与驱动

日期与来源：2026-11-14 ~ 2026-11-21 的 BSP 提案与补记，取自 #12058、#12007、#12032、#12013 与 #11998。

  • 芯擎（ArtInChip）：D213ECV-DEMO-V4-0 是 C906、RV64GC、128 MiB DDR3 的评估板。板级包复用 RISC-V 公共移植层的 M 模式启动、上下文切换、FPU 状态与 PLIC。外部加载器先配 DDR、PLL 与内存属性，再把系统装到 0x40000000。UART0 轮询发送，接收线程缓冲默认 512 字节。
  • 沁恒（WCH）：CH32V208 补上电源管理组件，drv_pm.c 637 行，8 文件 +725/-1。内容含休眠唤醒入口、外设时钟关断恢复、唤醒源配置与功耗曲线 readme。这笔 11-14 17:28 合入，落在上一期核查截点之后，本周补记。
  • 嘉楠（Canaan）：K230 的脉宽回读把计数方向算反。配置成递增计数时，读回的脉宽是反的。驱动 +11/-6，用例 +120/-42，把边界值、零占空比与满占空比都纳入。
  • 乐鑫（Espressif）：ESP32-C3 v1.x 芯片拒绝官方预编译镜像。原因是镜像头里的芯片版本字段按新版本填写。修法是把版本字段改回兼容区间。
  • 意法半导体（STM32）：输入捕获的多通道改造见第二章架构与设备层。本周另有 serial_v2 的 DMA 对齐缺陷报告，尚未修复。
  • 瑞萨（Renesas）：RH850 G4KH 移植仍是 52 个文件、+4122 行。libcpu 用 TRAP0 做线程切换，含嵌套中断、FPU 上下文与故障转储。CI 做硬浮点与软浮点两种构建，工具链与 QEMU 包在解压前校验 SHA-256。
  • 全志（Allwinner，发布日补录）：11-21 下午连提四笔 V861 板级提案。#12077 是 C907 板级支持，#12078 是 E907 异构板级支持，#12079 是硬件 MSGBOX 与 OpenAMP 通信，#12080 是 MMC 认卡与扇区读取。四笔均未合入，不计入本周口径。

六、趋势观察

  • 安全线进入「单笔完整收口」，验证仍是短板：ptyfs 给了两万次循环的内存曲线，ivshmem 只到两种配置的编译结论，块设备那笔没有运行时用例。serial_v2 的高质量报告尚未修复。本周没有一笔带自动化用例的安全修复。
  • 延迟的瓶颈在「报告到提案」这一段：FinSH 报告到提案 50 天、提案到合入 3 天。块设备报告到提案 5 天、提案到合入 14 天。iso9660 相隔 17 分钟。评审并不慢，慢的是有人愿意动手。
  • 破坏性变更是本周最需要下游注意的一项：九个通用命令整体位移、无兼容宏、验证 BSP 一栏为空、只同步仓内 14 个文件。凡把旧命令值写死的仓外 BSP 与软件包，升级后都会走到错误分支。
  • 测试配置的静默丢失比缺陷更隐蔽：mem.cfg 未选中 MEMHEAP，整组用例不编入，构建与测试都显示通过。这类缺口只能靠配置对照发现，靠跑测试发现不了。
  • 生态层吞吐高于内核：主仓库 9 笔、包索引 7 笔、Env 2 笔。包索引这一层同时承接厂商准入、AI 组件配置化与调试工具标准化。对装机量以亿计的操作系统，生态层的吞吐比内核提交数更能反映活跃度。
  • 串口双轨维护不是零成本：维护者把 V1 定为低维护而非冻结，V1 本周仍接新缺陷，12 分钟内就有修复提案。V2 则缺 RX_TIMEOUT 宏，需要走读侧的控制接口。两条线的语义差异会长期存在。
