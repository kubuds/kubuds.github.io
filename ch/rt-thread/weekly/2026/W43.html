RT-Thread周报（2026-10-19 ~ 2026-10-23）

2026-10-23 苦芽科技

素材来源：本刊每日 RT-Thread 动态日报 5 期（10-19、10-20、10-21、10-22、10-23），合计有效窗口 10-16 08:00 至 10-23 08:00（周一期为跨周末 72 小时窗口）；发布日核查基于 GitHub 主仓库与 packages、env、rtthread-skills、smart-build、Studio SDK 索引各仓提交流实测

一、本周要闻

  • 进迭时空 K1 首版 BSP 合入主线，应用处理器级 RISC-V 平台首次进入主干（10-19）：提案 #11132 自 2026-01-11 挂出，评审约九个月后由作者 GuEe-GUI 落地，4 笔提交、173 文件、+53862/-12，属 Next RISC-V 重构（#10320）的后续。BSP 面向集成 8 个 X60 核的 64 位 RISC-V 平台，由 U-Boot/OpenSBI 引导、在 S 模式运行，默认开启 MMU 与 SMP，验证平台为香蕉派 BPI-F3；已支持 PCIe/NVMe、eMMC HS400、以太网与 PTP、HDMI 帧缓冲、JPU 与 V2D 加速、音频、CPUfreq 与热管理。驱动层单独抽到 bsp/spacemit/dm（147 文件、49 个 C 文件、约 30 个模块），供同系 SoC 复用。

  • RISC-V 票号自旋锁改用原子加，K1 的 SMP 配置同日由 4 核放开到 8 核（10-22 合入）：提案 #11904 把取票改为一条 amoadd 指令、放锁改为一次 16 位半字存储，6 文件 +33/-37。原实现取票与放锁在同一字上走加载保留加条件存储的循环，多核高争用下会互相冲掉保留并陷入活锁，放锁的整字读改写还会覆盖并发新领的票号；两处根因一并消除，并在两侧各补一处内存屏障。该代码为所有 RISC-V 板卡共用，影响面大于单个 BSP。

  • ESP32-C3/C6 适配 ESP-IDF v6.1 全链落地，RISC-V 工具链跳到 GCC 15.2（10-21 ~ 10-22）：包侧 RT-Thread-packages 的 esp-idf 于 10-21 15:23 完成自 5.1 到 6.1.0 的整包升级并合入（变更文件两万余），新增 components/rtthread 移植层与 CONFIG_IDF_RTOS_RTTHREAD 内核替换开关；主仓提案 #11870 于 10-22 15:42 合入，涉及 55 个文件。C3 十三个配置与 C6 默认配置编译通过，硬件上板一栏仍写「待验证」。C3、C6 为 RISC-V 内核，这条路径现在从包到主仓都已就位。

  • 一周开出六枚缺陷单，其中五枚为内存与边界安全，NVMe 单次启动即漏约 1.1 MB 内核堆（10-20 ~ 10-23）：新增 #11902（tmpfs 截断后使用）、#11905（cromfs 目录名越界）、#11906（中文 Windows 编码）、#11913（raw DHCP 选项越界读）、#11917（NFS 越界写）、#11919（NVMe 堆泄漏）共六单，除编码问题外的五单均属内存与边界安全。其中 #11919 在 QEMU 原装 NVMe 设备上单次启动泄漏 1,156,872 字节，热插拔线性累积，报告给出 CWE-401 与 CVSS 3.1 4.9。#11917 的引入提交可回溯到 2010 年，自 v1.2.0 起全部版本受影响。

  • RT-Thread Smart 由批量提案转入可测试阶段，信号与设备树两处越界获修复提案（10-18 ~ 10-22）：维护者于 10-18 19:35 至 19:36 两分钟连开 13 笔提案（#11885 ~ #11897），内容含 qemu-virt64 启用 Smart、riscv64 关闭 SMP、virtio-blk 挂 ext4 与 ptyfs、lwp syscall 拆分、K230D 128MB DDR 适配等。本周对应缺陷的修复跟进：lwp 信号编号校验（#11899）、OFW 设备树深度预检（#11901，评审后改为调试门控）、cromfs 目录名边界（#11911）、tmpfs 截断后使用（#11910）。维护者就 libdl 动态模块缺陷表态：边界校验可做局部修复，内存隔离需转用户态。

  • 调度器两条独立路径收敛到同一判别式，三年旧案补测暴露单核二次释放（10-21）：社区成员对 2022 年挂起的时间片补丁 #6645 连发三条评论重新拉回评审，其「只有仍在运行且时间片未用尽被抢占才插队首」的判别式与本周新提案 #11907 独立得出的结论完全一致；但 #6645 的「延后写 READY」实现在单核路径引出 idle 回收时的 TCB 二次释放（调度组 utest 稳定崩溃），隔离实验证明问题不在 YIELD 清除位置。结论建议以 #11907 的「先存 stat_before 再判断」为基础推进。

  • 主线节奏为「三日静默、一次收尾」：本周共 7 笔提交、6 个提案，10-22 三小时内落四笔（10-19 ~ 10-23）：10-19 两笔（rt_null 提前注册 #11884、K1 首版 #11132），10-20 至 10-22 上午零提交，10-22 15:42 至 18:00 连落四笔（ESP32 #11870、票号锁与 K1 八核 #11904、attachconfig #11908），10-23 17:09 再落 clang-format 规则提案 #11859。版本侧仍无动作：最新标签与发布物仍是 09-10 的 v5.3.0，v5.4.0 只有 10-17 合入的版本宏与 Kconfig 默认值，无发布说明与二进制。

  • 厂商侧同周推进：睿擎 V1.8.4 发布并补工业现场修复，兆易创新 24 小时补齐联网与界面两个基础件（10-21 ~ 10-22）：睿擎 V1.8.4 于 10-21 发布（新增 QY1503 编码器、MIPI RGB666、GPIO 上下拉、amp_device 调试命令，修复 EtherCAT 中断亲和性、telnet 下 netstat 卡死、UART DMA 波特率），IDE 同步升至 V1.5.62；兆易创新侧 GD32VW553 于 10-22 进入 at_device 包、GD32EmbeddedUI 示例建仓一天后进 LVGL 包索引，Studio SDK 索引同日收录 Gino Pi（GD32H77D）1.1.0 与 PyOCD 0.3.1。

安全与缺陷

日期：2026-10-20 ~ 2026-10-23　来源：Issue #11919

  • 新开六单：#11902 tmpfs 在 rt_realloc(data, 0) 返回空指针时置 ENOMEM 却返回成功，合法的 ftruncate(fd, 0) 会先释放缓冲再报成功（自 v5.0.2 起全部版本，QEMU aarch64 与 RP2350 复现，10-20 已被社区认领）；#11905 cromfs 读取目录项时对目录名长度不设上界，可越过目录项缓冲并劫持内核程序计数器（自 v5.0.0 起，DFS 两代实现同源，未认领）；#11913 raw-API DHCP 服务端选项遍历未先校验 buf + 1 < end，可越过 1500 字节 pbuf 最多 4 字节（同目录的套接字实现已做该校验，反证缺失点）；#11917 nfs_read 以服务端回复的 count 作 memcpy 长度，内置 cat 用 81 字节栈缓冲可被覆盖返回地址（自 2010 年提交引入）；#11919 NVMe 扫描以设备上报的命名空间数作循环上界，每轮先分配 4480 字节后才发命令，两条失败路径均不释放。另 #11906 为中文 Windows 下的控制台编码缺陷，归入工具链一侧（见第三节）。
  • 修复提案五笔：#11899 在 sys_sigaction 入口限定信号号 1 至 64 并在 lwp_signal_action 内加同样校验；#11901 在设备树展开前预遍历求最大深度、超过 63 层拒绝（评审后改为调试开关门控）；#11911 约束 cromfs 目录名长度；#11910 修 tmpfs 零长度截断后的释放后使用；#11918 让 9PFS 读与 getdents 两条路径都按实际接收字节数收敛报文长度，作者用 bsp/simulator 加 ASan 搭假 9P 服务器复现（修复前触发 use-after-poison，读位置落在 8 MB 堆区第 8,334,515 字节）。
  • 仍未闭环：#11878 lwip-dhcpd 租约池耗尽死循环、#11905、#11913、#11917 四单无认领，其中 #11917 本期只有状态刷新。
  • 共性判断：本周五单安全缺陷的共同形态是「设备或服务端可控的元数据被直接当作内存操作的长度或上界」，同一研究者两天内报出 NFS、NVMe、9PFS 三单，并自述其线索可追溯到 mtd-cfi 与 usbhost 的旧单。逐单修补的成本高于按族排查。

评审队列观察

日期：2026-10-19 ~ 2026-10-23　来源：PR #11907

  • 调度与内核语义：#11907 修正同优先级线程就绪顺序（4 文件 +255/-22，含新增 utest），实测把信号量唤醒顺序由乙甲改为甲乙、启动顺序由丁丙改为丙丁；#11909 把串口 V1 框架里被静默丢弃的接收超时事件并入接收指示回调（一行分支），受影响的是依赖空闲超时切帧的 CH579M 与 SWM341 两个国产板级支持；#11900 修 netdev 的 ping 在次数为 1 时漏记最小时延。
  • 调度旧案复核：#6645 的判别式与 #11907 一致，但实现手段在单核路径引出 TCB 二次释放，作者给出隔离实验与 SMP 补测数据，结论建议以 #11907 为推进基线。
  • 外设与架构：#11912 在组件层补 OSPI 与 OctaFlash，接进 SFUD 并覆盖读、写、擦与状态查询，附通用 STM32 OctoSPI 驱动与 L4 系列板级配置，32 文件 +3728/-956，作者报告实板 1-1-1 与 8-8-8 两种模式均可被识别；#11914 修正 Cortex-A 的 GIC 信息打印格式符（%p 传整数属未定义行为），2 文件 +64/-40；#11915 修可重定位模块加载路径四处缺陷（BSS 分配指针不推进、段符号重定位缺链接地址修正、SHN_COMMON 被静默跳过、ET_REL 模块不构建符号表导致 dlsym 永远失败），2 文件 +147/-9，qemu-vexpress-a9 上三个测试模块验证通过。
  • 仍在流程中：#11844（ESP32-S3 板级支持）卡在软件包依赖补齐，最近一次回复停在 09-29；#11860（aarch64 中断应答）作者表示再测一版；#11864（IAR 隐式声明）评审要求补板级配置与前后输出记录；#10096（按需编译）被建议先变基；#9941 经实测确认 scons –attach 在主线上可用，建议关闭。

六、趋势观察

  • 应用处理器级 RISC-V 平台进入主线是本周最重的结构性变化：K1 以 S 模式、MMU 与多核 SMP 的形态合入，配 PCIe/NVMe、HDMI 与多媒体加速，标志 RT-Thread 在高端 RISC-V 平台上从「能启动」走向「外设齐备」；驱动独立成 bsp/spacemit/dm 一层，BSP 目录开始出现「厂商层加板级层」的分工，K1 只是第一个使用者。这类平台后续会持续反向暴露通用代码缺陷——本周同批带出的原子比较交换、电源域命名、DVFS 查重三处修正即为证据。
  • 多核正确性成为本周的技术主线：票号锁的活锁面从根上去掉、原子比较交换的期望值不再被状态寄存器覆盖、同优先级就绪顺序拉回先来先服务，三处都属长期被默认行为掩盖的问题，且都在同一周内被定位。调度器侧还出现「两个互不知情的实现收敛到同一判别式」的情形，跨提案横向比对正在替代单条补丁的讨论方式。
  • 安全审计已呈族化特征，逐单修补的成本正在超过收益：本周五单安全缺陷的共同形态是采信外部可控的元数据作为内存操作长度或上界，涉及 NFS、NVMe、9PFS、cromfs、DHCP 五个组件。报告者自带引入提交、影响版本区间与复现环境，修复成本已被压低；但 v1 与 v2 两代 DFS 实现同源导致的重复缺陷（cromfs 一单两份拷贝均未加约束）提示应做按族排查与结构性收敛。
  • 主线呈「静默—集中收尾」节奏，发布流程尚未启动：连续三日零提交后，三小时内落四笔且由同一维护者处理，更像攒批评审后的批量处理。v5.4.0 自 10-17 起只有版本宏与 Kconfig 默认值，无标签、无二进制、无发布说明；这种「版本号先行、发布物滞后」的状态已持续一周，下一期应以发布页与 ChangeLog 复核是否真正开闸。
  • 工具链的两条线并行：新底座可得性与本地化细节：一边是 ESP-IDF 6.1 加 GCC 15.2 与 CONFIG_IDF_RTOS_RTTHREAD 内核替换通道的打通，C3/C6 之外也为后续 RISC-V 产品线留出路径；另一边是中文 Windows 下表情符号导致整条命令不可用、clang-format 规则收紧、Studio SDK 索引三笔更新这类「技术含量低但直接影响上手体验」的修补。后者对国内开发者的边际收益往往更高。
  • 官方渠道静默与社区承载的分工进一步固化：新闻接口停更逾四个月，本周的对外信息几乎全部由 GitHub、论坛大赛作品与行业媒体承载，睿擎的版本发布也走媒体稿而非自有渠道。这一格局已连续两周未变，社区内容密度（本周三篇作品、日均一到两帖）反而在替官方承担叙事职能。
