오늘의 핵심: 복귀일 머지 러시——메인 저장소 하루 12건 머지 마감, Ascend 「3종 세트」 복귀 완료 (10-08/10-09)

날짜: 2026-10-08, 2026-10-09　출처: 메인 저장소 PR 목록／ FP32 Reduce2D (#1852)／ K 풀 배리어 절감 (#3419)

연휴 이후 첫 완전 근무일에 tile-ai 조직은 머지와 신규 오픈이 각각 21건이었다; 그중 메인 저장소 tilelang은 하루 12건 머지(자정을 넘긴 심야 수정 3건 포함, 그중 11건이 본지 신규 수록), TileOPs 4건 머지, Ascend 어댑테이션 저장소 5건 머지——9월 하순 이래 가장 밀집된 머지일이었다. 주목할 두 가지 주선은:

  • 메인 저장소 리듬 전면 회복: 병합 범위가 다섯 갈래에 걸쳐 있다 — 정확성 수정(Profiler 동기화, 중첩 LDG 프레디케이트, JIT 캐시, 양자화 마스크, 희소 GEMM), 성능(K 풀 배리어 축소), 리팩토링(math codegen 디스패치 분리), CI(Windows wheel 속도 향상), 그리고 Ascend 코드 생성(라인 명령 지원). 가장 늦은 세 건은 10-09 새벽 0시 전후에 착지해 “자정을 넘나드는” 연속 병합 구간을 형성했다.
  • Ascend “삼종 세트” 복귀 완료: 어댑테이션 저장소의 Vector 마스크 재사용(#1850) / 동기화 의존성 수명 주기(#1851) / FP32 Reduce2D와 워크스페이스 계약(#1852) 세 건의 봇 서명 PR이 오후에 차례로 병합되었다. 여기에 앞서 기록된 C/V 귀속(#1848)과 버퍼 도메인 검증(#1786)을 더하면, 기존 #1829 “Part 2” 분할 이후의 다섯 건이 모두 착지했다 — 9월 하순에 통째로 롤백되었던 이 950 기능 라인이 복귀를 완료했다. 같은 날 CI 측에서는 CANN 9.3 자체 빌드 이미지와 a5 runner 마이그레이션 두 건이 열렸다(2.2 참조).
  • 속도 향상 측면: K 풀 배리어 축소(#3419)는 디코딩 체인의 11개 메타데이터 검증 프레디케이트를 한 번의 디바이스-호스트 동기화로 병합하고, 폭 32의 warp shuffle로 5단계 Hadamard-128 단계를 커버한다 — 디코딩 헤드 지연이 연산자 커버리지에 이어 새로운 최적화 타깃이 되고 있다(상세는 1.2 참조).

1. 핵심 프로젝트 진행 상황

1.1 메인 저장소 심야 배치: Profiler 디바이스 동기화, 중첩 LDG 프레디케이트 보존, JIT 테스트 캐시 격리 세 건 반영(10-09)

날짜: 2026-10-09　출처: Profiler 검증 동기화(#3457)／ 중첩 LDG 프레디케이트(#3390)／ JIT 캐시 격리(#3450)

  • Profiler 검증 디바이스 동기화(#3457): profiler 검증 텐서가 무조건 CUDA를 동기화하는 문제를 수정(결함 이슈 #3410) — 검증 텐서는 자신이 위치한 디바이스에 따라 동기화하며, 더 이상 전면 CUDA 동기화를 트리거하지 않는다. PR은 그날 밤 22:58에 열려 약 한 시간 후 병합되었다.
  • 중첩 LDG 프레디케이트 보존(#3390): 프레디케이트화된 LDG가 외부 저장소 프레디케이트를 무시하는 문제를 수정(결함 이슈 #3381) — 중첩 읽기가 외부 프레디케이트 제약을 보존한다.
  • JIT 테스트 캐시 격리(#3450): 테스트 캐시를 격리하고 디스크 캐시 히트 경로의 사례 커버리지를 보강해 테스트 간 캐시 간섭을 제거했다.
  • 세 건은 10-09 새벽 0시 전후에 연달아 반영되었으며, 앞서 심야에 병합된 #3447과 함께 모니터링 기간 말미의 “자정을 넘나드는” 병합 구간을 이룬다.

1.2 메인 저장소: K 풀 Hadamard 배리어 축소 병합 — 디코딩 검증을 단일 디바이스-호스트 동기화로 병합(10-08)

날짜: 2026-10-08　출처: K 풀 배리어 축소(#3419)

  • 목표: 전체 K 풀 디코딩 호출 지연을 낮춘다. 11개 디코딩 메타데이터 프레디케이트를 고정 형상 텐서 상의 배치 평가로 바꾸고, 불리언 결과를 한 번에 호스트로 전달한다(단일 디바이스-호스트 동기화로 병합). 압축 및 디코딩 체인의 5단계 Hadamard-128 단계는 폭 32의 warp shuffle 구현으로 교체했다.
  • 엔지니어링 경계: 정렬 및 인접 값 검사는 중복 꼬리 블록과 캐시 목적지를 발견하는 데 사용되며, 패딩과 풀 완료 검사는 기존 오류 우선순위를 유지한다. 캐시 인터페이스, 오류 메시지와 우선순위, BF16 반올림 경계, FP8 스케일링과 정렬된 꼬리 업데이트의 계약은 변하지 않는다.
  • 맥락: 이미 병합된 GLM-5.3 독립 파이프라인(#3254)을 이어받는다 — K 풀 경로에서 “동기화 횟수와 배리어 오버헤드”가 연산자 수준 최적화와 나란히 성능 지렛대로 자리 잡고 있다.

1.3 메인 저장소: math codegen 디스패치 분리 리팩토링과 AscendC 라인 명령 지원 병합(10-08)

날짜: 2026-10-08　출처: math codegen 리팩터링(#3449)／ AscendC 라인 지시어(#3447)

  • math codegen 디스패치 분리(#3449): CUDA 측 수학 함수 코드 생성의 디스패치 로직을 분리·리팩터링——단일 지점 결합도를 낮추고 후속 확장을 위한 길을 열었다(20:30 머지).
  • AscendC 라인 지시어 지원(#3447): 메인 저장소에서 tl.emit_line_directives가 AscendC 코드 생성에 진입하도록 지원——디바이스 소스 코드를 행 번호 지시어에 따라 출력하여, Ascend 측 디버깅과 프로파일링에서 소스 행을 정렬할 수 있다(23:48 머지).
  • 인프라 리팩터링 한 건, Ascend 코드 생성 역량 한 건이 각각 저녁과 심야에 자리 잡았다.

1.4 메인 저장소 수정 배치: 제로 패딩 매칭, interleave_weight 마스크, uint8 희소 GEMM, 패킹 비교, ROCm 반올림(10-08)

날짜: 2026-10-08　출처: -0.0 제로 패딩(#3343)／ interleave_weight 마스크(#3140)／ uint8 희소 GEMM(#3297)／ 패킹 벡터 비교(#3303)／ ROCm 반올림(#3299)

  • 비동기 복사 제로 패딩 매칭(#3343): 제로 패딩 매처가 더 이상 -0.0을 포함하지 않아, 음의 영이 매칭에 참여하는 경계 상황을 제거했다(17:20 머지).
  • interleave_weight 마스크(#3140): 양자화 경로 interleave_weight의 특수 분기를 순수 정수 마스크로 전환했다(15:08 머지).
  • uint8 희소 GEMM(#3297): CUDA 희소 GEMM이 uint8 피연산자를 지원한다(15:04 머지).
  • 패킹 벡터 비교(#3303): 패킹된 FP16/BF16 벡터 비교를 발행한다(14:35 머지, 같은 날 #3315와 동일 배치 서명).
  • ROCm 반올림(#3299): T.round의 짝수 반올림을 수정했다(13:08 머지)——국경절 합본에 이미 수록되었으며(복귀 후 첫 건), 여기서는 모니터링 기간 완전성을 위한 기록으로 남긴다.

1.5 메인 저장소 엔지니어링 라인: Windows wheel 빌드 가속 머지; 오픈 PR 174건 집계(10-08)

날짜: 2026-10-08　출처: Windows wheel 가속(#3315)／ 메인 저장소 PR 목록／ T.copy 시맨틱스 RFC(#3459)

  • Windows wheel 빌드(#3315): 안정적인 uv 환경으로 Windows wheel 빌드를 가속한다(17:50 머지)——9월 빌드 라인의 연속 정비(ccache 히트 회귀, uv 환경화)를 이어간다.
  • 큐 온도: 모니터링 기간 내 신규 11건(#3445, #3447, #3449, #3450, #3452~#3458 번호 구간); 메인 저장소 오픈 PR 174건 집계(연휴 전 합본 기준 116건, 연휴 및 복귀 기간 순증 58건).
  • 신규 오픈 중 주목할 만한 것: Ascend CI 두 건(#3454, #3458, 2.2 참조), SimdVF 다중 버퍼 패딩(#3455), warp 특수화 단계 해제(#3452), 스칼라 읽기 인덱스 계수(#3453), 양의 정수 제수 안전 가드 평탄화(#3445), CodeRabbit 리뷰 제안(#3456); 새벽에는 별도로 T.copy extent 시맨틱스와 memory scope 역할 명확화 RFC(#3459)가 열렸다.

날짜: 2026-10-08　출처: Vector 마스크 재사용(#1850)／ 동기화 의존성 수명 주기(#1851)／ FP32 Reduce2D와 워크스페이스 계약(#1852)
