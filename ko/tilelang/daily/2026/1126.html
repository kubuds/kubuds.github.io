오늘의 중점: FlashQLA v0.1.4 릴리스, 듀얼 카드 CP가 소비자용 Blackwell까지 확장

QwenLM/FlashQLA가 11-25 23:16에 v0.1.4를 릴리스했으며, 저장소는 현재 770 스타. 이는 채택사 측면에서 이번 모니터링 기간 가장 완전한 버전 인도이다.

릴리스 노트에는 세 가지 주요 라인이 나열되어 있다. 첫째는 크로스 파티션 수정 정밀도 경로로, FP32 및 3회 TF32x3을 지원하며 런타임이 wave 인식 휴리스틱으로 선택한다. 카드 간 h0 및 dht 폴딩은 슬롯 매핑을 통해 이미 집계된 (h, M) 버퍼를 직접 읽도록 변경되었으며, 더 이상 물질화된 언팩 및 재인덱싱을 수행하지 않는다.

둘째는 SM120 및 SM121에서의 듀얼 카드 CP로, 순방향과 역방향 모두 카드 간 및 카드 내 조합을 커버한다. 구현은 새로 추가된 aggregate_card_state와 aggregate_m을 통해 완료된다.

셋째는 ZigZag 카드 간 CP 레이아웃이다. r번째 rank가 각 문서의 r번째 블록과 2·cp−1−r번째 블록을 담당하며, 어텐션 레이어 분할 위치와 정렬되고 TileLang kernel 수정을 요구하지 않는다.

나머지 변경은 엔지니어링 중심이다. KKT 솔버가 8×8 대각 블록 대입으로 변경되었으며, FP16 MMA와 FP32 재귀를 병합하고 FlashInfer의 블록 역행렬을 독립적으로 재작성했다. flash_qla.warmup()은 모든 정적 파라미터 조합을 JIT 캐시에 사전 컴파일할 수 있다. CP 인터페이스 build_cp_context는 기본적으로 카드 간 및 카드 내를 활성화하며 zigzag=를 받는다.

수정 항목 중 하나는 이전 데일리 리포트의 SM120 단서와 이어진다. block_DV=64 와 한 곳의 __threadfence_block 이 nvcc가 g_exp_shared 를 배리어 밖으로 승격하는 것을 막는다. 역방향 배리어는 이제 먼저 dV 쓰기를 커밋한 뒤 K가 dqkv_shared 를 재사용하게 한다.

벤치마크는 세 가지 하드웨어 등급을 커버한다. 단일 카드는 H200, GB200 및 RTX 5090이다. 듀얼 카드 CP는 H200×8, GB200×4 및 RTX 5090×2이다. 릴리스에는 Auto-CP와 Dual-CP 기술 보고서도 함께 첨부된다.

출처: https://github.com/QwenLM/FlashQLA/releases/tag/v0.1.4.

오늘의 초점: 야간 휠이 0.1.16으로 교체, 버전 문자열 개편이 두 건의 회귀 유발

tilelang-nightly 모니터링 기간 내에 두 개의 휠이 나왔다. 11-25 13:18 빌드는 v0.1.16+d20261125.git3684ae6a, 22:30 빌드는 v0.1.16+d20261125.gitfa93ba14이다. 전날은 여전히 v0.1.15+d20261124였다.

이는 11-24에 병합된 버전 번호가 이미 패키징 체인에 진입했음을 의미한다. GitHub 태그 최신은 여전히 v0.1.15, Releases 최신도 여전히 9-30의 v0.1.15, PyPI의 tilelang 도 0.1.15이다. 따라서 정확한 표현은 빌드 측은 이미 0.1.16에 도달했으나 릴리스는 아직 완료되지 않았다는 것이다.

버전 문자열 형식도 동시에 변경되었다. 이전 형식은 0.1.15+cuda.d20260125.githash, 새 형식은 0.1.16+githash이며 dYYYYMMDD 날짜 세그먼트는 더 이상 나타나지 않는다.

형식 개편이 두 건의 회귀를 유발했으며, 모두 11-25 17:26 전후에 보고되었고 환경은 소스 빌드 a3a4f9ce이다.

#4513 은 build_date() 가 dev 버전에 대해 조용히 None을 반환한다고 보고한다. 해당 함수의 정규식은 [+.]d(\d{8}) 이며 날짜 세그먼트에 의존한다. 신구 두 형식의 파싱 자체는 모두 정확하며, 문제는 실제 산출물이 더 이상 날짜 세그먼트를 포함하지 않는다는 점이다.

#4514 는 Ascend NPU에서 do_bench 가 반드시 크래시한다고 보고하며, 오류는 aclrtDeviceL2CacheFlush failed: 207000 이다. profiler의 NPU 경로가 cache 버퍼를 cache_numel=0 의 빈 자리표시자로 변경한 후, _flush_cache 가 무조건 aclrtDeviceL2CacheFlush(None) 을 호출한다. dav-3510과 CANN 9.2.1에서 해당 호출이 실패한다. 두 이슈 모두 4개의 논의가 있다.

출처: https://github.com/tile-ai/tilelang/issues/4513.

오늘의 초점: 메인 저장소 세 건 모두 캐시 하위 시스템, 캐시 키에 툴체인 버전 포함

메인 저장소 모니터링 기간 내에는 세 건의 커밋만 있었으며, 두 건이 캐시를 직접 수정한다. 이는 전일의 ROCm 일괄 수정, Ascend 결함 보고와 뚜렷한 분업을 이룬다.

#4511 은 현재 CUDA 및 Ascend 툴체인 버전을 kernel 캐시 키에 포함하며, 20개 파일을 수정한다. tilelang/contrib/bisheng.py 를 신규 추가하고, pto_toolchain.py 는 그에 상응하여 슬림화되었다. BackendModule 에 toolchain_stamp 콜백을 추가하여 무인자 호출을 허용한다. CUDA 컴파일러 선택은 _cuda_compiler_module 로 통합되었다.

변경 동기는 캐시 무효화 경계이다. 이전에는 컴파일러를 교체하거나 CANN 버전을 변경한 후에도 이전 바이너리가 여전히 캐시에 히트할 수 있었다. 테스트 측에서는 Ascend 바이너리 캐시, PTO 캐시 및 JIT 진단 세 곳의 케이스를 동시에 보강했다.

#3756 은 공유 캐시의 권한을 처리한다. 캐시 항목은 먼저 임시 저장된 후 전체 디렉터리 이름 변경으로 게시되므로, 생성 프로세스의 umask를 따른다. SGID에 그룹 쓰기 가능이 설정된 공유 캐시 루트에서 umask 077인 프로세스는 0700 및 0600 항목을 생성하여 다른 사용자가 읽을 수 없다.

수정 방법은 게시 전에 임시 저장 항목을 legalize하는 것이다. 캐시 루트에 SGID가 있으면 디렉터리는 0o2755로, 파일은 0o644로 변경하고 실행 비트를 유지한다. SGID가 없는 루트 및 해당 비트를 지원하지 않는 파일 시스템은 원래대로 유지한다. 해당 커밋은 148줄의 권한 회귀 테스트를 추가하고, 공유 캐시 디렉터리 초기화 및 다중 루트 조회를 수정했다.

부수적으로 한 건이 심사 중이다. #4512 는 툴체인 아이덴티티별로 실행 가능 캐시의 키를 만드는 제목으로, #4511 과 동일한 주제에 속한다.

출처: https://github.com/tile-ai/tilelang/pull/4511.

1. 핵심 프로젝트 진행

1.1 캐시 키에 CUDA 및 Ascend 툴체인 버전 포함, 교차 툴체인 재사용 차단

#4511 은 LeiWang1999에 의해 23:09에 병합되었으며, 이번 기간의 유일한 기능적 변경이다. 제안 설명은 네 단계로 진행된다. 먼저 활성 툴체인별로 CUDA 및 Ascend JIT kernel의 키를 만들고, 툴체인 인식을 CUDA로 제한한 후, Ascend 툴체인도 포함시키고, 마지막으로 각 백엔드의 툴체인 스탬프를 통일한다.

구조적으로 BackendModule.toolchain_stamp 훅을 신규 추가한다. CUDA 측은 tilelang/cuda/backend.py 가 버전 문자열을 제공하고, Ascend 측은 tilelang/ascend/backend.py 가 제공한다. 둘 다 contrib 아래의 어댑터 계층을 거치도록 변경되었다.

테스트 측에서 여섯 개 파일을 수정했다. 세 가지 캐시 사용 사례 외에도, kernel 캐시를 명시적으로 끄는 host-mapped 출력 검증 테스트도 조정했다.

출처: https://github.com/tile-ai/tilelang/pull/4511.

1.2 공유 캐시가 SGID별로 그룹 읽기 가능 항목을 게시하며, umask 077에서도 더 이상 비공개 디렉터리를 생성하지 않음

#3756은 KellyFrog가 16:18에 병합했으며, kernel_cache.py와 새 테스트 파일 하나를 변경했다. 제안서는 문제를 게시 방식으로 귀인한다. 임시 저장 후 디렉터리 전체 이름을 바꾸면 권한이 umask에서 비롯되어 공유 루트의 SGID 의도와 일치하지 않는다.

판정 조건은 캐시 루트에 SGID가 있는지 여부만 본다. 있으면 디렉터리 0o2755, 파일 0o644이며 실행 비트는 유지된다. 없으면 그대로 두어 Windows 등 해당 비트를 지원하지 않는 파일 시스템을 커버한다.

테스트는 공유 루트와 비공개 루트 두 가지 상황을 커버한다. POSIX가 아닌 시스템과 POSIX 권한을 지원하지 않는 파일 시스템은 건너뛴다.

출처: https://github.com/tile-ai/tilelang/pull/3756.

1.3 CUDA 어텐션 샘플 테스트 병렬화, CI 단일 작업 시간 단축

#4485는 block causal attention의 샘플 사용 사례를 병렬 실행으로 바꾸고 Z3에 예산을 추가했다. 3개 파일을 변경했으며 ci.yml 한 줄을 포함한다.

제안서는 중간에 DeepSeek TopK의 Z3 예산 커버리지를 한 번 철회했다가 이후 z3 한도를 복원했다. 전날의 #4463과 #4489도 동일한 TopK 사용 사례 세트의 솔버 소요 시간을 둘러싼 것이었으며, 이번 건은 테스트 소요 시간의 마무리에 해당한다.

출처: https://github.com/tile-ai/tilelang/pull/4485.

1.4 야간 휠 0.1.16으로 표기 변경, build_date()가 dev 버전에서 None 반환

두 야간 휠 모두 0.1.16 기반이다. 22:30 것은 커밋 fa93ba14에 해당하며, 이는 이번 기간 #4485의 병합 지점이다. 13:18 것은 3684ae6a에 해당하며, 모니터링 기간 시작 이후 첫 번째 건이다.

#4513은 tilelang.build_date()가 0.1.16+gita3a4f9ce에서 None을 반환한다고 지적한다.

5. 동향 관찰

  • 캐시가 구현 세부사항에서 일급 시민으로 변모하고 있습니다. 하루 만에 이와 관련된 세 건이 있었습니다: 캐시 키가 툴체인을 인식하고, 공유 캐시가 권한을 인식하며, 심사 중인 건은 툴체인 신원에 따라 실행 가능 캐시의 키를 부여합니다. 다중 사용자 빌드와 다중 툴체인 병존이 주된 동인입니다.

  • 0.1.16의 릴리스 경로가 이미 빌드 측까지 진행되었습니다. 야간 휠이 먼저 0.1.16으로 표기를 변경했지만, 태그와 PyPI는 여전히 0.1.15에 머물러 있습니다. 버전 문자열에서 backend 태그가 제거된 후, 구 형식에 의존하던 두 곳의 코드가 당일 회귀를 보고했으며, 이는 형식 변경의 호환 범위가 예상보다 넓음을 보여줍니다.

  • Ascend의 결함 구성이 변화하고 있습니다. 전일에는 열 가지 “수용해서는 안 되는 입력이 수용된” 사례였으나, 이번 호는 T.fmod의 하강 누락, SimtVF 스코프 오판, PTODSL 다중 kernel 심볼 충돌입니다. 문제가 인터페이스 계약에서 컴파일 및 링크 계층으로 내려갔으며, 단일 수정 비용이 상승하고 있습니다.

  • TileOPs의 최적화가 kernel 내부뿐만 아니라 모델 호출 방식으로까지 확장되기 시작했습니다. ReLU를 비제자리로 교체, 인덱스 텐서를 매 단계 한 번만 계산, 디코딩 단계 전체를 CUDA graph로 처리하는 세 가지 모두 스케줄링과 복사를 줄이는 것이지 단일 코어 연산량을 높이는 것이 아닙니다.

  • 채택 측의 속도가 빨라지고 있습니다. FlashQLA는 하루 만에 v0.1.4의 코드, 벤치마크, 문서 및 기술 보고서를 완성했고, TileFoundry는 검증 범위를 학습 단계 수준까지 확장했습니다. TileLang의 다운스트림은 더 이상 kernel만 작성하지 않고 시스템 수준 예제도 작성하기 시작했습니다.

  • RISC-V 측은 연속 세 모니터링 기간 동안 변화가 없습니다. TVM 노선과 MLIR 노선 모두 제자리에 머물러 있고, 인덱스 페이지에도 새로운 PR이 없습니다.

검증 설명

기준: 모니터링 기간은 베이징 시간 11-25 07:00부터 11-26 07:00까지 총 24시간이다. 저장소 커밋은 committer 시간으로 집계하며, 먼저 이전 회차 기준점인 11-25 07:00과 비교한 뒤 신규 여부를 판정한다.

버전 측 표현은 세 단계로 나누어 기술한다: VERSION 파일은 0.1.16, 야간 휠은 0.1.16으로 빌드되었으며, GitHub 태그와 PyPI는 여전히 0.1.15이다. 본문에는 「0.1.16 릴리스됨」이라고 쓰지 않았다.

#4513과 #4514의 보고 환경은 소스 빌드 a3a4f9ce, 즉 11-25 09:11 UTC의 메인라인 커밋이다. 두 건 모두 공개 API 회귀이며 컴파일 실패가 아니다.

MLIR Ascend의 두 건은 PR의 base 브랜치로 대조했으며, 각각 mlir-dialect와 harness에 해당한다. Ascend 서브 저장소의 기본 브랜치는 ascendc_pto이며, 저장소별 스크립트를 main 기준으로 가져오면 빈 결과가 나온다.

Hygon의 푸시 시간은 검색 인터페이스에서 11-25 19:38로 표시되었으나, 이벤트 인터페이스로 대조한 결과 WatchEvent, 즉 스타 한 건으로 코드 푸시에 해당하지 않는다. 해당 저장소의 메인 브랜치에는 모니터링 기간 내 커밋이 실제로 없었다.

RISC-V 4개 소스는 이번에 인용 대조와 인덱스 페이지 PR 재검토를 수행했으며, 27건의 브랜치 인용이 이전 회차 기록과 한 줄씩 일치한다.

뉴스 측은 Google News 중영문, Hacker News, arXiv 세 경로로 재검토했으며, 모니터링 기간 내 TileLang 관련 보도는 실제로 없었고, 빈 결과를 수집 장애로 추정하지 않았다.
