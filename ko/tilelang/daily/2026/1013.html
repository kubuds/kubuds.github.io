1. 핵심 프로젝트 진행

1.1 메인 저장소: ROCm 두 건 — DeepSeek NSA 순전파/디코드와 flash-decoding 실행 가능 타일(10-13)

날짜: 2026-10-13(베이징 시간 새벽에 병합)　출처: ROCm NSA(#3152)／ ROCm flash-decoding 타일(#3149)

  • DeepSeek NSA on ROCm(#3152, +111/-2): gfx942의 웨이브프론트 크기는 64이며, TileLang은 웨이브프론트보다 작은 HIP block을 거부하는데, 두 NSA 예시는 32 스레드를 하드코딩하고 있었다; 이번 건은 순전파와 단일 token 디코드 커널에 대해 단일 64 lane 웨이브를 선택하고, CUDA의 기존 32 스레드 시작 구성을 유지하며, gfx942에서 인과 순전파와 단일 token 디코드의 정확성 커버리지를 보강한다(PyTorch NSA 레퍼런스 대조, FP16, 16 Q 헤드 1 KV 헤드, 시퀀스 64).
  • flash-decoding 타일 자동 적응(#3149, +82/-5): gfx942에서 128x64 타일의 생성 커널은 66048바이트 동적 LDS가 필요하며(65536 디바이스 상한 초과) 256 VGPR 한계에 도달해, 시작 시 「invalid argument」를 보고했다; 이번 건은 시작 전에 생성된 HIP LDS와 VGPR 점유를 검사하고, 예산을 초과할 때만 기존 64x64 타일로 폴백하며(디바이스 이름으로 하드코딩하지 않음), CUDA 경로는 변경하지 않고, gfx942 런타임 회귀를 추가한다.

1.2 메인 저장소: thread_storage_sync 정확한 스레드 경계(#3291) 및 #2954 수정(10-13)

날짜: 2026-10-13　출처: 정확한 스레드 경계(#3291)

  • thread_storage_sync에 대한 정확한 스레드 경계를 계산합니다(4개 파일, +292/-96). 작성자는 #2954가 이 커밋으로 수정되었음을 확인했으며, “동등한 부분 스레드 가드가 동일한 barrier로 환원됨”을 검증하는 테스트 케이스를 추가하고 SM89(4060 Ti)에서의 전후 컴파일 산출물 비교를 첨부했습니다.

1.3 메인 저장소: Autotune 구조화 실험 보고서, CodeRabbit 자동 할당 및 테스트 규범 문서 (10-12 ~ 10-13)

날짜: 2026-10-12, 2026-10-13　출처: 실험 보고서(#3393)／ CodeRabbit 자동 할당(#3487)／ 테스트 규범(#3489)

  • Autotune 실험 보고서(#3393, +98/-7): 실험적 AutoTuner.run(on_trial=...) 관찰자 인터페이스를 추가했습니다(RFC #3375에 대응). 시험마다 설정 인덱스, JSON 설정, 결과, 지연 시간, 검증 레이블, 제한된 오류 텍스트를 출력하며, 콜백은 집계 스레드와 공유 캐시 잠금 밖에서 실행됩니다. 보고/직렬화 오류는 해당 보고만 종료하고 튜닝에는 영향을 주지 않으며, 후보 생성·타임아웃·캐시 아이덴티티를 변경하지 않습니다. 작성자는 “콜백 vs 고정 JSONL 아티팩트”가 여전히 열린 API 결정 사항임을 명시했습니다.
  • 리뷰 가드레일(#3487, +1/-1): CodeRabbit의 reviews.auto_assign_reviewers를 true로 설정하여 실제로 review 요청을 발송하도록 했습니다(이전에는 순회 검토에서 권장 사항만 나열). 11개의 reviewer 규칙과 순서는 변경되지 않았습니다.
  • 테스트 규범(#3489, 8개 파일): Testing Style Guide를 신설했습니다 — 기존 커버리지에 의존할 시점, 최소 확장할 시점, 집중 커버리지를 신설할 시점. tilelang-cpp-style은 tilelang-dev-guide로 이름을 변경하고 C++ 규칙은 필요 시 참고용으로 전환했으며, CONTRIBUTING은 간소화하고 링크를 연결했습니다.

1.4 메인 저장소: Ascend PTODSL SIMT 리덕션 헬퍼 vendoring(#3469)으로 CANN Weekly 컴파일 수정 (10-12)

날짜: 2026-10-12　출처: PTODSL 리덕션 헬퍼 vendor(#3469)

  • PTOAS 상류에서 ptodsl/_allreduce.py를 제거하고 TileLang이 자체적으로 vendor하기를 기대했지만, 메인 저장소의 contrib/ptodsl/simt.py가 여전히 해당 모듈을 참조하고 있었습니다 — 최신 CANN Weekly(09-30)로 모든 PTO 대상 연산자를 컴파일하면 즉시 ModuleNotFoundError가 발생했습니다. 이 커밋은 헬퍼를 tilelang/contrib/ptodsl/allreduce.py로 vendored하고(+555/-115), 정수 부호 호환성을 monkey patch에서 리덕션 테이블 및 dtype 디스패치로 통합하여 PTO 대상의 사용 가능성을 복원했습니다.

1.5 메인 저장소 심사 중: SM120 MXFP8/MXFP4 블록 스케일링 MMA, L2 프리페치 및 Host IR 두 건 등 (10-12)

날짜: 2026-10-12　출처: SM120 MX 블록 스케일링 MMA(#3495)／ L2 프리페치(#3490)／ Host IR 직접 연결 JIT(#3481)／ Host IR 실행 통합(#3473)／ Windows ARM64 CI(#2962)

  • #3495 (+884/-51): T.gemm_blockscaled가 SM120/SM121에서 블록 스케일링 MMA 제품군을 NVFP4에서 MXFP8(kind::mxf8f6f4, 1X, UE8M0)과 MXFP4(mxf4nvf4, 2X, UE8M0)로 확장하며, FP32 누적, K 요소 32개마다 스케일 하나; 10-10에 병합된 SM121 점등(#3430)을 이어 하드웨어 매트릭스를 계속 확장한다.
  • #3490 (+87/-1): tl.prefetch_l2(addr, eviction_policy=...)를 신규 추가, evict_normal / evict_last를 지원하며 sm_80 이상을 요구하고, CUDA codegen이 정책을 컴파일 타임 템플릿 파라미터로 방출한다.
  • Host IR 두 건(#3481 / #3473): 직접 연결 Host IR JIT와 캐시, CUDA와 CuTeDSL 실행이 Host IR을 통해 통합되며 계속 심사 중.
  • 기타 심사 중: CI에 Windows ARM64 추가(#2962), JIT 파라미터 해시 가능 검증(#3417), 부분 웨이브 스칼라 리덕션(#3478), 양수 상수 제수 안전 guard 평탄화(#3488), cast 조합 검증(#3350), TMA 디스크립터 이름 검증(#3484) 등.

2. 멀티 백엔드 적응 (Ascend / MetaX / Hygon / Moore Threads)

2.1 Ascend: NSA Decode / NSA Bwd 두 건의 대규모 이관 병합——48개 계층별 테스트 (10-12)

5. 트렌드 관찰

5.1 ROCm 보강: 디바이스 예산 인식 관련 두 건의 수정

  • 이번 모니터링 기간의 두 건의 ROCm 수정은 동일한 주제, 즉 “디바이스 현실에 맞춘 적응”을 가리킴: gfx942의 64 lane 웨이브프런트(#3152)와 LDS/VGPR 예산(#3149). 둘 다 사용 사례 측(examples)에서 수정되었고 커널 내부 생성 전략은 건드리지 않았으며, 이는 ROCm 지원이 여전히 “실행 성공 및 회귀 추가” 단계에 있음을 보여줌. 메인 저장소의 최근 SM121, SM89 다세대 동시 수정과 합류한 후, TileLang의 백엔드 토폴로지는 “NVIDIA 우선”에서 “다중 디바이스 동시 유지보수”로 전환 중임.

5.2 SM89가 두 번째 플랫폼으로: 하루 6건 머지에 4건 심사 중

  • TileOPs가 하루 만에 6건의 SM89 머지(어텐션 프리필/디코드, 선형 어텐션, Norm 전면 커버)에 4건의 SM89 심사 중을 더함. RTX 40 시리즈와 L40 / 6000 Ada급 워크스테이션이 연산자 라이브러리 측에서 Hopper와 나란히 상시 목표가 됨. 평가 측도 동기화(야간 기준선 +10 항목)되어, SM89의 정확성 커버리지는 “컴파일 가능”에서 “회귀 보유”로 나아가는 중.

5.3 Ascend 마이그레이션 라인은 정확성 마무리 단계로 전환

  • NSA 정방향/역방향 두 건의 대규모 마이그레이션 머지(합계 48개 계층별 테스트), 캐시 3분할과 cross-warp allreduce 그룹화 수정이 이어짐 — Ascend 라인의 중심이 “예제와 연산자 이식”에서 “정확성, 캐시 의미론, 컴파일 사용성”의 마무리 감사로 이동. #3469 수정 직후 커뮤니티 피드백에 따른 정확성 수정(#3494)이 등장해 협업 루프가 정상 작동함.

5.4 릴리스 침묵기의 기준선 성장

  • 메인 저장소는 09-30 v0.1.15 이후 신규 릴리스 없음. 조직 오픈 PR은 총 507건(이전 호 498건), 단일 모니터링 기간 신규 41건, 머지 20건 — “머지 게이트는 조이고 심사 대기열은 두꺼워지는” 구조가 지속됨. TileOPs의 SM89 확장과 야간 기준선 +10은 정식 버전이 침묵하는 동안에도 머지와 평가 두 라인의 “정적 준비”가 계속 축적되고 있음을 보여주며, 릴리스 창이 임박했다는 판단은 변함없음.
