오늘의 중점: 주말 전면 추진——TileOPs 21건 병합 마무리, 메인 저장소 SM121 착지, TileFoundry 희소 링크 관통(10-10 ~ 10-12)

날짜: 2026-10-10 ~ 2026-10-12　출처: TileOPs PR 목록／ Op 기반 클래스 리팩터링(#2520)／ SM121 블록 스케일링 MMA(#3430)／ 희소 디코딩 TIR 관통(#223)／ 야간 스냅샷(fc2a2a91)

모니터링 기간 48시간 내 조직은 34건을 병합했고(메인 저장소 9, TileOPs 21, TileFoundry 2, MLIR 경로 1, 문서 1), 42건을 새로 열었으며, 8개 저장소에 푸시가 있었고, 리듬은 토요일 종일, 일요일과 월요일 새벽까지 이어졌다——병합 분포는 토요일 23건, 일요일 9건, 월요일 새벽 2건으로, 주말 병합량이 이전 모니터링 기간(금요일)의 21건보다 뚜렷하게 많았다.

  • TileOPs 주말 하루 만에 21건 병합: Op 기반 클래스 「직무별 단일 체계」 대규모 리팩터링(#2520, 363개 파일, 순감 약 1865줄)이 릴리스 전에 마무리되었다. MLA, KDA, NSA 세 가지 성능 라인이 동시에 마감되었고, attention sinks 5연속과 masked FP8 GEMM 등 새로 열린 건이 추가되었다(자세한 내용은 3장 참조).

  • TileFoundry는 희소 디코딩을 TIR까지 밀어붙였다: #223(84개 파일, +4424/-1543)은 DSA 디코딩의 손실 루프 작업량, 조회 청구 과다와 단계별 업데이트 오류를 수정하고, 아래첨자 방식 비동기 수집, Bitcast와 Where를 구현했다(자세한 내용은 1.5 참조).
  • 야간 파이프라인이 세 번의 스냅샷을 연속 생성(최신 병합 지점 #2525): 정확성 1032건, 벤치마크 1947건(52개 스위트), 실패 0건 오류 0건. 이전 스냅샷 대비 각각 2건 증가했고, 이틀에 세 번의 스냅샷이 중단 없이 이어졌다.

1. 핵심 프로젝트 진행 상황

1.1 메인 저장소: SM121(DGX Spark) 블록 스케일링 MMA 점등; CuTeDSL 펜스 선출과 파라미터 아이덴티티 수정(10-10 ~ 10-11)

날짜: 2026-10-10, 2026-10-11　출처: SM121 블록 스케일링 MMA(#3430)／ CuTeDSL 펜스 선출(#3400)／ NVRTC / CuTeDSL 파라미터 아이덴티티(#3414)

  • SM121 지원 추가(#3430, 10-11 00:32 머지): SM121(GB10, DGX Spark)은 실제로 SM120급 warp 블록 스케일링 MMA를 지원하지만, tl::sm120_mma_sync_blockscaled는 CUTLASS_ARCH_MMA_SM120A_ENABLED만 검사하며(이는 __CUDA_ARCH__ == 1200일 때만 정의됨), 이로 인해 sm_121a에서 모든 블록 스케일링 MMA가 OMMA.SF 대신 BPT.TRAP으로 컴파일되었다. 이번 커밋은 arch와 패밀리 기준으로 SM120 / SM121 타깃을 동시에 허용하도록 변경하고, NVF4 테스트를 SM12x 패밀리 기준으로 게이팅하며, CuTeDSL TMA 아키텍처 테이블에서 sm_121 / sm_121a를 허용한다. 작성자는 DGX Spark(드라이버 580.178.04, CUDA 13.0)에서 실측 통과했다.
  • 펜스 선출(#3400, 10-10 10:47 머지): sync_grid()는 이전에 모든 tid.x == 0 스레드를 선출하여, 2D / 3D 스레드 블록에서 여러 스레드가 동일 블록 도달을 중복 발행하고 펜스가 조기에 해제될 수 있었다. 이제 물리 스레드 (0, 0, 0)만 선출하며, 카운터 / 세대 프로토콜과 협력적 시작은 변경되지 않는다. 회귀 테스트는 1D / 2D / 3D 그리드와 반복 재사용을 커버한다(RTX 5090, CuTeDSL 4.7.0).
  • 파라미터 아이덴티티(#3414, 10-10 13:58 머지): NVRTC와 CuTeDSL 호스트 래퍼는 이전에 원시 Var 이름으로 시그니처를 생성하고 출력 이름으로 파라미터를 매칭하여, 중복 이름(stream, device_id 등)과 디바이스 측 이름 변경이 서로 간섭할 수 있었다. 이제 Var 아이덴티티 기준으로 래퍼 파라미터 이름을 할당하고 위치 ABI를 유지하며, CuTeDSL은 동일 커널을 서로 다른 스칼라 바인딩으로 반복 호출할 수 있게 되어 동일 이름의 shape / stride 심볼을 구분할 수 있다.

1.2 메인 저장소: GEMM dtype 화이트리스트 마무리 — 지원되지 않는 조합은 CUDA codegen 전에 거부(10-12)

날짜: 2026-10-12　출처: GEMM dtype 화이트리스트(#3245)

  • 일부 T.gemm 피연산자 dtype 조합(예: bf16 x bf16 → fp16)은 이전에 프런트엔드에서 허용되어 nvcc 내부에서 불투명한 static_assert로 실패했다(결함 티켓 #3004). 이번 커밋은 Ampere / Ada mma.sync 경로에 명시적 dtype 화이트리스트를 추가하여, 프런트엔드(tileop/gemm)와 C++ 명령 선택 양쪽에서 강제하며, 지원되지 않는 조합은 CUDA codegen 전에 명확한 메시지와 함께 거부된다.
  • 부정 예시 1건과 긍정 예시 3건의 회귀 테스트를 첨부했으며, 지원되는 조합과 비 Ampere 타깃의 동작은 변경되지 않는다. 이 커밋은 10-12 01:21에 머지되어 모니터링 기간 마감 전 최신 커밋이다.

1.3 메인 저장소: For 스텝, JIT 출력 인덱스, popcount, 비트 리덕션 및 테스트 인프라 다섯 건 확정(10-10 ~ 10-11)

날짜: 2026-10-10, 2026-10-11　출처: For 루프 스텝(#3427)／ JIT 출력 인덱스(#3318)／ popcount(#3300)／ 비트 리덕션(#3332)／ 테스트 인프라(#3313)

  • For 스텝 크기（#3427, 10-10 12:54 병합）: 루프 전달 충돌 분석이 이전에는 스텝 크기를 항상 1로 간주했으나（주석 「기본값 1, 미지정 시」와 상충），비단위 / 부호 스텝 크기에서 유효 반복 쌍 판정이 왜곡되었습니다. 이제 명시적 스텝 크기에 따라 반복 쌍 범위를 축소하고, CUDA와 HIP codegen 모두 스텝 크기를 유지하며 CodeGenC에 위임하여 발행하고, 루프 전개 시의 어휘적 할당 스코프도 함께 고려합니다.
  • JIT 출력 인덱스（#3318, 10-10 12:02）: out_idx=[-1]이 파라미터 개수가 다른 커널 간에 재사용될 때 정규화로 인해 오염되었습니다（2-파라미터 커널이 [-1]을 [1]로 정규화하고, 4-파라미터 커널이 이후에 입력 슬롯을 잘못 점유）. 이제 정규화 전에 호출자 목록을 복사하고, 파라미터 개수와 동일한 스칼라 인덱스를 거부하며, 유효 범위를 제공합니다.
  • popcount（#3300, 10-10 12:02）: 부호 있는 정수와 8 / 16비트 좁은 정수의 CUDA 하강을 보완했습니다. 먼저 원래 폭에 따라 부호 없는 정수로 변환한 후 확장합니다（int8(-1)은 32비트가 아닌 8비트로 계산）. 64비트는 __popcll으로 처리하며, 8가지 dtype 회귀를 커버합니다. #2984를 수정했고, H100（CUDA 13.0）에서 16개 테스트 전부 통과했습니다.
  • 비트 리덕션（#3332, 10-11 14:13）: reduce_bitand / bitor / bitxor가 이전에는 대상 버퍼만 검사하고 부동소수점 소스를 허용했습니다（[1.0, 2.0, 4.5, 8.9]가 경고 없이 1 2 4 8 = 15로 조용히 잘림）. 이제 소스와 대상 모두 정수 / 불리언 규칙에 따라 거부합니다（refs #3301）.

5. 트렌드 관찰

5.1 온전한 주말: 34건 머지가 토요일, 일요일과 월요일 새벽에 걸쳐 실행

  • 34건 머지는 토요일 23건, 일요일 9건, 월요일 새벽 2건으로 분포했고, 42건 신규 오픈도 하루 종일 분포했다(일요일 밤부터 월요일 새벽까지 신규 오픈 지속). 이전 모니터링 기간(금요일)의 21건과 비교하면 — 주말 머지량이 이전 근무일보다 많았으며, 프로젝트의 「7×24 롤링」 리듬은 이미 안정되었다.
  • 평가 기반도 동시에 롤링한다: 이틀 동안 세 차례 야간 스냅샷이 중단 없이 이어졌고, 정확성 1032건, 벤치마크 1947건 규모는 계속 상승하고 있다.

5.2 리팩터링 마무리와 버전 침묵: 릴리스 기간이 눈앞

  • 세 가지 신호가 겹쳤습니다. TileOPs의 Op 기본 클래스 리팩터링은 스스로 “릴리스 전” 마무리라고 칭하며(한 번에 약 1865줄 순감소), 문서 사이트는 다음 날 《Op 기본 클래스 가이드》로 후속 대응했으며, 메인 저장소 태그는 09-30 v0.1.15 이후 조용히 유지되고 야간 파이프라인은 계속 제로 실패로 평가 기반을 갱신하고 있습니다.
  • 엔지니어링 품질 작업(네이밍 / 캐시 시맨틱 / 리뷰 가드레일)은 이번 모니터링 기간에도 계속 집중적으로 착지했으며, “먼저 기준선을 고정하고 이후 정식 버전을 낸다”는 경로가 뚜렷합니다. 다음 버전 릴리스를 위한 정적 준비는 이미 완료되었습니다.

5.3 하드웨어 커버리지 동시 주간 확장: SM121 점등, SM89 성능 정책 대량 적용

  • 같은 기간에: SM121(GB10 / DGX Spark) 점등 블록 스케일링 MMA(#3430), SM89(RTX 40 시리즈 / L40급)에 대량 디코딩 성능 정책 적용(#2510 / #2511 / #2506), SM90(H100 / H200)은 계속 세분화(#2512 / #2497 / #2503).
  • 하드웨어 중심축이 “단일 Hopper 최적화”에서 “여러 세대 동시 수정, 소비자급 진입”으로 전환되었습니다. 국산 백엔드도 같은 박자로: Ascend 희소 MLA 마이그레이션 2건에 캐시 수정 4연타, Hygon 레지스터 파이프라인 업데이트.
