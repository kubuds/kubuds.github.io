1.1 메인 저장소: 벡터화 분석에 0 아닌 루프 하한 포함(#3579)

10-21 00:27에 병합되었고, 10개 파일 +818/-198이며, #2819의 guard 수정을 이어받는 동시에 #2669, #2616 두 이슈를 닫습니다. 기존 구현은 f(i)와 f(floor(i / W) * W)를 비교하여 표현식이 각 벡터 그룹 내에서 동일한 값인지 판단했는데, 이는 루프가 0에서 시작한다는 암묵적 가정을 내포합니다. 루프 하한이 0이 아닐 때 unit-step 벡터화는 서로 다른 lane의 주소를 같은 그룹으로 계산하게 되어, 브로드캐스트 로드와 전체 그룹 공유 조건의 증명이 더 이상 유효하지 않게 됩니다. 새로운 판정은 루프 최솟값을 분석에 포함하고, 혼합 정밀도 변환을 옮길 때 중첩 guard를 유지합니다. 조용히 수치 결과를 바꿀 수 있는 컴파일러 결함에 해당합니다.

출처: https://github.com/tile-ai/tilelang/pull/3579

1.2 메인 저장소: 공유 메모리 스레드 간 WAW 검출(#2821)

10-20 23:41에 병합되었고, 3개 파일 +153/-19이며, #2698을 수정합니다. 공유 메모리에서 S[tx]와 S[tx + 10]은 단일 스레드에게는 서로 다른 두 주소이지만, 서로 다른 스레드의 쓰기는 겹칠 수 있습니다. 기존 WAW 검사는 두 접근에 동일한 스레드 변수를 재사용했기 때문에 판정을 놓치고 배리어 삽입을 누락했습니다. 수정 방법은 동일 반복의 WAW에 서로 다른 두 스레드 인스턴스를 사용하고 각자의 Bind 정의를 이름 변경하며, 기존 RAW/WAR 모델을 재사용하고 루프 전달 WAW는 기존 처리를 유지하는 것입니다. 테스트는 “삽입해야 하는” 경우와 “삽입하지 말아야 하는” 경우를 모두 포함하며, guarded 쓰기, Bind 파생 인덱스, 서로소 파티션, threadIdx.y/z 치환을 포함하고, 스레드 동기화와 issue 두 세트의 테스트 케이스 95건이 통과했습니다.

출처: https://github.com/tile-ai/tilelang/pull/2821

1.3 메인 저장소: 지원되지 않는 MMA tile에 명시적 K 패딩 요구(#2818)

10-20 16:41에 병합되었고, 5개 파일 +57/-14이며, #2715를 수정합니다. 범용 MMA emitter는 피연산자 레이아웃을 구성하기 전에 K 원자를 조용히 축소할 수 있어, FP16 K=8이 잘못된 결과를 계산하게 됩니다. K=20, K=28 같은 불규칙 크기는 공유 메모리 레이아웃 추론 단계에서 명확한 안내 없이 바로 실패합니다. 이제 emitter 초기화 시 아키텍처별로 고정된 K 원자에 따라 tile의 K를 검증하고, 나누어떨어지지 않으면 ValueError를 발생시키며, 입력 dtype, 필요한 나눗셈 관계, 권장 패딩 값(예: SM80에서 FP16 K=20은 원자 16으로 보고, K=32까지 채우고 남는 원소를 0으로 채우도록 권장)을 포함합니다.

출처: https://github.com/tile-ai/tilelang/pull/2818

1.4 메인 저장소: fragment reduce가 유지 차원 목표 지원(#2815)

10-20 16:35에 병합되었고, 8개 파일 +343/-63이며, #2530을 수정합니다. T.reduce_sum 등이 (64, 64)를 dim=1을 따라 (64, 1)로 축약할 때 컴파일 타임에 크래시합니다(Check failed: vars.size() == InputDim() (2 vs. 1)). 반면 reduce_op.py의 문서 계약은 [X, Y]와 [X, 1, Y] 두 출력 형태를 모두 명시적으로 허용하고 이미 대응하는 기대 형태를 구성하고 있으므로, 이는 오용이 아니라 백엔드의 결함입니다. 수정은 두 lowering 경로를 동시에 처리하고, 유지 차원 목표가 없는 기존 동작을 보존합니다.

출처: https://github.com/tile-ai/tilelang/pull/2815

1.5 메인 저장소: TIR 조건자가 정수 비트 폭 상향에 따라 동기적으로 재작성(#3550)

10-20 09:59에 병합되었으며, 4개 파일에서 +950/-27입니다. 정수 인덱스가 더 넓은 비트 폭으로 승격된 후에도 제어 버퍼 접근을 검사하는 경계 검사는 여전히 이전 비트 폭으로 계산되어, 이론적으로 범위를 벗어난 접근을 통과시킬 수 있습니다. 새로운 IndexPredicateRewriter를 추가하여 ConfigIndexBitwidth와 FlattenBuffer에서 각 접근의 승격 정보를 기록하고, 접근 문장 처리가 끝난 후 관련 guard를 재작성합니다. 매칭은 동등한 덧셈 및 곱셈 형태로 제한되며, 무관한 조건, 데이터 값 표현식 및 고정 폭 경계는 보존됩니다. 인덱스 승격, guard 재작성, 접근 범위, 벡터 엔드포인트 및 충돌 승격의 다섯 가지 테스트를 새로 추가했습니다.

출처: https://github.com/tile-ai/tilelang/pull/3550

1.6 메인 저장소: CuTeDSL scan 참여 스레드 오프셋 보완 (#3576)

10-20 12:49에 병합되었으며, 2개 파일에서 +30/-6입니다. 공유 메모리 scan lowering은 #3536에서 참여 스레드 오프셋을 도입했지만, CuTeDSL 측 helper는 여전히 이전 생성자 인수로 호출을 생성하여 tl.CumSum1D(32, False, 0).run(...)가 직접 생성자 인수 오류를 보고합니다. 같은 배치에서 무효화된 codegen 어서션도 #2815의 두 번의 CUDA CI 실패 원인입니다. 수정 방법은 1차원, 2차원 cumsum/cummax helper에 선택적 thread_offset(기본값 0으로 호환성 유지)을 추가하고, 참여 lane과 warp를 선택하기 전에 오프셋을 빼며, CUDA 전용 테스트에 requires_cuda를 지정하는 것입니다.

출처: https://github.com/tile-ai/tilelang/pull/3576

5. 트렌드 관찰

컴파일러 정확성이 이번 모니터링 기간의 주된 흐름이 되었으며, 기능 확장이 아니다. 메인 저장소의 9건 머지 중 5건은 조용한 오류 정리였다: 벡터화가 루프가 0에서 시작한다고 가정(#3579), 공유 메모리 WAW 누락 판정(#2821), MMA emitter의 조용한 K 원자 축소(#2818), fragment reduce 보존 차원 충돌(#2815), 인덱스 비트 폭 향상 후 프레디케이트 미추종(#3550). 이러한 결함의 공통점은 오류를 보고하지 않고 잘못된 결과만 내거나 배리어를 누락한다는 것으로, 사용자가 생산 환경에서 가장 찾기 어려운 유형에 속한다. 같은 날 TileOPs의 #2661도 “성능 상한 기준”을 수정하고 있어, 프로젝트가 “숫자의 신뢰성”을 “빠르게 실행됨”과 동급의 엔지니어링 목표로 삼고 있음을 보여준다.

Ascend 라인이 예제 보충에서 훈련 측으로 전환되고 있다. 5건의 머지 중 3건은 역방향 또는 재귀 연산자(indexer_bwd, situ_glu_grad, LSTM/GRU)이며, situ_glu_grad는 Kimi K3 Stable LatentMoE의 게이트 활성화에 직접 정렬하고 910B3에서 aclnn과의 교차 검증 데이터를 제시한다. #3577의 DeepGEMM-Ascend 구성 선택과 epilogue 정렬과 함께, Ascend 측의 커버리지는 추론 전방에서 훈련 역방향, 상태 재귀와 대형 모델 MoE 게이팅으로 확장되고 있다.
