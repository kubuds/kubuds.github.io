1. 핵심 프로젝트 진행

1.1 메인 저장소: Ascend PTO 실행 라우팅——ascend × pto 직결 PTO codegen(#3316)(10-15)

날짜: 2026-10-15　출처: PTO 실행 라우팅(#3316)／ 메인 저장소 PR 목록

  • 실행 라우팅(#3316): target="ascend"와 execution_backend="pto"의 조합이 실제로 작동하도록 함——명시적 PTO 실행 백엔드가 백엔드 해석 전에 네이티브 Ascend 타깃을 PTO 타깃 변형으로 특수화하고(arch 등 타깃 속성 유지), 컴파일은 이에 따라 PTO 백엔드와 PTO 디바이스 코드 생성기(CodeGenTileLangPTO, 즉 codegen_pto.cc)를 선택한다. 구현상 실행 인식 타깃 정규화 훅을 새로 추가하여 BackendContext 생성 지점에 연결하며, Ascend 전용 정규화기가 매핑을 담당하고 디바이스 코드 생성은 PTO_CODEGEN과 target.build.tilelang_pto_without_compile로 전환된다.
  • 경로 의미론(PR 동작 표): ascend × auto는 AscendC + TVM-FFI 경로를 유지하고, ascend × tvm_ffi / cython은 AscendC를 사용하며, ascend × pto와 기존 target="pto" 축약형은 모두 PTO 백엔드를 사용한다. 문서는 동등한 환경 구성으로 TILELANG_DEFAULT_TARGET=ascend에 TILELANG_EXECUTION_BACKEND=pto를 제시한다. 테스트는 직접 컨텍스트 해석, 타깃 속성 유지, 캐시 디스패치, 환경 변수 선택을 커버한다.
  • 연결: 10-14에 병합된 예시 타깃 선택(#3474, CI가 ascend와 pto 두 타깃에 대해 모든 Ascend 예시를 각각 한 번씩 실행)과 심사 중인 PTO 패밀리(tvm_ffi 실행 백엔드 #3516, VMI 벡터화 #3512, SS buffer #3514, 부분 L0 복사 pitch #3511)를 이어받는다——Ascend 측의 “이중 경로 병존”이 “하나의 타깃, 두 가지 실행 백엔드”로 나아가고 있다.

1.2 메인 저장소: JIT가 해시 불가능한 컴파일 타임 인자 거부(#3417), 테스트 컴파일 시간 제거(#3517)(10-15)

날짜: 2026-10-15　출처: JIT 해시 검증(#3417) / 테스트 컴파일 시간(#3517)

  • JIT가 해시 불가능한 컴파일 타임 인자 거부(#3417): JIT 특수화는 이제 컴파일 타임 인자와 기본값이 해시 가능할 것을 요구한다——해시 불가능한 기본값은 JIT 래퍼 생성 시점에 즉시 TypeError를 발생시키고, 명시적으로 전달된 해시 불가능한 인자는 커널 조회 또는 팩토리 실행 전에 거부된다. 변경 가능한 기본값이 오래된 커널을 조용히 재사용하는 것을 방지하고, 지연 및 즉시 두 가지 인자 계약을 통일한다. 검증은 hash()를 사용하며(해시 불가능한 값을 포함하는 튜플 포함), 호출 형식 캐시는 먼저 해시 가능성을 확인한 뒤 “마지막 호출 동등” 지름길을 적용하고, 컨테이너 내용 정규화를 제거하며, 런타임 텐서 인자는 여전히 특수화 키에 포함되지 않는다. 검증: 네이티브 소스 재빌드 통과, 인자 바인딩 및 관련 스위트 합계 91개 통과, 스킵 없음.
  • 테스트 컴파일 시간 제거(#3517):
    test_tilelang_issue_2994.py의 네 개 packed-type CUDA 소스 헬퍼 함수가
    target.build.tilelang_cuda_without_compile로 전환되어(생성 소스만 가져오고 전체 빌드는 수행하지 않음), 이 헬퍼 함수들은 원래 생성 소스만 검사하므로 더 이상 일반 빌드 오버헤드를 부담하지 않는다.

1.3 메인 저장소 심사 중: cumsum 공유 버퍼 warp 특수화 수정 신규 개설(#3536), PTO 패밀리 일곱 건 진행(10-15)

날짜: 2026-10-15　출처: cumsum 수정(#3536) / PTO tvm_ffi(#3516) / VMI 벡터화(#3512) / SS buffer(#3514) / 부분 L0 복사(#3511) / UB에서 L1로 부분 복사(#3530) / PTO Ramp 값(#3535) / SIMT VF 접근(#3523)

  • cumsum 공유 버퍼 warp 특화 수정(#3536, 10-16 새벽 신규 개설): warp 특화에서 소비자 스레드가 128부터 번호가 매겨지는데, 공유 메모리 스캔 템플릿이 스레드 구간 하한을 전달받지 못함——CumSum1D / CumSum2D가 각 소비자 스레드에서 조기 반환하고 버퍼가 기록되지 않은 채로 유지됨; 수정은 스레드 구간 최솟값을 스캔 템플릿에 전달함(AllReduce는 이미 그렇게 작성되어 있음), HIP 측 스캔 템플릿도 동기 수정(LowerSharedScan은 두 백엔드가 공유). 1D / 2D 공유 버퍼의 파이프라인 T.cumsum 케이스 추가. 검증: H100에서 19개 통과(신규 파이프라인 케이스는 main에서 2건 실패); #3528 재현 케이스는 수정 후 131072개 항목 전부 정확(main에서는 129019개 항목 오류). #3528 수정.
  • PTO 패밀리 7건 진전: #3516(PTO 타깃 tvm_ffi 실행 백엔드), #3512(T.Parallel에서 PTO VMI 벡터화), #3514(SS buffer), #3511(부분 L0 복사 명시적 pitch), #3530(NZ 버퍼의 UB에서 L1로의 부분 복사, 신규 개설), #3535(PTO Ramp 값을 타입별로 벡터 발행, 신규 개설), #3523(SIMT VF 내 벡터 로컬 접근 수정, 신규 개설).
  • 기타 심사 중: TMA 생산자 한정(#3503), 공유 버퍼 이중 확장 방지(#2342), SM120 MXFP8 / MXFP4 블록 스케일링 MMA(#3495)와 mxf8f6f4 전체 오퍼랜드 패밀리(#3099) 지속 업데이트; profiler L2 읽기 전용 플러시(#3534)와 공유 스캔 스레드 수 진단(#3532) 신규 개설. 메인 저장소 오픈 PR은 총 165건(이전 회차 160).

3.1 TileOps: 어텐션 삼연속 병합——varlen GQA 집계, 페이징 GQA 전체 기능 및 페이징 KV 쓰기(10-15)

  • varlen GQA 싱크 및 파이프라인 슬라이딩 윈도우(#2537): FP16 / BF16 / FP8 varlen GQA에 선택적 FP32 per-head sinks를 추가——sink는 softmax 분모에 들어가는 unscaled, untruncated logit이며, “어텐션 싱크” 이슈(#2269)의 varlen 부분을 커버하고 동시에 파이프라인화된 슬라이딩 윈도우를 병합한다.
  • 페이지드 GQA 전체 기능(#2516): GQAPagedFwdOp에 읽기 전용 RoPE, 양방향 슬라이딩 윈도우와 선택적 per-head sinks를 추가하여 어텐션 싱크 이슈의 페이지드 경로 부분을 보완한다.

3.2 TileOPs: foundry 성능 3건——W4A16 로드 재정렬, sigmoid IEEE 나눗셈 면제, SM89 스캔 확장(10-15)

날짜: 2026-10-15　출처: W4A16 사전 로드(#2586)／ sigmoid IEEE 나눗셈 면제(#2588)／ SM89 스캔 확장(#2574)／ TileOPs PR 목록

  • W4A16 가중치 선행(#2586): GemmW4A16Kernel은 기존에 packed 가중치 이전에 각 K 타일의 활성화를 복사했고, warp 특화 프로듀서가 이 순서로 발행하고 단계별로 대기하여 가중치의 DRAM 로드가 실제로 한 K 타일 늦게 이루어졌다; 이제는 가중치가 선행한다(해당 stage는 디코드 읽기 후 즉시 해제). 8행 디코드 타일은 세 번 대신 한 번의 시프트로 대체한다(w4a16_dequant_word_one_shift가 제자리에서 마스크 홀짝 니블을 처리하고 한 번의 FMA로 중심을 맞추며, 가중치에 1/16을 곱함). decode-long-k는 marlin-fp16의 1.047배(기존 0.996배)에 도달하고, 8행 타일은 각 행이 2.5%에서 7.6% 빨라졌으며, prefill-mlp-up은 5.7% 빨라졌다(torch 역양자화 행렬 곱 대비 0.992배로 동등); 느려진 행은 없다.
  • sigmoid IEEE 나눗셈 면제(#2588): make_unary_regcopy가 evict_last 로드를 지원——전체 16바이트 벡터의 스레드는 tileops::load16_evict_last를 타고, 마지막 블록은 벡터별 가드를 추가; SigmoidFwdKernel만 이 경로를 활성화한다(나머지 37개 단항 커널은 동일한 CUDA를 생성하며, 357개 커널을 dtype별로 대조). float16 sigmoid는 refined_reciprocal(__fdividef 역수에 뉴턴 한 단계 추가, 분기 없음)로 전환하여 원소별 범위 검사와 슬로우 패스 호출을 대체한다; float16 / bfloat16 결과는 torch.sigmoid와 비트 단위로 일치하고, float32는 IEEE 나눗셈을 유지한다. forward 입력은 vector_aligned를 타서 시작 원소가 16바이트 경계를 넘을 때의 정렬 오류 주소 버그를 수정한다. 16M 행에서 torch-compile 대비 1.020배에서 1.042배 앞서며; 테스트 노드 +2.
  • SM89 스캔 확장(#2574): 기존 16열 사전 채움 스캔이 4096에서 16384 token 구간에서 8개 값 헤드에서 16개 값 헤드로 확장된다(≤8 값 헤드 호출은 기존 전략 유지); 동일한 스캔 프로그램과 빌드 아이덴티티를 공유하며, GDN과 DeltaNet이 이익을 보고 KDA는 변하지 않는다. 전체 목록 A/B 후 19개 영향 워크로드가 최종적으로 2.5%에서 19.7% 빨라졌다.
  • TileOPs 오픈 PR은 16건 집계(이전 기간 17); 신규 5건: 래스터 퍼시스턴트 타일(#2589), GemmW4A8FwdOp(#2590, INT4 가중치 곱하기 FP8 활성화), 읽기 전용 페이지드 GQA FP8(#2591), SM89 롱 프리필 32열 스캔(#2592) 등.

  • Google News 중문 및 영문 다중 쿼리 모니터링 기간 내 신규 제로——영문 쿼리는 10-14의 리뷰 기사를 적중했으나 이미 모니터링 기간 밖; 중문 쿼리는 제로 적중. Hacker News는 관련 항목 제로(Show HN 두 건은 퍼지 매칭 노이즈에 해당). arXiv는 신규 프리프린트 없음(최신 관련은 여전히 07-24의 TileSight).

5. 트렌드 관찰

5.1 PTO가 “독립 목표”에서 “일급 실행 경로”로 이동

  • #3316은 ascend 목표가 PTO 실행 백엔드를 직접 선택할 수 있게 하며, 모니터링 기간 이전의 #3474(환경 변수 목표 선택, CI 듀얼 목표 병렬) 및 심사 중인 #3512 / #3514 / #3516 / #3511과 함께 PTO를 “독립 목표, 별도 링크”에서 “Ascend 목표 상의 조합 가능한 실행 경로”로 전환. 이와 대조적으로 ascend 저장소 #1900은 dav-3510(A5) 상의 조용한 수치 오류 부류 문제가 체계적으로 포착되기 시작했음을 드러냄——한쪽 끝은 인터페이스 수렴, 다른 쪽 끝은 검증이 심수구에 진입, Ascend 측의 엔지니어링이 양 끝에서 동시에 추진되고 있음.

5.2 어텐션 패밀리 수렴: 장문 추론 연산자 면 보강

  • 단일 창 통합 sinks(varlen 및 페이징), 양방향 슬라이딩 창, 읽기 전용 RoPE, 페이징 KV 쓰기, 심사 중인 읽기 전용 페이징 FP8 및 32열 스캔 — TileOPs의 페이징 / 장문맥 어텐션 매트릭스가 보강되고 있으며, FlashInfer, vLLM, FLA 외부 대조를 검수 기준으로 삼고 있다. 다음 관찰 지점은 동일 계열 역량의 Ascend로의 이전(심사 중인 Sparse MLA, KDA chunk 시리즈)이다.

5.3 Hygon 이중 라인 유지보수와 분산 방향

  • Hygon은 v0.1.12-release(블록 수축 스케일링 패치)와 v0.1.15 메인라인(업그레이드가 통합되고 릴리스 브랜치가 확립됨)을 동시에 유지하며, distributed 브랜치로 IPC 집합 통신을 추진 중이다 — “구 라인은 납품 보장, 신 라인은 업스트림 추격, 신규 브랜치는 분산”이라는 삼중 구조가 명확하다. 멀티카드 통신이 실현되면 Hygon은 단일 카드 적응에서 멀티카드 시스템 단계로 진입하게 된다.

5.4 TileFoundry, 외부 감사 단계 진입

  • 핵심 리팩터링(인스턴스 슬롯 #232, lowering 계약 #233)이 막 착지한 같은 모니터링 기간에, 서드파티 스킬 저장소가 TileFoundry를 워크플로에 vendor로 포함시키고 emitter와 런타임 버그 목록을 나열하며 지원 경로를 획정했다 — 툴체인이 실제 사용 압력 아래에서 외부 감사화되기 시작한 것이다. 제품화의 전형적 궤적: 섀시 리팩터링 다음은 인터페이스 계약 수렴과 결함 대장 공개화다.
