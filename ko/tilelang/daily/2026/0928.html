오늘의 핵심: TileOPs 「Manifest 파라미터화 시그니처」 전체 라운드 마이그레이션 완료——17건 병합, 200개 연산자 릴리스 계획 당일 개시 (09-26/09-27)

날짜: 2026-09-26, 2026-09-27　출처: 설계 문서 PR (#2209)／ 시그니처 검사와 생성 (#2212)／ 200개 연산자 추적 이슈 (#2271)／ 24개 spec-only 항목 (#2279)

09-26 08:02부터 09-27 11:57 (베이징 시간)까지, TileOPs의 Manifest 시리즈 17건 PR이 순차 병합되어 연산자 목록을 YAML 표에서 「파라미터화 시그니처」(parametric signature)로 재작성하고, 동일 모니터링 기간에 200개 연산자 릴리스 계획을 개시했습니다:

  • 설계(#2209, 09-26 08:02 머지): 각 연산자를 manifest에 하나의 파라미터화된 시그니처로 작성 — forall 인덱스와 종류, 타입 패밀리와 대수적 데이터 타입(ADT), 폐쇄 표현식 언어, 읽기/쓰기 효과, 생성기를 동반한 워크로드 행, 검증 체크리스트; roofline 가격 책정은 ix 상의 인라인 표현식 평가로 변경; 연산자 설계 문서, 신뢰 모델, 테스트 가이드와 agent 도메인 규칙 동시 개정(13개 파일, +633/-1193, 삭제가 추가보다 많음).
  • 구현(#2212~#2227, 09-26 종일~09-27 정오): 시그니처 검사와 연산자 메서드 생성을 명세로부터 유도하도록 변경(#2212); 각 연산자 패밀리 순차 전환 — elementwise(#2216), moe(#2218), reduction/normalization(#2221), linear_attention(#2222), gemm/quantization/convolution(#2223), attention(#2224), mamba(#2214), pool/scan/rope/sequence-modeling/FFT(#2217); 마무리 작업(#2225, 09-27 10:32)으로 마지막 gemm 항목 전환 완료 및 레거시 manifest 경로 삭제; manifest YAML을 spec/ 디렉터리로 이전, 파일 명명 통일(#2227). 동반 동작 변경: 트리 내 커널 선언이 없는 디바이스에서 연산자 호출 시 OpNotAvailableError를 던지도록 변경(#2219).
  • 릴리스 계획(09-27 저녁): 추적 이슈 “TileOPs 200-operator release plan”(#2271) 개설 — 목표 200개 manifest 항목(implemented + spec-only 기준 집계; 신규 연산자만 계산, 확장과 스케줄링은 제외), 최악의 경우 추산표 첨부; 같은 날 PR #2279가 계획에 24개의 spec-only 항목과 새로운 sampling 패밀리를 추가, 해당 PR 설명에 따르면 저장소 카운트 배지가 172/177에서 172/201로 변경. 24개 신규 항목은 네 방향을 포괄: 양자화 패밀리 9개(INT8/INT4 per-tensor, per-channel, per-block과 SmoothQuant, FP8 per-block), 샘플링과 추측 디코딩 패밀리 6개(TopK/TopP/MinP/TopKTopP 마스크, SamplingFromProbs, ChainSpeculativeSampling), MLA와 KV 캐시 패밀리 7개(MLA Paged/Varlen, PagedKVCache 쓰기와 수집, MergeAttentionStates, DeepSeekSparseAttentionPaged), norm 1개(FusedQKNormRope)와 선형 어텐션 1개(KimiDeltaAttention).
  • 동반 제약(#2279): 신규 test_spec_reference.py가 spec-only 항목별로 워크로드마다 참조 구현을 실행하고 입력 쓰기와 호출 거부를 검증; 불변식 “implemented ⊆ public ⊆ manifest” 확립; 이슈에 5개의 spec-only 보완 추적(GQA 2건, GatedDeltaNet, DeltaNetInference, GLAInference)과 11개의 커널 커버리지 하위 작업(FP8 Q/K/V, RoPE, FP8 KV 캐시, GDN 변형 등)을 동시에 등록.

판독: 이는 TileOPs가 최근 2주간 진행한 “신뢰 엔지니어링”(roofline 자체 점검, 공식 오류 수정 이후)의 제도적 승격이다 — 먼저 계약을 정하고, 그다음 구현을 정하며, 검사는 생성기가 담당한다; 200 연산자 계획은 로드맵을 공개화했고, 양자화, 추측 디코딩, MLA와 KimiDeltaAttention 등 자국산 대형 모델 연산자 방향이 이에 따라 부상하고 있다. 사용자 입장에서 연산자 동작의 “계약 출처”가 코드 주석에서 검증 가능한 명세로 바뀌었으므로, 연동 전에 커버리지 공백을 먼저 평가할 수 있다.

날짜: 2026-09-25　출처: #3276

5. 트렌드 관찰

5.1 “계약 우선”의 제도화: roofline 자체 점검에서 릴리스 계획까지

3단계 경로가 이번 모니터링 기간에 완전히 나타남: 09-20의 roofline 목록 자체 점검(어떤 공식이 한 번도 실행된 적 없는지) → 09-26/09-27의 파라미터화 시그니처 전면 마이그레이션(계약이 검사와 생성의 유일한 소스가 됨) → 09-27의 200 연산자 릴리스 계획(spec-only로 먼저 계약을 정착, 카운트와 커버리지를 공개 추적). 엔지니어링적 의미: TileOPs가 “구현 지향”에서 “계약 지향” 릴리스 거버넌스로 전환——먼저 목록으로 “무엇이 있고, 무엇이 빠졌고, 얼마나 걸려야 머지되는지”를 답할 수 있어야 버전 계획이 가능해진다.

5.2 SM120 라인의 소보폭 빠른 반복과 lowering-only 테스트 전략

요구사항 이슈(#3256) → 패치(#3257) → 강화(#3283/#3284) → 후속(#3286/#3290), 일주일 내 4단계 완료; 또한 회귀 테스트는 명시적으로 sm_120a로 lower하는 방식으로 하드웨어 없는 조건에서 실행. 소비자급/워크스테이션 Blackwell의 블록 스케일링 저정밀 GEMM 커버리지가 체계화되기 시작했으며, 이는 데이터센터 라인(B300/sm_103a의 FP8 가속 실측)과 이중 트랙을 형성.

5.3 어텐션 커널: 다중 경로 병렬에서 단일 계보로

SM90 varlen GQA 프리필 3연속(영속화 개조 포함), 페이지드 디코딩 통일, 레거시 varlen 경로 제거——TileOPs 어텐션 레이어가 한 모니터링 기간 내에 “신설 + 구정리”를 완료; 선형 어텐션(GLA/GDN) 동시 정비, 역방향 경로(MHA backward)는 이미 후속 초안 개설. 200 연산자 계획 중 MLA와 DeepSeek 희소 어텐션 항목과 맞물려, 어텐션 연산자 계보가 “연산자당 하나의 규범 경로”로 수렴하려는 의도가 명확.

5.4 공백과 리스크 포인트

첫째, 국산 백엔드 4개사와 MLIR Ascend는 모니터링 기간 내 제로 활동, Moore Threads는 이미 11일째 침묵, 열기 불균형은 여전; 둘째, TileRT 릴리스 페이지가 릴리스 PR보다 4일 지연, 버전 추적에 여전히 사각지대 존재; 셋째, 메인 저장소 RNG 큐가 4일째 업데이트 없음, 대형 건(TileIR 백엔드 #3247, 비동기 스테이징 #3279)의 느린 심사 구도 지속; 넷째, 메인 저장소 72시간 내 3건 머지(주말 포함), 상대적으로 새로 열린 10건 대비, 큐 소화 능력은 관찰 필요.
