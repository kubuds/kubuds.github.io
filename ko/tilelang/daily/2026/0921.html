날짜: 2026-09-20　출처: tilelang #3254 GLM-5.3 k 풀 Top-K 변환／병합 커밋 eab74a4a／kpool 예제 README

09-20 17:06(베이징 시간) 병합, 압축 방식으로 반영(단일 부모 커밋), 이전 기간에 체인을 이룬 GLM-5.3 k 풀 시리즈를 메인라인으로 진입: 11개 파일, +2520/-4. 병합 내용은 단일 연산자 패치가 아니라 완전한 실행 가능 자산 세트:

  • 예제 스위트 examples/kpool/: README 설명 + 네 가지 예제로, GLM-5.3-Flash 희소 어텐션 인덱서의 전체 흐름에 대응한다——풀 내 softmax 가중 풀링, BF16 왕복 및 정규화 Hadamard-128, 벡터별 FP8 양자화와 FP32 스케일링, 호출자가 보유한 페이지 캐시에 쓰기, 다시 읽어 32헤드 MQA 가중 점수 계산, 512개 풀 선택 및 풀당 네 토큰 확장(토큰 테이블과 불규칙 오프셋 매핑도 지원). 배포된 특화 구성은 pool_size=4, head_dim=128이다. 캐시 계약에는 다음과 같이 명시되어 있다: 프로덕션 vLLM 커널은 FP8 값과 FP32 스케일을 하나의 인터리브된 uint8 할당에 패킹하며, 예제는 두 호출자 텐서로 k_cache와 scale_cache를 표현하고, FP8 형식은 플랫폼에 따라 선택한다(pre-gfx950은 e4m3fnuz, gfx950/CUDA는 e4m3fn).
  • AMD 측 테스트 testing/python/amd/: 네 가지 ROCm 테스트(압축, 디코딩 테일, 페이지드 FP8 MQA logits, Top-K 변환).
  • 언어 계층 소규모 변경: tilelang/language/fp8.py의 determine_fp8_type()과 determine_torch_fp8_type()에 device 매개변수를 추가——FP8 dtype 선택이 고정 장치 0에서 지정 가능한 장치로 변경되었다.

검증: exact-head CI(run 35428061006) Quick Lint, ROCm, CUDA, Metal, CuTeDSL 모두 통과. ROCm 7.2 작업은 MI300X/gfx942에서 2433개 통과, 1852개 건너뜀을 보고했다.

스택 상태: 이 커밋은 자체 설명에서 “스택이 #3253 위에 쌓였고, #3250, #3251, #3253을 각각 머지될 때까지 포함한다”고 밝힌다——이것은 전체 스택의 최상단 커밋이며, 압축 머지가 스택 내용 전체를 main에 반영한다. 모니터링 기간 종료 시점까지 #3250, #3251, #3253, #3255 네 건은 여전히 미머지 상태이고, 09-19 이후 업데이트가 없어 유지보수자가 rebase 또는 종료로 마무리해야 한다.

판독: #3250 개시(09-19 새벽)부터 전체 체인 내용이 main에 진입(09-20 오후)까지 약 34시간이 걸렸다. AMD 측 작업은 이미 “백엔드 사용 가능”과 “새 모델 연산자 필요”에서 “모델 전용 예제 스위트와 테스트 자산 저장소 등록”으로 나아갔다. 앞서 #3165에서 확립한 “예제가 곧 테스트”와 맞물려, 이 경로의 전달 형태는 이미 안정되었다——예제는 문서일 뿐만 아니라 CI가 직접 실행하는 정합성 자산이다.

1.1 메인 저장소: SM120 블록 스케일 GEMM, 레지스터 상주와 홀수 warp 그리드 보완, 요구사항 이슈에서 패치까지 21분(09-21)

날짜: 2026-09-20 ~ 2026-09-21　출처: tilelang #3256 SM120 블록 스케일 GEMM 요구사항 이슈／#3257 SM120 fragment와 홀수 warp 그리드／#2253 SM120 블록 스케일 MMA와 SageAttention3

모니터링 기간 후반(09-21 새벽) 메인 저장소에 “요구사항 이슈에서 패치까지”의 직선이 나타났다: 01:22 요구사항 이슈 #3256 생성(SageAttention3가 저빈도 MMA 매크로를 T.gemm_blockscaled로 교체했으나 두 가지 제약에 막혔다——fragment A와 공유 B의 피연산자 스코프를 지원하지 않음; M=N=K=128, 256 스레드에서 FullRow와 컴팩트 스케일링의 warp별 1x8 MMA 원자 그리드가 거부됨); 01:43 패치 #3257이 즉시 개시, 동일 작성자(sepcnt), 6개 파일 +252/-42: SM120 블록 스케일 GEMM의 fragment A와 행 우선 스케일 fragment 지원, 홀수 warp별 원자 그리드(8x1 파티션 포함)의 컴팩트 스케일링 수정, 그리고 하강 및 정합성 테스트 추가; 같은 시간대에 #2253(SageAttention3 메인라인 대형 PR) 업데이트. 요구사항 이슈에 자체 검증 조건 포함: #3254 머지 후 main eab74a4a에서, torch 2.11.0+cu130, sm_120a 환경 실측.

판독: 21분 간격은 이 라인의 작성자가 문제 경계를 이미 완전히 파악하고 있음을 보여준다. SM120(신세대 소비자 및 워크스테이션 GPU)의 블록 스케일 GEMM은 “사용 가능”에서 “특정 어텐션 커널의 형태 요구사항 충족”으로 나아가고 있으며, 노선은 SageAttention3의 실제 필요에 의해 견인되고 있다.

1.3 TileOPs: 밀집 Gated DeltaNet 프리필 전환 병합, 약 900줄 순삭제 (09-20)

날짜: 2026-09-20　출처: TileOPs #2144 밀집 Gated DeltaNet 프리필 전환

09-20 21:29 병합, 19개 파일, +2102/-3003(순 -901), 작성자 superAngGao, 선형 어텐션 통일화 작업(#2143)의 한 단계: Hopper의 BTHD 밀집 프리필 파이프라인을 통합 연산자 GatedDeltaNetFwdOp에 연결하고, 구현을 gated_deltanet/prefill/로 분할(엔트리, 공용 lowering 및 캐시, 상태 보정, 융합 전방 4계층); 기존 GatedDeltaNetPrefillFwdKernel은 커널 목록에서 직접 제거하고 호환 별칭을 남기지 않음(릴리스 전 정리), 새 이름은 GatedDeltaNetDensePrefillFwdKernel이다.

범위와 검증: 이번 단계에서는 등장, 제로 초기 상태, H==HV, K==V==128인 프리필만 지원한다(디코드, 초기 상태, GVA, 가변 길이 등은 후속으로 남김); H200, SM 클럭 1500 메가헤르츠 고정: Gated DeltaNet 5개 테스트 통과; 6개 목록 벤치마크 케이스와 FLA 항목별 대조 통과, BF16 출력 최대 절대 오차 1.37e-4, FP32 최종 상태 2.31e-3; 엔드투엔드 0.3855밀리초 대 FLA 0.5435(S=4096, 1.41배), 0.5224 대 1.5384(S=32768, 2.94배).

판독: 이는 “이관”을 릴리스 전 정리로 수행한 사례다——구 커널 삭제, ABI 통일, 목록 정리, 그 대가는 decode 등의 기능을 후속 모니터링 기간에 보완해야 한다는 것; 연산자 라이브러리의 인터페이스 수렴은 “먼저 통일, 이후 완성”으로 추진된다.

1.4 TileOPs: roofline 목록 자체 점검——175개 연산자 중 88개의 선언된 공식이 실행된 적 없음 (09-20/09-21)

날짜: 2026-09-20 ~ 2026-09-21　출처: TileOPs #2158 목록 공식과 실제 실행 공식을 일치시키고 재집계

09-20 07:29 새로 열림, 09-21 06:55 여전히 업데이트 중(57개 파일, +2965/-980, 20개 커밋, 병합되지 않음). 이 항목은 “측정 신뢰성” 거버넌스를 공식 계층으로 끌어올린다: roofline 필드는 마땅히 공식의 단일 출처여야 하고, eval_roofline()은 그 유일한 평가 면이어야 한다——당시 둘 다 성립하지 않았다. 점검 결과: 175개 구현된 연산자 중 코드 생성이 서비스하는 것은 77개, 나머지 98개는 작성자가 손으로 작성한 메서드를 갖고 있으며, 그중 88개의 목록 내 공식은 한 번도 실행된 적이 없다; 16개의 인라인 항목은 아예 평가가 불가능하다(변수 계층에서 한 번도 바인딩된 적 없는 이름을 참조); 구조 오라클은 14개 연산자만 검사했고, 나머지 161개는 이유 없이 “PENDING”으로 나열되었다.

한 커뮤니티 프로젝트가 모니터링 기간 내 두 번 커밋했다: SOPHGO 가속기를 위한 TileLang의 TPU 백엔드 확장(target="tpu", pcie와 cmodel 두 가지 모드, ppl_* 계열 DSL 내장, JIT 전 과정)으로, Mamba2 관련 ChunkScan 청크 스캔 연산자를 BM1690에 이식하는 중이다—두 커밋은 각각 cmodel 파이프라인과 BM1690 PCIe 하드웨어 검증이다. 프로젝트 스타 수는 적고 초기 탐색 단계이나, 방향은 기록할 가치가 있다: TileLang의 서드파티 백엔드가 더 많은 중국산 칩 라인으로 확장되고 있다.

4. 커뮤니티, 튜토리얼과 활동

4.1 문서 사이트: 메인 저장소와 TileOPs 문서 사이트 각각 자동 배포 1회 (09-20)

날짜: 2026-09-20　출처: 메인 저장소 문서 사이트／TileOPs 문서 사이트

메인 저장소 문서 사이트 17:10 “Update docs” 자동 커밋 1회; TileOPs 문서 사이트 07:58 gh-pages 브랜치 배포 1회. 모두 파이프라인 자동 동작이며 사이트 콘텐츠에는 실질적 변화가 보이지 않았다.

4.2 미디어와 학술 측: 모니터링 기간 내 신규 제로 (09-21)

날짜: 2026-09-21　출처: Google News RSS (여러 중영문 쿼리, 프록시 경유)／Hacker News／arXiv

Google News 한국어·중국어 다중 쿼리(TileLang, tile-ai, 연산자, 중국산 칩 조합 등) 모니터링 기간 내 0건 적중; Hacker News 최근 5일간 주제 관련 항목 없음; arXiv 주제 검색 최신 1편은 여전히 07-24의 TileSight 성능 모델 논문이며, 모니터링 기간 내 신규 프리프린트 없음.

4.3 릴리스 리듬: 메인 저장소 v0.1.14 릴리스 19일 경과, 각 적응 저장소 태그 변동 없음 (09-02)

날짜: 2026-09-02(최근 릴리스)　출처: tilelang v0.1.14

메인 저장소 최신 릴리스는 여전히 09-02의 v0.1.14(19일 경과); 적응 저장소는 모니터링 기간 내 신규 태그 없음: Ascend v0.1.2.000(09-09), MLIR Ascend v0.1.2.020(06-11), Moore Threads v0.1.14+musa.1(09-11).

5. 트렌드 관찰

5.1 ROCm 라인: 스택형 전달이 수렴하기 시작 — 한 번의 압축 머지로 전체 예제가 메인라인에 진입

#3250부터 #3254까지의 스택이 지난 모니터링 기간에 체인을 이루고, 이번 모니터링 기간에 최상단 커밋 한 번으로 메인라인에 들어갔다. 스택형 PR의 효율이 여기서 드러난다: 리뷰는 체인을 보고, 랜딩도 체인 전체를 본다. 남은 문제는 체인 위 나머지 네 건의 마무리다 — 내용은 이미 main에 있으므로 rebase하거나 닫아야 하며, 그렇지 않으면 큐에 네 개의 「이름과 실체가 다른」 열린 이슈가 남는다.

5.2 NVIDIA 라인: SM120이 시간 단위 대응 리듬에 진입

요구 이슈 #3256(01:22)에서 패치 #3257(01:43)까지 간격 21분, 동일 작성자이며, 구체적인 다운스트림 프로젝트(SageAttention3)의 병목을 중심으로 진행되었다. 이러한 「다운스트림 요구에서 당일 밤 패치까지」의 리듬은 SM120 블록 스케일링 GEMM에 이미 명확한 담당자와 검증 기준선(머지 후 main 헤드, sm_120a, torch 2.11)이 있음을 보여준다.

5.3 TileOPs의 신뢰 엔지니어링: 수치, 판정 기준에서 공식 자체까지

3일간 네 건(#2155 의미론, #1996 물리, #2154 출처 추적, #2158 공식)을 거치면서, 메트릭 거버넌스는 「읽어낸 수치」와 「기록된 공식」을 모두 다시 훑었다. 출발점은 겨우 8줄의 대역폭 이상이었지만, 거버넌스 반경은 175개 연산자의 공식 자산으로 확대되었다 — 교훈은 동일하다: 지표의 신뢰도는 「그럴듯해 보이는 것」에서 오지 않고, 「실행되는 것과 선언된 것이 동일한 것」에서 온다.

5.4 Ascend의 대량 머지일: 이익 외에도 검증 꼬리가 남는다

하루 11건, 최대 1건이 72개 파일과 1만 행 추가 이후, 정기 작업 실패와 두 건의 후속 PR이 반나절 만에 연이어 나타났다 — 이는 이상이 아니라 대량 머지의 내재적 비용이다(엄격화 변경은 기존 커널과 테스트 전제에 영향을 준다). 관찰 포인트: 후속 PR 머지 후 정기 회귀가 완전 녹색을 회복하는지, 테스트 케이스 수가 1936에서 상향되는지.

5.5 공백과 리스크 포인트

세 가지: 첫째, 메인 저장소 릴리스 정체가 19일째이며, 리뷰 큐의 주간 초과 항목(#3109, #3230, #2253 등)이 계속 누적되고 있다; 둘째, k 풀 스택 내용이 이미 main에 있지만 네 건의 열린 이슈가 마무리되지 않아 중복 유지보수 리스크가 존재한다; 셋째, Ascend 정기 회귀가 대량 머지 후 실패했고 후속 수정이 아직 머지되지 않았다 — 「매일 완전 녹색」 신호를 주시하는 다운스트림 사용자에게 이날은 적색으로 간주해야 한다.
