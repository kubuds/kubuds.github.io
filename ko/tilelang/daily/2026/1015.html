1. 핵심 프로젝트 진행 상황

1.1 메인 저장소: Ascend 측 네 곳 마무리——독립 AIV 실행 (#3485), PTO DeepGEMM codegen (#3330), 크로스 warp allreduce 수정 (#3494), 예제 대상 선택 (#3474) (10-14)

날짜: 2026-10-14　출처: 독립 AIV (#3485)／ PTO codegen (#3330)／ allreduce 수정 (#3494)／ 예제 대상 선택 (#3474)

  • 독립 AIV 실행(#3485): Ascend AutoSchedule를 확장하여 AIV0와 AIV1이 sid 의존성 기반 제어 흐름에서 서로 다른 작업을 수행할 수 있도록 함——교대 에필로그, 역양자화와 에필로그 분업, 서로소 입력 파티션, 루프 내 역할 전환을 지원한다. 구현상 AssignCore를 지연 추정 및 스케줄링 이전으로 앞당기고, AIV 로컬 UB 버퍼와 스칼라 상태에 독립적 정체성을 부여하며, 참여 코어별로 파이프라인 리소스, 특수 레지스터 의존성, UB 용량, 동기화 플래그 라이브러리를 모델링한다. 통합 커널의 collective 경로와 1/2 AIV 발사 지오메트리는 유지된다. L0C→UB 복사는 여전히 AIC에서 실행된다.
  • PTO DeepGEMM codegen(#3330): 제어 흐름 전반에 걸쳐 tl.ascend_set_mmad_direction을 추적하고 적용된 방향을 MAD 명령에 인코딩하며, 충돌 방향에서 도달 가능한 MAD를 거부한다. SIMD 후 증분 로딩(데이터와 갱신 포인터를 동시에 반환), 혼합 AIC/AIV 커널에서 UB 주소의 PTODSL 포인터 변환, 동적 L0C→UB 차원 및 스트라이드, int16 부호 있는 패킹 MX scale을 지원한다. 조건 표현식과 런타임 루프의 코드 생성을 개선했다. 15개 DeepGEMM PTO 케이스 중 14개가 통과했으며, test_bf16_m_grouped_padding은 PTOAS VPTO 백엔드가 FP32→BF16 변환을 합법화하지 못해 여전히 차단된 것으로 보고되었다.
  • 크로스 warp allreduce 수정(#3494): 하나의 cross-warp allreduce 호출이 여러 독립 리덕션 그룹을 커버할 때 ascend와 pto 타깃이 첫 번째 그룹 결과를 모든 그룹에 잘못 전달하던 문제를 수정한다(#3469 후속).
  • 예제 타깃 선택(#3474): Ascend 예제와 테스트에서 하드코딩된 target="ascend"를 제거하고 TILELANG_DEFAULT_TARGET 환경 변수로 결정하도록 변경했다. DeepGEMM JIT 진입점은 execution_backend="auto"를 지원한다. CI는 Ascend 예제 스위트를 ascend와 pto 두 타깃으로 각각 한 번씩 실행하며, 문서에 선택 방식을 명시했다.

1.2 메인 저장소: 인프라 3건——CPU OpenMP 병렬 grid 루프(#3109), C 계열 codegen 공유 발사(#3289), Windows NVCC의 MSVC 전환(#3510) (10-14)

날짜: 2026-10-14　출처: CPU OpenMP(#3109) / codegen 공유(#3289) / Windows MSVC(#3510)

  • CPU OpenMP 병렬(#3109): CPU 백엔드에 선택적 grid 루프 OpenMP 병렬을 추가——새로운 MaterializeCPUParallelGrid가 어노테이션된 CPU grid 루프를 병렬 루프로 변환하며, 루프 collapse, 스레드 수 설정, 최소 trip 수 임계값, 할당 하향을 함께 제공한다. Linux / macOS / Windows의 OpenMP 컴파일 플래그와 pass 설정 항목을 보완했다. 테스트는 정확성, pragma, 할당 하향, 임계값, 단일 차원 상황을 커버한다. CPU 백엔드가 처음으로 grid 수준 병렬 기능을 갖추게 되었다.
  • C 계열 codegen 공유(#3289): CodeGenTileLangCBase를 도입하여 CUDA, HIP, CPU C, Ascend C++, Metal, C 호스트 코드 생성을 통합했다. T.import_source, T.Kernel(prelude=...), pragma_import_c가 소스 텍스트가 끝에 개행 없이 끝나거나 백슬래시로 끝날 때 다음 생성 줄을 삼키는 문제를 수정했다. 가져온 내용을 「헤더→임포트→생성 선언 및 함수」 순으로 정렬하고 두 개의 구분 개행을 보장한다. 검증: 집중 회귀 83건 통과, 관련 codegen 및 launch 스위트 405건 통과.
  • Windows NVCC의 MSVC 전환(#3510): NVCC가 get_cplus_compiler()가 선택한 clang-cl을 거부——NVCC 하위 프로세스 환경에서 cl.exe를 선택하도록 변경(호스트 C++ 컴파일러 선택은 변경하지 않음), VS 2026 18/* 폴백 경로 추가, 비 Windows 플랫폼에서 더 이상 -ccbin=None을 전달하지 않음. CUDA 13.3에서 재현 케이스가 수정 전 실패, 수정 후 컴파일 통과.

1.3 메인 저장소: ROCm scan 웨이브프론트 수정(#2326), 테스트 인프라 캐시(#3502), 거버넌스 설정(#3513) (10-14)

날짜: 2026-10-14　출처: ROCm scan (#2326)／ 테스트 인프라 (#3502)／ CodeRabbit 레이블 (#3513)

  • ROCm scan 웨이브프런트 수정 (#2326): HIP의 cumsum / cummax는 기본적으로 64 lane 세그먼트로 실행되어 Wave32 GPU에서 결과가 잘못됨——기존 run 진입점이 대상 웨이브프런트 너비에 따라 세그먼트 너비를 선택하도록 하고(블록 스레드 수 상한에 제약됨), 32 스레드 블록은 컴파일 시점에 64 lane 템플릿을 제외하며, 32 스레드 전방/역방향 스캔과 소스/대상 스트라이드가 다른 경우에 대한 커버리지를 보강하고, gfx950 MXFP4 예제와 테스트를 {"kind": "hip", "mcpu": "gfx950"} 대상 표기법으로 변경. 검증: CUDA scan 스위트는 B300에서 17개 통과, CuTeDSL 소스 생성 테스트 2개 통과; AMD 측 런타임 검증은 ROCm CI에 위임.
  • 테스트 인프라 캐시 (#3502): 최근 조회된 IR 본문의 호출 데이터를 캐시하여 collect_calls / assert_call_count에 제공; 변환 테스트의 재귀 visitor와 생성 스크립트 텍스트 검사를 구조화된 IR 어서션으로 교체하고, 소프트웨어 파이프라이닝, 스케줄링, 동기화, 배리어 및 Hopper intrinsic의 구조 검사를 확장.
  • 거버넌스 구성 (#3513): PR과 issue에 대한 CodeRabbit 자동 레이블 활성화(PR 13개 레이블, issue 14개), 11개 리뷰 라우팅 규칙 전부 유지, 레이블 추가/이름 변경/삭제 없음.

5.2 메인 저장소의 “인프라 데이”: 컴파일 면 재구성과 플랫폼 확장

  • 단일 모니터링 기간 10건 병합 중 절반 이상이 컴파일 및 플랫폼 인프라: C 계열 codegen 공유(CUDA / HIP / CPU / Ascend / Metal 통합 베이스 클래스), CPU OpenMP 그리드 병렬, Windows MSVC 툴체인, 테스트 인프라 캐시, ROCm scan 웨이브프론트——여기에 PTO/Ascend 신규 4건 추가. 릴리스 정적기(v0.1.15 이후 15일간 신규 버전 없음)에 화력이 뚜렷하게 저수준 확장성과 신규 플랫폼 지원으로 향하고 있으며, 이는 “MoE/성능 병합 → 기반 성장 → 신규 버전”의 리듬과 표리 관계.

5.3 야간 기준선 +41: 테스트가 머지와 함께 동반 확장

  • 정확성 일일 +41건은 최근 일주일 중 최대 증가폭이며, TileOPs 16건 머지와 일대일로 대응한다(성능 배치는 일반적으로 test-node 증항을 동반하고, 어텐션 확장은 신규 부하 행을 동반한다). 「한 건 머지할 때마다 기준선이 한 칸 올라간다」는 롤링 집계는 각 변경의 검증을 야간 스냅샷에 계속 축적해 왔다——릴리스 전 정적 준비는 여전히 꾸준히 누적되고 있다.

5.4 Ascend 저장소의 롤백 규율: 저우선순위 케이스도 지킨다

  • 앞선 세 건의 「문서 사실 검증」 PR이 저우선순위 예상 실패 케이스의 이상 정규식 불일치로 인해 전체 롤백되고, 이후 삭제 버전으로 재작업되었다——이는 「PR 단계 CI는 저우선순위 케이스를 실행하지 않고, 매일 전체 스위트가 이를 보완한다」는 2단계 검증 구조를 드러낸다. 이러한 「롤백—재작업」이지 「부상 상태로 전진」이 아닌 처리 방식은 Ascend 적응 저장소의 CI 거버넌스가 「전부 통과」에서 「단언 정밀화, 기준 통일」로 전환되고 있음을 보여주며, 이는 모니터링 기간 내 머지 품질이 매일 전체 실행의 지속적 제약을 받는다는 것을 의미한다.
