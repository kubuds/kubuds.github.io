오늘의 핵심

오늘의 병합량은 어제의 24건에서 12건으로 줄었으나 구조는 더 집중되었다: Ascend 전용 저장소가 5건, 메인 저장소가 5건, TileFoundry와 TileOPs가 각각 1건을 차지했다. Ascend 저장소의 이번 배치는 전부 알고리즘 측 연산자이며, 모두 업스트림 모델에 직접 사용할 수 있는 부류다. GLM-5.3-Flash 희소 어텐션 indexer의 kpool 압축 연산자는 차원별 softmax 풀링, BF16 경계, 정규화 Hadamard-128 회전과 E4M3 양자화를 하나의 순수 Vector kernel에 압축했으며, 각 블록이 64개의 pool을 커버하고 두 개의 벡터 서브코어가 각각 32개를 담당하며, 호스트 측 재배열이 전혀 없이 호출자의 3차원 레이아웃에 따라 스트라이드 복사를 수행한다; E4M3 인코딩은 순수 정수 비트 연산으로 구현되었으며(round-half-even, 서브노멀 포함, 448로 포화), FP8 타입에 의존하지 않고 근사도 하지 않는다. Chunk Scaled Dot KKT는 블록 게이트 선형 어텐션 포워드 내의 A = gate(K K^T)로, 정적 4블록 전개, GM 워크스페이스 제로, 호스트 연산자 제로이며, L0와 L1 세 가지 사례의 일치율은 모두 1.0이다.

메인 저장소의 오늘 주제는 컴파일과 발사 계층이다. 전체 warp 리덕션은 redux.sync로 전환되었다: 메인 브랜치의 네 개 독립 32레인 FP32 최댓값이 CUDA 13.1, sm_103a에서 20개의 shuffle로 전개되었으나, 변경 후에는 네 개의 redux.sync.max.f32가 되었고 shuffle은 포함되지 않는다; 정수 리덕션은 SM80 이상에서 하드웨어 리덕션을 사용하며, FP32의 최댓값/최솟값은 sm_100a, sm_100f, sm_103a, sm_103f에서만 사용 가능하고, 좁은 타입(CUTLASS의 FP16, BF16 포함)은 FP32로 승격되며, FP64는 여전히 shuffle 경로를 유지한다. 저자는 엔드투엔드 가속을 주장하지 않으며 명령어 수준 대조만 제시했다. autotuner의 동시 컴파일은 전체 구간에서 보유하던 컴파일 락을 분리했다: 각 커버리지 구성은 dataclasses로 독립적인 JITImpl을 복제하며, 1단계 키를 공유하는 후보만 직렬화되고, 디버그 출력의 디스크 쓰기는 여전히 직렬화된다. 저자가 제시한 크로스 백엔드 검증은 Ascend 1797건, ROCm 3220건, Metal 95건, CUDA 5500건이다.

기록할 만한 또 다른 세부 사항이 있다: 오늘 새로 열린 역방향 인덱스 오컴파일 결함(#3705)은 T-HEAD 명의의 tilelang 브랜치 저장소에서 런타임 재현되었으며, 이는 이미 조직 차원의 팀이 이 업스트림 코드를 자사 하드웨어 스택의 기반으로 삼아 추적하고 있음을 보여주며, 단순한 외부 의존성이 아님을 나타낸다.

1.1 메인 저장소: 전체 warp 리덕션이 redux.sync로 전환, 네 개 32레인 FP32 최댓값이 20개 shuffle에서 4개 하드웨어 리덕션으로 (#3692)

10-29 15:08에 병합, 4개 파일 +337/-35. 이전의 일반적인 스레드 간 리덕션(예: T.reduce_max)은 그룹 전체가 정렬된 풀 warp여도 shuffle 트리로 전개되었다: 메인 브랜치 837486a에서 네 개의 독립 32레인 FP32 최댓값이 sm_103a + CUDA 13.1 컴파일 시 20개 shuffle, 0개 redux로 생성되었으나, 변경 후에는 네 개 redux.sync.max.f32, 0개 shuffle이 되었다. 방식은 스칼라 및 배치 전체 리덕션에 이미 존재하는 warp_reduce 헬퍼를 재사용하는 것이다: 호출자는 스레드 지오메트리(warp 정렬 여부, 단위 스트라이드, 풀 warp)만 판단하고, 아키텍처, 데이터 타입과 연산자 디스패치는 헬퍼에 위임한다. 정수 리덕션은 SM80 이상에서 하드웨어 redux를 사용하며, 더 작은 정수는 32비트로 승격된다; FP32의 최댓값/최솟값은 sm_100a, sm_100f와 sm_103a, sm_103f에서만 사용 가능하다; 좁은 부동소수점은 FP32로 승격된 후 헬퍼에 진입하며, FP64는 정밀도를 낮추지 않고 여전히 shuffle 경로를 사용한다. 서브 warp, 스트라이드, 패킹 리덕션 및 지원되지 않는 연산자와 타깃은 모두 shuffle로 폴백되며, 크로스 warp 공유 메모리 교환과 배리어는 변경되지 않는다. 부수적으로 컴파일 실패 한 건도 수정되었다: 사용자 정의 부호 없는 정수 reducer가 인라인 디스패치가 빈 타입을 반환하여 컴파일되지 않던 문제가 이제 shuffle 폴백으로 처리된다. PTX 회귀는 실제 명령어와 shuffle 부재를 단언하며, 런타임은 부호 있는/없는 경계값, 배치 미초기화, NVRTC 실행, 비유한값, 부호 있는 0과 FP64 정확한 결과를 커버한다. 저자는 엔드투엔드 가속을 명시적으로 주장하지 않는다. 기존의 유산 문제 하나도 설명에 명시되었다: 배치 리덕션에서 batch=4, 스레드당 2개 출력, batch=8, 스레드당 4개 출력 시 FP16과 BF16 실패가 존재하며, 메인 브랜치 원본 템플릿에서도 동일하게 재현되고, 실패는 하강 단계에서 발생하여 본 커밋과 무관하다.

5. 트렌드 관찰

Ascend 측의 리듬은 이미 「백엔드 이식」에서 「연산자 보충」으로 넘어갔다. 어제 기록한 것은 NPUIR 백엔드가 메인 브랜치에 병합된 것과, 검수 기준이 504개 자체 테스트 및 71 대 72의 예제였다. 오늘 병합된 다섯 건 중 네 건은 연산자와 예제이며, 업스트림 모델의 요구에 따라 배치되었다: GLM-5.3의 인덱서 압축, 블록 게이팅 어텐션의 내적, 4비트 양자화 행렬 곱, 양자화 비전 모델의 심층 합성곱. 이 연산자들의 공통점은 양자화와 융합을 호스트 측에 맡기지 않고 kernel 본체에 직접 기록했다는 것이다(E4M3 순수 정수 인코딩, 4비트 패킹 규약, 이중 kernel + 1승 1 패스트 패스). 동시에 두 건은 부수적으로 엔지니어링 기준을 세웠다: 연산자 성능 프로파일링을 프로세스에 포함시키고, 동시 배치로 인한 불안정 테스트 케이스를 목록화된 테스트 채널로 전환했다. 이는 Ascend 측의 주요 모순이 「컴파일이 가능한가」에서 「연산자의 수치와 성능이 안정적으로 검수될 수 있는가」로 변하고 있음을 보여준다.

메인 저장소의 오늘 세 건(하드웨어 리덕션, 동시 컴파일, 경계 초과 복사 그룹화)은 각각 명령어 선택, 컴파일 지연, 발사 품질에 대응하며, 모두 컴파일러 커널 문제이지 언어 계층 기능이 아니다. 이는 어제의 신규 결함 방향과 일치한다: 경계 초과, 별칭, 비트 폭 같은 정적 검사의 경계가 하나씩 열리고 있다. 오늘 세 건의 신규 결함 중 두 건(패딩 버퍼가 있는 배치 복사, 뷰 비트 폭 오버플로)이 실제 모델 형상에서 트리거되었으며, 이는 TileLang의 사용 범위가 경계 조건에 부딪힐 정도의 규모로 깊어졌음을 의미한다: 248320 x 5120의 NVFP4 가중치, K가 16의 정수 배가 아닌 어텐션 헤드 차원.

생태계 측에서 오늘 가장 주목할 점은 「fork화」다. Ascend 커뮤니티에 독립 연산자 저장소가 등장했고, T-HEAD 명의로 PPU 브랜치가 있는 TileLang 브랜치 저장소가 있으며, PTO-ISA는 문제 은행과 벤치마크를 모두配套 저장소로 만들었고, 별도의 개발 도구 저장소는 다운스트림 추적을 독립 패키지로 배포했다. 이러한 움직임의 공통 전제는 TileLang을 자사 하드웨어 스택의 기반으로 취급한다는 것이다: 자사 명령어 집합에 맞춰 레이아웃을 변경하고, 자사 테스트 체계로 검수하며, 자사 지식 형태로 경험을 축적해야 한다. 도메인 특화 언어에게 이는 스타 수보다 더 강한 채택 신호이지만, 업스트림이 「브랜치와 업스트림의 동기화」라는 장기 비용에 직면해야 함을 의미하기도 한다: 오늘 #3705 결함은 브랜치 사용자가 실제 빌드에서 먼저 부딪힌 것이다.
