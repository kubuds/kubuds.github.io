1. 핵심 프로젝트 진행 상황

1.1 메인 저장소: partial-sync 이름 있는 배리어 id가 두 저장 영역 간에 중복(#3643)

10-25 14:30 머지, 2개 파일 +57/-1, #3642 수정. ThreadSync가 shared와 shared.dyn에 대해 각각 한 번씩 실행되는데, 매번 새로운 재작성기를 생성하고 각자 kFirstUsedBarrier부터 번호를 다시 매긴다. 두 번째 실행은 첫 번째 실행이 이미 재작성한 동기화를 건너뛰지만 해당 id가 이미 점유되었음을 알지 못하므로, 동일한 bar.sync id, count를 서로 겹치지 않는 두 스레드 그룹에 할당한다. 수정 방법은 번호 매기기를 두 번의 실행에 걸쳐 연속되게 하고, 영역 간 재사용에 대한 단언을 추가하는 것이다. 이러한 결함은 컴파일 시 오류를 보고하지 않고 대형 kernel에서만 간헐적으로 발생한다.

출처: https://github.com/tile-ai/tilelang/pull/3643

1.2 메인 저장소: clamp의 NaN 전파 하강 롤백, T.clamp가 min/max로 복귀(#3628)

10-23 16:51 머지. #3205 전체 체인을 롤백: tl.clamp 내장 삭제, 각 백엔드 하강 등록, codegen 분기 및 디바이스 측 보조 함수(Ascend 등록 포함)를 삭제하고, T.clamp(x, lo, hi)는 T.min(T.max(x, lo), hi)로 복원되었다. 이유는 추가적인 NaN 처리가 min/max의 간소화와 벡터화를 가로막기 때문이다. NaN 요구는 사라지지 않아 같은 날 별도로 #3605를 열어 T.clamp_symmetric으로 CUDA SM86+에서 단독 구현했으며, 역할 분담은 “T.clamp는 범용성 유지, 새 인터페이스는 시맨틱 유지”이다.

출처: https://github.com/tile-ai/tilelang/pull/3628

1.3 메인 저장소: int64 원자적 max/min 및 AtomicStore의 int64, bf16, fp16 크래시(#3307)

10-23 18:44에 병합됨. normalize_atomic_type은 #1716부터 int64_t를 unsigned long long으로 정규화하여 atomic add를 지원했는데, 그 결과 Atomic의 max/min 및 참조 형식이 int64에서 바로 크래시가 발생했고, AtomicStore도 동일하게 영향을 받았으며 추가로 bf16과 fp16에도 파급되었다. 수정은 연산별로 int64에 대해 별도 타입을 선택하고, AtomicStore는 독립적인 타입 분기를 사용하도록 했다. 이는 “하나의 연산을 위해 공용 정규화를 변경하여 나머지 연산까지 연쇄적으로 깨뜨린” 전형적인 회귀에 해당한다.

출처: https://github.com/tile-ai/tilelang/pull/3307

1.4 메인 저장소: VectorizeLoop가 더 이상 루프 스텝을 조용히 무시하지 않음 (#3345)

10-23 19:02에 병합됨, #3301에서 추적하는 F319에 해당. 벡터화기는 (loop_var, extent, body)만 받고 스텝은 전혀 전달되지 않았다: T.vectorized(0, 8, step=2)(반복 집합 0/2/4/6)가 전체 [0, 8)을 커버하는 연속 접근으로 하강되었다. 수정은 벡터화 진입 전에 비단위 스텝을 거부하고 진단을 제공한다. 이 하위 항목들의 공통된 특징은 프런트엔드가 하강 불가능한 표기를 받아들이고 백엔드가 다른 프로그램의 기계어를 내놓는다는 점이다.

출처: https://github.com/tile-ai/tilelang/pull/3345

1.5 메인 저장소: NVRTC가 디스크 캐시에 히트한 후 자동 튜닝 결과를 다시 쓰지 못함 (#3193)

10-23 15:04에 병합됨. NVRTC가 디스크에서 kernel을 로드할 때 adapter.libpath를 설정하지 않는데, 튜닝이 설정을 선택한 후에는 해당 필드로 캐시 kernel을 저장해야 하므로 히트할 때마다 AttributeError가 발생하고 결론이 버려져 사용자는 “매번 시작할 때마다 재조정 중”이라고 보게 된다. 수정은 캐시 로드 경로에서 libpath를 복원하여 새 컴파일 경로와 일치시키고, 캐시 재로드 및 부정 대조 테스트 케이스를 보강했다.

출처: https://github.com/tile-ai/tilelang/pull/3193

1.6 심사 중: 독립 패키징된 TIRx로 내장 TVM 교체, 1043개 파일 변경 (#3666)

10-25 19:16에 제출됨, 1043개 파일 +71428/-104176. 3rdparty/tvm 및 submodule 항목을 삭제하고(CUTLASS와 HIP 헤더는 유지), 프런트엔드, 네이티브 텐서 및 스코프 IR, 하강 pass, 백엔드 파이프라인, 실행 어댑터를 전체적으로 독립 빌드로 배포되는 tvm_tirx로 이전했으며, 호환 계층은 TileLang 내부로 한정하고 전역 tvm 별칭을 두지 않으며 두 번째 TIRx를 유지하지 않는다. 이는 지난 몇 기간의 “tvm fork 선행, 메인 저장소 후속”을 종착점까지 밀어붙인 것으로: 기반이 vendored 소스에서 외부 의존성으로 전환되어 이후 독립적으로 릴리스 및 롤백이 가능하며, 병합 영향 범위는 전체 저장소를 포괄한다.

5. 트렌드 관찰

릴리스 엔지니어링이 주된 전장이 되었다. 78건의 머지 중 TileOPs가 51건을 차지하며, 그중 십여 건은 이름 변경, 패키징, 의미 통일, 문서 및 CI 게이트에 해당—성능도 새 연산자도 아니라 인터페이스를 동결하는 작업임. 추적 티켓 7할, CHANGELOG에 0.1.0 확정 및 10-26 표기, 이후 0.x의 호환성 약속이 발효되기 시작; 같은 시기 TileFoundry는 core/nvidia/apple 3개 패키지로 구성, Sunrise는 0.1.15 배포판 머지, 세 라인이 같은 주에 같은 일을 함: “돌아가는” 것을 “출시 가능한” 것으로 바꾸는 것.

정확성의 중심이 형상 검증에서 새 하드웨어와 새 스케줄링으로 이동. 지난주 메인 저장소 머지는 대부분 형상과 기하 검증이었으나, 이번 모니터링 기간에는 수명 주기와 배리어로 바뀜: 크로스 스토리지 도메인 배리어 중복 번호, sm_100 텐서 메모리 해제 시 CTA 배리어 누락, warp 특화가 선행문을 잘못 옮김, setmaxnreg가 ptxas 실패를 유발. 공통점은 컴파일은 통과하지만 결과가 간헐적으로 틀리며, 모두 자동 warp 특화와 신규 아키텍처 스토리지에 속함—스케줄링 권한을 컴파일러에 넘긴 뒤 반드시 치러야 할 비용.

Ascend 라인이 동작 확인에서 모델별 연산자 전개 및 일일 회귀로 진화. situ_glu는 Kimi K3 Stable LatentMoE 게이트 활성화에 정렬, 심사 중인 sparse_mla_fwd와 GLM-5.3 kpool 역시 특정 모델 구조의 부품. 일일 전체 2903항목 전부 통과 후 다음 날 다시 실패 보고, 이는 테스트 케이스 규모가 이미 게이트로 삼기에 충분함을 의미; CI 이미지가 cann9.3.0 주간 업데이트 버전을 추종하는 것과 맞물려, 이 라인의 결론 유효 기간은 주 단위로 계산됨.

실행 백엔드는 감산, 백엔드 목록은 증산. CPU는 TVM-FFI로 통일, PTO는 기본 tvm_ffi, CuTeDSL 수정과 NVRTC 컴파일 추가, 방향은 일관되게 실행 경로 분기 감소. 백엔드 목록은 역방향으로 확장——Intel AMX는 CPU 경로로 편입, ROCm은 FP4와 E8M0 보강, Hygon은 레지스터 파이프라인 재제안. 배포 형태는 「한 세트 코드 다중 백엔드 분기」에서 「한 세트 IR, 다중 패키징」으로 전환 중이며, #3666에서 TVM을 외부 의존성으로 전환한 것과 같은 방향이다.
