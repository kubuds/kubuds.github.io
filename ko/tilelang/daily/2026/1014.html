오늘의 핵심: MoE 이중 연산자 확정과 foundry 성능 배치——TileOPs 하루 18건 병합, 야간 기반 +22항목 (10-13 ~ 10-14)

날짜: 2026-10-13, 2026-10-14　출처: masked FP8 그룹 GEMM (#2521)／ DeepSeek 그룹 top-k (#2535)／ DeepSeek mHC 커널 (#3156)／ Qwen3.8-27B 프리필 예제 (#229)／ 야간 스냅샷 (a79a21e4)

모니터링 기간 24시간 내 조직은 28건을 병합했고(메인 저장소 4, TileOPs 18, Ascend 적응 저장소 3, MLIR Ascend 1, TileFoundry 2), 42건을 새로 열었으며, 10개 저장소에 푸시가 있었다. 이번 모니터링 기간의 주요 흐름은 두 가지다: TileOPs의 MoE 연산자 이중 확정과 foundry 성능 배치의 병합 러시.

  • MoE 이중 연산자 확정: masked FP8 그룹 GEMM(#2521)과 DeepSeek 그룹 top-k 라우팅(#2535)이 같은 날 병합됐다——전자는 deep_gemm masked 시맨틱에 정렬하고 14행 부하를 등록했으며, 후자는 vLLM grouped_topk 시맨틱에 정렬하고 T=512에서의 SM 스케줄링 문제를 수정했다(상세는 3.1).
  • TileOPs 하루 18건 병합: MoE 이중 연산자 외에 SM89 역방향/프리필 네 건(#2546~#2549), foundry 성능 배치 8건과 GQA 수정 건(#2550)이 같은 날 마무리됐다(상세는 3.2, 3.3).
  • 메인 저장소 ROCm 두 건: DeepSeek mHC(매니폴드 제약 초연결) 전/후처리 커널(#3156)과 safe-gated KDA 디코딩 예제(#3249)가 병합됐다——ROCm 라인은 연속 세 번째 날 마무리됐다(상세는 1.1).
  • TileFoundry 마일스톤: Qwen3.8-27B 프리필 예제(#229)가 병합됐으며, 이 저장소에서 처음으로 1024 / 4096 / 8192 전체 길이에서 SGLang을 앞선 예제다(상세는 3.4).
  • 야간 기반 지속 상승: 새 스냅샷 a79a21e4——정확성 1064항목(+22), 벤치마크 1966항목(+19), 실패 제로(상세는 3.5).

1. 핵심 프로젝트 진행

1.1 메인 저장소: ROCm 두 건——DeepSeek mHC 전/후 커널과 safe-gated KDA 디코딩 예제 (10-13 ~ 10-14)

날짜: 2026-10-13, 2026-10-14　출처: DeepSeek mHC (#3156)／ KDA 디코딩 예제 (#3249)

  • DeepSeek mHC 전/후 커널(#3156, 2개 파일, +83/-6, 10-14 새벽 병합): mHC 전처리는 CUDA에서 96 스레드 블록 내 32 스레드 경계로 역할을 분담하고 TF32 GEMM 입력을 채택한다. CDNA에서는 이것이 네이티브 64 lane 웨이브프론트를 분할하며, TF32는 MFMA의 입력 타입이 아니다. HIP 경로는 전체 목표 크기 웨이브프론트에서 분할 역할을 실행하도록 변경하고, FP32 혼합 가중치를 공유 메모리에서 BF16으로 변환해 MFMA 계산에 제공한다. CUDA 측은 기존 96 스레드 / TF32 레이아웃을 그대로 유지하며, 추가로 gfx942의 전/후 커널 정확성 커버리지(32 token 전처리, 8 token 후처리 등 케이스)를 보강했다.
  • safe-gated KDA 디코딩(#3249, +360/-0): 패킹 디코딩 커널을 신규 추가——컨볼루션 후 패킹된 QKV와 원시 게이트 입력(a, b, A_log, dt_bias), FP32 상태 풀과 요청별 상태 인덱스를 소비한다. Q/K L2 정규화와 delta-rule 재귀 업데이트를 수행하고, 지정된 상태 슬롯을 제자리에서 덮어쓰며 [batch, 1, value_heads, value_dim]을 출력한다. 음수 상태 인덱스는 0을 출력하고 상태 풀을 변경하지 않는다. 구현은 차원별로 파라미터화되어 있으며 모델명/아키텍처 디스패치를 포함하지 않고, 문서는 GLM-5.3-Flash TP8의 전용화 설정을 제시한다.

1.2 메인 저장소: Ascend 컴파일 면 두 건——SimdVF 멀티 버퍼 T.fill(#3455)과 bisheng 임시 파일 정리(#3461) (10-13)

날짜: 2026-10-13　출처: SimdVF T.fill(#3455)／ bisheng 정리(#3461)

  • #3455(+247/-31): Ascend SimdVF의 LowerFill은 원래 전체 버퍼 채우기만 지원했다(각 차원이 0에서 시작하고 범위가 버퍼 형상과 같아야 함). 다중 버퍼 파이프라인에서 MaterializeMultiBuffer가 버퍼에 버전 차원을 추가하면(예: [64] 논리 버퍼가 [2, 64] 물리 버퍼로 변환) 루프 내 T.fill은 현재 버전 슬롯 [v:v+1, 0:64]만 채우면 되는데, 전체 버퍼 검사에서 거부되었다. 이 PR은 처리 대상을 실제 채우기 영역으로 변경하여 영역 시작점과 범위에 따라 각 VReg 데이터 블록의 쓰기 인덱스를 계산하고, 상수 범위·연속성·VReg 정렬을 검사하며, 컴팩트 레이아웃과 명시적 stride를 지원한다. NPU 테스트 3건(1D / 2D / 2단계 파이프라인 다중 버퍼)을 추가했다.
  • #3461(+2/-1): bisheng wrapper가 임시 디렉터리를 생성할 때 keep_for_debug를 전달하지 않아 컴파일된 AscendC 소스가 항상 삭제되었다. 반면 nvcc, hipcc, PTO wrapper는 모두 keep_for_debug=not env.should_cleanup_temp_files()를 전달한다. 이 PR은 이를 정렬하여 TILELANG_CLEANUP_TEMP_FILES=0이 Ascend 백엔드에서도 동일하게 적용되도록 한다.

1.3 메인 저장소 검토 중: SM120 mxf8f6f4 전체 패밀리, Metal 배치와 Ascend 검토 중 클러스터(10-13)

날짜: 2026-10-13　출처: SM120 mxf8f6f4 패밀리(#3099)／ SM120 MXFP8/MXFP4(#3495)／ Metal 배치(#3194 ~ #3210)／ Ascend 독립 AIV(#3485)／ Windows MSVC(#3510)

  • SM120 블록 스케일링 MMA 두 갈래 병행: kind::mxf8f6f4 전체 f8f6f4 오퍼랜드 패밀리, 서브바이트 TMA producer와 공식 예제(#3099) 및 SM120 MXFP8/MXFP4(#3495)가 모두 검토 중 업데이트되었다. 10-10 SM121 점등에 이어 Blackwell 워크스테이션의 매트릭스를 계속 확장한다.
  • Metal 배치(10건): 세그먼트 정규화 누산기, simdgroup GEMM 프래그먼트, 스칼라 warp 리덕션, BF16 벡터 타입, 짧은 상수 루프 언롤, torch 백엔드 캐시와 파라미터 바인딩 등 — Metal 백엔드가 연속 정련 단계에 들어섰다.
  • Ascend 검토 중 클러스터: 독립 AIV 실행(#3485), 접근 영역 중첩 분석의 repeat/stride 지원(#3506), PTO 실행의 PTO codegen 라우팅(#3316)과 DeepGEMM의 PTO codegen(#3330), VF 스코프 외부 스칼라 sqrt(#3466), SimtVF remat_idx / 벡터 gather pack(#3492), profiling 호스트-디바이스 연관(#3321) 등.
  • 인프라와 수정: CI에 Windows MSVC 추가(#3510), TMA-only producer가 warp 0만 실행(#3503), 번들 TVM 발견과 DSL 선언(#3508), 테스트 인프라 캐시 IR 순회(#3502), fill / reduce 경계 3건(#3499 ~ #3501), codegen 공유 C 계열 발행(#3289). 메인 저장소 오픈 PR은 161건(이전 기간 168건).

2. 멀티 백엔드 어댑테이션(Ascend / MetaX / Hygon / Moore Threads)

2.1 Ascend: 문서 팩트체크 캠페인 3건 머지, 11건 검토 중; chunk와 희소 MLA 마이그레이션 배치 개시(10-13)

날짜: 2026-10-13　출처: round 시맨틱(#1612) / bitwise_rshift(#1676) / bitwise_xor(#1681) / Chunk O Forward(#1866) / sparse_mla_topk_reducesum(#1884)

  • 문서 팩트 체크 캠페인: T.tile.* API 항목별 점검(docstring 재작성 + 실기 테스트 + API 문서) 모니터링 기간 내 3건 머지 — 그중 #1612는 문서에 그치지 않는다: PTO의 round 낮춤을 CAST_ROUND에서 CAST_RINT로 변경하여 .5 중간값이 0에서 멀어지는 방향으로 반올림되던 문제를 수정하고 ties-to-even 시맨틱에 정렬했다(17건 실기 테스트와 codegen 단언 포함); #1676 / #1681은 bitwise_rshift / bitwise_xor를 커버한다. 별도로 11건의 동일 유형 점검이 리뷰 중 갱신되었다(axpy, clamp, clear, fill, bitwise_and/or/not/lshift, exp/ln 계열, relu 계열, sin/cos 등).
  • 연산자 이관 배치 개시: wch0810의 chunk 계열 이관 — Chunk O Forward(#1866), chunk_o_bwd(#1802), Chunk Delta H(#1799), Chunk Scaled Dot KKT(#1803); 희소 MLA 3건 — Sparse MLA SeeSaw(#1869), Sparse MLA Forward Pipelined(#1870), sparse_mla_topk_reducesum(#1884); 그 외 MHA 예제(#1879).
  • 품질과 회귀: 정밀도 표준 보급 3건 — 기존 예제에 정밀도 표준 적용(#1882), 정밀도 harness 및 runner 수정(#1883), 저성능 연산자를 examples_experiment로 이동(#1881); gemm_v0에서 W4A4 int4xint4 GEMM 결과 오류 수정(#1731). Ascend 저장소 오픈 PR은 총 229건(지난 회차 228건).

2.2 MLIR Ascend: NPUIR 명시적 메모리와 파이프라인 제어 머지(#190); Cube 메모리 할당 API 리뷰 중(#201)(10-13)

5. 트렌드 관찰

5.1 MoE: 쌍별 분할에서 쌍별 확정으로

  • 모니터링 기간 내 MoE 영역에서 두 건이 연속으로 수용되었다: masked FP8 그룹 GEMM(deep_gemm masked 시맨틱 정렬)과 DeepSeek 그룹 top-k(vLLM grouped_topk 정렬)가 같은 날 병합되었고, 여기에 컴팩트 행별 레이아웃이 통합되어 MMA 커널로 진입했다——TileOPs의 MoE 커버리지는 「연산자 개별 보충」에서 「모델 레시피 기준 수렴」으로 전환되었으며, DeepSeek-V3 / Qwen3-235B / Kimi-K2 워크로드가 대량으로 등재되었다. 심사 측에서는 동일 주제(gpt-oss swigluoai 전문가, permute-align, 전문가 검색 건너뛰기)가 지속적으로 두터워지고 있으며, MoE는 현재 TileOPs에서 가중치가 가장 높은 방향이다.

5.2 foundry 성능 배치가 일일 업데이트 리듬에 진입

  • 하루에 foundry 성능 병합 8건에 신규 오픈 8건: GEMM(타일 재배열, 공동 선택, 단일 WGMMA) 이후 풀링, 정규화, 리덕션, RoPE가 전면적으로 확산되었고, 각 건마다 대조 벤치마크(torch-compile / cuBLASLt / quack)가 첨부되었다. 단독 저자의 일일 업데이트 리듬은 다음을 시사한다: TileOps의 성능 엔지니어링이 이미 「핵심 연산자 집중 공략」에서 「전체 연산자 일일 순위 경신」으로 전환되었으며, 잔여 낙후 항목(MoE 네 줄, 일부 16비트 나눗셈 행)이 건별로 기록되었다.

5.3 ROCm: DeepSeek 신아키텍처 커널의 세 번째 마무리 라인

  • NSA 포워드/디코딩과 flash-decoding 타일(10-12 ~ 10-13)에 이어, 이번 모니터링 기간에는 mHC 전/후 커널과 KDA 디코딩 예시가 추가로 수용되었다——ROCm 라인은 연속 세 번째 날 병합이 있었으며, 주제가 DeepSeek 계열 신아키텍처(NSA, mHC)와 GLM-5.3 추론에 고도로 집중되었다. 기술 부채(CDNA 웨이브프런트 크기, MFMA 입력 타입, LDS/VGPR 예산)를 건별로 청산하는 방식은 다음을 보여준다: ROCm 지원이 「작동 확인」에서 「신아키텍처 릴리스와 동기화」로 전환되고 있다.

5.4 심사 대기열이 계속 두터워지며, 릴리스 침묵기의 저변 성장

  • 단일 모니터링 기간 내 병합 28건, 신규 오픈 42건, 심사 중 업데이트 79건: 메인 저장소 오픈 PR 161건(이전 기간 168건), TileOPs 26건(이전 기간 19건), Ascend 저장소 229건——메인 저장소는 슬림화, TileOPs는 두터워짐. 정식 버전은 계속 침묵 상태(메인 저장소 최신 v0.1.15, 09-30; TileFoundry v0.0.2)이지만, 야간 저변 정확성 +22, 벤치마크 +19의 상승이 지속되고 있다: 병합, 평가, 예시 세 라인이 다음 릴리스 기간을 위해 정적 준비를 축적하고 있다.
