컴파일러, 언어 계층 및 실행 경로

  • 전체 warp 리덕션을 하드웨어 redux로 전환(#3692, 10-29 병합, 4개 파일 +337/-35): 이전에는 전체 그룹이 정렬된 풀 warp이더라도 일반 크로스 스레드 리덕션이 그대로 shuffle 트리로 전개되었다. 메인 브랜치 837486a에서 네 개의 독립적인 32 lane FP32 최댓값 연산을 sm_103a + CUDA 13.1로 컴파일하면 20개의 shuffle과 0개의 redux가 생성되었으나, 변경 후에는 4개의 redux.sync.max.f32와 0개의 shuffle이 생성된다. 방식은 스칼라 및 배치 전체 리덕션에 이미 존재하는 warp_reduce 헬퍼를 재사용하고, 호출자는 스레드 지오메트리만 판단하도록 한 것이다. 정수 리덕션은 SM80 이상에서 하드웨어 redux를 사용하며, FP32의 최댓값/최솟값은 sm_100a, sm_100f와 sm_103a, sm_103f에서만 사용 가능하다. 좁은 부동소수점은 FP32로 승격된 후 헬퍼로 진입하며, FP64는 정밀도를 낮추지 않고 여전히 shuffle 경로를 사용한다. 작성자는 엔드투엔드 가속을 주장하지 않으며 명령어 수준 대조만 제시한다.
  • autotuner의 독립 JIT 구성을 동시 컴파일로 변경(#3476, 10-29 병합, 2개 파일 +54/-46): 기존 구현은 전체 컴파일 기간 동안 하나의 락을 보유하여 기본 컴파일 옵션만 사용하는 구성까지 직렬화되었고, 프런트엔드, 하강, 디바이스 컴파일이 모두 대기했다. 변경 방식은 각 오버라이드 구성에 대해 dataclasses로 독립 JITImpl을 복제하고, 기본 옵션은 기존 지연 경로를 유지하여 커널 캐시와 객체 아이덴티티를 보존하며, 공유 1단계 키를 가진 후보만 직렬화하고 디버그 출력의 디스크 쓰기는 여전히 직렬화한다. 크로스 백엔드 검증 데이터: Ascend 1797개 통과(Python 3.12.14, torch_npu 2.10.0, CANN 9.3.0, AscendC 예제 50개 전부 통과, PTO 예제 44개 통과 6개 스킵), ROCm 7.2 gfx942에서 3220개 통과, Metal 95개 통과, CUDA H100 PCIe cu130에서 5500개 통과, CuTeDSL 75개 통과 17개 스킵.

  • 백엔드 측면: 910 A2/A3의 NPUIR 경로를 mlir-ascend 메인라인에 병합(#207, 55개 파일 +21490/-1). 모드 스위치 TILELANG_ASCEND_MODE는 expert 또는 developer 값을 가지며 기본값은 expert. 두 번째 커밋은 이전 백엔드와의 동작 차이를 항목별로 정렬했으며, 핵심은 bf16 합법화(HIVM이 bf16 피연산자를 받지 않으므로 fp32로 계산한 뒤 명시적으로 변환)와 동적 extent의 복사 하강이다.
  • 스케줄링 및 주소 지정: 메인 저장소에 T.annotate_buffer_addresses가 추가되어, 스케줄링된 Ascend 파이프라인에서 UB, L1, L0A, L0B, L0C 및 SS 각 풀 내의 할당에 대해 정확한 바이트 주소 지정이 가능해졌다. 주소를 지정할 버퍼는 먼저 T.annotate_buffer_versions로 고정 개수를 선언해야 하며, 검증은 누락되거나 지원되지 않는 개수, 중복, 정렬 미준수, 동적 크기, 용량 초과를 포함한다(#3607, 14개 파일 +982/-26). PerCoreTask 후보체는 내부 if/else를 허용하며, 조건부 L1 채움도 더 이상 전체적으로 거부되지 않는다(#3686). 수작업 파이프라인은 구성 레지스터 위상을 유지한다(#3624).
  • 연산자 공급: 일주일 동안 situ_glu(#1891), GLM-5.3의 kpool 압축(#1910), Chunk Scaled Dot KKT 전방(#1803), W4A4 int4×int4의 근본 원인 수정(#1731), depthwise_conv_2d 예제 재제출(#1920, 동시 배치를 피하기 위해 목록화된 테스트 채널로 변경)이 병합되었다. 심사 중인 것으로는 GroupNorm과 fla_chunk 두 예제(#1607 / #1953 / #1952), NPUIR 뷰와 브로드캐스트 세 건(#1962 / #1960 / #1961)이 있다. 이들 연산자의 공통점은 양자화와 융합을 호스트 측 보완에 맡기지 않고 커널 본체에 작성한다는 것이다.
  • 엔지니어링 기준: 연산자 성능 프로파일링 skill이 추가되어 msprof op 출력으로 최적화 방향을 정한다(#1931). 설치 프로그램의 SHMEM 구간을 이중 수정하여 빈 껍데기 wheel이 더 이상 거짓 성공하지 않는다(#1943 / #1946). 2차원을 초과하는 GM에서 UB로의 복사는 DMA 행 수에 따라 선행 차원을 접는다(#1805). Cython 래퍼가 호출마다 분석기를 재구성하는 문제(약 0.28밀리초)는 먼저 기록하고(#1945) 이후 심사 중인 지연 생성으로 수정한다(#1948).
  • 회귀 상태: 매일 전체 테스트는 10-25에 2903개 항목 전부 통과를 보고했고, 10-26 새벽 테스트 작업은 실패를 보고했으며(#1944), 10-27과 10-28 이틀 연속 2903개 항목 전부 통과했다(#1950). 테스트 케이스 규모는 이미 게이트로 삼기에 충분하며, 결론의 유효 기간은 주 단위로 본다.
  • 심사 중인 호환성 변경: Carver는 선택된 SDK에 따라 A3 리소스 예산을 읽어, 256×256 FP32 누산기를 128 KiB에 불과한 L0C에 배치하지 않도록 한다(#1955). AI Core Exception Dump의 의존성은 CANN 9.2.0으로 낮추고 네 개의 필수 필드를 보완했다(#1956). 문서는 T.Tensor로 전환하고 T.Buffer DSL 인터페이스를 폐기한다(#1957). Ascend 저장소의 문서 사실 검증 네 건은 단일 댓글이 최대 46라운드에 달했다(#1628 / #1655 / #1656 / #1659).

Hygon: 일주일 네 건, 하드웨어 구조에 맞춘 배치

  • 레지스터 파이프라인은 기존의 공유 메모리 파이프라인과 협력할 수 있으며, 대응하는 커밋과 배리어 명령은 파이프라인 단계에 따라 삽입되고, warp 수가 4를 초과하면 warp 발산을 활성화한다(#18). 이 건은 10-08에 열려 두 주 넘게 수렴했으며, 병합 시 먼저 메인라인에 병합한 뒤 브랜치를 따르는 대형 병합이었기에 변경 줄 수가 같은 배치의 다른 변경보다 훨씬 크다.
  • 네이티브 B16 저장과 동적 WASP GEMM(#28): MLS의 Let 매개변수 발행 순서를 유지하고, GEMM의 warp 분할을 행렬 저장에 전파하며, 패킹된 B16에서 B32 출력으로의 별칭을 거부하고, 동시에 WASP 차원을 동적으로 만들고 축에 따라 정렬을 추론한다.
  • scale 버퍼의 행 계획을 독립적인 이중 bank 파티션으로 변경하고 LDS bank와 분리했으며, 동일한 행 매핑을 할당, scale 복사, MMAC 하강 세 곳에 동시에 넘겨 세 곳이 각자 레이아웃을 다시 추론하는 것을 피한다(#29, 12개 파일 +1389/-314). 이 건은 #28에 이어지며, Hygon은 이틀 동안 세 건의 메인라인 병합을 완료했다.
  • 일반 복사 경로의 LDS 쓰기 위상과 swizzle 전략이 심사 중이며, b8과 fp8 두 가지 데이터 폭을 갖춘다(#30, 18개 파일 +2000/-84, 다섯 개 테스트 추가).

TileOPs: 0.1.0 이후 두 번째 주

  • 릴리스 이후 병합 속도가 뚜렷이 둔화됨: 화요일 14건, 수요일 4건, 목요일 7건, 금요일 1건으로, 중심축이 “인터페이스를 동결하는 것”에서 성능과 정확성의 마무리로 옮겨갔다.
  • 성능 측면의 네 가지 확정 수치: 선택기는 더 이상 manifest에 붙여 피팅하지 않고, 바쁜 시간(device_busy_ms)에서 160개의 밀집 shape, 60개의 m 9~32 shape, 264개의 m≤8 shape로 재보정하며, softmin 기대 로그 리그렛으로 좌표 하강을 수행해 엔드투엔드 바쁜 시간 리그렛이 홀드아웃 manifest에서 5.79%에서 0.48%로, m≤8 홀드아웃 세트가 14.18%에서 1.79%로 낮아졌다(#2784). 비 NT 레이아웃은 전치 퍼시스턴트 커널 coop2_swap으로 전환해 2112×7168×4096 TN이 195.3마이크로초에서 175.3마이크로초로, 동일 기기의 다른 H200이 174.3에서 158.5마이크로초로 낮아져 모두 QuACK의 187.9와 167.0마이크로초를 앞섰다(#2789). cumsum 긴 행은 2단계 시드 스캔으로 변경해 (8,65536)이 12.75마이크로초에서 5.18마이크로초로 낮아지고 65535 tile 이상의 런치 실패도 수정했다(#2790). extrema 리덕션은 PTX의 max.NaN / min.NaN으로 전환해 amax (2048,4096) bf16이 8.352마이크로초에서 6.976마이크로초로 돌아와 FlagGems보다 빨라졌다(#2792).
  • 백투백 기준이 별도 항목으로 책정됨: 목요일 새 이슈에서 단일 호출에서는 본 구현이 QuACK을 앞서지만, 백투백·전력 상한 훈련 시나리오에서는 열 개의 큰 행 중 여섯 개가 뒤처진다고 지적했다(#2791). 이어서 심사 중인 GEMM 변경은 전력 상한에 따라 그리드 그룹화와 상주 블록 수를 재계산해 DeepSeek V3 프리필의 q-b shape에서 메모리 읽기가 168 MB에서 94 MB로 줄었다(#2794).
  • 정확성과 기능 보완: D128 밀집 포워드에서 key를 분리해 prefill-rope가 31.04마이크로초에서 17.09마이크로초로 낮아졌다(#2777). D128 퍼시스턴트 포워드는 스레드 기준으로 재작성하고 LSE를 출력한다(#2774). 융합 덧셈의 LayerNorm 행을 CTA 간에 분할하고 정밀도 결함은 별도 이슈로 분리했다(#2768 / #2773). 오프셋 저장 세 가지 수정과 SM90 그룹 GEMM, 출력 ABI(#2761 / #2765 / #2762).
  • 릴리스 형태: 릴리스 이미지가 병합되어(#2793) 연산자 라이브러리와 TileFoundry가 처음으로 같은 이미지에 포함되었다. 알려진 결함 중 FusedAddLayerNormFwdOp 정밀도 문제는 주간 내에 여전히 수정되지 않았고, 로드맵 첫 단계의 융합 연산자는 아직 병합되지 않았다.

TileFoundry: 세 패키지 분할에서 정적 계약으로

  • 주 초에 core / nvidia / apple 세 개의 배포 패키지로 분할하고 테스트 입력은 한 번만 로드하도록 했다(#268 / #269). sm_89에 E4M3의 warp MMA를 추가하고, 능력 검증을 “MMA만 검사”에서 모든 명령어로 확장했다. bulk copy, TMA copy, mbarrier 형식은 이전에 검증을 통과했지만 codegen이나 ptxas에서야 실패했다(#261 / #262 / #264).

6. 트렌드 관찰

릴리스 엔지니어링이 「마지막 칸에 막힘」에서 「이미지화 배포」로 나아갔다. 월요일자 데일리 리포트는 아직 TileOPs 첫 출시가 「문서 준비 완료, 아티팩트 미업로드」라고 쓰고 있었고, PyPI 최신은 여전히 2025-10-09의 0.0.1.dev2였다; 화요일 07:45 아티팩트 업로드, 13:15 릴리스 페이지 게시, 목요일 릴리스 이미지는 연산자 라이브러리, TileFoundry와 세 가지 환경 식별자(cuda13.2, torch2.13, tilelang0.1.12)를 함께 잠갔다. 일주일 만에 이 라인은 「출시할 수 있느냐」에서 「어떻게 조합해 배포하느냐」로 바뀌었다. 200여 연산자의 라이브러리에게 설치 가능성은 1퍼센트 포인트를 더 최적화하는 것보다 외부 채택 속도를 더 크게 결정하며, 이번 주의 답은 설치 경로마저 아티팩트로 만드는 것이었다.

결함 유형이 「컴파일 통과, 실행 시 오류 없음, 결과 오류」에 고도로 집중되며 하드웨어 또는 컨텍스트와 강하게 연관된다. 잘못된 스트림에 출력 할당(비기본 스트림이고 대기 작업이 있을 때만 손상), T.ws(-1)가 0개 스레드에서 실행, 슬라이스 채우기가 길이가 아닌 끝단으로 검증, 음수 인덱스 랩어라운드 후 여전히 음수, address_of가 읽기로 간주됨—다섯 가지 모두 컴파일 시 경고 없음, 실행 시 예외 없음. 이런 결함의 비용은 컴파일 오류보다 훨씬 높은데, 그것들이 오염시키는 것이 「테스트 전부 통과」라는 전제 자체이기 때문이다; 수요일에 드러난 콜드 컴파일을 가정한 여섯 개 테스트와 목요일의 without_kernel_cache 의미 漏洞는 테스트 인프라도 같은 위험 구역에 있음을 정확히 보여준다. 이번 주의 대응은 경계 검증을 컴파일 시점으로 앞당기는 것이며 방향은 옳지만 #3704, #3705, #3707 세 건의 새로 열린 결함은 이 경계가 아직 멀리 그려지지 않았음을 보여준다.

Ascend가 「백엔드 이식」에서 「연산자 보충」으로 전환하고 처음으로 재계산 가능한 검수 기준을 제시했다. 수요일은 NPUIR가 메인라인에 병합되었고(504개 자체 테스트, 71/72 예제), 목요일부터 금요일까지의 다섯 건 병합 중 네 건이 연산자와 예제였으며 모두 업스트림 모델 요구에 따라 배열되었다: GLM-5.3의 indexer 압축, 블록 게이티드 어텐션의 내적, 4비트 양자화 행렬 곱, 양자화 비전 모델의 깊이별 합성곱. 공통점은 양자화와 융합을 kernel 본체에 작성하는 것(E4M3 순수 정수 인코딩, 4비트 패킹 규약, 이중 kernel + 1x1 고속 경로)으로, 호스트 측에 보완을 남기지 않는 것이다; 동시에 프로파일링 skill과 체크리스트 테스트 채널을 프로세스로 확립했다. 주요 모순은 「컴파일할 수 있느냐」에서 「연산자의 수치와 성능이 안정적으로 검수될 수 있느냐」로 바뀌고 있으며, a2a3 스케줄러 마이그레이션의 100개 파일은 다음 단계의 변동이 스케줄러 계층에 있음을 예고한다.

실행 경로는 덜어내고, 백엔드 목록은 더한다. 메인 저장소는 이번 주 전 warp 리덕션을 redux.sync로 모으고, autotuner의 컴파일 잠금을 세분화하고, GM에서 L1로의 복사와 채우기를 하나의 작업으로 합치고, buffer 뷰의 레이아웃을 공유 변수에서 단일 뷰로 회수했다; 동시에 백엔드 목록은 계속 확장되고 있다—ROCm은 pip 버전 SDK와 FP4를 보충하고, Hexagon은 하루 15건, PPU는 무변경 래퍼가 나타났으며, Intel AMX는 TileFoundry에서 39개의 정적 계약으로 변했다. 두 방향은 모순되지 않는다: 업스트림은 실행 경로를 수렴시키고, 다운스트림은 각자 패키징하여 배포하며, 이는 TIRx가 TVM을 외부 의존성으로 만드는 것과 같은 사고방식이다.

「fork 화」는 이번 주 가장 강력한 채택 신호이자 가장 실질적인 동기화 비용을 가져왔다. T-HEAD는 TileLang을 자체 하드웨어 스택의 기반으로 삼아 PPU 브랜치를 만들었고, CANN 커뮤니티는 자체 연산자 저장소를 구축했으며, PTO-ISA는 문제집과 벤치마크를 모두配套 저장소로 만들었고, RISC-V에는 커뮤니티 허브 저장소가 등장했다. 이들은 모두 tile-ai 조직에 속하지 않지만 언어 계층의 안정성에 의존하고 있으며, 이것이 바로 0.1.0이 공개 API를 동결하고 CI 게이트로 만든 의미다. 대가는 마찬가지로 분명하다. 금요일 #3705 결함은 브랜치 사용자의 실제 빌드가 먼저 부딪힌 후에야 업스트림이 수정을 보완했다. 브랜치가 많아질수록 이러한 「다운스트림이 먼저 발견하고 업스트림이 나중에 수정하는」 경로는 더 길어지며, 메인 저장소는 브랜치와 업스트림의 동기화 방법이라는 장기적인 문제에 답하기 시작해야 한다.

기준 문제가 제품 문제로 처리되기 시작했다. TileOPs는 목요일에 「단일 호출 선행,背对背 후행」을 별도 항목으로 등록했고(#2791), 금요일의 GEMM 변경은 전력 상한에 따라 격자 그룹을 재계산하고 DRAM 읽기를 168 MB에서 94 MB로 줄였다(#2794). 선택기 역시 manifest에 붙여 맞추는 방식에서忙时 교정 방식으로 변경되었다. 「특정 행이 몇 마이크로초 빨라졌다」보다 이러한 변경은 훈련과 추론의 실제 호출 형태가 벤치마크와 다르다는 점을 인정하고 그 차이를 스케줄링 전략에 기록한다. 대규모 모델을 위한 커널을 작성하는 언어에게 이는 연산자 수를 더 쌓는 것보다 장기적으로 채택될지를 더 크게 결정한다.
