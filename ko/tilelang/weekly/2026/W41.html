TileLang 위클리 리포트 (2026-09-30 ~ 2026-10-07)

2026-10-07 Kubuds

보고 기간: 2026년 9월 30일(수) ~ 10월 7일(수), 총 8일 — 국경절 연휴 특별 집계 기간(10월 1일~7일 데일리 리포트 휴간, 본지는 연휴 통합판)

자료 출처: 본지 데일리 TileLang 동향 리포트의 연휴 직전 마지막 호(2026-09-30, 모니터링 기간은 당일 07:00까지); 연휴 기간 동향은 tile-ai 조직(29개 저장소) 216시간 모니터링 기간의 실측 검증을 기준으로 함(커밋, PR, 태그 및 릴리스, 야간 파이프라인, 검증은 10-08 오후까지 연장), 뉴스 측은 연휴 모니터링 기간(약 9일)의 여러 키워드 공개 검색 결과(부록 참조)

1. 이번 주 주요 뉴스

  • TileLang v0.1.15 연휴 직전 릴리스: Ascend 950 네이티브 백엔드가 버전과 함께 릴리스(09-30): 베이징 시간 07:31, “Public Release 9/30”으로 표기된 Ascend 950 백엔드 대형 PR(#3308, 134 커밋, 379 파일, +79956/-733)과 버전 상향 PR(#3309)이 잇따라 병합됨; 08:29, v0.1.15 정식 릴리스(릴리스 페이지). 버전의 네 가지 하이라이트: Ascend 950 네이티브 지원(엔드투엔드 NPU 백엔드: 네이티브 코드 생성, Cube/Vector 자동 스케줄링 및 동기화, SIMD/SIMT 혼합 프로그래밍), CUDA 자동 warp 특수화(역할별로 TMA 로드, MMA 연산 및 저장을 전담 warp 그룹에 디스패치), 통합 블록 스케일링 GEMM(T.gemm_blockscaled 시맨틱 통일, SM100 명령어 선택 및 SM120 프래그먼트 확장), 표현력이 더 강화된 Python 프런트엔드(컴파일 시점 반복과 컴프리헨션). 연휴 직전 데일리 리포트 마감 시점에는 두 PR이 아직 열린 상태였으며, 본지 검증으로 보완: 당일 아침 병합, 릴리스 페이지 동시 반영; Ascend A2/A3 지원은 커뮤니티가 유지보수하는 적응 저장소에 보존됨.

  • DeepSeek, 昇腾 대상 인프라 구성 요소 오픈소스 공개, TileLang 昇腾 버전 포함(09-30): 9월 30일, DeepSeek는 Huawei 昇腾 연산 플랫폼 대상 인프라 구성 요소를 오픈소스로 공개한다고 발표, TileLang 고급 언어 컴파일 도구, 연산 라이브러리 및 분산 통신 라이브러리를 포함(보도 내용: NVIDIA 플랫폼 구성 요소와 일대일 대응). 조직 측 근거: deepseek-ai는 당일 DeepGEMM-Ascend, DeepEP-Ascend, TileKernels, FlashMLA, DeepSelect 등 여러 저장소에 푸시 기록이 있음. 보도는 “DeepSeek 훈련에 사용된 모든 TileLang 연산자가 昇腾에서 대응하는 고성능 구현을 갖추고 있다”고 인용. 국내외 매체는 당일부터 집중적으로 후속 보도(열 개 키워드로 모니터링 기간 내 약 210건 적중, 제5장 참조).

  • PTO 백엔드 메인 저장소 병합: Ascend 950이 같은 날 두 번째 코드 경로 확보(09-30): #3310(+11406/-31, 36 파일)이 12:08에 병합됨 — pto 타깃과 실행 백엔드 등록, PTO 디바이스 코드 생성, 커널 래핑과 Cython 런타임 인터페이스로 실행, ptoas와 毕昇으로 PTODSL 커널 컴파일; 지원 함수는 GEMM, SIMT/SIMD, 동기화, 혼합 커널, 캐시 바이패스 접근 및 Philox 난수를 포함. 후속 대기열은 이미 열 건 넘게 열려 있음(PTO 실행 라우팅, 임포트 격리, DeepGEMM 코드 생성 등), 아직 리뷰 중.

  • TileOPs 연휴 8일간 137건 병합: 양자화, 샘플링, 선형 어텐션 3개 라인이 체계화(09-30 ~ 10-07): 137건 병합, 143건 신규 개설(별도로 10-08 복귀일 2건 추가); 09-30 하루 32건이 최고치. 샘플링 라인은 마스크부터 거부 샘플링까지 여섯 개 커널이 전 과정 반영; 선형 어텐션 라인은 GLA, Gated DeltaNet, DeltaNet과 Kimi Delta Attention(텐서 코어 WY 역행렬 #2365 포함)이 집중적으로 진행; 양자화와 GEMM 라인은 INT4/INT8/FP8 다형태를 포괄; 커널 인터페이스 리팩터링, PyPI 릴리스 파이프라인과 README 개편이 동시에 반영(제4장 참조).

  • Moore Threads MUSA, 공개 0.1.15 정비 및 v0.1.15+musa.1 릴리스(09-30): 하루 53건 커밋(51건 MUSA 측 기능, 2건 업스트림 동기화) — mp31 아키텍처 배치(tme 시리즈, sqmma, wmma, warp 특수화, 캐시 힌트, peer memory 등), 런타임 배치(기본 타깃과 백엔드 진입점, 디바이스 코드 생성, JIT 래핑, ipc/vmm, dlpack 호환, 명시적 스트림 등); 저녁 “Prepare public TileLang MUSA 0.1.15” 반영 후, 17:59에 릴리스 v0.1.15+musa.1 태그(이전 버전 v0.1.14+musa.1은 09-11).

  • Hygon 3연속 병합(09-30): 행렬 저장(gfx946, #14), multi-XCD Cython 시작 지원(#15), LDS 전략 충돌 수정(#16) — 연휴 전 비동기 복사 개선(#13)에 이은 연속 진전; Hygon은 이번 기간 Ascend 외에 유일하게 코드 진전이 있는 중국산 백엔드입니다.

  • 야간 파이프라인 12개 스냅샷 중단 없음: 벤치마크 스위트 1939개로 확대(09-30 ~ 10-08): 12개 스냅샷이 매일 생성되었으며, 정확성 테스트 케이스는 1009개에서 1044개로(테스트 구조 재편 기간에 기복 있음), 최신 스냅샷은 1027개 전부 통과; 벤치마크 측정은 1355개(39개 스위트)에서 1939개(52개 스위트)로 확대; 전체 기간 중 유일한 실패 1건 — 10-07 스냅샷의 FFT 케이스가 CUDA 메모리 부족(환경적 요인)으로 실패했으나 다음 스냅샷에서 즉시 전부 통과로 복구.

  • 채택처 동일자 대응: TileKernels v2.0.0 Ascend 지원 포함 릴리스, FlashQLA v0.1.3 업데이트(09-30): DeepSeek TileKernels가 v2.0.0을 릴리스(09:58), README에 “Huawei Ascend support” 추가: 듀얼 백엔드를 런타임이 자동 선택하며, 동일한 Python API가 NVIDIA GPU와 Huawei NPU에서 동시에 실행됨(TileLang 0.1.15+, CANN 9.2.0+ 필요); Qwen FlashQLA가 v0.1.3을 업데이트(21:02), sm90/sm100 autocp 계수 및 벤치마크 업데이트 동봉. 채택처와 업스트림 릴리스가 같은 날 기록되어 연동이 검증됨.

2. 핵심 프로젝트 진행 상황(메인 저장소 tilelang)

버전 및 릴리스: v0.1.15 정식 릴리스(09-30)

  • 타임라인: 09-30 07:31, ‘Public Release 9/30’로 표기된 #3308과 버전 번호 상향 #3309가 병합됨; 08:29, v0.1.15 릴리스——직전 버전 v0.1.14(09-02)로부터 28일 후로, 기존의 월 단위 릴리스 간격과 일치한다.
  • Ascend 950 단락(릴리스 노트 발췌): tilelang.ascend.language와 target="ascend"(dav-3510에 대응)가 추가됨; 동일 커널 내에서 Cube GEMM과 Vector 연산을 결합(T.SimdVF / T.SimtVF 영역); 명시적 UB/L1/L0 저장소, 타일 복사, 크로스 코어 전송 및 MXFP8/MXFP4 블록 스케일링 GEMM; 자동 스케줄링, 파이프라인, 다중 버퍼링, 레이아웃 추론 및 동기화 삽입; Bisheng 컴파일, tvm_ffi 및 Cython 실행, PyTorch NPU 텐서와 스트림, NPU 프로파일링 통합; 예제에는 GEMM, DeepGEMM 스타일 커널, FlashAttention 순방향/역방향, RMSNorm 및 FP8 양자화가 포함됨. A2/A3 지원은 커뮤니티에서 유지 관리하는 TileLang-Ascend 프로젝트에 보존됨.
  • CUDA 단락: 역할 기반 자동 warp 특수화(환경 변수로 활성화 가능); SM120 블록 스케일링 GEMM 확장(프래그먼트 상주 A 피연산자, 행 우선 스케일링 프래그먼트, 홀수 per-warp 원자 그리드); T.fma/T.fmul 최근접 반올림; FP8 희소 MLA 순방향 예제(DeepSeek V3.2, Hopper, #3224); WGMMA/UMMA K 패널 스트라이드 수정 및 희소 MMA 비동기 펜스.
  • 언어, 컴파일러 및 런타임 단락: 커널 런치 인코딩 목표 중립화; Python 컴파일 타임 반복과 컴프리헨션; coalesced_width 힌트화; AllReduce 스레드 스트라이드와 리덕션 NaN 전파 dtype 검증; 캐시 매개변수를 JSON으로 변경, CUDA 바이너리 원자적 게시, 월 클록 기준, wheel을 GPU runner에서 검증, 성능 회귀로 CI 실패 처리.
  • ROCm, CPU 및 Metal 단락: ROCm은 DeepSeek V3.2 Top-K 선택기, wave64 Hadamard 및 GLM-5.3 k 풀 예제 지원; CPU 스칼라 GEMM은 누적 dtype에 따라 계산; Metal 32비트 원자적 덧셈.
  • 호환성 참고 사항: T.Pipelined에서 사용되지 않는 sync/group 매개변수 제거, T.gemm_sp에서 k_pack 제거; T.symbolic은 사용 중단 별칭으로 전환(새 코드는 T.dynamic 사용); TILELANG_CACHE_VERIFY_HASH 제거, 캐시 해시 검증은 강제로 변경.

휴일 수정 라인과 엔지니어링 소규모 진행(10-02 ~ 10-08)

  • 정확성 수정: #3361 bfloat16 스칼라 매개변수 지원 (10-02); #3334 NVFP4에 보존된 UE4M3 NaN 스케일링 코드워드 디코딩 (10-03); #3429 인덱스 승격 시 명시적 변환 유지 (10-06); #3441 LDSM 복사 시 공유 영역 오프셋 유지 (10-07); #3439 SM89에서 fp8 T.gemm을 시작 즉시 충돌 대신 게이트된 오류 보고로 변경 (10-07).
  • JIT 및 테스트: #3435 지연 커널 빌드 시 가변 매개변수 유지 (10-07); #3443 지원되지 않는 BF16 스칼라 회귀 테스트 제거 (10-07).
  • 엔지니어링 기타: #3418 완전히 동일한 두 브랜치 병합 (10-03); #3431 pre-commit 자동 업데이트 (10-07).
  • 복귀 첫 커밋 (10-08): #3299 ROCm에서 T.round의 최근접 짝수 반올림 수정 — 릴리스 당일 정오에 병합되어, 연휴 후 리듬이 예정대로 회복되었습니다.
  • 소결: 전체 모니터링 기간 12건 병합 (09-30 세 건은 릴리스 배치, 10-02부터 아홉 건은 연휴 소규모 수정), 연휴 전 단일 주간 14건 대비 소폭 감소, 실질 증가분은 리뷰 대기열에 집중 (다음 절).

리뷰 대기열 관찰

  • 격차: 모니터링 기간 내 신규 오픈 96건, 병합 12건; 09-30 하루 신규 오픈 약 45건, 구성은 두 가지 — Ascend 테마 배치 (약 20건: #3316부터 #3331까지, PTO 실행 라우팅, AutoSimtVF, T.PersistentKernel, torch_npu 작업 큐, 연산자 생성 agent, DeepGEMM 코드 생성, RNG 리셋 등)와 체계적 소규모 수정 경화의 “지원하지 않는 모드 거부” 배치 (#3332부터 #3372까지, 사십여 건).

  • 압력 판단: 연휴 전 데일리 리포트 기준 오픈 PR 116건; 연휴 동안 심사 대기 작업이 다시 순증했습니다. 연휴 후 리뷰 대역폭이 950 추종 대기열의 병합 속도와 다음 버전 리듬을 직접 결정할 것입니다.

3. 다중 백엔드 적응 (Ascend / MetaX / Hygon / Moore Threads 등)

  • 메인 저장소(릴리스 및 백엔드): 자세한 내용은 2장 참조——#3308(950 네이티브 백엔드)과 #3310(PTO 백엔드)이 같은 날 병합되었다.

  • 휴일 개발 강도 상승: TileOPs 8일 137건, MUSA 하루 53건, 야간 파이프라인 12건, 적응 저장소 연휴 후 첫날 2건 병합——「휴일 저강도 운영」이라는 기존 가정은 더 이상 성립하지 않음.
  • 「열기는 많고 병합은 적음」이 여전히 구조적 긴장: 메인 저장소 96건 신규 대비 12건 병합, 오픈 큐 순증; Ascend 대형 묶음과 40여 건의 경화 소규모 수정이 심사 대기——연휴 후 리뷰 대역폭이 950 후속 대응과 다음 버전 리듬을 직접 결정.
  • 다중 백엔드 열기 분화, 계층은 안정: Ascend(이중 백엔드)와 MUSA(공용 버전 릴리스)가 열기 양대 핵심; Hygon은 안정적 소걸음; MetaX, MLIR Ascend는 조용; tvm 서브모듈 저장소는 유지보수성 회귀 중심——「메인 저장소 네이티브 + 적응 저장소 후속 + 공용 버전 동기화」의 계층 형태가 이미 안정화.
  • 엔지니어링 마무리 작업 밀집: PyPI 릴리스 파이프라인, bench.Runner, 캐시 원자적 릴리스, 테스트 통합과 명명 규범——병목이 「연산자 작성」에서 「릴리스와 검증 파이프라인」으로 이동, 라이브러리가 엔지니어링 성숙기로 향하는 전형적 시퀀스.
