TileLang 위클리 리포트 (2026-10-12 ~ 2026-10-16)

2026-10-16 Kubuds

보고 기간: 2026년 10월 12일(월)부터 10월 16일(금)까지, 총 5영업일, 5회분 데일리 리포트 소재 소재 출처: 본지의 일일 TileLang 동향 데일리 리포트 5회분(10-12, 10-13, 10-14, 10-15, 10-16); 추가로 tile-ai 조직 29개 저장소의 168시간 모니터링 기간 보충 점검, 야간 파이프라인 6개 스냅샷의 테스트 결과를 개별 재계산 및 각 저장소 릴리스 메타데이터 재검토(상세 내용은 부록 참조)

1. 이번 주 주요 뉴스

  • 메인 저장소 ROCm 라인 4일 연속 마무리, DeepSeek 신규 아키텍처 커널이 세 번째 마무리 라인으로 부상(10-13 ~ 10-14): 10-13에 DeepSeek NSA 전방향/단일 토큰 디코딩의 64 lane 단일 웨이브 구현(#3152, +111/-2)과 flash-decoding의 LDS/VGPR 예산 적응형 타일(#3149, +82/-5)이 병합됨; 10-14 새벽에 mHC(다양체 제약 초연결) 전/후처리 커널(#3156, 2개 파일 +83/-6, HIP 측은 전체 64 lane 웨이브프런트에서 분업하도록 변경하고 FP32 혼합 가중치를 BF16으로 변환하여 MFMA에 공급)과 safe-gated KDA 디코딩 예제(#3249, +360, GLM-5.3-Flash TP8 전용화 구성 포함)가 추가로 병합됨; 10-14에는 cumsum/cummax의 64 lane 세그먼트 폭 수정(#2326)도 있음. 네 건 모두 “장치 현실에 따른 적응”을 공통적으로 지향: gfx942 웨이브프런트 크기, MFMA 입력 유형, LDS/VGPR 예산을 항목별로 청산, ROCm 지원이 “동작 확인”에서 “신규 아키텍처 릴리스와 동기화”로 전환.

  • Ascend PTO가 “독립 타깃”에서 “일등 실행 경로”로 승격, NSA 이중 마이그레이션과 롤백 규율이 같은 주에 발생(10-12 ~ 10-15): 10-15에 실행 라우팅 #3316 병합——target="ascend"와 execution_backend="pto" 조합이 실행 인식 타깃 정규화를 거쳐 CodeGenTileLangPTO에 직결되고, auto 경로는 AscendC + TVM-FFI를 유지; 선행된 예제 타깃 선택 #3474(10-14 병합, 하드코딩된 target="ascend" 제거, CI가 ascend / pto 두 타깃을 각각 한 번씩 실행)과 본 모니터링 기간에 심사 중인 tvm_ffi 백엔드, VMI 벡터화, SS buffer, 부분 L0 복사 pitch 등 일곱 건이 패밀리를 구성. 같은 주 10-12에 Ascend NSA Decode(#1701, +755, 28개 계층별 테스트)와 NSA Bwd(#1730, +1593, 20개)가 병합됨; 10-14에 세 건의 “문서 사실 확인” PR(#1612, #1676, #1681)이 저우선순위 예상 실패 테스트 케이스의 예외 정규식 불일치로 인해 일괄 롤백됨(#1888 ~ #1890), bitwise_rshift는 재작업 버전 #1893으로 예상 실패 단언을 삭제한 후 재제출됨; 10-15에 dav-3510에서 gemm_v0의 조용한 수치 오류 수정이 시작됨(#1900), --npu-arch가 무조건 dav-2201을 취하여 A5 커널이 잘못된 아키텍처를 겨냥하게 되는 문제를 노출.

  • TileOPs 일주일 52건 머지: Op 기반 클래스 리팩터링 확정, MoE 듀얼 연산자 확정, SM89 두 번째 플랫폼으로 등극 (10-12 ~ 10-16): 10-11에 머지된 Op 기반 클래스 리팩터링(#2520, 363개 파일, +3362/-5227, 스스로 “릴리스 전” 마무리라고 칭함)은 컴파일 경계가 있는 연산자와 없는 연산자를 모두 _run_call을 통해 실행하도록 통일하고, select_kernel_key/select_implementation을 key_for로 병합하며, 컴파일 경계를 manifest에서 도출하도록 변경했으며, 문서 사이트는 다음 날 《Op 기반 클래스 가이드》로 후속 조치했다. 10-13에는 MoE 듀얼 연산자가 같은 날 확정되었다 — masked FP8 그룹 GEMM(#2521, 20개 파일 +1788/-37, deep_gemm masked 시맨틱에 정렬)과 DeepSeek 그룹 top-k(#2535, 15개 파일 +1193/-69, vLLM grouped_topk에 정렬하고 T=512일 때 32/132 SM의 스케줄링 문제 수정). SM89는 10-12부터 일괄 마무리되었다(GQA 프리필/디코드, GDN / DeltaNet 프리필, GLA / DeltaNet 역방향, KDA 프리필, Norm 전체 스펙트럼). RTX 40 시리즈와 L40 / 6000 Ada급 워크스테이션이 연산자 라이브러리 측면에서 Hopper와 나란히 서게 되었다.

  • 야간 기반시설 6개 스냅샷: 정확성 1032 → 1134 (+102), 벤치마크 1947 → 1989 (+42), 전 과정 제로 실패 (10-12 ~ 10-16): 이번 주 6개 스냅샷의 정확성 테스트 케이스는 1032건에서 1134건으로, 벤치마크는 1947건(52개 스위트)에서 1989건(55개 스위트)으로 증가했으며, 6개 모두 제로 실패·제로 오류, 각 1건 스킵이었다. 일일 최대 증가폭은 10-15(+41, TileOPs 16건 머지와 동시)에 나타났고, 10-16에는 스냅샷이 두 번(새벽과 야간 각 1회) 발생하여 이번 주 처음으로 하루 두 번의 스냅샷이 있었다. 평가 환경은 H200, CUDA 13.2, torch 2.13.0+cu132, tilelang 0.1.12이다(자세한 내용은 4장 표 참조).

  • 멀티 백엔드 동일 버전 마무리: Hygon v0.1.15 업그레이드 적용 및 분산 IPC 라인 개설, MetaX 업스트림 추격, Moore Threads 전 주간 침묵 (10-13 ~ 10-16): Hygon은 10-14에 v0.1.15 전체 업그레이드를 머지하고(#20, HCU 백엔드 유지 및 블록 스케일 GEMM의 scale 버퍼 레이아웃 계획 신규 추가), v0.1.15-release 브랜치를 생성했으며, 같은 날 #19(+2577/-28, 44개 파일)로 Distributed 라인을 개설했다(통합 프로세스 런처, IPC allreduce 테스트, IPC GEMM allreduce 예제 등). 10-15에는 #21로 블록 스케일 비동기 복사 레이아웃을 당일 개설, 당일 v0.1.12-release 유지보수 라인에 머지했으며, 10-16에는 다시 #22를 머지했다(K-major 패킹 scale 복사 및 네이티브 FP32 MLS GEMM). MetaX는 10-13에 main을 업스트림 v0.1.15 노드로 푸시했고(미러 #3309), 10-16에는 dev 라인에 업스트림 main을 머지하고 xfail 테스트 케이스 하나를 수정했다. Moore Threads는 09-30 이후 전 주간 활동이 없었으며, 4개 중 유일하게 v0.1.15에 정렬되지 않은 백엔드이다.

  • TileFoundry 일주일 만에 10건 병합: 희소 디코딩 TIR 관통, Qwen3.8-27B 프리필 최초 전체 길이에서 SGLang 추월, 핵심 리팩터링과 외부 감사 동시 진행 (10-12 ~ 10-16): 10-12에 희소 디코딩 TIR 관통 #223 병합(84개 파일, +4424/-1543, 누락된 루프 작업량, 과도한 조회 비용 및 단계별 업데이트 오류 수정); 10-13에 Qwen3.8-27B 프리필 예제 #229 병합(89개 파일, +38069), 해당 저장소 최초로 1024 / 4096 / 8192 세 길이 모두에서 SGLang보다 빠른 예제(8192에서 스코어링이 FLOP의 3.1%만 차지, 부하가 H200 변곡점을 36배 초과); 10-15 같은 기간에 인스턴스 슬롯 리팩터링(#232, 소스 전체 1674개 통과)과 lowering / printer 계약(#233) 적용; 10-16에 analysis 접근 컨텍스트(#238)와 issue 237의 할당/lowering 수정(#241) 추가. 리팩터링 적용과 같은 기간에 써드파티 스킬 저장소가 TileFoundry를 워크플로에 vendor하고 4개의 emitter 버그와 2개의 런타임 버그를 나열—외부 감사 단계 진입.

  • 채택 측 최초 버전 반복: TileKernels v2.1.0 Ascend 중심 재작성, FlashQLA Blackwell sm120 수정 (10-14): DeepSeek TileKernels v2.1.0(16개 파일, +352/-382)은 해당 저장소가 09-30에 Ascend 지원을 추가한 후 첫 버전 반복으로, 변경은 Ascend 측에 집중(norm_forward_asc 대폭 재작성, SwiGLU 순방향/역방향, Engram 게이팅), README는 TileLang 0.1.15, PyTorch 2.13, Ascend 950 NPU 및 CANN 9.2.0으로 업그레이드 요구; Qwen FlashQLA #48(5개 파일, +82/-5)은 0.1.13 이후 Blackwell sm120 순방향/역방향 사용 불가 문제 수정(block_DV가 잘못 128로 변경됨, aggregate_card_state 누락), RTX 5090 + tilelang 0.1.15 + CUDA 13.0에서 전체 테스트 통과.

  • 하드웨어 매트릭스 같은 주 확장: SM121 점등, SM120 블록 스케일링 이중 라인 심사 중, D=256 디코딩 SM80/SM90으로 확대, CPU OpenMP 그리드 병렬 적용 (10-12 ~ 10-15): SM121(GB10 / DGX Spark) 블록 스케일링 MMA가 10-11에 점등(#3430, DGX Spark 드라이버 580.178.04 / CUDA 13.0 실측), 이전에는 sm_121a에서 모든 블록 스케일링 MMA가 BPT.TRAP으로 컴파일됨; SM120 측의 MXFP8/MXFP4(#3495)와 mxf8f6f4 전체 피연산자 패밀리(#3099)는 주중 내내 심사 중. 소비자 및 워크스테이션 측에서는 D=256 FP16/BF16 밀집 디코딩이 SM89에서 SM80/SM90으로 확대(#2563, Gemma-2B 8K cache 부하 포함, 동시에 밀집 RoPE split이 softcap을 무시하는 문제 수정); 메인 저장소는 10-14에 CPU 백엔드의 그리드 수준 OpenMP 병렬(#3109)과 Windows NVCC의 cl.exe 전환(#3510) 병합.

2. 핵심 프로젝트 진행 상황(메인 저장소 tilelang)

버전 및 릴리스

  • 메인 저장소의 최신 태그와 릴리스는 여전히 v0.1.15(09-30 릴리스)이며, 주간 전체에 걸쳐 신규 태그와 신규 릴리스 페이지 항목이 없었고, 이번 주 금요일 기준으로 이미 16일째입니다. 릴리스 페이지의 최근 세 항목은 각각 v0.1.15(09-30), v0.1.14(09-02), v0.1.13(08-03)이며, 기존의 월간 리듬이 이번 주에 깨졌습니다.
  • 적응 라인 태그는 주간 전체 동안 변동이 없었습니다: Ascend v0.1.2.000, MLIR Ascend v0.1.2.020.sglang.poc, MetaX v0.1.14(10-13에는 main 이미지만 v0.1.15 노드로 이동했고 신규 태그는 없음), Moore Threads v0.1.14+musa.1; Hygon은 v0.1.15 메인라인과 v0.1.12-release 유지보수 라인의 이중 라인으로 병행하고 있습니다.
  • 릴리스 정체의 대조면은 다운스트림 제약의 상향입니다: TileKernels v2.1.0은 TileLang 0.1.15 이상을 명시적으로 요구하며, FlashQLA의 sm120 수정 또한 0.1.15에서 검증되었습니다. 이번 주부터 「0.1.15 베이스라인」이 채택 측의 사실상 최저 요구 사항이 되었습니다.

컴파일러, 실행 경로 및 언어 계층

  • PTO 실행 라우팅(#3316, 10-15 병합): 실행 인식 대상 정규화 훅을 신설했으며(BackendContext 생성 지점에 연결), Ascend 전용 정규화기가 파싱 전에 네이티브 Ascend 대상을 PTO 대상 변형으로 전문화하고 arch 등 속성을 보존한다. 디바이스 코드 생성은 PTO_CODEGEN과 target.build.tilelang_pto_without_compile로 전환되었으며, 문서에는 TILELANG_DEFAULT_TARGET=ascend에 TILELANG_EXECUTION_BACKEND=pto를 더한 등가 구성이 제시되어 있다. 테스트는 컨텍스트 파싱, 대상 속성 보존, 캐시 디스패치, 환경 변수 선택을 커버한다.
  • PTO DeepGEMM codegen(#3330, 10-14 병합): 제어 흐름을 넘나들며 tl.ascend_set_mmad_direction을 추적하고 적용된 방향을 MAD 명령에 인코딩하며, 충돌 방향에서 도달 가능한 MAD를 거부한다. SIMD 후 증분 로딩, 혼합 AIC/AIV 커널의 UB 주소에서 PTODSL 포인터로의 변환, 동적 L0C→UB 차원과 스트라이드, int16 부호 있는 패킹 MX scale을 지원한다. 자체 보고 기준 DeepGEMM PTO 테스트 케이스 15개 중 14개가 통과했으며, test_bf16_m_grouped_padding은 PTOAS VPTO 백엔드가 FP32→BF16 변환을 합법화하지 못하는 문제로 여전히 차단되어 있다.
  • 독립 AIV 실행(#3485, 10-14 병합): Ascend AutoSchedule을 확장하여 AIV0와 AIV1이 sid 의존성 아래에서 서로 다른 작업을 수행할 수 있게 했다(교대 마무리, 역양자화와 마무리 분담, 서로소 입력 파티션, 루프 내 역할 전환). AssignCore를 지연 추정과 스케줄링 이전으로 앞당기고, AIV 로컬 UB 버퍼와 스칼라 상태에 독립적인 정체성을 부여했다.

  • tilelangGym이 10-14에 생성되었으며, “다양한 benchmark / microbenchmark의 PTO lowering과 성능 민감도 테스트”를 표방한다. 10-15의 일곱 건(06:47~07:59)으로 독립 SimtVF 표준 테스트 스위트가 형성되었다: SV / CF / SP 및 PTO-DSL의 시드 커밋과 버전 pins, 회귀(#1), 스크립트와 레이아웃 정리, SV1 SIMD keynote와 단일 PASS 표(#3), remat 버텍스 전체 PASS 표와 행별 Simt 대 SIMD-DSL 대조(#4), 그리고 SIMD 약 85%와 Simt IPC / bubble / ILP 분석을 ANALYSIS에 링크—PTO lowering의 성능 민감도 분석을 위한 데이터 플랫폼을 구축했다.
  • SuperNPUBench는 주중 고빈도: 10-12에 네 건의 커밋(rms_norm 16 KiB 타일 분해 R=8192 리덕션, gfsim RES_CHECK 파일 IO 락스텝 안전, matmul_test 4-PE 단순화, #225 머지)과 두 건의 릴리스(ops-20261012, ops-20261013, 후자는 suite별로 2개 소패키지 분할, 전체 컴파일 산출 ELF 포함); 10-13에 ops-20261013.2 릴리스 및 matmul_test CUBE TCVT 직결, topk 이식 가능 gfsim fixture 추진; 10-14에 세 건 아카이브(rms_norm_dynamic_simt_32k, group_norm_grad 정적 커널 V0 편입, matmul reuseB 커널); 10-15에 그룹 정규화 역방향 단일 패스 리덕션과 gamma/beta 균형(#245).
  • tilelang-puzzles-ascend의 simt_compare 브랜치는 주중 계속 진행: T.reduce_max가 직렬 스캔 대비 실측 8.94배 빠르며, 12개 커널이 T.reduce_absmax로 전환되어 재측정되었다.

6. 트렌드 관찰

  • 릴리스 정적기의 「정적 준비」가 네 방향에서 동시에 완료됨: TileOPs의 Op 기본 클래스 리팩터링은 스스로 릴리스 전 마무리라고 칭했고, 야간 기반의 여섯 스냅샷은 무실패로 증가했으며, TileFoundry의 예시는 디코딩에서 프리필 전 길이 초월로 확장되었고, 멀티 백엔드 v0.1.15는 정렬되었다 — 메인 저장소는 09-30 이후 16일째 태그가 없지만, 다음 버전의 정적 준비는 이번 주에 기본적으로 갖춰졌다. 릴리스 여부는 내용이 아니라 리뷰 게이트에 달려 있다.
  • 멀티 백엔드가 「버전 정렬」에서 「동일 시맨틱 마무리」로 이동: Hygon은 v0.1.15 전량 업그레이드를 완료하고 별도로 v0.1.12 유지보수 라인을 세웠으며, MetaX는 미러링을 따라잡은 후 dev 합류로 전환했고, Ascend는 문서 사실 검증, 캐시 시맨틱과 실기 검증(#1900)에 중심을 두었으며, Moore Threads는 유일한 공백이다. 네 곳의 격차는 이미 「백엔드가 있느냐」에서 「시맨틱이 일치하느냐」로 바뀌었다.
  • ROCm이 새 모델 릴리스와 동기화되는 두 번째 라인이 됨: 연속 나흘 동안 DeepSeek NSA, mHC, KDA와 GLM-5.3 관련 커널이 착지했고, 기술 부채는 장치 예산(웨이브프런트 64 lane, MFMA 입력 타입, LDS/VGPR 상한)에 따라 건별로 청산되었다. SM121 / SM89의 다세대 동시 수정 합류 이후, 백엔드 토폴로지는 「NVIDIA 우선」에서 「다중 장치 동시 유지보수」로 전환되었다.
  • TileOPs의 성능 엔지니어링이 「핵심 연산자 집중 공략」에서 「전 연산자 일일 순위 경신」으로 전환: 하루 8~11건, 각 건에 외부 대조(torch-compile / cuBLASLt / quack / FlashInfer / FLA)를 붙였고, 잔여 격차는 공개적으로 PR에 기록되었다(lm-head 두 줄 0.909x, GLA 역방향은 가속을 명시적으로 주장하지 않음) — 「뒤짐」을 정량화하고 기록으로 남기는 것이 단일 지점 속도 향상보다 엔지니어링 규율을 더 잘 보여준다.
  • Ascend의 거버넌스 기준이 「전부 통과」에서 「단언 정밀화」로 전환: 세 건의 문서 검증이 저우선순위 케이스의 예외 정규식 불일치로 인해 통째로 롤백된 뒤 삭제·축소 후 재작업되었고, 이는 PR 단계에서 low_priority를 실행하지 않고 매일 전량으로 보완하는 2단계 CI 구조를 드러냈다. 이런 롤백은 퇴보가 아니라 「예상된 실패」를 기술 부채 청산의 신호로 삼는 것이다.
  • TileFoundry가 컴파일러 도구에서 납품 가능한 제품 형태로 전환: scaffold 독립 프로젝트, 인스턴스 슬롯과 lowering 계약, 크로스 스파인 프리필 예시 논증, 리팩터링 착지와 같은 모니터링 기간에 즉시 제3자 vendor가 병렬로 나열하고 결함 대장을 공개했다 — 제품화의 전형적 궤적은 「기반 리팩터링 이후, 인터페이스 계약 수렴과 결함 공개화」다. 다음 호에서는 이 emitter / 런타임 결함들이 흡수되는지 추적해야 한다.
  • 다음 호 관심 지점: 메인 저장소 v0.1.16 릴리스 여부(16일째 정적); SM120 블록 스케일링 MMA 두 라인(#3495 / #3099)의 합입 가능성; cumsum warp 특화 수정(#3536)과 PTO 계열 일곱 건의 진척; Ascend #1900의 두 건 커밋과 A5 실기 검증 일정; Hygon 분산 IPC에서 첫 합입 멀티 카드 PR이 나타나는지; TileOPs에 릴리스 파이프라인 정리류 커밋이 나타났으며(주말) 이것이 첫 정식 버전을 이끌어낼지; TileFoundry의 외부 결함 목록이 흡수되는지.
