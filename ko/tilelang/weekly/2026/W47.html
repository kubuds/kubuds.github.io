TileLang 위클리 리포트 (2026-11-16 ~ 2026-11-20)

2026-11-20 Kubuds

보고 기간: 2026년 11월 16일(월)~11월 20일(금), 영업일 5일, 데일리 리포트 5회; 별도로 릴리스일(11월 21일)에 tile-ai 조직 30개 저장소에 대한 168시간 보충 점검 포함

제1부 · 브리핑

이 섹션은 이번 주 주요 사항을 선별한 것으로, 기본 800자 이내(이번 호 701자)입니다. 전체 항목, 건별 목록과 출처는 제2부 아카이브를 참조하십시오.

이번 주 5회 데일리 리포트에 기록된 머지 건수는 총 141건, 신규 오픈 issue는 467건입니다. TileOPs 한 곳이 84건을 차지했고, 메인 저장소는 12건에 불과했으며 그중 4건은 런타임 수정이었습니다.

  • 보안 사건: 11-15 업스트림 Ascend 저장소 CI에 외부 PR로 스크립트가 주입되어 기여자 token이 탈취되었습니다. 4개 저장소에서 동일 스타일의 PR이 나타났으며 전부 종료되어 머지되지 않았고, 공개 내용은 issue #2016을 참조하십시오.
  • TileOPs가 주 전장이 되다: 5회 머지 건수는 15, 18, 12, 23, 16건입니다. manifest가 선언적 파라미터로 업그레이드된 후 pilot 모델의 연산자가 일별로 이행되었으며, Embedding 오머지는 당일 롤백되고 다음 날 재제출되어 머지되었습니다.
  • 감사 파이프라인화: 11-16 호에서 72시간 동안 신규 오픈 issue 406건, 두 계정이 314건을 기여했습니다. 이후 4회는 19, 15, 20, 7건이었으며, 심사 대기열이 한때 102건까지 쌓였습니다.
  • Ascend 패밀리별 적용: DSA와 KDA 각 3종 세트가 같은 날 머지되었고, catlass가 v2.2.0으로 올라가며 fp32 GEMM의 조용한 NaN을 수정했습니다. 11-17에는 약 300개 조합의 dtype 감사를 추가로 진행했습니다.
  • 성능은 선택기 규칙으로 전환: #3045 한 규칙이 302개 형상을 커버했고, 286개가 1.03~2.6배 빨라졌습니다. TopKSelect와 MLA cache 두 건의 미결 과제가 당일 종료되었습니다.
  • 플랫폼 외연 확장: TileFoundry가 같은 날 Metal 타깃과 자동 미분을 출시했으나 둘 다 IR 계층에 머물렀습니다. 별도로 303개 파일의 용어 및 레이아웃 리팩터링이 있었습니다.
  • RISC-V 교차 추진: TVM 노선은 hikari 브랜치를 새로 열어 5건, MLIR 노선은 buddy-opt 기본화와 예제 2건을 머지했습니다. 11-18부터 3회 연속 정체 상태입니다.

이번 주 판단: 주 전장이 두 모니터링 기간 연속 연산자 라이브러리에 머물렀으며, 병목이 개발량에서 리뷰 대역폭으로 이동했습니다. 자동 warp specialization의 배리어 삽입이 일급 리스크가 되었고, v0.1.15는 51일째 정체 중이어서 모든 변경이 다음 tag 밖에 묶여 있습니다.

제2부 · 아카이브

아래는 이번 주 전체 본문으로, 구조와 기준은 지난 위클리 리포트와 동일합니다. 브리핑의 각 판단은 여기에서 건별 근거와 출처를 찾을 수 있습니다.

자료 출처: 본지의 일일 TileLang 커뮤니티 동향 5회(11-16, 11-17, 11-18, 11-19, 11-20). 11-16 호는 주말을 가로지르는 72시간 모니터링 기간(11-13 07:00~11-16 07:00)입니다. 나머지 4회는 24시간씩 연속됩니다. 따라서 5회의 행위 사실 구간은 11-13 07:00~11-20 07:00입니다. 지난 위클리 리포트는 11-13 07:00에 마감되었으며, 이번 호의 시작점은 이와 맞닿아 있습니다. 릴리스일에는 별도로 tile-ai 조직 168시간 점검(30개 저장소, 모니터링 기간 내 push 12건)을 실시했습니다. 이 점검은 push와 버전 상태 확인에만 사용되며, 데일리 리포트에 이미 기록된 사실은 변경하지 않습니다.

편집 설명: 이번 주 주요 뉴스, 핵심 프로젝트 진행, 멀티 백엔드 적응, 생태계와 채택 주체, 커뮤니티 튜토리얼과 활동, 추세 관찰, 부록의 7개 차원으로 구성합니다. 머지 건수, 심사 중 건수, 신규 오픈 issue 건수는 각 회차 데일리 리포트의 GitHub 검색 실측값(is:merged, is:open, created)에서 가져왔으며, 저장소별 메인 브랜치 커밋과 교차 검증했습니다. 5회 머지 건수는 순서대로 30, 30, 20, 38, 23건으로 합계 141건입니다. 신규 오픈 issue는 순서대로 406, 19, 15, 20, 7건으로 합계 467건입니다. 비기본 브랜치의 머지는 건별로 브랜치를 명시하며 기본 브랜치와 합산하지 않습니다. 관련된 비기본 브랜치는 hygon distributed, mlir-ascend mlir-dialect와 harness입니다. 별도로 TileOPs stats와 nightly snapshots가 있습니다.

1. 이번 주 주요 뉴스

  • 업스트림 Ascend 저장소의 CI가 악용되어 기여자 자격 증명 탈취 (11-15 발생, 11-16 공개): 기여자 liggest가 tilelang-ascend에 이슈 #2016을 제기했습니다. 11-15 오전 7시부터 계정 miramar-labs가 PR #2014를 제출했습니다. 해당 PR에는 CI 실행 시 서버 정보를 수집하는 스크립트가 포함되었습니다. 해당 저장소의 CI는 자체 구축 서버에서 실행됩니다. 공격에 노출된 후 공격자는 대량의 정보와 로그인 자격 증명을 빼갔습니다. 그중에는 liggest의 GitHub token도 포함되어 있었습니다. 11-15 오전 9:39부터 11:40까지 공격자는 해당 token으로 liggest를 사칭했습니다. 그는 #2014 아래에 연속으로 18개의 댓글을 게시했습니다. 그는 또한 TileOPs에 채굴 스크립트가 포함된 두 개의 PR(#2902, #2903)을 제출했습니다. 또 SemiAnalysisAI/InferenceX에 동일한 유형의 PR #5086을 제출했습니다. 작성자는 두 채굴 스크립트가 GitHub 자동 검사로 인해 실행되지 않았다고 밝혔습니다. 검색 결과 miramar-labs는 네 개의 저장소에 동일한 스타일의 PR을 제출했습니다. 네 건은 tilelang #4148, tilelang-ascend #2014, tilelang-mlir-ascend #251, TileOPs #2900입니다. 명목상 모두 「캐시 워밍」 또는 「CI 기능 탐지」였습니다. 네 건 모두 종료되었고, 병합된 것은 없습니다. 작성자는 이슈 종료 후 댓글을 추가했습니다. 그는 앞선 설명이 「과장된 측면도 있어 보인다」고 밝혔으며, 계정은 복구되었다고 합니다. 피해 범위는 여전히 작성자 본인의 진술에 근거하며, 아직 제3자 검증은 없습니다. 작성자는 신규 기여자의 PR이 유지관리자 승인을 받은 후에만 자체 구축 서버를 사용하는 CI가 트리거되어야 한다고 제안했습니다. 출처: https://github.com/tile-ai/tilelang-ascend/issues/2016, https://github.com/tile-ai/tilelang-ascend/pull/2014, https://github.com/tile-ai/TileOPs/pull/2902

  • TileOPs가 이번 주 주요 전장이 되어, 5개 기간에 84건 병합, 전체 주 141건의 60% 차지: 5개 기간 병합 건수는 순서대로 15, 18, 12, 23, 16건입니다. 11-18 하루에 23건으로, 베이징 시간 10:17부터 21:50까지 이어졌습니다. 이는 이번 분기 하루 최고 밀도입니다. 11-16 하루 18건은 pilot 모델 인터페이스 정렬 방향이었습니다. 5개 기간의 주된 흐름은 세 가지로 정리할 수 있습니다. 첫째는 manifest의 파라미터 설명 능력 보완입니다. 둘째는 pilot 모델이 실제로 호출하는 연산자를 하나씩 구현하는 것입니다. 셋째는 양자화와 어텐션의 성능 부채를 이슈 종료로 해소하는 것입니다. 메인 저장소는 같은 주에 12건만 병합되었습니다. 그중 네 건은 런타임 버그픽스, 두 건은 버전 및 문서 관련 변경입니다. 출처: https://github.com/tile-ai/TileOPs/pulls

  • 인터페이스가 구현보다 먼저: manifest가 선언적 파라미터 타입으로 업그레이드되고, 이후 연산자별로 이행: 11-16의 #2958은 manifest의 표현 능력을 재작성했습니다. 「고정 텐서와 스칼라만 설명 가능」에서 세 가지 서명 유형으로 확장했습니다: 텐서 시퀀스, 스칼라 또는 텐서 중 택일, 필수이지만 None 허용. 호출 시 입력은 통일적으로 type과 default를 갖는 선언으로 변경되었습니다. 같은 기간 #2967은 pilot 모델의 인터페이스 실측값을 보완했습니다. pilot 모델은 Qwen3.6, DeepSeek-V4-Flash, GLM-5.3-Flash를 가리킵니다. 일곱 개 연산자를 spec-only로 등록하고, 이미 구현된 열다섯 개 연산자에 실제 파라미터를 추가했습니다. 이후 이행은 날짜별로 진행되었습니다. 11-17에는 게이트 RMSNorm(#2984)과 MaskedScatter(#2982)가 병합되었습니다. Embedding 오병합은 같은 날 롤백되었습니다(#2983). 11-18에는 Embedding(#2992), Concat(#2987), 호출자가 cos/sin을 지정하는 RoPE(#2988)가 재제출되어 병합되었습니다. 11-19에는 어텐션 sink(#3038, #3048), FP4 그룹 양자화(#3027), MoE 해시 라우팅(#3036)이 보완되었습니다. 각 제안에는 대조 구현과 벤치마크 행이 포함되었습니다. 대부분의 자체 평가는 여전히 「수용 기준선 미달」입니다. 이는 병합 기준과 성능 기준이 별개의 사안임을 보여줍니다. 출처: https://github.com/tile-ai/TileOPs/pull/2958, https://github.com/tile-ai/TileOPs/pull/2967, https://github.com/tile-ai/TileOPs/pull/2992

  • issue 감사가 「문제 발견」에서 「파이프라인식 문제 생산」으로 변화: 11-16 호 기준 72시간 내에 새로 열린 issue 406건. cn-sys 한 계정이 11-15 저녁 1시간 46분 동안 연속으로 172건을 열었다. 번호는 #4208부터 #4381까지 연속이며, 다른 출처가 섞인 것은 한 건도 없다. ilovexsir는 사흘에 걸쳐 세 차례로 142건을 열었다. 두 사람 합계 314건으로 전체의 7할 7에 해당한다. ilovexsir의 해당 묶음은 다섯 개 batch 수정 PR과 직접 대응한다. 다섯 PR은 #4201부터 #4205까지 같은 분에 열렸다. 이후 네 기간의 신규 issue는 차례로 19, 15, 20, 7건이었다. 규모는 줄었으나 끊기지는 않았다. 11-17에는 또 한 차례 체계적인 dtype 커버리지 감사가 나타났다. 기여자 JeffDing이 1분 안에 연속으로 4건을 올렸고, 30분 후에 5번째(#4391부터 #4395)를 보충했다. 결론은 T.simd의 단항 및 이항 연산자가 컴파일러 내부 호출로 전달되기 전에 dtype을 전혀 검증하지 않는다는 것이다. 225개의 (연산자, dtype) 조합 중 70개가 그대로 통과되었다. 크로스 lane 리덕션 계열 역시 화이트리스트가 빠져 있어 63개 조합 중 27개가 통과되었다. 출처: https://github.com/tile-ai/tilelang/issues/4381, https://github.com/tile-ai/tilelang/pull/4201, https://github.com/tile-ai/tilelang/issues/4391

  • Ascend가 「연산자 보충」에서 「모델 패밀리별 일괄 적용」으로 전환: 11-13 하루 동안 tilelang-ascend에 아홉 건이 머지되었다. DSA 희소 어텐션 세트가 같은 날 적용되었다. 포워드 파이프라인 버전은 DQK를 512+64=576의 단일 GEMM으로 합쳤다. 역방향은 79395마이크로초를 27388마이크로초로 압축했다. topk 확률 질량 리덕션에는 듀얼 스트림을 보충했다. KDA 세트도 같은 날 적용되어 상태 재귀가 전 과정에서 UB에 남는다. catlass는 v1.0.0-6에서 v2.2.0으로 올라갔다. 이번 업그레이드는 그동안 완전히 조용히 있던 결함 하나도 함께 고쳤다. 구버전 CopyL1ToL0A/L0B에는 float 특수화가 없어 fp32 GEMM이 오류 없이 곧바로 NaN 또는 음의 무한대를 출력했다. bitwise 4-in-1은 uint8 PTO 래핑의 꼬리 바이트 범위 초과를 고쳤다. 통제된 실측에서 센티널 0xA5가 0x03으로 덮인 적이 있었다. 출처: https://github.com/tile-ai/tilelang-ascend/pull/1870, https://github.com/tile-ai/tilelang-ascend/pull/1989, https://github.com/tile-ai/tilelang-ascend/pull/2000

런타임 및 실행 경로

  • cython 동적 공유 메모리(#3882, 11-16 병합): 동적 공유 메모리 상한이 원래 init()에서 한 번만 설정되었다. 이 속성은 디바이스별이다. 48 KB를 초과해야 하는 커널은 나머지 디바이스에서 cudaErrorInvalidValue를 보고한다. 수정 방법은 커널마다 _set_dynamic_smem() 도우미 함수를 생성하고 승격된 디바이스를 기록하는 것이다.
  • ROCm HIP 런타임 재사용(#3899, 11-16 병합): PyTorch의 ROCm wheel은 RTLD_LOCAL로 libamdhip64를 로드하여 stub가 찾지 못한다. 수정 방법은 먼저 RTLD_NOLOAD로 이미 매핑된 런타임을 탐지하는 것이다. 이렇게 하면 dlopen으로 두 번째 사본을 만들어 모듈 핸들이 런타임을 넘어가 첫 kernel 시작이 실패하는 것을 피할 수 있다.
  • 부호 없는 버퍼 읽기(#3875, 11-17 병합): CuTeDSL 타깃에서 uint8, uint16, uint32 버퍼에서 읽은 값이 부호 있는 수로 취급되었다. 근본 원인은 MLIR 정수에 부호 비트가 없고 코드 생성이 전역 및 공유 메모리의 모든 접근을 반복자 타입에서 출발하기 때문이다. 작성자는 RTX PRO 6000에서 256개의 uint8 값으로 프로브했다. 다섯 가지 작성법이 메인 브랜치에서 각각 128개의 값을 잘못 계산했다. 수정 방법은 tl.make_tensor가 dtype=을 받아들이고 타입을 뷰에 다시 연결하는 것이다.
  • 레이아웃 자리표시자 변수의 직렬화 간 바인딩 유지(#4410, 11-20 병합): tl.Layout, tl.Fragment, tl.PartialFragment는 프로세스 내 싱글턴 tirx::Var 자리표시자로 인덱스와 스레드 매핑을 표현한다. 판단 기준은 객체 동일성이지 name_hint가 아니다. 레이아웃이 pickle 또는 tvm.ir.save_json을 왕복하면 자리표시자가 재생성된다. 따라서 map_forward_index([7])이 [_i]를 반환하고 OutputShape()이 (32,)를 (_i + 1,)로 계산한다. spawn된 worker에서 주석이 달린 PrimFunc을 다운로드하면 “forward map must be injective”로 실패한다. 수정 방법은 바인딩된 자리표시 Var 참조를 동일한 ObjectGraphSerializer 채널에 포함시키는 것이다.
  • CUDA Tile IR 백엔드 RFC 재제출(#4402, #4403, 11-19): 목표는 TileLang 프로그램에서 CUDA Tile IR을 생성하여 tileiras에 컴파일과 스케줄링을 맡기는 것이다. 레이아웃, 파이프라인, warp 특화 및 명령 선택은 모두 tileiras가 결정한다. 백엔드는 Tile IR이 올바르게 표현할 수 있는 의미론만 변환한다. 변환할 수 없으면 바로 컴파일 오류를 보고하고 해당 프로그램을 거부하며, 기존 CUDA 백엔드와의 완전한 호환을 추구하지 않는다. 이 버전은 이전 #3247의 재작업이다. 리뷰에서 이전 구현에 try-catch가 너무 많고 약 1.85만 줄의 Python으로 pass를 작성했다고 지적했다.

  • Ascend 자동 튜닝 테스트에서 크로스 NPU 프로브 제거(#4401, 11-18 병합): 해당 브랜치는 크로스 NPU 복사를 한 번 수행한다. 일부 Torch-NPU와 CANN 조합에서 이 복사가 NPU 컨텍스트를 중단시킨다. RuntimeError를 캐치한 후 케이스를 건너뛰어도 컨텍스트를 복구할 수 없다. 동일한 pytest 프로세스 내의 후속 무관 케이스들도 연이어 실패한다. 따라서 장애 양상이 실행 순서에 의존한다.
  • 신규 보고 결함: MLA decode 예제에 쓰기 후 읽기 동기화 누락(#4412, 11-19): 보고서는 examples/deepseek_mla/example_mla_decode_ws.py를 지목한다. 오른쪽 warpgroup이 sum_exp_shared를 읽을 때 왼쪽 warpgroup의 쓰기를 대기하지 않는다고 지적한다. 해당 보고서에는 아직 수정 사항이 첨부되지 않았으며 재현 환경도 표시되지 않았다. 이번 호에서는 「보고됨, 처리 대기」로 기록한다.
  • 심사 중 수정: warp 특수화 시 레이아웃 비호환 TMA 승격 건너뛰기(#4413, 11-19): b1367a59에서 sm_90a를 대상으로 하는 파이프라인 GEMM이 로딩 해제되지 못한다. 트리거 조건은 8비트 B tile이 패딩이 있는 swizzled 레이아웃을 사용하는 것이다. A의 로드로 인해 해당 루프가 warp 특수화 자격을 갖추게 된다. 이후 해당 pass가 B의 일반 복사도 TMA로 승격시키지만 LowerBulk가 패딩이 있는 레이아웃을 거부한다. 수정 방법은 후보 TMA 로드의 대상 레이아웃 어노테이션을 개별적으로 검사하는 것이다.
  • 행(hang) 수정 체인(#2896 → #2899 → #2901, 11-15): #2896 병합 후 main의 gpu-smoke가 중단되었다. sliced_pair가 i // wg_rows == bz 조건에서 out_shared를 임시 저장한다. 레이아웃 lowering 후 해당 타일의 절반을 유지하는 consumer warpgroup만 임시 저장 루프를 실행한다. TileLang은 때때로 이 쓰기를 보호하는 배리어를 이 분기에 삽입한다. 해당 배리어는 전체 256개의 소비 스레드를 커버한다. 다른 warpgroup은 절대 도달하지 못한다. 두 그룹이 동일한 배리어의 서로 다른 인스턴스에서 멈춘다. 더 문제인 것은 배리어 위치가 동일한 cache key의 두 컴파일 사이에서 안정적이지 않다는 점이다. CI의 영속 커널 캐시가 불량 빌드를 계속 재생한다. 수정 방법은 임시 저장을 조건 밖으로 이동하여 두 consumer warpgroup 모두 자신의 절반을 쓰도록 하는 것이다.

6. 트렌드 관찰

첫째, 주요 전장이 이미 컴파일러 본체에서 연산자 라이브러리와 스케줄러로 이동했으며, 이 이동은 두 모니터링 기간 연속 성립함. 이번 주 141건 머지 중 TileOPs가 84건을 차지했고, 메인 저장소는 12건에 불과함. 메인 저장소의 12건 중 4건은 런타임 버그픽스, 2건은 버전 및 문서. 지난주 상황도 유사함. 메인 저장소 작업은 회귀 수정에 집중되어 있고, 신규 기능은 더 많이 연산자 라이브러리의 타일, 선택기, 비용 모델 형태로 나타남. 판단 근거는 머지 수뿐 아니라 의존 방향임. TileOPs의 성능 결론은 TileFoundry의 roofline과 스케줄을 인용해야 하는데, 메인 저장소는 이번 주에 이들에게 아무런 새것도 제공하지 않음.

둘째, 감사가 이미 파이프라인화되었고, 병목이 “발견”에서 “리뷰”로 이동함. 11-16期 72시간 내 신규 오픈 issue 406건, 두 계정이 314건 기여. cn-sys의 172건은 1시간 46분 내에 작성됨. ilovexsir의 142건은 다섯 개 batch 수정 PR에 직접 대응함. 이 패턴은 확실히 “결함 발견에서 수정까지”의 주기를 압축하며, 같은 날 issue와 PR이 병존함. 그러나 압력을 리뷰 측으로 전가함. 11-16期 리뷰 중 102건, 머지 30건. 그중 22건의 mlir-ascend 동형 PR은 극소수만이 통과시킬 수 있음. 다음 단계 병목은 발견 속도가 아니라 리뷰 대역폭이 될 것임.

셋째, 보안 경계가 이번 주 유일하게 회피할 수 없는 부정적 사건이 되었으며, 드러난 것은 구조적 문제이다. 자체 구축 CI가 외부 PR에 의해 침투되었고, 개인 token이 도용되었다. 네 개의 저장소에 동시에 동일한 스타일의 PR이 나타났다. 이는 「신규 기여자 PR이 자체 구축 서버 CI를 직접 트리거한다」는 기본 설정이 조직 차원에서 공유되는 위험 면임을 보여준다. 작성자의 처리는 기존 권한 부여 철회, 악성 fork 증거 보존, 자체 구축 CI 서버 보안 처리였다. 제안된 수정 방식은 신규 기여자 PR이 유지관리자의 승인을 받은 후에만 트리거되도록 하는 것이다. 이 조항은 전체 RISC-V 및 AI 컴파일 커뮤니티에도 동일하게 적용된다. 자체 구축 runner의 신뢰 경계는 저장소별로 개별 판단하는 것이 아니라 기본적으로 강화되어야 한다.

넷째, 자동 warp specialization의 정확성이 이미 일급 위험이 되었다. #2896에서 #2901에 이르는 체인이 한 가지를 설명한다. 성능 변경이 동기화 책임을 컴파일러 자동 계측에 넘길 때, 계측 위치가 정확성의 일부가 된다. 그리고 그것은 상위 계층에 불투명하다. 동일한 cache key로 두 번 컴파일하면, 배리어가 분기 안에 놓일 수도 있고 분기 밖에 놓일 수도 있다. 여기에 CI의 영속적 커널 캐시가 겹치면, 간헐적인 잘못된 계측이 고정화되어 안정적 실패가 된다. 이 문제는 현재 구조적 해법이 없으며, 「쓰기 작업을 조건 분기 밖으로 이동」하는 국소적 회피만 있을 뿐이다. 이후 더 많은 타일이 ping-pong을 사용하게 되면, 동일한 유형의 행(hang)이 다시 발생할 가능성이 높다.

다섯째, 플랫폼 경계가 외부로 확장되고 있지만, 모두 IR 계층에 머물러 있다. 같은 날 Metal 타깃과 자동 미분이 도입되었고, 컴파일러는 추론 커널에서 훈련 및 Apple GPU로 확장되었다. 둘 다 실행 가능한 커널을 산출하지는 않는다. 순서는 명확하다. 먼저 인터페이스를 세우고, 나중에 백엔드와 런타임을 보충한다. 같은 주에 TileFoundry는 303개 파일로 용어와 레이아웃 알고리즘을 단일 규격으로 수렴시켰다. 이는 중간 표현을 「구현에서 자라난 것」에서 「먼저 정의하고 나중에 구현하는 것」으로 바꾼 것과 같다. 이런 변경은 단기적으로 리뷰 비용을 증가시키지만, 장기적으로 IR이 외부 백엔드에 의해 올바르게 구현될 수 있는지를 결정한다.

여섯째, 버전이 장기간 릴리스되지 않는 것이 이번 주 모든 진전의 공통된 출구 문제이다. v0.1.15는 09-30에 멈춰 있으며, 이번 주 금요일까지 이미 51일이다. 메인 저장소의 런타임 수정, Ascend의 실행 백엔드 변경, TileOPs의 연산자 보충은 모두 다음 tag가 있어야 다운스트림 배포 패키지에 들어갈 수 있다. 이와 대조적으로 독립 배포판은 이미 앞서 나가고 있다. Sunrise는 0.1.15+sunrise.1.2.1을 출시했고, MetaX는 v0.1.12+musa.5를 준비 중이며, Hygon은 병합식 수정으로 뒤따르고 있다. 세 곳이 각자 릴리스하면서 버전 정렬과 호환성 매트릭스가 새로운 유지보수 비용이 될 것이다.

일곱째, RISC-V 4개 소스 중 이번 주 두 갈래가 각각 한 번씩 진전되었지만, 리듬은 여전히 불연속적이다. TVM 노선은 hikari 브랜치를 새로 열고 K3 이식 검증과 RVV 그리드 데이터를 제시했다. MLIR 노선은 buddy-opt 기본화와 두 가지 예시를 병합했다. 커뮤니티 인덱스 페이지는 처음으로 TVM 측 fork를 수록했다. 그러나 11-18부터 세 기간 모두 조용해졌다. 두 노선의 분업은 이미 명확하다. TVM 노선은 「실행 가능하고 실측 데이터가 있는 것」을 하고 있다. MLIR 노선은 「설계가 있고 예시가 있는 것」에 머물러 있다. 이 라인은 모니터링 기간 단위로 추적할 가치가 있지만, 주 단위로 진척을 계산하기는 적절하지 않다.

검증 설명

  1. 이번 호는 2026년 11월 16일부터 20일까지 5영업일, 5회의 데일리 리포트를 다룬다. 11-16 회차는 주말을 넘는 72시간 모니터링 기간(11-13 07:00 ~ 11-16 07:00)이며, 나머지 네 회차는 24시간 단위로 연속된다. 따라서 행위 사실 구간은 11-13 07:00부터 11-20 07:00까지이다.
  2. 머지 수, 심사 중 수, 신규 오픈 issue 수는 각 회차 데일리 리포트에 기록된 GitHub 검색 실측값(is:merged, is:open, created)을 출처로 하며, 저장소별 main 브랜치 커밋과 교차 검증했다. 5개 회차의 머지는 30, 30, 20, 38, 23건으로 총 141건이다. 저장소별 비중은 TileOPs 84, 메인 저장소 12, TileFoundry 11, MLIR Ascend 8, topa 8, Ascend 저장소 9, Hygon 3, Sunrise 1이다. 나머지는 문서 사이트, harness 브랜치, 야간 스냅샷류 커밋이다.
  3. 기본 브랜치가 아닌 머지는 본문에 건별로 브랜치를 명시했다. mlir-ascend의 머지는 mlir-dialect 브랜치에 반영되며, 해당 main은 11-04 이후 움직이지 않았다. 별도로 1건은 harness에 반영되었다. TileOPs stats와 TileOPs-nightly snapshots에는 각각 여러 건이 있다. 이들 저장소의 main은 해당 기간에 커밋이 없거나 소수였으며, 브랜치 기준으로 조회해야 확인된다.
  4. 성능 수치는 모두 각 PR 본문의 표와 Result: 행에서 인용했으며, 별도 환산은 하지 않았다. 목표 미달 조건(below bar)과 자체 평가 “합격선 미달”인 경우는 원문 그대로 유지하며, 미화하지 않았다.
  5. 보안 사건의 범위는 작성자 자술을 중심으로 한다. 작성자는 issue 종료 후 설명에 “과장된 측면도 있는 것으로 보인다”라고 보충했다. 본 보고서는 이 보충과 검색 측에서 확인 가능한 부분을 함께 기록한다. 확인 가능한 부분은 네 개 저장소의 동일한 스타일 PR이 모두 종료되고 하나도 머지되지 않았다는 점이다. 자술 내용은 제3자 결론으로 간주하지 않는다.
  6. 뉴스 측은 5개 회차 모두 검색 결과가 없었으며, 이번 주 프로젝트 진행 상황을 교차 검증할 외부 보도는 없다. Hacker News와 arXiv의 검색 결과는 동명이거나 일반적인 단어의 노이즈였으며 제외했다.
  7. 수집 측 한계: 이번 주 여러 모니터링 기간의 GitHub 익명 API 할당량이 기간 말미에 속도 제한에 도달했다. 브랜치와 태그 정보는 Atom 구독과 git ls-remote로 재확인했으며, 결론에는 영향을 주지 않았다. 일부 PR의 파일 수와 행 수는 API 반환값이며, diff를 행 단위로 재검증하지는 않았다.
  8. 본 보고서에는 어떠한 로컬 경로, 프록시 주소, 내부망 정보도 포함되지 않는다. 모든 링크는 공개 접근 가능한 주소이다.
