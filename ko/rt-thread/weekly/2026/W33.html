RT-Thread 위클리 리포트 (2026-08-12)

2026-08-12 Kubuds

데이터 출처: 로컬 데일리 리포트(8/11, 8/12) 집계 + GitHub 추가 수집(8/6-8/10 모니터링 기간, rt-thread 메인 저장소 / RT-Thread/env / packages 인덱스) + 교차 모니터링 기간 보도 추가 기록. 설명: 로컬 데일리 리포트 시스템은 8월 11일 K3기기에서 마이그레이션되었으며, 8/6-8/10은 일자별 데일리 리포트가 없어 해당 구간은 GitHub 커밋(committer 시간)과 8/10-8/11 교차 모니터링 기간 보도를 기준으로 하였고, 중복 제거 및 병합을 최대한 진행하였다. 공식 뉴스 API 최신 항목은 여전히 6월 17일(약 2개월 지연)이며, 공식 동향은 GitHub와 제3자 산업 매체로 교차 검증하였다.

1. 커널 및 버전 동향

1.1 dm 디바이스 모델 프레임워크 일주일 집중 병합(이번 주 중점)

날짜: 2026-08-06 ~ 08-08　출처: rt-thread 메인 저장소

RT-Thread 차세대 디바이스 모델(dm) 프레임워크가 이번 주 고빈도 병합기에 진입하여 사흘 동안 실질적인 커밋 십여 건이 반영되었다:

  • 네트워크 측(8/6): dm ethernet 기반 프레임워크 + MACB/DWMAC 컨트롤러 지원; phy 드라이버 개선(v2) 및 RTL8211F 드라이버 신규 추가;
  • 스토리지 측(8/6-8/7): nvme DMA 주소 사용으로 전환(CPU 물리 주소 직접 사용 문제 수정), nvmem DT bits 파싱 수정, DW AHCI(ATA) 지원;
  • 기타 서브시스템(8/6-8/8): thermal 쿨링 정책 업데이트, dfs 파일 시스템 연산자 유형 검사(유형 불일치 예외 방지), RT_BITS_PER_LONG 사용자 정의 가능, ivshmem 가상 머신 간 공유 메모리(가상화 시나리오), graphic 업데이트, ufs 수정, regulator 업데이트, phye Mode/State 및 MIPI D-PHY 타이밍 헬퍼 신규 추가(#11675), clk 워크플로 수정(#11673).

dm 프레임워크는 네트워크/스토리지부터 클록/전원/디스플레이까지 완전한 디바이스 트리 드라이버 체계를 아우르며, 이번 주 병합 속도는 “대규모 드라이버 확산” 단계에 진입했음을 보여주며 RT-Thread의 고성능/가상화 시나리오를 겨냥한 중요한 기반이다.

1.2 NXP BSP 대형 기능 병합: 멀티코어 / HyperRAM / CherryUSB / NETC / etherCAT

날짜: 2026-08-10　출처: rt-thread 메인 저장소 #11672

[BSP][NXP] Add new features of multicore, hyperram, cherryUSB, NETC and etherCAT: NXP 플랫폼 BSP가 멀티코어, HyperRAM, CherryUSB, NETC 네트워크 컨트롤러, 이더넷 및 EtherCAT 지원을 한 번에 보강하였다. i.MX 시리즈 사용자에게는 실질적인 플랫폼 역량 확장이며, 멀티코어와 NETC는 산업/엣지 게이트웨이 시나리오와 직접적으로 관련되고 EtherCAT은 RuyiAI 산업 플랫폼 메인라인과 호응한다.

1.3 Renesas RA6W1 BSP 2단계 “드라이버 완성” 병합

날짜: 2026-08-11　출처: rt-thread 메인 저장소 커밋

“ra6w1 기본 BSP 드라이버 완성”(45개 파일)이 병합되어 Renesas RA6W1(BLE MCU, Cortex-M33)의 ADC, SPI, I2C, PWM, Timer, DMAC, OSPI, QSPI-PSRAM 등 주변장치 드라이버를 보강하였다. 벤더 BSP 2단계 병합 모델의 또 다른 사례: 1차 기본 BSP는 8월 5일 병합되었고, 2단계에서 플랫폼을 주변장치 완비 상태로 보강하였다.

1.4 lwIP DHCPD pbuf 누수 수정

날짜: 2026-08-12　출처: rt-thread 메인 저장소 커밋

[lwip-dhcpd] Fix pbuf leak for oversized requests: lwIP 내장 DHCP 서버의 초대형 요청 시나리오에서 pbuf 프로토콜 버퍼 누수를 수정하여 AP/핫스팟 모드(스마트 홈 게이트웨이, 차량용 핫스팟)의 장시간 운용 안정성을 향상시켰다.

2. 공식 및 커뮤니티 활동

2.1 첫 AI 비행 컨트롤 제품 Edgi-X 정식 출시 및 사전 판매 개시

날짜: 2026-08-10(사전 판매 8월 6일 개시)　출처: EE Times China

RT-Thread 첫 AI 비행제어 제품 Edgi-X가 정식 출시되고 사전 판매를 시작했다. 드론/지능형 비행체 시나리오를 대상으로 하며, RTOS 실시간성, 소프트웨어 패키지 생태계와 AI 추론 능력을 결합한다. 이는 Ruiside가 “운영체제+생태계”에서 “자체 하드웨어 제품”으로 확장하는 중요한 이정표이며, 이미 상용화 단계에 진입했다.

2.2 2026 RT-Thread 대학생 서머 캠프 선발 명단 발표

날짜:2026-08-11(추가 모집)　출처:EE Times China

2026년 RT-Thread 운영체제 대학생 서머 캠프 선발 명단이 확정되었으며, 대학 개발자 양성 채널이 시행 단계에 들어섰다.

2.3 Ruìqíng 산업 플랫폼 Workshop 예고: 8월 27일 상하이

날짜:2026-08-11(행사 8월 27일)　출처:EE Times China

Ruiside는 8월 27일 상하이 “Ruìqíng 산업 플랫폼 Workshop”을 예고했다: 주제는 EtherCAT 실시간 제어와 산업 솔루션 실전이며, 산업 실시간 제어 생태계 보급이 오프라인 실행 단계에 들어선다.

3. 생태계와 툴체인

3.1 Env 툴체인 플러그인 체계: 개발(8/7-8/8)→ 병합(8/12)

날짜:2026-08-07 ~ 08-12　출처:RT-Thread/env PR #284

이번 주 가장 주목할 만한 툴체인 이벤트: Env 플러그인 체계가 개발부터 병합까지 완전히 마무리되었다. 8월 7-8일 env 저장소에 집중 커밋이 이루어졌고(Env plugin lifecycle, CLI plugin 예제, WebUI host와 플러그인 예제, WebUI assets 패키징), 8월 12일 PR #284(창업자 BernardXiong 주도, 90개 파일, +약 9600줄)가 정식 병합되었다:

  • env plugin 하위 명령: 로컬 설치/제거/조회 플러그인, 설치 전 패키지명, 버전, 서명 상태와 권한 선언 표시;
  • epack 플러그인 패키징 형식: 패키징과 빌드 흐름 정의, 내장 예제 플러그인 build-insight-1.0.0, 플러그인 API_VERSION=1 계약 고정;
  • env webui 명령: 로컬 Env WebUI 서버 시작.

Env는 명령줄 도구에서 확장 가능한 플러그인 플랫폼으로 업그레이드되었으며, 시각화 인터페이스, 클라우드 빌드, 서드파티 도구 연동을 위한 표준 인터페이스를 마련했다. 이는 개발자 툴체인의 구조적 업그레이드이다.

3.2 packages 인덱스: 엣지 AI 소프트웨어 패키지 2연속 진입(8/10, 8/11)

날짜:2026-08-10/11　출처:RT-Thread/packages

  • 8월 10일: AIfES 입고(임베디드 머신러닝 라이브러리, MCU급 훈련과 추론 지원);
  • 8월 11일: 경량화 agent 프레임워크 입고([ai/agent]), 같은 날 ch390 네트워크 카드 패키지 작성자 정보 수정.

packages 인덱스는 “엣지 AI” 주선에서 연속적으로 입건되고 있으며, “MCU급 Agent 실행 능력 + 임베디드 ML”의 소프트웨어 스택이 형성되고 있다.

3.3 서드파티 생태계: canopennode-rtt / gdr / h120d-protocol

날짜:2026-08-11/12　출처:wdfk-prog/canopennode-rtt / flespark/gdr / H4ck3rTR/h120d-protocol

  • canopennode-rtt(8/11): 커뮤니티 CANopenNode 통합 패키지(CANopen 산업용 필드버스), 아직 공식 인덱스에 진입하지 않은 서드파티 인큐베이션 프로젝트;
  • gdr(8/11): GDB RTOS helper framework 5회 연속 커밋, RT-Thread mbox/msgq/mempool 객체 추출 및 rtthread help 명령 추가로 GDB에 RT-Thread 스레드 인식 디버깅 기능 부여;
  • h120d-protocol(8/12): Holy Stone H120D 드론 WiFi 프로토콜 리버스 엔지니어링 문서 업데이트, RT-Thread 커널 구조 분석 포함——소비자급 드론 비행제어에 RT-Thread가 대량 채택된 생태계 샘플.

4. 산업 응용 특별 장(산업 / 드론)

4.1 산업 라인: EtherCAT 실시간 제어 + RuiQing 플랫폼 보급

8월 27일 상하이 Workshop(EtherCAT 실시간 제어와 산업 솔루션 실전)은 산업 라인의 핵심 액션; 여기에 NXP BSP의 EtherCAT 지원 신규 추가(1.2), 공식 측의 기존 “RuiQing 산업 플랫폼으로 공업 제어 연구개발 역량 강화”와 아부다비 투자 포럼 등장이 겹쳐, 산업 시나리오는 RuiSaiDe가 현재 명확히 설정한 상용화 메인라인이다.

4.2 드론/비행 지능: Edgi-X 출시 + 생태계 양방향 호응

Edgi-X 정식 출시(2.1)는 “OS 벤더 → 산업용 하드웨어 제품” 경로의 안착을 상징; h120d-protocol 등 드론 리버스 엔지니어링 프로젝트가 지속적으로 활발한 것은 소비자급 드론 시장과 RT-Thread의 결합이 심화되고 있음을 방증한다. 비행 지능 방향의 침투는 지속 추적할 가치가 있다.

5. 요약 및 트렌드 관찰

  1. dm 디바이스 모델 프레임워크가 드라이버 확산 단계에 진입: 일주일간 십여 건의 병합이 네트워크/스토리지/클록/전원/디스플레이/가상화를 포괄, 이번 주 커널 측 가장 두드러진 엔지니어링 신호다.
  2. 툴체인 플랫폼화: Env 플러그인 체계가 개발에서 병합까지의 폐루프(env plugin / webui / epack)를 완성, 개발자 도구가 확장 가능해지기 시작했다.
  3. 엣지 AI 소프트웨어 스택 형성: AIfES + 경량화 agent 프레임워크가 선후로 저장소에 들어오며, MCU급 AI/Agent 역량이 하향 보급되고 있다.
  4. 산업 상용화 양 라인 추진: 산업(EtherCAT/RuiQing Workshop)과 드론/비행(Edgi-X 하드웨어 제품)이 동시에 역량을 집중하고 있다.
  5. 벤더 BSP 2단계 병합 모델 안정화: RA6W1 2차, NXP 대형 특성, NXP는 한 번에 멀티코어/네트워크/EtherCAT을 포함해 적응 품질과 리듬 모두 양호하다.
  6. 한계 설명: 8/6-8/10 구간은 일별 데일리 리포트가 없어 GitHub 커밋을 기준으로 한다; 공식 뉴스 API는 지속적으로 지연(6/17); Google News는 “RT-Thread”에 대한 노이즈가 많아(도박/SEO) 제외했다.
