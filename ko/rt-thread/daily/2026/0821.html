1. 커널 및 버전 동향

1.1 Rust 빌드 통합 체계 완비: 크로스 컴포넌트 빌드 설정 수정 및 STM32 CI 커버리지 추가

날짜: 2026-08-21 (11:17 베이징 시간 병합)　출처: RT-Thread/rt-thread commit 30af7388

모니터링 기간 내 가장 주목할 만한 병합: [rust][tools] Fix Rust build example configuration handling. 커밋 설명에 따르면 이는 Rust 빌드 통합에 대한 체계적인 수정으로, core, applications, components, module 예제 네 계층을 아우른다: 빌드 실패 전파, target 및 feature 처리, 링크 플래그 전달, 예제 설정 의미론 등의 문제를 수정하고, STM32 (stm32f407-rt-spark)에 CI attach 커버리지를 추가했다. components/rust/ 아래의 Cargo.toml, SConscript, core 소스 및 중영문 README 등 여러 파일에 걸쳐 있다. 8월 중순 이후 rust 관련 병합 리듬과 결합해 볼 때, Rust 지원은 여전히 RT-Thread 툴체인 방향에서 활발한 투자 지점이며, 이번 커밋은 Rust 예제의 빌드 정확성을 CI 보호 범위에 포함시켰다.

1.2 libc timegm 월 오버플로 계산 수정

날짜: 2026-08-21 (09:44 베이징 시간 병합)　출처: RT-Thread/rt-thread commit 339bffb7

[fix][libc] fix timegm month overflow calculation: libc timegm 구현에서 월 오버플로 계산 오류를 수정. timegm은 struct tm을 직접 time_t로 변환하는 데 사용되며(로컬 시간대를 거치지 않음), 월(tm_mon)에 범위를 벗어난 값이 있을 때 계산 결과가 잘못되는데, 이 수정은 오버플로 환산 로직을 바로잡는다. libc 측 시간 처리 견고성 수정에 해당한다.

1.3 dfs utimensat 경로 버퍼 누수 수정

날짜: 2026-08-20 (18:30 베이징 시간 병합)　출처: RT-Thread/rt-thread commit 7d1e5515

[dfs] Fix path buffer leaks in utimensat: utimensat(파일 타임스탬프를 설정하는 시스템 콜) 구현에서 경로 버퍼 누수를 수정. dfs 계층이 경로 해석 경로에서 이미 할당된 버퍼에 대한 해제 경로가 빠져 있었는데, 이번에 보완했다. 어제의 memheap 이중 해제 방지와 같은 “결함 수정” 기조를 이어가며, 커널 측은 최근 이틀간 자원 관리와 시간 처리의 소규모 견고성 수정이 주를 이루고 있다.

1.4 Nations Technology N32H 시리즈 BSP 3차 확장: H47X/H49X/H7XX 드라이버 지원 병합

날짜: 2026-08-20(17:32 베이징 시간 머지, PR #11711)　출처: RT-Thread/rt-thread commit 9fce24b6 / PR #11711

[bsp][n32] add H47X/H49X/H7XX driver support(커뮤니티 기여자 OnlyoutzZ 커밋), 60개 파일 변경, 전부 bsp/n32/n32hxxx/libraries/N32_Drivers/drivers/config/ 하위: h47x_48x 및 h49x의 CAN/UART 드라이버 설정 신규 추가, h7xx의 ADC, CAN, DAC, I2C 하드웨어, LPTIM, 펄스 인코더, PWM, SPI, TIM, UART 등 외부 장치 설정 확장. 이는 N32H 시리즈 BSP의 세 번째 머지: 07-22 초판(n32h760zil7-stb 수정 완성 + n32h497zgl7-evb, n32h487zgl7-evb 보드 지원 신규 추가), 08-12 2차(Nsing LCDC 및 SDRAM 드라이버), 이번 3차에서 H47X/H49X/H7XX 외부 장치 드라이버 설정을 완성, 벤더 BSP의 “골격 먼저 머지, 드라이버 나중 보충” 반복 모델에 부합하며, Guoxin Technology H 시리즈(Cortex-M 고연산 모델)의 RT-Thread 생태계 내 적응이 지속 심화되고 있다.

1.5 버전 상태 안정적

날짜: 2026-08-21　출처: rt-thread releases

최신 정식 버전은 여전히 v5.2.2(2025-10-31 릴리스)이며, 모니터링 기간 내 새 release 없음, 프리릴리스 없음. AF_UNIX(08-17), memheap 강화(08-20) 및 오늘 여러 수정 사항은 다음 버전에 통합 릴리스될 것으로 예상된다.

2. 공식 및 커뮤니티 활동

2.1 공식 뉴스 API 여전히 신규 없음, 분류 인터페이스 “분류 데이터 없음” 반환

날짜: 2026-08-21　출처: RT-Thread 공식 뉴스 API

공식 뉴스 API(rt_org 분류)는 여전히 5개의 오래된 항목이며, 최신은 2026-06-17 아부다비 투자 포럼 보도로, 약 2개월 지연되어 개선되지 않고 있다; news 및 activity 분류 인터페이스는 이번에 “분류 데이터가 존재하지 않습니다. 관리자에게 문의하세요”를 반환했다(어제는 빈 값 반환). 공식 정보 출구의 인터페이스 상태에 변화가 생겼으며, 업데이트 리듬은 실제 동향보다 지속적으로 뒤처지고 있다. 8월 27일 상하이 Ruiqing 산업 플랫폼 Workshop(EtherCAT 실전)이 임박했으나, 모니터링 기간 내 새로운 공식 예열이나 정상회의/해커톤/대학 프로그램 공개 정보는 없다.

3. 생태계 및 소프트웨어 패키지

3.1 packages 인덱스 CI 업그레이드: PR 단계에서 Kconfig 검증; LiME-TM 기본 설정 수정

날짜: 2026-08-21(09:24 베이징 시간 머지)　출처: RT-Thread/packages commits

소프트웨어 패키지 인덱스 저장소 모니터링 기간 내 두 건 머지:

  • ci: validate Kconfig from current PR: 소프트웨어 패키지 CI에 “현재 PR에서 Kconfig 검증” 프로세스 신규 추가, 08-14에 이미 지원된 Gitee 저장소 검증과 결합하여 소프트웨어 패키지 인덱스의 입고 품질 기준이 더욱 향상됨(이전에는 머지 후 인덱스에 대해서만 검증);
  • ai: Fix LiME-TM example choice default: 08-19에 새로 입고된 LiME-TM 패키지 예제 기본 설정 수정. LiME-TM은 RT-Thread AI 소프트웨어 패키지 방향의 새 멤버(8월 19일 입고, 어제 이미 보도)로, 당일 바로 설정 수정이 이루어졌으며, 이는 새 패키지 입고 후 빠른 다듬기에 해당한다.

3.2 생태계 관찰: canopennode-rtt 모니터링 기간 내 새 커밋 없음

날짜: 2026-08-21　출처: wdfk-prog/canopennode-rtt

어제 보도된 서드파티 CANopenNode 통합 패키지(wdfk-prog/canopennode-rtt)는 모니터링 기간 내 새 커밋이 없다(최신은 여전히 08-20 11:11 베이징 시간의 SDO 블록 전송 검증, 이미 보도됨). topic:rt-thread 최근 일주일 활발한 저장소의 나머지는 awtk(08-20 문서 개선만), gd32_rt-thread(08-21 다운스트림 미러 동기화), h120d-protocol(08-21 문서 업데이트) 등이며, 모두 특별한 새 내용이 없어 생태계 참고용으로만 다룬다.

4. 산업 응용 특별 장(산업 / 로봇 / 구현지능)

4.1 모니터링 기간 내 새 항목 없음, 최근 3일 트렌드 회고

날짜: 2026-08-18 ~ 2026-08-20　출처: 각 항목 참조

산업 응용 측 모니터링 기간 내 신규 공개 보도는 없으며, 미디어 주류 흐름은 최근 3일 추세를 이어감(어제 상세 보도, 여기서는 회고):

  • Ruiqing 산업 플랫폼 DSMC+FPGA 통신 90MB/s (08-19, EE Times China): Ruiqing파이 RK3506J 산업용 보드 + FPGA 확장 보드, 16비트 DSMC 병렬 버스 + rt_event 이벤트 구동 DMA, 실측 대역폭 90MB/s로 향상, 산업 제어 실시간 데이터 수집 방향 지속 출력;
  • Beningo 2026 RTOS 성능 보고서 참가 (08-19): RT-Thread가 유일한 중국산 오픈소스 RTOS로 8개 참가 명단에 진입;
  • 8/27 상하이 Ruiqing 산업 플랫폼 Workshop 사전 예열 (08-18): EtherCAT 실시간 제어 및 산업 솔루션 실전, 최근 산업 제어 주류 흐름의 최신 착지 활동.

5. 요약 및 트렌드 관찰

  1. 커널 측 “소화기” 지속, Rust 방향 가장 활발: AF_UNIX(08-17), memheap 강화(08-20) 이후, 모니터링 기간 내 3건 병합 중 2건이 libc/dfs 결함 수정; 최대 움직임은 Rust 빌드 통합 시스템화 수정 및 STM32 CI 커버리지 포함, Rust 지원 투자 리듬 명확.
  2. N32H 시리즈 BSP 3기 확장: GigaDevice 생태가 커뮤니티 기여자에 의해 지속 추진, H47X/H49X/H7XX 주변장치 드라이버 구성 완비(60 파일), “먼저 골격 후 드라이버” 모델로 3기 완주.
  3. 소프트웨어 패키지 품질 기반 인프라 업그레이드: packages CI에 PR 단계 Kconfig 검증 신규 추가, 저장소 진입 품질 기준선 전진; LiME-TM 신규 패키지 신속 정비.
  4. 공식 정보 출구 상태 변화 주목 필요: news/activity 분류 인터페이스가 “비어 있음”에서 “분류 데이터 없음”으로 변화, rt_org는 여전히 2개월 지연, 8/27 Workshop 공식 채널 사전 예열 정보 없음, 공식 공개 정보 역량 지속 취약.
  5. 버전 리듬: v5.2.2가 이미 9개월 이상 유지, 최근 다수 수정(AF_UNIX, memheap, libc, dfs, Rust 빌드) 누적, 다음 버전 릴리스 시점 주목할 만함.
