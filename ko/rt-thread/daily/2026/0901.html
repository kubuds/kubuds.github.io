1. 커널 및 버전 동향

1.1 메인 저장소 모니터링 기간 내 PR 4건 머지: MPU 권한 수정, PWM utest, Renesas CAN FD, net/sal 리소스 해제

날짜: 2026-09-01 (09:05-09:39 베이징 시간 머지)　출처: PR #11760, PR #11751, PR #11754, PR #11769

어제 RT-Smart POSIX 호환 배치(PR #11732/#11733, 커밋 13건) 이후, 메인 저장소는 오늘 오전에 PR 4건을 추가로 머지했으며(별도로 clang-format style 커밋 1건 포함), 평일 머지 리듬이 회복되었다:

  • PR #11760 (09:05) [net][sal]: 소켓 생성 실패 시 DFS v2 vnode가 해제되지 않는 문제 수정, 리소스 누수 수정에 해당;
  • PR #11751 (09:16) [bsp/renesas][drivers]: Renesas BSP 드라이버가 구성 가능한 CAN FD 동작 지원, 주변장치 기능 지속 발전;
  • PR #11754 (09:33) [utest][pwm]: 구성 가능한 PWM matrix 테스트 추가, 매트릭스 테스트 정리 및 타임아웃 문제 수정;
  • PR #11769 (09:39) fix[arm][cortex-m4]: MPU 권한 표현 명확화, cortex-M4 커널 MPU 권한 구성 표현 수정.

전일 RT-Smart POSIX 호환 계층을 대상으로 한 대량 머지와 달리, 이번 배치는 커널 세부 견고성에 집중되었다: ARM cortex-M4 MPU 권한, 네트워크 소켓 실패 경로의 리소스 해제, 드라이버 구성 가능화 및 테스트 커버리지이며, 대형 기능 머지는 보이지 않았다.

2. 공식 및 커뮤니티 활동

2.1 공식 뉴스 API 열두 번째 날 연속 신규 없음, 미디어 측 모니터링 기간 내 신규 항목 제로

날짜: 2026-09-01　출처: RT-Thread 공식 뉴스 API

공식 뉴스 API(rt_org 분류)는 여전히 기존 5건이며, 최신은 여전히 2026-06-17 아부다비 투자 포럼 보도로, 열두 번째 날 연속 신규가 없다. gnews 다중 보충 조회(RT-Thread when:3d, RT-Thread 睿赛德 when:3d, 睿擎派 OR 睿擎 when:3d): 영어 조회는 SCALR AI 등 “RT” 분리 단어 노이즈만 적중; 중국어 조회는 어제 이미 수록된 elexcon 2026 참가 예고(EE Times China 08-30 게재)를 적중; Ruiqing 조회는 결과 없음. 미디어 측 모니터링 기간 내 신규 항목 제로이며, 최근 유일한 대외 신호는 여전히 9월 9-11일 선전 elexcon 2026 참가(RT-Thread Ruiside가 AI 하드웨어 “풀 세트”를 전시할 예정)이다.

3. 생태계 및 벤더 적응

3.1 packages: optparse v1.0.0 / v1.0.1 버전 항목 추가, 신구 인터페이스 공존 선택 가능

날짜: 2026-08-31(16:55 병합)　출처: RT-Thread/packages PR #2032

어제 packages는 optparse 소프트웨어 패키지에 대해 파괴적 인터페이스 변경을 롤백하기 위해 v1.0.0 버전 항목을 복원한 바 있다(v1.0.0은 2개 파라미터 인터페이스). 오늘 PR #2032는 v1.0.1 버전 항목을 추가로 보완한다. 두 tag 모두 3개 파라미터 인터페이스 커밋(07a365d)을 가리키며, v1.0.0의 2개 파라미터 인터페이스와 구분되어 사용자는 인터페이스 요구에 따라 소프트웨어 패키지 인덱스에서 해당 버전을 선택할 수 있다. 인덱스 계층의 인터페이스 호환 관리가 “듀얼 버전 공존” 단계에 진입했다.

3.2 생태계 참고: canopennode-rtt 커뮤니티 CANopenNode 통합 패키지 연속 개발

날짜: 2026-08-31 ~ 09-01　출처: github.com/wdfk-prog/canopennode-rtt(문서 사이트 wdfk-prog.space/canopennode-rtt/ 포함)

커뮤니티 저장소(2026-06-30 생성, C 언어)는 RT-Thread에 국제적으로 유명한 오픈소스 CANopen 프로토콜 스택 CANopenNode를 통합하는 것을 목표로 하며, 최근 커밋이 활발하다: 이벤트 기반 메인라인 스케줄링 추가(09-01 08:54), 고해상도 시간 지원 및 kconfig 런타임 구성 메뉴 정리, 기본 객체 사전과 demo 모듈 분리(08-31), RX 규칙을 거친 HDR 필터로 컴파일(08-30), SRDO 생성 J09/B09S 객체 사전 및 MCU 진단 fixture(08-29). 이 패키지는 현재 공식 packages 인덱스와 독립적이며(PR 제출이 확인되지 않음), 향후 공식 소프트웨어 패키지 체계에 진입할지 주목할 만하다. 산업용/차량용 CANopen 통신 시나리오에서 주의를 기울일 가치가 있다.

3.3 생태계 참고: GigaDevice gd32_rt-thread, F503 주변장치 드라이버 및 F207i BSP 업그레이드 병합

날짜: 2026-08-31(19:17 / 19:31 병합)　출처: GD32-MCU-IOT/gd32_rt-thread PR #58, PR #63

GigaDevice 공식 다운스트림 저장소(gd32_rt-thread)는 모니터링 기간 내 원칩 엔지니어에 의해 두 건의 BSP 적용이 병합되었다: PR #58은 gd32f503v-eval에 USART / I2C / SPI / DMA 드라이버를 보강했고, PR #63은 gd32207i-eval BSP를 업그레이드하고 F20x 시리즈 드라이버를 적용했다. 칩 원칩 주도의 BSP 커버리지가 계속 확장되고 있다(최근 2주 동안 305R/407V/470Z/470i/L23x/F527 등 여러 모델 관련 적용이 연속 병합됨).

4. 산업 응용

모니터링 기간 내 신규 항목 없음, 최근 3일 추세는 요약 참조.

5. 요약 및 추세 관찰

  • 커널 측: 메인 저장소의 평일 병합 리듬이 회복되었으며, 이번 배치는 견고성 수정 위주(cortex-M4 MPU 권한, net/sal 소켓 실패 경로 vnode 해제, PWM utest 매트릭스 테스트), Renesas BSP의 CAN FD 구성 가능화가 주변장치 진화를 이어감.
  • 생태계 측: 소프트웨어 패키지 인덱스의 optparse 신구 인터페이스 듀얼 버전 공존 관리가 안착; GD32 원칩의 지속적인 BSP 적용; 커뮤니티 CANopenNode 통합 패키지(canopennode-rtt) 개발 활발, 산업 통신 방향을 추적할 가치가 있음.
  • 공식 측: 공식 미디어 12일 연속 침묵, 다음 대외 창구는 9월 9-11일 선전 elexcon 2026.
  • 최근 3일 추세(08-30 ~ 09-01): RT-Smart POSIX 호환 배치 병합(08-30) → ENV WebUI TypeScript화 및 수정, agent 오디오 프레임워크(08-31) → 커널 견고성 수정 배치(09-01). 메인라인은 RT-Smart 호환 계층 완성 + 공식 툴체인 현대화 + 커널 세부사항 다듬기이며, 뉴스량이 적은 날은 GitHub 저장소 동향 위주.
