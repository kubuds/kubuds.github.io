1.1 Xiaohua Semiconductor HC32 시리즈 BSP 설정 동기화 메인라인 병합 (09-16)

날짜: 2026-09-16 17:54 (베이징 시간, 병합 시간)　출처: PR #11798

Xiaohua Semiconductor HC32 시리즈의 설정 동기화 제안이 모니터링 기간 내 메인라인에 병합되었으며, 규모는 52개 파일, 약 2844행 추가, 720행 삭제, 네 건의 커밋이 각각 시리즈 설정 동기화 및 프로젝트 파일 재생성, 코드 포맷팅, 헤더 파일 포맷 정리 및 시리얼 인터럽트 드라이버 컴파일 오류 수정, rtconfig 롤백 및 포맷팅 무시 목록 조정을 완료했습니다. 구체적 변경 사항으로는 전원 관리 설정에서 웨이크업 타이머 활성화 마스크 삭제, 이름 길이 상한을 24로 조정하고 커널 이름 길이 설정 항목 동기화 등이 있습니다. 해당 제안은 09-11에 리뷰 요청, 09-14에 마지막 수정 라운드 완료, 리뷰에서 병합까지 약 5일 소요되었습니다. HC32 시리즈는 최근 일주일 내 드라이버 확장과 설정 동기화 두 배치 변경이 이미 적용되었습니다.

1.2 STM32 GCC 링커 스크립트 용량 검증 수정 병합, 용량 초과 펌웨어 문제 종료 (09-17)

날짜: 2026-09-17 09:31 (베이징 시간, 병합 시간)　출처: PR #11805, Issue #11124

STM32 각 영역 링커 스크립트의 용량 검증 결함이 모니터링 기간 내 수정 완료 및 병합되었으며, 변경은 110개 링커 스크립트를 포함, 추가 및 삭제 각각 약 659행입니다. 문제 원인은 일부 스크립트가 초기화 데이터 세그먼트로 로드 주소를 지정했지만 해당 세그먼트를 대응하는 읽기 전용 저장 영역에 연결하지 않아, 코드와 상수 자체는 초과하지 않았지만 초기화 데이터 이미지가 중첩된 후에야 초과될 때 링커가 여전히 통과하여 설정 용량을 초과하는 펌웨어를 생성하는 것이었습니다. 수정은 STMicroelectronics 공식 링커 스크립트 방식을 참조하여 영역 귀속을 보완했습니다. 동일 출처 결함 보고는 올해 1월 제출 이후 줄곧 미종료 상태였으며, 이번 수정과 함께 종료되었습니다.

1.3 SDIO 드라이버 등록 해제 메모리 누수 수정 제안 제출, 지난 호 결함 보고 접수 (09-17)

날짜: 2026-09-17 10:01 (베이징 시간, 제출 시간)　출처: PR #11806

지난 호 보고에서 기록된 SDIO 드라이버 등록 해제 결함에 대해 수정 제안이 접수되었으며, 변경은 1개 파일, 6행 추가, 4행 삭제입니다. 기존 로직은 일치하는 SDIO 카드를 찾았을 때만 드라이버 등록 노드를 해제했고, 장치에 카드가 없거나 카드가 일치하지 않으면 노드가 해제되지 않아 반복 등록과 등록 해제 시 메모리 누수가 발생했습니다. 수정 방안은 등록 해제할 드라이버를 확정한 후 현재 일치하는 카드 존재 여부와 관계없이 드라이버 연결 리스트에서 제거하고 노드를 해제하며, 카드가 일치할 때만 드라이버의 제거 콜백을 계속 호출하여 기존 장치 바인딩 해제 절차를 변경하지 않는 것입니다. 결함 보고에서 수정 제안까지 약 이틀이 걸려 처리 속도가 비교적 빠른 편입니다.

1.4 세 건의 소규모 수정 리뷰 진입: UART4 수신 DMA, 블록 디바이스 로그 포맷, 지속적 통합 의존성 (09-17)

날짜: 2026-09-17 10:38 ~ 11:50 (베이징 시간, 커밋 시간)　출처: PR #11808, PR #11809, PR #11807

모니터링 기간 말미에 세 건의 일상적 수정이 리뷰에 진입했다. 첫째는 STM32H7 범용 DMA 설정에 UART4 수신 측 정의를 보충한 것으로, 인스턴스, 요청, 인터럽트 및 클럭 매크로를 포함하며, 이전에는 UART4 수신 DMA를 활성화하면 컴파일이 실패했다. 둘째는 블록 디바이스 파티션 컴포넌트의 로그 형식 지정자와 매개변수 타입 불일치 문제를 수정한 것으로, 일부 32비트 툴체인에서 부호 없는 정수형이 장정수형에 대응하고, 방금 전까지는 단정수형 형식 지정자를 사용하면 형식 경고가 발생했으며, 변경은 출력 문에만 관련되고 파티션 탐지 로직에는 영향을 미치지 않는다. 셋째는 LLVM ARM 지속적 통합 파이프라인에 터미널 정보 라이브러리 의존성을 추가 설치하여 해당 파이프라인의 최근 빌드 실패를 수정한 것이다.

1.5 lwip 2.2.1 프로토콜 스택 지원 제안, 모니터링 기간 내 지속 반복 (09-16)

날짜: 2026-09-16 18:39 (베이징 시간, 최근 업데이트)　출처: PR #11797

네트워크 프로토콜 스택 버전추진 제안이 모니터링 기간 내에 다시 업데이트되었으며, 규모는 여전히 1874개 파일, 약 34.6만 행 추가, 45행 삭제이고, 논의 수는 4건으로 증가했다. 이 제안은 기존 이슈를 수정하고 lwip 2.2.1 지원을 도입하며, 검증 플랫폼은 NXP i.MX RT1180 평가 보드로, 이더넷, 소켓 추상화 계층, 네트워크 디바이스 및 lwip 컴포넌트를 활성화한다. 리뷰 레이블은 컴포넌트이며, 이전에 제3자 메모리 비교 도구가 메모리 사용량 변화를 도입하지 않았다고 판정했다. 만약 병합되면, 메인라인 네트워크 스택 기준선이 2.1.x에서 2.2.x로전진하게 되며, 게이트웨이와 산업용 네트워킹 시나리오의 일반적인 경로에 해당하고, 현재 여전히 리뷰 반복 기간에 있다.

2. 공식 및 커뮤니티 활동

2.1 공식 발표 기사 《동남아시아를 지지점으로, RT-Thread, 고등교육 산학융합 및 오픈소스 생태계 국제화 배치 가속화》 (09-17)

날짜: 2026-09-17 11:20 (베이징 시간, 발표 시간)　출처: EE Times China 집계 항목

집계 소스가 이번 모니터링 기간 내에 공식 기사 한 편을 수록했으며, 주제는 동남아시아를 중점으로 고등교육 산학융합 및 오픈소스 생태계 국제화를 가속화하는 것이다. 공개 채널의 이전 커뮤니티 월간 보고서와 결합하여, 동남아시아 측 추진 방식이 고등교육 기관 양해각서 체결, 교사 워크숍 및 과정 공동 구축임을 확인할 수 있으며, 8월의 주요 활동으로는 말레이시아 오픈 대학과의 협력 양해각서 체결, Infineon 개발 보드 워크숍을 협력 시작 활동으로 삼고, 말레이시아 여러 학교를 방문하여 공동 연구소 방향을 논의한 것이 포함된다. 대외 공개된 고등교육 협력 총량은 이미 200개 학교에 근접했다. 기사 본문 페이지는 사이트 접근 제한으로 확보하지 못했으며, 시나리오와 데이터는 집계 요약 및 기존 공식 채널 정보를 교차하여 설명한다.

2.2 라이브 예고: RT-Thread 및 NXP N947 기반 리모컨 동작 전면 분석 (09-16)

날짜: 2026-09-16 11:50 (베이징 시간, 발표 시간)　출처: EE Times China 집계 항목

공식이 라이브 예고를 발표했으며, 내용은 RT-Thread 및 NXP N947 플랫폼 기반 리모컨 구현 전면 분석으로, 임베디드 고급 방향의 기술 라이브로 포지셔닝된다. N947은 NXP 크로스오버 프로세서 시리즈에 속하며, 그 평가 보드는 이미 메인라인 BSP 지원 목록 내에 있다. 이러한 라이브는 Ruiside 반도체 협력사연합 콘텐츠 운영의 일상적 활동으로, 국제 칩 원제조사와의 협력 홍보 리듬을 관찰하는 단서로 삼을 수 있다.

2.3 커뮤니티 포럼에 기술 기사 두 편 추가: 저장소 계층 관리 및 MQTT 대용량 연결 누수 (09-17)

날짜: 2026-09-17 09:01 / 09:20 (베이징 시간, 발표 시간)　출처: 포럼 기사 64254b1144ae4465, 포럼 기사 46bb8d1c8740c2e5

커뮤니티 포럼 기사 인터페이스가 복구된 후 이번 호에는 당일 기술 기사 두 편이 수록되었다. 첫 번째 글은 서브모듈과 희소 체크아웃으로 펌웨어 저장소를 관리하는 방법을 다루며, 커널, 벤더 라이브러리, 보드 레벨 적응 및 비즈니스 코드의 버전 경계, 작업 공간 경계와 빌드 경계를 분리하는 것을 설명하고, 독립적인 수명 주기와 릴리스 리듬을 갖춘 공용 모듈만이 서브모듈로 분리할 가치가 있다고 주장한다. 두 번째 글은 실기 결함 분석이다. 장치가 초당 5~10킬로바이트의 동시 처리량에서 완전히 연결이 끊어지는데, 원인은 서버가 수신 창을 작게 압박하고 종료 메시지를 보낼 때 소켓 닫기가 진행 중 오류를 반환하는데, 추상화 계층과 상위 컴포넌트는 여전히 성공으로 처리하고 핸들을 해제하여 최종적으로 하위 소켓에 접근할 수 없게 되고 힙 메모리가 킬로바이트 수준으로 떨어진다. 작성자는 기존 전송 잠금으로 닫기 호출을 감싸 우회했고, 30회 회귀 후 자원이 기준선으로 돌아왔다. 두 편 모두 커뮤니티 자발적 산출물로, 장기 실행 장치에 참고 가치가 있다.

2.4 공식 뉴스 인터페이스 28일 연속 신규 없음, 제품 발표 중심은 공식 계정에 남아 있음 (09-17)

날짜: 2026-09-17(확인 시간)　출처: RT-Thread 공식 뉴스 인터페이스

공식 뉴스 인터페이스의 최신 항목 날짜는 여전히 2026-06-17이며, 모니터링 기간 내 신규가 없어 28일 연속 업데이트가 중단되었다. 공식 웹사이트 뉴스 목록 페이지도 마찬가지로 로딩 실패를 반환한다. 이와 대조적으로 공식 웹사이트 몰 측의 Gino Pi 판매 게시물은 모니터링 기간 내 2026-09-17 11:15로 업데이트되었으며, 제품 및 활동 정보는 계속 공식 계정과 몰 채널에서 최초 공개된다. 외부 관찰은 집계 소스와 저장소 상태를 교차 검증해야 하며, 공식 인터페이스는 현재 역사적 기사 인덱스로만 사용할 수 있다.

3. 생태계 및 벤더 적응

3.1 Gino Pi BSP SDK에 JLink 디버그 체인 추가, 50개 프로젝트 동시 보완 (09-16)

날짜: 2026-09-16 18:27 / 18:33(베이징 시간, 커밋 시간)　출처: Studio BSP SDK 저장소

Gino Pi 보드의 Studio BSP SDK는 모니터링 기간 내 JLink 디버그 지원을 추가했으며, 두 건의 커밋은 총 50개 파일, 약 2281줄 추가, 20줄 삭제였다. 방식은 각 예제 프로젝트에 JLink 디버그 시작 구성과 디버거 설정 파일을 생성하고, 중영문 설명 및 프로젝트 가이드 문서를 동시에 업데이트하는 것이다. 이전에 이 SDK의 다운로드와 디버그 체인은 Studio 측 DAP-Link와 MDK 측 CMSIS-DAP 두 가지뿐이었는데, 이번에 세 번째 디버거를 보완하여 JLink를 사용하는 산업 및 양산 검증 팀에 더 친화적이다. 이 SDK는 커널 5.3.0 기반이며 16개의 주변장치 및 애플리케이션 예제 프로젝트를 포함하고, 보드 코어는 GD32H77D로 고성능 그래픽 인터랙션 및 네트워킹 평가 포지셔닝에 속한다.

3.2 RuyiAI 플랫폼 최초 Gino Pi 적응: GD32H77D 개발 보드 전 체인 개봉 즉시 사용 (09-16)

날짜: 2026-09-16 11:50(베이징 시간, 발표 시간)　출처: EE Times China 집계 항목

집계 소스 항목에 따르면, RuyiAI 플랫폼이 Gino Pi 개발 보드를 최초 적응하며 GD32H77D 플랫폼 전 체인 개봉 즉시 사용을 강조한다. RuyiAI 플랫폼의 이전 보드 탑재는 Rockchip RK3506과 RK3562 두 라인이었으며, 이번에 마이크로컨트롤러급 고성능 그래픽 플랫폼으로 확장하여 산업 제어 및 엣지 인터랙션 포지셔닝과 상호 보완적이다.지원된 보드 지원 패키지와 예제 프로젝트는 이미 Studio 측에 준비되어 있으며, 디버그 체인도 같은 모니터링 기간 내 JLink로 보완되었다. 원문 페이지는 사이트 접근 제한으로 확보하지 못했으며, 적응 범위와 기능 목록은 집계 요약과 SDK 저장소 공개 자료로 교차 설명한다.

4. 산업 응용

4.1 모니터링 기간 내 신규 적용 사례 없음, 로봇 방향 침묵 지속 (09-17)

날짜: 2026-09-17(확인 시간)　출처: RT-Thread 공식 뉴스 인터페이스, GitHub org: RT-Thread

모니터링 기간 내 신규 양산 또는 상용 적용 사례가 없으며, 공식 뉴스 인터페이스에도 사례 유형 기사가 없고, 포럼 기사 인터페이스와 집계 소스 역시 산업 응용 유형 콘텐츠가 보이지 않는다. 추적 가능한 시나리오 단서는 여전히 지난 호에 기록된 두 가지다. 오픈소스 대회의 산업 품질 검사 주제는 접수 기간에 있으며, 대학 경진대회 수상작은 지능형 센싱 및 임베디드 단말 방향에 집중되어 있다. 로봇 및 엠바디드 인텔리전스 방향은 이번 호 신규 움직임이 없으며, 최근 2주 리듬과 일치한다.

5. 요약 및 트렌드 관찰

5.1 최근 3일 트렌드 (09-14 ~ 09-17)

  • 기존 결함 정리 단계 진입: 이번 기간의 두 건 주요 병합은 모두 오래 계류된 문제의 마무리였다. STM32 링크 스크립트 용량 초과 결함은 올해 1월부터 8개월간 보류된 끝에 수정과 함께 종료되었고, SDIO 등록 해제 누수는 결함 보고에서 수정 제안까지 이틀밖에 걸리지 않았다. 리뷰와 수정 폐쇄 속도는 지난 기간보다 빨라졌다.
  • 중국산 마이크로컨트롤러 원제조사가 병합 주체: Xiaohua Semiconductor HC32 시리즈 설정 동기화, Nation Technologies N32H 시리즈 드라이버 확장이 최근 사흘간 잇달아 반영되었으며, 중국산 마이크로컨트롤러 원제조사의 적응 보완이 여전히 메인라인 병합의 주요 원천이다.
  • 개발 보드 지원이 구동 가능에서 사용성 중심으로 전환: Gino Pi는 판매 개시 이후 모니터링 기간 내에 JLink 디버깅 경로와 Ruiqing 플랫폼 적응을 동시에 보완했는데, 이는 작업 중심이 하드웨어 출시에서 툴체인과 플랫폼 사용성으로 옮겨졌음을 보여주며 신제품 도입기의 전형적인 리듬이다.
  • 네트워크 스택과 디렉터리 관리 두 장기 과제 여전히 진행 중: lwip 2.2.1 제안은 계속 반복 개선되고 있고, 커뮤니티 측에는 서브모듈과 스파스 체크아웃을 결합한 저장소 계층화 실무 글이 등장했으며, 이는 각각 메인라인 업그레이드와 엔지니어링 조직이라는 두 장기 의제에 대응한다.
  • 공식 인터페이스 약 두 달째 업데이트 중단, 전파 채널 이전 완료: 공식 뉴스 인터페이스는 연속 28일째 신규 항목이 없으며, 제품과 이벤트 정보는 전부 공식 계정, 몰, 포럼 채널에서 최초 발행되고 있어 외부 관찰은 반드시 집계 소스와 저장소 상태를 교차 검증해야 한다.

5.2 한계와 중복 제거 설명

  • 이번 기간 세 건의 뉴스 항목은 모두 집계 소스에서 나왔으며, 원 사이트 페이지는 접근 제한으로 본문을 확보하지 못했다. 그중 Ruiqing 적응의 적용 범위와 동남아 기사의 구체적 데이터는 집계 요약과 공식 SDK 저장소 및 기존 커뮤니티 월간 보고를 교차 설명한 것으로, 원 페이지의 2차 확인은 얻지 못했다.
  • 중복 제거 설명: 지난 기간 보고서의 HC32 드라이버 확장 제안, STM32N657과 N32H 시리즈 병합, env 대버전 릴리스, SDIO 결함 보고, lwip 2.2.1 반복 개선은 모두 2026-09-15와 09-16 보고서에 이미 수록되었다. 이번 기간 신규 내용은 위 두 건의 병합과 네 건의 신규 제안, 두 편의 포럼 기술 글, Gino Pi의 JLink와 Ruiqing 적응이다.
  • 이번 기간 HC32 항목은 지난 기간 보고서의 HC32 드라이버 확장과 동일 시리즈의 서로 다른 제안이며, 본문에서 각각 설명했고 병합하지 않았다.
  • 공식 뉴스 인터페이스는 신규 항목이 없으며, 최신 항목 날짜는 2026-06-17이다.
