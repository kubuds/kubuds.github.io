RT-Thread 데일리 리포트 (2026-08-17)

2026-08-17 Kubuds

모니터링 기간: 지난 24시간 (2026-08-16 11:18 ~ 2026-08-17 11:18 베이징 시간) 출처: RT-Thread 공식 뉴스 API, GitHub (org: RT-Thread / topic: rt-thread), Google News 집계 (zh-CN / en-US), HN 등 (상세 내용은 부록 참조)

1. 커널 및 버전 동향

1.1 WLAN 프레임워크에 WPA3/엔터프라이즈/WAPI/OWE/DPP 보안 모드 플래그 추가 (8월 17일 병합)

날짜: 2026-08-17 (베이징 시간 11:00 병합, 작성자 커밋은 8월 11일, 일괄 병합 모드)　출처: rt-thread 메인 저장소 commit 0823a4b

components/drivers/wlan/dev_wlan.h 보안 플래그 비트가 한 번에 다섯 종류로 확장되었다: WPA3_SECURITY (WPA3), ENTERPRISE_ENABLED (WPA2/WPA3 엔터프라이즈 인증), WAPI_ENABLED (중국 국가 표준 WAPI), OWE_ENABLED (오픈 네트워크 강화, 공공 Wi-Fi 비밀번호 없는 암호화), DPP_ENABLED (Wi-Fi Easy Connect 기기 프로비저닝 프로토콜)이며, 이전에는 WPA/WPA2/WEP/TKIP/AES 비트만 있었다. 이는 WLAN 기기 프레임워크 계층의 API 기능 확장으로, 드라이버가 이를 기반으로 애플리케이션에 현대적 Wi-Fi 보안 프로토콜 기능을 노출할 수 있으며, 구체적인 드라이버 적용은 후속 대응이 필요하다. 작성자 Kai (8월 11일 커밋), 유지관리자 Rbb666이 오늘 11:00 메인 저장소에 병합했으며, 전형적인 일괄 병합 모드에 해당한다.

1.2 [bsp/raspberry-pi] Raspberry Pi 5 BSP 및 BCM2712 DMA 지원 추가 (8월 16일)

날짜: 2026-08-16 19:56 (베이징 시간)　출처: rt-thread 메인 저장소 commit f7258a6

GuEe-GUI 커밋: 라즈베리파이 공용 드라이버를 기기 프레임워크 (DM) 아래로 재구성, Raspberry Pi 5 BSP 추가 (설정 및 문서 포함), BCM2712 및 DesignWare AXI DMA 컨트롤러 지원 병합, channel mask에 따라 BCM2712의 DMA32/DMA40 채널 구분, 컨트롤러 리셋 후 AXI DMA 활성화 비트 복원, DMA 채널 간 AXI 최대 버스트 길이 공유 지원. Pi 5 (BCM2712)는 Raspberry Pi 시리즈가 해당 BSP에 처음으로 적용된 사례로, RT-Thread의 라즈베리파이 하드웨어 지원을 현재 주력 모델까지 끌어올렸다.

1.3 [bsp/rockchip] 플랫폼 및 주변장치 지원 확장 (8월 16일)

날짜: 2026-08-16 19:57 (베이징 시간)　출처: rt-thread 메인 저장소 commit d890866

동일 작성자가 같은 날 커밋: 오디오, 디스플레이, 이더넷, PCIe, PHY, SDIO, UFS, 하드웨어 암호화 및 멀티미디어 가속기 지원을 추가하고 RK3300 및 RK3500 플랫폼 설정과 검증 애플리케이션을 함께 갱신했다. Rockchip 플랫폼이 기초 BSP에서 전체 주변장치 커버리지로 나아가고 있으며, 그중 UFS/PCIe/하드웨어 암호화 등은 중고급 저장장치 및 엣지 게이트웨이 시나리오를 겨냥한다.

1.4 버전 상태 변동 없음

날짜: 2026-08-17　출처: rt-thread releases

최신 정식 버전은 여전히 v5.2.2 (2025-10-31 릴리스)이며, 모니터링 기간 내 신규 릴리스나 프리릴리스 버전은 나타나지 않았다.

2. 생태계 및 툴체인 (오늘의 중점)

2.1 smart-build, ROS 2 크로스 컴파일 지원 병합: rt-smart, 로봇 미들웨어 스택 연결 (8월 17일)

날짜: 2026-08-17 08:07 (베이징 시간)　출처: RT-Thread/smart-build PR #50

BernardXiong이 주도한 PR #50 “Add ROS 2 cross-build and Smart package support”가 오늘 08:07 병합되었으며, 100여 개 파일이 변경되었다 (그중 packages/ros2 디렉터리 63개). 핵심 내용:

  • ament_cmake 크로스 컴파일 지원: ROS 2 패키지와 host 툴킷 그룹 발견, host 의존성 스케줄링, 소스 패치와 C++ 런타임 staging;
  • ROS 2 패키지 스택: ROS 2 코어 패키지 + host SDK + 의존성 레시피(CycloneDDS, console-bridge, fmt, libyaml 등), 고정 버전 소스 + RT-Smart 적응 패치;
  • QEMU aarch64 전송 계층 스모크 타깃: ros2-transport-smoke 애플리케이션/패키지 신규 추가, boards/qemu-virt-aarch64에 연결, 하드웨어 환경 없이 ROS 2 전송 계층 검증 가능;
  • 경량 ipkg 패키지 관리: ipkg 활성화 및 BusyBox dpkg/rpm 기능 비활성화, BusyBox mount/rootfs 런타임 통합 개선;
  • 품질 게이트: pytest 150개 항목 전부 통과; 커널 측 procfs와 시스템 호환성 변경은 별도로 커밋할 것임을 명확히 설명.

의미: 8월 15일 Buildroot 패키지 가져오기에 이어, smart-build가 나흘 만에 두 번째 생태계 규모 도약을 완료했으며, 방향이 “범용 애플리케이션 생태계”에서 “로봇 미들웨어 생태계”로 전환되었다. ROS 2는 현대 로봇/embodied intelligence의 사실상 표준 미들웨어이며, rt-smart가 ament 빌드와 CycloneDDS 지원을 확보했다는 것은 RT-Thread가 공식적으로 ROS 2 임베디드 타깃 플랫폼 대열에 진입했음을 의미한다; QEMU aarch64 스모크 타깃은 8월 15일 QEMU virt 듀얼 아키텍처 준비의 포석을 이어가며 연속 추진 체인을 형성했다.

3. 공식 및 커뮤니티 활동

3.1 공식 뉴스 API 신규 없음

날짜: 2026-08-17　출처: RT-Thread 공식 뉴스 API

공식 뉴스 API 모니터링 기간 내 신규 없음, 최신 항목은 여전히 2026-06-17 아부다비 투자 포럼 보도(약 2개월 지연). 2026 대학생 서머 캠프, RuiyiAI 생태계 관련 공고는 모니터링 기간 내 확인 가능한 신규 없음.

3.2 8월 27일 상하이 Workshop 10일 카운트다운 진입

날짜: 2026-08-17　출처: EE Times China (8월 15일 수록)

8월 27일 상하이 “RuiyiAI 산업 플랫폼 Workshop: EtherCAT 실시간 제어와 산업 솔루션 실전”이 개최 10일 전으로 다가왔으며, 모니터링 기간 내 신규 예열 항목은 확인 불가; 당일 공식 콘텐츠 회수에 주목할 만하다(상세는 산업 응용 전문 장 참조).

4. 산업 응용 전문 장 (로봇 / embodied intelligence / 산업)

  1. ROS 2 지원은 로봇 방향의 상징적 사건: rt-smart + ROS 2(ament + CycloneDDS + QEMU 전송 계층 스모크)는 로봇/embodied intelligence의 미들웨어 수요에 직접 대응한다. 이전 “Dishui Zhihui” 린강 embodied intelligence 생태계 배치, Edgi-X AI 비행 제어는 생태계 측 움직임이었으며, 이번은 툴체인 측에서 실제로 ROS 2 빌드와 전송 계층을 구동시킨 엔지니어링 기반이다; 공식이 후속으로 커널 procfs 동반 변경을 커밋하면 런타임 역량이 완비될 것이다. 향후 공식 ROS 2 예제와 로봇 제조사 적응 사례가 가시화될 것으로 예상된다.
  2. 산업 EtherCAT 주선 불변: RuiyiAI 산업 플랫폼 Workshop 카운트다운 10일, 26.08.06 버전과 3코어 산업용 PC 사전 판매 여운이 여전하며, 모니터링 기간 내 신규 상업화 움직임 없음.
  3. Wi-Fi 보안 프로토콜 비트 보완의 산업적 가치: WPA3/엔터프라이즈급 인증은 산업 게이트웨이, 리테일 단말 등 보안 접속이 필요한 시나리오에 적합; WAPI는 국내 규제 시장 대상; OWE/DPP는 공공 네트워크 경험 대상. 프레임워크 계층 준비 완료 후, 상용 Wi-Fi 드라이버(Realtek/ESP 등)의 구현 후속이 필요하다.

5. 요약과 트렌드 관찰

  1. 툴체인 3일 연속 강화, 방향이 명확히 로봇으로 전환: 8/15 Buildroot 패키지 가져오기 → 8/16 ENV 플러그인 동시성 → 8/17 ROS 2 크로스 컴파일. 3연타 이후 rt-smart 애플리케이션 생태계는 “범용 Linux 생태계(Buildroot)”와 “로봇 미들웨어 생태계(ROS 2)” 두 축을 동시에 커버하며, 공식이 하반기 로봇/embodied intelligence를 rt-smart 주력 방향으로 삼으려는 의도가 명확하다.
  2. ROS 2실현 전략은 실용적이고 점진적: QEMU aarch64 스모크 타깃에서 출발, 커널 측 변경은 별도 커밋으로 단일 병합 리스크를 낮춤; 향후 커널 procfs 동반 커밋과 ROS 2 실제 디바이스 구동 사례를 추적할 것.
  3. 커널 측 BSP 양선 추진: Raspberry Pi 5(BCM2712)와 Rockchip(RK3300/RK3500 주변장치 확장)이 같은 날 병합, DM 드라이버 프레임워크가 주류 개발 보드 플랫폼에서 coverage 확대; RPi 5 편입은 개발자 기반에 직접적 가치가 있다.
  4. WLAN 프레임워크 보안 프로토콜 비트 보완: WPA3/OWE/DPP/엔터프라이즈급/WAPI 플래그 준비 완료, 드라이버 구현을 위한 인터페이스 확보; 상용 Wi-Fi 드라이버의 후속 속도에 주목.
  5. 버전 면 안정, 공식 API 지연 여전, 미디어 측 확인 제한: v5.2.2 불변; 공식 뉴스 API 약 2개월 지연 개선 없음; 이번 모니터링 기간 Google News(zh/en)는 프록시 경유 모두 타임아웃으로 접속 불가(상세는 부록 참조), 미디어 측 확인이 불완전하여 본일 결론은 주로 GitHub 병합 사실에 기반한다.
