RT-Thread 데일리 리포트 (2026-08-18)

2026-08-18 Kubuds

모니터링 기간: 지난 24시간 (2026-08-17 11:18 ~ 2026-08-18 11:18 베이징 시간) 출처: RT-Thread 공식 뉴스 API, GitHub (org: RT-Thread / topic: rt-thread / 메인 저장소 commits), Google News 집계 (zh-CN, 프록시 경유), HN 등 (부록 참조)

1. 커널 및 버전 동향

1.1 커널에 네이티브 AF_UNIX 로컬 소켓 구현 추가 (8월 17일 병합, 이번 모니터링 기간 최대 커널 이벤트)

날짜: 2026-08-17 17:15 (베이징 시간 병합)　출처: rt-thread PR #11681

창시자 BernardXiong이 제출하고 메인테이너 Rbb666이 메인 저장소에 병합한 PR #11681 “Add AF_UNIX sockets implementation”은 총 36개 파일, 순증 약 5700줄로 이번 모니터링 기간 규모가 가장 큰 커널 병합이다. 핵심 내용:

  • SAL에 로컬 프로토콜 패밀리 레지스트리 추가: 기존에는 SAL이 socket 프로토콜 제공자에게 반드시 네트워크 장치 연결을 요구했으나, 이 모델은 로컬 IPC에 적합하지 않았다. 이번에 netdev와 독립된 로컬 프로토콜 패밀리 메커니즘을 도입했으며, 기존 네트워크 장치형 socket 동작은 그대로 유지된다.
  • DFSv2의 S_IFSOCK 노드 지원: tmpfs와 devtmpfs가 소켓 파일 노드를 수용할 수 있게 되어 /dev/log 같은 경로 기반 소켓을 위한 기반을 마련했다.
  • SCM_RIGHTS 디스크립터 전달: DFS 파일 참조 카운트 헬퍼를 추가하여 프로세스 간 파일 디스크립터 전달(sendmsg/recvmsg 보조 데이터)을 지원한다.
  • LWP socket 시스템 콜 변환 확장: sockaddr_un, musl msghdr, ancillary data 및 MSG_CTRUNC 변환 지원을 보완하여 rt-smart 사용자 공간 프로세스가 AF_UNIX를 사용하는 경로를 열었다.
  • 선택적 컴포넌트 components/net/af_unix 추가: SOCK_DGRAM과 SOCK_STREAM, 경로명 기반 bind/connect, socketpair, 블로킹/논블로킹 IO, 송수신 타임아웃, poll/select 준비, shutdown 및 상대방 종료 처리, SCM_RIGHTS 디스크립터 전달을 지원한다.
  • 부속: Kconfig 옵션, SCons 통합, 컴포넌트 문서(README), 7개 utest 케이스(common/ipc/namespace/node/poll/rights 등 약 1800줄 테스트).

동기와 의의: BusyBox syslogd/logger 등 애플리케이션은 경로명 기반 AF_UNIX 소켓(대표적으로 /dev/log)에 의존한다. 기존에는 RT-Thread가 이를 네이티브로 제공할 수 없어 네트워크 스택을 빌려 에뮬레이션할 수밖에 없었다. 이번 병합으로 RT-Thread(rt-smart 포함)는 네트워크 카드에 의존하지 않는 로컬 프로세스 간 통신 채널을 확보하게 되었으며, 이는 8월 17일 rt-smart가 ROS 2 크로스 컴파일을 연결한 데 이어 “사용자 공간 프로세스 모델 + 표준 POSIX IPC” 방향으로 보완된 또 하나의 핵심 인프라이다. 로보틱스/임베디드 AI 시나리오의 다중 프로세스 협업과 시스템 로그 경로에 직접적인 가치가 있다.

1.2 wlan, wifi 명령의 무음 실패 문제 수정 (8월 17일)

날짜: 2026-08-17 14:34 (베이징 시간 병합)　출처: rt-thread PR #11696

kaidegit이 제출한 수정: 장치 모드가 AP에 바인딩되지 않은 상태에서 wifi ap 명령을 실행하면 아무런 오류 없이 바로 실패하여 사용자가 원인을 파악하기 어려웠다. 이번에 모드 검사를 추가하고 실패 시 명확한 로그 안내를 제공한다. 검증 환경은 hpm + esp hosted 보드이다. 사용성 소규모 수정에 해당하며, 전날 병합된 WLAN 보안 모드 플래그(WPA3/엔터프라이즈/WAPI/OWE/DPP)와 함께 WLAN 프레임워크 계층은 최근 집중적인 개선기에 있다.

1.3 버전 상태 변화 없음

날짜: 2026-08-18　출처: rt-thread releases

최신 정식 버전은 여전히 v5.2.2(2025-10-31 릴리스)이며, 모니터링 기간 내 신규 릴리스나 사전 릴리스 버전은 나타나지 않았다. 커뮤니티 학습 프로젝트에 등장하는 “5.3.0” 표기는 개발 브랜치를 가리키는 것으로 정식 릴리스가 아니다.

2. 공식 및 커뮤니티 활동

2.1 2026 RT-Thread AIoT 대회 순위 발표 (8월 17일)

날짜: 2026-08-17 19:17 (베이징 시간)　출처: EE Times China 보도 (Google News 수록 경유)

EE Times China, 《2026 RT-Thread AIoT 대회 순위 발표! 하드코어 AI 프로젝트 총출동, 대상은 누구에게!》를 게재했다. 2026년도 AIoT 대회가 마무리 단계에 접어들며 수상 순위가 공식 발표되었고, 출품작은 AI 프로젝트가 주를 이루었다. 공식 뉴스 API와 클럽 페이지에는 아직 동기화된 공지를 확인할 수 없으며(EET 원사이트 접속 불가, 본문 세부 내용 확장 불가), 전체 순위 명단은 추후 공식 공지를 기준으로 하는 것이 권장된다. 이는 이번 모니터링 기간 내 유일한 미디어 측 유효 뉴스이다.

2.2 공식 뉴스 API 모니터링 기간 내 신규 없음

날짜: 2026-08-18　출처: RT-Thread 공식 뉴스 API

공식 뉴스 API(rt_org 분류)는 여전히 5건의 기존 항목이며, 최신은 2026-06-17 아부다비 투자 포럼 보도로 약 2개월째 개선되지 않고 있다. news/activity 분류 인터페이스는 빈 값으로 반환된다. 8월 17일 AIoT 대회와 같이 미디어가 이미 보도한 이벤트가 공식 API에 동기화되지 않아, 공식 정보 출구의 업데이트 리듬은 여전히 실제 동향보다 현저히 뒤처져 있다.

3. 생태계와 툴체인

3.1 ENV 툴체인에 선택적 온라인 플러그인 마켓 신규 추가(8월 18일 새벽 병합)

날짜: 2026-08-18 00:17(베이징 시간 병합)　출처: RT-Thread/env PR #288

BernardXiong이 주도한 PR #288 「Add optional online plugin market」이 ENV 툴체인(RT-Thread Studio의 커맨드라인 백엔드)에 병합되었다:

  • CLI 기능: rt-env plugin market / market set / market clear 명령이 신규 추가되어, ENV_PLUGIN_MARKET_URL 환경 변수로 설정 파일 내 마켓 주소를 덮어쓸 수 있다;
  • WebUI 통합: 마켓을 설정하면 WebUI에 온라인 플러그인 목록이 표시되며, 로컬 Host API가 마켓 목록·상세·prepare 과정을 프록시한다; 아티팩트 다운로드 후 일회성 upload id를 통해 로컬 인스톨러가 설치를 완료한다;
  • 보안 및 호환 설계: 마켓 미설정 시 동작은 현행과 완전히 동일하며, ‘온라인 플러그인’ 페이지는 숨겨지고 관련 API는 404를 반환한다; ENV는 플러그인 ID나 임의 URL로 직접 설치하지 않는다(다운로드 후 검증하고 설치);
  • 품질: 29개 단위 테스트 통과(test_market / test_env_cli / test_webui_server).

의미: 이는 RT-Thread 공식 툴체인이 최초로 플러그인 배포 채널을 갖추게 된 것이다. 8월 14일 병합된 epack 인터랙티브 스캐폴딩(epack init 마법사)과 8월 13일 플러그인 라이프사이클 문서를 결합하면, ENV는 ‘개발(epack) → 배포/획득(플러그인 마켓) → 설치(일회성 upload id 안전 설치)’의 플러그인 폐쇄 루프를 형성했다. 툴체인 측은 연속 5일째 병합이 이루어지고 있다(8/14 epack 마법사 → 8/15 Buildroot 패키지 가져오기 → 8/16 플러그인 명령 동시성 → 8/17 smart-build ROS 2 → 8/18 플러그인 마켓). 생태계 기반 조성 리듬이 밀도 높다.

3.2 smart-build ROS 2 지원: 모니터링 기간 내 신규 병합 없음

날짜: 2026-08-18　출처: RT-Thread/smart-build

어제 병합된 ROS 2 크로스 컴파일 패키지 스택(PR #50, ament + CycloneDDS + QEMU aarch64 전송 계층 스모크 타깃) 이후, smart-build는 모니터링 기간 내 신규 병합이 없으며 소화 단계에 있다. 향후 커널 측 procfs 부수 변경과 ROS 2 실제 디바이스 사례를 주목할 필요가 있다.

3.3 생태계 참고(비전문 동향)

  • zlgopen/awtk: 8월 17일 고빈도 커밋(pointer cursor / edit 컴포넌트 개선)이 있었으나, 모두 범용 GUI 개선으로 RT-Thread와 전문적 연관은 없다;
  • wdfk-prog/canopennode-rtt: CANopenNode 소프트웨어 패키지(개인 저장소)가 8월 17일 업데이트되었으나, 약한 후보이다;
  • GD32-MCU-IOT/gd32_rt-thread: GD32 다운스트림 저장소로, 8월 18일 정례 동기화되었으며 비공식·비중대 사항이다.

4. 산업 응용 전문 장(로봇 / 임베디드 AI / 산업)

  1. 로컬 IPC 인프라 보강, 로봇 멀티프로세스 아키텍처 수혜: AF_UNIX 병합으로 rt-smart 사용자 공간 프로세스 간 통신이 더 이상 네트워크 스택에 의존하지 않게 되었으며, SCM_RIGHTS 디스크립터 전달과 결합하여 로봇 시스템의 “메인 제어 프로세스 + 센서/액추에이터 서비스 프로세스”라는 전형적인 분해 아키텍처를 지원할 수 있게 되었다. 또한 전일 ROS 2 크로스 컴파일 지원과도 호응한다. ROS 2의 DDS는 네트워크 도메인, 로컬 보조 IPC는 AF_UNIX로 가는 분업이 RT-Thread에서 가능해졌다.
  2. AIoT 대회 마무리, AI 프로젝트가 주류: 2026 RT-Thread AIoT 대회 순위가 발표되었으며, 참가작은 AI 프로젝트가 주를 이루어 커뮤니티 개발자가 “베어메탈/전통 RTOS 애플리케이션”에서 “엣지 AI 애플리케이션”으로 이동하는 지속적인 추세를 반영했다. 전체 명단과 수상 프로젝트 상세는 공식 발표를 기다려야 한다.
  3. 산업 메인라인 불변: 8월 27일 상하이 「Ruiqing 산업 플랫폼 Workshop: EtherCAT 실시간 제어와 산업 솔루션 실전」 카운트다운 9일, 모니터링 기간 내 추가 예열 정보 없음. Ruiqing 산업 플랫폼과 ENV 플러그인 마켓(공업 제어 시나리오 플러그인 배포)의 협력이 주목할 만하다.

5. 요약과 트렌드 관찰

  1. 커널 측: 로컬 IPC가 “무”에서 “유”로: AF_UNIX 네이티브 구현(SAL 로컬 프로토콜 패밀리 + DFSv2 S_IFSOCK + SCM_RIGHTS)은 이번 모니터링 기간 최대 기술 이벤트로, RT-Thread가 POSIX 호환과 프로세스 간 통신 능력에서 실질적 진전을 이루었음을 표시하며 rt-smart 사용자 공간 노선과 직접 맞물린다.
  2. 툴체인 측: 공식 플러그인 배포 채널 0에서 1로: ENV 온라인 플러그인 마켓이 병합되어 epack 스캐폴드와 함께 개발-배포-설치 폐루프를 형성했다. 향후 Studio 플러그인 생태계의 공급 방식이 변화할 수 있다.
  3. 공식 정보 출구 지연 여전, 미디어 측 검증 정상화: 공식 뉴스 API는 여전히 약 2개월 지연되어 AIoT 대회 순위 같은 이벤트는 제3자 미디어로만 확인 가능하다. 이번 모니터링 기간 Google News는 프록시를 통해 접근이 복구되었으며(어제는 타임아웃), 미디어 검증 완전성은 어제보다 향상되었다.
  4. 로봇 방향 연속 동작 유지: 8/17 ROS 2 크로스 컴파일 → 8/18 AF_UNIX 로컬 IPC, 이틀 내 로봇/멀티프로세스 아키텍처와 직접 관련된 인프라 두 건이 병합되어 공식 하반기 주력 방향이 더욱 명확해졌다.
  5. 버전 면 안정: v5.2.2 불변, 커널 대기능(AF_UNIX)은 master에 먼저 병합되는 방식으로 다음 버전 릴리스에 포함될 예정이다.
