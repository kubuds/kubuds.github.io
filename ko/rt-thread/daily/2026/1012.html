1. 커널 및 버전 동향

1.1 네트워크 스택 보안 수정: DHCP 서버 옵션 경계 검사 병합, #11323 종료(10-10)

날짜: 2026-10-10 17:20(병합 시간)　출처: PR #11858, Issue #11323

DHCP 서버 옵션 파싱의 버퍼 경계 검사 제안(#11858, 단일 파일 +63/-33, 두 건의 커밋 — 경계 검사 및 clang-format 정리)이 메인테이너에 의해 메인라인에 병합되었으며, 결함 티켓 #11323(옵션 파싱 시 데이터 패킷 버퍼 범위 초과 읽기, 보안 연구자에 의해 보고됨)이 이에 따라 종료되었다. 수정은 옵션 파싱 전에 경계 검증을 추가하여 범위 초과 읽기 경로를 제거한다; 해당 사안은 10-08에 개설되어 연휴 이후 대기열 소화를 거쳐 병합 위치에 진입했으며, 모니터링 기간 내 네트워크 측 첫 보안类 수정이다.

1.2 STM32 전 라인 BSP 스택 8바이트 정렬 수정 병합(10-10)

날짜: 2026-10-10 17:20(병합 시간)　출처: PR #11841, Issue #7527

전 라인 STM32 BSP 스택 정렬 수정 병합(#11841, 작성자 avm1234567, 110 파일 +220/-220): 각 BSP 링커 스크립트와 템플릿의 .stack 섹션이 ALIGN(4)에서 ALIGN(8)로 통일 변경되어 ARM AAPCS의 공용 함수 경계에서의 스택 포인터 정렬 요구를 충족한다. 수정은 2023년 5월에 개설된 결함 티켓 #7527(전 라인 STM32 링커 스크립트 문제; 해당 티켓은 현재까지 열린 상태이며 이번 병합으로 자동 종료되지 않음)을 인용한다.

1.3 C++ 전역 생성 호환성 수정 병합: cplusplus_system_init에 .init_array 경로 보완(10-11)

날짜: 2026-10-11 16:11 (머지 시간)　출처: PR #11856, Issue #11778

C++ 런타임 호환 수정 머지 (#11856, 작성자 cms19859230182-lang, 4개 파일 +60/-6): 최신 GCC는 C++ 전역 생성자를 .init_array 섹션에 배치하지만, 기존 초기화 흐름은 ctors_start/ctors_end 구간만 스캔하여 해당 섹션이 병합되지 않은 일부 BSP에서 생성자가 누락되는 문제가 발생했다. 수정은 __init_array_start/__init_array_end(약한 심볼 선언)를 추가로 처리하고, 이미 ctors 구간에 포함된 중복 항목은 건너뛰도록 했다. 관련 결함 티켓 #11778(다수 BSP의 C++ 자동 생성자 지원 이상)은 종료되었다.

1.4 USB CDC VCOM 링 버퍼 별칭 결함 수정 머지, #11739 종료 (10-11)

날짜: 2026-10-11 17:37 (머지 시간)　출처: PR #11770, Issue #11739

USB CDC 가상 시리얼 수정 머지 (#11770, 작성자 Finder16, 단일 파일 +47/-6, 커밋 2건): 기존 구현은 내장 링 버퍼를 serial_rx에 직접 연결했는데, Serial V2가 해당 포인터를 시리얼 FIFO 구조로 해석했다. 링 버퍼가 우연히 첫 번째 멤버여서 겉으로는 동작하는 것처럼 보였지만 rx_cpt, rx_timeout 등의 필드가 실제로는 어긋나 있었다. 수정은 규격에 맞게 연결하고 VCOM 폴링 수신 지원을 추가했다. 해당 건은 08-29에 개설되어 여러 차례 리뷰를 거쳐 메인라인에 머지되었고, 결함 티켓 #11739는 종료되었다.

1.5 utest 성능 테스트 클럭 의존성 수정 머지 (10-11)

날짜: 2026-10-11 15:59 (머지 시간)　출처: PR #11813

테스트 프레임워크 수정 머지 (#11813, 작성자 CYFS3, 2개 파일 +8/-1): utest 성능 테스트의 고정 클럭 타이밍 의존성을 수정하고 테스트 빌드 가드를 강화하여 다양한 보드 및 시뮬레이션 환경에서의 오탐을 줄였다.

1.6 RISC-V 벡터: vstart 복원 순서 수정 제안 리뷰 진입 (10-10 ~ 10-11)

날짜: 2026-10-10 13:37 ~ 10-11 17:15 (생성 및 업데이트)　출처: PR #11861, Issue #11786

RISC-V 벡터 컨텍스트 수정 제안 리뷰 진입 (#11861, 작성자 PiyushPatle26, 4개 파일 +187/-5): 기존에는 RESTORE_VECTOR가 vsetvl 이전에 vstart를 복원했지만, 벡터 구성 명령이 이를 0으로 초기화하여 재시작 인덱스가 유실되었다. 수정은 복원 동작을 구성 명령 이후로 이동하고, qemu-virt64-riscv에 0/비0 vstart와 vl, vtype, vcsr를 커버하는 회귀 테스트 케이스(어셈블리 프로브 + C 케이스)를 추가했다. 유지보수자는 10-11 리뷰에서 수정 방식이 올바름을 확인하고, 테스트 동시성 문제를 먼저 해결하고 검증 근거를 보강할 것을 권고했으며, 작성자는 당일 수정 커밋을 푸시했다. 동일 작성자가 추진하는 OSPP 2026 의제 “RISC-V 지연 FP/RVV 컨텍스트 스위칭”(#11786) 구현 계획도 기간 내 동기화되어 업데이트되었다.

1.7 netdev ping 통계 0으로 나누기 결함 담당자 지정, 수정 제안 신규 개설 (10-11)

날짜: 2026-10-11 22:10 ~ 23:05 (담당자 지정 및 제안 시간)　출처: Issue #11852, PR #11862, PR #11853

netdev ping 결함의 수정 경과가 기간 내에 뚜렷하게 진전되었다: 결함 티켓 #11852(10-05 보고, 목적지 도달 불가 시 received가 0이 되어 평균값 나눗셈이 x86 SIGFPE / Cortex-M 0으로 나누기를 유발하여 shell 스레드를 종료시킴)는 10-11 저녁 기여자 ymj0440이 댓글로 담당을 지정받고 즉시 제안 #11862(단일 파일 +1/-1)를 개설했다. 이전의 동종 제안 #11853(작성자 r3wretrhy, 10-06 개설)은 10-07에 리뷰 통과(LGTM)되었으나 아직 머지되지 않았다. 두 건이 병행 중이며, 유지보수자가 하나를 선택할 예정이다.

1.8 Next RISC-V 대규모 리팩터링 제안 모니터링 기간 내 재차 갱신 (10-10)

날짜: 2026-10-10 19:18 (최신 커밋 시간)　출처: PR #10320

대규모 리팩터링 제안 「Next RISC-V」 (#10320, 작성자 GuEe-GUI, 166개 파일 +15175/-2614)가 모니터링 기간 내 다시 갱신되었다: 헤드 커밋이 「[libcpu][risc-v] Refactor the RISC-V architecture port」로 업데이트되었으며, 10-08 리베이스 이후 또 한 번의 푸시이다. 제안의 누적 코멘트가 이미 100건에 달했고, 통합 범위는 S-mode RT-Thread / RT-Smart, Sv32~Sv64 MMU, AIA / CLIC / PLIC 인터럽트 컨트롤러, T-Head 플랫폼 병합 등을 포함하며, 여전히 리뷰가 진행 중이다.

1.9 리뷰 대기열 두 건 후속: #11787 CI排查, #11815 커밋 갱신 (10-10 ~ 10-11)

날짜: 2026-10-10 ~ 10-11 (갱신 시간)　출처: PR #11787, PR #11815

리뷰 대기열에서 두 건을 후속 추적한다: 첫째, Eclipse 타깃 생성 스크립트의 숨김 디렉터리 제외 제안 (#11787)은 메인테이너가 10-11에 CI 오류를 지적한 후, 작성자가 당일 밤排查를 완료했다——실패 원인은 파이프라인 환경에 scons 명령이 없기 때문이며, 제외 로직 자체와는 무관하다; 둘째, lwip 세그먼트 매크로 스위치 제안 (#11815)의 작성자가 10-10에 세 건의 커밋을 갱신하여, PBUF_RAM 여유분 설정 가능화와 리스 제거, 부팅 오류 처리 수정을 포함시켰다.

공식 뉴스 인터페이스 (rt_org 분류)가 반환하는 아카이브 원고의 최신 항목은 여전히 2026-06-17이며, 모니터링 기간 내 신규 없이 53일 연속 업데이트가 중단되었다; 제품 및 활동 정보는 계속해서 위챗 공식 계정, 커뮤니티 포럼, GitHub 채널을 통해 최초 공개된다.

2.1 睿赛德, 커뮤니티 9월 회고 월간 보고서 발표 (10-11)

날짜: 2026-10-11 10:00 (발표 시간)　출처: EE Times China 원문 (집계 항목)

睿赛德가 커뮤니티 9월 회고 월간 보고서를 발표했으며, v5.3.0 릴리스와 하드웨어 생태계를 두 가지 주축으로 삼았다: 버전 측면에서는 Rust 컴포넌트, 디바이스 트리 (DM), DVFS, VirtIO 1.2 지원 및 Raspberry Pi 5, 玄铁 C908X 등의 신규 BSP를 기록했고; 하드웨어 측면에서는 Gino Pi (GD32H77D)의 예열—판매—적용 3단계 도약과 Titan Mini (RA8P1) OpenMV 5.0.1 업데이트를 추적했다. 프로젝트 데이터: 9월 커밋 57회 / 20명 기여자, 메인라인 개발 버전 v5.3.1; 「최근 동향」에서 RISC-V 지연 FP/RVV 컨텍스트 스위칭 의제가 커널 메인테이너의 응답을 받은 것 (#11786)을 동시 수록했으며, 이 모니터링 기간의 #11861 제안과 같은 맥락이다.

2.2 포럼 토론: 「rtthread가 zephyr의 일부 특징을 참고할 수 있을까」 지속 활발 (10-11)

날짜: 2026-10-11 09:22 (인터페이스 타임스탬프)　출처: 포럼 게시글 37b351dfb3690ab5

포럼 토론글 「rtthread가 zephyr의 일부 특징을 참고할 수 있을까」가 모니터링 기간 내 계속 상호작용을 받았다 (10-11 09:22 갱신): 게시글 작성자는 RT-Thread Studio 사용 경험에서 출발하여 Zephyr의 경량화 접근법을 참고하고 GUI 설정의 유지보수 부담을 줄일 것을 제안했다. 포럼 인터페이스는 답글 본문을 제공하지 않으므로, 이번 호에서는 활성도만 기록한다; 해당 게시글은 이전에 이미 두 차례 갱신을 촉발했다 (10-09, 10-10).

3.1 RT-Thread Studio: SDK 인덱스에 小华半导体 세 가지 보드 BSP 항목 추가 (10-10)

날짜: 2026-10-10 11:34 (커밋 시간)　출처: Studio sdk-index 커밋 47693f18

SDK 인덱스에 XHSC 보드 레벨 항목 추가 (커밋 47693f18, 4개 파일 +52/-1): Board_Support_Packages/XHSC 아래에 HC32F467, HC32F4A2, HC32F4A8 세 칩의 XHSC EV 평가 보드용 SDK BSP 항목을 생성하고 인덱스에 등록했으며, 이로써 세 칩이 RT-Thread Studio 보드 지원 시퀀스에 진입했다. Studio의 다른 저장소는 모니터링 기간 내 새로운 푸시가 없었다.

3.2 벤더 다운스트림: GD32G553 DMA 제안 리뷰 대응 커밋, CI 전체 통과 (10-10)

날짜: 2026-10-10 16:41 ~ 16:59 (커밋 및 CI 시간)　출처: GD32 다운스트림 PR #72

GD32G553 DMA 지원 제안(#72)은 모니터링 기간 내 리뷰 대응을 완료하고 CI를 수정했다: 작성자 5JingYang이 커밋 한 건을 추가하여(10-10 16:41) G5x3 시리즈 DMA 지원을 F50x/H7xx 기존 패턴에 맞추고 리뷰 의견을 처리했으며, 제안은 현재 4개 커밋, 13개 파일, +1082/-167이다. 이전 gd32_arm 타깃 컴파일 실패는 해결되었고, 컴파일 봇은 10-10에 두 차례 32개 GD32 BSP 전체 컴파일 통과를 보고했다(10:55, 16:59). 제안은 열린 상태로 머지를 기다리고 있다.

4. 산업 응용

4.1 커뮤니티 연구 프로젝트: K230 + RT-Thread Smart 주방 화재 감지 프로토타입 인수인계 문서 업데이트 (10-11)

날짜: 2026-10-11 18:57 (푸시 시간)　출처: 1nuoiscute/SRTP-K230-Fire-Guardian

커뮤니티 연구 프로젝트 「SRTP K230 Fire Guardian」이 인수인계 문서를 업데이트했다: 이 프로젝트는 주방 시나리오를 대상으로 한 대학생 연구 프로토타입으로, K230이 비전 노드(화염 객체 감지)를 담당하고 RT-Thread Smart가 보드 측 제어, 다중 센서 융합 및 적응형 연동을 담당한다. 이번 커밋은 기본 브랜치 진입점을 전체 개발 기록 브랜치로 지정하고, 보드 측 베이스라인과 검수 상태를 요약했다: 비전 노드와 KEY2 컨트롤러의 보드 측 아이덴티티는 검수 기록이 있으며, KEY1 패널 커버리지와 장시간 안정성은 아직 해결되지 않았고, 보드 측 관심 영역(ROI) 기능은 아직 구현되지 않았다. 프로젝트는 연구 일정에 따라 중간 기록을 계속 공개하고 있다.

5. 요약 및 트렌드 관찰

5.1 최근 이틀 트렌드 (10-10 ~ 10-12)

  • 머지 리듬 회복: 모니터링 기간 내 다섯 건의 머지가 집중적으로 반영되었다(DHCP 경계 검사, STM32 스택 정렬, C++ .init_array, USB VCOM, utest). 네트워크 및 런타임 정확성 수정 비중이 높으며, 그중 두 건은 장기 결함 마무리였다.
  • RISC-V 방향 가열: vstart 수정 제안이 리뷰에 진입하고 QEMU 회귀 케이스가 보완되었으며, OSPP 2026 지연 FP/RVV 안건이 동시에 추진되고 있다. Next RISC-V 대규모 리팩터링이 다시 갱신되어, RISC-V는 커널 측에서 가장 활발한 방향 중 하나가 되었다.
  • 커뮤니티 대응 체인 가속화: ping 0으로 나누기 결함이 보고(10-05), 리뷰 통과(10-07)에서 새 기여자의 인수 및 두 번째 안 제출(10-11)까지 약 일주일 만에 완료되었으며, 두 안이 병렬로 머지 대상 선별을 기다리고 있다.
  • 생태계 측 소폭 진전: Studio 인덱스에 XHSC 보드 세 종이 추가되었다. GD32 대규모 변경은 리뷰 대응 후 CI가 전체 통과로 전환되어 머지 직전 마지막 단계에 진입했다.
  • 공식 채널 리듬 불변: 커뮤니티 월간 리포트는 정상 발행되었으며(9월 회고), 뉴스 인터페이스는 제53일까지 침묵이 지속되고 있다.

5.2 한계 및 중복 제거 설명

  • 6개 도시 순회 오프라인 이벤트의 10-10 매체 재홍보 기사(EE Times China)는 09-27 공식 발표의 후속으로, 회차 및 등록 정보는 09-28자에 이미 수록되었으므로 새로운 정보가 없어 중복 전개하지 않는다.
  • 포럼 zephyr 토론 게시글은 모니터링 기간 내 타임스탬프 갱신(10-11 09:22)에 해당하며, 인터페이스가 답글 본문을 제공하지 않았다. h120d-protocol 저장소(10-11 푸시)는 문서류 업데이트로 관례에 따라 수록하지 않는다.
  • EE Times China 원사이트 직접 접속이 제한되어, 월간 리포트 요점은 원문 페이지를 열람하여 정리했다. 6개 도시 순회 기사는 이미지형 페이지로, 축자 대조하지 않았다.
  • Google News 중국어 측 4건 적중 중: 월간 리포트와 순회 기사는 상기 참조. 「공업박람회 Workshop 마지막 좌석」 기사(10-09)는 이전 호에 이미 수록되었다. 「x86, Arm 및 RISC-V 산업용 엣지 아키텍처 비교」 기사는 RT-Thread 주제가 아니므로 수록하지 않는다. 영어 측 유효 신규 항목 없음.
  • HN 모니터링 기간 내 관련 논의 없음. 공식 뉴스 인터페이스와 공식 웹사이트 뉴스 목록 페이지는 계속 침묵 중이다(프런트엔드 동적 렌더링으로 직접 열람 불가).
