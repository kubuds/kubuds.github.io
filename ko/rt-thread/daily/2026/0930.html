1. 커널 및 버전 동향

1.1 Next RISC-V 아키텍처 리팩터링 제안, 창립자의 병합 추진 확보—제출자가 밤새 리베이스 갱신 (09-29 ~ 09-30)

날짜: 2026-09-29 21:09 (창립자 코멘트) ~ 09-30 00:01 (최신 커밋)　출처: PR #10320

수개월간 보류되었던 메인 저장소 RISC-V 아키텍처 리팩터링 제안 「Next RISC-V」 (#10320, 171개 파일, +15018/-3490)가 모니터링 기간 내 명확한 추진 신호를 맞이했다: 창립자 Bernard Xiong이 09-29 21:09에 「이 PR, 최근에 병합할 수 있겠죠, 동시에 일부 riscv soc에서도 디바이스 트리를 열어보는 시도를 해봅시다」라고 코멘트하며 메인테이너와 제출자를 지목해 후속 조치를 요청했다. 이후 제출자 GuEe-GUI는 해당 제안을 그날 밤부터 다음 날 새벽까지 연속 3회 갱신 기록 (21:22, 23:54, 00:01, 포매팅 및 메모리 비교 파이프라인도 함께 재실행)을 트리거했으며, 최신 head 커밋 「Refactor the RISC-V architecture port」는 09-30 00:01에 현재 메인라인 최신 커밋 dc8aaa73f 위로 다시 리베이스되었다. 방안 요점: ISA 관리 인터페이스, RV32E/32I/64I 통합, CBOM 기반 캐시 처리, Sv32~Sv64 MMU 및 SVPBMT, M/S 모드 CSR 작업 병합, SMP, AIA (APLIC/IMSIC), CLIC, ACLINT/CLINT, PLIC, 디바이스 트리 (DM) 지원, T-HEAD 벤더 코드 병합, qemu-virt64-riscv64 디바이스 트리 이식 및 비 0번 코어에서의 부팅 등; 계획 목록은 S 모드 RT-Thread, RT-Smart 및 디바이스 트리 경로가 완료 검증되었음을 보여주며, 나머지 조합 (M 모드, MMU 없음 등 포함)은 여전히 진행 중이다. 해당 제안은 2026-05 제출 이후 누적 리뷰 코멘트 74건을 기록했다.

1.2 커널 calloc 오버플로 수정 제안, 리뷰 통과 (09-29 ~ 09-30)

날짜: 2026-09-29 22:34 (제출) ~ 09-30 08:30 (LGTM 획득)　출처: PR #11848

기여자 luchenxu73가 커널 수정 #11848 (단일 커밋, 3개 파일, +57/-3)을 제출했다: rt_calloc 할당 시 count×size 오버플로 여부를 검사하지 않아, 초과 시 결과가 랩어라운드되어 할당과 제로 초기화 불일치의 범위 초과 위험이 존재한다; 수정 방안은 할당 크기를 사전 계산하고 초과 시 할당을 거부하는 것이며, 변경은 include/rtdef.h, src/kservice.c 및 메모리 유닛 테스트 src/utest/mem_tc.c (새 테스트 케이스 추가)를 포함하고, 검증 플랫폼은 qemu-vexpress-a9이다. 해당 제안은 09-30 오전 08:30에 커뮤니티 리뷰 「LGTM」을 통과했으며, 모니터링 기간 내 가장 빠르게 추진된 신규 제안이다.

1.3 드라이버 및 BSP 수정 제안 3건 집중 제출: ofw 해시 범위 초과, ESP32-C6 SPI, ESP32-C3 링커 스크립트 (09-29)

날짜: 2026-09-29 20:11 ~ 21:53　출처: PR #11845, PR #11846, PR #11847

09-29 저녁 약 한 시간 반 동안 커뮤니티는 수정 제안 세 건을 집중적으로 제출했으며, 모두 테스트 증거를 첨부했으나 아직 리뷰를 기다리고 있다. 첫째(#11845)는 디바이스 트리(ofw) phandle 해시 테이블 범위 초과 수정이다. 항목 수 할당은 범위의 차이로 계산했지만 조회 인덱스는 phandle과 시작 값의 차이로 계산하여, 범위 상한에 접근할 때 범위를 초과하게 되었고 확장 시 초기화 위치에서도 시작 값을 빼지 않았다. 수정은 항목 수에 1을 더하고 확장 시 이전 테이블 끝에서부터 새 영역을 초기화하는 것이며, 작성자는 GCC에 AddressSanitizer/UBSan을 적용하여 6개 케이스의 함수 수준 검증을 완료했다(시작 phandle을 1, 5, 128로 설정, 추가로 상한 128에서 256으로 확장 테스트). 둘째(#11846)는 Espressif ESP32-C6의 요청 시 컴파일 SPI이다. BSP_USING_SPI 선택 후 IDF SPI master에 연결하고, 공유 ESP 드라이버가 전송 바이트 수를 반환하지 않는 문제와 칩 선택 핀 값 설정 문제를 수정했으며, 설정이 비어 있을 때 -RT_EINVAL을 반환하도록 했다(6개 파일, +466/-19). 셋째(#11847)는 ESP32-C3 링크 스크립트의 Windows 경로 와일드카드 수정이다. sections.ld에서 「/」로 작성된 와일드카드가 Windows 대상 경로의 riscv 디렉터리 오브젝트 파일과 일치하지 않아 벡터 점프 재배치가 한계를 초과하게 되었고, 「?」로 변경하여 두 구분자를 모두 호환하도록 했다. #11816과 동일한 위치의 수정이며 이번에는 최신 메인라인 기반으로 다시 작업했고, Windows에 GCC 11.2.0 환경에서 scons 빌드가 통과했다.

1.4 공식 뉴스 인터페이스 연속 41일째 신규 없음 (09-30)

날짜: 2026-09-30(확인 시간)　출처: RT-Thread 공식 뉴스 인터페이스

공식 뉴스 인터페이스(rt_org 분류)가 반환하는 아카이브 기사의 최신 항목 날짜는 여전히 2026-06-17이며, 모니터링 기간 내 신규가 없어 연속 41일째 업데이트가 중단되었다. 제품 및 활동 정보는 계속해서 WeChat 공식 계정, 커뮤니티 포럼 및 GitHub 채널을 통해 최초 공개되고 있다.

2. 공식 및 커뮤니티 활동

2.1 모니터링 기간 내 포럼 및 공개 채널 신규 콘텐츠 없음 (09-30)

커뮤니티 포럼 게시물 인터페이스에는 모니터링 기간 내 신규 게시물이 없었다(최신은 여전히 09-29 오전의 《MCU 링크 스크립트 「업그레이드」》로, 어제 데일리 리포트에 수록됨). 공개 집계 채널에서는 새로운 게시물이 보이지 않았고, 가장 최근의 유효 보도는 여전히 09-28의 「가상-실물 결합 물류 공장」 교육 플랫폼 기사이다. 공식 대외 정보 배포는 「뉴스 인터페이스 중단, 커뮤니티 채널 최초 공개」 구도를 유지하고 있다.

3. 생태계 및 제조사 적응

3.1 RT-Thread Studio Infineon OpenOCD 디버거 컴포넌트 5.50.0.3639로 업그레이드 (09-29)

날짜: 2026-09-29 14:35(병합 시간)　출처: sdk-debugger-openocd-infineon PR #2

RT-Thread Studio의 SDK 컴포넌트 저장소 sdk-debugger-openocd-infineon(Infineon 및 구 Cypress 보드용 OpenOCD 디버거 패키지)이 모니터링 기간 내에 버전 업데이트를 병합했다(#2). 내장 OpenOCD를 5.50.0.3639로 업그레이드했다(09-26 커밋). 이 저장소는 08-31에 생성되어 09-01에 첫 병합을 완료했으며, 이번이 두 번째 병합으로 Studio 측 디버그 컴포넌트가 지속적으로 업스트림 버전을 따라가고 있다.

3.2 제조사 및 소프트웨어 패키지 측 모니터링 기간 내 신규 푸시 없음 (09-30)

소프트웨어 패키지 인덱스(RT-Thread/packages, 최신 09-24), env 도구 저장소(09-28), GD32 다운스트림 저장소(09-28) 및 디바이스 지원 패키지 조직(최신 09-24) 모두 모니터링 기간 내 신규 푸시가 없었다. esp-idf 소프트웨어 패키지는 2023년 말 이후 푸시가 없는 상태를 유지하고 있다.

4. 산업 응용

4.1 말레이시아 과학대학 졸업 프로젝트 업데이트: RA8P1 + RT-Thread 엣지 음향 이벤트 감지 펌웨어 검증 (09-30)

날짜: 2026-09-30 05:49 ~ 05:50(커밋 시간)　출처: KhaiFaw/ai-acoustic-event-detection

topic:rt-thread 생태계의 서드파티 프로젝트 「Acoustic event detection at the edge」(말레이시아 과학대학 기계전자공학 졸업설계)가 모니터링 기간 내에 두 건의 업데이트를 연속 커밋했다: 음향 펌웨어 빌드와 모델 계약을 점검하고, 임베디드 모델과 펌웨어 간의 입력 스케일 불일치를 수정했으며, 소프트웨어 검증 기록을 보강했다(호스트 테스트 16건과 전체 BSP 로컬 빌드 1회 통과; 수정판 펌웨어는 아직 실기 플래싱 평가 미실시). 프로젝트는 Renesas RA8P1 Titan 보드 기반: RT-Thread가 운영체제 프레임워크를 제공하고, Renesas FSP가 디바이스 지원을 제공하며, CMSIS-DSP가 FFT를 구현하고, TensorFlow Lite Micro가 INT8 CNN을 실행한다; MAX9814 마이크로 16000 포인트 오디오를 수집하고, MFCC 특징 추출 후 온디바이스에서 아기 울음, 유리 깨짐, 경보/사이렌, 노크, 초인종, 배경 여섯 가지 소리를 인식한다.

5. 요약 및 트렌드 관찰

5.1 최근 하루 트렌드 (09-29 ~ 09-30)

  • RISC-V 아키텍처 라인에 명확한 병합 신호 출현: 창립자가 직접 #10320 「최근 병합」을 추진했고, 제출자가 밤새 세 차례 새로고침하며 최신 메인라인으로 리베이스했다——해당 리팩터링(171개 파일)이 병합되면 RISC-V 지원의 시스템적 세대 교체가 될 것이다.
  • 커널 메모리 안전 수정 집중 커밋: calloc 오버플로(#11848)는 커밋 다음 날 바로 LGTM을 받았고, ofw 해시 범위 초과(#11845) 등 수정에는 모두 재현 가능한 테스트가 첨부되었다; 수정 방향은 경계 및 오버플로 검사에 집중되었다.
  • Espressif 계열 BSP가 병합 후 정리 단계 진입: C6 SPI(#11846)와 C3 링커 스크립트(#11847)를 동일 기여자가 연이어 추진하며, 09-28의 C6 BSP 병합, S3 BSP 제안과 함께 완전한 시퀀스를 형성했다.
  • 메인라인 병합 공백과 제안 적체: master는 09-28 22:22 이후 새로운 병합이 없으며, 모니터링 기간 내 움직임은 전부 제안 측에 집중되었다; #10320과 #11848의 후속 병합 동향을 주목할 것을 권장한다.
  • 공식 채널은 계속 조용함: 공식 뉴스 인터페이스가 업데이트 중단 41일째에 진입했다; 포럼, 집계 채널 모두 모니터링 기간 내 신규 없음.
