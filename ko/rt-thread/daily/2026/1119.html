1. 디바이스 계층: 명령 공간의 재구분

1.1 2021년 이슈, 인코딩 교체로 종결 (11-18)

날짜: 2026-11-18 09:11 (머지). 출처: #11881.

이슈 #5073은 2021년 9월 17일에 제기되었다. 제목에는 시리얼 포트가 POSIX 인터페이스 ioctl로 하위 파라미터를 설정할 수 없고, 하위 config로 호출되지 않는다고 쓰여 있으며, 원인은 “매크로 정의 값이 3”이라는 데 있다. 이슈는 지금도 열려 있다.

제안 #11881은 2026년 10월 17일에 제출되었다. 11월 18일 오전 9시 11분, Rbb666이 이를 머지했다. 보고에서 머지까지 5년 2개월, 제안에서 머지까지 32일.

커밋 해시 629a7970. 규모는 14개 파일, 80줄 추가, 57줄 삭제. 방향은 특정 드라이버에 패치를 넣는 것이 아니라, 디바이스 제어 명령의 번호 부여 방식을 전면 교체하는 것이다.

1.2 충돌 지점: fcntl의 1~4와 디바이스 명령이 동일 값 (11-18)

날짜: 2026-11-18 (제안 본문). 출처: #5073.

제안 본문은 충돌을 표로 정리했다. POSIX 쪽에서 F_GETFD, F_SETFD, F_GETFL, F_SETFL은 각각 1, 2, 3, 4이다. 구정의에서 RT_DEVICE_CTRL_RESUME, SUSPEND, CONFIG, CLOSE는 0x01, 0x02, 0x03, 0x04이다.

두 명령 체계가 int 파라미터 하나를 공유한다. F_GETFL과 CONFIG가 3에서 충돌하고, F_SETFL과 CLOSE가 4에서 충돌한다.

경로도 명확히 서술되어 있다. fcntl은 dfs_file_ioctl, dfs_file_fcntl을 거쳐 fops->ioctl로 간다. 드라이버가 값으로 매칭할 때 F_GETFL을 CONFIG로 처리하게 된다. 이것이 바로 이슈 #5073의 “파라미터를 설정할 수 없다”는 현상의 기계적 원인이다.

새 인코딩은 디바이스 클래스를 상위 바이트로 옮긴다. 기저 매크로는 RT_DEVICE_CTRL_BASE(Type)이다. 클래스 번호에 1을 더한 뒤 0x100을 곱해 계산하며, 상위 바이트에 클래스 번호, 하위 바이트에 클래스 내 인덱스를 둔다.

9개의 범용 명령은 BASE(Unknown) + 1..9로 변경되어 실제로는 0x2001에서 0x2009에 위치한다. 이는 POSIX의 0~4와 완전히 분리된다.

기존 RT_DEVICE_CTRL_MASK = 0x1f는 하위 5비트만 보므로 새 인코딩과 호환되지 않는다. 작성자가 전체 저장소를 grep한 결과 호출자가 없어 바로 삭제했다. RT_DEVICE_CTRL_CLASS_MASK = 0xff00과 RT_DEVICE_CTRL_INDEX_MASK = 0x00ff로 교체했다.

한 가지 세부 사항은 주목할 만하다. 제안의 “검증한 bsp와 config” 항목은 비어 있고, .config와 action 링크도 채워지지 않았다.

1.3 14개 파일 동반 수정, BSP와 rt-link 포함 (11-18)

날짜: 2026-11-18(커밋 변경 범위). 출처: 629a7970.

변경을 따라간 파일 중 여덟 개는 efm32 보드 레벨 드라이버다. acmp, adc, ethernet, iic, leuart, sdcard, timer, usart로, 각각 명령 값 서너 줄씩 바뀌었다. hk32f030c8-mini의 rtconfig.py는 한 줄이 수정됐다.

헤더 파일 쪽 변경은 더 집중돼 있다.
dev_pin.h에서 PIN_CONFIG_BIAS_BUS_HOLD는 원래 열거형 첫 항목으로 값이 0이었는데,
이제 RT_DEVICE_CTRL_BASE(Pin) + 1로 바뀌었다.

dev_serial_v2.h는 RT_HW_SERIAL_CTRL_GETC, PUTC, GET_DMA_PING_BUF 세 개의 매크로를 열거형으로 교체했다. 값은 RT_DEVICE_CTRL_BASE(Char) + 0x40부터 시작하며, 0x40부터 0x4f까지는 하드웨어 시리얼 제어용으로 남겨둔다고 명시했다.

rt-link의 두 파일도 함께 바뀌었다. include/rtdef.h가 가장 큰 부분으로, 34줄이 추가되고 16줄이 삭제됐다. 버전 주석에 한 줄이 추가됐다: 2026-11-07, CXSforHPU, class-encode RT_DEVICE_CTRL_* commands.

판단: 아홉 개의 범용 명령이 0x01부터 0x09까지에서 0x2001부터 0x2009까지로 이동했다. 저장소 외부의 BSP나 소프트웨어 패키지가 옛 값을 하드코딩했다면, 업그레이드 후 잘못된 분기로 진입하게 된다. 근거는 커밋이 저장소 내 14개 파일만 동기화했고 호환 매크로를 남기지 않았으며, 검증 BSP 항목이 비어 있다는 점이다.

2. 테스트와 CI 마무리

2.1 MEMHEAP이 없는 BSP에서 memheap 테스트 케이스가 조용히 누락됨(11-18)

날짜: 2026-11-18 17:29(머지). 출처: #12066.

커밋 설명에 인과 사슬이 명시돼 있다. RT_UTEST_MEMHEAP은 RT_USING_MEMHEAP에 의존한다. mem.cfg가 이 항목을 선택하지 않았다. 그래서 memheap 테스트 그룹은 해당 설정이 없는 BSP에서 컴파일되지 않았다. 기존 mem.conf는 원래 선택돼 있었다.

수정은 .github/utest/configs/kernel/mem.cfg에 두 줄을 보충한 것이다. 제안 #12066은 당일 새벽 3시 13분에 제출되어 17시 29분에 머지됐으며, 간격은 14시간이다.

이런 누락은 빌드를 실패시키지도, 테스트를 빨갛게 만들지도 않는다. 보고서에는 통과로 표시되고, 누락된 케이스는 통계에 나타나지 않는다.

2.2 utest 문서에 혼용된 경로 구분자(11-18)

날짜: 2026-11-18 10:01(머지). 출처: ebd32d7a.

components/utilities/utest/README.md에서 두 줄이 수정되어 혼용된 경로 구분자가 통일됐다. 작성자는 sexenteen이며, 11월 16일에 작성되어 11월 18일 오전에 머지됐다. 문서 수준의 변경으로 동작에는 영향을 주지 않는다.

2.3 새벽 세 건, 당일 한 건 머지(11-18)

날짜: 2026-11-18(제안 상태). 출처: #12064.

어제 나열한 새벽 제안 세 건은 오늘 서로 다른 결과를 맞았다. #12066은 머지됐다. #12064와 #12065는 여전히 열린 상태이며, 마지막 업데이트는 각각 19시 08분과 20시 25분이다.

세 건 모두 parthitce가 제출했다. #12065의 본문에는 테스트 환경이 명시돼 있다: RH850 qemu-rh850-u2c의 kernel_basic. -O2에서 스택 손상이 rt_memmove를 크래시시켰고, 수정 후 22개 테스트 케이스가 모두 통과했다.

테스트 케이스 자체의 결함은 11바이트로 6바이트 소스와 10바이트 대상 두 배열을 읽고 쓰는 것이었다.

3. 소프트웨어 패키지와 생태계

3.1 AI Agent 패키지에 A2A 채널과 계층형 메모리 추가(11-18)

날짜: 2026-11-18 09:45(커밋). 출처: 6595550d.

소프트웨어 패키지 인덱스 저장소에 커밋 하나가 들어왔으며, ai/Agent/Kconfig만 수정해 378줄이 추가되고 212줄이 삭제됐다. 커밋 설명에는 세 가지가 적혀 있다.

첫째, a2a channel 지원을 추가했다. 둘째, 계층형 메모리의 스위치, 용량, 영속화 옵션을 보충했다. 셋째, 영속화가 켜지면 DFS와 4.1 이상의 POSIX 파일 인터페이스를 자동으로 선택해, 사용자가 돌아가서 컴포넌트를 보충할 필요가 없게 했다.

패키지 본체 ai/Agent의 설명은 「rtthread 경량 Agent 소프트웨어 패키지」입니다. 키워드는 ai, Agent, llm, toolcall입니다. 저장소는 저자 본인의 CXSforHPU/Agent를 가리키며, cJSON, webclient, mbedTLS, ulog에 의존합니다.

이 메뉴를 이틀 만에 두 번째로 손댄 것입니다. 11월 16일 11시 22분에 #2050 「Agent 설정 항목 보완, 용도별 메뉴 재정렬」이 머지되었고, 이것도 같은 Kconfig를 수정한 것이었습니다. 저자 CXSforHPU는 오늘 메인 저장소에 1.1의 명령 인코딩 커밋도 머지했습니다.

4. 공식 및 커뮤니티 활동

인터페이스가 다섯 건을 반환합니다. 최신 건은 여전히 11월 6일 15시 54분의 《OS 기반에서 AI 구현까지: RT-Thread 루이사이드 풀스택 역량이 산업 지능화 업그레이드를 견인하다》입니다. 11월 7일부터 계산하면 9회 연속 신규 없음입니다.

4.2 새 버전도, 새 태그도 없음 (11-19)

날짜: 2026-11-19 (버전 및 태그 점검). 출처: releases.

release 최신은 v5.3.0이며 9월 10일 릴리스되었습니다. tag 목록도 일치하며, 모니터링 기간 내 신규는 없습니다.

메인 브랜치의 버전 번호 주석은 10월 17일 이미 v5.4.0으로 기록되었습니다. 이슈 #12063의 보고자도 master를 v5.4.0-dev로 표기합니다. 정식 릴리스 버전은 여전히 5.3.0이며, 둘은 개발 주기 하나만큼 차이 납니다.

5. 심사 대기 큐

5.1 RH850 포팅, 일주일 만에 52개 파일로 증가 (11-18)

날짜: 2026-11-18 20:15 (최근 업데이트). 출처: #11998.

Renesas RH850 G4KH 포팅과 qemu-rh850-u2c 보드 패키지가 11월 6일 제안되었습니다. 어제는 48개 파일, 3921줄 추가였습니다. 오늘은 52개 파일, 4122줄 추가로, 하루에 4개 파일, 201줄이 늘었습니다.

내용은 세 부분입니다. libcpu/rh850는 TRAP0으로 스레드 전환을 하며, 중첩 인터럽트, FPU 컨텍스트, 장애 덤프를 포함합니다. bsp/renesas/rh850에는 시작 코드, INTC, OSTM, RLIN3 시리얼이 있으며, 시리얼은 serial V1만 지원합니다. CI는 하드 플로트와 소프트 플로트 두 가지 빌드를 수행하고, QEMU상의 kernel utest를 추가하며, 툴체인과 QEMU 패키지는 압축 해제 전에 SHA-256을 검증합니다.

저자가 제시한 실측 환경은 툴체인 v1.2.0(GCC 14.3, picolibc)과 qemu-rh850 v1.2.0입니다.

판단: 이 건은 아직 내용을 추가 중이며, 리뷰를 기다리는 것이 아닙니다. 근거는 파일 수와 줄 수가 하루 사이에 동시에 증가한 반면, 리뷰 측의 댓글 수는 그에 상응해 늘지 않았다는 점입니다.

5.2 나머지 세 건은 타임스탬프만 갱신 (11-18)

날짜: 2026-11-18 19:26 (최근 업데이트). 출처: #11842.

HUST CSE의 devtmpfs 초장문 경로 컴포넌트 스택 오버플로 수정은 여전히 5개 커밋, 4개 파일, 314줄 추가, 8줄 삭제입니다. 어제 점검과 일치하며, 최근 업데이트는 19시 26분입니다. #12064와 #12065의 상황은 2.3을 참조하십시오.

세 건 모두 업데이트 시간만 갱신되었고, 새 커밋은 들어오지 않았습니다.

5.3 모니터링 기간 내 신규 제안 및 이슈 없음 (11-19)

날짜: 2026-11-19 (제안 및 이슈 집계). 출처: 제안 목록.

모니터링 기간 내 신규 제안 0건, 신규 이슈 0개입니다. 미종료 제안은 138건으로, 이전 회차 141건입니다. 미종료 이슈는 341개로, 이전 회차와 동일합니다.

6. 요약 및 추세 관찰

6.1 오늘의 무게는 제안 한 건에 실려 있음

모니터링 기간 내 세 건의 커밋은 총 16개 파일, 84줄 추가, 59줄 삭제입니다. 그중 629a7970 한 건이 14개 파일, 80줄 추가, 57줄 삭제를 차지합니다. 나머지 두 건은 각각 한 개 파일, 각각 두 줄을 수정했습니다.

판단: 오늘은 패치 누적이 아니라 기기 명령 공간의 재구획입니다. 근거는 변경이 include/rtdef.h와 네 개의 기기 헤더 파일에 집중되어 있고, BSP 측은 수치만 따라 바꿨을 뿐 로직 변화가 없다는 점입니다.

6.2 조용한 누락은 테스트 측에서 가장 발견하기 어려운 결함

memheap 그룹의 테스트 케이스는 컴파일 실패가 아니라, 아예 컴파일 대상에 들어가지 않은 것입니다. 빌드는 통과했고, 테스트도 통과했습니다. 리포트상으로는 이상을 알아챌 수 없습니다.

판단: 이런 문제는 설정 대조를 통해서만 발견할 수 있고, 테스트 실행으로는 발견할 수 없습니다. 근거는 커밋 설명에 명시된 메커니즘입니다. RT_UTEST_MEMHEAP는 RT_USING_MEMHEAP에 의존하는데, mem.cfg에서 선택되지 않으면 전체 테스트 케이스 그룹이 건너뛰어지며, 기존 mem.conf는 선택되어 있었습니다.

6.3 명령 숫자 값 시프트 이후, 저장소 외부 코드는 직접 확인해야 함

판단: 9개의 범용 명령이 0x01~0x09에서 0x2001~0x2009로 이동했으며, 저장소 외부의 BSP와 소프트웨어 패키지가 코드에 이전 값을 기록해 두었다면 업그레이드 후 잘못된 브랜치로 진입하게 된다. 근거는 커밋이 저장소 내 14개 파일만 동기화했고 호환 매크로를 남기지 않았으며, 검증 BSP 항목이 비어 있다는 점이다.

6.4 AI Agent 패키지의 두 번째 변경

11월 16일 메뉴를 재정렬했고, 11월 18일 A2A 채널과 계층형 메모리를 추가했다. 두 번 모두 Kconfig만 변경했다.

판단: 이 패키지의 구성 면은 「프로토콜 연동 + 메모리 관리」로 확장되고 있으며, 더 이상 단순한 기능 스위치가 아니다. 근거는 두 번째 커밋에서 a2a channel과 메모리 용량, 영속화 옵션이 새로 추가되었고, 첫 번째는 용도별로 메뉴를 재정렬한 것에 불과하다는 점이다.
