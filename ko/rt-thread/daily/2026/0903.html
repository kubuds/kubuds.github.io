1. 커널 및 버전 동향

1.1 메인 저장소 병합 [lwp]: terminal/을 전역 CPPPATH에서 제거

날짜: 2026-09-03(09:20 베이징 시간 병합)　출처: PR #11776(병합 커밋 54e5164, TTLLDD 커밋)

components/lwp/SConscript는 이전에 ./terminal/ 디렉터리를 전역 CPPPATH에 추가했으나, 이번 커밋에서 이를 제거했다. 전체 저장소 검증 결과: terminal 서브시스템 헤더 파일(terminal.h, tty_config.h, bsd_porting.h 등)의 모든 비한정 include는 components/lwp/terminal/ 내부 소스 파일에서 비롯되며, 컴파일러의 따옴표 형식 검색으로 충분히 충족되므로 내부 디렉터리를 전역 포함 경로에 노출할 필요가 없다. 이는 2025-11 이슈 #10980 “CPPPATH 사용 규범화” 합의의 최소화 시범 적용이다——컴포넌트가 더 이상 내부 디렉터리를 전역 include 경로에 노출하지 않으며, 빌드 시스템/include 위생 방향의 소규모 진전에 해당한다. 모니터링 기간 내 메인 저장소의 유일한 병합이며, 평일 아침 병합 리듬은 최근과 일치하고 대형 기능은 없다.

1.2 진행 중: 커뮤니티 개발자가 CAN 프레임워크 구조적 리팩터링 PR 제출

날짜: 2026-09-02(13:21 베이징 시간 생성, open, CI clean, 비 draft)　출처: PR #11779

wdfk-prog(즉 어제 공식 인덱스로 전환된 CANopenNode 이식 패키지 작성자)가 refactor[CAN] PR을 제출했다: Generic CAN Framework 및 STM32 bxCAN 백엔드에 대한 구조적 리팩터링(2 commits, 8 파일, +2902/-1308)으로, 프레임워크 책임 경계를 재정립한다——Generic CAN은 하드웨어 리소스 관리, 동기화, ownership 및 라이프사이클을 담당하고, 송신 캐시/재시도/스케줄링과 프로토콜 QoS 정책은 상위 프로토콜 스택이나 애플리케이션이 자체적으로 결정하도록 한다. 방안은 두 가지 단서에서 비롯되었다: 8-26 기능 요청 #11759(CANopen CiA 305 LSS Activate Bit Timing 런타임 전환 보드레이트에 TX Full Flush와 Hardware Abort 기능이 필요, 이미 종료됨)와 8-28 프레임워크 리팩터링 논의 #11767(TX Engine, Mailbox Ownership 및 Lifecycle 통일, 논의 종료 후 3분 만에 본 PR로 전환). 두 이슈 모두 모니터링 기간 내 종료되어 본 PR로 집결되었으며, 레이블에는 BSP: STM32와 component: drivers/can이 포함된다. 이 PR은 CANopenNode 이식에서 드러난 저수준 기능 공백을 프레임워크 계층 리팩터링 제안으로 승격시킨 것으로, 현재 유지관리자 리뷰를 기다리고 있으며, 병합될 경우 Generic CAN Framework의 최근 몇 년간 가장 큰 책임 경계 조정이 될 것이다.

2. 공식 및 커뮤니티 활동

2.1 공식 뉴스 API 14일 연속 신규 없음, elexcon 2026 카운트다운 6일

날짜: 2026-09-03　출처: RT-Thread 공식 뉴스 API

공식 뉴스 API(rt_org 카테고리)는 여전히 5건의 이전 항목이며, 최신 항목은 2026-06-17 아부다비 투자 포럼 보도로, 14일 연속 신규 항목이 없다. gnews 다중 보충 조회(RT-Thread when:3d 중영문, RT-Thread 睿赛德 when:3d, 睿擎派 OR 睿擎 when:3d): 영문은 여전히 Rotten Tomatoes 분해 노이즈와 무관한 기술 게시물이며, 중국어 조회는 전부 비어 있다. 다음 대외 창구는 9월 9-11일 선전 elexcon 2026(루이사이드 전시 참가, 8-30 예고 이미 수록)이며, 카운트다운 6일, 회의 전 침묵기 지속은 예상된 리듬이다.

3. 생태계와 벤더 적응

3.1 canopennode-rtt 기능 브랜치 지속 활발, 메인라인 기간 내 신규 커밋 없음

날짜: 2026-09-02(22:30 베이징 시간 저장소 push)　출처: github.com/wdfk-prog/canopennode-rtt

topic:rt-thread 기간 내 push 저장소 중 하나. 기본 브랜치 master 최신 커밋은 여전히 09-02 11:02 베이징 「co_rtt_mainline_deadline_min을 extern으로 조정하여 메인라인 스케줄링에 대응」(어제 이미 수록), 기간 내 push는 A04와 ds402 두 기능 브랜치에 위치 — CANopen 서로 다른 profile(DS402 모션 제어, A04 애플리케이션) 브랜치의 지속적 진화이며, 메인라인에는 신규 내용이 없다. 같은 날 해당 저장소 작성자는 RT-Thread 메인 저장소에서 CAN 프레임워크 리팩터링 PR을 제기(1.2 참조), “애플리케이션 계층(CANopenNode 소프트웨어 패키지) → 프레임워크 계층(Generic CAN 리팩터링)” 양방향 추진, CAN 생태계가 현재 커뮤니티에서 가장 활발한 추진 메인라인이 되었다.

4. 산업 응용

4.1 생태계 참고: 소비자급 드론 H120D 펌웨어 리버스 문서 업데이트

날짜: 2026-09-02(13:34 베이징 시간 push)　출처: H4ck3rTR/h120d-protocol

topic:rt-thread 생태계 저장소 h120d-protocol 기간 내 업데이트(README 개정, 4월 Hackaday 투고 내용 정리). 해당 프로젝트는 소비자급 드론 Holy Stone H120D의 WiFi 통신 프로토콜 및 그 펌웨어 내 RT-Thread 내부 구현을 리버스 문서화하며, 제어 도구를 제공하고 코드는 C++ 위주이다. 기간 내 코드 실질 업데이트는 없으며 문서 유지보수에 해당; 프로젝트 존재 자체가 RT-Thread가 소비자급 드론 펌웨어에 배포되었음을 방증(리버스 프로젝트 자칭, 공식 검증되지 않음), 저활동 생태계 참고로 수록.

5. 요약과 트렌드 관찰

  • 커널 측: 기간 내 단일 머지 — [lwp] terminal/을 전역 CPPPATH에서 제거(09-03 09:20), 빌드/include 위생 규범(이슈 #10980)의 이행 리듬 지속, 대형 기능 머지 없음.
  • 진행 중: CAN 프레임워크 구조적 리팩터링 PR(#11779, +2902/-1308)이 커뮤니티 개발자 wdfk-prog에 의해 제출, CI clean, 비 draft, 메인테이너 리뷰 대기; 8월 말 CAN 논의(#11767)와 기능 요청(#11759)은 모두 닫히고 본 PR로 집약, 리팩터링 방향은 커뮤니티 측 합의 획득.
  • 공식 측: 공식 뉴스 API 14일 연속 신규 없음; 다음 대외 창구 9월 9-11일 선전 elexcon 2026, 카운트다운 6일.
  • 생태계 측: CAN 이중 라인 추진(애플리케이션 계층 CANopenNode 정식 전환 후 DS402 등 profile 브랜치 확장 + 프레임워크 계층 리팩터링 제안)이 현재 가장 명확한 커뮤니티 메인라인; 소프트웨어 패키지 인덱스 기간 내 신규 머지 없음, 텐센트 IoT SDK 설정 PR #2034 여전히 open.
  • 최근 3일 트렌드(09-01 ~ 09-03): 커널 견고성 4 PR 배치, CANopenNode 이벤트 구동 스케줄링, RTC utest와 푸단웨이 FM33/CANopenNode 두 소프트웨어 패키지 인덱스 진입(09-01) → 텐센트 IoT SDK 설정 PR, CAN 프레임워크 리팩터링 PR 제기, h120d 문서 업데이트(09-02) → lwp CPPPATH 위생 머지, CAN 리팩터링 PR 리뷰 대기, 공식 침묵 제14일(09-03). 추진 메인라인이 “소프트웨어 패키지 인덱스 확장”에서 “CAN 생태계 심층 추진 + 빌드 시스템 규범화”로 전환.
