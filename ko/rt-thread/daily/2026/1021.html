1. 커널 및 버전 동향

1.1 RISC-V 티켓 스핀락, 원자적 증가로 전환: 다중 코어 경합 시 라이브락 경로 제거 (10-20)

날짜: 2026-10-20 16:04 (생성 시간)　출처: PR #11904, cpuport.c

메인테이너 GuEe-GUI가 RISC-V 공통 레이어의 티켓 스핀락 개조를 제출했다(6개 파일 +33/-37, 커밋 2건). 기존 구현은 번호 발급과 해제 모두 동일한 32비트 워드에서 “로드 예약 및 조건부 저장” 루프를 실행했다: 상위 16비트는 발급 대기 번호, 하위 16비트는 현재 보유 번호다. 해제 측이 동일 워드에서 조건부 저장을 재시도하면 발급 측의 예약이 반복적으로 무효화되어 다중 코어 고경합 시 라이브락에 빠질 수 있다. 새 구현은 번호 발급을 원자적 증가 명령 하나로 교체하여 상위 반워드에 1을 더하면 발급이 완료되며, 해제와 동일한 예약을 두고 경합할 수 없다. 해제는 보유자만 하위 반워드를 기록하도록 변경되어 반워드 저장 한 번으로 완료되고 더 이상 전체 워드를 읽고-수정-쓰기하지 않으므로 번호 발급이 동시에 진행 중이어도 새 티켓을 덮어쓰지 않는다. 락 획득 후에는 메모리 배리어를 한 번 더 추가하여 임계 영역 접근이 해제 관찰 이후에 정렬되도록 보장한다. 제안은 성숙 버전으로 표시되어 RISC-V 커널 리뷰에 배정되었다.

1.2 동일 우선순위 스레드 준비 순서 수정 제안: IPC 웨이크업 및 신규 시작을 대기열 끝에 추가로 변경 (10-21)

날짜: 2026-10-21 00:06 (생성 시간)　출처: PR #11907, Issue #8459

Yunlk 커뮤니티 멤버가 준비 큐 삽입 순서 문제에 대한 수정안을 제출했습니다(4개 파일 +255/-22, 신규 utest 포함). 기존 로직은 ‘양보됨’ 플래그가 없는 모든 스레드를 큐 선두에 삽입하는데, 스레드가 전환될 때 이 플래그가 지워지므로 세마포어 등 IPC 대기 큐에서 복귀한 스레드와 새로 시작된 스레드가 모두 선두에 삽입되어, 동일 우선순위 스레드의 실제 실행 순서가 준비 순서와 반대로 됩니다. 제안은 먼저 원래 상태를 저장한 뒤 덮어쓰는 방식으로, ‘여전히 실행 중이면서 시간 할당량이 소진되지 않은 채 선점된’ 경우에만 선두 삽입을 유지하고 나머지는 모두 큐 끝에 추가합니다. 단일 코어와 멀티 코어 두 곳의 삽입 분기를 일관되게 수정하고, 세마포어 깨우기와 시작 두 경로를 모두 커버하는 테스트 케이스를 새로 추가했습니다. 작성자는 qemu-vexpress-a9에서 실측했는데, 수정 전에는 세마포어 깨우기 순서가 을-갑, 시작 순서가 정-병이었으나 수정 후에는 각각 갑-을, 병-정이 되었습니다. 제안은 여전히 검토 중이며 두 워크플로가 메인테이너 승인을 기다리고 있습니다.

1.3 시리얼 V1 수신 타임아웃 이벤트 보완: 타임아웃을 RX_IND 콜백에 통합 (10-21)

날짜: 2026-10-21 00:15(생성 시간)　출처: PR #11909, Issue #8143

수신 타임아웃 이벤트(코드 0x05)는 헤더 파일에 일찍부터 정의되어 있었지만, V1 프레임워크의 인터럽트 처리는 앞의 네 가지 이벤트만 다루고 폴백 분기가 없어 드라이버가 해당 이벤트를 발생시켜도 프레임워크는 아무 동작도 하지 않고 알림이 조용히 버려집니다. 저장소에는 이를 이용해 데이터 프레임을 분할하는 드라이버가 정확히 두 개 있습니다: 친헝 CH579M과 화신웨이트 SWM341 모두 칩의 수신 타임아웃 인터럽트로 ‘한 프레임 수신 완료’를 판정하며, 둘 다 V1 프레임워크 위에 있어 결과적으로 프레임 경계가 실제로 유실되어 하드웨어 워터마크 기준 보고로 퇴화할 수밖에 없습니다. 제안은 해당 이벤트를 수신 지시 콜백에 통합합니다: 먼저 하드웨어 FIFO를 비운 뒤 소프트웨어 FIFO에 캐시된 길이에 따라 상위 계층에 콜백합니다. 변경은 단 한 줄 분기(주석 포함 총 5줄)이며 V2는 건드리지 않았는데, V2 헤더 파일에는 이 매크로가 아예 없기 때문입니다. 작성자는 컴파일 수준 검증만 했고 유휴 타임아웃 인터럽트가 있는 하드웨어가 없으며, 가상 시리얼 장치에 테스트 케이스를 추가해 CI에 넣을 수 있다고 제안했습니다.

2. 보안 및 안정성 추적

2.1 cromfs 디렉터리 이름 길이 미제약: ls/getdents 범위 초과 및 커널 PC 탈취 (10-20)

날짜: 2026-10-20 19:29(생성 시간)　출처: Issue #11905

기여자 XueDugu가 cromfs 결함 이슈를 새로 열었습니다. 디렉터리 항목을 읽을 때 디렉터리 이름 길이에 대한 상한 검사가 전혀 없어, 지나치게 긴 이름은 내용을 고정 크기 디렉터리 항목 버퍼에 복사하며 그 끝을 넘어설 수 있고, 오버플로 양이 충분하면 인접 데이터를 덮어쓸 수 있습니다. ls 또는 디렉터리 읽기만으로 트리거되며, 작성자는 커널 프로그램 카운터를 제어 가능한 위치로 유도할 수 있다고 밝혔습니다. 결함은 2022-12-14의 cromfs 동기화 커밋에서 도입되었으며, v4.1.1에는 이 문제가 없고 v5.0.0부터 v5.3.0 및 현재 메인라인까지 모두 영향을 받습니다. DFS의 두 구현은 동일 소스이며 v1과 v2에 각각 제약이 없는 사본이 하나씩 있습니다. 작성자는 QEMU vexpress-a9에서 재현했으며, 이슈는 현재 아직 담당자가 없습니다.

2.2 OFW 심층 사전 검사를 디버그 게이트로 변경: 메인테이너 제안 후 작성자가 컴파일 스위치 추가 (10-20)

날짜: 2026-10-20 09:11 ~ 16:03(댓글 시간)　출처: PR #11901, Issue #11879

지난 호에 수록된 디바이스 트리 깊이 사전 검사 제안이 이번 모니터링 기간에 한 차례 리뷰를 마쳤습니다. 리뷰는 먼저 사전 순회의 오버헤드를 문제 삼아, 런타임 검사로 전환하고 초과 시 즉시 종료하며 메모리를 해제할 것을 제안했습니다. 작성자는 불완전한 트리의 해제는 포인터를 따라 재귀 순회해야 하고 할당 지점이 흩어져 있어 누락이나 중복 해제가 발생하기 쉬운 반면, 검사 함수는 읽기 전용이며 할당도 하지 않고 속성도 파싱하지 않아 전개 자체에 비해 오버헤드가 매우 작다고 응답했습니다. 이어 메인테이너가 방향을 제시했습니다: OFW는 설계상 펌웨어를 신뢰하는 쪽이며 64계층은 대부분 SoC의 실제 요구를 크게 초과하므로, 이 검사는 디버그 모드에서만 활성화할 것을 권했습니다. 작성자는 이를 수용해 깊이 검사를 디버그 스위치로 감쌌고, qemu-virt64-aarch64에서 디버그 모드를 켜고 65계층 디바이스 트리로 재테스트했습니다. 변경은 이미 푸시되었으며 제안은 여전히 검토 중입니다.

2.3 tmpfs 잘림 결함이 RT-Smart의 aarch64에서 재현되어 담당자 지정 (10-20)

날짜: 2026-10-20 22:53(재현 댓글)　출처: Issue #11902

지난 호에 수록된 tmpfs 잘림 결함에 이번 모니터링 기간에 디바이스 측 증거가 보강되었습니다. 커뮤니티 멤버가 RT-Smart의 qemu-virt64-aarch64 보드에서 재현했습니다: 파일을 0바이트로 자를 때 버퍼는 해제되지만 함수는 성공을 반환하고, 이후 애플리케이션의 읽기/쓰기가 이미 해제된 커널 힙에 접근하여 정보 유출과 이중 해제를 초래할 수 있습니다. 재현 환경은 QEMU 11.0.0의 virt 머신에 GICv3, 크로스 툴체인 15.2.1, DFS_V2 구성입니다. 이 이슈는 10-20에 다른 커뮤니티 멤버가 담당자로 지정되었으며, 수정 패치는 아직 제출되지 않았습니다.

2.4 나머지 검토 중 진행 상황: 인터럽트 응답 수정 재테스트 대기, IAR 암시적 선언 논의 지속 (10-20)

날짜: 2026-10-20(논평 시간)　출처: PR #11860, PR #11864, Issue #9941, PR #10096

네 개 기존 항목의 모니터링 기간 내 진전. aarch64 인터럽트 컨트롤러 응답에서 중복된 펜딩 클리어를 제거하는 제안(#11860)의 작성자는 이틀 내에 트랩 처리 수정 방식을 한 번 더 테스트할 예정이며, 아직 병합하지 않겠다고 밝혔다. IAR 8.40에서 로그 함수의 암시적 선언으로 인해 부동소수점 출력이 깨지는 제안(#11864)에는 어셈블리 수준의 설명이 보충되었다: 프로토타입이 없을 때 컴파일러가 고정 인자 전달 방식으로 가변 인자를 추론하여 %f가 잘못된 위치에서 값을 가져오게 되며, 리뷰에서는 여전히 보드 레벨 설정과 동일 설정에서의 전후 출력 기록을 보완할 것을 요구하고 있다.此外 두 가지 프로세스 확인 사항: #9941은 scons --attach가 메인라인에서 실제로 사용 가능함을 확인하여 해당 요구 사항 티켓을 닫을 것을 제안했고, #10096은 온디맨드 컴파일 옵션이 여전히 메인라인에 들어가지 않았으며 제안 브랜치가 심각하게 뒤처져 있어 먼저 리베이스할 것을 제안했다.

5.1 듀얼 보드 협업 스마트 터미널: M7 디스플레이 측이 RT-Thread와 LVGL 구동, C3는 네트워킹 브리지 역할 (10-20)

날짜: 2026-10-20 08:31 (게시 시간)　출처: 커뮤니티 글: NS800RT7P65와 ESP32-C3 기반 듀얼 보드 협업 스마트 터미널

2026 임베디드 대회 작품으로, 두 개의 마이크로컨트롤러로 역할을 분담한다. Novosense NS800RT7P65(Cortex-M7, 하드웨어 부동소수점 지원)는 RT-Thread 5.3.0과 LVGL 9.1.0을 구동하여 3×3 데스크톱과 14개 애플리케이션을 구현하며, 화면은 240×320 드라이버 칩 방식으로 작성자가 실측한 SPI 상한은 50 MHz이고 70 MHz를 시도했을 때 전체 화면이 깨졌다. 16 MB 외부 NOR에 소형 파일 시스템을 마운트하여 백라이트, 색상 조정, 게임 최고 점수, 알람이 전원 차단 후에도 유지된다. 노브는 직교 디코더에 연결하고 버튼은 직접 읽기와 소프트웨어 디바운스를 적용했다. Espressif ESP32-C3은 네트워킹 측으로서 무선 연결, 시간 동기화, 보고, 로컬 웹 업그레이드를 담당하며 웹에서 설정 변경과 펌웨어 전송이 가능하다. 두 보드는 시리얼 한 회선만 사용하며, 작성자는 이에 근거하여 시리얼 대역폭이 전체 화면 픽셀을 전송하기에 부족하다고 판단하여 영상 재생은 구현하지 않았다.

5.2 Edgi-Talk 인체 감지 경보 시스템: M55에 NPU 추가, 감지와 경보를 로컬에서 폐루프 처리 (10-20)

날짜: 2026-10-20 08:31 (게시 시간)　출처: 커뮤니티 글: Edgi-Talk 기반 엣지 AI 인체 감지 경보 시스템

M55 코어는 RT-Thread를 실행하며 비디오, 스케줄링, 비즈니스를 담당하고, M33 코어는 보안 부팅을 관리하며, NPU는 고정소수점 추론을 수행한다. 카메라는 USB 호스트를 통해 YUYV 형식 424×240을 출력하고, 화면은 320×240을 표시하며, 5프레임마다 한 번 추론하고, 입력은 320×320의 8비트 고정소수점이며, 후보 박스는 최대 8개, 신뢰도 임계값 0.45, 중복 억제 0.45이다. 경보는 연속 3회 적중으로 확인하고 연속 5회 미적중으로 해제하여 단일 프레임 오검출로 인한 흔들림을 방지한다. 저장 쓰기, 네트워크 보고, 오디오 재생은 각각 큐에 넣어 비디오 스레드를 점유하지 않으며, 네트워크 단절은 로컬 검출과 음향·광학 경보에 영향을 주지 않는다. 시스템 틱은 1000 Hz이며, 이상 발생 시 코어 프리뷰로 성능을 낮춘다.

6. 요약과 동향 관찰

6.1 이번 기간 동향

  • 커널의 두 저수준 경로가 동시에 수정됨: 스케줄러가 동일 우선순위 준비 순서를 선입선출로 되돌렸고, RISC-V 티켓 번호 락이 번호 획득을 단일 명령 원자적 증가로, 해제를 반워드 저장으로 변경했다. 전자는 실행 순서의 예측 가능성에, 후자는 다중 코어 경합 상황의 활성도에 영향을 준다. 두 가지 모두 오랫동안 기본 동작에 가려져 있던 문제다.
  • 주변기기 이벤트 의미가 보완되기 시작함: 시리얼 V1이 마침내 「수신 타임아웃은 한 프레임의 끝과 같다」를 프레임워크에 연결했는데, 영향을 받은 것은 정확히 두 개의 국산 보드 지원으로, 둘 다 유휴 인터럽트로 프레임을 나누는 방식에 의존한다. 프레임워크 계층의 역사적 공백이 여전히 하나씩 발견되고 있음을 보여준다.
  • 결함 발견은 계속 외부 연구자에 의해 주도됨: 이번 기간 cromfs 경계 초과 건은 영향 범위를 v5.0.0까지 거슬러 올라가 확인했고, DFS의 두 구현이 동일 기원임을 지적했다. 이런 버전 구간이 포함된 보고는 단일 패치보다 가치가 크며, v1과 v2 병행 유지에 따른 중복 위험도 시사한다.
  • 벤더 플랫폼이 부팅 가능에서 납품 가능으로 나아감: K1은 기본으로 8코어까지 켜고, SPI와 QSPI 상태가 정식으로 승격되어 지원 매트릭스에 진입했으며, D1s는 에뮬레이터 실행 경로를 보완했고, 심사에서는 「재현 가능한 환경」을 디렉터리 규격과 AI 지향 설명 문서로 격상시켰다. 이는 플랫폼화 사고방식에 속한다.
  • 툴체인의 로컬화 세부 사항이 시야에 들어옴: 중국어 Windows에서 이모지가 빌드 명령을 중단시키는 문제는 작지만 영향 범위가 크며, 크로스 플랫폼 사용성 테스트가 여전히 취약함을 반영한다.
  • 공식 채널은 계속 침묵: 뉴스 인터페이스가 4개월 넘게 갱신을 멈췄고, 버전 릴리스도 여전히 9월에 머물러 있으며, 대외 정보는 주로 GitHub과 커뮤니티 작품에 의존한다. 이 구도는 이미 2주 연속 변하지 않았다.

6.2 한계와 중복 제거 설명

  • 이번 기간은 24시간 윈도(10-20 08:00 ~ 10-21 08:00)이며, 월요일이 아니므로 여러 날을 병합하지 않는다.
  • 메인 저장소는 기간 내 병합된 것이 없고, 모든 항목이 제안, 결함 티켓, 커뮤니티 측에서 나왔으므로 「커널과 버전 동향」의 세 절은 모두 심사 중인 제안이며 이미 반영된 변경이 아니다. 각 항목에 상태를 명시했다.
  • 지난 기간과의 중복 제거: 디바이스 트리 심층 사전 검사(#11901)와 tmpfs 절단 건(#11902) 자체는 지난 기간에 이미 수록되었으므로, 이번 기간에는 기간 내 새로 추가된 심사 결론과 디바이스 측 재현만 기록한다. 인터럽트 응답(#11860), IAR 암시적 선언(#11864), 온디맨드 컴파일(#10096), attach 설정(#9941)은 모두 더 이른 항목이므로 이번 기간에는 진척만 기록한다.
  • 두 대회 작품의 주 제어기는 모두 RISC-V가 아니다. Navinci NS800RT7P65는 Cortex-M7이고, 네트워크 측의 Espressif ESP32-C3가 RISC-V이며, Edgi-Talk는 Cortex-M55에 M33을 더한 구성이다. 수록 이유는 RT-Thread 응용 사례와 툴체인 실천이며, RISC-V 적응 해석으로는 다루지 않는다.
  • 조직 수준 전체 푸시는 인터페이스 검증을 통과하지 못했고(익명 한도 소진), 대신 저장소 커밋 흐름과 조직 페이지를 교차 검증했다. Studio의 SDK 인덱스는 커밋 흐름으로 확인한 결과 10-10에 멈춰 있다.
  • 포럼 글 인터페이스는 처음 20건만 가져오며, 초과분은 확인하지 않았다. 공식 뉴스 목록 페이지는 프런트엔드 렌더링이어서 수집 시 빈 껍데기만 얻어지므로, 뉴스는 인터페이스를 기준으로 한다.
  • Google 뉴스 영어 윈도는 적중이 없었고, 중국어 3일간의 2건 중 1건은 이미 수록된 기사, 1건은 10-18의 옛 기사였다. 루이칭 조회는 여전히 동명의 자동차 기사에 묻혀 추가 항목이 발생하지 않았다.
