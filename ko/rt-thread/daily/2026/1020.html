1. 커널 및 버전 동향

1.1 SpacemiT K1 BSP 첫 버전 메인라인 병합: 173개 파일, 5.4만 줄, S 모드 및 4코어 SMP (10-19)

날짜: 2026-10-19 18:49 (병합 시간)　출처: PR #11132, K1 BSP 설명

SpacemiT K1 플랫폼의 첫 버전 BSP가 병합되었다. 4개 커밋, 173개 파일 +53862/-12, 작성자 GuEe-GUI, 제안은 2026-01-11에 올라왔으며 약 9개월의 리뷰 후 반영되었고 Next RISC-V 시리즈(#10320)의 후속이다. BSP는 64비트 RISC-V, 8개 X60 코어를 통합한 K1을 대상으로 하며 벡터 확장을 갖추고, U-Boot/OpenSBI로 부팅되어 S 모드에서 실행되며 기본적으로 MMU와 4코어 SMP를 활성화한다. 검증 플랫폼은 Banana Pi BPI-F3이며 콘솔은 UART0(115200 8N1)을 사용한다. PCIe/NVMe, eMMC HS400, 이더넷 및 PTP, HDMI 프레임버퍼(콜드 부팅 디스플레이 포함), JPU 및 V2D 가속, ES8326 오디오, CPUfreq 및 열 관리, AES/RNG/eFuse를 지원한다. SPI와 QSPI는 이식 완료, 검증 중으로 표기되었다. 드라이버 계층은 별도로 bsp/spacemit/dm에 분리되었으며(147개 파일, 49개 C 파일, 약 30개 모듈, 클럭, 오디오, 그래픽, 암복호화, PCI, SDIO, 시리얼, 열 관리 등 포함), 향후 동일 계열 SoC에서 재사용된다. CI 측에는 spacemit-k1 빌드 레그가 추가되었고, 기존에 K230 툴체인만 설치하던 단계를 모든 riscv64 musl BSP에 적용하도록 변경했다.

1.2 RISC-V 원자 CAS 재시도 결함 동일 배치에서 수정: 기대값이 더 이상 상태 레지스터에 의해 덮어쓰이지 않음 (10-19)

날짜: 2026-10-19 18:49 (머지 시간)　출처: 머지 커밋 1c801efa, atomic_riscv.c

같은 배치의 커밋에서 RISC-V 원자적 비교 교환 구현에 있는 실제 결함 하나를 수정했다. 기존 코드는
rt_hw_atomic_compare_exchange_strong 에서 동일한 변수 tmp 를 기대값 저장과 sc 명령의 성공/실패 상태 수신에 동시에 사용했다. sc 가 실패하면 tmp 에 0이 아닌 값이 기록되고, 재시도 분기에서 lr 결과를 이와 비교하게 되어, 덮어쓰인 값을 기대값으로 사용하는 셈이므로 루프가 영원히 빠져나오지 못하거나 잘못된 판단을 할 수 있었다. 수정에서는 기대값을 읽기 전용 오퍼랜드로 옮기고, sc 결과를 받을 status 레지스터를 별도로 두었으며, 결과 출력을 쓰기 전용 제약으로 변경했다. 이 구현은 모든 RISC-V 보드의 원자적 연산 경로에서 사용되며 아키텍처 공통 코드에 속하므로 영향 범위가 단일 BSP보다 크다.

1.3 rt_null 콘솔 디바이스를 BOARD 초기화로 조기 이동: 전원 인가 즉시 로그 포트를 null로 설정 가능 (10-19)

날짜: 2026-10-19 16:53 (머지 시간)　출처: PR #11884, Issue #11472

커뮤니티에서 제출한 한 줄짜리 변경으로 null 디바이스의 등록 시점을 INIT_DEVICE_EXPORT에서 INIT_BOARD_EXPORT로 앞당겨, RT_CONSOLE_DEVICE_NAME을 null로 설정하면 전원 인가 즉시 적용되도록 했다. 이는 로그 포트와 통신 포트가 같은 UART를 공유할 때 초기 단계에서 조용히 출력할 수 없던 문제를 해결한다. 작성자는 qemu-vexpress-a9에서 검증했는데, uart0은 정상 출력되고 null로 변경하면 QEMU 부팅 배너가 사라지며, uart0로 복원하면 msh 프롬프트가 돌아오고 rt_null.o가 .rti_fn.1 섹션에 배치된다. 변경은 1개 파일 +4/-1이며 작성자는 AI의 도움을 받아 완료했다고 명시했다. 초기 콘솔과 일반 콘솔을 분리하는 더 근본적인 방향은 이번에 구현되지 않았다.

1.4 디바이스 모델 프레임워크 두 곳 수정: 파워 도메인 proxy 명명과 DVFS OPP 중복 경고 (10-19)

날짜: 2026-10-19 18:49 (머지 시간)　출처: power_domain.c, dvfs.c

K1 BSP의 머지와 함께 프레임워크 계층 수정 두 건이 함께 들어왔으며, 이는 “BSP가 먼저, 프레임워크가 뒤따라 보완”하는 전형적인 사례다. 첫째, 파워 도메인 proxy 객체를 등록할 때 이름을 실제 파워 도메인의 이름으로 기록해, 이름으로 조회할 때 proxy를 도메인 자체로 오인하게 만들었다. 이제 proxy 전용 이름을 사용해 디바이스 트리의 파워 도메인 참조가 proxy의 해석 콜백으로 올바르게 연결되도록 했다. 둘째, DVFS가 OPP 테이블을 해석할 때 중복 확인 없이 바로 추가해, 디바이스 트리에 중복 항목이 있으면 중복 경고가 발생하고 추가가 실패했다. 이제 주파수 기준으로 먼저 조회하고, 찾으면 재사용하도록 했다. 두 수정 모두 components/drivers 아래에 있으며 수혜 범위는 K1에 국한되지 않는다.

1.5 netdev ping 지연 통계 수정: count가 1일 때 최소 지연이 누락되지 않도록 (10-19)

날짜: 2026-10-19 16:42 (생성 시간)　출처: PR #11900

커뮤니티에서 netdev 계층 ping 통계 수정을 제출했다(1개 파일 +5/-1). 기존 로직은 ping 횟수가 1이고 성공한 경우 최대 지연만 집계하고 최소 지연은 건너뛰어, 한 번의 성공 탐사 후 최솟값이 비정상으로 표시되었다. 수정 방식은 첫 성공 응답 수신 시 최댓값과 최솟값을 동시에 초기화하는 것이다. 변경은 작지만 자주 쓰는 진단 명령의 가시적 결과에 해당하며, 제안은 아직 심사 중이다.

2. 보안 및 안정성 후속 조치

2.1 lwp 시그널 번호 검증 제안: sys_sigaction 진입점에서 1~64로 제한 (10-19)

날짜: 2026-10-19 08:49 (생성 시간)　출처: PR #11899, Issue #11882

메인테이너 BernardXiong이 지난 호 결함 티켓 #11882에 대해 수정 제안을 열었습니다(2개 파일 +11-0): sys_sigaction이 사용자 공간에서 전달된 시그널 번호를 그대로 lwp_signal_action에 넘기는데, 후자는 시그널 번호에서 1을 뺀 값으로 고정 길이 배열(_LWP_NSIG는 64)을 인덱싱하므로, 범위를 벗어나거나 음수 값이면 커널 힙 범위를 벗어난 읽기/쓰기를 유발하며, 일반 프로그램이 시스템 콜 한 번으로 트리거할 수 있습니다. 제안은 sys_sigaction 진입점에서 1부터 64까지만 허용하고 그 외에는 EINVAL을 설정해 반환하며, lwp_signal_action 내부에도 동일한 검증을 추가해 향후 추가되는 호출자를 보호합니다. 저장소에는 이미 valid_signo_check가 있으며, 이번에 이 접근 방식을 재사용합니다. 제안은 components 리뷰로 배정되어 심사 중 상태입니다.

2.2 OFW 디바이스 트리 전개 전 깊이 사전 검사 추가: 63계층 초과 시 즉시 거부 (10-20)

날짜: 2026-10-20 01:12(생성 시간)　출처: PR #11901, Issue #11879

커뮤니티 멤버 liangzhan5가 #11879에 대해 수정을 제출했습니다(1개 파일 +60-0). fdt_unflatten_single은 고정 64개 항목 스택으로 순회 경로를 임시 저장하는데, 중첩이 64계층을 초과할 때 푸시 전에 검사가 없어 부팅 단계에서 범위를 벗어나 쓰고 크래시합니다. 제안은 실제 전개 전에 자체 스택으로 디바이스 트리를 한 번 순회해 최대 깊이를 계산하고, 63계층을 초과하면 오류를 출력하고 이후 전개를 중단하여 잔여 트리와 2차 단언 문제를 회피합니다. 작성자는 qemu에서 해당 결함을 재현했다고 밝혔으며, 검증 구성은 qemu-virt64-aarch64이고 CLA에 서명했으며 제안은 심사 중입니다.

2.3 새로운 tmpfs 결함 티켓: ftruncate(fd, 0)이 버퍼를 해제하고도 성공 반환 (10-20)

날짜: 2026-10-20 01:53(생성 시간)　출처: Issue #11902

기여자 XueDugu가 dfs_v2 결함 티켓을 새로 열었습니다. tmpfs의 절단 함수는 rt_realloc(data, 0)이 널 포인터를 반환할 때 ENOMEM을 설정하면서도 0을 반환하는데, 두 힙 백엔드 모두 길이 0인 realloc의 의미가 “해제 후 널 반환”이므로, 합법적인 ftruncate(fd, 0)이 파일 버퍼를 먼저 해제한 뒤 애플리케이션에 성공을 보고하여 댕글링 포인터와 만료된 길이를 남기고, 이어지는 읽기/쓰기가 이미 해제된 커널 힙에 접근하여 정보 유출과 이중 해제를 초래할 수 있습니다. 결함은 2023-09-20의 커밋(PR #8063)에서 도입되었으며, v5.0.2부터 모든 버전과 master가 영향을 받고, QEMU aarch64의 RT-Smart와 RP2350에서 재현되었습니다. 티켓은 열린 상태로 유지됩니다.

2.4 메인테이너, libdl 동적 모듈 결함에 대응: 부분 수정 가능, 완전 격리는 사용자 공간 필요 (10-19)

날짜: 2026-10-19 08:16(댓글 시간)　출처: Issue #11898

지난 호에 수록된 libdl 재배치 범위 초과 쓰기 결함 티켓이 이번 모니터링 기간에 메인테이너의 응답을 받았습니다. BernardXiong은 설명이 사실임을 확인하고 경계 검증으로 일정 부분 수정할 수 있다고 보면서, 동적 모듈은 본질적으로 코드 조각을 커널에 삽입하는 것이며 권한이 전부 열려 있어 이 메커니즘에서 공식이 더 많은 시도를 하지 않은 이유라고 지적했습니다. 메모리 격리를 구현하려면 사용자 공간 모드로 가야 한다고 밝혔습니다. 이 발언은 후속 수정 범위의 경계를 그었습니다: 이번 라운드에서는 메타데이터 검증만 보완하고 모듈 로딩의 전체 권한 모델은 변경하지 않을 것으로 예상됩니다.

3.1 공식 뉴스 인터페이스에 여전히 신규 없음, v5.4.0 태그와 릴리스물 없음 (10-20)

날짜: 2026-10-20(확인 시간)　출처: RT-Thread 공식 뉴스 인터페이스, releases

공식 뉴스 인터페이스(rt_org 분류)가 반환한 5건의 아카이브 기사 중 최신은 여전히 2026-06-17이며, 모니터링 기간 내 신규는 없고 갱신 중단이 이미 4개월을 넘었습니다. 공식 웹사이트 뉴스 목록 페이지는 프런트엔드 동적 렌더링이라 크롤링 시 로딩 중인 빈 껍데기만 얻어지며, 뉴스 데이터는 인터페이스를 기준으로 합니다. 버전 측 변화 없음: 최신 tag와 release는 여전히 09-10의 v5.3.0이고, v5.4.0은 이전에 병합된 버전 매크로와 Kconfig 기본값만 있으며 릴리스 노트와 릴리스물은 아직 나타나지 않았습니다. 제품 및 활동 정보는 계속 위챗 공식 계정, 커뮤니티 포럼, GitHub 채널에서 최초 공개됩니다.

3.2 커뮤니티 포럼 모니터링 기간 내 1건 추가, 2026 임베디드 대회 작품 (10-19)

날짜: 2026-10-19 09:35(게시 시간)　출처: 커뮤니티 포럼 기사 인터페이스

커뮤니티 포럼 기사 인터페이스는 총 5건을 반환했으며, 모니터링 기간 내 신규 1편은 2026 임베디드 대회의 온실 환경 모니터링 단말(기술 세부 사항은 5.1 참조)이다. 나머지는 이전에 수록된 작품의 업데이트이다: 런화(Renhua)의 수분 로봇 게시글은 10-19 15:19에 편집되었고, 청소부 소독 장치, 슈헝 즈양(Shuheng Zhiyang) 로봇 팔, GD32H759IM USB 보조 화면은 각각 10-18부터 10-19 사이에 업데이트되었으며, 모두 지난 호 또는 그 이전 내용에 속하므로 이번 호에서는 중복하여 다루지 않는다.

4. 생태계 및 벤더 적응

4.1 ESP32 C3/C6의 ESP-IDF v6.1 적응: 로컬 기본 설정 통과, CI 정적 분석은 업스트림 대기 중 (10-19)

날짜: 2026-10-19 13:43 (댓글 시간)　출처: PR #11870, PR #11844

ESP32 C3/C6를 ESP-IDF v6.1로 업그레이드하고 RISC-V 툴체인을 GCC 15.2로 올리는 제안은 여전히 리뷰 중이다. 작성자는 모니터링 기간 내에 답변하기를: C3와 C6의 로컬 기본 설정은 모두 컴파일을 통과했으며, CI에서 C3의 정적 분석은 여전히 빨간불이 들어와 esp-idf 측의 18번째 변경을 기다려야 하며, 아직 추가 진행은 하지 않았다. 같은 작성자의 ESP32-S3-DevKitM-1 보드 지원(#11844)은 여전히 소프트웨어 패키지 의존성 보완에 막혀 있으며, 최근 답변은 09-29에 멈춰 있다. 두 항목이 병합되면 Espressif의 C3/C6/S3 세 제품 라인을 커버할 수 있다.

4.2 SpacemiT, V100 서버 칩 문서 보완, AI SDK 비전 서브모듈 업데이트 (10-19)

날짜: 2026-10-19 10:45 ~ 22:54 (커밋 시간)　출처: V100 제품 소개, docs-chip 커밋, ai-sdk

K1 BSP가 병합된 같은 날, SpacemiT는 자사 문서 저장소에 연속 세 건을 푸시하여 V100의 제품 소개와 다운로드 링크를 보완했다. 칩 구조 문서는 10-12에 228번째 제안과 함께 신규 추가된 것이며, 이번에 브리핑을 보완한 것이다. 문서 설명에 따르면 V100은 서버급 RISC-V CPU로 포지셔닝된다: 46개 코어는 6개의 샹산 쿤밍후 V2R2와 40개의 X100으로 구성되며, RVA23과 호환되고 최고 주파수 2.4 GHz, Hypervisor 1.0, AIA 및 IOMMU 가상화를 지원하며, 8채널 DDR5-4800, 대역폭 307 GB/s이다. AI SDK 저장소는 같은 날 vision 서브모듈 포인터를 업데이트했으며, 이는 모델 라이브러리 동기화에 해당한다. 이상은 벤더 측 동향으로 RT-Thread 주제 항목에 속하지 않으며, 배경 증거로만 제공한다.

4.3 조직 내 나머지 저장소는 이번 기간 조용, 툴체인과 소프트웨어 패키지 인덱스에 신규 커밋 없음 (10-20)

날짜: 2026-10-20 (확인 시간)　출처: RT-Thread 조직 저장소, packages, Studio sdk-index

조직 수준에서 푸시 시간순으로 확인: 모니터링 기간 내에는 메인 저장소만 푸시가 있었으며(10-19 10:49), rtthread-skills와 smart-build는 10-18에 멈춰 있고, rtthread-specification과 env는 10-17에 멈춰 있으며, packages 소프트웨어 패키지 인덱스의 최근 커밋은 10-14(hpm_sdk v1.13.0)이고, Studio SDK 인덱스는 10-10에 멈춰 있다. 툴체인, 소프트웨어 패키지, Studio 세 라인 모두 이번 기간 신규 내용이 없으며, 이는 메인 저장소가 K1 BSP를 집중적으로 소화하는 리듬과 일치한다.

5. 산업 응용

5.1 온실 환경 모니터링 단말: E907 단일 코어에 LVGL 4페이지 인터페이스, 완전 오프라인 사용 가능 (10-19)

날짜: 2026-10-19 09:35 (게시 시간)　출처: 커뮤니티 기사

2026 임베디드 대회 작품으로, 소형 및 가정용 비닐하우스를 위한 로컬 환경 모니터링 단말이다. 하드웨어는 ArtInChip D12X-DEMO68 개발 보드를 사용하며, 메인 컨트롤러는 Damo Academy XuanTie E907(RV32, 396 MHz, 단정밀도 FPU 탑재)이고, 8 MB PSRAM, 16 MB SPI NOR, 480×272 정전식 터치스크린(GT911)을 갖추며, 센서는 DHT11과 BH1750 두 개뿐이고 Wi-Fi에 연결하지 않으며 클라우드 플랫폼에 의존하지 않는다. 소프트웨어는 RT-Thread 4.1.1과 LVGL 8.3.1 기반으로: 6개 스레드가 12~26 레벨로 계층화되어 있고, 두 개의 메시지 큐가 각각 알람과 인터페이스에 공급되며, 뮤텍스가 상태 스냅샷과 센서 버스를 보호하고, 임계값은 세마포어를 통해 비동기로 LittleFS에 기록된다. 인터페이스는 4개 페이지 캐시 방식 전환을 사용하고, 곡선은 최근 60개 포인트 링 버퍼를 유지하며 세 채널이 세로축을 공유하지 않는다. 알람은 연속 3회 확인과 2°C, 2% RH 히스테리시스를 가지며, 부저는 PWM으로 구동된다. 또한 12개의 MSH 진단 명령을 제공하여 현장에서 샘플링 유효 비트, 터치 좌표, UI 소요 시간을 확인할 수 있다.

6. 요약 및 동향 관찰

6.1 이번 기간 동향

  • 하이엔드 RISC-V 플랫폼이 메인라인에 진입: K1 BSP가 S 모드, MMU, 4코어 SMP 형태로 병합되었고, PCIe/NVMe, HDMI, 멀티미디어 가속과 함께 RT-Thread가 애플리케이션 프로세서급 RISC-V 플랫폼에서의 지원이 「부팅 가능」에서 「주변장치 완비」로 나아갔음을 보여준다.
  • 드라이버 계층이 SoC 패밀리별로 축적: bsp/spacemit/dm이 약 30개의 디바이스 모델 드라이버를 독립 계층으로 분리했으며, K1은 첫 번째 사용자일 뿐이고 이후 동일 계열 칩에서 재사용 가능하며, BSP 디렉터리 구조에 「벤더 계층 + 보드 계층」의 분업이 나타나기 시작했다.
  • 프레임워크가 BSP와 함께 수정: 동일 배치 커밋에서 전원 도메인 프록시 명명, DVFS OPP 중복 검사, RISC-V 원자적 CAS 세 가지 프레임워크 및 아키텍처 수정이 도출되어, 새 플랫폼 통합이 범용 코드의 결함을 역으로 드러내고 있음을 시사한다.
  • 보안 부채 정리가 수정 단계로 진입: 지난 기간의 결함 4건 중 2건(lwp 신호 검증, OFW 심층 사전 검사)에 대해 수정 제안이 제출되었고, tmpfs 절단 결함 1건이 추가되었으며, 유지관리자는 동적 모듈에 대해 「부분 수정은 가능하나 격리는 사용자 공간 필요」라는 경계 판단을 내렸다.
  • 공식 채널은 계속 침묵: 뉴스 인터페이스가 4개월 넘게 업데이트를 중단했고, v5.4.0은 버전 번호만 선행되었으며, 대외 정보는 주로 GitHub와 커뮤니티 작품에 의존한다.
  • 바이너리 펌웨어 규정 준수에 유의 필요: K1 BSP에 벤더 Linux 이미지에서 가져온 RCPU 펌웨어(HDMI 오디오 서비스용)가 내장되어 있으며, 저장소 설명에 체크섬이 제시되고 병합 전 재배포 조건 확인을 권고하고 있다. 이처럼 BSP와 함께 메인라인에 진입하는 벤더 바이너리는 후속 추적이 필요하다.

6.2 한계 및 중복 제거 설명

  • 이번 기간은 24시간 모니터링 기간(10-19 08:00 ~ 10-20 08:00)이며, 월요일이 아니므로 여러 날 병합은 하지 않는다.
  • 지난 기간과의 중복 제거: #10320 Next RISC-V 리팩터링, 보안 결함 4건(#11898, #11882, #11879, #11878), ESP32-C6 SPI 병합, Allwinner F101 BSP, Ruiqing 1.8.4, Env 2.0.3은 모두 지난 기간에 다루었으므로, 이번 기간에는 모니터링 기간 내의 새로운 진전만 기술한다.
  • K1 BSP는 지난 기간에 수록되지 않았는데, 제안이 이번 모니터링 기간에야 병합되었기 때문이다. 이번 기간에는 병합 시간 기준으로 헤드라인으로 분류한다.
  • Google News 중국어 3일 모니터링 기간에는 2건뿐이고 모두 이전 기사이며, 영어 모니터링 기간은 적중이 없고, Ruiqing 7일 조회는 동명의 자동차 뉴스에 묻혔으며, 모두 새 항목이 발생하지 않았다. HN 4건 후보는 모두 threads 오매칭이다.
  • 공식 웹사이트 뉴스 목록 페이지는 프런트엔드 동적 렌더링이라 크롤링 시 빈 껍데기만 얻을 수 있으며, 뉴스는 공식 인터페이스를 기준으로 한다.
  • SpacemiT V100과 AI SDK는 벤더 측 동향으로 RT-Thread 주제가 아니므로 뉴스 항목으로 별도 분류하지 않고 배경으로만 다룬다. 해당 바이너리 펌웨어의 재배포 조건은 이번 라운드에서 검증하지 않았으며 저장소 설명에 따라 표기만 한다.
