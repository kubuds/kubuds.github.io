1. 커널 및 버전 동향

1.1 RT-Thread v5.3.0 정식 릴리스: v5.2.2 이후 첫 버전, 커널 / 컴포넌트 / 디바이스 모델 / 아키텍처 / 도구 / BSP 전 영역 포괄

날짜: 2026-09-10 (18:05 베이징 시간 릴리스)　출처: RT-Thread v5.3.0 Release (ChangeLog.md)

이번 모니터링 기간의 가장 중요한 사건: RT-Thread 메인 저장소가 v5.3.0 정식 버전을 릴리스했다. 이는 2025-10-31에 릴리스된 v5.2.2 이후 첫 정식 버전으로, 약 10개월 반의 간격을 두고 있으며, 최근 1년여 동안 규모가 가장 큰 통합 릴리스이기도 하다. 버전은 프로젝트 메인테이너 Rbb666이 릴리스했으며, 변경 로그(ChangeLog.md)에 263줄이 추가되었고 Kernel, Components, DM, Libcpu, Tools, Action, BSP 7대 영역으로 구성되어 있다.

커널 측(Kernel)은 정확성과 견고성 수정이 주를 이룬다: IPC 및 LWP 대기 경로에서의 타임아웃 웨이크업 소유권 경쟁 상태 수정, 스레드가 반복적으로 서스펜드될 때의 지연 웨이크업, 아이들 스레드 서스펜드 금지, 스레드가 다른 주체에 의해 삭제될 때 보유한 뮤텍스 해제; 스레드 CPU 점유율을 샘플링 윈도우 증분 통계로 변경; 8비트 및 16비트 원자적 연산 지원 추가; 객체 이름 길이 단언을 안전한 절단으로 변경; memheap 불법 해제 및 rt_smem_setname 빈 이름 처리 강화; 그리고 콘솔 출력 활성화 스위치, 인터럽트 훅 포인터 내보내기 추가.

컴포넌트 측(Components)에서 두 가지 구조적 신규 추가가 나타났다. 첫째는 완전히 새로운 클록 프레임워크 clock_time으로, 클록 소스와 클록 이벤트를 분리하고 고해상도 타이머, 부팅 시간 보조 인터페이스 및 외부 설정 타이머 어댑터 계층을 도입하며 기존의 ktime / cputime / hwtimer 구현을 대체하고 동시에 아키텍처, BSP 및 POSIX 시간 통합을 이관한다. 둘째는 ADC V2로, 세션 관리, 시퀀스 읽기, 전압 환산 및 FinSH 명령을 갖추고 DMA 스트림, 최신 프레임과 FIFO 버퍼링, 타이머와 비교기 트리거를 지원하며 기존 ADC 드라이버와 상호 배타적이다. 또한 시리얼 V2는 RX DMA 이벤트 모드 제어를 새로 추가했고, DFS는 9PFS(QEMU 등 가상 머신과 파일을 공유하는 용도)를 새로 추가하고 Elm FatFs를 R0.16으로 업그레이드했으며, 네트워크 측은 선택적 AF_UNIX 스트림 및 데이터그램 소켓(socketpair, SCM_RIGHTS 디스크립터 전달 포함)을 새로 추가했고, WLAN은 WPA3, 기업급 인증, WAPI, OWE, DPP 보안 모드 정의를 새로 추가했으며, USB는 CherryUSB를 v1.6.1로 업데이트했고, Rust 컴포넌트는 ARM / AArch64 / RISC-V 타깃 감지와 SCons / Cargo 통합을 새로 추가하고 스레드, 뮤텍스, 세마포어, 메시지 큐, 메모리, 시간 및 파일에 Rust 래퍼를 제공한다.

디바이스 모델(DM)은 이번 버전에서 가장 큰 구조적 신규 추가 영역이다. 디바이스 트리와 OFW 지원을 확장하고(Cortex-M 타깃에서 활성화), 클록 프레임워크를 재구성하며 regulator / 전원 도메인 / reset / 전원 관리를 확장하고, 동적 전압 주파수 조절(DVFS), ARM SCMI 펌웨어 통합, 하드웨어 스핀락과 하드웨어 캐시 컨트롤러, 원격 프로세서 메시지(RPMSG)와 신뢰 실행 환경(TEE) 지원을 새로 추가했다. VirtIO는 1.2로 업그레이드하고 packed queue, MMIO / PCI 전송을 지원하며 9P, crypto, RNG, SCMI, SCSI 드라이버를 새로 추가했고, 스토리지 측은 UFS, DesignWare AHCI, 범용 MTD 드라이버와 NVMEM을 새로 추가했으며, 네트워크 측은 이더넷 디바이스 모델(MACB / DWMAC)과 IEEE 1588 PTP 클록을 새로 추가했다.

아키텍처 측(Libcpu)에서 RISC-V와 직접 관련된 것은 QEMU virt64 및 Damo Academy XuanTie C 시리즈 / R 시리즈 프로세서에 SMP 지원을 새로 추가하고, Damo Academy XuanTie C908X 플랫폼 지원을 새로 추가하고, C908의 Svpbmt 지원을 보완하고 C906 / C908의 캐시 속성과 페이지 테이블 속성을 수정하고, PLIC 인터럽트 처리 순서를 수정한 것이다. Cortex-R52 측은 이 보고서가 어제 기록한 Renesas RZ/N2L 인터럽트 중복 분배 수정을 포함했다.

1.4 Renesas SCI SPI 런타임 구성 및 전송 오류 수정 병합 (PR #11792)

날짜: 2026-09-10 (16:23 베이징 시간 병합)　출처: RT-Thread/rt-thread commits (PR #11792)

지난 리포트에서 「신규 오픈 및 지속 업데이트」로 분류했던 Renesas SCI SPI 수정이 이번 모니터링 기간에 정식 병합되었다. 변경은 bsp/renesas/libraries/HAL_Drivers/drivers/drv_sci.c 단일 파일에 집중되었으며, 두 커밋 합계 +254/-193(기능 커밋 +90/-41, 이어서 clang-format 포맷팅 +164/-152)이다. PR은 09-09 17:25에 생성되어 09-10 16:23에 병합되었으며, 약 23시간이 소요되어 같은 Renesas 방향이면서 리뷰가 월을 넘긴 klibc와 clock_timer 두 장기 PR보다 처리 속도가 현저히 빨랐다.

수정 내용은 RZ/N2L EtherKit의 SCI SPI 루프백 점검에서 발견된 일련의 결함을 대상으로 한다. RZ 분주 인터페이스가 false를 분주 결과 포인터로 전달하면서 FSP 설정의 실제 클럭 소스를 사용하지 않았고, 런타임 설정이 FSP에 안정적으로 전달되지 않았으며 중복 설정 시 기존 인스턴스가 제대로 닫히지 않았다. 설정 과정에서 RT-Thread의 비트 폭 단위를 bit에서 byte로 잘못 변경했고, 송수신 대기 타임아웃 또는 오류 발생 후에도 전송 길이를 반환하여 호출자가 성공으로 오판하게 했다. 해결 방안은 각 SCI 버스마다 영구적인 쓰기 가능 FSP 설정 복사본을 저장하고, 각 분기의 분주 호출을 수정하며, 재설정 전에 이미 열린 인스턴스를 명시적으로 닫고, 비트 폭 단위를 bit로 유지하며, 타임아웃 또는 오류 시 전송을 종료하고 이벤트와 버스 소유권을 정리하여 재시도가 가능하도록 하는 것이다. 이 수정은 v5.3.0 변경 로그(Renesas 섹션)에 포함되었다.

2.1 RT-Thread Env v1.5.3 릴리스: Env 도구의 2024년 4월 이후 첫 버전

날짜: 2026-09-10(17:57 베이징 시간 발표)　출처: RT-Thread/env v1.5.3 Release

커널과 같은 날, RT-Thread의 개발 환경 도구 Env가 v1.5.3을 발표했다(Rbb666 발표). 이전 버전은 2024-04-28의 v1.5.2로, 약 2년 4개월 만이다. 이 버전은 Env 도구 현대화 개편의 일련의 변경 사항을 집약한 것으로, Xiong Puxiang(BernardXiong)과 ComerLater, supperthomas, mysterywolf 등의 기여로 이루어졌다: sdk 명령을 새로 추가하고 PowerShell에서 menuconfig, sdk, system 등의 명령을 제공하여 기존 ps1 스크립트 방식을 대체했으며, kconfiglib를 명령줄 진입점으로 도입하고 의존성 설치를 보완했고, Ubuntu에서 pip를 통한 Env 설치를 지원하며, 환경 정보 파일 env.json과 버전 번호 읽기를 추가하고, ebuild(Embedded Build System)를 새로 추가했으며, install_arch.sh를 추가하고, 설치 스크립트에 IP 기반으로 Tsinghua 소스 또는 기본 소스를 판단하여 사용하는 기능과 자동 모드를 지원하도록 했다. 동시에 tar 처리, pkgs –update / –update-force, git checkout 브랜치, menuconfig –silent, VS Code 콘솔 kconfiglib 오류 등의 문제를 수정하고, arm-none-eabi, gdb, qemu 등 사전 패키지에 대한 패키징을 제거했다.

Env가 커널과 같은 날 릴리스된다는 것은 개발자 도구와 운영체제 버전을 함께 업데이트할 수 있음을 의미하며, 이는 v5.3.0 “툴체인 + 커널” 동시 제공의 일환이다.

2.3 커뮤니티 공유: Edgi-Talk 개발 보드에서 처음부터 직접 구현한 필기 숫자 인식(09-10)

날짜: 2026-09-10　출처: EE Times China “필기 숫자 인식 직접 구현｜오픈소스 프로젝트 공유”(Google News 집계 항목)

업계 미디어 측 모니터링 기간 내 RT-Thread와 직접 관련된 유일한 기술 공유 글: 작성자가 Edgi-Talk 개발 보드(Infineon PSoC Edge E84 듀얼코어 플랫폼 + RT-Thread Studio)에서 처음부터 엔드투엔드 필기 숫자 인식 애플리케이션을 구현했으며, 마우스로 직접 학습 데이터를 수집하고, 네트워크 모델을 직접 작성 및 학습한 뒤, 모델을 디바이스 측 추론에 배포하는 전체 경로를 포함한다. 이 글은 topic:rt-thread 아래 커뮤니티 저장소 p32qc3/Edgi-Talk(PSoC Edge 듀얼코어 환경 음향 인식 및 멀티모달 경보 시스템, 09-10 푸시 있음)와 동일한 개발 보드를 가리키며, RT-Thread의 “MCU + NPU/엣지 AI” 방향 커뮤니티 활성도의 관측 창으로 삼을 수 있다.

3. 생태계 및 벤더 적응

3.1 소프트웨어 패키지 인덱스 3건 업데이트: Lely CANopen 패키지 추가, CanopenNode 모듈화 Kconfig 리팩터링, 파라미터 저장 커스텀 backend(PR #2038)

날짜: 2026-09-11(11:09 베이징 시간 병합)　출처: RT-Thread/packages commits(PR #2038)

모니터링 기간 말미(본 보고서 수집 약 9분 전) 소프트웨어 패키지 인덱스 저장소에 19개 파일 +2621/-1580의 집중 업데이트가 병합되었다(wdfk-prog 커밋). CANopen 및 파라미터 저장 관련 패키지 설정 세 가지를 동기화했다:

  • canopen-lely 패키지 인덱스 신규 추가: Lely CANopen의 RT-Thread 이식 버전을 package index에 추가하여 single-owner EV/IO2 런타임, RT-Thread CAN 통합, 클래식 CAN 및 선택적 CAN FD, 자동 런타임 초기화, owner 스레드 설정, 로그, 시작/정지 설정, 그리고 선택적 CANopen 마스터(Master) 서비스를 제공한다. 해당 런타임은 LELY_NO_THREADS=1 방식으로 동작하며, Lely의 EV / IO2 / CANopen 객체는 전용 RT-Thread owner 스레드가 직렬로 접근하고, 비동기 CAN, 타이머, 상태 이벤트는 해당 owner가 처리하도록 전달된다.
  • CanopenNode Kconfig 모듈화 리팩터링: 기존에 misc/CanopenNode/Kconfig에 집중되어 있던 설정을 현재 이식 구조에 맞게 분리하여, core 프로토콜 설정, RT-Thread 런타임 설정, 스토리지 설정, 객체 사전 및 demo/test 설정, CiA 401 디바이스 서브프로토콜, CiA 402 디바이스/컨트롤러 서브프로토콜, 그리고 각 profile 전용 설정을 포괄하며, Kconfig에 따라 스토리지 구현을 선택하는 SCons 소스 파일 선택을 새로 추가했다.
  • autogen_parameter_manager에 애플리케이션 사용자 정의 스토리지 backend 추가: AUTOGEN_PM_BACKEND_APP_DEFINED 옵션을 새로 추가하여, 선택 시 패키지 자체의 scalar backend를 활성화하지 않고 애플리케이션이 강한 심볼 par_store_backend_get_api()를 제공하도록 한다(필요 시 par_store_backend_bind()도 재정의 가능). 기존 기본 backend는 그대로 유지되어 기존 프로젝트에 영향을 주지 않는다.

09-01에 병합된 CANopenNode 인덱스까지 더하면, CANopen 프로토콜 스택은 RT-Thread 소프트웨어 패키지 차원에서 “Lely(마스터 및 EV/IO2 런타임 지향) + CanopenNode(슬레이브 지향)”의 이중 스택 선택지를 형성했으며, 이는 산업 현장 버스 및 차량 방향 소프트웨어 패키지화의 중요한 보강이다.

4. 산업 응용

4.1 RT-Thread, 2026 제8회 Jinji Award 최우수 기술 실무 응용상 신청, 신청 기술은 Chengxuan 차량 기본 소프트웨어 운영체제 (09-11)

날짜: 2026-09-11 (09:41 베이징 시간)　출처: Gasgoo (Google News 집계 항목) (2026 제8회 Jinji Award 설명)

상하이 RT-Thread는 “Chengxuan 차량 기본 소프트웨어 운영체제”로 2026년 제8회 Jinji Award “최우수 기술 실무 응용상”을 신청했으며, 신청 분야는 자동차 소프트웨어와 인공지능이고, 항목은 Gasgoo가 게시했습니다. Jinji Award는 Gasgoo가 시작했으며 “중국 자동차 신공급망 100강”에 초점을 맞추고, 2026년 제8회는 “중국 솔루션”으로 글로벌을 향한다는 것을 연간 주제로 삼아 ADAS/AD, 스마트 콕핏, 스마트 섀시, 차량용 칩, 자동차 소프트웨어와 인공지능, 파워트레인 전기화 및 충전/배터리 교환과 열관리, 바디 및 내외장, 신소재와 첨단 제조, 임바디드 인텔리전스와 융합 기술 등의 트랙을 포괄하며, 평가 기준은 기업 신청, 산업 데이터, 전문가 심사, 시장 검증을 포함합니다. RT-Thread는 이전에 2025년 제7회 Jinji Award “최우수 기술 실무 응용상”을 수상한 바 있으며, 이번은 동일 상에 대한 재신청입니다.

심층 분석: Chengxuan은 RT-Thread가 자동차 전자를 대상으로 하는 차량 기본 소프트웨어 제품 라인으로, 2022년 “Chengxuan 차량 융합 소프트웨어 플랫폼”으로 발표되며 차량 운영체제 시장 진출을 표시했습니다. 제품 구성에는 안전형 실시간 시스템 RT-Thread Secure Auto, 마이크로커널 운영체제 RT-Thread Smart Auto, 가상화 시스템 vmRT-Thread Hypervisor와 vmBUS 통합 메시지 버스가 포함되며, 바디, 섀시, 파워트레인, 스마트 드라이빙, 콕핏 등 시스템 제어 시나리오를 포괄합니다. 그중 멀티코어 MCU 가상화는 비교적 새로운 기술 포인트입니다. RT-Thread는 기능 안전에서 ISO 26262 ASIL D, IEC 61508 SIL 3, EN 50128 SIL 4 등의 인증을 통과했으며, 협력 칩 기업으로는 Infineon, NXP, Texas Instruments, STMicroelectronics, Black Sesame Intelligence, ChipON 등이 있습니다. 이 항목은 브랜드 및 산업 평가 유형 동향에 속하며, 모니터링 기간 내 신제품 출시나 양산 지정 정보는 포함하지 않습니다.

5. 요약과 트렌드 관찰

당일 핵심

  • 모니터링 기간의 핵심 이벤트는 RT-Thread v5.3.0 정식 릴리스로, 이는 2025-10-31의 v5.2.2 이후 첫 정식 버전이며, 변경 로그에 263줄이 추가되어 Kernel, Components, DM, Libcpu, Tools, Action, BSP 7대 영역을포괄하며, 지난 1년여 중 최대 규모의 통합 방출이다.
  • 릴리스 마무리 세 가지 작업이 당일 저녁에 집중적으로 완료되었다: 변경 로그를 master에 병합하고 메인라인 버전 번호를 v5.3.1로추진(PR #11795), v5.3.0 beta 단계 수정 사항 백포트(PR #11796, 14개 커밋), 그리고 Release 객체발표(18:05).
  • 같은 날 Env 도구가 v1.5.3을 릴리스(2024년 4월 이후 첫 버전)하여, 커널과 개발 환경이지원릴리스을형성했다.
  • 모니터링 기간 내 org: RT-Thread 관련 커밋은 총 7건(메인 저장소 4건 + 소프트웨어 패키지 인덱스 3건)이며, 메인 저장소에 신규 PR 1건이 추가되고 3건이 병합되었으며, 소프트웨어 패키지 인덱스에 1건 19개 파일의 대규모 변경이 병합되었다; 소프트웨어 패키지 측에 Lely CANopen 패키지가 신규 추가되어 CANopen이 이중 스택 선택을형성했다.
  • 공식 뉴스 API는 22일 연속 신규 추가가 없으며, v5.3.0은 공식 보도자료 채널을 타지 않았고, 대외 전파는 여전히 GitHub을주 전장으로 하고 있으며, 미디어 측 해석 기사는 아직 없다.
  • 업계 측 모니터링 기간 내 유일한 신규 추가는 Ruiside가 Chengxuan 차량 기본 소프트웨어 운영체제로 2026 제8회 진지장 최고 기술 실천 응용상을 신청한 것이다.

최근 3일 추세(09-09 ~ 09-11)

메인라인 판단

  • 버전 리듬: 메인라인은 v5.2.2 이후 약 10개월 반 동안 정식 릴리스가 없었고, 이번에 일괄적으로 v5.3.0을 방출했으며, 릴리스 당일 바로 v5.3.1로추진하고 beta 수정을 백포트한 것은 ‘정식 버전 릴리스 → 메인라인 버전 번호 갱신 → 수정 백포트’의 폐쇄 루프가 이미형성되었음을 보여주며, 이후 마이너 버전 리듬은 빨라질 수 있다.
  • 디바이스 모델(DM)은 v5.3.0에서 가장 구조적인 신규 영역이다: 디바이스 트리와 OFW, 클록과 전원 프레임워크 재구성, DVFS, ARM SCMI, RPMSG와 TEE, VirtIO 1.2, UFS/AHCI, IEEE 1588 PTP가 집중실현되어, RT-Thread가 Cortex-A와 RISC-V 고성능 플랫폼 방향으로의 포지셔닝을 강화하는 것을 가리키며, 단지 MCU 시나리오만을 위한 것이 아니다.
  • RISC-V 측: Damo Academy XuanTie C908X 플랫폼과 C 시리즈 / R 시리즈 SMP 지원이 정식 버전에 진입했으며, 모니터링 기간 내 여전히 리뷰 중인 c908 rt-smart / QEMU MMU 관련 PR(#11775)과 동일한 진화 라인을구성한다.
  • CANopen 생태계 형성: Lely(마스터와 EV/IO2 런타임)와 CanopenNode(슬레이브) 이중 스택이 소프트웨어 패키지 계층에서실현되었고, 메인 저장소의 CAN 드라이버 라이프사이클 재구성이 리뷰 중이며, 산업 및 차량용 필드버스는 최근의 지속적 투자 방향이다.
  • 리뷰 소화 리듬은 여전히 분화되어 있다: 릴리스 관련과 문서류 변경은 수 시간 내 완료(#11795 약 36분, #11792 약 23시간)되는 반면, 커널, 드라이버, 메모리 관리류 장기 PR(#11228, #11313, #11689, #11772)은 여전히 주 단위심지어 월 단위로 체류하고 있다.

한계 설명

  • 공식 뉴스 센터와 공식 API는 모니터링 기간 내 버전 릴리스 보도자료가 없었으며(API 22일 연속 신규 추가 없음), v5.3.0의 대외 전파는 당분간 GitHub Release와 변경 로그가 주를 이루고, 미디어 측 해석 기사는 아직 나타나지 않았으므로, 본 보고서의 버전 의의에 대한 판단은 주로 변경 로그 자체에 근거한다.
  • Google News 영어 쿼리는 ‘RT-Thread’에 대해 지속적으로 Rotten Tomatoes 영화 평점류 노이즈가 검출되며(‘RT’가 분리 매칭됨), 중국어 측 ‘Ruiqing’ 쿼리는 Geely i-HEV Zhiqing 하이브리드 자동차 보도에 대량 오염되어, 모두 제목 의미에 따라 제외하고 집계하지 않았다.
  • EE Times China 원사이트는 본기 네트워크에서 접근 불가하여, 2.3 항목의 본문 세부 사항은 공개 링크와 집계 요약에서 취했으며, 원문을 문장별로 대조하지 않았다.
  • Ruiside 진지장 신청 항목의 원본 페이지는 Gasgoo 기업 정보류 투고이며, 본 보고서는 집계 링크를 인용한다; 신청 내용은 기업 자술 성격으로 제3자 검증을 거치지 않았다.
