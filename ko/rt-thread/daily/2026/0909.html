날짜: 2026-09-08 (16:15 베이징 시간 병합, 즉 08:15:21Z)　출처: RT-Thread/rt-thread commits (PR #11785)

어제 리포트에서 리뷰 대기열에 올렸던 #11785 [bsp][nxp] Add FRDM-MCXC162 BSP support (yandld 제출)가 오늘 오후 정식으로 master에 병합되었다. 해당 PR은 09-07 저녁에 생성되었으며 (어제 수록 시점에는 여전히 리뷰 중이었고 오늘 아침에도 업데이트가 있었음), 단 3일 만에 리뷰와 병합이 완료되어 속도가 빨랐다. 2.1 elexcon 2026 선전 전시회 오늘 개막, Ruiside가 「AI 하드웨어 풀 패키지」로 참가

날짜: 2026-09-09(개막 첫날)　출처: elexcon 2026 선전 국제 전자전 겸 임베디드 전시회(공식 채널 08-30 예고, 수집 완료)

elexcon 2026 선전 국제 전자전 겸 임베디드 전시회가 오늘(09-09 ~ 09-11) 선전 국제 컨벤션 센터(바오안 신관)에서 개막했으며, Ruiside가 참가한다(부스 동향은 이전 08-30 리포트에 수집됨). 이전 공식 위챗 계정에서 예고한 「Gino Pi 플래그십 메이커 플랫폼」 신제품 첫 공개 카운트다운(어제 추가 수록)이 전시 기간과 맞물려, 부스 첫 공개 신제품인지는 오늘 현장 정보로 확인이 필요하다. 본 리포트 생성 시점(개막 첫날 오전)까지 미디어 측의 전시회 현장 보도는 없다(gnews elexcon 관련 조회 0건, 개막 첫날 오전의 정상적 지연). 공식 대외 콘텐츠는 전시 기간에 집중적으로 공개될 것으로 예상되며, 내일 리포트에서 첫날 동향을 후속 보도할 예정이다.

2.2 2026 상하이 오픈소스 소프트웨어 응용 혁신 대회: Ruiside 오늘 17:00 라이브로 AI 품질 검사 문제 해설

날짜: 2026-09-08(다중 플랫폼 예고) ~ 2026-09-09(라이브 진행)　출처: OSChina《RT-Thread 전문가 해설: AI 산업 품질 검사 도입의 마지막 1킬로미터를 명확히 설명》, CSDN techforward

Ruiside가 「2026 상하이 오픈소스 소프트웨어 응용 혁신 대회」(오픈소스 중국 주최, 《상하이시 오픈소스 강화…》 정책 이행, 「오픈소스로 실천」 테마, AI+산업 소프트웨어 / 지능형 컴퓨팅 클라우드 / 오픈소스 AI 도구 세 개 트랙)에 출제한 문제가 라이브 해설 단계에 진입했다: 오늘 17:00, RT-Thread Ruiside 산업 사업부 솔루션 책임자 궈잔신이 「OSC 오픈소스 커뮤니티」 비디오 채널 라이브룸에 출연하여, 출제 배경과 AI 품질 검사 도입의 「마지막 1킬로미터」 병목 지점을 현장에서 해설한다. 문제는 즉 09-03 공개되고 어제 이미 수록된 《루이칭 산업 개발 플랫폼 기반 사전 학습 비전 모델 경량화 적응 및 로우코드 배포 최적화》이다: 기반은 루이칭 산업 개발 플랫폼(고실시간 산업 커널 + NCNN 추론 프레임워크, YOLOv3 범용 객체 검출 기본 지원)이며, 데이터 수집 정규화, 결함 샘플 온라인 라벨링, 사용자 정의 모델 양자화와 연산자 적응, 로우코드 원클릭 배포의 네 단계 툴체인을 보완하도록 요구하며, 플랫폼 실시간 커널은 개조하지 않는다. 대회 접수 마감은 10월 11일, 결선은 10월 24일 상하이에서 개최되며, 수상 프로젝트는 100만 위안 상금 풀(현금, Token, 대형 모델 API 등)을 나누고 상하이시 오픈소스 프로젝트 육성 공정에 선정될 기회도 얻는다. 이는 Ruiside가 지역 오픈소스 대회를 통해 루이칭 산업 플랫폼 생태계와 개발자 모집을 추진하는 두 번째 핵심 노드이다(문제 공개 → 문제 라이브 해설 → 접수 마감 → 결선). 오늘 개막한 elexcon 2026과 함께 이번 주 대외 활동의 두 축을 이룬다.

2.3 공식 뉴스 API 20일 연속 신규 없음

날짜: 2026-09-09　출처: RT-Thread 공식 뉴스 API

공식 뉴스 API(rt_org 분류)는 여전히 5건의 기존 항목이며, 최신은 여전히 2026-06-17 아부다비 투자 포럼 보도로, 20일 연속 신규가 없다. 공식 웹사이트 뉴스 채널의 최근 실질적 업데이트는 모두 위챗 계정 / 제3자 플랫폼 채널로 이루어졌으며(예: 2.1, 2.2의 예고와 라이브), 공식 웹사이트 뉴스 섹션 자체는 20일째 침묵 중이다. 오늘은 elexcon 2026 개막일이며, 만약 전시회 정보가 공식 웹사이트 뉴스 형태로 공개된다면 이 API 침묵의 종료 신호가 될 것이다.

3. 생태계와 제조사 적응

3.1 canopennode-rtt 모니터링 기간 내 CiA401 기능 세 건 병합: RT-Thread 장치 프로파일 지원, 다중 장치 노드 논리 장치, MSH 테스트 제어

날짜: 2026-09-08(17:56 베이징 시간 일괄 병합, 즉 09:56:22Z)　출처: wdfk-prog/canopennode-rtt commits

외부 생태계 저장소 canopennode-rtt(CANopen 포팅, wdfk-prog 유지보수)가 모니터링 기간 내 새로운 기능 커밋 세 건을 일괄 병합했다(author 시간 09-07 ~ 09-08 오전, 09-08 저녁 일괄 병합):

  • feat[canopennode][cia401]: add RT-Thread device profile support: CiA401(I/O 장치 프로파일)에 RT-Thread 지향 장치 프로파일 지원 레이어 추가;
  • feat[CiA401][device]: support logical devices in multiple-device nodes: 다중 장치 노드 시나리오에서 논리 장치 지원(하나의 노드 내에 여러 논리 장치 탑재);
  • feat[CIA401][RTT]: add MSH bench controls for device testing: MSH 명령줄 벤치마크 테스트 제어 추가로 장치 테스트 편의성 제공.

09-06의 CiA401 아날로그 이벤트 2건과 Fail-Safe 적용(이미 수록)에 이은 두 번째 CiA401 기능 배치로, CANopen CiA401 디바이스 프로파일의 RT-Thread 측 이식이 「프로토콜 프레임 수준」에서 「디바이스 프로파일 + 다중 논리 디바이스 + 테스트 툴체인」 수준으로 진전되었음을 의미하며, 기능 범위가 지속적으로 확대되고 있다. wdfk-prog는 동시에 공식 저장소에서 CAN 드라이버 라이프사이클 리팩터링(#11779)을 추진하고 있으며, 「외부 생태계 이식 + 공식 프레임워크」의 이중 트랙 병행은 현재 RT-Thread CAN/CANopen 방향에서 가장 활발한 기여자임을 보여준다.

3.2 packages 인덱스 2건 업데이트: Tencent IoT SDK 설정 조정, autogen_parameter_manager 설정 항목 리팩터링

날짜: 2026-09-08 (17:56 / 18:16 베이징 시간)　출처: RT-Thread/packages commits (5d983b53, 866a20b5)

packages 소프트웨어 패키지 인덱스 저장소가 09-01 이후의 정적 상태(CANopenNode 인덱스 추가 후 일주일 연속 커밋 없음)를 깨고, 모니터링 기간 내 2건이 추가되었다:

  • Update Tencent IoT SDK package configuration (#2034): Tencent Cloud IoT SDK 소프트웨어 패키지의 Kconfig 및 package.json 설정 업데이트(iot/iot_cloud/tencent-iot-sdk)로, 클라우드 플랫폼 SDK 소프트웨어 패키지의 정기적 설정 후속 조치에 해당;
  • refactor(autogen_parameter_manager): Kconfig 설정 옵션 기본값 조정: misc/autogen_parameter_manager 소프트웨어 패키지에서 RT_USING_HEAP 및 RT_USING_CAN에 대한 강제 의존성 선택을 제거하고, AUTOGEN_PM_USING_NVM, AUTOGEN_PM_NVM_OBJECT 기본값을 y에서 n으로 변경 — 소프트웨어 패키지 도입 장벽을 낮추어 전원 관리 파라미터 생성기를 힙/CAN 없는 설정에서도 선택 설치 가능하게 함. 이 리팩터링 방향은 최근 여러 소프트웨어 패키지의 「의존성 제거, 유연성 증대」 조정과 일치한다(09-01 CANopenNode 등 신규 인덱스 추가 흐름과 대비).

3.3 생태계 검증: awtk 푸시는 범용 GUI 개선으로 RT-Thread 전용이 아니므로 미수록

날짜: 2026-09-09　출처: zlgopen/awtk commits

fetch 기간 내 zlgopen/awtk가 감지되었으나(09-09 00:23Z 푸시), 커밋 내용을 검증한 결과 combo_box 상호작용 개선, 중복 bsearch 코드 정리, emitter_dispatch_log 최적화 등 AWTK 프레임워크의 범용 GUI 변경사항으로 RT-Thread 전용과 직접적 관련이 없어(어제 동일 저장소 푸시 검증 결론과 일치) 제외하여 미수록. topic:rt-thread 생태계 저장소의 최근 7일 신규 push는 이 한 건뿐으로, 생태계 저장소 측은 낮은 활성도를 유지하고 있다.

4. 산업 응용

신규 적용 사례 보도 없음. 모니터링 기간 내 신규 산업 응용/적용 사례 뉴스 없음; 산업 측면에서 가장 실질적인 움직임은 2.2에서 언급한 Ruiside 산업사업부의 오늘 17:00 AI 산업 검사 경진대회 문제 해설 라이브 방송 — Ruiqing 산업 플랫폼(산업용 커널 + NCNN + YOLOv3)이 「AI 검사 최종 1km」를 향한 툴체인 보완 요구에 대응하는 것으로, Ruiside의 산업 검사 방향이 제품에서 개발자 생태계로 이어지는 체계적 배치이며, 그 결선(10-24 상하이)에서 나오는 우수 적응 방안이 플랫폼 역량에 환류될 가능성이 있다. elexcon 2026(산업/로봇/자동차 전자 섹터, 오늘 개막) 현장 동향이 다음 산업 콘텐츠 모니터링 기간이며, 내일 후속 진행.
