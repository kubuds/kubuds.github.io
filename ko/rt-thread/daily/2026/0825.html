1.1 master 복귀 머지: Renesas RA8D1 Vision Board Keil 플래시 설정 수정

날짜: 2026-08-24 (17:10 베이징 시간)　출처: RT-Thread/rt-thread commit 5d19f815

메인 저장소 master 모니터링 기간 내 신규 머지 1건: [renesas][ra8d1] Fix Keil flash download configuration, 커뮤니티 개발자 CYFS가 커밋하고 핵심 메인테이너 Rbb666이 08-24 17:10 (UTC 09:10)에 머지. 변경 범위는 bsp/renesas/ra8d1-vision-board/ 하위 template.uvoptx (2곳)와 template.uvprojx (4곳), 즉 RA8D1 Vision Board 프로젝트 템플릿 내 Keil (MDK) Flash 다운로드 알고리즘 설정 수정으로, BSP 템플릿 가용성 수정에 해당하며 커널에는 영향 없음. 해당 커밋은 08-21 NXP RT1180 BSP 대규모 머지 (+3579줄) 이후 master의 첫 신규 머지로, 브랜치 생성 후 정리 기간 종료 및 머지 채널 복귀를 의미함; v5.3.0-beta 브랜치 (08-24 생성)는 현재 여전히 master와 동일 지점으로 독립 커밋 없음.

2. 공식 및 커뮤니티 활동

2.1 RISC-V 기술 살롱@창사역: 슝푸샹(Xiong Puxiang) 연설 「Chengxuan」 차량 규격 및 AI 뉴 패러다임

날짜: 2026-08-24 (보도 게재 11:26 베이징 시간; 행사는 08-18 14:00-17:00 개최)　출처: EE Times China (RT-Thread 공식 칼럼)

2026 RISC-V 시티 투어·기술 살롱@창사역 (후난성 반도체 산업 협회, Nuclei, 후난 융촹웨이 주최, 창사 웨루구 Four Points by Sheraton 호텔) 사후 보도가 08-24 게재되었으며, 주제는 RISC-V의 AI, 산업 제어, 항공우주 분야 적용에 초점. RT-Thread 창립자 겸 CEO 슝푸샹(Xiong Puxiang)이 초청되어 《RISC-V에 뿌리내려 지혜롭게 멀리 나아가다——RT-Thread의 생태계 실천, 차량 규격 “Chengxuan”과 AI 뉴 패러다임》을 연설, 핵심 정보량이 상당함: 첫째, 생태계 규모 데이터——글로벌 누적 설치량 25억 대 초과, 활성 개발자 커뮤니티 30만 명 초과, 서비스 기업 1만 개 초과; RISC-V 측은 2018년부터 선제적으로 적응을 시작하여 Nuclei, GigaDevice, Canaan, XuanTie, HPMicro, WCH 등 수십 개 제조사의 100여 개 제품에 깊이 적응, 공식 및 커뮤니티 공동 유지보수 BSP 30여 개. 둘째, 상용화 및 기능 안전——RT-Safety 운영체제는 IEC61508 SIL3, EN50128 SIL4 인증 통과, 이를 기반으로 한 Chengxuan 차량 제어 시스템은 ISO26262 ASIL D 인증 통과, AUTOSAR CP 호환, BSW 설정, 코드 생성 도구 및 가상 ECU 개발 환경 지원. 셋째, AI 전략——RT-Thread AI Kit 원스톱 MCU 측 AI 배포 플랫폼 출시 (모델 접속, 최적화, 백엔드 변환부터 프로젝트 통합 전 과정, 프루닝/양자화/캘리브레이션), 및 Env + Agent 지능형 개발 패러다임 예고, 향후 자율 인지 및 의사결정 능력을 갖춘 AI Agent로 진화 예정. 해당 보도는 모니터링 기간 내 유일한 뉴스 측 신규 사항이며, 공식 대외 메시지의 집중 업데이트임.

2.2 공식 뉴스 API 5일 연속 신규 항목 없음, 8/27 Ruiyi Workshop D-2

날짜: 2026-08-25　출처: RT-Thread 공식 뉴스 API / EE Times China (Google News 경유)

공식 뉴스 API(rt_org 카테고리)는 여전히 5건의 이전 항목이며, 최신은 2026-06-17 아부다비 투자 포럼 보도로 약 2개월 지연, 5일 연속 신규 항목이 없다. news / activity 카테고리 인터페이스는 계속 “카테고리 데이터 없음”을 반환한다. 미디어 측면에서 8월 27일 상하이 “Ruiyi 산업 플랫폼 Workshop: EtherCAT 실시간 제어와 산업 솔루션 실전”이 2일 앞으로 다가왔으며, Ruiyi 7일 기간 조회는 여전히 08-18 등록 / 08-19 DSMC+FPGA / 08-21 카운트다운 이전 글만 히트하고 신규 예열은 없으며, 나머지는 Geely Smart Engine 하이브리드, Ford Lingrui 등 분절 단어 노이즈다. 이 Workshop은 이번 주 가장 주목할 만한 실착용 관찰 지점이다.

3. 생태계와 벤더 기술 적용

3.1 packages 인덱스 하루 세 번 연속 업데이트: BMI270 IMU 드라이버 / LiteType 폰트 엔진 / AI Agent 멀티모달

날짜: 2026-08-24 (13:29 ~ 17:35 베이징 시간)　출처: RT-Thread/packages commits

소프트웨어 패키지 인덱스 저장소 packages의 모니터링 기간 내 3개 PR이 머지되어 이전 일주일 이상의 침묵(마지막 머지 08-21 09:24)을 깼다:

  • bmi270 (#2026, 17:35 머지): BMI270 6축 IMU 드라이버 소프트웨어 패키지 추가, Mahony AHRS 자세 융합 내장, I2C 지원(장치 주소 0x68/0x69 선택 가능), RT-Thread sensor 장치(/dev/acce_bmi)로 등록해 sensor 프레임워크에 연결 가능. Bosch BMI270은 TWS/웨어러블/로봇 등 저전력 시나리오에서 흔하며, 센서 주변장치 패키지 보완에 해당;
  • LiteType (#2020, 13:42 머지): multimedia 카테고리 경량 임베디드 폰트 엔진 패키지 추가, 동시에 패키지 저장소를 Gitee에서 GitHub으로 마이그레이션하여 국제 개발자의 접근성 향상;
  • ai/Agent (#2022, 13:29 머지): ai/Agent 패키지(08-11 추가된 경량화 agent 프레임워크) 업데이트, 이번 머지에서 멀티모달 지원과 채팅 기록 트리밍 기능 추가, 엣지 agent 프레임워크가 멀티모달 입력으로 진화.

세 가지 머지 방향(센서, 멀티미디어 렌더링, 엣지 AI agent) 모두 생태계 측면의 증분 보완이며, 공식 “실시간+지능형” AI OS 기조와 호응한다.

3.2 canopennode-rtt 브랜치 개발 LSS 시작 지속성, 스토리지 백엔드와 AT24CXX 분리

날짜: 2026-08-24 18:34 ~ 2026-08-25 09:43　출처: wdfk-prog/canopennode-rtt 브랜치 feat/lss-precan-persistence

어제 상세 보도한 CANopenNode 통합 패키지(08-24 11:09 main에 EEPROM 스토리지 진단 머지)가 오늘 브랜치 개발로 전환: feat/lss-precan-persistence 브랜치에서 연속 커밋 feat[canopennode][lss]: add backend-neutral startup persistence(08-24 18:34), 스토리지 진입점 단순화 리팩터링(08-24 19:10), EEPROM provider와 AT24CXX 분리 리팩터링(08-25 09:43 브랜치 tip). 방향은 CANopen 노드 계층 설정 서비스(LSS, CiA 305)의 시작 지속성: EEPROM 스토리지 백엔드를 provider로 추상화하고 AT24CXX 특정 소자 바인딩에서 벗어나, LSS 파라미터 사전 스캔과 전원 투입 복구를 위한 토대를 마련. 기능은 아직 main에 머지되지 않았으며 진행 중 개발에 해당. 08-17 이후 NMT 하트비트 감시 마스터, SDO 블록 전송, ASCII 게이트웨이 등 일련의 커밋과 함께, 이 서드파티 패키지의 산업 제어 CANopen 방향 심화는 계속되고 있다.

4. 산업 응용

4.1 모니터링 기간 내 신규 독립 보도 없음, 최근 3일 동향 회고

날짜: 2026-08-23 ~ 2026-08-25　출처: 각 항목 참조

산업 응용 측 모니터링 기간 내 새로운 독립 공개 보도 없음. 최근 3일 동향 회고:

  • v5.3.0 버전 주기 시작(08-24): beta 브랜치 생성은 10개월 만에 첫 신규 버전 주기 개시를 의미하며, 산업 제어/네트워크(AF_UNIX) 등의 기능이 v5.3.0 정식 릴리스와 함께 배포될 예정;
  • NXP i.MX RT1180 BSP 대규모 업데이트에 EtherCAT 포함(08-21): 산업 제어 실시간 버스 기능이 NXP 크로스오버 MCU 플랫폼에 안착(+3579줄, HyperRAM/멀티코어/rpmsg-lite/NetC 지원), RuiyiAI 산업 플랫폼과 이중 라인 형성;
  • RuiyiAI 산업 플랫폼 Workshop 임박: 8월 27일 상하이 「EtherCAT 실시간 제어와 산업 솔루션 실전」이 이제 2일 남음(08-25 확인), 이번 주 가장 주목할 만한 현장 적용 관찰 포인트;
  • CANopen 생태계 제3자 적용 심화(08-17 → 08-25): canopennode-rtt 연속 업데이트로 NMT/SDO/저장 진단 커버, LSS 부팅 영속화 브랜치 개발 개시, 산업 현장 버스 방향 지속 활발.

5. 요약 및 동향 관찰

  1. master 병합 채널 복구: Renesas RA8D1 Vision Board Keil 플래시 설정 수정(08-24 17:10)은 NXP RT1180 대규모 병합 이후 첫 신규 커밋으로, v5.3.0-beta 브랜치 생성 후 정리 기간 종료.
  2. 창사 살롱 보도는 뉴스 측 유일한 신규: Xiong Puxiang 발표는 공식 입장을 집중 업데이트——누적 설치량 25억 대 초과, Cheng Xuan 차량 제어 시스템 ASIL D/AUTOSAR CP 상용화 성과, AI Kit와 Env+Agent의 AI 전략, 모니터링 기간 내 정보량이 가장 많은 항목.
  3. 소프트웨어 패키지 생태계 하루 세 번 업데이트: BMI270 IMU 드라이버(Mahony 융합 포함), LiteType 폰트 엔진(Gitee → GitHub 이전), AI Agent 멀티모달 지원, 센서/멀티미디어/엣지 AI 삼선 보강.
  4. CANopenNode 통합 패키지 방향이 LSS로 확장: 저장 백엔드 provider화, AT24CXX와 분리, CANopen 노드 설정 영속화로 진화(브랜치 개발 중).
  5. 한계 설명: gnews는 “RT-Thread” 검색 시 노이즈가 높음(Rotten Tomatoes 단어 분리, Geely Smart Engine 하이브리드 등), 본 모니터링 기간 뉴스 측 신규 1건만 공식 API + GitHub + 다중 gnews 교차 확인으로 확정; EET-China 의제 원문(a518185) 수집 타임아웃, 살롱 활동 시간은 검색 요약(8월 18일 14:00-17:00) 기준.
