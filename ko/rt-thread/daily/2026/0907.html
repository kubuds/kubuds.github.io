1. 커널 및 버전 동향

1.1 3일간 제로 머지 종료: 월요일 아침 배치에서 4개 PR 머지, mmcsd AC5 호환, MPU Kconfig, eclipse 툴체인, hpmicro C++ 빌드 포함

날짜: 2026-09-07 (머지 기간 10:19 ~ 11:18 베이징 시간, 즉 02:19:23Z ~ 03:18:42Z)　출처: RT-Thread/rt-thread commits (PR #11690, PR #11766, PR #11762, PR #11777)

메인 저장소 rt-thread는 09-03 #11776 이후 연속 세 모니터링 기간(3일)의 제로 머지를 끝내고, 월요일 아침 한 시간 내에 연속으로 4개 PR을 머지했다:

  • #11690 [device][mmcsd] Fix Arm Compiler 5 build compatibility（CYFS3 커밋, 08-10 생성, 큐에서 가장 오래 대기한 약 4주）：AC5로 MMC/SD 및 블록 디바이스 코드를 컴파일할 때의 호환성 문제를 체계적으로 수정——일반 SWITCH 명령 이름이 일부 칩 레지스터 매크로와 충돌（MMC_SWITCH로 개명하고 Phytium SDIF 호출 지점도 동기 수정）；ARMCC5를 위해 이름 있는 SD 상태 필드 접근 방식을 제공（다른 컴파일러는 계속 익명 필드 인터페이스 사용）；typeof에 의존하는 블록 디바이스 연결 리스트 순회를 명시적 rt_list_entry로 대체；DFS 비활성화 시 파티션 구조 정의 보충；void * 포인터 연산 정리.
  • #11766 [mprotect][kconfig] Add safe defaults for MPU region count options（RogerNext 커밋, 08-28 생성）：NUM_MEM_REGIONS / NUM_CONFIGURABLE_REGIONS / NUM_EXCLUSIVE_REGIONS에 Kconfig 기본값 추가. 이전에는 RT_USING_HW_STACK_GUARD를 켜고 명시적으로 설정하지 않으면 rtconfig.h에 빈 매크로(#define NUM_CONFIGURABLE_REGIONS)가 생성되어 잘못된 C 표현식((2 + ), for (i = 0U; i < ; i++))으로 확장되었고, 이로 인해 cortex-m4/m7/m33의 MPU 코드 컴파일이 실패했다.
  • #11762 [tools][eclipse] Sync assembler include paths（wdfk-prog 커밋, 08-28 생성）：eclipse 플러그인 프로젝트의 어셈블러 include 경로 동기화, 공식 툴체인(eclipse 플러그인) 빌드 일관성 수정.
  • #11777 [bsp][hpmicro] wire CXX/CXXFLAGS from rtconfig into scons Environment（kaidegit 커밋, 09-01 생성）：hpmicro BSP(HPMicro HPM 시리즈)에서 RT_USING_CPLUSPLUS를 켰을 때 scons Environment가 rtconfig의 CXX/CXXFLAGS를 연결하지 않고 호스트 g++로 폴백하여, C++ 그룹 컴파일 인자가 따옴표 없는 단일 인자로 취급돼 빌드가 실패했다. 수정 후 CXX/CXXFLAGS를 scons 환경에 주입한다.

이 배치는 메인테이너 Rbb666의 같은 날 아침 집중 리뷰(1.2 참조)와 같은 시간대에 발생했으며, 메인 저장소는 「축적기」에서 「머지 + 리뷰 동시 활성」으로 전환했다. release는 여전히 v5.2.2(2025-10-31)이며, 아직 새 버전 릴리스 움직임은 없다.

1.2 리뷰 큐 집중 활성: #11774 반려 후 당일 재푸시, #11775 재검토로 전환, #11770 인라인 제안 수신; 신규 PR #11781 착지

날짜：2026-09-07（베이징 시간 10:16 ~ 11:18）　출처：RT-Thread/rt-thread pulls

머지 배치와 같은 시간대에 메인테이너 Rbb666이 리뷰 큐를 집중 처리했다:

  • #11774 [components][sal] Fix SIOCGIFCONF buffer overflow（Huoyanlifusu）：02:30:45Z에 Rbb666의 CHANGES_REQUESTED 리뷰 의견을 받았고, 작성자는 당일 03:04:48Z에 곧바로 새 커밋（[components][sal] Fix SIOCGIFCONF buffer overflow）을 푸시하며 대응해, 회신 속도가 빨랐다.
  • #11775 [bsp][c908] rt-smart와 MMU Sv39/48 지원（QEMU xiaohui c908, OpenSBI SMP 포함）（BadmintonMaster）：Rbb666이 02:18:28Z에 “@rcitach review 좀 도와주세요”라고 남기며 다른 메인테이너에게 재검토를 넘겼다. 이 PR은 Damo Academy XuanTie C908의 QEMU xiaohui 플랫폼에서의 rt-smart 및 OpenSBI SMP 지원으로, RISC-V 관련이다.
  • #11770 fix[usb]: stop aliasing rt_ringbuffer as rt_serial_rx_fifo in VCOM（Finder16）：Rbb666이 03:17:12Z에 components/legacy/usb/usbdevice/class/cdc_vcom.c:358에 인라인 제안을 남겼다——rx_bufsz == 0인 폴링 수신 경로를 보완하라（Serial V2가 장치를 열기 전에 config.rx_bufsz를 0으로 설정하고 RT_SERIAL_RX_BLOCKING을 사용할 때 폴링 모드로 진입하며 serial_rx를 할당하지 않음）는 내용이며, 예시 패치도 제시했다.
  • #11772 [components][asan] Add runtime AddressSanitizer for heap（RogerNext）：02:16:58Z에 Rbb666의 리뷰 코멘트（COMMENTED）를 받았다.

신규 PR 측면에서: #11781 [BSP][STM32] Adapt Ethernet driver to new HAL API（CYFS3, 09-06 15:17 베이징 시간 생성）가 모니터링 기간 내에 착륙했으며, STM32 이더넷 드라이버를 새 HAL API에 적응시킨다. 큐에 있는 #11689（stm32 SPI BDMA, moment-NEW）와 함께 STM32 드라이버 현대화 메인라인에 속한다. 모니터링 기간 내 신규 이슈는 없었다.

2. 공식 및 커뮤니티 활동

2.1 공식 뉴스 API 열여덟 번째 날 연속 신규 없음, elexcon 2026 개막까지 2일

날짜: 2026-09-07　출처: RT-Thread 공식 뉴스 API

공식 뉴스 API（rt_org 카테고리）는 여전히 5개의 이전 항목이며, 최신 항목도 여전히 2026-06-17 아부다비 투자 포럼 보도로, 열여덟 번째 날 연속 신규가 없다. 9월 9-11일 선전 elexcon 2026（Ruiside 참가, “AI 하드웨어 풀 패키지” 예고는 08-30에 이미 수록）개막까지 2일 남았고, 이번 주 수요일이 다음 대외 창구다. 중국어 미디어 측（Google News 프록시 검증 “RT-Thread” when:3d, Ruiside when:7d, Ruijingpai OR Ruijing when:7d）과 영어 측（”RT-Thread” when:2d）모니터링 기간 내 모두 신규 보도가 없었으며, 최신 미디어 콘텐츠는 여전히 09-04 EE Times China 커뮤니티 작품 공유（어제 이미 수록）로, 회의 전 정적이 이어지고 있다.

3. 생태계 및 벤더 적응

3.1 canopennode-rtt 모니터링 기간 내 중단, 작성자 wdfk-prog의 공식 eclipse 툴체인 PR 같은 날 병합——생태계 양축 병행

날짜: 2026-09-07　출처: wdfk-prog/canopennode-rtt, RT-Thread/rt-thread PR #11762

외부 브랜치 저장소 canopennode-rtt는 09-06 10:06（CiA401 아날로그 이벤트 및 페일세이프 지원, 어제 이미 수록） 이후 모니터링 기간 내 신규 커밋이 없으며, CiA402/CiA401 듀얼 프로파일 확장이 단계적 휴지기에 들어갔다. 주목할 점은 동일 개발자 wdfk-prog의 공식 저장소 기여가 오늘 착륙했다는 것이다: 그의 08-28 제출 eclipse 툴체인 PR #11762가 오늘 아침 메인 저장소에 병합되었고（1.1 참조）, 그가 주도하는 CAN 프레임워크 재구성 #11779는 여전히 리뷰 중이다（마지막 코멘트 CYFS3 09-03）. “외부 CANopenNode 생태계 이식（canopennode-rtt）+ 공식 CAN 프레임워크/툴체인 기여（#11779/#11762）” 양축 병행 구도는 변함없으며, 이번 월요일의 병합 시간대는 그의 두 축 성과가 처음으로 같은 날 착륙한 시점이다.

3.2 topic:rt-thread 생태계 권역 모니터링 기간 내 기타 동향 없음

날짜: 2026-09-07　출처: GitHub topic:rt-thread

topic:rt-thread 생태계 점검: 09-06 이후 새 저장소 push 없음(검색 topic:rt-thread pushed:>2026-09-06 0건); packages 인덱스 저장소도 여전히 업데이트 없음(마지막 09-01 CANopenNode 인덱스, 이미 수록됨); zlgopen/awtk 등 고빈도 저장소는 모니터링 기간 내 RT-Thread 전용과 직접 관련된 커밋 없음. 생태계 측 초점은 여전히 canopennode-rtt와 그 작성자의 메인 저장소 기여에 있음.

4. 산업 응용

신규 항목 없음. 모니터링 기간 내 신규 산업 응용/적용 사례 보도 없음; 최근 3일간 산업 측은 침묵 유지, 최근 수록된 산업 콘텐츠는 08-27 말레이시아 도시 IoT 사례와 08-24 RISC-V+AI 듀얼 트랙 서밋 보도(EE Times China). Ruiyai는 임바디드 인텔리전스(린강 디수이지후이), 산업(루이칭 산업 플랫폼) 등 방향의 최신 대외 동향이 09-09 개막하는 elexcon 2026과 함께 집중적으로 공개될 것으로 예상됨.

5. 요약 및 트렌드 관찰

  • 커널 측: 연속 3일 제로 머지 종료, 월요일 아침 10:19-11:18 한 시간 내 배치로 4개 PR 머지——mmcsd의 AC5 호환 수정(Phytium SDIF 호출 지점 동기화 포함, 큐 최장 약 4주 #11690), MPU region count Kconfig 기본값(cortex-m4/m7/m33 컴파일 실패 수정), eclipse 툴체인 어셈블리 include 동기화, hpmicro BSP C++ 빌드 수정; 같은 기간 메인테이너 Rbb666 집중 리뷰——#11774 반려 후 작성자 당일 재푸시, #11775 rcitach로 재검토 이관, #11770 인라인 패치 제안 수신, #11772 리뷰 코멘트 수신; 신규 PR #11781(STM32 이더넷 HAL 적응) 머지, 모니터링 기간 내 신규 issue 제로, release 여전히 v5.2.2. 메인 저장소 상태가 축적에서 「머지 + 리뷰 양측 활성」으로 전환, elexcon 2026 개막이 임박한 점을 고려하면 회의 전 리뷰 큐 정리 의도가 명확함.
  • 생태계 측: canopennode-rtt 모니터링 기간 내 일시 중단(직전 커밋 09-06 아침 이미 수록), 그러나 그 작성자 wdfk-prog의 공식 eclipse 툴체인 PR #11762와 외부 포팅이 같은 날 머지, 「외부 생태계 + 공식 기여」양측 병행; topic 생태계 나머지는 동향 없음.
