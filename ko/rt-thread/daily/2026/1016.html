1. 커널 및 버전 동향

1.1 커널 및 드라이버 수정 병합 배치: ofw 해시 테이블 경계 초과 수정 및 N32 타이머 보완 확정 (10-15)

날짜: 2026-10-15 13:32 ~ 13:50 (병합 시간)　출처: PR #11845, PR #11812

유지보수자 모니터링 기간 내 커뮤니티 수정 2건 병합. 첫째는 디바이스 트리 ofw 수정(#11845, 1개 파일 +4/-2, 유지보수자 Rbb666 병합): phandle 해시 테이블 두 곳의 경계 초과 위험 수정 — 할당 수량을 max-min에서 max-min+1로 변경(조회 인덱스는 phandle-min이며, phandle이 범위 상한일 때 원래 할당 영역 밖에 접근함), 확장 초기화를 이전 테이블 항목 수 기준으로 이전 테이블 끝에서부터 기산하도록 변경(기존 구현은 시작 값을 빼지 않아 시작 phandle이 1이 아닐 때 초기화 위치가 부정확함); 작성자는 6개 사례를 GCC에서 ASan/UBSan으로 함수 레벨 검증. 둘째는 N32 타이머 보완(#11812, 39개 파일 +3956/-105): N32H47x_48x 및 N32H49x에 이전에 누락된 클럭 소스와 ATIM/GTIM/BTIM 인스턴스 테이블 분기를 추가(두 시리즈는 drv_tim.c를 공유하지만 이전에는 H7xx 분기만 구현), LPTIM tick을 실제 LSI 기반으로 유도하도록 변경, PWM 및 펄스 인코더 동기 확장, 세 보드에 실제로 드라이버 기능 선언까지 컴파일되는 ci-attach 항목 추가, #11800 후속.

1.2 lwip 세그먼트 콘텐츠 매크로 제어 제안 병합: 네트워크 스택 3건 커밋 마무리 (10-15)

날짜: 2026-10-15 13:04 ~ 13:28 (커밋 / 병합 시간)　출처: PR #11815

lwip 세그먼트 콘텐츠 매크로 제어 제안(#11815)이 이전 회차 리포트 마감 시점 전후로 확정: 작성자 rcitach가 13:04에 최종 커밋 3건 푸시(wlan AP 라이프사이클과 직접 수신 경로 동기화, lwip 버퍼 옵션 설정과 PBUF tailroom 보존, DHCP 시작 로직 최적화), 13:28 병합, 총 6개 파일 +188/-28. 해당 안건은 이전 회차에서 ‘심사 중, 수정 요청’ 상태로 마무리되었으며, 이번 회차에서 병합 최종 상태로 추가 기록.

1.3 9PFS 연속 2건 결함 노출: ARMv7-A 비정렬 접근으로 커널 중단, getdents 경계 초과 읽기 재현 확인 (10-15)

날짜: 2026-10-15 20:33 ~ 21:18 (댓글 / 생성 시간)　출처: Issue #11868, Issue #11289

기여자 XueDugu는 모니터링 기간 내 9PFS 파일 시스템 결함 두 건을 진척시켰다. 첫째는 새로 개설한 결함 티켓 #11868: 수신 경로의 64비트 값 매크로가 일반 포인터 역참조로 버퍼를 읽으며(get_rx_value64_of), ARMv7-A에서 GCC가 생성하는 LDRD는 8바이트 정렬이 필요한데, 구조체 크기 292와 프로토콜 상수 42로 인해 rx_buffer+42가 항상 6 mod 8이 된다——모든 Tstat 응답(완전히 정상적인 응답 포함)이 dfs_9pfs_open / dfs_9pfs_stat에서 정렬 예외를 발생시키고 커널 data abort를 유발한다. 보고서는 2025-12에 9PFS를 도입한 커밋을 특정하고, CVSS 3.1 7.5(원격 서비스 거부) 등급과 QEMU vexpress-a9 전체 재현 체인을 제시했으며, 디스어셈블리와 addr2line 검증을 첨부했다. 둘째는 3월에 개설된 #11289(getdents 경로가 서버가 내려보낸 stat/name 길이를 신뢰하여 범위 초과 읽기 발생)로, 10-15 저녁 커뮤니티가 master(bsp/simulator + ASan)에서 재현 확인했으며, 근본 원인은 수신 바이트 수가 버려지고 레코드 경계가 검증되지 않은 것이다. 두 건 모두 열린 상태를 유지한다.

1.4 신규 제안: DFS 계층 F_GETFL/F_SETFL과 디바이스 제어 명령 코드 충돌 해소(10-16)

날짜: 2026-10-16 00:51(생성 시간)　출처: PR #11869

기여자 CXSforHPU가 DFS 계층 충돌 해소 제안을 개설했다(2개 파일 +56/-15): POSIX의 F_GETFL(=3)/F_SETFL(=4)와 RT-Thread의 RT_DEVICE_CTRL_CONFIG(=3)/RT_DEVICE_CTRL_CLOSE(=4)가 숫자 값이 충돌하며, 두 명령 집합이 동일한 정수 매개변수를 공유하여 fcntl 경로에서 드라이버가 잘못 해석할 수 있다——dfs_v2의 ioctl은 순수 통과이며, 시리얼 등 드라이버는 LWP 종료 시 F_GETFL을 CONFIG로 오인하여 하드웨어를 재구성하기까지 한다. 제안은 명령 인코딩을 바꾸지 않고 매개변수 형태로 충돌을 해소한다: 명령 3은 매개변수가 있으면 드라이버로 전달하고, 없으면 POSIX에 따라 파일 상태 플래그를 반환하며; 명령 4는 매개변수가 없으면 드라이버로 전달하고, 있으면 상위 계층 설정으로 처리한다. dfs_v1과 dfs_v2 두 세대 구현을 동시에 개조하고 socket 알림 경로를 유지한다.

1.5 심사 중 제안 리뷰: ESP32-C6 SPI에 세 가지 줄 단위 의견 제시 및 작성자의 항목별 답변(10-15)

날짜: 2026-10-15 13:38 ~ 16:30(리뷰 / 답변 시간)　출처: PR #11846

ESP32-C6 SPI 지원 제안(#11846)이 유지보수자 Rbb666로부터 세 가지 줄 단위 리뷰 의견을 받았다: 첫째, DMA를 끄면 IDF의 단일 전송 상한이 64바이트인데 드라이버는 여전히 전체 패킷을 제출하여 65바이트 메시지가 중단을 유발하므로, 분할 전송하거나 최소한 오류 코드를 반환해야 한다; 둘째, C3/C6가 ESP-IDF-latest를 공유할 때 C6를 빌드하면 gdma.c가 영구적으로 4개 매개변수 호출로 재작성되고, 이어서 C3를 빌드하면 매개변수 과다 오류가 발생하므로, 대상 매크로를 사용하거나 별도 복사본을 사용해야 한다; 셋째, 비트 폭 검증이 버스 초기화 성공 이후에 발생하여, 16비트 요청 실패 후 8비트로 재시도하면 버스가 이미 초기화되어 중단되므로, 자원 신청 전에 먼저 검증해야 한다. 작성자는 항목별로 개선하겠다고 답변했으며(드라이버 내 분할 전송, 대상 매크로별로 두 호출 집합을 유지하고 양방향 컴파일 검증, 비트 폭 검증을 앞당김), 빌드 스크립트의 재작성 로직을 제거하는 데 동의했다.

1.6 심사 중 논의: aarch64 GIC 응답 경로 존치 논쟁 심화(10-15)

날짜: 2026-10-15 13:57 ~ 19:39(댓글 시간)　출처: PR #11860

aarch64 GIC 수정 제안(#11860)이 모니터링 기간 내 심층 기술 논의를 불러왔다: 작성자 Xenithya는 삭제 대상이 EOI 이전의 불필요한 GICD_ICPENDR pending 클리어 쓰기라고 설명했다——인터럽트 처리 중 동일한 에지 소스가 새 이벤트를 재발생시킬 때(예: 그의 NPU 시나리오: 먼저 AXI 오류 보고 후 완료 보고) 이 쓰기가 재래치된 pending을 지워 새 인터럽트가 영구적으로 손실된다. 그리고 실측 데이터를 제시했다: 해당 쓰기를 유지하면 약 19~33회 추론마다 완료 인터럽트 손실이 반드시 한 번 발생하고, 삭제 후 순수 인터럽트 경로에서 48만 회 추론이 제로 실패였다. 유지보수자 GuEe-GUI는 두 번 답변했다: 이 함수의 의미는 GIC 비-EOI 모드로 이해해야 하며, 문제는 traps.c의 인터럽트 응답 인터페이스 호출 방식에 있을 수도 있으니 trap 경로 수정도 함께 검증할 것을 권했다. 제안은 열린 상태를 유지한다.

1.7 신규 작업 활성화: efm32 menuconfig 지원 제안 개설(10-15)

날짜: 2026-10-15 18:30 ~ 18:31(댓글 / 생성 시간)　출처: Issue #7530, PR #11867

장기 보류된 「menuconfig 초보자 과제」 결함 티켓(#7530)이 모니터링 기간 내 재활성화: 기여자 ymj0440이 efm32 하위 과제를 승인——bsp/efm32에 누락된 Kconfig와 .config를 보충(.config는 rtconfig.h에서 역추출 생성, RT_USING_LWIP는 미활성 유지), 해당 BSP가 menuconfig 구성을 지원하도록 함, sam7x, lm3s8962 선례 인용; 18:30 승인 코멘트 게시 후 1분 만에 제안 개설(#11867, 2개 파일 +408). 해당 티켓에서 이전에 보충 대기로 표시된 다른 BSP rm48x50은 메인라인을 따라 구성 파일을 이미 갖춤.

1.8 공식 뉴스 인터페이스 연속 57일째 신규 없음(10-16)

날짜: 2026-10-16(확인 시간)　출처: RT-Thread 공식 뉴스 인터페이스

공식 뉴스 인터페이스(rt_org 분류)가 반환하는 아카이브 원고의 최신 항목은 여전히 2026-06-17이며, 모니터링 기간 내 신규 없음, 연속 57일째 업데이트 중단; 제품 및 활동 정보는 계속 위챗 공식 계정, 커뮤니티 포럼 및 GitHub 채널에서 최초 공개. 공식 웹사이트 뉴스 목록 페이지는 프런트엔드 동적 렌더링으로, 이번 기간에는 직접 확인 불가.

2. 공식 및 커뮤니티 활동

모니터링 기간 내 공식 및 커뮤니티 활동 측면에서 신규 수집 항목 없음: 커뮤니티 포럼 게시글 인터페이스의 최신 게시글은 여전히 10-15 오전의 「슈헝즈양」 작품 게시글(지난 기간에 이미 수집), 미디어 측도 모니터링 기간 내 신규 원고 없음.

3. 생태계 및 제조사 적응

3.1 커뮤니티 프로젝트: SiFli SF32LB525(황산파이) 보드 측 FreeDOS 이식 발표(10-15 ~ 10-16)

날짜: 2026-10-15 22:11 ~ 2026-10-16 03:08(커밋 시간)　출처: equence/sf8086

커뮤니티 개발자가 이식 프로젝트 sf8086 발표: 8086tiny 에뮬레이터를 RT-Thread 기반 SiFli Technology SF32LB525(황산파이, Cortex-M33) 개발 보드에 이식, 보드 측에서 FreeDOS 직접 실행——BIOS, 부팅 플로피 디스크 및 Turbo C 2.01 컴파일 툴체인 전부 펌웨어에 상주, 외부 저장소 불필요; A: 드라이브는 매번 부팅 시 flash에서 재구성되는 RAM 디스크(약 144 KB 사용 가능), EDIT, DEBUG, ZIP 등 DOS 도구 실행 가능; RT-Thread shell과 DOS 콘솔이 UART1 공유(시리얼 중재, 터미널 키 매핑 등 적응 커밋 포함). 프로젝트 모니터링 기간 내 13건 커밋 푸시, MS-DOS 6.22 부팅 디스크 빌드 스크립트 및 보드 측 실행 스크린샷 포함, 저장소에 rt-thread, sifli, sf32lb525, freedos 등 토픽 표기.

기타 생태계 채널 모니터링 기간 내 침묵 지속: packages 소프트웨어 패키지 인덱스(최근 병합 10-14), Studio SDK 인덱스(최근 업데이트 10-10), env 도구 저장소(최근 커밋 10-09), N32 디바이스 드라이버 저장소(최근 커밋 10-14) 및 GD32 제조사 다운스트림 모두 모니터링 기간 내 푸시 없음.

4. 산업 응용

모니터링 기간 내 산업 응용 측면에서 신규 수집 항목 없음.

5. 요약 및 트렌드 관찰

5.1 최근 하루 트렌드(10-15 ~ 10-16)

  • 9PFS 보안 감사가 모니터링 기간 초점으로 부상: 파일 시스템 9PFS 스택에서 연속 두 건의 결함 노출, 그 중 하나는 결정론적으로 재현 가능한 원격 서비스 거부(CVSS 7.5, 완전한 재현 체인 및 디스어셈블리 증거 포함), 2025년 말 도입된 신규 컴포넌트가 집중 감사 시기에 진입했음을 시사.
  • 병합 리듬 유지: 모니터링 기간 내 세 건의 병합 완료(ofw 해시 테이블 범위 초과 수정, N32 타이머 보완, lwip 매크로 제어 마무리), 모두 커뮤니티 기여자가 제출하고 메인테이너가 병합.
  • 리뷰 상호작용 밀도 높음: ESP32-C6 SPI가 세 건의 라인 레벨 의견 획득 및 작성자가 항목별 응답; aarch64 GIC 제안에 수십만 회 추론급 실측 데이터 및 메인테이너 의미론 토론 등장.
  • 초보자 과제 승인 획득: menuconfig 과제 티켓이 수개월 보류 후 재활성화, 승인 후 1분 만에 efm32 제안 개설.
  • 보드 레벨 생태계 커뮤니티 활발: SiFli SF32LB525 보드 측 FreeDOS 이식 프로젝트가 모니터링 기간 내 13건 커밋 완료, RT-Thread shell과 DOS 환경이 동일 시리얼에서 공존.
  • 공식 채널 침묵 지속: 공식 뉴스 인터페이스 57일째 업데이트 중단; packages / Studio / env 등 생태계 저장소도 모니터링 기간 내 푸시 없음.

5.2 한계 및 중복 제거 설명

  • 이번 모니터링 기간은 지난 기간 보충 실행 마감 시점(10-15 13:30)부터 기산하여 약 18.5시간이며, #11815, #11812 등 지난 기간에 심사 중/재개 상태였던 제안은 마감 시점 전후로 확정되어 이번 기간에 병합 최종 상태로 추가 기록합니다(1.1 ~ 1.2 참조).
  • 지난 기간에 이미 수록된 항목(공업박람회 AI 소형차 회고 글, 「슈헝즈양」 작품 게시물 등)은 이번 기간에 다시 다루지 않으며, 포럼 글 인터페이스와 Google News 중국어 측 모니터링 기간 내 모두 신규 유효 원고가 없고 영어 측은 0건 적중입니다.
  • HN 재검사 0건 적중, topic:rt-thread 생태 검색 모니터링 기간 내 1건(sf8086, 이미 수록), 기타 범용 프로젝트는 수록하지 않습니다.
  • 메인 저장소 releases / tags에 신규 버전 없음(최신 v5.3.0, 09-10 릴리스), 공식 웹사이트 뉴스 목록 페이지는 프런트엔드 동적 렌더링으로 직접 확인이 불가능합니다.
  • 집계 후보 중 riscv.org 담마원 인터뷰 원고 1편이 있었으나, 확인 결과 RISC-V 주제로 RT-Thread와 무관하여 미수록했습니다.
