1. 커널 및 버전 동향

1.1 Cortex-M4 하드웨어 스택 가드 (HW Stack Guard) 지원 커널 병합

날짜: 2026-08-26 (10:37 베이징 시간 병합)　출처: RT-Thread/rt-thread commit e2e6245a

메인 저장소 기간 내 커널급 기능 하나가 병합되었다: [arm][cortex-m4] Add hardware stack guard support, 커뮤니티 개발자 hanzhijian이 제출 (author 시간 08-25 09:19), 핵심 메인테이너 Rbb666이 08-26 10:37 (UTC 02:37)에 병합. 이 커밋은 하드웨어 MPU 기반 스택 오버플로 보호 (RT_USING_HW_STACK_GUARD)를 기존에 지원하던 Cortex-M7 / Cortex-M33에서 Cortex-M4로 확장한다 — 후자는 M 시리즈 중 배포량이 가장 큰 커널 클래스로, 하드웨어 스택 가드 적용의 의미가 상당하다. 핵심 변경은 libcpu/arm/cortex-m4/에 집중된다: M7 MPU 계층과 정렬된 mpu.c / mpu.h / mputype.h 신규 추가 (유일한 차이는 M4에 L1 캐시가 없어 cacheability 비트가 세 개로 축소된 점); cpuport.c에 rt_hw_stack_guard_init() 신규 추가; context_gcc.S에 #include <rtconfig.h> 보완 및 PendSV 컨텍스트 스위치 경로에서 rt_hw_mpu_table_switch() 호출; SConscript에서 메모리 보호 비활성화 시 mpu.c 제외. 참조 BSP는 bsp/stm32/stm32f407-fk407m2-zgt6 (Zhengdian Atom STM32F407 보드): board.h/board.c에서 NUM_STATIC_REGIONS와 static_regions[]를 정의하고 Flash 영역을 읽기 전용으로 표시하며, 전체적으로 RT_USING_MEM_PROTECTION 스위치로 제어되고 기본적으로 활성화되지 않는다. 이는 v5.3.0-beta 브랜치 생성 (08-24) 이후 메인 브랜치에 병합된 첫 커널급 기능 커밋으로, v5.3.0의 커널 견고성 방향에 한 획을 더했다.

1.2 finsh 정리: 폐기된 매크로 FINSH_FUNCTION_EXPORT_ALIAS 제거

날짜: 2026-08-26 (10:53 베이징 시간)　출처: RT-Thread/rt-thread commit 0305faf8

설립자 Bernard Xiong이 08-26 10:53(UTC 02:53)에 [finsh] Remove deprecated FINSH_FUNCTION_EXPORT_ALIAS(PR #11734에 대응)를 직접 푸시하여, 코드베이스에서 폐기된 FINSH_FUNCTION_EXPORT_ALIAS 매크로의 모든 사용을 제거했습니다. 총 19개 파일, +124/-81 라인으로, allwinner(sunxi-hal disp2 디버그 및 테스트 파일), apm32(drv_common.c), at91(at91sam9260 reset.c), fujitsu(mb9x nand.c), simulator(board.c / module_win32.c) 등의 BSP와 dfs_v1 / dfs_v2의 dfs_posix.c 컴포넌트 코드를 포함합니다. FINSH_FUNCTION_EXPORT_ALIAS는 finsh 컴포넌트에서 역사적으로 명령 내보내기에 별칭을 부여하던 구식 매크로로, 이번 정리는 코드 현대화의 마무리 작업에 해당하며, 어제 RA8D1 머지와 같은 “정리기” 리듬에 속합니다. 머지 채널이 복구된 후 메인 브랜치는 저위험 정리와 기능 두 가지 유형의 커밋을 교대로 진행하며 v5.3.0 정식 릴리스를 준비하고 있습니다.

1.3 utest 콘솔 버퍼 제약 및 Renesas RA6W1 BLE OTA 생성 최적화

날짜: 2026-08-25 22:04 ~ 2026-08-26 10:42　출처: RT-Thread/rt-thread commits 45679c79 / 64f1fa4a

모니터링 기간 내 추가로 두 건의 머지가 있었습니다(별도 항목으로 분리하지 않음). 첫째, CYFS가 커밋하고 Rbb666이 08-26 10:42에 머지한 [utest] Enforce minimum console buffer size(src/Kconfig, utest 콘솔 버퍼에 최소 길이 제약을 설정하는 것으로 테스트 프레임워크 구성 검증 강화에 해당)입니다. 둘째, rcitach가 커밋하고 Rbb666이 08-25 22:04에 머지한 Renesas RA6W1 BSP 개선으로, Improve BLE OTA image generation to avoid executing OPEN every time a flash erase and write operation occurs이며, bsp/renesas/ra6w1-ek/ 아래 ra6w1_ospi_flash.c와 scripts/gen_rrq61_flash_image.py를 수정하여 BLE OTA 이미지 생성 흐름을 최적화하고 매번 Flash 소거/기록 시마다 OPEN 명령이 실행되는 것을 방지합니다. RA6W1(Renesas BLE 단일 칩) BSP는 08-05 첫 버전, 08-11 2차 주변장치 보강에 이어 다시 한번 다듬어졌으며, 서드파티/커뮤니티의 지속적 반복 특성이 뚜렷합니다.

2. 공식 및 커뮤니티 활동

2.1 공식 뉴스 API 6일 연속 신규 없음, Ruiqing Workshop 내일(08-27) 개최

날짜: 2026-08-26　출처: RT-Thread 공식 뉴스 API / EE Times China(Google News 경유)

공식 뉴스 API(rt_org 분류)는 여전히 5건의 예전 항목이며, 최신은 2026-06-17 아부다비 투자 포럼 보도로 약 2개월 지연, 6일 연속 신규 없음입니다. news / activity 분류 인터페이스는 계속 “분류 데이터 없음”을 반환합니다. 미디어 측에서는 Google News에서 “RT-Thread” 검색(zh-CN 및 en-US의 3일 기간)이 모두 0건을 반환하여 뉴스 면은 완전히 조용합니다. Ruiqing 7일 기간에서는 여전히 08-18 등록 / 08-19 DSMC+FPGA / 08-21 카운트다운 예전 기사만 잡히고 새로운 예열은 없으며, 나머지는 Ford Lingrui, Geely Zhiqing 하이브리드 등 단어 분리 노이즈입니다. 내일(08-27) 상하이에서 「Ruiqing 산업 플랫폼 Workshop: EtherCAT 실시간 제어와 산업 솔루션 실전」이 정식 개최되며, 이는 이번 주 공식 채널의 가장 중요한 실행 관찰 지점으로 내일 보고서에서 회의 후 보도를 중점 확인해야 합니다.

3. 생태계 및 벤더 적응

3.1 canopennode-rtt: LSS 기동 영속화 master에 머지, LSS Store 구성 영속화 신규 추가

날짜: 2026-08-25(15:13 ~ 17:36 베이징 시간)　출처: wdfk-prog/canopennode-rtt

어제 상세 보고의 CANopenNode 통합 패키지 브랜치 개발이 오늘 메인라인에 병합되었다: feat/lss-precan-persistence 브랜치의 3개 커밋(feat[canopennode][lss]: add backend-neutral startup persistence, 저장 진입점 단순화 리팩터링, EEPROM provider와 AT24CXX 디커플링 리팩터링)이 08-25 15:13에 master에 일괄 병합되었다; 이후 08-25 17:36에 다시 master에 커밋 feat[canopennode][lss]: persist LSS Store configuration(b4695346)이 추가되었다——LSS(CiA 305 노드 계층 설정 서비스) Store 설정의 영속화를 구현하여, 앞선 “backend-neutral 시작 영속화”와 호응한다: EEPROM 저장 백엔드가 이미 provider로 추상화되었고, LSS 파라미터는 노드 전원 투입 후 복구 가능하며, 산업용 필드버스 설정의 디스크 기록 방향으로 한 걸음 더 나아갔다. 저장소는 또 새 브랜치 feat/j08-lss-runtime-bitrate를 개설하여 LSS 런타임 비트레이트 방향을 가리키며, 이는 진행 중 개발에 해당한다. 08-17 이후 NMT 하트비트 감시 마스터, SDO 블록 전송, ASCII 게이트웨이, 저장 진단의 연속 병합과 함께, 해당 서드파티 패키지의 산업용 CANopen 방향 심화 리듬은 줄어들지 않았다.

3.2 GD32 다운스트림 BSP 브랜치 주변장치 지원 보완: GD32107C-EVAL / DMA

날짜: 2026-08-26(09:37 ~ 11:08 베이징 시간)　출처: GD32-MCU-IOT/gd32_rt-thread

GD32 에코시스템 다운스트림 동기화 저장소 gd32_rt-thread의 모니터링 기간 내 두 브랜치 커밋(모두 메인 저장소 master에 병합되지 않음, 에코시스템 참고로 표기): 브랜치 107c는 08-26 11:08에 Add gd32107c-eval usart i2c spi and dma support를 커밋하여 GD32107C-EVAL 보드에 USART / I2C / SPI / DMA 주변장치 드라이버 지원을 보완했다; 브랜치 dma_fun은 08-26 09:37에 Add DMA-related modifications를 커밋하여 DMA 관련 기능을 수정했다. GD32F107C는 GigaDevice 커넥티비티 제품 라인에 속하며, 두 커밋의 방향이 일치하여 GD32 측의 RT-Thread 상 주변장치 드라이버 지속 보완을 반영한다(이전 f503_dma / 470i-eval / f303c_start 등 브랜치도 같은 부류에 속하며, 일부는 이미 병합됨). master 브랜치는 08-19 이후 새로운 병합이 없다.

3.3 에코시스템 참고: awtk 정례 업데이트 / gd32_rt-thread master 정례 동기화

날짜: 2026-08-25 ~ 2026-08-26　출처: zlgopen/awtk / GD32-MCU-IOT/gd32_rt-thread

topic:rt-thread 최근 일주일 활성 저장소의 나머지 항목은 모두 정례 동향이다: zlgopen/awtk는 08-25 18:08에 web gif 지원 등을 커밋했다(범용 GUI/Web 개선, RT-Thread와 직접적 연관 없음); h120d-protocol / gdr은 모니터링 기간 밖이거나 이미 보고됨. 모두 에코시스템 참고로 표기하며, 별도 항목으로 나열하지 않는다.

4. 산업 응용

4.1 모니터링 기간 내 새로운 독립 보도 없음, 최근 3일 동향 회고

날짜: 2026-08-24 ~ 2026-08-26　출처: 각 항목 참조

산업 응용 측면에서 모니터링 기간 내 새로운 독립 공개 보도는 없다(gnews 이중 언어 3일 모니터링 기간 모두 0건). 최근 3일 동향 회고:

  • v5.3.0 버전 주기 진행 (08-24부터): beta 브랜치가 생성된 후 메인 브랜치는 “정리 + 기능” 두 축으로 진행 — finsh 폐기 매크로 정리(08-26), Cortex-M4 하드웨어 스택 보호(08-26)는 모두 v5.3.0을 위한 축적; 산업 제어/네트워크(AF_UNIX) 등의 기능은 정식 버전과 함께 릴리스될 예정;
  • NXP i.MX RT1180 BSP 대규모 업데이트, EtherCAT 포함 (08-21): 산업 제어 실시간 버스 기능이 NXP 크로스오버 MCU 플랫폼에 착륙(+3579줄, HyperRAM/멀티코어/rpmsg-lite/NetC 지원), v5.3.0-beta 브랜치는 RT1180 병합 지점 위에 세워짐;
  • Ruiqing 산업 플랫폼 Workshop 내일 개최: 8월 27일 상하이 “EtherCAT 실시간 제어와 산업 솔루션 실전”, RT1180 EtherCAT 기능과 함께 공식 + 생태계 두 축을 형성하며, 내일은 회의 후 보도 관찰 창구;
  • CANopen 생태계 제3자 착륙 심화 (08-17 → 08-26): canopennode-rtt 연속 업데이트로 NMT/SDO/저장 진단/ASCII 게이트웨이 커버, LSS 시작과 Store 설정 지속화가 오늘 master에 병합, 산업 현장 버스 방향 지속 활발;
  • GD32 주변장치 드라이버 보완 (08-26): GD32107C-EVAL의 USART/I2C/SPI/DMA 브랜치 커밋, GigaDevice 생태계의 RT-Thread 상 커버리지 계속 확대.

5. 요약 및 트렌드 관찰

  1. 커널급 기능 회귀: Cortex-M4 하드웨어 스택 보호(HW Stack Guard) 병합, 하드웨어 MPU 스택 오버플로 보호를 M7/M33에서 M 시리즈 최대 배치량 커널로 확장, v5.3.0-beta 생성 후 메인 브랜치 첫 커널 기능 커밋, 참조 구현은 ALIENTEK STM32F407 보드(기본 비활성, 명시적 활성화 필요).
  2. v5.3.0 전 정리기 신호: Bernard Xiong이 finsh 폐기 매크로 FINSH_FUNCTION_EXPORT_ALIAS 전 저장소 정리 직접 푸시(19개 파일, +124/-81), utest Kconfig 제약과 함께 메인 브랜치는 “정리 + 기능” 두 축 진행의 버전 전 정리 리듬을 보임.
  3. 제3자 산업 제어 생태계 지속 활발: canopennode-rtt 어제 브랜치 개발 당일 master 병합 및 LSS Store 설정 지속화 추가, 별도 런타임 bitrate 새 브랜치 개설; CANopen 방향은 이미 10일 연속 실질 커밋 존재.
  4. 제조사 측 주변장치 보완: GD32 다운스트림 저장소 GD32107C-EVAL에 USART/I2C/SPI/DMA 보충(브랜치 개발 중); Renesas RA6W1 BLE OTA 생성 스크립트 최적화 병합, RA6W1 BSP 세 번째 라운드 다듬기 진입.
  5. 뉴스 측 여섯째 날 연속 조용: 공식 API 여전히 06-17까지 지연, gnews 이중 언어 3일 창구 0건 히트; 내일 Ruiqing Workshop은 이번 주 유일하게 확정된 공식 활동 관찰점, 내일 리포트에서 회의 후 보도와 공식 발표 확인 권장.
  6. 한계 설명: gnews는 “RT-Thread” 검색 노이즈 높음(분할 단어 매칭 Rotten Tomatoes / Ford Lingrui / Geely Smart Engine 등), 본 모니터링 기간 뉴스 측 0건 추가는 공식 API + GitHub 전수 검증 + 다중 gnews 교차 검증으로 확인, GitHub 측 정보가 주요 증분.
