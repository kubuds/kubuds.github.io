1. 커널 및 버전 동향

1.1 NXP i.MX RT1180 EVK BSP 기능 대폭 업데이트: I2C DMA/CAN/SPI/DWT/SDIO 및 EtherCAT 지원

날짜: 2026-08-21 (17:45 베이징 시간 병합, PR #11715)　출처: RT-Thread/rt-thread commit 6ea68279 / PR #11715

기간 내 규모가 가장 큰 병합으로, NXP 엔지니어(nxp-ran)가 주도했으며 46개 파일, +3579/-769. [BSP][NXP] Add new features of I2C DMA, CAN, SPI, DWT and SDIO for RT1180: 템플릿, 설정 파일 및 빌드 스크립트를 업데이트하여 HyperRAM, 멀티코어 부팅(multicore kickoff), rpmsg-lite, NetC 이더넷, CherryUSB 및 EtherCAT 지원; GCC/IAR/KEIL 세 가지 툴체인용 링커 스크립트를 업데이트하여 멀티코어 kick-off와 다양한 로드 방식 지원; Keil 디버그 ini 파일 업데이트; I2C DMA, CAN, SPI, DWT, SDIO 등 외부 디바이스 기능 지원 추가. i.MX RT1180은 NXP 크로스오버 MCU(Cortex-M33 플랫폼, NetC 이더넷 통합)로, 이번은 벤더 주도의 평가 보드 BSP 기능급 강화. 주목할 점: EtherCAT 지원이 NXP BSP 목록에 포함되어 RuiQing 산업 플랫폼 EtherCAT 메인라인과 호응하며, 공업 제어 실시간 버스 역량이 RT-Thread 생태계 내에서 양축으로 추진되고 있음.

1.2 커널 IPC 타임아웃 웨이크업 소유권 경쟁 조건 수정, 회귀 테스트 병행

날짜: 2026-08-21 (16:52 베이징 시간 병합)　출처: RT-Thread/rt-thread commit ba79f694

[kernel][ipc] Fix timeout wakeup ownership race (ari.liu 커밋, 8개 파일, +721/-14): timer stop과 in-flight 타임아웃 콜백 경쟁 시 스레드 timer 소유권 문제 수정 — 타임아웃 콜백이 더 이상 진행되지 않음을 확인할 때까지 스레드 timer 소유권을 유지하고, waiter가 성공적으로 복구된 후에만 IPC 자원을 소비; 동시에 범용 및 RT-Smart channel 타임아웃 콜백의 소유권 정리 보완. 회귀 테스트로 결정론적 스케줄러와 LWP 테스트를 추가하여 Event, Semaphore, Mailbox, Message Queue, sender, receiver 6가지 시나리오 커버. IPC 타임아웃 경로의 자원 소유권 경쟁 조건은 임베디드 RTOS의 전형적 난제로, 이번 수정은 rt-thread 커널과 rt-smart LWP 채널을 동시에 커버하고 회귀 테스트를 고정하여 커널 견고성의 실질적 강화에 해당.

1.3 C906 커널은 XuanTie MMU 속성만 유지

날짜: 2026-08-21 (16:51 베이징 시간 머지)　출처: RT-Thread/rt-thread commit 5ae08713

Ensure that c906 uses only the Xuantie MMU properties (rcitach 커밋, 1개 파일, -56줄): libcpu/risc-v/t-head/c906/riscv_mmu.h를 정리하여 T-Head Xuantie C906 (RISC-V) 코어가 Xuantie MMU 속성만 사용하도록 보장하고, 범용 RISC-V MMU 속성과 혼용하면서 발생하는 모호성을 제거했다. rt-smart RISC-V 코어 측 적응의 지속적인 유지보수에 해당한다.

1.4 Renesas RA6W1 BSP 디바이스 드라이버 결함 수정

날짜: 2026-08-21 (13:10 베이징 시간 머지)　출처: RT-Thread/rt-thread commit 46d74447

fix ra6w1 device bug (rcitach 커밋, 6개 파일, +124/-23): RA6W1 EK 보드 지원의 디바이스 문제를 수정했으며, ADC 드라이버(drv_adc.c), PWM 드라이버(drv_pwm_w.c), 보드 레벨 Kconfig와 클럭 설정(bsp_clock_cfg.h, hal_data.c)을 포함한다. Renesas RA6W1 BSP의 반복 주기를 이어간다: 08-05 첫 버전, 08-11 2차 45개 파일로 ADC/SPI/I2C 등 드라이버 보강, 이번은 3차 결함 수정으로, 벤더 BSP의 “먼저 골격 머지, 이후 드라이버 보강, 다음 결함 수정” 진화 패턴에 부합한다.

1.5 Nuvoton 4개 시리즈 CAN 드라이버 수신 DLC 클램핑

날짜: 2026-08-21 (11:22 베이징 시간 머지)　출처: RT-Thread/rt-thread commit 642040c4

[bsp][nuvoton] Clamp CAN receive DLC (hanzhijian 커밋, 4개 파일, +16): m2354, m480, n9h30, nuc980 네 시리즈의 drv_can.c에서 CAN 수신 DLC(데이터 길이 코드)를 일괄적으로 클램핑 처리하여 범위를 벗어난 값이 전달되는 것을 방지하며, CAN 드라이버의 견고성 보완에 해당한다.

1.6 버전 상태 안정적

날짜: 2026-08-22　출처: rt-thread releases

최신 정식 버전은 여전히 v5.2.2(2025-10-31 릴리스)이며, 모니터링 기간 내 신규 릴리스와 프리릴리스가 없다. 최근 누적된 수정(Rust 빌드, IPC 경쟁 상태, libc/dfs, 각 BSP)은 다음 버전에 일괄 반영될 것으로 예상된다.

2. 공식 및 커뮤니티 활동

2.1 공식 뉴스 API 여전히 신규 없음, news/activity 분류 인터페이스 이틀 연속 오류

날짜: 2026-08-22　출처: RT-Thread 공식 뉴스 API

공식 뉴스 API(rt_org 분류)는 여전히 5건의 오래된 항목이며, 최신은 2026-06-17 아부다비 투자 포럼 보도로 약 2개월간 지연되어 개선되지 않고 있다. news와 activity 분류 인터페이스는 이틀 연속 “분류 데이터가 존재하지 않습니다. 관리자에게 문의하세요”를 반환했다. 공식 정보 출구의 업데이트 주기는 커뮤니티와 미디어 측의 실제 동향보다 계속 뒤처지고 있다.

2.2 Ruiqi Workshop 등록 마감 카운트다운: 8/27 상하이 EtherCAT 실전 임박

날짜: 2026-08-21 (16:55 베이징 시간 게재)　출처: EE Times China (Google News 경유)

EE Times China는 《다음 주 목요일 상하이 Ruiqi Workshop 등록 마감 카운트다운: EtherCAT 실시간 제어와 산업 솔루션 실전》을 게재했으며, 8월 27일 상하이 「Ruiqi 산업 플랫폼 Workshop」이 등록 마감 카운트다운 단계에 들어섰다는 후속 홍보다. 해당 행사는 08-18에 이미 예열되었고(어제 모니터링 기간 이후 미디어 측이 다시 후속 보도), 정보 자체에는 새로운 내용이 없지만 공식 측이 임박한 시점의 홍보 리듬에 들어섰음을 보여준다. 행사까지 불과 6일 남아 이번 주 가장 추적할 가치가 있는 실행 관찰 지점이다. EET-China 원사이트에 접속할 수 없어 본문 세부 내용을 펼칠 수 없으며, gnews 링크를 인용한다.

3. 생태계 및 벤더 적응

3.1 flespark/gdr: RT-Thread GDB 디버깅 보조 프레임워크, 모니터링 기간 내 3회 연속 업데이트

날짜: 2026-08-21 (03:38 / 07:11 / 07:49 UTC 머지)　출처: flespark/gdr commits

서드파티 GDB RTOS helper 프레임워크 gdr 모니터링 기간 내 RT-Thread와 직접 관련된 3건의 머지: rtthread object container 호환성 및 heap 추상화 데이터 필드 수정; rtthread heap 정보가 상대 필드 누락 시 메모리 순회로 fallback; rtt 시스템 출력 형식 업데이트. 이 도구는 08-19에 rtthread heap detail 명령을 새로 추가했으며, GDB로 RT-Thread/rt-smart를 디버깅하는 시나리오의 heap 상세 정보와 객체 컨테이너 파싱을 지속적으로 다듬고 있어 커널 모드와 LWP 사용자 모드 디버깅 체인에 실질적 가치가 있다.

3.2 생태계 관찰: awtk 커밋은 범용 GUI 개선으로, RT-Thread 전용 아님

날짜: 2026-08-21　출처: zlgopen/awtk commits

topic:rt-thread 최근 일주일 활발한 저장소 중, awtk 모니터링 기간 내 커밋(vgcanvas clip 개선, 빌드 스크립트 최적화, crc 재구현)은 모두 범용 GUI 엔진 작업으로 RT-Thread와 직접적인 관련이 없어 “생태계 참고/비전용”으로 표기; canopennode-rtt 모니터링 기간 내 신규 커밋 없음; GD32 다운스트림 미러 저장소 gd32_rt-thread는 08-19 이후 업데이트 없음.

4. 산업 응용 특별 챕터 (산업 / 로봇 / 임바디드 인텔리전스)

4.1 모니터링 기간 내 신규 독립 항목 없음, 최근 3일 트렌드 회고

날짜: 2026-08-19 ~ 2026-08-21　출처: 각 항목 참조

산업 응용 측면에서 모니터링 기간 내 새로운 독립 공개 보도는 없으나, 두 가지 산업 제어 관련 호응이 주목할 만하다:

  • EtherCAT, NXP RT1180 BSP에 진입 (오늘 1.1): 산업 제어 실시간 버스 기능이 NXP 플랫폼에서 구체화되어 Ruiqing 플랫폼과 함께 이중 라인을 형성;
  • Ruiqing Workshop 등록 카운트다운 (오늘 2.2): 8/27 상하이 EtherCAT 실전이 임박 홍보 단계에 진입.

최근 3일 트렌드(모두 상세 보도 완료, 여기서는 회고):

  • Ruiqing 산업 플랫폼 DSMC+FPGA 통신 90MB/s (08-19, EE Times China): RK3506J 산업 보드 + FPGA 확장 보드, 16비트 DSMC 병렬 버스 + rt_event 이벤트 구동 DMA;
  • Beningo 2026 RTOS 성능 보고서 참가 (08-19): RT-Thread가 유일한 중국 오픈소스 RTOS로 8개 참가 목록에 진입;
  • 8/27 Ruiqing Workshop: 예열 (08-18) → 등록 카운트다운 (08-21): EtherCAT 실시간 제어 및 산업 솔루션 실전.

트렌드 판단: EtherCAT 생태계 포지션이 NXP와 Ruiqing 두 플랫폼에서 동시에 나타나고 있으며, 산업 제어 실시간 버스가 현재 가장 명확한 메인 라인이다.

5. 요약 및 트렌드 관찰

  1. 커널 + BSP “수정일”: 모니터링 기간 내 5건 머지, 규모가 가장 큰 것은 NXP RT1180 BSP 기능 업데이트(+3579행, EtherCAT/HyperRAM/멀티코어/rpmsg-lite 지원), 그 다음은 IPC 타임아웃 웨이크업 귀속 레이스 수정——커널과 rt-smart LWP 채널을 동시에 커버하고 6가지 시나리오 회귀 테스트를 함께 제공하여 최근 커널 측에서 가장 비중 있는 견고성 강화이다.
  2. RISC-V 측 지속 유지보수: C906 XuanTie MMU 속성 정리, rt-smart RISC-V 적응 활발 유지.
  3. 벤더 BSP 진화 리듬 명확: Renesas RA6W1은 “첫 버전 → 2기 드라이버 보완 → 3기 결함 수정” 완료; Nuvoton 4개 시리즈 CAN 드라이버 통일 DLC 클램핑 보완.
  4. 산업 제어 메인 라인 이중 플랫폼 추진: EtherCAT의 NXP RT1180 BSP 진입 + Ruiqing 8/27 Workshop 등록 카운트다운 진입, 이번 주 목요일 행사가 최근 가장 주목할 만한 구체화 관찰 지점이다.
  5. 공식 정보 출구 지속 지연: rt_org 2개월 정체, news/activity 분류 인터페이스 연속 오류, 커뮤니티와 미디어 동향이 여전히 공식 채널보다 빠르다.
  6. 버전 리듬: v5.2.2가 이미 9개월 이상 유지되고 있으며, 최근 수정(Rust 빌드, IPC, libc/dfs, 다중 벤더 BSP)이 지속 누적되어 다음 버전 릴리스 윈도우가 주목할 만하다.
