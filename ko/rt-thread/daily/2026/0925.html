1. 커널 및 버전 동향

1.1 Qinheng CH32V203C8T6 개발 보드 BSP 메인라인 병합 (09-24)

날짜: 2026-09-24 16:21 (베이징 시간, 병합 시간; 제안은 09-22 저녁에 생성)　출처: PR #11827, 병합 커밋 386b877b

메인라인에 모니터링 기간 내 새로운 보드 지원이 병합되었다: Qinheng Micro (WCH) CH32V203C8T6-EVT-R0 개발 보드 BSP로, bsp/wch/risc-v/ch32v203c-evt-r0에 위치한다. 이 보드는 Qingke V4B 코어 (CH32V20x_D6)이며, 64KB 제로 웨이트 Flash와 20KB SRAM을 갖추고 있다. 공식 SDK가 D8W 시작 파일만 제공하고 D6에 대해 직접 Exit()를 호출하기 때문에, 일반 소프트웨어 패키지 빌드로는 펌웨어를 생성할 수 없었다. 제안은 D6 인터럽트 벡터 테이블 (소프트웨어 인터럽트 심볼 SW_handler)과 64KB/20KB 링커 스크립트로 이를 보완하고, 이 조건에서만 SDK 패키지 스크립트를 수정하여 D8W 프로세스에 영향을 주지 않도록 했다. 기본 이미지는 GPIO와 UART1 (USART1은 PA9/PA10에 멀티플렉싱)을 활성화하며, PWM, ADC, RTC, 독립 워치독 및 USB 디바이스는 menuconfig에 유지된다 (64KB 용량으로는 USB와 앞서 언급한 네 가지 주변장치를 동시에 수용할 수 없다). 제안에는 두 가지 공유 드라이버 수정도 포함된다: drv_usbd.c는 USBFS DMA의 16비트 SRAM 오프셋과 SET_ADDRESS 쓰기 타이밍을 조정하고 (엔드포인트 버퍼는 SRAM에 상주해야 하며, 풀스피드 패킷 길이는 64바이트), drv_iwdt.c는 CH32V2 시리즈를 위한 대응을 보충한다. 제안은 총 4개의 커밋, 26개의 파일로 구성된다 (+2216/-57).

1.2 rt_vsnprintf 너비 시맨틱 결함 및 커널 수정 제안 (09-24)

날짜: 2026-09-24 20:52 ~ 21:29 (베이징 시간, 결함 보고 및 수정 제안 시간)　출처: Issue #11833, PR #11834

커뮤니티 기여자가 모니터링 기간 내 커널 결함 보고와 그에 따르는 수정을 제출했다: 현재 rt_vsnprintf 구현 (특히 tiny 버전)이 %[width].[precision]s의 시맨틱 처리가 잘못되어, 최소 너비가 최대 너비 절단으로 오인된다 — 예를 들어 %3s로 “abcdef”를 포맷팅하면 전체 문자열이 아닌 “abc”를 출력하며, 좌측 정렬 %-3s와 %*s 등의 변형도 동일하게 영향을 받는다. 수정 제안이 동시에 제출되었으며, 변경 사항은 rt_vsnprintf_std.c, rt_vsnprintf_tiny.c 및 해당 단위 테스트 TC_rt_sprintf.c를 포함한다 (총 3개 파일, +37/-18). 내용은 경계 검출 보충, 너비와 정밀도의 조합 기능 구현 및 테스트 케이스 최적화이다. 결함 보고에는 이미 3개의 논의가 있으며, 수정 제안은 리뷰 상태에 있다.

1.3 리뷰 큐에 세 가지 제안 추가: 네트워크 스택 수정 및 빌드 정리 (09-24)

날짜: 2026-09-24 14:15 ~ 17:52 (베이징 시간, 생성 시간)　출처: PR #11831, PR #11835, PR #11832

이번 모니터링 기간 리뷰 대기열에는 총 다섯 건의 제안이 추가되었으며, 그중 커널 vsnprintf 수정은 1.2, ESP32-C6 보드 지원은 3.1에서 다루고, 본 항목에서는 나머지 세 건을 수록한다. 첫째는 lwip-nat의 포트 할당 결함 수정이다. 기존 구현은 유휴 슬롯 인덱스가 아닌 스캔 카운터로 변환 포트를 할당했는데, 할당 경로에 진입할 때 카운터가 항상 테이블 크기와 동일하여 모든 신규 매핑이 같은 포트를 받게 되어 동시 UDP/TCP 세션이 상호 충돌하고 반환 트래픽이 잘못된 테이블 항목에 매칭될 수 있었다. 제안은 동시에 lwIP 2.1 대응(헤더 파일 명칭 변경 및 타임아웃 인터페이스)을 완료하고, NAT 적용 조건을 소스와 목적 네트워크 모두 규칙에 매칭되는 경우로 강화했으며, ICMP 테이블이 가득 찰 때 LRU 방식으로 가장 오래된 항목을 제거하도록 했다(파일 1개, +41/-11). 둘째는 lwip-dhcpd에 누락된 string.h 헤더 파일을 보충한 것이다. dhcp_server_raw.c가 memcmp / memset / strlen / strncmp / strchr를 표준 헤더 포함 없이 직접 호출하고 있어, 암시적 선언이 64비트 타깃에서 strchr() 반환 포인터를 잘라낼 수 있었다(파일 1개). 셋째는 components/drivers/ipc/SConscript에서 중복된 __RT_IPC_SOURCE__ 매크로 정의를 제거한 것이다(파일 1개).

1.4 공식 뉴스 인터페이스 연속 36일째 신규 없음 (09-25)

날짜: 2026-09-25 (확인 시간)　출처: RT-Thread 공식 뉴스 인터페이스

공식 뉴스 인터페이스(rt_org 분류)가 반환하는 아카이브 원고의 최신 항목 날짜는 여전히 2026-06-17이며, 모니터링 기간 내 신규가 없어 연속 36일째 업데이트가 중단되었다. 공식 웹사이트 뉴스 목록 페이지는 여전히 프런트엔드 동적 렌더링 방식이라 직접 확인할 수 없다. 제품 및 활동 정보는 계속해서 포럼, 스토어, 업계 매체 채널을 통해 최초 공개되고 있다.

2. 공식 및 커뮤니티 활동

2.1 모니터링 기간 내 신규 활동 및 튜토리얼 원고 없음 (09-25)

모니터링 기간 내 포럼 글 인터페이스와 공식 채널 모두 신규 활동이나 튜토리얼 원고가 없었다. RSOC26 여름 캠프 튜토리얼 연재의 최근 업데이트는 여전히 09-23의 《제1장 개발 환경, BSP 설정과 RT-Thread 디바이스 모델》(이전에 수록됨)이며, 공업박람회 엣지 AI 스마트 카 Workshop(10월 13일 상하이 특별 세션, 상세 내용은 이전에 수록됨)은 모니터링 기간 내 신규 정보가 공개되지 않았다.

3. 생태계 및 제조사 대응

3.1 Espressif ESP32-C6 개발 보드 BSP 제안 및 소프트웨어 패키지 소스 동시 제출 (09-25)

날짜: 2026-09-25 01:20 ~ 02:38 (베이징 시간, 제안 및 동반 소프트웨어 패키지 제안의 생성과 업데이트 시간)　출처: 메인라인 PR #11836, esp-idf 소프트웨어 패키지 PR #17

커뮤니티 기여자가 모니터링 기간 내 Espressif ESP32-C6-DevKitC-1 개발 보드용 메인라인 BSP 제안을 제출했다. 모듈은 ESP32-C6-WROOM-1(RISC-V, 8MB Flash)이며, bsp/ESP/ESP32_C6를 신규 추가하고 GPIO, UART0(GPIO16/17), ADC를 기본 활성화한다. 제안은 C6가 전용 bootloader 이미지를 사용해야 하며(C3의 이미지를 재사용할 수 없음), Flash는 DIO 8MB 80MHz, 애플리케이션 오프셋은 0x10000임을 강조한다. 업스트림 esp-idf 소프트웨어 패키지가 2023-11-26 이후 업데이트되지 않아 C6 소스가 없는 관계로, 기여자는 소프트웨어 패키지 저장소에 PR #17을 동시 제출하여 C6의 scons 빌드 소스를 보충했으며, 두 제안 모두 리뷰 상태에 있다(메인라인 측 커밋 2건, 파일 40개, +9492/-50). 해당 기여자는 1.1의 CH32V203 BSP 제출자와 동일 인물로, 같은 날 WCH와 Espressif 두 RISC-V 칩 라인을 넘나들었다.

3.2 커뮤니티, RT-Thread Nano IDF 불필요 포팅 프로젝트 공개: ESP32-S31에서 구동 (09-25)

날짜: 2026-09-25 10:04 (베이징 시간, 푸시 시간)　출처: esp32s31_rtt_nano 저장소

커뮤니티 개발자가 Espressif ESP32-S31(듀얼코어 RISC-V, 320MHz, 온보드 16MB Flash와 16MB PSRAM)용 RT-Thread Nano 이식 프로젝트를 공개했다. 특징은 ESP-IDF 빌드 시스템을 완전히 우회한다는 점이다: 자체 작성한 부팅 어셈블리와 링커 스크립트, riscv32-esp-elf-gcc로 직접 컴파일, 독립 esptool 플래싱, 이미지는 칩 bootROM이 Flash 0x2000에서 직접 로드(IDF 2차 bootloader 미사용). 콘솔은 칩 내장 USB-Serial/JTAG를 사용하고, tick은 SYSTIMER, 인터럽트는 CLIC를 사용하며, PIN / SPI(QSPI 포함) / I2C 주변장치는 RT-Thread 디바이스 프레임워크에 연결되어 msh에서 직접 검증할 수 있다. 프로젝트는 재현 가능한 빌드 검증을 완료했다(89개 추적 파일이 깨끗한 디렉터리에서 바이트 단위로 동일한 이미지를 빌드). 개인 프로젝트이며 커뮤니티 참고용이다.

4. 산업 응용

4.1 모니터링 기간 내 신규 적용 사례 없음 (09-25)

모니터링 기간 내 신규 양산, 상용 또는 협력 적용 사례가 없다. 산업 측에서 최근 확인 가능한 움직임은 여전히 공업박람회 엣지 AI 스마트 카 Workshop(10월 13일 특별 세션)과 Gino Pi 출시 이후의 생태계 추진이며(모두 이전에 수록됨), 로봇 및 임베디드 AI 방향은 모니터링 기간 내 신규 배포 소식이 없어 지난주 리듬과 일치한다.

5. 요약 및 트렌드 관찰

5.1 최근 하루 트렌드 (09-24 ~ 09-25)

  • 보드 레벨 라인 하루 세 건 연속, 모두 RISC-V 칩에 집중: WCH CH32V203C8T6 메인라인 병합, Espressif ESP32-C6 개발보드 제안 리뷰 진입, 커뮤니티의 RT-Thread Nano → ESP32-S31 이식——서로 다른 세 제조사의 RISC-V 칩이 같은 날 보드 레벨 지원 체인에 등장했으며, RT-Thread 보드 레벨 생태계에서 RISC-V의 비중이 계속 상승하고 있다.
  • 리뷰 큐가 커널과 네트워크 스택 결함을 집중 처리: rt_vsnprintf 너비 의미론, lwip-nat 포트 할당, lwip-dhcpd 헤더 파일 누락 세 가지 문제 모두 커뮤니티가 주도적으로 제출한 것으로, 품질 지향 기본 수정이 이번 기간의 주를 이루었다.
  • 메인라인 리듬 저빈도 유지: 모니터링 기간 내 메인라인은 BSP 병합 한 건뿐으로, 최근 일주일의 산발적 병합과 리뷰 큐 소화 리듬과 일치한다.
  • 공식 채널 36일째 침묵: 공식 웹사이트 뉴스 페이지가 여전히 확인 불가하며, 제품과 활동 정보는 계속 포럼과 GitHub 측에서 우선 발표되고 있다.

5.2 한계와 중복 제거 설명

  • 중복 제거 설명: Titan Mini OpenMV(09-18, 09-22, 09-24 수록, 모니터링 기간 내 신규 커밋 없음), Gino Pi 관련(09-14 ~ 09-22 수록, 모니터링 기간 내 신규 추진 없음), 소프트웨어 패키지 인덱스 3연속 병합과 GD32 디바이스 패키지(09-23, 09-24 수록)는 중복 보도하지 않는다.
  • CH32V203 제안의 공유 드라이버 수정 범위는 제안 설명을 기준으로 하며, 실제 영향 범위는 후속 사용을 기준으로 한다; ESP32-C6 제안은 기여자 브랜치의 소프트웨어 패키지 소스에 의존하며, 병합 형태와 버전은 리뷰 결론을 기준으로 한다.
  • 공식 뉴스 인터페이스와 공식 웹사이트 뉴스 목록 페이지 상태는 이전과 동일하다(36일째 업데이트 중단, 페이지 직접 확인 불가).
