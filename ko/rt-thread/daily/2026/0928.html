1. 커널 및 버전 동향

1.1 메인라인에 유지보수성 수정 2건 병합: GD32VW553H-EVAL 빌드 정리 및 ipc 파일 정리 (09-26 ~ 09-27)

날짜: 2026-09-26 19:58 / 09-27 12:18 (베이징 시간, 병합 시간)　출처: PR #11837, PR #11832, 병합 커밋 b40aeb146, 병합 커밋 05badce95

메인라인은 모니터링 기간 내 소규모 수정 2건을 병합했다. 첫 번째 (#11837)는 GD32VW553H-EVAL BSP의 CI 정리 단계 실패를 수정한다: riscv-none 작업이 빌드, 패키징 성공 후 scons -c 정리 단계에서 종료되는 문제로, 근본 원인은 SConstruct에 등록된 소프트웨어 패키지 사전 검사(bsp_pkg_check)가 정리 모드에서도 무조건 실행되는 것이었으며, 정리 시 소프트웨어 패키지가 이미 제거되었거나 아직 풀되지 않았을 수 있기 때문이다. 수정은 해당 검사를 clean 모드에서 즉시 단락(short-circuit)하도록 했으며 (파일 1개, +3/-0), 정상 빌드의 검사 로직은 변경되지 않았다. 이 제안은 GitHub Copilot 코딩 에이전트(copilot-swe-agent)가 제출했고, 에이전트 세션은 유지보수자가 트리거했으며, 이슈 개설 후 약 3분 만에 수정이 완료되어 09-26 19:58에 Rbb666에 의해 병합되었다. 두 번째 (#11832)는 components/drivers/ipc/SConscript에서 중복된 __RT_IPC_SOURCE__ 매크로 정의를 제거한 것으로 (파일 1개, +1/-1), 09-24 리뷰 큐의 소화에 해당하며 09-27 12:18에 병합되었다.

1.2 리뷰 큐에 견고성 수정 2건 추가: STM32 링커 스크립트 스택 정렬 및 devtmpfs 경로 범위 초과 (09-27)

날짜: 2026-09-27 20:57 ~ 21:11 (베이징 시간, 생성 시간)　출처: PR #11841, PR #11842

리뷰 큐에 모니터링 기간 내 견고성 수정 두 건이 추가되었다. 첫째(#11841)는 STM32 계열 전체 링커 스크립트의 스택 정렬을 수정한다: .stack 섹션의 ALIGN(4)를 ALIGN(8)로 변경하여, 공용 함수 경계에서 스택 포인터가 8바이트 정렬이어야 한다는 ARM AAPCS 요구사항에 부합하도록 한다. 이는 2023-05에 보고된 오래된 결함 #7527(스택 4바이트 정렬로 인해 가변 인자에서 double 전달이 잘못됨)에 대응한다. 변경은 12개 템플릿과 98개 보드에 걸친 총 110개 링커 스크립트를 포괄하며(+220/-220), 각 보드의 메모리 레이아웃은 건드리지 않았다. 둘째(#11842)는 devfs의 스택 버퍼 오버플로를 수정한다: devtmpfs.c의 _path_separate()와 _get_subdir()가 버퍼 길이 매개변수를 받지 않아, 단일 경로 구성 요소가 255바이트를 초과하면 범위를 벗어난다(최대 초과 약 3.8KB, 기록 내용과 길이는 호출자가 제어하며 반환 주소를 덮어쓸 수 있음). 수정은 devfs와 tmpfs의 기존 검증을 정렬시킨다(초과 시 -ENAMETOOLONG 반환, 1개 파일 +48/-8). 커밋 서명 접두사는 [HUST CSE]. 두 건 모두 현재 리뷰 상태이다.

1.3 FinSH 경로 자동 완성 힙 오버플로 결함 보고: 제출자가 수정 의사 표명 (09-26)

날짜: 2026-09-26 03:55(베이징 시간, 생성 시각)　출처: Issue #11839

커뮤니티가 모니터링 기간 내 FinSH 컴포넌트의 고위험 결함 보고를 제출했다: msh에서 경로 자동 완성(Tab 키)을 트리거할 때, msh_auto_complete_path 관련 로직이 현재 작업 디렉터리와 사용자 입력을 결합할 때 엄격한 경계 검사를 하지 않아, 지나치게 길거나 깊게 중첩된 경로가 힙 버퍼 범위 초과 쓰기(CWE-122)를 유발할 수 있으며, v5.3.0 및 현재 메인라인, STM32F407-ATK 등의 보드에 영향을 미친다. 이슈에는 결함 설명과 라벨(bug, in progress 등)이 첨부되어 있으며, 제출자 Acen28이 당일 해당 이슈를 인계받아 직접 수정을 제출할 예정이다. 이는 devtmpfs 범위 초과(1.2 참조)에 이어 커뮤니티 감사로 진전된 또 하나의 메모리 안전 문제 단서이다.

1.4 공식 뉴스 인터페이스 연속 39일째 신규 없음 (09-28)

날짜: 2026-09-28(확인 시각)　출처: RT-Thread 공식 뉴스 인터페이스

공식 뉴스 인터페이스(rt_org 분류)가 반환하는 아카이브 원고의 최신 항목 날짜는 여전히 2026-06-17이며, 모니터링 기간 내 신규는 없고 연속 39일째 업데이트가 중단되었다. 공식 웹사이트 뉴스 목록 페이지는 여전히 프런트엔드 동적 렌더링으로 직접 확인할 수 없다. 제품 및 활동 정보는 계속 포럼, 위챗 공식 계정, GitHub 채널에서 최초 공개된다——이번 순회 교육 공식 발표도 위챗 공식 계정에서 나왔다(2.1 참조).

2. 공식 및 커뮤니티 활동

2.1 2026 순회 오프라인 교육 6개 도시 개최, 참가 접수 시작 (09-27)

날짜: 2026-09-27 11:50(발표 시각)　출처: EE Times China 보도(전재), 참가 신청 폼

위챗 공식 계정 “RT-Thread操作系统”이 모니터링 기간 내 새로운 순회 오프라인 교육 공식 발표를 게시했다: 2026년 교육은 6개 도시에서 총 6회 진행되며, 모두 토요일에 배치되었다——상하이, 베이징(10월 24일), 선전, 우한(10월 31일), 시안(11월 7일), 항저우(11월 14일). 교육 내용은 이론 과정, Demo 시연, 실습을 포함하며, 공식 팀과의 대면 질의응답도 제공한다. 무료 참가 접수(JinData 폼, 상하이루이사이드전자과학기술유한회사 명의), 참가 시 기념품 증정, RT-Thread 전문가 팀이 강의한다. 업계 매체(EE Times China)가 당일 후속 전재했다. 2025년 7개 도시 3개 배치와 비교하면, 이번에는 6개 도시, 4개 배치로 축소되었다.

2.2 포럼 튜토리얼 《MCU 링커 스크립트 “업그레이드”》: 고아 Section과 정렬 처리 (09-28)

날짜: 2026-09-28 08:17(발표 시각, 11:03 업데이트)　출처: 포럼 글 54cb40d33610387a, Bilibili 동영상

커뮤니티 작성자 「다무슝」의 MCU 저수준 시리즈 업데이트(전편 《MCU GNU 링커 스크립트》 09-22 이미 수록): 이번 편은 고아 Section과 정렬 문제를 심화 처리한다. 요점: -Wl,--warn-orphan을 사용해 링커가 명시적으로 배치되지 않은 section을 나열하도록 한다; SHF_ALLOC 플래그에 따라 section을 런타임에 필요한 것(.text/.rodata/.data/.bss, 메모리 영역 할당 필요)과 필요하지 않은 것(.debug_*, .comment, .ARM.attributes, 심볼 테이블 등, 명시적으로 나열하지만 할당하지 않음) 두 가지로 분류하여 하나씩 배치한다; .ARM.exidx/.ARM.extab는 ALLOC 분류에 속하므로 배치하고 시작/끝 심볼을 내보내야 한다; 마지막으로 4바이트 정렬로 마무리하고, 링커 경고가 모두 제거되었는지, map 파일과 스크립트 설명이 일치하는지 검증한다. B站(빌리빌리) 동반 영상 첨부, 커뮤니티 튜토리얼류 콘텐츠에 해당.

3. 생태계와 벤더 적응

3.1 친헝 CH32V003F4P6-EVT 보드 지원 제안 리뷰 진입 (09-25)

날짜: 2026-09-25 21:11(베이징 시간, 생성 시간; 09-27 업데이트 있음)　출처: PR #11838

기여자 cms19859230182-lang(이전 CH32V203 BSP와 ESP32-C6 제안 작성자)이 친헝 CH32V003F4P6-EVT 개발 보드를 위한 BSP 제안을 제출했다. CH32V003F4P6는 RISC-V 코어, 주파수 48MHz, 16KB Flash, 2KB SRAM, TSSOP20 패키지; 기본 이미지는 UART1만 활성화(TX PD5 / RX PD6, 115200으로 msh 진입), 디버깅은 단선 SWDIO(PD1)로 WCH-LinkE 외부 연결. 제출자는 이미 실측 완료: WCH RISC-V GCC 8.2.0(-march=rv32ec -mabi=ilp32e)으로 빌드, 이미지 15680 바이트(16KB Flash에 적재), 플래싱 후 시리얼 출력에 RT-Thread banner와 msh 프롬프트 표시. 제안은 총 5개 커밋, 47개 파일(+9258/-0), 현재 리뷰 상태.

3.2 CANopen 생태계 두 저장소 MkDocs 문서 사이트 오픈 (09-28)

날짜: 2026-09-28 08:45 ~ 09:09(푸시 시간)　출처: canopennode-rtt, lely-canopen-rtt

커뮤니티 기여자 wdfk-prog(RT-Thread 소프트웨어 패키지 인덱스에서 canopennode 패키지 09-24 v1.2.0에 병합된 커밋 작성자)가 모니터링 기간 내에 두 CANopen 통합 저장소를 위한 문서 사이트를 발표: canopennode-rtt(CANopenNode 통합, 다중 장치 노드의 논리 장치 모드 지원)와 lely-canopen-rtt(Lely CANopen 통합, 단일 소유자 EV/IO2 런타임과 정적 객체 사전, 선택적 마스터 서비스) 모두 MkDocs 매뉴얼과 Doxygen API 문서를 푸시; lely 저장소는 추가로 PR 문서 검증 CI 추가. 두 패키지 모두 이전에 RT-Thread 포럼에 소개 글이 있었음(lely 마스터 사용법 장문 09-11 이미 수록). 산업용 통신 방향 소프트웨어 패키지 구축 지속 투자.

3.3 AWTK 오픈소스 라이선스 Apache 2.0으로 전환 (09-26)

날짜: 2026-09-26 08:50(커밋 시간)　출처: zlgopen/awtk 라이선스 변경 커밋

범용 임베디드 GUI 툴체인 AWTK(zlgopen/awtk, 3.3k stars)가 모니터링 기간 내에 라이선스를 LGPL-2.1에서 Apache License 2.0으로 전체 전환(LICENSE 파일 +201/-504), 프로젝트 주요 작성자 lixianjing이 커밋. AWTK 및 그 RT-Thread 소프트웨어 패키지(awtk 등)는 오랫동안 RT-Thread 상의 GUI 애플리케이션 개발에 기여해 왔으며, 라이선스 완화는 상용 통합에 유리. 생태계 참고류 소식에 해당(RT-Thread 전용 아님).

4.1 Luckfox RV1103 단일 칩 드론 프로토타입: RISC-V 코어에서 RT-Thread 비행 제어 실행 (09-27)

날짜: 2026-09-27 17:25 ~ 20:04(생성 및 푸시 시간)　출처: luckfox-rv1103-drone

개발자 nguyencanhanh가 단일 칩 쿼드콥터 드론 프로토타입을 공개했다. Rockchip RV1103(Luckfox Pico Mini B)을 핵심으로 하며, Cortex-A7이 Linux를 실행하여 카메라, NPU 인식, Wi-Fi, GPS와 원격 수신을 담당하고, 칩 내 RISC-V MCU 코어(HPMCU)가 RT-Thread를 실행하여 1kHz 비행 제어 루프를 수행한다. 프로젝트 목표는 실측 데이터로 “단일 칩 아키텍처가 직접 비행할 수 있는가”를 답하는 것이며, 대안은 독립 비행 제어기를 외장하는 것이다. 09-27 기준: 아직 실제 비행은 하지 않았으나 Linux와 MCU가 이미 병렬로 실행 중이고, 1kHz 루프는 실측되었으며, 비행 제어 소프트웨어는 시뮬레이터에서 완전히 실행 가능하고 3D 조작 뷰를 지원한다. 자체 개발한 LFX_FC_R1 비행 제어 보드(46×46mm)는 배선이 완료되었다. 프로젝트는 MIT + CERN-OHL-P 라이선스로 오픈소스화되었으며, 커뮤니티 개인 프로토타입에 속한다.

5. 요약 및 트렌드 관찰

5.1 최근 3일 트렌드 (09-25 ~ 09-28)

  • RISC-V 단서가 보드 레벨, CI와 애플리케이션 계층을 관통: GD32VW553H-EVAL(GD32V 시리즈 RISC-V)의 CI 정리 수정이 메인라인에 머지되었고, CH32V003F4P6-EVT(RV32EC) BSP 제안이 리뷰에 진입했으며, 커뮤니티에서는 RT-Thread를 RV1103 칩 내 RISC-V 코어에서 실행하여 비행 제어를 하는 프로토타입도 있다. 빌드 체인에서 보드 레벨 지원, 나아가 애플리케이션 프로토타입까지 RISC-V의 모습이 지속적으로 나타나고 있다.
  • 메모리와 ABI 견고성 수정이 집중적으로 추진: STM32 링커 스크립트 스택 정렬(110개 파일, 3년 전 이슈 #7527에 대응), devtmpfs 경로 범위 초과, FinSH 경로 완성 힙 오버플로 세 가지 문제가 같은 모니터링 기간에 나타났다. 09-22에 제출된 7건의 강화 시리즈 중 6건(#11820 ~ #11825)이 09-26에 집중적으로 리뷰 대기로 전환되어, 보안 방향 정리가 리뷰 상자의 주체가 되었다.
  • AI 코딩 에이전트가 일상 협업 체인에 진입: GD32V CI 수정이 GitHub Copilot 코딩 에이전트에 의해 제출되었으며, 착수부터 초안까지 약 3분, 다음 날 메인라인에 머지되어 에이전트가 메인라인의 소규모 수정의 완전한 폐쇄 루프를 담당하기 시작했음을 보여준다.
  • 공식 오프라인 교육 재접수 시작: 순회 교육 6개 도시 6회차 공식 발표(10월 하순부터 11월 중순까지의 4개 토요일), 오프라인 활동 밀도가 연내 고점으로 회귀했다.

5.2 한계 및 중복 제거 설명

  • 중복 제거 설명: ESP32-C6 보드 레벨 제안(#11836, 09-25 이미 수록, 기간 내 지속 리뷰로 실질적 변동 없음), 커널 vsnprintf 수정(#11834, 09-25 이미 수록, 기간 내 리뷰 업데이트만 있음), CH32V203 BSP 머지(09-24 이미 수록), Gino Pi 시리즈(09-22 ~ 09-24 이미 수록)와 RSOC26 튜토리얼(09-23 이미 수록)은 모두 중복 보도하지 않는다.
  • 순회 교육 회차 정보는 공식 접수 양식을 기준으로 한다. 매체 전재 버전이 공식 위챗 공식 계정과 차이가 있을 경우 공식을 기준으로 한다.
  • 공식 뉴스 인터페이스와 공식 웹사이트 뉴스 목록 페이지 상태는 이전과 동일하다(업데이트 중단 제39일, 페이지 직접 확인 불가).
