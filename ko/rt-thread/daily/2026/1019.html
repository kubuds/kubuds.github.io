1. 커널 및 버전 동향

1.1 커널 버전 번호 v5.4.0으로 전환: 버전 매크로와 Kconfig 우선, 릴리스물은 아직 미출시 (10-17)

날짜: 2026-10-17 09:43 (병합 시간)　출처: PR #11875, include/rtdef.h

메인테이너 Rbb666이 버전 전환 제안을 병합했다 (2개 파일 +4/-3): include/rtdef.h의 버전 매크로를 5.3.1에서 5.4.0으로 변경하고 2026-10-17 변경 기록을 추가했으며, src/Kconfig의 RT_VER_NUM 기본값을 0x50301에서 0x50400으로 변경했다. 작성자는 qemu-vexpress-a9 기본 구성으로 scons –pyconfig-silent를 실행하여 생성된 rtconfig.h의 RT_VER_NUM이 0x50400임을 확인했다. 10-19 기준 저장소의 최신 tag와 release는 여전히 v5.3.0 (09-10 릴리스)이며, ChangeLog.md 제목도 여전히 v5.3.0으로, 이번 작업은 버전 주기의 시작점일 뿐 5.4.0의 릴리스 노트와 릴리스물은 아직 나오지 않았다. 모니터링 기간 내 커뮤니티 결함 보고서에서는 master를 v5.4.0-dev로 표기하고 있다.

1.2 Next RISC-V 대규모 리팩터링 병합: 165개 파일 RV32/RV64 통일, Sv32~Sv57 및 AIA 동시 적용 (10-17)

날짜: 2026-10-17 09:44 (병합 시간)　출처: PR #10320, Issue #10722

약 5개월에 걸친 RISC-V 아키텍처 리팩터링(#10320)이 병합되었다. 4개의 커밋, 165개 파일 +15134/-2617. 내용에는 ISA 관리 인터페이스, 32E/32I/64I 통합, CBOM ISA에 따른 캐시 처리, Sv32/Sv39/Sv48/Sv57/Sv64 MMU와 SVPBMT, M 모드와 S 모드 CSR 연산 통합, SMP, APLIC/IMSIC(AIA), CLIC, ACLINT/CLINT, INTC와 PLIC, 선택적 DM(OFW 경유만), T-HEAD 벤더 코드 통합이 포함되며, qemu-virt64-riscv64에서 DM을 이식하고 0번이 아닌 코어 부팅을 지원한다. 계획표에서 S-mode RT-Thread, S-mode RT-Smart(APP, DM, MMU 없음, DM 없음 포함)와 M-mode(DM, DM 없음)는 모두 체크되었으나 BSP 적응은 여전히 진행을 기다리고 있다. 같은 날 #10722, #9571, #9567, #9566, #9521, #11226 여섯 건의 RISC-V 작업 티켓이 집중적으로 닫혔다.

1.3 RT-Thread Smart 13건의 제안 일괄 개설: syscall 분리, 시그널과 MMU 수정, K230D 적응 (10-18 ~ 10-19)

날짜: 2026-10-18 19:35 ~ 10-19 02:49 (생성 / 갱신)　출처: PR #11896, PR #11897, PR #11892

메인테이너 BernardXiong는 10-18 19:35부터 19:36까지 2분 만에 13건의 제안(#11885 ~ #11897)을 연달아 개설했으며, 이번 호 마감 시점까지 전부 심사 중이다. 핵심은 Smart를 QEMU와 실제 보드에서 구동시키는 것이다. qemu-virt64-riscv64/aarch64에서 RT_USING_SMART를 활성화하고, riscv64에서 SMP를 비활성화하며, virtio-blk에 ext4/elm을 올리고 ptyfs와 procfs를 마운트한다. libcpu/riscv에서는 초기 페이지 테이블 물리 오프셋 환산, 코어별 페이지 테이블의 사용자 매핑 상속, 사용자 모드 예외 처리를 수정하고, XuanTie 아키텍처 선택과 SVPBMT를 추가한다. lwp에서는 syscall 구현을 분리하고 시그널 전달 순서와 ELF 세그먼트 보호를 수정하며, TIOCLINUX와 TIOCGWINSZ를 보완한다. K230D에는 128MB DDR 설정과 ext4 루트 파일 시스템을 추가한다. 그 외에 SAL RAW socket 프로토콜 검증, lwip 루프백 네트워크 카드, 8250 earlycon 레지스터 폭, SDIO 블록 크기, poll의 DFS 파일 연산 경유와 UTIME_OMIT 수정이 있다.

1.4 ESP32-C6 SPI 제안 개선 후 병합: 분할 전송, BSP 자체 gdma, 비트 폭 검증 전진 (10-16)

날짜: 2026-10-16 11:31 (병합 시간)　출처: PR #11846, PR #11870

지난 호에서 심사 중이던 ESP32-C6 SPI 제안이 심사 개선을 거쳐 병합되었다(7개 파일 +1253/-26). DMA를 끌 때 IDF의 단일 64바이트 상한에 따라 분할 전송하고, gdma.c는 BSP 자체 사본으로 바꾸어 C3/C6가 공유 빌드에서 서로를 덮어쓰지 않도록 하며, 비트 폭 검증을 버스 초기화 이전으로 이동했다. 동작상 BSP_USING_SPI를 선택해야만 IDF SPI master를 링크하고, 기본 이미지는 여전히 SPI를 비활성화한다. 공유 ESP 드라이버는 더 이상 SPI 모드를 관통하지 않고 실제 전송 바이트 수를 반환하며, 칩 셀렉트는 SPI2_IOMUX_PIN_NUM_CS에서 가져오고 설정이 비어 있으면 -RT_EINVAL을 반환한다. 같은 시기 C3/C6를 ESP-IDF v6.1에 적응시키고 RISC-V 툴체인을 GCC 15.2로 올리는 제안(#11870)은 여전히 심사 중이다.

1.5 HPMicro BSP가 hpm_sdk v1.13.0으로 상향, HPM5100EVK 보드 지원 추가 (10-17)

날짜: 2026-10-17 16:28 (머지 시간)　출처: PR #11871, packages 인덱스 커밋

bsp/hpmicro가 hpm_sdk v1.10.0에서 v1.13.0으로 업그레이드됨 (434개 파일 +23873/-16669): hpm5100evk(HPM5151)의 board, startup, applications, Kconfig, 문서 및 이미지가 추가되었고 ALL_BSP_COMPILE.json과 BSP 목록에 등록됨. 기존 11개 보드가 새 SDK에 맞춰 재동기화되었으며, RT-Thread 측 변경 사항(clock_time 기반 drv_timer, scons의 CXX 연동, 산출물을 build/로 출력, 명명된 Kconfig choice, board_delay_*가 rt_hw_us_delay를 사용하도록 변경, 보드 레벨 codec 파일 등)은 유지되었고 드라이버 계층은 v1.13.0으로 동기화됨. 소프트웨어 패키지 인덱스에는 10-14에 hpm_sdk v1.13.0이 먼저 추가됨.

1.6 보안 감사 4연발: libdl 임의 쓰기, lwp 시그널 범위 초과, OFW 스택 오버플로, lwip-dhcpd 원격 서비스 거부 (10-17 ~ 10-19)

날짜: 2026-10-17 14:25 ~ 10-19 00:37 (생성 / 갱신)　출처: Issue #11898, Issue #11882, Issue #11879, Issue #11878

기여자 XueDugu가 모니터링 기간 내에 네 건의 결함 이슈를 연달아 제출했으며, 모두 도입 커밋, 영향받는 버전 구간, QEMU 재현 환경을 제시함. #11898: libdl/dlmodule이 ELF 재배치 메타데이터에 대해 경계 검증을 수행하지 않아, 변조된 .mo가 로딩 단계에서 제어된 값으로 커널 상태 메모리에 쓸 수 있으며, 최초 도입은 2018년 v3.1.0의 커밋으로 거슬러 올라가고 ARM/RISC-V/x86 세 가지 재배치 구현이 동일 구조임. #11882: lwp의 sys_sigaction이 시그널 번호를 검증하지 않아 커널 힙을 범위 초과하여 읽고 쓸 수 있음 (Smart, v5.0.0부터). #11879: OFW 디바이스 트리 확장에 중첩 깊이 제한이 없어 64개 항목의 np_stack을 오버플로함 (v5.0.2부터). #11878: lwip-dhcpd의 임대 풀이 고갈된 후 dhcp_client_alloc이 무한 루프에 빠져, 인증되지 않은 원격에서 전체 lwIP 스택을 마비시킬 수 있음 (v4.0.0부터). 네 건 모두 열린 상태로 유지됨.

1.7 DFS 코드 충돌 제안 종료 후 재작성하여 재개: 디바이스 제어 명령을 디바이스 클래스별로 인코딩하도록 변경 (10-17)

날짜: 2026-10-17 16:55 ~ 17:06 (종료 / 재개 시간)　출처: PR #11869, PR #11881

지난 호에 기록된 DFS 계층의 F_GETFL/F_SETFL과 RT_DEVICE_CTRL_* 코드 충돌 제안(#11869)이 10-17 16:55에 종료되었으며 머지되지 않음. 11분 후 작성자 CXSforHPU가 #11881(3개 파일 +37/-20)을 별도로 열어 인코딩 계층에서 해결하는 방식으로 변경: RT_DEVICE_CTRL_BASE(Type) = (디바이스 클래스 + 1) × 0x100을 도입하여 상위 바이트는 디바이스 클래스를, 하위 바이트는 클래스 내 일련번호를 나타내며, pin 설정 명령과 시리얼 하드웨어 제어 명령을 각자의 클래스 기반 주소 이후로 이전하여 범용 제어 명령이 더 이상 POSIX의 3, 4와 충돌하지 않도록 함. 새 제안은 심사 중.

1.8 공식 뉴스 인터페이스 연속 60일째 신규 항목 없음 (10-19)

날짜: 2026-10-19 (확인 시간)　출처: RT-Thread 공식 뉴스 인터페이스

공식 뉴스 인터페이스(rt_org 분류)가 반환하는 아카이브 원고의 최신 항목은 여전히 2026-06-17이며, 모니터링 기간 내 신규 항목이 없어 연속 60일째 갱신이 중단됨. 제품 및 활동 정보는 계속 위챗 공식 계정, 커뮤니티 포럼, GitHub 채널을 통해 최초 공개됨. 공식 웹사이트 뉴스 목록 페이지는 프런트엔드 동적 렌더링 방식으로, 10-19 확인 시 “로드 실패”를 반환했으며, 이번 호 뉴스 데이터는 인터페이스를 기준으로 함.

2.1 Ruiqing 플랫폼 V1.8.4 릴리스 예고: 산업용 게이트웨이 가상 네트워크 포트, QY1503 인코더 및 MIPI RGB666, 10-21 라이브 해설 (10-16)

날짜: 2026-10-16 (게시 시간)　출처: EE Times China 보도

Ruiside가 미디어 측을 통해 Ruiqing 플랫폼 V1.8.4 예고를 공개했습니다. 업데이트는 산업용 게이트웨이, 주변장치 드라이버, 디스플레이 인터페이스 및 디버깅 도구를 포함합니다. EG1200 산업용 게이트웨이는 가상 네트워크 포트와 NFS 네트워크 파일 시스템 마운트를 추가하여 네트워크를 통해 개발 보드 파일 시스템에 직접 접근할 수 있어 데이터 공유와 원격 디버깅이 용이해졌습니다. QY1503 로터리 엔코더 드라이버가 추가되어 모터 폐루프, 위치 피드백 및 속도 측정을 지원합니다. RC-Pi-3506의 MIPI는 RGB666을 지원하여 더 많은 모델의 스크린을 점등할 수 있습니다. 또한 MIPI 전원 투입 타이밍 제어, GPIO 핀 풀업/풀다운 설정 및 amp_device 디버깅 명령(AMP 코어 간 통신 상태와 장치 할당 확인)이 추가되었습니다. 공식적으로 10-21 20:00에 RC-Pi-3506에서 항목별 실기 시연을 진행할 예정입니다.

2.2 커뮤니티 튜토리얼: HardFault에서 Cortex-M 크래시 현장 추출 (10-17)

날짜: 2026-10-17 17:04 (게시 시간)　출처: 커뮤니티 글

커뮤니티 작성자 「다무슝」이 Cortex-M 크래시 위치 파악 시리즈 상편을 게시하여 HardFault 처리 방식을 설명했습니다. 예외 진입 시 8개의 핵심 레지스터가 이미 스택에 푸시되며, 오류 원인이 SCB 상태 레지스터에 기록되므로 개발자는 HardFault에서 이를 읽어 출력하기만 하면 오류 위치를 파악할 수 있습니다. 글은 HFSR 설명에 따라 트리거 경로를 정리하고, 이 시리즈 상편은 「현장 출력」만 해결하며 호출 체인 역추적은 하편에서 다룰 것이라고 밝혔습니다. core dump 메커니즘이 없는 MCU 펌웨어 디버깅에 직접적인 참고 가치가 있으며, 시스템 수준 트러블슈팅 방법에 대한 커뮤니티 콘텐츠를 보완합니다.

날짜: 2026-10-17 01:37 ~ 09:13 (커밋 / 병합 시간)　출처: env 버전 커밋, EE Times China 보도

Env 저장소는 당일 버전 전환(env.json 및 info.py가 v2.0.3을 가리킴)을 완료하고 WebUI 내장 문서 내비게이션(+291/-36)을 병합하여 독립 HTML 문서 추적을 허용했으며, PR #302는 10-17 09:13에 병합되었습니다. 공식적으로 동시에 소개 글을 게시했으며, v2.0.3의 핵심은 플러그인입니다. 기능을 .epack 패키지로 묶어 설치, 업그레이드, 활성화, 비활성화 및 제거할 수 있으며, 플러그인은 명령줄 명령을 추가할 수도 있고 WebUI 페이지를 확장할 수도 있습니다. 공식적으로 epack 개발 도구(초기화, 검증, 빌드, 테스트)도 제공합니다. 설치 전에 출처, 권한 및 무결성을 확인해야 하며, 플러그인은 현재 사용자 권한으로 실행되며 보안 샌드박스가 아닙니다. 툴체인은 두 가지 진입점으로 나뉩니다. SDK 다운로드 설치와 로컬 툴체인(MDK, IAR) 등록입니다. Windows에서는 BSP 디렉토리에서 마우스 오른쪽 버튼으로 Env 터미널을 직접 열 수 있습니다. 버전은 RT-Thread 5.1.0 이후 및 메인 개발 브랜치를 대상으로 합니다.

3.2 NaXinwei NS800RT7P65D의 RT-Thread UART 평가 및 BSP 구성 개선 (10-16)

날짜: 2026-10-16 (게시 시간)　출처: EE Times China 평가

미디어가 RT-Thread 기반 NS800RT7P65 UART 평가를 게시했습니다. 이 칩은 NaXinwei NSSine 시리즈 듀얼 Cortex-M7 실시간 MCU로, ARMv7E-M 기반이며 배정밀도 FPU, DSP 확장 및 MPU를 갖추고 있습니다. 글은 칩 수준 UART 리소스와 레지스터 구성부터 코드 수준 기능 테스트까지 다루며, menuconfig 구성 후 rtconfig.h에 해당 매크로가 생성되고 모든 UART 장치가 등록됨을 검증하고, console을 각기 다른 시리얼 포트에 매핑하여 테스트했습니다. 작성자는 또한 보드 수준 드라이버에 보레이트, 정지 비트 등의 하드코딩이 존재함을 지적하고, menuconfig에 매핑하여 BSP 견고성을 높일 것을 제안했으며 개선 제안을 제출했습니다. 동일 칩은 이 모니터링 기간의 커뮤니티 작품 「런화」에도 등장합니다(4.1 참조).

5. 요약 및 동향 관찰

5.1 3일 동향 (10-16 ~ 10-19)

  • 버전 주기 전환: v5.4.0의 버전 매크로와 Kconfig가 먼저 반영되었으나, tag, release와 ChangeLog는 여전히 v5.3.0에 머물러 있어 5.4.0이 릴리스된 것이 아니라 개발 주기에 진입했음을 보여준다.
  • RISC-V 리팩터링 반영: 165개 파일, +1.5만 줄 규모의 Next RISC-V가 병합되어 RV32/RV64, Sv32~Sv57, AIA/CLIC와 M/S 상태를 하나의 ISA 관리 인터페이스로 통합했으며, 여섯 건의 장기 작업 티켓이 같은 날 종료되었다.
  • Smart가 메인라인으로 부상: 13건의 일괄 제안이 syscall, 시그널, MMU, rootfs, QEMU와 K230D를 포괄하며, 방향이 「부팅 가능」에서 「테스트 가능, 인도 가능」으로 전환되었다.
  • 보안 부채 집중 노출: 네 건의 결함 티켓이 libdl, lwp, ofw와 lwip-dhcpd에 걸쳐 있으며, 가장 이른 것은 2018년에 도입된 코드까지 거슬러 올라간다. 세 건은 v5.0 이전 버전에 영향을 미치며, 하루 네 건의 밀도는 최근 모니터링 기간 중 드문 수준이다.
  • 툴체인의 플러그인화 및 AI 협업 진화: Env 2.0.3은 .epack 플러그인과 툴체인 관리를 핵심으로 하며, 공식 rtthread-skills는 BSP, 소프트웨어 패키지와 Git 흐름을 스킬로 작성하여 AI 보조 개발이 공식 저장소에 진입했다.
  • 벤더 적응 지속 확장: HPMicro가 hpm_sdk 1.13.0으로 업그레이드되고 HPM5100EVK가 추가되었으며, Allwinner F101 신규 BSP 제안, Naxinwei NS800RT7P65D가 커뮤니티 UART 평가를 받았다.
  • 공식 채널 침묵: 뉴스 인터페이스가 제60일까지 업데이트 중단되었으며, 공식 웹사이트 뉴스 페이지는 10-19에 로딩 실패를 반환했다.
