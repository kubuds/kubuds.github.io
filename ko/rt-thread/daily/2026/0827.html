1. 커널 및 버전 동향

1.1 netdev: 네트워크 카드 없는 환경에서 ping 널 포인터 크래시 수정

날짜: 2026-08-27 (09:04 베이징 시간 병합)　출처: RT-Thread/rt-thread commit 14ef29af

메인 저장소 모니터링 기간 내 컴포넌트 안정성 수정 1건 병합: fix(netdev): NIC 부재 시 ping 명령 널 포인터 크래시 수정, 커뮤니티 개발자 zhangyuyang 제출 (author 시간 08-26 14:19), 핵심 메인테이너 Rbb666이 08-27 09:04 (UTC 01:04) 병합. 문제 근본 원인: netdev_cmd_ping에서 netdev가 netdev_default로 폴백된 후 널 체크를 하지 않아, QEMU 네트워크 카드 없는 환경에서 ping 실행 시 바로 NULL 역참조로 data abort 발생; 수정 후 폴백 경로에 널 포인터 검사를 추가하여 사용 가능한 네트워크 카드가 없음을 알리고 오류를 반환. 변경 사항은 components/net/netdev/src/netdev.c 단일 파일에 집중됨. 이는 v5.3.0-beta 브랜치 생성 (08-24) 이후 메인 브랜치의 또 다른 저위험 안정성 수정 묶음으로, 이전 HW Stack Guard, finsh 정리와 함께 “정리 기간” 리듬의 연장을 형성함.

1.2 Renesas BSP: SPI 드라이버 2건 수정 병합

날짜: 2026-08-27 (09:01 베이징 시간 병합)　출처: RT-Thread/rt-thread commits 69c26789 / fcc4d6c0

동일 시점 (09:01 UTC 01:01) CYFS가 제출 및 병합한 Renesas BSP SPI 드라이버 수정 2건: 첫째 [bsp/renesas][drivers] Fix SPI runtime configuration, SPI 런타임 구성 문제 수정; 둘째 [bsp/renesas][drivers] Skip invalid chip select writes in SCI SPI, SCI SPI에서 유효하지 않은 칩 셀렉트(chip select) 쓰기 건너뛰기. 두 건 모두 bsp/renesas/ 드라이버 계층 다듬기에 해당하며, 08-25 병합된 RA6W1 BLE OTA 이미지 생성 최적화와 함께 Renesas BSP 지속적 반복 시퀀스에 속함 (RA6W1 BSP 08-05 첫 버전, 08-11 2차 주변장치 보완 후, SPI 드라이버 계층 마무리 지속), “먼저 골격 병합, 이후 드라이버 보완” 특징이 이어짐.

2. 공식 및 커뮤니티 활동

2.1 Ruixin 산업 플랫폼 Workshop 오늘 (08-27) 상하이 개최, 공식 뉴스 API 7일 연속 신규 없음

날짜: 2026-08-27　출처: RT-Thread 공식 뉴스 API / EE Times China (08-21 등록 카운트다운, Google News 경유)

어제 보고서에서 예고한 「루이칭 산업 플랫폼 Workshop: EtherCAT 실시간 제어와 산업 솔루션 실전」이 오늘 상하이에서 개최되며, 이번 주 공식 채널에서 가장 중요한 실제 적용 관찰 지점이다. 모니터링 기간 내 사전 추가 보도는 없었다: gnews 「루이칭 when:2d」 모니터링 기간 11건 적중은 모두 포드 링루이, 지리 즈칭, 성급 유니콘 등 분리 단어 노이즈였고, Workshop 관련 예열이나 현장 보도는 없었다. 사후 보도는 내일(08-28) 나타날 것으로 예상되며, 내일 보고서에서 중점 확인해야 한다. 공식 뉴스 API(rt_org 분류)는 여전히 5건의 오래된 항목이며, 최신은 2026-06-17 아부다비 투자 포럼 보도로 약 2개월 지연되어 7일 연속 신규 항목이 없다. news / activity 분류 인터페이스는 계속 “분류 데이터 없음”을 반환한다.

3. 생태계와 벤더 적응

3.1 canopennode-rtt: LSS 런타임 보드레이트 활성화 추가

날짜: 2026-08-27(11:00 베이징 시간 병합)　출처: wdfk-prog/canopennode-rtt commit 11d7e9eb

RT-Thread용 CANopenNode 통합 소프트웨어 패키지(wdfk-prog/canopennode-rtt)가 11:00에 새 기능 feat[canopennode][lss]: support runtime bitrate activation을 병합하여 CANopen 노드 런타임 보드레이트 활성화를 지원한다. 08-25에 LSS Store 구성 영속화(EEPROM 저장 계층과 AT24CXX 디커플링, 시작 영속화 포함)를 병합한 데 이어, 이는 해당 패키지 LSS 기능의 두 번째 확장이다. 최근 2주간 이 패키지는 안정적인 반복 리듬을 유지했다: 08-17 GFC 프로토콜 진단, 08-19 ASCII 게이트웨이 MSH 콘솔 브리지, 08-20 SDO 블록 전송 검증, 08-24 EEPROM 저장 진단, 08-25 LSS 영속화, 08-27 런타임 보드레이트 활성화로, 매주 2-3건의 기능 커밋을 기록하며 현재 RT-Thread 서드파티 산업 프로토콜 소프트웨어 패키지 중 가장 활발한 것 중 하나다.

3.2 생태계 참고: h120d-protocol 드론 리버스 엔지니어링 문서 업데이트

날짜: 2026-08-27(08:30 베이징 시간 업데이트)　출처: H4ck3rTR/h120d-protocol

커뮤니티 리버스 엔지니어링 프로젝트 h120d-protocol(4 stars)이 Holy Stone H120D 소비자급 드론 WiFi 프로토콜 리버스 엔지니어링 문서를 업데이트했으며, 내용은 패킷 캡처 형식, RT-Thread 펌웨어 내부 구현(RT-Thread internals)과 제어 도구를 아우른다. 해당 드론 펌웨어는 RT-Thread 기반으로 구동되며, 리버스 문서가 RT-Thread 시작 흐름, 태스크 구조 등 내부 구현을 정리한 것은 RT-Thread가 소비자급 드론 분야에서 실제 배포되었음을 측면에서 입증한다. 서드파티 커뮤니티 프로젝트로 공식 적용 사례는 아니며 생태계 참고 성격으로 표기한다. 앞서 같은 날 fetch 후보에 있던 Ni-ear RT-Spark 개발 보드 LED 테스트 저장소(개인 학습 프로젝트)도 이와 같은 성격으로, 모두 별도 항목으로 분리하지 않는다.

4. 산업 응용

4.1 2026 RTOS 성능 순위 발표: RT-Thread, 8대 RTOS 독립 평가에 포함

날짜: 2026-08-26(매체 게재)　출처: EE Times China(Google News 경유) / Beningo 공식 보고서 페이지 / PX5 공식 해설 페이지

EE Times China가 08-26에 「2026년 RTOS 성능 순위 발표!」를 게재했다: Beningo Embedded Group(Jacob Beningo)이 《2026 RTOS Performance Report》를 발표했으며, Eclipse Thread-Metric 테스트 스위트를 기반으로 실제 Cortex-M 하드웨어에서 8종 RTOS를 독립 비교했다——PX5 5.3.1, ThreadX 6.5.1, FreeRTOS 11.3.0, Zephyr 4.4.1, Arm Keil RTX5 5.9.1, RT-Thread, NuttX, Micrium uC/OS-III. 여기에는 9개 native API 테스트(스케줄링, 메모리 할당, 메시지, 동기화, 인터럽트 처리 및 인터럽트 지연 등)와 POSIX pthread 벤치마크, 크로스 아키텍처(M4F vs M33) 및 컴파일러(IAR vs GCC) 영향 부록이 포함된다. 결론: PX5가 2년 연속 전체 1위로 가장 빠름(native API 기준 ThreadX 최대 30.2% 느림, FreeRTOS 80.7% 느림, Zephyr 45.3% 느림); RT-Thread는 native 테스트에서 PX5 대비 최대 86.3% 느림, POSIX pthread 기준으로는 최대 94.6% 느림(PX5 공식 기준, POSIX 시나리오에서는 자사 네이티브 구현이 우위). 이 보고서의 의미: 첫째, RT-Thread가 제3자 독립 평가에서 8강 비교 라인업에 포함되었다는 점은 글로벌 시장 지위를 방증한다; 둘째, 성능 데이터는 최상위 그룹에 미치지 못하며, Beningo 보고서는 RT-Thread를 제외한 모든 참가 시스템에 고정 버전을 표기했으나(RT-Thread는 버전 미표기) 횡적 비교 기준에 한계가 있으므로 구체적 결론은 원 보고서 방법론을 참조한 후 해석할 것을 권한다.

5. 요약 및 트렌드 관찰

  1. 메인 브랜치 소규모 강화 지속: netdev ping 널 포인터 수정과 Renesas SPI 2건 수정이 08-27 오전 같은 날 병합되었고, v5.3.0-beta 수립 이후 메인 브랜치는 계속 저위험 안정성 수정 위주로 진행되며 대형 기능 병합은 보이지 않았다.
  2. RuiyiAI Workshop 오늘 개최: 이번 주 공식 기준 가장 중요한 관찰 포인트로, 모니터링 기간 내 사전 보도는 없었으며 사후 보도는 내일 나타날 것으로 예상되므로, 그때 공식 뉴스 API와 미디어 측을 검증할 필요가 있다.
  3. 서드파티 소프트웨어 패키지 생태계 활발: canopennode-rtt는 주당 2-3건의 기능 커밋 리듬을 유지하고 있으며, LSS 런타임 보드레이트 활성화는 2단계 역량 확장이다; CANopen 산업 프로토콜 방향은 지속 추적할 가치가 있다.
  4. 업계 지위와 성능 평판 공존: RT-Thread가 Beningo 2026 RTOS 성능 순위 8강 비교에 포함되어 시장 지위가 제3자로부터 인정받았다; 그러나 성능 데이터 순위는 뒤처지고 참가 버전도 표기되지 않았으므로 변증법적으로 볼 필요가 있다.
  5. 뉴스 면 지속적 고요: 공식 뉴스 API는 7일 연속 신규 항목이 없었고, 미디어 측은 EE Times China의 순위 보도 1건뿐이며 나머지 gnews 검색 결과는 모두 단어 분리 노이즈였다.

한계 설명: EE Times China 원사이트(eet-china.com)는 로컬 직접 연결 시간 초과되어, 순위 보도 세부 내용은 Beningo 공식 페이지와 PX5 공식 해석 페이지로 교차 검증했다; RT-Thread 참가 버전은 공식 보고서에 표기되지 않아 성능 비교 기준에 불확실성이 존재한다.
