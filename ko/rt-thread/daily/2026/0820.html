1. 커널 및 버전 동향

1.1 memheap 이중 해제 방어 병합: release 빌드에서 중복 free가 더 이상 힙 장부를 손상시키지 않음

날짜: 2026-08-20 (09:48 베이징 시간 병합)　출처: RT-Thread/rt-thread commit 8234a36

메인 저장소 모니터링 기간 내 유일한 신규 병합: [kernel/memheap] fix: stop invalid frees from corrupting heap (작성자 Hui Su, 메인테이너 Rbb666 병합, commit 8234a36). 커밋 설명에 따르면: RT_DEBUGING_ASSERT가 비활성화된 경우 RT_ASSERT()가 더 이상 실행을 중단하지 않아, release 빌드에서 순차적으로 발생하는 중복 free가 이후 로직까지 계속 진행되어 memheap의 힙 통계와 빈 리스트를 손상시킵니다. 수정은 블록 검증 완료 후 바로 return하여 불법 해제가 더 이상 힙 장부를 갱신할 수 없도록 합니다. 커밋에 첨부된 재현 데이터 (double-free: used=64 / alloc=224 / free=64 → 해제 후 used가 4294959232로 변경, 즉 32비트 오버플로)는 취약점의 결과를 직관적으로 보여줍니다; 수정은 scons -C bsp/qemu-vexpress-a9 빌드로 검증되었습니다. 이는 08-17 AF_UNIX 대규모 기능 병합 이후 커널 측의 방어적 강화로, release 빌드 견고성 수정에 해당합니다.

1.2 버전 상태 안정

날짜: 2026-08-20　출처: rt-thread releases

최신 정식 버전은 여전히 v5.2.2 (2025-10-31 릴리스)이며, 모니터링 기간 내 신규 릴리스나 사전 릴리스는 없습니다; packages 인덱스 저장소 역시 모니터링 기간 내 신규 병합이 없습니다 (직전 병합은 08-19 09:17의 LiME-TM으로, 어제 이미 보도됨).

2. 공식 및 커뮤니티 활동

2.1 공식 뉴스 API 모니터링 기간 내 신규 항목 없음

날짜: 2026-08-20　출처: RT-Thread 공식 뉴스 API

공식 뉴스 API (rt_org 분류)는 여전히 5개의 이전 항목이며, 최신은 2026-06-17 아부다비 투자 포럼 보도로 약 2개월 지연이 개선되지 않고 있습니다; news/activity 분류 인터페이스는 빈 값을 반환합니다. 8월 18일 이미 보도된 8월 27일 상하이 Ruiqing 산업 플랫폼 Workshop (EtherCAT 실전)과 8월 17일 AIoT 대회 순위는 모두 공식 API에 동기화되지 않아, 공식 정보 출력의 업데이트 주기가 실제 동향보다 계속 뒤처지고 있습니다; 모니터링 기간 내 새로운 서밋, 해커톤 또는 대학 프로그램 공개 정보도 없습니다.

3. 생태계 및 소프트웨어 패키지

3.1 서드파티 CANopenNode 통합 패키지 지속 반복 개발 (이번 모니터링 기간 생태계 측 최대 활성 지점)

날짜: 2026-08-19 ~ 2026-08-20　출처: wdfk-prog/canopennode-rtt commits

RT-Thread용 CANopenNode 통합 패키지(wdfk-prog/canopennode-rtt, topic: rt-thread, 신규 프로젝트, star 수는 아직 낮음)가 모니터링 기간 내 연속 두 차례 기능 커밋:

  • 08-19 14:42 베이징 시간: ASCII gateway MSH 콘솔 브리지 추가(CANopen ASCII 게이트웨이 명령이 RT-Thread MSH shell을 통해 상호작용);
  • 08-20 11:12 베이징 시간: SDO 블록 전송(block transfer) 검증 지원 추가.

08-17/08-18에 이미 병합된 heartbeat 감독 NMT 마스터 예제, GFC 프로토콜 진단, MCU 측 SDO 클라이언트 검증과 결합하면, 이 패키지는 “예제 우선, 기능별 순차 보완” 리듬으로 빠르게 형성되고 있으며, NMT/SDO/GFC 등 CANopen 핵심 서비스를 커버하고 산업용 필드버스 시나리오를 겨냥한다. 초기 프로젝트 관찰 대상에 속하며, 생태계 동향으로 수록한다.

3.2 생태계 참고(비특집 / 주변부 동향)

  • awtk(zlgopen, 08-20 push): 모니터링 기간 내 문서 개선만 있었고, 범용 임베디드 GUI 프레임워크의 일상적 커밋으로 RT-Thread와 직접적인 연관은 없음(비특집);

4. 산업 응용 특별 장(산업 / 로봇 / 임베디드 지능)

4.1 Ruiqing 플랫폼 DSMC+FPGA 통신 대역폭 90MB/s로 향상

날짜: 2026-08-19(18:15 베이징 시간)　출처: EE Times China(Google News 수록 경유) / EET-China 원문

EE Times China가 《Ruiqing 플랫폼 DSMC+FPGA 통신 속도 90MB/s로 향상》 기술 기사를 게재했다(EET-China 원 사이트 접속 불가, 본문은 검색 요약으로 검증). Ruiqing 플랫폼(Ruiqing Pai RK3506J 산업용 보드 + 공식 FPGA 확장 보드)의 DSMC 병렬 버스가 16비트 통신 지원으로 업그레이드된 후, FPGA 실측 통신 대역폭이 90MB/s로 향상되었다. 기사는 업그레이드 전후 드라이버 메커니즘을 비교했다. 동기화 메커니즘은 “없음(동기 블로킹)”에서 rt_event 이벤트 구동으로 변경되었고, 단일 전송량은 4바이트에서 2KB(DMA 최대 단일)로 향상되었으며, 버스트 설정을 최적화하여 CPU 점유율이 현저히 낮아졌다. 이는 Ruiqing 26.08.06 버전 특성(8월 13일 릴리스 라이브 예고 기준 89MB/s)의 실측 기술 전개이며, 하드웨어 기반은 RK3506J(트리플 코어 Cortex-A7 + 싱글 코어 Cortex-M0, 최대 1.5GHz)의 DSMC/Flexbus 병렬 버스(하드웨어 대역폭 400MB/s, FPGA 고속 데이터 수집 직결)이다. 이 진전은 8월 27일 상하이 EtherCAT 실시간 제어 Workshop과 함께 Ruiqing 산업 플랫폼의 산업용 통신 메인라인에 속하며, 방향은 모션 제어 + FPGA 데이터 수집의 저지연 고대역폭 경로다.

4.2 RT-Thread, Beningo 2026 RTOS 성능 보고서 참가 측정 명단에 선정

날짜: 2026-08-19(19:30 베이징 시간)　출처: EE Times China 《2026년 RTOS 성능 순위 발표, PX5 RTOS가 성능 1위 차지》 / Beningo 2026 RTOS Performance Report

EE Times China는 Beningo(Embedded Group) 2026 RTOS 성능 리포트 발표를 보도했다. 이 리포트는 독립 벤치마크로, 실제 Cortex-M 하드웨어에서 Eclipse Thread-Metric 스위트로 8개 RTOS를 테스트했다——PX5 5.3.1, ThreadX 6.5.1, FreeRTOS 11.3.0, Zephyr 4.4.1, Arm Keil RTX5 5.9.1, RT-Thread, NuttX, Micrium µC/OS-III. 테스트에는 9개 네이티브 API 테스트(기본 처리, 협력/선점 스케줄링, 메모리 할당, 메시지 처리, 동기화, 인터럽트 처리, 인터럽트 선점, 인터럽트 지연 오실로스코프 실측 등) 및 POSIX API 비교가 포함된다. 결과 헤드라인은 PX5의 1위 차지다. ThreadX는 최대 30.2% 느리고, FreeRTOS는 최대 80.7% 느리고, Zephyr는 최대 45.3% 느렸다. RT-Thread는 8개 참가 대상 중 유일하게 중국에서 온 오픈소스 RTOS로 선정되었으며, 구체적 순위와 세부 내용은 이메일 구독을 통해 리포트를 무료로 다운로드해야 확인할 수 있다. 리포트의 전년 대비 데이터(2024 vs 2026)는 FreeRTOS/ThreadX/Zephyr/PX5만을 대상으로 하며, RT-Thread는 이번에 새로 추가된 참가 대상이다. 커뮤니티 입장에서 이는 RT-Thread가 국제 독립 벤치마크의 시야에 들어섰다는 외부 검증 신호이며, 성능 포지셔닝은 리포트의 공식 내용을 기준으로 해야 한다.

5. 요약 및 트렌드 관찰

  1. 커널 측 “소화기 + 방어 강화”: AF_UNIX 소켓(08-17) 이후 모니터링 기간 내 첫 번째 머지는 memheap 이중 해제 방어(08-20)로, release 빌드(어서션 비활성화)에서 중복 free가 힙 회계를 훼손하는 문제를 수정했다. 대규모 기능은 다음 릴리스와 함께 공개될 것으로 예상된다.
  2. Ruiqing 산업용 플랫폼이 이번 달 미디어 측 메인라인이 되다: DSMC 16비트 버스 업그레이드 + rt_event 이벤트 기반 DMA로 FPGA 통신 90MB/s 구현, 이어서 8/27 EtherCAT Workshop 예열로, 산업 제어 실시간 제어 방향의 연속적 성과물.
  3. 국제 벤치마크 노출: RT-Thread가 처음으로 Beningo 2026 RTOS 성능 리포트의 8개 참가 명단(유일한 중국산 오픈소스 RTOS)에 진입했으며, 성능 포지셔닝은 리포트 전문 공개를 기다려야 한다.
  4. 생태계 활성도는 GitHub와 제3자 미디어가 담당: CANopenNode 통합 패키지 등 제3자 프로젝트의 빠른 반복, 공식 뉴스 API가 약 2개월 지연되는 상황이 지속(최신은 여전히 06-17)되고 있어, 공식 정보 출구의 복구가 시급하다.
  5. 한계 설명: EET-China 원 사이트에 접속할 수 없어, DSMC와 RTOS 순위 두 기사의 본문 세부 내용은 검색 요약 및 리포트 공식 페이지 확인에 의존했으며, RT-Thread의 성능 리포트 내 구체적 순위는 확보하지 못했다.
