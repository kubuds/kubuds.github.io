1. 커널 및 버전 동향

1.1 Xuantie C908 BSP 병합: QEMU virt64 플랫폼 RT-Thread Smart 지원

날짜: 2026-08-28 (12:25 베이징 시간 병합)　출처: RT-Thread/rt-thread PR #11719

메인 저장소 모니터링 기간 내 가장 중요한 병합: feat[bsp][xuantie]: c908 support rt-smart. BadmintonMaster가 대신 제출(원본 commit은 shuta.lst의 rt-thread fork에서 유래), 핵심 메인테이너 Rbb666이 08-28 12:25(UTC 04:25)에 병합, 총 27개 파일. 내용: bsp/xuantie/virt64/c908 보드 지원 패키지 신규 추가 — QEMU RISC-V64 VIRT 가상 플랫폼 기반 T-Head Xuantie C908 프로세서 이식, RT-Thread Smart 마이크로커널 모드(커널/사용자 공간 분리)와 표준 모드 이중 빌드 지원, 루트 파일 시스템 실행 설명(link_smart.lds, run.sh) 동봉; 동시에 SMP 적응을 위해 libcpu/risc-v/common64/mmu.c 수정. 툴체인은 Xuantie-900 GCC(musl 버전, riscv64-unknown-linux-musl- 접두사) + Xuantie QEMU 에뮬레이터 사용. 이는 xuantie virt64 BSP 패밀리에서 C910 등에 이어 C908 지원이 추가된 것으로, RISC-V 벡터 확장 커널이 RT-Thread Smart 고급 응용 시나리오에서 개발 검증을 위한 QEMU 가상화 진입점을 제공하며, libcpu RISC-V 공통 레이어 SMP/MMU 적응의 지속적 보강이기도 하다.

1.2 qemu-vexpress-a9 백트레이스 함수명 지원

날짜: 2026-08-28 (11:29 베이징 시간 병합)　출처: RT-Thread/rt-thread commit 0ae80cc7

커뮤니티 개발자 Hui Su 제출: Cortex-A9 QEMU BSP에서 RT_BACKTRACE_FUNCTION_NAME 활성화 시 컴파일러와 어셈블러에 -mpoke-function-name을 전달하여 커널 백트레이스 출력에 함수명을 포함시켜 디버깅을 용이하게 함. 변경은 bsp/qemu-vexpress-a9/SConstruct 단일 파일에 집중된 디버깅 경험 소규모 개선.

2. 공식 및 커뮤니티 활동

2.1 라이브 방송 예고: ADC에서 DMA까지, 데이터 수집 컴포넌트 설계 방법?

날짜: 2026-08-28 (게재)　출처: EE Times China (원문 eet-china.com/mp/a520847.html)

EE Times China가 08-28에 RT-Thread 라이브 방송 예고 “ADC에서 DMA까지, 데이터 수집 컴포넌트 설계 방법?”을 게재. 주제 개요: 첫째, 왜 ADC가 데이터 수집과 같지 않은가; 둘째, 주기적 샘플링과 DMA 샘플링 두 경로 중 선택 방법; 셋째, 다채널 인터리브 프레임 — 처리량과 실시간성을 모두 고려한 데이터 구성 방법. 이 라이브 방송은 이전 “Ruiqing 플랫폼 RK3506 다채널 데이터 수집 컴포넌트 설계와 실천”(eet-china.com/mp/a520342) 글의 연장으로, 동일 주제 시리즈가 엔지니어링 실천에서 라이브 교육으로 나아가며 Ruiqing 산업 플랫폼의 산업 제어 데이터 수집 방향 역량 출력에 대응. 원문 사이트는 로컬 직접 연결 불가, 세부 내용은 검색 인덱스 요약과 제목 기준.

2.2 공식 뉴스 API 9일 연속 신규 항목 없음, Ruiqing Workshop 사후 보도 여전히 부재

날짜: 2026-08-29　출처: RT-Thread 공식 뉴스 API

공식 뉴스 API(rt_org 분류)는 여전히 5건의 이전 항목이며, 최신은 2026-06-17 아부다비 투자 포럼 보도로, 9일 연속 신규 항목이 없었다. news / activity 분류 인터페이스는 계속 “분류 데이터가 존재하지 않습니다”를 반환했다. 어제 보고서에서 점검을 예고한 「루이칭 산업 플랫폼 Workshop」(08-27 상하이 개최)의 개최 후 보도는 모니터링 기간 내에도 여전히 나타나지 않았다. gnews 「루이칭 when:3d」 10건 적중은 모두 Ford Lingrui, Boyue L i-HEV, Geely Emgrand Zhiqing 등 단어 분리 노이즈였고, 「루이칭파이」 정확 검색은 1건뿐이며 역시 Lingrui 영상이었다. 공식 채널 뉴스 면은 계속 조용했고, 미디어 측은 EE Times China 라이브 예고 1건뿐이었다. 루이칭 Workshop 후속 보도는 계속해서 내일의 관찰 지점으로 삼는다.

3. 생태계 및 벤더 적응

3.1 canopennode-rtt 지속 반복 개발: SRDO 객체 사전 및 빌드 테스트 완성

날짜: 2026-08-29(11:10 베이징 시간 커밋)　출처: wdfk-prog/canopennode-rtt

RT-Thread용 CANopenNode 통합 소프트웨어 패키지(커뮤니티 개발자 wdfk-prog 유지관리)는 모니터링 기간 내 3건의 커밋이 추가되었다: canopen[srdo] J09/B09S 객체 사전(SRDO, Safety-Relevant Data Objects, CANopen 안전 관련 데이터 객체) 생성, MCU 진단 테스트 픽스처(test fixture) 추가, 그리고 누적 B 단계 빌드 구성(CI). 이 패키지는 08-25부터 LSS(노드 구성) 영속화 및 런타임 비트레이트 활성화 반복 개발에 들어갔고, 08-27 처음으로 본 데일리 리포트에 수록되었으며(LSS 런타임 비트레이트 활성화), 오늘도 계속해서 CANopen 안전 확장(SRDO)과 엔지니어링(CI/테스트)으로 나아가고 있다. CANopenNode는 오픈소스 커뮤니티에서 잘 알려진 CANopen 프로토콜 스택이며, 이 패키지는 개인 프로젝트(1 star)로 아직 RT-Thread packages 인덱스에 진입하지 않았고, 생태계 참고로 표기한다.

4. 산업 응용

모니터링 기간 내 신규 산업 응용 항목은 없다. 최근 3일 추세: 08-27 EE Times China가 말레이시아 도시 IoT 고객 성공 사례(홍수 경보 + 대기 오염 모니터링, 08-28 데일리 리포트에 수록됨)를 게재했다. 루이칭 산업 플랫폼 Workshop은 08-27 상하이에서 개최되었으나 개최 후 보도는 계속 부재하다. 이번 모니터링 기간의 산업 측은 루이칭 플랫폼 데이터 수집 라이브 교육이 연속 신호로 나타났다.

5. 요약 및 추세 관찰

  1. XuanTie C908, RT-Thread Smart 가상화 검증 진입점 보완: QEMU virt64 플랫폼에 C908 BSP가 추가되어 RT-Thread Smart 마이크로커널과 루트 파일 시스템 실행을 지원하며, libcpu RISC-V 공통 계층 SMP/MMU 적응 수정이 동반되었다——RISC-V 애플리케이션 프로세서 방향(rt-smart)이 Pingtouge 커널 커버리지에서 한 걸음 더 나아갔으며, 이는 모니터링 기간 내 가장 가치 있는 메인 저장소 병합이다.
  2. 공식 뉴스 면 9일째 조용: 뉴스 API 신규 없음, 루이칭 Workshop 개최 후 보도 부재 지속. 미디어 측은 EE Times China 「ADC에서 DMA 데이터 수집」 라이브 예고 1건뿐이다.
  3. 루이칭 플랫폼 콘텐츠 출력이 라이브 교육으로 전환: RK3506 다채널 데이터 수집 엔지니어링 실무(08-22 전후 게재) 이후, 공식은 라이브 형식으로 ADC/DMA 데이터 수집 컴포넌트 설계 시리즈를 전개했으며, 산업 제어 데이터 수집 방향은 현재 루이칭 생태계의 대외 주요 라인 중 하나다.
  4. 커뮤니티 CANopen 안전 역량의 완만한 성장: canopennode-rtt가 LSS 구성에서 SRDO 안전 객체 사전과 CI/테스트 완성으로 나아가고 있으며, CANopen 산업 버스 생태계는 RT-Thread 측에서 개인 프로젝트 형태로 계속 축적되고 있다.
  5. 메인 저장소 모니터링 기간 내 병합 2건뿐: C908 rt-smart(신규 BSP) + qemu-vexpress-a9 백포트 개선, 전반적으로 기능 간헐기에 있으며, 어제 Renesas BSP 마무리 리듬과 일치한다.

한계 설명: EE Times China 원사이트(eet-china.com)는 로컬 직접 연결 시간 초과로, 라이브 예고 세부 내용은 검색 인덱스 요약과 제목에만 의존했다. 루이칭 Workshop 개최 후 보도는 공식 WeChat 채널에만 게시되었을 가능성이 있으며, gnews 단어 분리 노이즈가 커서 커버할 수 없다. canopennode-rtt는 1 star 개인 프로젝트로 영향력이 제한적이며, 수록은 생태계 관찰용이다.
