RuyiAI 위클리 리포트 (2026-10-12 ~ 2026-10-16)

2026-10-16 Kubuds

보고 기간: 2026년 10월 12일(월)부터 10월 16일(금)까지, 총 5영업일

자료 출처: 본 간행물의 일일 RuyiAI 동향 리포트 5호(2026-10-12부터 2026-10-16까지, 각 호의 모니터링 기간은 전일 04:30부터 당일 04:30까지); 추가로 RuyiAI-Stack, ruyisdk, buddy-compiler 세 조직의 168시간 저장소 점검, openRuyi-Project 주요 저장소 보충 점검, 그리고 RuyiSDK 개발자 커뮤니티와 openRuyi 뉴스 페이지의 이중 출처 재확인(10-17 아침까지 포함)

편집 설명: 이번 주 기술 주류는 openRuyi의 K3 펌웨어 플랫폼 라인(10-13부터 10-15까지 3일 연속 3개 버전 릴리스)과 Ztt 행렬 확장 툴체인의 GCC + LLVM 듀얼 백엔드 구현이다. 위클리 리포트는 데일리 리포트 자료 외에 두 가지 점검 신규 발견을 보충했다. 첫째, 10-15 오전 riscv-gcc의 ztt-dev 브랜치에서 단일 배치 20건의 Ztt 커밋(당일 데일리 리포트에는 미수록); 둘째, 10-16의 tilelang-riscv 부활과 Buddy MLIR 0.1.0 릴리스(데일리 리포트 모니터링 기간 이후 발생).

1. 주간 주요 뉴스

  • openRuyi, K3 펌웨어 플랫폼 라인 개척, 10-13부터 10-15까지 3일 연속 3개 버전 펌웨어 릴리스: 10-13 edk2-ruyi 신규 생성(35건 전체 배치 최초 푸시, SpacemiT K3 Pico ITX의 EDK2 플랫폼 코드) 및 ruyifirmware 신규 생성(5건으로 패키징 릴리스 체인 구축), 당일 18:46 첫 버전 「Ruyi Firmware 20261013」 릴리스; 10-14 두 번째 버전에서 UEFI 내 CPU 모드 선택(X100 전용 / X100+A100 혼용 / A100 전용, RVV 및 H 확장 스위치 포함) 도입 및 영구 저장; 10-15 세 번째 버전에서 읽기 전용 System Information 페이지, x64 및 ARM64 UEFI 드라이버 에뮬레이션(기본 비활성화, Platform Settings를 통해 활성화) 및 실험적 AMD ARM64 GOP 1.68 시범 적용 추가. 출처: edk2-ruyi, Ruyi Firmware 20261013, 20261014, 20261015

  • Ztt 행렬 확장 툴체인, LLVM 측 보완하여 GCC + LLVM 듀얼 백엔드 형성(10-12): ruyisdk/llvm-project는 10-12 오전 ztt-dev 브랜치를 신규 생성하고 26건의 LLVM / Clang 패치 전체 스택 최초 푸시 완료(작성자 LukeZhuang, Ztt 확장 기초 지원, 함수 수준 profile, CSR 및 행렬 레지스터 그룹, 명령어 어셈블리 및 디스어셈블리, IR 타입 및 intrinsic, Clang 행렬 레지스터 타입, 레지스터 할당 후 의사 명령어 확장, M 레지스터 및 ACC 오버플로 처리 포함, 마지막 커밋에서 테스트를 AME 진단 체계에 정렬); GCC 측 riscv-gcc의 ztt-dev 브랜치는 09-30 개설 후 이미 10-08의 36건, 10-11의 51건, 10-15의 20건을 연속 반영(마지막 배치는 이번 주 점검에서 발견). attached-matrix-extension의 Ztt intrinsic 문서 V0.6 PR과 함께 「규격—문서—듀얼 툴체인」 체인이 동시에 활발하다. 출처: llvm-project ztt-dev, 헤드 aeb52e1a, riscv-gcc ztt-dev

  • Buddy MLIR 0.1.0 정식 릴리스, RISC-V 크로스 컴파일 및 CI 전면 확대 (10-16): buddy-compiler/buddy-mlir는 이번 주 16개의 커밋과 4개의 릴리스가 있었으며, 그중 0.1.0은 베이징 시간 10-16 새벽에 릴리스되었다(tag release/v0.1.0). 이어서 야간 라인은 0.1.1.dev 시리즈(dev20261016, dev20261017)로 전환되었다. RISC-V 라인의 움직임이 집중되었는데, buddy-cli에 RISC-V 보드 크로스 컴파일 추가(#987), Makefile의 RISC-V 타깃 수정(#986), 크로스 컴파일 프로세스 간소화(#975), buddy-server에 RISC-V 서버 크로스 컴파일 추가(#989)를 수행했으며, manylinux riscv64 빌드에서 Ruyi 패키지 인덱스로 riscv64 버전 torch를 설치하고 libsndfile을 보완했다(#990, #937, #988). 출처: buddy-mlir, BUDDY MLIR 0.1.0, PR #989

  • RuyiAI의 tilelang-riscv, 약 한 달간의 침묵 끝에 5개의 RISC-V 커밋으로 Buddy 릴리스 체인에 합류 (10-16): 해당 저장소의 마지막 커밋은 09-20이었으며, 이번 주 금요일에 5개의 커밋이 연달아 적용되었다. 코드 포맷팅, 업스트림 연산자 런타임 시맨틱 지원(lane-local 상태, ragged copy, 동적 제어 흐름, FP8/FP4 변환 수정), TileOps 런타임 적응 업그레이드(서브모듈을 67250e81로 올리고 paged-cache gather 및 varlen GQA sinks 커널 구동 성공), Buddy MLIR release CI 추가 및 Buddy CI에서 Python 확장 빌드가 포함된다. 이는 TileLang의 RISC-V 백엔드가 Buddy MLIR의 버전 산출물을 기준으로 지속적 통합을 시작했음을 의미한다. 출처: tilelang-riscv 커밋 목록, 5개 첫 배치 32fce5ed

  • openRuyi 배포판 주간 대규모 유지보수: Go 모듈 약 90건, KDE Plasma 6.7.5 총 39개 패키지, LLVM 24, mesa 26.2.4 및 PowerVR 백포트 (10-12 ~ 10-14): 10-12 메인 저장소 40건 중 39건이 KDE Plasma 데스크톱 스택 전체를 6.7.5로 업그레이드했다(plasma-workspace / kwin / systemsettings / powerdevil / breeze 등). 10-13 하루 103건으로, 약 90건이 Go 생태계 모듈 일괄 업데이트(k8s 0.37.1 시리즈, gRPC 1.84, OpenTelemetry Collector 1.67, 클라우드 벤더 SDK 등)였으며, llvm-snapshot을 LLVM 24로 업그레이드, audit 4.2.1의 RISC-V 지원 활성화, GnuPG 스택 일괄 업데이트도 포함되었다. 10-14에는 3건이 그래픽 스택으로 전환되어 mesa 26.2.4와 첫 번째 PowerVR 최적화 백포트가 이루어졌다. 10-16에는 rust-riscv-0.16 등 6개의 Rust RISC-V 관련 crate의 SPEC이 추가되었다. 출처: openRuyi 커밋 목록, PR #1410, PR #1347, PR #1399

  • ruyisdk/llvm-project, XTHeadVector 인덱스 메모리 접근 혼합 너비 수정 병합 (10-13, PR #168): th.vlxe / th.vxse에서 데이터와 인덱스 요소 비트 너비가 일치하지 않는 시나리오의 처리를 수정하고(부호 있는 오프셋, 메모리 요소 크기, 마스크 passthrough 및 제로 길이 시맨틱 유지), intrinsic lowering을 정수와 부동소수점 벡터의 혼합 너비로 확장했으며, RV32 / RV64를 위한 마스크, 제로 길이, 음수 오프셋 및 대형 인덱스 사용 사례의 codegen 커버리지를 보강했습니다. 해당 rebase-17.0.6 브랜치의 마지막 실질 커밋은 6월이었으며, 이번 작업은 XuanTie 벡터 툴체인 라인이 장기 유지보수에서 표적 수정으로 전환되었음을 보여주는 신호입니다. 출처: PR #168, issue #136

  • 커널 양대 라인 추진: openRuyi linux, ruyi/7.3.y 신설 후 첫 31건; linux-xuantie-kernel 벤더 키를 XUANTIE로 통일하고 hwprobe 확장 보강 (10-15 ~ 10-16): ruyi/7.3.y는 10-13에 생성되어 10-15에 첫 31건을 반영했습니다(K3 GPU 노드 및 디스플레이 전원 도메인, Type-C Port A / USB3 PHY / FUSB301, 이더넷 MAC에 EEPROM 바인딩, spacemit DP 수정 시리즈, K3에서 amdgpu 동적 PCIe 속도 전환 비활성화, UFS FASTAUTO, SG2044 SRD3-12 보드 지원 등). linux-xuantie-kernel은 10-15에 T-Head 벤더 확장 키를 전면 XUANTIE 형태로 개명했고(XTHEADVDOT → XUANTIE_VDOT 등), 10-16에 추가로 4건을 반영했습니다. Ziccamoa / Ziccif / Ziccrse / Za64rs / Zicclsm을 cpufeature와 hwprobe에 포함하고, ISA 확장 id 공간에 사설 대역을 할당하며, 확장 id를 업스트림과 정렬시켰습니다. 출처: ruyi/7.3.y, linux-xuantie-kernel

  • 격주 리포트 078 공개, 주제는 「RuyiSDK, RISC-V 중국 서밋에 참가」; 서밋은 10-18부터 10-20까지 선전에서 개최 (10-13): 078호는 8건의 편찬 파이프라인(#371 ~ #378)을 거쳐 확정되어 포럼에 동기화되었습니다. 주요 내용으로는 패키지 관리자 0.54.0이 월말 출시 예정(ABI 호환성 검사, macOS 공식 패키지, SpacemiT K1/K3 툴체인 적응 개발 중), IDE 1차 다듬기, glibc와 newlib 각각 6개의 벡터 수학 함수 이식, GCC의 ZTT 백엔드 완성 및 GEMM/GEMV 검증 방안(컴파일 시간 약 5.05% ~ 6.97% 감소), LLVM의 RISC-V P 확장 intrinsics, V8이 처음으로 실제 하드웨어에서 RVV Wasm SIMD 테스트를 수행하고 hwprobe 폴백 패치 병합, OpenJDK의 JEP 483 / 515 AOT 이식, Go의 riscv64 원자 연산 수정 등이 있습니다. 서밋 의제에는 기조연설, 포스터 전시, D15 부스 데모가 포함됩니다. 출처: 078호 파일, 포럼 #2891

2. RuyiAI 스택 진척 (PyTorch / Triton / TileLang RISC-V 적응)

모니터링 기간 개요: RuyiAI-Stack 조직(18 ~ 19개 저장소)의 이번 주 활동은 pytorch(네 번의 아침 각각 전체 스택 재빌드 1회 완료), llvm-project(10-12 야간 재생 후 중단), triton-riscv(야간 빌드 신규 회차), tilelang-riscv(10-16 다섯 건으로 회복), ruyiai-daily(10-12 ~ 10-16호 연속 갱신), 사이트 저장소(기여자 데이터 정례 커밋)에 집중되었습니다. harness, mxnet, caffe, FBGEMM, IntrinTrans, VecIntrinBench, cpuinfo, torq-tile, dsh-osc, pytorch-ci, SyncBots-DeepAgents는 모니터링 기간 내 푸시가 없었습니다.

PyTorch fork: 네 번의 아침 각각 전체 스택 재빌드 1회, 오픈 PR 8건 매일 갱신

  • 재빌드 주기: riscv 브랜치는 10-12, 10-13, 10-14, 10-15 네 차례 아침에 각각 전체 스택 재빌드를 완료했으며, 매 회차 23건의 로컬 커밋이 새로운 커미터 시간으로 다시 적용되었고, 헤드는 회차에 따라 6ff4eefe → a17584a3 → b870a71a → 73ef01df5d로 순차 갱신되었습니다(동일 제목 「[SyncBots] Integrate PyTorch at e188cec」, SHA는 재빌드에 따라 갱신됨). 스택 구성은 기존 시퀀스를 유지했습니다(#44 bytes_to_scalar 수정, #50 차단 목록 확장, #42 ULP 허용 오차, 3건의 SyncBots 통합, #40 / #41 CI 파싱, #20 / #21 CI 분리, #18 cpuinfo 교체, #12 커밋 해시 고정, #11 / #4 / #1 차단 목록 시리즈). 10-15 회차와 이전 회차 헤드 사이에는 총 101건의 차이가 있으며, 업스트림 10-13 ~ 10-14 커밋의 병합이 포함되어 있습니다.
  • 리뷰 대기열: 8건의 오픈 PR(#23 Enable XNNPACK, #35 테스트용 PR, #36 타임아웃 완화, #38 DataLoader 임시 비활성화, #43 패치 간소화, #46 ATen RVV 지원, #48 RVV CPU capability, #51 riscv64 로컬 이미지)이 매일 오전 재빌드와 동시에 베이스라인을 일괄 갱신했으며, 주간 내내 오픈 상태를 유지하여 머지 및 클로즈가 없었습니다.
  • 주기 외 후속: 점검 시(10-17 아침) 10-17 새벽을 커미터 시간으로 하는 또 한 회차의 재빌드 배치가 확인되었으며, 그중 「Add riscv64 image locally (#51)」가 이미 스택과 함께 브랜치에 반영되었습니다. 즉 RVV 외의 CI 로컬 이미지 보완이 코드 라인에 진입했으므로 다음 주 관찰 항목에 포함할 것을 권장합니다. 출처: riscv 브랜치, PR 목록

컴파일러 fork(llvm-project): 10-12 밤 재적용 후 3일 연속 밤 미속행

  • riscv 브랜치는 10-12 심야에 26건의 패치 스택 재적용을 완료했으며(헤드 0fb2da86, 여전히 #31 「A100 HP/SP 및 pack/unpack lowering과 스케줄링 캘리브레이션」), 베이스는 당일 업스트림 스냅샷으로 동기화되었습니다. 이후 10-13, 10-14, 10-15 세 차례 밤 모두 새로운 회차가 나타나지 않았고, 10-16 점검 시점까지 헤드는 10-12 버전에 머물러 있습니다.
  • 2건의 FPGA 백엔드 PR(#25 「BOSCAME FPGA 백엔드」, #28 「xboscame FPGA」)은 오픈 상태를 유지하며, 최종 갱신은 10-12에 멈춰 있습니다. buckyball 브랜치(10-06 헤드)는 동작이 없습니다. main 브랜치 업스트림 동기화는 정상적으로 진행되었습니다(이번 주 매일 15:00경, 일반 커밋은 필터 규칙에 따라 개별 수집하지 않음).
  • 관찰 포인트: 야간 재적용이 재개되는지 여부, 그리고 ruyisdk/llvm-project 유지보수 라인(XTHeadVector 수정이 rebase-17.0.6에 이미 머지됨)과의 역할 분담에 변화가 생기는지 여부. 출처: riscv 브랜치, PR #25, PR #28

외부 동향: RISE의 SpeexDSP RVV 최적화와 XuanTie C950의 행렬 확장 서사

  • RISE SpeexDSP RVV 최적화 (10-14): SpeexDSP에 Meson 빌드, Checkasm 테스트 및 수작성 RVV 커널을 도입하고 K1(VLEN 256)과 K230(VLEN 128)에서 검증—K1 부동소수점 리샘플링은 Clang 18 / GCC 13 베이스라인 대비 각각 약 3.71배 / 3.59배. 이 작업은 RVV 최적화를 VoIP, 오디오 리샘플링 등 기초 멀티미디어 라이브러리로 확장했으며 SpacemiT 플랫폼과 직접 관련된다. 출처: RISE 블로그
  • 다모아카데미 XuanTie C950 인터뷰 (10-15): RISC-V 인터내셔널 공식 사이트에 XuanTie 수석 과학자 Meng Jianyi 인터뷰 게재—팀은 C950의 64코어 목표 구성에서 Qwen3.8-27B를 로컬 실행, 처리량 30 tokens/s 초과, 독립 GPU 또는 NPU 없이 달성, 해당 처리량 달성에는 약 400 GB/s급 메모리 이동이 필요하며 고대역폭 메모리와 실리콘 검증된 자체 개발 행렬 확장에 의존; 팀은 이후 Qualcomm, IBM, VRULL, ISCAS, BOSC 등과 함께 AME(Attached Matrix Extension) 태스크 그룹을 발족해 표준화를 추진. 요점: prefill은 주로 밀집 행렬 연산, decode는 대역폭 병목으로 전환; 독립 행렬 레지스터(INT4 / INT8 ~ INT32, FP4 / FP8 / FP16 / BF16 ~ FP32 혼합 정밀도 누산) 채택으로 RVV 레지스터 경쟁 회피; 규격은 아직 데이터 레이아웃, 누산기, 반올림과 포화, 컨텍스트 저장 복원, 예외와 가상화, 컴파일러와 ABI 매핑을 포괄해야 함. 출처: RISC-V International 인터뷰
  • 문서 측면: attached-matrix-extension의 Ztt intrinsic 문서 V0.6(PR #1)은 계속 열려 있으며, GCC / LLVM 두 ztt-dev 라인의 코드 진전과 상호 호응한다.

7. 트렌드 관찰

  • K3가 이번 주 유일한 체계적 메인라인으로 부상: 펌웨어(3일 3개 버전), 커널(ruyi/7.3.y 첫 배치 31건), 이미지(kiwi-image 자동화) 세 계층이 같은 주에 동시에 움직였으며, 펌웨어는 이미 「링크 개통」에서 「CPU 모드 선택 가능 + 드라이버 시뮬레이션 가능」으로 진전했다. 관찰 포인트는 이러한 기능들이 10-18 서밋 주간에 시연 가능한 완제품 형태를 갖출 수 있는지, 그리고 3단계 CPU 모드의 실측 데이터다.
  • 매트릭스 확장이 「단일 백엔드 추진」에서 「듀얼 백엔드 + 규격 + 연산자 검증」 병렬로 전환: GCC ztt-dev 세 배치(36 → 51 → 20건)의 주제가 기능 구축에서 다른 확장과의 협력 정확성(크로스 RVV / Zfa / 원자적 연산의 상태 보존)으로 이동했고, LLVM 측 ztt-dev 첫 배치가 나머지 절반을 보완했으며, 문서 V0.6과 AME-operator 튜토리얼이 뒤따랐다; 동시에 upstream AME 태스크 그룹이 XuanTie 주도로 표준화를 추진 중——저장소 내 초안과 규격 라인이 동기화되기 시작했다.
  • 두 fork 유지보수 라인의 리듬 분화가 확대 중: PyTorch riscv 브랜치는 매일 아침 23건 재빌드, 8건 PR 동기화 갱신을 유지; LLVM riscv 브랜치는 10-12 이후 연속 3일 밤 재생되지 않았다. 전자는 업스트림 추종 메커니즘의 자동화 수준이 높음을 보여주고, 후자는 LLVM 측 작업 중심이 ruyisdk/llvm-project 유지보수 라인(XTHeadVector 수정이 해당 라인의 성과)으로 이동했을 가능성을 시사한다.
  • Buddy Compiler가 RuyiAI의 실질적 업스트림 중 하나로 부상: buddy-mlir는 일주일 내에 0.1.0 릴리스와 riscv64 크로스 컴파일 / CI / manylinux 릴리스 체인 수정을 완료했고, triton-riscv의 의존성 업그레이드와 tilelang-riscv의 신규 CI 모두 Buddy의 버전 산출물을 기준으로 삼았다——「MLIR 컴파일 프레임워크 → 연산자 프론트엔드 → 야간 산출물」체인이 이번 주 처음으로 riscv64에서 릴리스 가능한 wheel까지 클로즈드 루프를 완성했다.
  • 배포판 유지보수가 「배치 처리 + 보안 배치」 이중 리듬으로 진입: openRuyi 단일 일자 90건 Go 모듈, 39개 패키지 KDE, GnuPG 전체 스택, 5개 패키지 보안 연속 릴리스로 의존성 추종이 엔지니어링화되었음을 보여준다; 암묵적 제약은 전체 재빌드 비용과 이미지 릴리스 리듬의 결합이며, 0.54.0과 2026.10 이미지의 시점을 관찰할 가치가 있다.
  • 관찰 대기 목록: 0.54.0 월말 릴리스와 ABI 호환성 검사; ruyi/7.3.y가 언제 이미지 채널에 진입하는지; triton-riscv #85 리뷰; LLVM FPGA 두 건의 PR(#25 / #28); PyTorch #46 / #48(RVV)과 #51(로컬 이미지가 이미 브랜치에 반영); attached-matrix-extension 문서 PR #1; 서밋(10-18 ~ 10-20) 기간 중 버전 또는 성과 릴리스 여부.
