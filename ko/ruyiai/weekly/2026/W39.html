RuyiAI 위클리 리포트 (2026-09-21 ~ 2026-09-25)

2026-09-25 Kubuds

보고 기간: 2026년 9월 21일(월)부터 9월 25일(금)까지, 총 5 영업일 자료 출처: 본지의 일일 RuyiAI 동향 리포트(09-21, 09-22, 09-23, 09-24, 09-25 총 5회분), 그리고 조직 저장소 168시간 모니터링 기간 점검 및 커뮤니티 이중 출처 재검증(09-26 아침까지 포함) 편집 설명: 본 모니터링 기간은 RuyiSDK 릴리스(ruyi 0.53.0), 툴체인과 커널, 보드 지원 매트릭스, openRuyi 배포판, 커뮤니티와 행사의 다섯 가지 차원을 다룹니다. 기술적 사실은 모두 코드 저장소, 릴리스 산출물 및 커뮤니티 포럼의 실측 검증에서 비롯되었습니다.

1. 이번 주 주요 뉴스

  • ruyi 0.53.0 정식 릴리스, 소프트웨어 소스 간 설치 상태 문제 사흘 만에 종결(09-21 ~ 09-25): 09-21 저녁 커뮤니티 사용자가 문제 #501을 보고했습니다. 소프트웨어 소스를 전환한 후 이미 설치된 소프트웨어 패키지가 “미설치”로 표시되고, 재설치가 건너뛰어지며, 제거 시 오류가 발생하여 “파일은 디스크에 있는데 상태는 영원히 미설치”라는 교착 상태가 만들어졌습니다. 09-23 오전 메인테이너 xen0n의 수정이 PR #502를 통해 main에 병합되었으며(162줄 변경, 그중 117줄은 회귀 테스트), 설치 상태를 설치 신원에 따라 소스 간 매칭하도록 변경했습니다. 09-24 오전 수정이 v0.53.x 릴리스 브랜치로 backport되었고(10:34) 곧바로 버전 번호가 부여되었으며(10:35), 14:57에 0.53.0 정식 버전이 릴리스되었습니다(GitHub Release 비사전 릴리스, PyPI는 같은 날 14:56에 동시 등록). 09-25 저녁 릴리스 당일 마무리 PR #503(테스트 설치 타임아웃을 패키지 수 기준으로 계산)이 병합되었습니다. 정식 버전은 0.53.0-beta.20260917 대비 커밋 두 건만 추가되었습니다. 테스트 기간에 이미 병합된 바이너리 패키지 ABI 호환성 검사, 기본 소프트웨어 소스 우선순위 수정, 다운로드 실패 시 미러 폴백이 테스트 버전과 함께 정식으로 전환되었습니다. 다음 버전은 2026년 10월 말로 예고되었습니다. 출처: Release 0.53.0, PR #502, PR #503

  • RuyiSDK, 2026 윈치 대회 루이 커뮤니티 부스에 등장(09-22 ~ 09-24): 2026 윈치 대회가 09-22에 개막했으며, RuyiSDK는 대회의 루이 커뮤니티 부스에 등장하여 산업 파트너와 RISC-V 개발자를 대상으로 원스톱 RISC-V 소프트웨어 개발 키트, 툴체인, 패키지 관리자, IDE 개발 플러그인 및 다중 하드웨어 플랫폼 적응 성과를 집중적으로 전시했고, 현장에서 실습 데모와 기술 교류를 진행했습니다. 부스는 대회 마지막 날인 09-24까지 이어졌습니다. 출처: 커뮤니티 게시글 2849

  • 격주 리포트 제077호 발행: “ruyi 0.53 릴리스” 특집판 게시(09-24): 제077호 《RuyiSDK 격주 진행 보고》가 09-24 16:01에 개발자 커뮤니티에 정식 발행되었습니다. 주요 내용은 다음과 같습니다. 패키지 관리자 0.53 업데이트 목록(ABI 호환성 검사 및 보고 인프라, 기본 소프트웨어 소스 우선순위 수정, 다중 소스 동명 동일 버전 설치 상태 동기화 수정 등), IDE 신규 기능 16항목, 지원 매트릭스 다중 보드 항목(P550 Fedora 44, CoM260 Kit, CH32V307, Milk-V Duo S의 Zephyr 4.1.99 등), 기반 구성 요소(glibc의 pow를 libmvec로 이식, newlib의 rsqrt와 expm1 이식, GCC의 SpacemiT 벤더 확장을 16.2 브랜치로 backport 완료, LLVM의 P 확장 및 RVA23.1/RVB23.1 방향 다수 병합, V8이 Word32 비교 최적화를 통해 AOT 내장 라이브러리 정적 코드 크기를 2.7% 감소, OpenJDK 11개 메인라인 PR, Go chacha20 RVV 재측정)을 포함합니다. 커뮤니티 동향에는 윈치 대회 등장이 수록되었습니다. 원고에는 다음 버전이 2026년 10월 말에 릴리스될 예정이며, 이번 호는 중추절과 국경절 연휴 일정으로 인해 앞당겨 발행되었음이 명시되었습니다. 출처: 발행 게시글 2852, 077호 원고

  • riscv-gcc 16.2 브랜치에 SpacemiT X100/A100 코어 지원 병합 (09-21): 두 개의 패치(SpacemiT Mark Zhuang 작성)가 두 코어를 공식적으로 컴파일러 -mcpu/-mtune에 추가: X100 스케줄링은 범용 비순차 모델 generic_ooo에 매핑; A100은 순차 듀얼 이슈, 마이크로아키텍처는 X60에 근접, 당분간 X60 비용 모델 재사용, ISA상 X100에 가장 근접, 주요 차이는 H 확장 미구현, VLEN=1024(zvl1024b)이며 xsmtvdotii 확장 포함(확장 정의는 riscv-ext-spacemit.def와 확장 문서에 동기화 작성). K3 플랫폼을 목표로 하는 개발 보드(예: CoM260 Kit의 X100 8개 + A100 8개 조합)의 경우, 툴체인에서 직접 -mcpu로 코어를 선택하고 해당 확장 정의와 스케줄링 설정을 얻을 수 있다. 출처: X100 커밋, A100 커밋

  • 보드 지원 매트릭스 일주일에 12건 보고서: “단일 보드 다중 시스템” 모드 체계적 확산 (09-20 ~ 09-23): CoM260 Kit(SpacemiT K3)가 단일 Buildroot에서 Bianbu, openEuler, OpenHarmony 4개 시스템 패밀리로 확장; Milk-V Duo S에 Arch Linux, Ubuntu, Debian, RT-Thread, xv6 5건 보고서 추가; SiFive HiFive Premier P550에 Fedora 44 Server 추가; CH32V307이 RT-Thread BSP 5.3.1로 업데이트; K510이 BuildRoot 보고서 업데이트. 모니터링 기간 말에 아직 3건 심사 중: Duo S의 Zephyr와 RT-Thread Smart, ESP32C3의 RT-Thread 5.3.1. 함께 board-docs에서 P550과 CoM260의 보드 문서, HelloWorld/CoreMark 예제와 ROS 2 과정 입구를 동기화 보완. 출처: 지원 매트릭스 PR #400, PR #407

  • openRuyi 배포판 롤링 업데이트 고빈도 추진: 커널 이중 라인 업그레이드, 컨테이너 riscv_hwprobe 허용 (09-20 ~ 09-24): 5회 데일리 리포트 모니터링 기간 내 소프트웨어 패키지 디렉터리 합계 약 79회 커밋. 커널 linux가 7.2.6으로, linux-lts가 6.18.52로 상승하고 4개의 ruyi/* 브랜치 동시 푸시; openruyi-linux-build 패키지 신규 추가로 빌드 의존성 통일, 스펙 파일 전면 RPM 매크로로 전환; containers-common이 기본 seccomp 화이트리스트에 riscv_hwprobe 허용(OpenSSL과 zlib-ng가 ENOSYS로 인해 조용히 스칼라 구현으로 폴백하여 컨테이너 내 암호화 및 압축 성능 저하 방지); 보안 업데이트 일괄 반영(pcre2 10.48, imagemagick 7.1.2.31, expat 2.8.5 등). 테스트 라인은 같은 날 BRS 규정 준수 커버리지 추진: fwts에 riscv-brs AML 검사 10건 추가, kvm-unit-tests에 BRS SBI와 EFI 하 ACPI 부팅 테스트 보완. 출처: openRuyi 커밋 기록

  • llvm-project에 매트릭스 확장 사전연구 브랜치 신규 개설, XTHeadVector 혼합 폭 메모리 접근 수정 제출 (09-23 ~ 09-24): ruyisdk/llvm-project가 모니터링 기간 내 AME, riscv-ime-preview 두 브랜치 신규 추가(09-23의 ame0p6와 함께 매트릭스 확장 방향 사전연구 라인 구성); 09-24 오후 rebase-17.0.6 기반으로 PR #168 제출, T-Head 벡터 인덱스 메모리 접근 명령어 th.vlxe/th.vxse의 혼합 폭 인덱스 지원 수정(949행 수정, 6개 파일 커버), 2025년 2월 제기되어 장기간 열려 있던 이슈 #136에 대응. 출처: 브랜치 목록, PR #168

  • 프레임워크 측은 넓고 얕게: PyTorch fork 재정렬 후 전환 조용, 조직에 mxnet 및 caffe 두 저장소 신규 추가 (09-20 ~ 09-23): PyTorch fork의 riscv 브랜치는 09-20에 96개 커밋 재정렬을 완료했고, 09-21에 한 차례 더 강제 푸시(열린 PR 8개의 베이스라인 일괄 갱신)가 발생한 후, 한 주 내내 기능 커밋이 없었다; RVV 두 건의 패치(#46 ATen RVV 지원, #48 RVV CPU capability)는 대기열에 걸쳐 주를 넘겨 머지되지 않았다; CI 측에는 PR #51(riscv64 로컬 이미지 빌드 스크립트, 네이티브 riscv64 하드웨어 요구)이 신규 추가되었다. 09-23에 조직에 mxnet과 caffe 두 저장소가 신규 생성되었다(완전한 업스트림 이력 포함). 고전 딥러닝 프레임워크 커버리지가 넓어졌다. 출처: riscv 브랜치, PR #51

2. RuyiAI 스택 진척 (PyTorch / Triton / TileLang RISC-V 적응)

PyTorch fork: 한 차례 재정렬, 한 차례 강제 푸시, 이후 한 주 내내 조용

  • 09-20 브랜치 재정렬: riscv 브랜치(저장소 기본 브랜치)의 브랜치 헤드가 ca728fab에서 6d667e1e로 변경되었으며, 96개 커밋 앞서고 22개 뒤처진 상태로, rebase 후 재푸시된 자동화 동기화 형태에 해당한다. 기존 RISC-V 전용 패치(byte 변환 수정, 선형 교차 엔트로피 ULP 허용 오차, inductor 연산자 정보 테스트 blocklist, ci-riscv64 워크플로 등)를 더 새로운 업스트림 베이스라인으로 재정렬했으며, 열린 PR 7개의 브랜치 상태도 이에 따라 갱신되었다.
  • 09-21 강제 푸시: 08:24에 기본 브랜치가 다시 force push되었다(타임라인 기록 조작자 WuXintong123). GitHub는 열린 PR 8개(#23, #35, #36, #38, #43, #46, #48, #51)에서 기준 브랜치 강제 푸시 이벤트를 기록하고 업데이트 타임스탬프를 일괄 갱신했다; 브랜치 헤드는 4f173e3e(bytes_to_scalar 수정 일괄)이다.
  • 09-22부터 조용: riscv 브랜치에 신규 커밋 없음, 열린 PR 8개에 신규 머지 없음, 신규 오픈 없음, 닫힘 동작 없음; RVV 두 건의 심사 대기 패치(#46, 작성자 소프트웨어연구소 Zhang Fei, 22개 커밋, 32개 파일, +2361/-32줄; #48, 작성자 XYenChi, 21개 커밋, 18개 파일)는 대기 시간이 네 개의 보고 기간을 넘겼다.
  • CI 이미지 현지화: PR #51이 .ci/docker/build-riscv64-local.sh(25줄)를 추가했으며, 머신 아키텍처가 riscv64이고 docker buildx에 의존할 것을 요구한다. CI 이미지 체인을 보완하기 위한 것으로 검증 상태는 WIP이다.
  • main 업스트림 동기화: 기간 내 매일 약 20~89회의 업스트림 동기화 커밋(09-21 기간 89회가 최고치)이 있었으며, RISC-V 키워드로 건별 필터링한 결과 관련 내용이 없어 이 스택 진척에 포함하지 않는다.

  • 릴리스 폐쇄 루프와 운영 리듬: 문제 보고(#501, 09-21)부터 수정 병합(09-23), backport와 릴리스(09-24), 마무리(09-25)까지 사흘 남짓 소요되었고, 「수정, 릴리스 노트, 격주 보고서」가 동일 릴리스 주기 내에서 폐쇄 루프를 형성했다. 정식 버전과 테스트 버전은 단 두 개의 커밋 차이로, 릴리스 브랜치 규율이 명확하다. 커뮤니티 대외 리듬(격주 보고서 077이 「09-24 릴리스」 예고를 이행)과 내부 기술 리듬이 동기화되어 있다.
  • K3/Jindie 플랫폼 지원 체인이 지속적으로 촘촘해짐: 툴체인 측 「핵심 식별(GCC -mcpu/-mtune)에서 연산자 최적화(RVV 실측)로, 다시 통합 패키지 튜닝(RuyiTuner)으로」 이어지는 3개 계층이 이번 주기에 모두 진전되었다. X100은 잠정적으로 범용 비순차 모델을 사용하고, A100은 X60 비용 모델을 재사용하는데, 이는 모두 과도기 방안이며 스케줄링 세분화와 테스트 커버리지를 추적할 가치가 있다.
  • 보드 지원 매트릭스가 「단일 보드 다중 시스템 + 부속 자산」의 체계화 단계에 진입: 일주일 동안 열두 건의 보고서가 애플리케이션급(P550, K3)에서 MCU급(CH32V307, K510)까지 걸쳐 있으며, 각 보드의 보고서, 문서, 예제, 과정 완성도가 향상되었다. 심사 대기열 길이가 단일 일자 병합 수보다 커뮤니티 기여 활성도를 더 잘 반영한다.
  • 프레임워크 측 심층 추진이 툴체인 및 시스템 측에 비해 지체: PyTorch fork의 riscv 브랜치는 조용하고, RVV 두 건의 패치가 주를 넘겨 대기 중이다. 조직에 새로 등록된 mxnet과 caffe는 「확장」 조치이며, 「넓고 얕은」 단계적 상태는 두 저장소의 첫 배치 커밋으로 검증을 기다린다. 다음 단계로 #46/#48 심사와 mxnet/caffe의 용도 정착을 관찰한다.
  • 시스템 소프트웨어가 「돌아감」에서 「올바르게 돌아감, 규정에 맞게 돌아감」으로 전환: 컨테이너 seccomp의 riscv_hwprobe 허용, 커널 PMA 정정 확장, BRS 규정 준수 테스트 집중 보완 — 이번 주기에서 기술적 함량이 가장 높은 커밋은 대부분 이런 뉴스를 만들지 않는 수정들로, 실측 성능과 플랫폼 품질 선언을 직접 결정한다.
  • 공백과 관심 지점: ruyiai-daily는 09-24부터 두 기간 연속 업데이트 중단. 뉴스 측에서 RuyiAI, RuyiSDK, Ruyi 커뮤니티, openRuyi에 대한 중영문 다중 검색이 지속적으로 제로 히트. openRuyi 2026.09 월간 버전 공지 미발행. 0.53.0의 미러 사이트 동기화와 커뮤니티 설치 피드백. 지원 매트릭스 심사 중 3건의 병합 리듬. llvm-project 두 개 예비 연구 브랜치의 후속 내용.

검증 방식

  • GitHub 조직 검증(168시간 기간): RuyiAI-Stack과 ruyisdk 조직의 주요 저장소 커밋과 Release를 커버(Atom과 웹페이지 이중 채널, API 한도에 의존하지 않음). pytorch, llvm-project 등 업스트림 fork의 커밋은 RISC-V 관련 키워드로 건별 필터링.
  • 주요 저장소 커밋 수준 재검토: linux-xuantie-kernel, ruyi, ruyiai-daily, support-matrix, ruyisdk/llvm-project 등, 09-26 아침까지 확인.
  • 커뮤니티 이중 출처 검증: RuyiSDK 개발자 커뮤니티 포럼 최신 주제 목록; openRuyi 배포판 뉴스 페이지 2026.09 공지 상태.
  • 이번 주기 뉴스 측(Google News 중영문 다중 검색)에서 연속 제로 히트, 5기 데일리 리포트 모두 조직 저장소와 커뮤니티 채널을 주 출처로 하며, 이는 해당 주제의 상시적 특징이다.

기준 설명

  • 커밋 집계는 각 기간 데일리 리포트 모니터링 기간을 기준으로 한다(기간이 인접하며 소량의 중복 집계를 허용하고, 기간을 넘는 항목은 최초 수록일 기준으로 집계한다).
  • 업스트림 fork(PyTorch main, llvm-project 등)는 커밋량이 많고 대부분 RISC-V와 무관하므로, 리포트는 키워드 필터링 후의 관련 내용만 채택한다.
  • 「공용 미러 사이트 0.53.0 동기화 진행 상황」은 09-25 데일리 리포트 모니터링 기간 말에 관찰된 것이며, 이후의 진전은 이번 점검 범위에 포함되지 않는다.
  • ruyiai-daily의 업데이트 중단 상태는 09-26 아침 점검 결과이다(09-24, 09-25 두 기간 파일 모두 나타나지 않음).
