오늘의 핵심: buddy-mlir 3일 연속 0.1.5, 0.1.6, 0.1.7 릴리스, RISC-V 휠 동시 제공 (11-20 ~ 11-22)

출처: BUDDY MLIR 0.1.5, 0.1.6, 0.1.7. PR #1074.

3일 내에 buddy-mlir가 정식 버전 3개를 출시했다. 0.1.5는 11-20 23:40, 0.1.6은 11-21 22:49, 0.1.7은 11-22 01:12에 릴리스되었으며, 간격은 각각 약 23시간과 2시간이다.

세 버전의 태그는 모두 구체적인 커밋을 가리킨다. 0.1.5는 20d3a102를 가리키며, 이는 11-19에 머지된 ZTT v0.6 방언 교체이다. 0.1.6은 8cbc1a9b를 가리키며, 이는 #1074「Release LLVM with dump() support」이다. 0.1.7은 a848378f를 가리키며, 제목은 「Shrink the LLVM tarball so it fits in one release asset」이다.

각 버전은 8개의 에셋을 포함한다. x86_64의 wheel과 tar.gz 외에도 manylinux_2_39_riscv64의 wheel과 tar.gz, riscv64의 buddy-cli 단일 파일, 그리고 LLVM 24.0.0git의 사전 빌드 패키지 두 세트가 있다.

용량 면에서 0.1.7의 riscv64 wheel은 380,057,776바이트, x86_64 wheel은 365,782,329바이트이다. riscv64의 buddy-cli는 436,952바이트, x86_64는 759,592바이트이다. LLVM 쪽은 x86_64 패키지가 1.03 GB, riscv64 패키지가 1.14 GB이다.

세 버전 모두 릴리스 노트가 없고 본문이 비어 있다. 확인 가능한 정보는 태그, 커밋, 에셋 목록뿐이다.

오늘의 핵심: DeepSeek-R1-Distill-Qwen-1.5B의 K3 A100 FP16 최적화 머지, Prefill 43.42 token/s (11-23)

출처: PR #997. 커밋 3d5d674a. K3 설정 f16_k3.json.

#997은 11-23 00:25에 머지되었으며, 10-25에 생성되어 리뷰가 약 한 달간 진행되었다. 20개 파일을 변경했으며, 새로 추가된 A100 legalization pass, IME 방언 확장, 모델 설정을 포함한다.

PR 설명에서 제시한 핵심 수단은 네 가지이다. 첫째, 네 개의 FP32 누산기가 전체 K 리덕션에서 레지스터에 상주하며, Prefill은 8×32 분할, Decode는 블록당 32개 출력 채널을 계산한다. 둘째, 일부 Decode 프로젝션 가중치를 N32/K8 패널로 묶고, 나머지 프로젝션은 기존 RVV 레이아웃을 유지한다. 셋째, Prefill은 네이티브 VLEN=1024와 BLIS 폭 64를 사용하고, 요소별 연산자와 벡터화된 SiLU를 융합한다. 넷째, 이상의 선택을 models/deepseek_r1/specs/f16_k3.json에 집중시키고, 기존 설정의 기본 파이프라인은 변경하지 않는다.

실측 데이터는 PR 설명에 기록된 대로이다. Prefill은 128개 위치를 평가하고, Decode는 64번째 위치부터 32스텝을 측정하며, 8스레드, A100 코어 8~15, 네 번의 샘플을 사용한다. 표의 단위는 token/s이다.

구현 Prefill Decode
Buddy 메인라인, 패킹된 FP16 4.53 5.88
llama.cpp (SpacemiT 백엔드 0.1.6) 27.95 3.90
Buddy, 본 PR 43.42 6.06

Prefill은 Buddy 메인라인 대비 약 8.6배 향상되었고, llama.cpp 대비 55% 높다. Decode는 llama.cpp 대비 55% 높고, Buddy 메인라인 대비 3%만 높다.

Prefill 수치는 세션 및 인터페이스 호출 오버헤드를 포함하며, PR 설명에 명시되어 있다. llama.cpp 측은 FP16 GGUF 가중치와 FP16 KV cache를 사용했고, 양측 입력 ID는 동일하다.

동일한 커널 세트는 다른 모델에도 재사용되었다. #1075는 Whisper Base, #1076은 PaddleOCR-VL-0.9B, #1001은 Qwen3-0.6B를 대상으로 한다. 세 건 모두 #997의 pass와 가중치 패킹을 참조한다.

1.2 FlagGems 예제 2개 추가 개설: 연산자 72 + 61개, 누적 279개 (11-21, 11-22)

출처: PR #131. PR #132.

#131은 11-21 18:53에 열렸으며 연산자 72개를 다룹니다. #132는 11-22 18:48에 열렸으며 연산자 61개를 다룹니다. 두 PR 모두 python/examples/flaggems/만 변경합니다.

#131의 네 가지 계열은 좌표 복사, 내부 복사와 할당, 형상 구성, 타입 변환과 채우기입니다. PR 설명에는 세 가지 상위 편차가 나열되어 있습니다: padding 래핑은 aten의 (w, h, d) 순서로 입력을 받은 뒤 커널의 (d, h, w)로 재배열합니다; replication의 역방향은 스칼라 소스 위치를 기준으로 스캔하여 aten의 누적 순서에 맞춥니다; rank가 2보다 클 때 rot90은 마지막 차원 항을 누락했습니다.

#132의 네 가지 계열은 BLAS 래핑과 희소 smm, gamma 특수 함수, 양자화 연산자, 저정밀도와 희소 행렬 곱입니다. PR 설명에는 fp64 점곱은 fp32 누적까지만 가능하므로 이런 축소는 스칼라 FMA 루프로 정밀도를 보존하도록 변경했다고 명시되어 있습니다; e5m2 fp8은 강등 경로가 없어 커널 내 상향 변환으로 바꾸었고, e4m3와 int8은 네이티브를 사용합니다.

테스트 수는 계속 증가하고 있습니다. #131은 7830개 통과, 739개 신규를 기록했습니다; #132는 8617개 통과, 787개 신규를 기록했습니다. 모두 x86_64에서 실행되었으며 기존의 크래시 파일 세 개는 제외했습니다.

다섯 개 PR이 하나의 사슬을 이룹니다: #126의 63개, #127의 43개, #130의 40개, #131의 72개, #132의 61개로, 합계 279개의 연산자 예제입니다. PR 설명에 따르면 선행 PR이 병합되지 않았을 때 diff는 선행 커밋을 포함하므로, #131은 main 대비 34개 커밋, 548개 파일이며, #132는 38개 커밋, 670개 파일입니다.

1.3 pytorch의 riscv 브랜치는 지난 동기화에 멈춰 있고, main은 계속 업스트림 트래픽을 받음 (11-23 상태)

riscv 브랜치의 헤드는 여전히 3b5279fd “[ci] Drop JENKINS_RC (#57)”이며, 시각은 11-15 19:00에 멈춰 있습니다. 모니터링 기간 내 해당 브랜치의 커밋은 0건입니다.

main 브랜치는 모니터링 기간 내 20건이며, 내용은 여전히 업스트림 동기화입니다. 샘플링에서 Inductor의 CUTLASS 옵션 수렴, MPS의 avg_pool2d_backward Metal 이전, XPU의 SDPA 훈련 검사, float64 반올림 관련 롤백 1건이 보입니다.

RISC-V 키워드로 필터링하면 이 커밋들에서는 0건이 매칭됩니다. 즉 모니터링 기간 내에 RuyiAI 자체의 RISC-V 변경은 없습니다.

포크에는 현재 9개의 브랜치가 있으며, agent/riscv-linear-cross-entropy-ulp, improve-riscv64-ci, sync/upstream-lc-eps-riscv 등이 포함됩니다. 이 세 브랜치는 모니터링 기간 내에 새 커밋이 없습니다.

#1075는 다른 경로를 갑니다. 인코더의 P @ V는 4행 M 전개 FP32 누적 RVV 커널로 낮아지고, matmul_transpose_b와 conv_1d_ncw_fcw는 IME로 낮아집니다.

세 건의 공통점은 벡터 너비를 하드웨어 VLEN에 바인딩한다는 것입니다. 지난 회차 triton 측 #129의 튜닝도 같은 사고방식을 사용했으며, 양측의 매개변수 기준을 대조할 수 있습니다.

4.2 0.1.6은 dump() 지원 보충, 0.1.7은 LLVM 자산 압축 (11-21)

출처: PR #1074. 커밋 a848378f.

#1074의 발단은 구체적으로 명시되어 있다. 나이틀리 빌드는 main에서 빌드되지만 #1062가 llvm-multitarget 브랜치에 머지되었기 때문에, 0.1.5의 LLVM 패키지에는 dumpPretty()만 있고 dump()는 없다.

다운스트림 현상은 링크 실패로, undefined reference to mlir::Operation::dump() 및 mlir::Value::dump() const 오류가 발생한다. 수정 방법은 LLVM_ENABLE_DUMP를 켜고 이 두 헬퍼만 복원하며, assertion은 활성화하지 않는 것이다.

PR 설명에서는 추가로 LLVM 설치가 해시 기준으로 캐시되므로, 이후 버전에서는 llvm_cache_mode=clean을 한 번 실행해야 해당 스위치가 반영된다고 언급한다.

0.1.7은 자산 상한을 처리한다. 커밋 설명에는 riscv64의 LLVM 설치 패키지가 gzip 후 단일 자산 2 GiB 상한을 약간 초과하여 v0.1.6에서 「size must be less than 2147483648」 오류가 발생했다고 명시되어 있다.

수정 방법은 다운스트림에서 사용하지 않는 개발자 도구를 잘라내고, src, share, libexec를 제거하며 나머지 부분을 strip하는 것이다. x86_64 실측 결과 1617 MB에서 817 MB로 감소했다.

설명에는 한 번의 실패한 시도도 기록되어 있다. 처음에는 파일을 직접 삭제했으나, LLVMExports.cmake가 configure 단계에서 임포트 대상이 누락된 파일을 가리켜 중단되었기 때문에 잘라내는 방식으로 변경했다.

두 버전은 현재 각각 8개의 자산을 가진다. riscv64의 LLVM 패키지는 0.1.7에서 1,138,715,828바이트로 상한 이하이다.

공식 사이트 저장소의 모니터링 기간 내 두 건은 모두 chore: update contributors.json [skip ci]이며, 시각은 11-21 05:27과 11-20 06:29이다. 이러한 자동 커밋은 페이지 내용을 변경하지 않는다.

5.2 포럼에 새 글 여덟 개, 다섯 개는 도박 스팸 게시물 (11-22)

출처: RuyiSDK 커뮤니티 최신 토픽.

모니터링 기간 내 신규 토픽 8개. 시간순으로 최신에서 과거로, 11-22에 “신성회사 게임 회원 등록”류 스팸 게시물이 다섯 개 있으며, 동일 도메인이 반복 게시되었다.

유효 게시물은 세 건으로 대략 11-20에서 11-22 사이다. 11-22의 《단계적으로 배우는 xv6-riscv 개발》 Part 3가 게시되어 파일 시스템을 다룬다. 11-20에는 RISC-V Club 창립 기념식 및 RISC-V 자동차 칩 기술 및 응용 생태계 심포지엄 보도를 전재했다. 11-20에는 또 한 편의 오픈소스 기술 핫이슈 뉴스 정보가 있다.

지난 호에 언급된 격주 리포트 081 게시물은 여전히 목록에 있다(11-19). 격주 리포트 082는 아직 게시되지 않았으며, 격주 주기에 따라 다음은 약 12-03이다.

포럼의 스팸 게시물은 심사 차단이 없다. 다섯 게시물의 게시 시간이 같은 날에 집중되어 있어, 일괄 게시에 해당한다.

5.3 openRuyi 패키징 저장소 55건, 커널과 펌웨어 패키지 갱신 (11-22)

출처: openRuyi 커밋 목록. linux 7.3.5 커밋. linux-firmware 커밋 2717e73d.

패키징 저장소 모니터링 기간 내 55건으로, 28개 SPECS 패키지를 포함하며, 기간은 11-20 11:56부터 11-22 20:24까지이다.

가장 큰 부분은 커널이다. linux가 7.3.5로 올라갔고, linux-lts는 6.18.64로, linux-headers는 7.3.5를 따라갔으며, 세 건 모두 patchset과 config 갱신을 동반한다. linux-lts는 rust BuildRequires 하나를 복구하기도 했다.

두 번째는 펌웨어이다. linux-firmware는 8건으로, 20261019로 올라갔고, powervr-firmware 하위 패키지가 신규 추가되었으며, noarch 빌드로 전환되고, WHENCE에 따라 License를 도출하며, 파일 중복 제거를 수행했다.

세 번째는 Go 패키징이다. 신규 go-github-* 패키지는 clickhouse-go, pierrec-lz4, cloudflare-golz4, gettext-go, jsonpath, handysort, colortext 등을 포함하며, 함께 go-rpm-macros가 0.3으로 올라갔다.

나머지는 정례적 후속 조치이다. libuv는 1.53.0으로, softhsm은 2.7.0으로, debugedit는 5.4로 올라갔고, unicorn은 %prep을 수정했으며, powertop, ntfs-3g, openntpd, rtkit, tclap, genext2fs는 각각 업데이트되었다.

배포판 측에는 새 버전이 없다. 뉴스 페이지 최신은 여전히 10-19의 두 건이며, 월간 버전은 여전히 2026.09이고, 2026.10과 2026.11은 릴리스되지 않았다.

6. 동향 관찰

6.1 릴리스가 월 단위 진행에서 다운스트림 블로킹 패치로 전환

지난 호에는 ruyi가 0.55.0을 11월 말로 미룬다고 기록했다. 이번 호에서 ruyi는 beta를 냈고, buddy-mlir는 사흘 만에 세 버전을 연속 릴리스했다.

0.1.6과 0.1.7 모두 기능 버전이 아니다. 한 건은 다운스트림 링크에서 누락된 dump()를 보충했고, 한 건은 자산 크기를 압축해 2 GiB 상한을 통과시켰다.

판단 근거는 커밋 설명이다. #1074는 triton의 undefined reference를 직접 명시했고, a848378f는 size must be less than 2147483648을 직접 명시했다.

이는 버전 번호가 패치 채널로 사용되고 있음을 보여준다. 대가는 0.1.7과 0.1.6이 분기되어, 다운스트림이 두 수정을 동시에 받으려면 다음 병합을 기다려야 한다는 점이다.

6.2 K3 A100에서 모델 최적화 파이프라인 형성

#997 병합 후, 동일한 IME 커널이 Whisper, PaddleOCR-VL, Qwen3 세 모델의 PR에 나타났다.

세 건의 성능 수치는 모두 동일한 머신 K3-002, 동일한 코어 그룹 8~15, 8스레드, VLEN=1024로 기록되었다. 가로 비교가 가능하다.

이득의 규모 차이는 매우 크다. DeepSeek의 Prefill은 메인 8.6배, Whisper의 엔드투엔드는 818.8배이다. 후자의 기준값은 인코더 재사용을 하지 않은 F32 단일 포워드에서 나왔으며, 배수가 베이스라인에 의해 증폭되었다.

검증 가능한 기준은 토큰 시퀀스가 참조 구현과 일치한다는 점이다. #1076은 19개 토큰이 전부 동일함을 기록하고 OCR 텍스트를 첨부했다.

6.3 툴체인 측은 병합 대기 큐 적체기 진입

triton-riscv의 다섯 FlagGems PR이 하나의 체인으로 이어져, 합계 279개 연산자 예시를 담고 있다. 각 PR은 앞 PR이 병합되어야 diff를 재계산할 수 있다.

pytorch의 riscv 브랜치는 11-15에, tilelang-riscv는 11-16에 멈춰 있다. 두 곳 모두 새 커밋이 없다.

ruyi 측은 반대로, 여섯 건의 PR이 하루 만에 병합 완료되고 beta가 나왔다. 차이는 ruyi의 변경이 CLI와 설정에 집중되어 리뷰 범위가 좁다는 점이다.

한계 설명

이번 모니터링 기간은 3일(11-20 04:30 ~ 11-23 04:30)로, 주말을 포함한다. 월요일 기간은 3일로 계산하며, 11-20호 리포트의 마감 시점과 앞뒤로 연결된다.

0.1.5부터 0.1.7까지 세 버전 모두 릴리스 노트가 없고 본문이 비어 있다. 버전 간 차이는 태그가 가리키는 커밋과 compare 결과로만 추정할 수 있으며, 공식적으로 항목별로 나열되지 않았다.

0.1.7과 0.1.6의 분기 상태는 GitHub compare API에서 가져왔다. 이후 병합이 있으면 결론을 다시 확인해야 한다.

#997, #1075, #1076의 성능 수치는 모두 PR 작성자가 자체 측정하여 보고한 것으로, 이번 기간에 K3 하드웨어에서 재측정하지 않았다. Whisper의 818.8배는 인코더 재사용을 하지 않은 F32 단일 순전파를 기준선으로 한 것이므로, 이 배수는 다른 모델과 횡적으로 비교하기에 적절하지 않다.

ruyi 0.55.0-beta의 19개 변경 중 13개는 모니터링 기간 내에 대응하는 커밋이 없으며, 본문에서는 0.54.0 주기의 누적으로 처리했고 항목별 반영 날짜를 확인하지는 않았다.

포럼 스팸 게시물은 제목으로 판단했으며, 게시물을 하나씩 열어 확인하지는 않았다. Google News 6개 쿼리에서는 샹산(XiangShan) 관련 보도 한 건만 검색되었고, 이번 주제와 무관하여 제외했다. arXiv 최신 논문은 11-19자이며, 모니터링 기간 내 신규는 없다.
