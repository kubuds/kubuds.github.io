오늘의 중점: 툴체인 동기화 이중 라인——Triton-RISCV 패치 신규 LLVM API 적응 (#86 머지), LLVM riscv 브랜치 또 한 차례 야간 리플레이 완료

날짜: 2026-10-09 ~ 2026-10-10　출처: triton-riscv PR #86, 머지 커밋 e00fdd60, llvm-project riscv 커밋 목록, 헤드 커밋 8f38c047, PR #25, PR #28

triton-riscv는 09-14(#81) 이후 첫 PR 병합을 완료했다. 기여자 trdthg가 10-09 정오에 생성 및 병합한 PR #86 「[patches] Support newer LLVM symbol and inline-asm APIs」(1개 파일, +111줄, 생성에서 병합까지 약 20분)이다. 배경은 renovate가 관리하는 Buddy MLIR 의존성 업그레이드 PR #84로, buddy-compiler/buddy-mlir를 nightly/v0.0.9에서 nightly/v0.0.11로 올리는 내용이었다. v0.0.11은 더 새로운 LLVM 버전을 포함하며, 그 MLIR API(기호 및 인라인 어셈블리 인터페이스 등)가 고정 프런트엔드의 Triton과 더 이상 호환되지 않아 x64와 riscv64, 각 Python 버전의 CI가 빌드 단계에서 전면 실패했다. #86은 패치 형태로 새로운 LLVM 기호와 인라인 어셈블리 API 지원을 보완했고, 병합 후 해당 블로킹이 해제되었다(#84는 이후 당일 오후에 갱신되어 열린 상태로 병합 대기 중이다).

LLVM 측면에서는 llvm-project의 riscv 브랜치가 10-09 심야에 또 한 차례 패치 스택 전체 리플레이를 완료했다. 26개의 로컬 패치가 새로운 커미터 시간으로 다시 적용되었으며(푸시 약 베이징 시간 23:00), 헤드는 #31 「A100 HP/SP와 pack/unpack lowering 및 스케줄링 캘리브레이션」(8f38c047)을 유지했다. 스택 구성은 이전 라운드와 동일하다(BOSC AME, Buckyball, IME lowering to A100 dot, xtame 등 벤더 확장 패치와 SyncBots 통합 기록 포함). 리플레이 완료 후 두 개의 FPGA 백엔드 PR(#25 「BOSCAME FPGA 백엔드」, #28 「xboscame FPGA」)의 업데이트 시간이 10-10 00:53에 갱신되어 새로운 베이스라인에서 리뷰 진행을 기다리고 있다.

핵심 요약: 본 모니터링 기간에 두 개의 툴체인 유지보수 라인이 전후로 자리잡았다. LLVM 측은 야간 리플레이를 완료했고, Triton 측은 새로운 LLVM API에 대한 패치 적응을 완료했다. 두 가지가 함께 RISC-V AI 컴파일 스택이 빠르게 진화하는 LLVM 업스트림 아래에서 「리플레이—적응—빌드 채널」의 안정성 엔지니어링을 구성한다. 해당 병합은 당일 ruyiai-daily 10-10호에 수록되어 「RuyiAI의 Triton→Buddy/MLIR 빌드 체인에 직접 관련되며, LLVM 업그레이드 후 인터페이스 비호환을 해제한다」는 평가가 달렸다.

1. RuyiAI 스택 진행 상황(PyTorch / Triton / TileLang RISC-V 적응)

모니터링 기간 개요: RuyiAI-Stack 조직에서 모니터링 기간 내 작업은 네 곳이다. llvm-project(riscv 브랜치 야간 리플레이 26건), pytorch(riscv 브랜치 신규 없음, 8건의 열린 PR 베이스라인 일괄 갱신, main 업스트림 동기화 73건), triton-riscv(#86 병합과 #84 갱신, 야간 채널 기록 유지), ruyiai-daily(2회 연속 발행)와 사이트 저장소(2건의 일상 커밋). harness, tilelang-riscv, mxnet, caffe, FBGEMM, IntrinTrans, VecIntrinBench, cpuinfo, torq-tile, dsh-osc, skills, pytorch-ci, SyncBots-DeepAgents 등은 모니터링 기간 내 푸시가 없다.

1.1 llvm-project: riscv 브랜치 또 한 차례 패치 스택 리플레이 완료(26건), FPGA 2건 PR 업데이트 리뷰 대기(10-09 ~ 10-10)

날짜: 2026-10-09 ~ 2026-10-10　출처: riscv 커밋 목록, 헤드 커밋 8f38c047, 커밋 d68a4f62, PR #25, PR #28

riscv 브랜치는 10-09 심야(약 23:00)에 또 한 차례 패치 스택 전체 리플레이를 완료했다. 26개의 로컬 패치가 새로운 커미터 시간으로 다시 적용되었고, 헤드 8f38c047은 여전히 #31 “A100 HP/SP 및 pack/unpack lowering과 스케줄링 교정”(이전 라운드 헤드와 동일 제목, 정례적 리플레이에 해당)이다. 스택 구성은 기존 26개를 유지했으며(#30 “IME intrinsics를 SpacemiT A100 dot 명령어로 lowering”, #29 BOSC AME 명령어 업데이트, #27 xtame 설계, #24 BOSC AME 백엔드 설계, #23 XBuckyball 명령어 캐리어, #20 Buckyball 벤더 확장, #18 / #16 / #14 등, 그리고 [SyncBots] Integrate LLVM 기록 포함)을 포함한다. 브랜치 베이스에는 10-09 당일 업스트림 커밋(UTC 14:57 전후)이 보이며, 즉 이번 리플레이가 최신 업스트림 스냅샷을 동기화해 가져왔다. 리플레이 완료 후 두 건의 FPGA 백엔드 PR 업데이트 시간이 10-10 00:53에 갱신되어 열린 상태로 리뷰 대기 중이다. 모든 세부 사항은 오늘의 주요 사항을 참조.

1.2 PyTorch fork: riscv 브랜치 모니터링 기간 내 신규 없음, 8건의 열린 PR 베이스라인 일괄 갱신, main 업스트림 동기화 73건(10-09)

날짜: 2026-10-09　출처: riscv 브랜치 커밋, PR 목록

riscv 브랜치는 모니터링 기간 내 신규 커밋이 없다. 헤드는 이전 기간의 “[SyncBots] Integrate PyTorch at e188cec” 통합 라인을 유지한다. 8건의 열린 PR(#23 Enable XNNPACK, #35 테스트용 PR, #36 타임아웃 완화, #38 DataLoader 임시 비활성화, #43 패치 간소화, #46 ATen RVV 지원, #48 RVV CPU capability, #51 riscv64 로컬 이미지)의 업데이트 시간이 10-09 오전(09:21)에 일괄 갱신되었으며(매일 정례적 베이스라인 동기화 리듬의 연장), 모두 열린 상태를 유지하고 모니터링 기간 내 병합과 종료는 없었다. main 브랜치는 모니터링 기간 내 73건의 업스트림 커밋을 동기화했다(샘플링 결과 inductor, MPS, ROCm, CUDA 등 범용 변경으로 필터링 규칙에 따라 개별 수록하지 않음, 제목 중 RISC-V 관련 커밋은 보이지 않음).

1.3 triton-riscv: 패치 스택의 새 LLVM API 적응 병합(#86), Buddy 의존성 PR 갱신, 야간 채널 기록 일괄 유지보수(10-09)

날짜: 2026-10-09　출처: PR #86, PR #84, PR #85, Releases 페이지

메인 브랜치의 이번 모니터링 기간 유일한 커밋은 PR #86의 병합이다(10-09 12:45, 커밋 e00fdd60, 배경과 세부 사항은 오늘의 주요 사항을 참조). 의존성 측면에서는 renovate의 Buddy MLIR 업그레이드 PR #84(buddy-compiler/buddy-mlir → nightly/v0.0.11.dev20260925)가 10-09 오후(16:38)에 한 차례 갱신되어 열린 상태를 유지했다. 커뮤니티 기여자 PR #85(softmax 및 matmul 최적화)는 모니터링 기간 내 업데이트가 없어 열린 상태를 유지했으며, 나머지 열린 PR은 동작이 없었다. 야간 채널 측면에서는 09-20 / 09-27 / 10-04 세 기간 빌드의 Release 기록이 10-09 정오(11:51 ~ 11:52)에 일괄 업데이트되었으며(빌드 산출물과 게시 타임스탬프는 변동 없음, 채널 유지보수 동작에 해당), 신규 기간 빌드는 없으며 최근 빌드는 여전히 “Nightly 2026-10-04-12c2f6a”이다(CPython 3.12 / 3.13 / 3.14 대상 x86_64 및 riscv64 6개 휠 커버, 기존 주간 리듬에 따라 순연).

1.4 정보 및 사이트 인프라: ruyiai-daily 10-09 / 10-10 두 기간 연속 게시, 사이트 저장소 정례 커밋(10-09 ~ 10-10)

날짜: 2026-10-09 ~ 2026-10-10　출처: 10-09 기 커밋, 10-10 기 커밋, 사이트 커밋 d462ffd0

기술 정보 저장소 ruyiai-daily가 두 기를 연속 발행: 10-09 기(10-09 06:26 발행)의 요점에는 Triton-RISCV Agent와 Harness 통합 회고, SpacemiT AI Gateway의 모델 다운로드 및 이어받기 기능, XiangShan difftest 가속기 클럭이 포함됨; 10-10 기(10-10 06:16 발행)의 주요 소식에는 triton-riscv #86의 LLVM 대응(오늘의 중점 참조), Ubuntu가 RISC-V 대상 실험적 데스크톱 이미지 공개(SpacemiT K3 테스트 참여 가능), XiangShan FMA 조기 웨이크업 최적화(SPECfp2006/GHz 3.44% 향상) 등이 포함됨. RuyiAI 공식 사이트 저장소의 모니터링 기간 내 2건의 일상적 커밋(contributors.json, 10-09 및 10-10 아침)이 있으며 신규 블로그 글은 없음. 연구개발 인프라 저장소 harness는 모니터링 기간 내 신규 커밋 없음(해당 Triton-RISCV agent 통합은 이전 기 항목).

2. RuyiSDK 툴체인 및 배포판(빌드, 툴체인, IDE, openRuyi)

모니터링 기간 개요: ruyisdk 조직의 모니터링 기간 내 동작은 두 곳: VS Code 플러그인(PR #262 개설)과 ruyi-imager(야간 채널 일상적 갱신); riscv-gcc, riscv-binutils, riscv-gnu-toolchain, ruyi, packages-index, support-matrix, board-docs, ruyi-tuner, ruyici, sail-riscv, riscv-isa-sim, qemu, ruyi-backend, AME-operator, attached-matrix-extension 등은 모니터링 기간 내 커밋과 릴리스 없음. openRuyi-Project 조직의 동작은 메인 저장소에 집중됨(13건, 2.3 참조).

2.1 riscv-gcc 및 매트릭스 툴체인: 모니터링 기간 내 전면 침묵(ztt-dev 헤드 10-08 유지)

날짜: 2026-10-09(상태)　출처: ztt-dev 커밋 목록, riscv-binutils, riscv-gnu-toolchain

모니터링 기간 내 전면 침묵: ztt-dev 브랜치 헤드는 10-08의 af51a350 유지(36건 Ztt 배치, 이전 기에 기술); riscv-binutils의 ztt-dev 브랜치(최신 09-30)와 riscv-gnu-toolchain의 ame-experimental 브랜치(최신 09-30)는 신규 동작 없음; PR 측은 모니터링 기간 내 신규 없음(최근 병합 #20 / #21은 10-07로 모니터링 기간 외).

날짜: 2026-10-09(상태)　출처: VecIntrinBench, IntrinTrans, FBGEMM, MXNet PR 목록, caffe PR 목록

벡터 내장 함수 벤치마크, 내장 함수 번역, 저정밀 연산자 라이브러리를 대상으로 하는 세 저장소는 계속 조용함(VecIntrinBench 최종 커밋 02-13, IntrinTrans 06-25, FBGEMM fork 07-13); 같은 그룹의 cpuinfo(05-20), torq-tile(04-09)는 활동 없음. 클래식 프레임워크 두 저장소는 오픈 상태 유지: MXNet 15건, Caffe 3건, 합계 18건으로 모니터링 기간 내 모두 업데이트 없음(각각 최근 업데이트 09-24 / 09-28). 이번 모니터링 기간의 연산자와 컴파일 체인 활동은 triton-riscv의 패치 적응 병합(#86, 1.3 참조)에 집중되었다.

4. 커뮤니티와 활동 (격주 리포트, 포럼)

4.1 포럼 모니터링 기간 내 신규 게시글 없음; RuyiAI 섹션과 격주 리포트는 077회차 유지 (10-09 상태)

날짜: 2026-10-09(상태)　출처: RuyiSDK 개발자 커뮤니티, #2886, #2852

포럼 모니터링 기간 내 신규 주제와 신규 답글 없음; 최신 주제는 여전히 지난 기간의 #2886「스크립트로 ruyi 설치 및 업그레이드 실전 노트」(10-08 저녁)임. RuyiAI 섹션 최신 글은 여전히 09-30의 정보 게시물(#2876)임; RuyiSDK 격주 리포트 077호(09-24)가 여전히 최신이며, 078호는 아직 발표되지 않음. 국경절 연휴 이후 커뮤니티 활성도는 아직 회복기에 있음.

4.2 외부 뉴스와 arXiv 제로 히트; openRuyi 뉴스 페이지 신규 글 없음(10-09 상태)

날짜: 2026-10-09(상태)　출처: openRuyi 뉴스 페이지, arXiv, RuyiAI 공식 웹사이트

Google News에서 RuyiSDK, RuyiAI, openRuyi 및 루이 RISC-V에 대한 중영문 다중 쿼리 모니터링 기간 내 관련 히트 제로(유일한 「루이 RISC-V」 히트는 36Kr의 IPO 기사로 본 프로젝트와 무관하여 미수집; 채널 정상). arXiv(RISC-V 및 컴파일, 벡터, 추론 방향) 모니터링 기간 내 신규 수록 없음(최근 관련 항목 10-07). openRuyi 배포판 뉴스 페이지 신규 글 없음(2026.09 릴리스 공지가 여전히 최신); RuyiAI 공식 웹사이트와 블로그 신규 글 없음.

5. 트렌드 관찰

5.1 툴체인 동기화 폐루프: 업스트림 진화에서 패치와 채널까지

이번 모니터링 기간의 관찰 중점은 「업스트림 진화—로컬 패치—빌드 채널」의 폐루프 운영에 있음: LLVM 업스트림의 빠른 반복 속에서 riscv 브랜치는 야간 리플레이로 베이스라인 동기화를 유지; Triton 측은 #86 패치로 새 LLVM의 API 변경을 소화하여 Buddy MLIR v0.0.11의 의존성 업그레이드를 위한 장애물을 제거함. 후속 관찰 포인트: #84(Buddy v0.0.11)가 언제 메인 브랜치에 병합되어 야간 채널에 진입하는지; #85(커뮤니티 softmax / matmul 최적화)의 리뷰 진행 상황; 두 건의 FPGA 백엔드 PR(#25 / #28)의 새 베이스라인에서의 리뷰 결과.

5.2 패키징 확장의 연속 배치 리듬과 월간 버전 관찰 포인트

openRuyi는 10-08 하루 31건의 Go 생태 배치에 이어, 10-09에 13건의 Go 모듈 SPECS(franz-go, OpenTelemetry profiling, Jaeger IDL, 알리바바 클라우드 OpenAPI 등 포함)를 추가로 반영하여, 클라우드 네이티브와 옵저버빌리티 컴포넌트 의존성 체인을 지속적으로 보완하며 2026.09 릴리스 이후의 패키징 확장을 이어감. 관찰 포인트: 2026.10 월간 버전 주기가 시작될 때, 이 두 배치의 의존성이 빌드 베이스라인에 진입하는지.

5.3 정보 양 기간 푸시와 커뮤니티 회복기

ruyiai-daily는 매일 리듬에 따라 10-09 / 10-10 두 기간을 연속 푸시했으며, triton-riscv #86은 당일 병합, 당일 수록되어 정보와 연구개발 간의 연동이 효율적으로 유지됨; 상대적으로 커뮤니티 측(포럼, 격주 리포트)은 국경절 연휴 이후 아직 연휴 전 리듬으로 돌아오지 못함——포럼 모니터링 기간 내 신규 게시물 제로, 격주 리포트는 077호에 정지, 그 회복 진행 상황(078호와 정보 게시물 시리즈)이 다음 주 관찰 포인트임.
