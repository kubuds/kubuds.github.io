오늘의 중점: 매트릭스 확장 두 축 동시 진행——Ztt 초안 GCC 백엔드 하루 36건, LLVM riscv 스택 야간 재빌드 완료

날짜: 2026-10-08 ~ 2026-10-09　출처: riscv-gcc ztt-dev 커밋 목록, llvm-project riscv 커밋 목록, 헤드 커밋 44b1cf2, PR #25, PR #28

이 모니터링 기간 최대 단일 산출물은 riscv-gcc의 ztt-dev 브랜치에서 나타났다. 기여자 pz9115가 10-08 오전(08:40 ~ 11:27)에 36건의 Ztt 백엔드 커밋을 연속 푸시했다. Ztt는 RISC-V 행렬 확장 방향의 초안 명령어 집합으로, RuyiAI가 LLVM 측 BOSC AME / A100 라인 외에 GCC 툴체인에 구축한 배치다. 해당 배치의 내용은 하위부터 상위까지 아우른다. 0 추출(zero extraction)과 0 브로드캐스트의 구성 단순화(x0 재사용 및 데이터 타입 제거), 구조 접기(투영 / 재구성 / 역연산 / 연결 추출 / zip 및 unzip)와 witness 처리, Md(행렬 기술자 상태) 추적이 스칼라·행렬·행열·그룹 각 연산 클래스를 관통, 기술자 레지스터 재사용, 부동소수점 행열 intrinsics 신규 추가, 대형 ACC 기본 반올림 별칭 수정, 내장 함수 입력 속성 캐시, 미사용 작업 공간 정리, 그리고 M 값 시맨틱의 테스트와 문서화. 해당 브랜치가 09-30에 새로 열린 이래 가장 집중적인 배치다.

LLVM 측에서는 llvm-project의 riscv 브랜치(기본 브랜치)가 새 라운드의 야간 재빌드를 완료했다. 로컬 패치 스택 26건이 새로운 커미터 시간으로 전체 재적용되었고(10-08 심야), 10-09 00:51에 푸시가 완료되었다. 헤드는 44b1cf2 「[RISCV] Add A100 HP/SP and pack/unpack lowering with calibrated scheduling」(#31이며, 이전 라운드 재빌드의 헤드 패치와 동일한 정례적 재적용)이다. 스택 내 통합 커밋은 「[SyncBots] Integrate LLVM at b3b5e33」를 유지하며, 재적용 앵커는 10-08 당일 업스트림 스냅샷(업스트림 베이스라인에는 당일 [RISCV] 벡터 ISD 수정 #228215 등의 커밋이 포함됨)까지 전진했다. 재빌드 완료 후 두 건의 FPGA 백엔드 PR(#25 「BOSCAME FPGA 백엔드」, #28 「xboscame FPGA」)의 업데이트 시간이 곧바로 10-09 00:51로 갱신되어, 새로운 베이스라인에서의 리뷰 진행을 기다리고 있다. 또한 fork 내에는 10-08 18:38에 buckyball 브랜치(재빌드 이전의 구 헤드를 가리킴)가 새로 생성되었으며, 스택 내 Buckyball 벤더 확장(#20 / #23) 방향과 동일한 이름이다.

요점 정리: 행렬 확장이 LLVM(BOSC AME / A100)과 GCC(Ztt) 두 툴체인에서 같은 모니터링 기간에 병행 추진되고 있으며, 재빌드형 동기화, FPGA 측 리뷰 대기 PR 및 새 브랜치 배치가 다음 단계의 관찰 면을 구성한다.

날짜: 2026-10-08 ~ 2026-10-09　출처: riscv 커밋 목록, 헤드 커밋 44b1cf2, PR #25, PR #28

Harness 업스트림을 동기화하고 Triton-RISCV 플러그인 패키지를 이전했으며, agent 백엔드, 네이티브 라이프사이클 및 워크벤치 연동을 완료했습니다. 이 라인은 triton-riscv 저장소 내 기존 agent 시리즈 PR(#59 자율 연산자 에이전트, #72 컨트롤 플레인, #75 operator 도구, 작성자 ada-cl25)과 동일한 계보이며, 이번에 독립 저장소 형태로 자리 잡았습니다.

날짜: 2026-10-08　출처: ztt-dev 커밋 목록, 헤드 커밋 af51a350

ztt-dev 브랜치 10-08 오전 (08:40 ~ 11:27) 36건 연속 진행 (작성자 pz9115), Ztt 초안 확장을 중심으로 체계적 정밀 수정: 제로 값 경로 (x0 재사용, 데이터 타입 제거 재사용, 제로 브로드캐스트 단순화), 폴딩 최적화 (투영 / 재구성 / 역연산 / 연결 및 zip-unzip, 터미널 복사 증거), Md 행렬 디스크립터 상태 추적 (스칼라, 행렬, 행렬-열, 그룹 연산 및 생성자 전면 커버), 디스크립터 레지스터 재사용, 부동소수점 행렬 intrinsics, 대형 ACC 반올림 별칭 수정, M 값 의미론 테스트 및 문서 (내용 세부 사항은 오늘의 주요 사항 참조). 동일 조직의 나머지 툴체인 저장소는 조용: riscv-binutils의 ztt-dev와 riscv-gnu-toolchain의 ame-experimental 모두 모니터링 기간 내 커밋 없음 (각각 최신은 09-30); riscv-gcc의 나머지 브랜치 (16.1, p-rebase) 새 활동 없음.

Google News에서 RuyiSDK, RuyiAI, openRuyi 및 Ruyi RISC-V에 대한 중·영문 다중 쿼리 모니터링 기간 내 히트 제로 (채널 정상, 동일 기간 내 나머지 출처 모두 정상 반환). arXiv (RISC-V 및 컴파일, 벡터, 추론 방향) 모니터링 기간 내 신규 수록 없음 (최근 항목 10-07 커밋). openRuyi 배포판 뉴스 페이지 신규 글 없음 (2026.09 릴리스 공지가 여전히 최신); RuyiAI 공식 웹사이트와 블로그 신규 글 없음 (블로그는 여전히 Triton 적응과 PyTorch RISC-V CI 두 편).

5. 트렌드 관찰

5.1 매트릭스 확장의 듀얼 스택 리듬과 관찰 포인트

이번 모니터링 기간 두 툴체인 스택이 같은 날 실질적 진전을 보였다: GCC 측 Ztt 초안 백엔드 단일 일 36건 (규모는 해당 라인 최대), LLVM 측 패치 스택 일상적 리플레이로 전선 유지 (A100 HP/SP 패치 최상위). 관찰 포인트: Ztt 라인의 riscv-binutils 측 동기화와 업스트림화 경로 (binutils의 ztt-dev 이번 모니터링 기간 커밋 없음); FPGA 백엔드 두 건의 PR (#25, #28) 새 베이스라인에서의 리뷰 진행 상황.

5.2 야간 재빌드, 베이스라인 푸시와 PR 연동

llvm-project와 pytorch 두 포크의 「야간 재빌드 / 일일 베이스라인 푸시」 메커니즘이 이번 모니터링 기간 모두 정상 가동: 재빌드 완료 후 오픈 PR의 베이스라인 기록이 갱신됨 (llvm #25, #28; pytorch 8건). 이 메커니즘은 이미 RuyiAI 측 포크의 상시 운영 형태가 되었다 — 업스트림 동기화 지점 (SyncBots b3b5e33 라인)의 진행 효율, 그리고 재빌드 리듬과 PR 리뷰 차수의 협력을 관찰.

5.3 지능형 인프라와 커뮤니티 연산자 기여

harness가 독립 저장소로 Triton-RISCV agent 백엔드와 워크벤치를 담당; triton-riscv가 커뮤니티 기여의 softmax / matmul 최적화 PR (#85)을 받음. 두 라인은 공동으로 지향: RuyiAI 툴체인의 「agent화 / 자동화」 서사와 커뮤니티 참여도가 병행 상승 — agent 워크벤치와 연산자 기여의 후속 반복 리듬을 관찰.

5.4 openRuyi 생태계 확장과 월간 릴리스 리듬

openRuyi 단일 모니터링 기간 61건 (Go 생태계 31, Python 3.14 업그레이드 배치, AI 데이터 스택 17, ceph / moby / dotnet 등 수정), 2026.09 릴리스 이후 지속적 패키징 확장으로, 클라우드 네이티브와 AI / 데이터 과학 스택 두 생태계 라인이 동시에 두터워짐. 관찰 포인트: 다음 월간 릴리스 주기 개시 시, 이번 배치의 Python 3.14와 Go 의존성이 버전 빌드 베이스라인에 진입할지 여부.
