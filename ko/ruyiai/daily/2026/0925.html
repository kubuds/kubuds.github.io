오늘의 중점: ruyi 0.53.0 정식 릴리스, 크로스 소스 설치 상태 수정이 backport 형태로 반영

날짜: 2026-09-24　출처: Release 0.53.0, 버전 비교, PyPI

베이징 시간 09-24 14:57, ruyi 패키지 관리자가 0.53.0 정식 버전을 릴리스(GitHub Release 최신 표시, 사전 릴리스 아님); PyPI 채널의 0.53.0 패키지는 같은 날 14:56에 업로드, Release 페이지는 단일 파일 바이너리 배포판과 PyPI 설치 두 채널을 동시 제공. 이는 077호 격주 보고서가 예고한 “RuyiSDK 0.53, 2026년 9월 24일 릴리스”를 이행한 것.

릴리스 작업은 당일 오전에 집중적으로 완료되었다. v0.53.x 브랜치는 10:34에 먼저 backport 한 건을 남겼고(커밋 fd39afa3, fix(ruyipkg): recognize installations across repos, 09-23에 main에 병합된 크로스 소프트웨어 소스 설치 상태 수정을 릴리스 브랜치로 체리픽), 10:35에 버전 번호 커밋을 남겼으며(커밋 ceb2f961, build: bump self version to 0.53.0), 이후 tag를 달고, 패키지를 생성하고, 공지를 발표했다. GitHub 버전 비교 데이터에 따르면, 0.53.0은 이전 테스트 버전 0.53.0-beta.20260917 대비 이 두 건의 커밋만 추가되었다. 정식 버전의 테스트 기간 대비 증분은 바로 이 수정이다(변경은 ruyi/ruyipkg/state.py에 집중되어 46줄 추가, 8줄 삭제, 그리고 tests/ruyipkg/test_state.py에 116줄의 회귀 테스트 추가). 테스트 주기 내에 이미 병합된 바이너리 패키지 ABI 호환성 검사 인프라, 기본 소프트웨어 소스 우선순위 수정, 다운로드 실패 미러 폴백 수정 등의 업데이트는 테스트 버전과 함께 정식으로 전환되었다(전체 목록은 4.1 격주 리포트 참조).

나머지 상태: main 브랜치는 릴리스 후 09-23의 병합 상태를 유지하고 있으며, 아직 새로운 개발 커밋은 없다. 0.53.0이 전체 저장소의 최신 Release이며, 다음 버전은 2026년 10월 말로 예고되었다(자세한 내용은 4.1). 릴리스 폐쇄 루프 타임라인: #501 문제 보고(09-21) → 수정 main 병합(09-23) → backport 및 버전 태깅 릴리스(09-24), 전체 약 3일.

1. RuyiAI 스택 진행(PyTorch / Triton / TileLang RISC-V 적응)

기간 개요: RuyiAI-Stack 조직의 19개 저장소 중 기간 내 동작이 있는 것은 2개: triton-riscv(renovate 브랜치 푸시), ruyiai-stack.github.io(기여자 데이터); pytorch(riscv 브랜치 정적), tilelang-riscv, llvm-project, pytorch-ci, FBGEMM, cpuinfo, VecIntrinBench, IntrinTrans, harness, dsh-osc, torq-tile, skills, SyncBots-DeepAgents, mxnet, caffe 등은 기간 내 푸시가 없다. 또한 ruyisdk 조직 아래의 LLVM 툴체인 fork에 브랜치와 PR 동작이 있다(1.1 참조).

1.1 컴파일러 fork 이중 동작: llvm-project에 AME 및 riscv-ime-preview 브랜치 추가, XTHeadVector 혼합 폭 메모리 접근 수정 PR 개설(09-24)

날짜: 2026-09-24　출처: 브랜치 목록, PR #168, 이슈 #136

RuyiSDK 조직 아래의 LLVM 툴체인 fork는 기간 내에 두 개의 브랜치를 추가했다: AME(베이징 시간 11:38에 생성, 09-24의 LLVM 업스트림 스냅샷을 가리키며 최근 커밋은 모두 업스트림 변경)와 riscv-ime-preview(11:35에 생성, 8월 중순 업스트림 노드에 기반); 09-23에 생성된 ame0p6 브랜치(8월 초 업스트림 노드에 ameop5로 표기된 커스텀 커밋 한 건 포함, 작성자 Liao Chunyu)와 함께 행렬 확장 방향의 사전 연구 브랜치 라인을 구성한다. 기간 내 두 신규 브랜치 모두 PR이 첨부되지 않았으며, 구체적인 패치 내용은 후속 기간에 추적이 필요하다. 해당 저장소는 동시에 rebase-17.0.6, rebase-19.1.6 등 여러 툴체인 유지보수 브랜치를 보유하고 있다.

같은 날 오후 16:01, 메인테이너 imkiva는 rebase-17.0.6 브랜치를 기반으로 XTHeadVector 수정 PR #168을 개설했다(쉬안티에(XuanTie) 벡터 인덱스 메모리 접근 명령어 th.vlxe/th.vxse가 데이터와 인덱스 폭이 동일한 레지스터-메모리 페어링만 지원하는 문제 수정, 949줄 증분 변경, 6개 파일 커버), 이는 이슈 #136에 대응한다—해당 이슈는 2025년 2월 제기된 이후 장기간 열려 있었다. 수정 후 혼합 폭 인덱스 메모리 접근을 지원하며, 부호 오프셋, 메모리 요소 폭, 마스크 passthrough 및 제로 렝스 연산 시맨틱을 커버한다. 해당 PR은 현재 열린 상태이며, CI 검사가 아직 모두 완료되지 않았다.

1.2 triton-riscv: buddy-mlir 의존성 라인을 v0.0.11 nightly로 상향, 기능 PR 큐 심사 대기(09-24)

날짜: 2026-09-24　출처: PR #84, renovate 커밋 b392c40b

Triton의 RISC-V 백엔드 저장소는 모니터링 기간 내 renovate 봇이 의존성 브랜치에 커밋 한 건을 푸시했으며(베이징 시간 09:49), buddy-compiler/buddy-mlir 의존성 참조를 nightly/v0.0.9.dev20260911에서 nightly/v0.0.11.dev20260924로 업그레이드하고 대응하는 PR #84(오픈)를 생성했다. 이는 buddy-mlir 야간 빌드가 두 개의 마이너 버전만큼 스텝 진행된 데 따른 의존성 후속 조치다. 기능 라인 측면에서 저장소에는 여전히 6건의 변환 및 예제류 PR이 심사 대기 상태이며(텐서 채움값 마스크 로드, 배치 커널 포인터 선택, 루프 이월 gather 오프셋 유지, asin 프런트엔드 패치, FlagGems 연산자 마이그레이션, 중복 인덱스 scatter 테스트 수정), 최근 업데이트 시각은 09-17에 멈춰 있고 모니터링 기간 내 새로운 리뷰는 없었다.

1.3 PyTorch fork는 모니터링 기간 내 RISC-V 기능 커밋 없음: riscv 브랜치와 8개 오픈 PR 타임스탬프 유지(09-23 상태)

날짜: 2026-09-24　출처: riscv 브랜치 커밋, PR 목록

1.4 기술 정보 저장소는 모니터링 기간 내 새 호를 푸시하지 않았고, 사이트 기여자 데이터는 정례 업데이트(09-24)

날짜: 2026-09-24　출처: ruyiai-daily 커밋 기록, 사이트 데이터 커밋 6080eb58

기술 정보 저장소(ruyiai-daily)는 모니터링 기간 내 새 호를 푸시하지 않았다. 최신 호는 여전히 09-23 호(베이징 시간 09-23 아침 커밋)이며, 09-24 호는 모니터링 기간 종료까지 나타나지 않았다. 해당 저장소는 09-17부터 연속 매일 푸시를 유지해 왔으며, 이번 모니터링 기간이 첫 중단이다. 지연인지 중단인지는 후속 모니터링 기간에 확인이 필요하다. 사이트 저장소 측면에서는 베이징 시간 09-25 03:48에 자동 커밋 한 건이 있었으며, 기여자 데이터 파일(contributors.json)을 정례 업데이트했다.

모니터링 기간 개요: ruyisdk 조직의 46개 저장소 중 모니터링 기간 내 동작이 있었던 것은 6개다: ruyi(0.53.0 릴리스 및 릴리스 브랜치 동작), wechat-articles(077호 마무리 3건), ruyi-tuner(v1.x 한 건), ruyisdk-website(submodules PR), ruyi-backend(의존성 업그레이드), llvm-project(1.1 참조). support-matrix는 병합 없음(3건 심사 중), linux-xuantie-kernel, ruyisdk-vscode-extension, riscv-gcc, board-docs, packages-index, docs 등은 모니터링 기간 내 새 커밋 없음.

2.1 ruyi 릴리스 당일 마무리: 테스트 타임아웃 계산 조정 PR #503 생성 및 리뷰 획득(09-24)

날짜: 2026-09-24　출처: PR #503

베이징 시간 09-24 11:30, 커뮤니티 멤버 weilinfox가 ruyi 저장소에 PR #503 「tests(ruyi-pytest): calculate ruyi install timeout by pkg count」(1줄 추가, 1줄 삭제)를 생성했다. 패키지 관리자 pytest 스위트의 설치 타임아웃을 설치 패키지 수 기준으로 계산하도록 변경하여 고정 타임아웃을 대체하며, 패키지 수가 많을 때 테스트가 간헐적으로 타임아웃되는 문제를 줄인다. PR 생성 직후 리뷰 이벤트가 한 번 있었으며, 현재 병합 가능 상태(clean)다. 이는 0.53.0 릴리스 당일 테스트 라인의 마무리 소걸음이다.

5. 트렌드 관찰

#501 보고(09-21)부터 0.53.0 릴리스 아티팩트(09-24)까지 3일이 소요되었으며, “수정 사항 main에 병합, 릴리스 브랜치로 backport, 버전 번호 부여, 패키지 생성, 공지, 격주 보고서 설명”이 동일한 릴리스 주기 내에 모두 완료되었다; 정식 버전과 테스트 버전 사이는 단 두 개의 커밋 차이로, 릴리스 브랜치 규율이 명확하다. 관찰이 필요한 운영 세부 사항 하나: 모니터링 기간 말까지 공개 미러 사이트의 releases 디렉토리에 아직 0.53.0이 나타나지 않았다(0.52.0은 정상 다운로드 가능, testing 디렉토리는 여전히 0.53.0-beta). 아티팩트 동기화 진행 상황을 주목할 만하다. 향후 관찰 포인트로는 0.53.0의 실제 설치 피드백과 10월 말 다음 버전의 콘텐츠 계획도 포함된다.

5.2 컴파일러 측 이중 트랙 병행: 행렬 확장 사전 연구와 XTHeadVector 유지보수

이번 모니터링 기간에 RuyiSDK 툴체인 fork에서 동시에 두 개의 컴파일러 트랙이 나타났다: 미래 지향 행렬 확장 사전 연구 브랜치(AME, riscv-ime-preview, 09-23의 ame0p6 포함)와 Xuantie 벡터를 위한 기존 결함 수정(PR #168 혼합 폭 인덱스 메모리 접근, 문제가 1년 반에 걸쳐 존재). 이와 대조적으로 프레임워크 측 PyTorch fork는 계속 조용하다. 컴파일러 측 활발, 프레임워크 측 대기의 분화가 이미 일주일 이상 지속되고 있으며, AME 브랜치의 향후 지원 패치 및 PR 발생 여부를 관찰할 가치가 있다.
