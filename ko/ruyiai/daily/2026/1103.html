날짜: 2026-11-02　출처: 0.54.0-beta.20261102, PR #507 호스트 ABI 호환성 탐지, PR #496 ELF ABI 스캐너, packages-index 커밋

11-02 18:37(베이징 시간), ruyi가 0.54.0-beta.20261102를 릴리스했다. 태그 커밋은 15:16에 위치하며, PyPI에도 0.54.0b20261102가 동기화되어 나타났다. 정식 버전 채널은 여전히 09-24의 0.53.0이다. 이는 0.53.0 이후 39일 만의 첫 새 태그다. 직전 프리릴리스인 0.54.0-alpha.20260918은 0.53.0보다도 엿새 앞서 있었으니, 다시 말해 10월 내내 어떤 alpha나 beta도 나오지 않았다. 지난 호 데일리 리포트에 기록된 「10월 말 기준이 빗나갔다」는 여기서 후속이 나왔다. 취소된 것이 아니라 11월 첫 영업일까지 미뤄져서야 beta가 끊어진 것이다.

릴리스 노트에는 PR 열세 건이 나열되어 있지만, 비교 기준이 0.52.0-alpha.20260714로 적혀 있어서 08-24 이후 이미 0.53.0에 들어간 아홉 건이 그대로 다시 나열되었다. 실제로 0.53.0과 대조하면 순신규는 네 건뿐이다. #503 테스트 타임아웃을 패키지 수 기준으로 계산, #508 벤더 명명 문서, #507 호스트 ABI 호환성 탐지, #509 패키지 가져오기 오류 보고. 릴리스 페이지에서 독자가 보는 「열세 건 변경」과 실제 증분 사이에는 두 달 반의 차이가 있다. 이 점을 이번 호에서 먼저 짚어야 한다.

이 버전의 실제 내용은 #507에 집중되어 있다. ruyi admin check-abi 명령을 새로 추가하여 주어진 패키지에 대해 호스트 ABI 탐지와 호환성 판정을 수행한다. ruyi list는 호스트 호환성 비고를 표시하고, ruyi install은 비호환 시 경고를 낸다. 판정은 삼상태(호환, 비호환, 미판정)이며 관대한 것과 엄격한 것 두 가지 술어를 구분한다. RISC-V 측에서는 ld.so.cache의 부동소수점 ABI 필터링, 버전 번호가 붙은 단일 문자 확장 파싱, 스택 정렬 요구 사항, 그리고 약한 심볼 버전 누락을 실패로 보지 않는这类 경계까지 처리했다. 패치는 규모 +5760/−834, 64개 파일로 이번 버전에서 가장 큰 건이다.

구분해야 할 것은 계층이다. ABI 스캐너 #496은 이미 09-16에 머지되어 0.53.0과 함께 릴리스되었다. 이것은 디렉터리와 tar/zip/deb 아카이브를 스캔하여 결정론적인 .abi.toml 주석을 산출하고 rescan-package-abi를 제공한다. 0.54.0-beta에서 새로 추가된 것은 소비 측이다. 주석을 가지고 현재 호스트와 비교하여 「이 패키지가 이 머신에서 돌 수 있는가」에 답한다. 툴체인의 절반은 이번 호에 도달했고, 데이터의 절반은 이제 막 시작되었다. packages-index는 13:09부터 13:26까지 세 건을 잇달아 커밋하여 wlink, qemu-system-riscv-upstream, gnu-ruyisdk 세 패키지에 ABI 주석을 보충했으며, 총 열한 개 파일이고 그중 qemu는 amd64 두 개뿐이고 riscv64는 없다.

인덱스의 327개 패키지 버전 설명 파일과 대조하면, 세 패키지란 대다수 패키지가 check-abi 아래에서 「미판정」만 반환할 수 있음을 뜻한다. 이는 명령 자체의 사용 가능성에는 영향을 주지 않지만, 지금 이것이 일반 사용자의 패키지 설치 시의 보편적 보장이라기보다 패키저와 얼리 어답터를 위한 디버깅 도구에 더 가깝다는 것을 결정한다. 주석의 범위가 따라잡으려면 빌드 파이프라인이 패키지별로 다시 스캔해야 하며, 이는 0.54.0 정식 버전 전에 주시할 만한 라인이 될 것이다.

날짜: 2026-11-02(상태)　출처: pytorch riscv 브랜치, PR #51 riscv64 로컬 이미지, PR #44 bytes_to_scalar 수정

riscv 브랜치는 모니터링 기간 내에 새 커밋이 없다. 헤드 커밋은 b20942de이며, 커밋 시각은 11-02 03:00(작성자 시각 10-29 12:48)이고 메시지는 여전히 [SyncBots] Integrate PyTorch at 3afdbd3다. 브랜치의 스무 개 커밋은 커밋 시각이 같은 초로 일괄 재작성되어 있어 또 한 차례 전체 브랜치 재생에 해당하며, 베이스라인은 전진하지 않았다.

재생은 모니터링 기간 시작 전 약 한 시간 반에 일어났으므로, 이번 호에서는 상태만 기록한다. 패치 집합은 지난 호와 동일하며, 여전히 Add riscv64 image locally (#51), Fix bytes_to_scalar for float/complex on RISC-V (#44), Scope linear cross entropy ULP tolerance to RISC-V (#42), inductor opinfo blocklist (#50) 그리고 더 이른 CI와 허용 오차 변경이다. 브랜치가 07-22부터 누적한 이 RISC-V 전용 변경들은 3주 내에 이미 여러 차례 재생을 겪었고 새로운 업스트림 동기화는 없다.

main 브랜치는 모니터링 기간 내에 스무 개의 업스트림 커밋(AOTI, dynamo, DCP 등)이 있었으나 본 스택과 무관하여 기존 기준에 따라 집계하지 않는다.

11-02 23:00, riscv 브랜치가 다시 한 번 전체 리플레이를 수행했다: 스물여섯 건의 브랜치 자체 커밋의 커밋 시간이 23:00:22부터 23:00:26까지로 일괄 변경되었다. 헤드 커밋은 375bf3e4로 교체되었으며, 내용은 여전히 10-29의 [workflows] Push rebased PRs directly and document contribution options로, 새로운 변경 사항이 그 위에 얹히지는 않았다.

RuyiAI 스택과 가장 관련이 깊은 두 건은 여전히 제자리에 있다: [RISCV] Lower IME intrinsics to SpacemiT A100 dot instructions (#30)와 [RISCV] Add A100 HP/SP and pack/unpack lowering with calibrated scheduling (#31). 그 아래층에는 [AME] Update BOSC AME instructions (#29)와 [RISCV] Update xtame design (#27)이 있어 「AME 설계 문서 → 명령어 정의 → 내장 함수 → 하향 및 스케줄링」의 체인을 구성한다. 이번 모니터링 기간에 이 체인에는 신규 사항이 없으며, 리플레이는 커밋 시간만 변경할 뿐 내용은 바꾸지 않는다.

지난 호에 기록된 「동기화 봇 기록과 실제 업스트림 베이스라인의 괴리」는 이번 호에서도 여전히 해명되지 않았다: 브랜치 헤드 커밋의 작성자 시간은 09-29에 멈춰 있지만, 브랜치는 실제로 10-30의 업스트림 커밋을 이미 포함하고 있으며, 브랜치에는 새로운 [SyncBots] 기록이 없다.

1.3 triton-riscv: 메인 브랜치 커밋 없음, 나이틀리 빌드는 정상 배포, 리베이스 PR #92 모니터링 기간 내 갱신 (11-02 상태)

그중 Ruyi Firmware는 RuyiAI의 검증 환경과 직접 관련되므로 추가로 기록할 가치가 있다: 펌웨어는 coreboot, OpenSBI, EDK2를 기반으로 하며 빌드 및 플래싱 절차를 공개하고; MultiArchUefiPkg의 x64emu를 통합하여 RISC-V UEFI 환경에서 일부 x64 그래픽 카드 UEFI 구성 요소를 실행할 수 있게 했으며(AMD Radeon RX 6400에서 조합 테스트 완료), K3가 DMA32를 지원하지 않아 발생한 RX 550 oprom 문제를 해결하기 위해 AArch64 oprom 구성 요소로 전환했다; UEFI Setup에는 CPU mode 선택(X100 only, X100 + A100, A100 only)이 새로 추가되었으며, 그중 A100 only는 벡터 확장을 지원하여 1024-bit vlen 테스트 환경으로 사용할 수 있다. 릴리스 패키지는 20261013, 20261014, 20261015 세 가지 버전이며, 저장소는 10-13에 생성되었고 SpacemiT K3 Pico ITX에서 Wayland 데스크톱과 glmark2-wayland를 구동하는 데 성공했다.

3. 벡터 확장과 연산자 최적화(VecIntrinBench / IntrinTrans / FBGEMM)

3.1 세 벡터 저장소 계속 조용, 최신 커밋 각각 02-13, 06-25, 07-13에 정지

날짜: 2026-11-03(상태)　출처: VecIntrinBench, IntrinTrans, FBGEMM

정지 시점이 서로 다르다는 것은 통일된 프로젝트 종료가 아니라 각자 자연적으로 냉각되었음을 의미한다. VecIntrinBench가 가장 오래 멈춰 있는데, 이는 커버리지 판단에 직접 영향을 준다: 벡터 내장 함수 벤치마크가 장기간 갱신되지 않으면 측정되는 집합과 컴파일러가 실제로 지원하는 집합의 격차가 점점 벌어지게 되며, LLVM 측의 A100/AME 강등 체인은 바로 계속 확장되고 있다(1.2 참조).

3.2 연산자 작업면은 여전히 triton-riscv 대기열: 16건 오픈, 정보 보존 계열 5건 미병합(11-02 상태)

날짜: 2026-11-02(상태)　출처: PR #93 스칼라 메모리 접근 마스크, PR #95 텐서 gather 강등, PR #85 softmax 및 matmul 최적화, 오픈 PR 목록

이들과 병행하는 두 가지 범주가 더 있다: 하나는 #92의 전체 리베이스(1.3 참조)이고, 다른 하나는 #85의 softmax 및 matmul 최적화——후자는 10-18 이후 갱신이 없으며 대기열에서 성능을 직접 겨냥한 유일한 항목이다. 셋은 서로 의존하지 않으면서도 서로 양보하지 않아, 메인 브랜치는 10-31 이후 새로운 연산자 능력이 반영되지 않고 있다.

6. 동향 관찰

6.1 공백이 베타로 마무리, 0.54.0의 플래그십 항목은 「이 기계에서 돌아가는가」

0.54.0은 09-18의 알파에서 11-02의 베타까지 45일이 걸렸고, 0.53.0 정식 버전에서 베타까지는 39일이 걸렸다. 이 기간 동안 ruyi 메인 브랜치에 코드가 없었던 것은 아니다. ABI 시리즈 커밋이 10-30과 11-02에 두 차례로 나뉘어 반영됐다. 다만 릴리스 채널은 11월 첫 영업일이 되어서야 다시 가동됐다.

다시 가동될 때 선택한 내용은 명확하다. 호스트 ABI 호환성이다. 이는 「신기능」식의 판매 포인트가 아니라 「설치하면 돌아가는가」를 경험적 판단에서 조회 가능한 항목으로 바꾸는 것이다. 여러 벤더의 보드와 툴체인을 대상으로 하는 패키지 관리자에게 이 방향의 우선순위는 패키지를 몇 개 더 추가하는 것보다 높다.

6.2 릴리스 노트의 기준 오류, 두 달 반 치의 옛 기록을 다시 나열하다

열세 건 대 네 건은 이번 호에서 가장 오독하기 쉬운 부분이다. 릴리스 노트의 비교 기준이 0.53.0이 아니라 0.52.0-alpha.20260714에 멈춰 있다. 그 결과 08-24의 「RuyiSDK Certified」 벤더 표시, 09-16의 ABI 스캐너, 09-23의 교차 저장소 설치 상태 수정이 모두 0.54.0-beta의 변경 목록에 다시 등장했다.

다운스트림에 대한 의미는 다음과 같다. 이 목록으로 「0.53.0에서 0.54.0으로 무엇이 바뀌었는가」를 판단할 수 없으며, 직접 비교 인터페이스를 실행해야 한다. 프로젝트가 릴리스 절차에 「기준 태그는 직전 정식 버전으로 지정」하는 단계를 추가하는 것은 어렵지 않지만, 독자의 신뢰 비용에는 적지 않은 영향을 준다.

6.3 데이터 측이 도구 측에 뒤처져, ABI 검사는 대부분 「미판정」만 회신 가능

도구는 이미 삼상 판정, 설치 경고, check-abi 디버그 명령을 모두 갖췄으나, 데이터 측에는 패키지 세 개, 주석 열한 건뿐으로 327개 패키지 버전 설명 파일의 1퍼센트에도 미치지 못한다. qemu-system-riscv-upstream은 심지어 amd64 주석만 있다.

이는 현 단계에서 사용자가 실제로 체감할 수 있는 것이 「일부 패키지가 호환성을 표시한다」이지 「설치 전에 모두 확인할 수 있다」가 아님을 의미한다. 이 체인을 보편적 역량으로 보완하려면 빌드 파이프라인이 패키지별로 재스캔하고 다시 채워 넣어야 한다. 이는 패키지 단위로 계산되는 작업량이며 릴리스에 따라 자동으로 완료되지 않는다. 다음 호에서는 packages-index의 주석 수가 계속 증가하는지를 이 라인이 실제로 가동됐는지의 판단 기준으로 삼을 수 있다.

6.4 open루이의 결산과 결판 부재 병존, 병목은 개발이 아닌 릴리스

11-02 하루에 일곱 건이 병합됐으며 그중 다섯 건은 8월부터 10월 초까지의 오래된 PR이다. 같은 날 네 건의 직접 커밋도 있었다. 개발 측의 움직임은 부족하지 않으나 2026.10 월간 버전은 아직 릴리스되지 않아 뉴스 페이지는 10월 특집 두 편으로만 내용을 유지하고 있다.

이는 ruyi 측 상황과 함께 읽으면 동일한 판단을 가리킨다. RuyiSDK 생태계의 두 배포 파이프라인(패키지 관리자와 배포판)이 10월 모두 「코드는 가는데 릴리스는 가지 않는」 상태에 놓였다. 0.54.0-beta가 패키지 관리자 라인을 다시 끌어올렸으니, 배포판 라인은 2026.10을 기다리거나 곧바로 2026.11로 건너뛰어야 하며, 그때에야 절차 지연인지 리듬 조정인지를 판단할 수 있다.
