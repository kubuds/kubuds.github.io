오늘의 중점: K3 펌웨어 3기 “Ruyi Firmware 20261015” 릴리스——시스템 정보 페이지와 UEFI 드라이버 시뮬레이션 (x64/ARM64) 적용, AMD ARM64 GOP 1.68 파일럿

날짜: 2026-10-15　출처: Ruyi Firmware 20261015 릴리스, edk2-ruyi: 시스템 정보 페이지 커밋 a8ea1ac6, edk2-ruyi: SPI 에뮬레이션 스위치 커밋 5581e304, edk2-ruyi: ARM64 GOP 1.68 커밋 c13cf98c, coreboot: A100-only 인터럽트 수정 7b1ac324, ruyifirmware: raw SPI 플래싱 문서 6aece1c0

openRuyi 펌웨어 패키징 저장소 ruyifirmware는 10-15에 세 번째 펌웨어 “Ruyi Firmware 20261015”를 릴리스했으며(앞선 두 기간은 10-13, 10-14), 이번 모니터링 기간을 완전히 포함한다. 이번 릴리스의 두 가지 주요 흐름: 첫째는 시각화와 정보 측면으로, UEFI 설정에 읽기 전용 “System Information” 페이지가 새로 추가되어 CPU, 메모리, PCIe 디바이스와 링크 속도, 저장장치 상세 정보를 포함한다. SMBIOS는 DRAM 타입, 부품 번호, 구성 속도를 동기 보고한다. PCI 그래픽 카드를 사전 초기화하고 Setup 진입 시 그래픽 콘솔 재진입 문제를 수정했다. IMG GPU 코어 주파수는 1228.8 MHz로 고정되었다. 둘째는 UEFI 드라이버 에뮬레이션으로, x64와 ARM64 드라이버 에뮬레이션이 동시에 DEBUG와 RELEASE 패키지에 포함되었다(기본 비활성화). CPU 모드와 에뮬레이션 스위치는 Platform Settings에 통합되었고, 선택 사항은 SPI 전용 섹터에 저장되며(CRC와 읽기 검증 포함), 재부팅 후 적용된다. 또한 초기 GCN, Polaris, Vega M 그래픽 카드를 위해 실험적 AMD ARM64 GOP 1.68을 연결했다(나머지 디바이스는 여전히 온보드 x64 GOP를 사용하며, 교체 실패 시 폴백하지 않음). 수정 측면: A100-only 모드 인터럽트 매핑(coreboot 동일 소스 수정: S 모드 인터럽트 테이블을 A100 hart로 제한하고 IMSIC/SSWI 레지스터 윈도를 시프트). 최초 설치 문서는 raw SPI 플래싱으로 변경되었다.

이번 릴리스는 K3 펌웨어 스택의 여러 저장소가 10-15에 협력하여 완료했다: edk2-ruyi 6건(시스템 정보 페이지, DRAM SMBIOS, 그래픽 콘솔 재연결, Platform Settings 그룹화, ARM64 GOP, SPI 에뮬레이션 스위치), coreboot k3/port 2건(인터럽트 라우팅 수정, DRAM 구성 payload 전달), ruyifirmware 빌드 8건, MultiArchUefiPkg 브랜치 2건(AArch64 게스트 지원 Makefile 진입, 플랫폼 정책 스위치).

날짜: 2026-10-15　출처: V Questions with… DAMO Academy’s Dr. Jianyi Meng (RISC-V International)

RISC-V 인터내셔널 공식 블로그에 DAMO Academy XuanTie 수석 과학자 Meng Jianyi와의 인터뷰가 게재되었다: XuanTie 팀은 자사 RISC-V 프로세서 C950의 64코어 목표 구성에서 Qwen3.8-27B 대규모 모델을 로컬로 실행했으며, 처리량이 30 tokens/s를 초과했다(약 20~22 단어/초). 또한 독립 GPU나 NPU 가속에 의존하지 않았다; 이 처리량을 달성하려면 약 400 GB/s급 메모리 데이터 이동이 필요하며, C950은 고대역폭 메모리와 실리콘에서 이미 검증된 자체 개발 행렬 확장을 결합하여 이를 구현했다. 팀은 이후 Qualcomm, IBM, VRULL, ISCAS, BOSC 등의 멤버와 함께 RISC-V 인터내셔널에서 AME(Attached Matrix Extension) 태스크 그룹을 발족하여 표준화를 추진했다. 인터뷰 요점: 양자화, 행렬 명령어, 온칩 스토리지, 대역폭 및 kernel 수준 최적화는 전체적으로 공동 설계되어야 한다; prefill은 주로 밀집 행렬 연산이 중심이고, decode는 메모리 대역폭 병목으로 전환된다; 독립 행렬 레지스터(INT4 / INT8에서 INT32, FP4 / FP8 / FP16 / BF16에서 FP32 혼합 정밀도 누산)를 사용하여 RVV 레지스터와의 경쟁을 피한다; 규격은 아직 데이터 레이아웃, 누산기, 반올림과 포화, 컨텍스트 저장 및 복원, 예외와 가상화, 컴파일러와 ABI 매핑을 포괄해야 한다. Meng Jianyi는 현재 RISC-V China Summit 부의장이며, 해당 서밋은 10-18 선전에서 개막한다; 그의 전망은 데이터센터 생태계, 완전한 소프트웨어 체인 및 아키텍처 혁신에 초점을 맞추고 있다.

5. 트렌드 관찰

5.1 K3 펌웨어 「구성 가능 + 시뮬레이션 가능」 병행 추진: 드라이버 시뮬레이션 활성화 전략과 주변기기 호환성 관찰

K3 펌웨어가 세 번째 릴리스 일에 진입, 기능면이 「CPU 모드 선택 가능」에서 「UEFI 드라이버 시뮬레이션 가능」으로 확장: x64와 ARM64 시뮬레이션은 기본 비활성화, Platform Settings를 통해 활성화 및 지속화, AMD ARM64 GOP 1.68은 실험 명목으로 초기 GCN / Polaris / Vega M 그래픽카드 시범 적용, 교체 실패 시 롤백하지 않는 설정은 이 경로가 보수적 호환 경로임을 의미. 관찰 포인트: 첫째, 시뮬레이션 계층이 실제 혼합 부하에서의 안정성과 성능 비용; 둘째, 시뮬레이션 가능 드라이버와 장치 목록의 확장 속도(그래픽카드 외에 네트워크 카드, 저장장치 등 포함 여부); 셋째, openRuyi 이미지, 커널 ruyi/7.3.y 디스플레이 패치(DP 및 GPU 전원 도메인)와의 협력 전달 방식.

5.2 두 fork 유지보수 라인 리듬 차이: PyTorch 재빌드 일일 단위 지속, LLVM 리플레이 세 번째 모니터링 기간 미재개

PyTorch riscv 브랜치는 약 24시간마다 재빌드 유지(이번 라운드 23건, 8건 PR 동기 갱신; 이전 라운드 헤드 대비 총 101건 차이에 업스트림 병합 포함), 자동화 리듬 안정적; LLVM riscv 브랜치는 10-12 이후 연속 세 번째 모니터링 기간 동안 야간 리플레이 미확인, 두 fork의 유지보수 리듬에 뚜렷한 분기 발생. 관찰 포인트: LLVM 리플레이의 복귀 여부, 그리고 ruyisdk 측 llvm-project 유지보수 라인(XTHeadVector 관련 작업)과의 분업에 변화가 있는지.

5.3 커널과 배포판 유지보수면 확장: ruyi/7.3.y 개시, 보안 배치 및 XuanTie 키 이름 통일

커널 트리에서 openRuyi linux가 ruyi/7.3.y를 새로 개시하고 모니터링 기간 내 31건 커밋(K3 주변기기, 디스플레이 및 SG2044 마이그레이션 리플레이 중심), 7.2.y와 병행 유지보수 형성; linux-xuantie-kernel은 벤더 확장 키를 XUANTIE 형태로 통일 — 네이밍과 브랜드 측면의 수렴은 hwprobe와 툴체인 측의 일관된 참조에 유리. 배포판 측면에서 openRuyi는 같은 날 5개 보안 패키지(cups / nltk / capstone / llama-cpp / multipath-tools) 커밋, CVE 대응이 배치화 경향. 관찰 포인트: 7.3.y가 언제 이미지 릴리스 채널에 진입하는지, 보안 배치의 릴리스 빈도가 안정적인지.
