오늘의 중점: ruyi, 소프트웨어 소스 간 설치 상태 문제 수정, RuyiSDK 0.53 금일 릴리스 예정

날짜: 2026-09-23　출처: 수정 PR #502, 이슈 #501

베이징 시간 09-23 09:01, ruyi 패키지 매니저가 「Fix installation state managemet across repos」를 main 브랜치에 병합했다 (병합 커밋 802dd4d9; 수정 커밋 08fd6aeb, 메인테이너 xen0n 개발). 이는 커뮤니티 사용자 qingwan12138이 09-21에 보고한 #501 이슈를 닫았다: 소프트웨어 소스를 전환한 후 이미 설치된 패키지가 「미설치」로 표시되고, 재설치가 건너뛰어지며, 상태가 영원히 업데이트되지 않는 문제였다.

문제 메커니즘: 설치 기록은 「출처 소프트웨어 소스 ID」를 키로 삼지만, 설치 중복 판정은 「이름 + 버전」만으로 이루어진다. 동일 이름·동일 버전 패키지가 여러 소프트웨어 소스에 존재할 때, 사용자가 소스 A에서 설치한 후 소스 B로 전환하면 ruyi list가 새 소스 ID로 조회하기 때문에 「미설치」로 표시되고; 이때 재설치는 「이미 설치됨 건너뛰기」로 단락(종료 코드 0)되지만 새 소스 기록을 쓰지 않으며; 제거는 「설치 추적으로 등록되지 않음」을 보고한다. 최종적으로 「파일은 디스크에 있고 상태는 영원히 미설치」인 교착이 형성되어, --reinstall이나 먼저 제거하는 방법으로만 복구할 수 있다. 수정은 설치 상태 조회를 설치 신원(카테고리, 이름, 버전, 호스트) 기준 소스 간 매칭으로 변경하고, 동일 신원일 때 정확한 소스 ID 기록을 우선하며, 제거가 모든 소프트웨어의 동일 신원 기록을 포괄하도록 하고, 겸사겸사 구버전 --reinstall이 남긴 중복 기록도 정리한다; 총 162줄을 변경했으며 그중 117줄이 새 회귀 테스트(state.py와 test_state.py 두 파일)이다.

이 수정 사항은 같은 날 완료된 제077호 격주 보고서 초안에 반영되었다(4.1 참조): 초안의 ‘패키지 관리자’ 장에는 ‘RuyiSDK 0.53이 2026년 9월 24일에 릴리스될 예정이며, 대응하는 패키지 관리자 버전도 0.53.0이다’라고 명시되어 있으며, 바이너리 패키지 ABI 호환성 검사 인프라, 기본 소프트웨어 소스 우선순위 수정, 다운로드 실패 미러 폴백 수정 등 동일 배치의 업데이트를 나열하고 있다. 모니터링 기간 말(09-24 04:30) 기준, 릴리스된 Release는 여전히 0.54.0-alpha.20260918이 최신이며 v0.53.x 브랜치는 0.53.0-beta.20260917에 머물러 있어, 정식 버전 번호 부여와 릴리스 공지는 오늘의 최우선 관찰 포인트다.

1. RuyiAI 스택 진행 상황 (PyTorch / Triton / TileLang RISC-V 적응)

기간 개요: RuyiAI-Stack 조직의 19개 저장소 중 기간 내 동작이 있는 것은 5개다: pytorch(main 업스트림 동기화), ruyiai-daily, ruyiai-stack.github.io, mxnet과 caffe(신규 생성); triton-riscv, tilelang-riscv, llvm-project, pytorch-ci, FBGEMM, cpuinfo, VecIntrinBench, IntrinTrans, harness, dsh-osc, torq-tile 등은 기간 내 푸시가 없었다.

1.1 PyTorch fork 기간 내 RISC-V 기능 커밋 없음: riscv 브랜치 침묵, 8개 오픈 PR 업데이트 없음 (09-23 상태)

날짜: 2026-09-23　출처: riscv 브랜치 커밋, PR 목록

해당 fork의 riscv 브랜치는 기간 내 신규 커밋이 없다: 브랜치 헤드는 여전히 4f173e3e 일괄(bytes_to_scalar 수정, inductor 테스트 블록 명단, 선형 교차 엔트로피 ULP 허용 오차, SyncBots 통합 등, 타임스탬프는 09-20 저녁에 멈춤); 8개의 오픈 병합 요청(#23, #35, #36, #38, #43, #46, #48, #51)의 타임스탬프는 09-21로 변동 없이 유지되며, 기간 내 신규 병합도 신규 오픈 PR도 없다. RVV 방향의 두 대기 패치(#46 ATen RVV 지원, #48 RVV CPU capability)는 계속 미병합 상태로 남아 대기 시간이 계속 누적되고 있다.

main 브랜치는 기간 내 20회 업스트림 동기화 커밋이 있었으며, 내용은 일반적 의제(FakeTensor 관련 롤백, MTIA SDPA 테스트 임계값, CUTLASS 테스트, MPS histc, ROCm 테스트 재사용, xpu Triton 고정 등)로, riscv, rvv, vector, XuanTie, rv64, rv32 등의 키워드로 항목별 필터링한 결과 RISC-V 관련 내용이 없어 이번 호에서는 다루지 않는다.

날짜: 2026-09-23　출처: triton-riscv, tilelang-riscv, llvm-project

1.3 기술 정보 저장소 09-23 호 푸시, 사이트 기여자 데이터 자동 업데이트 (09-23 ~ 09-24)

기술 정보 저장소가 모니터링 기간 내에 한 번의 커밋을 완료했습니다(베이징 시간 09-23 06:20). 내용은 09-23 호이며, 자체 설명 롤링 윈도우는 09-22 06:00부터 09-23 05:00까지입니다. 해당 호의 RISC-V 섹션에 수록된 항목: XuanTie Hypervisor 테스트 스위트 리팩터링(PR #33, 테스트의 주소 변환 모드가 플랫폼/스위트 설정에 의해 구동되도록 변경), XiangShan 벡터 부동소수점 경로 연결(PR #6615, kunminghu-v3 브랜치에서 벡터와 부동소수점 영역 간의 레지스터 읽기/쓰기, 웨이크업 및 바이패스 데이터 경로 보완), LLVM “소프트웨어 인터프리트 실행” RISC-V 타깃 RFC(인터프리터 비용 모델 논의), 그 외에 Buildroot 외부 트리에 SyterKit 부팅 빌드를 포함시키는 등의 항목이 있습니다. 위 항목들의 원래 시각은 대부분 모니터링 기간 이전이므로, 중복 제외 원칙에 따라 이번 호에서는 더 이상 다루지 않고 릴리스 동작만 기록합니다. 사이트 저장소는 모니터링 기간 내에 또 한 번의 자동 커밋이 있었습니다(베이징 시간 09-24 03:26). 기여자 데이터 파일을 정기적으로 업데이트합니다.

1.4 RuyiAI-Stack 조직에 mxnet과 caffe 두 저장소 추가(09-23)

날짜: 2026-09-23　출처: RuyiAI-Stack/mxnet, RuyiAI-Stack/caffe

조직은 베이징 시간 09-23 오전(09:32와 09:38 전후)에 두 개의 저장소를 연달아 새로 생성했습니다: mxnet과 caffe이며, 공개 저장소 총수가 19개로 늘었습니다. 두 저장소 모두 GitHub fork 링크가 아니며 완전한 업스트림 이력을 갖추고 있습니다. mxnet은 43개의 브랜치(master, v1.x, v2.0.0.alpha 등)를 포함하며 최신 커밋은 2023-01에 멈춰 있습니다. caffe는 7개의 브랜치를 포함하며 최신 커밋은 2020-02에 멈춰 있습니다. 모니터링 기간 내 두 저장소 모두 새 커밋이 없습니다. 조직이 기존에 보유한 pytorch fork와 결합하면, RuyiAI-Stack은 “네이티브 + 적응” 노선 아래에서 클래식 딥러닝 프레임워크 커버리지가 넓어졌습니다. 두 저장소의 구체적 용도(아카이브, 적응 기준선 또는 새 작업의 출발점)는 이후 모니터링 기간에 추적이 필요합니다.

2. RuyiSDK 툴체인과 배포판(커널, 지원 매트릭스, IDE, openRuyi)

2.1 XuanTie 커널 작업 트리에 두 건 병합: perf annotate 아키텍처 이름 매칭과 compat UTS 정의 수정(09-23)

날짜: 2026-09-23　출처: 커밋 94494ca6, 커밋 5eed2594

베이징 시간 09-23 13:16, ruyisdk 조직의 XuanTie 커널 작업 트리(linux-xuantie-kernel, linux-6.6.36 브랜치)에 두 건의 수정이 연달아 병합되었습니다. 첫째 “perf annotate: Match the normalized riscv architecture name”(작성자 cp0613) — perf annotate의 RISC-V 아키텍처 이름 매칭을 정규화된 이름 기준에 맞추어, 툴체인에서 아키텍처 이름 정규화와 매칭이 일치하지 않는 문제를 수정했습니다. 둘째 “riscv: compat: fix COMPAT_UTS_MACHINE definition”(작성자 RevySR) — compat 계층의 COMPAT_UTS_MACHINE 매크로 정의를 수정한 것으로, 32비트 호환 프로세스의 UTS 머신 이름 필드 값과 관련됩니다. 이 작업 트리의 이전 최근 병합은 09-20의 T-Head PMA 메모리 타입 정정 패치였으며, 이번 호의 두 건은 연속적인 소규모 유지보수에 해당합니다.

2.2 지원 매트릭스에 네 건 집중 반영: Milk-V Duo S 세 건의 리포트와 K510 업데이트, 그 외 세 개 PR 심사 중(09-23)

날짜: 2026-09-23　출처: PR #407, PR #396, PR #395, PR #392

벡터 내장 함수 벤치마크, 내장 함수 트랜슬레이션과 저정밀도 연산자 라이브러리를 대상으로 한 세 저장소 모두 모니터링 기간 내 커밋이 없었다: VecIntrinBench의 마지막 커밋은 02-13(최신 푸시 기록 06-24), IntrinTrans는 06-25, FBGEMM fork는 07-13이며, 같은 그룹의 관찰 대상인 cpuinfo(05-20), torq-tile(04-09)도 마찬가지로 조용했다. 이 방향의 가장 최근 재현 가능한 결과는 여전히 09-17에 수록된 ONNX Runtime MLAS RVV 커널 최적화(K3/X100에서 ResNet50 3.01배 속도 향상)이며, 벡터 최적화와 관련된 도구 측 진전은 4.1 위클리 리포트 초안의 LLVM, Go, V8 각 절 항목을 참조할 수 있다.

4. 커뮤니티와 활동(위클리 리포트, 포럼)

4.1 위클리 리포트 077호 다섯 개 장 통합 완료, 발행일은 오늘(09-23)

날짜: 2026-09-23　출처: 커밋 #359, 커밋 #364, 077호 초안

제 077호 위클리 리포트는 모니터링 기간 내에 다섯 건의 장 단위 커밋을 완료했다(파일 20260924-ruyisdk-biweekly-77.md): ruyipkg(#359, 09:17, 0.53 업데이트 설명과 packages-index 리소스 업데이트 포함), GCC(#360, 11:36), Go(#361, 12:24), OpenJDK(#363, 15:22), 기본 C 라이브러리(#364, 16:24). 내용 측면에서: 기본 C 라이브러리 절에는 glibc가 pow를 libmvec 프레임워크로 이식한 것, newlib가 rsqrt와 expm1의 벡터 수학 구현을 이식한 것을 보충했다; OpenJDK 절에는 이번 기간에 검토하고 병합한 11개의 JDK 메인라인 PR(RISC-V string_indexof_char 경계 초과 수정, G1 배리어 최적화, 벡터 정수 나눗셈, Zcb 확장 기본 활성화 등 포함)과 JEP 544 AOT 정적 컴파일의 RISC-V 이식 진전을 나열했다; Go 절에는 chacha20의 RVV 최적화 재측정과 image 라이브러리 RVV SIMD 제안을 기록했다; GCC 절은 Spacemit 벤더 확장 backport 등을 다뤘다. 077호는 계획대로 오늘(09-24) 발행되며, 모니터링 기간 말까지 여전히 초안 통합 상태에 있었다(포럼의 최신 발행 호는 여전히 076).

4.2 포럼에 09-23 오픈소스 기술 핫뉴스 정보 게시글 신규 추가(09-23)

날짜: 2026-09-23　출처: 커뮤니티 게시글 2850

포럼 모니터링 기간 내에 하나의 주제가 신규 추가되었다: 베이징 시간 09-23 11:30, 커뮤니티 멤버 Yaya-tan001이 RuyiAI 섹션에 「2026-09-23 오픈소스 기술 핫뉴스 정보」(제 2850호 주제)를 게시했으며, 내용은 일일 오픈소스 정보 요약으로, 이번 호는 LLVM LLD의 Massive Binaries 워킹 그룹 설치 예정, Triton의 FP4에서 FP32로의 업캐스트 지원, Spike의 mip.SEIP 읽기/쓰기 시맨틱 결함 수정, 그리고 PyTorch 생태계와 AI 업계 항목을 다뤘다. 해당 게시글에는 댓글 토론이 없었다; 이번 모니터링 기간에 포럼에는 다른 신규 주제도, 새로운 위클리 진전 게시글도 없었다. 윈치 콘퍼런스 Ruyi 커뮤니티 부스는 오늘(09-24) 전시 기간 마지막 날을 맞았다.

5. 트렌드 관찰

5.1 릴리스 주간 리듬: 즉시 폐쇄 루프 수정과 0.53 릴리스 및 위클리 리포트 077의 중첩

문제 제기부터 병합까지 약 36시간(#501은 09-21 20:48에 보고, 09-23 09:01에 수정 병합)이 걸렸으며, 메인테이너는 병합 후 약 15분 이내에 수정 사항을 위클리 리포트의 0.53 업데이트 설명에 반영했다 — 「보고, 수정, 릴리스물」이 동일한 릴리스 주기 내에서 폐쇄 루프를 완성한 것은 커뮤니티 대응 리듬의 직관적인 표본이다. 다음 24시간 동안 확인할 만한 관찰 지점: v0.53.x 브랜치의 공식 태깅과 0.53.0 릴리스 공지가 예정대로 나타나는지; 0.53.0의 실제 업데이트 목록에 해당 수정이 backport 형태로 반영되는지(현재 v0.53.x 브랜치는 여전히 0.53.0-beta.20260917에 머물러 있다).

5.2 지원 매트릭스의 「단일 보드 다중 시스템」 모드와 심사 대기열

Milk-V Duo S는 사흘 만에 Arch Linux, Ubuntu에서 Debian, RT-Thread, xv6로 확장되었고, 심사 중인 Zephyr와 RT-Thread Smart까지 더해져 단일 저비용 보드의 운영체제 커버리지가 체계적으로 펼쳐지고 있다; 같은 기간 K510, CH32V307, ESP32C3 등 엣지 및 MCU급 칩의 보고도 계속 갱신되고 있다. 사용자 입장에서는 「먼저 매트릭스를 확인하고 보드를 선택」할 수 있는 재현 가능한 자료의 밀도가 높아지고 있다; 커뮤니티 입장에서는 이런 보고가 대부분 신규 기여자의 입문 경로이므로, 심사 대기열의 길이가 일일 병합 수보다 기여 활성도를 더 잘 반영한다.

5.3 프레임워크 커버리지의 폭 확장과 PyTorch 측 깊이 대기

RuyiAI-Stack에 mxnet과 caffe가 새로 저장소에 등록되었으며(1.4 참조), 기존 pytorch fork와 함께 세 개의 고전 딥러닝 프레임워크가 병치되었다. 그러나 PyTorch fork의 RISC-V 기능 라인은 지속적으로 조용한 상태이다(riscv 브랜치에 새 커밋 없음, 8개의 오픈 PR 타임스탬프 변동 없음, RVV 두 건의 커널 지원 패치 계속 대기 중). 범위 확장과 심도 있는 추진이 분화되는 양상이며, 「넓고 얕은」 단계적 상태는 mxnet, caffe 두 저장소의 첫 번째 움직임으로 다음 방향을 검증할 수 있다.

5.4 이번 모니터링 기간의 공백과 관심 사항

사실대로 기록해야 할 공백: PyTorch riscv 브랜치와 오픈 PR 이중 침묵; triton-riscv, tilelang-riscv, 벡터 연산자 세 가지 전용 목표 저장소 모두 침묵; ruyi-tuner, riscv-gcc, board-docs, packages-index 커밋과 릴리스 없음; 뉴스 측에서 RuyiAI, RuyiSDK, 루이 커뮤니티, openRuyi에 대한 Google News 중영문 다중 쿼리 연속 제로 히트, arXiv 모니터링 기간 내 신규 수록 없음. 관심 사항: 첫째, RuyiSDK 0.53과 ruyi 0.53.0의 정식 릴리스 및 v0.53.x 버전 넘버링; 둘째, 격주 리포트 077 정식판 내용; 셋째, 윈치 콘퍼런스(09-24까지) 폐막 동향; 넷째, mxnet, caffe 두 저장소의 후속 움직임; 다섯째, openRuyi 2026.09 월간 버전 공지.
