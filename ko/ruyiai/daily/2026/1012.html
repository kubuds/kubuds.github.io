오늘의 중점: 행렬 확장과 스택 동기화 삼선 병진——Ztt 단일 배치 51건, PyTorch riscv 전체 스택 재구축 (23건), triton-riscv #84 의존성 업그레이드 머지

날짜: 2026-10-10 ~ 2026-10-11　출처: riscv-gcc ztt-dev 커밋 목록, 헤드 커밋 a326bc3, pytorch riscv 브랜치 커밋 목록, 헤드 커밋 0fc3546d, triton-riscv PR #84

GCC 백엔드 라인의 행렬 확장 방향이 이번 주에 한 걸음 더 나아갔다: 기여자 pz9115가 10-11 오후(13:50)에 riscv-gcc의 ztt-dev 브랜치에 Ztt 커밋 51건을 단일 배치로 푸시했는데, 이는 해당 브랜치가 09-30에 생성된 이래 최대 규모의 배치이다(10-08의 36건 배치를 초과). Ztt는 RISC-V 행렬 확장 방향의 초안 명령어 집합으로, RuyiAI가 LLVM 측 BOSC AME / A100 라인 외에 GCC 툴체인에서 펼치는 배치이다. 이번 배치는 Ztt 백엔드 인프라에 대한 체계적인 정밀 다듬기를 중심으로 한다: 디스크립터 체계의 전면적 재사용과 캐싱(TC / ACC / zip / 행렬·열 / 생성자 및 consumer, unary 오퍼랜드 상태), 인덱스화 조회와 등록(builtin 디코더, store 선언, 오버로드 후보, profile과 타입 조회, datatype 이름과 등록 키), 영값과 협소 캐리어 단순화(영 레지스터를 스칼라 / 제어 입력에 사용, 협소 Ztt 스칼라 캐리어, 부동소수점 영 오프셋 시프트 폴딩), 브랜치 엣지와 fallthrough를 따른 디스크립터 전파, DCE 후 디스크립터 정리, 동적 워크스페이스 계산의 인수분해, 그리고 LTO dump 검사와 최적화 명령어 검사 업데이트. 51건 모두 신규 개발 커밋이다(작성자와 커미터 시간이 동일한 푸시 시점). 브랜치 헤드는 a326bc3 “Update Ztt descriptor and LTO dump checks”로 전진했다.

두 포크의 전체 스택 재구성이 이번 모니터링 기간에 동시에 자리 잡았다. PyTorch 포크의 riscv 브랜치는 10-11 새벽(약 03:00)에 전체 스택 재구성을 완료했다: 로컬 커밋 23건이 새로운 커미터 시간으로 다시 반영되었다(작성자 날짜는 4월부터 10-04까지 이어지며, 이미 머지된 #1 차단 테이블, #4 / #11 / #12 / #18 / #20 / #21 / #40 ~ #44의 CI와 수정 시리즈, #50 차단 테이블 확장, 그리고 SyncBots 통합 기록 3건 포함). 헤드는 “[SyncBots] Integrate PyTorch at e188cec”를 유지하며, 베이스는 업스트림을 따라 전진했다(10-10 당일 업스트림 커밋 포함). LLVM 포크의 riscv 브랜치는 10-11 심야(약 23:00)에 또 한 차례 야간 리플레이를 완료했다: 로컬 패치 26건이 새로운 커미터 시간으로 전체 재반영되었으며, 헤드는 여전히 #31 “A100 HP/SP와 pack/unpack lowering 및 스케줄링 캘리브레이션”이고 스택 구성은 이전 라운드와 동일하며, 리플레이 앵커는 10-11 당일 업스트림 스냅샷으로 동기화되었다. 양측의 재구성 / 리플레이 완료 후, 각자의 오픈 PR(PyTorch 8건, LLVM의 FPGA 2건 #25 / #28) 기준 기록이 연이어 갱신되었으며, 새로운 라운드의 리뷰 진행을 기다리고 있다.

Triton 측에서는 지난 모니터링 기간에 장애물을 제거한 Buddy MLIR 의존성 업그레이드 PR #84가 10-10 오후(13:31)에 머지되었다(봇 자동 머지): 이 PR은 09-20에 개설되어 buddy-mlir를 nightly 버전 v0.0.11.dev20260925로 업그레이드한다. 이전에는 v0.0.11이 가져온 새로운 LLVM이 고정 프론트엔드 API와 호환되지 않아 빌드가 실패했으나, 10-09의 패치 적응(#86)으로 장애물이 제거된 후 머지 조건을 갖추었다. 이로써 “패치 적응(#86) → 의존성 업그레이드(#84)” 체인이 닫혔다. 이후 관찰 지점은 야간 채널이 v0.0.11을 포함한 새 빌드를 산출하는지, 그리고 커뮤니티 소프트웨어 최적화 PR #85의 리뷰 진행 상황이다.

1. RuyiAI 스택 진행 상황(PyTorch / Triton / TileLang RISC-V 적응)

모니터링 기간 개요: RuyiAI-Stack 조직 18개 저장소, 모니터링 기간 내 동작 다섯 곳: pytorch(riscv 브랜치 전체 스택 재구성 23건 재반영, 오픈 PR 8건 기준 갱신, main 업스트림 동기화 55건), llvm-project(riscv 브랜치 야간 리플레이 26건, FPGA 2건 PR 갱신), triton-riscv(#84 머지), harness(1건: Triton-RISCV 플러그인 백엔드) 및 ruyiai-daily(10-11호)와 사이트 저장소(2건 정례); tilelang-riscv, mxnet, caffe, FBGEMM, IntrinTrans, VecIntrinBench, cpuinfo, torq-tile, dsh-osc, skills, pytorch-ci, SyncBots-DeepAgents 등은 모니터링 기간 내 푸시 없음.

1.1 pytorch: riscv 브랜치 전체 스택 재구성 완료(23건 재반영); 오픈 PR 8건 정례 기준 갱신(10-11)

날짜: 2026-10-11　출처: riscv 브랜치 커밋 목록, 헤드 커밋 0fc3546d, 재빌드 샘플 커밋 9434cbce, PR 목록

riscv 브랜치는 10-11 새벽(약 03:00)에 전체 스택 재빌드를 완료했다. 23건의 로컬 커밋이 새로운 커미터 시간으로 다시 반영되었으며, 헤드는 「[SyncBots] Integrate PyTorch at e188cec」 통합 라인(작성자 날짜 10-04)을 유지하고, 그 아래에 기존 순서대로 로컬 패치와 CI 커밋(#44 bytes_to_scalar 수정, #50 차단 목록 확장, #42 ULP 허용 오차, 세 건의 SyncBots 통합, #40 / #41 CI 파싱, #20 / #21 CI 분리, #18 cpuinfo 교체, #12 커밋 해시 고정, #11 차단 목록, #4 차단 목록 형식, #1 초판 차단 목록 등)이 배치되어 있으며, 베이스에는 10-10 당일 업스트림 스냅샷이 포함되어 있다. 이번 회차는 해당 브랜치가 10-08 새벽에 재빌드된 이후의 또 한 차례이다(머신 타임스탬프 집중, 작성자 날짜가 모니터링 기간보다 이르므로, 신규 개발이 아닌 일상적 재빌드에 해당). 오픈 PR 측면: 8건(#23 Enable XNNPACK, #35 테스트용 PR, #36 타임아웃 완화, #38 DataLoader 임시 비활성화, #43 패치 간소화, #46 ATen RVV 지원, #48 RVV CPU capability, #51 riscv64 로컬 이미지)이 10-11 오전(09:10)에 일괄 갱신되었으며(일상적 베이스라인 동기화 리듬의 연속), 전부 오픈 상태를 유지하고 모니터링 기간 내 병합 및 종료는 없었다. main 브랜치 모니터링 기간 내에는 업스트림 커밋 55건이 포함되어 있다(샘플링 결과 inductor, dynamo, ROCm 등 범용 변경으로, 필터링 규칙에 따라 개별 수록하지 않음).

1.2 llvm-project: riscv 브랜치 또 한 차례 야간 리플레이 완료(26건); FPGA 두 건 PR 갱신 후 리뷰 대기(10-11)

날짜: 2026-10-11　출처: riscv 커밋 목록, 헤드 커밋 a2a364a1, PR #25, PR #28

riscv 브랜치는 10-11 심야(약 23:00)에 또 한 차례 패치 스택 전체 리플레이를 완료했다. 26건의 로컬 패치가 새로운 커미터 시간으로 다시 반영되었으며, 헤드 a2a364a1은 여전히 #31「A100 HP/SP 및 pack/unpack 저하 및 스케줄링 캘리브레이션」이다(직전 회차 헤드와 동일 제목으로, 일상적 리플레이에 해당). 스택 구성은 기존 26건을 유지하고 있으며(#30「IME intrinsics를 SpacemiT A100 dot 명령으로 저하」, #29 BOSC AME 명령 업데이트, #27 xtame 설계, #24 BOSC AME 백엔드 설계, #23 XBuckyball 명령 캐리어, #20 Buckyball 벤더 확장, #18 / #16 / #14 등, 그리고 SyncBots 통합 기록 포함), 브랜치 베이스에는 10-11 당일 업스트림 커밋(UTC 14:49 전후)이 포함되어 있어, 이번 리플레이가 최신 업스트림 스냅샷을 함께 가져왔다(이번 회차는 10-09 심야 이후의 또 한 차례이다). 리플레이 완료 후, 두 건의 FPGA 백엔드 PR(#25「BOSCAME FPGA 백엔드」, #28「xboscame FPGA」)의 갱신 시간이 10-12 00:55에 새로 고쳐졌으며, 오픈 상태로 리뷰 대기 중이다. 참고: buckyball 브랜치(10-06 헤드)는 모니터링 기간 내 새로운 활동이 없었다.

1.3 triton-riscv: #84 Buddy MLIR 의존성 업그레이드 병합; #85 오픈 유지(10-10)

날짜: 2026-10-10　출처: PR #84, 병합 커밋 fe554ffa, PR #85, Releases 페이지

5.1 재구성 리듬 이중 가동: 두 fork가 같은 주에 각각 한 차례 전체 스택 재구성 완료

이번 모니터링 기간 내 PyTorch와 LLVM 두 fork의 riscv 브랜치는 각각 한 차례 전체 스택 재구성을 완료했다: PyTorch 23건 재적용(10-11 새벽), LLVM 26건 재적용(10-11 심야), 재구성 후 각각의 오픈 PR 베이스라인이 함께 갱신되었다—”업스트림 진전 → 전체 스택 재적용 → PR 베이스라인 갱신”은 이미 양측 fork의 상시화된 운영 형태가 되었다(이번 회차는 각각 PyTorch가 10-08, LLVM이 10-09에 이은 또 한 차례이다). 관찰 포인트: 재구성은 업스트림과 동일 베이스라인만 보장할 뿐, 실제 내용 진전은 여전히 PR 리뷰의 효율에 달려 있다(LLVM의 FPGA 2건, PyTorch의 RVV 시리즈).

5.2 Ztt 라인 연속 두 배치 가속: 단일 배치 규모 36건 → 51건

Ztt 초안 매트릭스 확장의 GCC 백엔드 라인은 09-30 구축 이후 리듬이 빨라졌다: 10-08 하루 36건에 이어, 이번 모니터링 기간에 다시 51건(최대 단일 배치)이 적용되었으며, 주제는 기능 구축에서 디스크립터 체계의 성능화 정밀 다듬기(재사용, 캐시, 인덱스화와 워크스페이스 인수분해)로 전환되었다—이는 일반적으로 기능 면이 안정화되어 최적화와 마무리 단계에 진입했음을 의미한다. 관찰 포인트: riscv-binutils 측 ztt-dev의 후속(현재 여전히 09-30에 정지)과 업스트림화 경로.

5.3 의존성 업그레이드 체인 폐합: #86 적응 → #84 머지

지난 모니터링 기간에는 #86 패치 적응으로 새 LLVM API를 위한 장애물을 제거했고, 이번 모니터링 기간에는 #84가 곧바로 머지되어 Buddy MLIR v0.0.11 의존성 업그레이드가 자리 잡았다—Triton-RISCV 프론트엔드가 “LLVM 업스트림 빠른 진화—고정 프론트엔드—의존성 업그레이드” 사이에서의 적응 체인을 또 한 번 폐합했다. 후속 관찰: 야간 채널이 v0.0.11을 포함한 새 회차 빌드를 산출하는지(현재 최신은 여전히 10-04 회차); 커뮤니티 최적화 PR #85의 리뷰(softmax와 matmul 경로); LLVM 스택 내 A100 / BOSC AME 패치가 다음 회차 재적용에서의 진전.
