오늘의 중점: SpacemiT X100/A100 코어 지원이 RuyiSDK GCC 16.2 브랜치에 병합

날짜: 2026-09-21　출처: spacemit-x100 커밋, Spacemit-A100 커밋

베이징 시간 09-21 15:04와 15:10, RuyiSDK의 GCC 다중 버전 유지보수 저장소 riscv-gcc의 16.2 브랜치에 SpacemiT 코어 지원 패치 두 건이 연달아 병합되었다: RISC-V: Add basic spacemit-x100 core support와 RISC-V: Add basic Spacemit-A100 core support로, 두 코어를 정식으로 컴파일러의 -mcpu/-mtune 옵션에 추가했다.

X100은 한 번의 커밋으로 스케줄링을 기존 generic_ooo 모델에 매핑했으며, 변경 사항은 riscv-cores.def의 코어 및 튜닝 항목, riscv.cc에 새로 추가된 spacemit_x100_tune_info, mcpu/mtune 문서 재생성, 그리고 새로 추가된 테스트 케이스 mcpu-spacemit-x100.c를 포함한다. A100의 커밋 설명은 더 자세하다: 이 코어는 순차 2-issue이며 마이크로아키텍처가 X60에 가까워서 일단 Spacemit X60의 비용 모델을 재사용한다; ISA상으로는 X100에 가장 가깝고, 주요 차이는 H(가상화) 확장을 구현하지 않으며 벡터 길이 VLEN=1024(zvl1024b)이고 xsmtvdotii 확장을 가진다는 점이다—해당 확장 정의도 함께 riscv-ext-spacemit.def와 확장 문서에 작성되었고, 테스트와 코어 항목이 동기적으로 보완되었다.

두 패치의 작성자는 모두 T-Head의 Mark Zhuang(패치 서명 날짜는 6월 말)이며, 09-21에 저장소 측에서 머지를 완료했다. K3 플랫폼을 채택한 개발 보드(예: CoM260 Kit의 X100 8개 + A100 8개 코어 조합) 입장에서 이는 RuyiSDK 툴체인이 -mcpu로 이 두 코어를 직접 선택하고 해당 확장 정의와 스케줄링 설정을 얻을 수 있음을 의미하며, 범용 설정만 사용하지 않아도 된다. 두 건 모두 basic support(X100은 범용 비순차 모델, A100은 X60 비용 재사용)임을 고려하면, 향후 스케줄링 세분화와 테스트 커버리지는 데일리 리포트에서 계속 추적할 가치가 있다.

1. RuyiAI 스택 진행 상황 (PyTorch / Triton / TileLang RISC-V 적응)

모니터링 기간 개요: RuyiAI-Stack 조직의 16개 저장소 중 모니터링 기간 내 활동이 있는 곳은 4개다: pytorch(기본 브랜치 강제 푸시 및 main 업스트림 동기화 89회), triton-riscv(릴리스 1건), ruyiai-daily(커밋 1건), ruyiai-stack.github.io(자동 커밋 1건); tilelang-riscv, llvm-project, pytorch-ci, FBGEMM, cpuinfo, VecIntrinBench, IntrinTrans, harness, dsh-osc, torq-tile, skills, SyncBots-DeepAgents는 모니터링 기간 내 푸시가 없다.

1.1 PyTorch의 riscv 기본 브랜치가 모니터링 기간 내 다시 강제 푸시, 열린 PR 8건의 기준선 일괄 갱신 (09-21)

날짜: 2026-09-21　출처: riscv 브랜치 커밋, PR #51, PR #46

베이징 시간 09-21 08:24, 이 fork의 기본 브랜치 riscv에서 강제 푸시(force push, 타임라인 기록상 작업자는 WuXintong123)가 발생했다: GitHub는 열린 병합 요청 8건에 대해 같은 시각 기준 브랜치 강제 푸시 이벤트(base_ref_force_pushed)를 기록했고, 이 8개 PR의 업데이트 타임스탬프를 동일한 시각으로 일괄 갱신했다—#23, #35, #36, #38, #43, #46, #48, #51. 브랜치 헤드는 현재 4f173e3e(Fix bytes_to_scalar for float/complex on RISC-V, PR #44의 내용에 해당)이며; 브랜치 헤드의 각 커밋 커미터 타임스탬프는 09-21 03:00 전후에 집중되어 있어, 브랜치 내용이 전날 늦은 밤 한 차례 재정렬되었음을 보여준다. 이 저장소의 riscv 브랜치는 자동화 동기화 흐름에 의해 지속적으로 재정렬되며(브랜치 이력에 SyncBots 통합 커밋 포함), 이번 작업은 전날의 푸시 리듬과 일치한다; 모니터링 기간 내 riscv 브랜치에는 새로운 내용 커밋이 없다.

상태가 갱신된 열린 병합 요청 8건은 모니터링 기간 내 모두 머지되지 않았으며, 구성은 다음과 같다: RVV 방향 2건—#46 RISC-V Vector Extension (RVV) support for ATen(작성자는 소프트웨어연구소 Zhang Fei, 커밋 22개, 파일 32개, +2361/-32 라인)과 #48 Add RISC-V Vector (RVV) CPU capability(작성자 XYenChi, 커밋 21개, 파일 18개); CI 및 테스트류—#36 타임아웃 완화, #38 dataloader 테스트 임시 비활성화; 기능 및 자리표시자류—#23 Enable XNNPACK, #35 테스트용 PR, #43 재제출 대기 중인 최적화 패치; 그리고 09-20에 새로 열린 #51 Add riscv64 local image(로컬 이미지 빌드 스크립트).

메인라인 main(업스트림 미러 브랜치)은 모니터링 기간 내 89회 동기화 커밋이 있었고, 최신 푸시는 베이징 시간 09-22 02:56에 이루어졌으며 내용은 업스트림 일반 이슈: precompile 모듈화, MPS 경쟁 조건 수정, ROCm 디바이스 항목과 분산 테스트 안정성 등이다; riscv, rvv, vector, XuanTie, rv64, rv32 등의 키워드로 항목별 필터링한 결과 RISC-V 관련 내용은 없어 이번 호에서는 다루지 않는다.

날짜: 2026-09-21　출처: Nightly 2026-09-20-12c2f6a

베이징 시간 09-21 새벽, triton-riscv가 주간 빌드 Nightly 2026-09-20-12c2f6a를 릴리스했다(이전 회차는 2026-09-13-da5291b, 그 이전은 09-06, 08-30으로 매주 1회의 고정 리듬을 보인다). 이번 빌드는 저장소의 현재 브랜치 헤드 12c2f6a에서 가져왔으며, 그 내용은 09-14의 의존성 정례 업데이트(buddy-mlir 나이틀리 버전이 v0.0.9.dev20260911을 가리킴)이다. 저장소 커밋 자체는 여전히 09-14에 머물러 있고 모니터링 기간 내에 새로운 코드가 유입되지 않았으므로, 빌드 파이프라인의 정례 산출물에 해당한다.

1.3 tilelang-riscv, llvm-project 및 나머지 전용 목표 저장소는 모니터링 기간 내 조용 (07-16 / 09-17 상태)

날짜: 2026-09-21　출처: tilelang-riscv, llvm-project

RISC-V 측의 컴파일러 및 연산자 적응 라인은 이번 기간에 새로운 움직임이 없다: tilelang-riscv의 마지막 커밋은 07-16에 멈춰 있고, llvm-project fork는 09-17에 멈춰 있다. pytorch-ci는 커밋 기록이 없으며, harness(09-10), torq-tile(04-09), dsh-osc(09-15) 역시 조용하다. 세 저장소 모두 모니터링 기간 내에 커밋과 릴리스가 없다.

기술 정보 저장소는 모니터링 기간 내에 한 번의 커밋이 있었으며(베이징 시간 09-21 06:17), 내용은 09-21 회차로, 자체적으로 밝힌 롤링 윈도우는 09-20 02:24부터 09-21 06:00까지이다. 해당 회차의 RISC-V 섹션에는 AME 툴체인 아티팩트(AME_llvm에 ztt v0.6의 LLVM 21 툴체인 분할본과 검증 파일 추가), AME_gem5의 Ztt 테스트 연동, NEMU의 tile 레지스터 범위 초과 읽기 감지, XiangShan 부동소수점 백엔드 FltRegion 머지와 아키텍처 테스트의 실험적 확장 스위치 등의 항목이 수록되어 있으나, 원본 시간이 모두 이번 모니터링 기간 이전에 속하므로 중복 방지 원칙에 따라 이번 회차에서는 더 다루지 않는다. 사이트 저장소는 모니터링 기간 내에 별도로 한 번의 자동 커밋이 있었으며(베이징 시간 09-22 04:16), 기여자 데이터 파일을 정례적으로 업데이트했다.

기간 개요: ruyisdk 조직의 46개 저장소 중 모니터링 기간 내에 푸시가 있었던 것은 4개이다: riscv-gcc(16.2와 p-rebase 두 브랜치), support-matrix(5회 커밋), board-docs(1회), ruyi-backend(Dependabot 정례 브랜치 업데이트). ruyi, packages-index, docs, linux-xuantie-kernel, ruyisdk-vscode-extension, ruyisdk-website, ruyisdk-overlay 등의 최신 활동은 모두 09-20 및 그 이전이다. openRuyi-Project 조직은 모니터링 기간 내에 openRuyi에서 56회의 커밋이 있었고, 나머지 4개 저장소에도 푸시가 있었다(2.5 참조).

2.1 riscv-gcc 16.2 브랜치에 T-Head X100/A100 코어 지원 머지 (09-21)

날짜: 2026-09-21　출처: 16.2 브랜치 커밋 기록

자세한 내용은 「오늘의 중점」 참조. 보충: 16.2 브랜치에는 모니터링 기간 내에 총 4건의 커밋이 있었으며, 나머지 두 건은 정례적인 내용이다 — 업스트림 libstdc++의 gamma_distribution 수정 백포트(PR123409)와 일일 빌드 번호 커밋. 이 저장소는 브랜치로 여러 버전의 GCC를 조직하며(기본 브랜치는 16.1), 16.2 브랜치는 신규 플랫폼을 위한 코어 및 확장 패치를 지속적으로 받고 있다.

2.2 P 확장 lowering 지속 머지: packed min/max와 psh1add가 p-rebase 브랜치에 진입 (09-21)

날짜: 2026-09-21　출처: PR #19

2.5 openRuyi 모니터링 기간 내 56회 커밋: 커널 이중 라인 업그레이드, 빌드 체계 재구성 및 보안 업데이트 일괄 (09-21 ~ 09-22)

모니터링 기간 동안 openRuyi 소프트웨어 패키지 디렉터리에는 총 56회의 커밋이 있었으며, 이는 세 조직 가운데 단일 일자 최다 커밋으로 네 가지 라인에 집중되어 있다.

셋째, 보안 업데이트 일괄: pcre2 10.48, imagemagick 7.1.2.31, python-ujson 6.0.0, python-datasets 5.0.1, python-pytorch-lightning 2.6.6, btrbk 0.32.7 모두 security-fixes로 표기; glibc는 새로운 빌드 베이스라인으로 업데이트.

넷째, 클라우드 네이티브 및 데스크톱 도구 보강: go-k8s-kms, konnectivity-client, datadog dd-trace-go, victoriametrics-metrics, opencensus 등 Go 패키지와 cloudpods-dashboard 신규 추가; 데스크톱 측에는 fd, pngquant를 신규 추가하고 그 Rust 의존성 클로저(vte, vt100, lscolors, jiff, clap-complete, etcetera 등 십여 개 crate)를 일괄 편입.

5. 트렌드 관찰

5.1 툴체인이 코어를 인식하기 시작하다: X100/A100이 -mcpu/-mtune에 진입, RVV 실측 수치와 두 가지 지지선 형성

이번 모니터링 기간의 가장 구체적인 기술 진전은 riscv-gcc 16.2 브랜치가 SpacemiT의 두 코어를 위해 -mcpu/-mtune 및 확장 정의(VLEN=1024와 xsmtvdotii 포함)를 보완한 것이다. 09-17의 ONNX Runtime MLAS RVV 커널 최적화(K3/X100 실측 3.01배 향상)와 결합하면, K3 플랫폼을 겨냥한 두 가지 지지선이 동시에 추진되고 있다: 성능 측에는 재현 가능한 연산자 수준 수치가 있고, 툴체인 측에는 코어 수준 인식과 스케줄링 진입점이 있다. 다음으로 주목할 만한 것은 스케줄링 모델의 세분화——X100은 잠정적으로 범용 아웃오브오더 모델을 사용하고 A100은 X60 비용 모델을 재사용하는 것은 모두 과도기 방안이다——그리고 이러한 코어 지원의 향후 유지보수 경로이다.

5.2 openRuyi의 롤링 업데이트가 커널 이중 라인과 빌드 표준화 단계에 진입

하루 56회 커밋 중 커널 7.2.6과 LTS 6.18.52 이중 라인 업그레이드, openruyi-linux-build 신규 패키지와 RPM 매크로 재구성이 이번 라운드에서 가장 무거운 두 부분이며, 나머지는 보안 업데이트와 클라우드 네이티브, 데스크톱 패키지 보완이다. 뉴스 페이지에 아직 09월 버전 공지가 없는 현황과 결합하면, 월간 버전의 내용은 여전히 빠르게 축적되고 있다. 다음 관찰 지점은 2026.09 월간 버전 공지 및 그에 따르는 커널과 보안 베이스라인이다.

5.3 K3/CoM260 플랫폼이 일주일 만에 검증, 예제, 강좌의 콘텐츠 폐쇄 루프 완성

09-18의 K3 Pico-ITX ROS2 강좌 진입점에서, 09-20의 CoM260 Buildroot 보고서, 09-21의 CoM260 Kit 3개 시스템 일괄 보고서와 board-docs 예제 보완, 그리고 같은 시기 GCC 측의 코어 인식 지원에 이르기까지, K3 플랫폼은 일주일 만에 「다중 시스템 검증—예제 코드—강좌 자료—툴체인」의 연속적 커버리지를 완성했다. K3를 목표로 하는 개발자와 제품 팀에게 툴체인, 시스템 이미지, 학습 자료의 준비도가 뚜렷이 향상되었다.

5.4 이번 모니터링 기간의 공백과 관심 지점

솔직히 기록해야 할 공백: 뉴스 측에서 RuyiAI, RuyiSDK, 루이 커뮤니티, openRuyi에 대한 Google News 중영문 다중 쿼리가 연속 제로 히트였다. arXiv는 모니터링 기간 내 신규 수록이 없다. ruyi와 packages-index는 조용하다(커밋과 릴리스 없음). 벡터와 연산자 세 가지 전문 목표 저장소는 모두 조용하다. PyTorch fork는 자동 동기화 동작만 있고 새로운 기능 커밋이 없다. 관심 지점: 첫째, ruyi 0.54 프리릴리스 라인의 후속 동향과 0.53 정식 버전 넘버링. 둘째, 바이위클리 진행 077호(지난 호 09-15). 셋째, openRuyi 2026.09 월간 버전. 넷째, riscv-gcc 16.2 브랜치의 후속 병합 리듬.
