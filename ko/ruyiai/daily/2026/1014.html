오늘의 중점: openRuyi, K3 펌웨어 플랫폼 라인 개척——edk2-ruyi / ruyifirmware 두 저장소 신규 생성 및 전량 최초 푸시, 첫 펌웨어 버전 릴리스; 격주 리포트 078 최종 확정 및 서밋 예고

날짜: 2026-10-13　출처: edk2-ruyi 커밋 목록, ruyifirmware Releases, 격주 리포트 078 기 파일, 포럼 주제 #2891

openRuyi-Project는 10-13에 K3 펌웨어 플랫폼 라인을 한 번에 확정했습니다. 새 저장소 edk2-ruyi(저장소는 당일 11:07 베이징 시간에 생성)가 35개의 커밋으로 SpacemiT K3 Pico ITX의 EDK2 플랫폼 코드를 일괄 최초 푸시했으며(작성자 RevySR, 푸시 기간 11:55 ~ 16:21), 플랫폼 패키지 정의부터 각 주변기기 드라이버까지의 전체 체인을 포함합니다. 플랫폼 기반 측에는 SpacemitPlatformPkg 독립 플랫폼 패키지와 공유 리소스/클록 처리, 전원 도메인 제어, DMA 고주소 비일관성 지원, 보드 레벨 EEPROM과 이더넷 MAC 할당이 포함됩니다. 부팅 및 보안 체인 측에는 SEC 단계 메모리 발견과 디바이스 트리 게시, 부팅 선택과 핫키 정책, 부팅 로고와 카운트다운/복구 상태 표시, NOR 백엔드 UEFI 런타임 변수, DDR 트레이닝 기록 저장, 그리고 Fastboot 전체 구현(EFI 이미지 로드, NOR/NVMe/UFS 펌웨어 업데이트, 버전 조회, NV 보존을 포함한 검증 업데이트와 USB 디바이스 측 전송)이 포함됩니다. 주변기기 측에는 저장(UFS 고속 링크 협상, QSPI NOR 접근), 네트워크(EQoS 네이티브 이더넷, RTL8127 SFP 링크, SNP 폴링 서비스와 어댑터 정보), 디스플레이(DPU 클록/스캔면 관리, Inno DP의 AUX와 링크 트레이닝, EDID 모드와 GOP 동작), USB 호스트 컨트롤러와 PCIe 컨트롤러/공유 PHY가 포함됩니다. 마지막 두 커밋은 그래픽 콘솔 연결 타이밍과 Option ROM이 있는 디바이스의 64-bit BAR 보존에 대한 마무리 수정입니다.

함께 제공되는 ruyifirmware는 같은 날 12:01에 새로 생성되어 5개의 커밋으로 착지했습니다(12:17 ~ 18:31, 작성자 역시 RevySR). “coreboot, OpenSBI, EDK2 기반 펌웨어”를 지향하며 K3 Pico ITX를 대상으로 패키징 체인 make package를 구축하고, 산출물은 x64 에뮬레이터 스위치 두 변형으로 나뉩니다(에뮬레이터는 x64 UEFI Option ROM 실행, 독립 그래픽 카드 GOP 지원에 사용, README에는 K3에서 RX550에 포인터 절단 문제가 있어 no-x64emu 변형 사용을 권장한다고 명시). 또한 PCI Option ROM/GOP 업데이트와 CI 빌드 릴리스 파이프라인을 포함합니다. 당일 18:46에 첫 펌웨어 버전 “Ruyi Firmware 20261013”을 릴리스했습니다. 같은 조직의 kiwi-image도 같은 날 riscv64 이미지의 GitHub Action과 로컬 빌드 스크립트를 착지시켰습니다(3개, 작성자 Z572, Fancyhe1). 펌웨어—패키징—이미지 세 라인이 같은 날 함께 움직이며 K3 하드웨어 기반의 개방형 전달 체인이 형성되었습니다.

커뮤니티 측에서도 같은 날 전파 노드가 확정되었습니다. RuyiSDK 격주 위클리 리포트 078호가 편집 파이프라인을 완료하고(#371 ~ #378 총 8개, 17:46에 “add summary, remove sections with no progress”로 마무리) 온라인에 게시되었습니다. 주제는 “RuyiSDK, RISC-V 중국 서밋에 등장”(10.18-20 선전 컨벤션 센터 푸톈, 기조연설, 포스터 전시, D15 부스 데모)입니다. 내용은 패키지 매니저 0.54.0 월말 릴리스 계획, IDE 한 차례 다듬기, 기반 C 라이브러리/GCC/LLVM/V8/OpenJDK/Go 각 라인 진행 상황을 종합합니다(자세한 내용은 4.1과 2.4 참조).

riscv 브랜치가 또 한 차례 전체 스택 재구성을 완료했다: 23개의 로컬 커밋이 새로운 커밋터 시간(10-13 새벽 03:00 전후에 집중)으로 일괄 재적용되었고, 헤드가 a17584a3 「[SyncBots] Integrate PyTorch at e188cec」로 갱신되었다(같은 제목의 이전 버전 6ff4eefe는 이번 재구성으로 대체되었으며, SHA는 재구성에 따라 갱신됨). 스택 구성은 기존 시퀀스를 유지한다(#44 bytes_to_scalar 수정, #50 마스킹 테이블 확장, #42 ULP 허용 오차, 3건의 SyncBots 통합, #40 / #41 CI 파싱, #20 / #21 CI 분할, #18 cpuinfo 교체, #12 커밋 해시 고정, #11 / #4 / #1 마스킹 테이블 시리즈 등). 베이스는 10-12 저녁 업스트림 스냅샷을 포함한다(그 하한 경계는 업스트림 동기화 지점 db0d2902b8). 이번 라운드는 최근 일주일간 매일 아침 한 번 푸시하는 재구성 리듬을 이어간다(10-08부터 연속 확인됨). 열린 PR 측은 8건(#23 Enable XNNPACK, #35 테스트용 PR, #36 타임아웃 완화, #38 DataLoader 임시 비활성화, #43 패치 간소화, #46 ATen RVV 지원, #48 RVV CPU capability, #51 riscv64 로컬 이미지)이 10-13 오전(09:08)에 베이스를 일괄 갱신했으며, 전부 열린 상태로 유지되고 모니터링 기간 내 머지와 클로즈는 없었다. main 브랜치는 모니터링 기간 내 업스트림 커밋 70건을 동기화했다(inductor, CUDA, CI, MPS 등 범용 변경 포함, 필터 규칙에 따라 개별 수록하지 않음).

4.3 외부 뉴스: 서밋 사전 보도 집중; arXiv와 openRuyi 뉴스 페이지 업데이트 제로(10-13 상태)

날짜: 2026-10-13(상태)　출처: 21경제 보도, openRuyi 뉴스 페이지, arXiv

외부 뉴스 측면은 서밋 사전 홍보가 주를 이룬다: 21경제는 10-13 14:40에 “RISC-V 풍향계: 2026 중국 서밋 전면 업그레이드, 생태계 성숙도 공동 논의”를 발표 — 서밋 규모(예상 오프라인 관객 3000여 명, 참가 업체 150여 곳, 온라인 커버리지 80만 명), RISC-V가 이미 글로벌 프로세서 시장의 25% 점유율을 차지했다는 설명, 7개 병행 분과 포럼 구성을 열거; 36Kr 등도 같은 주제의 사전 홍보 기사를 게재. Google News의 RuyiSDK / RuyiAI / openRuyi 중영문 직접 검색 모니터링 기간 내 관련 히트 제로(채널 정상). openRuyi 배포판 뉴스 페이지에 신규 글 없음(2026.09 릴리스 공지가 여전히 최신); RuyiAI 공식 웹사이트에 신규 블로그 글 없음. arXiv(RISC-V 컴파일, 벡터 및 추론 방향) 모니터링 기간 내 신규 등재 없음(최근 관련 항목은 여전히 10-05 ~ 10-07의 장벡터 레지스터 저장 SVRF, 엣지 AI Transformer 추론 가속 프레임워크 등).

5. 동향 관찰

5.1 펌웨어 플랫폼 라인 개설: K3 하드웨어 기반이 “펌웨어—패키징—이미지” 삼위일체로 진입

openRuyi-Project는 “저장소 생성 + 전량 최초 푸시 + 당일 릴리스”의 조합으로 K3 펌웨어 플랫폼 라인을 개척: edk2-ruyi 플랫폼 코드(35건), ruyifirmware 패키징 및 릴리스 체인(5건 + 첫 펌웨어 버전), kiwi-image 이미지 자동화(3건) 세 라인이 같은 날 안착. 기존 K1/K3 펌웨어 저장소와 나란히, openRuyi의 SpacemiT 플랫폼에 대한 시스템 레벨 지원이 커널/배포판에서 펌웨어 계층으로 보완됨; 격주 보고서의 “K1/K3 툴체인 적응 개발 중”이라는 설명과 결합하면 K3의 소프트웨어-하드웨어 통합 딜리버리 리듬이 가속화되고 있다. 관찰 포인트: edk2-ruyi / ruyifirmware의 향후 이터레이션 리듬, 첫 펌웨어 버전의 실제 보드 검증 피드백, 그리고 openRuyi 배포판 이미지 체인과의 연결.

5.2 생태계 운영이 서밋 리듬에 진입: 격주 보고 078과 D15 부스 사전 홍보

10.18 서밋 개막까지 일주일 남은 시점에서 운영 라인 움직임이 집중: 격주 보고 078이 서밋 등장을 주제로 마무리, 포럼 참여 공지 발표, 외부 미디어(21경제, 36Kr) 동시 사전 홍보 — RuyiSDK의 서밋 내러티브(발표 + 포스터 + D15 부스 데모)가 실행 주간에 진입. 관찰 포인트: 서밋 일주일 내 발표 박자(중심 서밋에서 버전 또는 성과 발표 여부), 데모 방안의 기술적 하이라이트.

5.3 정례 유지보수 이중 트랙 관찰: PyTorch 아침 리빌드 정상, LLVM 야간 리플레이 이번 라운드 미속행

두 fork 유지보수 라인의 리듬이 이번 모니터링 기간에 분화: PyTorch riscv 브랜치는 정상적으로 제N차 아침 리빌드(23건, 헤드 업데이트 a17584a3)와 PR 베이스라인 갱신을 완료; LLVM riscv 브랜치는 새로운 야간 리플레이 라운드가 나타나지 않음(헤드는 10-12 리플레이 버전 유지). 둘 모두 정례 운영 범주에 속하지만, LLVM 측의 “야간 리플레이” 리듬이 복귀할 수 있을지, 그리고 ruyisdk/llvm-project의 rebase 라인(XTHeadVector 수정 이미 머지)과 fork 리플레이 라인의 관계는 지속적 관찰이 필요하다.

5.4 배포판 의존성 유지보수 배치화: Go 모듈 대량 업데이트와 GnuPG 스택 교체

openRuyi 메인 저장소 하루 103건 중 약 90%가 Go 생태계 모듈 대량 업데이트, 여기에 GnuPG 보안 스택 전량 교체(gnupg / libgcrypt / libksba / libgpg-error)와 llvm-snapshot의 LLVM 24로 점프가 겹쳐, openRuyi의 의존성 유지보수가 “배치 처리” 형태에 진입했음을 보여준다: 단일 모니터링 기간에 규모 있게 업스트림 버전을 따라가는 것. 이러한 대량 배치의 리뷰 효율과 빌드 검증(전체 패키지 재빌드 비용)은 배포판 리듬의 암묵적 제약이며, 관찰 포인트는 업데이트 배치와 실제 이미지 릴리스의 결합 방식에 있다.
