오늘의 중점: Caffe RVV 연산자 PR 세 건 개설, MXNet 시리즈 15건 심사 중——클래식 프레임워크 적응 라인이 실무 단계 진입

날짜: 2026-09-23 ~ 2026-09-28　출처: caffe PR #1, caffe PR #2, caffe PR #3, MXNet PR 목록

베이징 시간 09-28 14:56부터 14:59 사이 (3분 이내), 기여자 Xlawy가 caffe 저장소 (09-23 머지된 두 클래식 프레임워크 저장소 중 하나)에서 RVV 연산자 PR 세 건을 연속 개설하여, 두 저장소가 머지된 이래 첫 실질적 코드 움직임이 되었다:

  • #1 im2col (+113 / -9, 파일 2개): im2col 출력 행 수집을 스칼라 헬퍼와 RVV float 오버로드로 분리하고, 각 행을 제로 패딩과 경계 내 두 구간으로 나누며, stride_w에 따라 단위 스텝 또는 스트라이드 벡터 로드를 선택하고, 가변 길이 e32,m4 블로킹을 채택했다. 아울러 Protobuf의 SetTotalBytesLimit 단일 인자 API를 3.6.0 이상 버전에 맞게 조정했다.
  • #2 float CPU max pooling (+167 / -24, 파일 2개): e32,m4 블로킹으로 최대 풀링 내부 열을 처리하고, 스트라이드 로드와 엄격한 초과 비교로 최댓값 및 승자 위치 오프셋을 갱신하며, 최초 발생 동점 시맨틱과 -1 센티널을 유지하고, 3열 윈도우를 전개했다. 경계는 여전히 스칼라로 처리한다.
  • #3 float vPowx (+166 / -1, 파일 2개): 비 MKL vPowx<float>에 RVV 특화를 추가했다 — 입력이 모두 정규수이고 지수가 [-1, 1]일 때 벡터 log/exp 근사(배정밀도 중간값)를 활성화하고, 지수 0과 1은 직접 벡터 연산으로 처리하며, 블로킹된 인플레이스 호출을 지원한다. 도메인 검사가 통과되지 않으면 전체 호출이 스칼라로 폴백한다.

세 건 모두 RVV 매크로 가드로 새 특화를 추가하고 비 RVV 빌드의 스칼라 폴백을 유지했으며, 현재 모두 오픈 상태이고 리뷰 기록이 없다. 같은 노선의 더 이른 움직임은 MXNet 저장소에 집중되어 있다: 09-23부터 09-24까지 이틀 동안 세 명의 기여자가 누적 15건의 PR을 열었고(ww8191201-coder 11건, Xlawy 2건, 6eanut 2건), 그중 11건이 RVV 연산자 벡터화다 — GELU(erf) 역방향, ReLU 역방향, softmax, log-softmax, softmin, CTC log-softmax, im2col, col2im, batched cumsum, 최근접 업샘플링, float32 최솟값 리덕션; 나머지 4건은 성능과 빌드 기반이다(broadcast_reduce와 reduce_with_axis의 인덱스 순회 강도 축소, 합산 리듀서 volatile 제거, 비 MSVC 빌드에서 -fno-math-errno 요청). 여러 PR 설명이 SG2044(RVV 1.0, GCC 15.1)의 테스트 맥락을 직접 인용한다. 이 계열은 이전 모니터링 기간에 다뤄지지 않았으며, 이번 기간에 Caffe의 새 움직임과 합쳐 기록한다.

모니터링 기간 말 기준으로 두 저장소 합계 18건의 PR이 전부 오픈 상태이며 하나도 머지되지 않았다. 09-24 기간에 두 저장소를 「아카이브, 적응 베이스라인 또는 새 작업의 기점」으로 두고 지켜본다는 기록과 결합하면, 이번 배치의 움직임이 단계적 답을 내놓는다: 두 저장소는 클래식 프레임워크의 RVV 적응 실습 기지로 쓰이고 있으며, MXNet 계열은 추론 주간 연산자 면을 커버하고, Caffe 계열은 합성곱과 활성화 기반 인프라에 집중한다. 같은 날 밤, 컴파일러 측의 RVV 움직임은 tilelang-riscv PR #4가 이어받았으며(1.1 참조), RVV는 당일 조직 내에서 가장 집중된 기술 주제가 되었다.

5. 트렌드 관찰

5.1 클래식 프레임워크 RVV 양대 축 형성: “저장소 진입”에서 “PR 쌓기”로

09-23 두 저장소가 진입했을 때 그 용도는 관찰 대기로 기록되었으나, 일주일 만에 MXNet은 15건의 PR(기여자 3명)로 11개의 RVV 연산자와 4건의 성능·빌드 기반을 커버했고, Caffe는 09-28에 세 건의 RVV 연산자로 뒤따랐습니다. “적응” 노선이 클래식 프레임워크 차원에서 공식적으로 자리 잡은 것입니다. 주목할 세부 사항은 여러 PR이 SG2044(RVV 1.0, GCC 15.1)의 테스트 맥락을 직접 인용한다는 점으로, 이는 이 작업들이 실행 가능한 실기기 베이스라인을 지향함을 보여줍니다. PyTorch fork 측의 RVV 패치(#46, #48)가 여전히 큐에서 대기 중인 것과 대조적입니다. RVV 적응의 현재 추진은 부분적으로 PyTorch 메인라인을 우회하고 있습니다.

5.2 추석 전후의 리듬: 09-28 연휴 후 집중 산출

09-25(음력 8월 15일, 추석)와 그 뒤 주말에 세 조직의 커밋은 거의 멈췄습니다. 09-28 연휴 후 첫 근무일에 집중 산출이 나타났습니다. openRuyi 메인 저장소 5건, kiwi-image 3건, VS Code 플러그인 2건과 0.1.7 릴리스, ruyiai-daily와 포럼 정보 스레드가 같은 날 재개되었습니다. 연휴로 인한 “저점, 반등”이 두 기간에 걸쳐 완전히 드러났습니다.

5.3 도구 측 릴리스 리듬 안정

기간 내 세 가지 도구 라인이 각자의 리듬으로 추진되었습니다. VS Code 플러그인 0.1.7 정식 전환(beta 이후 8일), Ruyi Imager 나이틀리 채널 업데이트, triton-riscv 주간 나이틀리 빌드가 예정대로 산출되었습니다. 이에 대응하여 ruyi-tuner의 1.9 버전 라인은 “릴리스되지 않았으나 변경이 진행 중”인 상태를 두 기간째 유지하고 있습니다.

5.4 이 기간의 공백과 관심 지점

공백 항목: PyTorch riscv 브랜치와 열린 PR이 연속 침묵(09-21 이후), llvm-project PR #168(XTHeadVector 수정) 리뷰가 09-24에 정지, support-matrix 심사 대기열 적체(09-21부터 09-24까지 업데이트 없음), openRuyi 2026.09 월간 버전 공지 미게시, 외부 뉴스와 arXiv 제로 히트. 관심 지점: 첫째, MXNet / Caffe 18건 PR의 리뷰와 첫 배치 머지 리듬. 둘째, ruyiai-daily가 매일 푸시를 재개하는지 여부. 셋째, ruyici macOS 빌드와 riscv-gcc p 확장 패치의 추진. 넷째, 6.18.54-1 커널 태그가 openRuyi 정식 빌드에 진입하는지 여부.
