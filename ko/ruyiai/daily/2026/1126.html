오늘의 중점: FlagGems 5개 배치 245개 연산자 단일일에 triton-riscv에 병합 (11-25)

출처: PR #136. 나머지 4개 배치는 #137 ~ #140이며, 링크는 부록 [2] ~ [5] 참조.

11-25 10:13 ~ 19:53, triton-riscv에 FlagGems 연산자 예시 5개 배치, 총 245개 연산자 병합.

5개 배치는 각각 B12의 55개, B13의 51개, B14의 41개, 랜덤 및 RNN 및 attention의 50개, 희소 및 중첩 텐서의 48개.

각 배치는 연산자별로 CPU 정확성 테스트 1부씩 구성하며, examples 패키지의 __init__.py에서 통합 내보내기.

5개 배치 합계 54,550줄 추가, 315줄 삭제. B13의 검증 기록은 riscv64 CPU에서 146개 테스트 전부 통과, 환경은 Python 3.12, PyTorch 2.10.0, CPU Triton 3.9.0.

B14는 int4 패커도 함께 수정. 기존에는 출력 열 너비가 입력 값 128개를 초과할 때 나머지 바이트가 기록되지 않았고, 비연속 텐서도 연속 메모리로 읽혔음.

지난 기간 보고서에 기록된 B12, B13, B14 세 배치는 여전히 검토 중이었으나, 이번 기간에 모두 반영되었다. 11-24에 병합된 선형대수 59개를 포함하면 이번 라운드 이식 누적은 304개 연산자이다.

오늘의 핵심: triton-riscv, RISC-V 백엔드 튜닝 병합, Buddy 근사 수학 의존 (11-26)

출처: PR #129. Buddy 의존 항목은 부록 [24] 참조.

11-26 00:24, PR #129가 triton-riscv 메인라인에 병합되었으며, 2개 파일을 변경하고 136줄을 추가, 15줄을 삭제했다.

변경 사항은 모두 _ttsharedir_to_llir에 위치하며, 대상이 RISC-V일 때만 적용된다.

다섯 가지 조정: 수학 함수를 다항식 근사로 변경; 확장 가능 벡터와 AVL 테일 루프로 변경; matmul 벡터 폭을 2·VLEN/32로 설정; buffer를 할당 해제 전에 스택으로 승격; 스트라이드 memref 복사를 linalg로 변환하여 벡터화.

PR이 제시한 정밀도는 f32에서 1~7 ULP, f16과 bf16에서 1 ULP 이하이며, exp와 erfc의 서브노멀 결과는 제외된다.

이 변경은 buddy-mlir#1068이 제공하는 polynomial-approximate-math pass와 use-avl-loop 옵션에 의존한다. buddy-opt 버전이 너무 오래된 경우, RISC-V lowering은 알 수 없는 pass 또는 옵션으로 인해 중단된다.

튜닝 기준은 VLEN-256의 RISC-V 개발 보드이며, 대조군은 triton-cpu이다.

1.2 백엔드 튜닝 PR #129: 근사 수학, 확장 가능 벡터, matmul 벡터화 (11-26)

출처: PR #129.

다항식 근사는 exp, expm1, log, log2, log1p, tanh, erf, erfc, sin, cos, atan, atan2, asin, acos, cbrt 총 15개 함수를 포함한다.

이전에는 RVV에 벡터 수학 라이브러리가 없어, 이 함수들이 레인별로 libm 호출로 퇴화하여 벡터 레지스터를 활용할 수 없었다.

matmul의 벡터 폭은 고정 4에서 2·VLEN/32로 변경되어, 8개 행 누산기, 행당 두 개의 벡터 레지스터, LMUL 2에 해당한다. PR은 LMUL 4가 오버플로된다고 설명한다.

--lower-vir-to-vector에 use-scalable=true와 use-avl-loop=true가 추가되었다. 잔여 구간은 한 번의 활동 길이 반복으로 마무리하며, 더 이상 반으로 나눈 구간과 스칼라 루프로 분해하지 않는다.

스트라이드 memref.copy는 convert-strided-memref-copy-to-linalg로 변경되어, 동적 형상의 복사는 SCF로 저하되고 FP8 복사는 원래 경로를 유지한다.

1.3 PR #135 여전히 검토 중: 표준 CPU lowering 통합 및 matmul VIR 경유 (11-25 상태)

출처: PR #135.

PR #135의 제목은 “Unify standard CPU lowering and matmul through VIR”이다. 2개 파일을 변경하고 254줄을 추가, 123줄을 삭제했으며, 최근 업데이트는 11-25 16:29 UTC이다.

이 브랜치는 이미 병합된 #129를 포함하고 있으며, main과의 차이는 backend/compiler.py만 남아 있다.

이는 buddy-mlir#1080이 포함된 Buddy 배포판에 의존한다. 병합되면 표준 CPU lowering과 matmul이 통합되어 VIR을 경유하며, 더 이상 두 경로를 유지하지 않는다.

뉴스 페이지 atom 구독의 업데이트 시간은 여전히 11-12입니다.

최신 글은 「openRuyi × 오픈소스의 여름｜테스트 검증 체계를 정비하고 RISC-V 기반 소프트웨어 품질 보장을 공고히 하다」로, 네 가지 기본 컴포넌트의 업스트림 테스트 복구를 다루고 있습니다.

모니터링 기간 내 버전 릴리스나 신규 공지는 없습니다. 11월에도 여전히 월간 버전이 없습니다.

3. 벡터 확장과 연산자 최적화

3.1 B12, B13, B14 세 배치 심사 중에서 병합으로 전환 (11-25)

출처: PR #136. #137과 #138은 부록 [2], [3] 참조.

세 배치는 11-25 10:13부터 10:24까지의 11분 동안 순차적으로 머지되었다.

B12는 55개의 연산자로, 정규화, 통계, 거리와 노름, 히스토그램, 리덕션 및 역전파를 포함한다.

B13은 51개의 연산자로, 인덱스, scatter, embedding, grid sampling, 보간 및 batch-norm 통계를 포함한다.

B14는 41개의 연산자로, 컨볼루션 및 역전파, 풀링과 역풀링, 양자화 풀링, 가중치 재배열 및 희소 인덱스 변환을 포함한다.

B13의 검증은 riscv64 CPU에서 146개 통과, 0개 실패, 0개 스킵으로 실행되었으며, 845개 예제 파일의 SHA256이 매니페스트와 일치한다.

3.2 랜덤, RNN, attention 및 희소, 중첩 텐서 두 배치 머지 (11-25)

출처: PR #139. #140은 부록 [5] 참조.

랜덤, RNN, attention 배치는 50개의 연산자로, 101개 파일을 변경하고 2150줄을 추가했다.

희소 및 중첩 텐서 배치는 48개의 연산자로, 97개 파일을 변경하고 1049줄을 추가했으며, 희소 구성과 인덱스, 중첩 텐서와 반구조화 희소성을 포함한다.

두 배치 모두 __init__.py에서 통합 export되며, 연산자 파일은 더 이상 각자 __all__을 선언하지 않는다.

3.3 VecIntrinBench, IntrinTrans 및 FBGEMM 계속 조용 (11-25 상태)

출처: VecIntrinBench. 나머지 두 저장소는 부록 [26], [27] 참조.

세 저장소의 최근 커밋은 각각 02-13, 06-25, 07-13이며, 모니터링 기간 내 동향은 없다.

벡터 벤치마크와 intrinsic 변환 두 라인은 여전히 정체 상태이다. 연산자 측 작업은 triton의 예제 패키지에 집중되어 있다.

4. Buddy Compiler 동향

4.1 buddy-mlir, VIR 최적화 두 건 머지, masked tile과 matmul 대폭 수정 (11-25 ~ 11-26)

출처: PR #1080. #1085는 부록 [19] 참조.

buddy-mlir 모니터링 기간 내 두 건의 커밋이 있으며, 모두 11-26 새벽이다.

00:07에 #1080「Optimize masked tiles, reductions, and matmul」이 머지되어 23개 파일을 변경하고 3163줄을 추가, 30줄을 삭제했다.

해당 PR은 masked tile 복사 제거, tile 메모리 전달과 마스크 벡터 저장, 리덕션과 matmul 최적화를 보강하고, 수명 주기가 겹치지 않는 작은 블록 스택 슬롯을 재사용한다.

01:20에 #1085「Keep the reassoc of a linalg.reduce combiner」가 머지되어 2개 파일을 변경하고 131줄을 추가, 4줄을 삭제했다.

기존에는 -lower-linalg-to-vir가 vir.reduce를 생성할 때 reassoc을 잃어버려, 순서 무관 리덕션이 순서 있는 vfredosum으로 강등되었다. 해당 PR은 reassocOf()를 보완하여 네 곳의 리덕션 강등 경로에서 통일적으로 사용한다.

4.2 nightly 0.1.9.dev20261125 릴리스, 8개 자산 (11-25)

출처: Release 목록.

나이틀리 버전이 11-25 12:17에 릴리스되었으며, 8개 자산, 릴리스 노트는 비어 있다.

riscv64 휠은 381,521,273바이트, x86_64 휠은 367,049,027바이트이다.

두 개의 LLVM 24.0.0git 사전 빌드 패키지는 각각 1,158,841,744바이트와 953,416,621바이트이며, 모두 tar.zst이다.

이외에 riscv64와 x86_64 설치 패키지가 각각 하나씩, 그리고 두 개의 buddy-cli 단일 파일이 있다.

4.3 PR #1059 머지 없이 종료, memref 복사 벡터 방식 보류 (11-25)

출처: PR #1059.

PR #1059「Copy memrefs with vectors instead of memrefCopy」는 11-26 01:31에 종료되었으며 머지되지 않았다.

4개 파일을 변경하고 216줄을 추가, 17줄을 삭제했다.

PR 자체 설명에 따르면 SpacemiT K3에서 측정한 결과, masked load/store가 생성하는 memrefCopy가 add, exp, softmax 및 matmul 커널 시간의 44%에서 99%를 차지했다.

종료 사유는 페이지에 설명되지 않았다. 같은 시간대에 #1080이 이미 masked tile과 tile 메모리 최적화를 머지했다.

4.4 K3에서의 EmbeddingGemma 300M 튜닝 PR 검토 중 (11-25 상태)

출처: PR #1070.

PR #1070은 여전히 검토 중이며, 주제는 SpacemiT K3에서의 EmbeddingGemma 300M 성능 최적화입니다.

17개 파일 변경, 2196줄 추가, 8줄 삭제, 최근 업데이트는 11-25 22:05입니다.

PR은 9개 워크로드의 1차 데이터를 제시했습니다: F32 RAX 베이스라인 대비 23.24~38.24배 속도 향상, 네이티브 Hugging Face F32 대비 7.11~19.03배 속도 향상.

최대 프로세스 RSS는 RAX 베이스라인 대비 71.6%~93.5% 감소했으며, 81회 측정 모두 임베딩 정밀도 임계값을 통과했습니다.

이 PR은 #835를 이어받아 모델 가져오기, RAX 패키징 및 토크나이저 호환성을 수정했으며, K3의 IME와 RVV를 사용합니다.

AI 스택 측은 이번 모니터링 기간 새로운 변경이 없으며, triton과 buddy 패키지는 이전 호 상태에 머물러 있습니다.
