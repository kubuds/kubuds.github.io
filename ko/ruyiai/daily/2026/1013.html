오늘의 중점: Ztt 툴체인 LLVM 측 최초 푸시와 야간 빌드 폐쇄 루프——ztt-dev 브랜치 26건 반영, triton-riscv 신규 빌드, VS Code 플러그인 이중 기능 병합

날짜: 2026-10-12　출처: ztt-dev 커밋 목록, 헤드 커밋 aeb52e1a, 행렬 레지스터 커밋 836a7ebc, Nightly 2026-10-11-fe554ff, VS Code 플러그인 PR #264, PR #265

Ztt 행렬 확장 방향의 툴체인 배치가 이번 모니터링 기간에 중요한 한 걸음을 내디뎠다: ruyisdk/llvm-project가 10-12 오전에 ztt-dev 브랜치를 새로 만들고 전체 스택 첫 푸시를 완료했다——26개의 LLVM / Clang 패치(작성자 LukeZhuang)가 통일된 커미터 시간(10:05 ~ 10:43)으로 자리 잡았으며, 작성자 날짜는 9월 하순부터 10-10까지 이어져 기존 로컬 개발 스택의 첫 공개 푸시에 해당하고, 헤드는 aeb52e1a “[RISCV] Match Ztt tests to AME diagnostics”이다. 스택은 백엔드부터 프런트엔드까지 아우른다: Ztt 확장 기반 지원과 함수 수준 프로파일(-mzzt-profile, 서브타깃의 프로파일별 격리, 프로파일 간 인라인 억제), CSR과 행렬 레지스터 그룹, 명령어 어셈블과 디스어셈블, IR 타입과 intrinsic 정의, Clang 측 행렬 레지스터 타입과 데이터 스칼라 타입, TableGen과 빌트인 함수 등록, 빌트인 시맨틱 검사, 의사 명령어 테이블과 레지스터 레이아웃 추적, 레지스터 할당 후 의사 명령어 확장, M 레지스터와 ACC의 스필 및 스택 프레임 처리, 마지막 커밋은 테스트를 기존 AME 진단 체계에 정렬한다. GCC 측 riscv-gcc의 ztt-dev 브랜치(09-30 생성, 10-11 단일 배치 51건)에 이어, Ztt 라인은 이번에 LLVM 측을 보완하여 GCC + LLVM 듀얼 백엔드 툴체인 배치를 형성했다; 같은 모니터링 기간 내 문서 측의 attached-matrix-extension Ztt intrinsic 문서 V0.6 PR도 갱신 중이며(3.1 참조), “명세—문서—듀얼 툴체인” 체인이 동시에 활발하다.

Triton 측의 관찰 지점도 같은 날 실현되었다: 야간 채널에서 새 빌드 “Nightly 2026-10-11-fe554ff”(10-12 아침 공개)가 산출되었으며, 빌드 기준은 10-10에 병합된 Buddy MLIR 의존성 업그레이드(PR #84) 이후의 riscv 브랜치 헤드이다——즉 “패치 적응(#86) → 의존성 업그레이드(#84) → 야간 산출물” 체인의 첫 번째 폐루프 산출물이다. 이번 회차는 CPython 3.12 / 3.13 / 3.14 세 가지 버전, x86_64와 riscv64 듀얼 아키텍처 총 6개의 휠(triton 3.8.0 프리픽스 패키지)을 제공하며, 이전 회차는 여전히 “Nightly 2026-10-04-12c2f6a”였다. 이로써 의존성 업그레이드 검증이 “빌드 통과”에서 “산출물 사용 가능” 단계로 전환되었고, 향후 관찰 지점은 riscv64 휠의 디바이스 측 실측 피드백이다.

스택 동기화의 두 액션 라인도 계속 추진된다: LLVM fork의 riscv 브랜치가 또 한 차례 야간 리플레이를 완료했고(26개의 로컬 패치가 새 커미터 시간으로 전체 재배치, 헤드 0fb2da86은 여전히 #31), PyTorch fork의 riscv 브랜치가 또 한 차례 전체 스택 재빌드를 완료했다(23건 재배치, 헤드가 6ff4eefe로 갱신, 최근 일주일간 매일 아침 한 번 푸시하는 리듬 유지). 도구 측에서는 두 가지 체험 특성이 확정되었다: VS Code 플러그인 #264 “패키지 설치 오류를 내부 상세로 이동”과 #265 “패키지 인덱스 새로 고침에 오류 보고 추가”가 10-12 오후에 연이어 병합되었다——전자는 장황한 설치 오류를 대화 상자에서 “View Details” 문서 뷰로 이동시켰고, 후자는 실패할 수 있는 패키지 인덱스 새로 고침에 오류 가시성을 보강하여, 플러그인 측의 오류 진단 경로가 점진적으로 제품화되고 있다.

riscv 브랜치는 10-12 오전(09:02)에 또 한 차례 전체 스택 재구축을 완료하고 푸시했다: 23건의 로컬 커밋이 새로운 커미터 시간(10-12 새벽)으로 일괄 재적용되었으며, 헤드는 6ff4eefe「[SyncBots] Integrate PyTorch at e188cec」로 갱신되었고, 그 아래에는 기존 순서대로 배열된 로컬 패치(#44 bytes_to_scalar 수정, #50 차단 목록 확장, #42 ULP 허용 오차, 세 건의 SyncBots 통합, #40 / #41 CI 파싱, #20 / #21 CI 분리, #18 cpuinfo 교체, #12 커밋 해시 고정, #11 / #4 / #1 차단 목록 시리즈 등)가 배치되어 있으며, 베이스는 10-11 저녁의 업스트림 커밋을 포함한다. 이번 회차는 최근 일주일간 매일 아침 1회 푸시 리듬의 연장이다(10-06부터 연속 확인 가능). 재구축 후 오픈 PR 측 8건(#23 Enable XNNPACK, #35 테스트용 PR, #36 타임아웃 완화, #38 DataLoader 임시 비활성화, #43 패치 간소화, #46 ATen RVV 지원, #48 RVV CPU capability, #51 riscv64 로컬 이미지)이 같은 날 같은 시각(09:02)에 베이스를 일괄 갱신했으며, 전부 오픈 상태를 유지했고 모니터링 기간 내 머지와 클로즈는 없었다. main 브랜치는 모니터링 기간 내 업스트림 커밋 42건을 동기화했다(inductor, CUDA, CI 등 일반 변경 포함, 필터링 규칙에 따라 개별 수록하지 않음).

Google News에서 RuyiSDK, RuyiAI, openRuyi 및 「루이 RISC-V」에 대한 중영문 다중 쿼리 모니터링 기간 내 관련 히트 제로(동기 RISC-V 범용 쿼리는 정상 반환, 채널 이상 없음). arXiv(RISC-V 및 컴파일, 벡터, 추론 방향) 모니터링 기간 내 신규 수록 없음(최근 관련 항목은 10-05 ~ 10-07의 장벡터 레지스터 저장(SVRF), 엣지 AI Transformer 추론 가속 프레임워크 등, 모두 모니터링 기간 이전). openRuyi 배포판 뉴스 페이지 신규 문서 없음(2026.09 릴리스 공지가 여전히 최신); RuyiAI 공식 웹사이트와 블로그 신규 문서 없음.

5. 트렌드 관찰

5.1 Ztt 라인 LLVM 측 보완: 매트릭스 확장 툴체인 이중 백엔드 단계 진입

Ztt(RISC-V 매트릭스 확장 방향 초안)는 이전에 GCC 백엔드(riscv-gcc ztt-dev) 단일 라인으로 추진되었으나, 본 모니터링 기간 LLVM / Clang 측 ztt-dev가 ruyisdk/llvm-project에 착지(26건 최초 푸시), 이중 백엔드 구도 형성; attached-matrix-extension의 intrinsic 문서 V0.6 갱신과 겹쳐 「규범—문서—이중 툴체인」삼환 동기화에 실질적 진전. 관찰 포인트: 양측 스택의 공개 리뷰 경로(GCC 측 PR 병합 리듬, LLVM 신규 브랜치의 후속 푸시와 업스트림화 경로), 그리고 riscv-binutils 측 ztt-dev의 추종 여부(현재 09-30에 정체).

5.2 정례 재빌드 안정적 리듬 진입: LLVM 매일 밤 리플레이, PyTorch 매일 아침 재빌드

LLVM fork의 riscv 브랜치가 또 한 라운드 야간 리플레이 완료(26건, 이전 라운드들과 스택 구성 일치), PyTorch fork의 riscv 브랜치가 연속으로 또 한 라운드 전체 스택 재빌드 완료(23건, 헤드 6ff4eefe로 갱신), 둘 모두 「커미터 시간 집중, 작성자 날짜 모니터링 기간 이전」의 정례적 재착지——업스트림 추종 메커니즘 이미 일상화(PyTorch 최근 일주일 매일 아침 1회 푸시). 이러한 재빌드는 스택과 업스트림 동일 베이스라인을 보장, 실제 콘텐츠 진전은 여전히 열린 PR의 리뷰 효율에 달림(PyTorch 8건, LLVM FPGA 2건 모두 열린 상태 유지).

5.3 의존성 업그레이드 검증 산출물 단계 진입: 야간 빌드 최초로 업그레이드 후 코드 기반

triton-riscv 신규 야간 빌드(Nightly 2026-10-11-fe554ff)는 Buddy MLIR 의존성 업그레이드(#84) 병합 후 첫 야간 산출물, 「패치 적응(#86) → 의존성 업그레이드(#84) → 빌드 산출」체인 폐합. 관찰 포인트는 이로써 riscv64 휠의 디바이스 측 실측 피드백, 그리고 커뮤니티 최적화 PR #85(softmax와 matmul 경로)의 리뷰 진행으로 전환.

5.4 운영과 도구 측 병진: 격주 리포트 편찬, IDE 경험 다듬기, 지원 매트릭스 리뷰

격주 리포트 078 편찬 추진(기초 C 라이브러리 / V8 / 지원 매트릭스 장절 통합), VS Code 플러그인 오류 경험 2연발(#264 / #265 병합), 지원 매트릭스 두 보고서 심사 중——생태 운영과 도구 제품화가 일일 갱신 리듬 외에 동시 추진; ruyici의 macOS 빌드 지원과 ruyi-tuner의 aarch64 지원은 빌드와 튜닝 도구가 크로스 플랫폼, 크로스 아키텍처 배치를 시작했음을 보여줌.
