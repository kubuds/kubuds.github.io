1. 오픈소스 커뮤니티와 소프트웨어 생태계

1.1 Canonical, 엔터프라이즈급 오픈소스 RISC-V 소프트웨어 준비도 상세 설명: Ubuntu riscv64 패키지 통과율 55.1%(09-07)

날짜: 2026-09-07(ServeTheHome 월요일 게재, 모니터링 기간 진입 시각 09-08 01:00 베이징 시간)　출처: ServeTheHome

ServeTheHome가 Hot Chips 2026 발표 실록을 추가 게재: Canonical 실리콘밸리 협력 총괄 Gordan Markus가 Ubuntu의 다중 아키텍처 빌드 메커니즘과 RISC-V 엔터프라이즈급 준비 경로를 체계적으로 설명하고, 정량적 격차 데이터를 제시했다——Ubuntu 26.10 테스트 스냅샷에서 riscv64 총 3,443개 소프트웨어 패키지가 테스트를 받아 1,898개가 통과, 통과율 약 55.1%로 amd64의 약 92%에 훨씬 못 미친다. Canonical은 격차의 일부를 에뮬레이션 빌드와 테스트 목표(실행 시간이 수 시간에서 수일로 늘어남)에 기인한다고 보고, 이미 네이티브 RISC-V 빌드 머신을 도입했으며 파트너가 서버급 RVA23 플랫폼 지원을 제공한다. 오픈소스 협업 측면: Canonical은 RISC-V International의 RISE 프로젝트(모바일, 소비자 전자, 데이터센터와 자동차를 위한 상용 소프트웨어 준비 지향)에 참여하고 있으며, Ubuntu 24.04 네이티브 RISC-V runner가 Scaleway Elastic Metal에 호스팅된 빌드와 보드 팜을 지원하고, Alibaba와 SpacemiT 하드웨어를 사용해 누적 116개 조직, 24,000개 작업과 70만 분 빌드량을 기록했다. Canonical의 핵심 판단은: RVA23 스타일 프로파일이 소프트웨어 목표를 예측 가능하게 만들고, 대규모 업스트림 협업과 결합하면 새로운 ISA 오픈소스 채택을 늦추는 역사적 “소프트웨어 준비 격차”를 넘어설 수 있다는 것이다. 향후 2년간 서버급 RVA23 하드웨어가 속속 갖춰지면 소프트웨어 스택에 고정된 수렴 목표가 생긴다. 이는 모니터링 기간 내 엔터프라이즈급 RISC-V 소프트웨어 생태계에 가장 데이터 가치가 높은 항목이다.

1.2 XiangShan: 신규 벡터 백엔드 vfma 경로 재구성 및 광폭 명령어 지원 배치 반영(09-07)

날짜: 2026-09-07(16:19~17:33 베이징 시간 배치)　출처: GitHub openxiangshan/XiangShan commits

샹산 오픈소스 고성능 코어(쿤밍후) 벡터 백엔드 리팩터링 지속 추진: 09-07 오후 배치에서 feat(vfma) “support vfma in new vector backend”, feat(vector, vfmac) pipeline 레지스터 리팩터링 및 widen 명령어 지원, fix(vector) vfma pipe metadata 초기화가 병합되며, 새로운 벡터 백엔드 실행 경로가 전체 레지스터 이동(전일 배치)에서 부동소수점 곱셈-덧셈(vfma/vfmac)과 확장 연산으로 확대되었음을 표시한다. 같은 배치에는 bypass 준비 및 비레지스터 소스 수정, LoadQueueReplay 비정렬 head 지연 웨이크업 처리, ROD 인코딩 정렬 수정(#6509)과 FFlagsWen 테이블에 VFREC7_V/VFRSQRT7_V 추가도 포함된다. 지난 며칠간의 vialu/mgu 연결 및 벡터 폭 증감 명령어 지원과 결합해 볼 때, 샹산 벡터 실행 서브시스템 리팩터링이 “명령어 기능 보완—경로 데이터 흐름 수정—부동소수점 행렬 연산 접속” 순서로 추진되고 있으며 엔지니어링 성숙도가 지속적으로 향상되고 있음을 판단할 수 있다. 본 모니터링 기간 내 릴리스는 없었다.

1.3 CVA6: 수정 범위가 RV32/64 명령어 적법성으로 확대, 가상화와 메모리 보호 지속 다듬기(09-07~08)

날짜: 2026-09-07 20:18 ~ 09-08 05:36(베이징 시간, 9개 커밋)　출처: GitHub openhwgroup/cva6 commits

OpenHW Group의 애플리케이션급 오픈소스 코어 CVA6는 모니터링 기간 내 계속해서 수정 사항을 대량 병합했으며, 커버 범위가 전일보다 더욱 확대되었다. 명령어 의미론적 적법성 차원이 새로 추가되었다——zip/unzip은 RV32에서만 적법하고 RV64에서는 불법으로 디코딩되어야 하며(#3527), RV64 전용 FCVT의 RV32에서의 불법 사용을 거부하고(#3540), mstatus.MPP가 RVH=1일 때 예약 값 2’b10에 대한 적법화를 처리한다. 가상화와 메모리 보호 경로는 전일 주제를 이어간다——ptw에서 HLVX 규칙이 VS-stage PTE 읽기에 적용되지 않는 G-stage 검사 수정, PMPADDR63 범위 초과 접근 수정(#3485)이다. 또한 C 확장 비활성화 시 misaligned branch 회귀 테스트(#3424), 가짜 4 KiB 앨리어스 회귀 테스트(#3453)와 debug 루프 공유 포인터 범위 초과 수정도 보완되었다. 이틀 연속 합계 15개 이상의 커밋으로, 가상화 2단계 주소 변환과 PMP 보안 경로의 다듬기가 고빈도 시기에 접어들었으며, 이는 RISC-V 오픈소스 애플리케이션 코어 품질 유지보수 리듬의 관찰 신호로 삼을 수 있다.

2. 제품 및 생태계 동향

2.1 YuzukiHD, YuzukiNeko 오픈소스: Allwinner F101(다모서원 셴톄 C907) Pico 사이즈 Linux 보드(09-08)

날짜: 2026-09-08　출처: CNX Software, YuzukiHD/YuzukiNeko GitHub

오픈소스 하드웨어 팀 YuzukiHD가 새 보드 YuzukiNeko를 발표했다. Raspberry Pi Pico 사이즈(약 51 x 21 mm)의 Linux 단일 보드 컴퓨터로, Allwinner의 신형 SoC Allwinner F101 “지능형 제어 및 디스플레이 프로세서”를 탑재했다. F101은 단일 코어 다모서원 셴톄 C907 RISC-V 코어(1.008 GHz, 32 KB I-cache + 16 KB D-cache)를 채택했으며, QFN-68 패키지, SiP 통합 8 MB(F101S2) 또는 16 MB(F101S3) PSRAM(252 MHz), 통합 디스플레이 엔진(RGB888 720p, 단일 링크 LVDS 1366x768, 4채널 MIPI DSI 1280x800), 대형 JPEG/PNG 디코딩, USB 2.0 DRD와 512 bit eFuse를 갖췄다. 보드에는 128 Mbit SPI NOR + microSD, USB-C(데이터/전원/플래싱), 듀얼 20-pin GPIO 확장 핀 헤더와 FEL 버튼이 있다. 소프트웨어 측면에서 YuzukiHD는 이미 GitHub에 회로도, EasyEDA 프로젝트, Gerber, 3D STEP과 BOM을 오픈소스로 공개했으며, mainline Linux 7.2 기반 sun252i_f101 브랜치, Buildroot 외부 트리 및 Zephyr RTOS 지원(Linux와 Zephyr 듀얼 시스템)을 제공한다. Whycan 포럼 소식에 따르면 F101 SoC 단가는 약 18 위안(약 2.7 달러)이며, 커뮤니티는 완제품 보드 판매가가 10 달러 이하가 될 것으로 예상한다. 보드는 아직 판매되지 않았다. 의의: 다모서원 셴톄 C907은 D1 계열(C906)에 이어 다시 한번 본토 SoC에 대규모 저비용으로 채택되었으며, 초저가 “Linux/Zephyr 듀얼 시스템” RISC-V 마이크로 보드 생태계가 더욱 확장될 전망이다.

3. 국내 팀 동향 및 심층 분석

3.1 Alibaba DAMO XUANTIE-RV: priv-ATS에 Hypervisor 테스트 추가, XTheadCmo 규격 dcache 연산 범위 강화 (09-07)

날짜: 2026-09-07(14:29~22:55 베이징 시간)　출처: XUANTIE-RV/damo-rv-priv-ats commits, XUANTIE-RV/thead-extension-spec commits

Alibaba DAMO XUANTIE의 공개 저장소가 월요일의 조용한 기간을 지나 반복 개발을 재개했으며, 모니터링 기간 내 두 저장소에서 총 4개의 커밋이 발생했다. 특권 아키텍처 저장소 damo-rv-priv-ats는 09-07 22:55에 “add Hypervisor_Za* tests”(#27)를 병합하여 hypervisor 모드의 원자 명령(Za* 계열)에 대한 테스트를 추가했다. 확장 규격 저장소 thead-extension-spec는 14:29~14:48에 PR #77(XTheadCmo 확장)을 병합했다. clean set/way 연산과 th.dcache.isw 명령 범위를 L1 D-cache로 강화하여, 해당 캐시 관리 연산 확장이 L1 시맨틱에만 적용됨을 명확히 했다. 두 동향 모두 규격 세분화와 테스트 보강 성격으로, “확장 정의—테스트 검증”의 일상적인 리듬에 해당하며 새로운 등급의 신호는 없다. 참고: 해외 매체에서 09-07에 여전히 Geeky Gadgets 등이 “C950 GPU 없이 Qwen 3.8 실행”(제목에 Reportedly 포함)을 전재했으나, 확인 결과 08-18 Day 0 적응 공식 발표(본 리포트 08-19/20에서 상세 보도)의 지연된 메아리로 새로운 이벤트가 아니므로 별도 항목으로 기재하지 않는다.

3.2 종합 모니터링 기간 관찰: Sophgo/SpacemiT/Sipeed 일상적 반복 개발, 뉴스 측 중국 팀 전반 조용 (09-07/08)

날짜: 2026-09-07/08　출처: sophgo/zsbl, spacemit-com/docs-chip, sipeed/NanoKVM-Pro, spacemit-com/linux, spacemit-com/onnxruntime 등 commits API

중국 팀의 GitHub 측은 화요일 전반적으로 일상적 반복 개발을 재개했으며, 모두 일반 개발로 릴리스급 동향은 없다. Sophgo의 zsbl 제로 레벨 부트 도구는 09-07 16:13~19:47에 xmodem 명령, 시리얼 속도 설정 명령(console speed), console 표시점 후방 이동, libc strncpy 제로 패딩 수정을 병합했으며, 이는 부트 디버깅 도구 체인 정비에 해당한다. SpacemiT의 docs-chip은 17:17~17:50에 K3 UART 레지스터 베이스 주소 설명과 개정 이력을 업데이트하고 P3 문서 내부 앵커를 수정했으며(순수 문서 유지보수), linux와 onnxruntime 저장소에는 pushed 신호가 있었으나 기본 브랜치의 모니터링 기간 내 새로운 커밋은 보이지 않았다(비기본 브랜치/태그 푸시로 추정, 심층 조사하지 않음). Sipeed의 NanoKVM-Pro는 18:07~19:29에 가상 키보드 충돌 수정(#148), Flask-SocketIO 5.6.1 업그레이드, 사용자 정의 업데이트 소스/수동 업데이트 기능(#145)을 병합했으며, KVM-over-IP 제품 소프트웨어가 지속적으로 발전하고 있다. 뉴스 측 확인: 중국어 검색어 “XUANTIE/DAMO/Sophgo/SpacemiT/Nuclei/XiangShan”은 대부분 시맨틱 노이즈(Xiaomi “XRING” 칩은 다른 브랜드, Sophgo는 “컴퓨팅-전력 협조” 그린 컴퓨팅 파이낸스 기사에 매칭, Nuclei는 Yuexin/Huawei 등 범용 “칩” 콘텐츠에 매칭)이거나 모니터링 기간 외 구뉴스(SpacemiT는 AGIC 마감 09-03에서 이미 보도)였다. “Nuclei” 테마의 09-04 EE Times China “로봇 오리 판매 폭발, Rockchip 상한가”는 이미 보도된 메아리에 해당한다. 결론: 중국 팀의 뉴스 측에는 새로운 증분이 없으며, 실질적 동향은 여전히 GitHub 커밋이 주를 이룬다.

4. Embodied AI와 로봇 특별 장

4.1 모니터링 기간 관찰: 새로운 동향 없음, 09-09 Shenzhen IICIE Embodied AI 산업 대회 내일 개막 (09-07/08)

날짜: 2026-09-07/08

본 모니터링 기간 RISC-V Embodied AI/로봇 방향에는 새로운 제품 발표와 중대 이벤트가 없다. 보충 검색 “Embodied AI RISC-V when:7d”의 결과는 모두 모니터링 기간 외 사전 예열과 범산업 콘텐츠(09-02 EE Times China Shenzhen 3전시 연동 예열, 09-05 Fudan MBA Zhangjiang Robot Valley 방문 등)로 실질적 새 항목이 없다. 관찰 포인트는 변함없이 유지된다: 09-09부터 Shenzhen IICIE 국제 집적회로 혁신 박람회(14호관 RISC-V 산업 생태계 혁신 대회, 15호관 2026 Embodied AI 산업 대회)가 개막하며, 스마트카 x Embodied Robot 3전시 연동(09-09~11)과 함께 Alibaba DAMO XUANTIE/Sophgo/SpacemiT 등이 참가하여, 내일부터 중국 RISC-V x Embodied 동향의 실현 관찰 기간에 진입한다.

5. 요약 및 트렌드 관찰

이 보고서의 모니터링 기간은 일반 활성일(조용한 날 아님)이다: 오픈소스 커뮤니티 측에서는 엔터프라이즈급 준비도 정량화 보도 1건과 두 오픈소스 코어의 지속적 커밋이 있었고, 제품 측에서는 XuanTie 코어의 저비용 채택 하드웨어 항목 1건이 있었으며, 국내 팀은 GitHub에서 반복을 재개했으나 뉴스 측은 조용했다. 요점을 정리하면 다음과 같다.

첫째, 엔터프라이즈급 소프트웨어 준비도가 “정량적 검수 가능” 단계에 진입했다. Canonical은 Hot Chips 추가 발표에서 riscv64 패키지 통과율 55.1% 대 amd64 92%의 정량적 격차를 공개하고, 그 원인을 명확히 에뮬레이션 빌드 병목으로 지목했으며, 해결책은 네이티브 빌드 머신에 RVA23 profile 수렴을 더하는 것이다——RISC-V 서버 소프트웨어 서사는 “돌아간다”에서 “검수 가능하다”로 전환 중이며, RISE 프로젝트와 24,000 태스크급 빌드 팜의 존재는 업스트림 투입이 이미 규모를 갖추었음을 보여준다.

둘째, 오픈소스 코어 리팩터링이라는 주된 흐름이 이어진다. XiangShan의 새 벡터 백엔드는 전체 레지스터 이동(09-06)에서 vfma/vfmac 부동소수점 곱셈-덧셈과 widen 명령어(09-07)로 진전했으며, 실행 경로 기능 보완 리듬이 명확하다. CVA6는 이틀 연속 15+ 수정을 진행했고, 적용 범위가 가상화/PMP에서 RV32/64 명령어 적법성으로 확장되어, 다중 아키텍처 의미 정확성 다듬기가 새로운 관전 포인트가 되었다.

셋째, Damo Academy XuanTie 생태계의 “상향 탐색과 하향 침투” 양방향 확장. 상향 탐색 측면에서는 C950이 GPU 없이 Qwen 3.8을 구동한 8월 공식 발표가 여전히 해외 매체에서 뒤늦은 메아리를 형성하고 있어, 서사 전파 주기가 끝나지 않았음을 보여준다. 하향 침투 측면에서는 C907이 18위안급 Allwinner F101 SoC에 진입했고, YuzukiHD 오픈소스 보드와 Linux/Zephyr 듀얼 시스템 지원과 맞물려, XuanTie 코어 라이선스의 초저가 마이크로 보드 시장 적용 범위가 계속 확대되고 있다.

넷째, 전방 모니터링 창: 09-09 선전 IICIE 개막, 같은 시기 RISC-V 산업 생태 혁신 대회와 구현 지능 산업 대회(14/15호관), 여기에 3개 전시 연동의 스마트 자동차와 로봇 테마가 겹쳐, 이번 주 중반 국내 RISC-V 동향은 뚜렷하게 회복될 것으로 예상되며, 내일 보고서에서 중점 추적할 것이다.

한계 설명: GitHub 미인증 API 속도 제한(60 req/h) 상황에서 org 점검은 pushed_at 정렬로 최근 활성 저장소를 표본 점검했으며, spacemit-com의 비기본 브랜치 푸시, 저활성 저장소 커밋은 누락될 수 있다. XiangShan/CVA6/각 벤더 커밋 내용은 커밋 message 제목만 근거로 판단했고 코드 세부 사항을 일일이 대조하지 않았다. Canonical 통과율과 빌드 팜 데이터는 ServeTheHome 발표 실록에서 전재한 것으로, Ubuntu 공식 독립 데이터로 교차 검증되지 않았다.
