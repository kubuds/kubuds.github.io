오늘의 핵심: 차량용 RISC-V, 이번엔 툴체인 차례 — HighTec과 TASKING, 같은 날 AURIX RC1 지원 발표(11-10)

Infineon AURIX RC1이 11월 4일 발표되고, 11월 9일 RISC-V 코어가 MIPS IP에서 왔음이 확인된 데 이어, 11월 10일에는 세 번째 단계인 툴체인으로 진입했다. 유럽의 차량용 소프트웨어 툴 기업 두 곳이 같은 날 지원 성명을 발표했는데, 마침 뮌헨 electronica 2026 개막 첫날(11월 10~13일)에 맞춰진 것이다.

HighTec EDV-Systeme의 발표는 매우 구체적이다. RISC-V용 Embedded AI, Rust 및 C/C++ 개발 플랫폼이 이미 RC1을 지원하며, 방식은 RC1의 디바이스 관련 컴파일 옵션을 동일한 멀티 아키텍처 컴파일러에 통합하고, Infineon과 협력해 파이프라인과 코드 크기에 특화된 최적화를 추가한 것이다. 이 노선의 독특한 점은 언어 커버리지에 있다. 안전 및 정보 보안 인증을 받은 C/C++와 Rust 툴체인을 동시에 제공하고, RC1용 임베디드 AI 개발 플랫폼 출시도 계획하고 있다. 지원 범위도 자연스럽게 AURIX에서 TRAVEO와 PSOC로 확대되는데, 이는 Infineon이 기존 두 제품 라인을 합병해 형성한 전체 MCU 제품군이다. HighTec은 동시에 DRIVECORE RISC-V 가상 프로토타입 번들의 참여사이기도 하다. 이 번들에는 Synopsys VDK, Lauterbach TRACE32, HighTec의 RISC-V C/C++ 플랫폼과 주변장치 드라이버가 포함되며, FreeRTOS 구현과 공동 시뮬레이션 예제도 갖추고 있다. 칩이 오기 전에 소프트웨어가 먼저 달린다는 것은 차량용 프로젝트의 통상적인 리듬이다.

TASKING의 접근 방식은 전체 라이프사이클을 하나의 툴 세트에 담는 것입니다. 컴파일에는 VX-toolset, 디버깅에는 winIDEA와 BlueBox, 검증에는 LDRA를 연결하고, 툴체인에 Agentic AI를 내장합니다. 일정은 명확합니다. RC1을 지원하는 VX-toolset for RISC-V는 2026년 12월에 사용 가능하며, 툴체인 인증 계획은 2027년입니다. AI 부분은 두 곳에 적용됩니다. 12월 버전은 TASKING의 툴체인 지식(빌드, 진단, map 파일과 LSL 분석, 부트 코드)을 MCP를 통해 VS Code 환경에 연결하며, 이미 인증된 툴 자체는 변경되지 않습니다. 디버깅 측 winIDEA AI Kit는 세 가지 사용 사례에서 최소 50%의 작업량 감소를 이미 보여주었습니다. 마이그레이션 중인 팀에게 판매 포인트는 「아키텍처를 바꿔도 툴체인은 바꾸지 않는다」입니다. TriCore에서 이전하는 팀은 기존 CI/CD와 경험을 유지하고, Arm에서 이전하는 팀은 동일한 툴 세트로 두 아키텍처를 커버합니다.

사흘간의 소식을 연결해 보면, 차량용 RISC-V의 추진 순서는 IP, 실리콘, 툴체인, 인증이며, 네 단계 각각에 명확한 외부 신호가 있습니다. 11-09는 IP 출처(MIPS, GlobalFoundries 파운드리), 11-04는 제품 정의(최대 12코어, 40MB 스토리지, ASIL D, 2027년 상반기 샘플 출하), 11-10은 툴체인 가용성(12월 컴파일러 출시, 2027년 인증)입니다. 두 툴 업체가 제시한 인증 시점이 Infineon의 샘플 출하 시점과 정렬된다는 것은 이 일정이 각자 다른 말을 하는 것이 아님을 보여줍니다. 국내에서 차량용 RISC-V를 하는 팀에게 이번 라운드에서 주목할 점은 컴파일러 공급업체가 두 곳 더 늘었다는 것이 아니라, 「인증 시간표」가 고객 질문의 표준 형식이 되고 있다는 것입니다.

1. 오픈소스 커뮤니티와 소프트웨어 생태계

RevyOS 커널, 한 번에 여섯 건 반영: K3, K1, DP1000, EIC7700 네 플랫폼 설정 트리에 반영(11-10)

RevyOS의 linux 저장소(revyos/7.3.y 브랜치)가 모니터링 기간 말미에 설정 커밋 여섯 건을 한꺼번에 반영했습니다. SpacemiT K3 지원 활성화, SpacemiT K1 지원 활성화, UltraRISC DP1000 지원 활성화, ESWIN EIC7700 지원 활성화, 그리고 linuxboot 설정과 CI의 크로스/네이티브 빌드 작업이 추가되었습니다. 여섯 건의 커밋은 동일 저자, 동일 타임스탬프로, 점진적 개발이 아닌 플랫폼 매트릭스의 일괄 마무리입니다.

설정을 트리에 반영하는 것의 의미는 「부팅 가능」을 「기본으로 컴파일 가능」으로 바꾸는 데 있습니다. 이 네 플랫폼은 세 업체에 속합니다. Spacemit의 K1과 차세대 K3, UltraRISC의 DP1000, ESWIN의 EIC7700으로, 현재 국내 RISC-V 개발 보드와 산업용 제어 보드에서 가장 많이 쓰이는 SoC들을 정확히 커버합니다. linuxboot 설정과 CI 이중 빌드가 함께 반영된 것은 이 배포판이 단순히 돌아가는 한 대의 머신을 유지하는 것이 아니라 「재현 가능한 빌드」로 나아가고 있음을 보여줍니다.

날짜: 2026-11-10　출처: revyos/linux

openRuyi 메인 저장소, 보안 수정 배치로 전환: policycoreutils 3.11로 업그레이드, cups/lxc/libmtp 업스트림 패치 반영(11-10)

openRuyi 메인 저장소는 모니터링 기간 동안 작업 중심이 버전 업그레이드에서 보안으로 전환되었습니다. policycoreutils를 3.11로 올리고 fixfiles 수정을 반영했으며, lxc, libmtp, cups 세 패키지는 각각 업스트림 보안 패치를 반영했습니다(커밋 모두 security-fixes 태그 포함). libssh는 0.12.2로, llvm-snapshot은 20261109 스냅샷으로 따라갔습니다.

이는 전날 해당 저장소의 20건 「일상적 롤링 업그레이드」와 대조됩니다. 하루는 기능 버전, 하루는 보안 반영을 하는 것은 롤링 배포판의 전형적인 리듬 전환입니다. cups와 lxc는 데스크톱과 컨테이너 두 가지 주요 경로에 속하고, libmtp는 모바일 기기 마운트에 영향을 줍니다. 이 세 패키지의 반영은 버전 번호 변화보다 실제 사용자에게 더 큰 의미가 있습니다. 보안 수정이 메인라인에 들어가지 않으면 배포판은 「프로덕션 사용 가능」이라는 설득력을 갖지 못합니다.

날짜: 2026-11-10　출처: openRuyi-Project/openRuyi

NEMU, riscv64의 SIP 쓰기 래치 타이머 인터럽트 수정, AME는 CRC32C로 행렬 완료 해시 계산으로 변경(11-10)

샹산의 NEMU 시뮬레이터가 모니터링 기간 내에 방향이 반대인 두 건의 커밋을 병합했다. 한 건은 정확성 수정으로, riscv64 측에서 SIP(감독자 레벨 인터럽트 펜딩 레지스터)에 대한 쓰기가 타이머 인터럽트를 래치시키는 것을 차단한다(#1242). 이는 인터럽트 가상화 경로상의 세부 오류로, SIP 쓰기가 소프트웨어 트리거 인터럽트의 소스로 취급되어서는 안 된다는 것이다. 다른 한 건은 성능 최적화로, AME(행렬 확장)가 CRC32C를 사용해 행렬 완료 해시를 계산하도록 변경했으며(#1280), 이전 #1275의 hosttlb 행렬 접근 공유 최적화와 함께 적용된다.

시뮬레이터에서 이 두 유형의 커밋이 동시에 나타난다는 것은 행렬 확장 소프트웨어 스택이 진지하게 다듬어지고 있음을 보여준다. 한쪽에서는 특권 상태 의미론을 수정하고, 다른 쪽에서는 검증 및 캐시 경로의 오버헤드를 낮추고 있다. RISC-V 행렬/벡터 확장 평가를 하는 팀에게 NEMU의 AME 구현은 현재 전체 소프트웨어 스택을 구동할 수 있는 소수의 오픈소스 참고 구현 중 하나이며, 이런 커밋은 벤치마크 점수보다 성숙도를 더 잘 보여준다.

날짜: 2026-11-10　출처: OpenXiangShan/NEMU

2. 제품 및 생태계 동향

riscv100.top 순위 페이지 개편: 전체 표를 「아키텍처 카드 + 종합 순위」로 교체 (11-10)

riscv100.top의 순위 페이지가 모니터링 기간 내에 개편되었다. 기존에 행 단위로 모든 성적을 나열하던 표는 더 이상 페이지 소스에 나타나지 않고, 「각 아키텍처당 1위 카드 1장 + Overall Ranking 종합 목록」 구조로 바뀌었다. 카드에는 플랫폼, 컴파일러, Ratio/GHz, Run rank, Tests, Run date가 제시되며, 종합 목록은 각 플랫폼의 최고 기록 한 줄만 유지한다. 크로스 아키텍처 SPEC CPU2006을 예로 들면, 카드는 각각 AWS EC2 Graviton5(GCC 15.1.0, 24.91), 샹산 KMHv3 RTL(XSCC 2.0, 22.80, NEW 표시 포함, 기록 날짜 2026-10-17), AMD Ryzen 9 9950X(GCC 15.1.0, 17.72)에 대응한다. RISC-V 측은 종합 목록에 진디에 K3 X100(XSCC 1.1, 8.54)과 이텐 710(XSCC 1.1, 17.69)을 별도로 나열한다. 홈페이지 What’s New에는 현재 6개 항목이 있으며, SpaceMiT K3 X100 XSCC 1.1 SPEC CPU2006, SpaceMiT K3 X100 Version Progress Now Available, Run Comparison Now Available 등이 포함된다.

개편의 직접적 영향은 「역대 전체 성적」을 더 이상 페이지에서 직접 얻을 수 없게 되어, 데일리 리포트 측의 기존 표 파싱이 무효화되었다는 점이다. 이번 호에서는 이를 근거로 어떤 신규 진입이나 순위 이탈도 판정하지 않는다. 사이트가 같은 개편에서 페이지 구조와 스냅샷 기준선을 동시에 갱신했기 때문에, 이런 변화는 「성적 변동」과 「표시 축소」를 구분할 수 없다. 독자를 위한 실용적 조언은 다음과 같다. 구체적 점수가 필요하면 카드와 종합 목록에서 읽고, 역사적 추세가 필요하면 사이트의 Version Progress와 Run Comparison 두 블록을 이용하라.

날짜: 2026-11-10　출처: riscv100.top 크로스 아키텍처 SPEC CPU2006, riscv100.top 홈페이지

RISC-V Day Tokyo 2026 Autumn 오늘 도쿄대학교에서 개막 (11-11)

RISC-V 협회(일본)가 주최하는 RISC-V Day Tokyo 2026 Autumn이 11월 11일 도쿄대학교 혼고 캠퍼스에서 개최되며, 약 400명이 참가할 것으로 예상된다. 오전 일정은 칩 설계 튜토리얼, 오후는 기술 발표와 부스로 진행된다. 제임스타운 재단, 중국 RISC-V 노선 평가: 전략이 역량에 앞선다 (11-10)

미국 싱크탱크 제임스타운 재단이 11월 10일 중국의 RISC-V 추진 상황을 평가하는 글을 게재했으며, 저자는 Sunny Cheung이다. 글은 검증 가능한 몇 가지 사실 단서를 제시한다. 진디에스페이스와 샹산 팀이 10월 19일 제6회 RISC-V 중국 서밋에서 46코어 서버 칩 V100을 발표하며, RISC-V 서버 표준을 완전히 준수하는 최초의 범용 칩이라고 주장했다. 9월에 발표된 《전자정보제조업 「15차 5개년」 규획》은 RISC-V 연구개발과 산업화 추진, 인공지능을 겨냥한 RISC-V 칩 발전을 제시했으며, 이전에는 국가급 정책 문서에서 이 명령어 집합을 직접 지목하는 경우가 드물었다.

5. 요약 및 동향 관찰

1. 차량 규격의 경쟁점은 이미 툴체인과 인증 시점으로 이동했다. AURIX RC1의 사흘간 세 단계 — 11-04 제품 정의, 11-09 IP 출처, 11-10 툴체인 지원 — 는 차량 규격 RISC-V의 추진 순서를 매우 명확히 보여준다: 칩 제조사가 플랫폼을 정의하고, IP 제조사가 코어를 공급하고, 툴 제조사가 컴파일과 디버깅을 제공하고, 마지막으로 인증이다. HighTec과 TASKING이 제시한 “12월 툴 사용 가능, 2027 인증”과 Infineon의 “2027 상반기 샘플 출하”는 정확히 맞물려 있으며, 이 일정이 협력하여 조율되었음을 보여준다. 국내 차량 규격 팀이 이후 받을 질문은 아마도 “RISC-V 코어가 있느냐”가 아니라 “툴체인이 언제 인증을 통과하느냐”일 것이다.

2. 배포판 측이 이날 한 일은 「새 기능」이 아니라 「전달 가능성」이었습니다. RevyOS는 K3, K1, DP1000, EIC7700 네 개 플랫폼 설정을 한 번에 트리에 병합하고 linuxboot와 이중 빌드 CI를 보강했으며, openRuyi는 보안 백포트 배치로 전환했습니다. 두 가지 모두 같은 질문에 답하고 있습니다. 이 시스템을 다른 사람에게 전달물로 넘길 수 있는가. 설정의 트리 병합은 「다른 사람이 컴파일할 수 있는가」를 결정하고, 보안 백포트는 「프로덕션에 배치할 수 있는가」를 결정합니다. 이에 비해 새 기능 릴리스는 이날 부재했습니다.

3. 국내 팀의 작업은 지표를 끌어올리는 것이 아니라 링크를 보완하는 데 집중되었습니다. XiangShan은 분기 예측과 검증 정렬을 수정했고, Jindie는 llama.cpp에서 양자화 메인 경로를 복원하고 융합 연산자 라이프사이클을 수정했으며, 로봇 측은 SONIC 스케줄링과 추적을 분리하고 SLAM 저장소를 보강했습니다. 이러한 변경의 공통점은 「기존 능력을 안정적이고 재현 가능하게 만드는 것」이며, 바로 전날의 Nuclei NI1000 릴리스(신규 IP, 신규 지표)와는 두 가지 리듬의 교대를 형성합니다.

4. 순위권 출처의 비교 가능성은 재확인이 필요합니다. riscv100.top 개편으로 전체 점수가 페이지에서 제거되고 각 아키텍처 1위와 개요 목록만 남았습니다. 일상 모니터링 관점에서 이는 「점수 변화」라는 차원을 당분간 연속 관측할 수 없음을 의미합니다. 이번 호의 처리 방침은 신규 진입과 순위 이탈을 판정하지 않고, 사이트 구조가 안정된 후에 베이스라인을 재구축하는 것입니다. 단일 순위표에 의존해 결론을 내리는 모든 서술은 개편 기간 동안 기준 설명을 한 줄 덧붙여야 합니다.

5. 역외 관점은 중국 RISC-V를 「규모」가 아닌 「능력」으로 평가하기 시작했습니다. Jamestown Foundation의 글은 정책과 생태계 추진의 강도를 인정하면서도 성능 격차와 대체 점유율은 「무시할 수 있는 수준」이라고 지적했습니다. 이러한 평가를 전부 수용할 필요는 없지만 한 가지를 시사합니다. 국내 담론이 출하량, 서밋 규모, 표준 적합성을 중심으로 할 때 외부 관찰자는 단일 코어 성능, 소프트웨어 성숙도, 실제 대체율을 봅니다. 두 지표 체계 사이의 격차가 바로 다음 단계에서 보완해야 할 과제입니다.
