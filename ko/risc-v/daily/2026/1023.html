오늘의 중점: Kehua Data와 SpacemiT 계약 체결, RISC-V 서버 칩 컴퓨팅 인프라에 접속

날짜: 2026-10-22　출처: Guandian: Kehua Data와 SpacemiT 전략 협력 협약 체결, 자국 컴퓨팅 생태계 공동 구축 (10-22), Sohu: ‘칩’ 여정 함께하기——Kehua Data와 SpacemiT 전략 협력 달성 (10-22)

Kehua Data 주식회사와 SpacemiT (베이징) 인텔리전트 테크놀로지 유한회사가 전략 협력 협약을 체결하고, 기술, 제품, 시장, 생태계 네 가지 차원에서 협력하며, 목표는 AI 칩 계층과 컴퓨팅 인프라 계층의 적응 경로를 연결하여 자국 컴퓨팅 생태계를 공동 구축하는 것이다.

  • Kehua 측 역량: 전력전자 업계에서 약 40년간 심층 운영, 10여 년의 데이터센터 건설 및 운영 경험 보유, 고급 전원, 정밀 온도 제어 및 데이터센터 전 수명주기 운영 관리를 아우르는 사업; 『자국 칩과 컴퓨팅 하드웨어 인프라 협력 기술 규범 (CCHS)』 단체 표준 편집 주관, 다수의 국내외 선도 AI 칩 제조사와 협력 중.
  • SpacemiT 측 제품: K3는 글로벌 최초로 RVA23 규범을 충족하고 양산된 RISC-V AI CPU; V100은 10-18부터 20까지의 서밋 기간에 발표, 공식 입장은 글로벌 최초로 서버 전 규격을 충족하고 RISC-V Server SoC 규범을 준수하는 고성능 서버급 CPU이며, 동시에 C2201 컴퓨팅 서버, G5201 지능형 컴퓨팅 서버, S5236 스토리지 서버 세 가지 완제품을 제시.
  • 협력 접점: 자주 제어 가능한 컴퓨팅 솔루션을 칩 정의, 시스템 적응에서 규모 배치까지 전 과정에 걸쳐 관통 추진; 기술적으로 RISC-V AI 칩과 컴퓨팅 인프라의 협력 최적화 추진, 제품적으로 다양한 컴퓨팅 시나리오를 위한 솔루션 공동 구축.

서버 칩의 발표는 단지 하드웨어를 만든 것일 뿐, 기계실에 들어갈 수 있을지는 전원 공급, 냉각, 완제품 설계 및 운영 체계가 이를 위해 변경할 의지가 있는지에 달려 있다. 이번 계약의 실질적 의미는 ‘적응’을 칩 회사의 일방적 추진에서 인프라 제조사의 공동 작업으로 바꾸는 데 있다; 같은 시기 해외 미디어의 분석이 정확히 지적한 바에 따르면 적응 비용이 바로 고객이 전환 여부를 결정하는 결정적 변수이다. 두 단서는 같은 결론을 가리킨다: RISC-V 클라우드의 다음 여정은 발표회가 아니라 기계실에 있다.

1. 오픈소스 커뮤니티와 소프트웨어 생태계

1.1 openRuyi: 20건 커밋, Python 3.14.9, nginx 1.31.8 및 Node.js 24.22.1 적용

날짜: 2026-10-22　출처: openRuyi 메인 저장소 커밋 기록(10-22), openRuyi 공식 사이트 뉴스 페이지

openRuyi 메인 저장소는 모니터링 기간 내 20건의 커밋을 기록했으며, 내용은 주로 SPECS 디렉터리의 버전 업그레이드와 보안 수정이며, 그 외에 몇 가지 패키징 규범 정리가 포함된다.

  • 런타임 및 언어 스택: python이 3.14.9로 업그레이드(커밋에 security-fixes 표기), nodejs가 24.22.1로 업그레이드, openjdk-17이 17.0.21.9로 업그레이드, openjdk-21이 21.0.13.9로 업그레이드.
  • 서비스 및 미들웨어: nginx가 1.31.8로 업그레이드(security-fixes), python-pillow가 13.0.0으로 업그레이드(security-fixes), rdma-core가 65.0으로 업그레이드, libudev-zero가 1.0.5로 업그레이드. rdma-core는 RDMA 사용자 공간 라이브러리로, 고속 네트워크와 HPC 클러스터를 대상으로 하며 서버 배포판의 기반 구성 요소이다.
  • 엔지니어링 정리: opencv가 하드코딩된 /home 경로 대신 빌드 디렉터리 변수를 사용하도록 변경; xmltoman, xinetd, xdg-utils, xcb-util-renderutil, xcb-util-image 등의 패키지에 source checksums를 보완하고 자동 변경 로그 매크로를 사용하도록 변경.
  • 공식 사이트 이중 출처: 뉴스 페이지의 최신 공지는 여전히 2026.09 버전이며, 모니터링 기간 내 새로운 버전 릴리스는 없다.

연속 3일간의 커밋을 보면, openRuyi의 보완 순서는 Go 클라우드 네이티브 구성 요소, uv의 Rust 의존성, 그리고 Python과 Node의 런타임 메이저 버전이다. security-fixes 표기가 붙은 커밋이 일괄적으로 나타나는 것은 보안 업데이트가 이미 프로세스화된 채널로 진입했음을 의미하며, 산발적인 패치가 아니다.

1.2 커뮤니티 프로젝트, ESP32-S31에서 Linux 7.3과 OpenSBI 1.9 구동 성공

날짜: 2026-10-22　출처: GitHub: annoyedmilk/esp32-s31-linux(10-22)

커뮤니티 프로젝트 esp32-s31-linux가 Espressif ESP32-S31에서 업스트림 Linux 7.3 커널과 OpenSBI 1.9를 구동하는 데 성공했으며, 16 MB 8선 PSRAM을 주 메모리로 사용한다.

  • 부팅 체인: ESP ROM에서 ESP-IDF 2단계, 다시 loader, OpenSBI, Linux, 마지막으로 Buildroot 루트 파일 시스템 마운트(SD 카드, USB 드라이브 또는 flash).
  • 사용 가능한 사용자 공간: LCD 상의 shell, wpa_supplicant 네트워크 연결, BlueZ 블루투스, SSH, USB 키보드·마우스와 USB 드라이브, vim, gdb, strace, MicroPython 그리고 텍스트 브라우저 links.
  • 기술적 관전 포인트: 해당 SoC에는 PLIC도, Zicbom도, 일관성 DMA도 없으며, 프로젝트는 수백 줄의 코드로 대체 구현을 제시하고 커널 개발자를 위한 내부 구현 문서를 작성했다.
  • 하드웨어 지원: ESP32-S31-Korvo-1, ESP32-S31-Function-CoreBoard-1과 ESP32-S31-WROOM-3-N16R16V 모듈 세 가지 빌드.

MCU로 포지셔닝된 듀얼 코어 RV32(320 MHz, 512 KB SRAM, 16 MB PSRAM)가 완전한 Linux 사용자 공간을 구동할 수 있다는 것은 소프트웨어 스택이 하드웨어에 요구하는 수준이 이미 매우 얇아졌음을 보여준다. 이러한 프로젝트는 제품 경로를 구성하지는 않지만, 툴체인, 커널 이식 및 드라이버 성숙도를 검증하는 극단적 사용 사례로서 교육과 이식 참고 모두에 직접적인 가치가 있다.

1.3 XiangShan Kunminghu V3와 CORE-V cvw: mnret/dret 디코딩 보완, jalr 정정

날짜: 2026-10-22　출처: XiangShan 커밋 기록(10-22), cvw 커밋 기록(10-22)

XiangShan Kunminghu V3 브랜치는 모니터링 기간 내 3건의 커밋으로, 모두 기능이 아닌 세부 사항에 해당한다: decode에 mnret과 dret 두 특권 반환 명령어의 디코딩 추가(#6692), ROB 리디렉션 시작 인덱스 수정(#6729), README에 Dashboard와 star 이력 링크 추가(#6696).

  • CORE-V 측: cvw 저장소 2건, jalr 명령어의 Table I.1에 정오표 항목을 추가(PR #1996)하고 병합.
  • 해석: mnret과 dret는 각각 M 모드와 디버그 모드의 복귀 경로 명령어로, 디코딩 보완은 Xiangshan이 특권 상태와 디버그 지원을 개선하고 있음을 의미한다; jalr 정오표는 문서 수준의 수정으로, 검증 팀에게 더 큰 가치가 있으며 외부 사용자에게는 그렇지 않다.

오픈소스 코어의 진전은 종종 이런 “기능이 보이지 않는” 커밋이 주를 이룬다. 오픈소스 코어가 진전되고 있는지를 판단할 때는 또 어떤 benchmark를 통과했는지가 아니라 특권 상태, 예외, 디버그처럼 쉽게 간과되는 부분을 봐야 한다.

2. 제품 및 생태계 동향

2.1 밀리미터파 레이더의 RISC-V 노선: 중국산 칩이 먼저 시장에 진입, CPU 슬롯은 여전히 두 번째 옵션

날짜: 2026-10-22　출처: RFID 월드넷: 밀리미터파 레이더 RISC-V 중국산 선행 (10-22)

밀리미터파 레이더 칩의 명령어 집합 선택을 정리한 기사는 상당히 실용적인 판단을 제시했다: 레이더 칩에서 RISC-V와 Arm은 현재 병존하는 옵션이며, 세대 교체가 아니다.

  • 중국산 선행 진입: Zhenghe Microchip RS6240(2024년 출시, 듀얼코어 RISC-V)은 이미 스마트 홈, 케어 모니터링, 보안 경보에 사용되고 있다; Kaiku K60213은 RISC-V MCU와 AI 가속기를 내장하고 TV, 에어컨, 선풍기 등 실내 인터랙션 기기에 진입했다.
  • 차량 규격 침투: Nuclei NA900은 이미 ISO 26262 ASIL-D 인증을 획득했고, Calterah Kunlun-Pro는 해당 코어를 내장하며 듀얼 이슈 듀얼코어 총 연산력 3668 DMIPS로 이전 세대 Alps-Pro의 약 5배에 달하며 L2 ADAS 전방 인지로 나아가고 있다.
  • 분업 경계: 외부에서 주목하는 10배 신호 처리 연산력은 Calterah 자체 개발 RSP 2.0에서 나온 것이지 RISC-V 코어가 아니다; RISC-V가 담당하는 것은 포인트 클라우드 후처리와 목표 추적처럼 알고리즘 업데이트가 빠르고 반드시 프로그래머블 CPU에 남아 있어야 하는 부분이다. 제조사는 개방형 확장 인터페이스를 활용해 정렬, 보간, 삼각함수를 하드웨어 명령어로 만들어 실측 클러스터링 소요 시간이 약 절반으로 줄고 추적 소요 시간이 50% 이상 감소했다.
  • 국제 대기업: TI의 AWR2188, NXP의 TEF8388과 SAF8444는 여전히 Cortex-A53과 M7을 사용하며 단기적으로 전환 동력이 없다; Esosw가 홍콩 증시에 상장할 때 낸 투자설명서에서도 RISC-V가 여전히 시장 검증 초기 단계에 있어 사용자 인지도와 신뢰도가 충분히 형성되지 않았다고 밝혔다.

이 소식의 가치는 RISC-V가 특정 품목에서 가지는 실제 좌표를 제시한다는 데 있다: “누구를 대체하는가”가 아니라 “어느 슬롯에서 더 경제적인가”이다. 원동력은 공급망 통제 가능성, 비용과 커스터마이징 자유도이며 성능 세대 차이가 아니다; 기능 안전도 약점이 아니라 NA900은 이미 ASIL-D 능력을 갖추고 있으며, 진짜 오래 걸리는 것은 칩 전체의 3~5년 인증 주기다.

2.2 국제 미디어 관점: 서버 CPU가 집중 등장한 후, 적응 비용이 진정한 관문으로 부상

날짜: 2026-10-22　출처: Global Times: Chinese chipmakers roll out new RISC-V server CPUs for AI demand (10-22)

서밋 이후 해외 미디어가 내놓은 한 논평은 SpacemiT V100과 Lanxin Suanli LX500을 같은 맥락에 놓았다: 중국 제조사들이 RISC-V를 임베디드에서 AI 서버로 밀어내고 있다.

  • 사실 부분: V100은 46코어, 최대 2.4 GHz, DDR5와 PCIe 5.0을 지원하며 컴퓨팅, AI, 스토리지 세 가지 유형의 완제품을 동시에 제시했다; LX500은 48코어에 전용 AI 엔진을 통합했으며 Qwen, DeepSeek, Kimi 등 모델을 적응 중이고 목표 시나리오는 기업 지식베이스 검색, 사무 보조, 금융 컴플라이언스 추론, 산업 순찰을 포함한다.
  • 관점 부분: 인터뷰에 응한 분석가는 서버 CPU 경쟁이 단일 칩 성능에 그치지 않으며 프로세서 교체는 부품 교체가 아니라고 보았다; 운영체제, 애플리케이션, 개발 도구가 원활히 실행되는지, 적응 및 유지보수 비용이 수용 가능한지가 고객 이전의 관건이다. 적응 비용이 너무 높으면 새 칩에 기술적 우위가 있어도 고객은 망설인다.

“발표”와 “안착”을 분리해 보면, 이 기사는 외부 관점의 기준자를 제공한다: 전시회의 완제품은 하드웨어 형태가 이미 갖춰졌음을 증명하고, 생태계 측의 비용 산정이 주문을 결정한다. 이는 이번 호의 오늘의 핵심과 서로를 보완한다.

XuanTie가 유지보수하는 CubeSandbox는 모니터링 기간 동안 작업 중심을 “RISC-V 브랜치 개설”에서 CI 난관 돌파로 옮겼습니다. feat/riscv64-ci 브랜치에 12건의 커밋이 기록되었으며, 전부 RISC-V에서 마이크로 VM(microVM) 제어면을 안정적으로 구동하는 데 집중되어 있습니다.

이 십여 건의 커밋 중 “기능 릴리스”는 단 하나도 없고, 전부 불안정 요소를 하나씩 못 박은 것입니다. 커널 설정, 시리얼 관측성, 더티 페이지 로그, MySQL 기동·정지 검증이 그것입니다. 마이크로 VM이 RISC-V에서 부팅 가능한 단계에서 실제 부하를 감당하는 단계로 넘어가려면 비용이 거의 전부 이런 작업에 들어가며, 이는 이 스택의 성숙도를 판단하는 가장 신뢰할 만한 관찰 지점이기도 합니다.

4. 임바디드 인텔리전스와 로봇 특별 장

4.1 21세기경제보도 쑨옌방 인터뷰: K3가 휴머노이드 로봇 완주를 지원, 로봇은 단일 칩으로 나아갈 것

날짜: 2026-10-22　출처: 21세기경제보도(시나파이낸스 전재): 휴머노이드 로봇 마라톤 뒤의 RISC-V 역량(10-22)

서밋 이후의 심층 인터뷰로, 인터뷰이는 SpacemiT 공동 창업자 쑨옌방이며, 검증 가능한 몇 가지 진척과 판단을 제시했다.

  • 이미 발생한 진척: 2026년 4월 베이징 이좡 휴머노이드 로봇 하프 마라톤에서 링룽 2.0 완주에 사용된 것은 SpacemiT K3 칩이었다; K1은 누적 출하 15만 개, K3는 전 세계 최초로 RVA23 규격을 충족하는 양산 RISC-V 칩이며 이미 규모 양산 납품되었다. 이 두 세대 엣지 칩의 축적은 클라우드로 확장하는 출발점으로 묘사되었다.
  • 시장 예측: Omdia 데이터를 인용해 RISC-V 프로세서 연간 출하량 성장률은 50%, 2030년 글로벌 시장 점유율은 25%에 근접해 약 4개 프로세서 중 1개가 RISC-V가 될 것이라고 밝혔다.
  • 판단 1: 로봇 산업은 규모화 착지 주기에 진입한 후 반드시 단일 칩 통합 노선으로 나아갈 것이며, 차세대 로봇은 RISC-V에 더 의존하게 될 것인데, 그 이유는 안전성에 대한 극한 요구와 강력한 CPU 및 AI 역량의 융합 때문이다.
  • 판단 2: 로봇의 실시간성 요구는 “영원히 천장이 없으며”, AI Agent 이탈 현상이 빈번해 가상화와 물리적 격리 모두 시스템이 항상 통제 가능 범위 내에 있음을 완전히 보장하기 어렵고, 오히려 오픈소스 개방 메커니즘이 돌파구가 될 수 있다; Physical AI는 최대의 기회다.
  • 판단 3: 연구개발 노선은 자금 실력과 매칭되어야 한다; PPA 외에 하드웨어는 반드시 초과 구성되어야 소프트웨어 생태계가 발휘할 공간이 생긴다; 국산 산업 체인의 반복 속도는 기대할 만하지만 최종 측정 기준은 여전히 주문 전환이다.
  • 외부 관점: 튜링상 수상자 David Patterson의 판단도 인용했는데, AI가 저장 대역폭과 용량 압박을 끌어올리고 주류 표준 저장 성능 향상이 정체되어, 영역 특화 저장(DSA)이 컴퓨팅 파워 희소 배경에서 실행 가능해졌다는 것이다.

이 글은 “RISC-V로 로봇 만들기”를 개념에서 두 가지 구체적 좌표로 내려놓는다: 이미 규모 양산된 엣지 칩 하나, 그리고 “안전 + 실시간” 아키텍처 이유 하나. 컴퓨팅 파워 숫자에 비해 후자가 로봇 제조사가 왜 아키텍처를 바꾸려 하는지를 더 잘 설명하며, “하드웨어는 반드시 초과 구성”이라는 문장은 현재 로봇 칩이 보편적으로 컴퓨팅 파워를 미리 예약하는 방식을 정확히 설명한다.

4.2 spacemit-robotics: 동작 인식 구성이 13포인트 골격에 정렬

날짜: 2026-10-22　출처: ros2_action_recognition 커밋(10-22), spacemit-com/docs-ros 커밋(10-22)

SpacemiT의 로봇 소프트웨어 라인이 모니터링 기간 내에 인터페이스 정렬을 완료했다: 동작 인식 저장소에 수정이 병합되어 STGCN 구성과 13포인트 골격 정의를 비전 API에 정렬했으며(#8); 동시기 docs-ros의 두 건은 인지와 비전 문서를 새로운 노드 동작과 SDK 인터페이스에 동기화했고, ai-sdk의 두 차례 서브모듈 업데이트는 vision을 가리킨다.

5. 요약과 트렌드 관찰

  • 서버 서사의 중심이 ‘칩 발표’에서 ‘인프라 적응’으로 이동: 서밋에서 V100, LX500, C950A가 집중적으로 공개되었고, 서밋 이후 첫 번째 새로운 움직임은 Kehua Data와 Jindie Shikong의 계약 체결, 그리고 해외 매체의 적응 비용 논의입니다. 하드웨어 형태는 이미 갖춰졌으며, 다음 단계는 데이터센터 측의 수용도와 소프트웨어 스택의 마이그레이션 비용입니다.
  • RISC-V가 세부 카테고리에서의 위치가 더 명확해짐: 밀리미터파 레이더 보도는 DSP와 하드웨어 가속기가 주요 연산을 담당하는 칩에서 CPU 명령어 집합이 ‘세대 교체’가 아닌 ‘솔루션 선택’임을 보여줍니다. 국내 제조사가 먼저 채택한 이유는 공급망 통제 가능성과 커스터마이징 자유도이지, 성능 세대 차이가 아닙니다.
  • 배포판 보완의 리듬이 안정적이고 수준이 상향됨: openRuyi가 연속 3일 동안 각각 Go 클라우드 네이티브 컴포넌트, uv의 Rust 의존성과 Python, Node, Java 런타임 버전을 보완했으며, 보안 수정이 마커를 달고 프로세스를 따르기 시작했습니다. RISC-V 배포판은 ‘설치 가능’에서 ‘프로덕션 사용 가능’으로 나아가고 있습니다.
  • 마이크로 VM 스택이 RISC-V에서 디버깅 단계에 진입: CubeSandbox의 12건 커밋은 전부 커널 설정, 관측성 및 프로세스 검증이며, 기능 릴리스는 단 하나도 없습니다. 이는 부팅 가능에서 워크로드 수용 가능으로 가는 필수 단계이며, RISC-V 가상화 성숙도를 관찰하는 최적의 창구입니다.
  • 엣지 측에서 외溢 효과 발생: ESP32-S31이 프리뷰 디바이스에서 서드파티 완제품까지 약 10일밖에 걸리지 않았으며, 커뮤니티 프로젝트는 심지어 그 위에서 완전한 Linux와 그래픽 이외의 전체 유저스페이스를 구동했습니다. 이러한 ‘하향 압착’ 방식은 RISC-V MCU의 개발자 노출을 지속적으로 확대할 것입니다.
  • 로봇 측 증거는 여전히 엣지와 실시간 제어에서 나옴: K3가 휴머노이드 로봇 완주를 지원하고, 관절 제어 칩은 이미 양산되었으며, 대연산량의 ‘브레인’ 칩은 대부분 테이프아웃 단계에 있습니다. RISC-V가 로봇에서的第一波 실제 출하很可能 여전히 운동 제어에서 나올 것이지, 범용 AI 연산에서 나오지는 않을 것입니다.
  • 한계 설명: Kehua Data와 Jindie Shikong의 협력 세부 사항은 두 회사의 대외 입장과 재경 매체의 전언에서 나왔으며, 계약 금액, 일정 및 구체적 프로젝트는 공개되지 않았습니다. 밀리미터파 레이더 보도의 성능 수치(3668 DMIPS, 클러스터링 및 추적 소요 시간)는 제조사 테스트에서 나왔으며, 제3자 재현은 확인되지 않았습니다. Global Times의 인터뷰 대상자는 업계 분석 인사이며, 관점은 산업 컨센서스를 대표하지 않습니다. ESP32-S31-Linux는 커뮤니티 프로젝트로, 저자가 ‘Linux용으로 설계되지 않은’ 디바이스에서의 이식 실험이라고 자술했으며, 제품화 경로를 구성하지 않습니다. openRuyi의 커밋 내용은 커밋 제목을 기준으로 판단했으며, changelog를 항목별로 대조하지 않았습니다. CubeSandbox의 RISC-V 지원은 여전히 개발자 프리뷰이며, 공식적으로 릴리스 이미지를 제공하지 않았습니다. 회원 공식 웹사이트 점검에서 감지된 95개 변화는 모두 대학, 기관 및 제조사 홈페이지의 정례 업데이트이며, 실질적인 제품, 투자 또는 아키텍처 발표는 발견되지 않았습니다.
