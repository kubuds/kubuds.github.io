1. 오픈소스 커뮤니티 및 커널/버전 동향

1.1 Linux 7.2 릴리스 정리: RISC-V 측 NR_CPUS 256으로 상향, Eswin defconfig 진입 (08-21)

날짜: 2026-08-16 (커널 릴리스, LKML)／2026-08-21 (CNX 아키텍처급 정리 보도, 06:00 베이징)　출처: CNX Software, Linux Journal

Linus Torvalds가 08-16에 Linux 7.2를 릴리스했으며(LKML), CNX가 08-21에 아키텍처급 정리를 내놓았고, RISC-V 측 업데이트가 집중적이다. 일반 하이라이트: cache-aware 태스크 스케줄링 (동일 프로세스 스레드를 LLC 도메인별로 함께 배치), CFS에서 영감을 받은 Fair GPU 스케줄러, USB4STREAM 직접 스트리밍 전송, swap table 4단계. RISC-V 특집:

  • NR_CPUS 64비트 기본값을 256으로 상향——공식 이유는 국산 멀티코어 머신을 직접 지목: SpacemiT은 이미 80코어 RVA23 서버를 생산했고, 듀얼 소켓 SG2042의 SOPHGO Pisces는 128코어에 도달해 기본 64로는 부족함;
  • Eswin SoC가 RISC-V defconfig에 추가——국산 제조사가 메인라인 기본 설정에 진입, 병합 기준이 일반 드라이버보다 높음;
  • T-Head TH1520: PWM 수정, BeagleV Ahead, Lichee Pi 4a 두 보드에서 WiFi 활성화;
  • SpacemiT: K1에 SPI/thermal 드라이버 및 I2C 활성화 추가, K3에 USB2 PHY 및 ASoC 드라이버 추가, P1 칩에 reboot cell 보완; K1 보드급 주변기기 대량 활성화 (Milk-V Jupiter eMMC, Muse Pi Pro EEPROM/PCIe/QSPI/USB, OrangePi R2S PMIC/USB3, OrangePi RV2 전체 주변기기); CoM260-IFX 및 DeepComputing FML13V05 두 K1 보드 추가;
  • SOPHGO: Milk-V Duo S에 bindings 추가; SG2042/SG2044 디바이스 트리 수정 (CPU 주소를 16진수로 변경, MSI 실제 16 인터럽트만, PCIe RC 캐시 일관성 표시);
  • StarFive: JH8100 인터럽트 컨트롤러는 해당 칩이 양산되지 않고 단종되어 이름을 바꿔 JHB100 버전으로 재작업; JH7110에 SiFive ccache 비표준 cache 조작 목록 추가 (GPU DMA 비일관성); JHB100에 clint 바인딩 및 SGMII GMAC 지원 추가;
  • 핵심 수정: kexec_file 대용량 메모리 초기 부팅, 무조건적 sfence.vma, kfence 오탐 수정, CFI vDSO 패치, ftrace_graph_ret_addr, BUILDTIME_MCOUNT_SORT 부팅 오버헤드 감소 등.

7.3 merge window가 릴리스와 함께 열렸습니다(Linus는 이미 40개의 병합 대기 PR이 있다고 언급). Phoronix는 7.3이 구형 32비트 ARM 플랫폼을 대규모로 퇴출할 것이라고 보도했습니다(ARM 중심 재편, RISC-V에 대한 영향은 지켜봐야 함). 이번 점검은 다음을 확인시켜 줍니다: Linux 메인라인이 “80-128코어 중국산 RISC-V 서버”를 위해 대량으로 기반을 다지고 있다는 점입니다.

1.2 NetBSD 11, 64비트 RISC-V 지원 정식 반영 (08-20)

날짜: 2026-08-20 (The Register 보도 21:45 베이징 시간; HN 동시)　출처: The Register, HN 토론

NetBSD의 19번째 메이저 버전인 11.0(7월 말 릴리스)이 The Register의 장문 리뷰를 받았습니다: 64비트 RISC-V 지원 추가(Tier II 플랫폼, QEMU 가상화 환경 대상)으로 NetBSD는 Linux, FreeBSD에 이어 RISC-V에 메인라인 지원을 제공하는 또 하나의 BSD 계열 운영체제가 되었습니다. 11.0은 동시에 다음을 제공합니다: MICROVM 전용 커널(x86 게스트 약 10밀리초 콜드 부팅, 2020년대 프로세서 실측), POSIX.1-2024 및 C23 준수 향상, Linux 시스템 콜 호환성 강화, Xen/QEMU 실행 최적화, 52개 Tier II 플랫폼과 9개 Tier I 플랫폼. 리뷰는 또한 NetBSD가 “구식” 스타일을 유지하고 있다고 지적합니다: sysinst 텍스트 설치 프로그램, /etc/rc.conf 수동 편집 필요, 상용 드라이버 부족. RISC-V 생태계에 대한 의미: BSD 진영의 RISC-V 지원이 보완되었으며, 가상화 시나리오(QEMU)가 먼저 반영되었습니다.

2. 제품 및 생태계 동향

2.1 Andes, Condor 설계 센터 폐쇄, Cuzco 데이터센터급 코어 IP 모회사로 회귀 (08-17/08-20)

날짜: 2026-08-17 (Jon Peddie Research 최초 보도)／2026-08-20 (EE Times 후속 보도, 06:00 베이징 시간)　출처: Jon Peddie Research, design-reuse 전재, EE Times

Andes Technology는 미국 텍사스주 오스틴에 있는 고급 설계 센터 Condor Computing(2023-03 설립, 약 100명, 85% 이상이 연구개발)을 공식 폐쇄했습니다. Condor는 Andes가 데이터센터급 RISC-V에 도전하는 플래그십 프로젝트 Cuzco 코어를 담당했습니다 — RVA23 준수, 라이선스 가능, 새로운 특허 마이크로아키텍처(깊은 비순차 실행 + 비전통적 시간 스케줄링 설계, Hot Chips 2025 공개) 채택. 현황: Cuzco IP는 Andes 모회사로 회귀, 후속 test silicon 개발 없음; 팀은 50명에서 15명으로, 다시 한 자릿수로 줄어 해당 IP를 진정으로 이해하는 엔지니어만 남음; 전 CEO Ty Garibay는 Ambiq의 SoC Design VP로 이동. 폐쇄는 2026-04에 발표된 비용 절감 계획의 일부입니다: 회장 겸 CEO Frankwell Lin은 지난 3-4년간 너무 빠르게 확장했고 매출이 이를 따라가지 못했다고 인정하며, 운영 비용 10-20% 절감, 글로벌 직원을 480명에서 약 450명으로 감축할 계획이라고 밝혔습니다(EE Times는 현재 이미 약 400명으로 추정).

산업적 의미: Jon Peddie Research 분석가 David Harold는 이것이 “Andes의 고급 야심에 대한 좌절이자, 데이터센터에서 RISC-V가 Arm/x86의 신뢰할 수 있는 대안을 구축하려는 노력의 후퇴”라고 직언했습니다. 1.1에서 Linux 메인라인이 멀티코어 서버를 위해 기반을 다지는 것과 대조됩니다 — 소프트웨어 측은 가속하고 있지만, IP 공급업체 진영은 재편과 축소가 진행 중입니다.

3. 국내 팀 동향 및 심층 분석

3.1 샹산: 24시간 20건 커밋, WritebackQueue 및 TAGE 성능 최적화 (08-20)

날짜: 2026-08-20(10:59 ~ 익일 01:32 베이징 시간, committer 시간)　출처: OpenXiangShan/XiangShan, XiangShanLab, env-scripts

샹산 조직 모니터링 기간 내 총 20건의 커밋이 있었으며, 메인 저장소(XiangShan)에는 4건의 실질적인 커밋이 반영되어 성능 지향 반복이 뚜렷하다:

  • timing(WritebackQueue): use lowestIndexFirst policy (#6379)(08-20 10:59 베이징 시간) — writeback queue가 lowest-index-first 스케줄링 정책으로 변경, 메모리 접근 백엔드 타이밍 최적화;
  • build: generate CHIRRTL only for gsim (#6374)(11:36) — 빌드 시스템 간소화(CHIRRTL은 gsim에서만 생성);
  • perf(Tage): optimize UseAltOnNa (#6328)(17:24) — TAGE 분기 예측기 UseAltOnNa 정책 최적화;
  • fix(uart16550): expose DesignWare status register (#6385)(08-21 01:32) — UART 상태 레지스터 노출, 디버깅 및 보드 레벨 사용성 개선.

동반 저장소: XiangShanLab에 xs bug replay 스크립트 추가(commit hash 기준 버그 재현), env-scripts의 perf_trigger 2건 수정(#154/#155, 런타임 분석 로그 강화). 연속 며칠간 고강도 병합이 이루어졌으며, 이번 라운드의 중심은 메모리 접근 정확성에서 writeback queue 스케줄링 및 분기 예측의 성능 미세 조정으로 이동했다. 이는 아키텍처 성능 마무리 단계의 특징이다.

3.2 SpacemiT: K1 소프트웨어 스택 v2.2.11 버전 업데이트 (08-20)

날짜: 2026-08-20(09:07 ~ 17:25 베이징 시간)　출처: spacemit-com/buildroot-ext, uboot-2022.10, mpp, v2d-test

SpacemiT 조직 모니터링 기간 내 22건의 커밋이 있었으며, 핵심은 K1 소프트웨어 스택 v2.2.11 버전 전체 패키지 업데이트이다: buildroot-ext, uboot-2022.10, v2d-test가 v2.2.11로 동기화되었으며, 그중 K1 buildroot는 GENERIC_HOSTNAME을 “K1-Buildroot”로 변경하고 루트 파일 시스템을 1GB로 확장했다(더 큰 소프트웨어 집합에 적응); mpp 미디어 파이프라인은 2건의 엔지니어링 리팩토링(stream manager를 mpi 인터페이스 계층에서 분리, AL module 빌드 타깃 분할)을 진행했고, v2d-test는 K1 buildroot 빌드 오류를 수정했다. 08-18에 이미 보도된 “K1 메인라인 커널 7.2가 meta-riscv를 통해 Yocto에 안착” 흐름을 이어, 이번 라운드는 BSP 전체 패키지 버전화 전달이며, 미디어 파이프라인은 독립적으로 유지보수 가능한 모듈 구조로 진화하고 있다.

4. 중점 방향 특별 장: 임바디드 인텔리전스와 로봇

4.1 모니터링 기간 내 신규 특집 뉴스 없음: 기반 공정은 멈추지 않았다 (08-20)

날짜: 2026-08-20　출처: gnews 특집 쿼리 (“risc-v” robot when:3d, 엠바디드 AI RISC-V when:3d), GitHub 조직 검색

모니터링 기간 내 gnews 로봇 특집 쿼리는 전날 이미 보도된 항목(Dubhe-100, NetBSD)만 조회되었고, 독립적인 신규 뉴스는 없었다. 중국어 “엠바디드 AI RISC-V” 쿼리는 결과가 비어 있었다. 신규 특집 뉴스가 없는 날로 판정하지만, 기반 공정은 멈추지 않았으며 엠바디드/엣지 컴퓨팅과 직접 관련된다:

  • Linux 7.2에서 SpacemiT K3의 PDMA, USB2, Ziccrse 확장 활성화 — 로봇 메인 컨트롤 SoC의 주변장치 기반이 메인라인에서 지속적으로 보강되고 있다;
  • XiangShan WritebackQueue 스케줄링 정책과 TAGE 최적화 — 저지연 응답을 겨냥한 마이크로아키텍처 미세 조정;
  • 트렌드 연결: 08-19/08-20 리포트에서 이미 T-Head C950(30 tok/s로 Qwen3.8-27B 구동)과 StarFive Dubhe-100이 모두 “AI agent 서버/로봇”을 핵심 시나리오로 내세운 것을 정리했다. 이번 모니터링 기간에는 새로운 서사가 없지만 하드웨어 베이스라인은 전진하고 있다. 관찰 결론: 로봇 방향의 뉴스 밀도는 주기적으로 하락하며, 판단 시에는 제목이 아니라 하드웨어와 커널 동작을 기준으로 삼아야 한다.

5. 요약 및 트렌드 관찰

  1. Linux 7.2는 중국산 멀티코어 RISC-V 서버의 메인라인 이정표: NR_CPUS 기본값이 256으로 상향(SpacemiT 80코어, Sophgo Pisces 128코어 지목), ESWIN이 defconfig에 진입, SpacemiT K1/K3 주변장치 대규모 활성화 — 메인라인과 중국산 고급 SoC의 결합이 뚜렷하게 심화되었다;
  2. 데이터센터급 IP 진영 재편: Andes가 Condor를 종료하고 Cuzco를 모회사로 반환한 것은 SiFive 축소에 이은 또 하나의 신호이다. 고급 RISC-V 코어 경쟁에서 “중국 쌍두마차”(T-Head/StarFive)의 비중이 더욱 상승하며, 소프트웨어 측 길닦기와 IP 측 축소가 병존하고 있다;
  3. BSD 생태계 보강: NetBSD 11이 64비트 RISC-V 메인라인 지원을 제공하며, 주요 오픈소스 OS의 RISC-V 커버리지가 다시 한 걸음 나아갔다;
  4. 국내 팀 리듬 분화: XiangShan(성능 미세 조정기), SpacemiT(v2.2.11 전체 패키지 납품)가 높은 활성도를 보였다. T-Head/Nuclei/StarFive/ESWIN 저장소는 조용하지만, ESWIN의 병합 동작은 메인라인 defconfig에서 확인된다;
  5. 조용한 날 설명: gnews 중국어 쿼리 결과가 모니터링 기간 내 비어 있었고, 벤더 영어 쿼리는 대부분 이미 보도된 이벤트였다. 국내 동향은 주로 GitHub 조직 검색으로 포착된다(부록 검증표 참조).

한계 설명: Linux 7.2 RISC-V 변경 사항은 CNX 전언을 기준으로 하며, 커널 changelog를 항목별로 대조하지 않았다. Andes 종료 세부 사항(팀 규모, headcount)은 EE Times/JPR 보도 기준이며, Andes 공식 확인을 거치지 않았다(공식 성명 미발표). NetBSD 11은 The Register 리뷰 관점이며, RISC-V 포트는 Tier II(QEMU)에 속하고 Tier I 실기가 아니다. XiangShan/SpacemiT 커밋은 committer 시간 기준으로 분류했으며, 일부 커밋의 author 날짜는 모니터링 기간보다 이를 수 있다.
