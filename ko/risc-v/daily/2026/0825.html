1.1 CPython 공식 RISC-V 지원: 공식 tier 3 플랫폼으로 등재 (08-25)

날짜: 2026-08-25 (블로그 게시 동시; HN수록 08-24 20:12 UTC = 08-25 04:12 베이징)　출처: blog.python.org, HN

CPython이 RISC-V를 공식 지원 플랫폼으로 공식 발표하며, PEP 11에 따라 tier 3에 등재했습니다. 지원 경로: RISE Project가 다수의 실제 RISC-V 하드웨어를 buildbot 테스트와 아키텍처 문제 디버깅 환경으로 제공 (Ludovic Henry, Furkan Onder, Emma Smith 등 커뮤니티 기여자), Sovereign Tech Agency 장학금이 이번 아키텍처 지원 작업을 후원했습니다. 다음 단계 계획: RISE RISC-V Runners를 통해 RISC-V를 CPython 공식 CI에 직접 연결 (buildbot보다 빠른 피드백), 장기적으로 tier 2 승격 추진 및 아키텍처 특화 성능 최적화. 의의: Python은 AI/로봇 소프트웨어 스택의 중추 언어이며, 공식 tier 3 지원은 RISC-V 엣지와 서버 시나리오의 소프트웨어 사용성을 보완하는 핵심 연결고리입니다 (2.1의 서버 진전과호응).

1.2 Linux 7.3, 다수의 RISC-V 확장 지원 추가 (08-24)

날짜: 2026-08-24 (Phoronix 10:12 UTC = 18:12 베이징)　출처: Phoronix

개발 중인 Linux 7.3에 다수의 최신 RISC-V ISA 확장에 대한 발견 및 열거 지원이 병합되었습니다: 간접 CSR 접근 (Smcsrind/Sscsrind), 카운터 특권 필터링 (Smcntrpmf), S 모드 카운터 구성 (Ssccfg), 카운터 위임 (Smcdeleg, 모든 특권 레벨포괄), 메모리 원자성/일관성류 (Zicclsm 비정렬 메모리 접근, Ziccamoa 원자 연산, Ziccif 명령어 인출 원자성, Ziccrse LR/SC 전방 진행, Za64rs 예약 집합), QoS 식별 (Ssqosid, 메모리/캐시 대역폭 모니터링). 또한 CFI Shadow Stack 처리 개선, QoS 태그 컨텍스트 스위치, UEFI Runtime 서비스의 재시작/종료 활용 등이 있습니다. 이 확장들은 서버와 성능 모니터링 지향이 주를 이루며, RVA23 서버 플랫폼추진 (2.1 참조)과 특성상 직접 호응합니다.

1.3 Hot Chips 2026: NVIDIA, CUDA의 RISC-V 이식 기술 요구사항 상세 설명 (08-24)

날짜: 2026-08-24 (Chips and Cheese 발표; HN 68점, 댓글 9개)　출처: Chips and Cheese, HN

Hot Chips 2026에서 NVIDIA는 CUDA 지원을 RISC-V로 확장하는 내용을 발표했다: RVA23 profile과 RISC-V server SoC / server platform 규격( RAS, 전용 보안 프로세서 등 베이스라인 기능 포함)을 요구하며; 추가로 PCIe 일관성(그렇지 않으면 DMA와 CPU 캐시 간에 소프트웨어 명시적 무효화가 필요해 CUDA 스택이 처리하기 어려움), 디바이스 간 P2P PCIe, 벡터 확장 프레디케이트 지원 등을 요구하여 “최소 공통분모”로 인해 성능 향상 명령어를 사용할 수 없게 되는 상황을 피하고자 한다; ACPI 문제는 이전에 이식을 저해했으나 2025년 UEFI 포럼의 RISC-V ACPI 지원과 작년에 승인된 BRS(Boot and Runtime Services) 규격으로 해결되었다. 한국 매체 《매일경제》(한국)는 같은 시기 NVIDIA가 AI 서버 CPU 지원을 Arm/x86에서 RISC-V로 확대할 계획이라고 보도했다. SiFive가 CUDA가 자사의 BigSky 플랫폼에서 실제로 구동됨을 확인한 점(2.1 참조)과 결합하면, “RISC-V에서의 CUDA”는 2025년의 입장 표명에서 기술 요구사항이 구체화되는 단계로 진입했다.

1.4 RISC-V 명령어 집합 매뉴얼, ISO/IEC DIS 26791-1 국제 표준 초안 단계 진입 (08-24)

날짜: 2026-08-24 (HN 12:54 UTC = 20:54 베이징 시간)　출처: HN, iso.org/standard/94578

RISC-V 명령어 집합 매뉴얼이 ISO/IEC DIS 26791-1 번호로 국제 표준 초안(DIS) 단계에 진입했다——ISO/IEC JTC 1 표준 절차에서 DIS는 회원국 투표를 거치며, 이는 공식 국제 표준화의 핵심 분기점이다. 개방형 ISA가 ISO 표준으로 나아가는 상징적 조치로서, RISC-V International의 JTC 1에서의 표준화 추진과 일치한다. 참고: ISO 공식 홈페이지는 안티 크롤링으로 본문을 직접 수집할 수 없으므로, 기술 범위는 공식 홈페이지와 DIS 텍스트를 기준으로 한다.

2. 제품 및 생태계 동향

2.1 SiFive BigSky SF-2U870: 세계 최초 랙 장착형 2U RISC-V 엔터프라이즈 서버 발표 (08-24)

날짜: 2026-08-24 (SiFive 보도자료; HotHardware 12:23 EDT = 08-25 00:23 베이징 시간)　출처: SiFive 보도자료, HotHardware, HPCwire

SiFive는 Hot Chips 2026과 같은 시기에 BigSky SF-2U870 데이터센터 개발 플랫폼을 발표하며, 세계 최초의 엔터프라이즈급, 랙 배치 가능한 2U RISC-V 서버라고 주장했다: 32코어 P870-D @2GHz, 256GB DDR5-5600, 3.84TB U.2 NVMe, 10/25Gbps OCP 3.0 네트워크, 64레인 PCIe Gen5 확장(듀얼 와이드 GPU 및 전용 가속기 수용 가능), RVA23 준수; 개봉 즉시 Ubuntu 26.04 LTS 및 RHEL 10 지원; 하이퍼스케일 클라우드 사업자, 칩 제조사 및 소프트웨어 기업을 대상으로 하며, 엔터프라이즈 소프트웨어 이식, 워크로드 튜닝 및 자체 개발 칩 테이프아웃 전 검증에 활용된다. 이미 한정 수량으로 현물 판매 중이다(공식 측은 “수요가 공급을 초과한다”고 밝혔으며, CEO Patrick Little은 “RISC-V의 데이터센터 진입은 더 이상 먼 비전이 아니다”라고 말했다). 핵심 세부 사항: SiFive는 NVIDIA와 협력하여 CUDA를 이식하고 향후 플랫폼에 NVLink Fusion을 통합할 계획이며, CUDA는 이미 BigSky에서 실제로 구동되어 NVIDIA GPU 상의 현대적 LLM 워크로드의 헤드 노드 역할을 한다——RISC-V 하드웨어가 처음으로 이 능력을 갖추게 되었다.

2.2 IAR와 Neusoft Reach 전략적 협력 체결: RISC-V 차량용 툴체인 보완 (08-24/25 보도)

날짜: 2026-08-24/25 보도 (EET-China 08-25 00:17 베이징; 양측 08-20 상하이에서 계약 체결)　출처: BigGo Finance, EET-China (EE Times China)

임베디드 툴체인 업체 IAR와 Neusoft Reach가 전략적 협력을 체결했다: NeuSAR OS와 IAR 개발 도구의 심층 통합에 집중하여 국내 개발 시나리오를 대상으로 일체형 소프트웨어 및 툴체인 솔루션을 제공하고, AUTOSAR 소프트웨어 생태계와 RISC-V 차량용 칩의 융합을 추진한다; 양측은 “칩—기반 소프트웨어—애플리케이션 개발”을 아우르는 완전한 툴체인을 공동 구축하여 RISC-V 차량용 등급 개발의 툴체인 공백을 메우고 자동차 산업에서의 규모화 배포를 가속할 것이다. 참고: 계약 체결 08-20, 보도 08-24/25로 본 모니터링 기간에 진입, 최초 수록; Neusoft Reach는 국산 차량용 기반 소프트웨어 NeuSAR의 주요 업체이며, IAR은 이전에 SiFive 차량용 E7A/S7A 코어를 지원한 바 있다.

2.3 Andes D23-SE, ISO 26262 ASIL-B/ASIL-D 기능 안전 인증 획득 (08-24 보도)

날짜: 2026-08-24 보도 (New Electronics 18:42 베이징; 원제조사 공고 08-18)　출처: New Electronics, andestech.com

AndesCore D23-SE 프로세서가 ISO 26262 ASIL-B와 ASIL-D 이중 등급 기능 안전 인증을 획득했다 (개발 프로세스가 제2/4/5/7/8부 요건을 충족). D23-SE는 3단 파이프라인, 부분 듀얼 이슈의 에너지 효율 지향 안전 코어로, ABS(잠김 방지 제동), 타이어 압력 모니터링, 에어백, 모터 구동 제어 등 ECU/DCU 시나리오를 커버한다; 이번 인증으로 N25F-SE/D25F-SE/D45-SE와 함께 Andes의 완전한 차량용 안전 코어 라인업을 구성하게 되었다. 참고: 원제조사 공고 08-18 (모니터링 기간 외), 본 기간에는 New Electronics 보도로 수록, 최초 수록.

2.4 LilyGo T-Display K230 Kit: Tech Times, 현행 Ubuntu 실행 불가 보도 (08-24/25)

날짜: 2026-08-24/25 (Tech Times 08-25 03:48 베이징)　출처: Tech Times (gnews)

Tech Times는 “RISC-V AI 포켓 컴퓨터가 현행 Ubuntu에서 외면받다”라는 제목으로 LilyGo T-Display K230 Kit(CoreSet 약 150달러, Kendryte K230 듀얼코어 RISC-V + ESP32-S3-R8 코프로세서, 키보드 및 LoRa 옵션)을 보도했다. 08-21 발표 사건의 2차 확산에 해당하며, 새로운 세부 내용은 다음과 같다: 현행 Ubuntu 배포판에서는 이 기기 위에서 실행할 수 없다(전용 Linux/RTOS 이미지 필요). 이는 엣지 단말 RISC-V의 배포판 지원이 여전히 취약점임을 입증하며, 해당 제품 라인의 후속 관찰 포인트로 삼을 수 있다(2.1 서버 측의 “개봉 즉시 사용 가능한 Ubuntu/RHEL”과 대조를 이룬다).

3.1 XiangShan: COVE/MPT 수정 지속 수렴, 성능과 스토리지 서브시스템 다방면 추진 (08-24~25)

모니터링 기간 내 XiangShan 메인 저장소와 부속 저장소의 19건 커밋을 방향별로 분류하면 다음과 같다:

  • COVE 기밀 컴퓨팅 수렴: fix(MMU, COVE): fix mpt walker bug, pre-flush transaction not properly cleaned (#6314)——MPT walker의 pre-flush 트랜잭션이 제대로 정리되지 않는 문제 수정; fix(mpt): correct mfence operand decoding (#6400)——mfence 오퍼랜드 디코딩 수정. 08-24 리포트의 CoVE/MPT(메모리 보호 테이블) 노선을 이어가며, 구현이 세부 수렴 단계에 진입;
  • AME 행렬 확장 검증: feat(ame): add mcfg state comparison to DiffTest (#944)——차분 테스트에 AME 행렬 구성 상태 비교 추가, 행렬 확장 검증 체계 보강;
  • 스토리지와 성능: feat(extLLC): support external LLC to v3 (#6384), feat(openLLC): enlarge openLLC to 32MB (#6401)(오픈 LLC를 16MB에서 32MB로 확대), feat(prefetch): add L3 prefetch path for stash prefetch (#6274), feat(MMU): improve performance counters (#6383);
  • 검증/엔지니어링: difftest v2→v3 이식(#6387), globalmem C++11 문법 호환, GSIM 빌드 시간 기록 등.

의미: XiangShan은 “기능 연결 완료”에서 “성능 마무리 + 기밀 컴퓨팅 수렴”의 양선 추진 단계로 진입했다. LLC 확장과 L3 prefetch, MMU 성능 카운터 등의 작업은 성능 튜닝이 현재 주 리듬임을 보여주며, AME 행렬 확장 검증도 동시에 추진되고 있다.

날짜: 2026-08-24　출처: spacemit-com/mpp, spacemit-com/docs-chip, spacemit-com/docs-tool

3.3 ESWIN Computing: 홍콩 IPO 공시 누적 적자 52억 위안 초과 (08-25)

날짜: 2026-08-25(Sohu Finance 08:20 베이징 시간, 모니터링 기간 말)　출처: Sohu Finance(gnews)

Sohu Finance가증권신고서를 인용해 보도한 바에 따르면: ESWIN Computing은 누적 적자가 52억 위안을 초과했으며, 상위 5대 고객 매출 비중이 80%를 넘고(2022/2023/2024년 각각 88.7%/90.7%/88.5%), 핵심 제품 단가가 하락하고 있다; 회사는 홍콩 증시 IPO를 추진 중이다. ESWIN Computing은 국내 선두 RISC-V 칩 설계 회사로(RISC-V 아키텍처 기반, 스마트 단말과 인터커넥트 컴퓨팅 두 라인을 아우르며, 후자는 자동차·로봇·산업 시나리오를 대상으로 함), 그 상용화 진척도와 고객 집중도는 국내 RISC-V 선두 기업의 수익 모델을 관찰하는 중요한 샘플이다. 주: 데이터는 언론 보도와증권신고서 요약에서 비롯되었으며, 공식 공시 문서를 기준으로 한다; 보도 시점은 본 모니터링 기간 말단에 위치하므로 기간 내 이벤트로 수록한다.

4. 중점 방향 특별 장: 임바디드 인텔리전스와 로봇

4.1 신규 전용 뉴스 없음: 엣지 컴퓨팅과 로봇 시나리오 지속 관찰 (08-24)

날짜: 2026-08-24　출처: gnews 로봇 전용 검색(“risc-v” robot when:3d, 임바디드 인텔리전스 RISC-V when:7d), 관찰자(gnews)

기간 내 로봇 전용 검색은 08-18~21 옛 뉴스(엣지 RISC-V 돌파론, 르네사스 임바디드 인텔리전스 배치, Jindie K3 양산 하프마라톤 완주)만 적중하여 신규 전용 뉴스 없는 날로 판정. 관련 단서:

  • ICDIA 2026 폐막 보도(관찰자 08-24): 대회에 임바디드 인텔리전스 특별 세션과 AI 로봇 전시 구역을 마련, 다방면에서 “인지 지능에서 물리적 실행 착지까지”의 경로를 논의——08-23에 이미 보도된 이벤트의 후속으로, 임바디드 인텔리전스는 이미 국산 IC 대회의 고정 의제;
  • 엣지 컴퓨팅 하방 확산 추세 지속: Jindie K1/K3 비전 매트릭스, K230 Kit, ESP32-S31 리눅스화 등이 RISC-V 디바이스가 AI/로봇 워크로드를 담지하는 경계를 계속 확장; ESWIN Computing 공식 사이트는 인터커넥트 및 컴퓨팅 칩을 “주로 자동차, 로봇 및 산업 시나리오에 적용되어 지능체가 인지, 처리 및 실행 능력을 갖추게 한다”고 포지셔닝하며, 그 IPO 공시(3.3)는 해당 사업 라인의 고객 집중도가 극히 높음을 보여줌;
  • 서버 측 신규 변수: BigSky + CUDA(2.1)는 임바디드 인텔리전스의 클라우드 학습/추론 기반에 RISC-V 새 옵션을 제공, 후속 추적 포인트로 삼을 만함.

5. 요약과 트렌드 관찰

  1. RISC-V 서버화가 ‘실물 납품’ 단계에 진입: BigSky 2U 랙 서버 한정 현물 공급 + CUDA 실제 구동(NVIDIA GPU LLM 부하 헤드 노드 역할) + NVLink Fusion 로드맵, 여기에 Linux 7.3 서버 특성 확장(QoS 식별자/카운터 위임/CFI)과 ISO 표준화 추진이 겹치며——데이터센터 ‘마지막 1마일’ 소프트웨어 스택이 집중적으로 보완되고 있음;
  2. NVIDIA CUDA 지원이 2025년 입장 표명에서 2026년 Hot Chips 기술 요구사항 세분화로(RVA23, PCIe 일관성, P2P)——’서버급 CPU + 플랫폼’이 하드 요건이며, P870-D급 고성능 코어와 RVA23 서버 규격 생태계에 직접적 호재;
  3. 국내 분화 지속: XiangShan 양축 추진(COVE 수렴 + 성능/스토리지 다듬기, 19건 커밋, 모니터링 기간 내 최다 활동); Intes Secspace 드라이버/문서 일상적 작업; ESWIN Computing 홍콩 IPO 공시에서 누적 적자 52억 위안 초과, 고객 집중도 높음——국내 선두 RISC-V 설계 기업의 상업화 압력이 표면화되고 있어 지속 추적 필요;
  4. 차량 규격 생태계 보강: IAR×Neusoft Reach 툴체인 협력, Andes D23-SE ASIL-B/D 인증, 여기에 ESWIN EAI8800(7월 이중 인증)——RISC-V 차량 규격 ‘IP—툴체인—기반 소프트웨어—칩’ 체인이 점차 닫히고 있으며, AUTOSAR 생태계의 RISC-V 이전이 가속;
  5. 오픈소스 측 활기 회복: CPython tier 3, Linux 7.3 다중 확장 병합, HN의 CUDA-on-RISC-V 논의 고조(68점), 최근 이틀간의 정체와 대비됨; Python 공식 지원이 AI 소프트웨어 스택의 핵심 고리 하나를 보완.

한계 설명: BigSky 성능 데이터와 CUDA 구동 세부사항은 제조사 보도자료 기준이며, 독립 평가는 아직 없음; ESWIN Computing 재무 데이터는 언론 보도와 공모서 요약에서 비롯되었으며, 공식 공시 문서를 기준으로 함; ISO/IEC DIS 26791-1 페이지는 크롤링 방지로 직접 수집 불가, 구체적 기술 범위는 ISO 공식 웹사이트 기준; XiangShan 커밋 내용은 commit message 기준이며, 마이크로아키텍처 수준 검증 세부사항은 다루지 않음; IAR×Neusoft Reach 계약 체결은 08-20 사건으로 보도가 모니터링 기간에 진입한 것이며, 사건 자체는 모니터링 기간 내에 발생하지 않음.
