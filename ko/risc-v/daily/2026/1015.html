오늘의 주요 사항: SpacemiT 엣지 Agent 풀스택 집중 공개: BiBit GUI 및 음성 서비스 1.0Beta1 릴리스, Bianbu AgentOS 컴포넌트 오픈소스화

날짜: 2026-10-14　출처: bibit Release 1.0Beta1 (10-14), bibit-voice Release 1.0Beta1 (10-14), bianbu-agent-runtime 초기 임포트 (10-14), bianbu-agent-memory 초기 공개 스냅샷 (10-14)

10-13의 집중 저장소 생성 (지난 호 데일리 리포트에서 보도)에 이어, SpacemiT는 모니터링 기간 내에 엣지 Agent 시스템 소프트웨어 스택 (Bianbu AgentOS) 전체를 공개로 전환했다: 데스크톱 BiBit GUI와 오프라인 음성 서비스 Bibit Voice가 1.0Beta1을 릴리스하고, Agent 런타임, 메모리 서비스, 보안 컴포넌트 등을 집중 오픈소스화했다. 요점:

  • BiBit GUI(1.0Beta1): Agent 시스템 어시스턴트를 위한 데스크톱 프런트엔드로, 오픈소스 프로젝트 Jan을 코드 골격으로 삼았다(React 19＋Tauri 2＋Rust, Yarn 4.5.3 빌드 체인). 현재 대화 상호작용, 리치 메시지, 첨부파일, 세션 기록 및 설정 인터페이스를 유지하고 발전시키고 있다. Bianbu 4.x riscv64를 대상으로 Debian 네이티브 패키지를 제공한다(소스 내 Yarn 버전을 고정하여 RISC-V 빌드 머신의 메모리 제약에 적응). Agent Runtime은 당분간 Jan 호환 구현을 계속 사용하며, 이후 Adapter를 통해 정식 런타임에 연결할 예정이다.
  • bianbu-agent-runtime(최초 오픈소스화): YAML 설정 기반의 Agent 서비스로, 스스로를 Bianbu AgentOS의 런타임 핵심이라고 설명한다. 세션은 이벤트 스트림(멀티엔드 동일 프로젝션)이며, 플러그인은 Tool／Skill／Hook／MCP／Console 페이지를 기여할 수 있고, securityd 서명 매니페스트와 Tool 승인 등의 보안 경계를 갖는다(프로덕션 모드 fail-closed). 현재는 K3(riscv64, Bianbu 4.0)만 지원한다.
  • bianbu-agent-memory: 디바이스 측, 로컬 우선 메모리 서비스(Rust 데몬＋Python SDK＋Unix socket 프로토콜)로, L1 세션 이벤트／L2 작업 요약／L3 장기 기억의 세 계층 구조를 가지며, 로컬 전문 검색, SQLCipher 암호화, 버전 충돌 감지 및 네임스페이스 격리를 제공한다. CLI, MCP 서비스와 Runtime Bridge를 제공하며 Hermes 및 DeepSeek Harness 어댑터를 포함한다.
  • Bibit Voice(1.0Beta1): K3／Bianbu Desktop을 위한 오프라인 음성 서비스 스택으로, 웨이크워드 감지(KWS), 음성 활동 감지(VAD) 및 음성 인식(ASR, SenseVoice／Qwen3-ASR)을 포함하며, PipeWire 캡처와 sherpa-onnx SpacemiT runtime 기반이다. 외부에 두 계층의 Unix socket과 MCP(8개 도구)를 제공하며, 웨이크업 응답음 “나는 여기 있어”가 패키지에 함께 배포된다.
  • 동일 배치 오픈소스 컴포넌트: bibit-intent(엣지 우선 의도 라우팅 및 도구 실행), bibit-filesearch(로컬 파일 검색 서비스), bibit-runtime-plugin, bianbu-agent-security가 최초 공개되었으며, mpp 미디어 처리 라이브러리는 MIT 라이선스로 전환하고 저작권 고지를 통일했고, ai-sdk는 KWS 서브모듈과 중영문 아키텍처 다이어그램을 추가했으며, docs-product는 V100 시리즈(C2201／S5236／G5201) 제품 페이지 골격을 신설했다.

위 컴포넌트는 K3 하드웨어, Bianbu 배포판과 함께 «칩—시스템—Agent 런타임»의 수직적 조합을 형성한다. Bianbu AgentOS가 단일 플랫폼(K3)에서 먼저 검증한 후 다른 플랫폼으로 확장하는 노선은 이미 비교적 명확해졌다.

1. 오픈소스 커뮤니티와 소프트웨어 생태계

1.1 Linux 커널 패치로 «이 머신이 RVA23을 준수하는가»를 원클릭으로 확인 가능

날짜: 2026-10-14　출처: Phoronix: Linux Finally Making It Easier To Answer The Question: “Is This RISC-V System RVA23?”(10-14), LPC 2026 발표 《RVA23 in practice》 자료(10-02)

Phoronix 보도: Linux 사용자가 곧 «한 번에» «내 RISC-V 시스템이 RVA23을 준수하는가»라는 질문에 답할 수 있게 된다——머지 대기 중인 커널 패치가 단일 조회 기능을 제공한다(현재는 /proc/cpuinfo, hwprobe와 프로필 요건을 결합하여 항목별로 비교해야 하며, Ubuntu 측 도구는 이전까지 «probably RVA23»만 제시할 수 있었다). 보도에 첨부된 이미지는 SpacemiT K3 한 대의 RVA23 리포트 스크린샷이다. 배경(본 시리즈의 이전 보도와 연결): 이 기능은 LPC26에서 공개된 **riscv_hwprobe 단일 비트 방안(KEY_BASE_BEHAVIOR: IMA RVA23U64, 부팅 시 전체 ISA 비트맵에서 한 번에 계산)**이다. 시리즈 패치는 Andrew Jones가 RFC를 시작했고 현재는 Guodong Xu가 추진 중이며, 10-09에 v8에 도달했다(11개 patch 중 앞 8개가 riscv/for-next에 수록됨). v9는 RVA22／RVA20 등급 비트를 보완할 예정이다. RVA23 프로필은 통일된 현대 RISC-V 바이너리 배포에 매우 중요하다(Ubuntu 현대 버전은 이미 이를 베이스라인으로 지정했으나, 준수하는 하드웨어는 여전히 제한적이다).

1.2 RISE 프로젝트, SpeexDSP의 RVV 벡터 최적화 성과 발표: 리샘플링 최대 4.88배 가속

날짜: 2026-10-13~10-14　출처: RISE Project: Accelerating Audio Processing with SpeexDSP Optimizations for RISC-V(10-13), Hacker News 토론(10-14)

RISE(RISC-V 소프트웨어 생태계) 프로젝트가 RP020 결산 성과를 게재했다: 실시간 오디오 기반 라이브러리 SpeexDSP(오디오 리샘플링, 에코 제거, 지터 버퍼 및 전처리, VLC, Firefox, Wireshark, PulseAudio, Mumble 등에서 광범위하게 사용됨)에 수기 작성 RVV 어셈블리를 도입하고 빌드 및 검증 인프라를 현대화했다. 요점:

  • 성능: 수기 작성 벡터 리샘플링 커널과 「컴파일러 자동 벡터화 C」 비교 — 부동소수점 커널 3.71배(Clang 18)／3.59배(GCC 13) 가속; 고정소수점 커널 2.69배(Clang 18)／4.88배(GCC 13) 가속(후자는 GCC가 자동 벡터화하지 못함).
  • 크로스 하드웨어 검증: RVV의 길이 무관 특성 덕분에 동일한 어셈블리가 SpacemiT K1(VLEN=256)과 Canaan K230(VLEN=128) 두 물리 플랫폼 모두에서 유효.
  • 검증 인프라 외부 파급 효과: Meson＋Checkasm 검증 과정에서 SSE2 커널의 8년 된 데이터 의존성 결함을 발견하여 수정(내적 커널이 이전에는 스칼라 C보다 0.58~0.75배 느렸음).
  • 조직 형태: Google 엔지니어와 RISE 협력으로 추진(기술 리드 Nathan Egge, 계약자 FFlabs／Tristan Matthews), RISE가 4만 달러 지원.

1.3 openRuyi: 펌웨어 라인 「Ruyi Firmware 20261014」 릴리스, K3 듀얼 클러스터 CPU 모드 선택 적용

날짜: 2026-10-14　출처: Ruyi Firmware 20261014 Release(10-14), edk2-ruyi: K3 persistent CPU selection modes(10-14), openRuyi 커밋 기록(10-14)

openRuyi 펌웨어 라인이 「Ruyi Firmware 20261014」를 릴리스했다. 핵심 기능은 K3 플랫폼의 CPU 클러스터 모드 선택이다: UEFI Setup에 모드 스위치가 추가되어 설정이 SPI 전용 섹터에 영속화되고 coreboot가 OpenSBI 시작 전에 읽는다(다음 부팅 시 적용, 펌웨어 업그레이드 시 기본값으로 복원). 세 가지 모드를 제공한다 — X100 only(기본, 8코어, RVV VLEN 256, H 확장 유지), X100＋A100(16코어), A100 only(8코어, VLEN 1024) — fastfetch 등의 도구에서 k3／k3-x100-a100／k3-a100로 표시된다. 구현 세부 사항: A100-only 부팅은 SBI HSM을 통해 SEC를 hart 0에서 hart 8로 이관(원래 hart가 정지하기를 기다린 후 스택 재사용), UEFI 핸드오프 트리에서 X100 노드를 비활성화하되 물리적 IMSIC 슬롯 번호는 유지, 디바이스 트리 루트 호환 문자열이 모드를 동기 반영하여 사용자 공간 명명에 제공(Linux 소스 수정 불필요). 메인 저장소 측에서는 Mesa 26.2.4 업그레이드와 PowerVR(pvr) 최적화 백포트, mesa-gallium의 mesa-vulkan-drivers 권장 등 SPECS 업데이트를 동시에 머지했다; openRuyi 공식 웹사이트 뉴스 페이지에는 새 버전이 없다(최신은 여전히 2026.09).

2. 제품 및 생태계 동향

2.1 RVSC2026 회의 전 업데이트 집중: 참가업체 홍보 자료 대량 게시, 의제 및 전시장 정보 준비 완료; Zhaosong Technology 기능 안전 툴체인 발표 예고

날짜: 2026-10-13~10-14　출처: 서밋 공식 웹사이트: 다수 RISC-V 생태계 기업 서밋 집결 (10-14), 대회 의제, 동시 진행 활동, Zhaosong Technology 참가 예고 (10-14)

3.2 ESWIN Computing: 오픈소스 RISC-V 행렬 확장(AME) BF16 GEMM 테스트 벡터 라이브러리

날짜: 2026-10-13~10-14　출처: eswincomputing/riscv-matrix-gemm-vectors(10-14 업데이트), 업데이트 커밋(10-14)

ESWIN Computing이 riscv-matrix-gemm-vectors 저장소를 오픈소스로 공개했다(10-13 생성, 10-14 저작권 및 README 보강). RISC-V 행렬 확장(AME) 사양 제안 v0.6.0을 대상으로 하는 BF16×BF16→FP32 행렬 곱셈 누산 테스트 벡터 집합으로, 각 테스트 케이스는 베어메탈 프로그램(연산 실행, 자체 검증 및 판정 결과 기록)이며 구현 독립적인 참조값과 결과 검사기 check.py가 함께 제공된다. 판정에는 표준 반올림 오차 범위( Ĉ−C* ≤ γ(G)·Σ a·b , 기본값 G=K)를 채택하여 비트 단위 비교 대신 사양이 허용하는 “무순서 합산” 구현 차이를 수용한다(양수와 음수 곱이 상쇄될 때 정확한 결과가 정확한 합에서 수천 ULP 떨어질 수 있음). 동시에 “모든 규격 준수 구현에서 결과 비트가 동일한” 두 개의 테스트 케이스를 제공하여 잘못된 반올림을 검출한다. 참조값과 판정 기준은 특정 명령어 집합에 의존하지 않아 다른 행렬 확장 구현에도 재사용할 수 있으며, 국내 벤더가 AME 생태계를 위해 제공한 테스트 인프라 기여에 해당한다.

4. 임바디드 인텔리전스와 로보틱스 특별 장

4.1 엣지 Agent 인프라, 「시스템급 패키징」으로: Bianbu AgentOS와 K3의 조합 납품 관찰

날짜: 2026-10-14　출처: bianbu-agent-runtime(10-14), bibit-voice(10-14), spacemit-robotics 조직 저장소

이 모니터링 기간 임바디드 인텔리전스와 로봇 측의 주요 관찰 포인트는 「엣지 Agent 인프라의 시스템 레벨 패키징」이다. Jindie Shikong은 Bianbu AgentOS 명의로 데스크톱 프런트엔드(BiBit), 런타임, 로컬 메모리, 오프라인 음성(KWS／VAD／ASR)과 보안 컴포넌트를 포함한 전체 체인을 공개했으며(오늘의 중점 참조), K3(riscv64)를 최초 출시 및 현재 유일하게 지원하는 플랫폼으로 명확히 지정했다. 로봇／엣지 디바이스에게 이는 「음성 웨이크업—의도 이해—도구 실행—장기 기억—감사 보안」의 자체 배포 가능한 오픈소스 스택이 RISC-V에서 처음으로 완전한 세트의 샘플을 갖추게 되었음을 의미하며, 산발적인 SDK가 아니다. 이에 맞춰 하드웨어 측 K3의 CPU 클러스터 모드 선택(X100／A100, 1.3 참조)은 「성능 코어로 추론 실행, 에너지 효율 코어로 제어 실행」의 이기종 분업에 펌웨어 레벨 옵션을 제공한다. 상대적으로 로봇 전문 조직 spacemit-robotics는 모니터링 기간 내 새로운 푸시가 없었으며(주변기기 IMU／모터／인식 라이브러리 최근 푸시는 10-12), 「칩＋Agent 소프트웨어 스택＋시나리오 패키징」의 조합 딜리버리는 여전히 심화 중이며 소프트웨어 스택은 「사용 가능」에서 「유지보수 가능, 감사 가능」으로 나아가고 있다.

5. 요약 및 트렌드 관찰

  • 엣지 Agent가 RISC-V 소프트웨어 스택의 새로운 초점으로 부상: Jindie Shikong이 Bianbu AgentOS 전체 스택(GUI／런타임／메모리／음성／보안)을 집중 공개하고 K3로 선행 검증——Lanxin Suanli 등의 「서버화」 서사와 대조를 이루며, RISC-V가 엣지 AI Agent 인프라 방향에서 완전한 세트의 오픈소스 스택을 등장시켰다.
  • 인프라 양쪽 끝 동시 보강: Linux 커널 rva23u64 단일 비트 쿼리가 거의 착륙(Phoronix 보도, v8 부분은 이미 riscv/for-next에 진입, v9는 진행 중), RISE가 SpeexDSP에 수기 RVV 벡터 커널을 보강(리샘플링 최대 4.88배)——「자격 인증(RVA23)＋멀티미디어 성능(RVV)」 두 가지 주선이 동시기에 추진되고 있다.
  • 서밋 주 임박: RVSC2026(10-18~20 선전) 사전 자료(보도자료, 의제, 전시장 도면, 동시 진행 행사)가 모두 준비되었고, 10-17 Jindie Shikong 개발자 대회, 10-21 GBA／HK Day, 10-22 Xuantie 베이징 세미나가 겹친다. Ubuntu 26.10이 첫 공식 RISC-V 데스크톱 이미지를 갖추어 10-15에 발표될 예정으로, 다음 호의 중점 관찰 대상이다.
  • 국내 엔지니어링 측 고밀도 출력: Damo Academy Xuantie가 BF16 벡터 테스트를 보강, Eswin이 AME 테스트 벡터를 오픈소스화, Xiangshan이 L2 메모리 접근 지연을 최적화하고 ICache를 수정, Suanneng이 부팅 체인과 서버 펌웨어를 리팩터링, SiSpeed가 SLogic 두 버전을 연속 발표.
  • 한계 설명: Phoronix 본문은 사이트 보호 제한을 받아 1.1 항목은 해당 RSS 요약과 LPC26 공개 자료를 교차하여 작성했다. RVSC2026 항목의 일부 정보는 서밋 공식 웹사이트와 위챗 공식 계정에서 비롯되었으며 공식 발표를 기준으로 한다. Esin 테스트 벡터 저장소의 컴플라이언스 판정 세부 사항은 해당 README를 기준으로 한다.
