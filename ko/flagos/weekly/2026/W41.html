FlagOS 위클리 리포트 (2026-09-30 ~ 2026-10-07)

2026-10-07 Kubuds

보고 기간: 2026년 9월 30일(수) ~ 10월 7일(수), 총 8일 — 국경절 연휴 특별 집계 기간 자료 출처: 본지 일일 FlagOS 동향 리포트의 연휴 전 마지막 호(2026-09-30)와 연휴 후 첫 호(2026-10-08, 모니터링 기간 말단 연결 검증용); 10월 1일~7일 연휴 기간에는 데일리 리포트 휴간, 연휴 동향은 본 조직의 전체 54개 GitHub 저장소에 대한 커밋, PR 및 태그 점검을 기준으로 함(점검은 10-08 오전까지 확장), 뉴스 측은 연휴 기간(약 9일) 다중 키워드 공개 검색을 기준으로 함 편제 설명: 연휴 기간에도 조직의 개발은 멈추지 않음: 커밋 합계 801건(FlagQuantum 712건), PR 머지 412건(FlagQuantum 312건), 신규 PR 447건(FlagQuantum 331건); 16개 저장소에 푸시가 있었고, 12개 저장소에서 기간 내 기본 브랜치 커밋이 기록됨. 대외 뉴스 측 컴포넌트급 검색은 조용한 상태를 유지했으며, 산업 측 초점은 DeepSeek가 9월 30일 Ascend를 겨냥해 오픈소스한 인프라스트럭처 컴포넌트임(제5장 참조). 연휴 후 첫날(10-08) 복귀 리듬은 예정대로 회복: 당일 오전 점검 시점까지 14건의 PR 머지가 기록됨.

1. 이번 주 주요 뉴스

  • 휴가 기간에도 개발 강도는 줄지 않음: 8일 모니터링 기간 801건 커밋, 412건 PR 병합 (09-30 ~ 10-07): FlagQuantum 단일 저장소가 712건 커밋(88.9%)과 312건 병합을 기여하며 조직 휴가 기간 개발의 절대적 주력임; 나머지 저장소는 합계 89건 커밋으로, 멀티벤더 CI 마이그레이션과 문서 배치에 집중됨. 커밋 리듬은 10-01부터 매일 상승(FlagQuantum 단일 저장소: 10-01 60건, 10-05 101건, 10-06 194건, 10-07 122건), 연휴 중후반 강도가 전 기간 중 최고치.
  • FlagQuantum 분산 인증 전역 종결: two-node 전 라인 인증 릴리스 궤도 진입 (10-01 ~ 10-08): 10-01 #312는 two-node 상태 벡터, MPS 및 텐서 네트워크 훈련을 production_supported로 승격; #318 / #321은 실측 증거로 두 노드 claim을 재기록하고 블로커를 역추적; 10-06 #535는 두 노드 상태 벡터를 인증하고 MPS / TN 용량 천장을 측정; 10-08 아침 #587은 두 노드 MPS 훈련을 인증하고 TN 용량 상한을 기록——two_node_mps_training이 release_certified로 승격. 인증 허용 오차 게이트(#292)와 증거 고정 버전(#348)도 동시 보강.
  • FlagGems: KernelGen 공급측 대진 + 멀티벤더 CI 마이그레이션 (10-01 ~ 10-06): kernelgen-dev 브랜치 34건 커밋——226개 연산자 정의 및 테스트(#6853), 70개 원시 연산자 정의(#6860), 제1 ~ 28차 및 마무리 배치 테스트 스위트(#6799 ~ #6839), 누락 정의 보강(#6862, thnn_conv2d); 메인 브랜치 14건——hygon / metax / mthreads / iluvatar 4개 백엔드 테스트를 runtime 이미지로 이관(#6844), CPU runner 사전 설치 플랫화(#6847), flagtree 0.7.0 백엔드 파싱 및 PPU 지원(#6863 / #6852). 모니터링 기간 병합 합계 47건.
  • build-infra 2.2 확정, 2.3 개시 (10-01): 저녁 17:30에 주석 태그 v2.2.0 생성(“Release 2.2.0” 표기; 해당 저장소는 GitHub Release 객체가 아닌 태그로 버전 라인 관리); 이후 “Bump base version to 2.3.0”(#1316) 및 루트 디렉터리 정리(#1317) 병합, 저녁에 워크플로 정비 배치(#1318 ~ #1321) 완료——인프라 저장소 개발 베이스라인이 공식적으로 2.3 라인으로 전환.
  • FlagCX CRL 전송 강화 6연타 (09-30 ~ 10-04): #633 kernel proxy에 공유 RMA 전송 연동, #635 collective proxy와 정렬 멀티채널 / 다중 QP 전송 통합, #636 대칭 윈도우 및 MR 수명 주기 강화, #638 GET 데이터를 게시 완료 전 flush, #639 원격 가시성 flush 시맨틱 통일(별도 #637은 이미 무효화된 이미지 빌드 워크플로 정리)——전송 계층 정확성 강화가 휴가 기간 내내 관통.
  • FlagFFT 멀티플랫폼 최적화 브랜치 연휴 기간 추진 (10-02 ~ 10-05): MetaX maca-3d-opt와 Ascend npu-2d / npu-3d-opt 브랜치 10-02 ~ 10-03 다회 푸시; Hygon 측 10-03 ~ 10-04 연속으로 codex/hcu-fourstep-c2r, codex/hcu-3d-route-fix 및 -dev 분기 개설; Moore Threads musa-3d-opt는 연휴 전 시작 이후 지속 추진. 기본 브랜치에는 신규 병합 없음, 성과는 브랜치 형태로 리뷰 대기; 저장소 최종 푸시 10-05 16:10.
  • 회원 기관 연휴 배치 지속 유입 (09-30 ~ 10-08): MetaX W8A8 INT8 행렬곱(#6572) 병합, Hygon bmm / baddbmm 신규(#6865 / #6866), Kunlunxin XPU3 SDNN 46-marker 수정 배치(#6867), DAMO Academy XuanTie ADDMM 시리즈 성능 배치(#6859), Ascend 수정 3연타(#6848 ~ #6850) 및 Qwen3.6 추론 경로 최적화(sglang-plugin-FL #137), Enflame 특화 연산자 4연타(FlagGems-vllm #889 ~ #892), Cambricon rotary embedding 백엔드(FlagAttention #84)——상세는 제4장 참조.
  • 산업계 초점: DeepSeek, Ascend 대상 인프라 컴포넌트 오픈소스화 (09-30): TileLang 고급 언어 컴파일 도구, 연산 라이브러리 및 분산 통신 라이브러리를 포괄하며, 모든 컴포넌트는 NVIDIA 플랫폼 대상 오픈소스 컴포넌트(DeepGEMM, DeepEP, TileKernels, FlashMLA, DeepSelect)와 일대일 대응; 동시에 Huawei와 공동 추진 중인 Ascend 950 기반 128카드 초노드 방안(UBL128 네트워킹 및 ASC-COMM 통신 라이브러리 지원) 공개. FlagOS 조직 외 동향으로, 산업 배경으로 수록(제5장 참조).

2. 버전 및 릴리스 동향

주기 전환: 2.2 확정, 2.3 베이스라인 개시

  • build-infra v2.2.0(10-01 17:30): 주석 태그 “Release 2.2.0”이 생성되어 2.2 주기 빌드 인프라의 최종 확정을 가리킨다. 해당 저장소는 태그(v2.1.0 / v2.1.1 / v2.2.0)로 버전 노드를 관리하며, GitHub Release 객체는 발행하지 않았다.
  • 2.3 베이스라인 개시(10-01 저녁): #1316 “Bump base version to 2.3.0”이 17:37에 병합되었고, #1317 루트 디렉터리 정리, 저녁 #1318 ~ #1321 워크플로 정비(표시 이름 통일, 파일 이름을 .yml로 규격화, 릴리스 워크북을 파일 이름 기준으로 트리거, 기본 이미지 빌드 로직 인라인화)가 이루어졌다. 인프라 저장소는 2.3 개발 모드에 진입했다.
  • 연휴 전 연결(09-30 새벽): 새벽에 5건이 병합되어 2.2 마무리를 완료했다. build-infra #1312(EXTRA_PYPI 폴백을 Tencent 미러로 전환), #1313(megatron 애플리케이션 이미지 tag 2.2.0-0.2.3 기록), Torch-FL #483 / #484(wheel 선행 릴리스 수정), docs #530.

컴포넌트 tag와 Release 목록(모니터링 기간 내)

  • 전체 저장소 태그 스캔: 본 조직의 54개 저장소를 순차적으로 점검한 tags / releases 원자 소스에서 모니터링 기간 내 유일한 신규 태그는 build-infra v2.2.0(10-01)이었다. 나머지 컴포넌트는 신규 버전 릴리스가 없었다(2.2 정식 태그 배치는 09-24에 완료되었으며, 연휴는 그 이후 첫 동결 정온기였다).
  • FlagQuantum: 최신 태그는 여전히 v0.1.0 계열(06월)이며, 개발 라인은 현재 release_certified 인증 단계에 있다(3장 참조). 연휴 기간에는 신규 태그가 생성되지 않았다.
  • 개발 라인 상태: FlagGems 5.5 개발 라인(KernelGen 테스트 배치), FlagGems-Experimental(Nvidia KernelGen 연산자 배치 지속 병합), FlagGems-vllm 0.3.0-dev1, FlagTree(PPU / mthreads 백엔드 추진) — 2.3 주기 컴포넌트는 연휴 기간에도 개발 상태를 유지했다.

이미지와 아티팩트

  • 애플리케이션 이미지 라인: build-infra는 연휴 기간 기록 마무리 위주였다. megatron_rl mthreads-musa5.2.0 이미지 기록(#1313), mthreads sglang 문서 수정(#1314), sync-to-remote 워크플로에서 authorize 작업 제거(09-30).
  • runtime 이미지 매트릭스: FlagGems는 hygon / metax / mthreads / iluvatar 네 백엔드 테스트를 한 번에 runtime 이미지로 이관했으며(#6844, 10-01), 이에 맞춰 단일 저장소 CI를 조정했다(#6840 ~ #6843). flagtree 0.7.0 버전 정렬과 PPU 지원은 3장을 참조.

6. 트렌드 관찰

  • 휴일 집중식 개발이 다시 인식을 갱신: FlagQuantum이 약 90%의 커밋 비중으로 모니터링 기간의 절대적 엔진이 됨(10-06 단일 일 194건 피크 포함), 조직의 나머지 부분은 저전력 모드로 운영(CI 마이그레이션, 문서, 이슈 생성)——연휴 후 리뷰 큐가 일시에 대량으로 소화될 것(첫날 14건 병합으로 이미 징후 확인).
  • 릴리스 엔지니어링이 2.3 교대 완료: build-infra가 “2.2 확정 태그 → 2.3 베이스라인 전환 → 워크플로 정비”를 일사천리로 완수; 연휴 후 2.3 개발 라인(FlagGems 5.5, FlagGems-vllm 0.3.0, vLLM 0.28 적응)이 가속 합류할 것으로 예상.
  • KernelGen이 “연산자 생성”에서 “정의 및 테스트 공급” 단계로 진입: 226 + 70건 정의와 29배치 테스트 스위트가 집중 병합——연산자 공급 측이 2.3의 커버리지 스프린트를 위해 산업화 기반을 다지는 중.
  • 벤더 협업의 휴일 저강도 상시화: 4개 백엔드 runtime 이미지 마이그레이션과 다수 최적화 / 수정 이슈 생성이 공휴일에도 지속 유통, 협업 리듬이 이미 평일 박자에 의존하지 않음; 대형 작업(Hygon bmm 시리즈, Ascend 수정 삼연타)은 연휴 전 이슈 생성, 연휴 후 리뷰의 리듬을 선택.
  • 양자 라인의 “증거 우선” 방법론 출력: 인증 campaign에서 증거 수정 선언까지(#595 한 번의 선언으로 16건 수정), release_certified 상태 획득이 재현 가능한 측정과 감사 가능한 선언을 근거로 함——이 엔지니어링 규율은 2.3의 다른 구성요소 라인에 방법론적 참조 가치가 있음.
  • 다음 관찰 지점: 10-17 대회의 대외 발표물과 양자-지능 융합 특별 세션; 2.3 개발 라인 합류와 첫 배치 태그; Hygon bmm 시리즈, Ascend 수정 삼연타, FlagFFT 브랜치 최적화의 리뷰 반영; KernelGen 배치의 합류 방향; community 목록의 2.2 마무리에 대한 스냅샷 갱신.
