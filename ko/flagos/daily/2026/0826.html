1. 오픈소스 프로젝트 진행 상황(GitHub 동향)

모니터링 기간 개요: org 내 52개 저장소 중 17개가 모니터링 기간 내 푸시 발생; commit search에서 모니터링 기간 내 고유 커밋 87건 매칭(build-infra 55, FlagGems 19, FlagTree 4, Torch-FL 4, FlagGems-vllm 2, sglang-plugin-FL 1, FlagCX 1, FlagScale 1), 이 외에 TransformerEngine-FL, Megatron-LM-FL 각 1건. 모니터링 기간 헤드라인은 Hygon DCU의 FlagOS ‘학습-통신-추론’ 3개 라인 합류: FlagScale에 BW1000 CI 추가, FlagCX에 DCU 적응 및 CI 추가, sglang-plugin-FL에 HCU vendor 백엔드 추가. 본 모니터링 기간의 주된 흐름은 ‘신규 벤더 백엔드 합류 + 기존 검증 매트릭스의 FlagGems 5.3.5 신버전 라인에서의 재검증’으로 요약할 수 있다.

1.1 Hygon 3개 라인 합류——FlagScale BW1000 CI, FlagCX DCU 적응, sglang-plugin-FL HCU vendor(모니터링 기간 헤드라인)

출처: FlagScale #1272, FlagCX #541, sglang-plugin-FL #35(8/25 11:48-19:44 머지)

  • FlagScale(학습): #1272가 학습 툴체인에 Hygon BW1000 CI 지원을 추가(8/25 11:48 머지)——Hygon DCU가 FlagScale 공식 CI 매트릭스에 진입.
  • FlagCX(통신 라이브러리): #541이 Hygon DCU 적응 및 CI workflow를 완료(8/25 12:32 머지)——크로스칩 통신 라이브러리에 Hygon 백엔드 보강.
  • sglang-plugin-FL(추론): #35가 HCU vendor를 신규 추가(8/25 19:44 머지)——SGLang 0.5.11에서 DCU 플랫폼을 지원: 벤더 감지 및 초기화, DCU 디바이스 관리, 커널 최적화, 기본 추론 및 serve 테스트 완료.

해석: 이는 하이광(Hygon)이 FlagOS 생태계에서 「FlagSparse DCU 테스트 견고성」(8/22-24)에서 「학습·통신·추론 3개 라인 공식 지원」으로 나아가는 결정적 도약이다. 이로써 FlagOS 멤버 기관 중 GPU/DCU 제조사(무어 스레드, 엔플레임, 일루바타 코어엑스, 메타엑스, 캄브리콘, 하이광)가 거의 전부 공식 CI/백엔드 매트릭스에 진입했으며, 하이광은 그중 가장 최근에 3개 라인 커버리지를 완성한 기업이다. 어제 리포트에서 관찰된 「추론 측 검증 매트릭스 집단 그린 전환」이 무어 스레드와 메타엑스로 확산되었고, 이번 모니터링 기간에 하이광이 추가되면서 검증 패러다임의 템플릿화 복제 효과가 지속적으로 나타나고 있다.

1.2 build-infra: FlagGems 5.3.5 버전 추진, 캄브리콘/메타엑스 다중 백엔드 재검증 (08-25/08-26)

출처: #534(flaggems 5.3.5 bump), #561(캄브리콘 재검증), #535(메타엑스), #558(엔플레임), #560(일루바타 코어엑스)

  • FlagGems 5.3.5, app image 의존성 라인 진입: #534는 build 설정에서 flaggems를 5.3.5로 bump하고(8/25 15:10), flaggems release workflow도 함께 간소화했다(#555) — 이는 FlagOS 2.1(6/24, FlagGems v5.3.0) 이후 연산자 라이브러리가 이미지 라인에서 이루어진 또 한 번의 버전 추진이다.
  • 캄브리콘(Cambricon) 재검증: #538/#539에서 neuware4.7.2 app image tag를 기록한 후, vllm 0.20.2의 T 열 셀을 pending으로 재설정하여 5.3.5 재검증을 대기시켰으며, #561(8/26 07:53 병합)이 neuware4.7.2 + flag_gems 5.3.5 검증을 완료하고 종료했다.
  • 메타엑스(MetaX): #533은 maca3.7.2.1의 triton scalar-return 버그를 기록했고, #535는 5.3.5 수정 후 해당 기록을 종료하고 maca3.8.1.3 검증 비고를 추가했으며, #526은 metax 백엔드 vllm app image tag 2.1.2-0.2.1_g3bc66eb.d20260825를 기록했다.
  • 엔플레임(Enflame): #558은 triton_gcu의 TOPS를 1.10.6으로 업데이트했다(8/25 22:43).
  • 일루바타 코어엑스(Iluvatar): #560은 runtime에 filelock 의존성을 추가했으며(8/25 23:15, 다음 날 #562에서 롤백 — 의존성이 이미 이미지에서 제공됨),
  • Megatron 측: #527/#528/#529/#530은 megatron 전체 wheel 재빌드(0.17.1+fl.20260822) 및 cambricon-neuware4.4.3 app image tag를 기록했다.

해석: FlagGems 5.3.5의 추진은 「전 백엔드 재검증」 라운드를 촉발했다 — 캄브리콘과 메타엑스 두 곳의 vllm 0.20.2 검증 셀이 재설정된 후 다시 통과되었고, 검증 매트릭스는 버전 진화 속에서도 신뢰성을 유지하고 있다. 각 제조사의 소프트웨어 스택 버전(메타엑스 maca3.8.1.3, 엔플레임 TOPS 1.10.6)이 지속적으로 반복되고 있으며, build-infra의 「버전 정렬 허브」 역할이 더욱 명확해지고 있다.

1.3 build-infra: 검증 주도 엔지니어링 하드닝 마무리 — 병렬화, 격리, 장시간 타임아웃 (08-25)

출처: #531, #536, #540, #552, #556, #557, #563, #564

  • vllm과 megatron 두 개의 verify-driver를 병렬로 실행(#536), 백엔드별 검증 실행을 상호 격리하여 동시성 충돌 방지(#540).
  • 검증 산출물은 run_id 기준으로 명명하여 업로드(#531), 실패 셀 세부 정보를 실행 로그에 회신(#540), megatron 측은 NullTokenizer를 사용해 wget 다운로드를 피하고 model-size 파라미터 보완(#527/#529).
  • verify-driver 자동 재트리거 루프 중지(#557), PSUTIL_PREINSTALL 데드 코드 제거(#556), serve 준비 상태 폴링 타임아웃을 300s에서 900s로 상향(#563), completion 요청 타임아웃을 120s에서 600s로 상향(#564) — 장시간 작업 검증이 더 이상 타임아웃으로 인해 실패로 오판되지 않음.

해석: 어제의 “검증 드라이버 하드닝”에 이어, 이번 모니터링 기간에는 E2E 검증을 “단일 머신 직렬 + 고정 타임아웃”에서 “병렬 + 격리 + 장시간 타임아웃 + 감사 가능한 산출물”의 엔지니어링 형태로 발전시켰다. 다중 백엔드 매트릭스 규모가 확대되면서 검증 인프라 자체가 병목이 되었고, 이번 하드닝은 차기 신규 벤더(Hygon 등) 편입을 위한 엔지니어링 준비 작업이다.

1.4 FlagGems: KernelGen 연산자 확장 및 다중 백엔드 최적화 (08-25/08-26)

출처: FlagGems commits (모니터링 기간 내 19개 커밋)

  • KernelGen Nvidia 측 6개 연산자 신규 추가: miopen_batch_norm(#3936), divide(#5162), native_batch_norm(#5177), native_group_norm(#5178), true_divide_(#5206), special_gammaincc(#5315) — Triton 커널을 하나씩 적용.
  • KMCompiler Ascend 측: log_sigmoid_backward 성능 최적화(#5718), exponential 연산자(#5682), linalg_lstsq 진입점에 stages 추가(#5700), linalg_det 테스트 수정(#5701).
  • Moore Threads(MThreads): AddMM layouts 및 bias epilogue 최적화(#5384).
  • Cambricon: tensor mask를 Python and/or/not 대신 elementwise 비트 연산으로 변경(#5745, 5.3.5 재검증과 함께).
  • Iluvatar: repeat_interleave.self_int 전용 커널 신규 추가, matmul_bias_activation 최적화(8/26 09:41, 모니터링 기간 최신 커밋).
  • 기타: Metax conv_depthwise2d(#4762), QC fp8-w8a16 Rmsnorm 최적화(#4437), conv2d_padding/baddbmm/any_dim 정밀도 수정(#5445/#5336/#5381).

해석: KernelGen 연산자 커버리지는 norm 계열/수치 함수 계열로 계속 확장되고, KMCompiler Ascend 측과 Iluvatar 신규 백엔드도 동시에 속도를 내고 있다 — “신규 백엔드 적응과 연산자 커버리지의 이중 트랙 병행” 리듬은 변함없다.

  • 순조롭게 상장하면 Enflame은 Moore Threads, MetaX, Biren과 함께 “국산 GPU 4대 강자”로 자본시장에 총집결하게 된다.
  • FlagOS와의 호응: Enflame은 FlagOS 회원사 중 “신규 칩 접속 전초기지”인 PyTorch-Plugin-FL의 주요 추진자 — 어제 sglang-plugin-FL #42에 Enflame GCU 백엔드가 신규 추가되었고, 오늘 build-infra #558은 Enflame TOPS 1.10.6 업데이트, Torch-FL #187은 GCU torch.compile 적용. 자본화 가속과 오픈소스 소프트웨어 스택 투자가 동시에 추진되고 있다.

3.2 Moore Threads, MTT S5000 Prefill-as-a-Service 백서 발표 (08-24 발표/08-25 보도)

출처: ITHome/Sina Tech(8/24), ifeng(8/25)

  • Moore Threads가 《MTT S5000 Prefill-as-a-Service 기술 백서》를 발표하며 Prefill-Decode 이기종 분리 방안을 제시: Prefill(연산 집약형)과 Decode(메모리 접근 집약형)를 분리 풀에 배치하여 긴 컨텍스트 추론(수백 K에서 1M token) 하의 구조적 연산력 미스매치를 해결.
  • 실측 데이터: 64K 컨텍스트 단일 장비 Prefill 처리량 95,920 tok/s; 400K 극한 장시퀀스 TPM 2.6M tokens 도달. AI Agent, 코드 생성, 초장문 문서 분석 시나리오를 대상으로 「단위 Token 인프라 비용 절감」을 주력으로 내세움.
  • Moore Threads는 FlagOS 멤버 단위 중 검증 매트릭스가 가장 완전한 백엔드 중 하나(8/24 리포트: musa4.3.6/5.2.0 듀얼 백엔드 F/T 듀얼 경로 전부 통과); 긴 컨텍스트 추론 측면의 하드웨어 전략이 FlagOS의 추론 측 검증 메인라인과 동일한 방향.

3.3 MetaX: GPU 지능형 컴퓨팅 페이로드 우주 궤도 검증, 외신 집중 조명 획득 (08-25)

출처: DIGITIMES(8/25), Tencent News(이벤트 출처, 7/25)

  • DIGITIMES 8/25 보도 「중국 GPU 응용, 우주로 확장」: MetaX GPU 지능형 컴퓨팅 페이로드를 탑재한 「Yunjian MetaX호」 위성(Jitianxing A-04, 삼체 컴퓨팅 성좌)이 7/24 Lijian-1 Yao-15에 실려 궤도에 진입, 현재 궤도에서 국산 상용 GPU의 우주 고에너지 입자 방사선, 진공 열순환 하에서의 작동 신뢰성을 검증 중——국산 지능형 컴퓨팅 칩이 「지상 검증」에서 「궤도 실전」으로 나아가는 핵심 도약. 이벤트는 7월 말에 발생했으며, 본 모니터링 기간 내 국제 산업 매체의 재조명을 받음.
  • MetaX 공식 웹사이트 동향: 8/3 Xiyun C 시리즈 GPU의 멀티모달 생성 모델 MiniMax H3 Day 0 적용 발표; 7/30 Shanghai AI Laboratory와 함께 KernelSwift 연산자 혁신 대회 개시. MetaX의 FlagOS 측(MetaX) vllm 0.20.2 app image와 maca3.8.1.3 검증이 지속 추진 중(1.2 참조).

FlagGems 5.3.5 버전 추진으로 전 백엔드 재검증 유발, Cambricon, MetaX 검증 셀 리셋 후 재실행 통과, 검증 매트릭스가 버전 진화 속에서도 신뢰성 유지; 3. verify-driver 엔지니어링 강화 마무리(병렬, 격리, 장기 타임아웃, 감사 가능 산출물), 차기 신규 벤더 진입을 위한 기반 마련; 4. 멤버 단위 자본화와 생태계 양선 병행——Enflame 커촹반(과창판) 발행 개시(9/2 청약, 60억 위안 모집), Moore Threads Prefill-as-a-Service 백서 발표, MetaX 우주 지능형 컴퓨팅 페이로드 외신 조명 획득.
