날짜: 2026-11-12　출처: build-infra #1742 (PPU base 2.3.0 버전 데이터) · build-infra #1769 (Iluvatar runtime 2.3.0) · FlagTree 0.7.1+ascend3.5 · FlagTree 0.7.1+xpu3.6 · vllm-plugin-FL #706

  • 버전 측면: FlagTree가 0.7.1a2에서 정식 버전으로 넘어가며 먼저 두 개 백엔드를 허용했습니다——0.7.1+ascend3.5(15:43)와 0.7.1+xpu3.6(19:28)이며, Release 설명에는 “pypi 0.7.1+<백엔드>" 한 줄만 있어 백엔드별 휠 배포 방식임을 보여줍니다. 나머지 백엔드는 여전히 0.7.1a1(hcu, tsingmicro), a2(iluvatar, mthreads) 또는 dev1(ppu)에 머물러 있으며, 정식 버전은 일괄 전량이 아니라 백엔드별로 순차 허용되는 방식입니다.
  • 빌드 측면: build-infra가 2.3.0에서 두 곳의 버전 데이터를 보완했습니다——T-Head PPU 2.1.0의 base 문서(#1742, 도구가 23개 백엔드 기준으로 버전을 조회하고 23개 검증 전부 통과)와 Iluvatar corex5.0.1의 runtime 문서(#1769, 1개 백엔드)입니다. 2.3.0의 이미지 라인은 이미 base와 runtime 양쪽을 동시에 커버하고 있지만, 기록은 여전히 “백엔드 하나당 PR 하나” 방식으로 진행됩니다.
  • 하드웨어 계층: Ascend CANN 9.2.1에 910C의 base 이미지가 추가되었고(#1760, 910B 버전은 11-03에 이미 존재), flagcx 패키징 매트릭스에 ascend-cann9.2.1-910c 행을 추가했습니다(#1761). 해당 행은 모든 channel에 대해 비활성화되어 있는데, 910C와 910B가 flagcx 0.14.1+cann9.2.1이라는 하나의 pin을 공유하므로 활성화하면 중복 wheel이 생성되기 때문입니다. 행을 보완하지 않으면 매트릭스가 드리프트되어 모든 channel의 set-matrix가 실패하고 flagcx 휠을 배포할 수 없게 됩니다.
  • 프레임워크 측면: vLLM 0.32 적응이 단일 지점에서 큐 형태로 바뀌었습니다——이번 기간에 NVIDIA KV cache 마이그레이션(#737)과 T-Head PPU-ZW810E(#706) 두 건이 머지되었고, 별도로 MUSA, Hygon, MetaX, Kunlunxin, Ascend, Iluvatar, Enflame, AMD 8개 사가 심사 중입니다.
  • 의미: 2.3의 두 가지 하드 노드(12월 7일 FlagTree 분기, 12월 30일 릴리스)에 관측 가능한 중간 상태가 생기기 시작했습니다: 0.7.1은 백엔드별 허용, 2.3.0 이미지 문서는 백엔드별 보완, vLLM 0.32는 벤더별 마무리. 세 가지 모두 한 번에 완료되는 작업이 아니므로, 데일리 리포트의 관찰 단위를 “버전 번호”에서 “백엔드 × 컴포넌트”로 세분화해야 합니다.

1.3 FlagTree: 0.7.1 정식 버전, 먼저 두 백엔드 반영, Intellifusion 백엔드 Triton 3.8 진입 (11-12)

날짜: 2026-11-12　출처: FlagTree #1598 (Intellifusion 백엔드) · FlagTree #1637 (Ascend Triton 3.6.x, 심사 중) · FlagTree 0.7.1+ascend3.5 · FlagTree 0.7.1+xpu3.6 · FlagTree 저장소

  • 버전 계보: 0.7.1의 프리릴리스는 a1 6개 백엔드(ascend, hcu, iluvatar, mthreads, tsingmicro, xpu)와 a2 2개 백엔드(iluvatar, mthreads)를 커버하며, 정식 버전은 현재 ascend3.5와 xpu3.6만 출시되었다. 핑터우거(PingTouGe)는 여전히 0.7.1.dev1+ppu3.6이다. 동일 버전 번호 아래 백엔드별로 순차 배포하는 것은 FlagTree의 일관된 방식이다.
  • 신규 백엔드: #1598이 병합되어 Intellifusion을 위해 ifwa:100 타깃의 컴파일러와 런타임 백엔드를 추가했다. 메모리 접근과 matmul의 lowering, 소프트웨어 파이프라이닝, 비동기 복사, LHS에서 TMEM으로의 승격을 포함하며, IFWA Toolkit 빌드 검사, CModel 예제, 별도의 수동 wheel 배포 워크플로를 갖춘다. 이 백엔드는 README 메인라인 매트릭스에 아직 등록되지 않았으며, 신규 추가에 해당하고 범위 확장에는 해당하지 않는다.
  • 어센드 버전 라인: #1637이 심사 중이며, 어센드 NPU 백엔드를 Triton 3.6.x로 이식한다. 전체 lowering 파이프라인, Python 런타임, 테스트 스위트를 포함한다. 병합되면 어센드는 triton_v3.5.x 브랜치에서 메인라인으로 복귀하며, 이는 2.3의 버전 매트릭스를 직접 변경하게 된다.
  • TLE와 TileIR: #1534는 병합 분석을 수렴하고 gather 사실을 보존하며, #1535는 병합 순서를 유지한 전제에서 인덱스 호환 레이아웃 제안을 담고, #1615는 TileIR에 token-aware 포인터 읽기/쓰기와 원자 연산을 추가한다.
  • 백엔드 세부 사항: #1633은 Iluvatar CoreX에서 tle_raw로 sort를 최적화하고, #1488은 XPU cluster 소스를 동기화하며 SDNN 객체를 v0.3.6.9.1로 올리고, #1635는 XPU의 FlagGems 테스트 tag를 v5.3.5에서 v5.5.0.dev1로 올려 FlagGems 개발 버전과 정렬한다.

  • 버전 출시는 백엔드별로 배치 처리: FlagTree 0.7.1 정식 버전은 ascend3.5와 xpu3.6에만 제공되었고, 나머지는 여전히 a1/a2/dev입니다. 이는 지연이 아니라 각 백엔드가各自 CI를 통과해야 하는 필연적 결과이며, 12월 7일 컷오프 노드의 압박을 설명합니다. 컷오프 전에 출시되지 않은 백엔드는 프리릴리스 버전만 탑재할 수 있습니다.
  • vLLM 0.32 마이그레이션이 이번 주 메인라인으로: NVIDIA와 T-Head는 이미 병합되었고, 8개사가 심사 중입니다. 어제 Kunlunxin의 py3.10 실패는 진정한 리스크가 API 이름 변경이 아닌 플랫폼 차이에 있음을 보여줍니다. 다음 기간의 핵심은 「누가 먼저 0.32를 포기하는가」 또는 「누가 패치를 업스트림에 반영하는가」입니다.
  • Hygon의 「보강형」 투자는 기록할 가치가 있음: 하루 27건, foreach 20개에 bmm 3종 세트를 더해 옵티마이저와 행렬 곱 경로의 폴백을 직접 줄였습니다. 이런 작업은 뉴스가 되지 않지만, 학습 스크립트가 국산 카드에서 전체적으로 실행될 수 있는지를 결정하며, 단일 성능 최적화보다 가용성을 더 크게 바꿉니다.
  • FlagQuantum의 폭발은 별도로 봐야 함: 하루 70건 커밋, 29건 병합으로 Hubbard/t-V 두 모델, 패리티 대칭성 및 216개 프로그램의 네이티브 구현을 동시에推进했습니다. 양자 시뮬레이션은 「데모」에서 「학습 가능한 모델 커버리지」로 전환 중이지만, 제품화와는 여전히 거리가 있어 릴리스 수준으로 해석하기는 어렵습니다.
  • 뉴스면과 코드면의 괴리는 계속: gnews 컴포넌트명 조회는 연속 제로 히트였으며, 이번 기간 거의 모든 사실은 GitHub에서 나왔습니다. 데일리 리포트의 판단 기준은 점점 커밋, PR 및 패키징 매트릭스의 1차 데이터에 의존하고 있으며, 산업 기사는 배경일 뿐 증거는 아닙니다.
