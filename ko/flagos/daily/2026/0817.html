기간 총람: org 내 52개 저장소 중 8개가 기간 내 푸시 발생; commit search에서 기본 브랜치 기간 내 커밋 26건 확인(FlagBLAS 18, build-infra 7, FlagPrism 1), 별도로 Megatron-LM-FL #100, FlagTree #969 두 건의 PR 병합, 공식 GitHub Release 없음. 본 기간 3대 주요 흐름: FlagBLAS 벤치마크 스위트 대규모 확장(Level-1/2/3 전면 커버, Hygon hipBLAS를 명시적 적응 대상으로 지정), build-infra Hygon 라인 이미지 엔지니어링과 hygon25 4개 시나리오 검증, Megatron-LM-FL에 Kunlunxin P800 CI 지원 추가(신규 칩 라인 신호).

1.2 build-infra: Hygon 이미지 엔지니어링 + megatron 라인 검증(커밋 7건, PR #403-#409)

출처: build-infra pulls

  • #403 하이곤 base 이미지에 LLVM DTK 추가 (8/16 11:18): vendor triton이 의존하는 DTK LLVM 패키지를 보충하여 이미지 내 컴파일러 체인 누락을 수정.
  • #404 하이곤 triton 3.3.0 → 3.5.1 (8/16 11:24): 하이곤 측 Triton 버전 업그레이드.
  • #405/#406 2.1.2 이미지 설명 자동 새로고침 (8/16 11:48/12:55): base 레이어 17개 백엔드 버전 데이터 전부 검증 통과; runtime 레이어 1개 백엔드 검증 1건 실패 (정례 자동 새로고침).
  • #407 megatron wheel 빌드 시 sysconfig 패치 (8/16 18:25): compile_helpers()가 원래 python3-config(CPython 빌드 산출물, uv venv에는 없음)에 의존하던 것을 stdlib sysconfig.get_config_var("EXT_SUFFIX")로 변경; 삼상 태 멱등 패치 스크립트는 Megatron-LM-FL 업스트림 #112 머지 전 임시 fallback이며, 두 가지의 최종 코드 형태는 동일.
  • #408 하이곤 hygon25 네 가지 시나리오 검증 기록 (8/16 18:27): 전체 megatron-core wheel(MLF #107) 기반으로 training / rl / post_training / inference 네 시나리오 결과 기록——rl은 플랫폼 gap으로 차단(megatron/rl/inference/megatron.py:87에 동적 추론 엔진 어서션 flash-attn ≥ 2.7.3 하드코딩), tensorboard는 미선언 런타임 의존성, vendor flash_attn 버전 정보 불일치(__version__이 2.6.1로 고정되어 있으나 실제로는 2.8.3+); 컴파일러 마스크 정정: flagtree 3.6.0은 새 이미지에서 사용 가능으로 판정 (기존 blocked 결론은 DTK LLVM 패키지가 빠진 구 컨테이너에서 비롯됨).
  • #409 app 레이어 env 프레임워크 + vllm flashinfer gate (8/16 20:03): vLLM 0.24.0이 CUDA에서 flashinfer를 무조건 임포트(샘플러 스위치 기본 켜짐)하는 문제를, 새로 추가한 configs.yaml env.app.<app> 세 번째 차원을 통해 VLLM_USE_FLASHINFER_SAMPLER=0을 주입하여 해결; 동시에 vllm 기본 버전 0.20.2의 torch 끌어오기 함정 수정——순수 vllm==0.20.2 단일 단계 설치 시 이미지 소스에서 최신 torch(2.11.0+cu130)를 해석하여 런타임 매트릭스를 덮어쓰는 문제로, 기본 버전을 0.24.0으로 변경하고 +flagos pin을 강제하여 실측 설치 시 더 이상 torch를 다운로드하지 않음.

1.3 Megatron-LM-FL: 쿤룬신 P800 CI 진입 (PR #100)

출처: Megatron-LM-FL PR #100

  • 쿤룬신(KunlunXin) P800 플랫폼 지원 (8/17 09:48 머지, AlexMa616): 쿤룬신 플랫폼 설정 및 독립 CI workflow 추가, 8개 XPU 디바이스에서 전체 단위 테스트 매트릭스 통과(kl-8g-cicd-megatron 노드); Qwen3 0.6B TP1/PP1 기능 테스트 통과 및 P800 golden values 기록; FlagCX 구성 및 vendor.kunlunxin TransformerEngine-FL 백엔드 우선 적용.
  • 알려진 제한: TP2/PP2 벤치마크 미활성화——쿤룬신 백엔드의 sequence-length-4096 커널 지원 부족, 미지원 연산자의 느린 fallback 구현으로 인한 타임아웃 발생, 벤치마크 구성은 TE-FL 측 후속 검증 완료까지 보류.

해석: 이는 쿤룬신(바이두 계열 XPU)이 처음으로 Megatron-LM-FL CI 매트릭스에 진입한 것이다. release-info 이미지 문서에 이미 존재하는 kunlunxin-xre5.37.1 base 이미지와 결합하면, 훈련 라인의 신규 칩 적응 전초기지가 이미 마련된 셈——skill의 “PyTorch-Plugin-FL은 신규 칩 접속 전초기지”라는 관찰과 일치하며, 쿤룬신은 base 이미지 → CI 매트릭스 경로를 따라 FlagOS 생태계에 진입하고 있다.

2. 뉴스 보도와 생태계

2.1 뉴스 측 종합 평가

Google News는 FlagGems/FlagScale/FlagTree/FlagPerf/FlagCX/KernelGen/FlagOS-Robo/FlagQuantum 등 컴포넌트 키워드에 대해 모니터링 기간 내 직접 적중이 전무했고, HN 조회(FlagOS/FlagGems/FlagScale/FlagTree/BAAI)도 관련 적중이 없다(적중한 것은 고전 AI 논의, Stripe 수수료 등 무관한 게시물). 모니터링 기간 내 gnews 적중 항목은 모두 금융/주식시장 노이즈였다. ETF 중점 보유 종목 시세(Cambricon/Hygon/VeriSilicon), 반기 실적, 항셍통 편입 조정 예측(Iluvatar CoreX 09903), 사회보장기금 보유(Moore Threads), Cambricon Q1 실적과 주주총회 공지 등이며 모두 FlagOS 오픈소스 동향이 아니다. “Zhiyuan 연구원 오픈소스” 조회는 여전히 도박/SEO 노이즈(스포츠/공식 사이트/입구류 제목)가 주를 이루어 전량 제거했다. Zhiyuan 커뮤니티 집계 글(Anthropic/Claude/DeepSeek Harness/Qwen3.8 등)은 AI 업계 화제로 FlagOS와 직접 관련이 없다. 뉴스 측 당일 중대 동향은 없으며, 본문 내용은 GitHub commits에 의존한다.

KunlunXin P800의 CI 진입은 본 모니터링 기간 가장 주목할 만한 증분이다. TE-FL 측 kernel이 보완되면 KunlunXin은 “이미지 준비 완료”에서 “학습 라인 사용 가능”으로의 도약을 완성하게 된다.

4. 요약
