날짜: 2026-11-02　출처: build-infra PR #1589 · build-infra PR #1608 · FlagGems-sglang PR #271 · FlagQuantum PR #1004 · FlagGems PR #8240(전체는 부록 참조)

  • AMD 관련: build-infra #1589는 FlagTree의 amd 백엔드를 위해 새로운 패키징 라인을 신설했다(bare-ubuntu 22.04 빌드 머신, backends.yaml 행, verify_stage 단계 및 wheel 타깃). 동기는 glibc 하한이 아니라 추적성이다. 벤더 0.7.0+amd3.6의 wheel 자체가 22.04 빌드이지만 Source-Commit을 첨부하지 않는다. 해당 라인은 amd-rocm7.2.4 런타임 노드에서 A/B를 수행했다. 연산자 스캔과 torch.compile 결과가 일치했고(maxdiff 1.526e-05, 9/9), 182개의 벤더 독점 파일이 설계대로 전부 대조되었다. 같은 날 #1599는 rocm7.2.4의 torch 클로저를 vLLM 0.32의 고정 조합에 정렬했다. FlagGems-sglang #271은 gfx1100을 위해 decode_attention, decode_grouped_attention, extend_attention, log_scaling_tau 네 개 연산자를 보완했다. 빌드, 런타임, 연산자 세 계층이 한 모니터링 기간 내에 같은 방향으로 나아가고 있으며, AMD 라인은 「돌아감」에서 「추적 가능, 재현 가능」으로 이동하고 있다.
  • 양자 관련: FlagQuantum은 하루 21건 머지, 122건 커밋으로 세 가지 수용 기준 라인에 걸쳐 있다. UP-01은 Python qfunc 프로그램을 공용 프런트엔드로 만들고(#1004), AO-00/01/02는 순차적으로 산술 베이스라인, 순수 표현식 정규화, 보호된 산술 구현을 구축하며(#1006, #1010, #1013), PF-00/01은 Python 컴파일 지연과 프로세스 메모리 원장을 구축한 뒤 검증된 계획 필드를 재사용한다(#1018, #1021). 같은 기간 QEC 측은 노이즈 surface memory 조합, 코히런트 매칭 보정, 블록 스케줄링을 보완했고(#1012, #1015, #1019), 런타임 측은 정규화 IR로 전환해 Module 학습을 재사용하고 진단 스냅샷 오버헤드를 줄였다(#1017, #1014).
  • T-Head 관련: FlagGems는 16:03부터 16:46까지 43분 동안 13개의 T-Head 전용 연산자를 머지했다. Chebyshev 다항식, igamma, conv_transpose3d, quantized_lstm, nuclear_norm, fused_rms_norm_backward, _adaptive_avg_pool3d_backward 등 롱테일 항목을 포함하며, 모두 KernelGen의 T-Head 라인을 거쳤다. 이는 연산자 라이브러리 총량 확장 이후 단일 백엔드 전용 연산자가 처음으로 「배치」 형태로 메인라인에 진입한 것이다.
  • 판단: 세 라인은 모두 같은 점을 가리킨다. FlagOS의 역량 확장이 「리더보드식 연산자 수 채우기」에서 「백엔드별 배치 납품 + 수용 단위별 기록」으로 전환되었다는 것이다. AMD는 자체 빌드 추적성 라인을 갖췄고, 양자 스택은 의미론, 산술, 성능을 독립적으로 수용 가능한 작은 단계로 분해했으며, T-Head는 분 단위 리듬으로 일괄 병합되었다. 진정한 병목은 여전히 개발이 아니라 머지와 릴리스에 있다. 이 모니터링 기간에 162건이 머지되고 192건이 새로 열렸으며, 대기열은 계속 확장 중이고 2.3.0도 여전히 「이미지 선행, 매니페스트 미동결」 상태에 머물러 있다.

3.3 Ascend와 Hygon: W8A8 INT8의 GEMM 및 BMM 두 구현 (11-02)

날짜: 2026-11-02　출처: FlagGems PR #6060 · FlagGems PR #7741 · FlagGems PR #7774 · FlagGems PR #7760

  • Ascend GEMM: #6060은 mm_w8a8_int8 및 mm_w8a8_int8_out에 Ascend 백엔드를 추가하며, 공개 진입점을 통해 디스패치된다. 연산자는 사전 양자화된 INT8의 A와 B, FP32의 스칼라 또는 행별·열별 scale, 선택적 bias를 받아 정수 곱셈-덧셈 후 양측 scale과 bias를 적용하고, BF16, FP16 또는 FP32를 출력한다. 작은 M과 좁은 N은 벡터 곱셈-덧셈 커널로 처리하며, 각 FP32 리덕션 구간은 1024개의 INT8 곱을 넘지 않도록 하여 정수 부분의 정확성을 보장한다. 비대칭 제로 포인트는 지원하지 않는다.
  • Hygon BMM: #7741은 Hygon에 채널 레벨 bmm_w8a8을 보강하며, 기존 scaled-MM 커널과 tile 선택을 재사용하여 INT8 행렬 곱, FP32 채널 스케일링, 출력 변환을 하나의 커널에 융합한다.
  • 정밀도 수정: #7774는 Ascend 측에서 두 피연산자를 먼저 승격한 후 CANN libdevice의 pow를 수행하여 혼합 정밀도 환경의 언더플로와 정밀도 손실을 방지한다.
  • Hopper 성능: #7760은 TMA 파이프라인으로 FP8 W8A8의 BMM을 최적화하며, 이는 NVIDIA 측의 대응 최적화에 해당한다.
  • 판단: 두 회사는 동일한 모니터링 기간에 각각 하나의 W8A8 경로를 보강했다—Ascend는 GEMM의 완전한 시맨틱(행별·열별 scale, 세 가지 출력 dtype 포함)을, Hygon은 BMM의 채널 레벨 스케일링 재사용을 선택했다. 차이는 시맨틱 커버리지의 범위와 구현 재사용 사이의 절충에 있으며, 각자의 다운스트림 모델이 요구하는 양자화 형태의 차이도 반영한다.

3.4 Moore Threads: Conv1D 진정한 1차원 GEMM으로 26개 기준 예제 모두 0.8배 기준선 통과 (11-02)

날짜: 2026-11-02　출처: FlagGems PR #6754 · FlagGems PR #7428 · FlagGems PR #6903 · FlagBLAS PR #157 · FlagTree PR #1314

  • Conv1D 결과: #6754는 MTT S5000에 conv1d 백엔드 커버리지를 추가하여, 공식 conv1d_padding 기준을 18/26 예제 달성에서 26/26 예제가 0.80배 torch 이상으로 끌어올렸다. 이전에는 모든 FP32 K3/K5 padding 예제가 0.41~0.53배에 불과했다.
  • 3계층 수정 방식: 첫째, conv1d는 원래 MTHREADS 커버리지가 없어 전부 범용 conv2d로 처리되었고, 작은 그룹 형상은 padding을 실체화했으며, W=1 형상은 단일 유효 OW 채널만 히트했다. 라우팅 변경 후 중복 padding과 bias 할당을 제거하고 퇴화된 너비 디스패치를 수정했다. 둘째, 전용 Triton-MUSA Conv1D 커널을 신설하여 M = N × Lout 기준으로 3차원 그리드 분할을 수행하고, 출력 채널에 대해 더 이상 나눗셈과 나머지 연산을 하지 않는다. 셋째, 가중치를 커널 너비, 입력 채널, 출력 채널 순으로 사전 패킹하고 정밀도 보상이 포함된 SQMMA와 결합했다.
  • 부수 작업: #7428은 S5000에서 one_hot의 검증과 추론을 최적화하고, #6903은 빈 인덱스를 index_add의 빈 연산으로 처리하며, #157은 MUSA의 L1 BLAS를 보강하고, #1314는 두 번의 비동기 TME 복사 사이에서 membar를 건너뛴다.
  • 판단: 이는 본 모니터링 기간에 드물게 “기준을 전부 통과시킨” 완전한 사례다—라우팅, 전용 커널, 가중치 레이아웃, 명령어 레벨 정밀도 보상의 4계층을 동시에 수정하고 전후 비교를 제시했다. 다른 백엔드에 복제 가능한 템플릿이다.

4. 요약과 트렌드 관찰

날짜: 2026-11-02 ~ 2026-11-03　출처: flagos-ai 조직 저장소 · build-infra PR #1589 · FlagQuantum PR #1004 · FlagGems PR #8240

  • AMD 라인은 한 모니터링 기간 내에 세 계층을 모두 채웠다: 빌드 측에서는 FlagTree의 amd 패키징 라인을 새로 추가하고 A/B 대조로 동등성을 입증했으며(maxdiff 1.526e-05, 9/9), 런타임 측에서는 rocm7.2.4의 torch 클로저를 vLLM 0.32의 고정 조합에 정렬했고, 연산자 측에서는 gfx1100을 위해 LoRA와 어텐션을 합쳐 열 개 연산자를 보강했다. 이 세 가지를 합치면 AMD는 「백엔드가 있음」에서 「추적 가능한 빌드, 재현 가능한 런타임, 튜닝 가능한 연산자」를 갖춘 상태가 되었다.
  • 양자 스택이 「인수 단위별 납품」 단계에 진입했다: 단일 일자 21건의 머지가 UP(의미), AO(산술), PF(성능) 세 라인에 분포하며, 각 라인은 독립적인 기준선과 oracle, 실패 시 즉시 적색이 되는 증거를 갖추고 있다. 이러한 분할 방식은 양자 컴파일러의 모든 변경이 기존 장부로 그 비용을 측정할 수 있게 하여, 단일 지점의 가속비를 추구하는 것보다 장기적 진화를 더 잘 뒷받침한다.
  • T-Head가 전용 연산자를 배치 단위로 만들어냈다: 13개의 전용 연산자가 43분 만에 머지되었으며, 평균 3.3분에 한 건꼴로 특수 함수, 3차원 컨볼루션, 양자화 LSTM, 풀링 역전파 등 롱테일 항목에 집중되었다. 이는 KernelGen의 T-Head 생산 라인이 이미 배치 공급 능력을 갖추었고, 리뷰도 백엔드별로 병렬 소화할 수 있음을 보여준다.
  • 리뷰 처리량이 현재의 진정한 병목이다: 이번 모니터링 기간 머지 162건, 신규 개설 192건, 전체 리뷰 중 311건이며, 그중 FlagGems 한 저장소가 210건(신규 개설 148건)이다. 머지량은 직전 24시간 모니터링 기간 대비 11.5% 감소했으나 신규 개설량은 128.6% 증가했다——생산 라인은 전개되었으나 리뷰가 빠듯한 구조는 변하지 않았다.
  • 2.3.0은 여전히 이미지 선행 상태에 머물러 있다: base 계층과 Cambricon, MetaX, Hygon, AMD 네 계층 모두 2.3.0 명의로 changelog 날짜가 소급 기입되었고, 런타임 이미지도 백엔드별로 푸시되었으나, community의 release/2.3 목록은 여전히 404이며 GitHub Release는 신규 추가가 없다. 이전 회차 대비 실질적 진전이 없으며, 이번 업무 주에 목록이 동결되지 않으면 릴리스 기간이 다음 버전 계획에 밀리게 될 것이다.
  • 뉴스 측은 연속 두 번째 조용한 모니터링 기간이다: 24조의 중영문 쿼리에서 컴포넌트 레벨 적중이 0건이었고, CSDN 칼럼의 최신 글은 여전히 10-29이며, HN 직격 적중은 0건이다. 생태계 배경 두 건(Wuzhen 오픈소스 전시관, Jiuyuan 연합체의 3건 공동 발표)은 모두 주변 이벤트로 명확히 표기되어 프로젝트 진행에 산입되지 않았다.
