FlagOS 데일리 리포트 (2026-11-19)

2026-11-19 Kubuds

모니터링 기간: 2026-11-18 06:00 ~ 2026-11-19 06:00 (베이징 시간, 24시간; 이전 데일리 리포트 마감 시점에서 이어짐).

출처: GitHub 측에서 flagos-ai 전체 65개 저장소를 점검했으며, 모니터링 기간 내 148건의 커밋, 149건의 병합된 PR, 318건의 검토 중 업데이트, 19개 저장소 푸시를 포함한다. 또한 13개 저장소의 Release와 Tag, 24개 그룹의 Google News 쿼리, HN Algolia 및 멤버 기관 원사이트를 확인했으며, 상세 내용은 부록 출처 목록을 참조.

오늘의 핵심: FlagOS 2.3 기반 레이어에서 하루 만에 세 곳 교체, MetaX가 maca3.10.1.11로 전환, Enflame 두 개 tops 라인 첫 인도, Moore Threads musa4.3.6 전 체인 퇴출 (11-18)

날짜: 2026-11-18　출처: #1894 · metax-maca3.10.1.11 · enflame-tops1.9.29

  • MetaX 라인 교체: #1894는 base 레이어의 maca3.7.2.1을 maca3.10.1.11로 교체하며, MetaX C550 칩을 대상으로 하고 드라이버 3.100.1을 포함하며 기본 이미지는 ubuntu:24.04이다. 변경 기록 원문에는 이 라인이 maca3.7.2.1을 대체한다고 명시되어 있다. 드라이버는 사용자 공간에만 설치되며, 이미지는 카드 없이도 빌드할 수 있고 커널 드라이버는 호스트 머신에 남는다. #1895는 runtime 레이어의 같은 날짜 변경 기록을 보충하고, #1896은 SDK에 내장된 ompi 라이브러리를 LD_LIBRARY_PATH에 추가한다.
  • Enflame 최초 인도: tops1.9.29는 Zixiao C200(S60)용, tops4.1.6은 L600용이며 두 라인 모두 최초 인도이다. 인도 범위는 동일하다: driver, runtime, CC, PTI, TOPSTX, TOPS ATen, EFML, ECCL, Triton GCU 1.0.20261116 및 gculare-perftest이며, 모두 ubuntu:24.04 기반이다. /opt/triton_gcu는 벤더 triton 설치 위치를 가리키는 심볼릭 링크로 만들어지며, FlagTree의 toolkit.py가 바로 이 경로에서 찾는다.
  • Moore Threads 정리: #1902는 base 레이어에서 musa4.3.6 빌드 레이어를 퇴역시키고, #1904는 애플리케이션 레이어에서 같은 라인을 삭제한다. flagcx 행에 해당하는 #1905는 여전히 심사 중이다. musa5.2.0과 musa5.3.0 두 라인은 유지된다.
  • 버전 기준: configs.yaml의 stack version은 2.3.0이며, flaggems는 5.4.0으로 고정되어 있다. 2.3 일정은 community #176을 기준으로 한다: FEP 머지 마감 11-13, 기능 동결 및 rc0 11-30, rc1 12-07, rc2 12-14, 코드 프리즈 12-25, GA 12-30.
  • 관찰: 같은 날 두 곳이 세대 교체하고 한 곳이 정리되었으며, 모든 작업은 변경 기록과 Containerfile에 반영되었을 뿐 릴리스 공지는 없다. 기반 레이어의 리듬은 먼저 이미지가 빌드되고 검증될 수 있게 한 뒤 버전 번호를 논하는 것이다. 이 시점은 rc0까지 열이틀 남은 상태이다.

오늘의 핵심: Zhiyuan과 Qingmao Intelligence, Token 공장 엔드투엔드 솔루션 공동 발표, 상용 국산 Token 공장 FlagOS 기반으로 출시 (11-17~11-18)

날짜: 2026-11-17 ~ 2026-11-18　출처: Leiphone · Huanqiu Tech · Investorscn

  • 이벤트: 11월 17일, 「국산 칩·국산 모델 자주 생태계」 2026 칭마오 AI 파트너 콘퍼런스 겸 Token 팩토리 연례회의에서 베이징 지위안 인공지능연구원과 칭마오 인텔리전스가 공동으로 「국산 Token 팩토리 엔드투엔드 추론 최적화 방안」을 발표하고 즈중 FlagOS 기반 상용 Token 팩토리를 출시했다. 레펑왕은 11-18 13:31에 보도를 게재했고, 환치우왕과 투쯔자왕이 같은 날 후속 보도를 냈다.
  • 생태계 기준: 보도에 따르면 FlagOS 생태계는 이미 21개 칩 기업, 86개 생태 파트너를 모았으며 35종 AI 칩을 커버한다. 9대 연산자 라이브러리에 누적 1454개 이상의 오픈소스 Triton 연산자가 축적되었으며, 그중 약 800개가 최소 5종 국산 칩에서 네이티브 연산자 성능의 80% 이상을 달성했다. 단일 코드 저장소가 20개 벤더 백엔드를 커버하며, 지난 반년 동안 여러 차례 신모델 발표 당일 12종 칩에서 구동에 성공했다.
  • Ascend 910C의 성과: Zhipu GLM-5.3과 GLM-5.3-Flash를 대상으로 Prefill 측에서 81920 입력, 16 동시성 조건하에 웨이브 처리량이 3.41% 향상되었고, 256K 입력에서 TTFT p50이 4.94% 감소했다. Decode 측에서는 LI 양자화 write-back으로 동적 양자화, 스케일 변환, HBM 캐시 write-back을 동일 커널에 통합하여 910C 마이크로벤치마크가 18.03마이크로초에서 2.04마이크로초로 단축되었다. 엔드투엔드 ITL은 10% 이상 감소, TPOT는 8% 이상 낮아졌다.
  • 기존 910B: BAAI Token Hub는 48장의 910B를 Prefill과 Decode가 분리된 클러스터로 구성하여 32장을 4개 Prefill 도메인에, 16장을 8개 Decode 도메인에 배치하고 1M 컨텍스트의 GLM-5.3-Flash 서비스를 운영하여 2주 연속 안정적으로 가동 중이며, TTFT P50은 약 2.3초, TPOT P50은 22밀리초이다. Prefill 도메인 간 Prefix Cache 재사용으로 적중률을 82.65%에서 94.15%로 높였고, 재사용 단계의 첫 토큰 지연 중앙값은 16.63초에서 3.10초로 단축되었다.
  • 교차 비교: 핑토우거 810E에서 FlagOS 2.2는 DeepSeek-V4.1-Flash를 77%에서 82%까지 향상시켰으며, 16로드 동시성 사용 가능, 최대 80 동시성, 단일 요청 디코딩 136.2 tok/s를 기록했다. 하이광 BW1100에서 GLM-5.3-Flash는 25% 이상 향상되었고 다중 동시성 조건에서 단일 경로 처리량이 80 TPS를 돌파했다.
  • 기준 유의사항: 환치우왕 버전은 별도로 910C에서 GLM-5.3-Flash의 전체 출력이 20여 TPS에서 50여 TPS로 상승했으며, 로직 서비스 처리량이 최적화 전의 2.04배, 단위 연산 비용이 상용 API 과금 대비 19.4%에서 27.6% 낮다고 밝혔고, 자동 튜너가 검색 효율을 298배 높였다고 주장했다. 이 수치들은 벤더 및 미디어 기준에 따른 것으로 제3자 재현은 확인되지 않았다.

1. 오픈소스 프로젝트 진행 상황 (GitHub 동향)

1.1 조직 리듬: 19개 저장소 푸시, 148건 커밋, 149건 병합, 15시~16시 가장 집중 (11-18)

날짜: 2026-11-18　출처: flagos-ai 조직 · FlagGems · FlagGems-vllm

  • 총량: 65개 저장소 중 19개가 모니터링 기간 내 푸시되었다. 커밋 검색 히트 148건, 병합 PR 149건, 기간 내 업데이트된 심사 중 PR 318건.
  • 커밋 및 병합 분포: 양자가 거의 1대1로, 당일 트래픽이 기본적으로 압축 병합으로 진행되었음을 보여준다. FlagGems 34, FlagGems-vllm 28, build-infra 20, FlagQAI 20, FlagQuantum 14, 나머지 8개 저장소 합계 32건(FlagTrain 9, FlagTree 5, FlagAttention 5, optest 4, FlagGems-sglang 4, FlagCX 3, Torch-FL 2, vllm-plugin-FL 1).
  • 시간 분포: 첫 커밋 07:13, 마지막 커밋은 다음 날 05:15까지 진행 중이었다. 16시 19건이 최고치, 15시와 10시 각 18건. 20시 이후 11건으로 감소, 22시부터 매시간 1~2건으로 마무리 단계.
  • 푸시되었으나 메인 브랜치에 커밋 없는 2개 저장소: community의 푸시는 codex/fep23-flagtree-device-enablement-20261105 브랜치에서 발생했으며 FEP-23의 FlagTree 디바이스 활성화에 해당한다. docs는 기간 내 IssueComment 이벤트만 있었고 소스 변경은 없었다.
  • 관찰: 병합 리듬이 15시~16시에 단일 피크를 형성했으며, build-infra와 FlagGems-vllm 두 배치의 집중 병합 시점과 일치한다. 당일 신규 저장소 생성도, Release 발행도 없었고 FlagCX 태그 하나만 있었다.

1.2 build-infra: 2.3.0 기반 3개 라인 당일 동시 착수, 20건 병합 전부 라인 교체 중 (11-18)

날짜: 2026-11-18　출처: #1894 · #1898 · #1904

  • 구성: 20건 머지. MetaX 라인 10건(6건 라인 교체 및 수정, 4건 변경 기록 보충), Enflame 라인 3건, Moore Threads 라인 2건, 나머지 5건은 flagcx 휠 기록, vLLM 검증 출력 표기, vendor.sh의 PYTHONPATH 덮어쓰기 수정이 각 1건씩, 여기에 2.3.0 설명 갱신 2건.
  • MetaX 시퀀스: #1894 base 레이어 교체, #1895 runtime 레이어 변경 기록 보충, #1896 ompi 라이브러리 경로 수정, #1897과 #1899 변경 기록 날짜 보충, #1900 드라이버 버전의 오래된 주석 삭제. 6건이 연달아 이어져 당일 가장 완결된 라인 교체였다.
  • Enflame 시퀀스: #1886 FlagTree를 0.7.1에 고정하고 연산자 폴백 환경 변수 삭제, #1887 sglang 워밍업 예산 완화 및 환경 변수 고정 3건 제거, #1888 두 라인의 runtime 변경 날짜 보충.
  • Moore Threads 시퀀스: #1902 base 레이어의 musa4.3.6 폐기, #1904 애플리케이션 레이어에서 해당 행 삭제. 애플리케이션 레이어 이 건의 동기는 커밋에 적혀 있다. 해당 행이 더 이상 필요로 하는 이미지가 없으며, 남겨두면 구성 매트릭스에 빈칸만 하나 늘어날 뿐이다.
  • 기록과 릴리스: #1883, #1889, #1901, #1903 네 건이 2.3.0을 각 레이어 이미지 설명에 반영하고 설명을 갱신했다. #1898과 #1876은 flagcx 휠 릴리스를 기록했다.
  • 관찰: 20건 중 신규 기능은 한 건도 없다. 베이스 레이어의 당일 작업은 “어느 라인이 남고 어느 라인이 빠지는가”를 구성과 문서에서 정합시키는 것이었으며, 검수 시 구식 기준을 읽지 않도록 하기 위함이다.

1.3 FlagCX: v0.14.1 태깅, Enflame 디바이스 속성 유형을 SDK 정의로 변경(11-18)

날짜: 2026-11-18　출처: v0.14.1 · #721 · #723

  • 태깅: v0.14.1이 베이징 시간 11:05에 태그되었으며, 커밋 268d6aa2를 가리킨다. 이 태그는 #724에서 생성되었으며, #723이 0.14.0-rc2 브랜치에 적용한 것과 동일한 수정이다.
  • 수정 내용: Enflame 플랫폼에서 더 이상 이름으로 디바이스 속성 유형을 추측하지 않고, SDK가 제공하는 유형을 직접 사용한다. 변경 폭은 크지 않지만, 컴파일 시점에 벤더가 추가한 필드를 호환할 수 있는지를 결정한다.
  • 플랫폼 역량: #721은 Iluvatar에 IXCUDA 스트림, 호스트 메모리 등록, DMA-BUF 지원을 추가했으며, 통신 라이브러리의 해당 플랫폼 기능 보완에 해당한다.

  • Mouxianfei 입장: 베이징 Mouxianfei Technology Co., Ltd.는 자신을 베이징시 과학기술위원회와 중관춘관리위원회가 지도하는 Zhongzhi FlagOS 가속 계획 과제에서 물리 시뮬레이션 분야 유일 협력 파트너이자 FlagOS 유일 지정 시뮬레이션 플랫폼 협력 기업이라고 밝혔다. 공동창업자 겸 수석 아키텍트 Sun Jiaqi가 임바디드 AI 세션에서 발표했다.
  • 기술 세부사항: MotrixSim 물리 엔진, MotrixLab 학습 플랫폼, MotrixGen 데이터 엔진이 풀스택 자체 개발 체인을 구성하며, UniLab 오픈소스 학술 협력 프로젝트는 2.0까지 반복되었다. 기사에서는 특정 후속 학습 시나리오에서 실제 기기 데이터 양의 약 2~3배에 해당하는 시뮬레이션 데이터로 순수 실제 기기 데이터 후속 학습의 성공률에 도달할 수 있으며, 시뮬레이션 학습 프레임워크의 실행 속도가 다른 오픈소스 시뮬레이터의 3~5배 이상이라고 주장했다.
  • 생태계 측 정보: 같은 기사에서 FlagOS가 유엔개발계획(UNDP)과 중아프리카 창업 협력을 전개하고, 30여 개국, 50명 교사를 대상으로 하는 글로벌 AI 컴퓨팅 교원 연수를 실시하며, 유엔이 개방 컴퓨팅 워킹그룹을 설립하고 FlagOS를 기술 기반으로 삼는다고 언급했다.
  • 관찰: 「유일 지정」은 기업 자체 서술이며, FlagOS 공식 채널에서는 대응 공고를 확인할 수 없어 수록 시 협력사 입장으로 처리한다.

2.3 CSDN 칼럼과 Zhiyuan 커뮤니티: 모니터링 기간 내 신규 기술 기사 없음 (11-18)

날짜: 2026-11-18　출처: qq_41610763 · Zhiyuan 커뮤니티

  • CSDN 칼럼: FlagOS 지능형 컴퓨팅 시스템 소프트웨어 스택 칼럼에서 확인된 최신 글은 8월 21일의 SGLang 연산자 최적화 챌린지 원고 모집이며, 모니터링 기간 내 신규 게시물은 없습니다.
  • Zhiyuan 커뮤니티: 모니터링 기간 내 여러 푸시는 모두 모델 및 리더보드 관련 콘텐츠(Tencent Hunyuan Flash, 소재과학 에이전트 MatOS, 우제 PhysCapBench, 궁커 연설)로 FlagOS와 직접적인 관련이 없어 수집하지 않았습니다.

3. 회원사 심층 분석

3.1 Moore Threads: Kimi K3.1 Pro 훈련 적응, 2대 16카드 400스텝 수렴 (11-17~11-18)

날짜: 2026-11-17 ~ 2026-11-18　출처: Yicai · China Business Journal 전재 · EEFocus 기술 기고

  • 사건: Moonshot AI가 2.8조 파라미터의 Kimi K3.1 Pro를 오픈소스로 공개한 후, Moore Threads는 MTT S5000 지능형 컴퓨팅 카드와 MUSA 소프트웨어 스택을 기반으로 훈련 적응을 완료했습니다. 네이티브 FSDP2 멀티모달 훈련 경로를 구축하여 모델 로딩, 샤딩 스케줄링부터 그래디언트 동기화까지 전체 체인을 연결했습니다. Yicai와 NBD는 11-17 저녁에 최초 보도했고, China Business Journal은 11-18에 기술 세부 사항을 보충했습니다.
  • 검증 구성: 축소 훈련 방안은 13층 언어 백본, 16개 전문가(top-8 라우팅)와 전체 27층 비전 타워로, 2대에 총 16장의 MTT S5000을 사용하며 MedPix-VQA 이미지-텍스트 데이터로 무작위 초기화부터 훈련을 시작했습니다. 16개 프로세스가 연속으로 400회의 옵티마이저 업데이트를 완료했으며, 훈련 Loss는 8.9365에서 2.1802로 수렴하고 검증 세트 Loss는 6.5297에서 4.6873으로 감소했으며, 메모리 피크는 44.80 GiB였습니다.
  • 엔지니어링 요점: 신규 연산자의 순전파와 그래디언트 구현을 보완하고, 전문가 분배와 병합을 통합 계산 그래프에 연결했습니다. 병렬화에서는 FSDP2와 EP를 혼합하고 파라미터 프리페치와 그래디언트 통신 스케줄링을 적용했습니다. 손실 측에서는 Chunk Loss 분할(청크 길이 256)로 대규모 어휘 메모리를 제어했습니다.
  • 범위 경계: China Business Journal은 훈련 적응이 해당 모델을 해당 칩에서 사전 훈련한 것과 같지 않다고 명확히 지적했으며, 둘은 분리하여 표현해야 합니다. Moore Threads는 이전에 021 과학 기초 모델(2360억 파라미터)의 제로부터 훈련을 완료했으며, Zhiyuan/BAAI와 협력하여 구현 뇌 모델 RoboBrain 2.5의 전 과정 훈련을 완료했습니다.
  • 관찰: 이 소식의 기술적 함의는 “추론 가능”이 아닌 “훈련 적응”에 있으며, 검증 규모는 축소 구성입니다. 이는 국산 카드가 조 단위 모델에서의 엔지니어링 역량이 진전되고 있음을 보여주지만, 완전한 규모의 사전 훈련과는 여전히 거리가 있습니다.

3.2 MetaX와 Enflame: 두 라인 교체 이면의 칩과 SDK 기준 (11-18)

날짜: 2026-11-18　출처: base 계층 변경 기록 디렉터리 · metax-maca3.10.1.11 · enflame-tops4.1.6

  • 칩 대응: MetaX 신규 라인은 C550에, Enflame 두 라인은 각각 Zixiao C200(S60)과 L600에 대응합니다. 이전에 Enflame 두 퇴역 라인은 11-17에 이미 교체 라인으로 바뀌었으며, 당일은 신규 라인의 첫 납품으로 동일한 세대 교체의 마무리입니다.
  • 드라이버 전략: MetaX는 드라이버를 사용자 공간 전용 설치로 만들어 컨테이너 내에 커널 모듈을 설치하지 않습니다. 이는 NVIDIA의 방식과 일치하며, 장점은 이미지를 카드 없이 빌드할 수 있다는 것이고, 대가는 호스트 드라이버 버전이 이미지와 반드시 일치해야 한다는 것입니다.
  • SDK 구성 요소: Enflame 두 라인의 구성 요소 목록은 완전히 동일하여, 두 라인의 차이는 칩과 스택 버전에만 있고 기능 범위에는 없음을 보여줍니다. Triton GCU는 모두 1.0.20261116, 즉 11월 16일 빌드입니다.
  • 디렉터리 정리: base 계층과 runtime 계층의 maca3.7.2.1 이미지 디렉터리가 삭제되어 이력 변경 기록만 남았으며, Enflame 구 라인의 디렉터리도 트리에 없습니다. 이러한 “디렉터리 삭제, 기록 유지” 방식은 빌드 매트릭스를 깨끗하게 유지하면서 추적 가능성을 보존합니다.
  • 관찰: 기반 계층의 세대 교체 기준은 “한 라인이 한 장의 카드에 대응”하는 것입니다. 세 회사가 같은 날 이 작업을 완료한 것은 2.3 주기의 플랫폼 목록이 기본적으로 확정되었음을 의미하며, 다음은 rc0 전의 검수입니다.

4. 요약

  • 베이스 레이어가 당일 메인 라인: FlagOS 2.3의 base 및 runtime 레이어는 하루 만에 MetaX 라인 교체, Enflame 듀얼 라인 최초 인도, Moore Threads 구 라인 정리를 완료했으며, 20건의 머지 중 신규 기능은 단 한 건도 없습니다. rc0의 11-30까지 아직 12일이 남아 있으며, 플랫폼 목록이 수렴 중입니다.
  • 연산자 레이어는 두 가지 작업 진행 중: FlagAttention은 한 번에 네 가지 어텐션 변형을 추가했고, FlagGems-vllm은 융합 연산자를 백엔드별로 하나씩 전개했습니다. 전자는 능력 경계를 확장하고, 후자는 커버리지 밀도를 보완합니다.
  • 컴파일러 인터페이스 세대 교체: TLE pipeline 이터레이터가 제거되었고, FlagGems, FlagGems-vllm, FlagAttention 세 라이브러리가 같은 날 tl.range로 변경되었습니다. 이는 저장소 간 인터페이스 정렬입니다.
  • 양자 라인 비중 상승: FlagQuantum과 FlagQAI 합계 34건으로, 당일 머지량의 약 4분의 1에 달합니다. 오류 정정 측은 엔지니어링화, 연구 측은 인터페이스화가 진행 중입니다.
  • 공개 보도는 단 하나의 메인 라인: Zhiyuan과 Qingmao Intelligence의 Token 팩토리 방안이 유일하게 실질적 내용이 있는 산업 뉴스이며, 나머지는 파트너 측 회고와 구 기사 전재입니다. 컴포넌트 레벨 버전 소식은 여전히 GitHub로만 전달됩니다.
  • 관찰 필요: Moore Threads 구 라인의 flagcx 행에 여전히 1건이 심사 중입니다. Hygon BW에서 FlagGems-vllm 0.2.0 베이스라인 활성화 시 한 케이스가 비활성화됩니다. 2.3의 GA는 12-30으로 정해져 있으며, 중간에 rc0, rc1, rc2 세 노드가 있습니다.
