  • 새 백엔드 측면: Torch-FL에 Horizon Robotics BPU의 연산자별 실행 계층이 병합되었다(#674, 31개 파일, 5698줄 추가 145줄 삭제). 기존에 BPU는 PrivateUse1에서 어떤 계산 연산자도 등록하지 않았다—hbDNNInferV2는 이미 컴파일된 전체 그래프만 받아들이므로, 모든 aten 호출이 cpu_fallback으로 떨어졌고 backends_bpu.conf는 비어 있었다. 이번 커밋은 누락된 중간 계층을 보완한다: 보드 외부의 x86 측에서 hbdk4로 단일 연산자 .hbm 산출물 라이브러리를 컴파일하고, 이 산출물을 제출하는 C++ 커널을 생성하며, drobotics conf 라우팅을 추가한다. 40개의 요소별 연산자(32개 단항, 8개 이항), 11개의 형상 버킷을 포괄하며, RDK S600에서 440개 산출물을 NumPy와 비교하여 차이 없음을 확인했다.
  • 버전 측면: FlagCX가 10-28 17:25에 v0.14.1 태그를 생성했다(commit 7ed4a82, 제목은 “어댑터별 디바이스 비트코드 생성, 더 이상 NVIDIA 하드코딩 안 함”, 즉 10-18에 병합된 #668). 해당 태그는 git tag만 있을 뿐 GitHub Release 본문이 없으며, 이전 버전 v0.14.0의 정식 Release는 9-28에 멈춰 있다. 같은 아카이브에서 v0.15.0.dev0 태그도 보인다(이 모니터링 기간 이전). 같은 기간에 0.14.0-rc2 라인을 위한 분산식 패치가 진행 중이다(#683, 심사 중).
  • 패키징 측면: FlagCX의 rpm 라인이 세 백엔드에서 여섯 개로 확장되었다(#673, 10개 파일, 295줄 추가 8줄 삭제). 새로 추가된 libflagcx-tsm(Tsingsemi), libflagcx-sunrise(Sunrise), libflagcx-du(Hygon DCU) 세 곳 모두 벤더 기본 이미지를 필요로 하지 않는다—SDK를 /opt 또는 /usr/local에 압축 해제하고 패키지 관리자를 호출하지 않으므로, openEuler 이미지에 파일 저장소만 더하면 완전한 빌드 환경이 된다; 벤더 soname은 Ascend의 기존 기준에 따라 통일적으로 필터링한다.
  • 뉴스 측면: Moore Threads가 10-28에 대규모 모델 훈련 인프라 Megatron-MUSA-Titan을 오픈소스로 공개한다고 발표했으며, 만 카드급 클러스터의 조 단위 파라미터 MoE 훈련에 초점을 맞추고 사전 훈련과 강화 학습을 포괄한다; 이미 자사의 만 카드 클러스터 사전 훈련에서 지속적으로 사용 중이며, blockwise FP8을 지원하고 DeepEP와 ACE 비동기 통신을 결합하여 전문가 병렬과 계산 중첩을 구현하며, slime, miles 강화 학습 프레임워크와 협력할 수 있다. 저장소 MooreThreads/Megatron-MUSA-Titan은 GitHub에 존재하지만 이 모니터링 기간 내에 푸시가 없다(마지막 푸시 10-16), “오픈소스 발표, 코드 미변동” 상태이다.
  • 판단: 세 라인이 각각 한 계층씩 전진한다—새 칩을 eager 경로에 연결(BPU), 통신 라이브러리의 제공 면을 소스 트리에서 태그와 배포 패키지로 확장(FlagCX), 훈련 스택의 오픈소스 서사를 FlagOS에서 멤버 기관 자체 개발 프로젝트로 확장(Megatron-MUSA-Titan). 이 스택과 직접 관련된 것은 처음 두 가지이며; 세 번째는 그 코드가 FlagOS가 재사용 가능한 훈련 컴포넌트로 환류되는지 관찰해야 한다.

  • 내용 측면: #668은 setup.py 비트코드 단계에서 하드코딩된 bindings/ir/nvidia를 어댑터별 조회 테이블(BITCODE_MAKEFILES)로 교체하여, 각 어댑터가 자체 Makefile과 아키텍처 변수를 선언하도록 한다. 이전에는 모든 비NVIDIA 어댑터가 RuntimeError를 발생시키거나 조용히 비트코드를 생성하지 못했으며, FlagTree의 iluvatar 백엔드는 FlagCX 소스 코드를 복사하여 자체적으로 다시 컴파일할 수밖에 없어 FlagCX가 마땅히 생성해야 할 비트코드를 소비할 수 없었다.

3.1 Horizon Robotics: BPU가 처음으로 연산자별 실행 가능한 PrivateUse1 백엔드가 되다 (10-28)

날짜: 2026-10-28　출처: Torch-FL PR #674 · PR #676 · PR #678 · PR #673

  • 연동 방식: BPU의 실행 단위는 hbdk4가 생성하는 .hbm 산출물이며, hbdk4는 x86에서만 실행 가능하다. 보드에서는 컴파일할 수 없고, 저장소와 함께 전달되는 산출물도 없다. 이전의 결론은 “설계상 eager 불가”였으나, 이번 커밋은 이를 세 계층으로 분해한다. 보드 외부에서 단일 연산자 .hbm 라이브러리를 빌드하고, C++ 커널을 생성하여 이러한 산출물을 제출하며, drobotics conf 라우팅을 추가한다.
  • 커버리지 및 검증: 40개의 원소별 연산자, 11개의 형상 버킷에 대해 RDK S600에서 440개의 산출물 전부가 NumPy와 비교하여 차이 없음을 확인했으며, flagos 텐서 상의 aten 호출이 실제로 BPU에 도달함을 검증했다. 작성자는 동시에 두 가지 부정적 결론을 기록했다. libhbtl.so는 단지 CPU 참조 구현일 뿐이며(ldd에서 libc/libstdc++/libm만 확인됨, hbtl::ucp::Add의 cpu/wall이 1.00), 동적 형상은 HBRT 4.7.5에서 실행 불가능하다(로더가 해당 축을 stride 0으로 선언하고, 태스크 검증에서 64 이상을 요구함).
  • 마무리 세 건: #676은 kDrobotics에 dispatcher.h의 두 곳 switch를 보완했다. 이전에는 BPU 빌드의 디스패치 로그 이름이 일괄적으로 unknown으로 출력되었고, KernelSetOf가 BPU 자체의 커널 라이브러리를 소속 없음으로 보고했다. #678은 세 곳의 copy 브랜치가 무조건 CUDA로 box되는 문제를 수정했다. 기본 FlagGems 주도의 NVIDIA 및 Damo Academy XuanTie PPU wheel은 의도적으로 CPU 전용 pip torch를 링크하며, CUDA 복사 커널의 DispatchStub이 비어 있어 첫 호출 시 missing kernel for cuda가 발생한다. #673은 빌드 기록에서 벤더 이름과 플랫폼 id의 불일치(hygon/dcu, mthreads/musa, enflame/gcu, nvidia/cuda)를 수정했으며, 이는 Hygon DCU 레인에서 8개 단위 테스트 실패의 근본 원인이었다.

  • 관찰 필요 사항 세 가지: 첫째, v0.14.1 이후 Release 설명이 보충되어 2.3 목록에 포함되는지 여부. 둘째, BPU 경로가 요소별 연산자에서 컨볼루션 등 메인라인 연산자로 확장되는지 여부. 셋째, Megatron-MUSA-Titan의 코드가 모니터링 기간 이후 실제로 푸시되기 시작하는지, 그리고 Megatron-LM-FL과 재사용 관계를 형성하는지 여부.
