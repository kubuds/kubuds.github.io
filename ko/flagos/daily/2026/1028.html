  • 백엔드 측면: AMD의 ROCm 7.2.4가 기본 이미지 한 장에서 완전한 백엔드로 성장했다. 설정 우선(torch 2.11.0+rocm7.2, triton-rocm 3.6.0, flagtree 0.7.0+amd3.6, 하드웨어는 W7900／gfx1100 표기) 후, triton-rocm을 pin하고 hipsolver／hipfft／miopen-hip 개발 패키지를 보충했으며, FlagCX의 AMD wheel 행과 벤더 PyPI를 활성화하고, 로컬 16카드 gfx1100에서 검증을 통과했다. 같은 기간에 native deb와 native rpm 두 패키징 라인에 arm64 차원을 추가하고, 호스팅된 arm64 머신으로 빌드와 검증을 수행했다.

  • 연산자 측면: FlagGems-Experimental이 10-27 17:43부터 17:59까지 한 시간 내에 135건의 PR(#744부터 #878)을 새로 열었으며, 제목은 일괄적으로 「Add MetaX support for …」이다. PR 본문은 이번 라운드가 MetaX 특화 연산자 재검증이라고 자술한다. 150개 연산자가 참여하여 135개가 세 차례 재검증을 통과한 후 하나씩 제출되었고, 환경은 torch 2.8.0+metax3.7.2.0, flagtree 0.6.1, 8카드 C550이며, 단일 연산자 정밀도는 29개 케이스 전부 통과, 성능 기하평균 1.008배(임계값 0.8)이다.
  • 정확성 측면: FlagGems가 index_put의 정수 오버플로 수정을 머지했다(#6892, 두 파일 112행 추가 4행 삭제). 증상은 Damo Academy XuanTie PPU-ZW810E에서 나타났다. int32 인덱스 텐서로 큰 stride 텐서에 쓸 때 조용히 잘못된 주소에 기록되어, 대상 행은 변경되지 않고 같은 할당 영역 내의 가드 영역이 대신 덮어써졌다. 근본 원인은 주소 산술이 int32 내에서 완료되어, 인덱스에 stride를 곱한 값이 포인터 오프셋을 형성하기 전에 이미 랩어라운드된 것이다. 같은 기간에 Ascend의 컴파일러 고정을 설치 시점에서 런타임으로 앞당겼다(#7837).

  • 런타임 변경 기록: 2.3.0의 런타임 changelog를 동기적으로 보완했으며, 먼저 Hygon dtk26.04를 추가하고, 이어서 AMD rocm7.2.4를 추가했다(hipsolver/hipfft/miopen-hip를 재빌드한 1건 포함).
  • AMD 백엔드: 설정 계층에 vendors.amd.rocm7.2.4를 신규 추가했으며, 스택은 torch 2.11.0+rocm7.2, triton-rocm 3.6.0, flagtree 0.7.0+amd3.6이고, 하드웨어는 Radeon PRO W7900(gfx1100, RDNA3), 드라이버 6.16.13, Python 3.12로 표기했다. 빌드 측은 자체 호스팅 amd runner를 사용하고, 검증은 rocm-smi로 수행하며, FlagGems에는 아직 ROCm/HIP용 C++ 백엔드가 없으므로 당분간 cmake 백엔드를 설정하지 않는다고 명시했다.
  • 패키징 측면: native deb와 native rpm 두 라인에 아키텍처 차원을 추가했으며(deb는 amd64와 arm64, rpm은 x86_64와 aarch64), arm64 행은 호스팅 머신으로 빌드와 검증을 수행하고 의존성 인덱스는 아키텍처별로 읽는다. 이전에는 FlagCX의 Ascend 행이 머신이 마침 aarch64였기 때문에 arm64 패키지가 산출된 적이 있을 뿐이다.
