1. 오픈소스 프로젝트 진행 상황(GitHub 동향)

기간 개요: org 내 53개 저장소 중 14개가 기간 내 푸시 있음; commit search 기간 내 커밋 65건 확인(build-infra 24건, FlagBLAS 19건이 상위), 공식 GitHub Release 없음. 이번 기간 헤드라인: build-infra가 시왕신커 SUNRISE 백엔드 추론 전체 경로 연결——FlagTree sunrise wheel 생산 라인 공식화 및 vllm 두 버전(0.24.0/0.20.2) 엔드투엔드 검증과 온라인 decode hang 수정 완료; 또한 vllm-plugin-FL 최초 쿤룬신 백엔드 지원, Torch-FL 3칩 기능 동일자 보완, FlagScale 승등/MetaX CI 신규 추가.

1.1 build-infra: 시왕신커 SUNRISE 추론 전체 경로 연결(기간 헤드라인, 12개 커밋)

출처: build-infra commits

  • wheel 프로덕션 라인 정식화 (8/19 15:26 #442): packaging/flagtree/sunrise 빌드 메커니즘 신규 추가 — ubuntu 22.04 old-glibc 기반(metax builder 방식과 동일), sunrise 의존성(LLVM 22 / sunriseTritonPlugin_v0.6.0.4 / triton toolkits) 사전 설치, FLAGTREE_BACKEND=sunrise로 소스에서 FlagTree wheel을 빌드하고 버전 게이팅 적용; CI target도 함께 신규 추가. 같은 날 #441에서 vllm-sunrise 0.24.0의 TANGRT 1.2.0상 종단 간 검증 완료(ptpu 빌드의 DOCKER_RUN_FLAGS 포함).
  • 빌드 트러블슈팅 시리즈 (8/19 17:16-20:25 #445-#450): clang/lld로 gcc 빌드 대체, ld.lld 툴체인 점검, 시스템 python3.10으로 cp310 wheel 빌드, pip를 알리윈 미러로 전환(runner가 pypi.org에 직접 연결 불가), $ORIGIN RUNPATH 복원 및 tang 별칭 추가.
  • 온라인 문제 수정 및 두 버전 재검증 (8/20 07:39-09:01 #451/#459/#461): sunrise FlagTree wheel 재빌드로 decode hang 수정(vllm 0.20.2 §2.9 및 0.24.0 §11.5 두 곳에 기록); 이어서 sunrise 0.24.0 vllm-repack 종단 간 검증(#459)과 0.20.2(F) 재점검(#461) 완료.
  • 동일 저장소 내 기타 커밋: metax flagtree 학습 E2E 및 merged-wheel 사용법 변경 기록(#435), megatron-rl app 환경에 TORCHINDUCTOR_COMPILE_THREADS=1 고정(#443), NVIDIA flash-attn 소스 빌드 workflow(#454), NVIDIA cuda13.3 4개 시나리오 이중 컴파일러 검증 기록(#455), app image 접두사를 flagos-app으로 통일 및 tag 명명 규칙화(#457/#462/#463).

해석: XiwangXinke SUNRISE는 8/18에 FlagTree 백엔드 의존성 업데이트(#999)를 완료한 후, 이번 모니터링 기간에 바로 “wheel 프로덕션 라인 + 추론 E2E + 온라인 문제 수정“의 심층 딜리버리 단계에 진입했다 — 빌드 기반 선정부터 이미지 소스 적응, decode hang 수정까지 전 링크의 엔지니어링 완성도는 최근 국산 백엔드 접속 사례 중 가장 완결성 있는 사례다(이전에는 T-Head PPU만이 유사한 깊이에 도달했다). 동시에 NVIDIA 측 megatron app image 메커니즘(flash-attn 소스 빌드, cuda13.3 이중 컴파일러 매트릭스, tag 명명 규칙)도 함께 정비되면서 학습/추론 이미지 체계가 통일되어 가고 있다.

1.2 vllm-plugin-FL: Kunlunxin 백엔드 신규 추가 (#268)

출처: PR #268 (8/19 15:16 병합)

vLLM 0.20.2 기반(빈 라이브러리 적응)으로 vllm-plugin-FL에 Kunlunxin 백엔드 지원을 추가했으며, 검증 모델은 Qwen3.6-35B-A3B와 Qwen3.6-27B이고 테스트는 고동시성 텍스트 및 이미지 입력(TP=4, max-model-len 16384, FLAGCX_PATH 및 USE_RESHAPE_AND_CACHE_FLASH 통합)을 커버한다. Kunlunxin은 8/18에 KernelGen 프로덕션 라인에 첫 연산자 배치(digamma, arctan minimax, bernoulli)를 병합했고, 다음 날 바로 추론 플러그인 라인에 진입했다 — 추론 측 국산 백엔드 매트릭스가 한 자리 더 확장되었다(이전에는 Enflame, Iluvatar CoreX, Moore Threads, Ascend 등을 이미 커버).

추세 판단: 8/18의 “KernelGen 전 벤더 병렬 출하” 이후, 본 모니터링 기간의 중심은 백엔드 심층 적용과 추론 경로 연결로 전환되었다——Xiwang Xinke SUNRISE는 “wheel 생산 라인 + E2E + 온라인 문제 수정”의 완전한 모델로 최근 진입 속도가 가장 빠른 국산 백엔드가 되었다; Kunlunxin은 KernelGen 연산자(8/18)에서 vllm 플러그인 백엔드(8/19)까지 단 하루 만에 이동했다; 추론 플러그인 라인 백엔드 매트릭스는 이미 Enflame, Iluvatar CoreX, Moore Threads, Ascend, Kunlunxin, Xiwang Xinke 등 여러 업체를 포괄한다. 학습 측(FlagScale CI 확장, Torch-FL AMP/profiler, FlagBLAS L2 보완)과 이미지 측(build-infra app image 통일)이 동시에 추진되고 있다. FlagOS 2.1(6/24) 이후 이미 8주 이상 경과했으며 기능량은 지속적으로 누적되고 있으나, 본 모니터링 기간에도 정식 버전 릴리스 신호는 아직 없다.

추세 판단: 본 모니터링 기간 칩 지형의 특징은 “추론 체인 심층 연결 + 백엔드 매트릭스 지속 확장“이다. 한편으로 SunriseCore SUNRISE는 국산 백엔드가 FlagOS에 접속하는 가장 완전한 체인(wheel 생산 라인→E2E→문제 수정)을 완성했고, KunlunXin이 뒤이어 추론 플러그인 라인에 진입하여 추론 측 백엔드 커버리지가 이미 6개사 이상에 달했다. 다른 한편으로 학습 측(FlagScale/FlagBLAS/Torch-FL)은 “다중 칩 CI 매트릭스 + 연산자군 보완 + AMP/profiler 역량” 삼선 병진으로 나아가고 있다. 상업적 측면에서는 Horizon Robotics Journey 6B 천만 세트 지정, Hygon 생태계 협력 2연타, Moore Threads 홍콩 증시 진전이 주요 포인트를 구성한다——소프트웨어 스택 적응과 상업적 실행 리듬이 동기화되고 있다.

4. 요약

  1. SUNRISE 추론 전체 체인 연결 완료(이번 모니터링 기간 헤드라인): build-infra 12건의 커밋으로 sunrise FlagTree wheel 생산 라인 완성(#442, ubuntu 22.04 old-glibc 기반 + LLVM 22 + sunriseTritonPlugin v0.6.0.4), vllm-sunrise 0.24.0 E2E(TANGRT 1.2.0, #441), decode hang 수정 및 0.20.2/0.24.0 이중 버전 재검증(#451/#459/#461) — 중국산 백엔드의 FlagOS 접속을 보여주는 가장 완전한 엔지니어링 사례.
  2. Kunlunxin, 추론 플러그인 라인 진입: vllm-plugin-FL #268이 vLLM 0.20.2 기반으로 Kunlunxin 백엔드를 지원하며, Qwen3.6-35B-A3B/27B 고동시성 이미지·텍스트 검증 통과. KernelGen 연산자 병합 이후 불과 하루 만의 성과.
  3. 학습 측 3개 라인 동시 진행: Torch-FL 3개 칩 동시 보완(핑터우거 PPU AMP 완료, Moore Threads MUSA MUPTI profiler, Ascend AMP 확장). FlagScale에 Ascend/MetaX 빌드 테스트 CI 추가. FlagBLAS는 하루 만에 Level-2 희소/대역 연산자군(SYMV/SPMV/GER/SYR/HER/SPR/HPR/SYR2/HER2/GBMV/HBMV/SBMV) 보완.
  4. 이미지 및 엔지니어링 메커니즘 개선: build-infra가 app image 접두사를 flagos-app으로 통일하고 tag 명명 규칙 정비(#457/#462/#463). NVIDIA flash-attn 소스 빌드 추가(#454) 및 cuda13.3 4개 시나리오 이중 컴파일러 검증 기록(#455) 추가. TransformerEngine-FL이 TP comm overlap에 필요한 backend ops 노출(#95).
  5. 회원사 비즈니스 동향 활발: Bosch의 Journey 6B 기반 MPC4가 천만 세트급 수주 확보(Horizon Robotics, Journey 6B 누적 수주량 2000만 세트 돌파). Hygon이 Tianji Data, Koal Software와 두 건의 생태계 협력 체결. Moore Threads 홍콩 상장 추진. Cambricon 인센티브 해제 입금.
  6. 뉴스 측 잠잠: 컴포넌트 키워드 제로 히트, HN 유효 결과 없음, 공식 GitHub Release 없음. FlagTensor 0.2.x 및 Megatron-LM-FL 0.2.0 시리즈는 여전히 준비 중이며 버전 릴리스 신호는 나타나지 않음.

한계 설명: 커밋 수와 병합 시간은 commit search에서 가져왔으며(검색 인덱스가 실제 병합보다 다소 지연될 수 있고, 일부 커밋 시간은 repos API pushed_at 기준), FlagBLAS 시리즈 커밋은 주로 AriesMTR 기여자 배치의 일괄 병합분입니다. gnews 링크는 본문을 크롤링할 수 없어 뉴스 측 판단은 제목과 다중 출처 교차 검증에 의존합니다. SUNRISE와 Kunlunxin은 org 회원사 공식 명단에 없으며 백엔드 생태계 사실에 따라 정리했습니다. “톈지즈쏸” 항목은 7/24 발사 이벤트에 대한 8/19 심층 보도로, 모니터링 기간 내 신규 발사가 아닙니다.
