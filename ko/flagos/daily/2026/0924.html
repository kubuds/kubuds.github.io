오늘의 중점: 2.2 GA(09-28)까지 4일——공식 목록이 L1 연산자 라이브러리를 수록 시작: 10개 컴포넌트 정식 버전 태그 일괄 저장소 반영

날짜: 2026-09-24　출처: community #114, community #113, release-2.2-rc2.yaml, 공식 목록 release-2.2.yaml

rc2 안정화 기간이 마지막 날에 진입했다(공식 일정 09-24 마감, GA는 09-28로 확정). 릴리스 엔지니어링은 09-24 새벽에 두 가지 작업을 완료했다.

첫째, 공식 릴리스 목록이 L1 연산자 라이브러리를 수록하기 시작했다. 09-24 01:49 ~ 01:50, 열 개 L1 모듈의 정식 버전 태그(순수 버전 번호, rc / post 접미사 없음)가 일괄적으로 찍혔다.

  • flaggems v5.4.0, flagfft v0.2.0, flagsparse v0.3.0, flagdnn v0.3.0, flagblas v0.3.0, flagtensor v0.3.0, flagaudio v0.3.0, flagattention v0.4.0, flaggems-vllm v0.2.0, flaggems-sglang v0.1.0.

각 정식 태그는 해당 모듈 rc2 브랜치 HEAD(즉 최신 검증 완료 post 태그 커밋)에 찍혔으며, 푸시 후 원격과 항목별로 재확인했다. 동반 PR(community #114 「add L1 operator libraries to the 2.2 official manifest」)이 01:51에 열렸다. 공식 목록 release-2.2/release-2.2.yaml에 열 개의 「공식 태그 ← rc2 기준선」 매핑(flaggems v5.4.0 ← post4; flagattention v0.4.0 ← post1; flaggems-vllm v0.2.0 ← post1; flaggems-sglang v0.1.0 ← post1; 나머지 각 항목 ← post2)을 추가했으며, 해당 PR은 여전히 심사 중(waiting merge)이다. 공식 목록에는 이전에 sglang-plugin-fl v0.2.0 한 건만 있었고(09-22 등록), 이 PR은 L1 계층의 첫 번째 일괄 수록이다.

둘째, rc2 채널이 13개 모듈 post 태그로 마무리되었다(09-24 00:42, community #113). release-2.2-rc2.yaml에서 13개 모듈 버전 필드를 각 rc2 브랜치 HEAD의 최신 검증 태그로 일괄 bump했다. flaggems rc2.post4; flagfft / flagdnn / flagblas / flagtensor / flagaudio rc2.post2(내용은 Debian / RPM 패키징과 Nexus 릴리스 체인, flagaudio 게인 항등 수정); flagtree 삼선 0.7.0rc2.post2; vllm-plugin-fl 이중선 post3; transformerengine-fl post2; flagscale post2. 모든 태그는 푸시 전에 원격과 확인했다.

같은 날 범위 측에는 또 하나의 축소 기록이 있다. community #112(FEP-0085)는 rc2 테스트에서 FlagCX 0.14.0-rc2와 FlagTree 0.7.0-rc2-triton3.6 모두 GEMM+ReduceScatter 구현이 발견되지 않았음을 지적했으며(FlagCX#620 참조), 개발 라인과 협의하여 해당 연산자를 2.2 범위에서 제외하기로 했고 FEP 문서, 테스트 계획, 구현 이력이 동시에 개정되었다(해당 PR은 여전히 심사 중).

판단: 정식 태그 일괄 등록 + rc2 목록 마무리 + 범위 축소 세 가지가 동일한 기간에 나타난 것은 2.2의 릴리스 면이 「코드 동결」에서 「릴리스물 동결」로 전환되었음을 의미한다. 목록, 태그, 범위 세 가지가 서로를 검증하기 시작했다. 앞으로 나흘의 관찰 지점은 #114의 병합과 L2 / L3 배치(vllm-plugin-FL, TE-FL, FlagScale, KernelGen 등)의 수록 순서다.

기간 개요: org 내 54개 저장소 중 23개가 기간 중 푸시가 있었다. 커밋 검색 히트 211건(13개 저장소에 걸침): FlagGems 59, build-infra 46, FlagQuantum 35, FlagSparse 20, FlagGems-Experimental 13, FlagGems-vllm 13, Torch-FL 10, FlagGems-sglang 5, docs 4, FlagTree 2, FlagAttention 2, community 1, FlagBLAS 1. 그 외 release-info(gh-pages), FlagScale, vllm-plugin-FL, TransformerEngine-FL, Megatron-LM-FL, flir, FlagFFT / FlagDNN / FlagTensor / FlagAudio 등의 태그와 브랜치 측 푸시는 검색에 포함되지 않았다(tags.atom은 저장소별로 확인 완료).

이번 기간의 형태 = 「릴리스물 동결」+「플랫폼 면 확장」+「연산자 검수 배치」: 릴리스 엔지니어링은 「오늘의 중점」과 1.1 / 1.2 참조. FlagTree 오플랫폼 태그와 thead-ppu 애플리케이션 페이지가 같은 날 등장했다(1.2 / 1.3). FlagGems의 KernelGen 배치와 Kunlunxin 최적화 배치는 GA 전 성능 달성 조치다(1.4).

중영문 24개 쿼리어(7개 컴포넌트명 + 생태계 및 멤버십 단위어)가 24시간 모니터링 기간 내 컴포넌트명 검색에서 연속 열아홉 번째 모니터링 기간 제로 히트; 생태계 측 히트는 모두 회의 시즌 연장선에 속함(2.1 ~ 2.3 참조). Baidu 검색에서 「FlagOS」의 공식 출처는 여전히 Zhiyuan 커뮤니티와 GitHub가 주류. 평온한 모니터링 기간이 이미 상시화되었으며, FlagOS의 대외 정보 증분은 여전히 릴리스 리듬과 회의 노드에 집중되어 있다.

3. 멤버십 단위 심층 분석

3.1 Moore Threads: RLinf 공식 CI에 MTT S5000接入——「단방향 적응」에서 「양방향 공동 구축」으로 (09-22/09-23 보도)

날짜: 2026-09-19(살롱) ~ 2026-09-23(보도)　출처: 증권시보·인민재훈, 위페이왕, PChome

Moore Threads가 주최한 「MUSA 오픈소스 기술 살롱: RLinf × MUSA Meetup」(09-19, 베이징)에서 임바디드 AI 강화학습 실측 데이터 한 세트가 공개되었다: RLinf 공식 CI는 0.3 버전부터 MTT S5000을 연동하며, 모든 코드는 메인 브랜치에 병합되기 전에 국산 컴퓨팅 파워로 자동화 검증을 완료해야 한다; RLinf는 이미 MUSA 백엔드 실행을 공식 지원한다. 핵심 데이터: 248개 병렬 환경, 동일 레시피와 랜덤 시드 하에서 S5000과 국제 주류 GPU의 훈련 곡선 점진적 상관계수 r = 0.976(191 스텝 공통 윈도우); 실기 LIBERO-Spatial 평가에서 두 하드웨어 세트의 정책 성공률이 정합; 엔지니어링 측 전체 스텝 소요 시간이 2549초에서 1888초로 감소(-26%), GPU 유휴율 18.5%에서 3.1%로 압축; 연산자급 벤치마크에서 S5000의 GEMM과 어텐션 성능이 국제 주류 GPU의 1.6 ~ 2배에 도달. 양측은 또한 엔드-클라우드 협업 프레임워크(클라우드 S5000 / 엔드 MTT E300)를 공동 구축할 예정이다. 「단방향 적응에서 양방향 공동 구축으로」가 이 항목의 성격을 규정하는 핵심이다——오픈소스 프레임워크가 국산 컴퓨팅 파워를 CI 디렉터리에 등재한 것은 생태계 위치의 전환에 해당한다.

동일 모니터링 기간 연산자 측 작업: FlagGems mv 최적화(#6591), FlagGems-vllm 공유 INT4 / FP8 융합 Marlin MoE(#835)와 TLE topk_softplus_sqrt(#838), FlagGems-sglang MUSA 융합 router(#106), FlagSparse MUSA 최적화, Torch-FL MUSA strided softmax 수정(#398), FlagTree 0.7.0+mthreads3.6 태그.

4. 요약 및 동향 관찰

  • 2.2 릴리스 측면은 “릴리스물 동결” 단계에 진입: 10개 컴포넌트 정식 버전 태그가 일괄 저장소에 등록되고(01:49 ~ 01:50), rc2 목록 13개 모듈 post 태그가 마감되며(00:42), FEP-0085 범위가 축소되었다(17:52)——세 라인이 동일한 모니터링 기간 내에 “태그, 목록, 범위”의 정합을 완료했다. GA(09-28)까지 4일 남았고, rc2 안정화 기간은 오늘 마감되며, 관찰 지점은 목록 L2 / L3 배치 수록과 Go/No-Go로 전환된다.
  • 플랫폼 측면은 계속 확장되고 있으며 경로는 각기 다르다: thead-ppu2.1.0 애플리케이션 페이지는 “수동 등록, 사후 관리”의 과도기 형태에 속한다. FlagTree 5개 플랫폼 태그는 “벤더 특화”를 정식으로 버전 체계에 편입시켰다. vllm-plugin-FL의 비런(Biren) SUPA 백엔드 PR은 “신규 벤더가 플러그인 저장소에서 진입”하는 또 하나의 사례다. 다원적 칩 구상은 GA 전에도 계속 확장되고 있다.
  • 연산자 라이브러리는 전면적으로 “검수와 튜닝” 리듬으로 전환: KernelGen 단일 모니터링 기간 16건(롱테일 보충 지속) + 캉루프(Kunlunxin) 31개 연산자 최적화 배치(27/31 목표 달성) + mv / GEMM / 어텐션 다중 플랫폼 수정——특성 동결 이후의 일정 형태와 완전히 일치하며, GA 전 마지막 주의 성능 작업이 집중적으로 방출되고 있다.
  • 양자와 희소라는 두 “비주류” 컴포넌트는 자체 리듬을 형성: FlagQuantum은 두 모니터링 기간 연속 30+ 건을 기록하며 Cirq / Qiskit Aer 이중 브리지를 완성했고, FlagSparse와 NCIC-AlphaSparse는 6건의 양방향 동기화를 이루었다. 이들의 엔지니어링 성숙도는 GA 전에 현저히 상승하여, 2.2 외의 장기 관찰 항목을 구성한다.
  • 대외 정보 측면: 학회 시즌 막바지 + 개방형 소프트웨어 스택 서사가 동시에 울린다: AICC2026 회의 후 종합에서 FlagOS의 위상을 재언급, Open3D-PIMC 후속 보도, 다모원(DAMO Academy) 쉬안톄(XuanTie) SAIL의 “GitHub 연구개발 메인라인”——중국 AI 칩의 “소프트웨어 스택 개방”과 FlagOS의 “다원 통합 스택”이라는 두 서사가 같은 주에 집중 방출되었으며, 컴포넌트 수준 검색은 여전히 열아홉 번째 평온한 모니터링 기간에 머물러 있어, 정보 증분이 여전히 미디어 측이 아닌 릴리스 리듬에 의해 주도됨을 보여준다.
  • 관찰 대기 항목: ① community #114 병합과 L2 / L3 배치 수록, ② FlagTree 0.7.0 시리즈 태그에 대응하는 정식 Release와 문서(wiki가 이미 정비를 시작함), ③ 다모원 쉬안톄 PPU의 런타임 / 컴파일러 / 연산자 계층에서의 후속 관리(TE-FL PPU CI, FlagGems-vllm TLE 연산자는 이미 선행 신호), ④ 비런 SUPA, Sunrise 등 신규 벤더 백엔드의 병합 진행 상황.
