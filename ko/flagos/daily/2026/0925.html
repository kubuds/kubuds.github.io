오늘의 중점: 2.2 GA (09-28)까지 3일——납품 범위 감사 개시: FEP 18건 유지, 6건은 2.3으로 연기

날짜: 2026-09-24　출처: community #115, community #114

rc2 안정화 기간은 공식 일정에 따라 09-24에 종료되었고, GA는 09-28로 정해졌다. 기간 내 릴리스 엔지니어링의 주된 움직임은 「릴리스물 동결」에서 「범위와 선언 동결」로 전환되었다——09-24 14:29 (베이징 시간), community 저장소에 PR #115 「docs: define delivered FlagOS 2.2 FEP scope and defer remaining work to 2.3」가 개설되었다 (브랜치 docs/fep-2.2-rc2-audit-20260924, 당일 16:12까지 두 차례 푸시):

  • 범위 이분화: 2.2 인덱스에는 18개 Implemented FEP가 포함되며(유지), FEP 0019, 0069, 0081, 0084, 0093, 0100 여섯 개는 목표 버전을 2.3으로 변경하고 상태를 Deferred로 표기한다.
  • 유지 항목 긴축: 각 유지 FEP는 “구현된 인터페이스 + 검증된 구성”으로만 한정하고, 나머지 목표는 명시적 2.3 섹션과 연관된 deferred-work 인덱스로 옮긴다.
  • RC2 대조 업데이트 출처: source revisions, API, 패키징 세부 사항, 테스트 명령과 연관 PR을 항목별로 갱신하고 검증 출처 추적, 플랫폼 실패 및 알려진 제한을 유지한다.
  • 기준 명확화: Tree primitive QA와 NVSHMEM 융합 / FlagCX-backed 융합, 그리고 Compressor 산출물 테스트와 전모델 추론 인수를 명확히 구분한다——”컴포넌트 수준 검증”을 “엔드투엔드 인수”로 말하지 않도록 한다.
  • 문체 제약: 간결한 영어를 요구하고, 템플릿 문구와 “근거 없는 완료 / 성능 선언”을 삭제한다.

같은 기간, L1 연산자 라이브러리 10개 컴포넌트의 공식 태그 목록(community #114: flaggems v5.4.0, flagfft v0.2.0, flagsparse v0.3.0, flagdnn v0.3.0, flagblas v0.3.0, flagtensor v0.3.0, flagaudio v0.3.0, flagattention v0.4.0, flaggems-vllm v0.2.0, flaggems-sglang v0.1.0)은 여전히 심사 중(waiting merge)이다.

판단: 어제 관찰한 것은 “목록, 태그, 범위 세 가지가 서로를 검증”하는 것이었고, 오늘 #115는 검증을 세 번째 층——대외 선언 자체——으로 밀어 올렸다. GA 전 3일에는 신규 기능을 쫓지 않고, “구현됨 / 검증됨 / 연기됨”을 분리해 서술하며 항목별로 근거를 연결한다. 이는 릴리스 규율에 관한 행동이다. 2.2의 공개 소개는 이번 버전의 FEP 문서를 사실 초안으로 삼고, 이후 2.3의 개발 서사(3D 컴퓨팅, 양자 등 신규 방향 포함)도 2.2 납품 경계와 공식적으로 분리된다.

1. 오픈소스 프로젝트 진행 상황(GitHub 동향)

1.1 릴리스 엔지니어링: L1 목록 머지 대기, 개발 메인라인 일제히 승격(09-24)

날짜: 2026-09-24　출처: community #114, FlagSparse #90, FlagAudio #20, FlagAttention #77

  • #114 상태: L1 10개 컴포넌트 “공식 태그 ← rc2 베이스라인” 매핑 목록이 여전히 심사 중이다. 10개 공식 태그의 원격 항목별 재확인 대조는 완료되었으며, 목록이 머지되면 2.2 공식 릴리스물의 구성 요소가 된다.
  • 개발 메인라인 승격: 공식 태그가 저장소에 반영된 다음 날, 두 메인라인이 먼저 다음 주기로 전환했다——FlagSparse main은 0.4.0으로 승격(09-24 19:10, PR #90 “Bump main version to 0.4.0”), FlagAudio 버전 라인은 0.4.0으로 교정(19:20, PR #20, 중간에 한 차례 되돌림과 재적용을 거쳐 최종적으로 0.4.0으로 마무리), FlagAttention은 동시에 “update version” 커밋을 실행(18:12, PR #77).
  • 의미: 2.2 릴리스물(rc2 베이스라인 + 공식 태그)과 개발 메인라인(0.4.0 계열)이 버전 번호상 공식적으로 분기했다——2.3 개발 주기가 사실상 시작되었으며, 2.2 GA 전 목록 마무리와 병행해 추진된다.

  3. 신규 칩 접속과 버전 추적의 이중 라인 지속: Biren은 2계층 동시 진입(FlagGems + vllm-plugin-FL), Sunrise는 vLLM 0.24 라인 이식 완료; 「연산자 라이브러리 + 추론 플러그인 + 컴파일러」 3계층 동형 접속 모델이 반복 등장하며 외부 칩의 FlagOS 접속 표준 경로로 자리잡음.
  4. 플랫폼 매트릭스의 세밀도가 릴리스 전 빠르게 향상: build-infra가 단일 야간에 sglang 애플리케이션 페이지 7연속 릴리스(7개 플랫폼 각 1개), FlagTree 0.7.0 변형이 10여 개로 확대——2.2의 「플랫폼 커버리지 표」는 여전히 밀도를 높이는 중이며, 커버리지의 검증 가능성이 이번 릴리스의 핵심 자산.
  5. Ascend 910C 링크 준비 완료: RL E2E 이중 구성 통과 + 특권 컨테이너 수정으로, 2.2의 훈련 / RL 시나리오에서의 Ascend 선언에 재현 가능한 증거 체인을 제공(#115가 강조한 「검증 출처 보존」 요구에 정확히 대응).
