오늘의 주요 소식: MetaX Hy4 플래그십 Day0, FlagOS W8A8 가중치 공개 (11-20)

날짜: 2026-11-20　출처: 10jqka의 MetaX 공식 위챗 전재.　참고: Pandaily.

  • 이벤트: 11월 20일 텐센트 훈위안(Hunyuan)이 플래그십 Hy4를 오픈소스로 공개.
  • 적응: MetaX 시윈(Xiyun) C 시리즈가 당일 Day0 적응을 완료하고 플랫폼에서 구동 확인.
  • FlagOS와의 관계: MetaX가 Zhongzhi FlagOS 커뮤니티와 협력하여 MetaX 연산력에 맞춘 W8A8 버전을 제공.
  • 배포 위치: 양자화 가중치를 ModelScope와 Hugging Face에 업로드하여 개발자가 바로 사용 가능.
  • MetaX 설명: MXMACA 스택은 40여 종 프레임워크, 1000여 개 모델, 6000여 개 오픈소스 프로젝트를 지원.
  • 연산자 범위: 공식 발표에 따르면 PyTorch 2.8의 2410개 GPU 연산자를 전면 지원.
  • 누적 수치: MetaX는 2025년 12월부터 52개 모델의 Day0 적응을 완료했다고 밝힘.
  • 수치 차이: 11월 18일 Hy4 flash 관련 공식 홈페이지 기사에는 51개로 기재되어 있어 두 번의 수치가 하나 차이.
  • 테스트 규모: Pandaily는 서버 4대, 각 8장의 64GB C550, 총 32카드로 기록.
  • 부하: 동시성 64, 입력 약 4K, 출력 약 1K token.
  • 처리량: decode-graph 활성화 시 집계 출력 80.98 tokens/s, 비활성화 시 52.31, 약 55% 향상.
  • 지연: 대기열 포함 후 첫 token 지연은 227.2초와 220.5초로, 활성화 시 오히려 더 느림.
  • 컨텍스트 경계: 배포 구성의 최대 컨텍스트는 65,536 token으로 Hy4가 주장하는 100만에 크게 미달.
  • 미완료 항목: 모델 카드의 두 가지 멀티모달 평가는 「진행 중」으로 표시.
  • 라이선스: FlagRelease 측은 Apache-2.0으로 표기, 텐센트 Hy License 1.0은 양자화 가중치를 파생 저작물로 간주.
  • 라이선스 후속: 대규모 MaaS는 원 라이선스에 따라 별도 신청 필요, 배포 패키지의 라벨만 보고 판단 불가.
  • 관찰: FlagOS 최초의 제3자 미디어 검증이 포함된 상용 추론 사례.
  • 관찰 후속: 처리량과 지연은 같은 방향이 아니며, 32카드가 곧 프로덕션 검증을 의미하지 않으므로 인용 시 두 수치를 함께 봐야 함.

오늘의 핵심: Intellifusion IFWA, FlagOS 통합 컴파일러에接入 (11-20)

날짜: 2026-11-20　출처: Intellifusion 공고 10jqka 인용.　참고: FlagTree #1598.

  • 공고: Intellifusion과 Zhiyuan(BAAI)의 기술 협력 첫 오픈소스 성과, 시점은 11월.
  • 소프트웨어 스택: Intellifusion의 DeepVerse 및 DeepEdge 시리즈 대상 소프트웨어 스택은 IFWA.
  • 코드 위치: FlagTree의 triton_v3.8.x 브랜치에 intellifusion 백엔드 추가, PR 번호 #1598.
  • 머지 시점: #1598은 11월 12일 머지, 이번 주 신규 아님.
  • 규모: +21491/-8, 92개 파일, 리뷰는 sunnycase, menchunlei, Galaxy1458.
  • 백엔드 역할: 개발자는 여전히 Triton으로 작성, FlagTree가 컴파일 작업을 Intellifusion 백엔드에 위임.
  • 백엔드 후속: 백엔드는 다시 IFWA의 컴파일 툴체인, 런타임, 드라이버에 연결.
  • 오픈소스 경계: IFWA 컴파일러와 런타임은 여전히 통제된 바이너리 툴킷으로 제공, 오픈소스는 연동 계층과 예제.
  • FlagGems 첫 배치: 산술, 합계, 최댓값, Softmax, LayerNorm, TopK 커버.
  • 정밀도: IFWA 백엔드는 FP16, FP8, FP4 세 가지 정밀도 행렬 곱 지원.
  • 미머지: FlagGems의 명시적 IFWA 백엔드 #9545는 여전히 심사 중, 11월 20일 업데이트 있음.
  • 연동 방식: #9545는 GEMS_VENDOR=intellifusion으로 ifwa 디바이스 등록.
  • 후속: 양측은 신규 모델 적응을 추진하고 FlagOS 배포판 편입을 탐색.
  • 후속 계속: 클라우드 서비스 파트너와 공동 발표하여 성과를 상용 경로로 추진.
  • 관찰: 연동 비용이 백엔드 하나와 환경 변수 하나로 압축됨.
  • 관찰 후속: 멤버사 명단에는 아직 Intellifusion이 없지만, 백엔드 매트릭스에 한 줄 추가됨.

오늘의 핵심: Runtime 2.3.0 세 이미지 라인 정산 완료, CUDA 13.0.3 라인 개설 (11-22)

날짜: 2026-11-22　출처: #1951.　참고: community #176.

  • 2.3.0 기록：base와 runtime 양측의 변경 기록을 벤더 라인별로 각각 저장소에 기록한다.
  • 세 개 라인 포함：ascend-cann8.5.0, ascend-cann8.5.0-910c 및 metax-maca3.8.1.3.
  • 방식：이미지 내에 베이킹된 시스템 패키지 버전을 태그와 함께 기록하며, 하나의 PR이 하나의 태그에 대응한다.
  • 검증：두 백엔드의 버전 데이터 검증이 모두 통과했으며, 0 실패, 0 스킵.
  • 신규 백엔드：#1951에서 nvidia-cuda13.0.3 추가, base와 runtime 두 계층 포함.
  • 위치：이는 두 번째 CUDA 13 라인이며, 툴체인 마이너 버전은 13.0이다.
  • 추가 이유：vLLM이 끌어오는 일부 의존성은 특정 CUDA 마이너 버전으로 사전 컴파일되어 있어 커뮤니티에서 변경할 수 없다.
  • 호환 방향：CUDA 마이너 버전은 전방 호환만 되므로, 13.3의 toolchain은 cu130 의존성의 잘못된 쪽에 위치한다.
  • 불변 항목：torch 클로저는 여전히 2.13.0+cu130이며, 툴체인만 이동했다.
  • NCCL 차이：13.3의 NGC 런타임 이미지에는 NCCL이 없어 수동 설치 후 libnccl2를 hold해야 한다.
  • 다른 쪽：13.0.3 이미지는 2.28.3-1+cuda13.0을 자체 포함한다.
  • FlagCX：여전히 0.14.1+cuda13.3에 머물러 있으며, libcudart.so.13을 링크하는 유일한 휠이다.
  • 검증：두 이미지를 h20에서 빌드하고 푸시했으며, 컨테이너 내 torch가 CUDA 13.0 사용 가능을 보고한다.
  • 검증 계속：flagcx가 privateuseone으로 등록되었고, import flag_gems가 통과했다.
  • 미완료：이 라인에는 아직 앱 계층, 상태 매트릭스 셀 및 extras:가 없다.
  • 로드맵：community #176의 FlagOS 2.3 목표 출시일은 여전히 12월 30일이다.
  • 로드맵 계속：SIG Compiler 첫 항목은 Qwen3.8과 GLM5.3 Flash를 MegaKernel에 컴파일하는 것이다.
  • 관찰：베이스 계층이 라인 교체에서 기록으로 전환된 것은 기능이 동결되고 있음을 의미한다.
  • 관찰 계속：CUDA 13의 두 번째 라인 개설은 업스트림 의존성에 의해 강제된 것이지, 매트릭스를 능동적으로 확장한 것이 아니다.

1.2 FlagQuantum: 3일간 245건, PMH 선형 CNOT 합성 구현 (11-22)

날짜：2026-11-22　출처：#1296.　참고：#1084.

  • 규모: 245개 커밋으로 조직 내 1위입니다. 병합 측면에서는 최신 100개 PR 중 46개를 차지합니다.
  • 일자별: 11-20은 46개, 11-21은 23개, 11-22는 176개입니다.
  • 주요 라인 1: 라우팅: #1299는 네이티브 비용 실험에서 완료된 SABRE 실험을 재사용합니다.
  • 라우팅 후속: #1297은 실험 간 의존성을 재사용하고, #1295는 스코어링 할당 오버헤드를 낮춥니다.
  • 라우팅 추가 후속: #1289는 항등 레이아웃에 대해 포레스트 순회를 건너뛰고, #1276은 고정 크기 행렬 곱셈 반복 오버헤드를 낮춥니다.
  • 주요 라인 2: 합성: #1296은 가드가 적용된 네이티브 선형 CNOT 합성을 추가하며, +6988/-0, 7개 파일입니다.
  • 구현 출처: Qiskit 2.6.2의 Patel–Markov–Hayes 알고리즘에서 가져왔으며, Apache-2.0 및 수정 사항 명시를 포함합니다.
  • 정확성: 120개의 고정 네트워크가 설치된 Qiskit 2.6.2의 게이트 시퀀스와 비트 단위로 일치합니다.
  • 열거: 진리표로 512개의 3선 이진 행렬을 열거하고, 168개의 가역 행렬만 허용합니다.
  • 이점: 72쌍의 고정 제어에서 회귀가 없으며, 21/36 전체 상호 연결과 3/36 선 쌍에서 2체 게이트 수가 감소합니다.
  • 비용: 두 그룹 모두 변경되지 않은 기본 시간 및 메모리 임계값을 통과하지 못합니다.
  • 주요 라인 3: 내결함성: #1084는 여전히 검토 중이며, 네이티브 내결함성 컴파일과 가역 위상 실행을 수행합니다.

  • 분업 계속: 모델 및 트래픽 파트너는 수요를 제공하고 검수에 참여하며, Qingmao는 소프트웨어와 운영을 담당한다.
  • 첫 파트너: Zhiyuan, Shanghai Data Port, China Telecom Hubei 지사.
  • 관찰: 11-19 영문 기사는 추론 방안만 다루었고, 이 기사에서야 정량적 검수 기준을 제시했다.
  • 관찰 계속: FlagOS와의 관계는 방안 계층에 있으며, 코드 계층이 아니다.

2.3 CSDN 칼럼 신규 원고 없음, 11-19 Hunyuan Hy4 flash 9칩 보충 기록 (11-19)

날짜: 2026-11-19　출처: Hunyuan Hy4 flash 9칩 Day 0.　참조: CSDN 칼럼.

  • 기간 내: 칼럼 18개 링크의 게시 시간을 편별로 확인한 결과, 11-20 06:00 이후 신규 원고는 없다.
  • 최신 원고: 11월 19일 14:11의 Hunyuan Hy4 flash로, 이전 기간에 속한다.
  • 보충 기록 사유: 지난 기간에는 첫 페이지 상단 고정 3편만 확인하여 이 편을 놓쳤다.
  • 커버 플랫폼: T-Head, NVIDIA, Ascend, Hygon, Kunlunxin, MetaX, Moore Threads, Tsingmicro, Iluvatar CoreX, 총 9개 사.
  • H100 개봉: 8카드 80GB, 64 동시성, 4K 입력 1K 출력.
  • 처리량: 출력 처리량 35.9% 향상, 첫 token 지연 29.1% 감소, token당 소요 시간 24.3% 감소.
  • 장입력: 입력을 16K와 32K로 늘렸을 때 처리량은 각각 14.5%와 12.8% 향상되었다.
  • 압축 희소 어텐션: 후보 그룹 전개가 33개 kernel에서 1개로 합쳐졌다.
  • 실측: H100에서 90.44마이크로초에서 4.00마이크로초로 감소, 22.63배 가속.
  • 기타 융합 항목: FWHT + FP8 양자화 18.37배, 희소 레이어 MRoPE 17.32배.
  • 또 다른 예: 페이지 캐시 쓰기 8.44배.
  • iHC: prefill 단계 연산자 지연 44% 감소, decode 단계 19% 감소.
  • 적용: Pre/Post 연산자는 FlagGems-vLLM의 ihc 디렉터리에 공개되었다.
  • 정밀도: MATH-500, GPQA Diamond, MMBench, MMStar 네 항목이 NVIDIA 네이티브와 정렬되었다.
  • 관찰: FlagOS가 ‘개봉 시 NVIDIA 네이티브 초과’를 제목으로 내건 것은 이번이 처음이다.
  • 관찰 계속: 또한 2.2의 성능 계산에 대한 첫 공개 대조이며, 기준이 같은 글에 명시되어 있다.

2.4 Zhiyuan 커뮤니티와 공식 사이트: 수집 가능 범위 내 FlagOS 항목 없음 (11-23)

날짜: 2026-11-23　출처: Zhiyuan 커뮤니티.　참고: FlagOS 공식 웹사이트.

  • Zhiyuan 커뮤니티: 홈페이지에서 수집 가능한 콘텐츠 중 11-22와 11-23 푸시가 있으나 FlagOS 항목은 없음.
  • 검색 페이지: 클라이언트 렌더링 방식이라 목록을 수집할 수 없어 홈페이지 결론을 기준으로 함.
  • 공식 웹사이트: flagos.io 홈페이지는 앱 셸만 반환하고 본문은 스크립트로 주입됨.
  • 결론: 2.3의 외부 공개 창은 아직 열리지 않았고 미러 측이 먼저 움직임.
  • 관찰: 기반 레이어의 진전은 build-infra에서 먼저 나타나고 이후 문서와 공식 웹사이트에 나타남.
  • 관찰 이어서: 이러한 지연은 지난 버전에서도 마찬가지였음.

3. 멤버사 심층 분석

3.1 MetaX: Hy4와 Hy4 flash 두 차례에 걸쳐 Day0 (11-20)

날짜: 2026-11-20　출처: MetaX 공식 웹사이트 Hy4 flash.　참고: Economic Observer.

  • 두 차례 적응: 11월 18일 Hy4 flash가 오픈 웨이트로 공개되어 MetaX가 당일 적응.
  • 두 번째: 11월 20일 플래그십 Hy4가 오픈소스로 공개되어 MetaX가 당일 다시 한 번 적응.
  • 두 모델은 같은 것이 아님: Hy4 flash는 총 파라미터 224B, 활성 12B의 MoE.
  • KV Cache: 크기는 Hy4의 1/6, Hy3의 1/24.
  • 플래그십: Hy4는 처음으로 시각 능력과 컴퓨터 조작을 도입하여 생산성에 포지셔닝.
  • 수치 차이: 공식 웹사이트 11-18 기사에는 51종으로, 11-20 관위 기사에는 52개로 기재.
  • 기술 의존: 두 차례 모두 MXMACA 스택으로 분류되며 vLLM과 SGLang을 네이티브 호환.
  • 분업: 하드웨어 적응은 MetaX가 직접 수행하고, 크로스 칩 통일과 양자화 버전은 FlagOS 측에서 제공.
  • 관찰: 동일 패밀리가 두 차례에 걸쳐 출시되면서 Day0 성과가 두 차례의 대외 표현으로 나뉨.
  • 관찰 이어서: 횡적 비교를 할 때는 먼저 모델명을 정렬한 후 횟수를 봐야 함.

3.2 Moore Threads: Lushan 소비자용 카드 12-29 확정, FlagOS와는 두 갈래 (11-22)

날짜: 2026-11-22　출처: Tencent News.　참고: ZOL.

  • 시간과 장소: MDC 2026은 12월 29일부터 30일까지로 확정, 장소는 베이징 중관춘 국제혁신센터.
  • 코드명: Lushan, 5세대 Huagang 아키텍처 기반.
  • 사전 예고 기준: 이전 세대 MTT S80 대비 지오메트리 16배, 레이트레이싱 50배, AI 64배.
  • 게임 성능: 공식 기준은 15배.
  • 메모리: 공식 발표로는 최대 4배 향상, S80이 16GB이므로 이를 근거로 추산하면 최대 64GB.
  • 기준 주의: 제품 매니저의 발언은 개인적 표현이며 최종적으로는 발표회 기준.
  • 포지셔닝: DirectX 12 Ultimate를 지원하며 국내 최초 하드웨어 실시간 레이트레이싱 소비자용 카드로 불림.
  • FlagOS와의 관계: 이 라인은 그래픽 및 엣지 제품 라인으로 FlagOS 컴포넌트와 교집합이 없음.
  • FlagOS 측 동향: Moore Threads가 이쪽에서 하는 것은 _foreach 특화와 MUSA 백엔드.
  • 관찰: 멤버사의 제품 리듬과 FlagOS의 버전 리듬은 각자 다른 라인을 감.

3.3 코드 측 분포: Ascend와 Hygon이 각각 큰 몫, Enflame은 모니터링 기간 내 커밋 제로 (11-22)

날짜: 2026-11-22　출처: vllm-plugin-FL #711.　참고: Torch-FL #884.

  • Ascend: FlagGems 하루 44개의 foreach 연산자.
  • Ascend 계속: FlagGems-vllm에 910B용 MegaGate가 심사 중이고, FlagTrain에는 융합 프로젝션 최적화가 있음.
  • Hygon: Torch-FL #884가 HSDP가 네이티브 스트림을 반환하도록 함.
  • Hygon 계속: vllm-plugin-FL #711이 DCU를 vLLM 0.32에 연결, +1110/-117, 27개 파일.
  • Hygon 재계속: FlagGems-vllm #1389가 Megamhc 추가.
  • Moore Threads: FlagGems 11건의 _foreach, FlagGems-vllm에 MUSA 특화 있음.
  • Moore Threads 계속: FlagCX #722가 심사 중이며 MUSA 플랫폼 추가.
  • Qingwei: Torch-FL #889가 tsm-249에서 검증되었으며 여전히 심사 중이고 모니터링 기간 내 병합되지 않음.
  • Iluvatar CoreX: FlagTree #1704가 iluvatar3.6의 gems-vllm 테스트를 열었음.
  • Cambricon: build-infra가 neuware4.4.3을 퇴역시키고 네 건으로 build, app, flagcx와 wheel을 정리.
  • Enflame: 모니터링 기간 내 컴포넌트 커밋 없음, 2차 시장의 여파는 지속 중.
  • Kunlunxin: FlagGems 1건의 fake_quantize XPU 다운그레이드 수정.
  • 관찰: 멤버 단위의 코드 측 투입은 주가와 무관.
  • 관찰 계속: Enflame은 이번 주 컴포넌트 계층에서 제로 동작이었고, 자본 계층에서는 가장 많이 논의된 기업.
