1. カーネルとバージョン動向

メインリポジトリでは調査期間内に 9 件のマージと 1 件の RISC-V リファクタリングコミットが完了し、直近一週間で最も密集したマージバッチとなった；レビュー側では 8 件の審査中提案と複数の欠陥チケットが同時に更新された。

1.1 Next RISC-V 提案の新規コミット：RISC-V アーキテクチャ移植リファクタリング、RV32/RV64 共通層の統一（10-15）

日付：2026-10-15 11:51（コミット時間）　出典：PR #10320、リファクタリングコミット 6bf3686

RISC-V 大規模リファクタリング提案（#10320）は調査期間内に大型リファクタリングコミット「[libcpu][risc-v] Refactor the RISC-V architecture port」をプッシュした：オプションの RISC-V 統一共通層（RV32/RV64）を導入し、ARCH_RISCV と ARCH_CPU_64BIT でアーキテクチャと XLEN の選択を完了し、context、trap、MMU、cache、timer、SBI、SMP および ISA 処理を統一し、PLIC、CLIC、ACLINT、APLIC および IMSIC のサポートを新規追加し、物理 HART ID から論理 CPU ID へのマッピングテーブルを確立した；T-Head ベンダーオーバーライドブランチは保持される。qemu-virt64-riscv が新共通層に最初に接続した BSP となり（同一ディレクトリで RV32 と RV64 S-mode をサポート）、RT_USING_RISCV_NEW_COMMON マクロを選択していない既存 BSP は引き続き legacy_common / common64 パスを使用する。コミット後、自動フローが再実行された（フォーマット通知、レビュー割り当て、membrowse メモリレポート）；RISC-V 調整追跡チケット #11246 も同時に更新された（11:52）。提案はオープンのまま維持されている。

1.2 ネットワークスタック修正バッチのマージ：ping 統計のゼロ除算と最終パケット遅延の 2 件が連続して着地（10-14 ~ 10-15）

日付：2026-10-14 09:33 ~ 2026-10-15 09:10（マージ時間）　出典：PR #11853、PR #11866

netdev コンポーネントの調査期間内に ping 関連の修正が 2 件マージされた。1 件目（#11853、10-14 マージ）は、ターゲット到達不能時に ping 統計のゼロ除算により shell がクラッシュする問題を修正し、関連する欠陥票 #11852 は同日クローズされた。2 件目（#11866、10-15 午前にマージ）は、最終パケットの遅延ロジックを修正した——元のループ判定が常に偽となるため最後のパケットの後も遅延を追加し、かつ遅延がゼロでも rt_thread_delay(0) を呼び出して不正な引数を返していた。実際の所要時間を記録し、最終パケットでなくかつ遅延がゼロより大きい場合にのみ呼び出すよう変更し、関連する欠陥票 #11865 は同日クローズされた。同方向の初期提案 #11862 はマージされずにクローズ済み。

1.3 カーネルと USB 修正バッチのマージ：calloc オーバーフローと USB host インターフェース数検証の強化（10-14）

日付：2026-10-14 09:28 ~ 10:17（マージ時間）　情報源：PR #11848、PR #11822

カーネル側では calloc の整数オーバーフロー問題（#11848）を修正し、コミュニティ貢献者によりコミットされマージされた。USB 側では legacy USB host の強化（#11822）を完了した。「host がデバイスから報告されたインターフェース数を直接信頼し、範囲外アクセスを引き起こす可能性がある」という欠陥票（#11288）に対し、インターフェース数の上限判定およびインターフェース列挙、クリーンアップ経路の境界処理を追加し、2 件のコミット（インターフェース数検証の明確化、列挙とクリーンアップの収束）を同時にマージし、欠陥票は同日クローズされた。

1.4 複数ベンダーの BSP とドライババッチのマージ：ra6w1、ESP32-C3、STM32H723、RISC-V ベクタ復元など（10-14）

日付：2026-10-14 09:13 ~ 09:44（マージ時間）　情報源：PR #11814、PR #11847、PR #11851、PR #11861、PR #11855

メンテナが複数ベンダーの BSP とドライバ更新を集中的にマージした。ルネサス ra6w1 はシステムリソース配分を最適化（メインスレッドスタックを 4096 に調整、RC コミット、#11814）。Espressif ESP32-C3 は Windows パスにおける IRAM ワイルドカードマッチングと Bluetooth リンカスクリプトの誤マッチング問題を修正（#11847）。STM32H723-DM-MC02 は SPI6 BDMA サポートを追加（#11851）。RISC-V ベクタユニットは設定後の vstart 状態復元を修正（#11861）。components/drivers の reset フレームワークは ulog と同時有効化時のビルドエラーを修正（#11855）。

1.5 審査中提案がメンテナのレビューを集中的に受領：lwip マクロ制御、ESP32-S3 BSP、rt_kprintf 修正、STM32 イーサネット ops（10-14 ~ 10-15）

日付：2026-10-14 10:13 ~ 2026-10-15 09:22（レビュー時間）　情報源：PR #11815、PR #11844、PR #11864、PR #11819

メンテナは調査期間内に 4 件の審査中提案に対してレビューを行った。lwip セグメントマクロ制御提案（#11815）は 10-15 午前に変更要求を受けた（それ以前に作者は 10-14 に変更を再プッシュ済み）。ESP32-S3 ボードサポート提案（#11844）は作者が 10-14 にレビュー指摘へ対応・修正した後、10-15 午前にメンテナによる行レベルコメント付きの再レビューを受けた。rt_kprintf 暗黙宣言修正提案（#11864）は変更要求を受けた——本件は IAR 環境で宣言を含まない場合に %f ログ出力が異常となる問題を修正することを目的とする。STM32 の新イーサネットドライバ ops 層適配提案（#11819）は変更要求を受けた。4 件はいずれもオープン状態を維持している。

1.6 その他の審査中提案の動向：clang-format 追加コミット、N32 タイマ提案の再オープン、ASan 提案の追加テスト（10-14）

日付：2026-10-14 09:46 ~ 12:27（更新時間）　出典：PR #11859、PR #11812、PR #11772

clang-format 規範詳細化提案（#11859）に新たに2件のコミットを追加：スタイル規則の微調整（整列、括弧の改行と間隔）を行い、thread.c で実際の効果を実証；N32 シリーズタイマ補完提案（#11812）はメンテナにより再オープン——本件は N32H47x/48x と H49x に共用ドライバブランチを補完し、ci-attach エントリを併せて整備；ヒープメモリ ASan 提案（#11772）の作者は補足説明を追加：新規の rt_memcpy、rt_memset、rt_memmove の範囲チェックとオプションの libc インターフェースラッパーを追加し、越境、解放後アクセス、ゼロ長などの境界テストを補完、最新 CI は全て通過したと報告。

1.7 旧欠陥票に新たな議論：at_gethostbyname オーバーフロー対処方針の明確化待ち（10-14）

日付：2026-10-14 16:26（コメント時間）　出典：Issue #5913

2022 年に作成されたヒープバッファオーバーフロー報告票（#5913）は調査期間内に新たなコメントを獲得：at_gethostbyname における ip_str 処理関連のオーバーフローリスクの議論が2年以上棚上げされ結論が出ていないことを指摘し、コミュニティに対処方針の明確化を提案——コピー長の制限または過長ホスト名の拒否、および修正担当者の指定；もし既に他のコミットで解決済みであれば、コミット番号を補足すれば本票をクローズ可能。
