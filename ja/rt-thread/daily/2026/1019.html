1. カーネルとバージョン動向

1.1 カーネルバージョン番号が v5.4.0 に切り替え：バージョンマクロと Kconfig が先行、リリース物は未着地（10-17）

日付：2026-10-17 09:43（マージ時刻）　出典：PR #11875、include/rtdef.h

メンテナ Rbb666 がバージョン切り替え提案をマージ（2 ファイル +4/-3）：include/rtdef.h のバージョンマクロを 5.3.1 から 5.4.0 に変更し、2026-10-17 の変更記録を 1 条追加；src/Kconfig の RT_VER_NUM のデフォルト値を 0x50301 から 0x50400 に変更。作者は qemu-vexpress-a9 のデフォルト設定で scons –pyconfig-silent を実行し、生成される rtconfig.h の RT_VER_NUM が 0x50400 であることを確認。10-19 時点で、リポジトリの最新 tag と release は依然 v5.3.0（09-10 リリース）、ChangeLog.md のタイトルも依然 v5.3.0 であり、今回はバージョンサイクルの起点に過ぎず、5.4.0 のリリースノートとリリース物はまだ出ていないことを示す；ウィンドウ内のコミュニティ不具合票では master が v5.4.0-dev と表記されている。

1.2 Next RISC-V 大規模リファクタリングがマージ：165 ファイルで RV32/RV64 を統一、Sv32~Sv57 と AIA を一括導入（10-17）

日付：2026-10-17 09:44（マージ時間）　ソース：PR #10320、Issue #10722

約5か月にわたる RISC-V アーキテクチャ再構築（#10320）がマージされた。4 コミット、165 ファイル +15134/-2617。内容には ISA 管理インターフェース、32E/32I/64I の統合、CBOM ISA に基づくキャッシュ処理、Sv32/Sv39/Sv48/Sv57/Sv64 MMU と SVPBMT、M モードと S モードの CSR 操作の統合、SMP、APLIC/IMSIC（AIA）、CLIC、ACLINT/CLINT、INTC と PLIC、オプションの DM（OFW 経由のみ）、T-HEAD ベンダーコードの統合が含まれ、さらに qemu-virt64-riscv64 で DM を移植し、非 0 番コアからの起動をサポートした。計画表では S-mode RT-Thread、S-mode RT-Smart（APP、DM、MMU なし、DM なしを含む）および M-mode（DM、DM なし）がいずれもチェック済みとなっており、BSP の適合は引き続き推進待ちである。同日、#10722、#9571、#9567、#9566、#9521、#11226 の 6 件の RISC-V タスクチケットが集中クローズされた。

1.3 RT-Thread Smart 十三筆の提案を一括起票：syscall 分割、シグナルと MMU 修正、K230D 適合（10-18 ~ 10-19）

日付：2026-10-18 19:35 ~ 10-19 02:49（作成 / 更新）　ソース：PR #11896、PR #11897、PR #11892

メンテナの BernardXiong は 10-18 19:35 から 19:36 までの 2 分間に 13 筆の提案（#11885 ~ #11897）を連続起票し、本号の締め時点ですべて審査中である。主軸は Smart を QEMU と実ボードで動作させることにある。qemu-virt64-riscv64/aarch64 で RT_USING_SMART を有効化、riscv64 で SMP を無効化、virtio-blk 上に ext4/elm を載せ ptyfs と procfs をマウントする。libcpu/riscv では初期ページテーブルの物理オフセット換算を修正し、コアごとのページテーブルでユーザーマッピングを継承し、ユーザー態例外処理を修正するとともに、玄鉄アーキテクチャ選択と SVPBMT を追加した。lwp では syscall 実装を分割し、シグナル配送順序と ELF セグメント保護を修正し、TIOCLINUX と TIOCGWINSZ を補完した。K230D では 128MB DDR 設定と ext4 ルートファイルシステムを追加した。その他、SAL RAW socket のプロトコル検証、lwip ループバックネットワークカード、8250 earlycon のレジスタ幅、SDIO ブロックサイズ、poll の DFS ファイル操作経由化と UTIME_OMIT 修正がある。

1.4 ESP32-C6 SPI 提案が整改を経てマージ：分割転送、BSP 専有 gdma、ビット幅検証の前倒し（10-16）

日付：2026-10-16 11:31（マージ時間）　ソース：PR #11846、PR #11870

前号で審査中であった ESP32-C6 SPI 提案は、審査での整改を経てマージされた（7 ファイル +1253/-26）。DMA 無効時は IDF の 1 回 64 バイト上限に従って分割送信し、gdma.c は BSP 専有のコピーに変更して C3/C6 の共通ビルドで相互に書き換えられないようにし、ビット幅検証をバス初期化の前に前倒しした。動作面では、BSP_USING_SPI を選択した場合のみ IDF SPI master をリンクし、デフォルトイメージでは引き続き SPI を無効とする。共有 ESP ドライバは SPI モードを貫通しなくなり、実際の転送バイト数を返し、チップセレクトは SPI2_IOMUX_PIN_NUM_CS から取得し、設定が空の場合は -RT_EINVAL を返す。同期間中、C3/C6 を ESP-IDF v6.1、RISC-V ツールチェーンを GCC 15.2 に適合させる提案（#11870）は引き続き審査中である。

1.5 HPMicro BSP を hpm_sdk v1.13.0 に更新、HPM5100EVK ボードサポートを追加（10-17）

日付：2026-10-17 16:28（マージ時間）　ソース：PR #11871、packages インデックスコミット

1.6 セキュリティ監査四連発：libdl 任意書き込み、lwp シグナル範囲外、OFW スタックオーバーフロー、lwip-dhcpd リモート拒否サービス（10-17 ~ 10-19）

日付：2026-10-17 14:25 ~ 10-19 00:37（作成 / 更新）　ソース：Issue #11898、Issue #11882、Issue #11879、Issue #11878

貢献者 XueDugu が調査期間内に四件の欠陥報告を連続して起票し、いずれも導入コミット、影響バージョン範囲、QEMU 再現環境を提示している。#11898：libdl/dlmodule が ELF リロケーションのメタデータに対して境界チェックを行わず、不正な .mo がロード段階で制御された値によりカーネル空間メモリへ書き込み可能、最早 2018 年の v3.1.0 のコミットまで遡れ、ARM/RISC-V/x86 の三つのリロケーション実装が同構である。#11882：lwp の sys_sigaction がシグナル番号を検証せず、カーネルヒープの範囲外読み書きが可能（Smart、v5.0.0 以降）。#11879：OFW のデバイスツリー展開にネスト深度制限がなく、64 項目の np_stack をオーバーフローする（v5.0.2 以降）。#11878：lwip-dhcpd のリースプール枯渇後に dhcp_client_alloc が無限ループとなり、未認証のリモートから lwIP スタック全体を飽和させられる（v4.0.0 以降）。四件はいずれもオープンのまま。

1.7 DFS コード衝突提案のクローズ後に書き直して再オープン：デバイス制御コマンドをデバイスクラス別のエンコードに変更（10-17）

日付：2026-10-17 16:55 ~ 17:06（クローズ / 再オープン時間）　ソース：PR #11869、PR #11881

前号で記録した DFS 層の F_GETFL/F_SETFL と RT_DEVICE_CTRL_* のコード衝突提案（#11869）は 10-17 16:55 にクローズされ、マージされず；11 分後に作者 CXSforHPU が別途 #11881（3 ファイル +37/-20）を起票し、エンコード層面から解決する方向に変更：RT_DEVICE_CTRL_BASE(Type) =（デバイスクラス + 1）× 0x100 を導入し、上位バイトでデバイスクラス、下位バイトでクラス内連番を表し、pin 設定コマンド、シリアルハードウェア制御コマンドをそれぞれのクラスベースアドレス以降に移行させることで、汎用制御コマンドが POSIX の 3 と 4 と衝突しなくなる。新提案は審査中。

2.1 睿擎プラットフォーム V1.8.4 リリース予告：産業用ゲートウェイ仮想ネットポート、QY1503 エンコーダ、MIPI RGB666、10-21 ライブ配信解説（10-16）

日付：2026-10-16（公開日）　情報源：電子工程専輯報道

睿赛德はメディア向けに睿擎プラットフォーム V1.8.4 の予告を発表した。アップデートは産業用ゲートウェイ、ペリフェラルドライバ、ディスプレイインターフェース、デバッグツールをカバーする。EG1200 産業用ゲートウェイには仮想ネットワークポートと NFS ネットワークファイルシステムのマウントが追加され、ネットワーク経由で開発ボードのファイルシステムに直接アクセスでき、データ共有とリモートデバッグが容易になる。QY1503 ロータリーエンコーダドライバを新規追加し、モーターのクローズドループ、位置フィードバック、速度測定に対応する。RC-Pi-3506 の MIPI は RGB666 に適応し、より多くの型番のスクリーンを点灯可能にする。さらに MIPI の電源投入タイミング制御、GPIO ピンのプルアップ・プルダウン設定、amp_device デバッグコマンド（AMP コア間通信状態とデバイス割り当ての確認）を追加した。公式は 10-21 20:00 に RC-Pi-3506 上で項目ごとに実機デモを実施する予定。

2.2 コミュニティチュートリアル：HardFault から Cortex-M のクラッシュ現場を抽出（10-17）

日付：2026-10-17 17:04（公開日）　情報源：コミュニティ記事

コミュニティ作者「大目熊」が Cortex-M クラッシュ位置特定シリーズの前編を公開し、HardFault の処理方針を明快に解説した。例外エントリでは既に 8 つの主要レジスタがスタックに退避されており、エラー原因は SCB ステータスレジスタに書き込まれる。開発者は HardFault 内でこれを読み出して出力するだけで、エラー発生位置を特定できる。記事は HFSR の説明に沿ってトリガーパスを整理し、本シリーズ前編では「現場の出力」のみを解決し、コールチェーンの遡及は後編に委ねると指摘する。core dump 機構を持たない MCU ファームウェアのデバッグに直接の参考価値があり、システムレベルでのトラブルシューティング手法に関するコミュニティの内容も補完する。

3.1 RT-Thread Env v2.0.3 リリース：プラグイン体系とツールチェーン管理を中核に（10-17）

日付：2026-10-17 01:37 ~ 09:13（コミット / マージ時間）　情報源：env バージョンコミット、電子工程専輯報道

Env リポジトリは当日バージョン切り替えを完了し（env.json と info.py が v2.0.3 を指す）、WebUI 内蔵ドキュメントナビゲーション（+291/-36）をマージし、独立した HTML ドキュメントのトラッキングを許可した。PR #302 は 10-17 09:13 にマージされた。公式は同時期に紹介記事を公開し、v2.0.3 の重点はプラグインにある。機能を .epack パッケージにまとめることでインストール、アップグレード、有効化、無効化、アンインストールが可能になり、プラグインはコマンドラインコマンドの追加も WebUI ページの拡張もできる。公式はさらに epack 開発ツール（初期化、検証、ビルド、テスト）を提供する。インストール前に情報源、権限、完全性を確認する必要があり、プラグインは現在のユーザー権限で実行され、セキュリティサンドボックスではない。ツールチェーンは 2 つの入口に分かれる。SDK のダウンロードとインストール、およびローカルツールチェーン（MDK、IAR）の登録である。Windows では BSP ディレクトリを右クリックして直接 Env ターミナルを開ける。バージョンは RT-Thread 5.1.0 以降およびメイン開発ブランチを対象とする。

3.2 納芯微 NS800RT7P65D の RT-Thread UART 評価と BSP 設定化改善（10-16）

日付：2026-10-16（公開日）　情報源：電子工程専輯評価

メディアは RT-Thread ベースの NS800RT7P65 UART 評価を公開した。このチップは納芯微 NSSine シリーズのデュアル Cortex-M7 リアルタイム MCU で、ARMv7E-M ベース、倍精度 FPU、DSP 拡張、MPU を備える。記事はチップ層の UART リソースとレジスタ設定からコード層の機能テストまでを解説し、menuconfig 設定後に rtconfig.h が対応するマクロを生成し、全 UART デバイスが登録を完了することを検証し、console を順に異なるシリアルポートへマッピングしてテストした。作者は同時に、ボードレベルドライバにボーレートやストップビットなどのハードコードが存在することを指摘し、menuconfig へマッピングして BSP の堅牢性を高めることを提案し、改善提案を提出済みである。同一チップは本調査期間のコミュニティ作品「稔花」にも登場する（4.1 参照）。

3.3 全志 F101 YuzukiNeko 新 BSP 提案：M/S デュアル設定と一連の DM ドライバ（10-17）

日付：2026-10-17 12:55（作成時間）　情報源：PR #11877

コミュニティは全志 F101（Sun252i）YuzukiNeko ボードサポートを提出（134 ファイル +26189/-3）：M-mode と S-mode の設定を同時に提供し、クロック、リセット、pinctrl、DMA、SDIO、SPI、USB、オーディオ、熱管理、RTC、PWM、ADC、NVMEM、ウォッチドッグ、DVFS、G2D、JPEG などの DM ドライバを補完；表示側には Sunxi DE0/TCON0 出力バックエンドを新規追加し、RGB、LVDS、MIPI-DSI をカバーし、ST77916 QSPI パネル設定を備える；CherryUSB 側では Sunxi MUSB glue を補完。さらに電源ドメイン、DVFS、グラフィックス、UART リセットとレジスタシフト、QSPI、熱管理 workqueue、入力キャプチャ、DM USB 統合を修正。提案は審査中。

3.4 公式ツールと仕様リポジトリの更新：rtthread-skills スキルセット、smart-build DTB ビルド、移植仕様リンク修正（10-17 ~ 10-18）

日付：2026-10-17 09:39 ~ 10-18 20:34（コミット / マージ時間）　情報源：RT-Thread/rtthread-skills、RT-Thread/smart-build、移植仕様 PR #19

4. 業界応用

4.1 施設農業：K230 + NS800RT7P65D による「稔花」スマート授粉ロボット（10-17）

日付：2026-10-17 14:59（公開時間）　情報源：コミュニティ記事

コミュニティがハウス栽培トマト向けのスマート授粉ロボットを公開。ロボット本体は幻爾 K230 視覚モジュールで知覚を行い、納芯微 NS800RT7P65D をメインコントローラとし、4輪エンコーダモータシャーシ、ステッピングモータと3系統の HTS-35H バスサーボで構成するマニピュレータ、および振動モータ、送風 DC モータなどのアクチュエータを搭載；環境ノードは ESP8266 に DHT11 と SGP30 を組み合わせて温湿度、二酸化炭素を収集し、WiFi と MQTT 経由でアップロード；上位側はサーババックエンド、Web、Qt デスクトップ端末を含む。システムは振動、点触、送風の3つの授粉モード切替に対応し、K230 が花を認識するとマニピュレータの位置決め授粉をトリガーし、病害を認識すると画像をアップロードしてバックエンドで分析させる。

4.2 公衆衛生：GD32F303 + STM32F103 デュアルボードの「清道夫」スマート消毒装置（10-17 ~ 10-18）

日付：2026-10-17 16:35 ~ 10-18 21:19（コミット / 公開時間）　情報源：コミュニティ記事、Allin-JO/GD32

コミュニティが教室、廊下、公共ベンチ向けの移動式消毒装置を公開。「GD32 下位機 + ESP8266（WiFi/MQTT）+ クラウドサーバ + PC/Web マルチエンド」アーキテクチャを採用し、噴霧散布、移動制御、消毒液残量監視、映像伝送、QR コード予約を一体化し、収集、伝送、処理、制御の閉ループを形成；作者によれば原理試作機と3端ソフトウェアの連携調整を完了しており、イノベーション・起業および大学生訓練プロジェクトの基礎として位置づけている。関連リポジトリ Allin-JO/GD32 は 10-17 に2件のコミットをプッシュし、メインコントローラを STM32F103 から GD32F303 へ移行しリポジトリを整理した。

5. 総括とトレンド観察

5.1 3日間のトレンド（10-16 ~ 10-19）

  • バージョンサイクルの切り替え：v5.4.0 のバージョンマクロと Kconfig が先行して着地し、tag、release、ChangeLog は依然 v5.3.0 のまま。これは 5.4.0 がリリース済みではなく開発サイクルに入ったことを示す。
  • RISC-V リファクタリングの着地：165 ファイル、+1.5 万行の Next RISC-V がマージされ、RV32/RV64、Sv32~Sv57、AIA/CLIC と M/S 態を単一の ISA 管理インターフェースに統一し、六枚の長期タスクチケットが同日クローズされた。
  • Smart がメインラインに：13 件のバッチ提案が syscall、シグナル、MMU、rootfs、QEMU と K230D をカバーし、方向性は「起動できる」から「テスト可能、デリバリー可能」へ転換。
  • セキュリティ債務の集中露呈：四枚の欠陥チケットが libdl、lwp、ofw と lwip-dhcpd にまたがり、最も古いものは 2018 年に導入されたコードに遡れる。三枚は v5.0 以前のバージョンに影響し、一日に四枚という密度は最近の調査期間ではまれである。
  • ツールチェーンのプラグイン化と AI 協働への進化：Env 2.0.3 は .epack プラグインとツールチェーン管理を核心とし、公式 rtthread-skills は BSP、ソフトウェアパッケージと Git フローをスキルとして記述し、AI 支援開発が公式リポジトリに参入。
  • ベンダー適配の継続拡大：HPMicro は hpm_sdk 1.13.0 にアップグレードし HPM5100EVK を新規追加、全志 F101 の新 BSP 提案、納芯微 NS800RT7P65D がコミュニティ UART 評価を獲得。
  • 公式チャネルの静穏：ニュースインターフェースは第六十日まで更新停止、公式サイトのニュースページは 10-19 に読み込み失敗を返す。
