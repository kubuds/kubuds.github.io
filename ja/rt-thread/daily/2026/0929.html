1. カーネルとバージョン動向

1.1 メインラインに一夜で3件集中マージ：ESP32-C6 と CH32V003 BSP、IAR テンプレート修正（09-28）

日付：2026-09-28 22:19 ~ 22:22（北京時間、マージ時間）　出典：PR #11836、PR #11838、PR #11843

メンテナ Rbb666 が期間内の約3分間に3件のマージを完了した。其一（#11836）乐鑫 ESP32-C6-DevKitC-1 ボードサポート（9 コミット、40 ファイル、+9598/-50）が正式にメインライン入り：bsp/ESP/ESP32_C6 完全ボードプロジェクト（ビルド設定、IDF 適配層 idf_port、リンカスクリプトと証明書パッケージ）、ESP 共有ドライバと Kconfig の適配更新および CI 接続を含む；当該提案は 09-25 未明に提出され、約4日後にマージ、本件には別途 CH32V203 SConstruct の調整も併合された。其二（#11838）沁恒 CH32V003F4P6-EVT ボードサポート（5 コミット、47 ファイル、+9258）がマージ：RISC-V コア RV32EC、48MHz、16KB Flash、デフォルト UART1 で msh に入る、此前すでに 09-25 にレビュー入りしていた。其三（#11843）5 つの BSP の IAR プロジェクトテンプレートを修正：テンプレート ewp のリンク設定ファイルが元々他の開発機の絶対パスを指していたのを、統一して $PROJ_DIR$ 相対パスに変更（+7/-7、asm9260t、mm32f3270-100ask-pitaya、stm32f103-100ask-mini などのボードを含む）。

1.2 ESP32-S3-DevKitM-1 BSP 提案がレビュー入り：ソフトウェアパッケージ依存の補完が必要（09-28 ~ 09-29）

日付：2026-09-28 19:04（作成）~ 09-29 10:18（最近更新）　出典：PR #11844、PR #11816

同一貢献者（cms19859230182-lang）は調査期間内に、乐鑫 ESP32-S3-DevKitM-1 向けの全新 BSP 提案（#11844）をコミットした。6 コミット、44 ファイル、+6862/-31 で、bsp/ESP/ESP32_S3 と libcpu/xtensa/esp32s3 を新規追加し、シングルコアイメージ、UART0（GPIO43/44）から msh に入り、Flash 8MB DIO 80MHz に対応する。提案には、このボードが Xtensa LX7 アーキテクチャであり RISC-V ではないため、ESP32-C3 のツールチェーンと割り込み接続方法を流用できないことが明記され、付属ツールチェーンは xtensa-esp32s3-elf GCC 12.2.0 である。レビューでは、メンテナが依然としてコンパイルとソフトウェアパッケージ依存の問題があることを指摘し（09-28 22:18）、投稿者は 09-29 午前に回答して修正に着手した。また、ESP32-C3 の Windows ビルド修正提案（#11816、09-21 コミット）は 09-29 午前に投稿者がフォローアップコメントし、依然としてレビュー中である。

1.3 RT-Thread Env ツールが Unicode と不正パス処理を修正（09-28）

日付：2026-09-28 21:07 ~ 21:10（コミットとマージ時間）　情報源：RT-Thread/env PR #298

env（Windows 側開発ツール）は調査期間内に修正 #298 をマージした。ASCII のみを許可する BSP パス検証を削除し、Env コマンドが中国語などの Unicode 作業ディレクトリ下で正常に使用できるようにした。同時に、エクスプローラーの右クリックメニューがディスクルートディレクトリ下でパスを処理する問題を修正し、選択したパスが存在しない場合は起動を直接終了するようにし、回帰テスト（Unicode パスのケースを含む）を追加した。プロジェクト創始者 Bernard Xiong がコミットしてマージし、env リポジトリにとって 09-16 以来の初の更新である。

日付：2026-09-29（確認時間）　情報源：RT-Thread 公式ニュースインターフェース

3. エコシステムとメーカー適配

3.1 GD32 下流リポジトリがドライバ更新をマージ：USART/I2C/SPI の GPIO 初期化を新バージョンに切り替え（09-28）

日付：2026-09-28 16:20（マージ時間）　情報源：GD32-MCU-IOT/gd32_rt-thread PR #71

兆易創新が保守する RT-Thread 下流リポジトリは、調査期間内にドライバ更新をマージした（#71、コミット説明は USART、I2C、SPI ドライバの GPIO 初期化を新バージョンに更新）：drv_hard_i2c、drv_spi、drv_usart の 6 ファイルに関わり、以前のバージョンと比較して純減 797 行（旧版実装の回収が主で、ドライバファイルは保持、実装は収束）。当該リポジトリのチップ適応とドライバ保守のペースは今月も継続（09-18 に F20x I2C DMA 更新をマージ済み）。

3.2 楽鑫 esp-idf ソフトウェアパッケージ C6 ソース提案が提出者によりクローズ（09-29）

日付：2026-09-29 08:28（クローズ時間）　情報源：RT-Thread-packages/esp-idf PR #17

esp-idf ソフトウェアパッケージに ESP32-C6 scons コンパイルソースを補うための提案（#17、09-25 提出）は、09-29 午前に提出者自身によりクローズされ、未マージ；当該ソフトウェアパッケージリポジトリは 2023 年 11 月以来、新規プッシュがない。メインライン側の ESP32-C6 ボード級サポートはマージ済み（1.1 参照）、ソフトウェアパッケージ側の付随形態についてはこれ以上の公開情報はない。

5. まとめと趨勢観察

5.1 直近一日の趨勢（09-28 ~ 09-29）

  • 夜間の集中マージが常態化：3 件のマージが 22:19 ~ 22:22 の約 3 分間に集中して完了、RISC-V ボード級ライン（ESP32-C6、CH32V003）と工程テンプレート修正が一括で落地；ESP32-C6 提案は提出からマージまで約 4 日。
  • ESP32 ラインは単一貢献者により多点的に推進：同一貢献者が C6（マージ済み）、S3（新規提案レビュー中）、C3（旧提案フォロー）とソフトウェアパッケージ側（提案クローズ）を横断し、楽鑫系チップのボード級エコシステムにおける存在感は引き続き上昇。
  • ベンダー側の保守と運営が並行：GD32 下流倉ドライバ更新が落地；Gino Pi メインライン BSP 提案（#11829）は調査期間内に新規進展なく、発売稿が再度更新（実質的新規追加なし）——兆易創新ラインは工程と運営が並行する安定期に入る。
  • ツールチェーンとコンテンツ側：Env ツールが Unicode パスを修正（創設者が直接コミット）；公式公众号が「虚実結合物流工場」教学プラットフォームを推進、人材育成テーマが継続。
  • 公式ニュースインターフェースが満 40 日停止：対外情報配信は引き続き公众号、フォーラムと GitHub に依存。

5.2 局限性と重複排除説明

  • 重複排除：Gino Pi 発売稿が 09-28 14:56 に再度更新（内容は 09-22 に収録済みのバージョンと一致）、メインライン提案 #11829 は調査期間内に更新なし、いずれも重複報道せず；「端側 AI 視覚実践」は 9 月上旬場次の旧帖更新であり、収録せず；AWTK リポジトリは 09-28 夜間にドキュメント類コミットであり、収録せず。
