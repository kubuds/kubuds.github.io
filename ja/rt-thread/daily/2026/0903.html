1. カーネルとリリース動向

1.1 メインリポジトリに [lwp] をマージ：terminal/ をグローバル CPPPATH から除外

日付：2026-09-03（09:20 北京時間にマージ）　出典：PR #11776（マージコミット 54e5164、TTLLDD がコミット）

components/lwp/SConscript は以前 ./terminal/ ディレクトリをグローバル CPPPATH に追加していたが、本コミットでこれを削除する。リポジトリ全体の検証によると、terminal サブシステムのヘッダファイル（terminal.h、tty_config.h、bsd_porting.h など）の非修飾 include はすべて components/lwp/terminal/ 内部のソースファイルからのものであり、コンパイラの引用符形式検索で満たせるため、内部ディレクトリをグローバルインクルードパスに漏らす必要はない。これは 2025-11 の課題 #10980「CPPPATH の使用を規範化する」の取り決めの最小化模範実装であり、コンポーネントが内部ディレクトリをグローバル include パスに漏らさなくなる——ビルドシステム/include 衛生方向への小さな前進である。ウィンドウ内でメインリポジトリ唯一のマージであり、平日早朝のマージリズムは最近と一致しており、大きな機能はない。

1.2 進行中：コミュニティ開発者が CAN フレームワークの構造的リファクタリング PR を提出

日付：2026-09-02（13:21 北京時間に作成、open、CI clean、非 draft）　出典：PR #11779

wdfk-prog（すなわち昨日公式インデックスに転正された CANopenNode 移植パッケージの作者）が refactor[CAN] PR を提出：Generic CAN Framework および STM32 bxCAN バックエンドに対して構造的リファクタリングを行う（2 commits、8 ファイル、+2902/-1308）。フレームワークの責務境界を再明確化——Generic CAN はハードウェアリソース管理、同期、ownership とライフサイクルを担当し、送信キャッシュ/再試行/スケジューリングとプロトコル QoS ポリシーは上位プロトコルスタックまたはアプリケーションが自行決定する。方案の出所は二つの手がかり：8-26 特性リクエスト #11759（CANopen CiA 305 LSS Activate Bit Timing のランタイムボーレート切替には TX Full Flush と Hardware Abort 能力が必要、すでにクローズ）と 8-28 フレームワークリファクタリング討論 #11767（統一 TX Engine、Mailbox Ownership と Lifecycle、討論クローズ後 3 分で本 PR に転換）。両課題はすでにウィンドウ内でクローズされ本 PR に集約されており、ラベルには BSP: STM32 と component: drivers/can が含まれる。本 PR は CANopenNode 移植で露呈した低レベル能力のギャップをフレームワーク層のリファクタリング提案に格上げしたもので、現在メンテナのレビュー待ちであり、マージされれば Generic CAN Framework 近年最大の責務境界調整となる。

2. 公式・コミュニティイベント

2.1 公式ニュース API は連続14日間新規なし、elexcon 2026 まであと6日

日付：2026-09-03　情報源：RT-Thread 公式ニュース API

公式ニュース API（rt_org カテゴリ）は依然として 5 件の旧エントリで、最新も引き続き 2026-06-17 のアブダビ投資フォーラム報道であり、14 日連続で新規追加なし。gnews の複数グループによる追加調査（RT-Thread when:3d 中英、RT-Thread 睿赛德 when:3d、睿擎派 OR 睿擎 when:3d）：英語は依然として Rotten Tomatoes の分割語ノイズと無関係なテック投稿、中国語クエリはすべて空。次の対外ウィンドウは 9 月 9-11 日の深圳 elexcon 2026（睿賽德が出展、8-30 予告は既に収録済み）で、カウントダウン 6 日、会前静默期の継続は予想されるペース。

3. エコシステムとベンダー対応

3.1 canopennode-rtt 特性ブランチが継続的に活発、メインラインのウィンドウ内に新規コミットなし

日付：2026-09-02（22:30 北京時間リポジトリ push）　情報源：github.com/wdfk-prog/canopennode-rtt

topic:rt-thread ウィンドウ内 push リポジトリの一つ。デフォルトブランチ master の最新コミットは依然として 09-02 11:02 北京「co_rtt_mainline_deadline_min を extern に調整しメインラインスケジューリングに対応」（昨日既に収録済み）で、ウィンドウ内の push は A04 と ds402 の 2 つの特性ブランチに位置する——CANopen の異なる profile（DS402 モーション制御、A04 アプリケーション）ブランチの継続的進化であり、メインラインに新規内容はない。同日、当該リポジトリの作者は RT-Thread メインリポジトリで CAN フレームワーク再構築 PR を提出（1.2 参照）、「アプリケーション層（CANopenNode ソフトウェアパッケージ）→ フレームワーク層（Generic CAN 再構築）」の双方向推進により、CAN エコシステムが現在コミュニティで最も活発な推進メインラインとなっている。

4. 業界応用

4.1 エコシステム参考：コンシューマー向けドローン H120D ファームウェアリバース文書が更新

日付：2026-09-02（13:34 北京時間 push）　情報源：H4ck3rTR/h120d-protocol

topic:rt-thread エコシステムリポジトリ h120d-protocol がウィンドウ内で更新（README 改訂、4 月の Hackaday 投稿内容を整理）。本プロジェクトはコンシューマー向けドローン Holy Stone H120D の WiFi 通信プロトコルとそのファームウェア内の RT-Thread 内部実装をリバース文書化し、制御ツールを提供、コードは主に C++。ウィンドウ内にコードの実質的更新はなく、ドキュメントメンテナンスに属する；プロジェクトの存在自体が RT-Thread のコンシューマー向けドローン�ファームウェアへの展開を側面から裏付ける（リバースプロジェクトの自称であり、公式に検証されていない）、低活発エコシステム参考として収録。

5. 総括とトレンド観察

  • カーネル側：ウィンドウ内の単一マージ——[lwp] terminal/ をグローバル CPPPATH から除外（09-03 09:20）、ビルド/include 衛生規範（議題 #10980）の落地ペースを継続、大型特性のマージなし。
  • 進行中：CAN フレームワーク構造的再構築 PR（#11779、+2902/-1308）がコミュニティ開発者 wdfk-prog により提出、CI clean、非 draft、メンテナーレビュー待ち；8 月末の CAN 議論（#11767）と特性リクエスト（#11759）は既にクローズされ本 PR に集約、再構築方向はコミュニティ側のコンセンサスを獲得。
  • 公式側：公式ニュース API は 14 日連続で新規追加なし；次の対外ウィンドウは 9 月 9-11 日の深圳 elexcon 2026、カウントダウン 6 日。
  • エコシステム側：CAN 二路線推進（アプリケーション層 CANopenNode 転正後の DS402 等 profile ブランチ拡張 + フレームワーク層再構築提案）は現在最も明確なコミュニティメインライン；ソフトウェアパッケージインデックスはウィンドウ内に新規マージなし、テンセント IoT SDK 設定 PR #2034 は依然 open。
  • 直近 3 日のトレンド（09-01 ~ 09-03）：カーネル堅牢性 4 PR バッチ、CANopenNode イベント駆動スケジューリング、RTC utest と復旦微 FM33/CANopenNode の 2 ソフトウェアパッケージ インデックス入り（09-01）→ テンセント IoT SDK 設定 PR、CAN フレームワーク再構築 PR 提出、h120d ドキュメント更新（09-02）→ lwp CPPPATH 衛生マージ、CAN 再構築 PR レビュー待ち、公式静默第 14 日（09-03）。推進メインラインは「ソフトウェアパッケージインデックス拡容」から「CAN エコシステム深度推進 + ビルドシステム規範化」へ切り替わり。
