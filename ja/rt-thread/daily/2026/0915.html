1. カーネルとバージョン動向

1.1 RISC-V 遅延 FP/RVV コンテキストスイッチ提案がカーネルメンテナから前向きな回答を獲得（#11786）（09-15）

日付：2026-09-07 提案コミット、2026-09-15 10:23 メンテナ返信（北京時間）　出所：Issue #11786

本議題は OSPP 2026 の選題として提出され、既存の RISC-V 移植層に二つの構造的欠陥があると指摘している。一つは、コンテキストスイッチのたびに無条件で完全な FPU 状態を保存・復元しており、スレッドが浮動小数点ユニットを一度も使用していなくても実行されること。もう一つは、ベクトル拡張 RVV をまったくサポートしておらず、ベクトルレジスタがスレッドコンテキストに含まれていないため、ベクトル命令を使用するスレッドの状態がコンテキストスイッチによって暗黙的に破壊されること。この二点は既存の議題 #10722 にすでに記録されている。提案は拡張状態を遅延保存・復元に変更する、すなわち実際に使用される場合にのみ状態を書き出すことを提案している。メンテナの Rbb666 は期間内に返信し、これは優れたパフォーマンス最適化提案であると認め、PR の提出を歓迎すると述べた。本議題のラベルは enhancement、Kernel、Arch: RISC-V であり、期間内で唯一のアーキテクチャレベルの方向性表明である。

1.2 レビューキュー観察（一）：STM32N657 Nucleo BSP が1日で4回強制プッシュし CI を修正（#11799）（09-14）

日付：2026-09-14 13:21 / 13:24 / 15:06 / 16:44（北京時間）　出所：PR #11799

STMicroelectronics STM32N657 シリーズの stm32n657-st-nucleo BSP（84ファイル、約15340行追加）は、期間内に作者によって連続4回強制プッシュされた（09-14 13:21、13:24、15:06、16:44）。これはメンテナの「CI 問題を修正する必要がある」というレビュー意見に直接対応したものである。本 PR は 09-11 にレビュー提出され、レビュアーには Liang1795、hamburger-os、wdfk-prog が指名されている。サードパーティのメモリ比較ツールが発行したレポートでは、本ボードはまだ比較対象に含まれていない。1日での高頻度再プッシュは、CI とレビュー意見のクローズドループが進行中であり、まだマージ段階に入っていないことを示している。

1.3 レビューキュー観察（二）：国民技術 N32H 三シリーズドライバ拡張がレビューを受けて再プッシュ（#11800）（09-14）

日付：2026-09-14 16:48（北京時間、強制プッシュ）　出所：PR #11800

同 PR は bsp/n32/n32hxxx 配下で N32H47x_48x、N32H49x、N32H7xx の三シリーズドライバを拡張し、n32h487zgl7-evb、n32h497zgl7-evb、n32h760zil7-stb の三枚のボードをカバーする。共用ドライバ層に ADC、DAC、I2C、SPI 設定ヘッダファイルを新規追加し、さらに drv_adc、drv_dac、drv_eth、drv_gpio、drv_hard_i2c、drv_nand、drv_qspi、drv_sdram、drv_spi、drv_usart、drv_wdt など 29 ファイルを拡張した。二枚の evb にはさらに FEMC タイミングテーブル、ETH PHY リセットと CherryUSB 設定を追加した。調査期間内に作者は再度強制プッシュを行い、レビュースレッドで自動レビューが提起した問題に一つずつ回答した。これには I2C DMA タイムアウト処理を独立した変更として記述すること、N32H7xx の転送中止ロジックを拡張することなどを含む。国産 MCU 原廠ドライバの補完は依然是としてレビューキューの主要な構成要素である。

1.4 レビューキュー観察（三）：lwip 2.2.1 サポートブランチが再度再プッシュ、サードパーティメモリ比較に変化なし（#11797）（09-15）

日付：2026-09-15 11:19（北京時間、強制プッシュ）　情報源：PR #11797

同 PR は #11588 を修正するために lwip 2.2.1 サポートを導入したもので、検証用 BSP は bsp/nxp/imx/imxrt/imxrt1180-nxp-evk/m7 であり、BSP_USING_ETH、RT_USING_SAL、RT_USING_NETDEV、RT_USING_LWIP を有効化している。調査期間内に作者は再度強制プッシュを行った（commit 04a4e19b）。同期間にサードパーティメモリ比較ツール（MemBrowse）が同 PR に対してレポートを出具し、メモリ占用の変化を導入していないと判定した。レビューラベルは components、レビュー担当は Maihuanyi。プロトコルスタックのバージョンアップグレードは工業・ゲートウェイシーンで常用される経路であり、本期はレビュー反復期間中にあり、まだメインラインに合入されていない。

3. エコシステムとベンダー対応

3.1 RT-Thread が兆易創新と共同で Gino Pi 開発ボードを正式発売、初回割引80元（09-15）

日付：2026-09-15 08:00（北京時間、集約時間）　情報源：電子工程専輯（集約）

RT-Thread 睿賽德は兆易創新と共同で Gino Pi 開発ボードを正式に発売し、初回割引は80元、同時期に Gino Pi 新製品の解説を発表した。このボードは以前 09-11 に RT-Thread Studio SDK インデックスに登録済み（GD32H77D-Gino BSP v1.0.0、パッケージサイズ 138 MB）であり、本期は「ダウンロード可能な BSP」から「公開販売」へと進んだ。これは兆易創新と睿賽德の戦略的提携（GD32 全シリーズをカバーし、GD32F5、GD32VW553、GD32H7 の3製品ラインを重点的に深化）が開発ボードレベルで具現化した初のハードウェアである。原文ページはネットワークアクセスが制限されており、価格と割引幅は集約要約を基準とし、公式ページによる二次確認は得られていない。

3.2 Gino Pi のハードウェア仕様と技術的詳細：Studio BSP SDK リポジトリの公開資料（09-10）

日付：2026-09-10（SDK 最終コミット）　情報源：sdk-bsp-gd32h77d-realthread-ginopi

Studio BSP SDK リポジトリからボードの実際の形態が確認できる：コアは GD32H77DIW（Arm Cortex-M7、最高 600 MHz）、25 MHz 水晶振動子、コンソール UART1（PA2/PA3、115200-8-N-1）、動作インジケータ PC4 は500ミリ秒ごとにトグルする。外部拡張 32 MiB SDRAM（0xC0000000 にマッピング）とオンボード 8 MiB GD25Q64E QSPI Flash；ディスプレイは 720×720 MIPI DSI スクリーン（FL7707N、RGB565）、タッチは GT911 が I2C3 経由；カメラは OV7670（QVGA RGB565、DCI プラス DMA）；イーサネットは ENET1 RMII；Wi-Fi は GD32VW553 AT モジュールが UART4 経由で提供；ダウンロードとデバッグは SWD（Studio 側 DAP-Link / PyOCD、MDK 側 CMSIS-DAP）。SDK は RT-Thread 5.3.0 をベースとし、16 のペリフェラルと応用例プロジェクトを含み、UART、I2C、SPI、QSPI Flash、SD カード、CAN、PWM、RTC、SDRAM、USB デバイスとホスト、LVGL ディスプレイとタッチ、Wi-Fi、イーサネット、カメラ、MQTT および出荷時総合デモをカバーし、同時に Studio と MDK5 の2種類のプロジェクトを提供する。全体として H7 級のグラフィカルインタラクションとネットワーキング評価プラットフォームに位置づけられ、明らかにヒューマンマシンインターフェースとマルチメディアアプリケーションに傾斜している。

3.3 ソフトウェアパッケージインデックス：STM32N657xx FSBL インデックスコミットがメインインデックスにマージ（09-14）

日付：2026-09-14 12:35（北京時間、マージ時間；作者コミット日 09-10）　情報源：commit d9b53de7

前回審査提出された hal_sdk ディレクトリの STM32N657xx FSBL ソフトウェアパッケージインデックス（対応するソフトウェアパッケージインデックスリポジトリ PR #2041）は調査期間内にマージされ、コミットは peripherals/hal-sdk/stm32/stm32n657xx_fsbl/Kconfig と package.json の2ファイルを追加し、同時に stm32 ディレクトリの Kconfig を更新して新エントリをマウントした。このソフトウェアパッケージはメインリポジトリで審査提出中の stm32n657-st-nucleo BSP と配套し、STM32N6 シリーズの FSBL（初段セキュアブートローダ）环節のリソースがソフトウェアパッケージ側で先行して整備されたことを意味し、開発者はパッケージマネージャから直接取得できる。ソフトウェアパッケージインデックスとメインリポジトリ BSP 審査提出の前後配合は、最近の STM32 新シリーズ導入の定番リズムである。

5. 総括とトレンド観察

5.1 直近三日間のトレンド（09-12 ~ 09-15）

  • 製品側のクローズドループ：Gino Pi は SDK インデックス登録（09-11）から正式発売（09-15）へと至り、今週最も実装意義のある動きである。GD32H7 プラットフォームは睿賽徳にとって高性能グラフィックインタラクションボードにおける第二の製品ラインとなった。これまでこの位置は STM32H7 プラットフォームの ART-Pi シリーズが担っており、チップサプライチェーンの国産化選択がより明確になった。
  • カーネル側はアーキテクチャ級の議題へ転換：RISC-V の遅延 FP/RVV コンテキストスイッチ提案がメンテナから前向きな反応を得ており、玄鉄 C908 の QEMU rt-smart サポートが継続的に推進されていることも重なり、RISC-V 方向のメインラインカーネルへの投入可視度が向上している。この種の変更はリアルタイム性能とベクターシーンの可用性に直接影響し、後続の PR を追跡する価値がある。
  • レビュー側は依然として BSP とドライバ：STM32N657 Nucleo BSP と国民技術 N32H 三シリーズのドライバ拡張がレビューキューの主体を構成しており、両チップメーカーとエコシステム開発者が密集して再プッシュし、逐条レビューに応答しており、マージペースは CI とレビュー意見のクローズドループ速度に依存する。
  • エコシステム側は着実に収束：STM32N657xx FSBL ソフトウェアパッケージインデックスがマージされ、メインリポジトリ BSP の審査提出と配套を形成し、STM32N6 シリーズがパッケージマネージャで先行利用可能となった。
  • 伝播側のチャネル移行：公式ニュースインターフェースは 06-17 以降更新停止が既に二十六日に達し、製品と活動情報は集中的に公衆号チャネルから発信されており、外部検索はアグリゲーションソースと GitHub 状態を組み合わせて裏付けを取る必要があり、公式インターフェースだけでは重大な製品動きを見落とすことになる。
