1. カーネルとバージョン動向

1.1 メインラインに保守性修正 2 件をマージ：GD32VW553H-EVAL ビルドクリーンアップと ipc ファイル整理（09-26 ~ 09-27）

日付：2026-09-26 19:58 / 09-27 12:18（北京時間、マージ時間）　出典：PR #11837、PR #11832、マージコミット b40aeb146、マージコミット 05badce95

メインラインは期間内に小規模な修正 2 件をマージした。其一（#11837）は GD32VW553H-EVAL BSP の CI クリーンアップ段階の失敗を修正：riscv-none タスクがビルド・パッケージング成功後の scons -c クリーンアップ段階で終了——根本原因は SConstruct が登録したソフトウェアパッケージ事前チェック（bsp_pkg_check）がクリーンモードでも無条件に実行され、クリーンアップ時にはソフトウェアパッケージが既に削除されているか取得されていない可能性があったこと；修正はこのチェックを clean モードで直接ショートサーキットさせるもの（1 ファイル、+3/-0）で、通常ビルドのチェックロジックは変更されていない。この提案は GitHub Copilot コーディングエージェント（copilot-swe-agent）により提出され、エージェントセッションはメンテナがトリガーし、起案後約 3 分で修正が完了、09-26 19:58 に Rbb666 によりマージされた。其二（#11832）は components/drivers/ipc/SConscript 内の冗長な __RT_IPC_SOURCE__ マクロ定義を削除（1 ファイル、+1/-1）し、09-24 レビューキューの消化に属し、09-27 12:18 にマージされた。

1.2 レビューキューに堅牢性修正 2 件を追加：STM32 リンカスクリプトのスタックアライメントと devtmpfs パス境界外アクセス（09-27）

日付：2026-09-27 20:57 ~ 21:11（北京時間、作成時間）　出典：PR #11841、PR #11842

レビュー・キューに期間内で堅牢性修正が2件追加された。その1（#11841）は STM32 系すべてのリンカスクリプトのスタック・アラインメントを修正する。.stack セクションの ALIGN(4) を ALIGN(8) に変更し、ARM AAPCS が要求する公開関数境界でのスタックポインタの 8 バイト・アラインメントに適合させる。これは 2023-05 に報告された旧欠陥 #7527（スタックが 4 バイト・アラインメントのため可変引数の double 引数受け渡しが誤る）に対応する。変更は 12 のテンプレートと 98 ボード、計 110 のリンカスクリプトに及ぶ（+220/-220）。各ボードのメモリ配置には手を付けていない。その2（#11842）は devfs のスタックバッファ・オーバーフローを修正する。devtmpfs.c の _path_separate() と _get_subdir() がバッファ長の引数を受け取っておらず、単一のパス構成要素が 255 バイトを超えると境界を越える（最長で約 3.8KB の越境。書き込み内容と長さは呼び出し側が制御し、戻りアドレスを上書き可能）。修正により devfs と tmpfs の既存検証と整合させる（越境時は -ENAMETOOLONG を返し、1 ファイル +48/-8）。コミットの署名プレフィックスは [HUST CSE]。いずれも現在レビュー中である。

1.3 FinSH パス補完のヒープオーバーフロー欠陥報告：提出者が修正を引き受け予定（09-26）

日付：2026-09-26 03:55（北京時間、作成時刻）　情報源：Issue #11839

コミュニティが期間内に FinSH コンポーネントの高危険度欠陥報告を提出した。msh でパス自動補完（Tab キー）をトリガーすると、msh_auto_complete_path 関連のロジックが現在の作業ディレクトリとユーザー入力を連結する際に厳密な境界チェックを行わず、超長または深くネストしたパスによりヒープバッファの越境書き込み（CWE-122）が発生しうる。影響は v5.3.0 および現在のメインライン、STM32F407-ATK などのボード。イシューには欠陥の説明とラベル（bug、in progress など）が付属し、提出者 Acen28 が当日にイシューを引き受け、自ら修正を提出する予定である。devtmpfs の越境（1.2 参照）に続き、コミュニティの監査によって進展するメモリ安全性の問題の手がかりとなる。

2.2 フォーラム教程「MCU リンカスクリプト”アップグレード”」：孤児 Section とアラインメント処理（09-28）

日付：2026-09-28 08:17（公開時刻、11:03 更新）　情報源：フォーラム記事 54cb40d33610387a、B 站付属動画

コミュニティ作者「大目熊」の MCU 低レベルシリーズ更新（前編『MCU GNUリンクスクリプト』09-22 収録済み）：今回はオーファン Section とアラインメント問題の高度な処理。要点：-Wl,--warn-orphan でリンカに明示的に配置されていない section を列挙させる；SHF_ALLOC フラグにより section を実行時に必要なもの（.text/.rodata/.data/.bss、メモリ領域の割り当てが必要）と不要なもの（.debug_*、.comment、.ARM.attributes、シンボルテーブルなど、明示的に列挙するが割り当てなし）の2種類に分類し個別に配置；.ARM.exidx/.ARM.extab は ALLOC クラスに属し配置と開始・終了シンボルのエクスポートが必要；最後に4バイトアラインメントで締めくくり、リンク警告がすべて解消され、map ファイルとスクリプト記述が一致することを検証。B站の配套動画付き、コミュニティチュートリアル系コンテンツ。

3. エコシステムとベンダー適配

3.1 沁恒 CH32V003F4P6-EVT ボードサポート提案がレビュー入り（09-25）

日付：2026-09-25 21:11（北京時間、作成時間；09-27 に更新あり）　情報源：PR #11838

貢献者 cms19859230182-lang（以前の CH32V203 BSP と ESP32-C6 提案の作者）が沁恒 CH32V003F4P6-EVT 開発ボードの BSP 提案を提出。CH32V003F4P6 は RISC-V コア、主周波数 48MHz、16KB Flash、2KB SRAM、TSSOP20 パッケージ；デフォルトイメージでは UART1 のみ有効（TX PD5 / RX PD6、115200 で msh に入る）、デバッグはシングルワイヤ SWDIO（PD1）経由で WCH-LinkE を外付け。提出者は実測済み：WCH RISC-V GCC 8.2.0（-march=rv32ec -mabi=ilp32e）でビルド、イメージ 15680 バイト（16KB Flash に収まる）、書き込み後シリアル出力で RT-Thread バナーと msh プロンプトを確認。提案は計5コミット、47ファイル（+9258/-0）、現在レビュー中。

3.2 CANopen エコシステムの2リポジトリが MkDocs ドキュメントサイトを公開（09-28）

日付：2026-09-28 08:45 ~ 09:09（プッシュ時間）　情報源：canopennode-rtt、lely-canopen-rtt

コミュニティ貢献者 wdfk-prog（RT-Thread ソフトウェアパッケージインデックスで canopennode パッケージを 09-24 に v1.2.0 としてマージしたコミッタ）が、調査期間内に2つの CANopen 統合リポジトリ向けにドキュメントサイトを公開：canopennode-rtt（CANopenNode 統合、マルチデバイスノードの論理デバイスモードをサポート）と lely-canopen-rtt（Lely CANopen 統合、単一オーナーの EV/IO2 ランタイムと静的オブジェクトディクショナリ、オプションのマスタサービス）がいずれも MkDocs マニュアルと Doxygen API ドキュメントをプッシュ；lely リポジトリには PR ドキュメント検証 CI も追加。両パッケージは以前より RT-Thread フォーラムに紹介スレッドあり（lely マスタ用法の長文 09-11 収録済み）。産業通信方向のソフトウェアパッケージ構築が継続的に投入されている。

3.3 AWTK のオープンソースライセンスが Apache 2.0 に切り替え（09-26）

日付：2026-09-26 08:50（コミット時間）　情報源：zlgopen/awtk ライセンス変更コミット

汎用組み込み GUI ツールチェーン AWTK（zlgopen/awtk、3.3k stars）が調査期間内にライセンスを LGPL-2.1 から Apache License 2.0 へ全面的に切り替え（LICENSE ファイル +201/-504）、プロジェクト主要作者 lixianjing がコミット。AWTK およびその RT-Thread ソフトウェアパッケージ（awtk など）は長らく RT-Thread 上の GUI アプリケーション開発に貢献しており、ライセンスの緩和は商用統合に有利。エコシステム参考系の情報（RT-Thread 専向ではない）。

4. 業界応用

4.1 Luckfox RV1103 シングルチップドローンプロトタイプ：RISC-V コアで RT-Thread フライトコントローラを実行（09-27）

日付：2026-09-27 17:25 ~ 20:04（作成・プッシュ時間）　情報源：luckfox-rv1103-drone

開発者 nguyencanhanh は単一チップ四旋翼ドローンのプロトタイプを公開した。Rockchip RV1103（Luckfox Pico Mini B）をコアとし、Cortex-A7 は Linux を実行してカメラ、NPU 認識、Wi-Fi、GPS、リモコン受信を担当し、オンチップ RISC-V MCU コア（HPMCU）は RT-Thread を実行して 1kHz のフライト制御ループを実行する。プロジェクトの目標は実測データで「単一チップアーキテクチャで直接飛行できるか」に答えることであり、代替案は独立したフライトコントローラを外付けする方式である。09-27 時点：まだ実機飛行はしていないが、Linux と MCU は並行稼働済み、1kHz ループは実測済み、フライト制御ソフトウェアはシミュレータで完全に動作し 3D 操縦ビューに対応している。自社開発の LFX_FC_R1 フライトコントローラボード（46×46mm）は配線が完了している。プロジェクトは MIT + CERN-OHL-P ライセンスでオープンソース化されており、コミュニティの個人プロトタイプに属する。

5. 総括とトレンド観察

5.1 直近三日間のトレンド（09-25 ~ 09-28）

  • RISC-V の手がかりがボードレベル、CI、アプリケーション層を貫く：GD32VW553H-EVAL（GD32V シリーズ RISC-V）の CI クリーンアップ修正がメインラインにマージされ、沁恒 CH32V003F4P6-EVT（RV32EC）BSP 提案がレビュー入りし、さらにコミュニティでは RT-Thread を RV1103 オンチップ RISC-V コア上で動作させフライト制御を行うプロトタイプもある——ビルドチェーンからボードサポート、そしてアプリケーションプロトタイプまで、RISC-V の姿が継続的に現れている。
  • メモリと ABI の堅牢性修正が集中的に推進：STM32 リンカスクリプトのスタックアライメント（110 ファイル、三年越しの旧案件 #7527 に相当）、devtmpfs パスの範囲外アクセス、FinSH パス補完のヒープオーバーフローの三件の問題が同一調査期間に出現。09-22 提出の七件のハードニングシリーズのうち六件（#11820 ~ #11825）が 09-26 に集中的にレビュー待ちへ移行し、セキュリティ向けのクリーンアップがレビュー対象の主体となっている。
