1. カーネルとバージョン動向

メインリポジトリは期間内に新規コミットとマージなし：master の最新コミットは依然として 10-12 午前の Eclipse プロジェクト生成修正（#11787）で、その後約 45 時間マージ動作なし。レビューと協業側は活発を維持：5 件の審査中提案と 2 件の旧欠陥チケットが期間内にいずれも更新され、コミュニティ検証活動は RISC-V リファクタリングとメモリ安全性の方向に集中した。

1.1 Next RISC-V 大規模リファクタリング提案コミュニティ実測推進：QEMU 設定ガイドの明確化、ESP32-C3 実機パッチ検証（10-13）

日付：2026-10-13 10:54 ~ 23:52（コメントとテスト時間）　出典：PR #10320

RISC-V 大規模リファクタリング提案（#10320）は期間内に 4 ラウンドのコミュニティインタラクションを完了：第一に、コントリビューターが QEMU 5 グループの設定実測レポートを提出、うち「S-Mode デバイスモデル無効」の組み合わせは共通起動とマルチコアスケジューリングシンボルを欠くためリンク失敗；第二に、メンテナーがプラットフォーム適配の方針を提示——デバイスモデルと非デバイスモデルの二者択一（qemu-virt64-riscv は前者、d1/d1s と smartl/e907 は後者）、テスターはこれに基づきテストケースの割り当てを調整；第三に、同日夕方に当該コントリビューターが ESP32-C3 実機で 2 枚の付随パッチ（bsp/ESP を新版共通 RISC-V コードパスへ切替）を検証し、C3 と C6 はいずれもコンパイル通過、警告ゼロと報告。提案はオープン維持。

1.2 ヒープメモリ ASan 提案追加コミット：libc アクセスチェックと境界ケース（10-13）

日付：2026-10-13 15:25（コミット時間）　出典：PR #11772

ヒープメモリランタイム AddressSanitizer 提案（#11772、8 月末開設）は期間内に追加コミット：既存のヒープインストルメンテーションランタイムと QEMU CI カバレッジを基盤に、libc メモリアクセスのチェックを拡張し境界ケースを補完。本件は GCC kernel-address によるメモリアクセスインストルメンテーションに基づき、ランタイムでヒープバッファオーバーランと解放後使用を検出可能とし、FinSH 対話コマンドによる診断情報の参照を提供。提案はオープン維持、レビュー待ち。

1.3 lwip/WLAN 制御提案拡張コミット：DNS、DHCP、バッファ、WLAN ライフサイクルの 4 グループ更新（10-13）

日付：2026-10-13 14:27 ~ 16:08（コミット時間）　出典：PR #11815

lwip セグメントマクロ制御提案（#11815）は期間内にマクロ制御テーマから四組のコミットへ拡張され、二度の強制プッシュが行われた。第一に、STA モードでの切断時に DNS 設定をクリアする。第二に、DHCP 起動ロジックを最適化する。第三に、lwip バッファオプションを設定し PBUF テール空間を保持する。第四に、WLAN AP ライフサイクルと直収パス処理を同期させる。提案の対象範囲はコンパイルマクロの整理からネットワークスタックの動作修正へと拡大し、オープン状態を維持している。

1.4 ESP32-S3 BSP 提案が自動レビュー是正を完了、人手による再レビューを依頼（10-13）

日付：2026-10-13 12:02 ~ 12:42（コメント時間）　情報源：PR #11844

ESP32-S3 ボードサポート提案（#11844）は期間内に自動レビューの是正を完了した。著者は Copilot のレビュー意見に従いミューテックスロックのマクロ展開と UART0 割り込み割り当てレベルを修正し、説明に浮動小数点と AI 命令の制限を補足した。残るビルドチェック失敗は上流の既存問題と判定され本件とは無関係であり、著者は人手による再レビューを名指しで依頼し、メンテナは当日後ほど確認すると応答した。本件は 09-28 に起票され複数回の更新を経ており、今回は期間内における実質的な進展である。

1.5 Keil/IAR ターゲット選択提案：著者が二箇所の再レビュー意見に回答、オープン維持（10-13）

日付：2026-10-13 16:34 ~ 17:38（コメント時間）　情報源：PR #11743

Keil/IAR ターゲット自動選択提案（#11743）は期間内に二箇所の再レビュー意見に対して回答した。「targets 初期化ループの欠落」の疑問に対し、著者は関連パスとマクロ定義の連結コードは補完済みで問題は存在しないと指摘した。IAR リンク設定フィールドに –config_def の無効シンボルが混入する問題に対し、著者は同フィールドは各エントリに IDE が自動でプレフィックスを付加するため、LINKFLAGS が設定定義を再度持つべきではないという議論を提起し、メンテナの確認を求めた。提案はオープン状態を維持している。

1.6 二件の旧欠陥チケットがコミュニティに引き継がれ進展：シリアル POSIX 制御パラメータと DAC ドキュメント例（10-13）

日付：2026-10-13 22:13 ~ 22:17（コメント時間）　情報源：Issue #5073、Issue #6568

二件の旧欠陥チケットが期間内にコミュニティメンバーに引き継がれ進展した。シリアル POSIX インタフェース ioctl が下層パラメータを設定できない（#5073）——貢献者が確認したところ、これまで関連付けられた提案は一部のシナリオのみをカバーしており、問題は dfs_v1 に依然存在するとして、本チケットの引き継ぎを希望した。DAC デバイスドライバのドキュメント例問題（#6568）——修正は既にマージされ、ドキュメントセンターのパラメータ記述も更新され、貢献者はドキュメントの表現形式についてさらなる修正案を提起した。

2. 公式・コミュニティイベント

2.1 仮想化ハイブリッドデプロイ教育プラットフォーム記事が掲載：RK3588 シングルチップでデュアルドメイン実行 Linux と RT-Thread（10-13）

日付：2026-10-13（メディア公開時間）　情報源：電子工程専輯原文

電子工程専輯が RT-Thread 仮想化ハイブリッドデプロイ教育プラットフォームの特集を掲載した。Rockchip HyperCar は RK3588 シングルチップで Linux/ROS 2 と RT-Thread のデュアルドメインを同時実行し、HyperBoot が起動、隔離、リソース割り当てを担当、両ドメインは仮想ネットワークと micro-ROS を介して協調する——Linux 側は知覚・意思決定とアプリケーションオーケストレーションを担い、RT-Thread 側はシャシーのハードリアルタイム実行を担う。プラットフォームには基礎制御、地図構築ナビゲーション、ビジョンサービス、ロボットアームの四類モジュール計 16 事例と三階層の実訓パスが付属し、大規模モデルのローカルデプロイと六軸ロボットアーム把持の総合事例も提供される。

2.2 〖2026 組み込みコンテスト〗GD32H759IM の USB サブディスプレイ + OV2640 カメラ二合一作品スレッドが投稿（10-13）

日付：2026-10-13 17:43（投稿時間）　情報源：フォーラムスレッド 76ffa34214c0eda4

2026 組み込みコンテスト作品投稿「GD32H759IM の USB サブディスプレイ＋OV2640 カメラ二合一」が公開：GD32H759IMK6 をコアとし、RT-Thread 4.1.1 と LVGL 9.5 を動作させ、USB 高速ポート経由で 4.3 インチ 480×272 RGB スクリーンをパソコンの第二ディスプレイに変換。ファームウェアは TLI 表示、EXMC SDRAM、DCI カメラ、USBHS0 を統合し、PC モニタリングダッシュボード、画面ミラーリング、カメラストリーミングの 3 モードを提供。ホスト側は Python ツール。-O0 ビルドで Flash 約 354 KB、RAM 約 84 KB。

2.3 〖2026組み込みコンテスト〗GD32H7 ベースの多機能環境モニタリング＆ローカルデータロガー作品投稿が公開（10-13）

日付：2026-10-13 08:37（公開時間）　情報源：フォーラム投稿 248f9e54e367993d

2026 組み込みコンテスト作品投稿「GD32H7 ベースの多機能環境モニタリング＆ローカルデータロガーシステム」が公開：GD32H759I-EVAL をプラットフォームとし、RT-Thread 5.3.0 と LVGL 8.3.11 を採用。SHT40、BH1750、SGP30 により温湿度、照度、等価二酸化炭素、TVOC を収集。中国語タッチインターフェースは数値表示、閾値調整、トレンド閲覧、履歴参照をサポートし、データは周期的に SD カードへ CSV 形式で書き込み、パソコン側オフライン解析ツールを付属。温室、機房、実験室などのローカルモニタリングシーン向けで、現バージョンはネットワークアップロードを含まない。

3.1 packages インデックスの新提案：hpm_sdk v1.13.0 ソフトウェアパッケージインデックスが開設、上流タグも同日リリース（10-13）

日付：2026-10-13 17:07（作成時間）　情報源：PR #2045（RT-Thread/packages）、rtt-pkg-hpm-sdk v1.13.0

ソフトウェアパッケージインデックスリポジトリ（RT-Thread/packages）に新提案：HPMicro hpm_sdk に v1.13.0 インデックスを追加——PKG_USING_HPM_SDK_V113 設定と対応するダウンロードエントリを新設。デフォルトバージョンは v1.10.0 を維持し、明示的な選択が必要。v1.13.0 は HPM5100 シリーズ（HPM5151 / HPM5100EVK）サポートを新設し、各シリーズのペリフェラルドライバ更新を同期。対応するパッケージリポジトリ rtt-pkg-hpm-sdk は同日（16:05）に v1.13.0 タグをリリース済み。提案はオープン状態を維持。

3.2 サードパーティ GDB デバッグフレームワーク GDR が 2026.04 をリリース：アダプタ自動検出と自動初期化を新設（10-13）

日付：2026-10-13 15:58（公開時間）　情報源：GDR 2026.04 リリースページ、プロジェクトリポジトリ

サードパーティ GDB デバッグ補助フレームワーク GDR が 2026.04 をリリース：アダプタ自動検出を新設——gdr probe はマッチングシンボル、バージョンソース、レイアウトフィンガープリントにより exact / range / undetected の信頼度を提示し、gdr init auto は唯一確定した回答の場合のみ自動選択。同時に VS Code 拡張 2026.4.0 の VSIX 成果物をマウント。本フレームワークはデバッガ内で RT-Thread カーネルオブジェクトを解読し、3.1.x / 4.0.x / 4.1.x をサポート。RV64 は 4.0.4 以降、Cortex-A9 は実機検証済みで、サードパーティエコシステムの参考に属する。

その他のエコシステムチャネルは調査期間内静観が継続：env ツールリポジトリ（最近のマージ 10-09）、packages インデックス（最近のマージ 09-24）、Studio SDK インデックス（最近の更新 10-10）はいずれも期間内のプッシュなし。GD32 ベンダーダウンストリームの gd32_rt-thread も新規動作なし（最近 10-10）。同組織の Zephyr 方向リポジトリの期間内プッシュは本期の範囲に属さない。
