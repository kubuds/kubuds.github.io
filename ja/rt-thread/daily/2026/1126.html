1.1 ulog が呼び出し関数・ファイル・行番号を出力可能に、2023年の課題がクローズ（11-25）

日付：2026-11-25 18:17（マージ）。
出典：#11987。
#7724。

提案は11月5日に提出され、11月25日にマージ。作者 ymj0440、4ファイル変更、398行追加、13行削除。

3つのスイッチはそれぞれ独立。ULOG_USING_OUTPUT_FILE はファイル名、ULOG_USING_OUTPUT_FUNC は関数名、ULOG_USING_OUTPUT_LINE は行番号を出力。3つともオフの場合は従来と同じ出力。

全てオンの場合、1行のログは [main.c:42] app_entry(): this is a debug log! の形。旧インターフェース ulog_output と ulog_e/i/w/d は変更なし。新関数 ulog_output_ctx は LOG_X マクロからのみ呼ばれる。

課題 #7724 は2023年6月26日に提出され、約3年5ヶ月滞留した後、本コミットのマージとともにクローズ。

判断：これはデバッグ情報の補完であり、ログの骨格変更ではない。根拠はデフォルトオフ、旧インターフェース不変であり、アップグレードしても既存のログフォーマットは変わらない。

1.2 ISO9660 ディレクトリ名長の未検証、範囲外書き込みの修正がマージ（11-25）

日付：2026-11-25 17:52（マージ）。
出典：#12062。
#12061。

ISO9660 がディレクトリレコードを解析する際、namelen は媒体から直接取得され、範囲検証が行われていなかった。非ディレクトリレコードは無条件に ;1 バージョン接尾辞を剥がす。namelen が 0 または 1 の場合に長さがアンダーフローし、その後の rt_strncpy で範囲外書き込みが発生、カーネルがクラッシュする。

修正は2点。namelen をローカル名バッファが収容できる範囲に制限する。namelen が 2 未満でない場合にのみバージョン接尾辞を剥がす。1ファイル変更、77行追加、23行削除、メンテナ Bernard Xiong によるコミット。

提案が自己申告する検証は qemu-virt64-riscv 上でのコンパイル・リンクのみ。ブロックデバイスを伴う実行時再現は行っていない。同一パーサーの他のレコード走査境界問題は本コミットの範囲外。

判断：セキュリティ境界の修正に属するが、適用範囲は限定的。根拠は名称長のみ検証しており、作者がカバーしていない項目を提案に明記している。

3.1 CAN フィルタマスクをフレーム種別のビット幅まで狭める（11-25）

日時：2026-11-25 22:27。
情報源：#12089。
#11576。

初期化マクロは全部で 12 個あり、マスクは一律 0xFFFFFFFF を設定している。標準フレームの識別子は 11 ビットのみ、拡張フレームは 29 ビット。マスクモードではマスクビットが 1 の場合そのビットが一致しなければならないため、ビット幅を超えるビットはマスクに残すべきではない。

提案では2つの定数を新規追加する。
RT_CAN_STD_ID_MASK は標準フレーム用。
RT_CAN_EXT_ID_MASK は拡張フレーム用。
12個のマクロをすべて切り替え、フレームタイプのマッピングは変更せず、変更は1ファイル、25行追加、12行削除。

作者は ymj0440 で、本日マージされた ulog 提案と同じ人物。対応する議題 #11576 は7月6日に提出された。

4. 業界応用：大会一等賞のモータ制御プラットフォーム

4.1 電力分配型 SVM がデュアルポートエネルギー scheduling を変調層に組み込む（11-25）

日付：2026-11-25 17:29（公開）。
情報源：電子工程専輯。
コミュニティ原文。

RT-Thread 公式アカウントは当日、大会作品の共有記事を配信し、電子工程専輯が同日転載した。作品 NS800-PD-FOC は 2026 RT-Thread 組み込み大会の一等賞で、作者は朱玉施、コミュニティ ID は NinoC137_。ハードウェアは NSSinePad NS800RT7P65D、ソフトウェアは RT-Thread 5.3.0。

核心は電力分配型 SVM。従来の SVM は三相電圧の合成のみを解くが、この版は高圧と低圧の2つの直流ポートがそれぞれどれだけの電力を担うかを同時に解く。分配係数 xi は0から1の間で、上下2組の電圧ベクトルそれぞれで SVM を1回計算し、最終的に6組のブリッジアームデューティ比を導出する。

母線電圧はもはや固定値ではない。2つのポート電圧は当拍の ADC 実測値を取り、読み値が条件を満たさない場合のみ設定定数にフォールバックする。

4.2 三層故障停止、最速層は CPU を経由しない（11-25）

日付：2026-11-25 17:29（公開）。
情報源：電子工程専輯。

第1層はハードウェア経由。ADC 後処理ブロック PPB1 が相電流を監視し、限界超過で ADCAEVT1 をトリガーする。イベントは ePWM X-BAR を経て EPWM8 から EPWM13 のトリップ領域に送られ、6路の PWM が直接ローレベルに固定され、全行程で CPU を経由せず、応答は1マイクロ秒未満。

第2層は 20 kHz 制御割り込み内で 22 A 閾値を比較し、超過で強制トリップ、応答は50マイクロ秒以内。第3層は監視スレッドで、10ミリ秒ポーリングし、ラッチ、停止、現場記録を担当する。

制御ファストパスはオブザーバ、デュアルポート SVM、PWM 更新のみを行う。表示、シリアル、ボタンはそれぞれ100ミリ秒、イベント駆動、5ミリ秒のタスクに配置される。

4.3 ADC ドライバが先にメインラインへマージ、その後作品が還元（11-25）

日付：2026-11-25 17:29（公開）。
情報源：#11437。
作品リポジトリ。

作品で使用された NS800 ADC ドライバは別途 #11437 として提出され、6月8日にメインラインへマージ、6ファイル、1124行追加。作者は作品作者と同一人物。

ドライバは ADC を rt_adc_device フレームワークに接続する。また、割り込み、PPB オーバーサンプリング、閾値イベントもサポートする。

プロジェクトコードは GitHub の NinoC137/ns800_pdfoc リポジトリにあり、6月26日に作成、最終プッシュは11月9日、現在0スター。

判断：これはドライバが先に上流へ、作品の宣伝が後という経路である。根拠は ADC ドライバが6月にすでにメインラインへ入り、作品の投稿が11月になってから発信されたことである。

5. まとめとトレンド観察

  • 合入口径は日常水準に戻る：1日5件で、前日の16件から明らかに減少したが、方向性は変わらず、依然としてドライバとコンポーネントの修正が中心である。
  • 2件はいずれも過去案件の処理：ulogの1件は2023年6月のイシューをクローズし、ISO9660の1件は11月17日に提起されたセキュリティ欠陥をクローズした。1件は3年以上放置され、1件はわずか8日間の放置だった。
  • セキュリティ境界が2日連続で主位を占める：昨日は6件の同源提案の清算、今日はISO9660のディレクトリ名長であり、類型はいずれも境界外書き込みである。
  • V861のボトルネックはすでに移行：ビルドマトリクスとDTBが一夜で补齐され、CI 48項目中43項目が通過した。新たな分歧はPLICアドレスとコードフォーマットにあり、設計ではなく詳細に属する。
  • ニュース側は依然として薄い：公式ニュースインターフェースは11月6日以降更新がなく、当日唯一利用可能な中国語報道は賽事作品の転載であった。
  • 審査待ちキューにプロトコル詳細が現れ始める：CANマスクビット幅のような提案は新機能に関わらず、ビット定義のみを修正しており、保守の重心がプロトコルの正確性にあることを示している。
