1. カーネルとバージョン動向

1.1 玄鉄 C908 プラットフォーム RISC-V サポート三連合流：rt-smart、MMU と SMP（09-15）

日付：2026-09-15 22:57（北京時間、合流時間）　出典：PR #11775

玄鉄 C908 プラットフォームの三つのコミットが調査期間内に一括してメインラインに合流、合計 31 ファイル、新規約 2575 行、削除 565 行。三項目の内容はそれぞれ：libcpu の MMU フレームワークが SV39 / SV48 / SV57 アドレスモードサポートを補完しテストケースを付属；K230 と Virt / C906 の既存実装を参照し、C908 に rt-smart サポートを追加；C908 に SMP サポートを追加し、副コア起動タイミング、TLB フラッシュと IPI 初期化に対して最適化を実施。検証プラットフォームは BSP ディレクトリ下の xiaohui C908（QEMU 仿真）。rt-smart と SMP が同時に整備されたことは、このコアが「動作する」段階から「マルチコアユーザー態検証が可能」な段階に入ったことを意味する。

1.2 env ツールチェーンが v2.0.0 と v2.0.2 を連続リリース、コマンドライン化リファクタリングが確定（09-16）

日付：2026-09-16 09:48 / 09:51（北京時間、リリース時間）　出典：env v2.0.0、env v2.0.2

RT-Thread env ツールチェーンが調査期間内に二つのバージョンを連続リリース、バージョン番号は 1.5.x から直接 2.0.0 へ飛躍し、二分会後にさらに 2.0.2 修正を追加リリース。これは 2024 年 4 月の v1.5.2 以来の初回リリースである。主な変更点は：kconfiglib による設定システムのリファクタリングとコマンドラインエントリの統一、Windows 側はスクリプト依存ではなくコマンド登録に変更；sdk コマンドと e-build 組込みビルドシステムを新規追加；env.json をバージョン番号、リポジトリアドレスとミラー情報の単一ソースとして導入し、コード内のハードコードアドレスはアクセス層から読み取るよう変更；デフォルトインストールで arm-none-eabi、gdb と qemu ツールチェーンを同梱しなくなる；インストールスクリプトがネットワーク位置に応じてミラーソースを自動選択。配布名は rt-env に調整。

1.3 SDIO ドライバ注销とノードメモリリーク欠陥報告が処理キューに投入（09-15）

日付：2026-09-15 17:53（北京時間、最終更新）　出典：Issue #11801

ウィンドウ内で1件のデバイスドライバ欠陥報告のディスカッションが更新された。報告はSDIOドライバフレームワークに2箇所の潜在的リスクがあると指摘している。複数のSDIOドライバをロードした後、そのうち1つをアンロードする際、リンクリストの走査がマッチ成功後に終了せず、ローカルポインタが次のループでNULLに上書きされる可能性がある。また、割り当て済みノードポインタの解放がカードにマッチした分岐内に縛られており、カードにマッチしなかった場合は解放されず、メモリリークのリスクがある。報告はさらに、より安全なリンクリスト走査マクロで既存の写法を置き換えることを提案している。本議題は欠陥とドライバコンポーネントに分類され、ステータスは処理中で、ウィンドウ内には3件のディスカッションがある。

2. 公式・コミュニティ活動

2.1 第9回全国大学生組込みチップ・システム設計競技：深圳技術大学が特等賞 RT-Thread杯を受賞（09-15）

日付：2026-09-15 14:34（北京時間、発布時刻）　情報源：南方都市報報道

第9回全国大学生組込みチップ・システム設計競技の全国決勝結果が公表され、深圳技術大学チームが特等賞 RT-Thread杯および全国一等賞3項、二等賞4項、三等賞2項を受賞した。大会は中国電子教育学会が主催し、15社のチップ企業が共同で出題、計908校、4.45万人の学生、1.7万チームが参加し、1227チームが全国決勝に進出した。特等賞を受賞した作品は『RT-Threadベースのジェスチャーインタラクション・デスクトップアンビエントライトと植物育成一体化端末』、他に『OpenHarmonyとRISC-Vベースのスマート会議室システム』が全国一等賞を受賞した。企業冠名賞の登場は、RT-Threadの大学競技への投入が開発ボードの提供から出題と審査の段階へと拡大したことを示している。

2.2 コミュニティフォーラムに技術記事『MCU C ランタイムライブラリ起動フロー』が新規追加（09-15）

日付：2026-09-15 17:04（北京時間、更新時刻）　情報源：コミュニティフォーラム記事インターフェース

コミュニティフォーラムに技術記事が新規追加され、ARMv7-Mのリセット動作から説き起こし、ベクタテーブルとVTORの関係、.dataセクションのFlashからRAMへのコピーと.bssセクションのゼロクリアを段階的に分解し、組込みCランタイムライブラリで標準的に初期化フローを引き継ぐ方法を議論している。記事には配套動画が付属し、初心者向けの体系的な解説である。フォーラム記事インターフェースは前回異常を返していたが、今回は正常に復旧し、今後再び日常チェックに組み込む。

3. エコシステムとベンダー対応

3.1 STM32N657 Nucleo BSPがメインラインにマージ、83ファイル規模（09-16）

日付：2026-09-16 09:05（北京時間、マージ時刻）　情報源：PR #11799

前回レビューキューにあったSTM32N657 Nucleo BSP提案がウィンドウ内でメインラインにマージされ、規模は83ファイル、新規約17884行、レビュアーはsupperthomasとkurisaW。当該提案は09-11に審査提出され、09-14には1日で4回の強制プッシュで継続的インテグレーション問題を修正し、その後レビューを通過してマージされた。これと配套するSTM32N657xx FSBLソフトウェアパッケージインデックスは09-14に先行マージ済みで、STM32N6シリーズはBSPとソフトウェアパッケージの両側でここに整った。STM32N6はニューラルプロセッシングユニット付きのグラフィックス・ビジョン応用向けで、本シリーズがメインラインサポートリストに入るのは今回が初である。

3.2 国民技術 N32H 三シリーズドライバ拡張がメインラインにマージ（09-16）

日付：2026-09-16 09:06（北京時間、マージ時刻）　情報源：PR #11800

前回レビューキューにあったN32H三シリーズドライバ拡張も同様にウィンドウ内でメインラインにマージされ、70ファイル、新規約8096行、削除2778行、N32H47xとN32H48x、N32H49x、N32H7xxの3シリーズおよび3枚の評価ボードをカバーしている。共用ドライバ層にADC、DAC、I2C、SPI設定ヘッダファイルを新規追加し、ADC、DAC、イーサネット、GPIO、ハードウェアI2C、NAND、QSPI、SDRAM、SPI、シリアル、ウォッチドッグなどのドライバ分岐を拡張した。2枚の評価ボードにはさらにFEMCタイミングテーブル、イーサネット物理層リセット、USB設定を追加。3款の新ボードも同時に継続的インテグレーションビルドマトリクスに追加された。国産MCU原廠のドライバ補完は依然として今四半期のメインラインマージの主要な來源である。

3.3 STM32イーサネットドライバが新版HALインターフェース移行を完了（09-15）

日付：2026-09-15 22:59（北京時間、マージ時間）　情報源：PR #11781

STM32 イーサネットドライバが新しいハードウェア抽象化層インターフェースへの移行を完了。8 ファイル、755 行追加、968 行削除で、F4 と H7 の 2 プラットフォームで検証済み。この変更は分散していた送受信ロジックを統一インターフェースに集約し、今後の各 BSP が同一のイーサネットドライバを再利用するための基盤を築くものである。コミット者は STM32 移植層を長期的にメンテナンスしてきた開発者であり、メインラインのメンテナンス性変更に属する。

3.4 ドライバ側修正動向：GD32 シリアルピン、Infineon PWM マクロと STM32 リンク問題（09-15 ~ 09-16）

日付：2026-09-15 21:50 ~ 2026-09-16 10:19（北京時間、コミットとマージ時間）　情報源：PR #11802、PR #11803、PR #11804

調査期間内には 3 件のドライバ修正系変更があった。マージ済みの 1 件（#11803）は STM32 ダイレクトメモリアクセスドライバにおける型名関数のリンク問題を修正するもので、変更はわずか 1 行で、ログコンポーネント未启用時のコンパイル警告を解消するためのものである。レビュー入りした 2 件の変更はそれぞれ：GD32 各シリーズのシリアル送受信ピン初期化修正で、送信ピンを復用プッシュプル、受信ピンをプルアップ入力に設定し、両ピンを汎用プッシュプル出力に設定していた誤った別名を除去するもので、GD32E50x、F10x、F20x、F30x の 4 シリーズに影響する；および Infineon PSoC6 評価ボードの PWM マクロ不整合修正で、条件コンパイルマクロ名とボードレベル設定が一致せず、スライダーサンプル内の PWM 初期化コードが丸ごとコンパイルから除外され、サンプルが PWM デバイスを永遠に見つけられない問題であり、計 14 ファイル。3 件はいずれもエコシステム開発者が提出した定常的な修正である。
