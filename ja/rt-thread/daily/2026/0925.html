1. カーネルとバージョン動向

1.1 沁恒 CH32V203C8T6 開発ボード BSP がメインラインにマージ（09-24）

日付：2026-09-24 16:21（北京時間、マージ時間；提案作成は 09-22 夜）　出典：PR #11827、マージコミット 386b877b

メインラインは期間内に新たなボードサポートを 1 件マージした：沁恒微（WCH）CH32V203C8T6-EVT-R0 開発ボード BSP で、bsp/wch/risc-v/ch32v203c-evt-r0 に配置される。このボードは青稞 V4B コア（CH32V20x_D6）を採用し、64KB ゼロウェイト Flash と 20KB SRAM を搭載する；公式 SDK は D8W 用のスタートアップファイルのみを提供し、D6 に対しては直接 Exit() を呼び出すため、通常のソフトウェアパッケージビルドではファームウェアを生成できない。提案は D6 の割り込みベクタテーブル（ソフトウェア割り込みシンボル SW_handler）と 64KB/20KB リンカスクリプトで補完し、この条件でのみ SDK パッケージスクリプトを修正し、D8W フローには影響しない。デフォルトイメージは GPIO と UART1（USART1 は PA9/PA10 を多重化）を有効化し、PWM、ADC、RTC、独立ウォッチドッグ、USB デバイスは menuconfig に保持される（64KB 容量では USB と前述の 4 種類のペリフェラルを同時に収容できない）。提案はさらに 2 箇所の共有ドライバ修正を伴う：drv_usbd.c は USBFS DMA の 16 ビット SRAM オフセットと SET_ADDRESS 書き込みタイミングを調整し（エンドポイントバッファは SRAM に常駐する必要があり、フルスピードパケット長は 64 バイト）、drv_iwdt.c は CH32V2 シリーズ向けの適応を補完する。提案は計 4 コミット、26 ファイル（+2216/-57）。

1.2 rt_vsnprintf の幅セマンティクス欠陥とカーネル修正提案（09-24）

日付：2026-09-24 20:52 ~ 21:29（北京時間、欠陥報告と修正提案の時間）　出典：Issue #11833、PR #11834

コミュニティ貢献者が期間内にカーネル欠陥報告と付随する修正を提出した：現在の rt_vsnprintf 実装（特に tiny 版）は %[width].[precision]s のセマンティクス処理に誤りがあり、最小幅が誤って最大幅として切り詰められる——例えば %3s で “abcdef” をフォーマットすると完全な文字列ではなく “abc” を出力し、左揃えの %-3s や %*s などの変種も同様に影響を受ける。修正提案は同時に提出され、変更は rt_vsnprintf_std.c、rt_vsnprintf_tiny.c と対応する単体テスト TC_rt_sprintf.c をカバーし（計 3 ファイル、+37/-18）、内容は境界検出の補完、幅と精度の組み合わせ機能の実装、テストケースの最適化である。欠陥報告には既に 3 件のディスカッションがあり、修正提案はレビュー待ち状態にある。

1.3 レビューキューに新規提案 3 件：ネットワークスタック修正とビルド整理（09-24）

日付：2026-09-24 14:15 ~ 17:52（北京時間、作成時間）　出所：PR #11831、PR #11835、PR #11832

今期レビューキューには合計5件の提案が新規追加され、うちカーネル vsnprintf 修正は 1.2、ESP32-C6 ボードサポートは 3.1 を参照、本条では残る3件を収録する。その一つ目は lwip-nat のポート割り当て欠陥の修正：元の実装は空きスロットインデックスではなくスキャンカウンタで変換ポートを割り当てており、割り当てパスに入るとカウンタが常にテーブルサイズと等しくなるため、新しいマッピングごとに同一ポートが取得され、並行する UDP/TCP セッションが相互に衝突し、戻りトラフィックが誤ったテーブルエントリにマッチする可能性があった。提案は同時に lwIP 2.1 対応（ヘッダファイルの名称変更とタイムアウトインターフェース）を完了し、NAT 適用条件を送信元と宛先のネットワークがともにルールにマッチするよう厳格化、ICMP テーブル満杯時は LRU で最古のエントリを淘汰する（1ファイル、+41/-11）。二つ目は lwip-dhcpd に欠落していた string.h ヘッダファイルの追加：dhcp_server_raw.c は memcmp / memset / strlen / strncmp / strchr を直接呼び出しながら標準ヘッダを含んでおらず、暗黙宣言は 64 ビットターゲットで strchr() の戻りポインタを切り詰める（1ファイル）。三つ目は components/drivers/ipc/SConscript 内の冗長な __RT_IPC_SOURCE__ マクロ定義の削除（1ファイル）。

3. エコシステムとベンダー対応

3.1 楽鑫 ESP32-C6 開発ボード BSP 提案とソフトウェアパッケージソースの同期コミット（09-25）

日付：2026-09-25 01:20 ~ 02:38（北京時間、提案と付随ソフトウェアパッケージ提案の作成・更新時間）　出所：メインライン PR #11836、esp-idf ソフトウェアパッケージ PR #17

コミュニティ貢献者が期間内に楽鑫 ESP32-C6-DevKitC-1 開発ボードのメインライン BSP 提案を提出：モジュールは ESP32-C6-WROOM-1（RISC-V、8MB Flash）、bsp/ESP/ESP32_C6 を新規追加、デフォルトで GPIO、UART0（GPIO16/17）、ADC を有効化。提案は C6 が専用 bootloader イメージを使用する必要があること（C3 のイメージは再利用不可）、Flash は DIO 8MB 80MHz、アプリケーションオフセット 0x10000 であることを強調。上流の esp-idf ソフトウェアパッケージは 2023-11-26 以降更新されておらず、C6 ソースコードが欠落しているため、貢献者は同時にソフトウェアパッケージリポジトリで PR #17 を提出し C6 の scons ビルドソースを追加、両方の提案ともレビュー状態にある（メインライン側 2 コミット、40ファイル、+9492/-50）。この貢献者は 1.1 の CH32V203 BSP の提出者と同一人物であり、同日に沁恒と楽鑫の2つの RISC-V チップラインを横断している。

3.2 コミュニティが RT-Thread Nano の IDF 不要移植プロジェクトを公開：ESP32-S31 上で動作（09-25）

日付：2026-09-25 10:04（北京時間、プッシュ時間）　出所：esp32s31_rtt_nano リポジトリ

コミュニティ開発者が、楽鑫 ESP32-S31（デュアルコア RISC-V、主周波数 320MHz、オンボード 16MB Flash と 16MB PSRAM）向けの RT-Thread Nano 移植プロジェクトを公開した。特徴は ESP-IDF ビルドシステムを完全に迂回している点にある。自作の起動アセンブリとリンカスクリプト、riscv32-esp-elf-gcc による直接コンパイル、独立した esptool による書き込み、イメージはチップの bootROM から Flash 0x2000 に直接ロードされる（IDF のセカンドステージ bootloader は使用しない）。コンソールはチップ内蔵の USB-Serial/JTAG を使用し、tick は SYSTIMER、割り込みは CLIC、PIN / SPI（QSPI 含む）/ I2C ペリフェラルは RT-Thread デバイスフレームワークに接続され、msh の中で直接検証できる。プロジェクトは再現可能なビルド検証を実施済み（89 個の追跡ファイルがクリーンなディレクトリでバイト単位まで一致するイメージをビルド）。個人プロジェクトであり、コミュニティの参考に供するもの。

5. まとめとトレンド観察

5.1 直近一日のトレンド（09-24 ~ 09-25）

  • ボード級が一日で三連、すべて RISC-V チップ上に集中：沁恒 CH32V203C8T6 がメインラインにマージ、楽鑫 ESP32-C6 開発ボード提案がレビュー入り、コミュニティが RT-Thread Nano を ESP32-S31 に移植——三社の異なるベンダーの RISC-V チップが同じ日にボード級サポートチェーンに現れ、RT-Thread のボード級エコシステムにおける RISC-V の比重は引き続き上昇している。
  • レビューキューがカーネルとネットワークスタックの欠陥を集中的に処理：rt_vsnprintf の幅セマンティクス、lwip-nat のポート割り当て、lwip-dhcpd のヘッダファイル欠落の三箇所の問題はいずれもコミュニティからの自主的なコミットであり、品質志向の基本的な修正が本期の主体となっている。
  • メインラインのペースは低頻度を維持：調査期間内にメインラインへは BSP のマージがわずか一件で、直近一週間の散発的なマージとレビューキュー消化のペースと一致している。
  • 公式チャネルは三十六日目も沈黙：公式サイトのニュースページは依然として確認・閲覧不可であり、製品とイベントの情報は引き続きフォーラムと GitHub 側から先行発信されている。

5.2 限界と重複排除の説明

  • 重複排除の説明：Titan Mini OpenMV（09-18、09-22、09-24 に収録済み、調査期間内に新規コミットなし）、Gino Pi 関連（09-14 ~ 09-22 に収録済み、調査期間内に新規の進展なし）、ソフトウェアパッケージインデックスの三連マージと GD32 デバイスパッケージ（09-23、09-24 に収録済み）はいずれも重複報道しない。
  • CH32V203 提案の共有ドライバ修正範囲は提案の説明に準じ、実際の影響範囲は今後の使用に準じる。ESP32-C6 提案は貢献者ブランチ内のソフトウェアパッケージソースコードに依存しており、マージ形態とバージョンはレビューの結論に準じる。
