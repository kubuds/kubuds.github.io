1. カーネルとバージョン動向

1.1 進畳時空 K1 BSP 初版がメインラインにマージ：173 ファイル、5.4 万行、S モード＋4 コア SMP（10-19）

日付：2026-10-19 18:49（マージ時間）　來源：PR #11132、K1 BSP 説明

進畳時空 K1 プラットフォームの初版 BSP がマージされた。4 コミット、173 ファイル +53862/-12、作者 GuEe-GUI、提案は 2026-01-11 に公開され、レビュー約 9 ヶ月を経て着地、Next RISC-V シリーズ（#10320）の後続に属する。BSP は 64 ビット RISC-V 向けで、8 個の X60 コアを統合した K1 に対応し、ベクトル拡張を備え、U-Boot/OpenSBI によりブートされ、S モードで動作、デフォルトで MMU と 4 コア SMP を有効化、検証プラットフォームは Banana Pi BPI-F3、コンソールは UART0（115200 8N1）経由。PCIe/NVMe、eMMC HS400、イーサネットと PTP、HDMI フレームバッファ（コールドブート表示含む）、JPU と V2D アクセラレーション、ES8326 オーディオ、CPUfreq と熱管理、AES/RNG/eFuse をサポート済み。SPI と QSPI は移植済み・検証中と記載。ドライバ層は別途 bsp/spacemit/dm に抽出され（147 ファイル、49 個の C ファイル、約 30 モジュール、クロック、オーディオ、グラフィックス、暗号化/復号、PCI、SDIO、シリアル、熱管理などを含む）、後続の同系 SoC で再利用される。CI 側では spacemit-k1 ビルドレッグを追加し、従来 K230 ツールチェーンのみをインストールしていたステップを、全 riscv64 musl BSP に対して有効となるよう変更した。

1.2 RISC-V アトミック CAS リトライ欠陥を同批で修正：期待値がステータスレジスタに上書きされなくなる（10-19）

日付：2026-10-19 18:49（マージ時間）　情報源：マージコミット 1c801efa、atomic_riscv.c

同一のコミット群で、RISC-V のアトミック比較交換実装にある実在の欠陥が修正された。元のコードでは rt_hw_atomic_compare_exchange_strong の中で同じ変数 tmp を期待値の保持と sc 命令の成否状態の受け取りの両方に使っていた。sc が失敗すると tmp に非ゼロ値が書き込まれ、リトライ分岐の lr の結果がそれと比較されるため、上書きされた値を期待値として扱うことになり、ループが永久に抜けられない、あるいは誤った判定をする可能性があった。修正では期待値を読み取り専用オペランドに退避し、status レジスタを別に設けて sc の結果を受け取り、結果の出力を書き込み専用制約に変更した。この実装はすべての RISC-V ボードのアトミック操作が通る経路であり、アーキテクチャ共通コードに属するため、影響範囲は単一の BSP より大きい。

1.3 rt_null コンソールデバイスを BOARD 初期化へ前倒し：電源投入直後からログポートを null に設定可能に（10-19）

日付：2026-10-19 16:53（マージ時間）　情報源：PR #11884、Issue #11472

コミュニティから提出された一行の変更で、null デバイスの登録タイミングを INIT_DEVICE_EXPORT から INIT_BOARD_EXPORT へ引き上げ、RT_CONSOLE_DEVICE_NAME を null に設定した際に電源投入直後から有効になるようにした。ログポートと通信ポートが同じシリアルを共用する場合に、早期に出力を静かに止められない問題を解決する。作者は qemu-vexpress-a9 で検証済み：uart0 は正常に出力し、null に変更すると QEMU に起動バナーが出ず、uart0 に戻すと msh プロンプトが復帰し、rt_null.o は .rti_fn.1 セクションに配置された。変更は 1 ファイル +4/-1 で、作者は AI の支援を受けて完成したと注記している。早期コンソールと通常コンソールを分離するというより抜本的な方向性は今回は実装されていない。

1.4 デバイスモデルフレームワークの2箇所修正：電源ドメイン proxy の命名と DVFS OPP の重複警告（10-19）

日付：2026-10-19 18:49（マージ時間）　情報源：power_domain.c、dvfs.c

K1 BSP のマージと同時にフレームワーク層の修正が2箇所もたらされた。これは「BSP が先行し、フレームワークが追いつく」典型例である。第一に、電源ドメインの代理オブジェクトが登録時に本物の電源ドメインの名前を書いてしまい、名前で検索する際に代理をドメイン本体と誤認していた。代理専用の名前に変更することで、デバイスツリー内の電源ドメイン参照が正しく代理の解決コールバックに届くようになった。第二に、DVFS が OPP テーブルを解析する際に重複チェックなしで追加していたため、デバイスツリーの重複エントリが重複警告を引き起こし追加に失敗していた。周波数で先に検索し、ヒットすれば再利用するように変更した。いずれも components/drivers 配下にあり、受益者は K1 だけではない。

1.5 netdev ping 遅延統計の修正：count が 1 のとき最小遅延が記録されない問題を解消（10-19）

日付：2026-10-19 16:42（作成時間）　情報源：PR #11900

コミュニティから netdev 層の ping 統計修正が提出された（1 ファイル +5/-1）。元のロジックでは ping 回数が 1 かつ成功のとき最大遅延のみを統計し、最小遅延がスキップされていたため、1 回の成功したプローブ後に最小値が異常表示されていた。修正方法は、初回の応答受信成功時に最大値と最小値を同時に初期化するというもの。変更は小さいが常用の診断コマンドの表示結果に関わるため、提案はまだ審査中である。

2. セキュリティと安定性のフォローアップ

2.1 lwp シグナル番号検証の提案：sys_sigaction の入口を 1 から 64 に制限（10-19）

日付：2026-10-19 08:49（作成時間）　情報源：PR #11899、Issue #11882

メンテナのBernardXiong氏が前回の欠陥票#11882に対して修正提案を提出した（2ファイル+11-0）：sys_sigactionはユーザー空間から渡されたシグナル番号をそのままlwp_signal_actionに渡すが、後者はシグナル番号から1を引いた値で固定長配列（_LWP_NSIGは64）をインデックスするため、範囲外や負の値ではカーネルヒープの範囲外読み書きが発生し、通常のプログラムでもシステムコール1回で引き起こせる。提案ではsys_sigactionの入口で1から64のみを受け付け、それ以外はEINVALを設定して返し、さらにlwp_signal_action内にも同じ検証を追加して今後の新規呼び出し元を保護する。リポジトリ内には既にvalid_signo_checkがあり、今回はこの考え方を再利用する。提案はcomponentsのレビューに割り当てられ、審査中状態にある。

2.2 OFWデバイスツリー展開前に深度の事前チェックを追加：63層を超えたら直接拒否（10-20）

日付：2026-10-20 01:12（作成時間）　情報源：PR #11901、Issue #11879

コミュニティメンバーのliangzhan5氏が#11879に対して修正をコミットした（1ファイル+60-0）。fdt_unflatten_singleは固定64項目のスタックで走査パスを一時保存するが、ネストが64層を超えるとプッシュ前のチェックがなく、起動段階で範囲外書き込みが発生してクラッシュする。提案では実際の展開前に自作スタックでデバイスツリーを一通り走査して最大深度を計算し、63層を超える場合はエラーを出力して以降の展開を中止することで、残存ツリーと二重アサートの問題を回避する。作者によればqemu上でこの欠陥を再現済みで、検証構成はqemu-virt64-aarch64、CLAは署名済み、提案は審査中である。

2.3 新たなtmpfs欠陥票：ftruncate(fd, 0)がバッファを解放するのに成功を返す（10-20）

日付：2026-10-20 01:53（作成時間）　情報源：Issue #11902

貢献者のXueDugu氏がdfs_v2の欠陥票を新たに起票した。tmpfsの切り詰め関数はrt_realloc(data, 0)が空ポインタを返した際にENOMEMを設定するのに0を返すが、2つのヒープバックエンドはいずれも長さ0のreallocに対して「解放して空を返す」というセマンティクスを持つため、正当なftruncate(fd, 0)が先にファイルバッファを解放し、その後アプリに成功を報告することになり、ダングリングポインタと陳腐化した長さが残り、その後の読み書きが解放済みのカーネルヒープ上に落ちて情報漏洩と二重解放を引き起こし得る。欠陥は2023-09-20のコミット（PR #8063）で導入され、v5.0.2以降の全バージョンとmasterが影響を受け、QEMU aarch64のRT-SmartとRP2350で再現済みである。チケットはオープンのままである。

2.4 メンテナがlibdl動的モジュール欠陥に回应：部分修正は可能、完全な隔離にはユーザー空間が必要（10-19）

日付：2026-10-19 08:16（コメント時間）　情報源：Issue #11898

前回収録したlibdlのリロケーション範囲外書き込み欠陥票が今回の調査期間でメンテナの回应を得た。BernardXiong氏は記述が事実であることを確認し、境界検証はある程度修正できると考える一方、動的モジュールは本質的にコードの断片をカーネルに挿入し権限を全開にするものであり、これが公式がこの機構でこれ以上試みていない理由でもあると指摘した。メモリ隔離を実現するにはユーザー空間モードに移行する必要がある。この表明は今後の修正範囲に境界を引いた：今回はメタデータ検証のみを補い、モジュールロードの全体的な権限モデルは変更しない見込みである。

5.1 ビニールハウス環境モニタリング端末：E907シングルコアにLVGL四ページインターフェース、完全オフラインで利用可能（10-19）

日付：2026-10-19 09:35（公開時間）　情報源：コミュニティ記事

2026 組込みコンテスト作品、小型および家庭用ビニールハウス向けのローカル環境モニタリング端末。ハードウェアは ArtInChip D12X-DEMO68 開発ボードを使用し、メインコントローラは達摩院玄鉄 E907（RV32、396 MHz、単精度 FPU 搭載）、8 MB PSRAM、16 MB SPI NOR、480×272 静電容量タッチスクリーン（GT911）を搭載、センサーは DHT11 と BH1750 の 2 本のみで、Wi-Fi に接続せず、クラウドプラットフォームにも依存しない。ソフトウェアは RT-Thread 4.1.1 と LVGL 8.3.1 をベースとする：6 つのスレッドを 12～26 級で階層化し、2 つのメッセージキューがそれぞれアラームと画面に給餌し、ミューテックスロックが状態スナップショットとセンサーバスを保護し、閾値はセマフォを介して非同期に LittleFS へ書き込まれる。画面は 4 ページのキャッシュ式切り替えで、曲線は直近 60 点のリングバッファを保持し、3 チャネルは縦軸を共有しない。アラームは連続 3 回確認と 2 摂氏度、2% RH のヒステリシスを備え、ブザーは PWM で駆動する。さらに 12 本の MSH 診断コマンドを提供し、現場でサンプリング有効ビット、タッチ座標、UI 所要時間を確認できる。

6. まとめとトレンド観察

6.1 今期のトレンド

  • ハイエンド RISC-V プラットフォームがメインライン入り：K1 BSP が S モード、MMU、4 コア SMP の形態でマージされ、PCIe/NVMe、HDMI、マルチメディアアクセラレーションを備えることで、RT-Thread のアプリケーションプロセッサ級 RISC-V プラットフォームにおけるサポートが「起動できる」段階から「周辺機器が揃う」段階へ移行したことを示す。
  • ドライバ層が SoC ファミリー単位で蓄積：bsp/spacemit/dm が約 30 のデバイスモデルドライバを独立した層とし、K1 は最初の利用者にすぎず、後続の同系チップで再利用可能。BSP ディレクトリ構造に「ベンダー層＋ボード層」の分業が現れ始めた。
  • フレームワークも BSP とともに修正：同一バッチのコミットで電源ドメイン代理命名、DVFS OPP 重複チェック、RISC-V アトミック CAS の 3 箇所のフレームワークおよびアーキテクチャ修正が持ち出され、新プラットフォームの接続が汎用コードの欠陥を逆照射していることを示す。
  • セキュリティ債務の整理が修復期に突入：前期の 4 件の欠陥チケットのうち 2 件で修復提案が出され（lwp シグナル検証、OFW 深度事前検査）、さらに tmpfs 切り詰め欠陥が 1 件追加された。メンテナは動的モジュールについて「部分修復は可能、隔離にはユーザー態が必要」という境界判断を示した。
  • 公式チャネルは引き続き沈黙：ニュースインターフェースは 4 ヶ月以上更新停止、v5.4.0 はバージョン番号のみ先行し、対外情報は主に GitHub とコミュニティ作品に依存。
  • バイナリファームウェアのコンプライアンスに留意：K1 BSP にベンダー Linux イメージから取得した RCPU ファームウェア（HDMI オーディオサービス用）が組み込まれており、リポジトリ説明にチェックサムとマージ前の再配布条項確認の注意が示されている。この種の BSP とともにメインライン入りするベンダーバイナリは今後も追跡に値する。

6.2 制約と重複排除の説明

  • 今期は 24 時間の調査期間（10-19 08:00 ～ 10-20 08:00）であり、月曜日ではないため複数日の統合は行わない。
  • 前期との重複排除：#10320 Next RISC-V リファクタリング、4 件のセキュリティ欠陥チケット（#11898、#11882、#11879、#11878）、ESP32-C6 SPI マージ、全志 F101 BSP、睿擎 1.8.4 と Env 2.0.3 はいずれも前期で展開済みのため、今期は調査期間内の新たな進展のみを記載する。
  • K1 BSP は前期未収録であったが、その提案が今期の調査期間内にマージされたため、今期はマージ時刻に基づきトップ記事とした。
  • Google News 中国語 3 日間の調査期間では 2 件のみでいずれも旧稿、英語の調査期間ではヒットゼロ、睿擎の 7 日間クエリは同名の自動車ニュースに埋没し、いずれも新規項目は発生しなかった。HN の 4 件の候補はすべて threads の誤マッチであった。
  • 公式サイトのニュース一覧ページはフロントエンド動的レンダリングのため、クロールでは空の殻しか得られず、ニュースは公式インターフェースを基準とする。
  • 進迭時空 V100 と AI SDK はベンダー側の動向であり、RT-Thread の主題ではないためニュース項目としては単独で記載せず、背景としてのみ扱う。そのバイナリファームウェアの再配布条項は今回未確認であり、リポジトリ説明に基づく注記のみとする。
