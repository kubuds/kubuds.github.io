1. カーネルとバージョン動向

1.1 メインリポジトリ、月曜に9件の提案を集中的にマージ：SDIO 二重メモリリーク修正とネットワークホスト名検証の厳格化（09-21）

日付：2026-09-21 09:28 ~ 10:18（北京時間、マージ時間）　出典：PR #11782、PR #11806

調査期間の終わりとなる月曜午前、メインラインは9件の提案を集中的にマージした。すべてレビューキューの既存修正と整理で、新機能レベルの変更はない。最も重要なのはネットワークコンポーネントの AT チャネルにおけるホスト名処理の厳格化である。元の実装は数値に見えるホスト名文字列を自身の長さで16バイトのスタックバッファにコピーしており、長すぎる入力で範囲外書き込みが発生しうるため、マージ版では長すぎる数値ホスト名を直接拒否するように変更された。ストレージ側の2件はいずれも SDIO メモリリークである。1件目は一部の CIS タプル分岐を処理する際に一時メモリを確保したまま解放しておらず（関連欠陥報告 #11724）、SDIO デバイスの初期化と逆初期化を繰り返すとリークし続ける。2件目はドライバ登録ノードが一致するカードを見つけた場合にのみ解放され、カードがない、または一致しないシナリオで登録と解除を繰り返しても同様にリークする。2件は同じコントリビュータにより提出され、うち2件目は前号で収録した提案であり、今号でマージのクローズまで完了した。

1.2 ボードレベルとツールチェーンのパッチが同時に着地：GD32 シリアルピン、STM32H7 受信 DMA と Rust ターゲット選択の修正（09-21）

日付：2026-09-21 09:28 ~ 10:18（北京時間、マージ時間）　出典：PR #11808、PR #11804

同バッチにはさらに4件のボードレベルとツールチェーンの修正が含まれる。STM32H7 の汎用 DMA 設定ファイルに UART4 受信側チャネル定義を追加し、ボードレベルでこのチャネルを有効化した後にシリアル受信が機能しない問題を修正した。この件はブロックデバイスパーティションのログフォーマット指定子の修正とともに、前号でレビューされた3件の小規模修正に属し、今号ですべて着地した。兆易創新 GD32 シリーズの USART 初期化修正：送信ピンを代替機能プッシュプル、受信ピンをプルアップ入力に変更し、従来の両ピンを通常出力に設定していた誤ったエイリアス実装を置き換え、E50x から F30x までの複数シリーズをカバーする。Rust ツールチェーンのチップターゲット検出は Cortex-M33 分岐を修正：従来は固定でソフトフロートターゲットを返していたため、ハードフロートのボードは誤ったライブラリを取得していたが、現在はハードフロート判定が M4/M7 分岐と一致するようになった。ほかに QEMU Linux クイックスタートガイドとドキュメント内の高リスクアンインストールコマンドの削除という2件のドキュメント修正がある。

日付：2026-09-21（検証時間）　出典：RT-Thread 公式ニュースインターフェース

3. エコシステムとベンダー適合

3.1 RT-Thread Studio の付随アップグレードがカーネル v5.3.0 に、J-Link デバッガが V9.76a に更新（09-20）

日付：2026-09-20 17:36 ~ 17:50（北京時間、統合時間）　情報源：SDK インデックスリポジトリ、カーネルソースコードリポジトリ

RT-Thread Studio の付随モジュールが同日に二つのアップグレードを完了した。第一に、SDK インデックスと内蔵カーネルソースコードリポジトリが同期して v5.3.0 に切り替わった。インデックス側はカーネルエントリを更新しバージョン統合を完了、ソース側は内蔵カーネルを新バージョンに更新し、ユーザーが開発ツール内で新規プロジェクト作成および SDK インストールを行う際に新カーネルが使用される。第二に、デバッガコンポーネントリポジトリが J-Link を V9.76a にアップグレードし、インデックスに対応エントリを追記した——前回のアップグレードは 2025 年 7 月の V8.48 であり、今回は年をまたいだバージョン追従となり、J-Link に依存する量産検証と工業デバッグ環境にとってより関連性が高い。v5.3.0 カーネルは 09-10 にリリースされ、Studio 側は 10 日後に追従を完了した。

3.2 STM32H7 デバイスサポートパッケージと HAL ドライバパッケージの同時リリース：v1.10.7 と v1.11.6（09-18）

日付：2026-09-18 12:58 ~ 12:59（北京時間、プッシュ時間）　情報源：CMSIS デバイスパッケージ、HAL ドライバパッケージ

STM32H7 シリーズの二つの基本サポートパッケージが調査期間内に同日新バージョンをリリースした。デバイスパッケージ v1.10.7 は TIM23 と TIM24 タイマインスタンス定義を補完し、GPIO モードレジスタビット定義の誤記とリンクスクリプトコメントのエンコーディングを修正し、一種のコンパイラ警告を条件付きで処理した。HAL ドライバパッケージ v1.11.6 は約二十筆の上流同期を一括で取り込み、USB ゼロ長パケット処理、イーサネット十メガ速率切替と受信タイムスタンプコンテキスト、SDMMC 超高速カードクロック上限、I2C トランザクションデッドロック、暗号ペリフェラル AES-GCM と CCM の非整語出力、FDCAN フィルタオーバーフロー防止、DMA コールバックトリガビット反転とスマートカード設定シーケンスなどをカバーしている。両パッケージはマイクロコントローラプロジェクト新規作成時の頻繁な依存であり、今回は歴史的ノードの補完と上流との整合を主とし、デバイスパッケージ側の最近のバージョン整合リズムを継続している。

3.3 英飛凌 PSoC6 評価ボード BSP が PWM/ADC 問題を修正、ルネサス RA8P1 が OpenMV リリースプロジェクトを新規追加（09-18 ~ 09-21）

日付：2026-09-18 ~ 2026-09-21（プッシュ時間）　出典：PSoC6 評価ボード BSP、RA8P1 Titan Mini BSP

Studio BSP 組織下の 2 つのベンダーボード級リポジトリに更新がある。独 Infineon の PSoC6 評価ボード BSP は、外部コントリビューターによって PWM と ADC マクロおよびドライバのプロジェクト横断修正がコミットされ、メインラインのレビュー中にある Infineon PWM マクロ不整合提案（#11802）と同源であり、当該ボードサポートパッケージの収束整理に属する。Renesas の RA8P1 Titan Mini は OpenMV リリースプロジェクトと継続的インテグレーション設定を新規追加し、この高性能 Cortex-M85 ボード向けにマシンビジョンアプリケーションのリリース経路を補完した。前号で収録したグラフィカル開発の動向と相互に接続する。

3.4 GD32 下流リポジトリがドライバ更新提案をコミット、界面ライブラリ AWTK も継続コミット（09-18 ~ 09-20）

日付：2026-09-18 ~ 2026-09-20（プッシュ時間）　出典：GD32 下流リポジトリ PR #71、AWTK リポジトリ

兆易創新側の下流ボード級リポジトリは、調査期間内に包括的なドライバ更新提案を 1 件コミットした（09-20 コミット、依然レビュー中）。このリポジトリのここ 1 か月のボードサポート補完ペースを継続している。そのメインブランチの最新コミットもドライバ更新系の変更であり、ベンダー側の自主保守ブランチは安定した推進を維持している。汎用界面ツールキット AWTK（タグは RT-Thread エコシステム）は調査期間内に 3 件のコミットがあり、界面記述ファイルの読み込み、アニメーション処理、ドキュメント更新に関わり、いずれもツールキット自身の汎用改善に属するため、慣例どおり非専項エコシステムの参考として記録する。

4. 業界応用

4.1 コミュニティが RK3576 ボード上で異種 AMP ネットワークを動作させた：RT-Thread が 1 つの A53 を独占し独立送受信（09-21）

日付：2026-09-21 09:39（北京時間、更新時間）　出典：フォーラム長文 63207209b0514465

コミュニティは RK3576（NanoPi M5 ボード）の異種マルチコア実践長文を公開した。Linux から 1 つの A53 コアを切り離して RT-Thread に渡し、GMAC1 イーサネットコントローラを丸ごと RT-Thread 側に移設して、独立したネットワーク送受信（ping 疎通）を完成させた。著者はまず同一チップ上の Cortex-M0 コプロセッサ経路を否定し（アーキテクチャレベルのアクセス制御隔離により不適用）、次にアプリケーションコア方式において 3 つの根本原因を特定して修正した。すなわち、MDIO クロック周波数計算の誤り、PHY リファレンスクロック有効化タイミングの遅延、連続 ping によるヒープクラッシュである。チップベンダー SDK における当該型番の GMAC ハードウェア抽象化レイヤは空実装であり、移植項目を自ら補完する必要がある。記事には完全な再現手順と残存問題の説明が付されており、AMP シナリオにおけるリアルタイム側の独立ネットワーク接続とエッジゲートウェイ方向に直接の参考価値があり、コミュニティでは珍しい深度ある実践記録に属する。

5. 総括とトレンド観察

5.1 直近 3 日間のトレンド（09-18 ~ 09-21）

  • メインラインは週末静黙、月曜に集中的に収束：3 日間の調査期間内で 9 件のマージはすべて月曜午前に発生し、いずれも既存修正と整理（ネットワークスタック入力検証、SDIO 二重リーク、ボード級パッチ、ドキュメント）である。レビューキュー内のネットワークプロトコルスタックアップグレード、バスドライバ再構築などの比較的大きな提案は引き続き待機しており、調査期間内に新規提案の開設はなく、新規欠陥報告もない。
  • ツールチェーン付帯物が追随期に入る：v5.3.0 カーネルリリースから 10 日余り後、Studio の SDK インデックス、内蔵カーネルソース、デバッガビルドが同一調査期間内に追随し、製品リリース後の付帯物落地のリズムは安定している。年をまたいで未更新だった J-Link も併せて補完された。
  • デバイスパッケージはバージョン整合のリズムを維持：STM32H7 の 2 パッケージが同日リリースされ、内容は過去ノードの補完とアップストリーム同期が中心であり、今月のデバイス側の整理型更新を継続している。
  • コミュニティの深度あるコンテンツは産出を維持：RK3576 AMP ネットワーク長文は珍しいマルチコア異種実戦記録である。チュートリアル連載とコンテスト、アプリケーション系の旧スレッドは継続的メンテナンス状態にあり、コミュニティのコンテンツ産出は公式チャネルの静黙によって鈍化していない。
  • 公式発信は依然として新メディア側：公式ニュースインターフェースは更新停止 32 日目であり、今号の対外コンテンツは主に公衆号と業界メディアの形式で登場している（電子工程専輯 2 件：メディア視点の総説と工博覧会 Workshop 募集）。公式サイトのニュースページは依然として直接確認できない。

5.2 限界と重複排除の説明

  • 集約ソースの媒体・イベント項目2件（工博会 Workshop、「隠れたチャンピオン」報道）は原サイトへのアクセスが制限され、本文を取得できなかったため、項目の要点は集約タイトルと欄情報に基づいて記述し、詳細は原文に準ずる。
  • 重複排除の説明：Gino Pi 発売（09-15、09-17 に既収録、今期の商城稿は小幅更新のみ）、電賽 H 題オープンソース工程（09-18 に既収録）、体感マウスチュートリアル（09-12 初出時に既収録、今期は旧スレッドの更新）、UART チュートリアル2章と zephyr 討論スレッド（09-17、09-18 に既収録）はいずれも重複報道しない。旧スレッドの更新は付録の情報源表でのみ説明する。
  • フォーラム記事インターフェースの「更新時間」は初出時間より遅れる場合があり、今期の項目日付はインターフェースが返す更新時間を基準とする。
  • 今期は月曜日で、調査期間は過去3日間（週末をカバー）であり、項目の日付スパンが平日の調査期間より長くなるのは正常である。
