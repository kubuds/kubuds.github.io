1. カーネルとバージョン動向

1.1 Next RISC-V アーキテクチャ再構築提案、創業者によるマージ推進を獲得、提出者が夜通しリベース更新（09-29 ~ 09-30）

日付：2026-09-29 21:09（創業者コメント）~ 09-30 00:01（最新コミット）　出所：PR #10320

数ヶ月間保留されていたメインリポジトリの RISC-V アーキテクチャ再構築提案「Next RISC-V」（#10320、171 ファイル、+15018/-3490）が、期間内に明確な推進シグナルを迎えた：創業者 Bernard Xiong が 09-29 21:09 に「この PR、近期にマージできそうだね、同時にいくつかの riscv の soc でも、デバイスツリーを有効にしてみることを試みよう」とコメントし、メンテナと提出者のフォローアップを名指しした。その後、提出者 GuEe-GUI は提案を当日夜から翌日未明にかけて三度連続でリフレッシュ記録を発生させ（21:22、23:54、00:01、フォーマットとメモリ比較パイプラインもそれに伴い再実行）、最新 head コミット「Refactor the RISC-V architecture port」は 09-30 00:01 に現在のメインライン最新コミット dc8aaa73f の上に再リベースされた。方案の要点：ISA 管理インターフェース、RV32E/32I/64I 融合、CBOM によるキャッシュ処理、Sv32~Sv64 MMU と SVPBMT、M/S モード CSR 操作統合、SMP、AIA（APLIC/IMSIC）、CLIC、ACLINT/CLINT、PLIC、デバイスツリー（DM）サポート、T-HEAD ベンダーコード統合、qemu-virt64-riscv64 デバイスツリーポートと非 0 番コアからの起動など；計画リストは S モード RT-Thread、RT-Smart とデバイスツリーパスが検証完了済みであることを示し、その他の組み合わせ（M モード、MMU なしなどを含む）はなお推進中である。この提案は 2026-05 の提出以来、累計レビューコメント 74 条を獲得している。

1.2 カーネル calloc オーバーフロー修正提案がレビュー通過（09-29 ~ 09-30）

日付：2026-09-29 22:34（提出）~ 09-30 08:30（LGTM 獲得）　出所：PR #11848

貢献者 luchenxu73 がカーネル修正 #11848（単一コミット、3 ファイル、+57/-3）を提出：rt_calloc 割り当て時に count×size がオーバーフローするかチェックしておらず、超過時に結果がラップアラウンドし、割り当てとゼロクリアの不一致による範囲外リスクが存在する；修正方案は割り当てサイズを事前計算し超過時に割り当てを拒否するもので、変更は include/rtdef.h、src/kservice.c とメモリユニットテスト src/utest/mem_tc.c（新規ケース追加）をカバーし、検証プラットフォームは qemu-vexpress-a9。この提案は 09-30 午前 08:30 にコミュニティレビュー「LGTM」を通過し、期間内で最も早く推進された新規提案である。

1.3 三条のドライバと BSP 修正提案が集中提出：ofw ハッシュ範囲外、ESP32-C6 SPI、ESP32-C3 リンカスクリプト（09-29）

日付：2026-09-29 20:11 ~ 21:53　情報源：PR #11845、PR #11846、PR #11847

09-29 夜間の約1時間半の間に、コミュニティは集中して3件の修正提案をコミットした。いずれもテスト証拠が添付されており、まだレビュー待ちである。その一（#11845）はデバイスツリー（ofw）phandle ハッシュテーブルの範囲外アクセス修正：テーブル項目数の割り当てに範囲の差を使用しているが、検索インデックスは phandle と開始値の差で計算しているため、範囲上限にアクセスした際に範囲外となり、拡張時のクリア位置も開始値を減算していなかった。修正としてテーブル項目数に1を加え、拡張時には旧テーブルの末尾から新規領域をクリアするようにした。作者は GCC に AddressSanitizer/UBSan を併用して6つのユースケースの関数レベル検証を完了した（開始 phandle を1、5、128とし、別途上限128から256への拡張をテスト）。その二（#11846）は Espressif ESP32-C6 のオンデマンド SPI コンパイル：BSP_USING_SPI を選択後に IDF SPI master へ接続し、共有 ESP ドライバが転送バイト数を返さない問題やチップセレクトピンの値の取得問題を修正し、設定が空の場合に -RT_EINVAL を返すようにした（6ファイル、+466/-19）。その三（#11847）は ESP32-C3 リンクスクリプトの Windows パスにおけるワイルドカード修正：sections.ld で「/」で記述されたワイルドカードが Windows ターゲットパス内の riscv ディレクトリのオブジェクトファイルにマッチせず、ベクタジャンプの再配置が範囲超過を引き起こしていたため、「?」に変更して両方の区切り文字に対応させた。#11816 と同一箇所の修正であり、今回は最新メインラインに基づいて作り直し、Windows に GCC 11.2.0 を併用した scons ビルドが通過した。

4. 業界応用

4.1 マレーシア科学大学の卒業プロジェクト更新：RA8P1 + RT-Thread エッジ音響イベント検出ファームウェア検証（09-30）

日付：2026-09-30 05:49 ~ 05:50（コミット時間）　情報源：KhaiFaw/ai-acoustic-event-detection

topic:rt-thread エコシステム下のサードパーティプロジェクト「Acoustic event detection at the edge」（マレーシア理科大学メカトロニクス工学卒業設計）は、調査期間内に2件のコミットを連続して更新した。音響ファームウェアのビルドとモデル契約の照合、組込みモデルとファームウェア間の入力スケーリングの不一致の修正、およびソフトウェア検証記録の補足（16件のホストテストと1回の全 BSP ローカルビルドの通過、修正版ファームウェアはまだ実機書き込み評価を行っていない）。プロジェクトはルネサス RA8P1 Titan ボードをベースとする。RT-Thread がオペレーティングシステムフレームワークを提供し、ルネサス FSP がデバイスサポートを提供し、CMSIS-DSP が FFT を実装し、TensorFlow Lite Micro が INT8 CNN を実行する。MAX9814 マイクで 16000 点の音声を収集し、MFCC 特徴抽出を経て、エッジ側で乳児の泣き声、ガラス破損、警報/サイレン、ノック、ドアベル、背景の6種類の音を識別する。

5. まとめとトレンド観察

5.1 直近一日のトレンド（09-29 ~ 09-30）

  • RISC-V アーキテクチャラインに明確なマージシグナルが出現：創設者自らが #10320「近期合併」を推進し、コミッターは夜通し3回のリフレッシュを行い最新メインラインにリベースした。このリファクタリング（171ファイル）がマージされれば、RISC-V サポートのシステム的な世代交代となる。
  • カーネルメモリ安全修正が集中コミット：calloc オーバーフロー（#11848）はコミット翌日に LGTM を取得し、ofw ハッシュ境界外（#11845）などの修正はいずれも再現可能なテストを伴っている。修正の方向性は境界チェックとオーバーフローチェックに集中している。
  • Espressif 系 BSP がマージ後の調整段階に突入：C6 SPI（#11846）と C3 リンクスクリプト（#11847）は同一のコントリビューターが連続して推進し、09-28 の C6 BSP マージ、S3 BSP 提案と合わせて完全なシーケンスを形成している。
  • メインラインマージの空白と提案の滞留：master は 09-28 22:22 以降新規マージがなく、調査期間内の動きはすべて提案側に集中している。#10320 と #11848 の今後のマージ動作に注目することを推奨する。
  • 公式チャネルは平穏が継続：公式ニュースインターフェースの停止更新は第41日目に入った。フォーラム、アグリゲーションチャネルともに調査期間内の新規追加はない。

5.2 限界と重複排除の説明

  • 重複排除：#11844（ESP32-S3 BSP、09-29 に収録済み、調査期間内に更新なし）、#11834（vsnprintf 修正、09-25 に収録済み。調査期間内に 09-29 21:53 に一度改訂プッシュが完了したが、依然レビュー中）、#11816（更新なし）は重複報道しない。#11797、#11841、#11132 および複数のマージ済み旧提案は調査期間内に自動化された再チェック（フォーマットとメモリ比較ボット）のみがトリガーされ、実質的な進展はない。
  • 除外：topic:rt-thread でヒットした zlgopen/awtk（汎用 GUI ドキュメント類のコミット）と h120d-protocol（説明ファイルの更新、RT-Thread と実質的な関連なし）は収録しない。
  • 検証：Google News の中国語・英語の3日間の調査期間ともに新規の有効な報道はない。ヒットした業界年次大会のプロモーション内容と旧稿は収録しない。
