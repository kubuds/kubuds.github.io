1. カーネルとバージョン動向

1.1 ネットワークスタック安全修正：DHCP サーバオプション境界チェックがマージされ、#11323 クローズ（10-10）

日付：2026-10-10 17:20（マージ時間）　出所：PR #11858、Issue #11323

DHCP サーバオプション解析のバッファ境界チェック提案（#11858、単一ファイル +63/-33、二件のコミット——境界チェックと clang-format 整理）がメンテナによりメインラインへマージされ、欠陥票 #11323（オプション解析時にデータパケットバッファを越えて読み取る問題、セキュリティ研究者により報告）もこれに伴いクローズされた。修正はオプション解析前に境界検証を追加し、越境読み取り経路を解消する；本件は 10-08 に起票され、連休後のキュー消化を経てマージ位置に入り、調査期間内のネットワーク側で最初のセキュリティ系修正となった。

1.2 STM32 全系 BSP スタック 8 バイトアライメント修正がマージ（10-10）

日付：2026-10-10 17:20（マージ時間）　出所：PR #11841、Issue #7527

全系 STM32 BSP スタックアライメント修正がマージ（#11841、作者 avm1234567、110 ファイル +220/-220）：各 BSP リンカスクリプトとテンプレートの .stack セクションを ALIGN(4) から一律 ALIGN(8) に変更し、ARM AAPCS が公共関数境界でのスタックポインタアライメントに課す要求を満たす。修正は 2023 年 5 月に起票された欠陥票 #7527（全系 STM32 リンカスクリプト問題；本票は現在もオープン状態にあり、今回のマージに伴い自動クローズされていない）を引用している。

1.3 C++ グローバルコンストラクタ互換修正がマージ：cplusplus_system_init が .init_array を経由するよう補正（10-11）

日付：2026-10-11 16:11（マージ時間）　出典：PR #11856、Issue #11778

C++ ランタイム互換修正がマージ（#11856、作者 cms19859230182-lang、4 ファイル +60/-6）：新版 GCC は C++ グローバルコンストラクタを .init_array セグメントに配置するが、既存の初期化フローは ctors_start/ctors_end 区間のみを走査するため、当該セグメントを統合していない一部の BSP でコンストラクタが実行されない問題が発生していた。修正では __init_array_start/__init_array_end（弱シンボル宣言）も辿るようにし、すでに ctors 区間に含まれる重複エントリはスキップする。関連缺陷単 #11778（複数 BSP の C++ 自動構築サポート異常）はクローズ。

1.4 USB CDC VCOM リングバッファ別名缺陷修正がマージ、#11739 クローズ（10-11）

日付：2026-10-11 17:37（マージ時間）　出典：PR #11770、Issue #11739

USB CDC 仮想シリアル修正がマージ（#11770、作者 Finder16、単一ファイル +47/-6、2 コミット）：旧実装は内蔵リングバッファを直接 serial_rx に接続しており、Serial V2 はこのポインタをシリアル FIFO 構造として解釈していた——リングバッファがたまたま先頭メンバーであるため表面上は動作するが、rx_cpt、rx_timeout などのフィールドは実際にはずれていた。修正では正規の接続方式に改め、VCOM ポーリング受信サポートを追加。本案は 08-29 に起票され、複数回のレビューを経てメインラインにマージ、缺陷単 #11739 はクローズ。

1.5 utest パフォーマンステストのクロック依存修正がマージ（10-11）

日付：2026-10-11 15:59（マージ時間）　出典：PR #11813

テストフレームワーク修正がマージ（#11813、作者 CYFS3、2 ファイル +8/-1）：utest パフォーマンステストの固定クロック計時への依存を修正し、テストビルドガードを強化して、異なるボードレベルとシミュレーション環境での誤検出を低減。

1.6 RISC-V ベクトル：vstart 復元順序修正提案がレビュー入り（10-10 ~ 10-11）

日付：2026-10-10 13:37 ~ 10-11 17:15（作成と更新）　出典：PR #11861、Issue #11786

RISC-V ベクトルコンテキスト修正提案がレビュー入り（#11861、作者 PiyushPatle26、4 ファイル +187/-5）：RESTORE_VECTOR は従来 vsetvl の前に vstart を復元していたが、ベクトル構成命令がこれをクリアしてしまい再開インデックスが失われる。修正では復元動作を構成命令の後に移動し、qemu-virt64-riscv にゼロ/非ゼロ vstart と vl、vtype、vcsr をカバーする回帰ケース（アセンブリプローブ + C ケース）を追加。メンテナは 10-11 のレビューで修法が正しいことを確認し、まずテスト並行性問題の解決と検証証拠の追加を提案、作者は当日修正コミットをプッシュ済み。同作者が推進する OSPP 2026 議題「RISC-V 遅延 FP/RVV コンテキストスイッチ」（#11786）も期間内に実装計画を同期更新。

1.7 netdev ping 統計ゼロ除算缺陷が認領、修正提案が新規起票（10-11）

日付：2026-10-11 22:10 ~ 23:05（認領と提案時間）　出典：Issue #11852、PR #11862、PR #11853

netdev ping 缺陷の修正経緯は期間内に明らかに前進：缺陷単 #11852（10-05 報告；ターゲット到達不能時に received が 0 となり、平均値除算が x86 SIGFPE / Cortex-M ゼロ除算を触发、shell スレッドを杀死）は 10-11 夜に貢献者 ymj0440 がコメントで認領、直ちに提案 #11862（単一ファイル +1/-1）を起票；これに先立ち同類提案 #11853（作者 r3wretrhy、10-06 起票）は 10-07 にレビュー通過（LGTM）したがまだマージされていない。両案が並行しており、メンテナがいずれかを選択するのを待つ。

4.1 コミュニティ研究プロジェクト：K230 + RT-Thread Smart 厨房火災検知プロトタイプが引き継ぎ文書を更新（10-11）

日付：2026-10-11 18:57（プッシュ時間）　出典：1nuoiscute/SRTP-K230-Fire-Guardian

コミュニティ研究プロジェクト「SRTP K230 Fire Guardian」が引き継ぎ文書を更新：プロジェクトは厨房シーン向けの大学生研究プロトタイプ——K230 が視覚ノード（火炎目標検知）を担当、RT-Thread Smart がボード端制御、マルチセンサ融合と適応連動を担当。今回のコミットはデフォルトブランチ入口を完全な開発記録ブランチへ指向させ、ボード端ベースラインと検収状態を総括：視覚ノードと KEY2 コントローラのボード端身元は検収記録あり、KEY1 パネルカバレッジと長時間安定性は未解決のまま、ボード端選区（ROI）機能は未実装；プロジェクトは研究ペースに従い中間記録を継続公開。
