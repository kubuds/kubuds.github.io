1. カーネルとバージョン動向

1.1 メインリポジトリの調査期間内に 4 件の PR をマージ：MPU 権限修復、PWM utest、ルネサス CAN FD、net/sal リソース解放

日付：2026-09-01（09:05-09:39 北京時間にマージ）　出典：PR #11760、PR #11751、PR #11754、PR #11769

昨日の RT-Smart POSIX 互換バッチ（PR #11732/#11733、13 コミット）に続き、メインリポジトリは今朝さらに 4 件の PR（ほかに clang-format style コミット 1 件を含む）をマージし、平日のマージペースが回復した：

  • PR #11760（09:05）[net][sal]：ソケット作成失敗時に DFS v2 vnode が解放されない問題を修復、リソースリーク修復に属する；
  • PR #11751（09:16）[bsp/renesas][drivers]：ルネサス BSP ドライバが設定可能な CAN FD 操作をサポート、ペリフェラル機能が引き続き進化；
  • PR #11754（09:33）[utest][pwm]：設定可能な PWM matrix テストを新規追加し、マトリクステストのクリーンアップとタイムアウト問題を修復；
  • PR #11769（09:39）fix[arm][cortex-m4]：MPU 権限式を明確化、cortex-M4 カーネル MPU 権限設定の記述を修正。

前日の RT-Smart POSIX 互換層向けの大量マージとは異なり、本バッチはカーネル細部の堅牢性に集中している：ARM cortex-M4 MPU 権限、ネットワークソケット失敗パスのリソース解放、ドライバの設定可能化とテストカバレッジであり、大きな機能のマージは見られない。

2. 公式・コミュニティ動向

2.1 公式ニュース API は連続 12 日間新規追加なし、メディア側も調査期間内に新規項目ゼロ

日付：2026-09-01　出典：RT-Thread 公式ニュース API

公式ニュース API（rt_org カテゴリ）は依然として 5 件の旧項目で、最新は依然として 2026-06-17 のアブダビ投資フォーラム報道であり、連続 12 日間新規追加なし。gnews の複数グループ追加調査（RT-Thread when:3d、RT-Thread 睿赛德 when:3d、睿擎派 OR 睿擎 when:3d）：英語クエリは SCALR AI など “RT” の語分割ノイズのみヒット；中国語クエリは昨日すでに収録済みの elexcon 2026 出展予告（電子工程専輯 08-30 掲載）がヒット；睿擎クエリは空。メディア側は調査期間内に新規項目ゼロであり、最近の唯一の対外シグナルは依然として 9 月 9-11 日の深圳 elexcon 2026 出展（RT-Thread 睿賽德が AI ハードウェア「フルセット」を出展予定）。

3. エコシステムとベンダー適合

3.1 packages：optparse に v1.0.0 / v1.0.1 のバージョン項目を追加、新旧インターフェースが併存可能

日付：2026-08-31（16:55 マージ）　ソース：RT-Thread/packages PR #2032

昨日 packages は optparse ソフトウェアパッケージに v1.0.0 バージョンエントリを復元し、破壊的インターフェース変更をロールバックした（v1.0.0 は 2 引数インターフェース）。本日 PR #2032 はさらに v1.0.1 バージョンエントリを補充した。両 tag はいずれも 3 引数インターフェースのコミット（07a365d）を指し、v1.0.0 の 2 引数インターフェースと区別され、ユーザーはインターフェース要件に応じてパッケージインデックス内で対応バージョンを選択できる。インデックス層におけるインターフェース互換の管理は「二バージョン併存」段階に入った。

3.2 エコシステム参考：canopennode-rtt コミュニティ CANopenNode 統合パッケージの継続開発

日付：2026-08-31 ~ 09-01　ソース：github.com/wdfk-prog/canopennode-rtt（ドキュメントサイト wdfk-prog.space/canopennode-rtt/ 付き）

コミュニティリポジトリ（2026-06-30 作成、C 言語）は、RT-Thread への国際的に著名なオープンソース CANopen プロトコルスタック CANopenNode の統合を目的としており、最近的提交が活発である。イベント駆動メインラインスケジューリングの追加（09-01 08:54）、高分解能時間サポートと kconfig 実行設定メニューの整理、デフォルトオブジェクトディクショナリと demo モジュールの分離（08-31）、RX ルールを粗粒度 HDR フィルタへコンパイル（08-30）、SRDO による J09/B09S オブジェクトディクショナリおよび MCU 診断 fixture の生成（08-29）。本パッケージは現在公式 packages インデックスから独立している（PR 提出は未見）。今後の公式ソフトウェアパッケージ体系への参入に注目する。産業／車載 CANopen 通信シーンは留意に値する。

3.3 エコシステム参考：兆易創新 gd32_rt-thread が F503 ペリフェラルドライバと F207i BSP アップグレードをマージ

日付：2026-08-31（19:17 / 19:31 マージ）　ソース：GD32-MCU-IOT/gd32_rt-thread PR #58、PR #63

GigaDevice 公式ダウンストリームリポジトリ（gd32_rt-thread）は調査期間内に、原廠エンジニアによって 2 件の BSP 対応がマージされた。PR #58 は gd32f503v-eval に USART / I2C / SPI / DMA ドライバを追加。PR #63 は gd32207i-eval BSP をアップグレードし、F20x シリーズドライバに対応。チップ原廠主導の BSP カバレッジは引き続き拡大している（直近二週間で 305R/407V/470Z/470i/L23x/F527 など複数モデル関連の対応が連続してマージ済み）。

4. 業界応用

調査期間内に新規エントリなし。直近三日の趨勢はまとめを参照。

5. まとめと趨勢観察

  • カーネル側：メインリポジトリの平日マージペースが回復。本バッチは堅牢性修復が主体（cortex-M4 MPU 権限、net/sal ソケット失敗パスの vnode 解放、PWM utest マトリクステスト）。ルネサス BSP の CAN FD 設定可能化はペリフェラル進化を継続。
  • エコシステム側：パッケージインデックスにおける optparse 新旧インターフェース二バージョン併存管理が実現。GD32 原廠は BSP 対応を継続。コミュニティ CANopenNode 統合パッケージ（canopennode-rtt）の開発が活発で、産業通信方向は追跡に値する。
  • 公式側：公式メディアは連続 12 日間沈黙。次の対外ウィンドウは 9 月 9-11 日の深圳 elexcon 2026。
  • 直近三日の趨勢（08-30 ~ 09-01）：RT-Smart POSIX 互換バッチのマージ（08-30）→ ENV WebUI の TypeScript 化と修復、agent 音声フレームワーク（08-31）→ カーネル堅牢性修復バッチ（09-01）。メインラインは RT-Smart 互換層の完善 + 公式ツールチェーンの現代化 + カーネル細部の研磨。ニュース量の少ない日は GitHub リポジトリの動態が主体。
