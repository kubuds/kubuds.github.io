1. カーネルとバージョン動向

1.1 小華半導体 HC32 シリーズ BSP 設定同期がメインラインにマージ（09-16）

日付：2026-09-16 17:54（北京時間、マージ時間）　出典：PR #11798

小華半導体 HC32 シリーズの設定同期提案が期間内にメインラインへマージされた。規模は 52 ファイル、新規約 2844 行、削除 720 行。4 つのコミットがそれぞれシリーズ設定同期とプロジェクトファイル再生成、コードフォーマット、ヘッダファイル形式整理とシリアル割り込みドライバのコンパイルエラー修正、rtconfig のロールバックとフォーマット無視リストの調整を完了した。具体的な変更には、電源管理設定におけるウェイクアップタイマー有効化マスクの削除、名称長上限を 24 に調整しカーネル名称長設定項目を同期することが含まれる。本提案は 09-11 に審査提出、09-14 に最終改訂を完了し、レビューからマージまで約5日。HC32 シリーズは直近1週間でドライバ拡張と設定同期の2批の変更が既に着地している。

1.2 STM32 GCC リンカスクリプト容量検証修正がマージ、容量超過ファームウェア問題をクローズ（09-17）

日付：2026-09-17 09:31（北京時間、マージ時間）　出典：PR #11805、Issue #11124

STM32 各領域のリンカスクリプトの容量検証欠陥が期間内に修正完了しマージされた。変更は 110 のリンカスクリプトをカバーし、新規と削除が各約 659 行。問題の根本原因は、一部のスクリプトが初期化データセグメントでロードアドレスを指定しているが、当該セグメントを対応する読み取り専用ストレージ領域に関連付けていなかったこと。これによりコードと定数自体は上限を超えず、初期化データイメージを重ねた後に初めて超過する場合でも、リンクが通過し設定容量を超えるファームウェアが生成されていた。修正は STMicroelectronics 公式リンカスクリプトの記述を参照し領域帰属を補完した。同源の欠陥報告は今年1月の提出以来ずっと未クローズ状態であり、今回の修正とともにクローズされた。

1.3 SDIO ドライバ登録解除のメモリリーク修正提案を提出、前期の欠陥報告を引き継ぐ（09-17）

日付：2026-09-17 10:01（北京時間、提出時間）　出典：PR #11806

前期レポートに記録された SDIO ドライバ登録解除の欠陥に修正提案が届いた。変更は 1 ファイル、新規 6 行、削除 4 行。元のロジックは一致する SDIO カードが見つかった場合のみドライバ登録ノードを解放し、デバイスにカードがないかカードが一致しない場合はノードを解放しなかったため、登録と解除を繰り返すとメモリリークが発生していた。修正案は、登録解除対象のドライバを確定した後、現在一致するカードが存在するかどうかに関わらずドライバ連結リストからノードを削除して解放し、カードに一致した場合のみドライバの削除コールバックを継続して呼び出し、既存のデバイスアンバインドフローを変更しないというもの。欠陥報告から修正提案まで約2日で、対応のテンポはやや速い。

1.4 三件の小規模修正がレビュー入り：UART4 受信 DMA、ブロックデバイスログ形式、継続的インテグレーション依存（09-17）

日付：2026-09-17 10:38 ~ 11:50（北京時間、コミット時間）　情報源：PR #11808、PR #11809、PR #11807

調査期間の末尾に、日常的な修正が3件レビュー入りした。1件目は STM32H7 汎用 DMA 設定に UART4 受信側の定義を補完するもので、インスタンス、リクエスト、割り込み、クロックマクロを含む。これ以前は UART4 受信 DMA を有効にするとコンパイルに失敗していた。2件目はブロックデバイスパーティションコンポーネントのログフォーマット指定子とパラメータ型の不一致を修正するもので、一部の32ビットツールチェーンでは符号なし整型が長整型に対応し、短整型フォーマット指定子を用いるとフォーマット警告が発生していた。変更は出力文のみでパーティション検出ロジックには触れていない。3件目は LLVM ARM 継続的インテグレーションフローにターミナル情報ライブラリの依存関係を追加インストールし、このパイプラインの最近のビルド失敗を修正するものである。

1.5 lwip 2.2.1 プロトコルスタックサポート提案、調査期間内で反復継続（09-16）

日付：2026-09-16 18:39（北京時間、最終更新）　情報源：PR #11797

ネットワークプロトコルスタックのバージョン推進提案が調査期間内に再び更新され、規模は依然として1874ファイル、約34.6万行追加、45行削除、ディスカッション数は4件に増加した。この提案は既存の課題を修正し、lwip 2.2.1 サポートを導入するもので、検証プラットフォームは NXP i.MX RT1180 評価ボードで、イーサネット、ソケット抽象化レイヤ、ネットワークデバイス、lwip コンポーネントを有効化している。レビューラベルはコンポーネントで、以前にサードパーティのメモリ比較ツールがメモリ使用量の変化を導入していないと判定した。マージされれば、メインラインのネットワークスタックベースラインは 2.1.x から 2.2.x に進むことになり、ゲートウェイや産業連網シーンで常用される経路であるが、現在もレビュー反復期間中である。

2.3 コミュニティフォーラムに技術記事2件を追加：リポジトリ階層管理と MQTT 大スループット接続リーク（09-17）

日付：2026-09-17 09:01 / 09:20（北京時間、公開時間）　情報源：フォーラム記事 64254b1144ae4465、フォーラム記事 46bb8d1c8740c2e5

コミュニティフォーラムの記事インターフェースが復旧した後、本期は当日の技術記事を2本収録した。1本目はサブモジュールとスパースチェックアウトでファームウェアリポジトリを管理する方法を述べ、カーネル、ベンダーライブラリ、ボードレベル対応、業務コードのバージョン境界、ワークスペース境界、ビルド境界を分離し、独立したライフサイクルとリリースリズムを持つ公共モジュールのみをサブモジュールに分割する価値があると主張している。2本目は実機の不具合分析である。デバイスは毎秒5〜10キロバイトの並行スループット下で完全にオフラインになり、サーバー側が受信ウィンドウを絞り終了メッセージを送信する際に、ソケットのクローズが進行中エラーを返すが、抽象層と上位コンポーネントは依然として成功として処理しハンドルを解放し、最終的に下位ソケットが到達不能となり、ヒープメモリがキロバイト級まで低下すると特定された。著者は既存の送信ロックでクローズ呼び出しをラップして回避し、30ラウンドの回帰後にリソースはベースラインに戻った。両記事ともコミュニティの自発的生産であり、長期運行デバイスにとって参考価値がある。

3. エコシステムとベンダー対応

3.1 Gino Pi BSP SDK に JLink デバッグ経路を追加、50のプロジェクトを一括補完（09-16）

日付：2026-09-16 18:27 / 18:33（北京時間、コミット時間）　情報源：Studio BSP SDK リポジトリ

Gino Pi ボードの Studio BSP SDK は調査期間内に JLink デバッグサポートを追加し、2件のコミットで合計50ファイル、約2281行を追加、20行を削除した。方法は各サンプルプロジェクトに JLink デバッグ起動設定とデバッガ設定ファイルを生成し、中国語と英語の説明およびプロジェクトガイド文書を同時に更新するというものである。これまでこの SDK のダウンロードとデバッグ経路は Studio 側の DAP-Link と MDK 側の CMSIS-DAP の2つのみであったが、今回3番目のデバッガを補完し、JLink を使用する産業・量産検証チームにとってより使いやすくなった。この SDK はカーネル 5.3.0 をベースとし、16のペリフェラルおよびアプリケーションサンプルプロジェクトを含み、ボードの核心は GD32H77D であり、高性能グラフィックインタラクションとネットワーク評価の位置づけに属する。

3.2 睿擎プラットフォームが Gino Pi を初対応：GD32H77D 開発ボードの全チェーンが開箱即用（09-16）

日付：2026-09-16 11:50（北京時間、リリース時間）　情報源：電子工程専輯 集約項目

集約ソースの項目によると、睿擎プラットフォームが Gino Pi 開発ボードを初対応し、GD32H77D プラットフォームの全チェーンが開箱即用であることを強調している。睿擎プラットフォームの従来のボード承載は瑞芯微 RK3506 と RK3562 の2ラインであり、今回マイクロコントローラ級の高性能グラフィックプラットフォームへ延伸し、その産業制御とエッジインタラクションの位置づけと互補する。付属のボードサポートパッケージとサンプルプロジェクトは既に Studio 側に整い、デバッグ経路も同一調査期間内に JLink を補完した。原文ページはサイト側のアクセス制限により取得できず、対応範囲と機能リストは集約要約と SDK リポジトリの公開資料でクロス説明する。
