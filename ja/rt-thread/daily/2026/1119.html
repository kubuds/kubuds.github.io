1. デバイス層：コマンド空間の再区分

1.1 2021年のイシュー、エンコーディング変更で決着（11-18）

日付：2026-11-18 09:11（マージ）。出典：#11881。

イシュー #5073 は2021年9月17日に提起された。タイトルにはシリアルポートが POSIX インターフェースの ioctl で下位パラメータを設定できず、下位の config が呼ばれないとあり、原因は「マクロ定義の値が 3」にあるとされている。イシューは現在もオープンのまま。

提案 #11881 は2026年10月17日に提出された。11月18日午前9時11分、Rbb666 がマージした。報告からマージまで5年2ヶ月、提案からマージまで32日。

コミット番号 629a7970。規模は14ファイル、80行追加、57行削除。方向性は特定ドライバへのパッチではなく、デバイス制御コマンドの番号付け方式を全体的に置き換えるもの。

1.2 衝突箇所：fcntl の 1 から 4 とデバイスコマンドが同値（11-18）

日付：2026-11-18（提案本文）。出典：#5073。

提案本文は衝突を表にまとめている。POSIX 側では F_GETFD、F_SETFD、F_GETFL、F_SETFL がそれぞれ 1、2、3、4。旧定義では RT_DEVICE_CTRL_RESUME、SUSPEND、CONFIG、CLOSE が 0x01、0x02、0x03、0x04。

両コマンド体系は int 引数を1つ共用する。F_GETFL と CONFIG が 3 で衝突し、F_SETFL と CLOSE が 4 で衝突する。

経路も明記されている。fcntl は dfs_file_ioctl、dfs_file_fcntl を経て fops->ioctl に至る。ドライバが数値でマッチングすると、F_GETFL を CONFIG として処理してしまう。これがまさにイシュー #5073 の「パラメータを設定できない」の機械的な原因である。

新エンコーディングではデバイスクラスを上位バイトに移す。
基底マクロは RT_DEVICE_CTRL_BASE(Type)。クラス番号に1を加え、0x100 を乗じて計算し、上位バイトにクラス番号、下位バイトにクラス内インデックスを置く。

9つの汎用コマンドは BASE(Unknown) + 1..9 に変更され、実際には 0x2001 から 0x2009 に配置される。これは POSIX の 0 から 4 と完全にずれる。

旧 RT_DEVICE_CTRL_MASK = 0x1f は下位5ビットのみを見るため、新エンコーディングと互換性がない。作者は全リポジトリを grep し、呼び出し元がないことを確認して直接削除。RT_DEVICE_CTRL_CLASS_MASK = 0xff00 と RT_DEVICE_CTRL_INDEX_MASK = 0x00ff に置き換えた。

一点留意すべき詳細がある。提案の「検証した bsp と config」の欄は空で、.config と action リンクも記入されていない。

1.3 14ファイルが連動して変更、BSP と rt-link を包括（11-18）

日付：2026-11-18（コミット変更面）。ソース：629a7970。

変更に追随したファイルのうち、八つは efm32 ボード級ドライバである。acmp、adc、ethernet、iic、leuart、sdcard、timer、usart、それぞれがコマンド値を三から四行変更している。hk32f030c8-mini の rtconfig.py は一行動いた。

ヘッダファイル側の変更はより集中的である。
dev_pin.h では PIN_CONFIG_BIAS_BUS_HOLD が元々列挙の先頭項目で値は 0 だったが、
現在は RT_DEVICE_CTRL_BASE(Pin) + 1 に変更されている。

dev_serial_v2.h は RT_HW_SERIAL_CTRL_GETC、PUTC、GET_DMA_PING_BUF の三つの生マクロを列挙に置き換えた。値は RT_DEVICE_CTRL_BASE(Char) + 0x40 から始まり、0x40 から 0x4f はハードウェアシリアル制御用に留保すると注記されている。

rt-link の二つのファイルも追随して変更された。include/rtdef.h が最大の箇所で、34 行追加、16 行削除。バージョンコメントに一行追加：2026-11-07、CXSforHPU、class-encode RT_DEVICE_CTRL_* commands。

判断：九つの汎用コマンドが 0x01 から 0x09 へ、0x2001 から 0x2009 へ移動した。リポジトリ外の BSP やソフトウェアパッケージが旧値をハードコードしている場合、アップグレード後に誤った分岐に進む。根拠は、コミットがリポジトリ内の 14 ファイルのみを同期し、互換マクロを残しておらず、BSP 検証の欄が空であることである。

2. テストと CI の收束

2.1 memheap 用例が MEMHEAP のない BSP でサイレントに破棄される（11-18）

日付：2026-11-18 17:29（マージ）。ソース：#12066。

コミット説明に因果連鎖が明記されている。RT_UTEST_MEMHEAP は RT_USING_MEMHEAP に依存する。mem.cfg はこの項目を選択していない。そのため memheap のグループ用例は、この設定を持たない BSP ではコンパイルに含まれない。旧 mem.conf は元々選択されていた。

修正は .github/utest/configs/kernel/mem.cfg に二行を補うものである。提案 #12066 は当日未明 3 時 13 分に提出され、17 時 29 分にマージ、間隔は 14 時間。

この種の欠落はビルドを失敗させず、テストを赤にもしない。レポート上は通過と表示され、破棄された用例は統計に現れない。

2.2 utest ドキュメントにおける混在したパス区切り文字（11-18）

日付：2026-11-18 10:01（マージ）。ソース：ebd32d7a。

components/utilities/utest/README.md が二行変更され、混在したパス区切り文字が統一された。作者は sexenteen、11 月 16 日に作成、11 月 18 日午前にマージ。ドキュメント級の変更で、動作には影響しない。

2.3 未明に三件、当日に一件成立（11-18）

日付：2026-11-18（提案状態）。ソース：#12064。

昨日列挙した未明の三件の提案は、本日それぞれ異なる去向となった。#12066 はマージ済み。#12064 と #12065 はなおオープン状態で、最終更新はそれぞれ 19 時 08 分と 20 時 25 分。

三件はいずれも parthitce によるものである。#12065 の本文にはテスト環境が明記されている：RH850 qemu-rh850-u2c の kernel_basic。-O2 下でスタック破壊により rt_memmove がクラッシュするが、修正後は 22 項目の用例がすべて通過する。

用例自体の欠陥は、11 バイトで 6 バイトのソースと 10 バイトのターゲットの二つの配列を読み書きしていたことである。

3. ソフトウェアパッケージとエコシステム

3.1 AI Agent パッケージに A2A チャネルと階層型メモリを追加（11-18）

日付：2026-11-18 09:45（コミット）。ソース：6595550d。

ソフトウェアパッケージインデックスリポジトリにコミットが届き、ai/Agent/Kconfig のみを変更、378 行追加、212 行削除。コミット説明には三つの事柄が書かれている。

一つは a2a channel サポートの追加。二つ目は階層型メモリのスイッチ、容量、永続化オプションの補完。三つ目はディスク書き込みをオンにした際に DFS と 4.1 以上の POSIX ファイルインターフェースを自動選択し、ユーザーがコンポーネントを補う必要をなくすこと。

パッケージ本体 ai/Agent の自己記述は「rtthread 軽量級 Agent ソフトウェアパッケージ」である。キーワードは ai、Agent、llm、toolcall。リポジトリは作者自身の CXSforHPU/Agent を指し、cJSON、webclient、mbedTLS、ulog に依存する。

これは二日以内にこのメニューを二度目に動かすことになる。11 月 16 日 11 時 22 分に #2050「Agent 設定項目を補完し、用途別にメニューを再配置」がマージされており、変更対象もこの Kconfig だった。作者 CXSforHPU は本日、メインリポジトリに 1.1 のコマンドエンコーディングのコミットもマージしている。

5.1 RH850 移植が1週間で52ファイルに拡大（11-18）

Renesas RH850 G4KH 移植と qemu-rh850-u2c ボードパッケージは11月6日に提出された。昨日は48ファイル、新規3921行だった。本日は52ファイル、新規4122行となり、1日で4ファイル、201行が追加された。

内容は3ブロックに分かれる。libcpu/rh850 は TRAP0 でスレッド切り替えを行い、ネスト割り込み、FPU コンテキスト、フォールトダンプを含む。bsp/renesas/rh850 にはスタートアップコード、INTC、OSTM、RLIN3 シリアルがあり、シリアルは serial V1 のみ対応。CI はハードフロートとソフトフロートの2種類のビルドに、QEMU 上の kernel utest を加え、ツールチェーンと QEMU パッケージは展開前に SHA-256 で検証する。

作者が提示した実測環境はツールチェーン v1.2.0（GCC 14.3、picolibc）と qemu-rh850 v1.2.0。

6. まとめとトレンド観察

6.1 本日の重みは1件の提案に集中

調査期間内の3コミットは、合計16ファイル、新規84行、削除59行。うち 629a7970 の1件が14ファイル、新規80、削除57を占める。残り2件はそれぞれ1ファイル、各2行のみ。

判断：本日はパッチの積み重ねではなく、デバイスコマンド空間の再区分である。根拠は変更が include/rtdef.h と4つのデバイスヘッダファイルに集中しており、BSP 側は数値の追従変更のみでロジックの変化がないことである。

6.2 静かな破棄はテスト側で最も発見しにくい欠落

memheap のそのテスト群はコンパイル失敗ではなく、そもそもコンパイルに含まれていない。ビルドは通り、テストも通る。レポート上は異常が見えない。

判断：この種の問題は設定の対照によってのみ発見でき、テスト実行では発見できない。根拠はコミット説明に明記されたメカニズムである。RT_UTEST_MEMHEAP は RT_USING_MEMHEAP に依存し、mem.cfg が未選択の場合はテスト群全体がスキップされるが、旧 mem.conf は選択されていた。

6.3 コマンド数値の移動後、リポジトリ外のコードは自身で確認する必要がある

判断：9つの汎用コマンドが 0x01 から 0x09 へ、0x2001 から 0x2009 へ移動した。リポジトリ外の BSP やソフトウェアパッケージが旧値をコードに書き込んでいると、アップグレード後に誤った分岐に入る。根拠は、コミットがリポジトリ内の 14 ファイルのみを同期しており、互換マクロを残しておらず、検証 BSP 欄が空であることだ。

6.4 AI Agent パッケージの2回目の変更

11月16日にメニューを再編成し、11月18日に A2A チャネルと階層型メモリを追加した。いずれも Kconfig のみを変更している。

判断：このパッケージの設定面は「プロトコル接続 + メモリ管理」へ拡大しており、もはや単なる機能スイッチではない。根拠は、2回目のコミットで a2a channel とメモリ容量、永続化オプションが新たに追加されたのに対し、1回目は用途別にメニューを再編成しただけであることだ。
