1. カーネルとバージョン動向

1.1 K230D マージ：128MB DDR バリアントが ext4 と ptyfs に対応（11-06）

日付：2026-11-06 09:37（マージ時刻）　出典：提案 #11897、提案 #11892

15ファイル、398行追加、198行削除。メンテナの BernardXiong が提出し、10月18日に作成、今期マージされた。内容は BSP の完全な補完である：SOC_K230 と SOC_K230D の二者択一を新設し、128MB DDR に合わせてデフォルトのメモリレイアウトを再配置；GPIO を RT-Thread の pin デバイスとして登録し、ドライバに一気に140行を追加、さらに GPIO テストを補完；ext4 ルートファイルシステムを有効化し、ptyfs と procfs をマウント；使用されていないボードレベル周辺機器定義の一群を削除。ツールチェーンは K230 SDK の riscv64-unknown-linux-musl を維持し、ABI は依然 lp64d。

この件の重みは依存関係にある：まず #11892 の RISC-V MMU と玄鉄アーキテクチャ修正（前回レポート 1.2 の件）が必要で、さらに lwext4 ソフトウェアパッケージも必要；ptyfs と procfs のマウントポイントはまさに RT-Smart ターミナルとデバイスツリーエクスポートの前提である。つまり、K230D は孤立してボードを1枚追加するのではなく、11-05 の Smart 修正群を128MB メモリの実 RISC-V ボード上でつなぎ合わせるものだ。CI はまだビルド結論を出しておらず、作者はローカルで K230 SDK ツールチェーンによるコンパイルのみ行っている。

1.2 STM32F1/H7 入力キャプチャ実装：746行で4系統タイマを補完（11-06）

日付：2026-11-06 09:20（マージ時間）　ソース：提案 #11975、議題 #11967

9 ファイル、746 行追加、削除ゼロ。議題は 11 月 2 日に提出され、それ以前はフォーラムに個人実装が 1 つあるだけで、4 日後にドライバがメインラインに進入した。実装は STM32 HAL の TIM1 から TIM4 を入力キャプチャデバイスとして使い、チャネル、フィルタ、初期キャプチャ極性が設定可能である。APB タイマクロックの逓倍、TIMPRE と 32 ビットカウンタの 3 か所のプラットフォーム差異を処理し、キャプチャチャネルを再起動する前に保留中のキャプチャフラグとオーバーキャプチャフラグをクリアする。

CI は 2 つのボードで実行された。STM32F103 戦艦版は inputcapture の断片を実行し、STM32H743 Nucleo は完全な設定を実行した。利用者にとって、この種のペリフェラルフレームワークの補完はカーネルの欠陥修正よりも適用範囲を広げられる。入力キャプチャはモータ制御、エンコーダ、パルス測定の常用経路である。

1.3 非 SMART の CPU 時間会計の補正（11-07）

日付：2026-11-07 21:39（マージ時間）　ソース：提案 #12001

src/clock.c の 2 行のみを変更し、ユーザー態時間会計の分岐を RT_USING_SMART で囲んだ。従来は非 SMART ビルドでもこのロジックを通り、スレッド時間がユーザー態に算入され、システム時間とアイドル時間の統計がそれに伴って過小になった。2 行の変更が、すべての非 Smart プロジェクトの CPU 使用率の読み取りに影響する。

1.4 GIC プリント関数の書式指定子の修正（11-08）

日付：2026-11-08 16:20（マージ時間）　ソース：提案 #11914

3 ファイル、71 行追加、48 行削除で、gic.c、gicv3.c、gicv3.h を変更した。4 種類の問題：32 ビット物理アドレスを %p でプリントし、%p に非ポインタを渡すのは未定義動作である；符号なし量を %d でプリントしている；GIC バージョン番号の型変換が欠落している；GIC RWP マクロ内の 1 か所の符号付き左シフト。提案は 10 月 21 日に作成され、11 月 8 日にマージされた。作者は Wei-beep、共同作者はメンテナの Rbb666。-Wall -Wformat で Cortex-A BSP をビルドする際に警告が出力されなくなった。この種のクリーンアップは機能に影響しないが、ベンダー BSP のビルドのクリーン度に直接影響する。

2. セキュリティと libc の修正

2.1 timerfd の 2 か所の検証が同日にマージ（11-08）

日付：2026-11-08 14:12 / 14:11（マージ時間）　ソース：提案 #11996、欠陥 #11984、提案 #11997、欠陥 #11980

2 件が 1 分差でマージされ、それぞれ 1 ファイルを変更した。

1 件目は timerfd_settime と gettime の fd 型検証である：元の実装は任意のファイル記述子のプライベートデータをタイマ構造体としてデリファレンスしていたため、通常のファイルやパイプを渡すとカーネルが誤った型で構造体を読むことになる。修正はまずファイル操作テーブルを比較し、timerfd であることを確認してからプライベートデータを取得する。DFS v2 は df->fops、v1 は vnode->fops を見る。25 行追加。

2 件目は POSIX タイマの配列境界外アクセスである：timer_gettime と timer_settime はユーザーが与えた timer_t をそのまま添字として _g_timerid をインデックスしていたが、timer_delete には以前から境界チェックがあった。id が TIMER_ID_MAX 以上であってはならないという判定を追加し、19 行追加。

これら 2 か所の欠陥は前々期と前期のレポートのセキュリティリストに登場しており、本期で報告済みから修正済みに変わった。timerfd と POSIX timer はいずれもユーザー制御可能なハンドルであり、問題のパターンは一致している：まずデリファレンスし、次に型や範囲を判定する。

2.2 picolibc プロトタイプ整合：asctime_r と ctime_r の配列引数（11-08）

日付：2026-11-08 14:01（マージ時間）　ソース：提案 #11999

ctime.c で 13 行追加、3 行削除。picolibc はバッファを長さ 26 の制限付き配列として宣言し、RT-Thread はポインタ形式で宣言していたため、配列引数と NULL ポインタ比較の 2 種類の警告が同時に発生していた。他の C ライブラリは依然ポインタ形式であるため、修正は条件付きコンパイルでライブラリに応じて宣言を切り替える。作者は Parthiban Nallathambi、Linumiz 所属。

この項目を单独に記載する理由は、別の作業ラインの行き詰まりを解消するためである。瑞薩 RH850 移植提案には、utest CI がまずこの ctime.c の修正を待つ必要があると明記されている。4.3 を参照。

2.3 RISC-V FPU コンテキストスイッチの欠陥：報告から4時間後に修正提案（11-07）

日付：2026-11-07 23:10（報告）/ 2026-11-08 03:14（提案）　情報源：欠陥 #12005、提案 #12006

今号で最も注目すべき項目。報告者 boa-z は ArtInChip D213（C906、M モード）の移植時に、スレッド切り替え後に fs1 が不正になることを発見した。BSP 要因を排除するため、公式の qemu-virt64-riscv に戻って再現を試みた。環境は QEMU 10.0.13、OpenSBI 1.6、RV64D、単一 hart、master c63d7bc9。彼は切り替えタイプをまたいで浮動小数点レジスタを検査するテストケースを作成し、二つの問題を確定させた。

一つ目は自発的切り替え、すなわち rt_thread_yield である。SAVE_CONTEXT と RESTORE_CONTEXT は整数の callee-saved レジスタのみを保存し、浮動小数点を使用する二つのスレッドが fs0 から fs11 を互いに上書きしてしまう。報告には実測値が示されており、期待値 0x3ff0000100000000 に対し実測値は 0x3ff0000000000000 であった。二つ目はタイマープリエンプションである。SAVE_ALL は f0 から f31 を保存するが fcsr を保存しておらず、浮動小数点の丸めモードと例外フラグが黙って変更されてしまう。この種の問題はクラッシュせず、計算結果が徐々にずれるだけである。

メンテナの BernardXiong は4時間後に #12006 を提出した。fs0 から fs11 および fcsr を切り替えフレームに追加し、trap フレームに fcsr のアクセスを補い、切り替えフレームのサイズを切り上げて 16 バイトアライメントを保証し、割り込み切り替え用に構築されるフレームの fcsr を初期化する。併せて context_ext.h と stack.h にオフセットとレイアウトのマクロを追加する。提案はまだ審査中で、実機検証の記録はまだない。RT-Thread における RISC-V の重みを考慮すると、この項目は優先的にマージすることを推奨する。

  • タッチフレームワークテスト（#12002）、Bouffalo ADC チャネル検証（#12003）、dlmodule リグレッション（#11989）、utest 複数回実行（#11983）、ulog 出力呼び出しポイント（#11987）はいずれも審査中。最初の四件はテスト基盤ラインに属する。4.1 を参照。

3.3 RISC-V中国サミット：端末側AIフルスタック、車載グレードソフトウェアは車載テスト済み（10-18）

日付：2026-10-18 至 10-20（活動）/ 2026-11-06 09:59（公開）　情報源：公式ニュース

第一の核心的判断は焦点の移行である。端末側AIは「モデルが動くかどうか」から「インテリジェントエージェントが制約された算力とリアルタイム制約下で安定的に駐留できるか」へ移った。手法は、下方向には統一BSPとドライバフレームワークでカーネル差異を遮蔽し、上方向には軽量化ランタイムでオフライン起動、音声対話、マルチモーダル推論を担い、AIタスクとリアルタイムタスクを同一のスケジューリング体系に同居させ、AIがリアルタイム性を奪わないようにする。

4.1 QEMU 仮想デバイスリストの推進：SPI ループバック、CAN、SDIO、DAC/I2C が CI に参加（11-06）

日付：2026-11-06 から 11-08（マージ時間）　情報源：議題 #11972、提案 #11979、提案 #11990、提案 #11752、提案 #11758

  • CAN 送受信テスト（#11752、1792 行）：1572 行のテストケースファイル、22 のホストスタブシナリオ、タイムアウト更新、tick ラップアラウンド、空読み、エラー伝播、正常受信をカバー。作者は 50 tick タイムアウトと 1000 tick ウォッチドッグで元の重複フレームと不一致フレームのハングを再現した。

4.2 WCH の二本の線：青稞の高速割り込み設定と CH32V208 の低電力（11-07）

日付：2026-11-07 から 11-08（提案時間）　情報源：提案 #12004、提案 #12007

WCH の RISC-V 青稞コアは高速割り込みに関して整っていない。型番によってサポート程度が異なり、二段階のハードウェア割り込みしか持たない型番は高速割り込みを使うべきではない。提案 #12004 はチップシリーズごとに対応するコア能力を設定し、高速割り込みスイッチを新設し、割り込み属性マクロを統一して、対応チップは高速割り込みを、それ以外は通常割り込みにフォールバックさせる。併せて SDK を更新し、CH32V203 起動ファイルを調整。検証ボードは CH32V208W-R0 と CH32V307V-R1。
