1. 新アーキテクチャ：RH850 がメインラインへ

1.1 ルネサス RH850/U2C8 の移植をマージ、52 ファイル、4122 行（11-24）

日付：2026-11-24 15:01（マージ）。出典：#11998。

提案は 11 月 6 日に提出され、11 月 24 日にマージ、レビューに 18 日を要した。作者は parthitce、コミット署名は Linumiz の Parthiban Nallathambi。

マージ後、メインブランチに一度に 4 コミットが着地：カーネルアーキテクチャ層、ボードレベルライブラリ、QEMU ボードレベル、CI。合計 52 ファイル、新規 4122 行、削除はゼロ。

カーネル層は libcpu/rh850 に配置。スレッド切り替えは TRAP0 を使用し、ネスト割り込み、FPU コンテキスト、フォールトダンプをサポート。ボードレベルライブラリにはスタートアップコード、INTC 割り込みコントローラ、OSTM タイマー、RLIN3 シリアルを含む。

QEMU ボードレベルは qemu-rh850-u2c と命名され、シリアルは RLIN311 に配置、起動後は直接 msh に入る。libcpu ディレクトリは現在 21 個、rh850 が今回の新規追加分。

判断：これはアーキテクチャレベルの移植であり、単なる開発ボードの追加ではない。根拠は、変更が libcpu、bsp、CI の 3 箇所に同時に及んでおり、独立したツールチェーンとシミュレータを伴うこと。

1.2 シリアルは V1 のみ接続、ツールチェーンは v850-elf を使用（11-24）

日付：2026-11-24 15:01（マージ）。出典：#11998 説明。

シリアルドライバは V1 のみ実装。Kconfig では BSP_USING_UART が RT_USING_SERIAL_V1 に依存しており、新版シリアルフレームワークは当面選択不可。

ツールチェーンは v850-elf-gcc を使用。tools/ci/toolchain_bsp.yml はこのボードを v850-elf-gcc の類に分類。ダウンロード元は linumiz/rh850-gcc-toolchain の v1.2.0 を指す。

このツールチェーンは GCC 14.3 に picolibc を加えたもの。シミュレータは linumiz/qemu-rh850 の rh850-v1.2.0 由来。CI は 2 つの圧縮パッケージをダウンロード後、まず SHA-256 を検証してから解凍する。

判断：ツールチェーンが v850 系譜を再利用していることは、このラインがまず動作させることを優先していることを示す。根拠は、RH850 と V850 がともにルネサスの 32 ビット MCU 命令セット系譜に属し、リポジトリには既に libcpu/v850 と bm3803 ボードレベルが存在すること。

1.3 CI マトリクスに RH850 を追加、ARM、AArch64、RISC-V と並列（11-24）

日付：2026-11-24 15:01（マージ）。ソース：utest_auto_run.yml。

utest_auto_run.yml のプラットフォームマトリックスに RH850 の行を追加、マシンは rh850-u2c、カーネルは standard、SD カードなし。テストケースセットは 3 つ失敗：kernel_basic、mem、cpp11。

3 つ目は C++ グローバルコンストラクタを検証するためのもの。トリガーパスに bsp/renesas/rh850 を追加。

bsp/README.md に RH850 アーキテクチャシリーズを追加、メンテナンスレベルは「基本サポート」、シリアル列はサポートと記載。

提案者は検証結果を提案に記載。ハードフロートとソフトフロートのビルドは通過、scons –dist も通過。msh で list thread と free は正常、kernel_basic は 22 項目すべて通過。clang-format と cppcheck はクリーン。

判断：CI に入れる方がメインラインに入れるより価値が高い。根拠は、シミュレータとテストケースセットがあれば、今後のカーネル変更はすべてこの関門を通らなければならなくなること。

2. カーネルとドライバの堅牢化：同源の提案 6 件を精算

2.1 同一作者のセキュリティ提案 6 件が 5 分以内にマージ（11-24）

日付：2026-11-24 15:11 から 15:16（マージ）。ソース：#11820、#11821、#11823、#11824、#11825、#11826。

6 件はすべて manyangshen によるもので、作者日付は 9 月 22 日、2 ヶ月間保留されていた。

ドライバ側 3 件。I2C はバス制御と転送を直列化する。ブロックデバイスはパーティション I/O を相対セクタ内に制限する。virtio は不正な入力オフセットを拒否し、オーバーフローを回避する。

カーネルと IPC 側 2 件。メッセージキューパスは終端 NUL に従ってサイズを決定する。電源管理はサスペンド時のモードでデバイスを復元し、一律にデフォルトモードにはしない。

ボードレベル側 1 件。STM32 OpenAMP の受信リング状態を有界にし同期を追加、ラップアラウンドを修正。6 件の変更はいずれも大きくなく、多くは十数行から数十行の間。

判断：これはまとめて放出したもの。根拠は 6 件が同一作者、同一分帯にマージされ、作者日付が一致しており、レビューが同じラウンドで完了したことを示す。

#10379 と #10380 は virtio_input ドライバの境界外書き込みと境界外読み込み。#11299 は stm32mp157a-st-ev1 上の OpenAMP 仮想シリアル RX リングの境界外書き込み。

#11292 は mq_open と mq_unlink が rt_sprintf でキュー名を固定バッファに結合、プレフィックスは /dev/mqueue/。#11854 は STM32F103C6 の機能リクエストで、ボードレベルマージに伴いクローズ。

判断：このイシュー群の共通点はバッファ境界と並行タイミング。根拠は 5 件すべてが同一ラウンドの修正に由来し、いずれも新機能に関与しないこと。

3. チップと開発ボードの適合

3.1 GD32H77D GinoPi ボードレベルサポートをマージ、107 ファイル、2.67 万行（11-24）

日付：2026-11-24 15:20（マージ）。ソース：#11829。

提案は CYFS3 から、9 月 23 日に提出。マージ時 107 ファイル、26711 行追加、907 行削除。

新しいボードレベルディレクトリは bsp/gd32/arm/gd32h77d-ginopi。メインコントローラ GD32H77DIW、Cortex-M7、600MHz。

オンボード 8MiB GD25Q64 QSPI Flash、32MiB 16 ビット SDRAM、さらに GD32VW553 AT Wi-Fi モジュールが uart4 経由。

ドライバは LCD、OV7670 カメラ、GT911 タッチ、QSPI Flash ファイルシステム、ENET1 RMII、USB 高速ポートを搭載。デフォルト .config はシリアルと PIN のみ有効、その他は必要に応じて menuconfig で有効化。

Gino Pi は RT-Thread と兆易創新が共同で発表した初の GD32H77D エコシステム開発ボードで、公式サイトの製品ページは 9 月 8 日に公開された。ボードのデフォルトクロックは 600MHz、サンプルプログラムは 500ms ごとに PC4 をトグルする。

判断：これはメーカーとコミュニティが共同で構築したフラッグシップボードであり、サードパーティによる移植ではない。根拠は、ボード製品ページが RT-Thread 公式サイトに掲載されており、BSP が GCC と MDK5 の両方のプロジェクトを提供していることである。

3.2 STM32F103C6 が blue-pill ボードに参入（11-24）

日付：2026-11-24 21:41（マージ）。情報源：#11850。

STM32F103C6 は C8 の縮小版で、Flash 32KB、RAM 10KB。この変更では Kconfig、リンカスクリプト、rtconfig.py を拡張し、同じ blue-pill ボードで小容量チップを選択できるようにした。

合計 8 ファイル、138 行追加、25 行削除。同じバッチで README の LED ピンの記載誤りも修正された。PB2 は PC13 が正しい。

判断：これは低コストボードをメインラインに取り込むもの。根拠は、同じ BSP が現在 C6 と C8 の両容量をカバーしていることである。

3.3 SWM341 CAN 受信がクラシックフレーム長で切り捨て（11-24）

日付：2026-11-24 15:04（マージ）。情報源：#12076。

ドライバは DLC フィールドに従って直接データをコピーするため、DLC が 8 より大きい場合は 8 バイトのバッファを越えてしまう。この変更では長さをクラシックフレームの上限にクランプした。

2 ファイル、8 行追加。作者は cms19859230182-lang で、全志 V861 五筆提案の投稿者でもある。

判断：読み取り側の境界修正であり、メッセージのセマンティクスは変更しない。根拠は、長さのみをクランプし、DLC フィールド自体には触れていないことである。

3.4 4 件の小修正：x86 ツールチェーン、AF_NETLINK、ROMFS アライメント、macOS ドキュメント（11-24）

日付：2026-11-24 15:05 から 21:24（マージ）。情報源：コミット一覧。

x86 ボードの README でツールチェーンのダウンロード URL を変更、1 行の変更。

netdev の AF_NETLINK パスでビルドエラーを補修、2 ファイル各 3 行前後。tools 内の ROMFS ジェネレータは UTF-8 ファイル名の後にバイナリエントリをアライメントするよう修正、41 行追加、15 行削除。

macOS の QEMU クイックスタートドキュメントで PATH 展開と再起動スクリプトを修正、作者は bernard。

プラグインの自己記述は、ローカルの Claude Code のオーケストレーションと実行ワークベンチであり、Windows と Linux 向け。機能宣言は commands、service、webui の 3 項目。

5.2 全志 V861 の5件が CI マトリクスで停滞、作者は夜間に作業を中断（11-24）

日付：2026-11-24 14:54 から 22:08（レビューと回答）。ソース：#12077。

メンテナーの Rbb666 は、BSP ビルドマトリクスが空であり、C907 がコンパイルに入っていないと指摘した。allwinner/avaota-f2 を .github/ALL_BSP_COMPILE.json の SUB_RTT_BSP に追加するよう要求。さらに、クリーンチェックアウトで DTB を生成し、ビルドを完了できることを検証するよう求めた。

22時08分、作者は「もう直せない、明朝起きてからやる」とコメントした。5件は依然マージされておらず、ブランチは当日の master 先端に基づいて再構築済みで、ベースコミットは STM32F103C6 のものである。

判断：停滞点は DTB 生成からビルドマトリクス登録へ移った。根拠は、今回の指摘で論点が変わったものの、いずれも同じ事柄を指していることである。すなわち、クリーンチェックアウトで自身がビルドを通せなければならない、ということだ。

6. 業界応用観察：車載と HMI の2つのライン

6.1 QEMU が先行する車載パス（11-24）

日付：2026-11-24（本レポートの判断）。ソース：ルネサス RH850/U2C 製品ページ。

RH850/U2C はルネサスの28nm車載 MCU。G4KH コアは最高320MHzで、デュアルコアロックステップを構成でき、安全レベルは ASIL D に達する。

公式が挙げる用途はシャシー、ボディ管理、バッテリー管理、モータ制御である。今回の RT-Thread は QEMU シミュレーションまでしか対応しておらず、ボード名も qemu-rh850-u2c で、実ハードウェアの記録はない。シリアルも V1 のみの対応である。

判断：これはまず入口を確保したものであり、量産レベルの適配ではない。根拠は、ツールチェーンとシミュレータがいずれも同一の外部企業から提供されており、リポジトリ側に原廠が共同保守している印がないことである。

6.2 GinoPi はグラフィカルインタラクションを指向（11-24）

日付：2026-11-24（本レポートの判断）。ソース：Gino Pi 製品ページ。

GD32H77D は MIPI DSI、LCD-TFT、カメラインターフェース、画像アクセラレータを備える。ボードレベルドライバには LCD、OV7670、GT911 の3つが揃っており、さらに SDRAM と QSPI Flash ファイルシステムも備える。

この組み合わせが対応するのは HMI パネル、ハンドヘルド機器、ビジョン取得であり、低消費電力センサーノードではない。

判断：メインラインは中高級グラフィックスボードを補完している。根拠は、このボードのドライバリストで表示と取得が大部分を占める一方、デフォルト設定ではむしろシリアルのみが有効になっていることである。

7. まとめとトレンド観察

7.1 単日16件のマージ、前日の3倍超

11月23日は6件、11月24日は16件で、2日合計22件。6件のセキュリティ提案の作者日付は9月22日で、2か月押されてからマージされた。

7.2 新アーキテクチャがもたらすのは長期的な保守コスト

RH850 は libcpu、bsp、CI の3か所に入り、今後カーネル変更はこのパイプラインで一度止められることになる。作者は同時に picolibc と mem.cfg の2か所の上流修正も提出しており、移植過程が逆に共通コードを修正したことを示している。

7.3 セキュリティ強化はバッファ境界に集中

6件の提案のうち4件は長さ、オフセット、終端文字に関係する。これは同時期にクローズされた5件のイシューと符合し、欠陥タイプが高度に一致している。

7.4 Env はプラグイン化へ転換

Env Pilot は2つ目のプラグインであり、webui を備えた最初のものでもある。プラグインパッケージと Env 本体は別々にリリースされ、今後の機能は独立してイテレーションできる。

7.5 ニュース側は引き続き静寂

局限性説明：RH850 は QEMU 検証記録のみで、実ハードウェアのテストは見られない。公式ニュースインターフェースは5件のみを返し、期間内の新規はない。Google News の RT-Thread に対するマッチングは信頼できず、中国語クエリの3日間ウィンドウの4件はいずれも汎用組み込み記事であり、除外済みである。
