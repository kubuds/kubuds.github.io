1. カーネルとリリース動向

1.1 ルネサス RZ/N2L 割り込み重複ディスパッチ修正がマージ：Cortex-R52 trap 層と FSP ベクタテーブルの二重ディスパッチにより CANFD 有効化後にシリアル割り込みが誤ってハング（PR #11765）

日付：2026-09-10（10:09 北京時間マージ）　出典：RT-Thread/rt-thread commits（PR #11765）

期間内のメインリポジトリ唯一の機能マージであり、本日最も重要なカーネルレベルの修正です。PR #11765 [libcpu][cortex-r52] Fix duplicate interrupt dispatch on Renesas RZ（CYFS コミット、Rbb666 マージ）は 09-10 午前に正式に master へ入り、変更は libcpu/arm/cortex-r52/trap.c に集中しています（+25/-27、単一ファイル）。

問題の根本原因はコミッターによって明確に説明されています：RZ/N2L プラットフォームはルネサス FSP（Flexible Software Package）で割り込みベクタを管理していますが、現在の Cortex-R52 の trap 処理は bsp_common_interrupt_handler() を呼び出した後、GIC の INTID を FSP ベクタテーブルのインデックスとして扱い、さらに RT-Thread の isr_table を経由してもう一度ディスパッチします——これにより二重ディスパッチが形成されます。CANFD を有効化すると、UART RX の GIC INTID 321 が誤って g_vector_table[321] の CANFD TX ISR にヒットし、コンソールでエンターを押すと即座に誤った割り込みに入り data abort が発生します。修正の方向性は、余分なディスパッチを除去し、割り込みを単一の経路で進入させることです。

この PR は 08-28 に作成され、約2週間のレビューを経て 09-10 にマージされました。ルネサス BSP 方向におけるさらなるプラットフォームレベルの正確性修正です。同時に観察すると、同じくルネサスと低レベル方向に属する長期 PR #11228（klibc のバイトアライメントアクセスによるハードウェアエラー）と #11313（ルネサス clock_timer の分周設定）は 09-10 午前にも更新があり、依然としてレビューキューにあり、ルネサス/KLIBC ラインのレビューペースが加速しています。

1.2 Rust コンポーネントビルドスクリプトの clean 段階における toml 依存を除去（PR #11791）

日付：2026-09-09（13:31 北京時間マージ）　出典：RT-Thread/rt-thread commits（PR #11791）

メインリポジトリの調査期間内にもう1件のマージがあり、変更内容は components/rust/examples/modules/SConscript（+3/-2）、タイトルは [rust][build] Avoid toml dependency during clean。clean ターゲット実行時に toml 解析へ依存しなくなり、関連する Python 依存が未インストールの環境でもクリーン処理を完了できるようになった。PR は 09-09 12:56 に作成、13:31 にマージされ、所要時間は約 35 分で、本日最も早く流水した1件である。コミット者は CYFS、マージ者は Rbb666。

この変更自体は小さいが、調査期間内の他2件の Rust 関連の動きと合わせて見ると、RT-Thread の Rust コンポーネント（rust コンポーネントサンプルモジュール）が継続的な磨き込み期にあることが観察できる。ビルドスクリプトの堅牢性最適化は典型的な「掃除」型メンテナンスであり、通常は新しい言語サポートが「動く」段階から「日常的に使える」段階へ移行する時期に現れる。

日付：2026-09-09 ~ 2026-09-10　情報源：RT-Thread/rt-thread pulls

日付：2026-09-09（13:52 ~ 19:56 北京時間）　情報源：GD32-MCU-IOT/gd32_rt-thread commits

topic:rt-thread エコシステムリポジトリのうち、GD32シリーズ下流リポジトリ（GD32-MCU-IOT/gd32_rt-thread）は調査期間内に4件のBSPブランチPRを集中的にマージした。これは当日のエコシステム側で最大規模の一連の動作である：

  • gd32103c-eval（PR #69、13:52マージ、26ファイル +4783/-2341）：GD32F103VCT6（Cortex-M3）向けにBSPボードレベル初期化とIDEプロジェクトテンプレートを補完し、Keil（AC6）/ GCC / IARの3ツールチェーンでコンパイル・書き込みおよびutestの実行を可能にし、F10xドライバ設定ヘッダとboardレベル初期化を新規追加。

  • gd32107c-eval（PR #66、19:38マージ、15ファイル +4213/-2439）：新しいGD32 BSPアーキテクチャにアップグレードし、f10xのdma/uart/spi/i2c設定ヘッダとSOC_SERIES_GD32F10xシリーズ対応、board_msd_init.cを新規追加。

4件の変更に共通する主線は「新GD32 BSPアーキテクチャへの移行」である：board_msd_init.cによるボードレベル初期化の統一的補完、Kconfig/.config設定項目の統一的再編、Keil/IARプロジェクトファイルの統一的更新。貢献者はjunying2025とyuanshuo0で、兆易創新エコシステム側が主導するコミットに属する。本リポジトリはRT-Threadの下流リポジトリであり主リポジトリではないため、内容はGD32デバイスファミリ（今回はすべてARM Cortex-Mコア）のRT-Thread上でのボードレベル対応であり、ベンダーエコシステム推進の観測窓口として収録する。

3.2 ソフトウェアパッケージインデックスに STM32N6 HAL SDK パッケージインデックスを追加（PR #2037）

日付：2026-09-09（15:26 北京時間マージ）　情報源：RT-Thread/packages commits（PR #2037）

RT-Thread ソフトウェアパッケージインデックスリポジトリの調査期間内に 1 件追加：[hal_sdk] add stm32n6 ソフトウェアパッケージリポジトリインデックス（yans6666 コミット、09-09 14:10 作成、15:26 マージ、Rbb666 レビュー）。これは STM32N6 シリーズ HAL SDK のパッケージリポジトリインデックスの実装であり、開発者がパッケージマネージャ内で STM32N6 の HAL サポートを直接参照できるようになる。STM32N6 は STMicroelectronics の自社開発 NPU 搭載ハイエンド MCU シリーズであり、インデックスの実装は、このプラットフォームの RT-Thread 接続がソフトウェアパッケージ化段階に入ったことを意味し、最近の STM32 方向の複数のドライバ対応（BDMA for SPI、イーサネットドライバの新 HAL API への対応）と同一のベンダーラインを形成している。

  • Renesas（Renesas）BSP は今週最も活発なベンダーラインである：09-07 から 09-10 まで四日連続でこの方向の動きがあり（SDHI カード検出、SCI SPI チップセレクト書き込み、GPT PWM レジスタ読み取り、RZ/N2L 割り込み分配）、いずれも新しいボードの導入ではなくドライバと割り込みレイヤの正確性修正であり、RZ シリーズの RT-Thread 上での成熟度磨き上げ段階を指し示している。
  • 「NXP は新ボードが入り、旧単はクリア」と「GD32 はバッチで新アーキテクチャへ移行」はベンダーエコシステムの二つの並行パスを構成する：前者はメインリポジトリの受理リズムであり、後者はベンダーの下流リポジトリが自組織的に推進している。
  • レビューキューの消化リズムは明らかに分化している：小さな変更（Rust ビルド約 35 分、ソフトウェアパッケージインデックス約 76 分）は速やかに通過する一方、カーネルとドライバレイヤの変更（Renesas 割り込み 13 日、KLIBC と clock_timer 系の長期 PR は月を跨ぐ）はサイクルが顕著に長い。

限界に関する説明

  • 本調査期間の Google News 中国語および英語クエリは「RT-Thread」に対していずれも有効なヒットがなかった（英語側は持続的に Rotten Tomatoes の映画評分類のノイズにヒット、中国語側は 08-30 の elexcon 予告に後退するのみ）。したがって本レポートは GitHub と公式 API を主たる情報源とし、メディア側のカバレッジは限定的である。
