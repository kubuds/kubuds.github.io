一、内核与版本动态

1.1 瑞萨 RZ/N2L 中断重复分发修复合入：Cortex-R52 trap 层与 FSP 向量表双重分发致 CANFD 使能后串口中断错挂（PR #11765）

日期：2026-09-10（10:09 北京时间合入）　来源：RT-Thread/rt-thread commits（PR #11765）

窗口内主仓库唯一一笔功能性合入，也是本日最有分量的内核级修复。PR #11765 [libcpu][cortex-r52] Fix duplicate interrupt dispatch on Renesas RZ（CYFS 提交、Rbb666 合入）于 09-10 上午正式进入 master，改动集中在 libcpu/arm/cortex-r52/trap.c（+25/-27，单文件）。

问题根因由提交者描述得很清楚：RZ/N2L 平台使用瑞萨 FSP（Flexible Software Package）管理中断向量，而当前 Cortex-R52 的 trap 处理在调用 bsp_common_interrupt_handler() 之后，又把 GIC 的 INTID 当作 FSP 向量表索引、再经 RT-Thread 的 isr_table 分发一次——形成双重分发。使能 CANFD 后，UART RX 的 GIC INTID 321 会错误命中 g_vector_table[321] 的 CANFD TX ISR，表现为控制台敲回车即进入错误中断并触发 data abort。修复方向是去掉多余的一次分发，让中断沿单一链路进入。

该 PR 08-28 创建，评审约两周后于 09-10 合入，属瑞萨 BSP 方向又一处平台级正确性修复。同步观察：同属瑞萨与底层方向的长期 PR #11228（klibc 字节对齐访问引发的硬件错误）与 #11313（瑞萨 clock_timer 分频设置）在 09-10 上午均有更新，仍在评审队列中，瑞萨/KLIBC 线的评审节奏正在加快。

1.2 Rust 组件构建脚本去除 clean 阶段的 toml 依赖（PR #11791）

日期：2026-09-09（13:31 北京时间合入）　来源：RT-Thread/rt-thread commits（PR #11791）

主仓库窗口内另一笔合入，改动为 components/rust/examples/modules/SConscript（+3/-2），标题 [rust][build] Avoid toml dependency during clean。执行 clean 目标时不再依赖 toml 解析，使清理流程在未安装相关 Python 依赖的环境下也能完成。PR 09-09 12:56 创建、13:31 合入，全程约 35 分钟，是本日流转最快的一笔；提交者 CYFS，合入者 Rbb666。

这笔改动本身很小，但与窗口内另两笔 Rust 相关动作合看，可观察到 RT-Thread 的 Rust 组件（rust 组件示例模块）正处在持续打磨期：构建脚本的健壮性优化属于典型的「扫地」型维护，通常出现在一门新语言支持从「能跑」走向「日常可用」的阶段。

1.3 评审队列观察：瑞萨 SCI SPI 修复 PR 新开、QEMU 文档 PR 新开、Copilot 提交的 FinSH 控制台加固 PR 关闭未合入

日期：2026-09-09 ~ 2026-09-10　来源：RT-Thread/rt-thread pulls

  • [bsp/renesas][drivers] Fix SCI SPI runtime configuration and transfer errors（PR #11792，CYFS3，09-09 17:25 创建，2 个提交、+254/-193）：排查 RZ/N2L EtherKit 的 SCI SPI 回环问题时，发现共享 SCI SPI 驱动存在数处缺陷——RZ 分频接口把 false 当作分频结果指针传入且未使用 FSP 配置中的实际时钟源；运行时配置未能可靠传递给 FSP，重复配置也未正确关闭旧实例；配置过程把 RT-Thread 的位宽单位从 bit 误改为 byte；收发等待超时或出错后仍返回传输长度，导致调用方误判成功。09-10 上午该 PR 仍有更新，为瑞萨驱动线的下一笔重点评审对象（与 1.1 同属 RZ/N2L EtherKit 平台）。
  • [docs] point QEMU Linux quick start at qemu-nographic.sh（PR #11793，shiptux，09-09 23:53 创建，+12/-0）：指出快速上手文档只提 ./qemu.sh，而该脚本传 -serial stdio 却不带 -nographic，QEMU 会尝试打开 GTK 窗口，在无显示环境或 SSH 下卡在 gtk initialization failed；BSP 本身已提供 qemu-nographic.sh 并在 README 中推荐用于服务器场景，故补充文档说明。延续 09-08 两笔文档 PR（#11789/#11790）的同一贡献者修文档节奏。
  • Harden FinSH console switching against unsafe output devices（PR #11455，Copilot，09-10 09:26 关闭，未合入）：该 PR 06-09 创建、累计 5 个提交（+290/-18），目标是给 rt_console_set_device() 加设备校验，只允许提供控制台安全打开标志或具备中断/DMA 异步发送能力的设备被切换为控制台，并保留旧控制台直到新设备校验通过，以消除 ISR 或故障处理上下文中向阻塞设备打印导致的崩溃路径。开放三个月后关闭未合并，判断为方案未获采纳（同批的另一只 Copilot 提交 #11454 sys_getaddrinfo 指针加固仍在评审）。窗口内主仓库另有新开 PR 3 只、合入 2 笔、新建 Issue 0 只。

三、生态与厂商适配

3.1 兆易创新生态仓库 GD32 四笔 BSP 集中合入：103c / 107c / 205r / e503v 向新 BSP 架构升级（09-09）

日期：2026-09-09（13:52 ~ 19:56 北京时间）　来源：GD32-MCU-IOT/gd32_rt-thread commits

topic:rt-thread 生态仓库中，GD32 系列下游仓库（GD32-MCU-IOT/gd32_rt-thread）在窗口内集中合入四笔 BSP 分支 PR，是当日生态侧体量最大的一组动作：

  • gd32103c-eval（PR #69，13:52 合入，26 文件 +4783/-2341）：为 GD32F103VCT6（Cortex-M3）补齐 BSP 板级初始化与 IDE 工程模板，使其可在 Keil（AC6）/ GCC / IAR 三工具链下编译烧录并跑通 utest，新增 F10x 驱动配置头与 board 级初始化。
  • gd32205r-start（PR #65，15:09 合入，18 文件 +6294/-6283）：新增 board_msd_init.c 完成 UART GPIO 初始化，移除 UART RX DMA 相关 Kconfig 与 rtconfig.h 选项，工程文件更新至 chip family GD32F20xxE。
  • gd32107c-eval（PR #66，19:38 合入，15 文件 +4213/-2439）：升级到新的 GD32 BSP 架构，新增 f10x 的 dma/uart/spi/i2c 配置头与 SOC_SERIES_GD32F10x 系列支持、board_msd_init.c。
  • gd32e503v-eval（PR #67，19:56 合入，35 文件 +10876/-2525）：适配 e503v 系统与常用外设，覆盖 GPIO、I2C、SPI、USART、DMA。

四笔改动的共同主线是「向新 GD32 BSP 架构迁移」：统一补 board_msd_init.c 板级初始化、统一重排 Kconfig/.config 配置项、统一刷新 Keil/IAR 工程文件。贡献者为 junying2025 与 yuanshuo0，属兆易创新生态侧主导提交。该仓库为 RT-Thread 下游仓库而非主仓库，内容是 GD32 器件家族（本次均为 ARM Cortex-M 内核）在 RT-Thread 上的板级适配，作为厂商生态推进的观测窗口收录。

日期：2026-09-09（15:26 北京时间合入）　来源：RT-Thread/packages commits（PR #2037）
