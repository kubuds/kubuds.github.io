RT-Thread ウィークリーレポート (2026-09-21 ~ 2026-09-25)

2026-09-25 Kubuds

報告期間：2026年9月21日（月）から9月25日（金）まで、計5営業日、5リリース日 素材来源：本誌の毎日RT-Thread動態デイリーレポート（09-21、09-22、09-23、09-24、09-25、計5号）；加えてGitHub組織の調査期間を09-26朝まで確認 編集説明：本期間はRT-Threadカーネルとリリース、ツールチェーン、エコシステムベンダー適配、コミュニティ活動と業界応用の5次元をカバーし、項目はすべて当該期のデイリーレポートで検証済みの情報源に基づく

1. 今週の要聞

  • Gino Piエコシステム全スタックを一週間で打通（09-21 ~ 09-23）：GD32H77D開発ボードGino PiのメインラインBSPがシリーズ提案の形でレビュー入り（19コミット、142ファイル、純増約2.6万行、ボードレベル骨格、ペリフェラルフルセットとデモプロジェクトをカバー）；同日、デバイスサポートパッケージの両リポジトリにGD32H77x_78xサポートが新規追加され、ATコンポーネントにオンボードGD32VW553モジュールのWi-FiとTCP socketサポートが補完され、これに先立ちStudio SDK側ではJ-Link依存とリンクスクリプト修正が补齐されていた。ボードが「Studioとベンダーダウンストリーム」から「メインラインで保守可能」へと移行したことは、兆易創新と睿賽徳の協業ラインにとって今週最も実質的な一歩である。
  • RISC-Vボードレベルサポートが一日で三連（09-24 ~ 09-25）：沁恒CH32V203C8T6 BSPがメインライン合入を完了（青稞V4Bコア、提案から合入まで約2日）；楽鑫ESP32-C6-DevKitC-1 BSP提案がレビュー入りし、同時にesp-idfソフトウェアパッケージのC6ビルドソースが提出された；コミュニティはRT-Thread NanoのIDF不要移植プロジェクト（ESP32-S31デュアルコアRISC-V、320 MHz）をリリース。三つのRISC-Vチップが集中してボードレベルリンクに出現し、RT-Threadボードレベル生態におけるRISC-Vの比重は引き続き上昇している。
  • メインラインは全週で13コミット合入：月曜朝の九コミット集中バッチ（ネットワークATチャネルのホスト名検証厳格化、SDIO二重メモリリーク修復、STM32H7 UART4受信DMA、GD32 USARTピン修正、Rustターゲット選択とQEMUドキュメントなど）、月曜午後の二コミット（英飛凌PWMマクロ不一致、CherryUSB N32H4x USBFSサポート）、水曜のCIフロー調整（clang-formatコミットはパイプラインをスキップしなくなった）、木曜のCH32V203 BSP、いずれも既に着地済み。
  • レビューキューは単週で22件の新規提案と2件の缺陷報告（09-21 ~ 09-24）：歴史的遺留缺陷七連加固シリーズ（バス相互排他、電源管理、USBホスト、IPC、ブロックデバイス、OpenAMP、virtio）、国民技術N32Hタイマー補完（39ファイル、約四千行）、lwip-natポート分配とlwip-dhcpdヘッダファイル欠落、rt_vsnprintf幅セマンティクス缺陷修復などを含み、品質向け修復が主体を構成している。
  • ソフトウェアパッケージインデックス三連マージ（09-24）：CanopenNode v1.2.0が九箇所のKconfig再構築を完了（CiA 401デバイススイッチを汎用デバイスプロファイル体系に統合）、「仮想センサー」新パッケージが入列（模擬データ生成、オプションのMQTT上报）、AI AgentパッケージにMQTTツールとrt_vsnprintf能力自動検出機構が新規追加。
  • 瑞薩Titan Mini端側ビジョン双推進（09-22、09-24）：OpenMVプロジェクトがまずSDRAMタイミングとメモリプール最適化を完了（Tiny YOLOv2 INT8単フレーム推論156.10 msから58.49 msへ、YOLOv8n 256×256は186.54 msから38.33 msへ）、続いてオンボード800×480 RGBスクリーンを接続し、LCD表示と色塊追跡の示例を新規追加；業界メディアも同期して報道。
  • ツールチェーンと配套生態が多方面で更新（09-18 ~ 09-22）：RT-Thread Studio配套がv5.3.0カーネルへ切替、J-LinkデバッガがV9.76aへアップグレード（年度跨ぎ更新）；STM32H7デバイスパッケージとHALドライバパッケージが二重リリース（v1.10.7 / v1.11.6）；第三者GDBデバッグフレームワークGDRが2026.03をリリース。
  • 公式チャネルは第三十二日から第三十六日まで沈黙；活動側は工博会と産教が主体：工博会Workshop詳細発表（10月13日上海専場、25セットのスマートカー教具）、臨港「場面直通車」睿賽徳閉門对接会の補録、RSOC26夏期キャンプ教程の体系化開篇；公式新聞インターフェースは全週で新規追加なし。

2. カーネルとリリース動態

リリースとメインライン

  • 新バージョンリリースなし：最新正式版は依然として 09-10 リリースの v5.3.0；本調査期間はリリース後の平常消化期であり、作業の重心はレビューキューと付随する落地にある。
  • マージリズム：全週 13 件のマージは「一極集中、全期間低頻度」の分布——月曜朝の 9 件と午後の 2 件がピーク、水曜・木曜は各 1 件、その他の時間帯はメインラインは静粛。
  • 付随フォロー（09-20）：RT-Thread Studio の SDK インデックスと内蔵カーネルソースが v5.3.0 に切り替わり、デバッガビルドは J-Link を V9.76a にアップグレード（前版は 2025 年 7 月の V8.48）；v5.3.0 カーネルリリースの 10 日後にフォローが完了。
  • ツールチェーンの現状：Env ツールチェーンは調査期間内に新規コミットとリリースなし（最新は 09-16 の v2.0.2）；ソフトウェアパッケージインデックスリポジトリは 09-24 の 3 件のマージ以外に動きなし。

今週メインラインにマージされた修正（時系列）

  • ネットワーク AT チャネルのホスト名検証を厳格化、数字に似た超長ホスト名を直接拒否し、スタックバッファの越境書き込みの潜在リスクを解消（09-21、#11782）
  • SDIO のメモリリーク修正 2 件：CIS タプル分岐の一時メモリ未解放（09-21、#11780）、ドライバ登録解除ノードリークのクローズドループ（09-21、#11806）
  • STM32H7 汎用 DMA に UART4 受信側チャネル定義を補完（09-21、#11808）
  • ブロックデバイスパーティションコンポーネントのログフォーマット指定子とパラメータ型を修正（09-21、#11809）
  • GD32 シリーズ USART 送受信ピン初期化を修正、送信は代替プッシュプル、受信はプルアップ入力に変更、E50x から F30x をカバー（09-21、#11804）
  • Rust ツールチェーン Cortex-M33 ハードフロート目標判定を修正（09-21、#11811）
  • QEMU Linux クイックスタートガイドとドキュメントの高リスクコマンド整理の 2 件（09-21、#11790 / #11793）
  • 英飛凌 PWM マクロのミスマッチ修正がメインラインでクローズ、評価ボード BSP 修正と同源（09-21、#11802）
  • CherryUSB に国民技術 N32H4x シリーズ USBFS デバイス側サポートを追加（09-21、#11764）
  • clang-format の自動コミットが継続的インテグレーションをスキップしなくなり、フォーマット結果がビルド検証チェーンに組み込まれる（09-23、#11830）
  • 沁恒 CH32V203C8T6-EVT-R0 BSP をマージ、D6 ベクタテーブル、64KB/20KB リンカスクリプトと共有ドライバ修正 2 件を含む（09-24、#11827）

セキュリティと欠陥

  • rt_vsnprintf の幅セマンティクス欠陥と修正（09-24）：最小幅が誤って最大幅として切り捨てられる（例 %3s で “abcdef” が “abc” に切り捨て、左揃えとアスタリスク幅の変種も同様に影響）；欠陥報告と修正提案は同日提出、修正は標準版と tiny 版の実装および単体テスト（3 ファイル）をカバー、レビュー状態。
  • 歴史的遺留欠陥の七連強化（09-22 提出、レビュー中）：同一貢献者が一度に 7 件の修正を提出、二線シリアルバス制御と送信相互排他、電源管理のサスペンドモードごとのペア復帰、USB ホストインターフェース数の境界、IPC メッセージキューパスの終端記号境界、ブロックデバイス論理パーティションの越境読み書き、STM32 OpenAMP 受信境界とリングラップ、virtio 入力オフセット検証をカバー；いずれも数カ月前の既存欠陥報告を引用し、GCC 16.1 ビルドと境界ケース検証を添付。
  • bluepill BSP ドキュメント欠陥報告（#11818）：クイックスタートに MDK プロジェクト再生成手順が欠如、ドキュメント通りに操作するとコンパイル不可。
  • 先週木曜の 4 件のセキュリティ系 issue（tmpfs、メッセージキュー、pread、finsh）公開記録には個別対応する修正コミットは見当たらず、本調査期間に更新なし。

レビューキュー観察

  • 2 バッチの単夜集中コミットが新規追加の主体を構成：09-21 から 09-22 未明の 8 件（N32H タイマー補完 39 ファイル約 4 千行、STM32 イーサネット ops 適配と adcv2 ログレベル、lwip マクロスイッチ化、RA6W1 リソース配分、ESP32-C3 Windows ビルド、単体テスト性能ケースのクロック依存、bluepill ドキュメント等）；09-22 夜間の 8 件（欠陥強化シリーズ 7 件＋CH32V203 BSP）。
  • ネットワークスタック修正が集中：lwip-nat ポート配分欠陥と lwIP 2.1 適配（#11831）、lwip-dhcpd に string.h ヘッダファイルを補完（#11835）、netdev AF_NETLINK ビルド修正（#11828）。
  • 大型提案が引き続き審査待ち：GD32H77D GinoPi ペリフェラルシリーズ（#11829、142 ファイル）、ネットワークプロトコルスタックアップグレード（lwip 2.2.1）長期待機、N32H タイマー補完。
  • ビルドと整理系：ipc SConscript 冗長マクロ整理（#11832）、bluepill ドキュメント修正（#11817）；他に ESP32-C6 ボード級提案（#11836、第 3 章参照）。
  • 旧提案の活動再開：#10689（2025 年 9 月作成）が調査期間末に議論を再開。

3. エコシステムとベンダー適配

ベンダー BSP

  • 兆易創新（GD32H77D / Gino Pi）：メインライン BSP シリーズ提案がレビュー入り——19 コミット、142 ファイル、純増約 2.6 万行。ボード級骨格（プロジェクト、リンクスクリプト、rtconfig）、ペリフェラル一式（イーサネット、USB ホストとデバイス、SDRAM、ハードウェア I2C、SPI3、PWM、SDIO とファイルシステム、RTC とアラーム、ウォッチドッグ、CAN と CAN FD、OSPI Flash、MIPI LCD、GT911 タッチ、OV7670 カメラ、LVGL）とデモプロジェクトをカバー。オンボード GD32VW553 無線モジュールの UART4 AT 通信と MAC 照会は検証済み、Wi-Fi アソシエーションは未完了（デフォルト無効）。
  • 兆易創新（デバイスパッケージとネットワークコンポーネント）：gd32-arm-cmsis と gd32-arm-series の両リポジトリに GD32H77x_78x サポートを追加（CMSIS デバイス層と新ペリフェラルライブラリ）。at_device に GD32VW553 Wi-Fi デバイスと TCP socket サポートを追加。
  • ルネサス（RA8P1 Titan Mini）：OpenMV プロジェクトで外部 SDRAM のタイミング／クロック設定とオンチップ SRAM メインガベージコレクションプールの拡張（1344 KiB から 1472 KiB）を完了し、3 モデルの推論所要時間が実測で低下（最大約 4.9 倍）。その後、RGB インターフェース 800×480 スクリーンドライバ（RGB565）と LCD 基本表示、カメラプレビュー、赤色ブロック追跡のサンプルを追加（17 ファイル、約 1200 行）。
  • 沁恒（CH32V203）：BSP をメインラインにマージ（第 2 章参照）。併せて drv_usbd の USBFS DMA タイミングと drv_iwdt ウォッチドッグ共有ドライバを修正。D6 型は 64KB Flash / 20KB SRAM のみで、USB とその他のペリフェラルは容量に応じて取捨選択が必要。
  • Espressif（ESP32-C6 / ESP32-S31）：ESP32-C6-DevKitC-1 BSP 提案（40 ファイル、+9492 行）と esp-idf ソフトウェアパッケージの C6 ビルドソース提案を同時にレビュー提出（この貢献者と CH32V203 のコミット者は同一人物）。コミュニティの ESP32-S31 IDF 不要移植プロジェクトは再現可能なビルド検証を実施済み（89 トラッキングファイル、バイト単位で一致するイメージ）。
  • Infineon（PSoC6）：PWM マクロのミスマッチ修正がメインラインでクローズ。評価ボード BSP も同時にクロスプロジェクト修正を完了。
  • GD32 下流リポジトリ：PR #71 ドライバ更新ブランチをリフレッシュしレビュー対話入り（USART、SPI、2 線シリアルバスドライバの GPIO 初期化バージョン更新）、メインラインへの還流は未完了。

ソフトウェアパッケージとミドルウェア

  • ソフトウェアパッケージインデックス三連マージ（09-24）：CanopenNode v1.2.0（9 箇所の Kconfig リファクタリング、汎用デバイスプロファイル体系、論理デバイスレジストリとトランスポート契約）、「仮想センサー」新パッケージ（模擬データ生成、オプションの MQTT 上报）、AI Agent パッケージ（MQTT ツール、カーネルシンボルによる rt_vsnprintf 能力の自動検出で 4.1.x カーネルの重複定義を回避）。約 2 週間滞留していた 3 件の提案が同日マージ。
  • STM32H7 デバイスパッケージと HAL ドライバパッケージの同時リリース（09-18）：デバイスパッケージ v1.10.7（TIM23 / TIM24 インスタンスを補完、GPIO ビット定義の誤記を修正）、HAL パッケージ v1.11.6（約 20 件の上流同期を統合、USB ゼロレングスパケット、イーサネット 10M レート、SDMMC クロック、I2C デッドロック、AES-GCM/CCM、FDCAN フィルタ、DMA コールバックなどをカバー）。
  • GDR 2026.03（09-22）：サードパーティ GDB デバッグフレームワークに RT-Thread オブジェクト集約コマンドと git 風の構造化ヘルプ体系を追加、初期化ポリシー検証失敗でセッションが終了する問題を修正。RT-Thread 3.1.x / 4.0.x / 4.1.x をサポート、Cortex-A9 と RV64 ターゲットはクローズドループ検証済み。

検証説明

  • AWTK ウィンドウ内のコミットは汎用 GUI 改善であり、「エコシステム参考、専項でない」記録を踏襲。h120d-protocol リポジトリの説明ファイルはダウンロード誘導コンテンツに書き換えられており（アカウント異常の疑い）、除外し掲載しない。gd32_zephyr は Zephyr 下流プロジェクトであり本主題でない。STM32H742 個人実践ベースラインリポジトリ（0 スター）は本文に収録しない。
  • 前週期末に収録済みの事項（メディア視点総説、工博会 Workshop 募集稿）は本期で項目を重複立てせず、情報更新時のみ増分提示する。
  • Gino Pi メインライン提案のマージ形態（分割の有無、ペリフェラルの取捨）はレビュー結論に従う。GD32VW553 の Wi-Fi アソシエーションと TCP / MQTT トラフィックは未検証（コミット説明の自述）。

  • Gino Pi 発売運営：公式商城発売稿を更新し、購入チャネルと首批ユーザー返現評価活動を明確化。
  • 落地事例：本周期内に量産、商用または協業落地事例の新規報道なし；ロボット及び具身智能方向に新規デプロイ消息なし、前週のリズムと一致。

6. 趨勢観察

  • RISC-Vがボード級増分の主力に：一週間内に沁恒CH32V203マージ、楽鑫ESP32-C6送審とESP32-S31 IDF不要移植が連続して出現、加えて兆易創新GD32VW553無線モジュール支持、ボード級リンクの新規動作はほぼ全てRISC-Vチップに集中。
  • 「メーカー発布からメインライン」パスが成形：Gino PiはStudio SDKインデックス、デバッグ補鏈、デバイスパッケージ铺垫からメインラインBSP提案まで一週間で完走；チップ廠主導コミット、Studioとメインライン両側並行が、再現可能な開発ボード落地リズムとなる。
  • 品質向修復が評審主体に：歴史的遺留欠陥七連加固、rt_vsnprintf幅語義、lwipポート分配とヘッダファイル欠落はいずれもコミュニティが主動コミット；メインライン低頻度（13筆マージ）と評審高頻度（22条新規提案）が並存し、コードベースは消化研磨期に入る。
  • 端側視覚が性能から機能へ：Titan Mini OpenMVは推論提速完成後すぐに屏幕と視覚示例を接続、デモ形態は「ベンチマーク」から「屏幕付きインタラクティブ」へ転換し、業界メディアの追従を得る。
  • ツールと付随エコシステムが平穏に追従：Studioはv5.3.0と同期、J-Link跨年度アップグレード、GDR新版発布、メインバージョン周辺のツールチェーンとデバッグエコシステムは活発を維持。
  • 公式伝播の静寂が継続：公式ニュースインターフェースは全週停止（第三十二から第三十六日）、対外情報は引き続きGitHub、フォーラム、商城と業界メディアを先行チャネルとし、工程側活発度と公式チャネルは明らかな対照を形成。
