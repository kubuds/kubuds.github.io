今日の重点：TileOPs が三日間で五十件をマージ、二つの完全モデルをオペレータの組み合わせで完成

11-20 から 11-22 の三日間で、TileOPs は 50 件をマージし、同期間の組織内で最も多い量となった。うち二件はモデル全体を公開オペレータで組み上げたもの。

DeepSeek-V4-Flash は #3072 でマージ、作者は bigSheep123、11-22 20:29 に主干へ。models/deepseek_v4/ は 43 層を指定 GPU に展開し、batch-1 の prefill と貪欲デコードを実行、MTP 層は構築しない。設定側はモデルが計算しない各設定を拒否し、ローダーは完全に読み込めない checkpoint を拒否する。

検収は DeepSeek 公式 inference/model.py の torch カーネルと対照。テストは三層モデルを用い、Flash 幅に従い、各アテンションタイプごとに一層を取る。長プロンプトと三トークンプロンプトでそれぞれ一回ずつ実行。

各層出力と prefill、デコード全体の logits は参考自身の bf16 丸めノイズ内に収まることが要求される。indexer の選択は公式 indexer と一致し、二カード分割は単カードと一致すること。

Qwen3.8-27B のテキストデコーダーは #3112 でマージされ、11-22 13:20 に主干へ入った。models/qwen3_8/ は from_pretrained、分割 prefill とデコード、reset と貪欲 generate を提供する。batch は 1。このモデルの Hugging Face 上の model_type は qwen3_5 である。Qwen3.5-27B と Qwen3.6-27B の設定値とテンソル名は同じため、三つの checkpoint はすべてロードできる。

Gated DeltaNet 層は CausalConv1dFwdOp、CausalConv1dUpdateFwdOp、GDNFwdOp を通る。正規化は RMSNormGatedFwdOp を通る。全注意層は FusedQKNormRoPEFwdOp（インターリーブ MRoPE、1 + w）、PagedKVCacheWriteFwdOp、GQAPagedFwdOp を通る。その後に sigmoid 出力ゲートを追加する。

ローダーは層ごとに safetensors シャードを読み、model.visual.* と mtp.* をスキップし、それ以外の読めないテンソルは直接拒否する。

二つのモデルのシェルは統合された。#3119 により DeepSeek-V4 と Qwen3.8 は一つの CausalLM と一つの read_checkpoint を共有し、ロード後のテンソルがビット単位で同一であることを宣言する。同じコミットで二つのサンプリングカーネルを一つのインデックス折り畳みマクロに収め、生成される CUDA はバイト単位で同一である。二つのローダーはテンソル欠落層に対して ValueError を投げるようになり、裸の KeyError ではなくなった。

この経路はまず問題を分解し、後で組み立てる。11-20 午前、TileOPs は一度に 14 件の DeepSeek-V4 作業項目（#3057 から #3068）を開いた。内容は FP8 indexer スコアリングと top-k、packed KV 収集と疎インデックス、デュアル packed キャッシュデコードを含む。

さらに圧縮器状態と packed キャッシュ書き込み、融合 QKV RMSNorm がある。二つのトラッカーがそれぞれ H200 の vLLM で TileOPs を検証すること、および SM90 MXFP4 バックエンドと TileOPs の差を確認することを管理する。二日後にモデル全体がマージされた。

情報源： https://github.com/tile-ai/TileOPs/pull/3072 https://github.com/tile-ai/TileOPs/pull/3112 https://github.com/tile-ai/TileOPs/pull/3119

今日の重点：TileFoundry が Apple ANE ターゲットを追加、第四類ハードウェアが実測性能ドキュメントを伴って登場

#361 は 11-22 21:33 にマージされ、作者は zhen8838、11-20 に開かれた。これは tilefoundry-apple に Apple Neural Engine ターゲットを追加し、形態は Metal ターゲット（#354）に倣う。命令宣言は TIR に置き、HIR を一組用意し、さらに TIR へ降ろす。コード生成とランタイムはこのコミットの範囲外である。

ハードウェア側は二つのドキュメントを提供する。apple.h14 アーキテクチャと apple.m2_pro.ane デバイスである。トポロジーは一つの engine、一つのユニットで、gmem を共有し、engine は自前の smem（L2、容量非公開）を持つ。性能は実測値として fp16 16.71 TFLOP/s が記載され、測定方法は 3×3 畳み込み、256 チャネル、384×384 である。

命令は全六条で、いずれも f16。それぞれ T.ane.conv、T.ane.bypass、T.ane.pool、T.ane.unary、T.ane.binary、T.ane.reduce である。各条は capability、実行 mesh、hir_matches とアクセス関係を伴う。さらに verify ルール、および段階的に fp16 へ丸め、ties away from zero とする torch 評価器がある。conv は Conv2D とチャネルが外側にある MatMul を兼ね、bypass は C/H/W 転置、ReLU、行列再配置を担う。

一つの厳格な制約がドキュメントに書き込まれた。特徴マップの W が 1 より大きい場合、W ストライドは必ず 1 でなければならない。engine に要素ストライドがないためである。ConvertHIRToTIR は ANE に対して engine 領域内の各 T.ane.* を一度だけ発行する。

併せて変更されたのはターゲットインターフェース自体である。Target 基底クラスは現在 capabilities()、documents() とクラス属性 hardware を宣言し、コアは名前で具体ターゲットの属性を読まなくなった。ane、metal、amx の三ターゲットはすべてフィールドが一つだけの凍結 dataclass となり、フィールドはデバイスドキュメントの ID またはパスである。cuda ターゲットはこの二つのメソッドを実装し、コンストラクタは変わらない。

これにより TileFoundry のハードウェアファミリーは三類から四類へ拡大した。CUDA、Metal、AMX に ANE を加える。ANE はこの類の中で初めて「ドキュメント + 命令 + verify ルール」が揃った形態で入ってきたモバイル向け推論エンジンである。

情報源： https://github.com/tile-ai/TileFoundry/pull/361

1. コアプロジェクトの進展

1.1 TVM サブモジュールで2件をフォロー：CodegenC の Let バインディングとドライバ欠如時の ROCm スタブ

tilelang メインリポジトリの調査期間内に3件をマージ、うち #4422 は 3rdparty/tvm を tilelang_main@5fb5cb27 に進める。このコミットは上流の2箇所の修正を取り込む。

1箇所目は TVM #95：InitFuncState が CodegenC 内で Let バインディング状態をクリアする。従来は状態が関数をまたいで残留し、後続関数のバインディング解析に影響していた。

2箇所目は ROCm スタブの挙動。TVM #79 は ROCMDeviceAPI の存在チェックを hsa_init() から hipGetDeviceCount() に変更する。ROCm ランタイムがない場合に非 hipSuccess を返すことを期待する。USE_ROCM=ON かつ hip_stub の Linux ビルドでは、hipGetDeviceCount は従来 HIPDriverAPI::get() に委譲していた。libamdhip64.so が存在しない場合に std::runtime_error を送出し、@requires_rocm の収集が非 ROCm マシンで直接失敗していた。本コミットはライブラリ欠如時に hipErrorNoDevice を返すよう変更する。

同じコミットで hipGetErrorName、hipGetErrorString も併せて降格処理し、不要になった HSA スタブと組み込み hsa.h を削除する。7ファイルを変更。

情報源： https://github.com/tile-ai/tilelang/pull/4422

1.2 CuTeDSL 単体テストを専用 CI ジョブに統合、セルフホスト runner の一時ディレクトリをジョブ内に分離

#4417 は 11-23 02:48 にメインへ進入、42ファイルを変更。CuTeDSL の単体テストを元のジョブから専用の CuTeDSL CI ジョブへ移す。

2箇所目の変更はセルフホスト runner の TMPDIR を RUNNER_TEMP 配下に隔離する。従来は並行ジョブがシステム一時ディレクトリを共用し、成果物やソケットが互いに衝突する可能性があった。

もう1件 #4387 はドキュメントで、Windows 上の HIP スタブのデフォルト値を明確化する。

情報源： https://github.com/tile-ai/tilelang/pull/4417

1.3 新規報告の欠陥は「コンパイルは通るが計算が誤る」に集中：パイプライン化コピー、ベクトル化スイッチ、fragment アラインメント

メインリポジトリで3日間に新規起票された CUDA と codegen 系 issue は11件、過半がコンパイル通過・結果誤りに属する。

#4423 は NVRTC JIT アダプタが非連続 PyTorch テンソル上で無音の誤出力を出すもので、原因は is_contiguous チェックの欠如。#4435 は CUDA codegen が float4、int の強制キャストで fragment 配列を読むのに対齊を行わず、誤読み出しを起こす。

#4434 は T.Pipelined(num_stages=2) と T.alloc_var インデックスの組み合わせで結果が誤るもので、codegen がインデックスをループ外へ繰り上げるため。#4460 は T.Pipelined ループ内でコピー済みタイルを読む continue、break がループの後に発行される。

#4461 は tirx.disable_vectorize がパイプライン化された fp16、bf16、int8 の T.copy を中断する。1または2バイトの cp.async を発行してしまう。#4439 はパックされた FP16、BF16 の T.fmul が FMA に縮約され、丸め境界を破壊する。

最初の2件は既に審査中の修正がある：#4442 はパックされた T.fmul の丸め境界を保持し、#4447 はローカル配列を16バイトにアラインする。

情報源： https://github.com/tile-ai/tilelang/issues/4423

1.4 コンパイル期エラー類：レイアウト推論の内部アサーションとシンボリック形状のダウンキャスト失敗

このグループはコンパイル期に停止するもの。#4426 は (64, 48, …) のようなスレッドで整除可能な形状で LayoutInference の内部エラーを報告し、has_best が偽になる。#4424 は CodeGenTileLangCUDA がシンボリック形状上で tirx.Sub から ir.IntImm へのダウンキャストに失敗する。

#4425 は fp16、bf16 の T.reduce_max、T.reduce_min が NVRTC 下でコンパイル失敗する。std::numeric_limits で止まる。#4427 は FP8 の T.gemm が Ampere sm_86 上でエラーを出さずに SM89 専用 MMA を発行し、実行期にクラッシュする。

ROCm 側の1件 #4462：float8_e5m2(fnuz) バッファの T.clear、T.fill とマスク付き T.copy が下降できない。Metal 側の1件 #4415：simdgroup をまたぐ2箇所のリダクションがスレッドローカルベクトルロードを誤コンパイルする。

情報源： https://github.com/tile-ai/tilelang/issues/4426

2. マルチバックエンド適配（昇騰 / 海光 / 摩尔線程 / 沐曦）

2.1 MLIR 昇騰が一日で八つの方言オペレータをマージ、単項オペレータの共用テンプレートを抽出

11-20 の一日で、tilelang-mlir-ascend の mlir-dialect ブランチは八件のオペレータをマージした。最初の四件は #232 sort、#233 reshape、#234 arange、#235 concat。後の四件は #236 flip、#237 not、#238 abs、#239 sqrt。

最初の五件は HadiaSaqib がコミットした。reshape は純粋なビューオペレータとして memref.reinterpret_cast に降ろされる。concat は可変引数の destination-style で、静的な軸に沿って連結する。arange、flip はそれぞれ TLIR 側と HIVM 側の降下とテストを伴う。

後の三件は Areeshh がコミットし、共用の単項インフラを一セット抽出した。構成要素は TL_UnaryOp 基底クラス、verifyElementwiseUnary 検証、ConvertUnary<> 変換テンプレート、EmitUnary<> 生成テンプレート。not は hivm.hir.vnot に、abs は vabs に、sqrt は vsqrt に降ろされる。

作者はコミット説明で作業方式を明記している。各オペレータは mlir-dialect の現在の末端から引き出したブランチをそれぞれ切り、共用インフラはまず本 PR 内で複製し、先にマージされたものが勝ち、残りは軽微な修正で rebase する。これがこの一批のオペレータが一日で連続して通せた理由であり、同時にマージ順序が手戻りを生むことも意味している。

同日、同リポジトリの main は別途 RoPE カーネル（#263）をマージした。main は 11-04 以降の静寂がこれで終わった。リリース側ではさらに #265 が夜間ホイールを OBS に配布し、#266 が昇騰 NPU のホイールテストを Dist パイプラインに接続した。

情報源： https://github.com/tile-ai/tilelang-mlir-ascend/pull/233

2.2 昇騰メインリポジトリで新たに十一件の缺陷を報告、950PR の 28 コアと L2 フラッシュが主な出所

メインリポジトリでは三日間に [Ascend] 付きの缺陷が新たに 11 件開かれた。

950PR 上の三件が最も具体的だ：#4430 は Split-K GEMM が 28 コアの 950PR 上でデッドロックし、NUM_BLOCKS 32 が常駐ブロック数を超える。#4432 は do_bench と自動チューニングが 950PR 上で失敗し、aclrtDeviceL2CacheFlush が 207000 を返す。#4452 は大きな shared→shared の reduce_sum が空のカーネルバイナリにコンパイルされる。

自動スケジューリングが二件：#4436 は自動スケジューリングの T.Kernel が UB→GM ストアを二つの AIV 上でそれぞれ書き込み、同期を挿入しない。#4441 は AscendMGroupedTileScheduler がグループ内に落ちたグループの出力タイルを丸ごと捨てる。

メモリ経路が三件：#4438 は列原点が非ゼロの GM↔UB T.copy がコンパイルでき、実行時にデバイスをクラッシュさせる。#4440 は T.gemm が padded L1 を読み、L0 割り当て内のローカルな M/N 領域で静かに誤る。#4437 は自動スケジューリングカーネル内の shared→shared の reduce_sum(dim=1) の結果が正しくない。

残り二件はコンパイル期：#4444 はパラメータまたはバッファを C++ の型名（half など）で命名すると生成コードが壊れる。#4429 は InsertSync が flash-MLA prefill の nk、topk が 832、896 などの値のとき決して終了しない。#4453 は flash attention の例が未対応の形状に対してメッセージなしの AssertionError を投げる。

情報源： https://github.com/tile-ai/tilelang/issues/4430

2.3 昇騰は審査中が七件、四件が前日以前に新規報告された缺陷に対応

メインリポジトリの審査待ちキューにある [Ascend] 付きの七件。作者は redelego、JINITAIMEI121、stwilliam503388-creator、yuqiha、erhsh の五人に分散している。

四件は新規報告の缺陷に直接対応する：#4451 は割り当て pitch に従って padded L1 GEMM のオペランドを扱い、#4440 に対応。#4445 は AscendC の typedef を保持し、half という名前のバッファまたはパラメータが生成コードを壊さないようにし、#4444 に対応。#4443 は m-grouped スケジューラが空のグループでタイルを捨てるのを修正し、#4441 に対応。#4446 はスカラーコピーのコンシューマをそれを生成する DMA の後に並べ、#4438 に対応。

3. エコシステムと採用側（TileOPs オペレータライブラリ / TileFoundry / topa / 採用側）

3.1 パフォーマンス線 31 件：GQA デコードの統合が 1.21 倍高速化、MXFP4 デコードが 8 コードあたり 9 命令に削減

TileOPs の 50 件のマージのうち 31 件に [Perf] タグが付き、6 割を占める。方向性は RoPE、インデックス、GEMM、MoE、要素単位、プーリング、正規化、アテンションの 8 箇所に集中している。

GQA 分割デコードの統合は #3119 で変更された。各シャードで 1 回だけ重み付けし並列実行、最後に合計で 1 回割る。単一リクエストのデコードは最大 1.21 倍高速化。同じコミットで 16 ビットオンチップ softmax をまず warp 最大値を取ってから合計する方式に変更し、fp32 カーネルは変更なし。

MXFP4 共有デコードは #3111 で変更された。32 ビットワード内の 8 つの e2m1 コードを一度に変換し、1 つのマスクで 2 つの振幅置換を供給、1 回のシフトと 2 つのバイト置換で符号を配置。8 コードあたり 11 命令から 9 命令に削減され、デコードされるバイトは不変。

このコミットは差を定量化した。prefill 行と FP8 グループ GEMM の差はまさに e2m1 デコードにある。ncu は 32k-up 上でタイルあたりのステップごとに 2264 条の warp 命令対 909 条を数え、うち約 1125 条はデコード warp 内にある。

GEMM は #3106 で変更された。float32 NT グリッドの一波、幅 128、両軸とも 2 つ以上のタイルの場合、セレクタは coop2 タイルに切り替え、SMEM に収まる最深リングを選ぶ。128×128 の基本タイルは退位する。根本原因は coop2 の 2 つの消費 warpgroup がリング深で基本タイルの 5 段に追いつくと追い越すことであり、メインブランチは coop2 を 4 段で封じている。両タイルが同点の場合、セレクタは従来基本タイル寄りだった。

自己評価の基準は記録に値する。多くのコミットが「below bar」（受け入れライン以下）と書きつつ、各行がメインブランチより速いと注記している。受け入れラインは目標倍数を見ており、メインブランチに対する相対的な高速化ではないことがうかがえる。

残りの方向はそれぞれ一から五筆。RoPE 五筆：広い呼び出しは SM ごとにトークンを分割し、各行を共有メモリに入れ、64 ビットインデックス、整数演算を前方に移動し、単一ヘッドのデッド境界チェックを除去。インデックス四筆：concat の行とベクトル、embedding の行タイル、int32 id の dtype 保持。要素ごと三筆：GELU、erf、16 ビット tanh をフル占有率のレジスタ予算に圧縮。アテンション三筆：FP8 indexer の key-scale 符号を分岐なしに、DSAPaged の二経路 bf16 key 分割を CTA ペアに統合、paged GQA の RoPE 準備を 16 バイトベクトルで処理。他にプーリング二筆、正規化二筆、KDA 一筆、MoE 三筆。

審査中の三筆はいずれも同じモデル群を指す。#3099 は GatedPoolCompress の DeepSeek-V4-Flash デコードにおける SGLang との差を収集。#3097 は HyperConnection のデコードとプリフィルにおける TileKernels との差を収集。#3101 は DSADense の行を常駐 CTA 上で実行させる。

ソース： https://github.com/tile-ai/TileOPs/pull/3119

3.2 一部バックエンドでテストスイート全体が失敗しなくなり、未サービスのオペレータは未検証として記録

#3121 は OpNotServedError を新設。OpNotAvailableError を継承し、target 属性を持つ。選択したターゲットにそのオペレータのカーネルビルダーが登録されていない場合にこのエラーを送出する。

テストレポートは一つの場合に限りこれを未検証として記録する（スキップして列挙）：例外が名指しした target が起動時の --tileops-target で固定されたものと等しい場合。テスト自身が後から設定したデフォルト値は含まない。同じエラーが他の target を名指しした場合は引き続き失敗と判定する。例えばディスパッチテスト内の偽 target など。

従来、一部のオペレータのみを提供するバックエンドで --tileops-target を使ってスイートを実行すると、未登録オペレータの各テストで失敗していた。原因はオペレータ層が単なる OpNotAvailableError を送出するだけだったこと。オペレータごとに段階的に進めるバックエンドはこれではスイート全体を使えなかった。

3.4 TileFoundry の autodiff を ModuleList 要素ごとの再計算に変更、dot はレジスタ順でペアリング

#363 はアナライザに二つの CTA から無順序で到達可能な通常のグローバルメモリを拒否させる。#365 は codegen を修正し、レイアウトの物理投影内で各テンソル値を書き込む。#360 はレイアウト未指定を Broadcast として読み取り、mesh 宣言をモジュールクラスに移動する。

5. トレンド観察

  • 受け入れ単位がオペレータからモデルへ上がった。2 件のモデル組立はいずれも公式参照実装を対照としている。DeepSeek 側は inference/model.py の torch カーネル、Qwen 側は HF transformers の torch パスを使用。判定基準は bf16 丸め誤差内での層ごとの一致であり、オペレータレベルの整列よりも「生産スタックを置き換え可能」という証拠に近い。
  • 欠陥の重心が「コンパイルが通らない」から「コンパイルは通るが計算が誤る」へ移った。11 件の CUDA 新規欠陥のうち少なくとも 6 件はサイレントエラーであり、昇騰側はコンパイル成功、実行時にデバイスがクラッシュするかタイル全体が欠落する。この種の欠陥はテストスイートで捕捉できるが、コンパイル時アサートでは捕捉できない。
  • バックエンド拡張は「ドキュメント先行」で進む。ANE ターゲットはまずハードウェアアーキテクチャ文書、実測算力、6 命令の verify ルールを提示し、コード生成とランタイムは明示的にスコープ外と記す。検証可能な境界を先に確立してから、実装に踏み込む。
  • 半完成バックエンドにテストチャネルができた。#3121 は未サービスのオペレータを失敗ではなく未検証として記録する。オペレータ単位で推進する昇騰、海光の路線にとって、これはテストスイートを「全緑でなければ受け入れない」から「カバレッジで採点する」へ変えるものだ。
  • エージェントパイプラインが価格付け段階に入った。topa の 15 項目はすべてコストモデルの細部（常駐 CTA、マルチウェーブグリッド、収集行、部分ウェーブ）を補うもの。性能提案はラウンドで産出された後、さらに割引評価を通す必要があり、このステップがエージェント産出の PR を主干に入れられるかどうかを決める。
  • 昇騰の 2 路線の重心が入れ替わった。先週は MLIR が方言を敷き、メインリポジトリがリリース工程化を担った。今期は MLIR が 1 日 8 オペレータ、メインリポジトリが 11 件の新規欠陥と 7 件の修正で、正確性に注力している。2 路線はリズムが異なるが、同じテストスイートを通す必要がある。
