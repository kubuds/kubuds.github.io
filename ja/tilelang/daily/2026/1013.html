1. コアプロジェクトの進展

1.1 メインリポジトリ：ROCm の2件——DeepSeek NSA 前向き/デコードと flash-decoding の実行可能タイル（10-13）

日付：2026-10-13（北京時間の未明にマージ）　情報源：ROCm NSA（#3152）／ ROCm flash-decoding タイル（#3149）

  • DeepSeek NSA on ROCm（#3152、+111/-2）：gfx942 のウェーブサイズは64であり、TileLang はウェーブ未満の HIP block を拒否するが、2つの NSA サンプルは32スレッドをハードコードしていた；本件は前向きと単一トークンデコードのカーネルに単一の64レーンウェーブを選択し、CUDA の既存の32スレッド起動構成を維持し、gfx942 における因果的前向きと単一トークンデコードの正確性カバレッジを追加（PyTorch NSA リファレンスと対照、FP16、16 Q ヘッド 1 KV ヘッド、シーケンス64）。
  • flash-decoding のタイル適応（#3149、+82/-5）：gfx942 上で128x64タイルの生成カーネルは66048バイトの動的 LDS（65536のデバイス上限を超過）を必要とし、256 VGPR の天井に達し、起動時に「invalid argument」を報告していた；本件は起動前に生成された HIP の LDS と VGPR 使用量を検査し、予算超過時のみ既存の64x64タイルにフォールバックする（デバイス名によるハードコードは行わない）、CUDA パスは変更なし、gfx942 の実行時リグレッションを追加。

1.2 メインリポジトリ：thread_storage_sync の正確なスレッド境界（#3291）と #2954 の修正（10-13）

日付：2026-10-13　情報源：正確なスレッド境界（#3291）

  • thread_storage_sync のために正確なスレッド境界を計算（4ファイル、+292/-96）。作者は #2954 が本コミットで修正されたことを確認。新規テストケースで「等価な部分スレッド guard が同一 barrier に帰約される」ことを検証し、SM89（4060 Ti）上での前後のコンパイル生成物の比較を添付。

1.3 メインリポジトリ：Autotune 構造化試験レポート、CodeRabbit 自動アサインとテスト規範ドキュメント（10-12 ~ 10-13）

日付：2026-10-12、2026-10-13　情報源：試験レポート（#3393）／ CodeRabbit 自動アサイン（#3487）／ テスト規範（#3489）

  • Autotune 試験レポート（#3393、+98/-7）：実験的な AutoTuner.run(on_trial=...) オブザーバーインターフェースを追加（RFC #3375 に対応）。試験ごとに設定インデックス、JSON 設定、結果、レイテンシ、検証ラベルと制限付きエラーテキストを出力。コールバックは集約スレッド上、共有キャッシュロックの外側で実行される。レポート/シリアライズのエラーは該当レポートを閉じるだけでチューニングには影響せず、候補生成、タイムアウト、キャッシュアイデンティティも変更しない。作者は「コールバック vs 固定 JSONL 成果物」が依然としてオープンな API 決定事項であると注記。
  • レビューガードレール（#3487、+1/-1）：CodeRabbit の reviews.auto_assign_reviewers を true に設定し、実際に review リクエストを発出させるようにした（従来は走査で提案を列挙するのみ）。11 件の reviewer ルールと順序は変更なし。
  • テスト規範（#3489、8ファイル）：Testing Style Guide を追加——いつ既存カバレッジに依存するか、いつ最小拡張するか、いつ焦点を絞ったカバレッジを新規追加するか。tilelang-cpp-style を tilelang-dev-guide に改名し、C++ ルールはオンデマンド参照へ移行。CONTRIBUTING を簡素化しリンクを掲載。

1.4 メインリポジトリ：昇騰 PTODSL SIMT 帰約ヘルパーの vendoring（#3469）で CANN Weekly コンパイルを修正（10-12）

日付：2026-10-12　情報源：PTODSL 帰約ヘルパー vendor（#3469）

  • PTOAS 上流が ptodsl/_allreduce.py を削除し、TileLang が自ら vendor することを想定したが、メインリポジトリの contrib/ptodsl/simt.py は依然として同モジュールを参照——最新の CANN Weekly（09-30）で任意の PTO ターゲットオペレータをコンパイルすると ModuleNotFoundError が発生。本コミットでヘルパーを tilelang/contrib/ptodsl/allreduce.py として vendored（+555/-115）し、整型シンボル互換を monkey patch から帰約テーブルと dtype ディスパッチに統合し、PTO ターゲットの可用性を回復。

1.5 メインリポジトリ審査中：SM120 MXFP8/MXFP4 ブロックスケーリング MMA、L2 プリフェッチと Host IR 2件など（10-12）

日付：2026-10-12　情報源：SM120 MX ブロックスケーリング MMA（#3495）／ L2 プリフェッチ（#3490）／ Host IR 直結 JIT（#3481）／ Host IR 実行統一（#3473）／ Windows ARM64 CI（#2962）

  • #3495（+884/-51）：T.gemm_blockscaled は SM120/SM121 上でブロックスケーリング MMA ファミリーを NVFP4 から MXFP8（kind::mxf8f6f4、1X、UE8M0）と MXFP4（mxf4nvf4、2X、UE8M0）へ拡張し、FP32 累加、K 要素 32 個ごとに 1 スケール；10-10 にマージされた SM121 点灯（#3430）を引き継ぎハードウェアマトリクスを拡張し続ける。
  • #3490（+87/-1）：tl.prefetch_l2(addr, eviction_policy=...) を新規追加、evict_normal / evict_last をサポート、sm_80 以上を要求、CUDA codegen はポリシーをコンパイル時テンプレートパラメータとして発行する。
  • Host IR 2 件（#3481 / #3473）：Host IR JIT とキャッシュへの直結、CUDA と CuTeDSL 実行の Host IR 経由での統一、引き続き審査中。
  • その他審査中の項目：CI に Windows ARM64 を追加（#2962）、JIT パラメータのハッシュ可能検証（#3417）、部分波スカラーリダクション（#3478）、正数定数除数の安全 guard 平坦化（#3488）、cast 組み合わせ検証（#3350）、TMA ディスクリプタ名検証（#3484）など。

2.1 昇騰：NSA Decode / NSA Bwd の 2 件の大型移行をマージ——48 例の階層テスト（10-12）

日付：2026-10-12　情報源：NSA Decode（#1701）／ NSA Bwd（#1730）

  • #1701（+755）：example_tilelang_nsa_decode.py は Developer mode hybrid（combineCV + auto_cv_sync + auto_sync + memory_planning の 4 つの pass_configs）で NSA Decode 単核デコード（seq_q=1）を実装し、明示的な L1/L0C/UB 割り当て、5 段の GM workspace を workspace_idx=[6..10] で自動割り当て；コンパイラが自動的に Cube/Vector スコープを分割し、クロスコア flag 同期を挿入する（手動 barrier/Scope/set_flag が不要）。階層テスト 28 例：L0 閾値、L1 機能（DeepSeek-V3 の典型的な設定 D=128、S=16、BS=64 を含む）、L2 異常と境界特殊値；910B3、fp16 の実測（B=2、SEQ_LEN=64）。
  • #1730（+1593）：example_tilelang_nsa_bwd.py は nsa_fwd（オンライン softmax + 疎な K ブロック選択、エンドツーエンド用）と nsa_bwd_single（単核逆方向：5 GEMM + softmax + Delta + dS をオンチップ融合）の 2 つの JITカーネルを提供；逆方向は flashattn_bwd パラダイムに従いオンチップ直結の T.copy（L0C→UB、UB→L1）で 9 個の GM workspace を省略し、2 段の補償 GEMM（ds_delta / ds_delta2）を保持；階層テスト 20 例。両件の移行バッチは国慶節前後を通じて行われ、本調査期間で適配リポジトリのデフォルトブランチに確定した。

3.2 TileOPs：foundry 性能バッチ——NSA 永続 CTA、W4A16 GEMM と 16 ビット除算（10-12）

日付：2026-10-12　情報源：NSA 永続 CTA（#2531）／ W4A16 GEMM（#2534）／ 16 ビット除算（#2543）

5. トレンド観察

5.1 ROCm の補習：デバイス予算を意識した 2 件の修正

  • 今回の調査期間の 2 件の ROCm 修正は同一テーマ——「デバイスの現実に応じて適応する」を指す：gfx942 の 64 lane ウェーブフロント（#3152）と LDS/VGPR 予算（#3149）。いずれもユースケース側（examples）での修正で、カーネル内の生成戦略には触れておらず、ROCm サポートが依然「動作させて回帰を追加する」段階にあることを示す。メインリポジトリで最近の SM121、SM89 の複数世代同時修正が合流したことと合わせると、TileLang のバックエンド構成は「NVIDIA 優先」から「複数デバイスの同時保守」へ移行しつつある。

5.2 SM89 が第二のプラットフォームに：1 日で 6 件マージに加え 4 件審査中

  • TileOPs は 1 日で 6 件の SM89 マージ（アテンションのプリフィル／デコード、線形アテンション、Norm の全カバー）に加え 4 件の SM89 審査中。RTX 40 シリーズと L40 / 6000 Ada 級ワークステーションが、オペレータライブラリ側で Hopper と並ぶ常態的なターゲットになった。評価側も同期（ナイトリー基盤 +10 項目）し、SM89 の正確性カバレッジは「コンパイルできる」から「回帰がある」へと向かっている。

5.3 昇騰移行ラインは正確性の収尾へ

  • NSA のフォワード／バックワードの 2 件の大型移行がマージ（合計 48 件の階層テスト）、キャッシュ三分割と cross-warp allreduce グルーピング修復が継続——昇騰ラインの重心は「サンプルとオペレータの移植」から「正確性、キャッシュセマンティクス、コンパイル可用性」の収尾監査へ移った。#3469 の修復後に即座にコミュニティから正確性修復のフィードバック（#3494）が現れ、協業ループは正常に機能している。
