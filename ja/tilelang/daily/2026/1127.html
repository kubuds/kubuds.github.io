今日の重点：摩尔線程 MP31 が一度に 14 件の PR を提出、低精度と集合通信を同時に補完

tile-ai/tilelang-musa は 11-27 未明 02:18 から 04:16 の間に 14 件の PR を新規作成、番号は #14 から #27。これらのコミットはすべて v0.1.15+musa.1 をベースブランチとし、スタック順序を宣言、#25 は #19 より後にマージするよう要求している。

低精度が主線だ。#19 で MP31 の fragment-A SQMMA GEMM を合法化し、188 KiB の共有メモリガードレールを追加した。#25 で MP31 ネイティブの W4A16 SQMMA を補完し、fp16/bf16 × int4 → fp32 と逆方向の2つの組み合わせをカバーする。#25 はさらに sqmma.h を書き換え、MUSA 5.2.0 ヘッダファイルで s4 が誤って fp4 と書かれている問題を回避した。#20 で warp 専用 GEMM の FP8 TME 記述子を有効化した。

メモリアクセスと同期がそれぞれ一群を占める。#27 で4ビット重みのパック済み UINT8 TME ロードを利用可能にした。#18 で TME カーネルに終了時の tme_flush() を追加した。#16 で MP31 の swizzle インデックスを要素単位に変更し、ベクトル化を維持した。#24 で warp 専用 TMA バリアを修正し、squad を跨ぐ部分同期を各 squad の128スレッドバリアに引き下げた。#26 でコンシューマ側のマルチ warp AllReduce を MP31 の部分バリアに引き下げた。

言語面も拡張中だ。#23 でブロック内並列の T.sort、T.argsort、T.topk を追加し、バイトニックソートテンプレートで実装、int4 以外の6種の dtype と任意の2の冪でない長さをサポートする。#15 で murand を通じて T.rng_init と T.rng_rand をサポートする。#21 で T.reduce_prod、2バリアのマルチ warp 一次元スキャン、mem-bound の TIR pass を追加した。#22 で tl.enable_fast_math を mcc -ffast-math に接続した。

検証側は MTT S5000（mp_31）で行った。#23 のソート用例は25項目すべて通過し、MoE top-2/8、NSA top-64/512、2の冪でない長さをカバーする。#25 には低精度と累加の用例もある。

情報源： https://github.com/tile-ai/tilelang-musa/pull/25。

今日の重点：メインリポジトリの3件はすべて昇騰、host-mapped バッファ引数が主線に進入

tile-ai/tilelang メインブランチの調査期間内はコミットが3件のみで、すべて昇騰タグ付き。これまでのキャッシュサブシステムや ROCm 修正のペースとは異なり、昇騰が主線の安定した入力源になっている。

#3909 は09:44にマージされ、昇騰に明示的な host-mapped バッファ引数を追加した。従来、ASCEND カーネルはマップ済みの CPU テンソルを受け取っても拒否し、呼び出し側はテンソル検証を無効化するしかなかった。新パスは #3802 の契約を踏襲し、同じ T.annotate_host_mapped_buffers(...) インターフェースを通る。Cython と TVM-FFI の両側で aclrtHostGetDevicePointer を使ってマッピングを検証し、その後デバイス可視アドレスを渡す。dtype、形状、ストライド、実行デバイスのチェックはすべて維持される。

#4486 は11:32にマージされ、#4429 を修正した。トリガーとなるシナリオは nk=topk=960 の FlashMLA プリフィルで、各 query が15個の KV タイルを処理し、2つの query スロットが交互に、最初のスロットは30回のループ後に再利用される。旧実装は同じパイプラインの各ペアサイトに対してイテレーション距離ごとに辺を構築し、単一ペアサイトで0から30までの計31個の距離を寄与し得た。新実装は「ソース、宛先、厳密性」ごとに互いに素な閉区間を格納し、2つの区間の合成もやはり区間となるため、新しいカバレッジ距離をバッチ単位で伝播できる。

#4390 は12:25にマージされ、昇騰 CI の PTOAS を PyPI からのインストールに変更した。CANN 9.2 イメージは変更せず、まずイメージ同梱スクリプトでその中の PTOAS コンポーネントをアンインストールし、次に --upgrade --no-deps --only-binary=:all: で最新の互換ホイールをインストールする。インストール後、Python 3.12、x86_64、パッケージと CLI バージョンの一致を検証し、PTOAS、PTODSL、MLIR Python モジュール、ネイティブ拡張がすべて仮想環境からロードできることを確認する。インストールまたは検証に失敗した場合は PTO バックエンドのサンプルと単体テストをスキップし、ステップの結果をジョブサマリに書き込む。

情報源： https://github.com/tile-ai/tilelang/pull/3909。

今日の重点：TileFoundry が Apple ANE ターゲットを公開、TIR から HWX コンテナを直接出力

tile-ai/TileFoundry に審査中の PR #369 が新規追加され、タイトルに Apple ANE の codegen チェーンが明記されている。パスは3段階に分かれる：TIR → タスク記述子 → HWX コンテナ。この変更は #361 で既に導入された ANE ターゲットの上に構築され、TileLang エコシステムで初のオンデバイス・ニューラルエンジンターゲットとなる。

実装は2層に分かれる。ISA 層はレジスタビットフィールド図を提供し、Common、L2、PE、NE、TileDMA、Kernel の6種類のブロックをカバーする。タスク記述子は RUN/MASK パケット符号化を採用し、load、store、compute-PE、compute-NE、conv、activation の6種類のプリミティブを備える。さらに宣言的式とクロスフィールド検証ライブラリがあり、構築時にフェイルクローズ方式で記述子を検証する。

コード生成層はエミッタ分派、パスごとのシリアライズ、HWX コンテナ出力を行う。コンテナは Mach-O 形式で、その記述に従ってリバースエンジニアリング後にゼロから実装し、デフォルトイメージには文字除去を施す。範囲外の tile_height と tile_width はコンパイル時に直接拒否する。

正確性について、提案ではカバー済みのオペレータ範囲において Apple 自社コンパイラの出力とビット単位で一致すると主張している。

同一リポジトリ同日に #368 をマージし、#162 の改名後に残った問題を修正した。コード生成は依然として ShardLayout であるバリアに対して tilefoundry::local を投射するが、この関数は local_tensor に改名済みであり、nvcc 段階へのコンパイルで中断する。修正法は「グリッド全体ブロードキャスト」のバリアのみ文字を取得し、シャードバリアに遭遇した場合は直接拒否するというもの。理由は、シャードバリアが各 warp に異なる文字を割り当てるのに対し、CopyAsyncBulk は最初の warp のスレッドからのみ CTA 到着時に一度だけ読み取り、残りの warp は永遠に完了しないフェーズの文字を待つことになるためである。

情報源： https://github.com/tile-ai/TileFoundry/pull/369。

1. コアプロジェクトの進展

1.1 host-mapped バッファパラメータがメインライン入り、昇騰はテンソル検証の無効化を要求しなくなる

#3909 は Cython と TVM-FFI の 2 つのバインディング経路を変更する。両方とも aclrtHostGetDevicePointer でデバイス側アドレスを取得し、元の dtype、形状、ストライドをカーネルに持ち込む。C++ バインディングのシグネチャは変わらず、既存のデバイス種別に応じてランタイムクエリを選択するよう変更した。Cython はデフォルトの CUDA パーサーを維持し、昇騰のみオプションのパーサーを提供する。CUDA 側は引き続き use_torch_stream() を使用し、共有デバイス選択ロジックは変更していない。

「全 host パラメータ」の昇騰シグネチャのみ、元の NPU ストリームを明示的にインストールする。テストは全 host パラメータ、自動割り当ての NPU 出力、NPU Graph キャプチャの 3 シナリオをカバーする。

1.2 InsertSync が区間ごとに依存距離を伝播するよう変更、31 個の反復距離で個別にエッジを構築しなくなる

#4486 は InsertSync という 1 つのパスのみを変更する。従来は同一パイプラインのサイトペアごとに、反復距離ごとに 1 本のエッジを挿入し、依存クロージャの構築時に繰り返し合成していた。新実装は到達可能距離を閉区間として保存し、2 つの区間を合成して別の区間を得ることで、まだカバーされていない距離のみを伝播する。ギャップと厳密性は明示的に保持し、距離 0 と 1 は従来の epoch ドメイン投射規則で処理する。

FIFO ワークキューは std::set に変更し、キーはソース、デスティネーション、2 つの距離境界、厳密性とし、重複する未処理区間のスキップに用いる。

1.3 昇騰 CI が PTOAS を PyPI からインストールするよう変更、CANN 9.2 イメージは据え置き

#4390 の動機は PTOAS と CANN のリリースサイクルが同期していないことである。従来は PTOAS がイメージに固定されており、アップグレードにはワークフローの変更が必要だった。変更後はインデックスに新バージョンがあれば取得され、workflow の変更や既存依存の更新は不要となる。

同件では通常の SIMD マスクの初期化も調整し、新版 PTOAS に適合させた。

1.4 レビュー中 16 件：PTO ベクトル化と正形状仮定が進行、T.reshape のサイレント NaN は修正待ち

メインリポジトリのレビュー中更新は計 16 件。PTO 方向では #4523 があり、T.Parallel を PTO にベクトル化し、条件分岐とレーン内で均一なシリアルループをカバーする。#4524 は ptoas 内で vdiv を使用するよう変更し、#4522 はマルチカーネル PTO コンパイルの補助シンボルを重複排除する。

性能方向では #4526 があり、バッファ形状が正である前提で冗長な保護を削除する。修正方向は 3 件。#4519 は examples/conftest.py に欠けている default_target_is_cutedsl を補う。#4520 は from __future__ import annotations 下で @T.prim_func デコレータが失敗する問題を修正する。#4521 は bfloat16 スカラーの min/max を float オーバーロード経由にする。

当日新規オープンの issue で最も重要なのは #4525。T.reshape が T.StridedTensor に作用するとストライドを失い行間パディングを読み取り、出力がサイレントに NaN になりエラーを報告しない。この件にはまだ修正 PR がない。

情報源： https://github.com/tile-ai/tilelang/issues/4525。

2. マルチバックエンド対応（昇騰 / 海光 / 摩尔線程 / 沐曦）

2.1 摩尔線程 14 件を一括コミット、MP31 に W4A16 SQMMA と 188 KiB 共有メモリガードを追加

14 件の PR は 5 種類の作業をカバーする：低精度 MMA のリーガライズ、TME アクセスとバリア、言語面オペレータ、高速数学スイッチ、検証用例。#19 が基盤であり、残りの多くはこれに依存するか同一スタックであると宣言している。

#19 の要点は fragment-A レイアウトの SQMMA GEMM リーガライズであり、同時に共有メモリ上限を 188 KiB に設定し、超過時は拒否する。#25 はその上にネイティブ W4A16 を追加し、int8/uint8 → fp32 の累積リーガライズを提供する：ハードウェア側では int32 SQMMA で累積し、その後ロスレスで fp32 に変換する。#25 はさらに Hilbert2D スレッド番号再配置を非方形 tile に一般化し、インターフェースは T.use_swizzle(..., order="hilbert") である。

#21 WarpFirstAllReduce、T.reduce_prod、および2バリアのマルチwarp一次元スキャンを追加し、さらに共有メモリ帯域幅に基づくモデリングを行うTIRパスを追加した。#24 はwarp専用TMAバリアを修正し、squad間の部分同期を各squadの128スレッドバリアに引き下げた。#26 はコンシューマ側のマルチwarp AllReduceもMP31の部分バリアに引き下げた。

#14 はint8/uint8/int16/int32ブロードキャスト用のパック整數ベクトル構築を補完した。#17 は__launch_bounds__、annotate_min_blocks_per_sm、-O3を復元した。#18 はTMEカーネルに終了時のtme_flush()を追加し、#20 はFP8 TME記述子を有効化し、自動TMEの16バイト内枠アラインメントを制約した。

言語面では#23のソートファミリが本批次で最も完全な一筆である。実装は「元のインデックスが小さい者を優先」とする厳密な全順序を行い、torch.sort(..., stable=True)およびtorch.topkと整合する。float32、float64、float16、bfloat16、int32、int64、一次元と二次元、昇順・降順、任意長をサポートする。バッファはshared、fragment、globalの三種類をカバーする。2の冪長で共有バッファをインプレースソートする場合、追加の共有メモリを消費しない。

2.2 昇騰サブリポジトリはキャッシュのアダプタライブラリパスを修正、HF32とUB列ストアは審査中

tile-ai/tilelang-ascendのデフォルトブランチascendc_ptoは調査期間内に1コミット。#2002が14:51にマージされ、#1999レビューで指摘された問題を修正した。ディスクキャッシュからカーネルをロードした後、adapter.libpathが復元されずNoneのままになる。その結果、このパスに依存してサブプロセスで動的ライブラリを再ロードするテストが、ctypes.CDLL("None")でOSErrorをスローする。

修正方法は、CythonとCtypesの2つのアダプタのfrom_databaseにそれぞれパス復元を1行追加し、回帰テストを新設した。計算、同期ロジック、キャッシュヒット方針はいずれも変更していない。

審査中には計算関連の2件がある。#2037はgemm_v0でHF32モードを公開しテストを拡充し、#2025は昇騰UBの列ストアとDMAサイズ計算を修正する。

2.3 MLIR昇騰はCANNバージョン差異をmasterへ移植、L0アドレス空間はmlir-dialectに配置

#274が17:13にmasterへマージされ、主リポジトリの#4399と同一のパッチであり、18ファイルが完全に一致する。問題記述は2つの実証を示す。第一に、CANN 9.1のストライドGM↔UBコピーAPIは32ビットのブロックカウントを16ビットに切り詰める。第二に、powf(-2.0f, 2.0f)はCANN 9.1.0上でNaNを返す。修正方法は、生成コードが引き続きSDK関数名を使用し、影響を受ける呼び出しを互換レイヤに統一路由する。DMAブロックカウント、行列コピーパラメータ、HF32丸めモード、INT32アトミック操作、スカラーGM読み取りをカバーする。

#252は同日マージされたが、ベースブランチがmasterではなくmlir-dialectであるため、masterのコミット履歴には計上されない。この一筆はtl.allocにTL_L0A、TL_L0B、TL_L0C、TL_L1の4つのアドレス空間を追加する。

審査側では、#261がtl.vreluを追加し、TLからHIVMへの下降とテストを示す。#253はreduce_sum、reduce_max、reduce_minの3つの帰約とそのHIVM下降を追加する。

3. エコシステムと採用側（TileOPs オペレータライブラリ / TileFoundry / FlashQLA）

3.1 TileOPs は10件、3箇所の 0.1.15 性能回収が同日に着地

tile-ai/TileOPs メインブランチの調査期間内に10件のコミットがあり、すべて性能またはテストであり、新規オペレータはない。3本のラインはいずれも TileLang 0.1.15 がもたらした性能損失を回収している。

1本目は dropout。#3181 は16ビット行の dropout が 0.1.15 以降13%から16%遅くなったと報告している。原因は T.rng_rand_float() が T.Parallel でベクトル化された後、1つのベクトルが1回のサンプリングを共有することである。0.1.15 はさらに16ビットベクトルを8要素から4要素に狭めた。#3187 は各要素が独立にカウンタから32ビットの Philox4x32-10 値を取得するよう変更し、上位16ビットはスレッドの初回サンプリングを使い、下位16ビットは上位ビットが閾値と等しい場合にのみ追加サンプリングする。この変更は同時にベクトル内のマスク相関を排除し、数値も相関から独立へと変わった。

2本目は W4A8 プリフィル。#3172 は各 tile 反復の冒頭でコンシューマ warp に T.sync_warp() を補う。従来は ptxas が warp が K ループの箇所で収束済みであることを証明できず、リングバッファの stage インデックスと WGMMA 記述子をベクトルレジスタに残し、毎回の WGMMA 前にユニフォームレジスタへコピーしていた。結果として R2UR が20から52に増え、4つの形状で10%から13%遅くなった。

3本目は RoPE。#3173 は段階的 RoPE を (tokens, sides) グリッドによる発行に変更し、各ブロックが1回の一次元バッチ書き込みで行全体を書き戻す。従来は 8 KiB の行が16回の tensor-map 書き込みに分割され、しかも毎回のテーブル参照に境界チェックが付いていた。実測では gptj-6b のプリフィルが15.440マイクロ秒から15.264マイクロ秒に短縮された。

3.2 DeepSeek-V4-Flash のプリフィルで RoPE 行コピーとウィンドウリングコピーを除去

#3186 は2箇所を変更する。圧縮層の RoPE テーブルは圧縮比に応じて各位置のコサインとサインを事前保存し、圧縮器のプリフィルは RoPECosSinFwdOp に毎回の呼び出しでコピーされるストライド付きスライスを渡さなくなる。プリフィルの最後に window_size 行の KV を書き込む際、従来は arange、剰余取得、gather、scatter の4ステップを踏んでいたが、現在は2回のスライスコピーに変更された。

テスト側には256トークンのプロンプト、2つの完全なウィンドウのケースが追加され、そのリング書き込みはスロット0から始まる。

3.3 Qwen3.8-27B の6ヘッドクエリグループが warp 専用 GQA カーネルへ

#3174 が解決するのはグループ幅の制約である。GQAPagedFwdWSKernel は従来、1つの KV ヘッドのクエリグループ全体を128行の tile に詰め込み、各ヘッドが 128 // group 行を占めていた。これでは1、2、4、8、16ヘッドまたは16ヘッド超のみがサポートされ、それ以外の組み合わせは gqa_paged_varlen_kernel にフォールバックする。Qwen3.8-27B の6ヘッドグループはまさにフォールバック分岐に該当し、24個のクエリヘッド対4個の KV ヘッド、head_dim 256を持つ。

新実装では1つの tile に1つのヘッドグループのみを置き、_tile_heads はクエリグループを整除でき、かつ各ヘッドが8行の swizzle アトムを満たす最大の2の冪を取る。Qwen ではすなわち2である。1つの KV ヘッドのグループは slices に従って複数のヘッドグループに分割され、それぞれがワークアイテムとなり、プロデューサは group_id // slices という KV ヘッドの K、V および回転後の key 列をロードする。

審査側には同日、体系的なシリーズが現れ、計6件である。#3189 から #3194 までのテーマはすべて「ストライド付きビュー下でのインプレース読み取り」である。BMM の a と out、CausalConv1d の x、RMSNormGated の x と z、PagedKVCacheWrite の k と v など6箇所に関係する。他に #3195 は Qwen3.8-27B の positions を各ステップで1回だけ構築し、アテンション層ごとに再構築しないようにした。

3.4 MXFP4 グループ化 GEMM を CTA ごとの tile プレフィックスによるエキスパート探索に変更

#3177 はタスク定位のオーバーヘッドを処理する。共有の task_walk はエキスパートごとに前進し、各ステップで1回の依存グローバル読み取り、連続区間では2回となる。そのため各 CTA はレイアウト内のすべてのエキスパートに対してコストを支払い、空のエキスパートにも同様に支払う。

追加された table_task_walk により、各 CTA は各エキスパートの行 tile 数を一度だけ合算して共有メモリに入れる。その後、warp shuffle でエキスパートの和の区間をスキャンし、エキスパート数がブロック内スレッド数を超える場合は、さらに 1 つの warp で各セグメントの総和をもう一度スキャンする。最後に各 warp は 1 回の ballot で最大 1 warp 幅のエキスパートまで進む。

3.5 サンプリング、埋め込み、KDA と CUDA Graph 資格テストを同日マージ

#3184 は top-p 行確率が 1 のケースを処理し、行全体をパススルーして保持キーを 1 回だけ取るように変更。#3188 は通過率が許す場合、幅広埋め込み呼び出しを 2 warp の CTA 単一波で完了させ、CTA ごとに 1 warp という保守的な分割で実行しないようにした。

#3179 は値主順序の KDA デコードが状態が FP32 上限に近づくと発散する問題を修正し、有限に保つように変更。#3175 は 2 つのモデルそれぞれのデコードステップオペレータごとに CUDA Graph キャプチャ資格テストを実施。#3176 はタイトル編集後にラベルが同期しない問題を修正し、GITHUB_EVENT_PATH を読むように変更。

3.6 TileFoundry はバリアブロードキャストのコード生成を修正、シャードバリアは直接拒否に変更

#368 は local_tensor 改名の残骸を修正するほか、2 つの座標分岐も処理した。これらも同様に既に存在しない関数を発行するが、現在到達経路はない：#186 以降、型推論はポインタビュー上の座標付きを拒否し、すべての pass はポインタからのみ TensorView を構築する。

5. トレンド観察

  1. 摩尔線程のこの14件の性質はパッチではなく、MP31バックエンドを一気に「低精度が使用可能、集合通信が使用可能、言語面が揃っている」状態へ押し上げるものである。根拠は3つ。W4A16とint8累積がいずれもハードウェア命令層で合法化された。AllReduceにはすでに3つの実装があり、warp先頭、部分バリア、squad間分割を含む。ソート系はPyTorchの安定性セマンティクスに直接整合する。この組み合わせは通常、バックエンドが推論オペレータライブラリを受け入れる準備の前に現れる。

  2. 昇騰はすでに主リポジトリを常態的な入力に変えている。調査期間内の主リポジトリ3件はすべて昇騰タグ付きで、性質もそれぞれ異なる。1件はAPI能力（host-mappedバッファ）、1件はコンパイル期の複雑度（InsertSync距離の区間化）、1件はCIサプライチェーン（PTOASをPyPIからのインストールに変更）。同時に12件の新規欠陥がRNGとDeepGEMMに集中しており、カバレッジが数値詳細層にまで入っていることを示す。

  3. TileOPsは0.1.15の性能回帰の回収を担っている。3つのライン（dropout、W4A8 GEMM、RoPE）はいずれも0.1.15のコード生成変化に起因し、いずれも具体的なパーセントまたはマイクロ秒数で着地している。これはコンパイラ側の変更にはオペレータレベルの回帰ベースラインで受け止める必要があることを示唆する。さもなければ損失は1バージョン遅れて初めて発見される。

  4. ターゲットは端末側へ拡張。Apple ANEのcodegen PRがマージされれば、TileLangのターゲット面はGPUと国産NPUからスマートフォンおよびタブレットのニューラルエンジンへ広がる。実装経路はTIRをタスク記述子へ降ろし、それをベンダーコンテナへパッケージングする。これは昇騰や摩尔線程が取る「ベンダーC++を生成して再コンパイル」路線とは異なり、別の実現方式である。

  5. RISC-Vの4情報源は2期連続でゼロ変化。TVM路線とMLIR路線はいずれも前号引用のままで、SOPHGO TPUのブランチ数も増減なし。この方向は依然として低調で、現時点ではトレンドを構成しない。
