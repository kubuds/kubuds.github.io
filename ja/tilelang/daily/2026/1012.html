1. 核心プロジェクトの進展

1.1 メインリポジトリ：SM121（DGX Spark）がブロックスケーリング MMA を点灯；CuTeDSL フェンス選出とパラメータ同一性の修正（10-10 ~ 10-11）

日付：2026-10-10、2026-10-11　情報源：SM121 ブロックスケーリング MMA（#3430）／ CuTeDSL フェンス選出（#3400）／ NVRTC / CuTeDSL パラメータ同一性（#3414）

  • SM121 点灯（#3430、10-11 00:32 マージ）：SM121（GB10、DGX Spark）は実際には SM120 級の warp ブロック・スケーリング MMA をサポートするが、tl::sm120_mma_sync_blockscaled は CUTLASS_ARCH_MMA_SM120A_ENABLED（__CUDA_ARCH__ == 1200 の場合のみ定義）しかチェックしないため、sm_121a ではすべてのブロック・スケーリング MMA が OMMA.SF ではなく BPT.TRAP にコンパイルされてしまう。本コミットでは arch とファミリーの両方で SM120 / SM121 ターゲットを受け入れるよう変更し、NVF4 テストは SM12x ファミリーでゲートし、CuTeDSL TMA アーキテクチャ・テーブルは sm_121 / sm_121a を通過させる。作者は DGX Spark（ドライバー 580.178.04、CUDA 13.0）で実測パスを確認。

  • フェンス選挙（#3400、10-10 10:47 マージ）：sync_grid() は以前、すべての tid.x == 0 のスレッドを選挙していたため、2D / 3D スレッド・ブロックでは複数のスレッドが同一ブロックの到達を重複して発行し、フェンスが早く解除される可能性があった。現在は物理スレッド (0, 0, 0) のみを選挙し、カウンタ / 世代プロトコルと協調起動は不変。回帰テストは 1D / 2D / 3D グリッドと重複再利用をカバー（RTX 5090、CuTeDSL 4.7.0）。

  • パラメータ同一性（#3414、10-10 13:58 マージ）：NVRTC と CuTeDSL ホスト・ラッパーは従来、生の Var 名でシグネチャを生成し、表示名でパラメータを照合していたため、同名（stream、device_id など）やデバイス側での改名がクロストークを引き起こしていた。現在は Var 同一性に基づいてラッパー・パラメータ名を割り当て、位置 ABI を保持する。CuTeDSL は同一カーネルを異なるスカラー・バインディングで繰り返し呼び出せるようになり、同名の shape / stride シンボルを区別できるようになった。

1.2 メインリポジトリ：GEMM dtype ホワイトリスト完結——未サポートの組み合わせは CUDA codegen 前に拒否（10-12）

日付：2026-10-12　情報源：GEMM dtype ホワイトリスト（#3245）

  • 一部の T.gemm オペランド dtype の組み合わせ（例：bf16 x bf16 から fp16）は以前フロントエンドで受け入れられ、nvcc 内で不透明な static_assert により失敗していた（欠陥票 #3004）。本コミットでは Ampere / Ada mma.sync パスに明示的な dtype ホワイトリストを追加し、フロントエンド（tileop/gemm）と C++ 命令選択の両端で強制し、未サポートの組み合わせは CUDA codegen 前に拒否され明確なメッセージを出す。

  • 負例 1 件と正例 3 件の回帰テストを添付。サポートされる組み合わせと非 Ampere ターゲットの動作は不変。本コミットは 10-12 01:21 にマージされ、調査期間の締め切り前で最新のコミットとなった。

1.3 メインリポジトリ：For ステップ、JIT 出力インデックス、popcount、ビットリダクション、テスト基盤の 5 件が確定（10-10 ~ 10-11）

日付：2026-10-10、2026-10-11　情報源：For ループ・ステップ（#3427）／ JIT 出力インデックス（#3318）／ popcount（#3300）／ ビットリダクション（#3332）／ テスト基盤（#3313）

  • For 步長（#3427、10-10 12:54 マージ）：ループキャリー衝突分析は従来、步長を常に 1 とみなしていた（コメントの「デフォルト 1、未指定時」と矛盾）。非単位／符号付き步長では有効イテレーションペアの判定が歪んでいた。現在は明示的な步長に従ってイテレーションペアの範囲を縮小し、CUDA と HIP codegen はいずれも步長を保持して CodeGenC に発行を委譲し、展開ループの字句的割り当てスコープにも配慮している。
  • JIT 出力インデックス（#3318、10-10 12:02）：out_idx=[-1] は引数の個数が異なるカーネル間で再利用されると正規化によって汚染される（2 引数カーネルが [-1] を [1] に正規化し、4 引数カーネルがその後誤って入力スロットを占有する）問題があった。現在は正規化の前に呼び出し側のリストをコピーし、引数の個数に等しいスカラーインデックスを拒否して、有効な区間を提示する。
  • popcount（#3300、10-10 12:02）：符号付きおよび 8 / 16 ビットの狭い整数の CUDA への降下を補完した。まず元の幅で符号なしに変換してから拡張する（int8(-1) は 32 ビットではなく 8 ビットとしてカウントする）。64 ビットは __popcll を通す。8 種の dtype の回帰をカバーする。#2984 を修正し、H100（CUDA 13.0）では 16 項のテストがすべて通った。
  • ビットリダクション（#3332、10-11 14:13）：reduce_bitand / bitor / bitxor は従来、ターゲットバッファのみをチェックし、浮動小数点のソースを通過させていた（[1.0, 2.0, 4.5, 8.9] は警告なしに静かに 1 2 4 8 = 15 に切り捨てられていた）。現在はソースとターゲットを統一して、整数 / ブールの規則に従って拒否する（refs #3301）。
  • テスト基盤（#3313、10-11 18:25）：共有 IR 検査ヘルパー（ノード収集、正確なオペレータ呼び出しカウント、記号ごとの外部呼び出し収集）を新設し、issue テストと transform テストを局所的な走査コードからヘルパーへ移行した。lower_ldgstg テストには構造アサーションを補い、选定された transform テストは sm_90 ターゲットを固定し、利用可否によるスキップを追加した。

1.4 メインリポジトリ新規オープン：Host IR JIT の 2 件と並列コンパイル、部分ウェーブリダクションなど 9 件（10-10 ~ 10-11）

日付：2026-10-10、2026-10-11　ソース：ホスト IR 統一（#3473）／ 直結 Host IR JIT（#3481）／ 並列 JIT コンパイル（#3476）／ 部分ウェーブリダクション（#3478）

  • コンパイルスループット（#3476）：autotuner が相互に独立した JIT 構成を並列コンパイルし、大きな構成空間のチューニングのウォールクロック時間を圧縮する。
  • 修正系の新規オープン：部分ウェーブスカラーリダクション（#3478）、ホスト式の強制変換グループ化（#3477）、実行時にしか行程カウントがわからないパイプライン末尾の展開（#3472）、昇騰サンプルのターゲットを任意化（#3474）；2 件の WIP（#3482 スパース逆伝播の原子的累加、#3483 MoE の陳腐化ルーティングエキスパート）が 10-11 深夜にオープンされた。

1.5 TileFoundry：スパースデコードが TIR を貫通；mesh スコープ修正（10-10 ~ 10-12）

日付：2026-10-10、2026-10-12　ソース：スパースデコードが TIR を貫通（#223）／ mesh スコープ（#220）／ パーサー属性（#221）
