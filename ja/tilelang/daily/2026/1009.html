今日の重点：復工日のマージラッシュ——メインリポジトリは1日で12件のマージを完了、昇騰「三点セット」の復帰完了（10-08/10-09）

日付：2026-10-08、2026-10-09　出典：メインリポジトリ PR リスト／ FP32 Reduce2D（#1852）／ K プールバリア削減（#3419）

連休後最初の完全な営業日において、tile-ai 組織はマージと新規オープンが各21件；うちメインリポジトリ tilelang は1日で12件をマージ（日付をまたぐ3件の深夜修正を含み、うち11件が本レポートの新規収録）、TileOPs は4件をマージ、昇騰適配リポジトリは5件をマージ——9月下旬以降で最も集中的なマージ日となった。注目すべき2つの主線がある：

  • メインリポジトリのリズムが全面的に回復：マージは五つのカテゴリにまたがる——正確性修正（Profiler 同期、ネスト LDG 述語、JIT キャッシュ、量子化マスク、スパース GEMM）、性能（K プール障壁削減）、リファクタリング（math codegen ディスパッチ分割）、CI（Windows wheel 高速化）、昇騰コード生成（行指令サポート）；最も遅い三件は 10-09 午前 0 時前後に着地し、「零点をまたぐ」連続マージ帯を構成している。
  • 昇騰「三種の神器」の復帰が完了：適応リポジトリ Vector マスク再利用（#1850）／ 依存ライフサイクル同期（#1851）／ FP32 Reduce2D とワークスペース契約（#1852） の三件のボット署名 PR が午後に相次いでマージされた；これに既に記録済みの C/V 帰属（#1848） と バッファドメイン検証（#1786） を加え、元の #1829「Part 2」分割後の五件がすべて着地——この 9 月下旬に一括ロールバックされた 950 特性ラインが復帰を完了した；同日 CI 側では CANN 9.3 自前ビルドイメージと a5 runner 移行の二件が起票された（2.2 参照）。
  • 高速化の側面：K プール障壁削減（#3419） はデコードチェーンの十一件のメタデータ検証述語を一回のデバイス・トゥ・ホスト同期に統合し、幅 32 の warp shuffle で五段の Hadamard-128 ステージをカバーする——デコードヘッドのレイテンシがオペレータカバレッジに続く新たな最適化ターゲットとなっている（詳細は 1.2 参照）。

1. コアプロジェクトの進展

1.1 メインリポジトリ深夜バッチ：Profiler デバイス同期、ネスト LDG 述語保持、JIT テストキャッシュ分離の三件が入帳（10-09）

日付：2026-10-09　情報源：Profiler 検証同期（#3457）／ ネスト LDG 述語（#3390）／ JIT キャッシュ分離（#3450）

  • Profiler 検証デバイス同期（#3457）：profiler 検証テンソルが無条件に CUDA を同期する問題を修正（欠陥票 #3410）——検証テンソルはそれが存在するデバイスに従って同期し、全量 CUDA 同期をトリガーしなくなった；PR は同日 22:58 に起票され、約一時間後にマージされた。
  • ネスト LDG 述語保持（#3390）：述語化 LDG が外層のストア述語を無視する問題を修正（欠陥票 #3381）——ネスト読み取りは外層の述語制約を保持する。
  • JIT テストキャッシュ分離（#3450）：テストキャッシュを分離し、ディスクキャッシュヒットパスのテストケースカバレッジを補完し、テスト間のキャッシュクロストークを排除した。
  • 三件は 10-09 午前 0 時前後に相次いで入帳し、それ以前に深夜マージされた #3447 とともに、ウィンドウ末尾の「零点をまたぐ」マージ帯を構成している。

1.2 メインリポジトリ：K プール Hadamard 障壁削減がマージ——デコード検証を単一のデバイス・トゥ・ホスト同期に統合（10-08）

日付：2026-10-08　情報源：K プール障壁削減（#3419）

  • 目標：完全な K プールデコード呼び出しのレイテンシを低減する。十一件のデコードメタデータ述語を固定形状テンソル上のバッチ評価に変更し、ブール結果を一度にホストへ返送する（単一のデバイス・トゥ・ホスト同期に統合）；圧縮とデコードチェーン上の五段の Hadamard-128 ステージは幅 32 の warp shuffle 実装に切り替えた。
  • エンジニアリング境界：ソートと隣接値チェックは重複する末尾ブロックとキャッシュ宛先の発見に用いる；パディングとプール完了チェックは元のエラー優先度を維持する；キャッシュインターフェース、エラーメッセージと優先度、BF16 丸め境界、FP8 スケーリングと順序付き末尾更新の契約は不変。
  • 系譜：既にマージ済みの GLM-5.3 独立パイプライン（#3254）を引き継ぐ——K プールパスにとって、「同期回数と障壁オーバーヘッド」はオペレータレベルの最適化と並ぶ性能の抓手となっている。

3. エコシステムと採用側

3.1 PTO-ISA：量化教学の新リポジトリ——torch/ASC/PTO の三档 22 変体の階段（10-08）

日付：2026-10-07、2026-10-08　情報源：tilelang-puzzles-ascend リポジトリ／ README

  • PTO-ISA 組織が新たに tilelang-puzzles-ascend 教学リポジトリを設置（10-07 夜に作成、10-08 に 9 コミットを集中的に実施）：四つの NPU 量化カーネル（cast_back、per_token_cast、per_block_cast、per_channel_cast）を中心に、三档の同構実装を提供——torch 档（CPU リファレンス、前提知識）、asc 档（Ascend SIMD、T.simd）、pto 档（PTO VMI、T.vmi）；各档 22 変体、番号は一対一に対応し、直接 diff 可能で、各変体は生産構成を一つだけ追加する。
  • 統一エントリ python -m harness.check（puzzle モードを含む：実装を穴埋めにし、ヒントを残す）；全カーネルはデバイス上で実行され、torch 档と突き合わせ検証；devcontainer を備える（イメージ構築時に固定バージョンの TileLang をクローン）。
  • 本体リポジトリ v0.1.15 の PTO バックエンド（#3310）、審査中の PTO 実行ルーティング（#3316） と配套を形成——PTO の第二コードパスに初めて体系的なハンズオン教材が登場し、教学が最も常用される量化カーネルシナリオへと沈み込む。

5. トレンド観察

5.1 昇騰 950：「差し戻され」から「分割コミットで復帰完了」へ

  • 9 月下旬に 950 の機能線は一時まとめて差し戻された（TVM の範囲外読みが真因で、連休前に特定し 1 行のパッチで元に戻した）。休暇と業務再開期は「分割コミット」方式に切り替えて推進し、C/V 帰属、バッファ領域検証、マスク再利用、同期ライフサイクル、Reduce2D の 5 件が 10-08 午後にすべてマージされた。同日 CI 側で CANN 9.3 自前ビルドイメージと a5 runner 移行が起票され、MLIR 側でイメージリリースが起票された——950 の「機能、基盤、コンパイル経路」の三面が同時に進行。復帰は原点回帰ではなく、CI とデバッグ能力を携えての再装備である。
  • 慎重な見方：950 バックエンドは v0.1.15 での公開リリースからわずか 9 日で、まだパッチ版はない。PTO 第二経路（#3316 実行ルーティング、#3330 DeepGEMM コード生成）は依然として審査中。「適応リポジトリ」から「メインリポジトリ原生 + PTO 二重経路」への移行は現在進行形である。

5.2 レビューの堰き止めとテストの拡大：オープン PR 174 筆に対して夜間ベンチマーク 1939 項目

  • メインリポジトリのオープン PR が連休前の 116 件から 174 件に増加（+58）。調査期間内に新規 11 件、マージ 12 件——「開多く合少なし」が継続し、レビュー帯域が次バージョンのリズムを左右する鍵となる変数。本日の 12 件のマージは、業務再開後のレビュー加速の初期シグナルと見なせる。
  • もう一方で、夜間ベンチマークは連休前の 1355 項目から 1939 項目に拡大した後も高水準を維持し、ゼロ失敗・ゼロスキップ——テスト資産とケースガバナンスが同時に拡張し、大量の審査待ちキューに対してマージ前の回帰基盤を提供している。

5.3 空白とリスク点

  • 沐曦、摩尔線程の公式リポジトリは沈黙。採用側（TileKernels、FlashQLA）は調査期間内にプッシュなし——エコシステムの増分は tile-ai と PTO-ISA の 2 組織内部に集中している。
  • TileOPs の審査中 4 件は注意力と正規化（線形注意力デコード、GroupNorm、ページド GQA RoPE）に集中——休暇中の規模集中スプリント後の修正・適応期の特徴。
  • メディア側（中英語）は引き続きカバレッジゼロ。本テーマの公開ナラティブは依然として GitHub のファクトソースが主体である。
