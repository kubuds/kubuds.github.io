TileLang ウィークリーレポート (2026-10-12 ~ 2026-10-16)

2026-10-16 Kubuds

レポート期間：2026年10月12日（月）から10月16日（金）まで、計5営業日、5期分のデイリーレポート素材 素材情報源：本誌のTileLang動向デイリーレポート5期分（10-12、10-13、10-14、10-15、10-16）。さらにtile-ai組織29リポジトリの168時間ウィンドウでの補充調査、夜間パイプライン6スナップショットのテスト結果の逐一再計算、および各リポジトリのリリースメタデータの再確認による（詳細は付録を参照）

1. 今週の要聞

  • メインリポジトリのROCmラインが4日連続で収束、DeepSeek新アーキテクチャカーネルが第3の収束ラインに（10-13 ~ 10-14）：10-13にDeepSeek NSAのフォワード/単一トークンデコードの64 lane単一波実装（#3152、+111/-2）とflash-decodingのLDS/VGPR予算適応型タイル（#3149、+82/-5）をマージ；10-14未明にさらにmHC（多様体制約付きハイパーコネクション）の前処理/後処理カーネル（#3156、2ファイル +83/-6、HIP側は完全な64 lane波面での分担に変更し、FP32混合重みをBF16に変換してMFMAに供給）とsafe-gated KDAデコード例（#3249、+360、GLM-5.3-Flash TP8専用化設定を含む）をマージ；10-14にはさらにcumsum/cummaxの64 laneセグメント幅修正（#2326）を実施。4件はいずれも「デバイスの現実に応じた適応」を指向：gfx942の波面サイズ、MFMA入力型、LDS/VGPR予算を項目ごとに清算し、ROCmサポートは「動作する」段階から「新アーキテクチャのリリースと同期する」段階へ移行。

2. コアプロジェクトの進展（メインリポジトリ tilelang）

バージョンとリリース

コンパイラ、実行パスと言語層

  • PTO 実行ルーティング（#3316、10-15 マージ）：実行感知型のターゲット正規化フック（BackendContext の生成箇所に設置）を新設。Ascend 専用ノーマライザは解析前にネイティブ Ascend ターゲットを PTO ターゲット変種へ特化し、arch などの属性を保持する。デバイスコード生成は PTO_CODEGEN と target.build.tilelang_pto_without_compile に切り替え。ドキュメントには TILELANG_DEFAULT_TARGET=ascend に TILELANG_EXECUTION_BACKEND=pto を加えた等価構成を示す。テストはコンテキスト解析、ターゲット属性の保持、キャッシュディスパッチ、環境変数による選択をカバーする。
  • PTO DeepGEMM codegen（#3330、10-14 マージ）：制御フローをまたいで tl.ascend_set_mmad_direction を追跡し、有効な方向を MAD 命令にエンコード、競合する方向下で到達可能な MAD を拒否する。SIMD 後のインクリメンタルロード、混在 AIC/AIV カーネルの UB アドレスから PTODSL ポインタへの変換、動的な L0C→UB 次元とストライド、int16 符号付きパッキング MX scale をサポート。自己申告では DeepGEMM PTO の 15 ケース中 14 ケースがパスし、test_bf16_m_grouped_padding は依然として PTOAS VPTO バックエンドが FP32→BF16 変換を合法化できない問題でブロックされている。
  • 独立 AIV 実行（#3485、10-14 マージ）：Ascend AutoSchedule を拡張し、AIV0 と AIV1 が sid 依存の下で異なる作業（交互の終了処理、逆量子化と終了処理の分担、互いに素な入力パーティション、ループ内のロール切り替え）を実行できるようにする。AssignCore をレイテンシ見積もりとスケジューリングの前に前倒しし、AIV ローカル UB バッファとスカラー状態に独立したアイデンティティを確立する。
  • C 系 codegen 共有基底クラス（#3289、10-14 マージ）：CodeGenTileLangCBase が CUDA、HIP、CPU C、Ascend C++、Metal、C ホストコード生成を統一。T.import_source、T.Kernel(prelude=...)、pragma_import_c において、ソーステキストが末尾改行を欠く場合やバックスラッシュで終わる場合に次の生成行を飲み込んでしまう問題を修正。検証：焦点回帰 83 パス、codegen と launch スイート 405 パス。
  • CPU グリッド並列（#3109、10-14 マージ）：アノテーション付き CPU grid ループを OpenMP 並列ループに変換する MaterializeCPUParallelGrid を新設。ループ collapse、スレッド数設定、最小 trip 数しきい値、割り当ての降下を併せて実装し、Linux / macOS / Windows のコンパイルフラグを整備——CPU バックエンドが初めてグリッドレベルの並列性を備えた。
  • Host IR ラインは全週レビュー中：CUDA と CuTeDSL の実行パスを統一する #3473 と、Host IR JIT 直結にネイティブキャッシュを加えた #3481 は 10-10 の起票以降マージが見られず、依然としてメインリポジトリ最大のレビュー中方向性である。
  • PTO ファミリー 7 件（10-15 からレビュー中）：tvm_ffi 実行バックエンド（#3516）、T.Parallel から PTO VMI へのベクトル化（#3512）、SS buffer（#3514）、一部 L0 コピーの明示的 pitch（#3511）、NZ バッファの UB→L1 部分コピー（#3530）、PTO Ramp 値を型ごとにベクトル発行（#3535）、SIMT VF 内ベクトルローカルアクセスの修正（#3523）。うち SS buffer は 10-16 午前にマージ（#3514、デイリーレポートの締め切り後に補足調査で確認）。

パフォーマンスとハードウェアマトリクス

  • SM121（GB10 / DGX Spark）：#3430 により、tl::sm120_mma_sync_blockscaled が arch とファミリーに応じて SM120 / SM121 を同時に受け入れるようになり、NVF4 テストは SM12x ファミリーでゲートされ、CuTeDSL TMA アーキテクチャテーブルは sm_121 / sm_121a を許可する。
  • SM120 ブロックスケーリング：MXFP8（kind::mxf8f6f4、1X、UE8M0）と MXFP4（mxf4nvf4、2X、UE8M0）の拡張（#3495、+884/-51、FP32 累積、K 要素 32 個ごとに 1 スケール）と全 f8f6f4 オペランドファミリー（#3099）が引き続き審査中。
  • ROCm：要聞の 4 件以外に、10-15 の scan 波面修正（#2326）により cumsum / cummax がターゲット波面幅に応じてセグメント幅を選択するようになり、32 スレッドブロックはコンパイル時に 64 lane テンプレートから除外される。B300 上の CUDA scan スイートは 17 件通過。
  • SM89 バッチ性能ポリシー：MLA デコードはバッチとヘッドブロック数に応じて 2/4/8/16 の KV 分割を選択（#2511：単一リクエスト bf16 4k 0.158→0.034 ms 約 4.6 倍、32k 1.170→0.162 ms 約 7.2 倍）、KDA プリフィルは 16 列値タイルで分割（#2510：4k/32k/64k で 22.9%/19.8%/18.5% 削減）、スキャン widening（#2574：4096~16384 token を 8 値ヘッドから 16 値ヘッドに拡張、19 行で 2.5%~19.7% 高速化）。
