TileLang ウィークリーレポート (2026-09-30 ~ 2026-10-07)

2026-10-07 Kubuds

レポート期間：2026年9月30日（水）から10月7日（水）まで、計8日間——国慶節休暇特別集約期間（10月1日から7日までは毎日デイリーレポートを休刊、本号は休暇統合版） 素材出典：本号は毎日発行のTileLang動向デイリーレポートの休暇前最終号（2026-09-30、調査期間は当日07:00まで）。休暇中の動向はtile-ai組織（29リポジトリ）の216時間調査期間における実測検証に基づく（コミット、PR、タグとリリース、夜間パイプライン、検証は10-08午後まで延長）。ニュース側は休暇期間（約9日間）の複数組のキーワードによる公開検索（詳細は付録参照）

1. 今週の主要ニュース

  • TileLang v0.1.15が休暇前にリリース：Ascend 950ネイティブバックエンドがバージョンとともに登場（09-30）：北京時間07:31、「Public Release 9/30」と注記されたAscend 950バックエンドの大型PR（#3308、134コミット、379ファイル、+79956/-733）とバージョンアップPR（#3309）が相次いでマージされた。08:29、v0.1.15が正式リリース（リリースページ）。バージョンの4大ハイライト：Ascend 950ネイティブサポート（エンドツーエンドNPUバックエンド：ネイティブコード生成、Cube/Vector自動スケジューリングと同期、SIMD/SIMTハイブリッドプログラミング）、CUDA自動warp特化（役割ごとにTMAロード、MMA計算、ストアを専用warpグループに派遣）、統合ブロックスケーリングGEMM（T.gemm_blockscaledのセマンティクス統合、SM100命令選択とSM120フラグメント拡充）、より表現力の高いPythonフロントエンド（コンパイル時のイテレーションと内包表記）。休暇前のデイリーレポート締め切り時点では2件のPRはまだオープン状態だったが、本号の検証で補完：当日朝にマージされ、リリースページも同時に記録された。Ascend A2/A3サポートはコミュニティがメンテナンスするアダプテーションリポジトリに保持されている。

  • DeepSeekが昇騰向け基盤コンポーネントをオープンソース化、TileLang昇騰版も含まれる（09-30）：9月30日、DeepSeekは華為昇騰算力プラットフォーム向けの基盤コンポーネントをオープンソース化すると発表、TileLang高級言語コンパイルツール、計算ライブラリ、分散通信ライブラリをカバー（報道の口径：NVIDIAプラットフォームのコンポーネントと一対一対応）。組織側の傍証：deepseek-aiの当日、DeepGEMM-Ascend、DeepEP-Ascend、TileKernels、FlashMLA、DeepSelectなど複数のリポジトリにプッシュ記録がある。報道は「DeepSeekの訓練で使用されるすべてのTileLangオペレータには、昇騰上に対応する高性能実装が存在する」と引用している。中外メディアは当日から集中的にフォロー（10組のキーワードで調査期間内に約210件のヒット、詳細は第5章参照）。

  • PTOバックエンドがメインリポジトリにマージ：Ascend 950が同日に2つ目のコードパスを獲得（09-30）：#3310（+11406/-31、36ファイル）が12:08にマージ——ptoターゲットと実行バックエンドの登録、PTOデバイスコードの生成、カーネルラッピングとCythonランタイムインターフェースによる実行、ptoasと畢昇によるPTODSLカーネルのコンパイルに対応；付随するヘルパー関数はGEMM、SIMT/SIMD、同期、ハイブリッドカーネル、キャッシュバイパスアクセス、Philox乱数をカバー。フォローアップのキューは既に10件以上が起票されており（PTO実行ルーティング、インポート分離、DeepGEMMコード生成など）、依然としてレビュー中。

  • TileOPsは休暇8日間で137件をマージ：量子化、サンプリング、線形アテンションの3ラインが制度的に完成（09-30 ~ 10-07）：137件マージ、143件新規起票（別途10-08の業務再開日にさらに2件）；09-30の単日32件がピーク。サンプリングラインは6つのカーネルがマスクから拒絶サンプリングまでの全チェーンで記録完了；線形アテンションラインはGLA、Gated DeltaNet、DeltaNet、Kimi Delta Attention（テンソルコアWY逆算 #2365を含む）が集中的に推進；量子化とGEMMラインはINT4/INT8/FP8の多形態をカバー；カーネルインターフェースのリファクタリング、PyPIリリースパイプライン、READMEの改訂が同時に着地（詳細は第4章参照）。

  • 摩尔線程がMUSA公共0.1.15を整備しv0.1.15+musa.1をリリース（09-30）：単日53コミット（51件がMUSA側の機能、2件が上流同期）——mp31アーキテクチャバッチ（tmeシリーズ、sqmma、wmma、warp特化、キャッシュヒント、peer memoryなど）、ランタイムバッチ（基本ターゲットとバックエンドエントリ、デバイスコード生成、JITラッピング、ipc/vmm、dlpack互換、明示的ストリームなど）；夕方に「Prepare public TileLang MUSA 0.1.15」が記録された後、17:59にリリースv0.1.15+musa.1を打ち出した（前バージョンv0.1.14+musa.1は09-11）。

  • 海光 Hygon 3連続マージ（09-30）：行列ストレージ（gfx946、#14）、multi-XCD Cython 起動サポート（#15）、LDS ポリシー競合修復（#16）——連休前の非同期コピー改善（#13）に続く連続的な推進。海光は本期、昇騰を除いて唯一コード推進のある国産バックエンドである。

  • 夜間パイプライン 12 件のスナップショットが途切れなく：ベンチマークスイートが 1939 項目に拡大（09-30 ~ 10-08）：12 件のスナップショットが日次で産出され、正確性テストケースは 1009 から 1044 項目（テスト組織再構築期に起伏あり）、最新スナップショットは 1027 項目でゼロ失敗。ベンチマーク測定は 1355 項目（39 スイート）から 1939 項目（52 スイート）に拡大。全期間で唯一の失敗は 1 例——10-07 のスナップショットの FFT ケースが CUDA メモリ不足（環境性）によるもので、次のスナップショットで即座に全緑に復帰した。

  • 採用元が同日にフォローアップ：TileKernels v2.0.0 が昇騰サポートを携えてリリース、FlashQLA が v0.1.3 に更新（09-30）：DeepSeek TileKernels が v2.0.0 をリリース（09:58）、README に「Huawei Ascend support」を新規追加：デュアルバックエンドはランタイムが自動選択し、同一の Python API が同時にエヌビディア GPU とファーウェイ NPU で動作する（TileLang 0.1.15+、CANN 9.2.0+ が必要）。Qwen FlashQLA が v0.1.3 に更新（21:02）、sm90/sm100 autocp 係数とベンチマーク更新を添付。採用元と上流のリリースが同日に着地し、連動が検証された。

2. コアプロジェクトの進展（メインリポジトリ tilelang）

バージョンとリリース：v0.1.15 正式リリース（09-30）

  • タイムライン：09-30 07:31、「Public Release 9/30」と标注された #3308 とバージョン番号引き上げ #3309 がマージ；08:29、v0.1.15 リリース——前バージョン v0.1.14（09-02）から28日、既存の月次リリース間隔と一致。
  • Ascend 950 段（リリースノート抜粋）：tilelang.ascend.language と target="ascend"（dav-3510 に対応）を新規追加；同一カーネル内で Cube GEMM と Vector 計算を組み合わせ（T.SimdVF / T.SimtVF 領域）；明示的な UB/L1/L0 ストレージ、タイルコピー、クロスコア転送と MXFP8/MXFP4 ブロックスケーリング GEMM；自動スケジューリング、パイプライン、マルチバッファリング、レイアウト推論と同期挿入；畢昇コンパイル、tvm_ffi と Cython 実行、PyTorch NPU テンソルとストリーム、NPU profiling を統合；サンプルには GEMM、DeepGEMM スタイルカーネル、FlashAttention 順伝播・逆伝播、RMSNorm と FP8 量子化を含む。A2/A3 サポートはコミュニティ維持の TileLang-Ascend プロジェクトに保留。
  • CUDA 段：ロールベース自動 warp 特殊化（環境変数で有効化可能）；SM120 ブロックスケーリング GEMM 拡張（フラグメント常駐 A オペランド、行主序スケーリングフラグメント、奇数 per-warp アトミックグリッド）；T.fma/T.fmul 就近丸め；FP8 スパース MLA 順伝播サンプル（DeepSeek V3.2、Hopper、#3224）；WGMMA/UMMA K パネルストライド修正とスパース MMA 非同期フェンス。
  • 言語、コンパイラとランタイム段：カーネル起動エンコーディング目標中立化；Python コンパイル時イテレーションと内包表記；coalesced_width ヒント化；AllReduce スレッドストライドとリダクション NaN 伝播 dtype 検証；キャッシュパラメータを JSON に変更、CUDA バイナリアトミック公開、ウォールクロックベンチマーク、wheel を GPU runner で検証、性能回帰で CI を失敗させる。
  • ROCm、CPU と Metal 段：ROCm が DeepSeek V3.2 Top-K セレクタ、wave64 Hadamard と GLM-5.3 k プールサンプルをサポート；CPU スカラー GEMM は累算 dtype に従い計算；Metal 32ビットアトミック加算。
  • 互換性注記：T.Pipelined は未使用の sync/group パラメータを削除、T.gemm_sp は k_pack を削除；T.symbolic は非推奨エイリアスに転換（新コードは T.dynamic を使用）；TILELANG_CACHE_VERIFY_HASH 削除、キャッシュハッシュ検証は強制に変更。

休暇中の修正ラインとエンジニアリングの小刻みな步み（10-02 ~ 10-08）

  • 正確性修正：#3361 bfloat16 スカラー引数をサポート（10-02）；#3334 NVFP4 が保持する UE4M3 NaN スケーリングコードワードをデコード（10-03）；#3429 インデックス昇格時に明示的キャストを保持（10-06）；#3441 LDSM コピーで共有領域オフセットを保持（10-07）；#3439 SM89 上の fp8 T.gemm を起動即クラッシュではなくゲート付きエラー報告に変更（10-07）。
  • JIT とテスト：#3435 遅延カーネル構築で可変引数を保持（10-07）；#3443 サポートされていない BF16 スカラーの回帰テストを削除（10-07）。
  • エンジニアリング雑項：#3418 完全に同一の二つのブランチをマージ（10-03）；#3431 pre-commit を自動更新（10-07）。
  • 連休明け最初のコミット（10-08）：#3299 ROCm 上の T.round の最近接偶数丸めを修正——リリース日昼にマージされ、連休後のペースが予定通り回復。
  • 小結：全調査期間で12件のマージ（09-30の3件はリリースバッチ、10-02以降の9件は休暇中の小刻みな修正）、連休前の単週14件と比べやや減少、実質的な増分はレビュー待ち行列に集中（次節）。

  • メインリポジトリ（リリースとバックエンド）：詳細は2章を参照——#3308（950 ネイティブバックエンド）と #3310（PTO バックエンド）が同日にマージ。

  • エンジニアリングライン：カーネルインターフェース化選択（#2321 以降でバッチ化）、命名規範（#2410、#2434）、PyPI の tag 自動リリース（#2359）、README「Built for agents」（#2358）、正確性チェックと夜間カバレッジの統一（#2429）、bench.Runner ベンチマーク再構築（#2470）。foundry プレフィックス付きオペレータの供給バッチが全期間を通じて実施。
  • 判定：4 つのファミリーライン（量子化、サンプリング、注意力、線形注意力）が 8 日間で「実行可能かつ検証可能」な状態に到達し、エンジニアリング面の収束作業（リリース、命名、インターフェース）も同時に集中——生産能力がパイプライン化へと近づいている。

6. トレンド観察

  • Ascend 950 の「Day-1 バージョン化」、マルチバックエンド叙事が転換点を完成：950 バックエンドは「大型 PR＋リリース＋第2コードパス（PTO）＋使用ガイド」のフルセットを v0.1.15 とともに提供し、A2/A3 はコミュニティリポジトリに残留、世代と保守の分業が明確——「マルチバックエンド」が正式に主干能力の叙事となった。観察点：950 実機の性能データとより長周期の保守コスト。
  • DeepSeek と華為が TileLang を国産算力議題の中心へ押し上げ：報道量は歴史的ピーク（約 210 件ヒット）；採用元 TileKernels が同日 v2.0.0 をリリースし昇騰サポートを追加、「上流リリース、下流リリース」の連動がこれほど緊密になったのは初。リスク面：叙事の熱量が検証可能なデータを上回り、エンドツーエンド精度と大規模トレーニング検証は依然として公開待ち。

  • エンジニアリング収束の動きが密集：PyPI リリースパイプライン、bench.Runner、キャッシュ原子リリース、テスト統一と命名規範——ボトルネックは「オペレータを書く」から「リリースと検証パイプライン」へ移行中であり、ライブラリが工程成熟期へ向かう典型的なシーケンス。
