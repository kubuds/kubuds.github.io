今日の重点：Andes がハイエンド RISC-V CPU Cuzco を減速、AI 事業がすでに売上の半分を占める（11-02）

EE Times が 11 月 2 日に台北から報道、Andes の最高技術責任者（CTO）Charlie Su は、同社がハイエンド RISC-V CPU IP「Cuzco」の開発ペースを減速し、エンジニアリングリソースをより成長の速い AI 事業へ移したことを確認した。Cuzco はもともと Andes がデータセンター級ハイエンドコアのために专门に分離した Condor 社のプロジェクトで、2025 年の Hot Chips で公開され、今年の初めに内部に回収された。Su の説明によれば、エコシステムがまずその段階に到達しなければハードウェアにチャンスはなく、AI の路線は成長が速すぎるため、即座に収益を生み出せる場所へリソースを集中せざるを得ないという。

数字の面では、Andes の AI 事業は現在売上の半分を占め、昨年は 30% 成長、今年は 50% 成長を見込む。自社開発のディープラーニングアクセラレータは規模が大きくなく、約 4 TOPS（1 GHz）でコンパイラを内蔵する。AI 収入の主体は、AI チップ企業が Andes の CPU コアを制御、オーケストレーション、データ転送に採用するもので、顧客には Meta、d-Matrix、Fractile、Axelera を挙げた。こうしたライセンスの多くはカスタムコアであり、納期が極めて厳しいことも、内部リソースが引き抜かれた理由である。

Cuzco はキャンセルされていない。Su 氏は、製品化は続ける考えを示しており、名称が変わる可能性はあるものの、スケジュールが長期化しただけで、同社は「ゆっくり進めながら、加速する価値のあるシグナルを待つ」と述べている。同氏は IP ビジネスの論理をかなり率直に説明した。現在最も多くの売上に貢献しているコアは十数年前に設計されたもので、顧客は同じコアのセット上で十年以上イテレーションを続ける可能性がある。だからこそ「正しく作ること、再利用可能であること」が先行投入よりも重要だという。直近の優先事項はストレージ市場向けのメインコントローラコア（すでに 10 社の顧客が小型コントローラコアで量産済み）、自動車、ロボティクスである。もう一つの背景として、Arm が自社開発のハイエンド CPU シリコンを投入したことでビジネスモデルが変わり、Su 氏はこれがむしろ顧客の信頼を損ない、Andes のような IP サプライヤーに有利に働くと見ている。

記録に値する判断は次の点だ。このニュースは「RISC-V がデータセンターのハイエンドへ突き進んでいる」というナラティブの方向とは逆だが、矛盾はしない——ハイエンドコアの研究開発は止まっておらず、商業的なリズムがロードマップではなく市場のモメンタムによって決まるようになっただけであり、実際に金を払っているのは AI エッジと制御面である。国内で RISC-V ハイエンドコアに取り組むチームにとって、これは「誰が最初に支払うのか」に関する現実的な参照事例である。

1. オープンソースコミュニティとソフトウェアエコシステム

香山、アウトオブオーダーの CSRR 実行をバックエンドデコードに復帰（11-02）

第 6779 号は、CSRR 一类の命令のアウトオブオーダー実行を復活させた。背景として、香山バックエンドにデコードユニットが新たに加わった後、それ以前の CSRR アウトオブオーダー実行の実装が失われ、本来並列発行できた CSR の読み書きが再び直列に戻り、CSR に依存するすべてのパスを遅くしていた。今回の変更の直接の目的は、これを新しいデコード経路に再び接続することである。

著者はついでに一つの漏れを指摘している。疑似デコードチャネルでは、CSRRVL と CSRRVLENB の二命令は CSRR 形式である場合にのみ特別処理され、CSRRSI／CSRRC／CSRRCI という同様にベクトル長レジスタを読み書きする形式はカバーされていない。この種の「一種のエンコード形式しか考慮していない」抜けはベクトルコードで発生しやすく、コンパイラはしばしば vsetvl を CSRR ではなく一連の CSRRSI にシリアライズするからである。

日付：2026-11-02　情報源：XiangShan #6779

香山 TAGE の bankIdx が履歴ビットを使用するよう変更、4 バンクの 2048 位置が利用可能に（11-02）

第 6771 号は TAGE 分岐予測器のインデックス方式を変更した。従来はバンクが PC のみで決定され、同じ履歴は固定でいずれか一つのバンクの 512 表項にしか落ちず、残り三つのバンクの容量はこの履歴にとって完全に無駄になっていた。変更後は履歴がバンクとセットの選択に同時に参与し、理論上は四バンク合計 2048 の位置すべてが使えるようになる。

実測結論はかなり控えめに書かれている。astar、xalancbmk、gobmk の3項目には明確な効果があり、libquantum では回退が発生した。原因は新構造が bank 衝突を起こしやすくなったことで、著者は後続での対応を残している。この変更の価値は、見落とされがちな容量の勘定を指摘した点にある——予測器テーブルがどれだけ大きくても、インデックスが1次元しか使われなければ、実際に利用可能な容量は構造によって細かく分割されてしまう。

日付：2026-11-02　情報源：XiangShan #6771

香山の事前計算 BPU の s2／s3 override 条件、次 PC パス最終段ロジックを圧縮（11-02）

第6753号は純粋なタイミング最適化である。各分岐候補の s2／s3 override 条件を事前に計算し、「最初の taken 分岐」のワンホットマスクで結果を選択する。同時に s2 の taken 結果を TAGE の2つの可能な結果ごとに事前計算し、遅れて到着する TAGE 予測は最終段の選択のみを担当するようにした。

効果は next-PC という最も厳しいパス上で、遅延信号以降の論理深度を抑えつつ、予測動作は変わらないことにある。この種の変更は性能数値には現れないが、周波数上限を決めるものであり、香山の最近の「まず高周波数のタイミング渋滞を解消する」という路線の延長である。

日付：2026-11-02　情報源：XiangShan #6753

香山、XSCache サブモジュールを「late hints」修正版に指し替え（11-02）

第6803号はサブモジュールポインタを1行変更しただけであり、XSCache を e9488ae から a041f07 に更新している。コミット説明は「late hints の問題を修正するためアービタを差し替え」である。この種のポインタ変更だけのコミットはデイリーレポートで見落とされやすいが、多くの場合クロスリポジトリの修正が既にマージされたことを意味する——キャッシュ側の late hints はプリフェッチ効果に直接影響し、今号の香山フロントエンド・プリフェッチキューの再構築と同じ路線上の作業である。

日付：2026-11-02　情報源：XiangShan #6803

difftest、squash replay で非同期 AME チェッカ状態を保持（11-02）

第987号は行列拡張チェックがリプレイ時に状態を失う問題を修正する。変更は squash による replay の前後で3つをスナップショットし復元する：行列ソフトウェア ROB、保留中の msync イベント、参照側の AME 状態。同時に AME コミットシーケンス番号を非同期 MMA チェックに貫通させ、「本パケット内のエラー」と「より早く残された失敗」を区別し、リプレイ境界で検査待ち項目を排出する。

もう1つ記録すべき実装詳細がある：リプレイ時にキューのチェックと保持されたエラーをリセットするが、バックエンドは置き換えない。CUDA サービスと結果プールを生かしたままにし、親プロセスで既に起動している LightSSS 子プロセスが再接続できるようにする。これは行列チェックを「一回限りのバッチ処理」から「中断可能・再開可能」にするための必要条件である。

日付：2026-11-02　情報源：difftest #987

NEMU、行列アクセスを共有 TLB 最適化パスに載せ、CI は性能コメントを再利用に変更（11-02）

第1275号は PERF_OPT_SHARE の共有キャッシュ資格判定と PBMT チェックを行列アクセスに拡張し、同時に既存の SLOW と2段階翻訳フォールバックパスを保持する。行列ヒットは共通の物理アクセス処理関数に回し、権限チェック、AMU イベント、遅延データ移動を維持する。言い換えれば、行列メモリアクセスはもはやバイパスではなく、通常のメモリアクセスと同じ TLB 会計に接続された。

第1276号は CI 改善である。性能結果コメントは同一のもの（隠しマーカーで特定）を更新する方式に変更し、PR ブランチごとに直列化して、並行完了した CI がコメントを重複投稿するのを防ぐ。毎日性能回帰を読む開発者にとって、これは新機能を1つ追加するよりも実用的である。

日付：2026-11-02　情報源：NEMU #1275、NEMU #1276

CORE-V CVW の3件：sfence.vma 後の DTLB 再ロード、CLINT 未完コードの整理、Verilator と VCS で機能カバレッジ収集（11-02 から 11-03）

3件のマージは検証側と実装側の両方をカバーする。第2019号は holdaccess テストを変更：各 sfence.vma の後にデータページを DTLB に再ロードすることで、テストは「無効化後の再ロード」という実際のパスをカバーでき、古いエントリで偶然当たることに頼らなくなる。第2034号は CLINT 内の未完成の timereg コード、未使用の TIMECLK、および一連の陳腐化した TODO／Hack コメントを削除し、24ファイル +39／−155 の負債削減である。第2009号は wsim が Verilator と VCS の両シミュレータで機能カバレッジを収集できるようにする——これはオープンソースコアにとって見た目以上に重要であり、機能カバレッジがシミュレータを跨いで再現できてこそ、カバレッジ数値に比較価値が生まれる。

日付：2026-11-02 から 2026-11-03　情報源：CVW #2019、CVW #2034、CVW #2009

CORE-V cvfpu で命名 clear 信号により FFLARNC を修正（11-02）

第 187 号は BSC 側からのもので、64 ビット多モード除算・平方根ユニット内の FFLARNC（浮動小数点フラグクリア）配線を変更：従来は位置による暗黙の対応に依存していたが、名前付き clear 信号に変更し、パラメータ化されたインスタンスでの誤配線を回避する。この種の修正は性能変化をもたらさないが、浮動小数点例外フラグの正確性に直接影響し、検証で見逃しやすくシリコン上での発見が困難な類の問題である。

日付：2026-11-02　情報源：cvfpu #187

openRuyi が clang-wrap の ninja リンクコマンドを修正、mtools が CVE-2026-118384 を補完（11-02）

openRuyi メインリポジトリの調査期間内に 7 件のコミット。最も実質的なものは clang-wrap を 20261102 に更新したもので、libical ビルド時にローカルリンクコマンドが ninja-build をサポートしない欠陥を修正——この種のパッケージが RISC-V 上でビルド失敗する場合、「上流がサポートしていない」と誤判定されがちだが、実際にはラッパー層のコマンド組み立ての問題である。他に mtools を 4.0.50 に更新して CVE-2026-118384 を修正、さらに 6 つの Go エコシステム spec（火山引擎 ve-tos SDK、テンセントクラウド cos-go-sdk と tencentcloud-sdk-go、go-httpheader など）を一括補入しており、クラウドネイティブとストレージスタックを依存関係ごとに層別に補充していることを示す。

KU Leuven が RISC-V コア上で DMP を初のオープンソース実装、SecDMP 防御を提案（11-03）

KU Leuven DistriNet と EURECOM の論文（NDSS 2027 採録、拡張版 32 ページ）はデータメモリ依存プリフェッチャ（DMP）のサイドチャネルを扱う。DMP は主要なデスクトップおよびサーバー CPU に搭載されており、メモリ内容中のポインタらしき値に基づいてプリフェッチする。性能上の利点がある一方、秘密をマイクロアーキテクチャ状態にエンコードしてしまい、Spectre 対策を施した定数時間コードでも防げない。

論文はまず DMP リークの分類と新攻撃を示し、次に RISC-V プロセッサ上で初のオープンソース DMP を実装、実測により既存の唯一「DMP 性能を維持しようとする」防御がリークの全クラスを防げないことを証明する。続いて SecDMP を提案：メモリ内で秘密をマークすることを要求し、DMP がこれらの秘密をマイクロアーキテクチャにエンコードしないことを保証し、そのリークが「DMP なしのベースライン」を超えないことを形式証明しつつ、公開データの性能を犠牲にしない。ハードウェアコストは RISC-V 研究コア上で面積 0.5% 以下。オープンソースコアコミュニティにとっての価値は、DMP のような最適化が大手専有から設定可能なコアへと移行しつつある中で、セキュリティ設計をテープアウト後に補うのではなく、RTL に事前に組み込む必要がある点にある。

日付：2026-11-03　情報源：arXiv:2610.37454 SecDMP（拡張版）、論文 HTML 版

欧州が ERICI 産業計算イニシアチブを発起、RVA23 を「産業用コンピュータ」に（11-02）

ERICI（European RISC-V Industrial Computing Initiative）という名称のイニシアチブが Hacker News に登場した。発起人はドイツの Yuri Zaporozhets で、非商業的な業界協業として位置づけられている。その問題提起はきわめて直接的だ。RVA23 のシリコンはすでに登場しているが、「産業用コンピュータ」は存在しない——ボードメーカーはソフトウェアを待ち、ソフトウェアはボードを待ち、顧客はその両方を待つ。この循環は、実ハードウェア上で動作するオープンなリファレンススタックによって断ち切るしかない。

リファレンススタックは層ごとに分割される。ファームウェアが初期化と POST を行い、その後 UEFI ブートローダーに引き渡す。gRouvr はカーネルのようにロードされ、CPIO で各パーティションのカーネルと initramfs をパッケージし、CPU、メモリ、デバイスとそれぞれのデバイスツリーをリアルタイムパーティションと Linux パーティションに割り当て、両者は同一 SoC 上で並列に分離実行される。ライセンスは明確に記されている。HFI BIOS は GPL-2.0（U-Boot ベース）、mr-bml は GPL-3.0、gRouvr と QSOE は Apache 2.0 だ。パーティションスタックはすでに進畳時空 K3 の PicoITX ボードでデモされ、QSOE は gRouvr のゲストとしてログインまで動作している。

また、ギャップも正直に列挙している。既製の RVA23 マシン（Firefly AIBOX-K3、Milk-V Jupiter2）は、広電圧入力、−40〜85℃、フィールドバスとリアルタイム I/O、レール取り付け、産業用 EMC と安全認証、10〜15 年の長期供給といった項目のほとんどが「未記載」であり、パーティションソフトウェアスタックもまだ製品には落ちていない。この「まず層間インターフェースを定義し、次に層ごとに検証して一緒に起動する」という手法は、国内の RISC-V 産業用・車載規格の取り組みと対比して見ることができる。

5. まとめとトレンド観察

本日の情報量は3箇所に集中しており、それぞれ異なる層を指し示している。

第一に、商業的リズムがロードマップを圧倒している。AndesがハイエンドコアCuzcoを減速させ、資源を既に売上の半分を占めるAI事業へ圧縮するのは、今回のRISC-V産業において珍しい「自主的な減速」のサンプルである。これはハイエンドコアに取り組むチームに警告する：エコシステムと顧客予算が整わないうちは、性能指標がどれほど良くても受注には結びつかず、IPビジネスの複利は初回発表ではなく再利用可能性から生まれるのだと。

第二に、オープンソースコアの進歩は依然として「小さく密」な形で現れている。香山は1日に4件（CSRRアウトオブオーダー実行、TAGEインデックス次元、BPUタイミング、XSCacheポインタ）、CVWは1日に3件（DTLBオーバーロードテスト、CLINT負債削減、デュアルシミュレータ機能カバレッジ）、NEMUとdifftestはそれぞれ行列拡張に関連する状態整合性の問題を1件ずつ修正した。単件はいずれも大きくないが、方向性は一致している。アウトオブオーダーと行列拡張という2つの新しいパスの状態管理を堅実にすることだ。

第三に、ロボットスタックは「デプロイ」の部分を補完している。進迭時空の3リポジトリが同日にマージされたが、重点は新しいアルゴリズムではなく、ハードウェアデプロイ、オンラインポリシー切り替え、キャリブレーションテーブルマッピング、起動復旧にある。これらは実験室のポリシーを納品可能な製品に変えるために必要な要素だ。ERICIが欧州でRVA23を産業用コンピュータにしようとする取り組みと併せて見ると、RISC-Vの次の成長段階は「動くかどうか」から「現場で長期的に安定して動けるかどうか」へと移りつつあるようだ。

ランキング側は今回、追加収録とサイト機能更新のみであり、性能の飛躍として読むべきではない。会員企業公式サイトの巡回391社のうち93社でトップページの内容が変動していたが、いずれもマーケティングとニュース枠の通常更新であり、実質的な製品、資金調達、アーキテクチャの動向はなかった。
