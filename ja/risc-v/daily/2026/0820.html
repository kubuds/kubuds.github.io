1.1 香山 12 リポジトリが活発、メインブランチ IBuffer タイミングと StoreUnit 修復（08-19）

日付：2026-08-19（09:45 ~ 20:33 北京時間）　出典：OpenXiangShan/XiangShan GitHub

香山組織では期間内に 12 のリポジトリでプッシュがあり、メインブランチ（XiangShan）と AI アクセラレータ（XSAI）にそれぞれ実質的なコミットが複数入った：

  • メモリアクセス正当性：fix(StoreUnit): kill younger cross-page unalign head store (#6382)（08-19 13:56 北京、当日の新規コミット）——ページをまたぐ非アラインメントのヘッド store と、より若いメモリアクセス命令とのアウトオブオーダー実行衝突を修正；
  • フロントエンドタイミング：timing(ibuffer): shorten valid paths for partial-drain output、fix(ibuffer): make deqEntries valid/bits consistent, fix VTypeGen input（08-19 10:42 北京マージ、作者 08-18）——命令バッファの部分ドレイン経路のタイミング最適化と VTypeGen 入力の修正。同バッチでは feat: use PNR ptr to judge for 2-pre/fetch (#6378)（08-19 10:10 北京）もマージ；
  • AI アクセラレータ：XSAI が fix(matrix): bump CUTE for MLCT,MSCT fixes (#106)（08-19 09:45 北京）をマージ——行列アクセラレータが CUTE（CUDA Tensor Engine 形式の行列ライブラリ）の更新に伴い MLCT/MSCT を修正。
  • その他の活発なリポジトリ：GEM5、llvm-project、XSCache、NEMU、XiangShan-doc、XiangShanLab、workshop、workload-builder、nexus-am、xs-env（いずれも定例の付随的イテレーション）。

メインブランチへのバッチマージは3日連続で、今回は「フロントエンド IBuffer タイミング + メモリアクセスアウトオブオーダー正当性 + 行列アクセラレータ」の三路線が並行して進み、開発ペースは高強度を維持している。

1.2 コミュニティ討論：Dmitry Grinberg が RISC-V 組み込み ISA を批判、多方面が反応（08-19）

日付：2026-08-19（Adafruit 転載 02:37 北京時間）　出典：Adafruit Blog、dmitry.gr 原文

組み込み開発者の Dmitry Grinberg 氏が長文《RISC-V: They Should Have Known Better》を執筆し、RISC-V 組み込みコアの命令セットの取捨選択を批判、Adafruit Blog が 08-19 に転載してコミュニティで大きな議論を呼んだ。核心的な論点：RISC-V 組み込み命令セット（RV32E を参照）には aarch64 式のビットフィールド命令（BFC/BFI）が欠けており、同氏は同一カーネルイメージ内でビットフィールド挿入/抽出命令が 6,284/8,881 回出现すると集計し、「唯一の目的——組み込みカーネル——において、RISC-V はかえって既存の競合製品より劣っている」と述べ、コード密度とコンテキストスイッチの設計も批判した。コミュニティの反応も速かった：

  • rvembedded.com《A Third World Embedded Engineer Responds》は実機の事例で反論：CH32V003 の 10 セントの RV32EC コア（16 レジスタ、乗除算なし、M モードのみ）でも同氏の量産製品 2 製品を支えられ、ツールチェーンは数時間で習得でき、「ISA マニュアルと C コンパイラがあれば十分」；
  • Reddit r/RISCV の議論は概ね肯定的な立場：「RISC-V はよく設計されており、将来主流の ISA になるだろう、性能の天井はなく、ベクトル拡張は ARM より優れている」；
  • HN でも同時に盛り上がった（返信スレッドは 5 点、コメント 2 件）。

これは「組み込み ISA の設計上の取捨選択」をめぐる公開討論であり、双方がビットフィールド命令、コード密度、コスト、ツールチェーンの成熟度をめぐって論戦を交わした——RISC-V が「真剣に批判され得るし、実機の証拠をもって応答もできる」エコシステム成熟期に入ったことを示している。

1.3 オープンソースプロジェクト観察：labwired-core——ARM/RISC-V 決定論的ファームウェアシミュレータ（08-20）

日付：2026-08-20（08:13 北京時間）　情報源：github.com/w1ne/labwired-core（59 stars）

w1ne が labwired-core をリリース：ARM Cortex-M と RISC-V 向けの決定論的ファームウェアシミュレータで、「ハードウェア検証済みの並列ペリフェラルエミュレーション」（hardware-validated parallel peripherals）を主眼とし、ファームウェア・イン・ザ・ループテストに用いる。組み込み/ファームウェアテスト方向の新ツールであり、RISC-V 側の対応は注目に値する（当日新規作成、スター数はまだ少なく、エコシステム観察としてのみ扱う）。

2. 製品とエコシステムの動向

2.1 トップニュース：賽昉科技が Dubhe-100 を発表——RVA23 準拠のサーバー/HPC RISC-V CPU IP（08-19）

日付：2026-08-19（公式 X で 13:19 北京時間に発表；CNX 報道は 08-20 08:00 北京時間）　情報源：CNX Software、StarFive 製品ページ

賽昉科技（StarFive）が Dubhe ファミリーの新たなフラッグシップ Dubhe-100 を公式に発表——サーバーと HPC 向けの 64 ビット RVA23 準拠商用グレード RISC-V CPU IP であり、公式 X では「commercial-grade RISC-V CPU IP for servers and HPC」と称している。主要仕様：

  • ISA/マイクロアーキテクチャ：RV64GCBVH（B/V/H 拡張を含む）、15 段パイプライン、6 発行スーパースカラ、深いアウトオブオーダー実行、命令融合とマルチコアキャッシュコヒーレンシをサポート、AIA 1.0 割り込みアーキテクチャ；
  • 性能：SPECint2006 15/GHz、Dhrystone v2.2 10.0 DMIPS/MHz（公式公称値）；
  • ベクトルと暗号：RISC-V Vector（RVV）と Vector Crypto の全拡張をサポート；
  • セキュリティとデバッグ：PMP/PMA（16/32/64 領域を設定可能、最小 4096 バイト粒度）、Svpbmt、RISC-V Debug/Trace 仕様に準拠したデバッグとトレースインターフェース、HPM ハードウェア性能カウンタ；
  • 目標アプリケーション：サーバー/HPC、LLM 推論、AI agent、視覚分析（コンピュータビジョン）、インフラチップ（Smart NIC コントローラ、分散ストレージコントローラ）；
  • 最初の顧客：LECARC（希奥端計算、2026-06-29 に提携を公式発表）が Dubhe-100 をベースにインテリジェントエッジサーバー SoC を設計中；
  • ソフトウェアエコシステム：開発は StarFive StarStudio IDE で行い、Dubhe SDK はまだダウンロード公開されていない（商用 SoC の登場後に starfive-tech GitHub で公開される見込み）。

位置づけ評述：Dubhe-100 は賽昉を「RVA23 ハイエンドコア」競争圏へ押し上げ、達摩院玄鉄 C950（64 コア、RVA23、行列加速）と正面から同じ土俵に立つ；RISC-V International CEO Andrea Gallo は同時期に「2026 年は高性能 RISC-V アプリケーションプロセッサの年だ」と評価しており、Dubhe-100 の正式発表はその最新の脚注である（詳細は 3.1 の深掘りと第 4 章を参照）。

2.2 Pine64 が Linux デバイス生産を一時停止：DRAM/eMMC の品薄と値上がり（08-19）

日付：2026-08-19（CNX 報道 18:29 北京時間）　情報源：CNX Software、Hackster.io

Pine64 公式（コミュニティ Mastodon）は次を発表した：DRAM と eMMC の品薄かつ価格高騰のため、即日で Linux デバイスの生産を一時停止し、「生産が再開されるかどうかは 2027 年半ば以降のストレージ価格の動向次第である」。要点：

  • 欠品タイムライン：PineNote と PineTab2 は約 3 か月以内に完売見込み；RISC-V 関連の Star64（JH7110、StarFive の A55 クラス 2 コア）も影響を受ける Linux 製品ラインに属する；
  • MCU 製品は影響なし：PineTime 腕時計、Pinecil はんだごて、PinePower 電源などの MCU 製品ラインは生産を継続し拡大する（ストレージコストの比率が低い）；
  • 業界シグナル：AI 需要が DRAM/eMMC の生産能力を圧迫して価格が急騰し、低コスト Linux/RISC-V シングルボードメーカーが真っ先に直撃を受ける——「手頃な RISC-V 入門ハードウェア」の供給にとっては負の撹乱であり、コミュニティの入門プラットフォーム（Star64 など）は短期的に供給圧力にさらされる。

3. 国内チームの動向と深掘り

3.1 達摩院玄鉄：C950 性能数値の批判的レビュー——SHL ソフトウェアスタックと測定の限界（08-19）

日付：2026-08-19（13:36 北京時間）　情報源：XenoSpectrum

昨日のトップニュース（C950 で Qwen-3.8 27B をネイティブ実行）は、今日、業界メディアによる批判的レビューを迎えた：XenoSpectrum は長文で「30 tok/s / TTFT 1.9s」という数値の背後にあるソフトウェアスタックと測定の境界を分解している：

  • 数値の出所：08-18 に技術観測者 tphuang が転載した XUANTIE タグ付きスライドに由来し、独立した再測定結果ではない；スライドには別途 Qwen3.8-2.4T-A95B の C950 上での decode 7.2 tok/s / TTFT 8.5s も記載されている；
  • 性能の源泉：核心は達摩院玄鉄の SHL（Heterogeneous Neural Network Library）ヘテロジニアスニューラルネットワークライブラリ——精度と計算形状に応じて MatMul/Linear 行列オペレータ、Softmax/RMSNorm 専用実装を選択し、オペレータ融合、バッファ再利用、フォーマット変換削減を組み合わせる；公式リポジトリは 8/16/f16 ビット、対称/非対称量子化、ヘテロジニアススケジューリングを公開サポートしている；
  • C950 の位置づけ：サーバー級 RISC-V プロセッサ IP（クラウド/データセンター、AI エージェントサーバー、高性能ロボティクス）、8 命令デコード、アウトオブオーダー実行、ベクトル計算、Matrix AI 加速、RVA23 Profile と CoVE；Qwen3.8-27B の重みは 08-12～14 にアップロードされ、C950 の資料は 08-18 に即座に出たので、Day 0 対応は事実である；
  • 測定の限界（原文の重点）：精度、量子化、バッチサイズ、プロンプト長、メモリ帯域、消費電力のいずれも開示されておらず、GPU/Mac と同一条件での比較はできない；C950 は IP であり、64 コアの target configuration は量産チップの出荷と等しくない；TSMC 5nm プロセス（Nikkei の「5nm 検証」報道）はアリババによる確認が取れていない。
  • その他：XUANTIE-RV/opensbi リポジトリは 08-19 07:56 UTC にプッシュがあった（デフォルトブランチに新しいコミットはなく、tag/ブランチレベルの更新と推測される；以前 08-07 に XuanTie_V1.4.0-rc2-c9502 タグが打たれており、C950 起動ファームウェアのイテレーションは継続している）。

評述：このレビューはナラティブを「公式発表のマイルストーン」から「再現可能なベンチマーク」の水準へ引き戻す——RISC-V で 27B 大規模モデルを走らせる方向性の検証は成立しているが、比較可能な効率データにはほど遠く、依然としてベンダーによる測定条件の開示が必要である。これは昨日のレポートの「メディアの口径を基準とする」という限界の説明と互いに裏付け合っている。

3.2 賽昉 StarFive：Dubhe-100 深掘——ファミリ進化とエコシステムのリズム（08-19）

日付：2026-08-19　情報源：StarFive 公式サイト、CNX Software

Dubhe ファミリの進化の系譜：Dubhe（2021-12 初公開、12nm、2 GHz、P550 対抗）→ Dubhe-90/80（2023-08 リリース、Max Performance / Efficiency Performance の2シリーズ）→ Dubhe-83（2024-12、RVA23 Profile に追随、RVV 1.0 + Vector Crypto）→ Dubhe-100（2026-08、RVA23 準拠、SPECint2006 15/GHz）。

  • エコシステム側のリズム：公式 GitHub（starfive-tech）は最近静か（直近のプッシュは 07-06、edk2/meta-starfive）で、CNX の判断と一致——Dubhe SDK はまだ公開されておらず、最初の商用 SoC（LECARC との協業）の立ち上がり後にオープンソース化される見込み；StarStudio IDE はすでにオープンソース化済み；
  • 戦略的位置づけ：賽昉はこれまで VisionFive シリーズ SBC（JH-7110）とデータセンター BMC チップを市場の抓手としてきた（08-13 で BMC 布局を既報）。Dubhe-100 は製品ラインを明確に「サーバー級 IP + AI インフラ」へと押し出すものであり、08-14 レポートの「RISC-V のデータセンターインフラへの浸透」という判断に対する、さらなる一手である。

3.3 進畳時空：mpp メディアパイプラインの2件の修正（08-19）

日付：2026-08-19（11:22 ~ 20:41 北京時間）　情報源：spacemit-com/mpp GitHub

進畳時空（SpacemiT）のメディア処理パイプライン mpp に、当日の新規コミットが2件マージされた：fix(sys): support cross-user shared memory access（クロスユーザー共有メモリアクセスのサポート）と fix(vdec): apply backpressure to a full depth queue（ビデオデコードキューの満杯時のバックプレッシャー制御）；docs-chip リポジトリも同日プッシュされた。mpp は K1/Muse シリーズチップのマルチメディアコーデックスタックであり、定例ではあるが継続的なドライバと安定性のイテレーションである。

3.4 算能：sophon-tools の agent 化ツールチェーンが引き続きバッチマージ（08-19）

3.5 楽鑫は定例メンテナンス；芯来、奕斯偉は静か（08-19）

日付：2026-08-19　情報源：espressif GitHub

楽鑫は 31 のリポジトリにプッシュがあった（esp-idf、arduino-esp32、esp-nn、esp-sr、esp-matter、llvm-project など）が、いずれも定例メンテナンスのリズムであり、RISC-V 専項のリリースはなし；芯来（Nuclei-Software）と奕斯偉計算（eswincomputing）は調査期間内にプッシュがなく、静かである。

4. 重点方向特章：身体性知能とロボティクス

4.1 RISC-V ハイエンド計算力の語りが集団で AI agent とロボティクスへ転換（08-19）

今週の国内2大注目リリース（C950とDubhe-100）は、製品ポジショニングが高度に同方向——いずれも「AI agent サーバー / 高性能ロボット / 具身智能」を中核応用シーンに書き込んでいる：

  • 達摩院玄鉄 C950：公式口径で「AI agent サーバーと高性能ロボット」を明確にカバー、SHL ソフトウェアスタック + 64コア RVV で 27B 級モデルを完走（30 tok/s）、端側/エッジ大モデル推論にベースラインデータを提供；
  • 賽昉 Dubhe-100：目標応用に LLM 推論、AI agent、視覚分析を含み、初顧客 LECARC は「スマートエッジサーバー」を手掛け、公式キャッチコピーはまさに「Agentic AI 時代」；
  • 香山 XSAI：行列アクセラレータ（CUTE）が継続的に反復、RISC-V オープンソース側の高性能 AI 計算基盤も並行して推進。

具身智能にとっての意義：VLA（視覚-言語-動作）モデルの搭載は「端側で負担可能な大モデル推論」に依存しており、C950 の 30 tok/s ベースラインは RISC-V マルチコア+ベクトル路線がこの方向で「デモ」の敷居をすでに越えたことを示す；一方 Dubhe-100 の 15/GHz 整数性能と Vector Crypto は「ロボット算力基盤 + セキュリティ」という一段上のポジショニングを指し示す。リスク面も同時に出現：DRAM/eMMC の値上げにより低コストロボット/エッジハードウェアの整機コストが圧迫され（2.2 参照）、サプライチェーンの変動が普及価格帯の具身プラットフォームの展開を遅らせる可能性がある。

5. まとめとトレンド観察

  1. 賽昉 Dubhe-100 公式発表：中国のサーバー級 RISC-V IP に新たな一員——RVA23 準拠、SPECint2006 15/GHz、Vector Crypto、達摩院玄鉄 C950 と正面から同場し、RISC-V ハイエンドコア競争は「中国の二強」段階へ；
  2. C950 の性能数字に批判的再検討が到来：XenoSpectrum は SHL ソフトウェアスタックが鍵（オペレータ融合/量子化/バッファ再利用）と分析し、同時に測定条件が未開示、「IP ≠ 量産チップ」と指摘——「RISC-V で大モデルを走らせる」というナラティブは理性的議論の時期へ；
  3. 香山が3日連続で高強度反復（12リポジトリ）：フロントエンド IBuffer タイミング、メモリアクセス順序違反の正確性、行列アクセラレータ CUTE の三路線が並行、オープンソース高性能コアの開発ペースは衰えず；
  4. コミュニティの議論が加熱：Dmitry Grinberg の組み込み ISA への批判と実機での反論（CH32V003 事例）が同じ画面に出現、RISC-V エコシステムは「批判可能、反論あり」の成熟期へ；
  5. サプライチェーンの暗雲：Pine64 が DRAM/eMMC の欠品により Linux デバイス生産を一時停止（Star64 などの RISC-V SBC が影響を受ける）、AI 需要がストレージ生産能力を圧迫する波及が普及価格帯の RISC-V ハードウェアに及び始めた。

限界に関する説明：Dubhe-100 の仕様は CNX の伝聞と StarFive 公式製品ページに準拠、SPECint2006 15/GHz は IP レベルのベンダー公称値であり、独立した第三者による再測定は経ていない；C950 の性能数字はベンダースライドの口径（XenoSpectrum も非独立再測定と強調）；XUANTIE-RV/opensbi 08-19 のプッシュは具体的なコミット内容を確認できず（デフォルトブランチに新規コミットなし）；gnews の中国語クエリ（zh-CN 地域）は調査期間内で空、英語は正常、国内ベンダーの中華圏報道には漏れがある可能性；今週のベンダー英語クエリ（SiFive/Milk-V など）は空ヒット、海外トップベンダーの新製品は見られず。
