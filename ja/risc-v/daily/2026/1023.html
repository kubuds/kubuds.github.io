今日の重点：科華データと進畳時空が契約、RISC-V サーバー芯片が算力インフラに接続

日付：2026-10-22　情報源：観点網：科華データと進畳時空が戦略的協力協定を締結 国産算力エコシステムを共同構築（10-22）、搜狐：共に「芯」の旅路へ——科華データと進畳時空が戦略的協力に到達（10-22）

科華データ股份有限公司と進畳時空（北京）智能科技有限公司が戦略的協力協定を締結し、技術、製品、市場、エコシステムの四つの次元で協力を展開する。目標は AI 芯片層と算力インフラ層 の適配経路を打通し、国産算力エコシステムを共同構築することにある。

  • 科華側の能力：電力電子業界に約40年深く従事し、十数年のデータセンター建設・運営経験を持ち、業務はハイエンド電源、精密温調、データセンターの全ライフサイクル運営管理をカバーする；「国産芯片と算力ハードウェアインフラの協同技術規範（CCHS）」団体標準の主編を牽頭し、すでに複数の国内外トップ AI 芯片メーカーと協力している。
  • 進畳側の製品：K3 は世界初の RVA23 規範に適合し量産を実現した RISC-V AI CPU；V100 は10-18から20のサミット期間中に発表され、公式の口径では世界初のサーバー全仕様を満たし RISC-V Server SoC 規範に適合する高性能サーバー級 CPU であり、同時に C2201 計算サーバー、G5201 智算サーバー、S5236 ストレージサーバーの三種の整機を提示した。
  • 協力の着地点：自主制御可能な算力方案を芯片定義、システム適配から大規模展開までの全プロセスで貫通させることを推進；技術的には RISC-V AI 芯片と算力インフラの協同最適化を推進し、製品面では異なる算力シーン向けのソリューションを共同で作り上げる。

サーバー芯片の発表はハードウェアを作り出したに過ぎず、機房に入れるかどうかは、給電、冷却、整機設計、運維体系がそれのために変わることをいとわないかどうかにかかっている。今回の契約の実際的な意義は、「適配」を芯片会社の一方的な推進からインフラメーカーの共同作業へと変えることにある；そして同時期の海外メディアの分析はまさに、適配コストこそが顧客が移行するかどうかの決定的変数であると指摘している。二つの手がかりは同じ結論を指し示す：RISC-V クラウドの次の行程は発表会ではなく、機房にある。

1. オープンソースコミュニティとソフトウェアエコシステム

1.1 openRuyi：20コミット、Python 3.14.9、nginx 1.31.8、Node.js 24.22.1 が着地

日付：2026-10-22　情報源：openRuyi メインリポジトリのコミット記録（10-22）、openRuyi 公式サイトニュースページ

openRuyi メインリポジトリは調査期間内に 20 件のコミットを記録し、内容は主に SPECS ディレクトリのバージョンアップとセキュリティ修正で、ほかに若干のパッケージング規範の整理があった。

  • ランタイムと言語スタック：python を 3.14.9 に更新（コミットには security-fixes の注記あり）、nodejs を 24.22.1 に更新、openjdk-17 を 17.0.21.9 に更新、openjdk-21 を 21.0.13.9 に更新。
  • サービスとミドルウェア：nginx を 1.31.8 に更新（security-fixes）、python-pillow を 13.0.0 に更新（security-fixes）、rdma-core を 65.0 に更新、libudev-zero を 1.0.5 に更新。rdma-core は RDMA ユーザー空間ライブラリで、高速ネットワークと HPC クラスタ向けであり、サーバー向けディストリビューションの基盤部品に属する。
  • エンジニアリング整理：opencv はハードコードされた /home パスをビルドディレクトリ変数で置き換え；xmltoman、xinetd、xdg-utils、xcb-util-renderutil、xcb-util-image などのパッケージに source checksums を追加し、自動変更履歴マクロに切り替え。
  • 公式サイトの二重ソース：ニュースページの最新告知は依然として 2026.09 バージョンで、調査期間内に新バージョンのリリースはなかった。

連続三日間のコミットを見ると、openRuyi の補完順序は Go クラウドネイティブコンポーネント、uv の Rust 依存、そして Python と Node のランタイムメジャーバージョンである。security-fixes マーク付きのコミットがまとまって出現していることは、セキュリティ更新がすでにプロセス化された経路に入っており、散発的なパッチ適用ではないことを示している。

1.2 コミュニティプロジェクトが ESP32-S31 上で Linux 7.3 と OpenSBI 1.9 を動作

日付：2026-10-22　情報源：GitHub：annoyedmilk/esp32-s31-linux（10-22）

コミュニティプロジェクト esp32-s31-linux が楽鑫 ESP32-S31 上で上流の Linux 7.3 カーネルと OpenSBI 1.9 を動作させ、16 MB のオクタル PSRAM をメインメモリとして使用している。

  • 起動チェーン：ESP ROM から ESP-IDF の二段目、さらに loader、OpenSBI、Linux、最後に Buildroot ルートファイルシステム（SD カード、USB メモリまたは flash）をマウント。
  • 利用可能なユーザー空間：LCD 上のシェル、wpa_supplicant によるネットワーク接続、BlueZ ブルートゥース、SSH、USB キーボード・マウスと USB メモリ、vim、gdb、strace、MicroPython およびテキストブラウザ links。
  • 技術的見どころ：この SoC には PLIC も Zicbom もコヒーレント DMA もないが、プロジェクトは数百行のコードで代替実装を提供し、カーネル開発者向けの内部実装ドキュメントも作成した。
  • ハードウェア対応：ESP32-S31-Korvo-1、ESP32-S31-Function-CoreBoard-1、ESP32-S31-WROOM-3-N16R16V モジュールの 3 種類のビルド。

MCU 向けに設計されたデュアルコア RV32（320 MHz、512 KB SRAM、16 MB PSRAM）が完全な Linux ユーザー空間を動作させられることは、ソフトウェアスタックのハードウェアへの要求がすでに極めて薄くなっていることを示している。こうしたプロジェクトは製品経路を構成するものではないが、ツールチェーン、カーネル移植、ドライバの成熟度を検証する極端なユースケースであり、教育と移植の参考の両面で直接的な価値がある。

1.3 香山昆明湖 V3 と CORE-V cvw：mnret/dret デコードの補完、jalr の訂正

日付：2026-10-22　情報源：XiangShan コミット記録（10-22）、cvw コミット記録（10-22）

香山昆明湖 V3 ブランチの調査期間内の 3 件のコミットは、いずれも機能ではなく細部に関するものだった：decode に mnret と dret の二つの特権リターン命令のデコードを追加（#6692）、ROB リダイレクトの開始インデックスを修正（#6729）、README に Dashboard と star 履歴のリンクを追加（#6696）。

  • CORE-V 側：cvw リポジトリで 2 件、jalr 命令について Table I.1 に正誤表項目を追加し（PR #1996）、マージされた。
  • 解読：mnret と dret はそれぞれ M モードとデバッグモードのリターンパス命令であり、デコードの補完は香山が特権状態とデバッグサポートを整備していることを意味する。jalr の正誤表はドキュメントレベルの修正であり、検証チームにとっての価値が外部ユーザーにとっての価値より大きい。

オープンソースコアの進展は、しばしばこのような「機能が見えない」コミットが中心となる。あるオープンソースコアが前進しているかどうかは、特権状態、例外、デバッグといった見落とされがちな隅々を見るべきであり、どのベンチマークをまた動かしたかではない。

2. 製品・エコシステム動向

2.1 ミリ波レーダーの RISC-V 路線：国産チップが先行して実装、CPU スロットは依然として第二の選択肢

日付：2026-10-22　情報源：RFID 世界網：ミリ波レーダー RISC-V 国産が先行（10-22）

ミリ波レーダーチップの命令セット選択を整理した報道は、かなり現実的な判断を示している。レーダーチップにおいて、RISC-V と Arm は現在併存する選択肢であり、世代交代の代替ではない。

  • 国産が先行して実装：正和微芯 RS6240（2024 年発表、デュアルコア RISC-V）はスマートホーム、健康・介護モニタリング、防犯警報に既に採用されている。開酷 K60213 は RISC-V MCU と AI アクセラレータを内蔵し、テレビ、エアコン、扇風機などの室内インタラクティブ機器に進出している。
  • 車載グレードの浸透：芯来 NA900 は ISO 26262 ASIL-D 認証を取得済みで、加特蘭 Kunlun-Pro はこのコアを内蔵し、デュアルイシュー・デュアルコアの総合演算性能は 3668 DMIPS、前世代 Alps-Pro の約 5 倍であり、L2 ADAS の前方知覚へと推進している。
  • 分業の境界：外部が注目する 10 倍の信号処理演算性能は加特蘭自社開発の RSP 2.0 によるものであり、RISC-V コアではない。RISC-V が担うのは点群後処理や目標追跡といった、アルゴリズムの更新が速く、プログラマブル CPU 上に留めておく必要がある工程である。メーカーはオープンな拡張インターフェースを利用して、ソート、補間、三角関数をハードウェア命令化し、実測でクラスタリング所要時間が約半分、追跡所要時間が 50% 以上削減された。
  • 国際大手：TI の AWR2188、NXP の TEF8388 と SAF8444 は依然として Cortex-A53 と M7 を使用しており、短期的に切り替える動機はない。奕斯偉が香港株式市場に上場した際の招股書（目論見書）も、RISC-V は依然として市場検証の初期段階にあり、ユーザーの認知と信頼はまだ十分に確立されていないと率直に認めている。

この記事の価値は、RISC-V が特定のカテゴリにおいて置かれている真の座標を示している点にある。「誰を代替するか」ではなく、「どのスロットにおいてより割に合うか」である。原動力はサプライチェーンの制御可能性、コスト、カスタマイズの自由であり、性能の世代差ではない。機能安全も弱点ではなく、NA900 は既に ASIL-D 能力を備えており、本当に長いのはチップ全体の 3 年から 5 年にわたる認証サイクルである。

2.2 国際メディアの視点：サーバー CPU が集中して登場した後、適配コストが真のハードルに

日付：2026-10-22　情報源：Global Times：Chinese chipmakers roll out new RISC-V server CPUs for AI demand（10-22）

サミット後、海外メディアが発表した総説は、進迭時空 V100 と藍芯算力 LX500 を同じ物語に位置づけている。中国のメーカーは RISC-V を組み込み分野から AI サーバーへと押し進めている。

  • 事実部分：V100 は 46 コア、最高 2.4 GHz、DDR5 と PCIe 5.0 をサポートし、計算、AI、ストレージの 3 種類の完成機を同時に提供する。LX500 は 48 コアで専用 AI エンジンを統合し、Qwen、DeepSeek、Kimi などのモデルへの適配を進めており、目標とするシーンには企業ナレッジベース検索、オフィスアシスタント、金融コンプライアンス推論、産業巡检が含まれる。
  • 意見部分：取材に応じたアナリストは、サーバー CPU の競争は単一チップの性能にとどまらないと考える。プロセッサの置き換えは部品の交換ではない。オペレーティングシステム、アプリケーション、開発ツールが円滑に動作するか、適配・保守コストが受け入れられるかが、顧客が移行するかどうかの鍵である。適配コストが高すぎる場合、たとえ新チップに技術的優位性があっても、顧客は躊躇する。

「発表」と「実装」を分けて見ると、この記事は外部視点の物差しを提供している。展示会場の完成機はハードウェア形態が既に整っていることを証明するが、エコシステム側のコスト計算が受注を決める。これは本号の今日の重点と互いに注釈し合うものである。

2.3 楽鑫 ESP32-S31 が完成品へ波及：GUITION ロータリースクリーンが新 SoC に世代交代

日付：2026-10-22　情報源：CNX Software：Rotary encoder with 1.8-inch touch display gets upgrade to ESP32-S31 SoC（10-22）

GUITION JC3636F118C-I-YR1 は、従来の ESP32-S3 バージョンを ESP32-S31NRV16 にアップグレードしたロータリーノブ画面製品です。1.8 インチ 360×360 円形 TFT（ST77916 ドライバと CST816 タッチ）、16 MB フラッシュと 16 MB PSRAM、スピーカーと MEMS マイク、DRV2605 触覚ドライバ、USB-C 給電を備えます。

  • 無線仕様：Wi-Fi 6、Bluetooth 5.4（LE Audio、方向探知、Mesh 1.1 を含む）、802.15.4 のトリプルモード。CPU は 320 MHz の RV32IMAFCP 高性能コアと低消費電力 MCU コア。
  • 製品の意義：ESP32-S31 が初めてサードパーティ製開発ボードに登場（10-14）してから十日足らずで、製品の世代交代が始まった。MCU 級 RISC-V の完成品への追随速度は、前世代アーキテクチャより明らかに速い。

3. 国内チームの深掘り

3.1 達摩院玄鉄 CubeSandbox：RISC-V CI を 12 コミット連続で推進、マイクロ VM 制御プレーンで MySQL を動作させ実証

日付：2026-10-22　情報源：XUANTIE-RV/CubeSandbox：feat/riscv64-ci ブランチ submit（10-22）

玄鉄がメンテナンスする CubeSandbox は、調査期間内に作業の重心を「RISC-V ブランチを開く」ことから CI の攻略へと移しました。feat/riscv64-ci ブランチには 12 コミットが記録され、そのすべてが RISC-V 上でマイクロ VM（microVM）の制御プレーンを安定して動作させることに向けられています。

  • カーネル設定：バージョン 7.2 の L1 カーネルに対して CONFIG_NUMA を有効化し、XFS と dummy ドライバをカーネルに組み込み、tc-bpf、bridge、tap ネットワークスタックを補完。
  • 可観測性：失敗時に L1 の dmesg と L2 ゲストコンソール出力を取得。環境変数スイッチを追加してゲストコンソールを可観測に。dirty log をデフォルトで無効化し、CUBE_DISABLE_VM_DIRTY_LOG をエスケープハッチとして用意。
  • フロー：shim の VM 起動待ち時間を延長し、終了時に L1 を停止。C1 制御プレーンのデモを apt でインストールした mysql systemd ユニットに切り替え、まず mysqld の可観測性を修正し、その後サービスが正常に停止できることを検証。
  • 上流の背景：上流はテンセントクラウドがオープンソース化した AI Agent サンドボックス（Apache 2.0、ハードウェア級分離、ミリ秒級起動、E2B インターフェース互換）であり、RISC-V 側のスナップショットと復元は依然として vAIA 状態移行の実装待ちで、開発者プレビュー段階に属する。

これら十数コミットのうち「機能リリース」と呼べるものは一つもなく、すべて不安定要素を一つずつ潰していく作業です。カーネル設定、シリアル可観測性、ダーティページログ、MySQL の起動停止検証。マイクロ VM が RISC-V 上で起動できる状態から実際の負荷を支えられる状態になるまでのコストは、ほぼすべてこうした作業に費やされます。これこそが、このスタックの成熟度を判断する最も信頼できる観察点です。

3.2 進迭時空のソフトウェアスタックが三本柱で反復：視覚モデルインターフェースの統一、llama.cpp のプリフィル最適化

日付：2026-10-22　情報源：model-zoo-vision submit（10-22）、llama.cpp：mtmd-backend ブランチ submit（10-22）、ai-sdk submit（10-22）

V100 のリリース後、進迭時空のソフトウェアスタックは三つの路線で同時に小幅な反復を進めており、その方向性はいずれも「外部開発者がそのまま使えるようにする」ことです。

  • 視覚モデルライブラリ：model-zoo-vision の 3 コミット。コアとなるリファクタリングで各タスクの Run インターフェースを統一し、task 層インターフェースを削除（#109）。各モデルサンプルの README を統一（#110）。track と match の 2 種類のモデルに Python サンプルを追加（#111）。
  • 推論スタック：llama.cpp の mtmd-backend ブランチで 2 コミット。ggml 側の SpacemiT プリフィル最適化（#49）と、古くなった重複する -lm および –load-mode オプションの整理（#50）。
  • SDK：ai-sdk で 2 件のサブモジュール更新、vision モジュールを指す。
  • 関連ドキュメント：docs-ros は同日 2 コミットで知覚と視覚のドキュメントを新しいノード動作と SDK インターフェースに整合（#217、#218）。

インターフェースの統一とサンプルの補完は、モデルライブラリが外部開発者に向き始めたシグナルです。一方プリフィル最適化は長コンテキストの処理効率と初回トークン遅延に直接影響し、サーバーシナリオで最も敏感な指標の一つです。チップリリース後のソフトウェア追随速度は、しばしば仕様そのものより重要です。

日付：2026-10-22　情報源：sophgo/sophon-demo コミット記録（10-22）

算能のサンプルリポジトリ sophon-demo は release ブランチに PaddleOCR-VL の Python サンプル（paddleocr_vl.py）を新規追加し、このドキュメントインテリジェンスモデルを自社プラットフォーム上で直接実行できるバージョンを補完した。

  • 経緯：10-19 に同リポジトリで整理を行い、リポジトリに同梱していた tpu-mlir wheel のダウンロードを削除した。今回は Python バージョンを補完し、ドキュメントとサンプルからなる完全な組み合わせを形成した。

4. 具身智能とロボット専門章

4.1 21世紀経済報道が孫彦邦氏に独占インタビュー：K3 がヒューマノイドロボットの完走を支え、ロボットは単一チップへ向かう

日付：2026-10-22　情報源：21世紀経済報道（新浪財経転載）：ヒューマノイドロボットマラソンの背後にある RISC-V の力（10-22）

サミット後の深掘り独占インタビューで、取材対象は進迭時空の共同創業者孫彦邦氏であり、検証可能ないくつかの進展と判断を示している。

  • 既に起きた進展：2026 年 4 月の北京亦荘ヒューマノイドロボットハーフマラソンで、霊龍 2.0 の完走に用いられたのは進迭時空の K3 チップであった。K1 は累計出荷 15 万個、K3 は世界初の RVA23 規範に適合する量産 RISC-V チップであり、すでに規模量産・納品を実現している。これら 2 世代のエッジ側チップの蓄積は、クラウドへと延伸する起点として描かれている。
  • 市場予測：Omdia のデータを引用し、RISC-V プロセッサの年間出荷台数成長率は 50%、2030 年の世界シェアは 25% 近くに達し、プロセッサ約 4 個に 1 個が RISC-V になるとした。
  • 判断 1：ロボット産業は規模化・実装の周期に入ると必然的に単一チップ集積の路線へ向かい、次世代ロボットは RISC-V への依存を強める。その理由は安全性への徹底した要求と、強力な CPU に AI 能力を融合させることにある。
  • 判断 2：ロボットのリアルタイム性要求は「永遠に天井がない」。AI Agent の逸脱現象が頻発し、仮想化も物理隔離もシステムを常に制御可能な範囲に保つことを徹底して保証するのは難しく、むしろオープンソース・オープンな仕組みが突破口になり得る。Physical AI が最大の機会である。
  • 判断 3：研究開発路線は資金力とマッチさせる必要がある。PPA の他にハードウェアは過剰搭載でなければソフトウェアエコシステムが活かせない。国産産業チェーンのイテレーション速度は期待に値するが、最終的な評価基準は依然として受注への転換である。
  • 外部の見解：別途、チューリング賞受賞者 David Patterson の判断を引用し、AI がストレージ帯域と容量の圧力を押し上げ、主流標準ストレージの性能向上は停滞しており、領域専用ストレージ（DSA）が計算資源希少の背景で実行可能になっているとした。

この記事は「RISC-V でロボットを作る」を概念から二つの具体的な座標へと落とし込んでいる。すなわち、すでに規模量産されたエッジ側チップと、「安全 + リアルタイム」というアーキテクチャ上の理由である。計算力の数字よりも、後者のほうがロボットメーカーがなぜアーキテクチャを切り替えたいのかをよく説明できる。そして「ハードウェアは過剰搭載でなければならない」という一言は、現在のロボットチップが一般に計算力を前もって余分に確保している手法をまさに説明している。

4.2 spacemit-robotics：動作認識設定を 13 点骨架に整合

日付：2026-10-22　情報源：ros2_action_recognition コミット（10-22）、spacemit-com/docs-ros コミット（10-22）

進迭時空のロボットソフトウェアラインは調査期間内に一度のインターフェース整合を完了した。動作認識リポジトリは修正をマージし、STGCN 設定と 13 点骨架定義を視覚 API に整合させ（#8）、同時期に docs-ros の 2 件が知覚と視覚のドキュメントを新たなノード動作と SDK インターフェースに同期し、ai-sdk の 2 回のサブモジュール更新は vision を指している。

  • リポジトリの位置づけ：spacemit-robotics はジェスチャー認識、動作認識、リアルタイムリンク、外設制御をカバーし、K3 プラットフォームロボットの付属ソフトウェアに属する。同じ調査期間内には realtime-link、manifest、peripherals_led のプッシュもあった。
  • 解読：骨架のキーポイントを一般的な 17 点や 21 点から 13 点に収束させるのは、上流モデルと自社推論パイプラインを整合させる際の典型的な一歩である。ドキュメントと SDK が同時に更新されていることは、このラインが内部試験ではなく対外納品を準備していることを示している。

5. まとめとトレンド観察

  • サーバー物語の重心は「チップ発表」から「インフラ適合」へ移行：サミットでは V100、LX500、C950A が集中的に登場し、サミット後の最初の新たな動きは科華データと進迭時空の契約締結、そして境外メディアによる適合コストに関する議論であった。ハードウェア形態はすでに整っており、次に問われるのはデータセンター側の受容度とソフトウェアスタックの移行コストである。
  • RISC-V の細分カテゴリーにおける位置づけがより明確に：ミリ波レーダーの報道は、DSP とハードウェアアクセラレータが主要な演算を担うチップにおいて、CPU 命令セットは「ソリューションの選択」であり「世代交代」ではないことを示している。国産メーカーが先に採用した理由はサプライチェーンの制御可能性とカスタマイズの自由度であり、性能の世代差ではない。
  • ディストリビューションの補完ペースは安定し、層が上昇：openRuyi は3日連続でそれぞれ Go クラウドネイティブコンポーネント、uv の Rust 依存関係と Python、Node、Java ランタイムバージョンを補完し、セキュリティ修正はマーク付きでプロセスに沿って進み始めた。RISC-V ディストリビューションは「インストールできる」段階から「本番環境で使える」段階へ向かっている。
  • マイクロ VM スタックは RISC-V 上でデバッグ期に突入：CubeSandbox の12件のコミットはすべてカーネル設定、可観測性、プロセス検証であり、機能リリースは一つもない。これは起動できる段階から負荷を支えられる段階への不可避な過程であり、RISC-V 仮想化の成熟度を観察する最良の窓口でもある。
  • 端末側に外溢効果が出現：ESP32-S31 はプレビュー部品から第三者完成品までわずか約10日で到達し、コミュニティプロジェクトはそれ上で完全な Linux とグラフィカル以外の全ユーザー空間を動作させた。このような「下へ絞り出す」遊び方は RISC-V MCU の開発者露出を継続的に拡大するだろう。
  • ロボット側の証拠は依然として端末側とリアルタイム制御から：K3 はヒューマノイドロボットの完走を支え、関節制御チップはすでに量産されているが、大算力の「脳」チップは多くがテープアウト段階にある。RISC-V のロボットにおける最初の実出荷は、おそらく汎用 AI 演算ではなくモーション制御からのものであろう。
  • 限界説明：科華データと進迭時空の協力詳細は両社の対外発表と財経メディアの転述によるもので、契約金額、タイムテーブル、具体プロジェクトは非開示。ミリ波レーダー報道の性能数値（3668 DMIPS、クラスタリングと追跡の所要時間）はメーカー試験によるもので、第三者による再現は見られない。Global Times のインタビュー対象は業界アナリストであり、見解は産業界のコンセンサスを代表するものではない。ESP32-S31-Linux はコミュニティプロジェクトに属し、作者自述によれば「Linux 向けに設計されていない」デバイス上での移植実験であり、製品化経路を構成するものではない。openRuyi のコミット内容はコミットタイトルに基づく判断であり、changelog を逐条照合したものではない。CubeSandbox の RISC-V サポートは依然として開発者プレビューであり、公式はリリースイメージを提供していない。会員公式サイト巡回で検出された95箇所の変更はすべて大学、機関、メーカーのホームページの定例更新であり、実質的な製品、資金調達、アーキテクチャリリースは発見されていない。
