今日の重点：進迭時空の端側 Agent フルスタックが集中的に公開：BiBit GUI と音声サービスが 1.0Beta1 をリリース、Bianbu AgentOS コンポーネントがオープンソース化

日付：2026-10-14　出典：bibit Release 1.0Beta1（10-14）、bibit-voice Release 1.0Beta1（10-14）、bianbu-agent-runtime 初回インポート（10-14）、bianbu-agent-memory 初回公開スナップショット（10-14）

10-13 の集中的なリポジトリ構築（前回デイリーレポートで既報）に続き、進迭時空は当期間内に端側 Agent システムソフトウェアスタック（Bianbu AgentOS）を全面的に公開した：デスクトップ向け BiBit GUI とオフライン音声サービス Bibit Voice が 1.0Beta1 をリリースし、Agent ランタイム、記憶サービス、セキュリティコンポーネントなどが集中的にオープンソース化された。要点：

  • BiBit GUI（1.0Beta1）：Agent システムアシスタント向けのデスクトップフロントエンド。オープンソースプロジェクト Jan をコード骨格とし（React 19＋Tauri 2＋Rust、Yarn 4.5.3 ビルドチェーン）、現在は対話インタラクション、リッチメッセージ、添付ファイル、セッション履歴、設定画面を保持・進化させている。Bianbu 4.x riscv64 向けに Debian ネイティブパッケージを提供（ソース内で Yarn バージョンを固定し、RISC-V ビルドマシンのメモリ制約に適応）。Agent Runtime は当面 Jan 互換実装を踏襲し、後続で Adapter 経由で正式ランタイムに接続する。
  • bianbu-agent-runtime（初期オープンソース）：YAML 設定駆動の Agent サービス。Bianbu AgentOS のランタイム核心と自称——セッションはイベントストリーム（マルチエンド同一投影）、プラグインは Tool／Skill／Hook／MCP／Console ページを提供可能、securityd 署名マニフェストと Tool 承認などのセキュリティ境界（本番モードは fail-closed）。現在は K3（riscv64、Bianbu 4.0）のみ対応。
  • bianbu-agent-memory：デバイス側、ローカル優先のメモリサービス（Rust デーモン＋Python SDK＋Unix socket プロトコル）——L1 セッションイベント／L2 ワークサマリ／L3 長期記憶の三層、ローカル全文検索、SQLCipher 暗号化、バージョン競合検出とネームスペース分離。CLI、MCP サービス、Runtime Bridge を提供し、Hermes と DeepSeek Harness アダプタを含む。
  • Bibit Voice（1.0Beta1）：K3／Bianbu Desktop 向けのオフライン音声サービススタック——ウェイクワード検出（KWS）、音声活動検出（VAD）、音声認識（ASR、SenseVoice／Qwen3-ASR）。PipeWire 収集と sherpa-onnx SpacemiT runtime をベースとする。対外的に二層の Unix socket と MCP（8 つのツール）を提供し、ウェイク応答音「我在」をパッケージに同梱して配布。
  • 同批次オープンソースコンポーネント：bibit-intent（エッジ優先の意図ルーティングとツール実行）、bibit-filesearch（ローカルファイル検索サービス）、bibit-runtime-plugin、bianbu-agent-security を初期公開。ほかに mpp メディア処理ライブラリは MIT ライセンスに変更し著作権表記を統一、ai-sdk は KWS サブモジュールと中日英アーキテクチャ図を追加、docs-product は V100 シリーズ（C2201／S5236／G5201）製品ページの骨格を新規追加。

上記コンポーネントと K3 ハードウェア、Bianbu ディストリビューションは「チップ—システム—Agent ランタイム」の縦方向の組み合わせを形成する。Bianbu AgentOS は単一プラットフォーム（K3）で先行検証し、その後他プラットフォームへ拡張する路線が比較的明確になっている。

1. オープンソースコミュニティとソフトウェアエコシステム

1.1 Linux カーネルパッチで「本機が RVA23 準拠か」をワンクリックで確認可能に

日付：2026-10-14　情報源：Phoronix：Linux Finally Making It Easier To Answer The Question: “Is This RISC-V System RVA23?”（10-14）、LPC 2026 講演《RVA23 in practice》資料（10-02）

Phoronix 報道：Linux ユーザーはまもなく「私の RISC-V システムが RVA23 準拠かどうか」を「一度に」回答できるようになる——マージ待ちのカーネルパッチが単一クエリ機能を提供する（現状は /proc/cpuinfo、hwprobe とプロファイル要件を突き合わせて項目ごとに比較する必要があり、Ubuntu 側のツールはこれまで「probably RVA23」しか提示できなかった）。報道の添付画像はまさに SpacemiT K3 の RVA23 レポートのスクリーンショットである。背景（本シリーズのこれまでの報道と接続）：この機能は LPC26 で開示された **riscv_hwprobe 単一ビット方式（KEY_BASE_BEHAVIOR：IMA RVA23U64、起動時に完全な ISA ビットマップから一度に計算）**——シリーズパッチは Andrew Jones が RFC を発起し、現在は徐国棟（Guodong Xu）が推進、10-09 に v8 に到達（11 枚の patch のうち前半 8 枚が riscv/for-next に収録）、v9 では RVA22／RVA20 の階層ビットを補足する。RVA23 プロファイルは統一された現代 RISC-V バイナリ配布にとって極めて重要である（Ubuntu の現代バージョンはすでにこれをベースラインに位置づけているが、準拠ハードウェアは依然限られている）。

1.2 RISE プロジェクトが SpeexDSP の RVV ベクトル最適化成果を発表：リサンプリングは最高 4.88 倍高速化

日付：2026-10-13~10-14　情報源：RISE Project：Accelerating Audio Processing with SpeexDSP Optimizations for RISC-V（10-13）、Hacker News 討論（10-14）

RISE（RISC-V ソフトウェアエコシステム）プロジェクトが RP020 結項成果を公表：リアルタイム音声基盤ライブラリ SpeexDSP（音声リサンプリング、エコーキャンセレーション、ジッタバッファ、前処理。VLC、Firefox、Wireshark、PulseAudio、Mumble などで広く使用）に手書き RVV アセンブリを導入し、そのビルドと検証基盤をモダナイズした。要点：

  • 性能：手書きベクトルリサンプリングカーネルと「コンパイラ自動ベクトル化 C」の比較——浮動小数点カーネルは 3.71 倍（Clang 18）／3.59 倍（GCC 13）高速化、固定小数点カーネルは 2.69 倍（Clang 18）／4.88 倍（GCC 13）（後者は GCC が自動ベクトル化できなかった）。
  • クロスハードウェア検証：RVV の長さ非依存特性により、同一のアセンブリが SpacemiT K1（VLEN=256）と Canaan K230（VLEN=128）の両物理プラットフォームで有効。
  • 検証基盤の波及効果：Meson＋Checkasm による検証の副産物として、SSE2 カーネルの 8 年間潜在していたデータ依存欠陥を発見・修正（内積カーネルは以前スカラー C よりも 0.58~0.75 倍遅かった）。
  • 組織形態：Google エンジニアと RISE の協力で推進（技術リード Nathan Egge、請負業者 FFlabs／Tristan Matthews）、RISE が 4 万ドルを助成。

1.3 openRuyi：ファームウェアラインが「Ruyi Firmware 20261014」をリリース、K3 デュアルクラスタ CPU モード選択が実装

日付：2026-10-14　情報源：Ruyi Firmware 20261014 Release（10-14）、edk2-ruyi：K3 persistent CPU selection modes（10-14）、openRuyi コミット記録（10-14）

openRuyi ファームウェアラインが 「Ruyi Firmware 20261014」をリリース。中核機能は K3 プラットフォームの CPU クラスタモード選択：UEFI Setup にモードスイッチを新設し、設定は SPI 専用セクタに永続化され、coreboot が OpenSBI 起動前に読み取る（次回起動時に有効、ファームウェアアップグレード時はデフォルトに復帰）。三つのモードを提供——X100 only（デフォルト、8 コア、RVV VLEN 256、H 拡張保持）、X100＋A100（16 コア）、A100 only（8 コア、VLEN 1024）。fastfetch などのツールでは k3／k3-x100-a100／k3-a100 として表示される。実装の詳細：A100-only 起動は SBI HSM を介して SEC を hart 0 から hart 8 に移管（元の hart の停止を待ってスタックを再利用）。UEFI 交接ツリーでは X100 ノードを無効化しつつ物理 IMSIC スロット番号を保持。デバイスツリーのルート互換文字列がモードを同期反映し、ユーザー空間の命名に供する（Linux ソースコードの変更は不要）。メインリポジトリ側では Mesa 26.2.4 アップグレードと PowerVR（pvr）最適化のバックポート、mesa-gallium が mesa-vulkan-drivers を推奨するなどの SPECS 更新を同時にマージ。openRuyi 公式サイトのニュースページには新しいバージョンの掲載はない（最新は依然 2026.09）。

2.2 楽鑫 ESP32-S31 に初のサードパーティ開発ボード登場：VIEWE 4.3インチスマートディスプレイモジュール

日付：2026-10-14　情報源：CNX Software：VIEWE launches 4.3-inch ESP32-S31 display development board（10-14）

楽鑫の新世代 RISC-V SoC ESP32-S31（320MHz ハイパフォーマンス RV32IMAFCP コア＋低消費電力コア、Wi-Fi 6／Bluetooth 5.4／802.15.4）に初のサードパーティ開発ボードが登場：VIEWE が4.3インチ 800×480 スマートディスプレイモジュール（型番 PLCM-UES31S043H800V480C-U、38.99ドル）を発表。要点：オンボード ESP32-S31-WROOM-3-N16R16V モジュール（16MB PSRAM／16MB Flash）、GT911 静電容量タッチ、ES8389 オーディオコーデックとデュアルマイク、RS485／CAN インターフェース、microSD（SDIO 3.0）、USB-C（CH340C デバッグ）＋USB-A（OTG）、-20～70℃対応。S31 は依然としてプレビュー部品であるため、開発には ESP-IDF master ブランチに –preview パラメータを使用する必要があり、VIEWE は GitHub で LCD／タッチ／オーディオ／RS485-CAN と LVGL ファクトリ UI のサンプルをオープンソース化済み。注：楽鑫は8月に ESP32-S31 の Linux BSP 開発者プレビューを発表している。

日付：2026-10-14~10-15　情報源：damo-rv-ats PR #7 マージコミット（10-15 00:19）、玄鉄 RISC-V 業界・技術セミナー・北京駅予告（10-14）

達摩院玄鉄（XUANTIE-RV）は自社開発の RISC-V アーキテクチャテストスイート DAMO-RV-ATS に Zvfbfmin と Zvfbfwma（BF16 ベクトル）命令テストをマージした：vfncvtbf16／vfwcvtbf16（単一ワード幅変換）と vfwmaccbf16.vf／.vv（BF16 拡幅積和演算）のテストケースおよびビルドスクリプトを新規追加し、さらに四份のテストフレームワークドキュメント（共通基盤、整数ベクトル、浮動小数点ベクトル、ベクトル暗号）を補足し、「設定→実行→照合」の方法論をカバーしている。同一調査期間に、玄鉄は業界・技術セミナー・北京駅の予告を発表した：10月22日 14:00–17:15 に北京中関村東升科技園万麗酒店で開催され、三大セクション――次世代高性能 RISC-V プロセッサコアアーキテクチャ進化の詳細解析、システム協調設計（STCO／Multi-Die／高性能ソフトウェアスタックチューニング）、エージェント時代の計算アーキテクチャ（「AI チップから Agent チップへ」）――を中心に展開される；参加登録は審査制。玄鉄のオフラインイベントとベクトル命令エコシステム構築の二本柱が並行して進み、10-18 サミット週にさらなるサイドイベントが加わった。

3.2 奕斯偉計算：RISC-V マトリクス拡張（AME）BF16 GEMM テストベクトルライブラリをオープンソース化

日付：2026-10-13~10-14　情報源：eswincomputing/riscv-matrix-gemm-vectors（10-14 更新）、更新コミット（10-14）

奕斯偉計算（ESWIN Computing）は riscv-matrix-gemm-vectors リポジトリをオープンソース化した（10-13 に作成、10-14 に著作権と README を補足）：RISC-V マトリクス拡張（AME）仕様提案 v0.6.0 向けの BF16×BF16→FP32 マトリクス積和演算テストベクトルセット――各テストケースはベアメタルプログラム（演算を実行し、自己検証して判定結果を書き戻す）であり、実装非依存の参照値と結果チェッカー check.py が付属する。判定には標準的な丸め誤差界（ Ĉ−C* ≤ γ(G)·Σ a·b 、デフォルト G=K）を採用し、ビット単位の比較ではなく、仕様が許容する「順序不問の総和」実装差異に対応している（正負の積の相殺時に正しい結果が正確な和から数千 ULP 離れることがある）；同時に、二つの「すべての準拠実装で結果のビットが同一」となるテストケースを提供し、誤った丸めを検出する。参照値と判定基準は特定の命令セットに依存せず、他のマトリクス拡張実装にも再利用可能であり、国内ベンダーによる AME エコシステム向けのテスト基盤への貢献である。

3.3 香山：昆明湖メインラインで L2 メモリアクセスレイテンシを最適化；検証チェーン（difftest／NEMU／GEM5）を継続的に反復

日付：2026-10-14　情報源：XiangShan #6713：reduce L2 load-to-use latency（10-14）、XiangShan ICache 修正（10-14）、difftest：GBD1 DMA drain（10-14）、NEMU #1251（10-14）、GEM5 #1228（10-14）

香山（kunminghu-v3）の調査期間内に dcache 性能最適化——L2 load-to-use レイテンシの低減（#6713） をマージし、ICache 例外伝播（#6414）とフェッチブロック末尾オフセットのデータ ECC シナリオにおける bank 選択を修正し、Zimop（MOP）命令デコードをサポートした（デコードは add rd, x0, x0）。検証・シミュレーション基盤：difftest は GBus DiffTest に GBD1 frozen-bank DMA drain（FPGA シナリオ向け）を追加；NEMU は AME 行列ストアロールバック記録（#1251）と vcompute REM 分岐判定（#1253）を修正；GEM5 は macOS ビルドを復旧し、手動スモーク CI を新規追加（#1228）、xsstream アクティブ領域判定を整合（#1223）。XSCache は調査期間内にメインブランチの新規コミットなし。

3.4 算能：zsbl 起動チェーンを二段階プラットフォームモデルに再構築；HD12 サーバファームウェア更新

日付：2026-10-14　情報源：zsbl：プラットフォームサブシステムとアプリの分割（10-14）、mcu：HD12 ファームウェア更新（10-14）

算能（SOPHGO）の二本柱の更新：zsbl（ゼロ段起動ローダー） はプラットフォーム構成を「サブシステム×アプリ」の二段階モデルに再構築——1つのプラットフォームが複数の CPU サブシステムを収容でき、各サブシステムが複数のブートアプリ（PLAT_SG2044／SG2044_MP／SG2044_MP_ZSBL など）を実行可能であり、各サブシステムのソースコードは plat/// に移動し、プラットフォームレベルには共用ヘッダーファイルとメモリマップのみを保持し、プラットフォームレベルの Kconfig を導入；同時に PLAT_BM1690TP を PLAT_BM1690 に改名（BM1690 は SoC、TP はサブシステム）。**サーバ MCU／BMC ファームウェア（mcu）** は HD12 マザーボードに **RHS12 ボード互換、C2C 相互接続リンク（起動／クリーンアップと状態チェック）、64GB DDR サポート、および MCU／BMC 起動ログの I2C 経由での公開**をマージ（ファームウェアバージョンは 14 に更新）。

3.5 矽速：ロジックアナライザソフトウェア SLogic が v2.3.0 をリリース、共有キャプチャエンジンを導入

日付：2026-10-14　情報源：SLogic Release release-2.3.0（10-14）、SLogic コミット記録（10-14）

矽速（Sipeed）のロジックアナライザソフトウェア SLogic が翌日にも新版をリリース：v2.3.0 は共有キャプチャエンジンを導入（ファームウェア 202610140927 以上が必要）、0% トリガ位置（ホスト側プリトリガバッファ）をサポートし、リンク能力に応じたサンプルレート制限とリンクラベルを追加、コールドスタートの計時を RUN 命令時点からの起算に変更、Windows での ngscopeclient ビルド問題を修正；リリースノートは中英二言語を提供。付随する ALL-LOGIC ライブラリは調査期間内に 7 件のコミット（トリガ位置、リンク速度制限、デバッグレベルのリアルタイムレートなど）。矽速組織は調査期間内に計 6 つのリポジトリをプッシュ（他に libsigrok、scopehal、pulseview を含む）し、ロジックアナライザのソフトウェア・ハードウェアのイテレーションは高ペースを維持。

4. 具身智能とロボティクス専章

4.1 端側 Agent 基盤は「システムレベルパッケージ」へ：Bianbu AgentOS と K3 の組み合わせ納品に関する観察

日付：2026-10-14　情報源：bianbu-agent-runtime（10-14）、bibit-voice（10-14）、spacemit-robotics 組織リポジトリ

本調査期間におけるエンボディドAIとロボティクス側の主な観察ポイントは「エッジ側Agent基盤のシステムレベル・カプセル化」である。進迭時空は Bianbu AgentOS の名義で完全なチェーンを公開した——デスクトップフロントエンド（BiBit）、ランタイム、ローカルメモリ、オフライン音声（KWS／VAD／ASR）、セキュリティコンポーネント（本日の重点参照）——そして明確にK3（riscv64）を初回リリースかつ現在唯一のサポートプラットフォームとしている。ロボット／エッジデバイスにとって、これは「音声ウェイクアップ—意図理解—ツール実行—長期記憶—監査セキュリティ」という自己デプロイ可能なオープンソーススタックが、散在するSDKではなく、RISC-V上で初めて一式のテンプレートとして提供されたことを意味する。これに伴い、ハードウェア側ではK3のCPUクラスタモード選択（X100／A100、1.3参照）が「性能コアで推論、省電力コアで制御」という異種分担にファームウェアレベルのオプションを提供している。これに対して、ロボット専門組織 spacemit-robotics は当期間に新規プッシュなし（ペリフェラルIMU／モーター／知覚ライブラリの最近のプッシュは10-12）。「チップ＋Agentソフトウェアスタック＋シーンカプセル化」の組み合わせデリバリはなお深化中であり、ソフトウェアスタックは「使える」から「メンテナブル、監査可能」へと移行しつつある。

五、総括とトレンド観察

  • エッジ側AgentがRISC-Vソフトウェアスタックの新たな焦点に：進迭時空はBianbu AgentOS全スタック（GUI／ランタイム／記憶／音声／セキュリティ）を集中的に公開し、K3で先行検証——藍芯算力など「サーバー化」のナラティブと対照をなし、RISC-Vはエッジ側AI Agentインフラ方向で一式のオープンソーススタックが出現した。
  • インフラの両端を同時に補強：Linuxカーネル rva23u64 の単一ビット照会が間もなく着地（Phoronix報道；v8の一部は既に riscv/for-next に入り、v9は進行中）、RISEはSpeexDSPに手書きRVVベクトルカーネルを追加（リサンプリング最大4.88倍）——「資格認証（RVA23）＋マルチメディア性能（RVV）」の2本の主線が同時期に推進されている。
  • サミットウィークが迫る：RVSC2026（10-18~20 深圳）の会前素材（宣传稿、議程、展示ホール図、同時期イベント）がすべて準備完了。さらに10-17進迭時空開発者会議、10-21 GBA／HK Day、10-22玄鉄北京研討会が重なる。Ubuntu 26.10が初の公式RISC-Vデスクトップイメージを伴い10-15にリリース予定で、次回の重点観察対象となる。
  • 国内エンジニアリング側の高密度出力：達摩院玄鉄がBF16ベクトルテストを補完、奕斯偉がAMEテストベクトルをオープンソース化、香山がL2メモリアクセス遅延を最適化しICacheを修正、算能が起動チェーンとサーバーファームウェアを再構築、矽速がSLogicを2版連続リリース。
  • 制約に関する説明：Phoronix本文はサイトの保護により制限されており、1.1の項目はそのRSS要約とLPC26公開資料に基づきクロス執筆した。RVSC2026の項目は一部情報がサミット公式サイトとWeChat公式アカウントに由来し、公式発表を基準とする。奕斯偉テストベクトルリポジトリのコンプライアンス判定の詳細はそのREADMEを基準とする。
