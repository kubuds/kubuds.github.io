今日の重点：LPC26 帰還——RVA23u64 カーネル profile ビット推進、8枚のパッチが riscv/for-next にマージ済み

日付：2026-10-11　情報源：WeChat公式アカウント「Docular嘚吧嘚」：LPC26 参会記（10-11）、LPC26 講演資料（slides）、作者ホームページ：Docular

RVA23 カーネル作業の主要推進者である徐国棟（Docular、現在クアルコム在職）が Linux Plumbers Conference 2026（LPC26、プラハ）参会記を発表：彼が主導する Linux カーネル rva23u64 profile ビットシリーズは v9（進行中）へと推進されており、10月9日の v8 の11個の patch のうち最初の8個が RISC-V カーネルメンテナ Paul Walmsley によって riscv/for-next に取り込まれた（次のマージウィンドウでメインライン入り待ち）。残り3枚のコア patch は LPC 会場での意見を反映した上で v9 として提出される予定。

  • 解決すべき問題：RVA23 profile 1.0（2024-10 批准、39 必須 + 15 オプション拡張）は、カーネルとユーザー空間が低コストで「このハードウェアは RVA23 か」に答える必要がある——現状はビット単位の問い合わせのみで、glibc、GCC がそれぞれ独自に計算し、Ubuntu 側の検出ツールも “probably RVA23” としか出せない。提案は、カーネル起動時に “RVA23 compliant” ビットを算出して vDSO に入れ、ユーザー空間は hwprobe UAPI を通じて一読するだけで取得できるようにするというもの。
  • LPC26 の 4 つの Ask の結論：① v8 ビット形式はメンテナに承認され、v9 では RVA22 / RVA20 の階層ビットを補足し（glibc が段階的にフォールバックするため）、IMA ビットを継承しない歴史的遺産の動作を明記する；② glibc は profile ごとのビルド + glibc-hwcaps による自動ライブラリ選択に変更する（hwcaps の来源はすなわちカーネルビット；ifunc はマイクロアーキテクチャレベルの選択に残す）。GCC メンテナの Jeff Law は GNU Tools Cauldron の RISC-V BoF で同方向に推進；③ ユーザー空間で動的に V 拡張を無効化するインターフェースは廃止する——LPC 翌日、Samuel Holland（SiFive）が 3-patch シリーズを送信（cover letter：RISE と LPC26 はすでにコンセンサスを形成、create more trouble than benefits）；④ 将来的にレジスタ状態を持つ拡張（例：matrix）では同種のスイッチを再導入しない。
  • 波及効果：当該シリーズは直接的または間接的に少なくとも 5 つのメインラインシリーズを牽引した——2 年間棚上げされていた 2 つの旧パッチ（拡張名の大文字小文字統一、Zicclsm）が吸収され、字節跳動の Qingwei Hu が Zic64b サポートを貢献、さらに do not report disabled extensions（6 patch シリーズ）、cpufeature BUNDLE から SUPERSET への精简、V-off 廃止シリーズが同期間に送信された。
  • 補足：今回の LPC の RISC-V MC は全 10 場の talk で、高通が 3 場を占めた；当該 talk の slides はすでに公開済み（参考リンク参照）。

1. オープンソースコミュニティとソフトウェアエコシステム

1.1 Phoronix／LPC26：カーネル自動ベクトル化で良好な結果、LZ4 は最大約 15% 向上

日付：2026-10-11　情報源：Phoronix：Auto Vectorizing The RISC-V Linux Kernel Shows Promising Results（10-11）、LPC26 講演ページ：Optimizing the kernel with vector、Hacker News ディスカッション

RISC-V カーネルビルドは現在まだ V（ベクトル）拡張を有効にしていない。Andy Chiu は LPC26（10 月 5-7 日、ブラハ）で講演「Optimizing the kernel with vector」を行い、コンパイラの自動ベクトル化でカーネルを最適化する手法を紹介した：crypto、RAID、XOR、ユーザーコピーなどカーネルシナリオを対象とした実験では——LZ4 が最大約 15% 向上、Btrfs が約 8.4%、XFS が約 5%、Nginx シナリオが約 2% 向上；代償としてベクトルコンテキスト管理による時間とメモリのオーバーヘッドが増大し、カーネル空間でのベクトルユニット使用には依然として既存の制約がある。Phoronix はこの方向性を「前景が有望」（promising results）と評価し、講演資料は会議とともに公開された。

1.2 RevyOS：カーネルが 6.17.11 設定を同期、Rust／PowerVR／NTSYNC などの機能を有効化

日付：2026-10-11　情報源：revyos/linux コミット記録（10-11）

RevyOS（マルチプラットフォーム向け RISC-V Debian ディストリビューション）のカーネルリポジトリは調査期間内に 50 コミット：カーネル設定を 6.17.11 ベースラインへ一括同期し、K1/K3、DP1000、SG2042/SG2044、TH1520 などのプラットフォーム設定を追加、Rust、PowerVR DRM、NTSYNC、K3 ディスプレイコントローラと UFS、SPACEMIT PM ドメイン、FUSB301 Type-C コントローラなどを有効化；デバイスツリーでは K3 Pico ITX に GPU と USB3 ポートを有効化、Milk-V Meles に USB を有効化；CI にはクロス／ネイティブビルドを追加。K3 などのプラットフォームのディスプレイ、USB、ストレージ、GPU サポートがディストリビューションカーネル側で集中的に整備されている。

1.3 openRuyi：SPECS が Go 1.27.2 と OpenSSL 3.6.5 を更新、docker-cli を独立パッケージ化

日付：2026-10-10　ソース：openRuyi コミット記録（10-10）、lookout コミット記録（10-11）、openRuyi 公式サイトニュースページ（10-12 確認）

openRuyi リポジトリの調査期間内に 5 件の SPECS 更新：Go を 1.27.2 へアップグレード、OpenSSL を 3.6.5 へアップグレード、docker-cli 独立パッケージを新規追加（moby の Provides を docker-cli へ移行）；PR テンプレートのリンクを修正。同一組織のバージョン巡回ツール lookout は調査期間内に 10 件のコミットがあり、Go コンポーネントの信頼できるソースタグからの自動検出、正確な Go バージョン追跡、NVD セキュリティアイデンティティ検証などの機能を推進。公式サイトニュースページの確認：最新リリースは依然として 2026.09 版で、新バージョンの告知はなし。

2. プロダクトとエコシステムの動向

2.1 M5Stack ToughC5：防水型 ESP32-C5 産業用 IoT コントローラが発売

日付：2026-10-10　ソース：CNX Software：M5Stack ToughC5 weatherproof ESP32-C5 IoT controller（10-10）

M5Stack は防水型産業用 IoT コントローラ ToughC5（2021 年の M5Stack TOUGH のアップグレード版）を発表：ESP32-C5（シングルコア RISC-V @240MHz + 低消費電力 RISC-V コア）をベースに、デュアルバンド Wi-Fi 6、BLE 5、802.15.4（Zigbee 3.0／Thread 1.3）、8MB Octal PSRAM、16MB フラッシュ、2.0 インチ 320×240 タッチスクリーン（最大 853 ニト）、RS485 と 4 系統の HY2.0-4P 拡張、RX8130CE RTC（独立ボタン電池）、6-24V 給電；防水筐体には USB-C と 4-pin 拡張ポートを内蔵し、M12 配線を装備。産業現場の制御、屋外エッジ収集、スマートビル向けで、価格は 49.9 ドル。

2.2 Wireless-Tag WT32P4C5-43S：ESP32-P4＋C5 デュアルチップ 4.3 インチタッチスクリーン開発ボード

日付：2026-10-11　ソース：CNX Software：Wireless-Tag WT32P4C5-43S（10-11）

Wireless-Tag WT32P4C5-43S タッチスクリーン開発ボード：ESP32-P4（デュアルコア RISC-V @400MHz + 低消費電力コア、16/32MB PSRAM）に ESP32-C5 ワイヤレスモジュールを組み合わせ、4.3 インチ 800×480 静電容量タッチスクリーン（18-bit RGB インターフェース）、15-pin MIPI CSI カメラインターフェース、microSD、デュアル USB-C（デバッグ／JTAG 含む）、14-pin GPIO 拡張を統合。産業オートメーション、スマートコントロールパネル、エッジ AI ビジョン端末向けで、32 ドルから；公式は ESP32-P4 メインファームウェアと C5 コプロセッサの 2 つのファームウェアリポジトリ、および回路図、STEP モデルを提供し、ESP-IDF／Arduino／LVGL をサポート。

2.3 産業観察：クアルコム対 Arm の法廷審理で RISC-V データセンターの成熟度をめぐり攻防

日付：2026-10-11　ソース：Wccftech：Even Court Judges Are Now Declaring That RISC-V Is Basically Worthless（10-11）

クアルコム対 Arm のライセンス紛争の法廷審理（デラウェア州連邦裁判所）をめぐり、RISC-V が意外にも法廷の話題となった。Arm の専門証人 Timothy Simcoe は、RISC-V と x86 が「長期的な競争圧力」を構成すると述べた。主審判事 Noreika は RISC-V の現時点での可用性を追及し、証人はその企業データセンターへの展開はまだ初期段階にあり、関連設計は主に中国企業（阿里玄鉄など）に由来することを認め、主審判事はその後深く追及しなかった。この報道は誇張された見出しで流布し、コミュニティで話題を呼んだ。議論の焦点は企業データセンターのシナリオであり、RISC-V が組み込み分野とエッジ分野で既に達成している進展とは直接矛盾しない。

2.4 業界分析：x86／Arm／RISC-V が工業エッジで「正面遭遇」

日付：2026-10-10　情報源：36 氪：《x86、Arm、RISC-V が工業エッジで正面遭遇》（10-10）

エッジ AI の爆発的成長により、3 つのアーキテクチャが工業シーンで正面から競争している。《半導体産業縦横》（36 氪の許諾を得て掲載）が整理したところによると——x86 はエコシステム（インテル Open Edge Platform、AMD 銳竜 AI 組み込み X100 は最大 80 TOPS、巡回ロボットで既に展開済み）に依拠し、Arm はエネルギー効率と異種統合（瑞芯微 RK3572 は RISC-V コアを統合、RK182X コプロセッサはマルチコア RISC-V を内蔵し、既に数百の顧客プロジェクトに導入済み）に依拠し、RISC-V はオープンでカスタマイズ可能なこと（玄鉄 C950、芯来 NA900 は ASIL-D を通過、奕斯偉 R500A は ASIL-B 認証を通過）に依拠している。記事は、2030 年に工業エッジチップにおける RISC-V の出荷シェアが 7% 未満から 24% 以上に上昇する可能性があると判断し、競争の鍵はツールチェーン、RTOS、認証体系にあるとしている。また、10-12 からの上海工博会展の国芯展で「RISC-V は工業エッジの難関を攻略できるか」フォーラムが設けられることを予告している。

3. 国内チームの深掘り

3.1 香山：圧縮 ROB（crob）アーキテクチャ機能をマージ、MMU と演算ユニットを修正

日付：2026-10-10/11　情報源：XiangShan コミット記録（10-10/11）、PR #6695：MMU が PTE G ビットを無視、PR #6689：狭いシフトのバイアス

香山メインリポジトリの調査期間内に 10 件をマージ：圧縮 ROB（crob）アーキテクチャ機能が着地——圧縮 ROB を実装し CSR 状態追跡を統合、併せて圧縮状態とタイムリミットパスを再構築し、ArchEvent にイベント位置を付与し、エントリオフセットで順序付きストアチェックを維持し、scommit のビット幅を修正してエントリ数を拡張した。また MMU（V=0 のとき PTE の G ビットを無視、#6695）、演算ユニットの狭いシフトバイアスを出力フォーマットに応じて選択（#6689）と CI 性能レポート（#6702、#6705）を修正した。

3.2 香山シミュレーション連鎖：difftest に並列ストアハッシュ検証を追加、NEMU／GEM5 の機能ブランチを推進

日付：2026-10-10/11　情報源：difftest store-hash ブランチコミット（10-10）、NEMU ブランチコミット（10-11）、GEM5 ブランチコミット（10-10）

シミュレーション連鎖の複数リポジトリが調査期間内に活発（主に機能ブランチ）：difftest は lane 並列 CRC-64 ストアハッシュ検証（store-hash ブランチ）を追加し、PLDM 向けに可搬ビルドをサポート；NEMU ブランチは新チェックポイントモード（CHECKPOINT_HERE）とベクトル浮動小数点リダクションの新ロジックを探索；GEM5 はゴールデンメモリ書き込み順序の保持、SMT LR リプレイ、PerfCCT 診断トレースを推進。メインブランチ側は中国語リポジトリレポートツールのコミット 1 件のみ。

3.3 楽鑫：esp-vision に nano track 追跡と IPA 統計を追加、esp-sr はプリコンパイル済みライブラリを更新

日付：2026-10-10/11　情報源：esp-vision コミット記録（10-11）、esp-sr コミット記録（10-10）、esp-idf コミット記録（10-10）

乐鑫のマルチリポジトリ継続メンテナンス：esp-vision に nano track 目標追跡サポートとセンサー IPA 統計インターフェースを新規追加（10-11）；esp-sr はプリコンパイルライブラリを更新（10-10）；esp-idf は BLE コマンド IRAM 使用量削減、ESP32 TWAI ランダム受信データずれのエラッタ修正、PSRAM レート DFS と H4 ECO2 水晶依存などの修正をマージ（10-10）。楽鑫組織の調査期間内で 25 のリポジトリがプッシュされ、端側（RISC-V チップラインを含む）のメンテナンスペースは稠密である。

3.4 算能：zsbl が v3.2.1 をリリース、LLM-TPU が bge-reranker-v2-m3 と MinerU2.5-Pro に適応

日付：2026-10-10　情報源：zsbl コミット記録：v3.2.1（10-10）、LLM-TPU PR #179（10-10）、tpu-mlir コミット記録（10-10）

算能のマルチリポジトリメンテナンス：ゼロ段階ブート zsbl が v3.2.1 をリリース（SG2042 ロード後にコンソールへ入る調整を含む）；LLM-TPU が PR #179 をマージし、bge-reranker-v2-m3 リランカーと MinerU2.5-Pro ドキュメント解析モデルの互換適応を新規追加；tpu-mlir はドキュメントビルド OOM を修正し qwen_asr パッケージをクリーンアップ；libsophon、sophon_media、edk2-non-osi などが同期プッシュ（libsophon 側はブランチレベルのプッシュで、メインブランチには調査期間内のコミットなし）。

3.5 矽速：SLogic が v2.1.0 をリリース、Windows RAW_IO スループットを修正し回帰セルフチェックを追加

日付：2026-10-10　情報源：SLogic コミット記録：v2.1.0（10-10）

矽速ロジックアナライザソフトウェア SLogic が v2.1.0 をリリース：Windows プラットフォームの RAW_IO スループット問題を修正、SLogic32U3 回帰セルフチェックを追加、CHANGELOG を補完し、macOS ダークテーマ下での slogicview コンボボックスドロップダウン幅を修正；以前追加された sigrok-cli 転送プラグインも併せて取り込まれた。

進畳時空の spine-triton-tutorial はドキュメント内の spine_raw を全面的に smt_rvisa にリネームし、全文の編集を完了、チュートリアルとメインリポジトリの命名を整合させた。

4. 具身智能とロボティクス専章

4.1 進畳時空ロボティクス：IMU ライブラリが BMI270 カーネル IIO 読み取りを新規追加、モータライブラリが M8010-A ネイティブ UART を完善

日付：2026-10-11　情報源：peripherals-imu feat/bmi270-iio ブランチ（10-11）、peripherals-motor feat/m8010a-native-uart ブランチ（10-11）

spacemit-robotics 外設ライブラリの 2 本の機能ブランチが調査期間内に推進：peripherals-imu は BMI270 IMU のカーネル IIO 読み取りサポートを新規追加（以前から BMI270 SPI イベントドリブンと IWT603 UART ドライバあり）；peripherals-motor は M8010-A モータ向けにネイティブ UART トランザクション境界を厳格化（以前から M8010-A RS485 共有ライブラリドライバを追加済み）。ロボティクス外設スタックは引き続きカーネル態とイベントドリブンの方向へ収斂している。

5. まとめとトレンド観察

  • カーネル低レイヤは2本柱で並行推進：LPC26 以降、RVA23u64 profile ビットは既に8枚が riscv/for-next に入り（glibc は profile に従ってビルド・配布され、ユーザー空間で V 拡張を動的に無効化するインターフェースは廃止される予定）、カーネル自動ベクトル化実験では LZ4 で約15%級の効果が示され、「カーネル空間でベクトルを使う」という長年の禁忌が再評価されつつある。
  • ディストリビューション設定のアップグレード：RevyOS カーネルは 6.17.11 に同期し、K3／TH1520／SG2042 などのプラットフォームで Rust、PowerVR、NTSYNC などの機能を有効化；openRuyi は Go／OpenSSL を更新し docker-cli を分割、lookout の巡回能力を強化。
  • エッジ競争のナラティブが形成：36氪の長文と Qualcomm 対 Arm の法廷審理での議論は同一の判断を指し示す——RISC-V は組み込み／エッジにおいて既に「参加資格」を持ち、データセンターには依然として時間が必要；第26回中国国際工業博覧会 国芯展は本日（10-12）から上海で開催。
  • 端末側と国内チームの実装：Espressif（esp-vision トラッキングと IPA 統計）、算能（zsbl v3.2.1、LLM-TPU モデル適応）、矽速（SLogic v2.1.0）、進迭時空（ロボット周辺機器ライブラリ、ドキュメント用語の統一）がいずれも実質的なコミットを実施。
  • 要観察：Ubuntu 26.10（10-15 リリース）RISC-V デスクトップイメージの実測フィードバック；RVA23 シリーズ v9 コミットとカーネルベクトル化議論の行方；香山圧縮 ROB の今後の性能検証。
