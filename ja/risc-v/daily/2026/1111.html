今日の重点：車載 RISC-V はツールチェーンにバトンタッチ、HighTec と TASKING が同日に AURIX RC1 対応を発表（11-10）

インフィニオン AURIX RC1 が 11 月 4 日に発表され、11 月 9 日に RISC-V コアが MIPS IP 由来であることが確認された後、11 月 10 日は第 3 の段階であるツールチェーンに入った。欧州の車載ソフトウェアツールベンダー 2 社が同日にサポート声明を発表し、それはミュンヘンの electronica 2026 開幕初日（11 月 10 日から 13 日）にちょうど重なった。

HighTec EDV-Systeme の発表は具体的だ。RISC-V 向けの Embedded AI、Rust、C/C++ 開発プラットフォームが RC1 をサポート済みで、その手法は RC1 のデバイス関連コンパイルオプションを同一のマルチアーキテクチャコンパイラに集約し、インフィニオンと協力してパイプラインとコードサイズ向けの最適化を追加するというもの。この路線の独自性は言語カバレッジにある。安全・セキュリティ認証済みの C/C++ と Rust ツールチェーンを同時に提供し、RC1 向けに組み込み AI 開発プラットフォームを投入する計画だ。サポート範囲もこれに伴い AURIX から TRAVEO と PSOC、すなわちインフィニオンが従来の 2 製品ラインを統合して形成した MCU ファミリ全体へと拡大する。HighTec は同時に DRIVECORE RISC-V 仮想プロトタイプバンドルの参加者でもあり、このバンドルには Synopsys VDK、Lauterbach TRACE32、HighTec の RISC-V C/C++ プラットフォームとペリフェラルドライバが含まれ、FreeRTOS 実装と協調シミュレーション例も付属する。チップが届く前にソフトウェアが先に動く、これは車載プロジェクトの通常のリズムである。

TASKINGの方針は、ライフサイクル全体を1つのツールセットに収めることにある。コンパイルには VX-toolset、デバッグには winIDEA と BlueBox、検証には LDRA を接続し、ツールチェーンに Agentic AI を組み込む。スケジュールは明確だ。RC1 対応の VX-toolset for RISC-V は 2026 年 12 月に利用可能となり、ツールチェーン認証は 2027 年に計画されている。AI 部分は2か所に落とし込まれる。12 月版では TASKING のツールチェーン知識（ビルド、診断、map ファイルと LSL 分析、スタートアップコード）を MCP 経由で VS Code 環境に接続するが、認証済みのツール自体は変わらない。デバッグ側の winIDEA AI Kit は3つのユースケースで少なくとも 50% の作業量削減を既に示している。移行中のチームにとっての売りは「アーキテクチャを替えてもツールチェーンは替えない」ことだ。TriCore から移行するチームは既存の CI/CD と経験を維持でき、Arm から移行するチームは同じツールセットで両方のアーキテクチャをカバーできる。

3日分のニュースを串刺しにして見ると、車載 RISC-V の推進順序は IP、シリコン、ツールチェーン、認証であり、4つのステップそれぞれに明確な外部シグナルがある。11-09 は IP の出所（MIPS、格芯による受託製造）、11-04 は製品定義（最大 12 コア、40MB ストレージ、ASIL D、2027 年上期にサンプル出荷）、11-10 はツールチェーンの可用性（12 月にコンパイラ提供、2027 年に認証）だ。2社のツールベンダーが示した認証時期と Infineon のサンプル出荷時期が一致しており、このスケジュールが各社の言い分の食い違いではないことを物語っている。国内で車載 RISC-V に取り組むチームにとって、今回注目すべきはコンパイラベンダーが2社増えたことではなく、「認証スケジュール」が顧客からの質問の標準フォーマットになりつつあることだ。

1. オープンソースコミュニティとソフトウェアエコシステム

RevyOS カーネルが一度に6件を投入：K3、K1、DP1000、EIC7700 の4プラットフォーム設定をツリーに追加（11-10）

RevyOS の linux リポジトリ（revyos/7.3.y ブランチ）は調査期間の末尾に6件の設定コミットを一挙に投入した。SpacemiT K3 サポートの有効化、SpacemiT K1 サポートの有効化、UltraRISC DP1000 サポートの有効化、ESWIN EIC7700 サポートの有効化に加え、linuxboot 設定と CI のクロス／ネイティブビルドタスクが1件ずつ。6件のコミットは同一作者、同一タイムスタンプであり、段階的な開発ではなくプラットフォームマトリックスの一括収束に属する。

設定をツリーに入れる意義は、「起動できる」を「デフォルトでコンパイルできる」に変えることにある。この4つのプラットフォームは3社に分かれる。進迭時空の K1 と新世代の K3、超睿（UltraRISC）の DP1000、奕斯偉の EIC7700 であり、まさに現在国内の RISC-V 開発ボードと産業用制御ボードで最もよく使われる SoC をカバーしている。linuxboot 設定と CI のデュアルビルドが同時に入ったことは、このディストリビューションが「再現可能なビルド」へと補強を進めており、動作するマシンを1台保守するだけではないことを示している。

日付：2026-11-10　情報源：revyos/linux

openRuyi メインリポジトリがセキュリティ修正バッチへ移行：policycoreutils を 3.11 に更新、cups／lxc／libmtp は上流パッチをバックポート（11-10）

openRuyi メインリポジトリの調査期間内の作業重心は、バージョンアップからセキュリティへと移った。policycoreutils を 3.11 に更新し fixfiles の修正をバックポート、lxc、libmtp、cups の3パッケージはそれぞれ上流のセキュリティパッチをバックポート（コミットにはいずれも security-fixes マーク付き）、libssh を 0.12.2 に更新、llvm-snapshot は 20261109 スナップショットに追随した。

これは前日同リポジトリの20件の「通常のローリングアップグレード」と対照をなす。ある日は機能バージョン、ある日はセキュリティバックポートというのは、ローリングディストリビューションに典型的なリズムの切り替えだ。cups と lxc はデスクトップとコンテナという2つの常用経路に属し、libmtp はモバイルデバイスのマウントに影響する。これら3パッケージのバックポートは実際の利用者にとってバージョン番号の変化以上の意味を持つ。セキュリティ修正がメインラインに入らなければ、ディストリビューションは「本番利用可能」という説得力を持たない。

日付：2026-11-10　情報源：openRuyi-Project/openRuyi

NEMU が riscv64 の SIP 書き込みによるタイマー割り込みラッチを修正、AME は CRC32C で行列完了ハッシュを計算するよう変更（11-10）

香山のNEMUシミュレータは調査期間内に方向性の異なる2件のコミットをマージした。1件は正確性修正である。riscv64側でSIP（監督者レベル割り込みペンディングレジスタ）への書き込みがタイマー割り込みをラッチしてしまうことを阻止する（#1242）。割り込み仮想化パス上の細部の誤りに属する——SIPへの書き込みはソフトウェアトリガー割り込みの発生源と見なすべきではない。もう1件は性能最適化である。AME（行列拡張）がCRC32Cを用いて行列完了のハッシュを計算するよう変更し（#1280）、あわせて先の#1275によるhosttlb行列アクセス共有最適化と組み合わせた。

シミュレータでこれら2種類のコミットが同時に現れたことは、行列拡張のソフトウェアスタックが真剣に打磨されつつあることを示している。一方で特権状態のセマンティクスを修正し、もう一方で検証とキャッシュパスのオーバーヘッドを削減している。RISC-Vの行列／ベクトル拡張の評価を行うチームにとって、NEMUのAME実装は現在、完全なソフトウェアスタックを実行できる数少ないオープンソース参考実装の一つであり、こうしたコミットはベンチマークスコアよりも成熟度をよく示している。

日付：2026-11-10　情報源：OpenXiangShan/NEMU

2. 製品とエコシステムの動向

riscv100.top ランキングページが改版：完全なテーブルを「アーキテクチャカード＋総覧ランキング」に置換（11-10）

riscv100.topのランキングページは調査期間内に改版を完了した。従来、全成績を行ごとに列挙していたテーブルはページのソースコードに現れなくなり、「各アーキテクチャにつき1枚の首位カード＋Overall Ranking総覧リスト」という構造に変わった。カードはプラットフォーム、コンパイラ、Ratio/GHz、Run rank、Tests、Run dateを示し、総覧リストは各プラットフォームの最良の1行のみを保持する。クロスアーキテクチャのSPEC CPU2006を例にとると、カードはそれぞれAWS EC2 Graviton5（GCC 15.1.0、24.91）、香山KMHv3 RTL（XSCC 2.0、22.80、NEWマーク付き、記録日2026-10-17）、AMD Ryzen 9 9950X（GCC 15.1.0、17.72）に対応する。RISC-V側は総覧において別途、進畳K3 X100（XSCC 1.1、8.54）と倚天710（XSCC 1.1、17.69）を掲載している。ホームページのWhat’s Newは現在6件で、SpaceMiT K3 X100 XSCC 1.1 SPEC CPU2006、SpaceMiT K3 X100 Version Progress Now Available、Run Comparison Now Availableなどを含む。

改版による直接的な影響は、「過去の全成績」がページから直接取得できなくなったことであり、デイリーレポート側の従来のテーブル解析もこれに伴い機能しなくなった。本期はこれに基づいて新規追加やランク外れを判定しない——サイトは同一の改版の中でページ構造とスナップショットのベースラインを同時に更新しており、こうした変化は「成績の変動」と「表示の縮小」を区別できない。読者への実用的な提案は、具体的なスコアが必要な場合はカードと総覧から読み、過去のトレンドが必要な場合はサイトのVersion ProgressとRun Comparisonの2つのセクションに切り替えることである。

日付：2026-11-10　情報源：riscv100.top クロスアーキテクチャ SPEC CPU2006、riscv100.top ホームページ

ジェームズタウン財団が中国のRISC-V路線を評価：戦略が能力に先行（11-10）

米国のシンクタンク、ジェームズタウン財団は11月10日、中国のRISC-V推進状況を評価する記事を掲載した。著者はSunny Cheung。記事は検証可能な事実の手がかりをいくつか示している。進畳時空と香山チームは10月19日の第6回RISC-V中国サミットで46コアのサーバーチップV100を発表し、RISC-Vサーバー標準に完全準拠した初の汎用チップであると宣称した。9月に発表された「電子情報製造業『第十五次五カ年計画』」はRISC-Vの研究開発と産業化の推進、人工知能向けRISC-Vチップの発展を提起しており、これまで国家級の政策文書がこの命令セットを直接名指しすることは比較的少なかった。

文章の核心的判断は「戦略が能力に優先する」というものだ。拡張利用と国際組織への影響力は明確だが、性能は依然として専用チップに劣り、記事は中国のアナリストによる「ガラスの天井」への懸念を引用し、国家情報技術代替計画における RISC-V チップの代替比率は「無視できる」と述べている。こうした外部評価は対照として読む価値がある——国内でよく語られる「エコシステムはすでに完成した」を別の指標体系の下で検証するものであり、この二つの指標体系の間の差こそ、次の段階で国産 RISC-V が答えるべき問いである。

3. 国内チームの深掘り

香山昆明湖 V3 の五つのコミット：VBTB を taken-first 選択に変更、NewCSR のブレークポイントゲートによる再取得（11-10）

香山メインリポジトリ（kunminghu-v3 ブランチ）は調査期間内に五つの実質的なコミットをマージした：MBTB における VBTB の予測選択ロジックを taken-first に変更（#従来の動作は別の優先度体系だった）、CSR 書き込みがブレークポイントゲートを変更した際に NewCSR が再取得しない問題を修正（#6862）、リダイレクトクリーンアップ時に ROB の保留スロットリセットを保持、CBO invalidate イベントを cache line 粒度に整合（#6864）、そして codeowners のメンテナンス1件。同じ期間内に NEMU、difftest、XSCache もそれぞれコミットがあり、difftest 側は Verilator コンパイルオプション、gsim アサーション登録、FPGA 側 XDMA グループのドレインに集中している。

五つのうち最も問題の本質を説明しているのは VBTB の taken-first と CBO invalidate の整合である。前者は分岐予測器内部の優先度の取捨選択であり、フェッチ帯域の利用率に直接影響する。後者はキャッシュコヒーレンスプロトコルと検証モデルの整合に属し、間違っても即座に落ちるわけではないが、長時間の回帰テストで再現困難な偏差を生じさせる。香山の最近のコミットスタイルは「マイクロアーキテクチャのチューニング」と「検証基盤」を交互に推進するものであり、この期間には両方が同時に現れた。

日付：2026-11-10　情報源：OpenXiangShan/XiangShan、OpenXiangShan/difftest

進迭時空 llama.cpp：IME1 の稠密 Q4 パスを復元、SSM 畳み込み融合で入力を維持（11-10）

spacemit-com の llama.cpp fork（mtmd-backend ブランチ）は調査期間内に K3 バックエンドに直接関連する三つのコミットをマージした：IME1 の稠密 Q4 パスを復元（#60）、ssm_conv 融合時に concat 入力が早期解放されないことを保証（#58）、ゲート付き delta ネットワークを head size ごとにストリップマイニング（#59、前日に同名方向を収録済み、今回はマージによる着地）。さらに #61 で上流同期（sync/upstream-20261110）を統合し、サーバー側は上流の動画能力検出ロジックに切り替えた。

三つの路線はそれぞれ具体的な問題を指している：IME1 の稠密 Q4 は K3 上の量子化推論のメインパスであり、復元は以前のロールバックが撤回されたことを意味する。ssm_conv の入力維持は融合オペレータのライフサイクル管理に属し、この種のバグは特定のグラフ構造下でのみ露呈する。head size ごとの展開は RVV のベクトル幅を使い切るものである。上流同期と K3 専用最適化を並行して推進するのは、この fork が一貫して維持しているパターンであり——上流から離れず、ローカルバックエンドも放棄しない。

日付：2026-11-10　情報源：spacemit-com/llama.cpp

平頭哥 IPO の進展：香港「信報」が香港取引所へ秘密裏に申請済みと報道（11-10）

11 月 9 日の「平頭哥が 2027 年に香港 IPO を計画、20 億〜30 億ドルを調達」というニュースの続報として、香港「信報」は 11 月 10 日、平頭哥が香港取引所へ上場申請を秘密裏に提出済みとさらに報道した。アリババと平頭哥側は報道時点までコメントしていない。これまでに開示された情報には以下が含まれる：評価額レンジは 250 億〜620 億ドル；真武シリーズ AI チップ（PPU）の累計出荷は 47 万枚超、年換算売上高は 100 億元超、2026 年 6 月時点で 650 社超の企業顧客にサービス提供、外部顧客比率は 60% 超；真武 V900 は 2027 年第 1 四半期の量産を計画。

RISC-V との関係は明確にしておく必要がある：今回上場予定の主体は平頭哥であり、製品は真武 PPU（AI アクセラレータカード）と倚天（Arm サーバー CPU）であり、玄鉄 RISC-V プロセッサ IP は 2024 年に平頭哥から分社化され、達磨院に移管済みである。メディアは平頭哥の製品ラインを振り返る際に「玄鉄シリーズの累計出荷が 60 億個を突破」と併せて計上することがよくあるが、それは歴史的沿革の口径であり、今回の IPO 資産に RISC-V IP 事業が含まれると理解すべきではない。この点は「国産 RISC-V の資本化経路」を判断する上で参考価値があるが、RISC-V 産業自体の資金調達イベントを構成するものではない。

日付：2026-11-10　情報源：同花順財経による財聞報道の転載

矽速の二本柱：TangMega-138K が PCIe 例程を修正し Gen3 の結論を提示、MaixPy はパッケージングを修正（11-10）

矽速（Sipeed）は調査期間内に2つの製品ラインを同時に収束させた。TangMega-138K-example は文書と例程の修正を5件連続で出した：PCIe 例程内の重複した rstn と 0x808760 への無効な書き込みを削除し、同じ修正を Gen3（8G）プロジェクトにも適用し、ラズベリーパイ側の PCIe 説明を訂正して REFCLK の修正方法を記録し、NextTang Gen3 のテスト結果を補足し、さらに「Gen3 の長時間安定性テストは信頼できない、Gen2 の使用を推奨する」と「DRP リプレイは内蔵されていない」という2つの結論的説明を明記した。MaixPy 側ではイメージパッケージングの問題を修正し、リリース用の CMake バージョンを固定した。

2つの事柄は性質が異なるが、いずれも「明確に説明する」ことに属する：PCIe の Gen3 結論は能動的に期待値を下げ、ユーザーが宣伝文句に従って調達するのを避けるものだ。MaixPy のパッケージングとバージョン固定はリリース成果物を再現可能にするものだ。開発ボードを主要形態とする RISC-V エコシステムにとって、こうした収束作業の価値は新たなボードを1枚出すことよりも高いことが多い。

日付：2026-11-10　情報源：sipeed/TangMega-138K-example、sipeed/MaixPy

4. エンボディドインテリジェンスとロボティクス特章

進畳ロボティクススタック：Unitree G1 と humanoid_common が SONIC トラッキングとスケジューリングを整合（11-10）

spacemit-robotics は調査期間内に二足ヒューマノイドスタックに対して一貫性修正を行った：humanoid_unitree_g1 は G1 の SONIC トラッキング、動作プリセット、起動準備判定を修正し、humanoid_common は SONIC スケジューリングを同期整合させてトラッキング応答を維持し、control_whole_body はフィードバック位置リミットと指令境界を分離処理した。3件のコミットは作者が同一で時刻も近く、リポジトリ横断の協調修正に属する。

技術的な要点は「トラッキング」と「スケジューリング」が分けて表現されていることにある。従来の実装ではプランナの CPU スケジューリングとトラッキングループが結合されていた（11-04 の #14 で既に分離が始まっていた）が、今回のラウンドではさらに起動準備、動作プリセット、トラッキング誤差の判定を分離した。K3 上でヒューマノイド制御を動かすチームにとって、こうした変更の意義はリアルタイムループのジッタ発生源を特定できるようにすることにある——問題発生時にプランナのキューイングなのかトラッキング自体の規格外れなのかを判断できる。

日付：2026-11-10　情報源：humanoid_unitree_g1、 control_whole_body

新リポジトリ ros2_spacemit_vslam が初期コミット、進畳が SLAM 环节を補完（11-10）

spacemit-robotics はリポジトリ ros2_spacemit_vslam を新規作成し初期コミットを完了した。命名から見ると視覚 SLAM を ROS 2 ノードとしてカプセル化し、進畳プラットフォーム向けに提供するものだ。同組織には既に perception（推論ランタイムを las2 にパッケージング）、unitree-go2、humanoid シリーズ、四足移植があり、SLAM はそのロボティクスソフトウェアスタックにおいて従来欠けていた一环であった。

SLAM を補完したことで、進畳のロボティクススタックはソフトウェア面で知覚（perception）、定位地図構築（vslam）、全身制御（control_whole_body）、機体適配（unitree_g1／go2）の4層をカバーした。この組み合わせは「再現可能な機体参考実装を一式完成させる」という性格が強く、個々のアルゴリズムを逐次リリースするものではない——K3 をロボット本体に組み込みたいチームにとって、参考実装の完成度は単項指標よりも有用だ。

日付：2026-11-10　情報源：ros2_spacemit_vslam

5. 総括とトレンド観察

1. 車載規格の競争点は既にツールチェーンと認証時点に移っている。 AURIX RC1 の3日間における3ステップ——11-04 の製品定義、11-09 の IP 供給元、11-10 のツールチェーンサポート——は車載 RISC-V の推進順序を明確に示している：チップメーカーがプラットフォームを定義し、IP メーカーがコアを供給し、ツールメーカーがコンパイルとデバッグを提供し、最後に認証が来る。HighTec と TASKING が示した「12月にツール利用可能、2027年に認証」とインフィニオン（Infineon）の「2027年上期にサンプル出荷」は寸分違わず整合しており、このスケジュールが協調して組まれたことを示している。国内の車載チームが次に問われるのは、おそらく「RISC-V コアを持っているか」ではなく「ツールチェーンはいつ認証を通過するのか」である。

2. ディストリビューション側がこの日行ったのは「新機能」ではなく「デリバリー可能」にすることである。 RevyOS は K3、K1、DP1000、EIC7700 の 4 プラットフォーム構成を一括でツリーに投入し、linuxboot とデュアルビルド CI を補完した。openRuyi はセキュリティバックポート批次へ移行した。この 2 つの出来事は同じ問いに答えている。すなわち、このシステムは成果物として他者に納品できるのか、という問いである。構成のツリー投入は「他者がビルドできるか」を決め、セキュリティバックポートは「本番環境に投入できるか」を決める。それに比べ、新機能のリリースはこの日は不在であった。

3. 国内チームの作業は指標を引き上げることではなく、チェーンを補完することに集中している。 香山は分岐予測と検証のアライメントを変更し、進迭は llama.cpp 上で量子化メインパスを復旧させ、融合オペレータのライフサイクルを修正した。ロボティクス側は SONIC のスケジューリングとトラッキングを分離し、SLAM リポジトリを補充した。これらの変更に共通するのは「既存の能力を安定して再現可能にすること」であり、前日の芯来 NI1000 リリース（新 IP、新指標）とは対照的な 2 つのリズムの交替を成している。

4. ランキング系情報源の比較可能性は再確認が必要である。 riscv100.top の改版により、全成績がページから削除され、各アーキテクチャの首位と総覧リストのみが残された。日常的な追跡において、これは「スコア変化」という次元が当面連続観測できないことを意味する。本期の処理は、新規追加とランク落ちの判定を行わず、サイト構造が安定した後にベースラインを再構築するというものである。単一ランキングに依存して結論を出す表現には、改版期間中は口径の説明を一言加えるべきである。

5. オフショアの視点は「規模」ではなく「能力」で中国の RISC-V を評価し始めている。 ジェームズタウン財団の文章は政策とエコシステム推進の力度を認めつつ、性能差と代替シェアは「無視できる」と指摘している。こうした評価を全面的に受け入れる必要はないが、ひとつのことを示唆している。国内の語りが出荷量、サミット規模、標準適合性を主とする一方で、外部の観察者が見るのはシングルコア性能、ソフトウェア成熟度、実際の代替率である——2 つの指標体系の間の差こそが、次の段階で埋めるべき課題である。
