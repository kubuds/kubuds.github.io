1. オープンソースコミュニティとソフトウェアエコシステム

openRuyi 20 件：OpenJDK のパッケージ分割と alternatives への接続、Rust パッケージ 15 個を新規追加（11-24）

11 月 24 日、openRuyi メインリポジトリは調査期間内に 20 件のコミットを着地させた。最大のグループは OpenJDK である。openjdk-17、21、25 と latest の 4 つの spec を同時に変更し、パッケージを細分化して alternatives メカニズムに接続した。これにより java、javac などのコマンドは複数の JDK 間で切り替え可能になった。同バッチで spec フォーマットも統一した。

Rust 側では一度に 15 個のパッケージを追加した。crossterm 0.27、sysinfo 0.33、fancy-regex 0.16、mio 0.8 と bytesize 1 を含む。残りは yaml-rust 0.4、terminal-colorsaurus 1、terminal-trx 0.2 と dissimilar 1 である。最後の 3 項目は proc-macro-hack 0.5 と execute-command シリーズである。linux spec は別途整理し、重複する arch_suffix と余分な %{name} の用法を削除した。

関連リポジトリの kiwi-image は 6 件。イメージ定義に x86_64 ターゲットを新規追加し、パーティションは EFI+GPT のみを保持するよう変更し、RVA20 設定を追加した。ブランチプッシュではイメージビルドをトリガーしなくなった。

openRuyi ブログには同時期に OSPP プロジェクトの記事が公開され、記事は 11 月 12 日付と記されている。プロジェクトは genimage、lua-json、LMDB と LibTomCrypt の 4 コンポーネントの上流テストを復旧した。genimage は x86_64 と RISC-V で生成される UUID が一致しない。原因は random32() の呼び出しが関数引数内に書かれており、C が引数の評価順序を規定していないことにある。修正後は固定順序で値を取得し、上流に PR #345 を提出した。

日付：2026-11-24　情報源：https://github.com/openRuyi-Project/openRuyi 。

前日のデイリーレポートでは同リポジトリの EDK II ベースラインアップグレードと SG2042 の実行変数変更を既に記録している。今回の 2 件は同一ファームウェアラインの後続に属する。

日付：2026-11-24　情報源：https://github.com/openRuyi-Project/ruyifirmware/tree/ruyi 。

香山 GEM5 5 件：スカラ浮動小数点除算と平方根のパイプライン化を選択可能に（11-24）

GEM5 の xs-dev ブランチは調査期間内に 5 件。最新の 1 件 #1328 はスカラ浮動小数点除算と平方根に選択可能なパイプライン化を追加するもので、性能モデルの能力補完に属する。#1380 は KMH の SStride トレーニングが必ず TLB ヒットすることを要求し、誤ったアドレスでプリフェッチャをトレーニングすることを避ける。

残り 3 件はツールと観測側にある。#1361 は BPU と load-triple profiling をオンデマンド有効化に変更した。#1379 は性能 CI と solver workload の実行方法を統一した。#1383 は codeowner を更新した。

日付：2026-11-24　情報源：https://github.com/OpenXiangShan/GEM5/tree/xs-dev 。

wasmc：ESP32-C3 上で WebAssembly を RV32IM にコンパイル（11-24）

オープンソースプロジェクト wasmc が 11 月 24 日に Hacker News に登場した。WASM 1.0 モジュールを RV32IM ネイティブコードに変換し、コンパイラ自体がデバイス上で動作する。ターゲットプラットフォームは ESP32-C3 で、利用可能な RAM は約 400 KB である。

プロジェクト側が示したデータは、典型的なモジュールのコンパイルに数十ミリ秒かかり、数 KB のヒープを占有するというものだ。出力は WAMR 2.4.4 の AOT ファイル形式を採用し、WAMR の AOT runtime で直接ロードできる。これにより MCU 上で LLVM を持ち込まなくても WASM を実行できる。

日付：2026-11-24　情報源：https://news.ycombinator.com/item?id=50626718、https://github.com/llllluca/wasmc 。

蓋世汽車が車載 RISC-V の量産スケジュールと標準ロードマップを公開（11-24）

11 月 24 日、蓋世汽車は RISC-V Club セミナーの続報記事を 2 本公開した。会議自体は 11 月 19 日に開催され、既に以前のデイリーレポートに収録されている。今回新たに追加されたのは量産計画と標準の詳細である。

車載メーカーがタイムテーブルを示した。奇瑞執行副総裁の戚士龍氏は、奇瑞が初の量産間近のユーザーだと述べた。奇瑞は2027年、2029年、2030年に段階的にInfineonと共同で車載グレードのベースラインインターフェース仕様ホワイトペーパーを出力し、コンパイル、デバッグ、オペレーティングシステム、認証の各段階を貫通させ、年間200万台超の規模でデータをフィードバックする計画だ。零跑高級副総裁の舒春成氏は、現在の車載MCUは依然としてArmと独自アーキテクチャが主流だが、RISC-Vエコシステムに全面的に融合していくと述べた。小米汽車の劉佳熙氏は、openvelaプラットフォームがすでにRISC-Vサポートをオープンソース化し、IoT分野での量産製品が1000万個を超えたと述べた。

香山5コミット：DCache可視性、TopDownグループ化、Debug例外リダイレクト（11-24）

香山メインリポジトリのkunminghu-v3ブランチは調査期間内に5コミット。#7035はDCacheの単一メモリチャネル下でのクライアント可視性を修正し、すべてのclientが完全なデータを見られるようにした。#6567はTopDownCountersにL1/L2グループ化を追加し、性能帰因を階層的に見られるようにした。

3コミットは正確性向け。#7038はDebug Mode中にトリガーされた例外をリダイレクトに変更し、デバッグ状態で直接処理しないようにした。MBTBの1コミットはio.enable切り替え時に陳旧予測を無効化し、状態跨ぎの再利用を回避した。#6876は面積最適化に属し、Scのtage metaを再利用した。

配套リポジトリXSCacheは2コミット：1コミットはCBOAck用にDスロットを予約し、1コミットはOpenNCBサブモジュールをアップグレードした。difftestは2コミットとも性能向け：MMA書き戻しをcompact block単位のバッチコミットに変更し、FPGA側のローカルXDMA FIFO読み取りもバッチに変更した。

日付：2026-11-24　情報源：https://github.com/OpenXiangShan/XiangShan/tree/kunminghu-v3、https://github.com/OpenXiangShan/XSCache、https://github.com/OpenXiangShan/difftest 。

シリコン製 SPI2HDMI サンプル：CH32V003/004 と ESP32-S3 で HDMI を駆動（11-24）

矽速（Sipeed）は SPI2HDMI_demo リポジトリに4件のコミットを記録し、サンプルコードとドキュメントを追加した。モジュールは ILI9341 の SPI コマンドを HDMI 出力に変換し、MCU は既存の画面ドライバをそのまま使って解像度を切り替えられる。

サンプルは2種類のプラットフォームをカバーする。CH32V003 と CH32V004 上では Bad Apple、Conway’s Life、リアルタイムフラクタルを実行する。CH32V004 には8項目メニューのアーケードサンプルもあり、720p と TE 同期をサポートする。ESP32-S3 側では esp_lcd パネルドライバを提供し、SPI と QSPI をサポートし、retro-go の NES、Game Boy、Doom 移植を備える。

日付：2026-11-24　情報源：https://github.com/sipeed/SPI2HDMI_demo 。

5. まとめとトレンド観察

  • 製品化：インドの VIHAAN-I は点灯から筐体全体の協業へと進み、欧州 Openchip のアクセラレータは EU AI Factory の議題に入った。いずれも RISC-V の伝統的な主戦場ではなく、ネットワーク機器とデータセンターアクセラレーションを指し示している。
  • 車載規格：国内の議論は「使うべきか」から「いつ搭載するか」へ移った。奇瑞は2027年から2030年までの段階的計画を示し、標準側は Profile の定義を始めた。真の試金石は2027年のサンプルチップと設計確定である。
  • パッケージングと検証：openRuyi は OpenJDK パッケージを分割し、上流テストを復活させ、ruyifirmware は Setup インターフェースを補完した。こうした変更はリリースノートには現れないが、ディストリビューションが長期的に上流を追従できるかを左右する。
  • 性能モデル：香山 GEM5 は浮動小数点除算のパイプライン化と SStride プリフェッチ制約を補完し、XSCache と difftest はバッチコミットを行った。検証ツール自体が高速化している。

これらを合わせて見ると、当日は新チップの発表も新ベンチマークもなかった。検証可能な進展は2点に集中している。製品側はチップを筐体・ラックへと押し進め、エンジニアリング側はパッチをディストリビューションと検証ツールに取り込んでいる。メディアの熱は車載規格にあり、コードの着地点はパッケージングにある。
