今日の重点：Onsemi が 1450 万ドルで Codasip の低端 RISC-V 事業を引き継ぐ

日付：2026-10-26　出典：Jon Peddie Research：Onsemi picks up Codasip’s low-end RISC-V business for $14.5 million（10-26）、Codasip：戦略調整と事業売却公告（04-08）

アンソニー（Onsemi）は Codasip の低端 RISC-V プロセッサ事業の買収を完了した。取引金額はチェコのビジネスメディア e15 の報道によると 1450 万ドルで、うち約 90% が既に支払われている。

  • 取引範囲：Codasip の約 260 名の従業員のうち 27 人のみに関わり、別途 Studio プロセッサ設計ツールのライセンスが付属する。Codasip は Studio の所有権と、公的資金支援を受けたプロジェクトの大部分を保持する。
  • 前因：Codasip は 2026-04-08 に戦略調整を発表し、低端 RISC-V プロセッサ設計事業を分離し、CHERI ベースの「ネットワークレジリエンス」セキュリティアーキテクチャへ転換することを明らかにした。当時の公告では買い手が米国上場半導体企業であるとだけ述べられ、名指しはされなかった。
  • チェコ国内の疑問：Codasip は過去に EU とチェコ国家レベルの研究助成を受けており、今年 7 月には 1.19 億ユーロ超の補助金と株式支援（大部分は未着金）を公開していたため、1450 万ドルの成約価格が議論を呼んだ。会社側の説明は「合理的な再編」であり、安売りではないというもの。
  • 競争格局：CHERI 方向にはすでに直接の競合 SCI Semiconductor が存在し、2026 年 9 月に 500 万ポンド（約 667 万ドル）の資金調達を完了し、さらに 770 万ポンドの政府契約があると述べている。Codasip CEO の Ron Black は CHERI 連盟に対し、国防・重要インフラ顧客のセキュリティ需要は汎用コアライセンスよりも強いと述べた。
  • 買い手の論理：Onsemi が獲得した低端 RISC-V 技術とチームは、その自動車・産業半導体事業に直接貢献できる——これまでの買収・ライセンスによる技術スタック構築の手法と一致する。

Jon Peddie Research の判断は記録に値する：基礎プロセッサコアは差別化と収益化が難しくなりつつある。顧客の前にはますます多くの商用・オープンソース代替が並んでいる。RISC-V の次の段階はより多くの成熟した半導体企業によって形作られ、価値は命令セットそのものから差別化製品とシステム統合へと移っていく。

1. オープンソースコミュニティとソフトウェアエコシステム

1.1 香山：35 件の修正を一括回収、TLB need_gpa とベクター例外が主軸に

日付：2026-10-26　情報源：XiangShan コミット記録（10-26、kunminghu-v3）

香山メインリポジトリの昆明湖 V3 ブランチは、調査期間内に 35 件のコミットをマージした。全コミットのタイムスタンプは 10-26 16:32 である一方、元の著者日付は 2026-02-04 から 2026-09-17 にまたがる——典型的な長期ブランチの一括回収であり、当日の新規開発ではない。

  • TLB／MMU グループ：need_gpa 関連の 4 件——need_gpa の robidx にマスクを追加して X 状態を回避（#6233）、非末端ポートの need_gpa クリア漏れを修正（#6251）、翻訳段階に応じた need_gpa レスポンスのマッチング（#6285）、さらにタイムアウトクリア機構を新設。ほかに TLB が needGpa によりフリーズする歴史的修正（#5610）も併せて回収。
  • ベクターとメモリアクセス：vlsu がベクター例外の guest physical address を XLEN に拡張（#6432）。Rob 側のベクター load/store の flushpipe に遅延が必要（#6244）。
  • 仮想化と特権：HLVHLVXHSV の PMP チェックを SPVP モードに変更（#6250）、RVH 下の暗黙的 G ステージ読み取りで MXR を無視（#6099）、HFENCE.GVMA 時に VS ステージ PageCache をフラッシュ（#6082）、HLVX の最終物理実行権限チェック（#6017）。
  • リセットと X 状態の治理：mtvec リセット値（#5862、#5889）、MemBlock／L2Top のリセット値欠落による X 状態（#5838）、LoadQueueRAR が RegEnable で X を回避（#5986）、CPU クロックゲーティングをプリスキャンリセットに変更——このグループがバッチの 3 分の 1 を占めた。
  • 新機能と小項目：NewCSR で PMM と CBIE の CSR 書き込みを有効化（#6269）。Debug で CBO 系命令に LT／GE トリガーマッチングを追加（#6447）。hartIDDmodeWidth のパラメータ化（#5627）。

35 件をテーマ別に広げると、これが「収束」を目標とした合流であることが見えてくる。X 状態、リセット値、need_gpa タイムアウトといった問題は機能デモには影響せず、長時間実行・マルチコア・仮想化プレッシャー下でのみ露呈する、テープアウト前に必ず清算すべき項目である。著者日付が最も早いもので 2 月に遡ることは、一部の修正がブランチ内で 7 か月間眠ってからメインラインに入ったことを意味する。

1.2 NEMU：AME 行列拡張のイベントエンコーディングとホスト FMA 例外フラグの修正

日付：2026-10-26　情報源：NEMU コミット記録（10-26）、NEMU リリース記録

参照モデル NEMU は調査期間内に 3 件のコミットがあり、2 件が AME（行列拡張）に関するもの、1 件が設定レイヤのリファクタリングである。

  • AME セマンティクス修正：fix(ame): encode MMA event types from mcfg semantics（#1269）——MMA イベントの型はこれまで固定の列挙型でエンコードされていたが、mcfg レジスタのセマンティクスに従ってデコードするよう変更され、マトリックス設定が変化した際にイベント分類が正しく行われるようになった。
  • 浮動小数点例外の忠実性：fix(ame): preserve host FMA exception flags（#1268）——AME パスはホストの FMA 命令でシミュレートされるため、ホストの浮動小数点例外フラグをそのままゲストに返す必要があり、そうでなければ差分比較で例外側の不一致を見逃してしまう。
  • 設定層のリファクタリング：refactor(config): reduce duplication with shared config layers（#1259）、重複する設定項目を共有層として抽出。
  • 背景：10-23、10-24 に v2026.10.r8、v2026.10.r9 の 2 つのタグが連続してリリースされたばかりであり、今回の修正はタグ後の継続的な打磨に属する。NEMU の直近 1 週間の変更の重心は、「機能追加」から「差分比較の信頼性向上」へと移っている。

参照モデルの価値は「DUT よりも少なく間違える」ことにある。ホストの浮動小数点例外フラグといった細部を補完したことは、香山の検証が「数値は同じだが例外フラグが異なる」ケースを区別する必要のある段階まで進んだことを示している。

1.3 difftest が BOOM サポートを実装、GEM5 にデコード融合圧縮を追加

日付：2026-10-26　情報源：difftest コミット記録（10-26）、GEM5 コミット記録（10-26）

差分検証フレームワークと GEM5 ブランチに、それぞれ方向性の明確なコミットが 1 件ずつある。

  • difftest が BOOM に接続：feat(difftest): add BOOM DiffTest support（#998）——カリフォルニア大学バークレー校の BOOM アウトオブオーダーコアを同じ比較フレームワークに接続。注目すべきは、10-23 のデイリーレポートで #995 が「BOOM の DiffTest 接続をドキュメントに書くだけ」であったと記録されたばかりであり、4 日後にコードが実装されたことである。
  • ビルド互換性：同じバッチの #1003 は C++11 ビルド互換性を維持し、新コードによるツールチェーンの敷居の上昇を避けている。
  • GEM5 デコード融合：cpu-o3: Add optional decode fusion compaction（#1184）——アウトオブオーダーモデルにオプションのデコード融合圧縮を追加し、フロントエンドが融合可能な命令ペアを 1 つのマイクロオペレーションに圧縮できるようにして、実際のフロントエンド動作に近づけた。

difftest が「香山のみを検証」から「他者のコアを検証」へと進んだ意義はプロジェクト自体を超えている。NEMU と BOOM を同時に比較できるフレームワークであって初めて、外部チームが公共の検証インフラとして利用できる可能性がある。GEM5 側のデコード融合追加は、性能モデルの楽観度をハードウェアフロントエンドの実際の手法に整合させるものである——シミュレーションとシリコンの口径差は、しばしばこのようなオプション項目に潜んでいる。

1.5 オープンソース EDA が自研 RV32I コアを GF180 テープアウトへ押し上げ：LibreLane 78 工程の全フロー

日付：2026-10-26（会員公式サイトの巡回により検出、イベント 11-11）　情報源：RISC-V 協会（日本）：RISC-V Day Tokyo 2026 Autumn ロジックデザイントラック議題、RISC-V 協会（日本）トップページ

RISC-V 協会（日本）は10月に RISC-V Day Tokyo 2026 Autumn（11-11、東京大学本郷キャンパス）の議題詳細を掲出し、その中の30分の講演が純オープンソースツールチェーンでテープアウトを完了する全経路を公開した。

  • 対象と経路：講演者である黒川能毅氏（JASA ハードウェア委員会 RISC-V WG）は LibreLane 3.1.0.dev2 を用いて自研の RV32I 互換コア SWC1 を GF180 プロセスへと押し進めた。フローは Verilator lint、Yosys 論理合成、OpenROAD の配置／CTS／配線、9つの signoff STA コーナー、Magic と KLayout の二重 DRC、netgen LVS をカバーし、計 78 工程に及ぶ。
  • DFT は今回の新規追加：論理合成後にスキャン FF 置換とスキャンチェーン作成の2工程を挿入（GF180 では 5V ライブラリのみがスキャンセルを備える）。オープンソース ATPG Atalanta を用いて約2分で 14,148 件のテストパターンを生成し、故障カバレッジは 97%。スキャンチェーン挿入後、周波数は 50MHz から 19MHz に低下したが、スキャンチェーン本体は 200MHz 以上で動作可能である。
  • 躓き記録：公開された 5V SRAM テンプレートは README 通りで通るが、自分のコアに換えると繰り返し失敗した。最終的に 5V セルで 3.3V コアを構成していたことが判明し、3.3V セルに切り替えたところ配置が完了し、STA は 50MHz の見込みを示した。
  • 環境：Windows 11 の WSL2（Ubuntu 24.04）に Nix を加え、フローのデバッグと STA レポートの確認には Claude Code（Pro プラン）を使用。SWC1 はすでに 2026-03 に Tiny Tapeout（IHP 130nm）でテープアウトを通過し、チップが輸送中である間は FPGA 上で μT-Kernel と lwIP を動作させている。
  • 同枠の次の講演：12:40–13:10 は圓山宗智氏による「AI-Designed RISC-V: From Claude Code to Linux Boot」。

この記事の技術的なポイントは「オープンソースツールでテープアウトする」という結論——Tiny Tapeout がすでに実現可能であることを証明している——にあるのではなく、DFT をオープンソースフローに組み込むことにある。スキャンチェーンと ATPG は長らく商用 EDA の領域だったが、個人愛好家が WSL2 上で 97% の故障検出率を達成したことは、オープンソースフローの弱点が「テープアウトできるかどうか」から「テスト可能かどうか」へと移りつつあることを示している。国内で教育用チップや MPW に取り組むチームにとって、これはそのまま照合できる工程チェックリストだ。

2. 製品とエコシステムの動向

2.1 SiFive、RISC-V を AI アクセラレータの制御レイヤとして位置づけ

日付：2026-10-26　情報源：Jon Peddie Research：SiFive makes the case for RISC-V as the control layer for custom AI accelerators（10-26）、SiFive ブログ：Orchestrating Custom Accelerators with Intelligent Control Units（10-16）

SiFive は Intelligence シリーズの RISC-V プロセッサを「アクセラレータ制御ユニット」（ACU）として充当し、ホストと自社開発アクセラレータの間にプログラマブルな制御レイヤを置くことを提唱した。Jon Peddie Research は 10-26 にこの構想について一篇の分析を掲載した。

  • 課題の提示：ハードワイヤードなステートマシンはアルゴリズムが変わると変更しにくい。共有バスはボトルネックになりやすい。下位層のオーケストレーションをホスト CPU に任せると演算能力を食い、遅延が増える。
  • ソリューション：スカラーとベクトル機能を備えた RISC-V コアが、データの準備と転送、アクセラレータ操作のディスパッチ、さらには活性化関数やデータフォーマット変換といった付属的な計算を担い、SSCI や VCIX などのコプロセッサインターフェースを介してアクセラレータに直接接続する。制御ロジックの変更はソフトウェア／ファームウェア側で行い、固定機能ハードウェアには手を加えない。
  • モデルごとの役割分担：X100 は制御集約型・低遅延・小面積向け。X200／X300 はより大きなベクトル帯域幅と演算能力を提供する。
  • 導入実績：Google のデータセンターではすでに X200 を AI 計算ホストとして採用。また X100 は、名前非公開の米国トップクラス半導体企業一社に産業用エッジ AI 向けとしてライセンスされている。
  • 評論の論調：JPR はこれを「価値が ISA からシステム統合へ移りつつある」ことの証左と見る——RISC-V は Arm や x86 に取って代わってメインプロセッサになる必要はなく、制御プレーンに入り込むことでも相応のポジションを獲得できる。

この話題と本日の重点にある買収案件は同じコインの裏表だ。汎用コアのライセンスは価値を下げる一方で、「コアを他者のシステムアーキテクチャに組み込む」ことは価値を上げている。ACU という呼称が成り立つのは、AI アクセラレータの形態がますます細分化され、どの企業も形態ごとにハードウェアのステートマシンを変更したくはないからだ。

2.2 MIPS の RISC-V フルスタック転換：Acies／Actus／Aegis の三プラットフォームと S8200 コア

日付：2026-10-26　情報源：電子工程専輯：從處理器 IP 到物理 AI 平台——MIPS 的 RISC-V 全棧轉型（10-26）、NeoTeo：MIPS’s RISC-V platforms: what Acies, Actus and Aegis do（10-26）

自社命令セットを手放した MIPS は、GlobalFoundries による買収と Synopsys の ARC プロセッサ IP の統合を経て、すでに自らを「RISC-V ベースで、車載エレクトロニクス／エッジ AI／高性能ネットワーク向けの IP とフルスタックソリューションを提供する企業」と再定義している。2026 年 9 月に発表された三つのプラットフォームが、今週、中英文のメディアで集中的に分析された。

  • Acies-1（推論ネイティブ）：Atlas S8200 をベースに、RVA23、RVV ベクトル拡張と VME をサポートし、llama.cpp、Qwen などの大規模モデルや視覚 Transformer、VLA モデルを実行可能。ソフトウェア側は Atlas SDK と IREE ベースの MLIR を採用し、TensorFlow／PyTorch／ONNX と互換。ハードウェア形態は統合しやすい M.2 PCIe で、ロボット、自動化設備、エッジインテリジェントエージェント向け。
  • Actus-1（イベントネイティブ）：Atlas M8500 をベースに、リアルタイムマルチスレッドアーキテクチャで FoC 加速をサポートし、VPX ベクトルコプロセッサを統合。シングルボードコンピュータ形態で提供し、モーション制御、センサーフュージョン、予知保全向けで、ISO 26262 と ISO 21434 に準拠。
  • Aegis-1（セキュリティネイティブ）：ミッションクリティカルなフィジカル AI システム向けで、RISC-V Android と Linux での開発をサポートし、データセンター外でエージェント負荷を実行可能。同様に ISO 26262／21434 に基づいて設計され、高安全度システムの認証サイクル短縮を目標とする。
  • S8200 コア：スカラー、ベクトル、マトリクスエンジンを統合し、公式によるとエネルギー効率は現行製品比 4 倍の TOPS/W。主要顧客へサンプル出荷済みで、初回シリコンリファレンスプラットフォームは 2027 年に登場予定。量産済みの NPX5／NPX6 専用 NPU と並行して存在する。
  • 顧客基盤：MIPS は、世界上位 12 の自動車メーカーのうち 9 社を顧客に持ち、Mobileye、Infineon がいずれも重要な顧客であると述べている。

MIPS の道筋は一つのことを示している。RISC-V 時代において、「歴史的負債を抱える IP 企業」に機会がないわけではない——旧 ISA を捨て、ツールチェーンと顧客関係を残し、「ワークロードネイティブ」でプラットフォーム階層を作り直す。Acies が VLA とロボットを直接名指ししたことは、今週 2 社目となる、RISC-V の着地点をフィジカル AI に置く国際 IP ベンダーである。

2.3 Adafruit Metro ESP32-P4 Hydra：UNO 形態のデュアル RISC-V コア開発ボード

日付：2026-10-26　情報源：CNX Software：Adafruit Metro ESP32-P4 Hydra（10-26）

Adafruit は Metro ESP32-P4 Hydra を発表した。Espressif の ESP32-P4 を Arduino UNO 外形にし、さらに ESP32-C6 を追加して無線を補完する。

  • メインコントローラ：ESP32-P4（v1）、デュアルコア 32 ビット RISC-V 高性能コア最大 360MHz（AI 命令拡張と単精度 FPU 付き）、加えて最大 40MHz の低消費電力 RISC-V コア。16MB PSRAM、16MB QSPI NOR。2D ピクセル処理アクセラレータと H.264／JPEG コーデック。
  • 無線：ESP32-C6 モジュールを SDIO 経由で接続し、Wi-Fi 6、Bluetooth LE 5.3、802.15.4（Thread／Zigbee、一部ファームウェアは自行統合が必要）を提供。
  • インターフェース：Raspberry Pi 互換の 2-lane MIPI DSI と CSI（22-pin、0.5mm ピッチ）、USB 2.0 高速 OTG ホストポート（480Mbps）、microSD、UNO ピンヘッダと独立 SPI ピンヘッダ、STEMMA QT、LiPo 充電。
  • 位置づけ：HMI、カメラ、IoT プロトタイプ。TinyUF2 によるドラッグ＆ドロップ式ファームウェア更新をサポート。

ESP32-P4 のエコシステムはモジュールから「標準外形 + 完全インターフェース」の完成品開発ボードへと移行しつつある。端側 HMI や視覚プロトタイプに取り組むチームにとって、UNO 外形は既存の拡張ボード在庫をそのまま再利用できることを意味する——こうしたエンジニアリング上の利便性は、数十メガヘルツの差よりも選定を後押しすることが多い。

3.1 算能：SG2044 ファームウェアに署名鍵、パッケージングツール、全プラットフォーム CI を追加

国産高性能 RISC-V サーバーの弱点は長らくコアではなく、「ファームウェアを顧客が安全に書き込めるか」にあった。署名鍵、パッケージングツール、独立ビルド環境、全プラットフォーム CI のこの四つが揃って初めて、ファームウェアは「研究開発でビルドできる」段階から「生産ラインで出荷できる」段階へと進む。この一歩に発表会はないが、次のロットの完成機が出荷できるかどうかを左右する。

4. エンボディドインテリジェンスとロボティクス特集章

4.1 進迭時空ロボティクススタックの補完：宇樹 Go2 が K3 上で動作、ヒューマノイド側は音声対話と画像伝送を接続

日付：2026-10-26　情報源：GitHub：spacemit-robotics/unitree-go2、 humanoid_linglong、 humanoid_common、 omni-agent、 realtime-link

4 本のラインを合わせると、「自社機種が動く」（霊龍）から「他社機種でも動く」（宇樹 Go2）へ拡張し、さらに音声インタラクションと映像リターンを補完したことになる。エンドサイドのロボティクスプラットフォームを手がけるベンダーにとって、複製可能な機種適応は単機デモよりも価値が高い。Go2 のような既存の四足ロボティクスは数が多く、SDK も比較的オープンであるため、これを K3 の対外的なサンプルとして使うことは、ヒューマノイドをもう一版調整するよりもプラットフォーム化能力を示せる。抑制すべきは、これらのコミットがいずれもリポジトリ内のコードとドキュメントであり、サードパーティによる実測や量産落地のデータが見られない点である。

5. 総括とトレンド観察

  • IP層の評価分化はすでに成約価格に反映されている：Codasipの低価格帯RISC-V事業は1450万ドル・27人規模で売却され、同じ時期にSiFiveは「アクセラレータ制御ユニット」を販売し、MIPSは「ワークロードネイティブ」プラットフォームを進めている。3社が同じ週に同じ結論に対する異なる答えを示した——汎用コアはもはや価値の中心ではなく、顧客のシステムアーキテクチャにどれだけ組み込めるかが鍵である。
  • 国内チームが補っているのはエンジニアリング化の最後の1マイル：算能のファームウェア署名とパッケージング、進迭のTEEドキュメント体系、芯来の拡張とトレーシングのドキュメント。この3件はいずれも発表会には登場しないが、「量産納品が可能かどうか」の前提条件である。この層をしっかり作り込むことは、さらに一版パラメータ表を出すよりも意義がある。
  • オープンソースコアは収束期に入った：香山の35件の修正が一括回収され、著者日付は2月から9月にまたがり、主題はX状態、リセット値、TLBのneed_gpaに集中している。あわせてNEMUが浮動小数点例外フラグを補い、GEM5がデコード融合を追加しており、検証側の動きが機能側より密である。参照モデルが「DUTより誤りが少ない」ことが明示的な目標になりつつある。
  • ディストリビューションの作業量はセキュリティ債で埋め尽くされている：openRuyiの46件のうち、[security-fixes]付きのクラウドネイティブコンポーネント更新とSequoia PGPへの一括移行が主体である。RISC-Vサーバーが実際の業務を担うには、まず署名、鍵、ミドルウェアのCVEといった「非アーキテクチャ問題」を片付ける必要がある。
  • ロボットスタックはデモから再現可能へ移行：進迭時空は宇樹Go2をK3に載せ、音声と映像伝送も补齐した。路線は「自社ヒューマノイドが動く」から「サードパーティ機種に適応できる」へと転換している。こうした作業はプラットフォームに対する検証として、パラメータよりも説得力がある。
  • 限界説明：OnsemiによるCodasip買収の価格、人数、支払い比率はチェコメディアe15の報道とJon Peddie Researchの転述に基づくもので、両社とも取引条件を公表していない。Codasipの公的助成データは同社自身の説明による。SiFiveのGoogle導入とX100ライセンス顧客情報はSiFiveのブログ記事とJPRの転述に基づくもので、顧客の確認は得ていない。MIPSのS8200電力効率倍数、2027年のシリコンリファレンスプラットフォーム時期、「上位12社の自動車メーカーのうち9社」はいずれも会社側の説明である。香山の35件、openRuyiの46件はGitHubのコミットページを逐頁照合して得たもので、著者日付とコミット日付の分離は一括回収の特徴であり、具体的な動機はプロジェクトの告知に見当たらない。算能、進迭時空、芯来のコミット内容はコミットタイトルとREADMEに基づく判断であり、パッチを逐条照合したものではない。LibreLaneの節の工程数、ATPGパターン数、カバレッジは講演概要によるもので、イベントは未開催であり、データは現場での確認を要する。会員公式サイトの巡回で検出された変化は大半が大学・機関のトップページの定例更新であり、RISC-V協会（日本）の会議アジェンダのみが実質的な情報を構成する。なお、中科通量のCNCC 2026（10-21から24、成都）での展示報道は同一製品（SmarCo AIワークステーション 12コアRISC-V／250 TOPS INT8／128GB統合メモリ）の再展示であり、仕様は10-20デイリーレポートで既に収録済みのため、本期では重複しない。睿芯高光D35の「12nmでNVIDIA 7nmを超える」報道は9-23の内容の再流通であり、同様に重複しない。
