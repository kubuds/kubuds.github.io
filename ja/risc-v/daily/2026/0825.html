一、开源社区与软件生态

1.1 CPython 官方支持 RISC-V：成为官方 tier 3 平台（08-25）

日期：2026-08-25（博客发布同期；HN 收录 08-24 20:12 UTC = 08-25 04:12 北京）　来源：blog.python.org、HN

CPython 正式宣布 RISC-V 成为官方支持平台，按 PEP 11 列入 tier 3。支撑路径：RISE Project 提供多台真实 RISC-V 硬件作为 buildbot 测试与架构问题调试环境（Ludovic Henry、Furkan Onder、Emma Smith 等社区贡献者），Sovereign Tech Agency 奖学金资助了本轮架构支持工作。下一步计划：借 RISE RISC-V Runners 将 RISC-V 直接接入 CPython 官方 CI（比 buildbot 更快反馈）、长期推动升级 tier 2 并做架构特定性能优化。意义：Python 是 AI/机器人软件栈的骨干语言，官方 tier 3 支持为 RISC-V 端侧与服务器场景的软件可用性补齐关键一环（配 2.1 的服务器进展）。

1.2 Linux 7.3 新增多款 RISC-V 扩展支持（08-24）

日期：2026-08-24（Phoronix 10:12 UTC = 18:12 北京）　来源：Phoronix

开发中的 Linux 7.3 合入多款较新 RISC-V ISA 扩展的发现与枚举支持：间接 CSR 访问（Smcsrind/Sscsrind）、计数器特权过滤（Smcntrpmf）、S 态计数器配置（Ssccfg）、计数器委派（Smcdeleg，覆盖所有特权级）、内存原子性/一致性类（Zicclsm 非对齐访存、Ziccamoa 原子操作、Ziccif 指令取指原子性、Ziccrse LR/SC 前向进度、Za64rs 保留集）、QoS 标识（Ssqosid，内存/缓存带宽监控）。另有 CFI Shadow Stack 处理改进、QoS 标签上下文切换、UEFI Runtime 服务用于重启/关机等。这批扩展以服务器与性能监控导向为主，与 RVA23 服务器平台推进（见 2.1）在特性上直接呼应。

1.3 Hot Chips 2026：NVIDIA 详解 CUDA 移植 RISC-V 的技术要求（08-24）

日期：2026-08-24（Chips and Cheese 发布；HN 68 分、9 评论）　来源：Chips and Cheese、HN

Hot Chips 2026 上 NVIDIA 演讲介绍将 CUDA 支持扩展到 RISC-V：要求 RVA23 profile 与 RISC-V server SoC / server platform 规范（含 RAS、专用安全处理器等基线特性）；额外要求 PCIe 一致性（否则 DMA 与 CPU 缓存间需软件显式失效，CUDA 栈难以处理）、设备间 P2P PCIe、向量扩展谓词支持等，避免”最低公分母”导致无法用性能增强指令；ACPI 问题此前阻碍移植，已由 2025 年 UEFI 论坛的 RISC-V ACPI 支持与去年批准的 BRS（Boot and Runtime Services）规范解决。韩媒《每日经济》（韩国）同期报道 NVIDIA 计划将 AI 服务器 CPU 支持从 Arm/x86 扩至 RISC-V。结合 SiFive 确认 CUDA 已在其 BigSky 平台实际运行（见 2.1），”CUDA 上 RISC-V”从 2025 年表态进入技术要求落地阶段。

1.4 RISC-V 指令集手册进入 ISO/IEC DIS 26791-1 国际标准草案阶段（08-24）

日期：2026-08-24（HN 12:54 UTC = 20:54 北京）　来源：HN、iso.org/standard/94578

RISC-V 指令集手册以 ISO/IEC DIS 26791-1 编号进入国际标准草案（DIS）阶段——ISO/IEC JTC 1 标准流程中 DIS 面向成员国投票，是正式国际标准化的关键节点。作为开放 ISA 走向 ISO 标准的标志性动作，与 RISC-V International 在 JTC 1 的标准化推进一致。注：ISO 官网页面反爬无法直接抓取正文，技术范围以官网与 DIS 文本为准。

二、产品与生态动态

2.1 SiFive BigSky SF-2U870：全球首款机架式 2U RISC-V 企业服务器发布（08-24）

日期：2026-08-24（SiFive 新闻稿；HotHardware 12:23 EDT = 08-25 00:23 北京）　来源：SiFive 新闻稿、HotHardware、HPCwire

SiFive 在 Hot Chips 2026 同期发布 BigSky SF-2U870 数据中心开发平台，宣称全球首台企业级、可机架部署的 2U RISC-V 服务器：32 核 P870-D @2GHz、256GB DDR5-5600、3.84TB U.2 NVMe、10/25Gbps OCP 3.0 网络、64 条 PCIe Gen5 扩展（可容纳双宽 GPU 与专用加速器）、RVA23 合规；开箱支持 Ubuntu 26.04 LTS 与 RHEL 10；面向超大规模云厂商、芯片厂商与软件商，用于企业软件移植、负载调优与自研芯片流片前验证。已限量现货发售（官方称”需求超供给”，CEO Patrick Little：”RISC-V 进入数据中心不再是遥远愿景”）。关键细节：SiFive 与 NVIDIA 合作移植 CUDA 并计划把 NVLink Fusion 集成进未来平台，CUDA 已实际运行于 BigSky，作为 NVIDIA GPU 上现代 LLM 工作负载的头节点——RISC-V 硬件首次具备该能力。

2.2 IAR 与东软睿驰达成战略合作：补齐 RISC-V 车规工具链（08-24/25 报道）

日期：2026-08-24/25 报道（EET-China 08-25 00:17 北京；双方 08-20 于上海签约）　来源：BigGo Finance、EET-China（电子工程专辑）

嵌入式工具链厂商 IAR 与 东软睿驰（Neusoft Reach） 签署战略合作：聚焦 NeuSAR OS 与 IAR 开发工具的深度集成，面向国内开发场景提供一体化软件与工具链方案，推动 AUTOSAR 软件生态与 RISC-V 车规芯片的融合；双方将共建覆盖”芯片—基础软件—应用开发”的完整工具链，弥合 RISC-V 车规级开发的工具链缺口，加速其在汽车行业的规模化部署。注：签约 08-20、报道 08-24/25 进入本窗口，系首次收录；东软睿驰为国产车规基础软件 NeuSAR 的主要厂商，IAR 此前已支持 SiFive 车规 E7A/S7A 核。

2.3 Andes D23-SE 获 ISO 26262 ASIL-B/ASIL-D 功能安全认证（08-24 报道）

日期：2026-08-24 报道（New Electronics 18:42 北京；原厂公告 08-18）　来源：New Electronics、andestech.com

AndesCore D23-SE 处理器获得 ISO 26262 ASIL-B 与 ASIL-D 双等级功能安全认证（开发流程符合第 2/4/5/7/8 部分）。D23-SE 为三级流水线、部分双发射的能效向安全核，覆盖防抱死制动、胎压监测、安全气囊、电机驱动控制等 ECU/DCU 场景；认证使其与 N25F-SE/D25F-SE/D45-SE 构成 Andes 完整的车规安全核组合。注：原厂公告 08-18（窗口外），本窗口为 New Electronics 报道收录，系首次收录。

2.4 LilyGo T-Display K230 Kit：Tech Times 报道现行 Ubuntu 无法运行（08-24/25）

日期：2026-08-24/25（Tech Times 08-25 03:48 北京）　来源：Tech Times（gnews）

Tech Times 以”RISC-V AI 口袋电脑被当前 Ubuntu 拒之门外”报道 LilyGo T-Display K230 Kit（CoreSet 约 150 美元、Kendryte K230 双核 RISC-V + ESP32-S3-R8 协处理器、键盘与 LoRa 选配）。属 08-21 发布事件的二次传播，新细节为：现行 Ubuntu 发行版无法在其上运行（需专用 Linux/RTOS 镜像），印证端侧 RISC-V 终端的发行版支持仍是短板，作为该产品线后续观察点（与 2.1 服务器侧”开箱即用 Ubuntu/RHEL”形成对照）。

窗口内香山主仓库与配套仓库 19 笔提交，按方向归类：

  • COVE 机密计算收敛：fix(MMU, COVE): fix mpt walker bug, pre-flush transaction not properly cleaned (#6314)——修复 MPT walker 的 pre-flush 事务未正确清理问题；fix(mpt): correct mfence operand decoding (#6400)——修正 mfence 操作数解码。延续 08-24 报告的 CoVE/MPT（内存保护表）路线，实现进入细节收敛阶段；
  • AME 矩阵扩展验证：feat(ame): add mcfg state comparison to DiffTest (#944)——为差分测试新增 AME 矩阵配置状态比较，矩阵扩展验证体系补强；
  • 存储与性能：feat(extLLC): support external LLC to v3 (#6384)、feat(openLLC): enlarge openLLC to 32MB (#6401)（开放 LLC 从 16MB 扩至 32MB）、feat(prefetch): add L3 prefetch path for stash prefetch (#6274)、feat(MMU): improve performance counters (#6383)；
  • 验证/工程：difftest v2→v3 移植（#6387）、globalmem C++11 语法兼容、GSIM 构建时长记录等。

意义：香山从”功能打通”进入”性能收尾 + 机密计算收敛”双线推进阶段；LLC 扩容与 L3 prefetch、MMU 性能计数器等工作显示性能调优是当前主节奏，AME 矩阵扩展验证同步推进。

五、总结与趋势观察

  1. RISC-V 服务器化进入”实物交付”阶段：BigSky 2U 机架服务器限量现货 + CUDA 实际运行（作 NVIDIA GPU LLM 负载头节点）+ NVLink Fusion 路线图，叠加 Linux 7.3 服务器特性扩展（QoS 标识/计数器委派/CFI）与 ISO 标准化推进——数据中心”最后一公里”软件栈正在密集补齐；
  2. NVIDIA CUDA 支持从 2025 表态到 2026 Hot Chips 技术要求细化（RVA23、PCIe 一致性、P2P），”服务器级 CPU + 平台”是硬门槛，直接利好 P870-D 类高性能核与 RVA23 服务器规范生态；
  3. 国内分化延续：香山双线推进（COVE 收敛 + 性能/存储打磨，19 笔提交，窗口内最活跃）；进迭时空驱动/文档例行；奕斯伟计算港股 IPO 披露累亏超 52 亿、客户集中度高——国内头部 RISC-V 设计公司的商业化压力显性化，需持续跟踪；
  4. 车规生态补强：IAR×东软睿驰工具链合作、Andes D23-SE ASIL-B/D 认证，叠加奕斯伟 EAI8800（7 月双认证）——RISC-V 车规”IP—工具链—基础软件—芯片”链条逐步闭合，AUTOSAR 生态向 RISC-V 迁移提速；
  5. 开源侧活跃度回升：CPython tier 3、Linux 7.3 多扩展合入、HN 对 CUDA-on-RISC-V 讨论升温（68 分），与近两日平静形成对比；Python 官方支持补齐 AI 软件栈关键一环。

局限性说明：BigSky 性能数据与 CUDA 运行细节以厂商新闻稿为准，尚无独立评测；奕斯伟计算财务数据源自媒体报道与招股书摘要，以正式披露文件为准；ISO/IEC DIS 26791-1 页面反爬无法直接抓取，具体技术范围以 ISO 官网为准；香山提交内容以 commit message 为准，未涉及微架构级验证细节；IAR×东软签约为 08-20 事件、报道进入窗口，事件本身非窗口内发生。
