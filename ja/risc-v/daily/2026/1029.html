    1. まとめとトレンド观察

今日の重点：Qwenputer が RV32IM CPU を Qwen3.5 の重みにコンパイルし、GDN 状態を RAM として使用（10-28）

開発者の Divyansh Agrawal 氏が Qwenputer を公開した。未学習の Qwen3.5-4B に、32ビット RISC-V CPU を直接モデルの重みにコンパイルし、モデル自身の Gated DeltaNet 層の状態をメモリとして使用するものだ。この件は調査期間内に Adafruit、Startup Fortune など複数メディアに転載され、Hacker News でも議論を呼んだ。

技術的経路は3段階。第1段階は GDN をアドレス可能な RAM に精密化する：ゲートを1に、書き込み強度 beta を1に、キーを one-hot エンコーディングに設定し、各書き込みは1行のみを上書き、各クエリは1つの正確な値のみを読み出す。これにより GDN ヘッドは行単位でアドレス指定可能なストレージとなり、状態サイズはコンテキストに応じて増加しない。第2段階は CPU を層にコンパイルする：学習不要で、コンパイラが「レジスタ読み出し／加算／条件分岐」などのステップを逐一、アテンションヘッド（ルックアップ）、フィードフォワード層（算術）、DeltaNet ヘッド（RAM）にマッピングし、CPU は Qwen の32層のうち先頭11層を占める。第3段階は実行をデコード中に走らせる：各命令は数個の生成トークンに対応し（ADDR が書き込み行を指定、VAL が数値を運搬、STEP が命令を終了）、これらのトークン自体が実行トレースとなる。

このチップコアは RV32IM に Zba 拡張を加えたもので、さらに小型の大数ユニットを備えている。公式によれば riscv-tests を通過し、プログラム結果は qemu と一致し、フリ－ランニング（free-running、すなわち完全に自身の出力のみで進行し、途中で参照マシンによる修正を一切受けない）で 1800 万命令を実行して誤りは一箇所もなく、約 23 万の出力位置を参照マシンのリプレイと比較して不一致はゼロだった。C と MicroPython を実行できるが、ファームウェアをロードするために小さなドライバ RvChat が必要で、軌跡トークンを Qwen 層の外に追い出すため、現時点では通常の generate 呼び出しで直接実行することはできない。性能面では 1 命令あたり数個のデコードトークンを消費し、ベンチマークのバッチ実行者は L4 上で約 3200 CPU トークン／秒である。

効果面では、DeepMind 算術セットにおいて div_big は 97.5%（Qwen に Python ツールを追加した場合は 95%、ベースモデルは 72.5%）、mul_big は 97.5%（ツール 100%、ベース 55%）、mul_div_multiple_longer は 100%（ツール 97.5%、ベース 90%）、add_or_sub_big は 97.5%（ツール 97.5%、ベース 87.5%）を記録し、NUPA の長整数算術では 48.6% から 100% に向上した。付随して実験的なファイルシステム（1024 スロットのディレクトリ、最大 512 ファイル、約 5.3 万トークンのテキスト）も作成し、GDN 状態に書き込んだ後はセッションをまたいで保持できる。代償としてチェックポイントは 18.8 GB（ベースモデルの約 2 倍、大部分はゼロ埋め）である。

  • 観察：これは産業ニュースではなく、製品情報として読むべきではない。収録に値する理由は、RISC-V に関連する二つの事柄を実演している点にある。一つ目は、あらゆる決定的な ISA は重みにコンパイルでき、ISA の敷居は決して命令エンコーディングになく、ソフトウェアスタックとエコシステムにあるということ。二つ目は、モデル内部のアドレス可能な状態が決定的な実行環境として機能し得ることで、これは「監視能力を重みにコンパイルし、モデル自身が改ざんできない」といった安全研究にとって既製の試験台となる。反面もはっきりと見るべきである。18.8 GB の重み、1 命令あたり数個のトークン、専用ドライバが必要という点で、これは研究装置であってチップの代替品ではないと運命づけられている——実際に RISC-V チップを作るチームがこれによって路線を調整する必要はない。

1. オープンソースコミュニティとソフトウェアエコシステム

1.1 香山 difftest がリモート XDMA ボード中継をサポート、FPGA 検証がマシンをまたいでスケジューリング可能に

日付：2026-10-28　情報源：GitHub：OpenXiangShan/difftest コミット記録

difftest の調査期間内のコミット 3 件で、核心は feat(fpga): support a remote XDMA board relay（#1011）：FPGA 上の被試験コアと参照モデル間のリンクを、リモート XDMA ボードを経由した中継が可能なように改造し、検証マシンとボードが同一マシン・同一席に置かれることを要求しなくなった。付随する 2 件として、一つは fix(fpga): let fork REF finish after the final endpoint（#1010）で、fork シナリオにおいて参照モデルが最後のエンドポイントの後で初めて終了するタイミングを修正する。もう一つは fix(mma): accept zero-sized reference operations（#1012）で、行列拡張パスが長さゼロの参照操作を許容し、空操作が誤りとして拒否されるのを避ける。

  • 観察：これら 3 件を合わせると、difftest が「単一マシンの比較器」から「リモートでスケジューリング可能な検証サービス」へと変わりつつあることが分かる。リモート中継が解決するのはリソース利用率である——一つの FPGA 検証環境はしばしば順番待ちで人を待たせるが、リンクがマシンをまたげるようになれば、複数の人・複数のタスクで時分割利用できる。RISC-V コアを作るチームにとって、検証マシンの時間は通常、設計人材よりも希少であり、この種の変更は性能最適化ポイントを一つ増やすよりも実用的である。

1.2 香山 GEM5 が TEA プロファイリングオプションを追加、XiangShan CI が profile とファジングテストを更新

日付：2026-10-28　情報源：GitHub：OpenXiangShan/GEM5 コミット記録、GitHub：OpenXiangShan/XiangShan コミット記録（kunminghu-v3 ブランチ）

GEM5 側では新たに cpu-o3: Add optional TEA profiling for XiangShan（#1255）を追加し、香山モデルにオプションの TEA プロファイリング経路を接続した。それ以前の調査期間内に、このリポジトリには sv48 機能レベル TLB 初期化の修正、CDP における L2 プリフェッチソース識別の修正、Sstc タイマーサポートなど一群のアーキテクチャレベル修正がちょうどマージされていた。香山本体リポジトリは同日 ci: update profile & improve fuzz（#6758）で、CI プロファイリング設定を更新しファジングテストのプロセスを強化した。

  • 観察：プロファイリング能力とファジングテストが同時に進むのは、コアが「性能帰属 + 長時間安定性」の段階に入った兆候である。GEM5 の路線は特に注目に値する——単なる性能モデルではなく、TEA プロファイリングを備えたアーキテクチャ探索プラットフォームであり、香山の多くのマイクロアーキテクチャ意思決定は RTL の前にここで試される。

1.3 openRuyi 単日 20 件：rust-vmm コンポーネント群をまとめて取り込み、krb5 サービス体系を再構築

日付：2026-10-28　情報源：GitHub：openRuyi-Project/openRuyi コミット履歴

openRuyi メインリポジトリの調査期間内に 20 件のコミット（コミット履歴の先頭 20 件がすべて期間内に該当）、内容は 4 ブロックに分かれる。第 1 ブロックは rust-vmm コンポーネント群のまとめ取り込み：rust-linux-loader 0.14、rust-vm-memory 0.18、rust-kvm-ioctls 0.25 を新規追加し、rust-acpi-tables を 0.2.1 に更新。第 2 ブロックは krb5 サービス体系の再構築で、3 件を一括処理：KDC パスと systemd サービスの統一的な整合、realm 設定を中立化して上流の認証情報規約を踏襲可能に、ビルドオプションをシステムライブラリ使用に変更して上流テストを実行。第 3 ブロックは言語とビルド基盤：go のバックポートインデックス最適化、go-google-api と go-git 関連パッケージの gcfg v2 依存への追従、cmake の Python 配布パッケージメタデータ提供、python-scikit-build-core を 1.1.1 に更新、python-httptools の setuptools バージョンピンを緩和、attr を 2.6.0 に更新。第 4 ブロックは仕上げの修正：ceph の main ブランチ新スナップショットへの追従、procps の rpm 名修正と uptime 復元、sql-migrate の新規追加、python-graphql-core を 3.2.13 にダウングレード、python-backports-zstd の削除。

  • 観察：rust-vmm の 4 点セットを一度に取り込んだことは、本期で最も実質的なシグナルである。このコンポーネント群は Cloud Hypervisor など Rust 仮想化スタックの土台であり、まとめてディストリビューションに入ることは、RISC-V 上で Rust 製 VMM を動かすための依存関係がすでに打通されたことを意味する。あるアプリケーションを移植するのに比べ、仮想化基盤の言語スタックを入れ替える方が影響範囲は一段深い。

1.4 CORE-V CVW が CBO キャッシュ管理を修正：非キャッシュ cbo.zero の最終ビートストールと PBMT エイリアス送出

日付：2026-10-28　情報源：GitHub：openhwfoundation/cvw コミット履歴

CORE-V の CVW リポジトリにキャッシュブロック操作（CBO）の修正 2 件をマージ：Stall an uncached cbo.zero through its final beat は非キャッシュ区間の cbo.zero を最終ビートまでストールさせ、書き込み応答完了前にパイプラインを解放することを避ける；Send cbo.clean/flush/inval to the D$ through PBMT=NC/IO aliases はこれら 3 種類の操作を、ページテーブルエントリが非キャッシュまたは IO エイリアスとマークされている場合でもデータキャッシュへ正しく届ける。2 件は PR #2010、#2008 を経てマージされた。

  • 観察：CBO は RVA23 で最も見落とされやすい命令群である——ベクトル拡張のように性能ランキングに現れることはないが、非キャッシュ区間の最終ビートタイミングと PBMT エイリアス処理はいずれも「普段は発動せず、ひとたび発動すればデータ破損」という位置にある。CORE-V のような仕様境界を一つ一つテストで突き合わせるプロジェクトの価値はまさにここにある。

2. 製品とエコシステムの動向

2.1 LILYGO T-Display K230：Kendryte K230 デュアルコア RISC-V ハンドヘルド開発キット

日付：2026-10-28　情報源：CNX Software：LILYGO T-Display K230 RISC-V AI dev kit、GitHub：Xinyuan-LilyGO/T-Display-K230

LILYGO が T-Display K230 ハンドヘルド開発キットを発表、メインコントローラは Canaan の Kendryte K230 デュアルコア 64 ビット RISC-V：1.6GHz 大コアは RISC-V ベクトル拡張 1.0 と FPU を搭載、800MHz 小コアは RV64GCB をサポート、さらに INT8／INT16 をサポートする KPU（公式が示す代表的なネットワーク性能は ResNet50 で 85fps 以上、MobileNetV2 で 670fps 以上、YOLOv5S で 38fps 以上）と H.264／H.265 ハードウェアエンコード・デコードを内蔵。本体は 4.1 インチ 568×123 AMOLED タッチスクリーン（MIPI DSI）、1GB LPDDR4、2MP GC2093 カメラ、HDMI 1080p30 出力、100M イーサネット、WiFi 4、SX1262 または LR2021 LoRa トランシーバを搭載；オプションのキーボードドックはさらに nRF9151 を搭載し、LTE-M、NB-IoT、GNSS をサポート、21700 バッテリー室を 2 つ備える。ソフトウェア側は K230 Linux SDK、CanMV／RT-Smart ファームウェア、LVGL ランチャーがあり、新ファームウェアは実験的な Meshtastic と LoRaWAN サポートを提供済み。価格はベアボード約 98.79 ドル、キット約 150 ドル、キーボードドックは 70.94 ドルの追加（nRF9151 付きは 113.25 ドル）。

  • 観察：K230 は「Linux が動き、かつ KPU を内蔵する」数少ない国産 RISC-V デュアルコアであり、LILYGO はそれを物理キーボード付きのハンドヘルド形態に仕上げた。狙いは明確で、LoRa や Meshtastic といった自組織ネットワークのシナリオはキーボード入力、長時間駆動、オフライン AI を必要とするが、これまではラズベリーパイ方案か純粋な MCU 方案のどちらも中途半端だった。150 ドル級の価格設定はアマチュア無線コミュニティや職業教育市場にとっても十分に低い。

2.2 Microchip PIC64-HPSC が初期照射結果を公表：TID 200 krad(Si)、SEL 78.2 MeV·cm²/mg

日付：2026-10-28（発表 10-27）　情報源：Microchip：PIC64-HPSC プロジェクトマイルストーンに関するプレスリリース、Hacker News の議論：PIC64GX 64 ビット RISC-V クアッドコアマイクロプロセッサ

Microchip が PIC64-HPSC 高性能宇宙計算シリーズの初期プロジェクトマイルストーンを公表。耐放射線モデル PIC64-HPSC1000-RH の初期照射特性評価では、総電離線量（TID）が 200 krad(Si) に到達し、単一イベントラッチアップ（SEL）は指定動作条件下で 78.2 MeV·cm²/mg まで試験された；単一イベント効果の特性評価ではシステムコントローラに訂正不能エラーは発生せず、外部リセットも不要だった。同時期のアーリーアクセスプログラムでは顧客にシリコンと開発キットが提供され、ボードパートナーは同プラットフォームに基づく VPX および VNX+ 計算モジュールを開発中である。本シリーズは NASA と JPL による将来の宇宙計算ニーズの評価に由来し、2022 年に HPSC 契約が Microchip に授与された；NASA FY26 民生宇宙不足優先リストでは「宇宙運用向け先進オンボード計算」が第 3 位の技術的不足として挙げられている。

  • 観察：宇宙は RISC-V にとって数少ない「需要が実際にあり、指標が厳しく、代替を受け入れない」市場である。200 krad(Si) という水準は、ミッション範囲が低軌道から月以遠までをカバーできることを意味し、SEL と SEE のデータは宇宙級選定の入場券である——実測の照射データがなければ、アーキテクチャがどれほどオープンでも型番カタログには入れない。この线索のもう一つの見どころは経路である：政府がまず需要を定め（NASA／JPL の評価）、商業企業がプラットフォームを提供し、さらにボードパートナーが VPX 形態への適配を行う。これはコンシューマエレクトロニクスよりはるかに長いが、確実性の高い産業チェーンである。

2.3 GUITION が VisionGo シリーズを発表、7 インチ ESP32-P4 一体型スクリーンモジュールが先頭に

日付：2026-10-28　情報源：StreetInsider／ABNewswire：GUITION が VisionGo シリーズを発表するプレスリリース

深セン晶彩智能傘下のGUITIONはVisionGoシリーズの組込みディスプレイモジュールを発表した。フラッグシップは7インチESP32-P4一体型スクリーンJC1060P470C_I_W_Yで、デュアルコアRISC-V、主周波数360～400MHz級、1024×600 IPS静電容量タッチ、32MB PSRAM、16MB Flash、WiFiとBluetoothを統合し、TFカードスロット、複数系統のGPIOを備え、一部モデルはMIPI-CSIをサポートする。全シリーズは1.28インチから21.5インチまでをカバーし、公式はESP-IDF、Arduino IDE、MicroPython、LVGL、ESPHome、Home Assistantとの互換性をうたう。

2.4 SiFive、RISC-VをAIアクセラレータの制御層に位置づけ、X100／X200／X300でACUを実現

日付：2026-10-28（SiFiveブログ10-16、Jon Peddie分析10-26、10-28にコミュニティで議論を喚起）　情報源：SiFive：The Next Leap in Datacenter AI — Orchestrating Custom Accelerators with Intelligent Control Units、Jon Peddie Research：SiFive makes the case for RISC-V as the control layer for custom AI accelerators

SiFiveはIntelligenceシリーズプロセッサを「アクセラレータ制御ユニット」（ACU）として用い、ホストプロセッサとカスタムアクセラレータの間にプログラマブルな制御プレーンを1層挿入し、低遅延のコマンドディスパッチ、データ移動、前後処理、アルゴリズム調整を担わせることを提唱した。その論証は従来方式の3つの欠陥に向けられている。ハードワイヤードのステートマシンはアルゴリズムやデータ形式の変化に際して高コストなハードウェアの作り直し（respin）を要する、共有バス上の頻繁なデータ移動は許容できない遅延をもたらしメモリアクセスのパイプラインを詰まらせる、低層のスケジューリングをホストCPUに押し付けるとホストの演算能力を奪うと同時に遅延を増幅する。シリーズの分担は、X100が制御集約型で面積と遅延に敏感なシナリオ向け、X200とX300がより大きなベクトル帯域幅と演算能力を提供する。Jon Peddie Researchの分析は2つの実装情報を補足している。Googleのデータセンターは既にIntelligence X200をAI計算ホストとして採用しており、別の米国大手半導体企業1社（匿名）が産業エッジAI向けにX100のライセンスを取得した。

  • 観察：この判断はトレンド欄に記録する価値がある——RISC-Vの商業的価値は「ISAの代替品」から「異種システムにおける固定された役割」へと移りつつある。SiFive自身の表現は「価値はISAから移りつつある」であり、残る差別化は実装とシステム統合にある。国内メーカーへの意味も同樣に直接的である。Armメインコントローラを正面から置き換えるよりも、AIアクセラレータの傍らで制御層とスケジューリング層を担う方が、ソフトウェアエコシステムへの要求がはるかに低く、受注も早く取りやすい。

3. 国内チーム深掘り

3.1 奕斯偉計算CTO何寧：車載グレードとエンボディドインテリジェンスが第2・第3の成長曲線に、RISC-Vコンシューマー向けAI NASは第4四半期に量産

日付：2026-10-28　情報源：21世紀経済報道：21対話｜奕斯偉計算CTO何寧、RISC-Vの高価値転換点が到来

奕斯偉計算の上級副社長兼最高技術責任者（CTO）である何寧氏は、サミット後の単独インタビューでいくつかの具体的な判断を示した。第一に、RISC-VとAIの融合は3つの経路に分かれる。RISC-VをメインコントローラCPUとしてNPUを外付けする（疎結合、製品は既に多い）、RISC-VがAIユニット内部に入りスケジューリングを担う（NVIDIA GPU内部には多数の小型RISC-Vコアが組み込まれている）、そしてベクトル・行列拡張によりRISC-V自身がAI演算能力を持つ、というものだ。同氏はスケジュールを示した。行列拡張は大規模モデル計算の8割以上を占め、仕様が完成し製品化されるまでにさらに1～2年、そこから2～3年を経て初めて規模の整った標準化製品が登場する。「RISC-VとAIの深い融合の爆発には、おそらくさらに3年以上かかる」。第二に、ソフトウェアエコシステムが依然として最大の障壁だが、3つのチャンスウィンドウが現れている。AIがソフトウェアとハードウェアを一体で再構築しつつあること、大規模モデルがアルゴリズムとオペレータのツールチェーンを再構築したこと、演算能力の重心が学習から推論へ移っていること（推論エコシステムの複雑さは学習より顕著に低い）である。

実装面では3つの確固たる進展がある。車載分野では、EAM2011は軽量AIアプリケーションをサポートする国内初の車載グレードMCUであり、自社開発の32ビットRISC-Vコアを搭載し、ディスプレイアセンブリ、車載ワイヤレス充電、バッテリー管理システムに量産適用済みである。自社開発のRISC-V CPU IP R520AはドイツのラインTÜVのASIL-D機能安全認証を取得し、世界初のASIL-Dを通過したマルチコア・マルチアーキテクチャRISC-Vコアとなった（従来のR500Aは世界初のASIL-B認証を取得したRISC-Vコア）。エッジ・知能計算分野では、極空間との協業により、RISC-Vアーキテクチャに基づく世界初のコンシューマ向けAI NASを発表し、2026年第4四半期の正式量産販売を計画している。エコシステム面では、150製品以上を量産し、世界220社の顧客にサービスを提供しており、RISAAエコシステム技術プラットフォームと主導して設立したRDI聚力聯盟を通じてエコシステムを推進している。

  • 観察：インタビューで最も堅実な一文は、車載の壁垒はチップになく体系にあるということだ——サプライチェーン、Tier1から自動車メーカーの導入まで、チェーンは極めて長く、チップを作ることは第一歩に過ぎない。ASIL-Dが重要なのは、「スマートドライビング領域に入れるかどうか」をビジネス上の問題から証明書の問題に変えたからである。証明書を取得した後、RISC-Vの柔軟性が「スマートカーの機能融合」という頻繁に変化する要件部分に適合する資格を得る。AI NASについては、第4四半期の量産は検証可能な時点であり、来四半期に振り返る価値がある。

4.2 unitree-go2 が地形専用 V2 歩行ポリシーに切り替え、IMU スナップショットをゼロコピー読み取り

unitree-go2 リポジトリの調査期間内は6コミットで、重点は歩行ポリシーと知覚読み取りにある：「地形専用」の V2 歩行ポリシーに切り替え、モデルダウンロードを指定バージョンに固定するとともに、既存のモデルアーカイブダウンロードアーキテクチャを維持。性能面では read IMU snapshots without copying motor state（PR #4）により、IMU スナップショットの読み取りがモーター状態のコピーを伴わなくなった。さらに CI 回帰下での SBUS 依存関係ロードとオプション SBUS 復旧のハードウェア設定説明を修正した。

  • 観察：「地形専用」とは、ポリシーが段差やスロープなどの工况ごとに分岐せず、単一の地形ポリシーでカバーすることを意味する——これは sim2real のドメインランダム化範囲を狭め、実機の安定性と再現性を取る一般的なトレードオフである。IMU スナップショットのゼロコピー読み取りは、1kHz 級の制御ループにおけるジッター源に直接対応する：モーター状態をデータパスから外すことで、読み取り遅延は「状態量に比例」から定数になる。

4.3 peripherals-imu が HI91 シリアルフィードバックをサポート、BMI270 IIO チャネルを再利用

日付：2026-10-28　情報源：GitHub：spacemit-robotics/peripherals-imu

peripherals-imu の調査期間内は2件：feat(imu): support HI91 serial feedback（#21）で HI91 のシリアルフィードバック解析を追加；perf(imu): reuse BMI270 IIO channels and pace sensor reads（#22）で BMI270 のカーネル IIO チャネルを再利用し、センサー読み取りをスロットリングするよう変更。このリポジトリはこれまでに BMI270 の SPI イベント駆動、IWT603 と Forsense の UART ドライバ、ICM42670P の割り込み出力をカバー済みである。

  • 観察：IMU ドライバのこの線は「機種ごとに1プロトコル」から「カーネル IIO 統一エントリ + 少数の独自プロトコルによるフォールバック」へと向かっている。組立メーカーにとっては良いシグナルだ——センサー交換時にアプリケーション層を変更する必要がなく、カーネルに IIO チャネルがあればよい。進迭自身にとっても、3社目のシリアルプロトコル（IWT603、Forsense、HI91）対応は、同社のロボットリファレンスデザインがより多くの国産 IMU サプライヤーに適応しつつあることを意味する。

5. まとめとトレンド観察

1. 検証インフラの次のステップはリソースプール化。 香山 difftest の今日のリモート XDMA ボード中継は、「検証機とボードが同一マシンでなければならない」という制約を取り除く。直近3日間の fast-ref と fork チェック、reftrace 記録リプレイ、MMA 同期検証スイッチと合わせると、difftest の技術路線は単回比較速度の向上から、複数セットの検証リソースのスケジューリングへと移っている。国内で RISC-V コアを手がけるチームは一般にマシンタイムが不足しており、この道は性能最適化点をもう一つ積むよりも現実的な価値がある。

2. AI における RISC-V の役割は「メインコントローラの代替」から「固定された脇役」へ変わりつつある。 同じ日に2つの独立した記述が現れた：SiFive は Intelligence シリーズを AI アクセラレータの制御ユニットと位置づけ（Google データセンターでは既に X200 を AI 計算ホストとして使用）、奕斯偉の何寧は RISC-V と AI の融合をメインコントローラ外付け、ユニット内スケジューリング、命令セット拡張の3つの経路に分解し、3年間のタイムテーブルを示した。両者は同じ判断を指し示している——先端プロセスにおける正面代替は現在の主戦場ではなく、制御面、スケジューリング面、推論側こそが受注を得られる位置である。

3. 車載規格が今回の分水嶺であり、コンシューマエレクトロニクスではない。 奕斯偉 R520A は TÜV ラインラントから ASIL-D（世界初のマルチコア・マルチアーキテクチャ RISC-V コア）を取得し、EAM2011 車載 MCU はすでに量産車への搭載を果たし、極空間と協業するコンシューマ向け AI NAS は第4四半期の量産に向けて調整中だ。三つのラインのうち、ASIL-D は価格競争で回避できない唯一のハードルである。これは「スマートドライビング領域に参入できるかどうか」を証明書の問題に変える。国内の他の RISC-V メーカーが高付加価値シーンを目指すなら、この証明書のタイムテーブルは個別に追跡する価値がある。

4. ロボティクススタックは「同期」から「開発」へ移行。 昨日は一括イメージ同期と判定された spacemit-robotics だが、本日は四つのリポジトリで十件の実質的なコミットを記録した。ミドルウェア層へのモーションアダプタとオペレータクライアントの接続、全身制御における表形式カップリングとフィードバック復旧のサポート、Go2 の地形限定 V2 ポリシーへの切り替え、IMU ドライバの第三社シリアルプロトコルへの拡張とカーネル IIO の再利用である。この欄の判読方法は引き続きメインブランチのコミット内容を見ることを原則とするが、結論は証拠に従うべきである。

5. 本期の情報量と判定根拠。 中国語と英語の Google News ウィンドウ内で重複排除後にヒットしたもののうち、実質的な新規項目は Qwenputer、奕斯偉 CTO インタビュー、LILYGO K230、Microchip PIC64-HPSC、GUITION VisionGo、SiFive 制御層の議論の六件に集中した。残りはサミット後の解説記事と株式市場関連記事であり、重複排除ルールに従って除外した。オープンソース側が本期の主体であり、香山検証チェーン、openRuyi の rust-vmm、CORE-V の CBO 修正、進畳のコンパイラ／ロボティクススタックのいずれも検証可能なコミット記録がある。
