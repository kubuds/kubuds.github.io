RevyOSカーネル単一期間101コミット：K3ディスプレイとUSB3の実装、EIC7700ファンと熱ゾーン、SG2044 SRD3両ボードのツリー投入（11-11）

revyos/linuxリポジトリのrevyos/7.3.yブランチは、本調査期間内に101コミットを実装し、時間順に三つのバッチに分かれる。最大のバッチは11-11 13:06（北京時間）前後で、主体はプラットフォーム特性とFROMLISTの回補である。SpacemiT側ではK3のGPUノードとディスプレイパワードメイン、K3 Pico ITXのType-C Port A、USB3 PHYとFUSB301自律コントローラ、PHY初期化後にPERST#をアサートするPCIe、UFSのWriteBoosterサポートを追加し、K3上のamdgpuの動的PCIeレート切り替えを無効化した。ESWIN側ではEIC7700にhwmonファンコントローラ、PWM、熱ゾーンノード、CPU／デバイス調頻を補い、最高周波数を1.4GHzに設定した。SiFive HiFive Premier P550ではUSB、SATA、PCIe、eMMC、SDを補完した。T-Head側ではLichee Pi 4Aがハンドオーバー時にUSB給電を維持するようにし、Milk-V MelesのUSBを有効化した。

チッププラットフォーム以外にも汎用的な変更がある。RISC-Vページテーブルアクセサ関連のFROMLISTパッチが一括で回補された。ページテーブルアクセスを一律にアクセサ関数経由にすること、アクセサの非冪等性を許容すること、ページテーブル書き込み時のメモリタイプを修正すること、NとMTビットをptdumpで有効状態に応じて表示すること、アセンブリ向けに全ページテーブルビットを公開すること、alternativeに三引数マクロと置換可能なリンクレジスタを追加すること、さらにDMA_DIRECT_REMAPの選択ロジックを修正した。KVM側では全カウンタをVS-modeに公開してbootloaderとの互換性を確保し、XLINUXENVCFGというcpufeatureでSENVCFGアクセスをガードした。

第三のバッチは14:52のdefconfig收口である。昨日報告の六件を基礎に完全なマトリクスへと拡張した。K1、K3、DP1000、EIC7700、TH1520、SG2042／SG2044を個別に有効化し、さらにPicoheart errata、common options、debian_defconfigを追加し、linuxboot設定、クロスとネイティブ両方のCIビルド、そして「大バージョン番号をパッケージ名に使う」などのパッケージ側HACKを補った。三バッチを合わせると、この日の重点はある新機能ではなく、これまで各ブランチに散在していたボードサポートを、コンパイルできパッケージを生成できる組み合わせにまとめ上げたことにある。

個別に注目すべきはSG2044のボードラインである。SRD3-10-LBとSRD3-12の二枚のボードのデバイスツリーが同時にツリー投入され、SRD3-12にはlarge-BAR変体も付き、さらに第二のC2C1 x4 PCIeポート、eFUSEコントローラを追加し、PCIeウィンドウをEDK2の実装に合わせて整列した。RISC-Vサーバー整機を手がけるチームにとって、ボード記述とファームウェアの口径が一致することは、ドライバが一つ増えることより重要である。一致しないウィンドウ分割は、マルチカードのシナリオでデバイス列挙の不完全さとして直接現れる。

Espressif esp-riscv-trace 0.2.0：RISC-V命令レベルtraceにdecode／profile／stats／historyの4コマンドを追加（11-11）

Espressifはesp-riscv-traceを0.2.0へ進めた。このツールが行うのは、EspressifのRISC-Vチップ上で取得したハードウェア命令traceのデコードである：OpenOCDが生成する.esptraceキャプチャを読むか、esp-coredumpが生成するtrace注記付きcore ELFを読み、プログラムの実行フローを再構築し、各PCを関数とソース行に解決し、テキストダンプ、ホットスポット表、クラッシュ前の呼び出し履歴、またはそのままフレームグラフに投入できるコールスタックを出力する；連続性が失われた位置は推測で埋めずgapとして标注する。0.2.0で新增された4つのコマンドは、この能力を「取得できる」から「分析できる」へ押し上げる：decodeは実行済み命令を列挙し、profileはフレームグラフのスタックを書き出し、statsはソース行ごとに命令数を集計し、historyはopen_captureインターフェースとともに複数キャプチャのマージと振り返りを開放する。

対応チップリストはESP32-C5、C6、C61、H2、H21、H4、P4、S31をカバーし、パッケージフォーマットはProcessor Trace 1.0とEfficient Trace 2.0の2世代に分かれる。使用方法はESP-IDFでtrace設定を有効化し、OpenOCDのesp riscv_trace start／stopでキャプチャし、panic後はファームウェアがデバッガ停止前に先にtraceを停止し、最後のセグメントの喪失を回避する。

この件の重みは「RISC-V 端側のデバッグ可視性」にある。これまで数十セントの RISC-V MCU で性能分析を行う場合、基本的には打点とカウントに頼っていた。命令レベルの trace は長らく高級デバッガの機能だった。楽鑫がこれを pip でインストール可能な Python ツールにし、さらにキャプチャを読み取るインターフェースを外部に公開したことで、「このコードが一体何命令実行されたのか、ホットスポットはどの行か」を通常の手段に変えた。RISC-V 上で推論オペレータやリアルタイム制御を行うチームにとって、こうしたツールの限界価値は、もう一度クロック周波数を上げることよりも高いことが多い。

ch32rv-clang：CH32 Arduino コアが RISC-V 専用 clang と lld に切り替え、RISCV バックエンドのみをコンパイル（11-11）

コミュニティ組織 CH32 RISC-V User Group は ch32rv-clang をリリースした。上流 LLVM リリース版からビルドし、RISCV バックエンドのみを残した clang と lld で、ホストシステムごとに圧縮パッケージを1つずつ作成し、ArduinoCore-CH32RV が Arduino ボードマネージャ経由でインストールできるようにした。このバージョンは意図的に減算を行っている——圧縮パッケージには C ライブラリもコンパイラランタイムも含まれず、当分は xPack GNU RISC-V Embedded GCC が提供する newlib-nano と libgcc にリンクする。その代わりに得られるのはサイズとインストールパスの簡素化だ。ルートディレクトリ1つ、bin 以下に12のツール（Linux と macOS では単一の multicall バイナリとソフトリンク、Windows ではそれぞれの実行ファイル）で、解凍すればすぐ使える。

命令セット側では WCH 青稞の XW 圧縮命令をサポートし、LLVM 19 以降の Xwchc 拡張に対応する（-march に _xwchc を含む）。どのコアが XW を備えるかはコアのデバイステーブルで管理される——この点はかなり明確に書かれている。QingKe V3A、V4A のように XW を持たないコアでは、最初のこの種の命令を実行した時点でプログラムが停止するため、チップ型番から推測してはならない。プリコンパイルは5つのホストをカバーする。x86_64 と aarch64 の Linux、x86_64 と aarch64 の macOS、そして Windows MSVC だ。バージョン番号は「LLVM バージョン-ビルド番号」で表記され、例えば v23.1.5-1 のように、1つのタグが全ホストのビルドをトリガーし、.sha256 付きの成果物をリリースする。ビルドスクリプトは MIT、アーカイブ内の LLVM は Apache 2.0 with LLVM Exceptions である。

この一連のコミットの技術的核心は「長時間収集でデータを失わない」ことにある。ロジックアナライザの価値は偶発的なタイミング問題を捉えることにあり、偶発問題の前提は往往にして数十分から数時間の連続収集である。フロントエンドのレンダリングがサンプリングレートに追いつかなくなると、ブラウザ側でフレーム落ちやメモリ爆発が起きる。ウィンドウを置換に変え、スキャンを消費速度にスロットリングし、バックプレッシャーをフロントエンドからデバイス側へ伝えることは、こうしたツールが必ず越えなければならないハードルである。

同じ調査期間内に、矽速のTangMega-138K-exampleにもPCIe関連の変更が2件マージされた。REFCLK安定後にSerDes起動レジスタを再送し、138KコンソールのDDR3説明を補足した。前者は典型的な「電源投入シーケンスの不確定によるリンク起動失敗」の修正方法であり、FPGA側のハードウェア適応経験に属する。

4. 具身知能とロボット専章

進迭 SuperMimic を LingLong から G1 へ拡張：待機に4つの選択可能動作と汎用動作ディレクトリを同一バッチで実装（11-11）

spacemit-roboticsの2リポジトリで同日、SuperMimicの拡張がマージされた。humanoid_unitree_g1にSuperMimic動作モードを追加し（#16）、待機状態と4つの選択可能動作を設定し、共通のCPU推論スケジューリングを共有するとともに、各動作のキャンセルタイミング、オペレータバインディング、音声提示、リソース準備、使用ドキュメントを補完した。humanoid_commonは同時にSuperMimicの動作ディレクトリをサポートした（#31）。2件のコミット時刻は1分差であり、同一の協調作業によるものである。

タイムラインを照合する価値がある。11月5日のhumanoid_linglongの#22で初めてLingLongのSuperMimic立ち姿策略を設定体系に接続した際は、1機種・1策略であった。6日後に同じ能力がG1へ拡張され、さらにcommon層の動作ディレクトリへと下沉されたことは、これが「単一機種の策略設定」から「機種横断の設定可能な特性」へと変わりつつあることを示している。動作ディレクトリがcommon層で定義されれば、新規機種は動作実装とバインディングを提供するだけでよく、スケジューリングをもう一套複製する必要はない。

整機インテグレーションを手がけるチームにとって、こうした作業の意義は「デモ」を「製品特性」に変えることにある。待機、動作選択、キャンセルタイミング、音声提示、リソース準備の5項目が揃って初めて、ロボットを顧客に納品する際の動作ライブラリとしてあるべき姿になる。北京が同日に発行した三年行動方案は、整機の年間生産能力と無故障時間を評価項目に盛り込んでおり、動作ライブラリの設定可能性と故障時のリセット可能性は、まさに生産ラインのタクトとアフターサービスコストの一部なのである。

5. 総括とトレンド観察

1. 政策はエンボディドインテリジェンスの需要側を数値化し、RISC-Vの機会は関節と本体の二段階にある。 北京のこの方案が示した年間20万台の整機生産能力、主要部品の現地調達率60%、1万元以内の器用なハンドは、本質的に「どのチップを、いくらのコストで、どの程度の信頼性で使うか」を調達パラメータとして書き込んだものである。関節側にはハードリアルタイムと確定的ネットワークが、本体側にはVLAを動かせる計算能力と帯域幅が求められ、どちらの段階も単一の大型チップでは解決できない。国内のRISC-Vサプライはこの両段階ですでに比較可能な製品を持っており、今後の競争点はピーク演算能力ではなく、2000時間無故障という制約の下でコストを整機メーカーが進んで部材を切り替えたくなる水準まで圧縮できるかどうかである。

2. ディストリビューションのこの日のキーワードは依然として「デリバラブル」だが、手法はパッチからマトリクスへと転換している。 RevyOSは1日で101コミット、重点はK3、EIC7700、SG2044、TH1520、P550のボードレベルサポートをdefconfigマトリクスに集約し、クロス／ネイティブ両方のCIを接続することにある。openRuyiは1日で36コミット、可観測性と認証という二つのサプライチェーンを同時に収束させ、カーネルを7.3.4／6.18.63に引き上げた。両者とも取り組んでいるのは新機能ではなく、「他人がビルドできるか、生産環境に投入する勇気があるか」である。

3. 検証と可観測性がツールチェーン競争の新たな前線となっている。 NEMUはAMEマトリクスのメモリアクセスに高速パスを追加し、difftestはMMA検証をベクトル化し、香山はCIにISAスモークテストを追加し、楽鑫は命令レベルtraceをpipでインストール可能な4コマンドに仕上げた——この四つの動きは同じ判断を指し示している。すなわち、コアと拡張が一定の複雑さに達すると、ボトルネックは「設計が正しいか」から「それが何をしているかを素早く見極められるか」へと移る。この線上の投入が不足しているチームは、インテグレーション段階で倍の時間を費やすことになる。

4. 香山の18コミットの純粋なリファクタリングは、高性能コアが構造ガバナンス期に入ったことを示す。 あるモジュールに対して「構造だけを動かし振る舞いは変えない」バッチリファクタリングが可能な前提は、リグレッション範囲が十分に密で、振る舞いがすでに安定していることである。TLBとPTWはメモリアクセス経路で最もデバッグが難しい区間であり、権限チェックとバイパス結果を単一の出口に収束させることは、後続の拡張にインターフェースを残すことになる。こうした作業はどの性能数値にも現れないが、次世代コアに機能を追加する際の変更コストを決定づける。

5. 資本側のプライシングアンカーが俎上に載ったが、資産の境界はなお開示を待つ。 アリババの公告は平頭哥の香港上場分拆を計画し、香港取引所は分割可能を確認、評価額は200億〜300億ドルから250億〜620億ドルまで幅がある。RISC-V企業にとって、この件の参考価値は評価額の数字ではなく、目論見書が外部収入と関連取引をいかに切り分けるかにある——同じ基準がほどなく、すべての国産演算チップ企業、すなわちまだ赤字期にあるRISC-Vサーバー／IPベンダーを含めて、評価に用いられることになるだろう。
