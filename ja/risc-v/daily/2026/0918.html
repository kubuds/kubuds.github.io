今日重点：中国方案首次完整主导 RISC-V 国际指令集标准

日期：2026-09-17　来源：中国科技网／科技日报《七年攻坚实现零的突破！中国方案正式写入 RISC-V 国际指令集标准》

上海交通大学计算机学院并行与分布式系统研究所（IPADS）团队主导的 SPMP（Supervisor-mode Physical Memory Protection，特权态物理内存保护）指令集标准，已通过 RISC-V 国际基金会董事会审议，正式合入 RISC-V 指令集架构标准。这是 RISC-V 国际基金会成立以来，首个由中国本土团队从零发起、完整主导的 ISA 标准特性。报道指出，2026 年获批的其他 ISA 扩展均来自 SiFive、Meta、高通等海外团队，国内此前在香山等实现层进展显著，但在顶层指令集标准制定上存在空白。

技术思路上，SPMP 针对终端设备轻量级安全隔离难题，采用「只看门牌、不查索引」的方案：依靠芯片内部一组配置条目记录物理地址区域的起始地址、长度与访问权限，处理器访问内存时仅需一次寄存器校验即可完成权限判断，无须多级地址转换，以极小硬件开销实现内存安全隔离，补齐 RISC-V 在高安全、低功耗终端场景的短板。项目自 2019 年 9 月提交设计初稿，由陈海波教授带领，杜冬冬、杨璧丞、夏虞斌等核心成员牵头推进近 2500 天完成标准化。该方案曾入选 RISC-V 国际基金会 2021 年度安全亮点特性，也是 Linux 基金会 2023 年度四大 RISC-V 安全进展中唯一来自中国的项目。

落地侧已具备实证：SPMP 技术已在香山开源高性能处理器、芯来 RISC-V IP 等国产芯片平台完成部署。RISC-V 国际基金会董事会成员、中科院计算所副所长包云岗评价称，这使我国芯片领域实现「从被动遵从规则到主动定义规则的转变」。对产业而言，这一事件的意义在于标准话语权的实质变化：全球芯片厂商在设计 RISC-V 芯片时均可选用这套中国主导的安全隔离规范，国内团队从生态应用方转为规范供给方。

一、开源社区与软件生态

1.1 Canonical：RVA23 之后的演进路线，CFI、矩阵扩展与 RVA23.1

日期：2026-09-17（文章 09-15 发布，09-17 经 Hacker News 进入窗口）　来源：Ubuntu 官方博客《Evolution of the RISC-V ISA. What next after RVA23?》

Canonical 的 Jon Taylor 系统梳理了 RVA23 之后的方向。安全侧以 CFI 为例，该扩展 2024 年获批，由 Zicfilp 与 Zicfiss 两条独立扩展组成，用于防御返回导向与跳转导向的控制流攻击；设计上尽量兼容既有 RVA23 硬件，硬件未实现时相关指令被忽略，但缺少 Zimop 支持的 RVA23 之前硬件上 Zicfiss 指令会陷入——这给编译器工具链先行适配留出了空间。矩阵扩展给出三条路线：VME 复用标准向量状态、操作系统无需改动；IME 扩展向量寄存器堆并新增结果寄存器；AME 使用全新寄存器文件。后两者要求操作系统在上下文切换时感知新增寄存器状态，应用则可通过 sys_riscv_hwprobe() 在运行时探测扩展并选择实现路径。

RVA23.1 侧新增三项开发选项与两项扩展选项，文章点出其中三项与发行版关系密切：Double Trap Handling 让机器态或虚拟化态安全捕获处理程序非可重入状态下的二次陷入，降低系统崩溃与内存损坏风险；Supervisor Counter Delegation 将计数器委托下放；以及协助操作系统与工具链对接的平台级能力。Canonical 的结论是，RVA23 提供的是规模化部署基线，而创新仍集中在安全与控制流、矩阵计算、以及不带强制扩展的小版本修订上，后者通过「开发选项」先行、后续配置文件再行强制的节奏，兼顾软件稳定性与新特性引入。

1.3 香山 difftest：关闭 Verilator SLP 向量化以规避 LLVM 误编译

日期：2026-09-17　来源：OpenXiangShan/difftest PR #968

香山差分测试框架 difftest 在 09-17 20:24 合入修复：在 Verilator 构建中关闭 SLP（Superword Level Parallelism）向量化。原因是该优化在部分 LLVM 版本下会触发误编译，导致仿真模型行为偏离参考实现，从而在差分比对中产生假性失败，干扰真实缺陷定位。这类「工具链误编译污染验证结果」的问题在开源处理器验证中并不罕见，处理方式是从构建选项层面关闭可疑优化，保证仿真与硬件行为一致，代价是部分仿真性能损失。

二、产品与生态动态

2.1 汽车侧：首个汽车领域 RISC-V 行业标准（QC/T）启动编制，34 家企业参与

日期：2026-09-17　来源：凤凰网转网通社快报《汽车 RISC-V 首个行业标准启动编制，34 家企业参与》

在 2026 第六届智能汽车芯片生态大会上，中汽芯（深圳）科技有限公司披露：汽车领域的首个 RISC-V 行业标准已启动编制，标准号属 QC/T 序列，目前已有国内外 34 家企业参与编制。这是 RISC-V 在国内汽车行业从企业级实践走向行业规范的关键一步——此前国内汽车芯片侧的 RISC-V 组织化动作集中在联盟与专委会层面（2026 年 4 月中国汽车芯片产业创新战略联盟成立 RISC-V 车规芯片专委会，5 月中电标协 RISC-V 工委会车规应用组揭牌），本次进入行业标准编制意味着技术路线开始沉淀为可检验的规范文本。同期会议还有紫荆半导体等企业分享 RISC-V 驱动汽车芯片革新的实践。

2.2 达摩院：RISC-V 车规功能安全研发周期通常 3 至 5 年，STL 诊断覆盖率存在 RTL 与网表差异

日期：2026-09-17（会议 09-16）　来源：凤凰网《阿里巴巴达摩院李伟立在 2026 第六届智能汽车芯片生态大会分享 RISC-V 车规功能安全研发情况》、盖世汽车同题报道

阿里巴巴达摩院处理器架构师李伟立给出 RISC-V 车规落地的量化判断：国内外 RISC-V 车规应用已在 IP、IC、整机和软件生态四个层面基本达到可用状态，但功能安全研发需经流程认证与产品认证双向迭代，走完流程一般需要 3 到 5 年。技术路径上，ASIL-D 普遍采用双核锁步（DCLS），逻辑简单但代价是两倍面积与两倍功耗；ASIL-B 出于 PPA 考量多采用 STL 软件诊断，要求 90% 诊断覆盖率，面积增加 10% 至 20%。

他点出的三重约束值得记录：STL 单程序段运行时间需控制在数千 cycle 内以免拉长中断响应延迟；车规存储紧张，测试用例丰富度受限；对 Device 类型 IO 设备的访问可能产生不可逆状态，压缩了软件诊断空间。一个关键研发发现是 RTL 仿真与网表仿真的诊断覆盖率存在 5% 以上差异（可达 7% 至 10%），意味着 RTL 阶段需做到 95% 甚至更高才能在网表层达标。李伟立呼吁更多厂商丰富 ASIL-B/D 等级的 MCU 级 IP，并开发面向智驾的高性能计算核心。

2.3 长安汽车：RISC-V 内核在 MCU 领域算力已超 ARM，正探索自定义指令集的 AI DSA 架构

日期：2026-09-17（会议 09-16）　来源：盖世汽车《长安汽车丁可：舱驾融合与 RISC-V 开源架构是汽车芯片破局关键》

长安汽车芯片开发高级副总工程师丁可披露了主机厂的 RISC-V 评估结论：长安早在 2022 年就详细评估 RISC-V CPU 内核，发现其在 MCU 领域算力已超过 ARM，实时性基本相当；基于五级流水线的 RISC-V 架构，中断响应可在 120 个时钟周期内到达入口函数，功耗表现优异。长安还在探索基于 RISC-V 自定义指令集扩展的 AI DSA 架构，通过 BF16 与 INT8 混合精度加速兼顾精度与成本，并提出将芯片管控下探到 IP 核级别、以开放态度参与标准制定的目标。

芯片需求侧，丁可的判断是汽车芯片朝大算力、高带宽、高集成化演进，未来以 1000 TOPS 以上 AI 算力加高带宽中央大脑为核心；7B 模型已实现车载部署，30B 模型在 MOE 架构下考虑上车；端到端路线由 Transformer+BEV 向 VLM、VLA 乃至世界模型迭代。他提到 L3 到 L4 级智驾涉及 1400 多个可运行进程，传统架构解决冗余与失效问题成本高昂，因此舱驾一体的「one box」与舱驾融合成为趋势方向。

2.4 SiFive 与 AMD 的 ROCm 数据中心演示进入主流财经媒体，AMD 当日涨 7%

日期：2026-09-17　来源：EE Times Asia《SiFive, AMD Demonstrate ROCm AI Workloads on RISC-V Datacenter Platform》、Yahoo Finance《Advanced Micro Devices (AMD) Expands ROCm Support To RISC V Datacenter Servers》

SiFive 与 AMD 在圣克拉拉 AI Infra Summit 上演示 ROCm 在 RISC-V 数据中心平台运行 AI 负载的事件，在接近窗口末段进入主流财经媒体视野：EE Times Asia 以「SiFive、AMD 展示 ROCm AI 工作负载在 RISC-V 数据中心平台运行」为题做技术侧复盘，Yahoo Finance 则以「AMD 将 ROCm 支持扩展到 RISC-V 数据中心服务器」的角度将此事写入投资叙事，当日 AMD 股价在半导体板块三连涨中上行约 7%（24/7 Wall St. 亦记录该涨幅并归因于数据中心 AI 扩张）。同一事件在 09-16 已由 Futurum Group、HPCwire 从「中立头节点」定位角度做第三方分析，本期的边际信息是叙事从产业媒体扩散到资本市场，这对 RISC-V 数据中心路线争取外部资源具有实际意义。需注意边界：演示仍为工作站级显卡与紧凑模型的验证性系统，两家公司表示将继续评估更大模型与更多加速场景的 ROCm 优化。

五、总结与趋势观察

  • 标准话语权层面出现标志性事件：上海交大 SPMP 合入 RISC-V 国际指令集标准，是国内团队首次从零发起并完整主导一项 ISA 特性，且已在香山与芯来 IP 落地。与本期汽车侧 QC/T 行业标准启动编制相互呼应，说明国内 RISC-V 参与方式正由「实现与适配」转向「定义与规范」，这是比单点产品发布更结构性的变化。
  • RISC-V 数据中心叙事进入资本市场视野：SiFive 与 AMD 的 ROCm 演示从产业媒体扩散到 Yahoo Finance 等财经渠道，并在 AMD 股价中得到反应。与之前「发布—第三方分析」的演进路径相比，本期的边际变化是外部资本开始为 RISC-V 宿主路线定价，这会影响后续客户评估与供应链投入节奏。
  • 车规是本期最密集的落点：行业标准启动（34 家企业）、达摩院给出 3 至 5 年功能安全周期与 STL 覆盖率量化经验、长安披露 RISC-V 内核在 MCU 算力超 ARM 并探索自定义指令 AI DSA，三条信息分别对应规范、方法与整机评估三个层次，共同指向国内汽车侧 RISC-V 正在从单点验证走向体系化工程。
  • 开源软件侧维持小步迭代：香山仿真链（GEM5 三项、difftest 一项）、revyos 内核配置与 CI、openRuyi 月度版本待发布，均属工程硬化型进展；本期无新的架构级发布，符合此前几期观察到的节奏。
  • 国内厂商工程主线集中在「AI 栈补齐 + 运控分层」：进迭时空在 llama.cpp 多模态后端、视觉示例库预处理后端上连续补强，同时 spacemit-robotics 以公共库承载电机反馈归一化与动作接管、机型仓库只做配置，运控软件分层架构已较清晰；算能则通过 ZSBL 3.1.0 与产品线更名为下游集成做准备。
