今日の重点：雲栖大会：達摩院玄鉄（平頭哥）が真武 V900 を発表、倚天 720／730／750 CPU ロードマップを初公開

日付：2026-09-22（2026 杭州雲栖大会 9月22日から24日）　出典：IT之家「阿里平頭哥が CPU 計画を初公開：倚天 720、730、750 の三代チップを投入へ」、新浪科技「阿里平頭哥が CPU 計画を公開」、快科技「阿里平頭哥の二大チップ重大進展：国産最強 AI チップ真武 V900 が登場、倚天二世代 CPU は 2027 年に確定」、TrendForce「Alibaba Unveils AI Chip Zhenwu V900 for 1Q27 Mass Production, Maps Out New Server CPUs for 3Q27」

9月22日、2026 杭州雲栖大会が開幕した。アリババグループ CEO の呉泳銘氏はメインフォーラムで、AI モデル、AI チップ、AI クラウドを「マシンインテリジェンス」時代の三大基盤として並び上げた。達摩院玄鉄（平頭哥）は同日、新世代の訓練推論一体型 AI チップ真武 V900 を発表した：自社開発の並列計算アーキテクチャを採用し、216GB の大容量メモリを搭載、チップ間インターコネクト帯域は 1200GB/s、単チップ性能は前世代の真武 M890 の 3 倍、FP8、FP4 低精度計算をネイティブサポートし、兆パラメータ級大モデルの訓練と推論の全シーンに対応する；呉泳銘氏はこれを「現在中国で演算性能が最も強い AI チップ」と称した。開示によれば、V900 は 2027 年第 1 四半期に量産販売され、アリババクラウドのデータセンターで大規模に展開される；配套する新世代磐久スーパーノードサーバは 2027 年 Q1 に上市し、その自社開発 ICN Switch は単一クラスタで最大 50 万個の V900 を接続できる。

同場で、平頭哥（T-Head）は初めて倚天サーバー CPU ロードマップを公開した。2027 年 Q3 に倚天 720 と倚天 730 を投入する——720 はスループット・並発型負荷向け（192 コア、PCIe 96 レーン、コアあたりコストを重視し、Agentic Rack の大規模並発実行にサービス提供）；730 は初めて全自社開発 CPU マイクロアーキテクチャ設計に基づく（従来の倚天 710 は Arm Neoverse IP コアを使用）、2 路同時マルチスレッディング（SMT）と PCIe 128 レーンをサポートし、シングルコア SPECint2017／GHz は倚天 710 の最大 1.4 倍に向上、AI Head Node など遅延に敏感なシーン向け；後続の倚天 750 は第 2 世代自社開発コアを採用し、初めて自社開発 ICN 相互接続プロトコルをネイティブサポートし、倚天 CPU と真武 AI チップの直接相互接続を実現する。平頭哥によれば、真武 AI チップ、倚天 CPU、ICN Switch、磐脈インテリジェント NIC、鎮岳ストレージコントローラの 5 本のプロダクトラインが整うことで、そのデータセンター中核チップは「算力（コンピューティング）、網力（ネットワーク）、存力（ストレージ）」のフルスタック自社開発を実現した。

境界と背景の説明：真武と倚天シリーズはいずれも RISC-V 製品ではない（倚天は Arm 命令セットを踏襲）。本項目は「国内チームの深耕」の口径で収録する——達磨院玄鉄は RISC-V エコシステムの中核チームであり（玄鉄 C シリーズプロセッサ IP、「無剣聯盟」、北京開源芯片研究院／中国科学院軟件研究所との次世代オープンソース香山の共同研究開発）、そのデータセンター自社開発路線は本レポートが長期的に追跡する RISC-V 高性能コア（玄鉄 C950 など）と同じチーム内で並行して推進されている。また公式口径によれば（2026 年 4 月時点）、真武シリーズは累計出荷 56 万枚、20 以上の業界 400 社以上の顧客にサービスを提供し、基盤ソフトウェアスタック T-Head SAIL は 2026 年 7 月の WAIC 期間中にオープンソース化された。

1. オープンソースコミュニティとソフトウェアエコシステム

1.1 香山：master にベクトル浮動小数点命令サポートをマージ、NEMU／GEM5／difftest で多数の修正

日付：2026-09-22　情報源：XiangShan コミット：feat(vector): support vector-float instructions、XiangShan コミット：decode に Zicbop 命令を補入（#6586）、NEMU #1222

香山メインリポジトリは調査期間内に 3 件のコミット：最も重要なものは「ベクトル浮動小数点命令のサポート」（feat(vector): support vector-float instructions）で、昆明湖ベクトルユニットに浮動小数点ベクトル演算パスを追加し、併せて vecRegion 接続を整理；decode 側では欠落していた Zicbop 命令を uopTable に補充（#6586）。周辺のシミュレーションおよび検証リポジトリも同時に修正：NEMU は 2 件——NutShell で未実装の一部 CSR を省略に変更（#1222）、Zicntr がない場合に CY／TM／IR を書き込み可能に維持（#1223）；GEM5 は 3 件——mem-cache で probeHit の境界を修正後に hit-under-block を有効化（#1164）、cpu-o3 で IBuffer bypass を無効化して pflush vset を修正（#1135）、SMT で IQ ごとの安全水位戦略を追加（#1175）；difftest は 2 件——iotrace で EOF 位置の最後の zstd ブロックを保持（#972）、OpenIOMMU のファイルリストを条件付き追加に変更（#974）。XSCache は調査期間内に新規コミットなし。

1.2 meta-riscv：BeagleV-Fire ボードサポートを収録、BeagleV-Ahead が SD カード起動に対応

日付：2026-09-22　情報源：meta-riscv：beaglev-fire 新 MACHINE、meta-riscv：hss-payload-generator-native レシピ、meta-riscv：beaglev-ahead SD カード起動サポート

Yocto の RISC-V レイヤ meta-riscv はウィンドウ内で 5 件のコミット：BeagleV-Fire（Microchip PolarFire SoC）ボード BSP と付随する hss-payload-generator-native レシピ（PolarFire SoC の HSS ブートペイロード生成ツール）を新規追加；BeagleV-Ahead に SD カード起動サポートを追加；gptfdisk を 1.0.10 にアップグレード；milkv-duo-fsbl で小コア FSBL 内の RTOS コアを無効化。BeagleV-Fire とそのブートツールチェーンが Yocto メインラインレイヤに入り、この「FPGA ロジック + 4 コア RISC-V」のオープンソースハードウェアプラットフォームにディストリビューション構築パスが揃った。

1.3 Tiny-Vedas が arxiv-v0 スナップショットをリリース：RISC-V AI アクセラレータのオープンソースインフラが論文版へ

日付：2026-09-22　情報源：Tiny-Vedas リリース：arxiv-v0、スナップショットコミット：arXiv v0 論文ソースファイル

RISC-V AI アクセラレータ向けのオープンソースインフラプロジェクト Tiny-Vedas（56 スター）はウィンドウ内で arxiv-v0 スナップショットをリリース：STREAM YOLO サンプル、U280 FPGA スタブ、論文ソースファイルをまとめて凍結し、対応する arXiv v0 プレプリント（論文版はまだ arXiv で公開エントリが検索できない）に対応する。プロジェクトは合成可能な RV32IM コア（4 段パイプライン）、8x8 int8 GEMM アクセラレータ（AXI4 経由で DCCM を共有）、Python ISS／RTL 協調検証、さらに PyTorch JIT（torch.compile から C、そして RV32 ELF へ）までの完全なチェーンを提供し、ロードマップは VLIW、スーパースカラ、アウトオブオーダー、ベクトルユニットなど多マイクロアーキテクチャ拡張をカバーし、物理設計は sv2v と OpenROAD に基づく。同プロジェクトは 2025 年 4 月にリポジトリを開設し、今回のスナップショットはその方法論が引用可能な段階に入ったことを示す。（注：個人主導のオープンソースプロジェクトであり、まだテープアウト記録はない。）

1.4 オープンソースエコシステム短波：RVVM 浮動小数点ユニット修正、Zeitlos FPGA プロジェクト進展、SLogic ツールチェーン修正

日付：2026-09-22　情報源：RVVM が fcvt 動的丸め修正をマージ（#260）、Zeitlos コミット：jumploader と TTS の改善、slogic16u3-tools：書き込み検証ロジック修正

4 件の軽量動向：第一に、RISC-V 仮想マシン RVVM（約 1.3k スター）はウィンドウ内で 5 件の浮動小数点修正をマージ——fcvt 動的丸めモード、fcsr 予約ビットと frm の明確化、NaN と sqrt 結果の正規化（#259、#260、#280）——浮動小数点挙動の仕様一貫性を引き続き磨き込む；第二に、machdyne の RISC-V FPGA SOC／OS プロジェクト Zeitlos（PicoRV32／Zeitlos32 コア、48MHz）が 9 件を集中的にコミット——gateware が任意の flash 位置からのロードをサポート、設定 flash を書き込み可能に、音声合成の改善など；第三に、Sipeed の SLogic16U3 ロジックアナライザツールチェーンが空白書き込み検証を修正（終了コードではなく openFPGALoader の読み戻し検証に変更）；第四に、Tenstorrent の RISC-V コア検証コンポーネント rv_tester が valgrind サポートを追加（#70）。

2.1 AI Infra Summit 回顾報道：Epic Semi の全 RISC-V サーバが登場、RISC-V 制御コアは「遍在」

日付：2026-09-22 報道（展示会 2026-09-15 から 09-17）　情報源：More Than Moore「AI Infra Summit Day 2: Threads + Highlights」

More Than Moore 09-22 掲載の AI Infra Summit（9月15日から17日、サンタクララ）2日目レビュー（著者 Dustin Sklavos、元 AnandTech シニアエディター、Tenstorrent プロダクトマネージャー）：展示場の一角に SiFive と Akeana のブースが設けられ、Epic Semi は正式ブースで「上から下まで全て RISC-V」のサーバーソリューションを展示——メイン制御 CPU と AI プロセッサはいずれも RISC-V コアをベースとしている。記事は特に、RISC-V の展示会における存在感はそのブース占有率をはるかに上回っていると指摘：Tenstorrent の AI アーキテクチャと CPU 製品ラインはいずれも RISC-V コアを採用し、Axelera は RISC-V コアで AI カードのデータフロー制御を担い、Xcena の MX1 CXL メモリ・フラッシュ拡張モジュールは千個を超える RISC-V コアを使用してデータ転送とキャッシュを行う。本誌 09-16、09-17 号で既に収録した SiFive と AMD ROCm の移植デモと合わせて、AI インフラにおける RISC-V の「制御プレーン／オーケストレーション層」としての役割がさらに裏付けられた。

進迭時空の UEFI ファームウェアリポジトリ edk2-spacemit は調査期間内に 20 件のコミットを一括プッシュ：0.0.7、0.0.8、0.0.9 の 3 バージョンを連続リリースし、edk2 と edk2-platforms をサブモジュールからリポジトリ内インラインソースへ変更して最新の上流コミットに同期、さらに Debian パッケージングを整備——control 依存、gitignore 戦略の説明、postinst での必要に応じた mtdblock カーネルモジュールのロード、Spacemit K3 プラットフォーム検出の修正、deb バージョン番号を edk2 プラットフォームバージョンとして使用。EDK2 は K3 などのプラットフォームの UEFI ブートチェーンの中核コンポーネントであり；Debian 化パッケージングへの移行は通常、ファームウェアが Ubuntu／Debian イメージ体系を通じて開発者と顧客に更新を配布することを意味する。

進迭時空ソフトウェアスタックは調査期間内に多点的に推進：ビジョンモデルライブラリ model-zoo-vision の2項目——検出モデルの NMS と後処理の厳格化（#90）、サンプル入力をカメラのデフォルト設定に変更（#91）；mpp（マルチメディア処理プラットフォーム）に「ストリームパケットを VB（ビデオバッファ）参照渡しにする」を追加し、リンク内のデータコピーを削減；ai-gateway に Qwen3-Embedding-0.6B-Q8_0 埋め込みモデルプリセットを追加（#42）；ai-sdk が vision、gateway サブモジュールを2回同期；spacemit-com の FlagTree ブランチに新しい builtins ドキュメントを補充（#1120）；docs-ros が K3 と Reachy の音声指令に英語ドキュメントを追加。その「AI とロボティクスソフトウェアスタックを同期的に厚みを持たせる」リズムを継続している。

3.4 算能：Qwen3.5 35B-A3B（MoE）が CV84X6 に適応、YOLOv8-seg が CV186X デュアルコアをサポート

日付：2026-09-22　情報源：sophon-demo：Qwen3.5 35B-A3B（MoE）が CV84X6 に適応、sophon-demo：YOLOv8_plus_seg が CV186X／2core をサポート、sophon-tools #202：VPP_USAGE が全 VPSS 部品をカバー

算能の調査期間内の3つのライン：sophon-demo は Qwen3.5 35B-A3B（MoE アーキテクチャ）を CV84X6 プラットフォームに適応——前号の Qwen3.5 prefix cache 修正に続くモデル拡張；また YOLOv8_plus_seg_fuse に CV186X デュアルコアサポートを追加。sophon-tools の get_info 出力設定は VPP_USAGE のカバレッジを5項目から13項目の VPSS 全部品に拡張（#202）、新世代パッケージ形態（CV84X6／CV186X）の運用可視化を引き続き整備。その TPU 製品ラインが MoE 大規模モデルとマルチコアビジョンサンプルを同時にサポートする点は、ソフトウェアの配套が依然として急速に補完されつつあることを示している。

4.1 進迭時空 spacemit-robotics：玲瓏ヒューマノイドロボットが立ち姿勢と動力学ポリシーゲインを修正

日付：2026-09-22　情報源：humanoid_linglong #14：動力学 mimic ポリシーを修正、humanoid_linglong #15：立ち姿勢ポリシーゲイン修正（マージ済み）

spacemit-robotics の玲瓏ヒューマノイドロボットプロジェクトは調査期間内に2組のポリシー修正をマージ：#14 は「修正動力学」（corrected-dynamics）mimic ポリシーを設定、#15 は立ち制御において修正後の立ち姿勢ポリシーゲインを採用（当日メインブランチにマージ）。これは実機上のポリシー出力とシミュレーション動力学の偏差に対する継続的なキャリブレーションであり、その「シミュレーション訓練から実機展開」の閉ループにおける定型的な微調整に属する。同組織の peripherals-imu と peripherals-motor は調査期間内にメインブランチへのコミットなし（ブランチレベルのプッシュを検出）。

5. まとめとトレンド観察

  • 国産データセンター・チップの「フルスタック自社開発」が雲栖大会で新たな密度に到達：平頭哥（T-Head）の5つの製品ライン（真武 AI チップ、倚天 CPU、ICN Switch、磐脈スマート NIC、鎮岳ストレージコントローラ）が揃い、倚天 730 は完全自社開発マイクロアーキテクチャへ転換。これと並行して、同一チームの RISC-V ライン（玄鉄 C シリーズ、無剣アライアンス）は引き続きオープン命令セットエコシステムの中核資産として機能——「自社開発マイクロアーキテクチャでデータセンター性能を追求」と「オープン命令セットでエコシステムを拡張」という2つの道筋が同一企業内で同時に進む格局は、継続的に追跡する価値がある。
  • AI インフラにおける RISC-V の「コントロールプレーン」的役割が再び裏付け：AI Infra Summit の振り返りによれば、Tenstorrent のビッグコアマトリクス、Axelera のデータフロー制御から、Xcena MX1 が千個級の RISC-V コアでデータ転送を行うまで、RISC-V は AI チップのオーケストレーション層として「至る所に」存在している。Epic Semi の全 RISC-V サーバー方案は筐体形態のサンプルを提供している。
  • オープンソースハードウェアの「正確性の補習」：今期の香山ベクトル浮動小数点命令サポート、RVVM の5項目の浮動小数点修正、BeagleV-Fire プラットフォームの補完は、RISC-V がフラッグシップコアからシミュレータ、ディストリビューション層に至るまで浮動小数点とベクトルの正確性を細分化していることを示す——まさに「使える段階から使いやすい段階へ」の時期に最も集中的に行われる作業タイプである。
  • 静かな側の観察：openRuyi は2つの情報源（公式サイトニュースページと GitHub リポジトリ）とも調査期間内に更新がなく、2026.09 リリースは依然として未発布。楽鑫（Espressif）の34リポジトリのプッシュは抜き取り調査の結果、USB／Bluetooth／WiFi／CI の定例的な反復であり、ESP32-C シリーズ専用のものではない。芯来（Nuclei）、奕斯偉計算、revyos、Radxa Linkr は調査期間内にプッシュなし。
  • 限界に関する説明：本期のデータは公開ウェブページと GitHub の公開コミットに由来し、非公開チャネルは使用していない。雲栖大会の情報は IT之家、新浪科技、快科技、新快報、紫牛新聞、TrendForce など複数報道に由来し、すでにクロスチェック済みである。一部のより遠いロードマップの時期の口径は媒体間で差異があり、逐一採用はしていない。会員公式サイトの巡回では70社が取得失敗（国内サイトとアンチクロールサイトが主）。
  • 次期の注目点：雲栖大会 09-23 から 09-24 の議程における RISC-V 関連内容；openRuyi 2026.09 リリースが発布されるか；香山ベクトル浮動小数点コミットの今後のマージ動向；奕斯偉計算の上場プロセスと EIC7X リリースのペース。
