今日の重点：奕斯偉計算が香港証券取引所の上場ヒアリングを通過、港股「RISC-V 第一株」となる見込み

日付：2026-09-21　出典：第一財経「奕斯偉計算が香港証券取引所の上場ヒアリングを通過」、新浪財経／観点網「奕斯偉計算が香港証券取引所の上場ヒアリングを通過 2025 年売上高 24.31 億元」、網易号「奕斯偉計算が香港証券取引所のヒアリングを通過、RISC-V トラックに『第一株』が誕生する見込み」

香港証券取引所の文書によると、北京奕斯偉計算技術股份有限公司は 09-21 に香港証券取引所メインボード上場のヒアリングを通過し、共同スポンサーは中信証券と中信建投国際（同社は 2026-07-31 に三度目の目論見書を提出）。今後の公募が順調に進めば、港股「RISC-V 第一株」となり、RISC-V チップトラックの上場銘柄の空白を埋めることになる。

経営データについて：同社は Fabless モデルを採用し、RISC-V を技術基盤として、製品は人機対話およびマルチメディア処理チップ、相互接続および計算チップをカバーし、スマート端末と具現化知能の二大シーンに注力している。2023 年から 2025 年の売上高はそれぞれ 17.52 億元、20.25 億元、24.31 億元、2025 年の純損失は 15.16 億元。2026 年第 1 四半期の売上高は 4.94 億元（前年同期比 18.4% 増）、純損失 3.75 億元、粗利率 14.8%。2026 年 3 月 31 日時点で、150 超のソフト・ハード協調製品を打ち出し、世界 220 社超の顧客にサービスを提供している。計算製品の収入は 2023 年の 37.5 万元から 2025 年には 3.20 億元に増加し、2026 年第 1 四半期には 2.23 億元に達し、製品は自動車、産業などの核心トラックに切り込んでいる。2025 年の売上高ベースで統計すると、同社は国内最大のスマート端末人機対話チッププロバイダーである。

業界データも併せて釋出された。弗若斯特沙利文の統計によると、中國の RISC-V 主控チップ市場規模は 2021 年の 11 億元から 2025 年の 377 億元へと成長し（年平均複合成長率 139.5%）、2030 年には 2194 億元へ拡大すると予測されている。押さえておくべき境界條件は、聆訊通過が正式な発行と価格決定までにはなお手続きが殘ること、同社の純損失と計算製品ラインの出荷拡大ペースが上場後最も直接的な檢驗指標となることだ。同日、同社の GitHub 側にはそれに対応するリリース動作があった（3.1 を參照）。

1. オープンソースコミュニティとソフトウェアエコシステム

1.1 openRuyi：カーネルを 7.2.6 と 6.18.52 の二本立てでアップグレード、セキュリティ修正を一括適用

日付：2026-09-21　情報源：openRuyi コミット：linux アップグレード 7.2.6、kernel-team-tools：TAG を v7.2.6-1 へ、openRuyi 公式サイトニュースページ

openRuyi ローリングディストリビューションの調査期間內のコミットは 20 項以上で、主軸はカーネルの二本立てアップグレードと上流への追隨だ。linux は 7.2.6、linux-lts は 6.18.52 へアップグレード（いずれも patchset と config の更新を含む）。kernel-team-tools は 4 つのカーネル系列のビルドタグ（6.18.52-1／7.0.14-5／7.1.13-1／7.2.6-1）を同期更新し、カーネル config で ULTRARISC、VFIO_IOMMU_TYPE1、ARCH_ANLOGIC などの項目を有効化した。openRuyi-Project/linux の ruyi/6.18.y、7.0.y、7.1.y、7.2.y の 4 つのメンテナンスブランチも同日同期プッシュされた。

ビルド體系側では、openruyi-linux-build コンポーネントを新規追加（各フレーバー変體に統一の linux パッケージを提供）、linux／linux-lts／linux-lts-kmhv2 の 3 つの spec は rpm マクロによる統一メンテナンスへ切り替えた。glibc 2.44 は上流スナップショットに追隨。セキュリティとパッケージ更新を一括適用：python-pytorch-lightning 2.6.6、python-datasets 5.0.1、python-ujson 6.0.0、ImageMagick 7.1.2.31、pcre2 10.48（コミットはいずれも security-fixes と表示）。クラウドネイティブ側では k8s konnectivity-client と kms、Datadog dd-trace-go、VictoriaMetrics などの Go パッケージを新規追加。公式サイトニュースページには調査期間内の新規告知はなく、9 月リリースは未発佈（最新は 2026.08、08-27 リリース）。

1.2 香山：昆明湖 V3 ブランチで CBO とプリフェッチ経路を修正、NEMU は mseccfg を設定可能化

日付：2026-09-21　情報源：XiangShan コミット：LoadUnit が prefetch.i の退休経路を保持（#6230）、NEMU コミット：mseccfg を Kconfig オプション化（#1221）

香山メインリポジトリの調査期間內の 5 項コミットは kunminghu-v3 ブランチに集中している。LoadUnit は prefetch.i を S1 段階でクリアするのではなく正常に退休させるよう変更（#6230）。CBO（Cache Block Operation）命令については 2 項の修正——decode 段階の numWb を 2 に変更、Load-Store Queue の StoreQueue credits が CBO レーンを跨ぐ際に正しく保持されるようにした。docker ベースイメージは xs-env:stable へ切り替え（#6577）、CI 側では ckpt_select.py を改善し nightly fuzz を追加（#6604）。NEMU 側は 2 項：mseccfg を Kconfig 設定可能項目に変更（#1221）、仮想化 supervisor タイマーは nemu_timer が有効な場合のみオフにする。

GEM5 はブランチレベルの開発も同樣に活発だ。feat-ywl-pfbuffer ブランチでは PDB（プリフェッチデータバッファ）モデルを新規追加し、そのリプレイクリーンアップとプリフェッチ准入ロジックを修正。調査期間內にはさらに Hybrid_CROB、calibrate-rvv-iq などの開発ブランチを新規開設（それぞれハイブリッド CROB と RVV 命令キュー校正を指す）。difftest と XSCache のメインブランチには調査期間內の新規コミットはなく、主干マージの動向は引き続き注視が必要だ。

1.3 Bluespec オープンソースハードウェア IP ライブラリ Tape-Out（FukuzSoC）がリポジトリを大量新規開設

日付：2026-09-21　情報源：GitHub 組織 Tape-Out（FukuzSoC）

FukuzSoC という名称のオープンソースハードウェア IP ライブラリが 09-21 にリポジトリを大量新規開設した。3 セットのリファレンス SoC（soc-mcu／soc-linux／soc-smp）と PLIC 割り込みコントローラなどを含む。その組織の自己説明は「Bluespec で構築し、XiRang パッケージマネージャで組み立てるオープンソースハードウェア IP ライブラリ」である。各 IP リポジトリには ip.yaml（設定項目、契約、実測面積）、regmap.yaml（レジスタマップ）、Bluespec ソースコード、全設定マトリクスを網羅する動作テストが含まれる。独自ツールチェーン xirang が解析、生成、テスト、「価格設定」を担当し、spec がファイルの意味を定義する。

IP の系譜は hart プロセッサコア、cache、NPU／GPGPU／YOLO アクセラレータ、ACLINT／PLIC／IMSIC などの RISC-V 割り込み体系部品、UART／SPI／I2C などの周辺機器とイーサネットスイッチ／ルーティングモジュールを網羅する。成熟度は planned／simulated／fpga-proven／asic-ready／silicon-proven の 5 段階に分かれ、各リポジトリでバッジ表示される。リファレンス SoC は「自社 RTL を含まない」と明言し、すべて IP の組み合わせで組み立てられる。この「パッケージマネージャ + IP ライブラリ」という組織方式は国内で一般的な RTL 単一リポジトリ方式とは異なり、その成熟度の進展は追跡に値する。（注：新たに公開されたプロジェクトであり、公開されたテープアウト記録とコミュニティでの議論はまだ見られない。）

1.4 simdjson に RVV ベクトルバックエンドの実験リポジトリが登場

日付：2026-09-21　情報源：MA-Gustave/Simdjson-rvv-vla

開発者が simdjson の RISC-V ベクトル（RVV 1.0）実験バックエンドをオープンソース化した。ベクトル長非依存（VLA）の書き方を採用し、GCC／Clang 検証、実行時ディスパッチ、上流受け入れテスト、再現可能な性能ベンチマークを備える。リポジトリは 09-21 に作成され、当日に連続してコミットがプッシュされた。simdjson は広く応用される高性能 JSON 解析ライブラリであり、RVV バックエンドが上流に受け入れられれば、RISC-V プラットフォームにおけるこのライブラリのベクトル加速経路が補完される。注：現在は個人の実験リポジトリであり、まだ初期段階にあり、性能と上流への受け入れ進捗は検証待ちである。

1.5 オープンソースエコシステム短波：GNOME Flatpak riscv64 ビルド、Exercism トラック、AG32 オープンソースツールチェーン

日付：2026-09-21　情報源：nico359/gnome-flatpak-riscv64、Exercism RISC-V トラック、bbenchoff/AGaMEMnon

3 件の軽量な動向：其一、開発者が GNOME Flatpak Platform／SDK の riscv64 非公式ビルドリポジトリを維持（09-11 にリポジトリ作成、調査期間内に継続更新）。形になれば RISC-V デスクトップ端末のコンテナ化アプリケーションの配布条件が改善される。其二、Exercism プログラミング学習プラットフォームが RISC-V トラックを開設（独立した test-runner を含む、09-21 にプッシュ）。RISC-V が同プラットフォームの言語リストに加わった。其三、AG32（AGM 半導体の RISC-V MCU、AGRV2K FPGA ロジックを内蔵）のオープンソース SDK とツールチェーンプロジェクト AGaMEMnon（48 スター、yosys／nextpnr ベースのオープンソースフロー）が調査期間内に活発で、この「MCU + FPGA」ハイブリッドチップへのオープンソースツールサポートを引き続き推進している。

2. 製品とエコシステムの動向

2.1 インドの Aheesa が VIHAAN-I を発表：自国開発 RISC-V ブロードバンドネットワーク SoC のテープアウト完了

日付：2026-09-21　出典：EE Times「Fabless Startup Aheesa Tapes Out First Indian RISC-V Network SoC」、Machine Maker「Aheesa Advances India’s Semiconductor Ambitions with Indigenous VIHAAN Broadband Networking Chip」

インド・チェンナイのFablessスタートアップAheesa Digital Innovationsは、SEMICON India 2026の期間中に自社開発のRISC-VブロードバンドネットワークSoC「VIHAAN-I」を披露した（ベンダーはこれをインド初の自国設計RISC-Vブロードバンドネットワークチップと称している）。同チップは28nmプロセスで、計算・ブロードバンドアクセス・システム制御をシングルチップに統合し、GPON／EPON光アクセスと通信インフラを対象とし、インドの通信・ネットワーク分野における輸入半導体の代替を目標とする。同社はVIHAAN-Iのテープアウトを完了し、マルチプロジェクトウェハ（MPW）製造への移行を計画、商用化時期の目標は2027年第1四半期である。プロジェクトはインドMeitYの設計リンクインセンティブ（DLI）計画に認定され、タミル・ナードゥ州の新興産業シードファンドから投資を受けている。意義と境界：これはインドの「国産チップ」アジェンダが通信インフラ方向で打ち出した最初のRISC-V SoCの担い手であるが、製品はまだ量産されておらず、プロセスと性能の詳細はいずれもベンダーおよび展示会報道の口径によるものである。

2.2 スマートカー半導体エコシステム大会続報：DF30は2026年の規模量産を計画、Infineonの次世代車載MCUは全面的にRISC-Vへ転換

3.3 進迭時空：model-zoo-vision の RVV 前処理融合最適化と mpp 更新

日付：2026-09-21　出典：model-zoo-vision #86：RVV 加速融合 CPU pack、mpp：流パケットを VB 参照で受け渡し、ai-sdk サブモジュール更新

進迭時空の視覚モデルライブラリ model-zoo-vision は1日以内に4本の最適化 PR をマージした。主軸は RISC-V ベクトル拡張（RVV）による画像前処理の加速である。まず RVV で融合 CPU pack を加速し（#86）、次に face／clip モデルを融合 pack へ移行し（#87）、続いて tracking pack と RVV OCR 認識を融合し（#88）、最後に共有の RVV u8c3 pack 補助関数を抽出してリファクタリングを完了した（#89）。同一期間に mpp（マルチメディア処理プラットフォーム）は feat ブランチで「流パケットを VB 参照で受け渡し」を新規追加し、テストと cpplint スタイル修正を補完した。ai-sdk は vision サブモジュールを2回更新した。前処理は CV パイプラインにおいて典型的な CPU 集約区間であり、この一連のコミットは「オペレータを CPU の汎用パスから RVV へ移す」という最適化の慣性を継続している。
