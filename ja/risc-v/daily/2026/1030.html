今日の重点：ポスト量子命令セット拡張が Cyclone V 上で Classic McEliece を実走、カプセル化解除サイクルが 86.1% 削減（10-29）

『Discover Computing』に掲載された論文が、この設計の完全な FPGA 検証を示した。著者は Haridhayal Maheswaran、Samuel Kennedy、Basel Halak（論文題『Architectural exploration and FPGA validation of a RISC-V instruction-set extension for Classic McEliece』、第29巻第1号論文808、DOI 10.1007/s10791-026-10770-1）で、10-29 に Scienmag と Bioengineer が伝えた。

核心的な結論は3つある。第一に、密結合命令セット拡張は実デバイス上で実現可能である：設計全体は Cyclone V 上で 10,531 個の適応型ロジックモジュールを占有し、最高フィットクロックは 118.89 MHz で、DE1-SoC ボード上に収まる。第二に、加速幅は検証可能である：同一条件の非同期メモリシミュレーション下で、カプセル化サイクルは 87.4% 削減、カプセル化解除は 86.1% 削減となり、未加速ベースラインの 7.18 倍に相当する。同期 FPGA 版はホスト生成の鍵で両端の操作を完了し、カプセル化解除には 3,654,113 サイクル、カプセル化は SHA-256 を含めて 13,585 サイクルを要する。第三に、受益の分布は不均一である：Berlekamp-Massey サブオペレーションは 5,832 サイクルから 40 サイクルに圧縮され、ガウス消去法は最小多項式生成を 297 から 38 サイクルに圧縮（7.8 倍）したが、カプセル化解除の残存コストはほぼすべてサポートリスト生成にあり、両方のメモリ形態でいずれも 99% 以上のサイクルを占め、ボトルネックはサポートを駆動する Benes 置換ネットワークであり、加速済みのデコードロジックではない。

論文で最も方法論的価値が高い部分は、却下された方案である。著者らは当初 composeinv に DMA 支援の命令マッピングを追加する予定だったが、統合プロファイリング後は controlbits 段階でわずか 1.0～1.1 倍の向上しか得られず、その原因は再帰呼び出し構造が狭いメモリ境界を繰り返し越えることでカーネルレベルの利益をすべて相殺してしまうことにあり、そのため直ちに断念した。著者らはこれにより加速器選定のルールを一つ示した：呼び出し構造がデータ移動コストを支配する場合、バッチ内核だけを速く計算しても無効である。この判断基準は、国内で RISC-V カスタム命令セット拡張に取り組んでいるチームにも同様に当てはまる。

実装の詳細も記録に値する。作者はカスタム命令を標準 RISC-V の custom-0 オペコード空間に移し、GCC の .insn 命令で従来のバイナリパッチスタブを置き換え、呼び出しごとに約 20 サイクルの関数呼び出しオーバーヘッドを削減するとともに、コンパイラがカスタム命令を周辺コードに組み込めるようにした。継承した Berlekamp-Massey ステートマシンは bring-up 段階で 4 箇所の欠陥を検出した。シフトループの境界誤り、体の分数演算のオペランド反転、暗黙の 32 ビット拡張がマスク計算を破壊する問題、乗算器入力のゼロ拡張欠如により上位ビットが結果へ漏れ出す問題である。転置パスにも通常のレジスタファイルではなく 64×64 クロスバー配線の転置ストレージが必要であり、この問題は実機のデカプセル化テストによって初めて露見した。ボードの面積予算に適合させるため、テストパラメータは誤り訂正能力 t=2、符号長 n=48、体の次数 12 に抑えられた。

限界は明確に記されている。鍵生成パスは controlbits が依然ソフトウェア側にあるため 3 億サイクルのシミュレーション予算を超過し、下限値しか示せない。ボードの 5 MHz クロックでは 60 秒超、システム全体が 118.89 MHz で動作できれば 2.52 秒超となる。完全なデバイス上での鍵生成は計時もボード上での実演も行われておらず、FPGA イメージにはホストで生成した鍵がロードされている。消費電力については、Quartus PowerPlay の推定で 5 MHz 時に合計 458.34 mW、1 回のデカプセル化は約 731 ミリ秒、消費エネルギー約 335 mJ で、その約 9 割が静的リーク電流である。本番パラメータとサイドチャネル耐性はいずれも評価されておらず、サイドチャネル実験は一切行わていない。mceliece348864 の全パラメータセットに基づくスケーリング分析では、パッキング行列、255 KB の公開鍵、プロセッサのストレージを目標デバイスの約 496 KB のブロックストレージに同時に収めることはできず、トイレベルのアクセラレーションブロックは単純な拡大ではなく再設計が必要であることが示された。

1. オープンソースコミュニティとソフトウェアエコシステム

openRuyi 1 日 20 コミット：vkpeak をリポジトリに追加、clang-wrap を追随、KDE Frameworks 6.31.0 を一括アップグレード（10-29）

20 コミットは 3 つの塊に分かれる。最大の塊は 13 個の kf6-* パッケージを KDE Frameworks 6.31.0 へ同期するもので、kio、kwallet、ksvg、prison、kguiaddons、threadweaver、syntax-highlighting、syndication、sonnet、solid、qqc2-desktop-style、purpose、networkmanager-qt をカバーする。第 2 の塊は新規の vkpeak パッケージ（上流 20260527 版）の追加で、これは合成型の Vulkan デバイスピーク性能ベンチマークであり、fp32／fp16／fp64 および int8 から int64、bf16、fp8 のベクトル・行列演算ピークを測定し、vulkan-headers と vulkan-loader に依存し、SPEC はソフトウェア研究所のメンテナがコミットした。第 3 の塊はビルドチェーンのメンテナンスで、clang-wrap を 20261029 に更新し、ecbuild は cmake モジュールをマルチアーキテクチャのライブラリディレクトリへ移設し、3 つの Go エコシステムパッケージの依存関係とビルドサポートを修正し、さらに重複パッケージ go-github-smartystreets-assertions を削除した。

vkpeak のリポジトリ追加の実際の意義は計測基準にある。RISC-V プラットフォーム上の Vulkan デバイスにはこれまで統一的なピーク演算性能の対照ツールが存在しなかったが、今では x86、Arm ボードと直接横比較できる。公式サイトのニュースページの最新リリースは依然 2026.09 版であり、10 月版は未リリースのため、この 20 コミットはリリースに向けた追い込みではなくローリングメンテナンスに属する。

日付：2026-10-29　情報源：openRuyi コミット記録、vkpeak SPEC

香山 difftest 3 コミット：MMA 書き戻しにプールバッファを再利用、gsim が FST 波形をサポート（10-29）

3 コミットはいずれも検証効率を指向する。第 1014 号は MMA 書き戻しを「命令ごとに物理結果バッファを丸ごと確保してゼロクリアする」方式から、有界プールからの再利用へ変更し、プールが満杯の場合は通常の確保にフォールバックする。新規の MatrixResult は結果の所有権をソフトウェア ROB から非同期検証へ移譲し、そのデリータがプール化ストレージの返却または通常配列の解放を担い、共有プールのライフサイクルが未完了の結果を常に有効に保ち、リタイア・リプレイ・デストラクトの各パスは RAII で締めくくられる。第 1013 号は CPU と CUDA 両側の MMA パスにおける物理レジスタレイアウトの忠実性問題を修正する。第 867 号は gsim に FST 波形出力を追加し、シミュレーション波形を直接通常のビューアツールへ接続できるようにする。

日付：2026-10-29　情報源：difftest #1014、#1013、#867

RISC-V ロボットスタックは当日コミットゼロ：spacemit-robotics の4リポジトリは前日で停止（10-29）

spacemit-robotics の humanoid_common、control_whole_body、unitree-go2、peripherals-imu の4リポジトリは調査期間内にコミットゼロで、最新コミットはいずれも10-28で停止している。前日の10件の実質的コミットには、運動アダプタとオペレータクライアントの接続、全身制御の表格化結合、Go2 の地形のみ V2 戦略への切り替え、IMU の第3社シリアルプロトコルへの拡張が含まれていた。単日の途絶は通常のペースであり、方向性判断の根拠にはならないが、「バッチミラー同期」とは区別する必要がある——昨日の判定は実質的開発であり、今日は更新停止である。

日付：2026-10-29　情報源：spacemit-robotics

5. まとめとトレンド観察

1. ポスト量子暗号の着地点は「命令セットの境界をどう切るか」であり、「大きな演算をより速く計算する」ことではない。 本日の論文は照合可能なデータで選定マップを示した：Berlekamp-Massey と Chien 探索は単位ロジックあたりのサイクル收益が最も高く、いずれも1,000個の適応ルックアップテーブル以内でほぼ1つのサブオペレーションをオフにできる；ストリーミング公開鍵生成は4,705個の適応ルックアップテーブルを占有し、デバイス側で鍵を生成する必要がある場合にのみ価値がある；却下された DMA 版 composeinv は、呼び出し構造がデータ転送コストを支配する場合、バッチカーネルの加速は無効であることを示している。この判断基準は「ベンチマークが何倍向上したか」よりも実用的であり、RISC-V カスタム命令拡張を行う国内チームに直接活用できる。

2. 検証インフラは引き続き「リソースプール化 + トリミング可能」へ進む。 difftest は MMA 結果をバッファプール化し、逐条割り当てを所有権移譲で置き換え、香山 CI の perf フローは difftest をオフにできるようになった。二つの変更の方向性は一致している——検証を予算として管理し、必ず全開にしなければならないコストとは見なさない。XSCache のポーリングアービトレーションが修正したのは餓死系の欠陥であり、長期的な安定性の問題に属し、前二件と同じく「まずインフラが足を引っ張らないようにする」ものだ。

3. openRuyi は「計測可能」という層を補っている。 vkpeak のリポジトリ投入後、RISC-V ボード上の Vulkan ピーク演算性能に統一された基準ができ、x86、Arm と直接横比較できるようになった。clang-wrap と KDE フレームワークの継続的なフォローはローリングディストリビューションのペースが安定していることを示す。ただし公式サイトのニュースページの最新は依然として 2026.09 版で、10 月版は未リリースであり、今期の 20 件はフレームワークとエコシステムパッケージが中心で、リリース前の集中的な追い込みではない。

4. 国内側は空白期間に入り、しかも空白は開発面に現れており納品面ではない。 玄鉄、奕斯偉、芯来は調査期間内に新規開発ゼロ、進迭時空は docs-product の二件のドキュメントコミットのみで、ロボティクススタックの四リポジトリは更新停止、算能は一行の性能データのみ。これと並行して、達摩院の具身チームでは二ヶ月以内に三度目の主要人事異動があった——この項目は RISC-V と直接の技術的関連はないが、具身知能の人材と資本が大企業プラットフォームから Physical RSI 方向のスタートアップへ流出していることを反映しており、国内 RISC-V ロボティクスソフトウェアスタックの主要供給元はまさにこうしたチームの外部協力者であるため、人事流動が今後のロードマップに与える影響は追跡に値する。

5. 今期の情報量と判定根拠。 中英文 Google News の二十六組のクエリを調査期間内で重複排除した結果、実質的な新規はポスト量子論文、Tenstorrent のインド現地化報道、達摩院の人事の三件のみであった。次元の、ブラウザ系とコンシューマエレクトロニクス系の項目（XHEART X7 Ultra、LattePanda Sigma 2、BeagleConnect QuadESC）は検証の結果それぞれ Armv9、Intel、TI の方案を使用しており、RISC-V とは無関係であるため除外した。オープンソース側は依然として今期の主体である：openRuyi の 20 件、香山の 6 件、CORE-V の 4 件、算能の 1 件はいずれも照合可能なコミット記録がある。GitHub の組織レベル API の匿名制限が今期の収集後半で枯渇したため、コミット取得に切り替えた。そのため楽鑫、矽速などの組織の全量プッシュはリポジトリごとに展開できなかった。

制限事項の説明

GitHub の組織レベル API の匿名制限が今期の収集後半で枯渇し、Espressif、矽速、revyos、OpenHW などの組織の全量プッシュリストをリポジトリごとに展開できなかったため、リポジトリのコミットフィードで代替した。そのため、これらの組織に非重点リポジトリの調査期間内の活動があっても漏れる可能性がある。香山と openRuyi の重点リポジトリはコミットフィードで逐一照合済みであり、結論は影響を受けない。会員企業の公式サイト巡回では、67 社がアンチクロール、リニューアル、またはファーストビューの内容が短すぎるため本文を取得できず、その公式サイトの動向は今期の判断に含めていない。第 6 回 RISC-V 中国サミットは 10-20 に終了しており、公式サイトとソースコードリポジトリの変更確認は今期から停止する。
