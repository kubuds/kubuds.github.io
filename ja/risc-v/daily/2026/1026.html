今日の重点：Claude が形式検証を RISC-V マシンコードまで押し上げ、123 のオープンソースライブラリで 1.8 億行の証明を獲得

日付：2026-10-23　出典：36氪：Claude が 1.8 億行の証明を狂ったように書き、万億回のテストで漏れた Bug を AI が一網打尽（10-25）、騰訊新聞（新智元）：Claude が 1.8 億行の証明を狂ったように書く（10-23）、搜狐（DoNews）：Claude が 1.8 億行の数学的証明を産出（10-23）

Anthropic フロンティアレッドチームが Theorem Labs と共同で報告書を発表：Claude に Google OSS-Fuzz コーパス内の 123 のオープンソースコードベース、239 のテストエントリに対して形式検証を実施させた。証明の対象はソースコードではなく、コンパイル後に実際に CPU 上で動作する RISC-V マシンコードである。

  • 規模とコスト：プロジェクトは累計約 10 億行の証明を生成し、うち 1.8 億行が Rocq 証明チェッカーで検証された。1 件の証明のマシン検証には 30 分から数時間かかる。cJSON の 391 行の C パーサーエントリには 63 万行の証明が付随する——プロセス起動、メモリアロケータ、printf とランタイムを併せて証明する必要があり、ビジネスに直接関連する部分は 10 分の 1 に過ぎないためである。
  • 検出能力：研究チームは自作の Rust 版 Python インタプリタに 7 つの Bug を事前に埋め込み、ランダムテストでは 5 つが見逃されたが、形式検証ではすべて検出された。一部の脆弱性は約 20MB の希少な入力でのみトリガーされ、ファジングテストではカバーしにくいパスに属する。
  • 進捗とコスト：Theorem は 2026 年 5 月から 9 月にリリースされた 7 つのフロンティアモデルをテストし、検証速度は約2 ヶ月ごとに倍増した。現在の単価で試算すると、1.34 億ドルの投入で 2027 年末までに Nix エコシステムの 95% のマシンコードをカバーでき、下流の単一ソフトウェアパッケージあたり約 14 ドルに均攤される。
  • 波及効果：zlib の対照実験のため、Claude は x86 命令セットの数学モデルを自律的に書き上げ、モデル内で Ubuntu ユーザーランドの起動をシングルステップで推演でき、その過程で x86 公式リファレンスドキュメントの数百箇所の誤りと少数の CPU ハードウェア欠陥を発見した。首批 25 のライブラリ、60 のエントリの証明はすでにオープンソース化されている。

RISC-V にとって、このニュースの重みは検証対象のレイヤーにある。これまでマシンコードレベルの形式検証は seL4 のようなプロジェクトにしか存在しなかった（エンコード2人年、検証20人年）。コストがそれを通常のオープンソースリポジトリに入れさせなかった。今回は単位コストを薄く攤分できる水準まで抑え、かつ証明の一式を Theorem で書かれた RISC-V 命令と Linux プロセス動作の数学モデルの上に構築しており、RISC-V エコシステムに再利用可能なセマンティクス基盤を残したことに等しい。抑制すべきは、証明が現在シングルスレッド、静的リンク、固定メモリ予算に限定されており、モデルと実ハードウェアの対応はなお人手による審査が必要で、チェッカーは証明が仕様に適合することのみを保証し、仕様が要件に適合することは保証しない点である。

1. オープンソースコミュニティとソフトウェアエコシステム

1.1 openRuyi：20件のコミット、Go サーバーサイドソフトウェアパッケージを一括登録

日付：2026-10-23　情報源：openRuyi メインリポジトリのコミット記録（10-23）、openRuyi 公式サイトニュースページ

openRuyi メインリポジトリは調査期間内に20件のコミットを記録し、すべて SPECS ディレクトリにあり、内容は一色に Go 言語の新規ソフトウェアパッケージ追加である。

  • Web フレームワーク依存チェーン：gobuffalo シリーズの packr、packd、logger、envy、および emicklei の go-restful を補完——これは Go サーバーサイドで最も一般的なルーティングとパッケージングの組み合わせである。
  • コンテナとデータベースドライバ：docker の libtrust、spdystream、gopkg の gorp v1、ziutek の mymysql、denisenkom の go-mssqldb、jaypipes の pcidb、howett の plist、golang-sql の civil。
  • 前回との接続：2026.09 バージョンで Go ビルド環境を1.27に上げたばかりであり、この一連のパッケージは「ツールチェーンが利用可能」から「アプリケーション依存が揃った」へと進めるものに等しい。公式サイトニュースページの最新告知は依然 2026.09 バージョンであり、調査期間内に新バージョンのリリースはない。

これら20件のコミットが指し示すのは同一の事柄である。RISC-V ディストリビューションが引き受けるべきサーバーサイド負荷のうち、Go で書かれたクラウドネイティブコンポーネントの割合は極めて高く、Go エコシステムの痛点は決してコンパイラではなく、誰も代わりにビルドしてくれないサードパーティパッケージにある。mysql、mssql ドライバや docker の低層ライブラリを一つずつ補完していくことは、典型的な「バージョンをリリースしないが可用性を決定する」作業に属する。

1.2 香山：NEMU が2つのタグを連続発行、difftest が Tensor Cores で MMA 比較を実行

日付：2026-10-23　情報源：NEMU リリース記録（10-23、10-24）、difftest コミット記録（10-23 から 10-25）、XiangShan コミット記録（10-23）

香山プロジェクトは調査期間内に3つの路線を同時に推進した。参照モデル、差分検証フレームワーク、プロセッサ本体である。

  • NEMU：10-23 と 10-24 に連続してv2026.10.r8、v2026.10.r9の2つのタグをリリースし、「difftest が参照実行を高速共有することをサポート」する改造（#1247）を合わせ、Copilot レビューワークフローを CI から削除した（#1260）。
  • difftest：調査期間内に9件のコミット、うち6件は MMA 検証の CUDA 性能最適化に集中——フォーマット別特化浮動小数点カーネル（#1000）、Tensor Coresで INT8 比較を実行（#1001）、ネイティブビット幅のオペランドロードへの変更（#1002）、冗長なオペランドと DUT 結果コピーの除去（#996、#999）。他に高速参照と fork チェック（#980）、並行レジスタ書き込みのハッシュ（#991）、そして BOOM の DiffTest 接続をドキュメントに書き込む（#995）。
  • プロセッサ本体：昆明湖 V3 ブランチに3件、StoreUnit がポインタマスク後のアドレスを報告する修正（#6742）、チェックポイント更新（#6756）、シミュレーション環境変数の CI 統一（#6701）を含む。

真の変化は difftest にある。行列拡張の参照モデルを GPU 上に移して Tensor Cores で実行するということは、差分検証のボトルネックがすでに「モデルが書けない」から「比較スループットが足りない」へと変わったことを意味する。検証インフラが性能最適化を始める時、通常は検証対象のコアがすでにサイクルごとのシミュレーションでは走らなくなるほど複雑になったことを意味している。

1.3 CVA6 の master が読み取り専用に、CVW が Sail 0.16 をマージ

日付：2026-10-23　情報源：cva6 コミット記録（10-23）、cvw コミット記録（10-23）

OpenHW の二つの中核プロジェクトは、調査期間内にそれぞれガバナンスまたはモデル層の変更を一件ずつ行った。

  • CVA6：master ブランチにコミット #3664 をマージ。タイトルは「Note: master made read-only」。このブランチの直前のコードコミットは 09-15 で、その後一ヶ月間は業務上の変更がなく、今回直接読み取り専用と明記されたが、デフォルトブランチ名はまだ切り替えられていない。
  • CVW：PR #1995 をマージし、Sail モデルを 0.16 にアップグレード。CVW は Sail を用いて RISC-V のゴールデンリファレンスモデルを維持しており、バージョンの追随は命令語義のリファレンス実装が上流仕様と同期を保つことを意味する。

二つの事象を合わせて見ると、同じ方向への二種類の動きである。一方ではメインブランチを凍結してブランチ戦略の調整のための場所を空け（移行案はまだ告知されていない）、もう一方では ISA リファレンスモデルを前進させている。CVA6 を採用するチームにとっては、短期的にコードベースの移行先を確認する必要があり、形式化および差分検証を行うチームにとっては、Sail 0.16 はコア自体よりも追随する価値のある更新である。

2. 製品・エコシステム動向

2.1 Tenstorrent、Chiplet 設計フレームワーク OCA Harness のベータ版を公開

日付：2026-10-23　情報源：Unite.AI：Tenstorrent Opens OCA Chiplet Harness Beta Under Apache 2.0（10-23）、GitHub：tenstorrent/tt-oca-harness

Tenstorrent は 10-22 に Open Chiplet Atlas（OCA）Harness のオープンソースベータ版を公開し、OCA の相互運用アーキテクチャを再利用可能かつデプロイ可能な実装へと変えた。

  • ライセンス：コードは Apache 2.0、ドキュメントと画像は CC-BY-4.0、コントリビューションも同様に Apache 2.0 で受け入れる。正式版の目標は 2027 年 1 月。
  • 三層構造：Architecture は chiplet の物理、伝送、プロトコル、システム、ソフトウェアの五層における相互運用を定義する。Harness は chiplet に必要な「アプリケーション以外のロジック」をすべて提供し、設計側が付加価値部分のみを書けるようにする。Compliance はシリコン前検証とシリコン後確認を担い、Golden Chiplet の概念とコミュニティ plugfest を含む。
  • 位置づけ：ベータ版は早期採用者、インテグレータ、コントリビュータ向けで、リポジトリはすでに tenstorrent 組織下で公開されている。

Tenstorrent は RISC-V 陣営において、「オープン」を命令セットからパッケージングと相互接続へと延伸させている数少ないベンダーである。Chiplet の現実的な障壁は、できるかどうかではなく、各社の die-to-die インターフェースが互いに認め合わないことにある。アプリケーション以外のロジックをオープンソースの足場とする実質は、相互運用コストを各設計チームからコミュニティへ移すことにある。マルチダイ方案に取り組む国産チームにとって、これは直接照合できる参考実装の一つである。

2.2 LILYGO T-Halow P4：ESP32-P4 と C6 のデュアル RISC-V コアを搭載した M.2 ボード

日付：2026-10-23　情報源：CNX Software：LILYGO T-Halow P4（10-23）、GitHub：Xinyuan-LilyGO/T-Halow-P4

LILYGO は T-Halow P4 を発表した。80 × 22mm の M.2 2280 開発ボードで、Wi-Fi HaLow 長距離リンクを標準 M.2 フォームファクタに組み込んでいる。

  • メインコントローラ：Espressif ESP32-P4NRW32X、デュアルコア RISC-V 400MHz（AI 命令拡張と単精度 FPU 付き）に加え、40MHz の低消費電力 RISC-V コアを1基；2D PPA、H.264 および JPEG エンコード／デコード、MIPI CSI と DSI を各1路、最大 1080p30 のハードウェアエンコード。
  • 無線：ESP32-C6-MINI-1U が Wi-Fi 6、Bluetooth 5 および 802.15.4（Zigbee／Thread／Matter）を提供し、SDIO 経由で P4 に接続；さらに泰芯 TX-AH モジュールを搭載して 802.11ah HaLow を実現、859–894MHz または 902–928MHz の2種帯域、1–8MHz チャネル、150Kbps から 32.5Mbps、見通し線最大 1.2km。
  • 価格と開発：公式ストア 26.57 ドルから（915MHz 版 31.07 ドル）、AliExpress では 36.98 ドル；サンプルは ESP-IDF 5.4.1 以上に基づき、HaLow は SPI でデータを伝送し、UART で AT コマンドを受信、ほかにブラウザ側の設定ツールも用意。

M.2 形態はこのボードの最も実用的な点である。もはや「配線が必要な開発ボード」ではなく、既製のキャリアボードに挿し込める通信モジュールとなっている。ESP32-P4 が演算力と映像経路を補い、C6 が Wi-Fi 6 と Matter を補い、TX-AH がキロメートル級の低消費電力リンクを補う。3つのチップの役割分担は明確で、まさに配線が最も難しい産業モニタリングと遠隔カメラという2類のシナリオに対応している。

3. 国内チームの深掘り

3.1 優智創芯が約1億元の Pre-A ラウンドを完了、「全贏芯」RISC-V GPGPU プロジェクトが長沙金霞に着地

日付：2026-10-22　情報源：掌上長沙（長沙晩報）：一つの「芯」、なぜ長沙を選ぶのか？（10-22）

長沙晩報の10月22日の報道によると、清華系の類脳智能企業長沙優智創芯科技有限公司が約1億元の Pre-A ラウンドを完了した。力匯基金が長沙投資控股集団、金霞盛世基金と共同で組成した専項基金・力優創投がリードし、既存株主の啟賦資本がフォローオンした。同社は同時に、孵化した「全贏芯」RISC-V GPGPU プロジェクトを長沙金霞経済開発区に着地させた。

  • 技術の源流：優智創芯は清華大学集積回路学院准教授の何虎氏が率い、SNNGrow 類脳仿真トレーニングフレームワークと CLAS 因果学習アルゴリズムを保有する。「全贏芯」の技術源流は、上海清華国際創新中心集積回路研究プラットフォームが2022年に打ち出した国内初のオープンソース RISC-V ベクトル拡張 GPGPU「Ventus（乗影）」に遡ることができ、指令セット、アーキテクチャ、エコシステムの三重の自主路線をとる。

3.5 算能 zsbl を eboot フレームワークへ再構築、外部デバイスツリーとアプリケーションツリーをサポート

日付：2026-10-23　情報源：sophgo/zsbl コミット記録（10-23）

5. 総括とトレンド観察

  • 形式検証の敷居は下がっており、RISC-V は最初の受益者である：証明は直接 RISC-V マシンコード上で行い、付随する RISC-V 命令とプロセス挙動モデルは再利用できる。単位コストを償却可能な水準まで圧縮できて初めて、セキュリティ認証や高保証ソフトウェアの採算が取れるようになる。自制すべき点は、現状依然としてシングルスレッド、静的リンク、固定メモリ予算に限定されていることだ。
  • ディストリビューションの補完は「言語ランタイム」から「アプリケーション依存」へ移行：openRuyi の今回は20件すべてが Go パッケージで、2026.09 バージョンで Go ビルド環境を1.27に引き上げたことと連動している。RISC-V サーバーが実際の業務を担えるかどうかは、ますますこの種のバージョン番号を持たないパッケージング作業にかかっている。
  • 検証インフラがスループット最適化に着手：香山 difftest は1週間で6件の MMA／CUDA 最適化を行い、参照モデルを Tensor Cores 上で走らせた。差分検証は「比較できる」段階から「速く比較できる」段階に入っており、検証対象のコアがサイクル単位のシミュレーションでは回らないほど複雑化したことを示している。
  • オープンソースコアはガバナンス調整期に入る：CVA6 は master を凍結し、CVW は Sail 0.16 に追随した。一方はブランチ戦略移行の先行動作、もう一方は ISA 参照モデルのバージョン同期であり、いずれも「検証可能性」という共通目標を指し示している。
  • 国内チームの2つの拡張経路はいずれも「エコシステム」段階に到達：奕行智能はチップ量産、スーパーノード納品、そして如意コミュニティ共同構築へ。優智創芯は資金調達、実装、そして OpenCL オペレータライブラリ共同構築へ。ハードウェアは入場券にすぎず、ソフトウェアとコミュニティこそが彼らが本当に賭けている場所だ。
  • エッジ側のソフトウェア補完は演算能力よりも密集：進畳時空は今回新チップこそなかったが、Agent 記憶サブシステムと付随プラグインをオープンソース化し、記憶、権限、ツール呼び出しを製品境界として作り上げた。エンボディドインテリジェンス機器にとって、こうした「見えないミドルウェア」はピーク演算能力よりも早く制約となる。
  • 限界に関する説明：Anthropic と Theorem Labs の報告内容は36kr、新智元の二次報道による転述に基づくもので、原報告の全文は入手していない。x86 ドキュメントのエラーと CPU ハードウェア欠陥の規模はいずれも報告側の説明である。優智創芯の項目はユーザー指定キューと長沙晩報の報道によるもので、調達額、産値、演算能力のデータはいずれも報道側の説明である。奕行智能の「業界初の量産納品 RISC-V スーパーノード」と「投資後評価額約150億元」は同社およびメディアの説明であり、財務報告による裏付けは得られていない。合見工軟と睿思芯科の内容はメディアインタビューにおける取材対象者の見解であり、産業界のコンセンサスを代表するものではない。CVA6 の master 凍結後の具体的な移行方案はプロジェクト公告が見当たらず、今回はコミットタイトルのみに基づいて記述した。openRuyi、算能、進畳時空のコミット内容はコミットタイトルと README に基づく判断であり、パッチを逐条照合してはいない。会員公式サイトの巡回で検出された45件の変化はいずれも大学、機構、ベンダーのトップページの定例更新であり、実質的な製品、資金調達、アーキテクチャの発表は見つかっていない。CNX が報じた RoboParty RP1 ヒューマノイドロボットは検証の結果 RK3588、A733、Jetson Orin NX を採用しており、RISC-V 方案には該当しないため除外した。
