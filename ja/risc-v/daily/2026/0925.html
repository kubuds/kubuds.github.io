今日の重点：UPC 研究：玄鉄 C910 とオンチップ性能カウンタで RISC-V チップに「自己診断」させるマイクロアーキテクチャ攻撃、検出精度 99%

日付：2026-09-24　出典：Scienmag「Machine Learning Turns RISC-V Chips Into Their Own Hardware Attack Detectors」、論文：Pou, Otero, Robledo, Pajuelo & Canal, RISC-V hardware attack detection using on-chip hardware performance counters, Cybersecurity 9(1) Article 222、HARPY-V データセット（CORA 研究データリポジトリ）

9月24日、Scienmagはスペイン・カタルーニャ工科大学（UPC）チームの研究を報道した。研究者らは機械学習検出器をRISC-Vチップ自体のハードウェアパフォーマンスカウンタ（HPC）に「組み込み」、チップ内部でのマイクロアーキテクチャ攻撃のリアルタイム検出を実現した。論文はジャーナルCybersecurity（9(1) 第222篇）に掲載された。実験は実商用シリコン上で完了——達磨院玄鉄C910（64ビットアウトオブオーダーコア、RV64GCV）を矽速LicheePi 4A開発ボードに搭載し、Debian 13を実行。チームはデータセットHARPY-Vを構築・公開した：約6.4万件のラベル付きサンプル、16種類のマイクロアーキテクチャ攻撃（Flush+Reload、Flush+Flush、Evict+Reload、Spectre V1/V2/RSB、タイミングドリフト、TLBとページテーブルウォーク系攻撃、およびGhostWriteなど）と16個の良性プログラムを含み、良性セットは意図的に攻撃とハードウェア構造を共有する負荷を選定し、分類問題を真の難易度に近づけた。

結果とエンジニアリングの詳細：二元検出（攻撃／良性）精度は99%に達し、多クラス分類（具体的な攻撃タイプの識別）は約95%。「leave-one-attack-out」ゼロデイシミュレーションでは、ランダムフォレストとmRMR特徴選択の組み合わせ、決定木とRFECVの組み合わせが依然として高い検出率を維持し、「正しいカウンタを選ぶ」ことが「より多くのカウンタを積む」よりも重要であった。チームはさらに2つの貴重な実測経験を公開した：C910では、perfが複数のカウンタを同時に監視すると相互干渉が発生し（一部の読み値が3倍以上に増幅）、カウンタごとに個別に収集する必要がある。また、C910のperfイベント記述の大半は不正確であり、公式マニュアルのカウンタマッピングに従う必要がある。

意義と限界：これは商用RISC-Vシリコン（FPGAソフトコアやシミュレータではなく）をプラットフォームとし、再現可能なデータセットを公開したマイクロアーキテクチャ攻撃検出研究の初期のものの一つであり、「チップ自前のカウンタと軽量モデルによる能動的検出」はシリコン変更もカーネルパッチも不要な低コストな強化路線であり、RISC-Vオープンエコシステムのセキュリティナラティブと呼応する。同時に限界にも注意が必要——実験は単一コアモデルのみをカバーし、カウンタパターンはマイクロアーキテクチャと強く相関し、チップをまたぐには再トレーニングが必要。教師あり学習はラベル付き攻撃データに依存し、全く新しい攻撃タイプへの汎化はなお検証を要する。

2. 製品とエコシステムの動向

2.1 楽鑫 ESP32-S31 の Linux 移植が加熱：マイコンから SBC 形態へ

日付：2026-09-24　情報源：XDA「The newest ESP32 can actually run Linux, and it’s getting uncomfortably close to a Raspberry Pi」、CNX Software：ESP32-S31 Linux BSP 開発者プレビュー（08-22）

XDA は楽鑫 ESP32-S31 に関する特集を掲載：デュアルコア 32 ビット RISC-V メインコア（最大 320 MHz、別途 40 MHz 低消費電力コアを搭載）に加え、初めて Sv32 MMU を内蔵した ESP32 であり、ハードウェア面ではギガビットイーサネット MAC（RGMII）、USB 2.0 High-Speed OTG ホスト、デュアルスロット SDIO、DVP カメラ入力、パラレル LCD コントローラを備える——ペリフェラルの組み合わせは既に現代のシングルボードコンピュータに近い。公式は 8 月に Linux BSP 開発者プレビューをリリース済み（Buildroot 2025.02 + U-Boot + Linux 6.18 ブランチ、フルイメージは約 13.7MB）。コミュニティによる移植も同時進行中：GrieferPig による Linux 6.12 supervisor モード移植（利用可能メモリ約 15MB、CoreMark 約 1059）、および Linux 7.1 + OpenSBI 1.9 ベースで 800x480 LCD コンソールを駆動可能な別の移植がある。XDA の判断：S31 のペリフェラル、帯域幅、CPU 特権モデルはいずれも「SBC に接近」しているが、Linux サポートは依然として実験的性質であり、短期的には生産用途には推奨されない。

2.2 算能 BM1688 の新ボード OrangePi O1 が発表：16 TOPS TPU と RISC-V C906 コプロセッサを搭載

日付：2026-09-24　情報源：LinuxGizmos「16-TOPS AI SBC with SATA 3.0 runs on octa-core Sophgo BM1688」

LinuxGizmos は OrangePi O1 ボード（90×70mm）の詳細を掲載：算能（SOPHGO）BM1688 ビジョンコンピューティングプロセッサをベースとする——8 コア Arm Cortex-A53（最大 1.65GHz）に加え RISC-V C906 コプロセッサ（最大 1.2GHz）を搭載。内蔵 TPU は INT8 16 TOPS／INT4 32 TOPS／FP16-BF16 約 4 TFLOPS を提供し、Caffe、PyTorch、TensorFlow、ONNX、MXNet をサポート、エッジ側の大規模モデルおよびビジョンモデル推論を位置付けとする。ボード上の構成：8/16GB LPDDR4X、eMMC（16-128GB 選択可）、M.2 NVMe（PCIe 3.0）、SATA 3.0、デュアルギガビットネットポート、Wi-Fi 6E／Bluetooth 5.3、オプションの 4G/5G モジュール、HDMI 2.0 4K60、デュアル MIPI-CSI と 6 系統のビデオ入力。16 系統の 1080p30 デコードをサポート。BM1688 に内蔵された RISC-V C906 コプロセッサは、Arm をメインコアとするこのエッジ AI チップの「RISC-V 内芯」であり、国産 RISC-V ベンダーによるマルチコア異種 AI チップ路線の典型的な一形態でもある。

日付：2026-09-24　情報源：Linkr v1.5.0 リリースノート

Radxa Linkr が v1.5.0 をリリース：プラグインセンター（プラグインのアップロード、インストール、有効化、無効化、アンインストールのワンストップ管理）を新規追加；ネットワーク構築向けに ZeroTier と EasyTier のネットワークプラグイン（ネットワークへの参加、ネットワーク情報の表示、ネットワークからの退出）を新規追加；スクリーンショットのウォーターマークはサイズに応じて自動調整され、スクリーンショット OCR テキスト認識に対応。Linkr は Radxa が開発ボードと NAS 向けに提供するブラウザベースのリモート管理製品ラインであり、9 月から本デイリーレポートの定例チェック範囲に組み込まれており、今回は調査期間内のメジャーバージョン更新である。

3. 国内チームの深掘り

3.1 進畳時空：llama.cpp ブランチが v0.2.0 をリリース、独立した ggml-spacemit バックエンドが登場

日付：2026-09-24　情報源：spacemit-com/llama.cpp v0.2.0 リリースノート

進畳時空の llama.cpp ブランチが v0.2.0 をリリース：中核となる変更は独立した ggml-spacemit バックエンドの導入（ビルドパラメータ -DGGML_SPACEMIT=ON）——単一のメインスレッドから spine runtime にタスクをコミットし、ランタイムがワーカースレッドを派生させるため、スレッドパラメータ -t は常に 1 に設定される；計算コアは環境変数 SPACEMIT_PERFER_CORE_ID により物理コア ID リスト（例えば 8 から 15 コア）で指定し、モデルは –device SPACEMIT0 で配置され、llama-cli／llama-bench／llama-server はいずれもこの方式でスケジューリングされる。サーバー側はマルチチャネル ASR 機能を継続：smt メディアバックエンドと組み合わせて音声リクエストを並行処理できる（例えば -np 4 に 6 コアを組み合わせる）。このブランチは v0.1.7 の MTMD リファクタリング以降も継続的に進化しており、今回「バックエンドの独立化」を実現したことは、進畳時空の推論スタックがモジュール化へと邁進する象徴的なバージョンである。

4.2 カリフォルニア大学バークレー校が IISWC 2026 チュートリアルを公開：ヘテロジニアス RISC-V SoC 上の ML とロボティクス負荷

日付：2026-09-24　情報源：ucb-bar/IISWC-tutorial-2026-RISCV-ML-Robotics

カリフォルニア大学バークレー校（ucb-bar）が IISWC 2026 チュートリアルのマイクロサイトリポジトリを公開：《Building, Tracing, and Optimizing End-to-End ML and Robotic Workloads on Heterogeneous RISC-V SoCs with a Lightweight Zephyr Runtime》——ヘテロジニアス RISC-V SoC 上で軽量 Zephyr ランタイムを用いてエンドツーエンドの機械学習とロボティクス負荷を構築、追跡、最適化することを中心に据えている。チュートリアルは「ロボティクス負荷の方法論」（構築、追跡、最適化）を独立した議題として組織しており、学術側の RISC-V ロボティクスと ML ワークロードに関する研究が体系化しつつあることを示している。

5. まとめとトレンド観察

  • セキュリティ研究は「再現可能」段階へ：UPC が玄鉄 C910 商用コアと公開データセットでマイクロアーキテクチャ攻撃検出研究を完了し、RISC-V セキュリティの語りは「単点脆弱性の開示（GhostWrite 等）」から「定量検出とデータセット共有」へと進展；国産コアにとって、実験プラットフォームとして選ばれたことは注目度向上の表れであると同時に、商用シリコンには能動的な検出方案が必要であることを示唆している。
  • エッジ AI のソフト・ハード同時補強：ESP32-S31 の Linux 化試み、BM1688 新ボード、進迭時空 llama.cpp v0.2.0 と楽鑫 esp-vision は、共通してエッジ推論が「動く」から「快適に動く」へのエンジニアリング段階に向かっていることを示す；RISC-V は MCU からエッジボックスまでの形態的境界を引き続き拡大している。
  • オープンソースコミュニティの二軸リズム：香山は複数ブランチでベクトル、予測、キャッシュのマイクロアーキテクチャ調整を並行して推進し、開発密度は高い水準を維持；openRuyi は今週、セキュリティ更新とパッケージング規範が中心で、2026.09 リリースウィンドウを待っている。
  • 具身知能の階層的推進：霊龍が SONIC 運動追跡ポリシーをマージした後、ロボットソフトウェアスタックは「ランタイムインターフェース、ポリシー資産、シミュレーション閉ループ」の 3 層で継続的に蓄積；IISWC チュートリアルなどの学術活動と組み合わせ、RISC-V ロボティクス負荷の方法論構築が産業と学術の両側で同時に展開している。
  • 観察点：openRuyi 2026.09 がリリースされるか；ESP32-S31 公式 Linux BSP が開発者プレビューから正式版へ移行するリズム；進迭時空 ggml-spacemit バックエンドのアップストリーム化動向。
