1. オープンソースコミュニティとカーネル/リリース動向

1.1 HAC 高保証暗号仕様、4日目に集中改訂：Zl→Zkl 改名提案、WARL ルール、Smacestatus 統合（30件以上）

日付：2026-08-18（12:05 ~ 22:26 北京時間）　出典：riscv/riscv-high-assurance-cryptography GitHub

高保証暗号（HAC、FIPS 140-3 レベル実装向けの暗号拡張仕様）リポジトリは、調査期間内に30件以上のコミットをマージし、直前3日間のレビュー収束という主線を継続するとともに、「命名と構造の最終調整」段階に入った：

  • 命名の確定：Changed Zl extension prefix to Zkl（Zl プレフィックスを Zkl に改名）、Added proposal for ratified names（批准名の提案）、Fixed Zlkn dependencies、Reformatted new names table——拡張の命名が作業名から批准名へ移行；
  • 意味論の確定：Defined WARL rules for aceiobuflen, aceiobuftop and acestart（3つの重要 CSR の WARL ルール）、Clarify invalid aceiobuftop exception behavior（不正な aceiobuftop 例外の挙動）、Integrate mcrstatus CSR into Smacestatus extension（mcrstatus を Smacestatus 拡張に統合）、Clarify vector I/O replacement rules、Default CSR values out of reset（リセット時のデフォルト値）；
  • ドキュメント構造の再編：pseudocode 例を Book 4 へ移動、有限体演算の定義を移動、ace-introduction の連続複数コミット改訂。

4日間連続で合計80件以上の改訂となり、HAC が「機能定義」から「命名凍結＋意味論の最終調整」段階へ進んでいることを示しており、正式レビュー/批准に一歩近づいた。今週の RISC-V 公式セキュリティ/暗号の主線（Spectre 論文、SPMP、riscv-security-model）と完全に同じ方向である。

日付：2026-08-18 21:18（北京時間）　情報源：riscv/riscv-isa-manual GitHub

2. 製品とエコシステムの動向

2.1 トップニュース：達摩院玄鉄が XuanTie C950 で Qwen-3.8 27B のネイティブ実行を公式発表——RISC-V 大規模モデル推論の「Day 0」の瞬間

日付：2026-08-18（Wccftech が 08-19 00:10 北京時間に報道）　情報源：Wccftech

Alibaba 達摩院玄鉄（T-Head Xuantie RISC-V チーム）は、そのフラッグシップ RISC-V チップ XuanTie C950 が最新のオープンソースモデル Qwen-3.8 27B に対して Day 0（リリース即時サポート） のネイティブ推論サポートを提供すると公式発表した。具体的な指標は次のとおり：64コア C950（RVV ベクトル拡張付き）でデコード速度 30 tokens/s、初回トークン遅延（TTFT）わずか 1.9 秒。要点：

  • チップの背景：C950 は 2026 年 3 月にリリースされ、「エッジ AI 向けサーバー級 RISC-V プロセッサ」と位置付けられる——単一チップに 64 の計算コア、最高周波数 3.20 GHz、GPU に依存せず AI ワークロードを実行する；標準 L1、柔軟に構成可能な L2、オプションの共有 L3 を備え、ハードウェアレベルのインテリジェントデータプリフェッチを搭載。TSMC 5nm 製造（Wccftech による）。
  • モデルの背景：Qwen-3.8 27B は 270 億パラメータのオープンソース重みモデルで、公式はコーディング能力が Opus 4.5 に匹敵すると述べ、単一の MacBook（32GB メモリ）上で実行可能——「中規模・高コストパフォーマンス」の推論モデルに属する。
  • 戦略的意義：これは Alibaba の「NVIDIA 類似の垂直統合」戦略のさらなる一手である——自社開発チップが自社開発モデルに対して Day 0 最適化を行い、「モデル-チップ-クラウド」の閉ループを形成する；C950 は同社のデータセンター AI アクセラレータと組み合わせて推論負荷を分担できる。

これは2026年のRISC-V陣営にとって「端末側/エッジ大規模モデル推論」方向で最も象徴的な進展の一つである。これまでのRISC-V大規模モデルのデモは小規模モデルや量子化蒸留にとどまることが多かったが、C950は64コアRVV上で27B級モデルを動作させ実用的なスループットを達成し、RISC-Vのマルチコア+ベクトル拡張路線が推論シーンで実現可能であることを検証した（詳細は3.1 達摩院玄鉄の深掘りを参照）。

2.2 Xenプロジェクトが安全委員会を設立（AMD/EPAM/Renesasが創設メンバー）、RISC-V完全リリースを推進

日付：2026-08-18 10:59（北京時間）　情報源：The Register

オープンソースHypervisorのXenプロジェクトがSafety Committee（安全委員会）を設立し、創設貢献メンバーはAMD、EPAM、Renesasである。目標はXenをIEC-61508などの機能安全正式標準に適合させること——自動車、ロボットなどのワークロード分離シーン（「ロボットの頭脳のパーティション化」）を対象とする。同時に、機能安全認証を求める組織向けに新たなPremier Plus会員層を設けた。ボーイング（Boeing）は最近Xenプロジェクトに参加し、The Registerの取材によればその関心はまさに安全業務にある。RISC-Vとの関連：Xenが月初に発表したアップデートは「RISC-Vプロセッサ向けの完全機能リリースに向けた作業を推進した」——Xen on RISC-Vは完全な実用化にさらに一歩近づいた。仮想化レイヤーの機能安全（分離、パーティション化、認証）はRISC-Vの自動車/ロボットへの実装と直接関連し、追跡に値する。

4. 重点方向専章：Embodied AI とロボティクス

4.1 安全仮想化の参入：Xen 安全委員会が「ロボットワークロード分離」を狙う

Xen プロジェクトは安全委員会（AMD/EPAM/Renesas が創設メンバー）を設立し、IEC-61508 準拠を推進しており、「ロボット」をワークロード分離の対象シナリオとして明確に位置付けている——「パーティション化されたロボットの頭脳」とは、リアルタイム制御、ナビゲーション、知覚などの混在クリティカルワークロードを同一ハードウェア上で分離実行することが認証可能なパスになることを意味する。RISC-V エンボディドインテリジェンスにとっての意義：Xen の RISC-V サポートは現在「完全機能リリース」を推進中であり、自動車/ロボット分野の安全認証仮想化レイヤが RISC-V 上で実現すれば、「リアルタイムコア＋アプリケーションコア」のデュアルコア異種構成（滴水湖フォーラムのロードマップ）に次ぐ第三の分離形態——仮想マシンレベルのパーティション——を補完することになる。Renesas（車載 MCU の主力）＋ AMD という組み合わせは、同委員会のマルチアーキテクチャ志向を示唆している。

4.2 C950 が 27B モデルを実行：RISC-V エッジ大規模モデル推論のエンボディドインテリジェンス潜在力

C950（64 コア RVV、3.2 GHz、30 tok/s）は、RISC-V のマルチコア＋ベクトル路線が 27B 級モデル推論において実用可能であることを検証した。エンボディドインテリジェンスにとって、端側/エッジ大規模モデル推論は「頭脳の上方移行」の鍵となる環節である——VLA（視覚-言語-動作）モデルが RISC-V プラットフォームで実用可能なスループットに達すれば、機体全体の GPU 依存を低減できる。C950 は現在エッジサーバ向けであり組込み向けではない（消費電力/体積の面でロボット本体への搭載にはまだ距離がある）ものの、「RISC-V で大規模モデルを動かす」ことがデモから製品へ向かう象徴的な一歩であり、後続の中規模チップへの展開にベースラインデータを提供する（30 tok/s / 1.9s TTFT は同類ソリューションの参照系となり得る）。

4.3 進迭「知覚-意思決定-運動制御」スタックの更新

model-zoo-vision に DEIMv2 COCO 検出器を新規追加（リアルタイム検出方向）、model_zoo_rl の Eigen ビルド修正がメインブランチにマージ——進迭時空の K3 humanoid RL ランタイムと視覚モデルライブラリは今週も二本立てで推進されており、その「知覚（vision）-意思決定（RL）-運動制御（SPERT NPU）」という三層布局と一致している。ペースは「メンテナンス＋増分」段階であり、重大な新規リリースはない。

5. 総括とトレンド観察

  1. ニュース側で唯一の重要案件：達摩院玄鉄 C950 が Qwen-3.8 27B をネイティブ実行（64 コア RVV、30 tok/s、TTFT 1.9s、Day 0 サポート）——RISC-V の大規模モデル推論方向における最も実際的な進展の一つであり、「チップ-モデル」垂直統合の物語が落地；同日 zero_stage_boot が C920V5 サポートをマージし、達摩院玄鉄の今週の重心は明確である。
  2. HAC 仕様は第四日目に集中的な改訂（30+ 件）を行い、名称凍結段階へ：Zl→Zkl 改名提案、WARL ルール、Smacestatus 統合——正式レビューにさらに一歩近づき、RISC-V 公式の安全/暗号メインラインは継続的に強化されている。
  3. 安全と仮想化の交差が加熱：Xen の安全委員会設立（AMD/EPAM/Renesas、IEC-61508、ロボットパーティション）＋ riscv-isa-manual のポインタマスク明確化 ＋ riscv-security-model の更新——「機能安全認証」が RISC-V エコシステム（自動車/ロボット/仮想化）の次の競争焦点となりつつある。
  4. 香山メインブランチが二日連続でバッチマージ（13 件：Pc 系リファクタリング、TLB 修正、BTB トレーニングタッチ置換ポリシー）、開発ペースは活発に維持；unified-db の意味論修正が三日連続で出現し、「仕様インフラ」のメンテナンス強度は衰えていない。
  5. 国内チームの分化が顕著：達摩院玄鉄（C950 エコシステム公式発表＋起動コード）、進迭（DEIMv2/RL 修正マージ）、算能（agent 化ツールチェーン反復）の三本柱で推進；楽鑫はルーチン、芯来/奕斯偉は静黙。

限界に関する説明：C950 公式発表の詳細（チップ仕様、プロセス、指標）は Wccftech の伝聞に基づくものであり、原文は X プラットフォームのツイート引用であり、アリババ公式ページによる直接検証は行っていない（wccftech 原文はアクセス可能）；Qwen-3.8 モデル本体のパラメータ（「Opus 4.5 対抗」「単一 MacBook で実行可能」）はメディア口径である；Xen の RISC-V「完全リリース」のタイムテーブルは未公表；sophon-tools のマージ内容は内部ツールチェーンの反復であり、業務影響評価は行っていない。
