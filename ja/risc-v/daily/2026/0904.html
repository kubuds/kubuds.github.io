1. オープンソースコミュニティとソフトウェアエコシステム

1.1 GCC 17 が RISC-V ネイティブの -mcpu/-mtune=native サポートをマージ

日付：2026-09-03　出典：Phoronix

GCC の RISC-V バックエンドで長らく欠けていた「ネイティブ自動チューニング」機能がついに補完された：以前議論されていた -mcpu=native / -mtune=native サポートのパッチが GCC メインラインにマージされ、GCC 17.1（2027年初頭リリース）で登場する見込みだ。これまで RISC-V ユーザーがローカル CPU に合わせてコード生成を最適化しようとすると、具体的な型番名（例えば sifive-p550、spacemit-x100）を手書きする必要があり、x86/Arm の native 動作と一致していなかった。今回のパッチは SiFive の Kito Cheng（RISC-V ツールチェーンの主要メンテナの一人）によるもの。現在判明している制限：マルチコア異種 SoC（例えば SpacemiT A100 と X100 の混載プラットフォーム）に対し、GCC はコンパイルプロセスが実際に動作しているコア種別に基づいて CPU ターゲットを選ぶことしかできず、チップ全体の異種トポロジーを認識できない。これは RISC-V ツールチェーンの「サーバー化/使いやすさ向上」に向けたまた小さな一歩であり、今年登場する RVA23 サーバーシリコン（1.2 参照）と組み合わせを成す。

1.2 SiFive が RISC-V 標準体系と将来の進化を詳説：Hot Chips 2026 講演実録の追加収録

日付：2026-09-02 公開 / 09-03 に HN と Google News が収録（本期間の追加収録）　出典：ServeTheHome（Patrick Kennedy 現場記録）、Hacker News

ServeTheHome が Hot Chips 2026（8月下旬、スタンフォード）の現場記録を追加掲載——SiFive の RISC-V 標準と採用進展に関する講演。この講演は 09-02 に既報の NVIDIA CUDA-on-RISC-V チュートリアルと同じく本届 Hot Chips の「RISC-V サーバー化」ナラティブに属し、本期は二つの手がかりのうちより「標準科普」寄りの一本である。要点：

  • 標準体系の全体像：RISC-V 16周年（2010-05-18 の誕生日）を引き合いに出し、「オープン標準は単一企業の運命に縛られない」ことを改めて強調。4種類の基本 ISA（RV32I/RV64I/RV32E/RV64E）はすでに批准済みで、CHERI ケイパビリティセキュリティ拡張と将来の RV128（128ビットアドレス空間）は開発中。
  • Profile メカニズムの細分化：RVA20/RVA22/RVA23 の3世代にわたる進化（RVA23 は 2024-10 に批准、ベクトルと hypervisor を必須化）。メジャーバージョンでは必須機能を強化し、マイナーバージョンでは option のみを追加するという互換モデルを明確化し、新ソフトウェアが旧ハードウェア上で動作することを保証。RVB23（Yocto/OpenEmbedded のカスタムビルドシナリオ）は独自に進化。
  • AI とセキュリティ：行列拡張は AME/IME/VME + ベクトル fast-track の「1+3」並行路線を提示。RISC-V が AI ホスト ISA（CUDA 移植）、アクセラレータデバイス ISA、エンドサイドセルフホスト ISA を同時に担える唯一のアーキテクチャであることを強調。セキュリティ機能のリストには PMP、RISC-V Worlds バスレベル分離、機密コンピューティング向け supervisor domains、ポインタマスキングが含まれ、進行中のプロジェクトには CHERI、投機バリア、メモリタグ付け、メモリ暗号化コンテキストがある。
  • 流言の打破：「可変長命令は弱点」「RISC-V は命令融合があってこそ競争力がある」「RISC-V は性能が低い」などの説に一つずつ反論（gnews 上の「SiFive RISC-V requires Fusion」「has too many extensions」などのセンセーショナルな見出しは、いずれもこの記事の小節から出たもの）。著者の結び：初の RVA23 サーバーが今年出荷されることは、標準化作業がハードウェアに実装された実際のシグナルである。

2. 製品とエコシステムの動向

2.1 トレンド項目：CUDA-on-RISC-V メディアの反響が継続：BigSky は「移植検証プラットフォーム」と位置づけ、NVLink Fusion チップは早くても 2027 年

日付：2026-09-03　情報源：igor’sLAB（ドイツメディア、英語版）

ドイツメディア igor’sLAB は 09-03 に SiFive BigSky SF-2U870 のフォローアップ解説を掲載（主要事象は 08-25 に既報、今回は繰り返さない）。その論調はエコシステムのリズムを第三者が確認するものとして位置づけられる：BigSky（32コア P870-D @ 2.0GHz、RVA23、Ubuntu 26.04 LTS / RHEL 10）はハイパースケールクラウド事業者、チップ企業、ソフトウェア開発者向けの移植検証プラットフォームとして位置づけられており、EPYC/Xeon に対抗する量産サーバーではない。CUDA はすでにその上で動作しており、RISC-V コアがホストとして OS と制御タスクを実行し、CUDA カーネルは実際には NVIDIA GPU 上で実行される。RISC-V International のウィークリーレポートによれば、このデモは RISC-V ホスト + NVIDIA Blackwell GPU の組み合わせである。記事では改めて、SiFive と NVIDIA が NVLink Fusion 統合を進めており、NVLink Fusion を統合した初の RISC-V カスタムチップは早くても 2027 年にならないと登場しないと述べられている。BigSky の意義は、まずソフトウェアスタックを実ハードウェア上で準備しておくことにある。09-02 に既報の NVIDIA の要件リスト（RVA23/ACPI/一貫性）を踏まえると、「CUDA on RISC-V」の実装リズムの判断は変わらない：ソフトウェアが先行し、シリコンは後から。

3. 国内チームの動向と深掘り

3.1 香山メインリポジトリと XSAI：ベクトル/浮動小数点ユニットのリファクタリングが進行、AI ブランチは同期を継続

日付：2026-09-03/04　情報源：openxiangshan/XiangShan commits、openxiangshan/XSAI、openxiangshan 組織

中国科学院計算技術研究所が主導するオープンソース高性能コア XiangShan は、調査期間内に 6 件のコミットをマージした（昨日の 10+ 件からペースは鈍化したが、通常の変動の範囲内）。ベクトル/浮動小数点実行とパイプライン最適化に集中している：

  • refactor(VCVT)：浮動小数点とベクトルの型変換ユニット（VCVT）のリファクタリングを開始、新しい VCVTWrapper 構造を導入（初期サポート）；
  • perf(LoadQueueReplay)：LoadQueueReplay のレイテンシを最適化（#6422）；
  • refactor(VIMac)：ベクトル整数積和演算ユニットの初期サポート；fix(vector,exu)：ベクトル実行のソースオペランドが常に bypass データを通るべきではない；
  • config(isa)：ISA 拡張文字列と実装の整合（#6463）；ready-to-run が NEMU 参照を同期して bump。

深掘：XSAI——香山 AI ブランチの並行推進。openxiangshan 組織の下に、自らを “A fork of Xiangshan for AI” と記述するリポジトリ XSAI（2023-12 にリポジトリ作成）が存在し、調査期間内も継続的にマージが行われている：difftest サブモジュールを mrelease retirement セマンティクスに整合（#121）、nightly regression checkpoint プールの更新（#120）；遡れば 08-31 に昆明湖（kunminghu-v2）のバグ修正を一括同期（#115）、さらに Palladium エミュレーション環境向けの commit-stall ウォッチドッグを導入（#119）していることが確認できる——これは香山チームが汎用コア（昆明湖）とは別に、AI ワークロード向けのプロセッサ変体ラインを維持しており、かつメインラインの正当性修正と同期を保っていることを示す；もう一つのリポジトリ YunSuan（雲算）は香山機能ユニットの独立したユニットテストプロジェクト（Verilator エミュレーション）であり、検証基盤に属する。全体として見れば、香山系の「プロセッサ＋エミュレータ＋AI 変体＋機能ユニットテスト」という開発クローズドループは依然として全速力で稼働しており、ベクトル／浮動小数点と信頼性の研磨が現在のテーマである。

3.2 HICOOL 2026 RISC-V+AI 協同創新チャレンジカップが閉幕

日付：2026-09-03（決勝・授賞式）　情報源：国際科技創新センター網絡サービスプラットフォーム（北京亦荘公式 WeChat 転載）、大会ホームページ rdi.hicool.com、経済参考網（準決勝報道、08-21）

国内初の RISC-V と AI の融合創新に焦点を当てた専門大会——HICOOL 2026 グローバル起業コンテスト「集積回路先端技術：RISC-V+AI 協同創新チャレンジカップ」が中国国際展覧中心で決勝ロードショーと授賞式を完了し、トップ 10 チームが全ての賞を争った末に盛大に閉幕した：

  • 一等賞は「RISC-V と OpenHarmony に基づくスマートビデオ監視（NVR）端側 AI 分析システム」に輝いた；他に二等賞 3 件、三等賞 6 件があり、受賞プロジェクトは端側 AI 分析、国産チップの産業対応、エッジコンピューティング端末、教育シーン向けソリューション、産業データストリーム処理などの方向をカバーしている；
  • 大会は北京市人材工作局の指導、北京海外高層次人材協会の主催の下、北京 RISC-V 数字インフラ創新センターと北京奕斯偉計算（ESWIN Computing）が共同で運営し、RDI 聚力聯盟などが協賛、四つの主要トラックは AI 駆動チップ設計、計算力基盤と CLI 創新、RISC-V+AI シーン応用、OPC スーパー個体軽量化 AI である；
  • 受賞特典の設計は北京亦荘のエコシステム戦略をよく反映している：年間最大 2000 万元の計算力券を申請可能、開発区の「科創二十条／人材十条」と集積回路専門政策、ACT（RISC-V アーキテクチャ適合性テスト）ツールを無償使用し RISC-V テスト認証を取得、奕斯偉計算エコシステムの後ろ盾と開発者エコシステムとの接続、RDI 聚力聯盟への無償参加。

08-21 の準決勝（70 余プロジェクトが晉級、起業家約 100 名）と比較すると、決勝はトップ 10 に焦点を当てており、この大会が「プロジェクト募集」から「実装インキュベーション」への第一行程を完走したことを示す。国内 RISC-V エコシステムにとって、これは「香山オープンソース、奕斯偉商業、亦荘産業政策」に続く、「オープンソースカーネル＋大手商業企業＋地域産業ベルト」の三者合力による新たな顕著な動きである；NVR 端側 AI 一等賞プロジェクトは RISC-V と OpenHarmony という二つのオープンソース基盤を同時に命中させており、その後の産業化を追跡する価値がある。

4. 具身智能とロボティクス専門章

4.1 ヒューマノイドロボットの計算は「中央＋分散」ハイブリッドアーキテクチャへ、安全の複雑さは自動運転を上回る

日付：2026-09-03（Liz Allan 文）　情報源：Semiconductor Engineering、Jon Peddie Research 分析（09-03）

Semiconductor Engineering が業界円卓レビューを掲載し、ヒューマノイドロボットの計算アーキテクチャと安全設計について議論した。核心的な判断は RISC-V エコシステムと強く関連する：

  • アーキテクチャのコンセンサス：ハイブリッド制。インフィニオンのヒューマノイドロボットシステムアーキテクト Ronald Stärz は「中央の強力な計算＋指先/関節レベルの分散前処理」というハイブリッドモデルを提唱し、自動車が集中 ECU からゾーンアーキテクチャへ移行した流れを明確に類推した（レイテンシ、帯域幅、フォールトトレランスが駆動要因）；MIPI Alliance Physical AI BoF 議長の Edo Cohen は手部の局所リアルタイム推論（ミリ秒級の把持力調整）と中央のタスク計画の責務分担を補足したが、集中型アーキテクチャが BOM、消費電力、ソフトウェアの複雑さの面で優位になり得ることも指摘した。TI は消費電力を抑えるため「ダムセンサー＋中央融合」の路線を主張。共通点は：安全を決して AI モデルだけに委ねてはならず、独立して認証されたハードウェアコンポーネントによる担保が必須である；
  • 安全脅威モデルの高度化：Secure-IC（Cadence 傘下、RISC-V セキュリティ IP の重要サプライヤー）の CTO は、ヒューマノイドロボットと自動運転の本質的な差異を指摘——物理的近接性（家庭、病院、学校）により、中間者攻撃や LLM による弱い立場の人々の操作といったシナリオが現実的リスクとなる；機能安全とサイバーセキュリティの融合が必須要件となる；
  • RISC-V の観点：MIPS（GF 傘下、全面的に RISC-V へ転換）の市場責任者 James Prior の発言が個別に引用された——「顧客が尋ねるのはいつ RISC-V を採用するかではなく、いかに RISC-V へ転換するか（誰と協業し、どのような道筋をたどるか）である」、さらにロボティクス業界（自動車/産業と同源）はリスク回避的であり、「ソフトウェア優先、オープン標準、エコシステムの活力」という供給ナラティブが必要だと強調した。これは昨日の MIPS 3 プラットフォーム（Acies/Actus/Aegis）のリリース、Jon Peddie Research 09-04 のフォローアップ分析（”MIPS gives physical AI three ways to think”）と相互に裏付けられる：具身智能における RISC-V の競争は「チップ仕様」から「アーキテクチャの主導権＋安全認証＋エコシステムサービス」へと移行しつつある。

5. 総括とトレンド観察

  1. ツールチェーンと標準の二本柱が「サーバー化」へ収束：GCC 17 が RISC-V ネイティブの -mcpu/-mtune=native（Kito Cheng/SiFive）を補完し、SiFive は Hot Chips で RVA/RVB profile、セキュリティ、マトリックス拡張のロードマップを体系的に説明——コンパイル、profile、OS の三層すべてが初の RVA23 サーバーシリコン（今年出荷）に向けて準備中；今週の Hot Chips における RISC-V 関連の 2 件の講演報道（NVIDIA CUDA 要件リストは 09-02 に既報、SiFive 標準進化は本日追記）がこれで揃った。
  2. CUDA-on-RISC-V のリズムが明確化：サードパーティメディア（igor’sLAB）と RISC-V International ウィークリーレポートが共同で BigSky の「移植検証プラットフォーム」としての位置づけと、RISC-V ホスト + Blackwell GPU のデモという事実を確認；NVLink Fusion カスタムチップは早くても 2027——ソフトウェアスタックが先行し、シリコンは後からという判断は変わらず、短期的に RISC-V サーバーの出荷量を過大評価すべきではない。
  3. 国内オープンソース側は香山系のみ活発：昆明湖メインリポジトリのベクトル/浮動小数点再構築（VCVT、VIMac、LoadQueueReplay）と AI fork XSAI の同期修正が並行して進み、開発クローズドループは完全；達摩院玄鉄/芯来/算能/進迭などは依然としてリリース後の平穏期にある。
