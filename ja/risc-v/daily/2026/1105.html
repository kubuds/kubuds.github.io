今日の注目：Infineon が初の RISC-V 車載グレード MCU プラットフォーム AURIX RC1 を発表、最大12コア、ASIL D、2027年上半期にサンプル出荷（11-04）

Infineon は11月4日、ミュンヘンで AURIX RC1 を発表した。これは同社初の RISC-V ベース MCU プラットフォームであり、AURIX 製品ラインとして初めてオープン命令セットを採用するものである。公式は、既存 MCU 製品ポートフォリオへの補完であり代替ではないと強調し、現行の TriCore シリーズは供給を継続する。位置づけは従来の MCU から MCU／MPU ハイブリッドデバイスまで広がり、ソフトウェア定義自動車（SDV）、その他のソフトウェア定義システム（SDX）、およびフィジカル AI を対象とする。

仕様面では、RC1 は単一チップ上に最大12個の32ビット処理コア、エッジ AI 向けの並列処理ユニット、最大40MB の組み込みストレージを統合する。Infineon は同一ファミリー内で64ビットマイクロプロセッサ機能を積層したモデルも投入し、計算性能をさらに一段引き上げる計画だ。セーフティ側は ASIL D まで対応し、情報セキュリティは ISO/SAE 21434 と「サイバーレジリエンス法」を満たし、ハードウェアレベルで物理的保護と暗号アジリティを実装し、ポスト量子暗号のサポートも確保する。通信側は CAN XL、10BASE-T1S、マルチギガビットイーサネットに対応し、一部モデルは BRIGHTLANE イーサネットスイッチとハードウェアアクセラレーションによるデータルーティングを統合し、外付け部品とメインプロセッサの負荷を低減する。

製品ロジックは注目に値する。RC1は、従来別々だったAURIXとTRAVEO T2Gの2つのラインを1世代の製品に統合し、同一のRISC-Vベースでゾーン制御、ボディ、シャシー、バッテリーマネジメント、パワートレイン、ADAS安全マネジメント、コックピットをカバーする。RISC-Vのモジュール性により、Infineonはアプリケーションに応じてコア数とペリフェラルを調整でき、ソフトウェア、ツール、ノウハウを同一ファミリ内で再利用できる――これは従来のドメイン別のポイントソリューションでは実現できなかったことだ。

エコシステム側ではDRIVECOREソフトウェアスタックを用意し、AUTOSAR、オープンソースソフトウェア、機能安全、情報セキュリティのサポートを提供する。バーチャルプロトタイプ（ハードウェア到着前に開発・検証が可能）とAI支援マイグレーションツールを含み、既存のAURIXおよびTRAVEO T2Gプロジェクトの受け皿とする。InfineonはRISC-V国際財団のシニアメンバーであり、合弁会社Quintaurisの創設メンバーでもある。同社は、ソフトウェア、ツール、ミドルウェア、仮想化のパートナーとともに車載グレードRISC-Vの共通基盤を構築していると公式に述べている。

スケジュール：11月10日から13日までミュンヘンのelectronica 2026でファミリコンセプトを展示（C3ホール502ブース）、2027年上半期のサンプル提供を目指す。オートモーティブ事業部総裁Peter Schiefer氏の表現は「MCUはよりコンフィギュラブルで、よりスケーラブルで、より適応性が高く、同時に最高水準の安全と情報セキュリティを維持する必要がある」というものだ。

産業の座標軸で見れば、これは世界の車載グレードMCU第一梯隊のメーカーが、試験プロジェクトではなく主軸製品をRISC-Vに切り替えることを意味する。これまで車載グレードRISC-Vは新興勢力と国産メーカーが主に推進してきた（同日、国芯科技のCCRC4XXXがAUTOSARとIARへの適合を完了した。第3章参照）。Infineonの参入は、AUTOSARスタック、機能安全認証、ツールチェーン、Tier1の適合リソースがこのラインに沿って動くことを意味する。国内で車載グレードRISC-Vに取り組むチームにとって、これはエコシステムの恩恵（ツールチェーンと基盤ソフトウェアの成熟）であると同時に、競争圧力（国際大手が同じオープン命令セットで同じ市場を狙う）でもある。

今日の重点：RISC-V組込み知能オープンソリューション RV-EAI が烏鎮「インターネットの光」で発表、6機関が共同でオープンソース化（11-04）

11月4日、RISC-V国際財団アンバサダー、甲辰計画主宰、苦芽科技共同創業者の呉偉氏が、世界インターネット大会烏鎮サミット「インターネットの光」博覧会の期間中に「RISC-Vベースの組込み知能オープンソリューション」（RV-EAI）を発表した。発表名称の作業コード名は「啓元」。ソリューションはopenKylin組込み知能ワーキンググループがMilk-V、超睿科技、上海OpenLoong、進畳時空、苦芽科技の計6機関と共同で発表したもので、全詳細はオープンソースプロジェクトとしてGitHubリポジトリと公式サイト上で継続的に進化する。今回の烏鎮サミットの会期は11月2日から5日まで、「インターネットの光」博覧会は11月2日に先駆けて開幕し、同会場ではロボットと組込み知能に関する分科会も設けられた。

ソリューションの主張は「インターフェース、マニフェスト、リファレンス実装を公開することであり、完成した一体型マシンではない」というものだ。1台のロボットをリアルタイム性に応じて3層に分割する。本体層はマイクロ秒級の電流ループを担い、関節モータ、エンコーダ、制御ボード、無線接続をカバーする。小脳層はミリ秒級の制御クローズドループを担い、リアルタイムコアでRTOSを実行し、CAN-FDとEtherCATで関節バスに接続する。大脳層は10ミリ秒級の推論を担い、知覚、計画、VLAを負責する。3層は同一のRISC-V命令セット（RVA23、RVV、IME、AME、VMEを組み合わせ）上に構築されるため、任意の層を入れ替えても他の2層を書き直す必要がない。小脳層の鍵となる設計は、リアルタイムコアとAIコアが同一チップ上で物理的に分離され、互いにプリエンプトしないことであり、両ドメインはrpmsg、共有メモリ、バスを介して協調する。

「オープン」に対する検証可能な定義として5つのプラガブルポイントを挙げる。本体側には中科本原、先楫、兆易創新、沁恒、楽鑫などのRISC-V関節駆動とMCUが選択可能。小脳側は進畳K3／SoM260、知合A210、超睿とMilk-VのUR-DP1000／Titan。大脳演算側はK3、愛芯元智AX650N、瑞芯微RK1828。OS層はopenKylin、Debian、Ubuntu、Fedora、openEulerの5ディストリビューションにリアルタイムドメインのRT-Threadを加えたもの。フレームワークとモデル層はFlagOS、llama.cpp、TileLangとベンダーランタイム。受け入れ基準は明記されている：1つのポイントを入れ替えても、残り4つのポイントは変更不要で、上位層の再適合も不要であり、一致性テストに合格できること。

サイトでは同時に、発表者が進畳K3実機上で行った自社テストデータも公開した（「本チーム実測」と注記、Bianbu 4.0.7、カーネル6.18.3、10月21日採取）：1B視覚言語モデルのローカル推論24.09 t/s、24B MoEモデル12.00 t/s、IME2は1コアあたり970 GMAC/s（8スレッドで5632 GMAC/s）。さらに、ベンダー公称のTOPSはピーク値であり利用可能なスループットとは異なると明言している。「ベンダー公表」と「本チーム実測」を別々に注記することは、この資料がデータの口径において大多数のソリューション文書よりも抑制的である点であり、項目ごとに検証可能にしている。

産業的意義は、国内で既に分散して実用化された能力を、接続可能な集合体へと集約することにある。チップ側では、真に RISC-V に基づく MCU と AI CPU が複数選択可能であり、システム側では openKylin と RT-Thread のデュアルドメイン連携があり、本体側では OpenLoong のフルサイズ・オープンソースヒューマノイドロボットが検証環境を提供している。これまで RISC-V のエンボディドインテリジェンスにおける実装はほとんどが単発の事例であり、「別のサプライヤーに変更する際に適合を作り直す必要があるか」という問いへの公共的な答えが欠けていた。この方案はそれを、インターフェース一覧、互換性マトリクス、一貫性テストのタスクリストとして書き表したものである。次のステップの価値は発表会ではなく、互換性マトリクスに最終的に何社の実機モデルを記入できるかにかかっている。

香山の四件の修正：ITTAGE はデフォルトで非割り当て、CBO コミットタイプを STORE に変更、ICache エラー通知、SC をデータ保持バイパスに変更（11-04）

香山メインブランチの調査期間内に4件の修正がマージされた。#6837 は ITTAGE の updateAlloc のデフォルト値を、関心を持たない DontCare から false に変更し、未初期化の分岐履歴が「割り当て許可」として予測テーブルに書き込まれるのを防ぐ；#6847 はデコード段階の CBO（キャッシュブロック操作）命令のコミット種別をデフォルト値から STORE に変更した。以前は load 類に分類されると、メモリアクセスキューとコミット経路で誤った分岐に入っていた；#6846 は ICache とツール関数のコンパイルエラーメッセージを最適化し、ジェネレータ展開後のエラーを特定しやすくした；#6764 は SC ユニットの holdRead を DataHoldBypass に置き換え、ストア条件命令の読み出しデータバイパス経路を調整した。4件はいずれもタイミングと境界シナリオの収束であり、アーキテクチャレベルの変更はない。

NEMU 2件の修正：hvictl 注入割り込み番号の保持、ゼロ長ベクトルロードをダーティとしてマーク（11-04）

NEMU に2件がマージされた。#1279 は hvictl 注入割り込み時に vscause が注入割り込み番号を失う問題を修正し、guest が読み取る例外原因が実際の注入と一致することを保証する；#1278 はゼロ長ベクトルロードをダーティとしてマークする。以前はこの種の命令は宛先レジスタを変更しないが、その後ダーティビットに依存する最適化によってクリーンなデータとみなされ、古い値を読み取っていた。2件はいずれも仮想化とベクトル拡張の組み合わせシナリオに該当する。

RV-EAI サイトとリポジトリの現状：サイトコンテンツは公開済み、ホワイトペーパーと参考実装ディレクトリは依然プレースホルダー（11-01）

発表公告が示す kubuds/RV-EAI リポジトリは 10 月 25 日に設立され、Apache-2.0 ライセンスを採用しており、最終プッシュは 11 月 1 日——つまりサイトのコンテンツは発表前にすでに完成していた。リポジトリのルートディレクトリには website/ だけが利用可能なコンテンツであり（Hugo サイト、中英バイリンガル、明暗二色の配色）、whitepapers/、src/、3rd-party/ の三つのディレクトリは現在それぞれ説明用の README が一つあるだけで、README の状態列には「計画中」と明記されている。すなわちホワイトペーパー、参考実装コード、サードパーティ素材の登録はまだ実現していない。

これは公告における「すべての参考コード、参考イメージ、互換性リストを外部にオープンソース化する」という表現との間に時間差が存在する。現時点で検証可能な内容は、アーキテクチャの青写真、インターフェースリストの表現、そしてサイト上のデータの基準である。コードとイメージはリポジトリの充実を待つ必要がある。参入を希望するチームが即座にできることは、サイトが提示する五つのプラガブルポイントに従って互換性マトリックスの項目を提出することであり、参考実装が必要な部分については、src/ ディレクトリがいつプレースホルダーからコードへと変わるかを見守る必要がある。

この道筋はゼロからのスタートではない。進迭時空の spacemit-robotics の三つのリポジトリが今期の調査期間内に行ったのは、まさに小脳層のリアルタイム性と大脳層のナビゲーションスタックの接続であり（本章の以下の三節）、RV-EAI はこうした分散した変更を公共インターフェースと互換性マトリックスにまとめ上げた。両者は同じ事柄の二つの層である。一つは具体的な機種における実装コミットであり、もう一つはベンダー間のインターフェース約定である。

5. まとめとトレンド觀察

  • 具身知能側で初のクロスベンダー対応・プラグイン可能な共通解が登場：RV-EAI が烏鎮で発表したのは完成機ではなく、インターフェース一覧、互換性マトリクス、参照実装の組織化手法であり、本体、小脳、大脳、オペレーティングシステム、AI フレームワークの5点を交換可能なユニットとし、「1点を交換しても残り4点は変更しない」という受け入れ基準を示した。その成色は発表会ではなく、互換性マトリクスに最終的に何社の実機を組み込めるかで判断される——今期の進迭機器人リポジトリへの3件のコミットは、まさにマトリクスに収録すべき類の項目である。
  • 車載グレード RISC-V が同日に2件、性質は異なるが同じことを指す：インフィニオンが主力 AURIX 製品ラインを RISC-V に切り替えたのは、国際的第一梯队メーカーの路線選択である。国芯 CCRC4XXX が AUTOSAR と IAR への適配を完了したのは、国産チップがソフトウェアスタックを補完する実装アクションである。両者とも、車載グレードの競争点が「RISC-V コアの有無」から「AUTOSAR、機能安全認証、デバッグツールを同時に整備できるか」へ移ったことを示している。
  • 比較データは総合スコアより情報量が多い：riscv100.top に新規追加された Run Comparison は、各 GHz で正規化した項目ごとの差異を明らかにしている——香山 KMHv3 は libquantum、xalancbmk で Neoverse V3 をリードするが、gcc、astar、mcf などのコンパイルおよびグラフ探索負荷では 18% から 31% 遅れている。玄鉄倚天 710 は llvm、gcc、sqlite で Zen 5 の毎 GHz 値を逆転するが、stockfish では 75% 遅れている。このような構造的差異はマイクロアーキテクチャとコンパイラの具体的な短板を指し示し、1つの総合スコアよりも最適化の指針になる。
  • オープンソースコアは小刻みな収束期に入る：香山4件、NEMU 2件、cvw 15件は、すべて境界条件とタイミングの修正であり、アーキテクチャレベルの変更はない。cvw の RV32IMCB 構成とラッチレジスタファイルは構成カバレッジと物理実装の推進に属し、プロジェクトの重心が新機能の追加ではなく既存設計を堅実にすることにあることを示している。
  • x86 互換レイヤーは端角落シナリオの研磨に入る：felix86 の単一ウィンドウ14件は、シグナルセマンティクス、32ビットリソース制限、statfs パス検証、x87 スタック例外といったロングテール問題に集中している。この種のコミットが密集して現れるのは、通常メインフローが既に動作し、残りはゲームとランタイムが偶発的にクラッシュしないようにする段階であることを意味する。
  • ディストリビューション側はやや静か：openRuyi の調査期間内の10件はすべてソフトウェアパッケージのバージョンとセキュリティ修正であり、公式サイトに新バージョンの告知はない。revyos のメインブランチは調査期間内にプッシュがない。エコシステムの熱量の重心は今週、ディストリビューションのリリースではなくチップと車載グレード側にある。
