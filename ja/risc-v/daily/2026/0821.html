1. オープンソースコミュニティとカーネル/リリース動向

1.1 Linux 7.2 リリース総括：RISC-V 側 NR_CPUS が 256 に向上、奕斯偉が defconfig に参入（08-21）

日付：2026-08-16（カーネルリリース、LKML）／2026-08-21（CNX アーキテクチャ級総括報道、06:00 北京）　出典：CNX Software、Linux Journal

Linus Torvalds は 08-16 に Linux 7.2 をリリース（LKML）、CNX は 08-21 にアーキテクチャ級総括を発表、RISC-V 側の更新が密集している。共通のハイライト：cache-aware タスクスケジューリング（同一プロセススレッドを LLC ドメインごとに共置）、CFS に触発された Fair GPU スケジューラ、USB4STREAM 直接ストリーミング転送、swap table 第4段階。RISC-V 専項：

  • NR_CPUS 64 ビットデフォルト値が 256 に向上——公式の理由は国産マルチコアマシンを直指す：進畳時空（SpacemiT）は 80 コア RVA23 サーバーを既に生産、デュアルソケット SG2042 の算能 Pisces は 128 コアに達し、デフォルト 64 ではもはや不十分；
  • 奕斯偉（Eswin）SoC が RISC-V defconfig に追加——国産ベンダーがメインラインのデフォルト設定に参入、マージ基準は通常のドライバより高い；
  • 達摩院玄鉄 TH1520：PWM 修正、BeagleV Ahead、Lichee Pi 4a の 2 ボードで WiFi 有効化；
  • 進畳時空：K1 に SPI/thermal ドライバと I2C 有効化を追加、K3 に USB2 PHY と ASoC ドライバを追加、P1 チップに reboot cell を補完；K1 ボード級周辺機器を大量有効化（Milk-V Jupiter eMMC、Muse Pi Pro EEPROM/PCIe/QSPI/USB、OrangePi R2S PMIC/USB3、OrangePi RV2 全周辺機器）；CoM260-IFX と DeepComputing FML13V05 の 2 枚の K1 ボードを新規追加；
  • 算能：Milk-V Duo S に bindings を追加；SG2042/SG2044 デバイスツリー修正（CPU アドレスを 16 進数に変更、MSI は実際には 16 割り込みのみ、PCIe RC にキャッシュコヒーレンシをマーク）；
  • 賽昉：JH8100 割り込みコントローラは同チップが量産されずに生産終了となったため、名称変更して JHB100 版として再製作；JH7110 を SiFive ccache 非標準 cache 操作リストに追加（GPU DMA 非一貫）；JHB100 に clint バインディングと SGMII GMAC サポートを新規追加；
  • コア修正：kexec_file 大メモリ早期起動、無条件 sfence.vma、kfence 誤報修正、CFI vDSO パッチ、ftrace_graph_ret_addr、BUILDTIME_MCOUNT_SORT による起動オーバーヘッド削減など。

7.3 merge window はリリースに伴い開設済み（Linus は 40 件のマージ待ち PR があると発言）；Phoronix は 7.3 で旧 32 ビット ARM プラットフォームを大規模に排除すると報道（ARM 再構築、RISC-V への影響は注視が必要）。今回の総括が裏付けるのは：Linux メインラインが「80-128 コアの国産 RISC-V サーバ」に向けて批量で道を整えつつあるということである。

1.2 NetBSD 11 が 64 ビット RISC-V サポートを実装（08-20）

日付：2026-08-20（The Register 報道 21:45 北京時間；HN 同時）　情報源：The Register、HN ディスカッション

NetBSD の第 19 メジャーバージョン 11.0（07 月末リリース）が The Register の長編レビューを獲得：新たに 64 ビット RISC-V サポート（Tier II プラットフォーム、QEMU 仮想化環境向け）を追加し、NetBSD は Linux、FreeBSD に続いて RISC-V にメインラインサポートを提供する BSD 系 OS となった。11.0 は同時に以下をもたらす：MICROVM 専用カーネル（x86 ゲストで約 10 ミリ秒のコールドスタート、2020 年代プロセッサでの実測）、POSIX.1-2024 と C23 準拠の向上、Linux システムコール互換の強化、Xen/QEMU 実行最適化、52 の Tier II プラットフォームと 9 の Tier I プラットフォーム。レビューは同時に NetBSD が「オールドスクール」なスタイルを保っていることも指摘：sysinst テキストインストーラ、/etc/rc.conf の手動編集が必要、商用ドライバは希少。RISC-V エコシステムにとっての意義：BSD 陣営の RISC-V サポートが補完され、仮想化シナリオ（QEMU）が先行して実装された。

2. 製品とエコシステムの動向

2.1 Andes が Condor 設計センターを閉鎖、Cuzco データセンター級コア IP は親会社に回帰（08-17/08-20）

日付：2026-08-17（Jon Peddie Research が初報）／2026-08-20（EE Times が続報、06:00 北京時間）　情報源：Jon Peddie Research、design-reuse 転載、EE Times

晶心科技（Andes Technology）は、米国テキサス州オースティンにあるハイエンド設計センター Condor Computing（2023-03 設立、約 100 人、85% 以上が研究開発）を正式に閉鎖した。Condor は Andes がデータセンター級 RISC-V に挑む旗艦プロジェクト Cuzco コアを担っていた——RVA23 準拠、ライセンス可能、新型の特許取得済みマイクロアーキテクチャを採用（深いアウトオブオーダー実行 + 非慣例的な時間スケジューリング設計、Hot Chips 2025 で公開）。現状：Cuzco IP は Andes 親会社に回帰、後続の test silicon 開発はなし；チームは 50 人から 15 人に削減、さらにこの IP を真に理解するエンジニアは一桁人数に縮小；元 CEO の Ty Garibay は Ambiq の SoC Design VP に転任済み。閉鎖は 2026-04 に公表されたコスト削減計画の一部：会長兼 CEO の Frankwell Lin は過去三、四年に拡張が速すぎ、売上が見合っていないことを認め、運営費を 10-20% 削減、全世界の従業員を 480 から約 450 に削減する計画（EE Times は現在すでに約 400 と推計）。

産業的な意義：Jon Peddie Research のアナリスト David Harold は直言する、これは「Andes のハイエンドへの野望にとっての挫折であり、データセンターにおいて Arm/x86 の信頼できる代替を築こうとする RISC-V の取り組みの後退でもある」と。1.1 で Linux メインラインがマルチコアサーバ向けに道を整えていることと対照をなす——ソフトウェア側は加速しているが、IP サプライヤ陣営は再編・縮小している。

3. 国内チームの動向と深掘り

3.1 香山：24時間で20コミット、WritebackQueueとTAGEの性能最適化（08-20）

日付：2026-08-20（10:59 ~ 翌日 01:32 北京時間、committer 時間）　情報源：OpenXiangShan/XiangShan、XiangShanLab、env-scripts

香山組織の調査期間内には計20コミット、メインリポジトリ（XiangShan）には4件の実質的コミットが着地し、性能志向のイテレーションが顕著である：

  • timing(WritebackQueue): use lowestIndexFirst policy (#6379)（08-20 10:59 北京時間）——ライトバックキューを lowest-index-first スケジューリングポリシーに変更、メモリアクセスバックエンドのタイミング最適化；
  • build: generate CHIRRTL only for gsim (#6374)（11:36）——ビルドシステムの簡素化（CHIRRTL は gsim のみで生成）；
  • perf(Tage): optimize UseAltOnNa (#6328)（17:24）——TAGE 分岐予測器の UseAltOnNa ポリシー最適化；
  • fix(uart16550): expose DesignWare status register (#6385)（08-21 01:32）——UART ステータスレジスタの露出、デバッグとボードレベルの可用性改善。

関連リポジトリ：XiangShanLab に xs bug replay スクリプトを新規追加（commit hash による bug リプレイ）、env-scripts の perf_trigger に2件の修正（#154/#155、ランタイム分析ログの強化）。連日にわたる集中的なマージが続いており、今回の重心はメモリアクセスの正確性からライトバックキューのスケジューリングと分岐予測の性能微調整へ移行しており、アーキテクチャ性能の収尾期の特徴と言える。

3.2 進畳時空：K1 ソフトウェアスタック v2.2.11 リリース更新（08-20）

日付：2026-08-20（09:07 ~ 17:25 北京時間）　情報源：spacemit-com/buildroot-ext、uboot-2022.10、mpp、v2d-test

進畳時空組織の調査期間内には22コミット、核心は K1 ソフトウェアスタック v2.2.11 のパッケージ全体更新：buildroot-ext、uboot-2022.10、v2d-test が同期して v2.2.11 へ、うち K1 buildroot は GENERIC_HOSTNAME を “K1-Buildroot” に変更し、ルートファイルシステムを 1GB に拡張（より大きなソフトウェアセットに対応）；mpp メディアパイプラインには2件のエンジニアリングリファクタリング（stream manager を mpi インターフェース層から移出、AL module ビルドターゲットの分離）、v2d-test は K1 buildroot のビルドエラーを修正。08-18 に既報の「K1 メインラインカーネル 7.2 が meta-riscv 経由で Yocto に着地」のリズムを継続し、今回は BSP パッケージのバージョン化されたデリバリであり、メディアパイプラインは独立して保守可能なモジュール構造へ進化しつつある。

3.3 達摩院玄鉄/芯来/奕斯偉/賽昉/算能の例行観察（08-20）

  • starfive-tech（賽昉）：0コミット、静観（Dubhe-100 後の SDK は依然として未放出、08-20 レポートの判断に合致）；

4. 重点方向専門章：エンボディドインテリジェンスとロボティクス

4.1 調査期間内に新規の専門ニュースなし：基盤の推進は停滞せず（08-20）

日付：2026-08-20　情報源：gnews 専門クエリ（”risc-v” robot when:3d、具身智能 RISC-V when:3d）、GitHub 組織検索

調査期間内の gnews ロボット専門クエリは前日に既報の項目（Dubhe-100、NetBSD）のみにヒットし、独立した新規ニュースはなし。中国語の「具身智能 RISC-V」クエリは空であった。新規専門ニュースなしの日と判定するが、基盤レベルの進展は停滞しておらず、具身/エッジコンピューティングに直接関連する：

  • Linux 7.2 における進迭時空 K3 の PDMA、USB2、Ziccrse 拡張の有効化——ロボット主制御 SoC のペリフェラル基盤がメインラインで継続的に補完されている；
  • 香山 WritebackQueue スケジューリング戦略と TAGE 最適化——低遅延応答に向けたマイクロアーキテクチャの微調整；
  • トレンドの接続：08-19/08-20 レポートで既に整理した達摩院玄鉄 C950（30 tok/s で Qwen3.8-27B を実行）と賽昉 Dubhe-100 がともに「AI agent サーバー/ロボット」を核心シーンとして位置づけており、本調査期間に新たなナラティブはないがハードウェア基線は前進している。観察結論：ロボット方向のニュース密度は周期的に低下しており、判断は見出しではなくハードウェアとカーネルの動きを基準とすべきである。

5. 総括とトレンド観察

  1. Linux 7.2 は国産マルチコア RISC-V サーバーのメインライン・マイルストーン：NR_CPUS のデフォルトが 256 に引き上げ（SpacemiT 80 コア、Sophgo Pisces 128 コアを名指し）、奕斯偉が defconfig に参入、進迭 K1/K3 ペリフェラルの大規模有効化——メインラインと国産ハイエンド SoC の結合が明らかに深まっている；
  2. データセンター級 IP 陣営の再編：Andes が Condor を閉鎖、Cuzco が親会社に回帰——SiFive の縮小に続くもう一つのシグナルである。ハイエンド RISC-V コア競争における「中国の二強」（達摩院玄鉄/賽昉）の重みがさらに上昇し、ソフトウェア側の鋪装と IP 側の縮小が併存している；
  3. BSD エコシステムの補完：NetBSD 11 が 64 ビット RISC-V メインライン・サポートを提供し、主流オープンソース OS による RISC-V のカバレッジがさらに一歩前進；
  4. 国内チームのリズムの分化：香山（性能微調整期）、進迭時空（v2.2.11 パッケージ全体納品）が高活性；達摩院玄鉄/芯来/賽昉/奕斯偉のリポジトリは静穏だが、奕斯偉のマージ動作はメインライン defconfig にある；
  5. 平穏日の説明：gnews 中国語クエリは調査期間内に空、ベンダー英語クエリは既報イベントが大半で、国内動向は主に GitHub 組織検索で捕捉している（付録チェック表を参照）。

限界に関する説明：Linux 7.2 RISC-V 変更は CNX の伝聞に準拠し、カーネル changelog を逐条照合していない；Andes 閉鎖の詳細（チーム規模、headcount）は EE Times/JPR 報道の口径に準拠し、Andes 公式確認は得ていない（公式は正式公告を出していない）；NetBSD 11 は The Register の評価視点であり、RISC-V ポートは Tier II（QEMU）であって Tier I 実機ではない；香山/進迭のコミットは committer 時間で分類しており、個別コミットの author 日付は調査期間より前の可能性がある。
