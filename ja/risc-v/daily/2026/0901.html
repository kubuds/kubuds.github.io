1. オープンソースコミュニティとソフトウェアエコシステム

1.1 CPython が RISC-V を公式サポート（Tier 3 プラットフォーム）：ソフトウェアエコシステムのマイルストーン

日付：2026-08-24（Python Insider 発表）/ 08-31（Adafruit 転載、HN ホットスレッド）　出典：Python Insider（公式発表）、RISE Project ブログ、Adafruit 報道（gnews リンク）

CPython メンテナの Stan Ulbrych 氏が Python Insider 公式ブログで発表：RISC-V が正式に CPython の Tier 3 サポートプラットフォームとなった（PEP 11）。達成条件の鍵は実ハードウェア上での継続的テストであり——RISE Project が複数の物理 RISC-V マシンを CPython buildbot とアーキテクチャ関連問題のデバッグ用に提供した。主要貢献者には RISE の Ludovic Henry 氏、Furkan Onder 氏、Emma Smith 氏も含まれ、Ulbrych 氏本人の作業は Sovereign Tech Agency の奨学金の支援を受けている。次のステップ：RISE RISC-V Runners 計画を活用して RISC-V を CPython 公式 CI に直接接続し（マージ前からフィードバックを取得可能）、長期的には Tier 2 への昇格を目指す。同時に RISC-V の特性を活用したアーキテクチャレベルの性能最適化も模索する。発表では併せて、コミュニティに対し実際の RISC-V ハードウェア上でのビルドと問題報告を呼びかけている。この発表は 08-24 に公開され、昨日のレポートではカバーされていなかったため、今号で補録する。08-31 の Adafruit 転載と Hacker News のホットスレッドにより、期間内に高い注目を集め、ここ一週間で RISC-V ソフトウェアエコシステムの最も重要なマイルストーンとなった。

1.2 Arduboy CHGame Rev0：39 ドルのオープンソース RISC-V カラー携帯ゲーム機

日付：2026-08-31　出典：Hackster.io、Arduboy ストア

名作オープンソース携帯ゲーム機 Arduboy が新プラットフォーム CHGame Rev0 を発表：39 ドルのベアボード開発キット、メインコントローラは沁恒（WCH）CH32X035G8U6——32 ビット RISC-V マイクロコントローラ、48 MHz、64 KB Flash、20 KB RAM、DMA とプログラマブル I/O（PIO）搭載；1.44 インチ ST7735 カラー LCD（128x128、16 ビット色）、8 つのボタン、圧電スピーカー、microSD スロット、200 mAh バッテリーを搭載。Arduino 互換でドライバ不要、基板シルクには GPIO/機能区分が表示され、GPIO、I2C、UART 拡張ポートを開放。公式の位置づけは「画面とボタンを備えた RISC-V 開発ボード」。現在は資金調達中の前期キットで、量産コストはさらに下がると見込まれる。これは国産 RISC-V MCU（沁恒）が海外オープンソースハードウェアコミュニティで実現した典型的な事例であり、CH32V003 シリーズの「激安 RISC-V 携帯ゲーム機」ブームを継続するものだ。

2. 製品とエコシステムの動向

2.1 Micro Magic MagicV プロセッサが即時供給開始を発表、世界最速/最低消費電力の 64 ビット RISC-V と主張

日付：2026-08-31　情報源：PR-Inside（ACCESS Newswire 通稿）、Middletown Life 転載

米国シリコンバレーの非公開企業 Micro Magic は、MagicV プロセッサシリーズを即日供給開始、1/2/4 コア構成を提供すると発表し、 multi-core MagicV 上で Linux、Zephyr、FreeRTOS を動作させるデモを披露した。通稿は例年主張してきた指標を繰り返している：シングルコア 1.1V で 5 GHz、13,000 CoreMarks；0.8V で 4.25 GHz わずか 200 mW（11,000 CoreMarks）；電力効率 110,000 CoreMarks/Watt；超低消費電力コアは 1 GHz でわずか 10 mW；データは 16nm プロセスに基づき、より先進的なノードも利用可能。CEO Mark Santoro は、顧客が性能に強い印象を受け、低消費電力の成果は「驚異的」だと述べた。注意すべきは：すべての性能数値はメーカー自身の主張であり、第三者によるベンチマークやテープアウトの公開証拠は見られず、同社は長期的に戦略的提携や M&A を模索していることだ。「主張は未検証」の項目として追跡することを推奨する（Micro Magic は 2021 年から同様の主張を発表しており、今回は初めて購入可能を宣言したもの）。

2.2 スペイン Indra-UPM が初の 4 チップのテープアウトを納入、RISC-V アーキテクチャチップを含む

日付：2026-08-31　情報源：Demócrata

スペインの Indra グループとマドリード工科大学（UPM）の共同講座「未来を変えるマイクロエレクトロニクス」は、初の 4 チップの設計を完了し製造に投入、現在は生産・納入され、評価・特性評価段階に入っている。具体的には 3 つの 65nm シリコンチップ（TSMC テープアウト）と 1 つのインジウムリン（InP）フォトニック集積チップ（ビームフォーミングアーキテクチャを研究）。うち1 つのシリコンチップは RISC-V アーキテクチャを採用し、残りの 2 つは 3D ヘテロジニアス集積のテストに用いられ、RF モジュールの小型化と集積度の向上を目指す。プロジェクトは競争前環境で、学生と産業博士が参加し、欧州の技術自主戦略に資するものだ；Indra は同時に III-V 族フォトニクス製造に特化した Sparc Foundry の大株主でもある（ビーゴ工場は 2027 年稼働予定）。この動向はスペインの OpenChip（RISC-V International 理事会メンバー）などの布陣と同調しており、欧州主権チップ路線の RISC-V 側における中規模な実装に属する。

3. 国内チームの動向と深掘り

3.1 国内チームの GitHub 動向：RevyOS が K1/K3 カーネルコンフィグを追加、算能 sophon-tools のリリース批次が着地

日付：2026-08-31　情報源：revyos/linux commits、sophgo/sophon-tools commits、sophgo/mcu PR#84、spacemit-com/docs-buildroot、sipeed/maix_ax620e_sdk

調査期間内に七つの国内チームの GitHub 組織を確認：達摩院玄鉄（XUANTIE-RV）、芯来（Nuclei-Software）、奕斯偉計算（eswincomputing）、楽鑫（espressif）は関連する push がなく、リリース後の平穏期が継続。実質的な動きがあったのは以下の三家：

進迭時空エコシステムの RevyOS（revyos/linux、Han Gao 08-31 一括コミット）が最も注目に値する項目：spacemit K1/K3 カーネルコンフィグファイル、linuxboot 起動コンフィグを新規追加、CONFIG_ERRATA_PICOHEART と Banana Pi F3（K1）USB2 サポートを有効化、さらに K3 プラットフォームの DC（ディスプレイコントローラ）と UFS サポートを有効化、同時に TH1520 の USB 関連オプションをモジュール化に変更、シリアルポート数のコンフィグを調整。これは RevyOS ディストリビューションの K1/K3 デュアルプラットフォーム向けカーネルコンフィグ強化批次であり、進迭時空エコシステムが K3 新プラットフォームの表示/ストレージ能力に向けてソフトウェア基盤を敷いていることを示す。spacemit-com/docs-buildroot は同日 K1 secure boot ドキュメントの章節を削除（ドキュメント整理）。

算能：sophon-tools 08-31 に計 15 件のコミット（zetao.zhang）、v26.08.31 リリースの前置批次——BMSSM（シングルボード管理システム）OTA アップグレード/ロールバックの最初の workflow が自身の handler ロックに誤って kill される問題を修正（MYS-451 競合状態）、sophliteos アップグレードのセマンティクスをシステムレベルに変更し二次確認コードを追加、deb パッケージングで制御メンバーと空の preinst を補完（overlayfs 下での dpkg obsolete-info エラーを根治）など、システム管理スタックの安定性加固に属する；sophgo/mcu は同時に SM5MINI(v20) の i2c_slave_reset が誤って IP 情報をクリアする問題を修正。

矽速：maix_ax620e_sdk が UVC エンドポイントのライフサイクル問題を修正（カメラストリームの安定性）、小規模なメンテナンス。

総体として国内チームは依然として通常のイテレーション期にあり、アーキテクチャ級/製品級のリリースはなし；K3 プラットフォームのソフトウェアスタックの推進が調査期間内で最も追跡に値するシグナルである。

4. 具身智能とロボティクス専章

4.1 MicroDuck：Hugging Face と Pollen Robotics のオープンソース二足歩行ロボット（エコシステム参照、メイン制御は非 RISC-V）

日付：2026-08-27（リリース）/ 08-31（OSChina 報道）　情報源：OSChina、Pollen Robotics 公式サイト、Interesting Engineering

Hugging Face ロボティクスチーム（2025-04 に統合されたフランスの Pollen Robotics）が MicroDuck を発表：25 cm、800 g 未満のオープンソース二足歩行ロボット、15 個のモーター、カメラ、深度センサー、デュアル IMU と把持可能な嘴、399 ドルで予約受付（08-27 開放）、歩行、しゃがみ、転倒からの起き上がり、甚至はローラースケートも可能；ソフトウェアスタックは全てオープンソース（Microduck と Microduck RL の二つのリポジトリ）、制御、シミュレーション、強化学習と sim-to-real をカバーし、ゲームパッドで「遊びながら」新スキルを訓練することをサポート。予約初日の売上は 250 万ドル超、ピーク時は 4 秒ごとに一台售出、納品目標は 2026 クリスマス前。RISC-V との関連：メイン制御は瑞芯微 RK3566（ARM プラットフォーム）で、RISC-V ハードウェアではない、オープンソース具身智能エコシステムの参照として収録——その「オープンソースハードウェア + オープンソース RL ソフトウェアスタック + 低価格普及」モデルは RISC-V ロボティクスエコシステムの路線と同構であり、ソフトウェアスタック（50 Hz 制御ループ、ポリシーデプロイ、OTA 更新メカニズム）の可搬性は RISC-V プラットフォームが借鉴するに値する；また「オープンソースハードウェアが消費級具身智能へ向かう」ことに対する市場検証サンプルを提供する。

5. 総括とトレンド観察

  1. ソフトウェアエコシステムのマイルストーン：CPython が RISC-V を Tier 3 サポート対象プラットフォーム（PEP 11）に位置づけ、RISE Project が実ハードウェア buildbot を提供したことが達成の鍵となった；次は公式 CI への接続と Tier 2 への挑戦である。Python は AI と科学計算の主要言語であり、この出来事が RISC-V 開発者エコシステムにもたらす長期的価値は顕著である。
  2. オープンソースハードウェアの継続的な大衆化：Arduboy CHGame Rev0 が 39 ドルで沁恒 CH32X035 RISC-V 携帯ゲーム機を主流オープンソースハードウェアコミュニティに持ち込み、国産 RISC-V MCU の海外浸透にまた一例が加わった。
  3. ハイエンドの主張と主権チップの並行：Micro Magic が MagicV の購入可能を発表（性能数値はすべてベンダーによる自己主張であり、検証待ち）；スペインの Indra-UPM の 4 チップ流片には RISC-V 設計が含まれ、欧州の主権チップ路線が無線周波数/フォトニクス方向へ延伸している。
  4. 国内チームは通常のイテレーション期に突入：7 つの組織にリリース級の動きはなし；RevyOS が K1/K3 カーネル設定（linuxboot、K3 DC/UFS を含む）を追加したことが調査期間内で最も実質的な進展であり、算能 sophon-tools v26.08.31 のリリースバッチはシステムスタックの安定性強化を主とするものである。
  5. 身体性知能エコシステムの参照：MicroDuck は初日 250 万ドルの予約購入で「低価格オープンソースロボット + RL ソフトウェアスタック」の需要が強いことを実証したが、そのメインコントロールは ARM である；RISC-V 側の機会の窓は依然として 9 月の国内ロボット展示会シーズンと各社 SoC ロボット SKU にある。
  6. 限界の説明：Google News の中国語ソースによる国内チームの直接取材は依然として制限されており（同名ノイズ汚染）、国内部分は GitHub コミットの検証に依存している；Micro Magic の指標は独立した検証を受けていない；MicroDuck と Indra の項目は一部の情報がベンダー/学院のプレスリリースに由来しており、可能な限りクロスチェックを行った。
