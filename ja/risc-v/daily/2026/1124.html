今日の重点：達摩院玄鉄が Zvfc 複素数ベクトル拡張提案をコミット、18命令（11-23）

11月23日、達摩院玄鉄が XUANTIE-RV/zvfx-proposal リポジトリに拡張提案をコミットした。提案名は Zvfc、正式名称は Vector Floating-Point Complex Arithmetic。このリポジトリは riscv-unified-db のミラーブランチであり、提案は UDB の YAML 構造に従って spec/std/isa 下の標準拡張スロットに書き込まれている。コミットは計21ファイルで、拡張定義1件、命令定義18件、ゴールデンサンプル更新2箇所を含む。

Zvfc は18命令を定義する。vfcjadd.vv と vfcjsub.vv は j 回転付きの加減算で、ベクトル-ベクトル形態のみ。vfcmul、vfcmacc、vfcnmul、vfcnmsac の4組はそれぞれ実部（r）と虚部（i）形式があり、各組に .vv と .vs の2形態がある。複素数は隣接要素ペアで格納され、偶数インデックスが実部、奇数インデックスが虚部を置く。

拡張は Zve32f に依存し、バージョン番号は 0.1.0、ステータスは development と記載。積和累算は融合演算として扱われ、成分積は事前に丸められない。レジスタグループは完全な複素数ペア1組を収容できなければならず、そうでなければ命令は予約される。奇数 vl は使用可能、奇数 vstart は予約。実装は vl が奇数のときソース要素を1つ余分に読んでもよく、活動出力要素のみが浮動小数点例外フラグを生成する。ファイルヘッダの著作権表示は Alibaba Damo Academy。

日付：2026-11-23　出典：https://github.com/XUANTIE-RV/zvfx-proposal 。

RISC-V 100 ランキング動向

霊晟の項目を TOP500 第一位に改題、スコア基準を補完（11-21）

riscv100.topの巡回で本日顕著な変化が報告され、再確認したところ、サイトが11月21日の告知のタイトルを変更していた。元のタイトルは LineShine LX2: SPEC CPU2017 Rate on One Node (256 copies)。現在のタイトルは TOP500 #1 LineShine: Single-Node SPECrate 422/452。告知の slug は変わらず、依然として 2026-11-21-lineshine-lx2-spec17-rate である。

ランキング記録自体は前回と一致している。日付は11月19日、コンパイラは LLVM 23.1.0、プラットフォームは LineShine-LX2、整数は272.258、浮動小数点は291.613、ステータスは completed。新しいタイトルにある422と452は、主周波数で正規化していない生のスコアである。422を1.55GHzで割ると272.258、452を1.55GHzで割ると291.613になる。

霊晟（LineShine）は深圳国家超級計算センターの CPU-only スーパーコンピュータで、LX2は Armv9 プラットフォームである。この記録が入っているのはクロスアーキテクチャ対照ランキングであり、その役割は RISC-V プラットフォームに同一ランキング上のベースラインを提供することである。これは RISC-V の成績を構成するものではない。RISC-V チャンネルの6つのランキングは今期新規追加なし、委員会メンバーの増減もない。

日付：2026-11-21　情報源：https://riscv100.top/cross-arch/spec17/ 。

1. オープンソースコミュニティとソフトウェアエコシステム

openRuyi 35件：nodejs を26.13.1に更新、RISC-V の戻りアドレスオフセットを修正（11-23）

11月23日、openRuyi メインリポジトリは調査期間内に35件の SPECS コミットを着地させた。nodejs は26.13.1に更新され、そのうち1件は Wasm フレームコードの検索と RISC-V の戻りアドレスオフセットを専門に修正するものである。同バッチで nodejs を LLD、システム Abseil、共有 Temporal に切り替え、OpenSSL 4に合わせてテストの期待値を調整した。

残りの変更はグラフィックスと言語スタックに分布している。mesa は26.3.1に、opencv は5.1.0に更新され、linux と linux-lts はパッチセットと設定を刷新した。Rust 側では一度に ICU4X 関連の20余りのパッケージが追加され、icu-calendar、icu-locale、diplomat、tzif、ixdtf、temporal-rs を含む。ほかに spdk-mcp の RPC schema 修正、python-mcp の pyjwt crypto extra 復旧がある。

日付：2026-11-23　情報源：https://github.com/openRuyi-Project/openRuyi 。

ruyifirmware：EDK II を edk2-stable202611に更新、SG2042 は SBI で実行変数を保存する方式に変更（11-23）

同日、配套ファームウェアリポジトリ ruyifirmware は7件を着地させた。EDK II ベースラインは edk2-stable202611に更新され、ファームウェアのバージョン番号は EDK II checkout から導出するように変更された。SG2042プラットフォームの永続実行変数は SBI 呼び出し経由に変わり、プラットフォーム固有のストレージパスに依存しなくなった。

CI 側も同時に基盤を変更した。1件は Debian 13でファームウェアをビルドし、別の1件は Ubuntu 26.04の GCC に切り替え、coreboot から libgcc を除去した。K3の PCIe ドライバには GCC 16向けの適応が別途1件ある。

edk2-ruyi リポジトリは4件を同期した。変更は RISC-V EFI メモリマップに恒等マッピングを使用することを要求し、SG2042の実行変数と高アドレス MMIO を分離し、DSC にファームウェア識別子を書き込む。Spacemit プラットフォームパッケージは PCIe サブデバイスの初期化をポート検証の前に移動した。

日付：2026-11-23　情報源：https://github.com/openRuyi-Project/ruyifirmware 。

香山 GEM5 が RVWMO litmus テストを週次回帰に組み込み（11-23）

香山の GEM5 リポジトリは当日5件。最新の1件は RVWMO の litmus テストを毎週の回帰に組み込んだ。別の1件は RISC-V 下の CSR 純粋読み取りの書き込み副作用と SATP squash を修正し、さらに1件は読み取り専用 CSR 命令の順序制約を緩和した。同バッチには cpu-o3のフェッチブロック trace データベース、および o3コミット段階の bad address パニック修正が1件含まれる。

日付：2026-11-23　情報源：https://github.com/OpenXiangShan/GEM5 。

CVA6 と CVW：ベクタモードのベースアドレスを256バイトに整列、浮動小数点ベクタを Verilator で実行（11-23）

openhwfoundation 側では、CVA6 がベースアドレス整列を1件マージし、ベクタモードで stvec と vstvec の BASE を256バイトに整列した。CVW は TestFloat と cover-float のベクタを Verilator 上で実行するよう移し、ベクタごとに比較する。

同日、core-v-mcu は uDMA の QSPI 4線 LSB-first 受信とカメラ VSYNC 極性を修正し、cvfpu-uvm はテスト計画と機能カバレッジモデルを補完した。

日付：2026-11-23　情報源：https://github.com/openhwfoundation/cva6 。

libRPMI 7件：クロックツリーのリソース解放とクロックグループテストの補完（11-23）

riscv-software-src の libRPMI は当日7件。中核は2点で、クロックツリー破棄時に全リソースを解放すること、およびクロックグループの線形区間におけるレートカウント処理の修正である。テスト側ではクロックグループの線形範囲と set rate の round down、auto モードのユースケースを補完し、README と logo も併せて更新した。

日付：2026-11-23　情報源：https://github.com/riscv-software-src/librpmi 。

2. 製品・エコシステム動向

楽鑫 esp-riscv-trace、命令セマンティックデコーダと障害ウィンドウを追加（11-23）

楽鑫の esp-riscv-trace リポジトリは当日6件、2本のフィーチャーラインを master にマージした。デコード側では命令セマンティックデコーダを新設し、RV32 の共有エンコーディング規則を encoding.py に抽出した。分析側ではレジスタ出自のバックトラックを行う障害ウィンドウを新設し、未追跡コードへ入る呼び出しに被呼び出し側の名前を補った。

同リポジトリは RISC-V 向けの命令トレース分析を対象とし、処理対象はチップが送出する trace ストリームである。同一期間に楽鑫は arduino-esp32 と IDF 関連リポジトリへの通常のコミットも行っているが、RISC-V 固有の変更は含まれない。

日付：2026-11-23　情報源：https://github.com/espressif/esp-riscv-trace 。

5. 総括とトレンド観察

  • 標準レイヤー：玄鉄の Zvfc は複素数演算を RVV の拡張提案として作り、そのまま UDB のデータ構造に書き込んだ。国内メーカーが標準フォーマットで ISA 拡張を提出するのは、これまであまり見られなかった。
  • ファームウェアレイヤー：ruyifirmware と edk2-ruyi が同日に進展。EDK II ベースライン、SBI 実行変数、K3 PCIe と SG2042 のデカップリングという四つの事柄を同時に進めている。
  • ロボットレイヤー：進畳の二つのリポジトリが同時に SONIC プランナーを接続。公共レイヤーがインターフェースを提供し、機種レイヤーがパラメータを提供する。

三つを並べて見ると、当日は発表会もなく、新しいベンチマークもない。検証可能な進展はいずれも構造の中に落ちている。ISA 定義ファイル、ファームウェア呼び出しパス、プランナーインターフェース。こうした作業はニュースにはならないが、後のプラットフォームが再利用できるかどうかを決める。メディア側で当日最も近いのは、RISC-V Club の後続転載と平頭哥の資本ナラティブである。前者はすでに 11 月 23 日号で収録済み、後者の主体は PPU と倚天ラインであり、RISC-V には属さない。
