RISC-V ウィークリーレポート (2026-11-02 ~ 2026-11-06)

2026-11-06 Kubuds

レポート期間：2026年11月2日（月）から11月6日（金）まで、計5営業日、5期分のデイリーレポート素材。うち11-02期は72時間の調査期間（10-30 05:00から11-02 05:00をカバー）であり、残り4期は24時間の調査期間である。したがって本文には日付が10-30から11-01に該当する項目が若干含まれており、項目タイトルに元の日付を明記している。

素材の情報源：毎日のRISC-Vグローバル動向デイリーレポート（11-02、11-03、11-04、11-05、11-06の5期分）。さらにGitHubのフォロー組織と重点リポジトリの168時間調査期間による再確認（匿名インターフェースのレート制限が今週のほとんどの時間帯で枯渇したため、各リポジトリのcommits.atomでリポジトリごとに照合する方式に切り替えた）、openRuyiの二重ソース確認（メインリポジトリのコミットと公式サイトのニュースページ）、riscv100.topの日次アーカイブ集計とRISC-V国際財団の会員企業公式サイト巡回による補強。

編成上の説明：今週の主线は「オープン命令セットを納品可能な製品にする層」。車載分野では一週間のうちに4つの層が同時に進展した。Infineonが主力AURIX製品ラインをRISC-Vに切り替え（チップ）、QuintaurisがEM-Altairをリリースしてバイナリ互換の実行環境を提供し（プラットフォーム仕様）、国芯科技がAUTOSARとIARへの適合を完了し（国産ソフトウェアスタック）、紫荊M100が「中国芯」エコシステム普及モデルケースに選定された（規模導入のサンプル）。AIマトリクス側では、進迭時空がRVISA仮想ISA作業ドラフトをオープンソース化し、PTXとcuTileの間に「プログラマが表現可能な」マッピング契約の層を挿入しようとしている。ディストリビューション側では、openRuyiがriscv64-openruyi-linuxのデフォルトISAレベルをRVA23U64に定め、RVA23がオプションからデフォルトベースラインになった。3つのラインが答えるのは同じ問いである。オープン命令セットがもたらす断片化を、どの層で収束させるのか。

  • RISC-V エンボディドインテリジェンス向けオープンソリューション RV-EAI が烏鎮「インターネットの光」で発表、6機関が共同でオープンソース化（11-04）：本ソリューションは openKylin エンボディドインテリジェンス作業部会が Milk-V、超睿科技、上海 OpenLoong、進畳時空、苦芽科技の計6機関と共同で発表したもので、発表名称の作業コード名は「啓元」であり、全詳細はオープンソースプロジェクトとして GitHub リポジトリと公式サイトで継続的に進化していく。主張は「完成された一台の筐体ではなく、インターフェース、マニフェスト、参照実装を公開する」ことであり、ロボットをリアルタイム性に応じて本体層（マイクロ秒級電流ループ）、小脳層（ミリ秒級制御閉ループ、リアルタイムコアで RTOS を実行し、CAN-FD と EtherCAT を介して関節バスに接続）、大脳層（十ミリ秒級推論、知覚・計画・VLA を担当）の三層に分割し、三層を同一の RISC-V 命令セット上に構築する（RVA23、RVV、IME、AME、VME を組み合わせ）。「オープン」の検証可能な定義は五つのプラガブルポイントである：本体側の中科本原、先楫、兆易創新、沁恒、楽鑫などの関節駆動と MCU；小脳側の K3／SoM260、知合 A210、UR-DP1000／Titan；大脳演算側の K3、愛芯元智 AX650N、瑞芯微 RK1828；オペレーティングシステム層の openKylin、Debian、Ubuntu、Fedora、openEuler の5ディストリビューションにリアルタイムドメイン RT-Thread を加えたもの；フレームワークとモデル層の FlagOS、llama.cpp、TileLang とベンダーランタイム。受け入れ基準には明記されている：一つのポイントを交換しても、残りの四ポイントは変更不要で、上位層の再適応も不要であり、一致性テストに合格できること。サイトでは同時に進畳 K3 実機の自社測定データを公開している（Bianbu 4.0.7、カーネル 6.18.3、10月21日採取）：1B 視覚言語モデルのローカル推論 24.09 t/s、24B MoE モデル 12.00 t/s、IME2 各コア 970 GMAC/s（8スレッドで 5632 GMAC/s）、そしてベンダー公称ピーク値と利用可能スループットを明確に区別している。この資料の重みは発表会にあるのではなく、互換性マトリクスに最終的に何社の実機を埋め込めるかにある。出典：甲辰計画公衆号、RV-EAI 公式サイト、kubuds/RV-EAI リポジトリ

  • 進畳時空が RVISA 仮想 ISA 仕様の作業草案をオープンソース化、初回で IME／VME／AME の三組のマッピングと blocked MMA を追加（11-04 リポジトリ作成、11-05 コミット）：新リポジトリ spacemit-com/rvisa は RISC-V Virtual ISA を提唱し、スカラー、ベクトル、行列計算のために仮想命令記法の層を定義しており、現在の仕様バージョン番号は 0.2.0。位置づけは明確に書かれている：意図的に NVIDIA PTX の上、cuTile の下に立つ——いかなるフロントエンド言語にも束縛されず（ソース言語フロントエンドの実装は本版の範囲外と明記）、特定チップの命令エンコーディングも直接規定せず、「ターゲットマッピング」をバージョン化された profile とし、どのレジスタクラス、レジスタグループ、命令シーケンスにマッピングするかを項目ごとに宣言し、上流の改訂番号と検証証拠を付す。記法は RVV Intrinsics を参照して型付き操作、オペランドの役割、レジスタグループ制約を表現し、tile は一次元から N 次元をサポートし、reshape と軸置換は要素位置を保持しなければならず、レイアウトは線形レイアウトから導出される。それが解決しようとしている問題を最もよく示すのは「表現可能性要件」である：RVISA の tile 計算に対するいかなる最適化も、プログラマが記法レベルで書き出せなければならない——これはまさに行列拡張の実装時にコンパイラが密かにベクトル化し、チップを替えるたびに書き直しを強いられる失敗の仕方を対象としている。成熟度は明確にすべきである：仕様ステータスファイル自身がこれが working draft であり、RISC-V International の承認済み仕様ではないと明記している；ターゲットマッピング档案は草案としてのみ登録され、実装一致性の証拠はまだ確立されておらず、MLIR dialect と実行可能な一致性ツールはいずれも TBD とされ、参照負荷は .rvisa 記法のソース形式のみで、コンパイル・実行はできない。リポジトリにはさらに RFC 0001 から 0003 の三つの草案があり、命令とレジスタマッピングの契約、コア型と操作の契約、プログラマが表現可能な tile レイアウトをカバーしている。MCU 側の EM-Altair とは同じ論理の二つの現れである：断片化は最終的にある層の安定した「ソフトウェアターゲット」によって収束される必要があり、違いはガバナンス構造にある——一方は大手6社の合弁会社が主導し、もう一方は単一ベンダーの作業草案である。出典：spacemit-com/rvisa リポジトリ、仕様ステータスページ

KU Leuven などのチーム（NDSS 2027 投稿）は、RISC-V プロセッサ上で初のオープンソース DMP（Data Memory-dependent Prefetcher）を実装し、実測により、既存で唯一「DMP の性能を守ろうとする」防御がリークの集合全体を防げないことを示した。その後 SecDMP を提案する。これはメモリ内で秘密をマークすることを要求し、DMP が秘密をマイクロアーキテクチャにエンコードしないことを保証し、そのリークが「DMP なしのベースライン」を超えないことを形式証明しつつ、公開データの性能を犠牲にしない。ハードウェアコストは研究コア上で 面積 0.5% 以下である。オープンソースコアコミュニティにとっての価値は、DMP のような最適化が大手専有から設定可能なコアへと移行しつつあり、セキュリティ設計はテープアウト後に補うのではなく、事前に RTL に入らなければならない点にある。同じ週、ルール大学ボーフム校、マックス・プランク安全保障・プライバシー研究所、ジョージア工科大学の共同チームは、CEASER-S、ScatterCache、SassCache、MIRAGE の 4 種のランダム化キャッシュをすべて同一のマルチコア・アウトオブオーダー RISC-V SoC の最終レベルキャッシュとして実装し、完全な FPGA プロトタイプを作成して SPEC CPU 2017 rate と GAPBS の全負荷を実行した。彼らの表現によれば、同一のフルシステムハードウェアプラットフォーム上でこれら 4 設計を横断評価したのは初である。論文は実装上の難点とトレードオフに重点を置き、公開抄録では性能オーバーヘッドの定量的比較は示されていない。二つの研究は同じことを指し示す。RISC-V のマイクロアーキテクチャ革新は、セキュリティコストも共に定量化する段階に達している。情報源：arXiv:2610.37454 SecDMP、IndexBox によるランダム化キャッシュ論文の報道

6. トレンド観察

  • 車載規格の競争軸は「RISC-Vコアがあるかどうか」から「どのプロファイルに準拠しているか」へ変わった：今週は四つの層で同時に動きが現れた——チップ層ではInfineonがAURIXのメインラインをRISC-Vへ切り替え、プラットフォーム規範層ではQuintaurisがEM-Altairで割り込みとメモリ順序を固定し、ソフトウェアスタック層では国芯がAUTOSARとIARへの適合を完了し、エコシステム事例層では紫荊M100が千万個出荷で模範事例に選定された。国内チームにとって、これは追い風（AUTOSAR、RTOS、ツールチェーンを各社が作り直す必要がない）であると同時に圧力（顧客が「あるプロファイルに準拠しているか」を問うてくる）でもある。
  • 断片化の収斂層が異なる高さで同時に現れ、その形態はそれぞれ異なる：RVISAはAIマトリクス側で仮想命令記法の層を提供し、「プログラマが表現できる最適化」をハード制約として書き下す。EM-AltairはMCU側でバイナリ互換の実行環境を提供する。openRuyiはRVA23U64をデフォルトトリプルとして書き下す。Linux 7.4はhwprobeで実行時検出を可能にする。四つの共通点は——チップメーカー各社に規範をそれぞれ解釈させるのではなく、規範と実装の間に安定したソフトウェアターゲットの層を挿入することにある。
  • オープンソースコアへの投資の重心は検証と可観測性へ移る：香山の週18件で最も重いのはinvalをzeroに変えてしまうデコードエラーである。同期間にはBPUカウンタ、CROBデバッグ信号、AIコーディングエージェント向けのAGENTS.mdが補われた。CVWはrv64gcカバレッジを100%にし、Ubuntu 26.04のインストールとbuildrootの再ビルドを本気の課題とする。GEM5の6件はすべてcheckpoint、trace、PMU、週次性能タスクにある。スコアは再現可能な測定法の上に築かれて初めて比較価値を持つ、というのがオープンソースコアのコンセンサスとなった。
  • 国内サプライヤーは「パラメータの発表」から「使える形での提供」へ移行：進畳は一週間で規範（RVISA）、SDKマニフェスト（manifest）、ロボットアームのマニュアル、安全境界（自動有効化／エラークリア／原点復帰／リトライを行わない）を同時に進めた。算能はピーク演算性能ではなく2コアと3コアのエンドツーエンド負荷テストを示した。紫荊は「エコシステム普及」を申請可能な事例にした。芯来は開発入口をEclipseからVS Codeへ移した。これら四つはいずれも「他者が使いこなせるか」という側を補強している。
  • 商業化のペースはロードマップではなく市場のモメンタムで決まる：AndesがハイエンドコアCuzcoを減速し、資源を売上高の半分を占めるAI事業へ寄せることと、InfineonがメインラインをRISC-Vへ切り替えることは、方向の逆な二つのシグナルを形成しているが矛盾はしない——Cuzcoは中止されたのではなく、加速に値するシグナルを待っているだけである。実際に金を払っているのはAIエッジ、制御面、車載規格である。ハイエンドコアを手がけるチームにとって、これは「誰が先に支払うのか」に関する現実的な参照となる。
  • 評価サイトは「まず測定法を固める」整理期に入った：今週のリストは追記、比較ビュー、バージョン進捗ページのみで、新たな測定はない。11-06の39件の「ランク外」は実際には比較行が消えたことによる錯覚である。これは香山がGEM5でcheckpoint、trace、PMUを補ったのと同じ種類の動きである——数字の比較可能性は数字そのものより注目に値する。

限界と基準の説明

  • 補録は新規実績ではない：riscv100.top の今週の補録記録3件（10-17、07-30、10-10）はいずれも巡回日より前の日付であり、本レポートでは逐条注記し、「今週の新規性能」には計上していない。同一コンパイラ条件での0.8%から0.5%の差異もノイズの範囲内である。11-06の39件の「ランキング外れ」は、サイトの比較ビューで対照行が消えたことによるものであり、実績変動としては扱わない。
  • ベンダー自行公表は第三者検証を受けていない：玄鉄 C950 の60億個出荷、400社の顧客、1000件のライセンス、クラウド負荷性能30%以上の向上は公式の表明である。紫荆 M100 の1000万個出荷と ASIL-D／ASIL-B 認証は会社の表明である。ベトナム Viettel の「暗号化・復号はソフトウェア方式の約15倍」は公式テストの表明である。インド GPU の24か月目標は製造元とアーキテクチャライセンスの詳細を公表しておらず、政策宣言に属する。
  • 成熟度を区別すべき仕様：RVISA は working draft（仕様ステータスファイルの自己記述）であり、RISC-V International が承認済みの仕様ではない。ターゲットマッピングプロファイルは草案としてのみ登録され、実装一致性の証拠は確立されておらず、MLIR dialect と一致性ツールは TBD である。EM-Altair は合弁会社のプラットフォーム仕様であり、その ASIL-B の表現は「同等要求」であって、認証完了と同義ではない。
  • コミット計数の口径：香山、CVW、openRuyi の件数はデイリーレポートで日々記録された PR／コミットのマージ数を集計したものであり、日をまたぐ期間では同一のコミット群が隣接する2期にそれぞれ1回ずつ記録される可能性がある（例えば CVW の11-04から11-05と11-05から11-06の2批次）。本レポートはデイリーレポートの口径でそれぞれ列記し、強制的に重複排除して合算してはいない。組織レベルのプッシュ計数は巡回スクリプトから取得したものであり、逐筆のコミット数とは異なる口径である。
