2. 命令セットとアーキテクチャエコシステム

RVA23 とカーネル：profile ビットのツリー投入、自動ベクトル化実験、「準拠の検証可能性」

  • profile ビットがマージフローに進入：v8 の 11 枚のパッチのうち 8 枚が riscv/for-next に投入済み（10-09）、残り 3 枚は v9 でコミットされる。v9 では RVA22／RVA20 の階層ビットを補完して glibc の段階的フォールバックを可能にし、IMA ビットを継承しない歴史的遗留動作を明記する。glibc 側は profile ごとのビルド＋glibc-hwcaps による自動ライブラリ選択に変更され、GCC メンテナ Jeff Law が GNU Tools Cauldron の RISC-V BoF で同方向に推進している。ユーザー空間で V 拡張を動的に無効化するインターフェースは廃止される予定（SiFive の Samuel Holland が 3-patch シリーズを投稿済み）。今後、レジスタ状態を持つ拡張には同種のスイッチを導入しない。
  • 波及シリーズ：このシリーズは直接的・間接的に少なくとも 5 つのメインラインシリーズを牽引した——2 年間棚上げされていた拡張名の大文字小文字統一と Zicclsm が吸収され、字節跳動の Qingwei Hu が Zic64b を貢献、do not report disabled extensions（6 patch）、cpufeature の BUNDLE から SUPERSET への簡素化、V-off 廃止シリーズ。今回の LPC の RISC-V MC は全 10 講演で、クアルコムが 3 講演を占めた。
  • カーネル自動ベクトル化：Andy Chiu は LPC26 でコンパイラ自動ベクトル化によるカーネル最適化の実践を紹介——LZ4 で最大約 15%、Btrfs で約 8.4%、XFS で約 5%、Nginx シナリオで約 2% の向上。代償としてベクトルコンテキスト管理の時間・メモリオーバーヘッドが増加する。RISC-V カーネルビルドは現在も V 拡張を有効化しておらず、この結果により「カーネル空間でのベクトル使用」という長年の禁忌が再評価されつつある。
  • クエリインターフェース：10-14 に Phoronix が単一ビットクエリ方式（KEY_BASE_BEHAVIOR：IMA RVA23U64、起動時に完全な ISA ビットマップから一括計算）を報道。Andrew Jones が RFC を起案し、徐国棟が推進。付随する「RVA23 in practice」講演資料は LPC サイトで公開済み。情報源：Phoronix 自動ベクトル化、LPC26 ベクトル講演

6. トレンド観察

  • RVA23が「規範テキスト」から「判定可能な事実」へ、三環クローズドループが今週形成：カーネルprofileビットは既に8個がriscv/for-nextに投入（v9は進行中）、単一クエリインターフェースは主要メディアに報道され、Ubuntu 26.10はRVA23をイメージベースラインとし「RVA23及以上」と明記。これは「このマシンはRVA23か」が項目ごとの照合から1回のシステムコールへ変わることを意味し、glibcのprofile別ビルド＋hwcapsによる自動ライブラリ選択が次の重要な着地点となる。このチェーンが予定通り通り抜ければ、RISC-Vソフトウェア配布におけるバイナリ断片化問題に初めて体系的な答えが出る。

  • 高性能の語りは2つの路線に分かれ、いずれも今週段階的な証拠を獲得：1つは「CPU自体がAIを担う」——玄鉄C950は64コア構成で独立アクセラレータなしに27Bを実行し、デコードは30 tokens／秒超。量化、行列命令、オンチップメモリ、帯域のシステムレベル協調によるもの。もう1つは「CPU＋オンチップAIエンジン」——藍芯LX500は48コア＋75 TOPSの単チップ融合で量産を目指す。前者は実現可能性の上限を、後者は商業的経路を証明するが、両者とも第三者ベンチマークとシステム全体の消費電力データを欠いており、次段階で最も補うべき証拠である。

  • ディストリビューション競争の焦点は「起動できる」から「プラットフォームの広さ＋ファームウェア体験＋セキュリティ保守」へ：openRuyiはファームウェアを日次更新ペースにし（K3デュアルクラスタCPUモード選択はSPI永続化とcoreboot読み取り層まで到達）、RevyOSは2週間でK1／K3／EIC7700／TH1520／SG2042／SG2044のプラットフォーム設定を一括集約、Ubuntuは公式デスクトップイメージ＋K3公式サポートで直接参戦。3社が同じ週にK3を最重要検証プラットフォームとしたことは、国産SoCのディストリビューションサポートが「パッチ的な適配」から「製品化デリバリ」へ移行したことを示す。

  • 端側AgentスタックがRISC-Vソフトウェアスタックの新たな競争領域に、ただし依然シングルプラットフォーム先行：進畳時空は1週間で「集中リポジトリ構築」から「フルスタックオープンソース＋能力配布クローズドループ」（GUI／ランタイム／記憶／オフライン音声／セキュリティ＋APM／Agent Hub／Skillsイメージ）へ進み、ヒューマノイドロボットのMuJoCoシミュレーションにRGBD起動コマンドを追加。この組み合わせはRISC-V上では初例。リスクは全コンポーネントが現在K3とBianbu 4.xのみをサポートしている点で、クロスチップ可搬性とコミュニティ外部貢献者の規模が今後の観察点。

  • 資本と量産が同じ週に出現、ただし「調達額」と「性能実現」は分けて見る必要：藍芯の約20億元BラウンドとUbitiumの1400万ドルシードラウンドが同時期に成立。前者は既にシステム全体の量産と通信事業者システム適配を有し、後者は依然テープアウト検証と2027年評価サンプル段階。国内RISC-Vサーバチップは「点灯」から「量産検証」へ移行中で、次なるハード指標は受注、第三者性能評価、ソフトウェアスタック成熟度であり、評価額ではない。

  • エコシステム活動の密度が年内最高点に到達、サミット週の後には一連の技術公開がある見込み：RVSC2026（10-18～20）に進迭開発者大会（10-17）、龍蜥 RISC-V 分科会（10-18）、香山エコシステム大会（10-20）、AME マトリックス拡張ワークショップ（10-20）、玄鉄北京駅（10-22）が重なり、1週間で5つのイベントがコンパイラ、マトリックス拡張、車載グレードツールチェーン、端末側 Agent の4本の主軸をカバーする。次回ウィークリーレポートでは、サミット現地資料を主軸に事実確認を一度やり直すべきであり、特に AME 仕様の推進状況と各メーカーのチップタイムテーブルに注目すべきである。
