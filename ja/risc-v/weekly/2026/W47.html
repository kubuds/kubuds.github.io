賽昉 JH-B100 が量産納入、天枢-70 が国産アウトオブオーダーコアをデータセンターへ（11-17、11-19）

賽昉科技は11月17日、サーバー BMC チップ「昉・驚鴻-B100（JH-B100）」が量産に入り顧客へ納入したと発表した。同社によれば、このチップは複数のサーバーメーカーとインターネット企業の製品導入・審査を通過しており、これを搭載したシステムはまもなく量産に入る。出荷量、顧客名、生産計画のペースはいずれも非公開。

11月19日、賽昉はコアの型番を補足した。自社開発 CPU IP「昉・天枢-70（Dubhe-70）」が搭載されている。同社は、国産アウトオブオーダー RISC-V CPU IP が初めてデータセンターで規模化量産商用化されたと述べ、年間出荷量は「千万級に達する見込み」とした。

仕様は賽昉公式サイトと2本のプレスリリースによる。JH-B100 は4コア自社開発 RISC-V コア、19200 DMIPS、昉・星路-500 コヒーレント NoC を搭載し、DDR4-3200 と DDR5-4800 に対応。PFR プラットフォームファームウェアレジリエンスと PROT を統合し、国密 SM2／SM3／SM4、セキュアブート、DICE をサポートする。インターフェースにはデュアル PCIe 4.0 エンドポイント、フル機能 eSPI Slave、PECI、I2C／I3C、USB 3.2 Gen1、SGPIO、CAN-FD、IPMB、MCTP、NCSI を含む。チップには2系統の LTPI を内蔵し、デュアルノード管理をサポートする。SDK は Yocto に準拠し、OpenBMC に直接接続できる。天枢-70 は9段以上のパイプライン、3発行スーパースカラー、深いアウトオブオーダーで、マルチコアと I/O キャッシュコヒーレンスをサポートし、命令セットは RV64GCBH。

このニュースの重みは性能ではなく位置にある。BMC は演算に関与しないが、すべてのサーバーに1個必要で、長らく Arm と 8051 系コントローラが握ってきた。RISC-V はこれまでこの位置ではサンプル出荷と検証しかなかった。突破口に選んだ論理は車載チップがボディコントロールから入るのと一致する。性能要求はメイン CPU よりはるかに低く、ソフトウェアスタックは OpenBMC と Yocto が支え、顧客導入の検証コストは制御可能である。ひとたび入れば長期供給となる。

エコシステムの裏付けは2つある。Intel は CRB プラットフォーム上で Intel CPU 管理機能の検証を完了した。AMI は JH-B100 の SDK を BMC ファームウェア製品 OneTree に統合した。この2項目はこれまでの Intel Connection と滴水湖フォーラムで既に披露されていたが、今週初めて「量産納品」に落とし込まれた。

割り引いて見るべき点は3つある。第一に、「まもなく量産に入る」は顧客側の言い分であり、量産拡大は完成機メーカーの生産計画次第で、しかも BMC の調達判断は多くの場合メイン CPU プラットフォームに追随する。第二に、年間出荷千万個規模はあくまで予想であり、受注でも納品済み数量でもない。世界のサーバー年間出荷台数はもともと千万台規模であり、一千万個を達成するということは増分市場の大部分を獲得することを意味する。第三に、天枢-70 の性能表現は前後で一貫していない。2024年8月の発表時の表現は SPECint2006 で毎 GHz 7.2点、Cortex-A72／A510 に対標し、A55 比で性能80%高、電力効率32%高、面積効率90%高としていた。今週の量産稿では「Cortex-A73 に近い」に改められた。本誌は併記して記録し、取捨選択はしない。

産業チェーン上の位置づけも明確にしておく。国産 RISC-V のデータセンターにおける量産事例は、現時点では BMC、エッジゲートウェイ、AI 推論カードといったサブコア的なシーンに集中している。デュアルソケットまたはクアッドソケットのメイン CPU で x86 を大量置換した公開事例はまだない。この一件が証明するのは、アウトオブオーダーコアがサーバー級の検証プロセスを通過できるということであり、汎用演算能力が置き換えられたということではない。今後注目すべきは2点：JH-B100 の四半期出荷が約束を果たせるか、天枢-83／100 に顧客によるテープアウトがあるかどうかだ。

Purism、フラッグシップ Linux スマホのメイン SoC を進畳時空 K1 に変更（11-14、11-17）

Purism は11月14日、Librem 5 v2 のクラウドファンディングを開始した。このシリーズがメイン SoC を Arm から RISC-V に変更するのは初めてだ。公式ページにはオクタコアの進畳時空 K1、5.7インチ 720×1440 スクリーン、8GB メモリ、128GB ストレージが示されている。バッテリーは 4500mAh の交換式で、デュアル SIM に対応する。さらにセルラー、Wi-Fi／Bluetooth、マイク／カメラの3組のハードウェアスイッチを備える。OS は Debian ベースの PureOS で、Waydroid 互換レイヤーを通じて Android アプリを動かせる。

価格とスケジュールも同時に公開された。クラウドファンディング価格は1599ドルで、目標は2027年2月15日までに2500件の注文を獲得すること。テスト機は2027年末を予定し、量産納品は2028年5月前後を指す。11月17日の公式プレスリリースでは納品時期の表現を「クラウドファンディング終了後14〜15ヶ月」と細分化し、初めて「ARM64 アプリ互換」を必ず克服すべき課題リストに加えた。CTO の Jonathon Hall の言葉は「RISC-V は未来であり、Librem 5 v2 はこのことをメインストリームのユーザーの手に届ける製品だ」というものだ。

リスクは公式ページに明記されている。RISC-V は PureOS にとって、まだ挿せば起動するプラットフォームではない。グラフィックススタックは現在画面を表示できるだけであり、完全な 3D サポートと最適化には依然として書き直しが必要だ。ボトルネックは K1 の演算能力ではなく、モバイルグラフィックススタック、カメラパイプライン、電源管理といった「Arm エコシステムでは既製だが、RISC-V では作り直しが必要」な部分にある。

これを今週の他のニュースと併せて見ると、流れがより明確になる。K1 は2週間のうちに相次いで Start9 のルーターと Purism のスマホに採用され、これは国内 RISC-V SoC では珍しい2つの完成機ラインの並行展開だ。同時期の FIORA5 は2027年プロトタイプ、2029年ライセンスを指し、霊睿智芯は2027年テープアウト、2028年量産を指す。高付加価値の完成機と高性能チップの実現時期は、概ね2027年から2029年に集中している。その間の2年間はソフトウェアスタックとシリコン後検証の期間となる。

インフィニオン、フラッグシップ AURIX ファミリーを RISC-V へ、riscv.org が5問インタビューを公開（11-19）

11月19日、RISC-V International のブログはインフィニオンの自動車マイクロコントローラーソフトウェア・エコシステム管理担当バイスプレジデント Thomas Schneid 氏への5問インタビューを掲載した。テーマは AURIX RC1 で、同製品は11月4日に発表され、インフィニオン初の RISC-V 命令セットに基づくマイクロコントローラーファミリーである。

インタビューが示した背景の数字は記録に値する。TechInsightsの統計によれば、インフィニオンは2025年に世界の車載マイクロコントローラの3分の1以上を供給した。AURIXはこの会社の自動車事業の出発点となったファミリーであり、その市場地位の主要な支えでもある。RC1は従来のTriCoreとTRAVEO T2Gという2つの製品ラインを1世代に統合し、リアルタイムコントローラからMCU／MPU複合デバイスまでをカバーする。応用範囲にはゾーナル、ボディ、シャシー、バッテリ管理、パワートレイン、運転支援安全管理、コックピットが含まれる。一部の型番にはAI加速用の並列処理ユニットが搭載される。

インフィニオンが強調するのは移行コストだ。Schneidの説明によれば、同社は多大な労力を費やし、自動車メーカーがRISC-Vへ移行する際のエンジニアリング投入と顧客のツールチェーンへの影響を最小限に抑えた。この言葉の重みは、車載MCUの置き換えコストが主にチップ自体になく、AUTOSAR設定、デバッガ、機能安全認証、サプライチェーンの再検証にあるという点にある。市場の3分の1を占めるサプライヤーがフラッグシップファミリーを動かすことを厭わないのは、エコシステムがすでに十分だと判断したことを意味する。

留保すべき余地も少なくない。インフィニオンは具体的な型番と製品ラインの詳細は未発表だと明言しており、これはSKUもなく、サンプル品のスケジュールもなく、量産ノードもないことを意味する。AURIXの既存顧客の移行も一晩で完了するものではなく、車規プロジェクトの設計サイクルは通常3〜5年だ。量産車にRC1が搭載されるのを実際に見るのは、2029年前後になる。

この話を賽昉のBMC量産と併せて見ると、2026年のRISC-Vの産業シグナルは管理プレーンと制御プレーンに集中しており、まだメインの演算力にはない。これは今年最も重いアーキテクチャのシグナルの一つだが、現時点で欠けているのは納品可能な型番とスケジュールだ。

紫荊 M100が量産出荷、車規チップ累計出荷が1000万個を突破（11-18）

11月17日夜から18日にかけて、湖南省の複数メディアが紫荊半導体のRISC-V車規チップを相次いで報道した。核心的な事実は3つある。M100は量産車載を果たし、安定した量産出荷を続けている。今年10月時点で、同社の車規グレードチップの累計出荷量は1000万個を突破した。紫荊は長城汽車が主導して孵化させた企業で、2024年11月に長沙経済開発区に拠点を置いた。

認証と顧客の状況は以下の通り。M100は今年7月にAEC-Q100など複数の信頼性テストを完全に通過し、主流の自動車メーカーと一次サプライチェーンに参入する資格を持つ。顧客は曼徳、蜂巣精工、鉄将軍、聯電など30社以上に拡大した。今年末の注文は3000万元と予想される。製品の切入ポイントはボディ制御で、コンビネーションヘッドランプ、アンビエントランプ、コンビネーションスイッチに使用され、1台の車に最大17個が使われる。同社の最高戦略責任者である許興奎氏は、こうしたチップは位置づけは周辺だが量が多く、置き換えの抵抗が最も小さいと述べた。第2の製品ラインは具身智能チップE100で、車規と具身智能の技術基盤の約7割は直接再利用できると同社は述べている。

重みは顧客と数量にあり、発表にはない。M100の発表は2025年12月18日だった。当時、初回25万個の注文が開示され、うち10万個はすでに納品済みで、指標はCoreMark 2.42、同種比38%向上、ASIL-Bと国密要件を満たすというものだった。今回新たに加わったのは3つのことだ。累計出荷が1000万個を超えたこと、顧客が協力意向から名前を挙げられる30社以上になったこと、年末注文に金額の目安が付いたこと。

RISE：Pythonのriscv64ネイティブホイールが1500個を突破、なお519個が不足（11-18）

11月18日、RISEプロジェクトは進捗レポート《Python on RISC-V: 1500 Packages and Counting》を発表した。著者はクアルコムのLudovic Henryだ。レポートの内容は、ホイールボードがPyPIのダウンロード数上位15000パッケージを追跡しており、そのうち2076個がネイティブコードを含み、riscv64向けに個別ビルドが必要というものだ。11月18日時点で、1506個がriscv64ホイールを取得している。

数字は分解して見る必要がある。1506個のうち117個は上流プロジェクト自身がPyPIで公開したもので、1389個はRISEの自建インデックスが提供するものだ。ダウンロードランキング別の層で見ると、上位100位では92個が利用可能で5個が不足、上位500位では438個が利用可能で50個が不足、上位1000位では842個が利用可能で133個が不足、全2076個のうちなお519個が不足しており、約4分の1に当たる。つまり、大多数のユーザーがインストールするには、コマンドラインにRISEインデックスを指すパラメータを1つ追加する必要がある。

インデックスに搭載済みのパッケージには NumPy、SciPy、pandas、cryptography、PyArrow、PyTorch、vLLM がある。PyTorch の 2.13.0 ホイールは CPython 3.12、3.13、3.14 とフリースレッド版 3.14 をカバーし、QEMU やクロスコンパイルではなく RISC-V 実機上でビルドされ、212038 個のテストケースを実行済みである。vLLM の 0.29.0+cpu は 9 月 21 日にマージされ、0.30.0 が 9 月 24 日に続いた。最初のバージョンは CPython 3.12 ABI3 の manylinux_2_39_riscv64 ホイールを生成した。

三種類のレイアウトの違いは計算できるかどうかになく、演算強度とレジスタプレッシャーにある。ドット積は最も柔軟で、ベクトルと行列、行列と行列のいずれもドット積に分解できるが、一回計算するごとに線形個数の要素を運ぶ必要があり、演算強度は最も低い。ファット内積は古典的な行列積に最も近く、行列と行列に適するが、ベクトルと行列では利用率が低い。外積は内積次元をほぼ 1 に圧縮し、アキュムレータが常駐し k 次元が十分大きければ、線形ロードで二乗級の計算を得られる。演算強度は最も高いが、オペランドの形状要求が最も厳しい。

これらの違いが三つのことを決定する。新たなレジスタファイルを追加するかベクトルレジスタを再利用するか、メモリレイアウトをどう並べるか、コンパイラが既存オペレータを自動的にマッピングできるか。

産業にとって真のリスクは提案の多さではなく、提案間の非互換性である。IME は独立した行列レジスタと独立した命令で進み、VME はベクトルレジスタに依存し、AME はまた別の付着方式だ。最終的に一本の主線に収束しなければ、オペレータライブラリとコンパイルバックエンドは組み合わせごとに一つの経路を維持しなければならない。RISC-V が AI 推論で「一つのコードで複数のチップを動かす」という売り文句は弱まる。

ブートチェーンとファームウェア：算能が SG2042／SG2044 の先頭パーティションを FAT32 に変更（11-16）

算能の RISC-V ブートリポジトリ bootloader-riscv は 11 月 16 日に 2 コミットを着地させた。1 コミット目は SG2042 と SG2044 の先頭パーティションを FAT32 に変更する。2 コミット目はビルドスクリプトを調整し、openEuler カーネル RPM をチップ別のワークスペースディレクトリツリー内で生成させるようにし、共通の出力ディレクトリを使わないようにした。

先頭パーティションの FAT32 化はファームウェアの互換性問題だ。UEFI 仕様はファームウェアが読めるパーティションを FAT 系ファイルシステムと要求しており、RISC-V サーバプラットフォームは一般に UEFI と GRUB によるブートチェーンを採る。先頭パーティションが FAT32 でなければ、ファームウェア段階でブートファイルを見つけられない可能性がある。こうした変更は単なるフォーマットパラメータに見えるが、公式イメージがファームウェアに直接認識されるかどうかを実際に左右する。

チップ別ワークスペースでカーネル RPM をビルドすることは、複数世代の製品を並行メンテナンスする現実を反映している。SG2042 は 64 コアの前世代、SG2044 は現行のサーバ級プラットフォームであり、両者のカーネル設定とパッチセットは異なるため、共通の出力ディレクトリを使うとバージョンが混ざりやすい。チップ別ワークスペースに分割した後は、同一の CI で 2 世代のカーネルパッケージを並行して出力できる。

同ウィンドウ内の算能のエッジ側にも一連のコミットがあるが、リポジトリの説明によれば成果物は arm64 deb であり、ARM エッジ製品ラインに属するため、RISC-V の項目には計上しない。

指標は論文による。CORe50 の NICv2-391 プロトコル上で、INT8 活性化構成は 78.6% の精度を達成し、単一サンプルのデバイス側遅延は 7.79 秒。INT16 構成では 81.6%、10.54 秒となる。量子化隠れ層再生と比較して、学習ステップ数は 3.8 分の 1、サンプルあたりの学習演算量は 22 分の 1 である。28 ナノプロセスでの合成結果は 9.43 平方ミリメートル、375MHz で 33.3 ミリワット。覚醒相のアクセラレータは面積のわずか 10.7% を占め、5.48MB の再生キャッシュは充電器側に置かれる。設計全体はすでにオープンソース化されている。

特筆すべきはリソーススケジューリングの思路である。トレーニングを電池駆動のデバイスに押し込もうとするのではなく、「定着」のステップを壁面電源と大容量メモリのある瞬間に移している。代償はデバイスを電源に接続しないと長期記憶を完成できないことであり、利点はデバイス側の消費電力と面積を実用範囲に抑えられることである。限界も明らかだ。7.79 秒に 1 サンプルでは緩やかに変化するセンサーストリームにしか使えず、カメラレベルの連続学習にはまだ遠い。

6. トレンド観察

  • 量産の着地点は「サブコア」に集中しており、これは戦略であって後退ではない：今週の 3 件の量産または納品のニュースはいずれも同一の種類の位置を指している——賽昉の BMC、紫荊の車体制御 MCU、インフィニオンの車載グレード MCU ファミリー。共通点は、あらゆる完成機に必ず搭載され、演算能力への要求は中程度で、信頼性と長期供給への要求が高いことである。これらの位置を選んで突破するのは、検証周期が制御可能で、一度入り込めば多年の供給となるためである。主演算能力については今週、バッチ置換の公開事例が一切なく、真の障壁が依然としてソフトウェアスタックと完成機適応にあり、コアのピーク性能にはないことを示している。

  • トップサプライヤがフラッグシップファミリーを動かすのは、今週最も重いアーキテクチャの信号である：インフィニオンは世界の車載用 MCU の 3 分の 1 以上を占め、TriCore と TRAVEO の 2 ラインを 1 世代の RISC-V 製品に統合する。このことの重みはパラメータになく、移行コストを負担する意思があることにある。AUTOSAR 設定、デバッガ、機能安全認証、サプライチェーンの再検証はすべてやり直しとなる。代価は時間である。SKU もサンプルタイムテーブルもなく、量産車は 2029 年前後まで待つことになる。国内の車載グレードチームにとって、これは競争ウィンドウがあと 2、3 年あることを意味するが、相手はすでに世界のトップティアである。

  • オープンソースコアが「検証可能・保守可能」段階に入ったことは、性能よりも成熟度を物語る：香山が今週行ったのは、メモリアクセスキューの境界欠陥、ICache アドレス翻訳、CSR 命名リファクタリング、difftest の下流 Chisel への切り替えと mill の固定である。CORE-V が行ったのは、ベクトルメモリアクセスの骨格、RVFI CSR ログ、AHB コンプライアンスである。FURSOY は Sail 差分と総合スクリプトを一緒に提供した。4 つのプロジェクト、4 つの路線で、動きはすべて「長期的に動かせるか、他人に検証できるか」に落ちている。オープンソースコアを使って製品を作るチームにとって、この段階はむしろ介入の好機である。インターフェースは安定し、欠陥は系統的に整理されつつある。

  • ディストリビューションが保守面を集約することで、3年後に上流へ追随できるかが決まる：openRuyi は週85コミット。Go の SHA-2 AES 最適化のバックポート、gRPC を bundled BoringSSL からシステム OpenSSL 4 へ切り替え、xgrammar と tvm-ffi をリポジトリに取り込むことを行っている。revyos はカーネルを「プラットフォームごとの設定変更」から Debian パッケージング層へ押し上げた。RISE は Python ホイールのカバレッジを追跡可能な表にし、「上流が引き継いだら自建ビルドを停止する」ことを成功指標としている。3社がやっているのは新機能ではなく、「誰が保守するか」という問題である。RISC-V のソフトウェアギャップの大きな部分は、こうした日常的な整合の中に隠れている。

  • マトリックス拡張の路線争いにコストが生じ始めた：IME、VME、AME と2種類のドット積提案が並行しており、違いはレジスタファイル、メモリレイアウト、コンパイラマッピングにある。今週、香山は difftest でマトリックスと AME の検証を行い、AME と matrix プレフィックスが11-19の全3コミットを占めた。芯来は前回 VME 路線を選び、賽昉は BMC 上でマトリックスよりもまず一貫性を解決した。異なるベンダーがシナリオに応じて路線を選ぶのは短期的には合理的だ。長期的に公共のベースラインがなければ、オペレータライブラリとコンパイルバックエンドは組み合わせごとに1本のパスを維持する必要があり、「1つのコードで複数のチップを動かす」という売り文句は弱まる。

  • 筐体とチップの実現時期は概ね2027年から2029年に分布し、中間の2年間がソフトウェアの窓口となる：Purism は2028年の納品を指し、霊睿智芯は2027年のテープアウト、2028年の量産を指す。FIORA5 は2027年のプロトタイプ、2029年のライセンス供与を指し、Infineon RC1 は2029年前後の車載搭載を指し、龍擎空天と SingNova は量産节点を示していない。この一群の約束の実現時期はすべて2年後にある。中間の窓口では、ソフトウェアスタック、認証、サプライチェーンのいずれか一环で問題が起きれば落地が遅れる。次に注目すべき3点は、JH-B100 の四半期出荷が実現できるか、K1 スマートフォンのグラフィックススタックが2027年のテスト機で動作するか、128コア級 RISC-V サーバチップの初回テープアウト結果である。
