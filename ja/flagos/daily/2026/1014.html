今日の重点：FlagOS 2.3 サイクル開線——日程とフリーズ規則を発表；エンジニアリング側の双線拡張：昆仑芯 XPU3 のバッチクローズ、FlagMega が AMD RDNA と Ada を開通（10-13）

日付：2026-10-13　出典：community #126 · FlagOS 2.3 日程 · FlagGems #7104 · FlagTree #1364 · Torch-FL #504（全量は付録参照）

24時間ウィンドウは高水準を維持：57 のリポジトリのうち 20 がウィンドウ内にプッシュがあり、コミット検索は 70 件ヒット、PR マージは 58 件（14 のリポジトリでマージあり）、さらに 217 件の審査中 PR がウィンドウ内で更新；ウィンドウ内で新規 1 リポジトリ（optest）と 1 ビルドタグ（FlagTree 0.7.1a1+xpu3.6）を追加。三つの主线が同時に推進：

  • FlagOS 2.3 サイクルが正式に開線：community #126 が release/2.3/schedule_CN.md を新規追加し FEP ドキュメントを更新——FEP マージ締切 2026-11-13、機能凍結 + rc0（11-30）、rc1（12-07）、rc2（12-14）、封板（12-25）、GA 2026-12-30；凍結ルールは「GA manifest は existing-tag リリースソースのみ受け入れる」と明確化し、2.2 の「主干締切時間」の兜底口径は一度限りの特例であり、今後踏襲しないと宣言（詳細は 1.2）。
  • 昆仑芯 XPU3 のバッチ収口：FlagGems 側で同日 14 件の XPU3 バッチを開出（capability-gated インフラ + オペレータバックエンド実装、chunk_gated_delta_rule_fwd / lstm / rnn_relu / conv 系 / fused MoE / foreach 系などをカバー）；Torch-FL は CI 三連を完了（#504 レーンが緑化、#507 バックエンドキー修正、#508 ビルドとテストを統合）；FlagTree は 0.7.1a1+xpu3.6 をリリース（10-13 16:36）——「接入、バッチ実装、CI ホスティング」の三段が同一日に揃う（詳細は 1.3 / 1.4 / 3.1）。
  • FlagMega が AMD RDNA と Ada を打通：FlagTree 側で五連が審査中（#1361 ~ #1365）——TLE（ソフトウェアパイプライン / warp 特化 / グローバルバリア）を RDNA（gfx1100 / gfx1201）へ下放、Qwen3-1.7B を単一 cooperative megakernel で W7900 / R9700 上に decode で跑通、prefill（M>1）WMMA + split-K パス、新規 nvidia-sm89（Ada）ターゲットと CP-SAT 検索加速を追加——FlagMega は BI-V150 単点最適化から「アーキテクチャ非依存の可搬パス」へのマルチハードウェア拡張へ転換（詳細は 1.5）。

判断：本ウィンドウは「サイクル切替 + 単一ベンダーバッチ + コンパイル側拡張」の組み合わせを呈する——2.3 日程はリリーストレインを制度化し（2.2 GA からわずか二週間で新サイクルを開線）、エンジニアリング面では昆仑芯が一日十四筆のバッチで XPU3 を「オペレータカバー率」段階へ押し上げ、同時に FlagMega が「同一の可搬カーネルで実モデルを跑通」することでクロスアーキテクチャ路線を検証；58 筆のマージと 217 筆の審査中更新はいずれも高水準にあり、大会（10-17 / 18）前週のスプリントリズムが明確である。

4. まとめとトレンド觀察

1. リリースリズムの制度化：2.2 GA から2週間で 2.3 サイクル開始：スケジュールは「FEP 締切（11-13）、凍結（11-30）、3週間の統合、封板（12-25）、GA（12-30）」をハードなタイムテーブルとして明記し、2.2 の「メインブランチ締切」特例を廃止、GA は existing-tag のみを認定——前調査期間に build-infra がパッケージング ref を release-2.2 正式タグに固定したことと対照的に、リリースエンジニアリングの「列車化」が今週、慣例からリポジトリの事実へと変わった。

2. 崑崙芯単一ベンダーの日：XPU3 が「接続」から「バッチ実装」へ：1日のうちに、オペレータ（FlagGems 14件）、CI（Torch-FL 3連）、ビルド（FlagTree xpu3.6）の3ラインが同日に着地し、かつバッチは「能力ゲーティング + オペレータリスト」という成熟した口径で組織——前調査期間の「CUDA-boxing 除去の置換レベルリファクタリング」が本調査期間で実行可能なカバレッジ構築として実を結び、崑崙芯は大会前にエンジニアリング密度が最も高いベンダーラインとなった。

3. コンパイル側最大の変数：FlagMega のマルチハードウェア拡張：5連のレビュー中案件が cooperative megakernel を NVIDIA Hopper と BI-V150 から RDNA（W7900 / R9700）と Ada（RTX 4090）へと推進——「同一のポータブルパスで実際の Qwen3-1.7B を走らせる」がマージされれば、FlagMega の位置づけを「単一チップのモデルレベル融合」から「アーキテクチャ非依存のモデルレベルコンパイル」へと書き換える；2.3 サイクル（機能凍結 11-30 前）との時間的関係は追跡に値する。

4. エコシステム運営と品質基盤が大会前週に同時に上量：コントリビューター3連（Kubuds などの組織を含む）、optest 新規リポジトリ、週次テスト修正（29 + 5 オペレータ）、4プラットフォーム一致性 CI（FlagCX）、テストエンジンガード（FlagGems）——「誰の貢献が見えるか」と「品質がどう測定されるか」の2ラインが同時に推進され、2.3 のコミュニティ計測とリリースゲートの土台を築く。

5. 次の觀察点：大会（10-17 / 18）での現地発表（FlagOS 2.2 公開、量智雲プラットフォームと FlagOS × FlagQuantum × FlagQAI 統一スタック方案）；FlagMega AMD/Ada 5連と PPU #1360 のマージリズム；vLLM 0.28 残りのライン（MUSA / S60 / 玄鉄 / 崑崙芯新批次）の着地点；FlagQuantum 0.3.0 正式版（rc 3連後約2週間で収束が見られず）；2.3 初回 FEP コミット（締切 11-13、2週間前倒しを推奨）。
