FlagOS デイリーレポート (2026-08-14)

2026-08-14 Kubuds

調査期間：過去 24 時間（2026-08-13 10:19 ~ 2026-08-14 10:19 北京時間） 情報源：GitHub（org: flagos-ai）、Google News アグリゲーション（中英文）、HN、智源コミュニティ等（詳細は付録参照）

1. オープンソースプロジェクトの進展（GitHub 動向）

期間総覧：org 内の 52 リポジトリのうち 16 が期間内にプッシュがあり、commit search で期間内コミット 46 件がヒット、正式リリースはなし（FlagOS 2.1 から 7 週間余り）。本期間の三大主線：FlagAttention マルチバックエンド runtime アーキテクチャの実装（8 つのチップバックエンドを一括展開）、PyTorch-Plugin-FL が Torch-FL 名義で org レベルの改名統合を完了、FlagGems は引き続き高頻度（19 件のコミット、KernelGen NVIDIA オペレータと KMCompiler 昇騰/天数智芯オペレータの二本柱で推進）。

1.1 FlagAttention：マルチバックエンド runtime の実装、8 つのチップバックエンドを一括展開

出典：FlagAttention PR #48、FlagAttention commits

  • 「add multi backends」（#48、8 月 13 日 12:18 マージ）：src/flag_attn/runtime/backend/ に統一バックエンド抽象を新設し、8 つのバックエンドパッケージを一括構築——_ascend（昇騰）、_enflame（燧原）、_hygon（海光）、_iluvatar（天数智芯）、_metax と _mthreads（沐曦の二系統）、_nvidia。FlagAttention は NVIDIA 単一バックエンドの Triton attention オペレータライブラリから FlagOS 全チップ attention オペレータライブラリへと移行し、FlagGems のマルチバックエンドモデルと足並みを揃えた。これは本期間で最も重要なアーキテクチャ上の出来事であり、バックエンド一覧は FlagOS メンバー機関のチップとほぼ一対一で対応している。
  • 付随コミット：08-13 02:55-04:07（UTC）の「add multi backends / add copy right / fix」の 3 件は #48 の開発過程のコミット。

1.2 Torch-FL：org レベルの改名統合（PyTorch-Plugin-FL → Torch-FL）

出典：.github commits、Torch-FL commits

  • org 公式 README（英語＋中国語）で PyTorch-Plugin-FL をすべて Torch-FL に置換（8 月 13 日 18:44/18:45 置換、21:25 リンク修正）：PyTorch-Plugin-FL が正式に Torch-FL 名義で org 本線に入った（Torch-FL リポジトリ README の CI バッジは依然として旧リポジトリ名を指しており、移行がまだ進行中であることを示している）。Torch-FL は FlagOS の PyTorch デバイスプラグインとして位置づけられ、統一 flagos device を公開し、オペレータごとに再利用可能なネイティブ kernel、コンパイラ kernel、ベンダーネイティブ実装、明示的 CPU fallback へルーティングする。
  • #99 の修正（14:54）：非グローバル swap モードで module parameters を保持；
  • docs #101（14:56）：実測オペレータサポートレポート（measured operator support report）を新規追加。

1.3 FlagGems：19 件のコミット、KernelGen NVIDIA + KMCompiler 昇騰/天数智芯の二本柱

出典：FlagGems commits

  • KernelGen NVIDIA オペレータ新規追加（8 月 13 日 13:06-14:22）：max_pool3d_with_indices_backward（#5264）、ormqr（#5252）、heaviside（#5120）、leaky_relu_backward（#5145）、_scaled_dot_product_attention_math（#5168）、_native_batch_norm_legit_no_training（#5243）；さらに hardswish（#5139）、absolute_（#5187）、arctanh（#4818）の 3 オペレータが生成区 “Move to ops” から正式に登録——KernelGen 生成オペレータが正式メンテナンスリストに入る最終動作；
  • KMCompiler オペレータ（8 月 14 日 10:19-10:22）：linalg_cross（#4850）、linalg_solve_triangular（#5201）新規追加；昇騰 pairwise_distance バックエンド + 天数智芯 Iluvatar CPU 参照エラー修正（#5394）——昇騰と天数智芯のデュアルバックエンドが同一コミットで推進；
  • flagtree 依存の正式化：#5444 Bump flagtree version for NVIDIA（15:26）；#5433 昇騰 backends.yaml の flagtree ascend whl を 0.6.1 に更新（17:13）——昨日の「FlagTree wheel 配布体系」判断が実現：FlagTree wheel（昇騰 0.6.1 含む）が FlagGems 各バックエンド設定の正式な依存コンポーネントに；
  • 修正とエンジニアリング：empty ゼロ要素処理（#5438）、nested_view_from_buffer_copy 精度修正（#5324）、xor/ixor 分割および登録（#5283）、cat cpp wrapper パスと dtype 修正 + rwkv_mm_sparsity 精度（#5388）；fused_marlin_moe カーネルを精度方案に基づき改名しベンチマークを分割（#5437、10:28）。

1.4 FlagGems-vllm：沐曦 MC550 の mthreads バックエンドが Fused MoE に進出

情報源：FlagGems-vllm #100

  • [KMCompiler] Fused moe: add mthreads backend and tune metax MC550（#100、8 月 13 日 16:35）：Fused MoE カーネルに mthreads（沐曦）バックエンドを新規追加し、MC550 をチューニング——沐曦は vLLM シーンオペレータ側で推進を継続（昨日の FlagTree METAX 特化統一、MACA wheel パッケージングと合わせてコンパイル-オペレータ-配布の三本柱を構成）；
  • v0.1.1-rc 安定線：#618 デバッグログ削除（18:23）、#679 一部テストを skip（19:32）。

2. ニュース報道とエコシステム

2.1 アリババが Qwen3.8-2.4T-A95B をオープンソース化、FlagOS コミュニティが同期してマルチチップ対応を完了（本調査期間のトップニュース）

日付：2026-08-13（北京時間 17:29）　情報源：新浪財経（gnews）

新浪財経はアリババが新世代 MoE フラッグシップモデル Qwen3.8-2.4T-A95B（総パラメータ 2.4T、アクティブ 95B）をオープンソース化し、智源 FlagOS コミュニティが同期してマルチチップ対応を完了したと報道。同日（8月13日 21:25）には、Qwen3.8-2.4T が国家スーパーコンピューティングインターネットプラットフォームに上線したとの報道もあった（caiwennews）。検証：レポート時点までに、GitHub org の調査期間内コミットには qwen3.8 の明示的な対応コミットは見当たらない（commit search は過去の qwen3 関連記録のみヒット）。対応作業はミラー/リリース準備段階にある可能性があり、本項目は報道ベースで収録する。この出来事は、以前の DeepSeek-V4 八チップ Day0 対応の「モデルオープンソース + FlagOS 迅速マルチチップ対応」というリズムと一致する。

2.2 海光信息（メンバー単位）2026 中間報告：営業収益 90.99 億元 +66.52%、親会社帰属純利益 17.98 億元 +49.69%

日付：2026-08-13（北京時間 18:45 より複数社）　情報源：東方財富、新浪財経

海光信息（688041）が 2026 年半期報告を発表：売上高 90.99 億元、前年同期比 66.52% 増、親会社株主に帰属する純利益 17.98 億元、前年同期比 49.69% 増。AI 算力が国産ハイエンドチップ需要を持続的に押し上げ、複数の証券会社が買い評価を維持／新規付与（華興証券は「CPU+DCU の二輪駆動」で買い維持、8 月 13 日 15:39）。メディアはまた、営業キャッシュフローがマイナスで期末在庫が 123 億元超という「戦略的備蓄」の議論にも注目（新浪財経 8 月 14 日 09:07）。同日の「六大国産 CPU 中央調達大口受注」報道では海光が 2059 台で首位（新浪財経 8 月 14 日 07:26）。FlagOS メンバー単位（Hygon DCU）として、海光の経営面とエコシステム対応（FlagAttention に hygon バックエンドを新規追加、1.1 参照）は同時期に好調に推移している。

2.3 天数智芯（メンバー単位）が上半期の黒字転換を予告

日付：2026-08-13（北京時間 17:38）　情報源：観点網、東方財富

天数智芯（09903.HK）が業績予告を発表：2026 年上半期に黒字転換を見込み、純利益は約 6000 万元から 1.4 億元（うち公正価値收益は最大約 7.9 億元）。同日、FlagGems が Iluvatar CPU 参照エラーの修正をマージ（#5394、1.3 参照）——技術対応と経営面が同頻度で進展している。

2.4 摩尔線程：香港上場後の分析が集中

日付：2026-08-13 ~ 08-14　情報源：新浪財経、CSDN

8 月 12 日の H 株 IPO 開始後、分析報道が集中的に続いている：新浪財経は「摩尔線程：国産 GPU が『雪山を越える』瞬間に最も近づいた」（8 月 14 日 07:52）、CSDN は「180 倍の市販率！摩尔線程が香港上場へ」（09:09）を掲載。中郵証券は初回カバレッジで買い評価を付与（8 月 13 日 17:54）。市場はバリュエーション水準と国産 GPU の競争格局に注目している。技術面では摩尔線程 S5000 のトレーニングイメージパイプラインが既に昨日 FlagScale に実装済み（昨日のレポート 1.1 参照）。

2.5 ニュース側の総合評価

Google News は FlagGems/FlagScale/FlagTree/FlagPerf/FlagCX/KernelGen などのコンポーネントキーワードに対して直接ヒットゼロ。本調査期間のニュースはモデルオープンソースエコシステム（Qwen3.8 マルチチップ適応）とメンバー機関の経営動向（海光中間報告、天数智芯の黒字転換、摩尔線程 IPO その後）が中心で、HN に FlagOS 関連項目はなし（C3 コンパイラ、CoreTrace CPU シミュレータはいずれも FlagOS と無関係のため除外）。「智源研究院 オープンソース」の中国語クエリのヒットは依然としてギャンブル/SEO ノイズが主流で、一括で除外済み。

4. まとめ

  1. FlagAttention マルチバックエンド runtime の実装：#48 で 8 つのチップバックエンドパッケージ（昇騰/燧原/海光/天数智芯/沐曦×2/NVIDIA）を一度にマージ、attention オペレータライブラリの全チップ化であり、FlagOS マルチチップアーキテクチャの重要な一歩。
  2. Torch-FL の正式名称変更と統合：org README で PyTorch-Plugin-FL を全面的に Torch-FL に置き換え、「flagos device」という単一デバイス抽象が PyTorch プラグイン層の統一エントリポイントに。
  3. FlagGems の二本柱が高頻度で進行：KernelGen NVIDIA オペレータ 6 件新規 + 3 件登録、KMCompiler 昇騰/天数智芯オペレータ 3 件連続リリース；flagtree wheel（NVIDIA bump + 昇騰 0.6.1）が各バックエンドの正式依存にとなり、昨日の「wheel 配布体系」判断が実現。
  4. 沐曦 MC550 の継続的な深掘り：FlagGems-vllm Fused MoE に mthreads バックエンドを新規追加し MC550 をチューニング、コンパイル（FlagTree METAX 特化）、配布（MACA wheel）、オペレータ（vLLM シナリオ）の三本柱が同時進行。
  5. ニュースヘッドライン：Qwen3.8-2.4T-A95B オープンソース + FlagOS コミュニティのマルチチップ対応（新浪財経の口径）、「モデルのオープンソース即迅速なマルチチップ対応」という FlagOS エコシステムのリズムを継続；メンバー企業の海光中報、天数智芯の黒字転換が経営面のハイライト。
  6. リリース側：正式 Release はなし；build-infra packaging 再構築 + FlagGems-vllm v0.1.1-rc 安定ライン、コンポーネント化リリースは依然として準備中（FlagOS 2.1 から 7 週間余り経過）。

限界に関する説明：Qwen3.8 マルチチップ対応の項目は報道口径に基づくもので、GitHub org の調査期間内には明示的な対応コミットは未確認；gnews の遷移リンクは本文を取得できず、ニュースの詳細はタイトルと複数情報源のクロスチェックに依存。
