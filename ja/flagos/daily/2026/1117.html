1.4 FlagGems：exponential_ のランダムストリーム再現と clone の FakeTensor クラッシュを同日修正（11-16）

日付：2026-11-16　情報源：FlagGems #8141 · FlagGems #8893 · FlagGems #9266

  • ランダムストリームのリプレイ：#8141 は、vLLM が argmax(probs / q)、q ~ Exp(1) の指数競争形式でサンプリングしているため、exponential_ は独立同分布のサンプリングを返し、呼び出し間で生成器を進めなければならないと指摘している。f32 の unroll8 カーネルは出力要素ごとに philox カウンタを1つ取るが、ラッパー層は生成器を N/8 しか進めないため、呼び出しごとに前回のランダムストリームの 7/8 がリプレイされる——2 の 20 乗規模のサンプリングで q2[:-N/8] と q1[N/8:] が 917504 個の要素で完全に一致する。修正方法は、実際に起動されたプログラム（末尾でマスクされていてもサンプリング中の lane を含む）に応じてカウンタを予約することである。
  • 対数ファストパスの歪み：safe_fast_log_f32 は ln(u) を exponent*ln2 + p(mantissa) に分解するが、u が 1 よりわずかに小さい場合、2 つの項が約 0.69 で相互に相殺され、多項式の約 1e-5 の絶対誤差がそのまま結果に残り、左裾の分布が歪む。同じコミットで併せて修正する。
  • compile 下でのクラッシュ：#8893 は、FlagGems を有効化した後に x.clone() が torch.compile 内で「Cannot access data pointer of Tensor (e.g. FakeTensor…)」を報告する問題を処理する——aten::clone は複合オペレータであり、その Meta 実装はデフォルトのバックエンドカーネルを通るため、形状伝播が flag_gems/ops/clone.py に落ち、FakeTensor に対して data_ptr() を呼び出してしまう。修正方法は、is_meta または fake_mode の入力を識別した後に出力レイアウトを直接解析し、カーネルを起動しないことである。新たに 3 種のメモリフォーマットと転置/通常の組み合わせのケースを追加し、test_clone.py の 64 項目が通過した。AMD の vllm-plugin-FL 適配はまさにこのコミットに依存している。
  • ベンチマークの欠陥：#9266 は router_gemm ベンチマークでバックエンドディスパッチがハードコードされている問題を修正し、ベンチマークが現在のバックエンドに応じてカーネルを取得するようにした。

日付：2026-11-16　情報源：FlagGems-vllm #1245 · FlagGems-vllm #1194 · FlagGems-vllm #1115 · FlagGems-vllm #1163

  • 950DT フォワード：#1245 で昇騰 950DT に BNSD 版 FlashAttention フォワード（dense と causal の 2 系統）を追加。flash_attention_fwd として _ascend/a5/ops の下に登録し、SpecOpRegistrar の a5 アーキテクチャキーでディスパッチする。+2215 行、7 ファイル。インターフェースは dense 形態 q[B,Hq,S,D]、k/v[B,Hkv,S,D]、fp16、D ∈ {64,128}、Hq % Hkv == 0、Sq == Skv で、既存の varlen/paged パスとは区別する。

  • 平頭哥 PPU：#1194 で cast_sigmoid（明示的な出力 dtype と計算 dtype を持つ要素ごとの sigmoid、vLLM のグループ化 top-k ゲーティングスコア用）を追加。sigmoid は 1/(1+exp2(-x*log2(e))) と書き、指数を SFU 命令に落とし、log2(e) をパラメータに折り込み、FP32 結果の書き戻し時には 1 回だけ変換する。autotune 候補は平頭哥と英偉達の tune_configs の両方に登録する。

3.4 天数智芯：FlagCX が GDR デバイスファミリーと PXN トポロジクエリを補完（11-16）

3.5 昇騰：950DT の a5 アーキテクチャと KMCompiler のサイレント誤値修正が並行（11-16）

日付：2026-11-16　情報源：FlagGems-vllm #1245 · FlagGems-vllm #1229 · FlagGems #8886 · FlagAttention #138

  • 新アーキテクチャ：950DT の BNSD FlashAttention フォワードは a5 をアーキテクチャキーとして _ascend/a5/ops に入り、既存の _ascend/fused/attention.py の varlen/paged パスと並列する。この一筆は「新ハードウェアでまず使えるフォワードを一つ生成する」を入口とし、benchmark と精度テストも併せて納品する。
  • 精度の取向：マスクは真の -inf で置換し、qk + (-1e6) は使わない。作者の理由は、有限バイアスは q·k·scale が 1e6 に近づくと破綻し得るためである——この種の「動きそうだが境界で誤る」実装差異こそ、クロスチップ整合で最も発見しにくい部分である。
  • サイレント誤値：#8886 は KMCompiler が昇騰上で polygamma と GRU の blockify 領域不一致により生じるサイレント誤値（タイトルは silent wrong results を直指す）を修正する。サイレント誤値はコンパイル失敗より危険である。下流は精度低下しか見えないからだ。
  • その他：#1229 の昇騰 910B4 cooperative_topk は分段 CANN sort/merge に整数キー精修とマスクヒストグラムを加える；FlagAttention #138 は昇騰側の互換性問題を処理する；ビルドライン上 0.7.1+ascend3.5 は 11-12 に既にリリース済みで、今期は新規なし。

4. まとめ

  • バージョンライン：2.3.0 のプレリリースイメージがベンダー別に落ち始め、海光 dtk26.10 と dtk26.04 には既に 2.3.0 タグがあり、イメージ内は FlagTree 0.7.1a1+hcu3.6、FlagGems 5.4.0、FlagCX 0.14.1+dtk2610 に固定；コミュニティのスケジュールでは rc0 が 11-30、GA が 12-30 で、今期は「イメージ先行、リリース後追い」に属する。
