1.1 Qwen4 稀疏注意力内核五后端批次，与 Qwen3.8-Flash-Next 发布同频（08-27）

来源：FlagGems-vllm #715、#716、#717、#718、#719

  • 8/27 13:52~23:06，liuhycs 连续合入 5 个 Qwen4 内核 PR：qwen4_compress_norm_mrope_store_groups（压缩归一化与 mrope 组存储）、qwen4_qsa_mqa_paged_dot（QSA MQA page 化点积）、qwen4_ple_state_scatter（PLE 状态散射）、qwen4_hc_inject_combine（HC 注入合并）、qwen4_store_qsa_kv_rows（QSA KV 行存储）。
  • 每个内核均提供昇腾910、海光 DCU、天数智芯 Iluvatar、沐曦 MetaX、摩尔线程 Mthreads 五后端的厂商优化版 Triton 实现（如昇腾 2D grid 单 warp、海光 3D grid 四 warp 等按芯片内存特征调优）。
  • 与 8/26 合入的 Qwen4 自研 Triton 内核及厂商基线（#713/#681）形成”自研 + 厂商优化”双轨。

解读：Qwen4 架构的核心特征是稀疏注意力（QSA）——阿里官方预告 Qwen3.8-Flash-Next 即基于 Qwen4 架构（ModelScope 页面明示）。FlagOS 在模型正式可用前已完成 QSA 全链路内核（KV 存储、压缩归一化、page 点积）的五后端适配，是”模型未至、算子先行”的 Day-0 前哨储备；结合 2.1 头条，Qwen4 架构的 FlagOS 适配链条（内核→推理→部署）已基本就绪。

1.2 Torch-FL：TileOPs 可选算子库集成、Apex 优化器零拷贝视图启用（08-28）

来源：Torch-FL #44、#216、#212、#211

  • #44（8/28 09:23 合入，lvyufeng）：将 TileOPs 集成为可选的 SM90 专用算子库，覆盖 60 条由 TileOPs manifest 代码生成（而非手写）的 aten 对齐路由。关键结论修正：此前的调研认为”适配器必须逐算子手写”，实际发现构造参数可从 aten 调用点机械推导（102 条对齐中 68 条可自动推导）。
  • #216（8/28 09:22 合入，lvyufeng）：通过在 Apex 的 MultiTensorApply 入口将 flagos 张量转为零拷贝 CUDA 视图，启用 NVIDIA Apex FusedAdam/SGD/LAMB 优化器。值得注意的是该 PR 由 Claude Code CLI（Claude Opus 5）编写、人工评审（见 3.4）。
  • #212/#211（8/27 13:10~14:47）：恢复 PrivateUse1 上 aten::narrow 的 autograd；各后端 copy 路径遵循 lazy conj/neg 数学位。

解读：Torch-FL 的路径从”逐算子适配”转向”按 manifest 代码生成 + 复用上游算子库”，将显著降低新后端算子覆盖成本；Apex 优化器启用补齐了 flagos 设备训练侧的优化器生态缺口。

来源：build-infra #598、#597、#596、#595、#594、#593、#591

  • #597（8/27 21:38）：昇腾 CANN 8.5.0 运行时依赖（decorator/attrs/psutil）补齐——昇腾验证线跟进 CANN 8.5。

来源：flir #68、community #95、FlagTree #1054、#1053

  • FlagTree #1054（8/27 20:43）：[TLE] 为每个后端补充 supported TLE primitives 清单；#1053（8/27 14:11）[XPU] 修复 Discrete offset 链回绕问题。

解读：FlagOS 编译器栈（FlagTree/flir/KMCompiler）进入”IR 抽象层设计“阶段——Common IR 提案是面向 DSA（专用加速器）与 GPGPU 统一编译的前瞻性设计，TLE 原语清单全后端化则提升编译器前端一致性。

四、总结

窗口主线：一、Qwen4 架构储备与 Day-0 适配同频共振——FlagGems-vllm 单日合入 5 个 Qwen4 稀疏注意力内核（QSA KV 存储/压缩归一化/page 点积等）覆盖昇腾/海光/天数/沐曦/摩尔线程五后端，同日摩尔线程联合 FlagOS 宣布 Qwen3.8-Flash-Next（基于 Qwen4 架构）Day-0 适配完成、BF16 版本开源至魔搭与 HuggingFace，打破组件级新闻八日零命中。二、框架层架构升级——Torch-FL 集成 TileOPs 代码生成算子库（60 条 aten 路由）并启用 Apex 优化器，FlagScale 新增 Qwen3.6 backbone。三、“无 CUDA 依赖”实证——build-infra 用摩尔线程 MACA 工具链编译 sgl-kernel 并双编译路径 E2E 通过，推理内核层去 CUDA 绑定取得可复现证据。四、成员单位纵深——燧原 FlagCX 通信流闭环、昇腾 CANN 8.5.0 跟进、vllm-plugin-FL 0.2 维护线收敛向 main 迁移。五、AI Agent 开发模式现身 FlagOS——Claude Code 全程编写的 Apex 修复 PR 合入。

下一观察点：vllm-plugin-FL v0.3.0 正式版（rc0 已出，W8A8 0.24 适配与 CI 迁移已合入 main 线）；Qwen3.8-Flash-Next 的 BF16 镜像在魔搭 FlagRelease 账号的落地与多芯片扩展；Qwen4 QSA 内核在 vllm 侧的开箱验证；FlagScale Qwen3.6 训练验证；flir Common IR 的 SIG 推进（community #95）；FlagGems 5.3.5 全后端重验收尾；OASIS-AI 征稿 8/31 截稿。
