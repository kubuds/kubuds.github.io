  • 規模：63 件のマージは今号の単一バックエンドの中で最多であり、すべてに KernelGen と Enflame タグが付いており、タイトルは GCU300 のハードウェア動作を直接指している。
  • 典型的な問題：index_copy_ の clone 起動は grid.x の上限内に収まる必要がある。searchsorted は int32 を返し、out= への書き込みをスキップする。nonzero_static の座標は int64 レーンの算術で破壊される。cummin のループカーネルは NaN を伝播する必要がある。one_hot は範囲外のカテゴリを拒否する必要がある。
  • 判断：これらは新規オペレータの数ではなく、境界条件における正確性の収束である。燧原バックエンドはすでに「動く」段階を越え、オペレータごとに欠陥を摘出する品質段階に入ったことを示しており、この種の作業量は通常オペレータの追加よりも大きい。

3.2 海光：20 個の専用オペレータが審査中からマージ済みへ（11-09）

日付：2026-11-09　情報源：FlagGems #8543 から #8551（Hygon 専用オペレータバッチ） · FlagGems リポジトリ

  • 落地：前回のデイリーレポートで「20 個の海光専用オペレータがすべて審査中」と記録したが、今回はこの 20 件がすべてマージされ、同一バッチの作業が収束した。
  • 対象範囲：igamma、lstm、histc、conv_tbc_backward、grid_sampler_3d、nuclear_norm、mixed_dtypes_linear、special_chebyshev_polynomial_t などを含み、特殊関数、リカレントネットワーク、サンプリング系オペレータが中心。
  • 付随対応：FlagAttention #129 で同バッチにて海光を含む 4 社のオペレータテスト失敗を修正しており、マージ前にクロスベンダー回帰を実施したことを示している。

3.3 昆仑芯：25 件のオペレータマージと atomic-free カバレッジ（11-09）

日付：2026-11-09　情報源：FlagGems #8631（atomic-free 上書き） · FlagGems #8578（adaptive_avg_pool2d 精度） · FlagGems #8523（foreach_lgamma 解析）

  • オペレータ：25 件の KernelGen オペレータが調査期間内にマージされ、汎用数学とプーリング系をカバー。
  • 正確性：#8631 は hash_tensor と histogram シリーズに非原子化上書きを追加し、XPU 上の原子操作による不確定な結果を回避；#8578 は adaptive_avg_pool2d の .out 精度失敗を修正；#8523 は foreach_lgamma のオペレータ解析失敗を修正。
  • アプリケーション層：sglang-plugin-FL #169 で昆仑芯バックエンドを SGLang 0.5.18 に更新、まだ審査中であり、アプリケーション層適配の次のステップ。

3.4 昇騰：41 件のオペレータマージ、KMCompiler の 2 件の性能最適化（11-09）

日付：2026-11-09　情報源：FlagGems #8567（linear 最適化） · FlagGems #8573（log_sigmoid_backward 最適化） · FlagBLAS #161（昇騰 L1）

  • オペレータ：41 件の KernelGen オペレータがマージされ、kl_div、floor、inverse などの汎用オペレータを含み、今回は第 2 位のバックエンドキュー。
  • 性能：#8567 は昇騰バックエンドの linear を最適化、#8573 は log_sigmoid_backward を最適化、2 件は KernelGen ではなく KMCompiler ラインを通じており、手動チューニングに属する。
  • 層次延伸：FlagBLAS #161 は昇騰に L1 サポートを追加、FlagCX #700 は昇騰 IPC と GPU MR を追加——オペレータ、数値ライブラリ、通信の 3 層が同日に推進された。

3.5 沐曦、摩尔線程、天数、清微、平頭哥：単点最適化と修正（11-09）

日付：2026-11-09　情報源：FlagGems #6811（MetaX C550） · FlagGems-vllm #1121（平頭哥 PPU-ZW810E） · FlagGems #6705（摩尔線程 addmm） · FlagGems #8625（清微インポート修正）

  • 沐曦：#6811 MetaX C550 向けに MM と BMM を最適化；FlagGems-vllm #1069 は共有サンプリングフィルタインターフェースで top_k_top_p を実装；FlagCX #699 は AllToAll のデータ検証を修正。
  • 摩尔線程：#6705 で addmm の最適化バックエンド実装を追加、ほかに FlagAttention #129 でそのオペレータテスト失敗を修正。
  • 天数：FlagGems #8310 で linalg_det を単一 warp 起動の panel/blocked カーネルに変更し、マルチ warp 下の数値・同期問題を回避。
  • 清微：#8625 で cache_results のインポートエラーを修正。
  • 平頭哥：FlagGems-vllm #1121 で chunk_kda の PPU-ZW810E 上の実装を最適化；FlagTensor の 5 コミットで PPU デバイスとベースライン検出を修正し主ブランチにマージ。ここでの PPU は平頭哥（T-Head）の AI アクセラレータカード系列に属し、玄鉄（達摩院）の RISC-V プロセッサとは無関係。

4. まとめとトレンド観察

  • オペレータ生産が一括量産段階へ：217 件のマージのうち FlagGems が 166 件を占め、しかも 137 件が 2 時間に集中して着地した。これはこれまで見られなかった単日規模である。KernelGen は「オペレータを書く」を「生成結果を審査する」に変え、ボトルネックは明確にレビューと受け入れ側に移った——審査中はなお 252 件ある。
  • オペレータライブラリが LLM から全モダリティ生成へ拡大：FlagOmni のリポジトリ開設により動画・画像・音声生成のラインが補完され、FlagGems（LLM 推論）、FlagGems-vllm、FlagGems-sglang（フレームワーク専用）と階層を形成。加えて従来の FlagCV、FlagAudio、FlagMRI-3D により、領域オペレータライブラリのマトリクスが概形を成した。
  • バックエンドの対象が「動く」から「正確性を突き詰める」へ：燧原の 63 件はほぼすべて GCU300 上の境界欠陥修正であり、新規オペレータではない；昆仑芯は非アトミック上書きの補完、天数は単一 warp 起動への変更、清微はインポート修正——こうした作業はカバレッジが頭打ちになった後の品質段階を象徴している。
  • バージョンラインが転換中：vllm-plugin-FL の 0.4.0-dev はすでに 0.5.0-dev へ前方同期され、SGLang 0.5.18 の昆仑芯と PPU 対応は審査中、build-infra は wheel ディレクトリを同期再構築中。三つの動きは同じことを指す：次期バージョンマトリクス向けに配布可能な成果物を準備すること。
  • 要観察：FlagOmni が build-infra のコンポーネントマトリクスと docs のコンポーネント一覧に組み込まれるか；コンテストが 11-13 に終了した後、性能成績が現れるか；海光が 20 件のマージ後、第 2 弾の専用オペレータを引き続き補完するか。
