1.3 FlagQuantum：53 件のコミット、20 件のマージ、ネイティブ Rydberg が契約からコードへ（10-22）

日付：2026-10-22　情報源：FlagQuantum コミット · PR #700 · PR #707 · PR #714

  • 総量：53 件のコミット、20 件のマージ。コミットは組織全体の 40% を占め、マージ数は第 2 位。前回（84 件のコミット、34 件のマージ）と比べて規模は半減したが、性質が変わった。前回は動的回路の Program IR と図出力の補完チェーンであったのに対し、今回は中性原子物理がドキュメントから実行へと落ちてきた。
  • Core フロントエンド（#700、22 ファイル、+2198/−16）：ネイティブ Rydberg 制御はもはや回路アダプタを借用せず、Core が ProgramRecord 上で直接フロントエンドを提供する。レコードには型付きの context と control フィールドが追加され、既存のバリデータは単一の物理 profile のみを受け入れ、CFG/SSA 検査を再利用する。連続パスの安全性は符号化座標上の厳密な算術で判定され、数値解法と分離されている。ソース符号化は既存のスカラーコーデックを再利用し、ネイティブ専用の厳密なフィールドと規範検査は、あらゆるテンソルデコードの前に不正入力を拒否する。新しい IR 階層、バインダ、ソルバ、レジストリ、ルートエクスポートは導入されていない。
  • ユーザー API：RydbergProgram は原子、サイト、長さと時間の単位、C6、損失率、最小間隔、輸送チャネルと駆動チャネルで構築され、move、pulse、to_ir の 3 つのアクションを提供する。サンプル出力は原子識別子 ('a','b')、次元 (3,3)、制御位置 (3.0,0.0)、生存オペレータ形状 (9,9)。PR には「制御位置は物理的存在を表さない」と明記されている。
  • Simulation（#707、19 ファイル、+1488/−188）：ネイティブ Rydberg プログラムは既存の Lindblad 計画、実行、初期密度随伴の入口を利用でき、ユーザーが原子、線形輸送、パルス、吸収損失を宣言すると、Simulation が区間行列を自ら組み立てる。plan 1.7 はちょうど 7 つの外層フィールドで密封され、実行時にソースを再コンパイルしない。実験的な数値パスは CPU-only で、1〜2 個の g/r/lost ロールを持ち、より大規模なものは指数的なメモリ割り当ての前に拒否される。幾何は線形パスを適用した区間中点近似であり、グリッド収束の証拠とソルバ精度は別々に記録される。
  • Examples（#714、3 ファイル、+217）：2 つのパルス振幅バインディングを訓練し、原子対を移動させる。40 ステップ、128 区間の実測出力は次のとおり：無条件 RR は 0.0431 から 0.1228 へ上昇、生存条件 RR 0.1500、no-flag 選択 RR 0.1439、厳密数値リプレイは成立。ローカルのデフォルト全量は 14,584 通過、167 スキップ、約 518 秒。初回の 64 区間では 2.28e-10 で 1 つの勾配が失敗し、128 区間へ細分化した後に通過し、ソルバとアサーションは変更されていない。
  • 判断：1 日のうちに、量子スタックは「原子とパルスを宣言できる」から「動力学を計算できる」、さらに「制御パラメータを訓練できる」へと 3 段階をつなぎ、しかも各段階で能力の境界を明記している（サンプリングイベント、フィードバック、加熱、量子運動、GPU や分散を主張せず、M3 の完了も主張しない）。これは今シーズンで最も情報量の多い単一リポジトリの推進方法である。まず契約を拒否可能な実装として書き、その後でブロックごとに開放していく。

  • ビルド層の収束：昆侖芯が FlagTree の第 7 バックエンドとなり、flagcx 0.14.0 が 20 バックエンドに固定され、optest がインストール可能なパッケージになった。三者を合わせた効果は「バックエンドを交換する際にインストールスクリプトを変更する必要がなくなる」ことであり、これは単点の性能向上よりも 2.3 のデリバリー速度を大きく左右する。
  • 可観測性が新たな弱点に：清微は初めてデバイスタイムラインを持ち、昆侖芯のクロスカードコピーはこれまでずっとサイレント失敗していた。この 2 つの出来事は、マルチバックエンドが「動く」ようになった後の最初のハードルが可観測性と再現性であり、より高速ではないことを示唆している。過去 2 週間のテスト移植とユースケース契約の改修（lukatao 一人で 61 件）は、まさに同じ判断の別の表現である。
  • リスク点 1：FlagQuantum の 20 件のマージはすべて単一アカウントによって完了しており、新規追加されたネイティブ Rydberg パスは CPU と 1〜2 ロールのみをカバーしている。物理セマンティクスの検証は同一の人々がテストと実装を書くことに依存しており、外部から独立して再確認できない。提案 083（終端サンプリング）はまだ承認されておらず、急速に推進されれば Runtime、測定結果、乱数源の 3 箇所を同時に変更することになる。
  • リスク点 2：燧原 #7077 のような「一括更新」は照合可能な明細を欠いており、26 ファイルと +3520 行を具体的なオペレータと具体的な収益に対応付けられない。昆侖芯の融合 MoE の 3 項目の性能も代替ベースラインで測定されている。両者とも、今後のクロスベンダー比較を歪めることになる。
  • 観察点：vLLM 0.28 の次のベンダー（清微または沐曦）が海光の empty バックエンドテンプレートを再利用するか；FlagTree 0.7.1 開発ビルド（10-20 の 0.7.1.dev1）が 2.3 前に正式版へ移行するか；TransformerEngine-FL の 3 件の NPU PR が週末前にマージできるか；地平線と寒武紀の沈黙が来週のウィークリーレポートまで続くか。
