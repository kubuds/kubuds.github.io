今日の重点：build-infra 全 20 バックエンド vLLM イメージのバッチ認可再構築、2.2 リリース件が rc2.post2 組立へ

日付：2026-09-19、2026-09-20　出典：build-infra #938、build-infra #956、build-infra #934

当期間の build-infra は 43 コミットで org 内で最も密集したラインとなり、動きは高度に集中している：全 20 バックエンドの vLLM イメージに対し 2.2.0 / プラグイン post2 の再構築を認可し、再構築結果を逐次後方へ書き戻した。09-20 03:07 の app changelogs: authorize the 2.2.0 / plugin-post2 rebuild for all 20 images（#938）が号砲となり、その後 09-20 03:07 から 10:28 までの一時間余りで、ボットアカウントがバックエンドごとに新しいイメージ tag を順次記録した；09-20 09:43 にはさらに一条 authorize the 2.2.0 / plugin-post2 rebuild for all 20 vllm 0.24.0 images を追加し、この一連の再構築の範囲とベースライン（vLLM 0.24.0）をタイトルに明記した。

記録されたイメージタグは org の全バックエンドマトリクスをカバーしている：2.2.0-0.3.0rc2.post2 の一档は昇騰（cann8.5.0、cann9.0.0 及び 2 つの 910c 変体）、寒武紀（neuware4.4.3 / 4.7.2）、摩尔線程（musa4.3.6 / 5.2.0）、燧原（tops1.9.10 / 1.10.6）、沐曦（maca3.7.2.1 / 3.8.1.3）、海光（dtk26.04）、天数（corex4.5.0）、昆侖芯（xre5.37.1）、中昊芯英（tangrt1.2.0）と英偉達（cuda12.8 / 13.3）に落ちている；さらに早い一档 0.2.2rc2.post2（プラグインバージョン）が先行して一批落ちている。単一ウィンドウ内で 20 個のバックエンドイメージが全て刷新され、これは本ウィンドウの org 内で最大規模のアクションである。

これと配套するのはプラグイン wheel の配布方式の変更である：09-19 23:34 の vllm-plugin wheel: build once, publish to every vendor index（#934）は「各ベンダーごとに 1 回ずつビルド」を「1 回ビルド、全ベンダーインデックスに公開」に改め、続く 2 本のコミットでバージョン番号を git ref から導出するよう変更し（#932）、runs-on パラメータの拆包問題を修正した（#935）。このチェーンはプラグイン配布を「N 回ビルド」から「1 回ビルド + N 回リリース」に圧縮し、リリースエンジニアリングにおける構造的な最適化である。

もう一本の並行する収尾ラインは「イメージに一体何がインストールされているか」を検証可能な事実にするものである：vllm app image: read the installed plugin version past the entrypoint（#937）はイメージにプラグインバージョンを自己申告させ；docs: print TBD for an app image that was never built（#948）は一度もビルドされたことのないイメージをドキュメント上で明確に TBD と標記し；changelogs: name the FlagTree each 2.2.0 vllm image actually builds on（#953）はイメージごとに実際のコンパイルベースを標注した。三箇所はいずれも「ドキュメントと制品の不一致」の余地を減らしている。

ウィンドウ内のアクションを並べて見ると：2.2 のリリース件装配はすでに「全バックエンドイメージの一括再ビルド + バージョン検証可能 + 配布通路の統合」の段階に達しており、リリース時間表上の GA（2026-09-28）まで残り 8 日、テストと安定期内の正常な推進リズムに属する。

FlagGems の今期 38 件のコミットは引き続き KernelGen の成果を基調としている：Nvidia 側ではオプティマイザ融合オペレータ _fused_adagrad_（#5917）と _fused_sgd_（#5878）が新規追加された；Experimental リポジトリ（1.8 参照）では同日、別途十件の Nvidia オペレータが取り込まれた。今期最も集中的なラインは昆仑芯バックエンドの修正：binliu が連続して約十件のコミットを着地させ、grouped_mm の大 M / 小 K 形状における persistent kernel スケジューリングと形状別自動チューニング、SDPA アテンション修正（value-1 パラメータの非特化維持、自動チューニングの収束）、mse_loss の第一段階を全ブロックマスクに変更（#6476）、scatter / log_sigmoid_backward / amp_foreach、fill / add_relu / special_log1p / dequantize、pow / pdist / ルジャンドル多項式、segment_reduce / arcsinh / cosh / acosh / log2 / log10、bessel_y1 / bernoulli、t_copy / selu / reflection_pad2d、log_softmax / logical_not、および lgamma 移行時の誤削除修正などをカバーし、ほぼ当該バックエンドの最近のオペレータ回帰を「在庫一掃」した。

ツール側は二件：[KMCompiler] operator linalg_lstsq bug fix（#6499）、[KMCompiler] fix fp64 error（#6491）と delete uint8 dtype（#6477）；MThreads 側では feature_dropout_ の復元と分割を修正（#6490、#6482）。ベンチマークと CI 側：Fix(benchmark): align pytest markers and op_name with operator registry ids（#6489）、ci: run pre-check jobs on basic-runner-cpu（#6431）。

FlagSparse の今期 39 件のコミットはほぼすべてが協力パートナーの双分支協働フロー（NCIC-AlphaSparse の二つのアカウントが交互にマージ）によるもので、テーマは三バックエンド適配である：MUSA（摩尔線程）ラインは musa updates をコミット；MACA（沐曦）ラインは maca spsm debug と maca test commands をコミット；DCU（海光）ラインは dcu updates、dcu sddmm tests、ci dcu および dcu spgemm test fp32 fp64 sperated（spgemm の単精度・倍精度テストを分離）をコミット。ほかに cwrapper add（C ラッパー層の追加）と「New update」に対する一度の revert（#63 でロールバック、#64 で撤回）、およびドキュメント整理がある。全体としてはスパースオペレータライブラリを国産三バックエンドに向けて実体化していくプロセスである。

1.6 FlagQuantum：アルゴリズムプリミティブパッケージを大幅拡張——QFT、位相推定、Grover、QUBO など十余項（09-18~09-20）

3.1 昆侖芯：FlagGems バックエンド修正の一括着地（09-20）

日付：2026-09-20　情報源：FlagGems #6317、FlagGems #6476

4. まとめとトレンド観察

  • リリース物が全バックエンド一括再ビルド段階に進入：20 のバックエンド vLLM イメージが 1 つのウィンドウ内で全て rc2.post2 に更新され、イメージ自己申告バージョン、ドキュメントの TBD 表記、個別のコンパイル基盤注記という 3 点が同時に着地——「リリース物の検証可能性」が今回のエンジニアリングの重心となり、GA（09-28）まで 8 日、ペースは正常。
  • プラグイン配布パラダイムの変化は記録に値する：「一度ビルド、全ベンダーインデックスへリリース」（#934）は N 回のビルドを 1 回のビルド + N 回のリリースに圧縮し、この種のインフラレベルの簡素化は今後の各バージョンのリリースコストを直接的に削減する。
  • マルチチップバックエンド修正の密集期：昆仑芯（約 10 件）、海光（Flash Attention + Qwen-Image）、沐曦（SDPA 修正）、昇騰（専用線形オペレータ）が同一ウィンドウに集中修正を行い、2.2 テスト期間（09-01 から 09-24）が「バックエンド別清算」段階に入ったことを反映；昆仑芯が grouped_mm の大 M / 小 K 特化を処理しているのは、MoE シーンに的を絞った最も直接的な証拠である。
  • FlagQuantum の拡張速度は全 org で最速の方向の一つ：単一コントリビュータが 48 時間で 23 コミット、プリミティブ（QFT、位相推定、Grover、振幅推定）からアプリケーション（QUBO 特徴選択、量子 PCA、k-medians）まで連鎖的に敷設し、同時に QEC 記録層を整備——「量智融合」のコードレベルでの具体的進捗。
  • T-Head の二路線参入：PPU バックエンドで TLE + KernelGen オペレータのブリッジをメインラインに導入し、2.2 マルチバックエンド計画における T-Head の位置づけと合致、玄鉄方向の FlagOS スタック内での参与度が持続的に深化。
  • エコシステム活動が大会サイクルに進入：10 月 17-18 日に FlagOS 技術大会の参加登録が開始、ワークショップのテーマ（KernelGen、端側、TLE Attention、FlagScale-Agent）はこれまでのエンジニアリング観察と一対一で対応；MiniCPM チャレンジ賽は 9/21 に開幕——9 月下旬以降、エコシステム運営密度は顕著に上昇する。
