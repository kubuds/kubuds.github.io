一、开源项目进展（GitHub 动态）

窗口总览：org 内 52 个仓库中 17 个在窗口内有推送；commit search 命中 87 条唯一窗口内提交（build-infra 55、FlagGems 19、FlagTree 4、Torch-FL 4、FlagGems-vllm 2、sglang-plugin-FL 1、FlagCX 1、FlagScale 1），另有 TransformerEngine-FL、Megatron-LM-FL 各 1 条。窗口头条是海光（Hygon）DCU 在 FlagOS 的「训练-通信-推理」三线入列：FlagScale 增 BW1000 CI、FlagCX 增 DCU 适配与 CI、sglang-plugin-FL 增 HCU vendor 后端。本窗口主线可概括为「新厂商后端入列 + 既有验证矩阵在 FlagGems 5.3.5 新版本线下的重验」。

1.1 海光 Hygon 三线入列——FlagScale BW1000 CI、FlagCX DCU 适配、sglang-plugin-FL HCU vendor（窗口头条）

来源：FlagScale #1272、FlagCX #541、sglang-plugin-FL #35（8/25 11:48-19:44 合入）

  • FlagScale（训练）：#1272 为训练工具链增加 Hygon BW1000 CI 支持（8/25 11:48 合入）——海光 DCU 进入 FlagScale 官方 CI 矩阵。
  • FlagCX（通信库）：#541 完成 Hygon DCU 适配与 CI workflow（8/25 12:32 合入）——跨芯片通信库补齐海光后端。
  • sglang-plugin-FL（推理）：#35 新增 HCU vendor（8/25 19:44 合入）——在 SGLang 0.5.11 上支持 DCU 平台：厂商检测与初始化、DCU 设备管理、内核优化，已完成基础推理与 serve 测试。

解读：这是海光在 FlagOS 生态中从「FlagSparse DCU 测试健壮性」（8/22-24）走向「训练、通信、推理三线官方支持」的关键一跳。至此 FlagOS 成员单位中的 GPU/DCU 厂商（摩尔线程、燧原、天数智芯、沐曦、寒武纪、海光）几乎全部进入官方 CI/后端矩阵，海光是其中最新完成三线覆盖的一家。昨日报告观察到「推理侧验证矩阵集体翻绿」向摩尔线程、沐曦扩散，本窗口再添海光，验证范式模板化的复制效应持续显现。

1.2 build-infra：FlagGems 5.3.5 版本推进，寒武纪/沐曦多后端重验（08-25/08-26）

来源：#534（flaggems 5.3.5 bump）、#561（寒武纪重验）、#535（沐曦）、#558（燧原）、#560（天数智芯）

  • FlagGems 5.3.5 进入 app image 依赖线：#534 将 build 配置中 flaggems bump 至 5.3.5（8/25 15:10），并同步简化 flaggems release workflow（#555）——这是 FlagOS 2.1（6/24，FlagGems v5.3.0）之后算子库在镜像线中的又一次版本推进。
  • 寒武纪（Cambricon）重验：#538/#539 记录 neuware4.7.2 app image tag 后，将 vllm 0.20.2 的 T 列单元格重置为 pending 以待 5.3.5 重验；#561（8/26 07:53 合入）完成 neuware4.7.2 + flag_gems 5.3.5 验证并关闭。
  • 沐曦（MetaX）：#533 记录 maca3.7.2.1 的 triton scalar-return bug；#535 在 5.3.5 修复后关闭该记录，并新增 maca3.8.1.3 验证备注；#526 记录 metax 后端 vllm app image tag 2.1.2-0.2.1_g3bc66eb.d20260825。
  • 燧原（Enflame）：#558 将 triton_gcu 的 TOPS 更新至 1.10.6（8/25 22:43）。
  • 天数智芯（Iluvatar）：#560 为 runtime 增加 filelock 依赖（8/25 23:15，次日 #562 回退——依赖已由镜像提供）。
  • Megatron 侧：#527/#528/#529/#530 记录 megatron 全量 wheel 重建（0.17.1+fl.20260822）与 cambricon-neuware4.4.3 app image tag。

解读：FlagGems 5.3.5 的推进引发一轮「全后端重验」——寒武纪、沐曦两家的 vllm 0.20.2 验证单元格被重置后重新跑通，验证矩阵在版本演进中保持可信。各厂商软件栈版本（沐曦 maca3.8.1.3、燧原 TOPS 1.10.6）持续迭代，build-infra 作为「版本对齐中枢」的角色愈发清晰。

1.3 build-infra：验证驱动工程硬化收官——并行、隔离、长超时（08-25）

来源：#531、#536、#540、#552、#556、#557、#563、#564

  • vllm 与 megatron 两套 verify-driver 并行运行（#536）；每后端验证运行相互隔离、避免并发冲突（#540）。
  • 验证产物按 run_id 命名上传（#531）；失败单元格细节回显到运行日志（#540）；megatron 侧用 NullTokenizer 避免 wget 下载、补 model-size 参数（#527/#529）。
  • 停止 verify-driver 自动重触发循环（#557）、移除 PSUTIL_PREINSTALL 死代码（#556）、serve 就绪轮询超时 300s 升至 900s（#563）、completion 请求超时 120s 升至 600s（#564）——长任务验证不再因超时误判失败。

解读：接续昨日「验证驱动硬化」，本窗口将 E2E 验证从「单机串行+固定超时」推进到「并行+隔离+长超时+可审计产物」的工程化形态。多后端矩阵规模扩大后，验证基础设施本身成为瓶颈，此轮硬化是为下一批新厂商（海光等）入列做的工程准备。

1.4 FlagGems：KernelGen 算子扩充与多后端优化（08-25/08-26）

来源：FlagGems commits（窗口内 19 条提交）

  • KernelGen Nvidia 侧新增 6 算子：miopen_batch_norm（#3936）、divide（#5162）、native_batch_norm（#5177）、native_group_norm（#5178）、true_divide_（#5206）、special_gammaincc（#5315）——Triton 内核逐个落地。
  • KMCompiler 昇腾侧：log_sigmoid_backward 性能优化（#5718）、exponential 算子（#5682）、linalg_lstsq 入口加 stages（#5700）、linalg_det 测试修复（#5701）。
  • 摩尔线程（MThreads）：AddMM layouts 与 bias epilogue 优化（#5384）。
  • 寒武纪：tensor mask 改用 elementwise 位运算替代 Python and/or/not（#5745，配合 5.3.5 重验）。
  • 天数智芯（Iluvatar）：新增 repeat_interleave.self_int 专用内核、matmul_bias_activation 优化（8/26 09:41，窗口最新提交）。
  • 其他：Metax conv_depthwise2d（#4762）、QC fp8-w8a16 Rmsnorm 优化（#4437）、conv2d_padding/baddbmm/any_dim 精度修复（#5445/#5336/#5381）。

解读：KernelGen 算子覆盖继续向 norm 族/数值函数族扩张，KMCompiler 昇腾侧与 Iluvatar 新后端同步提速——「新后端适配与算子覆盖双线并行」的节奏未变。

3.1 燧原科技启动科创板发行：拟募资 60 亿、9 月 2 日申购（08-25）

来源：钛媒体（8/25）、中财网、东方财富

  • 8/24 晚披露招股意向书，8/25 正式启动科创板发行：股票代码 688801，拟公开发行 4303.5173 万股（占发行后总股本 10%），募资 60 亿元——其中约 15.03 亿投向第五代 AI 芯片研发及产业化、11.97 亿投向第六代、33 亿投向先进 AI 软硬件协同创新项目。
  • 发行节奏：8/28 初步询价、9/1 刊登发行公告、9/2 网上网下申购；中信证券保荐，国泰海通、广发证券联席主承销。
  • 财务：2023-2025 营收 3.01/7.22/9.90 亿元，归母净亏损 16.65/15.10/11.64 亿元，预计 2026 或 2027 年实现盈利；2025 年对腾讯直接销售及相关模式收入占比 83.79%，腾讯及其一致行动人合计持股约 20.26%。
  • 若顺利上市，燧原将与摩尔线程、沐曦、壁仞并称的「国产 GPU 四小龙」齐聚资本市场。
  • 与 FlagOS 的呼应：燧原是 FlagOS 成员单位中「新芯片接入前哨站」PyTorch-Plugin-FL 的主要推进者——昨日 sglang-plugin-FL #42 新增燧原 GCU 后端，今日 build-infra #558 更新燧原 TOPS 1.10.6、Torch-FL #187 落地 GCU torch.compile。资本化加速与开源软件栈投入同步推进。

3.2 摩尔线程发布 MTT S5000 Prefill-as-a-Service 白皮书（08-24 发布/08-25 报道）

来源：IT之家/新浪科技（8/24）、凤凰网（8/25）

  • 摩尔线程发布《MTT S5000 Prefill-as-a-Service 技术白皮书》，提出 Prefill-Decode 异构解耦方案：Prefill（计算密集型）与 Decode（访存密集型）分池部署，破解长上下文推理（数百 K 至 1M token）下的结构性算力错配。
  • 实测数据：64K 上下文单机 Prefill 吞吐 95,920 tok/s；400K 极限长序列 TPM 达 2.6M tokens。面向 AI Agent、代码生成、超长文档分析场景，主打「单位 Token 基础设施成本下降」。
  • 摩尔线程是 FlagOS 成员单位中验证矩阵最完整的后端之一（8/24 报告：musa4.3.6/5.2.0 双后端 F/T 双路径全过）；其在长上下文推理侧的硬件打法与 FlagOS 的推理侧验证主线同频。

3.3 沐曦：GPU 智算载荷太空在轨验证获外媒聚焦（08-25）

来源：DIGITIMES（8/25）、腾讯新闻（事件源，7/25）

  • DIGITIMES 8/25 报道「中国 GPU 应用延伸至太空」：搭载沐曦 GPU 智算载荷的「云尖沐曦号」卫星（吉天星 A-04 星，三体计算星座）7/24 随力箭一号遥十五入轨，正在轨验证国产商用 GPU 在太空高能粒子辐射、真空热循环下的工作可靠性——国产智算芯片从「地面验证」到「在轨实战」的关键跨越。事件发生于 7 月底，本窗口内获国际产业媒体再度聚焦。
  • 沐曦官网动态：8/3 宣布曦云 C 系列 GPU Day 0 适配多模态生成模型 MiniMax H3；7/30 与上海 AI 实验室共启 KernelSwift 算子创新大赛。沐曦在 FlagOS 侧（MetaX）的 vllm 0.20.2 app image 与 maca3.8.1.3 验证持续推进（见 1.2）。

四、总结

窗口主线：一、海光 Hygon DCU 三线入列（FlagScale BW1000 CI、FlagCX DCU 适配、sglang-plugin-FL HCU vendor），成为继摩尔线程之后又一完成「训练-通信-推理」全栈官方覆盖的成员单位；二、FlagGems 5.3.5 版本推进引发全后端重验，寒武纪、沐曦验证单元格重置后重跑通过，验证矩阵在版本演进中保持可信；三、verify-driver 工程硬化收官（并行、隔离、长超时、可审计产物），为下一批新厂商入列铺路；四、成员单位资本化与生态双线并进——燧原科技启动科创板发行（9/2 申购、募资 60 亿），摩尔线程发布 Prefill-as-a-Service 白皮书，沐曦太空智算载荷获外媒聚焦。

下一观察点：vllm-plugin-FL v0.3.0 正式版发布（rc0 已出，Qwen3.5 兼容待并入）；昆仑芯 decode scale 修复 #400 合入状态；海光三线入列后首个验证结果；FlagGems 5.3.5 在摩尔线程/燧原后端的重验；Iluvatar（天数智芯）算子适配完成度。

局限性说明：提交数量与合入时间来自 commit search 与 repos/commits API（搜索索引可能略滞后，个别仓库 pushed_at 与主分支提交存在分支同步差异，已用 commits API 核验）；vllm-plugin-FL 的窗口内推送主要为 PR 分支（#405 CI 分支切换），主分支无新功能合入；gnews 跳转链接无法抓取正文，新闻侧判断依赖标题与多源交叉印证；燧原 IPO 募资额与持股比例为招股书口径。
