日付：2026-10-12 ~ 2026-10-13　情報源：Torch-FL #502 · Torch-FL #503 · Torch-FL #504 · Torch-FL #498 · Torch-FL #500

  • #502 ボクシング除去リファクタリング（10-12 22:31 マージ、47 ファイル +5347/-2443）：前の調査期間にマージされたばかりの昆仑芯「CUDA-boxing」方案が全面的に置き換えられた——新たにネイティブの kKunlunxin バックエンドスロット、ベンダー XPU SDK の純 C インターフェース libxpurt に基づくデバイス層（csrc/runtime/accelerator/kunlunxin/）と xdnn オペレータライブラリに基づくオペレータ層（aten/backends/kunlunxin/）を追加し、再生成された登録設定にはもはや cuda ルーティングが一切含まれない。PR の説明には明確に記載されている：チームは昆仑芯が CUDA-boxing を使用してはならず、バックエンドはベンダー XPU ランタイムに直結すべきと決定した——P800 は「CUDA 経由」から「ネイティブホスティング」へ転換した。

1.3 新規公開リポジトリ Trident：実験的 MLIR/LLVM コンパイルブリッジ（10-12）

日付：2026-10-12　情報源：flagos-ai/Trident · README · コミット履歴

  • 位置づけ：Trident は実験的なコンパイルブリッジである——Triton/Torch スタイルの計算を含む Python 関数を MLIR/LLVM にコンパイルし、tvm_ffi を経て実行する；中核は C++/MLIR（CMake ビルド、LLVM/MLIR を外部工程として導入）であり、Python 側は trident.jit と trident.compile のエントリを提供し、サンプルは add / attn / mm / softmax などの ATen オペレータの降下をカバーし、apache-tvm-ffi と torch>=2.10 に依存する。
  • タイムライン：リポジトリは 10-12 16:47（北京時間）に組織内で設立され公開され、master ブランチのコミット履歴は 5 月中旬まで遡ることができ、累計 274 件；調査期間内は 2 件——「refactor: unify FX and Triton imports around TVM FFI」（10-12 23:10）と「test: reorganize coverage and check e2e CUDA memory leaks」（10-13 00:50）。
  • 所見：プロジェクトは 7 月に torch-mlir インポートから FX 直結 TVM FFI への移行を完了しており、形態としてはマルチチップ統一接続に向けた「フロントエンド コンパイルブリッジ」の探索に属し、FlagTree の統一コンパイラ路線と呼応している；今後の方向性（TLE / FlagMega ラインと合流するか否か）は追跡に値する。
