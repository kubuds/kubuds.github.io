1.4 FlagGems：index_put の int32 オフセットオーバーフロー修正、昇騰コンパイラは実行時に固定バージョンを強制するよう変更（10-27）

日付：2026-10-27　情報源：FlagGems PR #6892 · FlagGems PR #7837 · FlagGems PR #7752 · FlagGems PR #7220

  • 正確性：index_put_ と index_put_impl がカーネルを共有するアドレス演算をワイド型に変更（#6892、2ファイルで112行追加・4行削除）。これまで達摩院玄鉄 PPU-ZW810E 上で、int32 インデックスと大きな stride のテンソルの組み合わせがアドレスを静かに誤書き込みし、対象行は変わらないものの同一アロケーション領域内のガードプレフィックスが書き換えられていた。根本原因はインデックス×stride が int32 内で評価されて先に回り込むことであり、事後に最終オフセットだけを変換しても間に合わない。
  • コンパイラ固定：昇騰側で flagtree を 0.7.0+ascend3.5 から 0.7.1a1+ascend3.5 へアップグレード（#7837、5ファイルで291行追加）。バージョン番号の変更だけでは無効——実行時イメージが flagtree を仮想環境の外の /opt/flagtree に焼き込んでおり、pip で入れた pin では上書きできない。reconcile を一層追加してもプリセットパスに先を越され、最終的に新規スクリプトでパッケージメタデータに基づき実行時に検証・是正するようにした。
  • ベンダー最適化：昆侖芯側で slice_scatter と vstack を最適化しベンダーオペレータ表を復元（#7752、sym_numel を借りて登録ロジックが取りこぼしたオペレータを回収）；同一ウィンドウで foreach の dtype ヘルパー（#7832）と 20261026 の一括マージ（#7776）を修正。天数側で conv2d を最適化し、パッキング済み重みをキャッシュして channels_last のチャネル変換を融合（#7220）。
  • KernelGen 側：新規 93 件は依然として NVIDIA 単一オペレータの補完が主体（本ウィンドウの榜内で 23 件が新規）、ほかに Hy4-preview の RMSNorm、BF16 線形と共有 INT8 インデクサインターフェース（#7782）が審査中。
  • 判断：本リポジトリの当日の価値は「静かなエラー」であって新規オペレータではない。index_put のようなアドレス誤書き込みはテストではエラーにならず、特定のバックエンドと大きなテンソルでのみ現れ、リリース後に破綻するタイプである。

  • ペース：24 時間の調査期間で 20 リポジトリへのプッシュ、98 件のマージ、401 件のレビュー中（うち 135 件は 1 回のバッチコミット）、マージ量は前日の 133 件から 26% 減少した。プッシュされたリポジトリ数は 2 週間ぶりの高水準だが、増分は主にボットによる記帳とバッチコミットによるもので、実質的なコード変更は前述の十数件に集中している。
  • バージョン：2.3.0 のアプリケーションイメージは既に 20 のバックエンドで記帳済みで、ランタイム変更記録も補完中だが、バージョンタグは未付与、リリースマニフェストも未作成。節目となるのは 11 月 13 日の FEP マージ締切と 11 月 30 日の rc0 であり、その時点で community/release/2.3 にスケジュール表しかなければ、rc 期間は圧縮される。
  • ルール：0.32 単発・0.28 スキップの決定により、バージョン追従コストは 1 回のスキップに圧縮されたが、その代償として 0.28 でマージされた適配（燧原 S60、天数、沐曦、玄鉄など複数ライン）を 0.32 で再検収する必要があり、この作業量はまだどの PR にも反映されていない。
  • カバレッジ：沐曦は 135 個の特化オペレータを実験リポジトリのバッチ PR 形式で提出し、メインリポジトリへ直接投入しなかった。これは実験リポジトリが「検収証拠を監査可能」という役割を担っていることを示す。メインリポジトリの FlagGems は依然として KernelGen の単一オペレータ補充を消化しており、2 つの流れのレビュー負荷が重なり、本周期のレビュー中件数急増の主因となっている。
  • バックエンド：AMD はベースイメージから設定、パッケージング、wheel 行へと進み、本周期唯一の新規バックエンドとなった。国産側は既存バックエンドの機能補充に集中している（昆侖芯 XPU3、清微図モード、燧原 0.28、天数畳み込み、曦望が初めてリスト入り）。
  • 要観察：FlagQAI 初回エクスポート後の CI 失敗と PR #1。その位置づけ（量子計算合成レイヤ）と FlagQuantum（量子シミュレーションとトレーニング）の境界はまだドキュメントで明確になっていない。FlagGems #7809 の繰り返しクローズ・再オープンも、自動リトライなのかプロセス上の欠陥なのかを確認する必要がある。
