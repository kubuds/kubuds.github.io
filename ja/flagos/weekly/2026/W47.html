6. トレンド観察

  • 基盤層は「バージョン補完」から「ライン交代と撤収」へ：今週は六社の SDK ラインが世代交代、一社が撤収、一社が新規参入。build-infra のマージ 125 件に新機能は一件もない。作業形態は「一ライン一カード」で、リズムは base 先行、runtime 追従、インデックス补齐後にホイール補完で統一。rc0 まで十日、このリズムは寒武紀 4.7.6 が 2.3.0 のデフォルトマトリクスにほぼ間に合わないことを意味する。

  • 性能の語りは host パスとコンテキスト再利用へ移行：Torch-FL はホットスタートの CPU コミットをベンダー PyTorch の 1.17 倍と 1.18 倍に压低し、#822 の 80% 閾値に入る。昇騰 MegaMHC のコンテキスト未事前バインドの Eager はわずか 0.648 倍で、収益が起動とワークスペース再利用に由来し、純粋なカーネル演算ではないことを示す。クロスチップ比較は今後 host ベースラインを同時に示さなければ、数字は比較不能。

  • 受入側がボトルネックに：KernelGen は一日で 43 オペレータを生成し、同日 40 件のコミットが各社バックエンドの精度とタイムアウトを修正。審査待ち行列は 261 から 318 件の間、昆仑芯「287 ops fix」は単件 203 ファイル、+53022 行。オペレータ補完がアライメントより速く、レビュー吞吐が 2.3 のカバレッジを決める。

  • 上流バージョンが下流を同期動作に縛る：vLLM 0.32 は五社が同日開門、六社が審査中、SGLang 0.5.18 は五社が同週収口。両阻塞はいずれも FlagOS 自身のコードではなく、符号契約。例は v2_apply_penalties のような導出欠落、flash_attn_3._C のようなハード import、ECCL の 64 ビット dtype 境界。こうした問題はマトリクスに明示的に記帳するしかなく、リトライで覆い隠すことはできない。

  • 新ハードは世代別にディレクトリ分け、コンパイラインターフェースは世代交代中：昇騰は「一バックエンド」から _ascend/a5 のような世代別ディレクトリに変わり、A5 は 950DT と 950PR に対応。同時に TLE pipeline イテレータが撤下され、FlagGems、FlagGems-vllm、FlagAttention の三ライブラリが同日 tl.range に変更。上層オペレータはコンパイラインターフェースに追随する必要があり、これは常態化している。

  • ニュース面とコード面は引き続き乖離するが、今週の産業叙事には実質的内容がある：コンポーネント名クエリは連続五期間ゼロヒットで、公開報道は依然メンバー単位の資本と製品消息が供給。Token 工場は今週唯一完全な技術数字のある産業イベント。BIS 新規則は唯一外部環境を変えるイベント。デイリーレポートの判断基準は依然コミット、PR、パッケージングマトリクスの一次データを主とする。
