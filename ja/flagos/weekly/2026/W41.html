FlagOS ウィークリーレポート (2026-09-30 ~ 2026-10-07)

2026-10-07 Kubuds

報告期間：2026年9月30日（水）から10月7日（水）まで、計8日間 —— 国慶節休暇特別総括期間 素材出所：本誌の毎日FlagOS動態レポートの休暇前最終号（2026-09-30）および休暇後初号（2026-10-08、期間末尾の接続検証用）；10月1日から7日までの休暇中はデイリーレポートを休刊し、休暇中の動態は本組織の全54のGitHubリポジトリのコミット、PRおよびタグの検証によるものとする（検証は10-08午前まで延長）。ニュース側は休暇期間（約9日間）の複数組のキーワードによる公開検索に基づく 編制説明：休暇期間中も組織の開発は停止しなかった：コミット合計801件（FlagQuantum 712件）、PRマージ412件（FlagQuantum 312件）、新規PR 447件（FlagQuantum 331件）；16のリポジトリにプッシュがあり、12のリポジトリで期間内のデフォルトブランチへのコミットが記録された。対外ニュース側のコンポーネントレベルの検索は平静を保ち、産業側の焦点はDeepSeekが9月30日に昇騰向けの基盤施設コンポーネントをオープンソース化したことである（詳細は第5章）。休暇後初日（10-08）の業務再開ペースは予定通り回復：同日午前の検証時点で、既に14件のPRマージが記録されている。

1. 今週の重要ニュース

  • 休暇期間中も開発強度は衰えず：8日間の調査期間でコミット801件、PRマージ412件（09-30 ~ 10-07）：FlagQuantum 単一リポジトリが712件のコミット（88.9%）と312件のマージを貢献し、組織の休暇期間における開発の絶対的な主力となった。その他のリポジトリは合計89件のコミットで、マルチベンダー CI 移行とドキュメントバッチに集中している。コミットのペースは10-01から日ごとに上昇し（FlagQuantum 単一リポジトリ：10-01 60件、10-05 101件、10-06 194件、10-07 122件）、祝日中盤から後半にかけての強度が全期間で最高となった。
  • FlagQuantum 分散認証キャンペーンが最終局面：two-node が全面的に認証リリース軌道へ（10-01 ~ 10-08）：10-01 #312 で two-node 状態ベクトル、MPS、テンソルネットワーク訓練を production_supported に昇格。#318 / #321 で実測証拠に基づき2ノード claim を再記録しブロッカーを逆算。10-06 #535 で2ノード状態ベクトルを認証し MPS / TN 容量の天井を測定。10-08 朝 #587 で2ノード MPS 訓練を認証し TN 容量上限を記録——two_node_mps_training が release_certified に昇格。認証許容誤差ゲート（#292）と証拠ピン留め（#348）も同時に整備された。
  • FlagGems：KernelGen の供給側大幅前進＋マルチベンダー CI 移行（10-01 ~ 10-06）：kernelgen-dev ブランチ 34件のコミット——226個のオペレータ定義とテスト（#6853）、70個のオリジナルオペレータ定義（#6860）、第1 ~ 28バッチと最終バッチのテストスイート（#6799 ~ #6839）、欠落定義の補完（#6862、thnn_conv2d）。メインブランチ 14件——hygon / metax / mthreads / iluvatar の4社バックエンドテストを runtime イメージへ移行（#6844）、CPU runner プリインストールのフラット化（#6847）、flagtree 0.7.0 バックエンド解析と PPU サポート（#6863 / #6852）。調査期間内のマージは合計47件。
  • build-infra が 2.2 を確定、2.3 を開始（10-01）：夕方17:30に注釈付きタグ v2.2.0 を打刻（注記「Release 2.2.0」。当該リポジトリは GitHub Release オブジェクトではなくタグでバージョンラインを管理）。その後「Bump base version to 2.3.0」（#1316）とルートディレクトリ清理（#1317）をマージし、夜間にワークフロー整備バッチ（#1318 ~ #1321）を完了——インフラリポジトリの開発ベースラインが正式に 2.3 ラインへ切り替わった。
  • FlagCX CRL 転送堅牢化六連（09-30 ~ 10-04）：#633 kernel proxy が共有 RMA 転送に接続、#635 collective proxy と順序付きマルチチャネル / マルチ QP 転送の統合、#636 対称ウィンドウと MR ライフサイクルの堅牢化、#638 GET データを公開完了前に flush、#639 リモート可視性 flush セマンティクスの統一（他 #637 で失効したミラー構築ワークフローを清理）——転送層の正確性堅牢化が休暇期間全体を貫いた。
  • FlagFFT マルチプラットフォーム最適化ブランチの祝日推進（10-02 ~ 10-05）：沐曦 maca-3d-opt と昇騰 npu-2d / npu-3d-opt ブランチが10-02 ~ 10-03に複数回プッシュ。海光側は10-03 ~ 10-04に codex/hcu-fourstep-c2r、codex/hcu-3d-route-fix と -dev 分線を連続開設。摩尔線程 musa-3d-opt は祝日前から起動後、継続的に推進。デフォルトブランチへの新規マージはなく、成果はブランチ形式でレビュー待ち。リポジトリの最終プッシュは10-05 16:10。
  • メンバー単位の祝日バッチが継続的に流動（09-30 ~ 10-08）：沐曦 W8A8 INT8 行列乗算（#6572）マージ、海光 bmm / baddbmm 新規（#6865 / #6866）、昆仑芯 XPU3 SDNN 46-marker 修正バッチ（#6867）、達摩院玄鉄 ADDMM シリーズ性能バッチ（#6859）、昇騰修正三連（#6848 ~ #6850）と Qwen3.6 推論パス最適化（sglang-plugin-FL #137）、燧原 Enflame 特化オペレータ四連（FlagGems-vllm #889 ~ #892）、寒武紀 rotary embedding バックエンド（FlagAttention #84）——詳細は第4章を参照。
  • 産業側の焦点：DeepSeek が昇騰向け基盤コンポーネントをオープンソース化（09-30）：TileLang 高級言語コンパイラツール、計算ライブラリ、分散通信ライブラリを網羅し、すべてのコンポーネントが英偉達プラットフォーム向けオープンソースコンポーネント（DeepGEMM、DeepEP、TileKernels、FlashMLA、DeepSelect）と一対一で対応。同時期に華為と共同で昇騰 950 ベースの128カード超ノード方案（UBL128 ネットワーキングと ASC-COMM 通信ライブラリサポート）を推進中であることを開示。FlagOS 組織の動向ではなく、産業背景として収録（第5章を参照）。
