  • 新規コミットなし（直近は 09-23）。10-05 に issue #286「kendryte-hash: 共有 DMA バッファが SHA-256 ドライバの並行呼び出しに対して安全でない」を受領――ローカルカーネルツリーの並行安全性の議題がキューに進入。

4. ベクトル拡張とオペレータ最適化（VecIntrinBench / IntrinTrans / FBGEMM）

  • 3つの目標リポジトリは全期間静黙：VecIntrinBench（最終コミット 02-13）、IntrinTrans（06-25）、FBGEMM fork（07-13）。同じグループの cpuinfo（05-20）、torq-tile（04-09）も同様に静黙——本調査期間に新規ベンチマークデータはなし。
  • 実質的な進展は隣接ワークラインにあり：行列／ベクトル方向のコード産出は主に——LLVM A100 ドット積と pack/unpack の lowering（#30~#32）、GCC/Binutils の Ztt ドラフトサポート（ztt-dev）、AME-operator の GEMM/GEMV カーネルと検証（詳細は今週の要聞と第2、3節）に集中。
  • 上流とアーキテクチャ側の観察（デイリーレポート由来、09-30 ~ 10-08）：
    • riscv-arch-test の密集合入：ベクトル浮動小数点テスト生成（#2349）、ポインタマスキング拡張（Ssnpm / Smmpm など）のテスト生成、ベクトル EEW 重複を Agnostic として扱う判定基準の修正（#2711）、Sdtrig mcontrol6 カバレッジグループ（#2418）、CHIPS Alliance VeeR EL2 コアの ACT 接続（#2443）など。
    • Sail 0.15 リリース（10-07）：Double Trap 拡張、一部の Sdtrig サポートと基本イベントフレームワークを追加。同時期に Sv32x4 PTE ライトバック、G-stage htval などの仮想化セマンティクス問題を修正。
    • 香山 DiffTest：AME 行列結果 128 ビットハッシュ完了記録（#978）を追加し、行列拡張の差分検証にコンパクトな照合パスを提供。
    • riscv-unified-db：Zvzip 0.3.0（構造化データのインターリーブ／デインターリーブ／ペア転置、開発中バージョン）を追加。
    • ボードレベルとモデル適配：進迭時空 K3 ファームウェアが新デバイスツリー（FML13V05）と COM260 互換修正をサポート。算能 sophon-demo が CV84X6 上の Qwen3 / Qwen2.5-VL などのモデル配備例を追加。
    • CVA6：回帰オーケストレーションを cook.py と統合ダッシュボードに集約（#3612）、ハードウェア検証フローを再現可能化。

6. トレンド観察

  • 休暇モードの分化：「マージ低調、キューとインテリジェンスは止まらず」：3つの組織は8日間でメインリポジトリへのマージが数えるほどしかなかった（riscv-gcc 2件、llvm-project 3件、openRuyi 0件）。しかし PR レビュー、ブランチ更新、インテリジェンスリポジトリとコミュニティチャネルは全期間稼働し続けた。連休明け初日（10-08）未明には早くも PyTorch の全面的な再ビルドと triton の新規 PR が現れ、その回復速度は記録に値する。
  • マトリクス拡張の体系的な布陣：LLVM 側の A100 シリーズのマージ、GCC/Binutils 側の Ztt ドラフトブランチ、オペレータ側の AME-operator オープンソース化、仕様側の公式 AME リポジトリの fork——マトリクス方向は散発的なパッチから「コンパイル-オペレータ-仕様-検証」の並行推進へと移行しており、本期で最も技術的価値の高い構造的変化である。
  • PyTorch RISC-V が「コンパイルできる」から「継続的検証」へ：CI ブログ記事、fork 再ビルド、SyncBots による自動同期がともに「上流追跡、実機リグレッション、問題フィードバック」の閉ループを構成する。次に注目すべきは RVV の2件の PR（#46 / #48）のレビューと、さらなるハードウェアバックエンドの接続である。
  • openRuyi の「エンタープライズ級ソフトウェアスタック」という語り：2026.09 版では Cloudpods クラウドプラットフォーム、Ceph / SPDK ストレージ、GPG サプライチェーン署名をメインラインに取り込み、さらに RVA23 の修正とコンテナ性能パスを重ねている——ディストリビューションの目標シナリオは「動かす」から「本番運用可能」へと転換しつつある。
  • コンパイラ側の命令レベル正確性の継続的修正：BCLR コード生成の修正（openRuyi GCC 16 バックポート）、P 拡張の lowering、A100 と Ztt——ツールチェーンは既存拡張の正確性と新拡張のサポートという両端で同時に成果を上げている。
  • 空白と注目点：隔週レポート 078 期のリリース；llvm-project #25 / #28（FPGA）と #22 クローズ後の標準 AME 路線の行方；openRuyi メインリポジトリのマージ回復と 2026.10 版のペース；ruyiai-daily の連休後の継続性；triton-riscv #85 のレビュー；support-matrix #409 と board-docs #50 のマージペース。
