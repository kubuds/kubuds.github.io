今日の重点：K3 ファームウェア第二版リリース——UEFI 設定に CPU モード選択（X100/A100）を導入し永続化可能；OpenSBI K3 v4 系列と coreboot / EDK2 が同日協調して整備

日付：2026-10-14　ソース：Ruyi Firmware 20261014 リリース、OpenSBI K3 v4 シリーズ接続コミット、edk2-ruyi コミット ba4ff0ad、coreboot k3/port コミットリスト、opensbi k3/port コミットリスト

openRuyi ファームウェアパッケージングリポジトリ ruyifirmware は 10-14 午後（14:42）に第二期ファームウェアリリース「Ruyi Firmware 20261014」を公開した。中核となる特徴は K3 の CPU 構成に選択肢をもたらすことである：UEFI 設定画面に CPU モード選択が新設され、設定は永続化保存されて次回起動時に有効となり、fastfetch などのツールはモードを k3 / k3-x100-a100 / k3-a100 として識別できる。三つのモードは以下の通り：X100 のみ使用（デフォルト、8 基の X100、RVV VLEN 256、H 拡張を保持）；X100 + A100 混在（16 コア、RVV と H 拡張はいずれも無効）；A100 のみ使用（8 基の A100、VLEN 1024、H 拡張無効）。

今回のリリースは K3 ファームウェアスタックの四つのリポジトリが同日午後に協調して完了した：OpenSBI の k3/port ブランチが先行して K3 v4 シリーズを着地（13 筆、FROMLIST プレフィックス 6 筆 09:50、RUYI プレフィックス 7 筆 13:05）；coreboot の k3-pico-itx が SPI 設定により CPU グレードを選択（14:11）、併せてデバイスツリー fixup を payload 引き渡し前に前倒しして実行；EDK2 側では edk2-ruyi が「永続化 CPU 選択モード」を新設（14:11）；ruyifirmware がその後順次 OpenSBI K3 v4 シリーズ（13:05）と K3 CPU 選択モード（14:24）を接続し、パッケージングを完了してリリースした。

第一期ファームウェア（20261013）から本期までわずか一日の間隔で、K3 のデリバリーの重心は経路開通（前日 35 筆の EDK2 プラットフォームコードを一括初投入）からハードウェア構成面へと移行した——CPU クラスタの組み合わせと拡張のオン・オフをファームウェア層の選択に委ねる。観察点：各モード（特に RVV / H を無効化した混在モードと大コアモード）の実負荷下での性能と互換性のトレードオフ、設定永続化のファームウェアアップグレード経路における挙動、そしてそれが openRuyi ディストリビューションイメージ（kiwi-image）や開発中のツールチェーン（K1/K3 適配）との協調にどう影響するか。

5. トレンド観察

5.1 K3 ファームウェアが「設定可能」段階へ：CPU モード選択のトレードオフと協調の観察ポイント

最初のファームウェアバージョン（10-13）から第 2 版（10-14）までわずか 1 日、K3 ファームウェアラインの重心はリンク開通からハードウェア設定面へと移行した：CPU クラスタ組み合わせ（X100 / A100）と拡張スイッチ（RVV、H）をファームウェアが選択・永続化する。観察ポイント：第一に、3 段階モードの実負荷における性能と互換性のトレードオフ——混用モードと大型コアモードで RVV / H を無効化する適用シナリオは実測で画定する必要がある；第二に、設定永続化のファームウェアアップグレード経路と復旧シナリオにおける挙動；第三に、openRuyi ディストリビューションイメージ（kiwi-image）および開発中ツールチェーン（K1/K3 適配）との協調ペース——サミット週（10.18 以降）が迫り、K3 関連成果が集中的に登場するかどうか。

5.2 定例メンテナンスの二本線：PyTorch の朝のリビルドペースは継続、LLVM riscv のリプレイは依然回帰せず

2 本の fork メンテナンスラインは本調査期間も差異が継続：PyTorch riscv ブランチは通常通り朝のリビルドを完了（23 コミット、ヘッド b870a71a）、8 件のオープン PR が 10-14 午前にベースラインを一括更新；LLVM riscv ブランチは 2 調査期間連続で新たな夜間リプレイが見られず（ヘッドは 10-12 バージョンを維持）——リプレイが回帰するか、ならびに ruyisdk/llvm-project の rebase ライン（XTHeadVector 修正はマージ済み）と fork リプレイラインの関係は、引き続き観察対象とする。

5.3 openRuyi の深度メンテナンス面が拡大：グラフィックススタック、ストレージ CI、クロスアーキテクチャチューニングが並行して前進

ディストリビューションのメンテナンスは一括依存関係更新にとどまらない：本調査期間は mesa（26.2.4 アップグレード + PVR 最適化バックポート）、ceph-ci（fork-patches の継続的パッチ）、ruyi-tuner（コンパイル比較結果のディスク出力、v1.x のメインライン統合）がそれぞれグラフィックススタック、ストレージスタック、ツールチェーンの 3 方向で小刻みに前進、加えてファームウェアラインの毎日リリースペースにより、openRuyi の「深度メンテナンス面」はサミット前に持続的に拡大している。観察ポイント：これらの専用ラインの作業と 0.54.0 バージョン、2026.10 イメージリリースペースとの結合方式。
