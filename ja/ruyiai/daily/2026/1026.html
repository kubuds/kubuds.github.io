今日の重点：BUDDY MLIR 0.1.2 リリース、openRuyi メタデータ修正 PART I が一度に102件着地（10-25）

今回は 3 日間の調査期間であり、最も記録に値するのは 3 つの出来事で、ちょうど 3 つの組織にそれぞれ属している。

第 1 は、buddy-mlir が 5 期連続の停滞を終え、10-25 06:18 に BUDDY MLIR 0.1.2 をリリースしたことだ。リリースノートは空で自動フローにより生成されており、実際の変更はコミット履歴から逆算する必要がある。調査期間末尾の 3 コミットはいずれも VIR（ベクトル化中間表現）に関するもので、「ベクトルサイズをどう決めるか」を単一ループからネストループへと一般化し、RVV の vlen を目標上限としている。1000 番目の PR はちょうど 0.1.2 リリースの翌日にマージされた。

第 2 は、openRuyi メインリポジトリで 124 コミット、13 PR がマージされたことだ。うち 102 コミットは 10-23 17:00 から 17:15 の一つの時間帯に集中しており、PR #1401「Correct package metadata and source declaration (PART I)」のマージ時刻と一致する。内容は一連の spec にソースファイルのチェックサムを追加し、%autochangelog に切り替えるものだ。残り 16 コミットは 10-24 00:54 に PR #1366 とともにマージされ、SQL-migrate の Go 依存チェーン全体を RPM 化した。10-24 と 10-25 の 2 日間はコミットゼロだった。

第 3 は、本来最も注目される 2 つの fork ブランチがいずれも新機能を持たなかったことだ。pytorch の riscv ブランチは 3 日間コミットゼロで、head は依然 10-22 のまま。llvm-project の riscv ブランチは 10-25 23:00 にベースを切り替えたものの、26 個のローカルパッチを 1 件ずつ比較した結果まったく変化しておらず、上流ベースラインを 474 コミット前進させただけだった。今回新たに追加された技術的内容はほぼすべて上流メインラインに由来する——P 拡張の 7 コミットの移入、spacemit-a100 の LoadStore スケジューリング選好のメインライン入り。

1.1 llvm-project：riscv ブランチが 10-25 に 3 回目のベース切替、ベースラインを 474 コミット前進（10-25）

日付：2026-10-25　情報源：riscv ブランチのコミット一覧、新 head 29edf281、2 回分の先頭比較

riscv ブランチは 10-25 23:00 に 3 回目のブランチ全体の書き換えを完了し、head は 58d62a47 から 29edf281 に切り替わった。先頭のタイトルは依然「[RISCV] Add A100 HP/SP and pack/unpack lowering with calibrated scheduling (#31)」である。前回の head との比較結果は diverged で、474 コミット先行、26 コミット遅れ、300 ファイルの差分だった。遅れの 26 コミットはちょうどローカルパッチ集の件数に等しく、1 件ずつ比較して 26 個のパッチのタイトルと順序がまったく変わっていないことを確認した——#31 の A100 HP/SP と pack/unpack スケジューリングから、BOSC AME の #14、#16、#18、#24、#29、Buckyball ベンダー拡張 #20 と #23、IME ビルトインから A100 dot #30、そして #11、#6、#4、#3、#1 の CI と MLIR-JIT 修正まで。つまり、今回のベース切替でローカル機能は一切追加されていない。

新しいベースラインには RISC-V に直接関連するエンジニアリング基盤が 2 箇所持ち込まれた。.github/workflows/riscv64-ci.yml を新規追加（+121 行）し、ミラーリポジトリに riscv64 ネイティブ CI ジョブを追加。BOLT 側では RISCVLongJmpPass（+174 行）と split-functions 系テストを新規追加し、split 関数の fragment をまたぐ分岐と長距離ジャンプを扱う。ベース切替のスパンも前回の 275 コミットから 474 コミットに戻り、10-21 の 1769 コミットという通常の追趕量に近づいている。

判断：ベース切替の頻度は「時期を選ぶ」段階から 2〜3 日に 1 回へと安定したが、パッチ集がゼロ変化であることは、この期間の産出が上流ベースライン側に集中していることを示す。このブランチを追跡する際は SHA やコミット数ではなく、パッチタイトルの集合を見るべきだ。

日付：2026-10-23 から 10-25　情報源：Packed Widening MAC 組み込み a94e3ab3、mul/macc isel パターン bbbc1cb9、Packed Slide b0e82457、mulu isel マッチング 99e46680、spacemit-a100 スケジューリング設定 fbdefa77

リベースに伴う474件の上流コミットのうち、RISC-V 関連は14件で、そのうち7件が P（packed SIMD）拡張に属し、以前のいくつかの調査期間より密度が高い。

6. トレンド観察

6.1 2つのリプレイラインがそろって停止：一方はベースを変えず、一方は変えても中身を追加せず

今号で最も明瞭なシグナルは、「リプレイ」という事象自体の情報量が低下していることである。pytorch の riscv ブランチは3日間ゼロコミット、llvm の riscv ブランチは 10-25 にベースを変更したものの、26個のローカルパッチは1件ごとに変化がなく、上流ベースラインを474コミット分前進させただけである。

両者を合わせると、これら2つの fork ブランチのメンテナンスモードは「ベースラインを上流に近づけ続ける」ことであり、「機能を継続的に追加する」ことではないと分かる。実際の新機能は上流のマージから来ており（6.2 参照）、ローカルパッチ集は長期間にわたり同一のベンダー拡張セットに留まっている。

読者にとっての実際的な意味：これら2つのブランチを追跡する際は、SHA やコミット数ではなく、パッチタイトルの集合を見るべきである。ベース変更はコミッター日時を一律に書き換え、コミット数は上流の膨張に伴って増えるが、パッチ内容は1週間動かないことがある——SHA で参照する下流はどれも当日に失効する。

6.2 上流の P 拡張は「コンパイルできる」から「うまくコンパイルできる」へ

三日間で上流の RISC-V 関連が 14 件、うち 7 件が P 拡張に属する：3 件が組み込み関数の補充（乗加算幅、スカラー累加、バイト水平乗加算）、3 件が命令選択パターンの補充（mul、macc、mulu の高低ニブル組み合わせと packed slide）、1 件が sati、usati の即値範囲チェックの補充である。

これら三つの層は、ちょうど一つの拡張が「命令がある」から「安心して使える」に至る順序に対応する：まず組み込み関数があり、コンパイラが表現できるようにし、次に isel があり、コードが生成できるようにし、最後にチェックがあり、誤った入力が拒否される。前回は P 拡張に「アプリケーション側のベンチマークが欠けている」と判断したが、今回もこの点は変わらない。ただし、下層はすでに性能比較を始められる程度まで補完されている。spacemit-a100 の LoadStore スケジューリング選好と「M 拡張がない場合の乗算を高コストと判定する」の二項目は、同じ方向のマシンモデル校正に属する。

6.3 テストスイートは統合でメンテナンスコストを削減

riscv-arch-test が riscv 組織に移行した後、三日間で 30 件のコミットがあり、そのかなりの部分が分散したスイートを一つに統合するものだった（PMP、Exceptions、Sv）。この種の変更はテストカバレッジを増やさず、削減するのはメンテナンス面である：スイート数が減ると、CI 設定、除外リスト、レポート集約がすべて簡単になる。

同時に補完された H 拡張テストは別の話である——ハイパーバイザー関連の CSR と割り込みセマンティクスはこれまでカバレッジが薄弱で、今回は Svinval、Shcounterenw、H_Zicntr など複数項目を一度に補完した。統合と補完を同時に行うことは、今回の再編の目標がまず構造を整理し、次に構造に内容を埋めることであり、単なるスリム化ではないことを示している。

6.4 ディストリビューションはリリース前の静穏期に入る

openRuyi の 124 件のコミットはすべて 10-23 の十数時間に集中し、その後二日間はゼロコミット；openRuyi 2026.10 バージョンはまだリリースされておらず、ニュースページは依然として 9-30 の 2026.09 告知のままだ。ruyi 側は 0.54.0 に 9-18 の alpha タグがあるだけで、メインブランチは 9-25 以降コミットがない。

前数か月の傾向からすると、月次バージョンのリリース前には「掃除と凍結」の静穏期がある：まずメタデータ、依存関係、セキュリティ更新を一度に push し、その後バージョンを切る。今回の期間の 102 件のメタデータ修正と 16 個の Go 依存パッケージは、まさにこのパターンの掃除段階に該当する。次回注目すべきは、2026.10 と 0.54.0 のどちらが先に出るかである。
