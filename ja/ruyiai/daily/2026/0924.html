今日の重点：ruyi がソフトウェアソース間のインストール状態問題を修正、RuyiSDK 0.53 は本日リリース予定

日付：2026-09-23　出典：修正 PR #502、問題 #501

北京時間 09-23 09:01、ruyi パッケージマネージャは「Fix installation state managemet across repos」を main ブランチにマージした（マージコミット 802dd4d9；修正コミット 08fd6aeb、メンテナ xen0n が開発）。これによりコミュニティユーザー qingwan12138 が 09-21 に報告した #501 号の問題をクローズした：ソフトウェアソースを切り替えた後、インストール済みのソフトウェアパッケージが「未インストール」と表示され、再インストールがスキップされ、状態が永遠に更新されなくなる。

問題の仕組み：インストール記録は「由来ソフトウェアソース ID」をキーとするが、インストールの重複判定は「名称 + バージョン」のみによる。同名同バージョンのソフトウェアパッケージが複数のソフトウェアソースに存在する場合、ユーザーがソース A でインストールした後にソース B に切り替えると、ruyi list は新しいソース ID でクエリするため「未インストール」と表示する；このとき再インストールは「インストール済みをスキップ」で短絡（終了コード 0）されるが新しいソースの記録は書き込まれない；アンインストールはまた「インストールとして追跡されていない」と報告する。最終的に「ファイルはディスクにあり、状態は永遠に未インストール」というデッドロックが形成され、--reinstall か先にアンインストールする方法でのみ復旧できる。修正はインストール状態のクエリをインストールアイデンティティ（カテゴリ、名称、バージョン、ホスト）によるソース間マッチングに変更し、同一アイデンティティの場合は正確なソース ID の記録を優先し、アンインストールがすべてのソフトウェアの同一アイデンティティ記録をカバーするようにし、ついでに旧バージョンの --reinstall が残した重複記録もクリーンアップする；合計 162 行を変更、うち 117 行は新規追加の回帰テスト（state.py と test_state.py の二つのファイル）。

当該修正は同日に完成した第077期ウィークリーレポート草稿に記載済み（詳細は4.1を参照）。草稿の「パッケージマネージャー」章には「RuyiSDK 0.53は2026年9月24日にリリースされ、対応するパッケージマネージャーのバージョンも0.53.0となる」と明記され、バイナリパッケージABI互換性検出基盤、デフォルトソフトウェアソース優先度の修正、ダウンロード失敗時のミラーリングフォールバック修正など同一バッチの更新が列挙されている。調査期間末（09-24 04:30）時点で、リリース済みReleaseは依然として0.54.0-alpha.20260918が最新であり、v0.53.xブランチは0.53.0-beta.20260917で止まっており、正式版のバージョン番号付与とリリース告知が本日の最重要観察ポイントである。

フォーラムでは調査期間内に1つのトピックが新規追加された：北京時間09-23 11:30、コミュニティメンバーのYaya-tan001がRuyiAI板に「2026-09-23 オープンソース技術ホットニュース情報」（第2850号トピック）を投稿。内容は毎日のオープンソース情報まとめで、本期はLLVM LLDがMassive Binariesワーキンググループの設置を検討していること、TritonのFP4からFP32への昇格変換サポート、Spikeがmip.SEIPの読み書きセマンティクス欠陥を修正したこと、およびPyTorchエコシステムとAI業界の項目をカバー。このスレッドに返信議論はない。本調査期間のフォーラムに他の新規トピックはなく、新しいウィークリ進展スレッドもない。雲栖大会の如意コミュニティ展示ブースは本日（09-24）に会期最終日を迎える。

5. トレンド觀察

5.1 リリース週のリズム：修正の即時クローズドループに0.53リリースとウィークリーレポート077が重なる

問題からマージまで約36時間（#501は09-21 20:48に報告、09-23 09:01に修正マージ）、しかもメンテナはマージ後約15分以内に修正をウィークリーレポートの0.53更新説明に書き込んだ——「報告、修正、リリース物」が同一リリースサイクル内でクローズドループを完成させることは、コミュニティの対応リズムの直感的なサンプルである。次の24時間で確認すべき観察点：v0.53.xブランチの正式なタグ付けと0.53.0リリース告知が予定通り現れるか；0.53.0の実際の更新リストにこの修正がbackport形式で反映されるか（現在v0.53.xブランチは依然として0.53.0-beta.20260917のまま）。

5.2 サポートマトリクスの「シングルボード・マルチOS」モデルと審査待ちキュー

Milk-V Duo Sは3日間でArch Linux、UbuntuからDebian、RT-Thread、xv6へと拡大し、加えて審査中のZephyrとRT-Thread Smartにより、単一の低コストボードのオペレーティングシステムカバレッジが系統的に展開されている。同期間中にK510、CH32V307、ESP32C3などのエッジおよびMCU級チップのレポートも継続的に更新されている。ユーザーにとっては「まずマトリクスを確認してからボードを選ぶ」ための再現可能な資料の密度が高まっている。コミュニティにとっては、こうしたレポートの多くは新規コントリビューターの練習入口であり、審査待ちキューの長さは1日のマージ数よりもコントリビューションの活性を反映する。

5.3 フレームワークカバレッジの広度拡大とPyTorch側の深度待ち

RuyiAI-Stack に新たに mxnet と caffe が登録され（1.4 参照）、既存の pytorch fork と合わせて三つの古典的深層学習フレームワークが並置されることになった。ただし PyTorch fork の RISC-V 機能ラインは引き続き沈黙している（riscv ブランチに新規コミットなし、8 件のオープン PR のタイムスタンプは動かず、RVV の二件のカーネルサポートパッチは依然として待ち行列にある）。広度の拡張と深度の推進に分化が生じており、「広く浅い」段階的状態は mxnet、caffe 両リポジトリの初回アクションによって次の方向性を検証できる。

5.4 本調査期間の空白と注目点

正直に記録すべき空白：PyTorch riscv ブランチとオープン PR の二重沈黙；triton-riscv、tilelang-riscv とベクトルオペレータの三つの専項目標リポジトリがすべて沈黙；ruyi-tuner、riscv-gcc、board-docs、packages-index にコミットとリリースなし；ニュース側では RuyiAI、RuyiSDK、如意コミュニティ、openRuyi に対する Google News の中国語・英語複数組クエリが連続してゼロ件、arXiv の調査期間内に新規収録なし。注目点：第一に RuyiSDK 0.53 と ruyi 0.53.0 の正式リリースおよび v0.53.x の打号；第二にウィークリーレポート 077 正式版の内容；第三に雲栖大会（09-24 まで）の閉幕動向；第四に mxnet、caffe 両リポジトリの今後のアクション；第五に openRuyi 2026.09 月次リリース公告。
