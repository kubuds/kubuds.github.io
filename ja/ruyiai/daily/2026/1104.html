今日の重点：openRuyi PR #1350がマージされ、RuyiAI三点セットが7週間後にディストリビューションパッケージングへ（11-03）

日付：2026-11-03　ソース：PR #1350 Add Ruyiai packages、3件のパッケージングコミット、後続修正PR #1575

11-03 15:59（北京時間）、openRuyi メインリポジトリの PR #1350 がマージされた。この PR は 09-21 17:55 に開かれ、レビューに 43 日を要し、最終的にはわずか 3 コミット、10 ファイル、838 行の追加にとどまったが、RuyiAI スタックの中で最も配布が難しい部分であるコンパイラバックエンドと MLIR ツールチェーンを、正式にディストリビューションの SPECS ディレクトリに収めた。

三本柱の役割分担は明確である。buddy-mlir は MLIR コンパイルフレームワークであり、RISC-V ベクトル（RVV）の降級に必要な方言と pass を提供する。spec には 0.1.2 と記され、ソースは buddy-compiler のコミット 60f354a7 に固定され、同時に RuyiAI-Stack/llvm-project の LLVM スナップショット（コミット 3845a205）を同梱し、clang/lld 22 でブートストラップビルドされ、テストと Python パッケージは無効化され、ツールチェーンは最終的に /usr/lib64/buddy-mlir/llvm にインストールされる。python-triton-ruyiai（spec 内のパッケージ名は python-triton-riscv）は、上流の Triton コミット 5889527 と triton-riscv の nightly/20260913-da5291b タグを組み合わせたもので、実行時に buddy-mlir、buddy-mlir-llvm、clang に依存する。python-tilelang-ruyiai（spec 内のパッケージ名は python-tilelang-riscv）は tilelang-riscv のコミット 0b7d66eb に固定され、さらに TVM、dmlc-core、rang、tvm-ffi、DLPack の五つのサブモジュールを上流で固定されたバージョンごとに個別にパッケージ化し、ビルド時には python3dist(torch) も必要とする。

パッチの内容から、ディストリビューションへの適応がどこで詰まっていたかが見えてくる。tilelang の五つのパッチはそれぞれ、apache-tvm-ffi の上限を 0.1.11 に緩和し、torch-c-dlpack-ext と patchelf のビルド依存を除去し、ツールチェーンが /usr/lib64/buddy-mlir/llvm 配下を検索するようにし、z3 の soname 書き換えをスキップし、さらに TVM FFI の libbacktrace スイッチを扱うものである。triton の二つのパッチは、cmake/ninja/nanobind をシステムパッケージに置き換え、buddy-translate、buddy-llc、llc、mlir-translate に PATH と /usr/lib64/buddy-mlir/llvm/bin の検索フォールバックを追加する。つまり、ソースツリー内で環境変数によって組み立てられていたパスを、ディストリビューション内では一つ一つ再現可能な検索ルールとして落とし込まなければならず、これこそが 43 日間のレビューの主な作業量だったのである。

同じ日の 20:16、PR #1575 がさらに追い打ちをかけた。buddy-mlir.spec 内の Source0、Source1 の #/ 区切りを / に変更し、RPM のソースアドレスの書き方を修正した。同日にはもう一箇所パッケージングのバグも修正されており、これら三つの spec の複雑さは機能ではなく、パッケージングの約束事とパスの細部にあることが分かる。前号のデイリーレポートに記録された「レビューの十九件の意見が spec の書き方に集中した」という件は、ここで決着を見た。

このマージの意義はバージョン番号ではなく、配布経路にある。これまで RuyiAI スタックを使うには、triton-riscv、tilelang-riscv、buddy-mlir を自分で取得し、ドキュメントに従って BUDDY_MLIR_BINARY_DIR のような変数を設定する必要があった。今では openRuyi のパッケージングリポジトリにこれら三つのコンポーネントが揃い、ビルドが通ればユーザーはディストリビューションの方法で同一の LLVM/MLIR チェーンをインストールでき、バージョン、依存関係、インストールレイアウトは spec によって固定される。PR の自己記述では、openRuyi の AI 貢献ポリシーに従って支援ツール（GLM-5.3、DeepSeek V4.1 Flash）も明記されている。

一点、留保が必要である。三つの spec が固定するコードは、いずれも今号の上流より古い。パッケージングの完了は能力の同期を意味せず、具体的な差は 2.2 を参照のこと。

2. RuyiSDK ツールチェーンとディストリビューション

2.1 PR #1350 の 3 つの spec：buddy-mlir、triton-ruyiai、tilelang-ruyiai がそれぞれどのバージョンを指すか（11-03）

日付：2026-11-03　情報源：buddy-mlir.spec、python-triton-ruyiai.spec、python-tilelang-ruyiai.spec

3 つの spec の実際のアンカーは以下の通りで、いずれもメインリポジトリで直接確認できる：

  • buddy-mlir 0.1.2：Source0 は buddy-compiler コミット 60f354a7（コミットメッセージは「[ci] Add the publish-models workflow #925」）を指し、Source1 は RuyiAI-Stack/llvm-project コミット 3845a205 を指す。clang/lld 22 でブートストラップし、BUDDY_ENABLE_TESTS=OFF、BUDDY_MLIR_ENABLE_PYTHON_PACKAGES=OFF、BUDDY_DOWNLOAD_CLI11=OFF、静的ライブラリビルドで、LLVM プレフィックスは /usr/lib64/buddy-mlir/llvm にインストールされる。
  • python-triton-ruyiai 3.8.0+git20261103.da5291b：Source0 は triton-lang/triton コミット 5889527、Source1 は triton-riscv タグ nightly/20260913-da5291b。2 つのパッチはそれぞれシステムビルドツール（cmake/ninja/nanobind）と /usr/lib64/buddy-mlir/llvm/bin 配下のツール検索を扱う。Requires: buddy-mlir、buddy-mlir-llvm、clang。
  • python-tilelang-ruyiai 0+git20261028.0b7d66e：メインソースは tilelang-riscv コミット 0b7d66eb（コミットメッセージ「[RISC-V] Add TileKernels runtime tests and refresh docs (#3)」）にアンカーし、TileLang/tvm 882a7748、dmlc-core 3031e4a6、rang cabe04d6、tvm-ffi ae346ec9、DLPack 93c8f2a3 の 5 つのサブモジュールを個別にパッケージ化する。5 つのパッチは tvm-ffi のバージョン上限、torch-c-dlpack-ext と patchelf、buddy-mlir ツールチェーンの検出、z3 soname、libbacktrace スイッチを扱う。BuildRequires: python3dist(torch)、実行時依存は buddy-mlir-llvm と clang。

3 つの spec は同じ LLVM/MLIR チェーンを共有する。buddy-mlir は pin された LLVM ビルドを自前で持ち、triton と tilelang は buddy-mlir-llvm パッケージに依存する。この構造が今後のアップグレード順序を決める——まず buddy-mlir を動かし、次に 2 つの Python パッケージを動かす。どの層でもアンカーを変える場合は同期して再ビルドが必要になる。

2.2 バージョンアンカー：triton は 09-13 ナイトリー版で停止、tilelang は 10-28 で停止、buddy は 0.1.2（11-03）で停止

日付：2026-11-03　情報源：triton-riscv ナイトリー版 2026-09-13、tilelang-riscv コミット 0b7d66e、buddy-mlir 0.1.3、buddy-mlir 0.1.4.dev20261103

3 点セットのバージョン番号はどれも新しく見えるが、コードアンカーはそれぞれ異なっており、1 つずつ照合する価値がある：

  • triton パッケージのバージョン文字列は 3.8.0+git20261103.da5291b で、このうち 20261103 はパッケージング日であり、実際の triton-riscv コードは 09-13 の nightly/20260913-da5291b タグ（リリース記録 09-14 01:41 UTC）に由来しており、マージから既に約 50 日が経過している。このタグに対応するコミット情報はまだ buddy-mlir を nightly/v0.0.9.dev... に更新中であり、アンカーポイントの古さがうかがえる。
  • tilelang パッケージは 0b7d66eb をアンカーとしており、これは PR #3「Add TileKernels runtime tests and refresh docs」に対応し、バージョン文字列は 0+git20261028 と記載されている。これは、11-03 にマージされたばかりの PR #5（TileOps streaming load と量子化パス）が今回パッケージングされたソーススナップショットに含まれていないことを意味し、スナップショットとリポジトリの間には今期最重要の機能の一つ分の差がある。
  • buddy-mlir パッケージは 0.1.2 と記載され、ソースは 60f354a7 である。上流の正式版は既に 0.1.3（10-31 23:01 UTC リリース、北京時間 11-01 07:01）に達しており、ナイトリー版は 0.1.4.dev20261103 に達している。spec は一つのパッチバージョン分遅れている。

バージョン文字列にパッケージング日が含まれていると、「3.8.0+git20261103」を 11-03 のコードと読み違えやすい。実際のコード日付は Source1 のタグまたはコミットに戻って確認する必要がある。パッケージは一度ビルド・リリースされると、その機能とリポジトリ HEAD との間に一定の遅延が生じ、この遅延は後続の bump コミットによって短縮する必要がある。

6. トレンド観察

6.1 ソースコードビルドからディストリビューションパッケージへ：RuyiAI スタックの配布経路が最後の一マイルを補完

三種の spec が openRuyi に入った後、RuyiAI スタックの配布経路は初めてディストリビューション設定として記述された。以前は「ソースを取得 + 環境変数を設定 + LLVM を自分でビルド」だったが、今はパッケージリポジトリ内に RPM 依存チェーンがあり、buddy-mlir が LLVM/MLIR プレフィックスを提供し、triton と tilelang が buddy-mlir-llvm に依存する。ビルド成果物がリポジトリに入ると、ユーザーのインストール障壁は「コンパイラをビルドできること」から「パッケージをインストールできること」に下がる。プロジェクトにとっては、バージョンと依存関係が初めて監査可能な spec に書き込まれたことになる。

七週間レビューの価値もここにある。争点は機能ではなく、パス検出、依存上限、ビルド分離、パッケージ名と Provides といったディストリビューションのルールである。PR #1575 が当日にソースアドレスを修正したことは、このチェーンが依然として脆いことを示すが、すでにマージフローを走り抜けられる状態である。

6.2 パッケージのアンカーが上流より遅れる：バージョン番号内の日付はコードの日付ではない

3つの spec のうち、triton のコードは 09-13 で停止し、tilelang は 10-28 で停止、buddy は 0.1.2 である。一方、3つのリポジトリはいずれも 11-03 に新しい動きがある。最も目立つのは tilelang である。11-03 にちょうどマージされた PR #5 は18日間の沈黙後の最初の機能追加だが、当日マージされた RPM には含まれていない。パッケージがアンカーしているのは 10-28 の 0b7d66eb である。

バージョン文字列 3.8.0+git20261103 は誤読を強化し、パッケージ日をコード日と見なさせてしまう。ディストリビューションユーザーにとって、これは「あるスナップショットがインストールされる」ことであり、「最新がインストールされる」ことではない。今後は定期的な bump フローを確立するか、パッケージ説明にスナップショット日を明記する必要がある。そうでなければ、機能がマージされるたびに、パッケージとリポジトリの差はさらに広がる。

6.3 二つの開発ラインが同日回復、ruyi メインラインと openRuyi のリリースは依然静止

11-03 のこの日、tilelang-riscv は18日間の沈黙を終え、buddy-mlir はナイトリーバージョンを再開し、openRuyi は1日に7件の PR をマージした。開発側の動きはコンパイラバックエンドとパッケージングに集中している。一方、ruyi メインリポジトリはゼロコミット、ゼロ新規タグで、openRuyi の 2026.10 月度版は依然として欠けている。

二つのラインのリズムは同期していない。コードは進み、リリースは進まない。前回、この状態を「ボトルネックは開発ではなくリリースにある」と概括したが、本期も依然として成立する。次の観察点は、openRuyi 十一月版が三種を収録するかどうか、そして triton-riscv の #92 リベースがマージされるかどうかである。前者はディストリビューションが提供できるかを決め、後者は triton パッケージの次回 bump の落とし所を決める。
