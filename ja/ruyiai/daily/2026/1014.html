今日の重点：openRuyi が K3 ファームウェアプラットフォームラインを開設——edk2-ruyi / ruyifirmware の二倉を新規作成し一括初回プッシュ、初のファームウェアリリース；双週報 078 が確定・予告サミット

日付：2026-10-13　出典：edk2-ruyi コミットリスト、ruyifirmware Releases、双週報 078 期ファイル、フォーラム主題 #2891

openRuyi-Project は 10-13 に K3 ファームウェアプラットフォームラインを一挙に確定した。新リポジトリ edk2-ruyi（リポジトリ作成は当日 11:07 北京時間）は 35 筆のコミットで SpacemiT K3 Pico ITX の EDK2 プラットフォームコードを一括初回プッシュし（作者 RevySR、プッシュ期間 11:55 ~ 16:21）、プラットフォームパッケージ定義から各ペリフェラルドライバまでの完全なチェーンをカバーする。プラットフォーム基盤側には SpacemitPlatformPkg 独立プラットフォームパッケージと共有リソース/クロック処理、電源ドメイン制御、DMA 高アドレス非一貫性サポート、ボードレベル EEPROM とイーサネット MAC 割り当てが含まれる。起動とセキュリティチェーン側には SEC 段階のメモリ検出とデバイスツリー公開、起動選択とホットキー戦略、起動 logo とカウントダウン/復旧状態表示、NOR バックエンド UEFI ランタイム変数、DDR トレーニング記録保存、および Fastboot 一式実装（EFI イメージロード、NOR/NVMe/UFS ファームウェア更新、バージョン照会、NV 保持付き検証更新と USB デバイス側転送）が含まれる。ペリフェラル側にはストレージ（UFS 高速リンクネゴシエーション、QSPI NOR アクセス）、ネットワーク（EQoS ネイティブイーサネット、RTL8127 SFP リンク、SNP ポーリングサービスとアダプタ情報）、ディスプレイ（DPU クロック/スキャン面管理、Inno DP の AUX とリンクトレーニング、EDID モードと GOP 操作）、USB ホストコントローラと PCIe コントローラ/共有 PHY が含まれる。最後の 2 筆はグラフィックスコンソール接続タイミングと Option ROM 搭載デバイスの 64-bit BAR 保持に対する收尾修正である。

配套の ruyifirmware は同日 12:01 に新規作成され 5 筆で着地した（12:17 ~ 18:31、作者は同じく RevySR）。位置づけは「coreboot、OpenSBI、EDK2 をベースとするファームウェア」で、K3 Pico ITX 向けにパッケージングチェーン make package を構築し、成果物は x64 エミュレータスイッチの 2 変種に分かれる（エミュレータは x64 UEFI Option ROM の実行用、独立グラフィックスカード GOP をサポート、README には RX550 が K3 上でポインタ切り捨て問題が存在し、no-x64emu 変種への変更を推奨すると記載）、さらに PCI Option ROM/GOP 更新と CI ビルドリリースパイプラインを含む。当日 18:46 に即座に最初のファームウェアリリース「Ruyi Firmware 20261013」を発表した。同組織の kiwi-image も当日 riscv64 イメージの GitHub Action とローカルビルドスクリプトを着地させた（3 筆、作者 Z572、Fancyhe1）。ファームウェア—パッケージング—イメージの三ラインが同日に一斉に動き、K3 ハードウェア基盤のオープン提供チェーンが形を成した。

コミュニティ側では同日、発信ノードが確定した。RuyiSDK ウィークリーレポート 078 期が編纂パイプラインを完了し（#371 ~ #378 の計 8 筆、17:46 に「add summary, remove sections with no progress」で收尾）、オンライン化された。テーマは「RuyiSDK が RISC-V 中国サミットに登場」（10.18-20 深圳会展中心福田、基調講演、ポスター展示と D15 ブースデモ）。内容はパッケージマネージャ 0.54.0 の月末リリース計画、IDE の一巡の研磨、基礎 C ライブラリ/GCC/LLVM/V8/OpenJDK/Go 各ラインの進展をまとめている（詳細は 4.1 と 2.4 を参照）。

二つの fork メンテナンスラインのリズムは本調査期間で分化が見られた：PyTorch riscv ブランチは通常通り第 N 回の朝の再構築を完了（23筆、ヘッド更新は a17584a3）し、PR ベースラインを刷新；LLVM riscv ブランチは新たな夜間リプレイが出現せず（ヘッドは10-12のリプレイバージョンを維持）。両者はいずれも定例運維の範疇に属するが、LLVM 側の「隔夜リプレイ」リズムが回帰するか、そして ruyisdk/llvm-project の rebase 線（XTHeadVector 修復は既にマージ済み）と fork リプレイ線の関係は、継続的に観察する価値がある。

5.4 ディストリビューション依存メンテナンスのバッチ化：Go モジュールの大量更新と GnuPG スタックの更迭

openRuyi メインリポジトリの単日103筆のうち約9割が Go エコシステムモジュールの大量更新であり、GnuPG セキュリティスタックの一括更迭（gnupg / libgcrypt / libksba / libgpg-error）と llvm-snapshot の LLVM 24 へのジャンプが重なり、openRuyi の依存メンテナンスが「バッチ処理」形態に入ったことを示す：単一調査期間で規模を伴って上流バージョンに追随。このような大量のレビュー効率とビルド検証（全量パッケージ再構築コスト）はディストリビューションリズムの暗黙の制約であり、観察ポイントは更新バッチと実際のイメージリリースの結合方式にある。
