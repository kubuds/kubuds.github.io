今日の重点：進畳時空 X100/A100 コアサポートが RuyiSDK GCC 16.2 ブランチにマージ

日付：2026-09-21　出典：spacemit-x100 コミット、Spacemit-A100 コミット

北京時間 09-21 15:04 と 15:10、RuyiSDK の GCC マルチバージョン維持リポジトリ riscv-gcc の 16.2 ブランチに前後して二筆の進畳時空コアサポートパッチがマージされた：RISC-V: Add basic spacemit-x100 core support と RISC-V: Add basic Spacemit-A100 core support、二つのコアを正式にコンパイラの -mcpu/-mtune オプションに追加した。

X100 は1回のコミットでスケジューリングを既存の generic_ooo モデルにマッピングし、変更は riscv-cores.def のコアおよびチューニング項目、riscv.cc に新規追加された spacemit_x100_tune_info、mcpu/mtune ドキュメントの再生成をカバーし、さらに新規テストケース mcpu-spacemit-x100.c を添付している。A100 の1回のコミットの説明はより詳細である。このコアは順序デュアルイシューで、マイクロアーキテクチャは X60 に近いため、暫定的に Spacemit X60 のコストモデルを再利用する。ISA 上では X100 に最も近く、主な差異は H（仮想化）拡張を実装していないこと、ベクトル長 VLEN=1024（zvl1024b）であること、そして xsmtvdotii 拡張を備えていることである。この拡張定義は riscv-ext-spacemit.def と拡張ドキュメントに併せて記載され、テストとコア項目も同時に補完されている。

両パッチの作者はいずれも進畳時空の Mark Zhuang（パッチ署名日は6月末）で、09-21 にリポジトリ側がマージを完了した。K3 プラットフォームを採用する開発ボード（例えば CoM260 Kit の 8 個の X100 と 8 個の A100 コアの組み合わせ）にとって、これは RuyiSDK ツールチェーンが直接 -mcpu でこれら2つのコアを選択し、対応する拡張定義とスケジューリング設定を得られることを意味し、汎用設定のみを使用するわけではない。両者が basic support（X100 は汎用アウトオブオーダーモデル、A100 は X60 コストを再利用）であることを考慮すると、今後のスケジューリングの細分化とテストカバレッジはデイリーレポートで引き続き追跡する価値がある。

3.1 3つの専門対象リポジトリは調査期間内にすべて静か（09-21 時点）

日付：2026-09-21　情報源：VecIntrinBench、IntrinTrans、FBGEMM

ベクトル組み込み関数ベンチマーク、組み込み関数翻訳、低精度オペレータライブラリを対象とする3つのリポジトリは調査期間内にいずれもコミットがない。VecIntrinBench の最終コミットは 02-13、IntrinTrans は 06-25、FBGEMM fork は 07-13 である。同じグループの観察対象である cpuinfo（05-20）、torq-tile（04-09）も同様に静かである。この方向で最近再現可能な結果は、09-17 に収録された ONNX Runtime MLAS RVV カーネル最適化（K3/X100 で ResNet50 が 3.01 倍高速化）であり、今期は新規ベンチマークデータはない。ツールチェーン側の対応する進展は「今日の重点」の GCC コアサポートを参照されたい。

4. コミュニティとイベント（隔週進展、フォーラム、ドキュメント）

4.1 コミュニティが 09-21 オープンソース技術ホットニュース情報を公開（09-21）

日付：2026-09-21　情報源：コミュニティ投稿 2845

北京時間 09-21 11:30、RuyiAI 板块に毎日のホットニュース情報投稿（09-21 号）が新規追加された。要約は MLIR Vector 方言の transfer_read/transfer_write インデックス記号セマンティクス RFC、LLVM コマンドラインライブラリ置き換え RFC、Triton の新しい lowering pass と PyTorch デバイスインデックスガードなどのコンパイラ話題を主とし、RISC-V 段落には産業とアーキテクチャの動向を収録している。完全な原文は主题リンクを参照のこと。

4.2 コミュニティが RISC-V 産業動向を2件転載（09-21）

日付：2026-09-21　情報源：転載投稿 2846、転載投稿 2847

北京時間 09-21 11:37、コミュニティはさらに2件の転載を追加した。1つ目は国内 RISC-V クラウド AI 演算チップ企業の奕行智能（EVAS Intelligence）が約20億元の新規資金調達を完了し、投後評価額が約150億元に達したというもので（元報道日は 09-18）、2つ目は NVIDIA GPU 内部に数十個の RISC-V コアを統合したという科学技術情報の転載である。いずれの投稿にもコメント議論はない。

4.3 隔週進展第 077 期は未発行、openRuyi ニュースページに新規告知なし（09-15 以降）

日付：2026-09-21　情報源：隔週進展 076 期、openRuyi ニュースページ

RuyiSDK 双週進捗報告の最新号は依然として 076 期（09-15、内容は ruyi 0.52 と VS Code 拡張 0.1.6 のリリース）で、077 期は調査期間内に未発行；openRuyi ニュースページの最新記事は依然として 2026.08 バージョン公告で、2026.09 月次バージョンの予告はまだない。

5. 趨勢観察

5.1 ツールチェーンがコアを認識し始める：X100/A100 が -mcpu/-mtune に進入、RVV 実測値と二本のサポートラインを形成

本調査期間で最も具体的な技術進展は、riscv-gcc 16.2 ブランチが進迭時空の二つのコアに対して -mcpu/-mtune と拡張定義（VLEN=1024 と xsmtvdotii を含む）を補完したことである。09-17 の ONNX Runtime MLAS RVV カーネル最適化（K3/X100 実測で 3.01 倍高速化）と合わせ、K3 プラットフォームに対する二本のサポートラインが同時に推進されている：性能側には再現可能なオペレータレベルの数値があり、ツールチェーン側にはコアレベルの認識とスケジューリングの入口がある。次に追跡すべきはスケジューリングモデルの細分化——X100 は暫定的に汎用アウトオブオーダーモデルを使用し、A100 は X60 のコストモデルを再利用しており、いずれも過渡的な方案である——およびこれらのコアサポートの今後のメンテナンス経路である。

5.2 openRuyi のローリングアップデートがカーネル二本柱とビルド標準化段階に進入

単日 56 回のコミットのうち、カーネル 7.2.6 と LTS 6.18.52 の二本柱アップグレード、openruyi-linux-build 新パッケージと RPM マクロ再構築が今回最も重い二点であり、残りはセキュリティアップデートとクラウドネイティブ、デスクトップパッケージの補完である。ニュースページにまだ 09 月バージョン公告がない現状と合わせると、月次バージョンの内容は依然として急速に蓄積されている；次の観察点は 2026.09 月次バージョン公告とそれに伴うカーネルおよびセキュリティベースラインである。

5.3 K3/CoM260 プラットフォームが一週間で検証、サンプル、コースの内容クローズドループを完成

09-18 の K3 Pico-ITX ROS2 コース入口から、09-20 の CoM260 Buildroot 報告、09-21 の CoM260 Kit 三システム一括報告と board-docs サンプル補完、さらに同期の GCC 側コア認識サポートまで、K3 プラットフォームは一週間で「マルチシステム検証—サンプルコード—コース教材—ツールチェーン」の連続的なカバレッジを完成させた。K3 をターゲットとする開発者と製品チームにとって、ツールチェーン、システムイメージ、学習教材の準備度は明らかに向上した。

5.4 本調査期間の空白と注目点

正直に記録すべき空白：ニュース側では RuyiAI、RuyiSDK、如意コミュニティ、openRuyi に対する Google News の中国語・英語の複数組クエリが連続してゼロヒット；arXiv は調査期間内に新規収録なし；ruyi と packages-index は静かに（コミットとリリースなし）；ベクトルとオペレータの三つの専項目標リポジトリはすべて静かに；PyTorch fork は自動同期動作のみで、新規機能コミットなし。注目点：一是 ruyi 0.54 プレリリースラインの今後の動向と 0.53 正式版のタグ付け；二是双週進捗第 077 期（前回 09-15）；三是 openRuyi 2026.09 月次バージョン；四是 riscv-gcc 16.2 ブランチの今後のマージペース。
