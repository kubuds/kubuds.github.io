今日の重点：buddy-mlir が一夜で7コミット、RVV スケーラブルベクトルを補完、隔週レポート 079 期が確定（10-26）

日付：2026-10-26　出典：buddy-mlir メインブランチコミット一覧、#1002 vscale によるステップ、#1008 インデックスベクトル自動サイズ、隔週進捗 079 期

今回最も集中的な進展は Buddy Compiler から来ている。北京時間 10-26 22:48 から 10-27 03:22 までの4時間半の間に、7件のコミットがすべて VIR（ベクトル化中間表現）上に着地し、同一のスイッチ use-scalable を巡るものだった。まず strip-mining ループを vscale ステップで進めるようにし（#1002）、次にベクトルサイズ選択を RVV 上で vscale = VLEN/64 と LMUL に基づいて計算するようにし（#1003）、続いて結果付きの vir.set_vl をスケーラブルベクトルに降ろし（#1004、#1005）、動的ベクトルの行置換 vir.shuffle を補い（#1006）、vir.load と vir.store のインデックス規約を統一し（#1007）、最後にインデックスベクトルが明示的な幅を持たない場合のアサーションクラッシュを修正した（#1008）。7件を繋げると「VIR がスケーラブルベクトルで本当に表現できるようにする」ための完全なチェーンであり、散発的な修补ではない。

同一期間内に、RuyiSDK 隔週進捗第 079 期が 18:02 にコミュニティフォーラムへ投稿された。報告期間は 10-22 までで、今回の版では2つの明確なタイムポイントが示されている。パッケージマネージャ 0.54.0 はリリースサイクル調整により 10 月末に変更され、openRuyi の月次版は依然として未リリースである。開発中の項目も具体的に書かれている——パッケージとシステムの ABI 互換性検測、より多くの公式パッケージの macOS パッケージング、SpacemiT K1/K3 のツールチェーン適配。

上流側のもう一つの事柄は併せて読む価値がある。llvm-project の riscv ブランチは 10-26 23:00 に6日間で4回目のリベースを完了し、ベースラインはさらに 221 件前進し、26 個のローカルパッチは一字も変わっていない。一方、取り込まれた上流コンテンツの中では、17 個の RISC-V バックエンド pass が1時間以内に同一作者によって NewPM へ移行された。上流はコンパイラパイプラインを切り替え、ローカルはベクトル表現を切り替えており、両端が同時に動いているが、中間層（triton-riscv の依存アンカー、pytorch の riscv ブランチ）は今回どちらも接続されていない。

1.2 llvm-project 上流：17 個の RISC-V pass が1時間以内に NewPM へ移行（10-26）

日付：2026-10-26　情報源：InsertVSETVLI 移行、PreAllocZilsdOpt 移行、DeadRegisterDefinitions 移行

ベースバンド変更で取り込まれた221件の上流コミットのうち、RISC-V関連は21件で、そのうち17件がNewPM移植であり、作者はいずれもAiden Grossman、時刻は10-26 12:59から13:55（北京時間）の1時間足らずに集中している。リストはバックエンドの主要passをカバーする。命令選択後のVSETVLI挿入、CSR読み書きとVXRM書き込み、VMV0除去、圧縮命令生成、スタックプッシュ/ポップ最適化、ベースアドレス統合、LoadStore最適化、Zilsd事前割り当て、分岐最適化とQCRelaxマーキング、さらにレジスタのデッド定義除去、冗長コピー除去、間接ジャンプ追跡、ランディングパッド設定と定数昇格がある。

意義は個々の変更ではなく、パイプラインの帰属にある。これらのpassは長らくLegacyPMにぶら下がっており、NewPMへ移行した後は新しいpass managerの分析キャッシュ、pass順序、デバッグインターフェースと整合する。下流forkへの直接的な影響は、ベースバンド変更のたびにこの一式の変動が持ち込まれ、-passes= の名称とpipeline構成がそれに伴って上方へ移行することである。

2.3 openRuyi：Go に SHA-2 の Zvk ベクトル暗号最適化をバックポート（10-26）

日付：2026-10-26　情報源：openRuyi PR #1512、openRuyi マージ済み PR 一覧

18:33 にマージされた PR #1512 は、今調査期間で唯一 RISC-V 命令セットに直接関連するディストリビューション側の変更です。Go メインラインの Zvk に対する SHA-2 サポートを openRuyi の Go パッケージングにバックポートするものです。Zvk は RISC-V ベクトル暗号拡張ファミリーであり、SHA-2 はその中で最もよく使われるアルゴリズムスイートです。バックポートにより、ディストリビューション内の Go ツールチェーンは、この拡張をサポートするコア上で次の Go メジャーバージョンを待たずにベクトル命令を直接利用できるようになります。

この項目は 079 号の GCC 側 Zvdota/Zvbdota rebase と呼応しています。ツールチェーン（GCC）とランタイム（Go）の両側で同時にベクトル暗号に取り組んでおり、方向は一致していますがチャネルは異なります。前者は下流 fork が自ら保守し、後者はディストリビューションがパッチをバックポートします。

2.4 packages-index と ruyi-imager：イメージバージョン引き上げ、インストーラ対話修正（10-26）

日付：2026-10-26　情報源：packages-index イメージコミット、ruyi-imager PR #19、ruyi-imager コミット一覧

4. Buddy Compiler 動向

4.1 VIR 一晩で7件：ループ歩進からインデックス規約まで一括補完（10-26）

日付：2026-10-26 から 2026-10-27　情報源：#1002 vscaleに基づく歩進、#1003 RVVの伸縮可能サイズ、#1006 動的ベクトルの行置換、#1007 インデックス規約の統一

7件のコミットは同一作者が22:48から翌日03:22にかけて連続して行ったもので、番号は#1002から#1008、すべて[midend][VIR]プレフィックスを持つ。内容は3層に分解できる。

第一層はループとサイズである：#1002はstrip-miningループの歩幅を修正した。従来、vir.set_vlが結果を伴わない場合、定数vector-widthを歩幅とするメインループに降格され、各ラウンドでN倍vscale本のレーンをメモリアクセスしていたため、vscaleが1より大きいとイテレーションが重複していた。#1003はサイズ選択をRVV上でvscale = VLEN/64に基づいて計算させ、NとSEWがLMULを決定するようにし、固定長ベクトルへのフォールバックをなくした。#1008は、インデックスベクトルが幅を明示されない場合に要素ビット幅でサイズを取ることで発生するアサーションを修正した。

第二層は結果を伴うvir.set_vlである：#1004はこれを伸縮可能ベクトルに降格できるようにした。従来、そのスライス（vlと幅ベクトル、vlを幅で割った剰余のスカラー）はコンパイル時に既知のレーン数に依存していた。#1005はさらに多次元動的ベクトルをサポートした。decode attentionのクエリはregion外のvir.from_vectorから持ち込まれるためである。

第三層はメモリアクセスと置換である：#1006は動的ベクトルの行置換vir.shuffleを追加した。#1007はvir.loadとvir.storeのインデックス規約を統一し、結果を伴う/伴わない2種のset_vlが多次元動的ベクトル上で行をmemrefの最終次元より前の次元にマッピングし、vector.loadと整合させた。

4.2 動機の連鎖：decode attention と RoPE の表現ギャップ（10-26）

日付：2026-10-26　情報源：#1005 多次元動的ベクトル、#1006 行置換、buddy-mlir メインブランチのコミット一覧

コミット説明から見ると、この7件は汎用的なベクトル化改造ではなく、具体的なオペレータに迫られて生じたものである。トリガーはVIRのdecode attentionである。RoPEのrotate_halfは128要素のヘッドを前半と後半で入れ替えてから符号を反転する、すなわち[-x[1], x[0]]であり、本質は行置換である。しかしVIRは従来、動的ベクトルの行置換を表現できず、外側で固定長ベクトルを使って計算してからクエリをregionに持ち込むしかなかった。

続いて #1006 で置換を補い、#1005 で多次元動的ベクトルを補い、#1007 でインデックス入口を補い、三つを合成して「decode attention の一式を VIR 内に留める」経路とする。この経路の意義は可搬性にある。いったんオペレータが完全に表現できれば、バックエンドを RVV 固定長や可変長に切り替えても影響するのは降級のみで、中間表現には影響しない。

6. トレンド観察

6.1 上流はパイプラインを交換、ローカルは表現を交換：同じ日にそれぞれ一歩

10-26 のこの日、RVV に関連する 2 本のラインが同時に動いた。上流は 17 個の RISC-V バックエンド pass を NewPM に移行し、ローカルは VIR のスケーラブルベクトル対応をインデックス規約まで補完した。前者はコンパイラ内部パイプラインの構成方式を変え、後者は中間表現の RVV に対する表現能力を変える。両者は同じ結果を指す——RVV のスケーラブルベクトルはもはや「生成できる」だけでなく、「完全に表現でき、新パイプラインを安定的に通過できる」ものになった。

しかし中間層が追いついていない。triton-riscv の buddy-mlir アンカーは依然として 10-17 のナイトリー版で止まっており、pytorch の riscv ブランチは 5 日連続でコミットゼロ。これは、上流とローカルの両端の進展が、今期はいずれも RuyiAI スタックのオペレータ生成とフレームワーク適応の 2 段階にまだ落ちてきていないことを意味する。このスタックが本当に前進しているかを判断するには、次期に 2 つのことを見るべきだ。triton-riscv がアンカーを更新して再ビルドするか、pytorch ブランチがリプレイを再開するか。

6.2 リリース枠は隔週レポートによって月末に固定され、リリース側はセキュリティ補修とパッケージ蓄積の収尾リズムに入る

079 期は 2 つの日付をこれまでより明確に示した。ruyi 0.54.0 はリリースサイクル調整により 10 月末に変更され、現在の正式版は 0.53.0 で止まっている。openRuyi 2026.10 は依然として未リリース。これに対応して、openRuyi の今期 80 コミットのうち 31 コミットはセキュリティ修正、18 コミットは Rust crate の補完、14 コミットはバージョン更新で、48 パッケージに関係する——これは典型的なリリース前の掃除だ。まず依存チェーンを補完し、CVE を消してから、バージョンを切る。

注目すべきは、ISCAS ソフトウェアソースの同期問題により packages-index がここ 2 週間パッケージ更新なしとなっており、これにより ruyi ユーザーが ruyi update 時に見る内容がリポジトリの実際の状態より遅れることになる。0.54.0 が予定通りリリースされ而ソフトウェアソースが復旧しない場合、パッケージリストとリリース版の間にしばらくのずれが生じる。これは次期に確認すべきリスク点である。
