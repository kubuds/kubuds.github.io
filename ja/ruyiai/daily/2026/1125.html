今日の重点：FlagGems 線形代数 59 オペレータが triton-riscv にマージ（11-24）

出典：PR #134。

#134「Port/flaggems linalg」は 11-24 17:13 にマージ、121 ファイルを変更、2457 行追加、35 行削除。

PR は一度に 59 個の FlagGems 線形代数オペレータを追加、各オペレータにテストを一つ配し、統一してサンプルパッケージのエクスポート表からエクスポート。LU、Cholesky、三角求解と QR はそれぞれ一つの kernel を保持し、同アルゴリズムのオペレータは共用。

テストは LAPACK を求めない。RISC-V の PyTorch ビルドには LAPACK がないため、torch.linalg を呼び出さず、matmul 恒等式で結果を再構築して検証する。

同批で CPU バックエンドの affine_grid_generator を修正。各出力要素が一つの program で自身の theta をロードするよう変更、kernel はバッチ割り当て内に留まる。

このコードは以前サンプル形式で審査中だった。11-23 期レポートでは二件のサンプル PR が未マージと記録、本期で着地。

今日の重点：openRuyi が Triton 3.9.0 をパッケージ、Buddy ツールチェーンに切り替え旧パッケージを削除（11-24）

出典：python-triton アップグレードコミット。

openRuyi パッケージリポジトリは 11-24 15:14 に一度に三箇所を変更した。python-triton を 3.9.0 に上げて Buddy ツールチェーンに切り替え、buddy-mlir パッケージを 0.1.4 に上げ、旧パッケージ python-triton-ruyiai を削除した。

ソースは三箇所から取得する。triton-lang の v3.9.0 リリースパッケージ、RuyiAI-Stack の llvm-project コミット f346011a。

第三処は RuyiAI-Stack の triton-riscv コミット 9ded1d4c。三者は spec 内でバージョン固定されている。

ビルド依存は buddy-mlir 0.1.4、buddy-mlir-llvm 0.1.4 と clang 22 など。spec には CPU バックエンドが Buddy の LLVM ツールを使い、AMD GPU は同源の LLVM を自前ビルドすると明記されている。

この変更により、RuyiAI の Triton は単独パッケージからディストリビューション本線に統合された。旧パッケージ名の削除後、ruyi で導入される triton は一つのソースのみとなる。

バージョン遅れに注意が必要だ。上流の buddy-mlir は既に 0.1.8 までリリースされているが、ディストリビューションは依然 0.1.4 で固定されている。

情報源：main ブランチコミット一覧。

五件のコミットは順に、依存更新、affine_grid_generator の修正、線形代数オペレータ、ファイル毎のエクスポートテーブルの削除、サンプルとテスト。

同一コミットでは旧版 Triton 向けに書かれた六つのパッチも削除された。統合テストのトリガ条件は以前コメントアウトされており、毎回の PR が空タスクとして実行されていたが、今回併せて整理された。

4.3 調査期間内に七つのコミット、VIR スケジューリングチェーンが形成（11-24 から 11-25）

情報源：buddy-mlir コミットリスト。

七つのコミットは二区間に集中している。11-24 午前はパッケージングとフロントエンド：LLVM と Buddy の tar パッケージを zstd に変更し、DeepSeek のトークナイザをチャットテンプレートから分離した。

11-24 夜から 11-25 未明にかけてはベクトル側の四つ。まず VIR の取值系オペレーションに Pure を付与し、CSE がマージでき、スケジューリングがメモリアクセスをまたいで移動できるようにした。

続いて -vir-schedule を新設し、vir.set_vl 区間ごとにオペレーションを並べ替えてレジスタプレッシャーを下げる。さらに RVV セマンティクスを補完：ブロードキャストはスカラオペランドのみの場合ベクトルレジスタを消費せず、MoE top-8 マージの最大同時生存数を 10 から 4 に修正し、必要なグループ数を 9 から 3 に修正した。

最後のコミットはスケジューリングを -lower-vir-to-vector の前に前倒しする。

ほかに近似数学 pass が一つ。RVV にはベクトル数学ライブラリがないため、math.exp などは従来レーンごとに libm 呼び出しへ退化していた。新 pass は多項式近似に変更し、log、log2、sin、cos、atan2、cbrt には自研パターンを用いて、上流の非正規数と大きな絶対値における誤りを回避する。

4.4 ディストリビューションは 0.1.4 に固定、上流と四版差（11-24 状態）

情報源：buddy-mlir アップグレードコミット。

6.1 FlagGems 移植が日次バッチへ移行

線形代数 59 オペレータがマージされた misma日、B12、B13、B14 の三バッチ合計 96 以上のオペレータが起票された。単一 PR で 1 万行を超え、ペースは週次から日次へと圧縮された。

移植の口径も統一された。オペレータごとに 1 テスト、パッケージのエクスポートは初期化ファイルに集中、テストは LAPACK を迂回する。この手法は後続バッチにそのまま再利用できる。

6.2 ディストリビューションが Triton ビルドを引き継ぎ開始

openRuyi は triton 3.9.0 と triton-riscv の固定コミットを spec に書き込み、ビルドを Buddy ツールチェーンに切り替え、旧パッケージを削除した。RuyiAI の Triton はこれ以降、ディストリビューション本流からデリバリされる。

この一歩により「コミュニティが fork してホイールを作る」から「ディストリビューションがパッケージを出す」へと変わった。今後のバージョンペースはリポジトリのタグではなく、パッケージング側が決めることになる。

6.3 上流のリリースペースとパッケージ版の乖離

Buddy は 3 日で 3 版をリリースしたが、ディストリビューションは依然 0.1.4 をロックしている。zstd パッケージングや VIR スケジューリングといった新機能は、短期的にはディストリビューションに入らない。

パッケージング側が追随しなければ、Triton のビルドベースラインと上流の差はさらに広がり続ける。
