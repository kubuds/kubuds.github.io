本日の重点：FlagGems 5バッチ245オペレータが単日でtriton-riscvにマージ（11-25）

出典：PR #136。残り4バッチは#137から#140、リンクは付録[2]から[5]を参照。

11-25 10:13から19:53にかけて、triton-riscvはFlagGemsオペレータサンプルを5バッチ、合計245オペレータマージした。

5バッチはそれぞれB12の55件、B13の51件、B14の41件、乱数・RNN・attentionの50件、疎・ネストテンソルの48件。

各バッチはオペレータごとにCPU正確性テストを1本用意し、examplesパッケージの__init__.pyから統一的にエクスポートする。

5バッチ合計で54,550行を追加、315行を削除。B13の検証記録はriscv64 CPU上で146テストすべて通過、環境はPython 3.12、PyTorch 2.10.0、CPU Triton 3.9.0。

B14ではint4パッカーも併せて修正した。従来は出力列幅が128入力値を超えると残りバイトが書き込まれず、非連続テンソルも連続メモリとして読み込まれていた。

前期レポートで記録した B12、B13、B14 の 3 バッチは引き続きレビュー中であったが、今期はすべてマージされた。11-24 にマージされた線形代数の 59 個を加え、今回の移植で累計 304 個のオペレータとなった。

今日の重点：triton-riscv が RISC-V バックエンドチューニングをマージ、Buddy の近似数学に依存（11-26）

情報源：PR #129。Buddy の依存項目は付録 [24] を参照。

11-26 00:24、PR #129 が triton-riscv メインブランチにマージされ、2 ファイルが変更され、136 行追加、15 行削除された。

変更はすべて _ttsharedir_to_llir にあり、ターゲットが RISC-V の場合にのみ有効となる。

5 項目の調整：数学関数を多項式近似に変更；スケーラブルベクトルと AVL 末尾ループに変更；matmul のベクトル幅を 2·VLEN/32 に；buffer をデアロケーショ前にスタックへ昇格；ストライド付き memref コピーを linalg に変換してベクトル化を可能にする。

PR が示す精度は f32 で 1 から 7 ULP、f16 と bf16 では 1 ULP 以下、exp と erfc の非正規化結果を除く。

この変更は buddy-mlir#1068 が提供する polynomial-approximate-math pass と use-avl-loop オプションに依存する。buddy-opt のバージョンが古い場合、RISC-V lowering は未知の pass またはオプションにより終了する。

チューニングのベースラインは VLEN-256 の RISC-V 開発ボードで、対照群は triton-cpu である。

1. RuyiAI スタックの進展（PyTorch / Triton / TileLang の RISC-V 対応）

第 2 段は 03:35 で、上流の main をマージし、両側それぞれの FlagGems エクスポートテーブルを保持した。

第 3 段は 06:24 以降のランダム、RNN、attention とスパース、ネストテンソルの 2 バッチ、および 16:24 のバックエンドチューニングのコミットである。

2 バッチのオペレータはそれぞれ初期コミットとマージコミットの 2 件が現れ、9 件は実際には 5 件のオペレータ PR と 1 件のバックエンド PR に対応する。

1.2 バックエンドチューニング PR #129：近似数学、スケーラブルベクトル、matmul ベクトル化（11-26）

情報源：PR #129。

多項式近似は exp、expm1、log、log2、log1p、tanh、erf、erfc、sin、cos、atan、atan2、asin、acos、cbrt の計 15 関数をカバーする。

従来 RVV にはベクトル数学ライブラリがなく、これらの関数はレーンごとに libm 呼び出しへ退化し、ベクトルレジスタを利用できなかった。

matmul のベクトル幅は固定 4 から 2·VLEN/32 に変更され、8 行のアキュムレータ、各行 2 つのベクトルレジスタ、LMUL は 2 に対応する。PR の説明では LMUL 4 はオーバーフローする。

--lower-vir-to-vector に use-scalable=true と use-avl-loop=true を追加。残余セグメントは 1 回のアクティブ長のイテレーションで終了し、半分に分割したセグメントとスカラループにはもう分解しない。

ストライド付き memref.copy は convert-strided-memref-copy-to-linalg を経由するように変更され、動的形状のコピーは SCF に降格され、FP8 コピーは元のパスを維持する。

1.3 PR #135 は引き続きレビュー中：CPU lowering の統一と matmul の VIR 経由（11-25 時点）

情報源：PR #135。

PR #135 のタイトルは「Unify standard CPU lowering and matmul through VIR」。2 ファイルが変更され、254 行追加、123 行削除、最終更新は 11-25 16:29 UTC。

このブランチはマージ後の #129 をすでに含み、main との差分は backend/compiler.py のみである。

これは buddy-mlir#1080 を含む Buddy ディストリビューションに依存する。マージされれば、標準 CPU lowering と matmul は VIR 経由に統一され、2 つのパスは維持されなくなる。

4. Buddy Compiler 动态

4.1 buddy-mlir が VIR 最適化を 2 件マージ、masked tile と matmul を大幅改修（11-25 から 11-26）

情報源：PR #1080。#1085 は付録 [19] を参照。

buddy-mlir は調査期間内に 2 件のコミットがあり、いずれも 11-26 未明。

00:07 に #1080「Optimize masked tiles, reductions, and matmul」をマージ、23 ファイルを変更、3163 行追加、30 行削除。

当該 PR は masked tile のコピー除去、tile メモリの前方伝播とマスク付きベクトルストア、リダクションと matmul の最適化を追加し、ライフタイムが重ならない小さなブロックのスタック領域を再利用する。

01:20 に #1085「Keep the reassoc of a linalg.reduce combiner」をマージ、2 ファイルを変更、131 行追加、4 行削除。

従来 -lower-linalg-to-vir が vir.reduce を生成する際に reassoc を失い、順序不同を許容するリダクションが順序付きの vfredosum に降格されていた。当該 PR は reassocOf() を補い、4 箇所のリダクション降格パスで統一して使用する。

4.3 PR #1059 はマージされずクローズ、memref コピーのベクトル化案は保留（11-25）

情報源：PR #1059。

PR #1059「Copy memrefs with vectors instead of memrefCopy」は 11-26 01:31 にクローズされ、マージされなかった。

4 ファイルを変更、216 行追加、17 行削除。

PR の説明によれば、SpacemiT K3 上で測定したところ、masked load/store が生成する memrefCopy が add、exp、softmax、matmul カーネル時間の 44% から 99% を占めていた。

クローズ理由はページに記載されていない。同じ時間帯に #1080 が masked tile と tile メモリ最適化をマージ済みである。

4.4 EmbeddingGemma 300M の K3 におけるチューニング PR が審査中（11-25 時点）

情報源：PR #1070。

PR #1070 は依然審査中で、テーマは EmbeddingGemma 300M の SpacemiT K3 上での性能最適化である。

17 ファイルを変更し、2196 行追加、8 行削除、最終更新は 11-25 22:05。

PR は 9 組の負荷に関する初回データを提示している。F32 RAX ベースライン比で 23.24 倍から 38.24 倍の高速化、ネイティブ Hugging Face F32 比で 7.11 倍から 19.03 倍の高速化となる。

ピークプロセス RSS は RAX ベースライン比で 71.6% から 93.5% 低下し、81 回の測定すべてが埋め込み精度の閾値を通過した。

この PR は #835 を継承し、モデルインポート、RAX パッケージング、トークナイザ互換性を修正し、K3 の IME と RVV を使用している。
