今日の重点：FlagGemsオペレータ集にさらに63個追加、triton-riscvのサンプルリポジトリが239ファイルに拡大（11-18）

日付：2026-11-18　出典：PR #126。PR #120。

11-18 22:32、triton-riscvが新たに#126「Add FlagGems operators (63 ops)」を開設。63個のatenオペレータをTritonサンプル形式でpython/examples/flaggems/に移し、各オペレータにaten CPUリファレンス実装とのテストを1本ずつ添付した。

このブランチは依然オープンな#120の先頭に接続されている。PR説明によれば、mainに対する24コミット、239ファイルのうち、111ファイルは#120に属し、128ファイルが今回の新規追加である。#120がマージされれば、本PRは自身のコミットに収束する。

オペレータは用途別に六つのグループに分かれる。前半四つのグループは、スカラー要素ごと、比較とシフトの12個；要素ごとの中段、ビューとファクトリの14個；数値、論理とldexpの11個；unsafeインデックス、ampと量子化補助の9個である。後半二つのグループは、マスク付きsoftmax、pdistと線形パッキングの9個；foreachと融合オプティマイザの8個である。最後の二つのグループには、81個のラッパーを含む_foreach_binaryと60エントリの_foreach_unaryが含まれる。

本ツールチェーンは一部のlibdevice組み込みをlowerできず、buddy-optは呼び出しを直接拒否する。作者は閉形式の等価式に切り替え、fp64とtorchを基準に実測誤差を測定した。tanはsin/cos経由で、相対誤差は1.2e-7以下。log2はlogに1/ln2を掛ける形に置き換え、3.2e-7以下。lgammaはLanczos g=7に反射式を加え、6.4e-4以下。sinh、cosh、tanhは指数式経由で、誤差は2.4e-5から6.3e-5の間である。

erfcの処理が最も細かい。fp32では1-erfを直接計算すると、xが3.5以上で常にゼロになるため、2.85以下では1-erfを使い、それ以上では12項の漸近級数に切り替える。継ぎ目での最悪値は6.4e-4、それ以上では1.3e-4以下。四つの境界値と無限大およびNaNの値はtorchと完全に一致する。

意味論はtorchを基準とし、上流のFlagGemsに相違がある箇所はテストで個別に固定した。_fused_adamの重み減衰はL2式（gにwd掛けるpを加算）、amsgradは未補正vの最大値を取る。_fused_adamw_は先に分離減衰を行ってからステップする。_fused_adagrad_と_fused_sgd_はfound_infがちょうど1のときのみ更新をスキップする。

検証記録は、FlagGemsの全テストケース6416項が通過、ローカルx86_64上で実行し、既存のネイティブクラッシュ3ファイルを除外した。許容誤差は実測最悪誤差に対して1.6から10倍の余裕を確保している。

今日の重点：XSAIの行列と同期インターフェースがforkに進入、Buddy側も同時にAME実装をZTT v0.6へ置換（11-18）

日付：2026-11-18　情報源：llvm-project PR #33。buddy-mlir PR #1066。buddy-mlir PR #1064。

11-19 02:05（北京時間）、llvm-project forkのriscvブランチにマージコミット163d6a7が現れた。これはPR #33「Add XSAI ZAMES and ZMASYNC vendor extensions」に対応し、パッチ5150行、内容は行列と同期の組み込み、ターゲット拡張型、レジスタクラス、命令エンコーディングとアセンブリ逆アセンブリを含む。

実装はRV64 SelectionDAG経由で、レジスタ割り当て前の設定物化と割り当て後の展開を含む。行列のメモリオペランドを追跡し、組み込みの即値範囲を検証し、RV32コード生成時に明確な診断を出す。行列tile型はriscv.xsai.zames.tile.*名前空間に、同期値はriscv.xsai.zmasync.syncに置かれる。

作者が挙げた範囲の欠落は三箇所：行列のコピー、スピルとリロード、および関数間ABI。ベクトルexp2、MXFPとXX8変換拡張は明示的に今回の変更に含まれない。検証の口径は28個の専用テスト通過、別途11個のスモークシナリオ。

同日23:14、buddy-mlirは#1064「Bump LLVM to 542365c9cd38」をマージし、llvmサブモジュールポインタのみを変更した。フォローされたこのLLVM更新こそfork内のXAME/ZTT v0.6バックエンド、つまり前回のデイリーレポートで記録したマージである。

続く23:36、#1066「Replace legacy AME with ZTT v0.6 operations」がオープン：30ファイル、+8349 −1277。退役したAME方言を置き換え、既存のame名前空間下で138個の型付き命令オペレーションを定義し、二つのインターフェースを統一的にllvm.riscv.ztt.*へlowerする。

#1066は二套の計算例と二份のfreestandingなgem5検証負荷を備える。作者は旧ISA契約との数値互換性を約束しないと宣言している。4×4符号付き整数workloadはAME_gem5上で正確比較により通過：行列Aは1から16、Bは全て1、C初期値はゼロ、16個の結果は独立スカラー参照と一致し、行和の出力は10、26、42、58、二つのguestプロセスの終了コードはいずれも0。

三本の線を繋ぐと同じ方向である：LLVMがバックエンド能力を提供し、コンパイラ中間端が方言と降級経路を接続し、Triton側がさらにオペレータ例で検証する。

1.3 夜間ホイールから 668 MB の冗長を除去、strip とパッケージ経路を整合（11-18）

日付：2026-11-18　情報源：PR #125。夜間版 20261118。

11-18 18:43、#125「Strip the copies the wheel actually packages」がマージされ、3ファイル、+37 −31。従来 release.sh の strip ステップはソースツリーの成果物に作用していたが、wheel がパッケージするのはビルドディレクトリ内の別のコピーであり、そのため3つの大物が漏れていた。

PR の数値によると：triton-shared-opt は wheel 内で 398 MB、strip 後は約 118 MB。libtriton.so は 441.5 MB、strip 後は約 144 MB。libtriton_amd_codegen.so は amd/lib と amd/codegen/build に各1份あり、各 84 MB。合計すると 502 MB の wheel 内に 668 MB の回避可能なメンバーが存在する。

修正は4段階：実際にパッケージされる幾份を strip し、重複した cmake ビルドツリーを削除し、strip が効かない場合は静かにスキップせず直接失敗させ、リリース前に成品サイズを検査する。PR ではさらに Release Wheels ワークフローが各 PR で最終体積を出力するようにしたが、リリースはしない。

以前の号に strip-all で wheel を4割減量した旧試みを記録したが、今回は漏れていたコピーを補完するものである。マージ前の直近の夜間版は nightly/20261118-e9c34b7（11-18 09:59 北京時間リリース）で、体積は新フローで再ビルドされておらず、次の夜間ビルドが最初の基準となる。

日付：2026-11-18　情報源：隔週倉 PR #406。隔週レポート 081 原文。board-docs PR #58。support-matrix コミット 5dd057a4。

第 081 期隔週レポートは 11-18 10:23 に初期化され、タイトルの日付は 2026-11-19、すなわち本日刊行となる。調査期間内には四つのコミットがその内容を充填しており、最新のコミットは 11-19 01:28 である。

2.2 openRuyi 一日 36 コミット：curl と nginx のセキュリティ更新、openssl 4.1.0 に RISC-V アセンブリパッチ（11-18）

日付：2026-11-18　情報源：パッケージリポジトリのコミット一覧。nginx 1.31.9。curl 8.23.0。openssl 4.1.0。

パッケージリポジトリの調査期間内のコミットは36件で、主体はセキュリティ更新と依存関係の追随である。nginx は 1.31.9 に上がり、10 件の CVE 修正を併せて取り込んだ。curl は 8.23.0 に上がり、20 件の CVE 修正を取り込んだ。2 つの spec の変更はいずれも小さく、前者は +3 −2、後者は +6 −13 である。

openssl の 4.1.0 への更新はこの一批の中で最も変更が大きく、しかも RISC-V 部分に直接手を入れている。変更では旧来のアライメントクラッシュ修正と clang format パッチを削除し、RISC-V の ChaCha20 ドット積アセンブリ実装に置き換えた。さらに GHASH の複数ブロック集約に関する 3 つのパッチを追加し、Zvbc と Zvkg の 2 本のベクトル暗号拡張経路を含む。

残りは通常の追随である。tpm2-tss 4.2.2、libinput 1.32.0、lighttpd 1.4.85、libp11 0.4.21、acpica 20260930。さらに Go と yunion 関連の新規パッケージを 2 批追加した。RISC-V 専項の小修正は 2 件。libspng は riscv64 上で生成される %check を有効化し、5 行のスキップロジックを削除した。bash-completion は %{?_isa} を外した。それ自体が noarch であるためである。

3. ベクトル拡張とオペレータ最適化

3.1 FlagGems スイートが閉形式置換で libdevice のギャップを補い、6416 項が通過（11-18）

日付：2026-11-18　情報源：PR #126。

#126 の価値はオペレータの数だけにとどまらない。このツールチェーンが現時点で lower できない libdevice ビルトインを逐条列挙し、実測可能な代替式を示した。すなわちバックエンド能力のギャップの一覧に等しい。

リストに挙げられた拒否点は buddy-opt に集中している。pow は libdevice 版しか通らず、AST 内の ** はサポートされない。round は明示的な half-to-even に変更。erfc は fp32 の精度不足のため分段処理とする。各代替式には相対誤差と境界挙動が添えられており、後にネイティブのビルトインへ置き換える際の比較に資する。

テスト側の基準も記録に値する。すべての許容差は実測の最悪誤差に対して 1.6 から 10 倍の余裕を確保し、シードはプロセスに依存しない。この手法により、新增オペレータの回帰結果が再現可能となり、偶然に頼らない。

3.2 VecIntrinBench、IntrinTrans、FBGEMM は依然として静穏（11-18 時点）

日付：2026-11-18　情報源：VecIntrinBench。IntrinTrans。FBGEMM。

3 つのリポジトリは依然としてコミットがない。VecIntrinBench は 02-13 で停止、IntrinTrans は 06-25 で停止、FBGEMM は 07-13 で停止している。ベクトルイントリンシックのベンチマークと変換ツールチェーンは既に 3 四半期動いておらず、性能データは triton-riscv のオペレータテストから間接的に読むしかない。

4. Buddy Compiler の動向

4.1 LLVM サブモジュールを 542365c まで追従、AME 方言を ZTT v0.6 に置換する PR を発行（11-18）

日付：2026-11-18　情報源：PR #1064。PR #1066。

#1064 は gitlink を 1 行変更するのみ：llvm サブモジュールを f346011a から 542365c9 へ、すなわち RuyiAI LLVM fork の riscv ブランチの最新コミットへ切り替える。このコミットには XAME/ZTT v0.6 のバックエンド、ターゲット拡張型、ビルトイン、および 2 セットのプロファイルが含まれる。

#1066 は続いて Buddy 側の旧 AME 実装を全面的に置き換える。138 個の型付き命令操作を定義し、カスタムアセンブリ構文、ビルトインブリッジ、および行列/アキュムレータのターゲット拡張型を備える。両方のインターフェースは --lower-ame を経て llvm.riscv.ztt.* へ降ろされ、同時に退役した AME 操作とサンプルが削除される。

受け入れ基準は 11-17 のバックエンド統合時と同一：gem5 上で 4×4 符号付き整数とパラメータ化カーネルの 2 つの負荷を実行し、厳密比較に合格する。著者はこれは機能検証であり、性能は測定しておらず、旧 ISA との数値的動作の互換性も主張しないと明記している。

メインラインのナイトリービルドは依然として nightly/v0.1.4.dev20261113 で停止しており、今回のサブモジュール更新のための単独リリースはない。

4.2 transpose タイル化 pass が転置バケットを 199.6G サイクルから 31.5G に削減（11-18）

日付：2026-11-18　情報源：PR #1065。

#1065 は linalg-transpose-tile pass を新規追加する：memref 上の linalg.transpose を tile-size × tile-size でタイル化した scf.parallel ループに書き換え、ループ順序のみを変更し、結果はビット単位で同一である。

デフォルトの降級方式は軸を入れ替えた次元で全行ストライドに沿って要素ごとに転送するため、大規模行列ではキャッシュを繰り返しフラッシュしてしまう。著者は x86 上で 240 個の実体化重み転置を含むグラフで実測し、転置バケットが 199.6G サイクルから 31.5G に減少、削減率 84% であった。

PR のチェックリストはまだ完了していない：既存テストとドキュメントの 2 項目が空欄、コードスタイルの項目も未チェックである。マージ前にこれらの項目を補完する必要がある。

4.3 モデルサンプルキューに回復の兆し、BGE-M3 の RVV チェーンが再更新（11-18）

日付：2026-11-18　情報源：PR #934。PR #1061。PR #1059。

6. トレンド観察

6.1 オペレータ検証セットが急速に拡大

一週間のうちに、triton-riscv の FlagGems サンプルは 54 オペレータから二批合計 117 に拡大し、ファイル数は 111 から 239 に増えた。この速度は、バックエンドが一般的な aten オペレータの主干をカバーできるようになったことを示しており、残りの作業は精度パッチと境界動作に集中している。

6.2 行列拡張に上下貫通の三層が誕生

バックエンドは LLVM、方言と降級は Buddy、検証は Triton と gem5。三つのラインが今週それぞれ着地し、インターフェース名は ZTT v0.6 に統一され、XSAI は別途独自のネイティブ名前空間を設けた。二套並行は衝突しないが、下流は選択を迫られる。

6.3 ツールチェーンがリリース前の収尾期に入る

ホイールのスリム化、依存のピン留め、方言の置換、ボードドキュメント、これらは新機能ではなく、リリース前に必ず清算すべき帳尻である。双週報 081 期が V100 の実機テストを原稿に書き込んだことも、ドキュメント側が同じ収尾を行っていることを示している。
