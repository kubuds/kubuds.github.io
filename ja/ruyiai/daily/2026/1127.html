今日の重点：triton-riscvがPR #135をマージ、CPU loweringとmatmulを統一的にVIR経由に（11-26）

出典：PR #135。

11-26 17:41、PR #135がtriton-riscvのメインブランチにマージされた。タイトルは「Unify standard CPU lowering and matmul through VIR」。作者はWuXintong123、コミット12件を含む。変更は2ファイル、255行追加、124行削除。

前回レポートではこのPRは依然審査中と記録されており、ブランチにはすでにマージ後の#129が含まれ、メインブランチとの差分はbackend/compiler.pyのみで、今回その差分がすべて反映された。

変更は5箇所に集中している。RVVのベクトル幅はターゲット特性のうち最大の+zvlNbから導出するよう変更し、デフォルトは128ビット。同時に明示的なtarget_vector_bitsも受け付ける。標準パイプラインはmasked storeをベクトル化し、crop、transpose、プロデューサ融合を伴うリダクションの書き換えをbufferizationの前に前倒しする。標準matmulは固定幅およびRVVターゲットで統一的にVIR経由となり、レジスタブロッキングはターゲットのベクトル幅とレジスタ数に応じて設定される。新たにtarget_tuneを追加し、-mtuneをoptとllcに透過的に渡す。サンプル値にはspacemit-x100、spacemit-a100、xt-c920v2がある。x86側ではベクトル幅も併せて修正された。optの前に関数へprefer-vector-widthを付与し、Emerald Rapidsのようなターゲットでは512ビットをフルに使えるようになった。

PR 説明 -mattr は引き続き ISA を定義し、-mcpu はハードウェアが報告していない拡張を有効にできる。両者の役割分担は変わらない。

依存関係は解除されていない。依然として buddy-mlir#1068 を含む Buddy リリース版が必要で、メインラインが現在固定しているバージョンは必要な pass とオプションより早い。カーネルをコンパイルする CI は、新しいリリース版と Buddy バージョンの更新を待つ必要がある。

今日の重点：buddy-mlir に XSAIAME 方言を追加、RISC-V 行列拡張が IR 層に進出（11-26）

情報源：PR #1071。

11-26 17:18、PR #1071 がマージされ、xsai_ame 方言を追加した。変更は 32 ファイル、1541 行追加、1 行削除、作者は xyyy1420。

この方言は XSAI の ZAMES 行列拡張と ZMASYNC 同期拡張に型付き SSA IR を提供する。LLVM バックエンドのサポートは #1067 の LLVM アップグレードに伴ってメインラインに入っており、今回は IR と Python バインディングのみを追加する。llvm.riscv.xsai.* intrinsic への降下と Linalg 変換は後続の PR に残され、LLVM gitlink は変更されていない。

型は二種類ある。!xsai_ame.tile<kind, MxN, element> の kind は a、b、c を取り、それぞれ A は MxK、B は NxK、C は MxN に対応する。次元は正数または動的。要素型は全部で 15 種類あり、整数側は i4、u4、i8、u8、i32、浮点側は fp8e4m3、fp8e5m2、fp16、bf16、tf32。残りは fp32、nvfp4、mxfp4、fp2pack4、fp2pack5。!xsai_ame.sync は行列同期レジスタの SSA ハンドルであり、物理レジスタ番号はインターフェースに入らない。

操作には load、store、mma、mzero、さらに msyncregreset、mfence、mrelease、macquire が含まれる。load/store はレジスタとランク 2 の memref ビューとの間で tile を移動し、オプションで転置できる。ビューの形状は tile と一致していなければならない。mma は a/b/c の種類と静的 K/M/N 次元を検査し、要素型の組み合わせは検査しない。どの組み合わせをサポートするかはハードウェア実装と LLVM バックエンドが決める。

四つの同期操作はいずれもメモリ効果を持ち、削除されず、メモリアクセスをまたいで並べ替えられることもない。

方言は buddy-opt と InitAll に登録済み。Python 側では方言登録、TileType と SyncType、および ODS が生成するオペレータコンストラクタを提供する。

1. RuyiAI スタックの進展（PyTorch / Triton / TileLang RISC-V 適配）

1.1 PR #135 の七組の実測：matmul の収益が最大、CPU チューニングはほぼ同等（11-26）

情報源：PR #135。

PR は七組の過去の実測を示しており、いずれもベースラインに対する幾何平均比で、1 未満は高速化を意味する。サンプルはそれぞれの実験によるもので、同一の全量ベンチマークではない。

RVV、VLEN 256、SpacemiT X100 上で計三組。masked tile コピー除去は 1726 例、CPU 時間 0.934、ウォールクロック 0.941。masked メモリとリダクションの書き換えは 8643 例、CPU 時間 0.952、ウォールクロック 0.959。VIR matmul の変更対象は 553 例、CPU 時間 0.810、ウォールクロック 0.807。

x86-64、AVX-512、Emerald Rapids 上でベクトル幅の優先設定を修正したのは 1712 例、CPU 時間 0.959、ウォールクロック 0.956。

CPU チューニングの三組はいずれも 1726 例。VLEN 128 の C920v2 は 0.995、VLEN 256 の X100 は 0.989。VLEN 1024 の A100 は 1.000。

PR はさらに、コピー除去対照の 1726 例がすべて通過し、matmul 対照の 856 例もすべて通過したと述べている。VLEN 修正は VLEN 256 と 1024 における大規模ユークリッド距離のオブジェクト検査を復旧させた。

6. トレンド観察

6.1 バックエンド統一完了後、ボトルネックはオペレータ在庫と Buddy バージョン固定に移行

#135 は「標準 CPU と matmul を 2 本の lowering に分ける」構造をクローズし、収益は matmul の 0.810 と masked メモリ書き換えの 0.952 に集中した。

CPU チューニングは VLEN 1024 の A100 上で 1.000、これはこの項目が広ベクトルマシンに対して当面増分がないことを示す。判断根拠は PR 自己記述の 3 組のチューニングサンプルであり、全量回帰ではない。

次の段階のボトルネックはコンパイル経路ではなく、2 箇所にある：279 個の審査中オペレータが進んでおらず、Buddy ディストリビューションは依然 #1068 より前のバージョンに固定されている。

6.2 マトリックス拡張の実装リズムは lowering と変換の 2 つの後続 PR に依存

buddy のマトリックス拡張には既に 2 セットの IR、AME（ZTT v0.6）と XSAI AME（ZAMES/ZMASYNC）がある。

両セットとも「Linalg から方言」と「方言から intrinsic」の完全なチェーンが欠けている。#1071 の PR 自己記述もこの 2 ステップを後続作業として挙げている。

判断：マトリックス命令は短期的にエンドツーエンドモデルの性能データには入らず、midend のマージが先に変えるのは表現可能性である。

6.3 ディストリビューションパッケージングの重点はカーネル追従からアプリケーション層の可用性へ

openRuyi は本調査期間 28 件、カーネルはゼロ変更、オフィススイートコーパス、RDF、線形計画ソルバーとフォントが大半を占めた。

box64 のツリーインは今回の中でソフトウェア面の幅を変えた唯一の変更であり、x86 バイナリのみを配布する一部ソフトウェアに実行経路を与えた。

AI スタック側は本調査期間に新規パッケージなし、triton と buddy のパッケージング状態は前回と一致。
