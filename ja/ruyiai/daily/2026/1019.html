4.1 BUDDY MLIR 0.1.1：2 件の変更——RISC-V サーバー側クロスコンパイルとモデルリリースワークフロー（10-18）

日付：2026-10-18　情報源：リリースページ、差分比較、PR #989、PR #925 リリースワークフロー、コミット 60f354a7

0.1.1 と 0.1.0 の差異はわずか 2 コミット、24 ファイル、約 +896/-54 行のみである：RISC-V サーバーサイドのクロスコンパイル（#989）とモデルリリースワークフロー（#925）。前者は buddy-server に riscv64 クロスコンパイルパスを追加し、ランタイム依存ハンドル（RaxDependenciesHandle）と依存マニフェストテスト、プラグイン検出のスタブ実装を導入するとともに、buddy-cli を簡素化し RVV 環境ドキュメントを更新した；後者は .github/workflows/publish-models.yml と Hugging Face リリーススクリプトを追加し、モデル成果物のリリースを CI に組み込んだ。この 2 つの変更を合わせることで、サーバーサイドの実装と成果物デリバリーの両端が整備され、0.1.1 が 0.1.0 のわずか 2 日後にリリースできた理由も説明できる（主要な内容は 0.1.0 で既に凍結済み）。

6. トレンド観察

6.1 コンパイラスタックのバージョン連動が緊密化：Buddy MLIR が二日で二版、下流は当日追随

Buddy MLIR は 0.1.0 から 0.1.1 までわずか約二日しか経過しておらず、しかも 0.1.1 の二件の変更はいずれもデリバリー可能性を指向している——サーバー側クロスコンパイルにより buddy-server が RISC-V マシンに入れるようになり、モデルリリースワークフローによりモデル成果物が CI から出せるようになる。下流の応答も同樣に日単位である：triton-riscv は 10-17 に #87 をマージして 0.1.0 を固定し、10-18 午前に自動追随により 0.1.1 ナイトリー版へ昇格；tilelang-riscv は 10-16 に Buddy MLIR リリース CI を自社構築パイプラインに組み込んだ。三つのリポジトリが同一の LLVM バックエンドを巡るバージョン結合を緊密化しており、観察点は統一されたリリースウィンドウと回帰ベースラインが形成されるかどうかにある。

6.2 二つの fork メンテナンスラインの分化が継続：PyTorch はマージとリプレイが並行、LLVM は六日間静止

PyTorch の riscv ブランチは調査期間内に 143 コミットをマージし（上流同期が主体）、一括リプレイによりローカルパッチスタックを維持しつつ、約五週間ぶりの PR マージ（#51 riscv64 ローカルイメージ）も出現した；LLVM の riscv ブランチは 10-12 以降六日間コミットがなく、二件の FPGA バックエンド PR は 10-12 で止まっている。同じ「上流 fork ＋ ローカルパッチスタック」でありながら、一方は日単位で進むパイプライン、他方はレビュー待ちの静的ブランチであり、メンテナンス投入の差異は前回の調査期間よりも明顕である。観察点：LLVM のリプレイが新たな上流ベースラインに伴い再起動するか、また FPGA バックエンド PR がレビューに入るかどうか。

6.3 RuyiSDK の三ライン並進：カーネル検出の補完、ディストリビューションの拡面、ツールチェーンのバージョンウィンドウ待ち

カーネル側では RVA23 関連の原子性と命令フェッチ原子性プロファイル拡張を cpufeature と hwprobe にマージし、私有拡張 ID を上流と整合させた；ディストリビューション側では Rust 組み込み向け六パッケージを追加し、Rust ベアメタル開発の基盤依存をソフトウェアソースに組み入れた；ツールチェーン側では 0.54.0 が 10 月末に確定し、ABI 互換検出と K1/K3 適配が引き続き推進されている；ファームウェアラインは三連発の後、停止している。全体として「カーネル検出の補完、ディストリビューションの拡面、ツールチェーンのバージョンウィンドウ待ち」というリズムを呈しており、次は 0.54.0 が予定通りリリースされるか、またサミット後の方案落地が焦点となる。
