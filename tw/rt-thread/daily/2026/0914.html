一、核心與版本動態

1.1 STM32 SPI BDMA 支援合入主線，DMA / BDMA / GPDMA 配置統一（PR #11689）（09-14）

日期：2026-09-14 09:59（北京時間，合入時間；作者提交日期 09-11）　來源：PR #11689

主線在 v5.3.1 版本號推進之後恢復合入，本視窗內首筆功能性提交為 STM32 平臺 SPI 的 BDMA 支援，並順帶統一了 DMA、BDMA、GPDMA 三類搬運通道的配置寫法（隨附 clang-format 格式化提交）。BDMA 是 STM32H7 / U5 等系列在低功耗域可用的獨立 DMA 控制器，此前 SPI 驅動僅走通用 DMA 路徑；本次合入補齊了 SPI 在 BDMA 通道上的收發能力，對需要在 STOP 低功耗模式下維持外設搬運的工業與感測器場景有直接價值。該 PR 自開啟至合入歷時數日，屬社群驅動的外設驅動增強。

1.2 QEMU 入門文件兩處修正合入（PR #11789 / #11794）（09-11）

日期：2026-09-11 13:23 與 13:26（北京時間）　來源：PR #11789、PR #11794

兩筆文件修復同日合入：一是補齊 QEMU Linux 快速上手過程中缺失的 apt 依賴包，二是更新 qemu-vexpress-a9 README 中已失效的 GNU GCC 工具鏈下載連結。兩筆提交的作者日期分別為 09-07 與 09-08，屬長期擱置後的收尾合入。QEMU 模擬器是 RT-Thread 最常見的免硬體上手路徑，文件可用性直接影響新開發者首次體驗。

1.3 四項安全類 issue 集中於 09-13 關閉（tmpfs / 訊息佇列 / pread / finsh 補全）（09-13）

日期：2026-08-23 提交，2026-09-13 15:46 ~ 15:47 集中關閉　來源：#11735、#11736、#11737、#11738

同一日提交的四項安全類缺陷在 09-13 被集中標記為已完成關閉，覆蓋：tmpfs 路徑處理（_path_separate / _get_subdir）長路徑分量導致的棧緩衝溢位、POSIX 訊息佇列名處理中 mq_unlink() 的無界棧溢位與 mq_open() 的差一錯誤、pread() 傳入大負偏移繞過 rw_verify_area() 造成 tmpfs 越界堆讀（資訊洩露或崩潰）、finsh TAB 自動補全（msh_auto_complete_path）補全結果未裁剪到行緩衝導致的堆越界寫。四項均由同一提交者認領並關閉，公開評論與提交歷史中未見與之逐條對應的修復提交，修復的實際落地路徑（可能併入 v5.3.0 的 dfs / posix 加固批次，或另行走內部流程）仍待核實。對以 RT-Smart 與檔案系統、訊息佇列為賣點的工業與車載場景而言，該批缺陷的閉環進度值得持續跟蹤。

1.4 評審佇列觀察（一）：新 BSP 與國產 MCU 驅動擴充套件密集送審（09-14）

日期：2026-09-11 ~ 2026-09-14　來源：#11799、#11800、#11798、#11764

視窗內新開與更新的 BSP / 驅動類 PR 集中：意法半導體 STM32N657 系列的 stm32n657-st-nucleo BSP（84 檔案，+15340 行）、國民技術 N32H 系列驅動從單一板卡擴充套件到 n32h487zgl7-evb / n32h497zgl7-evb / n32h760zil7-stb 三塊板（69 檔案，+7561/-2754 行，覆蓋 ADC、DAC、乙太網、I2C、SPI、QSPI、NAND、SDRAM 等）、小華半導體 HC32 系列驅動擴充套件，以及 CherryUSB 元件對 N32H4x USBFS 裝置側的支援。整體呈現「國產 MCU 原廠與生態開發者密集補齊 BSP」的特徵，與新版本釋出後的適配視窗吻合。

1.5 評審佇列觀察（二）：lwip 2.2.1 協議棧支援入列，工具鏈與 USB 修復並存（09-14）

日期：2026-09-11 ~ 2026-09-14　來源：#11797、#11743、#11770、#11748

評審佇列中的元件與工具類更新：新增 lwip 2.2.1 協議棧支援（改動 1875 檔案，修復 #11588，驗證平臺為 NXP i.MX RT1180 EVK，配置 RT_USING_SAL + RT_USING_NETDEV + RT_USING_LWIP），這將把主線網路棧從既有 lwip 2.1.x 基線推進到 2.2.x；工具側有「按 Kconfig 連結指令碼自動選擇 Keil / IAR 目標」的改進；缺陷修復側包括 USB VCOM 中 rt_ringbuffer 與 rt_serial_rx_fifo 型別別名衝突的修正，以及核心新增棧指標對齊配置項。

1.6 評審佇列觀察（三）：達摩院玄鐵 C908 的 QEMU rt-smart 支援持續推進（09-14）

日期：2026-08-31 開啟，2026-09-14 10:16 更新　來源：PR #11775

針對達摩院玄鐵 C908 的 QEMU 模擬平臺（xiaohui c908）新增 rt-smart 支援，包含 MMU sv39 / sv48 頁表模式與 SMP 多核啟動，並補充 mmu_dem 相關能力，改動 31 檔案、+2575/-565 行。該 PR 仍在評審中。對 RISC-V 側而言，這是把 RT-Thread Smart（帶 MMU 的混合部署形態）在玄鐵高能效核上做模擬器級驗證的關鍵一步，可用於在無硬體條件下驗證程序隔離與使用者態應用。

1.7 新增缺陷報告：SDIO 驅動登出失敗與節點記憶體洩漏風險（#11801）（09-12）

日期：2026-09-12 14:56（北京時間）　來源：#11801

視窗內新增驅動類缺陷報告一則：SDIO 驅動在登出路徑上存在失敗與節點記憶體洩漏風險，已打上 bug 與 component: drivers 標籤，尚未有人認領。SDIO 是 Wi-Fi 模組與儲存卡的共用匯流排，該問題對長期執行裝置的熱插拔與資源回收場景有潛在影響。
