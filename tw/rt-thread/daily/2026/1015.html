一、核心與版本動態

主倉庫視窗內完成 9 筆合入與 1 筆 RISC-V 重構提交，為近一週最密集的合入批次；評審側 8 筆在審提案與多條缺陷單同步更新。

1.1 Next RISC-V 提案新提交：RISC-V 架構移植重構、統一 RV32/RV64 公共層（10-15）

日期：2026-10-15 11:51（提交時間）　來源：PR #10320、重構提交 6bf3686

RISC-V 大重構提案（#10320）視窗內推送一枚大型重構提交「[libcpu][risc-v] Refactor the RISC-V architecture port」：引入可選的 RISC-V 統一公共層（RV32/RV64），以 ARCH_RISCV 與 ARCH_CPU_64BIT 完成架構與 XLEN 選擇，統一 context、trap、MMU、cache、timer、SBI、SMP 與 ISA 處理，新增 PLIC、CLIC、ACLINT、APLIC 與 IMSIC 支援，並建立物理 HART ID 到邏輯 CPU ID 的對映表；保留 T-Head 廠商覆蓋分支。qemu-virt64-riscv 成為首個接入新公共層的 BSP（同一目錄支援 RV32 與 RV64 S-mode），未選用 RT_USING_RISCV_NEW_COMMON 宏的既有 BSP 繼續沿用 legacy_common / common64 路徑。提交後自動流程復跑（格式通知、評審分配、membrowse 記憶體報告）；RISC-V 調整跟蹤單 #11246 同步重新整理（11:52）。提案維持開放。

1.2 網路棧修復批次合入：ping 統計除零與末包延時兩案接連落地（10-14 ~ 10-15）

日期：2026-10-14 09:33 ~ 2026-10-15 09:10（合入時間）　來源：PR #11853、PR #11866

netdev 元件視窗內合入兩筆 ping 相關修復：其一（#11853，10-14 合入），修復目標不可達時 ping 統計除零導致 shell 崩潰的問題，關聯缺陷單 #11852 同日關閉；其二（#11866，10-15 上午合入），修正末包延時邏輯——原迴圈判斷恆假導致最後一包後仍補時延、且延時為零時仍呼叫 rt_thread_delay(0) 返回非法引數，改為記錄實際耗時、僅非末包且延時大於零時呼叫，關聯缺陷單 #11865 同日關閉。同方向早期提案 #11862 已關閉未合入。

1.3 核心與 USB 修復批次合入：calloc 溢位與 USB host 介面數校驗加固（10-14）

日期：2026-10-14 09:28 ~ 10:17（合入時間）　來源：PR #11848、PR #11822

核心側修復 calloc 整數溢位問題（#11848），由社群貢獻者提交併合入。USB 側完成 legacy USB host 加固（#11822）：針對「host 直接信任裝置上報介面數量、可觸發越界訪問」的缺陷單（#11288）補上介面數上界判斷與介面列舉、清理路徑的邊界處理，兩筆提交（介面數校驗澄清、列舉與清理收口）同步合入，缺陷單同日關閉。

1.4 多廠商 BSP 與驅動批次合入：ra6w1、ESP32-C3、STM32H723、RISC-V 向量恢復等（10-14）

維護者集中合入多筆廠商 BSP 與驅動更新：瑞薩 ra6w1 最佳化系統資源分配（主執行緒棧調整為 4096，RC 提交，#11814）；樂鑫 ESP32-C3 修復 Windows 路徑下 IRAM 萬用字元匹配與藍芽連結指令碼誤匹配問題（#11847）；STM32H723-DM-MC02 新增 SPI6 BDMA 支援（#11851）；RISC-V 向量單元修復配置後 vstart 狀態恢復（#11861）；components/drivers reset 框架修復與 ulog 同時啟用時的構建錯誤（#11855）。
