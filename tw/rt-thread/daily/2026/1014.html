一、核心與版本動態

主倉庫視窗內無新提交與合入：master 最新一筆仍為 10-12 上午的 Eclipse 工程生成修復（#11787），此後約 45 小時無合入動作。評審與協作側保持活躍：五筆在審提案與兩條舊缺陷單視窗內均有更新，社群驗證活動集中在 RISC-V 重構與記憶體安全方向。

1.1 Next RISC-V 大重構提案社群實測推進：QEMU 配置指引澄清、ESP32-C3 實板補丁驗證（10-13）

日期：2026-10-13 10:54 ~ 23:52（評論與測試時間）　來源：PR #10320

RISC-V 大重構提案（#10320）視窗內完成四輪社群互動：其一，貢獻者提交 QEMU 五組配置實測報告，其中「S-Mode 關閉裝置模型」組合因缺少公共啟動與多核排程符號而連結失敗；其二，維護者給出平臺適配口徑——裝置模型與無裝置模型二選一（qemu-virt64-riscv 屬前者，d1/d1s 與 smartl/e907 屬後者），測試者據此調整用例分配；其三，當晚該貢獻者在 ESP32-C3 實板驗證兩枚配套補丁（bsp/ESP 切換至新版公共 RISC-V 程式碼路徑），報告 C3 與 C6 均編譯透過、零告警。提案維持開放。

1.2 堆記憶體 ASan 提案增補提交：libc 訪問檢查與邊界用例（10-13）

日期：2026-10-13 15:25（提交時間）　來源：PR #11772

堆記憶體執行時 AddressSanitizer 提案（#11772，8 月末開出）視窗內增補提交：在既有堆插樁執行時與 QEMU CI 覆蓋的基礎上，擴充套件對 libc 記憶體訪問的檢查並補齊邊界用例。該案基於 GCC kernel-address 對記憶體訪問插樁，執行時可檢測堆緩衝區越界與釋放後使用，並提供 FinSH 互動命令檢視診斷資訊。提案維持開放、待評審。

1.3 lwip/WLAN 控制提案擴充套件提交：DNS、DHCP、緩衝與 WLAN 生命週期四組更新（10-13）

日期：2026-10-13 14:27 ~ 16:08（提交時間）　來源：PR #11815

lwip 段宏控制提案（#11815）視窗內由宏控制主題擴充套件為四組提交併兩度強制推送：其一，STA 模式下斷開連線時清理 DNS 配置；其二，最佳化 DHCP 啟動邏輯；其三，配置 lwip 緩衝選項並保留 PBUF 尾部空間；其四，同步 WLAN AP 生命週期與直收路徑處理。提案覆蓋面由編譯宏整理擴充套件至網路棧行為修正，維持開放。

1.4 ESP32-S3 BSP 提案完成自動評審整改、請求人工複審（10-13）

日期：2026-10-13 12:02 ~ 12:42（評論時間）　來源：PR #11844

ESP32-S3 板級支援提案（#11844）視窗內完成自動評審整改：作者按 Copilot 評審意見修正互斥鎖宏展開與 UART0 中斷分配級別，並在說明中補充浮點與 AI 指令限制；剩餘構建檢查失敗被判定為上游既有問題、與本案無關，作者點名請求人工複審，維護者回應當日稍後檢視。該案自 09-28 開出並歷經多次重新整理，本次為視窗內實質推進。

1.5 Keil/IAR 目標選擇提案：作者回應兩處複審意見，維持開放（10-13）

日期：2026-10-13 16:34 ~ 17:38（評論時間）　來源：PR #11743

Keil/IAR 目標自動選擇提案（#11743）視窗內就兩處複審意見作出回應：針對「targets 初始化迴圈缺失」的疑問，作者指出相關路徑與宏定義拼接程式碼已補齊、問題不存在；針對 IAR 連結配置欄位混入 –config_def 無效符號的問題，作者提出該欄位每條目由 IDE 自動加字首、LINKFLAGS 不應再攜帶配置定義的討論，尋求維護者確認。提案維持開放。

1.6 兩條舊缺陷單獲社群接手推進：串列埠 POSIX 控制引數與 DAC 文件示例（10-13）

日期：2026-10-13 22:13 ~ 22:17（評論時間）　來源：Issue #5073、Issue #6568

2.1 虛擬化混合部署教學平臺稿刊出：RK3588 單晶片雙域執行 Linux 與 RT-Thread（10-13）

日期：2026-10-13（媒體釋出時間）　來源：電子工程專輯原文

電子工程專輯刊出 RT-Thread 虛擬化混合部署教學平臺專題：Rockchip HyperCar 以 RK3588 單晶片同時執行 Linux/ROS 2 與 RT-Thread 雙域，由 HyperBoot 負責啟動、隔離與資源分配，雙域經虛擬網路與 micro-ROS 協同——Linux 側承載感知決策與應用編排，RT-Thread 側承擔底盤硬實時執行。平臺配套基礎控制、建圖導航、視覺服務、機械臂四類模組共 16 個案例與三階實訓路徑，並提供大模型本地部署與六軸機械臂抓取綜合案例。

2.2 〖2026嵌入式大賽〗GD32H759IM 的 USB 副屏加 OV2640 攝像頭二合一作品帖釋出（10-13）

日期：2026-10-13 17:43（釋出時間）　來源：論壇帖 76ffa34214c0eda4

2026 嵌入式大賽作品帖「GD32H759IM 的 USB 副屏加 OV2640 攝像頭二合一」釋出：以 GD32H759IMK6 為核心、執行 RT-Thread 4.1.1 與 LVGL 9.5，經 USB 高速口把 4.3 英寸 480×272 RGB 屏變為電腦第二顯示器；韌體整合 TLI 顯示、EXMC SDRAM、DCI 攝像頭與 USBHS0，提供 PC 監控儀表盤、螢幕映象與攝像頭推流三種模式，主機端為 Python 工具；-O0 構建下 Flash 約 354 KB、RAM 約 84 KB。

2.3 〖2026嵌入式大賽〗基於 GD32H7 的多功能環境監測與本地資料記錄儀作品帖釋出（10-13）

日期：2026-10-13 08:37（釋出時間）　來源：論壇帖 248f9e54e367993d

2026 嵌入式大賽作品帖「基於 GD32H7 的多功能環境監測與本地資料記錄儀系統」釋出：以 GD32H759I-EVAL 為平臺、RT-Thread 5.3.0 與 LVGL 8.3.11，經 SHT40、BH1750 與 SGP30 採集溫溼度、光照、等效二氧化碳與 TVOC；中文觸控介面支援數值檢視、閾值調整、趨勢瀏覽與歷史翻閱，資料按週期寫入 SD 卡 CSV，配套電腦端離線解析工具；面向溫室、機房與實驗室等本地監測場景，當前版本不含聯網上傳。

3.2 第三方 GDB 除錯框架 GDR 釋出 2026.04：新增介面卡自動探測與自動初始化（10-13）

日期：2026-10-13 15:58（釋出時間）　來源：GDR 2026.04 釋出頁、專案倉庫

第三方 GDB 除錯輔助框架 GDR 釋出 2026.04：新增介面卡自動探測——gdr probe 按匹配符號、版本來源與佈局指紋給出 exact / range / undetected 置信度，gdr init auto 僅在唯一確定答案時自動選擇；同步掛載 VS Code 擴充套件 2026.4.0 的 VSIX 產物。該框架在偵錯程式內解讀 RT-Thread 核心物件，支援 3.1.x / 4.0.x / 4.1.x，RV64 自 4.0.4 起、Cortex-A9 已實機驗證，屬第三方生態參考。
