一、核心與版本動態

1.1 構建工具鏈缺失檢查合入：工具鏈目錄缺失時構建顯式失敗（10-12）

日期：2026-10-12 09:56（合入時間）　來源：PR #11863

構建工具修復合入（#11863，作者 Rbb666，單檔案 tools/building.py）：構建入口在工具鏈目錄缺失時的處理由置位區域性退出標誌（need_exit = True）改為直接 sys.exit(1)，使構建以非零退出碼立即顯式失敗，不再帶著缺失的工具鏈繼續執行後續流程。該提案 10-12 上午開出、約 36 分鐘後即獲合入，為視窗內首筆落地。

1.2 Eclipse 工程生成修復合入：#11787 落地，SCM 後設資料目錄不再遞迴掃描（10-12）

日期：2026-10-12 11:06（合入時間）　來源：PR #11787

Eclipse 目標生成指令碼修復合入（#11787，作者 wdfk-prog，單檔案 tools/targets/eclipse.py）：為原始檔收集與排除邏輯引入 SCM 後設資料目錄清單（.git / .svn / .hg），此類目錄不再被遞迴展開掃描，避免在含版本庫後設資料的工程樹上遍歷海量物件檔案；隱藏目錄同步改為與普通目錄一致的排除規則。該案 09-08 開出，經 10-11 CI 排查（失敗原因為流水線缺 scons 命令、與排除邏輯無關）後本期合入，為視窗內第二筆落地。

1.3 新提案：rtdbg.h 包含關係修正，修復 IAR 下 rt_kprintf 隱式宣告（10-12）

日期：2026-10-12 13:50（建立時間）　來源：PR #11864

新提案（#11864，作者 meng-plus，單檔案 include/rtdbg.h）：將標頭檔案內的 #include 改為 #include ，使僅經 rtdbg.h 做日誌重定向的元件也能獲得 rt_kprintf 的正式函式宣告。作者報告：IAR 8.40 環境下經 rtdbg.h 重定向日誌時出現 rt_kprintf 隱式宣告，導致 %f 格式化輸出異常；提案附 with_proto / no_proto 兩組最小對照樣例。提案處於開放評審。

1.4 RISC-V 向量：vstart 提案按維護者意見調整測試組織（10-12）

日期：2026-10-12 09:17（評審時間）　來源：PR #11861、Issue #11786

RISC-V 向量上下文修正提案（#11861）視窗內收到維護者新一輪評審意見：建議將測試及其彙編探針遷入專用 utest 目錄、啟用條件化構建整合，並補充 VLEN=128 與 VLEN=256 兩種配置下向量支援、堆與 UTest 的 CI 配置。提案作者 10-11 已按前輪意見推送修正提交（為每次呼叫獨立分配棧幀並在成敗路徑統一釋放）；本案維持開放，等待測試組織調整。同作者推動的 OSPP 2026 議題「RISC-V 惰性 FP/RVV 上下文切換」（#11786）視窗內亦有一次更新，維持開放。

1.5 ping 除零第二案：作者吸納旁路建議再推修復（10-12）

日期：2026-10-12 20:18 ~ 20:47（評論與推送）　來源：PR #11862、PR #11853

netdev ping 除零修復第二案（#11862）視窗內再迭代：貢獻者 CXSforHPU 就 ping 迴圈內的延時邏輯提出兩點改進（最後一條報文不應再補時延、避免以 0 參呼叫 rt_thread_delay），並詢問是否在本案一併修改；原作者 ymj0440 當晚採納並推送修復——延時判斷由恆假的 index == times 改為 index != times - 1，且僅當 delay_tick > 0 時才呼叫延時函式，避免觸發 -RT_EINVAL。本案與首案 #11853 並行，仍待維護者擇一合入。

1.6 工具與規範在審佇列更新：Keil/IAR 目標選擇獲複審意見（10-12）

日期：2026-10-12（更新時間）　來源：PR #11743、PR #11859、PR #11850、PR #11815、PR #11814

工具與規範方向多處在審推進：其一，Keil/IAR 目標自動選擇提案（#11743）作者上午請求複核自動化報錯，維護者當晚給出兩處具體複審意見（targets 初始化迴圈與變數缺失、IlinkConfigDefines 對無效符號項的提取方式）；其二，clang-format 規則收斂討論（#11859）維持活躍——wdfk-prog 給出 LGTM，Rbb666 則認為以 thread.c 為樣例的格式觀感不佳，作者此前呼籲儘快收斂規則、減少各提案追加格式化提交的負擔；其三，STM32F103C6「藍丸」支援提案（#11850）深夜更新並點名請求評審（關聯缺陷單 #11854）；其四，lwip 段宏控制提案（#11815）force-push 後觸發自動化複核並獲改進意見；其五，RA6W1 資源分配最佳化提案（#11814）視窗內重新整理提交。

日期：2026-10-12 11:14（釋出時間）　來源：論壇帖 60a5931af4191d52

2026 嵌入式大賽作品帖「行動式偵錯程式」釋出：以 GD32H759IM（Cortex-M7 @600 MHz，Flash 3840 KB、AXI SRAM 832 KB）為核心、執行 RT-Thread 的手持除錯平臺——7 英寸 800×480 RGB565 觸控式螢幕（GT911 電容觸控）與全中文圖形介面，內建約 5000 常用漢字點陣字型檔；功能覆蓋串列埠除錯（USART1，八檔波特率熱切換與自動波特率檢測）、CAN 匯流排除錯、雙通道示波器（0~3.3 V）、雙路開關檢測與 DDS 訊號發生器，其中示波器與開關檢測複用同一取樣鏈路以簡化硬體；板載 GD-Link 除錯下載單元。

2.2 【2026嵌入式大賽】目語心聲-阿爾茲海默症老人智慧輔具作品帖釋出（10-12）

日期：2026-10-12 08:26（釋出時間）　來源：論壇帖 4656e92595977d25

2026 嵌入式大賽作品帖「目語心聲-阿爾茲海默症老人智慧輔具」釋出：面向失智老人居家照護場景，老人注視螢幕圖片即可表達需求。下位機主控由 Arduino Mega 2560 更換為兆易創新 GD32H759I-EVAL（Cortex-M7 @600 MHz），開發方式轉為 GD32 官方韌體庫（Keil MDK / IAR），軟體框架預留 FreeRTOS / RT-Thread 任務排程選項；整合幻爾 K230 視覺模組（人臉、摔倒、人形、人眼朝向識別）、步進雲臺人臉跟蹤、MPU6050 姿態檢測、GPS 定位、智慧藥盒、起夜燈、淘晶馳串列埠屏與語音播報，形成「看、記、護、陪」照護閉環。

四、行業應用

4.1 端邊協同靈巧機械臂系統開源分享：Titan Board RA8P1 全自主控制與 17 類手勢 NPU 識別（10-12）

日期：2026-10-12（媒體釋出時間）　來源：電子工程專輯原文、專案程式碼倉庫

RT-Thread AIoT 大賽優秀獎作品「端邊協同靈巧機械臂系統」刊出完整技術分享並開原始碼（倉庫 10-12 完成初始提交）：面向單側上肢障礙人群的桌面級輔助機械臂，將機械臂與靈巧手控制從 PC 剝離——以 Titan Board（瑞薩 RA8P1，Cortex-M85 + Ethos-U55 NPU）為唯一控制核心，執行端為 LeRobot SO101 機械臂與 Amazing Hand 靈巧手，Joy-Con 手柄經 ESP32 / Bluepad32 接入實現遙操作；板端部署 17 類手勢識別模型（YOLO-Fastest 經 PyTorch 訓練、INT8 TFLite 量化、RUHMI / Vela 編譯為全 NPU 單子圖，107 個運算元全落 Ethos-U55），單次推理約 77~78 ms，攝像頭 640×480 採集、本地 LCD 顯示與 WebSocket 影片上雲（160×120 JPEG，約 3~6 KB/幀）並行，網頁端疊加 MediaPipe 手部關鍵點顯示。工程要點包括 D-cache 與 OSPI 時鐘分階段啟動策略（解決 WHD 韌體下載回讀校驗失敗）、WiFi 與 NPU 工程融合、TinyJPEG 低頻寬推流等，作者並公開兩類踩坑處置經驗：RT-Thread Studio 軟體包索引報錯處理與不依賴 e2 Studio 的模型轉換命令線流程。
