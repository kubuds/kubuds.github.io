1.1 核心版本號切換至 v5.4.0：版本宏與 Kconfig 先行，釋出物尚未落地（10-17）

日期：2026-10-17 09:43（合入時間）　來源：PR #11875、include/rtdef.h

維護者 Rbb666 合入版本切換提案（2 檔案 +4/-3）：include/rtdef.h 的版本宏由 5.3.1 改為 5.4.0，並補一條 2026-10-17 的變更記錄；src/Kconfig 中 RT_VER_NUM 的預設值由 0x50301 改為 0x50400。作者以 qemu-vexpress-a9 預設配置執行 scons –pyconfig-silent，確認生成的 rtconfig.h 中 RT_VER_NUM 為 0x50400。截至 10-19，倉庫最新的 tag 與 release 仍為 v5.3.0（09-10 釋出），ChangeLog.md 標題仍是 v5.3.0，說明本次只是版本週期的起點，5.4.0 的釋出說明與釋出物尚未出；視窗內的社群缺陷單已把 master 標註為 v5.4.0-dev。

1.2 Next RISC-V 大重構合入：165 檔案統一 RV32/RV64，Sv32~Sv57 與 AIA 一併落地（10-17）

日期：2026-10-17 09:44（合入時間）　來源：PR #10320、Issue #10722

歷時近五個月的 RISC-V 架構重構（#10320）合入，4 筆提交、165 檔案 +15134/-2617。內容含 ISA 管理介面、32E/32I/64I 合併、按 CBOM ISA 處理快取、Sv32/Sv39/Sv48/Sv57/Sv64 MMU 與 SVPBMT、M 態與 S 態 CSR 操作合併、SMP、APLIC/IMSIC（AIA）、CLIC、ACLINT/CLINT、INTC 與 PLIC、可選 DM（僅經 OFW）、T-HEAD 廠商程式碼合併，並在 qemu-virt64-riscv64 移植 DM、支援非 0 號核啟動。計劃表中 S-mode RT-Thread、S-mode RT-Smart（含 APP、DM、無 MMU、無 DM）與 M-mode（DM、無 DM）均已勾選，BSP 適配仍待推進。同日 #10722、#9571、#9567、#9566、#9521、#11226 六枚 RISC-V 任務單集中關閉。

1.3 RT-Thread Smart 十三筆提案批次開出：syscall 拆分、訊號與 MMU 修復、K230D 適配（10-18 ~ 10-19）

日期：2026-10-18 19:35 ~ 10-19 02:49（建立 / 更新）　來源：PR #11896、PR #11897、PR #11892

維護者 BernardXiong 於 10-18 19:35 至 19:36 兩分鐘內連開 13 筆提案（#11885 ~ #11897），截至本期截點全部在審。主線是把 Smart 在 QEMU 與真實板卡上跑通：qemu-virt64-riscv64/aarch64 啟用 RT_USING_SMART、riscv64 關閉 SMP、在 virtio-blk 上掛 ext4/elm 並掛載 ptyfs 與 procfs；libcpu/riscv 修正早期頁表物理偏移換算、按核頁表繼承使用者對映、使用者態異常處理，並新增玄鐵架構選擇與 SVPBMT；lwp 拆分 syscall 實現、修正訊號投遞順序與 ELF 段保護、補齊 TIOCLINUX 與 TIOCGWINSZ；K230D 增加 128MB DDR 配置與 ext4 根檔案系統。另有 SAL RAW socket 協議校驗、lwip 迴環網絡卡、8250 earlycon 暫存器寬度、SDIO 塊大小、poll 走 DFS 檔案操作與 UTIME_OMIT 修復。

1.4 ESP32-C6 SPI 提案整改後合入：分段傳輸、BSP 自有 gdma、位寬校驗前移（10-16）

日期：2026-10-16 11:31（合入時間）　來源：PR #11846、PR #11870

上期處於評審的 ESP32-C6 SPI 提案經評審整改後合入（7 檔案 +1253/-26）：關閉 DMA 時按 IDF 單次 64 位元組上限分段傳送，gdma.c 改為 BSP 自有副本以免 C3/C6 共用構建互相改寫，位寬校驗前移到匯流排初始化之前。行為上，只有選擇 BSP_USING_SPI 才連結 IDF SPI master，預設映象仍關閉 SPI；共享 ESP 驅動不再穿透 SPI 模式、返回實際傳輸位元組數，片選取自 SPI2_IOMUX_PIN_NUM_CS，配置為空時返回 -RT_EINVAL。同期把 C3/C6 適配到 ESP-IDF v6.1、RISC-V 工具鏈升到 GCC 15.2 的提案（#11870）仍在審。

1.6 安全審計四連發：libdl 任意寫、lwp 訊號越界、OFW 棧溢位、lwip-dhcpd 遠端拒絕服務（10-17 ~ 10-19）

日期：2026-10-17 14:25 ~ 10-19 00:37（建立 / 更新）　來源：Issue #11898、Issue #11882、Issue #11879、Issue #11878

貢獻者 XueDugu 在視窗內連開四枚缺陷單，均給出引入提交、受影響版本區間與 QEMU 復現環境。#11898：libdl/dlmodule 對 ELF 重定位後設資料不做邊界校驗，畸形 .mo 可在載入階段以受控值寫核心態記憶體，最早可追到 2018 年 v3.1.0 的提交，ARM/RISC-V/x86 三套重定位實現同構。#11882：lwp 的 sys_sigaction 未校驗訊號編號，可越界讀寫核心堆（Smart，自 v5.0.0）。#11879：OFW 裝置樹展開無巢狀深度限制，會溢位 64 項 np_stack（自 v5.0.2）。#11878：lwip-dhcpd 租約池耗盡後 dhcp_client_alloc 死迴圈，可被未認證遠端打滿整個 lwIP 棧（自 v4.0.0）。四單均保持開放。

2.2 社群教程：從 HardFault 提取 Cortex-M 崩潰現場（10-17）

日期：2026-10-17 17:04（釋出時間）　來源：社群文章

社群作者「大目熊」釋出 Cortex-M 崩潰定位系列上篇，講清 HardFault 的處理思路：異常入口已把 8 個關鍵暫存器壓棧，錯誤原因寫入 SCB 狀態暫存器，開發者只需在 HardFault 中讀出並列印，就能定位到出錯位置；文章按 HFSR 的說明梳理觸發路徑，並指出本系列上篇只解決「列印現場」，呼叫鏈回溯留待下篇。對缺少 core dump 機制的 MCU 韌體除錯有直接參考價值，也補足了社群在系統級排障方法上的內容。

日期：2026-10-17 01:37 ~ 09:13（提交 / 合併時間）　來源：env 版本提交、電子工程專輯報道

Env 倉庫當日完成版本切換（env.json 與 info.py 指向 v2.0.3），併合入 WebUI 內建文件導航（+291/-36）、允許獨立 HTML 文件跟蹤，PR #302 於 10-17 09:13 合併。官方同期釋出介紹文章，v2.0.3 的重點是外掛：功能打成 .epack 包後可安裝、升級、啟用、禁用與解除安裝，外掛既能新增命令列命令，也能擴充套件 WebUI 頁面，官方另提供 epack 開發工具（初始化、校驗、構建、測試）；安裝前需核對來源、許可權與完整性，外掛以當前使用者許可權執行、並非安全沙箱。工具鏈分兩個入口：SDK 下載安裝與本地工具鏈（MDK、IAR）登記；Windows 下支援在 BSP 目錄右鍵直接開啟 Env 終端。版本面向 RT-Thread 5.1.0 之後及主開發分支。

3.2 納芯微 NS800RT7P65D 的 RT-Thread UART 測評與 BSP 配置化改進（10-16）

日期：2026-10-16（釋出時間）　來源：電子工程專輯測評

媒體釋出基於 RT-Thread 的 NS800RT7P65 UART 測評。該晶片是納芯微 NSSine 系列雙 Cortex-M7 實時 MCU，基於 ARMv7E-M，帶雙精度 FPU、DSP 擴充套件與 MPU。文章從晶片層 UART 資源與暫存器配置講到程式碼層功能測試，驗證 menuconfig 配置後 rtconfig.h 生成對應宏、全部 UART 裝置完成註冊，並逐一把 console 對映到不同串列埠測試；作者同時指出板級驅動存在波特率、停止位等硬編碼，建議對映進 menuconfig 以提升 BSP 魯棒性，並已提交改進提案。同一晶片也出現在本視窗的社群作品「稔花」中（見 4.1）。

四、行業應用

4.1 設施農業：K230 + NS800RT7P65D 的「稔花」智慧授粉機器人（10-17）

日期：2026-10-17 14:59（釋出時間）　來源：社群文章

社群釋出面向大棚番茄的智慧授粉機器人。機器人本體以幻爾 K230 視覺模組做感知、納芯微 NS800RT7P65D 做主控，配四路編碼電機底盤、步進電機與三路 HTS-35H 匯流排舵機組成的機械臂，以及震動馬達、吹風直流電機等執行機構；環境節點用 ESP8266 配 DHT11 與 SGP30 採集溫溼度、二氧化碳，經 WiFi 與 MQTT 上傳；上位機含伺服器後端、Web 與 Qt 桌面端。系統支援震動、點觸、吹風三種授粉模式切換，K230 識別到花朵即觸發機械臂定位授粉，識別到病害則上傳影象供後端分析。

4.2 公共衛生：GD32F303 + STM32F103 雙板的「清道夫」智慧消殺裝置（10-17 ~ 10-18）

日期：2026-10-17 16:35 ~ 10-18 21:19（提交 / 釋出時間）　來源：社群文章、Allin-JO/GD32

社群釋出面向教室、樓道與公共座椅的移動消殺裝置，採用「GD32 下位機 + ESP8266（WiFi/MQTT）+ 雲伺服器 + PC/Web 多端」架構，集霧化噴灑、移動控制、消毒液餘量監測、影片回傳與掃碼預約於一體，形成採集、傳輸、處理、控制的閉環；作者稱已完成原理樣機與三端軟體聯調，定位為創新創業與大學生訓練專案的基礎。配套倉庫 Allin-JO/GD32 於 10-17 推送兩筆提交，完成主控由 STM32F103 遷移到 GD32F303 並整理倉庫。

五、總結與趨勢觀察

5.1 三日趨勢（10-16 ~ 10-19）

  • 版本週期切換：v5.4.0 的版本宏與 Kconfig 先行落地，tag、release 與 ChangeLog 仍停在 v5.3.0，說明 5.4.0 進入開發週期而非已釋出。
  • RISC-V 重構落地：165 檔案、+1.5 萬行的 Next RISC-V 合入，把 RV32/RV64、Sv32~Sv57、AIA/CLIC 與 M/S 態統一到一套 ISA 管理介面，六枚長期任務單同日關閉。
  • Smart 成為主線：13 筆批次提案覆蓋 syscall、訊號、MMU、rootfs、QEMU 與 K230D，方向從「能啟動」轉向「可測試、可交付」。
  • 安全債務集中暴露：四枚缺陷單跨 libdl、lwp、ofw 與 lwip-dhcpd，最早可追到 2018 年引入的程式碼，三枚影響 v5.0 之前版本，一日四單的密度在近期視窗中少見。
  • 工具鏈向外掛化與 AI 協作演進：Env 2.0.3 以 .epack 外掛和工具鏈管理為核心，官方 rtthread-skills 把 BSP、軟體包與 Git 流程寫成技能，AI 輔助開發進入官方倉庫。
  • 廠商適配繼續擴充套件：HPMicro 升到 hpm_sdk 1.13.0 並新增 HPM5100EVK，全志 F101 新 BSP 提案，納芯微 NS800RT7P65D 獲社群 UART 測評。
  • 官方渠道靜默：新聞介面停更至第六十日，官網新聞頁 10-19 返回載入失敗。
