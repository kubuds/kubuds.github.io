一、核心與版本動態

1.1 主倉庫合入 [lwp]：將 terminal/ 移出全域性 CPPPATH

日期：2026-09-03（09:20 北京時間合併）　來源：PR #11776（合併提交 54e5164，TTLLDD 提交）

components/lwp/SConscript 此前把 ./terminal/ 目錄加入全域性 CPPPATH，本筆將其移除。全倉庫核查顯示：terminal 子系統標頭檔案（terminal.h、tty_config.h、bsd_porting.h 等）的所有非限定 include 均來自 components/lwp/terminal/ 內部原始檔，編譯器引號形式查詢即可滿足，無需將內部目錄洩漏到全域性包含路徑。這是 2025-11 議題 #10980「規範 CPPPATH 的使用」約定的最小化示範落地——元件不再把內部目錄洩漏進全域性 include 路徑，屬構建系統/include 衛生方向的小步推進。視窗內主倉庫唯一合入，工作日早間合入節奏與近期一致，無大特性。

1.2 進行中：社群開發者提交 CAN 框架結構性重構 PR

日期：2026-09-02（13:21 北京時間建立，open、CI clean、非 draft）　來源：PR #11779

wdfk-prog（即昨日轉正官方索引的 CANopenNode 移植包作者）提交 refactor[CAN] PR：對 Generic CAN Framework 及 STM32 bxCAN 後端做結構性重構（2 commits、8 檔案、+2902/-1308），重新明確框架職責邊界——Generic CAN 負責硬體資源管理、同步、ownership 與生命週期，傳送快取/重試/排程與協議 QoS 策略交由上層協議棧或應用自行決定。方案來源兩條線索：8-26 特性請求 #11759（CANopen CiA 305 LSS Activate Bit Timing 執行時切換波特率需要 TX Full Flush 與 Hardware Abort 能力，已關閉）與 8-28 框架重構討論 #11767（統一 TX Engine、Mailbox Ownership 與 Lifecycle，討論關閉後 3 分鐘即轉本 PR）。兩議題均已在視窗內關閉並彙集為本 PR，標籤含 BSP: STM32 與 component: drivers/can。該 PR 將 CANopenNode 移植中暴露的底層能力缺口上升為框架層重構提案，目前待維護者評審，若合入將是 Generic CAN Framework 近年最大一次職責邊界調整。
