一、核心與版本動態

1.1 v5.3.0-beta 分支建立，v5.3.0 版本週期正式啟動

日期：2026-08-24（10:38 北京時間）　來源：RT-Thread/rt-thread 分支列表 / 倉庫事件

今日 10:38（UTC 02:38），RT-Thread 核心維護者 Rbb666 在 rt-thread 主倉庫建立 v5.3.0-beta 分支，指向當前 master HEAD（08-21 的 NXP RT1180 BSP 大合入，6ea68279）。倉庫此前已有 v5.2.0-beta / v5.2.1-beta / v5.2.2-beta 三個先例分支，beta 分支建立是 RT-Thread 版本釋出流程的第一步：先切出穩定分支收攏修復、隨後釋出正式 tag。v5.2.2 正式版釋出於 2025-10-31，此後主倉庫進入 v5.3.0 開發積累期（期間合入 AF_UNIX 套接字、Device Model 重構、多廠商 BSP 等大量特性）；本次 beta 分支建立標誌 v5.3.0 版本週期正式啟動，距 v5.2.2 釋出約 10 個月，與歷史版本節奏（v5.1→v5.2 間隔約 11 個月）基本一致。分支當前與 master 同點，尚無獨立提交，預計後續修復與特性收尾將在此分支上開展。

1.2 主倉庫視窗內無新合入，master 停在 NXP RT1180 合入

日期：2026-08-24　來源：RT-Thread/rt-thread commits

主倉庫 master 分支視窗內無新 commit，最後合入仍為 08-21 17:45（北京時間）的 NXP RT1180 BSP 功能更新（I2C DMA、CAN、SPI、DWT、SDIO，昨日已詳報）。軟體包索引倉庫 packages 最後 push 亦停在 08-21 09:24，視窗內無新軟體包合入。releases 無新增（v5.2.2 仍為最新正式版），v5.3.0-beta 為唯一新引用，開發主線進入版本收尾前的整理期。

三、生態與廠商適配

3.1 CANopenNode 整合包 canopennode-rtt 新增 EEPROM 儲存診斷，一週五連更

日期：2026-08-24（11:09 北京時間）　來源：wdfk-prog/canopennode-rtt / commits

第三方開源專案 canopennode-rtt（面向 RT-Thread 的 CANopenNode V4 整合移植包）今日新增 feat[canopennode][storage]: add EEPROM storage diagnostic support 提交，為 AT24CXX EEPROM 儲存後端增加診斷支援。該包不重實現協議棧，透過 git submodule 引用上游 CANopenNode 核心，由本倉庫提供 RT-Thread 目標層：CAN 裝置繫結、Kconfig/SCons 構建整合、接收/主迴圈/實時三執行緒執行模型、DFS 或 AT24CXX 儲存後端、CiA 301/303/304/305/309 特性組開關與 demo 物件字典。近一週連續提交（08-17 NMT 心跳監督主站 demo、08-18 SDO 客戶端驗證、08-19 ASCII 閘道器 MSH 控制檯橋、08-20 SDO 塊傳輸驗證、08-24 EEPROM 診斷），功能面從 NMT/SDO 向儲存與診斷收斂，工控 CANopen 匯流排方向在 RT-Thread 生態的第三方落地持續加深。

五、總結與趨勢觀察

  1. v5.3.0 版本週期正式啟動是今日頭條：核心維護者建立 v5.3.0-beta 分支（10:38），延續 v5.2.x 各版本”先 beta 分支、後正式 tag”的釋出慣例；v5.2.2（2025-10-31）之後約 10 個月的特性積累（AF_UNIX、Device Model、多廠商 BSP）進入版本化收尾階段。
  2. 主倉庫程式碼側平靜：master 視窗內零合入，packages 索引亦無新增，開發處於分支建立後的整理期，與昨日判斷一致。
  3. 工控主線多線並進：CANopenNode 整合包一週五連更（今日 EEPROM 儲存診斷）疊加 8/27 睿擎 EtherCAT Workshop 臨期，工業實時匯流排方向是生態側最活躍主題。
  4. 官方資訊出口持續滯後：rt_org 停滯 2 個月、news/activity 介面連續第四日報錯，官方渠道節奏遠慢於 GitHub 動態，版本週期啟動這類訊號目前只能從倉庫事件觀測。
