一、核心與版本動態

1.1 進迭時空 K1 BSP 首版合入主線：173 檔案、5.4 萬行，S 模式加 4 核 SMP（10-19）

日期：2026-10-19 18:49（合入時間）　來源：PR #11132、K1 BSP 說明

進迭時空 K1 平臺的首版 BSP 合入，4 筆提交、173 檔案 +53862/-12，作者 GuEe-GUI，提案自 2026-01-11 掛出，評審約九個月後落地，屬 Next RISC-V 系列（#10320）的後續。BSP 面向 64 位 RISC-V、整合 8 個 X60 核的 K1，帶向量擴充套件，由 U-Boot/OpenSBI 引導、在 S 模式執行，預設開啟 MMU 與 4 核 SMP，驗證平臺為香蕉派 BPI-F3，控制檯走 UART0（115200 8N1）。已支援 PCIe/NVMe、eMMC HS400、乙太網與 PTP、HDMI 幀緩衝（含冷啟動顯示）、JPU 與 V2D 加速、ES8326 音訊、CPUfreq 與熱管理、AES/RNG/eFuse；SPI 與 QSPI 標註為已移植、驗證中。驅動層單獨抽到 bsp/spacemit/dm（147 檔案、49 個 C 檔案、約 30 個模組，含時鐘、音訊、圖形、加解密、PCI、SDIO、串列埠、熱管理等），供後續同系 SoC 複用。CI 側新增 spacemit-k1 編譯腿，並把原先只裝 K230 工具鏈的步驟改為對全部 riscv64 musl BSP 生效。

1.2 RISC-V 原子 CAS 重試缺陷隨同批修復：期望值不再被狀態暫存器覆蓋（10-19）

日期：2026-10-19 18:49（合入時間）　來源：合入提交 1c801efa、atomic_riscv.c

同一批提交修掉了 RISC-V 原子比較交換實現裡的一個真實缺陷。原始碼在
rt_hw_atomic_compare_exchange_strong 中用同一個變數 tmp 既存期望值，又接收 sc 指令的成敗狀態：sc 失敗時會把 tmp 寫成非零值，重試分支的 lr 結果再與它比較，等於拿被覆蓋的值當期望值，迴圈可能永遠退不出去或做出錯誤判斷。修復把期望值轉存為只讀運算元、另立 status 暫存器接收 sc 結果，並把結果輸出改為只寫約束。該實現被所有 RISC-V 板卡的原子操作走，屬架構公共程式碼，影響面大於單個 BSP。

1.3 rt_null 控制檯裝置提前到 BOARD 初始化：上電即支援將日誌口設為 null（10-19）

日期：2026-10-19 16:53（合入時間）　來源：PR #11884、Issue #11472

社群提交的一行改動把 null 裝置的註冊時機從 INIT_DEVICE_EXPORT 提到 INIT_BOARD_EXPORT，使 RT_CONSOLE_DEVICE_NAME 配成 null 時上電即可生效，解決日誌口與通訊口複用同一路串列埠時無法在早期靜默輸出的問題。作者在 qemu-vexpress-a9 上驗證：uart0 正常輸出，改配 null 後 QEMU 無啟動橫幅，恢復 uart0 後 msh 提示符迴歸，rt_null.o 落入 .rti_fn.1 段。改動 1 檔案 +4/-1，作者註明由 AI 輔助完成。早期與常規控制檯拆分這一更徹底的方向未在本次實現。

1.4 裝置模型框架兩處修正：電源域 proxy 命名與 DVFS OPP 重複告警（10-19）

日期：2026-10-19 18:49（合入時間）　來源：power_domain.c、dvfs.c

K1 BSP 的合入同時帶來兩處框架層修正，屬「BSP 先行、框架補齊」的典型。其一，電源域代理物件在註冊時把名字寫成了真實電源域的名字，導致按名字查詢時把代理誤認成域本身，現改用代理專用名，使裝置樹裡的電源域引用能正確落到代理的解析回撥。其二，DVFS 解析 OPP 表時直接新增而不查重，裝置樹重複表項會觸發重複告警且新增失敗，現先按頻率查詢、命中則複用。兩處都在 components/drivers 下，受益方不只 K1。

1.5 netdev ping 時延統計修正：count 為 1 時最小時延不再漏記（10-19）

日期：2026-10-19 16:42（建立時間）　來源：PR #11900

社群提交 netdev 層 ping 統計修正（1 檔案 +5/-1）。原邏輯在 ping 次數為 1 且成功時只統計最大時延，最小時延被跳過，表現為一次成功探測後最小值顯示異常；修法是在首次成功收到響應時同時初始化最大值與最小值。改動小但屬常用診斷命令的可見結果，提案仍在審。

二、安全與穩定性跟進

2.1 lwp 訊號編號校驗提案：sys_sigaction 入口限定 1 至 64（10-19）

日期：2026-10-19 08:49（建立時間）　來源：PR #11899、Issue #11882

維護者 BernardXiong 就上期缺陷單 #11882 開出修復提案（2 檔案 +11-0）：sys_sigaction 把使用者態傳入的訊號號直接交給 lwp_signal_action，而後者用訊號號減一索引定長陣列（_LWP_NSIG 為 64），越界或負值會造成核心堆越界讀寫，普通程式一次系統呼叫即可觸發。提案在 sys_sigaction 入口只接受 1 至 64，否則置 EINVAL 返回，並在 lwp_signal_action 內加同樣校驗以保護後續新增呼叫者；倉庫內已有 valid_signo_check，本次複用該思路。提案已分派 components 評審，處於在審狀態。

2.2 OFW 裝置樹展開前加深度預檢：超過 63 層直接拒絕（10-20）

日期：2026-10-20 01:12（建立時間）　來源：PR #11901、Issue #11879

社群成員 liangzhan5 就 #11879 提交修復（1 檔案 +60-0）。fdt_unflatten_single 用固定 64 項棧暫存遍歷路徑，巢狀超過 64 層時壓棧前無檢查，會在啟動階段寫越界並崩潰。提案在真正展開前先用自建棧遍歷一遍裝置樹算最大深度，超過 63 層則列印錯誤並終止後續展開，避開殘留樹與二次斷言問題；作者稱已在 qemu 上覆現該缺陷，驗證配置為 qemu-virt64-aarch64，CLA 已籤，提案在審。

2.3 新的 tmpfs 缺陷單：ftruncate(fd, 0) 釋放緩衝區卻返回成功（10-20）

日期：2026-10-20 01:53（建立時間）　來源：Issue #11902

貢獻者 XueDugu 新開一枚 dfs_v2 缺陷單。tmpfs 的截斷函式在 rt_realloc(data, 0) 返回空指標時置 ENOMEM 卻返回 0，而兩種堆後端對長度為 0 的 realloc 語義都是「釋放並返回空」，於是合法的 ftruncate(fd, 0) 會先釋放檔案緩衝、再向應用報成功，留下懸空指標與過期長度，隨後的讀寫落在已釋放的核心堆上，可造成資訊洩露與雙重釋放。缺陷由 2023-09-20 的提交引入（PR #8063），自 v5.0.2 起所有版本與 master 均受影響，已在 QEMU aarch64 的 RT-Smart 與 RP2350 上覆現。單子保持開放。

2.4 維護者回應 libdl 動態模組缺陷：可做區域性修復，徹底隔離需使用者態（10-19）

日期：2026-10-19 08:16（評論時間）　來源：Issue #11898

上期收錄的 libdl 重定位越界寫缺陷單在本視窗獲得維護者回應。BernardXiong 確認描述屬實，認為邊界校驗可以做一定修復，同時指出動態模組本質是把一段程式碼插進核心、許可權全開，這也是官方在該機制上未做更多嘗試的原因；若要做到記憶體隔離，需要走使用者態模式。該表態為後續修復範圍劃了邊界：本輪預計只補後設資料校驗，不改動模組載入的整體許可權模型。

五、行業應用

5.1 大棚環境監測終端：E907 單核加 LVGL 四頁介面，全離線可用（10-19）

日期：2026-10-19 09:35（釋出時間）　來源：社群文章

2026 嵌入式大賽作品，面向小型與家庭大棚的本地化環境監測終端。硬體用 ArtInChip D12X-DEMO68 開發板，主控為達摩院玄鐵 E907（RV32，396 MHz，帶單精度 FPU），配 8 MB PSRAM、16 MB SPI NOR 與 480×272 電容觸控式螢幕（GT911），感測器只有 DHT11 與 BH1750 兩支，不接 Wi-Fi、不依賴雲平臺。軟體基於 RT-Thread 4.1.1 與 LVGL 8.3.1：6 個執行緒按 12 至 26 級分層，兩條訊息佇列分別喂報警與介面，互斥鎖保護狀態快照與感測器匯流排，閾值經訊號量非同步寫入 LittleFS；介面四頁快取式切換，曲線保留最近 60 點環形緩衝且三通道不共用縱軸；報警帶連續 3 次確認與 2 攝氏度、2% RH 回差，蜂鳴器走 PWM。另提供 12 條 MSH 診斷命令，可現場查取樣有效位、觸控座標與 UI 耗時。

六、總結與趨勢觀察

6.1 本期趨勢

  • 高階 RISC-V 平臺進入主線：K1 BSP 以 S 模式、MMU 與 4 核 SMP 的形態合入，配合 PCIe/NVMe、HDMI 與多媒體加速，標誌 RT-Thread 在應用處理器級 RISC-V 平臺上的支援從「能啟動」走向「外設齊備」。
  • 驅動層按 SoC 家族沉澱：bsp/spacemit/dm 把約 30 個裝置模型驅動獨立成層，K1 只是第一個使用者，後續同系晶片可複用，BSP 目錄結構開始出現「廠商層加板級層」的分工。
  • 框架隨 BSP 一起修：同批提交裡帶出電源域代理命名、DVFS OPP 查重與 RISC-V 原子 CAS 三處框架與架構修正，說明新平臺接入正在反向暴露通用程式碼的缺陷。
  • 安全債務清理進入修復期：上期四枚缺陷單中已有兩枚開出修復提案（lwp 訊號校驗、OFW 深度預檢），並新增一枚 tmpfs 截斷缺陷；維護者對動態模組給出「區域性修復可行、隔離需使用者態」的邊界判斷。
  • 官方渠道繼續靜默：新聞介面停更逾四個月，v5.4.0 只有版本號先行，對外資訊主要靠 GitHub 與社群作品。
  • 二進位制韌體合規需留意：K1 BSP 內嵌了取自廠商 Linux 映象的 RCPU 韌體（供 HDMI 音訊服務），倉庫說明中已給出校驗值並提示合入前確認再分發條款，這類隨 BSP 進入主線的廠商二進位制值得後續跟蹤。
