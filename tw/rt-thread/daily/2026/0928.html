一、核心與版本動態

1.1 主線合入兩筆維護性修復：GD32VW553H-EVAL 構建清理與 ipc 檔案整理（09-26 ~ 09-27）

日期：2026-09-26 19:58 / 09-27 12:18（北京時間，合入時間）　來源：PR #11837、PR #11832、合入提交 b40aeb146、合入提交 05badce95

主線在視窗內合入兩筆小型修復。其一（#11837）修復 GD32VW553H-EVAL BSP 的 CI 清理階段失敗：riscv-none 任務在構建、打包成功後的 scons -c 清理環節退出——根因是 SConstruct 註冊的軟體包預檢查（bsp_pkg_check）在清理模式下也無條件執行，而清理時軟體包可能已被移除或未拉取；修復為該檢查在 clean 模式直接短路（1 個檔案，+3/-0），正常構建的檢查邏輯保持不變。該提案由 GitHub Copilot 編碼代理（copilot-swe-agent）提交，代理會話由維護者觸發、開題後約 3 分鐘完成修改，09-26 19:58 由 Rbb666 合入。其二（#11832）移除 components/drivers/ipc/SConscript 中冗餘的 __RT_IPC_SOURCE__ 宏定義（1 個檔案，+1/-1），屬 09-24 評審佇列的消化，09-27 12:18 合入。

1.2 評審佇列新增兩筆健壯性修復：STM32 連結指令碼棧對齊與 devtmpfs 路徑越界（09-27）

日期：2026-09-27 20:57 ~ 21:11（北京時間，建立時間）　來源：PR #11841、PR #11842

評審佇列在視窗內新增兩筆健壯性修復。其一（#11841）修正 STM32 系全部連結指令碼的棧對齊：將 .stack 段的 ALIGN(4) 改為 ALIGN(8)，以符合 ARM AAPCS 對棧指標在公共函式邊界 8 位元組對齊的要求，對應 2023-05 報告的舊缺陷 #7527（棧 4 位元組對齊導致可變引數中 double 傳參錯誤）；改動覆蓋 12 個模板與 98 塊板卡共 110 個連結指令碼（+220/-220），未觸碰各板卡的儲存佈局。其二（#11842）修復 devfs 的棧緩衝區溢位：devtmpfs.c 的 _path_separate() 與 _get_subdir() 未接收緩衝區長度引數，單個路徑分量超過 255 位元組即發生越界（最長越界約 3.8KB，寫入內容與長度由呼叫者控制、可覆蓋返回地址）；修復讓 devfs 與 tmpfs 的既有校驗對齊（越界返回 -ENAMETOOLONG，1 個檔案 +48/-8），提交署名字首 [HUST CSE]。兩筆目前均處於評審狀態。

1.3 FinSH 路徑補全堆溢位缺陷報告：提交者已認領擬修復（09-26）

日期：2026-09-26 03:55（北京時間，建立時間）　來源：Issue #11839

社群在視窗內提交 FinSH 元件的高危缺陷報告：在 msh 中觸發路徑自動補全（Tab 鍵）時，msh_auto_complete_path 相關邏輯在拼接當前工作目錄與使用者輸入時未做嚴格邊界檢查，超長或深層巢狀路徑可造成堆緩衝區越界寫（CWE-122），影響 v5.3.0 及當前主線、STM32F407-ATK 等板卡。議題附帶缺陷描述與標籤（bug、in progress 等），提交者 Acen28 當日認領該議題，擬自行提交修復。屬繼 devtmpfs 越界（見 1.2）之後又一條由社群審計推進的記憶體安全問題線索。

2.2 論壇教程《MCU 連結指令碼“升級”》：孤兒 Section 與對齊處理（09-28）

日期：2026-09-28 08:17（釋出時間，11:03 更新）　來源：論壇文章 54cb40d33610387a、B 站配套影片

社群作者「大目熊」的 MCU 底層系列更新（前篇《MCU GNU連結指令碼》09-22 已收錄）：本篇進階處理孤兒 Section 與對齊問題。要點：用 -Wl,--warn-orphan 讓連結器列出未顯式安排的 section；按 SHF_ALLOC 標誌把 section 分為執行時需要（.text/.rodata/.data/.bss，需分配記憶體區域）與不需要（.debug_*、.comment、.ARM.attributes、符號表等，顯式列出但不分配）兩類逐個安置；.ARM.exidx/.ARM.extab 屬 ALLOC 類需安排並匯出起止符號；最後以 4 位元組對齊收束，驗證連結警告全部消除、map 檔案與指令碼描述一致。附 B 站配套影片，屬社群教程類內容。

3.1 沁恆 CH32V003F4P6-EVT 板級支援提案進入評審（09-25）

日期：2026-09-25 21:11（北京時間，建立時間；09-27 有更新）　來源：PR #11838

貢獻者 cms19859230182-lang（此前 CH32V203 BSP 與 ESP32-C6 提案作者）為沁恆 CH32V003F4P6-EVT 開發板提交 BSP 提案。CH32V003F4P6 為 RISC-V 核心、主頻 48MHz、16KB Flash、2KB SRAM、TSSOP20 封裝；預設映象僅啟用 UART1（TX PD5 / RX PD6，115200 進 msh），除錯經單線 SWDIO（PD1）外接 WCH-LinkE。提交者已實測：以 WCH RISC-V GCC 8.2.0（-march=rv32ec -mabi=ilp32e）構建，映象 15680 位元組（裝入 16KB Flash），燒錄後串列埠輸出 RT-Thread banner 與 msh 提示符。提案共 5 筆提交、47 個檔案（+9258/-0），目前處於評審狀態。

3.2 CANopen 生態雙倉上線 MkDocs 文件站（09-28）

日期：2026-09-28 08:45 ~ 09:09（推送時間）　來源：canopennode-rtt、lely-canopen-rtt

社群貢獻者 wdfk-prog（RT-Thread 軟體包索引中 canopennode 包 09-24 合入 v1.2.0 的提交者）在視窗內為兩個 CANopen 整合倉庫釋出文件站：canopennode-rtt（CANopenNode 整合，支援多裝置節點的邏輯裝置模式）與 lely-canopen-rtt（Lely CANopen 整合，單一所有者 EV/IO2 執行時與靜態物件字典、可選主站服務）均推送 MkDocs 手冊與 Doxygen API 文件；lely 倉另增加 PR 文件校驗 CI。兩包此前均在 RT-Thread 論壇有介紹帖（lely 主站用法長文 09-11 已收錄）。工業通訊方向軟體包建設持續投入。

3.3 AWTK 開源許可證切換至 Apache 2.0（09-26）

日期：2026-09-26 08:50（提交時間）　來源：zlgopen/awtk 許可證變更提交

通用嵌入式 GUI 工具鏈 AWTK（zlgopen/awtk，3.3k stars）在視窗內把許可證從 LGPL-2.1 整體切換至 Apache License 2.0（LICENSE 檔案 +201/-504），由專案主要作者 lixianjing 提交。AWTK 及其 RT-Thread 軟體包（awtk 等）長期服務於 RT-Thread 上的 GUI 應用開發，許可證放寬有利於商用整合。屬生態參考類訊息（非 RT-Thread 專向）。

四、行業應用

4.1 Luckfox RV1103 單晶片無人機原型：RISC-V 核執行 RT-Thread 飛控（09-27）

日期：2026-09-27 17:25 ~ 20:04（建立與推送時間）　來源：luckfox-rv1103-drone

開發者 nguyencanhanh 公開一套單晶片四旋翼無人機原型：以 Rockchip RV1103（Luckfox Pico Mini B）為核心，Cortex-A7 執行 Linux 承擔相機、NPU 識別、Wi-Fi、GPS 與遙控接收，片內 RISC-V MCU 核（HPMCU）執行 RT-Thread 執行 1kHz 飛控環路；專案目標是以實測資料回答“單晶片架構能否直接飛行”，備選方案為外掛獨立飛控。截至 09-27：尚未實飛，但 Linux 與 MCU 已並行執行、1kHz 環路已實測，飛控軟體可在模擬器中完整執行並支援 3D 操控檢視；自研 LFX_FC_R1 飛控板（46×46mm）已完成佈線。專案以 MIT + CERN-OHL-P 許可開源，屬社群個人原型。
