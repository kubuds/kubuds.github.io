一、核心與版本動態

1.1 沁恆 CH32V203C8T6 開發板 BSP 合入主線（09-24）

日期：2026-09-24 16:21（北京時間，合入時間；提案建立於 09-22 晚間）　來源：PR #11827、合入提交 386b877b

主線在視窗內合入一筆新板級支援：沁恆微（WCH）CH32V203C8T6-EVT-R0 開發板 BSP，落位 bsp/wch/risc-v/ch32v203c-evt-r0。該板為青稞 V4B 核心（CH32V20x_D6），64KB 零等待 Flash 與 20KB SRAM；因官方 SDK 只提供 D8W 啟動檔案、對 D6 直接呼叫 Exit()，常規軟體包構建無法產出韌體，提案以 D6 中斷向量表（軟體中斷符號 SW_handler）與 64KB/20KB 連結指令碼補齊，並僅在該條件下修補 SDK 包指令碼，不影響 D8W 流程。預設映象啟用 GPIO 與 UART1（USART1 複用 PA9/PA10），PWM、ADC、RTC、獨立看門狗與 USB 裝置保留在 menuconfig 中（64KB 容量無法同時容納 USB 與前述四類外設）。提案另附帶兩處共享驅動修復：drv_usbd.c 調整 USBFS DMA 的 16 位 SRAM 偏移與 SET_ADDRESS 寫入時序（端點緩衝須駐留 SRAM、全速包長 64 位元組），drv_iwdt.c 為 CH32V2 系列補充適配。提案共 4 筆提交、26 個檔案（+2216/-57）。

1.2 rt_vsnprintf 寬度語義缺陷與核心修復提案（09-24）

日期：2026-09-24 20:52 ~ 21:29（北京時間，缺陷報告與修復提案的時間）　來源：Issue #11833、PR #11834

社群貢獻者在視窗內提交核心缺陷報告與配套修復：當前 rt_vsnprintf 實現（尤其 tiny 版本）對 %[width].[precision]s 的語義處理有誤，最小寬度被誤作最大寬度截斷——例如 %3s 格式化 “abcdef” 輸出 “abc” 而非完整字串，左對齊 %-3s 與 %*s 等變體同樣受影響。修復提案同步提交，改動覆蓋 rt_vsnprintf_std.c、rt_vsnprintf_tiny.c 與對應單元測試 TC_rt_sprintf.c（共 3 個檔案，+37/-18），內容為補充邊界檢測、實現寬度與精度的組合功能並最佳化測試用例。缺陷報告已有 3 條討論，修復提案處評審狀態。

1.3 評審佇列新增三條提案：網路棧修復與構建清理（09-24）

日期：2026-09-24 14:15 ~ 17:52（北京時間，建立時間）　來源：PR #11831、PR #11835、PR #11832

本期評審佇列合計新增五條提案，其中核心 vsnprintf 修復見 1.2、ESP32-C6 板級支援見 3.1，本條收錄其餘三條。其一修復 lwip-nat 的埠分配缺陷：原實現按掃描計數器而非空閒槽位索引分配轉換埠，進入分配路徑時計數器恆等於表大小，導致每個新對映都拿到同一埠，併發 UDP/TCP 會話相互衝突、回程流量可能匹配到錯誤表項；提案同時完成 lwIP 2.1 適配（標頭檔案更名與超時介面），並把 NAT 應用條件收緊為源與目的網路均匹配規則、ICMP 表滿時按 LRU 淘汰最舊條目（1 個檔案，+41/-11）。其二為 lwip-dhcpd 補上缺失的 string.h 標頭檔案：dhcp_server_raw.c 直接呼叫 memcmp / memset / strlen / strncmp / strchr 而未包含標準頭，隱式宣告在 64 位目標上會截斷 strchr() 返回指標（1 個檔案）。其三移除 components/drivers/ipc/SConscript 中冗餘的 __RT_IPC_SOURCE__ 宏定義（1 個檔案）。

三、生態與廠商適配

3.1 樂鑫 ESP32-C6 開發板 BSP 提案與軟體包原始碼同步提交（09-25）

日期：2026-09-25 01:20 ~ 02:38（北京時間，提案與配套軟體包提案的建立與更新時間）　來源：主線 PR #11836、esp-idf 軟體包 PR #17

社群貢獻者在視窗內為樂鑫 ESP32-C6-DevKitC-1 開發板提交主線 BSP 提案：模組為 ESP32-C6-WROOM-1（RISC-V，8MB Flash），新增 bsp/ESP/ESP32_C6，預設啟用 GPIO、UART0（GPIO16/17）與 ADC；提案強調 C6 須使用專用 bootloader 映象（不可複用 C3 的映象）、Flash 為 DIO 8MB 80MHz、應用偏移 0x10000。由於上游 esp-idf 軟體包自 2023-11-26 起未更新、缺少 C6 原始碼，貢獻者同步在軟體包倉庫提交 PR #17 補上 C6 的 scons 構建原始碼，兩處提案均處評審狀態（主線側 2 筆提交、40 個檔案，+9492/-50）。該貢獻者與 1.1 中 CH32V203 BSP 的提交者為同一人，同日橫跨沁恆與樂鑫兩條 RISC-V 晶片線。

3.2 社群釋出 RT-Thread Nano 免 IDF 移植工程：執行於 ESP32-S31（09-25）

日期：2026-09-25 10:04（北京時間，推送時間）　來源：esp32s31_rtt_nano 倉庫

社群開發者公開一份面向樂鑫 ESP32-S31（雙核 RISC-V，主頻 320MHz，板載 16MB Flash 與 16MB PSRAM）的 RT-Thread Nano 移植工程，特點是完全繞開 ESP-IDF 構建系統：自寫啟動彙編與連結指令碼、直接用 riscv32-esp-elf-gcc 編譯、獨立 esptool 燒錄，映象由晶片 bootROM 從 Flash 0x2000 直接載入（不使用 IDF 二級 bootloader）；控制檯走晶片內建 USB-Serial/JTAG，tick 採用 SYSTIMER、中斷走 CLIC，PIN / SPI（含 QSPI）/ I2C 外設接入 RT-Thread 裝置框架，可在 msh 中直接驗證。工程已做可復現構建驗證（89 個跟蹤檔案在乾淨目錄構建出逐位元組一致的映象）。屬個人專案，供社群參考。
