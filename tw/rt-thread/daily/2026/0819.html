三、生態與軟體包

3.1 新 AI 軟體包 LiME-TM 合入 packages 索引（本視窗最大技術事件）

日期：2026-08-19（09:17 北京時間合入）　來源：RT-Thread/packages commit #2015

社群開發者 wuhanstudio 提交的 LiME-TM 包今日合入 packages 索引倉庫（ai/LiME-TM，commit 69de99dd，PR #2015），RT-Thread AI 生態新增一條獨特的機器學習路線：

  • 定位：全稱 “Lightning fast and Memory Efficient Machine Learning for MCU (Tsetlin Machine)”，即基於 Tsetlin Machine 的嵌入式機器學習 C 語言庫（上游倉庫 wuhanstudio/lime-tm.c，MIT 許可）。Tsetlin Machine 以命題邏輯子句（布林模式）而非權重網路完成分類，推理退化為位運算，資源佔用極低且決策可解釋；
  • 包能力：支援片上模型訓練（MNIST 訓練與測試示例，可開 TSETLIN_MODEL_TRAINABLE）；模型可經 tsetlin compiler 編譯為靜態 C header 直接嵌入韌體，或以 protobuf 檔案從檔案系統載入（依賴 RT_USING_POSIX_FS）；Kconfig 提供兩組示例選擇，預設靜態模型示例；
  • 意義：packages/ai 目錄現有 14 個 AI 包（nnom、ncnn、TensorflowLiteMicro、AIfES、r-tinymaix 等）以神經網路推理為主，LiME-TM 首次補上”可解釋符號學習”路線，為工業故障診斷、感測器分類等需要決策可審計的場景提供新選項。

3.2 gdr GDB 除錯輔助框架更新

日期：2026-08-18（16:06-17:27 北京時間，5 筆提交）　來源：flespark/gdr

GDB RTOS 除錯輔助框架 gdr（GDB Python 擴充套件，在偵錯程式側解析 RT-Thread 核心物件）視窗內連續 5 筆提交：rtthread 核心物件列印器增加更多欄位、列印與命令輸出可讀性增強、新增 freertos 別名命令（frt）、config 符號統一改名、文件改進。配合 08-12 合入的子命令與實時物件名 tab 補全，面向核心與 rt-smart 使用者態除錯的開發者體驗在持續完善。個人專案（star 數少）但迭代活躍，列生態參考。
