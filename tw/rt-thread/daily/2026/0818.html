一、核心與版本動態

1.1 核心新增原生 AF_UNIX 本地套接字實現（8 月 17 日合入，本視窗最大核心事件）

日期：2026-08-17 17:15（北京時間合入）　來源：rt-thread PR #11681

創始人熊譜翔（BernardXiong）提交、維護者 Rbb666 合入主倉庫的 PR #11681「Add AF_UNIX sockets implementation」，共 36 個檔案、淨增約 5700 行，是本視窗規模最大的核心合入。核心內容：

  • SAL 新增本地協議族登錄檔：此前 SAL 要求 socket 協議提供方必須掛接網路裝置，該模型不適用於本地 IPC；本次引入獨立於 netdev 的本地協議族機制，原有網路裝置型 socket 行為保持不變；
  • DFSv2 支援 S_IFSOCK 節點：tmpfs 與 devtmpfs 可承載套接字檔案節點，為 /dev/log 這類路徑型套接字鋪路；
  • SCM_RIGHTS 描述符傳遞：新增 DFS 檔案引用計數助手，支援跨程序傳遞檔案描述符（sendmsg/recvmsg 輔助資料）；
  • LWP socket 系統呼叫轉換擴充套件：補充 sockaddr_un、musl msghdr、ancillary data 與 MSG_CTRUNC 的轉換支援，打通 rt-smart 使用者態程序使用 AF_UNIX 的路徑；
  • 新增可選元件 components/net/af_unix：支援 SOCK_DGRAM 與 SOCK_STREAM、基於路徑名的 bind/connect、socketpair、阻塞/非阻塞 IO、收發超時、poll/select 就緒、shutdown 與對端關閉處理、SCM_RIGHTS 描述符傳遞；
  • 配套：Kconfig 選項、SCons 整合、元件文件（README）、7 組 utest 用例（common/ipc/namespace/node/poll/rights 等約 1800 行測試）。

動機與意義：BusyBox syslogd/logger 等應用依賴基於路徑名的 AF_UNIX 套接字（典型如 /dev/log）。此前 RT-Thread 無法原生提供，只能藉助網路棧模擬。本次合入後 RT-Thread（含 rt-smart）獲得不依賴網絡卡的本地程序間通訊通道，是繼 8 月 17 日 rt-smart 打通 ROS 2 交叉編譯後，向”使用者態程序模型 + 標準 POSIX IPC”方向補上的又一塊關鍵基礎設施，對機器人/具身智慧場景的多程序協作與系統日誌鏈路有直接價值。

1.2 wlan 修復 wifi 命令靜默失敗問題（8 月 17 日）

日期：2026-08-17 14:34（北京時間合入）　來源：rt-thread PR #11696

kaidegit 提交的修復：當裝置模式未繫結到 AP 時執行 wifi ap 命令會無任何報錯地直接失敗，使用者難以排查；本次增加模式檢查並在失敗時給出明確日誌提示。驗證環境為 hpm + esp hosted 板。屬可用性小修復，配合前日合入的 WLAN 安全模式標誌（WPA3/企業級/WAPI/OWE/DPP），WLAN 框架層近期處於密集完善期。

三、生態與工具鏈

3.1 ENV 工具鏈新增可選線上外掛市場（8 月 18 日凌晨合入）

日期：2026-08-18 00:17（北京時間合入）　來源：RT-Thread/env PR #288

BernardXiong 主導的 PR #288「Add optional online plugin market」合入 ENV 工具鏈（RT-Thread Studio 的命令列後端）：

  • CLI 能力：新增 rt-env plugin market / market set / market clear 命令，支援 ENV_PLUGIN_MARKET_URL 環境變數覆蓋配置檔案中的市場地址；
  • WebUI 整合：配置市場後 WebUI 顯示線上外掛目錄，由本機 Host API 代理市場目錄、詳情與 prepare 流程；下載製品後透過一次性 upload id 交給本機安裝器完成安裝；
  • 安全與相容設計：未配置市場時行為與現狀完全一致，”線上外掛”頁隱藏、相關 API 返回 404；ENV 不會按外掛 ID 或任意 URL 直接安裝（下載後校驗再安裝）；
  • 質量：29 項單元測試透過（test_market / test_env_cli / test_webui_server）。

意義：這是 RT-Thread 官方工具鏈首次具備外掛分發渠道。結合 8 月 14 日合入的 epack 互動式腳手架（epack init 嚮導）與 8 月 13 日外掛生命週期文件，ENV 已形成”開發（epack）→ 釋出/獲取（外掛市場）→ 安裝（一次性 upload id 安全安裝）”的外掛閉環。工具鏈側連續第五天有合入（8/14 epack 嚮導 → 8/15 Buildroot 包匯入 → 8/16 外掛命令併發 → 8/17 smart-build ROS 2 → 8/18 外掛市場），生態基建節奏密集。

四、行業應用專章（機器人 / 具身智慧 / 工業）

  1. 本地 IPC 基建補齊，機器人多程序架構受益：AF_UNIX 合入使 rt-smart 使用者態程序間通訊不再依賴網路棧，配合 SCM_RIGHTS 描述符傳遞，可支撐機器人系統中”主控程序 + 感測器/執行器服務程序”的經典分解架構，也與前日 ROS 2 交叉編譯支援形成呼應——ROS 2 的 DDS 走網路域、本地輔助 IPC 走 AF_UNIX 的分工在 RT-Thread 上成為可能。
  2. AIoT 大賽收官，AI 專案是主旋律：2026 RT-Thread AIoT 大賽排名公佈，參賽作品以 AI 專案為主，反映了社群開發者從”裸機/傳統 RTOS 應用”向”端側 AI 應用”遷移的持續趨勢；完整名單與獲獎專案詳情待官方公告。
  3. 工業主線不變：8 月 27 日上海「睿擎工業平臺 Workshop：EtherCAT 實時控制與工業方案實戰」倒計時 9 天，視窗內無新增預熱資訊；睿擎工業平臺與 ENV 外掛市場（工控場景外掛化部署）的協同值得關注。

五、總結與趨勢觀察

  1. 核心側：本地 IPC 從”無”到”有”：AF_UNIX 原生實現（SAL 本地協議族 + DFSv2 S_IFSOCK + SCM_RIGHTS）是本視窗最大技術事件，標誌著 RT-Thread 在 POSIX 相容與程序間通訊能力上邁出實質一步，與 rt-smart 使用者態路線直接咬合。
  2. 工具鏈側：官方外掛分發渠道從 0 到 1：ENV 線上外掛市場合入，配合 epack 腳手架形成開發-分發-安裝閉環；未來 Studio 外掛生態的供給方式可能發生變化。
  3. 官方資訊出口滯後依舊，媒體側核查恢復正常：官方新聞 API 仍滯後約 2 個月，AIoT 大賽排名這類事件僅靠第三方媒體可查；本視窗 Google News 經代理恢復可達（昨日超時），媒體核查完整度較昨日提升。
  4. 機器人方向連續動作保持：8/17 ROS 2 交叉編譯 → 8/18 AF_UNIX 本地 IPC，兩天內兩筆與機器人/多程序架構直接相關的基礎設施合入，官方下半年主攻方向進一步明朗。
  5. 版本面平穩：v5.2.2 不變，核心大功能（AF_UNIX）以合入 master 方式先行，預計隨下個版本釋出。
