一、核心與版本動態

1.1 NXP i.MX RT1180 EVK BSP 功能大更新：I2C DMA/CAN/SPI/DWT/SDIO 與 EtherCAT 支援

日期：2026-08-21（17:45 北京時間合入，PR #11715）　來源：RT-Thread/rt-thread commit 6ea68279 / PR #11715

視窗內體量最大的一條合入，NXP 工程師（nxp-ran）主導，46 個檔案、+3579/-769。[BSP][NXP] Add new features of I2C DMA, CAN, SPI, DWT and SDIO for RT1180：更新模板、配置檔案與構建指令碼以支援 HyperRAM、多核啟動（multicore kickoff）、rpmsg-lite、NetC 乙太網、CherryUSB 與 EtherCAT；為 GCC/IAR/KEIL 三種工具鏈更新連結指令碼以支援多核 kick-off 與不同載入方式；更新 Keil 除錯 ini 檔案；新增 I2C DMA、CAN、SPI、DWT、SDIO 等外設特性支援。i.MX RT1180 為 NXP 跨界 MCU（Cortex-M33 平臺、整合 NetC 乙太網），本次為廠商主導的評估板 BSP 功能級增強。值得注意：EtherCAT 支援寫入 NXP BSP 清單，與睿擎工業平臺 EtherCAT 主線形成呼應，工控實時匯流排能力在 RT-Thread 生態內雙線推進。

1.2 核心 IPC 超時喚醒歸屬競態修復，配套迴歸測試

日期：2026-08-21（16:52 北京時間合入）　來源：RT-Thread/rt-thread commit ba79f694

[kernel][ipc] Fix timeout wakeup ownership race（ari.liu 提交，8 個檔案、+721/-14）：修復 timer stop 與 in-flight 超時回撥競爭時的執行緒 timer 歸屬問題——保持執行緒 timer 歸屬權直到超時回撥確認不再進行，且僅在 waiter 成功恢復後才消費 IPC 資源；同時補齊通用與 RT-Smart channel 超時回撥的歸屬清理。配套新增確定性排程器與 LWP 迴歸測試，覆蓋 Event、Semaphore、Mailbox、Message Queue、sender、receiver 六類場景。IPC 超時路徑的資源歸屬競態是嵌入式 RTOS 經典難點，本次修復同時覆蓋 rt-thread 核心與 rt-smart LWP 通道並固化迴歸測試，屬核心健壯性的實質增強。

1.3 C906 核心僅保留玄鐵 MMU 屬性

日期：2026-08-21（16:51 北京時間合入）　來源：RT-Thread/rt-thread commit 5ae08713

Ensure that c906 uses only the Xuantie MMU properties（rcitach 提交，1 個檔案、-56 行）：清理 libcpu/risc-v/t-head/c906/riscv_mmu.h，確保平頭哥玄鐵 C906（RISC-V）核心僅使用玄鐵 MMU 屬性，移除與通用 RISC-V MMU 屬性混用帶來的歧義。屬 rt-smart RISC-V 核心側適配的持續維護。

1.4 瑞薩 RA6W1 BSP 裝置驅動缺陷修復

日期：2026-08-21（13:10 北京時間合入）　來源：RT-Thread/rt-thread commit 46d74447

fix ra6w1 device bug（rcitach 提交，6 個檔案、+124/-23）：修復 RA6W1 EK 板級支援中的裝置問題，涉及 ADC 驅動（drv_adc.c）、PWM 驅動（drv_pwm_w.c）、板級 Kconfig 與時鐘配置（bsp_clock_cfg.h、hal_data.c）。延續瑞薩 RA6W1 BSP 的迭代節奏：08-05 首版、08-11 二期 45 檔案補 ADC/SPI/I2C 等驅動，本次為三期缺陷修復，符合廠商 BSP”先合骨架、後補驅動、再修缺陷”的演進模式。

1.5 Nuvoton 四系列 CAN 驅動鉗制接收 DLC

日期：2026-08-21（11:22 北京時間合入）　來源：RT-Thread/rt-thread commit 642040c4

[bsp][nuvoton] Clamp CAN receive DLC（hanzhijian 提交，4 個檔案、+16）：在 m2354、m480、n9h30、nuc980 四個系列的 drv_can.c 中統一對 CAN 接收 DLC（資料長度碼）做鉗制處理，防止越界值傳入，屬 CAN 驅動的健壯性修補。

1.6 版本狀態平穩

日期：2026-08-22　來源：rt-thread releases

最新正式版本仍為 v5.2.2（2025-10-31 釋出），視窗內無新 release、無預釋出。近期累積修復（Rust 構建、IPC 競態、libc/dfs、各 BSP）預計隨下個版本統一發布。

三、生態與廠商適配

3.1 flespark/gdr：RT-Thread GDB 除錯輔助框架視窗內三連更

日期：2026-08-21（03:38 / 07:11 / 07:49 UTC 合入）　來源：flespark/gdr commits

第三方 GDB RTOS helper 框架 gdr 視窗內 3 條與 RT-Thread 直接相關的合入：修復 rtthread object container 相容性與 heap 抽象資料欄位；rtthread heap 資訊在相對欄位缺失時 fallback 到記憶體遍歷；更新 rtt 系統輸出格式。該工具 08-19 已新增 rtthread heap detail 命令，面向 GDB 除錯 RT-Thread/rt-smart 場景的堆詳情與物件容器解析持續打磨，對核心態與 LWP 使用者態除錯鏈路有實際價值。

3.2 生態觀察：awtk 提交為通用 GUI 改進，非 RT-Thread 專項

日期：2026-08-21　來源：zlgopen/awtk commits

topic:rt-thread 近一週活躍倉庫中，awtk 視窗內提交（vgcanvas clip 改進、構建指令碼最佳化、crc 重實現）均為通用 GUI 引擎工作，與 RT-Thread 無直接關聯，標”生態參考/非專項”；canopennode-rtt 視窗內無新提交；GD32 下游映象倉庫 gd32_rt-thread 自 08-19 後無更新。

四、行業應用專章（工業 / 機器人 / 具身智慧）

4.1 視窗內無新獨立條目，近 3 天趨勢回顧

日期：2026-08-19 ~ 2026-08-21　來源：見各條目

行業應用側視窗內無新的獨立公開報道，但兩條工控呼應值得注意：

  • EtherCAT 進入 NXP RT1180 BSP（今日 1.1）：工控實時匯流排能力在 NXP 平臺落地，與睿擎平臺形成雙線；
  • 睿擎 Workshop 報名倒計時（今日 2.2）：8/27 上海 EtherCAT 實戰進入臨期推廣。

近 3 天趨勢（均已詳報，此處回顧）：

  • 睿擎工業平臺 DSMC+FPGA 通訊 90MB/s（08-19，電子工程專輯）：RK3506J 工業板 + FPGA 擴充套件板，16 位 DSMC 並行匯流排 + rt_event 事件驅動 DMA；
  • Beningo 2026 RTOS 效能報告參測（08-19）：RT-Thread 作為唯一國產開源 RTOS 進入 8 款參測名單；
  • 8/27 睿擎 Workshop：預熱（08-18）→ 報名倒計時（08-21）：EtherCAT 實時控制與工業方案實戰。

趨勢判斷：EtherCAT 生態位在 NXP 與睿擎雙平臺同時出現，工控實時匯流排是當前最清晰的主線。

五、總結與趨勢觀察

  1. 核心 + BSP”修復日”：視窗內 5 條合入，體量最大為 NXP RT1180 BSP 功能更新（+3579 行，EtherCAT/HyperRAM/多核/rpmsg-lite 支援），其次為 IPC 超時喚醒歸屬競態修復——同時覆蓋核心與 rt-smart LWP 通道並配套六類場景迴歸測試，是近期核心側最有分量的健壯性增強。
  2. RISC-V 側持續維護：C906 玄鐵 MMU 屬性清理，rt-smart RISC-V 適配保持活躍。
  3. 廠商 BSP 演進節奏清晰：瑞薩 RA6W1 走完”首版 → 二期補驅動 → 三期修缺陷”；Nuvoton 四系列 CAN 驅動統一補 DLC 鉗制。
  4. 工控主線雙平臺推進：EtherCAT 進入 NXP RT1180 BSP + 睿擎 8/27 Workshop 進入報名倒計時，本週四的活動為近期最值得跟蹤的落地觀察點。
  5. 官方資訊出口持續滯後：rt_org 停滯 2 個月，news/activity 分類介面連續報錯，社群與媒體動態仍快於官方渠道。
  6. 版本節奏：v5.2.2 已維持 9 個多月，近期修復（Rust 構建、IPC、libc/dfs、多廠商 BSP）持續累積，下個版本釋出視窗值得關注。
