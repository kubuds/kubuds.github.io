一、核心與版本動態

1.1 K230D 合入：128MB DDR 變體接上 ext4 與 ptyfs（11-06）

日期：2026-11-06 09:37（合入時間）　來源：提案 #11897、提案 #11892

15 個檔案、398 行新增、198 行刪除，維護者 BernardXiong 提的，10 月 18 日建、本期合入。內容是一次 BSP 的完整補齊：新增 SOC_K230 與 SOC_K230D 二選一，按 128MB DDR 重排預設記憶體佈局；把 GPIO 註冊成 RT-Thread 的 pin 裝置，驅動一次加 140 行，並補了 GPIO 測試；開啟 ext4 根檔案系統，掛載 ptyfs 與 procfs；刪掉一批沒有用到的板級外設定義。工具鏈保持 K230 SDK 的 riscv64-unknown-linux-musl，ABI 仍是 lp64d。

這條的分量在依賴關係：它要求先有 #11892 的 RISC-V MMU 與玄鐵架構修正（上一期報告 1.2 那筆），還需要 lwext4 軟體包；ptyfs 與 procfs 的掛載點正是 RT-Smart 終端與裝置樹匯出的前提。也就是說，K230D 不是孤立加一塊板，而是把 11-05 那批 Smart 修正在一塊 128MB 記憶體的真實 RISC-V 板子上串起來。CI 尚未給出構建結論，作者只在本地用 K230 SDK 工具鏈編過。

1.2 STM32F1/H7 輸入捕獲落地：746 行補齊四路定時器（11-06）

日期：2026-11-06 09:20（合入時間）　來源：提案 #11975、議題 #11967

9 個檔案、746 行新增、零刪除。議題 11 月 2 日提出，此前論壇只有一份個人實現，四天後驅動進主線。實現用 STM32 HAL 的 TIM1 至 TIM4 做輸入捕獲裝置，通道、濾波器與初始捕獲極性都可配置；處理了 APB 定時器時鐘倍頻、TIMPRE 與 32 位計數器三處平臺差異；重啟捕獲通道前先清掛起的捕獲與過捕獲標誌。

CI 掛了兩塊板：STM32F103 戰艦版掛 inputcapture 片段，STM32H743 Nucleo 掛完整配置。對使用者來說，這類外設框架補齊比核心修缺陷更能擴大適用面——輸入捕獲是電機控制、編碼器與脈衝測量的常用路徑。

1.3 非 SMART 的 CPU 時間記賬糾偏（11-07）

日期：2026-11-07 21:39（合入時間）　來源：提案 #12001

只改 src/clock.c 兩行：把使用者態時間記賬的分支用 RT_USING_SMART 包起來。此前非 SMART 構建也會走這段邏輯，執行緒時間被算進使用者態，系統時間與空閒時間統計隨之偏小。兩行的改動，影響所有非 Smart 專案的 CPU 佔用率讀數。

1.4 GIC 列印函式的格式符糾正（11-08）

日期：2026-11-08 16:20（合入時間）　來源：提案 #11914

3 個檔案、71 行新增、48 行刪除，改 gic.c、gicv3.c 與 gicv3.h。四類問題：把 32 位實體地址用 %p 列印，向 %p 傳非指標屬未定義行為；把無符號量用 %d 列印；GIC 版本號的型別轉換缺失；GIC RWP 宏裡的一處有符號左移。提案 10 月 21 日建、11 月 8 日合入，作者 Wei-beep，共同作者是維護者 Rbb666。用 -Wall -Wformat 編 Cortex-A BSP 時不再刷警告。這類清理不影響功能，但直接影響廠商 BSP 的編譯潔淨度。

二、安全與 libc 修復

2.1 timerfd 兩處校驗同日合入（11-08）

日期：2026-11-08 14:12 / 14:11（合入時間）　來源：提案 #11996、缺陷 #11984、提案 #11997、缺陷 #11980

兩筆相隔一分鐘落地，各改一個檔案。

第一筆是 timerfd_settime 與 gettime 的 fd 型別校驗：原實現把任意檔案描述符的私有資料當作定時器結構體解引用，傳進來一個普通檔案或管道，核心就會按錯誤型別讀結構體。修法是先比對檔案操作表，確認是 timerfd 才取私有資料，DFS v2 看 df->fops、v1 看 vnode->fops，25 行新增。

第二筆是 POSIX 定時器的陣列越界：timer_gettime 與 timer_settime 直接拿使用者給的 timer_t 當下標索引 _g_timerid，而 timer_delete 早就有邊界檢查。補上 id 不得大於等於 TIMER_ID_MAX 的判斷，19 行新增。

這兩處缺陷在前兩期報告的安全清單裡出現過，本期從已報告變成已修復。timerfd 與 POSIX timer 都屬於使用者可控控制代碼，問題模式一致：先解引用，再判斷型別或範圍。

2.2 picolibc 原型對齊：asctime_r 與 ctime_r 的陣列引數（11-08）

日期：2026-11-08 14:01（合入時間）　來源：提案 #11999

ctime.c 13 行新增、3 行刪除。picolibc 把緩衝區宣告成長度 26 的受限陣列，RT-Thread 用指標形式宣告，於是陣列引數與空指標比較兩類警告一起出現；其它 C 庫仍是指標形式，修法是用條件編譯按庫切換宣告。作者 Parthiban Nallathambi，來自 Linumiz。

這筆單獨列出的原因是它解開了另一條線的死結：瑞薩 RH850 移植提案明確寫著 utest CI 要先等這個 ctime.c 修復，見 4.3。

2.3 RISC-V FPU 上下文切換缺陷：報告四小時後出修復提案（11-07）

日期：2026-11-07 23:10（報告）/ 2026-11-08 03:14（提案）　來源：缺陷 #12005、提案 #12006

本期最值得盯的一筆。報告者 boa-z 在移植 ArtInChip D213（C906，M 模式）時發現執行緒切換後 fs1 不對，為排除 BSP 因素，回到官方 qemu-virt64-riscv 復現，環境是 QEMU 10.0.13、OpenSBI 1.6、RV64D、單 hart、master c63d7bc9。他寫了一個跨切換型別檢查浮點暫存器的用例，坐實兩個問題。

其一是自願切換，也就是 rt_thread_yield：SAVE_CONTEXT 與 RESTORE_CONTEXT 只儲存整數 callee-saved 暫存器，兩個用浮點的執行緒互相覆蓋 fs0 至 fs11，報告裡給了實測值，期望 0x3ff0000100000000、實得 0x3ff0000000000000。其二是定時搶佔：SAVE_ALL 存了 f0 至 f31 卻沒有存 fcsr，浮點舍入模式與異常標誌會被靜默改掉。這類問題不會崩，只會讓計算結果慢慢漂移。

維護者 BernardXiong 四小時後提出 #12006：把 fs0 至 fs11 與 fcsr 追加進切換幀，trap 幀補 fcsr 的存取，切換幀大小向上取整保證 16 位元組對齊，併為中斷切換構造的幀初始化 fcsr；配套在 context_ext.h 與 stack.h 加偏移與佈局宏。提案仍在審，尚無實機驗證記錄。考慮到 RISC-V 在 RT-Thread 裡的權重，這條建議優先合入。

3.3 RISC-V 中國峰會：端側 AI 全棧，車規軟體已上車測試（10-18）

日期：2026-10-18 至 10-20（活動）/ 2026-11-06 09:59（釋出）　來源：官方新聞

第六屆 RISC-V 中國峰會在深圳會展中心福田舉行，設 1 場主論壇、7 場平行分論壇與 Member Day。RT-Thread 技術專家張丙儒在嵌入式物聯網智慧硬體與汽車電子工業機器人兩個分論壇演講，題目分別是《從模型上芯到 Agent 入場：RT-Thread 的 RISC-V 端側 AI 全棧實踐》與《RT-Thread 與 RISC-V 在車載和機器人實時控制中的實踐》。

第一條的核心判斷是焦點轉移：端側 AI 從模型能否跑通，轉到智慧體能否在受限算力與實時約束下穩定駐留。做法是向下用統一 BSP 與驅動框架遮蔽核心差異，向上用輕量化執行時承載離線喚醒、語音互動與多模態推理，並讓 AI 任務與實時任務同處一套排程體系，避免 AI 搶佔實時性。

第二條給了兩個硬進展：車規級基礎軟體已應用於 RISC-V 晶片並完成上車測試，正推進量產；程翧車控系統可為 RISC-V 提供完整的 AUTOSAR CP 基礎軟體，覆蓋系統服務、儲存、通訊、診斷、標定與資訊保安，並配套配置和程式碼生成工具。機器人側，RT-Thread Smart 已在 SoC 級晶片上完成 ROS2 數十個 C/C++ 軟體包適配。適配範圍寫的是 2018 年啟動、覆蓋芯來、玄鐵、Andes 等 IP 廠商授權的超百款晶片與 BSP，核心原生支援 SMP 與 AMP。

3.4 elexcon 深圳：25 億裝機與三重功能安全認證（09-09）

日期：2026-09-09 至 09-11（活動）/ 2026-11-06 15:54（釋出）　來源：官方新聞

第 23 屆深圳國際電子展暨嵌入式展，RT-Thread 睿賽德攜全棧能力參展。稿件給出的數字：2006 年起步、30 萬開發者、累計裝機 25 億臺；面向工業與汽車推出睿擎工業平臺與程翧整車 OS，客戶點名國家電網與中國中車。

最硬的一條是功能安全：Safety OS 同時拿到 IEC 61508 SIL3、EN 50128 SIL4 與 ISO 26262 ASIL-D 三重認證，稿件稱國內同時握有這三張證書的嵌入式作業系統僅此一家。AI 側的說法與此前一致：AIOS 混合部署已在晶圓廠天車與六軸機器人場景驗證，AI KIT 做一站式開發，與英飛凌聯合的 AI 飛控平臺已在無人機上做 AI 故障檢測；展會期間獲邊緣 AI 解決方案創新獎。

4.1 QEMU 虛擬裝置清單推進：SPI 迴環、CAN、SDIO、DAC/I2C 進 CI（11-06）

日期：2026-11-06 至 11-08（合入時間）　來源：議題 #11972、提案 #11979、提案 #11990、提案 #11752、提案 #11758

本期最成體系的一條線。議題 #11972 是一份 QEMU 虛擬裝置與覆蓋率清單，背景寫得很直接：按 #11955 的版本釋出規劃，Z 版本主要依靠 QEMU 加 CI 自動測試核心、元件與模擬支援範圍內的驅動，彙總覆蓋率、透過率與已知問題，供維護者決定是否釋出。清單按框架逐項列 utest 與 QEMU 兩個勾，覆蓋 adc、dac、i2c、spi、can、pwm、rtc、watchdog、timer、touch、audio、usb、sdio、flash、ethernet、wlan、pin、serial 與 ipc 等二十餘項。

視窗內落地的四筆：

  • SPI 虛擬迴環匯流排（#11979，6 個檔案、154 行）：註冊一條純軟體 SPI 匯流排，預設名 spi2，用記憶體複製做迴環傳輸，讓 qemu-vexpress-a9 在沒有 PL022 模型時也能跑 SPI 迴環用例；配套加 utest 配置與 CI 矩陣項。
  • DAC 與 I2C 的 QEMU 任務（#11990）：各加一份 utest 配置，工作流裡拆成兩個獨立作業。
  • CAN 收發測試（#11752，1792 行）：1572 行的用例檔案，22 個主機樁場景，覆蓋超時續期、tick 迴繞、空讀、錯誤傳播與正常接收；作者用 50 tick 超時加 1000 tick 看門狗復現了原來的重複幀與不匹配幀掛死。
  • SDIO 塊裝置讀寫測試（#11758，438 行）：372 行用例，驗證限定在格式與空白改動，未做整 BSP 構建。

仍在審的兩筆同樣屬於這條線：觸控框架測試（#12002）讓中斷使能與禁用返回錯誤碼，並用模擬操作在 QEMU 連跑兩輪；dlmodule 迴歸（#11989）在構建時生成真實 ARM ELF 模組，10 個用例覆蓋可重定位目標、共享目標、符號匯入匯出與重複載入解除安裝。測試基建正在從零散補用例變成按釋出流程列清單，這是 Z 版本節奏的前置條件。

4.2 WCH 兩條線：青稞快速中斷配置與 CH32V208 低功耗（11-07）

日期：2026-11-07 至 11-08（提案時間）　來源：提案 #12004、提案 #12007

WCH 的 RISC-V 青稞核心在快速中斷上並不齊整：不同型號支援程度不同，只有兩級硬體中斷的型號不該用快速中斷。提案 #12004 按晶片系列配置對應的核心能力，新增快速中斷開關，統一中斷屬性宏，讓支援的晶片走快速中斷、其餘退回普通中斷；順帶更新 SDK 並調整 CH32V203 啟動檔案。驗證板是 CH32V208W-R0 與 CH32V307V-R1。

#12007 給 CH32V208 加 PM 元件支援，依賴前一筆記合入。兩筆都還開著。WCH 是國內 RISC-V MCU 出貨量最大的廠商之一，BSP 的電源管理與中斷配置直接決定低功耗場景的可用性。

4.3 瑞薩 RH850 G4KH 移植提案：ARM 與 RISC-V 之外的第三個架構（11-06）

日期：2026-11-06 20:41（提案時間）　來源：提案 #11998

libcpu/rh850 用 TRAP0 做執行緒切換，含巢狀中斷、FPU 上下文與故障轉儲；bsp/renesas/rh850 提供啟動、中斷控制器、OSTM 與 RLIN3 串列埠驅動，以及 qemu-rh850-u2c 板級；CI 覆蓋硬浮點與軟浮點兩種構建加核心 utest。驗證記錄寫得很實：GCC 14.3 加 picolibc 工具鏈 v1.1.0、qemu-rh850 v1.0.0，msh 能啟動，kernel_basic 22/22，記憶體與 ipc 用例透過。

提案仍標草稿，原因就是 utest CI 需要先修 picolibc 下的 ctime.c，本期 #11999 已合入，這個前置條件解除。RH850 是車規 MCU 裡常見的架構，RT-Thread 此前主力在 ARM 與 RISC-V，這一筆如果合入，等於把 utest 與 libcpu 抽象拿到第三個架構上驗證。
