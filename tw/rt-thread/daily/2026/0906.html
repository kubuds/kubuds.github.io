一、核心與版本動態

1.1 主倉庫零合入延續至第三視窗；新 PR #11780 修復 SDIO CIS 後設資料記憶體洩漏

日期：2026-09-05（PR 建立 16:59 北京時間）　來源：RT-Thread/rt-thread PR #11780（關聯 issue #11724）

主倉庫 rt-thread 本視窗零合入、零新 issue，最近合入仍為 09-03 的 #11776（第三視窗延續），release 仍為 v5.2.2（2025-10-31）。視窗內唯一新增為社群開發者 Huoyanlifusu 提交的 PR #11780「[components][sdio] Fix CIS tuple memory leak」：修復 #11724 所指問題——sdio_read_cis() 處理 CISTPL_FUNCE 與 CISTPL_VERS_1 等部分 CIS tuple 時申請記憶體但處理完成後未釋放，反覆初始化/反初始化 SDIO 裝置會導致記憶體洩漏；修復方案為上述兩個分支處理完畢後釋放臨時 tuple，未知 tuple 仍交由 func->tuples 連結串列管理並由 sdio_free_cis() 統一釋放。改動 1 個檔案、淨增 2 行，作者在 qemu-vexpress-a9 BSP 上完成驗證。該 PR 是作者連續第三個元件級修復（#11756 netdev ping 空指標崩潰修復已於 08-26 合入；#11774 sal SIOCGIFCONF 越界修復仍在評審中），延續「元件級記憶體安全修復」的貢獻主線。評審佇列其餘條目與昨日持平：#11779 CAN 框架重構自維護者 CYFS3 09-03 表態後無新評論，#11775（c908 rt-smart）、#11772（堆 ASan）、#11689（stm32 SPI BDMA）等均 open 未動。

三、生態與廠商適配

3.1 canopennode-rtt：CiA402 控制器側與診斷/EMCY 補齊，CiA401 通用 I/O profile 分支啟動

日期：2026-09-05 ~ 09-06（14:08 ~ 次日 10:06 北京時間，6 筆提交）　來源：wdfk-prog/canopennode-rtt（CIA401 分支）

自昨日 11:08 收錄 CSP/CSV/CST 週期同步模式後，該倉庫開發未停：預設分支新增「CiA402 device diagnostics and EMCY bridge」（裝置診斷與 EMCY 應急報文橋接，09-05 14:08）、「新增 CiA402 控制器支援和相關測試」（16:13，CiA402 覆蓋從裝置側擴充套件到控制器側）與文件清理重構（16:36）；隨後開出新分支 CIA401，09-05 21:53 起連續落地「generic I/O device profile core」「digital event and output fail-safe support」及 09-06 10:06 的「模擬量輸入輸出事件和故障安全功能支援」。至此該 CANopenNode 移植在 09-03 以來一週內完成雙線擴充套件：運動控制 profile（CiA402：多軸、PP/PV/Homing、CSP/CSV/CST、診斷與 EMCY、控制器側）與通用 I/O 裝置 profile（CiA401：數字/模擬量事件與故障安全），CAN/工業現場匯流排方向的生態推進主線保持全社群最活躍。結合該作者同時在主倉庫推進 Generic CAN 框架重構（#11779），「框架層 + 應用層」雙線並進的態勢不變。

3.2 生態參考：gdr GDB 除錯框架收尾 FreeRTOS 適配，RT-Thread 保持首要支援

日期：2026-09-05（17:39 北京時間收尾提交）　來源：flespark/gdr

topic:rt-thread 倉庫 flespark/gdr（GDB Python 環境下的 RTOS 除錯輔助框架，提供 rtt threads/rtt timers 等 RTOS 命令樹、核心物件 pretty-printer 與便利函式）視窗內提交「refactor(freertos): wrapup of new rtos support, code and docs quality enhance」，收尾 FreeRTOS 第二介面卡。據其 README：RT-Thread（3.1.x / 4.0.x / 4.1.x，Cortex-A9 全系驗證、RV64 自 4.0.4 起）仍是首要支援物件，視窗內完成的 FreeRTOS 通道（V10.3.0 ~ V11.3.x）在 QEMU 上補齊了 64 位 RISC-V lane 與 MPS2-AN521 雙核 SMP 驗證，屬通用框架擴充套件、非 RT-Thread 專項提交，但對 RT-Thread 使用者（含 RISC-V 目標）的 GDB 除錯工具面是正向參照，收錄作生態參考。
