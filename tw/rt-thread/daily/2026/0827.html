一、核心與版本動態

1.1 netdev：修復無網絡卡環境 ping 空指標崩潰

日期：2026-08-27（09:04 北京時間合入）　來源：RT-Thread/rt-thread commit 14ef29af

主倉庫視窗內合入一筆元件穩定性修復：fix(netdev): 修復無網絡卡時 ping 命令空指標崩潰，由社群開發者 zhangyuyang 提交（author 時間 08-26 14:19）、核心維護者 Rbb666 於 08-27 09:04（UTC 01:04）合入。問題根因：netdev_cmd_ping 中 netdev 回退到 netdev_default 後未判空，QEMU 無網絡卡環境下執行 ping 直接解引用 NULL 觸發 data abort；修復後在回退路徑補充空指標檢查，提示無可用網絡卡並返回錯誤。改動集中在 components/net/netdev/src/netdev.c 單檔案。這是 v5.3.0-beta 分支建立（08-24）後主分支的又一批低風險穩定性修復，與此前 HW Stack Guard、finsh 清理形成”整理期”節奏的延續。

1.2 瑞薩 BSP：SPI 驅動兩筆修復合入

日期：2026-08-27（09:01 北京時間合入）　來源：RT-Thread/rt-thread commits 69c26789 / fcc4d6c0

同一時間點（09:01 UTC 01:01）由 CYFS 提交併合入瑞薩 BSP 兩筆 SPI 驅動修復：其一 [bsp/renesas][drivers] Fix SPI runtime configuration，修復 SPI 執行時配置問題；其二 [bsp/renesas][drivers] Skip invalid chip select writes in SCI SPI，跳過 SCI SPI 中無效片選（chip select）寫入。兩筆均屬 bsp/renesas/ 驅動層打磨，與 08-25 合入的 RA6W1 BLE OTA 映象生成最佳化同屬瑞薩 BSP 持續迭代序列（RA6W1 BSP 08-05 首版、08-11 二期補外設後，SPI 驅動層繼續收尾），”先合骨架、後補驅動”特徵延續。

三、生態與廠商適配

3.1 canopennode-rtt：新增 LSS 執行時波特率啟用

日期：2026-08-27（11:00 北京時間合入）　來源：wdfk-prog/canopennode-rtt commit 11d7e9eb

面向 RT-Thread 的 CANopenNode 整合軟體包（wdfk-prog/canopennode-rtt）於 11:00 合入新功能 feat[canopennode][lss]: support runtime bitrate activation，支援 CANopen 節點執行時波特率啟用。繼 08-25 合入 LSS Store 配置持久化（含 EEPROM 儲存層與 AT24CXX 解耦、啟動持久化）後，這是該包 LSS 能力的第二期擴充套件。近兩週該包保持穩定迭代節奏：08-17 GFC 協議診斷、08-19 ASCII 閘道器 MSH 控制檯橋、08-20 SDO 塊傳輸校驗、08-24 EEPROM 儲存診斷、08-25 LSS 持久化、08-27 執行時波特率啟用，每週 2-3 筆功能提交，是當前 RT-Thread 第三方工業協議軟體包中最活躍者之一。

四、行業應用

4.1 2026 RTOS 效能榜單出爐：RT-Thread 納入八大 RTOS 獨立評測

日期：2026-08-26（媒體刊出）　來源：電子工程專輯（經 Google News） / Beningo 官方報告頁 / PX5 官方解讀頁

電子工程專輯 08-26 刊出「2026 年 RTOS 效能榜單出爐！」：Beningo Embedded Group（Jacob Beningo）釋出《2026 RTOS Performance Report》，基於 Eclipse Thread-Metric 測試套件在真實 Cortex-M 硬體上對 8 款 RTOS 做獨立對比——PX5 5.3.1、ThreadX 6.5.1、FreeRTOS 11.3.0、Zephyr 4.4.1、Arm Keil RTX5 5.9.1、RT-Thread、NuttX、Micrium uC/OS-III，含 9 項 native API 測試（排程、記憶體分配、訊息、同步、中斷處理與中斷延遲等）與 POSIX pthread 基準、跨架構（M4F vs M33）與編譯器（IAR vs GCC）影響附錄。結論：PX5 連續第二年全場最快（native API 下 ThreadX 最高慢 30.2%、FreeRTOS 慢 80.7%、Zephyr 慢 45.3%）；RT-Thread 在 native 測試中最高較 PX5 慢 86.3%，POSIX pthread 口徑下最高慢 94.6%（PX5 官方口徑，POSIX 場景其原生實現佔優）。對本報告的意義：其一，RT-Thread 被第三方獨立評測納入 8 強對比陣容，側面印證其全球市場地位；其二，效能資料不及第一梯隊，且 Beningo 報告對除 RT-Thread 外全部參測系統均標註固定版本（RT-Thread 未標版本），橫向比較口徑存在侷限，具體結論建議參照原報告方法論後解讀。

五、總結與趨勢觀察

  1. 主分支小步加固延續：netdev ping 空指標修復與瑞薩 SPI 兩筆修復於 08-27 上午同日合入，v5.3.0-beta 建立後主分支繼續以低風險穩定性修復推進，未見大型特性合入。
  2. 睿擎 Workshop 今日落地：本週官方口徑最重要的觀察點，視窗內無會前新報道，會後報道預計明日出現，屆時核查官方新聞 API 與媒體側。
  3. 第三方軟體包生態活躍：canopennode-rtt 保持每週 2-3 筆功能提交節奏，LSS 執行時波特率啟用為二期能力擴充套件；CANopen 工業協議方向值得持續跟蹤。
  4. 行業地位與效能口碑並存：RT-Thread 納入 Beningo 2026 RTOS 效能榜單 8 強對比，市場地位獲第三方認可；但效能資料排名靠後且參測版本未標註，需辯證看待。
  5. 新聞面持續平靜：官方新聞 API 連續第七日無新增，媒體側僅電子工程專輯榜單報道一條，其餘 gnews 命中均為拆詞噪音。

侷限性說明：電子工程專輯原站（eet-china.com）本機直連超時，榜單報道細節以 Beningo 官方頁與 PX5 官方解讀頁交叉核實；RT-Thread 參測版本在官方報告中未標註，效能對比口徑存在不確定性。
