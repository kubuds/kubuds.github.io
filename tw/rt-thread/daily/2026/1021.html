一、核心與版本動態

1.1 RISC-V 票號自旋鎖改用原子加：多核爭用下的活鎖路徑被移除（10-20）

日期：2026-10-20 16:04（建立時間）　來源：PR #11904、cpuport.c

維護者 GuEe-GUI 提交 RISC-V 公共層的票號自旋鎖改造（6 檔案 +33/-37，兩筆提交）。原實現取號與釋放都在同一個 32 位字上走「載入保留加條件儲存」的迴圈：高 16 位是待發票號、低 16 位是當前持有號；一旦解鎖方在同一字上重試條件儲存，取號方的保留會被反覆沖掉，多核高爭用下可陷入活鎖。新實現把取號換成一條原子加指令，向高半字加一即完成取號，不可能與解鎖爭用同一保留；解鎖改為只由持有者寫低半字，一次半字儲存完成、不再讀改寫整字，因此在取號併發進行時也不會覆蓋新票。拿到鎖後另補一次記憶體屏障，保證臨界區訪問排在觀察到釋放之後。提案標為成熟版本，分派給 RISC-V 核心評審。

1.2 同優先順序執行緒就緒順序修復提案：IPC 喚醒與新啟動改為追加隊尾（10-21）

日期：2026-10-21 00:06（建立時間）　來源：PR #11907、Issue #8459

社群成員 Yunlk 就就緒佇列插入順序問題開出修復（4 檔案 +255/-22，含新增 utest）。原邏輯對任何沒有「已讓出」標誌的執行緒都插到隊首，而執行緒被切走時該標誌會被清掉，於是從訊號量等 IPC 掛起佇列恢復的執行緒、以及新啟動的執行緒全都插隊首，同優先順序執行緒的實際執行順序與就緒順序相反。提案先儲存原始狀態再覆蓋，只有「仍在執行、且時間片未用盡被搶佔」這一種情況保留隊首插入，其餘一律追加隊尾；單核與多核兩處插入分支做一致修改，並新增一個覆蓋訊號量喚醒與啟動兩條路徑的用例。作者在 qemu-vexpress-a9 實測：修復前訊號量喚醒順序為乙甲、啟動順序為丁丙，修復後分別為甲乙與丙丁。提案仍在審，兩個工作流待維護者批准。

1.3 串列埠 V1 補上接收超時事件：超時併入 RX_IND 回撥（10-21）

日期：2026-10-21 00:15（建立時間）　來源：PR #11909、Issue #8143

接收超時事件（編碼 0x05）在標頭檔案裡早有定義，但 V1 框架的中斷處理只覆蓋前四個事件且沒有兜底分支，驅動發出該事件時框架什麼都不做，通知被靜默丟棄。倉庫裡恰有兩個驅動依賴它切分資料幀：沁恆 CH579M 與華芯微特 SWM341 都用晶片的接收超時中斷判定「一幀收完」，兩者都在 V1 框架上，結果是幀邊界實際丟失，只能退化成按硬體水位上報。提案把該事件併入接收指示回撥：先排空硬體 FIFO，再按軟體 FIFO 已快取長度回撥上層。改動僅一行分支（含註釋共 5 行），未動 V2，因為 V2 標頭檔案根本沒有這個宏。作者只做到編譯級驗證，缺少帶空閒超時中斷的硬體，另提出可在偽串列埠裝置上補用例進 CI。

二、安全與穩定性跟進

2.1 cromfs 目錄名長度未約束：ls/getdents 越界並劫持核心 PC（10-20）

日期：2026-10-20 19:29（建立時間）　來源：Issue #11905

貢獻者 XueDugu 新開 cromfs 缺陷單。讀取目錄項時對目錄名長度不做任何上界檢查，超長名字會把內容拷進固定大小的目錄項緩衝、越過其尾部，溢位量足夠改寫相鄰資料，ls 或讀取目錄即可觸發，作者稱可將核心程式計數器導向可控位置。缺陷由 2022-12-14 的一筆 cromfs 同步提交引入，v4.1.1 尚無此問題，自 v5.0.0 起至 v5.3.0 與當前主線全部受影響；DFS 的兩份實現同源，v1 與 v2 各有一份未加約束的複製。作者在 QEMU vexpress-a9 上覆現，單子目前未被認領。

2.2 OFW 深度預檢改為除錯門控：維護者建議後作者加編譯開關（10-20）

日期：2026-10-20 09:11 ~ 16:03（評論時間）　來源：PR #11901、Issue #11879

上期收錄的裝置樹深度預檢提案在本視窗走完一輪評審。評審先質疑預遍歷的開銷，建議改用執行期檢查、超限即退出並釋放記憶體；作者回應稱不完整樹的釋放要沿指標遞迴遍歷，分配點零散、易漏或重複釋放，而檢查函式只讀、不分配、不解析屬性，相對展開本身開銷很小。隨後維護者給出方向：OFW 在設計上偏信任韌體，64 層遠超多數 SoC 的實際需求，建議只在除錯模式下啟用這段檢查。作者接受，把深度檢查包進除錯開關，並在 qemu-virt64-aarch64 上開啟除錯模式、用一棵 65 層裝置樹複測。改動已推送，提案仍在審。

2.3 tmpfs 截斷缺陷在 RT-Smart 的 aarch64 上覆現並被認領（10-20）

日期：2026-10-20 22:53（復現評論）　來源：Issue #11902

上期收錄的 tmpfs 截斷缺陷在本視窗補上裝置側證據。社群成員在 RT-Smart 的 qemu-virt64-aarch64 板級上覆現：把檔案截斷到 0 位元組時，緩衝區被釋放、函式卻返回成功，應用隨後讀寫落在已釋放的核心堆上，可造成資訊洩露與雙重釋放。復現環境為 QEMU 11.0.0 的 virt 機型加 GICv3、交叉工具鏈 15.2.1、DFS_V2 配置。該單已於 10-20 由另一位社群成員認領，修復補丁尚未提交。

2.4 其餘在審進展：中斷應答修復待複測、IAR 隱式宣告討論繼續（10-20）

日期：2026-10-20（評論時間）　來源：PR #11860、PR #11864、Issue #9941、PR #10096

四條既有條目的視窗內進展。aarch64 中斷控制器應答裡去掉冗餘掛起清除的提案（#11860）作者表示這兩天再測一版陷阱處理改法，暫不合並。IAR 8.40 下日誌函式隱式宣告導致浮點列印錯亂的提案（#11864）補充彙編層面解釋：缺少原型時編譯器按固定傳參推導可變引數，%f 因此取錯位置，評審仍要求補齊板級配置與同配置下的前後輸出記錄。另有兩條流程核實：#9941 實測 scons --attach 在主線可用，建議關閉該需求單；#10096 確認按需編譯選項仍未進主線，且提案分支嚴重滯後，建議先變基。

日期：2026-10-20 16:04（建立時間）　來源：PR #11904、K1 BSP 說明

與自旋鎖改造同批，進迭時空 K1 的預設核數從 4 改為 8，中英文說明同步更新。倉庫根目錄的板級支援表新增該廠商分割槽，K1 一行在 GPIO、串列埠、ADC、I2C、SPI、看門狗、定時器、PWM、RTC、SDIO、PCI、DMA、乙太網、音訊、顯示、加解密各列均標為支援；SPI 與 QSPI 從「已移植、驗證中」改為「支援」，此前掛著的 SPI NOR 讀 ID 問題隨之關閉。上一期 K1 首版合入時留下了這兩處待辦，本視窗一併收口。

4.2 中文 Windows 下 scons –attach 崩潰：表情符號換 ASCII 的修復提案（10-20）

日期：2026-10-20 23:42（缺陷單建立）　來源：Issue #11906、PR #11908

中文 Windows（內碼表 936）下執行 scons --attach 會直接拋編碼異常、整條命令中止：提示語裡用了兩個表情符號，GBK 無法編碼。該命令的三種用法都走同一個函式，等於在中文環境完全不可用；設環境變數強制 UTF-8 可繞過，但普通使用者不會知道。缺陷單當天提交，同日給出修復提案，把 4 處符號換成 ASCII 標記並保留原有 ANSI 顏色，作者稱與倉庫其他指令碼的彩色輸出慣例一致。另有一條評論說明該提案的記憶體報告檢查失敗源於上游第三方 action 自身損壞，與本改動無關。

五、行業應用

5.1 雙板協同智慧終端：M7 顯示端跑 RT-Thread 與 LVGL，C3 作聯網橋（10-20）

日期：2026-10-20 08:31（釋出時間）　來源：社群文章：基於 NS800RT7P65 與 ESP32-C3 的雙板協同智慧終端

2026 嵌入式大賽作品，用兩顆微控制器分工。納芯微 NS800RT7P65（Cortex-M7，帶硬體浮點）跑 RT-Thread 5.3.0 與 LVGL 9.1.0，做 3×3 桌面與 14 個應用，屏為 240×320 的驅動晶片方案，作者實測 SPI 上限 50 MHz，曾試 70 MHz 整屏破圖；16 MB 外部 NOR 掛載小檔案系統，背光、調色、遊戲最高分與鬧鐘斷電不丟；旋鈕接正交解碼器，按鍵直讀加軟體消抖。樂鑫 ESP32-C3 作聯網端，負責無線連線、時間同步、上報與本機網頁升級，網頁可改配置、傳韌體。兩板只走一路串列埠，作者據此測算串列埠頻寬不足以傳整屏畫素，故未做影片播放。

5.2 Edgi-Talk 人形檢測報警系統：M55 加 NPU，檢測與報警本地閉環（10-20）

日期：2026-10-20 08:31（釋出時間）　來源：社群文章：基於 Edgi-Talk 的邊緣 AI 人形檢測報警系統

另一件大賽作品以英飛凌 PSoC E84 為平臺：M55 核跑 RT-Thread 承擔影片、排程與業務，M33 核管安全啟動，NPU 做定點推理。攝像頭經 USB 主機輸出 YUYV 格式 424×240，螢幕顯示 320×240，每 5 幀推理一次，輸入 320×320 的八位定點，候選框最多 8 個，置信度閾值 0.45、重疊抑制 0.45；報警按連續 3 次命中確認、連續 5 次未命中解除，避免單幀誤檢抖動。儲存寫入、網路上報與音訊播放各自排隊，不佔用影片執行緒，斷網不影響本地檢測與聲光報警；系統節拍 1000 Hz，異常時降級為核心預覽。

5.3 農田害蟲聲紋識別：AIoT 大賽獲獎作品登上電子工程專輯（10-20）

日期：2026-10-20 17:30（釋出時間）　來源：電子工程專輯：離線也能聽蟲辨害，基於 Edge Impulse 的端側聲紋識別實戰

行業媒體刊出一件 RT-Thread AIoT 大賽優秀獎作品：用 Edgi-Talk 板載麥克風採集田間蟲鳴，在 Edge Impulse 上做四分類（蟬、蟋蟀、噪聲、未知），特徵取梅爾濾波器組能量，視窗 1 秒、步長 200 毫秒、取樣 16 kHz，累計樣本約 2 分 15 秒，按 82 比 18 劃分訓練與測試，訓練 100 輪後匯出定點模型到端側推理。判定為害蟲即觸發外接噴藥，識別為噪聲或未知則不動作，全程離線、不依賴雲端。作者公開文件與程式碼。

六、總結與趨勢觀察

6.1 本期趨勢

  • 核心兩條底層路徑同時被修：排程器把同優先順序就緒順序拉回先來先服務，RISC-V 票號鎖把取號改為單指令原子加、釋放改為半字儲存。前者影響執行順序的可預期性，後者影響多核爭用下的活性，兩處都屬長期被預設行為掩蓋的問題。
  • 外設事件語義開始補齊：串列埠 V1 終於把「接收超時等於一幀結束」接進框架，受影響的恰是兩個靠空閒中斷切幀的國產板級支援，說明框架層的歷史缺口仍在被逐個發現。
  • 缺陷發現繼續由外部研究者驅動：本期 cromfs 越界單把影響面回溯到 v5.0.0，並指出 DFS 兩份實現同源，這類帶版本區間的報告比單點補丁更有價值，也提示 v1 與 v2 並行維護帶來的重複風險。
  • 廠商平臺從能啟動走向可交付：K1 預設開到 8 核、SPI 與 QSPI 狀態轉正並進入支援矩陣；D1s 補上模擬器執行路徑，評審把「可復現環境」提升為目錄規範與面向 AI 的說明文件，屬平臺化思路。
  • 工具鏈的本地化細節進入視野：中文 Windows 下表情符號導致構建命令中止，問題小但影響面大，反映跨平臺可用性測試仍是短板。
  • 官方渠道繼續靜默：新聞介面停更逾四個月，版本釋出仍停在九月，對外資訊主要靠 GitHub 與社群作品，這一格局已連續兩週未變。

6.2 侷限性與去重說明

  • 本期為 24 小時視窗（10-20 08:00 ~ 10-21 08:00），非週一，不做多日合併。
  • 主倉庫視窗內無合入，全部條目來自提案、缺陷單與社群側，故「核心與版本動態」中的三節均為在審提案而非已落地改動，各條已註明狀態。
  • 與上期去重：裝置樹深度預檢（#11901）與 tmpfs 截斷單（#11902）本身在上期已收錄，本期只寫視窗內新增的評審結論與裝置側復現；中斷應答（#11860）、IAR 隱式宣告（#11864）、按需編譯（#10096）與 attach 配置（#9941）均為更早條目，本期只記進展。
  • 兩件大賽作品的主控均非 RISC-V：納芯微 NS800RT7P65 是 Cortex-M7，聯網側的樂鑫 ESP32-C3 才是 RISC-V；Edgi-Talk 為 Cortex-M55 加 M33。收錄原因是 RT-Thread 應用案例與工具鏈實踐，不作 RISC-V 適配解讀。
  • 組織級全量推送未能透過介面核查（匿名限額耗盡），改用倉庫提交流與組織頁交叉驗證；Studio 的 SDK 索引經提交流確認停在 10-10。
  • 論壇文章介面只取前 20 條，超出部分未核；官方新聞列表頁為前端渲染，抓取只得空殼，新聞以介面為準。
