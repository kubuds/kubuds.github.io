一、核心與版本動態

1.1 RT-Thread v5.3.0 正式釋出：自 v5.2.2 以來首個版本，覆蓋核心 / 元件 / 裝置模型 / 架構 / 工具 / BSP 全板塊

日期：2026-09-10（18:05 北京時間釋出）　來源：RT-Thread v5.3.0 Release（ChangeLog.md）

本視窗最重要的事件：RT-Thread 主倉庫釋出 v5.3.0 正式版本，這是繼 2025-10-31 釋出 v5.2.2 之後的第一個正式版本，間隔約十個半月，也是近一年多來規模最大的一次整合放量。版本由專案維護者 Rbb666 釋出，變更日誌（ChangeLog.md）新增 263 行，按 Kernel、Components、DM、Libcpu、Tools、Action、BSP 七大板塊組織。

核心側（Kernel）以正確性與健壯性修復為主：修復 IPC 與 LWP 等待路徑上的超時喚醒歸屬競態、執行緒被反覆掛起時的延遲喚醒、禁止空閒執行緒被掛起、執行緒被他人刪除時釋放其持有的互斥量；執行緒 CPU 佔用率改為按取樣視窗增量統計；新增 8 位與 16 位原子操作支援；物件名長度斷言改為安全截斷；memheap 非法釋放與 rt_smem_setname 空名處理加固；並新增控制檯輸出使能開關、匯出中斷鉤子指標。

元件側（Components）出現兩處結構性新增：一是全新的時鐘框架 clock_time，把時鐘源與時鐘事件分離，引入高解析度定時器、啟動時間輔助介面與外設定時器適配層，並替換原有的 ktime / cputime / hwtimer 實現，同時遷移架構、BSP 與 POSIX 時間整合；二是 ADC V2，具備會話管理、序列讀取、電壓換算與 FinSH 命令，並支援 DMA 流、最新幀與 FIFO 緩衝、定時器與比較器觸發，與舊 ADC 驅動互斥。此外，串列埠 V2 新增 RX DMA 事件模式控制；DFS 新增 9PFS（用於與 QEMU 等虛擬機器共享檔案）並把 Elm FatFs 升級到 R0.16；網路側新增可選 AF_UNIX 流式與資料包套接字（含 socketpair、SCM_RIGHTS 描述符傳遞）；WLAN 新增 WPA3、企業級認證、WAPI、OWE、DPP 安全模式定義；USB 更新 CherryUSB 到 v1.6.1；Rust 元件新增 ARM / AArch64 / RISC-V 目標檢測與 SCons / Cargo 整合，併為執行緒、互斥量、訊號量、訊息佇列、記憶體、時間與檔案提供 Rust 封裝。

裝置模型（DM）是本次版本最大的結構性新增板塊：擴充套件裝置樹與 OFW 支援（並在 Cortex-M 目標啟用）、重構時鐘框架並擴充套件 regulator / 電源域 / reset / 電源管理，新增動態電壓頻率調節（DVFS）、ARM SCMI 韌體整合、硬體自旋鎖與硬體快取控制器、遠端處理器訊息（RPMSG）與可信執行環境（TEE）支援；VirtIO 升級到 1.2 並支援 packed queue、MMIO / PCI 傳輸，新增 9P、crypto、RNG、SCMI、SCSI 驅動；儲存側新增 UFS、DesignWare AHCI、通用 MTD 驅動與 NVMEM；網路側新增乙太網裝置模型（MACB / DWMAC）與 IEEE 1588 PTP 時鐘。

架構側（Libcpu）與 RISC-V 直接相關的是：為 QEMU virt64 以及達摩院玄鐵 C 系列 / R 系列處理器新增 SMP 支援，新增達摩院玄鐵 C908X 平臺支援，補齊 C908 的 Svpbmt 支援並修正 C906 / C908 的快取屬性與頁表屬性，修復 PLIC 中斷處理順序；Cortex-R52 側則收進了本報告昨日記錄的瑞薩 RZ/N2L 中斷重複分發修復。

日期：2026-09-10（16:23 北京時間合入）　來源：RT-Thread/rt-thread commits（PR #11792）

昨日報告中列為「新開並持續更新」的瑞薩 SCI SPI 修復，本視窗內正式合入：改動集中在 bsp/renesas/libraries/HAL_Drivers/drivers/drv_sci.c 單檔案，兩個提交合計 +254/-193（功能提交 +90/-41，隨後一筆 clang-format 格式化 +164/-152），PR 09-09 17:25 建立、09-10 16:23 合入，歷時約 23 小時，流轉速度明顯快於同屬瑞薩方向、評審跨月的 klibc 與 clock_timer 兩隻長期 PR。

修復內容針對 RZ/N2L EtherKit 的 SCI SPI 迴環排查發現的一組缺陷：RZ 分頻介面把 false 當作分頻結果指標傳入且未使用 FSP 配置中的實際時鐘源；執行時配置未可靠傳遞給 FSP、重複配置未正確關閉舊例項；配置過程把 RT-Thread 的位寬單位從 bit 誤改為 byte；收發等待超時或出錯後仍返回傳輸長度，導致呼叫方誤判成功。方案為每條 SCI 匯流排儲存持久的可寫 FSP 配置副本、修正各分支分頻呼叫、在重新配置前顯式關閉已開啟例項、保持位寬單位為 bit，並在超時或錯誤時關閉傳輸、清理事件與匯流排歸屬以便重試。該修復已隨 v5.3.0 變更日誌收錄（Renesas 板塊）。

三、生態與廠商適配

3.1 軟體包索引三筆更新：新增 Lely CANopen 包、CanopenNode 模組化 Kconfig 重構、引數儲存自定義 backend（PR #2038）

日期：2026-09-11（11:09 北京時間合入）　來源：RT-Thread/packages commits（PR #2038）

視窗末尾（本報告採集前約 9 分鐘）軟體包索引倉庫合入一筆 19 個檔案 +2621/-1580 的集中更新（wdfk-prog 提交），同步三類 CANopen 與引數儲存相關包的配置：

  • 新增 canopen-lely 包索引：把 Lely CANopen 的 RT-Thread 移植版加入 package index，提供 single-owner EV/IO2 執行時、RT-Thread CAN 整合、經典 CAN 與可選 CAN FD、自動執行時初始化、owner 執行緒配置、日誌、啟停配置以及可選的 CANopen 主站（Master）服務。其執行時以 LELY_NO_THREADS=1 方式工作，Lely 的 EV / IO2 / CANopen 物件由專用 RT-Thread owner 執行緒序列訪問，非同步 CAN、定時器與狀態事件轉交該 owner 處理。
  • CanopenNode Kconfig 模組化重構：把原先集中在 misc/CanopenNode/Kconfig 的配置按當前移植結構拆分，覆蓋 core 協議配置、RT-Thread 執行時配置、儲存配置、物件字典與 demo/test 配置、CiA 401 裝置子協議、CiA 402 裝置/控制器子協議以及各 profile 專屬配置，並新增按 Kconfig 選擇儲存實現的 SCons 原始檔選擇。
  • autogen_parameter_manager 增加應用自定義儲存 backend：新增 AUTOGEN_PM_BACKEND_APP_DEFINED 選項，選中時不啟用包自帶的 scalar backend，由應用提供強符號 par_store_backend_get_api()（必要時還可覆蓋 par_store_backend_bind()）。原有預設 backend 保持不變，不影響既有工程。

加上 09-01 合入的 CANopenNode 索引，CANopen 協議棧在 RT-Thread 軟體包層面已形成「Lely（面向主站與 EV/IO2 執行時）+ CanopenNode（面向從站）」的雙棧選擇，是工業現場匯流排與車載方向軟體包化的重要補強。

3.2 廠商 BSP 全景（v5.3.0 版本級）：瑞薩、兆易創新、NXP、意法半導體、瑞芯微、樹莓派、達摩院玄鐵、芯來等

日期：2026-09-10（隨 v5.3.0 釋出）　來源：RT-Thread v5.3.0 Release 變更日誌 BSP 板塊

v5.3.0 的 BSP 板塊覆蓋面較廣，可作為各廠商在 RT-Thread 上適配成熟度的版本級快照：

  • 瑞薩（Renesas）：新增 EK-RA6W1 與 RA8P1 Titan BSP，補齊 RA8P1 Titan 的 Cortex-M85 / M33 工程與 GPIO / 外部中斷裝置模型驅動，擴充套件 RA6W1 外設並改進 MDK 工程，修復 RA8D1 Vision Board 的 Keil 下載配置；驅動側收錄 SCI SPI 位速率與配置生命週期修復（PR #11792）、R7FA8M85 的 SDHI 卡檢測、可配置 CAN FD 仲裁與資料速率、以及從 GPT 暫存器讀取 PWM 週期與脈寬。瑞薩仍是本週期最活躍的廠商線。
  • 兆易創新（GigaDevice）：新增 GD32405RG 與 GD32VW553H-EVAL BSP，補齊 GD32VW553 的 UART、Wi-Fi、硬體 I2C、SPI、ADC、PWM、定時器與看門狗驅動，擴充套件 GD32F5 / H7 串列埠與 GPIO 支援。

4.1 睿賽德申報 2026 第八屆金輯獎最佳技術實踐應用獎，申報技術為程翧整車基礎軟體作業系統（09-11）

日期：2026-09-11（09:41 北京時間）　來源：蓋世汽車（Google News 聚合條目）（2026 第八屆金輯獎說明）

上海睿賽德以「程翧整車基礎軟體作業系統」申報 2026 年第八屆金輯獎「最佳技術實踐應用獎」，申報領域為汽車軟體與人工智慧，條目由蓋世汽車釋出。金輯獎由蓋世汽車發起，聚焦「中國汽車新供應鏈百強」，2026 年第八屆以「中國方案」向全球為年度主題，覆蓋 ADAS/AD、智慧座艙、智慧底盤、車規級晶片、汽車軟體與人工智慧、動力總成電氣化及充換電與熱管理、車身及內外飾、新材料與先進製造、具身智慧與跨界技術等賽道，評選維度包括企業申報、產業資料、專家評審與市場驗證。睿賽德此前已於 2025 年獲得第七屆金輯獎「最佳技術實踐應用獎」，本次為同一獎項的再次申報。

深挖：程翧是睿賽德面向汽車電子的整車基礎軟體產品線，2022 年以「程翧車載融合軟體平臺」釋出並標誌其進軍車載作業系統市場，產品構成包括安全型實時系統 RT-Thread Secure Auto、微核心作業系統 RT-Thread Smart Auto、虛擬化系統 vmRT-Thread Hypervisor 與 vmBUS 統一訊息匯流排，覆蓋車身、底盤、動力、智駕與座艙等系統控制場景；其中多核 MCU 虛擬化為較新的技術點。睿賽德在功能安全上已透過 ISO 26262 ASIL D、IEC 61508 SIL 3、EN 50128 SIL 4 等認證，合作晶片企業包括英飛凌、NXP、德州儀器、意法半導體、黑芝麻智慧、芯旺微等。本條屬於品牌與產業評選類動態，未涉及視窗內的新產品釋出或量產定點資訊。

主線判斷

  • 版本節奏：主線在 v5.2.2 之後約十個半月沒有正式發版，本次一次性釋放 v5.3.0，且釋出當日即推進 v5.3.1 並回移 beta 修復，說明「釋出正式版 → 主線續版本號 → 修復回移」的閉環已經成型，後續小版本節奏可能加快。
  • 裝置模型（DM）是 v5.3.0 最具結構性的新增板塊：裝置樹與 OFW、時鐘與電源框架重構、DVFS、ARM SCMI、RPMSG 與 TEE、VirtIO 1.2、UFS/AHCI、IEEE 1588 PTP 集中落地，指向 RT-Thread 在 Cortex-A 與 RISC-V 高效能平臺方向的定位強化，而非僅服務 MCU 場景。
  • RISC-V 側：達摩院玄鐵 C908X 平臺與 C 系列 / R 系列 SMP 支援進入正式版本，與視窗內仍在評審的 c908 rt-smart / QEMU MMU 相關 PR（#11775）構成同一條演進線。
  • CANopen 生態成形：Lely（主站與 EV/IO2 執行時）與 CanopenNode（從站）雙棧在軟體包層落地，疊加主倉庫 CAN 驅動生命週期重構在評審中，工業與車載現場匯流排是近期的持續性投入方向。
  • 評審消化節奏依舊分化：釋出相關與文件類改動數小時內完成（#11795 約 36 分鐘、#11792 約 23 小時），而核心、驅動與記憶體管理類長期 PR（#11228、#11313、#11689、#11772）仍跨周乃至跨月停留。
