一、核心與版本動態

1.1 Next RISC-V 架構重構提案獲創始人合併推動，提交者連夜變基重新整理（09-29 ~ 09-30）

日期：2026-09-29 21:09（創始人評論）~ 09-30 00:01（最新提交）　來源：PR #10320

擱置數月的主倉庫 RISC-V 架構重構提案「Next RISC-V」（#10320，171 個檔案、+15018/-3490）在視窗內迎來明確推進訊號：創始人 Bernard Xiong 於 09-29 21:09 評論「這份PR，近期能合併掉吧，同時在一些riscv的soc上，也嘗試把裝置樹開啟試試」，並點名維護者與提交者跟進。隨後提交者 GuEe-GUI 讓提案在當晚至次日凌晨連續觸發三輪重新整理記錄（21:22、23:54、00:01，格式化與記憶體對比流水線隨之重跑），最新 head 提交「Refactor the RISC-V architecture port」已於 09-30 00:01 重新變基至當前主線最新提交 dc8aaa73f 之上。方案要點：ISA 管理介面、RV32E/32I/64I 融合、按 CBOM 的快取處理、Sv32~Sv64 MMU 與 SVPBMT、M/S 模式 CSR 操作合併、SMP、AIA（APLIC/IMSIC）、CLIC、ACLINT/CLINT、PLIC、裝置樹（DM）支援、T-HEAD 廠商程式碼合併、qemu-virt64-riscv64 裝置樹移植與從非 0 號核啟動等；計劃清單顯示 S 模式 RT-Thread、RT-Smart 與裝置樹路徑已完成驗證，其餘組合（含 M 模式、無 MMU 等）仍在推進。該提案自 2026-05 提交以來累計評審評論 74 條。

1.2 核心 calloc 溢位修復提案獲評審透過（09-29 ~ 09-30）

日期：2026-09-29 22:34（提交）~ 09-30 08:30（獲 LGTM）　來源：PR #11848

貢獻者 luchenxu73 提交核心修復 #11848（單筆提交、3 個檔案、+57/-3）：rt_calloc 分配時未檢查 count×size 是否溢位，超限時結果迴繞、存在分配與清零不一致的越界風險；修復方案為預計算分配尺寸並在超限時拒絕分配，改動覆蓋 include/rtdef.h、src/kservice.c 與記憶體單元測試 src/utest/mem_tc.c（新增用例），驗證平臺為 qemu-vexpress-a9。該提案在 09-30 上午 08:30 獲得社群評審「LGTM」透過，為視窗內推進最快的新提案。

1.3 三條驅動與 BSP 修復提案集中提交：ofw 雜湊越界、ESP32-C6 SPI、ESP32-C3 連結指令碼（09-29）

日期：2026-09-29 20:11 ~ 21:53　來源：PR #11845、PR #11846、PR #11847

09-29 晚間約一個半小時內，社群集中提交三條修復提案，均附測試證據、尚待評審。其一（#11845）裝置樹（ofw）phandle 雜湊表越界修復：分配表項數用範圍之差、查詢下標卻按 phandle 與起始值之差計算，導致範圍上限被訪問時越界，擴容時清零位置亦未減起始值；修復為表項數加一併在擴容時從舊錶末尾起清零新增區域，作者以 GCC 加 AddressSanitizer/UBSan 完成 6 個用例的函式級驗證（起始 phandle 取 1、5、128，另測上限 128 擴充套件至 256）。其二（#11846）樂鑫 ESP32-C6 按需編譯 SPI：選中 BSP_USING_SPI 後接入 IDF SPI master，修正共享 ESP 驅動未返回傳輸位元組數、片選引腳取值等問題，並在配置為空時返回 -RT_EINVAL（6 個檔案、+466/-19）。其三（#11847）ESP32-C3 連結指令碼在 Windows 路徑下的萬用字元修正：sections.ld 中以「/」書寫的萬用字元未能匹配 Windows 目標路徑中的 riscv 目錄物件檔案、導致向量跳轉重定位越限，改用「?」同時相容兩種分隔符；與 #11816 為同一處修改、本次基於最新主線重做，Windows 加 GCC 11.2.0 下 scons 構建透過。

4.1 馬來西亞理科大學畢設專案更新：RA8P1 + RT-Thread 端側聲學事件檢測韌體驗證（09-30）

日期：2026-09-30 05:49 ~ 05:50（提交時間）　來源：KhaiFaw/ai-acoustic-event-detection

topic:rt-thread 生態下的第三方專案「Acoustic event detection at the edge」（馬來西亞理科大學機電工程畢業設計）在視窗內連續提交兩筆更新：核對聲學韌體構建與模型契約、修正嵌入式模型與韌體之間的輸入縮放不一致，並補充軟體驗證記錄（16 項主機測試與一次全 BSP 本地構建透過；修正版韌體尚未實機燒錄評估）。專案基於瑞薩 RA8P1 Titan 板：RT-Thread 提供作業系統框架，瑞薩 FSP 提供裝置支援，CMSIS-DSP 實現 FFT，TensorFlow Lite Micro 執行 INT8 CNN；以 MAX9814 麥克風採集 16000 點音訊，經 MFCC 特徵提取後在端側識別嬰兒啼哭、玻璃破碎、警報/警笛、敲門、門鈴與背景六類聲音。
