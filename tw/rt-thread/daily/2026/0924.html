一、核心與版本動態

1.1 clang-format 自動提交不再跳過 CI：格式化流水線併入常態驗證（09-23）

日期：2026-09-23 16:30 ~ 16:34（北京時間，建立與合入時間）　來源：PR #11830、合入提交

主線在視窗內合入一筆持續整合流程調整：clang-format 自動格式化提交的提交資訊中去除「跳過 CI」標記，此後格式化提交與普通提交一樣觸發持續整合流水線。該標記原用於避免「自動格式化提交再觸發一輪 CI」的迴圈，代價是格式化結果不經構建驗證直接入庫；調整後格式化動作納入常態驗證鏈路。對應工作流檔案為此提案唯一變更檔案，提案由社群貢獻者提交，建立後約四分鐘即完成合入。

1.2 評審佇列視窗內新增兩條提案：netdev 構建修復與 GD32H77D 外設系列（09-23）

日期：2026-09-23 11:05 / 15:41（北京時間，提案時間）　來源：PR #11828、PR #11829

評審佇列在視窗內新開兩條提案。其一為網路元件的小範圍修復（#11828，netdev 的 AF_NETLINK 構建錯誤）：補上結構體前向宣告，並把路由通知回撥中的節點索引引用從臨時變數改為直接取列表節點，修復開啟相關配置組合後的編譯報錯，涉及兩個檔案。其二為大體量的廠商板級提案（#11829）——GD32H77D GinoPi 板卡外設系列，共 19 筆提交、142 個檔案，詳見第三章 3.1。

二、官方與社群活動

2.1 RSOC26 夏令營教程體系化推進：視窗內更新《第一章 開發環境、BSP 配置與裝置模型》（09-23）

日期：2026-09-23 15:22（北京時間，更新時間）　來源：論壇文章 5a5a1f34db847d92

社群論壇在視窗內更新一篇 RSOC26 系教程《第一章 開發環境、BSP 配置與 RT-Thread 裝置模型》，給出從零到裝置模型的完整主線：安裝 RT-Thread Studio 並經 SDK 管理器部署核心原始碼與晶片支援包；以「基於晶片」方式新建工程（星火一號平臺 STM32F407ZG，核心 4.1.1、USART1 控制檯、ST-LINK 與 SWD 除錯）；解析 BSP 工程目錄結構與 board.c / board.h 職責（時鐘樹 168 MHz、系統滴答、堆邊界）；講解 I/O 裝置模型三層架構與 GET_PIN 引腳編號機制；並以 GPIO 心跳燈與串列埠列印完成編譯、燒錄與 FinSH（MSH）命令列驗證。該篇與此前散點發布的星火一號實踐篇目形成章節化編排，屬夏令營教程的體系化開篇。

三、生態與廠商適配

3.1 Gino Pi 主線 BSP 提案進入評審：GD32H77D 外設系列 19 筆提交、142 個檔案（09-23）

日期：2026-09-23 15:41（北京時間，提案時間）　來源：PR #11829

兆易創新 GD32H77D 板卡 Gino Pi 的板級支援以系列提案形式提交主線評審：單分支 19 筆提交、142 個檔案、淨增約 2.6 萬行。內容覆蓋三層：板級骨架（工程、連結指令碼、rtconfig）；外設全家桶——乙太網、USB 主機與裝置、SDRAM、硬體 I2C、SPI3、PWM、SDIO 與檔案系統、RTC 與鬧鐘、看門狗、CAN 與 CAN FD、OSPI Flash、MIPI LCD、GT911 觸控、OV7670 攝像頭與 LVGL；以及 GinoPi 外設演示工程與全 BSP 編譯檢查掛載。另含板載 GD32VW553 無線模組的 Wi-Fi 與 MQTT 支援，提交說明註明該模組的 UART4 AT 通訊與 MAC 查詢已驗證、Wi-Fi 關聯尚待完成，模組與示例預設關閉。該板卡此前已完成 Studio SDK 索引、發售與除錯鏈路補完（見 3.2），本期是「從廠商 SDK 走向主線」的實質一步，目前處於評審中。

3.2 GD32 器件支援包與 Wi-Fi 元件三倉同步：H77x_78x 器件/外設庫與 GD32VW553 聯網支援（09-23）

日期：2026-09-23 16:01 ~ 16:10（北京時間，推送時間）　來源：gd32-arm-cmsis 提交、gd32-arm-series 提交、at_device 提交

與主線提案同日下午，RT-Thread 器件支援包組織的三個倉庫先後完成鋪墊性更新：CMSIS 器件支援包（gd32-arm-cmsis）與 GD32 外設庫支援包（gd32-arm-series）分別新增 GD32H77x_78x 支援，為 H77 系列晶片提供 CMSIS 器件層與新外設庫；AT 元件倉庫（at_device）新增 GD32VW553 Wi-Fi 裝置與 TCP socket 支援，使這款無線模組可經 AT 通道接入網路元件。三筆提交與主線 BSP 提案在同一時間窗內推送，構成 Gino Pi 軟體棧的一次同步就位。

3.3 軟體包索引三連合並：CanopenNode v1.2.0 配置重構、虛擬感測器新包、AI Agent 增加 MQTT 工具（09-24）

日期：2026-09-24 09:23 ~ 09:25（北京時間，合入時間）　來源：CanopenNode v1.2.0 合併、虛擬感測器包合併、AI Agent 配置合併

軟體包索引倉庫在視窗內集中合入三筆提案（均為 9 月 11 日 ~ 14 日提交、視窗內完成評審）：其一為 CanopenNode v1.2.0，9 個 Kconfig 檔案重構，把原先的 CiA 401 裝置 worker 開關整合為通用裝置剖面體系——新增純 C、無堆分配、與實時系統解耦的邏輯裝置登錄檔，以及剖面控制器傳輸契約與 RT-Thread 主站傳輸選項，工業匯流排元件的配置結構向模組化前進。其二為新軟體包「虛擬感測器」：提供模擬感測器資料生成，可選經 MQTT 上報（依賴 paho MQTT 與 cJSON 元件），面向無硬體條件的聯調與教學場景，包源指向作者維護的獨立倉庫。其三為 AI Agent 軟體包配置更新：新增 MQTT 工具及其 broker 地址等配置項，同時引入對 rt_vsnprintf 能力的自動檢測機制——以「核心是否已定義該符號」為判據（而非套用版本號），自動決定是否啟用完整版格式化軟體包，避免 4.1.x 核心上重複定義導致連結失敗，並保證浮點格式等完整能力可用。

3.4 瑞薩 RA8P1 Titan Mini OpenMV 新增 RGB LCD 顯示與視覺示例（09-24）

日期：2026-09-24 09:42（北京時間，提交時間）　來源：提交 98076cf8、Titan Mini OpenMV 倉庫

Studio BSP 組織下瑞薩 RA8P1 Titan Mini 倉庫在視窗內推送一筆功能提交（17 個檔案、約 1200 行新增）：為 OpenMV 工程接通板載 RGB 介面的 800×480 螢幕（RGB565），補齊 LCD 驅動與 MicroPython 的 lcd 模組，並同步調整顯示適配、NPU 與執行時相關檔案及 machine_pin / machine_pwm 等機器模組；示例側新增 LCD 基礎顯示（色條、文字、圖形、2 倍縮放與背光調節）、相機預覽與紅色色塊追蹤兩個視覺示例，背光由 LCD 統一管理（佔用 GPT7）。該工程此前完成 OpenMV 釋出鏈路與效能最佳化（09-18、09-22 已收錄），本期從效能收口轉向顯示與示例擴充套件，端側視覺演示鏈路進一步完整。
