一、核心與版本動態

1.1 玄鐵 C908 平臺 RISC-V 支援三連合入：rt-smart、MMU 與 SMP（09-15）

日期：2026-09-15 22:57（北京時間，合入時間）　來源：PR #11775

玄鐵 C908 平臺的三個提交在視窗內一併合入主線，合計 31 個檔案、新增約 2575 行、刪除 565 行。三項內容分別是：libcpu 的 MMU 框架補齊 SV39 / SV48 / SV57 地址模式支援並附帶測試用例；參照 K230 與 Virt / C906 的既有實現，為 C908 增加 rt-smart 支援；為 C908 增加 SMP 支援，並針對副核拉起時機、TLB 重新整理與 IPI 初始化做最佳化。驗證平臺為 BSP 目錄下的 xiaohui C908（QEMU 模擬）。rt-smart 與 SMP 同時到位，意味著該核從能跑進入可做多核使用者態驗證的階段。

1.2 env 工具鏈連發 v2.0.0 與 v2.0.2，命令列化重構落定（09-16）

日期：2026-09-16 09:48 / 09:51（北京時間，釋出時間）　來源：env v2.0.0、env v2.0.2

RT-Thread env 工具鏈在視窗內連發兩個版本，版本號從 1.5.x 直接躍遷至 2.0.0，兩分鐘後再補發 2.0.2 修正。這是自 2024 年 4 月 v1.5.2 以來的首次釋出。主要變化包括：以 kconfiglib 重構配置系統並統一命令列入口，Windows 側改為註冊命令而不再依賴指令碼；新增 sdk 命令與 e-build 嵌入式構建系統；引入 env.json 作為版本號、倉庫地址與映象資訊的單一來源，程式碼中的硬編碼地址改由訪問層讀取；預設安裝不再捆綁 arm-none-eabi、gdb 與 qemu 工具鏈；安裝指令碼按網路位置自動選擇映象源。分發名調整為 rt-env。

1.3 SDIO 驅動登出與節點記憶體洩漏缺陷報告進入處理佇列（09-15）

日期：2026-09-15 17:53（北京時間，最近更新）　來源：Issue #11801

視窗內一條裝置驅動缺陷報告的討論更新。報告指出 SDIO 驅動框架存在兩處隱患：載入多個 SDIO 驅動後解除安裝其中一個時，連結串列遍歷未在匹配成功後退出，區域性指標可能被下一輪迴圈覆蓋為空；已分配節點指標的釋放被繫結在已匹配到卡的分支內，未匹配到卡時不會釋放，存在記憶體洩漏風險。報告另建議用更安全的連結串列遍歷宏替代現有寫法。該議題標記為缺陷與驅動元件，狀態為處理中，視窗內有三條討論。

二、官方與社群活動

2.1 第九屆全國大學生嵌入式晶片與系統設計競賽：深技大斬獲特等獎 RT-Thread杯（09-15）

日期：2026-09-15 14:34（北京時間，釋出時間）　來源：南方都市報報道

第九屆全國大學生嵌入式晶片與系統設計競賽全國總決賽結果公佈，深圳技術大學團隊斬獲特等獎 RT-Thread杯及全國一等獎 3 項、二等獎 4 項、三等獎 2 項。賽事由中國電子教育學會主辦，15 家晶片企業聯合命題，共 908 所院校、4.45 萬名學生、1.7 萬支隊伍參賽，1227 支隊伍晉級全國總決賽。獲特等獎的作品為《基於 RT-Thread 的手勢互動桌面氛圍燈與植物養護一體化終端》，另有《基於 OpenHarmony 與 RISC-V 的智慧會議室系統》獲全國一等獎。企業冠名獎項的出現，說明 RT-Thread 在高校賽道的投入已從提供開發板延伸到命題與評審環節。

2.2 社群論壇新增技術文章《MCU C 執行時庫啟動流程》（09-15）

日期：2026-09-15 17:04（北京時間，更新時間）　來源：社群論壇文章介面

社群論壇新增一篇技術文章，從 ARMv7-M 的復位行為講起，逐層拆解向量表與 VTOR 的關係、.data 段從 Flash 到 RAM 的複製與 .bss 段清零，並討論如何用嵌入式 C 執行時庫標準化接管初始化流程。文章附有配套影片，屬面向初學者的體系性講解。論壇文章介面此前一期返回異常，本期恢復正常，後續重新納入日常核查。

三、生態與廠商適配

3.1 STM32N657 Nucleo BSP 合入主線，八十三檔案規模（09-16）

日期：2026-09-16 09:05（北京時間，合入時間）　來源：PR #11799

上期處於評審佇列的 STM32N657 Nucleo BSP 提案於視窗內合入主線，規模 83 個檔案、新增約 17884 行，評審人為 supperthomas 與 kurisaW。該提案 09-11 送審，09-14 曾單日四次強制推送修復持續整合問題，隨後透過評審併合入。與之配套的 STM32N657xx FSBL 軟體包索引已於 09-14 先行合入，STM32N6 系列在 BSP 與軟體包兩側至此齊備。STM32N6 面向帶神經處理單元的圖形與視覺應用，這是該系列首次進入主線支援列表。

3.2 國民技術 N32H 三系列驅動擴充套件合入主線（09-16）

日期：2026-09-16 09:06（北京時間，合入時間）　來源：PR #11800

上期評審佇列中的 N32H 三系列驅動擴充套件同樣在視窗內合入主線，70 個檔案、新增約 8096 行、刪除 2778 行，覆蓋 N32H47x 與 N32H48x、N32H49x、N32H7xx 三個系列及三塊評估板。共用驅動層新增 ADC、DAC、I2C、SPI 配置標頭檔案，並擴充套件 ADC、DAC、乙太網、GPIO、硬體 I2C、NAND、QSPI、SDRAM、SPI、串列埠與看門狗等驅動分支；兩塊評估板另增 FEMC 時序表、乙太網物理層復位與 USB 配置。三款新板卡同步加入持續整合編譯矩陣。國產 MCU 原廠的驅動補齊仍是本季度主線合入的主要來源。

3.3 STM32 乙太網驅動完成新版 HAL 介面遷移（09-15）

日期：2026-09-15 22:59（北京時間，合入時間）　來源：PR #11781

STM32 乙太網驅動完成向新版硬體抽象層介面的遷移，8 個檔案、新增 755 行、刪除 968 行，已在 F4 與 H7 兩個平臺上驗證。改動把分散的收發邏輯收斂到統一介面，為後續各 BSP 複用同一份乙太網驅動打底。提交者為長期維護 STM32 移植層的開發者，屬主線維護性改動。

3.4 驅動側修復動態：GD32 串列埠引腳、Infineon PWM 宏與 STM32 連結問題（09-15 ~ 09-16）

日期：2026-09-15 21:50 ~ 2026-09-16 10:19（北京時間，提交與合入時間）　來源：PR #11802、PR #11803、PR #11804

視窗內有三條驅動修復類改動。已合入的一條（#11803）修正 STM32 直接儲存器訪問驅動中一個型別名函式的連結問題，改動僅一行，用於消除未啟用日誌元件時的編譯告警。兩條進入評審的改動分別是：GD32 各系列的串列埠收發引腳初始化修復，把傳送腳配置為複用推輓、接收腳配置為上拉輸入，並移除把兩個引腳都配成通用推輓輸出的錯誤別名，影響 GD32E50x、F10x、F20x、F30x 四個系列；以及 Infineon PSoC6 評估板的 PWM 宏錯配修復，條件編譯宏名與板級配置不一致，導致滑塊示例中的 PWM 初始化程式碼被整段編譯掉、示例始終找不到 PWM 裝置，共 14 個檔案。三條均為生態開發者提交的常態化修復。
