一、核心與版本動態

1.1 主倉庫視窗內合入 4 個 PR：MPU 許可權修復、PWM utest、瑞薩 CAN FD、net/sal 資源釋放

日期：2026-09-01（09:05-09:39 北京時間合併）　來源：PR #11760、PR #11751、PR #11754、PR #11769

昨日 RT-Smart POSIX 相容批次（PR #11732/#11733，13 筆提交）之後，主倉庫今日上午再合入 4 個 PR（另含 1 筆 clang-format style 提交），工作日合入節奏恢復：

  • PR #11760（09:05）[net][sal]：修復套接字建立失敗時 DFS v2 vnode 未釋放的問題，屬資源洩漏修復；
  • PR #11751（09:16）[bsp/renesas][drivers]：瑞薩 BSP 驅動支援可配置 CAN FD 操作，外設能力繼續演進；
  • PR #11754（09:33）[utest][pwm]：新增可配置 PWM matrix 測試，並修復矩陣測試清理與超時問題；
  • PR #11769（09:39）fix[arm][cortex-m4]：澄清 MPU 許可權表示式，cortex-M4 核心 MPU 許可權配置表述修正。

與前一日面向 RT-Smart POSIX 相容層的大批次合入不同，本批集中於核心細節健壯性：ARM cortex-M4 MPU 許可權、網路套接字失敗路徑的資源釋放、驅動可配置化與測試覆蓋，未見大特性合入。

3.1 packages：optparse 補充 v1.0.0 / v1.0.1 版本條目，新舊介面並存可選

日期：2026-08-31（16:55 合併）　來源：RT-Thread/packages PR #2032

昨日 packages 曾為 optparse 軟體包恢復 v1.0.0 版本條目以回滾破壞性介面變更（v1.0.0 為 2 引數介面）。今日 PR #2032 進一步補充 v1.0.1 版本條目：兩個 tag 均指向 3 引數介面提交（07a365d），與 v1.0.0 的 2 引數介面區分，使用者可按介面需求在軟體包索引中選擇對應版本。索引層對介面相容的管理進入”雙版本並存”階段。

3.2 生態參考：canopennode-rtt 社群 CANopenNode 整合包連續開發

日期：2026-08-31 ~ 09-01　來源：github.com/wdfk-prog/canopennode-rtt（附文件站 wdfk-prog.space/canopennode-rtt/）

社群倉庫（2026-06-30 建立，C 語言）面向 RT-Thread 整合國際知名開源 CANopen 協議棧 CANopenNode，近期提交活躍：新增事件驅動主線排程（09-01 08:54）、高解析度時間支援與 kconfig 執行配置選單整理、預設物件字典與 demo 模組解耦（08-31）、RX 規則編譯為粗粒度 HDR 過濾器（08-30）、SRDO 生成 J09/B09S 物件字典及 MCU 診斷 fixture（08-29）。該包目前獨立於官方 packages 索引（未見提交 PR），關注後續是否進入官方軟體包體系；工業/車載 CANopen 通訊場景值得留意。

3.3 生態參考：兆易創新 gd32_rt-thread 合入 F503 外設驅動與 F207i BSP 升級

日期：2026-08-31（19:17 / 19:31 合併）　來源：GD32-MCU-IOT/gd32_rt-thread PR #58、PR #63

GigaDevice 官方下游倉庫（gd32_rt-thread）視窗內由原廠工程師合入兩筆 BSP 適配：PR #58 為 gd32f503v-eval 增補 USART / I2C / SPI / DMA 驅動；PR #63 升級 gd32207i-eval BSP 並適配 F20x 系列驅動。晶片原廠主導的 BSP 覆蓋繼續擴充套件（近兩週已連續合入 305R/407V/470Z/470i/L23x/F527 等多款型號相關適配）。
