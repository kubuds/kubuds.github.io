一、核心專案進展

1.1 主倉：ROCm 雙筆——DeepSeek mHC 前/後核心與 safe-gated KDA 解碼示例（10-13 ~ 10-14）

日期：2026-10-13、2026-10-14　來源：DeepSeek mHC（#3156）／ KDA 解碼示例（#3249）

  • DeepSeek mHC 前/後核心（#3156，2 檔案、+83/-6，合入於 10-14 凌晨）：mHC 前處理在 CUDA 上按 96 執行緒塊內的 32 執行緒邊界分工並採用 TF32 GEMM 輸入；在 CDNA 上這會切開原生 64 lane 波前，且 TF32 不是 MFMA 的輸入型別。HIP 路徑改為在完整的目標尺寸波前上執行分割角色，並把 FP32 混合權重在共享記憶體中轉 BF16 供 MFMA 計算；CUDA 側保持原 96 執行緒 / TF32 佈局不變，另補 gfx942 的前/後核心正確性覆蓋（32 token 前處理、8 token 後處理等用例）。
  • safe-gated KDA 解碼（#3249，+360/-0）：新增打包解碼核心——消費卷積後打包 QKV 與原始門控輸入（a、b、A_log、dt_bias）、FP32 狀態池與按請求狀態索引；執行 Q/K L2 歸一化與 delta-rule 遞迴更新，原位改寫指定狀態槽並輸出 [batch, 1, value_heads, value_dim]；負狀態索引輸出零且不改狀態池。實現按維度引數化、不含模型名/架構分發，文件給出 GLM-5.3-Flash TP8 的專用化配置。

1.2 主倉：昇騰編譯面兩筆——SimdVF 多緩衝 T.fill（#3455）與 bisheng 臨時檔案清理（#3461）（10-13）

日期：2026-10-13　來源：SimdVF T.fill（#3455）／ bisheng 清理（#3461）

  • #3455（+247/-31）：昇騰 SimdVF 的 LowerFill 原先只支援整緩衝填充（各維須從 0 開始且範圍等於緩衝形狀）；多緩衝流水線中 MaterializeMultiBuffer 給緩衝加了版本維（如 [64] 邏輯緩衝變 [2, 64] 物理緩衝），迴圈內 T.fill 只需填當前版本槽位 [v:v+1, 0:64]，而被完整緩衝檢查拒絕。本筆把處理物件改為實際填充區域，按區域起點與範圍計算每個 VReg 資料塊的寫入索引，檢查常量範圍、連續性與 VReg 對齊，支援緊湊佈局與顯式 stride；補 3 例 NPU 測試（1D / 2D / 兩階段流水線多緩衝）。
  • #3461（+2/-1）：bisheng wrapper 建臨時目錄時未傳 keep_for_debug，導致編譯的 AscendC 源總是被刪——而 nvcc、hipcc、PTO wrapper 均傳 keep_for_debug=not env.should_cleanup_temp_files()。本筆對齊，使 TILELANG_CLEANUP_TEMP_FILES=0 在昇騰後端同樣生效。

日期：2026-10-13　來源：GLA 反向（#2546）／ DeltaNet 反向（#2547）／ KDA 預填（#2548）／ 緊湊逐行 GEMM（#2549）／ GQA 修復（#2550）

  • DeltaNet 反向（#2547，+166/-113）：chunk 64、K=V=128 的三段程式落在 90112 / 98304 / 98816 位元組內；顯式狀態緩衝檢視把評審人報告的 147968 位元組 w/u 分配降到 98816；縮短運算元壽命、鍵與逆矩陣在最後消費者後複用狀態儲存。
