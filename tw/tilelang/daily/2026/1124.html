今日重點：主倉 JIT 加入程序級並行編譯，繞開 GIL 對執行緒池的限制

#3903 於 11-23 11:57 進主幹，改 6 個檔案，增 552 行、刪 100 行。

tilelang.par_compile() 與 kernel.par_compile() 新增可選引數 executor="process"。提案寫明的動機是：執行緒式並行在 Python 側偏重的編譯負載上受 GIL 限制。

程序模式下，父程序先規範化 target、執行後端、pass 配置與快取根目錄。記憶體或磁碟快取已命中的配置不再起 worker。未命中的按 key 去重後再分發。

每個 worker 用 KernelCache.compile_to_disk() 把結果寫進磁碟快取，返回已釋出的 cache_path。worker 的異常型別與 traceback 跨 IPC 保留。

父程序用 KernelCache.load_published_entry() 直接載入，不回退序列編譯。出錯時立即取消已排隊的 future。

不支援磁碟快取的後端在起 worker 之前被拒絕，例如 TorchKernelCache（supports_disk_cache = False）。這樣不會改動全域性快取狀態。

執行緒模式仍是預設值。程序模式要求開啟快取，並要求指令碼帶 if __name__ == "__main__": 保護入口。

提案記錄在昇騰上以 64 程序驗證，覆蓋 128 組 SwiGLU 與 MoE 配置。迴歸測試落在 testing/python/jit/test_tilelang_jit_parcompile.py。用例含自定義 TILELANG_CACHE_DIR 下的程序編譯與去重。

來源： https://github.com/tile-ai/tilelang/pull/3903

一、核心專案進展

1.1 夜間輪子改由 Dist 作業釋出，GitHub Releases 與華為雲 OBS 雙通道

#4411 於 11-23 21:30 進主幹，改 2 個檔案，增 414 行、刪 11 行。提案說明背景：舊的 tile-ai/tilelang-nightly 流水線已停用，OBS 此前沒有接上中國大陸下載。

做法是把 Dist 作業已構建好的輪子在各平臺間複用。test-wheels-gpu 透過後，各平臺的輪子直接進入釋出。schedule 與 workflow_dispatch 觸發的構建加日期與提交字尾，開關為 TILELANG_BUILD_WHEEL_WITH_DATE=ON。PyPI 釋出版本格式不變。

兩條釋出通道互相獨立。publish-github-nightly 把輪子發到 tile-ai/tilelang-nightly 的 GitHub Releases。它同時更新帶 SHA-256 的索引 https://tile-ai.github.io/whl/nightly。未配置 NIGHTLY_GITHUB_TOKEN 時該通道跳過並告警。

publish-obs 把輪子與百分號編碼的 TileLang/index.html 上傳到 obs://ascend-triton-open/TileLang/。隨後以匿名 HTTPS 驗證可讀性，失敗時回退 -acl=public-read。索引寫到 https://tile-ai.github.io/whl/nightly-cn。

來源： https://github.com/tile-ai/tilelang/pull/4411

1.2 佈局與分片物件自持佔位變數，輸入維數上限 16 取消

#4416 於 11-23 21:07 進主幹，改 23 個檔案，增 607 行、刪 583 行。

此前的三個佈局型別依賴程序級靜態 tirx::Var 單例。三個型別是 tl.Layout、tl.Fragment 與 tl.PartialFragment。單例是 InputPlaceholder(0..15) 與 ReplicationPlaceholder()。

派生問題有三條。FFI 序列化要手寫反射存取器。輸入維數被硬性限制在 16。src/layout/ 之外的呼叫方會透過共享全域性 Var 隱式耦合。

改法是對齊 TVM 的 tirx::IndexMap。LayoutNode 持有 forward_vars_，FragmentNode 持有 replicate_var_。兩者在 forward_index 與 forward_thread 之前用 SEqHashDef() 註冊。

由此兩個 JSON 圖介面可直接序列化。StructuralEqual 與 StructuralHash 具備 alpha 等價性。建構函式中統一用 MakeLayoutVars(ndim) 與 MakeReplicateVar() 生成規範變數。

來源： https://github.com/tile-ai/tilelang/pull/4416

1.4 TVM 子模組修 Z3 兩處誤證明，主倉跟 bump 在審

TVM 子模組 tilelang_main 分支視窗內兩筆合入，均由同一位作者提交。

#97 修兩處可靠性缺陷。其一，VisitShiftOp 在未 push() 的共享求解器上執行 solver->add，任何移位表示式都會永久約束移位量 b。後果是在 b < 0 或 b >= 64 的外層作用域裡，後續謂詞都可能被判為可證。

其二，DivNode 與 ModNode 走的是向零截斷，而 Z3 對 Int 的原生 / 與 % 是歐幾里得語義。因此 CanProve(truncmod(a, 4) >= 0) 在 a 可為負時也會假成功。改法是用 floordiv 與 floormod 對稱編碼，按 a >= 0 分支取式。

#96 單獨修常量有符號右移，改為整數運算。主倉側的跟進 #4482 仍在審。

來源： https://github.com/tile-ai/tvm/pull/97

2.1 PTO 生成器補迴圈攜帶標量，五個 DeepGEMM 用例恢復編譯

#4418 於 11-23 10:17 進主幹，只改 1 個檔案，增 23 行、刪 11 行。

問題出在 CANN 9.2.0 自帶的 PTODSL（PTOAS 0.65）。五個 DeepGEMM 的 scale 尾巴與 group padding 用例編譯失敗，都走到 grouped scale 變換裡的同一個迴圈。MLIR 拒絕生成的 scf.while，報 operand #0 does not dominate this use。

核心把 group_start 初始化為 0，再在 if lo > 0 內更新。首次迭代要用分支選出的值。PTODSL 的活性分析漏掉這條依賴，直接用分支內的值當迴圈輸入。當 lo == 0 時該值沒有定義。

修法是 PTO 程式碼生成器在輸出 while 頭之前收集迴圈攜帶的區域性量。對已在作用域內、且在迴圈體中被賦值的普通標量，各輸出一次裸名字讀取。生成的 PTODSL 在迴圈入口因此多出 group_start、lo、num_ranges 三行讀取。

來源： https://github.com/tile-ai/tilelang/pull/4418

3.3 FlashQLA 修 sm120 上共享記憶體被編譯器提前讀取

QwenLM/FlashQLA 的 #55 於 11-23 18:37 合入，改 1 個檔案，增 5 行。

根因經 PTX 核對。TileLang 0.1.12 的 tl::mbarrier_wait 位於 tl_templates/cuda/barrier.h。該處內聯彙編沒有 "memory" clobber。

在 blackwell_sm120/fused_fwd.py 中，S warpgroup（tx < 128）從不寫靜態共享記憶體。它只讀 g_exp_shared[block_S - 1] 這個編譯期常量偏移。特化到 use_initial_state=False 時，nvcc 或 cicc 把 ld.shared.f32 提升到 for i_s 迴圈之外。讀到的就是未初始化共享記憶體。

後果是第 0 塊之後狀態誤差變大。未初始化共享記憶體若含 NaN 位型，則直接出 NaN。

修法保留 torch.empty(...) 與 T.clear(h_fragment) 不動。隨後在 barrier 等待之後插入一次塊內柵欄呼叫。插入位置是 T.barrier_wait(bar_1, i_s % 2) 之後。呼叫形式為 T.call_extern("void", "__threadfence_block")，在兩個 warpgroup 都加。PTX 上表現為 membar.cta。

驗證環境為 RTX 5090、CUDA 12.8、PyTorch 2.8.0+cu128、TileLang 0.1.12。

來源： https://github.com/QwenLM/FlashQLA/pull/55
