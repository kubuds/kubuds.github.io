一、核心專案進展

1.1 主倉：ROCm 雙筆——DeepSeek NSA 前向/解碼與 flash-decoding 可行瓦片（10-13）

日期：2026-10-13（合入於北京時間凌晨）　來源：ROCm NSA（#3152）／ ROCm flash-decoding 瓦片（#3149）

  • DeepSeek NSA on ROCm（#3152，+111/-2）：gfx942 波前尺寸為 64，TileLang 拒絕小於波前的 HIP block，而兩枚 NSA 示例硬編碼了 32 執行緒；本筆為前向與單 token 解碼核心選擇單個 64 lane 波，保留 CUDA 現有 32 執行緒啟動配置，並補 gfx942 上因果前向與單 token 解碼的正確性覆蓋（對照 PyTorch NSA 參考，FP16、16 Q 頭 1 KV 頭、序列 64）。
  • flash-decoding 瓦片自適應（#3149，+82/-5）：gfx942 上 128x64 瓦片的生成核需 66048 位元組動態 LDS（超 65536 裝置上限）並觸及 256 VGPR 天花板，導致啟動報「invalid argument」；本筆在啟動前檢查生成的 HIP LDS 與 VGPR 佔用，僅超預算時回退既有 64x64 瓦片（不按裝置名硬編碼），CUDA 路徑不變，並加入 gfx942 執行時迴歸。

1.2 主倉：thread_storage_sync 精確執行緒邊界（#3291）並修復 #2954（10-13）

日期：2026-10-13　來源：精確執行緒邊界（#3291）

  • 為 thread_storage_sync 計算精確執行緒邊界（4 檔案、+292/-96），作者核實 #2954 由本筆修復；新增用例驗證「等價的部分執行緒 guard 歸約到同一 barrier」，並附 SM89（4060 Ti）上的前後編譯產物對比。

1.3 主倉：Autotune 結構化試驗報告、CodeRabbit 自動指派與測試規範文件（10-12 ~ 10-13）

日期：2026-10-12、2026-10-13　來源：試驗報告（#3393）／ CodeRabbit 自動指派（#3487）／ 測試規範（#3489）

  • Autotune 試驗報告（#3393，+98/-7）：新增實驗性 AutoTuner.run(on_trial=...) 觀察者介面（對應 RFC #3375），逐試驗輸出配置索引、JSON 配置、結果、時延、驗證標籤與限量錯誤文字；回撥在聚合執行緒、共享快取鎖之外執行；報告/序列化出錯只關閉該次報告、不影響調優，且不改動候選生成、超時與快取身份。作者註明「回撥 vs 固定 JSONL 工件」仍是開放 API 決策。
  • 評審護欄（#3487，+1/-1）：CodeRabbit 的 reviews.auto_assign_reviewers 置為 true，使其真正發出 review 請求（此前僅在走查中列出建議），11 條 reviewer 規則與順序保持不變。
  • 測試規範（#3489，8 檔案）：新增 Testing Style Guide——何時依賴現有覆蓋、何時最小擴充套件、何時新增聚焦覆蓋；tilelang-cpp-style 更名 tilelang-dev-guide，C++ 規則轉為按需參考，CONTRIBUTING 精簡併掛鏈。

  • D256 dense GQA 解碼（#2529）：SM89 上開放 256 維 dense GQA 解碼——沿用 64×64、單 stage、128 執行緒劃分程式，16 個候選劃分佔 98304 位元組（低於 SM89 上限 101376）；排除單 split 候選、保留短 KV 的兩 split 候選；測試擴至 61 節點（+6），覆蓋 KV 長 1 / 63 / 2048。RTX 6000 Ada 實測。

  • GDN / DeltaNet 預填（#2527，11 檔案）：複用 KDA 的 chunk prepare 與 scan 程式實現 SM89 預填，21 例通用預填從「失敗不可分發」轉為透過；保留 raw-beta 舍入、打包序列邊界、分組頭、FP32 初末態與 GDN 的 value-major 狀態佈局；穩定性三角求解複用，相關性鍵用例不放鬆容差。
  • Norm 兩筆：#2526 修復 192×192 空間輸入的 InstanceNorm 訓練編譯（六個 batch / 精度組合從失敗到透過，複用 GroupNorm 的寬度邊界與兩遍歸約）；#2544 將共享位移歸約寬度常量（32768）歸位到 norm 配置模組（87 例全過，無效能宣告）。

3.2 TileOPs：foundry 效能批——NSA 持久 CTA、W4A16 GEMM 與 16 位除法（10-12）

日期：2026-10-12　來源：NSA 持久 CTA（#2531）／ W4A16 GEMM（#2534）／ 16 位除法（#2543）

  • NSA 壓縮持久 CTA（#2531，+391/-2）：SM90 上 NSACompressedVarlenFwdOp 換用新核 NSACompressedFwdVarlenTMAKernel——舊核按（token, KV 頭）一枚 32 執行緒 CTA、逐 token 過載壓縮 K/V；新核 512 持久 CTA，每 CTA 步行 64 行瓦片（4 token × 16 頭），查詢經雙 stage TMA 環、請求 K/V 塊常駐共享記憶體，QK 以 n=16 SS WGMMA、PV 以 n=64 RS WGMMA，O 在 QK 讀完後經 TMA 連同 log-sum-exp 出；每 SM 駐四個 48KB CTA。
