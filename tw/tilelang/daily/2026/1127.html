今日重點：摩爾執行緒 MP31 一次丟擲 14 筆 PR，低精度與集合通訊同時補齊

tile-ai/tilelang-musa 在 11-27 凌晨 02:18 至 04:16 之間新建 14 筆 PR，編號從 #14 到 #27。這批提交全部以 v0.1.15+musa.1 為基礎分支，並宣告瞭堆疊順序，#25 要求排在 #19 之後合入。

低精度是主線。#19 讓 MP31 的 fragment-A SQMMA GEMM 合法化，並加上 188 KiB 共享記憶體護欄。#25 補上 MP31 原生 W4A16 SQMMA，覆蓋 fp16/bf16 × int4 → fp32 與反向兩種組合。#25 還改寫了 sqmma.h，繞開 MUSA 5.2.0 標頭檔案裡 s4 被誤寫成 fp4 的問題。#20 開啟 warp 專用 GEMM 的 FP8 TME 描述符。

訪存與同步各佔一批。#27 讓 4 位權重的打包 UINT8 TME 載入可用。#18 給 TME 核心補退出時的 tme_flush()。#16 把 MP31 的 swizzle 索引改成元素單位，以保住向量化。#24 修 warp 專用 TMA 屏障，跨 squad 的部分同步被降到每 squad 的 128 執行緒屏障。#26 把消費者側的多 warp AllReduce 降到 MP31 部分屏障。

語言面也在擴。#23 增加塊內並行的 T.sort、T.argsort 與 T.topk，用雙調排序模板實現，支援 int4 之外的六種 dtype 與任意非 2 的冪長度。#15 透過 murand 支援 T.rng_init 與 T.rng_rand。#21 增加 T.reduce_prod、兩屏障多 warp 一維掃描與 mem-bound 的 TIR pass。#22 把 tl.enable_fast_math 接到 mcc -ffast-math。

驗證側落在 MTT S5000（mp_31）。#23 的排序用例 25 項全過，覆蓋 MoE top-2/8、NSA top-64/512 與非 2 的冪長度。#25 另有低精度與累加用例。

來源： https://github.com/tile-ai/tilelang-musa/pull/25。

今日重點：主倉三筆全在昇騰，host-mapped 緩衝引數進入主線

tile-ai/tilelang 主分支視窗內只有 3 筆提交，全部帶昇騰標籤。這與此前快取子系統、ROCm 修復的節奏不同，昇騰已成為主線的穩定輸入源。

#3909 於 09:44 合入，給昇騰加上顯式的 host-mapped 緩衝引數。此前 ASCEND 核心即使拿到已對映的 CPU 張量也會拒絕，呼叫方只能關閉張量校驗。新路徑沿用 #3802 的契約，走同一個 T.annotate_host_mapped_buffers(...) 介面。Cython 與 TVM-FFI 兩側都用 aclrtHostGetDevicePointer 驗證對映，再傳裝置可見地址。dtype、形狀、步長與執行裝置的檢查全部保留。

#4486 於 11:32 合入，修 #4429。觸發場景是 nk=topk=960 的 FlashMLA 預填：每個 query 處理 15 個 KV tile，兩個 query 槽交替，首個槽在 30 次迴圈後複用。舊實現給每對同管線站點按每個迭代距離各建一條邊，單對站點可貢獻 0 到 30 共 31 個距離。新實現按「源、目的、嚴格性」存不相交閉區間，兩個區間複合仍是區間，於是能按批傳播新覆蓋的距離。

#4390 於 12:25 合入，把昇騰 CI 裡的 PTOAS 改為從 PyPI 安裝。CANN 9.2 映象不動，先用映象自帶指令碼解除安裝其中的 PTOAS 元件，再用 --upgrade --no-deps --only-binary=:all: 裝最新相容輪子。安裝後校驗 Python 3.12、x86_64、包與 CLI 版本一致，並確認 PTOAS、PTODSL、MLIR Python 模組與原生擴充套件都能從虛擬環境載入。安裝或校驗失敗時跳過 PTO 後端示例與單測，並把步驟結果寫進作業摘要。

來源： https://github.com/tile-ai/tilelang/pull/3909。

今日重點：TileFoundry 開 Apple ANE 目標，TIR 直出 HWX 容器

tile-ai/TileFoundry 新增在審 PR #369，標題寫明 Apple ANE 的 codegen 鏈路。路徑分三段：TIR → 任務描述符 → HWX 容器。該筆建立在 #361 已引入的 ANE 目標之上，是 TileLang 生態裡第一個端側神經引擎目標。

實現分兩層。ISA 層給出暫存器位域圖，覆蓋 Common、L2、PE、NE、TileDMA 與 Kernel 六類塊。任務描述符采用 RUN/MASK 包編碼，並配套 load、store、compute-PE、compute-NE、conv、activation 六類原語。另有一套宣告式公式與跨欄位校驗庫，在構建期即以失敗關閉的方式驗證描述符。

程式碼生成層做發射器分派、逐 pass 序列化與 HWX 容器輸出。容器是 Mach-O 格式，按其描述為逆向後從頭實現，並對預設映象做字消除。超出範圍的 tile_height 與 tile_width 在編譯期直接拒絕。

正確性上，提案稱在已覆蓋的運算元範圍內與蘋果自家編譯器的輸出位級一致。

同倉同日合入 #368，修 #162 改名後遺留的問題。程式碼生成對仍為 ShardLayout 的屏障投射 tilefoundry::local，而該函式已改名為 local_tensor，編譯到 nvcc 階段即中斷。修法是隻為「整網格廣播」的屏障取字，遇到分片屏障直接拒絕。理由是分片屏障給每個 warp 分配不同的字，而 CopyAsyncBulk 只從第一個 warp 的執行緒按 CTA 到達一次，其餘 warp 會等一個永不完成相位的字。

來源： https://github.com/tile-ai/TileFoundry/pull/369。

一、核心專案進展

1.1 host-mapped 緩衝引數進主線，昇騰不再要求關掉張量校驗

#3909 改在 Cython 與 TVM-FFI 兩條繫結路徑。兩者都用 aclrtHostGetDevicePointer 取裝置端地址，並把原始 dtype、形狀與步長帶到核心。C++ 繫結簽名不變，改為按已有裝置型別選擇執行時查詢。Cython 保留預設的 CUDA 解析器，只有昇騰提供可選解析器。CUDA 側仍走 use_torch_stream()，共享裝置選擇邏輯未動。

只有「全 host 引數」的昇騰簽名會顯式安裝原始 NPU 流。測試覆蓋全 host 引數、自動分配的 NPU 輸出與 NPU Graph 捕獲三種場景。

1.2 InsertSync 改按區間傳播依賴距離，31 個迭代距離不再逐條建邊

#4486 只改 InsertSync 這一個 pass。此前對每個同管線站點對，實現按每個迭代距離各插一條邊，並在構建依賴閉包時反覆複合。新實現把可達距離存成閉區間，複合兩個區間得到另一個區間，從而只傳播尚未覆蓋的距離。空隙與嚴格性都顯式保留，距離 0 與 1 仍按原有的 epoch 域投射規則處理。

FIFO 工作佇列改用 std::set，鍵為源、目的、兩個距離邊界與嚴格性，用於跳過重複的待處理區間。

1.3 昇騰 CI 改從 PyPI 裝 PTOAS，CANN 9.2 映象保持不動

#4390 的動機是 PTOAS 與 CANN 的發版節奏不同步。此前 PTOAS 隨映象固定，升級要改工作流。改後只要索引裡有新版本就會被拾取，無需改 workflow 或更新既有依賴。

同一筆還調整了普通 SIMD 掩碼的初始化，以適配新版 PTOAS。

1.4 在審 16 筆：PTO 向量化與正形狀假設推進，T.reshape 靜默 NaN 待修

主倉在審更新共 16 筆。PTO 方向有 #4523，把 T.Parallel 向量化到 PTO，覆蓋條件分支與 lane 內均勻的序列迴圈。#4524 在 ptoas 裡改用 vdiv，#4522 去重多核心 PTO 編譯的輔助符號。

效能方向有 #4526，按緩衝區形狀為正的前提刪掉冗餘保護。修復方向有三筆。#4519 補 examples/conftest.py 缺失的 default_target_is_cutedsl。#4520 修 from __future__ import annotations 下 @T.prim_func 裝飾失敗。#4521 讓 bfloat16 標量 min/max 走 float 過載。

當日新開 issue 裡最重的一條是 #4525。T.reshape 作用在 T.StridedTensor 上會丟步長並讀到行間填充，輸出靜默變成 NaN，不報錯。該條尚無修復 PR。

來源： https://github.com/tile-ai/tilelang/issues/4525。

二、多後端適配（昇騰 / 海光 / 摩爾執行緒 / 沐曦）

2.1 摩爾執行緒 14 筆成批提交，MP31 補 W4A16 SQMMA 與 188 KiB 共享記憶體護欄

14 筆 PR 覆蓋五類工作：低精度 MMA 合法化、TME 訪存與屏障、語言面運算元、快速數學開關、以及驗證用例。#19 是底座，其餘多筆宣告依賴它或與它同棧。

#19 的要點是 fragment-A 佈局的 SQMMA GEMM 合法化，同時把共享記憶體上限定為 188 KiB，超限即拒絕。#25 在其上補原生 W4A16，並給出 int8/uint8 → fp32 的累加合法化：硬體側用 int32 SQMMA 累加，再無損轉 fp32。#25 還把 Hilbert2D 執行緒序號重排推廣到非方形 tile，介面為 T.use_swizzle(..., order="hilbert")。

#21 新增 WarpFirstAllReduce、T.reduce_prod 與兩屏障多 warp 一維掃描，另加一個按共享記憶體頻寬建模的 TIR pass。#24 修 warp 專用 TMA 屏障，並把跨 squad 的部分同步降到每個 squad 的 128 執行緒屏障。#26 把消費者側的多 warp AllReduce 也降到 MP31 部分屏障。

#14 補 int8/uint8/int16/int32 廣播用的打包整型向量構造。#17 恢復 __launch_bounds__、annotate_min_blocks_per_sm 與 -O3。#18 給 TME 核心補退出時的 tme_flush()，#20 開啟 FP8 TME 描述符並約束自動 TME 的 16 位元組內框對齊。

語言面 #23 的排序族是本批最完整的一筆。實現按「原索引更小者優先」做嚴格全序，與 torch.sort(..., stable=True) 和 torch.topk 對齊。支援 float32、float64、float16、bfloat16、int32 與 int64，一維與二維，升降序，任意長度。緩衝覆蓋 shared、fragment 與 global 三類。在 2 的冪長度上原地排序共享緩衝時不額外佔共享記憶體。

2.2 昇騰子倉修快取的介面卡庫路徑，HF32 與 UB 列儲存仍在審

tile-ai/tilelang-ascend 預設分支 ascendc_pto 視窗內 1 筆提交。#2002 於 14:51 合入，修 #1999 評審提出的問題：從磁碟快取載入核心後，adapter.libpath 沒有恢復，仍為 None。後果是依賴該路徑在子程序過載動態庫的測試，會在 ctypes.CDLL("None") 處拋 OSError。

修法是在 Cython 與 Ctypes 兩個介面卡的 from_database 裡各補一行路徑恢復，並新增迴歸測試。計算、同步邏輯與快取命中策略都未改動。

在審兩筆與計算相關。#2037 在 gemm_v0 裡暴露 HF32 模式並擴充測試，#2025 修昇騰 UB 的列儲存與 DMA 尺寸計算。

2.3 MLIR 昇騰把 CANN 版本差異移植到 master，L0 地址空間落在 mlir-dialect

#274 於 17:13 合入 master，與主倉 #4399 是同一份補丁，18 個檔案完全一致。問題描述給出兩個實證。其一，CANN 9.1 的跨步 GM↔UB 複製 API 會把 32 位塊計數截成 16 位。其二，powf(-2.0f, 2.0f) 在 CANN 9.1.0 上返回 NaN。修法是生成程式碼繼續用 SDK 函式名，把受影響的呼叫統一路由到相容層，覆蓋 DMA 塊計數、矩陣複製引數、HF32 舍入模式、INT32 原子操作與標量 GM 讀。

#252 於同日合入，但基礎分支是 mlir-dialect 而非 master，因此不計入 master 的提交歷史。該筆給 tl.alloc 增加 TL_L0A、TL_L0B、TL_L0C、TL_L1 四個地址空間。

在審側，#261 增加 tl.vrelu 並給出 TL 到 HIVM 的下降與測試。#253 增加 reduce_sum、reduce_max、reduce_min 三個歸約及其 HIVM 下降。

2.4 海光主分支無提交，FP16 MMAC 與 BW1000 構建快取各一筆在審

tile-ai/tilelang-hygon 的 pushed_at 落在視窗內，但主分支零提交，推送來自 PR 分支。#48 題為 FP16 MMAC 佈局與向量儲存，11-26 21:14 新建，描述為空。#49 讓 HCU 構建快取持久化，面向 BW1000 平臺的構建，21:55 新建。#47 只是 README 更新。

2.5 沐曦僅一次 main 到 dev 的分支同步

tile-ai/tilelang-metax 主分支無提交，視窗內唯一動作是 #164，把上游 main 合到 dev。該筆為分支同步，無功能變更，按慣例不計入技術進展。

來源： https://github.com/tile-ai/tilelang-ascend/pull/2002。

三、生態與採用方（TileOPs 運算元庫 / TileFoundry / FlashQLA）

3.1 TileOPs 十筆，三處 0.1.15 效能回收同日落地

tile-ai/TileOPs 主分支視窗內 10 筆提交，全部為效能或測試，無新運算元。三條線都在回收 TileLang 0.1.15 帶來的效能損失。

第一條是 dropout。#3181 報 16 位行的 dropout 自 0.1.15 起慢 13% 到 16%。原因是 T.rng_rand_float() 被 T.Parallel 向量化後，一個向量共用一次抽樣。0.1.15 又把 16 位向量從 8 元素收窄到 4 元素。#3187 改為每個元素獨立從計數器取 32 位 Philox4x32-10 值，高 16 位用執行緒首批抽樣，低 16 位僅在高位與閾值相等時才補抽。該改動同時消除了向量內的掩碼相關性，數值也從相關轉為獨立。

第二條是 W4A8 預填。#3172 在每個 tile 迭代開頭給消費者 warp 補 T.sync_warp()。此前 ptxas 無法證明 warp 在 K 迴圈處已收斂，把環形緩衝的 stage 索引與 WGMMA 描述符留在向量暫存器裡，每次 WGMMA 前複製到統一暫存器。結果 R2UR 從 20 漲到 52，四個形狀慢 10% 到 13%。

第三條是 RoPE。#3173 把分階段 RoPE 改成按 (tokens, sides) 網格發射，每塊用一次一維批次寫回整行。此前 8 KiB 的行被拆成 16 次 tensor-map 寫，且每次查表都帶越界保護。實測 gptj-6b 預填從 15.440 微秒降到 15.264 微秒。

3.2 DeepSeek-V4-Flash 預填去掉 RoPE 行複製與視窗環複製

#3186 改兩處。壓縮層的 RoPE 表按壓縮比預存每個位置的餘弦與正弦，壓縮器預填不再給 RoPECosSinFwdOp 傳一個每次呼叫都複製的跨步切片。預填寫最後 window_size 行 KV 時，原先走 arange、取餘、gather、scatter 四步，現改為兩次切片複製。

測試側新增 256 token 提示、兩個完整視窗的用例，其環形寫入從槽 0 開始。

3.3 Qwen3.8-27B 的 6 頭查詢組走上 warp 專用 GQA 核心

#3174 解決的是分組寬度受限。GQAPagedFwdWSKernel 此前把一個 KV 頭的整個查詢組塞進 128 行 tile，每頭佔 128 // group 行。這樣只支援 1、2、4、8、16 頭或超過 16 頭，其餘組合回落 gqa_paged_varlen_kernel。Qwen3.8-27B 的 6 頭組正落在回落分支，它有 24 個查詢頭對 4 個 KV 頭，head_dim 256。

新實現讓一個 tile 只放一個頭組，_tile_heads 取能整除查詢組、且讓每頭佔滿 8 行 swizzle 原子的最大 2 的冪，對 Qwen 即 2。一個 KV 頭的組按 slices 拆成多個頭組，各自成為工作項，生產者載入 group_id // slices 這個 KV 頭的 K、V 與旋轉後的 key 列。

在審側同日出現一個成體系的系列，共六筆：#3189 到 #3194，主題都是「跨步檢視下原地讀」。涉及 BMM 的 a 與 out、CausalConv1d 的 x、RMSNormGated 的 x 與 z、PagedKVCacheWrite 的 k 與 v 等六處。另有 #3195 把 Qwen3.8-27B 的 positions 每步只構建一次，不再逐注意力層重建。

3.4 MXFP4 分組 GEMM 改按每 CTA 的 tile 字首找專家

#3177 處理任務定位的開銷。共享的 task_walk 逐個專家前進，每步一次依賴的全域性讀，連續段上兩次。每個 CTA 因此要為佈局裡所有專家付費，空專家也照付。

新增的 table_task_walk 讓每個 CTA 把各專家的行 tile 數一次求和進共享記憶體。之後用 warp shuffle 掃描一段專家的和，專家數超過塊內執行緒數時再讓一個 warp 掃一遍各段總和。最後每個 warp 用一次 ballot 前進最多一個 warp 寬度的專家。

3.5 取樣、嵌入、KDA 與 CUDA Graph 資格測試同日合入

#3184 處理 top-p 行機率為 1 的情形，改為整行直通並只取一次保留鍵。#3188 讓寬嵌入呼叫在透過率允許時以兩個 warp 的 CTA 單波完成，不再按每 CTA 一個 warp 的保守劃分執行。

#3179 修值主序的 KDA 解碼在狀態接近 FP32 上限時發散，改為保持有限。#3175 給兩個模型各自的解碼步運算元逐項做 CUDA Graph 捕獲資格測試。#3176 修標題編輯後標籤不同步，改為讀 GITHUB_EVENT_PATH。

3.6 TileFoundry 修屏障廣播的程式碼生成，分片屏障改為直接拒絕

#368 除修 local_tensor 改名遺留，還處理了兩個座標分支。它們同樣會發射已不存在的函式，但當前無路徑可達：#186 起型別推斷拒絕在指標檢視上帶座標，而所有 pass 都只從指標構建 TensorView。

五、趨勢觀察

第一，摩爾執行緒這一批 14 筆的性質不是補丁，而是把 MP31 後端一次性推到「低精度可用、集合通訊可用、語言面齊全」。依據有三條。W4A16 與 int8 累加都在硬體指令層合法化。AllReduce 已有三套實現，含 warp 首、部分屏障與跨 squad 拆分。排序族直接對齊 PyTorch 穩定性語義。這套組合通常出現在後端準備承接推理運算元庫之前。

第二，昇騰已經把主倉變成常態化輸入。視窗內主倉 3 筆全部帶昇騰標籤，且性質各異。一筆是 API 能力（host-mapped 緩衝），一筆是編譯期複雜度（InsertSync 距離區間化），一筆是 CI 供應鏈（PTOAS 改從 PyPI 裝）。同時 12 條新缺陷集中在 RNG 與 DeepGEMM，說明覆蓋面已進入數值細節層。

第三，TileOPs 正在承擔 0.1.15 的效能迴歸回收。三條線（dropout、W4A8 GEMM、RoPE）都由 0.1.15 的程式碼生成變化引起，且都以具體百分比或微秒數落地。這提示編譯器側的改動需要有運算元級迴歸基線來兜住，否則損失會滯後一個版本才被發現。

第四，目標擴充套件到端側。Apple ANE 的 codegen PR 若合入，TileLang 的目標面將從 GPU 與國產 NPU 擴到手機與平板的神經引擎。實現路徑是把 TIR 降到任務描述符再打包成廠商容器。這與昇騰、摩爾執行緒走的「生成廠商 C++ 再編譯」路線不同，是另一條落地方式。

第五，RISC-V 四源連續第二個視窗零變化。TVM 路線與 MLIR 路線都停在上一期引用，SOPHGO TPU 分支數也無增減。該方向仍處低位，暫不構成趨勢。
