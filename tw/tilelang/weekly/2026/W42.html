TileLang週報（2026-10-12 ~ 2026-10-16）

2026-10-16 苦芽科技

報告週期：2026 年 10 月 12 日（週一）至 10 月 16 日（週五），共 5 個工作日、5 期日報素材 素材來源：本刊每日 TileLang 動態日報 5 期（10-12、10-13、10-14、10-15、10-16）；另經 tile-ai 組織 29 個倉庫的 168 小時視窗補充核查、夜間流水線六份快照的測試結果逐份復算與各倉庫釋出後設資料複核（詳見附錄）

一、本週要聞

  • 主倉 ROCm 線連續四日收筆，DeepSeek 新架構核心成為第三收筆線（10-13 ~ 10-14）：10-13 合入 DeepSeek NSA 前向/單 token 解碼的 64 lane 單波實現（#3152，+111/-2）與 flash-decoding 的 LDS/VGPR 預算自適應瓦片（#3149，+82/-5）；10-14 凌晨再合入 mHC（流形約束超連線）前/後處理核心（#3156，2 檔案 +83/-6，HIP 側改在完整 64 lane 波前上分工並把 FP32 混合權重轉 BF16 供 MFMA）與 safe-gated KDA 解碼示例（#3249，+360，含 GLM-5.3-Flash TP8 專用化配置）；10-14 另有 cumsum/cummax 的 64 lane 段寬修復（#2326）。四筆共同指向「按裝置現實自適應」：gfx942 波前尺寸、MFMA 輸入型別、LDS/VGPR 預算逐項清償，ROCm 支援從「跑通」轉入「與新架構釋出同步」。

  • 昇騰 PTO 由「獨立目標」升為「一等執行路徑」，NSA 雙遷移與回滾紀律同周發生（10-12 ~ 10-15）：10-15 合入執行路由 #3316——target="ascend" 與 execution_backend="pto" 組合經執行感知的目標規範化後直連 CodeGenTileLangPTO，auto 路徑維持 AscendC + TVM-FFI；前置的示例目標選擇 #3474（10-14 合入，移除硬編碼 target="ascend"，CI 對 ascend / pto 雙目標各跑一遍）與本視窗在審的 tvm_ffi 後端、VMI 向量化、SS buffer、部分 L0 複製 pitch 等七筆構成家族。同周 10-12，昇騰 NSA Decode（#1701，+755，28 例分層測試）與 NSA Bwd（#1730，+1593，20 例）合入；10-14 三筆「文件事實核查」PR（#1612、#1676、#1681）因低優先順序預期失敗用例的異常正則不匹配被整批迴滾（#1888 至 #1890），bitwise_rshift 以 重做版 #1893 刪減預期失敗斷言後重新提交；10-15 開出 dav-3510 上 gemm_v0 的靜默數值錯誤修復（#1900），暴露 --npu-arch 無條件取 dav-2201 導致 A5 核心瞄錯架構。

  • TileOPs 一週 52 筆合入：Op 基類重構定稿、MoE 雙運算元落定、SM89 成為第二平臺（10-12 ~ 10-16）：10-11 合入的 Op 基類重構（#2520，363 檔案、+3362/-5227，自稱「釋出前」收口）把帶與不帶編譯邊界的運算元統一經 _run_call 執行、select_kernel_key/select_implementation 合併為 key_for、編譯邊界改從 manifest 推導，文件站次日跟進《Op 基類指南》；10-13 MoE 雙運算元同日落定——masked FP8 分組 GEMM（#2521，20 檔案 +1788/-37，對齊 deep_gemm masked 語義）與 DeepSeek 分組 top-k（#2535，15 檔案 +1193/-69，對齊 vLLM grouped_topk 並修 T=512 時 32/132 SM 的排程問題）；SM89 從 10-12 起成批收口（GQA 預填/解碼、GDN / DeltaNet 預填、GLA / DeltaNet 反向、KDA 預填、Norm 全譜），RTX 40 系與 L40 / 6000 Ada 級工作站在運算元庫側與 Hopper 並列。

二、核心專案進展（主倉 tilelang）

版本與釋出

  • 主倉最新標籤與釋出仍為 v0.1.15（09-30 釋出），全周無新標籤、無新發布頁條目，至本週五已 16 天。釋出頁最近三條依次為 v0.1.15（09-30）、v0.1.14（09-02）、v0.1.13（08-03），此前的月度節奏在本週被打破。
  • 適配線標籤全周未動：昇騰 v0.1.2.000、MLIR 昇騰 v0.1.2.020.sglang.poc、沐曦 v0.1.14（10-13 僅 main 映象到 v0.1.15 節點、未打新標籤）、摩爾執行緒 v0.1.14+musa.1；海光以 v0.1.15 主線加 v0.1.12-release 維護線雙線並行。
  • 釋出靜默的對照面是下游約束上移：TileKernels v2.1.0 明確要求 TileLang 0.1.15 起，FlashQLA 的 sm120 修復亦在 0.1.15 上驗證——本週起「0.1.15 基線」成為採用方事實上的最低要求。

編譯器、執行路徑與語言層

  • PTO 執行路由（#3316，10-15 合入）：新增執行感知的目標規範化鉤子（掛在 BackendContext 建立處），昇騰專屬規範化器在解析前把原生 Ascend 目標專門化為 PTO 目標變體並保留 arch 等屬性，裝置程式碼生成改走 PTO_CODEGEN 與 target.build.tilelang_pto_without_compile；文件給出 TILELANG_DEFAULT_TARGET=ascend 加 TILELANG_EXECUTION_BACKEND=pto 的等價配置。測試覆蓋上下文解析、目標屬性保留、快取分發與環境變數選擇。
  • PTO DeepGEMM codegen（#3330，10-14 合入）：跨控制流跟蹤 tl.ascend_set_mmad_direction 並把生效方向編碼進 MAD 指令、拒絕衝突方向下可達的 MAD；支援 SIMD 後增量載入、混合 AIC/AIV 核心的 UB 地址到 PTODSL 指標轉換、動態 L0C→UB 維度與步長、int16 有符號打包 MX scale。自報 15 個 DeepGEMM PTO 用例 14 個透過，test_bf16_m_grouped_padding 仍受 PTOAS VPTO 後端無法合法化 FP32→BF16 轉換阻塞。
  • 獨立 AIV 執行（#3485，10-14 合入）：擴充套件 Ascend AutoSchedule，使 AIV0 與 AIV1 可在 sid 依賴下執行不同工作（交替收尾、反量化與收尾分工、不相交輸入分割槽、迴圈內角色切換）；AssignCore 提前到延遲估計與排程之前，併為 AIV 區域性 UB 緩衝與標量狀態建立獨立身份。
  • C 系 codegen 共享基類（#3289，10-14 合入）：CodeGenTileLangCBase 統一 CUDA、HIP、CPU C、Ascend C++、Metal 與 C 主機程式碼生成；修復 T.import_source、T.Kernel(prelude=...) 與 pragma_import_c 在源文字缺少末尾換行或以反斜槓結尾時吞掉下一生成行的問題。驗證：聚焦迴歸 83 透過、codegen 與 launch 套件 405 透過。
  • CPU 網格並行（#3109，10-14 合入）：新增 MaterializeCPUParallelGrid 把帶註解的 CPU grid 迴圈轉為 OpenMP 並行迴圈，配套迴圈 collapse、執行緒數配置、最小 trip 數門限與分配下沉，補齊 Linux / macOS / Windows 的編譯標誌——CPU 後端首次具備網格級並行。
  • Host IR 線全周在審：統一 CUDA 與 CuTeDSL 執行路徑的 #3473 與直連 Host IR JIT 加原生快取的 #3481 自 10-10 開出後未見合入，仍是主倉最大的在審方向。
  • PTO 家族七筆（10-15 起在審）：tvm_ffi 執行後端（#3516）、T.Parallel 到 PTO VMI 向量化（#3512）、SS buffer（#3514）、部分 L0 複製顯式 pitch（#3511）、NZ 緩衝 UB→L1 部分複製（#3530）、PTO Ramp 值按型別向量發射（#3535）、SIMT VF 內向量區域性訪問修復（#3523）。其中 SS buffer 於 10-16 上午合入（#3514，日報截點之後經補充核查確認）。

  • 10-12（週末視窗收口）：GEMM dtype 白名單（#3245，不支援組合在 CUDA codegen 前拒絕，缺陷單 #3004）、For 迴圈步長（#3427）、JIT 輸出索引歸一化汙染（#3318）、popcount 窄整數下沉（#3300，int8(-1) 計 8 位）、位歸約放行浮點源（#3332）、CuTeDSL 柵欄選舉（#3400，2D/3D 執行緒塊下多執行緒重複釋出到達）、NVRTC / CuTeDSL 引數身份（#3414）。

三、多後端適配（昇騰 / 沐曦 / 海光 / 摩爾執行緒等）

  • SuperNPUBench 全周高頻：10-12 四筆提交（rms_norm 16 KiB 瓦片分解 R=8192 歸約、gfsim RES_CHECK 檔案 IO 鎖步安全、matmul_test 簡化 4-PE、#225 合併）與兩個釋出（ops-20261012、ops-20261013，後者按 suite 拆 2 小包、含全部編譯產出 ELF）；10-13 釋出 ops-20261013.2 並推進 matmul_test 直連 CUBE TCVT、topk 可移植 gfsim fixture；10-14 三筆歸檔（rms_norm_dynamic_simt_32k、group_norm_grad 靜態核心進 V0、matmul reuseB 核心）；10-15 組歸一化反向單趟歸約與 gamma/beta 均衡（#245）。
  • tilelang-puzzles-ascend 的 simt_compare 分支全周推進：T.reduce_max 對序列掃描實測快 8.94 倍，12 個核心改用 T.reduce_absmax 摺疊並重測。

六、趨勢觀察

  • 釋出靜默期的「靜態準備」在四個方向同時到位：TileOPs 的 Op 基類重構自稱釋出前收口、夜間底盤六份快照零失敗增長、TileFoundry 的示例從解碼跨到預填全長度超越、多後端 v0.1.15 對齊——主倉自 09-30 已 16 天無標籤，但下一版本的靜態準備在本週基本就位。是否釋出，取決於評審閘門而非內容。
  • 多後端從「版本對齊」走向「同語義收口」：海光完成 v0.1.15 全量升級並另立 v0.1.12 維護線，沐曦映象追平後轉入 dev 合流，昇騰把重心放在文件事實核查、快取語義與真機驗證（#1900），摩爾執行緒是唯一缺口。四家的差距已從「有沒有後端」變為「語義是否一致」。
  • ROCm 成為第二條與新模型釋出同步的線：連續四日 DeepSeek NSA、mHC、KDA 與 GLM-5.3 相關核心落地，技術債按裝置預算（波前 64 lane、MFMA 輸入型別、LDS/VGPR 上限）逐筆清償；與 SM121 / SM89 的多代並修合流後，後端拓撲已從「英偉達優先」轉為「多裝置同時維護」。
  • TileOPs 的效能工程從「重點運算元攻堅」轉為「全運算元逐日刷榜」：單日 8 至 11 筆、每筆帶外部對照（torch-compile / cuBLASLt / quack / FlashInfer / FLA），殘餘落後被公開寫進 PR（lm-head 兩行 0.909x、GLA 反向明確不主張加速）——把「落後」量化並留檔，比單點提速更能說明工程紀律。
  • 昇騰的治理口徑從「全部透過」轉向「斷言精確」：三筆文件核查因低優先順序用例的異常正則不匹配被整批迴滾再刪減重做，暴露 PR 階段不跑 low_priority、每日全量兜底的兩級 CI 結構；這類回滾不是退步，而是把「預期失敗」當成技術債清算的訊號。
  • TileFoundry 從編譯器工具轉向可交付產品形態：scaffold 獨立工程、例項槽與 lowering 契約、跨脊線的預填示例論證，重構落地的同一視窗即被第三方 vendor 並列出缺陷臺賬——產品化的典型軌跡是「底盤重構之後，介面契約收斂與缺陷公開化」。下一期需跟蹤這些 emitter / 執行時缺陷是否被吸收。
  • 下一期關注點：主倉 v0.1.16 是否釋出（已靜默 16 天）；SM120 塊縮放 MMA 雙線（#3495 / #3099）能否合入；cumsum warp 特化修復（#3536）與 PTO 家族七筆的推進；昇騰 #1900 的兩筆提交與 A5 真機驗證排期；海光分散式 IPC 是否出現首個合入的多卡 PR；TileOPs 已出現釋出流水線整理類提交（週末），其是否引出首個正式版本；TileFoundry 的外部缺陷清單是否被吸收。
