FlagOS 每日動態報告（2026-08-17）

2026-08-17 苦芽科技

調研視窗：2026-08-16 10:18 ~ 2026-08-17 10:25 北京時間 信源：GitHub（org: flagos-ai）、Google News 聚合（中英文）、HN、智源社群等（詳見附錄）

一、開源專案進展（GitHub 動態）

視窗總覽：org 內 52 個倉庫中 8 個在視窗內有推送；commit search 命中 26 條預設分支視窗內提交（FlagBLAS 18、build-infra 7、FlagPrism 1），另有 Megatron-LM-FL #100、FlagTree #969 兩條 PR 合入，無正式 GitHub Release。本視窗三大主線：FlagBLAS 基準套件大規模擴充（Level-1/2/3 全覆蓋、海光 hipBLAS 為顯式適配目標）、build-infra 海光線映象工程與 hygon25 四場景驗證、Megatron-LM-FL 新增崑崙芯 P800 CI 支援（新晶片線訊號）。

1.1 FlagBLAS：BLAS 基準套件大擴充，海光 hipBLAS 後端鋪開（10 個 PR / 18 條提交）

來源：FlagBLAS pulls

  • Level-1 基準（8/16 10:38-13:46 合入）：Givens 旋轉 rot（#46）、ger 通用秩-1 更新（#56）、rank-1 update（#50）、rank-2 update（#51）。
  • Level-2 基準（8/16 10:40-21:28 合入）：三角矩陣求解 trsv、Hermitian 打包矩陣-向量 hpmv（#52）、稀疏打包 spmv、Hermitian 帶狀 hbmv、三角陣（#45，含海光 hipBLAS 版 #49）、帶狀陣（#47，海光 hipBLAS）、對稱/Hermitian（#48，海光 hipBLAS）。
  • Level-3 基準：trmm 三角矩陣-矩陣乘（#57，8/16 23:41 合入）。
  • 配套 core_shapes.yaml 同步登記各基準核心形狀（8/16 16:40-21:55 多條提交）。

解讀：FlagBLAS 基準覆蓋從 Level-1 標量/向量操作到 Level-3 矩陣乘全面鋪開，其中三角/帶狀/對稱-Hermitian 三個 Level-2 家族均顯式增加 Hygon/hipBLAS 後端——海光是本視窗基準適配最集中的目標晶片，與 build-infra 海光線工作構成閉環。

1.2 build-infra：海光映象工程 + megatron 線驗證（7 條提交，PR #403-#409）

來源：build-infra pulls

  • #403 海光 base 映象加入 LLVM DTK（8/16 11:18）：補上 vendor triton 依賴的 DTK LLVM 包，修復映象內編譯器鏈缺失。
  • #404 海光 triton 3.3.0 → 3.5.1（8/16 11:24）：海光側 Triton 版本升級。
  • #405/#406 2.1.2 映象描述自動重新整理（8/16 11:48/12:55）：base 層 17 後端版本資料全部透過校驗；runtime 層 1 後端校驗 1 失敗（例行自動重新整理）。
  • #407 megatron wheel 構建期 sysconfig 補丁（8/16 18:25）：compile_helpers() 原依賴 python3-config（CPython 構建產物，uv venv 中沒有），改為 stdlib sysconfig.get_config_var("EXT_SUFFIX")；三態冪等補丁指令碼作為 Megatron-LM-FL 上游 #112 合入前的臨時 fallback，兩者最終程式碼形態一致。
  • #408 海光 hygon25 四場景驗證記錄（8/16 18:27）：基於全量 megatron-core wheel（MLF #107）記錄 training / rl / post_training / inference 四場景結果——rl 因平臺 gap 阻塞（megatron/rl/inference/megatron.py:87 硬編碼動態推理引擎斷言 flash-attn ≥ 2.7.3）、tensorboard 為未宣告執行時依賴、vendor flash_attn 版本資訊錯亂（__version__ 寫死 2.6.1 實為 2.8.3+）；編譯器掩碼糾正：flagtree 3.6.0 在新映象上判定可用（此前 blocked 結論來自缺 DTK LLVM 包的舊容器）。
  • #409 app 層 env 框架 + vllm flashinfer gate（8/16 20:03）：vLLM 0.24.0 在 CUDA 上無條件匯入 flashinfer（取樣器開關預設開），透過新增 configs.yaml env.app.<app> 第三維度注入 VLLM_USE_FLASHINFER_SAMPLER=0；同時修復 vllm 預設版本 0.20.2 的 torch 拉取陷阱——裸 vllm==0.20.2 單步安裝會從映象源解析到最新 torch（2.11.0+cu130）覆蓋執行時矩陣，預設版本改 0.24.0 並強制 +flagos pin，實測安裝不再下載 torch。

1.3 Megatron-LM-FL：崑崙芯 P800 進入 CI（PR #100）

來源：Megatron-LM-FL PR #100

  • 崑崙芯（KunlunXin）P800 平臺支援（8/17 09:48 合入，AlexMa616）：新增崑崙芯平臺配置與獨立 CI workflow，8 個 XPU 裝置跑通完整單測矩陣（kl-8g-cicd-megatron 節點）；Qwen3 0.6B TP1/PP1 功能測試透過並落 P800 golden values；配置 FlagCX 並優先 vendor.kunlunxin TransformerEngine-FL 後端。
  • 已知限制：TP2/PP2 基準未啟用——崑崙芯後端對 sequence-length-4096 的 kernel 支援不足，未支援運算元回退慢實現導致超時，基準配置保留待 TE-FL 側完成後續驗證。

解讀：這是崑崙芯（百度系 XPU）首次進入 Megatron-LM-FL CI 矩陣。結合 release-info 映象文件中已存在的 kunlunxin-xre5.37.1 base 映象，訓練線新晶片適配前哨已就位——與 skill 中”PyTorch-Plugin-FL 是新晶片接入前哨站”的觀察一致，崑崙芯正沿 base 映象 → CI 矩陣的路徑進入 FlagOS 生態。
