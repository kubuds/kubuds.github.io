FlagOS 每日動態報告（2026-08-15）

2026-08-15 苦芽科技

調研視窗：2026-08-14 10:19 ~ 2026-08-15 22:30 北京時間（補跑：10:18 定時任務因模型服務超時失敗，本報告為補跑產出） 信源：GitHub（org: flagos-ai）、Google News 聚合（中英文）、HN、智源社群等（詳見附錄）

一、開源專案進展（GitHub 動態）

視窗總覽：org 內 52 個倉庫中 15 個在視窗內有推送，commit search 命中 76 條視窗內提交（committer-date 口徑），無正式 GitHub Release，但 build-infra 配置已將版本號推進至 2.1.2——這是距 FlagOS 2.1（2026-06-24 六元件同步釋出）約 7 周後的首個版本週期啟動訊號。本視窗三大主線：FlagOS 2.1.2 釋出週期啟動（build-infra megatron wheel 工廠全線打通）、Torch-FL 分散式通訊三線突破（燧原 GCU / 摩爾執行緒 MUSA / 昇騰 FSDP2）、FlagFFT / FlagBLAS / FlagDNN 三個基礎庫同時擴晶片後端（摩爾執行緒 / 海光 / 昇騰）。

1.1 build-infra：FlagOS 2.1.2 釋出週期啟動，megatron wheel 工廠全線打通（本視窗頭條）

來源：build-infra configs.yaml、build-infra commits

  • 版本號推進：configs.yaml 中 version: "2.1.2"、flaggems: "5.3.4"（此前 2.1.1 / 5.3.x 週期）；同日 #390/#398/#400 三條 “refresh image descriptions for 2.1.2” 由 flagos-ci 自動重新整理 base/runtime 映象描述文件（8/15 17:57 ~ 8/16 00:52）。2.1.2 釋出週期正式啟動，各元件 wheel 與映象標籤統一錨定新版本號。
  • megatron wheel 構建重構（#375）：放棄此前”構建器工具鏈映象 + repack”方案，改為直接在廠商 runtime 映象內構建 megatron wheel（build env == delivery env），單步安裝即構建時驗證；repack/ 目錄移除。
  • megatron 驗證閉環（#379/#383）：新增 verify-megatron-backend.sh——安裝 wheel 前後對 torch/triton/flag_gems/numpy 矩陣逐項比對（必須位元組級不變）、megatron.core 匯入 + helpers_cpp pybind 繫結檢查；#383 將驗證步驟接入 app-image workflow，驗證失敗 gate 掉映象推送。hygon25 節點實測透過（torch 2.9.0+das.opt1.dtk2604 / flag_gems 5.3.4 / megatron-core 0.17.1）。
  • 版本溯源（#393）：wheel 版本改為 commit 級溯源 0.17.1+fl.<日期>.g<sha>（如 0.17.1+fl.20260814.gba22f6b673f3），PEP 440 語義下 ==0.17.1 釘住不受影響，且可按日期排序比較新舊。
  • 海光映象增強（#399）：hygon runtime 映象加入 flash-attn（注意此前 hygon 的 megatron 驗證矩陣裡 triton 為 MISSING，flash-attn 補齊是海光側推理棧完善訊號）。
  • 工程修復：unzip 缺失批次修復（#382，11 個基礎映象）、MetaX runner label 修正（#384）、github.com 克隆超時 + HTTP_PROXY 只作用於 clone 步驟（#378）、aliyun/flagos/baai 端點 NO_PROXY 規避隧道失敗（#395）、gendoc TSV 傳輸回退 upload-artifact（#388）。

1.2 Torch-FL：分散式通訊三線突破（燧原 GCU / 摩爾執行緒 MUSA / 昇騰 FSDP2）

來源：Torch-FL PR #103、PR #105、PR #106

  • #103 燧原 Enflame GCU 分散式走 FlagCX（8/14 23:34）：此前 ProcessGroupFlagOS 無 Enflame 行，fall through 到 nvidia 預設配置（flagcx_dev=”cuda” / no NCCL），GCU 上 init_process_group 根本無法工作。本次新增 enflame profile，釘住上游 FlagCX enflame adaptor（devName=”gcu”），並加 _gcu_device_guard（GCU stream/指標是裝置作用域的，collective 運算元在其他裝置會靜默 no-op）；19 項路由測試透過，覆蓋 collectives/DDP/FSDP2。注意：無 GCU 硬體環境，live 指令碼未實跑，需雙卡驗證（提交自注）。
  • #105 摩爾執行緒 MUSA 分散式集合通訊（8/15 00:30）：新增 _flagos_identity_view C++ 繫結（原樣返回 tensor），讓 FlagCX 的 MUSA adaptor 直接消費 privateuseone tensor（FlagCX musa_adaptor.cc 取 data_ptr() 不校驗 device type，無需 storage 轉換，繞開 torch 棄用的 UnsafeStorageView）；MCCL（torch_musa ProcessGroupMCCL）作為原生兜底。配套 5 個測試檔案約 650 行：6 個基礎 collective、DDP（3 層 MLP）、FSDP2、Qwen3-0.6B 端到端 DDP（對齊生產規模梯度同步）。單測 17/17 透過。
  • #106 昇騰 FSDP2 原生 ACL stream/event 語義（8/15 00:30，本視窗工程量最大）：此前昇騰 stream/event 層只是名字相容（query 恆 False、wait/record 降級為 host 同步、GuardImpl 全 stream 返回 ID 0），FSDP2 的 fully_shard 要求獨立 compute/comm stream + 顯式事件序。本次實現：共享 ACL stream 登錄檔（C++ 執行緒本地 + 快取 GetDevice 避免熱路徑 syscall）、Python AclStream/AclEvent 包裝（ctypes + dlopen 快取）、補 split_with_sizes_copy.out / _chunk_cat.out / _foreach_copy_ 三個 FSDP2 必需運算元（CANN 無 aclnnForeachCopy，分解為逐張量 copy_ 走 aclnnInplaceCopy 消除 CPU 往返）。910 雙卡 CANN 9.0 實測：stream smoke、FlagCX collectives、DDP（loss 0.061/0.119）、FSDP2（4 grads/rank，loss 0.044/0.064）全部透過。

1.3 FlagFFT：摩爾執行緒 MUSA/muFFT 後端合入（#14）

來源：FlagFFT PR #14

  • MUSA 後端（8/14 20:29 開發、23:06 合入）：FlagFFT 經 MUSA driver API 適配摩爾執行緒 GPU，muFFT 作為參考 FFT oracle；BACKEND CMake 選項支援 CUDA/MUSA，libtriton_jit 同值配置；src/adaptor/backend/musa/ 完整實現 Memory/Stream/EventTimer/CudaGraph/device 查詢，device_architecture 返回 MUSA capability（如 31），triton_target 構建 musa:{arch}:32。
  • TLE codegen 特化：MTGPU LLVM 後端（FlagTree mthreads 3.6）對 vectorized 3D transpose v2、thread-local mixed four-step、TLE fused twiddle 三種模式暫存器分配失敗，回退標準 kernel。
  • MTT S5000（arch 31）實測：全部 1D/2D/3D 精度測試對 muFFT 透過。這是 FlagFFT 在 NVIDIA 之外的首個晶片後端，Fourier 庫補上”摩爾執行緒”拼圖。

1.4 FlagBLAS：Level-2 BLAS 運算元批次合入，Ascend/Hygon 多後端（#29）

來源：FlagBLAS PR #29、commits

  • PR #29（8/14 23:09 合入）：新增 Level-2 BLAS 運算元及其單元/精度測試，帶 Ascend / Hygon 多後端支援；配套 #34（測試檔案 8/15 00:44）、#40（benchmark logger 修復 + Level-2 benchmark shapes，8/15 22:02）、#41（清理 L1 benchmark、重構 swap benchmark，8/15 23:20）——Level-2 運算元 + 基準設施同步落地，FlagBLAS 從 L1 向 L2 擴充套件。
