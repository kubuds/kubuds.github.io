一、開源專案進展（GitHub 動態）

視窗總覽：org 內 52 個倉庫中 17 個在視窗內有推送；commit search 命中 87 條唯一視窗內提交（build-infra 55、FlagGems 19、FlagTree 4、Torch-FL 4、FlagGems-vllm 2、sglang-plugin-FL 1、FlagCX 1、FlagScale 1），另有 TransformerEngine-FL、Megatron-LM-FL 各 1 條。視窗頭條是海光（Hygon）DCU 在 FlagOS 的「訓練-通訊-推理」三線入列：FlagScale 增 BW1000 CI、FlagCX 增 DCU 適配與 CI、sglang-plugin-FL 增 HCU vendor 後端。本視窗主線可概括為「新廠商後端入列 + 既有驗證矩陣在 FlagGems 5.3.5 新版本線下的重驗」。

1.1 海光 Hygon 三線入列——FlagScale BW1000 CI、FlagCX DCU 適配、sglang-plugin-FL HCU vendor（視窗頭條）

來源：FlagScale #1272、FlagCX #541、sglang-plugin-FL #35（8/25 11:48-19:44 合入）

  • FlagScale（訓練）：#1272 為訓練工具鏈增加 Hygon BW1000 CI 支援（8/25 11:48 合入）——海光 DCU 進入 FlagScale 官方 CI 矩陣。
  • FlagCX（通訊庫）：#541 完成 Hygon DCU 適配與 CI workflow（8/25 12:32 合入）——跨晶片通訊庫補齊海光後端。
  • sglang-plugin-FL（推理）：#35 新增 HCU vendor（8/25 19:44 合入）——在 SGLang 0.5.11 上支援 DCU 平臺：廠商檢測與初始化、DCU 裝置管理、核心最佳化，已完成基礎推理與 serve 測試。

解讀：這是海光在 FlagOS 生態中從「FlagSparse DCU 測試健壯性」（8/22-24）走向「訓練、通訊、推理三線官方支援」的關鍵一跳。至此 FlagOS 成員單位中的 GPU/DCU 廠商（摩爾執行緒、燧原、天數智芯、沐曦、寒武紀、海光）幾乎全部進入官方 CI/後端矩陣，海光是其中最新完成三線覆蓋的一家。昨日報告觀察到「推理側驗證矩陣集體翻綠」向摩爾執行緒、沐曦擴散，本視窗再添海光，驗證正規化模板化的複製效應持續顯現。

  • 寒武紀（Cambricon）重驗：#538/#539 記錄 neuware4.7.2 app image tag 後，將 vllm 0.20.2 的 T 列單元格重置為 pending 以待 5.3.5 重驗；#561（8/26 07:53 合入）完成 neuware4.7.2 + flag_gems 5.3.5 驗證並關閉。
  • 沐曦（MetaX）：#533 記錄 maca3.7.2.1 的 triton scalar-return bug；#535 在 5.3.5 修復後關閉該記錄，並新增 maca3.8.1.3 驗證備註；#526 記錄 metax 後端 vllm app image tag 2.1.2-0.2.1_g3bc66eb.d20260825。

  • 天數智芯（Iluvatar）：#560 為 runtime 增加 filelock 依賴（8/25 23:15，次日 #562 回退——依賴已由映象提供）。
  • Megatron 側：#527/#528/#529/#530 記錄 megatron 全量 wheel 重建（0.17.1+fl.20260822）與 cambricon-neuware4.4.3 app image tag。

解讀：FlagGems 5.3.5 的推進引發一輪「全後端重驗」——寒武紀、沐曦兩家的 vllm 0.20.2 驗證單元格被重置後重新跑通，驗證矩陣在版本演進中保持可信。各廠商軟體棧版本（沐曦 maca3.8.1.3、燧原 TOPS 1.10.6）持續迭代，build-infra 作為「版本對齊中樞」的角色愈發清晰。

1.3 build-infra：驗證驅動工程硬化收官——並行、隔離、長超時（08-25）

來源：#531、#536、#540、#552、#556、#557、#563、#564

  • vllm 與 megatron 兩套 verify-driver 並行執行（#536）；每後端驗證執行相互隔離、避免併發衝突（#540）。
  • 驗證產物按 run_id 命名上傳（#531）；失敗單元格細節回顯到執行日誌（#540）；megatron 側用 NullTokenizer 避免 wget 下載、補 model-size 引數（#527/#529）。
  • 停止 verify-driver 自動重觸發迴圈（#557）、移除 PSUTIL_PREINSTALL 死程式碼（#556）、serve 就緒輪詢超時 300s 升至 900s（#563）、completion 請求超時 120s 升至 600s（#564）——長任務驗證不再因超時誤判失敗。

解讀：接續昨日「驗證驅動硬化」，本視窗將 E2E 驗證從「單機序列+固定超時」推進到「並行+隔離+長超時+可審計產物」的工程化形態。多後端矩陣規模擴大後，驗證基礎設施本身成為瓶頸，此輪硬化是為下一批新廠商（海光等）入列做的工程準備。

來源：鈦媒體（8/25）、中財網、東方財富

  • 發行節奏：8/28 初步詢價、9/1 刊登發行公告、9/2 網上網下申購；中信證券保薦，國泰海通、廣發證券聯席主承銷。

3.2 摩爾執行緒釋出 MTT S5000 Prefill-as-a-Service 白皮書（08-24 釋出/08-25 報道）

來源：IT之家/新浪科技（8/24）、鳳凰網（8/25）

  • 摩爾執行緒釋出《MTT S5000 Prefill-as-a-Service 技術白皮書》，提出 Prefill-Decode 異構解耦方案：Prefill（計算密集型）與 Decode（訪存密集型）分池部署，破解長上下文推理（數百 K 至 1M token）下的結構性算力錯配。
  • 實測資料：64K 上下文單機 Prefill 吞吐 95,920 tok/s；400K 極限長序列 TPM 達 2.6M tokens。面向 AI Agent、程式碼生成、超長文件分析場景，主打「單位 Token 基礎設施成本下降」。
  • 摩爾執行緒是 FlagOS 成員單位中驗證矩陣最完整的後端之一（8/24 報告：musa4.3.6/5.2.0 雙後端 F/T 雙路徑全過）；其在長上下文推理側的硬體打法與 FlagOS 的推理側驗證主線同頻。

3.3 沐曦：GPU 智算載荷太空在軌驗證獲外媒聚焦（08-25）

來源：DIGITIMES（8/25）、騰訊新聞（事件源，7/25）

  • DIGITIMES 8/25 報道「中國 GPU 應用延伸至太空」：搭載沐曦 GPU 智算載荷的「雲尖沐曦號」衛星（吉天星 A-04 星，三體計算星座）7/24 隨力箭一號遙十五入軌，正在軌驗證國產商用 GPU 在太空高能粒子輻射、真空熱迴圈下的工作可靠性——國產智算晶片從「地面驗證」到「在軌實戰」的關鍵跨越。事件發生於 7 月底，本視窗內獲國際產業媒體再度聚焦。
  • 沐曦官網動態：8/3 宣佈曦雲 C 系列 GPU Day 0 適配多模態生成模型 MiniMax H3；7/30 與上海 AI 實驗室共啟 KernelSwift 運算元創新大賽。沐曦在 FlagOS 側（MetaX）的 vllm 0.20.2 app image 與 maca3.8.1.3 驗證持續推進（見 1.2）。

四、總結

視窗主線：一、海光 Hygon DCU 三線入列（FlagScale BW1000 CI、FlagCX DCU 適配、sglang-plugin-FL HCU vendor），成為繼摩爾執行緒之後又一完成「訓練-通訊-推理」全棧官方覆蓋的成員單位；二、FlagGems 5.3.5 版本推進引發全後端重驗，寒武紀、沐曦驗證單元格重置後重跑透過，驗證矩陣在版本演進中保持可信；三、verify-driver 工程硬化收官（並行、隔離、長超時、可審計產物），為下一批新廠商入列鋪路；四、成員單位資本化與生態雙線並進——燧原科技啟動科創板發行（9/2 申購、募資 60 億），摩爾執行緒釋出 Prefill-as-a-Service 白皮書，沐曦太空智算載荷獲外媒聚焦。

下一觀察點：vllm-plugin-FL v0.3.0 正式版釋出（rc0 已出，Qwen3.5 相容待併入）；崑崙芯 decode scale 修復 #400 合入狀態；海光三線入列後首個驗證結果；FlagGems 5.3.5 在摩爾執行緒/燧原後端的重驗；Iluvatar（天數智芯）運算元適配完成度。

侷限性說明：提交數量與合入時間來自 commit search 與 repos/commits API（搜尋索引可能略滯後，個別倉庫 pushed_at 與主分支提交存在分支同步差異，已用 commits API 核驗）；vllm-plugin-FL 的視窗內推送主要為 PR 分支（#405 CI 分支切換），主分支無新功能合入；gnews 跳轉連結無法抓取正文，新聞側判斷依賴標題與多源交叉印證；燧原 IPO 募資額與持股比例為招股書口徑。
