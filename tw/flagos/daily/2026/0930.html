今日重點：Torch-FL v2.10.0 釋出落庫——FlagOS 2.2 清單最後一項補齊（09-29）

日期：2026-09-29　來源：Torch-FL v2.10.0 Release、community #124、community #125

09-28 日報中 2.2 清單（24 項）的「唯一留白」Torch-FL 在本視窗落庫——12:34 / 17:01 兩個候選標籤（v2.10.0rc1 / rc2）先行演練釋出流水線，18:17 建立 Release、18:20 正式釋出：

  • 釋出內容：torch-fl 是 FlagOS 的 PyTorch 裝置外掛——將逐運算元路由（原生廠商核心 / FlagGems 可移植核心 / CUDA 相容 boxing / CPU 兜底）統一到單一 flagos 裝置之下，同一 PyTorch 程式不改程式碼跨九類加速平臺執行：NVIDIA（A100 / H800）、昇騰（910C）、海光（BW1000）、沐曦（C550）、達摩院玄鐵（ZW810E）、摩爾執行緒（S5000）、燧原（S60）、崑崙芯（P800）與地平線系 BPU（s600）。
  • 版本與打包：自本版本起版本號跟隨所繫結 PyTorch 小版本線（本次 >=2.10,<2.11）；wheel 命名為 torch_fl-2.10.0+<sdk>（如 +cuda13.3 / +dtk2604 / +cann9.0.0），「一個標籤、每平臺一個製品」；wheel 自描述（compatibility.json 記錄平臺、核心集、構建 ABI 與 FlagTree / FlagGems / FlagCX 釘版），並隨附 torch-fl-preflight 校驗 CLI（免匯入 torch_fl 即可檢查環境）。
  • 驗證口徑：DDP 與 FSDP2 在主流卡全部透過；torch.compile 將 flagos 註冊為一等 inductor GPU 裝置（FlagTree 後端覆蓋六家、燧原走廠商 Triton、BPU 走板載編譯器）；profiler 對齊 CUPTI（含各家專用 tracer）；跨平臺基準（Qwen-Image-2.1，單卡 1024²、40 步）中 H100 原生 6.52 秒/圖對照 FlagOS H100 10.67、摩爾執行緒 S5000 14.87、海光 BW1000 23.59、昇騰 910C 24.94、沐曦 C550 31.61、達摩院玄鐵 ZW810E 37.44、燧原 S60 58.04（影象質量與 H100 對齊，CLIP-Score 偏差在 ±1.6% 內）；純 CPU Arm 路徑（Mac M5 Pro）取得對標 PyTorch CPU 1.74 倍的加速。
  • 三項新能力：新晶片後端接入 skill（本週期 T-Head ZW810E 與崑崙芯 P800 即按此路徑引入）、boxing 路徑的 FP8 / FP4 軟體模擬（無 FP8 硬體可用）、運算元級自動選路調優。
  • 邊界說明（釋出物自帶）：torch.compile 各後端仍為實驗特性；崑崙芯 P800 的 profiler / RNG 與 compile 尚在路線圖；flex_attention 本版未支援；BPU s600 僅作 torch.compile 圖裝置（eager 落在 CPU）。
  • 體量：自 v0.1.0 起累計 269 筆提交（62 特性 / 101 修復 / 11 效能 / 25 CI / 18 文件 / 16 測試 / 10 重構 / 4 構建），HuggingFace 100+ 模型在矩陣各板驗證。

判斷：至此 2.2 官方清單全部 24 項均有對應釋出物落庫（清單中 Torch-FL 條目的審查快照仍為 pending，屬預期，待下一修正批次重新整理）；「標籤 → Release → wheel → 映象」四類製品鏈在本視窗閉合。
