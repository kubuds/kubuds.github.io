四、總結與趨勢觀察

  • 平臺面從”有鍵”走到”可交付”：平頭哥 ZW810E PPU 在兩天內完成後端鍵、base 映象、runtime changelog 與狀態矩陣四處對齊，2.3.0 是該後端第一次有 runtime 交付。裝置只在阿里雲 PAI-DSW 映象裡可取、runner 無 GitHub 出口，這兩條約束決定了它的交付形態與其他後端不同，短期內 app 層仍是空白。
  • 運算元生產已進入批次節奏：單日 123 筆 FlagGems 合入、其中 87 個昇騰運算元由一人一小時內落庫，另有 20 個海光專用運算元排隊待審。KernelGen 把”寫運算元”變成了”稽核生成結果”，瓶頸從實現轉到評審與驗收——這解釋了為什麼在審 PR 數（269 筆）持續高於合入數。
  • 分發層在收斂：TransformerEngine-FL 用一份純 Python wheel 供給所有非 NVIDIA 廠商，FlagTree 的 deb 改為一後端一包、rpm 直接取已釋出 wheel，兩條動作指向同一目標——減少逐晶片重複構建，把差異留在配置裡。
  • 框架適配呈波浪形：vLLM 0.32.0 與 SGLang 0.5.18 的適配在視窗內集中出現，覆蓋平頭哥、天數、MUSA、崑崙芯、昇騰五家，但絕大多數仍在審。能否在 11-30 的 rc0 前合入，是 2.3 能否按矩陣交付的關鍵變數。
  • 2.3 進入收口倒計時：社群 2.3 時間表為 FEP 合入截止 11-13、特性凍結與 rc0 11-30、rc1 12-07、rc2 12-14、程式碼鎖 12-25、GA 12-30。本期無新 FEP 提交，11-06 那批六份（0164 至 0168、0170）仍為 Provisional Draft 且自述未跑 GPU 驗收，收口壓力集中在下週。
  • 風險與觀察點：平頭哥 app 層未接、海光 20 個運算元全在審、天數四條 CI 三處在審、競賽提交只入庫未出成績——四項都屬於”已有動作、未到驗收”，下週重點看合入率而非新增量。
