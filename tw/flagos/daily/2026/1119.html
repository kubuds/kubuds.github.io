日期：2026-11-17 ~ 2026-11-18　來源：雷峰網 · 環球網科技 · 投資家網

  • 事件：11 月 17 日，「國芯國模 自主生態」2026 清昴 AI 夥伴大會暨 Token 工廠年會上，北京智源人工智慧研究院與清昴智慧聯合釋出「國產 Token 工廠端到端推理最佳化方案」，基於眾智 FlagOS 上線商用 Token 工廠。雷峰網在 11-18 13:31 刊出報道，環球網與投資家網同日跟進。
  • 生態口徑：報道稱 FlagOS 生態已匯聚 21 家晶片企業、86 家生態夥伴，覆蓋 35 款 AI 晶片。9 大運算元庫累計沉澱 1454 個以上開源 Triton 運算元，其中近八百個在至少 5 款國產晶片上達到原生運算元 80% 以上效能。單個程式碼倉庫覆蓋 20 家廠商後端，過去半年多次做到新模型釋出當天 12 款晶片跑通。
  • 昇騰 910C 的賬：針對智譜 GLM-5.3 與 GLM-5.3-Flash，Prefill 側在 81920 輸入、16 併發下波次吞吐提升 3.41%，256K 輸入下 TTFT p50 下降 4.94%。Decode 側用 LI 量化寫回把動態量化、尺度轉換與 HBM 快取寫回合併進同一核心，910C 微基準從 18.03 微秒壓到 2.04 微秒。端到端 ITL 下降超過 10%，TPOT 降低 8% 以上。
  • 存量 910B：BAAI Token Hub 把 48 張 910B 組成 Prefill 與 Decode 分離的叢集，32 張卡分 4 個 Prefill 域、16 張卡分 8 個 Decode 域，跑 1M 上下文的 GLM-5.3-Flash 服務，已連續穩定兩週，TTFT P50 約 2.3 秒、TPOT P50 為 22 毫秒。跨 Prefill 域的 Prefix Cache 複用把命中率從 82.65% 提到 94.15%，複用階段首字時延中位數從 16.63 秒降到 3.10 秒。
  • 橫向對比：平頭哥 810E 上 FlagOS 2.2 讓 DeepSeek-V4.1-Flash 提升 77% 至 82%，16 路併發可用、最高 80 併發，單請求解碼 136.2 tok/s。海光 BW1100 上 GLM-5.3-Flash 提升 25% 以上，多併發下單路吞吐突破 80 TPS。
  • 口徑提示：環球網版本另稱 910C 上 GLM-5.3-Flash 整體輸出從二十多 TPS 升到五十多 TPS，邏輯服務吞吐為最佳化前 2.04 倍，單位算力成本比商業 API 計費低 19.4% 至 27.6%，並稱自動調優器把搜尋效率提高 298 倍。這些數字出自廠商與媒體口徑，未見第三方復現。

3.1 摩爾執行緒：Kimi K3.1 Pro 訓練適配，雙機 16 卡 400 步收斂（11-17~11-18）

日期：2026-11-17 ~ 2026-11-18　來源：第一財經 · 中國經營報轉載 · 與非網技術稿

  • 事件：月之暗面開源 2.8 萬億引數的 Kimi K3.1 Pro 後，摩爾執行緒基於 MTT S5000 智算卡與 MUSA 軟體棧完成訓練適配。構建了原生 FSDP2 多模態訓練路徑，打通模型載入、分片排程到梯度同步的全鏈路。第一財經與每經在 11-17 晚間首發，中國經營報 11-18 補充技術細節。
  • 驗證配置：裁剪訓練方案為 13 層語言主幹、16 專家（top-8 路由）與完整 27 層視覺塔，雙機共 16 張 MTT S5000，用 MedPix-VQA 圖文資料從隨機初始化開訓。16 個程序連續完成 400 次最佳化器更新，訓練 Loss 從 8.9365 收斂到 2.1802，驗證集 Loss 從 6.5297 降至 4.6873，視訊記憶體峰值 44.80 GiB。
  • 工程要點：補齊新增運算元的前向與梯度實現，把專家分發與歸併接入統一計算圖；並行上採用 FSDP2 與 EP 混合，配引數預取與梯度通訊排程；損失側用 Chunk Loss 分塊（塊長 256）控制大詞表視訊記憶體。
  • 口徑邊界：中國經營報明確指出訓練適配不等於該模型在該晶片上預訓練，二者需分開表述。摩爾執行緒此前已完成 021 科學基礎模型（2360 億引數）的從零訓練，並聯合智源完成具身大腦模型 RoboBrain 2.5 的全流程訓練。
  • 觀察：這條訊息的技術含量在「訓練適配」而非「推理可用」，且驗證規模是裁剪配置。它說明國產卡在萬億級模型上的工程量在推進，但離完整規模預訓練仍有距離。

3.2 沐曦與燧原：兩條換線背後的晶片與 SDK 口徑（11-18）

日期：2026-11-18　來源：base 層變更記錄目錄 · metax-maca3.10.1.11 · enflame-tops4.1.6

  • 晶片對應：沐曦新線對 C550，燧原兩條線分別對紫霄 C200（S60）與 L600。此前燧原兩條退役線在 11-17 已被換成成交接線，當日是新建線首次交付，屬同一輪換代的收尾。
  • 驅動策略：沐曦把驅動做成僅使用者態安裝，容器內不裝核心模組。這與 NVIDIA 的做法一致，好處是映象可無卡構建，代價是宿主機驅動版本必須與映象匹配。
  • SDK 元件面：燧原兩條線的元件清單完全一致，說明兩條線的差異只在晶片與棧版本，不在能力範圍。Triton GCU 均為 1.0.20261116，即 11 月 16 日的構建。
  • 目錄收斂：base 層與 runtime 層的 maca3.7.2.1 映象目錄已刪除，只留歷史變更記錄；燧原舊線的目錄同樣不在樹中。這種「刪目錄、留記錄」的做法讓構建矩陣保持乾淨，同時保住可追溯性。
  • 觀察：底座層的換代口徑是「一條線對應一張卡」。三家在同一天完成這件事，說明 2.3 週期的平臺清單已基本定型，接下來是 rc0 前的驗收。

四、總結

  • 底座層是當日主線：FlagOS 2.3 的 base 與 runtime 層一天內完成沐曦換線、燧原雙線首交、摩爾執行緒舊線清退，二十筆合入沒有一筆新功能。距 rc0 的 11-30 還有十二天，平臺清單正在收斂。
  • 運算元層在做兩件事：FlagAttention 一次進四個注意力變體，FlagGems-vllm 把融合運算元按後端逐個鋪開。前者擴能力邊界，後者補覆蓋密度。
  • 編譯器介面在換代：TLE pipeline 迭代器被移除，FlagGems、FlagGems-vllm、FlagAttention 三個庫同一天改到 tl.range。這是一次跨倉庫的介面對齊。
  • 量子線佔比升高：FlagQuantum 與 FlagQAI 合計 34 筆，接近當日合入量的四分之一。糾錯側在工程化，研究側在介面化。
  • 公開報道只有一條主線：智源與清昴智慧的 Token 工廠方案是唯一有實質內容的產業新聞，其餘為夥伴側回顧與舊聞轉載。元件級的版本訊息仍只走 GitHub。
  • 待觀察：摩爾執行緒舊線的 flagcx 行仍有一筆在審；海光 BW 上 FlagGems-vllm 0.2.0 基線啟用時禁用一個用例；2.3 的 GA 定在 12-30，中途還有 rc0、rc1、rc2 三個節點。
