今日重點：FlagQuantum 視窗 23 筆合入——分散式 MPS 訓練升入釋出認證（10-07 ~ 10-08）

日期：2026-10-07 ~ 2026-10-08　來源：FlagQuantum #587、#590、#591、#595

節後首期視窗，FlagQuantum（FlagOS 量子模擬與訓練元件）成為組織內最大增量：視窗內 76 筆提交、23 筆 PR 合入，從 10-07 上午連續推進至 10-08 上午，覆蓋釋出認證、效能派發、梯度與幾何量、糾錯解碼、原生熵匯出五條線：

  • 釋出認證落地（#587，10-08 07:16 合入）：分散式 MPS 釋出戰役收官——two_node_mps_training 能力行由 production_supported 升至 release_certified（本視窗唯一升格的能力行），認證建立在兩份透過釋出門禁的已簽署實測生產執行載荷之上；同時以實測理由記錄張量網路（TN）容量前提在當前修訂上的不可滿足性，並修復檢查流程發現的全部產出側缺陷（自合併基準 c7bba053 起含 28 筆非合併提交）。該戰役接續 #535 開啟的分散式 MPS / 張量網路釋出工作。
  • 效能派發批（#576 / #581 / #582 / #583）：statevector 公開派發擴充套件至 SV-014（SWAP）、SV-010（對角）與有界 SV-011（Pauli 旋轉），並完成有界 Pauli 旋轉派發重認證——SV 系列逐項「實現 + 證據」的推進方式延續。
  • 梯度與幾何量（#562 / #568 / #575 / #585 / #564 / #565）：新增 fq.jacobian / fq.jvp / fq.vjp（多輸出程式）；二階導（Hessian）以引數平移複用一階規則；新增 Fubini-Study 度規張量（中心差分實現，附反證表說明為何不復用算符移位規則）；N3-9 將「梯度方法 × 執行模式」的 30 對矩陣落成契約並在門禁複測。
  • QEC 與熵匯出（#590 / #591 / #592 / #589）：新增滑動視窗解碼器（flagquantum/qec/sliding_window.py，新增 772 行，按視窗讀取檢測器錯誤模型並逐窗解碼）；fq.vn_entropy 將 von Neumann 熵升為原生 Stable Core 匯出（根匯出預算 37 → 38）；四行 QEC 對齊項收斂；Quafu 遠端提交在缺少憑據時改為 fail-closed。
  • 質量收口（#595 / #597）：#595 補錄 16 筆未宣告的派發修訂；#597（開放）修復 CI 併發組缺陷——兩次連續合入會整批取消前一次校驗（#590 的 23/23 檢查曾被取消即屬該機制）。

判斷：FlagQuantum 的「釋出認證 + 契約化治理」雙軌正在成型——能力以契約檔案落檔、以門禁與實測載荷復證，其工程紀律與 FlagOS 主線釋出體系同構；視窗恰跨假期尾段與節後首日，該倉是長假期間仍保持高強度的開發線。

1.1 FlagQuantum：分散式 MPS 釋出認證落地——兩節點訓練升入 release_certified（10-08）

日期：2026-10-08　來源：FlagQuantum #587、#535

  • 認證內容：two_node_mps_training 由 production_supported 升至 release_certified，為能力表中唯一變動行；認證基於兩份透過釋出門禁（release gate）接受的已簽署 measured_production_run 實測生產執行載荷。
  • 容量記錄：張量網路容量前提按實測理由記錄為「在當前修訂上不可滿足」——把容量邊界顯式落檔，而非留作隱式約束。
  • 工程範圍：自合併基準 c7bba053 起含 28 筆非合併提交與 2 筆主線合併；同步修復本倉自檢流程發現的全部產出側缺陷。
  • 承接關係：戰役由 #535（10-06 合入）開啟，本次完成並向倉庫的釋出認證體系（release_certified 檔）交付首個分散式能力行。

  • 門批（#566 / #571）：有界可逆三位元門派發（#566）、稠密區域性雙位元矩陣派發（#571）——區域性門派發覆蓋面繼續加密。

1.4 FlagQuantum：QEC 與原生熵匯出——滑動視窗解碼器與 von Neumann 熵（10-08）
