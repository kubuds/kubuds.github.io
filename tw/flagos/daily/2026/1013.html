1.3 新公開倉庫 Trident：實驗性 MLIR/LLVM 編譯橋（10-12）

日期：2026-10-12　來源：flagos-ai/Trident · README · 提交記錄

  • 定位：Trident 是一個實驗性編譯橋——把包含 Triton/Torch 風格計算的 Python 函式編譯為 MLIR/LLVM，再經 tvm_ffi 執行；核心為 C++/MLIR（CMake 構建、LLVM/MLIR 作為外部工程引入），Python 側提供 trident.jit 與 trident.compile 入口，示例覆蓋 add / attn / mm / softmax 等 ATen 運算元下落，依賴 apache-tvm-ffi 與 torch>=2.10。
  • 時間線：倉庫於 10-12 16:47（北京時間）在組織內建立並公開，master 分支提交歷史可溯至 5 月中旬、累計 274 筆；視窗內 2 筆——「refactor: unify FX and Triton imports around TVM FFI」（10-12 23:10）與「test: reorganize coverage and check e2e CUDA memory leaks」（10-13 00:50）。
  • 觀察：專案在 7 月完成從 torch-mlir 匯入向 FX 直連 TVM FFI 的遷移，形態上屬於面向多芯統一接入的”前端編譯橋”探索，與 FlagTree 的統一編譯器路線形成呼應；後續走向（是否與 TLE / FlagMega 線合流）值得跟蹤。

3. vLLM 0.28 適配批進入落點期：天數 / 昇騰首批合入，摩爾執行緒（#575 跨日高頻更新）、玄鐵（#574）、燧原 S60（#582）在審——上期”五線仍在審”的觀察點在一天內兌現兩線，剩餘線仍處移動狀態；這批適配完成後，各廠商推理棧將統一到 0.28 基線，為大會期間的端到端演示提供版本底座。

4. 開發線”開新面”訊號密集：FlagGems 開出 5.5 開發線（v5.5.0.dev0）、FlagTree 天數構建線升至 0.7.1a1、組織新增 Trident 編譯橋倉庫——三者在 24 小時內同窗出現，疊加 FlagMega 在 BI-V150 上的 token 級量化最佳化與 TileIR 13.4 升級（#1352）在審，編譯與運算元棧正處於”上一交付週期收尾 + 下一週期佈局”的疊加態。

5. 下一觀察點：大會（10-17 / 18）現場釋出（FlagOS 2.2、量智雲平臺與大會後的對外物料）；FlagQuantum 0.3.0 正式版（rc 三連後的收口節奏）；Torch-FL #504 合入與崑崙芯 CI 首綠；vLLM 0.28 剩餘三線（MUSA / 玄鐵 / S60）的合入順序；FlagMega 分支是否轉 PR 併入主線；2.3 週期 FEP 與里程碑推進。
