FlagOS 每日動態報告（2026-08-14）

2026-08-14 苦芽科技

調研視窗：過去 24 小時（2026-08-13 10:19 ~ 2026-08-14 10:19 北京時間） 信源：GitHub（org: flagos-ai）、Google News 聚合（中英文）、HN、智源社群等（詳見附錄）

一、開源專案進展（GitHub 動態）

視窗總覽：org 內 52 個倉庫中 16 個在視窗內有推送，commit search 命中 46 條視窗內提交，無正式 Release（距 FlagOS 2.1 已 7 周餘）。本視窗三大主線：FlagAttention 多後端 runtime 架構落地（一次性鋪開 8 個晶片後端）、PyTorch-Plugin-FL 以 Torch-FL 名義完成 org 級更名整合、FlagGems 持續高頻（19 條提交，KernelGen NVIDIA 運算元與 KMCompiler 昇騰/天數智芯運算元雙線推進）。

1.1 FlagAttention：多後端 runtime 落地，8 個晶片後端一次鋪開

來源：FlagAttention PR #48、FlagAttention commits

  • “add multi backends”（#48，8 月 13 日 12:18 合入）：新增 src/flag_attn/runtime/backend/ 統一後端抽象，一次性建立 8 個後端包——_ascend（昇騰）、_enflame（燧原）、_hygon（海光）、_iluvatar（天數智芯）、_metax 與 _mthreads（沐曦兩系）、_nvidia。FlagAttention 從 NVIDIA 單後端 Triton attention 運算元庫走向 FlagOS 全晶片 attention 運算元庫，與 FlagGems 的多後端模式對齊。這是本視窗最重要的架構事件，後端清單與 FlagOS 成員單位晶片幾乎一一對應。
  • 配套提交：08-13 02:55-04:07（UTC）的 “add multi backends / add copy right / fix” 三條為 #48 的開發過程提交。

1.2 Torch-FL：org 級更名整合（PyTorch-Plugin-FL → Torch-FL）

來源：.github commits、Torch-FL commits

  • org 官方 README（英文 + 中文）將 PyTorch-Plugin-FL 全部替換為 Torch-FL（8 月 13 日 18:44/18:45 替換、21:25 修正連結）：PyTorch-Plugin-FL 正式以 Torch-FL 名義進入 org 主線（Torch-FL 倉庫 README 的 CI badge 仍指向舊倉庫名，說明遷移尚在進行中）。Torch-FL 定位為 FlagOS 的 PyTorch 裝置外掛，暴露統一 flagos device，按運算元路由到可複用原生 kernel、編譯器 kernel、廠商原生實現與顯式 CPU fallback。
  • 修復 #99（14:54）：非全域性 swap 模式下保留 module parameters；
  • docs #101（14:56）：新增實測運算元支援報告（measured operator support report）。

1.3 FlagGems：19 條提交，KernelGen NVIDIA + KMCompiler 昇騰/天數智芯雙線

來源：FlagGems commits

  • KernelGen NVIDIA 運算元新增（8 月 13 日 13:06-14:22）：max_pool3d_with_indices_backward（#5264）、ormqr（#5252）、heaviside（#5120）、leaky_relu_backward（#5145）、_scaled_dot_product_attention_math（#5168）、_native_batch_norm_legit_no_training（#5243）；另有 hardswish（#5139）、absolute_（#5187）、arctanh（#4818）三個運算元從生成區 “Move to ops” 正式入冊——KernelGen 生成運算元進入正式維護列表的收尾動作；
  • KMCompiler 運算元（8 月 14 日 10:19-10:22）：linalg_cross（#4850）、linalg_solve_triangular（#5201）新增；昇騰 pairwise_distance 後端 + 天數智芯 Iluvatar CPU 引用錯誤修復（#5394）——昇騰與天數智芯雙後端同條提交推進；
  • flagtree 依賴正式化：#5444 Bump flagtree version for NVIDIA（15:26）；#5433 昇騰 backends.yaml 更新 flagtree ascend whl 至 0.6.1（17:13）——昨日”FlagTree wheel 分發體系”判斷兌現：FlagTree wheel（含昇騰 0.6.1）已成為 FlagGems 各後端配置的正式依賴元件；
  • 修復與工程：empty 零元素處理（#5438）、nested_view_from_buffer_copy 精度修復（#5324）、xor/ixor 拆分並註冊（#5283）、cat cpp wrapper 路徑與 dtype 修復 + rwkv_mm_sparsity 精度（#5388）；fused_marlin_moe 核心按精度方案改名並拆分基準（#5437，10:28）。

四、總結

  1. FlagAttention 多後端 runtime 落地：#48 一次合入 8 個晶片後端包（昇騰/燧原/海光/天數智芯/沐曦×2/NVIDIA），attention 運算元庫全晶片化，是 FlagOS 多晶片架構的關鍵一步。
  2. Torch-FL 官方更名整合：org README 全面替換 PyTorch-Plugin-FL 為 Torch-FL，”flagos device”單一裝置抽象成為 PyTorch 外掛層的統一入口。
  3. FlagGems 雙線高頻：KernelGen NVIDIA 運算元 6 新增 + 3 入冊、KMCompiler 昇騰/天數智芯運算元 3 連發；flagtree wheel（NVIDIA bump + 昇騰 0.6.1）成為各後端正式依賴，昨日”wheel 分發體系”判斷兌現。
  4. 沐曦 MC550 持續深入：FlagGems-vllm Fused MoE 新增 mthreads 後端並調優 MC550，編譯（FlagTree METAX 特化）、分發（MACA wheel）、運算元（vLLM 場景）三線齊頭。
  5. 新聞頭條：Qwen3.8-2.4T-A95B 開源 + FlagOS 社群多晶片適配（新浪財經口徑），延續”模型開源即快速多晶片適配”的 FlagOS 生態節奏；成員單位海光中報、天數智芯扭虧為經營面亮點。
  6. 釋出側：無正式 Release；build-infra packaging 重構 + FlagGems-vllm v0.1.1-rc 穩定線，元件化版本釋出仍在醞釀（距 FlagOS 2.1 已 7 周餘）。
