1.1 build-infra：昇騰 vllm 0.20.2 雙編譯器 F/T E2E 全透過（視窗頭條）

來源：PR #496（8/24 08:39 合入）

  • 昇騰成為 vllm 0.20.2 驗證矩陣雙編譯器全透過後端：在 cann8.5.0 @ hw26 與 cann9.0.0 @ hw25 兩個昇騰後端上，FlagTree 與 Triton 兩條編譯路徑的 serve + inference（Qwen3-4B）全部透過，0.20.2 矩陣單元格由未驗證翻為已驗證，deps_app 置位、app 變為可構建（launch_docs 同步開啟）。
  • 配套變更：status_matrix.vllm0.20.2.yaml 翻轉昇騰 F/T 單元、configs.yaml 為兩個昇騰後端增加 vllm0.20.2 deps_app key、report §2.8 記錄雙路徑完成並新增 pow_scalar 黑名單條目（驗證矩陣經 render_status_matrix.py 重新生成）。

解讀：8/21 昇騰 CANN 8.5.0 訓練側（megatron）雙編譯器 E2E 之後，本次補齊推理側（vllm）雙後端雙路徑驗證——昇騰成為繼 NVIDIA、崑崙芯之後第三個在 vllm 0.20.2 矩陣完成雙編譯器驗證的後端，且覆蓋 cann 8.5/9.0 兩個 toolchain 代際。”F/T 雙路徑驗證正規化”的晶片覆蓋序列（NVIDIA → 崑崙芯 → 昇騰）在推理側成型。

1.2 build-infra：status-matrix 結構化驗證跟蹤體系上線

來源：PR #485（8/23 14:16 合入）、#494（8/23 21:10 合入）、#495（8/23 21:48 合入）

  • #485：驗證矩陣 YAML 化。將各 app 的驗證矩陣表格從 markdown 抽為結構化 status_matrix.<app>.yaml（每個 app 一份，置於 packaging/<component>/），由 scripts/render_status_matrix.py 渲染回人類可讀的 markdown（verification + facility 標記塊），--check 模式檢測漂移；首批落地 4 份 YAML：megatron_training、megatron_rl、vllm0.20.2、vllm0.24.0（0.20.2 與 0.24.0 為兩個獨立 app，命名與映象倉 app 段一致、無連字元）；後端級上游 PR 在 backends.<backend>.prs 欄位跟蹤。配套 .githooks/pre-commit + 安裝指令碼做本地防漂移守衛。
  • #494：image_tag 單一發布源。矩陣中 image_tag 取代 harbor_repo 成為已釋出映象 tag 的唯一事實來源。
  • #495：釋出 tag 自動記錄。app-image 釋出後自動把 published image tag 寫回 status matrix——釋出與驗證狀態閉環。

解讀：這是本視窗最值得關注的基礎設施訊號——驗證矩陣從”文件記錄”升級為”程式化資料 + 自動渲染 + 防漂移守衛 + 釋出自動回寫”，配合昨日 #475（megatron-train launcher 入 app image），build-infra 正把”誰能跑、跑到什麼程度”變成機器可審計的狀態機。多晶片驗證的規模化（後端數持續增加）倒逼驗證管理工程化。

1.3 build-infra：vllm 產線化——崑崙芯 0.24.0 雙編譯器 verified + NVIDIA 0.20.2 empty-mode + vllm-plugin-FL 純 Python 構建

來源：#479、#482、#484、#486、#487（8/23 11:31-17:03）、#488、#489、#490、#492（8/23 17:42-20:32）

  • 崑崙芯升級 vllm 0.24.0 app-image 線：昨日視窗崑崙芯剛在 0.20.2 完成雙編譯器 E2E（#476），本視窗即推進到 0.24.0 新線——8/23 11:31 可行性審計（#479，report §13）→ 12:20 加入 0.24.0 matrix 條目（#482）→ 13:36 app-image serve E2E 記錄（#484）→ 14:11 triton-path serve E2E 記錄（#486）→ 17:03 雙編譯器 E2E 標記 verified（#487）。崑崙芯 0.24.0 雙路徑驗證全綠。
  • NVIDIA 0.20.2 empty-mode + cuda13.3 雙編譯器 verified：17:42 NVIDIA 統一到 empty-mode wheel 構建（#488）→ 19:35 記錄 0.20.2 empty-mode app-image E2E（#490）→ 19:40 增加 vllm0.20.2 deps_app key for nvidia-cuda13.3（#491）→ 20:32 nvidia-cuda13.3 0.20.2 雙編譯器標記 verified（#492）。
  • vllm-plugin-FL 純 Python 構建統一（#489，18:38）：所有後端改走 pure-python wheel 構建——依賴從 wheel 內建改為 deps_app 執行時裝配，是 #488/#491 的構建體系統一動作。

1.4 Torch-FL：CUDA-boxing RNG 生成器翻譯修復

來源：commit #147（8/24 10:11 合入）

  • fix: translate flagos generators in CUDA-boxing RNG ops：修復 CUDA-boxing 路徑下 RNG 運算元未翻譯 FlagOS 生成器的問題——此前對 FlagOS 生成器的處理與 CUDA 原生生成器不一致，導致跨後端 RNG 語義偏差。
