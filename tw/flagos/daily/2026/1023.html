日期：2026-10-22　來源：FlagQuantum 提交 · PR #700 · PR #707 · PR #714

  • Core 前端（#700，22 檔案，+2198/−16）：原生 Rydberg 控制不再借用線路適配，而是由 Core 直接在 ProgramRecord 上提供前端。記錄增加型別化的 context 與 control 欄位，既有驗證器只接受一個物理 profile 並複用 CFG/SSA 檢查；連續路徑安全用編碼座標上的精確算術判定，與數值演化解耦；源編碼複用既有標量編解碼器，原生專用的嚴格欄位與規範檢查在任何張量解碼之前就拒絕非法輸入。未引入新的 IR 層級、繫結器、求解器、登錄檔或根匯出。
  • 使用者 API：RydbergProgram 以原子、位點、長度與時間單位、C6、損耗率、最小間距、傳輸通道與驅動通道構造，提供 move、pulse、to_ir 三個動作，示例輸出原子標識 ('a','b')、維度 (3,3)、受控位置 (3.0,0.0) 與存活運算元形狀 (9,9)。PR 明確寫明「受控位置不代表物理存在」。
  • Simulation（#707，19 檔案，+1488/−188）：原生 Rydberg 程式可以走既有的 Lindblad 計劃、執行與初始密度伴隨入口，使用者宣告原子、線性傳輸、脈衝與吸收損耗，Simulation 自行裝配區間矩陣；plan 1.7 密封為恰好七個外層欄位，執行時不重新編譯源。實驗性數值路徑為 CPU-only、一至兩個 g/r/lost 角色，更大規模在指數級記憶體分配前拒絕；幾何是施加線性路徑的區間中點近似，網格收斂證據與求解器精度分開記錄。
  • Examples（#714，3 檔案，+217）：訓練兩個脈衝幅度繫結並讓原子對移動，40 步、128 區間的實測輸出為：無條件 RR 由 0.0431 升至 0.1228，存活條件 RR 0.1500，no-flag 選擇 RR 0.1439，精確數值回放成立。本地預設全量 14,584 透過、167 跳過，約 518 秒；首輪 64 區間曾在 2.28e-10 上失敗一個梯度，細化到 128 區間後透過且未改求解器與斷言。

四、總結與趨勢觀察

  • 產能結構：FlagGems 一家吃掉 56% 合入，量子棧吃掉 40% 提交，構建與執行時各一成。合入量創近一週新高而提交量下降，說明當日的主旋律是消化積壓而非擴張，這與 10-20、10-21 連續兩日大額合入之後的狀態一致。
  • 2.3 週期的第一格：FEP-0140 與 FEP-0141 在 10-21 合入，10-22 海光就把 vLLM 0.28.0 與 SGLang 0.5.18 兩個版本同時落地。這條鏈路從「把矩陣寫進文件」到「第一條實測透過」只用了一天，是本季最快的需求到證據閉環。剩下的九家與兩條版本線是此後六週的主工作量。
  • 構建層收斂：崑崙芯成為 FlagTree 第七後端、flagcx 0.14.0 釘到二十個後端、optest 變成可安裝包。三者合起來的效果是「換後端時不再改安裝指令碼」，這比任何單點效能提升都更能決定 2.3 的交付速度。
  • 可觀測性成為新短板：清微第一次有裝置時間線，崑崙芯跨卡複製此前一直靜默失敗。這兩件事提示，多後端在「能跑」之後的第一道坎是可觀測與可復現，而不是更快；過去兩週的測試移植與用例契約改造（lukatao 一人 61 筆）正是同一判斷的另一種表達。
  • 風險點一：FlagQuantum 的 20 筆合入全部由單一賬號完成，且新增的原生 Rydberg 路徑只覆蓋 CPU、一至兩個角色。物理語義的驗證依賴同一批人寫測試與實現，外部無法獨立複核；提案 083（終端取樣）尚未批准，若快速推進，會同時改動 Runtime、測量結果與隨機源三處。
  • 風險點二：燧原 #7077 這類「整批更新」缺少可核對明細，26 檔案與 +3520 行無法對應到具體運算元與具體收益；崑崙芯融合 MoE 的三項效能又以替代基線測出。兩者都會讓後續的跨廠商對比失真。
  • 觀察點：vLLM 0.28 的下一個廠商（清微或沐曦）是否複用海光的 empty 後端模板；FlagTree 0.7.1 開發構建（10-20 的 0.7.1.dev1）是否在 2.3 前轉正式版；TransformerEngine-FL 的三筆 NPU PR 能否在週末前合入；地平線與寒武紀的靜默是否延續到下週週報。
