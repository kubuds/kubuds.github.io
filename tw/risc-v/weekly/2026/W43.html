二、指令集與架構生態

RVA23：一週之內完成「規範—核心—發行版—晶片—作業系統」的閉環

  • 可判定性：Linux 7.3 用 hwprobe 暴露 RVA23U64 基礎行為，使用者態可直接判斷機器是否符合 RVA23，這是從「編譯期猜」到「執行時可查」的關鍵一步；同版補齊計數器委派、QoS 標識與 KVM 的 Svadu、影子棧（Zicfiss／Zicfilp）支援。
  • 落到產品：進迭時空 V100 按 RVA23／伺服器 SoC／伺服器平臺／BRS／安全模型五項規範設計並透過 BRS 全項測試；超睿科技 UR-CP400 符合 RVA23 並支援 RVV 1.0；K3 被表述為全球首顆符合 RVA23 規範並規模量產交付的 RISC-V AI CPU。
  • 落到作業系統：RISE 的 Android 17 構建明確以 RVA23 硬體為目標，給出鎖定 manifest 與校驗和，成為「移動作業系統 + 應用處理器規範」這一最苛刻組合的第一份公共基線。
  • 判斷：三條線在同一周內互相對齊，說明 RVA23 已從規範文字轉為可採購、可安裝、可復現的工程事實；下一步的觀察點是發行版側的 profile 分級位與 glibc 逐級回退是否隨核心推進落地。
  • 來源：Kernel Newbies（Linux 7.3）、RISE（Android 17 on RVA23）、Phoronix（SpacemiT V100）、搜狐（超睿 UR-CP400）

香山：效能引數之外，本週重心明顯轉向特權態、驗證與 CI

  • 10-19 期（含 10-16 至 10-18 覆蓋）：主倉 #6730 將重排序緩衝（ROB）擴大至 160 項，屬亂序執行視窗的引數級效能調整；GEM5（xs-dev）#1231 為兩執行緒 SpMT 增加中間端資源劃分；NEMU #1246 新增昆明湖 V2（kmhv2）配置並對齊 V2／V3 公共修復、#1252 降低 DiffTest 儲存 CRC 校驗開銷。
  • 10-20：XSCache #36 把 CoupledL2 的 L2 SRAM 按 set 與 bank 拆分並對預取准入限流，指向末級快取頻寬爭用與預取汙染；主倉 #6738 提升 XSCache 子模組版本；GEM5 #1241 在 store／AMO 傳送失敗時跳過 load 流水線的 replay 標記。
  • 10-22：主倉 #6692 補上 mnret 與 dret 兩條特權返回指令的譯碼、#6729 修正 ROB 重定向起始索引、#6696 README 增加 Dashboard 與 star 歷史連結。
  • 10-23（上次日報截點之後，經 Atom 複核）：主倉 #6742 讓 StoreUnit 在 tval 中上報指標掩碼後的地址、#6756 更新 checkpoint、#6701 統一 CI 的 PERF_HOME 與 WAVE_HOME 並快取構建好的 emu；NEMU #1260 移除 Copilot review 工作流。
  • 模擬與驗證：GEM5 於 10-23 合入 #1189 Hybrid CROB 支援與 #1257 SMT LSQ DynamicBorrowing 捐贈者檢測修復及統計，10-22 合入 #1214 在延遲翻譯前初始化訪存大小；difftest 於 10-23 一天內合入 #991 併發暫存器寫入雜湊、#996 避免回拷成功的 CUDA 結果、#995 補充 BOOM DiffTest 整合文件及 CUDA 驗證吞吐最佳化。
  • 判斷：本週香山沒有釋出新的效能數字，提交集中在特權態譯碼、重定向索引、tval 上報、CI 與 DiffTest 基建——這是開源核從「跑分」走向「可交付」階段的典型形態。來源：XiangShan、XSCache、NEMU、difftest

CORE-V：CVA6 主幹收口，CVW 驗證面擴容

  • 治理層變化（10-23）：openhwfoundation/cva6 提交 #3664「master made read-only」，README 明確寫明 master 分支不再接受新 PR、僅保留供繼續整合舊版本的使用者使用，新貢獻一律轉向已成為預設分支的 main。這是一次分支治理收口，對下游整合方（尤其仍跟 master 的專案）構成明確的遷移訊號。
  • 驗證平臺：CVW（CORE-V Wally）本週合入 3 筆——新增 QM Tech K7 開發板支援（PR #1601，FPGA 板級適配繼續擴容）、加入 hptwReservedAD 迴歸測試（PR #1993）覆蓋保留葉 PTE 的 A/D 位更新行為；10-22 合入 jalr 在 Table I.1 的勘誤條目（PR #1996）；10-23 合併 Sail 0.16 升級（PR #1995），此前已把 riscv-arch-test 對齊至 act4 2b0415eef。
  • 判斷：對以形式化驗證與迴歸套件見長的 CORE-V 而言，本週的動作是「換主幹 + 補邊界用例 + 升級形式化模型」，比功能新增更能反映驗證成熟度。來源：cva6 #3664、cvw

工具鏈與模擬：達摩院的社群貢獻與樂鑫的模擬器一致性

  • 達摩院玄鐵（峰會口徑）：GCC 社群 RISC-V 相關貢獻量全球第二，為處理器帶來 10% 以上典型效能提升；OpenJDK 社群過半數 RISC-V 程式碼來自達摩院；在 RISC-V 國際基金會參與 CSC 認證基線建設並開源 2796 個測試用例；C950 首次實現 RISC-V 與伺服器 Java 深度適配，效能提升 30%。
  • 樂鑫 esp-emu 0.50.0（10-20）：ESP32-P4 與 S31 的單精度融合乘加改走宿主直通路徑，約 3 倍加速，sinf、expf、powf 等數學函式隨之受益且標誌位保持一致；P4 的 PSRAM 視窗改為跟隨 PSRAM MMU，執行時重對映外部記憶體視窗的韌體不再讀到全零或非法指令 trap；C3 與 S3 的 BLE 發射功率 API 修復 Load access fault；P4 對 rev 0.x／1.x 韌體的啟動在模擬器側提前拒絕。
  • 判斷：模擬器與矽片行為對齊到單條指令級，是 RISC-V 端側韌體 CI 擺脫真機依賴的前提；這類工作不產生新聞熱度，但決定生態的迭代速度。來源：GCC/OpenJDK 口徑見玄鐵峰會報道、esp-emu 0.50.0

三、作業系統與發行版

openRuyi：一週逾百筆提交，補齊層次從工具鏈一路上移到執行時與雲原生

  • 主倉節奏：10-19 期 15 筆（dpdk 回移 RISC-V 的 lpm 與 fib 查詢最佳化、spdk 升至 26.09，Rust 生態包成組更新至 regex 1.13.1／regex-automata 0.4.18）；10-20 40 筆（minio 系列、Prometheus 與 prom2json、IBM sarama、gobwas-ws、xdg-scram，另加 uwsgi 與 dropwatch 兩個新包）；10-22 凌晨 20 筆（全部為 rust-uv-* 0.0.96 系列依賴，服務 uv 這一 Rust 編寫的 Python 包管理器）；10-22 再一批 20 筆（python 3.14.9、nodejs 24.22.1、openjdk-17 17.0.21.9、openjdk-21 21.0.13.9、nginx 1.31.8、python-pillow 13.0.0、rdma-core 65.0，多筆標註 security-fixes）；10-23 約 20 筆（go-github-gobuffalo-* 系列、go-gopkg-gorp.v1、go-howett-plist、go-github-ziutek-mymysql 等 Go 生態包成批入庫）。五個工作日累計逾 110 筆。
  • 補齊順序：Go 雲原生元件 → uv 的 Rust 依賴 → Python／Node／Java 執行時主版本 → Go 生態軟體包。帶 security-fixes 標記的提交成批出現，說明安全更新已進入流程化通道，而不是零散發補丁。
  • 雙源核查結論：官網新聞頁最新公告仍為 2026.09 版本（9 月 30 日釋出，改進 RVA23 支援、擴充雲與儲存軟體棧、升級 Go 1.27 構建環境），本週無新版本釋出公告；組織內 lookout、kiwi-image、TakoPack、homepage 同期有推送。
  • 判斷：openRuyi 本週實際回答的是「RISC-V 伺服器能不能承接真實業務」——minio、Prometheus、sarama 決定資料中心側可用性，uv 與 Python／Node／Java 執行時決定開發者能否日常使用。來源：openRuyi 主倉、openRuyi 官網新聞

核心：7.3 釋出與 7.4 的效能回灌

  • Linux 7.3（10-18）：除本週要聞所列 RISC-V 內容外，還補齊 Smcsrind／Sscsrind、Zicclsm、Ziccamoa、Ziccif、Ziccrse、Za64rs 等擴充套件的識別與列舉，靜態計算 alternative 段邊界修補 vDSO 相容，並進一步移除 xip 支援。
  • Linux 7.4 加密庫（10-21）：Google 核心工程師 Eric Biggers 的加密子系統效能工作已合入，把 x86／x86_64 與 RISC-V 的 AES 各模式最佳化實現遷移進 lib/crypto，覆蓋 ECB、CBC、CBC-CTS、CTR、XCTR、XTS 六種模式；RISC-V 側為基於向量與加密擴充套件的加速實現。附帶收益是清理掉大量重複的膠水程式碼，同批還包括 SPARC64 的 AES-XTS 最佳化。
  • 發行版核心層：meta-riscv 視窗內 14 筆提交，linux-mainline 由 7.2.10 升至 7.2.11，riscv-common 調整為首選主線 Linux 與 U-Boot、減少對廠商 BSP 分支的依賴，文件補齊進迭時空 K3 Pico-ITX、K3 COM260 與 LicheePi-4A 的啟動與 UART 說明。發行版構建層向主線收斂，與 openRuyi、RevyOS 近期的平臺收攏動作同向。來源：Kernel Newbies、Phoronix、meta-riscv

RevyOS 與其他發行版

  • RevyOS：revyos/linux 7.3.y 分支 10-19 的批次配置提交與 10-16 已收錄的 20 筆批次內容一致（K3／K1／EIC7700／linuxboot／CI），判定為重推而非新增；組織內 runner 倉庫同期有推送。本週無新增平臺支援條目。
  • openEuler：本週五期日報均未收錄 openEuler 側新版本或 RISC-V SIG 動態，故本節不含其內容；V100 的發行版相容清單中列出 openEuler，屬廠商口徑而非本週實測。
  • Android on RVA23：RISE 的 RP024（見本週要聞）是本週發行版維度最具結構性的進展——從「又一次移植」變成「帶 manifest、校驗和、燒寫工具與 Board Farm 迴歸的公共基線」，第二階段將把構建與測試自動化。
  • 社群專案：社群專案 esp32-s31-linux 在樂鑫 ESP32-S31（雙核 RV32、320 MHz、512 KB SRAM、16 MB 八線 PSRAM）上跑通上游 Linux 7.3 與 OpenSBI 1.9，構建鏈為 ESP ROM → ESP-IDF 二階段 → loader → OpenSBI → Linux → Buildroot 根檔案系統；可用使用者態含 LCD shell、wpa_supplicant、BlueZ、SSH、USB 鍵鼠與 U 盤、vim、gdb、strace、MicroPython 與 links。技術看點在於該 SoC 無 PLIC、無 Zicbom、無一致 DMA，專案以數百行程式碼給出替代實現。該專案不構成產品路徑，但是檢驗工具鏈、核心移植與驅動成熟度的極端用例。來源：revyos/linux、esp32-s31-linux

伺服器與資料中心 CPU：一週內五款產品同臺

  • 判斷：政策的兩個抓手（標準體系、開源社群）與 RISC-V 側長期缺位的軟體與介面規範正好對應；具身智慧是本週唯一同時具備政策、資本與出貨三層證據的方向。來源：新浪科技（工信部）、證券時報、大河財立方（智元）

國際社群

  • riscv.org：刊出 CERN 團隊（Benoît Denkinger 等）的峰會海報論文，介紹在 SOCRATES（System-on-Chip Radiation-Tolerant Ecosystem）專案下開發的 SoCMake，用於模組化構建面向高能物理的抗輻射 RISC-V SoC；配套原型晶片 TriglaV 是全抗輻射 ASIC，面向 LHC 探測器前端讀出等強輻射環境。技術組合為三模冗餘、加固互連與記憶體保護，同樣適用於汽車與工業控制的安全關鍵場景。
  • 邊界：國際媒體對本週伺服器產品的集中報道，多數為峰會後續綜述，與國內已報道事項重合；對「適配成本是真正門檻」的判斷來自受訪行業分析人士，觀點不代表產業共識。來源：riscv.org 部落格、Global Times

六、趨勢觀察

  • 伺服器 RISC-V 的重心從「釋出」轉向「適配」：本週 V100、LX500、珠峰200、UR-CP400 集中亮相，證明硬體形態已經齊備；峰會之後的第一個動作卻是科華資料與進迭時空的基礎設施協同簽約，境外媒體的分析也把適配與維護成本列為客戶遷移的決定性變數。雲端下一程的勝負手不在釋出會，而在機房與軟體棧。
  • 開源核第一次進入可銷售的商用伺服器晶片：V100 的 46 核裡有 6 個香山昆明湖 V2R2，開源高效能核不再只是學術與驗證物件，而是以 IP 形式進入資料中心產品。同一周 OpenHW 把 CVA6 的 master 轉只讀、以 main 為預設分支，開源核專案的治理與產品化同時在收口——一進一出，構成「開源核供給能力」的兩面。
  • 伺服器 IP 供給正在分化為三條路徑：Qualcomm 十個月內收進 Ventana 與 Akeana（大廠內部資產），國內把開源核裝進商用晶片（V100），奕斯偉選擇「自研核 + 外部 IP 聯盟」（與 SiFive 的 MOU 升級）。三條路徑都在回答同一個問題：伺服器級 RISC-V 的 IP 從哪來。
  • 效能路線繞開製程，轉向架構與系統：資料流（睿芯、中科通量）、統一記憶體與 CXL（藍芯）、SMT 與 AME 矩陣擴充套件（達摩院）、可重構陣列（Ubitium）——在先進製程受限的前提下，這些是靠設計拿回效能的手段。達摩院給 C950A 定的「5 倍」目標，本質是同一邏輯的延伸。
  • 發行版的補齊層次一週內上移了兩級：openRuyi 從工具鏈與核心包，推進到雲原生中介軟體（minio、Prometheus、sarama），再到 Python／Node／Java 執行時與 Go 生態；安全修復開始帶 security-fixes 標記成批走流程。RISC-V 發行版正在從「能裝」走向「敢用於生產」，但官網版本仍停在 2026.09，版本釋出節奏與提交節奏並不同步。
  • 具身智慧的第一波真實出貨來自實時控制，而非通用 AI 算力：工信部給出全年 10 萬臺的量級，智元以 47 筆投資繫結上游晶片，而可核驗的產品進度顯示——關節控制晶片與小腦晶片已量產、車規電機控制 MCU 出貨超 100 萬顆，定位「大腦」的 V1000（2.5D Chiplet、1000 TOPS）仍在流片階段。這個節奏差比任何路線圖都更能說明產業當前的位置。
