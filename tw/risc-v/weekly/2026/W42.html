一、本週要聞

  • 達摩院玄鐵 C950 在 64 核目標配置上無獨立加速器跑通 27B 大模型，成果經 RISC-V 國際基金會官網專訪傳播（10-15）：RISC-V 國際基金會「V Questions」專欄刊出對玄鐵首席科學家、RISC-V 中國峰會 2026 副主席孟建熠的專訪，披露玄鐵團隊在 64 核 C950 配置上原生跑通 Qwen3.8-27B（270 億引數），不依賴獨立 GPU／NPU，解碼速度超過 30 tokens／秒（約合 20 至 22 詞／秒，達到自然實時對話水平）；該負載需約 400 GB／s 的記憶體資料搬運能力，訪談強調量化、矩陣指令、片上記憶體、頻寬與運算元最佳化必須作單一系統協同設計。C950 為伺服器級 64 位超標量處理器，以 RVA23 檔案（含 RVV 1.0） 為通用計算基線；玄鐵自研矩陣擴充套件經矽驗證後，與 Qualcomm、IBM、VRULL、ISCAS、BOSC 等成員共同發起 AME（Attached Matrix Extension）任務組，正推動規範走向正式批准。設計上 AME 採用獨立 tile 暫存器而非複用向量暫存器，原生支援 INT4／INT8→INT32、FP4／FP8／FP16／BF16→FP32 混合精度累加。邊界：解碼速度為公司團隊口徑，未附第三方基準與整機功耗資料。來源：riscv.org

  • 藍芯算力完成近 20 億元 B 輪系列融資，RISC-V＋AI 伺服器晶片進入量產驗證（10-12 中文首發／10-13 英文跟進）：深圳藍芯算力完成 B 輪系列融資合計近 20 億元人民幣（約合 2.99 億美元），深創投、華控基金、隆湫資本等老股東追加，蘇國投、蘇創投、兆易創新、同創偉業、建銀國際、粵科金融、九坤創投等進場；資金投向 RISC-V CPU 量產、AI 異構處理器迭代與運營商／金融／雲服務商通用算力方案。核心產品 LX500 為 48 核異構（32 效能核＋16 能效核）伺服器 CPU，片內整合 75 TOPS（INT8） AI 引擎，支援 RVV 1.0 與 RVA23，原生相容 PCIe 5.0 與 CXL 2.0；2026 年 2 月流片點亮，7 月搭載該晶片的聯想問天 WR5219 G5 在合肥聯寶量產下線，已適配中國移動 BC-LINUX 並完成 Kimi K2.6、Qwen3.6-35B 推理驗證。邊界：融資規模為中文媒體與 DIGITIMES 口徑，晶片尚無第三方效能評測。來源：鳳凰網·投資界、DIGITIMES

  • RVA23 從「規範」變成「可判定事實」：核心 profile 位 8 枚補丁進入 riscv/for-next，單次查詢能力獲 Phoronix 報道（10-11／10-14）：LPC26 參會記披露，Linux 核心 rva23u64 profile 位系列已推進至 v9（在途），v8 的 11 枚 patch 中前 8 枚於 10-09 被 RISC-V 核心維護者 Paul Walmsley 收入 riscv/for-next，其餘 3 枚將吸收 LPC 現場意見後隨 v9 提交。LPC26 的四個結論：v9 將補充 RVA22／RVA20 分級位便於 glibc 逐級回退；glibc 改為按 profile 構建並由 glibc-hwcaps 自動選庫（hwcaps 來源即核心位，ifunc 留給微架構級）；使用者態動態關閉 V 擴充套件的介面將廢棄，Samuel Holland（SiFive）已在次日發出 3-patch 系列；未來帶暫存器狀態的擴充套件（如矩陣）不再引入同類開關。該系列外溢帶動不少於 5 個主線系列，包括擱置兩年的副檔名大小寫統一與 Zicclsm、位元組跳動 Qingwei Hu 的 Zic64b 支援。10-14 Phoronix 跟進報道「單次查詢系統是否 RVA23 合規」的補丁（方案即 riscv_hwprobe 單位元 KEY_BASE_BEHAVIOR：IMA RVA23U64），此前 Ubuntu 側工具只能給出「probably RVA23」。來源：LPC26 參會記、Phoronix、LPC26 演講材料

  • Ubuntu 26.10 正式釋出，首個官方 RISC-V 桌面映象隨版落地，基線明確為 RVA23（10-15）：Ubuntu 26.10（Stonking Stingray）於 10 月 15 日釋出，官方 cdimage 站點已提供 ubuntu-26.10-desktop-riscv64.iso（4.0 GB），標註為「面向 64 位 RISC-V RVA23 及以上處理器」；同批 riscv64 映象還包括 live-server（1.6 GB）、netboot tarball 與 preinstalled-server（1.3 GB）。這是 Ubuntu 首次提供帶桌面環境的 RISC-V 官方映象（此前 riscv64 僅有伺服器／CLI 版），Canonical 同時為 SpacemiT K3 Pico-ITX 提供官方支援與安裝文件；實驗性 Xubuntu Minimal 映象面向 QEMU 環境（GNOME 在純模擬下載入需 30 分鐘以上）。釋出前一週（10-12）社群已釋出「測什麼」的測試指引與中文媒體報道。意義：桌面映象是 RVA23 基線第一次落到消費可下載的成品上，與本週核心 profile 位進展形成「規範—核心—發行版」閉環。來源：Ubuntu cdimage 26.10、Canonical Discourse

二、指令集與架構生態

RVA23 與核心：profile 位入樹、自動向量化實驗與「合規可查」

  • profile 位進入合併流程：v8 的 11 枚 patch 中 8 枚已進 riscv/for-next（10-09），餘 3 枚隨 v9 提交；v9 將補 RVA22／RVA20 分級位便於 glibc 逐級回退，並寫明不繼承 IMA 位的歷史遺留行為。glibc 側改為按 profile 構建 + glibc-hwcaps 自動選庫，GCC 維護者 Jeff Law 在 GNU Tools Cauldron 的 RISC-V BoF 同向推進；使用者態動態關閉 V 擴充套件的介面將廢棄（SiFive 的 Samuel Holland 已發 3-patch 系列），未來帶暫存器狀態的擴充套件不再引入同類開關。
  • 外溢系列：該系列直接或間接帶動不少於 5 個主線系列——擱置兩年的副檔名大小寫統一與 Zicclsm 被吸收、位元組跳動 Qingwei Hu 貢獻 Zic64b、do not report disabled extensions（6 patch）、cpufeature BUNDLE 到 SUPERSET 精簡、V-off 廢棄系列。本屆 LPC 的 RISC-V MC 共 10 場 talk，高通佔 3 場。
  • 核心自動向量化：Andy Chiu 在 LPC26 介紹以編譯器自動向量化最佳化核心的實踐——LZ4 最大提升約 15%、Btrfs 約 8.4%、XFS 約 5%、Nginx 場景約 2%，代價是向量上下文管理的時間與記憶體開銷上升。RISC-V 核心構建目前仍未啟用 V 擴充套件，該結果使「核心態用向量」這一長期禁區被重新評估。
  • 查詢介面：10-14 Phoronix 報道單位元查詢方案（KEY_BASE_BEHAVIOR：IMA RVA23U64，開機從完整 ISA 點陣圖一次性計算），由 Andrew Jones 發起 RFC、徐國棟推進；配套《RVA23 in practice》演講材料已在 LPC 網站公開。來源：Phoronix 自動向量化、LPC26 向量演講

香山：壓縮 ROB、全相聯 vBTB 與 L2 訪存延遲三線推進

  • 前端與亂序結構：主倉（kunminghu-v3）視窗內落地壓縮 ROB（crob）架構特性——實現壓縮 ROB 並整合 CSR 狀態跟蹤，重構壓縮狀態與時限路徑、為 ArchEvent 攜帶事件位置、以條目偏移保持有序儲存檢查、修復 scommit 位寬並擴充條目數；隨後合入 MBTB（主分支目標緩衝）全相聯 vBTB（#6587）、修復 MMU 在 V=0 時忽略 PTE G 位（#6695）、運算單元窄移位偏置按輸出格式選擇（#6689）、儲存佇列前遞舊儲存資料修復（#6693）。
  • 訪存與快取：10-14 合入 降低 L2 load-to-use 延遲（#6713），並修復 ICache 異常傳遞與取指塊末偏移在資料 ECC 場景下的 bank 選擇，支援 Zimop（MOP）指令解碼。週期末（10-15）主倉無新合入，分支級推送為主（kunminghu-v2 有 1 筆 ChiselAIA 回壓修復）。
  • 模擬與驗證鏈：NEMU 將 AME 矩陣擴充套件的指令分發與 PMEM 訪問解耦（#1249）、加速 AME 矩陣雜湊、修復 AME 矩陣儲存回滾記錄（#1251）與跨頁儲存缺頁的首頁寫入保留（#1240），併發布 v2026.10.r3；difftest 新增 MCSim 時序後端（與 DRAMSim3 並列）、mcsr／mcfg 的 delta 編碼、lane 並行 CRC-64 儲存雜湊校驗、GBD1 frozen-bank DMA drain 與 trace 握手門控（#990）；GEM5 分支（xs-dev）增加 Zimop 指令支援與 TRACERTL／NEMU 軌跡格式，恢復 macOS 構建並新增手工冒煙 CI（#1228），10-15 再合入 MLP 感知取指策略、私有 MBTB victim cache 預設啟用（#1235）及其共享寫入下的失效修復（#1236）、每週理想 BTB SPEC 基準（#1233）。
  • 判斷：本週香山的投入呈「前端結構（crob／vBTB）＋訪存延遲＋驗證基建（時序後端、雜湊校驗）」三線並行，驗證鏈的工程化程度提升快於核本體效能資料的公開。來源：XiangShan、NEMU、GEM5、difftest

架構測試與工具鏈：玄鐵 ATS 補 BF16 向量、奕斯偉開源 AME 測試向量、openKylin 的 RVV 收益

  • 達摩院玄鐵：damo-rv-priv-ats 特權架構測試框架合入 PR #37，引入 T-SBI（Test Supervisor Binary Interface）協議層並把全部測試套件遷移到 S 模式常規執行模型——啟動階段完成僅 M 模式初始化後在 main() 之前降至 S(HS) 模式，以正確建模 Smstateen 門控 CSR 等 HS 視角行為；damo-rv-ats 合入 Zvfbfmin 與 Zvfbfwma（BF16 向量）指令測試（vfncvtbf16／vfwcvtbf16 與 vfwmaccbf16.vf／.vv 用例及構建指令碼），並補充公共基礎設施、整型向量、浮點向量、向量密碼四份框架文件；damo-rv-priv-ats 另將 Sail 形式化模型依賴升級至 0.15；thead-extension-spec 合入 3 筆（RV32 LWUD 修復 #80、使用者 PR #78、README 更新 #72）。
  • 奕斯偉計算：開源 riscv-matrix-gemm-vectors 倉庫，面向 RISC-V 矩陣擴充套件（AME）規範提案 v0.6.0 提供 BF16×BF16→FP32 矩陣乘累加測試向量集——每個用例為裸機自校驗程式，隨附與實現無關的參考值及檢查器，判據採用標準舍入誤差界（ Ĉ−C* ≤ γ(G)·Σ a·b ）而非逐位比對，以適配規範允許的無序求和實現差異；另提供兩個「所有合規實現結果位相同」的用例以檢出錯誤舍入。該套件不依賴具體指令集，可複用於其他矩陣擴充套件實現。
  • openKylin：在 Open Source Summit Europe 2026（布拉格，10-07 至 10-09）披露 RISC-V 側進展——RVV 核心最佳化使 ONNX Runtime FP32 推理提速 2 至 5 倍，相關核心最佳化與推理框架適配計劃回饋上游；AI 棧支援在進迭時空 K3 上以 vLLM 做 CPU 推理，交付形態含 deb、Python wheel、Conda 與 Docker；現場展出預裝 openKylin 3.0 的 K3 筆記本。

  • RVA23 從「規範文字」變成「可判定事實」，三環閉環本週成形：核心 profile 位已有 8 枚進入 riscv/for-next（v9 在途）、單次查詢介面獲主流媒體報道、Ubuntu 26.10 直接以 RVA23 為映象基線並寫明「RVA23 及以上」。這意味著「這臺機器是不是 RVA23」將從逐項比對變成一次系統呼叫，glibc 按 profile 構建 + hwcaps 自動選庫是下一個關鍵落點。若該鏈條按期走通，RISC-V 軟體分發的二進位制碎片化問題將首次有系統性答案。

  • 高效能敘事分成兩條路線，且都在本週拿到階段性證據：一條是「CPU 本身承載 AI」——玄鐵 C950 在 64 核配置上無獨立加速器跑 27B、解碼超 30 tokens／秒，靠的是量化、矩陣指令、片上記憶體與頻寬的系統級協同；另一條是「CPU＋片內 AI 引擎」——藍芯 LX500 以 48 核＋75 TOPS 單晶片融合衝刺量產。前者證明可行性上限，後者證明商業路徑，但兩者都缺少第三方基準與整機功耗資料，這是下一階段最該補的證據。

  • 發行版競爭焦點從「能啟動」轉向「平臺廣度＋韌體體驗＋安全維護」：openRuyi 把韌體做成了日更節奏（K3 雙簇 CPU 模式選擇已下到 SPI 持久化與 coreboot 讀取層），RevyOS 兩週內把 K1／K3／EIC7700／TH1520／SG2042／SG2044 的平臺配置一次收攏，Ubuntu 則用官方桌面映象＋K3 官方支援直接參與。三家同周把 K3 當首要驗證平臺，說明國產 SoC 的發行版支援面已從「補丁式適配」進入「產品化交付」。

  • 端側 Agent 棧成為 RISC-V 軟體棧的新賽道，但仍是單平臺先行：進迭時空一週內從「集中建倉」走到「全棧開源 + 能力分發閉環」（GUI／執行時／記憶／離線語音／安全 + APM／Agent Hub／Skills 映象），並把人形機器人 MuJoCo 模擬補上 RGBD 啟動命令。這套組合在 RISC-V 上尚屬首例；風險在於全部元件當前只支援 K3 與 Bianbu 4.x，跨晶片可移植性與社群外貢獻者規模是後續觀察點。

  • 資本與量產在同一周出現，但「融資額」與「效能兌現」仍需分開看：藍芯近 20 億元 B 輪與 Ubitium 1400 萬美元種子輪同期落地，前者已有整機量產與運營商系統適配，後者仍在流片驗證與 2027 年評估樣片階段。國內 RISC-V 伺服器晶片正從「點亮」進入「量產驗證」，接下來的硬指標是訂單、第三方效能評測與軟體棧成熟度，而非估值。

  • 生態活動密度達到年內高點，峰會周之後應有一批技術披露：RVSC2026（10-18 至 20）疊加進迭開發者大會（10-17）、龍蜥 RISC-V 分論壇（10-18）、香山生態大會（10-20）、AME 矩陣擴充套件研討會（10-20）與玄鐵北京站（10-22），一週內五場活動覆蓋編譯器、矩陣擴充套件、車規工具鏈與端側 Agent 四條主線。下一期週報應以峰會現場材料為主線重做一次事實核對，尤其是 AME 規範的推進狀態與各廠商的晶片時間表。
