今日重點：進迭時空 llama.cpp 分支引入獨立 ggml-spacemit 後端，釋出 v0.2.1

日期：2026-10-12　來源：spacemit-com/llama.cpp PR #43：Add standalone ggml-spacemit backend（10-12）、llama.cpp 分支 Release v0.2.1（10-12）

進迭時空的 llama.cpp 分支倉庫合入 PR #43，引入獨立的 ggml-spacemit 後端，與既有 CPU 路徑實現雙後端共存：

  • 獨立後端為顯式啟用：未啟用時裝置登錄檔報告零裝置、預設行為保持不變（仍走傳統 CPU 路徑）；啟用須設定環境變數
    GGML_SPACEMIT_BACKEND 為 1，使用者透過 --device SPACEMIT0 選擇該後端。
  • 構建修復：調整 libggml-cpu 與 libggml-spacemit 兩個庫的構建方式，修復兩者之間的符號插入（symbol interposition）衝突。
  • 同日釋出 v0.2.1（上一版 v0.2.0 於 09-24 釋出）——分支版本號保持約 2~3 周的迭代節奏。

疊加本視窗其他進迭時空更新（xslim 靜態量化支援忽略運算元、模型庫新增 RT-DETR 與 MNN 後端，見 3.6）以及 Ubuntu 26.10 對 K3 的官方支援臨近（見 1.1），K3／K1 端側 AI 推理與桌面上層生態鏈路在公司內外同步完善。

一、開源社群與軟體生態

1.1 Ubuntu：26.10 RISC-V 桌面映象進入釋出前測試周

日期：2026-10-12　來源：NeoTeo：Ubuntu 26.10 RISC-V desktop images: what to test（10-12）、新浪財經：Ubuntu 計劃推出適配 RISC-V 指令集的官方 26.10 桌面映象（10-12）、Canonical Discourse：Announcing Ubuntu Desktop Images for RISC-V（10-09，背景）

Ubuntu 26.10（Stonking Stingray）定於 10 月 15 日釋出，riscv64 桌面映象進入釋出前最後一週的集中測試期。本視窗測試側跟進：NeoTeo 釋出「測什麼」測試指引（10-12），新浪財經等中文媒體跟進報道（10-12）。此前已報道的要點：Ubuntu Desktop 首次提供 RISC-V 官方映象，另有實驗性 Xubuntu Minimal 映象（建議虛擬機器試用）；官方推薦在 SpacemiT K3（Pico-ITX）上測試（26.10 起為該平臺提供官方支援）；完整桌面體驗面向 RVA23 級硬體（Milk-V Jupiter 2、DeepComputing DC-ROMA、SiFive HiFive Unmatched）；真機啟動需自行放入首級引導（U-Boot）與裝置樹；缺陷報告走 Launchpad。

1.4 技術社群：RVBNA（批次歸一化演算法）解析文章釋出

日期：2026-10-11（10-12 經 Hacker News 傳播）　來源：FProx：RISC-V Bulk Normalization Algorithm (RVBNA)（10-11）、Hacker News 討論（10-12）

社群作者 FProx 撰文解析 RVBNA（RISC-V Bulk Normalization Algorithm）——一種可擴充套件的點積（dot product）近似計算方案：以定點累加器為核心，乘積與累加兩個階段均採用 round-to-odd 舍入，犧牲少量精度換取實現成本與延時的可伸縮性（累加器 guard 位數隨累積項數擴充套件）。RVBNA 已寫入 RISC-V ISA 手冊草案（5 月併入），當前整合於兩個擴充套件專案：向量矩陣擴充套件 VME 的 Zvt 家族（riscv-isa-manual PR #2997）與大批次點積擴充套件 Zvdota／Zvbdota（PR #2618）。文章系統比較了 FP MUL+ADD、FMA、Kulisch 精確累加等方案的精度—成本權衡，並開源了誤差評估器（rvbna-explorer）。

二、產品與生態動態

2.1 元（Meta）：開源 Muse Gadgets SDK，官方 Home Link 硬體基於 ESP32-C5

日期：2026-10-12　來源：CNX Software：Facebook releases Muse Gadgets SDK for ESP32 and Raspberry Pi/Linux-based devices（10-12）、facebookincubator/muse-gadget-sdk（GitHub）

Meta 釋出開源 Muse Gadgets SDK（Apache-2.0），讓自制硬體接入其個人 AI 助手 Muse：含 ESP32 裝置 SDK（顯示影象、音訊輸入輸出、感測器/執行器介面，支援多款 ESP32 開發板，覆蓋 ESP32-C5／C6 等 RISC-V 晶片型號）與 Linux 裝置 SDK（樹莓派等，提供 system.run、file.read/write 等指令）；另含第三方裝置技能目錄（智慧家居、印表機、3D 印表機等）。Meta 自制 五千臺 Muse Home Link 面向美國訂閱使用者免費發放，硬體基於 ESP32-C5（雙頻 Wi-Fi 6、BLE、802.15.4）。這是 RISC-V 無線 MCU 進入大廠消費級硬體的最新案例，也顯示 ESP32 生態正被用作個人 AI 代理的硬體底座。

2.2 行業分析：AI 負載加速 RISC-V 採用，SHD 預測 2031 年 SoC 出貨 359 億顆

日期：2026-10-12　來源：Bisinfotech：Why AI workloads are accelerating RISC-V adoption（10-12）

行業媒體 Bisinfotech 刊文分析 AI 與邊緣計算如何重塑 SoC 設計取向：效能瓶頸從主頻轉向資料搬運、記憶體層次與互連效率；異構 SoC 中 RISC-V 適合承擔控制與系統管理角色，併為矩陣／張量運算等定製擴充套件留出空間。文章引用 SHD Group《2026 RISC-V 市場報告》：預計 2031 年 RISC-V SoC 出貨量達 359 億顆、CAGR 約 31.7%，並強調軟硬體協同（編譯器/執行時對自定義指令的支援）與 pre-silicon 驗證（FPGA 原型）對定製 RISC-V SoC 落地的重要性。

3.2 達摩院玄鐵：合規測試框架引入 T-SBI，測試套件遷移至 S 模式執行

日期：2026-10-12　來源：damo-rv-priv-ats PR #37（10-12）、damo-rv-priv-ats 倉庫

達摩院玄鐵（XUANTIE-RV）組織下的 damo-rv-priv-ats 合規測試框架（覆蓋 RISC-V 特權級規範 90 餘個擴充套件、以裸機程式直接執行於 QEMU／Sail／Spike／FPGA）合入 PR #37：引入 T-SBI（Test Supervisor Binary Interface）協議層，並將全部測試套件遷移到 S 模式常規執行模型——啟動階段完成僅 M 模式的初始化後，在 main() 之前降至 S(HS) 模式執行。動機是原先把測試體跑在 M 模式下無法建模 S/HS 視角下的暫存器行為（例如 Smstateen 門控 CSR 在 HS 模式讀取時應陷入）；遷移後測試執行位置與規範判定場景一致。該組織視窗內 73 個倉庫僅此一倉推送。
