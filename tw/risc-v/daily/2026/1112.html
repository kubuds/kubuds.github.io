今日重點：北京印發具身智慧機器人三年行動方案，20 萬臺年產能與 5 萬 PFlops 叢集把需求側量化（11-11）

北京市經濟和資訊化局 11 月 11 日印發《北京市具身智慧機器人產業高質量發展行動方案（2026—2028 年）》，自印發之日起實施，有效期至 2028 年 12 月 31 日。檔案把此前多輪政策裡的方向性表述換成了可考核的數字：到 2028 年培育不少於 5 家國際一流、10 家國內領先的人形機器人整機企業；京津冀區域整機產能佔全國 25%，關鍵零部件配套率超過 60%；在京形成 20 萬臺／年的整機生產能力；新增建設總規模超過 50000 PFlops 的具身智慧專用算力叢集，並推動重點企業與算力節點建設單位以「結對子」方式形成算力供需協同。

技術路線寫得比以往具體。方案明確支援視覺語言動作模型（VLA）、世界模型（WM）、強化學習等多路線佈局與融合，並把攻關拆成「大腦」與「小腦」兩側：大腦側是多源資訊融合、物理空間理解與人類情感識別，目標是讓機器人理解物理規律約束、主動識別人的動作與表情等非語言指令；小腦側是實時推理、跨本體遷移與自學習進化，指向多工泛化、高可靠執行與超精密操作。製造端給的是一條條硬指標：打造 3 至 5 種國際一流整機平臺，整機額定負載達到自重 40% 以上，平均無故障工作時間超過 2000 小時，核心運動部件與末端執行器年故障率低於 10%，設計使用壽命超過 5 年，連續作業工況電池續航 4 小時以上，高自由度靈巧手單隻成本降至萬元以內。

治理與資本安排同步給足。方案提出構建「一機一碼」全過程管理體系，覆蓋研發、生產、報廢、回收全週期；建立整機企業上市「一對一」服務機制；在整機、關鍵零部件、具身智慧模型與資料採集等領域培育不少於 200 家創新型企業，推動在京高校與科研院所建立 100 個機器人研究團隊，並明確反對「內卷式」競爭。這些指標不是憑空定的：工信部 10 月 19 日披露，2026 年上半年國內人形機器人整機產品突破 400 款、產量超 4 萬臺，預計全年突破 10 萬臺；中國信通院 10 月報告則給出另一面——上半年公開披露的中標專案中教育科研機構佔約 55.5%、政府及公共平臺約 20.6%、工業及技術型企業約 21.1%，相當比例裝置月均開機天數不足 10 天，整機價格可能只佔總擁有成本的 40% 到 60%。

對 RISC-V 這條線，這份方案的價值在於把「需求側」從願景變成了採購引數。20 萬臺／年的整機產能、60% 的關鍵零部件本地配套率、萬元以內的靈巧手，這三條合起來指向的是關節控制與本體算力兩級晶片的成本與可靠性：關節側要的是硬實時、低功耗與確定性網路，本體側要的是能跑 VLA 推理的算力與記憶體頻寬，且都要在 2000 小時無故障的約束下量產。國內 RISC-V 供給目前能對上這兩級的，是進迭時空的 K3 系列（本體算力）、算能的 SG 與 BM 系列（伺服器與邊緣）、芯來的 N1000／NI1000（實時核與向量矩陣核）以及 MIPS 的 Atlas M8500（關節級實時核，11-09 已報道其 Actus 平臺）。5 萬 PFlops 的專用叢集則落在訓練與資料側，與 PPU、DCU 這類加速卡直接相關。需要說明的是，方案本身沒有點名任何指令集或供應商，上述對應關係是供給側現狀的對照，不是政策指定。

RevyOS 核心單視窗 101 筆：K3 顯示與 USB3 落地、EIC7700 風扇與熱區、SG2044 SRD3 雙板入樹（11-11）

revyos/linux 倉庫的 revyos/7.3.y 分支在本視窗內落地 101 筆提交，按時間分成三個批次。最大的一批在 11-11 13:06（北京時間）前後，主體是平臺特性與 FROMLIST 回補：SpacemiT 側加入 K3 的 GPU 節點與顯示電源域、K3 Pico ITX 的 Type-C Port A、USB3 PHY 與 FUSB301 自主控制器、PCIe 在 PHY 初始化後再拉 PERST#、UFS 的 WriteBooster 支援，並關掉 K3 上 amdgpu 的動態 PCIe 速率切換；ESWIN 側為 EIC7700 補上 hwmon 風扇控制器、PWM、熱區節點與 CPU／裝置調頻，最高頻定在 1.4GHz；SiFive HiFive Premier P550 補齊 USB、SATA、PCIe、eMMC 與 SD；T-Head 側讓 Lichee Pi 4A 在交接時保持 USB 供電、為 Milk-V Meles 開啟 USB。

晶片平臺之外還有一層通用改動。一批 RISC-V 頁表訪問器相關的 FROMLIST 補丁被整體回補：讓頁表訪問一律走訪問器函式、允許訪問器非冪等、修正寫頁表時的記憶體型別、把 N 與 MT 位在 ptdump 裡按使能狀態顯示、為彙編暴露全部頁表位、給 alternative 增加三引數宏與可替換連結暫存器，另外修了 DMA_DIRECT_REMAP 的選擇邏輯。KVM 側把全部計數器暴露給 VS-mode 以相容 bootloader，並用 XLINUXENVCFG 這個 cpufeature 守護 SENVCFG 訪問。

第三批是 14:52 的 defconfig 收口：在昨日報告的六筆基礎上擴寫為完整矩陣——K1、K3、DP1000、EIC7700、TH1520、SG2042／SG2044 逐個開啟，另加 Picoheart errata、common options 與 debian_defconfig，並補上 linuxboot 配置、交叉與原生兩套 CI 構建，以及「用大版本號作包名」等打包側 HACK。三批加起來，這一天的重點不是某個新功能，而是把此前散落在各分支的板級支援收成一套能編譯、能出包的組合。

值得單獨看一眼的是 SG2044 的板卡線：SRD3-10-LB 與 SRD3-12 兩塊板的裝置樹同時入樹，SRD3-12 還帶一個 large-BAR 變體，並新增第二條 C2C1 x4 PCIe 口、eFUSE 控制器，PCIe 視窗按 EDK2 的實現對齊。對做 RISC-V 伺服器整機的團隊，板級描述與韌體口徑一致比多一個驅動更重要——不一致的視窗劃分會在多卡場景下直接表現為裝置列舉不全。

openRuyi 36 筆：OpenTelemetry 與四個 Python 認證包安全更新，OpenCL 三包入樹，核心升至 7.3.4／6.18.63（11-11）

openRuyi 主倉本視窗 36 筆，兩條供應鏈同時收口。第一條是可觀測性：python-opentelemetry 全家升到 1.45.2，其中 api 包顯式標註 security-fixes，semantic-conventions 升到 0.66b2，並新增 exporter-otlp-common 與 exporter-http-transport 兩個子包，等於把 OTLP 匯出的可選路徑補齊。第二條是認證：python-pyjwt 2.15.1、python-oauthlib 4.0.1、python-joserfc 1.8.0、python-authlib 1.9.3 四個包同日以 security-fixes 名義更新。兩件事都屬於「不上頭條但決定能不能上線」的類別。

樂鑫 esp-riscv-trace 0.2.0：RISC-V 指令級 trace 補上 decode／profile／stats／history 四條命令（11-11）

樂鑫把 esp-riscv-trace 推到 0.2.0。這個工具做的事是解碼樂鑫 RISC-V 晶片上抓到的硬體指令 trace：讀 OpenOCD 產生的 .esptrace 抓包，或讀 esp-coredump 生成的、帶 trace 備註的 core ELF，重建程式執行流，把每個 PC 解析到函式與原始碼行，然後輸出文字轉儲、熱點表、崩潰前的呼叫歷史，或可直接餵給火焰圖的呼叫棧；連續性丟失的位置標為 gap 而不是猜測填補。0.2.0 新增的四條命令把這套能力從「能抓」推到「能分析」：decode 列出執行過的指令，profile 寫出火焰圖棧，stats 按原始碼行統計指令數，history 連同 open_capture 介面一起開放多份抓包的合併與回看。

支援的晶片列表覆蓋 ESP32-C5、C6、C61、H2、H21、H4、P4 與 S31，包格式分 Processor Trace 1.0 與 Efficient Trace 2.0 兩代。使用方式是在 ESP-IDF 裡開啟 trace 配置，用 OpenOCD 的 esp riscv_trace start／stop 抓包，panic 後韌體會在偵錯程式停機前先停 trace，避免最後一段丟失。

這件事的分量在「RISC-V 端側的除錯可見性」。過去在幾十美分的 RISC-V MCU 上做效能分析，基本靠打點和計數；指令級 trace 長期是高檔偵錯程式的功能。樂鑫把它做成 pip 可裝的 Python 工具，並對外開放讀取抓包的介面，等於把「這段程式碼到底執行了多少條指令、熱點在哪一行」變成常規手段。對在 RISC-V 上做推理運算元與實時控制的團隊，這類工具的邊際價值往往高於再提一次主頻。

ch32rv-clang：CH32 Arduino 核改用 RISC-V-only clang 與 lld，只編 RISCV 後端（11-11）

社群組織 CH32 RISC-V User Group 釋出了 ch32rv-clang：從上游 LLVM 發行版構建、只保留 RISCV 後端的 clang 與 lld，按宿主系統各打一個壓縮包，供 ArduinoCore-CH32RV 透過 Arduino 開發板管理器安裝。這一版刻意做減法——壓縮包裡沒有 C 庫、沒有編譯器執行時，暫時仍鏈 xPack GNU RISC-V Embedded GCC 提供的 newlib-nano 與 libgcc；換來的是體積與安裝路徑的簡化：一個根目錄、bin 下 12 個工具（Linux 與 macOS 上是單一 multicall 二進位制加軟鏈，Windows 上是各自的可執行檔案），解壓即用。

指令集側支援 WCH 青稞的 XW 壓縮指令，對應 LLVM 19 及以後的 Xwchc 擴充套件（-march 裡帶 _xwchc）。哪些核具備 XW 由核心的裝置表管理——這一點寫得相當明確：QingKe V3A、V4A 這類沒有 XW 的核上，一旦執行到第一條此類指令程式就停住，所以不能憑晶片型號猜。預編譯覆蓋五個宿主：x86_64 與 aarch64 的 Linux、x86_64 與 aarch64 的 macOS、以及 Windows MSVC。版本號按「LLVM 版本-構建號」標註，如 v23.1.5-1，一個標籤觸發全部宿主的構建併發布帶 .sha256 的產物；構建指令碼 MIT，歸檔內的 LLVM 為 Apache 2.0 with LLVM Exceptions。

對這條產品線，換編譯器不是目的，降低上手門檻才是。CH32V003 這類十美分級別的 RISC-V MCU 過去在 Arduino 生態裡依賴 GCC 工具鏈，版本與安裝步驟都比較脆；把 LLVM 的 tar 包接進開發板管理器後，「裝不上工具鏈」這個最常見的勸退點被消掉了一半。

NEMU 四筆：SMBLOCKCTL 加 PF 重新整理位、RVV 零長訪存置髒 VS、AME 矩陣快路徑（11-11）

NEMU 在本視窗落地四筆。功能側，SMBLOCKCTL 增加了 PF 重新整理使能位（#1285），把這一控制位從保留位變成可配置行為；RVV 側修了零長度 gather、slide 與 mask 類操作未置髒 VS 的問題（#1286）——向量狀態髒位漏標在虛擬化場景下會讓宿主誤判上下文是否需要儲存，屬於典型的「只在特定指令組合下才暴露」的缺陷。MMU 側修了第二頁非規範地址時應當報告下一頁基址的問題。

效能側一筆更值得注意：共享 ref 中啟用矩陣 load／store 的快路徑（#1284）。AME 是香山系的矩陣擴充套件，這一年裡 NEMU 對它的支援從指令語義補齊走到訪存路徑最佳化，說明矩陣單元在模擬器裡已經跑得夠多、效能成了瓶頸。同日 difftest 側也有兩筆配合動作：nightly 工作流去掉 Firtool 發行版的 latest 標籤（#1040），以及把 MMA 的 CPU 校驗向量化並複用已解碼運算元（#1038）。

五、總結與趨勢觀察

一、政策把具身智慧的需求側量化，RISC-V 的機會在關節與本體兩級。 北京這份方案給出的 20 萬臺／年整機產能、60% 關鍵零部件本地配套率與萬元以內靈巧手，本質是把「用什麼晶片、什麼成本、什麼可靠性」寫成了採購引數。關節側要硬實時與確定性網路，本體側要能跑 VLA 的算力與頻寬，兩級都不是靠單顆大晶片解決。國內 RISC-V 供給在這兩級都已經有可對照的產品，接下來的競爭點不是峰值算力，而是能不能在 2000 小時無故障的約束下把成本壓到整機廠願意換料。

二、發行版這一天的關鍵詞仍是「可交付」，但做法從補丁轉向矩陣。 RevyOS 一日 101 筆，重心是把 K3、EIC7700、SG2044、TH1520 與 P550 的板級支援收成 defconfig 矩陣並接上交叉／原生兩套 CI；openRuyi 一日 36 筆，把可觀測性與認證兩條供應鏈同時收口，並把核心升到 7.3.4／6.18.63。兩家做的都不是新功能，而是「別人能不能編譯出來、敢不敢放到生產」。

三、驗證與可觀測性成為工具鏈競爭的新前線。 NEMU 給 AME 矩陣訪存加快路徑、difftest 把 MMA 校驗向量化、香山給 CI 加 ISA 冒煙測試、樂鑫把指令級 trace 做成 pip 可裝的四條命令——四個動作指向同一個判斷：核與擴充套件複雜到一定程度後，瓶頸從「設計對不對」轉向「能不能快速看清它在做什麼」。這條線上投入不足的團隊，會在整合階段付出成倍的時間。

四、香山的 18 筆純重構說明高效能核進入結構治理期。 能對一個模組做「只動結構不動行為」的批次重構，前提是迴歸面足夠密、行為已穩定。TLB 與 PTW 是訪存路徑上最難除錯的一段，把許可權檢查與旁路結果收斂到單一出口，是在為後續擴充套件留介面。這類工作不出現在任何效能數字裡，但決定下一代核加特性時的改動成本。

五、資本側的定價錨擺上檯面，但資產邊界仍待披露。 阿里公告擬分拆平頭哥赴港、港交所確認可拆分，估值區間從 200 億至 300 億美元到 250 億至 620 億美元不等。對做 RISC-V 的公司，這件事的參考價值不在估值數字，而在招股書將如何切分外部收入與關聯交易——同一套標準很快會被用來衡量所有國產算力晶片公司，包括還在虧損期的 RISC-V 伺服器與 IP 廠商。
