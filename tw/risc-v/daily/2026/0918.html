今日重點：中國方案首次完整主導 RISC-V 國際指令集標準

日期：2026-09-17　來源：中國科技網／科技日報《七年攻堅實現零的突破！中國方案正式寫入 RISC-V 國際指令集標準》

上海交通大學計算機學院並行與分散式系統研究所（IPADS）團隊主導的 SPMP（Supervisor-mode Physical Memory Protection，特權態實體記憶體保護）指令集標準，已透過 RISC-V 國際基金會董事會審議，正式合入 RISC-V 指令集架構標準。這是 RISC-V 國際基金會成立以來，首個由中國本土團隊從零發起、完整主導的 ISA 標準特性。報道指出，2026 年獲批的其他 ISA 擴充套件均來自 SiFive、Meta、高通等海外團隊，國內此前在香山等實現層進展顯著，但在頂層指令集標準制定上存在空白。

技術思路上，SPMP 針對終端裝置輕量級安全隔離難題，採用「只看門牌、不查索引」的方案：依靠晶片內部一組配置條目記錄實體地址區域的起始地址、長度與訪問許可權，處理器訪問記憶體時僅需一次暫存器校驗即可完成許可權判斷，無須多級地址轉換，以極小硬體開銷實現記憶體安全隔離，補齊 RISC-V 在高安全、低功耗終端場景的短板。專案自 2019 年 9 月提交設計初稿，由陳海波教授帶領，杜鼕鼕、楊璧丞、夏虞斌等核心成員牽頭推進近 2500 天完成標準化。該方案曾入選 RISC-V 國際基金會 2021 年度安全亮點特性，也是 Linux 基金會 2023 年度四大 RISC-V 安全進展中唯一來自中國的專案。

落地側已具備實證：SPMP 技術已在香山開源高效能處理器、芯來 RISC-V IP 等國產晶片平臺完成部署。RISC-V 國際基金會董事會成員、中科院計算所副所長包雲崗評價稱，這使我國晶片領域實現「從被動遵從規則到主動定義規則的轉變」。對產業而言，這一事件的意義在於標準話語權的實質變化：全球晶片廠商在設計 RISC-V 晶片時均可選用這套中國主導的安全隔離規範，國內團隊從生態應用方轉為規範供給方。

一、開源社群與軟體生態

1.1 Canonical：RVA23 之後的演進路線，CFI、矩陣擴充套件與 RVA23.1

日期：2026-09-17（文章 09-15 釋出，09-17 經 Hacker News 進入視窗）　來源：Ubuntu 官方部落格《Evolution of the RISC-V ISA. What next after RVA23?》

Canonical 的 Jon Taylor 系統梳理了 RVA23 之後的方向。安全側以 CFI 為例，該擴充套件 2024 年獲批，由 Zicfilp 與 Zicfiss 兩條獨立擴充套件組成，用於防禦返回導向與跳轉導向的控制流攻擊；設計上儘量相容既有 RVA23 硬體，硬體未實現時相關指令被忽略，但缺少 Zimop 支援的 RVA23 之前硬體上 Zicfiss 指令會陷入——這給編譯器工具鏈先行適配留出了空間。矩陣擴充套件給出三條路線：VME 複用標準向量狀態、作業系統無需改動；IME 擴充套件向量暫存器堆並新增結果暫存器；AME 使用全新暫存器檔案。後兩者要求作業系統在上下文切換時感知新增暫存器狀態，應用則可透過 sys_riscv_hwprobe() 在執行時探測擴充套件並選擇實現路徑。

RVA23.1 側新增三項開發選項與兩項擴充套件選項，文章點出其中三項與發行版關係密切：Double Trap Handling 讓機器態或虛擬化態安全捕獲處理程式非可重入狀態下的二次陷入，降低系統崩潰與記憶體損壞風險；Supervisor Counter Delegation 將計數器委託下放；以及協助作業系統與工具鏈對接的平臺級能力。Canonical 的結論是，RVA23 提供的是規模化部署基線，而創新仍集中在安全與控制流、矩陣計算、以及不帶強制擴充套件的小版本修訂上，後者透過「開發選項」先行、後續配置檔案再行強制的節奏，兼顧軟體穩定性與新特性引入。

1.2 香山模擬鏈 GEM5：預解碼對齊、L2 請求源跨緩衝保留等三項提交

日期：2026-09-17　來源：OpenXiangShan/GEM5 PR #1150、PR #1156、PR #1123

香山 GEM5 模擬倉庫在視窗內落地三項提交。一是預解碼對齊（Predeocde align，PR #1150，提交時間 09-17 23:19），修正預解碼環節與前級取指的對齊關係。二是配置側支援上游 SE 工作負載資源（PR #1156，09-17 18:35），使系統呼叫模擬模式下可直接引用上游負載資源定義，減少本地配置分叉。三是訪存側保留 L2 請求的源資訊跨緩衝傳遞（PR #1123，09-17 09:57），避免請求在中間緩衝階段丟失發起方標識而影響後續回填與競爭判斷。三項分屬取指、配置與訪存三個方向，屬於連續迭代的小步改進。

1.3 香山 difftest：關閉 Verilator SLP 向量化以規避 LLVM 誤編譯

日期：2026-09-17　來源：OpenXiangShan/difftest PR #968

香山差分測試框架 difftest 在 09-17 20:24 合入修復：在 Verilator 構建中關閉 SLP（Superword Level Parallelism）向量化。原因是該最佳化在部分 LLVM 版本下會觸發誤編譯，導致模擬模型行為偏離參考實現，從而在差分比對中產生假性失敗，干擾真實缺陷定位。這類「工具鏈誤編譯汙染驗證結果」的問題在開源處理器驗證中並不罕見，處理方式是從構建選項層面關閉可疑最佳化，保證模擬與硬體行為一致，代價是部分模擬效能損失。

二、產品與生態動態

2.1 汽車側：首個汽車領域 RISC-V 行業標準（QC/T）啟動編制，34 家企業參與

日期：2026-09-17　來源：鳳凰網轉網通社快報《汽車 RISC-V 首個行業標準啟動編制，34 家企業參與》

在 2026 第六屆智慧汽車晶片生態大會上，中汽芯（深圳）科技有限公司披露：汽車領域的首個 RISC-V 行業標準已啟動編制，標準號屬 QC/T 序列，目前已有國內外 34 家企業參與編制。這是 RISC-V 在國內汽車行業從企業級實踐走向行業規範的關鍵一步——此前國內汽車晶片側的 RISC-V 組織化動作集中在聯盟與專委會層面（2026 年 4 月中國汽車晶片產業創新戰略聯盟成立 RISC-V 車規晶片專委會，5 月中電標協 RISC-V 工委會車規應用組揭牌），本次進入行業標準編制意味著技術路線開始沉澱為可檢驗的規範文字。同期會議還有紫荊半導體等企業分享 RISC-V 驅動汽車晶片革新的實踐。

2.2 達摩院：RISC-V 車規功能安全研發週期通常 3 至 5 年，STL 診斷覆蓋率存在 RTL 與網表差異

日期：2026-09-17（會議 09-16）　來源：鳳凰網《阿里巴巴達摩院李偉立在 2026 第六屆智慧汽車晶片生態大會分享 RISC-V 車規功能安全研發情況》、蓋世汽車同題報道

阿里巴巴達摩院處理器架構師李偉立給出 RISC-V 車規落地的量化判斷：國內外 RISC-V 車規應用已在 IP、IC、整機和軟體生態四個層面基本達到可用狀態，但功能安全研發需經流程認證與產品認證雙向迭代，走完流程一般需要 3 到 5 年。技術路徑上，ASIL-D 普遍採用雙核鎖步（DCLS），邏輯簡單但代價是兩倍面積與兩倍功耗；ASIL-B 出於 PPA 考量多采用 STL 軟體診斷，要求 90% 診斷覆蓋率，面積增加 10% 至 20%。

他點出的三重約束值得記錄：STL 單程式段執行時間需控制在數千 cycle 內以免拉長中斷響應延遲；車規儲存緊張，測試用例豐富度受限；對 Device 型別 IO 裝置的訪問可能產生不可逆狀態，壓縮了軟體診斷空間。一個關鍵研發發現是 RTL 模擬與網表模擬的診斷覆蓋率存在 5% 以上差異（可達 7% 至 10%），意味著 RTL 階段需做到 95% 甚至更高才能在網表層達標。李偉立呼籲更多廠商豐富 ASIL-B/D 等級的 MCU 級 IP，並開發面向智駕的高效能運算核心。

2.3 長安汽車：RISC-V 核心在 MCU 領域算力已超 ARM，正探索自定義指令集的 AI DSA 架構

日期：2026-09-17（會議 09-16）　來源：蓋世汽車《長安汽車丁可：艙駕融合與 RISC-V 開源架構是汽車晶片破局關鍵》

長安汽車晶片開發高階副總工程師丁可披露了主機廠的 RISC-V 評估結論：長安早在 2022 年就詳細評估 RISC-V CPU 核心，發現其在 MCU 領域算力已超過 ARM，實時性基本相當；基於五級流水線的 RISC-V 架構，中斷響應可在 120 個時鐘週期內到達入口函式，功耗表現優異。長安還在探索基於 RISC-V 自定義指令集擴充套件的 AI DSA 架構，透過 BF16 與 INT8 混合精度加速兼顧精度與成本，並提出將晶片管控下探到 IP 核級別、以開放態度參與標準制定的目標。

晶片需求側，丁可的判斷是汽車晶片朝大算力、高頻寬、高整合化演進，未來以 1000 TOPS 以上 AI 算力加高頻寬中央大腦為核心；7B 模型已實現車載部署，30B 模型在 MOE 架構下考慮上車；端到端路線由 Transformer+BEV 向 VLM、VLA 乃至世界模型迭代。他提到 L3 到 L4 級智駕涉及 1400 多個可執行程序，傳統架構解決冗餘與失效問題成本高昂，因此艙駕一體的「one box」與艙駕融合成為趨勢方向。

五、總結與趨勢觀察

  • 標準話語權層面出現標誌性事件：上海交大 SPMP 合入 RISC-V 國際指令集標準，是國內團隊首次從零發起並完整主導一項 ISA 特性，且已在香山與芯來 IP 落地。與本期汽車側 QC/T 行業標準啟動編制相互呼應，說明國內 RISC-V 參與方式正由「實現與適配」轉向「定義與規範」，這是比單點產品釋出更結構性的變化。
  • RISC-V 資料中心敘事進入資本市場視野：SiFive 與 AMD 的 ROCm 演示從產業媒體擴散到 Yahoo Finance 等財經渠道，並在 AMD 股價中得到反應。與之前「釋出—第三方分析」的演進路徑相比，本期的邊際變化是外部資本開始為 RISC-V 宿主路線定價，這會影響後續客戶評估與供應鏈投入節奏。
  • 車規是本期最密集的落點：行業標準啟動（34 家企業）、達摩院給出 3 至 5 年功能安全週期與 STL 覆蓋率量化經驗、長安披露 RISC-V 核心在 MCU 算力超 ARM 並探索自定義指令 AI DSA，三條資訊分別對應規範、方法與整機評估三個層次，共同指向國內汽車側 RISC-V 正在從單點驗證走向體系化工程。
  • 開源軟體側維持小步迭代：香山模擬鏈（GEM5 三項、difftest 一項）、revyos 核心配置與 CI、openRuyi 月度版本待發布，均屬工程硬化型進展；本期無新的架構級釋出，符合此前幾期觀察到的節奏。
  • 國內廠商工程主線集中在「AI 棧補齊 + 運控分層」：進迭時空在 llama.cpp 多模態後端、視覺示例庫預處理後端上連續補強，同時 spacemit-robotics 以公共庫承載電機反饋歸一化與動作接管、機型倉庫只做配置，運控軟體分層架構已較清晰；算能則透過 ZSBL 3.1.0 與產品線更名為下游整合做準備。
