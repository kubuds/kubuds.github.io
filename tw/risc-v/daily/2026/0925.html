今日重點：UPC 研究：用玄鐵 C910 與片上效能計數器讓 RISC-V 晶片「自檢」微架構攻擊，檢出精度 99%

日期：2026-09-24　來源：Scienmag《Machine Learning Turns RISC-V Chips Into Their Own Hardware Attack Detectors》、論文：Pou, Otero, Robledo, Pajuelo & Canal, RISC-V hardware attack detection using on-chip hardware performance counters, Cybersecurity 9(1) Article 222、HARPY-V 資料集（CORA 研究資料倉儲）

9 月 24 日，Scienmag 刊發西班牙加泰羅尼亞理工大學（UPC）團隊的研究報道：研究者把機器學習檢測器「裝進」RISC-V 晶片自身的硬體效能計數器（HPC），實現在晶片內部對微架構攻擊的實時檢測，論文發表於期刊 Cybersecurity（9(1) 第 222 篇）。實驗在真實商用矽片上完成——達摩院玄鐵 C910（64 位亂序核，RV64GCV）搭載於矽速 LicheePi 4A 開發板、執行 Debian 13；團隊構建並公開了資料集 HARPY-V：約 6.4 萬條標註樣本，含 16 種微架構攻擊（Flush+Reload、Flush+Flush、Evict+Reload、Spectre V1/V2/RSB、計時漂移、TLB 與頁表遍歷類攻擊，以及 GhostWrite 等）與 16 個良性程式，良性集刻意選用與攻擊共享硬體結構的負載，使分類問題接近真實難度。

結果與工程細節：二元檢測（攻擊／良性）精度達 99%，多分類（區分具體攻擊型別）約 95%；在「留一攻擊」零日模擬中，隨機森林配合 mRMR 特徵選擇、決策樹配合 RFECV 的組合仍保持高檢出率，而「選對計數器」比「堆更多計數器」更關鍵。團隊還公開了兩條珍貴的實測經驗：在 C910 上，perf 同時監控多個計數器會相互干擾（部分讀數被放大 3 倍以上），必須逐計數器單獨採集；且 C910 的 perf 事件描述大多不準確，須以官方手冊的計數器對映為準。

意義與邊界：這是首批以商用 RISC-V 矽片（而非 FPGA 軟核或模擬器）為平臺、並公開可復現資料集的微架構攻擊檢測研究之一，「用晶片自帶計數器加輕量模型做主動檢測」是一條不需要改矽、不需要核心補丁的低成本加固路線，與 RISC-V 開放生態的安全敘事相呼應；同時需注意邊界——實驗僅覆蓋單一核心型號，計數器模式與微架構強相關、跨晶片需重訓練；監督學習依賴已標註攻擊資料，對全新攻擊型別的泛化仍待驗證。

2.1 樂鑫 ESP32-S31 的 Linux 移植升溫：從微控制器邁向 SBC 形態

日期：2026-09-24　來源：XDA《The newest ESP32 can actually run Linux, and it’s getting uncomfortably close to a Raspberry Pi》、CNX Software：ESP32-S31 Linux BSP 開發者預覽（08-22）

XDA 刊發專題討論樂鑫 ESP32-S31：雙核 32 位 RISC-V 主核（最高 320 MHz，另帶 40 MHz 低功耗核）加上首個內建 Sv32 MMU 的 ESP32，硬體上還具備千兆乙太網 MAC（RGMII）、USB 2.0 High-Speed OTG 主機、雙槽 SDIO、DVP 攝像頭輸入與並行 LCD 控制器——外設組合已接近現代單板計算機。官方已於 8 月釋出 Linux BSP 開發者預覽（Buildroot 2025.02 + U-Boot + Linux 6.18 分支，整機映象約 13.7MB）；社群移植同步推進：GrieferPig 的 Linux 6.12 supervisor 模式移植（約 15MB 可用記憶體、CoreMark 約 1059），以及基於 Linux 7.1 + OpenSBI 1.9、可驅動 800x480 LCD 控制檯的另一移植。XDA 的判斷：S31 的外設、頻寬與 CPU 特權模型都已「靠近 SBC」，但 Linux 支援仍屬實驗性質，短期內不建議用於生產。

2.2 算能 BM1688 新單板 OrangePi O1 公佈：16 TOPS TPU 加 RISC-V C906 協處理器

日期：2026-09-24　來源：LinuxGizmos《16-TOPS AI SBC with SATA 3.0 runs on octa-core Sophgo BM1688》

LinuxGizmos 刊發 OrangePi O1 單板（90×70mm）詳情：基於算能（SOPHGO）BM1688 視覺計算處理器——8 核 Arm Cortex-A53（最高 1.65GHz）加 RISC-V C906 協處理器（最高 1.2GHz），內建 TPU 提供 INT8 16 TOPS／INT4 32 TOPS／FP16-BF16 約 4 TFLOPS，支援 Caffe、PyTorch、TensorFlow、ONNX、MXNet，定位邊緣側大模型與視覺模型推理。板上配置：8/16GB LPDDR4X、eMMC（16-128GB 可選）、M.2 NVMe（PCIe 3.0）、SATA 3.0、雙千兆網口、Wi-Fi 6E／藍芽 5.3、可選 4G/5G 模組、HDMI 2.0 4K60、雙 MIPI-CSI 與 6 路影片輸入；支援 16 路 1080p30 解碼。BM1688 內嵌 RISC-V C906 協處理器，是這款以 Arm 為主核的邊緣 AI 晶片的「RISC-V 內芯」，也是國產 RISC-V 廠商在多核異構 AI 晶片路線上的一類典型形態。

4.1 進迭時空 spacemit-robotics：靈龍合入 SONIC 運動跟蹤策略，MuJoCo 模擬修復

日期：2026-09-24　來源：humanoid_linglong PR #16：整合 SONIC 運動跟蹤策略、humanoid_common PR #20：SONIC 動作選擇與 RL 保護、humanoid_common 提交：SONIC 執行時介面、simulation_mujoco 提交：渲染與物理解耦（#9）

進迭時空機器人線視窗內合入重要軟體更新：人形機器人應用包靈龍（LingLong L1，28 自由度）整合 SONIC 運動跟蹤策略（PR #16）——註冊 SONIC 模型與八條可選參考動作至策略 YAML，配置 28 自由度動作對映、觀測與參考輸入、增益與目標邊界；humanoid_common 同步支援 SONIC 動作選擇與 RL 保護（PR #20）：策略介面卡與 HMI 可在保持全身控制的前提下切換 SONIC 參考動作，新增逐關節目標邊界與推理超時診斷。模擬側，MuJoCo 修復 PC 渲染與物理模擬解耦（#9），配合既有的「PC 模擬 + K3 板卡 RL 推理」sim2sim 流程，便於在單機上除錯策略後再上實機。

4.2 加州大學伯克利分校釋出 IISWC 2026 教程：異構 RISC-V SoC 上的 ML 與機器人負載

日期：2026-09-24　來源：ucb-bar/IISWC-tutorial-2026-RISCV-ML-Robotics

加州大學伯克利分校（ucb-bar）釋出 IISWC 2026 教程的微站倉庫：《Building, Tracing, and Optimizing End-to-End ML and Robotic Workloads on Heterogeneous RISC-V SoCs with a Lightweight Zephyr Runtime》——圍繞在異構 RISC-V SoC 上以輕量 Zephyr 執行時構建、追蹤與最佳化端到端機器學習與機器人負載。教程把「機器人負載方法學」（構建、追蹤、最佳化）作為獨立議題組織，顯示學術側對 RISC-V 機器人與 ML 工作負載的研究正在體系化。

五、總結與趨勢觀察

  • 安全研究進入「可復現」階段：UPC 以玄鐵 C910 商用核與公開資料集完成微架構攻擊檢測研究，RISC-V 安全敘事從「單點漏洞披露（GhostWrite 等）」推進到「量化檢測加資料集共享」；對國產核而言，被選為實驗平臺既是關注度提升的體現，也提示商用矽片需要主動檢測方案。
  • 端側 AI 軟硬體同步補強：ESP32-S31 的 Linux 化嘗試、BM1688 新單板、進迭時空 llama.cpp v0.2.0 與樂鑫 esp-vision，共同指向端側推理從「能跑」到「好跑」的工程化階段；RISC-V 在 MCU 到邊緣盒子的形態邊界繼續擴張。
  • 開源社群雙線節奏：香山在多分支上並行推進向量、預測與快取微架構調優，開發密度維持高位；openRuyi 本週以安全更新與打包規範為主，等待 2026.09 釋出視窗。
  • 具身智慧分層推進：靈龍合入 SONIC 運動跟蹤策略後，機器人軟體棧按「執行時介面、策略資產、模擬閉環」三層持續沉澱；配合 IISWC 教程等學術活動，RISC-V 機器人負載的方法學建設在產業與學術兩側同步展開。
  • 觀察點：openRuyi 2026.09 是否釋出；ESP32-S31 官方 Linux BSP 由開發者預覽轉正的節奏；進迭時空 ggml-spacemit 後端的上游化動向。
