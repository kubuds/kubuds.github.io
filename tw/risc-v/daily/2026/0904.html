一、開源社群與軟體生態

1.1 GCC 17 合入 RISC-V 原生的 -mcpu/-mtune=native 支援

日期：2026-09-03　來源：Phoronix

GCC 在 RISC-V 後端長期缺失的 “本機自動調優” 能力終於補齊：此前討論的 -mcpu=native / -mtune=native 支援補丁已合入 GCC 主線，將隨 GCC 17.1（2027 年初發布）落地。過去 RISC-V 使用者若想按本機 CPU 最佳化程式碼生成，必須手寫具體型號名（如 sifive-p550、spacemit-x100），與 x86/Arm 的 native 行為不一致。本次補丁來自 SiFive 的 Kito Cheng（RISC-V 工具鏈核心維護者之一）。當前已知限制：對多核異構 SoC（如 SpacemiT A100 與 X100 混搭平臺），GCC 只能按編譯程序實際執行所在的核心型別選 CPU 目標，暫無法感知全晶片異構拓撲。這是 RISC-V 工具鏈”伺服器化/易用化”的又一小步，與 RVA23 伺服器矽片今年落地（見 1.2）形成配套。

1.2 SiFive 詳解 RISC-V 標準體系與未來演進：Hot Chips 2026 演講實錄補錄

日期：2026-09-02 釋出 / 09-03 被 HN 與 Google News 收錄（本視窗補錄）　來源：ServeTheHome（Patrick Kennedy 現場記錄）、Hacker News

ServeTheHome 補發其 Hot Chips 2026（8 月下旬，斯坦福）現場記錄——SiFive 的 RISC-V 標準與採用進展演講。該演講與 09-02 已報的 NVIDIA CUDA-on-RISC-V 教程同屬本屆 Hot Chips”RISC-V 伺服器化”敘事，本期為兩條線索中較”標準科普”的一條。要點：

  • 標準體系全景：以 RISC-V 十六週年（2010-05-18 生日）為引，重申”開放標準非單家公司命運繫結”；四類基礎 ISA（RV32I/RV64I/RV32E/RV64E）已批准，CHERI 能力安全變體與未來 RV128（128 位地址空間）正在開發；
  • Profile 機制細化：RVA20/RVA22/RVA23 三代演進（RVA23 於 2024-10 批准，強制向量與 hypervisor），明確大版本加強制功能、小版本只增 option 的相容模型，保證新軟體在舊硬體上可執行；RVB23（Yocto/OpenEmbedded 定製構建場景）獨立演進；
  • AI 與安全：矩陣擴充套件給出 AME/IME/VME + 向量 fast-track 的”1+3”並行路線；強調 RISC-V 是唯一能同時扮演 AI 主機 ISA（CUDA 移植）、加速器裝置 ISA 與端側自託管 ISA 的架構；安全特性清單含 PMP、RISC-V Worlds 匯流排級隔離、面向機密計算的 supervisor domains、指標遮蔽，進行中專案含 CHERI、推測屏障、記憶體標籤與記憶體加密上下文；
  • 破除流言：逐一回應”變長指令是弱點”“RISC-V 需要指令融合才有競爭力”“RISC-V 效能不行”等說法（gnews 上”SiFive RISC-V requires Fusion”“has too many extensions”等驚悚標題均出自該文小節）。作者結語：首個 RVA23 伺服器今年出貨，是標準工作落地硬體的實際訊號。

二、產品與生態動態

2.1 趨勢條目：CUDA-on-RISC-V 媒體回聲延續：BigSky 定位”移植驗證平臺”，NVLink Fusion 晶片最早 2027

日期：2026-09-03　來源：igor’sLAB（德媒，英文版）

德媒 igor’sLAB 於 09-03 刊出 SiFive BigSky SF-2U870 的跟進解讀（主事件 08-25 已報，本期不重複展開），口徑可作為生態節奏的第三方確認：BigSky（32 核 P870-D @ 2.0GHz、RVA23、Ubuntu 26.04 LTS / RHEL 10）定位是面向超大規模雲廠商、晶片公司與軟體開發者的移植驗證平臺，而非對標 EPYC/Xeon 的量產伺服器；CUDA 已在其上執行——RISC-V 核擔任主機跑作業系統與控制任務，CUDA 核心實際在 NVIDIA GPU 上執行，據 RISC-V International 週報，該演示為 RISC-V 主機 + NVIDIA Blackwell GPU 組合。文中重申：SiFive 與 NVIDIA 正推進 NVLink Fusion 整合，首批整合 NVLink Fusion 的 RISC-V 定製晶片最早 2027 年才可能問世，BigSky 的意義在於先把軟體棧在真實硬體上備好。結合 09-02 已報 NVIDIA 的要求清單（RVA23/ACPI/一致性），”CUDA 上 RISC-V”的落地節奏判斷不變：軟體先行、矽片在後。

三、國內團隊動態與深挖

3.1 香山主倉與 XSAI：向量/浮點單元重構推進，AI 分支援續同步

日期：2026-09-03/04　來源：openxiangshan/XiangShan commits、openxiangshan/XSAI、openxiangshan 組織

中科院計算所主導的開源高效能核 XiangShan 視窗內合入 6 筆提交（較昨日 10+ 筆節奏放緩，屬正常波動），集中在向量/浮點執行與流水線最佳化：

  • refactor(VCVT)：浮點與向量型別轉換單元（VCVT）開始重構，引入新的 VCVTWrapper 結構（初始支援）；
  • perf(LoadQueueReplay)：最佳化 LoadQueueReplay 延遲（#6422）；
  • refactor(VIMac)：向量整數乘加單元初始化支援；fix(vector,exu)：向量執行源運算元不應總走 bypass 資料；
  • config(isa)：ISA 擴充套件字串與實現對齊（#6463）；ready-to-run 同步 bump NEMU 引用。

深挖：XSAI——香山 AI 分支並行推進。openxiangshan 組織下存在一個自述為 “A fork of Xiangshan for AI” 的倉庫 XSAI（2023-12 建倉），視窗內持續合入：difftest 子模組對齊 mrelease retirement 語義（#121）、nightly regression checkpoint 池更新（#120）；回溯可見其 08-31 批次同步昆明湖（kunminghu-v2）bug 修復（#115）、並引入 Palladium 模擬環境的 commit-stall 看門狗（#119）——說明香山團隊在通用核（昆明湖）之外維護著一條面向 AI 負載的處理器變體線，且與主線的正確性修復保持同步；另一倉庫 YunSuan（雲算）為香山功能單元的獨立單元測試工程（Verilator 模擬），屬驗證基建。整體看，香山系”處理器+模擬器+AI 變體+功能單元測試”的開發閉環仍在全速運轉，向量/浮點與可靠性打磨是當前主題。

3.2 HICOOL 2026 RISC-V+AI 協同創新挑戰賽收官

日期：2026-09-03（決賽頒獎）　來源：國際科技創新中心網路服務平臺（北京亦莊官微轉載）、賽事主頁 rdi.hicool.com、經濟參考網（複賽報道，08-21）

國內首個聚焦 RISC-V 與 AI 融合創新的專項賽事——HICOOL 2026 全球創業大賽”積體電路前沿技術：RISC-V+AI 協同創新挑戰賽”在中國國際展覽中心完成決賽路演與頒獎，十強隊伍角逐全部獎項後圓滿落幕：

  • 一等獎花落”基於 RISC-V 與 OpenHarmony 的智慧影片監控（NVR）端側 AI 分析系統”；另有 3 個二等獎、6 個三等獎，獲獎專案覆蓋端側 AI 分析、國產晶片工業適配、邊緣計算終端、教育場景解決方案、工業資料流處理等方向；
  • 賽事由北京市人才工作局指導、北京海外高層次人才協會主辦，北京 RISC-V 數字基礎設施創新中心與北京奕斯偉計算（ESWIN Computing）聯合承辦，RDI 聚力聯盟等協辦，四大賽道為 AI 驅動晶片設計、算力底座與 CLI 創新、RISC-V+AI 場景應用、OPC 超級個體輕量化 AI；
  • 獲獎權益設計頗能反映北京亦莊的生態打法：可申請每年最高 2000 萬元算力券、經開區”科創二十條/人才十條”與積體電路專項政策、免費使用 ACT（RISC-V 架構符合性測試）工具並獲 RISC-V 測試認證、奕斯偉計算生態背書與開發者生態對接、免費加入 RDI 聚力聯盟。

與 08-21 複賽（70 餘專案晉級、近百位創業者）相比，決賽聚焦十強，標誌著該賽事從”專案徵集”走完”落地孵化”第一程。對國內 RISC-V 生態而言，這是繼”香山開源、奕斯偉商業、亦莊產業政策”之後，“開源核心 + 頭部商業公司 + 區域產業帶”三方合力的又一顯性動作；NVR 端側 AI 一等獎專案同時命中 RISC-V 與 OpenHarmony 兩個開源底座，值得跟蹤其後續產業化。

四、具身智慧與機器人專章

4.1 人形機器人計算走向”中央+分散式”混合架構，安全複雜度高於自動駕駛

日期：2026-09-03（Liz Allan 文）　來源：Semiconductor Engineering、Jon Peddie Research 分析（09-03）

Semiconductor Engineering 刊發行業圓桌綜述，討論人形機器人算力架構與安全設計。核心判斷與 RISC-V 生態強相關：

  • 架構共識：混合制。英飛凌人形機器人系統架構師 Ronald Stärz 提出”中央強算力 + 指端/關節級分散式預處理”的混合模型，明確類比汽車從集中 ECU 到 zone 架構的遷移（延遲、頻寬、容錯驅動）；MIPI Alliance Physical AI BoF 主席 Edo Cohen 補充手部區域性實時推理（毫秒級抓握力調節）與中央任務規劃的職責切分，但也提示集中式架構在 BOM、功耗與軟體複雜度上可能更優。TI 則主張”啞感測器 + 中央融合”路線以省功耗。共同點是：安全絕不能只交給 AI 模型，必須有獨立認證的硬體元件兜底；
  • 安全威脅模型升級：Secure-IC（Cadence 旗下，RISC-V 安全 IP 重要供應商）CTO 指出人形機器人與自動駕駛的本質差異——物理親近性（家庭、醫院、學校），使中間人攻擊、LLM 操縱弱勢群體等場景成為現實風險；功能安全與網路安全的融合成為剛需；
  • RISC-V 角度：MIPS（GF 旗下，全面轉向 RISC-V）市場負責人 James Prior 的表述被單獨引用——”客戶問的不是何時採用 RISC-V，而是如何轉向 RISC-V（找誰合作、走什麼路徑）”，並強調機器人行業（汽車/工業同源）風險厭惡，需要”軟體優先、開放標準、生態活力”的供應敘事。這與昨日 MIPS 三平臺（Acies/Actus/Aegis）釋出、Jon Peddie Research 09-04 跟進分析（”MIPS gives physical AI three ways to think”）相互印證：RISC-V 在具身智慧的競爭正從”晶片規格”轉向”架構話語權 + 安全認證 + 生態服務”。

五、總結與趨勢觀察

  1. 工具鏈與標準雙線”伺服器化”收口：GCC 17 補上 RISC-V 原生 -mcpu/-mtune=native（Kito Cheng/SiFive），SiFive 在 Hot Chips 系統化闡述 RVA/RVB profile、安全與矩陣擴充套件路線——編譯、profile、OS 三層都在為首個 RVA23 伺服器矽片（今年出貨）做準備；本週 Hot Chips 兩條 RISC-V 演講報道（NVIDIA CUDA 要求清單 09-02 已報、SiFive 標準演進今日補錄）至此集齊。
  2. CUDA-on-RISC-V 節奏清晰化：第三方媒體（igor’sLAB）與 RISC-V International 週報共同確認 BigSky 的”移植驗證平臺”定位與 RISC-V 主機 + Blackwell GPU 演示事實；NVLink Fusion 定製晶片最早 2027——軟體棧先行、矽片在後的判斷不變，短期內不宜高估 RISC-V 伺服器出貨量。
  3. 國內開源側唯香山系活躍：昆明湖主倉向量/浮點重構（VCVT、VIMac、LoadQueueReplay）與 AI fork XSAI 的同步修復並進，開發閉環完整；平頭哥/芯來/算能/進迭等仍處釋出後平靜期。
  4. 生態動作看亦莊：HICOOL RISC-V+AI 挑戰賽收官（一等獎為 RISC-V+OpenHarmony NVR 端側 AI），奕斯偉計算與北京 RISC-V 數字基礎設施創新中心聯合承辦、ACT 免費開放——國內 RISC-V+AI 的”產業帶孵化”模式初顯。
  5. 侷限說明：今日無重大新品釋出級事件，屬標準/工具鏈/生態會議類資訊為主的”輕量日”；BigSky、MIPS 相關報道均為已報主事件的媒體回聲，本期只作趨勢條目不重複展開；Google News 中文源對國內團隊零命中，國內部分依賴 GitHub 提交核查與亦莊官方渠道。
