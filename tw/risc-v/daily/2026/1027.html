今日重點：Onsemi 以 1450 萬美元接手 Codasip 低端 RISC-V 業務

日期：2026-10-26　來源：Jon Peddie Research：Onsemi picks up Codasip’s low-end RISC-V business for $14.5 million（10-26）、Codasip：戰略調整與業務剝離公告（04-08）

安森美（Onsemi）已完成對 Codasip 低端 RISC-V 處理器業務的收購，交易金額據捷克商業媒體 e15 報道為 1450 萬美元，其中約 90% 已支付。

  • 交易範圍：只涉及 Codasip 約 260 名員工中的 27 人，另附 Studio 處理器設計工具的授權。Codasip 保留 Studio 的所有權與大部分受公共資金支援的專案。
  • 前因：Codasip 於 2026-04-08 宣佈戰略調整，剝離低端 RISC-V 處理器設計業務、轉向基於 CHERI 的「網路韌性」安全架構；當時公告只說買方是一家美國上市半導體公司，未點名。
  • 捷克國內的質疑：Codasip 曾獲歐盟與捷克國家級研究資助，今年 7 月還公開過逾 1.19 億歐元的補助與股權支援（大部分尚未到賬），1450 萬美元的成交價因此引發討論；公司口徑是「合理重組」而非賤賣。
  • 競爭格局：CHERI 方向已出現直接對手 SCI Semiconductor，其在 2026 年 9 月完成 500 萬英鎊（約 667 萬美元）融資，並稱另有 770 萬英鎊政府合同；Codasip CEO Ron Black 對 CHERI 聯盟表示，國防與關鍵基礎設施客戶的安全需求強於通用核授權。
  • 買方邏輯：Onsemi 拿到的低端 RISC-V 技術與團隊，可直接服務其汽車與工業半導體業務——與它此前透過收購、授權拼裝技術棧的做法一致。

Jon Peddie Research 的判斷值得記錄：基礎處理器核正在變得難以差異化與變現，客戶面前擺著越來越多的商用與開源替代；RISC-V 的下一階段會更多由成熟半導體公司塑造，價值從指令集本身移向差異化產品與系統整合。

1.1 香山：35 筆修復一次性回收，TLB need_gpa 與向量異常成主線

日期：2026-10-26　來源：XiangShan 提交記錄（10-26，kunminghu-v3）

香山主倉昆明湖 V3 分支在視窗內合入 35 筆提交，全部提交時間戳為 10-26 16:32，而原始作者日期跨 2026-02-04 至 2026-09-17——典型的長期分支批次回收，不是當日新開發。

  • TLB／MMU 成組：need_gpa 相關四筆——為 need_gpa 的 robidx 加掩碼避免 X 態（#6233）、修復非末埠 need_gpa 清除丟失（#6251）、按翻譯階段匹配 need_gpa 響應（#6285）、以及新增超時清除機制。另有 TLB 因 needGpa 凍結的歷史修復（#5610）一併回收。
  • 向量與訪存：vlsu 把向量異常的 guest physical address 擴充套件到 XLEN（#6432）；Rob 側向量 load/store 的 flushpipe 需要延遲（#6244）。
  • 虛擬化與特權：HLVHLVXHSV 的 PMP 檢查改用 SPVP 模式（#6250）、RVH 下隱式 G 階段讀忽略 MXR（#6099）、HFENCE.GVMA 時重新整理 VS 階段 PageCache（#6082）、HLVX 的最終物理執行許可權校驗（#6017）。
  • 復位與 X 態治理：mtvec 復位值（#5862、#5889）、MemBlock／L2Top 缺復位值引起的 X 態（#5838）、LoadQueueRAR 用 RegEnable 規避 X（#5986）、CPU 時鐘門控改用預掃描復位——這一組佔了批次的三分之一。
  • 新特性與小項：NewCSR 開啟 PMM 與 CBIE 的 CSR 寫（#6269）；Debug 為 CBO 類指令補 LT／GE 觸發器匹配（#6447）；hartIDDmodeWidth 引數化（#5627）。

把 35 筆按主題攤開，能看出這是一次以「收斂」為目標的合流：X 態、復位值、need_gpa 超時這類問題不影響功能演示，只在長跑、多核、虛擬化壓力下暴露，屬於流片前必須清賬的項。作者日期最早回到 2 月，說明部分修復在分支裡躺了七個月才進主線。

1.2 NEMU：AME 矩陣擴充套件的事件編碼與主機 FMA 異常標誌修正

日期：2026-10-26　來源：NEMU 提交記錄（10-26）、NEMU 釋出記錄

參考模型 NEMU 視窗內 3 筆提交，兩筆落在 AME（矩陣擴充套件）上，一筆是配置層重構。

  • AME 語義修正：fix(ame): encode MMA event types from mcfg semantics（#1269）——MMA 事件的型別此前按固定列舉編碼，改為按 mcfg 暫存器的語義解碼，矩陣配置變化時事件分類才正確。
  • 浮點異常保真：fix(ame): preserve host FMA exception flags（#1268）——AME 路徑用主機 FMA 指令模擬，需把主機的浮點異常標誌如實回傳給客機，否則差異比對會漏掉異常側的不一致。
  • 配置層重構：refactor(config): reduce duplication with shared config layers（#1259），把重複的配置項抽成共享層。
  • 背景：10-23、10-24 剛連發 v2026.10.r8、v2026.10.r9 兩個標籤，本批修正屬標籤後的繼續打磨；NEMU 近一週的改動重心已從「加功能」轉向「讓差異比對更可信」。

參考模型的價值全在「錯得比 DUT 少」。把主機浮點異常標誌這種細節補齊，說明香山的驗證已經推進到需要區分「數值相同但異常標誌不同」的階段。

1.3 difftest 落地 BOOM 支援，GEM5 加入譯碼融合壓縮

日期：2026-10-26　來源：difftest 提交記錄（10-26）、GEM5 提交記錄（10-26）

差分驗證框架與 GEM5 分支各有一筆方向性明確的提交。

  • difftest 接入 BOOM：feat(difftest): add BOOM DiffTest support（#998）——把加州大學伯克利分校的 BOOM 亂序核接進同一套比對框架。值得注意的是，10-23 的日報剛記錄過 #995 只是「把 BOOM 的 DiffTest 接入寫進文件」，四天後程式碼落地。
  • 構建相容：同批的 #1003 保留 C++11 構建相容，避免新程式碼抬高工具鏈門檻。
  • GEM5 譯碼融合：cpu-o3: Add optional decode fusion compaction（#1184）——在亂序模型里加入可選的譯碼融合壓縮，讓前端把可融合的指令對壓成一條微操作，貼近真實前端行為。

difftest 從「只驗證香山」走向「驗證別人的核」，意義超出專案本身：一套能同時比 NEMU、BOOM 的框架，才有可能被外部團隊當成公共驗證基礎設施來用。GEM5 側加譯碼融合，則是讓效能模型的樂觀程度與硬體前端的實際做法對齊——模擬與矽片的口徑差，往往就藏在這種可選項裡。

openRuyi 主倉視窗內 46 筆提交，提交時間集中在 10-26，原始作者日期為 09-19 至 10-23，同樣是批次入庫。

  • 雲原生棧安全更新：nats-server 升到 2.15.1、moby 升到 29.9.2、etcd 升到 3.7.2、containerd 升到 2.4.2、fzf 升到 0.74.5，四條帶 [security-fixes] 標記。
  • Java 與簽名體系：openjdk-latest 升到 27.0.1.0.2.1（並在上游 retag 後重新整理原始碼校驗和）；新增 Sequoia PGP 整套元件——sequoia-sq、sqv、sequoia-sop、sequoia-chameleon-gnupg、sequoia-git、sequoia-policy-config、sequoia-keystore-server、sq-cryptoki。
  • Rust 依賴補齊：rust-libgit2-sys-0.17、rust-git2-0.19、rust-interprocess-1、rust-to-method-1、rust-convert-case-0.6、rust-static-toml-1、rust-seq-macro-0.3。
  • Python 與工具鏈：python-docker、python-sagemaker* 五件套升到 3.26／1.26／2.26、boto3／botocore 到 1.43.115；另有 capnproto、fwupd-efi、cc-switch-cli 5.11.1、go-gopkg-fatih-set.v0 等。

一條主線很清楚：RISC-V 發行版當下的主要工作量是安全債，不是新特性。nats、etcd、containerd 這類元件的 CVE 不修，伺服器場景就無從談起；把整套 Sequoia 拉進來（含 sequoia-chameleon-gnupg 這種 GnuPG 相容層），意味著包簽名與金鑰管理要按現代 PGP 棧重建，而不是繼續吃 GnuPG 的老賬。

1.5 開源 EDA 把自研 RV32I 核推向 GF180 流片：LibreLane 78 步全流程

日期：2026-10-26（會員官網巡檢檢出，活動 11-11）　來源：RISC-V 協會（日本）：RISC-V Day Tokyo 2026 Autumn 邏輯設計軌道議程、RISC-V 協會（日本）首頁

RISC-V 協會（日本）在 10 月掛出 RISC-V Day Tokyo 2026 Autumn（11-11，東京大學本鄉校區）的議程細節，其中一場 30 分鐘的演講公開了一條用純開源工具鏈完成流片的完整路徑。

  • 物件與路徑：講者黑川能毅（JASA 硬體委員會 RISC-V WG）用 LibreLane 3.1.0.dev2 把自研 RV32I 相容核 SWC1 推到 GF180 工藝，流程覆蓋 Verilator lint、Yosys 綜合、OpenROAD 佈局／CTS／佈線、9 個 signoff STA 角、Magic 與 KLayout 雙重 DRC、netgen LVS，共 78 道工序。
  • DFT 是本次新增：在綜合後插入掃描 FF 替換與掃描鏈建立兩道工序（GF180 上只有 5V 庫帶掃描單元），用開源 ATPG Atalanta 約 2 分鐘生成 14,148 條測試圖形，故障覆蓋率 97%；插入掃描鏈後頻率從 50MHz 降到 19MHz，掃描鏈本體可跑 200MHz 以上。
  • 踩坑記錄：公開的 5V SRAM 模板按 README 能過，換自己的核就反覆失敗，最後發現是拿 5V 單元搭了 3.3V 核，切到 3.3V 單元后佈局完成、STA 給出 50MHz 預期。
  • 環境：Windows 11 的 WSL2（Ubuntu 24.04）加 Nix，流程除錯與 STA 報告檢查用 Claude Code（Pro 計劃）。SWC1 已於 2026-03 透過 Tiny Tapeout（IHP 130nm）流片，晶片在途期間在 FPGA 上跑 μT-Kernel 與 lwIP。
  • 同場下一講：12:40–13:10 為圓山宗智的「AI-Designed RISC-V: From Claude Code to Linux Boot」。

這條的技術含量不在「用開源工具流片」這個結論——Tiny Tapeout 早已證明可行——而在把 DFT 補進開源流程：掃描鏈與 ATPG 長期是商用 EDA 的地盤，個人愛好者在 WSL2 上做出 97% 故障覆蓋，說明開源流程的短板正從「能不能流片」轉向「能不能可測」。對國內做教學晶片與 MPW 的團隊，這是一份可直接對照的工序清單。

二、產品與生態動態

2.1 SiFive 把 RISC-V 定位為 AI 加速器的控制層

日期：2026-10-26　來源：Jon Peddie Research：SiFive makes the case for RISC-V as the control layer for custom AI accelerators（10-26）、SiFive 博文：Orchestrating Custom Accelerators with Intelligent Control Units（10-16）

SiFive 提出用 Intelligence 系列 RISC-V 處理器充當「加速器控制單元」（ACU），在主機與自研加速器之間做可程式設計的控制層。Jon Peddie Research 在 10-26 對這一思路做了整篇分析。

  • 問題陳述：硬連線狀態機在演算法變化時難改；共享匯流排容易成瓶頸；把底層編排交給主機 CPU 會吃掉算力並增加延遲。
  • 方案：用帶標量與向量能力的 RISC-V 核承擔資料準備與搬運、加速器操作派發、以及啟用函式與資料格式化這類附屬計算，透過 SSCI、VCIX 一類協處理器介面直連加速器；控制邏輯的改動落在軟體／韌體裡，不動固定功能硬體。
  • 型號分工：X100 面向控制密集、低延遲與小面積；X200／X300 提供更大向量頻寬與算力。
  • 已有落地：Google 資料中心已用 X200 作 AI 計算主機；另有 X100 授權給一家未具名的美國一級半導體公司，用於工業邊緣 AI。
  • 評論口徑：JPR 認為這印證了「價值正從 ISA 移向系統整合」——RISC-V 不必取代 Arm 或 x86 當主處理器，進入控制面同樣能拿到有分量的位置。

這條與今日重點裡的收購案是同一枚硬幣的兩面：通用核授權在貶值，而「把核嵌進別人的系統架構裡」在升值。ACU 這個提法之所以成立，是因為 AI 加速器的形態越來越碎片化，沒有哪家願意為每種形態去改硬體狀態機。

2.2 MIPS 的 RISC-V 全棧轉型：Acies／Actus／Aegis 三平臺與 S8200 核心

日期：2026-10-26　來源：電子工程專輯：從處理器 IP 到物理 AI 平臺——MIPS 的 RISC-V 全棧轉型（10-26）、NeoTeo：MIPS’s RISC-V platforms: what Acies, Actus and Aegis do（10-26）

放下自有指令集的 MIPS，在格羅方德（GlobalFoundries）收購、並整合新思科技 ARC 處理器 IP 之後，已把自己重新定義為「基於 RISC-V、面向汽車電子／邊緣 AI／高效能網路的 IP 與全棧方案提供商」。2026 年 9 月釋出的三個平臺在本週被中英文媒體集中拆解。

  • Acies-1（推理原生）：基於 Atlas S8200，支援 RVA23、RVV 向量擴充套件與 VME，可執行 llama.cpp、Qwen 等大模型以及視覺 Transformer 與 VLA 模型；軟體側走 Atlas SDK 與基於 IREE 的 MLIR，相容 TensorFlow／PyTorch／ONNX；硬體形態是易整合的 M.2 PCIe，面向機器人、自動化裝置與邊緣智慧體。
  • Actus-1（事件原生）：基於 Atlas M8500，實時多執行緒架構並支援 FoC 加速，整合 VPX 向量協處理器，以單板計算機形態交付，面向運動控制、感測器融合與預測性維護，符合 ISO 26262 與 ISO 21434。
  • Aegis-1（安全原生）：面向任務關鍵型物理 AI 系統，支援 RISC-V Android 與 Linux 開發，可在資料中心之外執行智慧體負載，同樣按 ISO 26262／21434 設計，目標是壓縮高安全等級系統的認證週期。
  • S8200 核心：整合標量、向量與矩陣引擎，官方稱能效較當前產品高 4 倍 TOPS/W，已向關鍵客戶送樣，首批矽參考平臺預計 2027 年推出；與已量產的 NPX5／NPX6 專用 NPU 並行存在。
  • 客戶基礎：MIPS 稱客戶覆蓋全球前十二大汽車製造商中的 九家，Mobileye、英飛凌均為其重要客戶。

MIPS 的路徑說明一件事：在 RISC-V 時代，「有歷史包袱的 IP 公司」並非沒有機會——把舊 ISA 丟掉、把工具鏈與客戶關係留下，再用「工作負載原生」重做平臺分層。Acies 直接點名 VLA 與機器人，是本週第二家把 RISC-V 的落點放在物理 AI 上的國際 IP 廠商。

2.3 Adafruit Metro ESP32-P4 Hydra：UNO 形態的雙 RISC-V 核開發板

日期：2026-10-26　來源：CNX Software：Adafruit Metro ESP32-P4 Hydra（10-26）

Adafruit 推出 Metro ESP32-P4 Hydra，把樂鑫 ESP32-P4 做成 Arduino UNO 外形，並額外掛一顆 ESP32-C6 補無線。

  • 主控：ESP32-P4（v1），雙核 32 位 RISC-V 高效能核最高 360MHz（帶 AI 指令擴充套件與單精度 FPU），加一顆最高 40MHz 的低功耗 RISC-V 核；16MB PSRAM、16MB QSPI NOR；2D 畫素處理加速器與 H.264／JPEG 編解碼。
  • 無線：ESP32-C6 模組經 SDIO 連線，提供 Wi-Fi 6、藍芽 LE 5.3 與 802.15.4（Thread／Zigbee，部分韌體需自行整合）。
  • 介面：樹莓派相容的 2-lane MIPI DSI 與 CSI（22-pin、0.5mm 間距）、USB 2.0 高速 OTG 主機口（480Mbps）、microSD、UNO 排針與獨立 SPI 排針、STEMMA QT、LiPo 充電。
  • 定位：HMI、相機與 IoT 原型；TinyUF2 支援拖放式韌體更新。

ESP32-P4 的生態正在從模組走向「標準外形 + 完整介面」的成品開發板。對做端側 HMI 與視覺原型的團隊，UNO 外形意味著現成的擴充套件板庫存可以直接複用——這類工程便利，往往比多幾十兆赫茲更能推動選型。

3.1 算能：SG2044 韌體補上簽名金鑰、打包工具與全平臺 CI

算能的 EDK2 韌體倉在 SG2044 分支（devel-sg2044）上視窗內錄得 6 筆提交，全部為 10-26 當日創作，內容集中在「讓韌體可被交付」，而不是改功能。

  • 簽名鏈路：新增 SOPHGO 預設 RSA 簽名金鑰（keys:），配套 tools: 下的韌體二進位制簽名指令碼，把「能籤」變成倉內可復現的步驟。
  • 打包：新增 firmware.bin 的打包工具，把分散的映象拼成單一韌體檔案；同時提供 envsetup.sh，支援脫離完整 EDK2 樹的獨立韌體構建。

國產高效能 RISC-V 伺服器的短板長期不在核，而在「韌體能不能被客戶安全地刷進去」。簽名金鑰、打包工具、獨立構建環境、全平臺 CI 這四件湊齊，才算把韌體從「研發能編」推進到「產線能發」。這一步沒有釋出會，但它決定下一批整機能不能出貨。

四、具身智慧與機器人專章

4.1 進迭時空機器人棧補位：宇樹 Go2 跑上 K3，人形側接入語音互動與圖傳

日期：2026-10-26　來源：GitHub：spacemit-robotics/unitree-go2、 humanoid_linglong、 humanoid_common、 omni-agent、 realtime-link

進迭時空的機器人組織 spacemit-robotics 視窗內 5 個倉庫有推送、共 9 筆提交，四條線拼起來是一次棧級的補位。

  • 第三方機型適配（新倉）：unitree-go2 倉庫名為「Go2 on SpacemiT K3」，README 直接給出在 K3 板端以 root 執行的啟動指令碼（SDK 位於 /root/spacemit_robot，使用 new_bigcore 配置），並規定啟動前必須擺好蹲姿 Pose A、開機自啟需在上電前擺好；配套網頁控制檯在同網段訪問 go2-sdk.local:8082。視窗內 5 筆提交包含 ROS 2 應用 + ONNX 策略 + 網頁控制，以及 SDK 交付簡化、硬體生命週期與相機幀同步、CI 模型下載加固。
  • 人形側（靈龍）：humanoid_linglong 對應靈龍 L1 V1.4，28 自由度（左腿 6 + 右腿 6 + 頭 2 + 左臂 7 + 右臂 7），支援 MuJoCo 模擬與 whole_body 實機後端切換、PC 單機模擬、sim2sim 跨機推理（PC 模擬 + K3 板端 RL 推理）、K3 實機 28 軸電機與並聯腳踝／Forsense IMU 控制，另有 Android App 與掃碼網頁經 HMI 服務接入。本期新增「靜態互動與語音服務」配置。
  • 通用層：humanoid_common 新增操作員語音客戶端與靜態 profile；omni-agent 新增對講（push-to-talk）與互動式語音工具（#20）。
  • 圖傳：realtime-link 新增影片傳輸（#2），提供單標頭檔案 C ABI（libvideo_transmission.so）、參考 UDP 後端，並有基於 MPP 編解碼器與 SDL2 顯示的板端取圖示例。

四條線合起來，是從「自家機型能跑」（靈龍）擴到「別人的機型也能跑」（宇樹 Go2），再把語音互動與影片回傳補上。對做端側機器人平臺的廠商，可複製的機型適配比單機演示更值錢：Go2 這類存量四足機器人數量大、SDK 相對開放，拿它做 K3 的對外樣板，比再調一版人形更能說明平臺化能力。需要剋制的是，這些提交都是倉庫內的程式碼與文件，未見第三方實測或量產落地資料。

五、總結與趨勢觀察

  • IP 層的估值分化已經落地到成交價：Codasip 低端 RISC-V 業務以 1450 萬美元、27 人的規模轉手，同期 SiFive 在賣「加速器控制單元」、MIPS 在做「工作負載原生」平臺。三家在同一周給出同一結論的不同答案——通用核不再是價值中心，能不能嵌進客戶的系統架構才是。
  • 國內團隊補的是工程化的最後一公里：算能的韌體簽名與打包、進迭的 TEE 文件體系、芯來的擴充套件與追蹤文件，三件事都不進釋出會，卻都是「能不能量產交付」的前置條件。這一層做紮實，比再發一版參數列更有意義。
  • 開源核進入收斂期：香山 35 筆修復批次回收，作者日期跨 2 月至 9 月，主題集中在 X 態、復位值與 TLB need_gpa；配合 NEMU 補浮點異常標誌、GEM5 加譯碼融合，驗證側的動作比功能側密集。參考模型「錯得比 DUT 少」正在成為顯式目標。
  • 發行版的工作量被安全債佔滿：openRuyi 46 筆裡，帶 [security-fixes] 的雲原生元件更新與整套 Sequoia PGP 遷移是主體。RISC-V 伺服器要承接真實業務，先要把簽名、金鑰與中介軟體 CVE 這些「非架構問題」清完。
  • 機器人棧從演示轉向可複製：進迭時空把宇樹 Go2 拉上 K3，並補齊語音與圖傳，路線從「自家人形能跑」轉向「第三方機型可適配」。這類工作對平臺的檢驗，比引數更有說服力。
  • 侷限說明：Onsemi 收購 Codasip 的價格、人數與支付比例來自捷克媒體 e15 的報道與 Jon Peddie Research 轉述，兩家公司均未公佈交易條款；Codasip 的公共資助資料引自其自身口徑；SiFive 的 Google 部署與 X100 授權客戶資訊來自 SiFive 博文與 JPR 轉述，未獲客戶確認；MIPS 的 S8200 能效倍數、2027 年矽參考平臺時間與「前十二大車企中的九家」均為公司口徑；香山 35 筆、openRuyi 46 筆為 GitHub 提交頁逐頁核對所得，作者日期與提交日期分離屬批次回收特徵，具體動機未見專案公告；算能、進迭時空、芯來的提交內容依據提交標題與 README 判斷，未逐條核對補丁；LibreLane 一節的工序數、ATPG 圖形數與覆蓋率來自演講摘要，活動尚未舉行，資料待現場核實；會員官網巡檢檢出的變化多為高校與機構首頁例行更新，僅 RISC-V 協會（日本）的會議議程構成實質資訊。另：中科通量在 CNCC 2026（10-21 至 24，成都）的展臺報道為同一批產品（SmarCo AI 工作站 12 核 RISC-V／250 TOPS INT8／128GB 統一記憶體）的復展，規格已於 10-20 日報收錄，本期不重複；睿芯高光 D35 的「12nm 超越英偉達 7nm」報道系 9-23 內容的再次流轉，同樣不重複。
