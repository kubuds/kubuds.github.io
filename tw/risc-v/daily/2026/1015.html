今日重點：進迭時空端側 Agent 全棧集中公開：BiBit GUI 與語音服務釋出 1.0Beta1，Bianbu AgentOS 元件開源

日期：2026-10-14　來源：bibit Release 1.0Beta1（10-14）、bibit-voice Release 1.0Beta1（10-14）、bianbu-agent-runtime 初始匯入（10-14）、bianbu-agent-memory 初始公開快照（10-14）

接續 10-13 的集中建倉（上期日報已報道），進迭時空在視窗內把端側 Agent 系統軟體棧（Bianbu AgentOS）整體推向公開：桌面端 BiBit GUI 與離線語音服務 Bibit Voice 釋出 1.0Beta1，Agent 執行時、記憶服務、安全元件等集中開源。要點：

  • BiBit GUI（1.0Beta1）：面向 Agent 系統助手的桌面前端，以開源專案 Jan 為程式碼骨架（React 19＋Tauri 2＋Rust，Yarn 4.5.3 構建鏈），當前保留並演進對話互動、富訊息、附件、會話歷史與設定介面；面向 Bianbu 4.x riscv64 提供 Debian 原生包（原始碼內固定 Yarn 版本以適配 RISC-V 構建機記憶體約束）；Agent Runtime 暫沿用 Jan 相容實現、後續經 Adapter 接入正式執行時。
  • bianbu-agent-runtime（初始開源）：YAML 配置驅動的 Agent 服務，自述為 Bianbu AgentOS 的執行時核心——會話即事件流（多端同一投影）、外掛可貢獻 Tool／Skill／Hook／MCP／Console 頁面、securityd 簽名清單與 Tool 審批等安全邊界（生產模式 fail-closed）；當前僅支援 K3（riscv64，Bianbu 4.0）。
  • bianbu-agent-memory：裝置側、本地優先的記憶服務（Rust 守護程序＋Python SDK＋Unix socket 協議）——L1 會話事件／L2 工作摘要／L3 長期記憶三層，本地全文檢索、SQLCipher 加密、版本衝突檢測與名稱空間隔離；提供 CLI、MCP 服務與 Runtime Bridge，並含 Hermes 與 DeepSeek Harness 介面卡。
  • Bibit Voice（1.0Beta1）：面向 K3／Bianbu Desktop 的離線語音服務棧——喚醒詞檢測（KWS）、語音活動檢測（VAD）與語音識別（ASR，SenseVoice／Qwen3-ASR），基於 PipeWire 採集與 sherpa-onnx SpacemiT runtime；對外提供兩層 Unix socket 與 MCP（8 個工具），喚醒應答音「我在」隨包分發。
  • 同批開源元件：bibit-intent（邊緣優先意圖路由與工具執行）、bibit-filesearch（本地檔案搜尋服務）、bibit-runtime-plugin、bianbu-agent-security 初始公開；另 mpp 媒體處理庫改用 MIT 許可並統一版權宣告，ai-sdk 增設 KWS 子模組與中英架構圖，docs-product 新增 V100 系列（C2201／S5236／G5201）產品頁骨架。

上述元件與 K3 硬體、Bianbu 發行版形成「晶片—系統—Agent 執行時」的縱向組合；Bianbu AgentOS 以單一平臺（K3）先行驗證、再向其他平臺擴充套件的路線已較清晰。

一、開源社群與軟體生態

1.1 Linux 核心補丁讓「本機是否 RVA23 合規」一鍵可查

日期：2026-10-14　來源：Phoronix：Linux Finally Making It Easier To Answer The Question: “Is This RISC-V System RVA23?”（10-14）、LPC 2026 演講《RVA23 in practice》材料（10-02）

Phoronix 報道：Linux 使用者即將能「一次性」回答「我的 RISC-V 系統是否 RVA23 合規」——待合入的核心補丁提供了單次查詢能力（現狀需拼合 /proc/cpuinfo、hwprobe 與檔案要求逐項比對，Ubuntu 側工具此前只能給出「probably RVA23」）。報道配圖即為一臺 SpacemiT K3 的 RVA23 報告截圖。背景（與本系列此前報道銜接）：該能力即 LPC26 上披露的 **riscv_hwprobe 單位元方案（KEY_BASE_BEHAVIOR：IMA RVA23U64，開機從完整 ISA 點陣圖一次性計算）**——系列補丁由 Andrew Jones 發起 RFC、現由徐國棟（Guodong Xu）推進，已於 10-09 達到 v8（11 枚 patch 中前 8 枚被收入 riscv/for-next），v9 將補充 RVA22／RVA20 分級位。RVA23 檔案對統一現代 RISC-V 二進位制分發意義重大（Ubuntu 現代版本已將其列為基線，合規硬體仍有限）。

1.2 RISE 專案釋出 SpeexDSP 的 RVV 向量最佳化成果：重取樣最高加速 4.88 倍

日期：2026-10-13~10-14　來源：RISE Project：Accelerating Audio Processing with SpeexDSP Optimizations for RISC-V（10-13）、Hacker News 討論（10-14）

RISE（RISC-V 軟體生態）專案刊出 RP020 結項成果：為實時音訊基礎庫 SpeexDSP（音訊重取樣、回聲消除、抖動緩衝與預處理，被 VLC、Firefox、Wireshark、PulseAudio、Mumble 等廣泛使用）引入手寫 RVV 彙編，並現代化其構建與驗證設施。要點：

  • 效能：手寫向量重取樣核心對比「編譯器自動向量化 C」——浮點核心加速 3.71 倍（Clang 18）／3.59 倍（GCC 13）；定點核心 2.69 倍（Clang 18）／4.88 倍（GCC 13）（後者 GCC 未能自動向量化）。
  • 跨硬體驗證：得益於 RVV 的長度無關特性，同一份彙編在 SpacemiT K1（VLEN=256）與 Canaan K230（VLEN=128） 兩類物理平臺均有效。
  • 驗證基建外溢收益：Meson＋Checkasm 校驗順帶發現並修復了 SSE2 核心一個歷時 8 年的資料依賴缺陷（內積核心此前比標量 C 還慢 0.58~0.75 倍）。
  • 組織形式：由 Google 工程師與 RISE 合作推進（技術負責人 Nathan Egge，承包商 FFlabs／Tristan Matthews），RISE 資助 4 萬美元。

1.3 openRuyi：韌體線釋出「Ruyi Firmware 20261014」，K3 雙簇 CPU 模式選擇落地

日期：2026-10-14　來源：Ruyi Firmware 20261014 Release（10-14）、edk2-ruyi：K3 persistent CPU selection modes（10-14）、openRuyi 提交記錄（10-14）

openRuyi 韌體線釋出 「Ruyi Firmware 20261014」，核心特性為 K3 平臺的 CPU 簇模式選擇：UEFI Setup 新增模式開關，設定持久化到 SPI 專用扇區並由 coreboot 在 OpenSBI 啟動前讀取（下次啟動生效，韌體升級則恢復預設）；提供三種模式——X100 only（預設，8 核、RVV VLEN 256、保留 H 擴充套件）、X100＋A100（16 核）、A100 only（8 核、VLEN 1024），並在 fastfetch 等工具中按 k3／k3-x100-a100／k3-a100 顯示。實現細節：A100-only 引導透過 SBI HSM 將 SEC 從 hart 0 移交 hart 8（等待原 hart 停止後複用棧），UEFI 交接樹中禁用 X100 節點但保留物理 IMSIC 槽位編號，裝置樹根相容串同步反映模式供使用者態命名（無需改 Linux 原始碼）。主倉側同步合入 Mesa 26.2.4 升級與 PowerVR（pvr）最佳化回移、mesa-gallium 推薦 mesa-vulkan-drivers 等 SPECS 更新；openRuyi 官網新聞頁暫無新版本（最新仍為 2026.09）。

3.2 奕斯偉計算：開源 RISC-V 矩陣擴充套件（AME）BF16 GEMM 測試向量庫

日期：2026-10-13~10-14　來源：eswincomputing/riscv-matrix-gemm-vectors（10-14 更新）、更新提交（10-14）

奕斯偉計算（ESWIN Computing）開源 riscv-matrix-gemm-vectors 倉庫（10-13 建立、10-14 補充版權與 README）：面向 RISC-V 矩陣擴充套件（AME）規範提案 v0.6.0 的 BF16×BF16→FP32 矩陣乘累加測試向量集——每個用例為裸機程式（執行運算、自校驗並寫回判決），隨附與實現無關的參考值及結果檢查器 check.py。判定採用標準舍入誤差界（ Ĉ−C* ≤ γ(G)·Σ a·b ，預設 G=K）而非逐位比對，以適配規範允許的「無序求和」實現差異（正負乘積抵消時正確結果可距精確和數千 ULP）；同時提供兩個「所有合規實現結果位相同」的用例以檢出錯誤舍入。參考值與判據不依賴具體指令集，可複用於其他矩陣擴充套件實現，屬國內廠商面向 AME 生態的測試基建貢獻。

3.3 香山：昆明湖主線最佳化 L2 訪存延遲；驗證鏈（difftest／NEMU／GEM5）持續迭代

日期：2026-10-14　來源：XiangShan #6713：reduce L2 load-to-use latency（10-14）、XiangShan ICache 修復（10-14）、difftest：GBD1 DMA drain（10-14）、NEMU #1251（10-14）、GEM5 #1228（10-14）

香山（kunminghu-v3）視窗內合入 dcache 效能最佳化——降低 L2 load-to-use 延遲（#6713），並修復 ICache 異常傳遞（#6414）與取指塊末偏移在資料 ECC 場景下的 bank 選擇、支援 Zimop（MOP）指令解碼（解碼為 add rd, x0, x0）。驗證與模擬基礎設施：difftest 為 GBus DiffTest 增加 GBD1 frozen-bank DMA drain（面向 FPGA 場景）；NEMU 修復 AME 矩陣儲存回滾記錄（#1251）與 vcompute REM 分支判斷（#1253）；GEM5 恢復 macOS 構建並新增手工冒煙 CI（#1228）、對齊 xsstream 活躍區判定（#1223）。XSCache 視窗內無主分支新提交。

3.4 算能：zsbl 啟動鏈重構為兩級平臺模型；HD12 伺服器韌體更新

日期：2026-10-14　來源：zsbl：平臺子系統與應用拆分（10-14）、mcu：HD12 韌體更新（10-14）

算能（SOPHGO）雙線更新：zsbl（零級啟動載入器） 將平臺組織重構為「子系統×應用」兩級模型——一個平臺可承載多個 CPU 子系統、每個子系統可執行多個引導應用（如 PLAT_SG2044／SG2044_MP／SG2044_MP_ZSBL），各子系統原始碼移入 plat///，平臺級僅保留共用標頭檔案與記憶體對映，並引入平臺級 Kconfig；同時將 PLAT_BM1690TP 更名 PLAT_BM1690（BM1690 為 SoC、TP 為子系統）。**伺服器 MCU／BMC 韌體（mcu）** 為 HD12 主機板合入 **RHS12 板卡相容、C2C 互連鏈路（啟動／清理與狀態檢查）、64GB DDR 支援，以及 MCU／BMC 引導日誌經 I2C 暴露**（韌體版本升至 14）。

3.5 矽速：邏輯分析儀軟體 SLogic 釋出 v2.3.0，引入共享採集引擎

日期：2026-10-14　來源：SLogic Release release-2.3.0（10-14）、SLogic 提交記錄（10-14）

矽速（Sipeed）邏輯分析儀軟體 SLogic 次日再發新版：v2.3.0 引入共享採集引擎（要求韌體 202610140927 及以上），支援 0% 觸發位置（主機側預觸發緩衝）、按鏈路能力限制取樣率並增加鏈路標籤、冷啟動計時改為自 RUN 指令起算、修復 Windows 下 ngscopeclient 構建問題；釋出說明提供中英雙語。配套 ALL-LOGIC 庫視窗內 7 筆提交（觸發位置、鏈路限速、除錯級別實時速率等）。矽速組織視窗內共 6 個倉庫推送（另含 libsigrok、scopehal、pulseview），邏輯分析儀軟硬體迭代保持高節奏。

四、具身智慧與機器人專章

4.1 端側 Agent 基建走向「系統級封裝」：Bianbu AgentOS 與 K3 的組合交付觀察

日期：2026-10-14　來源：bianbu-agent-runtime（10-14）、bibit-voice（10-14）、spacemit-robotics 組織倉庫

本視窗具身智慧與機器人側的主要觀察點是「端側 Agent 基建的系統級封裝」：進迭時空以 Bianbu AgentOS 名義開封完整鏈路——桌面前端（BiBit）、執行時、本地記憶、離線語音（KWS／VAD／ASR）與安全元件（見今日重點），且明確以 K3（riscv64）為首發且當前唯一支援平臺。對機器人／邊緣裝置而言，這意味著「語音喚醒—意圖理解—工具執行—長期記憶—審計安全」的可自部署開源棧首次在 RISC-V 上有成套樣板，而非零散 SDK。配套地，硬體側 K3 的 CPU 簇模式選擇（X100／A100，見 1.3）為「效能核跑推理、能效核跑控制」的異構分工提供了韌體級選項。相對地，機器人專項組織 spacemit-robotics 視窗內無新推送（外設 IMU／電機／感知庫最近推送為 10-12）；「晶片＋Agent 軟體棧＋場景封裝」的組合交付仍在深化，軟體棧正從「能用」走向「可維護、可審計」。

五、總結與趨勢觀察

  • 端側 Agent 成為 RISC-V 軟體棧新焦點：進迭時空集中公開 Bianbu AgentOS 全棧（GUI／執行時／記憶／語音／安全），以 K3 先行驗證——與藍芯算力等「伺服器化」敘事形成對照，RISC-V 在端側 AI Agent 基礎設施方向出現成套開源棧。
  • 基建兩端同時補強：Linux 核心 rva23u64 單位元查詢接近落地（Phoronix 報道；v8 部分已進 riscv/for-next、v9 在途），RISE 為 SpeexDSP 補上手寫 RVV 向量核心（重取樣最高 4.88 倍）——「資格認證（RVA23）＋多媒體效能（RVV）」兩條主線同期推進。
  • 峰會周臨近：RVSC2026（10-18~20 深圳）會前物料（宣傳稿、議程、展廳圖、同期活動）全部就緒，疊加 10-17 進迭時空開發者大會、10-21 GBA／HK Day、10-22 玄鐵北京研討會；Ubuntu 26.10 攜首批官方 RISC-V 桌面映象定於 10-15 釋出，為下期重點觀察。
  • 國內工程側高密度輸出：達摩院玄鐵補 BF16 向量測試、奕斯偉開源 AME 測試向量、香山最佳化 L2 訪存延遲並修 ICache、算能重構啟動鏈與伺服器韌體、矽速連發 SLogic 兩版。
