一、開源社群與核心/版本動態

1.1 Linux 7.2 釋出盤點：RISC-V 側 NR_CPUS 提升至 256、奕斯偉進入 defconfig（08-21）

日期：2026-08-16（核心釋出，LKML）／2026-08-21（CNX 架構級盤點報道，06:00 北京）　來源：CNX Software、Linux Journal

Linus Torvalds 於 08-16 釋出 Linux 7.2（LKML），CNX 於 08-21 出架構級盤點，RISC-V 側更新密集。通用亮點：cache-aware 任務排程（同程序執行緒按 LLC 域共置）、受 CFS 啟發的 Fair GPU 排程器、USB4STREAM 直連流式傳輸、swap table 第四階段。RISC-V 專項：

  • NR_CPUS 64 位預設值提升至 256——官方理由直指國產多核機器：進迭時空（SpacemiT）已產 80 核 RVA23 伺服器，雙路 SG2042 的算能 Pisces 達 128 核，預設 64 已不夠；
  • 奕斯偉（Eswin）SoC 加入 RISC-V defconfig——國產廠商進入主線預設配置，合入門檻高於普通驅動；
  • 平頭哥 TH1520：PWM 修復，BeagleV Ahead、Lichee Pi 4a 兩塊板開啟 WiFi；
  • 進迭時空：K1 增加 SPI/thermal 驅動與 I2C 使能、K3 增加 USB2 PHY 與 ASoC 驅動、P1 晶片補 reboot cell；K1 板級外設大量使能（Milk-V Jupiter eMMC、Muse Pi Pro EEPROM/PCIe/QSPI/USB、OrangePi R2S PMIC/USB3、OrangePi RV2 全外設）；新增 CoM260-IFX 與 DeepComputing FML13V05 兩塊 K1 板；
  • 算能：Milk-V Duo S 增加 bindings；SG2042/SG2044 裝置樹修正（CPU 地址改十六進位制、MSI 實際僅 16 中斷、PCIe RC 標記快取一致性）；
  • 賽昉：JH8100 中斷控制器因該晶片未量產即停產，改名重做為 JHB100 版；JH7110 加入 SiFive ccache 非標準 cache 操作名單（GPU DMA 非一致）；JHB100 新增 clint 繫結與 SGMII GMAC 支援；
  • 核心修復：kexec_file 大記憶體早期啟動、無條件 sfence.vma、kfence 誤報修復、CFI vDSO 補丁、ftrace_graph_ret_addr、BUILDTIME_MCOUNT_SORT 降低啟動開銷等。

7.3 merge window 已隨釋出開啟（Linus 稱已有 40 個待合入 PR）；Phoronix 報道 7.3 將大規模淘汰舊 32 位 ARM 平臺（ARM 側重構，對 RISC-V 影響待觀察）。本次盤點印證：Linux 主線正為”80-128 核國產 RISC-V 伺服器”批次鋪路。

1.2 NetBSD 11 落地 64 位 RISC-V 支援（08-20）

日期：2026-08-20（The Register 報道 21:45 北京；HN 同步）　來源：The Register、HN 討論

NetBSD 第 19 個主版本 11.0（07 月底釋出）獲 The Register 長篇評測：新增 64 位 RISC-V 支援（Tier II 平臺，面向 QEMU 虛擬化環境），使 NetBSD 成為繼 Linux、FreeBSD 之後又一對 RISC-V 提供主線支援的 BSD 系作業系統。11.0 同時帶來：MICROVM 專用核心（x86 客戶機約 10 毫秒冷啟動，2020 年代處理器實測）、POSIX.1-2024 與 C23 合規提升、Linux 系統呼叫相容增強、Xen/QEMU 執行最佳化、52 個 Tier II 平臺與 9 個 Tier I 平臺。評測同時指出 NetBSD 保持”老派”風格：sysinst 文字安裝器、需手改 /etc/rc.conf、商業驅動稀少。對 RISC-V 生態的意義：BSD 陣營的 RISC-V 支援補齊，虛擬化場景（QEMU）先行落地。

二、產品與生態動態

2.1 Andes 關閉 Condor 設計中心，Cuzco 資料中心級核心 IP 迴歸母公司（08-17/08-20）

日期：2026-08-17（Jon Peddie Research 首曝）／2026-08-20（EE Times 跟進報道，06:00 北京）　來源：Jon Peddie Research、design-reuse 轉載、EE Times

晶心科技（Andes Technology）正式關閉其美國德克薩斯州奧斯汀的高階設計中心 Condor Computing（2023-03 成立，近 100 人、85% 以上為研發）。Condor 承載 Andes 衝擊資料中心級 RISC-V 的旗艦專案 Cuzco 核心——RVA23 合規、可授權，採用新型專利微架構（深度亂序執行 + 非常規時間排程設計，Hot Chips 2025 公開）。現狀：Cuzco IP 迴歸 Andes 母公司，無後續 test silicon 開發；團隊從 50 人砍至 15 人、再縮至個位數真正理解該 IP 的工程師；原 CEO Ty Garibay 已轉任 Ambiq 的 SoC Design VP。關閉屬 2026-04 公佈的成本削減計劃一部分：董事長兼 CEO Frankwell Lin 承認過去三四年擴張過快、營收未匹配，計劃削減運營開支 10-20%、全球員工從 480 降至約 450（EE Times 估計當前已約 400）。

產業意義：Jon Peddie Research 分析師 David Harold 直言，這是”對 Andes 高階野心的挫折，也是 RISC-V 在資料中心建立 Arm/x86 可信替代努力的一次退卻”。與 1.1 中 Linux 主線為多核伺服器鋪路形成對照——軟體側在加速，IP 供應商陣營卻在洗牌收縮。

香山組織視窗內共 20 筆提交，主倉庫（XiangShan）落 4 筆實質提交，效能向迭代明顯：

  • timing(WritebackQueue): use lowestIndexFirst policy (#6379)（08-20 10:59 北京）——寫回佇列改 lowest-index-first 排程策略，訪存後端時序最佳化；

3.2 進迭時空：K1 軟體棧 v2.2.11 版本更新（08-20）

日期：2026-08-20（09:07 ~ 17:25 北京）　來源：spacemit-com/buildroot-ext、uboot-2022.10、mpp、v2d-test

進迭時空組織視窗內 22 筆提交，核心是 K1 軟體棧 v2.2.11 版本整包更新：buildroot-ext、uboot-2022.10、v2d-test 同步至 v2.2.11，其中 K1 buildroot 將 GENERIC_HOSTNAME 改為 “K1-Buildroot” 並將根檔案系統擴至 1GB（適配更大軟體集）；mpp 媒體管線兩筆工程化重構（stream manager 移出 mpi 介面層、AL module 構建目標拆分），v2d-test 修復 K1 buildroot 構建錯誤。延續 08-18 已報道的”K1 主線核心 7.2 經 meta-riscv 落地 Yocto”節奏，本輪為 BSP 整包版本化交付，媒體管線在向可獨立維護的模組結構演進。

五、總結與趨勢觀察

  1. Linux 7.2 是國產多核 RISC-V 伺服器的主線里程碑：NR_CPUS 預設提至 256（點名 SpacemiT 80 核、Sophgo Pisces 128 核）、奕斯偉進入 defconfig、進迭 K1/K3 外設大規模使能——主線與國產高階 SoC 的耦合明顯加深；
  2. 資料中心級 IP 陣營洗牌：Andes 關閉 Condor、Cuzco 迴歸母公司，是繼 SiFive 收縮後的又一訊號；高階 RISC-V 核心競賽的”中國雙雄”（平頭哥/賽昉）權重進一步上升，軟體側鋪路與 IP 側收縮並存；
  3. BSD 生態補齊：NetBSD 11 提供 64 位 RISC-V 主線支援，主流開源 OS 對 RISC-V 的覆蓋再下一城；
  4. 國內團隊節奏分化：香山（效能微調期）、進迭時空（v2.2.11 整包交付）高活躍；平頭哥/芯來/賽昉/奕斯偉倉庫靜默，但奕斯偉的合入動作在主線 defconfig；
  5. 平靜日說明：gnews 中文查詢視窗內為空、廠商英文查詢多為已報道事件，國內動態主要靠 GitHub 組織檢索捕捉（見附錄核查表）。

侷限性說明：Linux 7.2 RISC-V 變更以 CNX 轉述為準、未逐條核對核心 changelog；Andes 關閉細節（團隊規模、headcount）以 EE Times/JPR 報道口徑為準，未經 Andes 官方確認（官方未發正式公告）；NetBSD 11 為 The Register 評測視角，RISC-V 埠屬 Tier II（QEMU）而非 Tier I 實機；香山/進迭提交按 committer 時間歸類，個別提交的 author 日期可能早於視窗。
