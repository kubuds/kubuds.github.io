今日重點：蘇州睿芯「高光 D35」RISC-V 資料流物理 AI 晶片量產獲園區官方確認

日期：2026-09-14（廠商量產釋出 09 月上旬）　來源：蘇州工業園區管委會官網《RISC-V 資料流物理 AI 晶片量產！》、極客公園《全球首款 RISC-V 資料流物理 AI 晶片「高光 D35」量產》、新浪財經《跨越架構週期：睿芯高光 D35 與資料流的邊緣突圍》

蘇州工業園區管委會官網於 09-14 14:25 刊發即時動態，確認蘇州睿芯積體電路科技有限公司自主研發的「高光 D35」資料流 AI 晶片正式實現量產，並稱其為「全球領先的基於 RISC-V 指令集的資料流架構物理 AI 晶片」，標誌著資料流計算這一提出已逾 60 年的架構路線從學術研究階段進入規模化商用。廠商口徑給出的三項「領先級」定位為：首款實現商業化量產的資料流架構 AI 晶片；將 RISC-V 開放指令集與資料流計算架構深度融合的雙路線方案；明確錨定「物理 AI」而非雲端大模型算力的產品定位。硬體側披露的一項關鍵引數是配備 128 GB 大視訊記憶體，用於支撐更大規模模型在邊緣側本地部署，強調資料不出端、響應更快。企業側，睿芯成立於 2020 年 8 月，總部位於蘇州工業園區（獨墅湖科教創新區），核心團隊來自中國科學院計算所、中國科學院自動化所、IBM、Intel 等機構，研發人員佔比超 70%、碩博學歷成員達 50%，已發表 100 餘篇學術論文，相關成果獲 ISCA 2026 國際計算機體系結構頂會最佳論文提名；另有報道稱公司首席科學家為中國工程院院士孫凝暉。公司已完成五輪融資。

產品落地層面，官方與廠商稿共同給出的場景劃分為四類：行業智慧計算（AI PC 加速、影片壓縮與分析、工業智慧控制）、具身智慧（機器人、無人車域控等感知加決策加控制一體化場景）、艙駕一體（智慧座艙與駕駛域控融合）、通訊（5G 小基站、毫米波、AI RAN）。生態側，睿芯宣佈即將啟動「光榮社群」，定位為面向資料流架構的 RISC-V 開發者社群，提供文件中心、SDK 工具鏈、模型庫、線上實訓與技術論壇，並設立「睿芯光榮基金」支援生態創新。技術論證上，廠商把能效比作為核心賣點，稱全資料流架構相比同類競品能效比提升數倍，理由是省去指令排程開銷、資料在計算單元間直接流動而非反覆讀寫記憶體、無分支預測失敗與快取失效帶來的延遲不確定性。

為何值得關注：這一條是本刊 9 月首次收錄的資料流架構量產事件，且此前未被本系列日報覆蓋（經全庫檢索確認）。其分量在於三點：其一，資料流（dataflow）路線長期停留在論文與小批次驗證階段，若有廠商宣稱進入量產交付，意味著該路線在中國出現了商業化樣板；其二，它是「RISC-V 加非馮諾依曼架構」的少見組合，與國內主流的「RISC-V 加向量/矩陣加速」路線形成對照，為端側物理 AI 提供另一種算力正規化；其三，具身智慧被其列為四大落地場景之一，與本期第四章的機器人軟體棧動態形成上下游呼應。需要注意的邊界：本條的量產宣稱、能效比倍數與「自研 RISC-V CPU 核心獲 Intel 全球唯一採購認可」等表述均來自廠商與媒體稿，尚無第三方獨立測試或客戶量產案例佐證，本報告按廠商口徑收錄並標註，後續應跟蹤其 SDK 開放程度、社群啟動實況與真實出貨規模。

1.1 香山昆明湖：分支預測與向量通路修復集中合入，IFU/FTQ 補自修改程式碼分支訓練

日期：2026-09-14　來源：OpenXiangShan/XiangShan 提交記錄

開源高效能 RISC-V 處理器香山（昆明湖 V3 分支）在視窗內共 8 次提交，延續「新特性收斂後轉正確性打磨」的節奏，重心集中在分支預測與取指側。分支預測方面，zhou tao 於 09-14 22:42 提交 #6484，為 IFU 與 FTQ 增加「誤預測時的直接跳轉分支訓練」，專門處理自修改程式碼（self-modifying code）引起的誤預測——這類場景在動態生成程式碼、JIT 與載入器自改寫場景中常見，是模擬與真實執行差異的典型來源；Muzi 於 22:41 提交 #6569，修正 ITTAGE 預測器中 useful 計數器掩碼從條目欄位推導的邏輯，並同日更新效能檢查點（#6568）；Zhihao Xu 於 22:50 提交 #6461，對 Bpu 做使能修正與除錯相關修復並清理程式碼。取指與異常方面，lengard2019 於 14:42 提交 #6428，修正 IFU 在異常與不可快取訪問同時觸發時的異常 PC 傳遞，屬特權態邊界正確性修復；Zhihao Xu 同日提交 #6553，清理已廢棄的 0604 傳統效能測試基線。向量通路方面，Xuan Hu 於 11:02 連續兩次提交（#6565、#6564），將向量源運算元反轉的時機移到讀暫存器之後，併為 VMove 結果補上浮點 boxing，避免窄位寬浮點值在暫存器合併時丟失 NaN-box 語義。整體看，當日提交幾乎全部是「正確性與邊界條件」類修復，未見新特性級推進。

1.2 XSCache：ZhuJiang（L3）子模組批次合入，HN 效能計數器改為按模組路徑命名

日期：2026-09-14　來源：OpenXiangShan/XSCache 提交記錄

香山配套的開源 L2（RN）與 LLC（HN）快取倉庫 XSCache 在視窗內一次性落 18 次提交，但提交時間集中在 09-14 17:48（北京時間），而作者日期橫跨 2026-06-10 至 09-10，屬典型的批次合入收尾（作者與提交日期不同日，本報告按合入時間計）。內容主線有三：一是 ZhuJiang（香山 L3 快取方向子模組）相關工作的集中落地，包括引數化 cfgAxiDataBits、為 ZhuJiang 適配 gsim 模擬環境、修復 resetgen 與復位同步、修復 FIRRTL 構建相容性、啟用 stash refill 跟蹤、以及新增 TestTopZhuJiang 測試頂層（支援 CoupledL2 加 ZhuJiang 組合、配置最小化 DongJiang 以加速模擬、初始化 ChiselDB）；二是效能計數器能力，zhengzhongqiang 提交 feat(perf): name HN collectors by module path，把 HN（Home Node）效能計數器從匿名編號改為按模組路徑命名，便於與香山頂層做聯合計數採集，同批加入「與香山協同採集 ZhuJiang 計數器」的能力；三是若干測試與適配修正（關閉 ZhuJiang 測試頂層的 DataCheck 與 Poison、保留 DCT home node ID）。本條的價值在於揭示香山的記憶體系統正在向「CoupledL2 加獨立 L3（ZhuJiang）」的配置演進，且配套模擬、復位、構建與效能採集鏈路已同步補齊——這是 L3 快取進入可驗證狀態的訊號。

1.3 香山模擬與驗證鏈：NEMU 精簡單步邊界，GEM5 校準 SBUFFER，difftest 切 slim 容器

日期：2026-09-14　來源：OpenXiangShan/NEMU 提交記錄、OpenXiangShan/GEM5 提交記錄、OpenXiangShan/difftest 提交記錄

香山驗證工具鏈在視窗內出現一組以「效能與效率」為目標的改動。NEMU（香山參考模型，超高速 RISC-V ISA 模擬器）由 Kamimiao 於 10:42 連續兩次提交：perf(difftest): lazily prepare CSR shadow for REF（為參考模型延遲準備 CSR 影子副本，減少每步開銷）與 perf(share): trim single-step execution boundary（裁簡單步執行的邊界），兩條都直接作用於差分測試（difftest）每步執行的固定成本，屬模擬吞吐最佳化。GEM5 香山分支由 ZHEN HAO 於 19:23 提交 cpu-o3: Calibrated SBUFFER behaviour（校準亂序流水線中 Store Buffer 的行為以貼近真實硬體）。difftest 框架由 Kunlin You 於 16:49 提交 #965，將 CI 容器從完整映象切換為 slim 映象並移除 GSIM 安裝步驟，降低持續整合環境的體積與準備時間。三者合併觀察：香山的驗證基礎設施正在同時做「跑得更快（NEMU/GEM5）」與「起得更輕（CI 容器）」兩件事，屬於大規模迴歸測試前的常態最佳化。

1.4 LLVM/Clang RISC-V 後端：RV32 下 f16 轉換拆解，新增 packed widening add accumulate 內建

日期：2026-09-14　來源：OpenXiangShan/llvm-project 提交記錄

香山維護的 LLVM 分支在視窗內推進 17 次提交，其中兩條為 RISC-V 目標相關：Kane Wang 於 15:42 提交 [RISCV] Lower f16 to i64 fp_to_[su]int via i32 on RV32 (#222829)，在 32 位 RISC-V 上把半精度浮點到 64 位整數的轉換拆解為經 i32 的兩步路徑，屬 RV32 目標下的程式碼生成合法化修正；陳子昂於 15:05 提交 [Clang][RISCV] Add packed widening add accumulate intrinsics (#221622)，為 RISC-V 向量擴充套件增加「打包加寬累加」內建函式——這類內建直接對應向量點積/矩陣乘累加場景，是 AI 推理與訊號處理核心的常用原語。其餘提交為上游通用改動（GlobalOpt 斷言修復、分配器對齊、ORC 執行時、libc 數學函式、LoongArch/SPARC 測試等）。結合本期香山在向量通路上的多次修復，可以看出香山的軟體側（編譯器與參考模型）與硬體側（向量執行）在同一周內同步推進。

1.5 CORE-V 生態：Wally 修 PWM 自檢與 IFU 三連缺陷，CVFPU 補除法開方 NaN boxing

日期：2026-09-14　來源：openhwgroup/cvw 提交記錄、openhwgroup/cvfpu 提交記錄、openhwgroup/uap 提交記錄

OpenHW 集團的開源核生態在視窗內多點推進。CORE-V Wally（cvw，面向教學的配置化 RISC-V 處理器）由 David Harris 於 09-15 03:56 提交 #1830，修正 PWM（脈寬調製）外設的 pending 位、計數器復位與 pwms 暫存器寫入問題，並新增一套完整的自檢式 PWM 測試；同日 IFU（取指單元）缺陷被成批修復，Rose Thompson 合併 #1855（satp 相關）、#1862（JALR 最低位處理）、#1861（flushm）、#1860（匯流排故障），四項均為取指路徑正確性問題；Syed-Moeed-Ali 於 13:01 提交 #1864，修正不支援 U-mode 時 mcounteren 被非法訪問的問題。CVFPU（引數化浮點單元，支援標準 RISC-V 浮點格式）由 Ihsane Tahir 於 16:32 合併 #185，修復除法與開方路徑的 NaN boxing。UAP（統一 RISC-V 接入平臺）由 sergialcaide 於 18:31 提交 #168，新增 BSC IP 卡支援。整體看，CORE-V 家族本視窗的改動集中在外設自檢與取指/特權態正確性，與香山同期「正確性打磨」的取向一致，反映開源核社群普遍進入功能驗證深水區。

1.6 openRuyi：9 月釋出頁不存在，最新正式版仍為 2026.08

2.1 JetKVM Mini：ESP32-P4X 雙核 RISC-V 的 39 美元 IP-KVM，內建 H.264 硬編，10 月 26 日開售

把今日重點的睿芯高光 D35 放在具身智慧視角下看，其給出的四條場景線中有兩條直接落在機器人方向：具身智慧（機器人、無人車域控等「感知加決策加控制」一體化場景）與艙駕一體（智慧座艙與駕駛域控融合）。其技術論證的核心是端側能效比而非峰值算力——理由是物理 AI 場景下供電、體積與成本構成硬約束，端側不可能外接資料中心，因此「單位瓦特能完成多少推理」取代「模型引數有多大」成為勝負手；資料流架構因為省去指令排程開銷、資料在計算單元間直接流動、缺乏分支預測與快取失效帶來的延遲不確定性，被其定位為更匹配這類確定性低延遲推理的路線。硬體上 128 GB 大視訊記憶體的產品定義，指向「大模型在端側本地部署、資料不出端」這一與具身智慧隱私與實時性需求直接對應的能力主張。對照觀察：本刊同期持續跟蹤的進迭時空路線是「RISC-V 通用 CPU 加自研推理後端加模型庫」（見 3.3 與 4.1），睿芯則代表「RISC-V 控制核加專用資料流加速陣列」的非通用路線；兩者在 RISC-V 與具身智慧的結合上給出了不同答案。前者生態門檻低、複用通用軟體棧，後者能效上限高、但依賴自有 SDK 與運算元庫，生態建設難度顯著更大——這也正是其「光榮社群」與 SDK 工具鏈能否落地成為關鍵變數的原因。本報告對其量產與效能宣稱保持廠商口徑標註（詳見今日重點條目）。

五、總結與趨勢觀察

  • 資料流架構在中國出現量產樣板，RISC-V 與「非馮諾依曼」路線的組合值得跟蹤。蘇州睿芯「高光 D35」經蘇州工業園區官方渠道確認量產，定位端側與邊緣的物理 AI 加速，配 128 GB 視訊記憶體，主打單位功耗推理吞吐，並規劃面向資料流架構的開發者社群。這是本刊 9 月首次收錄該類事件。其關鍵在於：若量產與能效比宣稱獲第三方驗證，RISC-V 在 AI 加速領域將不止「通用核加向量/矩陣擴充套件」一條路徑，而資料流路線長期停留學術階段的歷史也可能被改寫。當前證據僅為廠商與官方園區口徑，須跟蹤 SDK 開放度、社群啟動與真實出貨。

  • 開源高效能核集體進入「正確性深水區」。香山當日 8 次提交幾乎全是分支預測、自修改程式碼分支訓練、異常與不可快取同時觸發的 PC 傳遞、向量暫存器 NaN boxing 等邊界條件修復；CORE-V Wally 同視窗修復 PWM 自檢與 IFU 四連缺陷、CVFPU 修除法開方 NaN boxing。兩家開源核的推進重心都落在「正確性驗證驅動」，新特性節奏讓位於已有功能的可靠性收斂。

  • 香山記憶體系統向「CoupledL2 加獨立 L3」演進。XSCache 一次性批次合入 18 次提交，核心是 ZhuJiang（L3 方向）子模組的引數化、復位與構建修復、模擬環境適配，以及配套的 TestTopZhuJiang 測試頂層與 HN 效能計數器按模組路徑命名。這表明 L3 快取正在從開發走向可驗證狀態，配套的模擬、復位與效能採集鏈路已同步補齊。

  • 國產 RISC-V 應用級 MCU 同時推開能力上限與成本下限。JetKVM Mini 以 ESP32-P4X 雙核 400 MHz RISC-V 加內建硬體 H.264 編碼器，做到 39 美元的有線 IP-KVM 與 42 美元的無線版本，且韌體首日開源；無線版另用 ESP32-C5 提供 Wi-Fi 6 與 Zigbee/Thread。與本刊上期收錄的「ESP32-P4 跑起古墓麗影」互為印證：同一顆晶片既能跑 3D 遊戲引擎，也能支撐商用帶外管理裝置。

  • 國內團隊的視窗節奏以「新品適配與工程化打磨」為主。算能 sophon-demo 統一適配 BM1684X2（SE13-64）新硬體目標，是新品釋出前的軟體準備訊號；達摩院玄鐵新建 cove-dp1-poc 空倉庫，指向機密虛擬機器擴充套件方向的概念驗證；進迭時空、矽速的提交則分別落在影片流穩定性與 IP-KVM 文件易用性上。新聞側無新品級釋出，實質動態仍以 GitHub 提交為主。

  • 純 RISC-V IP 授權的財務模型繼續被現實檢驗。芯來科技披露口徑顯示上半年營收增長 41% 但歸母淨虧損擴大約 24.94%，毛利率 87.6%、研發費用率超 100%、股份支付主導虧損，剔除股份支付後虧損逐期收窄。高毛利、高研發、持續虧損的結構，為「RISC-V IP 授權的商業模式是否成立」提供了可比的實證樣本。
