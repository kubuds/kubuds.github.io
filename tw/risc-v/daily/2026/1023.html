今日重點：科華資料與進迭時空簽約，RISC-V 伺服器晶片接入算力基礎設施

日期：2026-10-22　來源：觀點網：科華資料與進迭時空簽署戰略合作協議 共建國產算力生態（10-22）、搜狐：共赴「芯」征程——科華資料與進迭時空達成戰略合作（10-22）

科華資料股份有限公司與進迭時空（北京）智慧科技有限公司簽署戰略合作協議，圍繞技術、產品、市場、生態四個維度開展合作，目標是打通 AI 晶片層與算力基礎設施層 的適配鏈路，共建國產算力生態。

  • 科華側能力：深耕電力電子行業近 40 年、有十餘年資料中心建設運營經驗，業務覆蓋高階電源、精密溫控與資料中心全生命週期運營管理；牽頭主編《國產晶片與算力硬體基礎設施協同技術規範（CCHS）》團體標準，並已與多家國內外頭部 AI 晶片廠商合作。
  • 進迭側產品：K3 為全球首顆符合 RVA23 規範並實現量產的 RISC-V AI CPU；V100 於 10-18 至 20 的峰會期間釋出，官方口徑為全球首款滿足伺服器全規格、符合 RISC-V Server SoC 規範的高效能伺服器級 CPU，同步給出 C2201 計算伺服器、G5201 智算伺服器與 S5236 儲存伺服器三類整機。
  • 合作落點：推動自主可控算力方案從晶片定義、系統適配到規模化部署的全流程貫通；技術上推進 RISC-V AI 晶片與算力基礎設施的協同最佳化，產品上聯合打造面向不同算力場景的解決方案。

伺服器晶片的釋出只是把硬體做出來，能不能進機房取決於供電、製冷、整機設計與運維體系是否願意為它改。這次簽約的實際意義，是把「適配」從晶片公司單方面推動變成基礎設施廠商的聯合工作；而同期境外媒體的分析恰好指出，適配成本正是客戶是否遷移的決定性變數。兩條線索指向同一個結論：RISC-V 雲端的下一程不在釋出會，而在機房。

一、開源社群與軟體生態

1.1 openRuyi：20 筆提交，Python 3.14.9、nginx 1.31.8 與 Node.js 24.22.1 落地

日期：2026-10-22　來源：openRuyi 主倉提交記錄（10-22）、openRuyi 官網新聞頁

openRuyi 主倉在視窗內錄得 20 筆提交，內容以 SPECS 目錄的版本升級與安全修復為主，另有若干打包規範整理。

  • 執行時與語言棧：python 升到 3.14.9（提交標註 security-fixes）、nodejs 升到 24.22.1、openjdk-17 升到 17.0.21.9、openjdk-21 升到 21.0.13.9。
  • 服務與中介軟體：nginx 升到 1.31.8（security-fixes）、python-pillow 升到 13.0.0（security-fixes）、rdma-core 升到 65.0、libudev-zero 升到 1.0.5。rdma-core 是 RDMA 使用者態庫，面向高速網路與 HPC 叢集，屬伺服器發行版的基礎件。
  • 工程整理：opencv 改用構建目錄變數替代硬編碼的 /home 路徑；xmltoman、xinetd、xdg-utils、xcb-util-renderutil、xcb-util-image 等包補上 source checksums 並改用自動變更日誌宏。
  • 官網雙源：新聞頁最新公告仍為 2026.09 版本，視窗內無新版本釋出。

從連續三天的提交看，openRuyi 的補齊順序是 Go 雲原生元件、uv 的 Rust 依賴、再到 Python 與 Node 的執行時主版本。帶 security-fixes 標記的提交成批出現，說明安全更新已經進入流程化通道，而不是零散發補丁。

1.2 社群專案在 ESP32-S31 上跑通 Linux 7.3 與 OpenSBI 1.9

日期：2026-10-22　來源：GitHub：annoyedmilk/esp32-s31-linux（10-22）

社群專案 esp32-s31-linux 在樂鑫 ESP32-S31 上跑通了上游 Linux 7.3 核心與 OpenSBI 1.9，並把 16 MB 八線 PSRAM 當作主存使用。

  • 啟動鏈：ESP ROM 到 ESP-IDF 二階段，再到 loader、OpenSBI、Linux，最後掛 Buildroot 根檔案系統（SD 卡、U 盤或 flash）。
  • 可用使用者態：LCD 上的 shell、wpa_supplicant 聯網、BlueZ 藍芽、SSH、USB 鍵鼠與 U 盤、vim、gdb、strace、MicroPython 以及文字瀏覽器 links。
  • 技術看點：該 SoC 沒有 PLIC、沒有 Zicbom、也沒有一致 DMA，專案用幾百行程式碼給出了替代實現，並寫了面向核心開發者的內部實現文件。
  • 硬體覆蓋：ESP32-S31-Korvo-1、ESP32-S31-Function-CoreBoard-1 與 ESP32-S31-WROOM-3-N16R16V 模組三種構建。

一顆按 MCU 定位設計的雙核 RV32（320 MHz、512 KB SRAM、16 MB PSRAM）能跑完整 Linux 使用者態，說明軟體棧對硬體的要求已經壓得很薄。這類專案不構成產品路徑，但它是檢驗工具鏈、核心移植與驅動成熟度的極端用例，對教學與移植參考都有直接價值。

1.3 香山昆明湖 V3 與 CORE-V cvw：補 mnret/dret 譯碼、jalr 勘誤

日期：2026-10-22　來源：XiangShan 提交記錄（10-22）、cvw 提交記錄（10-22）

香山昆明湖 V3 分支視窗內 3 筆提交，全部落在細節而非功能：decode 補上 mnret 與 dret 兩條特權返回指令的譯碼（#6692）、修正 ROB 重定向起始索引（#6729）、README 增加 Dashboard 與 star 歷史連結（#6696）。

  • CORE-V 側：cvw 倉庫 2 筆，為 jalr 指令在 Table I.1 補上勘誤條目（PR #1996）併合並。
  • 解讀：mnret 與 dret 分別是 M 模式與除錯模式的返回路徑指令，補譯碼意味著香山在完善特權態與除錯支援；jalr 勘誤屬文件級修正，對驗證團隊的價值大於外部使用者。

開源核的進展常常就以這種”看不出功能”的提交為主。判斷一個開源核是否在推進，看的是特權態、異常與除錯這些容易被忽略的角落，而不是又跑通了哪個 benchmark。

二、產品與生態動態

2.1 毫米波雷達的 RISC-V 路線：國產晶片先落地，CPU 槽位仍是第二選項

日期：2026-10-22　來源：RFID 世界網：毫米波雷達 RISC-V 國產搶跑（10-22）

一篇梳理毫米波雷達晶片指令集選擇的報道給出了相當務實的判斷：在雷達晶片裡，RISC-V 與 Arm 目前是並存選項，不是代際替代。

  • 國產先落地：正和微芯 RS6240（2024 年釋出，雙核 RISC-V）已用於智慧家居、康養監護與安防預警；開酷 K60213 內建 RISC-V MCU 與 AI 加速器，進入電視、空調、風扇等室內互動裝置。
  • 車規滲透：芯來 NA900 已獲 ISO 26262 ASIL-D 認證，加特蘭 Kunlun-Pro 內建該核心，雙發射雙核總算力 3668 DMIPS，約為上一代 Alps-Pro 的 5 倍，正往 L2 ADAS 前向感知推進。
  • 分工邊界：外界關注的 10 倍訊號處理算力來自加特蘭自研的 RSP 2.0，不是 RISC-V 核；RISC-V 承擔的是點雲後處理與目標跟蹤這類演算法更新快、必須留在可程式設計 CPU 上的環節。廠商借開放擴充套件介面把排序、插值、三角函式做成硬體指令，實測聚類耗時約減半、跟蹤耗時下降超過 50%。
  • 國際大廠：TI 的 AWR2188、NXP 的 TEF8388 與 SAF8444 仍用 Cortex-A53 與 M7，短期沒有切換動力；奕斯偉在港股上市的招股書也坦言 RISC-V 仍處市場驗證初期，使用者認知與信任度尚未充分建立。

這條的價值在於給出了 RISC-V 在具體品類裡的真實座標：不是”替代誰”，而是”在哪個槽位上更划算”。驅動力是供應鏈可控、成本與定製自由，而非效能代差；功能安全也不是短板，NA900 早已具備 ASIL-D 能力，真正漫長的是整晶片三到五年的認證週期。

2.2 國際媒體視角：伺服器 CPU 集中亮相後，適配成本成為真正門檻

日期：2026-10-22　來源：Global Times：Chinese chipmakers roll out new RISC-V server CPUs for AI demand（10-22）

峰會後境外媒體給出的一篇綜述，把進迭時空 V100 與藍芯算力 LX500 放進同一條敘事：中國廠商正把 RISC-V 從嵌入式推向 AI 伺服器。

  • 事實部分：V100 為 46 核、最高 2.4 GHz、支援 DDR5 與 PCIe 5.0，並同時給出計算、AI 與儲存三類整機；LX500 為 48 核並整合專用 AI 引擎，正在適配 Qwen、DeepSeek、Kimi 等模型，目標場景包括企業知識庫檢索、辦公助手、金融合規推理與工業巡檢。
  • 觀點部分：受訪分析人士認為伺服器 CPU 的競爭不止於單晶片效能，替換處理器不是換個零件；作業系統、應用與開發工具能否順暢執行，適配與維護成本能否被接受，才是客戶是否遷移的關鍵。適配成本過高時，即便新晶片有技術優勢，客戶也會猶豫。

把”釋出”與”落地”分開看，這篇提供了一個外部視角的標尺：展會上的整機證明硬體形態已經齊備，而生態側的成本核算才決定訂單。這與本期的今日重點互為註腳。

2.3 樂鑫 ESP32-S31 外溢到成品：GUITION 旋鈕屏換代新 SoC

日期：2026-10-22　來源：CNX Software：Rotary encoder with 1.8-inch touch display gets upgrade to ESP32-S31 SoC（10-22）

GUITION JC3636F118C-I-YR1 是把原 ESP32-S3 版本升級到 ESP32-S31NRV16 的旋鈕屏產品：1.8 英寸 360×360 圓形 TFT（ST77916 驅動加 CST816 觸控）、16 MB flash 與 16 MB PSRAM、揚聲器與 MEMS 麥克風、DRV2605 觸覺驅動與 USB-C 供電。

  • 無線規格：Wi-Fi 6、藍芽 5.4（含 LE Audio、方向查詢、Mesh 1.1）與 802.15.4 三模，CPU 為 320 MHz 的 RV32IMAFCP 高效能核加一顆低功耗 MCU 核。
  • 產品意義：距 ESP32-S31 首次出現在第三方開發板（10-14）不到十天，成品已開始換代。MCU 級 RISC-V 的整機跟進速度，比前幾代架構明顯更快。

三、國內團隊深挖

3.1 達摩院玄鐵 CubeSandbox：RISC-V CI 連推 12 筆，微虛擬機器控制面跑通 MySQL

日期：2026-10-22　來源：XUANTIE-RV/CubeSandbox：feat/riscv64-ci 分支提交（10-22）

玄鐵維護的 CubeSandbox 在視窗內把工作重心從”開出 RISC-V 分支”轉到 CI 攻堅：feat/riscv64-ci 分支錄得 12 筆提交，全部圍繞在 RISC-V 上把微虛擬機器（microVM）控制面穩定跑起來。

  • 核心配置：為 7.2 版本的 L1 核心開啟 CONFIG_NUMA、把 XFS 與 dummy 驅動編進核心、補齊 tc-bpf、bridge 與 tap 網路棧。
  • 可觀測性：失敗時抓取 L1 的 dmesg 與 L2 guest 控制檯輸出；新增環境變數開關讓 guest console 可觀測；把 dirty log 預設關閉，另給 CUBE_DISABLE_VM_DIRTY_LOG 作逃生口。
  • 流程：拉長 shim 的虛擬機器啟動等待並在退出時關掉 L1；C1 控制面演示改用 apt 安裝的 mysql systemd 單元，先修 mysqld 可觀測性、再驗證服務能正常停止。
  • 上游背景：上游是騰訊雲開源的 AI Agent 沙箱（Apache 2.0，硬體級隔離、毫秒級啟動、相容 E2B 介面），RISC-V 側的快照與恢復仍待 vAIA 狀態遷移實現，屬開發者預覽階段。

這十幾筆提交沒有一條是”功能釋出”，全是把不穩定因素逐個釘死：核心配置、串列埠可觀測性、髒頁日誌、MySQL 啟停驗證。微虛擬機器在 RISC-V 上從能啟動到能承載真實負載，成本幾乎全花在這類工作上，這也是判斷這條棧成熟度最可靠的觀察點。

3.2 進迭時空軟體棧三線迭代：視覺模型介面統一、llama.cpp 預填充最佳化

日期：2026-10-22　來源：model-zoo-vision 提交（10-22）、llama.cpp：mtmd-backend 分支提交（10-22）、ai-sdk 提交（10-22）

V100 釋出之後，進迭時空的軟體棧在三條線上同時小步迭代，方向都是”讓外部開發者能直接用”。

  • 視覺模型庫：model-zoo-vision 三筆提交，重構核心把各任務的 Run 介面統一、去掉 task 層介面（#109），統一各模型示例的 README（#110），為 track 與 match 兩類模型補上 Python 示例（#111）。
  • 推理棧：llama.cpp 的 mtmd-backend 分支兩筆，ggml 側 SpacemiT 預填充最佳化（#49）與清理過時的重複 -lm 與 –load-mode 選項（#50）。
  • SDK：ai-sdk 兩筆子模組更新，指向 vision 模組。
  • 配套文件：docs-ros 同日兩筆把感知與視覺文件對齊新的節點行為與 SDK 介面（#217、#218）。

介面統一與示例補齊，是模型庫開始面外部開發者的訊號；預填充最佳化則直接影響長上下文的處理效率與首 token 延遲，是伺服器場景最敏感的指標之一。晶片釋出後軟體跟進的速度，往往比規格更重要。

3.3 算能 sophon-demo 新增 PaddleOCR-VL 的 Python 樣例

日期：2026-10-22　來源：sophgo/sophon-demo 提交記錄（10-22）

算能的示例倉庫 sophon-demo 在 release 分支新增 PaddleOCR-VL 的 Python 樣例（paddleocr_vl.py），補上這條文件智慧模型在自家平臺上的可直接執行版本。

  • 前情：10-19 同倉剛做過一次整理，去掉隨倉打包的 tpu-mlir wheel 下載；這次把 Python 版本補齊，形成文件加樣例的完整組合。
  • 同期節奏：10-19 至 10-21 該倉連續補入 SAM3、SAM2、BLIP、MP_SENet、YOLO_world 的 C++ 樣例，以及 CV84X6 平臺的 MiniCPM4、InternVL3、MiniCPMV 適配。
  • 解讀：示例庫在兩個月裡從”Python 參考實現”擴充套件到”C++ 工程化樣例 + 熱點模型首日適配”。端側晶片的競爭力越來越取決於模型到了能不能跑、照著文件能不能復現，這一層比引數宣傳更實際。

四、具身智慧與機器人專章

4.1 21 世紀經濟報道專訪孫彥邦：K3 支撐人形機器人完賽，機器人將走向單晶片

日期：2026-10-22　來源：21 世紀經濟報道（新浪財經轉載）：人形機器人馬拉松背後的 RISC-V 力量（10-22）

峰會後的一篇深度專訪，受訪者為進迭時空聯合創始人孫彥邦，給出了幾條可核驗的進展與判斷。

  • 已發生的進展：2026 年 4 月北京亦莊人形機器人半程馬拉松中，靈龍 2.0 完賽所用的是進迭時空 K3 晶片；K1 累計出貨 15 萬顆，K3 為全球首顆符合 RVA23 規範的量產 RISC-V 晶片並已規模量產交付。這兩代端側晶片的積累，被描述為向雲端延伸的起點。
  • 市場預測：引用 Omdia 資料，RISC-V 處理器年出貨量增長率為 50%，2030 年全球市佔率將接近 25%，約每四顆處理器有一顆是 RISC-V。
  • 判斷一：機器人產業進入規模化落地週期後必然走向單晶片整合路線，下一代機器人會更依賴 RISC-V，原因是對安全性的極致要求與強 CPU 加 AI 能力的融合。
  • 判斷二：機器人的實時性需求”永遠沒有天花板”，AI Agent 逃逸現象頻發，虛擬化與物理隔離都難以徹底保證系統始終在可控範圍內，開源開放的機制反而可能是破局點；Physical AI 是最大的機遇。
  • 判斷三：研發路線要與資金實力匹配；PPA 之外硬體必須超配，軟體生態才有發揮空間；國產產業鏈迭代速度值得期待，但最終衡量標準仍是訂單轉化。
  • 外部觀點：另引圖靈獎得主 David Patterson 的判斷，AI 推高儲存頻寬與容量壓力，主流標準儲存效能提升停滯，領域專用儲存（DSA）在算力稀缺背景下變得可行。

這篇把”RISC-V 做機器人”從概念落到兩個具體座標：一顆已規模量產的端側晶片，以及一條”安全加實時”的架構理由。相比算力數字，後者更能解釋機器人廠商為什麼願意換架構；而”硬體必須超配”這句，也正好解釋了當前機器人晶片普遍提前預留算力的做法。

4.2 spacemit-robotics：動作識別配置對齊 13 點骨架

日期：2026-10-22　來源：ros2_action_recognition 提交（10-22）、spacemit-com/docs-ros 提交（10-22）

進迭時空的機器人軟體線在視窗內完成一次介面對齊：動作識別倉庫合入修復，把 STGCN 配置與 13 點骨架定義對齊到視覺 API（#8）；同期 docs-ros 兩筆把感知與視覺文件同步到新的節點行為與 SDK 介面，ai-sdk 兩次子模組更新指向 vision。

  • 倉庫定位：spacemit-robotics 覆蓋手勢識別、動作識別、實時鏈路與外設控制，屬 K3 平臺機器人的配套軟體；同視窗內還有 realtime-link、manifest、peripherals_led 的推送。
  • 解讀：骨架關鍵點從常見的 17 點或 21 點收斂到 13 點，是上游模型與自家推理管線對齊時典型的一步；文件與 SDK 同步更新，說明這條線在準備對外交付而不是內部試驗。

五、總結與趨勢觀察

  • 伺服器敘事的重心從”晶片釋出”轉向”基礎設施適配”：峰會上 V100、LX500、C950A 集中亮相，峰會後的第一批新動作是科華資料與進迭時空的簽約，以及境外媒體對適配成本的討論。硬體形態已經具備，接下來拼的是機房側的接受度與軟體棧的遷移成本。
  • RISC-V 在細分品類的位置更清楚了：毫米波雷達的報道說明，在 DSP 與硬體加速器承擔主要算力的晶片裡，CPU 指令集是”方案選擇”而非”代際替代”；國產廠商先用上的原因是供應鏈可控與定製自由，不是效能代差。
  • 發行版補齊的節奏穩定且層次上移：openRuyi 連續三天分別補 Go 雲原生元件、uv 的 Rust 依賴與 Python、Node、Java 執行時版本，安全修復開始帶標記走流程。RISC-V 發行版正在從”能裝”走向”敢用於生產”。
  • 微虛擬機器棧在 RISC-V 上進入除錯期：CubeSandbox 的 12 筆提交全部是核心配置、可觀測性與流程驗證，沒有一條功能釋出。這是從能啟動到能承載負載的必經階段，也是觀察 RISC-V 虛擬化成熟度的最佳視窗。
  • 端側出現外溢效應：ESP32-S31 從預覽器件到第三方成品只用了約十天，社群專案甚至在它上面跑通完整 Linux 與圖形化外的全套使用者態。這類”向下壓榨”的玩法會持續放大 RISC-V MCU 的開發者曝光。
  • 機器人側的證據仍來自端側與實時控制：K3 支撐人形機器人完賽、關節控制晶片已量產，而大算力的”大腦”晶片多處在流片階段。RISC-V 在機器人上的第一波真實出貨，很可能仍來自運動控制而非通用 AI 算力。
  • 侷限說明：科華資料與進迭時空的合作細節來自兩家公司的對外口徑與財經媒體轉述，未披露合同金額、時間表與具體專案；毫米波雷達報道中的效能數字（3668 DMIPS、聚類與跟蹤耗時）來自廠商測試，未見第三方復現；Global Times 的受訪者為行業分析人士，觀點不代表產業共識；ESP32-S31-Linux 屬社群專案，作者自述為”非為 Linux 設計”的器件上的移植實驗，不構成產品化路徑；openRuyi 的提交內容依據提交標題判斷，未逐條核對 changelog；CubeSandbox 的 RISC-V 支援仍為開發者預覽，官方未提供釋出映象；會員官網巡檢檢出的 95 處變化均為高校、機構與廠商首頁的例行更新，未發現實質產品、融資或架構釋出。
