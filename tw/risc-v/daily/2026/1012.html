今日重點：LPC26 歸來——RVA23u64 核心 profile 位推進，8 枚補丁已入 riscv/for-next

日期：2026-10-11　來源：微信公眾號「Docular嘚吧嘚」：LPC26 參會記（10-11）、LPC26 演講材料（slides）、作者主頁：Docular

RVA23 核心工作主要推動者徐國棟（Docular，現就職高通）釋出 Linux Plumbers Conference 2026（LPC26，布拉格）參會記：其主導的 Linux 核心 rva23u64 profile 位系列正推進至 v9（在途），10 月 9 日 v8 的 11 個 patch 中前 8 個已被 RISC-V 核心維護者 Paul Walmsley 收入 riscv/for-next（等下一合併窗進主線），其餘 3 枚核心 patch 將吸收 LPC 現場意見後隨 v9 提交。

  • 要解決的問題：RVA23 profile 1.0（2024-10 批准，39 必選 + 15 可選擴充套件）需要核心與使用者態低成本回答「這臺硬體是不是 RVA23」——現狀只能逐 bit 查詢，glibc、GCC 各算各的，Ubuntu 側的檢測工具也只能給出 “probably RVA23”。方案是核心啟動時算出 “RVA23 compliant” 位放入 vDSO，使用者態經 hwprobe UAPI 一讀即得。
  • LPC26 四個 Ask 的結論：① v8 位形態獲維護者認可，v9 將補充 RVA22 / RVA20 分級位（便於 glibc 逐級回退）並寫明不繼承 IMA 位的歷史遺留行為；② glibc 將改為按 profile 構建 + glibc-hwcaps 自動選庫（hwcaps 來源即核心位；ifunc 留給微架構級選擇），GCC 維護者 Jeff Law 在 GNU Tools Cauldron 的 RISC-V BoF 同向推進；③ 使用者態動態關閉 V 擴充套件的介面將廢棄——LPC 次日 Samuel Holland（SiFive）即發出 3-patch 系列（cover letter：RISE 與 LPC26 已形成共識，create more trouble than benefits）；④ 未來帶暫存器狀態的擴充套件（如 matrix）不會再引入同類開關。
  • 外溢效應：該系列直接或間接帶動不少於 5 個主線系列——兩塊擱置兩年的舊補丁（副檔名大小寫統一、Zicclsm）被吸收，位元組跳動 Qingwei Hu 貢獻 Zic64b 支援，另有 do not report disabled extensions（6 patch 系列）、cpufeature BUNDLE 到 SUPERSET 精簡、V-off 廢棄系列同期發出。
  • 補充：本屆 LPC 的 RISC-V MC 共 10 場 talk，高通佔 3 場；該 talk 的 slides 已公開（見參考連結）。

一、開源社群與軟體生態

1.1 Phoronix／LPC26：核心自動向量化取得積極結果，LZ4 最高提升約 15%

日期：2026-10-11　來源：Phoronix：Auto Vectorizing The RISC-V Linux Kernel Shows Promising Results（10-11）、LPC26 演講頁：Optimizing the kernel with vector、Hacker News 討論

RISC-V 核心構建目前尚未啟用 V（向量）擴充套件。Andy Chiu 在 LPC26（10 月 5-7 日，布拉格）演講「Optimizing the kernel with vector」，介紹以編譯器自動向量化最佳化核心的做法：針對 crypto、RAID、XOR、使用者複製等核心場景的實驗顯示——LZ4 最大提升約 15%、Btrfs 約 8.4%、XFS 約 5%、Nginx 場景約 2%；代價是向量上下文管理帶來的時間與記憶體開銷上升，核心態使用向量單元仍有既有約束。Phoronix 評價該方向「前景可觀」（promising results），演講材料已隨會議公開。

1.2 RevyOS：核心同步 6.17.11 配置，啟用 Rust／PowerVR／NTSYNC 等特性

日期：2026-10-11　來源：revyos/linux 提交記錄（10-11）

RevyOS（面向多平臺的 RISC-V Debian 發行版）核心倉庫視窗內 50 筆提交：將核心配置批次同步至 6.17.11 基線，新增 K1/K3、DP1000、SG2042/SG2044、TH1520 等平臺配置，啟用 Rust、PowerVR DRM、NTSYNC、K3 顯示控制器與 UFS、SPACEMIT PM 域、FUSB301 Type-C 控制器等；裝置樹為 K3 Pico ITX 啟用 GPU 與 USB3 埠、為 Milk-V Meles 啟用 USB；CI 新增交叉/原生構建。K3 等平臺的顯示、USB、儲存與 GPU 支援在發行版核心側密集補齊。

1.3 openRuyi：SPECS 更新 Go 1.27.2 與 OpenSSL 3.6.5，docker-cli 獨立打包

日期：2026-10-10　來源：openRuyi 提交記錄（10-10）、lookout 提交記錄（10-11）、openRuyi 官網新聞頁（10-12 核查）

openRuyi 倉庫視窗內 5 筆 SPECS 更新：Go 升級至 1.27.2、OpenSSL 升級至 3.6.5、新增 docker-cli 獨立包（moby 的 Provides 遷移至 docker-cli）；PR 模板修正連結。同組織版本巡檢工具 lookout 視窗內 10 筆提交，推進 Go 元件從可信來源標籤自動發現、精確 Go 版本跟蹤與 NVD 安全身份核驗等能力。官網新聞頁核查：最新發布仍為 2026.09 版，無新版本公告。

2.3 產業觀察：高通訴 Arm 庭審就 RISC-V 資料中心成熟度展開攻防

日期：2026-10-11　來源：Wccftech：Even Court Judges Are Now Declaring That RISC-V Is Basically Worthless（10-11）

圍繞高通訴 Arm 的許可糾紛庭審（特拉華州聯邦法院），RISC-V 意外成為庭上話題：Arm 專家證人 Timothy Simcoe 稱 RISC-V 與 x86 構成「長期競爭壓力」；主審法官 Noreika 追問 RISC-V 當下可用性，證人承認其企業資料中心部署尚處早期、相關設計主要來自中國企業（如阿里玄鐵），主審法官隨後未再深究。該報道以誇張標題流傳引發社群熱議；討論焦點為企業資料中心場景，與 RISC-V 在嵌入式與邊緣的既有落地進展無直接矛盾。

2.4 行業分析：x86／Arm／RISC-V 在工業邊緣「正面相遇」

日期：2026-10-10　來源：36 氪：《x86、Arm、RISC-V 在工業邊緣正面相遇》（10-10）

邊緣 AI 爆發讓三條架構在工業場景正面競爭：《半導體產業縱橫》（36 氪授權釋出）梳理——x86 靠生態（英特爾 Open Edge Platform、AMD 銳龍 AI 嵌入式 X100 最高 80 TOPS，巡檢機器人已落地）；Arm 靠能效與異構（瑞芯微 RK3572 整合 RISC-V 核、RK182X 協處理器內建多核 RISC-V，已匯入數百客戶專案）；RISC-V 靠開放可定製（玄鐵 C950、芯來 NA900 透過 ASIL-D、奕斯偉 R500A 透過 ASIL-B 認證）。文中判斷 2030 年 RISC-V 在工業邊緣晶片出貨佔比或從不足 7% 升至 24% 以上，競爭關鍵在工具鏈、RTOS 與認證體系；並預告 10-12 起上海工博會國芯展設「RISC-V 能否啃下工業邊緣的硬骨頭」論壇。
