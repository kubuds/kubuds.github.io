今日重點：軟體源上架 QEMU 11.1.0 的 AME 與 RVP 包，雙週報 081 同期刊出（11-19）

來源：雙週報第 081 期。qemu-user-riscv-ame 提交。qemu-system-riscv-rvp 提交。

11-19 10:33 至 14:42，packages-index 連續落下 13 筆提交。前四筆新增四個模擬器軟體包：qemu-system 與 qemu-user 各一套，分別帶 AME 與 RVP 支援。

四個包都基於上游 QEMU 11.1.0。AME 包的版本串是 11.1.0-ruyi.20261016，RVP 包是 11.1.0-ruyi.20261027。兩套擴充套件都對應 v0.6 草案。

雙週報 081 寫明，AME 支援由達摩院貢獻。這是矩陣擴充套件第一次以可安裝軟體包的形式進入 RuyiSDK 軟體源。

同一期雙週報在 11-19 定稿。wechat-articles 倉視窗內落了 9 筆提交，從骨架、正文到卷首語依次補齊（#411 至 #418）。

包管理器的節奏有調整。雙週報寫明 ruyi 0.55.0 預期在 11 月底釋出，當前最新仍是 0.54.0（11-10）。官方給出的原因是發版週期調整。

其餘更新是映象批次跟進。Armbian 的 VisionFive 2 與 Orange Pi RV2 最小映象升到 26.11.0-trunk.120。LicheeRV Nano 的 Buildroot SDK 升到 0.20261109.0。

FreeBSD riscv64 mini-live 升到 14.5，OpenBSD riscv64-live 升到 8.0，並移除上游已不提供的 7.6.0。OpenWrt 的 SiFive Unmatched 映象升到 25.12.6。

CanMV K230 修了失效的下載連結。CI 側另有一筆，把遙測上傳說成不阻斷工作流。

還有兩條映象 PR 未合。Bianbu K3 升 4.0.8（#250）與移除舊版 VisionFive 2 映象（#249）都還開著。

今日重點：buddy-mlir 合入 ZTT v0.6 與 LLVM 矩陣擴充套件，triton-riscv 後端調優跟進（11-19）

來源：buddy-mlir PR #1066。PR #1067。triton-riscv PR #129。

11-19 19:20 至 19:21，buddy-mlir 連續合入兩個 PR。#1067 把 LLVM 子模組從 542365c9cd38 推到 163d6a753b58。

新指標指向 llvm-project fork 的 #33 合併點。該合併加入 XSAI 的 ZAMES 矩陣指令與 ZMASYNC 同步指令。覆蓋面含矩陣與同步 intrinsic、無尺寸目標擴充套件型別、彙編與反彙編，以及 RV64 SelectionDAG 降級。

支援範圍有邊界。矩陣的複製、溢位與過載，以及跨函式 ABI 仍未覆蓋。PR 說明只改子模組指標，行數為 +1 −1。

#1066 把已退役的 AME 方言整體換成 ZTT v0.6，仍沿用 ame 名稱空間。它定義 138 個帶型別的指令 op，配自定義彙編語法與 intrinsic 橋。

降級路徑統一走 lower-ame，落到 llvm.riscv.ztt.* 呼叫。PR 附帶 8×8 與 4×4 兩組示例，以及兩個 freestanding 負載在 gem5 上的校驗。改動 30 個檔案，+8349 −1277。

下游當天就跟上了。triton-riscv 18:20 開出 #129，調 RISC-V 目標的 buddy-opt 降級引數。改動只在目標為 RISC-V 時生效，共 2 個檔案，+137 −12。

調優有三塊。數學函式改用多項式近似，覆蓋 exp、log、tanh、erf、sin、cos、atan 等 13 個運算元。向量改用目標最小 VLEN 的可伸縮向量，並用 avl 迴圈收尾。矩陣乘的向量寬度改為 2·VLEN/32。

VLEN 從目標的 +zvlNb 讀取。只給 +v 時按 128 計。作者在 VLEN-256 的 RISC-V 板卡上對比 triton-cpu 調的引數。

這條 PR 依賴尚未合入的 buddy-mlir #1068。PR 說明寫明，用舊版 buddy-opt 會在未知 pass 或選項處直接失敗。

1.2 FlagGems 示例三連：63 + 43 + 40 個運算元分三支待合（11-19）

來源：PR #126。PR #127。PR #130。

FlagGems 示例在一天內疊成三支。#126 覆蓋 63 個 aten 運算元，#127 再加 43 個 torch.special 運算元，#130 再加 40 個啟用、dropout 與損失運算元。

三支是序列堆疊的。#127 接在 #126 頭上，#126 接在 #120 頭上，#130 又接在 #127 頭上。PR 說明都註明，前序未合時 diff 會把前序提交一併計入。

按各自說明，相對 main 的規模分別是 239、325、405 個檔案。#130 自己的部分是 4 個提交、81 個檔案，其餘屬前序 PR。

測試數逐層上漲。#126 記 6416 項透過，#127 記 6782 項，#130 記 7091 項。新增用例分別是 309 與 366 項。

#127 的內容是特殊函式。貝塞爾家族、四類 Chebyshev 加移位版、兩種 Hermite、Laguerre 與 Legendre 都在內，另有 log_softmax 與 logsumexp。

工具鏈無法降級的 intrinsic 改用閉式。erfcx 用三段混合，fp32 段、fp64 段與漸近級數各管一段。log_ndtr 的尾部改算 −t² + log(erfcx(t)/2)，避開 ndtr 下溢。

#130 的內容偏神經網路運算元。GELU、GLU 的反向公式，融合的 conv/addmm/prelu，dropout 與 randomized-ReLU 變體，以及含 CTC 前向與反向的損失組。

CTC 的格子動態規劃用 fp64 的 Triton 核。反向把 beta 掃描留在主機側，同時清洗傳入的 alpha。作者註明，aten 的 CPU 實現會留下不可達格點未初始化。

卷積的 cudnn 尾聲改走 aten。Triton 只保留 bias、Z 相加與 ReLU。triplet margin 按 pairwise_distance 的語義處理，eps 廣播到差值向量上。

三支都把範圍限制在 python/examples/flaggems。PR 說明寫明不改後端、CI 與其他 PR 的檔案。

1.3 RISC-V 後端調優 PR #129 開出，依賴 Buddy 尚未合入的 pass（11-19）

來源：PR #129。PR #128。buddy-mlir PR #1068。

#129 在 18:20 開出，標題與 #128 相同。#128 在 10:19 開出、10:20 關閉，隨後以 #129 重開，內容一致。

改動集中在 Triton 到 LLIR 的一處函式。只有目標為 RISC-V 時才追加引數，其他目標不受影響。作者說明沒有繫結特定 VLEN。

引數分三類。數學函式開多項式近似，涉及 exp、expm1、log、log2、log1p、tanh、erf、erfc、sin、cos、atan、atan2、asin、acos、cbrt。

向量化改用可伸縮向量，按目標最小 VLEN 取寬度，並開 avl 迴圈。矩陣乘的向量寬度改為 2·VLEN/32，而原來是常數 4。

精度依據在 Buddy 側。#1068 的說明給出 f32 下 1 至 7 ULP，f16 與 bf16 至多 1 ULP。例外是 exp 與 erfc 的次正規結果。

依賴關係是硬約束。#1068 尚未合入，buddy 也還沒有帶這兩個特性的 release。PR 說明寫明，舊版 buddy-opt 會在未知 pass 或選項處停下。

三、P 擴充套件、向量與執行時最佳化

3.1 GCC 交付 3 個 P 擴充套件示例，13 個提交進主線（11-19）

來源：雙週報第 081 期。GCC 主線提交 fb66e0c。

三個 P 擴充套件示例可在 RV32 與 RV64 直接執行。場景是影象匹配、Q15 定點點積與 Q15 數字濾波，倉庫附預編譯工具鏈與兩份互動式教程。

影象示例裡，RV32 每條打包指令比較 4 個畫素，RV64 比較 8 個。程式遍歷 289 個候選位置，找回了向右 5 畫素、向上 3 畫素的位移。

動態指令降幅按 QEMU 在 -O3、允許非對齊訪存下統計。影象匹配 RV32 降 75.7%，RV64 降 80.0%。Q15 點積分別降 70.7% 與 74.9%，Q15 濾波降 69.5% 與 73.2%。

GCC 側 13 個提交進主線。8 個改進位操作與旋轉，4 個支援向量點積，1 個修通用迴圈最佳化。

K1 實機上的收益集中在標量位操作。32 位掩碼的置位、清位與翻轉，執行週期都減少約 27%。RV64 的單位元置位函式從 3 條指令縮到 2 條。

其他微基準有正有平。移位加法接左旋或右旋省約 19.8% 週期，接除法或取餘時動態指令減 8.30%、週期持平。gem5 上拼接兩個 32 位字省 32.77% 週期，SQLite 變長整數解碼反增 0.63%。

向量點積的 Zvdota 與 Zvbdota 已進主線。C/C++ 可呼叫整數、BF16、FP8 點積與批次 FP32 點積。

Binutils 側投了 Shlcofideleg v2。RISE 的 pre-commit CI 首次跑通手動試執行，三種配置能把補丁測試結果與生產基線自動比對。

3.2 LLVM 14 個 P 擴充套件 PR，13 個已合入（11-19）

來源：雙週報第 081 期。LLVM PR #243813。

本期提交 14 個 P 擴充套件 PR，其中 13 個已合入上游。剩餘一個仍在 review。

已合入的覆蓋面較寬。擴寬移位的合法化被限制到左移，修掉右移被誤選成左移指令的問題。

新增的 intrinsic 包括標量飽和移位加法、標量比較、飽和與舍入移位、高低半字乘法累加、標量 zip/unzip、窄化裁剪。

另有一批修復。zext_invec 補上 v8i8 到 v2i32 的匹配模式，打包移位遇零直接返回原運算元，RV32 的 i64 移位量合法化不再斷言失敗。

WADDA 與 WSUBA 在零累加值時的崩潰也修了。原因是零累加被選成 X0_Pair，改用 buildGPRPair 構造暫存器對。

GlobalISel 側保留 KCFI 型別資訊。間接呼叫因此能生成檢查，行為與 SelectionDAG 一致。

仍在 review 的是 #243813。它按 P 擴充套件的有符號移位語義，摺疊超出元素位寬的常量移位，生成零值或等價的填充與最高位提取。

3.3 V8 在 K3 上 JetStream 3 總分 +3.5%（11-19）

來源：雙週報第 081 期。CL 8698757。

本期 V8 的收益來自一批效能補丁。雙週報寫明這些補丁由 riscvlint 等工具找點、AI 輔助起草與基準驗證，再由 ISCAS 維護者人工評審後合入。

最大單項是蹦床池之後的短跳轉。原來用 8 至 12 位元組的 auipc 加 jr，現在改發 4 位元組 jal，並新增 far-jump pool 保證目標可達。

K3 真機上 JetStream 3 總分提高 3.5%。75 項裡 46 項超過噪聲，gaussian-blur 單項提高 27%，wasm 類提高 17% 至 22%。生成程式碼減少 1.7 MB，約 2.2%。

Zfa 的 fli 也進了 TurboFan 與 Liftoff。每個浮點常量從 3 條指令變成 1 條 fli.d，JetStream 3 裡消掉 248 處。

另有兩筆清理。空暫存器列表的 PushAll 與 PopAll 提前返回，Maglev 去掉約 9 萬條無用指令。Int32 比較直接比暫存器，指令數再降 0.47%。

內建模擬器側同樣有收益。IsShortInstruction 改為標頭檔案內聯後，richards 從 28.9 秒降到 19.0 秒，降幅 34%；ML 從 40.2 秒降到 27.3 秒，降幅 32%。

除錯檢查的快取再省一成。未開除錯時跳過六項檢查，richards 降 27%，ML 降 28%。解碼路徑最佳化後，richards 再降 20%，ML 再降 22%。

本期合入與審閱的補丁各 13 與 15 筆。內容包括堆數值去重、Liftoff 棧引數符號擴充套件、fence 與 AMO 記憶體序建模、CAS 地址計算順序等。

3.4 OpenJDK 與 Go 進入 1.28 凍結前的收尾（11-19）

硬體支援補了玄鐵處理器的廠商特性檢測（#32727）。程式碼生成側用 Zicond 最佳化條件算術（#32635），並在原子指令已提供記憶體序時去掉外圍屏障（#31955）。

四、Buddy Compiler 動態

4.1 AME 方言換成 ZTT v0.6，138 個指令 op 合入（11-19）

來源：buddy-mlir PR #1066。

#1066 在 19:21 合入，改動 30 個檔案，+8349 −1277。它把已退役的 AME 方言整體替換為 ZTT v0.6，名稱空間仍是 ame。

新方言定義 138 個帶型別的指令 op。每個 op 配自定義彙編語法、intrinsic 橋與矩陣/累加器目標擴充套件型別。

降級統一走 lower-ame，落到 llvm.riscv.ztt.* 呼叫。intrinsic 橋保留直接翻譯到 LLVM IR 的路徑。

驗證分兩層。一組覆蓋降級、診斷、全 intrinsic、混合方言、副作用與後端選擇。另一組是兩個 freestanding 負載，在 AME_gem5 上以原子系統呼叫模擬模式跑。

4×4 的有符號 i32 負載與獨立標量參考逐位比對透過。PR 說明寫明替換了舊 ISA 契約，不承諾與舊實現的數值行為相容。

文件不在本 PR 內。README 與獨立文件留到後續 PR，BOSCAME 與 XTAME 的實現也未改。

4.2 LLVM 跟到 163d6a7，XSAI 的 ZAMES 與 ZMASYNC 進後端（11-19）

來源：buddy-mlir PR #1067。llvm-project PR #33。

#1067 在 19:20 合入，只改 LLVM 子模組指標，+1 −1。舊指標是 542365c9cd38，新指標是 163d6a753b58。

新指標對應 llvm-project fork 的 #33 合併點。該合併給 RISC-V 後端加入 XSAI 的 ZAMES 矩陣指令與 ZMASYNC 同步指令。

覆蓋面包括矩陣與同步 intrinsic、無尺寸的目標擴充套件型別、彙編與反彙編，以及 RV64 的 SelectionDAG 降級。

邊界同樣明確。矩陣的複製、溢位與過載，以及跨函式 ABI 支援，都不在已支援範圍內。

這次更新是 Buddy 原生 ZAMES 支援的前置條件。PR 說明寫明，LLVM 後端就位後才能在 Buddy 側接原生命令。

4.3 EmbeddingGemma-300M 在 K3 上提速 23 至 38 倍（11-20）

來源：buddy-mlir PR #1070。

#1070 在 11-20 凌晨 01:56 開出，改動 19 個檔案，+3072。它接著 #835 的工作，修模型匯入、RAX 打包與分詞器相容。

最佳化手段是 IME 與 RVV。單次前向在 K3 上相對 F32 RAX 基線提速 23.24 至 38.24 倍，相對原生 Hugging Face F32 提速 7.11 至 19.03 倍。

記憶體佔用同步下降。峰值程序 RSS 相對 RAX 基線降 71.6% 至 93.5%。九個負載、81 次正式執行都透過嵌入精度門檻。

匯入側的修法換成了整圖。雙向加性掩碼在模型包裝層構造，一次匯入到池化、兩層 dense 與 L2 歸一化，舊版對生成 MLIR 做文字改寫。

批形狀與滑動注意力也修了。匯入用 eager attention，全量掩碼與滑動掩碼分開傳，不再假定 B1。

4.4 GPT-2 解碼修復開出，多項式近似數學 pass 待審（11-19）

來源：buddy-mlir PR #1069。PR #1068。PR #1065。

#1069 在 23:57 開出，修 GPT-2 解碼的數值錯誤。問題出在轉置 B 的批次矩陣乘被解碼向量化按非轉置佈局處理。

linalg 層沒有單獨的轉置 B 運算元。兩者共用 linalg.batch_matmul，只靠 indexing_maps 區分。解碼流水線裡兩個 pass 前後相鄰，前一個把所有 batch_matmul 都按預設佈局向量化。

修法是加守衛。只有預設 indexing_maps 才進入向量化，轉置 B 留給後面的專用 pass，並把這類運算元標為動態合法。改動 2 個檔案，+127。

#1068 是數學近似的本體，仍在審。新 pass 把 exp、tanh、log 等向量數學換成多項式，讓計算留在向量暫存器裡，不再逐 lane 調 libm。

上游 MLIR 的近似在六個運算元上有邊界問題。log 與 log2 把次正規輸入鉗到 FLT_MIN，sin 與 cos 的單常數歸約在大引數上失真，atan2 的象限判斷也有偏差。這個 pass 為它們另寫了模式。

sin 與 cos 用三段 Cody-Waite 歸約，超過 1e5 的引數走 192 位 Payne-Hanek。只在向量裡出現這類 lane 時才進分支。

迴圈尾部也改了。avl 迴圈讓餘數只跑一次活躍長度迭代，不再切半加標量迴圈。

#1065 同日 11:10 關閉，未合入。它做的是 linalg.transpose 的快取友好分塊，建立於 11-18。
