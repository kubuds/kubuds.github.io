今日重點：玄鐵核心補丁把 T-Head PMA 勘誤擴充套件到 PUD/P4D 大頁

日期：2026-09-20　來源：linux-xuantie-kernel 提交 167b3d7c

北京時間 09-20 16:33，RuyiSDK 的玄鐵核心樹（linux-6.6.36 分支）合入一筆上游回移補丁，題為 riscv: mm: Apply T-Head PMA memory-type errata to PUD and P4D entries。補丁說明指出：達摩院玄鐵的 PMA 記憶體型別勘誤在構建頁表項時透過 ALT_THEAD_PMA() 注入 PMA 型別位，此前只覆蓋 pfn_pte()、pfn_pmd()、pfn_pgd() 與 pte_modify()，未覆蓋 pfn_pud() 與 pfn_p4d()；因此 PUD 級（1GB）以及 sv57 下的 P4D 級（512GB）大頁對映不會攜帶玄鐵要求的記憶體型別編碼，在這類核心上會退回隱式/預設 PMA，記憶體屬性可能與其它尺寸的對映不一致。這些葉子項可由線性對映（create_pud_mapping() 以 PUD_SIZE 建立）與大頁 vmap 觸達。

修法是在 pfn_pud() 與 pfn_p4d() 中映象 pfn_pmd() 的做法，對保護值執行 ALT_THEAD_PMA()。提交帶 Cc stable 與 Fixes 標籤（指向引入勘誤處理的 a35707c3d850），上游討論見核心郵件列表帖子；回移由阿里雲側維護者署名完成，並按本樹風格把 ALT_THEAD_PMA() 作用於 u64 保護值。對使用玄鐵核心並依賴 GB 級大頁的負載（資料庫緩衝、虛擬機器記憶體、大模型權重對映）而言，這消除了同一程序內不同對映尺寸記憶體屬性不一致的隱患。

五、趨勢觀察

5.1 核心與容器兩側同日補 RISC-V 專屬行為：從能跑轉向跑得對

本視窗兩筆最有技術含量的提交都不增加新功能，而是修正 RISC-V 特有語義：玄鐵核心樹把 PMA 勘誤補到 PUD/P4D 級大頁，避免 GB 級對映記憶體屬性與其它尺寸不一致；openRuyi 把 riscv_hwprobe 加入容器 seccomp 白名單，避免 OpenSSL 與 zlib-ng 因 ENOSYS 靜默退回標量。兩者共同的判斷標準已不是「能否執行」，而是「是否按硬體實際能力與架構約束執行」。這一層次的補丁通常不產生新聞，卻直接決定實測效能與穩定性，值得在日報中持續跟蹤。

5.2 工具鏈產品線轉入小步釋出：外掛走 beta 通道，文件補齊圖形化工具

VS Code 外掛以 0.1.7-beta.1 進入下一版本預釋出，文件站同日補入 Ruyi Imager 圖形化燒寫說明，支援矩陣補錄進迭時空 K3 板卡的 Buildroot 報告——三件事分別覆蓋編輯器外掛、映象燒寫與系統適配三條使用鏈路，且都面向「降低上手門檻」。ruyi 本體保持靜默、0.53 正式版仍未打號，產品節奏呈現「周邊先行、主體消化」的形態。

5.3 PyTorch fork 的 riscv 分支借上游基線重排，CI 映象本地化補位

riscv 分支本次以 96 個提交重排的方式把本地補丁移到較新上游基線，短期內會帶來一次可觀的同步工作量與隨之而來的迴歸面；同日新開的 PR #51 要求原生 riscv64 硬體構建 CI 映象，說明 RISC-V 側流水線仍在補齊基礎設施，而非推進特性。RVV 相關的兩個開放合併請求（#46、#48）隨重排被重新整理，尚無新的評審進展，仍是本棧最值得等待的變更。
