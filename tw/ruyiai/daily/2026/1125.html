今日重點：FlagGems 線性代數 59 運算元合入 triton-riscv（11-24）

來源：PR #134。

#134「Port/flaggems linalg」在 11-24 17:13 合入，改動 121 個檔案，加 2457 行、刪 35 行。

PR 一次加入 59 個 FlagGems 線性代數運算元，每個運算元配一個測試，並統一從示例包的匯出表匯出。LU、Cholesky、三角求解與 QR 各保留一個 kernel，同演算法的運算元共用。

測試不求 LAPACK。RISC-V 的 PyTorch 構建沒有 LAPACK，因此不呼叫 torch.linalg，改用 matmul 恆等式重建結果來校驗。

同批修了 CPU 後端的 affine_grid_generator。改為每個輸出元素由一個 program 載入自己的 theta，kernel 停留在批次分配內。

這批程式碼此前以示例形式在審。11-23 期報告記錄兩筆示例 PR 未合入，本期已落地。

今日重點：openRuyi 打包 Triton 3.9.0，改用 Buddy 工具鏈並刪除舊包（11-24）

來源：python-triton 升級提交。

openRuyi 打包倉在 11-24 15:14 一次性改了三處。python-triton 升到 3.9.0 並改用 Buddy 工具鏈，buddy-mlir 包升到 0.1.4，舊包 python-triton-ruyiai 被刪除。

原始碼取三處：triton-lang 的 v3.9.0 釋出包、RuyiAI-Stack 的 llvm-project 提交 f346011a。

第三處是 RuyiAI-Stack 的 triton-riscv 提交 9ded1d4c。三者版本在 spec 裡固定。

構建依賴 buddy-mlir 0.1.4、buddy-mlir-llvm 0.1.4 與 clang 22 等。spec 寫明 CPU 後端用 Buddy 的 LLVM 工具，AMD GPU 走同源 LLVM 自建。

這一改動把 RuyiAI 的 Triton 從單獨包併入發行版主線。舊包名刪除後，ruyi 裝出的 triton 只有一個來源。

需要注意版本滯後。上游 buddy-mlir 已發到 0.1.8，發行版仍鎖 0.1.4。

4.3 視窗內七筆提交，VIR 排程鏈成形（11-24 至 11-25）

來源：buddy-mlir 提交列表。

七筆提交集中在兩段。11-24 上午是打包與前端：LLVM 與 Buddy 的 tar 包改用 zstd，DeepSeek 分詞從聊天模板中拆出。

11-24 晚間至 11-25 凌晨是向量側四筆。先給 VIR 的取值類操作標記 Pure，讓 CSE 能合併、排程能跨訪存移動。

隨後新增 -vir-schedule，按 vir.set_vl 區間重排操作以降暫存器壓力。再補 RVV 語義：廣播僅作標量運算元時不佔向量暫存器，MoE top-8 合併的最大活躍數由 10 修正為 4，所需分組由 9 修正為 3。

最後一筆把排程提前到 -lower-vir-to-vector 之前。

另有一筆近似數學 pass。RVV 上沒有向量數學庫，math.exp 等此前逐 lane 退化成 libm 呼叫。新 pass 改為多項式近似，並對 log、log2、sin、cos、atan2、cbrt 用自研模式，規避上游在次正規數與大幅值上的錯誤。

六、趨勢觀察

6.1 FlagGems 移植轉為日級批次

線性代數 59 個運算元合入的同一天，B12、B13、B14 三批共 96 個以上運算元開出。單筆 PR 上萬行，節奏從周級壓到日級。

移植口徑也統一了：每運算元一測試，包匯出集中在初始化檔案，測試繞開 LAPACK。這套做法可以直接複用到後續批次。

6.2 發行版開始接管 Triton 構建

openRuyi 把 triton 3.9.0 與 triton-riscv 固定提交寫進 spec，構建改用 Buddy 工具鏈，並刪除舊包。RuyiAI 的 Triton 從此由發行版主線交付。

這一步把「社群 fork 出輪子」變成「發行版出包」。後續版本節奏將由打包側決定，而不是倉庫標籤。

6.3 上游釋出節奏與打包版本脫節

Buddy 三天發了三版，發行版仍鎖 0.1.4。zstd 打包與 VIR 排程這些新能力，短期進不了發行版。

若打包側不跟進，Triton 的構建基線與上游會繼續拉開。
