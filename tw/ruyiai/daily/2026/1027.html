今日重點：buddy-mlir 一夜七筆補齊 RVV 可伸縮向量，雙週報 079 期落版（10-26）

日期：2026-10-26　來源：buddy-mlir 主分支提交列表、#1002 按 vscale 步進、#1008 索引向量自動尺寸、雙週進展 079 期

本期最集中的推進來自 Buddy Compiler。北京時間 10-26 22:48 到 10-27 03:22，四個半小時內七筆提交全部落在 VIR（向量化中間表示）上，圍繞同一個開關 use-scalable：先是讓 strip-mining 迴圈按 vscale 步進（#1002），再讓向量尺寸選擇在 RVV 上按 vscale = VLEN/64 與 LMUL 計算（#1003），隨後把帶結果的 vir.set_vl 降到可伸縮向量（#1004、#1005），補上動態向量的行置換 vir.shuffle（#1006），統一 vir.load 與 vir.store 的索引約定（#1007），最後修掉索引向量在沒有顯式寬度時的斷言崩潰（#1008）。七筆串起來是「讓 VIR 真正能用可伸縮向量表達」的一條完整鏈條，而不是零散修補。

同一視窗內，RuyiSDK 雙週進展第 079 期於 18:02 發到社群論壇。報告期截至 10-22，本次落版給出兩個明確時間點：包管理器 0.54.0 因發版週期調整改到 10 月底，openRuyi 月度版本仍未釋出。開發中項也寫得很具體——包與系統的 ABI 相容性檢測、更多官方包的 macOS 打包、SpacemiT K1/K3 的工具鏈適配。

上游側的另一件事值得並讀：llvm-project 的 riscv 分支在 10-26 23:00 完成六天內第四次換基，基線再前移 221 筆，26 個本地補丁一字未改；而換進來的上游內容裡，有 17 個 RISC-V 後端 pass 在一小時內被同一作者遷入 NewPM。上游在換編譯器管線，本地在換向量表達，兩端同時動，但中間層（triton-riscv 的依賴錨點、pytorch 的 riscv 分支）本期都沒接上。

2.3 openRuyi：Go 回移 SHA-2 的 Zvk 向量密碼學最佳化（10-26）

日期：2026-10-26　來源：openRuyi PR #1512、openRuyi 合併 PR 列表

18:33 合入的 PR #1512 是本視窗唯一一條與 RISC-V 指令集直接相關的發行版改動：把 Go 主線對 Zvk 的 SHA-2 支援回移到 openRuyi 的 Go 打包裡。Zvk 是 RISC-V 向量密碼學擴充套件族，SHA-2 是其中最常用的演算法套件，回移意味著發行版裡的 Go 工具鏈在支援該擴充套件的核上可以直接走向量指令，而不必等下一個 Go 大版本。

這條與 079 期裡 GCC 側的 Zvdota/Zvbdota rebase 形成呼應：工具鏈（GCC）與執行時（Go）兩側同時在接向量密碼學，方向一致但通道不同——前者靠下游 fork 自己維護，後者靠發行版打補丁回移。

2.4 packages-index 與 ruyi-imager：映象版本抬升、安裝器互動修復（10-26）

日期：2026-10-26　來源：packages-index 映象提交、ruyi-imager PR #19、ruyi-imager 提交列表

四、Buddy Compiler 動態

4.1 VIR 一夜七筆：從迴圈步進到索引約定一次補齊（10-26）

日期：2026-10-26 至 2026-10-27　來源：#1002 按 vscale 步進、#1003 RVV 可伸縮尺寸、#1006 動態向量行置換、#1007 統一索引約定

七筆提交由同一作者在 22:48 至次日 03:22 連做，編號 #1002 至 #1008，全部是 [midend][VIR] 字首。看內容能拆成三層。

第一層是迴圈與尺寸：#1002 修掉 strip-mining 迴圈的步長——此前 vir.set_vl 不帶結果時降成以常量 vector-width 為步長的主迴圈，每輪卻按 N 倍 vscale 條 lane 訪存，vscale 大於 1 時迭代會重疊；#1003 讓尺寸選擇在 RVV 上按 vscale = VLEN/64 計算，使 N 與 SEW 決定 LMUL 而不再退回定長向量；#1008 修掉索引向量在未顯式給寬度時因為按元素位寬取尺寸而觸發的斷言。

第二層是帶結果的 vir.set_vl：#1004 允許它降到可伸縮向量，此前它的分片（vl 與寬度向量、vl 對寬度取餘的標量）依賴編譯期已知的 lane 數；#1005 進一步支援多維動態向量，因為 decode attention 的 query 是從 region 外的 vir.from_vector 帶進來的。

第三層是訪存與置換：#1006 加上動態向量按行置換的 vir.shuffle；#1007 統一 vir.load 與 vir.store 的索引約定，讓帶結果與不帶結果兩種 set_vl 在多維動態向量上把行對映到 memref 末維之前的維度，與 vector.load 保持一致。

4.2 動機鏈：decode attention 與 RoPE 的表達缺口（10-26）

日期：2026-10-26　來源：#1005 多維動態向量、#1006 行置換、buddy-mlir 主分支提交列表

從提交說明看，這七筆不是泛化的向量化改造，而是被具體運算元逼出來的。觸發點是 VIR 的 decode attention：RoPE 的 rotate_half 要把一個 128 元素的頭按前後兩半互換再取負，即 [-x[1], x[0]]，本質是按行置換；而 VIR 此前無法表達動態向量的行置換，只能在外層用定長向量算好再把 query 帶進 region。

於是 #1006 補置換、#1005 補多維動態向量、#1007 補索引入口，三筆合成一條「讓 decode attention 整套留在 VIR 裡」的路徑。這條路徑的意義在可移植性：一旦運算元能完整表達，後端換 RVV 定長或可伸縮隻影響降級，不影響中間表示。

六、趨勢觀察

6.1 上游換管線、本地換表達：同一天各走一步

10-26 這一天，兩條與 RVV 相關的線同時動了：上游把 17 個 RISC-V 後端 pass 遷進 NewPM，本地把 VIR 的可伸縮向量支援補齊到索引約定。前者改的是編譯器內部管線的組織方式，後者改的是中間表示對 RVV 的表達能力，兩者指向同一個結果——RVV 的可伸縮向量不再只是「能生成」，而是「能被完整表達並穩定經過新管線」。

但中間層沒跟上。triton-riscv 的 buddy-mlir 錨點仍停在 10-17 夜間版，pytorch 的 riscv 分支連續五日零提交。這意味著上游與本地兩端的進展，本期都還沒有落到 RuyiAI 棧的運算元生成與框架適配這兩級。判斷這條棧是否真的在推進，下期應看兩件事：triton-riscv 是否更新錨點並重建，pytorch 分支是否恢復重放。

6.2 發版視窗被雙週報釘到月底，發行版進入補安全、攢包的收尾節奏

079 期把兩個日期說得比以往清楚：ruyi 0.54.0 因發版週期調整改到 10 月底，當前正式版停在 0.53.0；openRuyi 2026.10 仍未釋出。與之對應，openRuyi 本期 80 筆提交裡 31 筆是安全修復、18 筆是 Rust crate 補齊、14 筆是版本更新，涉及 48 個包——這是典型的發版前清掃：先把依賴鏈補全、把 CVE 清掉，再切版本。

值得注意的是 ISCAS 軟體源同步問題導致 packages-index 近兩週無包更新，這會讓 ruyi 使用者在 ruyi update 時看到的內容落後於倉庫實際狀態。若 0.54.0 按期釋出而軟體源未恢復，包清單與發行版版本之間會出現一段錯位，這是下期需要核實的風險點。
