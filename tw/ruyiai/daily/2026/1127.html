今日重點：triton-riscv 合入 PR #135，CPU lowering 與 matmul 統一走 VIR（11-26）

來源：PR #135。

11-26 17:41，PR #135 合入 triton-riscv 主線。標題為「Unify standard CPU lowering and matmul through VIR」。作者 WuXintong123，含 12 個提交。改動 2 個檔案，加 255 行、刪 124 行。

上期報告記錄該 PR 仍在審，分支已含合入後的 #129，與主線的差異只剩 backend/compiler.py，本次這批差異全部落地。

改動集中在五處。RVV 向量寬度改從目標特性裡最大的 +zvlNb 推導，預設 128 位。同時接受顯式的 target_vector_bits。標準流水線把 masked store 向量化，crop、transpose 與生產者融合的歸約改寫提前到 bufferization 之前。標準 matmul 在定寬與 RVV 目標上統一走 VIR，暫存器分塊按目標向量寬度與暫存器數配置。新增 target_tune，把 -mtune 透傳給 opt 與 llc。示例取值有 spacemit-x100、spacemit-a100 與 xt-c920v2。x86 側順帶修了向量寬度。opt 之前給函式加上 prefer-vector-width，Emerald Rapids 這類目標可用滿 512 位。

PR 說明 -mattr 繼續定義 ISA，-mcpu 可以開啟硬體未上報的擴充套件，二者分工不變。

依賴沒有解除：仍需含 buddy-mlir#1068 的 Buddy 發行版，主線當前鎖定的版本早於所需的 pass 與選項。編譯核心的 CI 要等新發行版與 Buddy 版本更新。

今日重點：buddy-mlir 新增 XSAIAME 方言，RISC-V 矩陣擴充套件進入 IR 層（11-26）

來源：PR #1071。

11-26 17:18，PR #1071 合入，新增 xsai_ame 方言，改動 32 個檔案，加 1541 行、刪 1 行，作者 xyyy1420。

該方言為 XSAI 的 ZAMES 矩陣擴充套件與 ZMASYNC 同步擴充套件提供型別化 SSA IR。LLVM 後端支援已隨 #1067 的 LLVM 升級進入主線，本次只加 IR 與 Python 繫結。降到 llvm.riscv.xsai.* intrinsic 與 Linalg 轉換留待後續 PR，LLVM gitlink 未動。

型別有兩種。!xsai_ame.tile<kind, MxN, element> 的 kind 取 a、b、c，對應 A 為 MxK、B 為 NxK、C 為 MxN。維度為正數或動態。元素型別共 15 種，整數側有 i4、u4、i8、u8、i32，浮點側有 fp8e4m3、fp8e5m2、fp16、bf16 與 tf32。其餘為 fp32、nvfp4、mxfp4、fp2pack4 與 fp2pack5。!xsai_ame.sync 是矩陣同步暫存器的 SSA 控制代碼，物理暫存器編號不進介面。

操作含 load、store、mma、mzero，以及 msyncregreset、mfence、mrelease 與 macquire。load/store 在暫存器與秩 2 memref 檢視之間搬 tile，可選轉置，檢視形狀須與 tile 一致。mma 檢查 a/b/c 種類與靜態 K/M/N 維度，元素型別組合不做校驗，支援哪些組合由硬體實現與 LLVM 後端決定。

四個同步操作都帶記憶體效應，不會被刪除，也不會跨記憶體訪問重排。

方言已在 buddy-opt 與 InitAll 註冊。Python 側提供方言註冊、TileType 與 SyncType，以及由 ODS 生成的運算元構造器。

一、RuyiAI 棧進展（PyTorch / Triton / TileLang RISC-V 適配）

1.1 PR #135 的七組實測：matmul 收益最大，CPU 調優接近持平（11-26）

來源：PR #135。

PR 給出七組歷史實測，都是相對基線的幾何平均比值，小於 1 表示變快。樣本來自各自的實驗，不是同一次全量跑分。

RVV、VLEN 256、SpacemiT X100 上共三組。masked tile 複製消除 1726 例，CPU 時間 0.934，牆鍾 0.941。masked 記憶體與歸約改寫 8643 例，CPU 時間 0.952，牆鍾 0.959。VIR matmul 的改動物件 553 例，CPU 時間 0.810，牆鍾 0.807。

x86-64、AVX-512、Emerald Rapids 上修向量寬度偏好 1712 例，CPU 時間 0.959，牆鍾 0.956。

CPU 調優三組都在 1726 例上。VLEN 128 的 C920v2 為 0.995，VLEN 256 的 X100 為 0.989。VLEN 1024 的 A100 為 1.000。

PR 另稱複製消除對照的 1726 例全部透過，matmul 對照的 856 例也全部透過。VLEN 修復恢復了 VLEN 256 與 1024 下的大規模歐氏距離物件檢查。

六、趨勢觀察

6.1 後端統一完成後，瓶頸轉向運算元庫存與 Buddy 版本鎖定

#135 關掉了「標準 CPU 與 matmul 分兩條 lowering」的結構，收益集中在 matmul 的 0.810 與 masked 記憶體改寫的 0.952。

CPU 調優在 VLEN 1024 的 A100 上是 1.000，說明這一項對寬向量機器暫時沒有增量。判斷依據是 PR 自述的三組調優樣本，不是全量回歸。

下一段瓶頸不在編譯路徑，而在兩處：279 個在審運算元沒有推進，Buddy 發行版仍鎖在早於 #1068 的版本。

6.2 矩陣擴充套件的落地節奏取決於降低與轉換兩個後續 PR

buddy 的矩陣擴充套件已有兩套 IR，AME（ZTT v0.6）與 XSAI AME（ZAMES/ZMASYNC）。

兩套都缺「Linalg 到方言」和「方言到 intrinsic」的完整鏈路。#1071 的 PR 自述也把這兩步列為後續工作。

判斷：矩陣指令短期內不會進入端到端模型效能資料，midend 的合入先改變的是可表達性。

6.3 發行版打包重點從核心跟進修到應用層可用性

openRuyi 本視窗 28 筆，核心零改動，辦公套件語料、RDF、線性規劃求解器與字型佔了大半。

box64 入樹是這批裡唯一改變軟體面寬度的改動，讓只發 x86 二進位制的一部分軟體有了執行路徑。

AI 棧側本視窗沒有新包，triton 與 buddy 的打包狀態與上一期一致。
