五、趨勢觀察

5.1 Ztt 線補齊 LLVM 側：矩陣擴充套件工具鏈進入雙後端階段

Ztt（RISC-V 矩陣擴充套件方向草案）此前以 GCC 後端（riscv-gcc ztt-dev）單線推進，本視窗 LLVM / Clang 側 ztt-dev 在 ruyisdk/llvm-project 落地（26 筆首推），雙後端佈局形成；疊加 attached-matrix-extension 的 intrinsic 文件 V0.6 重新整理，「規範—文件—雙工具鏈」三環同步有了實質進展。觀察點：兩側棧的公開評審路徑（GCC 側 PR 合入節奏、LLVM 新分支的後續推送與上游化路徑），以及 riscv-binutils 側 ztt-dev 是否跟進（目前停在 09-30）。

5.2 例行重建進入穩定節律：LLVM 每夜重放、PyTorch 每晨重建

LLVM fork 的 riscv 分支完成又一輪夜間重放（26 筆，與前幾輪棧組成一致），PyTorch fork 的 riscv 分支連續又完成一輪整棧重建（23 筆，頭部更新為 6ff4eefe），兩者均表現為「提交者時間集中、作者日期早於視窗」的例行重落——上游跟隨機制已日常化（PyTorch 近一週每晨一推）。此類重建保證棧與上游同基線，真正的內容推進仍取決於開放 PR 的評審效率（PyTorch 8 筆、LLVM FPGA 兩筆均保持開放）。

5.3 依賴升級驗證轉入產物階段：夜間構建首次以升級後程式碼為基礎

triton-riscv 新一期夜間構建（Nightly 2026-10-11-fe554ff）是 Buddy MLIR 依賴升級（#84）合入後的首個夜間產物，「補丁適配（#86）→ 依賴升級（#84）→ 構建產出」鏈條閉合。觀察點由此轉入 riscv64 輪子的裝置側實測反饋，以及社群最佳化 PR #85（softmax 與 matmul 路徑）的評審進度。

5.4 運營與工具側並進：雙週報編撰、IDE 體驗打磨、支援矩陣評審

雙週報 078 編撰推進（基礎 C 庫 / V8 / 支援矩陣章節匯入）、VS Code 外掛錯誤體驗兩連發（#264 / #265 合入）、支援矩陣兩份報告在審——生態運營與工具產品化在日更節奏之外同步推進；ruyici 的 macOS 構建支援與 ruyi-tuner 的 aarch64 支援則顯示構建與調優工具開始跨平臺、跨架構佈局。
