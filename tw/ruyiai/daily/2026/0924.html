今日重點：ruyi 修復跨軟體源安裝狀態問題，RuyiSDK 0.53 定於今日釋出

日期：2026-09-23　來源：修復 PR #502、問題 #501

北京時間 09-23 09:01，ruyi 包管理器把「Fix installation state managemet across repos」合併進 main 分支（合併提交 802dd4d9；修復提交 08fd6aeb，由維護者 xen0n 開發），關閉了社群使用者 qingwan12138 於 09-21 報告的 #501 號問題：切換軟體源後，已安裝的軟體包顯示為「未安裝」，且重新安裝被跳過、狀態永遠無法更新。

問題機制：安裝記錄以「來源軟體源 ID」為鍵，但安裝判重僅按「名稱 + 版本」。當同名同版本軟體包存在於多個軟體源時，使用者在源 A 安裝後切換到源 B，ruyi list 會因按新源 ID 查詢而顯示「未安裝」；此時重灌被「跳過已安裝」短路（退出碼 0）卻不寫新源記錄；解除安裝又報「未按安裝跟蹤」。最終形成「檔案在磁碟、狀態永遠為未安裝」的死鎖，只能靠 --reinstall 或先解除安裝恢復。修復將安裝狀態查詢改為按安裝身份（類別、名稱、版本、宿主）跨源匹配、同身份時優先精確源 ID 記錄，並讓解除安裝覆蓋所有軟體的同一身份記錄、順帶清理舊版本 --reinstall 遺留的重複記錄；共改動 162 行，其中 117 行為新增迴歸測試（state.py 與 test_state.py 兩個檔案）。

該修復已寫入同日完成的第 077 期雙週報草稿（詳見 4.1）：草稿「包管理器」章節寫明「RuyiSDK 0.53 將於 2026 年 9 月 24 日釋出，對應的包管理器版本也為 0.53.0」，並列出二進位制包 ABI 相容性檢測基礎設施、預設軟體源優先順序修復、下載失敗映象回退修復等同批更新。截至視窗末（09-24 04:30），已釋出 Release 仍以 0.54.0-alpha.20260918 為最新、v0.53.x 分支停在 0.53.0-beta.20260917，正式版打號與釋出公告是今天的首要觀察點。

5.2 支援矩陣的「單板多系統」模式與在審佇列

Milk-V Duo S 在三天內從 Arch Linux、Ubuntu 延伸到 Debian、RT-Thread、xv6，加上在審的 Zephyr 與 RT-Thread Smart，單一低成本板卡的作業系統覆蓋被系統化鋪開；同期 K510、CH32V307、ESP32C3 等邊緣與 MCU 級晶片的報告也在滾動更新。對使用者而言，「先查矩陣再選板」的可復現材料密度在提高；對社群而言，此類報告多為新貢獻者的練手入口，在審佇列長度比單日合併數量更能反映貢獻活性。

5.3 框架覆蓋的廣度擴張與 PyTorch 側深度等待

RuyiAI-Stack 新入庫 mxnet 與 caffe（見 1.4），與既有 pytorch fork 構成三個經典深度學習框架並置；但 PyTorch fork 的 RISC-V 功能線持續靜默（riscv 分支無新提交、8 個開放 PR 時間戳不動、RVV 兩筆核心支援補丁繼續排隊）。廣度擴張與深度推進出現分化，「寬而淺」的階段性狀態可用 mxnet、caffe 兩倉的首批動作來驗證下一步走向。

5.4 本視窗的空白與關注點

需要如實記錄的空白：PyTorch riscv 分支與開放 PR 雙靜默；triton-riscv、tilelang-riscv 與向量運算元三個專專案標倉庫全部靜默；ruyi-tuner、riscv-gcc、board-docs、packages-index 無提交與釋出；新聞側對 RuyiAI、RuyiSDK、如意社群、openRuyi 的 Google News 中英文多組查詢連續零命中，arXiv 視窗內無新收錄。關注點：一是 RuyiSDK 0.53 與 ruyi 0.53.0 的正式釋出及 v0.53.x 打號；二是雙週報 077 正式版內容；三是雲棲大會（至 09-24）收官動態；四是 mxnet、caffe 兩倉的後續動作；五是 openRuyi 2026.09 月度版本公告。
