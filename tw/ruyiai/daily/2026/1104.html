今日重點：openRuyi PR #1350 合入，RuyiAI 三件套七週後進入發行版打包（11-03）

日期：2026-11-03　來源：PR #1350 Add Ruyiai packages、三筆打包提交、後續修正 PR #1575

11-03 15:59（北京時間），openRuyi 主倉的 PR #1350 合入。這筆 PR 開於 09-21 17:55，複核走了 43 天，最終只帶三筆提交、十個檔案、838 行新增，卻把 RuyiAI 棧裡最難分發的一段——編譯器後端與 MLIR 工具鏈——正式收進了發行版的 SPECS 目錄。

三件套的分工是清楚的。buddy-mlir 是 MLIR 編譯框架，提供 RISC-V 向量（RVV）降級所需的方言與 pass，spec 裡寫 0.1.2，原始碼錨定 buddy-compiler 的提交 60f354a7，同時自帶一份 RuyiAI-Stack/llvm-project 的 LLVM 快照（提交 3845a205），用 clang/lld 22 引導構建，測試與 Python 包均關閉，工具鏈最終裝到 /usr/lib64/buddy-mlir/llvm。python-triton-ruyiai（spec 內包名 python-triton-riscv）把上游 Triton 提交 5889527 與 triton-riscv 的 nightly/20260913-da5291b 標籤拼在一起，執行期依賴 buddy-mlir、buddy-mlir-llvm 與 clang。python-tilelang-ruyiai（spec 內包名 python-tilelang-riscv）錨定 tilelang-riscv 提交 0b7d66eb，另外把 TVM、dmlc-core、rang、tvm-ffi、DLPack 五個子模組按上游固定的版本單獨打包，構建期還需要 python3dist(torch)。

從補丁內容可以看出發行版適配卡在哪裡：tilelang 的五個補丁分別放寬 apache-tvm-ffi 上限到 0.1.11、去掉 torch-c-dlpack-ext 與 patchelf 的構建依賴、讓工具鏈在 /usr/lib64/buddy-mlir/llvm 下查詢、跳過 z3 的 soname 改寫、另有一筆處理 TVM FFI 的 libbacktrace 開關；triton 的兩個補丁把 cmake/ninja/nanobind 換成系統包，並給 buddy-translate、buddy-llc、llc、mlir-translate 補上 PATH 與 /usr/lib64/buddy-mlir/llvm/bin 的查詢回退。換句話說，原始碼樹裡那些靠環境變數拼起來的路徑，在發行版裡必須逐條落成可重現的查詢規則，這才是 43 天覆核的主要工作量。

同一天 20:16，PR #1575 又補了一刀：把 buddy-mlir.spec 裡 Source0、Source1 的 #/ 分隔改成 /，修正 RPM 源地址寫法。同日又修了一處打包 bug，說明這三份 spec 的複雜度不在功能，而在打包約定與路徑細節；上一期日報記錄的「複核十九條意見集中在 spec 寫法」，在這裡有了收尾。

這筆合入的意義不在版本號，而在分發路徑。此前要用 RuyiAI 棧，得自己拉 triton-riscv、tilelang-riscv 與 buddy-mlir，按文件設 BUDDY_MLIR_BINARY_DIR 一類變數；現在 openRuyi 的打包倉裡有了這三個元件，構建透過後使用者可以按發行版方式安裝同一套 LLVM/MLIR 鏈，版本、依賴與安裝佈局由 spec 固定。PR 自述裡也按 openRuyi 的 AI 貢獻政策標註了輔助工具（GLM-5.3、DeepSeek V4.1 Flash）。

需要留一個尾巴：三份 spec 錨定的程式碼都早於本期上游。打包完成不等於能力同步，具體差距見 2.2。

2.2 版本錨點：triton 停在 09-13 夜間版，tilelang 停在 10-28，buddy 停在 0.1.2（11-03）

日期：2026-11-03　來源：triton-riscv 夜間版 2026-09-13、tilelang-riscv 提交 0b7d66e、buddy-mlir 0.1.3、buddy-mlir 0.1.4.dev20261103

六、趨勢觀察

6.1 從原始碼構建到發行版包：RuyiAI 棧的分發路徑補上最後一公里

三件套的 spec 進入 openRuyi 之後，RuyiAI 棧的分發路徑第一次被寫成發行版配置：以前是「拉原始碼 + 設環境變數 + 自己編 LLVM」，現在打包倉裡是一條 RPM 依賴鏈，buddy-mlir 提供 LLVM/MLIR 字首，triton 與 tilelang 依賴 buddy-mlir-llvm。構建產物進入倉庫後，使用者的安裝門檻會從「會編編譯器」降到「會裝包」；對專案而言，版本與依賴第一次被寫進可審計的 spec。

七週複核的價值也在這裡：爭的不是功能，而是路徑發現、依賴上限、構建隔離、包名與 Provides 這些發行版規矩。PR #1575 當天修源地址，說明這條鏈仍然脆，但它已經能跑通合併流程。

6.2 打包錨點滯後於上游：版本號裡的日期不等於程式碼日期

三份 spec 裡，triton 的程式碼停在 09-13，tilelang 停在 10-28，buddy 停在 0.1.2；而三個倉庫在 11-03 都還有新動作。最刺眼的是 tilelang：11-03 剛合入的 PR #5 是十八天靜默後的第一筆功能，但它不在當天合入的 RPM 裡——包錨定的是 10-28 的 0b7d66eb。

版本串 3.8.0+git20261103 會強化誤讀，把打包日期當成程式碼日期。對發行版使用者，這意味著「裝到的是某個快照」，不是「裝到的是最新」。後續要麼建立定期的 bump 流程，要麼在包描述裡寫清快照日期；否則每合入一筆功能，包與倉庫的差距就再拉大一點。

6.3 兩條開發線同日恢復，ruyi 主線與 openRuyi 發版仍靜止

11-03 這一天，tilelang-riscv 結束十八天靜默，buddy-mlir 重新出夜間版，openRuyi 一天合入七筆 PR；開發側的動作集中在編譯器後端與打包。另一邊，ruyi 主倉零提交、零新標籤，openRuyi 的 2026.10 月度版仍缺位。

兩條線的節奏並不同步：程式碼在走，發版不走。上一期把這種狀態概括為「卡點在釋出不在開發」，本期仍然成立。下一個觀察點是 openRuyi 十一月版是否把三件套收進去，以及 triton-riscv 的 #92 重基是否合併——前者決定發行版能否交付，後者決定 triton 包下一次 bump 的落點。
